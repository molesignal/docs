Un flujo es el contrato, definido a nivel de organización, que rige la ingesta, las consultas, las canalizaciones y la retención.
Abre **Flujos** para ver qué datos llegan y para inspeccionar o configurar cada flujo.

## Tipos de flujo

| Tipo | Contenido habitual |
|---|---|
| `logs` | Eventos estructurados y registros de aplicaciones. |
| `metrics` | Muestras de métricas de una sola fuente, como un servidor de Prometheus. El campo `metric_name` distingue las métricas. |
| `traces` | Spans de OpenTelemetry. |
| `profiles` | Metadatos de perfiles vinculados a blobs pprof. |
| `extend` | Datos de referencia que se administran en tablas de ampliación y se usan durante el procesamiento. |

El mismo nombre de flujo puede existir en distintos tipos de flujo. Incluye siempre `stream_type` en las solicitudes a la API
y en las automatizaciones.

### Flujos de la plataforma

MoleSignal escribe directamente en estos flujos:

| Flujo | Contenido |
|---|---|
| `_molesignal` | La telemetría del propio MoleSignal, en la organización `_sys`. Consulta [Autoobservabilidad](/es/self-observability). |
| `_synthetic_results` | Una fila por cada ejecución de una comprobación sintética. Consulta [Monitoreo sintético](/es/synthetics#flujo-de-resultados-y-retención). |
| `_audit` | Los eventos de auditoría del espacio de trabajo. Consulta [Flujo de auditoría](/es/settings/data-security#flujo-de-auditoría). |
| `_agent_model_traces` | Las llamadas de Mole Agent al modelo. Consulta [Uso y presupuesto](/es/agent#uso-y-presupuesto). |
| `_agent_score_traces` | Las puntuaciones de calidad de las respuestas de Mole Agent. Consulta [Calidad](/es/quality#puntuaciones-en-un-flujo). |

Lee estos flujos como cualquier otro. `_audit` requiere `audit.read`: sin ese permiso, el flujo no aparece ni en
la lista ni en las estadísticas operativas, y cualquier intento de abrirlo, modificarlo o eliminarlo devuelve `403`. Solo MoleSignal escribe en estos flujos: no se pueden crear flujos con esos nombres, cualquier intento de ingerir
datos en ellos devuelve `403` y ninguna [canalización](/es/pipelines#flujos-de-plataforma) puede escribir en ellos.

## Lista de flujos

**Flujos** muestra todos los flujos del espacio de trabajo. Cambia de pestaña para mostrar **Todos** o solo los de un tipo,
busca por nombre o descripción y filtra por estado operativo. El encabezado indica cuántos flujos reciben datos
con normalidad y cuántos requieren atención. También muestra el total de datos comprimidos escritos durante el período y el
almacenamiento actual.

| Columna | Qué muestra |
|---|---|
| **Estado** | **Operativo**, **Con retraso**, **Se interrumpió**, **Sin tráfico**, **Sin uso** o **Estadísticas no disponibles**. Consulta la tabla siguiente. |
| **Tasa de recepción**, **Última recepción** | A qué velocidad llegan los datos y cuándo llegaron por última vez. |
| Datos comprimidos | Los bytes comprimidos escritos durante el período. |
| **Almacenamiento actual**, **Retención** | Los bytes almacenados en este momento y cuántos días se conservan los datos. |
| **Registros**, **Tamaño recopilado**, **Tamaño almacenado**, **Tamaño del índice** | Los registros conservados, los bytes recibidos antes de las transformaciones, los bytes de los archivos de datos y los bytes de los índices. |

| Estado | Significado |
|---|---|
| **Operativo** | El flujo recibió datos en los últimos 15 minutos. |
| **Con retraso** | El flujo recibió datos por última vez hace entre 15 minutos y 2 horas. |
| **Se interrumpió** | El flujo lleva más de 2 horas sin recibir datos. |
| **Sin tráfico** | El flujo de trazas de Mole Agent no recibe datos entre respuestas. |
| **Sin uso** | El flujo nunca ha recibido datos. |

Un flujo marcado como **No se puede consultar** sigue recibiendo datos, pero no aparece en los selectores de consultas. Cada fila incluye
**Consulta** o **Explorar**, además de **Ver detalles** y **Copiar ID del flujo**. **Tareas de búsqueda**, en el encabezado, abre
las [tareas de búsqueda](#tareas-de-búsqueda).

## Crear un flujo

MoleSignal crea cada flujo al escribir en él por primera vez, así que la mayoría de los flujos aparecen automáticamente. Crea un flujo
de antemano para definir desde el inicio la retención, los campos cifrados o el acceso a las consultas. Selecciona
**Crear flujo**:

| Campo | Regla |
|---|---|
| **Nombre del flujo** | `snake_case`, hasta 64 caracteres. |
| **Descripción** | Opcional. Indica qué datos pasan por el flujo. |
| **Tipo de señal** | **Registros**, **Métricas** o **Trazas**. |
| **Retención (días)** | Tiempo durante el que se conservan los datos. |
| **Campos indexados** | Campos separados por comas para los que se crea un índice de texto completo. |
| **Campos cifrados** | Campos separados por comas que se cifran antes de almacenarlos. No puedes cambiar esta configuración después. Consulta [Campos cifrados](#campos-cifrados). |
| **Permitir consultas** | Desactiva esta opción si el flujo de origen solo alimenta una canalización de enrutamiento. |

## Detalles del flujo

Selecciona un flujo para abrirlo. **Consultar datos** abre el flujo en el explorador correspondiente. El menú incluye
**Copiar ID del flujo** y **Eliminar flujo**. Pestañas:

| Pestaña | Contenido |
|---|---|
| **Vista general** | El estado operativo, los primeros datos recibidos, el acceso a las consultas y la evolución durante 24 horas de las filas escritas y los datos comprimidos. Si el flujo no tiene datos, aparecen **Configurar fuente de datos** y **Enviar datos de prueba**. |
| **Campos e índices** | Los campos con su tipo, tipo de índice y cifrado. Edita un campo para cambiar su índice o su enmascaramiento. Consulta [Esquema y campos](#esquema-y-campos). |
| **Retención** | La retención del flujo y, en los flujos de métricas, la reducción de la resolución de las muestras. Consulta [Retención y eliminación](#retención-y-eliminación). |
| **Uso** | Los elementos que usan el flujo: el endpoint de ingesta que escribe en él, las canalizaciones, las consultas guardadas y las reglas de alerta. Revisa esta pestaña antes de modificar o eliminar el flujo. |
| **Configuración** | **Descripción**, **Permitir consultas**, **Intervalo máximo de consulta (horas)**, **Combinar archivos pequeños por día**, **Dividir por campo** y, para los registros, **Agrupar por campo**. |

La página reúne los cambios de las pestañas en un borrador. **Guardar y aplicar** aplica todos los cambios a la vez y
**Descartar cambios** los elimina. Antes de guardar, la página advierte de los cambios que no puedes revertir:
acortar la retención elimina los datos que ya superan el nuevo plazo, y reducir la resolución elimina las muestras originales.

**Intervalo máximo de consulta** limita cuántas horas puede abarcar una consulta SQL o PromQL en el flujo. MoleSignal rechaza las consultas que
superan el intervalo, así que una consulta accidental de los «últimos 90 días» no puede recorrer un flujo grande de principio a fin. Deja el campo vacío
o escribe `0` para no aplicar ningún límite.

Desactiva **Permitir consultas** cuando una fuente que recibe todo el tráfico deba seguir recibiendo datos sin aparecer en los
selectores de consultas. Las canalizaciones de enrutamiento aún pueden leer el flujo. Administra los datos `extend` desde
**Ampliar tablas** en lugar de usar la interfaz genérica de consultas de telemetría.

## Esquema y campos

Cada campo tiene un nombre, un tipo de datos, un indicador `nullable`, un tipo de índice y un indicador `encrypted`. Los tipos de datos son `bool`, `int64`, `float64`, `utf8`, `timestamp` y `json`. MoleSignal agrega un campo al esquema cuando aparece por primera vez en los datos entrantes y rechaza cualquier valor de otro tipo con el mensaje `type mismatch on field`.

El tipo de índice determina qué estructura auxiliar crea MoleSignal para el campo:

| Tipo de índice | Efecto |
|---|---|
| `none` | Sin índice auxiliar. Es la opción predeterminada. |
| `exact` | Un índice invertido de coincidencia exacta sobre valores completos (un filtro de Bloom de Parquet para los campos que no son de texto), más el mínimo y el máximo de cada archivo. `=` e `IN` omiten los archivos que no contienen los valores sin abrirlos. Si hay pocas filas coincidentes, solo leen las páginas que las contienen. Una condición `LIKE` o `ILIKE` sobre un campo con hasta 65,536 valores por archivo omite los archivos en los que ningún valor contiene el texto. Usa este índice para identificadores como `trace_id`. |
| `full_text` | Un índice invertido que divide el texto en tokens para la búsqueda: las secuencias de letras y dígitos se tratan como palabras, y el texto CJK se divide en bigramas superpuestos de dos caracteres. Los literales de `MATCH`, `MATCH_TEXT`, `LIKE` e `ILIKE`, incluidos los signos de puntuación y el texto CJK, permiten omitir los archivos que no pueden contener coincidencias. Solo para campos `utf8`. |
| `bloom` | Un filtro de Bloom de Parquet, más un filtro de valores completos por archivo para los campos de texto e `int64`, y el mínimo y el máximo de cada archivo. `=` e `IN` omiten sin abrirlos los archivos que con certeza no contienen los valores. Usa este índice para campos con muchos valores que solo se consultan por igualdad, como los identificadores de solicitudes. |
| `skip` | El mínimo y el máximo de cada archivo, y todos los valores de los archivos que contienen como máximo 32 valores distintos. Las comparaciones, `IN`, `BETWEEN` y `LIKE` con prefijo usan estos datos para omitir archivos. |
| `ngram` | Los trigramas de los valores de cada archivo y los fragmentos de cinco bytes de cada bloque de 1,024 filas, sin distinguir entre mayúsculas y minúsculas. Si un literal de `LIKE`, `ILIKE` o `MATCH` contiene un trigrama ausente de un archivo, la consulta omite ese archivo. Si contiene un fragmento ausente de un bloque, la consulta omite ese bloque. Así, una búsqueda de un identificador u otra cadena poco frecuente solo lee los pocos bloques que pueden contenerla. Un literal de menos de cinco bytes obliga a leer todos los bloques. Un flujo con un campo `ngram` escribe sus archivos en páginas de 1,024 filas. Las páginas pequeñas y los fragmentos ocupan espacio: en una prueba en la que uno de estos campos ocupaba dos tercios de cada fila, el almacenamiento aumentó cerca de un 14%. Usa este índice para buscar por fragmento en URL, rutas y nombres de host, no en texto libre extenso. Solo para campos `utf8`. |
| `ip` | El rango de direcciones de cada archivo, con las direcciones IPv4 representadas en IPv6. `CIDR_MATCH(field, '10.0.0.0/8')` y `=` sobre una dirección usan ese rango para omitir archivos. Solo para campos `utf8`. |
| `key_value` | Las claves de primer nivel de un objeto JSON y sus valores. `json_text(field, 'key') = 'value'`, `IN` e `IS NOT NULL` omiten los archivos que no contienen la clave o el valor. Si hay pocas filas coincidentes, solo leen las páginas que las contienen. La comparación usa el valor tal como lo devuelve `json_text`: el texto sin cambios y los números y booleanos en su representación JSON. Solo para campos `json`. |
| `range` | El índice guarda los valores numéricos de cada fila y el mínimo y el máximo de cada archivo. Una consulta `count(*)` con condiciones `=` sobre campos `exact`, condiciones `>`, `>=`, `<` o `<=` con un número sobre campos `range` y un rango de tiempo obtiene el resultado del índice sin leer los archivos. Las demás comparaciones omiten los archivos fuera del rango. Solo para campos `int64`, `float64` y `timestamp`. |

Para cada campo indexado, MoleSignal también registra cuántas filas de cada archivo dejan el campo vacío. `IS NULL` omite los archivos en los que el campo siempre tiene un valor. Cualquier otra condición sobre el campo, incluidas las que comprueban si tiene un valor, como `IS NOT NULL` y `!= ''`, omite los archivos en los que nunca tiene un valor.

Las condiciones unidas por `OR` también omiten un archivo si los índices permiten descartar todas las ramas, cada una con el índice que corresponda. Por ejemplo, `level = 'error' OR status >= 500` omite un archivo si su índice de `level` no contiene `error` y su `status` nunca llega a 500.

Cuando un campo aparece por primera vez en los datos entrantes, su nombre determina el tipo de índice:

| Tipo de flujo | Campos | Tipo de índice |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`, `level`, `session_id`, `fingerprint`, `country`, `browser`, `application`, `environment` | `exact` |
| `traces` | `trace_id`, `span_id`, `parent_span_id`, `service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

Los demás campos nuevos reciben `none`, salvo que las reglas del flujo indiquen lo contrario. Consulta [Índice de campos nuevos](#índice-de-campos-nuevos). Un índice `exact` en `level` permite al histograma de logs contar los errores a partir del índice sin leer los archivos. Los flujos de RUM indexan las claves de `context`, `feature_flags` y `usr.extra` con `key_value`.

El cambio de tipo de índice se aplica de inmediato a los datos que se escriben después. MoleSignal vuelve a indexar en segundo plano los datos anteriores con la nueva configuración: reconstruye cada partición sellada a partir de sus archivos (de forma predeterminada, la partición se sella 48 horas después de que termina su intervalo) y reindexa los archivos más recientes cuando se sellan o se fusionan. Hasta entonces, cada archivo conserva el índice original. Esto no cambia los resultados de las consultas, solo la cantidad de archivos que leen. **Cobertura de campos indexados**, en **Vista general**, muestra cuántos archivos quedan pendientes. Cuando cambia el formato del índice de texto completo, como ocurrió al pasar a dividir el texto CJK en bigramas, MoleSignal también reconstruye en segundo plano los índices de los archivos anteriores con el nuevo formato.

Para modificar un campo, abre **Campos e índices**, selecciona la opción de edición del campo y elige:

- el **Tipo de índice**: **Sin indexar**, **Búsqueda de texto completo**, **Coincidencia exacta**, **Filtro de Bloom**,
  **Índice de omisión**, **Subcadena de n-gramas**, **Dirección IP** o **Claves JSON**. Búsqueda de texto completo, Subcadena
  de n-gramas y Dirección IP se aplican a campos de texto; Claves JSON se aplica a campos JSON;
- la **Política del flujo** de **Enmascaramiento de campos en los resultados**: **Heredar la regla global**, **Regla personalizada del flujo**
  o **Desactivar el enmascaramiento para este flujo**. Consulta [Enmascaramiento de campos](/es/settings/data-security#enmascaramiento-de-campos).
  El enmascaramiento no se aplica a los flujos de métricas.

Selecciona **Aplicar al borrador** y luego **Guardar y aplicar**. El tipo de datos de un campo no cambia.

### Índice de campos nuevos

En **Índices de campos**, en la pestaña **Configuración**, las reglas asignan un índice a los campos que aparecen por primera vez en el flujo
según su nombre. Selecciona **Agregar una regla**, ingresa un patrón de nombre de campo y elige un tipo de índice:
`*` representa cualquier secuencia de texto y `?` representa un carácter. Así, `*_id` coincide con `user_id` y
`order_id`, y `http.*` coincide con todos los campos bajo `http`. Se aplica la primera regla de la lista cuyo patrón
coincida con el nombre y cuyo tipo de índice sea compatible con el tipo de datos del campo. Un índice configurado para un campo
por nombre en **Campos e índices** tiene prioridad. Si ninguna regla coincide con el campo, se aplica el valor predeterminado indicado arriba.
Las reglas solo afectan a los campos que aparezcan a partir de ese momento. Modifica los campos existentes en **Campos e
índices**. Cada flujo admite hasta 32 reglas.

### Dividir por campo

Puedes dividir un flujo de logs o trazas por uno o dos campos de texto. En **Dividir por campo**, en la
pestaña **Configuración**, selecciona **Agregar un campo**, elige el campo y el método de división. MoleSignal divide los datos que escribe
a partir de ese momento en fragmentos según los valores de los campos y escribe cada fragmento en archivos propios.

- **Hash** distribuye los valores de manera uniforme en entre 2 y 64 fragmentos según su hash. Una consulta con una condición de igualdad
  sobre el campo (`=` o `IN`) solo lee los archivos de los fragmentos correspondientes a esos valores.
- **Primer carácter** divide los valores en 37 fragmentos según su primer carácter: uno por cada dígito y
  por cada letra (sin distinguir entre mayúsculas y minúsculas), y otro para el resto, incluidos los valores vacíos. Una consulta con una
  condición de igualdad sobre el campo o con un `LIKE` que empieza con texto (como `'web-%'`) solo lee
  los archivos del fragmento correspondiente a ese carácter. `ILIKE` también lee el fragmento que contiene el resto. La uniformidad
  de los fragmentos depende de los datos: los identificadores de traza hexadecimales solo usan 16.

Con dos campos, MoleSignal divide los archivos por los fragmentos de ambos, de modo que las cantidades de fragmentos se multiplican. **Dividir
por campo** muestra el total, que no puede superar 256. Si usas el primer carácter (37 fragmentos), puedes combinarlo con un hash de hasta 4
fragmentos. Una consulta con una condición sobre cualquiera de los dos campos lee menos archivos. Si incluye condiciones sobre ambos,
lee aún menos. Elige campos de división que aparezcan en casi todas las consultas, como el servicio, el espacio de nombres o el tenant.
Cuantos más fragmentos haya, más archivos habrá y más pequeños serán.

La configuración se aplica a los datos escritos después del cambio. Los archivos existentes no cambian. Cada consulta evalúa
cada archivo según los campos de división que se usaron al escribirlo, y el compactador solo fusiona archivos que se escribieron con los
mismos campos. Usa campos de texto sin cifrar para la división. Si eliges dos, deben ser distintos.

### Agrupar por campo

Puedes agrupar las filas dentro de los archivos de un flujo de logs por uno o dos campos. En **Agrupar por campo**,
en la pestaña **Configuración**, selecciona **Agregar un campo**, elige el campo y el **Bloque de tiempo**. En cada
archivo que se escribe después, MoleSignal organiza las filas en bloques de esa duración, del más reciente al más antiguo. Dentro de cada bloque, ordena las filas por
los valores de los campos y, para cada combinación de valores, de la más reciente a la más antigua.

Si solo se ordenan las filas por tiempo, un valor como el de un servicio puede aparecer en todas las páginas de un archivo. Con la agrupación, cada bloque
lo concentra en unas pocas páginas. Así, una consulta con una condición de igualdad sobre un campo de agrupación (`=` o `IN`)
solo lee esas páginas. Usa campos que aparezcan con frecuencia en las consultas y que tengan pocos valores, como
el servicio o el nivel.

Cada archivo agrupado también registra cuántas filas hay en cada minuto para cada combinación de valores de
los campos de agrupación. MoleSignal usa estos recuentos para resolver, sin leer el archivo, un conteo con condiciones de igualdad sobre campos de agrupación de texto, un conteo
agrupado por uno de ellos (`GROUP BY service`) o un histograma cuyas barras abarcan minutos completos. Esto también se aplica
cuando el intervalo de la consulta empieza o termina justo al inicio de un minuto
dentro del archivo. Si los minutos y los valores del archivo generan más de 65,536 combinaciones, el archivo no guarda estos recuentos.
Estos mismos recuentos permiten ubicar una página con las filas más recientes o más antiguas. Así, para obtener esa página, con o
sin condiciones de igualdad sobre los campos de agrupación, la consulta solo lee los minutos de los que proceden las filas.

El bloque de tiempo dura uno, cinco o diez minutos. La duración predeterminada es de un minuto. Los bloques más largos permiten omitir más páginas,
pero una consulta con un intervalo corto lee completos los bloques que se superponen con ese intervalo.

La agrupación es distinta de [Dividir por campo](#dividir-por-campo). La división escribe cada fragmento en sus propios
archivos, así que la consulta lee menos archivos, pero el flujo tiene más archivos y son más pequeños. La agrupación conserva los archivos
y ordena las filas dentro de ellos. Puedes combinar ambas opciones.

La configuración se aplica a los datos escritos después del cambio. Los archivos existentes conservan el orden
original y el compactador solo fusiona archivos con la misma agrupación. Usa campos
sin cifrar de texto, `int64` o `bool` para la agrupación. Si eliges dos, deben ser distintos.

### Campos cifrados

Marca un campo como `encrypted` al crear el flujo para que MoleSignal lo cifre antes de escribirlo en Parquet. La columna almacena el texto cifrado y una consulta normal devuelve ese texto cifrado. Recupera el valor con `decrypt(field)` en SQL:

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

No puedes cambiar el indicador más adelante porque los datos existentes quedarían ilegibles. MoleSignal deriva la clave de la clave de cifrado de la organización y de la clave raíz de cifrado `MS_CIPHER_KEY`. Si pierdes la clave raíz, no podrás recuperar los campos cifrados. Consulta [Seguridad y arquitectura multiinquilino](/es/security#cifrado-a-nivel-de-campo).

## Retención y eliminación

La retención determina cuándo elimina datos el compactador. Configúrala en la pestaña **Retención** mediante
**Retención de datos (días)** o deja el campo vacío para usar el valor predeterminado de la plataforma: 30 días. Este valor se configura en
[Configuración → Retención de datos](/es/settings/platform#retención-de-datos) de la organización `_sys`. El compactador elimina los datos
que superan el período de retención en la siguiente limpieza. Si acortas el período, la limpieza elimina los datos
que queden fuera del nuevo plazo. Los archivos eliminados no se pueden recuperar. Si una métrica de un flujo de métricas no registra muestras
durante el período de retención, también desaparece de la lista de métricas.

En la pestaña **Retención** de un flujo de métricas, **Reducir la resolución de las muestras antiguas** agrupa las muestras de cada
métrica del flujo que superan la antigüedad indicada en días en intervalos de 1 minuto a 1 día. Las muestras de una serie en cada intervalo
se convierten en un solo punto: el compactador promedia los valores, suma los conteos delta y elimina las muestras originales.
Así, las consultas que abarcan períodos largos leen muchos menos datos y los datos antiguos solo conservan la resolución del intervalo. No
es posible recuperar las muestras originales.

Para los logs y las trazas, la opción del flujo **Combinar archivos pequeños por día** (activada de forma predeterminada) combina los archivos
de un día en uno solo una hora después de que termine el día, siempre que el tamaño total no supere
el valor de `[compactor].target_size` del compactador. Así, una consulta que abarca varios días abre muchos menos archivos. La retención
se aplica por día: el compactador elimina el archivo combinado cuando vence la retención de todo el día. Desactiva la opción
en la pestaña **Configuración** del flujo para conservar los archivos por hora.

**Eliminar flujo** elimina el flujo y su configuración. Esta acción no se puede deshacer. Puede afectar a los
paneles, las vistas guardadas, las alertas, los informes y las canalizaciones. Revisa primero la pestaña **Uso**.

## Tareas de búsqueda

Una tarea de búsqueda es una consulta que se ejecuta en segundo plano y conserva el resultado hasta que vence la tarea.
Hay tres orígenes posibles:

- una consulta enviada con `Prefer: respond-async` o cuyo resultado previsto es demasiado grande para
  una solicitud interactiva;
- la carga retroactiva de una canalización;
- una consulta que envía Mole Agent.

Selecciona **Tareas de búsqueda** en el encabezado de **Flujos** para abrir la lista. Las vistas en la parte superior de la
lista filtran por estado y muestran el total correspondiente: **Todos**, **En cola**, **En ejecución**, **Listo**, **Fallido**
y **Cancelado**. La lista se actualiza automáticamente mientras haya tareas en cola o en ejecución.

Cada fila muestra el tipo de tarea (**Consulta** o **Carga retroactiva**), la instrucción, el estado, el
intervalo consultado, la hora de envío, la duración, las filas del resultado, el intento y el vencimiento. La
acción disponible depende del estado de la tarea:

| Estado | Acción |
|---|---|
| En cola o en ejecución | **Cancelar trabajo** |
| Listo | **Descargar resultados** |
| Fallido o cancelado | **Reintentar** |

**Eliminar** borra una tarea y su resultado, sin importar su estado.

Cada miembro puede ver y administrar las tareas que haya enviado. Quienes administran la organización y tienen el permiso
`org.running_queries.cancel` pueden ver y administrar todas las tareas de la organización. Consulta
[Consulta](/es/query#rangos-de-tiempo-y-tareas-asincrónicas) para obtener información sobre la API de tareas.

## Uso de ingesta y presupuestos

Selecciona **Uso de ingesta** en el encabezado de **Flujos** para ver cuántos datos se ingirieron de cada fuente en
las últimas 24 horas, los últimos 7 días o los últimos 30 días. Las tres vistas agrupan los mismos datos de distintas formas, por lo que
los totales coinciden:

| Vista | Qué cuenta como fuente |
|---|---|
| **Credencial** | Un token de API, un token de cliente de RUM, un conector o una cuenta con sesión iniciada. **Interno de la plataforma** corresponde a la telemetría de la propia plataforma. |
| **Flujo** | Un flujo, identificado por su nombre y tipo. |
| **Servicio** | El servicio que indica el evento en `service.name` o, en su defecto, en `service` o `service_name`. **Servicio sin nombre** agrupa los eventos que no indican ningún servicio. |

La ingesta contabiliza los bytes descomprimidos de los datos aceptados en cada solicitud: los eventos rechazados no cuentan
y cada solicitud cuenta una sola vez aunque el remitente la reintente. Los spans cuentan al llegar, antes del muestreo al final de la traza.
Las reproducciones de sesiones cuentan en la fila `rum_replay` de la vista **Flujo**. Cuando una solicitud incluye varios
servicios o flujos, la plataforma reparte los bytes en proporción al número de eventos, por lo que esas vistas muestran cifras
aproximadas en lugar de exactas.

Cuando no hay una cifra disponible, la vista muestra `–` en lugar de cero. Una cifra con `≥` indica un mínimo porque
la medición comenzó dentro del intervalo seleccionado. La línea sobre la lista indica desde cuándo. Las cifras aparecen en la página
en aproximadamente un minuto. Si un nodo se detiene de forma abrupta, puede perder los conteos de los últimos 15 segundos.

Selecciona una fila para ver el uso de la fuente por hora y su desglose según las otras dos vistas.

### Definir un presupuesto

Selecciona **Definir presupuesto** en una fila o marca varias filas para definir un mismo presupuesto para todas.

| Campo | Significado |
|---|---|
| **Período** | **Cada día** o **Cada mes**, según el calendario en UTC. |
| **Limitar** | De 1 MiB a 1 PiB. |
| **Umbral de aviso (%)** | La plataforma envía un aviso al alcanzar este porcentaje del límite y otro al alcanzar el límite. Con `0`, solo avisa al alcanzar el límite. Valor predeterminado: 80. |
| **A quién se notifica** | Miembros de la organización. De forma predeterminada, se notifica a quien define el presupuesto. |

El presupuesto solo genera avisos. Si una fuente lo supera, la ingesta responde y almacena los datos igual que antes, sin
descartarlos ni ralentizarlos. La plataforma avisa una vez por umbral en cada período. Si aumentas el límite, la plataforma vuelve a avisar
cuando se alcanza el nuevo umbral.

La plataforma envía las notificaciones mediante las políticas integradas **Presupuesto de ingesta casi agotado** y **Presupuesto
de ingesta superado**. Las notificaciones aparecen en el centro de notificaciones de la barra superior. Consulta
[Canales de notificación](/es/notification-channels) para cambiar quién más recibe los avisos y por qué medio.

La organización `_sys` no tiene presupuestos porque no tiene políticas de notificación. No puedes definir un presupuesto para
**Interno de la plataforma**, **Servicio sin nombre** ni **Otros servicios**. Esta última categoría agrupa los servicios que quedan fuera del
límite definido en la [Configuración de la plataforma](/es/settings/platform#uso-de-ingesta).

## Permisos

| Permiso | Acción permitida |
|---|---|
| `intake_usage.read` | Abrir **Uso de ingesta**, donde aparecen los nombres de los tokens y los miembros. Disponible para quienes tienen el rol de propietario o administrador. |
| `intake_budgets.manage` | Definir y eliminar presupuestos. Disponible para quienes tienen el rol de propietario o administrador. |
| `streams.read` | Listar flujos e inspeccionar sus metadatos. |
| `streams.query` | Consultar datos de los flujos con SQL. |
| `query.jobs.read`, `query.jobs.run` | Abrir **Tareas de búsqueda**; enviar, cancelar, reintentar y eliminar tareas. |
| `logs.write`, `metrics.write`, `traces.write`, `profiles.write` | Ingerir datos en un flujo existente del tipo de señal correspondiente. |
| `streams.create` | Crear un flujo. |
| `streams.configure` | Cambiar la configuración del esquema y la retención. |
| `streams.delete` | Eliminar un flujo. |
