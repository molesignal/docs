MoleSignal expone una API HTTP versionada. Los endpoints del producto usan `/api/v1`. La sonda de salud, las métricas de Prometheus, los enlaces de uso compartido públicos y algunos protocolos de compatibilidad también usan otras rutas.

## URL base

Para una instancia local:

```text
http://localhost:5080/api/v1
```

En producción, reemplaza el host por la dirección pública del despliegue, que es el valor de `[http].external_url`.

## Autenticación

Los endpoints protegidos aceptan un token de portador en el encabezado `Authorization`:

```http
Authorization: Bearer <token>
```

| Token | Cómo obtenerlo | Vigencia |
|---|---|---|
| Token de API | **Configuración de la cuenta → Tokens de API**, o [Emitir un token de API](/es/api/auth/issue-token). Los tokens tienen el formato `mspat-<36>`. | Hasta que se revoque, o hasta la expiración elegida. |
| Token de ingesta predeterminado | `GET /api/v1/me/api-tokens/default`. Limitado a `logs.write`, `metrics.write`, `traces.write`, `profiles.write` y `apm.deploy`. | No expira. |
| Token de cliente de RUM | `GET /api/v1/auth/tokens/rum?applicationId=<id>`. Limitado a `rum.write`. | No expira. |

Usa un token de API para scripts y recolectores. Consulta [Datasource](/es/intake#tokens-de-ingesta) para los tokens de ingesta.

La interfaz web inicia sesión con `POST /api/v1/auth/signin`, que establece cookies de sesión en lugar de devolver un token. El encabezado `Authorization` no acepta un token de sesión. Consulta [Iniciar sesión](/es/api/auth/login).

La autenticación construye un contexto de IAM con el sujeto, la organización activa o el alcance de plataforma, y los permisos efectivos. La organización de una solicitud siempre proviene de ese contexto. Los cuerpos de las solicitudes no pueden seleccionar otra organización.

## Rutas públicas y de autenticación propia

Algunas rutas no pueden usar un token de portador de organización. En su lugar, validan una credencial más específica o una política:

- inicio de sesión, política de registro y restablecimiento de contraseña;
- `GET /api/v1/healthz` y el `/metrics` de nivel superior;
- intercambio público de recursos compartidos y solicitudes de sesión de uso compartido;
- descargas de archivos firmadas y avatares públicos;
- endpoints de conectores de notificaciones push, que validan un token de push.

Una ruta pública no es irrestricta. Su manejador verifica la política de registro, un token de uso compartido, un token de descarga, una firma o la credencial del conector.

## Autorización

Un endpoint puede requerir una o más de estas condiciones:

- un permiso de organización como `streams.query`;
- un permiso de plataforma como `sys.telemetry.read`;
- la propiedad de un recurso, una relación con él o una concesión entre organizaciones.

`GET /api/v1/iam/capabilities` devuelve los permisos efectivos del sujeto actual. No infieras el acceso a partir del nombre de un rol ni de un elemento de menú visible.

## Solicitudes

- La mayoría de los cuerpos son JSON con `Content-Type: application/json`.
- Los endpoints de ingesta de compatibilidad usan la carga útil de su protocolo, como Protobuf, NDJSON o un cuerpo comprimido con gzip.
- Los cuerpos de solicitud de ingesta mayores de 2 MiB, o de 16 MiB para la ingesta JSON nativa, se rechazan con `413`.
- Las horas son números enteros en microsegundos desde la época Unix. Un momento se nombra por lo que ocurrió (`createdAt`, `expiresAt`), con `Time` agregado cuando una sola palabra sería ambigua (`startTime`); una duración termina en `Time` (`p95Time`) a menos que su nombre ya lo indique (`duration`). Los registros de telemetría nativos usan `_timestamp`, también en microsegundos.
- Codifica en URL los ids de ruta y los nombres de los streams.

## Respuestas y errores

Una respuesta exitosa es JSON a menos que el endpoint transmita o descargue un archivo. Una respuesta de error tiene un código de estado y un cuerpo JSON con un código `error` legible por máquina y un `message`:

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

Un error `validation_failed` agrega un arreglo `issues` con una entrada por cada campo no válido.

| Estado | `error` | Significado |
|---|---|---|
| `400` | `invalid_argument`, `validation_failed` | La solicitud o uno de sus parámetros no es válido. |
| `401` | `unauthorized` | El token falta, tiene un formato incorrecto, no es válido o expiró. |
| `403` | `forbidden` | Falta el permiso, la relación o el alcance. |
| `404` | `not_found` | El recurso no existe o no es visible en el alcance autorizado. |
| `409` | `conflict` | Un conflicto de estado o de unicidad. |
| `413` | `payload_too_large` | El cuerpo supera el límite. |
| `429` | `resource_exhausted` | Se aplica un límite de velocidad. Respeta el encabezado `Retry-After` cuando esté presente. |
| `499` | `cancelled` | La solicitud se canceló. |
| `503` | `unavailable` | Una dependencia no está disponible. |
| `500` | `internal` | Una falla interna. El cuerpo lleva el mensaje `internal error` y los detalles permanecen en el log del servidor. |

Una solicitud cuyo cuerpo no se puede analizar falla antes de llegar al endpoint. Esa respuesta es texto plano en lugar de JSON:

| Estado | Significado |
|---|---|
| `400` | El cuerpo no es JSON válido. |
| `415` | La solicitud no tiene `Content-Type: application/json`. |
| `422` | Falta un campo o tiene el tipo incorrecto. El texto nombra el campo. |

Todas las respuestas llevan los encabezados `X-Request-Id` y `X-Trace-Id`. Incluye ambos cuando informes una falla del lado del servidor.

## Paginación

Los endpoints que pueden devolver muchas filas aceptan `limit` y `cursor`. Esa respuesta lleva `items` y `nextCursor`. Pasa `nextCursor` como `cursor` para leer la página siguiente y detente cuando esté vacío. Otros endpoints de lista devuelven la lista completa. Consulta la página de cada endpoint.

## Consultas y trabajo de larga duración

La familia de consultas devuelve JSON normal, transmite NDJSON y ejecuta consultas largas como trabajos de búsqueda asíncronos. Una consulta demasiado grande responde `202` con un `jobId` y una ruta `monitor`. Quienes llaman en modo de transmisión deben manejar la entrega parcial y cancelar la solicitud cuando el resultado ya no sea necesario. Consulta [Query](/es/query).

Los artefactos grandes, como informes generados, blobs de perfiles y exportaciones, se entregan como archivos mediante un token de descarga con alcance en lugar de dentro de un cuerpo JSON.
