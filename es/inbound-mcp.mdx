**MCP entrante** permite que Claude Code, Cursor, Codex, ChatGPT y otros clientes MCP descubran y
operen MoleSignal mediante el mismo entorno de ejecución controlado que usa Mole Agent. El cliente se conecta
de una de estas dos formas:

- **stdio** (recomendado): el cliente ejecuta `molesignal mcp` de la CLI de MoleSignal, disponible en el paquete npm
  `@molesignal/cli`. Inicia sesión una sola vez en el navegador y la CLI reenvía todos los mensajes a
  el endpoint que se indica a continuación.
- **Streamable HTTP**: el cliente llama directamente al endpoint.

El endpoint es:

```text
https://molesignal.example.com/api/v1/mcp
```

El servidor usa Streamable HTTP y admite las versiones `2026-07-28`,
`2025-11-25`, `2025-06-18` y `2025-03-26` del protocolo MCP. El servidor no expone el protocolo heredado HTTP+SSE. La CLI
proporciona stdio.

Para cambiar la configuración del servidor, usa el permiso de administrador `agent.inbound_mcp.manage` en
**Mole Agent → Configuración → MCP entrante**.

## Antes de conectarte

1. Configura `http.external_url` con el origen público de MoleSignal para cualquier implementación que no use una dirección
   de bucle local. Consulta [Configuración](/es/configuration).
2. Abre **Mole Agent → Configuración → MCP entrante** y confirma que el servidor esté habilitado.
3. Copia el endpoint completo que muestra la página, incluidos el esquema y el host.
4. Elige OAuth 2.1, un token de API personal o un token de API de cuenta de servicio.

Los cambios en los límites y las listas de orígenes permitidos se aplican
al comenzar la siguiente solicitud HTTP de MCP. Las solicitudes activas conservan la configuración
con la que comenzaron.

## Conéctate mediante stdio

Inicia sesión una sola vez con la CLI de MoleSignal. La CLI requiere Node.js 20 o una versión posterior:

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

El navegador abre MoleSignal para que apruebes el inicio de sesión. La CLI guarda la credencial y la renueva. Solo tu cuenta puede leer el archivo
`~/.config/molesignal/config.json`. Luego agrega MoleSignal
al cliente como servidor stdio con el comando `npx -y @molesignal/cli mcp`:

| Cliente | Configuración |
|---|---|
| Claude Code | `claude mcp add --scope user molesignal -- npx -y @molesignal/cli mcp` |
| Cursor | `{"mcpServers": {"molesignal": {"command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` en `~/.cursor/mcp.json` |
| Codex | `codex mcp add molesignal -- npx -y @molesignal/cli mcp` |
| VS Code | `{"servers": {"molesignal": {"type": "stdio", "command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` en `.vscode/mcp.json` |
| Gemini CLI | `gemini mcp add molesignal npx -y @molesignal/cli mcp` |

`npx -y @molesignal/cli status` verifica la conexión y cuenta las herramientas. Si no tienes un navegador
disponible, configura `MOLESIGNAL_URL` y `MOLESIGNAL_TOKEN` (un token de API) en el entorno del servidor
en lugar de iniciar sesión. Si instalas la CLI con `npm install -g @molesignal/cli`,
ejecútala con el comando `molesignal`. [CLI de MoleSignal](/es/cli) describe todos sus comandos.

El **Prompt de configuración** en **Mole Agent → Configuración → MCP entrante** genera estas instrucciones para que las siga
una herramienta de agente. Selecciona **stdio** o **Streamable HTTP** encima del prompt.

## Conéctate con un token de API

Los tokens de API son útiles para clientes no interactivos y para la automatización.

<Tabs>
  <Tab title="Token de API personal">
    Crea un token desde **Identidad y acceso → Tokens de API**. El token usa la identidad del usuario actual y
    el rol que tiene asignado. Pásalo mediante el mecanismo de secretos o variables de entorno del cliente como
    `Authorization: Bearer <token>`.
  </Tab>
  <Tab title="Token de API de cuenta de servicio">
    Crea una cuenta de servicio desde **Identidad y acceso → Cuentas de servicio**. Al crearla, MoleSignal
    genera automáticamente un token de API vinculado a la cuenta y lo muestra en texto sin formato una sola vez.

    Las cuentas de servicio son identidades no interactivas. No pueden iniciar sesión en la interfaz web ni aprobar
    una concesión de OAuth. Pasa el token inicial mediante el mecanismo de secretos o variables de entorno
    del cliente como `Authorization: Bearer <token>`.
  </Tab>
</Tabs>

Nunca incluyas un token de API en un commit de un archivo de configuración de MCP a nivel de proyecto. Los ejemplos de Codex y Claude Code
muestran configuraciones con variables de entorno para uso no interactivo.

MCP entrante solo acepta tokens personales, tokens de cuentas de servicio y tokens de acceso de OAuth. Las credenciales de ingesta y RUM
no permiten acceder a este endpoint. MCP nunca devuelve credenciales en texto sin formato en sus
recursos, herramientas, historial de ejecución ni registros de auditoría.

## Descubrimiento y vigencia de OAuth

MoleSignal publica los metadatos de OAuth en:

```text
https://molesignal.example.com/.well-known/oauth-protected-resource/api/v1/mcp
https://molesignal.example.com/.well-known/oauth-authorization-server
```

El servidor de autorización admite el flujo de código de autorización con PKCE `S256`, la vinculación de recursos
según RFC 8707, el registro dinámico de clientes, la rotación de tokens de actualización y la revocación de familias de tokens.
Los tokens de acceso tienen una vigencia de una hora. Los tokens de actualización requieren el alcance `offline_access` y el
tipo de concesión `refresh_token`. Tienen una vigencia de 30 días y rotan con cada uso.

Revisa y revoca las conexiones activas de OAuth desde **Mole Agent → Configuración → MCP
entrante**. Debajo de las conexiones, el **Prompt de configuración** incluye el endpoint de esta implementación. Selecciona
**Copiar prompt** y pégalo en una herramienta de agente como Claude Code o Cursor para que agregue
MoleSignal como servidor MCP.

## Aislamiento entre organizaciones

Nunca envíes `userId` ni `orgId` en el endpoint, en un encabezado personalizado ni en los argumentos de las herramientas.
MoleSignal obtiene ambas identidades de la credencial autenticada, vuelve a cargar el estado actual de IAM
en cada solicitud y vincula la sesión de MCP con la credencial que la inició.

El conjunto efectivo de herramientas es:

```text
Inbound MCP surface ∩ credential IAM permissions ∩ workspace Tool Policy
```

Los perfiles de agente no restringen MCP entrante. Este endpoint no actúa como intermediario para los servidores MCP salientes configurados para Mole Agent
ni para sus herramientas remotas.

Ninguna credencial permite leer las filas ni los campos del [flujo `_audit`](/es/settings/data-security#flujo-de-auditoría) mediante MCP
entrante. Ábrelo en **Registros**.

## Empieza con los adaptadores de herramientas

`tools/list` anuncia un conjunto reducido de herramientas autorizadas: siete herramientas de lectura de uso común, controles de aprobación y ejecución,
y tres adaptadores de descubrimiento progresivo.

| Adaptador | Propósito |
|---|---|
| `tool_search` | Busca en todo el catálogo autorizado de MCP entrante. |
| `call_read_tool` | Ejecuta una herramienta de solo lectura o de comprobación previa que hayas encontrado. |
| `call_managed_tool` | Ejecuta un cambio gestionado que hayas encontrado e incluye el valor obligatorio de `idempotencyKey`. |

Ejemplos de solicitudes:

- «Busca incidentes recientes con las herramientas de MoleSignal y luego resume el incidente abierto de mayor impacto».
- «Busca las herramientas de páginas de estado y enumera los incidentes activos. No hagas cambios».
- «Prueba esta regla de alerta y actualízala solo después de obtener la confirmación o aprobación requerida».

Consulta [Catálogo y ejecución de herramientas](/es/tools) para conocer los esquemas de descubrimiento, los niveles de riesgo, el funcionamiento de las aprobaciones
y las áreas del producto compatibles.

## Límites de ejecución

| Límite | Valor predeterminado | Rango permitido |
|---|---:|---:|
| Tamaño de la solicitud | 1 MB | 1–8 MB |
| Tamaño de la respuesta | 1 MB | 1–8 MB |
| Llamadas HTTP simultáneas por credencial | 8 | 1–128 |
| Llamadas HTTP por minuto por credencial | 60 | 1–10 000 |
| Tiempo de espera de las herramientas de lectura | 30 segundos | 100 ms–300 segundos |

Edita estos valores en **Mole Agent → Configuración → MCP entrante**. La política de herramientas de la organización puede
aplicar un tiempo de espera más corto o un límite de tamaño de respuesta más bajo a una herramienta específica.

## Comprobaciones de Origin del navegador y Host

El servidor acepta solicitudes sin un encabezado `Origin` de clientes MCP que no se ejecutan en un navegador. Las solicitudes del navegador
deben tener el mismo origen o coincidir exactamente con un origen HTTP o HTTPS configurado en MCP entrante.

En implementaciones que no usan la interfaz de bucle invertido, el encabezado `Host` de la solicitud debe coincidir con `http.external_url`. Esta comprobación
evita ataques de revinculación de DNS contra servidores MCP locales.

## Soluciona problemas de conexión

| Síntoma | Qué comprobar |
|---|---|
| `401 missing Authorization Bearer token` | Ejecuta `codex mcp login molesignal` o configura una variable de entorno compatible para el token de API. |
| La página de autorización vuelve a pedir que inicies sesión | Usa el mismo esquema y host para la interfaz web, `http.external_url` y el punto de conexión de MCP. Evita mezclar `localhost` y `127.0.0.1`. |
| `duplicate field resource` | Elimina la opción `--oauth-resource` configurada manualmente y vuelve a registrar el punto de conexión. |
| La devolución de llamada de OAuth indica que se rechazó la conexión | Mantén el cliente MCP en ejecución hasta que el navegador se redirija a la dirección temporal de devolución de llamada en la interfaz de bucle invertido. Si el receptor dejó de escuchar, vuelve a ejecutar `codex mcp login`. |
| El punto de conexión de MCP devuelve `403` | Comprueba si el servidor está habilitado y revisa el origen del navegador, el estado de la credencial, el permiso de IAM y la política de herramientas. |
| No aparece una herramienta | Búscala con `tool_search`. Si no hay coincidencias, comprueba si está disponible a través de MCP entrante y revisa los permisos de IAM y la política de herramientas. |
