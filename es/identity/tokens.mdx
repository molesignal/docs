Un token de API permite que un programa haga llamadas a MoleSignal sin iniciar sesión. Un token no tiene un rol propio:
actúa como un miembro o una cuenta de servicio, y su alcance limita las acciones que puede realizar. Una cuenta de servicio es
una identidad para un programa: no puede iniciar sesión, tiene un rol y sus tokens actúan en su nombre.

## Tipos de tokens

| Tipo | Actúa como | Dónde se emite |
|---|---|---|
| **Token de API personal** | El miembro que lo emitió. | **Configuración de la cuenta → Tokens de API** |
| **Token de API de cuenta de servicio** | Una cuenta de servicio. | **Identidad y acceso → Tokens de API** o **Cuentas de servicio** |
| **Token de ingesta predeterminado** | Su titular, con acceso limitado a la escritura de datos. | **Fuente de datos**. Consulta [Tokens de ingesta](/es/intake#tokens-de-ingesta). |
| **Token de cliente de RUM** | Su aplicación de RUM, con acceso limitado a la escritura de datos de RUM. | **Fuente de datos**. Consulta [Tokens de ingesta](/es/intake#tokens-de-ingesta). |

Todos los tokens tienen el formato `mspat-<36>`, con letras minúsculas y dígitos. MoleSignal usa los primeros 10 caracteres para localizar
el token y solo almacena un hash del resto. Envía el token como credencial de tipo Bearer:

```http
Authorization: Bearer mspat-…
```

Los tokens no permiten acceder a la organización `_sys`.

## Qué puede hacer un token

Un token solo puede realizar las acciones que su miembro o cuenta de servicio tiene permitidas en el momento de la solicitud.
El alcance impone límites adicionales:

| Alcance | Permisos del token |
|---|---|
| **Igual que yo**, **Igual que la cuenta de servicio** | Los permisos vigentes del miembro o de la cuenta de servicio, incluidos los cambios de acceso. |
| **Política de permisos** | Los permisos vigentes de una [política de permisos](/es/identity/roles#políticas-de-permisos), como **Ingesta de datos**, incluidos los cambios en la política. |
| **Personalizado** | Los permisos seleccionados al emitir el token. La selección no cambia. |

Solo puedes asignar al token permisos que tenga la entidad que lo emite. Cuando un miembro pierde un permiso, todos
sus tokens también lo pierden. Si el miembro sale del espacio de trabajo o su cuenta queda desactivada, sus tokens
dejan de funcionar. Un rol en un recurso específico, ya sea por una concesión de acceso o porque el recurso se compartió, solo se aplica al token
si su alcance lo permite. Un token de cliente de RUM pertenece a su aplicación y solo permite
escribir datos de RUM.

## Emite un token personal

1. Abre **Configuración de la cuenta → Tokens de API** y selecciona **Nuevo token**.
2. Ingresa un **Nombre**, por ejemplo, `collector-production`.
3. Elige el **Alcance**: **Igual que yo**, una **Política de permisos** o un conjunto de permisos con **Personalizado**.
   Solo puedes elegir políticas y permisos que ya tengas. Al elegir una política, la interfaz muestra sus
   permisos.
4. Configura **Vence en (días)**: el valor predeterminado es 365 y el máximo es 1825. Deja el campo vacío para que el token nunca
   venza.
5. Selecciona **Crear token** y luego **Copiar token**. MoleSignal solo muestra el token una vez.

La lista muestra tus tokens con su alcance, tipo, vencimiento y último uso. **Revocar** invalida un token de forma
inmediata y permanente. Para administrar tus propios tokens, necesitas `personal_tokens.manage`, un permiso que incluye cada
rol integrado. Para emitir un token personal, inicia sesión. Un token no puede emitir otro token.

## Tokens de la organización

**Identidad y acceso → Tokens de API** muestra todos los tokens del espacio de trabajo, junto con el miembro, la cuenta
de servicio o la aplicación en cuyo nombre actúa cada uno y su alcance. Para ver la lista, necesitas `api_tokens.read`. Con
`api_tokens.revoke`, puedes revocar cualquier token o seleccionar **Emitir token de cuenta de servicio** para asignar un token a una
cuenta de servicio. Elige la **Cuenta de servicio**, el **Alcance** y el vencimiento.

## Cuentas de servicio

Usa una cuenta de servicio para un recolector, una canalización de CI, una integración o un agente de IA que se ejecute
sin intervención humana. Así, la automatización seguirá funcionando aunque un miembro salga del espacio de trabajo.

1. Abre **Cuentas de servicio** y selecciona **Crear cuenta de servicio**.
2. Ingresa un **Nombre**, por ejemplo, `deployment-automation`, una **Descripción** y un **Rol**.
3. Selecciona **Crear cuenta y token** y copia el token de API inicial. El token recibe los permisos
   del rol al crearlo, vence en 365 días y solo aparece una vez.

Selecciona una cuenta para administrarla:

| Acción | Efecto |
|---|---|
| **Guardar cambios** | Guarda el nuevo nombre, la descripción o el rol. Si el nuevo rol elimina un permiso, todos los tokens de la cuenta lo pierden de inmediato. Si agrega uno, solo lo reciben los tokens emitidos a partir de ese momento. |
| **Administrar tokens de API** | Abre **Tokens de API** con un filtro para esa cuenta. Desde allí puedes emitir más tokens o revocar uno. |
| **Desactivar** / **Habilitar** | Si desactivas una cuenta, ni la cuenta ni sus tokens pueden autenticarse hasta que vuelvas a habilitarla. |
| **Eliminar** | Elimina la cuenta y revoca todos sus tokens. Esta acción es irreversible. |

El **ID de la entidad** identifica la cuenta en los registros de auditoría y las concesiones de acceso. Para consultar las
cuentas de servicio, necesitas `service_accounts.read`. Para modificarlas, necesitas `service_accounts.manage`.

## Elige un token

| Quién hace la llamada | Token recomendado |
|---|---|
| Un recolector o un agente que envía telemetría | Un token de cuenta de servicio que siga la política **Ingesta de datos** o el token de ingesta predeterminado. |
| Código del navegador o de una aplicación móvil que envía datos de RUM | El token de cliente de RUM de la aplicación. Los usuarios finales pueden verlo. |
| Un proceso de CI que informa sobre despliegues | Un token que siga la política **Ingesta de datos**, que también incluye `apm.deploy`. |
| Una automatización que lee datos o modifica recursos | Un token de cuenta de servicio con un alcance limitado por una política o por permisos personalizados. |
| Un cliente de MCP o un script de ejecución manual | Un token de API personal con vencimiento. |

El navegador guarda la sesión en cookies HttpOnly. Por defecto, la sesión termina después de 24 horas
(`[auth].session_ttl_secs`). El encabezado `Authorization` no acepta la sesión, por lo que los programas siempre usan
un token de API.

## API de tokens

| Operación | Endpoint | Permiso |
|---|---|---|
| Emitir un token personal | `POST /api/v1/me/api-tokens` | `personal_tokens.manage` |
| Listar tus tokens | `GET /api/v1/me/api-tokens` | `personal_tokens.manage` |
| Revocar un token propio | `DELETE /api/v1/me/api-tokens/{id}` | `personal_tokens.manage` |
| Listar las opciones de alcance de un token: las políticas de permisos y los permisos de la organización | `GET /api/v1/me/api-tokens/scopes` | Un miembro con sesión iniciada |
| Emitir un token de cuenta de servicio | `POST /api/v1/auth/tokens` | `api_tokens.revoke` |
| Listar todos los tokens | `GET /api/v1/auth/tokens` | `api_tokens.read` |
| Revocar cualquier token | `DELETE /api/v1/auth/tokens/{id}` | `api_tokens.revoke` |

Consulta [Emitir un token de API](/es/api/auth/issue-token), [Listar tokens de API](/es/api/auth/list-tokens) y
[Revocar un token de API](/es/api/auth/revoke-token).
