| Endpoint | Autenticación |
|---|---|
| `GET /api/v1/healthz` | Ninguna |
| `GET /metrics` | Ninguna |
| `GET /api/v1/readyz` | Token de portador |
| `GET /api/v1/version` | Token de portador |

## Comprobación de actividad

```http
GET /api/v1/healthz
```

Comprobación compuesta del estado del nodo. Devuelve `200` si el nodo funciona correctamente y `503` con un campo `reason` si no puede acceder al almacenamiento de objetos. Úsala en las comprobaciones de contenedores y balanceadores de carga.

<ResponseExample>
```json 200
{ "status": "ok" }
```
</ResponseExample>

## Comprobación de disponibilidad

```http
GET /api/v1/readyz
Authorization: Bearer <token>
```

Comprueba si el nodo está listo para recibir tráfico. Devuelve `200` en cuanto el nodo arranca, porque no reproduce datos al iniciarse. Aunque el almacenamiento de objetos se degrade, el nodo sigue listo para atender tráfico de solo lectura. La solicitud requiere un token de portador, por lo que una comprobación sin credenciales recibe `401`. Usa `/api/v1/healthz` si la comprobación no puede enviar un token.

<ResponseExample>
```json 200
{ "status": "ready" }
```
</ResponseExample>

## Versión

```http
GET /api/v1/version
Authorization: Bearer <token>
```

Devuelve la versión del producto, el commit y la rama, la fecha y hora de compilación, el ID de compilación, el canal de publicación y la edición.

<ResponseExample>
```json 200
{
  "version": "26.1.0.0",
  "commit": "<git-sha>",
  "branch": "main",
  "buildEpochSecs": 1790000000,
  "buildId": "<build-id>",
  "releaseChannel": "alpha",
  "edition": "oss"
}
```
</ResponseExample>

## Métricas

```http
GET /metrics
```

Expone métricas del proceso y de los subsistemas en el formato de Prometheus (`text/plain; version=0.0.4`), como las tasas de aciertos de `cache_*` y las métricas `wal_*`, `object_store_*` y `storage_reconciler_issues_total`. Restringe el acceso a esta ruta en el proxy o en la capa de red. Consulta [Observabilidad del propio sistema](/es/self-observability).
