```http
POST /api/v1/_cloudflare
```

El endpoint acepta NDJSON, incluido el cuerpo comprimido con gzip que suele enviar Cloudflare Logpush. El endpoint no usa un token de portador. Crea un conector de tipo `cloudflare_logpush` con un `pushToken` de al menos 16 caracteres y un `target_stream`, y envía el token en el encabezado `X-Connector-Token`. También puedes usar el parámetro de consulta `?token=`. Si el token no es válido, el endpoint responde con `401`.

Cada línea se convierte en un evento de registro en el flujo `target_stream` (`cloudflare` de forma predeterminada). El endpoint almacena los campos de la línea sin modificarlos y asigna al evento la hora de recepción. Si la solicitud se procesa correctamente, el endpoint responde con `204`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_cloudflare \
  -H 'X-Connector-Token: <pushToken>' \
  -H 'content-encoding: gzip' \
  --data-binary @logs.ndjson.gz
```
</RequestExample>

Consulta [Conectores](/es/connectors) para configurar el conector.

## Verifica la entrega y la selección del flujo

1. Confirma que el conector esté habilitado y que el emisor use el token de envío del conector. Un token de API normal no reemplaza un token de envío.
2. Al establecer `configJson` directamente mediante la API de conectores, usa `target_stream` para el flujo de destino, no `targetStream`. La clave del token sigue siendo `pushToken`, en camelCase.
3. Envía un evento de prueba con un marcador único y anota la hora de recepción. En **Registros**, selecciona el flujo de destino y un intervalo que incluya la hora de recepción. Luego, busca el marcador.
4. Si la solicitud se procesa correctamente pero el flujo de destino está vacío, revisa el flujo predeterminado correspondiente y el valor guardado para el campo de destino. Una confirmación HTTP no reemplaza una consulta en el flujo de destino.

Protege el token como cualquier otra credencial. Si lo pasas como parámetro de consulta de la URL, no incluyas la URL completa en registros, tickets ni capturas de pantalla. Antes de reintentar una solicitud fallida, distingue entre los problemas con el token o con el estado del conector y los errores de formato o compresión de los datos enviados.
