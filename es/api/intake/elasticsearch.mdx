```http
POST /api/v1/_bulk
```

Ingesta de NDJSON compatible con `_bulk` de Elasticsearch para Filebeat, Logstash y el destino `elasticsearch` de Vector. La solicitud requiere `logs.write`. El endpoint acepta un cuerpo con `Content-Encoding: gzip`.

| Acción | Comportamiento |
|---|---|
| `index`, `create`, `update` | El endpoint almacena el documento de origen como un evento de registro. |
| `delete` | El endpoint omite la acción y no incluye un elemento en la respuesta. Este endpoint nunca elimina datos de telemetría. |

El campo `_index` de la acción selecciona el flujo de registros de destino. Si falta, se usa el encabezado `stream-name`. Si tampoco se especifica el encabezado, se usa `default`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## Elige este endpoint

Usa este endpoint si un emisor existente puede enviar datos en el formato NDJSON de la API masiva de Elasticsearch. Es un adaptador de ingesta, no un clúster de Elasticsearch: esta API no admite búsquedas, plantillas de índice, IDs de documentos ni actualizaciones de documentos existentes. Usa [consultas SQL](/es/query) para leer los eventos almacenados.

## Crea un lote válido

- Envía un objeto de acción y un objeto de documento en líneas separadas para cada operación `index` o `create`. Termina el lote con un salto de línea.
- Para `update`, coloca los campos del evento dentro de `doc`. El endpoint crea un evento con esos campos en lugar de modificar un evento almacenado.
- Define `_index` en la acción para elegir un flujo. Si no lo defines, usa `stream-name` o deja que el endpoint use el flujo `default`.
- Para conservar la hora del evento, especifica `_timestamp` como una marca de tiempo Unix en microsegundos, expresada como un número entero. De lo contrario, el receptor usa la hora actual.
- El endpoint omite las acciones `delete`. Estas acciones no eliminan datos de telemetría ni generan elementos de eventos almacenados en la respuesta.

## Verifica la ingesta

Para un lote de un solo evento, la respuesta debe incluir `errors: false` y un elemento con `status: 201`. Compara la cantidad de elementos con la cantidad de eventos que esperabas ingerir. Una respuesta HTTP exitosa no basta para confirmar que el lote tenga la estructura prevista.

Abre **Registros**, selecciona el flujo indicado en `_index` y usa un intervalo de tiempo que incluya la marca de tiempo del evento. Haz una consulta con un campo distintivo del ejemplo. Si el evento no aparece, verifica el flujo seleccionado y la unidad de la marca de tiempo antes de reenviar todo el lote. Esta interfaz no usa los IDs de documentos de Elasticsearch para evitar duplicados en los reintentos.

## Soluciona problemas con solicitudes rechazadas

| Síntoma | Qué verificar |
|---|---|
| Error de autenticación o de permisos | Usa un token de API de la organización correspondiente con el permiso `logs.write`. |
| La acción o el documento no es un objeto JSON | Verifica los saltos de línea del NDJSON. No envíes un arreglo JSON ni un objeto con formato de varias líneas. |
| Acción desconocida | Usa los nombres de las acciones admitidas que aparecen arriba. |
| Error de descompresión | Define `Content-Encoding: gzip` solo si el cuerpo está comprimido con gzip. |
| Respuesta exitosa con menos eventos de los esperados | Verifica que cada acción de escritura tenga su línea de documento y distingue las acciones `delete` omitidas de los eventos almacenados. |
