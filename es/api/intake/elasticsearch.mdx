```http
POST /api/v1/_bulk
```

Ingesta NDJSON compatible con `_bulk` de Elasticsearch para Filebeat, Logstash y el sink `elasticsearch` de Vector. La llamada requiere `logs.write`. Se acepta un cuerpo con `Content-Encoding: gzip`.

| Acción | Comportamiento |
|---|---|
| `index`, `create`, `update` | El documento de origen se almacena como un evento de registro. |
| `delete` | Se omite sin un elemento de respuesta. La telemetría nunca se elimina a través de este endpoint. |

El `_index` de una acción selecciona el flujo de registros de destino. Sin él, se aplica la cabecera `stream-name` y, después, `default`.

Un documento con un valor que no se ajusta al tipo de su campo en el flujo se rechaza por sí solo. Su elemento tiene `status: 400` y un `error` con el `reason`, `errors` es `true`, y los demás documentos se escriben. Filebeat y Logstash no reintentan ese elemento.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## Elige este endpoint

Usa este endpoint cuando un emisor existente pueda emitir NDJSON masivo de Elasticsearch. Es un adaptador de ingesta, no un clúster de Elasticsearch: esta API no ofrece búsqueda, plantillas de índice, IDs de documento ni semántica de actualización en el lugar. Usa [consultas SQL](/es/query) para leer los eventos almacenados.

## Construye un lote válido

- Envía un objeto de acción y un objeto de documento en líneas separadas para cada operación `index` o `create`. Termina el lote con un salto de línea.
- Para `update`, coloca los campos del evento bajo `doc`; los campos se convierten en un evento nuevo en lugar de modificar un evento almacenado.
- Define `_index` en la acción para elegir un flujo. De lo contrario, usa `stream-name` o acepta el flujo `default`.
- Proporciona `_timestamp` como una marca de tiempo Unix entera en microsegundos cuando quieras conservar la hora del evento. De lo contrario, el receptor usa la hora actual.
- Una acción `delete` se omite. No elimina telemetría ni aporta un elemento de evento almacenado a la respuesta.

## Verifica la ingesta

Para un lote de un solo evento, espera `errors: false` y un elemento de respuesta con `status: 201`. Compara el número de elementos con el número de eventos que pretendías ingerir; un éxito HTTP por sí solo no demuestra que el lote se haya construido como se pretendía.

Abre **Registros**, selecciona el flujo elegido por `_index` y usa un rango de tiempo que contenga la marca de tiempo del evento. Consulta un campo distintivo de la muestra. Si el evento no aparece, revisa la selección del flujo y la unidad de la marca de tiempo antes de reenviar el lote completo. Esta interfaz no usa los IDs de documento de Elasticsearch para deduplicar reintentos.

## Soluciona problemas de una solicitud rechazada

| Síntoma | Qué revisar |
|---|---|
| Error de autenticación o de permisos | Usa un API Token de la organización prevista con `logs.write`. |
| La acción o el documento no es un objeto JSON | Revisa los límites de línea del NDJSON. No envíes un array JSON ni un objeto multilínea con formato indentado. |
| Acción desconocida | Usa los nombres de acción compatibles indicados arriba. |
| Error de descompresión | Define `Content-Encoding: gzip` solo cuando el cuerpo esté realmente comprimido. |
| Éxito con menos eventos de los esperados | Revisa que cada acción de escritura tenga su línea de documento y distingue las eliminaciones omitidas de los eventos almacenados. |
| `errors: true` con elementos de estado `400` | Un valor no se ajusta al tipo de su campo en el flujo, como texto en un campo `int64`; el `reason` del elemento indica el campo. Envía el tipo que el flujo almacena para ese campo o conviértelo en una pipeline. |
