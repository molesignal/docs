Configura un SDK o un Collector de OpenTelemetry para que envíe datos a MoleSignal. Ambos transportes requieren un token de portador con el permiso de escritura de la señal: `logs.write`, `metrics.write` o `traces.write`.

| Transporte | Punto de conexión |
|---|---|
| OTLP sobre HTTP | `POST /api/v1/logs`, `POST /api/v1/metrics`, `POST /api/v1/traces` |
| OTLP sobre gRPC | `:4317` |

El puerto `5082` es el puerto interno de confianza del clúster y no funciona como receptor OTLP.

## OTLP sobre HTTP

Configura el punto de conexión del exportador con la ruta base `/api`. Los exportadores agregan automáticamente `/v1/logs`, `/v1/metrics` y `/v1/traces`.

| Encabezado | Notas |
|---|---|
| `Authorization` | `Bearer <token>`. |
| `Content-Type` | `application/x-protobuf` o `application/json`. La codificación JSON representa los enteros de 64 bits como cadenas, y MoleSignal admite tanto cadenas como números. |
| `stream-name` | Opcional. Indica el flujo de destino. El valor predeterminado es `default`. |

No comprimas el cuerpo de la solicitud: si está comprimido, MoleSignal devuelve `400`. Desactiva la compresión en el exportador. El límite del cuerpo es de 2 MiB. Si la solicitud se procesa correctamente, MoleSignal devuelve `200` con `{"partialSuccess":null}`.

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP sobre gRPC

El receptor en `:4317` ofrece los servicios de registros, métricas, trazas y perfiles sin TLS. Envía `authorization: Bearer <token>` y, de forma opcional, `stream-name` como metadatos de gRPC. Para el tráfico que salga de una red de confianza, termina TLS antes de que llegue al puerto.

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## Campos almacenados

Los atributos de recursos y registros pasan a ser campos de nivel superior y conservan sus claves originales. Consulta [Campos almacenados](/es/query#campos-almacenados) para ver las columnas de registros, spans y métricas.

## Errores

| Estado | Causa |
|---|---|
| `400` | El cuerpo está comprimido o no contiene datos OTLP válidos. |
| `401` | Falta el token o no es válido. |
| `403` | El token no tiene el permiso de escritura de la señal o la solicitud envía los datos a un [flujo de la plataforma](/es/streams#flujos-de-la-plataforma). |
| `404` | El punto de conexión del exportador omite `/api`, por lo que la solicitud llega a `/v1/logs`. |
| `413` | El cuerpo supera los 2 MiB. |

Si HTTP rechaza una solicitud con `403`, gRPC devuelve `PERMISSION_DENIED` para esa misma solicitud.
