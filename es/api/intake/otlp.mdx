Point an OpenTelemetry SDK o Collector at MoleSignal. Ambos transportes requieren una credencial bearer con el permiso de escritura de la señal: `logs.write`, `metrics.write` o `traces.write`.

| Transporte | Endpoint |
|---|---|
| OTLP sobre HTTP | `POST /api/v1/logs`, `POST /api/v1/metrics`, `POST /api/v1/traces` |
| OTLP sobre gRPC | `:4317` |

El puerto `5082` es el puerto interno de confianza del clúster y no es un receptor OTLP.

## OTLP sobre HTTP

Configura el endpoint del exportador con la ruta base `/api`. Los exportadores añaden `/v1/logs`, `/v1/metrics` y `/v1/traces` por sí mismos.

| Encabezado | Notas |
|---|---|
| `Authorization` | `Bearer <token>`. |
| `Content-Type` | `application/x-protobuf` o `application/json`. La codificación JSON escribe los enteros de 64 bits como cadenas, y MoleSignal lee por igual cadenas y números. |
| `stream-name` | Opcional. El stream de destino. El valor predeterminado es `default`. |

El cuerpo no debe ir comprimido: un cuerpo comprimido responde `400`. Desactiva la compresión en el exportador. El límite del cuerpo es de 2 MiB. Una solicitud correcta responde `200` con `{"partialSuccess":null}`. Cuando el stream rechaza algunos registros de log o puntos de datos porque un valor no encaja con el tipo de su campo, los demás se escriben y `partialSuccess` contiene `rejectedLogRecords` o `rejectedDataPoints` con un `errorMessage` que indica el primer motivo. Los exportadores no los reintentan. La misma respuesta llega por gRPC.

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP sobre gRPC

El receptor en `:4317` sirve los servicios de logs, métricas, trazas y perfiles sin TLS. Envía `authorization: Bearer <token>` y el `stream-name` opcional como metadatos de gRPC. Termina TLS delante del puerto para el tráfico que sale de una red de confianza.

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## Campos almacenados

Los atributos de recurso y de registro se convierten en campos de nivel superior con sus claves originales. Consulta [Campos almacenados](/es/query#campos-almacenados) para ver las columnas de logs, spans y métricas.

## Errores

| Estado | Causa |
|---|---|
| `400` | Un cuerpo comprimido o un cuerpo que no es OTLP válido. |
| `401` | Token ausente o no válido. |
| `403` | El token no tiene el permiso de escritura de la señal, o los datos se envían a un [stream de plataforma](/es/streams#flujos-de-plataforma). |
| `404` | El endpoint del exportador omite `/api`, por lo que la solicitud llega a `/v1/logs`. |
| `413` | El cuerpo supera los 2 MiB. |

Por gRPC, una solicitud que HTTP rechaza con `403` responde `PERMISSION_DENIED`.
