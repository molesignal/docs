```http
POST /api/v1/prometheus/api/v1/write
```

Acepta solicitudes `remote_write` de versión 1 de Prometheus y VictoriaMetrics en formato protobuf comprimido con Snappy. La llamada requiere `metrics.write` y devuelve `204` si se completa correctamente.

El encabezado `stream-name` indica el flujo de métricas donde se escribe la solicitud. Si falta el encabezado, se usa `default`. Cada flujo de métricas contiene las métricas de una fuente. La etiqueta `__name__` pasa al campo `metric_name`, las demás etiquetas se convierten en campos y la muestra pasa al campo `value`. Si el nombre de una etiqueta coincide con el de un campo de métrica, como `metric_name` o `metric_kind`, la etiqueta se conserva como `exported_<name>`. El sistema omite los histogramas nativos y los metadatos de las métricas, y guarda los ejemplares junto a las muestras.

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

Consulta las métricas por nombre con PromQL, independientemente del flujo que las contenga. Una serie de `http_requests_total` con las etiquetas `service` y `status` se convierte en:

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

Los **límites** se aplican por serie y por organización: un máximo de 64 etiquetas por serie, nombres de etiqueta de hasta 128 bytes, valores de etiqueta de hasta 2048 bytes y límites de cardinalidad para las series activas y nuevas. Los límites del proceso se definen en `[intake.prometheus]` en [Configuración](/es/configuration#ingesta). La opción **Configuración → Cardinalidad de métricas** de la plataforma limita las series activas por organización y por métrica. Consulta los límites con `GET /api/v1/settings/series_limits` y configúralos con `PUT` en la misma ruta. El cuerpo tiene el mismo formato en ambos casos: `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }`. Ambas operaciones requieren `sys.settings.limits.manage` en el ámbito del sistema. El límite por métrica no puede superar el límite por organización, y ninguno de los dos puede superar los 100 000 000.
