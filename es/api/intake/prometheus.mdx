```http
POST /api/v1/prometheus/api/v1/write
```

Acepta solicitudes `remote_write` versión 1 de Prometheus y VictoriaMetrics, que son protobuf comprimido con snappy. La llamada requiere `metrics.write` y responde `204` si se completa correctamente. Cuando el flujo rechaza algunas muestras porque un valor no encaja en el tipo de su campo, las demás muestras se escriben y la respuesta es `400`, indicando cuántas se rechazaron y el primer motivo. Prometheus no reintenta una respuesta `400`.

Una solicitud se escribe en el flujo de métricas indicado por el encabezado `stream-name`, o en `default` cuando el encabezado no está presente. Un flujo de métricas contiene las métricas de una fuente. La etiqueta `__name__` se convierte en el campo `metric_name`, las etiquetas restantes se convierten en campos y la muestra se convierte en el campo `value`. Una etiqueta con el mismo nombre que un campo de métrica, como `metric_name` o `metric_kind`, se conserva como `exported_<name>`. Los histogramas nativos y los metadatos de métricas se omiten, y los ejemplares se almacenan junto a las muestras.

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

Consulta las métricas con PromQL por sus nombres, sea cual sea el flujo que las contenga. Una serie de `http_requests_total` con las etiquetas `service` y `status` se convierte en:

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**Límites** se aplican por serie y por organización: como máximo 64 etiquetas por serie, nombres de etiqueta de hasta 128 bytes, valores de etiqueta de hasta 2048 bytes y límites de cardinalidad para series activas y nuevas. Los límites del proceso están en `[intake.prometheus]` en [Configuración](/es/configuration#ingesta). Las series activas de una organización y de una de sus métricas están limitadas por el ajuste de plataforma **Configuración → Cardinalidad de métricas**, que se lee con `GET /api/v1/settings/series_limits` y se establece con `PUT` y el mismo cuerpo, `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }`, ambos con `sys.settings.limits.manage` en el ámbito del sistema. El límite de métricas es como máximo el límite de la organización, y ambos son como máximo 100.000.000.
