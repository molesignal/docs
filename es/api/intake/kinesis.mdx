```http
POST /api/v1/_kinesis_firehose
```

Acepta entregas de AWS Data Firehose a un punto de conexión HTTP. El punto de conexión no usa un token de portador. Crea un conector de tipo `aws_kinesis_firehose` con un `pushToken` de al menos 16 caracteres y un `target_stream`, y configura el token como clave de acceso en Firehose. El punto de conexión lee el token del encabezado `X-Amz-Firehose-Access-Key` y también acepta `X-Connector-Token` y `?token=`. Si el token es incorrecto, el punto de conexión responde con `401`.

Cada registro contiene `data` en base64. El punto de conexión decodifica los datos, los divide en líneas y convierte cada línea no vacía en un evento de registro en el flujo `target_stream` (de forma predeterminada, `kinesis`). Si una línea contiene un objeto JSON, el punto de conexión convierte sus propiedades en campos. Si contiene texto sin formato, lo guarda en el campo `message`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_kinesis_firehose \
  -H 'X-Amz-Firehose-Access-Key: <pushToken>' \
  -H 'content-type: application/json' \
  -d '{"requestId":"req-1","timestamp":1790000000000,"records":[{"data":"eyJsZXZlbCI6ImluZm8ifQo="}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{ "requestId": "req-1", "timestamp": 1790000000123 }
```
</ResponseExample>

La respuesta devuelve el mismo `requestId` e incluye un `timestamp` en milisegundos, tal como exige Firehose. Consulta [Conectores](/es/connectors) para configurar el conector.

## Verifica la entrega y la selección del flujo

1. Confirma que el conector esté habilitado y que el emisor use el token de envío del conector. Un token de API común no sustituye a un token de envío.
2. Al definir directamente `configJson` mediante la API de conectores, usa `target_stream` para el flujo de destino, no `targetStream`. La clave del token conserva el formato camelCase: `pushToken`.
3. Envía un evento de prueba con un marcador único y anota la hora de recepción. En **Registros**, selecciona el flujo de destino y un intervalo que incluya la hora de recepción. Luego, busca el marcador.
4. Si la solicitud se completa correctamente, pero el flujo de destino está vacío, revisa el flujo predeterminado correspondiente y el valor guardado en el campo de destino. Una confirmación HTTP no sustituye una consulta en el flujo de destino.

Protege el token como cualquier otra credencial. Si lo pasas como parámetro de consulta de una URL, no incluyas la URL completa en registros, tickets ni capturas de pantalla. Antes de reintentar una solicitud fallida, distingue los problemas con el token o el estado del conector de los errores de formato o compresión de los datos.
