```http
POST /api/v1/scheduled_pipelines
```

Crea un pipeline. La ruta conserva el nombre `scheduled_pipelines` en todos los modos. La llamada requiere el permiso `pipelines.create`.

**Cuerpo**

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `name` | cadena | Sí | Nombre del pipeline. |
| `sourceStream` | cadena | Sí | Primer flujo que lee el pipeline. Usa una cadena vacía para un pipeline de alertas. |
| `targetStream` | cadena | Sí | Primer flujo en el que escribe el pipeline. Si un pipeline programado lee ese mismo flujo, la llamada devuelve `409`. Usa una cadena vacía para un pipeline de alertas. |
| `functionSteps` | objeto | Sí | Pasos, modo y configuración de un pipeline programado, o condiciones de un pipeline de alertas. Consulta los detalles a continuación. |
| `cron` | cadena | Sí | `every:30s`, `every:5m` o `every:1h` para un pipeline programado. Usa una cadena vacía para un pipeline en tiempo real o de alertas. |
| `lookbackSecs` | entero | No | Segundos hacia atrás que abarca la primera lectura programada de un origen. Valor predeterminado: 300. Un pipeline programado requiere un valor positivo. |
| `enabled` | booleano | No | Valor predeterminado: `true`. |

Campos de `functionSteps`:

| Campo | Notas |
|---|---|
| `mode` | `scheduled` (predeterminado), `realtime` o `alert`. |
| `signalType` | `logs`, `metrics` o `traces`. Un pipeline en tiempo real también admite `profiles`. Un pipeline de métricas, trazas o perfiles en tiempo real modifica su flujo directamente: `targetStream` coincide con `sourceStream` y no incluye pasos de enrutamiento ni `retainSource`. Consulta [Métricas y trazas](/es/pipelines#métricas-y-trazas). Un pipeline de perfiles usa `default` como origen. Consulta [Perfiles](/es/pipelines#perfiles). Un pipeline de alertas no tiene tipo de señal. |
| `steps` | Pasos en orden de ejecución. Un paso de VRL tiene `transformName`, `script` y `kind` con el valor `vrl`. Un paso de enrutamiento tiene `kind` con el valor `builtin`, `operation` con el valor `route` y un objeto `routing`. Un pipeline de alertas admite hasta 20 pasos y no admite pasos de enrutamiento. Un paso de resumen con IA tiene `transformName`, `kind` con el valor `ai_summary`, `prompt` y `annotation`, la anotación donde guarda la respuesta (valor predeterminado: `ai_summary`). Un paso de llamada a la API tiene `kind` con el valor `http_enrich` y `connectorId`, que identifica un conector HTTP de la organización. Un paso de consulta tiene `kind` con el valor `query_enrich`, `language` (`sql`, el valor predeterminado, o `promql`), `stream`, `streamType` (`logs`, el valor predeterminado, `metrics` o `traces`), `statement`, `windowSecs` (valor predeterminado: 300; máximo: 86400), `maxRows` (valor predeterminado: 5; máximo: 50) y `annotation` (valor predeterminado: `query_result`). Consulta [Pasos de los pipelines de alertas](/es/pipelines/alert-events#pasos). Un pipeline en tiempo real también admite los pasos de conteo `generate_metric`, `quota` y `throttle`, con los campos que se indican a continuación. |
| `alert` | Solo para pipelines de alertas. Define cuándo se ejecuta el pipeline, en qué condiciones y en qué orden: `stage` (`open`, el valor predeterminado, o `notify`), `policies` (políticas de notificación a las que se aplica un pipeline `notify`; si la lista está vacía, se aplica a todas las políticas del evento de alerta), `sources` (`rule`, `external`, `synthetic`, `noData` y, para `notify`, también `manual`), `severities` (`info`, `warning`, `error`, `critical`), `labels` (objeto con las etiquetas y los valores que debe tener el evento) y `order` (entero con valor predeterminado de 0). Una lista vacía admite todos los orígenes o niveles de gravedad. Consulta [Pipelines de alertas](/es/pipelines/alert-events#crear-un-flujo-de-procesamiento-mediante-la-api). |
| `sources` | Flujos de lectura. El pipeline lee `sourceStream` primero. Un pipeline programado también lee los demás flujos de la lista, hasta 8 en total. Un pipeline en tiempo real solo acepta `[source_stream]`. |
| `sinks` | Flujos de escritura. `targetStream` va primero y cada uno de los demás flujos de la lista recibe todos los eventos, hasta 8 flujos en total. Un pipeline en tiempo real solo acepta `[target_stream]`. |
| `sinkConnectors` | Solo para pipelines programados. Identificadores de los conectores que reciben todos los eventos. |
| `sinkTables` | Solo para pipelines programados. Nombres de hasta 8 tablas de extensión que reciben una fila por evento. Consulta [Escribir en una tabla de extensión](/es/pipelines#escribir-en-una-tabla-de-enriquecimiento). |
| `delaySecs` | Solo para pipelines programados. Segundos que espera el pipeline antes de leer el intervalo más reciente para que lleguen los eventos retrasados. De 0 a 3600; valor predeterminado: 60. |
| `retry` | Solo para pipelines programados. `runRetries` indica cuántos intentos adicionales hace el pipeline si falla la lectura o la escritura de una ventana. `deliveryRetries` indica cuántos intentos adicionales hace al entregar eventos a un conector. Ambos admiten valores de 0 a 10, con 3 como valor predeterminado. |
| `deadLetterStream` | Solo para pipelines programados. Flujo de logs para los eventos que el pipeline no pudo procesar, escribir ni entregar. No puede ser un flujo que el pipeline lea o en el que escriba. |
| `dedupeField` | Solo para pipelines programados. En una misma ejecución, el pipeline descarta un evento si ya encontró el mismo valor en este campo. |
| `retainSource` | Solo para logs en tiempo real. Conserva el evento original en el flujo de origen. |

Campos de los pasos de conteo, además de `transformName` y `kind`. Cada paso de conteo debe tener un nombre distinto dentro del pipeline. Consulta [Contar y limitar](/es/pipelines#recuento-y-límites).

| Campo | Notas |
|---|---|
| `conditions` | Eventos a los que se aplica el paso. Define hasta 16 condiciones y exige que se cumplan todas. Cada condición incluye `field`, `test` (`equals`, `not_equals`, `contains`, `starts_with`, `matches`, `exists`, `missing`, `gt`, `gte`, `lt` o `lte`) y `value`. `gt`, `gte`, `lt` y `lte` comparan con un número, y `matches` compara con una expresión regular. Si la lista está vacía, el paso se aplica a todos los eventos. |
| `metric` | Solo para `generate_metric`. `name`, `type` (`count`, `gauge` o `histogram`), `field` (obligatorio para `gauge` e `histogram`; `count` suma los valores del campo si lo especificas), `groupBy` (hasta 10 campos), `buckets` (de 1 a 30 límites superiores en orden ascendente para un histograma), `stream` (flujo de métricas) e `intervalSecs` (`10`, `30`, `60`, que es el valor predeterminado, o `300`). Solo para pipelines de logs, RUM y trazas. |
| `quota` | Solo para `quota`. `unit` (`events` o `bytes`), `limit` (límite diario en esa unidad, de 1 a 10^15), `partitionBy` (hasta 5 campos), `overrides` (hasta 100 objetos `{"values": {"<field>": "<value>"}, "limit": <n>}`, con un valor para cada campo de `partitionBy`), `action` (`drop`, el valor predeterminado, `pass` o `route`) y `target` (flujo de logs para `route`). Solo para pipelines de logs y, sin `route`, para flujos de RUM distintos de `rum_views` y `rum_vitals`. |
| `throttle` | Solo para `throttle`. `limit` (eventos por ventana, de 1 a 1 000 000), `windowSecs` (de 1 a 86 400), `groupBy` (hasta 5 campos), `action` (`drop`, el valor predeterminado, o `route`) y `target`. Se aplica a los mismos pipelines que `quota`. |

          "script": ".level = downcase!(string!(.level))" }
      ]
    },
    "cron": "every:5m",
    "lookbackSecs": 300,
    "enabled": true
  }'

**Errores**

| Estado | Causa |
|---|---|
| `400` | Una programación que no sigue el formato `every:Ns/m/h`; un intervalo de lectura retrospectiva no positivo; un pipeline programado de perfiles; un pipeline de perfiles en un flujo distinto de `default`; un pipeline en tiempo real de métricas, trazas, perfiles o RUM que escribe en otro flujo, enruta eventos o conserva el evento original; un paso de uno de esos pipelines que modifica un [campo que debe conservarse](/es/pipelines#métricas-y-trazas) de una muestra; un paso que puede descartar eventos de `rum_views` o `rum_vitals`; un paso de VRL que no compila; un nombre de flujo no válido; más de 8 flujos de lectura, más de 8 flujos de escritura o más de 8 tablas de extensión; un paso de enrutamiento cuyo flujo fijo o alternativo es un origen; un flujo de eventos fallidos que el pipeline lee o en el que escribe; un [flujo de RUM](/es/pipelines#flujos-de-rum) como destino de escritura o enrutamiento; `rum_sessions` como origen de un pipeline en tiempo real; un [flujo de plataforma](/es/pipelines#flujos-de-plataforma) como destino de escritura o enrutamiento, o que se intenta modificar en tiempo real; `delaySecs` o un número de reintentos fuera del rango permitido. Para un pipeline de alertas: un origen o nivel de gravedad desconocido; un paso de enrutamiento; un paso de resumen con IA sin instrucciones; un paso de llamada a la API cuyo conector no es un conector HTTP de la organización; un paso de consulta que no contiene una única consulta, lee `_audit` o incluye un marcador de posición fuera de una cadena o que no existe en el evento; un pipeline `notify` con un paso que realiza acciones fuera de MoleSignal; un pipeline `open` con `policies` o con el origen `manual`; o más de 20 pasos. También devuelve este error un paso `generate_metric`, `quota` o `throttle` en un pipeline programado o de alertas, o en datos que no admite; dos pasos de estos tipos con el mismo nombre; o una configuración no válida, como un nombre de métrica que PromQL no puede seleccionar, una etiqueta presente en todas las muestras de métricas (`value`, `le`, `metric_name`…) o un `target` que coincide con el flujo de origen. |
| `403` | El pipeline lee `_audit` y el token no tiene el permiso `audit.read` o pertenece a una cuenta de servicio. |
| `409` | Un pipeline programado que escribiría en un flujo que también lee, o un pipeline en tiempo real cuando ya hay otro habilitado para el mismo tipo de datos y flujo de origen (`a realtime pipeline is already enabled for this <signal> stream`). |

Consulta [Pipelines](/es/pipelines) para obtener más información sobre el modo en tiempo real, el paso de enrutamiento, las posiciones de lectura y los reintentos.
