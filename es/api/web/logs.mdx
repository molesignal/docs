Estas llamadas leen un flujo de registros de la organización, tal como lo hace la página **Registros**. Un flujo que no existe devuelve un resultado vacío. Todas las llamadas requieren `logs.read`, o `sys.telemetry.read` en el ámbito del sistema.

Cada llamada salvo la agrupación en patrones usa `POST` con un cuerpo JSON, o `GET` con los mismos campos en la cadena de consulta: `filters` y `freeText` como el texto de una lista JSON, y `where` como el texto de un objeto JSON. Envía una consulta demasiado larga para una dirección como `POST`.

## Qué coincide en una llamada

Una llamada hace coincidir los registros del flujo en la ventana que cumplen todo lo siguiente:

| Campo | Tipo | Notas |
|---|---|---|
| `filters` | lista | Filtros que deben cumplirse todos. Como máximo 32, contados junto con los filtros de `where`. |
| `freeText` | lista | Palabras o frases para buscar en el campo `message`, cada una de hasta 512 bytes. Una palabra en minúsculas formada por letras y dígitos, de hasta 40 bytes, coincide sin importar mayúsculas ni minúsculas; el resto del texto coincide tal como está escrito. Como máximo 8, contados junto con el texto de `where`. |
| `where` | objeto | Un árbol de condiciones para alternativas: un filtro, `{"text": "..."}`, `{"and": [...]}` o `{"or": [...]}`. |
| `expression` | cadena | Una consulta de campos tal como la escribe la página **Registros**. Sustituye a `filters`, `freeText` y `where`: envía `expression` o los campos, no ambos. |

Un filtro es un objeto con `field`, `op`, `value` y `quoted`. Nombra su campo tal como lo nombra el flujo.

| Operador | Campos | Coincide con |
|---|---|---|
| `=`, `!=` | Cualquier campo escalar | El valor, o todos los demás valores. Con un valor vacío, indica si el campo tiene algún valor: `=` coincide con los registros que no lo tienen. |
| `>`, `>=`, `<`, `<=` | Números y marcas de tiempo | La comparación. |
| `contains` | Texto | El valor en cualquier parte del campo. |
| `match` | Cualquier campo | El valor como subcadena, sin importar mayúsculas ni minúsculas. Un valor vacío no coincide con nada. |
| `match_text` | Texto con índice de texto completo | Una búsqueda de texto completo: palabras, frases y comodines. Un campo sin índice de texto completo responde `400`. |

`eq`, `ne` y `like` son alias de `=`, `!=` y `contains`. `quoted` es `true` para un valor escrito entre comillas: una palabra, nunca un número. Un campo JSON no se puede filtrar aquí; consúltalo con SQL.

`expression` acepta el texto de la página **Registros**: comparaciones, `MATCH(field, 'text')` y `MATCH_TEXT(field, 'words')`, palabras para buscar, una frase entre comillas, `AND` y `OR` en cualquier combinación de mayúsculas y minúsculas con `AND` de mayor precedencia, y paréntesis. El servidor lo convierte en los `filters`, `freeText` y `where` que envía la página y los comprueba como se indica arriba. El texto tiene como máximo 8 KiB y anida paréntesis como máximo 32 niveles. Una parte que no puede interpretar, como un paréntesis sin cerrar o una comparación sin operandos, responde `400` e indica la parte.

```bash
curl -G "http://localhost:5080/api/v1/web/logs" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'stream=app' \
  --data-urlencode "expression=level = 'error' AND (service.name = 'checkout' OR timeout)"
```

## Listar registros

```http
POST /api/v1/web/logs
GET  /api/v1/web/logs
```

Devuelve los registros coincidentes, del más reciente al más antiguo, con paginación por cursor.

| Campo | Tipo | Notas |
|---|---|---|
| `stream` | cadena | Obligatorio. El flujo de registros. |
| `from`, `to` | entero | La ventana en microsegundos. Los valores predeterminados son las últimas 24 horas hasta ahora. `to` debe ser mayor que `from`. |
| `filters`, `freeText`, `where`, `expression` | | Criterios de coincidencia de la llamada. |
| `limit` | entero | Tamaño de página. Valor predeterminado `20`, acotado entre 1 y 5000. |
| `cursor` | cadena | El `nextCursor` o `previousCursor` de una página anterior. Mantiene la ventana y el criterio de coincidencia de la primera página. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/web/logs \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"stream":"app","expression":"level = '\''error'\''","limit":2}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    { "_timestamp": 1790000000000000, "level": "error", "message": "db pool exhausted", "trace_id": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "nextCursor": "eyJ2IjoxLC...",
  "previousCursor": null,
  "hasMore": true
}
```
</ResponseExample>

Cada elemento contiene los campos de un registro. `_timestamp` está en microsegundos. Una solicitud con un `cursor` y un flujo, una ventana, un `limit` o unos criterios de coincidencia distintos responde `400`.

## Contar registros en el tiempo

```http
POST /api/v1/web/logs/histogram
GET  /api/v1/web/logs/histogram
```

Cuenta los registros coincidentes en intervalos de tiempo.

| Campo | Tipo | Notas |
|---|---|---|
| `stream` | cadena | Obligatorio. |
| `from`, `to` | entero | Obligatorio. La ventana en microsegundos. |
| `filters`, `freeText`, `where`, `expression` | | Criterios de coincidencia de la llamada. |
| `bucketTime` | entero | La duración de un intervalo en microsegundos. Como mínimo `1000`. |
| `originTime` | entero | El inicio del primer intervalo. No posterior a `from`. |

Una solicitud abarca como máximo 512 intervalos desde `originTime` hasta `to`.

```json
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "buckets": [{ "startTime": 1790000100000000, "total": 120, "errors": 4 }],
  "split": true
}
```

`buckets` enumera los intervalos que contienen un registro, del más antiguo al más reciente. `errors` cuenta los registros de nivel `ERROR`, leídos de `level` o `body_level`. `split` es `false` cuando el flujo no tiene ninguno de los dos campos o el nivel está enmascarado para el lector; entonces `errors` es `0`. Cuando el recuento no está disponible, la llamada responde `200` con `buckets` vacío y `unavailable`: `time_budget`, `busy` o `scan_limit`, como en el [recuento de trazas](/es/api/web/trace#contar-trazas-a-lo-largo-del-tiempo).

## Describir un campo

```http
POST /api/v1/web/logs/field-stats
GET  /api/v1/web/logs/field-stats
```

Describe los valores que toma un campo en los registros coincidentes.

| Campo | Tipo | Notas |
|---|---|---|
| `stream` | cadena | Obligatorio. |
| `from`, `to` | entero | La ventana en microsegundos. |
| `filters`, `freeText`, `where`, `expression` | | Criterios de coincidencia de la llamada. |
| `field` | cadena | Obligatorio. El campo, tal como lo nombra el flujo. |

```json
{
  "kind": "text",
  "total": 1840,
  "present": 1840,
  "distinct": 3,
  "distinctExact": true,
  "top": [{ "value": "info", "count": 1500 }, { "value": "warn", "count": 300 }, { "value": "error", "count": 40 }],
  "topSkipped": false
}
```

`kind` es `number`, `time`, `text` o `bool`. `total` cuenta los registros coincidentes y `present` los que tienen un valor. `top` enumera los valores más frecuentes, de mayor a menor frecuencia; `topSkipped` es `true` cuando casi todos los valores son distintos y no se enumera ninguno. `range` da el valor más pequeño y el más grande como texto. Un campo numérico añade `spread` y `bars`. `trend` cuenta los valores más frecuentes a lo largo de la ventana y no aparece cuando ningún valor es más frecuente que los demás.

## Agrupar en patrones

```http
POST /api/v1/web/logs/patterns
```

Agrupa los registros coincidentes en patrones de mensajes a lo largo de toda la ventana y compara cada uno con un periodo de referencia. Una ventana con más de 5000 registros coincidentes se lee como una muestra de los registros más recientes de cuatro partes iguales, y el `estimatedCount` de cada patrón escala su recuento a la ventana. La llamada requiere `logs.read`.

| Campo | Tipo | Notas |
|---|---|---|
| `stream` | cadena | Obligatorio. |
| `from`, `to` | entero | Obligatorio. La ventana en microsegundos. |
| `filters`, `freeText`, `where`, `expression` | | Criterios de coincidencia de la llamada. |
| `field` | cadena | El campo que contiene el mensaje; si se omite, el primero de `message`, `body`, `summary`, `log`, `event`, `error`, `msg`, `content` y `text` que tenga el flujo. |
| `baseline` | cadena | `previous` (el valor predeterminado, el periodo de la misma duración justo anterior), `week_before` o `none`. |
| `limit` | entero | El máximo de patrones enumerados: 100 de forma predeterminada, como máximo 200. |

```json
{
  "stream": "app_logs",
  "field": "message",
  "levelField": "level",
  "timeRange": { "startTime": 1795510800000000, "endTime": 1795514399999999 },
  "logs": 48210,
  "read": 5000,
  "unread": 0,
  "sampled": true,
  "baseline": { "kind": "previous", "startTime": 1795507199999999, "endTime": 1795510799999999, "logs": 40102, "read": 5000, "sampled": true },
  "newPatterns": 1,
  "surgingPatterns": 0,
  "droppingPatterns": 0,
  "patternCount": 37,
  "patterns": [
    {
      "pattern": "upstream timeout after <number>ms",
      "tokens": [{ "lead": "", "trail": "", "text": "upstream", "wild": null, "unit": "" }],
      "count": 41,
      "share": 0.0082,
      "estimatedCount": 395,
      "firstSeen": 1795513020000000,
      "lastSeen": 1795514390000000,
      "levels": [{ "level": "ERROR", "count": 41 }],
      "baselineCount": 0,
      "change": "new",
      "fragment": "upstream timeout after",
      "example": "upstream timeout after 3000ms"
    }
  ]
}
```

Los patrones nuevos y en aumento aparecen primero, y los patrones que la ventana ya no tiene, al final. `change` es `new` (el periodo de referencia no tenía ninguno), `surging` (al menos el doble y al menos cinco más), `dropping` (la mitad o menos y al menos cinco menos) o `steady`; `ratio` es el recuento estimado de la ventana dividido por el del periodo de referencia. `tokens` son las palabras del patrón y `wild` nombra lo que cambia en una posición abierta. Un campo cifrado en reposo responde `400`. Un flujo en el que no se escribió nada responde un informe vacío.

## Errores

| Estado | Causa |
|---|---|
| `400` | Un parámetro no es válido: falta `stream`, `to` no es mayor que `from`, un filtro nombra un campo desconocido o usa un operador que su tipo no admite, las listas o el árbol superan sus límites, `expression` viene con `filters`, `freeText` o `where` o tiene una parte que no puede interpretar, el cursor no coincide con la consulta, o falta un parámetro del histograma o abarca más de 512 intervalos. |
| `403` | Al token le falta `logs.read`. |
