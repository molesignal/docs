Todas las llamadas leen un flujo de trazas de la organización: el flujo que tiene todos los campos `trace_id`, `span_id`, `service.name`, `name`, `start_time_unix_nano`, `end_time_unix_nano` y `status_code`. Un flujo llamado `default` tiene prioridad sobre otros flujos que cumplen los requisitos, y el nombre del flujo desempata los demás. Una organización sin ese flujo obtiene resultados vacíos. Solo se pueden leer las trazas que sobrevivieron al [muestreo de cola](/es/configuration#captura-de-trazas-y-muestreo-al-final).

Todas las llamadas requieren `traces.read`, o `sys.telemetry.read` en el ámbito del sistema.

## Listar resúmenes de trazas

```http
GET /api/v1/web/traces
```

Devuelve un resumen por traza, con paginación por cursor. Un flujo que aún no tiene resúmenes de trazas responde con una página vacía.

**Parámetros de consulta**

| Parámetro | Tipo | Notas |
|---|---|---|
| `from`, `to` | entero | La ventana en microsegundos. Los valores predeterminados son las últimas 24 horas hasta ahora. `to` debe ser mayor que `from`. |
| `q` | cadena | Texto que no distingue mayúsculas de minúsculas y que debe aparecer en el `trace_id`, `span_id`, servicio, operación o estado de un span. Hasta 256 caracteres. |
| `filters` | cadena | Un array JSON de filtros. Consulta más abajo. |
| `where` | cadena | Un árbol de condiciones JSON: filtros y texto unidos por AND y OR. Consulta más abajo. |
| `expression` | cadena | Una consulta de campos tal como la escribe la página **Trazas**. Representa a `q`, `filters` y `where`: envía una u otra. Consulta más abajo. |
| `sort` | cadena | `latest` (predeterminado), `earliest`, `duration_desc`, `duration_asc`, `span_count_desc` o `errors_desc`. |
| `limit` | entero | Tamaño de página. Valor predeterminado: `20`. El valor se limita al rango de 1 a 5000. |
| `cursor` | cadena | El `nextCursor` o `previousCursor` de una página anterior. |
| `fields` | cadena | Campos del span raíz de cada traza que se devuelven con ella, separados por comas y con el nombre que les da el flujo. Hasta 12. Un campo desconocido, un campo JSON o un campo `molesignal.trace.*` responde `400`. |

Un filtro es un objeto con `field`, `op` y `value`, y una solicitud incluye como máximo 32 filtros. Todos los filtros deben coincidir. El operador `in` toma `values`, una lista de valores, en lugar de `value`.

| Campo | Tipo | Operadores |
|---|---|---|
| `trace_id` | texto | `=`, `!=`, `contains`, `in` |
| `duration_ns`, `span_count`, `error_count` | entero | `=`, `!=`, `>`, `>=`, `<`, `<=`, `in` |
| Cualquier otro campo escalar del flujo de trazas | según el tipo de campo | Texto: `=`, `!=`, `contains`, `in`. Números y marcas de tiempo: `=`, `!=`, `>`, `>=`, `<`, `<=`, `in`. Booleanos: `=`, `!=`, `in`. |

Un filtro nombra su campo tal como lo nombra el flujo, por ejemplo `service.name` o `name`; ningún otro nombre representa un campo. Los operadores `eq`, `ne` y `like` son alias de `=`, `!=` y `contains`. Un campo JSON no se puede filtrar.

`trace_id`, `duration_ns`, `span_count` y `error_count` se comparan a nivel de traza. Cualquier otro campo pertenece a un span: un filtro sobre él coincide con una traza cuando uno de sus spans pasa el filtro, y `!=` coincide con una traza cuando ninguno de sus spans tiene el valor. Un span sin el campo no tiene el valor.

`in` coincide con cualquiera de sus `values`: de 1 a 64 valores, cada uno de hasta 512 bytes y del tipo del campo. Un valor que aparece dos veces cuenta una sola vez. En un campo de span, `in` coincide con una traza cuando uno de sus spans tiene uno de los valores.

`where` expresa lo que la lista de filtros no puede: alternativas. Es un objeto JSON en una de cuatro formas:

| Forma | Coincide con |
|---|---|
| Un filtro, como en `filters` | El filtro. |
| `{"text": "..."}` | El texto, tal como lo hace coincidir `q`. |
| `{"and": [...]}` | Todas las condiciones de la lista. |
| `{"or": [...]}` | Cualquier condición de la lista. |

`filters`, `q` y `where` se aplican juntos. Un filtro del árbol conserva su significado: uno sobre un campo de span coincide con una traza cuando uno de sus spans lo cumple, y `!=` cuando ninguno de sus spans tiene el valor. Una traza coincide con `{"or": [A, B]}` cuando coincide con `A` o con `B`. Los filtros de `filters` y `where` cuentan juntos para el límite de 32. Un árbol busca texto como máximo 8 veces, anida grupos hasta 8 niveles de profundidad y tiene al menos una condición en cada grupo.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'filters=[{"field":"status_code","op":"=","value":"ERROR"}]' \
  --data-urlencode 'where={"or":[{"field":"service.name","op":"=","value":"checkout"},{"field":"span_count","op":">","value":"50"}]}'
```

La solicitud lista las trazas fallidas que tienen un span de `checkout` o más de 50 spans.

`expression` toma en su lugar el texto de la página **Trazas**: comparaciones con `=`, `!=`, `>`, `>=`, `<`, `<=`, `contains` y `field in ('a', 'b')`, palabras que buscar, una frase entre comillas, `AND` y `OR` sin distinguir mayúsculas de minúsculas, con `AND` con mayor precedencia, y corchetes. El servidor lo interpreta como los `q`, `filters` y `where` que envía la página y los valida como se indica arriba. El texto tiene como máximo 8 KiB y anida corchetes como máximo 32 niveles de profundidad. Una parte que no puede leer, como un corchete sin cerrar o una comparación sin operandos, responde `400` e indica la parte.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "expression=status_code = 'ERROR' AND (service.name = 'checkout' OR span_count > 50)"
```

La solicitud lista las mismas trazas que la anterior.

Un `cursor` vincula la página con la consulta que la emitió. Repetir una solicitud con un cursor y con `limit`, `sort`, `q`, `filters` o `where` distintos responde `400`.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'sort=duration_desc' \
  --data-urlencode 'limit=2' \
  --data-urlencode 'fields=http.route' \
  --data-urlencode 'filters=[{"field":"service.name","op":"in","values":["checkout","payments"]}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "service": "checkout",
      "operation": "GET /checkout",
      "startNs": 1790000000000000000,
      "durationMs": 180.0,
      "spanCount": 3,
      "errorCount": 1,
      "status": "ERROR",
      "httpStatusCode": 502,
      "fields": { "http.route": "/checkout" }
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

Cada elemento describe una traza por su raíz: el `service` y la `operation` del span raíz, el tiempo de inicio en nanosegundos, la duración en milisegundos, el número de spans y el número de spans con error. `hasMore` es `true` cuando `nextCursor` está establecido.

| Campo | Notas |
|---|---|
| `status` | El estado del span raíz: `OK`, `ERROR` o `UNSET`. |
| `httpStatusCode` | El `http.response.status_code` del span raíz, o su `http.status_code`, cuando contiene un código de 100 a 599. No está presente en caso contrario ni en las trazas almacenadas antes de que el resumen lo conservara. |
| `fields` | Los campos solicitados en `fields` para los que el span raíz tiene un valor. No está presente cuando no tiene ninguno. La página se devuelve sin ellos cuando falla la lectura. |

## Contar trazas a lo largo del tiempo

```http
GET /api/v1/web/traces/histogram
```

Cuenta cada traza que coincide con una consulta de lista, en intervalos de tiempo, según la hora de inicio de la traza. La llamada toma la ventana, `q`, `filters` y `where` de la lista, y coincide con las mismas trazas. El cliente elige los intervalos.

**Parámetros de consulta**

| Parámetro | Tipo | Notas |
|---|---|---|
| `from`, `to` | entero | La ventana en microsegundos. Ambos son obligatorios. `to` debe ser mayor que `from`. |
| `q`, `filters`, `where`, `expression` | cadena | Lo mismo que para la lista. |
| `bucketTime` | entero | La duración de un intervalo en microsegundos. Como mínimo `1000`. |
| `originTime` | entero | El inicio del primer intervalo en microsegundos. No posterior a `from`. |

Una solicitud abarca como máximo 512 intervalos desde `originTime` hasta `to`.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/histogram" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=900000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode 'filters=[{"field":"service.name","op":"=","value":"checkout"}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 900000000,
  "originTime": 1790000100000000,
  "buckets": [
    { "startTime": 1790000100000000, "total": 42, "errors": 3, "p50Ns": 41000000, "p95Ns": 180000000, "p99Ns": 320000000 },
    { "startTime": 1790001900000000, "total": 17, "errors": 0, "p50Ns": 38000000, "p95Ns": 95000000, "p99Ns": 120000000 }
  ],
  "split": true
}
```
</ResponseExample>

`buckets` lista solo los intervalos que contienen una traza, del más antiguo al más reciente. `total` es el número de trazas que comenzaron en el intervalo. `errors` es el número de esas trazas con al menos un span con error. `p50Ns`, `p95Ns` y `p99Ns` son las duraciones de la mediana y de los percentiles 95 y 99 de esas trazas, en nanosegundos. Son estimaciones y no están presentes cuando no se contó ninguna duración.

El recuento lee los resúmenes de trazas y los spans cuando un filtro se aplica a un campo de span. La lista devuelve un resumen por cada traza. Un resumen que una escritura reintentada almacenó dos veces cuenta dos veces.

Cuando el recuento no está disponible, la llamada sigue respondiendo `200`. `buckets` queda entonces vacío y `unavailable` indica el motivo.

| `unavailable` | Causa |
|---|---|
| `time_budget` | El recuento tardó más de 20 segundos. |
| `busy` | Las consultas del rol llenan [`[search.admission]`](/es/configuration#control-de-admisión) y no se liberó ninguna ranura dentro de su `max_wait_secs`. |
| `scan_limit` | La ventana contiene más filas de las que `[querier].max_scan_rows` permite leer a una consulta. |

## Leer las métricas de las solicitudes

```http
GET /api/v1/web/traces/red
GET /api/v1/web/traces/red/breakdown
```

Lee la tasa, los errores y la duración de las solicitudes con las que coincide una consulta de lista: en total, bucket por bucket y según cuánto tardaron. El desglose lee las mismas métricas para cada valor de un campo. Una solicitud es un span. De forma predeterminada, las solicitudes son los spans en los que un servicio recibió una solicitud: un span de servidor o de consumidor, o la raíz de una traza. `scope=all` lee todos los spans.

Un filtro sobre un campo de span se aplica al propio span, así que `service.name = 'api'` lee las solicitudes que atendió `api`. `trace_id` y `duration_ns` se leen del span, y `span_count` y `error_count` de la traza a la que pertenece el span.

**Parámetros de consulta**

| Parámetro | Tipo | Notas |
|---|---|---|
| `from`, `to`, `bucketTime`, `originTime` | integer | Lo mismo que para el recuento de trazas en el tiempo. |
| `q`, `filters`, `where`, `expression` | string | Lo mismo que para la lista. |
| `scope` | string | `entry` (predeterminado) o `all`. |
| `by` | string | Solo para el desglose, y obligatorio en él: el campo por el que agrupar las solicitudes, tal como lo nombra el stream. |

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/red" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=60000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode "expression=service.name = 'checkout'"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "scope": "entry",
  "total": { "requests": 1840, "errors": 12, "p50Ns": 41000000.0, "p95Ns": 180000000.0, "p99Ns": 320000000.0 },
  "buckets": [
    { "startTime": 1790000100000000, "requests": 31, "errors": 0, "p50Ns": 40000000.0, "p95Ns": 150000000.0, "p99Ns": 210000000.0 }
  ],
  "latency": [
    { "fromNs": 0, "toNs": 50000000, "requests": 1203, "errors": 2 },
    { "fromNs": 50000000, "toNs": null, "requests": 637, "errors": 10 }
  ]
}
```
</ResponseExample>

`buckets` enumera los buckets que contienen alguna solicitud, del más antiguo al más reciente. `latency` enumera las solicitudes por duración, de la más corta a la más larga; el último rango no tiene límite superior. `errors` es `null` donde no se pueden distinguir los fallos, y las duraciones están en nanosegundos: `null` cuando no hay solicitud y donde las duraciones están enmascaradas.

El desglose devuelve `field`, `bucketTime`, `originTime`, `scope` y `groups`: primero los 50 valores más frecuentes, cada uno con sus métricas y una `series` de buckets con `requests`, `errors` y `p95Ns`. `value` es `null` para las solicitudes que no tienen valor. `more` es `true` cuando existen más valores que los enumerados.

Cuando las métricas no están disponibles, las llamadas siguen respondiendo `200` con `unavailable`: `time_budget`, `busy` y `scan_limit` como para el recuento de trazas, `timestamp_masked` cuando el tiempo está enmascarado para el lector y `field_protected` cuando el campo del desglose está enmascarado o cifrado.

`by` también puede nombrar una clave dentro de un campo JSON, escrita después del nombre del campo, como `attributes.tenant`: las solicitudes se agrupan por lo que contiene esa clave.

## Comparar las solicitudes lentas o fallidas

```http
GET /api/v1/web/traces/red/compare
```

Compara las solicitudes elegidas de una consulta con sus demás solicitudes, campo por campo: las solicitudes que fallaron, que tardaron al menos o menos de cierto tiempo, o que cumplen todo lo indicado. Para cada campo se compara la proporción de cada valor en los dos conjuntos, y los campos se clasifican según lo alejadas que estén esas proporciones, de `0` (la misma mezcla) a `1` (ningún valor en común). Se excluyen los identificadores, los momentos, las duraciones y los campos JSON, y también un campo cuyos valores son casi todos distintos fila a fila. Cuando se eligen las solicitudes fallidas, también se excluye `status_code`. Cada conjunto se lee como una muestra de sus primeros 1 000 spans.

**Parámetros de consulta**

Los parámetros de las métricas RED, sin `by`, y además:

| Parámetro | Tipo | Notas |
|---|---|---|
| `errors` | boolean | Elige las solicitudes fallidas. |
| `minDuration` | integer | Elige las solicitudes que tardaron al menos esta cantidad de nanosegundos. |
| `maxDuration` | integer | Elige las solicitudes que tardaron menos de esta cantidad de nanosegundos. |

Se requiere al menos uno de ellos, y `minDuration` debe ser menor que `maxDuration`.

<ResponseExample>
```json 200
{
  "scope": "entry",
  "selected": 212,
  "baseline": 1000,
  "sampled": true,
  "dimensions": [
    {
      "field": "cloud.region",
      "score": 0.71,
      "values": [
        { "value": "eu-west-1", "selected": 0.83, "baseline": 0.12 },
        { "value": "us-east-1", "selected": 0.17, "baseline": 0.88 }
      ]
    }
  ]
}
```
</ResponseExample>

`selected` y `baseline` son los spans leídos de cada conjunto, y `sampled` es `true` cuando alguno de los conjuntos tenía más. `dimensions` enumera como máximo 20 campos, los más alejados primero, cada uno con como máximo 5 valores cuyas proporciones difieren más. `value` es `null` para las solicitudes que no lo tienen. `unavailable` se responde como para las métricas RED.

## Listar spans

```http
GET /api/v1/web/traces/spans
```

Devuelve una fila por cada span con el que coincide una consulta, con paginación por cursor. La llamada toma la ventana, `q`, `filters` y `where` de la lista de trazas, y los lee para cada span: un filtro sobre un campo de span se aplica al propio span, y `!=` conserva un span que no tiene el campo. `duration_ns` es la duración propia del span. `span_count` y `error_count` son los de la traza a la que pertenece el span. Un span coincide con `{"or": [A, B]}` cuando coincide con `A` o coincide con `B`.

**Parámetros de consulta**

| Parámetro | Tipo | Notas |
|---|---|---|
| `from`, `to` | integer | La ventana en microsegundos. De forma predeterminada, las últimas 24 horas hasta ahora. `to` debe ser mayor que `from`. |
| `q`, `filters`, `where`, `expression` | string | Lo mismo que para la lista de trazas. |
| `sort` | string | `latest` (predeterminado), `earliest`, `duration_desc` o `duration_asc`. |
| `limit` | integer | Tamaño de página. Valor predeterminado `100`. El valor se limita al rango de 1 a 5000. |
| `cursor` | string | El `nextCursor` o `previousCursor` de una página anterior. El cursor lleva la consulta de su página; un `limit` distinto responde `400`. |

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "durationNs": 140000000,
      "status": "ERROR",
      "kind": 2,
      "httpStatusCode": 502
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

`status` es `OK`, `ERROR` o `UNSET`. `kind` numera el tipo de span como lo hace OTLP: `1` interno, `2` servidor, `3` cliente, `4` productor, `5` consumidor. `parent_span_id`, `kind` y `http_status_code` no están presentes cuando el span no los tiene. La llamada se ejecuta como una consulta rastreada y se admite como cualquier otra consulta.

## Leer una traza

```http
GET /api/v1/web/trace/{traceId}
```

Devuelve todos los spans de una traza, ordenados por hora de inicio. `trace_id` tiene de 1 a 128 caracteres de `A-Z`, `a-z`, `0-9`, `-` y `_`.

**Parámetros de consulta**

| Parámetro | Tipo | Notas |
|---|---|---|
| `from`, `to` | integer | La ventana en microsegundos en la que comenzaron los spans de la traza. Indica ambos o ninguno. Como máximo 31 días. Sin ellos, la traza se busca en las últimas 24 horas. |

La respuesta está limitada a 100 000 spans y 32 MiB. `truncated` es `true` cuando algún límite recortó la lista de spans.

<ResponseExample>
```json 200
{
  "traceId": "0af7651916cd43dd8448eb211c80319c",
  "rootSpanId": "b7ad6b7169203331",
  "spans": [
    {
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "endNs": 1790000000160000000,
      "durationNs": 140000000,
      "kind": 2,
      "status": "ERROR",
      "statusMessage": "upstream timeout",
      "attributes": { "http.method": "POST", "http.status_code": "502" },
      "events": [],
      "links": [],
      "samplingReason": "error",
      "partial": false,
      "late": false,
      "duplicate": false,
      "conflict": false
    }
  ],
  "truncated": false,
  "partial": false,
  "partialReasons": [],
  "samplingReasons": ["error"],
  "lateSpanCount": 0,
  "duplicateSpanCount": 0,
  "conflictSpanCount": 0

```
</ResponseExample>

El ejemplo muestra un span con sus campos principales. Un span real también incluye `traceFlags`, `traceState`, `resource`, `scope`, los contadores `dropped_*_count`, `schemaVersion` y `semanticConventionsVersion`.

| Campo | Notas |
|---|---|
| `rootSpanId` | El primer span sin padre. Construye el árbol a partir de `span_id` y `parent_span_id`. |
| `spans[].status` | `OK`, `ERROR` o `UNSET`. |
| `spans[].attributes` | Los atributos del span, combinados con las columnas de atributos aplanadas del stream. |
| `spans[].sampling_reason` | Por qué el muestreador de cola conservó la traza, por ejemplo `error`. |
| `partial`, `partialReasons` | Si faltan spans y por qué. |
| `lateSpanCount`, `duplicateSpanCount`, `conflictSpanCount` | Los spans que llegaron tarde, repetidos o en conflicto. |

## Encuentra los spans que enlazan con una traza

```http
GET /api/v1/web/trace/{traceId}/linked
```

Un span conserva enlaces a los spans de los que proviene, y el detalle de la traza los devuelve junto con el span. Esta llamada busca la dirección opuesta: spans de otras trazas cuyos enlaces hacen referencia a un span de esta traza. Toma los mismos `from` y `to` que el detalle de la traza y busca en esa ventana.

<ResponseExample>
```json 200
{
  "spans": [
    {
      "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
      "spanId": "00f067aa0ba902b7",
      "service": "billing-worker",
      "operation": "process invoice",
      "startNs": 1790000005000000000,
      "durationNs": 30000000,
      "status": "OK",
      "linkedSpanId": "53995c3f42cd8ad8",
      "attributes": { "messaging.operation": "process" }
    }
  ],
  "more": false
}
```
</ResponseExample>

`spans` enumera hasta 200 spans que enlazan, del más reciente al más antiguo, y `more` es `true` cuando más spans enlazan con la traza. `linkedSpanId` es el span de esta traza al que apunta el enlace, y `attributes` contiene los atributos del enlace.

La búsqueda lee los enlaces de cada span de la ventana como texto, dentro del presupuesto de tiempo del recuento de trazas. Cuando no puede terminar, la llamada responde igualmente `200` con `spans` vacío y un motivo `unavailable`: `time_budget`, `busy` o `scan_limit`, como en el recuento de trazas.

**Errores**

| Estado | Causa |
|---|---|
| `400` | Un parámetro no es válido: `to` no es mayor que `from`, un filtro usa un campo u operador desconocido (`unsupported trace filter field: nope`), un filtro `in` no tiene valores o tiene más de 64, `where` no es un árbol de condiciones o supera sus límites, `expression` viene con `q`, `filters` o `where`, o tiene una parte que no se puede leer, el cursor no coincide con la consulta, un campo de `fields` es desconocido o es un documento, o el `trace_id` tiene caracteres o longitud no válidos.
