```http
GET  /api/v1/query/stream
POST /api/v1/query/stream
```

Siempre responde con NDJSON en fragmentos (`application/x-ndjson`). Cada línea es un objeto JSON cuyas claves son los nombres de las columnas, y la última línea es `{"__meta__":{"scannedRows":...,"tookMs":...}}`. El endpoint nunca convierte una consulta en una tarea asíncrona. La llamada requiere `streams.query` o, en el ámbito del sistema, `sys.telemetry.read`.

La variante `POST` acepta el mismo cuerpo que [Ejecutar una consulta](/es/api/query/execute). La variante `GET` acepta parámetros de consulta:

| Parámetro | Obligatorio | Notas |
|---|---|---|
| `sql` | Sí | La sentencia. Si falta el valor, el endpoint responde con `400`. |
| `stream` | Sí | Nombre del flujo principal. |
| `streamType` | No | `logs`, `metrics`, `traces`, `profiles` o `extend`. El valor predeterminado es `logs`. |
| `from`, `to` | Sí | Intervalo de tiempo en microsegundos. |
| `limit` | No | Número máximo de filas. |

<RequestExample>
```bash cURL
NOW=$(date +%s)000000

curl -G http://localhost:5080/api/v1/query/stream \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "sql=SELECT level, msg FROM app ORDER BY _timestamp DESC" \
  --data-urlencode "stream=app" \
  --data-urlencode "streamType=logs" \
  --data-urlencode "from=$((NOW-3600000000))" \
  --data-urlencode "to=$((NOW+60000000))" \
  --data-urlencode "limit=3"
```
</RequestExample>

<ResponseExample>
```text 200
{"level":"info","msg":"fine"}
{"level":"error","msg":"db pool exhausted"}
{"__meta__":{"scannedRows":5,"tookMs":173}}
```
</ResponseExample>

Desactiva el almacenamiento en búfer de las respuestas en el proxy (`proxy_buffering off`) para que las filas lleguen a medida que el endpoint las genere y permite lecturas prolongadas. Deja de leer para cancelar el flujo.
