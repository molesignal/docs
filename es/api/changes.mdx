```http
GET    /api/v1/changes
POST   /api/v1/changes
GET    /api/v1/changes/{id}
PUT    /api/v1/changes/{id}
PATCH  /api/v1/changes/{id}
DELETE /api/v1/changes/{id}
```

Los cambios se guardan en un solo lugar: despliegues, cambios de configuración, feature flags, escalado y
cambios de infraestructura que los pipelines reportan a través de
[`POST /api/v1/apm/deployments`](/es/apm/deployments#reporta-despliegues-desde-ci), y las anotaciones
que las personas ponen sobre un rango de tiempo. `GET /api/v1/changes` las lista con las versiones que APM vio por primera vez en los spans
y las ediciones de reglas de alerta. Las demás llamadas mantienen las anotaciones.

## Listar cambios

| Parámetro | Notas |
|---|---|
| `from`, `to` | El rango en microsegundos. `to` toma el momento actual por defecto y `from`, un día antes de `to`. |
| `services` | Nombres de servicios, separados por comas. Los cambios de otros servicios se omiten; los cambios sin servicio, como las anotaciones y las ediciones de reglas, se mantienen. |
| `namespace`, `environment` | Los cambios reportados y las versiones de este namespace o entorno, y los cambios reportados que no indicaron ninguno. |
| `kinds` | Separados por comas: `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure`, `annotation`, `version`, `rule`. Si se omite, todos los tipos que el llamador puede leer. |
| `dashboardId`, `stream` | Las anotaciones de este dashboard o flujo de logs, y las anotaciones que no tienen ninguno. Las anotaciones de otro dashboard o flujo se omiten. |
| `limit` | Como máximo 500, el valor predeterminado. |

Cada tipo solicita su propio permiso, y un tipo que el llamador no tiene se omite en lugar de rechazarse:

| Tipos | Permiso, cualquiera de |
|---|---|
| `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure` | `apm.deployments.read`, `sys.telemetry.read` |
| `annotation` | `dashboards.annotations.read` |
| `version` | `apm.services.read`, `sys.telemetry.read` |
| `rule` | `alerts.rules.read` |

La respuesta es una lista, lo más reciente primero. Una versión que un pipeline reportó se lista una vez, tal como se reportó.

```json
[
  {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "kind": "deployment",
    "at": 1792316400000000,
    "service": "checkout",
    "namespace": "shop",
    "environment": "prod",
    "version": "2.0.0",
    "status": "succeeded",
    "commit": "9f2c1e7a4b3d5e6f",
    "author": "ada",
    "ciUrl": "https://ci.example.com/runs/7"
  },
  {
    "id": "3KEDP0aZ1y2b3c4d5e6f7g8h9i0",
    "kind": "annotation",
    "at": 1792312800000000,
    "end": 1792314600000000,
    "title": "Load test",
    "tags": ["test"],
    "dashboardId": "dash-1"
  }
]
```

| Campo | Notas |
|---|---|
| `at`, `end` | Cuándo ocurrió; `end` cierra una anotación sobre un rango. En microsegundos. |
| `service`, `namespace`, `environment`, `version` | De qué trataba un cambio reportado o una versión. |
| `status` | Cómo resultó un cambio reportado: `succeeded`, `failed` o `rolled_back`. |
| `title`, `description`, `tags` | El título de una anotación o de una regla, y lo que un cambio indicó de sí mismo. |
| `commit`, `repositoryUrl`, `pullRequestUrl`, `author`, `ciUrl` | De dónde provino un cambio reportado. |
| `dashboardId`, `stream` | A qué pertenece una anotación. |
| `ruleId` | La regla que se editó. |

## Mantener anotaciones

`POST /api/v1/changes` crea una anotación y requiere `dashboards.annotations.manage`:

```json
{
  "title": "Load test",
  "description": "k6, 2,000 users",
  "tags": ["test"],
  "timeStart": 1792312800000000,
  "timeEnd": 1792314600000000,
  "dashboardId": "dash-1",
  "streamName": null
}
```

`GET /api/v1/changes/{id}` lee una anotación con `dashboards.annotations.read`. `PUT` y `PATCH`
cambian los campos que indican, y `DELETE` la elimina, con `dashboards.annotations.manage`. Estas llamadas
solo llegan a anotaciones; un id que no corresponda a una anotación de la organización responde `404`.
Mole Agent mantiene las anotaciones con `create_annotation`, `update_annotation` y `delete_annotation`, y
lista los cambios con `list_changes`.
