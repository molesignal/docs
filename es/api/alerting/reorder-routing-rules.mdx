```http
PUT /api/v1/alerts/routing/rules/order
```

Coloca las [reglas de enrutamiento](/es/alerting/routing#reglas-de-enrutamiento) de la organización en el orden indicado. Requiere `alerts.routing.manage`. Las reglas de la lista van primero, en el orden indicado; las demás conservan su orden relativo. La operación ignora los ID que no corresponden a reglas de la organización.

| Campo | Tipo | Descripción |
|---|---|---|
| `ids` | matriz | Obligatorio. ID de las reglas en el orden en que se prueban. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/order \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<rule-id-2>", "<rule-id-1>"]}'
```
</RequestExample>

La respuesta incluye todas las reglas en el nuevo orden, con valores consecutivos de `position` a partir de 0. Consulta [Campos de las reglas](/es/api/alerting/list-routing-rules#campos-de-la-regla).

**Errores**

| Estado | Causa |
|---|---|
| `403` | El token no tiene el permiso `alerts.routing.manage`. |
| `422` | Falta `ids` o la solicitud incluye otro campo. La respuesta está en texto sin formato. |
