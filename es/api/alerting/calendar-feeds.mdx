Una aplicación de calendario (Google Calendar, Outlook, Apple Calendar, entre otras) consulta la dirección de suscripción. La dirección
devuelve un calendario en formato iCalendar (RFC 5545) con los turnos de los últimos 30 días y los próximos 90 días, incluidos los reemplazos y los intercambios.
Una fuente incluye todos los turnos de una programación o solo los turnos de la cuenta suscrita en todas las programaciones.

| Método y ruta | Qué hace | Permiso |
|---|---|---|
| `GET /api/v1/schedules/calendar-feeds` | Devuelve las fuentes de la cuenta actual. | `schedules.read` |
| `POST /api/v1/schedules/calendar-feeds` | Crea una dirección de suscripción. Si la misma programación (o la fuente personal) ya tiene una dirección, genera una nueva e invalida la anterior de inmediato. | `schedules.calendar_feeds.manage` y, para una fuente de programación, `schedules.calendar_feeds.manage` en esa programación |
| `DELETE /api/v1/schedules/calendar-feeds/{id}` | Desactiva una fuente de la cuenta actual e invalida su dirección de inmediato. | `schedules.calendar_feeds.manage` |
| `GET /api/v1/public/calendar/{token}.ics` | Proporciona la dirección que consulta la aplicación de calendario sin iniciar sesión. | El token de la dirección |

## Crea una dirección de suscripción

**Cuerpo de la solicitud**

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `scheduleId` | string | No | Suscribe la cuenta a esta programación. Omite el campo para crear una fuente personal. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/calendar-feeds \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"scheduleId": "<schedule-id>"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "feed": {
    "id": "3KHtq0dYc1fUe8WnP2xLbR7aZsM",
    "scheduleId": "<schedule-id>",
    "scheduleName": "Payments primary",
    "createdAt": 1790000000000000,
    "lastUsedAt": null
  },
  "path": "/api/v1/public/calendar/<token>.ics",
  "url": "https://molesignal.example.com/api/v1/public/calendar/<token>.ics"
}
```
</ResponseExample>

La respuesta muestra la dirección solo aquí y una sola vez. MoleSignal solo guarda el hash SHA-256 del token. `url` se genera a partir de la
dirección externa de la instancia y vale `null` si no hay ninguna configurada. En ese caso, agrega `path` al final de la dirección
que usas para acceder a MoleSignal. Cada fuente de la lista incluye `id`, `scheduleId`, `scheduleName`, `createdAt` y
`lastUsedAt`, que indica cuándo se consultó por última vez desde una aplicación de calendario. La lista no incluye la dirección de suscripción.

## Cómo consulta la fuente la aplicación de calendario

```http
GET /api/v1/public/calendar/{token}.ics
```

En cada consulta, MoleSignal verifica que la cuenta suscrita siga activa, siga perteneciendo a la organización y conserve
el permiso `schedules.read`. Si la fuente corresponde a una programación, también verifica que la cuenta siga teniendo acceso a esa programación.
Si falla alguna comprobación, el token es incorrecto o la fuente está desactivada, MoleSignal devuelve `404`. Los títulos y las descripciones de los turnos usan el idioma
de la interfaz de la cuenta suscrita.

Cualquiera que tenga la dirección puede ver estos turnos. Si se filtra la dirección, genera una nueva o desactiva la fuente.
