```http
PUT /api/v1/alerts/sources/{id}
```

Guarda de nuevo toda la configuración de una [fuente de alertas](/es/alerting/sources). Requiere `alerts.sources.manage`. Los campos son los mismos que en [Crear una fuente de alertas](/es/api/alerting/create-source). El tipo no puede cambiar, así que, si especificas `kind`, usa el valor actual. El token no cambia. Para cambiarlo, consulta [Rotar un token](/es/api/alerting/rotate-source-token). Si omites `homeCluster`, se conserva el clúster receptor. Los incidentes que ya están abiertos conservan su política de escalamiento y sus etiquetas.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/sources/$SOURCE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Production Prometheus", "enabled": false, "escalationPolicyId": "default", "severity": "error"}'
```
</RequestExample>

La respuesta contiene la fuente actualizada, sin el campo `token`.

**Errores**

| Estado | Causa |
|---|---|
| `400` | Un campo es incorrecto o el tipo cambió. |
| `403` | El token no tiene el permiso `alerts.sources.manage`. |
| `404` | La fuente no existe. |
