```http
GET /api/v1/alerts/incidents/{id}/timeline
```

Devuelve lo que ocurrió en un incidente: los pasos que registraron los usuarios y MoleSignal, las notificaciones
que se enviaron al respecto y los incidentes que se fusionaron con él. La llamada requiere `alerts.incidents.read`. La consola usa estos datos para construir la
[cronología](/es/alerting/incidents#detalles-del-incidente) del incidente.

| Campo | Contenido |
|---|---|
| `entries` | Los pasos registrados, del más antiguo al más reciente: `id`, `orgId`, `incidentId`, `at` en microsegundos, `kind`, `actor` (el ID del usuario o `null` si fue MoleSignal) y `detail`. |
| `deliveries` | Las notificaciones del incidente, de la más antigua a la más reciente, hasta un máximo de 500: `id`, `eventId` (`alert.triggered:…`, `alert.escalated:…`, `alert.acknowledged:…` o `alert.resolved:…`), `userId`, `connectorId`, `target` (enmascarado), `stage`, `status`, `error`, `createdAt` y `deliveredAt`. Si un [pipeline impidió que una política enviara una notificación](/es/pipelines/alert-events#antes-de-una-notificación), `status` es `skipped`, no aparecen `userId` ni `connectorId` y `error` contiene el motivo. |
| `merged` | Los incidentes [fusionados](/es/api/alerting/merge-incidents) con este: `id`, `summary`, `status`, `severity`, `createdAt` y `resolvedAt`. |

| `kind` | `detail` |
|---|---|
| `acknowledged`, `resolved` | `via`: `web`, `api`, `im`, `sms`, `phone` o `agent`. |
| `escalated` | `step` (a partir de 0), `loop`, `reason` y los `targets` del paso. |
| `reassigned` | `to`, como en [Reasignar un incidente](/es/api/alerting/reassign-incident), y `from`: los responsables, el equipo y la política anteriores. |
| `responders_added` | `userIds`. |
| `snoozed` | `until` en microsegundos y `durationSecs`. |
| `snooze_cancelled` | Vacío. |
| `retriggered` | `reason`: `snooze_ended` o `ack_timeout`. |
| `severity_changed` | `from` y `to`. |
| `merged` | `into`: el incidente al que se incorporó. |
| `merged_in` | `incidents`: los incidentes que se incorporaron a este. |
| `merged_recovered` | `incidentId` y `summary` de un incidente fusionado que se recuperó. |
| `note` | `text` y `via`. |
| `remediation_requested` | Se solicitó una [acción de remediación](/es/api/alerting/remediation): el ID de ejecución `runId`, el nombre de la acción `action` y las entradas proporcionadas en `inputs`. |
| `remediation_executed` | Finalizó una acción de remediación: `runId`, `action`, `status` (`succeeded` o `failed`) y `output` (el inicio de la respuesta o el error). |
| `remediation_verified` | La verificación posterior a una ejecución: `runId`, `action`, `passed` y el método de verificación, `by` (`incidentResolved` o `rule_healthy`). |
| `ticket_created` | Se creó un [ticket](/es/api/alerting/tickets): `system` (`jira` o `meegle`), `key`, `url` y el nombre del conector `connector`. |
| `ticket_updated` | Una sincronización detectó un cambio en el estado del ticket: `key`, `status` y `done`. |
| `declared_major` | Se declaró un [incidente grave](/es/api/alerting/major-incidents); `auto` es `true` si lo declaró la regla de la organización. |
| `role_assigned` | Se asignó un rol: `role` (`commander`, `communications` o `scribe`) y `userId`, que es `null` si se quitó la asignación. |
| `war_room_created` | Se creó la sala de coordinación: `platform`, el enlace para unirse `url` y el enlace a la reunión `meetingUrl`. |
| `task_added`, `task_done` | Se agregó o se completó una tarea: `title`. |
| `status_update` | Se publicó una actualización: `impact`, `current` y `next`. |
| `pipeline_processed` | Un [pipeline de alertas](/es/pipelines/alert-events#qué-ocurre-con-un-evento) modificó el evento antes de que se abriera el incidente o falló: `pipelineId`, `pipeline`, `changes` (cada cambio incluye `field`, como `severity` o `labels.team`, `from`, que no aparece en las adiciones, y `to`, que no aparece en las eliminaciones), `more` (la cantidad de cambios adicionales a los 40 que se muestran) y `error`. |

<RequestExample>
```bash cURL
curl -X GET http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/timeline \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

La respuesta contiene las tres listas.

**Errores**

| Estado | Causa |
|---|---|
| `403` | El token no tiene el permiso `alerts.incidents.read`. |
| `404` | El incidente no existe. |
