```http
GET    /api/v1/alerts/holiday-calendars
POST   /api/v1/alerts/holiday-calendars
GET    /api/v1/alerts/holiday-calendars/{id}
PUT    /api/v1/alerts/holiday-calendars/{id}
DELETE /api/v1/alerts/holiday-calendars/{id}
GET    /api/v1/alerts/holiday-calendars/{id}/references
POST   /api/v1/alerts/holiday-calendars/parse
```

Consultar un calendario requiere `alerts.calendars.read`. Crear, modificar o eliminar un calendario, o leer un archivo, requiere `alerts.calendars.manage`.
Consulta [Calendarios de días festivos](/es/alerting/on-call#calendarios-de-días-festivos) para saber cómo afectan al horario semanal.

## Crea o modifica un calendario

`POST` crea un calendario y `PUT` lo reemplaza. La respuesta incluye el calendario con su `id`,
`orgId`, `createdBy`, `createdAt` y `updatedAt`.

| Campo | Tipo | Obligatorio | Descripción |
|---|---|---|---|
| `name` | string | Sí | Hasta 80 caracteres. Debe ser único en la organización. |
| `description` | string | No | Hasta 500 caracteres. |
| `days` | array | No | Hasta 2.000 días, cada uno con el formato `{"date": "2026-10-14", "kind": "holiday", "name": "National Day"}`. `kind` puede ser `holiday` (día no laborable) o `workday` (día laborable de compensación, que cuenta como lunes). `name` admite hasta 80 caracteres. Cada fecha puede aparecer una sola vez. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/holiday-calendars \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "China 2026", "days": [{"date": "2026-10-01", "kind": "holiday", "name": "National Day"}, {"date": "2026-10-10", "kind": "workday", "name": "Make-up workday"}]}'
```
</RequestExample>

Para usar un calendario, pon su ID en el campo `calendar` del horario semanal:
`{"calendarId": "<id>", "holidays": "exclude"}` excluye los días no laborables y `"holidays": "only"`
aplica el horario solo en días no laborables. Puedes usar el calendario en el horario de atención de las
[políticas de escalamiento](/es/api/alerting/create-escalation), en las condiciones horarias de las
[reglas de enrutamiento](/es/api/alerting/create-routing-rule) y las políticas de notificación, en las rotaciones de los turnos de
guardia, en los flujos de procesamiento de alertas y en los periodos semanales de silenciamiento. Si guardas cualquiera de estas configuraciones con un calendario que no pertenece a
la organización, la API devuelve `400`.

## Lee un archivo ICS

`POST /parse` acepta `{"content": "<the .ics text>"}`, de hasta 2 MiB, y devuelve `{"days": [...]}` sin
guardar nada: convierte cada evento de día completo en un día y cada evento de varios días en un día por cada fecha que abarca.
Si el nombre contiene 补班 o 上班, o termina en 班, clasifica el día como `workday`.

## Consulta qué usa un calendario

`GET /{id}/references` enumera los elementos que usan el calendario con el formato `{"kind", "id", "name"}`. `kind` puede ser
`routing_rule`, `escalationPolicy`, `schedule`, `mute_rule`, `notify_policy` o `alert_pipeline`.
`DELETE` devuelve `409` mientras la lista contenga elementos.

**Errores**

| Estado | Motivo |
|---|---|
| `400` | Un campo no respeta sus límites, una fecha aparece dos veces o la API no puede leer el archivo. |
| `403` | El token no tiene el permiso necesario. |
| `404` | El calendario no existe en la organización. |
| `409` | Otro calendario tiene el mismo nombre o el calendario está en uso. |
