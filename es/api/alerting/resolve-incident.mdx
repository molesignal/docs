```http
POST /api/v1/alerts/incidents/{id}/resolve
```

Resuelve un incidente con estado `open` o `acknowledged`. La llamada cambia el estado a `resolved`, registra quién hizo la llamada y a qué hora en `resolvedBy` y `resolvedAt`, y detiene el escalamiento. También marca como confirmada la notificación que se disparó y envía un evento `alert.resolved`. La llamada requiere el permiso `alerts.incidents.acknowledge` y el cuerpo está vacío.

Al resolver un incidente, también se resuelven los incidentes que se [fusionaron](/es/api/alerting/merge-incidents) con él. Si la regla sigue cumpliéndose, abre un nuevo incidente en la siguiente evaluación. Resolver un incidente no desactiva la regla.

<Note>
  Si el incidente ya está en estado `resolved` o `closed`, la llamada lo devuelve sin cambios. El usuario
  y la hora originales se conservan en `resolvedBy` y `resolvedAt`, y la llamada no vuelve a enviar el evento.
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/resolve \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

La respuesta contiene el incidente actualizado. [Listar incidentes](/es/api/alerting/list-incidents) describe todos los campos.

**Errores**

| Estado | Causa |
|---|---|
| `403` | El token no tiene el permiso `alerts.incidents.acknowledge`. |
| `404` | El incidente no existe. |
