```http
PUT /api/v1/alerts/routing/rules/{id}
```

Reemplaza por completo una [regla de enrutamiento](/es/alerting/routing#reglas-de-enrutamiento). Requiere `alerts.routing.manage`. Usa los mismos campos que [Crear una regla de enrutamiento](/es/api/alerting/create-routing-rule). Si omites un campo opcional, vuelve a su valor predeterminado. La regla conserva su posición. Para cambiarla, usa [Reordenar las reglas de enrutamiento](/es/api/alerting/reorder-routing-rules). La actualización no afecta a los incidentes que ya están abiertos.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "enabled": false, "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

La respuesta contiene la regla actualizada.

**Errores**

| Estado | Causa |
|---|---|
| `400` | Uno de los campos no es válido o no existe el equipo o la política de destino. |
| `403` | El token no tiene el permiso `alerts.routing.manage`. |
| `404` | La regla no existe o pertenece a otra organización. |
| `422` | Falta `name` o `target`, o la API no reconoce un valor. La respuesta está en texto plano. |
