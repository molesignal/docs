```http
PUT /api/v1/alerts/incidents/{id}/severity
```

Establece la severidad de un incidente activo y registra en `severitySetBy` quién hizo la solicitud. A partir de ese momento,
la evaluación de la regla ya no cambia la severidad. Si aumentas la severidad de un incidente `open`, el escalamiento se
reinicia desde el primer paso que corresponde a la nueva severidad y establece `escalation.reason` en
`severity_raised`. Si reduces la severidad o cambias la de un incidente reconocido, solo cambia la severidad. La solicitud
requiere `alerts.incidents.update`.

**Cuerpo**

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `severity` | cadena | Sí | `info`, `warning`, `error` o `critical`. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/severity \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"severity": "critical"}'
```
</RequestExample>

La respuesta contiene el incidente actualizado. [Listar incidentes](/es/api/alerting/list-incidents) describe cada campo.

**Errores**

| Estado | Causa |
|---|---|
| `422` | Falta `severity` o su valor no es uno de los cuatro permitidos. |
| `403` | El token no tiene el permiso `alerts.incidents.update` o el incidente está fuera del alcance del token. |
| `404` | El incidente no existe. |
| `409` | El incidente se recuperó, se fusionó con otro o siguió cambiando durante la actualización. Vuelve a intentarlo. |
