```http
POST /api/v1/alerts/incidents
```

Abre un incidente para un problema que ninguna regla detectó, como uno notificado por un cliente. El incidente lleva la
etiqueta `alert.source=manual`, las anotaciones `createdBy` (quien realiza la llamada) y `description`, y el
`ruleId` `manual`. Omite los flujos de procesamiento de alertas. MoleSignal nunca lo deduplica con otro incidente ni
lo resuelve automáticamente. Esta llamada requiere `alerts.incidents.create` y registra el evento de auditoría
`alert.incident.created`.

**Cuerpo de la solicitud**

| Campo | Tipo | Obligatorio | Descripción |
|---|---|---|---|
| `title` | string | Sí | Hasta 200 caracteres. |
| `description` | string | No | Markdown, hasta 20000 caracteres. |
| `severity` | string | No | `info`, `warning`, `error` (predeterminado) o `critical`. |
| `urgency` | string | No | La clave de uno de los [niveles de urgencia](/es/alerting/on-call#niveles-de-urgencia-y-prioridad) de la organización, como `high` o `low`. Si omites este campo, la política de escalamiento del incidente determina la urgencia. Consulta [Urgencia](/es/alerting/on-call#urgencia). |
| `priority` | string | No | Una de las prioridades de la organización, de `P1` a `P5` de forma predeterminada (hasta `P9`). |
| `assign` | object | No | Determina quién se hace cargo del incidente. La opción predeterminada, `{"kind": "auto"}`, usa el [enrutamiento de alertas](/es/alerting/routing). `{"kind": "team", "teamId": "..."}` usa la política de guardia del equipo. `{"kind": "policy", "escalationPolicyId": "..."}` usa la política indicada. `{"kind": "users", "userIds": [...]}` notifica directamente a entre 1 y 10 miembros de la organización, sin aplicar una política de escalamiento. |
| `services` | string[] | No | Los servicios afectados, hasta 20. |
| `labels` | object | No | Hasta 50 etiquetas. `alert.source` siempre tiene el valor `manual`. |
| `declareMajor` | boolean | No | También declara un [incidente grave](/es/alerting/major-incidents). MoleSignal abre el incidente aunque falle la declaración. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"title": "Customers in the north cannot pay", "severity": "critical", "priority": "P1", "assign": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

La respuesta contiene el incidente. Consulta [Listar incidentes](/es/api/alerting/list-incidents) para conocer sus campos.

**Errores**

| Estado | Motivo |
|---|---|
| `400` | Falta el título o es demasiado largo, hay demasiadas etiquetas o servicios, `users` no indica entre 1 y 10 personas, o el equipo, la política o las personas no pertenecen a la organización. |
| `403` | El token no tiene el permiso `alerts.incidents.create`. |
