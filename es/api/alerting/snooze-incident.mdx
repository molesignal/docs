```http
POST /api/v1/alerts/incidents/{id}/snooze
DELETE /api/v1/alerts/incidents/{id}/snooze
```

`POST` pospone un incidente activo durante `durationSecs`. Si el incidente está en estado `open`, quien realiza la llamada
primero lo confirma. Mientras esté pospuesto, el incidente no envía notificaciones ni se escala. Cuando
se alcanza `snoozedUntil`, el incidente vuelve al estado `open` y las personas asignadas reciben una notificación de escalamiento cuyo
`escalation.reason` es `snooze_ended`. Posponer un incidente ya pospuesto cambia la hora de finalización de la pausa.

`DELETE` termina la pausa de inmediato. El incidente sigue en estado `acknowledged`. Ambas llamadas requieren el permiso
`alerts.incidents.acknowledge`. `DELETE` no tiene cuerpo.

**Cuerpo**

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `durationSecs` | entero | Sí | De 60 (1 minuto) a 604800 (7 días). |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/snooze \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"durationSecs": 3600}'
```
</RequestExample>

La respuesta contiene el incidente actualizado. [Listar incidentes](/es/api/alerting/list-incidents) describe todos los campos.

**Errores**

| Estado | Causa |
|---|---|
| `400` | `durationSecs` es menor que 60 o mayor que 604800. |
| `403` | El token no tiene el permiso `alerts.incidents.acknowledge` o no permite acceder al incidente. |
| `404` | El incidente no existe. |
| `409` | El incidente se recuperó, se fusionó con otro o siguió cambiando durante la actualización. Vuelve a intentarlo. |
