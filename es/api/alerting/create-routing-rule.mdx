```http
POST /api/v1/alerts/routing/rules
```

Crea una [regla de enrutamiento](/es/alerting/routing#reglas-de-enrutamiento). Requiere `alerts.routing.manage`. La regla nueva se agrega al final. Usa [Reordenar reglas de enrutamiento](/es/api/alerting/reorder-routing-rules) para subirla. Una organización admite hasta 200 reglas de enrutamiento.

| Campo | Tipo | Descripción |
|---|---|---|
| `name` | cadena | Obligatorio. De 1 a 128 caracteres tras quitar los espacios al inicio y al final. |
| `enabled` | booleano | El valor predeterminado es `true`. |
| `conditions` | arreglo | Hasta 16 condiciones. El arreglo está vacío de forma predeterminada. Una `key` tiene entre 1 y 512 caracteres. `equals`, `not_equals` y `matches` aceptan un valor cada uno, mientras que `in` acepta entre 1 y 100 valores. Cada valor admite hasta 512 caracteres. El patrón de `matches` debe compilarse correctamente. |
| `minSeverity` | cadena \| null | `info`, `warning`, `error` o `critical`. De forma predeterminada, admite cualquier nivel de gravedad. |
| `origins` | arreglo | Admite uno o más de estos valores: `rule`, `external` y `synthetic`. De forma predeterminada, el arreglo está vacío e incluye todos los orígenes. |
| `target` | objeto | Obligatorio. `{"kind": "team", "teamId": …}` debe identificar un equipo de la organización y `{"kind": "policy", "policyId": …}` debe identificar una política de escalamiento de la organización. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "conditions": [{"key": "env", "operator": "equals", "values": ["prod"]}], "minSeverity": "error", "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

La respuesta devuelve la regla nueva. Consulta [Campos de la regla](/es/api/alerting/list-routing-rules#campos-de-la-regla).

**Errores**

| Estado | Causa |
|---|---|
| `400` | Hay un campo no válido: el nombre está vacío, una condición tiene un número incorrecto de valores, un patrón no se puede compilar o el equipo o la política de destino no existen. También se devuelve este error si la organización ya tiene 200 reglas. |
| `403` | El token no tiene el permiso `alerts.routing.manage`. |
| `422` | Falta `name` o `target`, o la API no reconoce un valor, como un `operator` desconocido. La respuesta se devuelve en texto plano. |
