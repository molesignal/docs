```http
GET /api/v1/alerts/importance
PUT /api/v1/alerts/importance
```

`GET` requiere `alerts.importance.read` y `PUT` requiere `alerts.importance.manage`. Ambos devuelven los niveles de la organización:

```json
{
  "levels": {
    "priorities": [
      {"priority": "P1", "name": "Critical business impact", "description": "Customers cannot pay"},
      {"priority": "P2", "name": "", "description": ""},
      {"priority": "P3", "name": "", "description": ""}
    ],
    "urgencies": [
      {"key": "urgent", "name": "Urgent", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["critical"]},
      {"key": "high", "name": "", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["error"]},
      {"key": "low", "name": "", "escalates": false, "quietHours": "block", "steps": "low", "severities": ["warning", "info"]}
    ]
  },
  "updatedBy": "3KF1...",
  "updatedAt": 1793059200000000
}
```

Una organización que nunca ha guardado niveles recibe los predeterminados: de `P1` a `P5`, y `high` y `low` tal como se
describen en [Urgencia](/es/alerting/on-call#urgencia), con `updatedBy` vacío. `PUT` recibe el objeto
`levels`, reemplaza los niveles y registra el evento de auditoría `alert_importance.updated`.

| Campo | Descripción |
|---|---|
| `priorities` | De 1 a 9 niveles, `P1`, `P2`, … sin saltos. `name` admite hasta 32 caracteres y `description` hasta 200. Si el nombre está vacío, se usa la clave. |
| `urgencies` | De 2 a 5 niveles, con el más urgente primero. `key` empieza con una letra minúscula y admite letras minúsculas, dígitos y guiones bajos, hasta un máximo de 32 caracteres. Conserva `high` y `low`. `name` admite hasta 32 caracteres. Si el nombre está vacío, se usa el nombre predeterminado. |
| `escalates` | `true` envía avisos de guardia siguiendo los pasos de la política de escalamiento; `false` solo envía notificaciones en el primer paso. |
| `quietHours` | `switch` respeta la opción **Recibir alertas de urgencia alta incluso durante el horario de silencio** de cada persona; `block` nunca envía avisos de guardia durante el horario de silencio. |
| `steps` | Indica cuál de los dos grupos de pasos de cada persona usa el nivel: `high` o `low`. |
| `severities` | Severidades asignadas al nivel cuando una política establece la urgencia según la severidad. Cada una de las severidades `critical`, `error`, `warning` e `info` se asigna a un solo nivel. |

Los niveles determinan qué prioridades y urgencias pueden usar las reglas, las políticas de escalamiento, los incidentes y la API. Una prioridad fuera de los
niveles configurados o una urgencia que no corresponde a ningún nivel genera un error `400` en esos casos. Si una alerta externa o un pipeline de alertas
especifica una prioridad fuera de los niveles configurados, MoleSignal usa la más baja. Si especifica una urgencia que la organización no
tiene, MoleSignal descarta esa urgencia. Las notificaciones incluyen los nombres como `{{priority_name}}` y `{{urgency_name}}`.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/importance \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d @levels.json
```
</RequestExample>

**Errores**

| Estado | Motivo |
|---|---|
| `400` | Los niveles incumplen una regla de la tabla anterior. |
| `403` | El token no tiene el permiso necesario. |
| `422` | Un campo tiene un tipo incorrecto o una clave no es válida. |
