```http
POST /api/v1/alerts/incidents/{id}/escalate
```

Mueve un incidente activo a un paso de su política de escalamiento y notifica de inmediato a los destinatarios de ese paso,
con `escalation.reason` establecido en `manual`. Si no se especifica `step`, se usa el siguiente paso que corresponda a la
gravedad del incidente. Si el incidente está en `acknowledged`, vuelve a `open`. Se cancela cualquier aplazamiento y empieza a correr el
plazo de confirmación del paso. Si nadie confirma el incidente, el escalamiento continúa desde ese paso. La llamada requiere
`alerts.incidents.escalate` y el cuerpo puede estar vacío.

**Cuerpo**

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `step` | entero | No | El paso, numerado a partir de 0. Debe corresponder a la gravedad del incidente. Valor predeterminado: el siguiente paso que corresponda. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/escalate \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"step": 1}'
```
</RequestExample>

La respuesta contiene el incidente actualizado. [Listar incidentes](/es/api/alerting/list-incidents) describe todos los campos.

**Errores**

| Estado | Causa |
|---|---|
| `400` | El incidente no tiene una política de escalamiento; `step` supera el último paso de la política o no corresponde a la gravedad del incidente; o el incidente está en el último paso y no se especificó `step`. |
| `403` | El token no tiene el permiso `alerts.incidents.escalate` o el incidente queda fuera del alcance del token. |
| `404` | El incidente no existe. |
| `409` | El incidente se recuperó, se fusionó con otro o siguió cambiando durante la actualización. Vuelve a intentarlo. |
