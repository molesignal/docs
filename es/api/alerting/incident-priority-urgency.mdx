```http
PUT /api/v1/alerts/incidents/{id}/priority
PUT /api/v1/alerts/incidents/{id}/urgency
```

Ambas llamadas requieren `alerts.incidents.update` y se aplican a un incidente activo que no se haya fusionado con otro. La
cronología registra `priority_changed` y `urgency_changed`.

- **Prioridad**: especifica `{"priority": "P2"}` en el cuerpo o `null` para dejar el incidente sin prioridad. Usa uno de los
  [niveles de prioridad](/es/alerting/on-call#niveles-de-urgencia-y-prioridad) de la organización. La llamada solo cambia la prioridad y
  no vuelve a enviar notificaciones.
- **Urgencia**: especifica en el cuerpo la clave de uno de los niveles de urgencia de la organización, por ejemplo,
  `{"urgency": "high"}`. La llamada registra en `urgencySetBy` quién la hizo. El horario de soporte ya no modifica
  la urgencia. Si aumentas la urgencia de un incidente `open`, se vuelven a enviar notificaciones desde el primer paso aplicable,
  con el valor `urgency_raised` en `escalation.reason`. Un nivel menos urgente solo cambia la urgencia. Un nivel
  que no hace avanzar el escalamiento lo detiene.

Para cambiar varios incidentes a la vez, usa [acciones masivas](/es/api/alerting/bulk-incidents) con
`{"action": "set_priority", "priority": "P2"}` y `{"action": "set_urgency", "urgency": "low"}`.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/urgency \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"urgency": "high"}'
```
</RequestExample>

La respuesta devuelve el incidente. El campo `urgency` contiene la clave de un nivel (los incidentes que se abrieron antes de que existiera el campo
no lo incluyen y se consideran de urgencia alta). El campo `priority` contiene un valor de `P1` a `P9` o no aparece. El campo `urgencyByPolicy` vale
`true` cuando la política de escalamiento determina la urgencia.

**Errores**

| Estado | Motivo |
|---|---|
| `400` | La prioridad está fuera del rango de niveles de la organización o la urgencia no corresponde a ninguno de sus niveles. |
| `422` | La prioridad no es un valor de `P1` a `P9` o la urgencia no es una clave compuesta por letras minúsculas, dígitos y guiones bajos. |
| `403` | El token no tiene el permiso `alerts.incidents.update` o no permite acceder al incidente. |
| `404` | El incidente no existe. |
| `409` | El incidente se recuperó o se fusionó con otro. |
