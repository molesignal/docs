```http
POST /api/v1/alerts/incidents/{id}/responders
```

Agrega a las personas indicadas en `userIds` a la lista de responsables de un incidente activo y envía a cada nueva incorporación una
notificación de escalamiento con `escalation.reason` igual a `responder_added`. El estado del incidente no cambia
y quienes ya figuran como responsables no reciben otra notificación. La llamada requiere `alerts.incidents.update`.

**Cuerpo**

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `userIds` | arreglo | Sí | De 1 a 10 ID de usuario de miembros de la organización. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/responders \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"userIds": ["<another-user-id>"]}'
```
</RequestExample>

La respuesta contiene el incidente actualizado. [Listar incidentes](/es/api/alerting/list-incidents) describe cada campo.

**Errores**

| Estado | Causa |
|---|---|
| `400` | `userIds` está vacío, contiene más de 10 usuarios o incluye a un usuario ajeno a la organización. |
| `403` | El token no tiene el permiso `alerts.incidents.update` o no permite acceder al incidente. |
| `404` | El incidente no existe. |
| `409` | El incidente volvió a la normalidad, se fusionó con otro o siguió cambiando durante la actualización. Vuelve a intentarlo. |
