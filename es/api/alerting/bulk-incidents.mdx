```http
POST /api/v1/alerts/incidents/bulk
```

Aplica una acción a cada incidente de `ids`, uno a la vez: si no se puede procesar un incidente,
los demás se siguen procesando. `action` indica qué hacer y va acompañado de los campos que requiere:

| `action` | Campos | Qué hace |
|---|---|---|
| `acknowledge` | Ninguno | Igual que [Confirmar la recepción de un incidente](/es/api/alerting/ack-incident). |
| `resolve` | Ninguno | Igual que [Resolver un incidente](/es/api/alerting/resolve-incident). |
| `snooze` | `durationSecs` | Igual que [Posponer un incidente](/es/api/alerting/snooze-incident). |
| `reassign` | `to`, el cuerpo de [Reasignar un incidente](/es/api/alerting/reassign-incident) | Igual que esa llamada. |
| `set_severity` | `severity` | Igual que [Establecer la gravedad de un incidente](/es/api/alerting/set-incident-severity). |

La llamada requiere `alerts.incidents.acknowledge` y valida cada incidente igual que las llamadas individuales.
La fusión no es una acción masiva; usa [Fusionar incidentes](/es/api/alerting/merge-incidents).

**Cuerpo**

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `ids` | arreglo | Sí | De 1 a 100 ID de incidentes; los ID repetidos cuentan una sola vez. |
| `action` | cadena | Sí | `acknowledge`, `resolve`, `snooze`, `reassign` o `set_severity`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<incident-id>", "<another-incident-id>"], "action": "snooze", "durationSecs": 3600}'
```
</RequestExample>

La respuesta incluye un resultado por incidente: `id` y, si no se pudo procesar, `error`. Esto puede ocurrir, por ejemplo, si el incidente ya se recuperó o si `durationSecs` está fuera del rango permitido.

<ResponseExample>
```json 200
{
  "results": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW"
    },
    {
      "id": "3KEDQ4mJ8sLp2Xv6Nc1Rt9bYwHe",
      "error": "this incident is no longer active"
    }
  ]
}
```
</ResponseExample>

**Errores**

| Estado | Causa |
|---|---|
| `400` | `ids` está vacío o contiene más de 100 incidentes. |
| `403` | El token no tiene el permiso `alerts.incidents.acknowledge`. |
| `422` | Falta `action`, su valor no se reconoce o falta un campo que requiere. |
