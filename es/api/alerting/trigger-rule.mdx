```http
POST /api/v1/alerts/rules/{id}/trigger
```

Abre un incidente para una regla sin evaluar su condición. Usa esta llamada para probar las notificaciones y el escalamiento, o para abrir un incidente manualmente. La llamada funciona con reglas deshabilitadas. Requiere `alerts.rules.manage` y el cuerpo está vacío.

- Si la regla ya tiene un incidente abierto o reconocido, la llamada devuelve ese incidente sin cambios. Puedes repetir la llamada sin riesgo.
- De lo contrario, la llamada crea un incidente con el estado `open` y envía el evento de notificación de activación.
- La llamada usa el primer valor disponible en este orden: el campo `severity` de la regla, la etiqueta `severity` y `warning`. La llamada ignora `thresholds`.
- La anotación `manual_triggered_by` contiene el identificador de la cuenta que realiza la llamada, y `triggering_query.sample_values` está vacío.

Una regla habilitada resuelve el incidente en la siguiente evaluación si no se cumple su condición. Una regla deshabilitada mantiene el incidente abierto hasta que alguien lo resuelva.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/trigger \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**Errores**

| Estado | Causa |
|---|---|
| `403` | El token no tiene el permiso `alerts.rules.manage`. |
| `404` | La regla no existe. |
