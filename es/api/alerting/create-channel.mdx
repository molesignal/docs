Un conector almacena las credenciales y la configuración de transporte de un proveedor de notificaciones para una organización. Para listar y consultar conectores, se requiere `notify.connectors.read`. Para crear, actualizar, probar y eliminar un conector, se requiere `notify.connectors.manage`.

| Operación | Endpoint |
|---|---|
| Listar los tipos de conector | `GET /api/v1/notify/connector-types` |
| Listar los conectores | `GET /api/v1/notify/connectors` |
| Crear un conector | `POST /api/v1/notify/connectors` |
| Obtener un conector | `GET /api/v1/notify/connectors/{id}` |
| Actualizar un conector | `PUT /api/v1/notify/connectors/{id}` |
| Probar un conector | `POST /api/v1/notify/connectors/{id}/test` |
| Eliminar un conector | `DELETE /api/v1/notify/connectors/{id}` |

## Tipos de conector

La lista de tipos devuelve `connectorType`, `capabilities` y `addresses` para cada tipo que registra el backend en ejecución. Los tipos son `email_smtp`, `lark_app`, `lark_webhook`, `slackApp`, `slack_webhook` y `webhook`.

```json
[
  {
    "connectorType": "slack_app",
    "capabilities": {
      "directUser": true,
      "group": true,
      "richText": true,
      "interactive": true,
      "acknowledgement": false,
      "attachments": false
    },
    "addresses": [
      {
        "field": "apiBaseUrl",
        "picker": "site",
        "choices": [
          { "key": "slack", "url": "https://slack.com/api" },
          { "key": "govslack", "url": "https://slack-gov.com/api" }
        ]
      }
    ]
  }
]
```

`addresses` enumera las direcciones del proveedor que almacena `config` para un tipo de conector. Si la dirección se ingresa manualmente, como en el caso de un webhook o de SMTP, el tipo no tiene direcciones predefinidas y devuelve una lista vacía.

| Campo | Significado |
|---|---|
| `field` | La clave de `config`, como `apiBaseUrl`, `serviceUrl` o `wsUrl`. |
| `choices` | Las direcciones que admite la clave, cada una con `key` y `url`; la primera es la predeterminada. |
| `picker` | El criterio para elegir entre varias direcciones: `site` (plataforma) o `cloud`. La elección no se guarda. |
| `byRegion` | La dirección depende de la región elegida (Alibaba Cloud, AWS): `https://{service}.{region}.{one of domains}`. `choices` solo contiene la dirección que se usa antes de elegir una región. |

Al crear, actualizar o probar un conector, o al hacer un envío directo, estas claves solo admiten las direcciones de esta lista. Si la dirección es regional, solo se admite la que corresponde a la región indicada en `config`. Si falta una clave, se usa el valor predeterminado. La API rechaza cualquier otra dirección para evitar que las credenciales se envíen a otro destino.

El objeto `config` de un conector depende de su tipo. El valor predeterminado de `timeoutSecs` es 10 en todos los tipos y el intervalo permitido es de 1 a 60. Las URL deben ser absolutas y usar `http` o `https`. Las direcciones de proveedor deben figurar en `addresses` para ese tipo.

| `connectorType` | Claves de `config` |
|---|---|
| `email_smtp` | `host` y `from` (obligatorios), `port` (`587` de forma predeterminada), `username`, `password`, `tls` (`none`, `starttls` de forma predeterminada o `tls`), `timeoutSecs` |
| `slackApp` | `botToken`, `clientId` y `clientSecret` (el token del bot, el ID y el secreto del cliente, o los tres), `apiBaseUrl` (`https://slack.com/api` de forma predeterminada o `https://slack-gov.com/api` para GovSlack), `timeoutSecs` |
| `slack_webhook` | `webhookUrl` (obligatorio), `timeoutSecs` |
| `lark_app` | `appId` y `appSecret` (obligatorios), `apiBaseUrl` (`https://open.feishu.cn/open-apis` de Feishu de forma predeterminada o `https://open.larksuite.com/open-apis` para Lark), `receiveIdType` (`open_id` de forma predeterminada, `userId`, `union_id`, `email` o `chatId`), `timeoutSecs` |
| `lark_webhook` | `webhookUrl` (obligatorio), `secret`, `timeoutSecs` |
| `webhook` | `url` (obligatorio), `method` (`post` de forma predeterminada, `put` o `patch`), `headers`, `timeoutSecs` |

Consulta [Canales de notificación](/es/notification-channels) para conocer cada proveedor y sus destinos.

## Crear un conector

```http
POST /api/v1/notify/connectors
```

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `name` | cadena | Sí | Único dentro de la organización. |
| `connectorType` | cadena | Sí | Uno de los tipos anteriores. El tipo no se puede cambiar después. |
| `config` | objeto | Sí | La configuración de ese tipo de conector. |
| `enabled` | booleano | No | El valor predeterminado es `true`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/notify/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "Operations webhook",
    "connectorType": "webhook",
    "config": {
      "url": "https://hooks.example.com/molesignal",
      "method": "post",
      "headers": { "Authorization": "Bearer <token>" },
      "timeoutSecs": 5
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "id": "3KEDlokKjNmves95sRzL8tXpflY",
  "organizationId": "<organization-id>",
  "name": "Operations webhook",
  "connectorType": "webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 5
  },
  "capabilities": {
    "directUser": true,
    "group": true,
    "richText": true,
    "interactive": false,
    "acknowledgement": false,
    "attachments": false
  },
  "enabled": true,
  "status": "unknown",
  "lastTestedAt": null,
  "lastTestStatus": null,
  "lastTestError": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

MoleSignal cifra todo el objeto `config` en reposo. Las respuestas reemplazan por `***` el valor de cada clave que almacena una credencial. Estas claves son `url`, `webhookUrl`, `headers` y todas las claves que terminan en `password`, `secret` o `token`. Las demás claves, como `host`, `from` y `timeoutSecs`, siguen siendo legibles.

`status` vale `unknown` hasta la primera prueba y, después, `connected` o `error`. `lastTestStatus` vale `success` o `failed`. El enrutamiento omite los conectores con el estado `error` hasta que superen una prueba posterior.

## Listar y obtener conectores

```http
GET /api/v1/notify/connectors
GET /api/v1/notify/connectors/{id}
```

La lista devuelve un arreglo de conectores con la estructura anterior. Si no existe el `id`, la API devuelve `404`.

## Actualizar un conector

```http
PUT /api/v1/notify/connectors/{id}
```

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `name` | cadena | Sí | El nuevo nombre. |
| `config` | objeto | No | La nueva configuración. Omite este campo para conservar la configuración guardada. |
| `enabled` | booleano | No | El valor predeterminado es `true`. Si omites el campo, el conector se habilita. |

Envía `***` en una clave enmascarada para conservar el secreto almacenado, o envía un nuevo valor en texto sin cifrar para reemplazarlo:

```json
{
  "name": "Operations webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 8
  },
  "enabled": true
}
```

## Probar un conector

```http
POST /api/v1/notify/connectors/{id}/test
```

La prueba envía un mensaje a través del conector. No se puede probar un conector deshabilitado.

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `targetType` | cadena | Sí | `directUser`, `fixed_address`, `fixed_group` o `webhook`. Cada tipo de conector admite solo algunos de estos valores. Por ejemplo, `email_smtp` admite `directUser` y `fixed_address`. |
| `target` | cadena | Sí | El destinatario: una dirección, un identificador del proveedor, un grupo o una URL, según `targetType`. |
| `message` | objeto | No | `title`, `text`, `markdown` y `html`. De forma predeterminada, se usan un título y un texto genéricos. |

<ResponseExample>
```json 200
{
  "sent": true,
  "testedAt": 1790000000000000,
  "elapsedMs": 3,
  "providerMessageId": "req-1",
  "error": null
}
```
</ResponseExample>

Si falla la entrega, la API devuelve `200` de todos modos, con `sent` en `false` y el motivo en `error`, por ejemplo, `unavailable: webhook request failed`. La prueba también actualiza `status`, `lastTestedAt`, `lastTestStatus` y `lastTestError` del conector.

## Eliminar un conector

```http
DELETE /api/v1/notify/connectors/{id}
```

Si la eliminación se realiza correctamente, la API devuelve `204` sin cuerpo de respuesta. Si un endpoint de usuario, una política de notificación, una ruta alternativa, una inspección programada de logs, una página de estado o Mole Agent en un servicio de mensajería instantánea todavía hace referencia al conector, la API devuelve `409` con `notify connector is referenced by user endpoints, policies, default routes, scheduled log inspections, status pages, or Mole Agent in IM`. Reasigna primero esas referencias.

## Errores

| Estado | Causa |
|---|---|
| `400` | La configuración de `config` no es válida para el tipo, el tipo no es compatible (`unsupported connector type: pagerduty`), el conector no admite el destino o el conector está deshabilitado. |
| `404` | El conector no existe. |
| `409` | Otro conector de la organización ya usa ese nombre o todavía hay referencias al conector que se intenta eliminar. |
| `422` | Falta un campo o un valor no es válido, por ejemplo, un `targetType` desconocido. La respuesta es texto sin formato. |
