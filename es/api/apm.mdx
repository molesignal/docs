La API de APM expone agregados con alcance de organización derivados de spans de trazas. Todos los endpoints usan el
prefijo `/api/v1/apm` y requieren un token de portador.

```http
Authorization: Bearer <token>
```

Un espacio de trabajo de organización requiere el permiso de lectura del área: `apm.services.read`, `apm.errors.read`,
`apm.error_rules.read`, `apm.definitions.read`, `apm.slos.read`, `apm.deployments.read`, o `apm.settings.read`. Un cliente de plataforma puede usar
`sys.telemetry.read` en el ámbito protegido `_sys`. Cada llamada que escribe indica qué requiere. Informar un despliegue requiere
`apm.deploy`.

## Endpoints

| Método y ruta | Respuesta |
|---|---|
| `GET /api/v1/apm/overview` | Resumen RED y tendencia de todos los servicios, salud de los servicios y su tendencia, clasificaciones, despliegues, entornos, brechas de instrumentación, transacciones principales, dependencias y errores. |
| `GET /api/v1/apm/insights` | Qué cambió respecto al periodo anterior y al mismo periodo una semana antes, versiones con peor desempeño, dónde se podría recuperar tiempo y los cambios cercanos a cada uno. |
| `GET /api/v1/apm/services` | Catálogo paginado de servicios con instrumentación, versiones, salud, métricas RED y filtros de trazas. |
| `GET /api/v1/apm/services/{service}` | Resumen del servicio, tendencia, transacciones, dependencias, errores y versiones. |
| `GET /api/v1/apm/services/{service}/instances` | Las instancias de un servicio en un entorno, con su versión, atributos de recursos y lo que atendió cada una. |
| `GET /api/v1/apm/services/{service}/coverage` | Si los logs, las métricas, los perfiles y las sesiones de navegador del servicio llegan a MoleSignal, durante el día anterior a `to`. |
| `GET /api/v1/apm/correlation` | Qué tan bien se vincula cada servicio en vista con sus logs, métricas, trazas y cambios, y los nombres de servicio en logs y métricas que APM no conoce. |
| `GET /api/v1/apm/transactions` | Métricas RED paginadas de transacciones y clasificación por tiempo total. |
| `GET /api/v1/apm/transactions/{transaction}` | Tendencia de la transacción, errores afectados, versiones y filtros de trazas. |
| `GET /api/v1/apm/dependencies` | Métricas RED paginadas de llamador/dependencia y clasificación por tiempo total. |
| `GET /api/v1/apm/map` | El mapa de servicios de un entorno y espacio de nombres: servicios, a qué llaman, temas y las llamadas entre ellos. |
| `GET /api/v1/apm/map/edge` | Una llamada del mapa: su tendencia, qué se solicitó a través de ella y los errores de un servicio llamado. |
| `GET /api/v1/apm/blast-radius` | Qué alcanza un servicio a lo largo del mapa: qué lo llama y a qué llama, salto a salto. |
| `GET /api/v1/apm/errors` | Grupos de errores de backend saneados y paginados, con dónde ocurrieron los grupos listados. |
| `GET /api/v1/apm/errors/{fingerprint}` | Tendencia del error, transacciones y versiones afectadas, dónde ocurrió el grupo, stack representativo y muestras acotadas. |
| `GET /api/v1/apm/versions/compare` | Métricas RED de referencia y del candidato, deltas, estado de suficiencia y regresiones. |
| `GET /api/v1/apm/health` | Estado de la proyección del tenant, salud del runtime, límites y brechas. |
| `GET /api/v1/apm/service-definitions` | Todas las definiciones de servicio de la organización. |
| `PUT /api/v1/apm/service-definitions/{service}?namespace=` | Crea o reemplaza la definición de un servicio. Requiere `apm.definitions.manage`. |
| `DELETE /api/v1/apm/service-definitions/{service}?namespace=` | Elimina la definición de un servicio. Requiere `apm.definitions.manage`. |
| `POST /api/v1/apm/service-definitions/{service}/key-transactions?namespace=` | Marca con estrella un endpoint como transacción clave del servicio o quita la estrella. Requiere `apm.definitions.manage`. |
| `PUT /api/v1/apm/errors/{fingerprint}/issue` | Establece el estado, el equipo y el responsable de un grupo de errores. Requiere `apm.errors.manage`. |
| `GET /api/v1/apm/error-rules` | Las reglas de agrupación de errores de la organización, en el orden en que se prueban. |
| `POST /api/v1/apm/error-rules` | Crea una regla de agrupación, que se prueba después de las demás. Requiere `apm.error_rules.manage`. |
| `PUT /api/v1/apm/error-rules/{id}` | Reemplaza una regla de agrupación. Requiere `apm.error_rules.manage`. |
| `DELETE /api/v1/apm/error-rules/{id}` | Elimina una regla de agrupación. Requiere `apm.error_rules.manage`. |
| `PUT /api/v1/apm/error-rules/order` | Establece el orden en que se prueban las reglas. Requiere `apm.error_rules.manage`. |
| `GET /api/v1/apm/slos` | Todos los objetivos de nivel de servicio con su estado, su cumplimiento, el presupuesto de errores restante y las tasas de consumo. |
| `GET /api/v1/apm/slos/{id}` | El estado de un objetivo de nivel de servicio y cada día de su ventana. |
| `POST /api/v1/apm/slos` | Crea un objetivo de nivel de servicio. Requiere `apm.slos.manage`. |
| `PUT /api/v1/apm/slos/{id}` | Reemplaza un objetivo de nivel de servicio. Requiere `apm.slos.manage`. |
| `DELETE /api/v1/apm/slos/{id}` | Elimina un objetivo de nivel de servicio. Requiere `apm.slos.delete`. |
| `POST /api/v1/apm/deployments` | Informa un despliegue. Requiere `apm.deploy`. |
| `GET /api/v1/apm/settings` | La configuración de APM de la organización, o los valores predeterminados cuando no se guardó ninguna. |
| `PUT /api/v1/apm/settings` | Reemplaza la configuración de APM de la organización. Requiere `apm.settings.manage`. |

Los parámetros de ruta deben estar codificados para URL. Usa el nombre exacto de `transaction` o el `fingerprint`
de error que devuelve una respuesta de lista.

## Parámetros de consulta comunes

| Parámetro | Tipo | Comportamiento |
|---|---|---|
| `from` | integer | Inicio del intervalo en microsegundos desde la época Unix. El valor predeterminado es 24 horas antes de `to`. |
| `to` | integer | Fin del intervalo en microsegundos desde la época Unix. El valor predeterminado es la hora actual. |
| `namespace` | string | Filtro exacto de espacio de nombres del servicio. |
| `service` | string | Filtro exacto de nombre de servicio. La ruta de detalle del servicio anula este valor. |
| `environment` | string | Filtro exacto de entorno de despliegue. |
| `version` | string | Filtro exacto de versión del servicio. |
| `resolution` | enum | `auto`, `minute` o `hour`. `auto` selecciona la resolución retenida para el intervalo. |
| `sort` | string | Campo de ordenación específico del endpoint. |
| `direction` | enum | `asc` o `desc`. El valor predeterminado es `desc`. |
| `limit` | integer | Tamaño de página de 1 a 200. El valor predeterminado es 50. |
| `cursor` | string | Cursor opaco de una respuesta de lista anterior. |
| `status` | enum | Solo `/errors`: `all` (predeterminado), `unresolved` (grupos abiertos, en investigación y resueltos que se vuelven a ver), `investigating`, `resolved` o `ignored`. |

Los filtros deben ser no vacíos y no superar los 192 bytes. El intervalo no puede exceder el máximo
configurado, cuyo valor predeterminado es 30 días (`[apm].max_query_range_days`).

### Campos de ordenación

| Endpoint | Valores de `sort` admitidos | Valor predeterminado |
|---|---|---|
| `/services` | `requestCount`, `errorRate`, `p95`, `name` | `requestCount` |
| `/transactions` | `requestCount`, `errorRate`, `p95`, `total_time` | `requestCount` |
| `/dependencies` | `requestCount`, `errorRate`, `p95`, `total_time` | `total_time` |
| `/errors` | `occurrenceCount`, `errorRate`, `lastSeen` | `occurrenceCount` |

`/overview` acepta los mismos filtros y la misma resolución, pero no pagina. Los endpoints de detalle, comparación y
salud no devuelven listas paginadas.

## Consultar una vista general

<RequestExample>
```bash cURL
NOW=$(date +%s)000000
curl --get 'http://localhost:5080/api/v1/apm/overview' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode "from=$((NOW-86400000000))" \
  --data-urlencode "to=$NOW" \
  --data-urlencode 'environment=production' \
  --data-urlencode 'resolution=auto'
```
</RequestExample>

La respuesta contiene `red`, `trend`, `serviceHealth`, `services`, `topTransactions`,
`topDependencies`, `topErrors` y `recentVersions`, además de un objeto común `meta`, y:

| Campo | Notas |
|---|---|
| `serviceCount`, `activeServiceCount` | Servicios vistos en el intervalo, y aquellos de ellos que atendieron alguna solicitud. |
| `healthTrend` | Cuántos servicios estaban en cada estado, franja a franja: el intervalo en como máximo 48 franjas, ninguna más corta que un bucket. Un servicio sin solicitudes en una franja cuenta como `noTraffic` en ella. |
| `rankings` | `slowest` (por p95), `mostErrors` (por tasa de errores) y `busiest` (por solicitudes), cinco servicios cada uno. Los dos primeros listan servicios con al menos 20 solicitudes. |
| `deployments` | Versiones vistas por primera vez dentro del intervalo, las más recientes primero, como máximo 20, cada una con su `red` y `verdict` como en [las versiones de un servicio](#leer-las-versiones-de-un-servicio). |
| `environments`, `availableEnvironments` | Servicios y solicitudes por entorno en la vista, y todos los entornos en los que se ejecutan los servicios, independientemente del filtro `environment`. |
| `instrumentation` | Servicios por lenguaje y SDK, y cuántos no comunican `deployment.environment`, `service.version` ni `service.instance.id`. |

## Leer los insights

`GET /api/v1/apm/insights` acepta los parámetros comunes de intervalo y filtro y devuelve `meta` y:

| Campo | Notas |
|---|---|
| `now`, `previous`, `lastWeek` | Los servicios en la vista durante el intervalo, durante el periodo de la misma duración anterior y durante el mismo periodo una semana antes: `requestCount`, `throughput` en solicitudes por segundo, `errorRate`, `p95Time` y `apdex`. Un periodo sin solicitudes no aparece. |
| `insights` | Como máximo 30 hallazgos, los más urgentes primero. |

Cada hallazgo incluye:

| Campo | Notas |
|---|---|
| `kind` | `anomaly`, `regression`, `slow_dependency`, `repeated_call`, `slowQuery`, `hot_endpoint` o `log_errors`. |
| `severity` | `critical`, `warning` o `info` para una sugerencia. |
| `service` | `namespace`, `name` y `environment`. |
| `transaction`, `dependency` | El endpoint de un endpoint muy solicitado; la dependencia de un cuello de botella, una llamada repetida o una sentencia lenta. |
| `metric` | Qué cambió o empeoró: `errorRate`, `p95` o `throughput`. |
| `value` | La cifra actual: una tasa de errores como proporción, un P95 en microsegundos o solicitudes por segundo. Un cuello de botella o un endpoint muy solicitado indica su proporción del tiempo, una llamada repetida sus llamadas por solicitud, una sentencia lenta su P95 en microsegundos y `log_errors` sus líneas de log de nivel de error por minuto, con `metric` `log_errors`. |
| `previous`, `lastWeek` | La misma cifra durante el periodo anterior y durante el mismo periodo una semana antes; para una regresión, la cifra de la versión anterior. |
| `since` | Cuándo comenzó un cambio, o cuándo se vio por primera vez una versión que sufrió una regresión. |
| `version`, `previousVersion` | La versión de una regresión y la versión anterior a ella. |
| `calls`, `p95Time` | Las llamadas o solicitudes en las que se basa una sugerencia, y su P95. |
| `changes` | Los cambios cercanos a `since`, los más cercanos primero: `kind`, `source` (`reported` u `observed`), `service`, `version`, `status`, `at`, `downstream` (`true` para un servicio al que llama el servicio que cambia), `commit` y `description`. |

Los umbrales están en [Insights e investigaciones](/es/apm/insights#what-insights-find).

## Leer métricas RED

Cada resumen incluye un objeto `red` con las cifras de solicitudes, errores y duración del intervalo.

| Campo | Notas |
|---|---|
| `requestCount`, `errorCount`, `errorRate` | Solicitudes, solicitudes fallidas y la proporción de solicitudes fallidas respecto del total, de 0 a 1. |
| `durationSum`, `durationAverage` | La duración total y la duración media en microsegundos. La media es `null` sin solicitudes. |
| `p50Time`, `p90Time`, `p95Time`, `p99Time` | Percentiles de latencia en microsegundos, leídos dentro del bucket del histograma en el que cae la posición. Con la disposición predeterminada, un valor está dentro de aproximadamente el 4 % de la duración exacta. `null` sin solicitudes. |
| `apdex` | Solicitudes dentro del umbral T más la mitad de las solicitudes dentro de 4T, sobre todas las solicitudes, de 0 a 1. T es el `apdexThreshold` del servicio o, de lo contrario, 500 ms; las cifras de la vista general de todos los servicios juntos usan 500 ms. Las solicitudes fallidas nunca cuentan como satisfechas. `null` sin solicitudes. |
| `latencyPartial` | `true` cuando algunos buckets usan una disposición de latencia que no se puede distinguir a partir de ellos. Los buckets de una disposición anterior (`[apm.histogram].schema_version`) se convierten y se cuentan. Los percentiles omiten los buckets que no se pueden leer, mientras que los recuentos, la suma y la media aún los incluyen. |
| `timeoutCount`, `retryCount` | Solicitudes que agotaron el tiempo de espera (un tipo de error de timeout, `DEADLINE_EXCEEDED` de gRPC, HTTP 408 o 504) y solicitudes enviadas de nuevo (`http.request.resend_count` mayor que 0). Ausentes cuando no hay ninguna. |
| `statusCodes` | Respuestas por código de estado, como `http:<code>` (100 a 599) o `grpc:<code>` (0 a 16). Un bucket conserva hasta 24 códigos; los códigos adicionales se cuentan como `http:other` o `grpc:other`. Ausentes cuando no se contó ningún código, como en agregados escritos antes de que se contaran los códigos. |
| `exemplars` | Hasta 8 spans de muestra del intervalo, los más lentos primero. Un span se proyecta antes de que [el muestreo de cola](/es/configuration#captura-de-trazas-y-muestreo-al-final) decida sobre su traza, así que `traceAvailable` suele ser `false`; consulta la traza para saber si se conservó. El agregado sigue siendo válido. |

Los resúmenes de servicio y transacción incluyen `apdexThreshold`, el T con el que se calculó su Apdex.
Un resumen de servicio también incluye `health` y `healthReasons`: cada cifra que supera un umbral, como `metric`
(`errorRate` o `p95`), `level`, `value` y `threshold`. Incluye `sparkline`, el recuento de solicitudes, el recuento de errores y el p95 de cada bucket,
y `currentVersion` con `currentVersionSince`, la versión vista más recientemente y cuándo se
vio por primera vez. El detalle de un servicio o una transacción incluye `latencyDistribution`: los buckets del
histograma que contienen solicitudes, cada uno como `lowerTime`, `upperTime` y `count`, acotados a la
solicitud más rápida y la más lenta.

## Mantén las definiciones de servicio

Una definición registra quién es propietario de un servicio y cuánta importancia tiene. Se indexa por `namespace` y el
nombre del servicio, así que se mantiene en todos los entornos y puede existir antes de que el servicio informe.

```http
PUT /api/v1/apm/service-definitions/checkout?namespace=shop
Content-Type: application/json

{"description": "Takes orders and payments.", "teamId": "<team id>", "ownerId": "<user id>", "tier": "p0", "lifecycle": "production", "repositoryUrl": "https://github.com/acme/checkout", "tags": {"domain": "orders", "pci": ""}, "apdexThreshold": 300000, "aliases": ["order_service", "Order Center"], "dataSources": {"logs": [{"stream": "default", "filter": "service_name = 'order_service'"}], "metrics": [{"selector": "{service=\"checkout\"}"}], "dashboards": ["<dashboard id>"], "links": [{"name": "Runbook", "url": "https://wiki.example.com/checkout"}]}, "archived": false}
```

| Campo | Notas |
|---|---|
| `description` | Hasta 2.000 caracteres. |
| `teamId` | Un equipo de la organización, o `null`. Eliminar el equipo lo borra. |
| `ownerId` | Un miembro de la organización, o `null`. |
| `tier` | Desde `p0`, el más importante, hasta `p5`, o `null`. |
| `lifecycle` | `production`, `staging`, `experimental`, `deprecated` o `null`. |
| `repositoryUrl` | Una URL `http`, `https`, `ssh`, `git` o `git+ssh`, o `user@host:path`, sin espacios, de hasta 2.048 caracteres, o `null`. La contraseña se guarda como `****`, y también la parte de usuario de una dirección http(s). Se muestra cuando el servicio no informa de ningún repositorio. |
| `tags` | Hasta 32 etiquetas como `{ \"key\": \"value\" }`. Una clave tiene de 1 a 64 letras minúsculas, dígitos y `_ . - /`; un valor tiene hasta 128 caracteres sin espacios alrededor, vacío para una clave sola. |
| `apdexThreshold` | El umbral de Apdex T del servicio, mayor que 0 y como máximo 60.000.000 (un minuto), o `null` para 500 ms. |
| `aliases` | Hasta 20 nombres alternativos con los que se conoce el servicio en logs, métricas y otros sistemas; cada uno de 1 a 128 caracteres sin espacios alrededor. No se distingue entre mayúsculas y minúsculas: ningún nombre se repite, nunca el nombre del propio servicio y nunca el nombre ni otro nombre de un servicio diferente de la organización. Si se omite, una definición guardada conserva sus nombres. |
| `dataSources` | Dónde están los datos del servicio: `logs` (`stream` y un `filter` opcional, una expresión SQL booleana de hasta 2.000 caracteres), `metrics` (`selector`, un selector PromQL como `{service=\"checkout\"}`), `dashboards` (IDs de dashboards) y `links` (`name` y una `url` `http` o `https`), hasta 10 de cada uno. Si se omite, una definición guardada conserva sus fuentes. |
| `archived` | `true` mantiene el servicio fuera de la vista predeterminada del catálogo. Si se omite, una definición guardada conserva su estado. |

Una operación de guardado conserva las `keyTransactions` de la definición, que cambian de una en una. La respuesta es la
definición guardada con `namespace`, `name`, `keyTransactions`, `updatedBy` y `updatedAt`.
`DELETE` responde `204`, o `404` cuando el servicio no tiene definición.

### Marca transacciones clave

```http
POST /api/v1/apm/service-definitions/checkout/key-transactions?namespace=shop
Content-Type: application/json

{"transaction": {"name": "POST /orders", "kind": "http"}, "key": true}
```

`key: true` añade el endpoint a `keyTransactions`; `false` lo quita; solicitar lo que ya está
así no cambia nada. Un servicio sin definición recibe una. Un servicio conserva hasta 50
transacciones clave, y la fila de desbordamiento `__other__` no puede ser una. La respuesta es la definición después de
el cambio.

## Consulta cómo se vinculan los servicios con otros datos

`GET /api/v1/apm/correlation` acepta los parámetros comunes de rango y filtro (`from`, `to`,
`namespace`, `environment`, `service`) e indica, para cada servicio en la vista, qué tan bien se vincula con sus
logs, métricas, trazas y cambios. Los servicios se leen durante el rango; los logs y las métricas, durante la última
hora antes de `to`; y los cambios, durante la semana antes de `to`. Solo se leen recuentos y nombres de los
flujos, nunca líneas. Cada informe se conserva durante cinco minutos.

```json
{
  "from": 1792312896695000,
  "to": 1792316496695000,
  "changesSince": 1791711696695000,
  "services": [
    {
      "service": { "namespace": "shop", "name": "checkout", "environment": "prod" },
      "logs": { "state": "reported", "streams": ["default"], "lines": 1200, "traced": 480, "sampled": 10, "matched": 9 },
      "metrics": "missing",
      "resource": { "environment": true, "version": true, "instance": true, "placement": false },
      "changes": { "count": 3, "lastAt": 1792312896695000 },
      "grades": { "traceIds": "partial", "resource": "partial", "metrics": "missing", "changes": "good" }
    }
  ],
  "unmatched": [{ "name": "checkout-svc", "signal": "logs", "streams": ["default"], "lines": 640 }]
}
```

| Campo | Significado |
|---|---|
| `logs` | Las líneas del servicio en flujos de logs con un campo `service.name`, `service_name` o `service`, como máximo ocho flujos, `default` primero. `traced` cuenta las líneas con un `trace_id`, `traceId` o `trace.id`. Se buscan hasta diez IDs de traza recientes del servicio, 200 en total, entre las trazas: `sampled` y `matched`. |
| `metrics` | Si un flujo de métricas contiene una serie con el `service.name` del servicio. |
| `resource` | Si los spans informan un entorno, alguna versión y una instancia, y si una instancia informa `host.name`, `k8s.pod.name`, `k8s.node.name` o `container.id` (`placement`). |
| `changes` | Los despliegues, cambios de configuración y feature flags informados para el servicio desde `changesSince`. |
| `unmatched` | Hasta 20 nombres de servicio en logs o métricas a los que ningún servicio de APM responde, aplicadas las reglas de nombres y los alias, primero los que más líneas tienen. |

Cada grado es `good`, `partial`, `missing` o `unknown`:

| Grado | `good` | `partial` | `missing` |
|---|---|---|---|
| `traceIds` | Al menos el 90 % de las líneas llevan un ID de traza, y al menos el 80 % de las muestreadas se encuentran. | Algunas líneas llevan uno. | Ninguna línea lleva uno, o el servicio no escribió líneas. |
| `resource` | Los cuatro valores de `resource` son verdaderos. | Algunos son verdaderos. | Ninguno lo es. |
| `metrics` | Las métricas llevan el nombre. | | Ninguna lo hace. |
| `changes` | Al menos un cambio. | | Ninguno. |

`unknown` significa que una consulta falló o tardó más de tres segundos; un nombre no encontrado mientras un flujo no se pudo
leer es `unknown`, nunca `missing`. Mole Agent lee el mismo informe con
`get_correlation_quality`.

## Consulta la cobertura de un servicio

`GET /api/v1/apm/services/{service}/coverage` acepta `namespace` y `environment`, ambos obligatorios, y
`to` opcional, el final del rango en la vista en microsegundos (ahora de forma predeterminada). Consulta el día
anterior a `to` y conserva cada respuesta durante cinco minutos.

```json
{
  "from": 1792230096695000,
  "to": 1792316496695000,
  "logs": { "state": "reported", "found": ["default"] },
  "metrics": { "state": "missing" },
  "profiles": { "state": "reported", "found": ["cpu", "alloc_space"] },
  "rum": { "state": "unknown" }
}
```

| Señal | `reported` cuando | `found` |
|---|---|---|
| `logs` | Un flujo de logs con un campo `service.name`, `service_name` o `service` contiene una línea del servicio. Se consultan como máximo ocho flujos, `default` primero. | Los flujos. |
| `metrics` | `count(last_over_time({\"service.name\"=\"<service>\"}[1h]))` en `to` es mayor que cero. | El número de series. |
| `profiles` | El flujo de perfiles contiene un perfil del servicio. | Los tipos de perfil. |
| `rum` | Una acción del navegador incluyó una de las cinco trazas de muestra más recientes del servicio. | La sesión. |

`missing` significa que la consulta no encontró nada. `unknown` significa que la consulta falló o tardó más de tres
segundos. `rum` nunca es `missing`: una muestra de trazas puede mostrar que las sesiones llegan a un servicio, no que
ninguna lo haga.

## Consulta con qué se ejecuta un servicio

`GET /api/v1/apm/services` y `GET /api/v1/apm/services/{service}` dan a cada resumen de servicio un
`profile`, leído de las instancias que informaron en el rango, solo las de `version` cuando el
parámetro está establecido. Cada lista se ordena por cuántas instancias comparten un valor, como máximo cinco, como
`{ \"value\": \"1.8.2\", \"instances\": 4 }`.

| Campo | Notas |
|---|---|
| `instanceCount`, `hostCount` | Instancias y valores distintos de `host.name`. |
| `versions` | Las versiones que ejecutaron las instancias. Un despliegue gradual enumera dos. |
| `languages`, `runtimes`, `frameworks` | `telemetry.sdk.language`; `process.runtime.name` con su versión; el framework que indica la biblioteca de instrumentación de los spans de entrada. |
| `regions`, `clusters`, `k8sNamespaces`, `workloads` | `cloud.region`, `k8s.cluster.name`, `k8s.namespace.name` y `k8s.deployment.name` o `k8s.statefulset.name`. |
| `repositories`, `commits` | `vcs.repository.url.full` o `git.repository_url`, guardados sin credenciales; `vcs.ref.head.revision` o `git.commit.sha`. |
| `entryKinds` | `http`, `rpc`, `messaging`, `span`: los tipos de entrada que atiende el servicio. |

`GET /api/v1/apm/services/{service}/instances` enumera las instancias una por una, primero las vistas
más recientemente, como máximo 500. Acepta `namespace`, `environment` y `version`, `from` y
`to` opcionales; sin un servicio y un entorno, responde `400`. Cada elemento tiene `instanceId` (el
`service.instance.id`; si no, `k8s.pod.name`; si no, `host.name`), `version`, `firstSeenAt`,
`lastSeenAt`, `attributes`, un mapa de los atributos que la instancia informó por última vez, y lo que sirvió
en el rango: `red`, como en los resúmenes con Apdex en el umbral del servicio, y `sparkline`. Pasado el
límite de instancias, el resto se cuenta en un elemento cuyo `instanceId` es `__other__`. Una instancia que
sirvió en el rango antes de que se guardara algo sobre ella aparece en la lista con `attributes` vacío.

## Establecer el estado de un grupo de errores

```http
PUT /api/v1/apm/errors/<fingerprint>/issue
Content-Type: application/json

{"status": "investigating", "assigneeId": "<user id>", "teamId": "<team id>", "lastSeenAt": 1792316496695000}
```

`status` es `open`, `investigating`, `resolved` o `ignored`. `assigneeId` es un miembro de la
organización o `null`, y `teamId` un equipo de la organización o `null`. `lastSeenAt`, opcional, es cuándo se vio el grupo por última vez, en microsegundos. Establecer
`resolved` registra el tiempo como `resolvedAt`.

Los resúmenes de errores llevan el estado como `issue`, o `null` mientras nadie lo ha establecido. `issue.regressed`
es `true` cuando un grupo resuelto volvió a ocurrir después de `resolvedAt`; el filtro `unresolved` conserva
esos grupos. Establecer el estado de una huella que la proyección no conoce responde `404`.

## Mantener objetivos de nivel de servicio

Un objetivo de nivel de servicio (SLO) promete una proporción de solicitudes correctas de un servicio en un entorno, o
de uno de sus endpoints, durante una ventana móvil. Consulta
[Objetivos de nivel de servicio](/es/apm#objetivos-de-nivel-de-servicio) para saber qué significa cada cifra.

```http
POST /api/v1/apm/slos
Content-Type: application/json

{"name": "Checkout availability", "namespace": "shop", "service": "checkout", "environment": "production", "transaction": null, "kind": "availability", "objective": 0.999, "windowDays": 30}
```

| Campo | Notas |
|---|---|
| `name` | Obligatorio, hasta 255 bytes. |
| `description` | Opcional, hasta 2000 bytes. |
| `namespace`, `service`, `environment` | Obligatorios. El servicio tal como lo nombra APM. Un servicio sin `service.namespace` está en el espacio de nombres `default`. |
| `transaction` | Un endpoint, `{ "name": "POST /orders", "kind": "http" }`, o `null` para todo el servicio. |
| `kind` | `availability`: una solicitud es correcta cuando no falló. `latency`: una solicitud es correcta cuando no falló y tardó como máximo `latencyThreshold`. |
| `latencyThreshold` | Obligatorio y positivo para `latency`. Debe ser `null` o estar ausente para `availability`. |
| `objective` | La proporción de solicitudes correctas, mayor que 0 y menor que 1, como `0.999`. |
| `windowDays` | `7`, `28` o `30`. |

`POST` y `PUT` responden el SLO guardado con `id`, `createdBy`, `createdAt`, `updatedBy` y
`updatedAt`. `GET /api/v1/apm/slos` responde cada SLO de la organización como un estado. Pasa
`namespace`, `service` y `environment` juntos para conservar los SLO de un servicio. La ventana termina
en el momento de la llamada, así que los parámetros de rango comunes no aplican.

| Campo de estado | Notas |
|---|---|
| `slo` | El SLO tal como se guardó. |
| `state` | `healthy`, `at_risk`, `breached` o `noData`. |
| `sli` | Solicitudes correctas sobre todas las solicitudes de la ventana, o `null` sin solicitudes. |
| `goodRequests`, `totalRequests` | Los recuentos detrás de `sli`. Un SLO de latencia estima `goodRequests` a partir de los histogramas de latencia, por lo que puede ser fraccionario. |
| `budgetRemaining` | `1 - (1 - sli) / (1 - objective)`, por debajo de cero una vez que se rompe el objetivo, o `null` sin solicitudes. |
| `burnRates` | `oneHour`, `sixHours` y `oneDay`: `(1 - sli) / (1 - objective)` durante la última hora, seis horas y 24 horas, o `null` sin solicitudes. |

`GET /api/v1/apm/slos/{id}` responde `status` y `history`, una entrada por cada día UTC de la ventana
con solicitudes, la más antigua primero. Cada entrada tiene `dayStart` en microsegundos, `sli`, `goodRequests`
y `totalRequests`.

`DELETE` responde `204`. Responde `409` mientras reglas de alerta vigilan el SLO, como sus alertas de
burn rate: elimina esas reglas primero. Las reglas de alerta sobre un SLO son reglas de APM con la métrica
`slo_burn_rate`. Consulta [Crear una regla](/es/api/alerting/create-rule#reglas-de-apm).

## Desambiguar una transacción

Dos tipos de transacción pueden compartir un nombre. Pasa el parámetro opcional `kind` para seleccionar uno:

```http
GET /api/v1/apm/transactions/POST%20%2Fcheckout?kind=http&service=checkout
```

Los valores de tipo admitidos son `http`, `rpc`, `messaging`, `span` y `other`. Un nombre que comparten varios
servicios o tipos responde `400` con `APM transaction identity is ambiguous; provide service,
namespace, environment, and kind`.

## Comparar versiones

Proporciona valores distintos de `baseline` y `candidate`. Añade un filtro `service` para comparar un servicio.

```bash
curl --get 'http://localhost:5080/api/v1/apm/versions/compare' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'service=checkout' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'baseline=2.3.1' \
  --data-urlencode 'candidate=2.4.0'
```

La respuesta contiene los lados `baseline` y `candidate`, cada uno con `version`, `sampleCount` y
`red`, además de un `delta`, un `status`, `regressedTransactions` y `regressedErrors`. Cada lista de
regresiones contiene como máximo 20 entradas.

| Campo | Notas |
|---|---|
| `sufficientData` | `true` solo cuando ambas versiones cumplen el umbral de muestras configurado, que por defecto es 1000 solicitudes por versión (`[apm.version_comparison].min_requests_per_version`). |
| `status` | `insufficient_data`, `regressed`, `improved` o `neutral`. `regressed` cuando la tasa de errores de la candidata subió al menos un punto y hasta al menos 1,5 veces la de la línea base, o su p95 al menos una quinta parte y 50 ms; `improved` cuando uno de ellos bajó en la misma medida y ninguno subió en esa medida; `insufficient_data` cuando `sufficientData` es `false`. |
| `delta` | `requestCountAbsolute` y `requestCountRelative`, `errorRateAbsolute` y `errorRateRelative`, y `p95AbsoluteTime` y `p95Relative`. Un valor relativo es `null` cuando la línea base es cero o falta. |

Un `candidate` o `baseline` faltante, o dos versiones idénticas, responden `400`.

## Leer las versiones de un servicio

`GET /api/v1/apm/services/{service}` responde `versions`, las versiones vistas en el rango. Cada una lleva
`red`, lo que sirvió en el rango, y `verdict`, cómo le fue frente a la versión del mismo servicio
vista primero antes que ella, juzgada como lo hace [una comparación](#comparar-versiones):

| Campo | Notas |
|---|---|
| `previous` | La versión contra la que se compara. |
| `status` | `regressed`, `improved`, `neutral` o `insufficient_data`. |
| `worse` | Qué empeoró cuando `status` es `regressed`: `errorRate`, `latency` o ambos. |
| `delta` | Como en una comparación, con la versión anterior como línea base. |

La primera versión vista no tiene `verdict`. Un filtro de versión en la solicitud no acota las
cifras: cada versión se lee de todo el servicio.

## Leer dónde ocurrieron los errores

`GET /api/v1/apm/errors` responde un `breakdown` junto a la página, sobre cada grupo que conserva el filtro `status`
(no solo los de la página), y `GET /api/v1/apm/errors/{fingerprint}` responde el `breakdown` del
grupo. Contiene `versions`, `environments` y `languages`, cada uno una lista de `value` y `count`,
las ocurrencias, de mayor a menor. Un valor está vacío cuando los spans no lo informaron; después de los primeros
siete valores, el resto se cuenta junto como `__other__`. El lenguaje es el
`telemetry.sdk.language` del servicio.

## Mantener reglas de agrupación de errores

Una regla agrupa los errores de forma distinta a su tipo, frame y endpoint cuando se ven. Las reglas se
prueban en orden de `position` y se aplica la primera que coincide.

```http
POST /api/v1/apm/error-rules
Content-Type: application/json

{"name": "Upstream timeouts", "serviceNamespace": "shop", "serviceName": "checkout",
 "errorType": "*Timeout*", "message": "", "frame": "", "endpoint": "", "action": "merge", "enabled": true}
```

| Campo | Notas |
|---|---|
| `name` | Hasta 128 caracteres. El grupo fusionado se nombra con él. |
| `serviceNamespace`, `serviceName` | El servicio al que aplica la regla. Un `serviceName` vacío significa todos los servicios; un espacio de nombres necesita un nombre. |
| `errorType`, `message`, `frame`, `endpoint` | Patrones para el tipo de error, el mensaje de la excepción, el primer frame de la aplicación y el endpoint, cada uno de hasta 256 caracteres. Un patrón coincide con todo el texto, sin distinguir mayúsculas y minúsculas, con `*` para cualquier texto. Un patrón vacío coincide con todo; se debe establecer al menos uno. |
| `action` | `merge`: los errores coincidentes de un servicio pasan a ser un solo grupo. `ignore`: no forman grupo, y sus solicitudes siguen contando como fallidas. |
| `enabled` | Una regla desactivada se conserva pero no se prueba. Por defecto es `true`. |

La respuesta es la regla con su `id`, `position`, `updatedBy` y `updatedAt`. Una organización
conserva como máximo 100 reglas. `PUT /api/v1/apm/error-rules/order` recibe `{"ids": [...]}`, coloca esas reglas
primero en ese orden y las demás después, y responde las reglas en su nuevo orden.

Un cambio se aplica al instante en el nodo que lo guarda y en un plazo de 30 segundos en los demás, a los
errores vistos a partir de entonces; los grupos ya creados permanecen como están.

## Consultar el mapa de servicios

`GET /api/v1/apm/map` toma el intervalo común y los parámetros `environment` y `namespace`, y devuelve
`nodes`, `edges`, `namespaces` (de los servicios del entorno), `environments` (todos) y
`truncated` (`true` cuando solo se conservan los 400 nodos con más actividad).

| Campo | Notas |
|---|---|
| `nodes[].id` | `service:<name>`, `topic:<name>` o `<category>:<target>` para los destinos a los que llaman los servicios. |
| `nodes[].kind` | `service`, `external` o `topic`. Un nodo externo incluye su `category`. |
| `nodes[].red` | `requestCount`, `errorCount`, `errorRate` y `p95Time`: lo que atendió un servicio, o lo que se solicitó a un nodo externo o a un tema. Un servicio también incluye `health`, `namespace` y `environments`. |
| `edges[].kind` | `call`, `publish` (a un tema) o `consume` (de un tema). |
| `change` | En una arista o un nodo, frente al periodo anterior de la misma duración: `new` cuando antes no estaba, `gone` cuando ya no está. Ausente cuando no había nada antes. |

Las llamadas entre servicios provienen del grafo de servicios, con el P95 de su minuto más lento; el resto
proviene de los buckets de APM. `GET /api/v1/apm/map/edge` toma los ids de nodo `source` y `target`, además de los mismos
parámetros, y devuelve `kind`, `red`, `trend`, `operations` (`name`, `kind`, `red`), `everyCaller`
(`true` cuando las operaciones son los endpoints del servicio llamado para todos los llamadores) y `errors`, los
grupos de errores del servicio llamado.

## Consultar el radio de impacto de un servicio

`GET /api/v1/apm/blast-radius` toma `service`, que es obligatorio, y los parámetros de intervalo común y
`environment`. Lee todo el mapa del entorno, independientemente del espacio de nombres, y
devuelve `meta`, `service` (el nodo propio del servicio, ausente cuando el mapa no lo tiene en ningún punto del intervalo),
`upstream` (lo que lo llama, hasta tres saltos) y `downstream` (lo que llama o a lo que publica, hasta dos
saltos). Cada lado contiene como máximo 30 nodos, primero los que no están en buen estado; las llamadas desaparecidas respecto al periodo anterior se
omiten.

| Campo | Notas |
|---|---|
| `id`, `kind`, `name`, `namespace`, `category` | El nodo tal como lo nombra [el mapa de servicios](#consultar-el-mapa-de-servicios). |
| `hops` | Llamadas entre el nodo y el servicio: `1` para un llamador o un destinatario directo. |
| `via` | El nodo a través del cual se alcanza, un salto más cerca del servicio. |
| `health` | El estado de salud propio de un servicio. Para aquello a lo que se llama, el estado que determinan sus llamadas fallidas. |
| `red`, `call` | Lo que sirvió o se le solicitó, y las llamadas entre este y `via`. |

## Notificar despliegues

`POST /api/v1/apm/deployments` recibe el despliegue como JSON y responde `201` con él, y añade su `id`,
`createdBy` y `createdAt`. Los campos, sus límites y los ejemplos de CI están en
[Despliegues](/es/apm/deployments#reporta-despliegues-desde-ci). El servicio y el entorno
se nombran tal como los interpretan las reglas de nomenclatura, el mapeo de entornos y los alias de la organización. Una
dirección del repositorio se conserva con su contraseña enmascarada. Un cambio de configuración o un feature flag establece
`kind` en `configuration` o `feature_flag` y no necesita `version`.

Un cambio de escala o de la infraestructura establece `kind` en `scaling` o `infrastructure`. Los cambios notificados
se enumeran con [`GET /api/v1/changes`](/es/api/changes).

## Mantener la configuración de APM

`GET /api/v1/apm/settings` devuelve la configuración de la organización; `PUT` la reemplaza por completo y
devuelve lo que se conservó:

```json
{
  "health": {
    "errorRateWarning": 0.02,
    "errorRateCritical": 0.1,
    "p95WarningTime": 500000,
    "p95CriticalTime": 2000000
  },
  "apdexThreshold": 500000,
  "longTaskTime": 1000000,
  "namingRules": [{ "pattern": "^(checkout)-[a-z0-9]{5}$", "replacement": "$1" }],
  "environmentMap": [{ "from": "Production", "to": "production" }],
  "aliases": [{ "aliasNamespace": "shop", "alias": "checkout-v1", "namespace": "shop", "service": "checkout" }],
  "metadataRules": { "teamFromTier": "p1", "ownerFromTier": "p0", "repositoryFromTier": null }
}
```

Un campo omitido toma su valor predeterminado. Se recortan los espacios de los nombres, y un espacio de nombres de alias vacío es `default`. Los
límites y lo que hace cada ajuste están en [Configuración de APM](/es/apm/settings). Un guardado se aplica de inmediato
en el nodo que lo guarda y en un plazo de 30 segundos en los demás.

Los límites de cardinalidad de la plataforma se consultan y se reemplazan con `GET` y `PUT
/api/v1/settings/apm_limits`, que requieren `sys.settings.limits.manage`. El cuerpo incluye
`servicesPerOrgHour`, `transactionsPerServiceHour`, `dependenciesPerServiceHour`,
`operationsPerDependencyHour`, `errorGroupsPerServiceHour`, `versionsPerServiceHour` y
`instancesPerServiceHour`, cada uno de 1 a 100000.

## Consultar los metadatos de la respuesta

Todos los endpoints devuelven un objeto `meta` común:

```json
{
  "range": {
    "from": 1785801600000000,
    "to": 1785888000000000
  },
  "resolution": "minute",
  "projectionStartedAt": 1785798000000000,
  "lastCompleteBucketAt": 1785887940000000,
  "dataQuality": {
    "partial": false,
    "gaps": [],
    "overflowDimensions": []
  },
  "activationBoundary": false
}
```

- Trata `activationBoundary: true` como cobertura incompleta antes de `projectionStartedAt`.
- Trata `dataQuality.partial: true` como datos incompletos, no como un cero completo.
- Inspecciona `gaps` para detectar fallos de cola, repositorio, vaciado, datos tardíos, cardinalidad o apagado.
- Usa `lastCompleteBucketAt` para determinar si los datos recientes aún se están finalizando.
- Inspecciona `overflowDimensions` antes de confiar en un desglose de alta cardinalidad.

## Errores

| Código de estado | Causa |
|---|---|
| `400` | Un parámetro no es válido: un `sort` no admitido (`unsupported APM sort field`), un `limit` fuera del rango de 1 a 200, un filtro vacío o demasiado grande (`invalid APM service filter`), un intervalo más largo que el máximo (`APM query range exceeds configured maximum`), un final anterior al inicio (`APM range end precedes start`), una `direction` o `resolution` desconocida, un SLO que no supera las comprobaciones anteriores (`SLO objective must be between 0 and 1, exclusive`) o un filtro de lista de SLO al que le falta alguno de `namespace`, `service` y `environment`. |
| `403` | Al token le falta el permiso de la llamada. |
| `404` | La huella de error, la transacción, el servicio o el SLO no existe en el intervalo. |
| `409` | Las reglas de alerta siguen vigilando el SLO que se está eliminando. |
