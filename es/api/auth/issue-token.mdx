```http
POST /api/v1/me/api-tokens
```

Emite un token personal con el formato `mspat-<36>` que actúa en nombre de la cuenta con la que se inició sesión. El token en texto plano solo aparece en la respuesta, así que guárdalo de inmediato. Haz la llamada desde una sesión iniciada, nunca con otro token. La llamada requiere `personal_tokens.manage`.

**Cuerpo**

| Campo | Tipo | Obligatorio | Notas |
|---|---|---|---|
| `name` | cadena | Sí | Nombre visible, de 1 a 255 caracteres. |
| `policyId` | cadena | No | ID de una [política de permisos](/es/identity/roles#políticas-de-permisos) que aplica al token, como `builtin:data_intake`. Debes tener todos los permisos de la política. |
| `permissions` | cadena[] | No | Permisos de la organización asignados al token. Debes tener todos esos permisos. |
| `expiresInDays` | entero | No | Vigencia en días, de 1 a 1825. Omite el campo para que el token no caduque. |

Indica `policyId` o `permissions`, pero no ambos. Si omites ambos campos, el token puede realizar todas las acciones que permiten tus permisos. El token nunca puede realizar más acciones que las que permiten tus permisos en el momento de la solicitud: si pierdes un permiso, tus tokens también lo pierden.

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -X POST http://localhost:5080/api/v1/me/api-tokens \
  -H 'content-type: application/json' \
  -d '{
    "name": "grafana-readonly",
    "permissions": ["streams.read", "streams.query", "dashboards.read"],
    "expiresInDays": 90
  }'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KE5hOsEc3lMC9qr9RWnPn0pqWF",
  "prefix": "k7m2q9xv4b",
  "name": "grafana-readonly",
  "tokenKind": "personal",
  "userId": "<user-id>",
  "policyId": null,
  "permissions": ["dashboards.read", "streams.query", "streams.read"],
  "applicationId": null,
  "serviceAccountId": null,
  "expiresAt": 1798000000000000,
  "lastUsedAt": null,
  "revoked": false,
  "createdAt": 1790000000000000,
  "token": "mspat-k7m2q9xv4b<secret>"
}
```
</ResponseExample>

`ms-cookies.txt` guarda la sesión que abrió [Iniciar sesión](/es/api/auth/login). `GET /api/v1/me/api-tokens/scopes` enumera las políticas y los permisos de la organización a los que puedes limitar un token. Envía el token en el encabezado `Authorization`: `Authorization: Bearer mspat-…`.

## Para una cuenta de servicio

```http
POST /api/v1/auth/tokens
```

Emite un token que actúa en nombre de una cuenta de servicio. El cuerpo es el mismo, con el campo adicional `serviceAccountId`, y la llamada requiere `api_tokens.issue`. A diferencia de un token personal, puedes emitir este token con un token de API. Si omites `policyId` y `permissions`, el token queda limitado a los permisos del rol de la cuenta que tengas en el momento de la emisión. Si el rol obtiene un permiso más adelante, el token no lo adquiere. Si el rol pierde un permiso, el token deja de poder usarlo de inmediato.

```bash
curl -X POST http://localhost:5080/api/v1/auth/tokens \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "collector-production",
    "serviceAccountId": "<service-account-id>",
    "policyId": "builtin:data_intake",
    "expiresInDays": 365
  }'
```

**Errores**

| Estado | Causa |
|---|---|
| `400` | `name` está vacío, la solicitud incluye tanto `policyId` como `permissions`, la lista está vacía, el permiso o la política no se reconoce, o la cuenta de servicio está deshabilitada. |
| `403` | El alcance incluye un permiso que no tienes, la solicitud de un token personal usa un token de API o falta el permiso requerido (`personal_tokens.manage` o `api_tokens.issue`). |
| `404` | El alcance del sistema no tiene tokens de API o la cuenta de servicio no existe. |
