```http
POST /api/v1/orgs/{id}/select
```

Cambia la sesión activa del navegador a otra organización a la que pertenece la cuenta. La respuesta reescribe las cookies de sesión para esa organización y la sesión conserva su hora de caducidad. Consulta [Iniciar sesión](/es/api/auth/login) para obtener información sobre las cookies. Solo una sesión puede cambiar de organización: una solicitud con un token de API recibe `403`. Los administradores de la plataforma pueden seleccionar la organización protegida `_sys`, que requieren las llamadas que afectan a toda la plataforma, como [Rotar las claves de firma de JWT](/es/api/auth/rotate-jwt). Una sesión en `_sys` termina como máximo una hora después del cambio.

**Parámetros de ruta**

| Parámetro | Tipo | Notas |
|---|---|---|
| `id` | cadena | ID de la organización que devuelve `GET /api/v1/orgs`. |

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -c ms-cookies.txt \
  -X POST http://localhost:5080/api/v1/orgs/<organization-id>/select
```
</RequestExample>

<ResponseExample>
```json 200
{
  "userId": "<user-id>",
  "orgId": "<organization-id>",
  "orgName": "default",
  "displayRole": "Owner",
  "roles": [
    { "id": "<role-id>", "key": "owner", "name": "Owner", "builtin": true }
  ],
  "system": false
}
```
</ResponseExample>

Las pestañas del navegador comparten las cookies, así que todas las pestañas abiertas cambian a la organización seleccionada.

## Requisitos de inicio de sesión

Si el inicio de sesión actual no cumple todos los [requisitos de inicio de sesión](/es/identity/sso#requisitos-de-inicio-de-sesión) de la organización, la respuesta sigue siendo `200`, no incluye nuevas cookies e indica qué falta:

| Respuesta | Significado |
|---|---|
| `{"mfa": {"organization_name", "methods"}}` | Verifica un segundo factor en ese momento: vuelve a enviar la solicitud con `{"proof": {…}}` en el cuerpo. La prueba incluye `method` (`totp` o `recovery_code`) y `code`, o `method` con el valor `passkey` y los campos `ceremony` y `credential` de `POST /api/v1/me/mfa/passkey-proof`. |
| `{"mfaSetup": {"organization_name"}}` | La cuenta no tiene un segundo factor. Configura primero un segundo factor en `/api/v1/me/mfa` o `/api/v1/me/passkeys`. |
| `{"sso": {"organization_name", "providers"}}` | Solo se admite el inicio de sesión único de la organización. `providers` enumera `id`, `name`, `kind` y `platform`. |
