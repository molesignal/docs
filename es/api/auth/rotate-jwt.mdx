Ambas rutas requieren una sesión con alcance de sistema y el permiso `sys.signing_keys.rotate`. Si usas una sesión con alcance de organización o un token de API, la ruta devuelve `403`. Cambia la organización de la sesión a `_sys` con [Seleccionar un espacio de trabajo](/es/api/auth/select-organization).

## Listar claves de firma

```http
GET /api/v1/auth/jwt/secrets
```

Devuelve los metadatos de las claves de firma. Nunca devuelve los bytes de las claves.

<ResponseExample>
```json 200
[
  {
    "id": "3JtcPZ3AZJFyvBvSkJUia0N7wqo",
    "isPrimary": true,
    "createdAt": 1790000000000000,
    "retiredAt": null
  }
]
```
</ResponseExample>

## Rotar

```http
POST /api/v1/auth/jwt/rotate
```

Crea una nueva clave principal y retira la anterior. El sistema firma los tokens nuevos con la nueva clave. Los tokens que llevan la firma de una clave retirada siguen siendo válidos durante 24 horas después de su retiro.

No hace falta reiniciar ningún nodo. Cada nodo acepta desde la primera solicitud las sesiones que llevan la firma de la nueva clave y empieza a firmar con ella en unos 10 segundos. Los nodos dejan de verificar firmas con la clave retirada 5 minutos después de que se cumplan las 24 horas, para compensar ese retraso y las diferencias entre los relojes de los nodos.

<ResponseExample>
```json 200
{
  "newKid": "<new-key-id>",
  "retiredKid": "<previous-key-id>",
  "activeCount": 2
}
```
</ResponseExample>

`activeCount` indica cuántas claves pueden verificar tokens en ese momento. Si un despliegue fija la clave de firma con `MS_AUTH_JWT_SECRET_OVERRIDE`, sigue su propia política de rotación. Consulta [Seguridad y arquitectura multiinquilino](/es/security#claves-de-firma-de-jwt).
