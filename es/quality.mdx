Cada respuesta de Mole Agent recibe una puntuación. Las reglas la puntúan de inmediato, sin usar un modelo: comprueban si las herramientas funcionaron, si la respuesta cita evidencia, si las consultas tienen una sintaxis válida, si la respuesta tiene el formato requerido y qué valoración recibió. Los evaluadores que configures usan un modelo para puntuar una muestra de las respuestas según los criterios que definas. Las respuestas con puntuación baja, las que reciben la valoración **No útil** y las seleccionadas al azar quedan pendientes de revisión. Las que se aprueban pasan al conjunto de pruebas de regresión. Antes de usar una instrucción de la organización como predeterminada, una comprobación vuelve a responder algunas de estas preguntas con la versión nueva y con la actual. Un evaluador puntúa las respuestas de ambas versiones.

Las puntuaciones van de 0 a 100. La pestaña **Calidad** las muestra y Mole Agent también registra cada puntuación en el flujo `_agent_score_traces`.

## Antes de empezar

- La pestaña **Calidad** requiere `agent.quality.read`, un permiso que los roles de propietario y administrador tienen de forma predeterminada. Estos roles ya pueden leer todos los chats de equipo. Los chats personales solo cuentan en los totales y su contenido no se puede consultar en esta pestaña.
- Cada evaluador usa uno de los proveedores de modelos de la organización. Consulta [Mole Agent](/es/agent#configura-un-proveedor-de-modelos). Las reglas puntúan todas las respuestas aunque no haya un evaluador.

## Qué se puntúa

| Fuente | Qué incluye |
|---|---|
| **Chats de equipo** | Respuestas en chats de equipo. |
| **Chats personales** | Respuestas en chats personales. Solo las puntúan las reglas y solo cuentan en los totales. |
| **Automatizaciones** | La respuesta de cada ejecución de una automatización de la organización o del equipo. Consulta [Automatizaciones](/es/automations). Las ejecuciones de una automatización personal cuentan como chats personales. |
| **Análisis de causa raíz de incidentes** | Los análisis de causa raíz que se generan de forma automática o a petición, y cualquier análisis de causa raíz que reciba una valoración. |

Mole Agent puntúa cada respuesta al generarla y vuelve a puntuarla cuando se añade o retira una valoración.

## Reglas

Las reglas examinan la respuesta y los datos de su ejecución. Cada regla asigna una puntuación de 0 a 100. La puntuación por reglas de una respuesta es el promedio de las puntuaciones de las reglas aplicables.

| Regla | Puntuación | Se aplica a |
|---|---|---|
| **Llamadas a herramientas** | La proporción de llamadas a herramientas que no fallaron. | Respuestas que hicieron llamadas a herramientas. |
| **Evidencia** | 0 si no cita evidencia, 50 si cita evidencia que ninguna llamada exitosa a una herramienta respalda, 75 si hay una evidencia respaldada y 100 si hay dos o más. | Respuestas con el formato solicitado que hicieron llamadas a herramientas. |
| **Consultas** | La proporción de consultas SQL y PromQL con sintaxis válida en las llamadas a herramientas. | Respuestas cuyas herramientas ejecutaron consultas. |
| **Formato** | 100 si la respuesta tiene el formato solicitado. | Todas las respuestas de chat excepto las consultas generadas. |
| **Finalización** | 100 si la respuesta se completó, 50 si la ejecución de una automatización requirió intervención humana y 0 si falló, se detuvo o quedó vacía. | Todas las respuestas. |
| **Valoración** | 100 para **Útil** y 0 para **No útil**. En un análisis de causa raíz, basta una valoración **No útil**. | Respuestas que recibieron una valoración. |

## Evaluadores

Un evaluador asigna a cada respuesta una nota del 1 al 5 según sus criterios y justifica la nota en una o dos frases. La nota se convierte en una puntuación de 0, 25, 50, 75 o 100. El evaluador lee la pregunta, los resultados de las herramientas y la respuesta. Para un análisis de causa raíz, lee los hechos del incidente y el análisis.

- Cada evaluador puntúa el porcentaje de respuestas nuevas que configures. La selección se hace por respuesta, por lo que al repetirla se obtienen las mismas respuestas.
- El evaluador siempre puntúa las respuestas valoradas como **No útil**, salvo si ya las puntuó.
- Si un evaluador asigna a una respuesta una puntuación inferior al umbral de revisión, vuelve a puntuarla y usa el promedio de ambas puntuaciones.
- Los evaluadores nunca puntúan los chats personales.
- Cada evaluador escribe sus justificaciones en el idioma de la interfaz que estaba activo la última vez que se guardó su configuración.
- Las llamadas de los evaluadores a los modelos cuentan para el presupuesto diario de tokens de la organización y aparecen como **Puntuación de calidad** en el uso por fuente. Mientras el presupuesto esté agotado, los evaluadores omiten las respuestas nuevas.

Cada evaluador parte de la instrucción integrada **Evaluador de respuestas** (propósito `evaluation`). La organización puede reemplazarla en **Configuración → Gestión de instrucciones**. La instrucción no cambia el formato fijo en el que el evaluador devuelve la puntuación.

Si algún evaluador puntuó una respuesta, la puntuación de la respuesta es el promedio de las puntuaciones de sus evaluadores. De lo contrario, se usa la puntuación por reglas.

## La pestaña Calidad

Abre **Mole Agent → Calidad**. En **Vista general** y **Respuestas**, consulta los últimos 7, 30 o 90 días para una fuente o para todas.

| Vista | Qué muestra |
|---|---|
| **Vista general** | Las respuestas puntuadas, las puntuaciones medias de las reglas y de los evaluadores, las respuestas marcadas como útiles o poco útiles y cuántas están pendientes de revisión. Debajo: la puntuación por día, cada regla y las respuestas por fuente, versión del prompt, habilidad y modelo. |
| **Respuestas** | Las respuestas puntuadas, de la más reciente a la más antigua. Usa **Solo puntuaciones bajas** para mostrar solo las que no alcanzan el umbral de revisión. Abre una fila para ver la pregunta y la respuesta completas, los hallazgos de cada regla, la puntuación y el motivo de cada evaluador y la revisión de la respuesta. **Abrir el chat** o **Abrir el incidente** lleva al lugar donde se escribió la respuesta. |
| **Revisiones** | Las respuestas pendientes de revisión, aceptadas o rechazadas. |
| **Brechas de datos** | Los datos que faltan según las llamadas a herramientas de las respuestas. Consulta [Brechas de datos](#brechas-de-datos). |
| **Simulacros** | Los incidentes resueltos que Mole Agent vuelve a investigar y evalúa según su causa raíz conocida. Consulta [Simulacros](#simulacros). |
| **Evaluadores** | Los evaluadores y la configuración. |

### Revisar respuestas

Una respuesta queda pendiente de revisión cuando:

| Causa | Cuándo |
|---|---|
| **Puntuación baja** | La puntuación de un evaluador sigue por debajo del umbral de revisión tras la segunda evaluación. Si ningún evaluador puntúa la respuesta, se usa la puntuación de las reglas. |
| **Marcada como poco útil** | La respuesta recibió la valoración **No útil** de quien hizo la pregunta. |
| **Seleccionada al azar** | La respuesta entra en la muestra que determina el porcentaje de **Revisión aleatoria** para comprobar si las puntuaciones son fiables. |

Cada respuesta pasa a revisión una sola vez. Ábrela, escribe en **Nota** qué está mal y qué debería acertar una buena respuesta, y selecciona:

- **Aceptar**: la respuesta es incorrecta. Pasa al conjunto de pruebas de regresión, y el evaluador recibe la nota cuando una comprobación del prompt vuelve a responder la pregunta.
- **Rechazar**: la respuesta es correcta.

### Evaluadores y configuración

En **Evaluadores**, selecciona **Nuevo evaluador** para abrir el formulario:

| Campo | Descripción |
|---|---|
| **Nombre** | Debe ser único en la organización. |
| **Criterios de evaluación** | Describe qué debe hacer una buena respuesta y qué la penaliza, en un máximo de 4000 caracteres. El formulario incluye criterios iniciales. |
| **Respuestas** | Chats de equipo, automatizaciones y análisis de causa raíz de incidentes. |
| **Muestra** | Porcentaje de respuestas nuevas que puntúa el evaluador, de 0 a 100. |
| **Proveedor del modelo** y **Modelo** | Si dejas estos campos vacíos, el evaluador usa el primer proveedor disponible de la organización y su modelo predeterminado. |
| **Temperatura** | De 0 a 1. El valor 0 mantiene estables las puntuaciones. |
| **Activada** | Si desactivas esta opción, el evaluador no puntúa ninguna respuesta. |

Cada organización puede tener hasta 10 evaluadores. Si eliminas un evaluador, las puntuaciones que otorgó se conservan.

Opciones de configuración debajo de los evaluadores:

| Opción | Valor predeterminado | Descripción |
|---|---|---|
| **Umbral de revisión** | 60 | Las respuestas con una puntuación inferior quedan pendientes de revisión. |
| **Revisión aleatoria** | 0 | Porcentaje de las demás respuestas que se seleccionan al azar para revisión. |
| **Antes de establecer un prompt como predeterminado** | Comprobar y volver a preguntar si el resultado empeora | Consulta la información más abajo. |

### Brechas de datos

Al puntuar una respuesta con reglas, Mole Agent también examina sus llamadas a herramientas para detectar qué faltaba en los datos disponibles. Esto no cambia la puntuación: una brecha indica un problema en los datos, no en la respuesta. **Brechas de datos** resume las brechas de los últimos 7, 30 o 90 días.

| Tipo | Cuándo se detecta | Cómo corregirla |
|---|---|---|
| **Dónde están los datos** | Hubo 3 consultas o más al mismo flujo y la mayoría falló o no devolvió resultados, o hubo 3 consultas o más sobre la estructura (esquemas y listas de flujos, nombres y etiquetas de métricas). | Documenta dónde están los datos de cada servicio y cómo filtrarlos: en las fuentes de datos del catálogo de servicios o en el archivo `MOLE.md` de la base de conocimiento. |
| **Un solo nombre por servicio** | Un servicio tenía datos en las métricas o en APM, pero una consulta de registros o trazas con el mismo nombre no devolvió resultados y ninguna otra consulta del flujo encontró el servicio. | Usa el mismo nombre para el servicio en todas las señales (`service.name`) o registra los demás nombres como alias en el catálogo de servicios. |
| **Resumen de datos** | Hubo 2 extracciones o más de registros o series sin procesar, cada una con muchas filas, sin usar **Analizar patrones de registros** ni **Analizar tendencia de una métrica**. | Comprueba que los conjuntos de herramientas de los perfiles de agente de la organización incluyan esas herramientas. |

La vista agrupa por flujo y servicio las brechas recurrentes e indica cuántas respuestas detectaron cada una y cuándo apareció por última vez. Selecciona una respuesta debajo de una brecha para ver sus puntuaciones. Los chats personales solo cuentan en los totales: la vista no muestra qué consultaron.

### Simulacros

En un simulacro, Mole Agent vuelve a investigar un incidente resuelto como si estuviera ocurriendo y el sistema evalúa el resultado según la causa raíz establecida después del incidente. Vuelve a ejecutar todos los simulacros tras cambiar el modelo, un prompt o las herramientas para comprobar si mejoraron las investigaciones.

**Nuevo simulacro** muestra los incidentes resueltos en los últimos 180 días cuyo informe post mortem indica una causa raíz (en la sección **Causa raíz**). El simulacro usa esa causa raíz como referencia, a menos que escribas otra. En **Otro incidente**, ingresa un ID de incidente y escribe la causa raíz. Cada incidente admite un solo simulacro y cada organización puede conservar hasta 100.

Una ejecución de un simulacro:

- Usa los permisos de quien la inicia, que debe tener acceso de lectura al incidente. Funciona sin supervisión, en modo de solo lectura y durante un máximo de 10 minutos.
- Usa los datos disponibles cuando se activó el incidente (el resumen, la gravedad, los servicios, las etiquetas y la consulta que lo activó) y la guía de investigación de la regla de alerta. Examina el periodo desde una hora antes del inicio del incidente hasta media hora después de ese inicio.
- No puede acceder a los hallazgos ni a las acciones posteriores: notas, cronología, análisis de causa raíz, informe post mortem, tickets, aprobaciones e incidentes similares.
- Abre un chat que no aparece en la lista de chats. Desde la ejecución, selecciona **Abrir la investigación** para ver el chat en modo de solo lectura.

Cuando termina la investigación, un modelo compara la causa raíz identificada con la de referencia. La puntúa del 1 al 5, muestra el resultado en una escala de 0 a 100 y explica el motivo en el idioma de la interfaz de quien inició la ejecución. Usa el modelo del primer evaluador activado o, si no hay ninguno, el del primer proveedor de modelos de la organización. Las llamadas al modelo cuentan para el presupuesto diario de tokens como **Puntuación de calidad**. Si una ejecución falla, se detiene o no genera una respuesta, no recibe puntuación e indica el motivo.

**Ejecutar** inicia un simulacro; **Volver a ejecutar todos** inicia todos los que no tengan una ejecución en curso, hasta 50 a la vez. Para crear, ejecutar y eliminar simulacros, necesitas el permiso `agent.quality.manage`.

## Verifica un prompt antes de establecerlo como predeterminado

Al seleccionar **Establecer como predeterminado** en un prompt de la organización para chats (**Instrucción del sistema**) o para análisis de causa raíz de incidentes (**Análisis de causa raíz**), la configuración de la organización determina qué sucede:

| Configuración | Cuando no se ha verificado el prompt o la comprobación indica que es peor |
|---|---|
| **Verificar y pedir confirmación si el resultado es peor** | El cuadro de diálogo ofrece las opciones **Ejecutar la comprobación** y **Establecer como predeterminado de todos modos**. |
| **Verificar y bloquear si el resultado es peor** | Solo se puede establecer como predeterminado un prompt si la comprobación indica que no es peor. |
| **No verificar** | El prompt se establece de inmediato como predeterminado. |

La comprobación toma hasta 8 respuestas: primero, las del conjunto de pruebas de regresión y, después, las que el primer evaluador que puntúa estas respuestas haya puntuado más recientemente. El mismo modelo responde de nuevo a cada pregunta dos veces: una con el prompt predeterminado actual y otra con la nueva versión. No vuelve a ejecutar las herramientas: recibe la pregunta y los resultados que las herramientas obtuvieron en su momento. Para un análisis de causa raíz, el modelo redacta el análisis con cada versión a partir de los hechos del incidente. Luego, el evaluador puntúa cada par. El resultado para la nueva versión es **Peor** si su puntuación media está más de 5 puntos por debajo de la del prompt predeterminado actual y **Mejor** si está más de 5 puntos por encima. En los demás casos, el resultado es **No es peor**. Si se pueden comparar menos de 3 respuestas, la comprobación no arroja un resultado concluyente ni impide establecer el prompt como predeterminado.

El cuadro de diálogo muestra el progreso y luego el resultado de cada respuesta. Cada comprobación compara una versión del prompt con un prompt predeterminado. Si editas el prompt o estableces otro como predeterminado, vuelve a ejecutar la comprobación. Las llamadas al modelo durante la comprobación cuentan como **Puntuación de calidad**.

Los prompts para otros fines se establecen como predeterminados sin comprobación. Tampoco se ejecuta una comprobación al editar el prompt que ya es el predeterminado. Para comprobar un cambio, guárdalo como un prompt nuevo y establece ese prompt como predeterminado.

## Puntuaciones en un flujo

Cada puntuación también ocupa una fila en el flujo interno `_agent_score_traces`, que puedes consultar en **Registros**:

| Campo | Descripción |
|---|---|
| `target_kind`, `target_id` | `chat_answer` con el ID del mensaje o `incident_rca` con el ID del incidente. |
| `source` | `personal_chat`, `team_chat`, `automation` o `incident_rca`. |
| `scorer`, `scorer_kind` | `rules` o el ID del evaluador con `evaluator`. |
| `score`, `samples` | Puntuación media de 0 a 1 y cantidad de puntuaciones que se usaron para calcularla. |
| `tool_success`, `evidence`, `query_validity`, `answer_format`, `completion`, `feedback` | Puntuaciones de las reglas, de 0 a 1, cuando corresponden. |
| `reason`, `evaluator_model` | Justificación y modelo del evaluador. |
| `chat_id`, `team_id`, `automation_id`, `user_id`, `prompt_template_id`, `prompt_version`, `prompt_key`, `provider_id`, `model`, `skill`, `skill_version` | Origen de la respuesta y recursos que se usaron para generarla. |

Para recibir avisos si baja la calidad, crea una [regla de alerta de anomalías](/es/alerting) para el flujo, por ejemplo, sobre la puntuación media de los evaluadores:

```sql
SELECT avg(score) AS value FROM "_agent_score_traces" WHERE scorer_kind = 'evaluator'
```
