Una sesión es de tipo `user`, `synthetics` o `ci_test`. Una [comprobación sintética](/es/synthetics) de navegador que abre una página con el [SDK para navegador](/es/rum/browser-sdk) 0.3.0 o posterior crea una sesión de tipo `synthetics` sin necesidad de configurar nada. Sus eventos identifican la comprobación, la ejecución y la ubicación en `synthetics.test_id`, `synthetics.result_id` (el `task_id` del resultado de la ejecución) y `synthetics.location_id`.

## Cómo afecta a las cifras

Las cifras de una aplicación reflejan la actividad de usuarios reales, por lo que el sistema excluye las sesiones generadas por pruebas de:

- las páginas de resumen, rendimiento, frustración, errores, análisis, mapas de calor e indicadores de funciones, y los paneles integrados;
- las [reglas de alerta sobre cifras de RUM](/es/rum/alerts);
- las filas del explorador y las herramientas de RUM de Mole Agent.

Los errores de estas sesiones no abren [problemas](/es/rum/errors), así que una comprobación fallida no puede contar como un problema nuevo. Si una página excluye sesiones, muestra el enlace **N sesiones de prueba excluidas** para consultarlas.

El sistema tampoco aplica muestreo a estas sesiones: la [retención](/es/rum/sampling) de la aplicación las conserva completas. Si un filtro de la aplicación incluye `session.type`, la aplicación aplica a las ejecuciones de prueba los mismos filtros y proporciones que a cualquier otra sesión. El SDK conserva estas sesiones independientemente del valor de `sessionSampleRate`.

## Cómo encontrarlas

- Desde una ejecución: haz clic en **Abrir la sesión de RUM de esta ejecución** en el intento correspondiente al resultado de una comprobación de navegador.
- Desde la sesión: consulta el tipo en la página de la sesión y sigue el enlace a los resultados de la comprobación.
- En el explorador: las consultas que incluyen `session.type`, `synthetics.*` o `ci_test.*` respetan esos criterios. Por ejemplo, `session.type = 'synthetics'` encuentra las sesiones sintéticas. También puedes buscar una sesión por su `session.id`. Sin ninguno de estos criterios, el explorador muestra la actividad de usuarios reales. La lista de valores de `session.type` incluye todos los tipos de sesión.
- Con la API, los filtros de `search`, `aggregate`, `facets` y `histogram` siguen las mismas reglas.

## Pruebas de una aplicación

Define la misma variable global antes de que se ejecute cualquier script de la página. En Playwright:

```ts
await page.addInitScript((id) => {
  window.__MOLESIGNAL_TEST_CONTEXT__ = { type: 'ci_test', test_execution_id: id };
}, process.env.GITHUB_RUN_ID);
```

El SDK asigna a `window.__MOLESIGNAL_RUM_SESSION__` el ID de la sesión que registró. La comprobación lee ese ID para enlazar con la sesión y sale de la página al final del recorrido para que el SDK envíe los datos pendientes.

<Note>
La página debe usar una versión del SDK para navegador posterior a la 0.2.0 para que la sesión indique qué la generó. La política de tráfico saliente de la comprobación se aplica a las solicitudes del SDK como a cualquier otra solicitud. Si la política no permite el acceso a MoleSignal, la comprobación falla.
</Note>
