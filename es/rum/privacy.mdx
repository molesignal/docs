Aplica controles de privacidad en el navegador para que los valores confidenciales nunca lleguen a la red. Empieza con el
modo enmascarado predeterminado y permite contenido adicional solo después de revisar la grabación.

## Configuración predeterminada para proteger la privacidad

```ts
init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  defaultPrivacyLevel: 'mask',
  trackUrlQueryString: false,
});
```

Con esta configuración:

- el SDK elimina las cadenas de consulta y los fragmentos de las URL;
- el SDK oculta de forma recursiva claves como `password`, `secret`, `token`, `authorization`, `cookie` y `api_key`, así como los campos de tarjetas de crédito,
  en los datos de usuario, cuenta y contexto;
- los nombres de las acciones siguen el formato `Click <structural selector>` y los selectores no incluyen ID, ID de prueba ni clases. El texto de un
  elemento solo da nombre a una acción con `defaultPrivacyLevel: 'allow'`;
- el SDK enmascara el texto del DOM durante la reproducción de sesiones;
- el SDK enmascara todos los valores de los campos de entrada y de los elementos `contenteditable`, al igual que con `mask-user-input`.

<Warning>
  El ocultamiento por nombre de campo es una medida de respaldo, no un sistema de clasificación de datos. No agregues credenciales,
  datos de pago, datos de salud ni información personal innecesaria a los objetos de usuario o de contexto personalizado.
</Warning>

## Bloquea o enmascara contenido del DOM

El SDK reconoce los atributos de privacidad sin necesidad de código de grabación específico de la aplicación:

```html
<section data-molesignal-block>
  <!-- The entire subtree becomes a placeholder. -->
</section>

<span data-molesignal-mask>Account holder name</span>

<div data-molesignal-ignore>
  <!-- Mutations and events for this element are ignored. -->
</div>
```

Reemplaza los selectores predeterminados cuando sea necesario:

```ts
sessionReplay: {
  blockSelector: '.payment-form, [data-private-panel]',
  maskTextSelector: '.customer-name, [data-molesignal-mask]',
  ignoreSelector: '.animation-layer, [data-molesignal-ignore]',
},
```

Bloquea los secretos y los widgets grandes con datos confidenciales, enmascara el texto cuya disposición visual resulte útil e
ignora los elementos que generan ruido y no aportan valor a la investigación.

## Muestra la página y oculta los datos introducidos

`defaultPrivacyLevel: 'mask-user-input'` registra el texto de la página y enmascara los datos introducidos: los valores de los campos de entrada y
de los elementos `contenteditable`. Usa este nivel cuando la página muestre el mismo texto a todo el público. El texto que coincide con el `maskTextSelector` configurado sigue enmascarado.

Con `mask`, puedes mostrar una región si sabes que su texto no contiene datos confidenciales:

```html
<nav data-molesignal-allow>Pricing · Docs · Sign in</nav>
```

`data-molesignal-allow` muestra el texto del elemento y de su contenido. Dentro del elemento se mantienen los bloqueos, las exclusiones y las máscaras de
`maskTextSelector`, y los campos de entrada y los elementos `contenteditable` siguen enmascarados.

## Permite con precaución el texto visible de la página

Configura `defaultPrivacyLevel: 'allow'` solo después de marcar todas las regiones confidenciales. Este nivel también muestra los datos introducidos, salvo las contraseñas, las direcciones de correo
electrónico, los números de teléfono, los campos cuyo atributo `autocomplete` indica que contienen datos de una tarjeta o un código de un solo uso y los campos dentro de
`data-molesignal-mask`. El texto que coincide con el `maskTextSelector` configurado sigue enmascarado.

```ts
defaultPrivacyLevel: 'allow',
sessionReplay: {
  blockSelector: '[data-molesignal-block], .payment-details',
  maskTextSelector: '[data-molesignal-mask], .customer-identity',
},
```

## Controla las URL y la recopilación de datos de red

Mantén `trackUrlQueryString: false` a menos que la aplicación garantice que las cadenas de consulta nunca contienen
identificadores ni secretos. Excluye las rutas o los endpoints de red confidenciales antes de recopilar datos:

```ts
excludedUrls: [
  '/account/security',
  /^https:\/\/api\.example\.com\/private\//,
  (url) => url.includes('/token-exchange'),
],
```

`allowedTracingUrls` controla qué orígenes pueden aportar contexto de trazas. Esta opción no habilita la captura del cuerpo de las solicitudes
ni de las respuestas. El SDK registra los tiempos y los metadatos de URL depurados.

## Elimina el texto confidencial al recibir los eventos

El SDK es la primera línea de defensa y el servidor es la segunda. La aplicación elimina los tipos de texto confidencial seleccionados
de cada evento antes de almacenarlo, independientemente del SDK o cliente que lo haya enviado. Abre la aplicación en
**RUM → Aplicaciones** y activa o desactiva los tipos de **Datos confidenciales**. En las aplicaciones nuevas, todos están activos.

| Tipo | Qué se elimina | Reemplazo |
|---|---|---|
| **Tokens, claves y contraseñas** | Tokens Bearer y Basic, JWT, claves de servicios en la nube y de código (claves de acceso de AWS y tokens de GitHub, GitLab, Slack, Stripe, OpenAI, Google y npm), claves privadas, el valor que sigue a `password=`, `secret:`, `api_key=`, `authorization:` y términos similares, y los valores de los encabezados `Authorization`, `Cookie`, `Set-Cookie`, `Proxy-Authorization`, `X-API-Key`, `X-Auth-Token` y `X-CSRF-Token`. | `[secret]` |
| **Direcciones de correo electrónico** | Direcciones como `jane@example.com`. | `[email]` |
| **Números de teléfono** | Números internacionales que empiezan con `+` y tienen entre 8 y 15 dígitos, números de teléfonos móviles de China de 11 dígitos y números de Norteamérica como `(415) 555-2671`. | `[phone]` |
| **Números de tarjetas de pago** | Números de entre 13 y 19 dígitos, con espacios o guiones entre grupos, que empiezan con un prefijo de una red de tarjetas y superan la validación del dígito de control. | `[card]` |
| **Números de identificación personal** | Números de identificación de residentes de China con un carácter de control válido y números de Seguro Social de Estados Unidos. | `[id]` |
| **Parámetros confidenciales de URL** | Los valores de los parámetros de consulta y de fragmento cuyos nombres son `code`, `key`, `sig`, `sid`, `otp`, `ticket`, `email`, `phone` o similares, o contienen `token`, `secret`, `password`, `auth`, `signature`, `api_key`, `credential`, `jwt` o `session`. El nombre de usuario y la contraseña que preceden al host. El nombre del parámetro se conserva. | `[redacted]` |

El servidor elimina el texto confidencial de las direcciones donde ocurrió el evento y de las que provino (`view.url`, `view.referrer`, `resource.url` y la dirección de un
error), del mensaje y la traza de pila del error y de sus causas, del nombre de la vista y del elemento en el que se hizo clic, de la operación, la carga útil
y las variables GraphQL de una solicitud, de los encabezados de solicitud y respuesta, y del objeto `context`. El servidor también depura las direcciones que aparecen dentro de un texto
y conserva la posición que indica la traza de pila después de la dirección (`:10:5`). Los objetos `user` y `account` contienen los datos que la aplicación
decidió enviar sobre una persona y no se modifican.

El servidor elimina el texto antes de convertir el evento en filas. Así, los datos derivados se calculan a partir de los valores que se conservan:
`view.url_path` y `view.url_path_group` de una dirección que contenía un correo electrónico, y la [incidencia](/es/rum/errors) a la que pertenece un error. Los errores que
solo se diferencian por el correo electrónico o el número del mensaje se agrupan en una sola incidencia.

<Warning>
  Los tipos se basan en patrones y validaciones, no en una clasificación de datos. El servidor elimina como teléfono cualquier número que tenga ese formato, como un número de pedido de 11 dígitos
  que empieza con `13`, pero no reconoce un nombre ni una dirección en texto libre. Desactiva un tipo si elimina datos
  necesarios para una investigación y evita incluir valores confidenciales en los eventos desde el SDK.
</Warning>

Los cambios solo se aplican a los eventos que llegan después. Los datos almacenados anteriormente no cambian. El servidor no depura los segmentos de reproducción de sesiones:
el SDK enmascara su texto según el nivel de privacidad indicado anteriormente.

## Revisa la configuración antes de pasar a producción

<Steps>
  <Step title="Graba una sesión de prueba controlada">
    Prueba los flujos de inicio de sesión, compra, perfil, búsqueda y errores con datos de prueba que no sean de producción.
  </Step>
  <Step title="Revisa todas las superficies de captura de eventos">
    Revisa los metadatos de sesión, los nombres de las acciones, las URL, las trazas de pila de los errores, el contexto personalizado y la reproducción del DOM.
  </Step>
  <Step title="Agrega selectores y exclusiones">
    Bloquea los subárboles del DOM que contengan datos confidenciales y excluye las rutas de las que no necesites recopilar datos.
  </Step>
  <Step title="Repite la revisión después de cambiar la interfaz">
    Trata los selectores de privacidad como parte de la configuración de producción y comprueba su comportamiento después de modificar el marcado.
  </Step>
</Steps>
