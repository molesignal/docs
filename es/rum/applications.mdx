Una aplicación es el sitio web o la app que envía eventos de RUM. Créala antes de que cualquier SDK envíe datos:
el token de cliente está vinculado a una sola aplicación y MoleSignal rechaza los eventos de aplicaciones que
no existen.

Abre **RUM → Aplicaciones** para ver la lista de aplicaciones del espacio de trabajo. Para crear, modificar o eliminar
una aplicación, se requiere `rum.applications.manage`, ya que cada aplicación incluye su token de cliente.
Para consultar la lista, se requiere `rum.applications.read`.

## Crear una aplicación

<Steps>
  <Step title="Abre el formulario">
    Haz clic en **Crear aplicación**. Si el espacio de trabajo no tiene aplicaciones, el mismo botón aparece en el
    explorador.
  </Step>
  <Step title="Asigna un nombre a la aplicación">
    Ingresa un **Nombre** único de hasta 128 caracteres, como `Checkout web`, y elige la **Plataforma**:
    Navegador, Android, iOS, Flutter, React Native u Otra. La plataforma solo determina el fragmento de
    configuración que muestra la aplicación: el campo `source` de cada evento indica qué lo envió.
  </Step>
  <Step title="Define el identificador">
    El **Identificador** es el valor que se usa como `applicationId` al configurar los SDK. Deja el campo en blanco para
    generarlo a partir del nombre (`checkout-web`) o ingresa un identificador de hasta 64 caracteres que use `A-Z`, `a-z`, `0-9`,
    `.`, `_`, `:` y `-`. No puedes cambiar el identificador después de crear la aplicación.
  </Step>
  <Step title="Haz clic en Crear">
    La aplicación se abre y muestra el token de cliente.
  </Step>
</Steps>

Al crear una aplicación, MoleSignal también crea los siete flujos de RUM del espacio de trabajo si aún no existen.

## Token de cliente

Abre una aplicación para ver su **Token de cliente**. El token tiene el formato `mspat-<36>`, no vence
y solo concede `rum.write` para esta aplicación. El token aparece enmascarado. Selecciona **Mostrar token** o **Copiar el token**.

<Warning>
  El token se incluye en el código del navegador y de las apps móviles, donde los usuarios pueden leerlo. Usa solo este token en el código del cliente y nunca
  uses un token de propietario, de administrador o personal. Al eliminar la aplicación, se revoca el token.
</Warning>

También puedes obtener el mismo token desde la [API](/es/api/auth/rum-token). En la aplicación, **Abrir la guía de configuración** abre
la guía de **Fuente de datos** de la plataforma con la aplicación ya seleccionada. La guía muestra el endpoint, el token,
el fragmento de configuración del SDK con el identificador y una comprobación de que llegan los datos. React Native y Otra no tienen guía: envía los
[eventos](/es/rum/events) directamente con el token.

## Recopilación

La configuración de la aplicación determina qué datos se conservan con cada evento. Modifícala en la aplicación y haz clic en **Guardar**.

| Configuración | Valor predeterminado | Efecto |
|---|---|---|
| **Guardar la dirección IP** | Activado | Guarda la dirección IP del cliente en `network.client.ip` tal como la determinó el servidor. Si hay un proxy, configura primero la [detección de la IP del cliente](/es/rum#ip-del-cliente-detrás-de-un-proxy). |
| **Conservar la ubicación** | Activado | Guarda el país, la región y la ciudad que se obtienen a partir de la dirección IP. El servidor consulta la ubicación incluso si no conserva la dirección y solo guarda el resultado de la consulta. |
| **Privacidad predeterminada** | Enmascarar el texto y los campos de entrada | Nivel de privacidad que sugiere el fragmento de configuración para la reproducción de sesiones: **Enmascarar el texto y los campos de entrada**, **Enmascarar lo que escriben los usuarios** o **Grabar todo lo que se muestra**. |

Los cambios solo se aplican a los eventos que llegan después. Los datos ya almacenados no cambian.

## Configuración remota del SDK

Si inicias un SDK con `remoteConfiguration: true`, el SDK lee estas opciones al arrancar. Así puedes cambiarlas sin publicar una nueva versión de la página. Las opciones que queden en
**Según la configuración de la página** usan los valores que la página pasó a `init`.

| Configuración | Opción del SDK |
|---|---|
| **Tasa de muestreo de sesiones (%)** | `sessionSampleRate` |
| **Tasa de muestreo de reproducciones de sesiones (%)** | `sessionReplaySampleRate` |
| **Nivel de privacidad** | `defaultPrivacyLevel` |
| **Recopilar clics** | `trackUserInteractions` |
| **Reenviar mensajes de la consola** | `forwardConsoleLogs` |

El SDK consulta las opciones en `GET /api/v1/rum/config` con su token de cliente. Espera como máximo 1,5 segundos y, si no recibe respuesta, se inicia con los valores de la página.

## Segmentos

En **Segmentos** puedes definir hasta 20 grupos de sesiones para filtrar las [páginas de análisis](/es/rum/analytics#segmentos). Cada segmento admite hasta cinco
condiciones y la sesión debe cumplirlas todas. Una condición puede evaluar el país, el continente o la ciudad, el navegador, el sistema operativo o el tipo
de dispositivo, el ID o el correo electrónico del usuario, el ID de la cuenta, el servicio, la versión o la plataforma, o una propiedad del usuario que la aplicación haya definido
con `setUser` (`usr.extra.plan`). La condición puede exigir que el dato coincida con uno o más valores o con ninguno. Los cambios se reflejan de inmediato en las consultas y se aplican también a las
sesiones ya almacenadas. Las propiedades del usuario solo están disponibles en las sesiones que comenzaron después de implementar esta función.

## Datos confidenciales y sesiones conservadas

**Datos confidenciales** tiene un interruptor para cada tipo de texto que el servidor elimina antes de guardar un evento: tokens, claves y
contraseñas; direcciones de correo electrónico; números de teléfono; números de tarjetas de pago; números de identificación; y valores de parámetros confidenciales de URL.
Todos los interruptores están activados de forma predeterminada. Consulta [Privacidad de RUM](/es/rum/privacy#elimina-el-texto-confidencial-al-recibir-los-eventos) para saber qué elimina cada uno.

**Sesiones conservadas** determina qué sesiones guarda la aplicación. **Porcentaje de sesiones conservadas (%)** fija qué proporción de las sesiones que
recibe la aplicación se guarda. Usa un número entero entre `0` y `100`. Cada sesión se conserva o se descarta completa, incluida su reproducción.
**Añadir un filtro** permite asignar un porcentaje propio a las sesiones que coinciden con ciertos criterios (entorno, versión, país, navegador, entre otros). El primer
filtro que coincide con una sesión determina su porcentaje. Para las demás sesiones se aplica **Porcentaje de las demás sesiones que se conservan (%)**. **Conservar todos
los errores** guarda los errores incluso si se descartan las sesiones en las que ocurrieron. Las páginas que muestran totales extrapolan los datos conservados al total de
sesiones y muestran la etiqueta **Estimado**. Consulta [Muestreo de datos de RUM](/es/rum/sampling#conserva-un-porcentaje-de-las-sesiones-en-el-servidor).

## Problemas

La sección **Problemas** define cuántos [problemas](/es/rum/errors#problemas-nuevos-por-hora) nuevos puede abrir la aplicación por hora.

| Configuración | Valor predeterminado | Efecto |
|---|---|---|
| **Problemas nuevos por hora** | 100 | De 1 a 10 000. Al alcanzar el límite, la aplicación agrupa los errores que aún no pertenecen a ningún problema en un solo problema llamado **Otros errores** hasta que termine la hora. Los cambios se aplican en un máximo de 30 segundos. |

## Eliminar una aplicación

Haz clic en **Eliminar aplicación** y confirma. El token de cliente deja de funcionar de inmediato y MoleSignal rechaza los datos de los SDK que lo usan.
Los eventos que ya envió la aplicación permanecen en los flujos hasta que vence su período de retención. Mientras tanto, puedes buscarlos
en el explorador.
