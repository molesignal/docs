El SDK del navegador escribe los registros con la sesión y la vista en las que se generaron. Así, cada registro lleva a su reproducción y cada sesión muestra lo que escribió la página. El SDK no envía nada hasta que se escribe un registro o se activa la captura de la consola. Los registros requieren la versión 0.3.0 o posterior del [SDK del navegador](/es/rum/browser-sdk).

```ts
import { molesignalRum } from '@molesignal/browser-rum';

molesignalRum.logger.info('cart opened', { items: 3 });

const payments = molesignalRum.createLogger({ name: 'payments', level: 'warn', context: { provider: 'stripe' } });
payments.error('payment declined', { code: 402 }, error);
```

Un registrador omite los mensajes por debajo de su nivel y admite `debug`, `info`, `warn` y `error`. Si recibe un error como tercer argumento, el registro conserva el tipo de error y su traza de pila.

Para reenviar también lo que la página escribe en la consola:

```ts
init({ /* … */ forwardConsoleLogs: ['warn', 'error'] }); // or 'all'
```

El SDK reenvía la salida de la consola sin modificarla. Mantén esta opción desactivada si la consola puede contener datos personales o revisa qué [elimina la aplicación durante la ingesta](/es/rum/privacy#elimina-el-texto-confidencial-al-recibir-los-eventos), un proceso que también abarca el texto y la traza de pila de los registros.

## Dónde están los registros

- En la [página de la sesión](/es/rum/explorer#abre-una-sesión), la pestaña **Registros** debajo de la reproducción muestra los registros en orden y resalta el que corresponde al momento actual. Haz clic en una fila para saltar a ese momento en la reproducción.
- En el [explorador](/es/rum/explorer), **Registros** es un tipo de fila.
- En **Registros**, el flujo `rum_logs` es un flujo de registros normal, con `level` y `message`. El histograma por nivel y las demás funciones operan igual que con cualquier otro registro.

Si la aplicación [no conserva una sesión](/es/rum/sampling), tampoco conserva sus registros. El recuento de la vista no incluye los registros.

## Errores del SDK

Cuando falla el propio SDK (por ejemplo, si el servidor rechaza un evento o `beforeSend` lanza una excepción), el SDK escribe un registro con el registrador `molesignal-rum` y el origen `sdk`. Registra cada fallo una sola vez y solo unos pocos por carga de página. No registra los fallos de envío al servidor, ya que el registro tampoco llegaría. Desactiva estos registros con `trackSdkErrors: false`. El SDK llama a `onError` en ambos casos.

## Campos

| Columna | Descripción |
|---|---|
| `level` | `debug`, `info`, `warn` o `error`. |
| `message` | El texto del registro. |
| `log.id` | El identificador del registro. |
| `log.logger` | El nombre del registrador: `console` para la consola y `molesignal-rum` para el propio SDK. |
| `log.origin` | `logger`, `console`, `report` o `sdk`. |
| `log.error_type`, `log.stack` | El tipo y la traza de pila del error que describe el registro. |
