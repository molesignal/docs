MoleSignal separa las credenciales del proveedor de los destinatarios y del enrutamiento. Configura un conector una sola vez,
vincula identidades o destinos de respaldo y, después, elige cuándo debe usar esas
rutas el motor de notificaciones.

| Recurso | Propósito |
|---|---|
| **Conectores** | Almacenan las credenciales del proveedor y la configuración de transporte de la organización. |
| **Enrutamiento por usuario** | Vincula identidades de proveedores y ordena los destinos de entrega personales. |
| **Políticas** | Identifican los eventos que cumplen las condiciones, determinan los destinatarios, seleccionan las plantillas y controlan el escalamiento. |
| **Plantillas** | Contienen cuerpos de mensaje reutilizables por canal: una plantilla general sirve para todos los canales, y los SMS, las llamadas y otros canales pueden tener su propia plantilla. |
| **Rutas de respaldo** | Definen el orden en que se usan los destinos del equipo y de la organización si falla la entrega personal. |
| **Registro de entregas** | Permite revisar los intentos, la latencia, los errores, los reintentos, las confirmaciones y el escalamiento. |

| Llamadas de AWS (`aws_voice`) | Región, autenticación, identidad de origen, voz de Polly opcional, cantidad de lecturas, tiempo de espera | Número en formato E.164 |
| SMS de AWS (`aws_sms`) | Región, autenticación, identidad de origen opcional, tiempo de espera | Número en formato E.164 |

| PagerDuty (`pagerduty`) | Clave de integración, región del servicio, tiempo de espera | Cualquier destino; los eventos se envían a la integración asociada a la clave |
| Amazon SNS (`aws_sns`) | Región, autenticación, ARN del tema, mensaje, tiempo de espera | Cualquier destino; los mensajes se envían al tema |
| Webhook (`webhook`) | URL predeterminada, método HTTP, encabezados, tiempo de espera | Usuario, dirección, grupo o URL de webhook específica del destino |

El tiempo de espera de cada conector debe estar entre 1 y 60 segundos. Usa URLs absolutas con el esquema `http` o `https`
en todos los casos.

El selector agrupa los tipos de conectores por canal: **Mensajería instantánea**, **Llamadas telefónicas**, **SMS**
(que incluye WhatsApp), **Correo electrónico** e **Integraciones**, que incluye PagerDuty, Amazon SNS y
Webhook.

El conector muestra la dirección del proveedor en un campo de solo lectura que puedes copiar: los conectores de Alibaba Cloud, Tencent Cloud y
AWS (incluido Amazon SNS) obtienen la URL base de la API de la región elegida; PagerDuty, de la región del
servicio elegida; y las aplicaciones de Lark y Slack, de la plataforma elegida. El bot de Teams obtiene la URL del servicio
de la nube elegida. Los demás conectores usan la dirección fija del proveedor, como la dirección de conexión persistente del bot inteligente de
WeCom o la dirección de inicio de sesión de Microsoft para el correo electrónico. Huawei Cloud es la excepción:
la dirección depende de la aplicación y ninguna API la muestra, así que cópiala desde la consola. Antes de guardar, probar o enviar
directamente, MoleSignal comprueba que la dirección figure en la lista del proveedor y rechaza cualquier otra que se indique
mediante la API. Así, las credenciales nunca se envían a otra dirección. Una vez que guardas el conector, no puedes cambiar su tipo.

Ingresa el servidor de un bot de Mattermost o de Matrix del mismo modo que una URL de webhook. MoleSignal se conecta
solo a las direcciones a las que se resuelve el nombre de host, rechaza las direcciones de metadatos de la nube y no sigue
redirecciones.

## Crea y prueba un conector

Para ver los conectores, necesitas `notify.connectors.read`. Para crear, editar, probar, habilitar, deshabilitar o
eliminar conectores, necesitas `notify.connectors.manage`.

<Steps>
  <Step title="Abre la administración de notificaciones">
    Ve a **Configuración → Notificaciones → Conectores**.
  </Step>
  <Step title="Elige un proveedor">
    Haz clic en **Nuevo conector**, ingresa un nombre único y selecciona el tipo de conector. El tipo de conector
    no se puede cambiar después de crearlo.
  </Step>
  <Step title="Configura el proveedor">
    Agrega las credenciales y la configuración de transporte que se describen a continuación. Mantén habilitada la opción **Permitir que este conector
    envíe notificaciones**, salvo que estés preparando el conector para usarlo más adelante.
  </Step>
  <Step title="Guarda el conector">
    Haz clic en **Guardar conector**. MoleSignal cifra toda la configuración en reposo. Las respuestas de la API
    reemplazan los valores confidenciales por `***`.
  </Step>
  <Step title="Envía una notificación de prueba">
    Edita el conector guardado, selecciona un tipo de destino compatible, ingresa un destino real y haz clic en
    **Probar conexión**. El estado del conector cambia a **Conectado** o **Error** según el resultado de la
    última prueba.
  </Step>
</Steps>

<Note>
  Guarda el conector nuevo antes de probarlo. Al editar un conector, no modifiques el valor enmascarado `***`
  para conservar el secreto almacenado.
</Note>

## Configura cada proveedor

### Correo electrónico por SMTP

Ingresa el servidor SMTP, el puerto y una **Dirección del remitente** válida. Indica cómo inicia sesión MoleSignal en
**Autenticación**:

| Autenticación | Qué ingresar |
|---|---|
| **Nombre de usuario y contraseña** | **Nombre de usuario** si el servidor lo requiere y **Contraseña**. Si el proveedor de correo lo solicita, usa la contraseña de aplicación o el código de autorización que proporcione. |
| **Microsoft 365 (OAuth 2.0)** | **ID del inquilino**, **ID de cliente** y **Secreto de cliente** de una aplicación registrada en Microsoft Entra ID. En **Nombre de usuario**, ingresa el buzón de envío. Consulta [Microsoft 365](#microsoft-365). |
| **Google Workspace (OAuth 2.0)** | **Clave de la cuenta de servicio (JSON)** de una cuenta de servicio con delegación en todo el dominio. En **Nombre de usuario**, ingresa el buzón de envío. Consulta [Google Workspace](#google-workspace). |

Los dos métodos de OAuth 2.0 inician sesión con un token de acceso (SASL XOAUTH2) en lugar de una contraseña. Así, siguen
funcionando cuando el proveedor desactiva el inicio de sesión con contraseña. Microsoft desactiva la autenticación básica para SMTP
AUTH de forma predeterminada para los inquilinos existentes de Exchange Online a finales de 2026. MoleSignal conserva el token hasta un
minuto antes de que expire. Si falla un envío, vuelve a iniciar sesión.

Elige uno de estos modos de TLS:

| Modo de TLS | Cuándo usarlo |
|---|---|
| `none` | La conexión SMTP no usa TLS. Evita este modo en redes que no sean de confianza. |
| `starttls` | El servidor actualiza la conexión con STARTTLS, normalmente en el puerto `587`. |
| `tls` | La conexión comienza con TLS, normalmente en el puerto `465`. |

Usa `fixed_address` o `direct_user` como destino de prueba e ingresa un buzón válido, como
`oncall@example.com`.

#### Microsoft 365

MoleSignal inicia sesión como aplicación registrada en Microsoft Entra ID y envía correo desde un buzón. Solo admite la
nube global de Microsoft: la **URL de inicio de sesión** es siempre
`https://login.microsoftonline.com`.

<Steps>
  <Step title="Registra una aplicación">
    En Microsoft Entra ID, registra una aplicación. En **Permisos de API**, agrega el permiso de aplicación `SMTP.SendAsApp` de **Office 365 Exchange
    Online** y otorga el consentimiento de administrador. En **Certificados y
    secretos**, crea un secreto de cliente. El ID del inquilino y el ID de cliente aparecen en la página **Información general**
    de la aplicación.
  </Step>
  <Step title="Registra la aplicación en Exchange Online">
    Un administrador de Exchange se conecta a Exchange Online PowerShell (`Connect-ExchangeOnline`) y
    registra la entidad de servicio de la aplicación. `<object ID>` es el ID de objeto de la aplicación que aparece en
    **Aplicaciones empresariales** en Microsoft Entra ID, no el ID de objeto del registro de la aplicación:

    ```powershell
    New-ServicePrincipal -AppId <app ID> -ObjectId <object ID>
    ```
  </Step>
  <Step title="Concede acceso al buzón">
    Concede a la entidad de servicio acceso al buzón de envío:

    ```powershell
    Add-MailboxPermission -Identity <mailbox> -User <service principal> -AccessRights FullAccess
    ```
  </Step>
  <Step title="Habilita SMTP AUTH para el buzón">
    Habilita SMTP AUTH para el buzón. Por ejemplo:

    ```powershell
    Set-CASMailbox -Identity <mailbox> -SmtpClientAuthenticationDisabled $false
    ```
  </Step>
  <Step title="Completa la configuración del conector">
    Ingresa el servidor `smtp.office365.com`, el puerto `587` y el modo de TLS `starttls`. Elige
    **Microsoft 365 (OAuth 2.0)**, ingresa el ID del inquilino, el ID de cliente y el secreto de cliente, e indica el
    buzón como **Nombre de usuario** y como **Dirección del remitente**.
  </Step>
</Steps>

#### Google Workspace

MoleSignal inicia sesión con una cuenta de servicio que actúa en nombre de un buzón del dominio mediante la delegación en todo
el dominio.

<Steps>
  <Step title="Crea una cuenta de servicio">
    En un proyecto de Google Cloud, crea una cuenta de servicio y una clave JSON para la cuenta. Anota el ID
    de cliente numérico de la cuenta de servicio que aparece en su página de detalles.
  </Step>
  <Step title="Delega el alcance de Gmail">
    En la consola de administración de Google, un superadministrador abre **Seguridad → Control de acceso y de datos →
    Controles de APIs → Delegación en todo el dominio**, agrega el ID de cliente y autoriza el alcance
    `https://mail.google.com/`. La delegación puede tardar hasta 24 horas en surtir efecto.
  </Step>
  <Step title="Completa la configuración del conector">
    Ingresa el servidor `smtp.gmail.com` con el puerto `587` y el modo de TLS `starttls`, o el puerto
    `465` y `tls`. Elige **Google Workspace (OAuth 2.0)**, pega la clave en **Clave de la cuenta de servicio
    (JSON)** e ingresa el buzón desde el que envía la cuenta, que debe pertenecer a un usuario del dominio, como **Nombre de usuario** y
    como **Dirección del remitente**.
  </Step>
</Steps>

El `token_uri` de la clave debe ser el endpoint de tokens de Google, igual que para una [aplicación de Google Chat](#aplicación-de-google-chat).

### Aplicación de Slack

Crea una aplicación de Slack con un token de bot que permita llamar a `chat.postMessage`. Agrega el bot a cada canal
que deba recibir notificaciones. Ingresa lo siguiente:

- **Token del bot** — el token del bot, que normalmente empieza por `xoxb-`;
- **Token a nivel de aplicación** — opcional. Usa un token que empiece por `xapp-` y tenga el alcance `connections:write`. Permite a Mole Agent responder en Slack mediante Socket Mode. Consulta [Mole Agent en la mensajería instantánea](/es/im);
- **Plataforma** — Slack o GovSlack para el gobierno de EE. UU. Con GovSlack, la API y la autorización de las páginas
  de estado usan `slack-gov.com`;
- **ID de cliente** y **Secreto de cliente** — de la sección **Información básica** de la aplicación de Slack, para las páginas de
  estado cuyos visitantes agregan la página a sus propios canales de Slack. Consulta
  [Páginas de estado](/es/status-pages#slack);
- **Tiempo de espera** — un valor de 1 a 60 segundos.

El conector necesita el token del bot, el ID y el secreto de cliente, o los tres. Para enviar notificaciones, necesita el
token del bot. MoleSignal guarda el secreto de cliente y el token del bot cifrados con el conector y nunca
los devuelve.

Usa un ID de miembro de Slack para `direct_user` o un ID de canal para `fixed_group`. El valor no debe
contener espacios en blanco. Un nombre visible como `#alerts` no es un ID de canal.

Cuando actives el conector en **Mole Agent → Configuración → Mensajería instantánea**, las notificaciones de alerta que envíe
incluirán los botones Confirmar recepción y Resolver. Consulta [Tarjetas de alerta](/es/im#tarjetas-de-alerta).

### Webhook de Slack

Crea un webhook entrante en Slack y copia la URL en **URL del webhook**. Un destino `fixed_group`
usa la URL configurada. Un destino `webhook` usa el valor del destino como URL alternativa para esa
entrega.

MoleSignal envía un objeto JSON con un campo `text`. Si la respuesta no es 2xx, MoleSignal marca el intento como
fallido.

### Aplicación de Lark

Crea una aplicación del inquilino que pueda obtener un token de acceso del inquilino y enviar mensajes. Ingresa el **ID de la aplicación**
y el **Secreto de la aplicación**. Elige **Feishu** o **Lark** como **Plataforma**. La URL base de la API depende de esa selección.

El tipo de ID del destinatario que selecciones se aplica a los destinos `direct_user`:

| Tipo de destino | Valor |
|---|---|
| `direct_user` | `open_id`, `user_id`, `union_id` o correo electrónico, según el **Tipo de ID del destinatario** |
| `fixed_address` | Dirección de correo electrónico. MoleSignal envía con `receive_id_type=email` |
| `fixed_group` | ID del chat de Lark. MoleSignal envía con `receive_id_type=chat_id` |

Si la aplicación recibe eventos mediante una conexión persistente, también permite a Mole Agent responder en Feishu. Consulta
[Mole Agent en la mensajería instantánea](/es/im#feishu).

Cuando actives el conector en **Mole Agent → Configuración → Mensajería instantánea**, las notificaciones de alerta que envíe
incluirán los botones Confirmar recepción y Resolver. Consulta [Tarjetas de alerta](/es/im#tarjetas-de-alerta).

### Webhook de Lark

Copia la URL del bot personalizado en **URL del webhook**. Si activaste la verificación de firmas del bot, ingresa también
el **Secreto de firma**. MoleSignal genera la marca de tiempo y la firma HMAC-SHA256 para cada
solicitud.

Un destino `fixed_group` usa la URL configurada. Un destino `webhook` puede sustituir la URL configurada por otra
URL absoluta. Consulta [Conectores de webhook](/es/notification-channels/webhooks) para conocer el formato de la solicitud y de
la firma.

### Aplicación de DingTalk

Usa el robot de una aplicación interna de DingTalk. Ingresa el **ID de cliente** y el **Secreto de cliente** de la aplicación. Deja
**Código del robot** en blanco, salvo que el robot tenga un código propio. En ese caso, ingresa el ID de cliente. MoleSignal
intercambia las credenciales por un token de acceso y envía mensajes en Markdown mediante el robot.

| Tipo de destino | Valor |
|---|---|
| `direct_user` | ID de usuario de DingTalk (`userId`) de una persona incluida en el ámbito de visibilidad de la aplicación |
| `fixed_group` | El `openConversationId` de un grupo al que pertenece el robot |

Si el robot recibe mensajes en modo Stream, también permite a Mole Agent responder en DingTalk.
Consulta [Mole Agent en la mensajería instantánea](/es/im#dingtalk). Si además indicas un **ID de la plantilla de tarjeta**, las notificaciones de alerta
aparecen como tarjetas interactivas con los botones Confirmar recepción y Resolver. Para crear la plantilla, consulta
[Tarjetas interactivas de DingTalk](/es/im#tarjetas-interactivas-de-dingtalk).

### Webhook de DingTalk

Copia la URL del robot personalizado en **URL del webhook**. Si el robot firma las solicitudes, ingresa también el
**Secreto de firma**. MoleSignal agrega la marca de tiempo y la firma HMAC-SHA256 a cada solicitud. Un destino
`fixed_group` usa la URL configurada. Un destino `webhook` la sustituye.

### Aplicación de WeCom

Usa una aplicación propia de WeCom. Ingresa el **ID de la empresa**, el **Secreto** de la aplicación y su **AgentId**.
MoleSignal intercambia esos datos por un token de acceso y envía mensajes en Markdown. WeCom trunca los mensajes a
4,096 bytes. Agrega la dirección desde la que se conecta MoleSignal a las IP de confianza de la aplicación.

| Tipo de destino | Valor |
|---|---|
| `direct_user` | ID de usuario de un miembro incluido en el ámbito de visibilidad de la aplicación |
| `fixed_group` | ID de chat de un grupo que creó la aplicación |

Configura un **Token de devolución de llamada** y **EncodingAESKey**, e ingresa la URL de devolución de llamada del conector en
**Recibir mensajes** de la aplicación. Las notificaciones de alerta a los miembros aparecen como tarjetas de plantilla con los botones Confirmar recepción y
Resolver. Consulta [Botones de una aplicación de WeCom](/es/im#botones-de-una-aplicación-de-wecom).

### Webhook de WeCom

Copia la URL de un robot de grupo en **URL del webhook**. Un destino `fixed_group` la usa y un destino `webhook`
la sustituye.

### Bot inteligente de WeCom

Usa un bot inteligente de WeCom en modo API que reciba mensajes mediante una conexión persistente. Ingresa el
**ID del bot** y el **Secreto de la conexión persistente** que creaste para el bot. La **Dirección de la conexión persistente** es siempre
`wss://openws.work.weixin.qq.com`. Cuando actives el conector en **Mensajería instantánea** de Mole Agent, Mole Agent
responderá en WeCom (consulta [Mole Agent en la mensajería instantánea](/es/im#wecom)) y el bot también enviará notificaciones.
Todos los mensajes y respuestas usarán la conexión persistente.

| Tipo de destino | Valor |
|---|---|
| `direct_user` | ID de usuario de un miembro tal como lo ve el bot inteligente |
| `fixed_group` | ID de chat de un grupo |

El bot solo puede escribir a quienes le hayan enviado un mensaje directo y a los chats en los que
alguien lo haya mencionado. Las notificaciones de alerta aparecen como tarjetas de plantilla con los botones Confirmar recepción y
Resolver. Las demás notificaciones usan Markdown. Si el servidor que genera el envío no
mantiene la conexión del bot, el servidor que la mantiene envía la notificación, normalmente en segundos.
Si ningún servidor mantiene la conexión, la entrega falla. El método de notificación del miembro en este conector también
identifica a quien hace la solicitud por mensajería instantánea.

### Bot de Microsoft Teams

### Números de teléfono para llamadas de voz y SMS

Los conectores de voz y SMS envían notificaciones a un solo número: el que vincula un miembro (`direct_user`) o un
número fijo de una ruta alternativa (`fixed_address`). Escríbelo con `+` y el código de país, como
`+14155550100`. MoleSignal elimina los espacios y guiones. Los conectores de SMS de Alibaba Cloud, Tencent Cloud, Huawei Cloud y SMS genérico por HTTP
también aceptan números móviles de 11 dígitos de China continental.

La llamada lee el título de la notificación y luego el texto, hasta 400 caracteres. El SMS pone el título en
una línea y el texto en la siguiente, hasta 320 caracteres. Si una política de notificación elige una plantilla para
el canal de llamadas o SMS, la llamada o el SMS solo incluye el cuerpo de la plantilla, sin el título. Alibaba
Cloud, Tencent Cloud y Huawei Cloud solo envían plantillas aprobadas. Agrega sus códigos y variables a
las plantillas de notificación, como se describe en [Plantillas de proveedores en plantillas de
notificación](#plantillas-de-proveedor-en-las-plantillas-de-notificación).

Los proveedores limitan la frecuencia de llamadas o SMS a un mismo número. Si el proveedor rechaza una llamada o un SMS por ese límite, por un
número incorrecto o por una plantilla no aprobada, la entrega falla. La política pasa al
siguiente método de la persona y a las rutas alternativas. El proveedor no informa si alguien contestó o escuchó la llamada.
Una entrega exitosa solo indica que el proveedor aceptó la llamada o el SMS.

Un conector llama al mismo número como máximo una vez por minuto. Las notificaciones que llegan dentro de ese minuto
quedan en espera para el mismo número y aparecen como **En cola para combinar** en el registro de entregas. Al terminar el minuto,
una sola llamada lee por turno el título de cada notificación o el cuerpo si usa una plantilla de llamada,
y omite las notificaciones cuya recepción ya se confirmó. Alibaba Cloud, Tencent Cloud y Huawei Cloud
leen la plantilla de la primera notificación y completan cada variable con el valor de cada notificación,
por turno. De todos modos, Alibaba Cloud solo permite una
llamada por minuto a un mismo número, así que ya no rechaza las ráfagas de alertas. Si una política de notificación establece un
intervalo más largo para [combinar notificaciones](#agrupar-notificaciones), MoleSignal usa el intervalo de la política.

### Llamadas de voz de Alibaba Cloud

Envía notificaciones de voz mediante Alibaba Cloud Voice Service solo a números de China continental. Completa
la verificación empresarial en la consola de Voice Service, solicita una plantilla de notificación de voz de **texto a voz**,
como `Hello, ${content}. Please handle it now.`, y crea una AccessKey
para un usuario de RAM que solo pueda usar Voice Service. Luego, completa estos campos:

- **ID de AccessKey** y **Secreto de AccessKey**;
- **Región** — una de las regiones que enumera Alibaba Cloud. La URL base de la API depende de la región;
- **Identificador de llamadas** — déjalo en blanco para el modo compartido. Para el modo dedicado, ingresa el número que compraste. El número
  aparece en cada llamada para que el personal de guardia pueda guardarlo como contacto. La plantilla debe usar el mismo
  modo;
- **Número de lecturas** — de 1 a 3.

Agrega el código de la plantilla (que empieza por `TTS_`) y sus variables a una plantilla de notificación de llamadas.
Las políticas de notificación eligen esa plantilla para el canal de llamadas. Consulta [Plantillas de proveedores en plantillas de
notificación](#plantillas-de-proveedor-en-las-plantillas-de-notificación). Alibaba Cloud permite llamar a un número como máximo
una vez por minuto, 5 veces por hora y 20 veces por día. Rechaza las llamadas que superen esos límites. No incluyas enlaces ni
direcciones IP en las variables.

### SMS de Alibaba Cloud

Solicita una **firma de SMS** y una plantilla de **notificación**, como `${content}. Please handle it
now.`, en la consola de SMS. Luego, ingresa la AccessKey, la **Región** y la **Firma**. Elige
una de las regiones que enumera Alibaba Cloud. Algunas regiones fuera de China tienen sus propias direcciones y la URL
base de la API depende de la región. Agrega el código de la plantilla (que empieza por `SMS_`) y sus variables a
una plantilla de notificación de SMS. Las políticas de notificación eligen esa plantilla para el canal de SMS. Consulta [Plantillas de
proveedores en plantillas de notificación](#plantillas-de-proveedor-en-las-plantillas-de-notificación).

De forma predeterminada, cada variable de una plantilla de notificación admite 35 caracteres. Cuando Alibaba Cloud aumente el
límite para la cuenta empresarial, aumenta **Caracteres por variable** en la plantilla de notificación. Las variables
no pueden incluir enlaces ni direcciones IP. Usa números móviles de China continental o números internacionales.

### Llamadas de voz de Tencent Cloud

En la consola de mensajes de voz, crea una aplicación para obtener el `VoiceSdkAppid` y solicita una
plantilla de notificación de voz. Luego, crea una clave de API para un subusuario. Ingresa **SecretId**, **SecretKey**,
**Región** (se consulta con esa clave y determina la URL base de la API), **ID de la aplicación (SdkAppId)** y
**Número de lecturas** (de 1 a 3). Agrega el ID de la plantilla y sus variables a una plantilla de notificación de llamadas. Nombra las
variables según su posición: `1`, `2`, `3`. Consulta [Plantillas de proveedores en plantillas de
notificación](#plantillas-de-proveedor-en-las-plantillas-de-notificación).

El servicio de voz es prepago. Cuando se agota el paquete, las llamadas fallan y el registro de entregas muestra
`InsufficientBalanceInVoicePackage`. La política de notificación pasa al siguiente método de la persona, así que
no dejes las llamadas como único método. Cada llamada admite hasta 350 caracteres. La documentación
no especifica un límite por variable. El proveedor rechaza los valores demasiado largos (`ContentLengthLimit`). MoleSignal
trunca los valores a 20 caracteres de forma predeterminada. Para aumentar el límite, configúralo en la plantilla de notificación.

### SMS de Tencent Cloud

En la consola de SMS, crea una aplicación para obtener el `SmsSdkAppId` y solicita una firma
y las plantillas. Luego, ingresa **SecretId**, **SecretKey**, **Región**, **ID de la aplicación (SdkAppId)** y
**Firma** (el texto de la firma, no su ID. Es obligatorio para SMS en China continental). Agrega el ID de la plantilla
y sus variables a una plantilla de notificación de SMS. Nombra las variables según su posición: `1`, `2`, `3`.

<Warning>
  De forma predeterminada, las cuentas abiertas después del 25 de enero de 2024 y las cuentas inactivas admiten hasta **6 caracteres** por
  variable y rechazan los valores más largos (`TemplateParameterLengthLimit`). MoleSignal trunca los valores
  a 6 caracteres de forma predeterminada, por lo que muestra muy poco del título de la alerta. Cuando Tencent Cloud aumente
  el límite de la cuenta, ingresa el nuevo valor en **Caracteres por variable** en la plantilla de notificación.
  Las variables no pueden incluir enlaces.
</Warning>

Una llamada a la API exitosa no garantiza que el SMS se haya enviado a ese número. Lo que cuenta es el resultado para el
número. Si el resultado no es `Ok`, la entrega falla y el registro de entregas indica el motivo.

más largos y elimina los caracteres `$`, `{` y `}` de las variables.

### SMS de Huawei Cloud

### Llamadas de voz de Twilio

funcionan igual que en SMS. Consulta [Respuestas a SMS y llamadas](#respuestas-a-mensajes-de-texto-y-llamadas).

### Llamadas de voz y SMS de AWS

El conector de voz de AWS (`aws_voice`) llama mediante `SendVoiceMessage` de AWS End User Messaging y Amazon Polly
lee la notificación. El conector de SMS de AWS (`aws_sms`) envía un SMS transaccional con `SendTextMessage`.
Completa estos campos:

- **Región** — una región habilitada en la cuenta. Cuando ingresas las credenciales del conector, MoleSignal solicita la lista a AWS
  mediante `DescribeRegions` de EC2. El envío falla si la región no ofrece AWS End User
  Messaging;
- **Autenticación** — usa los mismos métodos que los conectores de datos de AWS: clave de acceso, clave temporal, identidad del
  nodo, rol asumido o identidad web. Para asumir un rol, configura su política de confianza con el ID externo
  que muestra la página;
- **Identidad de origen** — un número de teléfono, un ID de número de teléfono, un ID de grupo de números o el ARN de cualquiera de ellos. Para voz,
  indica una identidad de origen y usa un número que admita llamadas de voz. Para SMS, deja el campo en blanco para que AWS elija un número para el
  destino o indica un ID de remitente;
- **Voz de Polly** — solo para voz. Es opcional: `MATTHEW` si dejas el campo en blanco o `ZHIYU` para mandarín;
- **URL base de la API** — depende de la región, como `https://sms-voice.us-east-1.amazonaws.com`.

La identidad necesita `sms-voice:SendVoiceMessage` o `sms-voice:SendTextMessage`, y
`ec2:DescribeRegions` para enumerar las regiones. Una cuenta de AWS que aún esté en
el entorno de pruebas solo puede enviar notificaciones a números verificados.

### SMS genérico por HTTP

Envía cada SMS a una puerta de enlace propia o a un proveedor sin conector específico mediante una solicitud HTTP
personalizada. Completa estos campos:

- **URL de la puerta de enlace** — destino de la solicitud. Puede incluir marcadores, como
  `https://sms.example.com/send?to={{phone}}&msg={{content}}` para una puerta de enlace que use GET;
- **Método HTTP** — POST, PUT o GET. GET no tiene cuerpo;
- **Formato del cuerpo** y **Cuerpo** — JSON o formulario (`x-www-form-urlencoded`).
  El cuerpo predeterminado es `{"phone": "{{phone}}", "content": "{{content}}"}`;
- **Encabezados (JSON)** — por ejemplo, `{"Authorization": "Bearer {{secret}}}`;
- **Secreto** — token o contraseña que requiere la puerta de enlace. MoleSignal lo guarda cifrado. Usa `{{secret}}` para referenciarlo en
  la URL, los encabezados y el cuerpo;
- **Formato del número** — `+8613800138000` (E.164), `8613800138000` (sin +) o `13800138000` (números de China
  continental sin código de país);
- **Campo de éxito** y **Valor de éxito** — opcionales. Una respuesta 2xx cuenta como envío exitoso. Si defines un campo
  de éxito, como `code` o `result.status`, ese campo de la respuesta JSON también debe coincidir con el
  valor de éxito.

| Marcador | Valor |
|---|---|
| `{{phone}}` | Número de destino del SMS, en el formato seleccionado |
| `{{content}}` | Contenido del SMS: una línea para el título y otra para el texto, hasta 320 caracteres |
| `{{title}}` | Título de la notificación |
| `{{text}}` | Texto de la notificación |
| `{{secret}}` | Secreto |

MoleSignal escapa los valores según el contexto: como cadenas JSON en un cuerpo JSON o con codificación de URL en un formulario o en la URL.
Incluye el número y el texto en la solicitud. De lo contrario, no podrás guardar el conector.

### Webhook genérico

Ingresa una URL predeterminada, selecciona `POST`, `PUT` o `PATCH` y elige el **Cuerpo**:

- **Evento de MoleSignal**, la opción predeterminada: JSON para procesamiento automático con la versión, el evento, la alerta,
  la regla y el escalamiento, además del destino y el mensaje ya generado;
- **Cuerpo de la plantilla de notificación**: cuerpo de la plantilla que la política de notificación eligió para el canal de webhook.
  MoleSignal lo envía tal como está escrito. Si la plantilla usa JSON, la envía como JSON. Consulta [Condiciones](#condiciones) y los formatos en
  [Crea plantillas y políticas](#crea-plantillas-y-políticas).

Cada solicitud incluye `X-MoleSignal-Event` (el tipo de notificación) y `X-MoleSignal-Delivery` (el
ID de entrega, que permite al receptor descartar duplicados). Si configuras un **Secreto de firma** de al menos 16 caracteres,
la solicitud también incluye `X-MoleSignal-Timestamp` y `X-MoleSignal-Sign`, con los que el receptor verifica que
la solicitud proviene de MoleSignal. Consulta los campos del cuerpo, la firma y ejemplos para verificarla en
[Conectores de notificación por webhook](/es/notification-channels/webhooks#webhook-genérico).

Para `direct_user`, `fixed_address` y `fixed_group`, MoleSignal envía la solicitud a la URL predeterminada
configurada e incluye el destino como dato de enrutamiento. Para `webhook`, el valor del destino sustituye la
URL predeterminada. Una respuesta 2xx indica que el envío fue exitoso. Si la respuesta incluye `X-Request-ID`, MoleSignal registra el
valor del encabezado como ID de mensaje del proveedor. Los webhooks nunca se [combinan](#agrupar-notificaciones): cada
notificación genera su propia solicitud.

<Warning>
  Las URL de webhook, los encabezados de autorización, los tokens, las contraseñas y los secretos de firma son credenciales. No
  incluyas valores de credenciales en destinos de prueba, plantillas ni atributos de eventos.
</Warning>

### Amazon SNS

Publica cada notificación en un tema de Amazon SNS. Sus suscripciones la reenvían a Lambda, SQS,
endpoints HTTPS, correo electrónico y otros destinos. Completa estos campos:

- **Autenticación** y **Región** — igual que en [Llamadas de voz y SMS de AWS](#llamadas-de-voz-y-sms-de-aws). Usa la región del
  tema, que aparece en su ARN;
- **ARN del tema** — por ejemplo, `arn:aws:sns:us-east-1:123456789012:alerts`;
- **Mensaje** — **Evento de MoleSignal**, la opción predeterminada, publica el mismo JSON que envía un [webhook
  genérico](#webhook-genérico). **Cuerpo de la plantilla de notificación** publica el cuerpo de la plantilla que
  la política de notificación eligió para el canal de webhook.

El asunto contiene el título de la notificación en una sola línea, con menos de 100 caracteres. Cada mensaje incluye
el atributo `event_type`, como `alert.triggered`, y, para las alertas, `severity`. Las políticas de filtrado
de las suscripciones pueden usar estos atributos. En un tema FIFO (con un nombre que termina en `.fifo`), los mensajes de una alerta
comparten un grupo de mensajes y mantienen el orden. El ID de entrega funciona como ID de deduplicación, por lo que SNS
descarta las entregas que se publican dos veces.

La identidad necesita `sns:Publish` en el tema, `kms:GenerateDataKey` y `kms:Decrypt` en la clave del
tema cifrado, y `ec2:DescribeRegions` para enumerar las regiones. Puedes usar cualquier tipo de destino: los mensajes siempre
llegan al tema.

### PagerDuty

Envía eventos a un servicio de PagerDuty mediante Events API v2. En la pestaña **Integraciones** del servicio
en PagerDuty, agrega una integración **Events API V2** y copia su clave de integración, que es la clave de
enrutamiento de 32 caracteres, en **Clave de integración**. Elige la **Región del servicio**: **EE. UU.** o **UE** para una cuenta
cuya dirección termine en `.eu.pagerduty.com`.

| Evento de MoleSignal | Evento de PagerDuty |
|---|---|
| Alerta activada, Alerta escalada | `trigger` |
| Recepción de alerta confirmada | `acknowledge` |
| Alerta resuelta | `resolve` |
| Cualquier otro evento | `trigger`, como una alerta independiente de PagerDuty |

Cada alerta de MoleSignal mantiene una sola alerta de PagerDuty durante todo su ciclo de vida. La clave de deduplicación
`molesignal-<alert ID>` vincula ambas alertas. Un escalamiento vuelve a activar la misma alerta en lugar de crear otra. El evento `trigger`
incluye el título como resumen (hasta 1,024 caracteres), el servicio de la alerta como origen
(`MoleSignal` si no hay servicio), la gravedad (`critical`, `error`, `warning` o `info`), la hora,
el evento que envía un webhook genérico como detalles personalizados y un enlace a la alerta si configuras `http.external_url`.

PagerDuty solo recibe lo que las políticas de notificación envían a este conector. Para confirmar la recepción y resolver
las alertas de PagerDuty junto con las de MoleSignal, envía también los eventos **Recepción de alerta confirmada** y **Alerta resuelta**
al conector. Puedes usar cualquier tipo de destino: los eventos siempre llegan a la integración asociada a la clave.

## Vincular métodos de notificación por usuario

Los administradores pueden abrir **Configuración → Notificaciones → Enrutamiento por usuario**, seleccionar un miembro y hacer clic en
**Vincular método de notificación**. Cada identidad asocia un conector con una identidad externa, como una
dirección de correo electrónico, un ID de usuario de Slack o Lark, o el número de teléfono al que un conector de voz llama o un conector de SMS envía mensajes.

Después de vincular una identidad:

1. envía una notificación de prueba para confirmar que el proveedor la acepta;
2. verifica la identidad después de que la organización confirme su titularidad;
3. habilita la identidad en la preferencia **Eventos de alerta**, **Eventos de guardia** o **Informes**;
4. si hay varias identidades, ordénalas de la principal a las de respaldo;
5. si lo necesitas, configura un horario de silencio y permite que las alertas críticas se envíen durante ese horario.

### Pasar al siguiente paso si nadie confirma la alerta

En la secuencia de eventos de alerta, cada paso posterior al primero puede esperar un número de minutos:

| Configuración | Efecto |
|---|---|
| Primer paso | Envía la notificación en cuanto se activa la alerta o se escala al destinatario. |
| Esperar N minutos | Vuelve a enviar la notificación si nadie confirma la alerta en los N minutos posteriores a la primera notificación al destinatario. |
| Los mismos minutos que el paso anterior | Solo envía la notificación si falla el envío del paso anterior. |

Por ejemplo, Lark de inmediato, un SMS a los 3 minutos y una llamada a los 5 minutos: en cuanto alguien
confirma o resuelve la alerta, se cancelan los envíos de los pasos posteriores, incluidos los de los destinatarios
a los que se escaló la alerta. Si falla el envío de un paso, la secuencia pasa de inmediato al siguiente. Cada paso espera como máximo un día
y solo en los eventos de alerta. Las secuencias de eventos de guardia e informes solo recurren al respaldo si falla el envío.

Los miembros pueden administrar sus identidades y preferencias personales en **Configuración de la cuenta → Notificaciones**.
Para consultar la configuración de otro miembro, se necesita `org.members.read`. Para cambiar o verificar la identidad de otro
miembro, se necesita `org.members.update`.

<Note>
  Quita la identidad de todas las preferencias de envío antes de eliminarla.
</Note>

### Avisos urgentes en Feishu y DingTalk

Si un paso usa un conector de la app de Lark o DingTalk, puede pedirle a la app que envíe un aviso urgente al destinatario
después de enviar el mensaje. Elige cómo en el selector junto al paso:

| Plataforma | Opciones | Requisitos |
|---|---|---|
| Feishu (conector de la app de Lark) | **Buzz en la app**, **Buzz por SMS**, **Buzz por teléfono** | El permiso de la app correspondiente al tipo de aviso: `im:message.urgent`, `im:message.urgent:sms` o `im:message.urgent:phone`. Los avisos Buzz por SMS y por teléfono consumen la cuota de avisos urgentes de la instancia. Lark, el sitio internacional, solo ofrece Buzz en la app. El **Tipo de ID del destinatario** del conector debe ser `open_id`, `user_id` o `union_id`, no una dirección de correo electrónico. |
| DingTalk (conector de la app de DingTalk) | **DING en la app**, **DING por SMS**, **DING por teléfono** | La edición Professional o Exclusive de DingTalk y el permiso de la app `Premium.Ding.Write`. Los avisos DING por SMS y por teléfono requieren comprar una cuota. El aviso DING incluye el título de la notificación, y la llamada lo lee en voz alta. |

En la secuencia de eventos de alerta, un método puede aparecer dos veces con distintos tipos de aviso: por ejemplo, un mensaje de Feishu
de inmediato y luego el mismo método de Feishu con **Buzz por teléfono** a los 5 minutos si nadie ha
confirmado la alerta. Las demás secuencias admiten cada método una sola vez.

Si falla el aviso urgente, por ejemplo, por falta de cuota o de permisos, el paso cuenta como fallido aunque
el mensaje haya llegado, y la secuencia pasa de inmediato al siguiente paso. WeCom no ofrece avisos urgentes.

## Respuestas a mensajes de texto y llamadas

Con **Actuar según las respuestas** habilitado en un conector de voz, SMS o WhatsApp (**Ejecutar acciones al pulsar teclas** para
voz), el destinatario puede gestionar la alerta sin abrir MoleSignal:

- **Mensajes de texto**: el mensaje de una alerta activada o escalada termina con «Responde 31 para confirmar la alerta o 32 para
  resolverla». Basta con responder con uno de los códigos. La cifra de las decenas va rotando del 0 al 9 para cada número de teléfono,
  y la cifra de las unidades es 1 para confirmar la alerta o 2 para resolverla. Si respondes solo con `1` o `2`,
  la acción se aplica al último mensaje que recibió el número. Un solo código actúa sobre todas las alertas de un mensaje agrupado. Los códigos son válidos
  durante un día.
- **Llamadas**: después de escuchar la alerta, pulsa 1 para confirmarla o 2 para resolverla. La llamada indica qué acción
  se ejecutó.

La respuesta o la pulsación de una tecla ejecuta la acción en nombre del miembro que recibió el mensaje. El miembro necesita `alerts.incidents.acknowledge` y una
cuenta activa en una organización activa. La cronología registra la acción como una respuesta por SMS o una pulsación de tecla en una llamada.
Solo los mensajes enviados a un miembro incluyen códigos. Los mensajes enviados al número fijo de una ruta de respaldo no los incluyen.

El proveedor envía las respuestas y las pulsaciones de teclas a una URL de callback de MoleSignal. Configura la URL externa
`http.external_url` y asegúrate de que se pueda acceder desde
internet a las rutas bajo `/api/v1/public/notify/`. Consulta [Acceso público](/es/public-access). Tras habilitar la opción y guardar el conector,
el conector muestra la URL de callback, lista para copiar:

| Conector | Qué hacer | Cómo se valida el callback |
|---|---|---|
| Twilio SMS | En la configuración de mensajería del número, selecciona Webhook y HTTP POST en **A message comes in** e introduce la URL de callback. | La firma `X-Twilio-Signature` de Twilio, que se valida con el token de autenticación del conector. |
| Twilio WhatsApp | En Twilio, configura el webhook de mensajes entrantes del remitente de WhatsApp o de su servicio de mensajería con la URL de callback y el método HTTP POST. WhatsApp solo envía plantillas aprobadas, así que incluye los códigos en la plantilla: asigna `{{reply.ack}}` y `{{reply.resolve}}` a las variables de la plantilla. Si la plantilla asigna un código al ID de un botón de respuesta rápida, pulsar ese botón equivale a responder con ese código. | La firma de Twilio. |
| Voz de Twilio | No hagas nada: cada llamada incluye su propia URL para las pulsaciones de teclas. | La firma de Twilio. |
| AWS SMS | Habilita los SMS bidireccionales para el número con un tema de SNS para las respuestas y agrega al tema una suscripción HTTPS con la URL de callback como punto de conexión. La suscripción se confirma automáticamente. Introduce el ARN del tema en **ARN del tema de SNS para respuestas** para aceptar solo las respuestas de ese tema. | La firma del mensaje de SNS, con certificados obtenidos únicamente de `sns.<region>.amazonaws.com`. |
| Alibaba Cloud SMS | En SMS Service, configura el envío de los mensajes entrantes por HTTP a la URL de callback. Alibaba Cloud solo envía plantillas aprobadas, así que incluye los códigos en la plantilla: asigna las variables `{{reply.ack}}` y `{{reply.resolve}}` a los parámetros de la plantilla. Consulta [Variables de plantilla](#variables-de-plantilla). | El token de callback incluido en la URL. |
| Voz de Alibaba Cloud | Las llamadas usan el servicio de voz interactiva (IvrCall) y requieren el **Identificador de llamadas**, un número real adquirido para IvrCall. En Voice Service, configura el envío de las confirmaciones por HTTP a la URL de callback. Tras leer la plantilla, el sistema espera 10 segundos a que se pulse una tecla. | El token de callback incluido en la URL. |
| Tencent Cloud SMS | En la configuración de callbacks de la consola de SMS, introduce la URL de callback en el campo del callback de respuestas. Incluye los códigos en la plantilla: asigna `{{reply.ack}}` y `{{reply.resolve}}` a las variables de la plantilla. | El token de callback incluido en la URL. |
| Voz de Tencent Cloud | En la configuración de callbacks de eventos de la consola de mensajes de voz, introduce la URL de callback en el campo del callback de pulsación de teclas. Agrega manualmente «pulsa 1 para confirmar la alerta o 2 para resolverla» a la plantilla. El evento de pulsación solo incluye el número al que se llamó, por lo que la acción se aplica a la última llamada a ese número. | El token de callback incluido en la URL. |
| Huawei Cloud SMS | Al crear la aplicación de SMS, introduce la URL de callback como dirección para los SMS entrantes. Incluye los códigos en la plantilla como se indicó antes. | El token de callback, que es la última parte de la URL. |
| Voz de Huawei Cloud | En la administración de aplicaciones, introduce la URL de callback como dirección para el estado de la llamada. El sistema registra una sola pulsación después de leer la plantilla. Agrega manualmente «pulsa 1 para confirmar la alerta o 2 para resolverla» a la plantilla. | El token de callback, que es la última parte de la URL. |
| SMS genérico por HTTP | Configura la puerta de enlace para que envíe los mensajes de texto que reciba a la URL de callback mediante POST, en formato JSON `{"phone": "…", "text": "…"}` o como un arreglo de estos objetos. | El token de callback incluido en la URL. |

El servidor deriva el token de callback de cada conector a partir de su clave raíz y no lo almacena. Protege la URL
como una credencial. Los mensajes de voz de AWS no admiten pulsaciones de teclas, por lo que `aws_voice` no ofrece esta opción.

## Enlaces de acción de un solo uso

Cuando un conector envía una notificación de alerta a una sola persona sin incluir botones, el mensaje termina con
enlaces de un solo uso: **Confirmar recepción** y **Resolver** mientras esté pendiente la confirmación, y
solo **Resolver** una vez confirmada la recepción. Esto se aplica a los conectores de correo electrónico y mensajería instantánea que envían
la alerta sin botones, como un bot de Webex o una aplicación de Lark que no esté habilitada en **Mensajería instantánea**. En una
tarjeta, los enlaces aparecen junto a los botones de enlace; en los demás casos, aparecen al final del mensaje. El texto de los enlaces utiliza el
idioma de la interfaz de la persona destinataria.

- El enlace abre una página de MoleSignal, `https://<external address>/notify/actions/<token>`, sin necesidad de
  iniciar sesión. La página muestra la gravedad, el estado, el título y la hora de inicio de la alerta, además de un botón.
  Abrir la página no ejecuta ninguna acción, así que los sistemas de análisis de correo pueden abrir el enlace sin consecuencias. Para ejecutar la acción,
  haz clic en el botón.
- El enlace funciona una sola vez y es válido durante 24 horas. Al hacer clic en el botón, MoleSignal ejecuta la acción en nombre de la persona destinataria,
  que en ese momento debe tener el permiso `alerts.incidents.acknowledge` sobre la alerta y una cuenta activa en una
  organización activa.
- Si alguien ya usó el enlace, si caducó o si dejó de ser aplicable porque alguien gestionó la alerta o la condición volvió a la normalidad,
  o si la persona destinataria ya no puede actuar sobre la alerta, la página indica el motivo y no cambia nada.
- Los enlaces requieren `http.external_url`. Si no configuras ese valor, las notificaciones no incluyen enlaces. Si MoleSignal permanece en la
  red interna, la página y su API deben ser accesibles desde donde las personas destinatarias consultan el correo. Consulta
  [Acceso público](/es/public-access).

Las notificaciones a un grupo o a una dirección fija de una ruta de respaldo no incluyen enlaces. Tampoco los incluyen los
mensajes de texto, las llamadas ni las integraciones. Los mensajes de texto y las llamadas admiten [respuestas](#respuestas-a-mensajes-de-texto-y-llamadas) en su lugar.

## Crea plantillas y políticas

Abre **Configuración → Notificaciones → Plantillas** para crear un cuerpo de mensaje reutilizable. Selecciona una categoría de notificación
y un canal, inserta [variables](#variables-de-plantilla) o parte de una
[plantilla predefinida](#plantillas-predefinidas) y usa los atributos del evento de vista previa para verificar cómo se muestra el
mensaje. Las variables, las plantillas predefinidas y los atributos del evento de vista previa, a la derecha del editor,
están contraídos al inicio. Selecciona un título para desplegar la sección. La lista de plantillas se ordena por canal.

| Canal | Uso | Cuerpo |
|---|---|---|
| **General** | Cualquier canal para el que la política de notificación no especifique una plantilla. | Texto, Markdown o HTML. |
| **Mensajería instantánea**, **Correo electrónico**, **Webhook** | Solo el canal correspondiente. | Texto, Markdown o HTML. Una plantilla de mensajería instantánea también se puede [enviar como tarjeta](#tarjetas-en-las-plantillas-de-mensajería-instantánea). Una plantilla de webhook también admite JSON: el sistema escapa los valores como cadenas JSON, exige que el cuerpo con los valores insertados sea JSON válido y lo envía como **Cuerpo de la plantilla de notificación** de un [webhook genérico](#webhook-genérico). |
| **SMS**, **Teléfono** | Solo el canal correspondiente. | El sistema solo envía el texto sin formato, sin el título de la notificación. Un SMS admite hasta 320 caracteres y una llamada lee hasta 400. El editor cuenta los caracteres. |

Luego, abre **Políticas** y crea la regla de enrutamiento:

1. Selecciona un tipo de evento y una categoría.
2. Agrega criterios de coincidencia en JSON y establece la prioridad de la política. En **Tiempo**, **Solo dentro de este horario** o
   **Solo fuera de este horario** limita la política a un horario semanal según el momento en que ocurrió el
   evento. El horario puede tener en cuenta los días festivos de un [calendario de días festivos](/es/alerting/on-call#calendarios-de-días-festivos).
   Fuera del horario aplicable, la política no envía nada y las demás políticas siguen vigentes.
3. Elige un resolutor de destinatarios y su configuración.
4. Respeta las preferencias del usuario, fuerza el uso de un conector o envía mediante varios conectores.
5. Selecciona una plantilla general y, si es necesario, una plantilla específica para mensajería instantánea, teléfono, SMS
   y otros canales. Habilita las alternativas de respaldo del usuario, del equipo o de la organización.
6. Si es necesario, configura un tiempo de espera para el acuse de recibo y una ruta de escalamiento. Para las políticas de alerta, define también un intervalo para
   [agrupar notificaciones](#agrupar-notificaciones).
7. Revisa la vista previa de entrega en tiempo real. Identifica los miembros y las rutas que se usarán e indica la
   plantilla de cada paso sin enviar notificaciones.

Cada entrega usa la plantilla seleccionada para el canal de su conector. Si no hay una plantilla para ese canal,
usa la plantilla general. Si no hay ninguna de las dos, usa el mensaje propio del evento. No puedes eliminar una plantilla que
use una política de notificación ni moverla a otro canal.

Por ahora, las políticas cubren los eventos del ciclo de vida de las alertas y de los horarios de guardia. El editor de políticas muestra los
tipos de eventos y los resolutores de destinatarios que admite el backend en ejecución. Las políticas retienen los eventos de alerta
de los incidentes que coinciden con un [silencio](/es/alerting/silences). Consulta
[Notificaciones durante un silencio](/es/alerting/silences#notificaciones-durante-un-silencio).

### Agrupar notificaciones

Cuando se acumulan las alertas, una persona o un grupo puede recibir varias notificaciones en cuestión de segundos. Las políticas de notificación
de las categorías de alerta y escalamiento incluyen **Agrupar notificaciones**. Elige 30 segundos o 1, 2
o 5 minutos (la API admite de 10 segundos a 10 minutos). El sistema agrupa las notificaciones de alerta que se dirigen a un mismo destinatario
mediante el mismo conector dentro de ese intervalo: envía la primera de inmediato y, al final del
intervalo, envía las demás juntas, salvo aquellas cuyo recibo ya se confirmó.

- La mensajería instantánea y el correo electrónico envían una sola lista. El título es el de la primera alerta, con «(+N)» al final. El cuerpo
  enumera las alertas y enlaza cada una con su incidente si configuras la URL externa. Las tarjetas de las aplicaciones de Feishu
  o Slack incluyen **Confirmar recepción de todas**. Consulta [Tarjetas de alerta](/es/im#tarjetas-de-alerta).
- Los SMS muestran los títulos en orden y las llamadas los leen en ese mismo orden. Una sola respuesta por SMS actúa sobre todas las alertas. Las llamadas
  se agrupan en intervalos de al menos 60 segundos en cualquier caso.
- El sistema nunca agrupa las notificaciones del webhook genérico, PagerDuty ni Amazon SNS.

Las políticas integradas para alertas activadas, recuperadas y escaladas agrupan las notificaciones durante 1 minuto de forma predeterminada. Las demás
políticas usan **No agrupar** de forma predeterminada.

### Variables de plantilla

El cuerpo, los valores de una plantilla de proveedor y cada parte de una tarjeta admiten variables como
`{{rule.name}}`. El sistema las rellena con los valores de la notificación al enviarla. **Variables**, a la
derecha del editor, muestra las de la categoría de la plantilla. Selecciona una para insertarla en la posición del cursor.
Un nombre que termina en `_at` indica una marca de tiempo en microsegundos. Si termina en `_time`, indica una fecha y hora en UTC, como
`2026-07-29 00:00:00 UTC`. Si el evento no contiene una variable, el sistema la deja en el texto tal como aparece escrita.

Variables de alertas y escalamientos:

| Variable | Valor |
|---|---|
| `{{rule.name}}`, `{{rule.description}}` | El nombre y la descripción de la regla. |
| `{{severity}}`, `{{incident.status}}` | La severidad y el estado de la alerta. |
| `{{urgency}}`, `{{priority}}` | La clave del nivel de urgencia (`high`, `low` o un nivel agregado por la organización) y la prioridad (de `P1` a `P9`, vacía si no hay ninguna). Consulta [Urgencia](/es/alerting/on-call#urgencia). Las políticas de notificación también pueden usar los atributos del evento `urgency` y `priority` como criterios de coincidencia. |
| `{{urgency_name}}`, `{{priority_name}}` | Los nombres que la organización asignó al nivel de urgencia y a la prioridad en [Niveles de urgencia y prioridad](/es/alerting/on-call#niveles-de-urgencia-y-prioridad). Si no tienen nombre, los valores quedan vacíos. |
| `{{value}}`, `{{threshold}}` | El valor que activó la alerta y el umbral. Si la regla tiene niveles de severidad, devuelve el umbral del nivel de la alerta. Las reglas de anomalías no tienen umbral y devuelven `null`. |
| `{{incident.url}}` | La dirección de la alerta en MoleSignal. Requiere la URL externa `http.external_url`. |
| `{{incident.started_time}}`, `{{incident.duration}}` | El momento en que comenzó la alerta y cuánto tiempo lleva activa, por ejemplo, `1h 5m`. Si la alerta ya está resuelta, la duración se calcula hasta el momento de la resolución. |
| `{{incident.acknowledged_time}}`, `{{incident.acknowledged_by}}` | El momento del acuse de recibo y el ID de usuario de quien lo confirmó, una vez que esto ocurre. |
| `{{incident.resolved_time}}`, `{{incident.resolved_by}}` | El momento de la resolución y el ID de usuario de quien resolvió la alerta, una vez resuelta. Si la alerta se recupera por sí sola, no hay un usuario que la haya resuelto. |
| `{{incident.assignees}}`, `{{affected_services}}` | Los ID de usuario de las personas asignadas y los servicios afectados, separados por comas. |
| `{{service}}`, `{{environment}}` | El servicio y el entorno, tomados de las etiquetas o anotaciones de la alerta. |
| `{{labels}}`, `{{labels.<key>}}` | Todas las etiquetas (`service=api, env=production`) y el valor de una etiqueta específica, respectivamente. Para las anotaciones, usa `{{annotations.<key>}}`. |
| `{{escalation.step}}`, `{{escalation.loop}}`, `{{escalation.target}}` | El paso y la ronda del escalamiento, numerados desde 1, y el tipo de destinatario del paso (`user`, `schedule` o `team`). Solo se usan en escalamientos. |
| `{{escalation.reason}}` | El motivo del envío de la notificación de escalamiento: `step` (la política avanzó al siguiente paso), `manual` (escalamiento manual inmediato), `reassigned`, `responder_added`, `snooze_ended`, `ack_timeout` (se confirmó el recibo, pero no se resolvió a tiempo), `severity_raised` o `urgency_raised`. Consulta [Actúa sobre un incidente](/es/alerting/incidents#actuar-sobre-un-incidente). |
| `{{reply.ack}}`, `{{reply.resolve}}` | Los códigos para confirmar el recibo o resolver la alerta mediante una respuesta, por ejemplo, `31` y `32`. El sistema solo los rellena en alertas enviadas por conectores SMS con [Actuar sobre las respuestas](#respuestas-a-mensajes-de-texto-y-llamadas) habilitado. En los demás casos, deja las variables tal como aparecen escritas. |

Los horarios de guardia tienen `{{schedule.*}}`, `{{oncall.*}}` y `{{override.*}}`. Además de los
valores `_at` en microsegundos, usa las siguientes variables para el relevo y el intervalo de sustitución:
`{{oncall.transition_time}}`, `{{override.start_time}}` y `{{override.end_time}}`. Todas las categorías
incluyen `{{event.time}}`, `{{message.title}}` y `{{message.text}}`. Puedes acceder a cualquier atributo del evento con
`{{event.attributes.<key>}}`.

### Condiciones

El cuerpo admite bloques condicionales. El sistema solo incluye su contenido si se cumple la condición:

```text
{{#if severity == "critical"}}Act now{{else}}Take a look{{/if}}: {{rule.name}}
{{#if event.type == "alert.resolved"}}Recovered after {{incident.duration}}{{/if}}
{{#if annotations.runbook_url}}Runbook: {{annotations.runbook_url}}{{/if}}
```

- `{{#if variable == "value"}}` y `!=` comparan el valor de una variable. Si solo indicas la variable, la condición se cumple cuando tiene
  un valor que no está vacío.
- El contenido de `{{else}}` se incluye cuando no se cumple la condición. Este bloque es opcional.
- Puedes anidar bloques hasta 5 niveles. Si dejas un bloque abierto (sin `{{/if}}`), no podrás guardar la plantilla. El editor indica
  el problema debajo del cuerpo.
- La vista previa evalúa las condiciones con los atributos de su evento. **Condiciones**, a la derecha del
  editor, muestra algunas condiciones habituales. Selecciona una para insertarla.

### Plantillas predefinidas

Las **Plantillas predefinidas** ofrecen cuerpos de mensaje listos para usar como punto de partida. Después de aplicar uno, puedes seguir editándolo. La lista
se organiza por categoría y canal. Las plantillas de SMS y teléfono ofrecen opciones predefinidas para su canal.
Las plantillas de mensajería instantánea y correo electrónico también tienen sus propias opciones, como un mensaje en Markdown
con un enlace a la alerta o un correo de alerta en formato de tabla. Hay plantillas predefinidas para notificar la activación,
el acuse de recibo y la resolución de alertas. Si aplicas una plantilla de acuse de recibo o de resolución, la vista previa muestra
una alerta de ejemplo en el estado correspondiente. Los cuerpos predefinidos usan el idioma de la interfaz. Por ejemplo, la interfaz en chino
aplica cuerpos en chino.

### Plantillas de proveedor en las plantillas de notificación

Alibaba Cloud, Tencent Cloud y Huawei Cloud solo envían plantillas que hayan aprobado. WhatsApp solo envía
plantillas de contenido que haya aprobado. Una plantilla de SMS o teléfono puede incluir una plantilla para cada proveedor. La de WhatsApp solo se incluye
en plantillas de SMS:

- **Código de la plantilla** — El código que asignó el proveedor. En Alibaba Cloud, comienza con `SMS_` para SMS y
  con `TTS_` para voz. En Tencent Cloud y Huawei Cloud, usa el ID de la plantilla. Para WhatsApp, en
  **SID de contenido**, indica el SID de contenido de Twilio: `HX` seguido de 32 caracteres hexadecimales.
- **Variables** — El valor que rellena cada variable del proveedor. Escribe el valor como el cuerpo del mensaje. Puedes usar
  variables como `{{rule.name}}`. En Alibaba Cloud, usa los nombres que aparecen dentro de `${…}` en la plantilla.
  Tencent Cloud, Huawei Cloud y WhatsApp rellenan las variables por posición, así que los nombres son `1`, `2`, `3`.
- **Caracteres por variable** — El sistema recorta los valores más largos. Si dejas el campo vacío, aplica el límite predeterminado: 35 para Alibaba Cloud;
  6 para SMS y 20 para voz en Tencent Cloud; 20 para SMS y 32 para voz en Huawei Cloud (la voz también tiene un límite de 32 bytes);
  300 para WhatsApp.

Los conectores de estos proveedores envían la plantilla específica del proveedor. Los demás conectores de SMS y teléfono envían el
cuerpo de la plantilla. Si la plantilla que la política de notificación seleccionó para el canal no incluye una plantilla para ese
proveedor, la entrega falla y el registro de entregas indica el motivo.

Al probar uno de estos conectores, el sistema envía una plantilla de su canal que incluye una plantilla para ese proveedor,
con valores de ejemplo para los marcadores de posición. Al probar el número de un miembro vinculado a ese conector, usa la
primera plantilla que cumple ese requisito en orden alfabético por nombre. Las inspecciones programadas, las automatizaciones y otros envíos directos
no usan plantillas de notificación, por lo que no pueden usar estos conectores.

### Tarjetas en las plantillas de mensajería instantánea

Activa **Enviar como tarjeta** en una plantilla de mensajería instantánea para que las aplicaciones y los bots de grupo envíen una tarjeta.
Si desactivas la opción, siguen enviando texto. La tarjeta usa el cuerpo del mensaje de la plantilla como texto y admite estos
elementos:

- **Título de la tarjeta** — Si lo dejas vacío, la tarjeta usa el título de la notificación.
- **Color del título** — Usa el color según la severidad (rojo para crítica, naranja para error, amarillo para advertencia, azul para las demás y
  verde cuando la alerta se resuelve) o elige un color fijo.
- **Campos** — Un nombre y un valor, por ejemplo, `{{labels.service}}` para `Service`. Puedes agregar hasta 10.
- **Botones de enlace** — El texto del botón y una dirección, por ejemplo, `{{annotations.runbook_url}}` para
  `Runbook`. Puedes agregar hasta 5.
- **Pie de tarjeta** — Una línea de texto pequeño en la parte inferior de la tarjeta.

Todos los elementos admiten variables. El sistema omite los campos o enlaces que el evento no puede rellenar y los enlaces
cuya dirección no usa HTTP o HTTPS. La vista previa del editor muestra un diseño aproximado. Cada plataforma envía su propio
formato:

| Plataforma | Formato de envío |
|---|---|
| **Lark** | Una tarjeta interactiva con una franja de color para el título, campos en dos columnas y un pie debajo de una línea divisoria. En la aplicación, los botones de enlace aparecen junto a los botones Confirmar recepción y Resolver de la alerta. |
| **Slack** | Una tarjeta Block Kit con una barra de color. En la aplicación, los botones de enlace aparecen junto a los botones de la alerta. |
| **DingTalk** | Una ActionCard con el título en color y hasta 5 enlaces como botones debajo de la tarjeta. Si no hay enlaces, usa Markdown. Si la aplicación tiene un ID de plantilla de tarjeta, envía las notificaciones de alerta como tarjetas interactivas basadas en esa plantilla y con los botones de la alerta. |
| **WeCom** | Markdown con formato de tarjeta y el título en color (WeCom solo admite texto verde, gris y naranja). Si incluye botones de alerta, usa una tarjeta de plantilla interactiva con botones y hasta 6 campos como subtítulos con texto. Al pulsar la tarjeta, se abre MoleSignal. |
| **Teams** | Una Adaptive Card con una franja de color para el título, campos como pares de nombre y valor, enlaces como botones y un pie debajo de una línea divisoria. Los botones de enlace del bot aparecen junto a los botones de la alerta. |
| **Google Chat** | Una tarjeta con los campos en líneas etiquetadas y los enlaces como botones. Los botones de enlace de la aplicación aparecen junto a los botones de la alerta. Los títulos de las tarjetas de Google Chat no tienen color. |
| **Telegram** | Un mensaje con el título en negrita precedido por un punto del color del título, un campo por línea y el pie en cursiva. Los botones de la alerta aparecen en la primera fila y, debajo, los botones de enlace se distribuyen de dos en dos. Si Telegram rechaza una dirección no pública, muestra los enlaces como líneas de texto. |
| **Discord** | Un elemento incrustado con una barra de color, el título enlazado a la alerta, los enlaces debajo del texto, los campos uno al lado del otro y el pie. |
| **Mattermost** | Un archivo adjunto al mensaje con una barra de color, el título enlazado a la alerta, los campos (los cortos uno al lado del otro), los enlaces debajo del texto y el pie. Los botones de alerta del bot aparecen debajo del adjunto. |
| **Webex** | El bot envía una Adaptive Card con el mismo diseño que la tarjeta de Teams, con hasta 5 botones de enlace y los enlaces adicionales debajo del texto. El webhook envía Markdown. |
| **Matrix** | Un mensaje con formato: el título en color, los campos en una lista, seguidos de los enlaces, y el pie en cursiva. |

Los bots de grupo no reciben clics, por lo que sus tarjetas no incluyen los botones Confirmar recepción ni Resolver. Al probar un
conector, puedes seleccionar una plantilla de mensajería instantánea para enviar su tarjeta con valores de ejemplo para las
variables.

### Políticas integradas

Cada organización cuenta desde el inicio con las siguientes políticas de notificación para que las alertas y los eventos de guardia lleguen a sus destinatarios
antes de que se cree una política. Todas usan **Respetar la preferencia del usuario**. Si no pueden enviar un mensaje,
usan los destinos de respaldo del usuario y luego las rutas de respaldo del equipo y de la organización. No seleccionan ninguna
plantilla y envían el mensaje propio del evento.

| Política integrada | Evento | Notifica a | Estado inicial |
|---|---|---|---|
| Alerta activada: notificar al propietario | Alerta activada | El propietario de la alerta o las personas asignadas si no hay propietario | Activada |
| Alerta resuelta: notificar al propietario | Alerta resuelta | El propietario de la alerta o las personas asignadas si no hay propietario | Activada |
| Escalamiento: notificar a las personas del paso | Alerta escalada a personas | Las personas indicadas en el paso | Activada |
| Escalamiento: notificar al equipo del paso | Alerta escalada a un equipo | Los miembros de ese equipo | Activada |
| Relevo de guardia: notificar a ambas personas | Inicio de un turno de guardia | La persona que termina el turno y la persona que lo inicia | Activada |
| Guardia sin cobertura: notificar a los responsables del horario | Falta de cobertura de guardia | Los responsables del horario | Activada |
| Recepción de alerta confirmada: notificar al propietario | Recepción de alerta confirmada | El propietario de la alerta o las personas asignadas si no hay propietario | Desactivada |
| Sustitución de guardia: notificar a las personas involucradas | Sustitución de guardia creada | La persona que cubre la guardia y la persona que estaba de guardia | Desactivada |
| Intercambio de turnos: notificar a las personas involucradas | Intercambio de turnos actualizado | Las personas que deben conocer el paso. Consulta [Intercambios de turnos](/es/alerting/on-call#cambios-de-turno) | Activada |
| Miembro de guardia no localizable: notificar al miembro y a los responsables del horario | No se puede contactar al miembro de guardia (30 minutos antes de que empiece un turno) | La persona que toma el turno y los responsables del horario. Consulta [Miembros que no pueden recibir alertas](/es/alerting/on-call#miembros-que-no-pueden-recibir-alertas) | Activada |
| Presupuesto de ingesta casi agotado: notificar a las personas indicadas | Presupuesto de ingesta casi agotado | Las personas indicadas en el presupuesto. Consulta [Configura un presupuesto](/es/streams#definir-un-presupuesto) | Activada |
| Presupuesto de ingesta superado: notificar a las personas indicadas | Presupuesto de ingesta superado | Las personas indicadas en el presupuesto. Consulta [Configura un presupuesto](/es/streams#definir-un-presupuesto) | Activada |
| Actualización de incidente mayor: notificar a las partes interesadas | Actualización de incidente mayor | Las personas asignadas, los roles y las partes interesadas del incidente. Consulta [Publica una actualización](/es/alerting/major-incidents#publicar-una-actualización) | Activada |
| Se requiere aprobación: notificar a quienes pueden aprobar | Solicitud de aprobación de Mole Agent (`agent.approval.requested`) | Hasta 20 miembros con el permiso `agent.approve`, sin incluir a quien solicitó la aprobación. Consulta [Tarjetas de aprobación](/es/im#tarjetas-de-aprobación) | Activada |

Las políticas integradas llevan la etiqueta **Integrada** en la lista de **Políticas de notificación**. Puedes modificarlas y
desactivarlas, pero no eliminarlas ni cambiarles el nombre. Para recuperar la configuración anterior, selecciona
**Restaurar valor predeterminado** en el editor. Los pasos de escalamiento que apuntan a un horario de guardia no tienen una política integrada. Crea una
por horario y selecciona **Usuario de guardia actual** como destinatario.

## Configura las rutas de respaldo

Abre **Configuración → Notificaciones → Rutas de respaldo**. Selecciona el ámbito de una organización o un equipo y
una categoría de notificación. Agrega uno o más conectores habilitados, elige `fixed_address` o
`fixed_group` e ingresa el destino del proveedor.

MoleSignal prueba las rutas en el orden que se muestra cuando fallan las etapas habilitadas de la ruta personal. La
política determina si se usan las rutas de respaldo de usuario, equipo y organización.

## Revisa y reintenta las entregas

Abre **Configuración → Notificaciones → Registro de entregas**. Filtra por ID de evento, estado o etapa. Selecciona un
intento para revisar el destino enmascarado, el conector, la latencia, el error del proveedor y la cadena de entrega
completa.

- `notify.deliveries.read` permite consultar el historial de entregas.
- `notify.deliveries.acknowledge` permite confirmar la recepción del evento de origen.
- `notify.deliveries.retry` permite reintentar las rutas fallidas.

Cada reintento crea un nuevo intento. El historial de entregas existente no cambia.

MoleSignal vuelve a intentar automáticamente el envío de las notificaciones de alerta que fallaron. Deja de hacerlo cuando se confirma la recepción de la alerta o se resuelve, pero aún puedes reintentar el envío manualmente.

Una entrega en la etapa **Directo** proviene de una función que especifica su propio conector y destino,
como una [inspección programada de registros](/es/logs/inspections). Una entrega directa no pasa
por ninguna política y no se puede reintentar.

## Ciclo de vida y estado de los conectores

| Estado | Significado |
|---|---|
| **Desconocido** | El conector aún no ha completado ninguna prueba, ni con éxito ni con error. |
| **Conectado** | La prueba más reciente se completó correctamente. |
| **Error** | La prueba más reciente falló. El enrutamiento normal omite el conector hasta que una prueba posterior se complete correctamente. |
| **Deshabilitado** | MoleSignal no prueba el conector ni realiza entregas a través de él. |

Deshabilitar un conector no elimina sus referencias. No puedes eliminarlo mientras una identidad de usuario,
una política, una ruta de respaldo o una inspección programada de registros siga haciendo referencia a él. Reasigna todas
las referencias antes de eliminar el conector.

## Soluciona problemas de entrega

| Síntoma | Qué revisar |
|---|---|
| Falla la autenticación SMTP o TLS | Verifica el host, el puerto, las credenciales, el modo TLS, la dirección del remitente, el DNS y el acceso saliente a la red. |
| Slack devuelve un error de API | Verifica el token del bot, el permiso `chat.postMessage`, el ID de destino y la pertenencia al canal. |
| Lark rechaza el mensaje | Verifica los permisos de la aplicación, el tipo de ID del destinatario, la pertenencia al chat, el secreto del webhook y el reloj del servidor. |
| El webhook devuelve un error | Verifica la URL, el método, los encabezados en JSON y el tiempo de espera. Comprueba que el endpoint devuelva una respuesta 2xx. |
| El usuario no recibe la notificación | Verifica que la identidad y el conector estén habilitados, que la preferencia de la categoría incluya la identidad y que el horario de silencio no impida la entrega. |
| La ruta de respaldo nunca se activa | Verifica que la política habilite ese nivel de respaldo y que la categoría tenga una ruta habilitada. |
| No se envía una llamada ni un mensaje de texto | Verifica que el número empiece con + y el código de país, que la plantilla y la firma estén aprobadas, que la plantilla que eligió la política de notificaciones para el canal tenga una versión para este proveedor y que los nombres de las variables coincidan. Revisa también los límites de frecuencia del proveedor y el entorno de pruebas de la cuenta. |
| Una respuesta o una pulsación de tecla no tiene efecto | Verifica que el conector tenga activada la opción **Actuar según las respuestas**, que la llamada de retorno del proveedor apunte a la URL que muestra el conector y que esa URL sea accesible desde Internet. Comprueba que el número haya recibido un mensaje de texto de alerta con códigos, que el código tenga menos de un día y que el miembro que recibió el mensaje tenga el permiso `alerts.incidents.acknowledge`. |
| Un paso de Feishu o DingTalk falla aunque llega el mensaje | Falló el aviso urgente: verifica el permiso de la aplicación, la cuota de avisos urgentes o de DING y la edición de DingTalk. Para Feishu, verifica también el tipo de ID del destinatario y la plataforma. |
| Un enlace de acción no tiene efecto | Verifica que el enlace no se haya usado y tenga menos de 24 horas, que la alerta siga esperando esa acción y que el destinatario aún tenga el permiso `alerts.incidents.acknowledge`. Comprueba que la página y `/api/v1/public/notify/actions/` sean accesibles desde donde se abrió el enlace. |
