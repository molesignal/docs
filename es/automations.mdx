Cada vez que se inicia una automatización, esta le pide a Mole Agent que realice la misma tarea: comprobar el estado de los servicios cada mañana, investigar cada nuevo incidente crítico o revisar un despliegue cuando lo solicita el pipeline. Mole Agent realiza la tarea como en un chat, con las herramientas, las habilidades y el conocimiento del ámbito de la automatización. La ejecución se guarda como un chat que pueden abrir quienes tienen acceso a la automatización. Al finalizar la ejecución, el resultado se envía a los canales de notificación seleccionados. Si la automatización se inicia a partir de un incidente, puede registrar su análisis de causa raíz (RCA).

## Antes de empezar

- Activa al menos un modelo de IA en **Mole Agent → Configuración → Modelos y razonamiento**. Consulta [Mole Agent](/es/agent#configura-un-proveedor-de-modelos). Si no hay ningún modelo activo, la ejecución falla e indica el motivo.
- Comprueba los permisos:

| Tarea | Permiso |
|---|---|
| Ver las automatizaciones y sus ejecuciones, y abrir el chat de una ejecución | `agent.automations.read` y acceso al ámbito: consulta [Ámbito de la automatización](#ámbito-de-la-automatización) |
| Crear, editar y activar | `agent.automations.manage`, que se concede de forma predeterminada a los roles de propietario, administrador y editor, y acceso al ámbito |
| Ejecutar ahora | `agent.automations.run`, que se concede a los mismos roles, y acceso al ámbito |
| Administrar el token de API | `agent.automations.tokens`, que se concede a los mismos roles, y acceso al ámbito |
| Desactivar y eliminar | El mismo permiso que para activar, o `agent.manage` para cualquier automatización a la que se tenga acceso |
| Seleccionar canales de notificación en el formulario | `notify.connectors.read`, que permite listar los conectores de notificación |

## Crear una automatización

Abre **Mole Agent → Automatizaciones → Nueva automatización** y empieza con una automatización en blanco o con una plantilla:

| Plantilla | Inicio | Qué hace |
|---|---|---|
| **Análisis de incidentes** | Nuevos incidentes con gravedad de error o crítica | Investiga el incidente con herramientas: vuelve a ejecutar la consulta que lo activó, revisa los logs de errores, las trazas, el APM y la topología de los servicios, e indica la causa raíz probable y la evidencia que la respalda. Registra la conclusión como el RCA del incidente. |
| **Comprobación diaria del estado** | De lunes a viernes a las 09:00 | Comprueba las tasas de error, la latencia, los patrones de error y los incidentes abiertos de las últimas 24 horas. Indica qué requiere atención. |
| **Revisión semanal del ruido de alertas** | Los lunes a las 10:00 | Identifica las reglas de alerta que más se activaron, las que se activaron y desactivaron repetidamente y aquellas cuyas alertas no se atendieron en la última semana. Propone cómo ajustar cada regla. |
| **Carga semanal de guardia** | Los lunes a las 10:30 | Resume los incidentes por persona y por turno, los avisos nocturnos y los tiempos de respuesta. Sugiere cómo reducir la carga. |
| **Comprobación del impacto de los cambios** | Una llamada a la API | Compara el estado de los servicios afectados antes y después de un despliegue e indica si este provocó una regresión. |

El formulario tiene estos campos:

| Campo | Descripción |
|---|---|
| **Nombre** | Debe ser único en la organización. |
| **Qué hacer** | La tarea, de hasta 8000 caracteres. En cada ejecución, Mole Agent recibe la tarea como si fuera un chat nuevo. |
| **Descripción** | Una línea que explica para qué sirve la automatización. |
| **Ámbito** | Selecciona el ámbito al crear la automatización: personal, de un equipo al que perteneces o de la organización. |
| **Inicio** | Según una programación, con nuevos incidentes, mediante una llamada a la API o manualmente. Consulta [Qué inicia la automatización](#qué-inicia-la-automatización). |
| **Límite de tiempo** | De 5 a 60 minutos, con un valor predeterminado de 10. Si una ejecución supera el límite, se detiene y se contabiliza como fallida. |
| **Activada** | Una automatización desactivada solo se inicia con la opción Ejecutar ahora. |
| **Canales de notificación** | Hasta cinco direcciones o grupos fijos en los conectores de notificación. Los servicios de SMS y voz de Alibaba Cloud solo permiten enviar plantillas aprobadas y no están disponibles. |
| **Registrar la conclusión como el análisis de causa raíz (RCA) del incidente** | Para automatizaciones que se inician a partir de incidentes. |

Cada organización puede tener hasta 50 automatizaciones. La opción **Clonar** del menú de una fila abre una copia desactivada en el formulario. Guarda la copia con otro nombre o en otro ámbito.

### Ámbito de la automatización

El ámbito determina qué puede usar una ejecución y quién puede ver la automatización. No se puede cambiar después de crear la automatización. Clona la automatización para usar otro ámbito.

| Ámbito | Qué usa una ejecución | Quién puede verla |
|---|---|---|
| Personal | Las habilidades y los servidores MCP de la organización y los personales, el conocimiento de la organización y la memoria personal | Quien tiene la automatización en su ámbito personal y quienes tienen el permiso `agent.manage` |
| Equipo | Los recursos y el conocimiento de la organización y del equipo, y la memoria del equipo | Los miembros del equipo y quienes tienen el permiso `agent.manage` |
| Organización | Solo los recursos y el conocimiento de la organización. Las ejecuciones no conservan memoria. | Quienes tienen el permiso `agent.automations.read` |

Cuando un incidente inicia una automatización de la organización, la ejecución usa el ámbito del equipo del incidente. La política de escalamiento determina el equipo: primero, el primer equipo al que se envía un aviso; si no hay ninguno, el equipo del primer horario de guardia. Si no hay ningún equipo, la ejecución permanece en el ámbito de la organización.

### Con qué identidad se ejecuta

Una automatización se ejecuta con la identidad de quien la guardó por última vez. En cada ejecución, vuelve a consultar los permisos de esa persona y usa sus credenciales en los servidores MCP que requieren credenciales individuales. Al guardar la automatización, la ejecución queda asociada a la identidad indicada en el formulario. No se puede guardar con un token de API, porque el token representa el rol, no a quien lo creó.

Si la persona que guardó la automatización ya no puede usar Mole Agent en la organización, cada ejecución falla e indica ese motivo hasta que alguien con acceso vuelva a guardar la automatización.

## Qué inicia la automatización

| Activador | Cuándo se ejecuta |
|---|---|
| **Según una programación** | En los momentos que indique una expresión cron de cinco campos (minuto, hora, día del mes, mes y día de la semana) en una zona horaria, como máximo una vez cada 15 minutos. En el campo del día de la semana, 0 y 7 representan el domingo. Restringe el día del mes o el día de la semana, pero no ambos. Si la ejecución anterior sigue en curso, se omite la siguiente. |
| **Nuevos incidentes** | Por cada incidente creado después de guardar o activar la automatización que coincida con todos los filtros configurados: niveles de gravedad, reglas de alerta, servicios afectados y etiquetas con valores iguales. Cada incidente se analiza una sola vez. Los incidentes del mismo grupo, que comparten la regla y las etiquetas, se analizan como máximo una vez cada 30 minutos. |
| **Nuevos hallazgos de detección** | Por cada [hallazgo de detección](/es/alerting/discovery) que aparezca después de guardar o activar la automatización y coincida con todos los filtros configurados: tipos, gravedad mínima y servicios, hosts o contenedores. Cada hallazgo se investiga una sola vez. |
| **Llamada a la API** | Cuando un sistema externo envía el token de la automatización. Consulta [Iniciar desde CI/CD](#inicia-la-automatización-desde-ci/cd). |
| **Manualmente** | Solo cuando alguien inicia la ejecución. |

**Ejecutar ahora** en una fila inicia cualquier automatización, esté activada o desactivada, con la identidad de quien la guardó por última vez. Se puede iniciar como máximo una vez por minuto.

## Ejecuciones

**Ejecuciones** en una fila muestra las últimas 100 ejecuciones, de la más reciente a la más antigua. Para cada ejecución, muestra el resultado y su motivo, qué la inició, el inicio de la respuesta, los canales a los que no llegó la notificación y la opción **Abrir la ejecución** para acceder al chat completo. Ese chat no aparece en la lista de chats y no se puede continuar. Para volver a hacer la consulta, ejecuta de nuevo la automatización.

Durante una ejecución no se pueden enviar respuestas. Si Mole Agent hace una pregunta, continúa según su propio criterio. Omite las herramientas que requieren confirmación y no usa los servidores MCP que requieren una credencial personal no guardada de la persona con cuya identidad se ejecuta la automatización. Mole Agent explica lo ocurrido en su respuesta y marca la ejecución como **Requiere intervención**.

| Estado | Significado |
|---|---|
| **En ejecución** | Mole Agent está realizando la tarea. |
| **Exitoso** | Mole Agent respondió, envió las notificaciones y registró el RCA. |
| **Completada parcialmente** | Mole Agent respondió, pero quedó una notificación sin enviar o el RCA sin registrar. |
| **Requiere intervención** | Mole Agent respondió, pero quedó pendiente la respuesta a una pregunta, una confirmación o una credencial. |
| **Fallido** | Mole Agent no respondió: falló el modelo o una herramienta, la ejecución superó el límite de tiempo, no hay ningún modelo activo o la persona con cuya identidad se ejecuta la automatización ya no puede usar Mole Agent. |
| **Omitido** | La ejecución no se inició: se agotó el presupuesto diario de tokens de la organización, la ejecución anterior no había terminado o el incidente se había analizado poco antes. |
| **Detenida** | Alguien detuvo la ejecución o el servidor que la realizaba se detuvo. |

Las llamadas al modelo durante las ejecuciones cuentan para el presupuesto diario de tokens de la organización y aparecen como **Automatizaciones** en el desglose de uso por origen.

## Avisos y análisis de causa raíz (RCA) del incidente

Cuando una ejecución termina correctamente, requiere intervención o falla, envía un aviso a cada canal con el nombre de la automatización, el resultado de la ejecución, el inicio de la respuesta, los motivos y un enlace a la ejecución. El aviso usa el idioma de quien guardó la automatización y aparece en el historial de entregas como cualquier otra notificación.

Si un incidente activa una automatización con la opción **Registrar la conclusión como el análisis de causa raíz (RCA) del incidente** habilitada, la automatización guarda la respuesta de Mole Agent como el RCA que muestra la página del incidente. Si ya existe un RCA redactado desde un chat, la automatización lo conserva. Mientras la organización mantenga activa una automatización de este tipo, el generador integrado de RCA le delega el análisis de los incidentes para evitar analizarlos dos veces. La plantilla **Análisis de incidentes** viene con esta configuración.

## Inicia la automatización desde CI/CD

Si la automatización se inicia mediante una llamada a la API, abre **Token de API** en el menú de su fila y selecciona **Crear token**. La interfaz muestra el token una sola vez. Si creas otro, lo reemplazas de inmediato. Para eliminarlo, selecciona **Revocar token**.

Envía el token con el despliegue y describe el cambio en `text`:

```bash
curl -X POST "https://molesignal.example.com/api/v1/public/automations/<automation-id>/trigger" \
  -H "Authorization: Bearer mspat-..." \
  -H "Content-Type: application/json" \
  -d '{"text": "Deployed checkout-api v42 at 14:05"}'
```

El campo `text` es opcional y admite hasta 8000 caracteres. Mole Agent lo interpreta como datos de la ejecución, no como instrucciones. La API devuelve `202` con `runId`, `status` y `chatUrl`. Devuelve `401` si el token no es válido o si no reconoce la automatización, `409` si la automatización está desactivada o no admite llamadas a la API, y `429` si recibe una segunda llamada en un plazo de 10 segundos.

## Revisa el uso de Mole Agent

`/insight [days]` es una habilidad integrada que revisa el uso de Mole Agent en el ámbito del chat durante los últimos 30 días o durante el número de días que indiques. Revisa qué solicitudes se hicieron, qué resultados dieron las respuestas y las automatizaciones, qué se calificó como poco útil y por qué, qué herramientas fallaron con frecuencia y qué habilidades se usaron. Al final, sugiere hasta cinco mejoras, como crear un archivo de conocimiento o corregir una automatización. No aplica ningún cambio. En un chat de equipo, revisa el uso del equipo. En un chat personal, revisa tu uso y el de tus equipos. Usa la habilidad en un chat o como tarea de una automatización semanal.
