Revisa primero el registro del proceso. Imprime la causa de un fallo de arranque y el cuerpo del error HTTP de una solicitud rechazada incluye un mensaje. El nivel de registro proviene de `[telemetry].log_level` o `RUST_LOG`.

## Arranque

| Síntoma | Causa | Solución |
|---|---|---|
| `... password authentication failed for user` | El usuario o la contraseña del DSN son incorrectos. | Corrige `[meta_database].dsn`. |
| `... pool timed out while waiting for an open connection` | No se puede acceder a PostgreSQL desde el nodo. | Revisa el host, el puerto, el firewall y los requisitos de `sslmode`. |
| `startup_ping put: ... SignatureDoesNotMatch` | El almacén de objetos rechaza las credenciales. | Revisa `access_key` y `secret_key`. Configúralas con `MS_OBJECT_STORE_ACCESS_KEY` y `MS_OBJECT_STORE_SECRET_KEY`. |
| `startup_ping put: ... NoSuchBucket` | El bucket no existe. | Crea el bucket o corrige `[object_store].bucket`. |
| Aparecen líneas repetidas de `Encountered transport error` y luego el proceso finaliza | No se puede acceder al endpoint o no llegan credenciales al cliente. | Revisa `endpoint`, DNS y la red. Las credenciales deben provenir de `access_key` y `secret_key`. |
| `unknown field: found ...` | Una clave de una sección estricta está mal escrita o no es compatible. | Elimina o corrige la clave. Consulta [Configuración](/es/configuration#cómo-se-carga-la-configuración). |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN must be set when split-role self intake is enabled` | Un nodo con separación de roles sin el rol `intake` se inicia sin el token compartido mientras la captura de trazas o la autorrecolección están activadas. | Configura el mismo token en todos los nodos. Deshabilitar `[telemetry.self_collect]` por sí solo no es suficiente, porque la captura de trazas está activada de forma predeterminada. |
| `open Probe CA key` | `MS_CIPHER_KEY` difiere de la clave con la que se cifró la base de datos. | Restaura la clave original. Consulta [Lista de verificación para producción](/es/deployment/production-checklist). |
| `migration ... was previously applied but is missing in the resolved migrations` o `... has been modified` | El binario y la base de datos provienen de versiones incompatibles. | Ejecuta la versión que coincida o restaura una copia de seguridad. Consulta [Actualización](/es/upgrade). |
| `address already in use` | Otro proceso usa un puerto configurado. | Cambia el puerto. |
| `profiling.port and ... are both ...` | El listener de pprof comparte un puerto con otro listener. | Configura `[profiling].port` en un puerto que no use ningún otro listener. |
| Una configuración establecida mediante una variable de entorno no tiene efecto | El nombre de la variable contiene un punto, un doble guion bajo o un error tipográfico. | Une la ruta con guiones bajos simples, como en `MS_META_DATABASE_DSN`. |

## Inicio de sesión

| Síntoma | Causa | Solución |
|---|---|---|
| Se rechaza `admin@example.com` con `admin` | La base de datos ya tenía usuarios, por lo que la cuenta raíz no se volvió a crear, o `root_email` y `root_password` estaban vacíos. | Inicia sesión con una cuenta existente. Configura ambos valores e inicia el servicio contra una base de datos vacía para crear la cuenta raíz. |
| El correo de restablecimiento de contraseña nunca llega | SMTP o `http.external_url` no están configurados. La solicitud se acepta sin enviar nada. | Configura `[notify.smtp].host` y `[http].external_url`. |
| Un script que inicia sesión y envía `Authorization: Bearer` recibe `401` | El inicio de sesión establece cookies de sesión para la interfaz web y no devuelve ningún token. El encabezado solo acepta tokens de API. | Emite un token de API para el script. Consulta [Tokens de API](/es/identity/tokens). |
| La interfaz web pide iniciar sesión de nuevo cada día | Una sesión de inicio de sesión finaliza tras `[auth].session_ttl_secs` (24 horas). | Aumenta `[auth].session_ttl_secs`. |

## Envío de datos

| Síntoma | Causa | Solución |
|---|---|---|
| `401` | Falta el token, no es válido o el encabezado lleva un token de sesión de inicio de sesión. | Envía `Authorization: Bearer <token>` con un token de ingesta predeterminado o un token de cuenta de servicio. |
| `403` | Al token le falta el permiso de escritura de la señal, como `logs.write`, por ejemplo, un token de cliente de RUM enviado a una ruta de ingesta. | Usa un token con el permiso de escritura de la señal. |
| `413` | El cuerpo de la solicitud supera el límite del endpoint: 16 MiB para la ingesta JSON nativa y 2 MiB para las demás. | Envía lotes más pequeños. Aumenta el límite del proxy al menos hasta el límite del endpoint. |
| `400` de un endpoint de OTLP sobre HTTP | El emisor comprimió el cuerpo. | Configura `compression: none` en el exportador de OpenTelemetry Collector. |
| `404` de un endpoint de OTLP sobre HTTP | El endpoint del exportador omite la ruta base `/api`, por lo que las solicitudes van a `/v1/logs`. | Usa `http://host:5080/api` como endpoint de OTLP. |
| `429` con `Retry-After` | Se aplica el límite de frecuencia del rol `router` para la organización. | Reduce la velocidad o aumenta `[router.rate_limit]`. |
| El JSON nativo informa registros `rejected` | Un valor de campo no coincide con el esquema del flujo, por ejemplo, `type mismatch on field level: expected Utf8, got Number`. La respuesta indica el motivo por índice. Los números con fracción en un campo `int64` no están entre ellos: el campo pasa a ser `float64`. | Envía el tipo que el flujo ya almacena para el campo. |
| `400` con `event #1 must be a JSON object` | El arreglo contiene un elemento que no es un objeto JSON. Se rechaza toda la solicitud. | Envía un arreglo de objetos. |
| Promtail o Grafana Alloy no pueden enviar | El endpoint de Loki solo decodifica JSON y estos emisores usan protobuf comprimido con snappy. | Envía a través de OpenTelemetry Collector, Vector o Fluent Bit. |
| Se aceptan los registros, pero no se encuentran | La consulta usa otro nombre de flujo u otro tipo, o un intervalo de tiempo que los excluye. | Revisa el nombre del flujo y el tipo de señal. Consulta la siguiente sección para las marcas de tiempo. |

## Datos ausentes o anómalos

- **Marcas de tiempo.** `_timestamp` cuenta microsegundos desde la época Unix. Un valor en segundos, milisegundos o nanosegundos sitúa los eventos en el año equivocado o en un futuro lejano, y las consultas sobre el periodo reciente no los devuelven. Omite `_timestamp` para usar la hora de recepción del servidor.
- **Intervalo de tiempo.** Una consulta que abarca un intervalo largo se convierte en un trabajo asíncrono. Usa un `timeRange` acotado para consultas interactivas. Consulta [Consulta](/es/query#rangos-de-tiempo-y-tareas-asincrónicas).
- **Retención.** Se eliminan los datos más antiguos que la retención del flujo, o que la retención predeterminada de la plataforma en **Configuración → Retención de datos** para un flujo sin retención propia.
- **Tipo de flujo.** Un flujo se identifica por nombre y tipo. `default` puede existir para logs, métricas y trazas a la vez.

## Consultas

| Síntoma | Causa | Solución |
|---|---|---|
| La respuesta es `202` con un `jobId` y una ruta `monitor` | El tamaño estimado alcanza `[querier].auto_async_threshold_rows`, por lo que la consulta se ejecuta como un trabajo de búsqueda asíncrono. Con los valores predeterminados, eso es un intervalo de aproximadamente 13,9 horas o más. | Solicita la ruta `monitor` hasta que termine el trabajo y luego obtén sus `/results`. O reduce el intervalo de tiempo, o envía `Prefer: respond-sync`. Consulta [Consulta](/es/query#rangos-de-tiempo-y-tareas-asincrónicas). |
| El cliente de Flight SQL no puede conectarse | `[flight_sql]` está deshabilitado de forma predeterminada. | Configura `enabled = true`, expón el puerto `5083` y autentica con un token de API. |

## Operaciones

| Síntoma | Causa | Solución |
|---|---|---|
| `GET /api/v1/healthz` devuelve `503` | El almacén de objetos no es accesible. El cuerpo incluye un `reason`. | Corrige la conexión del almacén de objetos. |
| El directorio WAL crece | Los volcados fallan, normalmente porque el almacén de objetos no es accesible. | Corrige el almacén de objetos. La ingesta vuelca el backlog después. |
| La ingesta responde `429` con `intake buffer memory limit exceeded` | Los búferes del proceso contienen más de `[intake].max_buffer_memory_size`, normalmente porque los volcados siguen fallando. | Busca la causa en las líneas de log `intake flush failed` y corrige el almacén de objetos o la base de datos. Las filas que nunca se pueden publicar dejan de contar para el límite (consulta las dos filas siguientes). La ingesta JSON nativa envía `Retry-After` con esta respuesta; vuelve a intentarlo tras ese retardo. |
| El log muestra `dataset no longer exists; buffered rows discarded` | Se eliminó un flujo, o se eliminó y se volvió a crear, mientras aún quedaban filas suyas en el búfer. Esas filas no tienen destino, así que la ingesta las descarta y libera su memoria. El contador `intake_flush_errors_total` registra cada descarte bajo el paso `stream_gone` o `dataset_gone`. | No hay nada que corregir. Vuelve a enviar los datos si es importante. |
| Las escrituras responden `503` con `fenced by a newer writer epoch` | Otro proceso publica el mismo conjunto de datos con el mismo `[node].id`. El proceso cercado no puede publicar sus datos, descarta las filas que tiene en memoria y rechaza las escrituras a ese conjunto de datos. Su WAL permanece en disco. El contador `intake_flush_errors_total` registra el cercado bajo el paso `writer_fenced`. | Asigna a cada proceso un `[node].id` único y reinicia el proceso cercado. Consulta [Despliegue basado en roles](/es/deployment/role-based). |
| Fallan los informes programados en PDF o PNG | Falta Chrome o `[scheduled_reports.renderer].base_url` no llega a la interfaz web. | Usa la imagen de la versión, que incluye Chromium, y define `base_url` con la dirección de la interfaz web a la que puede llegar el nodo. |
| Los fragmentos de incorporación muestran el host incorrecto | `http.external_url` está vacío detrás de un proxy. | Define `[http].external_url` con la dirección pública y reinicia. |
| Las consultas responden `503` con `no querier node is available` | Ningún nodo con el rol `querier` tiene un latido reciente. | Inicia un nodo `querier` y comprueba que su `advertise_addr` sea accesible desde el enrutador. Consulta [Despliegue basado en roles](/es/deployment/role-based#membresía-del-clúster). |
| Las escrituras a través del enrutador responden `503` con `no intake node is available` | Ningún nodo con el rol `intake` tiene un latido reciente. | Inicia un nodo `intake` y comprueba su `advertise_addr`. Consulta [Despliegue basado en roles](/es/deployment/role-based#membresía-del-clúster). |
| Las solicitudes responden `503` con `no metadata database connection` | El nodo esperó 10 segundos una conexión a PostgreSQL y no obtuvo ninguna: PostgreSQL está sobrecargado o no es accesible, o todas las conexiones de `[meta_database].max_connections` están en uso. | Vuelve a intentar la solicitud. Si sigue ocurriendo, comprueba primero la carga y la accesibilidad de PostgreSQL. Si PostgreSQL está inactivo, aumenta `[meta_database].max_connections` según la carga, dentro del `max_connections` de PostgreSQL. |
| El puerto gRPC de OTLP no es accesible desde el host | El archivo de Compose no publica el puerto `4317`. | Agrega una asignación `4317:4317`. |
