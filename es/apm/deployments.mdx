La sección **Despliegues** de la página de un servicio reúne dos fuentes: los despliegues que
reportan los pipelines y las versiones que los spans del servicio incluyen en `service.version`. Una versión
aparece en función de los spans aunque ningún pipeline la haya reportado.

## Cronología de despliegues

La cronología enumera los eventos del servicio en el intervalo seleccionado, del más reciente al más antiguo:

| Evento | Cuándo |
|---|---|
| **Desplegado** | Un pipeline reportó un despliegue exitoso. |
| **Fallido** | Un pipeline reportó un despliegue fallido. Un despliegue fallido no cambia la versión en ejecución. |
| **Revertido** | Un pipeline reportó una reversión o el despliegue de una versión que se ejecutó antes que otra. La fila indica desde qué versión se hizo la reversión. |
| **Volvió a la versión anterior** | Los spans volvieron a mostrar una versión anterior que ningún pipeline reportó: la última versión observada apareció por primera vez antes que una versión más reciente que dejó de aparecer hace más de cinco minutos. |
| **Primera aparición** | Los spans incluyeron una versión que ningún pipeline reportó. |
| **Configuración** | Un pipeline o una herramienta reportó un cambio de configuración. La descripción aparece en la fila. |
| **Indicador de funcionalidad** | Un pipeline o una herramienta reportó un cambio en un indicador de funcionalidad. La descripción aparece en la fila. |

Un cambio de configuración o de un indicador de funcionalidad no altera la versión en ejecución ni tiene métricas
propias. Aparece entre los cambios cercanos a un hallazgo. Consulta
[Cambios cercanos a un hallazgo](/es/apm/insights#cambios-cercanos-a-un-hallazgo).

Cada despliegue reportado muestra el commit, la solicitud de incorporación de cambios, la ejecución de CI y el autor. Si el repositorio tiene una
dirección http o https, el commit se abre en su página web con el formato de enlace a commits que usa
GitHub, GitLab o Bitbucket.

La fila más reciente de cada versión muestra las solicitudes, la tasa de errores y el p95 del intervalo, junto con el resultado
de la comparación con la versión cuya primera aparición fue inmediatamente anterior:

| Resultado | Cuándo |
|---|---|
| **Reaparecido** | La tasa de errores subió al menos un punto porcentual y alcanzó al menos 1,5 veces su valor anterior, o el p95 subió al menos un 20 % y al menos 50 ms. Después del resultado se indica qué métrica empeoró. |
| **Mejoró** | Una de las dos métricas bajó lo suficiente para alcanzar esos mismos umbrales y ninguna empeoró. |
| **Sin cambios** | Ninguna de las dos métricas alcanzó esos umbrales. |
| **Solicitudes insuficientes** | Al menos una de las versiones atendió menos solicitudes que el mínimo necesario para compararlas: 1000 de forma predeterminada. |

Al seleccionar un resultado, se abren las dos versiones en **Comparar dos versiones**, donde aparecen los endpoints que
se volvieron más lentos y los errores que aumentaron. La vista general también marca las versiones que empeoraron o mejoraron entre los
despliegues recientes.

## Versiones canario

Cuando se ejecutan dos versiones a la vez, como una versión canario y la versión que reemplaza, una tarjeta encima de la
cronología las muestra en paralelo. Dos versiones se consideran simultáneas si ambas aparecieron en los cinco minutos previos al
último span del servicio. La tarjeta compara las dos versiones más recientes desde la primera aparición
de la más nueva:

- la proporción de solicitudes que atendió cada versión;
- las solicitudes, la tasa de errores, el p50, el p95 y el p99 de cada versión;
- el resultado de comparar la versión más reciente con la anterior.

## Reporta despliegues desde CI

Un pipeline reporta un despliegue con `POST /api/v1/apm/deployments`. La solicitud requiere un token de API
con el permiso `apm.deploy`. Los roles de propietario, administrador y editor tienen este permiso. La política de **Ingesta de datos**
que se aplica a los tokens de ingesta también lo incluye.

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "version": "2.4.0", "commit": "9f2c1e7a4b3d", "repository": "https://github.com/acme/checkout", "ciUrl": "https://ci.example.com/runs/7"}'
```

| Campo | Obligatorio | Descripción |
|---|---|---|
| `service` | Sí | El nombre del servicio tal como aparece en `service.name` en sus spans. Hasta 255 caracteres. |
| `version` | Para un despliegue | La versión desplegada tal como aparece en `service.version` en sus spans. Hasta 192 caracteres. |
| `kind` | No | `deployment` (valor predeterminado), `configuration` o `feature_flag`. |
| `namespace` | No | El `service.namespace` del servicio. Un despliegue sin espacio de nombres aparece en todos los espacios de nombres. |
| `environment` | No | El entorno, tal como figura en `deployment.environment.name`. Un despliegue sin entorno aparece en todos los entornos. |
| `status` | No | `succeeded` (valor predeterminado), `failed` o `rolled_back` si el despliegue restauró el servicio a la versión indicada en `version`. |
| `commit` | No | El commit desplegado: hasta 64 letras y dígitos. |
| `repository` | No | La ubicación del código: una dirección https, http, ssh o git de hasta 512 caracteres. El sistema guarda la contraseña de la dirección como `****` y hace lo mismo con el nombre de usuario de una dirección https. |
| `pullRequest` | No | Un enlace http o https a la solicitud de incorporación de cambios. |
| `author` | No | El autor del despliegue, hasta 128 caracteres. |
| `ciUrl` | No | Un enlace http o https a la ejecución de CI. |
| `description` | No | Hasta 1000 caracteres. Aparece al colocar el puntero sobre el evento. |
| `deployedAt` | No | El momento del despliegue, en microsegundos desde el inicio de la época Unix. De forma predeterminada, es el momento en que llega la solicitud. |

Usa los nombres de servicio y entorno que muestra APM: las reglas de nomenclatura, la asignación de
entornos y los alias de la organización se aplican igual que a los spans. Consulta
[Configuración de APM](/es/apm/settings).

La página **Fuente de datos** muestra los pasos siguientes en **GitHub Actions**, **GitLab CI/CD** y
**Jenkins**, con la dirección del espacio de trabajo ya completada.

### GitHub Actions

Guarda el token como secreto del repositorio y agrega un paso a la tarea de despliegue. `if: always()`
también reporta los despliegues fallidos.

```yaml
- name: Report the deployment to MoleSignal
  if: always()
  env:
    MOLESIGNAL_TOKEN: ${{ secrets.MOLESIGNAL_TOKEN }}
    DEPLOY_STATUS: ${{ job.status == 'success' && 'succeeded' || 'failed' }}
  run: |
    cat > deployment.json <<EOF
    {
      "service": "checkout",
      "environment": "production",
      "version": "${GITHUB_SHA::12}",
      "status": "$DEPLOY_STATUS",
      "commit": "$GITHUB_SHA",
      "repository": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY",
      "author": "$GITHUB_ACTOR",
      "ciUrl": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID"
    }
    EOF
    curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
      -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
      -H "Content-Type: application/json" \
      --data-binary @deployment.json
```

### GitLab CI/CD

Agrega el token como variable enmascarada de CI/CD con el nombre `MOLESIGNAL_TOKEN`. Luego reporta el despliegue desde el bloque
`after_script` de la tarea de despliegue, que se ejecuta tanto si el despliegue tiene éxito como si falla.

```yaml
deploy:
  stage: deploy
  environment: production
  script:
    - ./deploy.sh
  after_script:
    - |
      if [ "$CI_JOB_STATUS" = "success" ]; then DEPLOY_STATUS=succeeded; else DEPLOY_STATUS=failed; fi
      cat > deployment.json <<EOF
      {
        "service": "checkout",
        "environment": "$CI_ENVIRONMENT_NAME",
        "version": "$CI_COMMIT_SHORT_SHA",
        "status": "$DEPLOY_STATUS",
        "commit": "$CI_COMMIT_SHA",
        "repository": "$CI_PROJECT_URL",
        "author": "$GITLAB_USER_LOGIN",
        "ciUrl": "$CI_PIPELINE_URL"
      }
      EOF
      curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
        -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
        -H "Content-Type: application/json" \
        --data-binary @deployment.json
```

### Jenkins

Agrega el token como credencial de tipo **Secret text** con el ID `molesignal-token`. Luego reporta el despliegue en el bloque
`post` del pipeline. `post { always }` también reporta las compilaciones fallidas. Si `GIT_URL` contiene una contraseña,
el sistema la enmascara al guardar el despliegue.

```groovy
post {
  always {
    script {
      writeFile file: 'deployment.json', text: groovy.json.JsonOutput.toJson([
        service: 'checkout',
        environment: 'production',
        version: env.GIT_COMMIT.take(12),
        status: currentBuild.currentResult == 'SUCCESS' ? 'succeeded' : 'failed',
        commit: env.GIT_COMMIT,
        repository: env.GIT_URL,
        ci_url: env.BUILD_URL,
      ])
    }
    withCredentials([string(credentialsId: 'molesignal-token', variable: 'MOLESIGNAL_TOKEN')]) {
      sh '''
        curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
          -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
          -H "Content-Type: application/json" \
          --data-binary @deployment.json
      '''
    }
  }
}
```

## Reporta cambios de configuración e indicadores de funcionalidad

Reporta un cambio de configuración o de un indicador de funcionalidad mediante el mismo endpoint. Define `kind` e incluye una
descripción del cambio. No hace falta indicar una versión.

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "kind": "feature_flag", "description": "new_checkout on for 10% of users"}'
```

## Solución de problemas

| Síntoma | Qué revisar |
|---|---|
| Un despliegue reportado no aparece en la cronología | El intervalo debe incluir `deployedAt` y `service` debe coincidir con el nombre del servicio en APM. Si se reportó un entorno para el despliegue, este solo aparece en ese entorno. |
| Un despliegue y su versión aparecen en filas separadas | El valor de `version` reportado no coincide con el de `service.version` en los spans. Reporta el mismo valor. |
| El endpoint de despliegues devuelve `403` | El token no tiene acceso a `apm.deploy`: su alcance no lo incluye o el miembro o la cuenta de servicio asociados carecen de ese permiso. |
| El endpoint de despliegues devuelve `400` | Un campo no cumple un límite de la tabla anterior. El error indica qué campo es. |
