## Cómo se ejecuta un cambio

Un comando que realiza un cambio, como acusar recibo de un incidente, se lo solicita a MoleSignal mediante una
herramienta administrada, al igual que Mole Agent y las herramientas del agente. La política de herramientas de la organización define cómo se ejecuta cada
herramienta en **Mole Agent → Configuración → Herramientas y capacidades**:

| Modo de ejecución | Qué hace el comando |
|---|---|
| Automática | El cambio se ejecuta de inmediato. |
| Confirmación | MoleSignal solicita confirmación y el comando la pide en la terminal. `-y` (`--yes`) responde que sí de antemano, por ejemplo, en CI. Sin terminal ni `--yes`, no se aplica ningún cambio. |
| Aprobación única, aprobación doble | MoleSignal abre una solicitud para que se revise en **Mole Agent → Aprobaciones**. El comando muestra la solicitud y termina con el código `3`. Con `--wait`, espera la decisión hasta el límite de `--timeout` (30 minutos de forma predeterminada) y aplica el cambio si se aprueba. |
| Desactivada | El comando falla e indica el motivo. |

Si una herramienta no tiene una política propia, se ejecuta según su nivel de riesgo: los modos predeterminados son confirmación para
`create_annotation` y `submit_search_job`, y aprobación única para `acknowledge_incident`,
`resolve_incident` y `run_synthetic_monitor`. `--reason` indica el motivo para la revisión y el
registro de auditoría.

La confirmación requiere la revisión 2026-07-28 del protocolo MCP. La CLI usa esa revisión si MoleSignal también la usa.
`molesignal status` indica qué revisión está en uso.

## Lista los incidentes

```bash
molesignal incidents
```

La lista muestra los incidentes activos, del más reciente al más antiguo, con su estado, gravedad, antigüedad, servicios
y resumen. `--status resolved` o `--status all` permite ver otros incidentes, `--since 7d` muestra solo los que se abrieron
desde entonces y `-n` define cuántos se muestran.

`molesignal incidents show` muestra los detalles de un incidente: su regla, marcas de tiempo, servicios, etiquetas, notas como
el manual operativo y las trazas muestreadas. `--rca` agrega el análisis de causa raíz y `--web` abre el
incidente en MoleSignal:

```bash
molesignal incidents show <incident> --rca
```

## Acusa recibo de los incidentes y resuélvelos

```bash
molesignal incidents ack <incident>
```

```bash
molesignal incidents resolve <incident> --reason "Rolled back to 2.3.9"
```

Ambos comandos se rigen por la política de herramientas y requieren `alerts.incidents.acknowledge`.

## Consulta quién está de guardia

```bash
molesignal oncall
```

La lista muestra quién está de guardia en cada calendario de guardias habilitado. `--schedule` filtra por un solo calendario
y `--at` permite consultar otro momento, por ejemplo, `--at "2026-10-27 09:00"`.

## Aplica los cambios aprobados

`molesignal approvals` lista las solicitudes de Mole Agent, las herramientas del agente y los comandos que están pendientes de revisión o que ya se aprobaron pero
aún no se ejecutaron. `--all` incluye las solicitudes sobre las que ya se tomó una decisión
también.

```bash
molesignal approvals
```

`molesignal approvals show <approval>` muestra los detalles de una solicitud: su acción, objetivo, motivo, impacto y
revisiones. `molesignal approvals execute <approval>` aplica un cambio aprobado. MoleSignal puede
pedir confirmación antes de aplicarlo:

```bash
molesignal approvals execute <approval>
```

## Agrega anotaciones a los paneles

`molesignal annotate` agrega una anotación en un momento concreto o durante un intervalo, en todos los paneles
o en uno solo:

```bash
molesignal annotate "Release 2.4.0" --tags release,checkout --yes
```

| Opción | Significado |
|---|---|
| `--description <text>` | Detalles de la anotación. |
| `--tags <a,b>` | Etiquetas para encontrar la anotación. |
| `--dashboard <id>` | Limita la anotación a este panel. |
| `--stream <stream>` | Flujo al que se refiere la anotación. |
| `--time <time>`, `--end <time>` | Inicio y fin. De forma predeterminada, la anotación marca el momento actual. |

Para agregar una anotación, se requiere `dashboards.edit`.

## Ejecuta comprobaciones sintéticas

`molesignal synthetics` lista las comprobaciones con su tipo, estado y ciclo de vida.
`molesignal synthetics results <check>` lista las últimas ejecuciones de una comprobación en cada ubicación, con su
resultado, duración y el motivo de los fallos. Usa el ID o el nombre para identificar la comprobación.

`molesignal synthetics run` ejecuta de inmediato una comprobación en cada una de sus ubicaciones. Con `--wait`, el comando
espera a que terminen las ejecuciones y sale con el código `1` si alguna falla o no termina dentro del plazo de `--timeout`
(10 minutos de forma predeterminada). Así, un pipeline puede detener un lanzamiento en ese caso:

```bash
molesignal synthetics run "Checkout API" --wait --yes
```

Una ejecución se considera válida si el resultado es correcto o intermitente. Para ejecutar una comprobación, se requiere `synthetics.monitors.manage`. Para
ejecutar comprobaciones desde CI sin revisión, selecciona **Automática** como modo de `run_synthetic_monitor` en la política de
herramientas.
