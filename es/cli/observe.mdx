## Consultar métricas

`molesignal metrics query` ejecuta una consulta de rango en PromQL e imprime una línea por serie: su último valor,
su mínimo y su máximo en el intervalo, un minigráfico y sus etiquetas.

```bash
molesignal metrics query 'sum by (service) (rate(http_server_requests_total[5m]))' --since 6h
```

```text
LAST   MIN    MAX    TREND                           SERIES
12.4   3.1    14.9   ▁▂▂▃▅▆▇█▇▆▆▅▅▆▇▇█▇▆▅▄▄▅▅▆▆▇▇▇▆   {service="checkout"}
```

El intervalo abarca la última hora de forma predeterminada. Cámbialo con `--since`, `--from` y `--to`. `-n` limita la
cantidad de puntos a `1000` de forma predeterminada. `--json` imprime cada serie con sus puntos y `--csv` imprime los
puntos como filas.

Usa estos cuatro subcomandos para encontrar qué consultar:

| Comando | Qué lista |
|---|---|
| `molesignal metrics names [text]` | Los nombres de métricas que contienen el texto indicado. |
| `molesignal metrics labels <metric>` | Las etiquetas de una métrica. |
| `molesignal metrics values <metric> <label>` | Los valores de una etiqueta y cuántas veces aparece cada uno. |
| `molesignal metrics series <metric>` | Las series de una métrica. Usa `--match label=value` para filtrarlas. |

## Buscar trazas

```bash
molesignal traces --service checkout --errors --since 6h
```

La lista muestra las trazas más recientes con su hora de inicio, duración, cantidad de spans y servicio.

| Opción | Significado |
|---|---|
| `--service <name>` | Solo las trazas de este servicio. |
| `--errors` | Solo las trazas con algún span que falló. |
| `--min-duration <time>` | Solo las trazas que duraron al menos el tiempo indicado, por ejemplo, `500ms`. |
| `--since`, `--from`, `--to` | El intervalo, que abarca la última hora de forma predeterminada. |
| `-n`, `--limit <count>` | La cantidad de trazas: `20` de forma predeterminada y `200` como máximo. |

## Visualizar una traza

`molesignal traces show` muestra una traza en un gráfico de cascada: coloca cada span en una línea debajo de su span principal,
con una barra que indica cuándo se ejecutó dentro de la traza y cuánto duró. El comando marca los spans que fallaron con
`!` y los muestra en rojo en la terminal.

```bash
molesignal traces show 4bf92f3577b34da6a3ce929d0e0e4736
```

```text
checkout POST /orders          ████████████████████████████████████████  1.24s
├─ checkout SELECT orders       ███                                       98ms
└─ ! payments POST /charge         ███████████████████████████████████    1.1s
```

`--web` abre la traza en MoleSignal y `--json` imprime sus spans.

## Resumir servicios

```bash
molesignal services --env production --sort errors
```

La lista muestra cada servicio de APM con sus solicitudes, tasa de errores, latencia p95, estado y
versión actual. `--sort` ordena la lista por `requests`, `errors`, `p95` o `name`.

`molesignal services show` resume un servicio: primero muestra la tasa de solicitudes, los errores y la latencia; después, los
endpoints, las dependencias, los errores y las versiones:

```bash
molesignal services show checkout --since 2h
```

## Comparar dos versiones

`molesignal services compare` compara dos versiones de un servicio e indica si la
versión candidata empeoró, mejoró, se mantuvo igual o recibió muy pocas solicitudes para sacar una conclusión. Con
`--fail-on-regression`, el comando devuelve `1` si detecta una regresión, lo que permite que un pipeline detenga la
publicación:

```bash
molesignal services compare checkout 2.3.9 2.4.0 --since 1h --fail-on-regression
```

## Ejecutar consultas largas como trabajos de búsqueda

Un trabajo de búsqueda ejecuta una consulta en segundo plano sobre más datos y un intervalo más amplio que una consulta
inmediata, y conserva el resultado durante un tiempo. Tanto el envío como la cancelación del trabajo deben cumplir la
política de herramientas de la organización, como cualquier cambio. Consulta
[Incidentes y cambios](/es/cli/changes#cómo-se-ejecuta-un-cambio).

```bash
molesignal search-jobs submit "SELECT * FROM app_logs WHERE level = 'error'" --since 30d --wait
```

El comando usa el primer flujo que aparece después de `FROM`. Usa `--stream` para indicar otro y `--promql` para enviar una
consulta PromQL que se evalúa al final del intervalo o a cada paso indicado con `--step`, por ejemplo, `1m`. `--limit` limita
las filas que conserva el trabajo a un máximo de `100000` y `--keep` define cuánto tiempo las conserva. Usa `--wait` para esperar a que
termine el trabajo. El comando imprime el ID del trabajo.

| Comando | Efecto |
|---|---|
| `molesignal search-jobs` | Lista los trabajos de búsqueda con su estado, cantidad de filas y consulta. |
| `molesignal search-jobs show <job>` | Imprime el estado, la cantidad de filas, los tiempos y el error de un trabajo. |
| `molesignal search-jobs results <job>` | Escribe las filas de un trabajo finalizado, con un objeto JSON por línea. Usa `--csv` para escribir en CSV y `-o <file>` para escribir en un archivo. |
| `molesignal search-jobs cancel <job>` | Cancela un trabajo pendiente o en ejecución. |

## Acceso

Las métricas requieren `streams.query`, las trazas `traces.read`, APM `apm.services.read` y los trabajos de búsqueda `query.jobs.read` y
`query.jobs.run`. `sys.telemetry.read` permite leer todos estos datos en el ámbito `_sys`. La política de herramientas de la organización debe mantener
habilitadas las herramientas.
