`molesignal <command> --help` muestra la misma información para un solo comando.

## Opciones de cada comando

Todos los comandos que se comunican con MoleSignal aceptan estas opciones:

| Opción | Significado |
|---|---|
| `--profile <name>` | La sesión guardada que se usará. Consulta [Conserva varias sesiones](/es/cli/sign-in#mantén-varias-sesiones). |
| `--url <address>` | La dirección de MoleSignal, en lugar de la del perfil. |
| `--token <token>` | Un token de API solo para este comando. |

Para indicar un momento, usa una fecha y hora en formato ISO, una fecha y hora local como `2026-10-26 14:00`, una cantidad de
segundos, milisegundos o microsegundos desde la época Unix, o una duración hacia atrás desde el momento actual. Una duración
consta de un número y una unidad: `ms`, `s`, `m`, `h`, `d` o `w`.

## Inicio de sesión

| Comando | Opciones | Descripción |
|---|---|---|
| `login` | `--url <address>`, `--profile <name>`, `--with-token` | Inicia sesión en el navegador o con un token de API desde la entrada estándar. El perfil pasa a ser el activo. |
| `logout` | `--profile <name>` | Elimina la sesión guardada del perfil y conserva su dirección. |
| `profiles` | `--json` | Enumera los perfiles. `profiles remove <name>` elimina un perfil. |
| `use <profile>` | ninguna | Activa un perfil. |
| `status` | ninguna | Muestra la dirección, el perfil, el servidor, la revisión del protocolo MCP, el tipo de inicio de sesión y la cantidad de herramientas. |
| `whoami` | `--json` | Muestra la cuenta de usuario, la organización, el rol y los permisos. |
| `doctor` | ninguna | Comprueba Node.js, la configuración, la dirección, el proxy, la red y TLS, el reloj, el inicio de sesión y el punto de conexión de MCP. |

## Registros y consultas

| Comando | Opciones | Descripción |
|---|---|---|
| `streams` | `--type <type>`, `--names`, `--json` | Enumera los flujos de un tipo, `logs` de forma predeterminada. |
| `logs <stream>` | `-f`, `-n`, `-q`, `--where`, `--since`, `--from`, `--to`, `--fields`, `--around`, `-B`, `-A`, `--interval`, `--json`, `--utc`, `--web` | Muestra los registros más recientes de un flujo. Con `-f`, muestra también los nuevos conforme llegan. Consulta [Lee y sigue los registros](/es/cli/logs). |
| `query "<SQL>"` | `--stream`, `--since`, `--from`, `--to`, `-n`, `--csv`, `--json`, `--utc`, `--web` | Ejecuta una sentencia SQL de solo lectura en un flujo de registros. |
| `fields <stream> [field]` | `--type`, `--since`, `--from`, `--to`, `-n`, `--match`, `--json` | Enumera los campos de un flujo o los valores más frecuentes de un campo. |

### Opciones de `logs`

| Opción | Valor predeterminado | Significado |
|---|---|---|
| `-f`, `--follow` | desactivado | Sigue mostrando los nuevos registros hasta que presiones **Ctrl+C**. |
| `-n`, `--lines <count>` | `100` | Cantidad de registros recientes que se muestran al inicio, de `1` a `5000`. |
| `-q`, `--query <query>` | ninguno | Consulta por campos con la misma sintaxis que en la página **Registros**. |
| `--where <condition>` | ninguno | Condición SQL sobre los campos del flujo. |
| `--since <duration>` | `15m` | Cuánto tiempo hacia atrás abarca la consulta. |
| `--from <time>`, `--to <time>` | ninguno | Intervalo en lugar de `--since`. No combines `--to` con `-f`. |
| `--fields <a,b,c>` | todos | Muestra la marca de tiempo y solo los campos indicados. |
| `--around <time>` | ninguno | Muestra los registros inmediatamente anteriores y posteriores a un momento. |
| `-B`, `--before <count>` | `10` | Con `--around`: cantidad de registros anteriores a ese momento, hasta `250`. |
| `-A`, `--after <count>` | `10` | Con `--around`: cantidad de registros posteriores a ese momento, hasta `250`. |
| `--interval <duration>` | `2s` | Frecuencia de lectura durante el seguimiento. |
| `--json` | desactivado | Muestra cada registro en una línea de JSON. |
| `--utc` | desactivado | Muestra las marcas de tiempo en UTC. |
| `--web` | desactivado | Abre los registros en la página **Registros** en lugar de mostrarlos en la terminal. |

## Métricas, trazas y servicios

| Comando | Opciones | Descripción |
|---|---|---|
| `metrics query '<PromQL>'` | `--since`, `--from`, `--to`, `-n`, `--csv`, `--json` | Ejecuta una consulta de rango en PromQL y muestra una línea por serie con un minigráfico. |
| `metrics names [text]`, `metrics labels <metric>`, `metrics values <metric> <label>`, `metrics series <metric>` | `-n`, `--match <label=value>`, `--json` | Enumera los nombres de las métricas, las etiquetas, los valores de las etiquetas y las series. |
| `traces` | `--service`, `--errors`, `--min-duration`, `--since`, `--from`, `--to`, `-n`, `--json` | Enumera las trazas recientes. |
| `traces show <trace>` | `--since`, `--from`, `--to`, `--json`, `--web` | Muestra una traza en un diagrama de cascada. |
| `services` | `--env`, `--namespace`, `--sort`, `--since`, `--from`, `--to`, `-n`, `--json` | Enumera los servicios de APM y su estado. |
| `services show <service>` | `--env`, `--namespace`, `--since`, `--json`, `--web` | Muestra un resumen de un servicio. |
| `services compare <service> <baseline> <candidate>` | `--env`, `--since`, `--fail-on-regression`, `--json` | Compara dos versiones. |
| `search-jobs` | `-n`, `--json` | Enumera las tareas de búsqueda. |
| `search-jobs submit "<statement>"` | `--stream`, `--type`, `--promql`, `--step`, `--since`, `--from`, `--to`, `--limit`, `--keep`, `--wait`, opciones de cambio | Envía una tarea de búsqueda. |
| `search-jobs show <job>`, `search-jobs results <job>`, `search-jobs cancel <job>` | `-o <file>`, `--csv`, `--json`, opciones de cambio | Muestra una tarea, escribe las filas de sus resultados o la cancela. |

## Guardias y cambios

| Comando | Opciones | Descripción |
|---|---|---|
| `incidents` | `--status`, `--since`, `-n`, `--json` | Lista los incidentes. De forma predeterminada, solo muestra los activos. |
| `incidents show <incident>` | `--rca`, `--json`, `--web` | Muestra un incidente. |
| `incidents ack <incident>`, `incidents resolve <incident>` | opciones de cambio | Confirma la recepción de un incidente o lo resuelve. |
| `incidents create --title <text>` | `--description`, `--severity`, `--priority`, `--urgency`, `--service`, `--label`, `--team`, `--policy`, `--user`, `--major`, `--json`, opciones de cambio | Abre manualmente un incidente por un problema que ninguna regla detectó. Lo enruta como una alerta, salvo que `--team`, `--policy` o `--user` (ID) indiquen a quién asignarlo. `--priority` y `--urgency` usan los niveles de la organización. Muestra el ID y el enlace del nuevo incidente. |
| `oncall` | `--schedule`, `--at`, `--json` | Muestra quién está de guardia. |
| `approvals` | `--all`, `-n`, `--json` | Lista las solicitudes de aprobación pendientes o aprobadas. |
| `approvals show <approval>`, `approvals execute <approval>` | `--json`, opciones de cambio | Muestra una solicitud o ejecuta un cambio aprobado. |
| `annotate "<title>"` | `--description`, `--tags`, `--dashboard`, `--stream`, `--time`, `--end`, opciones de cambio | Agrega anotaciones a los paneles. |
| `synthetics` | `--lifecycle`, `--json` | Lista las comprobaciones sintéticas. |
| `synthetics results <check>` | `--since`, `-n`, `--json` | Lista las ejecuciones más recientes de una comprobación. |
| `synthetics run <check>` | opciones de cambio | Ejecuta una comprobación de inmediato. Con `--wait`, espera a que terminen las ejecuciones. |
| `alerts rules export` | `--ids`, `-o`, `--output` | Exporta las reglas de alerta en un paquete. Con `--ids`, solo exporta las reglas indicadas. Consulta [Importación y exportación](/es/alerting/rules#importar-y-exportar). |
| `alerts rules apply -f <file>` | `--dry-run`, `--create-only`, `--json` | Aplica un paquete o un archivo de reglas de alerta de Prometheus (`-f -` lee la entrada estándar). Primero prueba las reglas y muestra qué haría cada una. Si ninguna falla, guarda todas en una sola operación. Si alguna falla, termina con el código 1 para CI. |
| `alerts policies export`, `alerts schedules export`, `alerts routing export` | `--ids`, `-o`, `--output` | Exporta políticas de escalamiento, horarios de guardia o reglas de enrutamiento en un paquete que identifica a los usuarios por su correo electrónico y a los demás elementos por su nombre. Consulta [Importación y exportación](/es/alerting/on-call#importación-y-exportación). |
| `alerts policies apply -f <file>`, `alerts schedules apply -f <file>`, `alerts routing apply -f <file>` | `--dry-run`, `--create-only`, `--json` | Aplica uno de estos paquetes del mismo modo que `alerts rules apply`. Aplica los horarios de guardia antes de las políticas que los usan para enviar avisos. Aplica las políticas antes de las reglas de alerta y de enrutamiento que las mencionan. |

Estas son las opciones de cambio. Consulta [Cómo se ejecuta un cambio](/es/cli/changes#cómo-se-ejecuta-un-cambio).

| Opción | Significado |
|---|---|
| `--reason <text>` | Motivo del cambio. Queda registrado junto con la aprobación y en el registro de auditoría. |
| `--wait` | Si el cambio requiere aprobación, espera a que se apruebe y luego lo ejecuta. |
| `--timeout <duration>` | Tiempo máximo de espera de `--wait`: `30m` de forma predeterminada y `10m` para `synthetics run`. |
| `-y`, `--yes` | Confirma de inmediato el cambio cuando MoleSignal solicita confirmación. |

Estos comandos requieren un token de API. Consulta [CI y versiones](/es/cli/ci).

## Variables de entorno

| Variable | Significado |
|---|---|
| `MOLESIGNAL_URL` | Dirección de MoleSignal que sustituye a `--url` o a la dirección guardada. |
| `MOLESIGNAL_TOKEN` | Token de API que sustituye a las credenciales guardadas. |
| `MOLESIGNAL_PROFILE` | Perfil que sustituye al actual. |
| `MOLESIGNAL_CONFIG` | Archivo que guarda los perfiles. El valor predeterminado es `~/.config/molesignal/config.json`. |
| `HTTPS_PROXY`, `HTTP_PROXY` | Proxy para todas las solicitudes. |
| `NO_PROXY` | Hosts a los que se accede sin usar el proxy. |
| `NODE_EXTRA_CA_CERTS` | Autoridad de certificación de confianza adicional a las del sistema. |
| `NO_COLOR` | Muestra la salida sin colores. |
| `FORCE_COLOR` | Muestra colores aunque la salida no vaya a una terminal. |

Las opciones tienen prioridad sobre las variables de entorno, y las variables de entorno tienen prioridad sobre el perfil guardado.

## Códigos de salida

| Código | Significado |
|---|---|
| `0` | El comando se ejecutó correctamente o se detuvo un seguimiento. |
| `1` | El comando falló. El motivo aparece en la salida de error estándar. También indica que una ejecución sintética falló con `--wait`, que una versión presentó una regresión con `--fail-on-regression`, que `send` rechazó logs o que falló una comprobación de `doctor`. |
| `2` | Comando, opción o argumento desconocido. |
| `3` | El cambio está pendiente de aprobación y aún no se ha ejecutado. |

`deploy -- <command>` y `run` devuelven el código de salida del comando que ejecutan.
