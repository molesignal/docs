Los comandos de la CLI cubren las tareas habituales. Para ejecutar cualquier otra herramienta del catálogo de MoleSignal, como las
de RUM, análisis de perfiles o páginas de estado, usa `molesignal call`.

## Busca una herramienta

```bash
molesignal tools incident
```

La lista muestra las herramientas que mejor coinciden con los términos de búsqueda e indica qué hace cada llamada (`read` o
`change`), cómo se ejecuta un cambio según la política de herramientas de la organización y para qué sirve cada herramienta.
Si no indicas términos de búsqueda, el comando enumera todas las herramientas que puedes llamar. `--domain` limita la búsqueda a un dominio, como
`observability` o `alerts_on_call`.

`molesignal tools show` muestra una herramienta y los argumentos que acepta en formato JSON Schema:

```bash
molesignal tools show list_rum_sessions
```

## Llama a una herramienta

```bash
molesignal call list_rum_sessions --since 1h limit=20
```

El comando imprime en JSON el resultado de la herramienta. Escribe los argumentos así:

| Sintaxis | Valor que se envía |
|---|---|
| `name=value` | El valor con el tipo que exige el esquema de la herramienta: texto, un número, `true` o `false`, o una lista a partir de `a,b`. |
| `name:=json` | El JSON tal como lo escribes, por ejemplo, `match:='{"service":"checkout"}'`. |
| `parent.child=value` | Un campo dentro de un objeto, por ejemplo, `timeRange.startTime=…`. |
| `--input <file>` | Un objeto JSON con los argumentos de un archivo, o `-` para leerlos de la entrada estándar. Los pares que escribas después se agregan al objeto. |
| `--since`, `--from`, `--to` | Definen `timeRange` si la herramienta acepta ese argumento. |

Si una herramienta realiza cambios, se ejecuta conforme a la política de herramientas, como se describe en
[Cómo se ejecuta un cambio](/es/cli/changes#cómo-se-ejecuta-un-cambio). Puedes usar `--reason`, `--wait`, `--timeout` y
`--yes`. Si incluyes un argumento `reason` o `impact`, el comando lo envía sin cambios en la solicitud de aprobación.

```bash
molesignal call trigger_alert_rule rule_id=<rule> --reason "Testing the pager"
```

## Abre una página

`molesignal open` abre una página de MoleSignal en el navegador. Si no indicas ninguna, abre la página de inicio:

```bash
molesignal open logs app_logs
```

Las páginas son `home`, `logs`, `metrics`, `traces`, `services`, `incidents`, `oncall`,
`synthetics`, `dashboards`, `approvals`, `jobs`, `streams` y `agent`. La mayoría acepta un identificador, por ejemplo, el de
una traza, un incidente o un panel. En lugar de abrir la página, usa `--print` para imprimir su dirección.

Usa `--web` con `logs`, `query`, `traces show`, `incidents show` y `services show` para abrir en el navegador el resultado que
estos comandos imprimirían.

## Autocompleta comandos en el shell

`molesignal completion` imprime un script que autocompleta comandos, subcomandos, perfiles y nombres de
flujos. El script consulta los nombres de los flujos cada pocos minutos. Para bash:

```bash
echo 'source <(molesignal completion bash)' >> ~/.bashrc
```

Para zsh:

```bash
echo 'source <(molesignal completion zsh)' >> ~/.zshrc
```

Para fish:

```bash
molesignal completion fish > ~/.config/fish/completions/molesignal.fish
```
