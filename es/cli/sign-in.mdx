La CLI inicia sesión una sola vez y conserva la sesión para los comandos posteriores. Hay dos métodos disponibles:

| Método | Cuándo usarlo |
|---|---|
| Inicio de sesión en el navegador | Para iniciar sesión desde un equipo con navegador. Usa OAuth 2.1 y se renueva automáticamente. |
| Token de API | Para scripts, equipos de compilación y equipos sin navegador. |

El inicio de sesión en el navegador solo da acceso al endpoint MCP de MoleSignal. Para notificar despliegues, cargar
mapas de código fuente y símbolos, y enviar logs, la CLI usa la API de MoleSignal y requiere un token de API.

## Inicia sesión en el navegador

```bash
molesignal login --url https://molesignal.example.com
```

1. La CLI se registra en MoleSignal y abre la página de autorización de MoleSignal en el
   navegador predeterminado. Inicia sesión en MoleSignal si todavía no hay una sesión activa.
2. La página de autorización identifica el cliente, la cuenta y la organización, y enumera las
   acciones permitidas. Si la cuenta pertenece a varias organizaciones, selecciona una en **Organización**. El acceso queda
   limitado a esa organización.
3. Haz clic en **Autorizar**. El navegador devuelve el control a la CLI, que indica cuántas herramientas
   puede usar.

La CLI solicita los alcances `mcp` y `offline_access`, por lo que la sesión se renueva automáticamente hasta que se
revoca el acceso. La página de autorización espera cinco minutos. Después, el comando termina y la sesión anterior,
si existe, queda como estaba. Si se rechaza o se interrumpe el inicio de sesión, la sesión anterior también queda
intacta.

<Note>
  El navegador se conecta a un proceso que escucha en `http://127.0.0.1` solo mientras se ejecuta el comando.
  Cuando el comando termina, no queda ningún proceso a la escucha. Si accedes a un equipo remoto por SSH, el
  navegador no puede conectarse a ese proceso. En ese caso, inicia sesión con un token de API.
</Note>

## Inicia sesión con un token de API

Crea un token en **Identidad y acceso → Tokens de API** y luego pásalo por la entrada estándar:

```bash
printf '%s' "$MOLESIGNAL_TOKEN" | molesignal login --url https://molesignal.example.com --with-token
```

El token usa los permisos de la cuenta de usuario o de servicio a la que pertenece.

## Usa un token sin guardarlo

Configura la dirección y el token en el entorno, por ejemplo, en un equipo de compilación. La CLI no guarda nada:

```bash
MOLESIGNAL_URL=https://molesignal.example.com MOLESIGNAL_TOKEN=<token> molesignal status
```

`--url` y `--token` hacen lo mismo para un solo comando. La CLI nunca envía a otra dirección un token que guardó
para una dirección determinada.

## Mantén varias sesiones

La CLI guarda cada sesión en un perfil que contiene una dirección y el acceso correspondiente. Con varios perfiles, la CLI
puede mantener sesiones en varias instancias de MoleSignal o en varias organizaciones de una misma instancia.
`--profile` indica el perfil en el que se guarda la sesión:

```bash
molesignal login --url https://staging.molesignal.example.com --profile staging
```

El último perfil con el que iniciaste sesión pasa a ser el perfil actual. Los comandos usan el perfil actual;
`--profile` o `MOLESIGNAL_PROFILE` permiten elegir otro para un solo comando. Si inicias sesión por primera vez sin
`--profile`, la CLI guarda la sesión en el perfil `default`.

| Comando | Efecto |
|---|---|
| `molesignal profiles` | Enumera los perfiles, sus métodos de inicio de sesión y sus direcciones. `*` marca el perfil actual. |
| `molesignal use <profile>` | Establece un perfil como el actual. |
| `molesignal logout --profile <profile>` | Elimina la sesión guardada de un perfil y conserva su dirección. |
| `molesignal profiles remove <profile>` | Elimina un perfil. |

## Dónde guarda la CLI la sesión

La CLI guarda los perfiles en `~/.config/molesignal/config.json`. Solo el propietario del archivo puede leerlo. La
carpeta sigue la ruta de `XDG_CONFIG_HOME` si está definida y la de `%APPDATA%` en Windows.
`MOLESIGNAL_CONFIG` apunta a otro archivo.

## Trabaja detrás de un proxy

`HTTPS_PROXY` (o `HTTP_PROXY`) dirige todas las solicitudes de la CLI a través de un proxy, y `NO_PROXY`
enumera los hosts a los que la CLI accede sin pasar por el proxy:

```bash
HTTPS_PROXY=http://proxy.example.com:3128 NO_PROXY=localhost molesignal status
```

Si una autoridad de certificación privada emitió el certificado de MoleSignal, indica el certificado de esa autoridad
en `NODE_EXTRA_CA_CERTS`.

## Comprueba la sesión y la configuración

`molesignal status` muestra la dirección, el perfil, el servidor que respondió, la revisión del protocolo
MCP, el método de inicio de sesión y el número de herramientas de MCP:

```bash
molesignal status
```

`molesignal whoami` muestra la cuenta de usuario, la organización, el rol y los permisos que MoleSignal
otorga:

```bash
molesignal whoami
```

`molesignal doctor` comprueba cada requisito de la CLI e indica qué hacer si algo falla:
Node.js, los permisos del archivo de configuración, la dirección, el proxy, la red y TLS,
el reloj, la sesión y el endpoint MCP. El comando termina con el código `1` si alguna comprobación falla:

```bash
molesignal doctor
```

## Cierra una sesión

`molesignal logout` elimina la sesión guardada del perfil actual en este equipo:

```bash
molesignal logout
```

La autorización sigue vigente en MoleSignal hasta que la revoques en
**Mole Agent → Configuración → MCP entrante**.
