## Enumera los flujos

```bash
molesignal streams
```

La lista muestra cada flujo de registros que se puede leer con los permisos de la cuenta, junto con la cantidad de campos, el período de retención y
la descripción. `--type` enumera los flujos de otro tipo: `metrics`, `traces`, `profiles` o
`extend`. `--names` solo imprime los nombres y `--json` imprime un flujo por línea en JSON.

## Imprime los registros más recientes

```bash
molesignal logs app_logs
```

El comando imprime los 100 registros más recientes de los últimos 15 minutos, del más antiguo al más reciente, uno por línea:
la hora, el nivel, el servicio y el mensaje.

```text
2026-10-18 03:14:15.361 INFO  checkout order 4812 created
2026-10-18 03:14:25.361 ERROR payment gateway timeout after 3 retries
```

El comando lee el nivel de un campo como `level`, `severity` o `severity_text`; obtiene el servicio de
`service` o `service.name`, y el mensaje de `message`, `msg`, `body` o `log`. Si un registro
no tiene un campo de mensaje, el comando muestra los demás campos como `name=value`. La terminal muestra colores;
`NO_COLOR` los desactiva y `FORCE_COLOR` los conserva al canalizar la salida.

| Opción | Valor predeterminado | Significado |
|---|---|---|
| `-n`, `--lines <count>` | `100` | Cantidad de registros recientes que se imprimen al inicio, hasta `5000`. |
| `--since <duration>` | `15m` | Cuánto tiempo hacia atrás se buscan registros: `30s`, `10m`, `2h`, `1d`, `1w`. |
| `--from <time>`, `--to <time>` | ninguno | Define un intervalo en lugar de `--since`. Acepta una fecha y hora en formato ISO, `2026-10-26 14:00` en hora local o un tiempo hacia atrás a partir de ahora, como `2h`. |
| `-q`, `--query <query>` | ninguno | Una consulta por campos con la sintaxis de la página **Registros**. |
| `--where <condition>` | ninguno | Una condición SQL sobre los campos del flujo. |
| `--fields <a,b,c>` | todos | Imprime la hora y solo los campos indicados, como `name=value`. |
| `--json` | desactivado | Imprime cada registro en una línea en formato JSON. |
| `--utc` | desactivado | Imprime las horas en UTC en lugar de usar la hora local. |
| `--web` | desactivado | Abre los mismos registros en la página **Registros** en lugar de imprimirlos. |

## Filtra los registros

`-q` acepta una consulta por campos con la sintaxis de la página **Registros**. Combina comparaciones como
`level = 'error'`, `contains`, `MATCH` y `MATCH_TEXT` con `AND` y `OR`, y agrúpalas
con paréntesis. Si no indicas un campo, el comando busca el texto en `message`:

```bash
molesignal logs app_logs --since 1h -q "level = 'error' AND (service = 'payment' OR timeout)"
```

`--where` acepta una condición SQL sobre los campos del flujo, como en la cláusula `WHERE` de una consulta:

```bash
molesignal logs app_logs --where "status >= 500 AND duration_ms > 2000"
```

Si usas ambas opciones, cada registro debe cumplir las dos condiciones. Si una condición hace referencia a un campo inexistente o no es SQL válido,
el comando termina e indica el motivo.

## Sigue los registros nuevos

```bash
molesignal logs app_logs -f
```

Tras imprimir los registros más recientes, el comando sigue imprimiendo los que llegan hasta que presionas **Ctrl+C**:

- El comando vuelve a leer cada 2 segundos. Cambia el intervalo con `--interval`.
- Cada lectura empieza 10 segundos antes del final de la anterior. Así, aunque un registro llegue
  a MoleSignal unos segundos tarde, aparece de todos modos. Cada registro aparece una sola vez.
- Si llegan más registros de los que caben en una lectura, el comando lee el resto de inmediato, sin esperar.
- Si se pierde la conexión, la CLI intenta restablecerla con pausas cada vez más largas, de hasta 30 segundos. La CLI informa de la pérdida
  y del restablecimiento de la conexión en la salida de error estándar.

El seguimiento usa las marcas de tiempo de los propios registros. Si un registro llega con una marca de tiempo anterior al inicio
de la lectura actual, no aparece. No combines `--to` con `-f`.

## Lee los registros alrededor de un momento

`--around` imprime los registros inmediatamente anteriores y posteriores a un momento, con una línea que marca ese momento
entre ambos grupos. `-B` y `-A` fijan la cantidad de registros a cada lado: 10 de forma predeterminada y hasta 250. `-q` y `--where`
filtran los resultados:

```bash
molesignal logs app_logs --around "2026-10-26 14:03:12.345" -B 20 -A 20
```

`--around` acepta una marca de tiempo copiada de la salida de `molesignal logs`.

## Ejecuta SQL sobre un flujo

`molesignal query` ejecuta una sola sentencia SQL de solo lectura, con expresiones, uniones y agregaciones, e
imprime el resultado como tabla:

```bash
molesignal query "SELECT level, COUNT(*) AS logs FROM app_logs GROUP BY level ORDER BY logs DESC"
```

El comando usa el primer flujo que aparece después de `FROM`. Con `--stream` puedes indicar otro. De forma
predeterminada, el intervalo abarca la última hora. Cámbialo con `--since`, `--from` y `--to`. `-n` fija el límite de filas: `1000` de forma predeterminada y
`5000` como máximo. `--csv` imprime CSV con una fila de encabezado, `--json` imprime una fila por línea en JSON y
`--web` abre la sentencia en la página **Registros**.

## Consulta los campos de un flujo

```bash
molesignal fields app_logs
```

La lista muestra cada campo con su tipo y su índice. Si indicas un campo, el comando enumera los valores más
frecuentes de la última hora e indica cuántas veces aparece cada uno:

```bash
molesignal fields app_logs service --since 1d
```

`--match` conserva los valores que contienen un texto y `-n` fija la cantidad, `20` de forma predeterminada.
`--type` lee un flujo de otro tipo.

## Canaliza la salida a otro comando

`--json` imprime cada registro con todos sus campos:

```bash
molesignal logs app_logs -n 1000 --since 2h --json | jq -r .message
```

Si un comando como `head` deja de leer antes de tiempo, el comando termina sin mostrar avisos.

## Acceso

La CLI lee los datos con las herramientas de MoleSignal `list_streams`, `query_logs`, `get_stream_schema`,
`search_field_values` y `search_around`. Usa los permisos de la cuenta con sesión iniciada o de la
cuenta propietaria del token de API. La cuenta necesita el permiso `streams.query` y la política de herramientas de la organización debe
permitir el uso de estas herramientas.
