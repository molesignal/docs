`molesignal mcp` ofrece las herramientas MCP de MoleSignal a través de stdio. Una herramienta de agente inicia el comando
y se comunica con él mediante la entrada y la salida estándar. La CLI reenvía cada mensaje al
endpoint **MCP entrante** de MoleSignal y devuelve cada respuesta. MoleSignal define las herramientas, sus permisos y
sus aprobaciones: la CLI no agrega ninguno de estos elementos.

## Agrega el servidor a una herramienta de agente

Primero, [inicia sesión](/es/cli/sign-in). Luego, deja que la CLI se agregue a la herramienta de agente:

```bash
molesignal mcp setup claude
```

| Herramienta de agente | Qué cambia `molesignal mcp setup` |
|---|---|
| `claude` | Ejecuta `claude mcp add` para Claude Code. `--scope` admite `user` (predeterminado), `project` o `local`. |
| `cursor` | `~/.cursor/mcp.json` o, con `--scope project`, `.cursor/mcp.json` en la carpeta actual. |
| `codex` | `~/.codex/config.toml`. Si defines `CODEX_HOME`, usa el archivo `config.toml` de ese directorio. |
| `vscode` | `.vscode/mcp.json` en la carpeta actual. |
| `gemini` | `~/.gemini/settings.json` o, con `--scope project`, `.gemini/settings.json` en la carpeta actual. |

El comando agrega un servidor llamado `molesignal` o reemplaza el que ya tiene ese nombre. Conserva el resto de la
configuración del archivo. El servidor ejecuta `npx -y @molesignal/cli mcp`. Con `--installed`, ejecuta la versión
instalada de `molesignal`. `--profile` guarda el perfil en la configuración del servidor para que la herramienta de agente
use las credenciales de ese perfil, independientemente del perfil activo. `--print` muestra la configuración en lugar de
guardarla.

[Conéctate mediante stdio](/es/inbound-mcp#conéctate-mediante-stdio) muestra la misma configuración para cada
herramienta. El prompt de configuración en **Mole Agent → Configuración → MCP entrante** genera los pasos para la
instancia.

En entornos sin inicio de sesión, como un equipo de compilación, proporciona al servidor las credenciales mediante
variables de entorno:

```json
{
  "mcpServers": {
    "molesignal": {
      "command": "npx",
      "args": ["-y", "@molesignal/cli", "mcp"],
      "env": {
        "MOLESIGNAL_URL": "https://molesignal.example.com",
        "MOLESIGNAL_TOKEN": "<token>"
      }
    }
  }
}
```

## Cómo reenvía los mensajes la CLI

- Hasta que la herramienta de agente envía `notifications/initialized`, la CLI reenvía los mensajes uno por uno y en
  orden: MoleSignal abre la sesión al responder a `initialize`. Después, la CLI reenvía los mensajes
  a medida que llegan, de modo que una llamada lenta a una herramienta no bloquea las demás.
- Si MoleSignal deja de reconocer la sesión, por ejemplo, después de reiniciarse, la CLI abre una nueva con
  el mensaje `initialize` original de la herramienta de agente y vuelve a enviar el mensaje. La herramienta de agente sigue funcionando sin
  reiniciarse.
- Si una solicitud no puede llegar a MoleSignal, la CLI responde con un error para que la herramienta de agente no se quede
  esperando.
- Cuando la herramienta de agente cierra la entrada estándar, la CLI finaliza la sesión en MoleSignal y se cierra.
- La CLI envía los avisos, como los de pérdida de conexión, a la salida de error estándar.
  La salida estándar solo lleva mensajes MCP.
- `HTTPS_PROXY` y `NO_PROXY` se aplican igual que en los demás comandos.

## Comprueba la conexión

```bash
molesignal status
```

El número de herramientas coincide con el que ve la herramienta de agente. Un valor de cero suele indicar que
la política de herramientas de la organización o los permisos de usuario no permiten acceder a ninguna herramienta.
