Open **Registros** to search log streams in the active workspace.

## Choose a stream and time range

Selecciona un flujo de registros y luego establece la ventana de tiempo más pequeña que contenga el evento. Las ventanas estrechas
reducen las filas escaneadas y agilizan la exploración de campos.

MoleSignal puede inferir el esquema de un flujo a medida que llegan los eventos. El panel **Campos** enumera los campos del
flujo y agrega filtros sin reescribir la consulta completa.

## Pestañas de consulta

Cada consulta se ejecuta en su propia pestaña. Una pestaña conserva su flujo, su consulta y su intervalo de tiempo, y una consulta en
una pestaña no afecta a otra.

- Selecciona **Nueva pestaña** para abrir otra consulta. Se pueden tener abiertas hasta 10 pestañas a la vez.
- Abre el menú de una pestaña para **Cambiar nombre**, **Duplicar** o **Cerrar**.
- Selecciona **Dividir en dos** para mostrar dos pestañas en paralelo. Cada mitad enumera sus propias pestañas, y una pestaña
  se mueve de una a otra desde su menú. **Volver a una sola página** termina la división.

Las pestañas abiertas se conservan en el navegador para cada usuario y cada espacio de trabajo.

## Escribe una consulta

El editor tiene dos modos, **Código** y **Constructor**, que se cambian con los dos iconos junto al título (`</>` para
Código, los bloques para Constructor); cada uno muestra su nombre al pasar el cursor.

**Código** acepta una consulta de campos o SQL. Una sentencia que comienza con `SELECT` o `WITH` se ejecuta como SQL.
Cualquier otra cosa se ejecuta como consulta de campos:

| Consulta de campos | Significado |
|---|---|
| `service = 'checkout'` | El campo tiene exactamente este valor. |
| `message contains 'timeout'` | El campo contiene el texto. |
| `MATCH(message, 'timeout')` | Búsqueda de subcadena sin distinguir mayúsculas y minúsculas. |
| `MATCH_TEXT(message, 'timeout disk')` | Búsqueda de texto completo en un campo con índice de texto completo. |

Combina condiciones con `AND` y `OR`, en mayúsculas o minúsculas. `AND` tiene mayor precedencia que `OR`, y los paréntesis
agrupan condiciones: `level = 'error' AND (service = 'checkout' OR service = 'payments')`. El texto
sin un campo se busca en el campo `message` y puede ser una de las alternativas:
`timeout OR "connection reset"`. Las comillas mantienen una frase completa, incluso una que contenga una palabra como `or`.
Compara con `=`, `!=`, `>`, `>=`, `<` y `<=`.

**Constructor** muestra la misma consulta de campos como filas de filtros, una fila por cada alternativa: los
filtros de una fila se cumplen todos, y **O** aparece antes de cada fila posterior a la primera. Selecciona **Filtrar** para
agregar un filtro a una fila, o **O** para agregar una fila, y luego elige un campo, una comparación y un valor. Cada
fila tiene su propio texto de búsqueda. Una parte entre paréntesis dentro de una fila, como el `OR` del ejemplo
anterior, se conserva tal como se escribió y se cambia en **Código**. Una sentencia que es SQL no se puede mostrar como
filtros.

Usa SQL para uniones, expresiones, CTE o agregaciones:

```sql
SELECT "_timestamp", level, msg, trace_id
FROM app
WHERE level = 'error'
ORDER BY "_timestamp" DESC
LIMIT 200;
```

```sql
SELECT level, COUNT(*) AS events
FROM app
GROUP BY level
ORDER BY events DESC;
```

Ejecuta la consulta con **Ejecutar**, o pulsa `⌘ Enter` o `Ctrl+Enter` en el editor. La **Referencia de sintaxis
de consultas** enumera ejemplos para el modo actual. Consulta [Consulta](/es/query#búsqueda-de-texto) para ver las
funciones de búsqueda de texto.

El planificador de consultas aplica el límite de la organización actual incluso para SQL personalizado.

## Explora los campos

El panel **Campos** tiene tres partes: **Campos visibles**, **Campos indexados** y **Otros
campos**. Los campos que comparten la primera parte de un nombre con puntos, como `http.method` y
`http.route`, se abren como un solo grupo.

- Abre un campo para ver sus valores más comunes en el resultado. Agrega un valor como filtro de inclusión o
  de exclusión. El filtro limita toda la consulta: una consulta de alternativas se coloca entre paréntesis
  antes de él.
- Muestra u oculta un campo como columna del resultado.
- Selecciona **Analizar** en un campo para abrir el análisis del campo: el número de valores distintos, las filas
  con y sin valor, las estadísticas de un campo numérico, la distribución de valores y los valores
  más comunes a lo largo del tiempo.

## Lee los resultados

El histograma sobre los resultados cuenta todos los eventos que coinciden con la consulta en el intervalo de tiempo, no
solo la página que está cargada. Cuatro vistas leen el resultado:

| Vista | Contenido |
|---|---|
| **Registros** | Los eventos coincidentes, uno por fila. |
| **Estadísticas** | Un gráfico de un agregado. Elige la medida (recuento, recuento distinto, promedio, suma, mínimo, máximo, P50, P95 o P99), la agrupación y el tipo de gráfico, o dibuja el resultado de un agregado SQL. **Crear panel** guarda el gráfico como uno de los paneles de un panel nuevo. |
| **Inspección con IA** | Un informe que Mole Agent escribe sobre los registros que coinciden con la consulta. Consulta [Inspecciones de registros](/es/logs/inspections). |
| **Patrones** | Los eventos agrupados por patrón, con el recuento y la proporción de cada patrón. |

La vista **Patrones** cuenta los patrones de todo el intervalo de tiempo en el servidor. Un intervalo con más
de 5000 eventos se lee como una muestra distribuida a lo largo de él, y cada recuento se escala al intervalo y
se escribe con `≈`; la línea bajo los patrones indica cuántos eventos tiene el intervalo y cuántos se
leyeron. **Cambio** compara cada patrón con una línea base elegida junto a él: el tramo de la misma
longitud anterior (el valor predeterminado), el mismo tramo una semana antes, o ninguno. **Nuevo** marca un patrón que la
línea base no tenía, `×N` uno que creció al menos el doble con al menos cinco eventos, y **Menos** uno
que se redujo a la mitad. Abrir un patrón muestra los eventos cargados que le corresponden, o uno de sus mensajes cuando
no hay ninguno cargado. Una sentencia escrita en SQL se agrupa a partir de los eventos que devolvió.

En la vista **Registros**:

- **Columnas** selecciona y ordena las columnas. Las columnas predeterminadas provienen de los campos del
  flujo: el tiempo y luego los campos de nivel, servicio y mensaje cuando el flujo los tiene.
- El tamaño de página es de 100, 200, 500, 1000, 2000 o 5000 eventos.
- Haz clic en un evento para abrirlo en un panel lateral junto a los resultados; arrastra el borde izquierdo del panel para cambiar su
  tamaño, y el ancho se conserva. El encabezado muestra el nivel, el tiempo, el mensaje y los atributos que
  describen el evento (servicio, host, entorno, versión, traza), cada uno con las mismas acciones que un
  campo. Las vistas son **Campos**, **Traza** cuando el evento lleva un ID de traza, **Contexto** y
  **JSON sin procesar**. **Traza** muestra el waterfall de la traza con el span del evento seleccionado. **Contexto**
  muestra cinco filas circundantes a cada lado. Desde un campo, agrega un filtro, copia el valor o muestra el
  campo como columna.
- Haz un pivote a una traza, un servicio, una métrica u otra señal correlacionada cuando los identificadores estén presentes.
- Descarga el resultado como CSV, como texto o como JSON.

## Comparte una consulta

La dirección de la página es la consulta en pantalla. Cuando se ejecuta una consulta, la página escribe su flujo, su
sentencia (`q` para una consulta de campos, `sql` para SQL) y la vista de los resultados en la dirección, de modo que una
copia de la barra de direcciones comparte la consulta, con el intervalo de tiempo que muestra el selector, como la última
hora. Recargar la página mantiene la consulta y el editor tal como estaban.

Selecciona **Compartir** para copiar un enlace a la consulta en pantalla. El enlace se abre para los miembros que hayan iniciado sesión en la
organización y que puedan leer los datos. Elige el intervalo de tiempo del enlace: **Intervalo de tiempo seleccionado**
fija el intervalo a los momentos en pantalla, y la otra opción mantiene un intervalo relativo, como la última
hora, contado desde el momento en que se abre el enlace.

## Tareas de búsqueda

Una búsqueda demasiado grande para una solicitud interactiva se ejecuta como una tarea de búsqueda. Abre
**Flujos → Tareas de búsqueda** para seguir la tarea y descargar su resultado. Consulta
[Flujos](/es/streams#tareas-de-búsqueda).

## Vistas guardadas

Guarda una consulta SQL con un nombre como [vista guardada](/es/saved-views). Vuelve a abrir la vista, ejecuta la consulta
en otra ventana de tiempo o adjunta la vista a un informe.

<Tip>
  Conserva dimensiones estables como `service.name`, `deployment.environment`, `trace_id` y
  `host.name` durante la ingesta. Estos campos hacen fiables los pivotes entre señales.
</Tip>

## Permisos

- `streams.read` descubre flujos y esquemas.
- `logs.read` lee logs: la lista, el histograma y las estadísticas de campos.
- `streams.query` ejecuta una sentencia SQL y abre contexto.
- `agent.use` ejecuta una inspección de IA, que también requiere un modelo de IA habilitado.
- `saved_views.create`, `saved_views.edit` y `saved_views.delete` controlan las vistas guardadas.
