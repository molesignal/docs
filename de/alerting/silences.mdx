Eine Stummschaltung setzt Benachrichtigungen und Eskalationen für passende Vorfälle aus. MoleSignal erfasst diese Vorfälle
weiterhin. Eine semantische Gruppe fasst zusammengehörige Vorfälle zusammen, damit das Bereitschaftsteam sie gemeinsam bearbeitet. Beides
ändert die Regeln nicht. Verwenden Sie die folgende Funktion, um weniger schwerwiegende Vorfälle zu unterdrücken, solange ein schwerwiegenderer Vorfall aktiv ist:
[Unterdrückung](/de/alerting/inhibition).

## Stummschaltungsregeln

Öffnen Sie **Alarme → Stummschaltungsregeln**. Jede Regel zeigt ihren Status, ihr Zeitfenster und ihre Filterbedingungen.

| Status | Bedeutung |
|---|---|
| **Derzeit stummgeschaltet** | Die Regel schaltet passende Vorfälle stumm. |
| **Noch nicht begonnen** | Das Zeitfenster beginnt später. |
| **Außerhalb des Zeitfensters** | Das wiederkehrende Zeitfenster ist gerade nicht aktiv. |
| **Ende** | Das Zeitfenster ist abgelaufen. |
| **Aus** | Die Regel ist deaktiviert. |

So erstellen Sie eine Regel:

1. Wählen Sie **Neue Stummschaltungsregel** und geben Sie einen **Namen** ein. Lassen Sie **Aktiviert** eingeschaltet.
2. Wählen Sie unter **Filterbedingungen** für jede Bedingung an die Labels eines Vorfalls **Matcher hinzufügen**, zum Beispiel
   `service` `=` `checkout`. Alle Matcher müssen zutreffen. `=~` und `!~` erwarten reguläre Ausdrücke. Ohne
   Matcher gilt die Regel für **Jeder Vorfall**.
3. Wählen Sie unter **Zeitfenster** die **Art des Zeitfensters**:
   - **Fester Zeitraum**: ein **Beginn** und ein **Ende**;
   - **Jede Woche**: eine **Zeitzone** und mindestens ein Zeitraum mit eigenen Angaben für **Tage**,
     **Beginn (HH:MM)** und **Ende (HH:MM)**, minutengenau, zum Beispiel jeden Samstag von 02:00
     bis 06:00. Liegt die Endzeit vor oder auf der Startzeit, endet der Zeitraum am nächsten Tag. Unter **Feiertage** können Sie
     die freien Tage eines [Feiertagskalenders](/de/alerting/on-call#feiertagskalender) ausnehmen oder die Zeiträume auf diese Tage beschränken;
   - **Feiertage**: eine **Zeitzone** und ein **Feiertagskalender**. Die Regel gilt an allen freien Tagen des Kalenders ganztägig, etwa
     um eine Testumgebung an gesetzlichen Feiertagen stummzuschalten;
   - **Jeden Monat**: eine **Zeitzone**, ein **Tag des Monats** (fehlt dieser Tag, gilt der letzte
     Tag des Monats) oder **Welcher** (der erste bis fünfte oder der letzte) **Wochentag**, dazu **Beginn (HH:MM)** und
     **Dauer (Minuten)** von bis zu 7 Tagen. Beispiel: jeden ersten Sonntag im Monat ab
     02:00 für 240 Minuten. Gibt es den gewählten Wochentag in einem Monat nicht zum fünften Mal, entfällt das Zeitfenster.
4. Geben Sie unter **Kommentar** den **Grund** ein und wählen Sie **Stummschaltung erstellen**.

Die Liste zeigt, wann eine wiederkehrende Stummschaltung das nächste Mal beginnt oder endet. Der Server berechnet die Zeiten in seiner Zeitzone
und berücksichtigt die Sommerzeit.

Stummschaltungen prüfen die Labels der Vorfälle: die Labels der Alarmregel und die Gruppenwerte
einer [aufgeteilten Regel](/de/alerting/rules#regel-nach-spalten-gruppieren). Vorfälle aus [externen Alarmen](/de/alerting/sources)
enthalten `alert.source=external`, `external.kind` (zum Beispiel `alertmanager`), die Labels des Alarms und die
zusätzlichen Labels der Quelle. `external.kind` `=` `grafana` schaltet zum Beispiel alle Alarme von Grafana stumm.
Geben Sie bei jeder geplanten Stummschaltung den betroffenen Dienst und die Endzeit an. Lassen Sie die Stummschaltung automatisch ablaufen,
statt sie später zu löschen.

<Warning>
  Eine Stummschaltung unterdrückt Benachrichtigungen. Sie belegt nicht, dass der Dienst wieder funktioniert. Prüfen Sie nach Ablauf des Zeitfensters
  die Vorfallsliste.
</Warning>

### Benachrichtigungen während einer Stummschaltung

Während einer Stummschaltung öffnet und erfasst MoleSignal passende Vorfälle wie gewohnt. Der Versand hängt vom
Benachrichtigungstyp ab:

| Benachrichtigung | Während der Stummschaltung | Nach der Stummschaltung |
|---|---|---|
| Alarm ausgelöst, Alarm eskaliert | Kein Versand. Die Eskalation bleibt auf der aktuellen Stufe. | Ist der Vorfall weder bestätigt noch behoben, sendet MoleSignal die Auslösebenachrichtigung und setzt die Eskalation fort. Ist die Bestätigungsfrist der aktuellen Stufe während der Stummschaltung abgelaufen, benachrichtigt MoleSignal sofort die nächste Stufe. Bei Vorfällen, die während der Stummschaltung bestätigt oder behoben wurden, sendet MoleSignal nichts. |
| Spätere Schritte einer persönlichen Benachrichtigungsreihenfolge, Eskalation einer Benachrichtigungsregel nach Ablauf der Bestätigungsfrist | Kein Versand. | MoleSignal sendet die Benachrichtigungen, solange keine Bestätigung vorliegt. |
| Alarm bestätigt, Alarm behoben | MoleSignal sendet die Benachrichtigung nur, wenn die Auslösebenachrichtigung vor Beginn der Stummschaltung versendet wurde. | Versand wie gewohnt. |

Eine Stummschaltung endet, sobald das Zeitfenster abläuft oder die Regel deaktiviert oder gelöscht wird.

### Einzelnen Vorfall stummschalten

Wählen Sie bei einem Vorfall **Stummschalten**, um Benachrichtigungen und Eskalationen nur für diesen Vorfall für **1 Stunde**,
**4 Stunden**, **24 Stunden** oder **7 Tage** auszusetzen. Geben Sie optional einen **Grund** an. Die Alarmregel bleibt aktiv und
andere Vorfälle desselben Dienstes bleiben unberührt. Die Stummschaltung erscheint unter **Stummschaltungsregeln**. Dort können Sie sie
ändern oder vorzeitig aufheben.

Zum Erstellen, Ändern und Aufheben von Stummschaltungen ist `alerts.mutes.manage` erforderlich.

## Semantische Gruppen

Öffnen Sie **Alarme → Gruppen**. Eine semantische Gruppe fasst Vorfälle mit gleichen Labelwerten zusammen, ähnlich wie
`group_by` in Alertmanager. Bestätigen Sie eine Gruppe über die API oder markieren Sie sie als behoben, gilt das für jeden
Vorfall in der Gruppe. Siehe [Vorfallsgruppen](/de/alerting/incidents#vorfallgruppen).

1. Wählen Sie **Neue Gruppe** und geben Sie einen **Namen** ein, zum Beispiel `critical-by-service`. Lassen Sie **Aktiviert** eingeschaltet.
2. Fügen Sie unter **Matcher** die Bedingungen hinzu, die ein Vorfall erfüllen muss, zum Beispiel `severity` = `critical`.
   Alle Bedingungen müssen zutreffen. Ohne Matcher gilt die Gruppe für alle Vorfälle.
3. Geben Sie unter **Gruppieren nach** die **Labels für die Gruppierung** kommagetrennt ein, zum Beispiel `service, region`.
   MoleSignal fasst Vorfälle mit gleichen Werten für diese Labels zu einer Gruppe zusammen.
4. Wählen Sie **Gruppe erstellen**.

MoleSignal überspringt deaktivierte Gruppen. Wenn Sie eine Gruppe löschen, bleiben die Vorfälle erhalten. Nur die Gruppierung entfällt.

Mit **Importieren** erstellen Sie Gruppen aus JSON: aus einem Array von Gruppen oder aus einem Objekt mit einem `groups`-Array.

```json
[
  {
    "name": "crit-by-service",
    "enabled": true,
    "matchers": [{ "label": "severity", "op": "eq", "value": "critical" }],
    "groupBy": ["service"]
  }
]
```

Zum Verwalten von Gruppen ist `alerts.semantic_groups.manage` erforderlich.
