Bei einer Log-Analyse liest Mole Agent die Logs eines Zeitraums und erstellt einen Bericht: Gibt es ein
Problem, worin besteht es und welche Logs zeigen es? Die Analyse liest nur Logs. Sie ändert weder Daten noch
Konfigurationen.

| Art | Verwendung |
|---|---|
| **Bei Bedarf** | Analysieren Sie in der Ansicht **KI-Analyse** unter **Logs** einmalig die Logs, die der aktuellen Abfrage entsprechen. Der Bericht erscheint nach und nach auf der Seite. Die Analyse läuft als Chat mit Mole Agent und lässt sich daher in **Mole Agent** fortsetzen. Der Bericht erscheint nicht in der Liste der geplanten Berichte. |
| **Geplant** | Speichern Sie einen Stream, eine Abfrage und die Schwerpunkte der Analyse. MoleSignal führt die Prüfung nach Zeitplan aus, speichert jeden Bericht und benachrichtigt bei gemeldeten Problemen. |

## Vor dem Start

- Aktivieren Sie unter **Mole Agent → Einstellungen → Modelle und Reasoning** mindestens ein KI-Modell. Siehe
  [Mole Agent](/de/agent#modellanbieter-einrichten). Ohne aktiviertes Modell bleiben gespeicherte Prüfungen
  in der Liste, lassen sich aber nicht ausführen.
- Prüfen Sie die Berechtigungen:

| Aufgabe | Berechtigung |
|---|---|
| Analyse bei Bedarf ausführen | `agent.use` und `logs.read` |
| Geplante Prüfungen und zugehörige Berichte lesen | `inspections.read` und `logs.read` |
| Erstellen, bearbeiten, aktivieren, deaktivieren und löschen | `inspections.manage`, standardmäßig den Rollen „Eigentümer“, „Administrator“ und „Bearbeiter“ zugewiesen |
| Jetzt ausführen | `inspections.run`, denselben Rollen zugewiesen |
| Im Formular einen Benachrichtigungskanal auswählen | `notify.connectors.read` zum Auflisten der Benachrichtigungskonnektoren |

Mole Agent liest im Chat dieselben Prüfungen und Berichte mit `list_log_inspections`,
`list_log_inspection_runs` und `get_log_inspection_run`. Dabei gelten dieselben Berechtigungen.
`run_log_inspection` führt eine Prüfung sofort aus. Dafür sind `inspections.run` und standardmäßig eine Bestätigung
im Chat erforderlich. Siehe [Tool-Katalog und Ausführung](/de/tools).

## Analyse bei Bedarf ausführen

1. Öffnen Sie **Logs**, wählen Sie einen Stream und einen Zeitraum aus und führen Sie eine Abfrage aus. Lassen Sie die Abfrage leer, um
   alle Logs des Streams zu analysieren.
2. Öffnen Sie die Ansicht **KI-Analyse**.
3. Wählen Sie das **KI-Modell** aus. Geben Sie optional unter **Schwerpunkte der Analyse** an, welchen Dienst die Analyse überwachen
   oder welches Ergebnis sie als erwartungsgemäß einstufen soll.
4. Wählen Sie **Analyse starten** aus.

Die Analyse sendet die Abfrageergebnisse für diese Logs an das ausgewählte Modell. Wählen Sie **In Mole
Agent fortsetzen** aus, um Rückfragen zum Bericht zu stellen.

## Geplante Prüfung speichern

Öffnen Sie **Logs → KI-Analyse** und wählen Sie einen der beiden Einträge aus:

- **Als geplante Prüfung speichern** öffnet das Formular mit dem aktuellen Stream, der Abfrage, den Schwerpunkten und
  dem Modell. Speichern Sie die Prüfung auch dann, wenn die Abfrage gerade keine Treffer liefert.
- **Geplante Prüfungen** öffnet die Liste. Wählen Sie dort **Neue Prüfung** aus, um ein leeres Formular zu öffnen.

| Feld | Bedeutung |
|---|---|
| **Name** | Innerhalb der Organisation eindeutig. Höchstens 120 Zeichen. |
| **Stream** | Ein einzelner Log-Stream außer [`_audit`](/de/settings/data-security#audit-stream). Die Prüfung liest nur diesen Stream. |
| **Abfrage** | Optional. Die Prüfung berücksichtigt nur Logs, die der Abfrage entsprechen. Die Syntax entspricht der unter **Logs**. |
| **Schwerpunkte der Analyse** | Optional, höchstens 2.000 Zeichen. Legen Sie fest, worauf es ankommt und was als unauffällig gilt. |
| **Zeitplan** | **In festen Intervallen**, **Täglich** oder **Wöchentlich** zu einer festgelegten Uhrzeit. Das kürzeste Intervall hängt von der Instanzeinstellung ab und beträgt standardmäßig 1 Stunde. |
| **Prüfzeitraum** | Zeitraum unmittelbar vor jedem Lauf, den die Prüfung abdeckt. Im Formular stehen 15 Minuten bis 7 Tage zur Auswahl. Der Standardwert richtet sich nach dem Zeitplan. |
| **KI-Modell** | Ein aktiviertes Modell der Organisation. |
| **Zeitpunkt der Benachrichtigung** | **Bei Auffälligkeiten benachrichtigen** (Standard), **Ab Stufe „Achtung“ benachrichtigen** oder **Immer benachrichtigen**. |
| **Benachrichtigungskanäle** | Optional, höchstens 10. Jeder Kanal verweist auf eine feste Gruppe oder Adresse eines Benachrichtigungskonnektors. SMS- und Sprachnachrichten über Alibaba Cloud verwenden ausschließlich genehmigte Vorlagen und stehen nicht zur Auswahl. |
| **Nach dem Speichern nach Zeitplan ausführen** | Bei deaktivierter Option speichert MoleSignal die Prüfung, führt sie aber nur über **Jetzt ausführen** aus. |

Für tägliche oder wöchentliche Prüfungen gilt die Zeitzone der Benutzeroberfläche zum Zeitpunkt der Erstellung: die Zeitzone
aus den persönlichen Einstellungen oder, falls dort keine festgelegt ist, die Zeitzone des Browsers. Das Formular zeigt
die Zeitzone an. Eine spätere Bearbeitung ändert sie nicht. Benachrichtigungen und Berichte verwenden die Sprache der Benutzeroberfläche
zum Zeitpunkt der Erstellung.

Eine Organisation kann standardmäßig höchstens 20 geplante Prüfungen speichern.

## Ablauf einer Prüfung

| Aspekt | Verhalten |
|---|---|
| Identität | Ein Lauf liest die Logs mit der Identität des Kontos, das die Prüfung zuletzt gespeichert hat. Vor jedem Lauf prüft MoleSignal, ob das Konto sich weiterhin anmelden kann, noch zur Organisation gehört und weiterhin über `agent.use` und `logs.read` verfügt. Andernfalls schlägt der Lauf mit dem Hinweis fehl, dass die Identität nicht mehr nutzbar ist. Speichern Sie die Prüfung mit einem anderen berechtigten Konto erneut, damit sie unter dessen Identität läuft. Mit einem API-Token lässt sich keine geplante Prüfung speichern. |
| Tools | Das Modell verwendet vier Tools mit reinem Lesezugriff: `query_logs`, `get_stream_schema`, `search_field_values` und `analyze_log_patterns` (gruppiert Logs nach Mustern und vergleicht sie mit einem Referenzzeitraum). Der Zugriff beschränkt sich auf den Stream der Prüfung. Das Modell verwendet keine Tools, die die Tool-Richtlinie der Organisation deaktiviert oder von einer Genehmigung abhängig macht, da im Hintergrund keine Genehmigungen erfolgen. |
| Zeitfenster | Ein Lauf deckt den Zeitraum unmittelbar vor seinem Start ab. MoleSignal holt keine Läufe nach, die während des Stillstands eines Knotens ausgefallen sind. Sobald der Knoten wieder verfügbar ist, läuft eine fällige Prüfung einmal. Danach gilt wieder der Zeitplan. |
| Limits | Ein Lauf dauert standardmäßig höchstens 5 Minuten. Danach gilt das Zeitlimit als überschritten. Überschreitet ein Tool-Ergebnis 64 KiB, erhält das Modell statt des Ergebnisses die Aufforderung, die Abfrage einzugrenzen. Nach einem fehlgeschlagenen Lauf startet MoleSignal vor dem nächsten geplanten Lauf keinen weiteren Versuch. |
| Parallele Ausführung | Pro Prüfung läuft höchstens eine Ausführung gleichzeitig. Ein Knoten führt standardmäßig höchstens 2 Prüfungen gleichzeitig aus. |
| **Jetzt ausführen** | MoleSignal stellt den Lauf in die Warteschlange und startet ihn innerhalb von 15 Sekunden unter der Identität der Prüfung. Der Eintrag nennt das Konto, das den Lauf gestartet hat. Auf diese Weise lässt sich auch eine deaktivierte Prüfung ausführen. |

## Berichte und Bewertungen

Wählen Sie eine Prüfung in der Liste aus, um die zugehörigen Berichte zu öffnen. Vergangene Läufe stehen links. Für den ausgewählten Lauf
zeigt MoleSignal den Bericht, den Prüfzeitraum, die Dauer, die aufgerufenen Tools, die verbrauchten Tokens und die
gesendeten Benachrichtigungen an. **Logs für diesen Zeitraum öffnen** öffnet **Logs** mit demselben Stream, derselben Abfrage und
demselben Zeitraum.

Ein Bericht zu einer geplanten Prüfung enthält eine Bewertung:

| Bewertung | Bedeutung |
|---|---|
| **Unauffällig** | Kein Handlungsbedarf. |
| **Handlungsbedarf** | Es gibt einen Hinweis, der eine Prüfung verdient, aber keine Störung. |
| **Auffällig** | Es liegt ein Problem vor, das Maßnahmen erfordert. |
| **Keine Bewertung** | Die Antwort des Modells enthält keine auswertbare Bewertung. MoleSignal speichert den Bericht und behandelt ihn für Benachrichtigungen als auffällig. |

Ein nicht abgeschlossener Lauf erzeugt keinen Bericht. Der Eintrag zeigt den Status und den Grund an:

| Status | Grund |
|---|---|
| **Zeitlimit überschritten** | Der Lauf hat sein Zeitlimit überschritten. |
| **Fehlgeschlagen** | Die Identität ist nicht mehr nutzbar; das ausgewählte KI-Modell fehlt, ist deaktiviert oder hat keinen Schlüssel; der Modellaufruf ist fehlgeschlagen; das heutige Token-Budget der Organisation für Mole Agent ist aufgebraucht; der Knoten hat den Betrieb während des Laufs eingestellt; kein Knoten hat den Lauf übernommen; oder ein interner Fehler ist aufgetreten. |

MoleSignal speichert Berichte standardmäßig 30 Tage lang und entfernt abgelaufene Berichte stündlich. Beim Löschen einer Prüfung
löscht MoleSignal auch alle zugehörigen Berichte.

## Benachrichtigungen

- Wenn die Bewertung eines Berichts die unter **Zeitpunkt der Benachrichtigung** festgelegte Bedingung erfüllt, erhält jeder Kanal eine Benachrichtigung:
  Der Titel nennt die Bewertung und den Namen der Inspektion. Der Nachrichtentext enthält den Stream, den
  Zeitraum, die Bewertung, die Zusammenfassung des Berichts und einen Link zum Bericht. Damit der Link funktioniert, muss
  `http.external_url` festgelegt sein.
- Ein fehlgeschlagener Lauf löst eine Benachrichtigung aus, wenn der vorherige Lauf nicht fehlgeschlagen ist. Bei aufeinanderfolgenden Fehlern löst
  nur der erste eine Benachrichtigung aus, unabhängig von **Zeitpunkt der Benachrichtigung**.
- Ohne Kanal sendet MoleSignal keine Benachrichtigungen, speichert die Berichte aber weiterhin.
- Jede Benachrichtigung erscheint unter **Einstellungen → Benachrichtigungen → Zustellprotokoll** mit der Stufe
  **Direkt**. Bei einer direkten Zustellung greifen keine Benachrichtigungsrichtlinien. Die Zustellung lässt sich nicht
  über das Zustellprotokoll wiederholen.
- Solange eine geplante Inspektion einen Benachrichtigungskonnektor verwendet, lässt sich dieser nicht löschen.

## Instanzeinstellungen

| Einstellung | Standardwert | Zweck |
|---|---|---|
| `[log_inspection].min_interval_secs` | `3600` | Mindestabstand zwischen zwei Läufen derselben Inspektion. Werte unter 60 gelten als 60. |
| `[log_inspection].max_per_org` | `20` | Maximale Anzahl geplanter Inspektionen pro Organisation. `0` lässt keine zu. |
| `[log_inspection].concurrent_runs` | `2` | Anzahl der Inspektionen, die ein Knoten gleichzeitig ausführen kann. |
| `[log_inspection].run_timeout_secs` | `300` | Zeitlimit pro Lauf einschließlich aller Modellaufrufe und Abfragen. Der zulässige Wertebereich ist auf 30–480 begrenzt. |
| `[log_inspection].report_retention_days` | `30` | Aufbewahrungsdauer der Berichte. |

Knoten mit der Rolle `alert` führen geplante Inspektionen aus und prüfen alle 15 Sekunden, ob ein Lauf fällig ist oder
in der Warteschlange steht. Bei mehreren Knoten mit der Rolle `alert` übernimmt nur ein Knoten den jeweiligen Lauf. Siehe
[Rollenbasierte Bereitstellung](/de/deployment/role-based).

Zwei Metriken erfassen die Läufe:

| Metrik | Bedeutung |
|---|---|
| `log_inspection_runs_total{outcome}` | Abgeschlossene Läufe nach Ergebnis: `succeeded`, `failed` oder `timed_out`. |
| `log_inspection_run_duration_seconds` | Dauer eines Laufs. |

## API

Die Endpunkte befinden sich unter `/api/v1/logs/inspections`:

| Methode und Pfad | Zweck |
|---|---|
| `GET /logs/inspections` | Geplante Inspektionen der Organisation auflisten. |
| `POST /logs/inspections` | Eine Inspektion erstellen. |
| `GET /logs/inspections/limits` | Die Grenzwerte der Instanz abrufen. |
| `GET`, `PUT`, `DELETE /logs/inspections/{id}` | Eine Inspektion samt Berichten abrufen, ersetzen oder löschen. |
| `POST /logs/inspections/{id}/enabled` | Eine Inspektion aktivieren oder deaktivieren. |
| `POST /logs/inspections/{id}/run` | Eine Inspektion sofort einmalig ausführen. |
| `GET /logs/inspections/{id}/runs` | Vergangene Läufe ohne Berichtstext auflisten, neueste zuerst. Für `limit` gilt der Standardwert 50 und der Höchstwert 200. Rufen Sie mit `before` ältere Läufe ab. |
| `GET /logs/inspections/{id}/runs/{run_id}` | Einen Lauf samt Bericht abrufen. |
