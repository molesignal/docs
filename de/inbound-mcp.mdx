Mit **Eingehendes MCP** können Claude Code, Cursor, Codex, ChatGPT und andere MCP-Clients MoleSignal erkunden und
bedienen. Dabei nutzen sie dieselbe zugriffsgesteuerte Tool-Laufzeitumgebung wie Mole Agent. Ein Client stellt
die Verbindung auf eine von zwei Arten her:

- **stdio** (empfohlen): Der Client startet die MoleSignal CLI mit `molesignal mcp` aus dem npm-Paket
  `@molesignal/cli`. Die CLI meldet sich einmalig über den Browser an und leitet alle Nachrichten an
  den unten angegebenen Endpunkt weiter.
- **Streamable HTTP**: Der Client ruft den Endpunkt direkt auf.

Der Endpunkt lautet:

```text
https://molesignal.example.com/api/v1/mcp
```

Der Server verwendet Streamable HTTP und unterstützt die MCP-Protokollversionen `2026-07-28`,
`2025-11-25`, `2025-06-18` und `2025-03-26`. Das ältere HTTP+SSE bietet der Server nicht an. Die CLI
stellt stdio bereit.

Mit der Berechtigung `agent.inbound_mcp.manage` können Administratoren die Servereinstellung unter
**Mole Agent → Einstellungen → Eingehendes MCP** ändern.

## Vor dem Verbindungsaufbau

1. Legen Sie unter `http.external_url` den öffentlichen Origin von MoleSignal für jede Bereitstellung fest,
   die nicht auf Loopback beschränkt ist. Siehe [Konfiguration](/de/configuration).
2. Öffnen Sie **Mole Agent → Einstellungen → Eingehendes MCP** und prüfen Sie, ob der Server aktiviert ist.
3. Kopieren Sie den vollständigen Endpunkt von der Seite, einschließlich Schema und Host.
4. Wählen Sie OAuth 2.1, ein persönliches API-Token oder ein API-Token für ein Dienstkonto.

Änderungen an Limits und Listen zulässiger Origins greifen,
sobald die nächste MCP-HTTP-Anfrage beginnt. Für eine laufende Anfrage gelten weiterhin die Einstellungen,
die bei ihrem Start aktiv waren.

## Über stdio verbinden

Melden Sie sich einmalig über die MoleSignal CLI an. Die CLI benötigt Node.js 20 oder höher:

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

Der Browser öffnet MoleSignal zur Bestätigung der Anmeldung. Die CLI speichert die Anmeldedaten in
`~/.config/molesignal/config.json`, beschränkt den Lesezugriff auf das eigene Benutzerkonto und erneuert die Anmeldedaten. Fügen Sie MoleSignal anschließend
mit dem Befehl `npx -y @molesignal/cli mcp` als stdio-Server zum Client hinzu:

| Client | Konfiguration |
|---|---|
| Claude Code | `claude mcp add --scope user molesignal -- npx -y @molesignal/cli mcp` |
| Cursor | `{"mcpServers": {"molesignal": {"command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` in `~/.cursor/mcp.json` |
| Codex | `codex mcp add molesignal -- npx -y @molesignal/cli mcp` |
| VS Code | `{"servers": {"molesignal": {"type": "stdio", "command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` in `.vscode/mcp.json` |
| Gemini CLI | `gemini mcp add molesignal npx -y @molesignal/cli mcp` |

`npx -y @molesignal/cli status` prüft die Verbindung und zählt die Tools. Wenn kein Browser
verfügbar ist, setzen Sie statt der Anmeldung die Umgebungsvariablen `MOLESIGNAL_URL` und `MOLESIGNAL_TOKEN` (ein API-Token)
für den Server. Nach der Installation mit `npm install -g @molesignal/cli` steht die CLI
als Befehl `molesignal` zur Verfügung. Unter [MoleSignal CLI](/de/cli) finden Sie alle Befehle.

Der **Einrichtungs-Prompt** unter **Mole Agent → Einstellungen → Eingehendes MCP** formuliert diese Schritte für ein Agent-Tool.
Wählen Sie oberhalb des Prompts **stdio** oder **Streamable HTTP**.

## Mit einem API-Token verbinden

API-Token eignen sich für nicht interaktive Clients und für die Automatisierung.

<Tabs>
  <Tab title="Persönliches API-Token">
    Erstellen Sie unter **Identität und Zugriff → API-Token** ein Token. Das Token nutzt die aktuelle Benutzeridentität und
    die ihr zugewiesene Rolle. Übergeben Sie das Token über die Secret-Verwaltung oder eine Umgebungsvariable des Clients als
    `Authorization: Bearer <token>`.
  </Tab>
  <Tab title="API-Token für Dienstkonten">
    Erstellen Sie unter **Identität und Zugriff → Dienstkonten** ein Dienstkonto. MoleSignal erstellt dabei automatisch
    ein an das Dienstkonto gebundenes API-Token und zeigt es einmalig im Klartext an.

    Ein Dienstkonto ist eine nicht interaktive Identität. Es kann sich nicht an der Weboberfläche anmelden und
    keine OAuth-Freigabe erteilen. Übergeben Sie das erste Token über die Secret-Verwaltung oder eine Umgebungsvariable
    des Clients als `Authorization: Bearer <token>`.
  </Tab>
</Tabs>

Committen Sie niemals ein API-Token in einer MCP-Konfigurationsdatei auf Projektebene. Die Beispiele für Codex und Claude Code
zeigen, wie Sie Umgebungsvariablen für die nicht interaktive Nutzung konfigurieren.

Eingehendes MCP akzeptiert nur persönliche API-Token, API-Token für Dienstkonten und OAuth-Zugriffstoken. Zugangsdaten für die Datenerfassung und für RUM
gewähren keinen Zugriff auf diesen Endpunkt. MoleSignal gibt Zugangsdaten niemals im Klartext über MCP-
Ressourcen, Tools, den Ausführungsverlauf oder Audit-Einträge aus.

## OAuth-Discovery und Token-Gültigkeit

MoleSignal veröffentlicht die OAuth-Metadaten unter:

```text
https://molesignal.example.com/.well-known/oauth-protected-resource/api/v1/mcp
https://molesignal.example.com/.well-known/oauth-authorization-server
```

Der Autorisierungsserver unterstützt den Authorization-Code-Flow mit PKCE `S256`, die Ressourcenbindung
nach RFC 8707, die dynamische Clientregistrierung, die Rotation von Refresh-Token und den Widerruf ganzer Token-Familien.
Zugriffstoken sind eine Stunde lang gültig. Refresh-Token erfordern den Scope `offline_access` und den
Grant-Typ `refresh_token`, sind 30 Tage lang gültig und werden bei jeder Nutzung ersetzt.

Unter **Mole Agent → Einstellungen →
Eingehendes MCP** können Sie aktive OAuth-Verbindungen prüfen und widerrufen. Darunter enthält der **Einrichtungs-Prompt** den Endpunkt dieser Bereitstellung. Wählen Sie
**Prompt kopieren** und fügen Sie den Prompt in ein Agent-Tool wie Claude Code oder Cursor ein. Das Tool fügt
MoleSignal als MCP-Server hinzu.

## Mandantengrenze verstehen

Senden Sie `userId` oder `orgId` niemals als Teil des Endpunkts, in einem benutzerdefinierten Header oder als Tool-Argument.
MoleSignal leitet beide Identitäten aus den authentifizierten Zugangsdaten ab, lädt für jede Anfrage den aktuellen IAM-
Stand und bindet die MCP-Sitzung an die Zugangsdaten, mit denen der Client sie gestartet hat.

Für die verfügbaren Tools gilt:

```text
Inbound MCP surface ∩ credential IAM permissions ∩ workspace Tool Policy
```

Agentenprofile schränken eingehendes MCP nicht ein. Dieser Endpunkt leitet keine Anfragen an ausgehende MCP-Server weiter,
die für Mole Agent konfiguriert sind, und stellt deren Remote-Tools nicht bereit.

Über eingehendes MCP gewähren keine Zugangsdaten Lesezugriff auf den [`_audit`-Stream](/de/settings/data-security#audit-stream).
Das gilt sowohl für seine Zeilen als auch für seine Felder. Öffnen Sie den Stream unter **Logs**.

## Mit den Tool-Adaptern beginnen

`tools/list` listet eine kleine Auswahl autorisierter Funktionen auf: sieben gängige Lese-Tools, Funktionen zur Steuerung von Freigabe und Ausführung
sowie drei Adapter für die schrittweise Tool-Suche.

| Adapter | Zweck |
|---|---|
| `tool_search` | Durchsuchen Sie den gesamten autorisierten Tool-Katalog für eingehendes MCP. |
| `call_read_tool` | Führen Sie ein gefundenes Lese-Tool oder ein Tool zur Vorabprüfung aus. |
| `call_managed_tool` | Führen Sie eine gefundene verwaltete Änderung aus. Geben Sie dazu den erforderlichen `idempotencyKey` an. |

Typische Prompts:

- „Suchen Sie mit den MoleSignal-Tools nach aktuellen Incidents. Fassen Sie dann den offenen Incident mit den größten Auswirkungen zusammen.“
- „Suchen Sie die Tools für Statusseiten und listen Sie aktive Incidents auf. Nehmen Sie keine Änderungen vor.“
- „Testen Sie diese Alarmregel. Aktualisieren Sie sie erst nach der erforderlichen Bestätigung oder Freigabe.“

Unter [Tool-Katalog und Ausführung](/de/tools) finden Sie die Schemas für die Tool-Suche, die Risikostufen, die Regeln für
Freigaben und die unterstützten Produktbereiche.

## Laufzeitlimits

| Limit | Standardwert | Zulässiger Bereich |
|---|---:|---:|
| Anfragegröße | 1 MB | 1–8 MB |
| Antwortgröße | 1 MB | 1–8 MB |
| Gleichzeitige HTTP-Aufrufe pro Zugangsdaten | 8 | 1–128 |
| HTTP-Aufrufe pro Minute und Zugangsdaten | 60 | 1–10.000 |
| Timeout für Lese-Tools | 30 Sekunden | 100 ms–300 Sekunden |

Ändern Sie diese Werte unter **Mole Agent → Einstellungen → Eingehendes MCP**. Die Tool-Richtlinie der Organisation kann
für einzelne Tools einen kürzeren Timeout oder eine geringere maximale Antwortgröße festlegen.

## Origin- und Host-Prüfungen für Browseranfragen

Der Server akzeptiert Anfragen von MCP-Clients außerhalb des Browsers auch ohne `Origin`-Header. Browseranfragen
müssen denselben Origin haben oder exakt mit einem in den Einstellungen für eingehendes MCP konfigurierten HTTP- oder HTTPS-Origin übereinstimmen.

Bei Bereitstellungen außerhalb der Loopback-Schnittstelle muss der `Host`-Header der Anfrage mit `http.external_url` übereinstimmen. Diese Prüfung
verhindert DNS-Rebinding-Angriffe auf lokale MCP-Server.

## Verbindungsprobleme beheben

| Symptom | Prüfung |
|---|---|
| `401 missing Authorization Bearer token` | Führen Sie `codex mcp login molesignal` aus oder konfigurieren Sie eine unterstützte Umgebungsvariable für das API-Token. |
| Die Autorisierungsseite fordert erneut zur Anmeldung auf | Verwenden Sie dasselbe Schema und denselben Host für die Weboberfläche, `http.external_url` und den MCP-Endpunkt. Verwenden Sie nicht abwechselnd `localhost` und `127.0.0.1`. |
| `duplicate field resource` | Entfernen Sie die manuell konfigurierte Option `--oauth-resource` und registrieren Sie den Endpunkt erneut. |
| Der OAuth-Callback meldet, dass die Verbindung abgelehnt wurde | Lassen Sie den MCP-Client laufen, bis der Browser zur temporären Loopback-Callback-Adresse des Clients weiterleitet. Führen Sie `codex mcp login` erneut aus, falls der Callback-Listener nicht mehr läuft. |
| Der MCP-Endpunkt gibt `403` zurück | Prüfen Sie, ob der Server aktiviert ist. Prüfen Sie außerdem den Browser-Origin, den Status der Zugangsdaten, die IAM-Berechtigung und die Tool-Richtlinie. |
| Ein Tool fehlt | Suchen Sie mit `tool_search`. Falls die Suche keinen Treffer liefert, prüfen Sie, ob das Tool für eingehendes MCP verfügbar ist, sowie die IAM-Berechtigungen und die Tool-Richtlinie. |
