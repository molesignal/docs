Öffnen Sie **Metriken**, um die in Metrik-Streams gespeicherten Zeitreihen mit PromQL abzufragen. Eine Abfrage läuft in einem
Tab; Tabs können nebeneinander stehen, und **Teilen** kopiert einen Link zur Abfrage, wie unter
[Logs](/de/logs#abfrage-tabs). Die Adressleiste enthält die zuletzt ausgeführte Anweisung, sodass eine Kopie davon
die Abfrage weitergibt.

## Metrik finden

Öffnen Sie den **Metrik-Browser** neben dem Editor oder **Metriken suchen** und geben Sie einen Teil eines Namens ein. Jede
Metrik zeigt ihren Typ (**Counter**, **Histogramm** oder **Gauge**) und wie viele Labels und Felder sie hat.
Wählen Sie eine Metrik aus, um sie in die Abfrage einzufügen und diese auszuführen. Ein leerer Arbeitsbereich bietet **Metrikquelle
verbinden**; siehe [Datenquelle](/de/intake).

Eine Metrik, die innerhalb der Aufbewahrungsdauer ihres Streams nicht gesehen wurde, wird aus der Liste entfernt.

## Abfrage schreiben

Der Editor hat zwei Modi, die über die beiden Symbole neben dem Titel umgeschaltet werden (`</>` für Code, die Blöcke für den Editor):

- **Code**: PromQL direkt schreiben. **Häufig verwendete PromQL-Funktionen** führen die üblichen Funktionen auf; die
  [PromQL-Support-Matrix](/de/query/promql-subset) listet alle implementierten Funktionen auf.
- **Editor**: **Metrik** wählen, für jedes Label, das übereinstimmen soll, **Label-Filter hinzufügen**, eine **Funktion**
  (**Unverarbeitete Metrik**, **Rate**, **Momentane Rate** oder **Anstieg**), eine **Aggregation** (**Summe**,
  **Durchschnitt**, **Maximum** oder **Minimum**) und den **Zeitraum**. Das daraus erzeugte PromQL wird unten angezeigt.
  Ein Ausdruck, den der Editor nicht darstellen kann, etwa eine Funktion mit zusätzlichen Parametern, bleibt
  unverändert, bis ein Feld im Editor geändert wird.

```promql
sum by (service_name) (
  rate(http_server_request_duration_seconds_count[5m])
)
```

Klicken Sie auf **Ausführen**. **Optionen** legen fest, wie die Abfrage ausgeführt wird:

| Option | Auswahl |
|---|---|
| **Legende** | **Automatisch**, **Ausführlich** (jedes Label) oder **Benutzerdefiniert** mit einer Vorlage wie `{{service}}`. |
| **Formatieren** | **Zeitreihe** oder **Tabelle**. |
| **Schrittweite** | **automatisch**, wodurch der Zeitraum in 1.000 Schritte unterteilt wird, oder eine Dauer wie `30s` oder `5m`. |
| **Typ** | **Zeitraum** für ein Diagramm über den Zeitraum oder **Momentanabfrage** für den Wert an dessen Ende. |
| **Exemplare** | **Aktiv** zeichnet die Exemplare, die Punkte mit Traces verknüpfen. |

**Zum Dashboard hinzufügen** öffnet ein neues Dashboard mit der Abfrage als erstem Panel. **Abfrage leeren** leert
den Editor. Wenn eine gültige Abfrage nichts findet, helfen **Zeitraum vervierfachen** und **Filter entfernen und erneut versuchen**,
bevor der Ausdruck geändert wird.

## Diagramm lesen

- Ziehen Sie über die Zeichenfläche, um in einen Zeitraum hineinzuzoomen, ziehen Sie die X-Achse zum Verschieben und doppelklicken Sie zum Herauszoomen.
  **Zeitraum zurücksetzen** stellt den Zeitraum wieder her, der vor der Interaktion mit dem Diagramm galt.
- Wählen Sie den **Darstellungsstil** (**Linie**, **Balken** oder **Punkte**) und **Stapelung** (**Aus**, **Normal** oder
  **Prozent**; Stapelung erfordert mindestens zwei Zeitreihen).
- Nutzen Sie die Legende, um Zeitreihen zu isolieren oder zu vergleichen.
- **Vergleichen** legt dieselbe Abfrage über eine Basislinie im Diagramm, jede Zeitreihe gestrichelt in eigener Farbe:
  den gleich langen Zeitraum davor (Standard), denselben Zeitraum einen Tag oder eine Woche früher oder einen
  eigenen Zeitraum. Die Stapelung ist aus, solange eine Basislinie angezeigt wird; die Schaltfläche zum Schließen neben der
  Basislinie entfernt sie. Momentanabfragen haben keine Basislinie.
- Bei aktivierten Exemplaren wählen Sie eine Raute aus, um den zugehörigen Trace anzuzeigen, und klicken Sie auf **Trace öffnen**, um die Anfrage
  hinter dem Punkt zu prüfen.

Der gezoomte Zeitraum wird beim Wechsel zu Traces oder Logs übernommen.

## Ergebnis analysieren

**Diagramm**, **Tabelle** und **Abfrage-Inspektor** zeigen das Ergebnis als Diagramm, als Rohzeilen und als die Abfrage,
die ausgeführt wurde. Die Panels rund um das Ergebnis erläutern die Daten:

| Panel | Zeigt |
|---|---|
| **Zeitreihen** | Jede Zeitreihe mit ihren Labels sowie ihrem letzten, aktuellen, durchschnittlichen und maximalen Wert. |
| **Abfragestatistiken** | Zeitreihen, Datenpunkte, gescannte Zeilen, Abfragezeit, Zeitraum und Schrittweite. |
| **Datenqualität** | Negative Punkte, fehlende Daten und Zeitstempel-Anomalien. Ein Counter mit negativen Raten wurde zurückgesetzt, kam in falscher Reihenfolge an oder hat den falschen Typ: **Anomalien anzeigen**, **Rohdaten anzeigen** oder **Metriktyp prüfen**. |
| **Top-Labels** | Die Label-Werte, die im Ergebnis am stärksten ins Gewicht fallen. |
| **Statistische Zusammenfassung** | Die Verteilung der Werte aller Zeitreihen. |
| **Kardinalität** | Die aktiven Zeitreihen der Metrik mit den gescannten Zeilen. Damit finden Sie Labels, die zu viele Zeitreihen erzeugen. |
| **Ergebnisschema** | Die Spalten für Zeit, Wert und Label des Ergebnisses. |

Die [Metrik-Kardinalitätsgrenzen](/de/settings/platform#metrikkardinalität) der Instanz weisen neue
Zeitreihen jenseits eines Limits zurück; prüfen Sie daher **Kardinalität**, bevor Sie ein Label mit vielen Werten hinzufügen.

## Metrikspitze korrelieren

Wählen Sie das Zeitfenster der Spitze aus, behalten Sie die Service- und Umgebungs-Labels bei und öffnen Sie dann die zugehörigen Traces
oder Logs. MoleSignal übernimmt den ausgewählten Zeitraum in das nächste Signal. Siehe
[Signalübergreifende Korrelation](/de/correlation).

## Berechtigungen

Das Auflisten von Metriken erfordert `metrics.read`. Das Ausführen von PromQL erfordert `streams.query`. **Zum Dashboard hinzufügen**
erfordert `dashboards.create`.
