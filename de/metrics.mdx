Öffnen Sie **Metriken**, um die in Metrik-Streams gespeicherten Zeitreihen mit PromQL abzufragen. Jede Abfrage läuft in einem
Tab. Tabs können nebeneinander stehen, und **Teilen** kopiert wie unter
[Logs](/de/logs#abfrage-tabs) einen Link zur Abfrage. Die Adressleiste enthält die zuletzt ausgeführte Abfrage. Kopieren Sie die Adresse,
um die Abfrage zu teilen.

## Metrik finden

Öffnen Sie den **Metrik-Browser** neben dem Editor oder wählen Sie **Metriken suchen**. Geben Sie einen Teil des Namens ein. Zu jeder
Metrik erscheinen der Typ (**Counter**, **Histogramm** oder **Gauge**) und die Anzahl der Labels und Felder.
Wählen Sie eine Metrik aus, um sie in die Abfrage einzufügen und die Abfrage auszuführen. In einem leeren Arbeitsbereich steht **Metrikquelle
verbinden** zur Verfügung. Siehe [Datenquelle](/de/intake).

Wenn innerhalb der Aufbewahrungsdauer des Streams keine neuen Daten für eine Metrik eingehen, verschwindet sie aus der Liste.

## Abfrage schreiben

Der Editor hat zwei Modi. Wechseln Sie über die beiden Symbole neben dem Titel zwischen den Modi (`</>` für Code, die Blöcke für den Editor):

- **Code**: Schreiben Sie PromQL direkt. **Häufig verwendete PromQL-Funktionen** listet die gängigen Funktionen auf. Die
  [PromQL-Unterstützungsmatrix](/de/query/promql-subset) führt alle implementierten Funktionen auf.
- **Editor**: Wählen Sie die **Metrik** aus. Verwenden Sie **Label-Filter hinzufügen** für jedes Label, nach dem Sie filtern möchten. Wählen Sie eine **Funktion**
  (**Unverarbeitete Metrik**, **Rate**, **Momentane Rate** oder **Anstieg**), eine **Aggregation** (**Summe**,
  **Durchschnitt**, **Maximum** oder **Minimum**) und den **Zeitraum**. Darunter erscheint der erzeugte PromQL-Ausdruck.
  Kann der Editor einen Ausdruck nicht abbilden, etwa eine Funktion mit zusätzlichen Parametern, bleibt der Ausdruck unverändert,
  bis Sie ein Feld im Editor ändern.

```promql
sum by (service_name) (
  rate(http_server_request_duration_seconds_count[5m])
)
```

Klicken Sie auf **Ausführen**. Unter **Optionen** legen Sie fest, wie MoleSignal die Abfrage ausführt:

| Option | Auswahl |
|---|---|
| **Legende** | **Automatisch**, **Ausführlich** (alle Labels) oder **Benutzerdefiniert** mit einer Vorlage wie `{{service}}`. |
| **Formatieren** | **Zeitreihe** oder **Tabelle**. |
| **Schrittweite** | **automatisch** teilt den Zeitraum in 1.000 Schritte. Alternativ können Sie eine Dauer wie `30s` oder `5m` angeben. |
| **Typ** | **Zeitraum** für ein Diagramm über den gesamten Zeitraum oder **Momentanabfrage** für den Wert am Ende des Zeitraums. |
| **Exemplare** | **Aktiv** zeigt Exemplare an, die Datenpunkte mit Traces verknüpfen. |

**Zum Dashboard hinzufügen** öffnet ein neues Dashboard mit der Abfrage als erstem Panel. **Abfrage leeren** leert
den Editor. Liefert eine gültige Abfrage keine Ergebnisse, probieren Sie **Zeitraum vervierfachen** oder **Filter entfernen und erneut versuchen** aus,
bevor Sie den Ausdruck ändern.

## Diagramm lesen

- Ziehen Sie über die Diagrammfläche, um einen Zeitraum zu vergrößern. Ziehen Sie die X-Achse zum Verschieben und doppelklicken Sie zum
  Herauszoomen. **Zeitraum zurücksetzen** stellt den ursprünglichen Zeitraum wieder her.
- Wählen Sie den **Darstellungsstil** (**Linie**, **Balken** oder **Punkte**) und die **Stapelung** (**Aus**, **Unauffällig** oder
  **Prozent**. Für die Stapelung sind mindestens zwei Zeitreihen nötig).
- Blenden Sie über die Legende einzelne Zeitreihen ein oder vergleichen Sie mehrere.
- Wählen Sie bei aktivierten Exemplaren eine Raute aus, um den zugehörigen Trace anzuzeigen. Wählen Sie **Trace öffnen**, um die Anfrage
  hinter dem Datenpunkt zu prüfen.

Beim Wechsel zu Traces oder Logs übernimmt MoleSignal den eingezoomten Zeitraum.

## Ergebnis analysieren

**Diagramm** und **Tabelle** zeigen das Ergebnis als Diagramm bzw. als Rohdatenzeilen. Der **Abfrage-Inspektor** zeigt die Abfrage,
die MoleSignal ausgeführt hat. Die Panels rund um das Ergebnis erläutern die Daten:

| Panel | Inhalt |
|---|---|
| **Zeitreihen** | Jede Zeitreihe mit ihren Labels und dem letzten, aktuellen, durchschnittlichen und maximalen Wert. |
| **Abfragestatistiken** | Zeitreihen, Datenpunkte, gescannte Zeilen, Abfragedauer, Zeitraum und Schrittweite. |
| **Datenqualität** | Negative Datenpunkte, fehlende Daten und Zeitstempelanomalien. Negative Raten können darauf hindeuten, dass ein Counter zurückgesetzt wurde, Werte in falscher Reihenfolge eingingen oder der Typ nicht stimmt: **Anomalien anzeigen**, **Rohdaten anzeigen** oder **Metriktyp prüfen**. |
| **Top-Labels** | Die Label-Werte mit dem größten Gewicht im Ergebnis. |
| **Statistische Zusammenfassung** | Die Verteilung der Werte aller Zeitreihen. |
| **Kardinalität** | Die aktiven Zeitreihen der Metrik und die gescannten Zeilen. Ermitteln Sie damit, welche Labels zu viele Zeitreihen erzeugen. |
| **Ergebnisschema** | Die Spalten für Zeit, Wert und Labels im Ergebnis. |

Die [Kardinalitätslimits für Metriken](/de/settings/platform#metrikkardinalität) der Instanz begrenzen die Anzahl der Zeitreihen. Sobald die Instanz ein Limit erreicht, lehnt sie weitere
Zeitreihen ab. Prüfen Sie daher **Kardinalität**, bevor Sie ein Label mit vielen Werten hinzufügen.

## Metrikspitze mit anderen Signalen korrelieren

Wählen Sie den Zeitraum der Spitze aus und behalten Sie die Labels für Dienst und Umgebung bei. Öffnen Sie anschließend die zugehörigen Traces
oder Logs. MoleSignal übernimmt den ausgewählten Zeitraum beim Wechsel zum nächsten Signal. Siehe
[Signalübergreifende Korrelation](/de/correlation).

## Berechtigungen

Zum Auflisten von Metriken benötigen Sie `metrics.read`. Zum Ausführen von PromQL-Abfragen benötigen Sie `streams.query`. **Zum Dashboard hinzufügen**
erfordert `dashboards.create`.
