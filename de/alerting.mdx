Öffnen Sie **Alarme**, um erkannte Vorfälle zu bestätigen, zu eskalieren und zu beheben. Eine
[Regel](/de/alerting/rules) überwacht eine Abfrage oder eine Kennzahl und eröffnet einen [Vorfall](/de/alerting/incidents),
wenn die Bedingung erfüllt ist. Eine [Alarmquelle](/de/alerting/sources) eröffnet einen Vorfall, wenn ein anderes
System einen Alarm sendet. Das [Alarm-Routing](/de/alerting/routing) weist einem neuen
Vorfall ein Team und eine Eskalationsregel zu. Die [Eskalationsregel](/de/alerting/on-call#eskalationsrichtlinien) des
Vorfalls alarmiert die eingetragenen Personen und die Bereitschaft laut den angegebenen [Bereitschaftsplänen](/de/alerting/on-call#bereitschaftspläne).
Bleibt eine Bestätigung aus, folgt die nächste Eskalationsstufe. [Benachrichtigungskanäle](/de/notification-channels) stellen jede
Alarmbenachrichtigung zu. [Stummschaltungen](/de/alerting/silences) setzen Benachrichtigungen während der Wartung aus.
[Semantische Gruppen](/de/alerting/silences#semantische-gruppen) fassen zusammengehörige Vorfälle zusammen.

## Die Alarmzentrale

Das Seitenmenü gliedert die Seiten nach ihrem Zweck in fünf Gruppen. Klappen Sie das Menü über die
Suchleiste ein, damit die Seite die gesamte Breite nutzen kann.

| Gruppe | Seite | Zweck | Anleitung |
|---|---|---|---|
| Reagieren | **Vorfälle** | Aktive Vorfälle bestätigen, stummschalten, beheben und untersuchen. | [Vorfälle](/de/alerting/incidents) |
|  | **Verlauf** | Vergangene Vorfälle nach Dienst und Status durchsuchen. | [Verlauf](/de/alerting/incidents#verlauf) |
|  | **Postmortems** | Interne Postmortems zu Vorfällen, daraus abgeleitete Maßnahmen und Einstellungen für schwerwiegende Vorfälle. | [Schwerwiegende Vorfälle und Postmortems](/de/alerting/major-incidents) |
|  | **Erkenntnisse** | Anzahl der Vorfälle, Wiederherstellungszeit, Regeln mit vielen Alarmen, betroffene Dienste, Reaktion auf Vorfälle und Auslastung der Bereitschaft. | [Erkenntnisse](/de/alerting/incidents#erkenntnisse) |
| Erkennen | **Regeln** | Schwellenwert-, Prognose-, Ausreißer-, kombinierte und Heartbeat-Regeln sowie Anomalie- und Echtzeitregeln. | [Alarmregeln](/de/alerting/rules) |
|  | **Erkennung** | Probleme ohne Regel erkennen: plötzliche Änderungen bei APM-Diensten, Leistungsverschlechterungen in neuen Versionen, neue und wiederkehrende Frontend-Fehler, sprunghafte Anstiege bei Fehlerlogs und Probleme auf Hosts. | [Erkennung](/de/alerting/discovery) |
|  | **Quellen** | Eingehende Alarme von Alertmanager, Grafana, Datadog, PagerDuty, Zabbix und Cloud-Monitoring-Diensten (Alibaba Cloud, Tencent Cloud, Amazon CloudWatch) sowie per E-Mail oder API. | [Externe Alarme](/de/alerting/sources) |
| Alarmflut reduzieren | **Gruppen** | Semantische Gruppen fassen zusammengehörige Vorfälle zusammen. | [Semantische Gruppen](/de/alerting/silences#semantische-gruppen) |
|  | **Unterdrückung** | Unterdrückt Benachrichtigungen zu weniger schwerwiegenden Vorfällen, solange ein schwerwiegenderer oder vorgelagerter Vorfall aktiv ist. | [Unterdrückung](/de/alerting/inhibition) |
|  | **Stummschaltungsregeln** | Benachrichtigungen für passende Vorfälle aussetzen. | [Stummschaltungsregeln](/de/alerting/silences#stummschaltungsregeln) |
| Benachrichtigen | **Routing** | Team und Eskalationsregel für neue Vorfälle festlegen. | [Alarm-Routing](/de/alerting/routing) |
|  | **Eskalationen** | Festlegen, wer in welcher Reihenfolge alarmiert wird und wann die nächste Eskalationsstufe beginnt. | [Eskalationsregeln](/de/alerting/on-call#eskalationsrichtlinien) |
|  | **Bereitschaftspläne** | Rotationen, vorübergehende Vertretungen, Schichttausch und Kalenderabonnements. | [Bereitschaftspläne](/de/alerting/on-call#bereitschaftspläne) |
| Nachverfolgen | **Fehlerbehebung** | Maßnahmen über HTTP oder Kubernetes mit einem Klick am Vorfall anstoßen und nach Freigabe ausführen. | [Fehlerbehebung](/de/alerting/remediation) |
|  | **Tickets** | Integrationen mit Jira, ServiceNow oder Meegle erstellen Tickets für Vorfälle und synchronisieren den Ticketstatus. | [Tickets](/de/alerting/tickets) |

Statusseiten informieren über Vorfälle und Wartungsarbeiten. Sie bilden ein eigenes Modul. Siehe
[Statusseiten](/de/status-pages).

## Alarmierung einrichten

Richten Sie einen Arbeitsbereich für die erste Alarmbenachrichtigung üblicherweise in dieser Reihenfolge ein:

<Steps>
  <Step title="Benachrichtigungskanal verbinden">
    Konfigurieren Sie einen Konnektor für E-Mail, einen Messenger oder Telefon und SMS unter
    [Einstellungen → Benachrichtigungen → Konnektoren](/de/notification-channels). Lassen Sie die Mitglieder ihre
    persönlichen Benachrichtigungswege unter [Kontoeinstellungen → Benachrichtigungen](/de/account#benachrichtigungen) verknüpfen.
  </Step>
  <Step title="Bereitschaftsplan erstellen">
    Erstellen Sie einen [Bereitschaftsplan](/de/alerting/on-call#bereitschaftsplan-erstellen) mit der Rotation des Teams.
  </Step>
  <Step title="Standard-Eskalationsregel erstellen">
    Erstellen Sie eine Eskalationsregel namens `default`, die zuerst die Bereitschaft laut Plan und danach die Leitung alarmiert. Für Regeln aus dem
    Regeleditor gilt diese Eskalationsregel, wenn das [Routing](/de/alerting/routing) keine Bereitschaftsregel für das Team findet. Siehe [Die Standard-Eskalationsregel](/de/alerting/on-call#die-standardrichtlinie).
  </Step>
  <Step title="Regeln erstellen und testen">
    Wählen Sie eine Vorlage im [Regeleditor](/de/alerting/rules#schwellenwertregel-erstellen), testen Sie die Regel mit
    echten Daten und speichern Sie sie.
  </Step>
  <Step title="Ablauf proben">
    Lösen Sie mit [Regel auslösen](/de/api/alerting/trigger-rule) gezielt eine Regel aus. Prüfen Sie, ob die
    Alarmbenachrichtigung ankommt, die nächste Eskalationsstufe greift und die Bestätigung die Eskalation stoppt.
  </Step>
</Steps>

In [Alarme in der Produktion handlungsorientiert gestalten](/de/best-practices/actionable-alerts) und
[Bereitschaft und Benachrichtigungen einrichten](/de/best-practices/on-call-setup) finden Sie Empfehlungen dazu, wann Alarme sinnvoll sind
und wie Sie sie weiterleiten.

## Berechtigungen

| Berechtigung | Funktion |
|---|---|
| `alerts.incidents.read` | Vorfälle, den Verlauf und Erkenntnisse lesen. |
| `alerts.incidents.acknowledge` | Vorfälle und Vorfallgruppen bestätigen, beheben und zurückstellen. |
| `alerts.incidents.update` | Vorfälle neu zuweisen, Beteiligte hinzufügen, den Schweregrad ändern, Notizen schreiben und die Vorfallreaktion koordinieren: Rollen, Aufgaben und Statusmeldungen. |
| `alerts.incidents.escalate` | Vorfälle eskalieren, zusammenführen und als schwerwiegend einstufen. |
| `alerts.incidents.create`, `alerts.incidents.silence` | Vorfälle manuell eröffnen und stummschalten. |
| `alerts.incidents.remediate`, `alerts.incidents.tickets`, `alerts.incidents.rca` | Die Fehlerbehebung für einen Vorfall starten, Tickets erstellen und die Grundursache dokumentieren. |
| `alerts.rules.read`, `alerts.rules.manage` | Regeln lesen, erstellen und ändern. |
| `alerts.routing.read`, `alerts.routing.manage` | Routing-Regeln und Bereitschaftsregeln für Teams lesen und ändern. |
| `alerts.escalations.read`, `alerts.escalations.manage`, `alerts.escalations.delete` | Eskalationsregeln lesen, ändern und löschen. |
| `alerts.sources.read`, `alerts.sources.manage` | Alarmquellen lesen und ändern. |
| `alerts.mutes.read`, `alerts.mutes.manage` | Stummschaltungen lesen, erstellen, ändern und entfernen. |
| `alerts.inhibitions.read`, `alerts.inhibitions.manage` | Unterdrückungsregeln lesen, erstellen, ändern und löschen. |
| `alerts.semantic_groups.manage` | Gruppen verwalten. |
| `alerts.remediation.read`, `alerts.remediation.manage` | Maßnahmen zur Fehlerbehebung lesen und definieren. |
| `alerts.tickets.read`, `alerts.tickets.manage` | Ticket-Konnektoren lesen und verwalten. |
| `alerts.response.read`, `alerts.response.manage` | Einstellungen für schwerwiegende Vorfälle lesen und ändern. |
| `alerts.discovery.read` | Ergebnisse der Erkennung lesen. |
| `schedules.read` | Bereitschaftspläne und eingeteilte Personen einsehen. |
| `schedules.create`, `schedules.update`, `schedules.delete` | Bereitschaftspläne und deren Rotationen erstellen, ändern und löschen. |
| `schedules.overrides.manage`, `schedules.swaps.request`, `schedules.swaps.approve` | Schichten übernehmen sowie Schichttausch anfragen, genehmigen oder ablehnen. |
| `postmortems.read`, `postmortems.manage` | Postmortems lesen sowie Postmortems und zugehörige Maßnahmen verfassen. |
