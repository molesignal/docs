MoleSignal bietet derzeit drei Webhook-Konnektortypen: Slack-Webhook, Lark-Webhook und einen
generischen JSON-Webhook. Erstellen Sie Webhook-Konnektoren unter **Einstellungen → Benachrichtigungen → Konnektoren**.

Lesen Sie zuerst [Benachrichtigungskanäle und Zustellung](/de/notification-channels), um Identitäten zu verknüpfen,
Richtlinien zu erstellen, Ausweichrouten einzurichten oder den Zustellverlauf einzusehen.

## Webhook-Typen vergleichen

| Konnektor | Anfrageformat | Authentifizierung | Zieltypen |
|---|---|---|---|
| `slack_webhook` | `{ "text": "..." }` | Zugangsdaten in der Webhook-URL | `fixed_group`, `webhook` |
| `lark_webhook` | Lark `msg_type: text` | Zugangsdaten in der URL, optionale Signatur | `fixed_group`, `webhook` |
| `webhook` | MoleSignal-Ereignis als JSON oder Inhalt der Benachrichtigungsvorlage | Benutzerdefinierte JSON-Header, optionale Signatur | Alle Zieltypen |

Bei `fixed_group` sendet der Konnektor an die konfigurierte URL. Bei `webhook` muss der Zielwert
eine absolute URL sein und ersetzt die konfigurierte URL für diese Zustellung.

## Slack-Webhook

Konfigurieren Sie eine URL für den eingehenden Webhook und ein Timeout von 1 bis 60 Sekunden:

```json
{
  "webhookUrl": "https://hooks.slack.com/services/T000/B000/secret",
  "timeoutSecs": 10
}
```

MoleSignal kombiniert den Nachrichtentitel mit dem Markdown-Inhalt und sendet Folgendes:

```json
{
  "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
}
```

Ein HTTP-Statuscode im Bereich 2xx gilt als Erfolg. Bei jeder anderen Antwort oder bei einem Timeout markiert MoleSignal die Zustellung als fehlgeschlagen.

## Lark-Webhook

Konfigurieren Sie die URL eines benutzerdefinierten Bots in Lark oder Feishu. Geben Sie den Signaturschlüssel des Bots nur an, wenn die
Signaturprüfung aktiviert ist:

```json
{
  "webhookUrl": "https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx",
  "secret": "replace-with-signing-secret",
  "timeoutSecs": 10
}
```

Ohne Signaturschlüssel sendet MoleSignal Folgendes:

```json
{
  "msg_type": "text",
  "content": {
    "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
  }
}
```

Mit einem Signaturschlüssel erzeugt MoleSignal einen Unix-Zeitstempel in Sekunden, bildet
`timestamp + "\n" + secret`, verwendet diesen Wert als HMAC-SHA256-Schlüssel für eine leere Nachricht und
kodiert den resultierenden Hashwert in Base64. Die Anfrage enthält beide Felder:

```json
{
  "timestamp": "1599360473",
  "sign": "base64-signature",
  "msg_type": "text",
  "content": {
    "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
  }
}
```

MoleSignal verlangt sowohl einen HTTP-Erfolgsstatus als auch den Wert null in `code` oder `status_code` in der
Lark-Antwort.

<Note>
  Halten Sie die Systemuhr des MoleSignal-Servers synchron. Lark lehnt signierte Anfragen mit veraltetem Zeitstempel ab.
</Note>

## Generischer Webhook

Konfigurieren Sie die Standard-URL, die Methode, den Anfrageinhalt, den Signaturschlüssel, die Header und das Timeout:

```json
{
  "url": "https://notify.example.com/molesignal",
  "method": "post",
  "body": "event",
  "signingSecret": "<at-least-16-characters>",
  "headers": {
    "X-Environment": "production"
  },
  "timeoutSecs": 10
}
```

Als Methode sind `post`, `put` und `patch` zulässig. Header-Namen und -Werte müssen der HTTP-Syntax entsprechen.
`Content-Type` und die unten aufgeführten Namen nach dem Muster `X-MoleSignal-*` sind als Header-Namen nicht zulässig.

### Anfrageinhalt

Wenn `body` auf `event` steht (Standardwert, in der Konsole **MoleSignal-Ereignis**), enthält die Anfrage
maschinenlesbares JSON:

```json
{
  "version": 2,
  "event": {
    "id": "alert.triggered:3KEDNEyqouYJeBDTLTMTBui7XHW",
    "type": "alert.triggered",
    "occurredAt": "2026-10-28T08:00:00Z",
    "organizationId": "<organization-id>"
  },
  "alert": {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "status": "open",
    "severity": "critical",
    "title": "High error rate · checkout",
    "url": "https://molesignal.example.com/alerts/incidents/3KEDNEyqouYJeBDTLTMTBui7XHW",
    "startedAt": "2026-10-28T08:00:00Z",
    "acknowledgedAt": null,
    "resolvedAt": null,
    "acknowledgedBy": null,
    "resolvedBy": null,
    "assignees": ["<user-id>"],
    "teamId": "<team-id>",
    "service": "checkout",
    "environment": "production",
    "affectedServices": ["checkout"],
    "labels": { "service": "checkout", "env": "production" },
    "annotations": { "runbook_url": "https://runbooks.example.com/checkout" },
    "value": 120.0,
    "threshold": 50.0
  },
  "rule": { "id": "<rule-id>", "name": "High error rate", "description": "Share of 5xx answers." },
  "target": { "type": "fixed_group", "value": "platform-oncall", "metadata": {} },
  "message": {
    "title": "[CRITICAL] High error rate · checkout",
    "text": "The error rate exceeded 5%.",
    "markdown": "**Checkout** error rate exceeded 5%.",
    "html": null,
    "metadata": { "event_type": "alert.triggered", "alert_id": "3KEDNEyqouYJeBDTLTMTBui7XHW" }
  }
}
```

| Feld | Inhalt |
|---|---|
| `version` | Die Version der Struktur des Anfrageinhalts, derzeit `2`. Die Schlüssel dieser Struktur nutzen camelCase; `data` enthält weiterhin die unveränderten Ereignisattribute. MoleSignal fügt Felder nur hinzu und erhöht die Version nur bei Änderungen, die die Kompatibilität mit bestehenden Empfängern brechen. |
| `event` | `id`, `type` (zum Beispiel `alert.triggered`, `alert.escalated`, `oncall.shift.starting`), `occurredAt` und `organizationId` der Benachrichtigung. |
| `alert` | Nur bei Alarmbenachrichtigungen: Status, Schweregrad, Titel, URL des Vorfalls (wenn `http.external_url` gesetzt ist), Zeitpunkte von Beginn, Bestätigung und Behebung, zugewiesene Personen, Team, Dienst, Umgebung, Labels, Annotationen, Wert und Schwellenwert. Zeitangaben folgen RFC 3339 in UTC. MoleSignal gibt Personen und Teams als IDs an. |
| `rule` | Die Regel des Alarms: `id`, `name`, `description`. |
| `escalation` | Nur bei Eskalationsbenachrichtigungen: `step`, `loop`, `reason` (Grund für den Versand; siehe [Auf einen Vorfall reagieren](/de/alerting/incidents#maßnahmen-für-einen-vorfall)) und `target` (`kind` und `id`). |
| `data` | Bei Benachrichtigungen ohne Alarm, etwa bei einer Bereitschaftsübergabe oder fehlender Besetzung: die unveränderten Ereignisattribute. |
| `target` | Das Ziel dieser Zustellung: `type`, `value`, `metadata`. |
| `message` | Die gerenderte Nachricht: `title`, `text`, `markdown`, `html`, `metadata`. |

Wenn `body` auf `template` steht (**Inhalt der Benachrichtigungsvorlage**), sendet MoleSignal die Vorlage, die die Benachrichtigungsrichtlinie
für den Webhook-Kanal auswählt, im vorgegebenen Format: JSON-Vorlagen als `application/json` mit als JSON-Strings escapten Werten,
andere Formate als `text/plain; charset=utf-8`. Wenn die Richtlinie keine Vorlage für den
Webhook-Kanal vorgibt, sendet MoleSignal den Inhalt der allgemeinen Vorlage oder der Nachricht des Ereignisses. Hinweise zum Schreiben von Vorlagen finden Sie unter
[Bedingungen](/de/notification-channels#bedingungen).

### Header und Signatur

| Header | Inhalt |
|---|---|
| `Content-Type` | `application/json` oder `text/plain; charset=utf-8` für Vorlageninhalte in einem anderen Format als JSON. |
| `X-MoleSignal-Event` | Der Benachrichtigungstyp, identisch mit `event.type`. |
| `X-MoleSignal-Delivery` | Die ID dieser Zustellung. Anhand dieser ID kann der Empfänger wiederholte Anfragen verwerfen. |
| `X-MoleSignal-Timestamp` | Nur mit Signaturschlüssel: der Unix-Zeitstempel des Versands in Sekunden. |
| `X-MoleSignal-Sign` | Nur mit Signaturschlüssel: `sha256=<hex>`, der mit dem Signaturschlüssel berechnete HMAC-SHA256-Wert von `<timestamp>.<body>`. |

Der Empfänger berechnet die Signatur mit demselben Schlüssel und dem unveränderten Anfrageinhalt erneut, vergleicht sie in konstanter Zeit mit
`X-MoleSignal-Sign` und lehnt die Anfrage ab, wenn der Zeitstempel zu stark von der aktuellen Zeit abweicht, etwa um mehr als 5
Minuten. Verwenden Sie zur Berechnung die unveränderten Bytes, nicht eingelesenes und neu serialisiertes JSON:

<CodeGroup>
```python Python
import hashlib, hmac, time

def verify(secret: str, headers, body: bytes, tolerance: int = 300) -> bool:
    timestamp = headers.get("X-MoleSignal-Timestamp", "")
    signature = headers.get("X-MoleSignal-Sign", "")
    if not timestamp.isdigit() or abs(time.time() - int(timestamp)) > tolerance:
        return False
    mac = hmac.new(secret.encode(), timestamp.encode() + b"." + body, hashlib.sha256)
    return hmac.compare_digest("sha256=" + mac.hexdigest(), signature)
```

```javascript Node.js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verify(secret, headers, body, toleranceSecs = 300) {
  const timestamp = headers['x-molesignal-timestamp'] ?? '';
  const signature = Buffer.from(headers['x-molesignal-sign'] ?? '');
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSecs) return false;
  const expected = Buffer.from(
    'sha256=' + createHmac('sha256', secret).update(`${timestamp}.`).update(body).digest('hex'),
  );
  return expected.length === signature.length && timingSafeEqual(expected, signature);
}
```

```go Go
import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"net/http"
	"strconv"
	"time"
)

func verify(secret string, r *http.Request, body []byte, tolerance time.Duration) bool {
	timestamp := r.Header.Get("X-MoleSignal-Timestamp")
	seconds, err := strconv.ParseInt(timestamp, 10, 64)
	if err != nil || time.Since(time.Unix(seconds, 0)).Abs() > tolerance {
		return false
	}

	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(timestamp + "."))
	mac.Write(body)
	expected := "sha256=" + hex.EncodeToString(mac.Sum(nil))

	return hmac.Equal([]byte(expected), []byte(r.Header.Get("X-MoleSignal-Sign")))
}
```
</CodeGroup>

Ein Signaturschlüssel hat mindestens 16 Zeichen. Erzeugen Sie ihn zum Beispiel mit `openssl rand -hex 32`. Für HTTP-Ziele
von Konnektoren verwendet MoleSignal dasselbe Signaturverfahren. Siehe [Konnektoren](/de/connectors).

### Antworten und ausgehende Anfragen

Jede 2xx-Antwort gilt als Erfolg. Enthält die Antwort `X-Request-ID`, speichert MoleSignal den Header-Wert
als Nachrichten-ID des Anbieters. MoleSignal verbindet sich nur mit Adressen, zu denen der Hostname aufgelöst wird,
blockiert Cloud-Metadatenadressen und folgt keinen Weiterleitungen. MoleSignal führt Webhook-Benachrichtigungen nie
[zusammen](/de/notification-channels#benachrichtigungen-bündeln).

## Über die API erstellen und testen

Erstellen Sie einen generischen Webhook-Konnektor:

```bash
curl -X POST "$MOLESIGNAL_URL/api/v1/notify/connectors" \
  -H "Authorization: Bearer $MS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "platform webhook",
    "connectorType": "webhook",
    "enabled": true,
    "config": {
      "url": "https://notify.example.com/molesignal",
      "method": "post",
      "body": "event",
      "signingSecret": "<at-least-16-characters>",
      "headers": {"Authorization": "Bearer <token>"},
      "timeoutSecs": 10
    }
  }'
```

Speichern Sie die zurückgegebene `id` des Konnektors und senden Sie dann eine Testanfrage:

```bash
curl -X POST "$MOLESIGNAL_URL/api/v1/notify/connectors/$CONNECTOR_ID/test" \
  -H "Authorization: Bearer $MS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "targetType": "fixed_group",
    "target": "platform-oncall",
    "message": {
      "title": "MoleSignal connector test",
      "text": "Webhook delivery is working."
    }
  }'
```

Beim Auflisten, Lesen, Erstellen und Aktualisieren von Konnektoren gibt die API sensible Konfigurationsfelder als `***` zurück.
Senden Sie beim Aktualisieren eines vorhandenen Konnektors den Wert `***` unverändert, um das gespeicherte Geheimnis beizubehalten.

## Sicherheit und Einschränkungen

- MoleSignal verschlüsselt die gesamte Konnektorkonfiguration bei der Speicherung.
- API-Antworten maskieren `url`, `webhookUrl`, `headers`, `secret`, `signingSecret`, Token und Passwörter.
- Behandeln Sie eine Webhook-URL wie Zugangsdaten, auch wenn kein zusätzliches Geheimnis konfiguriert ist.
- Verwenden Sie bevorzugt `https`. Verwenden Sie `http` nur in einem vertrauenswürdigen Netzwerk.
- Beschränken Sie ausgehende Verbindungen von MoleSignal auf die erforderlichen Konnektorziele.
- Ein deaktivierter Konnektor kann weder Testanfragen noch Benachrichtigungen senden.

<Note>
  DingTalk, WeCom, Teams, Google Chat, Telegram, Discord, Mattermost, Webex, Matrix, PagerDuty und
  Amazon SNS haben eigene Konnektoren. Siehe
  [Einzelne Anbieter konfigurieren](/de/notification-channels#einzelne-anbieter-konfigurieren). Wenn das Ziel
  eine andere JSON-Struktur erwartet, bilden Sie diese in einer JSON-Webhook-Vorlage ab und wählen Sie **Inhalt der Benachrichtigungsvorlage** als
  Anfrageinhalt. Ein zwischengeschalteter Dienst zur Umwandlung ist nicht nötig.
</Note>
