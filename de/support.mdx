## Fehler melden

Geben Sie die folgenden Informationen an, damit sich der Fehler leichter reproduzieren lässt:

- Die Version aus `molesignal --version` und den Commit aus `GET /api/v1/version`.
- Die Art der Bereitstellung (Docker Compose, Binärdatei oder Kubernetes) und die aktiven Rollen.
- Den relevanten Konfigurationsausschnitt ohne vertrauliche Daten.
- Die Logzeilen unmittelbar vor und nach dem Fehler.
- Die Schritte, die das Problem auslösen, sowie das erwartete und das tatsächliche Ergebnis.

Fügen Sie niemals Tokens, Passwörter, `MS_CIPHER_KEY` oder Datenbank-Verbindungszeichenfolgen in ein öffentliches Issue ein.

## Sicherheitslücke melden

Erstellen Sie für eine Sicherheitslücke kein öffentliches Issue. Nutzen Sie einen der vertraulichen Meldekanäle:

- [Vertrauliche Meldung von Sicherheitslücken über GitHub](https://github.com/molesignal/molesignal/security/advisories/new).
- [security@molesignal.com](mailto:security@molesignal.com). Ein PGP-Schlüssel ist auf Anfrage verfügbar.

Fügen Sie eine kurze Beschreibung der Auswirkungen, ein minimales Beispiel zur Reproduktion, die getestete Version oder den getesteten Commit und einen Vorschlag für den Schweregrad hinzu.

Das Projektteam bestätigt den Eingang einer Meldung innerhalb von 3 Werktagen und bewertet sie innerhalb von 7 Werktagen. Bei Sicherheitslücken mit hohem oder kritischem Schweregrad liefert das Team innerhalb von 30 Tagen eine Korrektur oder einen Plan zur Risikominderung. Das Team stimmt die Veröffentlichung ab und nennt die meldenden Personen in den Release-Notes, sofern keine Anonymität gewünscht ist.

Bis MoleSignal Version 1.0 erreicht, übernimmt das Projektteam Sicherheitskorrekturen in den Branch `main` und in das neueste Release mit Tag. In den Kanälen `alpha` und `beta` fließen Korrekturen nur in neue Versionen ein.
