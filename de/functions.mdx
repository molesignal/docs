Funktionen bündeln wiederverwendbare Ereignistransformationen. Öffnen Sie **Funktionen**, um
Funktionsdefinitionen unabhängig von einer Pipeline zu erstellen, zu testen und zu pflegen.

## Funktion finden

Die Liste enthält die Funktionen der Organisation und die integrierten Vorlagen. Drei Ansichten am Anfang
der Liste grenzen die Auswahl ein und zeigen jeweils die Anzahl der Einträge:

| Ansicht | Inhalt |
|---|---|
| **Alle** | Alle Funktionen der Organisation und die Vorlagen. |
| **Eigene** | Die von der Organisation erstellten Funktionen. |
| **Vorlagen** | Die schreibgeschützten Funktionen, die MoleSignal mitliefert. |

Die Suche berücksichtigt Funktionsnamen und Vorlagenbeschreibungen. Klicken Sie auf eine Funktion
der Organisation, um sie im Funktionseditor zu öffnen.

## Sprachen

| Sprache | Verfügbarkeit | Geeignet für |
|---|---|---|
| VRL | Integriert | Parsen, Normalisieren, Filtern, Maskieren und Anreichern. |
| JavaScript | Integriert | Logik, die sich in JavaScript einfacher ausdrücken lässt. |
| LLM | Per API konfigurierbar; erfordert `llm_eval_enabled` und einen Modellanbieter | Klassifizierung oder Anreicherung mit Modellausgaben bei geringem Durchsatz. |

VRL und JavaScript laufen direkt im MoleSignal-Binary. Beide erfordern weder eine Einstellung noch eine zusätzliche Installation.

MoleSignal validiert und kompiliert eine Funktion beim Speichern. Bei ungültigem Quellcode bleibt
die bisherige Funktionsdefinition unverändert.

Der Funktionseditor unterstützt VRL und JavaScript. LLM-Funktionen stehen über einen erweiterten API-Workflow
zur Verfügung: Der Quellcode der Funktion dient als Systemanweisung, das Ereignis als Modelleingabe und
`params_schema.output_field` legt das Ausgabefeld fest (Standard: `_llm_eval`). Jeder Lauf ruft das
Modell auf. Deshalb steht `[functions].llm_eval_enabled` standardmäßig auf `false`. Siehe
[Konfiguration](/de/configuration#funktionen-und-integrationen). Nutzen Sie zum Zusammenfassen von Alarmereignissen
durch ein Modell den Schritt **KI-Zusammenfassung** in einer [Alarm-Pipeline](/de/pipelines/alert-events#ki-zusammenfassung).
Dieser Schritt ist von der Einstellung unabhängig.

## Integrierte Vorlagen

Diese schreibgeschützten VRL-Funktionen stehen jeder Organisation zur Verfügung:

| Funktion | Beschreibung |
|---|---|
| `add-intake-time` | Fügt einen Zeitstempel für den Eingang hinzu, um die Analyse der Ende-zu-Ende-Latenz zu erleichtern. |
| `normalize-logs` | Parst die JSON-Nachricht, fügt Felder für Umgebung und Cluster hinzu und schreibt den Wert von `level` klein. |
| `parse-key-value` | Parst eine Nachricht im Format logfmt oder `key=value` und fügt die extrahierten Felder wieder in das Ereignis ein. |
| `redact-email` | Ersetzt E-Mail-Adressen in `message` durch einen Platzhalter. |
| `route-by-service` | Normalisiert den Dienstnamen und leitet daraus den dienstspezifischen Zielstream (`logs_<service>`) als Routing-Hinweis ab. |

Jede Vorlagenzeile zeigt das Label **Integriert** und die Beschreibung in der aktuell eingestellten
Oberflächensprache an. Klicken Sie auf die Zeile, um den Quellcode anzuzeigen.

Vorlagen sind schreibgeschützt. Wählen Sie in der Zeile oder im Vorlagenbereich **Als Vorlage verwenden**,
um eine bearbeitbare Kopie zu erstellen. Der Funktionseditor öffnet eine neue Funktion mit der Sprache und dem Quellcode der Vorlage und dem Namen
`<preset>-copy`. Speichern Sie die Funktion, um sie in der Organisation anzulegen. Die Vorlage bleibt unverändert.

## Funktion schreiben und testen

Der Funktionseditor besteht aus drei Bereichen:

- Name und Sprache der Funktion;
- **Quelle**: der Editor mit dem Validierungsstatus des Quellcodes neben dem Titel;
- **Testlauf** mit der **Beispieleingabe** im JSON-Format und der **Beispielausgabe**.

Wählen Sie **Beispiel ausführen**, um den Quellcode im Editor mit dem Beispielereignis zu testen. Speichern ist
dafür nicht nötig. Unter **Beispielausgabe** erscheint das transformierte Ereignis. Schlägt der Testlauf fehl,
erscheint stattdessen der Fehlergrund.

In der Titelzeile stehen **Funktion speichern** und **Abbrechen**. Bei einer bereits gespeicherten Funktion
steht dort auch **Funktion löschen**. Fehlt der Name oder der Quellcode, ist **Funktion speichern**
deaktiviert. Der Tooltip zeigt an, was fehlt.
Drücken Sie im Editor `⌘ Enter` oder `Ctrl+Enter`, um das Beispiel auszuführen, und `⌘S` oder `Ctrl+S`, um zu speichern.

Der Testlauf ruft `POST /api/v1/functions/run` mit Sprache, Quellcode und Beispielereignis auf und
gibt das transformierte Ereignis zurück:

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".service = downcase!(string!(.service))","input":{"service":"Checkout"}}'
```

```json
{ "output": { "service": "checkout" } }
```

VRL-Beispiel:

```vrl
.service = downcase!(string!(.service))
.severity = upcase(string(.level) ?? "INFO")
if exists(.customer_id) {
  .customer = lookup("customers", .customer_id)
}
```

## Daten zu Schlüsseln und IP-Adressen nachschlagen

Zwei VRL-Funktionen lesen Daten, die MoleSignal vorhält. Sie funktionieren im Testlauf und in jedem VRL-Schritt
einer Pipeline, auch in Alarm-Pipelines.

| Funktion | Rückgabewert |
|---|---|
| `lookup("<table>", key)` | Die Zeile der [Erweiterungstabelle](/de/extend-tables) `<table>` mit dem Schlüssel `key` als Objekt oder `null`. |
| `geoip_lookup(ip)` | Der Standort einer IPv4- oder IPv6-Adresse als Objekt oder `null`. |

```vrl
# the team that owns the host, from the extend table host_owner
.team = lookup("host_owner", .host).team

# where the client is
place = geoip_lookup(.client_ip)
if is_object(place) {
  .country = place.country
  .city = place.city
}
```

- Beide Funktionen geben zur Laufzeit keine Fehler zurück. Fehlt die Tabelle oder Zeile, ist der Schlüssel weder Text noch Zahl noch
  boolescher Wert oder lässt sich die Adresse nicht parsen oder in der Datenbank finden, lautet der Rückgabewert `null`.
  Ein Pfad wie `.team` auf `null` ergibt ebenfalls `null`.
- Geben Sie den Tabellennamen in `lookup` als Stringliteral an. Ein Name aus einem Feld oder einer Variablen
  führt zu einem Kompilierungsfehler. Die Suche verwendet die Textdarstellung numerischer und boolescher Schlüssel: `42` findet die Zeile mit dem
  Schlüssel `42`.
- `lookup` liest die Erweiterungstabellen des Arbeitsbereichs. Unter
  [Erweiterungstabellen](/de/extend-tables#schlüssel-in-einer-pipeline-nachschlagen) steht, wann Änderungen an den
  Zeilen bei der Suche verfügbar sind.
- `geoip_lookup` liest die City-Lite-Datenbank von [DB-IP](https://db-ip.com), die unter
  [`[mmdb].db_path`](/de/configuration#funktionen-und-integrationen) angegeben ist. Ohne diese Datenbank lautet der Rückgabewert
  `null`. Die Datenbank enthält keine privaten Adressen. Das Objekt enthält nur die folgenden Felder,
  für die Daten vorliegen:

| Feld | Inhalt |
|---|---|
| `country` | ISO-3166-Code des Landes, z. B. `DE`. |
| `country_name` | Englischer Name des Landes. |
| `continent_code` | Code des Kontinents, z. B. `EU`. |
| `continent` | Englischer Name des Kontinents. |
| `region` | Englischer Name der obersten Verwaltungseinheit, z. B. eines Bundesstaats oder einer Provinz. |
| `city` | Englischer Name der Stadt. |
| `latitude`, `longitude` | Koordinaten in Grad. |

## JavaScript-Funktionen

MoleSignal führt den Quellcode einmal pro Ereignis aus. Das globale Objekt `molesignal` enthält das Ereignis und Hilfsfunktionen:

| Element | Zweck |
|---|---|
| `molesignal.fields` | Das Ereignis als Objekt. Lesen oder ändern Sie das Objekt oder weisen Sie ein neues Objekt zu. |
| `molesignal.set(name, value)` | Setzt ein Feld. |
| `molesignal.del(name)` | Entfernt ein Feld. |
| `molesignal.now()` | Aktuelle Zeit in Mikrosekunden seit der Unix-Epoche. |
| `molesignal.parse_json(text)` und `molesignal.encode_json(value)` | Konvertieren zwischen JSON-Text und Werten. |
| `molesignal.sha256(text)` | SHA-256-Hash der UTF-8-Bytes des Texts als 64 Hexadezimalzeichen in Kleinschreibung. |

```js
molesignal.set("severity", String(molesignal.fields.level || "info").toUpperCase());
molesignal.set("seen_at", molesignal.now());
molesignal.del("level");
```

Eine JavaScript-Funktion läuft in einer isolierten Engine mit folgenden Einschränkungen:

- Dauert ein Lauf länger als 50 ms, bricht er mit `js timeout 50ms` ab.
- Der Heap ist pro Funktion auf 32 MiB begrenzt.
- Netzwerkzugriff, Timer und `TextEncoder` stehen nicht zur Verfügung.

## Funktion verwenden

Pipeline-Schritte führen VRL aus. Wählen Sie in einem Schritt vom Typ **Benutzerdefinierter VRL-Code** die Option **Gespeicherte Funktion als Vorlage verwenden**, um den Quellcode
einer VRL-Funktion oder Vorlage als bearbeitbare Kopie in den Schritt zu übernehmen. Der Schritt behält diese Kopie:
Spätere Änderungen an der Funktion oder das Löschen der Funktion haben keinen Einfluss auf die Pipeline.

## Berechtigungen

- `functions.read` erlaubt das Auflisten und Öffnen von Funktionen.
- `functions.create` und `functions.edit` erlauben das Erstellen und Bearbeiten von Definitionen.
- `functions.run` erlaubt das Ausführen von Testläufen.
- `functions.delete` erlaubt das Löschen einer Definition.
