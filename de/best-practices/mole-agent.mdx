Mole Agent hilft ab dem ersten Chat. Vertrauen entsteht, wenn klar ist, worauf der Agent zugreifen kann,
und wenn die Antworten stimmen. Führen Sie Mole Agent schrittweise ein: Begrenzen Sie zuerst Datenzugriff und Aktionen, machen Sie den Agent mit der
Umgebung vertraut und übertragen Sie dann Routineaufgaben. Behalten Sie bei steigender Nutzung Kosten und Qualität im Blick.

## Festlegen, welche Daten das Modell erreichen

Mole Agent sendet den Gesprächsverlauf samt Tool-Ergebnissen an den Modellanbieter. Stimmen Sie diese
Einstellungen vor dem ersten Chat mit den Datenschutzverantwortlichen ab.

| Einstellung | Wo | Empfehlung |
|---|---|---|
| Modellanbieter | **Mole Agent → Einstellungen → Modelle und Reasoning** | Wählen Sie einen Anbieter, den die Datenrichtlinie zulässt. Ein OpenAI-kompatibler Endpunkt kann ein Modell im Unternehmensnetz bereitstellen. |
| Umfang des Datenzugriffs | **Mole Agent → Einstellungen → Datenzugriff** | Geben Sie nur die Umgebungen, Dienste und Streams frei, die für Untersuchungen nötig sind. |
| Netzwerkzugriff | **Mole Agent → Einstellungen → Netzwerkrichtlinie** | Lassen Sie den Netzwerkzugriff wie bei neuen Profilen deaktiviert, sofern kein Tool ihn benötigt. |
| Personenbezogene Daten | [Feldmaskierung](/de/settings/data-security#feldmaskierung) und [Regex-Muster](/de/settings/data-security#regex-muster) | Die Feldmaskierung gilt für Abfragen von Mole Agent genauso wie für manuelle Abfragen. **Bei der Erfassung schwärzen** entfernt Text vor dem Speichern. |

Hinterlegen Sie auch die Preise für jeden Anbieter, damit die Nutzungsübersicht die Kosten anzeigt.

## Erst beraten, dann ändern

Nutzen Sie für Chats zunächst den empfohlenen **Beratungsmodus**, um die Vorschläge von Mole Agent kennenzulernen. Der Agent
fragt Daten ab und schlägt Änderungen vor, ohne sie vorzunehmen. Wechseln Sie zu **Mit Genehmigung ausführen**, sobald sich die
Vorschläge bewähren. Je nach Ausführungsmodus des Tools fragt Mole Agent vor einer Änderung nach oder legt sie zur Genehmigung vor.
Siehe [Ausführungsmodi](/de/agent#ausführungsmodi).

- Lassen Sie **Modus „Berechtigungen umgehen“ zulassen** in der **Genehmigungsrichtlinie** gemeinsam genutzter Agent-Profile deaktiviert.
- Behalten Sie die Standardrichtlinie nach Risikostufe bei: von L0 (automatisch) bis L4 (deaktiviert). Legen Sie über **Tool-Richtlinie konfigurieren** unter
  **Tools und Funktionen** für **Produktion** strengere Regeln fest als für andere Umgebungen, etwa eine einzelne
  Genehmigung für Änderungen der Stufe L1.
- Für Genehmigungen ist `agent.approve` erforderlich. Die Rollen Owner und Admin haben diese Berechtigung. Vergeben Sie sie über eine benutzerdefinierte Rolle an
  Personen, die solche Änderungen auch selbst vornehmen würden.
- Neue Tools eines MCP-Servers bleiben deaktiviert, bis sie ausdrücklich aktiviert werden. Aktivieren Sie zuerst die schreibgeschützten Tools über
  **Alle schreibgeschützten Tools aktivieren**. Skills und MCP-Tools erweitern die Richtlinie nicht.

## Mole Agent mit der Umgebung vertraut machen

Die Qualität einer Antwort hängt davon ab, was Mole Agent über die Dienste weiß.

- Halten Sie das Wissen der Organisation in `MOLE.md` fest oder lassen Sie die Datei mit `/init` erstellen. Erfassen Sie die Dienste und
  ihre Verantwortlichen, die Umgebungen, die wichtigen Streams und Dashboards sowie die Ablageorte der Runbooks.
  Verweisen Sie mit `@path` auf längere Dateien wie `runbooks/checkout.md`. Siehe
  [Wissen und Gedächtnis](/de/agent#wissen-und-gedächtnis).
- Lassen Sie jedes Team eigenes Wissen pflegen, auf das die Team-Chats zugreifen. Bearbeiten Sie Incidents in Team-Chats,
  damit der Bereitschaftsdienst dieselbe Untersuchung nachvollziehen und fortsetzen kann.
- Aktivieren Sie **Wissenswertes aus Chats speichern**, um Erkenntnisse aus Chats festzuhalten. Prüfen Sie das **Gedächtnis** von
  Zeit zu Zeit und löschen Sie falsche Einträge.
- Machen Sie aus wiederkehrenden Abläufen [Skills](/de/agent#skills). Speichern Sie sie in einem
  [Skill-Repository](/de/agent#skill-repositorys) mit **Täglich synchronisieren**, damit Änderungen an
  Abläufen wie Codeänderungen geprüft werden.

## Routineaufgaben übertragen

Mit [Automatisierungen](/de/automations) arbeitet Mole Agent ohne aktive Chat-Teilnahme. Beginnen Sie mit den Vorlagen:

| Vorlage | Einsatz |
|---|---|
| **Incident-Analyse** | Hält bei Incidents der Stufen „Fehler“ und „Kritisch“ die wahrscheinliche Ursache samt Belegen als Ursachenanalyse (RCA) fest. Das dient dem Bereitschaftsdienst als Ausgangspunkt. |
| **Tägliche Zustandsprüfung** | Meldet werktags morgens, wo Handlungsbedarf besteht. |
| **Wöchentliche Prüfung der Alert-Flut** | Listet Regeln auf, die angepasst werden sollten. Siehe [Produktions-Alerts so gestalten, dass sie klare Maßnahmen auslösen](/de/best-practices/actionable-alerts). |
| **Wöchentliche Auslastung des Bereitschaftsdienstes** | Fasst zusammen, wie viele Alarmierungen pro Person und wie viele nachts eingehen. Siehe [Bereitschaftsdienst und Benachrichtigungen einrichten](/de/best-practices/on-call-setup). |
| **Auswirkungen von Änderungen prüfen** | Läuft, wenn die CI-Pipeline die Prüfung nach einem Deployment aufruft. Siehe [Release überprüfen](/de/best-practices/release-verification). |

Eine Automatisierung läuft im Namen und mit den Berechtigungen der Person, die sie zuletzt gespeichert hat. Verlässt diese Person
die Organisation, schlagen die Läufe fehl, bis die Automatisierung erneut gespeichert wird. Hinterlegen Sie deshalb für jede gemeinsam genutzte Automatisierung eine Zuständigkeit.

Während eines Laufs sind keine Antworten möglich. Tools, die eine Bestätigung benötigen, führt Mole Agent nicht aus. Der Lauf erhält den Status
**Eingreifen erforderlich**. Nutzen Sie Automatisierungen zum Lesen und Berichten. Nehmen Sie Änderungen in Chats vor.

## Kosten im Blick behalten

- Legen Sie das Tagesbudget unter **Mole Agent → Einstellungen → Nutzung** fest. Übernehmen Sie den Instanzstandard
  `[agent].daily_token_budget` oder legen Sie das Limit mit **Benutzerdefiniert** selbst fest. Orientieren Sie sich an der Nutzung pro Quelle in den letzten 30
  Tagen und planen Sie Puffer für gehäufte Incidents ein. Ist das Budget aufgebraucht, wartet die automatische Ursachenanalyse
  bis zum nächsten Tag. Log-Analysen und Schritte mit LLM-Funktionen schlagen fehl.
- Behalten Sie die Standardeinstellung **Modell nicht mehr aufrufen** bei. Wählen Sie **Weiter antworten und nur warnen** nur dann, wenn Chats
  auch nach Ausschöpfen des Budgets weiter Antworten liefern müssen.
- Fragen Sie für Details den internen Stream `_agent_model_traces` unter **Logs** ab. Er enthält Token-Anzahl, Latenz und Kosten
  jedes Aufrufs nach `origin`, `model` und `user_id`. Siehe [Nutzung und Budget](/de/agent#nutzung-und-budget).

## Qualität messen und verbessern

- Bitten Sie um Bewertungen der Antworten. Eine Bewertung als **Nicht hilfreich** mit Begründung zeigt, was verbessert werden muss.
- Fügen Sie einen [Evaluator](/de/quality#evaluatoren) hinzu, der eine Stichprobe von Team-Chats und RCAs bewertet. Prüfen Sie
  niedrige Bewertungen jede Woche auf dem Tab **Qualität**.
- Führen Sie `/insight` als wöchentliche Automatisierung aus. Der Befehl schlägt höchstens fünf sinnvolle Änderungen vor, etwa das Anlegen einer
  Wissensdatei.
- Stellen Sie die Prompt-Prüfung auf **Prüfen und bei schlechterem Ergebnis blockieren**, damit ein neuer organisationsweiter Prompt die
  Antworten nicht verschlechtert. Siehe [Prompt prüfen, bevor er zum Standard wird](/de/quality#prompt-vor-dem-festlegen-als-standard-prüfen).

## Abnahmekriterien

- Die Datenrichtlinie lässt den Modellanbieter zu, und die Preise sind hinterlegt.
- Das Standardprofil liest nur die benötigten Umgebungen, Dienste und Streams. Der Netzwerkzugriff ist deaktiviert.
- Kein gemeinsam genutztes Profil erlaubt **Berechtigungen umgehen**. Die Tool-Richtlinie für **Produktion** ist bewusst festgelegt.
- `MOLE.md` nennt die Dienste, ihre Verantwortlichen und ihre Runbooks. Jedes Bereitschaftsteam pflegt eigenes
  Wissen.
- Eine Automatisierung mit der Vorlage **Incident-Analyse** erstellt RCAs für Incidents der Stufen „Fehler“ und „Kritisch“.
- Das Tagesbudget bietet genug Spielraum für automatische Analysen. Die Prüfung des Tabs **Qualität** findet wöchentlich statt.
