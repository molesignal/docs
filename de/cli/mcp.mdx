`molesignal mcp` stellt die MCP-Tools von MoleSignal über stdio bereit. Ein Agenten-Tool startet den Befehl
selbst und kommuniziert mit ihm über Standardeingabe und Standardausgabe. Die CLI leitet jede Nachricht an den
Endpunkt **Eingehendes MCP** von MoleSignal und jede Antwort zurück. Tools, Berechtigungen und
Genehmigungen stammen von MoleSignal. Die CLI fügt keine eigenen hinzu.

## Server zu einem Agenten-Tool hinzufügen

[Melden Sie sich zuerst an](/de/cli/sign-in) und lassen Sie die CLI sich dann zum Agenten-Tool hinzufügen:

```bash
molesignal mcp setup claude
```

| Agenten-Tool | Was `molesignal mcp setup` ändert |
|---|---|
| `claude` | Führt `claude mcp add` für Claude Code aus. Für `--scope` stehen `user` (Standard), `project` und `local` zur Auswahl. |
| `cursor` | `~/.cursor/mcp.json` oder mit `--scope project` die Datei `.cursor/mcp.json` im aktuellen Ordner. |
| `codex` | `~/.codex/config.toml` oder `config.toml` im Verzeichnis `CODEX_HOME`, falls die Variable gesetzt ist. |
| `vscode` | `.vscode/mcp.json` im aktuellen Ordner. |
| `gemini` | `~/.gemini/settings.json` oder mit `--scope project` die Datei `.gemini/settings.json` im aktuellen Ordner. |

Der Befehl fügt einen Server namens `molesignal` hinzu oder ersetzt einen gleichnamigen Eintrag. Alle anderen
Einstellungen in der Datei bleiben unverändert. Der Server führt `npx -y @molesignal/cli mcp` aus. Mit `--installed` führt er stattdessen das
installierte `molesignal` aus. `--profile` trägt das Profil in die Serverkonfiguration ein. So verwendet das Agenten-Tool
die Anmeldung dieses Profils, unabhängig davon, welches Profil gerade aktiv ist. `--print` gibt die Konfiguration aus, statt
sie zu speichern.

[Über stdio verbinden](/de/inbound-mcp#über-stdio-verbinden) listet dieselbe Konfiguration für jedes
Tool auf. Der Einrichtungs-Prompt unter **Mole Agent → Einstellungen → Eingehendes MCP** erstellt die Schritte für die
jeweilige Instanz.

Wenn keine interaktive Anmeldung erfolgt, etwa auf einem Build-Server, stellen Sie die Zugangsdaten für den Server stattdessen über
Umgebungsvariablen bereit:

```json
{
  "mcpServers": {
    "molesignal": {
      "command": "npx",
      "args": ["-y", "@molesignal/cli", "mcp"],
      "env": {
        "MOLESIGNAL_URL": "https://molesignal.example.com",
        "MOLESIGNAL_TOKEN": "<token>"
      }
    }
  }
}
```

## Nachrichtenübermittlung

- Bis das Agenten-Tool `notifications/initialized` sendet, leitet die CLI die Nachrichten einzeln und in
  ihrer Reihenfolge weiter. MoleSignal eröffnet die Sitzung mit der Antwort auf `initialize`. Danach leitet die CLI Nachrichten
  direkt bei Eingang weiter, damit ein langsamer Tool-Aufruf andere Aufrufe nicht blockiert.
- Wenn MoleSignal die Sitzung nicht mehr kennt, etwa nach einem Neustart, eröffnet die CLI mit der
  `initialize`-Nachricht des Agenten-Tools eine neue Sitzung und sendet die Nachricht erneut. Das Agenten-Tool arbeitet ohne
  Neustart weiter.
- Wenn eine Anfrage MoleSignal nicht erreicht, gibt die CLI einen Fehler zurück, damit das Agenten-Tool nicht
  warten muss.
- Wenn das Agenten-Tool die Standardeingabe schließt, beendet die CLI die Sitzung bei MoleSignal und fährt herunter.
- Hinweise der CLI, etwa zu einem Verbindungsabbruch, erscheinen in der Standardfehlerausgabe.
  Die Standardausgabe enthält ausschließlich MCP-Nachrichten.
- `HTTPS_PROXY` und `NO_PROXY` gelten wie für jeden Befehl.

## Verbindung prüfen

```bash
molesignal status
```

Die Anzahl entspricht der Zahl der Tools, die dem Agenten-Tool angezeigt werden. Eine Anzahl von null bedeutet meist, dass
die Tool-Richtlinie der Organisation oder die Berechtigungen des Benutzerkontos kein Tool zulassen.
