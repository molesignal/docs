## Metriken abfragen

`molesignal metrics query` führt eine PromQL-Bereichsabfrage aus und gibt pro Zeitreihe eine Zeile aus: den letzten,
niedrigsten und höchsten Wert im Zeitraum, eine Sparkline und die Labels.

```bash
molesignal metrics query 'sum by (service) (rate(http_server_requests_total[5m]))' --since 6h
```

```text
LAST   MIN    MAX    TREND                           SERIES
12.4   3.1    14.9   ▁▂▂▃▅▆▇█▇▆▆▅▅▆▇▇█▇▆▅▄▄▅▅▆▆▇▇▇▆   {service="checkout"}
```

Der Zeitraum umfasst standardmäßig die letzte Stunde. Passen Sie ihn mit `--since`, `--from` und `--to` an. `-n` begrenzt die
Anzahl der Datenpunkte auf standardmäßig `1000`. `--json` gibt jede Zeitreihe mit ihren Datenpunkten aus. `--csv` gibt die
Datenpunkte als Zeilen aus.

Vier weitere Unterbefehle helfen bei der Auswahl der Abfrage:

| Befehl | Listet auf |
|---|---|
| `molesignal metrics names [text]` | Metriknamen, optional gefiltert nach dem angegebenen Text. |
| `molesignal metrics labels <metric>` | Die Labels einer Metrik. |
| `molesignal metrics values <metric> <label>` | Die Werte eines Labels und die Häufigkeit jedes Werts. |
| `molesignal metrics series <metric>` | Die Zeitreihen einer Metrik. `--match label=value` filtert die Liste. |

## Traces finden

```bash
molesignal traces --service checkout --errors --since 6h
```

Die Liste zeigt die neuesten Traces mit Startzeit, Dauer, Anzahl der Spans und Dienst.

| Option | Bedeutung |
|---|---|
| `--service <name>` | Nur Traces dieses Dienstes. |
| `--errors` | Nur Traces mit einem fehlgeschlagenen Span. |
| `--min-duration <time>` | Nur Traces mit mindestens der angegebenen Dauer, etwa `500ms`. |
| `--since`, `--from`, `--to` | Der Zeitraum, standardmäßig die letzte Stunde. |
| `-n`, `--limit <count>` | Anzahl der Traces, standardmäßig `20`, höchstens `200`. |

## Einen Trace visualisieren

`molesignal traces show` stellt einen Trace als Wasserfalldiagramm dar: eine Zeile pro Span, jeweils unter dem übergeordneten Span,
mit einem Balken für den Startzeitpunkt innerhalb des Traces und die Dauer. Der Befehl kennzeichnet fehlgeschlagene Spans mit
`!` und hebt sie im Terminal rot hervor.

```bash
molesignal traces show 4bf92f3577b34da6a3ce929d0e0e4736
```

```text
checkout POST /orders          ████████████████████████████████████████  1.24s
├─ checkout SELECT orders       ███                                       98ms
└─ ! payments POST /charge         ███████████████████████████████████    1.1s
```

`--web` öffnet den Trace in MoleSignal, `--json` gibt seine Spans aus.

## Eine Übersicht über Dienste anzeigen

```bash
molesignal services --env production --sort errors
```

Die Liste zeigt für jeden APM-Dienst die Anfragen, die Fehlerrate, die p95-Latenz, den Zustand und die aktuelle
Version. `--sort` sortiert die Liste nach `requests`, `errors`, `p95` oder `name`.

`molesignal services show` fasst einen Dienst zusammen: zuerst Anfragerate, Fehler und Latenz, dann
Endpunkte, Abhängigkeiten, Fehler und Versionen:

```bash
molesignal services show checkout --since 2h
```

## Zwei Versionen vergleichen

`molesignal services compare` stellt zwei Versionen eines Dienstes gegenüber und zeigt, ob sich die
Kandidatenversion verschlechtert oder verbessert hat, unverändert blieb oder zu wenige Anfragen für eine Bewertung vorlagen. Mit
`--fail-on-regression` endet der Befehl bei einer Verschlechterung mit dem Exit-Code `1`. So kann eine Pipeline
die Veröffentlichung stoppen:

```bash
molesignal services compare checkout 2.3.9 2.4.0 --since 1h --fail-on-regression
```

## Lang laufende Abfragen als Suchjobs ausführen

Ein Suchjob führt eine Abfrage im Hintergrund aus. Er verarbeitet mehr Daten über einen längeren Zeitraum als eine
direkte Abfrage und speichert das Ergebnis vorübergehend. Wie bei jeder Änderung gilt beim Starten und Abbrechen eines Suchjobs die
Tool-Richtlinie der Organisation. Siehe
[Vorfälle und Änderungen](/de/cli/changes#so-führt-molesignal-eine-änderung-aus).

```bash
molesignal search-jobs submit "SELECT * FROM app_logs WHERE level = 'error'" --since 30d --wait
```

Standardmäßig gilt der erste Stream nach `FROM`. Geben Sie mit `--stream` einen anderen Stream an. `--promql` übermittelt eine
PromQL-Abfrage und wertet sie am Ende des Zeitraums oder in einem mit `--step` festgelegten Intervall wie `1m` aus. `--limit` begrenzt
die Anzahl der gespeicherten Zeilen auf höchstens `100000`. `--keep` legt die Aufbewahrungsdauer fest. `--wait` wartet auf
den Abschluss des Jobs. Der Befehl gibt die Job-ID aus.

| Befehl | Wirkung |
|---|---|
| `molesignal search-jobs` | Listet die Suchjobs mit Status, Zeilen und Abfrage auf. |
| `molesignal search-jobs show <job>` | Gibt Status, Zeilen, Zeitangaben und Fehler eines Jobs aus. |
| `molesignal search-jobs results <job>` | Gibt die Ergebniszeilen eines abgeschlossenen Jobs aus, mit einem JSON-Objekt pro Zeile. `--csv` gibt CSV aus, `-o <file>` schreibt die Ausgabe in eine Datei. |
| `molesignal search-jobs cancel <job>` | Bricht einen ausstehenden oder laufenden Job ab. |

## Zugriff

Für Metriken ist `streams.query` erforderlich, für Traces `traces.read`, für APM `apm.services.read` und für Suchjobs `query.jobs.read` und
`query.jobs.run`. `sys.telemetry.read` erlaubt den Lesezugriff auf alle vier Bereiche im Scope `_sys`. Die Tool-Richtlinie der Organisation muss
die Tools aktiviert lassen.
