## So führt MoleSignal eine Änderung aus

Ein Befehl, der etwa einen Incident bestätigt, sendet die Änderungsanfrage über ein
verwaltetes Tool an MoleSignal, genau wie Mole Agent und die Agent-Tools. Die Tool-Richtlinie der Organisation legt fest, wie jedes
Tool ausgeführt wird. Sie finden die Richtlinie unter **Mole Agent → Einstellungen → Tools und Funktionen**:

| Ausführungsmodus | Verhalten des Befehls |
|---|---|
| Automatisch | MoleSignal führt die Änderung sofort aus. |
| Bestätigung | MoleSignal fordert eine Bestätigung an. Der Befehl fragt sie im Terminal ab. `-y` (`--yes`) bestätigt vorab, etwa in CI. Ohne Terminal und ohne `--yes` ändert sich nichts. |
| Einfache Genehmigung, doppelte Genehmigung | MoleSignal erstellt unter **Mole Agent → Genehmigungen** eine Genehmigungsanfrage zur Prüfung. Der Befehl gibt die Anfrage aus und endet mit dem Exit-Code `3`. Mit `--wait` wartet der Befehl bis zur Entscheidung, höchstens aber so lange wie in `--timeout` angegeben (standardmäßig 30 Minuten), und führt die Änderung nach der Genehmigung aus. |
| Deaktiviert | Der Befehl schlägt fehl und gibt den Grund aus. |

Ohne eigene Richtlinie bestimmt das Risiko des Tools den Ausführungsmodus. Standardmäßig ist eine Bestätigung für
`create_annotation` und `submit_search_job` erforderlich, eine einfache Genehmigung für `acknowledge_incident`,
`resolve_incident` und `run_synthetic_monitor`. Geben Sie mit `--reason` eine Begründung für die Prüfung und das
Audit-Log an.

Bestätigungen erfordern die MCP-Protokollrevision 2026-07-28. Die CLI verwendet diese Revision, wenn MoleSignal sie verwendet.
`molesignal status` zeigt die verwendete Revision an.

## Incidents auflisten

```bash
molesignal incidents
```

Die Liste zeigt aktive Incidents, die neuesten zuerst, mit Status, Schweregrad, Alter, Diensten
und Zusammenfassung. `--status resolved` oder `--status all` zeigt auch andere Incidents an. `--since 7d` beschränkt die Liste auf Incidents,
die in den letzten 7 Tagen eröffnet wurden. `-n` legt die Anzahl fest.

`molesignal incidents show` zeigt einen einzelnen Incident mit Regel, Zeitangaben, Diensten, Labels, Hinweisen wie
dem Runbook und einer Stichprobe von Traces an. `--rca` ergänzt die Ursachenanalyse. `--web` öffnet den
Incident in MoleSignal:

```bash
molesignal incidents show <incident> --rca
```

## Incidents bestätigen und beheben

```bash
molesignal incidents ack <incident>
```

```bash
molesignal incidents resolve <incident> --reason "Rolled back to 2.3.9"
```

Beide Befehle unterliegen der Tool-Richtlinie und erfordern die Berechtigung `alerts.incidents.acknowledge`.

## Rufbereitschaft anzeigen

```bash
molesignal oncall
```

Die Liste zeigt für jeden aktiven Rufbereitschaftsplan, wer gerade Rufbereitschaft hat. `--schedule` beschränkt die Anzeige auf einen Plan.
Mit `--at` fragen Sie einen anderen Zeitpunkt ab, etwa mit `--at "2026-10-27 09:00"`.

## Genehmigte Änderungen ausführen

`molesignal approvals` listet Genehmigungsanfragen von Mole Agent, Agent-Tools und Befehlen auf, die noch auf eine Entscheidung warten oder bereits genehmigt,
aber noch nicht ausgeführt sind. Mit `--all` zeigt der Befehl auch alle Anfragen an, über die bereits entschieden wurde.

```bash
molesignal approvals
```

`molesignal approvals show <approval>` zeigt eine Anfrage mit Aktion, Ziel, Begründung, Auswirkungen und
Prüfentscheidungen an. `molesignal approvals execute <approval>` führt eine genehmigte Änderung aus. MoleSignal fordert gegebenenfalls
zuerst eine Bestätigung an:

```bash
molesignal approvals execute <approval>
```

## Dashboards annotieren

`molesignal annotate` fügt eine Annotation für einen Zeitpunkt oder Zeitraum hinzu, entweder auf allen Dashboards
oder auf einem einzelnen Dashboard:

```bash
molesignal annotate "Release 2.4.0" --tags release,checkout --yes
```

| Option | Bedeutung |
|---|---|
| `--description <text>` | Details zur Annotation. |
| `--tags <a,b>` | Tags zum Auffinden der Annotation. |
| `--dashboard <id>` | Nur auf diesem Dashboard. |
| `--stream <stream>` | Stream, auf den sich die Annotation bezieht. |
| `--time <time>`, `--end <time>` | Beginn und Ende. Standardmäßig gilt der aktuelle Zeitpunkt ohne Zeitspanne. |

Für die Annotation ist die Berechtigung `dashboards.edit` erforderlich.

## Synthetische Checks ausführen

`molesignal synthetics` listet die Checks mit Typ, Status und Lebenszyklus auf.
`molesignal synthetics results <check>` listet die letzten Läufe eines Checks pro Standort auf, mit
Ergebnis, Dauer und bei einem Fehlschlag dem Grund. Geben Sie den Check per ID oder Name an.

`molesignal synthetics run` startet einen Check sofort an allen zugehörigen Standorten. Mit `--wait` wartet der Befehl
auf die Läufe und endet mit dem Exit-Code `1`, wenn ein Lauf fehlschlägt oder nicht innerhalb von `--timeout`
(standardmäßig 10 Minuten) abgeschlossen ist. So kann eine Pipeline ein Release stoppen:

```bash
molesignal synthetics run "Checkout API" --wait --yes
```

Ein Lauf gilt mit dem Ergebnis „fehlerfrei“ oder „instabil“ als bestanden. Für das Ausführen eines Checks ist die Berechtigung `synthetics.monitors.manage` erforderlich. Damit
Checks aus CI ohne Prüfung ausgeführt werden können, setzen Sie `run_synthetic_monitor` in der Tool-Richtlinie
auf **Automatisch**.
