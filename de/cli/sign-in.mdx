Die CLI meldet sich einmal an und speichert die Anmeldung für spätere Befehle. Es gibt zwei Möglichkeiten:

| Methode | Geeignet für |
|---|---|
| Anmeldung im Browser | Interaktive Nutzung an einem Computer mit Browser. Nutzt OAuth 2.1 und verlängert die Anmeldung automatisch. |
| API-Token | Skripte, Build-Rechner und Computer ohne Browser. |

Die Anmeldung im Browser gilt nur für den MCP-Endpunkt von MoleSignal. Das Melden von Deployments, das Hochladen von
Source Maps und Symbolen sowie das Senden von Logs laufen über die API von MoleSignal und erfordern ein API-Token.

## Im Browser anmelden

```bash
molesignal login --url https://molesignal.example.com
```

1. Die CLI registriert sich bei MoleSignal und öffnet die Autorisierungsseite von MoleSignal im
   Standardbrowser. Melden Sie sich dort bei MoleSignal an, falls noch keine Sitzung besteht.
2. Die Autorisierungsseite zeigt den Client, das Konto, die Organisation und die angeforderten
   Berechtigungen an. Wählen Sie bei Mitgliedschaft in mehreren Organisationen unter **Organisation** eine aus. Der Zugriff gilt nur
   für diese Organisation.
3. Klicken Sie auf **Autorisieren**. Der Browser leitet zurück zur CLI. Die CLI zeigt an, wie viele Tools zur
   Verfügung stehen.

Die CLI fordert die Scopes `mcp` und `offline_access` an. Dadurch verlängert sich die Anmeldung automatisch, bis der Zugriff
widerrufen wird. Die Autorisierungsseite wartet fünf Minuten. Danach endet der Befehl und eine eventuell vorhandene
Anmeldung bleibt unverändert. Auch bei einer abgelehnten oder abgebrochenen Anmeldung bleibt eine vorherige Anmeldung
bestehen.

<Note>
  Der Browser leitet an einen lokalen Listener unter `http://127.0.0.1` weiter, der nur während der Ausführung des Befehls aktiv ist.
  Nach Ende des Befehls lauscht dort kein Prozess mehr. Bei einem über SSH verbundenen Remote-Rechner kann der
  Browser diesen Listener nicht erreichen. Melden Sie sich dort mit einem API-Token an.
</Note>

## Mit einem API-Token anmelden

Erstellen Sie unter **Identität und Zugriff → API-Token** ein Token und übergeben Sie es über die Standardeingabe:

```bash
printf '%s' "$MOLESIGNAL_TOKEN" | molesignal login --url https://molesignal.example.com --with-token
```

Für das Token gelten die Berechtigungen des Benutzer- oder Dienstkontos, dem es gehört.

## Token ohne Speichern verwenden

Legen Sie die Adresse und das Token als Umgebungsvariablen fest, etwa auf einem Build-Rechner. Die CLI speichert nichts:

```bash
MOLESIGNAL_URL=https://molesignal.example.com MOLESIGNAL_TOKEN=<token> molesignal status
```

Mit `--url` und `--token` legen Sie dieselben Werte für einen einzelnen Befehl fest. Die CLI sendet ein für eine Adresse gespeichertes Token nie
an eine andere Adresse.

## Mehrere Anmeldungen speichern

Die CLI speichert jede Anmeldung in einem Profil mit der Adresse und den zugehörigen Zugangsdaten. Mit mehreren Profilen bleibt die CLI
bei mehreren MoleSignal-Instanzen oder bei mehreren Organisationen derselben Instanz angemeldet.
Geben Sie mit `--profile` an, in welchem Profil die CLI die Anmeldung speichert:

```bash
molesignal login --url https://staging.molesignal.example.com --profile staging
```

Nach der Anmeldung wird das zuletzt verwendete Profil zum aktuellen Profil. Befehle verwenden das aktuelle Profil.
Wählen Sie mit `--profile` oder `MOLESIGNAL_PROFILE` für einen einzelnen Befehl ein anderes Profil aus. Bei der ersten Anmeldung ohne
`--profile` verwendet die CLI das Profil `default`.

| Befehl | Wirkung |
|---|---|
| `molesignal profiles` | Listet die Profile mit Anmeldeart und Adresse auf. `*` kennzeichnet das aktuelle Profil. |
| `molesignal use <profile>` | Legt ein Profil als aktuelles Profil fest. |
| `molesignal logout --profile <profile>` | Entfernt die Anmeldung eines Profils, behält aber dessen Adresse bei. |
| `molesignal profiles remove <profile>` | Entfernt ein Profil. |

## Speicherort der Anmeldung

Die CLI speichert die Profile in `~/.config/molesignal/config.json`. Nur das Besitzerkonto kann die Datei lesen. Das
Verzeichnis richtet sich nach `XDG_CONFIG_HOME`, sofern die Variable gesetzt ist, und unter Windows nach `%APPDATA%`.
Geben Sie mit `MOLESIGNAL_CONFIG` eine andere Datei an.

## Hinter einem Proxy arbeiten

Mit `HTTPS_PROXY` (oder `HTTP_PROXY`) leiten Sie alle Anfragen der CLI über einen Proxy. Geben Sie in `NO_PROXY`
die Hosts an, die die CLI direkt erreichen soll:

```bash
HTTPS_PROXY=http://proxy.example.com:3128 NO_PROXY=localhost molesignal status
```

Wenn eine private Zertifizierungsstelle das MoleSignal-Zertifikat ausgestellt hat, geben Sie das Zertifikat dieser Stelle
in `NODE_EXTRA_CA_CERTS` an.

## Anmeldung und Konfiguration prüfen

`molesignal status` zeigt die Adresse, das Profil, den antwortenden Server, die Version des MCP-Protokolls,
die Anmeldeart und die Anzahl der MCP-Tools an:

```bash
molesignal status
```

`molesignal whoami` zeigt das Benutzerkonto, die Organisation, die Rolle und die von MoleSignal erteilten Berechtigungen
an:

```bash
molesignal whoami
```

`molesignal doctor` prüft die Voraussetzungen für den Betrieb der CLI und nennt bei Fehlern die nächsten Schritte:
Node.js, die Zugriffsrechte der Konfigurationsdatei, die Adresse, den Proxy, das Netzwerk und TLS,
die Systemzeit, die Anmeldung und den MCP-Endpunkt. Schlägt eine Prüfung fehl, endet der Befehl mit dem Exit-Code `1`:

```bash
molesignal doctor
```

## Anmeldung beenden

`molesignal logout` entfernt die gespeicherte Anmeldung des aktuellen Profils auf diesem Rechner:

```bash
molesignal logout
```

Die Autorisierung bleibt in MoleSignal bestehen. Widerrufen Sie sie unter
**Mole Agent → Einstellungen → Eingehendes MCP**.
