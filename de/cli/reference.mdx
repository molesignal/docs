`molesignal <command> --help` gibt dieselbe Hilfe für einen einzelnen Befehl aus.

## Optionen für alle Befehle

Alle Befehle, die mit MoleSignal kommunizieren, unterstützen diese Optionen:

| Option | Bedeutung |
|---|---|
| `--profile <name>` | Die gespeicherte Anmeldung, die der Befehl verwendet. Siehe [Mehrere Anmeldungen speichern](/de/cli/sign-in#mehrere-anmeldungen-speichern). |
| `--url <address>` | Die MoleSignal-Adresse, die der Befehl anstelle der Profiladresse verwendet. |
| `--token <token>` | Ein API-Token, das nur für diesen Befehl gilt. |

Als Zeitangabe sind ein ISO-Zeitstempel, ein Datum mit Uhrzeit wie `2026-10-26 14:00` in Ortszeit, die Anzahl der
Sekunden, Millisekunden oder Mikrosekunden seit der Unix-Epoche oder eine Zeitspanne rückwärts ab jetzt möglich. Eine Zeitspanne
besteht aus einer Zahl und einer Einheit: `ms`, `s`, `m`, `h`, `d` oder `w`.

## Anmeldung

| Befehl | Optionen | Beschreibung |
|---|---|---|
| `login` | `--url <address>`, `--profile <name>`, `--with-token` | Meldet im Browser oder mit einem API-Token aus der Standardeingabe an. Der Befehl aktiviert das Profil. |
| `logout` | `--profile <name>` | Entfernt die gespeicherte Anmeldung eines Profils und behält dessen Adresse bei. |
| `profiles` | `--json` | Listet die Profile auf. `profiles remove <name>` entfernt ein Profil. |
| `use <profile>` | keine | Aktiviert ein Profil. |
| `status` | keine | Zeigt die Adresse, das Profil, den Server, die Version des MCP-Protokolls, die Anmeldeart und die Anzahl der Tools an. |
| `whoami` | `--json` | Zeigt das Benutzerkonto, die Organisation, die Rolle und die Berechtigungen an. |
| `doctor` | keine | Prüft Node.js, die Konfiguration, die Adresse, den Proxy, das Netzwerk, TLS, die Systemzeit, die Anmeldung und den MCP-Endpunkt. |

## Logs und Abfragen

| Befehl | Optionen | Beschreibung |
|---|---|---|
| `streams` | `--type <type>`, `--names`, `--json` | Listet die Streams eines Typs auf, standardmäßig `logs`. |
| `logs <stream>` | `-f`, `-n`, `-q`, `--where`, `--since`, `--from`, `--to`, `--fields`, `--around`, `-B`, `-A`, `--interval`, `--json`, `--utc`, `--web` | Gibt die neuesten Logs eines Streams aus. Mit `-f` gibt der Befehl auch neu eintreffende Logs laufend aus. Siehe [Logs lesen und verfolgen](/de/cli/logs). |
| `query "<SQL>"` | `--stream`, `--since`, `--from`, `--to`, `-n`, `--csv`, `--json`, `--utc`, `--web` | Führt eine einzelne schreibgeschützte SQL-Anweisung für einen Log-Stream aus. |
| `fields <stream> [field]` | `--type`, `--since`, `--from`, `--to`, `-n`, `--match`, `--json` | Listet die Felder eines Streams oder die häufigsten Werte eines Felds auf. |

### Optionen für `logs`

| Option | Standardwert | Bedeutung |
|---|---|---|
| `-f`, `--follow` | aus | Gibt neue Logs aus, bis Sie **Strg+C** drücken. |
| `-n`, `--lines <count>` | `100` | Anzahl der neuesten Logs, die der Befehl zuerst ausgibt: `1` bis `5000`. |
| `-q`, `--query <query>` | keine | Eine Feldabfrage im selben Format wie auf der Seite **Logs**. |
| `--where <condition>` | keine | Eine SQL-Bedingung für die Felder des Streams. |
| `--since <duration>` | `15m` | Gibt an, wie weit die Suche zurückreicht. |
| `--from <time>`, `--to <time>` | keine | Ein Zeitfenster anstelle von `--since`. `--to` lässt sich nicht mit `-f` kombinieren. |
| `--fields <a,b,c>` | alle | Gibt den Zeitstempel und nur diese Felder aus. |
| `--around <time>` | keine | Gibt die Logs unmittelbar vor und nach einem Zeitpunkt aus. |
| `-B`, `--before <count>` | `10` | Mit `--around`: Anzahl der Logs vor dem Zeitpunkt, höchstens `250`. |
| `-A`, `--after <count>` | `10` | Mit `--around`: Anzahl der Logs nach dem Zeitpunkt, höchstens `250`. |
| `--interval <duration>` | `2s` | Gibt an, wie oft der Befehl beim Verfolgen neue Logs abruft. |
| `--json` | aus | Gibt jeden Log-Eintrag als einzelne JSON-Zeile aus. |
| `--utc` | aus | Gibt Zeitangaben in UTC aus. |
| `--web` | aus | Öffnet die Logs stattdessen auf der Seite **Logs**. |

| `metrics names [text]`, `metrics labels <metric>`, `metrics values <metric> <label>`, `metrics series <metric>` | `-n`, `--match <label=value>`, `--json` | Listet Metriknamen, Labels, Labelwerte und Zeitreihen auf. |
| `traces` | `--service`, `--errors`, `--min-duration`, `--since`, `--from`, `--to`, `-n`, `--json` | Listet die neuesten Traces auf. |
| `traces show <trace>` | `--since`, `--from`, `--to`, `--json`, `--web` | Zeigt einen Trace als Wasserfalldiagramm an. |
| `services` | `--env`, `--namespace`, `--sort`, `--since`, `--from`, `--to`, `-n`, `--json` | Listet APM-Dienste mit ihrem Zustand auf. |
| `services show <service>` | `--env`, `--namespace`, `--since`, `--json`, `--web` | Zeigt eine Übersicht für einen Dienst an. |
| `services compare <service> <baseline> <candidate>` | `--env`, `--since`, `--fail-on-regression`, `--json` | Vergleicht zwei Versionen. |
| `search-jobs` | `-n`, `--json` | Listet Suchjobs auf. |
| `search-jobs submit "<statement>"` | `--stream`, `--type`, `--promql`, `--step`, `--since`, `--from`, `--to`, `--limit`, `--keep`, `--wait`, Änderungsoptionen | Reicht einen Suchjob ein. |
| `search-jobs show <job>`, `search-jobs results <job>`, `search-jobs cancel <job>` | `-o <file>`, `--csv`, `--json`, Änderungsoptionen | Zeigt einen Suchjob an, gibt seine Ergebniszeilen aus oder bricht ihn ab. |

## Rufbereitschaft und Änderungen

| Befehl | Optionen | Beschreibung |
|---|---|---|
| `incidents` | `--status`, `--since`, `-n`, `--json` | Listet Incidents auf, standardmäßig nur aktive. |
| `incidents show <incident>` | `--rca`, `--json`, `--web` | Gibt einen einzelnen Incident aus. |
| `incidents ack <incident>`, `incidents resolve <incident>` | Änderungsoptionen | Bestätigt oder löst einen Incident. |
| `incidents create --title <text>` | `--description`, `--severity`, `--priority`, `--urgency`, `--service`, `--label`, `--team`, `--policy`, `--user`, `--major`, `--json`, Änderungsoptionen | Erstellt manuell einen Incident für ein Problem, das keine Regel erkannt hat. Leitet den Incident wie einen Alarm weiter, sofern nicht `--team`, `--policy` oder `--user` die Zuständigkeit per ID festlegt. `--priority` und `--urgency` verwenden die Stufen der Organisation. Gibt die ID und den Link des neuen Incidents aus. |
| `oncall` | `--schedule`, `--at`, `--json` | Zeigt an, wer Rufbereitschaft hat. |
| `approvals` | `--all`, `-n`, `--json` | Listet offene und genehmigte Freigabeanfragen auf. |
| `approvals show <approval>`, `approvals execute <approval>` | `--json`, Änderungsoptionen | Gibt eine Freigabeanfrage aus oder führt eine genehmigte Änderung aus. |
| `annotate "<title>"` | `--description`, `--tags`, `--dashboard`, `--stream`, `--time`, `--end`, Änderungsoptionen | Fügt Dashboards Annotationen hinzu. |
| `synthetics` | `--lifecycle`, `--json` | Listet synthetische Checks auf. |
| `synthetics results <check>` | `--since`, `-n`, `--json` | Listet die letzten Läufe eines Checks auf. |
| `synthetics run <check>` | Änderungsoptionen | Startet einen Check sofort. Mit `--wait` wartet der Befehl auf den Abschluss der Läufe. |
| `alerts rules export` | `--ids`, `-o`, `--output` | Exportiert Alarmregeln als Paket. Mit `--ids` exportiert der Befehl nur die angegebenen Regeln. Siehe [Import und Export](/de/alerting/rules#import-und-export). |
| `alerts rules apply -f <file>` | `--dry-run`, `--create-only`, `--json` | Wendet ein Paket oder eine Datei mit Prometheus-Alarmregeln an (`-f -` liest von der Standardeingabe). Prüft zuerst die Regeln und gibt aus, welche Änderung jede Regel bewirken würde. Schreibt alle Änderungen auf einmal, wenn kein Fehler auftritt. Bei einem Regelfehler liefert der Befehl für CI den Exit-Code 1. |
| `alerts policies export`, `alerts schedules export`, `alerts routing export` | `--ids`, `-o`, `--output` | Exportiert Eskalationsrichtlinien, Rufbereitschaftspläne oder Routingregeln als Paket. Das Paket referenziert Benutzerkonten per E-Mail-Adresse und alle anderen Einträge per Name. Siehe [Import und Export](/de/alerting/on-call#import-und-export). |
| `alerts policies apply -f <file>`, `alerts schedules apply -f <file>`, `alerts routing apply -f <file>` | `--dry-run`, `--create-only`, `--json` | Wendet ein solches Paket wie `alerts rules apply` an. Wenden Sie Rufbereitschaftspläne vor den Eskalationsrichtlinien an, die darüber benachrichtigen. Wenden Sie die Richtlinien vor den Alarm- und Routingregeln an, die auf sie verweisen. |

Die folgenden Optionen gelten für Änderungen. Siehe [Ablauf einer Änderung](/de/cli/changes#so-führt-molesignal-eine-änderung-aus).

| Option | Bedeutung |
|---|---|
| `--reason <text>` | Hinterlegt die Begründung bei der Freigabe und im Audit-Log. |
| `--wait` | Wartet bei einer freigabepflichtigen Änderung auf die Freigabe und führt die Änderung dann aus. |
| `--timeout <duration>` | Legt fest, wie lange `--wait` wartet: standardmäßig `30m`, für `synthetics run` dagegen `10m`. |
| `-y`, `--yes` | Bestätigt eine Änderung sofort, wenn MoleSignal eine Bestätigung verlangt. |

## Umgebungsvariablen

| Variable | Bedeutung |
|---|---|
| `MOLESIGNAL_URL` | Adresse von MoleSignal als Alternative zu `--url` oder zur gespeicherten Adresse. |
| `MOLESIGNAL_TOKEN` | API-Token anstelle der gespeicherten Anmeldung. |
| `MOLESIGNAL_PROFILE` | Profil anstelle des aktuellen Profils. |
| `MOLESIGNAL_CONFIG` | Datei, in der die Profile gespeichert sind. Standard: `~/.config/molesignal/config.json`. |
| `HTTPS_PROXY`, `HTTP_PROXY` | Proxy für alle Anfragen. |
| `NO_PROXY` | Hosts, die ohne Proxy erreichbar sind. |
| `NODE_EXTRA_CA_CERTS` | Zusätzliche vertrauenswürdige Zertifizierungsstelle neben denen des Systems. |
| `NO_COLOR` | Gibt Text ohne Farben aus. |
| `FORCE_COLOR` | Gibt Text auch dann farbig aus, wenn die Ausgabe nicht an ein Terminal geht. |

Optionen haben Vorrang vor Umgebungsvariablen, und Umgebungsvariablen haben Vorrang vor dem gespeicherten Profil.

## Exit-Codes

| Code | Bedeutung |
|---|---|
| `0` | Der Befehl war erfolgreich oder die laufende Ausgabe endete. |
| `1` | Der Befehl ist fehlgeschlagen und gibt den Grund auf der Standardfehlerausgabe aus. Dieser Code gilt auch, wenn ein synthetischer Lauf mit `--wait` fehlschlägt, eine Version mit `--fail-on-regression` eine Regression aufweist, `send` Logs ablehnt oder eine Prüfung von `doctor` fehlschlägt. |
| `2` | Unbekannter Befehl, unbekannte Option oder unbekanntes Argument. |
| `3` | Die Freigabe steht aus. Der Befehl hat die Änderung nicht ausgeführt. |

`deploy -- <command>` und `run` geben den Exit-Code des ausgeführten Befehls zurück.
