Mole Agent antwortet in Feishu, Slack, DingTalk, WeCom, Google Chat, Microsoft Teams und Telegram über einen Konnektor in den Benachrichtigungseinstellungen. Erwähnen Sie Mole Agent in einer Gruppe oder senden Sie ihm eine Direktnachricht. Mole Agent zeigt an, dass die Anfrage bearbeitet wird: In Feishu, Slack und Telegram reagiert er auf die Nachricht. In WeCom, Google Chat und Teams antwortet er zunächst mit „Wird geprüft …“ und ersetzt diese Meldung anschließend durch die fertige Antwort. Die Antwort enthält einen Link zum Chat in MoleSignal.

Dabei handelt es sich um reguläre Chats mit Mole Agent. Die Chats erscheinen in MoleSignal und lassen sich dort fortsetzen. Sie zählen zum Tagesbudget der Organisation. Für die Antworten gelten dieselben Bewertungskriterien wie für alle anderen Antworten. Siehe [Qualität](/de/quality).

## So gehen Nachrichten ein

| Plattform | Konnektor | Empfangsweg |
|---|---|---|
| Feishu | Feishu-App (`lark_app`) | Dauerhafte Verbindung zu Feishu |
| Slack | Slack-App (`slack_app`) | Socket Mode |
| DingTalk | DingTalk-App (`dingtalk_app`) | Stream-Modus |
| WeCom | WeCom-Smart-Bot (`wecom_bot`) | Dauerhafte Verbindung zum Smart Bot |
| Google Chat | Google Chat-App (`google_chat_app`) | Abruf aus einem Cloud Pub/Sub-Abonnement |
| Telegram | Telegram-Bot (`telegram_bot`) | Long Polling über die Telegram Bot API |
| Microsoft Teams | Microsoft Teams-Bot (`teams_app`) | Das Bot Framework sendet Nachrichten an eine öffentliche Callback-Adresse von MoleSignal |

Außer bei Teams baut jeweils ein MoleSignal-Server eine ausgehende Verbindung auf, um Nachrichten für den jeweiligen Konnektor zu empfangen. Dafür benötigt MoleSignal keine öffentliche Adresse. Teams benötigt eine öffentliche HTTPS-Callback-Adresse. Lesen Sie zuerst [Sicherheit für Teams](#sicherheit-für-teams). Die erforderlichen Adressen, Konten und Berechtigungen für jede Plattform finden Sie unter [Externe Voraussetzungen](#externe-voraussetzungen).

## Voraussetzungen

- Zum Aktivieren ist `agent.im.manage` erforderlich. Zum Stellen von Anfragen ist `agent.use` erforderlich.
- Richten Sie unter **Einstellungen → Benachrichtigungen → Konnektoren** einen Konnektor für die Plattform ein (siehe Tabelle oben). Eine Slack-App benötigt ein Bot-Token und ein Token auf App-Ebene. Eine Google Chat-App benötigt ein Pub/Sub-Abonnement. Siehe [Benachrichtigungskanäle](/de/notification-channels).
- Konfigurieren Sie die externe URL von MoleSignal unter `http.external_url`. So lassen sich Konten eigenständig verknüpfen und Antworten können auf den jeweiligen Chat verlinken. Für Teams muss die externe URL HTTPS verwenden, da die Callback-Adresse unter dieser URL liegt. Siehe [Konfiguration](/de/configuration).

## Plattform einrichten

### Feishu

<Steps>
  <Step title="Ereignisse über eine dauerhafte Verbindung empfangen">
    Öffnen Sie die App in der Feishu-Entwicklerkonsole, wechseln Sie zu **Ereignisse und Callbacks** und wählen Sie den Empfang von Ereignissen über eine dauerhafte Verbindung aus.
  </Step>
  <Step title="Nachrichten abonnieren">
    Fügen Sie das Ereignis **Nachricht empfangen** (`im.message.receive_v1`) hinzu.
  </Step>
  <Step title="Callbacks über eine dauerhafte Verbindung empfangen">
    Wählen Sie unter **Ereignisse und Callbacks → Callback-Konfiguration** den Empfang von Callbacks über eine dauerhafte Verbindung aus und fügen Sie den Callback für Kartenaktionen (`card.action.trigger`) hinzu. Die Schaltflächen auf Alarmkarten benötigen diesen Callback. Siehe [Alarmkarten](#alarmkarten).
  </Step>
  <Step title="Berechtigungen erteilen">
    Erlauben Sie der App, Direktnachrichten und Gruppennachrichten mit Erwähnung der App zu lesen, Nachrichten im eigenen Namen zu senden und auf Nachrichten zu reagieren. Damit sich ein Thread ohne erneute Erwähnung des Bots fortsetzen lässt, erlauben Sie der App auch, alle Gruppennachrichten zu lesen.
  </Step>
  <Step title="Veröffentlichen">
    Veröffentlichen Sie eine Version der App und fügen Sie den Bot den Gruppen hinzu, in denen er antworten soll.
  </Step>
</Steps>

Wählen Sie für Lark im Konnektor **Lark** als **Plattform** aus.

### Slack

<Steps>
  <Step title="Token auf App-Ebene erstellen">
    Erstellen Sie unter **Allgemeine Informationen → Token auf App-Ebene** ein Token mit dem Scope `connections:write`. Tragen Sie es im Konnektor als **Token auf App-Ebene** ein. Das Token beginnt mit `xapp-`.
  </Step>
  <Step title="Socket-Modus aktivieren">
    Aktivieren Sie den Modus unter **Socket-Modus**.
  </Step>
  <Step title="Interaktivität aktivieren">
    Aktivieren Sie unter **Interaktivität und Kurzbefehle** die Option **Interaktivität**. Im Socket-Modus ist keine Anfrage-URL nötig. Die Schaltflächen auf Alarmkarten benötigen diese Option. Siehe [Alarmkarten](#alarmkarten).
  </Step>
  <Step title="Ereignisse abonnieren">
    Fügen Sie unter **Ereignisabonnements → Bot-Ereignisse abonnieren** die Ereignisse `app_mention` und `message.im` hinzu. Damit sich ein Thread ohne erneute Erwähnung des Bots fortsetzen lässt, fügen Sie auch `message.channels` und `message.groups` hinzu.
  </Step>
  <Step title="Bot-Scopes hinzufügen">
    Fügen Sie unter **OAuth und Berechtigungen** die Scopes `app_mentions:read`, `chat:write`, `im:history` und `reactions:write` hinzu. Fügen Sie für Antworten in Threads auch `channels:history` und `groups:history` hinzu. Aktivieren Sie unter **App-Startseite** den Empfang von Nachrichten an die App. Installieren Sie die App erneut und laden Sie den Bot in die Kanäle ein, in denen er antworten soll.
  </Step>
</Steps>

### DingTalk

<Steps>
  <Step title="Bot-Nachrichten über Stream empfangen">
    Öffnen Sie in der DingTalk-Entwicklerkonsole den Bot der App und wählen Sie für den Nachrichtenempfang den **Stream-Modus** aus.
  </Step>
  <Step title="Veröffentlichen">
    Veröffentlichen Sie den Bot und fügen Sie ihn den Gruppen hinzu, in denen er antworten soll.
  </Step>
</Steps>

Die **Client-ID** und das **Client-Secret** des Konnektors entsprechen den Zugangsdaten der App. Wenn der Bot keinen eigenen Bot-Code hat, dient die Client-ID als Bot-Code.

### WeCom

In WeCom antwortet Mole Agent als intelligenter Bot. Er empfängt Nachrichten über die dauerhafte Verbindung im API-Modus und sendet Antworten über dieselbe Verbindung zurück.

<Steps>
  <Step title="Intelligenten Bot erstellen">
    Erstellen Sie in der WeCom-Administrationskonsole oder im Client einen intelligenten Bot. Wählen Sie den **API-Modus** und den Nachrichtenempfang über eine **dauerhafte Verbindung** aus. Notieren Sie die **Bot-ID** und den **Geheimschlüssel** für die dauerhafte Verbindung.
  </Step>
  <Step title="Konnektor erstellen">
    Erstellen Sie unter **Einstellungen → Benachrichtigungen → Konnektoren** einen Konnektor vom Typ **Intelligenter WeCom-Bot** und tragen Sie die **Bot-ID** und das **Secret für dauerhafte Verbindung** ein. Die feste Adresse für die dauerhafte Verbindung lautet `wss://openws.work.weixin.qq.com`.
  </Step>
  <Step title="Bot zu Gruppen hinzufügen">
    Fügen Sie den Bot den Gruppen hinzu, in denen er antworten soll, oder lassen Sie Direktnachrichten an den Bot zu.
  </Step>
</Steps>

- Pro Bot ist jeweils nur eine dauerhafte Verbindung möglich. Stellt etwa eine weitere MoleSignal-Instanz oder eine Testumgebung eine Verbindung mit derselben Bot-ID her, verliert MoleSignal seine Verbindung. Der Status zeigt **Verbindung nicht möglich** und nennt den Grund. Verwenden Sie für jede Umgebung einen eigenen Bot.
- Ein Bot empfängt Nachrichten entweder über die dauerhafte Verbindung oder über eine Callback-URL. Beim Wechsel zu einer Callback-URL endet die dauerhafte Verbindung.
- Hat ein Superadministrator der Organisation den Bot erstellt, enthalten die Nachrichten die Benutzer-IDs der Mitglieder im Klartext. Andernfalls sind die IDs verschlüsselt. Da sich verschlüsselte Benutzer-IDs nur schwer manuell zuordnen lassen, sollten Mitglieder ihre Konten über den Einmal-Link verknüpfen, den Mole Agent sendet.
- Nach der Aktivierung sendet der Bot auch Benachrichtigungen. Der Konnektor steht in Benachrichtigungsrichtlinien und bei persönlichen Benachrichtigungsmethoden zur Auswahl. Als Ziel dient die userid eines Mitglieds oder die chatid eines Chats. Der Bot erreicht nur Mitglieder, die ihm direkt geschrieben haben, und Chats, in denen er bereits erwähnt wurde. Alarmbenachrichtigungen verwenden Kartenvorlagen mit Schaltflächen. Siehe [Alarmkarten](#alarmkarten).

### Google Chat

Die Google Chat-App veröffentlicht Nachrichten in einem Cloud Pub/Sub-Thema. MoleSignal ruft sie über das zugehörige Abonnement ab. Eine öffentliche Adresse ist nicht nötig.

<Steps>
  <Step title="Dienstkonto vorbereiten">
    Aktivieren Sie in einem Google Cloud-Projekt die **Google Chat API** und die **Cloud Pub/Sub API**. Erstellen Sie im selben Projekt ein Dienstkonto und einen zugehörigen JSON-Schlüssel. Tragen Sie den Schlüssel im Konnektor als **Dienstkontoschlüssel** ein. Die Chat-App sendet im Namen dieses Dienstkontos, und MoleSignal nutzt es zum Abrufen von Nachrichten aus dem Abonnement.
  </Step>
  <Step title="Thema und Abonnement erstellen">
    Erstellen Sie in Pub/Sub ein Thema (z. B. `mole-chat`) und ein **Pull**-Abonnement dafür (z. B. `mole-chat-sub`). Weisen Sie dem Dienstkonto für das Abonnement die Rolle **Pub/Sub-Abonnent** (`roles/pubsub.subscriber`) zu.
  </Step>
  <Step title="Chat das Veröffentlichen im Thema erlauben">
    Weisen Sie `chat-api-push@system.gserviceaccount.com` für das Thema die Rolle **Pub/Sub-Publisher** (`roles/pubsub.publisher`) zu. Weisen Sie die Rolle bei einer Chat-App, die als Google Workspace-Add-on erstellt wurde, stattdessen dem Dienstkonto in den Verbindungseinstellungen zu.
  </Step>
  <Step title="Chat-App konfigurieren">
    Geben Sie unter **Google Chat API → Konfiguration** den Namen und den Avatar der App an. Aktivieren Sie **1:1-Nachrichten empfangen** und **Gruppenbereichen und Gruppenunterhaltungen beitreten**. Wählen Sie unter **Verbindungseinstellungen** die Option **Cloud Pub/Sub** und geben Sie den vollständigen Themennamen `projects/<project>/topics/mole-chat` ein. Legen Sie unter **Sichtbarkeit** fest, wer die App verwenden darf.
  </Step>
  <Step title="Abonnement eintragen">
    Tragen Sie `projects/<project>/subscriptions/mole-chat-sub` im Konnektor als **Pub/Sub-Abonnement** ein.
  </Step>
</Steps>

- Behalten Sie für das Abonnement die Standardfrist von 10 Sekunden für die Empfangsbestätigung bei. MoleSignal bestätigt jede Nachricht direkt beim Abruf.
- In Gruppenbereichen und Gruppenunterhaltungen empfängt die App nur Nachrichten, die sie erwähnen. Erwähnen Sie die App daher erneut, um einen Thread fortzusetzen. In einem Direktchat empfängt die App jede Nachricht.

### Telegram

Der Bot ruft Nachrichten per Long Polling über die Telegram Bot API (`getUpdates`) ab. Eine öffentliche Adresse ist nicht nötig.

<Steps>
  <Step title="Bot erstellen">
    Öffnen Sie in Telegram einen Chat mit **@BotFather**, senden Sie `/newbot` und wählen Sie einen Namen und einen Benutzernamen für den Bot. Kopieren Sie das ausgegebene Token, z. B. `123456789:AAE…`.
  </Step>
  <Step title="Konnektor erstellen">
    Erstellen Sie unter **Einstellungen → Benachrichtigungen → Konnektoren** einen Konnektor vom Typ **Telegram-Bot** und tragen Sie das Token als **Bot-Token** ein.
  </Step>
  <Step title="Empfang von Erwähnungen ermöglichen">
    Im standardmäßigen Datenschutzmodus von Telegram empfängt ein Bot in einer Gruppe nur an ihn gerichtete Befehle und Antworten auf seine Nachrichten, aber keine einfachen @Erwähnungen. Damit Mole Agent auf @Erwähnungen reagieren kann, senden Sie `/setprivacy` an @BotFather und wählen Sie **Deaktivieren** aus. Alternativ können Sie dem Bot Administratorrechte in der Gruppe geben.
  </Step>
  <Step title="Bot zu Gruppen hinzufügen">
    Fügen Sie den Bot den Gruppen hinzu, in denen er antworten soll.
  </Step>
</Steps>

- In einer Gruppe antwortet Mole Agent auf Nachrichten, die den Bot erwähnen, auf Befehle (`/new@<bot>` oder `/new`) und auf Antworten auf seine eigenen Nachrichten. Antworten auf Alarmbenachrichtigungen müssen den Bot ebenfalls erwähnen. Ohne Erwähnung erreichen ihn solche Antworten nicht. In einem privaten Chat empfängt der Bot jede Nachricht.
- Telegram startet einen privaten Chat mit dem Bot mit `/start`. Mole Agent behandelt den Befehl wie `/help` und sendet bei noch nicht verknüpften Konten den Link zur Verknüpfung.
- Ein Telegram-Bot kann nur dann eine private Nachricht senden, wenn das betreffende Mitglied bereits einen privaten Chat mit dem Bot geöffnet und auf **Beginn** geklickt hat. Andere Mitglieder mit noch nicht verknüpften Konten erhalten den Link in einer Gruppennachricht, die nur für das jeweilige Mitglied sichtbar ist. Falls auch das nicht klappt, bittet Mole Agent zuerst um eine private Nachricht. Siehe [Benutzerkonten verknüpfen](#konten-verknüpfen).
- Telegram leitet die Nachrichten eines Bots jeweils nur an einen Empfänger weiter. Beim Verbindungsaufbau entfernt MoleSignal einen eventuell für den Bot eingerichteten Webhook. Ruft ein anderes Programm gleichzeitig Nachrichten desselben Bots ab, weist Telegram einen der Abrufe zurück (HTTP 409), und der Status zeigt **Verbindung nicht möglich** mit dem Grund an. Verwenden Sie für jede Umgebung einen eigenen Bot.

### Microsoft Teams

Bot Framework sendet Teams-Nachrichten an eine öffentliche Callback-Adresse von MoleSignal. Nur für Microsoft Teams muss MoleSignal aus dem Internet erreichbar sein. Richten Sie vor der Aktivierung die externe Adresse wie unter [Sicherheit für Teams](#sicherheit-für-teams) beschrieben ein.

<Steps>
  <Step title="Azure Bot vorbereiten">
    Erstellen Sie im Azure-Portal einen **Azure Bot** vom Typ **Einzelner Mandant** oder verwenden Sie einen vorhandenen Bot dieses Typs. Erstellen Sie für den Bot in seiner Microsoft Entra-App-Registrierung ein Client-Secret. Tragen Sie die **App-ID**, das **Client-Secret** und die **Mandanten-ID** des Bots im Konnektor ein.
  </Step>
  <Step title="Teams-Kanal hinzufügen">
    Fügen Sie in den Einstellungen des Azure Bot unter **Kanäle** den Kanal **Microsoft Teams** hinzu.
  </Step>
  <Step title="Konnektor aktivieren und Callback-Adresse kopieren">
    Öffnen Sie **Mole Agent → Einstellungen → IM**, aktivieren Sie den Konnektor und kopieren Sie die Adresse unter **Callback**: `https://<external address>/api/v1/public/im/teams/<connector ID>/messages`.
  </Step>
  <Step title="Messaging-Endpunkt festlegen">
    Tragen Sie in der **Konfiguration** des Azure Bot die Callback-Adresse als **Messaging-Endpunkt** ein.
  </Step>
  <Step title="Teams-App veröffentlichen">
    Erstellen Sie ein Teams-App-Paket. Geben Sie im Manifest unter `bots` die App-ID des Bots und die Scopes `personal`, `team` und `groupChat` an. Laden Sie das Paket im Teams Admin Center oder im Developer Portal hoch und installieren Sie die App für die vorgesehenen Benutzerkonten, Teams und Gruppenchats.
  </Step>
</Steps>

- In Kanälen und Gruppenchats empfängt der Bot nur Nachrichten, die ihn erwähnen. Erwähnen Sie den Bot daher erneut, um eine Unterhaltung unter einem Beitrag fortzusetzen. In einem persönlichen Chat empfängt der Bot jede Nachricht.
- MoleSignal unterstützt Bot Framework in der öffentlichen Azure-Cloud und in den US-Regierungsclouds (GCC, GCC High, DoD). Wählen Sie im Konnektor die entsprechende **Cloud** aus.

## Sicherheit für Teams

Die Teams-Callback-Adresse ist über das Internet erreichbar. MoleSignal prüft jede Anfrage an diese Adresse:

- **Jede Anfrage enthält ein Bot Framework-Token.** Die Adresse akzeptiert keine MoleSignal-Anmeldung, sondern nur ein von Bot Framework signiertes JWT: Die Signaturschlüssel stammen aus den OpenID-Metadaten von `login.botframework.com` (24 Stunden im Cache); `iss` ist `https://api.botframework.com`; GCC High und DoD verwenden stattdessen `login.botframework.azure.us` und `https://api.botframework.us`; `aud` ist die App-ID des Bots; `exp` und `nbf` erlauben eine Zeitabweichung von fünf Minuten; der Signaturschlüssel muss für den Teams-Kanal (`msteams`) zugelassen sein; und die `serviceUrl` im Token muss mit der in der Nachricht übereinstimmen. Schlägt eine Prüfung fehl, antwortet MoleSignal mit 401 oder 403 und verarbeitet die Anfrage nicht.
- **Antworten gehen nur an Bot Framework.** MoleSignal sendet das Token des Bots nur an Dienstadressen von Bot Framework (`smba.trafficmanager.net`, `*.botframework.com`, `*.teams.microsoft.com`, `*.teams.microsoft.us`) oder an die im Konnektor konfigurierte Dienst-URL. Nachrichten mit einer anderen Adresse lehnt MoleSignal ab.
- **Nur der eigene Mandant.** Ist im Konnektor eine Mandanten-ID (eine GUID) hinterlegt, verarbeitet MoleSignal keine Nachrichten aus anderen Mandanten. Ein Domänenname oder `botframework.com` schränkt den Zugriff nicht ein.
- **Die Adresse funktioniert nur bei einem aktiven Konnektor.** Ist der Konnektor unter **IM** nicht aktiviert, deaktiviert oder gelöscht, liefert die Callback-Adresse den Statuscode 404. Die Adresse enthält nur die ID des Konnektors, nie ein Geheimnis.
- **Der Anfrageinhalt ist größenbeschränkt.** MoleSignal lehnt Anfragen ab, die größer als 256 KiB sind.

Beachten Sie bei der Bereitstellung außerdem Folgendes:

1. **Geben Sie nur den Callback-Pfad für das Internet frei.** Leiten Sie über einen Reverse-Proxy oder ein Gateway nur `POST /api/v1/public/im/teams/` weiter. Lassen Sie die Anmeldeseite und alle anderen APIs nur im internen Netzwerk erreichbar. Beispiel mit nginx:

   ```nginx
   server {
     listen 443 ssl;
     server_name molesignal.example.com;
     # ssl_certificate and ssl_certificate_key …
     client_max_body_size 256k;

     location /api/v1/public/im/teams/ {
       limit_except POST { deny all; }
       proxy_pass http://molesignal.internal:8080;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto https;
     }

     location / {
       return 404;
     }
   }
   ```

   Falls MoleSignal auch über diese externe Adresse erreichbar ist, beschränken Sie alle anderen Pfade am Gateway auf das Unternehmensnetz oder VPN. Geben Sie nur den Callback-Pfad für das Internet frei. Vollständige Konfigurationen für nginx, Kubernetes Ingress und Gateway API finden Sie unter [Öffentlicher Zugriff](/de/public-access).
2. **Verwenden Sie HTTPS.** `http.external_url` muss eine HTTPS-Adresse sein, da Teams keine POST-Anfragen über HTTP sendet. Der Proxy kann TLS mit einem Zertifikat einer öffentlichen Zertifizierungsstelle terminieren.
3. **Beschränken Sie optional die zulässigen Quellen.** Eine Firewall oder ein Gateway kann den Zugriff auf den Callback-Pfad auf die Adressen des Azure-Diensttags `AzureBotService` beschränken. Diese Adressen ändern sich. Halten Sie die Freigabeliste anhand der von Azure veröffentlichten Liste aktuell. Die Tokenprüfung bleibt die wichtigste Schutzmaßnahme.
4. **Schützen Sie den geheimen Clientschlüssel.** MoleSignal speichert den Schlüssel verschlüsselt mit dem Konnektor und gibt ihn nie zurück. Wechseln Sie den Schlüssel regelmäßig und aktualisieren Sie dabei den Konnektor. Erteilen Sie der App-Registrierung des Bots nur die erforderlichen Berechtigungen.
5. **Achten Sie auf Auffälligkeiten.** Die Logs und Traces von MoleSignal zeigen Callback-Anfragen und abgelehnte Tokens. Unter **IM** sehen Sie, wann jeder Konnektor zuletzt eine Nachricht empfangen hat.

## Externe Voraussetzungen

Voraussetzungen je Plattform außerhalb von MoleSignal:

| Plattform | Ausgehend von MoleSignal | Eingehend | Einrichtung auf der Plattform |
|---|---|---|---|
| Feishu | `open.feishu.cn` (`open.larksuite.com` für Lark) und die von der Plattform bereitgestellte Adresse für die dauerhafte Verbindung | Keine | Eine selbst erstellte App, Ereignisse über eine dauerhafte Verbindung, das Nachrichtenereignis, Callbacks über eine dauerhafte Verbindung, Berechtigungen, eine veröffentlichte Version |
| Slack | `slack.com`, die WebSocket-Adressen für Socket Mode und `hooks.slack.com` für Alarmkarten; für GovSlack stattdessen `slack-gov.com` und `hooks.slack-gov.com` | Keine | Ein Token auf App-Ebene, Socket Mode, Interaktivität, Ereignisabonnements, Bot-Scopes |
| DingTalk | `api.dingtalk.com`, `oapi.dingtalk.com` und die WebSocket-Adresse für den Stream-Modus | Keine | Der Roboter einer internen App, Stream-Modus; für Schaltflächen auf Alarmkarten eine interaktive Kartenvorlage und die Kartenberechtigung |
| WeCom | `openws.work.weixin.qq.com` (WebSocket, 443) | Keine | Ein Smart Bot im API-Modus über eine dauerhafte Verbindung, mit Bot-ID und geheimem Schlüssel |
| Google Chat | `oauth2.googleapis.com`, `pubsub.googleapis.com`, `chat.googleapis.com` | Keine | Die Chat- und Pub/Sub-APIs, ein Dienstkonto mit zugehörigem JSON-Schlüssel, ein Thema und ein Pull-Abo, die Rollen „Subscriber“ und „Publisher“, die Konfiguration der Chat-App |
| Telegram | `api.telegram.org` (443) | Keine | Ein mit @BotFather erstellter Bot und das zugehörige Token |
| Microsoft Teams | `login.microsoftonline.com`, `login.botframework.com` und die Dienst-URL des Konnektors (`smba.trafficmanager.net` für Global); für GCC High und DoD stattdessen `login.microsoftonline.us` und `login.botframework.azure.us` | Bot Framework greift auf `https://<external address>/api/v1/public/im/teams/…` (443) zu | Ein Azure Bot, ein geheimer Clientschlüssel, der Teams-Kanal, der Messaging-Endpunkt, ein Teams-App-Paket |

- Firewalls und ausgehende Proxys müssen Verbindungen zu den oben aufgeführten Adressen zulassen. Die dauerhaften WebSocket-Verbindungen (Feishu, Slack, DingTalk, WeCom) gehen ohne HTTP-Proxy direkt zur jeweiligen Plattform.
- Für eingehende Anfragen benötigt Teams öffentliches DNS, ein Zertifikat einer öffentlichen Zertifizierungsstelle und einen Reverse-Proxy, der nur den Callback-Pfad weiterleitet. Siehe [Sicherheit für Teams](#sicherheit-für-teams).
- Die Kontoverknüpfung und die Chatlinks in Antworten setzen `http.external_url` voraus.

## IM aktivieren

Öffnen Sie **Mole Agent → Einstellungen → IM**. Die Liste enthält alle Konnektoren, die in IM antworten können:

| Spalte | Inhalt |
|---|---|
| **Konnektor** | Konnektor, Plattform und Zeitpunkt der zuletzt empfangenen Nachricht. Unter einem Teams-Konnektor steht die Callback-Adresse zum Kopieren bereit. |
| **Status** | **Verbunden** mit Angabe des verbundenen Kontos, **Verbindung wird hergestellt**, **Wartet auf einen Server**, **Verbindung nicht möglich** mit Begründung, **Aus** oder eine noch fehlende Voraussetzung, etwa ein Slack-Token auf App-Ebene oder ein Pub/Sub-Abo für Google Chat. Teams nutzt keine dauerhafte Verbindung: **Verbunden** bedeutet, dass die Zugangsdaten des Bots gültig sind und Bot Framework die Nachrichten zustellt. |
| **Neue Gruppen-Threads** | Ziel für einen neuen Thread aus einer Gruppe: **Direktchat mit der fragenden Person** oder ein Team. Das Team kommt nur infrage, wenn die fragende Person Mitglied ist. |
| **Aktiv** | Gibt an, ob der Konnektor in IM antwortet. Aktivieren Sie einen Teams-Konnektor nur, wenn `http.external_url` eine HTTPS-Adresse ist. |

Deaktivieren Sie einen Konnektor, der in IM antwortet, zuerst hier. Erst dann können Sie ihn aus den Benachrichtigungseinstellungen löschen.

## Konten verknüpfen

Mole Agent beantwortet Anfragen mit den Berechtigungen des MoleSignal-Kontos, mit dem das jeweilige IM-Konto verknüpft ist. Mole Agent erkennt das Konto anhand einer aktiven, verifizierten Benachrichtigungsmethode am selben Konnektor:

| Plattform | Konto |
|---|---|
| Feishu | `open_id`, `user_id` oder `union_id` |
| Slack | Mitglieds-ID |
| DingTalk | Benutzer-ID |
| WeCom | Die für den Smart Bot sichtbare Benutzer-ID |
| Google Chat | Benutzer-ID (`users/123…`) oder E-Mail-Adresse |
| Telegram | Numerische Benutzer-ID |
| Microsoft Teams | Teams-Benutzer-ID (`29:…`) oder Microsoft Entra-Objekt-ID |

Mole Agent beantwortet keine Anfragen von Konten, die mit mehreren MoleSignal-Konten verknüpft sind.

- **Selbst verknüpfen**: Bei einer Anfrage von einem noch nicht verknüpften Konto sendet Mole Agent einen einmalig nutzbaren Link per Direktnachricht oder in Slack als Nachricht, die nur für die fragende Person sichtbar ist. Öffnen Sie den Link, während Sie in MoleSignal angemeldet sind, und wählen Sie **Verknüpfen**. Damit fügen Sie das IM-Konto als bereits verifizierte Benachrichtigungsmethode hinzu. Der Link ist 15 Minuten lang gültig und funktioniert nur einmal. In WeCom, Google Chat und Telegram kann Mole Agent eine Direktnachricht erst senden, wenn das Konto dem Bot direkt geschrieben hat. In Teams muss der Bot für das Konto installiert sein. Kann Mole Agent keine Direktnachricht senden, bittet Mole Agent im aktuellen Chat zunächst um eine Direktnachricht und sendet den Link dann dorthin. In Telegram versucht Mole Agent zuerst, eine Gruppennachricht zu senden, die nur für die fragende Person sichtbar ist.
- **Durch die Administration verknüpfen**: Ordnen Sie das Konto unter **Einstellungen → Benachrichtigungen → Benutzerrouting** dem Mitglied zu und verifizieren Sie das Konto. Siehe [Benachrichtigungskanäle](/de/notification-channels#benachrichtigungsmethoden-für-mitglieder-verknüpfen).

## Fragen stellen

Erwähnen Sie den Bot in einer Gruppe. Schreiben Sie in einer Direktnachricht einfach die Frage. In Direktnachrichten läuft derselbe Chat bis zum Befehl `/new` weiter.

| Plattform | Was in einer Gruppe als ein Chat zählt |
|---|---|
| Feishu, Slack | Ein Thread; die Antwort erscheint darin |
| Google Chat-Bereiche | Ein Thread; die Antwort erscheint darin. Erwähnen Sie den Bot erneut, um den Chat fortzusetzen |
| Microsoft Teams-Kanäle | Ein Beitrag; die Antwort erscheint darunter. Erwähnen Sie den Bot erneut, um den Chat fortzusetzen |
| DingTalk, WeCom, Google Chat-Gruppenunterhaltungen, Teams-Gruppenchats | Keine Threads: Die Fragen einer Person bilden in jeder Gruppe einen eigenen Chat |
| Telegram-Gruppen | Die Fragen einer Person bilden pro Forenthema einen eigenen Chat. Die Antwort erscheint direkt als Antwort auf die Frage |

| Befehl | Funktion |
|---|---|
| `/help` | Erklärt, wie Fragen gestellt werden, und listet diese Befehle auf. |
| `/new` | Startet hier einen neuen Chat. |
| `/scope` | Zeigt an, wem der Chat dieses Threads gehört. |
| `/scope <team>` | Setzt die Unterhaltung in einem neuen Teamchat fort. Teammitglieder können den Chat verfolgen und fortsetzen. |
| `/scope me` | Setzt die Unterhaltung in einem neuen persönlichen Chat fort. |
| `/feedback 👍` oder `/feedback 👎`, gefolgt von einem optionalen Kommentar | Bewertet die letzte Antwort im Thread. |

Andere Befehle wie `/rca INC-12` oder Befehle für Skills funktionieren wie in MoleSignal.

### Wem der Chat eines Threads gehört

Nur die Person, die einen persönlichen Chat gestartet hat, kann ihn fortsetzen. Teamchats können nur Mitglieder des jeweiligen Teams fortsetzen. Ein neuer Thread in einer Gruppe gehört zum Team des Connectors, wenn die fragende Person Mitglied dieses Teams ist. Andernfalls beginnt ein persönlicher Chat. `/scope` verschiebt den Thread in einen neuen Chat. Bisherige Nachrichten bleiben im alten Chat.

## Während Mole Agent antwortet

- Im Messenger lassen sich Rückfragen von Mole Agent nicht beantworten und Änderungen nicht bestätigen. Mole Agent trifft plausible Annahmen und nennt sie in der Antwort. Schritte, die eine Bestätigung erfordern, überspringt Mole Agent und weist in der Antwort darauf hin. Öffnen Sie den Chat über den Link in MoleSignal, um mit diesen Schritten fortzufahren.
- Mole Agent benötigt höchstens 15 Minuten für eine Antwort. In WeCom muss der Stream der Nachricht „Wird untersucht …“ innerhalb von 10 Minuten enden. Dauert die Antwort länger als 9 Minuten, sendet Mole Agent sie deshalb als separate Nachricht.
- Mole Agent sendet die Antwort mit Abschnitten wie „Wahrscheinliche Ursachen“, „Belege“ und „Nächste Schritte“ in der Oberflächensprache der fragenden Person.
- Alle Gruppenmitglieder können die Antwort lesen. Mole Agent verwendet jedoch beim Erstellen der Antwort die Berechtigungen der fragenden Person. Stellen Sie Fragen per Direktnachricht, wenn andere Gruppenmitglieder die Antwort nicht sehen sollen.
- Wenn das Tagesbudget der Organisation aufgebraucht ist, weist Mole Agent darauf hin, statt die Frage zu beantworten.

## Alarmkarten

In diesem Abschnitt geht es um Alarmbenachrichtigungen, nicht um Chats mit Mole Agent: Die folgenden Konnektoren senden Alarmbenachrichtigungen als Karten mit Schaltflächen. Alarme lassen sich direkt auf der Karte bestätigen, beheben oder zurückstellen, ohne MoleSignal zu öffnen.

| Konnektor | Wann die Karten Schaltflächen enthalten |
|---|---|
| Feishu-App, Slack-App, intelligenter WeCom-Bot, Google Chat-App, Microsoft Teams-Bot, Telegram-Bot | Der Konnektor ist unter **IM** aktiviert. Siehe [Aktivieren](#im-aktivieren) |
| DingTalk-App | Der Konnektor ist unter **IM** aktiviert und hat eine **ID der Kartenvorlage**. Siehe [Interaktive DingTalk-Karten](#interaktive-dingtalk-karten) |
| WeCom-App | Keine Aktivierung unter **IM** nötig. In der App ist **Nachrichten empfangen** eingerichtet. Siehe [Schaltflächen einer WeCom-App](#schaltflächen-einer-wecom-app). Nur Benachrichtigungen an Mitglieder enthalten Schaltflächen |
| Mattermost-Bot | Keine Aktivierung unter **IM** nötig. `http.external_url` ist konfiguriert und der Mattermost-Server kann die Adresse erreichen. Siehe [Schaltflächen eines Mattermost-Bots](#schaltflächen-eines-mattermost-bots) |

Gruppenbots (die Webhook-Konnektoren der jeweiligen Plattform) empfangen keine Klicks auf Schaltflächen. Ist in der Instant-Messaging-Vorlage **Als Karte senden** aktiviert, senden die Bots daher eine Karte ohne Schaltflächen, andernfalls eine Textnachricht. Siehe [Karten in Instant-Messaging-Vorlagen](/de/notification-channels#karten-in-vorlagen-für-instant-messaging). Alarmbenachrichtigungen an einzelne Personen enthalten bei Konnektoren ohne Schaltflächen stattdessen [einmalig nutzbare Aktionslinks](/de/notification-channels#einmal-links-für-aktionen).

| Schaltfläche | Funktion |
|---|---|
| **Bestätigen** | Übernimmt den Alarm wie bei einer Bestätigung in MoleSignal: Die Eskalation stoppt und MoleSignal weist den Alarm dem Konto zu, das auf die Schaltfläche geklickt hat. |
| **Beheben** | Beendet den Alarm. |
| **1 Stunde zurückstellen** | Setzt den Versand für eine Stunde aus. Steht die Bestätigung noch aus, bestätigt MoleSignal den Alarm zunächst. Nach Ablauf der Stunde wartet der Alarm wieder auf Bestätigung und MoleSignal benachrichtigt die zugewiesenen Konten erneut. Siehe [Maßnahmen bei einem Vorfall ergreifen](/de/alerting/incidents#maßnahmen-für-einen-vorfall). |
| **Alle bestätigen** | Erscheint nur in Nachrichten mit [zusammengefassten Benachrichtigungen](/de/notification-channels#benachrichtigungen-bündeln). Bestätigt bis zu 20 noch unbestätigte Alarme in der Nachricht. Telegram-Karten zeigen nur **In MoleSignal öffnen** an. |
| **In MoleSignal öffnen** | Öffnet die Seite des Vorfalls oder bei einer zusammengefassten Nachricht die Vorfallliste. Erfordert `http.external_url`. |

- Die Schaltflächen auf der Karte entsprechen dem Alarmstatus zum Zeitpunkt des Versands. Bei ausstehender Bestätigung zeigt die Karte „Bestätigen“, „Beheben“ und „1 Stunde zurückstellen“ an, nach der Bestätigung nur „Beheben“ und „1 Stunde zurückstellen“. Eine Entwarnung enthält keine Schaltflächen.
- Ein Klick führt die Aktion im Namen des mit dem IM-Konto verknüpften MoleSignal-Kontos aus. Dieses benötigt `alerts.incidents.acknowledge`. Ein noch nicht verknüpftes Konto erhält wie bei einer Anfrage einen einmalig nutzbaren Link per Privatnachricht. Siehe [Konten verknüpfen](#konten-verknüpfen). Kann der Telegram-Bot keine Privatnachricht senden, erscheint der Link in einer Gruppennachricht, die nur für das betreffende Konto sichtbar ist. Alternativ öffnet der Klick den privaten Chat mit dem Bot, der den Link dort sendet. Eine WeCom-App sendet stattdessen eine Nachricht. Ein Mattermost-Bot sendet eine Nachricht, die nur für das betreffende Konto sichtbar ist. Beide Nachrichten fordern dazu auf, das Konto zuerst im Profil als Benachrichtigungsmethode hinzuzufügen. Ist das IM-Konto mit mehreren MoleSignal-Konten verknüpft, bleibt der Klick ohne Wirkung.
- Nach einem Klick zeigt die Karte den aktuellen Alarmstatus an. MoleSignal erstellt den Inhalt erneut anhand der Vorlage der Benachrichtigungsrichtlinie, die die Karte gesendet hat. Eine Zeile zeigt an, welches Konto den Alarm bestätigt oder behoben hat. Nur die noch verfügbaren Schaltflächen bleiben sichtbar. Alle Gruppenmitglieder sehen dieselbe Karte. Sind keine Aktionen mehr verfügbar, bleibt auf einer WeCom-Karte eine funktionslose ✓-Schaltfläche sichtbar, da WeCom-Kartenvorlagen mindestens eine Schaltfläche erfordern.
- Feishu und Telegram zeigen nach einem Klick eine kurze Einblendung mit dem Ergebnis an. Bei einem Fehler zeigt Telegram stattdessen einen Hinweis zum Schließen an. Auf den anderen Plattformen erfährt nur das Konto, das geklickt hat, warum die Aktion fehlgeschlagen ist: Slack, Google Chat und Mattermost zeigen eine nur für dieses Konto sichtbare Nachricht an, Teams blendet eine Zeile ein und DingTalk und WeCom senden eine Direktnachricht.
- Die Schaltflächen verwenden die Oberflächensprache des Empfängerkontos. Karten an Gruppen verwenden die Standardsprache der Organisation.

### Interaktive DingTalk-Karten

Die interaktive Kartenvorlage legt das Layout einer DingTalk-Karte fest. MoleSignal füllt die Variablen der Vorlage aus und empfängt Klicks über die Stream-Verbindung.

<Steps>
  <Step title="Vorlage erstellen">
    Erstellen Sie auf der **Kartenplattform** der DingTalk-Entwicklerkonsole eine Vorlage für eine **Nachrichtenkarte** und verknüpfen Sie diese mit der App.
  </Step>
  <Step title="Variablen hinzufügen">
    Fügen Sie die Textvariablen `title`, `content`, `note`, `footer`, `open_text` und `open_url` hinzu. Fügen Sie außerdem `*_text` und `*_value` für jede Aktion hinzu: `acknowledge`, `resolve`, `snooze` und `acknowledge_all` sowie `approve` und `reject` für [Genehmigungskarten](#freigabekarten).
  </Step>
  <Step title="Komponenten anordnen">
    Binden Sie den Titel an `title`, den Markdown-Inhalt an `content` und zwei Zeilen mit kleiner Schrift an `note` (Konto, das den Alarm bestätigt oder behoben hat) und `footer` (Fußzeile der Vorlage). Fügen Sie für jede Aktion eine Schaltfläche hinzu. Binden Sie den Text an `*_text` und zeigen Sie die Schaltfläche nur an, wenn `*_text` nicht leer ist. Wählen Sie als Aktion eine **Callback-Anfrage** und binden Sie deren Parameter `value` an `*_value`. Fügen Sie eine weitere Schaltfläche hinzu, die `open_url` öffnet. Binden Sie ihren Text an `open_text` und zeigen Sie sie nur an, wenn `open_text` nicht leer ist.
  </Step>
  <Step title="Vorlage veröffentlichen und ID eingeben">
    Speichern und veröffentlichen Sie die Vorlage. Geben Sie ihre **Vorlagen-ID** im Konnektor unter **ID der Kartenvorlage** ein. Die App benötigt die Berechtigung zum Schreiben interaktiver Karten (`Card.Instance.Write`).
  </Step>
</Steps>

- Direkt gesendete Karten erreichen nur Mitglieder im Sichtbarkeitsbereich der App. Für Karten an eine Gruppe muss der Bot Mitglied der Gruppe sein.
- Ohne Vorlagen-ID sendet der Konnektor Alarmbenachrichtigungen wie bisher als ActionCard oder Markdown, ohne Schaltflächen.

### Schaltflächen einer WeCom-App

Eine WeCom-App (`wecom_app`) ist kein Mole Agent-Bot und braucht keine Aktivierung unter **IM**. Sobald die App unter **Nachrichten empfangen** Callbacks an MoleSignal sendet, erhalten Mitglieder Alarmbenachrichtigungen als Vorlagenkarten mit Schaltflächen. In App-Chats enthalten Benachrichtigungen keine Schaltflächen, weil WeCom keine Vorlagenkarten an App-Chats sendet.

<Steps>
  <Step title="Empfang über die API aktivieren">
    Öffnen Sie die App in der WeCom-Administrationskonsole, wählen Sie unter **Nachrichten empfangen** die Option **API-Empfang einrichten** und generieren Sie einen **Token** und einen **EncodingAESKey**.
  </Step>
  <Step title="Werte im Konnektor eingeben">
    Geben Sie die Werte im Konnektor unter **Callback-Token** und **EncodingAESKey** ein und speichern Sie die Einstellungen.
  </Step>
  <Step title="Callback-URL eingeben">
    Kopieren Sie die **Callback-URL** des Konnektors, `https://<external address>/api/v1/public/notify/<connector ID>/wecom`, tragen Sie sie unter **Nachrichten empfangen** als URL ein und speichern Sie die Einstellungen. WeCom ruft die URL sofort auf, um sie zu prüfen.
  </Step>
</Steps>

- Die Domain der Callback-URL muss in einer ICP-Registrierung des Unternehmens aufgeführt sein. WeCom muss den Pfad aus dem Internet erreichen können.
- MoleSignal lehnt Anfragen mit ungültiger Signatur ab, entschlüsselt den Inhalt mit dem EncodingAESKey und ignoriert Inhalte für andere Unternehmen.
- MoleSignal ordnet den Klick anhand der UserID des Mitglieds zu, die als verifizierte Benachrichtigungsmethode für diesen Konnektor hinterlegt ist.

### Schaltflächen eines Mattermost-Bots

Ein Mattermost-Bot (`mattermost_bot`) ist kein Mole Agent-Bot und braucht keine Aktivierung unter **IM**. Sobald `http.external_url` konfiguriert ist, enthalten seine Alarmbenachrichtigungen die Schaltflächen „Bestätigen“, „Beheben“ und „1 Stunde zurückstellen“. Ein Klick löst einen Callback an MoleSignal unter `https://<external address>/api/v1/public/notify/<connector ID>/mattermost?token=…` aus. Die Adresse enthält den Callback-Token des Konnektors. Mattermost gibt die Adresse nicht an seine Clients weiter.

- Der Mattermost-Server sendet die Anfrage und muss die externe Adresse erreichen können. Mattermost ruft private und interne Adressen nur auf, wenn der Host in der Systemkonsole unter **Umgebung → Entwickler → Nicht vertrauenswürdige interne Verbindungen zulassen zu** (`ServiceSettings.AllowedUntrustedInternalConnections`) eingetragen ist. Fügen Sie dort den Host aus `http.external_url` hinzu, wenn sich MoleSignal im internen Netzwerk befindet.
- MoleSignal ordnet den Klick anhand einer aktivierten und verifizierten Benachrichtigungsmethode für diesen Konnektor zu: dem Mattermost-Benutzernamen mit oder ohne `@` oder der Benutzer-ID. Kann MoleSignal den Klick keinem Konto zuordnen, erscheint eine nur für das betreffende Mattermost-Konto sichtbare Nachricht mit der Aufforderung, das Konto zuerst als Benachrichtigungsmethode hinzuzufügen.
- Bei einem ungültigen Callback-Token antwortet MoleSignal mit 401, bei einem deaktivierten Konnektor mit 404.
- Webhook-Nachrichten (`mattermost_webhook`) enthalten keine Schaltflächen, da sich Klicks keinem Konto zuordnen ließen. Sie enthalten nur den Link zum Alarm.

## Freigabekarten

Wenn Mole Agent einen Vorgang vorschlägt, der eine Freigabe erfordert, oder jemand eine Behebungsmaßnahme für einen Vorfall startet, sendet MoleSignal die Anfrage als Ereignis **Freigabe für Mole Agent angefordert** über die integrierte Benachrichtigungsrichtlinie **Genehmigung erforderlich: genehmigungsberechtigte Personen benachrichtigen**. MoleSignal benachrichtigt bis zu 20 Mitglieder mit der Berechtigung `agent.approve`, nie jedoch die anfragende Person. Jedes Mitglied erhält die Benachrichtigung über die eigenen Benachrichtigungsmethoden. Deckt eine [Vorabfreigabe](/de/alerting/remediation#vorabgenehmigung) die Anfrage ab, führt MoleSignal die Aktion sofort aus und sendet keine Benachrichtigung.

Bei Konnektoren, deren Alarmkarten Schaltflächen haben (siehe [Alarmkarten](#alarmkarten)), erscheint die Benachrichtigung als Karte mit diesen Schaltflächen:

| Schaltfläche | Funktion |
|---|---|
| **Freigeben** | Gibt die Anfrage frei. Sobald alle erforderlichen Freigaben vorliegen, führt MoleSignal die Aktion sofort aus, genau wie bei einer Freigabe im Freigabebereich von Mole Agent. |
| **Ablehnen** | Lehnt die Anfrage ab. MoleSignal führt die Aktion nicht aus. |
| **In MoleSignal öffnen** | Öffnet den Freigabebereich von Mole Agent. Erfordert `http.external_url`. |

- Ein Klick zählt als Aktion des mit dem IM-Konto verknüpften MoleSignal-Kontos. Der Konnektor erkennt dieses Konto ausschließlich anhand einer verifizierten Benachrichtigungsmethode. Das Konto benötigt die Berechtigung `agent.approve`. Die anfragende Person kann die Anfrage nicht freigeben. Ein noch nicht verknüpftes Konto erhält wie bei Alarmkarten einen Einmallink per Privatnachricht.
- Nach einem Klick zeigt die Karte die Anfrage ohne Schaltflächen sowie eine Zeile mit der Information, wer die Anfrage freigegeben oder abgelehnt hat und ob MoleSignal die Aktion ausgeführt hat. Die Person, die geklickt hat, erhält eine Rückmeldung zum Erfolg des Klicks.
- Wenn bereits an anderer Stelle eine Entscheidung gefallen ist oder dieselbe Person die Anfrage schon geprüft hat, ändert ein Klick die Anfrage nicht. Die Karte zeigt den aktuellen Status an.
- DingTalk-Karten zeigen die beiden Schaltflächen nur an, wenn die Vorlage die Variablen `approve_*` und `reject_*` enthält. Siehe [Interaktive DingTalk-Karten](#interaktive-dingtalk-karten).

## Einschränkungen

- Mole Agent liest Textnachrichten und den Text von Rich-Text-Nachrichten, in WeCom auch den Text von Sprachnachrichten. Bilder und Dateien ignoriert Mole Agent.
- Fällt der Server aus, auf dem ein Konnektor läuft, übernimmt ein anderer Server den Konnektor innerhalb von etwa einer Minute. Eine in dieser Zeit gestellte Frage beantwortet Mole Agent nach Wiederherstellung der Verbindung nur, wenn die Plattform sie erneut zustellt. Für Teams gilt das nicht: Der Server, der einen Callback empfängt, verarbeitet ihn auch.
- Nur der Server mit der Bot-Verbindung kann Antworten an WeCom senden. Liegt eine fertige Antwort auf einem anderen Server vor, leitet dieser sie an den Server mit der Bot-Verbindung weiter. Die Antwort kommt normalerweise innerhalb weniger Sekunden an.
- WeCom erlaubt pro Unterhaltung 30 Nachrichten pro Minute und 1.000 pro Stunde.
- Eine Telegram-Nachricht fasst höchstens 4.096 Zeichen. Längere Antworten verteilt Mole Agent deshalb auf mehrere Nachrichten.
- Wenn in MoleSignal oder auf einer anderen Karte jemand einen Alarm bestätigt oder schließt, bleiben bereits gesendete Alarmkarten unverändert. Ein Klick auf eine Schaltfläche auf einer dieser Karten zeigt an, dass der Alarm bereits bestätigt oder geschlossen ist, und aktualisiert die Karte.
