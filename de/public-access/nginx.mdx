Die folgende Konfiguration folgt der Empfehlung unter [Öffentlicher Zugriff](/de/public-access): Verwenden Sie einen einzigen Namen, `molesignal.example.com`. Das interne DNS löst ihn zur internen nginx-Adresse `10.0.0.10` auf, das öffentliche DNS zur öffentlichen Adresse `203.0.113.10`. Beide `server`-Blöcke nutzen dasselbe Zertifikat und unterscheiden sich anhand der Adressen, auf denen sie lauschen. Behalten Sie nur die `location`-Blöcke bei, die Sie verwenden.

## Gemeinsame Konfiguration

Definieren Sie den Upstream, das Logformat für den öffentlichen Zugriff und die Zone für die Ratenbegrenzung im `http`-Block, zum Beispiel am Anfang von `/etc/nginx/conf.d/molesignal.conf`:

```nginx
upstream molesignal {
    # A standalone node, or the router of a role-split deployment
    server 10.0.1.20:5080;
    keepalive 16;
}

# The public entry point logs paths, never query strings; heartbeat, calendar, action link and Huawei
# Cloud callback paths carry a token, so only their prefix is logged.
map $uri $molesignal_log_uri {
    ~^(/api/v1/(?:intake/heartbeats|public/calendar|public/notify/actions)/)  $1<token>;
    ~^(/notify/actions/)                                                      $1<token>;
    ~^(/api/v1/public/notify/[^/]+/(?:replies|keypress)/)                     $1<token>;
    default                                                                   $uri;
}

log_format molesignal_public '$remote_addr [$time_local] "$request_method $molesignal_log_uri $server_protocol" '
                             '$status $body_bytes_sent "$http_user_agent" $request_time';

limit_req_zone $binary_remote_addr zone=molesignal_public:10m rate=20r/s;
```

Alle `location`-Blöcke, die Anfragen weiterleiten, verwenden dieselben Proxy-Einstellungen aus `/etc/nginx/snippets/molesignal-proxy.conf`:

```nginx
proxy_pass http://molesignal;
proxy_http_version 1.1;
proxy_set_header Connection "";
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
```

## Interner Zugangspunkt

Der interne Zugangspunkt leitet wie bei einer Konfiguration ohne öffentlichen Zugangspunkt alle Pfade weiter. Live-Abfragen liefern Antworten als Stream. Puffern Sie diese Antworten nicht:

```nginx
server {
    listen 10.0.0.10:443 ssl;
    server_name molesignal.example.com;
    ssl_certificate     /etc/nginx/tls/molesignal.crt;
    ssl_certificate_key /etc/nginx/tls/molesignal.key;

    client_max_body_size 16m;

    location /api/v1/query/stream {
        include /etc/nginx/snippets/molesignal-proxy.conf;
        proxy_buffering off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }

    location / {
        include /etc/nginx/snippets/molesignal-proxy.conf;
        proxy_read_timeout 60s;
    }
}
```

## Öffentlicher Zugangspunkt

Geben Sie am öffentlichen Zugangspunkt nur die benötigten Pfade frei und erlauben Sie für jeden Pfad nur die benötigten Methoden. Der abschließende Block `location /` gibt für alle anderen Anfragen den Statuscode 404 zurück:

```nginx
server {
    listen 203.0.113.10:443 ssl;
    server_name molesignal.example.com;
    ssl_certificate     /etc/nginx/tls/molesignal.crt;
    ssl_certificate_key /etc/nginx/tls/molesignal.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    access_log /var/log/nginx/molesignal-public.log molesignal_public;
    client_max_body_size 2m;
    limit_req zone=molesignal_public burst=40 nodelay;
    limit_req_status 429;

    # External alerts
    location = /api/v1/intake/alerts {
        limit_except POST { deny all; }
        client_max_body_size 4m;
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Heartbeat check-ins
    location ^~ /api/v1/intake/heartbeats/ {
        limit_except GET POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # The Jira ticket webhook
    location ~ ^/api/v1/public/tickets/jira/[^/]+$ {
        limit_except POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # On-call calendar subscriptions
    location ^~ /api/v1/public/calendar/ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Mole Agent in Teams
    location ^~ /api/v1/public/im/teams/ {
        limit_except POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Replies to texts and calls; Huawei Cloud's address ends with the callback token
    location ~ ^/api/v1/public/notify/[^/]+/(replies|keypress)(/[^/]+)?$ {
        limit_except POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Buttons from a WeCom app: WeCom checks the address with a GET first
    location ~ ^/api/v1/public/notify/[^/]+/wecom$ {
        limit_except GET POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Buttons from a Mattermost bot
    location ~ ^/api/v1/public/notify/[^/]+/mattermost$ {
        limit_except POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # One-time action links: the confirm page and its API
    location ^~ /notify/actions/ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location ^~ /api/v1/public/notify/actions/ {
        limit_except GET POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Automation API triggers
    location ~ ^/api/v1/public/automations/[^/]+/trigger$ {
        limit_except POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Push sources
    location ~ ^/api/v1/(_kinesis_firehose|_cloudflare|_heroku)$ {
        limit_except POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # RUM: browsers send a CORS preflight first
    location ~ ^/api/v1/rum/(events|replay)$ {
        limit_except POST OPTIONS { deny all; }
        client_max_body_size 8m;
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Synthetics Probe Agent artifact uploads
    location ^~ /api/v1/synthetics/artifacts/ {
        limit_except PUT { deny all; }
        client_max_body_size 10m;
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Status pages
    location ^~ /status/ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location ^~ /api/v1/public/status-pages/ {
        limit_except GET POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Resource sharing
    location ^~ /s/ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location = /shared {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location ^~ /api/v1/public/share {
        limit_except GET POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # Web files of status pages, shared resources and action link pages
    location ^~ /assets/ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location ~ ^/favicon(-dark)?\.(ico|svg)$ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }

    # No other path exists on the internet
    location / {
        return 404;
    }
}
```

`limit_except GET` erlaubt auch `HEAD`. Um den Zugriff auf einen Pfad nach Quelladresse einzuschränken, fügen Sie dem zugehörigen `location`-Block `allow` und `deny all;` hinzu. Erlauben Sie so zum Beispiel den Zugriff auf den Teams-Callback nur aus den Adressbereichen des Azure-Diensttags `AzureBotService`.

## Benutzerdefinierte Domains für Statusseiten

Wenn eine Statusseite `status.example.org` verwendet, fügen Sie dafür einen öffentlichen `server`-Block hinzu. Geben Sie darin nur die Stammpfade, Endpunkte und Webdateien der Statusseite frei:

```nginx
server {
    listen 203.0.113.10:443 ssl;
    server_name status.example.org;
    ssl_certificate     /etc/nginx/tls/status.example.org.crt;
    ssl_certificate_key /etc/nginx/tls/status.example.org.key;

    access_log /var/log/nginx/molesignal-public.log molesignal_public;
    limit_req zone=molesignal_public burst=40 nodelay;
    limit_req_status 429;

    location ~ ^/(history|uptime)?$ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location ^~ /incidents/ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location ^~ /api/v1/public/status-pages/ {
        limit_except GET POST { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location ^~ /assets/ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location ~ ^/favicon(-dark)?\.(ico|svg)$ {
        limit_except GET { deny all; }
        include /etc/nginx/snippets/molesignal-proxy.conf;
    }
    location / {
        return 404;
    }
}
```

Wenn MoleSignal das Zertifikat für die benutzerdefinierte Domain selbst ausstellt, endet die TLS-Verbindung bei MoleSignal. nginx kann die Verbindung dann nur anhand von SNI mit dem `stream`-Modul durchreichen. Da nginx dabei keine Pfade sieht, kann es nicht gezielt nur die Statusseite freigeben. Verwalten Sie das Zertifikat in nginx, um die Pfade am Zugangspunkt einzuschränken.

## Konfiguration mit einem einzigen Zugangspunkt

Wenn nginx nur auf einer Adresse lauscht, unterscheiden Sie Anfragen anhand ihrer Quelladresse: Lassen Sie die freigegebenen Pfade im öffentlichen `server`-Block unverändert. Ersetzen Sie den abschließenden Block `location /` durch einen Block, der nur die Adressbereiche des Büronetzwerks und des VPN zulässt. Ergänzen Sie die Streaming-Einstellungen für Live-Abfragen:

```nginx
location /api/v1/query/stream {
    allow 10.0.0.0/8;
    allow 192.168.0.0/16;
    deny all;
    include /etc/nginx/snippets/molesignal-proxy.conf;
    proxy_buffering off;
    proxy_read_timeout 600s;
    proxy_send_timeout 600s;
}

location / {
    allow 10.0.0.0/8;
    allow 192.168.0.0/16;
    deny all;
    include /etc/nginx/snippets/molesignal-proxy.conf;
}
```

Interne Anfragen laufen dann über denselben `server`-Block. Erhöhen Sie `client_max_body_size` auf `16m`. Das Zugriffslog erfasst nun auch die Pfade interner Anfragen. Wenn ein Load Balancer vor nginx steht, übernehmen Sie die ursprüngliche Quelladresse mit `set_real_ip_from` und `real_ip_header`. Andernfalls berücksichtigt `allow` nur die Adresse des Load Balancers.

## Konfiguration prüfen

Prüfen Sie die Konfiguration und laden Sie sie neu:

```bash
nginx -t
```

```bash
nginx -s reload
```

Bei Anfragen aus dem Internet gibt der Anmeldeendpunkt `404` zurück:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://molesignal.example.com/api/v1/auth/signin
```

Wenn der Endpunkt für eingehende Alerts aus dem Internet eine Anfrage ohne Token erhält, gibt er `401` zurück. Das zeigt, dass die Anfrage MoleSignal erreicht hat:

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://molesignal.example.com/api/v1/intake/alerts
```

Tragen Sie abschließend in der Organisation `_sys` unter **Einstellungen → Client-IP-Erkennung** die nginx-Adressen als vertrauenswürdige Proxys ein. Weitere Informationen finden Sie unter [Client-IP-Erkennung](/de/settings/platform#client-ip-erkennung).
