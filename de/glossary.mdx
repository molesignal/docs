| Begriff | Definition |
|---|---|
| **Alarm** | Die Rolle, die Alarmregeln auswertet, Eskalationen steuert, geplante Berichte rendert und Konnektoren ausführt. Siehe [Rollenbasierte Bereitstellung](/de/deployment/role-based). |
| **API-Token** | Ein Bearer-Token im Format `mspat-<36>`, das den Zugriff im Namen eines Benutzer- oder Dienstkontos ermöglicht. Siehe [Identität und Zugriff](/de/identity). |
| **APM** | Überwachung der Anwendungsleistung. Mengenmäßig begrenzte Aggregate zu Diensten, Transaktionen, Abhängigkeiten, Fehlern und Versionen, die aus Trace-Spans abgeleitet sind. Siehe [APM](/de/apm). |
| **Arrow Flight SQL** | Das SQL-Protokoll auf Port `5083` für Datenbankclients wie DBeaver, JDBC und ADBC. Standardmäßig deaktiviert. Siehe [Mit einem Datenbankclient verbinden](/de/query/database-clients). |
| **Katalog** | Das Verzeichnis in PostgreSQL, das jedem Stream seine Parquet-Dateien und Indizes zuordnet. |
| **Verschlüsselungsschlüssel** | Der Hauptschlüssel in `MS_CIPHER_KEY`, mit dem MoleSignal die in PostgreSQL gespeicherten Geheimnisse verschlüsselt. Siehe [Checkliste für den Produktionsbetrieb](/de/deployment/production-checklist). |
| **Kompaktierung** | Das Zusammenführen kleiner Parquet-Dateien zu größeren Dateien. Die Rolle `compactor` übernimmt die Kompaktierung und setzt die Aufbewahrungsregeln durch. |
| **Konnektor** | Eine verwaltete Integration mit einer externen Plattform. Eine Quelle erfasst Logs, indem sie diese nach Zeitplan abruft oder von der Plattform entgegennimmt. Ein Ziel empfängt die Pipeline-Ausgabe. Siehe [Konnektoren](/de/connectors). |
| **Datenquelle** | Ein Eintrag im Datenquellenkatalog, der für eine Quelle den Endpunkt, das Token und einen Konfigurationsausschnitt generiert. Siehe [Datenquelle](/de/intake). |
| **Eskalationsrichtlinie** | Eine geordnete Liste von Benachrichtigungszielen mit Fristen für die Bestätigung. Siehe [Alarmierung](/de/alerting). |
| **Erweiterungstabelle** | Eine Nachschlagetabelle, die Schlüsseln Datensätze zuordnet. Pipelines lesen daraus, um Ereignisse anzureichern, und können Zeilen hineinschreiben. Siehe [Erweiterungstabellen](/de/extend-tables). |
| **Föderierte Abfrage** | Eine Abfrage, die auch entfernte Cluster durchsucht. Die Auswahl der Cluster erfolgt mit `?clusters=local,<name>`. Siehe [Rollenbasierte Bereitstellung](/de/deployment/role-based). |
| **Flush** | Das Schreiben der im Arbeitsspeicher eines Empfangsknotens gepufferten Daten in Parquet-Dateien und Indizes im Objektspeicher. |
| **Funktion** | Eine wiederverwendbare Transformation in VRL oder JavaScript. Siehe [Funktionen](/de/functions). |
| **Vorfall** | Ein ausgelöster Alarm, der die Phasen der Bestätigung und Behebung durchläuft. Siehe [Alarmierung](/de/alerting). |
| **Empfang** | Der Pfad, der Telemetriedaten entgegennimmt. Auch die Rolle, die diese Daten validiert, puffert und aus dem Puffer in den Objektspeicher schreibt. Siehe [Datenquelle](/de/intake). |
| **Token für die Datenaufnahme** | Ein Token für Sender und Bereitstellungspipelines gemäß der Berechtigungsrichtlinie **Datenerfassung**: `logs.write`, `metrics.write`, `traces.write`, `profiles.write` und `apm.deploy`. Siehe [Datenquelle](/de/intake#token-für-die-datenerfassung). |
| **Log-Analyse** | Ein Bericht, den Mole Agent auf Abruf oder nach Zeitplan über die Logs eines Zeitraums erstellt. Siehe [Log-Analysen](/de/logs/inspections). |
| **Mole Agent** | Der integrierte Agent für den Betrieb, der Probleme mit den Werkzeugen aus dem Werkzeugkatalog untersucht. Siehe [Mole Agent](/de/agent). |
| **Bereitschaftsplan** | Eine Rotation, die Zeitzonen und Ausnahmen berücksichtigt und als Ziel für Eskalationen dient. Siehe [Alarmierung](/de/alerting). |
| **Organisation** | Der Mandant und zugleich die Grenze für die Geltung von Richtlinien. Die Weboberfläche bezeichnet die Organisation als Arbeitsbereich. Siehe [Grundkonzepte](/de/concepts). |
| **Parquet** | Das spaltenorientierte Dateiformat, in dem MoleSignal Logs, Metriken und Traces speichert. |
| **Pipeline** | Eine Abfolge von Schritten, die Ereignisse beim Empfang in Echtzeit oder nach Zeitplan weiterleitet, normalisiert, bereinigt und anreichert. Eine Pipeline kann auch Alarmereignisse ändern, bevor die zugehörigen Vorfälle geöffnet werden. Siehe [Pipelines](/de/pipelines). |
| **Plattformadministrator** | Das über `[auth].root_email` festgelegte Benutzerkonto, das plattformweite Einstellungen verwaltet. |
| **Plattform-Stream** | Ein Stream, in den nur MoleSignal schreibt, etwa `_audit` oder `_synthetic_results`. Siehe [Streams](/de/streams#plattform-streams). |
| **Probe Agent** | Ein Prozess, der synthetische Prüfungen von einem Standort aus ausführt. Auf `standalone`-Knoten läuft ein integrierter Agent. Siehe [Synthetisches Monitoring](/de/synthetics). |
| **Rolle** | Eine mit `[node].roles` ausgewählte Prozessrolle: `standalone`, `router`, `intake`, `querier`, `compactor` oder `alert`. In IAM bezeichnet eine Rolle auch eine benannte Menge von Berechtigungen, die sich aus Berechtigungsrichtlinien und eigenen Berechtigungen zusammensetzt. |
| **RUM** | Real User Monitoring für Sitzungen in Browsern und mobilen Apps. Siehe [RUM](/de/rum). |
| **RUM-Client-Token** | Ein an eine Anwendung gebundenes Token mit der Berechtigung `rum.write`, das Browsercode und mobile Apps mitsenden. |
| **Gespeicherte Ansicht** | Eine gespeicherte Abfrage mit ihrem Zeitbereich und ihren Optionen. |
| **Suchjob** | Eine persistente asynchrone Abfrage. Abfragen oberhalb des Größenschwellenwerts laufen als Suchjobs und erscheinen unter **Streams → Suchjobs**. Siehe [Abfragen](/de/query). |
| **Eigentelemetrie** | Die Metriken, Traces und Profile, die MoleSignal über sich selbst im reservierten Stream `_molesignal` erfasst. Siehe [Selbstüberwachung](/de/self-observability). |
| **Dienstkonto** | Eine nicht personenbezogene Identität für Kollektoren und Automatisierung. Eine Anmeldung ist mit einem Dienstkonto nicht möglich. Siehe [Identität und Zugriff](/de/identity). |
| **Stummschalten** | Eine zeitlich begrenzte Regel, die Benachrichtigungen für passende Alarme aussetzt. Siehe [Alarmierung](/de/alerting). |
| **Standalone** | Die Standardrolle, die alle Rollen in einem Prozess ausführt. |
| **Statusseite** | Eine öffentliche oder private Seite, die den Status von Komponenten und Vorfälle anzeigt. Siehe [Statusseiten](/de/status-pages). |
| **Stream** | Die typisierte Spezifikation eines Signals: Name, Typ, Schema und Aufbewahrung. Siehe [Streams](/de/streams). |
| **Stream-Typ** | Einer der Typen `logs`, `metrics`, `traces`, `profiles` oder `extend`. |
| **Synthetischer Monitor** | Eine geplante Prüfung, etwa eine HTTP-Anfrage, die Verfügbarkeit und Latenz erfasst. Siehe [Synthetisches Monitoring](/de/synthetics). |
| **VRL** | Vector Remap Language, eine der Sprachen für Pipeline-Funktionen. |
| **WAL** | Das Write-Ahead-Log: Objekte im Objektspeicher, die bestätigte Datensätze bis zum Flush vorhalten. |
| **Arbeitsbereich** | Die Bezeichnung der Weboberfläche für die ausgewählte Organisation. |
