Die MoleSignal-Datenquelle ist ein Grafana-Plugin. Grafana liest Metriken mit PromQL, Logs und Traces mit den Feldabfragen der Seiten **Logs** und **Traces** und beliebige Streams mit SQL. Auch die Navigation zwischen den Signalen funktioniert: Eine Logzeile oder ein Exemplar öffnet den zugehörigen Trace, und jedes Ergebnis verlinkt zurück zu MoleSignal.

<Note>
Das Backend des Plugins läuft auf dem Grafana-Server. Grafana startet es als untergeordneten Prozess. Der Grafana-Server sendet jede Anfrage an MoleSignal mit dem Token der Datenquelle. Browser greifen nie direkt auf MoleSignal zu. Grafana Cloud erreicht MoleSignal in einem privaten Netzwerk über Private data source connect.
</Note>

## Voraussetzungen

| Element | Voraussetzung |
|---|---|
| Grafana | Version 12.3 oder höher, einschließlich 13.x. |
| MoleSignal | Eine Version, die das Feld `step` von [`POST /api/v1/query`](/de/api/query/execute) und den Parameter `expression` beim Lesen von [Logs](/de/api/web/logs) und [Traces](/de/api/web/trace) akzeptiert. **Speichern & testen** lehnt ältere Versionen ab, da diese bei Feldabfragen ungefilterte Ergebnisse liefern. |
| Netzwerk | Der Grafana-Server erreicht den HTTP-Port von MoleSignal, standardmäßig 5080. |
| Token | Ein API-Token eines Dienstkontos mit der Rolle **Betrachter**. Die Datenquelle verwendet `streams.read`, `streams.query`, `logs.read`, `traces.read` und `metrics.read`, für Anmerkungen und Variablen `dashboards.read` und `dashboards.annotations.read`, für Deployment-Anmerkungen `apm.deployments.read` und für Incident-Anmerkungen `alerts.incidents.read`. |

## Token für Grafana erstellen

1. Öffnen Sie **Identität und Zugriff → Dienstkonten** und wählen Sie **Dienstkonto erstellen**.
2. Geben Sie als **Name** `grafana` ein und wählen Sie die Rolle **Betrachter**.
3. Wählen Sie **Konto und Token erstellen** und kopieren Sie das Token. Es läuft nach 365 Tagen ab und erscheint nur einmal.

Beschränken Sie Grafana mit einem Token mit weniger Berechtigungen auf Lesezugriffe: Öffnen Sie **Identität und Zugriff → API-Token**, wählen Sie **Dienstkonto-Token erstellen**, wählen Sie das Konto und legen Sie die Richtlinie **Beobachter mit Lesezugriff** als **Geltungsbereich** fest. Siehe [API-Token und Dienstkonten](/de/identity/tokens).

Eine Datenquelle liest nur Daten aus der Organisation ihres Tokens. Alle Grafana-Konten mit Zugriff auf die Datenquelle können die Daten lesen, für die das Token Leserechte hat. Beschränken Sie den Zugriff mit den Datenquellenberechtigungen von Grafana oder richten Sie pro Team eine eigene Datenquelle mit eigenem Token ein.

## Plugin installieren

Installieren Sie das Release-Archiv mit der Grafana-CLI oder entpacken Sie es in das Plugin-Verzeichnis von Grafana. Bei den Linux-Paketen und im Docker-Image lautet der Pfad `/var/lib/grafana/plugins`:

```bash
grafana cli --pluginUrl https://github.com/molesignal/molesignal-grafana-plugin/releases/download/v0.1.0/molesignal-datasource-0.1.0.zip plugins install molesignal-datasource
```

Das Plugin hat noch keine Signatur. Erlauben Sie Grafana in `grafana.ini` oder mit der Umgebungsvariable `GF_PLUGINS_ALLOW_LOADING_UNSIGNED_PLUGINS=molesignal-datasource`, das Plugin zu laden. Starten Sie Grafana anschließend neu:

```ini
[plugins]
allow_loading_unsigned_plugins = molesignal-datasource
```

## Datenquelle hinzufügen

1. Öffnen Sie in Grafana **Verbindungen → Datenquellen**, wählen Sie **Neue Datenquelle hinzufügen** und wählen Sie **MoleSignal**.
2. Geben Sie die **URL** von MoleSignal ein, z. B. `https://molesignal.example.com`, und fügen Sie das **API-Token** ein.
3. Wählen Sie **Speichern & testen**.

**Speichern & testen** liest die MoleSignal-Version aus, prüft die Berechtigungen `streams.read` und `streams.query` des Tokens, zählt die Streams pro Typ und prüft, ob MoleSignal Feldabfragen unterstützt.

| Einstellung | Standard | Beschreibung |
|---|---|---|
| **URL** | | Die Adresse von MoleSignal ohne `/api/v1`. |
| **API-Token** | | Grafana speichert das Token verschlüsselt auf dem Server. |
| **TLS-Zertifikatsprüfung überspringen** | Aus | Nur für eine Testinstanz mit selbstsigniertem Zertifikat. |
| **CA-Zertifikat** | | Das Zertifikat der Zertifizierungsstelle, die das MoleSignal-Zertifikat signiert hat, im PEM-Format. |
| **Log-Stream** | | Der Standard-Stream für neue Logabfragen. Die Ad-hoc-Filter in Explore bieten die Felder dieses Streams an. |
| **Logfelder** | `message`, `level`, `trace_id` | Die Felder für Logzeile, Log-Level und Trace-ID. |
| **Scrape-Intervall** | `15s` | Das Intervall, in dem Metriken eintreffen. `$__rate_interval` beträgt mindestens das Vierfache dieses Intervalls. |
| **Verbundene Cluster** | Dieser Cluster | Die Cluster, die jede SQL- und PromQL-Abfrage erreicht, durch Kommas getrennt. |
| **MoleSignal-Webadresse** | Die URL | Die Zieladresse für Links mit der Bezeichnung **In MoleSignal öffnen**. |
| **Timeout (Sekunden)** | `60` | Die maximale Wartezeit für eine Anfrage an MoleSignal. |
| **Gleichzeitige Abfragen** | `10` | Die Anzahl der Abfragen, die pro Panel, Explore-Bereich oder Alarmregel gleichzeitig laufen. |

## Abfragetypen

| Abfragetyp | Liest | Zeigt |
|---|---|---|
| **PromQL** | Metriken als Bereichsabfrage im Intervall des Panels oder als Zeitpunktabfrage | Zeitreihen, eine Tabelle und Exemplare |
| **SQL** | Beliebige Streams | Eine Tabelle, Zeitreihen oder Logzeilen |
| **Logs** | Die neuesten Einträge eines Log-Streams, die zur Feldabfrage passen | Logzeilen |
| **Trace** | Einen Trace anhand seiner ID | Die Trace-Ansicht |
| **Trace-Suche** | Traces, die zur Feldabfrage passen | Eine Tabelle, aus der sich jeder Trace öffnen lässt |
| **RED** | Anfragen pro Sekunde, Fehler pro Sekunde, die Fehlerquote oder ein Perzentil der Dauer für Spans, die zur Feldabfrage passen | Zeitreihen; bei Auswahl eines Felds unter **Nach** eine Zeitreihe pro Feldwert |
| **Servicegraph** | Aufrufe zwischen Services | Einen Knotengraphen |

### PromQL

Eine Bereichsabfrage liest einen Datenpunkt pro Schritt. Als Schrittweite dient das Intervall des Panels, begrenzt durch **Min. Schrittweite** und höchstens 11.000 Schritte pro Zeitreihe. **Legende** benennt jede Zeitreihe. `{{label}}` steht dabei für den Wert eines Labels. **Exemplare** zeigt die Exemplare der Zeitreihe an. Jedes Exemplar öffnet den zugehörigen Trace. MoleSignal unterstützt eine [Teilmenge von PromQL](/de/query/promql-subset).

### Feldabfragen

**Logs**, **Trace-Suche** und **RED** verwenden dieselbe Feldabfragesyntax wie die MoleSignal-Seiten **Logs** und **Traces**. Eine Abfrage hat daher an beiden Stellen dieselbe Bedeutung:

```text
level = 'error' AND (service.name = 'checkout' OR timeout)
```

| Element | Bedeutung |
|---|---|
| `AND`, `OR`, Klammern | `AND` hat Vorrang vor `OR`. Klammern gruppieren Ausdrücke. |
| `=`, `!=`, `>`, `>=`, `<`, `<=`, `contains` | Vergleichen ein Feld mit einem Wert. |
| `field in ('a', 'b')` | Prüft in Trace-Abfragen, ob das Feld einen der angegebenen Werte enthält. |
| `MATCH(field, 'text')`, `MATCH_TEXT(field, 'words')` | Durchsuchen ein Feld in Logabfragen per Volltextsuche. |
| Ein einzelnes Wort oder eine Phrase in Anführungszeichen | Der gesuchte Text. |

Die Zeile **Bedingung hinzufügen** erstellt aus **Feld**, **Operator** und **Wert** einen Vergleich und fügt ihn mit `AND` zur Abfrage hinzu. **RED** liest entweder **Eingangs-Spans**, die den Eingang einer Anfrage bei einem Service markieren, oder **Alle Spans**.

### SQL

SQL liest beliebige Streams. **Stream** legt fest, für welchen Stream Grafana die Anweisung plant. Bleibt das Feld leer, gilt die Tabelle nach `FROM`. Wählen Sie unter **Formatieren** zwischen **Tabelle**, **Zeitreihe** und **Logs**. Die folgenden Makros verwenden das Zeitfenster des Panels:

| Makro | Ergebnis |
|---|---|
| `$__timeFilter(_timestamp)` | `_timestamp >= <from> AND _timestamp < <to>` |
| `$__timeGroup(_timestamp, $__interval)` | `date_bin(INTERVAL '<interval>', _timestamp)` |
| `$__timeFrom()`, `$__timeTo()` | Beginn und Ende des Zeitfensters als Zeitstempel |

`$__interval`, `$__rate_interval` und `$__range` funktionieren in PromQL und SQL, auch in Alarmregeln.

## Explore

| Aktion | Ergebnis |
|---|---|
| Logabfrage ausführen | Zeigt oberhalb der Logzeilen das Logvolumen nach Log-Level an. |
| Kontext einer Logzeile öffnen | Zeigt jeweils 50 Einträge vor und nach der Logzeile an. |
| In den Details einer Logzeile nach einem Wert filtern oder ihn ausschließen | Fügt `field = 'value'` oder `field != 'value'` mit `AND` zur Abfrage hinzu. |
| Die Trace-ID einer Logzeile oder ein Exemplar auswählen | Öffnet den zugehörigen Trace neben der Abfrage. |
| **In MoleSignal öffnen** auswählen | Öffnet dieselbe Abfrage mit demselben Zeitfenster in MoleSignal. |

## Variablen und Ad-hoc-Filter

Eine Abfragevariable listet eine der folgenden Optionen auf:

| Liste | Werte |
|---|---|
| **Streams** | Die Streams eines Typs. |
| **Felder** | Die Felder eines Streams. |
| **Feldwerte** | Die häufigsten Werte eines Felds in einem Log-Stream. |
| **Metriken** | Metriknamen, optional nur solche, die einen bestimmten Text enthalten. |
| **Labelwerte** | Die Werte eines Labels einer Metrik. |
| **SQL** | Die erste Spalte einer Anweisung. |

Sind für eine Variable mehrere Werte ausgewählt, folgt die Liste der Syntax der jeweiligen Abfragesprache: `(a|b)` für `=~` in PromQL, `'a', 'b'` für `IN (...)` in SQL und `'a', 'b'` für `in (...)` in einer Trace-Feldabfrage.

Ad-hoc-Filter schränken PromQL-Abfragen mit Label-Matchern in jedem Selektor und Feldabfragen mit `AND`-Bedingungen ein. Ihre Schlüssel und Werte stammen aus dem **Log-Stream** der Datenquelle.

## Annotationen

Eine Annotationsabfrage markiert Ereignisse aus einer **Quelle** in den Panels eines Dashboards:

| Quelle | Markiert |
|---|---|
| **Annotationen** | Die Annotationen von MoleSignal, optional nur solche mit einem **Tag**. |
| **Deployments** | Die von [APM](/de/apm/deployments) erfassten Deployments, optional nur für einen Dienst. |
| **Vorfälle** | Vorfälle von Beginn bis zur Behebung, optional nur für einen Dienst. |

## Alarmierung

Grafana-Alarmregeln führen PromQL- und SQL-Abfragen über das Backend des Plugins aus. Die [Alarmierung von MoleSignal](/de/alerting) bietet zusätzlich Echtzeitregeln, Vorfälle, Bereitschaftsdienst und Eskalation. Löst Grafana einen Alarm aus, kann dieser MoleSignal als [externer Alarm](/de/alerting/sources#grafana) erreichen.

## Dashboards

Über die Registerkarte **Dashboards** der Datenquelle lassen sich zwei Dashboards importieren:

| Dashboard | Zeigt |
|---|---|
| **MoleSignal · Dienste** | Anfragen, Fehler und Dauer für jeden Dienst, den Dienstgraphen und die langsamsten Traces. |
| **MoleSignal · Logs** | Das Log-Volumen und die neuesten Fehler eines Log-Streams. |

## Grenzwerte

| Element | Grenzwert |
|---|---|
| Log-Abfrage | Die neuesten 1.000 Datensätze oder mit **Zeilenlimit** bis zu 5.000. |
| Trace-Suche | 100 Traces oder mit **Zeilenlimit** bis zu 5.000. |
| Trace | Der Trace muss innerhalb der letzten 31 Tage des ausgewählten Zeitfensters begonnen haben. |
| PromQL | 11.000 Schritte pro Zeitreihe und 100.000 Datenpunkte pro Abfrage. Bei Überschreitung behält MoleSignal pro Zeitreihe Datenpunkte in gleichmäßigen Abständen bei. |
| SQL | 10.000 Zeilen oder mit **Zeilenlimit** bis zu 1.000.000. |

Die Grafana-Apps Logs Drilldown, Traces Drilldown und Metrics Drilldown unterstützen nur Loki, Tempo und Prometheus und können diese Datenquelle daher nicht öffnen.
