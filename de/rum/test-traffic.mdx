Eine Sitzung hat den Typ `user`, `synthetics` oder `ci_test`. Wenn eine [synthetische Browserprüfung](/de/synthetics) eine Seite mit [Browser-SDK](/de/rum/browser-sdk) 0.3.0 oder neuer öffnet, entsteht automatisch eine Sitzung vom Typ `synthetics`. Die Ereignisse enthalten die Prüfung in `synthetics.test_id`, die Ausführung in `synthetics.result_id` (die `task_id` des Ausführungsergebnisses) und den Standort in `synthetics.location_id`.

## Auswirkungen auf die Kennzahlen

Die Kennzahlen einer Anwendung spiegeln die tatsächliche Nutzung wider. Daher bleiben Testsitzungen an folgenden Stellen unberücksichtigt:

- auf den Seiten für Übersicht, Performance, Frustration, Fehler, Analysen, Heatmaps und Feature Flags sowie in den integrierten Dashboards;
- in [Alarmregeln für RUM-Kennzahlen](/de/rum/alerts);
- in den Ergebniszeilen des Explorers und in den RUM-Tools von Mole Agent.

Fehler in Testsitzungen erzeugen keine [Issues](/de/rum/errors). Eine fehlgeschlagene Prüfung zählt daher nicht als neues Issue. Wenn eine Seite Testsitzungen ausschließt, zeigt sie den Link **N Testsitzungen ausgeschlossen** an. Der Link führt zu diesen Sitzungen.

Für Testsitzungen gilt außerdem kein Sampling: Die [Aufbewahrung](/de/rum/sampling) der Anwendung behält sie vollständig bei. Sobald ein Anwendungsfilter `session.type` angibt, gelten für Testsitzungen dieselben Filter und Aufbewahrungsquoten wie für andere Sitzungen. Das SDK behält eine solche Sitzung unabhängig vom eigenen Wert für `sessionSampleRate` bei.

## Testsitzungen finden

- Über eine Ausführung: Klicken Sie beim Versuch eines Browserprüfergebnisses auf **RUM-Sitzung dieser Ausführung öffnen**.
- Über die Sitzung: Die Sitzungsseite zeigt den Sitzungstyp an und verlinkt auf die Ergebnisse der Prüfung.
- Im Explorer: Abfragen mit `session.type`, `synthetics.*` oder `ci_test.*` sowie Abfragen nach einer einzelnen `session.id` wenden die angegebenen Kriterien ohne zusätzlichen Ausschluss an. So findet `session.type = 'synthetics'` die synthetischen Sitzungen. Ohne solche Kriterien zeigt der Explorer nur tatsächliche Nutzungsaktivitäten an. Die Liste der Werte für `session.type` enthält alle Sitzungstypen.
- Über die API: Dasselbe gilt für die Filter von `search`, `aggregate`, `facets` und `histogram`.

## Anwendungstests

Setzen Sie dieselbe globale Variable, bevor die Seite ein Skript ausführt. In Playwright:

```ts
await page.addInitScript((id) => {
  window.__MOLESIGNAL_TEST_CONTEXT__ = { type: 'ci_test', test_execution_id: id };
}, process.env.GITHUB_RUN_ID);
```

Das SDK setzt `window.__MOLESIGNAL_RUM_SESSION__` auf die ID der aufgezeichneten Sitzung. Die Prüfung liest die ID aus, um auf die Sitzung zu verlinken. Am Ende des Testablaufs verlässt die Prüfung die Seite, damit das SDK die noch gepufferten Daten sendet.

<Note>
Die Seite muss ein Browser-SDK in einer Version nach 0.2.0 verwenden, damit aus der Sitzung hervorgeht, wodurch sie ausgelöst wurde. Für SDK-Anfragen gilt wie für alle anderen Anfragen die Richtlinie der Prüfung für ausgehenden Datenverkehr. Wenn diese Richtlinie MoleSignal nicht zulässt, schlägt die Prüfung fehl.
</Note>
