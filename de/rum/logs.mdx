Das Browser-SDK erfasst Logs zusammen mit der zugehörigen Sitzung und Ansicht. So führt ein Log zum Replay, und die Sitzung zeigt, was die Seite protokolliert hat. Das SDK sendet erst Daten, wenn ein Log entsteht oder die Konsolenerfassung aktiviert ist. Logs erfordern das [Browser-SDK](/de/rum/browser-sdk) ab Version 0.3.0.

```ts
import { molesignalRum } from '@molesignal/browser-rum';

molesignalRum.logger.info('cart opened', { items: 3 });

const payments = molesignalRum.createLogger({ name: 'payments', level: 'warn', context: { provider: 'stripe' } });
payments.error('payment declined', { code: 402 }, error);
```

Ein Logger überspringt Meldungen unterhalb seiner Logstufe und unterstützt `debug`, `info`, `warn` und `error`. Wenn der Logger als drittes Argument ein Fehlerobjekt erhält, erfasst der Log den Fehlertyp und den Stacktrace.

Leiten Sie auch die Konsolenausgaben der Seite weiter:

```ts
init({ /* … */ forwardConsoleLogs: ['warn', 'error'] }); // or 'all'
```

Die Konsolenausgaben bleiben unverändert. Lassen Sie die Weiterleitung deaktiviert, wenn die Konsole personenbezogene Daten enthalten kann, oder prüfen Sie, welche Daten die Anwendung [bei der Erfassung entfernt](/de/rum/privacy#sensible-texte-beim-empfang-bereinigen). Das betrifft auch den Text und den Stacktrace eines Logs.

## Wo Logs erscheinen

- Auf der [Sitzungsseite](/de/rum/explorer#sitzung-öffnen) listet der Tab **Logs** unter dem Replay die Logs chronologisch auf und hebt den Eintrag hervor, den das Replay gerade erreicht hat. Klicken Sie auf eine Zeile, um im Replay zum entsprechenden Zeitpunkt zu springen.
- Im [Explorer](/de/rum/explorer) ist **Logs** ein Eintragstyp.
- Unter **Logs** ist `rum_logs` ein regulärer Log-Stream mit `level` und `message`. Das Histogramm der Logstufen und die übrigen Funktionen stehen wie bei anderen Logs zur Verfügung.

Wenn die Anwendung eine Sitzung [nicht speichert](/de/rum/sampling), bleiben keine Logs zurück. Die Anzahl der Logs fließt nicht in die Zählung für die Ansicht ein.

## Fehler im SDK

Bei Fehlern im SDK selbst (wenn der Server ein Ereignis ablehnt oder `beforeSend` eine Ausnahme auslöst) schreibt das SDK einen Log mit dem Logger `molesignal-rum` und der Herkunft `sdk`. Es protokolliert jeden Fehler nur einmal und begrenzt die Anzahl dieser Logs pro Seitenaufruf auf wenige Einträge. Übertragungsfehler protokolliert das SDK nicht, da auch der Log den Server nicht erreichen würde. Deaktivieren Sie diese Logs mit `trackSdkErrors: false`. Das SDK ruft `onError` in beiden Fällen auf.

## Felder

| Spalte | Beschreibung |
|---|---|
| `level` | `debug`, `info`, `warn` oder `error`. |
| `message` | Die Logmeldung. |
| `log.id` | Die ID des Logs. |
| `log.logger` | Der Name des Loggers: `console` für die Konsole, `molesignal-rum` für das SDK selbst. |
| `log.origin` | `logger`, `console`, `report` oder `sdk`. |
| `log.error_type`, `log.stack` | Fehlertyp und Stacktrace des protokollierten Fehlers. |
