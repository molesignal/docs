Eine Heatmap zeigt, wie eine Seite einer Browseranwendung genutzt wird. Unter **Analysen → Heatmap** gibt es zwei Karten:

- **Klicks**: Zeigt, wo Klicks landen. Je mehr Klicks an einer Stelle landen, desto wärmer ist die Farbe. Die angeklickten Elemente stehen in einer Liste neben der Karte.
- **Scrolltiefe**: Zeigt, wie weit Aufrufe nach unten reichen. Je weiter unten, desto dunkler ist die Seite. Gestrichelte Linien markieren, bis wohin 75, 50 und 25 Prozent der Aufrufe reichen.

Heatmaps setzen das [Browser-SDK](/de/rum/browser-sdk) ab Version 0.3.0 voraus. Das SDK meldet, wo Klicks landen und wie weit Aufrufe nach unten reichen.

Eine Karte zeigt genau eine Seite für eine Fensterkategorie (Desktop ab 1024 Pixel Breite, Tablet ab 600 Pixel, Smartphone darunter), da sich das Layout je nach Fensterbreite unterscheidet. Die URL enthält alle ausgewählten Einstellungen. Teilen Sie die URL, um die Karte in ihrem aktuellen Zustand weiterzugeben.

## Voraussetzungen

Das Browser-SDK liefert die Daten für die Karten.

| Karte | Voraussetzung |
|---|---|
| Klicks | `trackUserInteractions: true` |
| Scrolltiefe | Keine: `trackScroll` ist standardmäßig aktiviert |
| Seite unter der Karte | [Sitzungswiedergabe](/de/rum/session-replay) für mindestens einige Sitzungen mit einem Aufruf dieser Seite |

Auch Klicks auf Elemente, die keine Bedienelemente sind, zählen. Sie zeigen, wo ein Bedienelement erwartet wird.

## Die Seite unter der Karte

Als Hintergrund dient eine [Aufzeichnung](/de/rum/session-replay) einer Sitzung, in der die Seite geöffnet wurde. Sie zeigt die Seite in voller Länge zum Zeitpunkt, an dem sie vollständig geladen war. Wählen Sie unter **Aufzeichnung** eine der letzten 20 Sitzungen aus, die diese Seite in dieser Fensterkategorie aufgezeichnet haben. **Diese Sitzung öffnen** führt zur angezeigten Sitzung.

Was in der Sitzungswiedergabe maskiert ist, bleibt auch hier maskiert. Zum Anzeigen der Seite ist `rum.replay.read` erforderlich. Auch ohne Aufzeichnung oder Berechtigung bleiben die Daten verfügbar: die Elemente in der Liste und die Scrolltiefen in der Tabelle.

## So ordnet die Heatmap Klicks zu

Für jeden Klick erfasst das SDK das Zielelement und die Position innerhalb dieses Elements. So erscheint der Klick unabhängig von der Fenstergröße auf demselben Element. Die Heatmap findet das Element anhand seiner Position in der Seitenstruktur der Aufzeichnung (`action.target.path`, nur Tags und Positionen, keine Texteingaben). Fehlt ein Element in der Aufzeichnung, weil sich die Seite geändert hat, zeigt die Heatmap die Klicks an ihren ursprünglichen Positionen auf der Seite. In der Liste steht dann **In dieser Seitenaufzeichnung nicht sichtbar**.

Bei Datensätzen aus älteren SDK-Versionen ohne dieses Feld gruppiert die Heatmap die Klicks nach Selektor. Findet der Selektor ein Element, zeigt die Heatmap die Klicks in dessen Mitte an.

## So berechnet die Heatmap die Werte

Die Heatmap zählt die gespeicherten Datensätze. Wenn eine Anwendung [nur einen Teil ihrer Sitzungen speichert](/de/rum/sampling), zeigt die Heatmap, wo Klicks landen, aber nicht, wie viele Klicks es insgesamt gab. [Durch Tests erzeugte Sitzungen](/de/rum/test-traffic) zählen nicht mit.

Die Scrolltiefe reicht vom oberen Rand der Seite bis zum unteren Rand des Fensters. Jeder Aufruf, der eine bestimmte Tiefe erreicht, zählt auch für alle darüberliegenden Tiefen. Der Anteil der Aufrufe kann daher mit zunehmender Scrolltiefe nicht steigen.

## Mole Agent

Das Tool `get_rum_heatmap` liefert dieselben Daten für eine Seite als Zahlen: die Elemente mit den meisten Klicks, die Seitenlänge und den Anteil der Aufrufe, die die jeweilige Scrolltiefe erreichen.
