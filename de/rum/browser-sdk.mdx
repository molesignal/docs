Das MoleSignal Browser RUM SDK erfasst Seitenaufrufe, Benutzerinteraktionen, Frontend-Fehler, Web Vitals, Netzwerkressourcen,
lange Tasks, [Logs](/de/rum/logs) und Kontext zur Trace-Korrelation und sendet diese Daten als [RUM-Ereignisse](/de/rum/events).

## Voraussetzungen

- URL der MoleSignal-Instanz;
- eine [RUM-Anwendung](/de/rum/applications) wie `checkout-web`;
- das Client-Token der Anwendung;
- Node 24 oder höher für die Installation über npm.

<Warning>
  `clientToken` steht im Browsercode und ist für Benutzer sichtbar. Verwenden Sie niemals ein Inhaber-Token, ein Administrator-Token
  oder ein persönliches Token. Verwenden Sie das an die Anwendung gebundene Client-Token. Alle Token beginnen mit `mspat-`. Das
  SDK kann die Token-Typen daher nicht unterscheiden.
</Warning>

## Anwendung und Token abrufen

Öffnen Sie **RUM → Anwendungen**, klicken Sie auf **Anwendung erstellen** und wählen Sie die Plattform **Browser**. Die Anwendung öffnet sich mit ihrem
Client-Token. **Einrichtungsanleitung öffnen** zeigt den Endpunkt, das Token und ein Codebeispiel mit bereits eingetragener Kennung an. Unter
**Datenquelle** finden Sie in **Web-RUM** dieselbe Anleitung. Das Token ist auch über die
[API](/de/api/auth/rum-token) verfügbar.

## Installieren und initialisieren

<Steps>
  <Step title="Paket installieren">
    ```bash
    npm install @molesignal/browser-rum
    ```
  </Step>
  <Step title="SDK einmalig initialisieren">
    ```ts
    import { init } from '@molesignal/browser-rum';

    const rum = init({
      applicationId: 'checkout-web',
      clientToken: 'mspat-your-client-token',
      site: 'https://molesignal.example.com',
      service: 'web-frontend',
      env: 'production',
      version: 'v1.4.0',
      sessionSampleRate: 100,
      trackUserInteractions: true,
    });
    ```

    `init` gibt den Client zurück. `initRum` ist der frühere Name derselben Funktion. `molesignalRum` stellt dieselbe API als
    Singleton bereit: `molesignalRum.init(...)` und `molesignalRum.setUser(...)`. `init` führt Aufrufe von `molesignalRum`, die vor `init` eingehen,
    nachträglich aus.

    Initialisieren Sie das SDK, bevor der Anwendungsrouter eingebunden wird, damit das SDK den ersten Seitenaufruf erfasst.
    Das Paket lässt sich beim serverseitigen Rendering gefahrlos importieren und initialisieren. Die Browserinstrumentierung
    startet erst, wenn Browser-APIs verfügbar sind.
  </Step>
  <Step title="Erste Sitzung überprüfen">
    Öffnen Sie **RUM → Explorer** und wählen Sie einen Zeitraum, der den aktuellen Zeitpunkt einschließt. Prüfen Sie, ob
    die Sitzung angezeigt wird. Öffnen Sie die Sitzung, um ihre Ansichten, Anfragen und Fehler zu sehen.
  </Step>
</Steps>

Geben Sie für `site` die Origin der MoleSignal-Instanz mit oder ohne einen der Pfade `/api`, `/api/v1` oder `/api/v1/rum` an. Das SDK sendet Ereignisse an
`POST /api/v1/rum/events` und Replay-Segmente an `POST /api/v1/rum/replay`. Das SDK sendet `applicationId` als `application.id`.
MoleSignal verwirft Ereignisse, wenn `application.id` nicht zur Anwendung des Tokens gehört.

## Über ein Script-Tag laden

`dist/molesignal-rum.js` ist ein eigenständiges Bundle, das rrweb und web-vitals enthält und die globale Variable
`MoleSignalRum` definiert. Laden Sie das Bundle mit diesem Codebeispiel asynchron. Die an `onReady` übergebenen Callbacks laufen erst, wenn das Skript geladen ist:

```html
<script>
  (function (w, d, s, u, n) {
    w[n] = w[n] || { q: [], onReady: function (callback) { w[n].q.push(callback); } };
    var script = d.createElement(s);
    script.async = 1;
    script.src = u;
    d.head.appendChild(script);
  })(window, document, 'script', 'https://cdn.jsdelivr.net/npm/@molesignal/browser-rum@0.4.0/dist/molesignal-rum.js', 'MoleSignalRum');

  MoleSignalRum.onReady(function () {
    MoleSignalRum.init({
      applicationId: 'checkout-web',
      clientToken: 'mspat-your-client-token',
      site: 'https://molesignal.example.com',
      service: 'web-frontend',
      env: 'production',
      version: 'v1.4.0',
    });
  });
</script>
```

Binden Sie die Datei zum synchronen Laden in ein `<script src>`-Tag ein und rufen Sie anschließend `MoleSignalRum.init(...)` auf.

## Ansichten und Sitzungen

Eine Ansicht entspricht einem Seitenaufruf oder einer Route. Das SDK meldet eine Ansicht beim Start, bei Änderungen mit einem höheren Wert für `view.revision`
(höchstens alle drei Sekunden), während der Laufzeit alle fünf Minuten und ein letztes Mal, wenn die Ansicht
endet: beim Routenwechsel, beim Sitzungsende oder wenn die Seite ausgeblendet oder entladen wird. Das SDK erkennt Routenwechsel anhand der
History API und `popstate`. Setzen Sie `trackViewsManually: true` und rufen Sie `startView` auf, um Ansichten zu benennen und ihren Start festzulegen.

Das SDK sendet keine Sitzungsereignisse: MoleSignal leitet Sitzungen aus den Ansichten ab. Das Cookie
`_msrum_s_<applicationId>` speichert die Sitzung für alle Tabs der Anwendung. Die Sitzung endet nach 15 Minuten Inaktivität oder spätestens nach vier
Stunden. Die nächste Benutzeraktivität startet eine neue Sitzung. Das SDK entscheidet einmal pro Sitzung über die Aufnahme in die Stichprobe. Siehe [Daten-Sampling](/de/rum/sampling). Setzen Sie
`trackSessionAcrossSubdomains: true` oder `sessionCookieDomain: '.example.com'`, um die Sitzung subdomainübergreifend zu nutzen.
`stopSession()` beendet die Sitzung für alle Tabs. Ohne Cookies speichert das SDK die Sitzung pro Seite im Arbeitsspeicher.

## Benutzer identifizieren und Kontext hinzufügen

Geben Sie die Benutzerdaten möglichst bei der Initialisierung an, damit bereits die erste Sitzung die richtige Identität enthält.

```ts
const rum = init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  user: { id: currentUser.id, plan: currentUser.plan },
  globalContext: { region: 'eu-west-1' },
});

rum.setUser({ id: 'user-42', name: 'Ada', email: 'ada@example.com' });
rum.setUserProperty('plan', 'enterprise');
rum.setAccount({ id: 'acme' });
rum.setGlobalContextProperty('checkout_step', 'payment');
```

`setUser` benötigt mindestens einen der Schlüssel `id`, `name` oder `email`. Weitere Schlüssel bleiben als Eigenschaften erhalten. Ohne gesetzte Benutzerdaten legt das SDK
eine stabile anonyme Kennung in `localStorage` an. Setzen Sie `trackAnonymousUser: false`, wenn die Datenschutzrichtlinie keine
dauerhafte anonyme Kennung erlaubt. Das SDK fügt den über Setter festgelegten Kontext allen nachfolgenden Ereignissen hinzu. Es führt den globalen Kontext, den Ansichtskontext
und den Kontext des Aufrufs in dieser Reihenfolge zusammen. Bei Konflikten gilt der zuletzt übernommene Wert.

## Einwilligung zum Tracking

```ts
const rum = init({ /* … */ trackingConsent: 'not-granted' });

rum.setTrackingConsent('granted');
```

Solange keine Einwilligung vorliegt, legt das SDK weder Cookies noch anonyme Kennungen oder Tab-Kennungen an. Es richtet keine
Instrumentierung ein und sendet keine Daten. Bei einem Widerruf stoppt das SDK die Instrumentierung und löscht seine Kennungen sowie die
persistente Warteschlange.

## Benutzerdefinierte Aktionen, Fehler, Zeitmessungen und Vitals hinzufügen

```ts
rum.addAction('Checkout submitted', { cart_size: 3 });

try {
  await submitOrder();
} catch (error) {
  rum.addError(error, { component: 'CheckoutForm' });
}

// Views: with trackViewsManually, or to name a route.
rum.startView({ name: 'Order confirmation', context: { step: 3 } });
rum.setViewName('Order confirmation (3DS)');

// Custom timings and feature flags belong to the current view.
rum.addTiming('cart_ready');
rum.addFeatureFlagEvaluation('new_checkout', true);

// Durations.
const vital = rum.startDurationVital('checkout_form_ready', { description: 'form is usable' });
rum.stopDurationVital(vital);

// The page is ready when the application says so: this replaces the loading time of the view.
rum.setViewLoadingTime();

// Logs.
rum.logger.warn('cart is stale', { age_ms: 90000 });

await rum.flush();
```

Rufen Sie vor einer gesteuerten Navigation oder dem Herunterfahren `rum.flush()` auf, um auf den Versand der Ereignisse in der Warteschlange zu warten. Rufen Sie `rum.stop()` auf, um
die Instrumentierung zu entfernen und die ausstehenden Ereignisse zu versenden. [Alarmregeln](/de/rum/alerts#von-der-anwendung-gemessene-kennzahlen) können benutzerdefinierte Zeitmessungen und
Vitals überwachen. Für [Feature Flags](/de/rum/feature-flags) gibt es eine eigene Seite. [Logs](/de/rum/logs) landen im Stream `rum_logs`.

## Auf die Wiedergabe einer Sitzung verlinken

`getSessionReplayLink()` gibt die URL der aktuellen Sitzung in MoleSignal zurück. Fügen Sie die URL bei Bedarf einem Support-Ticket oder einem
Fehlerbericht hinzu. Die Funktion gibt `undefined` zurück, wenn das SDK noch nicht gestartet ist, die Sitzung nicht in der Stichprobe liegt oder keine Einwilligung vorliegt. Die
Funktion bildet die URL aus `appUrl`. Standardmäßig entspricht `appUrl` dem Wert von `site`. Setzen Sie `appUrl`, wenn die URL der MoleSignal-Oberfläche vom Sendeziel des SDK abweicht.

```ts
ticket.replay = molesignalRum.getSessionReplayLink();
```

Zum Öffnen des Links sind eine Anmeldung und die Berechtigung `rum.replay.read` erforderlich.

## React

`@molesignal/browser-rum/react` übernimmt die Routen des Routers als SDK-Ansichten und benennt sie nach ihren Routenmustern
(`/orders/:id`, nicht `/orders/42`). Das Paket meldet außerdem Fehler, die im Komponentenbaum ausgelöst werden. React ist eine optionale Peer-Abhängigkeit.

```tsx
import { init } from '@molesignal/browser-rum';
import { reactPlugin, RumErrorBoundary, trackReactRouter } from '@molesignal/browser-rum/react';

init({ /* … */ plugins: [reactPlugin()] });
trackReactRouter(router); // a router of createBrowserRouter; trackTanStackRouter for TanStack Router

root.render(
  <RumErrorBoundary fallback={<Oops />}>
    <RouterProvider router={router} />
  </RumErrorBoundary>,
);
```

## Remote-Konfiguration

Mit `remoteConfiguration: true` liest das SDK vor dem Start die [SDK-Einstellungen der Anwendung](/de/rum/applications#sdk-fernkonfiguration).
So lassen sich Sampling-Raten und die Datenschutzstufe ändern, ohne die Seite neu zu veröffentlichen.

## Standardeinstellungen für die automatische Erfassung

| Daten | Option | Standard |
|---|---|---|
| Seitenaufrufe | `trackViewsManually` | Automatische Erfassung über die History API (`false`) |
| Fetch, XHR und Ressourcenladezeiten | `trackResources` | `true` |
| Lange Animationsframes und lange Tasks | `trackLongTasks` | `true` |
| Web Vitals der Ansicht | `trackWebVitals` | `true` |
| Klicks | `trackUserInteractions` | `false` |
| Scrolltiefe in der Ansicht | `trackScroll` | `true` |
| Rage-Klicks, wirkungslose Klicks und Klicks mit Fehlern | `trackFrustrations` | Wie bei der Interaktionserfassung |
| Laufzeitfehler, unbehandelte Promise-Ablehnungen und fehlgeschlagene Anfragen | integriert | Aktiviert |
| `console.error` | `trackConsoleErrors` | `false` |
| Konsolenausgaben als [Logs](/de/rum/logs) | `forwardConsoleLogs` | `[]` |
| SDK-Fehler als Logs | `trackSdkErrors` | `true` |
| Header von Anfragen und Antworten | `trackResourceHeaders` | `[]` |
| Wiederherstellung einer Seite aus dem Back/Forward-Cache | `trackBfcacheViews` | `false` |
| DOM-basierte Sitzungswiedergabe | `sessionReplaySampleRate` | `0` |

Das SDK kennzeichnet Sitzungen, die ein Test auslöst. Siehe [Testtraffic](/de/rum/test-traffic). Ressourcen, Fehler und lange Tasks, die während der Verarbeitung eines Klicks beginnen, erhalten dessen `action.id` und zählen zu dieser Aktion. Eine fehlgeschlagene
Anfrage erzeugt einen Fehler mit der Quelle `network` und der betroffenen Anfrage in `error.resource`. FCP, LCP und FID beschreiben den Seitenladevorgang.
Das SDK meldet diese Werte für die erste Ansicht. `web-vitals` misst INP und CLS einmal pro Seitenladevorgang. Das SDK meldet
jeden Wert für die Ansicht, in der die maßgebliche Interaktion oder Layoutverschiebung auftrat.

## Browseranfragen mit Traces verknüpfen

Bei URLs, die für das Tracing zugelassen sind, behalten die fetch- und XMLHttpRequest-Integrationen einen vorhandenen W3C-Header `traceparent` bei oder fügen einen neuen hinzu. Anschließend
lesen sie den Trace-Kontext aus der Anfrage, der Antwort oder einem `Server-Timing`-Eintrag namens `traceparent`. Die Integrationen schreiben die Trace-ID und die Span-ID
in `resource.trace_id` und `resource.span_id`. So kann MoleSignal eine Browseranfrage mit Backend-Traces verknüpfen. Standardmäßig
fügen die Integrationen den Trace-Kontext nur bei Anfragen an denselben Origin hinzu und lesen ihn nur dort aus. Geben Sie bei Cross-Origin-APIs die Antwortheader frei und erlauben Sie
den Origin ausdrücklich:

```http
Access-Control-Expose-Headers: traceparent, server-timing
```

```ts
allowedTracingUrls: [
  'https://api.example.com',
  /^https:\/\/edge-\w+\.example\.com\//,
]
```

## Konfiguration

| Option | Standardwert | Zweck |
|---|---|---|
| `applicationId` | erforderlich | Kennung der Anwendung; das SDK sendet sie als `application.id` |
| `clientToken` | erforderlich | An die Anwendung gebundenes Client-Token (`mspat-<36>`) |
| `site` | erforderlich | MoleSignal-Origin oder Basis-URL mit `/api`, `/api/v1` oder `/api/v1/rum` |
| `service` | `applicationId` | `service` der Ereignisse |
| `env`, `version` | nicht gesetzt | Deployment-Dimensionen. Die Suche nach Source Maps setzt `version` voraus |
| `debugId` | nicht gesetzt | Debug-ID des Builds; das SDK sendet sie in Stack-Frames von Fehlern als `debug_id` |
| `user`, `account`, `globalContext` | nicht gesetzt | Anfängliche Identität und benutzerdefinierte Attribute |
| `trackingConsent` | `granted` | Tracking und Erstellung von Kennungen entweder starten oder vollständig zurückstellen |
| `sessionSampleRate` | `100` | Prozentsatz der Sitzungen, die das SDK erfasst |
| `sessionReplaySampleRate` | `0` | Prozentsatz der erfassten Sitzungen, die das SDK zur Wiedergabe aufzeichnet |
| `sessionInactivityTimeout` | `900000` | Dauer der Inaktivität bis zum Sitzungsende, in Millisekunden |
| `maxSessionDuration` | `14400000` | Maximale Sitzungsdauer in Millisekunden |
| `defaultPrivacyLevel` | `mask` | `mask`, `mask-user-input` oder `allow`: Legt fest, welche Seiteninhalte und Eingaben das SDK übermittelt. Siehe [Datenschutz](/de/rum/privacy) |
| `trackUrlQueryString` | `false` | Querystrings in gemeldeten URLs beibehalten |
| `excludedUrls` | `[]` | Anfrage-URLs per String, RegExp oder Callback ausschließen |
| `allowedTracingUrls` | derselbe Origin | Anfragen, die Trace-Kontext erhalten und beisteuern |
| `traceSampleRate` | `100` | Prozentsatz der durch Anfragen gestarteten Traces, die das Backend behalten soll (W3C-Sampled-Flag). Die übrigen Anfragen enthalten weiterhin einen Trace-Kontext und bleiben so mit ihrer Trace-ID verknüpft |
| `trackResourceHeaders` | `[]` | Header von fetch- oder XHR-Anfragen nach Name oder RegExp auswählen und erfassen. Das SDK erfasst keine Zugangsdaten |
| `forwardConsoleLogs` | `[]` | Konsolenmethoden, die auch Logs schreiben: `'all'` oder eine Auswahl aus `debug`, `log`, `info`, `warn` und `error` |
| `trackSdkErrors` | `true` | SDK-Fehler in den Logs der Anwendung erfassen, begrenzt auf wenige Einträge pro Seitenaufruf |
| `trackScroll` | `true` | Scrolltiefe pro Seitenansicht erfassen |
| `compressIntakeRequests` | `false` | Anfragen mit Ereignissen per gzip komprimieren, sofern der Browser dies unterstützt |
| `remoteConfiguration` | `false` | Vor dem Start die [Anwendungseinstellungen](/de/rum/applications#sdk-fernkonfiguration) auslesen |
| `appUrl` | `site` | URL zum Öffnen von MoleSignal, die `getSessionReplayLink` verwendet |
| `plugins` | `[]` | SDK-Erweiterungen wie `reactPlugin()` |
| `enablePersistentQueue` | `true` | Nicht gesendete Telemetriedaten nach dem Neuladen aus IndexedDB wiederherstellen |
| `flushInterval`, `batchSize` | `5000`, `50` | Sendeintervall und Anzahl der Ereignisse pro Anfrage. Ein Batch enthält höchstens 100 Ereignisse |
| `maxQueueSize` | `1000` | Anzahl der Ereignisse, die das SDK im Offlinebetrieb vorhält |
| `beforeSend` | nicht gesetzt | Ereignis prüfen, ändern oder verwerfen |
| `onError` | nicht gesetzt | SDK-Diagnosen zu fehlgeschlagenen Uploads und abgelehnten Ereignissen erhalten |
| `transport` | fetch des Browsers | Ereignisse über einen eigenen Proxy senden |

`beforeSend(event, { kind })` erhält das Ereignisobjekt im [Ereignisformat](/de/rum/events). Geben Sie `false` zurück, um das Ereignis zu verwerfen;
das SDK lässt das Verwerfen eines `view`-Ereignisses nicht zu, weil sonst die Zählwerte nicht mehr stimmen.

## Übermittlung

Das SDK stellt Ereignisse in eine Warteschlange, sendet sie in Batches und speichert sie in IndexedDB, bis der Server sie annimmt. Bei einem Netzwerkfehler oder den Statuscodes `408`, `425`, `429` oder `5xx`
wiederholt das SDK die Anfrage mit exponentiell steigenden Wartezeiten und berücksichtigt `Retry-After`. Ereignisse, die MoleSignal **ablehnt**,
sendet das SDK nicht erneut, sondern meldet sie über `onError`. Bei jedem anderen `4xx`-Statuscode verwirft das SDK den Batch. Ist die Warteschlange voll, verwirft das SDK zuerst Ressourcen, dann lang laufende
Aufgaben, Replay-Daten, Web Vitals, Aktionen, Fehler und zuletzt Seitenansichten. Beim Verlassen der Seite sendet das SDK die wichtigsten Ereignisse zuerst in einer einzigen
`keepalive`-Anfrage. Tabs derselben Anwendung teilen sich die Warteschlange, ohne Ereignisse mehrfach zu senden.

## Upgrade von 0.2

- Bei `defaultPrivacyLevel: 'allow'` bleiben Feldeingaben jetzt sichtbar. Ausgenommen sind Passwörter, E-Mail-Adressen, Telefonnummern sowie Felder für Karten-
  oder Einmalcodes. `mask-user-input` entspricht dem bisherigen Verhalten von `allow`. Wechseln Sie zu dieser Einstellung, um Eingaben weiterhin zu maskieren.
- Das SDK meldet auch Klicks außerhalb von Bedienelementen als Klicks.

## Upgrade von 0.1

Version 0.2 stellt das SDK ohne Kompatibilitätsmodus auf das RUM-Ereignisformat um.

- Das SDK sendet Ereignisse nur noch an `POST /api/v1/rum/events`. Die Endpunkte für Sitzungen, Aktionen und Fehler entfallen. Benutzerdefinierte `transport`-
  Funktionen erhalten `kind: 'events' | 'replay'`.
- Das SDK sendet Seitenansichten statt Sitzungen. Ressourcen, lang laufende Aufgaben und Seitenansichten sind eigenständige Ereignisse. Rage-Klicks und wirkungslose Klicks kennzeichnet das SDK
  im Klickereignis unter `action.frustration.type`.
- `beforeSend` erhält Ereignisobjekte im Ereignisformat. `context.kind` enthält den Ereignistyp.
- Tabs speichern die Sitzung in einem gemeinsamen Cookie. Standardmäßig endet die Sitzung nach 15 Minuten Inaktivität.
- Der Server ermittelt Browser, Betriebssystem und Gerät anhand von `User-Agent`.
- Erstellen Sie zuerst die Anwendung. MoleSignal stellt Tokens nur für vorhandene Anwendungen aus.
