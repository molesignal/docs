Öffnen Sie **Logs**, um Log-Streams im aktiven Arbeitsbereich zu durchsuchen.

## Stream und Zeitraum auswählen

Wählen Sie einen Log-Stream und legen Sie den kürzesten Zeitraum fest, der das Ereignis enthält. Kürzere Zeiträume
verringern die Zahl der gescannten Zeilen und beschleunigen die Untersuchung der Felder.

MoleSignal kann das Schema eines Streams aus eingehenden Ereignissen ableiten. Der Bereich **Felder** listet die Felder des
Streams auf. Dort können Sie Filter hinzufügen, ohne die gesamte Abfrage neu zu schreiben.

## Abfrage-Tabs

Jede Abfrage läuft in einem eigenen Tab. Jeder Tab behält seinen Stream, seine Abfrage und seinen Zeitraum. Eine Abfrage in
einem Tab wirkt sich nicht auf andere Tabs aus.

- Wählen Sie **Neuer Tab**, um eine weitere Abfrage zu öffnen. Bis zu 10 Tabs können gleichzeitig geöffnet sein.
- Öffnen Sie das Tab-Menü und wählen Sie **Umbenennen**, **Duplizieren** oder **Schließen**.
- Wählen Sie **Ansicht teilen**, um zwei Tabs nebeneinander anzuzeigen. Jede Hälfte listet ihre eigenen Tabs auf. Verschieben Sie einen Tab
  über sein Menü auf die andere Seite. **Teilung aufheben** beendet die geteilte Ansicht.

Der Browser speichert offene Tabs pro Benutzerkonto und Arbeitsbereich.

## Abfrage schreiben

Der Editor bietet zwei Modi: **Code** und **Editor**. Wechseln Sie den Modus über die Symbole neben dem Titel (`</>` für
Code, Blöcke für Editor). Zeigen Sie auf ein Symbol, um den Namen des Modus zu sehen.

In **Code** können Sie eine Feldabfrage oder SQL eingeben. Eine Anweisung, die mit `SELECT` oder `WITH` beginnt, läuft als SQL.
Alle anderen Eingaben laufen als Feldabfrage:

| Feldabfrage | Bedeutung |
|---|---|
| `service = 'checkout'` | Das Feld hat genau diesen Wert. |
| `message contains 'timeout'` | Das Feld enthält den Text. |
| `MATCH(message, 'timeout')` | Suche nach einer Teilzeichenfolge ohne Beachtung der Groß- und Kleinschreibung. |
| `MATCH_TEXT(message, 'timeout disk')` | Volltextsuche in einem Feld mit Volltextindex. |

Verknüpfen Sie Bedingungen mit `AND` und `OR`. Die Groß- und Kleinschreibung spielt dabei keine Rolle. `AND` hat Vorrang vor `OR`. Klammern
gruppieren Bedingungen: `level = 'error' AND (service = 'checkout' OR service = 'payments')`. Text
ohne Feldangabe sucht MoleSignal im Feld `message`. Dieser Text kann auch eine der Alternativen sein:
`timeout OR "connection reset"`. Anführungszeichen halten eine Wortgruppe zusammen, auch wenn sie ein Wort wie `or` enthält.
Verwenden Sie für Vergleiche `=`, `!=`, `>`, `>=`, `<` und `<=`.

**Editor** zeigt dieselbe Feldabfrage als Filterzeilen an, eine pro Alternative:
Alle Filter einer Zeile müssen zutreffen. Vor jeder Zeile außer der ersten steht **ODER**. Wählen Sie **Filtern**,
um einer Zeile einen Filter hinzuzufügen, oder **ODER**, um eine Zeile hinzuzufügen. Wählen Sie dann ein Feld, einen Vergleichsoperator und einen Wert. Jede
Zeile hat einen eigenen Suchtext. Ein geklammerter Ausdruck in einer Zeile, etwa die `OR`-Verknüpfung im
Beispiel oben, bleibt unverändert. Bearbeiten Sie ihn in **Code**. SQL-Anweisungen lassen sich nicht als
Filter anzeigen.

Verwenden Sie SQL für Joins, Ausdrücke, CTEs oder Aggregationen:

```sql
SELECT "_timestamp", level, msg, trace_id
FROM app
WHERE level = 'error'
ORDER BY "_timestamp" DESC
LIMIT 200;
```

```sql
SELECT level, COUNT(*) AS events
FROM app
GROUP BY level
ORDER BY events DESC;
```

Führen Sie die Abfrage mit **Ausführen** aus oder drücken Sie im Editor `⌘ Enter` oder `Ctrl+Enter`. Die **Referenz zur
Abfragesyntax** enthält Beispiele für den aktuellen Modus. Die Funktionen für die Textsuche finden Sie unter
[Abfragen](/de/query#textsuche).

Der Abfrageplaner beschränkt auch benutzerdefinierte SQL-Abfragen auf die aktuelle Organisation.

## Felder untersuchen

Der Bereich **Felder** hat drei Abschnitte: **Angezeigte Felder**, **Indizierte Felder** und **Weitere
Felder**. Felder mit demselben Namenspräfix vor dem ersten Punkt, etwa `http.method` und
`http.route`, lassen sich als Gruppe öffnen.

- Öffnen Sie ein Feld, um seine häufigsten Werte im Ergebnis zu sehen. Fügen Sie einen Wert als Einschluss- oder
  Ausschlussfilter hinzu. Der Filter schränkt die gesamte Abfrage ein: Enthält die Abfrage Alternativen, setzt MoleSignal diese in Klammern,
  bevor es den Filter anwendet.
- Blenden Sie ein Feld als Ergebnisspalte ein oder aus.
- Wählen Sie bei einem Feld **Analysieren**, um die Feldanalyse zu öffnen: die Anzahl unterschiedlicher Werte, die Zeilen
  mit und ohne Wert, Statistiken für numerische Felder, die Werteverteilung und die häufigsten
  Werte im Zeitverlauf.

## Ergebnisse lesen

Das Histogramm über den Ergebnissen zählt alle Ereignisse im Zeitraum, die zur Abfrage passen, nicht
nur die Ereignisse auf der geladenen Seite. Vier Ansichten zeigen das Ergebnis:

| Ansicht | Inhalt |
|---|---|
| **Logs** | Die passenden Ereignisse, eines pro Zeile. |
| **Statistik** | Ein Diagramm für eine Aggregation. Wählen Sie die Kennzahl (Anzahl, Anzahl unterschiedlicher Werte, Durchschnitt, Summe, Minimum, Maximum, P50, P95 oder P99), die Gruppierung und den Diagrammtyp oder stellen Sie das Ergebnis einer SQL-Aggregation dar. **Dashboard erstellen** speichert das Diagramm als Panel in einem neuen Dashboard. |
| **KI-Analyse** | Ein Bericht von Mole Agent zu den Logs, die zur Abfrage passen. Siehe [Log-Analysen](/de/logs/inspections). |
| **Muster** | Nach Muster gruppierte Ereignisse mit Anzahl und Anteil pro Muster. |

In der Ansicht **Logs**:

- Legen Sie unter **Spalten** fest, welche Spalten in welcher Reihenfolge erscheinen. Die Standardspalten stammen aus den Feldern des
  Streams: zuerst die Zeit und dann, sofern vorhanden, die Felder für Log-Level, Service und Meldung.
- Die Seitengröße beträgt 100, 200, 500, 1.000, 2.000 oder 5.000 Ereignisse.
- Klicken Sie auf ein Ereignis, um es in einem Seitenbereich neben den Ergebnissen zu öffnen. Ziehen Sie am linken Rand, um die Breite zu ändern.
  Die eingestellte Breite bleibt erhalten. Die Kopfzeile zeigt das Log-Level, die Zeit, die Meldung und die Attribute, die das
  Ereignis beschreiben (Service, Host, Umgebung, Version, Trace). Für jedes Attribut stehen dieselben Aktionen wie für ein
  Feld zur Verfügung. Die Ansichten sind **Felder**, bei vorhandener Trace-ID **Trace**, **Kontext** und
  **JSON-Rohdaten**. **Trace** zeigt das Wasserfalldiagramm des Traces. Der Span des Ereignisses ist ausgewählt. **Kontext**
  zeigt je fünf Zeilen vor und nach dem Ereignis. Fügen Sie über ein Feld einen Filter hinzu, kopieren Sie den Wert oder zeigen Sie das
  Feld als Spalte an.
- Wechseln Sie zu einem Trace, einem Service, einer Metrik oder einem anderen korrelierten Signal, wenn entsprechende Kennungen vorliegen.
- Laden Sie das Ergebnis als CSV, Text oder JSON herunter.

## Abfrage teilen

Die Seitenadresse bildet die angezeigte Abfrage ab. Beim Ausführen einer Abfrage schreibt die Seite den Stream, die
Anweisung (`q` für Feldabfragen, `sql` für SQL) und die Ergebnisansicht in die Adresse. Teilen Sie die Abfrage, indem Sie
die Adresse aus der Adressleiste kopieren. Der Zeitraum entspricht der Auswahl, zum Beispiel der letzten
Stunde. Beim Neuladen der Seite bleiben die Abfrage und der Zustand des Editors erhalten.

Wählen Sie **Teilen**, um einen Link zur angezeigten Abfrage zu kopieren. Nur angemeldete Mitglieder der
Organisation mit Leseberechtigung für die Daten können den Link öffnen. Wählen Sie den Zeitraum für den Link: **Aktuell ausgewählter Zeitraum**
fixiert den angezeigten Start- und Endzeitpunkt. Die andere Option behält einen relativen Zeitraum bei, etwa die
letzte Stunde ab dem Zeitpunkt, zu dem der Link geöffnet wird.

## Suchjobs

Eine Suche, die für eine interaktive Anfrage zu umfangreich ist, läuft als Suchjob. Öffnen Sie
**Streams → Suchjobs**, um den Job zu verfolgen und das Ergebnis herunterzuladen. Siehe
[Streams](/de/streams#suchjobs).

## Gespeicherte Ansichten

Speichern Sie eine SQL-Abfrage unter einem Namen als [gespeicherte Ansicht](/de/saved-views). Öffnen Sie die Ansicht erneut, führen Sie die Abfrage
für einen anderen Zeitraum aus oder fügen Sie die Ansicht einem Bericht hinzu.

<Tip>
  Behalten Sie stabile Dimensionen wie `service.name`, `deployment.environment`, `trace_id` und
  `host.name` bei der Datenerfassung bei. Diese Felder ermöglichen einen zuverlässigen Wechsel zwischen korrelierten Signalen.
</Tip>

## Berechtigungen

- `streams.read` erlaubt das Auffinden von Streams und Schemas.
- `logs.read` erlaubt das Lesen von Logs: Liste, Histogramm und Feldstatistiken.
- `streams.query` erlaubt das Ausführen von SQL-Anweisungen und das Öffnen des Kontexts.
- `agent.use` erlaubt das Ausführen einer KI-Analyse. Dafür ist auch ein aktiviertes KI-Modell erforderlich.
- `saved_views.create`, `saved_views.edit` und `saved_views.delete` erlauben das Erstellen, Bearbeiten und Löschen gespeicherter Ansichten.
