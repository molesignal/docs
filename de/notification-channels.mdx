MoleSignal trennt die Zugangsdaten der Anbieter von Empfängern und Routing. Konfigurieren Sie einen Konnektor einmal,
verknüpfen Sie Identitäten oder Fallback-Ziele und legen Sie dann fest, wann die Benachrichtigungs-Engine diese
Routen verwendet.

| Ressource | Zweck |
|---|---|
| **Konnektoren** | Speichern Zugangsdaten der Anbieter und Transporteinstellungen auf Organisationsebene. |
| **Benutzerrouting** | Verknüpft Anbieteridentitäten und legt die Reihenfolge persönlicher Zustellziele fest. |
| **Richtlinien** | Gleichen Ereignisse ab, ermitteln Empfänger, wählen Vorlagen aus und steuern die Eskalation. |
| **Vorlagen** | Stellen wiederverwendbare Nachrichtentexte pro Kanal bereit: Eine allgemeine Vorlage gilt für alle Kanäle, und SMS, Telefonanrufe und andere Kanäle können jeweils eine eigene Vorlage haben. |
| **Fallback-Routen** | Legen die Reihenfolge der Ziele auf Team- und Organisationsebene fest, wenn die persönliche Zustellung fehlschlägt. |
| **Zustellprotokoll** | Zeigt Zustellversuche, Latenz, Fehler, Wiederholungsversuche, Bestätigungen und Eskalationen an. |

Legen Sie für jeden Konnektor einen Timeout zwischen 1 und 60 Sekunden fest. Verwenden Sie absolute `http`- oder `https`-
URLs.

Die Typauswahl gruppiert Konnektortypen nach Kanal: **Instant Messaging**, **Telefonanrufe**, **SMS**
(einschließlich WhatsApp), **E-Mail** und **Integrationen**. Zu den Integrationen gehören PagerDuty, Amazon SNS und
Webhook.

Der Konnektor zeigt die Anbieteradresse schreibgeschützt an. Kopieren Sie die Adresse bei Bedarf. Alibaba Cloud, Tencent Cloud und
AWS (einschließlich Amazon SNS) beziehen die API-Basis-URL aus der gewählten Region, PagerDuty aus der gewählten
Dienstregion und Lark- und Slack-Apps aus der gewählten Plattform. Ein Teams-Bot bezieht seine Dienst-URL
aus der gewählten Cloud. Die übrigen Konnektoren verwenden die feste Anbieteradresse, etwa die Adresse für die dauerhafte Verbindung eines WeCom-Smart-Bots
oder die Microsoft-Anmeldeadresse für E-Mail. Huawei Cloud ist die Ausnahme:
Die Adresse gehört zur Anwendung und keine API listet sie auf. Kopieren Sie die Adresse daher aus der Konsole. Vor dem Speichern, Testen oder direkten Senden
gleicht MoleSignal diese Adressen mit der Liste des Anbieters ab und lehnt jede andere über die API angegebene Adresse ab.
So gelangen die Zugangsdaten nur an den vorgesehenen Anbieter. Nach dem Speichern lässt sich der Typ eines Konnektors nicht mehr ändern.

Geben Sie den Server für einen Mattermost- oder Matrix-Bot genauso an wie eine Webhook-URL. MoleSignal verbindet sich
nur mit den Adressen, zu denen der Hostname aufgelöst wird, blockiert Adressen von Cloud-Metadatendiensten und folgt keinen
Weiterleitungen.

## Konnektor erstellen und testen

Zum Anzeigen von Konnektoren ist `notify.connectors.read` erforderlich. Zum Erstellen, Bearbeiten, Testen, Aktivieren, Deaktivieren oder
Löschen von Konnektoren ist `notify.connectors.manage` erforderlich.

<Steps>
  <Step title="Benachrichtigungsverwaltung öffnen">
    Wechseln Sie zu **Einstellungen → Benachrichtigungen → Konnektoren**.
  </Step>
  <Step title="Anbieter auswählen">
    Klicken Sie auf **Neuer Konnektor**, geben Sie einen eindeutigen Namen ein und wählen Sie den Konnektortyp aus. Der Konnektortyp
    lässt sich nach dem Erstellen nicht mehr ändern.
  </Step>
  <Step title="Anbietereinstellungen eingeben">
    Geben Sie die unten beschriebenen Zugangsdaten und Transporteinstellungen ein. Lassen Sie **Versand über diesen Konnektor
    erlauben** aktiviert, es sei denn, Sie bereiten den Konnektor für eine spätere Verwendung vor.
  </Step>
  <Step title="Konnektor speichern">
    Klicken Sie auf **Konnektor speichern**. MoleSignal speichert die gesamte Konfiguration verschlüsselt. API-Antworten
    ersetzen vertrauliche Werte durch `***`.
  </Step>
  <Step title="Testnachricht senden">
    Bearbeiten Sie den gespeicherten Konnektor, wählen Sie einen kompatiblen Zieltyp aus, geben Sie ein echtes Ziel ein und klicken Sie auf
    **Verbindung testen**. Je nach Ergebnis des letzten Tests wechselt der Konnektorstatus zu **Verbunden** oder
    **Fehler**.
  </Step>
</Steps>

<Note>
  Speichern Sie einen neuen Konnektor vor dem Testen. Lassen Sie beim Bearbeiten eines Konnektors einen als `***` maskierten Wert unverändert,
  damit der gespeicherte geheime Wert erhalten bleibt.
</Note>

## Einzelne Anbieter konfigurieren

### E-Mail per SMTP

Geben Sie den SMTP-Host, den Port und eine gültige **Absenderadresse** ein. Wählen Sie unter
**Authentifizierung**, wie sich MoleSignal anmeldet:

| Authentifizierung | Eingaben |
|---|---|
| **Benutzername und Passwort** | **Benutzername**, falls der Server einen verlangt, und **Passwort**. Falls der E-Mail-Anbieter ein App-Passwort oder einen Autorisierungscode verlangt, verwenden Sie diesen Wert als Passwort. |
| **Microsoft 365 (OAuth 2.0)** | **Mandanten-ID**, **Client-ID** und **Client-Secret** einer in Microsoft Entra ID registrierten App. Geben Sie unter **Benutzername** das Absenderpostfach ein. Siehe [Microsoft 365](#microsoft-365). |
| **Google Workspace (OAuth 2.0)** | **Dienstkontoschlüssel (JSON)** eines Dienstkontos mit domainweiter Delegierung. Geben Sie unter **Benutzername** das Absenderpostfach ein. Siehe [Google Workspace](#google-workspace). |

Beide OAuth-2.0-Methoden nutzen ein Zugriffstoken (SASL XOAUTH2) statt eines Passworts. Sie funktionieren
auch dann, wenn Anbieter die Anmeldung mit Passwort abschalten: Microsoft deaktiviert die Standardauthentifizierung für SMTP
AUTH bei bestehenden Exchange Online-Mandanten Ende 2026 standardmäßig. MoleSignal behält ein Token bis eine
Minute vor Ablauf und meldet sich nach einem fehlgeschlagenen Versand erneut an.

Wählen Sie einen der folgenden TLS-Modi:

| TLS-Modus | Einsatz |
|---|---|
| `none` | Die SMTP-Verbindung nutzt kein TLS. Vermeiden Sie diesen Modus in nicht vertrauenswürdigen Netzwerken. |
| `starttls` | Der Server stellt die Verbindung per STARTTLS auf TLS um, üblicherweise auf Port `587`. |
| `tls` | Die Verbindung nutzt von Anfang an TLS, üblicherweise auf Port `465`. |

Verwenden Sie `fixed_address` oder `direct_user` als Testziel und geben Sie ein gültiges Postfach wie
`oncall@example.com` ein.

#### Microsoft 365

MoleSignal meldet sich als in Microsoft Entra ID registrierte App an und sendet über ein Postfach. MoleSignal unterstützt nur die
globale Microsoft-Cloud. Die **Anmelde-URL** lautet fest
`https://login.microsoftonline.com`.

<Steps>
  <Step title="App registrieren">
    Registrieren Sie eine App in Microsoft Entra ID. Fügen Sie unter **API-Berechtigungen** für **Office 365 Exchange
    Online** die Anwendungsberechtigung `SMTP.SendAsApp` hinzu und erteilen Sie die Administratoreinwilligung. Erstellen Sie unter **Zertifikate &
    Geheimnisse** ein Client-Secret. Die Mandanten-ID und die Client-ID stehen auf der Seite **Übersicht**
    der App.
  </Step>
  <Step title="App in Exchange Online registrieren">
    Stellen Sie mit Exchange-Administratorrechten eine Verbindung zu Exchange Online PowerShell her (`Connect-ExchangeOnline`) und
    registrieren Sie den Dienstprinzipal der App. Verwenden Sie für `<object ID>` die Objekt-ID der App unter
    **Unternehmensanwendungen** in Microsoft Entra ID, nicht die Objekt-ID der App-Registrierung:

    ```powershell
    New-ServicePrincipal -AppId <app ID> -ObjectId <object ID>
    ```
  </Step>
  <Step title="Zugriff auf das Postfach gewähren">
    Gewähren Sie dem Dienstprinzipal Zugriff auf das Absenderpostfach:

    ```powershell
    Add-MailboxPermission -Identity <mailbox> -User <service principal> -AccessRights FullAccess
    ```
  </Step>
  <Step title="SMTP AUTH für das Postfach zulassen">
    Aktivieren Sie SMTP AUTH für das Postfach, zum Beispiel so:

    ```powershell
    Set-CASMailbox -Identity <mailbox> -SmtpClientAuthenticationDisabled $false
    ```
  </Step>
  <Step title="Konnektor konfigurieren">
    Geben Sie den Host `smtp.office365.com`, den Port `587` und den TLS-Modus `starttls` ein. Wählen Sie
    **Microsoft 365 (OAuth 2.0)** und geben Sie die Mandanten-ID, die Client-ID und das Client-Secret ein. Geben Sie das
    Postfach unter **Benutzername** und **Absenderadresse** ein.
  </Step>
</Steps>

#### Google Workspace

MoleSignal meldet sich mit einem Dienstkonto an, das per domainweiter
Delegierung im Namen eines Postfachs der Domain sendet.

<Steps>
  <Step title="Dienstkonto erstellen">
    Erstellen Sie in einem Google Cloud-Projekt ein Dienstkonto und einen JSON-Schlüssel dafür. Notieren Sie die
    numerische Client-ID des Dienstkontos von dessen Detailseite.
  </Step>
  <Step title="Gmail-Berechtigungsbereich delegieren">
    Öffnen Sie in der Google Admin-Konsole mit Super-Admin-Rechten **Sicherheit → Zugriffs- und Datenkontrolle →
    API-Steuerung → Domainweite Delegierung**. Fügen Sie die Client-ID hinzu und autorisieren Sie den Berechtigungsbereich
    `https://mail.google.com/`. Es kann bis zu 24 Stunden dauern, bis die Delegierung wirksam wird.
  </Step>
  <Step title="Konnektor konfigurieren">
    Geben Sie den Host `smtp.gmail.com` mit Port `587` und TLS-Modus `starttls` ein oder verwenden Sie Port
    `465` und `tls`. Wählen Sie **Google Workspace (OAuth 2.0)** und fügen Sie den Schlüssel unter **Dienstkontoschlüssel
    (JSON)** ein. Geben Sie das Absenderpostfach eines Kontos der Domain unter **Benutzername** und
    **Absenderadresse** ein.
  </Step>
</Steps>

Der Wert `token_uri` des Schlüssels muss auf den Token-Endpunkt von Google verweisen, wie bei einer [Google Chat-App](#google-chat-app).

### Slack-App

Erstellen Sie eine Slack-App mit einem Bot-Token, das `chat.postMessage` aufrufen darf. Fügen Sie den Bot zu jedem Channel hinzu,
der Benachrichtigungen erhalten soll. Geben Sie Folgendes ein:

- **Bot-Token** — das Bot-Token, das in der Regel mit `xoxb-` beginnt;
- **Token auf App-Ebene** — optional; ein Token, das mit `xapp-` beginnt und den Berechtigungsbereich `connections:write` hat. Damit kann Mole Agent in Slack über den Socket Mode antworten. Siehe [Mole Agent in IM](/de/im);
- **Plattform** — Slack oder GovSlack für US-Behörden. Bei GovSlack laufen die API und die Autorisierung
  für Statusseiten über `slack-gov.com`;
- **Client-ID** und **Client-Secret** — aus **Basic Information** der Slack-App. Diese Werte sind für Statusseiten nötig,
  die sich zu eigenen Slack-Channels hinzufügen lassen. Siehe
  [Statusseiten](/de/status-pages#slack);
- **Zeitlimit** — ein Wert zwischen 1 und 60 Sekunden.

Der Konnektor benötigt entweder das Bot-Token, die Client-ID samt Client-Secret oder alle drei Werte. Für Benachrichtigungen ist das
Bot-Token erforderlich. Der Konnektor speichert das Client-Secret wie das Bot-Token verschlüsselt und gibt es nie
zurück.

Verwenden Sie für `direct_user` eine Slack-Mitglieds-ID oder für `fixed_group` eine Channel-ID. Der Wert darf keine
Leerraumzeichen enthalten. Ein Anzeigename wie `#alerts` ist keine Channel-ID.

Nach der Aktivierung des Konnektors unter **Mole Agent → Einstellungen → IM** enthalten die darüber versendeten
Alarmbenachrichtigungen die Schaltflächen „Bestätigen“ und „Beheben“. Siehe [Alarmkarten](/de/im#alarmkarten).

### Slack-Webhook

Erstellen Sie einen eingehenden Webhook in Slack und kopieren Sie die URL in **Webhook-URL**. Ein Ziel vom Typ `fixed_group`
verwendet diese konfigurierte URL. Bei einem Ziel vom Typ `webhook` dient der Zielwert als alternative URL für die jeweilige
Zustellung.

MoleSignal sendet ein JSON-Objekt mit dem Feld `text`. Bei einem anderen Antwortstatus als 2xx gilt der Zustellversuch als
fehlgeschlagen.

### Lark-App

Erstellen Sie eine Mandanten-App, die ein Mandanten-Zugriffstoken abrufen und Nachrichten senden kann. Geben Sie die **App-ID**
und das **App-Secret** ein. Wählen Sie **Feishu** oder **Lark** als **Plattform**. Daraus ergibt sich die API-Basis-URL.

Der ausgewählte Typ der Empfänger-ID gilt für Ziele vom Typ `direct_user`:

| Zieltyp | Wert |
|---|---|
| `direct_user` | `open_id`, `user_id`, `union_id` oder E-Mail-Adresse, je nach **Typ der Empfänger-ID** |
| `fixed_address` | E-Mail-Adresse; MoleSignal sendet mit `receive_id_type=email` |
| `fixed_group` | Lark-Chat-ID; MoleSignal sendet mit `receive_id_type=chat_id` |

Empfängt die App Ereignisse über eine dauerhafte Verbindung, kann Mole Agent auch in Feishu antworten. Siehe
[Mole Agent in IM](/de/im#feishu).

Nach der Aktivierung des Konnektors unter **Mole Agent → Einstellungen → IM** enthalten die darüber versendeten
Alarmbenachrichtigungen die Schaltflächen „Bestätigen“ und „Beheben“. Siehe [Alarmkarten](/de/im#alarmkarten).

### Lark-Webhook

Kopieren Sie die URL des benutzerdefinierten Bots in **Webhook-URL**. Falls die Signaturprüfung des Bots aktiv ist, geben Sie auch
den **Signaturschlüssel** ein. MoleSignal erzeugt für jede Anfrage einen Zeitstempel und eine HMAC-SHA256-Signatur.
 
Ein Ziel vom Typ `fixed_group` verwendet die konfigurierte URL. Ein Ziel vom Typ `webhook` kann sie durch eine andere
absolute URL ersetzen. Das Anfrage- und Signaturformat finden Sie unter [Webhook-Konnektoren](/de/notification-channels/webhooks).

### DingTalk-App

Verwenden Sie den Roboter einer internen DingTalk-App. Geben Sie die **Client-ID** und das **Client-Secret** der App ein. Lassen Sie
**Robotercode** leer, sofern der Roboter keinen eigenen Code hat. Hat er einen eigenen Code, entspricht dieser der Client-ID. MoleSignal
tauscht die Anmeldedaten gegen ein Zugriffstoken aus und sendet Markdown-Nachrichten über den Roboter.

| Zieltyp | Wert |
|---|---|
| `direct_user` | DingTalk-Benutzer-ID (`userId`) eines Kontos im Sichtbarkeitsbereich der App |
| `fixed_group` | Die `openConversationId` einer Gruppe, der der Roboter angehört |

Empfängt der Roboter Nachrichten im Stream-Modus, kann Mole Agent auch in DingTalk antworten.
Siehe [Mole Agent in IM](/de/im#dingtalk). Mit einer **ID der Kartenvorlage** erscheinen Alarmbenachrichtigungen
als interaktive Karten mit den Schaltflächen „Bestätigen“ und „Beheben“. Informationen zum Erstellen der Vorlage finden Sie unter
[Interaktive DingTalk-Karten](/de/im#interaktive-dingtalk-karten).

### DingTalk-Webhook

Kopieren Sie die URL des benutzerdefinierten Roboters in **Webhook-URL**. Falls der Roboter Anfragen signiert, geben Sie auch den
**Signaturschlüssel** ein. MoleSignal fügt jeder Anfrage einen Zeitstempel und eine HMAC-SHA256-Signatur hinzu. Ein
Ziel vom Typ `fixed_group` verwendet die konfigurierte URL, ein Ziel vom Typ `webhook` ersetzt sie.

### WeCom-App

Verwenden Sie eine selbst erstellte WeCom-App. Geben Sie die **Unternehmens-ID**, den **Geheimschlüssel** der App und ihre **AgentId** ein.
MoleSignal tauscht diese Angaben gegen ein Zugriffstoken aus und sendet Markdown-Nachrichten. WeCom kürzt die Nachrichten auf
4.096 Bytes. Fügen Sie die IP-Adresse, von der MoleSignal die Verbindung aufbaut, zu den vertrauenswürdigen IP-Adressen der App hinzu.

| Zieltyp | Wert |
|---|---|
| `direct_user` | Die Benutzer-ID eines Mitglieds im Sichtbarkeitsbereich der App |
| `fixed_group` | Die Chat-ID einer Gruppe, die die App erstellt hat |

Hinterlegen Sie einen **Callback-Token** und einen **EncodingAESKey** und tragen Sie die Callback-URL des Konnektors unter
**Nachrichten empfangen** in der App ein. Mitglieder erhalten Alarmbenachrichtigungen dann als Karten mit den Schaltflächen „Bestätigen“ und
„Beheben“. Siehe [Schaltflächen einer WeCom-App](/de/im#schaltflächen-einer-wecom-app).

### WeCom-Webhook

Kopieren Sie die URL eines Gruppenroboters in **Webhook-URL**. Ein Ziel vom Typ `fixed_group` verwendet diese URL, ein Ziel vom Typ `webhook`
ersetzt sie.

### WeCom Smart Bot

Verwenden Sie einen WeCom Smart Bot im API-Modus, der Nachrichten über eine dauerhafte Verbindung empfängt. Geben Sie die
**Bot-ID** und das für den Bot erstellte **Secret für dauerhafte Verbindung** ein. Die **Adresse für dauerhafte Verbindung** lautet fest
`wss://openws.work.weixin.qq.com`. Sobald der Konnektor in Mole Agent unter **IM** aktiv ist,
antwortet Mole Agent in WeCom (siehe [Mole Agent in IM](/de/im#wecom)). Der Bot stellt auch Benachrichtigungen zu.
Alle Nachrichten und Antworten laufen über die dauerhafte Verbindung.

| Zieltyp | Wert |
|---|---|

### Rufnummern für Anrufe und SMS

Konnektoren für Anrufe und SMS verwenden jeweils eine Rufnummer: die von einem Mitglied hinterlegte Rufnummer (`direct_user`) oder eine
feste Rufnummer in einer Ausweichroute (`fixed_address`). Geben Sie die Nummer mit `+` und der Landesvorwahl ein, etwa
`+14155550100`. MoleSignal entfernt Leerzeichen und Bindestriche. Die Konnektoren für Alibaba Cloud, Tencent Cloud, Huawei Cloud und generische HTTP-SMS
akzeptieren auch 11-stellige Mobilfunknummern aus dem chinesischen Festland.

Ein Anruf liest zuerst den Titel der Benachrichtigung vor, dann den Text, insgesamt bis zu 400 Zeichen. Eine SMS enthält den Titel in
der ersten und den Text in der zweiten Zeile, insgesamt bis zu 320 Zeichen. Wählt eine Benachrichtigungsrichtlinie eine Vorlage für
den Anruf- oder SMS-Kanal, enthält der Anruf oder die SMS nur den Vorlageninhalt ohne Titel. Alibaba
Cloud, Tencent Cloud und Huawei Cloud versenden nur genehmigte Vorlagen. Hinterlegen Sie deren Codes und Variablen
in den Benachrichtigungsvorlagen, wie unter [Anbietervorlagen in Benachrichtigungs-
vorlagen](#anbietervorlagen-in-benachrichtigungsvorlagen) beschrieben.

Anbieter begrenzen die Anzahl der Anrufe und SMS pro Rufnummer. Lehnt der Anbieter einen Anruf oder eine SMS wegen dieses Limits, einer
falschen Nummer oder einer nicht genehmigten Vorlage ab, schlägt die Zustellung fehl. Die Richtlinie fährt mit der
nächsten Benachrichtigungsmethode des Mitglieds und den Ausweichrouten fort. Eine Rückmeldung zur Annahme oder zum Anhören eines Anrufs
gibt es nicht. Eine erfolgreiche Zustellung bedeutet, dass der Anbieter den Anruf oder die SMS angenommen hat.

Ein Konnektor ruft dieselbe Nummer höchstens einmal pro Minute an. Innerhalb dieser Minute eingehende Benachrichtigungen
warten in der Warteschlange für diese Nummer. Im Zustellungsprotokoll steht **Zur Zusammenführung vorgemerkt**. Nach Ablauf der Minute
liest ein Anruf die Titel nacheinander vor (bei einer Anrufvorlage deren Inhalt). Inzwischen bestätigte
Benachrichtigungen entfallen. Alibaba Cloud, Tencent Cloud und Huawei Cloud
lesen die Vorlage der ersten Benachrichtigung vor und setzen für jede Variable nacheinander die entsprechenden Werte aller Benachrichtigungen
ein. Alibaba Cloud erlaubt ohnehin nur einen
Anruf pro Minute und Rufnummer. Durch das Zusammenführen gehen auch bei vielen gleichzeitigen Alarmen Anrufe durch. Legt eine Benachrichtigungsrichtlinie ein
längeres Zeitfenster zum [Zusammenführen von Benachrichtigungen](#benachrichtigungen-bündeln) fest, gilt das Zeitfenster der Richtlinie.

### Alibaba Cloud: Anrufe

Alibaba Cloud Voice Service sendet Sprachbenachrichtigungen nur an Rufnummern auf dem chinesischen Festland. Schließen Sie
die Unternehmensverifizierung in der Voice Service-Konsole ab. Beantragen Sie eine **Text-to-Speech**-Vorlage für
Sprachbenachrichtigungen, etwa `Hello, ${content}. Please handle it now.`, und erstellen Sie einen AccessKey
für ein RAM-Konto, das ausschließlich Voice Service aufrufen darf. Geben Sie dann Folgendes ein:

- **AccessKey-ID** und **AccessKey-Secret**;
- **Region** — eine der von Alibaba Cloud aufgeführten Regionen. Daraus ergibt sich die API-Basis-URL;
- **Angezeigte Rufnummer** — im gemeinsamen Modus leer lassen. Geben Sie im dedizierten Modus die gekaufte Rufnummer ein. Sie
  erscheint bei jedem Anruf, damit der Bereitschaftsdienst sie als Kontakt speichern kann. Die Vorlage muss denselben
  Modus verwenden;
- **Anzahl der Wiedergaben** — 1 bis 3.

Hinterlegen Sie den Vorlagencode (beginnend mit `TTS_`) und seine Variablen in einer Benachrichtigungsvorlage für Anrufe.
Wählen Sie diese Vorlage in der Benachrichtigungsrichtlinie für den Anrufkanal aus. Siehe [Anbietervorlagen in Benachrichtigungs-
vorlagen](#anbietervorlagen-in-benachrichtigungsvorlagen). Alibaba Cloud ruft dieselbe Rufnummer höchstens
einmal pro Minute, 5-mal pro Stunde und 20-mal pro Tag an. Weitere Anrufe lehnt Alibaba Cloud ab. Verwenden Sie keine Links oder
IP-Adressen in Variablen.

### Tencent Cloud: Anrufe

Erstellen Sie in der Konsole für Sprachnachrichten eine Anwendung. Die Konsole stellt die `VoiceSdkAppid` bereit. Beantragen Sie eine
Vorlage für Sprachbenachrichtigungen und erstellen Sie dann einen API-Schlüssel für ein Unterkonto. Geben Sie **SecretId**, **SecretKey**,
**Region** (mit diesem Schlüssel abrufbar; sie bestimmt die API-Basis-URL), **App-ID (SdkAppId)** und

Variablen nach ihrer Position: `1`, `2`, `3`. Siehe [Anbietervorlagen in Benachrichtigungs-
vorlagen](#anbietervorlagen-in-benachrichtigungsvorlagen).

Anrufe laufen über ein vorausbezahltes Paket. Ist das Guthaben aufgebraucht, schlagen Anrufe fehl. Im Zustellungsprotokoll steht dann
`InsufficientBalanceInVoicePackage`. Die Benachrichtigungsrichtlinie wechselt zur nächsten Methode des Mitglieds. Verwenden Sie Anrufe daher
nicht als einzige Methode. Ein generierter Anruf umfasst höchstens 350 Zeichen. Die Dokumentation
nennt kein Limit pro Variable. Zu lange Werte lehnt der Anbieter ab (`ContentLengthLimit`). MoleSignal
kürzt Werte standardmäßig auf 20 Zeichen. Ein höheres Limit lässt sich in der Benachrichtigungsvorlage festlegen.

### Tencent Cloud: SMS

Erstellen Sie in der SMS-Konsole eine Anwendung, um die `SmsSdkAppId` zu erhalten. Beantragen Sie eine Signatur
und Vorlagen. Geben Sie dann **SecretId**, **SecretKey**, **Region**, **App-ID (SdkAppId)** und
**Signatur** ein. Verwenden Sie den Signaturtext statt der ID. Für SMS auf dem chinesischen Festland ist die Signatur erforderlich. Hinterlegen Sie die Vorlagen-ID

<Warning>
  Für Konten, die nach dem 25. Januar 2024 eröffnet wurden, und für inaktive Konten gelten standardmäßig höchstens **6 Zeichen** pro

  anhebt, tragen Sie den neuen Wert unter **Zeichen pro Variable** in der Benachrichtigungsvorlage ein.
  Variablen dürfen keine Links enthalten.
</Warning>

Ein insgesamt erfolgreicher API-Aufruf bedeutet nicht, dass der Anbieter die SMS an diese Rufnummer gesendet hat. Entscheidend ist das Ergebnis für die

### AWS: Anrufe und SMS

AWS-Anrufe (`aws_voice`) nutzen `SendVoiceMessage` von AWS End User Messaging. Amazon Polly liest die
Benachrichtigung vor. AWS-SMS (`aws_sms`) versendet transaktionale SMS mit `SendTextMessage`. Geben Sie
Folgendes ein:

- **Region** — eine für das Konto aktivierte Region. Nach Eingabe der Zugangsdaten fragt MoleSignal die Liste mit diesen Daten
  bei AWS ab (EC2 `DescribeRegions`). Der Versand schlägt in Regionen ohne End User
  Messaging fehl;
- **Authentifizierung** — dieselben Methoden wie bei AWS-Datenkonnektoren: Zugriffsschlüssel, temporärer Schlüssel, Knoten-
  identität, angenommene Rolle oder Webidentität. Damit MoleSignal eine Rolle annehmen kann, muss ihre Vertrauensrichtlinie die angezeigte externe
  ID verlangen;
- **Absenderidentität** — eine Rufnummer, eine Rufnummern-ID, eine Pool-ID oder ein entsprechender ARN. Für Anrufe ist eine
  Absenderidentität mit einer für Sprachanrufe geeigneten Nummer erforderlich. Lassen Sie das Feld für SMS leer, damit AWS eine zum
  Ziel passende Nummer auswählt, oder geben Sie eine Absender-ID an;
- **Polly-Stimme** — optional und nur für Anrufe: `MATTHEW` ohne Angabe, `ZHIYU` für Mandarin;
- **API-Basis-URL** — ergibt sich aus der Region, zum Beispiel `https://sms-voice.us-east-1.amazonaws.com`.

Die Identität benötigt `sms-voice:SendVoiceMessage` oder `sms-voice:SendTextMessage` sowie
`ec2:DescribeRegions`, um die Regionen aufzulisten. Ein AWS-Konto, das sich noch
in der Sandbox befindet, erreicht nur verifizierte Rufnummern.

### Generische HTTP-SMS

Der Konnektor übergibt jede SMS per konfigurierbarer HTTP-Anfrage an ein eigenes SMS-Gateway oder an einen Anbieter ohne eigenen
Konnektor. Geben Sie Folgendes ein:

- **Gateway-URL** — Ziel der Anfrage. Die URL kann Platzhalter enthalten, zum Beispiel
  `https://sms.example.com/send?to={{phone}}&msg={{content}}` für ein Gateway mit GET;
- **HTTP-Methode** — POST, PUT oder GET. GET hat keinen Anfragetext;
- **Nachrichtenformat** und **Anfragetext** — JSON oder Formulardaten (`x-www-form-urlencoded`);
  standardmäßig `{"phone": "{{phone}}", "content": "{{content}}"}`;
- **Header (JSON)** — zum Beispiel `{"Authorization": "Bearer {{secret}}"}`;
- **Geheimschlüssel** — ein Token oder Passwort für das Gateway. MoleSignal speichert den Wert verschlüsselt. Verwenden Sie dafür `{{secret}}` in
  der URL, in den Headern und im Anfragetext;
- **Rufnummernformat** — `+8613800138000` (E.164), `8613800138000` (ohne +) oder `13800138000` (Rufnummern
  aus dem chinesischen Festland ohne Landesvorwahl);
- **Feld für Erfolgsstatus** und **Wert für Erfolgsstatus** — optional. Eine 2xx-Antwort gilt als erfolgreicher Versand. Wenn ein
  Feld für den Erfolgsstatus angegeben ist, etwa `code` oder `result.status`, muss dieses Feld in der JSON-Antwort zusätzlich dem
  Wert für den Erfolgsstatus entsprechen.

| Platzhalter | Wert |
|---|---|
| `{{phone}}` | Die Zielrufnummer im gewählten Rufnummernformat |
| `{{content}}` | Der SMS-Inhalt: Titelzeile und Textzeile, insgesamt bis zu 320 Zeichen |
| `{{title}}` | Der Titel der Benachrichtigung |
| `{{text}}` | Der Text der Benachrichtigung |
| `{{secret}}` | Der Geheimschlüssel |

MoleSignal maskiert die Werte passend zum Kontext: als JSON-Zeichenfolgen im JSON-Anfragetext und URL-kodiert in Formulardaten oder in der URL.
Rufnummer und Text müssen in der Anfrage vorkommen. Andernfalls lässt sich der Konnektor nicht speichern.

### Generischer Webhook

Geben Sie eine Standard-URL ein, wählen Sie `POST`, `PUT` oder `PATCH` und wählen Sie den **Anfragetext**:

- **MoleSignal-Ereignis**, die Standardeinstellung: maschinenlesbares JSON mit Version, Ereignis, Alarm,
  Regel, Eskalation, Ziel und gerenderter Meldung;
- **Inhalt der Benachrichtigungsvorlage**: Der Konnektor sendet den Inhalt der Vorlage, die die Benachrichtigungsrichtlinie für den Webhook-Kanal auswählt,
  unverändert. Eine JSON-Vorlage sendet der Konnektor als JSON. Siehe [Bedingungen](#bedingungen) und die Formate unter
  [Vorlagen und Richtlinien erstellen](#vorlagen-und-richtlinien-erstellen).

Jede Anfrage enthält `X-MoleSignal-Event` (den Benachrichtigungstyp) und `X-MoleSignal-Delivery` (die
Zustellungs-ID, anhand derer der Empfänger Duplikate verwerfen kann). Mit einem **Signaturschlüssel** von mindestens 16 Zeichen
enthält die Anfrage auch `X-MoleSignal-Timestamp` und `X-MoleSignal-Sign`. Damit kann der Empfänger prüfen, ob die Anfrage
von MoleSignal stammt. Die Felder des Anfragetexts, die Signatur und Beispiele zur Signaturprüfung finden Sie unter
[Webhook-Benachrichtigungskonnektoren](/de/notification-channels/webhooks#generischer-webhook).

Für `direct_user`, `fixed_address` und `fixed_group` sendet MoleSignal die Anfrage an die konfigurierte Standard-
URL und fügt das Ziel als Routing-Daten hinzu. Für `webhook` ersetzt der Zielwert die Standard-
URL. Eine 2xx-Antwort gilt als Erfolg. Enthält die Antwort `X-Request-ID`, protokolliert MoleSignal den
Header-Wert als Meldungs-ID des Anbieters. MoleSignal führt Webhooks nie [zusammen](#benachrichtigungen-bündeln): Jede
Benachrichtigung ist eine eigene Anfrage.

<Warning>
  Webhook-URLs, Autorisierungsheader, Token, Passwörter und Signaturschlüssel sind Zugangsdaten. Tragen Sie
  keine Zugangsdaten in Testziele, Vorlagen oder Ereignisattribute ein.
</Warning>

### Amazon SNS

Der Konnektor veröffentlicht jede Benachrichtigung in einem Amazon SNS-Thema. Dessen Abonnements leiten sie an Lambda, SQS,
HTTPS-Endpunkte, E-Mail-Adressen und weitere Ziele weiter. Geben Sie Folgendes ein:

- **Authentifizierung** und **Region** — wie bei [AWS: Anrufe und SMS](#aws-anrufe-und-sms). Verwenden Sie die
  Region des Themas aus dessen ARN;
- **Themen-ARN** — zum Beispiel `arn:aws:sns:us-east-1:123456789012:alerts`;
- **Meldung** — **MoleSignal-Ereignis**, die Standardeinstellung, veröffentlicht dasselbe JSON wie ein [generischer
  Webhook](#generischer-webhook). **Inhalt der Benachrichtigungsvorlage** veröffentlicht den Inhalt der Vorlage, die die
  Benachrichtigungsrichtlinie für den Webhook-Kanal auswählt.

Als Betreff dient der einzeilige Benachrichtigungstitel mit weniger als 100 Zeichen. Jede Meldung enthält
das Meldungsattribut `event_type`, zum Beispiel `alert.triggered`, und bei Alarmen auch `severity`. Filterrichtlinien von
Abonnements können diese Attribute auswerten. In einem FIFO-Thema (Name mit der Endung `.fifo`) gehören alle Meldungen eines Alarms
zur selben Meldungsgruppe und behalten ihre Reihenfolge. Die Zustellungs-ID dient als Deduplizierungs-ID. So verwirft SNS
doppelt veröffentlichte Zustellungen.

Die Identität benötigt `sns:Publish` für das Thema, `kms:GenerateDataKey` und `kms:Decrypt` für den Schlüssel eines
verschlüsselten Themas sowie `ec2:DescribeRegions` zum Auflisten der Regionen. Jeder Zieltyp funktioniert. Meldungen gehen immer
an das Thema.

### PagerDuty

Der Konnektor sendet Ereignisse über Events API v2 an einen PagerDuty-Dienst. Öffnen Sie in PagerDuty die Registerkarte **Integrationen** des Dienstes,
fügen Sie eine **Events API V2**-Integration hinzu und kopieren Sie den 32 Zeichen langen
Routing-Schlüssel in **Integrationsschlüssel**. Wählen Sie die **Dienstregion**: **US** oder **EU** für ein Konto,
dessen Adresse auf `.eu.pagerduty.com` endet.

| MoleSignal-Ereignis | PagerDuty-Ereignis |
|---|---|
| Alarm ausgelöst, Alarm eskaliert | `trigger` |
| Alarm bestätigt | `acknowledge` |
| Alarm behoben | `resolve` |
| Jedes andere Ereignis | `trigger`, als eigener PagerDuty-Alarm |

Jedem MoleSignal-Alarm entspricht während seiner gesamten Laufzeit ein PagerDuty-Alarm mit dem Deduplizierungsschlüssel
`molesignal-<alert ID>`. Eine Eskalation löst denselben Alarm erneut aus, statt einen neuen anzulegen. Ein Auslöseereignis
enthält den Titel als Zusammenfassung (bis zu 1.024 Zeichen), den Dienst des Alarms als Quelle
(`MoleSignal`, falls kein Dienst angegeben ist), den Schweregrad (`critical`, `error`, `warning` oder `info`), den Zeitpunkt,
das Ereignis des generischen Webhooks als benutzerdefinierte Details sowie einen Link zum Alarm, falls `http.external_url`
gesetzt ist.

PagerDuty erhält nur die Ereignisse, die Benachrichtigungsrichtlinien an diesen Konnektor senden. Damit PagerDuty Alarme
zusammen mit MoleSignal bestätigt und behebt, leiten Sie auch die Ereignisse **Alarm bestätigt** und **Alarm behoben**
an den Konnektor weiter. Jeder Zieltyp funktioniert. Ereignisse gehen immer an die Integration des angegebenen Schlüssels.

## Benachrichtigungsmethoden für Mitglieder verknüpfen

Öffnen Sie mit Adminrechten **Einstellungen → Benachrichtigungen → Benutzerrouting**, wählen Sie ein Mitglied aus und klicken Sie auf
**Benachrichtigungsmethode verknüpfen**. Wählen Sie pro Identität einen Konnektor und eine externe Identität aus, etwa eine
E-Mail-Adresse, eine Slack- oder Lark-Benutzer-ID oder die Rufnummer, an die der Konnektor Anrufe oder SMS sendet.

Nach dem Verknüpfen einer Identität:

1. Senden Sie eine Testnachricht, um zu prüfen, ob der Anbieter sie annimmt.
2. Verifizieren Sie die Identität, sobald die Organisation die Inhaberschaft bestätigt hat.
3. Aktivieren Sie die Identität in der Einstellung **Alarmereignisse**, **Rufbereitschaftsereignisse** oder **Berichte**.
4. Legen Sie bei mehreren Identitäten die Reihenfolge fest: von der primären Identität bis zur letzten Ausweichoption.
5. Richten Sie bei Bedarf Ruhezeiten ein und lassen Sie kritische Alarme auch während der Ruhezeiten zu.

### Ohne Bestätigung mit dem nächsten Schritt fortfahren

Legen Sie in der Zustellreihenfolge für Alarmereignisse ab dem zweiten Schritt eine Wartezeit in Minuten fest:

| Einstellung | Wirkung |
|---|---|
| Erster Schritt | MoleSignal sendet die Benachrichtigung, sobald der Alarm ausgelöst oder an das Mitglied eskaliert wird. |
| N Minuten warten | MoleSignal sendet erneut eine Benachrichtigung, wenn N Minuten nach der ersten Benachrichtigung des Mitglieds noch keine Bestätigung vorliegt. |
| Gleiche Minutenzahl wie im vorherigen Schritt | MoleSignal führt diesen Schritt nur aus, wenn der Versand im vorherigen Schritt fehlschlägt. |

Beispiel: sofort per Lark, nach 3 Minuten per SMS und nach 5 Minuten per Anruf. Sobald der Alarm
bestätigt oder behoben ist, überspringt MoleSignal alle weiteren Schritte, auch für die durch Eskalation
benachrichtigten Mitglieder. Schlägt der Versand fehl, führt MoleSignal sofort den nächsten Schritt aus. Die Wartezeit beträgt höchstens einen Tag
und gilt nur für Alarmereignisse. Bei Rufbereitschaftsereignissen und Berichten greift die nächste Methode nur bei einem Versandfehler.

Mitglieder können ihre eigenen Identitäten und Einstellungen unter **Kontoeinstellungen → Benachrichtigungen** verwalten.
Um die Einstellungen eines anderen Mitglieds einzusehen, ist `org.members.read` erforderlich. Um dessen
Identität zu ändern oder zu bestätigen, ist `org.members.update` erforderlich.

<Note>
  Entfernen Sie eine Identität vor dem Löschen aus allen Zustelleinstellungen.
</Note>

### Dringende Benachrichtigungen in Feishu und DingTalk

Verwendet ein Schritt einen Lark- oder DingTalk-App-Konnektor, kann die App nach dem Versand der Nachricht
zusätzlich eine dringende Benachrichtigung auslösen. Wählen Sie die gewünschte Option in der Auswahlliste neben dem Schritt:

| Plattform | Optionen | Voraussetzungen |
|---|---|---|
| Feishu (Lark-App-Konnektor) | **Buzz in der App**, **Buzz per SMS**, **Buzz per Anruf** | Je nach Option benötigt die App die Berechtigung `im:message.urgent`, `im:message.urgent:sms` oder `im:message.urgent:phone`. Buzz per SMS und per Anruf belasten das Kontingent des Mandanten für dringende Benachrichtigungen. Lark, die internationale Variante, bietet nur Buzz in der App. Als **Typ der Empfänger-ID** muss im Konnektor `open_id`, `user_id` oder `union_id` eingestellt sein, nicht E-Mail. |
| DingTalk (DingTalk-App-Konnektor) | **DING in der App**, **DING per SMS**, **DING per Anruf** | Erforderlich sind die Professional- oder Exclusive-Edition von DingTalk und die App-Berechtigung `Premium.Ding.Write`. DING per SMS und per Anruf erfordern ein kostenpflichtiges Kontingent. Ein DING enthält den Titel der Benachrichtigung. Bei einem DING per Anruf liest DingTalk den Titel vor. |

Bei Alarmereignissen kann dieselbe Methode mit unterschiedlichen Dringlichkeitsoptionen zweimal in der Reihenfolge stehen. Beispiel: sofort eine Feishu-
Nachricht und nach 5 Minuten dieselbe Feishu-Methode mit **Buzz per Anruf**, falls noch keine Bestätigung
für den Alarm vorliegt. In den übrigen Reihenfolgen kann jede Methode nur einmal vorkommen.

Schlägt die dringende Benachrichtigung fehl, etwa wegen eines ausgeschöpften Kontingents oder einer fehlenden Berechtigung, gilt der Schritt auch dann als fehlgeschlagen,
wenn die Nachricht angekommen ist. MoleSignal führt sofort den nächsten Schritt aus. WeCom bietet keine dringenden Benachrichtigungen.

## Auf Textnachrichten und Anrufe reagieren

Aktivieren Sie **Antworten verarbeiten** in einem SMS- oder WhatsApp-Konnektor bzw. **Tasteneingaben verarbeiten** in einem
Anrufkonnektor. So können Empfänger einen Alarm bearbeiten, ohne MoleSignal zu öffnen:

- **Textnachrichten**: Bei Auslösung oder Eskalation eines Alarms endet die Nachricht mit „Antworten Sie mit 31 zum Bestätigen, mit 32 zum
  Beheben.“ Als Antwort genügt einer der beiden Codes. Die Zehnerstelle wechselt für jede Rufnummer zyklisch von 0 bis 9.
  Die Einerstelle ist 1 zum Bestätigen oder 2 zum Beheben. Eine Antwort nur mit `1` oder `2`
  bezieht sich auf die letzte Nachricht an diese Rufnummer. Ein Code gilt für alle Alarme in einer Sammelnachricht. Die Codes sind
  einen Tag lang gültig.
- **Aufrufe**: Drücken Sie nach der Ansage des Alarms die 1 zum Bestätigen oder die 2 zum Beheben. Eine Ansage bestätigt die
  ausgeführte Aktion.

MoleSignal führt die Aktion im Namen des Mitglieds aus, an das die Nachricht ging. Dafür braucht das Mitglied `alerts.incidents.acknowledge` und ein
aktives Konto in einer aktiven Organisation. Die Zeitleiste zeigt die Aktion als SMS-Antwort oder Tasteneingabe während eines Anrufs an.
Nur Nachrichten an Mitglieder enthalten Codes, nicht Nachrichten an eine feste Rufnummer einer Ausweichroute.

Der Anbieter sendet Antworten und Tasteneingaben an eine Callback-URL von MoleSignal. Konfigurieren Sie daher die externe URL
`http.external_url` und stellen Sie sicher, dass die Pfade unter `/api/v1/public/notify/` über das
Internet erreichbar sind. Siehe [Öffentlicher Zugriff](/de/public-access). Sobald Sie die Option aktivieren und den Konnektor speichern,
zeigt der Konnektor die Callback-URL zum Kopieren an:

| Konnektor | Konfiguration | Callback-Prüfung |
|---|---|---|
| Twilio SMS | Wählen Sie in den Messaging-Einstellungen der Rufnummer unter **A message comes in** die Option Webhook und die Methode HTTP POST aus. Geben Sie die Callback-URL ein. | Der Konnektor prüft die Twilio-Signatur `X-Twilio-Signature` mit seinem Auth Token. |
| Twilio WhatsApp | Hinterlegen Sie in Twilio die Callback-URL beim Webhook für eingehende Nachrichten des WhatsApp-Absenders oder des zugehörigen Messaging Service. Wählen Sie HTTP POST aus. WhatsApp sendet nur genehmigte Vorlagen. Hinterlegen Sie die Codes daher in der Vorlage: Belegen Sie die Vorlagenvariablen mit `{{reply.ack}}` und `{{reply.resolve}}`. Wenn die Vorlage einen Code als ID einer Schnellantwort-Schaltfläche einsetzt, wirkt ein Klick wie eine Antwort mit diesem Code. | Twilio-Signatur. |
| Twilio-Anrufe | Keine Konfiguration erforderlich. Jeder Anruf enthält eine URL für Tasteneingaben. | Twilio-Signatur. |
| AWS SMS | Aktivieren Sie Zwei-Wege-SMS für die Rufnummer und wählen Sie ein SNS-Thema für die Antworten aus. Fügen Sie dem Thema ein HTTPS-Abonnement mit der Callback-URL als Endpunkt hinzu. Das Abonnement wird automatisch bestätigt. Tragen Sie das Thema unter **SNS-Themen-ARN für Antworten** ein, um nur Antworten aus diesem Thema anzunehmen. | Signatur der SNS-Nachricht. Der Konnektor ruft Zertifikate ausschließlich von `sns.<region>.amazonaws.com` ab. |
| Alibaba Cloud SMS | Konfigurieren Sie den SMS Service so, dass er eingehende Nachrichten per HTTP an die Callback-URL sendet. Alibaba Cloud sendet nur genehmigte Vorlagen. Hinterlegen Sie die Codes daher in der Vorlage: Belegen Sie die Vorlagenparameter mit den Variablen `{{reply.ack}}` und `{{reply.resolve}}`. Siehe [Vorlagenvariablen](#vorlagenvariablen). | Callback-Token in der URL. |
| Alibaba Cloud-Anrufe | Der Konnektor nutzt interaktive Sprachanrufe (IvrCall) und benötigt als **Angezeigte Rufnummer** eine echte, für IvrCall erworbene Rufnummer. Konfigurieren Sie den Voice Service so, dass er Rückmeldungen per HTTP an die Callback-URL sendet. Nach der Ansage wartet der Dienst 10 Sekunden auf eine Tasteneingabe. | Callback-Token in der URL. |
| Tencent Cloud SMS | Hinterlegen Sie in den Callback-Einstellungen der SMS-Konsole die Callback-URL für Antworten. Hinterlegen Sie die Codes in der Vorlage: Belegen Sie die Vorlagenvariablen mit `{{reply.ack}}` und `{{reply.resolve}}`. | Callback-Token in der URL. |
| Tencent Cloud-Anrufe | Hinterlegen Sie in den Einstellungen für Ereignis-Callbacks der Sprachnachrichten-Konsole die Callback-URL für Tasteneingaben. Schreiben Sie „Drücken Sie die 1 zum Bestätigen und die 2 zum Beheben“ in die Vorlage. Der Callback für die Tasteneingabe enthält nur die angerufene Rufnummer. Die Eingabe gilt daher für den letzten Anruf an diese Rufnummer. | Callback-Token in der URL. |
| Huawei Cloud SMS | Geben Sie beim Erstellen der SMS-Anwendung die Callback-URL als Adresse für eingehende SMS an. Hinterlegen Sie die Codes wie oben beschrieben in der Vorlage. | Callback-Token am Ende der URL. |
| Huawei Cloud-Anrufe | Hinterlegen Sie in der Anwendungsverwaltung die Callback-URL als Adresse für Anrufstatusmeldungen. Nach der Ansage erfasst der Dienst eine Tasteneingabe. Schreiben Sie „Drücken Sie die 1 zum Bestätigen und die 2 zum Beheben“ in die Vorlage. | Callback-Token am Ende der URL. |
| Generische HTTP-SMS | Lassen Sie das Gateway eingehende Textnachrichten per POST als JSON-Objekt `{"phone": "…", "text": "…"}` oder als Array solcher Objekte an die Callback-URL senden. | Callback-Token in der URL. |

MoleSignal leitet das Callback-Token für jeden Konnektor aus dem Hauptschlüssel des Servers ab und speichert es nicht. Behandeln Sie die URL
wie Zugangsdaten. AWS-Sprachnachrichten unterstützen keine Tasteneingaben. Daher bietet `aws_voice` diese Option nicht.

## Einmal-Links für Aktionen

Wenn ein Connector eine Alarmbenachrichtigung ohne Schaltflächen an eine einzelne Person sendet, enthält sie am Ende
Einmal-Links: **Bestätigen** und **Beheben**, solange die Bestätigung aussteht, und
nur **Beheben**, sobald der Alarm bestätigt ist. Das gilt für E-Mail- und Instant-Messaging-Connectoren, die
Alarme ohne Schaltflächen senden, etwa einen Webex-Bot oder eine Lark-App, die unter **IM** nicht aktiviert ist. In einer
Karte stehen die Links bei den Link-Schaltflächen, sonst am Ende der Nachricht. Der Linktext erscheint in der
Sprache der Benutzeroberfläche des Empfängerkontos.

- Ein Link öffnet die MoleSignal-Seite `https://<external address>/notify/actions/<token>` ohne
  Anmeldung. Die Seite zeigt Schweregrad, Status, Titel und Startzeit des Alarms sowie eine Schaltfläche.
  Das Öffnen der Seite löst keine Aktion aus. E-Mail-Scanner können den Link daher gefahrlos öffnen. Erst ein Klick auf die Schaltfläche
  löst die Aktion aus.
- Ein Link lässt sich 24 Stunden lang einmal verwenden. Der Klick führt die Aktion im Namen des Empfängerkontos aus.
  Dieses Konto braucht zu diesem Zeitpunkt `alerts.incidents.acknowledge` für den Alarm und muss in einer
  aktiven Organisation aktiv sein.
- Wenn der Link bereits verwendet wurde, abgelaufen ist oder nach der Bearbeitung oder Rückkehr des Alarms in den Normalzustand nicht mehr gilt,
  oder wenn das Empfängerkonto keine Berechtigung mehr für die Aktion hat, zeigt die Seite einen Hinweis an. Der Alarm bleibt unverändert.
- Die Links setzen `http.external_url` voraus. Ohne diese Einstellung enthalten Benachrichtigungen keine Links. Wenn MoleSignal nur im
  internen Netzwerk läuft, müssen die Seite und ihre API von dort erreichbar sein, wo die E-Mails abgerufen werden. Siehe
  [Öffentlicher Zugriff](/de/public-access).

Benachrichtigungen an eine Gruppe oder an eine feste Adresse einer Fallback-Route enthalten keine Links. Das gilt auch für
SMS, Anrufe und Integrationen. Bei SMS und Anrufen sind stattdessen [Antworten](#auf-textnachrichten-und-anrufe-reagieren) möglich.

## Vorlagen und Richtlinien erstellen

Öffnen Sie **Einstellungen → Benachrichtigungen → Vorlagen**, um einen wiederverwendbaren Nachrichtentext zu erstellen. Wählen Sie eine Benachrichtigungskategorie
und einen Kanal aus. Fügen Sie [Variablen](#vorlagenvariablen) ein oder beginnen Sie mit einer
[vorgefertigten Vorlage](#vorgefertigte-vorlagen). Prüfen Sie anhand der Vorschau-Ereignisattribute die daraus erzeugte
Nachricht. Die Bereiche für Variablen, vorgefertigte Vorlagen und Vorschau-Ereignisattribute rechts im Editor
sind zunächst eingeklappt. Klicken Sie auf einen Titel, um den Bereich zu öffnen. Die Vorlagenliste ist nach Kanal sortiert.

| Kanal | Verwendung | Inhalt |
|---|---|---|
| **Allgemein** | Alle Kanäle, für die in der Benachrichtigungsrichtlinie keine Vorlage ausgewählt ist. | Text, Markdown oder HTML. |
| **Instant Messaging**, **E-Mail**, **Webhook** | Nur der jeweilige Kanal. | Text, Markdown oder HTML. Vorlagen für Instant Messaging lassen sich auch [als Karte senden](#karten-in-vorlagen-für-instant-messaging). Webhook-Vorlagen unterstützen auch JSON: MoleSignal maskiert die Werte als JSON-Zeichenfolgen. Der ausgefüllte Inhalt muss gültiges JSON sein und dient als **Inhalt der Benachrichtigungsvorlage** eines [generischen Webhooks](#generischer-webhook). |
| **SMS**, **Telefon** | Nur der jeweilige Kanal. | Nur Klartext ohne Benachrichtigungstitel. Eine SMS enthält höchstens 320 Zeichen, ein Anruf liest höchstens 400 Zeichen vor. Der Editor zählt die Zeichen. |

Öffnen Sie anschließend **Richtlinien** und erstellen Sie die Routingregel:

1. Wählen Sie einen Ereignistyp und eine Kategorie aus.
2. Fügen Sie JSON-Abgleichsregeln hinzu und legen Sie die Priorität der Richtlinie fest. Unter **Zeit** beschränken **Nur innerhalb dieser Zeiten** und
   **Nur außerhalb dieser Zeiten** die Richtlinie auf wöchentliche Zeitfenster. Maßgeblich ist der Zeitpunkt des Ereignisses.
   Ein [Feiertagskalender](/de/alerting/on-call#feiertagskalender) kann Feiertage bei der Auswertung berücksichtigen.
   Außerhalb der zulässigen Zeiten sendet die Richtlinie nichts. Die übrigen Richtlinien gelten weiterhin.
3. Wählen Sie aus, wie MoleSignal die Empfänger ermittelt, und konfigurieren Sie die gewählte Methode.
4. Berücksichtigen Sie Benutzerpräferenzen, erzwingen Sie einen bestimmten Konnektor oder senden Sie über mehrere Konnektoren.
5. Wählen Sie eine allgemeine Vorlage und optional eigene Vorlagen für Instant Messaging, Telefon, SMS
   und weitere Kanäle aus. Aktivieren Sie bei Bedarf Ausweichoptionen für Benutzer, Teams oder die Organisation.
6. Legen Sie optional eine Bestätigungsfrist und eine Eskalationsroute fest. Bei Alarmrichtlinien können Sie außerdem ein Zeitfenster zum
   [Bündeln von Benachrichtigungen](#benachrichtigungen-bündeln) festlegen.
7. Prüfen Sie die Live-Vorschau der Zustellung. Sie ermittelt die tatsächlichen Mitglieder und Routen und zeigt die
   Vorlage für jeden Schritt an, ohne etwas zu senden.

Bei der Zustellung bestimmt der Kanal des Konnektors die Vorlage: MoleSignal verwendet die für diesen Kanal ausgewählte Vorlage,
sonst die allgemeine Vorlage. Fehlen beide, sendet MoleSignal die ursprüngliche Ereignisnachricht. Solange eine
Benachrichtigungsrichtlinie eine Vorlage verwendet, lässt sich die Vorlage weder löschen noch in einen anderen Kanal verschieben.

Richtlinien decken derzeit Ereignisse im Alarmlebenszyklus und in Bereitschaftsplänen ab. Der Richtlinieneditor zeigt die
Ereignistypen und Methoden zur Empfängerermittlung an, die das laufende Backend unterstützt. Richtlinien unterdrücken Alarmereignisse
für Vorfälle, auf die eine [Stummschaltung](/de/alerting/silences) zutrifft. Siehe
[Benachrichtigungen während einer Stummschaltung](/de/alerting/silences#benachrichtigungen-während-einer-stummschaltung).

### Benachrichtigungen bündeln

Wenn sich Alarme häufen, können einzelne Personen oder Gruppen innerhalb weniger Sekunden viele Benachrichtigungen erhalten.
Benachrichtigungsrichtlinien für Alarme und Eskalationen bieten die Option **Benachrichtigungen bündeln**. Wählen Sie 30 Sekunden oder 1, 2
oder 5 Minuten aus (die API akzeptiert 10 Sekunden bis 10 Minuten). Innerhalb dieses Fensters bündelt MoleSignal Alarmbenachrichtigungen,
die über denselben Konnektor an denselben Empfänger gehen. MoleSignal sendet die erste sofort und die übrigen gemeinsam am
Ende des Zeitfensters. Inzwischen bestätigte Alarme fallen aus dem Bündel.

- Instant Messaging und E-Mail senden eine gemeinsame Liste. Der erste Titel erhält den Zusatz „(+N)“. Im Nachrichtentext
  stehen die Alarme. Wenn eine externe URL festgelegt ist, verweist jeder Alarm auf seinen Vorfall. Karten einer Feishu-App
  oder Slack-App enthalten **Alle bestätigen**. Siehe [Alarmkarten](/de/im#alarmkarten).
- SMS und Anrufe geben die Titel nacheinander aus. Eine einzige SMS-Antwort gilt für alle enthaltenen Alarme. Bei Anrufen
  beträgt das Bündelungsfenster immer mindestens 60 Sekunden.
- Der generische Webhook, PagerDuty und Amazon SNS unterstützen keine Bündelung.

Die integrierten Richtlinien für ausgelöste, behobene und eskalierte Alarme bündeln standardmäßig über 1 Minute. Für alle anderen
Richtlinien gilt standardmäßig **Nicht bündeln**.

### Vorlagenvariablen

Der Nachrichtentext, die Werte einer Anbietervorlage und alle Teile einer Karte können Variablen wie
`{{rule.name}}` enthalten. Beim Senden setzt MoleSignal die Werte der Benachrichtigung ein. Unter **Variablen** rechts
im Editor stehen die Variablen der Vorlagenkategorie. Wählen Sie eine aus, um sie an der Cursorposition einzufügen.
Ein Name mit der Endung `_at` steht für einen Zeitstempel in Mikrosekunden, ein Name mit der Endung `_time` für eine Zeitangabe in UTC wie
`2026-07-29 00:00:00 UTC`. Fehlt eine Variable im Ereignis, bleibt sie unverändert im Text stehen.

Variablen für Alarme und Eskalationen:

| Variable | Wert |
|---|---|
| `{{rule.name}}`, `{{rule.description}}` | Name und Beschreibung der Regel. |
| `{{severity}}`, `{{incident.status}}` | Schweregrad und Status des Alarms. |
| `{{urgency}}`, `{{priority}}` | Schlüssel der Dringlichkeitsstufe (`high`, `low` oder eine von der Organisation hinzugefügte Stufe) und Priorität (`P1` bis `P9`, sonst leer). Siehe [Dringlichkeit](/de/alerting/on-call#dringlichkeit). Benachrichtigungsrichtlinien können auch die Ereignisattribute `urgency` und `priority` abgleichen. |
| `{{urgency_name}}`, `{{priority_name}}` | Namen, die die Organisation der Dringlichkeitsstufe und der Priorität unter [Dringlichkeits- und Prioritätsstufen](/de/alerting/on-call#dringlichkeits-und-prioritätsstufen) gegeben hat. Ohne Namen bleibt der jeweilige Wert leer. |
| `{{value}}`, `{{threshold}}` | Wert, der den Alarm ausgelöst hat, und Schwellenwert. Bei Regeln mit mehreren Schweregraden gilt der Schwellenwert des Schweregrads des Alarms. Anomalieregeln haben keinen Schwellenwert und geben `null` aus. |
| `{{incident.url}}` | Adresse des Alarms in MoleSignal. Erfordert die externe URL `http.external_url`. |
| `{{incident.started_time}}`, `{{incident.duration}}` | Startzeit und bisherige Dauer des Alarms, etwa `1h 5m`. Bei behobenen Alarmen endet die Dauer zum Zeitpunkt der Behebung. |
| `{{incident.acknowledged_time}}`, `{{incident.acknowledged_by}}` | Nach der Bestätigung: Zeitpunkt der Bestätigung und Benutzer-ID des bestätigenden Kontos. |
| `{{incident.resolved_time}}`, `{{incident.resolved_by}}` | Nach der Behebung: Zeitpunkt der Behebung und Benutzer-ID des Kontos, das den Alarm behoben hat. Bei automatisch behobenen Alarmen fehlt die Benutzer-ID. |
| `{{incident.assignees}}`, `{{affected_services}}` | Benutzer-IDs der zugewiesenen Konten und betroffene Dienste, jeweils durch Kommas getrennt. |
| `{{service}}`, `{{environment}}` | Dienst und Umgebung aus den Labels oder Annotationen des Alarms. |
| `{{labels}}`, `{{labels.<key>}}` | Alle Labels (`service=api, env=production`) und der Wert eines einzelnen Labels. Auf Annotationen greift `{{annotations.<key>}}` zu. |
| `{{escalation.step}}`, `{{escalation.loop}}`, `{{escalation.target}}` | Schritt und Durchlauf der Eskalation, jeweils ab 1, sowie das Benachrichtigungsziel des Schritts (`user`, `schedule` oder `team`). Nur für Eskalationen. |
| `{{escalation.reason}}` | Grund für die Eskalationsbenachrichtigung: `step` (nächster Richtlinienschritt), `manual` (manuell eskaliert), `reassigned`, `responder_added`, `snooze_ended`, `ack_timeout` (bestätigt, aber zu lange nicht behoben), `severity_raised` oder `urgency_raised`. Siehe [Maßnahmen für einen Vorfall ergreifen](/de/alerting/incidents#maßnahmen-für-einen-vorfall). |
| `{{reply.ack}}`, `{{reply.resolve}}` | Codes zum Bestätigen und Beheben per Antwort, etwa `31` und `32`. MoleSignal setzt sie nur in Alarm-SMS von Konnektoren mit aktivierter Option [Aktionen per Antwort](#auf-textnachrichten-und-anrufe-reagieren) ein. Ansonsten bleiben die Variablen unverändert. |

Für Bereitschaftspläne stehen `{{schedule.*}}`, `{{oncall.*}}` und `{{override.*}}` zur Verfügung. Neben den
`_at`-Werten in Mikrosekunden gibt es für die Übergabe und das Vertretungszeitfenster die Variablen
`{{oncall.transition_time}}`, `{{override.start_time}}` und `{{override.end_time}}`. In jeder Kategorie stehen
`{{event.time}}`, `{{message.title}}` und `{{message.text}}` zur Verfügung. Auf jedes Ereignisattribut können Sie über
`{{event.attributes.<key>}}` zugreifen.

### Bedingungen

Ein Nachrichtentext kann Bedingungsblöcke enthalten. MoleSignal übernimmt deren Inhalt nur, wenn die Bedingung zutrifft:

```text
{{#if severity == "critical"}}Act now{{else}}Take a look{{/if}}: {{rule.name}}
{{#if event.type == "alert.resolved"}}Recovered after {{incident.duration}}{{/if}}
{{#if annotations.runbook_url}}Runbook: {{annotations.runbook_url}}{{/if}}
```

- `{{#if variable == "value"}}` und `!=` vergleichen den Wert einer Variablen. Steht die Variable allein, ist die Bedingung erfüllt, wenn ihr
  Wert nicht leer ist.
- Der optionale Block `{{else}}` enthält den Text für den Fall, dass die Bedingung nicht zutrifft.
- Verschachteln Sie Blöcke bis zu 5 Ebenen tief. Solange ein Block offen ist (ohne `{{/if}}`), lässt sich die Vorlage nicht speichern. Der Editor zeigt
  den Fehler unter dem Nachrichtentext an.
- Die Vorschau wertet Bedingungen anhand der Vorschau-Ereignisattribute aus. Unter **Bedingungen** rechts im
  Editor stehen einige gängige Beispiele. Wählen Sie eines aus, um es einzufügen.

### Vorgefertigte Vorlagen

**Vorgefertigte Vorlagen** bieten fertige Nachrichtentexte als Ausgangspunkt. Übernommene Texte bleiben bearbeitbar. Die Liste
ist nach Kategorie und Kanal gegliedert. Für SMS und Telefon stehen kanalspezifische Vorlagen zur Verfügung.
Auch Instant Messaging und E-Mail haben eigene Vorlagen, etwa Markdown für Instant Messaging
mit einem Link zum Alarm oder eine Alarm-E-Mail im Tabellenformat. Für Alarme gibt es vorgefertigte Vorlagen für Benachrichtigungen über ausgelöste,
bestätigte und behobene Alarme. Wenn Sie eine Vorlage für eine Bestätigung oder Behebung anwenden, zeigt die Vorschau einen entsprechend
bestätigten oder behobenen Beispielalarm. Die Nachrichtentexte richten sich nach der Sprache der Benutzeroberfläche. Die chinesische
Oberfläche übernimmt daher chinesische Texte.

### Anbietervorlagen in Benachrichtigungsvorlagen

Alibaba Cloud, Tencent Cloud und Huawei Cloud versenden nur freigegebene Vorlagen. WhatsApp versendet nur
freigegebene Content-Vorlagen. Eine SMS- oder Telefonvorlage kann pro Anbieter eine Vorlage enthalten. Vorlagen für WhatsApp lassen sich
nur in SMS-Vorlagen hinterlegen:

- **Vorlagencode** — der Code des Anbieters. Bei Alibaba Cloud beginnt er für SMS mit `SMS_` und für
  Sprachanrufe mit `TTS_`. Bei Tencent Cloud und Huawei Cloud ist es die Vorlagen-ID. Tragen Sie für WhatsApp unter
  **Content SID** die Twilio Content SID ein: `HX` gefolgt von 32 hexadezimalen Zeichen.
- **Variablen** — der Wert für jede Variable. Schreiben Sie Werte wie den Nachrichtentext. Sie können darin
  Variablen wie `{{rule.name}}` verwenden. Bei Alibaba Cloud stehen die Namen in der Vorlage innerhalb von `${…}`.
  Tencent Cloud, Huawei Cloud und WhatsApp füllen Variablen nach Position. Die Namen lauten daher `1`, `2`, `3`.
- **Zeichen pro Variable** — MoleSignal kürzt längere Werte. Bei leerem Feld gilt der Standardwert: Alibaba Cloud 35,
  Tencent Cloud 6 für SMS und 20 für Sprachanrufe, Huawei Cloud 20 für SMS und 32 für Sprachanrufe (zusätzlich auf 32 Bytes begrenzt),
  WhatsApp 300.

Konnektoren dieser Anbieter senden die jeweils hinterlegte Anbietervorlage. Andere SMS- und Telefonkonnektoren senden den
Nachrichtentext. Fehlt in der für den Kanal ausgewählten Benachrichtigungsvorlage die passende Anbietervorlage,
schlägt die Zustellung fehl. Das Zustellungslog zeigt den Grund an.

Beim Test eines solchen Konnektors sendet MoleSignal eine Vorlage des Kanals mit der passenden Anbietervorlage
und Beispielwerten für die Platzhalter. Beim Test einer Rufnummer, die für ein Mitglied mit diesem Konnektor verknüpft ist, verwendet MoleSignal die
erste passende Vorlage in alphabetischer Reihenfolge. Geplante Prüfungen, Automatisierungen und andere Direktzustellungen verwenden
keine Benachrichtigungsvorlagen und können diese Konnektoren daher nicht nutzen.

### Karten in Vorlagen für Instant Messaging

Aktivieren Sie in einer Vorlage für Instant Messaging **Als Karte senden**, damit Apps und Gruppenbots eine Karte senden.
Ist die Option deaktiviert, senden sie wie bisher Text. Als Kartentext dient der Nachrichtentext der Vorlage. Zusätzlich enthält
eine Karte folgende Elemente:

- **Kartentitel** — wenn das Feld leer ist, gilt der Benachrichtigungstitel.
- **Titelfarbe** — eine feste Farbe oder eine Farbe nach Schweregrad (kritisch: Rot, Fehler: Orange, Warnung: Gelb, sonst Blau,
  nach der Behebung Grün).
- **Felder** — jeweils ein Name und ein Wert, etwa `{{labels.service}}` für `Service`. Höchstens 10 Felder.
- **Link-Schaltflächen** — jeweils ein Schaltflächentext und eine Adresse, etwa `{{annotations.runbook_url}}` für
  `Runbook`. Höchstens 5 Schaltflächen.
- **Fußzeile** — eine Zeile in kleiner Schrift am unteren Kartenrand.

Alle Bestandteile unterstützen Variablen. Wenn Werte im Ereignis fehlen, lässt MoleSignal die betreffenden Felder oder Links weg. Das gilt auch für Links
ohne HTTP- oder HTTPS-Adresse. Die Vorschau im Editor zeigt nur das ungefähre Layout. Jede Plattform sendet ein
eigenes Kartenformat:

| Plattform | Versandformat |
|---|---|
| **Lark** | Interaktive Karte mit farbiger Titelleiste, zweispaltigen Feldern und Fußzeile unter einer Trennlinie. In der App stehen die Link-Schaltflächen neben den Alarmschaltflächen „Bestätigen“ und „Beheben“. |
| **Slack** | Block-Kit-Karte mit Farbbalken. In der App stehen die Link-Schaltflächen neben den Alarmschaltflächen. |
| **DingTalk** | ActionCard mit farbigem Titel und bis zu 5 Links als Schaltflächen unter der Karte. Ohne Links verwendet DingTalk Markdown. Wenn die App eine Kartenvorlagen-ID hat, erscheinen Alarmbenachrichtigungen als interaktive Karten aus dieser Vorlage mit Alarmschaltflächen. |
| **WeCom** | Markdown im Kartenlayout mit farbigem Titel (WeCom unterstützt nur grünen, grauen und orangefarbenen Text). Für Alarmschaltflächen verwendet WeCom eine interaktive Vorlagenkarte mit Schaltflächen. Bis zu 6 Felder erscheinen als Untertitel mit Text. Ein Klick auf die Karte öffnet MoleSignal. |
| **Teams** | Adaptive Card mit farbiger Titelleiste, Feldern als Schlüssel-Wert-Paare, Links als Schaltflächen und Fußzeile unter einer Trennlinie. Beim Bot stehen die Link-Schaltflächen neben den Alarmschaltflächen. |
| **Google Chat** | Karte mit beschrifteten Zeilen für Felder und Schaltflächen für Links. In der App stehen die Link-Schaltflächen neben den Alarmschaltflächen. Kartentitel in Google Chat haben keine Farbe. |
| **Telegram** | Nachricht mit fett gedrucktem Titel hinter einem Punkt in der Titelfarbe, einem Feld pro Zeile und kursiver Fußzeile. Die Alarmschaltflächen stehen in der ersten Zeile, darunter folgen jeweils zwei Link-Schaltflächen pro Zeile. Lehnt Telegram eine nicht öffentliche Adresse ab, erscheinen die Links stattdessen als Textzeilen. |
| **Discord** | Embed mit Farbbalken, auf den Alarm verlinktem Titel, Text mit darunterstehenden Links, nebeneinander angeordneten Feldern und Fußzeile. |
| **Mattermost** | Nachrichtenanhang mit Farbbalken, auf den Alarm verlinktem Titel, Feldern (kurze Felder nebeneinander), Links unter dem Text und einer Fußzeile. Die Alarmschaltflächen des Bots stehen unter dem Anhang. |
| **Webex** | Der Bot sendet eine Adaptive Card im Teams-Layout mit bis zu 5 Link-Schaltflächen und weiteren Links unter dem Text. Der Webhook sendet Markdown. |
| **Matrix** | Formatierte Nachricht mit farbigem Titel, Feldern als Liste, darunter den Links und einer kursiven Fußzeile. |

Gruppenbots empfangen keine Klicks. Ihre Karten enthalten daher keine Schaltflächen zum Bestätigen oder Beheben. Wählen Sie beim Test eines
Konnektors bei Bedarf eine Vorlage für Instant Messaging aus. MoleSignal sendet die Karte dann mit Beispielwerten für die
Variablen.

### Integrierte Richtlinien

Jede Organisation verfügt von Anfang an über die folgenden Benachrichtigungsrichtlinien. So erreichen Alarme und Bereitschaftsereignisse die zuständigen Personen
auch ohne eigene Richtlinien. Für alle gilt **Benutzerpräferenz berücksichtigen**. Scheitert der Versand,
verwendet MoleSignal zuerst die Ausweichendpunkte des Benutzers, dann die Ausweichrouten des Teams und der Organisation. Die Richtlinien verwenden keine
Vorlage und senden die ursprüngliche Ereignisnachricht.

| Integrierte Richtlinie | Ereignis | Empfänger | Standardzustand |
|---|---|---|---|
| Alarm ausgelöst: Verantwortliche benachrichtigen | Alarm ausgelöst | Für den Alarm verantwortliches Konto, andernfalls die zugewiesenen Konten | Ein |
| Alarm behoben: Verantwortliche benachrichtigen | Alarm behoben | Für den Alarm verantwortliches Konto, andernfalls die zugewiesenen Konten | Ein |
| Eskalation: Personen des Schritts benachrichtigen | Alarm an einzelne Personen eskaliert | Im Schritt angegebene Personen | Ein |
| Eskalation: Team des Schritts benachrichtigen | Alarm an ein Team eskaliert | Mitglieder des Teams | Ein |
| Bereitschaftsübergabe: Beide Beteiligten benachrichtigen | Bereitschaftsschicht beginnt | Personen, deren Schicht endet bzw. beginnt | Ein |
| Lücke im Bereitschaftsplan: Planverantwortliche benachrichtigen | Bereitschaft nicht besetzt | Verantwortliche des Bereitschaftsplans | Ein |
| Alarm bestätigt: Verantwortliche benachrichtigen | Alarm bestätigt | Für den Alarm verantwortliches Konto, andernfalls die zugewiesenen Konten | Aus |
| Vertretung im Bereitschaftsdienst: Beteiligte benachrichtigen | Vertretung eingerichtet | Vertretung und ursprünglich eingeteilte Person | Aus |
| Schichttausch: Beteiligte benachrichtigen | Schichttausch aktualisiert | Alle, für die der aktuelle Schritt relevant ist. Siehe [Schichttausch](/de/alerting/on-call#schichttausch). | Ein |
| Mitglied im Bereitschaftsdienst nicht erreichbar: Mitglied und Planverantwortliche benachrichtigen | Mitglied im Bereitschaftsdienst nicht erreichbar (30 Minuten vor Schichtbeginn) | Für die Schicht eingeteilte Person und Verantwortliche des Bereitschaftsplans. Siehe [Mitglieder, die keine Alarme empfangen können](/de/alerting/on-call#mitglieder-ohne-alarmempfang). | Ein |
| Aufnahmebudget fast ausgeschöpft: Hinterlegte Personen benachrichtigen | Aufnahmebudget fast ausgeschöpft | Im Budget hinterlegte Personen. Siehe [Budget festlegen](/de/streams#budget-festlegen). | Ein |
| Aufnahmebudget überschritten: Hinterlegte Personen benachrichtigen | Aufnahmebudget überschritten | Im Budget hinterlegte Personen. Siehe [Budget festlegen](/de/streams#budget-festlegen). | Ein |
| Update zu einem größeren Vorfall: Beteiligte benachrichtigen | Update zu einem größeren Vorfall | Zugewiesene Konten, Rollen und Beteiligte des Vorfalls. Siehe [Update veröffentlichen](/de/alerting/major-incidents#update-veröffentlichen). | Ein |
| Genehmigung erforderlich: Genehmigungsberechtigte benachrichtigen | Mole Agent fordert eine Genehmigung an (`agent.approval.requested`) | Bis zu 20 Mitglieder mit `agent.approve`, ohne das anfragende Konto. Siehe [Genehmigungskarten](/de/im#freigabekarten). | Ein |

In der Liste **Benachrichtigungsrichtlinien** tragen integrierte Richtlinien die Kennzeichnung **Integriert**. Sie können die Richtlinien ändern oder
deaktivieren, aber weder löschen noch umbenennen. Um die oben genannten Einstellungen für eine geänderte Richtlinie wiederherzustellen, klicken Sie im Editor auf
**Standard wiederherstellen**. Für Eskalationsschritte, die an einen Bereitschaftsplan weiterleiten, gibt es keine integrierte Richtlinie. Erstellen Sie je
Bereitschaftsplan eine Richtlinie mit **Aktuell im Bereitschaftsdienst** als Empfänger.

## Fallback-Routen konfigurieren

Öffnen Sie **Einstellungen → Benachrichtigungen → Fallback-Routen**. Wählen Sie als Geltungsbereich eine Organisation oder ein Team und
eine Benachrichtigungskategorie aus. Fügen Sie mindestens einen aktivierten Konnektor hinzu, wählen Sie `fixed_address` oder
`fixed_group` und geben Sie das Ziel beim Anbieter ein.

MoleSignal probiert die Routen in der angezeigten Reihenfolge aus, wenn alle aktivierten persönlichen Routing-Stufen fehlschlagen. Die
Richtlinie legt fest, ob Fallbacks auf Benutzer-, Team- und Organisationsebene zum Einsatz kommen.

## Zustellungen prüfen und wiederholen

Öffnen Sie **Einstellungen → Benachrichtigungen → Zustellprotokoll**. Filtern Sie nach Ereignis-ID, Status oder Stufe. Wählen Sie einen
Zustellversuch aus. Prüfen Sie das maskierte Ziel, den Konnektor, die Latenz, den Anbieterfehler und die vollständige
Zustellkette.

- `notify.deliveries.read` erlaubt das Einsehen des Zustellverlaufs.
- `notify.deliveries.acknowledge` erlaubt das Bestätigen des ursprünglichen Ereignisses.
- `notify.deliveries.retry` erlaubt das Wiederholen fehlgeschlagener Routen.

Jede Wiederholung erzeugt einen neuen Zustellversuch. Der bisherige Zustellverlauf bleibt unverändert.

MoleSignal wiederholt fehlgeschlagene Alarmbenachrichtigungen automatisch. Sobald der Alarm bestätigt oder behoben ist, enden die automatischen Wiederholungen. Manuelle Wiederholungen sind weiterhin möglich.

Eine Zustellung mit der Stufe **Direkt** stammt von einer Funktion, die Konnektor und Ziel
selbst vorgibt, etwa einer [geplanten Log-Prüfung](/de/logs/inspections). Für direkte Zustellungen gilt
keine Richtlinie. Sie lassen sich nicht wiederholen.

## Lebenszyklus und Status von Konnektoren

| Status | Bedeutung |
|---|---|
| **Unbekannt** | Für den Konnektor liegt noch kein Testergebnis vor. |
| **Verbunden** | Der letzte Test war erfolgreich. |
| **Fehler** | Der letzte Test ist fehlgeschlagen. Beim regulären Routing überspringt MoleSignal den Konnektor, bis ein weiterer Test erfolgreich ist. |
| **Deaktiviert** | MoleSignal testet den Konnektor nicht und nutzt ihn nicht für Zustellungen. |

Beim Deaktivieren eines Konnektors bleiben Verweise erhalten. Solange eine Benutzeridentität,
eine Richtlinie, eine Fallback-Route oder eine geplante Log-Prüfung auf den Konnektor verweist, lässt er sich nicht löschen. Stellen Sie alle
Verweise auf einen anderen Konnektor um, bevor Sie den Konnektor löschen.

## Zustellprobleme beheben

| Symptom | Prüfung |
|---|---|
| SMTP-Authentifizierung oder TLS schlägt fehl | Prüfen Sie Host, Port, Zugangsdaten, TLS-Modus, Absenderadresse, DNS und ausgehenden Netzwerkzugriff. |
| Slack gibt einen API-Fehler zurück | Prüfen Sie das Bot-Token, die Berechtigung `chat.postMessage`, die Ziel-ID und die Kanalmitgliedschaft. |
| Lark lehnt die Nachricht ab | Prüfen Sie die App-Berechtigungen, den Typ der Empfänger-ID, die Chat-Mitgliedschaft, das Webhook-Secret und die Serverzeit. |
| Der Webhook gibt einen Fehler zurück | Prüfen Sie URL, Methode, Header-JSON und Timeout. Stellen Sie sicher, dass der Endpunkt mit einem 2xx-Statuscode antwortet. |
| Keine Zustellung an den Benutzer | Prüfen Sie, ob Identität und Konnektor aktiviert sind, die Kategorieeinstellung die Identität enthält und keine Ruhezeit die Zustellung unterdrückt. |
| Die Fallback-Route greift nie | Prüfen Sie, ob die Richtlinie diese Fallback-Ebene aktiviert und die Kategorie eine aktivierte Route enthält. |
| Ein Anruf oder eine SMS bleibt aus | Prüfen Sie, ob die Rufnummer mit + und der Landesvorwahl beginnt, Vorlage und Signatur freigegeben sind und die für den Kanal gewählte Vorlage der Benachrichtigungsrichtlinie eine Variante für diesen Anbieter enthält. Prüfen Sie auch die Variablennamen, die Ratenlimits des Anbieters und die Konto-Sandbox. |
| Eine Antwort oder ein Tastendruck bleibt ohne Wirkung | Prüfen Sie, ob **Antworten verarbeiten** für den Konnektor aktiviert ist und der Callback des Anbieters auf die im Konnektor angezeigte URL verweist. Prüfen Sie, ob die URL aus dem Internet erreichbar ist, die Rufnummer eine Alarm-SMS mit Codes erhalten hat, der verwendete Code weniger als einen Tag alt ist und das Empfängermitglied über `alerts.incidents.acknowledge` verfügt. |
| Ein Feishu- oder DingTalk-Schritt schlägt fehl, obwohl die Nachricht ankommt | Die dringende Alarmierung ist fehlgeschlagen. Prüfen Sie die App-Berechtigung, das Kontingent für dringende Benachrichtigungen bzw. DING und die DingTalk-Edition. Prüfen Sie bei Feishu auch den Typ der Empfänger-ID und die Plattform. |
| Ein Aktionslink bleibt ohne Wirkung | Prüfen Sie, ob der Link unbenutzt und weniger als 24 Stunden alt ist, die Aktion für den Alarm noch aussteht und das Empfängerkonto weiterhin über `alerts.incidents.acknowledge` verfügt. Prüfen Sie, ob die Seite und `/api/v1/public/notify/actions/` aus dem Netzwerk erreichbar sind, in dem der Link geöffnet wurde. |
