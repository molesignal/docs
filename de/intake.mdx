Jedes Signal gelangt über die Erfassungs-API in MoleSignal. Die Seite **Datenquelle** in der Weboberfläche generiert für jede Quelle den Endpunkt, das Token und einen Konfigurationsausschnitt. Dieselben Protokolle lassen sich auch manuell konfigurieren.

## Seite „Datenquelle“

Öffnen Sie **Datenquelle**, um eine Quelle einzurichten:

1. Durchsuchen Sie den Katalog oder filtern Sie ihn nach Kategorie: **Empfohlen**, **Infrastruktur**, **Cloud**, **Datenbanken**, **Messaging**, **Apps und Programmiersprachen**, **Sicherheit** und **Benutzerdefiniert**. Über die Signal-Registerkarten (**Logs**, **Metriken**, **Traces**, **Profile**) lässt sich die Liste weiter eingrenzen.
2. Wählen Sie eine Quelle aus, etwa Kubernetes, einen Linux-Host, AWS, ein OpenTelemetry SDK oder Web RUM.
3. Führen Sie die drei Schritte der Anleitung aus:
   - **Endpunkt und Token** zeigt das Ziel für die Daten und das Token für die Authentifizierung an. **Token anzeigen** blendet das Token samt Geltungsbereich, Arbeitsbereich und Ablaufdatum ein. Wählen Sie bei einer RUM-Quelle zuerst die **RUM-Anwendung** aus. Danach erscheint das zugehörige Client-Token.
   - **Quelle einrichten** zeigt Befehle und Konfigurationen an, in denen der tatsächliche Endpunkt und das Token bereits eingetragen sind.
   - **Dateneingang prüfen** prüft zuerst den Empfänger und sucht dann nach Daten, die in der letzten Stunde eingegangen sind. **Verbindung prüfen** startet die Prüfung sofort. Die Zahlen werden alle 30 Sekunden aktualisiert.
4. Lesen Sie das Prüfergebnis:
   - **Daten eingegangen**: In der letzten Stunde sind Daten eingegangen und alle Signale der Quelle sind in Ordnung. **Empfangene Daten anzeigen** öffnet die Daten. **Pipeline erstellen** startet die Einrichtung einer Pipeline für diese Daten.
   - **Empfänger ist funktionsfähig, aber die Daten sollten geprüft werden**: Der Empfänger antwortet, aber es sind keine Daten eingegangen oder nicht alle Signale sind in Ordnung. Prüfen Sie das Deployment oder warten Sie auf den nächsten Batch.
   - **Überprüfung fehlgeschlagen**: Der Empfänger ließ sich nicht prüfen. **Mögliche Ursachen** nennt einen Collector, der nicht läuft, ein ungültiges oder abgelaufenes Token sowie ein Netzwerk oder einen Proxy, der den Endpunkt blockiert.

MoleSignal verwendet `http.external_url` als Endpunkt, sofern der Wert gesetzt ist. Andernfalls verwendet MoleSignal die Adresse im Browser. Setzen Sie `http.external_url` beim Betrieb hinter einem Reverse Proxy, damit generierte Konfigurationsausschnitte auf die öffentliche Adresse verweisen. Siehe [Konfiguration](/de/configuration).

## Token für die Datenerfassung

Sender authentifizieren sich mit einem Bearer-Token: `Authorization: Bearer <token>`.

| Token | Berechtigung | Erstellung | Verwendung |
|---|---|---|---|
| Standardtoken für die Datenerfassung | Nur `logs.write`, `metrics.write`, `traces.write`, `profiles.write` und `apm.deploy`: die Richtlinie **Datenerfassung** | Seite „Datenquelle“ oder `GET /api/v1/me/api-tokens/default` | Collectors, Agents und SDK-Exporter, die Logs, Metriken und Traces senden, sowie Pipelines, die [Deployments melden](/de/apm/deployments#deployments-aus-der-ci-melden). Läuft nicht ab. |
| RUM-Client-Token | Nur `rum.write`, an eine Anwendung gebunden | Seite „Datenquelle“ für Web-RUM- und mobile RUM-Quellen oder `GET /api/v1/auth/tokens/rum?applicationId=<id>` | Code für Browser und mobile Apps. Das Token ist für Endnutzende sichtbar. |
| Persönliches Token oder Dienstkonto-Token | Berechtigungen des Mitglieds oder Dienstkontos, eingeschränkt durch den Geltungsbereich des Tokens | **Kontoeinstellungen → API-Token** oder für Dienstkonten **Identität und Zugriff → API-Token** | Automatisierung, Skripte und MCP-Clients. |

Verwenden Sie für dauerhaft laufende Sender das Standardtoken für die Datenerfassung oder ein Dienstkonto-Token gemäß der Richtlinie **Datenerfassung**. Widerrufen Sie ein Token unter **Kontoeinstellungen → API-Token** oder **Identität und Zugriff → API-Token**, um es sofort ungültig zu machen. Mit einer Anmeldesitzung der Weboberfläche lassen sich keine Daten senden: Die Sitzung wird in Browser-Cookies gespeichert, und der Header `Authorization` akzeptiert sie nicht.

Die Seite **Datenquelle** erstellt ein RUM-Client-Token, sobald eine Anwendungs-ID eingegeben wird. Eine Anwendungs-ID besteht aus 1 bis 128 Zeichen aus `A-Z`, `a-z`, `0-9`, `.`, `_`, `:` und `-`. Verwenden Sie dieselbe ID als `applicationId` im SDK. Siehe [Browser-RUM-SDK](/de/rum/browser-sdk).

## Endpunkte und Protokolle

| Protokoll | Endpunkt | Kompatible Sender | Zielstream |
|---|---|---|---|
| Natives HTTP JSON | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`, Anwendungscode, Vector-Sink `http`, Fluent Bit-Ausgabe `http` | Das Pfadsegment `{stream}` |
| OTLP über HTTP | `POST /api/v1/logs`, `/api/v1/metrics`, `/api/v1/traces` | OpenTelemetry SDKs und Collector | Header `stream-name`, andernfalls `default` |
| OTLP über gRPC | `:4317` | OpenTelemetry SDKs und Collector | Metadaten `stream-name`, andernfalls `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus, VictoriaMetrics, alle Sender mit remote_write v1 | Header `stream-name`, andernfalls `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat, Logstash, Vector-Sink `elasticsearch` | `_index` der jeweiligen Aktion, andernfalls Header `stream-name`, sonst `default` |
| Loki Push (JSON) | `POST /api/v1/loki/api/v1/push` | Sender, die per POST im JSON-Format von Loki senden können | Header `stream-name`, andernfalls `default` |
| Kinesis Firehose, Cloudflare Logpush, Heroku | `/api/v1/_kinesis_firehose`, `/api/v1/_cloudflare`, `/api/v1/_heroku` | AWS, Cloudflare, Heroku | Im Connector konfiguriert. Siehe [Connectors](/de/connectors). |

Alle Endpunkte außer den Push-Connectors benötigen ein Bearer-Token mit der Schreibberechtigung für das jeweilige Signal: `logs.write`, `metrics.write`, `traces.write` oder `profiles.write`. MoleSignal ermittelt die Organisation aus dem Token. Die Organisation erscheint nie in einer URL.

### Limits für Sender

- **Anfragegröße.** Die native JSON-Erfassung akzeptiert Anfragekörper bis zu 16 MiB, gemessen nach der Dekomprimierung. Die übrigen Erfassungsendpunkte akzeptieren bis zu 2 MiB. Ist der Anfragekörper größer, gibt der Endpunkt `413` zurück. Halten Sie Batches unter dem jeweiligen Limit.
- **Komprimierung.** OTLP über HTTP akzeptiert keine komprimierten Anfragekörper und antwortet mit `400`. Deaktivieren Sie die Komprimierung im Sender. Der `otlphttp`-Exporter des OpenTelemetry Collector komprimiert standardmäßig mit gzip und benötigt daher `compression: none`. Die native JSON-Erfassung, Elasticsearch `_bulk`, Loki Push und die Push-Connectors akzeptieren `Content-Encoding: gzip`.
- **Loki-Kodierung.** Der Endpunkt dekodiert nur Anfragen im JSON-Format. Promtail und Grafana Alloy senden standardmäßig mit Snappy komprimiertes Protobuf und können daher nicht an diesen Endpunkt senden.
- **Ratenlimit.** Die Rolle `router` begrenzt die Anfragerate pro Organisation und antwortet bei Überschreitung mit `429` und dem Header `Retry-After`. Ein `standalone`-Knoten wendet dieses Limit nicht an. Siehe [Rollenbasiertes Deployment](/de/deployment/role-based#ratenbegrenzung).
- **Plattformstreams.** Nur MoleSignal schreibt in [Plattformstreams](/de/streams#plattform-streams) wie `_molesignal` für die eigene Diensttelemetrie und `_audit` für das Audit-Protokoll. Schreibanfragen über öffentliche Erfassungsendpunkte werden mit `403` abgewiesen.

## Streams und Schema

MoleSignal erstellt einen Stream beim ersten Schreibvorgang und erweitert das Schema, sobald neue Felder hinzukommen. Name und Signaltyp identifizieren einen Stream eindeutig. Daher kann `default` gleichzeitig für Logs, Metriken und Traces existieren. Siehe [Streams](/de/streams).

Jedes Ereignis hat einen Zeitstempel in Mikrosekunden seit der Unix-Epoche. Die native JSON-Erfassung und Elasticsearch `_bulk` lesen das Feld `_timestamp`. Fehlt `_timestamp`, verwendet der Server den Zeitpunkt, zu dem er das Ereignis angenommen hat.

## Natives HTTP JSON

Senden Sie ein Array von Datensätzen per POST an `/api/v1/intake/{logs,metrics,traces}/{stream}`:

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

Die Antwort gibt an, wie viele Datensätze der Endpunkt angenommen und abgelehnt hat, und nennt für jeden abgelehnten Index den Grund:

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

Konfigurieren Sie den Basispfad `/api` als Ziel für ein OpenTelemetry SDK oder einen OpenTelemetry Collector. Der Exporter hängt `/v1/logs`, `/v1/metrics` und `/v1/traces` an. Daraus ergeben sich `/api/v1/logs`, `/api/v1/metrics` und `/api/v1/traces`.

<Tabs>
  <Tab title="OTLP über HTTP">
    SDK-Umgebungsvariablen:

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    Senden Sie Daten als protobuf (`application/x-protobuf`), dem Standardformat der SDKs und des Collectors. Für Logs, Metriken und Traces ist auch JSON (`application/json`) möglich. Fügen Sie den Header `stream-name` hinzu, um einen anderen Stream als `default` auszuwählen. Der Header gilt für alle Signale, die dieser Exporter sendet.
  </Tab>
  <Tab title="OTLP über gRPC">
    Der OTLP-gRPC-Empfänger lauscht auf Port `4317` und stellt die Dienste für Logs, Metriken, Traces und Profile bereit. Der Empfänger terminiert TLS nicht. Terminieren Sie TLS vor dem Empfänger, wenn der Datenverkehr ein vertrauenswürdiges Netzwerk verlässt.

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    Entfernen Sie `insecure: true`, wenn ein vorgeschalteter Proxy TLS für diesen Port terminiert. Port `5082` ist der interne gRPC-Port des Clusters und dient nicht als OTLP-Empfänger.
  </Tab>
</Tabs>

MoleSignal speichert für OTLP-Metriken ein Ereignis pro Datenpunkt. Die gespeicherten Felder finden Sie in der [Spezifikation zur Metrikspeicherung](/de/query#otlp-metrikfelder).

## Prometheus remote_write

Fügen Sie MoleSignal in `prometheus.yml` als Remote-Write-Ziel hinzu:

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

Ein Metrik-Stream enthält die Metriken einer einzelnen Quelle. Weisen Sie daher jedem Prometheus-Server über den Header `stream-name` (`headers:` im Eintrag `remote_write`) einen eigenen Stream zu. Ohne diesen Header landen die Messwerte in `default`. Jeder Messwert ergibt eine Zeile mit dem Wert von `__name__` im Feld `metric_name`. Andere Labels werden zu Feldern. Hat ein Label denselben Namen wie ein Metrikfeld, etwa `metric_name`, speichert MoleSignal es unter `exported_<name>`. MoleSignal überspringt native Histogramme und Metrikmetadaten und speichert Exemplare neben den Messwerten.

## Elasticsearch Bulk

Sender, die das Elasticsearch-Bulk-Protokoll unterstützen, benötigen weder Loki noch OTLP:

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

Der Wert von `_index` legt für jede Aktion den Zielstream fest. Fehlt der Wert, gilt der Header `stream-name`. Fehlt auch dieser, gilt `default`.

## Loki Push

Der Endpunkt akzeptiert Anfragen im Loki-JSON-Format:

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

MoleSignal übernimmt Labels als Felder, speichert die Logzeile im Feld `message` und rechnet den Zeitstempel von Nanosekunden in Mikrosekunden um. Der Endpunkt antwortet mit `204`. Wählen Sie den Zielstream über den Header `stream-name` aus.
