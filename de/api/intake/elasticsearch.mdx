```http
POST /api/v1/_bulk
```

Elasticsearch-`_bulk`-kompatible NDJSON-Aufnahme für Filebeat, Logstash und die Vector-Sink `elasticsearch`. Der Aufruf erfordert `logs.write`. Der Endpunkt akzeptiert einen Request-Body mit `Content-Encoding: gzip`.

| Aktion | Verarbeitung |
|---|---|
| `index`, `create`, `update` | Der Endpunkt speichert das Quelldokument als Log-Ereignis. |
| `delete` | Der Endpunkt überspringt die Aktion ohne Eintrag in der Antwort. Er löscht keine Telemetriedaten. |

Das Feld `_index` einer Aktion legt den Ziel-Log-Stream fest. Fehlt das Feld, gilt der Header `stream-name`. Fehlt auch dieser, gilt `default`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## Diesen Endpunkt wählen

Verwenden Sie diesen Endpunkt, wenn ein vorhandener Sender NDJSON im Elasticsearch-Bulk-Format ausgeben kann. Der Endpunkt dient als Aufnahmeadapter, nicht als Elasticsearch-Cluster: Die API bietet weder Suche noch Indexvorlagen, Dokument-IDs oder direkte Aktualisierungen gespeicherter Dokumente. Lesen Sie gespeicherte Ereignisse mit [SQL-Abfragen](/de/query).

## Einen gültigen Batch erstellen

- Senden Sie für jede `index`- oder `create`-Operation ein Aktionsobjekt und ein Dokumentobjekt auf separaten Zeilen. Schließen Sie den Batch mit einem Zeilenumbruch ab.
- Legen Sie bei `update` die Ereignisfelder unter `doc` ab. Der Endpunkt erstellt aus diesen Feldern ein neues Ereignis, statt ein gespeichertes Ereignis zu ändern.
- Setzen Sie `_index` in der Aktion, um einen Stream auszuwählen. Verwenden Sie andernfalls `stream-name` oder nutzen Sie den Stream `default`.
- Geben Sie `_timestamp` als ganzzahligen Unix-Zeitstempel in Mikrosekunden an, um den ursprünglichen Ereigniszeitpunkt beizubehalten. Andernfalls verwendet der Empfänger die aktuelle Zeit.
- Der Endpunkt überspringt die Aktion `delete`. Sie löscht keine Telemetriedaten und erzeugt in der Antwort keinen Eintrag für ein gespeichertes Ereignis.

## Die Aufnahme prüfen

Bei einem Batch mit einem Ereignis enthält die Antwort `errors: false` und einen Eintrag mit `status: 201`. Vergleichen Sie die Anzahl der Einträge mit der Anzahl der Ereignisse, die der Endpunkt aufnehmen soll. Ein erfolgreicher HTTP-Status allein bestätigt nicht, dass der Batch wie vorgesehen aufgebaut war.

Öffnen Sie **Logs**, wählen Sie den über `_index` festgelegten Stream und stellen Sie einen Zeitraum ein, der den Ereigniszeitpunkt umfasst. Fragen Sie ein charakteristisches Feld aus dem Beispiel ab. Falls das Ereignis fehlt, prüfen Sie die Stream-Auswahl und die Einheit des Zeitstempels, bevor Sie den gesamten Batch erneut senden. Diese Schnittstelle verwendet keine Elasticsearch-Dokument-IDs, um Duplikate bei erneuten Sendeversuchen zu vermeiden.

## Fehler bei einer abgelehnten Anfrage beheben

| Symptom | Prüfung |
|---|---|
| Authentifizierungs- oder Berechtigungsfehler | Verwenden Sie ein API-Token für die vorgesehene Organisation mit der Berechtigung `logs.write`. |
| Aktion oder Dokument ist kein JSON-Objekt | Prüfen Sie die Zeilenumbrüche im NDJSON. Senden Sie weder ein JSON-Array noch ein zur besseren Lesbarkeit über mehrere Zeilen formatiertes Objekt. |
| Unbekannte Aktion | Verwenden Sie die oben aufgeführten unterstützten Aktionsnamen. |
| Dekomprimierungsfehler | Setzen Sie `Content-Encoding: gzip` nur, wenn der Request-Body tatsächlich komprimiert ist. |
| Erfolg mit weniger Ereignissen als erwartet | Prüfen Sie, ob auf jede Schreibaktion eine Dokumentzeile folgt. Unterscheiden Sie übersprungene Löschaktionen von gespeicherten Ereignissen. |
