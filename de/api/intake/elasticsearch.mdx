```http
POST /api/v1/_bulk
```

Elasticsearch-`_bulk`-kompatible NDJSON-Aufnahme für Filebeat, Logstash und die `elasticsearch`-Senke von Vector. Der Aufruf erfordert `logs.write`. Ein Body mit `Content-Encoding: gzip` wird akzeptiert.

| Aktion | Behandlung |
|---|---|
| `index`, `create`, `update` | Das Quelldokument wird als Log-Ereignis gespeichert. |
| `delete` | Wird ohne Antwort-Eintrag übersprungen. Telemetrie wird über diesen Endpunkt nie gelöscht. |

Die `_index` einer Aktion wählt den Ziel-Log-Stream. Fehlt sie, gilt der Header `stream-name`, danach `default`.

Ein Dokument mit einem Wert, der nicht zum Typ seines Felds im Stream passt, wird für sich allein abgelehnt. Sein Eintrag hat `status: 400` und ein `error` mit der `reason`, `errors` ist `true`, und die übrigen Dokumente werden geschrieben. Filebeat und Logstash wiederholen einen solchen Eintrag nicht.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## Diesen Endpunkt wählen

Verwenden Sie diesen Endpunkt, wenn ein vorhandener Sender Elasticsearch-Bulk-NDJSON ausgeben kann. Er ist ein Aufnahme-Adapter, kein Elasticsearch-Cluster: Suche, Index-Templates, Dokument-IDs und In-Place-Update-Semantik stellt diese API nicht bereit. Verwenden Sie [SQL-Abfragen](/de/query), um gespeicherte Ereignisse zu lesen.

## Einen gültigen Batch erstellen

- Senden Sie für jede `index`- oder `create`-Operation ein Aktionsobjekt und ein Dokumentobjekt in getrennten Zeilen. Beenden Sie den Batch mit einem Zeilenumbruch.
- Legen Sie bei `update` die Ereignisfelder unter `doc` ab; die Felder werden zu einem neuen Ereignis, statt ein gespeichertes Ereignis zu ändern.
- Setzen Sie `_index` in der Aktion, um einen Stream zu wählen. Andernfalls verwenden Sie `stream-name` oder akzeptieren den Stream `default`.
- Geben Sie `_timestamp` als ganzzahligen Unix-Zeitstempel in Mikrosekunden an, wenn die Ereigniszeit erhalten bleiben soll. Andernfalls verwendet der Empfänger die aktuelle Zeit.
- Eine `delete`-Aktion wird übersprungen. Sie löscht keine Telemetrie und trägt keinen Eintrag für gespeicherte Ereignisse zur Antwort bei.

## Aufnahme überprüfen

Erwarten Sie für einen Batch mit einem Ereignis `errors: false` und einen Antwort-Eintrag mit `status: 201`. Vergleichen Sie die Anzahl der Einträge mit der Anzahl der Ereignisse, die aufgenommen werden sollten; ein HTTP-Erfolg allein belegt nicht, dass der Batch wie beabsichtigt aufgebaut wurde.

Öffnen Sie **Logs**, wählen Sie den durch `_index` gewählten Stream und verwenden Sie einen Zeitraum, der den Ereignis-Zeitstempel enthält. Fragen Sie ein markantes Feld aus dem Beispiel ab. Wenn das Ereignis fehlt, prüfen Sie die Stream-Auswahl und die Zeiteinheit, bevor Sie den gesamten Batch erneut senden. Diese Schnittstelle verwendet keine Elasticsearch-Dokument-IDs, um Wiederholungen zu deduplizieren.

## Eine abgelehnte Anfrage beheben

| Symptom | Prüfen |
|---|---|
| Authentifizierungs- oder Berechtigungsfehler | Verwenden Sie ein API-Token für die vorgesehene Organisation mit `logs.write`. |
| Aktion oder Dokument ist kein JSON-Objekt | Prüfen Sie die NDJSON-Zeilengrenzen. Senden Sie kein JSON-Array und kein mehrzeilig formatiertes Objekt. |
| Unbekannte Aktion | Verwenden Sie die oben aufgeführten unterstützten Aktionsnamen. |
| Dekomprimierungsfehler | Setzen Sie `Content-Encoding: gzip` nur, wenn der Body tatsächlich komprimiert ist. |
| Erfolg mit weniger Ereignissen als erwartet | Prüfen Sie, ob jede Schreibaktion ihre Dokumentzeile hat, und unterscheiden Sie übersprungene Deletes von gespeicherten Ereignissen. |
| `errors: true` mit Einträgen vom Status `400` | Ein Wert passt nicht zum Typ seines Felds im Stream, etwa Text in einem `int64`-Feld; die `reason` des Eintrags nennt das Feld. Senden Sie den Typ, den der Stream dafür speichert, oder konvertieren Sie den Wert in einer Pipeline. |
