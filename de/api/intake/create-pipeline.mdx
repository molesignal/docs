```http
POST /api/v1/scheduled_pipelines
```

Erstellt eine Pipeline. Der Pfad behält in jedem Modus den Namen `scheduled_pipelines`. Der Aufruf erfordert `pipelines.create`.

**Anfragetext**

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `name` | string | Ja | Name der Pipeline. |
| `sourceStream` | string | Ja | Erster Stream, den die Pipeline liest. Bei einer Alarm-Pipeline eine leere Zeichenfolge. |
| `targetStream` | string | Ja | Erster Stream, in den die Pipeline schreibt. Bei einer geplanten Pipeline führt ein Stream, den die Pipeline liest, zu `409`. Bei einer Alarm-Pipeline eine leere Zeichenfolge. |
| `functionSteps` | object | Ja | Schritte, Modus und Einstellungen einer geplanten Pipeline oder Bedingungen einer Alarm-Pipeline. Siehe unten. |
| `cron` | string | Ja | `every:30s`, `every:5m` oder `every:1h` für eine geplante Pipeline. Bei einer Echtzeit- oder Alarm-Pipeline eine leere Zeichenfolge. |
| `lookbackSecs` | integer | Nein | Anzahl der Sekunden, die der erste geplante Lauf für eine Quelle zurückliest. Standard: 300. Eine geplante Pipeline benötigt einen positiven Wert. |
| `enabled` | boolean | Nein | Standard: `true`. |

Felder von `functionSteps`:

| Feld | Hinweise |
|---|---|
| `mode` | `scheduled` (Standard), `realtime` oder `alert`. |
| `signalType` | `logs`, `metrics` oder `traces`, bei einer Echtzeit-Pipeline auch `profiles`. Eine Echtzeit-Pipeline für Metriken, Traces oder Profile ändert ihren Stream direkt: `targetStream` entspricht `sourceStream`. Die Pipeline hat weder einen Routing-Schritt noch `retainSource`. Siehe [Metriken und Traces](/de/pipelines#metriken-und-traces). Eine Pipeline für Profile verwendet `default` als Quelle. Siehe [Profile](/de/pipelines#profile). Eine Alarm-Pipeline hat keinen Signaltyp. |
| `steps` | Schritte in Ausführungsreihenfolge. Ein VRL-Schritt hat `transformName`, `script` und `kind` mit dem Wert `vrl`. Ein Routing-Schritt hat `kind` mit dem Wert `builtin`, `operation` mit dem Wert `route` und ein `routing`-Objekt. Eine Alarm-Pipeline unterstützt bis zu 20 Schritte und keinen Routing-Schritt. Ein KI-Zusammenfassungsschritt hat `transformName`, `kind` mit dem Wert `ai_summary`, `prompt` und `annotation`. Die Antwort landet in der unter `annotation` angegebenen Annotation (Standard: `ai_summary`). Ein API-Aufrufschritt hat `kind` mit dem Wert `http_enrich` und `connectorId`, die ID eines HTTP-Connectors der Organisation. Ein Abfrageschritt hat `kind` mit dem Wert `query_enrich`, `language` (`sql` als Standard oder `promql`), `stream`, `streamType` (`logs` als Standard, `metrics` oder `traces`), `statement`, `windowSecs` (Standard: 300, höchstens 86400), `maxRows` (Standard: 5, höchstens 50) und `annotation` (Standard: `query_result`). Siehe [Schritte von Alarm-Pipelines](/de/pipelines/alert-events#schritte). Eine Echtzeit-Pipeline unterstützt auch die Zählschritte `generate_metric`, `quota` und `throttle` mit den unten aufgeführten Feldern. |
| `alert` | Nur für Alarm-Pipelines. Legt den Ausführungszeitpunkt, die Bedingungen und die Reihenfolge fest: `stage` (`open` als Standard oder `notify`), `policies` (die Benachrichtigungsrichtlinien, für die eine `notify`-Pipeline gilt; leer: alle Richtlinien eines Alarmereignisses), `sources` (`rule`, `external`, `synthetic`, `noData` und bei `notify` auch `manual`), `severities` (`info`, `warning`, `error`, `critical`), `labels` (ein Objekt mit Labels, die das Ereignis mit den angegebenen Werten haben muss) und `order` (Ganzzahl, Standard: 0). Eine leere Liste schränkt die Quellen bzw. Schweregrade nicht ein. Siehe [Alarm-Pipelines](/de/pipelines/alert-events#alarm-pipeline-über-die-api-erstellen). |
| `sources` | Streams, aus denen die Pipeline liest. Die Pipeline liest `sourceStream` zuerst. Eine geplante Pipeline liest auch alle weiteren Streams in der Liste, insgesamt bis zu 8. Eine Echtzeit-Pipeline akzeptiert nur `[source_stream]`. |
| `sinks` | Streams, in die die Pipeline schreibt. `targetStream` steht an erster Stelle. Jeder weitere Stream in der Liste erhält ebenfalls alle Ereignisse. Insgesamt sind bis zu 8 Streams möglich. Eine Echtzeit-Pipeline akzeptiert nur `[target_stream]`. |
| `sinkConnectors` | Nur für geplante Pipelines. IDs der Connectors, die jedes Ereignis erhalten. |
| `sinkTables` | Nur für geplante Pipelines. Namen von bis zu 8 Erweiterungstabellen, die für jedes Ereignis eine Zeile erhalten. Siehe [In eine Erweiterungstabelle schreiben](/de/pipelines#in-eine-erweiterungstabelle-schreiben). |
| `delaySecs` | Nur für geplante Pipelines. Wartezeit in Sekunden für verspätete Ereignisse, bevor ein Lauf das jüngste Zeitfenster liest. 0 bis 3600, Standard: 60. |
| `retry` | Nur für geplante Pipelines. `runRetries` gibt die Anzahl weiterer Versuche für ein Zeitfenster an, wenn das Lesen oder Schreiben fehlgeschlagen ist. `deliveryRetries` gibt die Anzahl weiterer Zustellversuche an einen Connector an. Jeweils 0 bis 10, Standard: 3. |
| `deadLetterStream` | Nur für geplante Pipelines. Log-Stream für Ereignisse, die die Pipeline nicht verarbeiten, schreiben oder zustellen konnte. Die Pipeline darf diesen Stream weder als Quelle noch als Ziel verwenden. |
| `dedupeField` | Nur für geplante Pipelines. Die Pipeline verwirft ein Ereignis, wenn der Wert dieses Felds im selben Lauf bereits vorkam. |
| `retainSource` | Nur für Logs im Echtzeitmodus. Behält das ursprüngliche Ereignis im Quellstream bei. |

Felder der Zählschritte zusätzlich zu `transformName` und `kind`. Die Namen dieser Schritte müssen innerhalb einer Pipeline eindeutig sein. Siehe [Zählen und begrenzen](/de/pipelines#zählen-und-begrenzen).

| Feld | Hinweise |
|---|---|
| `conditions` | Ereignisse, auf die der Schritt angewendet wird: bis zu 16 Prüfungen, die alle zutreffen müssen. Jede Prüfung umfasst `field`, `test` (`equals`, `not_equals`, `contains`, `starts_with`, `matches`, `exists`, `missing`, `gt`, `gte`, `lt` oder `lte`) und `value`. `gt`, `gte`, `lt` und `lte` vergleichen mit einer Zahl, `matches` mit einem regulären Ausdruck. Leer: alle Ereignisse. |
| `metric` | Nur für `generate_metric`. `name`, `type` (`count`, `gauge` oder `histogram`), `field` (für `gauge` und `histogram` erforderlich; `count` summiert die Feldwerte, wenn das Feld angegeben ist), `groupBy` (bis zu 10 Felder), `buckets` (1 bis 30 aufsteigende Obergrenzen für ein Histogramm), `stream` (der Metrik-Stream) und `intervalSecs` (`10`, `30`, `60` als Standard oder `300`). Nur für Pipelines für Logs, RUM und Traces. |
| `quota` | Nur für `quota`. `unit` (`events` oder `bytes`), `limit` (Tageslimit in dieser Einheit, 1 bis 10^15), `partitionBy` (bis zu 5 Felder), `overrides` (bis zu 100 Einträge der Form `{"values": {"<field>": "<value>"}, "limit": <n>}`, mit einem Wert für jedes Feld in `partitionBy`), `action` (`drop` als Standard, `pass` oder `route`) und `target` (der Log-Stream für `route`). Nur für Log-Pipelines sowie für RUM-Streams außer `rum_views` und `rum_vitals`. Bei RUM-Streams ist `route` nicht verfügbar. |
| `throttle` | Nur für `throttle`. `limit` (Ereignisse pro Zeitfenster, 1 bis 1.000.000), `windowSecs` (1 bis 86.400), `groupBy` (bis zu 5 Felder), `action` (`drop` als Standard oder `route`) und `target`. Unterstützt dieselben Pipelines wie `quota`. |

```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines \

  -H 'content-type: application/json' \
  -d '{
    "name": "normalize-app",
    "sourceStream": "app_raw",
    "targetStream": "app",

      "signalType": "logs",
      "sources": ["app_raw", "nginx_raw"],

          "script": ".level = downcase!(string!(.level))" }
      ]
    },
    "cron": "every:5m",
    "lookbackSecs": 300,
    "enabled": true
  }'
```

**Fehler**

| Status | Ursache |
|---|---|
| `400` | Ein Zeitplan, der nicht dem Format `every:Ns/m/h` entspricht, ein Rückblickwert kleiner oder gleich null, eine geplante Pipeline für Profile, eine Pipeline für Profile mit einem anderen Stream als `default`, eine Echtzeit-Pipeline für Metriken, Traces, Profile oder RUM, die in einen anderen Stream schreibt, Ereignisse weiterleitet oder die Originalereignisse im Quellstream beibehält, ein Schritt einer solchen Pipeline, der ein [beibehaltenes Feld](/de/pipelines#metriken-und-traces) eines Messpunkts ändert, ein Schritt, der Ereignisse in `rum_views` oder `rum_vitals` verwerfen kann, ein VRL-Schritt, der sich nicht kompilieren lässt, ein ungültiger Stream-Name, mehr als 8 Quellstreams, Zielstreams oder Erweiterungstabellen, ein Routing-Schritt mit einem Quellstream als festem Ziel oder Ausweichziel, ein Dead-Letter-Stream, den die Pipeline liest oder beschreibt, ein [RUM-Stream](/de/pipelines#rum-streams) als Schreib- oder Routing-Ziel, `rum_sessions` als Quelle einer Echtzeit-Pipeline, ein [Plattform-Stream](/de/pipelines#plattform-streams) als Schreib- oder Routing-Ziel oder als Stream, den die Pipeline in Echtzeit ändert, oder ein Wert für `delaySecs` oder die Anzahl der Wiederholungsversuche außerhalb des zulässigen Bereichs. Bei Alarm-Pipelines: eine unbekannte Quelle oder ein unbekannter Schweregrad, ein Routing-Schritt, ein KI-Zusammenfassungsschritt ohne Prompt, ein API-Aufrufschritt, dessen Connector kein HTTP-Connector der Organisation ist, ein Abfrageschritt, der keine einzelne Abfrage enthält, `_audit` liest oder einen Platzhalter außerhalb einer Zeichenfolge oder einen Platzhalter für einen im Ereignis fehlenden Wert enthält, eine `notify`-Pipeline mit einem Schritt außerhalb von MoleSignal, eine `open`-Pipeline mit `policies` oder der Quelle `manual` oder mehr als 20 Schritte. Der Fehler tritt auch auf, wenn ein Schritt vom Typ `generate_metric`, `quota` oder `throttle` in einer geplanten Pipeline oder einer Alarm-Pipeline vorkommt, nicht unterstützte Daten verarbeitet oder denselben Namen wie ein anderer solcher Schritt hat. Auch unzulässige Einstellungen führen zu diesem Fehler, etwa ein Metrikname, den PromQL nicht auswählen kann, ein Label, das jeder Metrikmesspunkt bereits hat (`value`, `le`, `metric_name`…), oder der Quellstream als `target`. |
| `403` | Die Pipeline liest `_audit`, und dem Token fehlt `audit.read` oder das Token gehört zu einem Dienstkonto. |
| `409` | Eine geplante Pipeline würde in einen Stream schreiben, den sie liest, oder für denselben Datentyp und Quellstream ist bereits eine andere Echtzeit-Pipeline aktiviert (`a realtime pipeline is already enabled for this <signal> stream`). |

Informationen zum Echtzeitmodus, zu Routing-Schritten, Lesepositionen und Wiederholungsversuchen finden Sie unter [Pipelines](/de/pipelines).
