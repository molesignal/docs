```http
POST /api/v1/_cloudflare
```

Der Endpunkt akzeptiert NDJSON, auch mit dem gzip-komprimierten Request-Body, den Cloudflare Logpush üblicherweise sendet. Der Endpunkt verwendet kein Bearer-Token. Erstellen Sie einen Konnektor vom Typ `cloudflare_logpush` mit einem `pushToken` von mindestens 16 Zeichen und einem `target_stream`. Senden Sie das Token im Header `X-Connector-Token`. Alternativ können Sie den Abfrageparameter `?token=` verwenden. Bei einem falschen Token antwortet der Endpunkt mit `401`.

Jede Zeile wird zu einem Log-Ereignis im `target_stream` (Standard: `cloudflare`). Der Endpunkt speichert die Felder der Zeile unverändert und verwendet den Empfangszeitpunkt als Ereigniszeitpunkt. Bei Erfolg antwortet der Endpunkt mit `204`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_cloudflare \
  -H 'X-Connector-Token: <pushToken>' \
  -H 'content-encoding: gzip' \
  --data-binary @logs.ndjson.gz
```
</RequestExample>

Eine Anleitung zur Einrichtung finden Sie unter [Konnektoren](/de/connectors).

## Zustellung und Stream-Auswahl prüfen

1. Prüfen Sie, ob der Konnektor aktiviert ist und der Absender das Push-Token des Konnektors verwendet. Ein reguläres API-Token ersetzt kein Push-Token.
2. Wenn Sie `configJson` direkt über die Konnektor-API setzen, verwenden Sie für den Ziel-Stream `target_stream`, nicht `targetStream`. Der Token-Schlüssel bleibt `pushToken` in CamelCase.
3. Senden Sie ein Testereignis mit einer eindeutigen Kennung und notieren Sie den Empfangszeitpunkt. Wählen Sie unter **Logs** den vorgesehenen Stream und ein Zeitfenster aus, das den Empfangszeitpunkt einschließt. Suchen Sie dann nach der Kennung.
4. Wenn die Anfrage erfolgreich ist, der vorgesehene Stream aber leer bleibt, prüfen Sie den zugehörigen Standard-Stream und das gespeicherte Zielfeld. Eine HTTP-Bestätigung ersetzt keine Abfrage im vorgesehenen Ziel-Stream.

Schützen Sie das Token wie andere Zugangsdaten. Wenn Sie das Token als URL-Abfrageparameter übergeben, halten Sie die vollständige URL aus Logs, Tickets und Screenshots heraus. Bevor Sie eine fehlgeschlagene Anfrage wiederholen, prüfen Sie, ob der Fehler am Token oder am Status des Konnektors liegt oder ob das Format oder die Komprimierung der Nutzdaten fehlerhaft ist.
