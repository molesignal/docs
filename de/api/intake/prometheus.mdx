```http
POST /api/v1/prometheus/api/v1/write
```

Akzeptiert `remote_write`-Anfragen der Version 1 von Prometheus und VictoriaMetrics im Format Protobuf mit Snappy-Komprimierung. Der Aufruf erfordert `metrics.write` und antwortet bei Erfolg mit `204`.

Der Endpunkt schreibt die Anfrage in den Metrikstream, den der Header `stream-name` angibt. Fehlt der Header, verwendet er `default`. Ein Metrikstream enthält die Metriken einer Quelle. Das Label `__name__` wird zum Feld `metric_name`, die übrigen Labels werden zu Feldern und der Messwert wird zum Feld `value`. Hat ein Label denselben Namen wie ein Metrikfeld, etwa `metric_name` oder `metric_kind`, behält der Endpunkt es als `exported_<name>` bei. Der Endpunkt überspringt native Histogramme und Metrikmetadaten und speichert Exemplare neben den Messwerten.

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

Fragen Sie Metriken in PromQL anhand ihrer Namen ab, unabhängig davon, in welchem Stream sie liegen. Eine Zeitreihe für `http_requests_total` mit den Labels `service` und `status` sieht so aus:

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**Limits** gelten pro Zeitreihe und pro Organisation: maximal 64 Labels pro Zeitreihe, bis zu 128 Bytes pro Labelname, bis zu 2048 Bytes pro Labelwert sowie Kardinalitätslimits für aktive und neue Zeitreihen. Die Limits pro Prozess stehen unter `[intake.prometheus]` in der [Konfiguration](/de/configuration#datenaufnahme). Die Plattformeinstellung **Einstellungen → Metrikkardinalität** begrenzt die Anzahl aktiver Zeitreihen pro Organisation und pro Metrik. Lesen Sie die Limits mit `GET /api/v1/settings/series_limits` aus und legen Sie sie mit `PUT` fest. Verwenden Sie für `PUT` denselben Body, den `GET` liefert: `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }`. Beide Aufrufe erfordern `sys.settings.limits.manage` im Systembereich. Das Limit pro Metrik darf das Limit pro Organisation nicht überschreiten. Beide Limits betragen höchstens 100.000.000.
