```http
POST /api/v1/prometheus/api/v1/write
```

Akzeptiert `remote_write`-Anfragen der Version 1 von Prometheus und VictoriaMetrics, bei denen es sich um snappy-komprimierte Protobuf-Daten handelt. Der Aufruf erfordert `metrics.write` und antwortet bei Erfolg mit `204`. Wenn der Stream einige Samples ablehnt, weil ein Wert nicht zum Typ seines Felds passt, werden die anderen Samples geschrieben und die Antwort lautet `400`, mit der Anzahl der abgelehnten Samples und dem ersten Grund. Prometheus wiederholt eine `400`-Antwort nicht.

Eine Anfrage wird in den Metrik-Stream geschrieben, der durch den Header `stream-name` benannt wird, bzw. in `default`, wenn der Header fehlt. Ein Metrik-Stream enthält die Metriken einer Quelle. Das Label `__name__` wird zum Feld `metric_name`, die übrigen Labels werden zu Feldern und das Sample wird zum Feld `value`. Ein Label, das wie ein Metrikfeld heißt, etwa `metric_name` oder `metric_kind`, wird als `exported_<name>` beibehalten. Native Histogramme und Metrikmetadaten werden übersprungen, und Exemplare werden neben den Samples gespeichert.

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

Fragen Sie die Metriken mit PromQL anhand ihrer Namen ab, unabhängig davon, welcher Stream sie enthält. Aus einer Serie von `http_requests_total` mit den Labels `service` und `status` wird:

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**Limits** gelten pro Serie und pro Organisation: höchstens 64 Labels pro Serie, Labelnamen bis 128 Bytes, Labelwerte bis 2048 Bytes und Kardinalitätslimits für aktive und neue Serien. Die Prozesslimits stehen in `[intake.prometheus]` unter [Konfiguration](/de/configuration#datenaufnahme). Die aktiven Serien einer Organisation und einer ihrer Metriken werden durch die Plattform-Einstellung **Einstellungen → Metrikkardinalität** begrenzt; diese wird mit `GET /api/v1/settings/series_limits` gelesen und mit `PUT` und demselben Body `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }` gesetzt, beides mit `sys.settings.limits.manage` im System-Scope. Das Metriklimit ist höchstens so groß wie das Organisationslimit, und beide betragen höchstens 100.000.000.
