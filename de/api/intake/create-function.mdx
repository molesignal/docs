```http
POST /api/v1/functions
```

Erstellt eine wiederverwendbare Transformation für Pipelines. Der Aufruf kompiliert VRL und JavaScript beim Erstellen der Funktion und weist Funktionen mit ungültigem Quellcode zurück. Die Binärdatei enthält beide Laufzeitumgebungen. Der Aufruf erfordert `functions.create`.

**Anfragetext**

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `name` | string | Ja | Name der Funktion. |
| `language` | string | Ja | `vrl`, `js` oder `llm`. Eine `llm`-Funktion benötigt `[functions].llm_eval_enabled` und einen Modellanbieter. |
| `source` | string | Ja | Der VRL- oder JavaScript-Quellcode oder die Anweisung für eine `llm`-Funktion. |
| `paramsSchema` | object | Nein | Parameter. Bei `llm` legt `outputField` das Ausgabefeld fest. Der Standardwert ist `_llm_eval`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/functions \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "lowercase-level",
    "language": "vrl",
    "source": ".level = downcase!(string!(.level))"
  }'
```
</RequestExample>

Bei einem Syntaxfehler gibt der Endpunkt `400` zurück, zum Beispiel mit `js syntax error: Uncaught SyntaxError: Unexpected token '}'`. Testen Sie den Quellcode vor dem Speichern mit `POST /api/v1/functions/run`. Der Endpunkt nimmt `language`, `source` und eine Beispieleingabe in `input` entgegen und gibt `output` zurück. Siehe [Funktionen](/de/functions).

Weitere Endpunkte für Funktionen: `GET /api/v1/functions` sowie `GET`, `PUT` und `DELETE` für `/api/v1/functions/{id}`. Die integrierten Vorlagen sind schreibgeschützt.

## Transformation vor dem Speichern testen

Der Endpunkt für den Testlauf erfordert `functions.run`, unabhängig von `functions.create`. Verwenden Sie repräsentative Eingabedaten mit fehlenden und fehlerhaft formatierten Feldern, bevor Sie die Transformation in die laufende Datenerfassung einbinden.

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".level = downcase!(string!(.level))","input":{"level":"ERROR","message":"example"}}'
```

Prüfen Sie für diese Eingabe, ob `output.level` den Wert `error` hat, das von der Transformation nicht betroffene Feld `message` unverändert bleibt und `dropped` den Wert `false` hat. Eine erfolgreiche Kompilierung garantiert nicht, dass jedes Ereignis im Produktivbetrieb die Voraussetzungen der Transformation erfüllt. Die obige Konvertierung in einen String kann beispielsweise fehlschlagen und setzt voraus, dass `level` bereits ein String ist.

## Funktion mit einer Pipeline verbinden

Beim Erstellen einer Funktion speichert MoleSignal eine wiederverwendbare Definition. Eingehende Ereignisse bleiben dadurch unverändert. Speichern Sie die zurückgegebene Funktions-ID, fügen Sie den gewünschten Funktionsschritt unter [Pipelines](/de/pipelines) hinzu und testen Sie die gesamte Pipeline, bevor Sie die Pipeline für einen produktiven Stream aktivieren.

Halten Sie zusammen mit der Änderung eine repräsentative Eingabe und die erwartete Ausgabe fest. Speisen Sie nach der Aktivierung der Pipeline ein gezieltes Testereignis ein und fragen Sie den Zielstream ab, um die gespeicherten Felder zu prüfen. Die Antwort eines Testlaufs allein bestätigt nicht, dass die Datenerfassung im Produktivbetrieb wie erwartet funktioniert.

## Häufige Fehler

| Symptom | Maßnahme |
|---|---|
| Leerer Funktionsname | Geben Sie für `name` einen nicht leeren Wert an. |
| Endpunkt weist Quellcode beim Erstellen zurück | Beheben Sie Syntax- oder Kompilierungsfehler, bevor Sie es erneut versuchen. |
| Endpunkt verweigert den Testlauf | Prüfen Sie `functions.run`. Zum Erstellen ist eine separate Berechtigung erforderlich. |
| Eingabe verursacht einen Laufzeitfehler | Stellen Sie die Feldstruktur, die den Fehler auslöst, in einem Testlauf nach und behandeln Sie fehlende Felder oder Felder mit abweichenden Datentypen. |
| Gespeicherte Funktion wirkt sich nicht auf neue Logs aus | Prüfen Sie, ob die Funktion in die Pipeline eingebunden ist und der Zielstream stimmt. |
