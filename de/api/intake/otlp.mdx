Richten Sie ein OpenTelemetry SDK oder einen OpenTelemetry Collector auf MoleSignal aus. Beide Transportwege erfordern ein Bearer-Token mit der Schreibberechtigung für den jeweiligen Signaltyp: `logs.write`, `metrics.write` oder `traces.write`.

| Transport | Endpunkt |
|---|---|
| OTLP über HTTP | `POST /api/v1/logs`, `POST /api/v1/metrics`, `POST /api/v1/traces` |
| OTLP über gRPC | `:4317` |

Port `5082` ist der vertrauenswürdige interne Cluster-Port und dient nicht als OTLP-Empfänger.

## OTLP über HTTP

Setzen Sie den Endpunkt des Exporters auf den Basispfad `/api`. Exporter hängen `/v1/logs`, `/v1/metrics` und `/v1/traces` automatisch an.

| Header | Hinweise |
|---|---|
| `Authorization` | `Bearer <token>`. |
| `Content-Type` | `application/x-protobuf` oder `application/json`. Die JSON-Kodierung schreibt 64-Bit-Ganzzahlen als Zeichenfolgen. MoleSignal liest sowohl Zeichenfolgen als auch Zahlen. |
| `stream-name` | Optional. Gibt den Zielstream an. Der Standardwert ist `default`. |

Deaktivieren Sie die Komprimierung im Exporter. Bei einem komprimierten Anfragekörper antwortet MoleSignal mit `400`. Der Anfragekörper darf höchstens 2 MiB groß sein. Bei einer erfolgreichen Anfrage antwortet MoleSignal mit `200` und `{"partialSuccess":null}`.

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP über gRPC

Der Empfänger auf `:4317` stellt die Dienste für Logs, Metriken, Traces und Profile ohne TLS bereit. Senden Sie `authorization: Bearer <token>` und optional `stream-name` als gRPC-Metadaten. Terminieren Sie TLS vor dem Port, wenn der Datenverkehr ein vertrauenswürdiges Netzwerk verlässt.

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## Gespeicherte Felder

Ressourcen- und Datensatzattribute werden als Felder auf oberster Ebene gespeichert und behalten ihre ursprünglichen Schlüssel. Unter [Gespeicherte Felder](/de/query#gespeicherte-felder) finden Sie die Spalten für Logs, Spans und Metriken.

## Fehler

| Status | Ursache |
|---|---|
| `400` | Der Anfragekörper ist komprimiert oder enthält keine gültigen OTLP-Daten. |
| `401` | Das Token fehlt oder ist ungültig. |
| `403` | Dem Token fehlt die Schreibberechtigung für den Signaltyp oder das Ziel ist ein [Plattformstream](/de/streams#plattform-streams). |
| `404` | Im Endpunkt des Exporters fehlt `/api`. Die Anfrage landet daher bei `/v1/logs`. |
| `413` | Der Anfragekörper ist größer als 2 MiB. |

Wenn MoleSignal eine Anfrage über HTTP mit `403` ablehnt, antwortet es über gRPC mit `PERMISSION_DENIED`.
