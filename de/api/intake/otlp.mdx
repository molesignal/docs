Richten Sie ein OpenTelemetry SDK oder einen Collector auf MoleSignal aus. Beide Transporte erfordern Bearer-Anmeldedaten mit der Schreibberechtigung des Signals: `logs.write`, `metrics.write` oder `traces.write`.

| Transport | Endpoint |
|---|---|
| OTLP über HTTP | `POST /api/v1/logs`, `POST /api/v1/metrics`, `POST /api/v1/traces` |
| OTLP über gRPC | `:4317` |

Port `5082` ist der vertrauenswürdige interne Cluster-Port und kein OTLP-Empfänger.

## OTLP über HTTP

Legen Sie den Exporter-Endpunkt auf den Basispfad `/api` fest. Exporter hängen `/v1/logs`, `/v1/metrics` und `/v1/traces` selbst an.

| Header | Hinweise |
|---|---|
| `Authorization` | `Bearer <token>`. |
| `Content-Type` | `application/x-protobuf` oder `application/json`. Die JSON-Kodierung schreibt 64-Bit-Ganzzahlen als Strings, und MoleSignal liest Strings und Zahlen gleichermaßen. |
| `stream-name` | Optional. Der Ziel-Stream. Der Standardwert ist `default`. |

Der Body darf nicht komprimiert sein: Ein komprimierter Body wird mit `400` beantwortet. Deaktivieren Sie die Komprimierung im Exporter. Das Body-Limit beträgt 2 MiB. Eine erfolgreiche Anfrage wird mit `200` und `{"partialSuccess":null}` beantwortet. Wenn der Stream einige Log-Datensätze oder Datenpunkte ablehnt, weil ein Wert nicht zum Typ seines Felds passt, werden die übrigen geschrieben und `partialSuccess` enthält `rejectedLogRecords` oder `rejectedDataPoints` mit einer `errorMessage`, die den ersten Grund angibt. Exporter wiederholen sie nicht. Über gRPC kommt dieselbe Antwort.

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP über gRPC

Der Empfänger auf `:4317` stellt die Dienste für Logs, Metriken, Traces und Profile ohne TLS bereit. Senden Sie `authorization: Bearer <token>` und den optionalen `stream-name` als gRPC-Metadaten. Terminieren Sie TLS vor dem Port für Datenverkehr, der ein vertrauenswürdiges Netzwerk verlässt.

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## Gespeicherte Felder

Ressourcen- und Datensatzattribute werden zu Feldern auf oberster Ebene mit ihren ursprünglichen Schlüsseln. Unter [Gespeicherte Felder](/de/query#gespeicherte-felder) finden Sie die Spalten von Logs, Spans und Metriken.

## Fehler

| Status | Ursache |
|---|---|
| `400` | Ein komprimierter Body oder ein Body, der kein gültiges OTLP ist. |
| `401` | Fehlendes oder ungültiges Token. |
| `403` | Dem Token fehlt die Schreibberechtigung des Signals, oder die Daten werden an einen [Plattform-Stream](/de/streams#plattform-streams) gesendet. |
| `404` | Der Exporter-Endpunkt lässt `/api` weg, sodass die Anfrage `/v1/logs` erreicht. |
| `413` | Der Body überschreitet 2 MiB. |

Über gRPC wird eine Anfrage, die HTTP mit `403` ablehnt, mit `PERMISSION_DENIED` beantwortet.
