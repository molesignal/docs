All calls read one traces stream of the organization: the stream that has all of the fields `trace_id`, `span_id`, `service.name`, `name`, `start_time_unix_nano`, `end_time_unix_nano`, and `status_code`. A stream named `default` wins over other streams that qualify, and the stream name breaks the remaining ties. An organization without such a stream gets empty results. Only traces that survived [tail sampling](/de/configuration#trace-erfassung-und-tail-sampling) are readable.

All calls require `traces.read`, or `sys.telemetry.read` in the system scope.

## Trace-Zusammenfassungen auflisten

```http
GET /api/v1/web/traces
```

Liefert eine Zusammenfassung pro Trace, mit Cursor-Paginierung. Ein Stream, der noch keine Trace-Zusammenfassungen hat, antwortet mit einer leeren Seite.

**Abfrageparameter**

| Parameter | Typ | Hinweise |
|---|---|---|
| `from`, `to` | integer | Das Zeitfenster in Mikrosekunden. Standard sind die letzten 24 Stunden bis jetzt. `to` muss größer als `from` sein. |
| `q` | string | Text ohne Beachtung der Groß-/Kleinschreibung, der in der `trace_id`, der `span_id`, dem Service, der Operation oder dem Status eines Spans vorkommen muss. Bis zu 256 Zeichen. |
| `filters` | string | Ein JSON-Array von Filtern. Siehe unten. |
| `where` | string | Ein JSON-Bedingungsbaum: Filter und Text, verbunden durch AND und OR. Siehe unten. |
| `expression` | string | Eine Feldabfrage, wie sie die Seite **Traces** schreibt. Sie steht für `q`, `filters` und `where`: Senden Sie das eine oder das andere. Siehe unten. |
| `sort` | string | `latest` (Standard), `earliest`, `duration_desc`, `duration_asc`, `span_count_desc` oder `errors_desc`. |
| `limit` | integer | Seitengröße. Standard `20`. Der Wert wird auf 1 bis 5000 begrenzt. |
| `cursor` | string | Der `nextCursor` oder `previousCursor` einer früheren Seite. |
| `fields` | string | Felder des Root-Spans jedes Traces, die mitgeliefert werden, durch Kommas getrennt und so benannt, wie der Stream sie benennt. Bis zu 12. Ein unbekanntes Feld, ein JSON-Feld oder ein Feld `molesignal.trace.*` antwortet mit `400`. |

Ein Filter ist ein Objekt mit `field`, `op` und `value`, und eine Anfrage enthält höchstens 32 Filter. Alle Filter müssen passen. Der Operator `in` nimmt `values` entgegen, eine Liste von Werten, anstelle von `value`.

| Feld | Typ | Operatoren |
|---|---|---|
| `trace_id` | text | `=`, `!=`, `contains`, `in` |
| `duration_ns`, `span_count`, `error_count` | integer | `=`, `!=`, `>`, `>=`, `<`, `<=`, `in` |
| Jedes andere skalare Feld des Traces-Streams | nach Feldtyp | Text: `=`, `!=`, `contains`, `in`. Zahlen und Zeitstempel: `=`, `!=`, `>`, `>=`, `<`, `<=`, `in`. Booleans: `=`, `!=`, `in`. |

Ein Filter benennt sein Feld so, wie der Stream es benennt, etwa `service.name` oder `name`; kein anderer Name steht für ein Feld. Die Operatoren `eq`, `ne` und `like` sind Aliase von `=`, `!=` und `contains`. Ein JSON-Feld ist nicht filterbar.

`trace_id`, `duration_ns`, `span_count` und `error_count` werden auf dem Trace verglichen. Jedes andere Feld gehört zu einem Span: Ein Filter darauf passt auf einen Trace, wenn einer seiner Spans den Filter besteht, und `!=` passt auf einen Trace, wenn keiner seiner Spans den Wert hat. Ein Span ohne das Feld hat den Wert nicht.

`in` passt auf einen der `values`: 1 bis 64 Werte, jeder bis zu 512 Byte groß und vom Typ des Feldes. Ein doppelt aufgeführter Wert zählt einmal. Bei einem Span-Feld passt `in` auf einen Trace, wenn einer seiner Spans einen der Werte hat.

`where` sagt, was die Liste der Filter nicht kann: Alternativen. Es ist ein JSON-Objekt in einer von vier Formen:

| Form | Passt auf |
|---|---|
| Ein Filter wie in `filters` | Den Filter. |
| `{"text": "..."}` | Den Text, so wie `q` darauf passt. |
| `{"and": [...]}` | Jede Bedingung in der Liste. |
| `{"or": [...]}` | Eine beliebige Bedingung in der Liste. |

`filters`, `q` und `where` gelten gemeinsam. Ein Filter im Baum behält seine Bedeutung: Einer auf einem Span-Feld passt auf einen Trace, wenn einer seiner Spans ihn besteht, und `!=`, wenn keiner seiner Spans den Wert hat. Ein Trace passt auf `{"or": [A, B]}`, wenn er auf `A` oder auf `B` passt. Die Filter aus `filters` und `where` zählen zusammen auf das Limit von 32. Ein Baum sucht höchstens 8-mal nach Text, verschachtelt Gruppen höchstens 8 Ebenen tief und hat in jeder Gruppe mindestens eine Bedingung.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'filters=[{"field":"status_code","op":"=","value":"ERROR"}]' \
  --data-urlencode 'where={"or":[{"field":"service.name","op":"=","value":"checkout"},{"field":"span_count","op":">","value":"50"}]}'
```

Die Anfrage listet die fehlgeschlagenen Traces, die einen Span `checkout` oder mehr als 50 Spans haben.

`expression` nimmt stattdessen den Text der Seite **Traces**: Vergleiche mit `=`, `!=`, `>`, `>=`, `<`, `<=`, `contains` und `field in ('a', 'b')`, Wörter, die gefunden werden sollen, eine Phrase in Anführungszeichen, `AND` und `OR` in beliebiger Schreibweise, wobei `AND` stärker bindet, sowie Klammern. Der Server liest ihn in die `q`, `filters` und `where` ein, die die Seite sendet, und prüft sie wie oben. Der Text ist höchstens 8 KiB groß und verschachtelt Klammern höchstens 32 Ebenen tief. Einen Teil, den er nicht lesen kann, etwa eine nicht geschlossene Klammer oder einen Vergleich ohne Inhalt, beantwortet er mit `400` und nennt den Teil.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "expression=status_code = 'ERROR' AND (service.name = 'checkout' OR span_count > 50)"
```

Die Anfrage listet dieselben Traces wie die obige.

Ein `cursor` bindet die Seite an die Abfrage, die sie ausgestellt hat. Wird eine Anfrage mit einem Cursor und einem abweichenden `limit`, `sort`, `q`, `filters` oder `where` wiederholt, antwortet der Aufruf mit `400`.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'sort=duration_desc' \
  --data-urlencode 'limit=2' \
  --data-urlencode 'fields=http.route' \
  --data-urlencode 'filters=[{"field":"service.name","op":"in","values":["checkout","payments"]}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "service": "checkout",
      "operation": "GET /checkout",
      "startNs": 1790000000000000000,
      "durationMs": 180.0,
      "spanCount": 3,
      "errorCount": 1,
      "status": "ERROR",
      "httpStatusCode": 502,
      "fields": { "http.route": "/checkout" }
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

Jedes Element beschreibt einen Trace anhand seines Root-Spans: den `service` und die `operation` des Root-Spans, die Startzeit in Nanosekunden, die Dauer in Millisekunden, die Anzahl der Spans und die Anzahl der Fehler-Spans. `hasMore` ist `true`, wenn `nextCursor` gesetzt ist.

| Feld | Hinweise |
|---|---|
| `status` | Der Status des Root-Spans: `OK`, `ERROR` oder `UNSET`. |
| `httpStatusCode` | Der `http.response.status_code` des Root-Spans oder dessen `http.status_code`, wenn er einen Code von 100 bis 599 enthält. Sonst nicht vorhanden, ebenso bei Traces, die gespeichert wurden, bevor die Zusammenfassung ihn enthielt. |
| `fields` | Die in `fields` angefragten Felder, für die der Root-Span einen Wert hat. Nicht vorhanden, wenn er keinen hat. Die Seite wird ohne sie beantwortet, wenn das Lesen fehlschlägt. |

## Traces über die Zeit zählen

```http
GET /api/v1/web/traces/histogram
```

Zählt jeden Trace, auf den eine Listenabfrage passt, in Zeit-Buckets, nach der Startzeit des Traces. Der Aufruf übernimmt das Zeitfenster, `q`, `filters` und `where` der Liste und passt auf dieselben Traces. Der Aufrufer wählt die Buckets.

**Abfrageparameter**

| Parameter | Typ | Hinweise |
|---|---|---|
| `from`, `to` | integer | Das Zeitfenster in Mikrosekunden. Beide sind erforderlich. `to` muss größer als `from` sein. |
| `q`, `filters`, `where`, `expression` | string | Dasselbe wie für die Liste. |
| `bucketTime` | integer | Die Länge eines Buckets in Mikrosekunden. Mindestens `1000`. |
| `originTime` | integer | Der Beginn des ersten Buckets in Mikrosekunden. Nicht nach `from`. |

Eine Anfrage umfasst höchstens 512 Buckets von `originTime` bis `to`.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/histogram" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=900000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode 'filters=[{"field":"service.name","op":"=","value":"checkout"}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 900000000,
  "originTime": 1790000100000000,
  "buckets": [
    { "startTime": 1790000100000000, "total": 42, "errors": 3, "p50Ns": 41000000, "p95Ns": 180000000, "p99Ns": 320000000 },
    { "startTime": 1790001900000000, "total": 17, "errors": 0, "p50Ns": 38000000, "p95Ns": 95000000, "p99Ns": 120000000 }
  ],
  "split": true
}
```
</ResponseExample>

`buckets` listet nur die Buckets, die einen Trace enthalten, älteste zuerst. `total` ist die Anzahl der Traces, die im Bucket begonnen haben. `errors` ist die Anzahl derjenigen Traces mit mindestens einem Fehler-Span. `p50Ns`, `p95Ns` und `p99Ns` sind der Median sowie das 95. und 99. Perzentil der Dauer dieser Traces in Nanosekunden. Sie sind Schätzwerte und fehlen, wenn keine Dauer gezählt wurde.

Die Zählung liest die Trace-Zusammenfassungen und die Spans, wenn ein Filter auf einem Span-Feld liegt. Die Liste liefert eine Zusammenfassung für jeden Trace. Eine Zusammenfassung, die ein erneut versuchter Schreibvorgang doppelt gespeichert hat, zählt doppelt.

Ist die Zählung nicht verfügbar, antwortet der Aufruf trotzdem mit `200`. `buckets` ist dann leer, und `unavailable` nennt den Grund.

| `unavailable` | Ursache |
|---|---|
| `time_budget` | Die Zählung dauerte länger als 20 Sekunden. |
| `busy` | Die Abfragen der Rolle füllen [`[search.admission]`](/de/configuration#zulassungssteuerung), und innerhalb von `max_wait_secs` wurde kein Slot frei. |
| `scan_limit` | Das Zeitfenster enthält mehr Zeilen, als `[querier].max_scan_rows` eine Abfrage lesen lässt. |

## Request-Kennzahlen lesen

```http
GET /api/v1/web/traces/red
GET /api/v1/web/traces/red/breakdown
```

Liest Rate, Fehler und Dauer der Requests, die eine Listenabfrage entspricht: insgesamt, Bucket für Bucket und danach, wie lange sie gedauert haben. Die Aufschlüsselung liest dieselben Kennzahlen für jeden Wert eines Felds. Ein Request ist ein Span. Standardmäßig sind die Requests die Spans, in denen ein Service einen Request entgegengenommen hat: ein Server- oder Consumer-Span oder die Wurzel eines Traces. `scope=all` liest jeden Span.

Ein Filter auf ein Span-Feld gilt für den Span selbst, sodass `service.name = 'api'` die Requests liest, die `api` bedient hat. `trace_id` und `duration_ns` werden vom Span gelesen, `span_count` und `error_count` vom Trace, zu dem der Span gehört.

**Abfrageparameter**

| Parameter | Typ | Hinweise |
|---|---|---|
| `from`, `to`, `bucketTime`, `originTime` | integer | Dieselben wie für die Trace-Anzahl über die Zeit. |
| `q`, `filters`, `where`, `expression` | string | Dieselben wie für die Liste. |
| `scope` | string | `entry` (Standard) oder `all`. |
| `by` | string | Nur bei der Aufschlüsselung und dort erforderlich: das Feld, nach dem die Requests gruppiert werden, so wie der Stream es benennt. |

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/red" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=60000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode "expression=service.name = 'checkout'"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "scope": "entry",
  "total": { "requests": 1840, "errors": 12, "p50Ns": 41000000.0, "p95Ns": 180000000.0, "p99Ns": 320000000.0 },
  "buckets": [
    { "startTime": 1790000100000000, "requests": 31, "errors": 0, "p50Ns": 40000000.0, "p95Ns": 150000000.0, "p99Ns": 210000000.0 }
  ],
  "latency": [
    { "fromNs": 0, "toNs": 50000000, "requests": 1203, "errors": 2 },
    { "fromNs": 50000000, "toNs": null, "requests": 637, "errors": 10 }
  ]
}
```
</ResponseExample>

`buckets` listet die Buckets auf, die einen Request enthalten, älteste zuerst. `latency` listet die Requests nach Dauer auf, kürzeste zuerst; der letzte Bereich hat keine Obergrenze. `errors` ist `null`, wo sich Fehler nicht feststellen lassen, und die Dauern sind in Nanosekunden, `null` ohne Request und wo Dauern maskiert sind.

Die Aufschlüsselung liefert `field`, `bucketTime`, `originTime`, `scope` und `groups`: die 50 häufigsten Werte zuerst, jeder mit seinen Kennzahlen und einer `series` aus Buckets mit `requests`, `errors` und `p95Ns`. `value` ist `null` für die Requests ohne Wert. `more` ist `true`, wenn mehr Werte existieren, als aufgelistet sind.

Wenn die Kennzahlen nicht verfügbar sind, antworten die Aufrufe weiterhin mit `200` und `unavailable`: `time_budget`, `busy` und `scan_limit` wie bei der Trace-Anzahl, `timestamp_masked`, wenn die Zeit beim Lesen maskiert ist, und `field_protected`, wenn das Feld der Aufschlüsselung maskiert oder verschlüsselt ist.

`by` kann auch einen Schlüssel innerhalb eines JSON-Felds benennen, geschrieben nach dem Namen des Felds, etwa `attributes.tenant`: Die Requests werden nach dem gruppiert, was dieser Schlüssel enthält.

## Langsame oder fehlgeschlagene Requests vergleichen

```http
GET /api/v1/web/traces/red/compare
```

Vergleicht die ausgewählten Requests einer Abfrage mit ihren übrigen Requests, Feld für Feld: die fehlgeschlagenen Requests, die mindestens oder weniger als eine bestimmte Zeit gedauert haben oder die alle angegebenen Bedingungen erfüllen. Für jedes Feld wird der Anteil jedes Werts in den beiden Mengen verglichen, und die Felder werden danach sortiert, wie weit die Anteile auseinanderliegen, von `0` (dieselbe Zusammensetzung) bis `1` (kein gemeinsamer Wert). IDs, Zeitpunkte, Dauern und JSON-Felder bleiben ausgeschlossen, ebenso ein Feld, dessen Werte sich von Zeile zu Zeile fast alle unterscheiden. Wenn die fehlgeschlagenen Requests ausgewählt werden, bleibt `status_code` ebenfalls ausgeschlossen. Jede Menge wird als Stichprobe ihrer ersten 1.000 Spans gelesen.

**Abfrageparameter**

Die Parameter der RED-Kennzahlen, ohne `by`, und:

| Parameter | Typ | Hinweise |
|---|---|---|
| `errors` | boolean | Wählen Sie die fehlgeschlagenen Requests aus. |
| `minDuration` | integer | Wählen Sie die Requests aus, die mindestens diese Anzahl Nanosekunden gedauert haben. |
| `maxDuration` | integer | Wählen Sie die Requests aus, die weniger als diese Anzahl Nanosekunden gedauert haben. |

Mindestens einer davon ist erforderlich, und `minDuration` muss unter `maxDuration` liegen.

<ResponseExample>
```json 200
{
  "scope": "entry",
  "selected": 212,
  "baseline": 1000,
  "sampled": true,
  "dimensions": [
    {
      "field": "cloud.region",
      "score": 0.71,
      "values": [
        { "value": "eu-west-1", "selected": 0.83, "baseline": 0.12 },
        { "value": "us-east-1", "selected": 0.17, "baseline": 0.88 }
      ]
    }
  ]
}
```
</ResponseExample>

`selected` und `baseline` sind die aus jeder Menge gelesenen Spans, und `sampled` ist `true`, wenn eine der beiden Mengen mehr enthielt. `dimensions` listet höchstens 20 Felder auf, die am weitesten auseinanderliegenden zuerst, jedes mit höchstens 5 Werten, deren Anteile sich am stärksten unterscheiden. `value` ist `null` für die Requests ohne Wert. `unavailable` wird wie bei den RED-Kennzahlen zurückgegeben.

## Spans auflisten

```http
GET /api/v1/web/traces/spans
```

Gibt eine Zeile pro Span zurück, der einer Abfrage entspricht, mit Cursor-Paginierung. Der Aufruf übernimmt das Zeitfenster, `q`, `filters` und `where` der Trace-Liste und liest sie für jeden Span: Ein Filter auf ein Span-Feld gilt für den Span selbst, und `!=` behält einen Span ohne das Feld. `duration_ns` ist die eigene Dauer des Spans. `span_count` und `error_count` sind die des Traces, zu dem der Span gehört. Ein Span entspricht `{"or": [A, B]}`, wenn er `A` oder `B` entspricht.

**Abfrageparameter**

| Parameter | Typ | Hinweise |
|---|---|---|
| `from`, `to` | integer | Das Zeitfenster in Mikrosekunden. Die Standardwerte sind die letzten 24 Stunden bis jetzt. `to` muss größer als `from` sein. |
| `q`, `filters`, `where`, `expression` | string | Dieselben wie für die Trace-Liste. |
| `sort` | string | `latest` (Standard), `earliest`, `duration_desc` oder `duration_asc`. |
| `limit` | integer | Seitengröße. Standard `100`. Der Wert wird auf 1 bis 5000 begrenzt. |
| `cursor` | string | Der `nextCursor` oder `previousCursor` einer früheren Seite. Der Cursor trägt die Abfrage seiner Seite; ein anderes `limit` antwortet mit `400`. |

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "durationNs": 140000000,
      "status": "ERROR",
      "kind": 2,
      "httpStatusCode": 502
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

`status` ist `OK`, `ERROR` oder `UNSET`. `kind` nummeriert das Span-Kind wie bei OTLP: `1` internal, `2` server, `3` client, `4` producer, `5` consumer. `parent_span_id`, `kind` und `http_status_code` fehlen, wenn der Span sie nicht hat. Der Aufruf läuft als getrackte Abfrage und wird wie jede andere Abfrage zugelassen.

## Einen Trace lesen

```http
GET /api/v1/web/trace/{traceId}
```

Gibt jeden Span eines Traces zurück, sortiert nach Startzeit. `trace_id` hat 1 bis 128 Zeichen aus `A-Z`, `a-z`, `0-9`, `-` und `_`.

**Abfrageparameter**

| Parameter | Typ | Hinweise |
|---|---|---|
| `from`, `to` | integer | Das Zeitfenster in Mikrosekunden, in dem die Spans des Traces gestartet sind. Geben Sie beide oder keinen an. Höchstens 31 Tage. Ohne sie wird der Trace in den letzten 24 Stunden gesucht. |

Die Antwort ist auf 100.000 Spans und 32 MiB begrenzt. `truncated` ist `true`, wenn ein Limit die Span-Liste abgeschnitten hat.

<ResponseExample>
```json 200
{
  "traceId": "0af7651916cd43dd8448eb211c80319c",
  "rootSpanId": "b7ad6b7169203331",
  "spans": [
    {
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "endNs": 1790000000160000000,
      "durationNs": 140000000,
      "kind": 2,
      "status": "ERROR",
      "statusMessage": "upstream timeout",
      "attributes": { "http.method": "POST", "http.status_code": "502" },
      "events": [],
      "links": [],
      "samplingReason": "error",
      "partial": false,
      "late": false,
      "duplicate": false,
      "conflict": false
    }
  ],
  "truncated": false,
  "partial": false,
  "partialReasons": [],
  "samplingReasons": ["error"],
  "lateSpanCount": 0,
  "duplicateSpanCount": 0,
  "conflictSpanCount": 0
}
```
</ResponseExample>

Das Beispiel zeigt einen Span mit seinen Hauptfeldern. Ein echter Span trägt außerdem `traceFlags`, `traceState`, `resource`, `scope`, die Zähler `dropped_*_count`, `schemaVersion` und `semanticConventionsVersion`.

| Feld | Hinweise |
|---|---|
| `rootSpanId` | Der erste Span ohne Parent. Bauen Sie den Baum aus `span_id` und `parent_span_id` auf. |
| `spans[].status` | `OK`, `ERROR` oder `UNSET`. |
| `spans[].attributes` | Die Span-Attribute, zusammengeführt mit den abgeflachten Attributspalten des Streams. |
| `spans[].sampling_reason` | Warum der Tail-Sampler den Trace behalten hat, zum Beispiel `error`. |
| `partial`, `partialReasons` | Ob Spans fehlen und warum. |
| `lateSpanCount`, `duplicateSpanCount`, `conflictSpanCount` | Die Spans, die verspätet, doppelt oder im Konflikt ankamen. |

## Spans finden, die auf einen Trace verweisen

```http
GET /api/v1/web/trace/{traceId}/linked
```

Ein Span speichert Links zu den Spans, aus denen er hervorgeht, und die Trace-Detailansicht liefert sie mit dem Span zurück. Dieser Aufruf findet die andere Richtung: Spans anderer Traces, deren Links auf einen Span dieses Trace verweisen. Er verwendet dieselben `from` und `to` wie die Trace-Detailansicht und durchsucht dieses Zeitfenster.

<ResponseExample>
```json 200
{
  "spans": [
    {
      "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
      "spanId": "00f067aa0ba902b7",
      "service": "billing-worker",
      "operation": "process invoice",
      "startNs": 1790000005000000000,
      "durationNs": 30000000,
      "status": "OK",
      "linkedSpanId": "53995c3f42cd8ad8",
      "attributes": { "messaging.operation": "process" }
    }
  ],
  "more": false
}
```
</ResponseExample>

`spans` listet bis zu 200 verweisende Spans auf, neueste zuerst, und `more` ist `true`, wenn weitere Spans auf den Trace verweisen. `linkedSpanId` ist der Span dieses Trace, auf den der Link zeigt, und `attributes` enthält die Attribute des Links.

Die Suche liest die Links jedes Span im Zeitfenster als Text, innerhalb des Zeitbudgets der Trace-Zählung. Wenn sie nicht fertig wird, antwortet der Aufruf trotzdem mit `200`, mit leerem `spans` und einem `unavailable`-Grund: `time_budget`, `busy` oder `scan_limit`, wie bei der Trace-Zählung.

**Fehler**

| Status | Ursache |
|---|---|
| `400` | Ein Parameter ist ungültig: `to` ist nicht größer als `from`, ein Filter verwendet ein unbekanntes Feld oder einen unbekannten Operator (`unsupported trace filter field: nope`), ein `in`-Filter hat keine Werte oder mehr als 64, `where` ist kein Bedingungsbaum oder überschreitet seine Grenzen, `expression` kommt zusammen mit `q`, `filters` oder `where` oder enthält einen Teil, der nicht gelesen werden kann, der Cursor passt nicht zur Abfrage, ein Feld in `fields` ist unbekannt oder ein Dokument, oder die `trace_id` hat ungültige Zeichen oder eine ungültige Länge. Für die Zählung: das Zeitfenster oder ein Bucket-Parameter fehlt, `bucketTime` ist kleiner als `1000`, `originTime` liegt nach `from`, oder die Anfrage umfasst mehr als 512 Buckets. Für die Trace-Detailansicht und ihre verweisenden Spans: nur eines von `from` und `to` ist angegeben, oder das Zeitfenster ist länger als 31 Tage. |
| `403` | Dem Token fehlt `traces.read`. |
| `404` | Der Trace wird im Zeitfenster nicht gefunden oder wurde durch Sampling verworfen. |
