```http
GET    /api/v1/changes
POST   /api/v1/changes
GET    /api/v1/changes/{id}
PUT    /api/v1/changes/{id}
PATCH  /api/v1/changes/{id}
DELETE /api/v1/changes/{id}
```

Änderungen werden an einer Stelle geführt: Deployments, Konfigurationsänderungen, Feature Flags, Skalierung und
Infrastrukturänderungen, die Pipelines über
[`POST /api/v1/apm/deployments`](/de/apm/deployments#deployments-aus-der-ci-melden) melden, und Annotationen,
die auf einen Zeitraum gesetzt werden. `GET /api/v1/changes` listet sie mit den Versionen auf, die APM zuerst in Spans
gesehen hat, sowie mit den Änderungen an Alarmregeln. Die übrigen Aufrufe verwalten Annotationen.

## Änderungen auflisten

| Parameter | Hinweise |
|---|---|
| `from`, `to` | Der Zeitraum in Mikrosekunden. `to` ist standardmäßig jetzt, `from` ein Tag vor `to`. |
| `services` | Servicenamen, durch Kommas getrennt. Änderungen anderer Services werden ausgelassen; Änderungen ohne Service, etwa Annotationen und Regeländerungen, bleiben erhalten. |
| `namespace`, `environment` | Gemeldete Änderungen und Versionen dieses Namespace oder dieser Umgebung sowie gemeldete Änderungen, die keine Angabe dazu gemacht haben. |
| `kinds` | Durch Kommas getrennt: `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure`, `annotation`, `version`, `rule`. Ohne Angabe jede Art, die der Aufrufer lesen darf. |
| `dashboardId`, `stream` | Annotationen dieses Dashboards oder Log-Streams und Annotationen ohne Zuordnung. Annotationen eines anderen Dashboards oder Streams werden ausgelassen. |
| `limit` | Höchstens 500, das ist der Standardwert. |

Jede Art verlangt eine eigene Berechtigung; eine Art, die dem Aufrufer fehlt, wird ausgelassen statt abgelehnt:

| Arten | Berechtigung, eine von |
|---|---|
| `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure` | `apm.deployments.read`, `sys.telemetry.read` |
| `annotation` | `dashboards.annotations.read` |
| `version` | `apm.services.read`, `sys.telemetry.read` |
| `rule` | `alerts.rules.read` |

Die Antwort ist eine Liste, das Neueste zuerst. Eine von einer Pipeline gemeldete Version wird einmal aufgeführt, so wie gemeldet.

```json
[
  {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "kind": "deployment",
    "at": 1792316400000000,
    "service": "checkout",
    "namespace": "shop",
    "environment": "prod",
    "version": "2.0.0",
    "status": "succeeded",
    "commit": "9f2c1e7a4b3d5e6f",
    "author": "ada",
    "ciUrl": "https://ci.example.com/runs/7"
  },
  {
    "id": "3KEDP0aZ1y2b3c4d5e6f7g8h9i0",
    "kind": "annotation",
    "at": 1792312800000000,
    "end": 1792314600000000,
    "title": "Load test",
    "tags": ["test"],
    "dashboardId": "dash-1"
  }
]
```

| Feld | Hinweise |
|---|---|
| `at`, `end` | Wann es passiert ist; `end` schließt eine Annotation über einen Zeitraum ab. Mikrosekunden. |
| `service`, `namespace`, `environment`, `version` | Worauf sich eine gemeldete Änderung oder eine Version bezieht. |
| `status` | Wie eine gemeldete Änderung ausgegangen ist: `succeeded`, `failed` oder `rolled_back`. |
| `title`, `description`, `tags` | Titel einer Annotation oder einer Regel und was eine Änderung über sich selbst angegeben hat. |
| `commit`, `repositoryUrl`, `pullRequestUrl`, `author`, `ciUrl` | Woher eine gemeldete Änderung kam. |
| `dashboardId`, `stream` | Wozu eine Annotation gehört. |
| `ruleId` | Die Regel, auf die sich eine Änderung bezog. |

## Annotationen verwalten

`POST /api/v1/changes` erstellt eine Annotation und erfordert `dashboards.annotations.manage`:

```json
{
  "title": "Load test",
  "description": "k6, 2,000 users",
  "tags": ["test"],
  "timeStart": 1792312800000000,
  "timeEnd": 1792314600000000,
  "dashboardId": "dash-1",
  "streamName": null
}
```

`GET /api/v1/changes/{id}` liest eine Annotation mit `dashboards.annotations.read`. `PUT` und `PATCH`
ändern die genannten Felder, und `DELETE` entfernt sie, mit `dashboards.annotations.manage`. Diese Aufrufe
betreffen nur Annotationen; eine id, die keine Annotation der Organisation ist, antwortet mit `404`.
Mole Agent verwaltet Annotationen mit `create_annotation`, `update_annotation` und `delete_annotation` und
listet Änderungen mit `list_changes` auf.
