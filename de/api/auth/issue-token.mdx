```http
POST /api/v1/me/api-tokens
```

Stellt ein persönliches Token im Format `mspat-<36>` aus, das im Namen des angemeldeten Benutzers handelt. Das Token erscheint nur in dieser Antwort im Klartext. Speichern Sie es daher sofort. Der Aufruf erfordert eine angemeldete Sitzung und die Berechtigung `personal_tokens.manage`. Eine Authentifizierung mit einem anderen Token ist nicht möglich.

**Anfragetext**

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `name` | string | Ja | Anzeigename mit 1 bis 255 Zeichen. |
| `policyId` | string | Nein | ID einer [Berechtigungsrichtlinie](/de/identity/roles#berechtigungsrichtlinien), die für das Token gilt, z. B. `builtin:data_intake`. Sie müssen über alle Berechtigungen der Richtlinie verfügen. |
| `permissions` | string[] | Nein | Berechtigungen auf Organisationsebene, die für das Token festgelegt sind. Sie müssen über jede dieser Berechtigungen verfügen. |
| `expiresInDays` | integer | Nein | Gültigkeitsdauer in Tagen, von 1 bis 1825. Lassen Sie das Feld weg, wenn das Token nicht ablaufen soll. |

Geben Sie entweder `policyId` oder `permissions` an, aber nicht beides. Ohne diese Angaben darf das Token alles, wozu Sie berechtigt sind. Ein Token hat nie mehr Berechtigungen als Sie zum Zeitpunkt der Anfrage. Wenn Sie eine Berechtigung verlieren, verlieren auch Ihre Tokens diese Berechtigung.

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -X POST http://localhost:5080/api/v1/me/api-tokens \
  -H 'content-type: application/json' \
  -d '{
    "name": "grafana-readonly",
    "permissions": ["streams.read", "streams.query", "dashboards.read"],
    "expiresInDays": 90
  }'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KE5hOsEc3lMC9qr9RWnPn0pqWF",
  "prefix": "k7m2q9xv4b",
  "name": "grafana-readonly",
  "tokenKind": "personal",
  "userId": "<user-id>",
  "policyId": null,
  "permissions": ["dashboards.read", "streams.query", "streams.read"],
  "applicationId": null,
  "serviceAccountId": null,
  "expiresAt": 1798000000000000,
  "lastUsedAt": null,
  "revoked": false,
  "createdAt": 1790000000000000,
  "token": "mspat-k7m2q9xv4b<secret>"
}
```
</ResponseExample>

`ms-cookies.txt` enthält die Sitzung, die durch die [Anmeldung](/de/api/auth/login) gestartet wurde. `GET /api/v1/me/api-tokens/scopes` listet die Richtlinien und Berechtigungen auf Organisationsebene auf, auf die sich ein Token beschränken lässt. Senden Sie das Token im Header `Authorization`: `Authorization: Bearer mspat-…`.

## Für ein Dienstkonto

```http
POST /api/v1/auth/tokens
```

Stellt ein Token aus, das im Namen eines Dienstkontos handelt. Der Anfragetext ist bis auf das zusätzliche Feld `serviceAccountId` identisch. Der Aufruf erfordert `api_tokens.issue`. Anders als bei einem persönlichen Token können Sie für die Ausstellung ein API-Token verwenden. Ohne `policyId` und `permissions` erhält das Token nur die Berechtigungen der Dienstkontorolle, über die Sie zum Zeitpunkt der Ausstellung verfügen. Erhält die Rolle später eine Berechtigung, erhält das Token sie nicht. Verliert die Rolle eine Berechtigung, verliert das Token sie sofort.

```bash
curl -X POST http://localhost:5080/api/v1/auth/tokens \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "collector-production",
    "serviceAccountId": "<service-account-id>",
    "policyId": "builtin:data_intake",
    "expiresInDays": 365
  }'
```

**Fehler**

| Status | Ursache |
|---|---|
| `400` | Leerer `name`, gleichzeitige Angabe von `policyId` und `permissions`, leere Liste, unbekannte Berechtigung oder Richtlinie oder deaktiviertes Dienstkonto. |
| `403` | Der Berechtigungsumfang enthält eine Berechtigung, über die Sie nicht verfügen, die Anfrage für ein persönliches Token verwendet ein API-Token oder die erforderliche Berechtigung (`personal_tokens.manage` oder `api_tokens.issue`) fehlt. |
| `404` | Auf Systemebene gibt es keine API-Tokens oder das Dienstkonto existiert nicht. |
