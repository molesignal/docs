```http
GET /api/v1/auth/tokens/rum?applicationId=<id>
```

Gibt das RUM-Client-Token einer [RUM-Anwendung](/de/rum/applications) zurück und erstellt es beim ersten Aufruf. Die Anwendung muss bereits existieren. Erstellen Sie die Anwendung zuerst. Das Token hat das Format `mspat-<36>` und ist an die Anwendung gebunden, nicht an das Konto, das es abruft. Es gewährt ausschließlich `rum.write` für diese Anwendung, erlaubt keinen weiteren Zugriff und läuft nie ab. Betten Sie das Token in Browser- oder Mobilcode ein, in dem es für Endnutzer sichtbar ist. Der Aufruf erfordert `api_tokens.issue`.

**Abfrageparameter**

| Parameter | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `applicationId` | string | Ja | Die Kennung einer Anwendung im Arbeitsbereich. |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/auth/tokens/rum?applicationId=checkout-web" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KDZpGNwn5vO9dhXyE3am4qhihX",
  "prefix": "c16jb8m5zr",
  "token": "mspat-c16jb8m5zr<secret>",
  "tokenKind": "rum_client",
  "policyId": null,
  "permissions": ["rum.write"],
  "applicationId": "checkout-web",
  "createdAt": 1790000000000000
}
```
</ResponseExample>

Bei einer ungültigen Kennung in `applicationId` gibt die API `400` zurück. Ist die Kennung gültig, gehört aber zu keiner Anwendung, gibt die API `404` zurück. Verwenden Sie im SDK dieselbe Kennung für `applicationId`. Siehe [RUM-Anwendungen](/de/rum/applications#client-token).
