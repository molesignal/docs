```http
POST /api/v1/orgs/{id}/select
```

Wechselt mit der angemeldeten Browsersitzung zu einer anderen Organisation, der das Konto angehört. Die Antwort setzt die Sitzungscookies für diese Organisation neu. Der Ablaufzeitpunkt der Sitzung bleibt unverändert. Informationen zu den Cookies finden Sie unter [Anmelden](/de/api/auth/login). Der Wechsel ist nur mit einer Sitzung möglich: Bei Verwendung eines API-Tokens antwortet die API mit `403`. Plattformadministratoren können die geschützte Organisation `_sys` auswählen. Plattformweite Aufrufe wie [JWT-Signaturschlüssel rotieren](/de/api/auth/rotate-jwt) setzen diese Organisation voraus. Eine Sitzung in `_sys` endet spätestens eine Stunde nach dem Wechsel.

**Pfadparameter**

| Parameter | Typ | Hinweise |
|---|---|---|
| `id` | string | Organisations-ID aus `GET /api/v1/orgs`. |

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -c ms-cookies.txt \
  -X POST http://localhost:5080/api/v1/orgs/<organization-id>/select
```
</RequestExample>

<ResponseExample>
```json 200
{
  "userId": "<user-id>",
  "orgId": "<organization-id>",
  "orgName": "default",
  "displayRole": "Owner",
  "roles": [
    { "id": "<role-id>", "key": "owner", "name": "Owner", "builtin": true }
  ],
  "system": false
}
```
</ResponseExample>

Alle Tabs eines Browsers verwenden dieselben Cookies und wechseln daher zur ausgewählten Organisation.

## Anmeldeanforderungen

Wenn die aktuelle Anmeldung die [Anmeldeanforderungen](/de/identity/sso#anmeldeanforderungen) der Organisation nicht vollständig erfüllt, antwortet die API weiterhin mit `200`. Die Antwort enthält keine neuen Cookies und gibt an, was fehlt:

| Antwort | Bedeutung |
|---|---|
| `{"mfa": {"organization_name", "methods"}}` | Bestätigen Sie direkt einen zweiten Faktor: Senden Sie die Anfrage erneut mit `{"proof": {…}}` im Anfragekörper. Geben Sie als Nachweis entweder `method` (`totp` oder `recovery_code`) und `code` an oder verwenden Sie für `method` den Wert `passkey` und geben Sie `ceremony` und `credential` aus `POST /api/v1/me/mfa/passkey-proof` an. |
| `{"mfaSetup": {"organization_name"}}` | Für das Konto ist kein zweiter Faktor eingerichtet. Richten Sie zuerst einen zweiten Faktor über `/api/v1/me/mfa` oder `/api/v1/me/passkeys` ein. |
| `{"sso": {"organization_name", "providers"}}` | Die Organisation erlaubt nur die Anmeldung per Single Sign-on. `providers` listet `id`, `name`, `kind` und `platform` auf. |
