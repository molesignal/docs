```http
GET /api/v1/audit
```

Gibt die Audit-Ereignisse der Organisation aus, die neuesten zuerst. Die Seitennavigation erfolgt per Cursor. Der Aufruf erfordert `audit.read`.

Jedes Ereignis steht auch als Zeile im Stream `_audit` der Organisation. Eine Pipeline kann den Stream abfragen und die Daten an andere Ziele weiterleiten. Diese API liest die maßgeblichen Datensätze. Siehe [Audit-Stream](/de/settings/data-security#audit-stream).

Das Audit-Protokoll erfasst sensible Vorgänge im Lebenszyklus von Ressourcen. Es erfasst nicht jede Änderung. Die Aktionsnamen der aktuellen Version beginnen mit diesen Präfixen:

| Präfix | Vorgänge |
|---|---|
| `agent.` | Modellanbieter, Prompts, Tools und Tool-Aufrufe, MCP-Server, Genehmigungen, Chats, Untersuchungen und Ausführungen in Mole Agent. |
| `iam.` | Rollenbindungen, Beziehungen und organisationsübergreifende Berechtigungen. |
| `resource_share.` | Erstellen, Rotieren, Widerrufen und Öffnen von Freigabelinks sowie fehlgeschlagene Passworteingaben. |
| `status_page.` | Statusseiten, Komponenten, Automatisierungsregeln und Logos. |
| `synthetic.` | Standorte, Agenten und Agenten-Tokens für synthetisches Monitoring. |
| `schedule.` | Bereitschaftspläne und Ausnahmeregelungen. |
| `trace_debug_token.` | Verwendung eines Trace-Debug-Tokens. |
| `dashboard.` | Dashboards auf Basis eines KI-Entwurfs. |

Das Audit-Protokoll erfasst keine Änderungen an Streams, Alarmregeln, Incidents und Konnektoren.

**Abfrageparameter**

| Parameter | Typ | Hinweise |
|---|---|---|
| `from`, `to` | string | Das Zeitfenster. Geben Sie jeden Wert in Mikrosekunden seit der Unix-Epoche oder als relativen Wert an: `now` oder `now-<N><unit>` mit der Einheit `s`, `m`, `h` oder `d`, etwa `now-30m`. |
| `actorKind` | string | Typ der handelnden Identität, zum Beispiel `user`. |
| `actor` | string | Kennung der handelnden Identität. |
| `action` | string | Exakter Aktionsname, etwa `agent.model_provider.created`. |
| `targetKind`, `targetId` | string | Typ und Kennung des Zielobjekts. |
| `limit` | integer | Seitengröße. Standard: `50`. Die API begrenzt den Wert auf 1 bis 200. |
| `cursor` | string | Der Wert `nextCursor` der vorherigen Seite. Der Wert ist opak. |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/audit?from=now-7d&action=agent.model_provider.created&limit=20" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**Antwort**

| Feld | Hinweise |
|---|---|
| `items[].actor_kind`, `items[].actor_id` | Die Identität, die die Änderung vorgenommen hat. |
| `items[].action` | Aktionsname, etwa `iam.role_binding.create`. |
| `items[].target_kind`, `items[].target_id` | Das betroffene Objekt. Beide Felder können `null` sein. |
| `items[].ip`, `items[].user_agent` | Client-Adresse und User-Agent, sofern der Vorgang diese Werte erfasst. Beide Felder können `null` sein. |
| `items[].payload` | Details zum Vorgang. Die Nutzdaten enthalten keine Secrets, Prompt-Inhalte oder Tool-Ergebnisse. |
| `items[].ts` | Zeitpunkt des Ereignisses in Mikrosekunden. |
| `nextCursor` | Cursor für die nächste Seite oder `null` auf der letzten Seite. |
| `retentionDays` | Aufbewahrungsdauer für Audit-Datensätze in Tagen. Sie gilt für alle Organisationen und für die Plattform. Die Plattform löscht ältere Datensätze einmal täglich. `0` steht für unbegrenzte Aufbewahrung. |

**Fehler**

| Status | Ursache |
|---|---|
| `400` | `from` oder `to` ist weder eine Zahl noch ein gültiger relativer Wert (`unparseable time: yesterday`, `bad time unit in: now-3x`), oder `cursor` ist ungültig. |
| `403` | Dem Token fehlt `audit.read`. |

## Weitere Audit-Endpunkte

| Endpunkt | Berechtigung | Zweck |
|---|---|---|
| `GET /api/v1/system/audit` | `sys.telemetry.read` im Systembereich | Dieselbe Abfrage für Audit-Ereignisse der Systemorganisation. Diese Ereignisse erfassen beispielsweise das Aktivieren oder Deaktivieren einer Organisation sowie Änderungen an der Trace-Richtlinie und an der Aufbewahrungsdauer für Audit-Datensätze. |
| `GET /api/v1/settings/audit_retention` | `sys.settings.retention.manage` im Systembereich | Aufbewahrungsdauer für Audit-Datensätze: `{ "retentionDays": 90 }`. |
| `PUT /api/v1/settings/audit_retention` | `sys.settings.retention.manage` im Systembereich | Legt die Aufbewahrungsdauer für Audit-Datensätze mit demselben Request-Body fest. `retentionDays` ist eine ganze Zahl von `0` (unbegrenzte Aufbewahrung) bis `3650`. Bei einem größeren Wert gibt die API `400` zurück. |
| `GET /api/v1/settings/audit_retention/preview?retentionDays=30` | `sys.settings.retention.manage` im Systembereich | Zeigt, wie viele Datensätze bei kürzerer Aufbewahrung gelöscht würden und wie alt der älteste davon ist: `{ "retentionDays": 30, "previousRetentionDays": 90, "rows": 2400, "earliestAt": 1780000000000000 }`. Die API zählt die Datensätze, statt ihre Anzahl zu schätzen. Bei längerer Aufbewahrung oder `0` gibt die API `"rows": 0` zurück. |
| `GET /api/v1/agent/audit/chat/{id}` | `audit.read` | Vollständiges Protokoll eines Chats in Mole Agent: der Datensatz `chat` und die zugehörigen `messages` mit Prompt-Hashes, Token-Anzahlen und Belegen. Bei einem unbekannten Chat gibt die API `404` zurück. |

<Warning>
  Ein Chatprotokoll enthält die Fragen aus dem Chat und die Antworten des Modells. Erteilen Sie `audit.read` nur Konten, die diese Inhalte lesen dürfen.
</Warning>
