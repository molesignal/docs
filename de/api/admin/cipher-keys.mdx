Verschlüsselungsschlüssel verschlüsseln die Felder, die Streams als verschlüsselt markieren. Jeder Schlüssel ist ein 32 Byte langer AES-256-GCM-Schlüssel. MoleSignal verschlüsselt das Schlüsselmaterial mit dem Stammschlüssel aus `MS_CIPHER_KEY` und gibt es nie zurück. Siehe [Sicherheit](/de/security#verschlüsselung-auf-feldebene).

Für neue zu verschlüsselnde Werte verwendet MoleSignal immer die neueste Version des Standardschlüssels `__field_default__`. MoleSignal erstellt diesen Schlüssel, sobald ein Stream ihn zum ersten Mal benötigt. Andere benannte Schlüssel und frühere Versionen aller Schlüssel bleiben verfügbar, um die damit verschlüsselten Werte zu entschlüsseln.

| Vorgang | Endpunkt | Berechtigung |
|---|---|---|
| Schlüssel auflisten | `GET /api/v1/cipher_keys` | `org.cipher_keys.read` |
| Schlüssel abrufen | `GET /api/v1/cipher_keys/{name}` | `org.cipher_keys.read` |
| Schlüssel erstellen | `POST /api/v1/cipher_keys` | `org.cipher_keys.manage` |
| Schlüssel rotieren | `POST /api/v1/cipher_keys/{name}/rotate` | `org.cipher_keys.rotate` |
| Schlüssel löschen | `DELETE /api/v1/cipher_keys/{name}` | `org.cipher_keys.manage` |
| Standardschlüssel rotieren | `POST /api/v1/field_encryption/rotate` | `org.cipher_keys.rotate` |

## Schlüsselmetadaten

Die Aufrufe zum Auflisten, Abrufen, Erstellen und Rotieren geben die Metadaten der Schlüsselversionen zurück. Der Listenaufruf gibt alle Versionen aller Schlüssel zurück, für jeden Schlüsselnamen mit der neuesten Version zuerst.

```json
{
  "id": "3KEZizkQsvBwoWQihNO6OdxRiSf",
  "name": "payments-key",
  "alg": "aes-256-gcm",
  "version": 1,
  "createdAt": 1790000000000000,
  "rotatedAt": null
}
```

`rotatedAt` hat den Wert `null`, wenn noch keine Rotation stattgefunden hat. Der Abruf gibt die neueste Version zurück.

## Schlüssel erstellen

```http
POST /api/v1/cipher_keys
```

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `name` | string | Ja | Der Schlüsselname. Falls der Name bereits existiert, gibt der Aufruf `409` zurück. Die Meldung verweist auf den Aufruf zum Rotieren. |
| `keyMaterialB64` | string | Ja | 32 zufällige Bytes in Standard-Base64 mit Padding. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/cipher_keys \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "{\"name\": \"payments-key\", \"key_material_b64\": \"$(openssl rand -base64 32)\"}"
```
</RequestExample>

Die Antwort enthält die oben gezeigten Schlüsselmetadaten.

## Schlüssel rotieren

```http
POST /api/v1/cipher_keys/{name}/rotate
```

Der Anfragetext enthält wie beim Erstellen `keyMaterialB64`. Der Aufruf fügt eine Version mit dem neuen Schlüsselmaterial hinzu und behält die früheren Versionen zum Entschlüsseln bei. Falls kein Schlüssel mit diesem Namen existiert, gibt der Aufruf `404` zurück. Erstellen Sie den Schlüssel zuerst mit dem entsprechenden Aufruf.

## Schlüssel löschen

```http
DELETE /api/v1/cipher_keys/{name}
```

Der Aufruf löscht alle Versionen des angegebenen Schlüssels und gibt `{"deleted": true}` zurück. Falls kein Schlüssel mit diesem Namen existiert, gibt der Aufruf `404` zurück. Der Aufruf prüft nicht, ob gespeicherte Daten den Schlüssel noch benötigen.

<Warning>
  Werte, die ein gelöschter Schlüssel verschlüsselt hat, lassen sich nicht mehr entschlüsseln. Prüfen Sie vor dem Löschen eines Schlüssels,
  welche verschlüsselten Felder diesen Schlüssel benötigen.
</Warning>

## Standardschlüssel rotieren

```http
POST /api/v1/field_encryption/rotate
```

Der Aufruf erzeugt neues Schlüsselmaterial auf dem Server, fügt eine neue Version von `__field_default__` hinzu und aktualisiert sofort den Entschlüsselungscache. Neue Schreibvorgänge verwenden die neue Version, und vorhandene Werte bleiben lesbar. Falls die Organisation noch keinen Standardschlüssel hat, erstellt der Aufruf ihn als Version 1. Der Anfragetext ist leer. Die Antwort enthält die Kennung und die Version des neuen Schlüssels:

```json
{
  "keyId": "3KEZj3uxMx5OOFX6NiYv3VFnfmD",
  "version": 2
}
```

**Fehler**

| Status | Ursache |
|---|---|
| `400` | `keyMaterialB64` ist kein gültiges Base64 oder ergibt beim Dekodieren nicht genau 32 Bytes (`key_material must be 32 bytes, got 5`). |
| `403` | Dem Token fehlt die für den Aufruf erforderliche Berechtigung. |
| `404` | Beim Abrufen, Rotieren oder Löschen hat der Aufruf keinen Schlüssel mit diesem Namen gefunden. |
| `409` | Ein Schlüssel mit diesem Namen existiert bereits. |
| `422` | Ein Pflichtfeld fehlt. Die Antwort enthält unformatierten Text. |
