| Endpunkt | Authentifizierung |
|---|---|
| `GET /api/v1/healthz` | Keine |
| `GET /metrics` | Keine |
| `GET /api/v1/readyz` | Bearer-Token |
| `GET /api/v1/version` | Bearer-Token |

## Liveness

```http
GET /api/v1/healthz
```

Diese Prüfung fasst mehrere Zustandsprüfungen zusammen. Sie gibt `200` zurück, wenn der Knoten fehlerfrei läuft, und `503` mit einem `reason`, wenn der Objektspeicher nicht erreichbar ist. Verwenden Sie diesen Endpunkt für Zustandsprüfungen durch Container und Load Balancer.

<ResponseExample>
```json 200
{ "status": "ok" }
```
</ResponseExample>

## Readiness

```http
GET /api/v1/readyz
Authorization: Bearer <token>
```

Diese Prüfung zeigt, ob der Knoten Anfragen annehmen kann. Sie gibt `200` zurück, sobald der Knoten gestartet ist, da beim Start keine Daten erneut eingespielt werden. Auch bei eingeschränkter Funktion des Objektspeichers bleibt der Knoten für Leseanfragen bereit. Die Anfrage erfordert ein Bearer-Token. Ohne Anmeldedaten gibt der Endpunkt `401` zurück. Prüfen Sie stattdessen `/api/v1/healthz`, wenn die Prüfanfrage kein Token mitsenden kann.

<ResponseExample>
```json 200
{ "status": "ready" }
```
</ResponseExample>

## Version

```http
GET /api/v1/version
Authorization: Bearer <token>
```

Gibt die Produktversion, den Commit, den Branch, den Build-Zeitpunkt, die Build-ID, den Release-Kanal und die Edition zurück.

<ResponseExample>
```json 200
{
  "version": "26.1.0.0",
  "commit": "<git-sha>",
  "branch": "main",
  "buildEpochSecs": 1790000000,
  "buildId": "<build-id>",
  "releaseChannel": "alpha",
  "edition": "oss"
}
```
</ResponseExample>

## Metriken

```http
GET /metrics
```

Gibt Prozess- und Subsystemmetriken im Prometheus-Expositionsformat (`text/plain; version=0.0.4`) aus, etwa `cache_*`-Trefferquoten sowie `wal_*`, `object_store_*` und `storage_reconciler_issues_total`. Beschränken Sie den Zugriff auf diesen Endpunkt auf Proxy- oder Netzwerkebene. Siehe [Selbstüberwachung](/de/self-observability).
