```http
POST /api/v1/alerts/incidents
```

Eröffnet einen Incident für ein Problem, das keine Regel erkannt hat, etwa bei einer Kundenmeldung. Der Incident trägt das
Label `alert.source=manual`, die Annotationen `createdBy` (Aufrufer) und `description` sowie die
`ruleId` `manual`. Er durchläuft keine Alert-Pipelines. MoleSignal dedupliziert ihn nie mit einem anderen Incident und löst ihn nie
automatisch auf. Der Aufruf erfordert `alerts.incidents.create` und protokolliert das Audit-Ereignis
`alert.incident.created`.

**Anfrageinhalt**

| Feld | Typ | Erforderlich | Beschreibung |
|---|---|---|---|
| `title` | string | Ja | Bis zu 200 Zeichen. |
| `description` | string | Nein | Markdown, bis zu 20000 Zeichen. |
| `severity` | string | Nein | `info`, `warning`, `error` (Standard) oder `critical`. |
| `urgency` | string | Nein | Schlüssel einer [Dringlichkeitsstufe](/de/alerting/on-call#dringlichkeits-und-prioritätsstufen) der Organisation, etwa `high` oder `low`. Fehlt der Schlüssel, legt die Eskalationsrichtlinie des Incidents die Dringlichkeit fest. Siehe [Dringlichkeit](/de/alerting/on-call#dringlichkeit). |
| `priority` | string | Nein | Eine Priorität der Organisation, standardmäßig `P1` bis `P5` (höchstens `P9`). |
| `assign` | object | Nein | Legt fest, wer den Incident übernimmt. Standardmäßig steuert [Alert-Routing](/de/alerting/routing) die Zuweisung mit `{"kind": "auto"}`. `{"kind": "team", "teamId": "..."}` nutzt die Bereitschaftsrichtlinie des Teams. `{"kind": "policy", "escalationPolicyId": "..."}` nutzt die angegebene Eskalationsrichtlinie. `{"kind": "users", "userIds": [...]}` benachrichtigt 1 bis 10 Mitglieder der Organisation direkt, ohne Eskalationsrichtlinie. |
| `services` | string[] | Nein | Bis zu 20 betroffene Services. |
| `labels` | object | Nein | Bis zu 50 Labels. `alert.source` lautet immer `manual`. |
| `declareMajor` | boolean | Nein | Deklariert den Incident zusätzlich als [schwerwiegenden Incident](/de/alerting/major-incidents). MoleSignal eröffnet den Incident auch dann, wenn die Deklaration fehlschlägt. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"title": "Customers in the north cannot pay", "severity": "critical", "priority": "P1", "assign": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

Die Antwort enthält den Incident. Eine Übersicht der Felder finden Sie unter [Incidents auflisten](/de/api/alerting/list-incidents).

**Fehler**

| Status | Grund |
|---|---|
| `400` | Der Titel fehlt oder ist zu lang, die Anfrage enthält zu viele Labels oder Services, `users` gibt weniger als 1 oder mehr als 10 Personen an oder das Team, die Richtlinie oder mindestens eine der angegebenen Personen gehört nicht zur Organisation. |
| `403` | Dem Token fehlt die Berechtigung `alerts.incidents.create`. |
