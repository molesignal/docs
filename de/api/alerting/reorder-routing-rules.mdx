```http
PUT /api/v1/alerts/routing/rules/order
```

Bringt die [Routing-Regeln](/de/alerting/routing#routing-regeln) der Organisation in die angegebene Reihenfolge. Der Aufruf erfordert `alerts.routing.manage`. Die aufgelisteten Regeln stehen in der angegebenen Reihenfolge zuerst. Die übrigen Regeln behalten untereinander ihre bisherige Reihenfolge. Der Aufruf ignoriert IDs, die keiner Regel der Organisation entsprechen.

| Feld | Typ | Beschreibung |
|---|---|---|
| `ids` | Array | Pflichtfeld. Liste der Regel-IDs in der Reihenfolge, in der der Aufruf die Regeln prüft. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/order \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<rule-id-2>", "<rule-id-1>"]}'
```
</RequestExample>

Die Antwort enthält alle Regeln in der neuen Reihenfolge. `position` beginnt bei 0 und steigt lückenlos an. Siehe [Regelfelder](/de/api/alerting/list-routing-rules#regelfelder).

**Fehler**

| Status | Ursache |
|---|---|
| `403` | Dem Token fehlt `alerts.routing.manage`. |
| `422` | `ids` fehlt oder die Anfrage enthält ein anderes Feld. Die Antwort ist Klartext. |
