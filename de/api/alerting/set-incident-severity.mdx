```http
PUT /api/v1/alerts/incidents/{id}/severity
```

Setzt den Schweregrad eines aktiven Vorfalls und erfasst den Aufrufer in `severitySetBy`. Danach ändert
die Regelauswertung den Schweregrad nicht mehr. Wenn der Schweregrad eines Vorfalls mit Status `open` steigt, beginnt
die Eskalation erneut beim ersten Schritt, der für den neuen Schweregrad gilt. Dabei erhält `escalation.reason` den Wert
`severity_raised`. Eine Senkung oder eine Änderung bei einem bestätigten Vorfall ändert nur den Schweregrad. Der Aufruf
erfordert `alerts.incidents.update`.

**Anfragetext**

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `severity` | string | Ja | `info`, `warning`, `error` oder `critical`. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/severity \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"severity": "critical"}'
```
</RequestExample>

Die Antwort enthält den aktualisierten Vorfall. [Vorfälle auflisten](/de/api/alerting/list-incidents) beschreibt alle Felder.

**Fehler**

| Status | Ursache |
|---|---|
| `422` | `severity` fehlt oder entspricht keinem der vier zulässigen Werte. |
| `403` | Dem Token fehlt `alerts.incidents.update` oder der Vorfall liegt außerhalb des Zugriffsbereichs des Tokens. |
| `404` | Der Vorfall existiert nicht. |
| `409` | Der Vorfall hat sich erledigt, das System hat ihn mit einem anderen zusammengeführt oder der Vorfall hat sich während der Aktualisierung wiederholt geändert. Wiederholen Sie den Aufruf. |
