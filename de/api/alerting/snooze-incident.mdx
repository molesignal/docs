```http
POST /api/v1/alerts/incidents/{id}/snooze
DELETE /api/v1/alerts/incidents/{id}/snooze
```

`POST` pausiert einen aktiven Incident für `durationSecs`. Hat der Incident den Status `open`, muss der
Aufrufer ihn zuerst bestätigen. Während der Pause sendet MoleSignal keine Benachrichtigungen für den Incident und eskaliert ihn nicht. Sobald
`snoozedUntil` verstrichen ist, wechselt der Incident zurück zu `open`. Die zuständigen Personen erhalten eine Eskalationsbenachrichtigung mit
`escalation.reason` = `snooze_ended`. Erneutes Pausieren setzt einen neuen Endzeitpunkt.

`DELETE` beendet die Pause sofort. Der Incident bleibt im Status `acknowledged`. Beide Aufrufe erfordern
`alerts.incidents.acknowledge`. `DELETE` hat keinen Anfragetext.

**Anfragetext**

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `durationSecs` | Ganzzahl | Ja | 60 (1 Minute) bis 604800 (7 Tage). |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/snooze \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"durationSecs": 3600}'
```
</RequestExample>

Die Antwort enthält den aktualisierten Incident. [Incidents auflisten](/de/api/alerting/list-incidents) beschreibt alle Felder.

**Fehler**

| Status | Ursache |
|---|---|
| `400` | `durationSecs` liegt unter 60 oder über 604800. |
| `403` | Dem Token fehlt `alerts.incidents.acknowledge` oder das Token gewährt keinen Zugriff auf den Incident. |
| `404` | Der Incident existiert nicht. |
| `409` | Der Incident hat sich normalisiert, ging in einem anderen Incident auf oder änderte sich während der Aktualisierung wiederholt. Wiederholen Sie den Aufruf. |
