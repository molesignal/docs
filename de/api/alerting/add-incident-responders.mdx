```http
POST /api/v1/alerts/incidents/{id}/responders
```

Fügt die in `userIds` aufgeführten Personen als Zuständige zu einem aktiven Incident hinzu und sendet jeder neu hinzugefügten Person eine
Eskalationsbenachrichtigung mit `rescalation.reason` gleich `responder_added`. Der Status des Incidents bleibt unverändert,
und bereits zugewiesene Personen erhalten keine weitere Benachrichtigung. Der Aufruf erfordert `alerts.incidents.update`.

**Anfragetext**

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `userIds` | Array | Ja | 1 bis 10 Benutzer-IDs von Mitgliedern der Organisation. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/responders \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"userIds": ["<another-user-id>"]}'
```
</RequestExample>

Die Antwort enthält den aktualisierten Incident. [Incidents auflisten](/de/api/alerting/list-incidents) beschreibt alle Felder.

**Fehler**

| Status | Ursache |
|---|---|
| `400` | `userIds` ist leer, enthält mehr als 10 Benutzer-IDs oder enthält die ID einer Person außerhalb der Organisation. |
| `403` | Dem Token fehlt `alerts.incidents.update` oder das Token erlaubt keinen Zugriff auf den Incident. |
| `404` | Der Incident existiert nicht. |
| `409` | Der Incident ist behoben, wurde mit einem anderen Incident zusammengeführt oder hat sich während der Aktualisierung wiederholt geändert. Wiederholen Sie den Aufruf. |
