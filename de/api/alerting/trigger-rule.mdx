```http
POST /api/v1/alerts/rules/{id}/trigger
```

Öffnet einen Vorfall für eine Regel, ohne die Bedingung auszuwerten. Verwenden Sie den Aufruf, um Benachrichtigungen und Eskalationen zu testen oder einen Vorfall manuell auszulösen. Der Aufruf funktioniert auch für deaktivierte Regeln. Er erfordert `alerts.rules.manage`. Der Request-Body ist leer.

- Wenn für die Regel bereits ein offener oder bestätigter Vorfall vorliegt, gibt der Aufruf diesen unverändert zurück. Der Aufruf lässt sich gefahrlos wiederholen.
- Andernfalls erstellt der Aufruf einen Vorfall mit dem Status `open` und sendet das Benachrichtigungsereignis für die Auslösung.
- Der Schweregrad ergibt sich in dieser Reihenfolge: `severity` der Regel, Label `severity`, Standardwert `warning`. Der Aufruf ignoriert `thresholds`.
- Die Annotation `manual_triggered_by` enthält die Kennung des aufrufenden Kontos. `triggering_query.sample_values` ist leer.

Eine aktivierte Regel schließt den Vorfall bei der nächsten Auswertung, wenn die Bedingung nicht erfüllt ist. Bei einer deaktivierten Regel bleibt der Vorfall offen, bis er manuell geschlossen wird.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/trigger \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**Fehler**

| Status | Ursache |
|---|---|
| `403` | Dem Token fehlt die Berechtigung `alerts.rules.manage`. |
| `404` | Die Regel existiert nicht. |
