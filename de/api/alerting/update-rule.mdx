```http
PUT /api/v1/alerts/rules/{id}
```

Ersetzt die Konfiguration einer Regel. Senden Sie den vollständigen Anfragebody wie unter [Regel erstellen](/de/api/alerting/create-rule). Der Aufruf behält die `id` der Regel, die Organisation sowie `createdAt`, `lastEvalAt` und `lastState` bei. Wenn Sie `escalationPolicyId` ändern, muss der Wert auf eine Richtlinie der Organisation verweisen oder `default` lauten. Der Aufruf erfordert `alerts.rules.manage`.

<Warning>
  Der Aufruf ersetzt die Regel, ohne Felder zusammenzuführen. Wenn Sie ein Feld weglassen, verwendet der Aufruf dessen Standardwert,
  etwa `true` für `enabled` und `scheduled` für `kind`. Wenn Sie
  `labels`, `annotations` oder `thresholds` weglassen, bleiben diese Felder leer. Nur wenn Sie `escalationPolicyId` weglassen,
  bleibt die aktuelle Richtlinie erhalten. Rufen Sie zuerst die Regel ab und senden Sie den vollständigen Anfragebody mit der Änderung zurück.
</Warning>

Der Fingerabdruck eines Incidents ergibt sich aus der `id` und den `labels` der Regel. Wenn Sie `labels` ändern, behält ein bereits offener Incident seinen bisherigen Fingerabdruck. MoleSignal löst ihn dann nicht mehr automatisch. Lösen Sie ihn mit [Incident lösen](/de/api/alerting/resolve-incident).

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  --data-binary @- <<'EOF'
{
  "name": "High error rate",
  "description": "More than 200 errors in five minutes",
  "enabled": true,
  "kind": "scheduled",
  "query": {
    "language": "sql",
    "statement": "SELECT count(*) AS c FROM app WHERE level = 'error'",
    "periodSecs": 300,
    "stream": { "name": "app", "streamType": "logs" }
  },
  "trigger": { "operator": "gt", "threshold": 200, "forPeriods": 2, "silenceSecs": 0 },
  "severity": "critical",
  "labels": { "team": "checkout" }
}
EOF
```
</RequestExample>

Die Antwort enthält die aktualisierte Regel im Format, das [Regeln auflisten](/de/api/alerting/list-rules) zeigt.

**Fehler**

| Status | Ursache |
|---|---|
| `400` | Der Anfragebody besteht die gleichen Prüfungen wie unter [Regel erstellen](/de/api/alerting/create-rule) nicht, oder der geänderte Wert von `escalationPolicyId` verweist auf keine Richtlinie der Organisation. |
| `404` | Die Regel existiert nicht. |
| `422` | Ein Pflichtfeld fehlt oder ein Wert hat den falschen Typ. Die Antwort besteht aus Klartext. |
