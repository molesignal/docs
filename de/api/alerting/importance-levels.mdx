```http
GET /api/v1/alerts/importance
PUT /api/v1/alerts/importance
```

`GET` erfordert `alerts.importance.read`, `PUT` erfordert `alerts.importance.manage`. Beide geben die Stufen der Organisation zurück:

```json
{
  "levels": {
    "priorities": [
      {"priority": "P1", "name": "Critical business impact", "description": "Customers cannot pay"},
      {"priority": "P2", "name": "", "description": ""},
      {"priority": "P3", "name": "", "description": ""}
    ],
    "urgencies": [
      {"key": "urgent", "name": "Urgent", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["critical"]},
      {"key": "high", "name": "", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["error"]},
      {"key": "low", "name": "", "escalates": false, "quietHours": "block", "steps": "low", "severities": ["warning", "info"]}
    ]
  },
  "updatedBy": "3KF1...",
  "updatedAt": 1793059200000000
}
```

Hat eine Organisation noch keine Stufen gespeichert, erhält sie die Standardstufen: `P1` bis `P5` sowie `high` und `low` wie
unter [Dringlichkeit](/de/alerting/on-call#dringlichkeit) beschrieben. `updatedBy` bleibt leer. `PUT` übernimmt das
Objekt `levels`, ersetzt die Stufen und protokolliert das Audit-Ereignis `alert_importance.updated`.

| Feld | Beschreibung |
|---|---|
| `priorities` | 1 bis 9 Stufen, lückenlos nummeriert: `P1`, `P2`, … `name` darf bis zu 32 Zeichen enthalten, `description` bis zu 200. Ist der Name leer, dient der Schlüssel als Name. |
| `urgencies` | 2 bis 5 Stufen, mit der höchsten Dringlichkeit zuerst. `key` beginnt mit einem Kleinbuchstaben und darf bis zu 32 Zeichen aus Kleinbuchstaben, Ziffern und Unterstrichen enthalten. `high` und `low` müssen erhalten bleiben. `name` darf bis zu 32 Zeichen enthalten. Ist der Name leer, gilt die Standardbezeichnung. |
| `escalates` | `true` alarmiert gemäß den Schritten der Eskalationsrichtlinie. `false` benachrichtigt nur die Empfänger des ersten Schritts. |
| `quietHours` | `switch` berücksichtigt die persönliche Einstellung **Alarme mit hoher Dringlichkeit auch während der Ruhezeiten erhalten**. `block` unterdrückt alle Alarmierungen während der Ruhezeiten. |
| `steps` | Legt fest, welche der beiden persönlichen Schrittgruppen die Stufe verwendet: `high` oder `low`. |
| `severities` | Legt fest, welche Schweregrade dieser Stufe zugeordnet sind, wenn eine Richtlinie die Dringlichkeit anhand des Schweregrads bestimmt. `critical`, `error`, `warning` und `info` müssen jeweils genau einer Stufe zugeordnet sein. |

Die Stufen bestimmen, welche Prioritäten und Dringlichkeiten in Regeln, Eskalationsrichtlinien, Incidents und der API zulässig sind. Eine Priorität oberhalb der höchsten
konfigurierten Stufe oder eine nicht konfigurierte Dringlichkeit führt dort zu `400`. Liefert ein externer Alarm oder eine Alarm-Pipeline
eine Priorität oberhalb der höchsten konfigurierten Stufe, verwendet MoleSignal die niedrigste Priorität. Eine Dringlichkeit, die in der Organisation nicht
konfiguriert ist, verwirft MoleSignal. Die Namen stehen in Benachrichtigungen als `{{priority_name}}` und `{{urgency_name}}` zur Verfügung.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/importance \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d @levels.json
```
</RequestExample>

**Fehler**

| Status | Grund |
|---|---|
| `400` | Die Stufen verletzen eine Regel aus der obigen Tabelle. |
| `403` | Dem Token fehlt die erforderliche Berechtigung. |
| `422` | Ein Feld hat den falschen Typ oder ein Schlüssel ist ungültig. |
