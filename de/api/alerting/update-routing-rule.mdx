```http
PUT /api/v1/alerts/routing/rules/{id}
```

Speichert eine [Routing-Regel](/de/alerting/routing#routing-regeln) vollständig neu. Dafür ist `alerts.routing.manage` erforderlich. Es gelten dieselben Felder wie unter [Routing-Regel erstellen](/de/api/alerting/create-routing-rule). Fehlt ein optionales Feld, erhält es wieder seinen Standardwert. Die Regel behält ihre Position. Mit [Routing-Regeln neu anordnen](/de/api/alerting/reorder-routing-rules) ändern Sie die Position. Bereits offene Incidents bleiben unverändert.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "enabled": false, "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

Die Antwort enthält die aktualisierte Regel.

**Fehler**

| Status | Ursache |
|---|---|
| `400` | Ein Feld ist ungültig oder das Zielteam oder die Zielrichtlinie existiert nicht. |
| `403` | Dem Token fehlt `alerts.routing.manage`. |
| `404` | Die Regel existiert nicht oder gehört zu einer anderen Organisation. |
| `422` | `name` oder `target` fehlt oder ein Wert ist unbekannt. Die Antwort besteht aus Klartext. |
