```http
GET /api/v1/alerts/routing/rules
```

Listet die [Routing-Regeln](/de/alerting/routing#routing-regeln) der Organisation in der Reihenfolge auf, in der das System sie prüft (nach `position` aufsteigend). Der Aufruf erfordert `alerts.routing.read`. Die Liste enthält auch deaktivierte Regeln.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "id": "3KF0q7vXbJ2mYc8sTn4LwRk9Ez1",
    "orgId": "<organization-id>",
    "name": "Payments in production",
    "enabled": true,
    "position": 0,
    "conditions": [
      { "key": "env", "operator": "equals", "values": ["prod"] },
      { "key": "service.name", "operator": "in", "values": ["checkout", "cart"] }
    ],
    "minSeverity": "error",
    "origins": [],
    "target": { "kind": "team", "teamId": "<team-id>" },
    "createdBy": "<user-id>",
    "createdAt": 1790000000000000,
    "updatedAt": 1790000000000000
  }
]
```
</ResponseExample>

## Regelfelder

| Feld | Beschreibung |
|---|---|
| `id`, `orgId` | IDs der Regel und der Organisation. |
| `name` | Name der Regel. |
| `enabled` | Das System prüft nur aktivierte Regeln. |
| `position` | Prüfreihenfolge: Kleinere Werte kommen zuerst. |
| `conditions` | Bedingungen für die Labels des Incidents. Alle Bedingungen müssen zutreffen. Eine leere Liste trifft auf jeden Incident zu. Jede Bedingung hat einen `key`, einen `operator` und `values`. |
| `minSeverity` | Mindestschweregrad des Incidents: `info`, `warning`, `error` oder `critical`. Bei `null` gilt jeder Schweregrad. |
| `origins` | Quellen, für die die Regel gilt: `rule` (Alarmregeln), `external` (Alarmquellen), `synthetic` (synthetische Prüfungen). Eine leere Liste steht für alle Quellen. |
| `target` | Routing-Ziel für einen passenden Incident: `{"kind": "team", "teamId": …}` oder `{"kind": "policy", "policyId": …}`. |
| `createdBy` | Benutzerkonto, das die Regel erstellt hat. |
| `createdAt`, `updatedAt` | Zeitstempel der Erstellung und der letzten Änderung in Mikrosekunden. |

Werte für `operator`:

| `operator` | `values` | Bedingung für eine Übereinstimmung |
|---|---|---|
| `equals` | Ein Wert | Der Labelwert entspricht dem angegebenen Wert. |
| `not_equals` | Ein Wert | Der Labelwert weicht vom angegebenen Wert ab oder dem Incident fehlt das Label. |
| `in` | Ein oder mehrere Werte | Der Labelwert entspricht einem der angegebenen Werte. |
| `matches` | Ein regulärer Ausdruck | Der gesamte Labelwert entspricht dem regulären Ausdruck. |
