Mit einer Diensttauschanfrage bittet die anfragende Person ein anderes Mitglied des Dienstplans, die Rufbereitschaft für einen Zeitraum zu übernehmen. Sobald die angefragte Person zusagt,
erhält der Dienstplan eine [Ausnahmeregelung](/de/alerting/on-call#vorübergehende-vertretung) und der Diensttausch tritt in Kraft. Ist im
Dienstplan **Diensttausche müssen genehmigt werden** aktiviert (`swapNeedsApproval`), muss eine Person mit Verwaltungsrechten für den Dienstplan
den Diensttausch zusätzlich genehmigen. Ist der Diensttausch am Ende des Zeitraums noch offen, verfällt er. Bei jedem Schritt benachrichtigt MoleSignal die
Beteiligten über die integrierte Richtlinie
[Diensttausch: Beteiligte benachrichtigen](/de/notification-channels#integrierte-richtlinien) und protokolliert den Schritt im
Audit-Log.

| Methode und Pfad | Funktion | Berechtigung |
|---|---|---|
| `GET /api/v1/schedules/swaps` | Listet dienstplanübergreifend alle selbst gestellten und erhaltenen Diensttauschanfragen auf. | `schedules.read` |
| `GET /api/v1/schedules/{id}/swaps` | Listet die Diensttausche eines Dienstplans auf, die neuesten zuerst. | `schedules.read` für den Dienstplan |
| `POST /api/v1/schedules/{id}/swaps` | Stellt eine Diensttauschanfrage. | `schedules.swaps.request` für den Dienstplan |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/accept` | Nimmt den Diensttausch an. Das kann nur die angefragte Person. | `schedules.swaps.request` für den Dienstplan |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/decline` | Lehnt den Diensttausch ab. Das kann nur die angefragte Person. | `schedules.swaps.request` für den Dienstplan |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/cancel` | Zieht die Diensttauschanfrage zurück. Das kann nur die anfragende Person, solange der Diensttausch noch offen ist. | `schedules.swaps.request` für den Dienstplan |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/approve` | Genehmigt einen angenommenen Diensttausch. Die Ausnahmeregelung tritt sofort in Kraft. | `schedules.swaps.approve` für den Dienstplan |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/reject` | Verweigert die Genehmigung für einen angenommenen Diensttausch. | `schedules.swaps.approve` für den Dienstplan |

## Diensttausch anfragen

**Anfrageinhalt**

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `targetId` | string | Ja | Übernimmt die Rufbereitschaft: ein anderes Mitglied desselben Dienstplans als die anfragende Person. |
| `startAt`, `endAt` | integer | Ja | Zeitraum des Diensttauschs, angegeben als Unix-Zeitstempel in Mikrosekunden. Der Beginn muss in der Zukunft liegen, das Ende nach dem Beginn. |
| `note` | string | Nein | Eine Notiz mit bis zu 500 Zeichen. |

Die anfragende Person muss laut Dienstplan während des gesamten Zeitraums allein Rufbereitschaft haben. Der angefragte Zeitraum darf
sich nicht mit einem offenen Diensttausch im selben Dienstplan überschneiden.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/$SCHEDULE_ID/swaps \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"targetId": "<user-id>", "startAt": 1790060400000000, "endAt": 1790146800000000, "note": "Travelling on Friday"}'
```
</RequestExample>

Jeder Aufruf gibt den Diensttausch zurück. Listenaufrufe geben `{ "swaps": [ ... ] }` zurück.

<ResponseExample>
```json 200
{
  "id": "3KHq2nB7yZ0d4kVwXc1sPa9LmQe",
  "orgId": "<organization-id>",
  "scheduleId": "<schedule-id>",
  "scheduleName": "Payments primary",
  "requesterId": "<user-id>",
  "targetId": "<another-user-id>",
  "startAt": 1790060400000000,
  "endAt": 1790146800000000,
  "note": "Travelling on Friday",
  "status": "pending",
  "overrideId": null,
  "decidedBy": null,
  "decidedAt": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

| Feld | Hinweise |
|---|---|
| `status` | `pending` (Antwort ausstehend), `awaiting_approval` (angenommen, Genehmigung ausstehend), `accepted` (in Kraft), `declined` (abgelehnt), `rejected` (Genehmigung verweigert), `cancelled` (zurückgezogen) oder `expired` (abgelaufen). |
| `overrideId` | ID der Ausnahmeregelung, die beim Inkrafttreten des Diensttauschs hinzugefügt wurde. |
| `decidedBy`, `decidedAt` | Wer den Diensttausch zuletzt beantwortet, genehmigt, nicht genehmigt oder zurückgezogen hat und wann. |

**Fehler**

| Status | Grund |
|---|---|
| `400` | Der Zeitraum ist ungültig, die angefragte Person gehört nicht zum Dienstplan, neben der anfragenden Person hat im Zeitraum noch jemand Rufbereitschaft oder der Zeitraum überschneidet sich mit einem offenen Diensttausch. |
| `403` | Eine Berechtigung fehlt oder die aufrufende Person darf diesen Schritt nicht ausführen. |
| `404` | Der Dienstplan oder der Diensttausch existiert nicht. |
| `409` | Der Diensttausch lässt diesen Schritt nicht mehr zu (etwa weil der Tausch bereits in Kraft oder abgelaufen ist) oder wurde inzwischen geändert. Rufen Sie den Diensttausch erneut ab und wiederholen Sie den Aufruf. |
