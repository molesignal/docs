Eine Kalender-App (Google Calendar, Outlook, Apple Calendar oder eine andere) liest die Abonnementadresse. Die Adresse
liefert iCalendar-Daten nach RFC 5545 mit den Schichten der letzten 30 und der nächsten 90 Tage, einschließlich Überschreibungen und Schichttausch.
Ein Feed enthält entweder alle Schichten eines Dienstplans oder nur die eigenen Schichten über alle Dienstpläne hinweg.

| Methode und Pfad | Funktion | Berechtigung |
|---|---|---|
| `GET /api/v1/schedules/calendar-feeds` | Listet die Feeds des aktuellen Kontos auf. | `schedules.read` |
| `POST /api/v1/schedules/calendar-feeds` | Erstellt eine Abonnementadresse. Gibt es für denselben Dienstplan oder den persönlichen Feed bereits eine Adresse, ersetzt der Aufruf diese. Die bisherige Adresse wird sofort ungültig. | `schedules.calendar_feeds.manage` und bei einem Dienstplan-Feed zusätzlich `schedules.calendar_feeds.manage` für den Dienstplan |
| `DELETE /api/v1/schedules/calendar-feeds/{id}` | Deaktiviert einen Feed des aktuellen Kontos. Die zugehörige Adresse wird sofort ungültig. | `schedules.calendar_feeds.manage` |
| `GET /api/v1/public/calendar/{token}.ics` | Ruft den Feed unter der Abonnementadresse ohne Anmeldung ab. | Das Token in der Adresse |

## Abonnementadresse erstellen

**Anfrageinhalt**

| Feld | Typ | Pflichtfeld | Hinweise |
|---|---|---|---|
| `scheduleId` | string | Nein | Abonniert diesen Dienstplan. Lassen Sie das Feld für einen persönlichen Feed weg. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/calendar-feeds \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"scheduleId": "<schedule-id>"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "feed": {
    "id": "3KHtq0dYc1fUe8WnP2xLbR7aZsM",
    "scheduleId": "<schedule-id>",
    "scheduleName": "Payments primary",
    "createdAt": 1790000000000000,
    "lastUsedAt": null
  },
  "path": "/api/v1/public/calendar/<token>.ics",
  "url": "https://molesignal.example.com/api/v1/public/calendar/<token>.ics"
}
```
</ResponseExample>

MoleSignal gibt die Adresse nur hier und nur einmal zurück und speichert lediglich den SHA-256-Hash des Tokens. MoleSignal bildet `url` aus der
externen Adresse der Instanz. Ist keine externe Adresse konfiguriert, lautet `url` `null`. Hängen Sie in diesem Fall `path` an die Adresse an,
unter der MoleSignal erreichbar ist. Jeder Feed in der Liste enthält `id`, `scheduleId`, `scheduleName`, `createdAt` und
`lastUsedAt` (Zeitpunkt des letzten Abrufs durch eine Kalender-App), aber keine Abonnementadresse.

## So ruft die Kalender-App den Feed ab

```http
GET /api/v1/public/calendar/{token}.ics
```

Bei jedem Abruf prüft MoleSignal erneut, ob das abonnierende Konto noch aktiv ist, zur Organisation gehört, weiterhin über
`schedules.read` verfügt und bei einem Dienstplan-Feed weiterhin Zugriff auf den Dienstplan hat. Schlägt die Prüfung fehl, ist das Token falsch
oder ist der Feed deaktiviert, gibt MoleSignal `404` zurück. Die Titel und Beschreibungen der Schichten erscheinen in der
Oberflächensprache des abonnierenden Kontos.

Die Adresse allein reicht aus, um diese Schichten einzusehen. Ersetzen Sie die Adresse oder deaktivieren Sie den Feed, wenn die Adresse in unbefugte Hände gerät.
