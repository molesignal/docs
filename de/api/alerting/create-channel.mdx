Ein Konnektor speichert die Zugangsdaten und Transporteinstellungen eines Benachrichtigungsanbieters für eine Organisation. Zum Auflisten und Abrufen von Konnektoren ist `notify.connectors.read` erforderlich. Zum Erstellen, Aktualisieren, Testen und Löschen eines Konnektors ist `notify.connectors.manage` erforderlich.

| Vorgang | Endpunkt |
|---|---|
| Konnektortypen auflisten | `GET /api/v1/notify/connector-types` |
| Konnektoren auflisten | `GET /api/v1/notify/connectors` |
| Konnektor erstellen | `POST /api/v1/notify/connectors` |
| Konnektor abrufen | `GET /api/v1/notify/connectors/{id}` |
| Konnektor aktualisieren | `PUT /api/v1/notify/connectors/{id}` |
| Konnektor testen | `POST /api/v1/notify/connectors/{id}/test` |
| Konnektor löschen | `DELETE /api/v1/notify/connectors/{id}` |

## Konnektortypen

Die Typenliste liefert `connectorType`, `capabilities` und `addresses` für jeden Typ, den das laufende Backend registriert. Die Typen sind `email_smtp`, `lark_app`, `lark_webhook`, `slackApp`, `slack_webhook` und `webhook`.

```json
[
  {
    "connectorType": "slack_app",
    "capabilities": {
      "directUser": true,
      "group": true,
      "richText": true,
      "interactive": true,
      "acknowledgement": false,
      "attachments": false
    },
    "addresses": [
      {
        "field": "apiBaseUrl",
        "picker": "site",
        "choices": [
          { "key": "slack", "url": "https://slack.com/api" },
          { "key": "govslack", "url": "https://slack-gov.com/api" }
        ]
      }
    ]
  }
]
```

`addresses` listet die Anbieteradressen auf, die `config` für den jeweiligen Typ speichert. Bei Typen mit manueller Adresseingabe wie Webhook oder SMTP bleibt die Liste leer.

| Feld | Bedeutung |
|---|---|
| `field` | Der Schlüssel in `config`, zum Beispiel `apiBaseUrl`, `serviceUrl` oder `wsUrl`. |
| `choices` | Die zulässigen Adressen, jeweils mit `key` und `url`. Die erste Adresse ist der Standardwert. |
| `picker` | Das Kriterium für die Auswahl aus mehreren Adressen: `site` (Plattform) oder `cloud`. MoleSignal speichert die Auswahl selbst nicht. |
| `byRegion` | Die Adresse richtet sich nach der gewählten Region (Alibaba Cloud, AWS): `https://{service}.{region}.{one of domains}`. `choices` enthält nur die Adresse, die vor der Regionsauswahl gilt. |

Beim Erstellen, Aktualisieren und Testen eines Konnektors sowie beim direkten Versand akzeptiert MoleSignal in diesen Schlüsseln nur Adressen aus der Liste. Bei regionalen Adressen akzeptiert MoleSignal nur die Adresse der in `config` angegebenen Region. Fehlt ein Schlüssel, gilt der Standardwert. MoleSignal lehnt alle anderen Adressen ab, damit keine Zugangsdaten an andere Ziele gelangen.

Das `config`-Objekt eines Konnektors hängt vom Typ ab. Für `timeoutSecs` gilt bei jedem Typ der Standardwert 10. Zulässig sind Werte von 1 bis 60. URLs müssen absolut sein und `http` oder `https` verwenden. Anbieteradressen müssen in `addresses` des jeweiligen Typs aufgeführt sein.

| `connectorType` | Schlüssel in `config` |
|---|---|
| `email_smtp` | `host` und `from` (Pflichtfelder), `port` (Standardwert: `587`), `username`, `password`, `tls` (`none`, `starttls` als Standardwert oder `tls`), `timeoutSecs` |
| `slackApp` | `botToken`, `clientId` und `clientSecret` (ein Bot-Token, eine Client-ID mit Client-Secret oder alle drei), `apiBaseUrl` (Standardwert: `https://slack.com/api`; für GovSlack: `https://slack-gov.com/api`), `timeoutSecs` |
| `slack_webhook` | `webhookUrl` (Pflichtfeld), `timeoutSecs` |
| `lark_app` | `appId` und `appSecret` (Pflichtfelder), `apiBaseUrl` (Standardwert: `https://open.feishu.cn/open-apis` für Feishu; für Lark: `https://open.larksuite.com/open-apis`), `receiveIdType` (`open_id` als Standardwert, `userId`, `union_id`, `email` oder `chatId`), `timeoutSecs` |
| `lark_webhook` | `webhookUrl` (Pflichtfeld), `secret`, `timeoutSecs` |
| `webhook` | `url` (Pflichtfeld), `method` (`post` als Standardwert, `put` oder `patch`), `headers`, `timeoutSecs` |

Unter [Benachrichtigungskanäle](/de/notification-channels) finden Sie eine Beschreibung der einzelnen Anbieter und ihrer Ziele.

## Konnektor erstellen

```http
POST /api/v1/notify/connectors
```

| Feld | Typ | Pflichtfeld | Hinweise |
|---|---|---|---|
| `name` | string | Ja | Innerhalb der Organisation eindeutig. |
| `connectorType` | string | Ja | Einer der oben aufgeführten Typen. Der Typ lässt sich später nicht ändern. |
| `config` | object | Ja | Die Einstellungen für den Typ. |
| `enabled` | boolean | Nein | Standardwert: `true`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/notify/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "Operations webhook",
    "connectorType": "webhook",
    "config": {
      "url": "https://hooks.example.com/molesignal",
      "method": "post",
      "headers": { "Authorization": "Bearer <token>" },
      "timeoutSecs": 5
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "id": "3KEDlokKjNmves95sRzL8tXpflY",
  "organizationId": "<organization-id>",
  "name": "Operations webhook",
  "connectorType": "webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 5
  },
  "capabilities": {
    "directUser": true,
    "group": true,
    "richText": true,
    "interactive": false,
    "acknowledgement": false,
    "attachments": false
  },
  "enabled": true,
  "status": "unknown",
  "lastTestedAt": null,
  "lastTestStatus": null,
  "lastTestError": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

MoleSignal speichert das gesamte `config`-Objekt verschlüsselt. In Antworten ersetzt MoleSignal den Wert jedes Schlüssels mit Zugangsdaten durch `***`. Dazu gehören `url`, `webhookUrl`, `headers` und alle Schlüssel, die auf `password`, `secret` oder `token` enden. Andere Schlüssel wie `host`, `from` und `timeoutSecs` bleiben lesbar.

Bis zum ersten Test lautet `status` `unknown`, danach `connected` oder `error`. `lastTestStatus` lautet `success` oder `failed`. Das Routing überspringt Konnektoren mit dem Status `error`, bis ein späterer Test erfolgreich ist.

## Konnektoren auflisten und abrufen

```http
GET /api/v1/notify/connectors
GET /api/v1/notify/connectors/{id}
```

Die Liste liefert ein Array mit Konnektoren in der oben gezeigten Struktur. Bei einer unbekannten `id` gibt die API `404` zurück.

## Konnektor aktualisieren

```http
PUT /api/v1/notify/connectors/{id}
```

| Feld | Typ | Pflichtfeld | Hinweise |
|---|---|---|---|
| `name` | string | Ja | Der neue Name. |
| `config` | object | Nein | Die neuen Einstellungen. Lassen Sie das Feld weg, um die gespeicherte Konfiguration beizubehalten. |
| `enabled` | boolean | Nein | Standardwert: `true`. Fehlt der Wert, aktiviert MoleSignal den Konnektor. |

Senden Sie für einen maskierten Schlüssel `***`, um den gespeicherten geheimen Wert beizubehalten. Senden Sie einen neuen Wert im Klartext, um ihn zu ersetzen:

```json
{
  "name": "Operations webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 8
  },
  "enabled": true
}
```

## Konnektor testen

```http
POST /api/v1/notify/connectors/{id}/test
```

Der Test sendet eine Nachricht über den Konnektor. Deaktivierte Konnektoren lassen sich nicht testen.

| Feld | Typ | Pflichtfeld | Hinweise |
|---|---|---|---|
| `targetType` | string | Ja | `directUser`, `fixed_address`, `fixed_group` oder `webhook`. Jeder Konnektortyp akzeptiert eine Teilmenge dieser Werte. Zum Beispiel akzeptiert `email_smtp` die Werte `directUser` und `fixed_address`. |
| `target` | string | Ja | Das Empfangsziel: je nach `targetType` eine Adresse, eine Anbieterkennung, eine Gruppe oder eine URL. |
| `message` | object | Nein | `title`, `text`, `markdown` und `html`. Standardmäßig verwendet MoleSignal einen generischen Titel und Text. |

<ResponseExample>
```json 200
{
  "sent": true,
  "testedAt": 1790000000000000,
  "elapsedMs": 3,
  "providerMessageId": "req-1",
  "error": null
}
```
</ResponseExample>

Auch bei fehlgeschlagener Zustellung gibt die API `200` zurück. Dabei lautet `sent` `false`, und `error` enthält den Grund, zum Beispiel `unavailable: webhook request failed`. Der Test aktualisiert außerdem `status`, `lastTestedAt`, `lastTestStatus` und `lastTestError` des Konnektors.

## Konnektor löschen

```http
DELETE /api/v1/notify/connectors/{id}
```

Nach erfolgreichem Löschen gibt die API `204` ohne Antworttext zurück. Solange ein Benutzerendpunkt, eine Benachrichtigungsrichtlinie, eine Fallback-Route, eine geplante Log-Prüfung, eine Statusseite oder Mole Agent in IM auf den Konnektor verweist, gibt die API `409` mit `notify connector is referenced by user endpoints, policies, default routes, scheduled log inspections, status pages, or Mole Agent in IM` zurück. Stellen Sie die Verweise zuerst auf einen anderen Konnektor um.

## Fehler

| Status | Ursache |
|---|---|
| `400` | `config` ist für den Typ ungültig, MoleSignal unterstützt den Typ nicht (`unsupported connector type: pagerduty`), das Ziel passt nicht zum Konnektor oder der Konnektor ist deaktiviert. |
| `404` | Der Konnektor existiert nicht. |
| `409` | Ein anderer Konnektor in der Organisation verwendet den Namen bereits oder beim Löschen bestehen noch Verweise auf den Konnektor. |
| `422` | Ein Feld fehlt oder ein Wert ist ungültig, zum Beispiel ein unbekannter `targetType`. Die Antwort besteht aus reinem Text. |
