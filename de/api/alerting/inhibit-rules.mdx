Die Regeln für die [Unterdrückung](/de/alerting/inhibition). Zum Lesen ist `alerts.inhibitions.read` erforderlich, zum Ändern `alerts.inhibitions.manage`.

```http
GET    /api/v1/alerts/inhibit-rules
POST   /api/v1/alerts/inhibit-rules
GET    /api/v1/alerts/inhibit-rules/{id}
PUT    /api/v1/alerts/inhibit-rules/{id}
DELETE /api/v1/alerts/inhibit-rules/{id}
```

**Anfrageinhalt**

| Feld | Typ | Beschreibung |
|---|---|---|
| `name` | string | Pflichtfeld, höchstens 255 Zeichen. |
| `enabled` | boolean | Standardwert: `true`. |
| `source.matchers` | array | Label-Bedingungen für die Quelle: `{label, op, value}`, wobei `op` den Wert `eq`, `neq`, `re` oder `nre` hat. Alle Bedingungen müssen zutreffen. |
| `source.min_severity` | string | Mindestschweregrad. Ohne Angabe sind alle Schweregrade zulässig. |
| `target.matchers` | array | Label-Bedingungen für das Ziel. Ohne Bedingungen trifft die Auswahl auf jeden Vorfall zu. |
| `target.max_severity` | string | Höchstschweregrad. Ohne Angabe sind alle Schweregrade zulässig. |
| `equal` | array | Höchstens 16 Labels, die Quelle und Ziel mit identischen Werten aufweisen müssen. `source.matchers` und `equal` dürfen nicht beide leer sein. |
| `moreSevereOnly` | boolean | Der Schweregrad der Quelle muss höher sein als der des Ziels. Standardwert: `true`. |
| `waitSecs` | integer | Wartezeit für Benachrichtigungen zum Ziel, 0 bis 600 Sekunden. Standardwert: 60. Werte unter 15 gelten als 15. |
| `lingerSecs` | integer | Dauer, für die die Quelle nach der Behebung weiterhin Benachrichtigungen zu Zielen unterdrückt, 0 bis 3600 Sekunden. Standardwert: 120. |
| `comment` | string | Ein Kommentar. |

In Label-Bedingungen verwenden `service` und `host` den betroffenen Dienst bzw. Host, wenn dem Vorfall das entsprechende Label fehlt. `alert.rule_id` bezeichnet die Regel oder Quelle, die den Vorfall eröffnet hat. Ein ungültiger regulärer Ausdruck führt zu `400`.

Jede Regel enthält in der Liste und in der Detailansicht zusätzlich `inhibiting`: die Anzahl der Vorfälle, deren Benachrichtigungen sie aktuell unterdrückt.

## Vorschau

```http
POST /api/v1/alerts/inhibit-rules/preview
```

Der Anfrageinhalt bleibt gleich (`name` ist optional, und die Regel muss nicht gespeichert sein). Der Aufruf erfordert `alerts.inhibitions.read`. Die Vorschau wendet ausschließlich diese Regel auf die derzeit aktiven Vorfälle an, unabhängig vom Wert von `enabled`.

| Feld | Beschreibung |
|---|---|
| `pairs[].source_incident_id`, `sourceSummary`, `sourceSeverity` | Der Vorfall, der die Benachrichtigungen zu einem anderen Vorfall unterdrückt. |
| `pairs[].target_incident_id`, `targetSummary`, `targetSeverity` | Der Vorfall, dessen Benachrichtigungen die Regel unterdrückt. |

## Unterdrückung für einen Vorfall aufheben

```http
POST /api/v1/alerts/incidents/{id}/inhibition/lift
```

Der Aufruf erfordert `alerts.incidents.update` für den Vorfall. MoleSignal sendet die zurückgehaltenen Benachrichtigungen sofort, unterdrückt keine weiteren Benachrichtigungen für diesen Vorfall und protokolliert die Freigabe in der Zeitleiste und im Audit-Log. Ohne aktive Unterdrückung bleibt der Aufruf wirkungslos. Bei einem behobenen oder zusammengeführten Vorfall liefert er `409`. Der Aufruf gibt den Vorfall zurück.

Im JSON eines Vorfalls geben diese Felder den Status der Unterdrückung an:

| Feld | Beschreibung |
|---|---|
| `inhibition` | Aktive Unterdrückung: `ruleId`, `ruleName`, `sourceIncidentId`, `sourceSummary`, `since` und `endingAt` als Endzeitpunkt nach Behebung des Quellvorfalls. Das Feld bleibt nach Behebung des Vorfalls erhalten und zeigt an, dass beim Beheben keine Benachrichtigung versendet wurde. |
| `inhibitionWaitUntil` | Zeitpunkt in Mikrosekunden, bis zu dem MoleSignal mit Benachrichtigungen auf einen möglichen Quellvorfall wartet. |
| `inhibitionLiftedBy` | Gibt an, wer die Unterdrückung aufgehoben hat. |
