```http
GET /api/v1/alerts/sources/{id}/requests
```

Gibt die Anfragen zurück, die eine [Alarmquelle](/de/alerting/sources) kürzlich empfangen hat, beginnend mit der neuesten. Erfordert `alerts.sources.read`. Der Cluster, der die Anfragen verarbeitet hat, speichert pro Quelle die letzten 500 Anfragen bis zu 7 Tage lang.

**Abfrageparameter**

| Parameter | Typ | Beschreibung |
|---|---|---|
| `limit` | Ganzzahl | Anzahl der zurückzugebenden Anfragen, von 1 bis 200. Standardwert: 50. |

| Feld | Beschreibung |
|---|---|
| `receivedAt` | Empfangszeitpunkt in Mikrosekunden. |
| `viaCluster` | Cluster im Verbund, der die Anfrage weitergeleitet hat. Bei direktem Empfang ist das Feld leer. |
| `status` | `accepted` (angenommen), `rejected` (abgelehnt) oder `forwarded` (an den empfangenden Cluster weitergeleitet). |
| `httpStatus` | HTTP-Statuscode in der Antwort an den Absender. |
| `message` | Grund für die Ablehnung oder dafür, dass keine Aktion ausgeführt wurde. |
| `alertCount` | Anzahl der Alarme in der Anfrage. |
| `alerts` | Für bis zu 100 Alarme: Aktion, Deduplizierungsschlüssel, Titel, Schweregrad, Ergebnis (siehe [Alarme senden](/de/api/alerting/send-alerts)), Grund und Incident-ID. |
| `bodyExcerpt` | Die ersten bis zu 16 KiB des Inhalts einer abgelehnten Anfrage. |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/alerts/sources/$SOURCE_ID/requests?limit=20" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>
