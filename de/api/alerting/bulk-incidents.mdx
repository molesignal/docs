```http
POST /api/v1/alerts/incidents/bulk
```

Führt die Aktion für jeden Incident in `ids` einzeln aus. Lässt sich ein Incident nicht bearbeiten,
fährt der Aufruf mit den übrigen fort. `action` gibt die Aktion an. Geben Sie die dafür erforderlichen Felder daneben an:

| `action` | Felder | Funktion |
|---|---|---|
| `acknowledge` | Keine | Wie [Incident bestätigen](/de/api/alerting/ack-incident). |
| `resolve` | Keine | Wie [Incident beheben](/de/api/alerting/resolve-incident). |
| `snooze` | `durationSecs` | Wie [Incident zurückstellen](/de/api/alerting/snooze-incident). |
| `reassign` | `to`, der Anfragetext von [Incident neu zuweisen](/de/api/alerting/reassign-incident) | Wie beim Einzelaufruf. |
| `set_severity` | `severity` | Wie [Schweregrad eines Incidents festlegen](/de/api/alerting/set-incident-severity). |

Der Aufruf erfordert `alerts.incidents.acknowledge` und prüft jeden Incident genauso wie der jeweilige Einzelaufruf.
Das Zusammenführen ist keine Sammelaktion. Verwenden Sie [Incidents zusammenführen](/de/api/alerting/merge-incidents).

**Anfragetext**

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `ids` | Array | Ja | 1 bis 100 Incident-IDs. Doppelte IDs zählen nur einmal. |
| `action` | String | Ja | `acknowledge`, `resolve`, `snooze`, `reassign` oder `set_severity`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<incident-id>", "<another-incident-id>"], "action": "snooze", "durationSecs": 3600}'
```
</RequestExample>

Die Antwort enthält pro Incident ein Ergebnis mit `id` und bei fehlgeschlagener Bearbeitung zusätzlich `error`, etwa wenn sich der Zustand bereits normalisiert hat oder `durationSecs` außerhalb des zulässigen Bereichs liegt.

<ResponseExample>
```json 200
{
  "results": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW"
    },
    {
      "id": "3KEDQ4mJ8sLp2Xv6Nc1Rt9bYwHe",
      "error": "this incident is no longer active"
    }
  ]
}
```
</ResponseExample>

**Fehler**

| Status | Ursache |
|---|---|
| `400` | `ids` ist leer oder enthält mehr als 100 Incidents. |
| `403` | Dem Token fehlt die Berechtigung `alerts.incidents.acknowledge`. |
| `422` | `action` fehlt oder ist unbekannt, oder ein für die Aktion erforderliches Feld fehlt. |
