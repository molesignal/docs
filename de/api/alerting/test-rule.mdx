```http
POST /api/v1/alerts/rules/{id}/test
```

Führt die Abfrage einer gespeicherten Regel einmal für das Zeitfenster von `now - period_secs` bis `now` aus und meldet, ob die Bedingung erfüllt ist. Der Aufruf ändert nichts: Auswertungsstatus, Incidents, Benachrichtigungen und die Regel selbst bleiben unverändert. Der Aufruf erfordert `alerts.rules.manage` und hat einen leeren Request-Body.

Testen Sie eine Regel, bevor Sie `enabled` auf `true` setzen. Das Speichern einer Regel mit einer ungültigen Anweisung oder einem unbekannten Stream löst keinen Fehler aus. Erst der Test zeigt das Problem.

Eine [APM-Regel](/de/api/alerting/create-rule#apm-regeln) liest ihre Kennzahl aus, statt eine Abfrage auszuführen. Das Ergebnis enthält eine Zeile mit den Spalten `value`, `service` und `trace_id`. Liegt im Zeitfenster kein Wert für die Kennzahl vor, enthält das Ergebnis keine Zeile.

Eine [nach Spalten gruppierte Regel](/de/api/alerting/create-rule#nach-spalten-gruppierte-regeln) listet alle Gruppen in `groups` auf. `matched` ist `true`, wenn mindestens eine Gruppe die Bedingung erfüllt. `value` enthält den Wert der ersten Gruppe, die die Bedingung erfüllt, und `severity` den höchsten Schweregrad aller Gruppen.

Eine [RUM-Regel](/de/api/alerting/create-rule#rum-regeln) liest ihre Kennzahl auf dieselbe Weise aus. Das Ergebnis enthält eine Zeile mit den Spalten `value` und `application`. Liegt im Zeitfenster kein Wert für die Kennzahl vor, enthält das Ergebnis keine Zeile. `scannedRows` gibt an, wie viele Zeilen der Kennzahl zugrunde liegen.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/test \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "matched": true,
  "value": 2.0,
  "severity": "critical",
  "columns": ["c"],
  "rows": [[2]],
  "scannedRows": 2,
  "tookMs": 170
}
```
</ResponseExample>

**Antwort**

| Feld | Typ | Hinweise |
|---|---|---|
| `matched` | boolescher Wert | Gibt an, ob die Bedingung aktuell erfüllt ist. Das Ergebnis berücksichtigt `forPeriods` nicht. |
| `value` | Zahl oder null | Wert der ersten Spalte in der ersten Zeile. `null`, wenn das Ergebnis keine Zahl enthält. |
| `severity` | Zeichenfolge oder null | Schweregrad, den ein Incident erhalten würde. `null`, wenn `matched` den Wert `false` hat. |
| `columns` | Array | Spaltennamen des Abfrageergebnisses. |
| `rows` | Array | Bis zu 20 Zeilen des Ergebnisses. |
| `scannedRows` | Ganzzahl | Anzahl der von der Abfrage gescannten Zeilen. |
| `tookMs` | Ganzzahl | Dauer der Abfrage in Millisekunden. |
| `anomaly` | Objekt | Nur für `anomaly`-Regeln. Enthält `baseline`, `deviation`, `score` von 0 bis 1 und eine Begründung als Text in `reason`. |
| `noData` | boolescher Wert | Nur bei `true`: Die Ausführung lieferte keinen Wert und die Regel wertet einen fehlenden Wert nicht als `0`. |
| `groups` | Array | Nur für nach Spalten gruppierte Regeln, in der Reihenfolge des Ergebnisses. Jede Gruppe enthält `labels` mit der Zuordnung der Spalten zu ihren jeweiligen Werten sowie `value`, `matched` und `severity`. |
| `groupsTruncated` | boolescher Wert | Nur bei `true`: Das Ergebnis umfasst mehr als 100 Gruppen und führt die übrigen Gruppen nicht auf. |

**Fehler**

| Status | Ursache |
|---|---|
| `400` | Die Abfrage lässt sich nicht ausführen, etwa wegen ungültigem SQL oder eines unbekannten Felds. Oder: Für eine `anomaly`-Regel fehlen brauchbare Verlaufsdaten für den Referenzwert. Oder: Die Regel ist vom Typ `composite` oder `heartbeat` und führt keine Abfrage aus. |
| `403` | Der Stream der Regel existiert nicht oder dem Token fehlt `alerts.rules.manage`. |
| `404` | Die Regel existiert nicht. |
