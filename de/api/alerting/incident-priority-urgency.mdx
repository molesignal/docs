```http
PUT /api/v1/alerts/incidents/{id}/priority
PUT /api/v1/alerts/incidents/{id}/urgency
```

Beide Aufrufe erfordern `alerts.incidents.update` sowie einen aktiven Incident, der nicht mit einem anderen zusammengeführt wurde. Die
Zeitleiste protokolliert `priority_changed` und `urgency_changed`.

- **Priorität**: Geben Sie im Request-Body `{"priority": "P2"}` oder `null` für keine Priorität an. Wählen Sie eine der
  [Prioritätsstufen](/de/alerting/on-call#dringlichkeits-und-prioritätsstufen) der Organisation. Der Aufruf ändert nur die Priorität und
  löst keine erneuten Benachrichtigungen aus.
- **Dringlichkeit**: Geben Sie im Request-Body den Schlüssel einer Dringlichkeitsstufe der Organisation an, etwa
  `{"urgency": "high"}`. Der Aufruf speichert den Aufrufer in `urgencySetBy`. Die Supportzeiten ändern die Dringlichkeit danach nicht
  mehr. Eine höhere Dringlichkeit für einen Incident im Status `open` löst ab dem ersten zutreffenden Eskalationsschritt erneut Benachrichtigungen aus,
  mit `escalation.reason` `urgency_raised`. Eine niedrigere Stufe ändert nur die Dringlichkeit. Eine Stufe,
  die keine weiteren Eskalationsschritte auslöst, stoppt die weitere Eskalation.

Verwenden Sie für mehrere Incidents gleichzeitig [Sammelaktionen](/de/api/alerting/bulk-incidents) mit
`{"action": "set_priority", "priority": "P2"}` und `{"action": "set_urgency", "urgency": "low"}`.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/urgency \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"urgency": "high"}'
```
</RequestExample>

Die Antwort enthält den Incident. `urgency` enthält den Schlüssel einer Dringlichkeitsstufe (bei Incidents, die vor Einführung des Felds
eröffnet wurden, fehlt das Feld und die Dringlichkeit gilt als hoch). `priority` liegt zwischen `P1` und `P9` oder fehlt. `urgencyByPolicy` ist
`true`, wenn die Dringlichkeit aus der Eskalationsrichtlinie stammt.

**Fehler**

| Status | Grund |
|---|---|
| `400` | Die Priorität liegt außerhalb der Stufen der Organisation oder die Dringlichkeit entspricht keiner ihrer Stufen. |
| `422` | Die Priorität liegt nicht zwischen `P1` und `P9` oder der Dringlichkeitsschlüssel besteht nicht ausschließlich aus Kleinbuchstaben, Ziffern und Unterstrichen. |
| `403` | Dem Token fehlt `alerts.incidents.update` oder der Zugriff auf den Incident. |
| `404` | Der Incident existiert nicht. |
| `409` | Der Incident hat sich erledigt oder wurde mit einem anderen zusammengeführt. |
