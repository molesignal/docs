```http
POST /api/v1/alerts/routing/rules
```

Erstellt eine [Routing-Regel](/de/alerting/routing#routing-regeln). Dafür ist `alerts.routing.manage` erforderlich. Die neue Regel steht am Ende der Liste. Mit [Routing-Regeln neu anordnen](/de/api/alerting/reorder-routing-rules) können Sie die Regel nach oben verschieben. Eine Organisation kann höchstens 200 Routing-Regeln haben.

| Feld | Typ | Beschreibung |
|---|---|---|
| `name` | string | Pflichtfeld. Nach dem Entfernen führender und nachgestellter Leerzeichen sind 1 bis 128 Zeichen zulässig. |
| `enabled` | boolean | Standardwert: `true`. |
| `conditions` | array | Höchstens 16 Bedingungen, standardmäßig leer. Ein `key` umfasst 1 bis 512 Zeichen. `equals`, `not_equals` und `matches` erwarten jeweils einen Wert, `in` erwartet 1 bis 100 Werte. Jeder Wert darf höchstens 512 Zeichen umfassen. Das Muster für `matches` muss sich kompilieren lassen. |
| `minSeverity` | string \| null | `info`, `warning`, `error` oder `critical`. Standardmäßig sind alle Schweregrade zulässig. |
| `origins` | array | Auswahl aus `rule`, `external` und `synthetic`. Standardmäßig ist die Liste leer und schließt damit alle Quellen ein. |
| `target` | object | Pflichtfeld. `{"kind": "team", "teamId": …}` muss auf ein Team der Organisation verweisen, `{"kind": "policy", "policyId": …}` auf eine Eskalationsrichtlinie der Organisation. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "conditions": [{"key": "env", "operator": "equals", "values": ["prod"]}], "minSeverity": "error", "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

Die Antwort enthält die neue Regel. Siehe [Regelfelder](/de/api/alerting/list-routing-rules#regelfelder).

**Fehler**

| Status | Ursache |
|---|---|
| `400` | Ein Feld ist ungültig: Der Name ist leer, die Anzahl der Werte einer Bedingung ist falsch, ein Muster lässt sich nicht kompilieren oder das Zielteam bzw. die Zielrichtlinie existiert nicht. Der Fehler tritt auch auf, wenn bereits 200 Regeln existieren. |
| `403` | Dem Token fehlt `alerts.routing.manage`. |
| `422` | `name` oder `target` fehlt oder ein Wert ist unbekannt, etwa ein unbekannter `operator`. Die Antwort enthält Klartext. |
