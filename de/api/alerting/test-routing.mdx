```http
POST /api/v1/alerts/routing/test
```

Ermittelt anhand der aktuellen Routingregeln, Bereitschaftsrichtlinien der Teams und des Servicekatalogs, wie das System einen Incident mit diesen Labels [weiterleiten](/de/alerting/routing#routing-reihenfolge) würde. Dafür ist `alerts.routing.read` erforderlich. Die Auswertung geht davon aus, dass die Quelle die Standardrichtlinie verwendet. Das System öffnet keinen Incident und sendet keine Benachrichtigungen.

| Feld | Typ | Beschreibung |
|---|---|---|
| `labels` | object | Die Labels des Incidents. Das Label `alert.source` gibt die Herkunft an: `external` steht für eine Alarmquelle, `synthetic` für eine synthetische Prüfung und jeder andere Wert für eine Alarmregel. |
| `services` | array | Betroffene Services. Fehlen die Labels `service.name` und `service`, verwendet das System den ersten Service. |
| `severity` | string | `info`, `warning` (Standard), `error` oder `critical`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"labels": {"service.name": "checkout", "env": "prod"}, "severity": "critical"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "decision": {
    "escalationPolicyId": "<policy-id>",
    "teamId": "<team-id>",
    "routing": { "reason": "rule", "ruleId": "<rule-id>", "ruleName": "Payments in production" }
  },
  "matchedRuleId": "<rule-id>",
  "service": "default/checkout",
  "serviceTeamId": "<team-id>",
  "labelTeamId": null
}
```
</ResponseExample>

| Feld | Beschreibung |
|---|---|
| `decision.escalation_policy_id` | Die Eskalationsrichtlinie, die für den Incident gelten würde. `default` steht für die Standardrichtlinie. |
| `decision.team_id` | Das Team, an das das System den Incident weiterleiten würde, oder `null`. |
| `decision.routing` | Die Begründung für die Routingentscheidung. Entspricht `routing` bei einem Incident. Siehe [Incident-Felder](/de/api/alerting/list-incidents#incident-felder). |
| `matchedRuleId` | Die zutreffende Routingregel oder `null`. |
| `service` | Der Service, für den das System das zuständige Team ermittelt, im Format `namespace/name`. |
| `serviceTeamId` | Das laut Servicekatalog für diesen Service zuständige Team. |
| `labelTeamId` | Das Team, auf das das Label `teamId` oder `team` verweist. |
