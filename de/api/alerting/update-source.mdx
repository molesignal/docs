```http
PUT /api/v1/alerts/sources/{id}
```

Schreibt die Einstellungen einer [Alarmquelle](/de/alerting/sources) vollständig zurück. Dafür ist `alerts.sources.manage` erforderlich. Es gelten dieselben Felder wie unter [Alarmquelle erstellen](/de/api/alerting/create-source). Der Typ lässt sich nicht ändern. Falls Sie `kind` angeben, muss der Wert dem aktuellen Typ entsprechen. Das Token bleibt unverändert. Unter [Token rotieren](/de/api/alerting/rotate-source-token) steht, wie Sie es ändern. Ohne `homeCluster` bleibt der empfangende Cluster unverändert. Bereits offene Vorfälle behalten ihre Eskalationsrichtlinie und ihre Labels.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/sources/$SOURCE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Production Prometheus", "enabled": false, "escalationPolicyId": "default", "severity": "error"}'
```
</RequestExample>

Die Antwort enthält die aktualisierte Quelle ohne `token`.

**Fehler**

| Status | Ursache |
|---|---|
| `400` | Ein Feld ist ungültig oder der angegebene Typ weicht vom aktuellen ab. |
| `403` | Dem Token fehlt die Berechtigung `alerts.sources.manage`. |
| `404` | Die Quelle existiert nicht. |
