Zu einem Incident gibt es höchstens ein internes Postmortem im Markdown-Format. Es bleibt von den
[Postmortems der Statusseiten](/de/status-pages#postmortems) getrennt. Die Statusseiten können die Zusammenfassung übernehmen. Einzelheiten zur
Verwendung auf Statusseiten stehen unter [Schwerwiegende Incidents und Postmortems](/de/alerting/major-incidents#postmortems).

| Methode und Pfad | Funktion | Berechtigung |
|---|---|---|
| `GET /api/v1/alerts/postmortems` | Listet die Postmortems der Organisation auf, die neuesten zuerst, jeweils mit der Anzahl der Maßnahmen. | `postmortems.read` |
| `GET /api/v1/alerts/incidents/{id}/postmortem` | Gibt das Postmortem des Incidents und die zugehörigen Maßnahmen zurück. | `alerts.incidents.read` für den Incident und `postmortems.read` |
| `POST /api/v1/alerts/incidents/{id}/postmortem` | Erstellt ein Postmortem für den Incident. | `alerts.incidents.read` für den Incident und `postmortems.manage` |
| `PUT /api/v1/alerts/postmortems/{id}` | Ändert Titel, Inhalt, Status, Zuständigkeit und die Liste der Prüfenden eines Postmortems. | `postmortems.manage` |
| `POST /api/v1/alerts/postmortems/{id}/actions` | Fügt eine Maßnahme hinzu. | `postmortems.manage` |
| `PUT /api/v1/alerts/postmortems/{id}/actions/{actionId}` | Ändert eine Maßnahme. | `postmortems.manage` |
| `DELETE /api/v1/alerts/postmortems/{id}/actions/{actionId}` | Löscht eine Maßnahme. | `postmortems.manage` |
| `POST /api/v1/alerts/postmortems/{id}/actions/{actionId}/ticket` | Erstellt ein Ticket für eine Maßnahme. | `postmortems.manage` |

## Postmortem erstellen und ändern

```http
POST /api/v1/alerts/incidents/{id}/postmortem
```

| Feld | Typ | Erforderlich | Hinweise |
|---|---|---|---|
| `title` | string | Ja | 1 bis 200 Zeichen. |
| `body` | string | Nein | Inhalt im Markdown-Format, bis zu 100000 Zeichen. |

Wenn für den Incident bereits ein Postmortem existiert, antwortet die API mit `409`. Die Seiten erstellen zunächst anhand einer Vorlage einen Entwurf
(Zusammenfassung, Auswirkungen, Zeitverlauf, Ursache, was gut lief, was schlecht lief, Maßnahmen) und rufen dann den Endpunkt auf.
Das Audit-Log protokolliert die Erstellung. Senden Sie bei einer Änderung nur die zu ändernden Felder: `title`, `body`,
`status`, `ownerId` (mit `null` entfernen Sie die Zuweisung) und `reviewerIds`.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/postmortems/$POSTMORTEM_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"status": "in_review", "reviewerIds": ["<user-id>"]}'
```
</RequestExample>

Beim Abrufen, Erstellen und Ändern gibt die API `{ "postmortem": { ... }, "actions": [ ... ] }` zurück. `postmortem` hat den Wert
`null`, wenn für den Incident kein Postmortem existiert.

```json 200
{

    "ownerId": "<user-id>",
    "reviewerIds": ["<user-id>"],
```

| Feld | Hinweise |
|---|---|
| `status` | `draft`, `in_review` oder `published`. Beim ersten Wechsel zu `published` setzt die API `publishedAt`. |

Jeder Listeneintrag enthält neben den Feldern des Postmortems die Incident-Zusammenfassung `incidentSummary`, die Anzahl der
noch offenen Maßnahmen `openActions` und die Anzahl der offenen Maßnahmen mit überschrittener Frist `overdueActions`.

## Maßnahmen

Senden Sie zum Hinzufügen einer Maßnahme `{ "title": "…", "ownerId": "<user-id>", "dueAt": 1790600000000000 }`. Der Titel muss 1
bis 300 Zeichen lang sein. Pro Postmortem sind bis zu 50 Maßnahmen möglich. Geben Sie `dueAt` in Unix-Mikrosekunden an. Senden Sie bei Änderungen nur die
zu ändernden Felder: `title`, `ownerId` und `dueAt` (mit `null` leeren Sie das jeweilige Feld) sowie `status` (`open` oder `done`).
Beim Hinzufügen und Ändern gibt die API die Maßnahme zurück, beim Löschen `{ "deleted": true }`.

```http
POST /api/v1/alerts/postmortems/{id}/actions/{actionId}/ticket
```

Senden Sie `{ "connectorId": "<connector-id>" }` als Request-Body. Die API erstellt über den angegebenen
[Ticket-Konnektor](/de/api/alerting/tickets) ein Ticket für die Maßnahme und gibt die Maßnahme mit `ticketKey` und
`ticketUrl` zurück. Falls bereits ein Ticket existiert, gibt die API die Maßnahme unverändert zurück. Das Ticket übernimmt keine Kommentare oder
Statuswechsel aus dem Incident. Das Abschließen des Tickets löst den Incident nicht.

**Fehler**

| Status | Grund |
|---|---|
| `400` | Ein Feldwert liegt außerhalb der zulässigen Grenzen oder der Ticket-Konnektor ist deaktiviert. |
| `403` | Eine Berechtigung fehlt oder der Zugriff auf den Incident ist nicht möglich. |
| `404` | Der Incident, das Postmortem, die Maßnahme oder der Ticket-Konnektor existiert nicht. |
| `409` | Für den Incident existiert bereits ein Postmortem. |
