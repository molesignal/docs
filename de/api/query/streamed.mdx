```http
GET  /api/v1/query/stream
POST /api/v1/query/stream
```

Der Endpunkt antwortet immer mit NDJSON in Chunks (`application/x-ndjson`). Jede Zeile enthält ein JSON-Objekt mit den Spaltennamen als Schlüsseln. Die letzte Zeile lautet `{"__meta__":{"scannedRows":...,"tookMs":...}}`. Der Endpunkt führt Abfragen nie als asynchrone Jobs aus. Der Aufruf erfordert `streams.query` oder im System-Scope `sys.telemetry.read`.

Die `POST`-Variante erwartet denselben Request-Body wie [Abfrage ausführen](/de/api/query/execute). Die `GET`-Variante erwartet Abfrageparameter:

| Parameter | Erforderlich | Hinweise |
|---|---|---|
| `sql` | Ja | Die SQL-Anweisung. Fehlt der Wert, antwortet der Endpunkt mit `400`. |
| `stream` | Ja | Der Name des primären Streams. |
| `streamType` | Nein | `logs`, `metrics`, `traces`, `profiles` oder `extend`. Standard: `logs`. |
| `from`, `to` | Ja | Zeitbereich in Mikrosekunden. |
| `limit` | Nein | Maximale Anzahl von Zeilen. |

<RequestExample>
```bash cURL
NOW=$(date +%s)000000

curl -G http://localhost:5080/api/v1/query/stream \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "sql=SELECT level, msg FROM app ORDER BY _timestamp DESC" \
  --data-urlencode "stream=app" \
  --data-urlencode "streamType=logs" \
  --data-urlencode "from=$((NOW-3600000000))" \
  --data-urlencode "to=$((NOW+60000000))" \
  --data-urlencode "limit=3"
```
</RequestExample>

<ResponseExample>
```text 200
{"level":"info","msg":"fine"}
{"level":"error","msg":"db pool exhausted"}
{"__meta__":{"scannedRows":5,"tookMs":173}}
```
</ResponseExample>

Deaktivieren Sie die Pufferung von Antworten am Proxy (`proxy_buffering off`), damit die Zeilen eintreffen, sobald sie vorliegen. Lassen Sie auch lange Lesevorgänge zu. Beenden Sie den Lesevorgang, um den Stream abzubrechen.
