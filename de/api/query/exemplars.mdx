```http
GET  /api/v1/prometheus/api/v1/query_exemplars
POST /api/v1/prometheus/api/v1/query_exemplars
```

Gibt die Exemplare der Zeitreihen zurück, die ein PromQL-Ausdruck auswählt. Die Antwort hat dasselbe Format wie beim Endpunkt `query_exemplars` der Prometheus HTTP API. Die Seite **Metriken** bezieht ihre Exemplare über diesen Endpunkt. Der Aufruf erfordert `metrics.read` oder im Systembereich `sys.telemetry.read`.

Die Exemplare stammen aus [Prometheus Remote Write](/de/intake#prometheus-remote_write) und werden zusammen mit den Messwerten gespeichert. Bei OTLP-Metriken speichert MoleSignal keine Exemplare.

`GET` übernimmt die Parameter aus dem Query-String, `POST` aus den Formulardaten (`application/x-www-form-urlencoded`):

| Parameter | Erforderlich | Hinweise |
|---|---|---|
| `query` | Ja | Ein PromQL-Ausdruck. Jeder Selektor darin muss den Namen seiner Metrik angeben. |
| `start` | Ja | Sekunden seit der Unix-Epoche, auch mit Nachkommastellen, oder ein Zeitstempel nach RFC 3339. |
| `end` | Ja | Dieselben Formate. Darf nicht vor `start` liegen. |

Nur die Selektoren des Ausdrucks zählen: Jeder wählt die Zeitreihen seiner Metrik aus, deren Labels die Filterbedingungen erfüllen. Funktionen, Operatoren und die Dauer von Zeitfenstern ändern das Ergebnis nicht. Sendet Remote Write ein Exemplar zweimal, etwa bei einem erneuten Sendeversuch, enthält die Antwort es nur einmal. Die Antwort enthält höchstens 10.000 Exemplare und bei einer Kürzung einen Warnhinweis. Eine Anfrage wartet wie eine Abfrage auf einen freien Platz in der [Zulassungssteuerung](/de/configuration#zulassungssteuerung). MoleSignal speichert die Antwort nie im Cache.

Die [Feldmaskierung](/de/settings/data-security#feldmaskierung) gilt für die Labels der Zeitreihen und der Exemplare. Eine Maskierungsregel für `value` oder `_timestamp` lässt die Anfrage fehlschlagen, da das Prometheus-Format keine maskierten Werte unterstützt.

<RequestExample>
```bash cURL
curl -G http://localhost:5080/api/v1/prometheus/api/v1/query_exemplars \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'query=histogram_quantile(0.95, rate(http_request_duration_seconds_bucket{service="checkout"}[5m]))' \
  --data-urlencode "start=$(( $(date +%s) - 3600 ))" \
  --data-urlencode "end=$(date +%s)"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "status": "success",
  "data": [
    {
      "seriesLabels": {
        "__name__": "http_request_duration_seconds_bucket",
        "le": "0.5",
        "service": "checkout"
      },
      "exemplars": [
        {
          "labels": { "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736", "span_id": "00f067aa0ba902b7" },
          "value": 0.43,
          "timestamp": 1790000000.123
        }
      ]
    }
  ]
}
```
</ResponseExample>

| Feld | Hinweise |
|---|---|
| `data[].seriesLabels` | Die Labels der Zeitreihe, mit dem Metriknamen als `__name__`. |
| `data[].exemplars[]` | Die Exemplare der Zeitreihe im angegebenen Zeitraum, beginnend mit dem ältesten. |
| `labels` | Die Labels des Exemplars, etwa `trace_id` und `span_id`. |
| `value` | Der im Exemplar erfasste Messwert. |
| `timestamp` | Sekunden seit der Unix-Epoche, mit Nachkommastellen. |
| `warnings` | Nur vorhanden, wenn der Endpunkt die Antwort auf 10.000 Exemplare begrenzt hat. |

**Fehler**

| Status | Ursache |
|---|---|
| `400` | `query` ist leer oder kein gültiger PromQL-Ausdruck, ein Selektor gibt keine Metrik an, eine Zeitangabe entspricht keinem der beiden Formate oder `end` liegt vor `start`. |
| `403` | Dem Token fehlt `metrics.read` oder eine Maskierungsregel gilt für `value` oder `_timestamp`. |
| `429` | Die [Zulassungssteuerung](/de/configuration#zulassungssteuerung) hat die Anfrage abgewiesen. |

Bei diesen Fehlern verwendet der Endpunkt das [Fehlerantwortformat](/de/api-reference#antworten-und-fehler) der anderen Endpunkte, nicht das von Prometheus.
