## Autorisierungsmodell

Ein Endpunkt kann Folgendes voraussetzen:

- eine Organisationsberechtigung wie `streams.query` oder `alerts.rules.manage`;
- eine Plattformberechtigung wie `sys.telemetry.read`;
- Eigentümerschaft, eine Beziehung oder eine explizite Zugriffsberechtigung auf Ressourcenebene;
- eine Sitzung für eine öffentliche Freigabe, die auf eine Ressource beschränkt ist.

Leiten Sie Berechtigungen nicht aus der angezeigten Rolle ab. Fragen Sie `/api/v1/iam/capabilities` ab, um den aktuellen Stand der wirksamen
Berechtigungen und verfügbaren Funktionen zu ermitteln.

## Anfrage auswählen und überprüfen

Beginnen Sie mit der verlinkten Anleitung zur passenden Gruppe. Prüfen Sie vor der Nutzung eines Endpunkts die HTTP-Methode, die erforderliche Berechtigung, den organisatorischen Geltungsbereich, die Anfragefelder und das Antwortformat. Eine Gruppe kann sowohl Verwaltungsanfragen als auch Datenabfragen mit unterschiedlichen Berechtigungen enthalten.

Überprüfen Sie die ausgewählte Organisation und Ressource mit der dokumentierten Leseanfrage, bevor Sie die Konfiguration ändern. Lesen Sie die Ressource nach einem Schreibvorgang erneut aus oder fragen Sie ein kontrolliertes Testereignis ab, um das erwartete Ergebnis zu bestätigen. Eine erfolgreiche HTTP-Antwort allein bestätigt weder, dass die Telemetriedaten den vorgesehenen Stream erreicht haben, noch, dass ein Vorfall behoben ist.

Beachten Sie bei Fehlern die [API-Einführung](/de/api-reference) und die Hinweise zum jeweiligen Endpunkt. Geben Sie beim [Melden einer Abweichung von der Dokumentation](/de/support) die laufende Version, eine Anfrage mit geschwärzten vertraulichen Angaben und die Anfrage-IDs an; lassen Sie Zugangsdaten und sensible Ereignisdaten weg.
