MoleSignal stellt eine versionierte HTTP-API bereit. Produkt-Endpunkte verwenden `/api/v1`. Die Health-Probe, Prometheus-Metriken, öffentliche Freigabelinks und einige Kompatibilitätsprotokolle verwenden ebenfalls andere Pfade.

## Basis-URL

Für eine lokale Instanz:

```text
http://localhost:5080/api/v1
```

Ersetzen Sie in der Produktion den Host durch die öffentliche Adresse der Bereitstellung, also den Wert von `[http].external_url`.

## Authentifizierung

Geschützte Endpunkte akzeptieren ein Bearer-Token im `Authorization`-Header:

```http
Authorization: Bearer <token>
```

| Token | So erhalten Sie es | Gültigkeitsdauer |
|---|---|---|
| API-Token | **Kontoeinstellungen → API-Token**, oder [API-Token ausstellen](/de/api/auth/issue-token). Token haben die Form `mspat-<36>`. | Bis zum Widerruf oder bis zum gewählten Ablauf. |
| Standard-Intake-Token | `GET /api/v1/me/api-tokens/default`. Beschränkt auf `logs.write`, `metrics.write`, `traces.write`, `profiles.write` und `apm.deploy`. | Läuft nicht ab. |
| RUM-Client-Token | `GET /api/v1/auth/tokens/rum?applicationId=<id>`. Beschränkt auf `rum.write`. | Läuft nicht ab. |

Verwenden Sie ein API-Token für Skripte und Collectors. Siehe [Datenquelle](/de/intake#intake-token) für die Intake-Token.

Die Web-UI meldet sich mit `POST /api/v1/auth/signin` an; dabei werden Session-Cookies gesetzt, statt ein Token zurückzugeben. Der `Authorization`-Header akzeptiert kein Session-Token. Siehe [Anmelden](/de/api/auth/login).

Die Authentifizierung erstellt einen IAM-Kontext mit dem Subjekt, dem aktiven Organisations- oder Plattform-Scope und den effektiven Berechtigungen. Die Organisation einer Anfrage stammt immer aus diesem Kontext. Request-Bodys können keine andere Organisation auswählen.

## Öffentliche und selbstauthentifizierende Routen

Einige Routen können kein Organisations-Bearer-Token verwenden. Stattdessen validieren sie eine engere Anmeldeinformation oder eine Richtlinie:

- Anmeldung, Registrierungsrichtlinie und Passwortzurücksetzung;
- `GET /api/v1/healthz` und die oberste `/metrics`;
- öffentliche Anfragen zum Austausch von Ressourcenfreigaben und für Share-Sessions;
- signierte Dateidownloads und öffentliche Avatare;
- Push-Connector-Endpunkte, die ein Push-Token validieren.

Eine öffentliche Route ist nicht uneingeschränkt. Ihr Handler prüft die Registrierungsrichtlinie, ein Share-Token, ein Download-Token, eine Signatur oder das Connector-Credential.

## Autorisierung

Ein Endpunkt kann eine oder mehrere dieser Bedingungen erfordern:

- eine Organisationsberechtigung wie `streams.query`;
- eine Plattformberechtigung wie `sys.telemetry.read`;
- Eigentümerschaft an einer Ressource, eine Beziehung zu ihr oder eine organisationsübergreifende Berechtigung.

`GET /api/v1/iam/capabilities` gibt die effektiven Berechtigungen des aktuellen Subjekts zurück. Leiten Sie Zugriff nicht aus einem Rollennamen oder einem sichtbaren Menüeintrag ab.

## Anfragen

- Die meisten Request-Bodys sind JSON mit `Content-Type: application/json`.
- Kompatibilitäts-Intake-Endpunkte verwenden die Nutzlast ihres Protokolls, etwa Protobuf, NDJSON oder einen gzip-komprimierten Body.
- Intake-Request-Bodys, die größer als 2 MiB sind – bzw. 16 MiB bei nativem JSON-Intake –, werden mit `413` abgelehnt.
- Zeitangaben sind Ganzzahlen in Mikrosekunden seit der Unix-Epoche. Ein Zeitpunkt wird nach dem benannt, was passiert ist (`createdAt`, `expiresAt`), wobei `Time` ergänzt wird, wo ein einzelnes Wort unklar wäre (`startTime`); eine Zeitdauer endet auf `Time` (`p95Time`), sofern ihr Name dies nicht bereits aussagt (`duration`). Native Telemetrie-Datensätze verwenden `_timestamp`, ebenfalls in Mikrosekunden.
- Kodieren Sie Pfad-IDs und Stream-Namen URL-konform.

## Antworten und Fehler

Eine erfolgreiche Antwort ist JSON, sofern der Endpunkt keine Datei streamt oder herunterlädt. Eine Fehlerantwort enthält einen Statuscode und einen JSON-Body mit einem maschinenlesbaren `error`-Code und einer `message`:

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

Ein `validation_failed`-Fehler ergänzt ein `issues`-Array mit einem Eintrag pro ungültigem Feld.

| Status | `error` | Bedeutung |
|---|---|---|
| `400` | `invalid_argument`, `validation_failed` | Die Anfrage oder einer ihrer Parameter ist ungültig. |
| `401` | `unauthorized` | Das Token fehlt, ist fehlerhaft, ungültig oder abgelaufen. |
| `403` | `forbidden` | Die Berechtigung, Beziehung oder der Scope fehlt. |
| `404` | `not_found` | Die Ressource existiert nicht oder ist im autorisierten Scope nicht sichtbar. |
| `409` | `conflict` | Ein Zustands- oder Eindeutigkeitskonflikt. |
| `413` | `payload_too_large` | Der Body überschreitet das Limit. |
| `429` | `resource_exhausted` | Ein Rate-Limit ist aktiv. Beachten Sie den `Retry-After`-Header, falls vorhanden. |
| `499` | `cancelled` | Die Anfrage wurde abgebrochen. |
| `503` | `unavailable` | Eine Abhängigkeit ist nicht verfügbar. |
| `500` | `internal` | Ein interner Fehler. Der Body enthält die Meldung `internal error`, und die Details verbleiben im Server-Log. |

Eine Anfrage, deren Body nicht geparst werden kann, schlägt fehl, bevor sie den Endpunkt erreicht. Diese Antwort ist Klartext statt JSON:

| Status | Bedeutung |
|---|---|
| `400` | Der Body ist kein gültiges JSON. |
| `415` | Der Anfrage fehlt `Content-Type: application/json`. |
| `422` | Ein Feld fehlt oder hat den falschen Typ. Der Text nennt das Feld. |

Jede Antwort enthält die Header `X-Request-Id` und `X-Trace-Id`. Geben Sie beide an, wenn Sie einen serverseitigen Fehler melden.

## Paginierung

Endpunkte, die viele Zeilen zurückgeben können, akzeptieren `limit` und `cursor`. Eine solche Antwort enthält `items` und `nextCursor`. Übergeben Sie `nextCursor` als `cursor`, um die nächste Seite zu lesen, und stoppen Sie, wenn er leer ist. Andere Listen-Endpunkte geben die vollständige Liste zurück. Siehe die Seite des jeweiligen Endpunkts.

## Query und langlaufende Vorgänge

Die Query-Familie gibt reguläres JSON zurück, streamt NDJSON und führt lange Queries als asynchrone Suchjobs aus. Eine zu große Query antwortet mit `202` sowie einem `jobId` und einem `monitor`-Pfad. Aufrufer, die streamen, müssen Teilauslieferungen verarbeiten und die Anfrage abbrechen, wenn das Ergebnis nicht mehr benötigt wird. Siehe [Query](/de/query).

Große Artefakte wie generierte Berichte, Profil-Blobs und Exporte werden als Dateien über ein bereichsbezogenes Download-Token statt innerhalb eines JSON-Bodys ausgeliefert.
