Eine **Erweiterungstabelle** ist eine kleine Nachschlagetabelle in MoleSignal, die Schlüsseln Datensätze zuordnet. Eine
Transformation in einer [Pipeline](/de/pipelines) schlägt darin einen Schlüssel nach und reichert Ereignisse mit Referenzdaten an: So lässt sich ein
`service` dem zuständigen Team, eine Konto-ID einer Tarifstufe oder ein Regionscode einem Regionsnamen zuordnen,
ohne im zeitkritischen Verarbeitungspfad auf einen externen Datenspeicher zuzugreifen.

## Tabellenliste

Öffnen Sie **Tabellen erweitern**. Im Kopfbereich steht die Anzahl der Tabellen und ihrer Datensätze. Für jede Tabelle zeigt die Liste den Suchschlüssel,
die Felder, die Anzahl der Datensätze, den Verwendungsort, die letzte Aktualisierung und den Status **Funktionsfähig** oder
**Leer**. Filtern Sie nach Status und Nutzung (**In Verwendung** oder **Nicht in Verwendung**) und suchen Sie nach Namen.

## Tabelle erstellen

Wählen Sie **Neue Erweiterungstabelle**. Der Assistent führt durch zwei Schritte.

<Steps>
  <Step title="Schema definieren">
    Geben Sie unter **Tabelle** einen Namen und unter **Beschreibung** eine Beschreibung ein. Wählen Sie als **Suchschlüssel** das Feld, das einen
    Datensatz identifiziert, etwa `customer_id`, `service` oder `region_code`. Fügen Sie unter **Wertfelder** Felder hinzu. Geben Sie für jedes **Feld**
    den Namen und den **Typ** (**Zeichenfolge**, **Zahl**, **Boolescher Wert** oder **Objekt**) an, legen Sie fest, ob es **Erforderlich** ist,
    und geben Sie eine Beschreibung ein. Lassen Sie die Wertfelder leer, um stattdessen JSON-Datensätze mit flexibler Struktur zu speichern. Eine Tabelle kann
    bis zu 100 Wertfelder enthalten. Feldnamen dürfen Buchstaben, Ziffern, `.`, `-` und `_` enthalten.
  </Step>
  <Step title="Daten hinzufügen oder importieren">
    Wählen Sie **Leer beginnen**, um später Datensätze hinzuzufügen, oder **JSON einfügen**, um sie sofort zu laden. Verwenden Sie ein JSON-Array aus
    Datensätzen, die jeweils den Suchschlüssel enthalten, oder ein Objekt, das jedem Schlüssel den zugehörigen Datensatz zuordnet.
  </Step>
</Steps>

Wählen Sie **Erweiterungstabelle erstellen**.

## Datensätze

Öffnen Sie eine Tabelle. Der Tab **Datensätze** listet die Datensätze auf. Suchen Sie darin nach dem Suchschlüssel oder einem Feldwert.

| Aktion | Auswirkung |
|---|---|
| **Datensatz hinzufügen** | Geben Sie den Suchschlüssel und die Feldwerte im **Formularmodus** oder im **JSON-Modus** ein. Nach einer Warnung überschreibt MoleSignal den Datensatz, falls der Schlüssel bereits vorhanden ist. |
| **Datensatz bearbeiten** | Ändert die Werte eines Datensatzes. |
| **JSON anzeigen** | Zeigt den gesamten Datensatz einschließlich der Felder an, die nicht als Spalten in der Tabelle erscheinen. |
| **Datensatz löschen** | Löscht den Datensatz. Das Löschen lässt sich nicht rückgängig machen. |
| **Daten importieren** | Importiert mehrere Datensätze auf einmal: aus einer JSON-Datei (einem Array oder einer Zuordnung von Schlüsseln zu Datensätzen), aus einer CSV-Datei mit den Feldnamen in der ersten Zeile oder aus eingefügten JSON- oder CSV-Daten. Die Daten müssen die Spalte mit dem Suchschlüssel enthalten. Die Zusammenfassung zeigt, wie viele Datensätze der Import übernimmt und wie viele davon Datensätze mit vorhandenen Schlüsseln überschreiben. |

## Schema, Nutzung und Einstellungen

| Tab | Inhalt |
|---|---|
| **Schema** | Zeigt den Suchschlüssel und die Wertfelder an. Wählen Sie **Felder bearbeiten**, um Felder hinzuzufügen, Beschreibungen zu ändern oder die Einstellung **Erforderlich** anzupassen. Solange die Tabelle Datensätze enthält, lassen sich vorhandene Felder weder umbenennen noch entfernen. Auch der Typ lässt sich nicht ändern. In einer leeren Tabelle sind alle diese Änderungen möglich. Tabellenname und Suchschlüssel bleiben unveränderlich. |
| **Nutzung** | Zeigt die Pipelines und gespeicherten Abfragen an, die auf die Tabelle verweisen. Prüfen Sie diesen Tab, bevor Sie die Tabelle ändern oder löschen. |
| **Einstellungen** | Zeigt die **Tabelleninformationen** an. Unter **Gefahrenzone** löscht **Erweiterungstabelle löschen** die Tabelle und alle ihre Datensätze. Danach liefern Abfragen der Tabelle `null`. Wenn eine Pipeline Ereignisse in die gelöschte Tabelle schreiben soll, schlägt der Schreibvorgang fehl. Falls die Pipeline einen Dead-Letter-Stream hat, leitet sie die Ereignisse dorthin weiter. |

## Schlüssel in einer Pipeline nachschlagen

Eine Pipeline liest eine Tabelle mit dem Schritt [**In Erweiterungstabelle nachschlagen**](/de/pipelines#in-erweiterungstabelle-nachschlagen).
Dieser Schritt kopiert die Werte der Zeile in Felder des Ereignisses. Alternativ gibt
[`lookup(table, key)`](/de/functions#daten-zu-schlüsseln-und-ip-adressen-nachschlagen) in einem VRL-Schritt die
Zeile zurück:

```ruby
# enrich each event with the service's owning team
.team = lookup("service_meta", .service).team
```

Beide Varianten funktionieren in allen Pipeline-Typen, auch in [Alarm-Pipelines](/de/pipelines/alert-events). Ein Knoten
liest die Tabelle, sobald ein Schritt sie zum ersten Mal benötigt, und hält sie 30 Sekunden im Arbeitsspeicher. So verursachen Nachschlagevorgänge bei der Pipeline-Ausführung keine zusätzlichen Abfrage-
oder Speicherkosten. Neue, geänderte oder gelöschte Datensätze berücksichtigt jede Pipeline
innerhalb von 30 Sekunden. Erweiterungstabellen gehören zum Arbeitsbereich. Alle Pipelines in diesem Arbeitsbereich können die Tabellen verwenden.

## Tabelle aus einer Pipeline befüllen

Eine zeitgesteuerte Pipeline kann eine Tabelle aktuell halten: **Ziel hinzufügen → Erweiterungstabelle** schreibt jedes Ereignis,
das die Schritte der Pipeline durchläuft, als Zeile unter dem jeweiligen Wert des Suchschlüssels in die Tabelle. Siehe
[In eine Erweiterungstabelle schreiben](/de/pipelines#in-eine-erweiterungstabelle-schreiben).

## API für Erweiterungstabellen

```bash
# upsert a record keyed by "checkout"
curl -X PUT http://localhost:5080/api/v1/extend_tables/service_meta/rows/checkout \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"team":"payments","tier":"gold"}'
```

| Aktion | Endpunkt |
|---|---|
| Tabellen auflisten | `GET /api/v1/extend_tables` |
| Datensätze einer Tabelle auflisten | `GET /api/v1/extend_tables/{table}` |
| Datensatz einfügen oder aktualisieren | `PUT /api/v1/extend_tables/{table}/rows/{key}` |
| Datensatz löschen | `DELETE /api/v1/extend_tables/{table}/rows/{key}` |

## Berechtigungen

Mit `functions.read` lassen sich Tabellen und ihre Nutzung auflisten. Zum Erstellen einer Tabelle ist `functions.create` erforderlich,
zum Ändern von Datensätzen und Feldern `functions.edit` und zum Löschen einer Tabelle `functions.delete`.
