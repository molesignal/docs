Mit einem API-Token kann ein Programm MoleSignal ohne Anmeldung aufrufen. Ein Token hat keine eigene Rolle:
Es handelt im Namen eines Mitglieds oder eines Dienstkontos. Sein Geltungsbereich kann die Berechtigungen weiter einschränken. Ein Dienstkonto
dient als Identität für ein Programm. Es kann sich nicht anmelden, hat eine Rolle und lässt seine Tokens in seinem Namen handeln.

## Token-Typen

| Typ | Handelt im Namen von | Ausgabe unter |
|---|---|---|
| **Persönliches API-Token** | Dem Mitglied, das das Token erstellt hat. | **Kontoeinstellungen → API-Token** |
| **API-Token für Dienstkonten** | Einem Dienstkonto. | **Identität und Zugriff → API-Token** oder **Dienstkonten** |
| **Standard-Token für die Datenaufnahme** | Dem zugehörigen Konto, beschränkt auf das Schreiben von Daten. | **Datenquelle**. Siehe [Token für die Datenaufnahme](/de/intake#token-für-die-datenerfassung). |
| **RUM-Client-Token** | Der zugehörigen RUM-Anwendung, beschränkt auf das Schreiben von RUM-Daten. | **Datenquelle**. Siehe [Token für die Datenaufnahme](/de/intake#token-für-die-datenerfassung). |

Jedes Token hat das Format `mspat-<36>` und besteht aus Kleinbuchstaben und Ziffern. MoleSignal sucht das Token
anhand der ersten 10 Zeichen und speichert für den Rest nur einen Hash. Senden Sie das Token als Bearer-Token:

```http
Authorization: Bearer mspat-…
```

Ein Token gewährt keinen Zugriff auf die Organisation `_sys`.

## Berechtigungen eines Tokens

Ein Token hat höchstens die Berechtigungen, die das zugehörige Mitglied oder Dienstkonto zum Zeitpunkt der Anfrage hat.
Der Geltungsbereich schränkt diese Berechtigungen weiter ein:

| Geltungsbereich | Berechtigungen des Tokens |
|---|---|
| **Wie meine eigenen Berechtigungen**, **Wie beim Dienstkonto** | Die jeweils aktuellen Berechtigungen des zugehörigen Mitglieds oder Dienstkontos. |
| **Berechtigungsrichtlinie** | Die jeweils aktuellen Berechtigungen einer [Berechtigungsrichtlinie](/de/identity/roles#berechtigungsrichtlinien), etwa **Datenerfassung**. |
| **Benutzerdefiniert** | Die bei der Erstellung ausgewählten Berechtigungen. Diese Auswahl bleibt unverändert. |

Ein Token kann nur Berechtigungen erhalten, die das ausstellende Konto selbst hat. Verliert ein Mitglied eine Berechtigung,
verlieren auch alle zugehörigen Tokens diese Berechtigung. Verlässt ein Mitglied den Arbeitsbereich oder wird das Mitglied deaktiviert,
verlieren die zugehörigen Tokens ihre Gültigkeit. Eine Rolle für eine einzelne Ressource, die über eine Zugriffsgewährung oder Freigabe zugewiesen ist, gilt für ein Token nur
innerhalb seines Geltungsbereichs. Ein RUM-Client-Token gehört zur zugehörigen Anwendung. Es kann nur RUM-Daten schreiben und
gewährt keinen weiteren Zugriff.

## Persönliches Token erstellen

1. Öffnen Sie **Kontoeinstellungen → API-Token** und wählen Sie **Neues Token**.
2. Geben Sie einen **Namen** ein, zum Beispiel `collector-production`.
3. Wählen Sie den **Geltungsbereich**: **Wie meine eigenen Berechtigungen**, **Berechtigungsrichtlinie** oder **Benutzerdefiniert**. Eine
   Richtlinie oder Berechtigung steht nur zur Auswahl, wenn das eigene Konto über die entsprechenden Berechtigungen verfügt. Die ausgewählte Richtlinie listet ihre
   Berechtigungen auf.
4. Legen Sie unter **Läuft ab in (Tagen)** die Gültigkeitsdauer fest: standardmäßig 365, maximal 1825 Tage. Lassen Sie das Feld leer, damit das Token nicht
   abläuft.
5. Wählen Sie **Token erstellen** und anschließend **Token kopieren**. MoleSignal zeigt das Token nur dieses eine Mal an.

Die Liste zeigt die eigenen Tokens mit Geltungsbereich, Typ, Ablaufdatum und Zeitpunkt der letzten Nutzung. **Widerrufen** macht ein Token sofort
und dauerhaft ungültig. Zum Verwalten eigener Tokens ist `personal_tokens.manage` erforderlich. Diese Berechtigung hat jede integrierte
Rolle. Persönliche Tokens lassen sich nur in einer angemeldeten Sitzung erstellen. Ein Token kann kein weiteres Token erstellen.

## Tokens der Organisation

Unter **Identität und Zugriff → API-Token** finden Sie alle Tokens des Arbeitsbereichs mit dem zugehörigen Mitglied,
Dienstkonto oder der zugehörigen Anwendung sowie dem Geltungsbereich. Zum Anzeigen der Liste ist `api_tokens.read` erforderlich. Mit
`api_tokens.revoke` können Sie jedes Token widerrufen. Wählen Sie **Dienstkonto-Token erstellen**, um ein Token für ein
Dienstkonto zu erstellen. Wählen Sie das **Dienstkonto** und den **Geltungsbereich** aus und legen Sie die Gültigkeitsdauer fest.

## Dienstkonten

Verwenden Sie ein Dienstkonto für einen Collector, eine CI-Pipeline, eine Integration oder einen KI-Agenten, der ohne
menschliches Zutun läuft. So läuft die Automatisierung weiter, auch wenn ein Mitglied den Arbeitsbereich verlässt.

1. Öffnen Sie **Dienstkonten** und wählen Sie **Dienstkonto erstellen**.
2. Geben Sie einen **Namen** ein, zum Beispiel `deployment-automation`, ergänzen Sie eine **Beschreibung** und wählen Sie eine **Rolle**.
3. Wählen Sie **Konto und Token erstellen** und kopieren Sie das erste API-Token. Das Token erhält die Berechtigungen
   der Rolle zum Zeitpunkt der Erstellung und läuft nach 365 Tagen ab. MoleSignal zeigt es nur einmal an.

Wählen Sie ein Konto aus, um es zu verwalten:

| Aktion | Auswirkung |
|---|---|
| **Änderungen speichern** | Speichert Änderungen an Name, Beschreibung oder Rolle. Berechtigungen, die in der neuen Rolle fehlen, entfallen sofort für alle Tokens des Kontos. Zusätzliche Berechtigungen gelten nur für Tokens, die ab dann erstellt werden. |
| **API-Tokens verwalten** | Öffnet **API-Token** mit einem Filter für das Konto. Dort können Sie weitere Tokens erstellen oder ein Token widerrufen. |
| **Deaktivieren** / **Aktivieren** | Solange das Konto deaktiviert ist, schlägt die Authentifizierung mit dem Konto und allen zugehörigen Tokens fehl. |
| **Löschen** | Löscht das Konto und widerruft alle zugehörigen Tokens. Diese Aktion lässt sich nicht rückgängig machen. |

Die **Principal-ID** identifiziert das Konto in Audit-Logs und Zugriffsgewährungen. Zum Anzeigen von Dienstkonten
ist `service_accounts.read` erforderlich, zum Ändern `service_accounts.manage`.

## Passendes Token auswählen

| Aufrufende Komponente | Empfohlenes Token |
|---|---|
| Collector oder Agent, der Telemetriedaten sendet | Ein Dienstkonto-Token mit der Richtlinie **Datenerfassung** oder das Standard-Token für die Datenaufnahme. |
| Browser- oder Mobilcode, der RUM-Daten sendet | Das RUM-Client-Token der Anwendung. Es ist für Endnutzende sichtbar. |
| CI-Pipeline, die Deployments meldet | Ein Token mit der Richtlinie **Datenerfassung**, die auch `apm.deploy` enthält. |
| Automatisierung, die Daten liest oder Ressourcen ändert | Ein Dienstkonto-Token mit einem Geltungsbereich, den eine Richtlinie oder benutzerdefinierte Berechtigungen einschränken. |
| MCP-Client oder manuell ausgeführtes Skript | Ein persönliches API-Token mit Ablaufdatum. |

Der Browser speichert die Anmeldesitzung in HttpOnly-Cookies. Die Sitzung endet standardmäßig nach 24 Stunden
(`[auth].session_ttl_secs`). Der `Authorization`-Header akzeptiert keine Anmeldesitzung. Programme verwenden daher immer
ein API-Token.

## API für Tokens

| Vorgang | Endpunkt | Berechtigung |
|---|---|---|
| Persönliches Token erstellen | `POST /api/v1/me/api-tokens` | `personal_tokens.manage` |
| Eigene Tokens auflisten | `GET /api/v1/me/api-tokens` | `personal_tokens.manage` |
| Eigenes Token widerrufen | `DELETE /api/v1/me/api-tokens/{id}` | `personal_tokens.manage` |
| Verfügbare Einschränkungen für Tokens auflisten: Berechtigungsrichtlinien und Organisationsberechtigungen | `GET /api/v1/me/api-tokens/scopes` | Angemeldetes Mitglied |
| Dienstkonto-Token erstellen | `POST /api/v1/auth/tokens` | `api_tokens.revoke` |
| Alle Tokens auflisten | `GET /api/v1/auth/tokens` | `api_tokens.read` |
| Beliebiges Token widerrufen | `DELETE /api/v1/auth/tokens/{id}` | `api_tokens.revoke` |

Siehe [API-Token erstellen](/de/api/auth/issue-token), [API-Token auflisten](/de/api/auth/list-tokens) und
[API-Token widerrufen](/de/api/auth/revoke-token).
