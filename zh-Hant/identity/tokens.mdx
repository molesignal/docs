API Token 讓程式無須登入即可呼叫 MoleSignal。Token 本身不綁定角色，而是以某個成員或服務帳號的身分執行，權限範圍可以進一步限制可執行的操作。服務帳號是程式的身分：無法登入，擁有自己的角色，其 Token 以該帳號的身分執行。

## Token 類型

| 類型 | 以誰的身分執行 | 核發位置 |
|---|---|---|
| **個人 Token** | 核發 Token 的成員。 | **個人設定 → API 權杖** |
| **服務帳號 Token** | 某個服務帳號。 | **身分與存取 → API 權杖** 或 **服務帳號** |
| **預設資料接收 Token** | Token 的擁有者，只能寫入資料。 | **資料來源**，請參閱[資料接收 Token](/zh-Hant/intake#資料接收-token)。 |
| **RUM 用戶端 Token** | Token 所屬的使用者體驗應用程式，只能寫入 RUM 資料。 | **資料來源**，請參閱[資料接收 Token](/zh-Hant/intake#資料接收-token)。 |

所有 Token 的格式都是 `mspat-<36 位>`，由小寫字母和數字組成。前 10 碼用於查找 Token，其餘部分只儲存雜湊值。請將 Token 做為 Bearer 憑證傳送：

```http
Authorization: Bearer mspat-…
```

Token 無法存取 `_sys` 組織。

## Token 能做什麼

Token 的權限不會超過所屬成員或服務帳號在發出請求當下擁有的權限。權限範圍會在此基礎上進一步限縮：

| 權限範圍 | Token 能做的事 |
|---|---|
| **與我相同**、**與服務帳號相同** | 可執行所屬成員或服務帳號有權執行的所有操作，並隨其權限變更。 |
| **權限政策** | 具備某項[權限政策](/zh-Hant/identity/roles#權限政策)的權限，例如 **資料寫入**，並隨政策變更。 |
| **自訂** | 具備核發時勾選的權限，之後不再變更。 |

核發者無法將本身沒有的權限授予 Token。成員失去某項權限後，該成員的所有 Token 也會失去同一項權限；成員離開工作區或帳號遭停用後，該成員的 Token 會立即失效。透過存取授權或共用取得的個別資源角色，也只在 Token 的權限範圍內生效。RUM 用戶端 Token 屬於應用程式，只能寫入 RUM 資料，無法執行其他操作。

## 核發個人 Token

1. 開啟 **個人設定 → API 權杖**，按一下 **新增 Token**。
2. 填寫 **名稱**，例如 `collector-production`。
3. 選擇 **權限範圍**：**與我相同**、某項 **權限政策**，或 **自訂** 權限。只能選擇已具備的政策或權限；選取政策後會列出該政策的權限。
4. 設定 **有效天數**：預設為 365，最多 1825。留空表示永不過期。
5. 按一下 **建立 Token**，再按一下 **複製 Token**。Token 只會顯示這一次。

清單會顯示目前成員的 Token，以及各 Token 的權限範圍、類型、到期時間和最近使用時間。按一下 **撤銷** 會立即永久停用 Token。管理自己的 Token 需要 `personal_tokens.manage`，所有內建角色都有這項權限。只能在登入工作階段中核發個人 Token，不能使用 Token 核發另一個 Token。

## 組織的 Token

**身分與存取 → API 權杖** 會列出工作區的所有 Token，以及各 Token 代表的成員、服務帳號或應用程式及其權限範圍。檢視清單需要 `api_tokens.read`。具備 `api_tokens.revoke` 權限即可撤銷任意 Token，也可以按一下 **為服務帳號核發 Token**，再選擇 **服務帳號**、**權限範圍** 和有效期限。

## 服務帳號

收集器、CI 管線、整合或 AI Agent 等無人值守的程式應使用服務帳號。即使成員離開工作區，自動化作業也不會中斷。

1. 開啟 **服務帳號**，按一下 **建立服務帳號**。
2. 填寫 **名稱**（例如 `deployment-automation`）、**說明** 和 **角色**。
3. 按一下 **建立帳號和 Token**，並複製初始 API Token。這個 Token 具備建立時所選角色的權限，365 天後到期，且只會顯示一次。

按一下帳號即可進行管理：

| 操作 | 效果 |
|---|---|
| **儲存變更** | 儲存新的名稱、說明或角色。新角色移除的權限會立即對該帳號的所有 Token 失效；新增的權限只會授予之後核發的 Token。 |
| **管理 API Token** | 開啟依該帳號篩選的 **API 權杖** 清單，可以核發新的 Token 或撤銷現有的 Token。 |
| **停用** / **啟用** | 停用後，帳號及其所有 Token 都無法通過驗證，直到重新啟用帳號。 |
| **刪除** | 刪除帳號並撤銷其所有 Token。這項操作無法復原。 |

稽核記錄和存取授權會使用帳號的 **身分主體 ID** 識別帳號。讀取服務帳號需要 `service_accounts.read`，修改則需要 `service_accounts.manage`。

## 選擇合適的 Token

| 呼叫端 | 建議使用的 Token |
|---|---|
| 傳送遙測資料的收集器或 Agent | 採用 **資料寫入** 政策的服務帳號 Token，或預設資料接收 Token。 |
| 傳送使用者體驗資料的瀏覽器或行動裝置程式碼 | 該應用程式的 RUM 用戶端 Token。終端使用者可以看到這個 Token。 |
| 回報部署的 CI | 採用 **資料寫入** 政策的 Token。這項政策也包含 `apm.deploy`。 |
| 讀取資料或修改資源的自動化作業 | 透過政策或自訂權限限縮權限範圍的服務帳號 Token。 |
| 由人員執行的 MCP 用戶端或指令碼 | 設有有效期限的個人 Token。 |

瀏覽器會將登入工作階段儲存在 HttpOnly Cookie 中，預設在 24 小時後結束（`[auth].session_ttl_secs`）。`Authorization` 請求標頭不接受這個 Cookie，程式一律使用 API Token。

## Token API

| 操作 | 端點 | 權限 |
|---|---|---|
| 核發個人 Token | `POST /api/v1/me/api-tokens` | `personal_tokens.manage` |
| 列出自己的 Token | `GET /api/v1/me/api-tokens` | `personal_tokens.manage` |
| 撤銷自己的 Token | `DELETE /api/v1/me/api-tokens/{id}` | `personal_tokens.manage` |
| 列出可用來限縮 Token 範圍的權限政策和組織權限 | `GET /api/v1/me/api-tokens/scopes` | 已登入的成員 |
| 為服務帳號核發 Token | `POST /api/v1/auth/tokens` | `api_tokens.revoke` |
| 列出所有 Token | `GET /api/v1/auth/tokens` | `api_tokens.read` |
| 撤銷任意 Token | `DELETE /api/v1/auth/tokens/{id}` | `api_tokens.revoke` |

請參閱[核發 API Token](/zh-Hant/api/auth/issue-token)、[列出 API Token](/zh-Hant/api/auth/list-tokens)與[撤銷 API Token](/zh-Hant/api/auth/revoke-token)。
