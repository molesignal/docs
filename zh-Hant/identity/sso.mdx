單一登入讓使用者用企業目錄或常用平台的帳號登入，不必使用 MoleSignal 密碼。開啟 **身分與存取 → SSO 服務提供者** 和 **電子郵件網域**。檢視服務提供者與網域需要 `org.sso.read`，修改需要 `org.sso.manage`。

## 新增服務提供者之前

將 `[http].external_url` 設為 MoleSignal 的公開網址。OIDC 與 OAuth 2.0 的 **Redirect URI**、SAML 的 **Assertion Consumer URL（ACS）** 以及 **SP Entity ID** 的預設值都依此產生。身分提供者需要回呼這些網址。服務提供者的設定儲存在資料庫中，不必重新啟動就會生效。

## 新增服務提供者

1. 開啟 **SSO 服務提供者**，點選 **新增服務**。
2. 選擇平台：**常用平台**、**企業目錄**，或 **通用通訊協定** 中的 **OIDC**、**OAuth 2.0**、**SAML**、**LDAP**。選錯時，點選 **更換平台**。
3. 平台支援多種通訊協定時，在 **通訊協定** 中選擇。
4. 填寫平台所需的資訊，並依照說明，在身分提供者端註冊表單上顯示的 **Redirect URI** 或 **Assertion Consumer URL（ACS）**。
5. 檢查[身分欄位對應](#身分欄位對應)、[角色繫結](#角色繫結)與[登入範圍](#登入範圍)。
6. 點選 **建立服務**。

## 預設平台

選擇預設平台後，系統會自動填入端點、Scopes 和欄位對應。OIDC 與 OAuth 2.0 平台只需填寫下表中的資訊和 **Client ID**、**Client Secret**。在 **端點與 Scopes** 中查看系統推導出的端點。

| 平台 | 通訊協定 | 需要填寫 | 使用者群組 |
|---|---|---|---|
| Google | OIDC、SAML | OIDC 不需要其他資訊 | OIDC 不提供；SAML 提供群組成員資格 |
| Microsoft Entra ID | OIDC、SAML | **目錄（租用戶）ID**、**雲端環境**（全球或世紀互聯） | 群組的物件 ID |
| GitHub | OAuth 2.0 | **部署方式**；GitHub Enterprise Server 還需要 **伺服器網域名稱** | 組織（`my-org`）與團隊（`my-org/sre`） |
| GitLab | OIDC | **執行個體網址**，預設為 `https://gitlab.com` | `groups` |
| Okta | OIDC、SAML | **Okta 網域名稱**、**授權伺服器** | `groups` 宣告 |
| Auth0 | OIDC | **租用戶網域名稱** | 自訂宣告 |
| Keycloak | OIDC | **服務網址**、**Realm** | Group Membership mapper 輸出的 `groups` |
| authentik | OIDC | **服務網址**、**應用程式 slug** | `groups` |
| 飛書 | OAuth 2.0 | **版本**（飛書或 Lark） | 不提供 |
| AD FS | SAML | IdP 中繼資料 | Token-Groups |
| JumpCloud | SAML | IdP 中繼資料 | `memberOf` |
| Active Directory、OpenLDAP、FreeIPA | LDAP | 服務網址、Base DN 與查詢帳號 | `memberOf` |

GitHub 依固定欄位讀取資料：主體使用帳號的數字 ID，電子郵件地址使用已驗證的主要電子郵件地址。讀取組織和團隊需要 `read:org`。組織啟用 OAuth 應用程式存取限制時，須由組織擁有者核准該應用程式，才能讀取組織和團隊。使用飛書時，請在開放平台為應用程式開啟取得使用者電子郵件地址的權限。

## 通用通訊協定

| 通訊協定 | 設定 |
|---|---|
| OIDC | **Issuer URL**、**Authorization URL**、**Token URL**、**UserInfo URL**、**JWKS URL**、**Client ID**、**Client Secret**，以及以空格分隔的 **Scopes**。填好 **Issuer URL** 後，點選 **自動探索**，從 `.well-known/openid-configuration` 填入其餘端點。 |
| OAuth 2.0 | 適用於不簽發 ID Token 的身分提供者：**Authorization URL**、**Token URL**、**UserInfo URL**、**Client ID**、**Client Secret** 與 **Scopes**。登入後，使用存取權杖讀取 **UserInfo URL**，再依欄位對應取得帳號。 |
| SAML | **SP Entity ID**、**IdP Entity ID**、**IdP SSO URL** 和 **IdP 簽章憑證（PEM）**。在 **IdP 中繼資料** 中填入中繼資料 URL，或點選 **貼上 XML** 貼上中繼資料，再點選 **匯入**，即可填入後三項。單一登入網址只支援 HTTP-Redirect。 |
| LDAP | **LDAP 服務網址**：`ldaps://`，或啟用 **StartTLS** 的 `ldap://`。**使用者 Base DN**，例如 `ou=people,dc=example,dc=com`。**使用者查詢篩選器** 須包含 `{username}`，系統會在查詢前對輸入值進行跳脫處理。**查詢帳號的 Bind DN** 及其 **查詢帳號密碼**：只有目錄允許匿名查詢時，才能同時留空。 |

編輯服務提供者時，將 **Client Secret** 或 **查詢帳號密碼** 留空，系統會保留已儲存的值。

## 身分欄位對應

**身分欄位對應** 指定 MoleSignal 從何處讀取使用者的四個欄位：

| MoleSignal 欄位 | OIDC 與 OAuth 2.0 | SAML | LDAP |
|---|---|---|---|
| **固定的主體識別碼** | Claim 或 JSON 欄位，支援 `realm_access.roles` 這類以句點分隔的路徑。 | Attribute Name，或用 `NameID` 讀取斷言的主體。 | 屬性，或用 `dn` 讀取項目的 DN。 |
| **電子郵件地址** | Claim 或 JSON 欄位。 | Attribute Name。 | 屬性。 |
| **顯示名稱** | Claim 或 JSON 欄位。 | Attribute Name。 | 屬性。 |
| **使用者群組** | Claim 或 JSON 欄位。 | Attribute Name。 | 屬性。 |

OIDC 與 OAuth 2.0 的值可用 `|` 列出多個來源，依序取用第一個有值的來源，例如 `email | preferred_username`。系統會拒絕沒有有效電子郵件地址的登入。

## 角色繫結

**驗證平台使用者群組 → 本平台角色** 列出 **使用者群組** 的值與 MoleSignal 角色之間的對應。點選 **新增對應**，填寫 **驗證平台使用者群組值**（例如 `platform-admins`），再選擇角色。使用者會取得所有符合對應條件的角色。系統會在每次登入時同步角色。

沒有符合的對應時，使用 **預設角色**；未指定預設角色時，使用自行加入工作區時的角色。不提供使用者群組的平台只使用預設角色。

## 登入範圍

填寫 **允許登入的群組** 後，只有屬於其中任一群組的帳號才能透過該服務提供者登入。

任何人都能在 Google、GitHub.com、GitLab.com 及 Microsoft 不限租用戶的入口註冊帳號。啟用這類服務提供者前，請先設定工作區的[電子郵件網域](#電子郵件網域)，或在服務提供者的設定中填寫 **允許登入的群組**。登入時只接受身分提供者已驗證的電子郵件地址。啟用後若清空電子郵件網域，這類服務提供者會拒絕登入。

## 測試登入

使用服務提供者之前，請先在服務提供者清單或其設定中點選 **測試**。測試會使用已儲存的設定執行一次實際登入流程，但不會建立工作階段、建立或連結帳號，也不會變更角色或影響目前的登入狀態。停用的服務提供者也能測試，不必先啟用。測試需要 `org.sso.manage`，無法使用 API Token 發起，每個服務提供者每分鐘最多可測試 10 次。

| 服務提供者 | 測試方式 |
|---|---|
| OIDC、OAuth 2.0、SAML | 在新分頁前往身分提供者，返回時會開啟結果頁面。測試與登入使用相同的回呼網址或 ACS 網址。 |
| LDAP | 輸入目錄帳號和密碼。測試會執行一次實際的 bind。輸入錯誤的密碼會計入目錄的鎖定原則和此執行個體的登入速率限制。系統不會儲存密碼。 |

結果頁面會顯示：

- **是否通過測試。** 未通過時，會顯示原因、處理建議，以及伺服器端或身分提供者傳回的原始訊息。實際登入會遭拒的情況也算未通過，例如不符合允許登入的群組或電子郵件網域條件，或帳號已停用。
- **身分來源傳回的資料：** 電子郵件地址、名稱、主體和使用者群組。
- **實際登入的處理結果：** 登入會使用哪個帳號（直接登入、由帳號擁有者確認連結，或建立帳號），以及登入後的角色，包括會被取代的角色。

如果身分提供者顯示自己的錯誤頁面，瀏覽器就不會返回。10 分鐘後，結果頁面會顯示未收到結果。常見原因是未在身分提供者端註冊回呼網址。

結果只適用於測試當下的設定。變更端點、金鑰、對應或允許登入的群組後，結果就會失效，清單會顯示 **設定已變更**。重新命名、啟用或停用不影響結果。每個服務提供者保留最近 20 次測試。系統不會顯示或儲存權杖、斷言、金鑰和密碼，也不會將這些資料寫入記錄。系統會以 `org.sso_provider.test` 將每次測試寫入稽核記錄，不含身分資訊。

## 登入要求

**身分與存取 → SSO 服務提供者** 頂端的 **登入要求** 決定進入此工作區須符合哪些條件。變更設定需要 `org.sso.manage`。啟用後，最晚 15 分鐘內套用至所有工作階段。不符合要求的工作階段會在下次續期時結束，必須重新登入。啟用和停用都會寫入稽核記錄。

| 要求 | 效果 |
|---|---|
| **要求多因素驗證** | 進入工作區的工作階段必須通過[多因素驗證](/zh-Hant/identity/mfa)。透過此工作區的 OIDC、OAuth 2.0 或 SAML 服務提供者登入，即視為通過，由身分提供者負責驗證。LDAP 和其他工作區的單一登入不符合要求。 |
| **只允許單一登入** | 只能透過此工作區的 OIDC、OAuth 2.0 或 SAML 服務提供者登入，不能使用帳號密碼、Passkey 或 LDAP。Root 使用者不受此限制，在身分提供者發生問題時仍可登入。至少須啟用一個這類服務提供者，才能開啟此要求。開啟期間，不能停用或刪除最後一個這類服務提供者。若尚未啟用的服務提供者以目前設定通過[測試登入](#測試登入)，開啟此要求時會顯示風險提示、要求輸入工作區名稱，並在稽核記錄中記下 `sso_tested: false`。 |

不符合要求時：

| 情況 | 結果 |
|---|---|
| 登入時，帳號屬於多個工作區 | 進入第一個允許登入的工作區。 |
| 登入時，只差多因素驗證 | 在登入流程中設定 Passkey 或驗證器應用程式。完成後才會建立工作階段，並顯示復原碼。 |
| 登入時，帳號只屬於只允許單一登入的工作區 | 拒絕登入，並在登入頁面顯示原因。 |
| 切換到要求多因素驗證的工作區 | 帳號已有第二種驗證因素時，須當場驗證一次；若尚未設定，請先到 **安全性與登入** 啟用。 |
| 切換到只允許單一登入的工作區 | 提示透過該工作區的服務提供者登入。 |
| 自助註冊 | 工作區只允許單一登入時，無法註冊；要求多因素驗證時，請在建立帳號後於登入流程中啟用。 |
| 使用帳號登入資料庫用戶端 | 工作區只要啟用任一要求，就會拒絕登入。已連線的用戶端會在下次提出請求時失效。請改用 [API Token](/zh-Hant/identity/tokens)。 |
| API Token | 不受影響。 |

帳號所屬的工作區要求多因素驗證時，帳號擁有者不能刪除最後一種驗證因素；[管理員重設](/zh-Hant/identity/mfa#管理員重設)不受此限制，成員會在下次登入時重新啟用多因素驗證。

在 `_sys` 組織的 **設定 → 登入要求** 中設定平台組織的要求。這需要 `sys.settings.signin.manage`，且只有 **要求多因素驗證** 這一項。

## 登入時的流程

登入頁面會為每個已啟用的服務提供者各顯示一列，並附上平台圖示。使用 LDAP 服務提供者時，點選該列後，依序輸入目錄使用者名稱和密碼。

1. 瀏覽器前往身分提供者，完成驗證後返回 MoleSignal。
2. 服務提供者確認身分：OIDC 使用 JWKS 中的公開金鑰（RSA、EC 或 EdDSA）或 Client Secret（HMAC）驗證 ID Token 的簽章；OAuth 2.0 則讀取使用者資訊介面。MoleSignal 讀取對應的欄位。
3. 系統會拒絕不屬於 **允許登入的群組** 的帳號。
4. 如果先前登入時已將身分連結至某個帳號，便直接登入該帳號。MoleSignal 依服務提供者和身分的 subject 查找帳號，不比對電子郵件地址。
5. 首次以某個身分登入時，如果該電子郵件地址已有 MoleSignal 帳號，須等帳號擁有者確認。請參閱[連結現有帳號](#連結現有帳號)。
6. 尚無 MoleSignal 帳號的使用者，在電子郵件地址通過工作區的[電子郵件網域](#電子郵件網域)檢查後，系統會自動建立帳號。
7. 尚未加入工作區的使用者，會以對應的角色或預設角色加入服務提供者所在的工作區。
8. 對於現有成員，符合對應條件的角色會取代原有角色。已停用的帳號無法登入。
9. 瀏覽器返回登入頁面完成登入，並開啟登入前要存取的頁面。登入失敗時，登入頁面會顯示原因。

## 連結現有帳號

服務提供者只為所屬工作區的使用者擔保。單憑服務提供者傳回的電子郵件地址，無法登入現有帳號，因為該帳號可能屬於使用同一電子郵件地址的另一位使用者。某個身分首次以現有帳號的電子郵件地址登入時，登入頁面會要求帳號擁有者在同一個瀏覽器中確認。

| 方式 | 提供條件 | 做法 |
|---|---|---|
| **帳號密碼** | 帳號曾設定密碼。 | 輸入帳號密碼。 |
| **電子郵件驗證碼** | 執行個體可以[傳送電子郵件](/zh-Hant/configuration#警示與郵件)。 | 點選 **傳送驗證碼**，輸入電子郵件中的 6 位數字。每分鐘最多傳送一次。 |

驗證碼只在發起登入的頁面上有效。未發起登入時收到驗證碼郵件，可直接忽略。輸入錯誤達 5 次或超過 30 分鐘後，請重新透過服務提供者登入。確認後，系統會連結身分，之後透過該身分登入時不必再次確認。帳號若已啟用[多因素驗證](/zh-Hant/identity/mfa)，確認後還須完成第二步驗證（Passkey、驗證器或復原碼），才算完成連結。帳號沒有密碼且執行個體無法傳送郵件時，無法在這裡確認。請使用原本的方式登入，或請管理員設定郵件傳送功能。

由工作區自己的服務提供者建立的帳號，在電子郵件地址通過驗證前，只能留在原工作區。管理員和其他服務提供者都不能將該帳號加入其他工作區。透過電子郵件連結重設密碼，或用電子郵件驗證碼確認連結，都能驗證電子郵件地址。透過 Google、GitHub.com、GitLab.com 或 Microsoft 不限租用戶的入口建立的帳號不受此限制，因為這些服務提供者只接受已驗證的電子郵件地址。

在[帳號設定 → 安全性與登入](/zh-Hant/account#安全性與工作階段)中查看或解除連結至目前帳號的身分。

## 管理服務提供者

清單會顯示每個服務提供者的平台、類型、啟用狀態、[測試登入](#測試登入)狀態及更新時間。

| 操作 | 效果 |
|---|---|
| **測試** | 執行一次[測試登入](#測試登入)。 |
| **編輯** | 修改設定與對應。 |
| **停用** / **啟用** | 停用的服務提供者不會出現在登入頁面，也會拒絕登入。 |
| **刪除** | 刪除服務提供者。仰賴該服務提供者的使用者將無法再透過它登入。 |

## 電子郵件網域

**電子郵件網域** 限制哪些電子郵件地址可以透過[邀請](/zh-Hant/identity/members#邀請)或單一登入加入工作區。點選 **新增網域** 並填寫網域，例如 `example.com`。清單為空時，任何電子郵件地址都可以加入，但無法啟用供公開註冊帳號使用的服務提供者。點選 **刪除** 可從清單移除網域。
