角色是一組具名的權限。權限政策也是一組具名的權限，但與角色分開儲存。多個角色可以附加同一項政策，API Token 也可以連結至該政策。成員在[使用者](/zh-Hant/identity/members#使用者)中取得適用於整個工作區的角色。存取授權會將角色授予使用者或團隊，適用於整個組織或選定的資源，也可設定到期時間。開啟 **身分與存取 → 角色**、**權限政策** 或 **存取授權**。

## 角色

**角色** 列出工作區的內建角色和自訂角色，包括各角色附加的政策、授予的權限，以及參照該角色的成員、服務帳號、邀請和繫結。內建角色為唯讀，請參閱[內建角色](/zh-Hant/identity#內建角色)。

建立自訂角色：

1. 點選 **新增角色**。
2. 填寫 **Key**，僅限使用小寫字母、數字和底線，建立後無法修改。
3. 填寫 **名稱** 和 **說明**。
4. 在 **權限政策** 中勾選要附加至角色的政策。角色會取得這些政策中的所有權限，並隨政策變更而更新。
5. 在 **個別設定的權限** 中，勾選政策未涵蓋但角色仍需要的權限。每項權限都會說明允許的操作。系統會自動勾選所選政策授予的權限，並標示來源政策，無法在此取消勾選。
6. 點選 **建立角色**。

角色授予的權限包含個別設定的權限和所附加政策的權限。點選自訂角色即可修改這兩部分。只有在沒有任何成員關係、服務帳號、邀請或繫結參照該角色時，才能使用 **刪除** 移除自訂角色。讀取角色需要 `iam.roles.read`，修改角色需要 `iam.roles.manage`，刪除角色需要 `iam.roles.delete`。

## 權限政策

**權限政策** 列出工作區的內建政策和自訂政策，包括每項政策的權限，以及使用該政策的角色和 Token。角色可以附加政策，API Token 可以連結至一項政策，請參閱 [Token 可以執行哪些操作](/zh-Hant/identity/tokens#token-能做什麼)。

| 內建政策 | 權限 |
|---|---|
| **唯讀觀察者** | 讀取可觀測性資料、儀表板、警示、值班排程、已儲存的檢視、處理管線、函式、報告、狀態頁、合成監控、服務等級和事件檢討。 |
| **資料分析師** | 探索可觀測性資料，並建立儀表板和已儲存的檢視。 |
| **處理管線開發者** | 讀取可觀測性資料，並管理資料串流、處理管線和函式。 |
| **警示管理員** | 讀取可觀測性資料，並管理警示規則、值班排程、狀態頁、合成監控和事件檢討。 |
| **組織管理員** | 管理組織設定、成員、角色、存取授權、API Token、服務帳號和稽核，以及狀態頁、合成監控、服務等級和事件檢討。 |
| **資料寫入** | 寫入資料並回報部署：`logs.write`、`metrics.write`、`traces.write`、`profiles.write` 和 `apm.deploy`。資料寫入 Token 連結至此政策。 |

內建政策為唯讀，並隨產品更新。開啟一項內建政策，點選 **複製為自訂策略**，即可用該政策作為撰寫自訂政策的起點。

建立自訂政策：

1. 點選 **新增策略**。
2. 填寫 **名稱**、**Key**（僅限使用小寫字母、數字和底線，建立後無法修改）和 **說明**。
3. 在 **權限** 中，可在 **視覺化** 裡勾選權限，也可在 **JSON** 裡直接編寫文件。兩種方式編輯的是同一份文件。**JSON** 會指出文件中的第一個錯誤及其位置；文件有效時，會在儲存前列出文件允許的權限。
4. 點選 **建立策略**。

政策文件的寫法參考 AWS IAM 政策：

```json
{
  "Version": "1",
  "Statement": [
    { "Sid": "Dashboards", "Effect": "Allow", "Action": "dashboards.*" },
    { "Effect": "Allow", "Action": ["streams.read", "streams.query"] }
  ]
}
```

- `Version` 為 `"1"`，政策至少要允許一項權限。
- `Effect` 只能是 `"Allow"`：政策只能授予權限，不能拒絕權限。
- `Action` 是一項權限或一組權限。`*` 可比對任意字串，因此 `dashboards.*` 代表所有儀表板權限，`*` 代表所有組織權限。系統會拒絕未比對到任何權限的 Action。
- `Sid` 是陳述式的名稱，可省略。
- 系統會拒絕 `Resource`、`Condition`、`Principal` 和 `NotAction`：政策適用於整個組織。若要將角色限定在單一資源或加上條件，請使用[存取授權](#存取授權)。

儲存時，政策會記錄文件當下允許的權限。使用萬用字元的政策也會涵蓋之後加入權限目錄的權限：MoleSignal 啟動時會將這些權限補入政策。在 **視覺化** 中勾選權限時，若文件含有萬用字元、`Sid` 或多個陳述式，系統會先提示，再將文件改寫為逐項列出權限的單一陳述式。

修改政策會立即更新所有附加該政策的角色，以及所有連結至該政策的 Token。只有在沒有角色附加該政策，也沒有仍然有效的 Token 連結至該政策時，才能使用 **刪除** 移除自訂政策。曾連結至該政策但已撤銷或過期的 Token，會以權限清單保留當時的權限。讀取政策需要 `iam.policies.read`，修改政策需要 `iam.policies.manage`，刪除政策需要 `iam.policies.delete`。

## 存取授權

存取授權是一項角色繫結：在一個組織內，針對特定範圍的資源，將角色授予一個身分主體。若需要針對特定使用者、團隊或資源授予存取權，而不是擴大通用角色的權限，請使用存取授權。

1. 開啟 **存取授權**，點選 **新增存取授權**。
2. **身分主體**：選擇 **使用者** 或 **團隊**，再選定要授權的對象。
3. **組織**：顯示目前的工作區，僅供參考。
4. **資源範圍**：選擇 **整個組織**，或選擇一種資源類型（**儀表板** 或 **資料串流**）下的特定資源或 **此類型的所有資源**。
5. **角色與權限**：選擇要授予的角色。
6. **限制條件**：可選擇性設定 **環境** 和 **到期時間**。設定環境後，請求的環境必須與該設定完全相符，例如 `prod`。
7. 點選 **建立授權**。

**刪除** 會立即終止授權。讀取授權需要 `iam.grants.read`，建立或刪除授權需要 `iam.grants.manage`。

## 跨組織共用資源

跨組織共用可讓另一個組織存取本組織選定的資源。共用必須明確指定，且無法傳遞：只對選定的組織和資源生效，無法繼承或轉授。

1. 在 **存取授權** 中點選 **跨組織共用**。
2. 選擇 **目標組織**。
3. 選擇資源類型（**儀表板** 或 **資料串流**），再選擇資源。
4. 選擇權限：儀表板可選擇 `dashboards.read` 和 `dashboards.edit`，資料串流可選擇 `streams.read` 和 `streams.query`。
5. 可設定 **到期時間**，接著點選 **建立共用**。

建立共用後，狀態為 **等待接受**。目標組織的管理員在該組織的 **存取授權** 中點選 **接受** 後，共用狀態會變為 **已生效**。雙方都可以 **撤銷** 共用。建立、接受和撤銷共用需要 `iam.cross_org.manage`。

## 角色、原則與授權 API

| 操作 | 端點 | 權限 |
|---|---|---|
| 列出權限目錄 | `GET /api/v1/iam/permissions` | `iam.roles.read` 或 `iam.policies.read` |
| 列出角色 | `GET /api/v1/roles` | `iam.roles.read` |
| 建立自訂角色 | `POST /api/v1/roles` | `iam.roles.manage` |
| 更新自訂角色 | `PATCH /api/v1/roles/{id}` | `iam.roles.manage` |
| 刪除未使用的自訂角色 | `DELETE /api/v1/roles/{id}` | `iam.roles.manage` |
| 列出權限原則或讀取單一原則 | `GET /api/v1/iam/policies`、`GET /api/v1/iam/policies/{id}` | `iam.roles.read` |
| 建立自訂原則 | `POST /api/v1/iam/policies` | `iam.roles.manage` |
| 更新自訂原則 | `PATCH /api/v1/iam/policies/{id}` | `iam.roles.manage` |
| 刪除未使用的自訂原則 | `DELETE /api/v1/iam/policies/{id}` | `iam.roles.manage` |
| 列出或建立存取授權 | `GET /api/v1/iam/role-bindings`、`POST /api/v1/iam/role-bindings` | `iam.policies.read`、`iam.policies.manage` |
| 刪除存取授權 | `DELETE /api/v1/iam/role-bindings/{id}` | `iam.policies.manage` |
| 列出或建立跨組織共用 | `GET /api/v1/iam/cross-org-grants`、`POST /api/v1/iam/cross-org-grants` | `iam.policies.read`、`iam.policies.manage` |
| 接受或撤銷共用 | `POST /api/v1/iam/cross-org-grants/{id}/accept`、`POST /api/v1/iam/cross-org-grants/{id}/revoke` | `iam.policies.manage` |

角色的請求本文包含直接為該角色設定的 `permissions` 和附加的 `policyIds`。回應也會傳回 `effectivePermissions`，也就是角色授予的所有權限。原則的請求本文包含 `key`（僅限建立時）、`name`、`description` 和 `document`。回應也會傳回 `builtin`、解析出的 `permissions`，以及 `usage`：附加此原則的角色數量，以及套用此原則的有效權杖數量。文件無效時，API 會傳回 `400` 並指出問題所在，例如 ``Statement[0].Action[1]: no permission is called `alerts.rules.reed` ``；刪除仍在使用的原則時，API 會傳回 `409`。
