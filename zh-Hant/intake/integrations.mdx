本指南涵蓋最常見的傳送端。**資料來源** 頁面會產生相同的設定，其中端點與 Token 已替換為實際值，並涵蓋更多平台，請參閱[資料來源](/zh-Hant/intake)。

將 `molesignal.example.com` 替換為部署的實際位址，並將 `MS_TOKEN` 替換為[接入 Token](/zh-Hant/intake#資料接收-token)。Docker Compose 沙箱使用 `http://localhost:5080`。

## OpenTelemetry Collector

Collector 的 `otlphttp` 匯出端會將 `endpoint` 視為基礎 URL，並自動附加 `/v1/logs`、`/v1/metrics` 與 `/v1/traces`。將 `endpoint` 設為 `/api` 路徑，請求就會送到 `/api/v1/logs`、`/api/v1/metrics` 與 `/api/v1/traces`。

```yaml
receivers:
  otlp:
    protocols:
      grpc:
      http:

processors:
  batch:
    send_batch_size: 500
    send_batch_max_size: 500

exporters:
  otlphttp/molesignal:
    endpoint: https://molesignal.example.com/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/molesignal]
    metrics:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/molesignal]
    logs:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/molesignal]
```

<Warning>
  保持 `compression: none`。`otlphttp` 匯出端預設使用 gzip 壓縮，但 OTLP over HTTP 會傳回 `400`，拒絕經過壓縮的請求主體。端點會傳回 `413`，拒絕超過 2 MiB 的請求主體，因此請依記錄大小將 `send_batch_max_size` 設得夠小。如果匯出端的日誌出現 `413`，請調低此設定值。
</Warning>

透過 gRPC 傳送時，請使用 `otlp` 匯出端。連接埠 `4317` 提供未加密的 gRPC。除非有 Proxy 終止 TLS，否則請設定 `tls.insecure: true`：

```yaml
exporters:
  otlp/molesignal:
    endpoint: molesignal.example.com:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

在 `headers` 中新增 `stream-name: <stream>`，即可寫入 `default` 以外的資料串流。此請求標頭適用於使用這個匯出端的所有訊號。若要將訊號寫入不同的資料串流，請為每個資料串流定義一個匯出端。

## OpenTelemetry SDK

所有 OpenTelemetry SDK 都會讀取標準環境變數。將 `OTEL_EXPORTER_OTLP_ENDPOINT` 指向 `/api` 路徑，並透過 HTTP 傳送 OTLP：

```bash
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=https://molesignal.example.com/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
export OTEL_SERVICE_NAME=checkout
export OTEL_RESOURCE_ATTRIBUTES=deployment.environment=production
```

SDK 匯出端預設不壓縮。請勿設定 `OTEL_EXPORTER_OTLP_COMPRESSION`，或將其設為 `none`。

## Vector

使用 `http` sink 將日誌傳送到原生 HTTP JSON 接入端點。若事件沒有 `_timestamp` 欄位，則使用伺服器接收該事件的時間。

```yaml
sources:
  host_journald:
    type: journald
    current_boot_only: true

sinks:
  molesignal_logs:
    type: http
    inputs: [host_journald]
    uri: https://molesignal.example.com/api/v1/intake/logs/default
    encoding: { codec: json }
    auth: { strategy: bearer, token: "${MS_TOKEN}" }
```

## Fluent Bit

使用 JSON 格式的 `http` 輸出：

```ini
[INPUT]
    Name        tail
    Path        /var/log/nginx/access.log
    Parser      nginx
    Tag         nginx.access

[OUTPUT]
    Name        http
    Match       nginx.*
    Host        molesignal.example.com
    Port        443
    URI         /api/v1/intake/logs/default
    Format      json
    Header      Authorization Bearer ${MS_TOKEN}
    tls         On
```

在 Docker Compose 沙箱中，將 `Port` 設為 `5080`，並將 `tls` 設為 `Off`。

### Kubernetes

將 Fluent Bit 以 DaemonSet 執行，從 `/var/log/containers` 收集日誌。開啟 **資料來源 → Kubernetes**，即可取得已填入實際端點與 Token 的完整資訊清單。Fluent Bit 設定中的輸出區段與上述 `http` 輸出相同，比對規則為 `Match kube.*`。

## Prometheus

將 MoleSignal 新增為 remote write 目標。評估期間，可讓 Prometheus 繼續在本機擷取並儲存資料：

```yaml
remote_write:
  - url: https://molesignal.example.com/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

樣本會寫入 `stream-name` 請求標頭指定的指標資料串流；若未提供此標頭，則寫入 `default`。在 `remote_write` 設定中加入 `headers: { stream-name: <來源> }`，讓每個 Prometheus 執行個體使用各自的資料串流。使用 PromQL 依指標名稱查詢這些資料。支援的函式請參閱 [PromQL 支援矩陣](/zh-Hant/query/promql-subset)。

## 指令碼與自訂傳送端

使用 `curl` 或任何 HTTP 用戶端傳送 JSON 記錄陣列：

```bash
curl -X POST https://molesignal.example.com/api/v1/intake/logs/app \
  -H "authorization: Bearer ${MS_TOKEN}" \
  -H 'content-type: application/json' \
  -d '[{"level":"info","service":"billing","msg":"invoice created"}]'
```

分批傳送記錄，確保每個請求不超過 16 MiB 的上限。若傳送時帶有 `Content-Encoding: gzip`，則以解壓縮後的大小為準。若要保留事件的原始時間，請以微秒為單位傳送 `_timestamp`。

## 驗證資料

1. 開啟 **資料串流**，確認資料串流的名稱、類型與上次接收時間。
2. 開啟 **日誌**、**指標** 或 **追蹤**，選取該資料串流。

若未收到資料，請檢查傳送端日誌中的狀態碼：`401`（缺少 Token 或 Token 已過期）、`403`（Token 沒有 `logs.write` 權限）、`400`（OTLP 請求主體經過壓縮）和 `413`（請求主體超過端點的大小上限）。請參閱[疑難排解](/zh-Hant/troubleshooting)。

## 從其他方案遷移

| 來源 | 可沿用的部分 |
|---|---|
| Prometheus | 保留 Prometheus，並新增 `remote_write` 目標。MoleSignal 僅支援 PromQL 的一部分功能，遷移警示規則前請先查看[支援矩陣](/zh-Hant/query/promql-subset)。 |
| Grafana | 保留 Grafana，透過 [MoleSignal 資料來源](/zh-Hant/query/grafana)讀取 MoleSignal 的資料；或在[儀表板編輯器](/zh-Hant/dashboards/edit)中重建儀表板，並將 PromQL 運算式直接貼到指標面板。不支援匯入 Grafana 儀表板 JSON。 |
| Loki | 將 Vector 或 Fluent Bit 指向原生 HTTP JSON 接入端點。Promtail 與 Grafana Alloy 無法向 Loki 端點傳送資料。 |
| Elasticsearch | 使用 `_bulk` 協定的傳送端可改為指向 `/api/v1/_bulk`。請使用 SQL 查詢，而非 Elasticsearch 查詢 DSL。 |
