Mole Agent 從第一次對話起就能提供協助，但要建立信任，得先知道它能存取哪些內容，並確認它的回答正確。分步導入：先限制資料存取與操作，再讓它瞭解環境，接著把例行工作交給它，並隨著用量增加持續留意成本與品質。

## 確認哪些內容會傳送給模型

Mole Agent 會將對話傳送給模型服務供應商，內容包括所呼叫工具傳回的結果。第一次對話前，請與負責資料保護的同事一起確認以下控制項目。

| 控制項目 | 位置 | 建議 |
|---|---|---|
| 模型服務 | **Mole Agent → 設定 → 模型與推論** | 選擇資料政策允許的服務供應商。相容於 OpenAI 的端點可以由部署在公司網路內的模型提供。 |
| 資料範圍 | **Mole Agent → 設定 → 資料存取範圍** | 只開放調查所需的環境、服務和資料流。 |
| 網路 | **Mole Agent → 設定 → 網路原則** | 除非有工具需要連線，否則請保持關閉（新建 Profile 的預設狀態）。 |
| 個人資料 | [欄位遮罩](/zh-Hant/settings/data-security#欄位遮罩)與[正規表示式模式](/zh-Hant/settings/data-security#正規表示式模式) | 欄位遮罩對 Mole Agent 和使用者的查詢同樣有效；**寫入時套用遮罩** 會在寫入磁碟前移除文字。 |

同時填寫各模型服務的單價，即可在用量中查看成本。

## 先提供建議，再進行變更

在熟悉 Mole Agent 會提出哪些建議前，請將對話維持在建議使用的 **建議模式**：Mole Agent 會查詢資料並提出變更建議，但不執行變更。確認建議經得起驗證後，再切換至 **執行模式（須核准）**：依工具的執行方式，先確認變更或送交核准。請參閱[執行模式](/zh-Hant/agent#執行模式)。

- 共用 Agent Profile 的 **核准原則** 中，請將 **允許 Bypass permissions** 保持關閉。
- 保留依風險等級套用的預設原則：從 L0 自動執行到 L4 停用。在 **工具與能力** 中使用 **設定工具原則**，對 **正式環境** 採用比其他環境更嚴格的原則，例如 L1 變更也須由一人核准。
- 核准需要 `agent.approve` 權限，Owner 和 Admin 具備這項權限。透過自訂角色，只將這項權限授予原本就會親自執行這類變更的人員。
- MCP 伺服器的新工具會保持停用，直到有人啟用。先用 **啟用所有唯讀工具** 開啟唯讀工具。技能和 MCP 工具不會放寬原則。

## 讓 Mole Agent 瞭解環境

Mole Agent 越瞭解服務，回答就越好。

- 在 `MOLE.md` 中記錄組織知識，或執行 `/init` 讓 Mole Agent 撰寫：列出有哪些服務、各服務的負責人、有哪些環境、重要的資料流和儀表板，以及操作手冊的位置。使用 `@路径` 指向較長的檔案，例如 `runbooks/checkout.md`。請參閱[知識與記憶](/zh-Hant/agent#知識與記憶)。
- 讓各團隊維護自己的知識，團隊對話會讀取這些知識。在團隊對話中處理事件，值班人員就能查看並接續同一項調查。
- 開啟 **對話結束後擷取記憶**，保留從對話中學到的內容，並不時檢視 **記憶**，刪除錯誤的內容。
- 將反覆採用的做法寫成[技能](/zh-Hant/agent#技能)，存放在已開啟 **每天自動同步** 的[技能儲存庫](/zh-Hant/agent#技能儲存庫)中，讓做法的變更和程式碼一樣經過審查。

## 將例行工作交給 Mole Agent

[自動化](/zh-Hant/automations)讓 Mole Agent 在無人參與對話時也能運作。從範本開始：

| 範本 | 用途 |
|---|---|
| **事件自動分析** | 記錄錯誤和嚴重等級事件最可能的根本原因及相關證據，作為事件的 RCA，供第一位應變人員據以展開調查。 |
| **每日健康檢查** | 每個工作日早上指出需要留意的項目。 |
| **警示降噪週報** | 列出需要調整的規則。請參閱[讓正式環境的警示能指引應變](/zh-Hant/best-practices/actionable-alerts)。 |
| **值班負載週報** | 彙整各值班人員收到的警示和夜間警示。請參閱[設定值班與通知](/zh-Hant/best-practices/on-call-setup)。 |
| **變更影響檢查** | 部署後由 CI 呼叫。請參閱[驗證單次部署](/zh-Hant/best-practices/release-verification)。 |

自動化會以最後儲存該項設定的人員身分執行，並使用該人員的權限。該人員離開後，執行會持續失敗，直到有人重新儲存，因此請為每項共用的自動化記錄負責人。

執行期間無人可以回覆：需要確認的工具不會執行，該次執行會標記為 **需要人工處理**。自動化適合讀取資料及回報結果，變更則留在對話中處理。

## 留意成本

- 在 **Mole Agent → 設定 → 用量** 中設定每日預算：沿用執行個體的預設值 `[agent].daily_token_budget`，或設定 **自訂** 上限。依最近 30 天各來源的用量設定預算，並為事件集中發生預留額度：預算用完後，自動根因分析會等到隔天，日誌檢查會失敗，LLM 函式的這個步驟也會失敗。
- 保留預設的 **不再呼叫模型**。只有在超出預算後仍須繼續回答時，才選擇 **照常回答，僅顯示提示**。
- 需要明細時，在 **日誌** 中查詢內部資料流 `_agent_model_traces`：依 `origin`、`model` 和 `user_id` 查看每次呼叫使用的 token 數、延遲及成本。請參閱[用量與預算](/zh-Hant/agent#用量與預算)。

## 衡量並提升品質

- 鼓勵為回答評分。選擇 **沒有幫助** 並附上原因，可指出需要改進之處。
- 新增一項[評審](/zh-Hant/quality#評審)，抽樣評分團隊對話和 RCA，並每週在 **品質** 分頁審查低分回答。
- 將 `/insight` 設為每週執行的自動化。它最多會列出五項值得進行的變更，例如需要補寫的知識檔案。
- 將 Prompt 檢查設為 **檢查，品質下降時禁止設為預設**，避免新的組織 Prompt 降低回答品質。請參閱[將 Prompt 設為預設前先檢查](/zh-Hant/quality#將-prompt-設為預設前先檢查)。

## 驗收標準

- 模型服務符合資料政策，且已填寫單價。
- 預設 Profile 只讀取所需的環境、服務和資料流，而且不會連線。
- 所有共用 Profile 都不允許 **略過權限確認**，且已針對 **正式環境** 特別設定工具原則。
- `MOLE.md` 已列明各項服務、負責人和操作手冊，各值班團隊也都有自己的知識。
- 已設定一項 **事件自動分析** 自動化，為錯誤和嚴重等級的事件撰寫 RCA。
- 每日預算已為自動分析預留額度，而且每週都有人審查 **品質** 分頁。
