遙測資料的成長總是比它能回答的問題快。忘了關閉的偵錯日誌、帶有使用者 ID 的標籤、每秒記錄一次的健康檢查，都可能讓儲存用量翻倍，卻不會讓任何一次故障更容易解決。減少無用的資料，保留排查問題真正需要的資料。

## 先量測

在進行任何變更之前，先找出資料量集中在哪些資料流。

| 位置 | 顯示內容 |
|---|---|
| [首頁](/zh-Hant/home#資料接收) | 所選時間範圍內各類資料的接收量，以及儲存量和接收量。 |
| [資料流](/zh-Hant/streams#資料串流清單) | 各資料流在該時段內的壓縮資料、轉換前的 **收集的資料大小**、**實際儲存大小**、**索引大小** 和 **資料筆數**。比較這些數字，找出最大的資料流。 |
| [接收用量](/zh-Hant/streams#資料擷取用量與預算) | 各 Token、連接器、資料流和服務接收的資料量。已設定預算的來源在用量接近或超過預算時會觸發提醒。 |
| [指標](/zh-Hant/metrics#分析結果) | 指標的 **基數**，也就是作用中的序列數。 |
| [Mole Agent 用量](/zh-Hant/agent#用量與預算) | 依來源和日期統計的模型 token 用量，以及每日預算。 |

記下最大的幾個資料流的數字，作為評估每項變更的基準。

## 儲存前捨棄不會查看的資料

最省錢的位元組是從未儲存的位元組。對日誌而言，[即時管線](/zh-Hant/pipelines#即時管線)會在接收資料時、儲存前執行：

- **篩選事件**：捨棄正式環境中不會查看的健康檢查、就緒探查和偵錯日誌。
- **取樣**：對頻繁出現但仍有用的事件類型，只保留部分事件。使用 **依欄位一致取樣** 時，欄位值相同的事件（例如具有相同的請求 ID）會一併保留或捨棄。
- **刪除欄位**：移除查詢用不到的大型欄位，例如完整的請求主體。

能修改傳送端時，優先在傳送端處理：在正式環境使用 `info` 日誌層級，或在收集器中捨棄雜訊，還能節省網路流量。捨棄的事件無法復原；只對重複出現的事件取樣，切勿對錯誤事件取樣。

建議在來源端或 OpenTelemetry Collector 減少追蹤資料量。取樣時，確保同一條追蹤的 Span 一併保留，並留意應用程式效能指標和 SLO 只會統計收到的 Span。追蹤資料流上的[即時管線](/zh-Hant/pipelines#追蹤)可以在尾端取樣後再次取樣：將 **依欄位一致取樣** 的欄位設為 `trace_id`，整條追蹤就會一併保留或捨棄。應用程式效能指標會在管線取樣前統計，因此仍包含管線捨棄的 Span。針對使用者體驗資料，依應用程式設定[工作階段取樣](/zh-Hant/rum/sampling)。

## 只在需要的期間內保留資料

| 資料 | 保留期限 | 做法 |
|---|---|---|
| 偵錯日誌和詳細日誌 | 數天 | 使用獨立的資料流，設定較短的 **資料保留期限（天）**。 |
| 應用程式日誌和存取日誌 | 數週 | 使用 30 天的[平台預設值](/zh-Hant/settings/platform#資料保留)，或個別設定。 |
| 稽核與法規遵循日誌 | 數月或數年 | 使用獨立的資料流，設定較長的保留期限和較窄的存取範圍。 |
| 指標 | 數月 | 在指標資料流的 **保留原則** 分頁啟用 **對較早的樣本降取樣**：依時間區間彙總較舊的樣本，大幅減少長時間範圍查詢的讀取量。 |

依排查問題時實際需要回溯的時間設定保留期限，並為較晚發現的問題多留一些時間。縮短保留期限會在下次清理時刪除因此到期的資料；降取樣會刪除原始樣本。這兩項操作都無法復原。日誌和追蹤資料流應維持啟用 **每日合併小檔案**，讓跨多天的查詢少開啟一些檔案。

## 控制指標序列數量

每種不同的標籤值組合都會形成一個序列。可能值沒有上限的標籤（例如使用者 ID、請求 ID 或原始 URL）會不斷產生新序列。達到[基數上限](/zh-Hant/settings/platform#指標基數)後，系統會拒絕整個組織的新序列。

- 新增標籤後，檢查指標頁面的 **基數**。
- 用路由範本取代原始路徑，用方案、區域等類別取代 ID。
- 將每個請求的詳細資訊放在日誌或 Span 中，這兩者不會因欄位值不同而增加成本。
- 無法修改傳送端時，使用指標資料流上的[即時管線](/zh-Hant/pipelines#指標與追蹤)，在儲存樣本前刪除或改寫該標籤。

## 降低查詢成本

| 習慣 | 效果 |
|---|---|
| 為大型資料流設定 **查詢時間範圍上限（小時）** | 如果誤選「最近 90 天」，系統會拒絕查詢，而不是掃描全部資料。 |
| 為儀表板常用的篩選欄位建立索引 | 篩選時略過不必讀取的檔案。請參閱[規劃資料流與欄位](/zh-Hant/best-practices/stream-design#為篩選欄位建立索引)。 |
| 從最小的時間範圍開始 | 先縮小範圍，只在需要時再擴大。 |
| 將長時間範圍的掃描當作[搜尋工作](/zh-Hant/streams#搜尋工作)執行 | 查詢會在背景執行並保留結果，不必一直開著頁面。 |
| 讓儀表板的重新整理頻率與查看頻率相近 | **自動** 重新整理會隨時間範圍調整；大螢幕上查詢成本較高的面板應避免使用過短的間隔。 |

## 驗收標準

- 已掌握最大的五個資料流，以及變更前後各資料流的每日資料量。
- 沒有資料流意外儲存健康檢查、就緒探查或正式環境的偵錯日誌。
- 每個資料流都已依需求設定保留期限，長期保留的指標也已啟用降取樣。
- 指標序列數每週維持穩定，且遠低於上限。
- 大型資料流已設定查詢時間範圍上限，常用的篩選欄位也已建立索引。
