資料、儀表板和告警規則一旦依賴了資料串流和欄位，就很難再修改：欄位寫入後型別固定，加密旗標無法事後新增，改名的欄位會讓所有已儲存的查詢失效。在接入第一個繁忙的資料來源之前，先花一小時做好設計。

## 依差異拆分資料串流

只有資料需要不同的契約時才單獨建立資料串流：不同的保留期、存取規則、Schema 或查詢範圍限制。否則把資料放在一起，用欄位區分。

| 情境 | 建議做法 | 取捨 |
|---|---|---|
| 偵錯日誌保留 3 天，稽核日誌保留一年 | 兩個 `logs` 資料串流，各自設定保留期。 | 同時需要兩者的查詢要使用兩個資料串流。 |
| 多個服務的日誌結構相同 | 一個資料串流，每筆事件都帶 `service.name`。 | 保留期和存取權限不能依服務區分。 |
| 由管線分揀到各資料串流的原始資料洪流 | 關閉 **可查詢** 的來源資料串流，新增一條路由管線。 | 原始事件會保留到保留期結束，所以保留期要短。 |
| 每台 Prometheus 伺服器 | 每個來源一個 `metrics` 資料串流。 | 跨來源查詢要指定多個資料串流。 |
| 每個 Pod、版本或客戶一個資料串流 | 避免。改用欄位區分。 | 大量小資料串流會讓檔案數成倍增加，每次變動都會破壞儀表板。 |

資料第一次寫入時，MoleSignal 會自動建立資料串流，因此傳送端的一個拼字錯誤會悄悄產生一個新資料串流。每接入一個資料來源都要檢查[資料串流清單](/zh-Hant/streams#資料串流清單)，並提前建立重要的資料串流，設定好保留期和加密欄位。

## 傳送之前約定欄位名稱

能用 OpenTelemetry 名稱的地方都用它，同一個含義在所有訊號中使用同一個名稱。跨訊號跳轉和應用程式效能都依賴這些欄位。

| 欄位 | 內容 | 原因 |
|---|---|---|
| `service.name` | 服務名稱，在日誌、追蹤和指標中保持一致。 | 把所有訊號關聯到同一個服務。 |
| `deployment.environment.name` | `production`、`staging` 等。 | 讓每個頁面都能依環境篩選。 |
| `service.version` | 發行的版本。 | 驅動應用程式效能中的部署比較。 |
| `trace_id`、`span_id` | 請求內寫出的每筆日誌都帶上。 | 讓日誌可以一鍵跳轉到它的追蹤。 |
| `level` | 統一的寫法，例如小寫的 `error`、`warn`、`info`。 | 日誌直方圖從索引統計等級。 |
| `host.name`、`k8s.pod.name` | 事件發生的位置。 | 把問題縮小到一台機器。 |

同一個欄位在所有傳送端中保持相同的型別：某個服務以數值傳送、另一個服務以文字傳送的欄位，會被以 `type mismatch on field` 拒絕。請在儲存前用管線的 **型別轉換** 步驟統一這類欄位。整數和帶小數的數可以共用一個欄位，欄位會變成 `float64`。不要給已有欄位名稱賦予新含義，應新增欄位。

## 為篩選欄位建立索引

[索引型別](/zh-Hant/streams#schema-與欄位)決定篩選的速度。除少數常見欄位外，新欄位預設沒有索引。請檢查儀表板和告警篩選用到的欄位：

- 整體比對的識別碼用 **精確比對**：`trace_id`、`user_id`、`order_id`、`service.name`。
- 依詞搜尋的文字（例如 `message`）用 **全文搜尋**。
- 用 `<`、`>` 比對的數值和時間（例如 `duration_ms`）用 **跳過索引**。
- 只用於顯示的欄位不建立索引。

修改索引只影響新資料，舊檔案在 Compactor 合併時獲得新索引。在 **資料串流 → 欄位與索引** 中修改，然後 **儲存並套用**。

## 不要把高基數值放進標籤

取值沒有上限的指標標籤（例如使用者 ID、請求 ID 或完整 URL）會為每個取值產生一個新序列。隨後[基數上限](/zh-Hant/settings/platform#指標基數)會拒絕整個組織的新序列。把這類值放到日誌或 Span 屬性中，它們不會依取值產生成本；指標標籤只保留服務、路由範本、方法、狀態碼類別這類有限集合。

服務所屬團隊、客戶方案這類否則要複製到每筆事件中的參考資料，應放進[擴充表](/zh-Hant/extend-tables)，由管線在處理時查詢。

## 從一開始就保護敏感值

| 需求 | 工具 | 生效時機 |
|---|---|---|
| 永遠不儲存某個值，例如銀行卡號 | 開啟 **寫入時套用遮罩** 的[正規表示式模式](/zh-Hant/settings/data-security#正規表示式模式)，或刪除該欄位的管線步驟。 | 寫入時，永久生效。 |
| 儲存某個值，但只給少數人讀取 | 建立資料串流時宣告的加密欄位，用 `decrypt()` 讀取。 | 從資料串流建立時起。 |
| 在多數查詢結果中隱藏某個值 | [欄位遮掩](/zh-Hant/settings/data-security#欄位遮罩)。 | 查詢時，作用於結果。 |

優先在傳送端或收集器中去除敏感值。從未離開來源的值，就不可能從 MoleSignal 洩露。

## 驗收標準

- 每個資料串流都有負責人、存在的理由，以及刻意設定的保留期。
- 一個已知請求可以從日誌一鍵追到它的追蹤。
- 儀表板和規則篩選用到的欄位都有合適的索引。
- 沒有指標標籤攜帶無上限的取值，指標頁的 **基數** 顯示穩定的序列數。
- 帶敏感標記的測試事件依計畫被遮罩、遮掩或加密。
