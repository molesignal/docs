資料、儀表板和警示規則一旦依賴資料串流和欄位，就很難再修改：欄位寫入後就會固定型別，無法事後加上加密標記，重新命名欄位也會讓所有已儲存的查詢失效。在接入第一個高流量的資料來源前，先花一小時做好設計。

## 依需求差異拆分資料串流

只有資料需要遵循不同約定時，才建立獨立的資料串流，例如採用不同的保留期限、存取規則、Schema 或查詢範圍限制。否則將資料放在同一個資料串流，用欄位區分。

| 情境 | 建議做法 | 取捨 |
|---|---|---|
| 除錯日誌保留 3 天，稽核日誌保留一年 | 建立兩個 `logs` 資料串流，各自設定保留期限。 | 同時查詢兩種日誌時，必須使用兩個資料串流。 |
| 多個服務的日誌結構相同 | 使用一個資料串流，每筆事件都帶有 `service.name`。 | 無法依服務區分保留期限和存取權限。 |
| 大量原始資料由處理管線分流至各資料串流 | 關閉來源資料串流的 **可查詢** 設定，並新增一條路由管線。 | 原始事件會保留到期，因此請縮短保留期限。 |
| 每台 Prometheus 伺服器 | 每個來源使用一個 `metrics` 資料串流。 | 跨來源查詢時，必須指定多個資料串流。 |
| 每個 Pod、版本或客戶各用一個資料串流 | 避免這種做法。改用欄位區分。 | 大量小型資料串流會讓檔案數量成倍增加，每次異動都會破壞儀表板。 |

首次寫入資料時，MoleSignal 會自動建立資料串流。因此，傳送端的一個拼字錯誤就可能在未察覺的情況下產生新的資料串流。每次接入資料來源時，都要檢查[資料串流清單](/zh-Hant/streams#資料串流清單)，並預先建立重要的資料串流，設定保留期限和加密欄位。

## 傳送前先約定欄位名稱

盡量採用 OpenTelemetry 的欄位名稱，並在所有訊號中以同一個名稱表示相同概念。跨訊號跳轉和應用程式效能監控都仰賴這些欄位。

| 欄位 | 內容 | 原因 |
|---|---|---|
| `service.name` | 服務名稱，在日誌、追蹤和指標中保持一致。 | 將所有訊號關聯至同一個服務。 |
| `deployment.environment.name` | `production`、`staging` 等。 | 讓每個頁面都能依環境篩選。 |
| `service.version` | 發行版本。 | 供應用程式效能監控比較各次部署。 |
| `trace_id`、`span_id` | 處理要求時寫入的每筆日誌都要包含這兩個欄位。 | 讓日誌可以一鍵跳轉至對應的追蹤。 |
| `level` | 採用一致的寫法，例如小寫的 `error`、`warn`、`info`。 | 日誌直方圖會根據索引統計各層級的筆數。 |
| `host.name`、`k8s.pod.name` | 事件發生的位置。 | 將問題範圍縮小到單一機器。 |

所有傳送端都要為同一欄位使用相同的型別。如果一個服務以數值傳送欄位，另一個服務卻以文字傳送，系統就會拒絕型別不符的寫入，並回報 `type mismatch on field`。儲存前，請透過處理管線的 **型別轉換** 步驟統一這類欄位的型別。不要更改既有欄位名稱的含義，請改為新增欄位。

## 為篩選欄位建立索引

[索引類型](/zh-Hant/streams#schema-與欄位)決定篩選速度。除了少數常見欄位，新欄位預設沒有索引。請檢查儀表板和警示篩選時使用的欄位：

- 比對完整識別碼時使用 **精確比對**：`trace_id`、`user_id`、`order_id`、`service.name`。
- 依詞彙搜尋的文字（例如 `message`）使用 **全文搜尋**。
- 使用 `<`、`>` 比較的數值和時間（例如 `duration_ms`）使用 **跳過索引**。
- 僅供顯示的欄位不建立索引。

修改索引只會影響新資料。Compactor 合併舊檔案時，才會為這些檔案建立新索引。在 **資料串流 → 欄位與索引** 中修改，然後選取 **儲存並套用**。

## 不要將高基數值放入標籤

取值沒有上限的指標標籤（例如使用者 ID、要求 ID 或完整 URL）會為每個取值產生一個新序列。一旦達到[基數上限](/zh-Hant/settings/platform#指標基數)，系統就會拒絕整個組織的所有新序列。請將這類值放入日誌或 Span 屬性，避免因取值增加而產生成本。指標標籤只保留取值有限的項目，例如服務、路由範本、方法和狀態碼類別。

服務所屬團隊、客戶方案等參考資料，應放入[擴充表](/zh-Hant/extend-tables)，由處理管線在處理時查詢，不必複製到每筆事件中。

## 從一開始就保護敏感值

| 需求 | 工具 | 生效時機 |
|---|---|---|
| 永不儲存特定值，例如金融卡卡號 | 啟用 **寫入時套用遮罩** 的[正規表示式模式](/zh-Hant/settings/data-security#正規表示式模式)，或新增移除該欄位的管線步驟。 | 寫入時生效，永久有效。 |
| 儲存特定值，但僅允許少數人讀取 | 建立資料串流時宣告加密欄位，使用 `decrypt()` 讀取。 | 自建立資料串流起。 |
| 在大多數查詢結果中隱藏特定值 | [欄位遮罩](/zh-Hant/settings/data-security#欄位遮罩)。 | 查詢時套用至結果。 |

優先在傳送端或收集器移除敏感值。未離開來源的值，就不可能從 MoleSignal 洩漏。

## 驗收標準

- 每個資料串流都有負責人、明確的用途，以及依需求設定的保留期限。
- 可從已知要求的日誌一鍵跳轉至對應的追蹤。
- 儀表板和警示規則用於篩選的欄位都有適合的索引。
- 沒有指標標籤使用無上限的取值，指標頁面的 **基數** 顯示穩定的序列數量。
- 對標記為敏感的測試事件，系統會依計畫在寫入時套用遮罩、在查詢時套用欄位遮罩，或進行加密。
