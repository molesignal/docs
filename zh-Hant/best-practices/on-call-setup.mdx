凌晨 3 點觸發的規則能否發揮作用，取決於通知能否送達可以處理事件的人。通知漏接通常不是規則出了問題，而是通知路徑有缺口：手機號碼未驗證、週日無人值班，或尚未建立升級策略。先把整條通知路徑設定好，再透過演練確認運作正常。

## 決定由誰處理哪些事件

開始設定前，先記下每項服務的負責團隊、第一順位與下一順位的值班人員，以及哪些嚴重程度的警示需要在深夜打電話。

| 嚴重程度 | 典型應變方式 | 常用管道 |
|---|---|---|
| **嚴重** | 立即叫醒值班人員。 | 先傳即時訊息，再傳簡訊，最後打電話。 |
| **錯誤** | 在工作時間內或儘快處理。 | 先傳即時訊息，再傳簡訊。 |
| **警告** | 白天查看。 | 只傳即時訊息或電子郵件。 |
| **資訊** | 不傳送通知。 | 儀表板或報表。 |

將各負責團隊的成員加入對應的[團隊](/zh-Hant/identity/teams#團隊)：值班排程、升級目標和備援路由都會參照團隊。

## 為每位成員準備已驗證的聯絡方式

1. 管理員在[設定 → 通知 → 連接器](/zh-Hant/notification-channels#建立並測試連接器)中設定連接器：即時通訊應用程式、電子郵件，以及嚴重警示使用的電話和簡訊。逐一按一下 **傳送測試**。
2. 每位成員在[帳號設定 → 通知設定](/zh-Hant/account#通知設定)中綁定個人通知方式，並逐一傳送測試通知。
3. 具備 `org.members.update` 權限的管理員確認通知方式屬於該成員後，逐一按一下 **驗證**。系統不會透過未驗證的通知方式傳送通知。
4. 每位成員為 **警示事件** 設定通知方式的順序和等待時間，依序升級通知管道：例如立即傳送即時訊息，3 分鐘後傳簡訊，5 分鐘後打電話。一旦有人確認事件，系統就會停止後續步驟。

系統不會在勿擾時段向該成員傳送通知，時段結束後也不會補送。所有接收嚴重警示的值班人員都應開啟 **嚴重警示可略過勿擾模式**。

## 建立沒有空班的值班排程

依各團隊所在的時區建立[值班排程](/zh-Hant/alerting/on-call#建立排班)：

- 採用 **每週** 輪替，將交接安排在交接雙方都清醒的工作時段；
- 需要配合各地白天時段或只涵蓋工作時間時，將第一個輪值限制在工作時段，再把第二個輪值放在下方，涵蓋其餘時段；
- 依輪替順序加入所有成員，每個值班排程至少安排兩人。

儲存前檢查 **未來 7 天預覽**，並留意值班排程清單和[首頁](/zh-Hant/home#我的值班)是否顯示無人值班的提示。事先將請假和換班登記為[臨時代班](/zh-Hant/alerting/on-call#臨時代班)，並 **匯出行事曆**，讓成員能在自己的行事曆中查看班次。

## 先建立預設升級策略

在規則工作台儲存的規則會使用名為 `default` 的策略。若未建立該策略，這些規則觸發事件時，系統不會通知任何人。請參閱[預設策略](/zh-Hant/alerting/on-call#預設策略)。

| 層級 | 目標 | 確認等候時間 | 最低適用嚴重程度 |
|---|---|---|---|
| 1 | 團隊的主要值班排程。 | 5 分鐘 | 任意嚴重程度 |
| 2 | 備援值班排程或團隊負責人。 | 10 分鐘 | **錯誤** |
| 3 | 整個團隊。 | 15 分鐘 | **嚴重** |

為關鍵服務開啟 **重複執行整個策略，直到事件獲得確認**，並將 **最多重複次數** 設為較小的值。需求不同的團隊可另建策略，再透過 API 使用 `escalationPolicyId` 將規則指向對應的策略。

## 加上備援機制

- [備援路由](/zh-Hant/notification-channels#設定備援路由)會在收件人的個人通知方式都無法使用時，將通知傳送至團隊頻道或組織的收件地址。
- [通知策略](/zh-Hant/notification-channels#建立範本和策略)決定每個事件使用的範本和連接器；即時預覽會顯示哪些人會收到事件通知，但不會實際傳送。
- [傳送記錄](/zh-Hant/notification-channels#檢視和重試傳送)會顯示每次傳送嘗試，方便在事件需要使用連接器前，就發現無法運作的連接器。

## 演練

在工作時間進行一次演練，並在每次重大變更後重新演練：

1. 使用[觸發規則](/zh-Hant/api/alerting/trigger-rule) API 主動觸發一條測試規則。
2. 確認值班人員依預期順序在各管道收到通知。
3. 先不要確認事件，等候並確認通知升級至第 2 級。
4. 確認事件，檢查系統是否停止後續層級和管道的通知。
5. 解決事件，並在 **傳送記錄** 中檢查傳送失敗的項目。

## 驗收標準

- 值班排程中的每位成員至少有兩種已驗證的通知方式，其中一種是嚴重警示使用的電話。
- 未來 7 天內，所有值班排程都沒有空班。
- 已建立名為 `default` 的策略，且每個層級都指向人員或值班排程。
- 每個接收警示的團隊都已設定備援路由。
- 最近一次演練中，通知已送達值班人員，並依預期升級，在事件獲得確認後停止傳送。
