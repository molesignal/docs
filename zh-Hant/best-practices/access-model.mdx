存取權限總會因例外而擴張：臨時多要一項權限、外包同仁需要檢視一個儀表板、指令碼需要一個 Token。若未事先規劃，一年後就難以說清楚誰能刪除資料流、哪個 Token 還在寫入資料。先一次訂好權限模型，再依模型處理例外。

## 將職責對應到角色

依職責選擇足以完成工作的最小權限角色。各角色具備的權限，請參閱[權限參考](/zh-Hant/identity/roles#權限參考)。

| 職責 | 角色 | 說明 |
|---|---|---|
| 檢視儀表板、日誌和事件 | **檢視者** | 大多數成員的預設角色。檢視者也能與 Mole Agent 對話。 |
| 建立儀表板、警示規則和管線，處理警示 | **編輯者** | 編輯者可以確認和靜默事件，但不能修改成員、Token 或設定。 |
| 管理工作區：成員、角色、Token、設定、合成監控、狀態頁面 | **管理員** | 每個工作區只指派給少數成員。 |
| 負責整個執行個體 | **擁有者** | 每位擁有者都能存取平台組織 `_sys`。維持兩到三位，不要再增加。 |
| 內建角色都無法滿足的職責，例如警示管理員，或也需要管理合成監控的編輯者 | [自訂角色](/zh-Hant/identity/roles#角色) | 套用最接近需求的 **權限政策**，再個別勾選缺少的權限。 |

透過[存取授權](/zh-Hant/identity/roles#存取授權)將角色授予[團隊](/zh-Hant/identity/teams#團隊)，而不是逐一授予個別成員，讓存取權限隨團隊成員資格變動。

## 透過單一登入存取

1. 在[身分與存取 → SSO 服務提供者](/zh-Hant/identity/sso)中連結公司的身分服務提供者，並使用 **驗證平台使用者群組 → 本平台角色** 將使用者群組對應到角色。之後每次登入時，角色都會與目錄同步。
2. 將 **預設角色** 設為 **檢視者**，套用至未對應到任何使用者群組的帳號。
3. 新增公司的[電子郵件網域](/zh-Hant/identity/sso#電子郵件網域)，讓邀請和單一登入只接受這些網域的電子郵件地址。
4. 關閉[自行加入](/zh-Hant/settings/organization#註冊與存取)，或保留此功能並開啟 **須經管理員核准**。

root 使用者是 `[auth].root_email` 對應的平台管理員帳號，使用密碼登入。將密碼儲存在密碼保管庫中，只在單一登入無法使用時使用此帳號。

## 只在特定期間授權存取單一資源

有些需求範圍有限，而且只是暫時的：外包同仁只需檢視一個儀表板，分析師只需查詢一個資料流。請為該資源建立有 **到期時間** 的[存取授權](/zh-Hant/identity/roles#存取授權)，而非授予整個工作區的角色。**環境** 限制條件（例如 `staging`）會進一步將授權限於該環境的請求。

若要讓其他組織的成員存取選定的儀表板或資料流，請使用[跨組織共用](/zh-Hant/identity/roles#跨組織共用資源)，並由對方組織的管理員接受。共用只適用於選定的資源和組織，且無法轉授。

## 以團隊明確劃分權責

團隊不只是成員的集合：[值班排程](/zh-Hant/alerting/on-call)和升級步驟、[備援路由](/zh-Hant/notification-channels#設定備援路由)，以及 [Mole Agent](/zh-Hant/agent#組織、團隊與個人資源) 的團隊對話、知識、技能和 MCP 伺服器都會參照團隊。為每個負責服務並接收警示的小組建立團隊，並在人員異動時立即更新成員。

## 為程式建立獨立的身分

| 程式 | 憑證 |
|---|---|
| 只傳送資料的收集器或 Agent | 預設接入 Token，只能寫入。 |
| 瀏覽器或行動裝置上的程式碼 | 該應用程式的 RUM Client Token，終端使用者可看見此 Token。 |
| 回報部署的 CI | 預設接入 Token，也能用於回報部署。 |
| 讀取資料或修改資源的自動化程式 | 指派最小權限自訂角色的[服務帳號](/zh-Hant/identity/tokens#服務帳號)。 |
| 手動執行的指令碼或 MCP 用戶端 | 設有有效期限的個人 API Token。 |

為每項整合建立一個服務帳號。整合停止使用時，停用對應的帳號，該帳號的所有 Token 都會隨之失效。為手動建立的每個 Token 設定有效期限，切勿將登入工作階段交給程式使用。

## 定期檢查存取權限

每季以及有人離開時：

- 在[使用者](/zh-Hant/identity/members#使用者)中停用已離開成員的帳號，並查看 **上次活躍**，找出不再使用的帳號。
- 在 [API Token](/zh-Hant/identity/tokens#組織的-token) 中撤銷近期未使用或屬於已離開成員的 Token。
- 在[存取授權](/zh-Hant/identity/roles#存取授權)中刪除不再需要的授權。
- 在[稽核](/zh-Hant/settings/data-security#稽核)中查看角色、授權、Token 和設定的變更。
- 檢查[共用政策](/zh-Hant/settings/organization#分享與公開存取)和現有的公開連結。

將[稽核保留期限](/zh-Hant/settings/platform#稽核記錄保留)設為符合法規遵循要求的期間。

## 驗收標準

- 大多數成員擔任 **檢視者**，每個 **管理員** 和 **擁有者** 的指派都有明確理由。
- 成員透過單一登入存取系統，角色與目錄中的使用者群組同步。
- 每個程式都使用服務帳號或接入 Token，從不使用個人的登入工作階段。
- 所有 API Token 都符合有效期限政策，不再使用的 Token 均已撤銷。
- 每季的檢查都有日期和負責人，並留下稽核記錄。
