開啟 **日誌**，搜尋目前工作區中的日誌資料串流。

## 選取資料串流與時間範圍

選取日誌資料串流，再設定涵蓋目標事件的最小時間範圍。時間範圍越小，掃描的列數越少，探索欄位也越快。

MoleSignal 可在收到事件時推斷並更新 schema。**欄位** 面板會列出資料串流的欄位，不必重寫整條查詢就能新增篩選條件。

## 查詢分頁

每條查詢都在各自的分頁中執行。各分頁分別保留資料串流、查詢和時間範圍，一個分頁中的查詢不會影響其他分頁。

- 選取 **新增分頁** 以開啟另一條查詢，最多可同時開啟 10 個分頁。
- 開啟分頁選單，即可 **重新命名**、**複製分頁** 或 **關閉**。
- 選取 **分成兩欄**，並排顯示兩個分頁。每欄各自列出分頁，可透過選單將分頁移到另一欄。選取 **合併為一欄** 即可結束分欄。

瀏覽器會依使用者和工作區儲存已開啟的分頁。

## 撰寫查詢

編輯器提供 **代碼** 和 **查詢建構器** 兩種模式。使用標題旁的兩個圖示切換（`</>` 代表代碼，積木代表查詢建構器）。將游標移到圖示上即可查看名稱。

**代碼** 模式支援欄位查詢或 SQL。以 `SELECT` 或 `WITH` 開頭的陳述式會以 SQL 執行，其餘則以欄位查詢執行：

| 欄位查詢 | 含義 |
|---|---|
| `service = 'checkout'` | 欄位值與指定值完全相同。 |
| `message contains 'timeout'` | 欄位包含指定文字。 |
| `MATCH(message, 'timeout')` | 不區分大小寫的子字串搜尋。 |
| `MATCH_TEXT(message, 'timeout disk')` | 在已建立全文索引的欄位中進行全文搜尋。 |

使用 `AND` 和 `OR` 連接多個條件，兩者皆不區分大小寫。`AND` 優先於 `OR`，可用括號將條件分組：`level = 'error' AND (service = 'checkout' OR service = 'payments')`。未指定欄位的文字會在 `message` 欄位中搜尋，也可作為其中一個分支：`timeout OR "connection reset"`。引號內的詞組會當成一個整體搜尋，即使其中含有 `or` 之類的字詞。比較運算子包括 `=`、`!=`、`>`、`>=`、`<` 和 `<=`。

**查詢建構器** 模式將同一條欄位查詢顯示為多列篩選條件，每個分支各占一列。同一列的條件必須同時符合，從第二列起，每列開頭都會顯示 **或**。選取 **條件** 在該列新增條件，或選取 **或** 新增一列，再選取欄位、比較方式和值。每列都有各自的搜尋文字。列中以括號括住的部分（例如上例中的 `OR`）會保留原樣，只能在 **代碼** 模式中修改。SQL 陳述式無法顯示為篩選條件。

需要 join、運算式、CTE 或彙總時，請使用 SQL：

```sql
SELECT "_timestamp", level, msg, trace_id
FROM app
WHERE level = 'error'
ORDER BY "_timestamp" DESC
LIMIT 200;
```

```sql
SELECT level, COUNT(*) AS events
FROM app
GROUP BY level
ORDER BY events DESC;
```

選取 **查詢** 執行，或在編輯器中按 `⌘ Enter` 或 `Ctrl+Enter`。**查詢語法速查** 會列出目前模式的範例。文字搜尋函式請參閱[查詢](/zh-Hant/query#文字搜尋)。

即使提交自訂 SQL，查詢規劃器仍會強制將查詢限制在目前組織的範圍內。

## 探索欄位

**欄位** 面板分為三個區塊：**顯示的欄位**、**索引欄位** 和 **其他欄位**。含有句點且第一段相同的欄位名稱（例如 `http.method` 和 `http.route`）會歸為同一組，可一併展開。

- 展開欄位，查看結果中最常見的值。可新增篩選條件來納入或排除特定值。篩選條件會套用至整條查詢：若查詢含有多個分支，系統會先用括號括住原查詢。
- 將欄位顯示為結果中的一欄，或將其隱藏。
- 在欄位上選取 **分析**，即可查看欄位分析：相異值總數、有值及缺少值的列數、數值欄位的統計指標、數值分布，以及最常見的值隨時間的變化。

## 查看結果

結果上方的直方圖會統計時間範圍內符合查詢的所有事件，而不只統計已載入的這一頁。結果有四種檢視：

| 檢視 | 內容 |
|---|---|
| **原始日誌** | 符合查詢的事件，每個事件一列。 |
| **統計圖表** | 彙總結果的圖表。選取統計方式（日誌數、不重複計數、平均值、總和、最小值、最大值、P50、P95 或 P99）、分組方式和圖表類型，也可直接繪製 SQL 彙總陳述式的結果。選取 **建立儀表板**，將圖表儲存為新儀表板中的面板。 |
| **智慧巡檢** | Mole Agent 根據符合查詢的日誌產生的報告。請參閱[日誌巡檢](/zh-Hant/logs/inspections)。 |
| **日誌分群** | 依模式分組的事件，以及各模式的事件數和占比。 |

在 **原始日誌** 檢視中：

- 使用 **欄位設定** 選取要顯示的欄位並調整順序。預設顯示的欄位取自資料串流：先顯示時間，再顯示資料串流中現有的層級、服務和訊息欄位。
- 每頁可顯示 100、200、500、1,000、2,000 或 5,000 個事件。
- 點選事件後，結果旁的抽屜會顯示詳細資料。拖曳抽屜左側邊緣即可調整寬度，系統會儲存調整後的寬度。頂端會顯示層級、時間、訊息，以及識別該筆日誌的屬性（服務、主機、環境、版本、追蹤），每個屬性都支援與欄位相同的操作。檢視包括 **欄位**、有 Trace ID 時才顯示的 **呼叫鏈**、**脈絡** 和 **原始 JSON**。**呼叫鏈** 會顯示追蹤瀑布圖，並選取該筆日誌所屬的 Span。**脈絡** 會顯示該筆日誌前後各 5 筆日誌。可在欄位上新增篩選條件、複製值，或將欄位顯示為一欄。
- 識別資訊齊全時，可跳到追蹤、服務、指標或其他相關訊號。
- 可將結果下載為 CSV、純文字或 JSON。

## 分享查詢

頁面網址會反映畫面上的查詢。執行查詢後，頁面會將資料串流、查詢陳述式（欄位查詢為 `q`，SQL 為 `sql`）和結果檢視寫入網址。直接複製網址列中的網址即可分享查詢。時間範圍與時間選擇器一致，例如最近 1 小時。重新整理頁面後，查詢和編輯器會維持原狀。

選取 **分享**，複製目前查詢的連結。已登入此組織且有權讀取這些資料的成員可開啟連結。可選擇連結使用的時間範圍：**目前選取的時間範圍** 會將範圍固定為畫面上顯示的這段時間；另一個選項會保留相對時間範圍（例如最近 1 小時），以開啟連結的時間為準。

## 搜尋工作

規模過大、不適合以互動式請求處理的搜尋，會以搜尋工作的方式執行。開啟 **資料串流 → 搜尋工作**，即可追蹤工作並下載結果。請參閱[資料串流](/zh-Hant/streams#搜尋工作)。

## 已儲存的檢視

為 SQL 查詢命名，並儲存為[已儲存的檢視](/zh-Hant/saved-views)。之後可重新開啟檢視、在其他時間範圍內重新執行查詢，或將檢視繫結至報告。

<Tip>
  在整合時保留 `service.name`、`deployment.environment`、`trace_id` 和 `host.name` 等穩定的維度，可提高跨訊號跳轉的可靠性。
</Tip>

## 權限

- `streams.read`：探索資料串流和 schema。
- `logs.read`：讀取日誌，包括清單、直方圖和欄位統計。
- `streams.query`：執行 SQL 和查看脈絡。
- `agent.use`：執行智慧巡檢，另須啟用 AI 模型。
- `saved_views.create`、`saved_views.edit`、`saved_views.delete`：分別控制建立、編輯和刪除已儲存檢視的權限。
