開啟 **日誌**，搜尋目前工作區中的日誌資料串流。

## 選擇資料串流與時間範圍

選擇日誌資料串流，然後設定包含目標事件的最小時間範圍。時間範圍越小，掃描的列數越少，欄位探索也越快。

MoleSignal 可在事件到達時推斷並演進 schema。**欄位** 面板會列出資料串流的欄位，無須重寫完整查詢即可新增篩選條件。

## 查詢分頁

每個查詢都會在自己的分頁中執行。各分頁會各自保留資料串流、查詢與時間範圍，一個分頁中的查詢不會影響另一個分頁。

- 選擇 **新增分頁** 開啟另一個查詢，最多可同時開啟 10 個分頁。
- 開啟分頁的選單，可以 **重新命名**、**複製分頁** 或 **關閉**。
- 選擇 **分成兩欄**，並排顯示兩個分頁。每一欄會列出自己的分頁，分頁可以從選單移到另一欄。**合併為一欄** 結束分欄。

已開啟的分頁會依使用者與工作區儲存在瀏覽器中。

## 撰寫查詢

編輯器有 **代碼** 與 **查詢建構器** 兩種模式，用標題旁的兩個圖示切換（`</>` 是代碼，積木是查詢建構器），懸停時會顯示名稱。

**代碼** 模式接受欄位查詢或 SQL。以 `SELECT` 或 `WITH` 開頭的陳述式會按 SQL 執行，其餘則按欄位查詢執行：

| 欄位查詢 | 意義 |
|---|---|
| `service = 'checkout'` | 欄位的值與之完全相等。 |
| `message contains 'timeout'` | 欄位包含該文字。 |
| `MATCH(message, 'timeout')` | 不區分大小寫的子字串搜尋。 |
| `MATCH_TEXT(message, 'timeout disk')` | 在已建立全文索引的欄位上執行全文檢索。 |

多個條件用 `AND` 和 `OR` 連接，不區分大小寫。`AND` 優先於 `OR`，括號可以將條件分組：`level = 'error' AND (service = 'checkout' OR service = 'payments')`。未指定欄位的文字會在 `message` 欄位中搜尋，也可以作為其中一個分支：`timeout OR "connection reset"`。引號內的片語會作為整體搜尋，即使其中含有 `or` 這類詞。比較運算子有 `=`、`!=`、`>`、`>=`、`<` 和 `<=`。

**查詢建構器** 模式會將同一個欄位查詢顯示為多列篩選條件，每個分支一列：同一列的條件需同時滿足，第一列之後的每一列前會標示 **或**。選擇 **條件** 在該列新增條件，選擇 **或** 新增一列，然後選擇欄位、比較方式和值。每列有自己的搜尋文字。列內帶括號的部分（例如上例中的 `OR`）會保持原樣，只能在 **代碼** 模式中修改。SQL 陳述式無法顯示為篩選條件。

需要 join、運算式、CTE 或彙總時使用 SQL：

```sql
SELECT "_timestamp", level, msg, trace_id
FROM app
WHERE level = 'error'
ORDER BY "_timestamp" DESC
LIMIT 200;
```

```sql
SELECT level, COUNT(*) AS events
FROM app
GROUP BY level
ORDER BY events DESC;
```

選擇 **查詢** 執行，或在編輯器中按 `⌘ Enter` 或 `Ctrl+Enter`。**查詢語法速查** 會列出目前模式的範例。文字搜尋函式請參閱[查詢](/zh-Hant/query#文字搜尋)。

即使提交自訂 SQL，查詢規劃器仍會強制套用目前組織的邊界。

## 探索欄位

**欄位** 面板分為三部分：**顯示的欄位**、**索引欄位** 和 **其他欄位**。帶點號的欄位名稱若第一段相同，例如 `http.method` 和 `http.route`，會歸為同一組展開。

- 展開欄位，查看結果中最常見的取值。可以將某個取值新增為正向篩選或排除篩選。該篩選會作用於整條查詢：含有多個分支的查詢會先加上括號。
- 將欄位顯示為結果的一欄，或將其隱藏。
- 在欄位上選擇 **分析**，開啟欄位分析：不同值總數、有值與缺失的列數、數值欄位的統計指標、數值分布，以及最常見取值隨時間的變化。

## 閱讀結果

結果上方的直方圖會統計時間範圍內符合查詢的全部事件，而不只是已載入的這一頁。結果有四種檢視：

| 檢視 | 內容 |
|---|---|
| **原始日誌** | 符合的事件，每個事件一列。 |
| **統計圖表** | 彙總結果的圖表。選擇統計方式（日誌數、去重計數、平均值、總和、最小值、最大值、P50、P95 或 P99）、分組方式和圖表類型，也可以直接繪製 SQL 彙總陳述式的結果。**建立儀表板** 會將圖表儲存為新儀表板中的面板。 |
| **智慧巡檢** | Mole Agent 針對符合查詢的日誌所撰寫的報告。請參閱[日誌巡檢](/zh-Hant/logs/inspections)。 |
| **日誌分群** | 依模式歸併的事件，以及每種模式的事件數和佔比。 |

**日誌分群** 由伺服器端統計整個時間範圍內的模式。時間範圍內超過 5,000 筆事件時，會在整個範圍內均勻取樣讀取，每種模式的數量會按比例換算到整個範圍，並以 `≈` 標示；模式下方的說明會載明時間範圍內的事件總數與讀取的筆數。**變化** 欄會將每種模式與旁邊選取的對比時段比較：先前同樣長的一段（預設）、一週前的同一時段，或不比較。**新出現** 表示對比時段中沒有的模式，`×N` 表示成長到至少兩倍，且多出至少 5 筆，**減少** 表示減少到一半以下。展開一種模式會顯示已載入事件中屬於它的事件；已載入事件中沒有時，會顯示它的一則訊息。以 SQL 撰寫的陳述式會依其傳回的事件歸併。

在 **原始日誌** 檢視中：

- **欄位設定** 用於選擇欄位並調整順序。預設欄位取自資料串流的欄位：先是時間，然後是資料串流中存在的層級、服務和訊息欄位。
- 每頁可顯示 100、200、500、1,000、2,000 或 5,000 筆事件。
- 點擊事件會在結果旁的抽屜中開啟詳細資料，拖曳抽屜左邊緣可以調整寬度，寬度會被儲存。標頭會顯示層級、時間、訊息，以及識別這筆日誌的屬性（服務、主機、環境、版本、追蹤），每個屬性都有與欄位相同的操作。檢視包括 **欄位**、帶有 Trace ID 時的 **呼叫鏈**、**脈絡** 和 **原始 JSON**。**呼叫鏈** 會顯示追蹤瀑布圖並選取這筆日誌所在的 Span。**脈絡** 會顯示前後各 5 筆日誌。在欄位上可以新增篩選、複製值，或將欄位顯示為欄。
- 識別資訊齊全時，可以跳轉到追蹤、服務、指標或其他關聯訊號。
- 結果可以下載為 CSV、文字或 JSON。

## 分享查詢

頁面網址就是畫面上的查詢：查詢執行後，頁面會將資料串流、查詢陳述式（欄位查詢為 `q`，SQL 為 `sql`）和結果檢視寫入網址，直接複製網址列即可分享這個查詢，時間範圍與時間選擇器一致，例如最近 1 小時。重新整理頁面後，查詢和編輯器會保持原樣。

選擇 **分享**，複製目前查詢的連結。已登入本組織且有權讀取這些資料的成員可以開啟連結。選擇連結的時間範圍：**目前選取的時間範圍** 會將範圍固定為畫面上的這段時間；另一個選項則保留相對範圍（例如最近 1 小時），從開啟連結時起算。

## 搜尋工作

對互動式請求來說過大的搜尋會作為搜尋工作執行。開啟 **資料串流 → 搜尋工作** 追蹤工作並下載結果。請參閱[資料串流](/zh-Hant/streams#搜尋工作)。

## 儲存的檢視

將 SQL 查詢命名並儲存為[儲存的檢視](/zh-Hant/saved-views)。之後可以重新開啟檢視、在其他時間範圍重新執行，或綁定到報告。

<Tip>
  接入時保留 `service.name`、`deployment.environment`、`trace_id` 和 `host.name` 等穩定維度，可以提高跨訊號跳轉的可靠性。
</Tip>

## 權限

- `streams.read` 用於探索資料串流與 schema。
- `logs.read` 用於讀取日誌：清單、直方圖和欄位統計。
- `streams.query` 用於執行 SQL 和查看脈絡。
- `agent.use` 用於執行智慧巡檢，此外還需要已啟用的 AI 模型。
- `saved_views.create`、`saved_views.edit`、`saved_views.delete` 控制儲存的檢視。
