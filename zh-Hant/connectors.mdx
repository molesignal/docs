**連接器**是與外部平台的託管整合，分為兩個方向：

- **來源**從其他服務收集日誌並寫入資料流。MoleSignal 定期擷取 CloudWatch Logs、Kafka 主題和 S3 物件；Amazon Data Firehose、Cloudflare Logpush、Heroku 則將日誌推送至 MoleSignal。
- **目標**接收[排程管線](/zh-Hant/pipelines#目標與連接器輸出)的輸出：Amazon S3 與 S3 相容儲存服務、Apache Kafka，以及任意 HTTP 端點。

| Kind | 連接器 | 方向 | 驗證 |
|---|---|---|---|
| `aws_cloudwatch_logs` | AWS CloudWatch Logs | 來源，每 30 秒擷取一次 | [AWS 憑證](#aws-驗證) |
| `kafka_source` | Kafka 主題 | 來源，每 30 秒擷取一次 | 無、SASL 或用戶端憑證 |
| `s3_source` | S3 物件 | 來源，每 30 秒擷取一次 | AWS 憑證 |
| `aws_kinesis_firehose` | Amazon Data Firehose | 來源，推送 | [推送權杖](#推送來源) |
| `cloudflare_logpush` | Cloudflare Logpush | 來源，推送 | 推送權杖 |
| `heroku_drain` | Heroku 日誌 Drain | 來源，推送 | 推送權杖 |
| `s3` | Amazon S3 | 目標 | AWS 憑證 |
| `kafka` | Apache Kafka | 目標 | 無、SASL 或用戶端憑證 |
| `http` | HTTP / Webhook | 目標 | 無、Bearer 權杖、Basic 驗證、自訂請求標頭或 HMAC 簽章 |

## 建立連接器

<Steps>
  <Step title="開啟連接器頁面">
    前往 **管線 → 連接器**。頁面分為 **來源** 和 **目標** 兩個區塊，分別列出連接器。
  </Step>
  <Step title="選擇類型">
    點選 **新增連接器**，選擇要連線的平台。
  </Step>
  <Step title="填寫設定">
    填寫組織內唯一的 **名稱**，指定讀取或傳送的位置，並選擇 **驗證方式**。
  </Step>
  <Step title="測試並建立">
    點選 **測試連線**，在儲存前測試目前的設定，再點選 **建立連接器**。推送來源沒有可連線的對象，因此不提供測試。
  </Step>
</Steps>

透過 API 建立連接器時，需提供 `name`、`kind` 和 `configJson`。`configJson` 的索引鍵依 kind 而異。`configJson` 中的 `auth` 指定驗證方式，每種方式都有各自的索引鍵。儲存無效的設定時，API 會傳回 `400`：例如缺少必填索引鍵、成對的憑證只填了一半，或填寫了所選 `auth` 不使用的索引鍵。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "archive",
        "kind": "s3",
        "configJson": {
          "bucket": "acme-logs",
          "region": "eu-west-1",
          "prefix": "pipelines/checkout/",
          "auth": "assume_role",
          "roleArn": "arn:aws:iam::123456789012:role/molesignal-delivery"
        }
      }'
```

## 金鑰

`configJson` 中的下列索引鍵用來儲存金鑰：

| Kind | 金鑰的索引鍵 |
|---|---|
| `s3`、`aws_cloudwatch_logs` | `accessKey`、`secretKey`、`sessionToken` |
| `aws_kinesis_firehose`、`cloudflare_logpush`、`heroku_drain` | `pushToken` |
| `kafka` | `saslPassword`、`tlsClientKey` |
| `http` | `url`、`bearerToken`、`basicPassword`、`headerValue`、`hmacSecret` |

API 不會傳回金鑰。回應中的金鑰顯示為 `***`，`secretKeys` 則列出已儲存值的金鑰：

```json
{
  "kind": "kafka",
  "configJson": {
    "brokers": "b-1.example.com:9096",
    "topic": "logs",
    "tls": true,
    "auth": "sasl_scram_sha_512",
    "saslUsername": "molesignal",
    "saslPassword": "***"
  },
  "secretKeys": ["saslPassword"]
}
```

- 更新時原樣傳回 `***`，即可保留已儲存的值。因此，重新命名、停用連接器或變更傳送位置時，不必重新填寫憑證。在介面上將已儲存的金鑰欄位留空，也會保留原值。
- 更新時若未帶入某個金鑰，系統會刪除該金鑰。
- 更新時若變更 `kind`，系統不會保留任何已儲存的金鑰。

MoleSignal 使用 `MS_CIPHER_KEY` 中的根金鑰（AES-256-GCM），將金鑰與其餘設定分開加密保存，不會以純文字儲存任何金鑰。MoleSignal 以權杖的 SHA-256 雜湊值查找推送來源。輪替根金鑰時，`molesignal rewrap-kek` 會將連接器金鑰與其他密文一併重新加密保存，請參閱[正式環境檢查清單](/zh-Hant/deployment/production-checklist)。

## 來源

### 推送來源

三種推送來源都採用相同的模式：建立含有 **`pushToken`** 和 **`target_stream`** 的連接器，再將平台指向對應的端點。這些端點不使用 JWT，而是以推送權杖驗證請求。請依平台支援的方式傳入權杖：

| 方式 | 適用平台 |
|---|---|
| `X-Connector-Token` 請求標頭 | 可設定自訂請求標頭的平台，例如 Cloudflare |
| `X-Amz-Firehose-Access-Key` 請求標頭 | Amazon Data Firehose 會自動傳送 |
| `?token=` 查詢參數 | 無法設定請求標頭的平台，例如 Heroku |

透過介面建立連接器時，系統會產生權杖，並連同要提供給平台的端點一併顯示。權杖只會顯示一次，之後無法再讀取。選擇 **產生新權杖** 後，儲存連接器時會取代目前的權杖。透過 API 建立時，請提供至少 16 個字元的 `pushToken`。在同一 kind 下，一個權杖只能對應一個連接器；若權杖已有人使用，API 會傳回 `409`。若請求未提供權杖、權杖無法辨識，或請求傳送至已停用的連接器，端點都會傳回 `401`。沒有權杖的連接器不接受任何推送。

MoleSignal 會自動解壓縮含有 `Content-Encoding: gzip` 的請求主體。事件採用與其他資料匯入方式相同的處理流程：schema-on-write、[管線](/zh-Hant/pipelines)和[資料遮罩](/zh-Hant/security)都會套用。

<Tabs>
  <Tab title="Amazon Data Firehose">
    使用 `kind: "aws_kinesis_firehose"` 建立連接器，接著為 Firehose 串流選擇 **HTTP endpoint** 目標：

    - **HTTP endpoint URL**：`https://molesignal.example.com/api/v1/_kinesis_firehose`
    - **Access key**：推送權杖。Firehose 會透過 `X-Amz-Firehose-Access-Key` 傳送權杖。

    MoleSignal 對每筆 record 進行 base64 解碼，依換行切分，再逐行剖析為 JSON。純文字則放入 `message` 欄位。MoleSignal 會依 Firehose 的要求傳回 `200` 確認。
  </Tab>
  <Tab title="Cloudflare Logpush">
    使用 `kind: "cloudflare_logpush"` 建立連接器，接著建立以 HTTP 為目標的 Logpush 工作。Cloudflare 會將以 `header_` 開頭的查詢參數轉換為請求標頭，因此請將權杖放在 `X-Connector-Token` 中：

    ```text
    https://molesignal.example.com/api/v1/_cloudflare?header_X-Connector-Token=<pushToken>
    ```

    Cloudflare 會傳送以 gzip 壓縮的 NDJSON，每行各形成一筆事件。端點會傳回 `204 No Content`。
  </Tab>
  <Tab title="Heroku">
    使用 `kind: "heroku_drain"` 建立連接器，接著新增 Drain。Heroku 無法設定自訂請求標頭，因此請將權杖放在 URL 中：

    ```bash
    heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
    ```

    每行日誌各形成一筆包含 `message` 和 `source: "heroku"` 的事件。端點會傳回 `204 No Content`。
  </Tab>
</Tabs>

<Tip>
  MoleSignal 會在首次傳送時建立 `target_stream`。如同其他資料流，結構描述會隨著新欄位出現而演進。省略 `target_stream` 時，會依來源使用預設資料流：`kinesis`、`cloudflare` 或 `heroku`。
</Tip>

### CloudWatch Logs

CloudWatch Logs 是**擷取**來源：MoleSignal 每 30 秒呼叫一次 `FilterLogEvents`，而非等待推送。首次執行時會讀取最近 5 分鐘的日誌。之後每次執行都會從上一次成功執行的結束位置繼續，因此未能讀取或寫入的事件會在下次執行時重新讀取。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "cw-prod",
        "kind": "aws_cloudwatch_logs",
        "configJson": {
          "region": "ap-southeast-1",
          "logGroup": "/aws/lambda/checkout",
          "auth": "node_role",
          "targetStream": "cloudwatch"
        }
      }'
```

| 欄位 | 說明 |
|---|---|
| `region` / `logGroup` | 必填。指定要讀取的 CloudWatch 區域與日誌群組。 |
| `auth` 及其索引鍵 | 憑證。需具備該日誌群組的 `logs:FilterLogEvents` 權限，請參閱 [AWS 驗證](#aws-驗證)。 |
| `targetStream` | 要寫入的資料流，預設為 `default`。 |

同一時間，每個連接器只會由一個節點輪詢。`alert` 節點依連接器分工，各節點先認領連接器，再進行輪詢。請參閱 [alert 節點之間的分工](/zh-Hant/deployment/role-based#alert-節點之間的分工)。每筆事件各形成一筆包含 `message`、`log_stream` 和 `log_group` 的日誌。節點不會輪詢已停用的連接器。

### Kafka 主題

`kafka_source` 連接器每 30 秒讀取一次主題，並從上次成功寫入的位置繼續讀取。連接器依指定的分割區讀取，不加入消費者群組，並將讀取位置儲存在 MoleSignal 中。因此只需該主題的讀取權限，叢集也不會新增消費者群組。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "orders",
        "kind": "kafka_source",
        "configJson": {
          "brokers": "b-1.example.com:9096,b-2.example.com:9096",
          "topic": "orders",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "<password>",
          "targetStream": "orders",
          "startFrom": "latest"
        }
      }'
```

| 欄位 | 說明 |
|---|---|
| `brokers`、`topic`、`tls`、`tlsCaCert`、`auth` 及其索引鍵 | 與 [Kafka 目標](#apache-kafka) 相同。 |
| `targetStream` | 要寫入的資料流，預設為 `default`。 |
| `startFrom` | 首次讀取的起點：`latest`（預設）讀取從現在起收到的訊息，`earliest` 讀取 Broker 儲存的所有訊息。之後新增的分割區會從頭讀取。介面標籤：**從哪裡開始**。 |

- 如果訊息值是 JSON 物件，物件欄位就是日誌欄位；其他值則放入 `message`。每筆日誌也包含 `kafka_topic`、`kafka_partition`、`kafka_offset` 和 `source`。若訊息有 key，日誌也會包含 `kafka_key`。日誌時間採用訊息的時間戳記。
- 每次讀取最多 10,000 則訊息或 32 MiB。若還有資料，就立即繼續讀取。每次擷取最多持續 2 分鐘。
- 日誌寫入成功後才會推進讀取位置。讀取或寫入失敗時，會在 30 秒後從同一位置重試，因此訊息可能重複寫入，但不會遺失。若 Broker 已清除該位置對應的訊息，就從 Broker 保留的最早訊息繼續讀取。
- 變更 `topic` 時，會依 `startFrom` 重新開始讀取，因為讀取位置是依主題記錄的。

### S3 物件

`s3_source` 連接器每 30 秒列出一次儲存貯體中的物件，依時間從舊到新讀取尚未讀取的物件。連接器支援 AWS S3 和 S3 相容儲存服務。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "elb-logs",
        "kind": "s3_source",
        "configJson": {
          "bucket": "acme-logs",
          "region": "us-east-1",
          "prefix": "AWSLogs/123456789012/",
          "auth": "node_role",
          "targetStream": "elb",
          "startFrom": "latest"
        }
      }'
```

| 欄位 | 說明 |
|---|---|
| `bucket`、`region`、`endpoint`、`virtualHostedStyle`、`auth` 及其索引鍵 | 與 [S3 目標](#amazon-s3) 相同。憑證需具備儲存貯體的 `s3:ListBucket` 權限，以及物件的 `s3:GetObject` 權限。 |
| `prefix` | 僅讀取此前置詞下的物件。每次擷取都會列出此前置詞下的所有物件，因此請為來源指定專用的前置詞。 |
| `targetStream` | 要寫入的資料流，預設為 `default`。 |
| `startFrom` | 首次讀取的起點：`latest`（預設）讀取從現在起出現的物件，以及之前 5 分鐘內出現的物件；`earliest` 則讀取前置詞下的所有物件。介面標籤：**從哪裡開始**。 |

- 連接器逐行讀取物件。若一行是 JSON 物件，物件欄位就是該筆日誌的欄位；若一行只含 `Records`（CloudTrail 的格式），則每筆記錄各形成一筆日誌；其他行則放入 `message`。連接器依副檔名解壓縮 `.gz` 和 `.zst` 物件。每筆日誌也包含 `s3_bucket`、`s3_key` 和 `source`。日誌時間採用物件的上次修改時間。
- 每次擷取最多讀取 100 個物件或 50,000 筆日誌。若還有資料，就立即繼續讀取，最多持續 2 分鐘。
- 日誌寫入成功後才會更新讀取狀態。若無法取得某個物件，本次擷取會停在該物件，並在 30 秒後重試，因此日誌可能重複寫入，但不會遺失。
- 連接器會略過無法讀取的物件並記錄原因，因為反覆重試會阻擋後續所有物件。這類物件包括已損毀、大小超過 256 MiB、解壓縮後超過 512 MiB、包含超過一百萬筆日誌，或有任一行超過 64 MiB 的物件。
- 連接器依物件的索引鍵和修改時間辨識物件，並保留 5 分鐘的緩衝時間。在這段期間以相同索引鍵重新寫入的物件不會再讀取。若物件的修改時間比已讀取的最新物件早超過 5 分鐘，連接器就不會讀取。S3 以開始上傳的時間作為分段上傳的時間，因此耗時超過 5 分鐘的上傳可能無法讀取。

### 擷取狀態

連接器頁面會顯示來源最近一次收到資料的時間。若來源上次讀取失敗，旁邊會顯示警告。提示和連接器設定都會列出失敗原因及最近略過的內容。透過 API 讀取時，`readState` 包含 `lastError`、`lastWarning`（各有 `atTime` 和 `text`），以及表示目前讀取位置的 `position`。儲存連接器不會改變讀取位置。

## 目標

目標會接收排程管線完成各步驟後的所有事件。使用 **新增目標 → 連接器**，將連接器加入流程的 **目標**。投遞失敗時，系統會在本次執行期間重試。若連接器仍未收到事件，系統會將這些事件寫入死信資料流，請參閱[重試與死信](/zh-Hant/pipelines#重試與死信)。

已停用的目標不會收到任何事件。每次執行都會略過該連接器，並在該次執行的 `warning` 中註明。系統不會將略過的事件計為失敗或寫入死信資料流，重新啟用連接器後也不會補送。編輯器會將已停用的連接器標示為 **停用**。

| 類型 | 投遞酬載 |
|---|---|
| `s3` | 每批事件以一個 JSON Lines 物件透過 `PUT` 寫入 `s3://<bucket>/<prefix><id>.jsonl`。 |
| `kafka` | 每筆事件都會在主題中產生一則訊息，訊息酬載為該事件的 JSON。 |
| `http` | 每批事件以一個要求傳送，較大的批次則拆成多個要求。格式為 NDJSON 或單一 JSON 陣列。 |

### Amazon S3

`s3` 也可以投遞至 MinIO、Cloudflare R2、阿里雲 OSS 等 S3 相容儲存空間。在介面中開啟 **S3 相容儲存空間** 即可填寫端點。

| 欄位 | 說明 |
|---|---|
| `bucket` | 必填。 |
| `region` | 儲存桶所在的區域。S3 相容儲存空間不一定需要此欄位。 |
| `prefix` | 物件名稱為 `<prefix><id>.jsonl`。系統會移除開頭的 `/`，並在結尾補上 `/`。 |
| `endpoint` | S3 相容儲存空間的 S3 API 位址，以 `http://` 或 `https://` 開頭。 |
| `virtualHostedStyle` | 設為 `true` 時，系統會在主機名稱中指定儲存桶，而不是將儲存桶名稱放在路徑中。阿里雲 OSS 等儲存服務要求使用此方式。介面標籤為 **在主機名稱中指定儲存桶**。 |
| `auth` 及其鍵 | 憑證須具備儲存桶的 `s3:PutObject` 權限，請參閱 [AWS 驗證](#aws-驗證)。 |

### Apache Kafka

| 欄位 | 說明 |
|---|---|
| `brokers` | 必填。填寫主機和連接埠，多組以逗號分隔。 |
| `topic` | 必填。 |
| `tls` | 設為 `true` 時使用 TLS 加密連線。請連線至 Broker 的 TLS 連接埠，常見的是 9093、9094 或 9096。介面標籤為 **TLS 加密連線**。 |
| `tlsCaCert` | 若 Broker 憑證由私有 CA 簽發，請填寫該 CA 的 PEM 憑證。只有開啟 `tls` 時才能使用此欄位。留空時，系統會信任系統的 CA。 |

| `auth` | 介面 | 鍵 | 說明 |
|---|---|---|---|
| `none` | **無** | | 用於不要求憑證的 Broker。 |
| `sasl_plain` | **SASL/PLAIN** | `saslUsername`、`saslPassword` | 以原樣傳送密碼。未開啟 TLS 時，請只在內部網路使用。 |
| `sasl_scram_sha_256` | **SCRAM-SHA-256** | `saslUsername`、`saslPassword` | 不會透過網路傳輸密碼本身。 |
| `sasl_scram_sha_512` | **SCRAM-SHA-512** | `saslUsername`、`saslPassword` | Amazon MSK 使用的機制。 |
| `mtls` | **用戶端憑證** | `tlsClientCert`、`tlsClientKey` | 雙向 TLS，須開啟 `tls`。兩者皆須為 PEM 格式，私密金鑰不得加密。 |

TLS 可與 SASL 搭配使用：透過 TLS 使用 SCRAM 時，以 `SASL_SSL` 連線。

### HTTP / Webhook

| 欄位 | 說明 |
|---|---|
| `url` | 必填。填寫以 `http://` 或 `https://` 開頭的絕對網址。網址通常包含憑證，例如路徑或查詢參數中的金鑰，因此系統會將網址視為金鑰儲存。回應只會顯示 `urlOrigin`，也就是通訊協定、主機和連接埠。系統會拒絕含有使用者名稱和密碼的網址，請改用 `basic`。 |
| `method` | `post`（預設）或 `put`。 |
| `format` | `ndjson`（預設）以 `application/x-ndjson` 每行傳送一筆事件；`json` 則以 `application/json` 傳送單一 JSON 陣列。 |

| `auth` | 介面 | 鍵 | 要求 |
|---|---|---|---|
| `none` | **無** | | 不附帶憑證。 |
| `bearer` | **Bearer 權杖** | `bearerToken` | `Authorization: Bearer <token>` |
| `basic` | **基本驗證** | `basicUsername`、`basicPassword` | HTTP 基本驗證標頭，請搭配 `https` 使用。 |
| `header` | **自訂要求標頭** | `headerName`、`headerValue` | 將值放在指定的要求標頭中，例如 `X-API-Key` 或 `DD-API-KEY`。 |
| `hmac` | **HMAC 簽章** | `hmacSecret` | 為要求主體加上簽章，共用金鑰至少須有 16 個字元。 |

自訂要求標頭不得使用投遞流程設定的標頭：`Host`、`Content-Type`、`Content-Length`、`Content-Encoding`、`Transfer-Encoding`、`Connection`、`X-MoleSignal-Timestamp`、`X-MoleSignal-Sign`。

投遞遵循下列規則：

- 系統會將大於 4 MiB 的批次拆成多個要求傳送。若單筆事件超過此大小，系統會以一個獨立要求傳送。
- 所有 `2xx` 狀態碼都視為投遞成功。其他狀態碼一律視為投遞失敗，包括重新導向：系統不會跟隨重新導向。
- 每個要求的逾時時間為 30 秒。
- MoleSignal 會在送出要求前解析主機名稱，且只會連線至解析所得的位址。無論是直接指定或經 DNS 解析取得，MoleSignal 一律拒絕雲端中繼資料服務的位址：`169.254.0.0/16`、`fe80::/10`、`fd00:ec2::254`、`100.100.100.200`。其他私有位址仍可使用。

#### 驗證 HMAC 簽章

`auth` 設為 `hmac` 時，每個要求都會附帶兩個要求標頭：

| 要求標頭 | 內容 |
|---|---|
| `X-MoleSignal-Timestamp` | 要求時間，以 Unix 秒表示。 |
| `X-MoleSignal-Sign` | `sha256=<十六进制>`，使用共用金鑰對 `<timestamp>.<body>` 計算所得的 HMAC-SHA256。 |

驗證要求時，將時間戳記、一個 `.` 和原始要求主體的位元組串接起來，使用相同的金鑰計算 HMAC-SHA256，再以固定時間與簽章比對。拒絕早於目前時間數分鐘以上的時間戳記，避免遭攔截的要求日後被重送。

```python
import hashlib
import hmac
import time


def verify(secret: bytes, timestamp: str, signature: str, body: bytes, tolerance: int = 300) -> bool:
    if abs(time.time() - int(timestamp)) > tolerance:
        return False
    signed = timestamp.encode() + b"." + body
    expected = "sha256=" + hmac.new(secret, signed, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## AWS 驗證

S3 與 CloudWatch Logs 使用下列五種方式之一向 AWS 驗證：

| `auth` | 介面 | 鍵 | 憑證 |
|---|---|---|---|
| `access_key` | **存取金鑰** | `accessKey`、`secretKey` | IAM 使用者的長期金鑰。 |
| `temporary_key` | **暫時金鑰** | `accessKey`、`secretKey`、`sessionToken` | AWS STS 簽發的短期金鑰，必須搭配工作階段權杖使用。請在到期前更換。 |
| `node_role` | **節點身分** | | MoleSignal 所在節點的身分，不儲存任何金鑰。 |
| `assume_role` | **擔任角色** | `roleArn`，可選填 `accessKey` 與 `secretKey` | 使用組織的外部 ID，透過 AWS STS 擔任角色。 |
| `web_identity` | **Web Identity** | `roleArn` | 使用節點的 Web Identity 權杖擔任角色。 |

未指定 `auth` 時，系統會依已填寫的鍵判斷：有存取金鑰就使用 `access_key`，有 `roleArn` 就使用 `assume_role`，兩者皆無則使用 `node_role`。`roleArn` 的格式為 `arn:aws:iam::<account>:role/<name>`。

### 節點身分

`node_role` 使用 AWS SDK 在節點上可取得的身分：EKS 的服務帳號 IAM 角色（IRSA）或 EKS Pod Identity、ECS 任務角色，或 EC2 執行個體設定檔。連接器不會使用節點環境中的靜態金鑰（例如 `AWS_ACCESS_KEY_ID`）。

<Warning>
  節點身分及其 Web Identity 權杖由整個部署共用。部署中的每個組織都能選用 `node_role` 和 `web_identity`，因此所有組織的連接器都能存取節點身分可存取的資源，也能擔任任何信任節點權杖的角色。請只授予每個組織都可以擁有的存取權限。
</Warning>

### 擔任角色

`assume_role` 會向 AWS STS 申請該角色的一小時效期金鑰，並在到期前 5 分鐘更換。擔任角色時，預設使用節點身分作為基礎憑證。若部署未在 AWS 上執行，請勾選 **使用存取金鑰而非節點身分擔任角色**，並填寫一組 IAM 使用者的金鑰。

每個組織都使用專屬的外部 ID `molesignal-<组织 ID>` 擔任角色，此值無法修改。表單會在 **外部 ID** 欄位顯示此值，`GET /api/v1/connectors/aws-external-id` 也會傳回此值。請在角色的信任政策中將此外部 ID 設為必要條件，這樣其他組織即使知道角色的 ARN，也無法擔任該角色：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "<节点角色或 IAM 用户的 ARN>" },
      "Action": "sts:AssumeRole",
      "Condition": { "StringEquals": { "sts:ExternalId": "molesignal-<组织 ID>" } }
    }
  ]
}
```

工作階段名稱為 `molesignal-<连接器 ID>`，AWS CloudTrail 會以此名稱顯示。要求會送往連接器 `region` 所指定區域的 STS 端點：區域留空時使用 `us-east-1`，中國區域則使用 `amazonaws.com.cn` 網域名稱。

### Web Identity

`web_identity` 使用節點上 `AWS_WEB_IDENTITY_TOKEN_FILE` 指定路徑的 Web Identity 權杖擔任角色，例如 EKS 為 IRSA 投射的服務帳號權杖。連接器無法指定其他檔案。角色的信任政策須信任簽發該權杖的 OIDC 提供者。若節點未設定 `AWS_WEB_IDENTITY_TOKEN_FILE`，連接器就無法取得憑證。

連接器會在 `region` 所指定區域的 STS 端點兌換權杖；若節點環境已設定 `AWS_ENDPOINT_URL_STS`，則改用該端點。來自 IRSA 的節點身分也適用相同規則。

## 測試連線

**測試連線** 會在儲存前試用表單中的目前設定。金鑰欄位若留空，則使用已儲存的值。針對每種類型，系統只執行足以確認可投遞或擷取資料的最少操作：

| 類型 | 測試內容 |
|---|---|
| `s3` | 在前綴下寫入物件 `.molesignal-connection-test`，若有權限則再刪除。 |
| `kafka` | 從 Broker 讀取主題的中繼資料，驗證連線、TLS 與驗證設定，並確認主題存在。不寫入訊息。 |
| `http` | 傳送一筆標記為測試的事件：`"message": "MoleSignal connection test"`、`"molesignal_connection_test": true`。 |
| `aws_cloudwatch_logs` | 讀取日誌群組最近一分鐘內的事件，最多一筆。不寫入資料流，也不變更讀取位置。 |
| `kafka_source` | 比照 `kafka` 從 Broker 讀取主題的中繼資料。不讀取訊息，也不變更讀取位置。 |
| `s3_source` | 列出前綴下的一個物件，以驗證憑證和 `s3:ListBucket` 權限。不讀取物件內容，也不變更讀取位置。 |

測試會在 25 秒後逾時。透過 API 測試時，`POST /api/v1/connectors/test` 會接收要測試的 `kind` 與 `configJson`。若附上相同 `kind` 的已儲存連接器的 `id`，`***` 就代表該連接器已儲存的金鑰。若設定無法生效，系統會比照儲存時傳回 `400`。

```bash
curl -X POST http://localhost:5080/api/v1/connectors/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "id": "<connector id>",
        "kind": "kafka",
        "configJson": {
          "brokers": "b-1.example.com:9096",
          "topic": "logs",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "***"
        }
      }'
```

```json
{ "ok": true, "code": "ok", "detail": null, "elapsedMs": 412 }
```

`elapsedMs` 是測試所花的時間。測試失敗時，`code` 會指出原因，`detail` 則會附上對方的原始訊息，最多 600 個字元：

| `code` | 意義 |
|---|---|
| `ok` | 連線成功。 |
| `invalid` | 設定無法生效，或連接器是沒有可連線對象的推送來源。 |
| `no_credentials` | 無法取得 AWS 憑證：節點沒有身分，或沒有所需類型的身分。 |
| `denied` | 對方拒絕接受憑證，或未授予憑證所需的權限。 |
| `not_found` | 儲存桶、主題、日誌群組或位址不存在。 |
| `tls` | TLS 交握失敗：對方的憑證不受信任，或對方未出示憑證。 |
| `unreachable` | 無法解析主機名稱或連線至主機。 |
| `timeout` | 等候回應逾時。 |
| `failed` | 其他失敗。 |
