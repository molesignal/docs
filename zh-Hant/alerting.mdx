開啟 **警示**，完成從發現問題到確認、升級與解決的完整流程。[規則](/zh-Hant/alerting/rules)監控查詢或指標，符合條件時建立[事件](/zh-Hant/alerting/incidents)；其他系統送來的警示也會透過[告警來源](/zh-Hant/alerting/sources)建立事件。[警示路由](/zh-Hant/alerting/routing)決定將新事件交給哪個團隊，以及採用哪一項升級策略。事件的[升級策略](/zh-Hant/alerting/on-call#升級策略)會通知指定人員及[值班排程](/zh-Hant/alerting/on-call#值班排程)中的值班人員；若無人確認，就依序通知下一級。[通知管道](/zh-Hant/notification-channels)負責傳送每則通知。[靜默](/zh-Hant/alerting/silences)會在維護期間暫停通知，[抑制](/zh-Hant/alerting/inhibition)會在有更嚴重的事件時停止傳送次要事件的通知，[語意分組](/zh-Hant/alerting/silences#語意分組)則將相關事件歸為一組。

## 警示中心

頁面依用途分為五組，列在左側選單中。頁面較寬時，可透過選單的搜尋列收合選單，讓內容使用整個頁面寬度。

| 分組 | 頁面 | 用途 | 指南 |
|---|---|---|---|
| 處理 | **警示事件** | 確認、靜默、解決與調查目前觸發中的事件。 | [警示事件](/zh-Hant/alerting/incidents) |
|  | **歷史紀錄** | 查看過往事件，可依服務和狀態搜尋。 | [歷史紀錄](/zh-Hant/alerting/incidents#歷史紀錄) |
|  | **事後檢討** | 記錄事件的內部事後檢討與改進事項，並設定重大事件。 | [重大事件與事後檢討](/zh-Hant/alerting/major-incidents) |
|  | **洞察** | 查看事件數量、復原時間、產生雜訊的規則、受影響的服務、人員的回應情況與值班負擔。 | [洞察](/zh-Hant/alerting/incidents#洞察) |
| 偵測 | **規則** | 閾值、預測、離群值、組合、心跳規則，以及異常規則與即時規則。 | [警示規則](/zh-Hant/alerting/rules) |
|  | **自動探索** | 無須建立規則即可找出問題：APM 服務的突變、表現變差的新版本、新出現或再次出現的前端錯誤、錯誤日誌暴增，以及發生問題的主機和容器。 | [自動探索](/zh-Hant/alerting/discovery) |
| 降低雜訊 | **分組** | 透過語意分組將相關事件歸為一組。 | [語意分組](/zh-Hant/alerting/silences#語意分組) |
|  | **告警來源** | Alertmanager、Grafana、Datadog、PagerDuty、Zabbix、雲端監控（阿里雲、騰訊雲、Amazon CloudWatch）、電子郵件或介面送來的警示。 | [外部警示](/zh-Hant/alerting/sources) |
|  | **抑制** | 有更嚴重或更上游的事件時，停止傳送次要事件的通知。 | [抑制](/zh-Hant/alerting/inhibition) |
|  | **靜默策略** | 暫停傳送符合條件的事件通知。 | [靜默策略](/zh-Hant/alerting/silences#靜默策略) |
| 通知 | **路由** | 決定將新事件交給哪個團隊，以及採用哪一項升級策略。 | [警示路由](/zh-Hant/alerting/routing) |
|  | **升級** | 指定通知對象、通知順序，以及何時轉交下一級。 | [升級策略](/zh-Hant/alerting/on-call#升級策略) |
|  | **值班排程** | 輪值、臨時代班、換班申請與行事曆訂閱。 | [值班排程](/zh-Hant/alerting/on-call#值班排程) |
| 整合 | **修復動作** | 在事件中一鍵發起 HTTP 與 Kubernetes 處置作業，核准後執行。 | [修復動作](/zh-Hant/alerting/remediation) |
|  | **工單** | 連接 Jira、ServiceNow 或飛書專案，為事件建立工單並同步狀態。 | [工單](/zh-Hant/alerting/tickets) |

若要向客戶通報事件與維護資訊，請使用獨立的狀態頁模組。請參閱[狀態頁](/zh-Hant/status-pages)。

## 設定警示

工作區通常依照下列順序準備首次警示通知：

<Steps>
  <Step title="串接通知管道">
    在[設定 → 通知 → 連接器](/zh-Hant/notification-channels)中設定電子郵件、即時通訊 App、電話與簡訊等連接器，並請成員在[帳號設定 → 通知設定](/zh-Hant/account#通知設定)中綁定個人通知方式。
  </Step>
  <Step title="設定值班排程">
    依團隊的輪值方式建立[值班排程](/zh-Hant/alerting/on-call#建立排班)。
  </Step>
  <Step title="建立預設升級策略">
    建立名為 `default` 的策略，先通知值班排程中的值班人員，再通知負責人。若規則工作台中儲存的規則無法透過[路由](/zh-Hant/alerting/routing)決定要採用哪個團隊的值班策略，就使用這項預設策略。請參閱[預設策略](/zh-Hant/alerting/on-call#預設策略)。
  </Step>
  <Step title="建立並測試規則">
    在[規則工作台](/zh-Hant/alerting/rules#建立閾值規則)中從預設設定開始，使用實際資料測試後再儲存。
  </Step>
  <Step title="演練">
    使用[觸發規則](/zh-Hant/api/alerting/trigger-rule) API 主動觸發一條規則，驗證通知是否送達、無人確認時是否會依序升級，以及確認後是否會停止升級。
  </Step>
</Steps>

若要了解哪些情況應觸發警示，以及如何設定路由，請參閱[讓正式環境的警示引導應變](/zh-Hant/best-practices/actionable-alerts)與[設定值班與通知](/zh-Hant/best-practices/on-call-setup)。

## 權限

| 權限 | 功能 |
|---|---|
| `alerts.incidents.read` | 讀取事件、事件歷史紀錄與洞察。 |
| `alerts.incidents.acknowledge` | 確認、解決與暫緩事件及事件分組。 |
| `alerts.incidents.update` | 改派事件、增派成員、變更嚴重程度、新增備註，以及管理事件處置的角色、任務與進度。 |
| `alerts.incidents.escalate` | 升級與合併事件，宣告重大事件。 |
| `alerts.incidents.create`、`alerts.incidents.silence` | 手動建立事件；將事件設為靜默。 |
| `alerts.incidents.remediate`、`alerts.incidents.tickets`、`alerts.incidents.rca` | 在事件中發起修復動作、建立工單、記錄根本原因。 |
| `alerts.rules.read`、`alerts.rules.manage` | 讀取規則；建立與修改規則。 |
| `alerts.routing.read`、`alerts.routing.manage` | 讀取與修改路由規則及團隊的值班策略。 |
| `alerts.escalations.read`、`alerts.escalations.manage`、`alerts.escalations.delete` | 讀取、修改與刪除升級策略。 |
| `alerts.sources.read`、`alerts.sources.manage` | 讀取與修改告警來源。 |
| `alerts.mutes.read`、`alerts.mutes.manage` | 讀取靜默設定；建立、修改與移除靜默設定。 |
| `alerts.inhibitions.read`、`alerts.inhibitions.manage` | 讀取抑制規則；建立、修改與刪除抑制規則。 |
| `alerts.semantic_groups.manage` | 管理分組。 |
| `alerts.remediation.read`、`alerts.remediation.manage` | 讀取與定義修復動作。 |
| `alerts.tickets.read`、`alerts.tickets.manage` | 讀取與管理工單連接器。 |
| `alerts.response.read`、`alerts.response.manage` | 讀取與修改重大事件設定。 |
| `alerts.discovery.read` | 讀取自動探索找出的問題。 |
| `schedules.read` | 讀取值班排程與目前的值班人員。 |
| `schedules.create`、`schedules.update`、`schedules.delete` | 建立、修改與刪除值班排程及其輪值安排。 |
| `schedules.overrides.manage`、`schedules.swaps.request`、`schedules.swaps.approve` | 安排代班；申請換班；核准或駁回換班申請。 |
| `postmortems.read`、`postmortems.manage` | 查看事後檢討；撰寫事後檢討與改進事項。 |
