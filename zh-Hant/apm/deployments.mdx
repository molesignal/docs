服務頁面的**部署**索引標籤彙整兩種來源：管線回報的發佈事件，以及服務 Span 的 `service.version` 所記錄的版本。即使管線沒有回報版本，也會根據 Span 顯示該版本。

## 發佈時間軸

時間軸按從新到舊的順序列出時間範圍內的服務變更：

| 事件 | 條件 |
|---|---|
| **發佈** | 管線回報了一次成功的發佈。 |
| **發佈失敗** | 管線回報了一次失敗的發佈。發佈失敗不會變更執行中的版本。 |
| **復原** | 管線回報了復原，或回報發佈的版本曾在另一個版本之前執行。這一列會標明從哪個版本復原。 |
| **退回** | Span 退回到管線未回報的舊版本：最近觀測到的版本比某個較新版本更早首次出現，而該較新版本已停止執行超過五分鐘。 |
| **首次出現** | Span 記錄了管線未回報的版本。 |
| **設定變更** | 管線或工具回報了一次設定變更。這一列會顯示變更說明。 |
| **功能開關** | 管線或工具回報了一次功能開關變更。這一列會顯示變更說明。 |

設定變更和功能開關不會變更執行中的版本，也沒有各自的指標。這些事件會列在洞察的鄰近變更中，請參閱[找出鄰近變更](/zh-Hant/apm/insights#發現前後的變更)。

系統會為回報的發佈顯示 commit、PR、CI 執行記錄和作者。如果儲存庫使用 http 或 https 網址，按一下 commit，就會依 GitHub、GitLab 或 Bitbucket 的提交網址格式開啟該筆提交的網頁。

每個版本最新的一列會顯示該版本在時間範圍內的請求數、錯誤率和 p95，並附上與上一個首次出現的版本比較後的結論：

| 結論 | 條件 |
|---|---|
| **變差** | 錯誤率至少上升 1 個百分點且達到原來的 1.5 倍，或 p95 同時增加至少五分之一及 50 毫秒。結論後會標明哪一項變差。 |
| **變好** | 其中一項下降的幅度達到相同門檻，且沒有任何一項變差。 |
| **無明顯變化** | 兩項變化都未達到上述幅度。 |
| **請求數不足** | 任一版本的請求數低於版本比較所需的數量，預設為 1,000。 |

按一下結論，即可在**比較兩個版本**中開啟這兩個版本，並查看變慢的端點和次數增加的錯誤。概觀的最近部署也會標示變差或變好的版本。

## 金絲雀

兩個版本同時執行時（例如金絲雀版本與即將被取代的版本並存），時間軸上方會顯示一張卡片，並排比較這兩個版本。如果兩個版本都在服務最後一筆 Span 往前推算的五分鐘內出現過，就視為同時執行。卡片會比較最新的兩個版本，從較新版本首次出現時算起：

- 每個版本處理的請求比例；
- 每個版本的請求數、錯誤率、p50、p95 和 p99；
- 較新版本與較舊版本的比較結論。

## 從 CI 回報發佈

管線透過 `POST /api/v1/apm/deployments` 回報發佈。請求需要具備 `apm.deploy` 權限的 API 權杖。擁有者、管理員和編輯者都具備這項權限，存取權杖所套用的 **資料寫入** 政策也包含這項權限。

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "version": "2.4.0", "commit": "9f2c1e7a4b3d", "repository": "https://github.com/acme/checkout", "ciUrl": "https://ci.example.com/runs/7"}'
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `service` | 是 | 服務名稱，與 Span 的 `service.name` 一致。最多 255 個字元。 |
| `version` | 發佈時必填 | 發佈的版本，與 Span 的 `service.version` 一致。最多 192 個字元。 |
| `kind` | 否 | `deployment`（預設）、`configuration` 或 `feature_flag`。 |
| `namespace` | 否 | 服務的 `service.namespace`。留空時，會在所有命名空間中顯示。 |
| `environment` | 否 | 環境，即 `deployment.environment.name`。留空時，會在所有環境中顯示。 |
| `status` | 否 | `succeeded`（預設）、`failed` 或 `rolled_back`。`rolled_back` 表示這次發佈將服務復原至 `version`。 |
| `commit` | 否 | 發佈的提交：最多 64 個字母或數字。 |
| `repository` | 否 | 程式碼儲存庫：https、http、ssh 或 git 位址，最多 512 個字元。儲存時會以 `****` 遮蔽位址中的密碼，https 位址中的使用者名稱也會遮蔽。 |
| `pullRequest` | 否 | PR 的 http 或 https 連結。 |
| `author` | 否 | 發佈者，最多 128 個字元。 |
| `ciUrl` | 否 | CI 執行記錄的 http 或 https 連結。 |
| `description` | 否 | 最多 1,000 個字元。將滑鼠游標停在事件上時顯示。 |
| `deployedAt` | 否 | 發佈時間，以 Unix 紀元起算的微秒數表示。預設為收到請求的時間。 |

服務名稱和環境採用 APM 的命名方式：組織的命名規則、環境對應和別名都適用，處理方式與 Span 相同。請參閱 [APM 設定](/zh-Hant/apm/settings)。

**資料來源**頁面上的 **GitHub Actions**、**GitLab CI/CD** 和 **Jenkins** 區塊提供下列步驟，並已預先填入工作區網址。

### GitHub Actions

將權杖儲存為儲存庫的 Secret，再於負責部署的作業中加入一個步驟。`if: always()` 可確保發佈失敗時也會回報。

```yaml
- name: Report the deployment to MoleSignal
  if: always()
  env:
    MOLESIGNAL_TOKEN: ${{ secrets.MOLESIGNAL_TOKEN }}
    DEPLOY_STATUS: ${{ job.status == 'success' && 'succeeded' || 'failed' }}
  run: |
    cat > deployment.json <<EOF
    {
      "service": "checkout",
      "environment": "production",
      "version": "${GITHUB_SHA::12}",
      "status": "$DEPLOY_STATUS",
      "commit": "$GITHUB_SHA",
      "repository": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY",
      "author": "$GITHUB_ACTOR",
      "ciUrl": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID"
    }
    EOF
    curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
      -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
      -H "Content-Type: application/json" \
      --data-binary @deployment.json
```

### GitLab CI/CD

將權杖新增為名為 `MOLESIGNAL_TOKEN` 的隱藏 CI/CD 變數，再於部署作業的 `after_script` 中回報。無論部署成功或失敗，`after_script` 都會執行。

```yaml
deploy:
  stage: deploy
  environment: production
  script:
    - ./deploy.sh
  after_script:
    - |
      if [ "$CI_JOB_STATUS" = "success" ]; then DEPLOY_STATUS=succeeded; else DEPLOY_STATUS=failed; fi
      cat > deployment.json <<EOF
      {
        "service": "checkout",
        "environment": "$CI_ENVIRONMENT_NAME",
        "version": "$CI_COMMIT_SHORT_SHA",
        "status": "$DEPLOY_STATUS",
        "commit": "$CI_COMMIT_SHA",
        "repository": "$CI_PROJECT_URL",
        "author": "$GITLAB_USER_LOGIN",
        "ciUrl": "$CI_PIPELINE_URL"
      }
      EOF
      curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
        -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
        -H "Content-Type: application/json" \
        --data-binary @deployment.json
```

### Jenkins

將權杖新增為 ID 為 `molesignal-token` 的 **Secret text** 認證，再於管線的 `post` 區塊中回報。`post { always }` 在建置失敗時也會回報。儲存時會遮蔽 `GIT_URL` 中的密碼。

```groovy
post {
  always {
    script {
      writeFile file: 'deployment.json', text: groovy.json.JsonOutput.toJson([
        service: 'checkout',
        environment: 'production',
        version: env.GIT_COMMIT.take(12),
        status: currentBuild.currentResult == 'SUCCESS' ? 'succeeded' : 'failed',
        commit: env.GIT_COMMIT,
        repository: env.GIT_URL,
        ci_url: env.BUILD_URL,
      ])
    }
    withCredentials([string(credentialsId: 'molesignal-token', variable: 'MOLESIGNAL_TOKEN')]) {
      sh '''
        curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
          -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
          -H "Content-Type: application/json" \
          --data-binary @deployment.json
      '''
    }
  }
}
```

## 回報設定變更與功能開關

透過同一個 API 回報設定變更和功能開關。設定 `kind`，並在說明中寫明變更內容，不必提供版本。

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "kind": "feature_flag", "description": "new_checkout on for 10% of users"}'
```

## 疑難排解

| 現象 | 檢查 |
|---|---|
| 回報的發佈未出現在時間軸上 | 確認時間範圍包含 `deployedAt`，且 `service` 與 APM 中的服務名稱一致。回報時指定環境的發佈只會在該環境中顯示。 |
| 同一次發佈及其版本分別顯示在兩列 | 回報的 `version` 與 Span 的 `service.version` 不同。請回報相同的值。 |
| 發佈 API 傳回 `403` | 權杖無法使用 `apm.deploy`：權杖的權限範圍未包含這項權限，或權杖所屬的成員或服務帳號沒有這項權限。 |
| 發佈 API 傳回 `400` | 某個欄位超出上表的限制。錯誤訊息會指出是哪個欄位。 |
