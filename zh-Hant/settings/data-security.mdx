**設定** 的 **資料安全** 群組包含 **加密金鑰**、**正規表示式模式**、**欄位遮罩**、**網域管理** 和 **稽核**。檢視前四項需要 `org.field_masking.read`，修改需要 `org.field_masking.manage`；**稽核** 需要 `audit.read`。稽核記錄的保留期限由[平台設定](/zh-Hant/settings/platform#稽核記錄保留)管理。

## 加密金鑰

**加密金鑰** 列出工作區的資料金鑰，包括演算法、版本和上次輪替時間。資料流首次寫入[加密欄位](/zh-Hant/streams#加密欄位)時，MoleSignal 會自動建立對應的金鑰，名稱為 `__field_default__`。每把金鑰都由根金鑰 `MS_CIPHER_KEY` 封裝，金鑰材料不會離開伺服器端。

| 操作 | 方法 |
|---|---|
| **新增金鑰** | 填寫 **名稱** 和以 base64 編碼的 32 位元組金鑰材料（`keyMaterialB64`）。 |
| **輪替** | 貼上新的 32 位元組 base64 金鑰材料。輪替會新增一個版本：新資料使用新版本，舊版本仍可解密先前以該版本加密的資料。 |
| 刪除 | 使用這把金鑰加密的資料將無法解密。 |

<Warning>
  遺失 `MS_CIPHER_KEY` 會導致所有加密欄位無法復原。請參閱[欄位層級加密](/zh-Hant/security#欄位層級加密)。
</Warning>

## 正規表示式模式

正規表示式模式可找出銀行卡號、權杖等敏感文字，並加以取代。

1. 按一下 **新增模式**。
2. 填寫 **名稱**、**規則運算式** 和 **說明**。儲存時，伺服器端會驗證規則運算式。
3. 填寫 **取代為**。支援 `$1` 等擷取群組；留空會刪除符合模式的片段。
4. 使用 **寫入時套用遮罩** 選擇何時生效，再按一下 **建立**。

| **寫入時套用遮罩** | 效果 |
|---|---|
| 開啟 | 系統會在管線處理後、寫入磁碟前，對每個寫入事件的所有字串值套用遮罩，原文將永久遺失。 |
| 關閉 | 儲存的資料會保留原文。在 SQL 查詢中呼叫 `mask(<column>)`，即可取得套用這些正規表示式後的欄。 |

`mask()` 會套用工作區的所有正規表示式模式。清單的 **遮罩** 欄會顯示各模式為 **寫入時** 或 **僅查詢時**。

## 欄位遮罩

欄位遮罩會在查詢結果中隱藏欄位值的一部分，查詢仍以原始值計算。欄位遮罩不適用於指標資料流。

1. 按一下 **新增規則**，並填寫 **規則名稱**。
2. **欄位比對**：輸入完整欄位名稱，或使用 `*`、`?` 萬用字元，例如 `user.*`。不支援正規表示式。
3. 可使用 **資料流比對**（例如 `customer-*`）和 **資料流類型** 縮小範圍。
4. 選擇 **演算法**，保持 **啟用規則** 開啟後儲存。

| 演算法 | 效果 |
|---|---|
| **完整遮罩** | 使用 **取代內容** 取代整個值。 |
| **區間遮罩** | 遮罩從 **起始字元** 到 **結束字元（不含）** 的字元。 |
| **內部遮罩** | 依 **保留的前綴字元數** 和 **保留的後綴字元數** 保留兩端字元，遮罩中間部分。 |
| **外部遮罩** | 只保留從 **起始字元** 到 **結束字元（不含）** 的字元，遮罩兩側。 |
| **HMAC-SHA-256 雜湊** | 使用伺服器端管理的工作區金鑰產生摘要，以取代原始值。相同的值會產生相同的摘要，因此結果仍可分組和關聯。 |

欄位會套用第一條符合且已啟用的規則。拖曳列可調整順序。[資料流](/zh-Hant/streams#schema-與欄位)的欄位設定可覆寫繼承的規則，也可關閉個別欄位的遮罩。

## 網域管理

**網域管理** 可讓工作區透過自訂網域存取。MoleSignal 會自動申請和續期憑證。

1. 啟用 `[http.tls]` 並填寫 `account_email`。請參閱 [HTTP TLS 與 ACME](/zh-Hant/configuration#http-tls-與-acme)。
2. 將網域的 DNS 指向 MoleSignal，讓 ACME 服務能透過未加密的 HTTP 連接埠存取 `/.well-known/acme-challenge/`。
3. 按一下 **新增網域**，填寫 **網域**，再按一下 **新增網域**。

清單會顯示各網域的 **狀態**、憑證到期時間和 **最近一次錯誤**。新增的網域在憑證簽發前會顯示為 `pending`，簽發後會變為 `active`。憑證會在到期前 30 天內自動續期。移除網域後，MoleSignal 不再透過該網域提供服務。

## 稽核

使用 **稽核** 搜尋工作區的稽核記錄，包括安全性相關操作，以及資源和設定的變更。每筆記錄都包含操作者、動作、目標、狀態和時間。

| 篩選條件 | 用法 |
|---|---|
| **起始時間** / **結束** | 時間範圍，可使用絕對時間，也可使用 `now-24h` 之類的相對時間。 |
| **操作者類型** / **操作者** | 指定某類操作者或特定使用者。 |
| **動作** | 動作鍵，例如 `audit_retention.update`。 |
| **目標類型** / **目標 ID** | 已修改資源的類型與 ID。 |

按一下 **應用程式** 搜尋，或按一下 **重設** 清除篩選條件。按一下任一列檢視完整事件，並可 **複製 ID**。Mole Agent 對話的事件會顯示該對話的歷程。頁面頂端會說明記錄保留多久；按一下 **變更保留期限** 會開啟 `_sys` 中的平台設定。

稽核記錄不會包含憑證、模型金鑰、敏感的 Webhook 要求標頭和簽章材料。請參閱[稽核](/zh-Hant/security#稽核)。

### 稽核資料流

系統也會將每個稽核事件寫入工作區的 `_audit` 日誌資料流，每個事件各占一列。因此，可在 **日誌** 中搜尋，也可使用[排程管線](/zh-Hant/pipelines#平台資料串流)傳送至其他目的地，例如 SIEM。系統會以與本頁記錄相同的方式清理這一列，並以事件發生時間作為時間戳記。

| 欄位 | 內容 |
|---|---|
| `audit_id` | 事件的 ID，即 **複製 ID** 取得的值。 |
| `actor_kind`、`actor_id` | 操作者。 |
| `action` | 動作鍵。 |
| `target_kind`、`target_id` | 已修改的資源，僅在事件包含此資訊時寫入。 |
| `ip`、`user_agent` | 要求的來源資訊，僅在事件記錄此資訊時寫入。 |
| `payload` | 事件詳細資料，僅在有內容時寫入。 |

以本頁和[稽核 API](/zh-Hant/api/admin/audit) 讀取的記錄為準。每個節點會在背景分批寫入這些列，最多可暫存 4096 個事件。佇列已滿時，系統不會將該列寫入資料流，但仍會保留原始記錄。這些列與其他資料流的列相同，皆適用各自資料流的保留期限。

讀取 `_audit` 和檢視本頁一樣，都需要 `audit.read`：

- 缺少這項權限時，資料流清單不會顯示 `_audit`，也無法檢視、修改或刪除。查詢 `_audit` 會傳回 `403`。產品內的查詢、查詢 API（包括 NDJSON 串流輸出）、Flight SQL 和聯合搜尋皆適用此限制。聯合搜尋由遠端叢集檢查呼叫端的權杖是否具備 `audit.read`。
- 查詢 `_audit` 一律在要求內執行。即使帶有 `Prefer: respond-async`，也不會轉成搜尋工作。提交讀取 `_audit` 的搜尋工作會傳回 `400`。
- 背景工作若未以特定使用者的身分執行，就無法讀取 `_audit`，無論由誰儲存。若告警規則讀取 `_audit`（資料流指向 `_audit`，或陳述式在任何位置讀取 `_audit`），或排程日誌巡檢選用 `_audit`，就無法儲存，呼叫會傳回 `400`。擁有者也適用此限制。報表同樣無法讀取 `_audit`。
- 無論使用何種憑證，Mole Agent 工具和 [Inbound MCP](/zh-Hant/inbound-mcp) 都無法讀取 `_audit` 的任何列或欄位。

[排程管線](/zh-Hant/pipelines#平台資料串流)會以最後儲存管線的使用者權限讀取 `_audit`。暫停和恢復不算儲存。管線詳細資料頁面頂端的 **讀取 \_audit 的身分** 會顯示該使用者，編輯器的來源下方也會顯示。若目前的使用者不是該使用者，但具備 `audit.read` 且可儲存，編輯器還會顯示 **儲存後改用你的權限讀取。**

- 儲存變更需要 `audit.read`。使用服務帳號權杖會傳回 `403`，因為執行時無法再次驗證該權杖的權限。個人權杖則以簽發者的權限為準。
- 每次讀取前，系統都會確認該使用者是否能登入、是否仍屬於組織，以及是否仍具備 `audit.read`。若不符合條件，該次讀取就會失敗，執行記錄會指出使用者和原因，例如 `` `_audit` is read with the access of admin@example.com, who no longer holds audit.read ``。系統不會停用管線，讀取位置會維持不變，也不會略過事件。
- 當該使用者重新取得 `audit.read`，或由具備該權限的使用者儲存管線後（即使沒有修改也可以），管線會從停止的位置繼續讀取。缺少 `audit.read` 或使用服務帳號權杖原樣儲存時，系統不會變更任何設定，也不會回報錯誤。
- 暫停和恢復只需要 `pipelines.pause`，也不會變更讀取時使用的身分。恢復後會和其他管線一樣[從頭開始](/zh-Hant/pipelines#排程與讀取位置)，因此若要保留讀取位置，請勿暫停。
- 回填會以提交者的權限讀取。提交時需要 `audit.read`，工作實際執行時會再次驗證。

管線複製到目的地的列會視為一般資料列。具備目的地讀取權限的使用者皆可讀取這些列。
