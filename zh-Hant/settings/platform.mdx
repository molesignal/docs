平台設定位於受保護的 `_sys` 組織中。使用工作區切換器切換到 `_sys`；只有超級管理員和獲授平台角色的帳號可以進入。這些頁面位於 `_sys` 的 **設定** 中。檢視頁面需要對應群組的 `.read` 權限，修改設定需要 `.manage` 權限，每個頁面都需要平台權限。

| 區段 | 群組 | 權限 |
|---|---|---|
| **組織管理** | 平台 | `sys.organizations.read` |
| **登入速率限制** | 平台 | `sys.settings.signin.manage` |
| **用戶端 IP 識別** | 資料平面 | `sys.settings.signin.manage` |
| **資料保留** | 資料平面 | `sys.settings.retention.manage` |
| **指標基數** | 資料平面 | `sys.settings.limits.manage` |
| **資料擷取用量** | 資料平面 | `sys.settings.limits.manage` |
| **稽核記錄保留** | 資料安全 | `sys.settings.retention.manage` |

各節點從資料庫讀取這些設定，修改後不必重新啟動。

## 組織管理

**組織管理** 列出執行個體中的租戶組織，包括名稱、識別資訊、狀態和 ID。

| 操作 | 效果 |
|---|---|
| **建立組織** | 使用 **名稱** 和 **識別資訊** 建立租戶組織。建立後無法修改識別資訊。 |
| 停用 | 立即暫停存取該組織：重新啟用前，系統會拒絕該組織的工作階段和 API 憑證。 |
| 啟用 | 恢復該組織成員和憑證的存取權。 |
| 刪除 | 永久刪除該組織：組織會立即消失，背景程序會在幾分鐘內清除其資料（包括已儲存的檔案）。識別資訊可立即重複使用。 |

至少要保留一個已啟用的租戶組織，且無法修改 `_sys` 組織本身。在各組織的[身分與存取](/zh-Hant/identity/members)中管理成員：先在[組織](/zh-Hant/identity/teams#組織)中按一下 **管理 IAM**。

## 登入速率限制

**登入速率限制** 可阻擋憑證填充和暴力破解，也能避免有人故意輸入錯誤密碼，導致帳號遭鎖定。這項功能會計算帳號密碼驗證失敗的次數，涵蓋密碼登入、LDAP 登入、資料庫用戶端的帳號登入、[連結現有帳號](/zh-Hant/identity/sso)時的密碼確認，以及[新增第二項驗證因素](/zh-Hant/identity/mfa)前的密碼確認。[公開連結](/zh-Hant/resource-sharing#存取密碼的限制)的存取密碼也會計數，每個連結視為一個帳號。通行金鑰（Passkey）和 OIDC、OAuth 2.0、SAML 單一登入不計數，也不受限制。

| 設定 | 預設值 | 達到上限後 |
|---|---|---|
| **同一位址、同一帳號** | 5 次 | 鎖定該位址對此帳號的登入，其他位址不受影響。 |
| **同一位址、任何帳號** | 30 次 | 該位址無法再使用密碼登入，共用該位址的使用者也會受影響。 |
| **同一帳號、所有位址** | 20 次 | 不鎖定帳號，改為限制登入速率。若此帳號最近 30 天內曾從某個位址成功登入，從該位址登入不受速率限制。連續一個計數期間沒有新的失敗，才會將計數歸零。 |
| **限制期間的密碼驗證間隔** | 60 秒 | 範圍為 1 到 600 秒。 |
| **鎖定與計數期間** | 15 分鐘 | 決定位址鎖定多久，以及往前計算多久內的失敗次數。範圍為 1 到 1440 分鐘。 |

將次數設為 `0` 即可停用該項目，範圍為 0 到 100000。修改後立即生效，並以 `signin_limits.update` 寫入平台稽核記錄。

| 情況 | 結果 |
|---|---|
| 遭拒絕的請求 | 回傳 `429` 和 `Retry-After`，不驗證密碼，也不延長任何鎖定。因此，鎖定最長不超過設定的期間。 |
| 帳號不存在 | 計數與回應方式均與帳號存在時相同，回應不會透露帳號是否存在。 |
| 密碼正確 | 清除該位址對此帳號的失敗次數。位址和帳號各自的計數只扣除這一次，不會歸零。 |
| 服務無法使用（例如無法連線至目錄服務） | 不計為失敗。 |
| 剛達到上限 | 以 `signin.lockout` 寫入平台稽核記錄，記下位址和達到上限的項目。僅在帳號存在時記下帳號。 |
| 成功重設密碼 | 立即解除該帳號的鎖定，該位址不再受帳號速率限制。 |
| 公開連結的存取密碼 | 每個連結視為一個帳號。若最近 30 天內曾從某個位址開啟此連結，從該位址存取不受速率限制。存取密碼輸入錯誤與登入失敗一併計入 **同一位址、任何帳號**。達到上限後，該位址也無法再使用密碼登入。 |
| 公開連結剛達到上限 | 以 `resource_share.lockout` 寫入連結所屬工作區的稽核記錄，記下連結、位址和達到上限的項目。**同一位址、任何帳號** 達到上限時，也會以 `signin.lockout` 寫入平台稽核記錄。 |

這些項目依[用戶端 IP 識別](#用戶端-ip-識別)取得位址，IPv6 以 /64 為單位計數。預設不將私有位址納入計數：若部署在代理後方卻未設定代理，所有使用者都會顯示為代理的位址。若將該位址納入計數，只要有一人輸錯幾次密碼，所有人都可能無法登入。此時只有 **同一帳號、所有位址** 生效。若使用者確實從內部網路連線，請開啟 **允許將私有位址視為用戶端位址**。

頁面上的 **你目前的位址** 會顯示此請求判定的位址，以及是否將該位址納入計數。如果請求帶有轉送 Header，系統卻採用連線位址，頁面會顯示提示，指出前方可能有尚未設定的代理。

確實需要提前解鎖時，請在中繼資料庫執行 `DELETE FROM signin_attempts`，清除所有計數。

## 用戶端 IP 識別

擷取使用者體驗資料時，系統會記錄每個瀏覽器或裝置的位址，並據此查出國家、行政區和城市；[登入速率限制](#登入速率限制)依位址計算失敗次數；[公開連結](/zh-Hant/resource-sharing#稽核與權限)的稽核記錄會記下存取者的位址。**用戶端 IP 識別** 決定從何處取得該位址，適用於所有組織。

| **位址來源** | 適用情境 |
|---|---|
| **直接連線位址** | 預設值。使用 TCP 對端位址，忽略所有轉送 Header。適用於資料擷取端點直接對外公開的情況。 |
| **單值 Header** | 從 CDN 或代理設定的 Header（例如 `CF-Connecting-IP`）讀取單一純 IP 位址。 |
| **轉送 IP 鏈** | 從右往左檢查 `X-Forwarded-For` 等 IP 鏈，略過受信任的代理，取第一個不受信任的位址。**位址鏈長度上限** 限制單一請求最多可讀取的位址數，範圍為 1 到 64。 |

部署在代理後方時，還需要設定：

| 欄位 | 規則 |
|---|---|
| **用戶端 IP Header** | 要讀取的 Header。系統不接受 `Authorization`、`Cookie`、API Key 和用戶端憑證 Header。 |
| **受信任的代理 CIDR** | 每行填入一個 IPv4 或 IPv6 CIDR，最多 64 個。只有連線的對端位於這些網路中時，系統才會讀取 Header。`/0` 網路會信任該位址家族的所有來源，只應在受保護的入口後方使用。 |
| **改用連線位址** | Header 缺少、格式錯誤、超過長度上限或沒有可用位址時，使用 TCP 對端位址。 |

無論使用哪種位址來源，都可以設定 **允許將私有位址視為用戶端位址**。開啟後，系統會接受受信任 Header 中的私有網路、回送（loopback）和連結本機位址，[登入速率限制](#登入速率限制)也會依這些位址計數。使用者從內部網路連線時，請開啟此設定；若前方有代理但未在此設定代理，請保持關閉，否則所有使用者都會計為同一個位址。

## 資料保留

**資料保留** 設定未個別指定保留期限的資料流要保留多少天：預設為 30 天，範圍為 1 到 3650 天。可在[資料流](/zh-Hant/streams#保留與刪除)中為每個資料流設定個別保留期限。系統會在下次清理時刪除超過保留期限的資料，且無法復原。

輸入較短的保留期限時，頁面會根據檔案目錄估算此次修改將刪除的資料，列出各資料流的資料列數、大小和最早的資料，並將最大的排在前面。儲存時需要確認；若達到 1 GiB 或一百萬列，或無法估算，還需要再輸入一次保留天數。延長保留期限時不會要求確認。工作階段重播和 Profile 封存檔也會依此設定清理，但不納入估算。

同一頁的 **合成監測結果** 設定合成監測的執行結果要保留多少天：預設為 30 天，範圍為 0 到 3650 天，0 表示永久保留。系統每天清理一次較舊的執行結果及其附件，以及已結束的任務；目前顯示為某個地點最新結果的項目，以及發布修訂版本所依據的測試結果，則會保留。可用率計算所讀取的 `_synthetic_results` 資料流依該資料流自己的保留期限保留，請參閱[合成監測](/zh-Hant/synthetics#結果資料流與保留期限)。

同一頁的 **儲存目錄歷程** 設定檔案目錄中已結束的記錄要保留多少天：預設為 7 天，範圍為 0 到 3650 天，0 表示永久保留。這些記錄包括垃圾回收已刪除的檔案、這些檔案所屬的舊資料區段和舊分割區清單，以及已關閉的寫入串流的排清記錄。系統每十分鐘清理一次超過此期限的記錄，不影響資料本身，資料流的累計接收量也不變。

## 指標基數

**指標基數** 限制同時處於活躍狀態的 Prometheus 時間序列數量，避免具有大量不同值的標籤耗盡記憶體與儲存空間。

| 上限 | 預設值 | 意義 |
|---|---|---|
| **每個組織** | 200,000 | 單一組織的活躍時間序列數量。 |
| **每個指標** | 100,000 | 組織中單一指標的活躍時間序列數量，不得超過每個組織的上限。 |

達到上限後，系統會拒絕寫入新的時間序列，現有的時間序列仍可照常寫入。一段時間未收到資料的時間序列不再計為活躍。各節點每 30 秒重新讀取一次上限。可使用[指標](/zh-Hant/metrics)的基數檢視找出產生大量時間序列的標籤。

## 資料擷取用量

**資料擷取用量** 設定[各來源的資料擷取記錄](/zh-Hant/streams#資料擷取用量與預算)要保留多久，以及最多對多少個服務分別統計。

| 欄位 | 預設值 | 意義 |
|---|---|---|
| **記錄保留天數** | 90 天 | 系統每天清理一次超過保留天數的每小時記錄。範圍為 35 到 3650 天：至少保留 35 天，才能確保每月預算都能讀取完整的記錄。 |
| **每個組織的服務數** | 1000 | 每個節點上，單一組織每小時可分別統計的服務數量上限。範圍為 1 到 100000。超出的服務合併計入 **其他服務**，避免傳送端利用服務名稱讓記錄過度膨脹。 |

## 稽核記錄保留

**稽核記錄保留** 設定所有組織和平台的稽核記錄要保留多少天：預設為 90 天，範圍為 0 到 3650 天，`0` 表示永久保留。系統每天清理一次較舊的記錄，刪除後無法復原。每次修改都會以 `audit_retention.update` 寫入平台稽核記錄。

輸入較短的保留期限時，頁面會統計此次修改將刪除多少筆記錄。儲存時需要確認；若達到 1,000 筆或無法統計，還需要再輸入一次保留天數。
