**節點 / 遠端叢集** 適用於整個執行個體，因此位於 `_sys` 組織的 **設定** 中。遠端叢集需要 `sys.clusters.read` 和 `sys.clusters.manage`，服務資料來源和叢集聯邦需要 `sys.settings.topology.read` 和 `sys.settings.topology.manage`。**AI 與 ML** 下的 **執行中的查詢管理** 屬於工作區：檢視查詢需要 `org.running_queries.read`，取消其他使用者的查詢需要 `org.running_queries.cancel`。

## 節點與遠端叢集

開啟 **設定 → 節點 / 遠端叢集**。

### 服務資料來源

**從儲存空間重新計算（多節點）** 決定如何從追蹤資料建構[服務地圖](/zh-Hant/apm/service-map)：

| 設定 | 方式 | 取捨 |
|---|---|---|
| 開啟 | 由一個節點定期從已儲存的追蹤資料重建服務地圖。 | 跨節點結果正確，但約有 1 到 2 分鐘的延遲。 |
| 關閉 | 每個 intake 程序在記憶體中配對 Span 並寫入結果。 | 延遲低，但同一次呼叫的 Span 若分散在不同 intake 節點，可能會漏計。 |

部署中若有多個 intake 節點，請開啟此設定。

### 跨叢集聯邦

聯邦會在多個叢集之間同步資源變更。填寫在聯邦內唯一且重新啟動後維持不變的 **叢集 ID**，例如 `cluster-eu-west`，再按一下 **儲存變更**。將叢集 ID 留空並確認，即可關閉聯邦。停止聯邦不影響本機資料。

**進階參數** 可用來調整同步行為：**outbox 推送間隔（秒）**、**每次推送的批次大小**、**去除重複事件的時間範圍（秒）** 和 **gossip 間隔（秒）**。

### 遠端叢集

遠端叢集是[聯邦查詢](/zh-Hant/deployment/role-based#聯邦查詢)的目標。

1. 按一下 **新增叢集**。
2. 填寫 **名稱** 和遠端叢集的 **Advertise 位址**，例如 `https://cluster.example.com`。
3. 填寫 **Token secret 參照**：請使用 `env:VAR` 或 `cipher_keys:<id>` 等參照，不要填入 Token 本身。清單會將參照顯示為 `***`。
4. 除非遠端叢集使用本機叢集無法驗證的私有憑證，否則請保持 **驗證 TLS 憑證** 開啟。
5. 按一下 **新增叢集**。

每一列還提供兩項操作：

| 操作 | 顯示內容 |
|---|---|
| **節點** | 顯示遠端叢集的節點、角色和版本；無法連線時顯示錯誤。 |
| **Org 對應** | 顯示遠端組織與本機組織的對應關係。系統會拒收未建立對應的組織所送出的設定。每個對應可指定專用的 **per-org token 參照**；若未指定，則使用叢集層級的 Token。 |

移除叢集後，聯邦查詢不再存取該叢集。

## 執行中的查詢管理

**設定 → 執行中的查詢管理** 會列出工作區中執行中的查詢，包括查詢 ID、使用者、開始時間和查詢陳述式。清單每 3 秒重新整理一次。按一下 **取消** 即可停止查詢。請在[資料流 → 搜尋任務](/zh-Hant/streams#搜尋工作)中管理在背景執行的搜尋任務。

| 操作 | 端點 | 權限 |
|---|---|---|
| 列出執行中的查詢 | `GET /api/v1/query/running` | `sys.clusters.read` |
| 取消查詢 | `POST /api/v1/query/{id}/cancel` | `sys.clusters.manage` |
