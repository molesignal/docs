**Mole Agent** 是內建的維運代理程式及其產品工作區。

Mole Agent 可以透過在伺服器註冊的工具查詢日誌、指標、追蹤、RUM、效能剖析、警示、值班資料和報告。Mole Agent 使用目前登入使用者的組織與權限，並忽略模型提供的組織識別碼。

## 設定模型服務

先設定模型服務，Mole Agent 才能在對話中回答。具備 `agent.models.manage` 權限的管理員可依下列步驟新增：

1. 開啟 **Mole Agent → 設定 → 模型與推論**，選取 **新增模型服務**。
2. 選取 **服務類型**：OpenAI、Anthropic，或相容於 OpenAI 的端點。
3. 填寫 **顯示名稱**、**預設模型** 與 **API Key**。API Key 只能寫入，不能讀取；頁面和 API 都不會傳回金鑰。
4. 若使用相容於 OpenAI 的端點，請設定 **Base URL**。留空則使用 OpenAI 或 Anthropic 的官方端點。
5. 若服務供應商的預設值不適用，請調整 **無回應逾時** 與 **最大輸出 Token 數**。若要在用量中查看成本，請選取 **幣別** 並填寫單價，再儲存設定。

在 **無回應逾時** 所設定的時間內，若未收到模型服務的任何資料，系統就會判定這次呼叫失敗。預設為 120000 毫秒，可設為 1000 至 600000 毫秒。非串流呼叫會等到整段回答產生完畢，請依產生最長回答所需的時間設定。若連線失敗、達到速率限制（429）或服務暫時無法使用（5xx、529），系統會自動重試兩次；若伺服器傳回 `Retry-After`，則依指定時間等候。系統只會在收到回答前重試。若未設定 Anthropic 服務的 **最大輸出 Token 數**，則使用 4096。

單價以每百萬 token 計算，使用該模型服務選取的 **幣別**，並套用至該服務的所有模型：**輸入單價，未命中快取**、**輸入單價，命中快取**（適用於服務供應商從快取提供的輸入部分）與 **輸出單價**。只有服務供應商對快取命中另行計價時，才需填寫命中快取的單價；否則，所有輸入都按未命中的單價計算。未填寫單價時，系統不會計算成本，但不影響使用或預算。

在模型服務下方的 **幣別** 區域管理可選的幣別。具備 `agent.usage.manage` 權限的管理員可依 ISO 4217 代碼新增幣別；若標準名稱或符號不適用，可另行填寫。無法刪除模型服務正在使用的幣別；刪除幣別後，以該幣別記錄的成本仍會以原幣別顯示。若沒有 `agent.usage.read` 權限，系統不會顯示這個區域，也無法修改 **幣別**：新加入的模型服務使用 USD，現有的模型服務保留原幣別。

模型呼叫會經過 Model Gateway。編輯時，將現有的金鑰欄位留空即可保留已儲存的金鑰；輸入新值則會輪替金鑰，這項操作需要 `agent.models.rotate` 權限。只有這項權限而沒有 `agent.models.manage` 時，只能修改金鑰。環境變數 `MS_AGENT_OPENAI_API_KEY`、`MS_AGENT_ANTHROPIC_API_KEY` 與 `MS_AGENT_COMPATIBLE_API_KEY` 是供開發使用的備用設定，請參閱[設定](/zh-Hant/configuration#環境變數)。

## 對話

開啟 **Mole Agent → 對話**，選取可用的模型，設定時間範圍並描述觀察到的現象。可將服務、警示、環境或資料流固定為調查的背景資訊。

若未啟用任何 AI 模型，對話會在輸入欄上方顯示提示。具備 `agent.models.manage` 權限的管理員可透過提示中的連結前往 **模型與推論**。

回應可包含：

- 自然語言結論；
- 工具呼叫與證據摘要；
- 原始日誌、指標、追蹤或事件的連結；
- Token 與模型成本的中繼資料（僅在模型服務填寫單價時顯示成本）；
- 用於重現結果的提示詞範本版本與內容雜湊值。

回答底部左側顯示 **複製**、**分支**、**置頂** 與回答時間。右側先顯示代表信心水準的儀表；信心度越高，弧線越長，顏色越偏綠，將滑鼠游標移到儀表上即可查看等級。儀表後方是 **有幫助** 與 **沒有幫助**。**分支** 會沿用截至這則回答的訊息來開啟新對話，並在清單中將新對話列在原對話下方。**置頂** 會將這則回答固定在對話頂端，只對執行置頂的使用者生效。

可在回答下方選取 **有幫助** 或 **沒有幫助**。選取 **沒有幫助** 時，可勾選原因（結論或根本原因有誤、未找出問題所在、建議不適用、答非所問、其他）並補充說明。只有提問者能評價該問題的回答；再次點選已選取的評價即可撤回。系統會隨評價記錄產生回答時使用的模型與提示詞版本。

當組織當日的 token 用量達到預算提醒門檻時，對話會在輸入欄上方顯示提示。預算用盡後的處理方式，請參閱[用量與預算](#用量與預算)。

大型原始工具結果會溢寫至物件儲存。刪除對話前，系統會盡可能封存對話記錄。

### 撰寫訊息

輸入欄會以傳送後的樣式即時顯示內容：`- ` 開始項目清單，`1. ` 開始編號清單，`# ` 表示標題，`> ` 表示引用，`[ ] ` 表示待辦事項，```` ``` ```` 表示程式碼區塊，`**粗体**` 與 `` `代码` `` 會在輸入時套用格式。按 **Enter** 傳送。在清單或程式碼區塊中，按 **Enter** 繼續輸入下一個項目或下一行；在空白清單項目上按 **Enter** 可結束清單。在任何位置按 **⌘ Enter** 或 **Ctrl Enter** 都可傳送。按 **Shift Enter** 換行。貼上 Markdown 時會保留格式；若以純文字貼上（**⌘ Shift V** 或 **Ctrl Shift V**），則保持原樣。訊息會以 Markdown 格式傳送。

### 執行模式

輸入欄下方的模式決定 Mole Agent 在這段對話中可執行的操作。開啟選單後，按數字 1 至 5 選取模式。

| 模式 | 執行的操作 |
|---|---|
| **建議模式**（建議使用） | 查詢資料並提出變更建議，不套用變更。 |
| **調查模式** | 視需要自動執行唯讀查詢，不進行任何變更。 |
| **執行模式（須核准）** | 自動執行查詢；依工具的執行方式，先請使用者確認變更，或將變更送交核准。 |
| **自動模式** | 自動執行查詢；對於只需使用者確認的變更，若可復原就直接執行，刪除等破壞性變更仍須先確認。 |
| **略過權限確認** | 不再逐項確認只需使用者確認的變更，包括破壞性變更。 |

無論使用哪種模式，只要組織的工具原則要求核准，系統仍會將變更送交核准人員；停用的工具仍無法使用。對話使用的 Agent Profile 必須在 **核准原則** 中啟用 **允許 Bypass permissions**，才能選取 **略過權限確認**。啟用前會顯示確認對話方塊。若問題在佇列等候期間，Agent Profile 不再允許略過確認，這一輪就會改為逐項確認，並在回答中說明。

### 對話名稱

系統會在回答第一個問題時為新對話命名：以提問所用的語言，簡短概括對話主題，做法與 ChatGPT、Claude 的對話命名方式相同。若一開始只是打招呼，還沒有明確主題，系統會先使用第一個問題的文字，等出現有明確主題的問題再命名。系統只會自動命名一次。點選清單中對話旁的鉛筆圖示即可重新命名：按 **Enter** 儲存，按 **Esc** 取消。手動重新命名後，系統不會再自動命名。記憶的來源會顯示對話目前的名稱。命名與其他模型呼叫一樣，會計入用量。

### 個人工作階段與團隊工作階段

對話預設為個人工作階段。若在傳送第一則訊息前選定團隊，對話就會成為該團隊的工作階段。可在輸入欄下方的 **團隊** 中選取，也可輸入 `/team <团队>`。清單會列出目前使用者所屬的團隊，具備 `agent.manage` 權限的管理員可選取任何團隊。第一則訊息送出後，便無法變更對話歸屬。

| | 個人工作階段 | 團隊工作階段 |
|---|---|---|
| 誰可以閱讀和繼續對話 | 僅對話發起者 | 團隊成員與具備 `agent.manage` 權限的管理員 |
| 可使用的技能與 MCP 伺服器 | 組織、發起者個人及已加入對話的團隊所提供的資源 | 組織及該團隊提供的資源，不使用任何成員的個人資源 |

工具一律以訊息傳送者的身分執行，並使用該傳送者的權限和憑證。在團隊工作階段中，其他成員提出的問題會顯示提問者的姓名。在個人工作階段中呼叫所屬團隊的技能或 MCP prompt 時，該團隊的技能與 MCP 伺服器會加入對話，並在後續對話中持續可用。對話清單會標示團隊工作階段所屬的團隊。有團隊工作階段後，可使用 **全部**、**個人**、**團隊** 篩選清單。

### 斜線指令

在輸入欄開頭輸入 `/` 即可開啟指令選單，繼續輸入可依名稱或說明篩選。按 ↑ 或 ↓ 選取，按 **Enter** 執行，按 **Tab** 只自動完成而不執行，按 **Esc** 關閉選單。自動完成含有參數的指令後，選單會列出可選的參數。對話頁面與隨處可按 ⌘J 開啟的 Mole Agent 面板都支援指令。

| 指令 | 用途 |
|---|---|
| `/help` | 列出所有指令 |
| `/new` | 開始新對話 |
| `/team <团队>` | 選取新對話所屬的團隊；`personal` 表示個人工作階段。在已開始的對話中輸入時，會為該團隊開啟新對話 |
| `/mode auto\|quick\|deep\|query` | 切換分析模式：**自動模式**、**快速問答**、**深入調查**、**僅產生查詢** |
| `/time 15m\|30m\|1h\|6h\|24h\|7d` | 設定時間範圍 |
| `/policy advice\|readonly\|approval\|auto\|bypass` | 設定執行模式：**建議模式**、**調查模式**、**執行模式（須核准）**、**自動模式**、**略過權限確認**。`bypass` 只在 Agent Profile 允許時可用，啟用前會顯示確認對話方塊 |
| `/model <模型服务>` | 依服務名稱或模型名稱選取模型服務；`auto` 表示自動選取 |
| `/profile <Agent 配置>` | 選取 Agent 設定；`auto` 表示使用預設設定 |
| `/prompt <Prompt>` | 選取 Prompt；`auto` 表示自動選取 |
| `/query <问题>` | 只產生查詢，不執行 |
| `/dashboard <要展示的内容>` | 建立儀表板 |
| `/rca <事件> [补充说明]` | 調查事件的根本原因；選單會列出進行中的事件。需要 `alerts.incidents.read` 權限 |
| `/export` | 將目前的對話下載為 Markdown 檔案 |

`/query`、`/dashboard` 與 `/rca` 會各自以一則訊息傳送，並在對話中顯示指令標籤與參數。重新產生回答時，系統會再次執行相同的指令。`/query` 的模式只對該則訊息生效。`/rca` 的時間範圍從事件開始前 30 分鐘到事件結束為止；若事件尚未結束，則到目前為止。其餘指令只會變更輸入欄中的設定，不會傳送訊息。

若指令不存在、缺少參數、參數不正確或權限不足，系統不會送出指令，並在輸入欄上方說明原因。若要傳送以 `/` 開頭的純文字，請在開頭輸入 `\/`，系統會在傳送時移除反斜線。像 `/var/log/app.log` 這類含有第二個斜線的路徑會以純文字傳送。

技能與 MCP prompt 也可當作指令使用，分別列在選單的 **技能** 與 **MCP** 群組下：

- `/名称 [要求]` 會執行對話中可用的技能。若兩個團隊的技能名稱相同，請使用 `/名称@团队`；在個人工作階段中，這種寫法也會將該團隊加入對話。
- `/<服务器>:<prompt> [参数]` 會使用傳送者的憑證，從 MCP 伺服器取得 prompt，並作為這一輪的問題送出。依序填寫參數，最後一個參數會接收剩餘的所有文字；也可用 `名称=值` 依名稱填寫，若值包含空格，請加上引號。

需要執行指令碼的技能需要 Mole Runner。若伺服器要求成員提供憑證，傳送者必須先填寫自己的憑證，才能使用該伺服器的 prompt。選單會在指令上標示這些要求。

## 知識與記憶

開啟 **Mole Agent → 知識**。**知識** 儲存對話會讀取的 Markdown 檔案，分為組織與各團隊的檔案。以 `MOLE.md` 作為進入點，使用 `@路径` 指向其他檔案。也可執行 `/init`，讓 Mole Agent 先檢視現有設定、提出幾個問題，並在取得確認後逐一撰寫檔案。具備 `agent.manage` 權限的使用者可修改組織知識，團隊成員可修改團隊知識。

- 選取 **新增** 可建立檔案，或為第一個檔案建立資料夾；若輸入 `runbooks/api.md` 之類的路徑，系統會同時建立資料夾與檔案。
- 選取 **上傳** 可選擇檔案或整個資料夾。
- 檔案會以 **預覽** 模式開啟。使用 **編輯** 時，與輸入欄一樣，會在輸入時即時顯示檔案的呈現效果；使用 **原始碼** 則可直接編輯 Markdown。若檔案包含編輯器無法保留的語法（例如 HTML 註解），請改用 **原始碼** 編輯。
- 選取 **AI** 可開啟對話，讓 Mole Agent 修改該檔案。

**記憶** 儲存對話中記下的偏好、做法、事實與經驗教訓。個人對話的記憶歸發起者所有，團隊對話的記憶則歸團隊所有。每筆記憶都以來源對話的名稱連結至該對話。系統會透過對話寫入記憶；記憶內容可像知識檔案一樣編輯或刪除。具備 `agent.memories.settings` 權限的使用者啟用 **對話結束後擷取記憶** 後，模型會在對話停止半小時後挑選值得保留的內容，並消耗組織的模型預算。

## 調查

將複雜問題轉為可追蹤的調查。調查會記錄：

- 狀態與目前步驟；
- 證據對結論的影響；
- 相互競爭的假設與信心度；
- 相關的對話、核准與執行作業；
- 最終摘要與復原驗證。

從事件發起對話時，系統會為該事件建立一筆調查記錄。在 APM 的服務、端點、錯誤或洞察中點選**調查**來發起對話時，系統會為該服務建立一筆調查記錄。在 RUM 頁面上點選**使用 Mole Agent 調查**來發起對話時，系統會為該應用程式建立一筆調查記錄。**Mole Agent → 調查**會列出這些調查。將 APM 服務附加至對話後，系統會提供模型該服務在對話時間範圍內的資料與洞察，以及呼叫該服務或由該服務呼叫的對象，請參閱[讓 Mole Agent 調查](/zh-Hant/apm/insights#讓-mole-agent-調查)。將 RUM 應用程式附加至對話後，系統會提供模型該應用程式的工作階段、Core Web Vitals、主要問題和進行中的警示，請參閱[使用 Mole Agent 調查](/zh-Hant/rum#使用-mole-agent-調查)。

將事件附加至對話時，除了事件本身，系統也會提供模型以下資訊：觸發事件的警示規則所記載的排查線索（若規則包含排查查詢，模型會先執行這些查詢）、受影響服務在服務目錄中的說明與資料入口、近 90 天內最相似的幾起事件（結束方式與根本原因的第一句），以及事件開始前後的部署、設定與功能旗標變更。從事件發起的對話和由事件觸發的自動化也會帶入這些資訊。

讀取資料時，Mole Agent 會優先使用彙整後的結果：`analyze_log_patterns` 將日誌歸納為模式，並與對照時段比較；`analyze_metric_trend` 說明指標何時開始變化、變化幅度，以及哪些序列與 Label 造成變化。需要範例時才讀取原始日誌。同一步驟需要讀取多種資料（例如指標、日誌與追蹤）時，會同時讀取，最多 4 項；變更操作仍會逐一執行。

若組織未使用自動化撰寫根本原因分析，系統會在背景為進行中的事件自動產生分析。這項作業只呼叫模型一次，不會呼叫工具。作業以系統身分執行，所有能查看事件的使用者都能查看分析結果。因此，作業不會讀取資料流中的資料，只參考事件本身、排查線索、服務目錄、相似事件與事件前後的變更。若要讓 Mole Agent 使用工具查證，請使用[自動化](/zh-Hant/automations)中的 **事件自動分析** 範本。範本會以儲存自動化的使用者身分執行。

## 自動化

自動化可讓 Mole Agent 在沒有使用者參與對話時執行任務：依排程執行、在有新事件時執行、由 CI/CD 呼叫，或手動執行。每次執行都會保留為一段對話，並可將結果傳送到通知管道。若由事件觸發，也可將結果寫入該事件的 RCA。請參閱[自動化](/zh-Hant/automations)。

## 品質

系統會依規則為每則回答評分，並使用組織設定的評估模型抽樣評分。分數偏低或獲得「沒有幫助」評價的回答會在**品質**分頁中等待審查。將對話或 RCA 使用的組織 Prompt 設為預設前，系統會先與目前的預設 Prompt 比較一次。請參閱[品質](/zh-Hant/quality)。

## IM

Mole Agent 也可透過連接器，在飛書、Slack、釘釘、企業微信、Google Chat、Microsoft Teams 和 Telegram 中回答問題。在群組中 @Mole Agent 或傳送私人訊息，即可開始對話。這些平台上的工作階段也可在此查看。請參閱[在 IM 中使用 Mole Agent](/zh-Hant/im)。

## 核准與執行

具備寫入能力的工具一律受伺服器執行原則約束。

| 風險 | 預設執行模式 |
|---|---|
| L0 | 自動執行。 |
| L1 | 使用者確認。 |
| L2 | 單人核准。 |
| L3 | 雙人核准。 |
| L4 | 預設停用；破壞性遠端工具至少採用此風險等級。 |

核准請求會保留待執行的操作，並在原則規定的時間後到期。執行前，伺服器會重新驗證權限、資源狀態、參數、風險與冪等性。執行記錄會保留結果與復原驗證。

## 日誌巡檢

Mole Agent 也可讀取單一日誌資料流並撰寫報告。可在 **日誌** 中立即執行一次巡檢，也可在背景定期執行。排程巡檢會儲存每次的報告，並在報告判定有異常時發出通知。請參閱[日誌巡檢](/zh-Hant/logs/inspections)。

## 技能

技能是包含 `SKILL.md` 的目錄，內含某類工作的做法說明（採用開放的 Agent Skills 格式），以及說明中用到的檔案。Mole Agent 能看到對話可用的技能名稱與說明。請求符合某項技能時，Mole Agent 會讀取該技能的說明；說明指向其他檔案時，再讀取這些檔案。每項技能也是一個斜線指令。

| 來源 | 在哪裡管理 | 誰可以使用 |
|---|---|---|
| **內建** | 隨 MoleSignal 提供 | 所有組織，唯讀 |
| **執行個體目錄** | 伺服器上 `[agent].skill_paths` 列出的目錄 | 所有組織，唯讀 |
| **上傳** | **Mole Agent → 設定 → 技能 → 上傳技能** | 組織、特定團隊或個人 |
| **儲存庫** | **Mole Agent → 設定 → 技能 → 新增儲存庫** | 組織、特定團隊或個人 |

內建技能包括撰寫知識的 `/init`、回顧 Mole Agent 使用情形並提供改進建議的 `/insight`（參見[自動化](/zh-Hant/automations#回顧-mole-agent-的使用情形)）、從 RUM 應用程式的概覽查閱問題、工作階段和追蹤，以排查真實使用者遇到的問題的 `/rum-triage`，以及檢查資料就緒程度並產生報告的 `/data-readiness`（檢查各資料流是否記錄服務、環境與 trace ID，同一服務在日誌、指標與追蹤中是否使用相同名稱，以及指標名稱是否包含單位，並為每項檢查附上修正建議）。具備 `agent.manage` 權限的管理員可以為所屬組織停用內建技能及執行個體目錄中的技能。技能同名時，對話會依下列順序選用第一個符合的技能：個人、團隊、組織、執行個體目錄、內建。MoleSignal 會在啟動時讀取執行個體目錄，並在目錄中的檔案有變更時重新讀取，參見[設定](/zh-Hant/configuration)。

### 編寫技能

`SKILL.md` 以 YAML frontmatter 開頭：

| 欄位 | 必填 | 說明 |
|---|---|---|
| `name` | 是 | 指令名稱：以字母開頭，只能包含字母、數字、`-` 與 `_`，最多 64 個字元。不得與內建指令同名。 |
| `description` | 是 | 說明技能的用途與使用時機，最多 1024 個字元。Mole Agent 依此選用技能。 |
| `allowed-tools` | 否 | 技能使用的工具。以指令執行技能時，Mole Agent 會直接將工具提供給模型，但仍須遵守組織的工具原則與核准規則。 |
| `argument-hint` | 否 | 參數的寫法，會顯示在指令選單中。 |
| `version` | 否 | 顯示在設定中，並在每次呼叫時記錄。也可以寫成 `metadata.version`。 |
| `tags`、`examples` | 否 | 標籤，以及顯示在技能詳細資料中的範例問題。 |
| `requires` | 否 | 填寫 `runner` 表示技能要執行指令碼，因此需要 Mole Runner。 |

在說明本文中，`$ARGUMENTS` 代表指令後的所有文字，`$1` 到 `$9` 分別代表其中的各個詞。本文未使用這些預留位置時，Mole Agent 會將指令後的文字附加到說明末尾。

技能套件是大小上限為 20 MiB 的 `.zip`、`.skill` 或 `.tar.gz` 壓縮檔，只能包含一個技能目錄。解壓縮後最多可有 300 個檔案，總大小上限為 20 MiB，單一檔案大小上限為 8 MiB。系統會拒絕連結及指向目錄外的路徑。上傳的技能與同一歸屬下的現有技能同名時，系統會先詢問是否取代。選取技能詳細資料中的 **在對話中試試**，即可開啟 Mole Agent 並預先填入指令。

### 技能儲存庫

MoleSignal 會依分支或標籤將技能儲存庫下載為單一壓縮檔。整個儲存庫中（或所填 **目錄** 下），每個包含 `SKILL.md` 的目錄都是一項技能。每個儲存庫最多可有 50 項技能，壓縮檔大小上限為 64 MiB。MoleSignal 可從網址辨識 GitHub、GitLab、Gitea、Forgejo 和 Bitbucket。使用其他託管服務時，請填寫含有 `{ref}` 的壓縮檔網址。私人儲存庫需要存取權杖，權杖只能寫入，無法讀取。

儲存儲存庫時，MoleSignal 會同步一次。選取 **同步** 可再次同步，啟用 **每天自動同步** 可讓儲存庫保持最新。每次同步都會新增、更新及移除儲存庫中的技能，並列出無法匯入的目錄及原因。刪除儲存庫時，MoleSignal 也會移除其中的技能。

## 組織、團隊與個人資源

技能、技能儲存庫與 MCP 伺服器隸屬於組織、特定團隊或個人。新增時請在 **歸屬** 中選取。之後，編輯者可將資源移至有權管理的其他歸屬。

| 歸屬 | 誰可以修改 | 在哪裡使用 |
|---|---|---|
| 組織 | 具備 `agent.manage` 權限的管理員 | 所有對話 |
| 團隊 | 團隊成員與具備 `agent.manage` 權限的管理員 | 此團隊的工作階段，以及加入此團隊的個人工作階段 |
| 個人 | 資源擁有者；具備 `agent.manage` 權限的管理員可檢視、停用或刪除 | 資源擁有者的個人工作階段 |

若團隊仍有技能、技能儲存庫或 MCP 伺服器，就無法刪除該團隊。**身分與存取 → 團隊** 會列出這些資源，請先移交或刪除。

團隊與個人新增的技能儲存庫和 MCP 伺服器只能存取公用網路，以及具備 `agent.network_policy.manage` 權限的管理員在 **Mole Agent → 設定 → 網路原則 → 團隊與個人可連線的內部網路** 中列出的內部網路主機與網段，且一律驗證 TLS 憑證。組織的技能儲存庫與 MCP 伺服器依各自的設定連線。

## 代理程式設定

開啟 **Mole Agent → 設定**。各區段在 Mole Agent 分頁下方排成一列：

| 區段 | 用途 |
|---|---|
| **代理程式設定檔** | 代理程式的設定，包括允許使用的工具、單輪回答的工具呼叫次數、調查時間、溫度、資料範圍與網路原則。 |
| **模型與推論** | 模型服務供應商、只能寫入的 API 金鑰、未回應逾時時間與單價。 |
| **用量** | 今日用量、每日 token 預算，以及最近 30 天依來源區分的用量。 |
| **Prompt 管理** | 內建提示詞，以及組織層級與個人層級的覆寫版本。 |
| **技能** | 內建、執行個體目錄、上傳與儲存庫來源的技能，以及技能儲存庫。 |
| **工具與能力** | 工具登錄表：每項工具的執行方式、限制及特定環境中的最低風險等級，以及組織、團隊與個人的 MCP 伺服器及其工具與 prompt。 |
| **Inbound MCP** | 供外部 AI 用戶端使用的 MCP 端點。 |
| **資料存取範圍** | 預設代理程式設定檔可讀取的環境、服務與資料流。 |
| **網路原則** | 代理程式設定檔能否使用需要連網的工具，以及團隊與個人的連線可存取的內部網路位址。 |
| **核准規則** | 各風險等級的核准規則。 |

MoleSignal 會加密儲存憑證，API 一律不會傳回憑證原文。

### 工具與能力

此區段依產品領域分組列出工具。開啟時，各群組預設為收合狀態。可展開個別群組，也可透過搜尋展開包含相符項目的群組。**全部**、**唯讀**、**自動執行**、**需核准** 和 **已停用** 篩選條件各自顯示符合條件的工具數量。

工具的標題和說明會依介面語言顯示。工具詳細資料也會顯示模型讀取的定義。無論介面語言為何，該定義一律以英文顯示。

### MCP 伺服器

開啟 **工具與能力 → MCP 伺服器**，新增伺服器、測試連線並匯入工具。每台伺服器都會標示歸屬。成員也可在此管理個人與團隊的伺服器。

| 設定 | 說明 |
|---|---|
| 連線方式 | **Streamable HTTP**；**SSE（舊版）**，適用於採用舊版 HTTP + SSE 傳輸方式的伺服器；**stdio**，僅供組織的伺服器使用：MoleSignal 會在自己的伺服器上啟動指令，且只會啟動執行個體在 `[agent].mcp_stdio_commands` 中列出的指令。指令不經由 shell 執行，只會取得 `PATH`、`HOME`、`LANG`、`TMPDIR` 及該伺服器設定的 **環境變數**。指令在系統暫存目錄中執行，並在每次呼叫結束後結束執行。請將 stdio 伺服器的憑證放在 **環境變數** 中：驗證方式、請求標頭和成員憑證只適用於透過 HTTP 連線的伺服器。組織的網路原則無法限制指令可存取的位址。 |
| 驗證方式 | 不驗證、全體共用的權杖或金鑰，或 **成員憑證（每人填寫自己的憑證）**：每位成員為伺服器指定的請求標頭儲存各自的值，只有該成員的呼叫會使用該值。 |
| **請求標頭** | 每個請求都會附帶這些標頭。若標頭名稱包含 key、token、secret、password、credential、auth 或 cookie，MoleSignal 會加密儲存其值，且只顯示最後四個字元。編輯時若將敏感值留空，則會保留原值。 |

**測試連線** 會列出伺服器的工具。**同步選取的工具** 會匯入選取的工具：新工具在啟用前會維持停用，最低風險等級則依伺服器的標註推斷。**工具與 prompt** 中的每項工具都有開關，選取 **啟用所有唯讀工具** 可一次啟用所有唯讀工具。工具原則與核准規則照常生效。伺服器提供的 prompt 會成為指令，格式為 `/<服务器>:<prompt>`。

Mole Agent 約每小時重新檢查一次已同步的伺服器。若工具的輸入 schema 有變更、伺服器不再列出該工具，或伺服器將該工具標示為更高風險，該工具就會暫時無法使用，直到有人檢查並重新同步。需要成員憑證的伺服器不納入這項檢查。

**匯入設定** 會讀取 Claude Desktop、Claude Code、Cursor 或 VS Code 的 MCP 設定，並新增其中的伺服器。匯入時不會帶入參照變數的值（例如 `${input:token}`），而是列出這些變數供填寫。含有 `command` 的伺服器是 stdio 伺服器，只能匯入至組織，且指令必須在執行個體允許的範圍內。

對於需要成員憑證的伺服器，選取 **填寫我的憑證** 可儲存個別成員的值。對話呼叫該伺服器的工具時，若尚未儲存憑證，或伺服器拒絕已儲存的憑證，回答會暫停在 **授權以繼續** 卡片。卡片會指出哪項工具需要憑證，並顯示伺服器提供的憑證取得說明。**儲存並繼續** 與 **填寫我的憑證** 同樣會儲存憑證，之後會重新執行該工具。選取 **跳過** 後，這一輪回答剩餘的部分不再使用該伺服器。憑證屬於提問者，因此只有提問者能填寫卡片。團隊工作階段中的其他成員會看到正在等待哪位成員填寫。卡片最多等待一小時。若無法向任何人要求憑證，工具會傳回缺少憑證的結果，Mole Agent 會請成員先填寫憑證。

### Prompt 管理

內建提示詞為唯讀，名稱依介面語言顯示。在內建提示詞上選取 **建立覆寫版本**，即可為組織或特定使用者取代該提示詞。將用於對話或 RCA 的組織提示詞設為預設值之前，須先通過組織的檢查，參見[品質](/zh-Hant/quality#將-prompt-設為預設前先檢查)。

### 代理程式設定檔的執行限制

下列三項限制適用於使用該設定檔的每一輪對話回答。若沒有生效的設定檔，則使用預設值：

| 設定 | 預設值 | 說明 |
|---|---|---|
| **工具呼叫次數上限** | `32` | 每輪回答可呼叫工具的次數上限，範圍為 1 到 256。 |
| **最長調查時間（分鐘）** | `30` | 每輪回答的總時間上限，範圍為 1 到 120 分鐘。 |
| **溫度** | `0.2` | 取樣溫度，範圍為 0 到 2。溫度越低，回答越穩定，也越容易重現。 |

達到工具呼叫次數或時間上限後，Mole Agent 不再呼叫工具，並以已取得的結果回答。

### 用量與預算

開啟 **Mole Agent → 設定 → 用量**，查看組織今日的 token 用量、每日預算及最近 30 天的用量。用量依 UTC 日曆日統計，token 數為輸入與輸出的總和，並計入下列來源：

| 來源 | 說明 |
|---|---|
| **對話** | Mole Agent 對話，包括建立儀表板。 |
| **根本原因分析** | 背景自動為進行中的事件產生的根本原因分析，以及在事件中手動產生的根本原因分析。 |
| **日誌巡檢** | 立即巡檢與排程巡檢。 |
| **LLM 函式** | [警示管線](/zh-Hant/pipelines/alert-events#ai-摘要)的 **AI 摘要** 步驟，以及 LLM 函式的執行。 |
| **自動化** | 自動化的執行，包括由事件觸發的執行。 |
| **品質評分** | 審查，以及 Prompt 檢查中重新撰寫的回答。 |

若已為模型服務設定單價，頁面也會以各模型服務使用的幣別顯示成本。不同幣別的成本會分開顯示，不會加總。若呼叫使用未設定單價的模型服務，該呼叫就不計入成本，金額前會標示 **≥**，表示實際成本至少為該金額。

每日預算預設採用執行個體設定 `[agent].daily_token_budget`（`0` 表示不限），參見[設定](/zh-Hant/configuration)。具備 `agent.usage.manage` 權限的管理員可以為所屬組織設定 **自訂** 上限或選取 **不限**，並設定預算用完時對話與手動根本原因分析的處理方式：

| 處理方式 | 行為 |
|---|---|
| **不再呼叫模型**（預設） | 不送出問題，並將問題保留在輸入框中。對話上方會說明今日預算已用完，並顯示重設時間。手動產生根本原因分析時，也會傳回相同的提示。 |
| **照常回答，僅顯示提示** | 照常回答，並在輸入框上方提示已超出預算。 |

預算用完後，自動根本原因分析、日誌巡檢、AI 摘要步驟和 LLM 函式不再呼叫模型。巡檢會記為失敗，原因為預算已用完。自動根本原因分析會延至預算重設後執行。AI 摘要步驟和 LLM 函式則會視為失敗。用量達到提醒門檻（預設為 80%，`[agent].budget_warning_percent`）時，對話會在輸入框上方顯示提醒。預算判定結果會快取十多秒，且系統不會中斷正在進行的回答，因此實際用量可能略為超出上限。

每次模型呼叫也會寫入內部資料流 `_agent_model_traces`，可在 **日誌** 中查詢。常用欄位包括 `origin`（`chat`、`rca`、`inspection`、`llm_eval`、`automation`、`evaluation`、`replay_summary`）、`provider`、`model`、`prompt_tokens`、`cached_prompt_tokens`（服務供應商從快取提供的部分輸入）、`completion_tokens`、`total_tokens`、`latency_ms`、`cost`、`cost_currency`、`status`、`error`、`tool_calls`、`streaming`、`chat_id`、`user_id`、`profile_id` 與 `prompt_hash`。只有在模型服務已設定單價時才會寫入 `cost` 與 `cost_currency`。`user_id` 表示呼叫歸屬的身分，即對話的提問者或巡檢的執行身分。根本原因分析與 LLM 函式的呼叫不含此欄位。

## 資料處理

Mole Agent 會將對話傳送至已設定的模型服務供應商，其中包含工具呼叫的回傳結果。若未設定模型服務，Mole Agent 不會將任何資料傳出部署環境。下列控制項會限制代理程式可存取的範圍：

- **資料存取範圍** 限制預設設定檔可讀取的環境、服務與資料流，並一律禁止跨組織存取。
- **網路原則** 決定設定檔能否使用需要連網的工具。新建的設定檔預設停用網路。此開關不會啟用任意 HTTP、shell、瀏覽器與開放式 MCP 工具。
- **核准規則** 依風險等級要求核准寫入作業，並決定使用此設定檔的對話能否選取 **略過權限確認**。
- **技能與 MCP 伺服器** 只會新增做法說明和工具，不會放寬原則。技能允許使用的工具和所有 MCP 工具都遵循組織規定的執行方式與核准規則。

MoleSignal 使用加密根金鑰加密模型金鑰，參見[正式環境檢查清單](/zh-Hant/deployment/production-checklist)。

## 權限

- `agent.use` 用於開啟對話和執行記錄，以及評價回答與根因分析。
- `agent.investigations.read`、`agent.knowledge.read`、`agent.memories.read`、`agent.skills.read`、`agent.mcp_servers.read` 和 `agent.usage.read` 用於開啟調查、知識、記憶、技能、MCP 伺服器和用量。對應的 `.manage` 權限可修改使用者及其所屬團隊的這些資源。新增技能儲存庫需要 `agent.skill_repositories.manage`。
- `agent.manage` 也可管理組織資源：所有團隊對話，以及組織的知識、技能與 MCP 伺服器。
- `agent.models.manage`、`agent.prompts.manage`、`agent.tools.manage`、`agent.toolsets.manage`、`agent.profiles.manage`、`agent.usage.manage`、`agent.network_policy.manage`、`agent.inbound_mcp.manage` 和 `agent.im.manage` 分別用於設定服務供應商、提示詞、工具、工具集、Agent、每日預算、網路原則、Inbound MCP 和聊天機器人。**設定**中的各個區塊只需要各自對應的權限。缺少讀取權限時，區塊會說明需要哪項權限；缺少 `.manage` 權限時，設定項目為唯讀，但仍可搜尋和複製區塊中顯示的內容。
- `agent.quality.read` 用於開啟**品質**頁籤，查看分數、審核回答和評審；`agent.quality.manage` 可修改這些項目。
- `agent.automations.read` 用於查看自動化，`agent.automations.manage` 用於新增和修改自動化，`agent.automations.run` 用於執行自動化，`agent.automations.tokens` 用於管理自動化的 API 權杖。請參閱[自動化](/zh-Hant/automations#開始之前)。
- `agent.approve` 用於審核受控操作。
