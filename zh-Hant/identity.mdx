MoleSignal 使用權限鍵來授權操作，而非比對角色名稱。同一位使用者可以隸屬多個組織，並在各組織中擁有不同的權限。從選單開啟 **身分與存取**，即可管理目前工作區的存取權限。

| 群組 | 頁面 | 指南 |
|---|---|---|
| 成員 | **使用者**、**邀請**、**審核** | [成員](/zh-Hant/identity/members) |
| 組織結構 | **組織**、**團隊** | [組織與團隊](/zh-Hant/identity/teams) |
| 權限與限制 | **角色**、**權限政策**、**存取授權** | [角色、權限政策與存取授權](/zh-Hant/identity/roles) |
| 驗證與存取 | **API 權杖**、**服務帳號** | [API 權杖與服務帳號](/zh-Hant/identity/tokens) |
| | **SSO 服務提供者**、**電子郵件網域** | [單一登入](/zh-Hant/identity/sso) |

## 授權運作方式

對於已通過身分驗證的請求，MoleSignal 依序解析：

1. 主體：使用者、服務帳號或 API 權杖；
2. 目前的組織，或受保護的平台範圍；
3. 主體的角色指派與存取授權；
4. 資源關聯，以及已接受的跨組織授權；
5. 路由與目標資源所需的權限。

權限目錄、內建角色與權限政策都儲存在 PostgreSQL 中。`GET /api/v1/iam/capabilities` 會傳回實際生效的權限，供 Web 應用程式建立導覽介面。

<Warning>
  頁面可見性與角色名稱都不代表已獲授權。對於每個受保護的操作，伺服器端都會檢查該操作所需的權限與資源歸屬。
</Warning>

## 權限範圍

組織權限僅適用於單一工作區，例如：

- `org.preferences.read` 與 `org.preferences.manage`；
- `org.members.read` 與 `org.members.update`；
- `iam.roles.read`、`iam.roles.manage`、`iam.grants.read` 與 `iam.grants.manage`；
- 資料流、儀表板、警示、排班、已儲存的檢視、管線、函式、報告、稽核、日誌巡檢和 Mole Agent 的權限。

平台權限以 `sys.` 開頭，只在 `_sys` 組織中生效，用於管理執行個體中的組織、系統遙測、追蹤偵錯、平台管理員和平台設定。

## 內建角色

| 角色 | 擁有的權限 |
|---|---|
| **擁有者** | 權限目錄中的所有組織權限，不含任何平台權限。 |
| **管理員** | 所有組織權限：除產品各功能區外，還可管理設定、成員、角色、存取授權、權杖、稽核、狀態頁面、合成監控、服務等級、事件檢討及 Mole Agent。 |
| **編輯者** | 讀取及修改資料流、儀表板、警示與排班、已儲存的檢視、管線、函式、報告及應用程式效能與使用者體驗設定，並執行 Mole Agent 自動化作業與日誌巡檢。 |
| **檢視者** | 讀取資料、儀表板、警示與排班、已儲存的檢視、管線、函式和報告，並與 Mole Agent 對話。 |

[權限參考](/zh-Hant/identity/roles#權限參考)列出各項權限及擁有該權限的內建角色。無法編輯內建角色。升級後，MoleSignal 會在啟動時將新增的權限授予擁有者角色。

如果職責範圍較小，請建立[自訂角色](/zh-Hant/identity/roles#角色)。

## 平台授權

執行個體設定中的 `root` 帳號是超級管理員。此帳號不需要任何角色：在每個組織中都擁有該組織的權限，在 `_sys` 中也擁有平台權限，但不具備任何組織的擁有者身分。此帳號的 API 權杖僅擁有所屬組織的組織權限，無法取得平台權限。

其他帳號必須取得授權才能存取平台。在 `_sys` 中，**身分與存取** 有專屬的 **角色**、**權限政策** 和 **存取授權**，需具備 `sys.administrators.read` 和 `sys.administrators.manage` 權限。平台提供兩個內建角色：

| 角色 | 擁有的權限 |
|---|---|
| `platform_admin` | 所有平台權限。 |
| `platform_viewer` | 所有唯讀平台權限。 |

授權以帳號為對象，可依電子郵件地址查找帳號。帳號不必隸屬任何組織。授權範圍可涵蓋整個平台，也可限於單一組織：若限於單一組織，只有 `sys.organizations.read`、`.update`、`.disable` 和 `.delete` 會生效，且僅適用於該組織。授予的權限不得超出授權帳號在整個平台上擁有的權限；移除授權後，相關權限自該帳號的下一次請求起即失效。

## 跨工作區存取

存取授權可將一個組織中的主體與另一個組織中的資源建立關聯。伺服器端會同時檢查此關聯與資源權限。授權不會將主體的目前工作區切換至另一個組織。請參閱[跨組織共用資源](/zh-Hant/identity/roles#跨組織共用資源)。

儀表板和報告另支援[資源共用](/zh-Hant/resource-sharing)。公開共用只會提供受限的共用工作階段，不會授予成員身分。

## 平台管理

`_sys` 組織與組織 IAM 彼此隔離。租用戶工作階段和 `mspat-*` 權杖都無法列出系統遙測資料或平台管理員。請使用 `_sys` 中具備相應 `sys.*` 權限的工作階段。請參閱[管理概觀](/zh-Hant/administration)。
