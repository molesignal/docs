未變更個人起始頁時，登入後開啟的第一個頁面就是 **首頁**。首頁顯示系統目前的狀態：頂端是狀態列，下方是需要優先查看的服務和進行中的事件，再往下是各類資料的接收狀態、合成監控和帳號的值班資訊。所有成員都能開啟首頁，各區塊只顯示帳號有權查看的內容。

## 頁面頂端

時間範圍決定頁面上所有數字的統計區間：**近 1 小時**（預設）、**近 24 小時** 或 **近 7 天**。選取的範圍會寫入網址（`?window=24h`），分享連結時會開啟相同的檢視。頁面每分鐘重新讀取一次資料，按下重新整理按鈕可立即讀取。

若還有未完成的設定步驟，時間範圍前方的按鈕會顯示剩餘步驟數。點選按鈕即可開啟[快速開始](#快速開始)。

## 系統狀態

狀態列開頭顯示整體狀態：**運作正常**，或顯示異常項目數。異常包括進行中的事件、失敗、降級或不穩定的探測、超過警告或嚴重門檻的服務，以及延遲或異常的資料。若有嚴重項目（嚴重或錯誤層級的事件、失敗的探測、處於嚴重狀態的服務、異常的資料），整體狀態會以紅色顯示；若只有其他異常，則以黃色顯示。整體狀態旁會顯示統計區間、最近一次讀取時間，以及日誌、指標、追蹤和 Profiles 各自的接收狀態。

每個指標區塊都可開啟對應的詳細頁面：

| 指標區塊 | 內容 |
|---|---|
| **進行中的事件** | 依嚴重程度列出待確認和處理中的事件，並標示待確認的數量。開啟[警示事件](/zh-Hant/alerting/incidents)。 |
| **觸發中的規則** | 顯示已啟用且正在觸發的規則數，接著顯示已啟用的規則總數，並標示尚未達到持續時間門檻的規則數。開啟規則清單。 |
| **運作正常的服務** | 顯示未超過門檻的服務數，接著顯示區間內出現過的服務總數，並列出嚴重、警告和無流量的服務數。開啟 [APM](/zh-Hant/apm)。 |
| **通過的探測** | 顯示正在執行且通過的檢查數，接著顯示正在執行的檢查總數，並列出失敗、降級和不穩定的檢查數。開啟[合成監控](/zh-Hant/synthetics)。 |
| **請求錯誤率** | 所有服務的請求失敗比例、請求數和趨勢。 |
| **P95 延遲** | 所有服務請求耗時的第 95 百分位數，以及 P50、P99 和趨勢。 |

帳號有權開啟對應頁面時，才會顯示該指標區塊。未收到 Trace 時，APM 相關的指標區塊會顯示短橫線。

## 服務

**服務** 最多列出八個服務：嚴重的服務排在最前，接著是警告的服務，運作正常的服務則依請求量排序。每列顯示環境、運作狀態、區間內的請求趨勢和輸送量、錯誤率和 P95。超過服務門檻的數值會以顏色標示。點選服務名稱即可在 APM 中開啟該服務；點選 **全部** 則會開啟服務清單。

## 進行中的事件

**進行中的事件** 最多列出六個待確認和處理中的事件，依嚴重程度排序。同一嚴重程度下，持續最久的事件排在最前。每列顯示嚴重程度、第一個受影響的服務、已持續的時間和負責人。點選 **確認** 可直接在清單中確認待確認的事件；沒有確認權限的帳號只會看到事件狀態。

## 資料接收

**資料接收** 依類型顯示各類資料的狀態、最近一次接收時間，以及統計區間內分時段彙整的接收量趨勢和資料列數。面板底部會顯示有資料的資料串流數量，以及儲存量和接收量。點選 **資料串流** 可開啟[資料串流](/zh-Hant/streams)。

| 狀態 | 意義 |
|---|---|
| **正常** | 至少有一個這類資料串流在最近 15 分鐘內收到資料。 |
| **延遲** | 這類資料串流有資料，但最近 15 分鐘內未收到資料。 |
| **異常** | 節點的接收探測回報故障。 |
| **無資料** | 統計區間內，這類資料串流都未收到資料。 |

## 合成監控

**合成監控** 顯示統計區間內所有檢查的可用率和趨勢，並最多列出四個失敗、降級或不穩定的檢查，狀態最差的排在最前。若全部通過，則顯示檢查數量。點選 **全部** 可開啟檢查清單。

## 我的值班

**我的值班** 會依工作區的[值班排程](/zh-Hant/alerting/on-call)顯示資訊：

- 帳號正在值班時，顯示 **值班中** 和交班時間；若目前未值班，但未來 30 天內有班，則顯示 **下一班** 和起訖時間。
- 若排程目前由其他人值班，則顯示當班人員。臨時代班期間也會註明原值班人員。
- 排程目前無人值班時會顯示提示。點選 **立即安排** 可開啟排程並新增臨時代班。
- 帳號有排班但無法收到警示時會顯示提示。點選 **設定通知方式** 可開啟帳號的[通知設定](/zh-Hant/account#通知設定)。
- 點選 **排程** 可開啟該班次所屬的排程。

## 快速開始

頁面頂端的按鈕會顯示距離完成設定還有幾個步驟。點選按鈕即可開啟步驟清單：

| 步驟 | 完成條件 |
|---|---|
| **連接資料來源** | 工作區中有[平台資料串流](/zh-Hant/streams#平台資料串流)以外的資料串流。 |
| **載入範例資料** | 範例資料串流、範例儀表板和四個已儲存的範例檢視均已存在。 |
| **建立儀表板** | 工作區中有儀表板。 |
| **建立警示** | 工作區中有警示規則。 |
| **設定值班排程** | 工作區中有[值班排程](/zh-Hant/alerting/on-call)。 |
| **設定通知管道** | 工作區中有已啟用且最近一次測試未失敗的[連接器](/zh-Hant/notification-channels)。 |
| **連接 AI 模型** | 工作區中有已啟用且已設定 API Key 的[模型服務](/zh-Hant/agent)。 |
| **自動化管線** | 工作區中有管線。 |

系統依目前使用者的權限顯示步驟：若無法讀取完成狀態或開啟對應頁面，就不顯示該步驟；若可讀取完成狀態但無權完成步驟，則只在步驟完成後顯示。

**載入範例資料** 適用於還沒有資料可供查看的工作區。工作區有自己的資料串流後，就不再提供這個步驟。無權讀取資料串流清單的使用者也看不到這個步驟。載入範例後，這個步驟會保留並標示為已完成，**連接資料來源** 也會一併完成。若要將範例資料載入已有資料的工作區，請送出[快速開始中的請求](/zh-Hant/quickstart#載入範例資料)。

**載入** 會將少量彼此關聯的範例資料寫入三個資料串流：`sample_app_logs`、`sample_app_metrics` 和 `sample_app_traces`。追蹤會模擬從 `frontend` 經 `checkout`、`payment` 到 `db` 的呼叫，日誌包含相同的 `trace_id`，指標則記錄各服務的耗時，因此可直接示範如何從追蹤跳至對應的日誌。載入時也會使用這三個資料串流建立一個儀表板，以及四個查詢 `sample_app_logs` 且已釘選的[已儲存檢視](/zh-Hant/saved-views)。這些檢視和儀表板都會顯示最近三小時的資料。載入完成後，系統會開啟該儀表板。每次載入只會寫入一批範例資料，時間戳記都早於載入時間。因此，載入三小時後，儀表板和已儲存的檢視就不會顯示資料。

再次載入時，系統會附加以目前時間為基準的資料。系統會保留原有的儀表板和已儲存的檢視（包含已做的變更），只補建缺少的項目，因此載入若中途失敗，可以重新執行。載入需要 `logs.write`、`metrics.write`、`traces.write`、`dashboards.create` 和 `saved_views.create`。系統會在寫入任何資料前檢查這五項權限。

## 權限

開啟首頁不需要權限。系統會依各區塊所屬模組的讀取權限載入內容。

| 權限 | 區塊 |
|---|---|
| `alerts.incidents.read` | **進行中的事件**、對應的指標區塊，以及整體狀態中的事件資訊。 |
| `alerts.incidents.acknowledge` | **進行中的事件** 中的 **確認**。 |
| `alerts.rules.read` | **觸發中的規則**。 |
| `apm.services.read` | **服務**、**運作正常的服務**、**請求錯誤率** 和 **P95 延遲**。 |
| `synthetics.monitors.read` | **合成監控** 和 **通過的探測**。 |
| `synthetics.results.read` | **合成監控** 中的可用率和趨勢。 |
| `streams.query` | **資料接收** 和狀態列中的資料接收狀態。 |
| `schedules.read` | **我的值班**。沒有這項權限時，不顯示此面板。 |
| `notify.policies.read` | **我的值班** 中「無法收到警示」的提示。 |
| `notify.connectors.read`、`agent.models.read`、`pipelines.read` | 快速開始中對應的步驟。 |
| `logs.write` | 快速開始中的 **載入**。 |
