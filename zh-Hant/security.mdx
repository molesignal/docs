MoleSignal 在 API 與資料平面層級執行租戶隔離與授權控管，而非在 Web 導覽層級執行。

## 租戶隔離

每個組織的資料串流與產品資源都有對應的 `org_id`。查詢規劃器會在執行前加入已授權組織的範圍限制。資源處理常式也會在讀取或修改前載入目標，並驗證其所屬組織。

跨工作區存取必須有明確的 IAM 授權，或使用支援的資源共用方式。資源不相符時，系統不會在未通知的情況下切換組織。

`_sys` 組織是受保護的平台範圍。租戶工作階段與 `mspat-*` API 權杖無法用來列舉平台管理員或 MoleSignal 平台遙測資料。

## 身分驗證與授權

MoleSignal 接受：

- 儲存在 HttpOnly Cookie 中的瀏覽器工作階段，切換工作區後會依新範圍重新寫入；
- 透過 `Authorization` 要求標頭傳送、格式為 `mspat-<36>` 的 API 權杖；
- 用於範圍受限的公開或整合路由的專用自我驗證權杖。

使用者可以使用密碼登入，也可以透過管理員在 **身分與存取 → SSO 服務提供者** 中設定的 OIDC、OAuth 2.0、SAML 或 LDAP 服務提供者登入。

系統使用 API 權杖的前綴查找權杖，並以雜湊形式儲存其密鑰。完整權杖只在建立時顯示。

身分驗證後，伺服器會解析資料庫中的權限、角色、繫結、資源關係與目標的擁有權。詳見[身分與存取](/zh-Hant/identity)。

## 瀏覽器工作階段

登入時會寫入兩個 Cookie：存取權杖與重新整理權杖。每個 API 要求都會附上存取權杖，有效期為 15 分鐘。重新整理權杖會在工作階段結束前為存取權杖續期，工作階段會在 `[auth].session_ttl_secs` 後結束。兩個 Cookie 都設有 `HttpOnly`，網頁指令碼無法讀取。兩者也都設有 `SameSite=Strict`，透過 HTTPS 存取時還會加上 `Secure`。使用工作階段修改資料的要求必須來自 MoleSignal 的頁面，瀏覽器會在 `Sec-Fetch-Site` 中標示來源。跨網域呼叫 API 時不會附帶認證資訊。

伺服器不儲存工作階段記錄，兩個權杖都是已簽署的 JWT。登出會刪除該瀏覽器中的 Cookie，但從瀏覽器複製出去的權杖在到期前仍然有效。若要立即中斷特定使用者的存取權，請停用該帳號。系統會在每次要求和續期時檢查帳號狀態。輪替簽署金鑰後，所有工作階段都會在 24 小時的寬限期結束時失效。

## JWT 簽署金鑰

系統會在首次啟動時初始化 JWT 簽署金鑰，並將金鑰寫入資料庫。中繼資料端點不會傳回金鑰的原始位元組。輪替後，系統會使用新金鑰簽發權杖，使用已停用金鑰簽發的權杖在 24 小時內仍然有效。所有節點都不必重新啟動，即可使用新金鑰。

列出或輪替簽署金鑰需要平台權限 `sys.signing_keys.rotate`：

```text
GET  /api/v1/auth/jwt/secrets
POST /api/v1/auth/jwt/rotate
```

只有在部署原則要求使用固定的初始金鑰時，才使用 `MS_AUTH_JWT_SECRET_OVERRIDE`。

## 稽核

安全性相關與產品變更的操作流程會記錄操作者、組織、操作、目標、時間與安全性中繼資料。具備 `audit.read` 權限即可在**設定 → 稽核**查詢組織事件。同一批事件也會以資料列的形式記錄在 `_audit` 資料串流中，請參閱[稽核資料串流](/zh-Hant/settings/data-security#稽核資料流)。

稽核記錄預設保留 90 天。系統每天會刪除所有組織和平台中超過保留期限的記錄，刪除後無法復原。在 `_sys` 組織的**設定 → 稽核記錄保留**中修改保留天數，需要 `sys.settings.retention.manage` 權限；輸入 `0` 表示永久保留。每次修改保留天數時，系統都會在平台稽核中記錄 `audit_retention.update` 事件。

稽核事件的內容不會包含認證資訊、模型金鑰、敏感的 Webhook 要求標頭與原始簽署材料。

## 資源共用

公開儀表板和報表連結屬於 Bearer 憑證，但不會轉換為組織權杖。MoleSignal 會將連結交換為短效的 HttpOnly 共用工作階段，並將存取範圍限制為單一已儲存的資源。

公開儀表板的面板只能透過受限的代理執行伺服器上已儲存的查詢。可以為共用連結設定到期時間、要求輸入密碼、限制最大檢視次數或停用下載，也可以撤銷或輪替連結。詳見[資源共用](/zh-Hant/resource-sharing)。

## 欄位層級加密

建立資料串流時，將欄位標示為加密欄位。MoleSignal 會在將值寫入 Parquet 前使用 AES-256-GCM 加密。一般查詢會傳回密文，在 SQL 中使用 `decrypt(field)` 即可還原為明文。請參閱[資料串流](/zh-Hant/streams#加密欄位)。

系統使用 `MS_CIPHER_KEY` 中的加密根金鑰封裝組織資料金鑰，建立後不會傳回金鑰材料。讀取金鑰中繼資料需要 `org.cipher_keys.read` 權限；建立、輪替或刪除金鑰需要 `org.cipher_keys.manage` 權限。

<Warning>
  遺失 `MS_CIPHER_KEY` 可能導致加密欄位無法復原。請將金鑰儲存在金鑰管理工具中，並與 PostgreSQL 和物件儲存分開備份。
</Warning>

## 機密資訊與遙測安全

- 將資料庫、物件儲存、SMTP、SSO、模型服務提供者與 Webhook 的認證資訊儲存在金鑰管理工具中。
- 匯出追蹤資料至外部時，請使用 `env:` 或 `secret:` 參照敏感的要求標頭。
- 將內部 gRPC `5082` 連接埠限制在受信任的網路內，因為該連接埠用於叢集通訊協定。
- 為外部 HTTP、OTLP gRPC `4317` 與 Flight SQL `5083` 設定 TLS。
- 除非已針對遠端診斷設置明確的保護措施，否則僅將 pprof 接聽程式繫結至迴路位址。
- 後端追蹤不會記錄要求本文、SQL 值、認證資訊、提示詞、模型輸出與工具參數。

## 速率與大小限制

`router` 角色使用權杖桶演算法限制每個組織的資料擷取與查詢要求速率，並在超過限制時傳回包含 `Retry-After` 回應標頭的 `429`。`standalone` 節點不套用這些限制，請參閱[依角色部署](/zh-Hant/deployment/role-based#速率限制)。系統會拒絕本文超過 2 MiB 的資料擷取要求並傳回 `413`，但原生 JSON 資料擷取的上限為 16 MiB。

系統會依帳號和來源位址計算密碼登入失敗次數。達到上限後，系統會傳回包含 `Retry-After` 的 `429`，不再驗證密碼。系統只封鎖發出要求的來源位址，對帳號本身只限制速率，不會因其他人輸入錯誤密碼而鎖定帳號。對不存在的帳號，系統也採用相同的計數與回應方式。請參閱[登入速率限制](/zh-Hant/settings/platform#登入速率限制)。

## 正式環境強化

接收實際資料前，請更換沙箱的預設值：root 帳號、`MS_CIPHER_KEY`、資料庫與物件儲存的認證資訊。請參閱[正式環境檢查清單](/zh-Hant/deployment/production-checklist)。部署在內部網路時，只對公用網際網路開放外部回呼與公開頁面。請參閱[公用網際網路存取](/zh-Hant/public-access)。
