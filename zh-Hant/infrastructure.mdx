**基礎架構**列出服務執行的位置，並把每個位置和寫明它的服務、日誌、指標關聯起來。出問題的節點可以找到它的 Pod 上的每個服務；變慢的服務執行個體可以找到它所在的 Pod 和節點。

## 實體從哪裡來

這個頁面不需要設定。平台每五分鐘讀取最近 15 分鐘的兩類資料：

- APM 在 Span 裡看到的執行個體，以及執行於執行個體上的服務。
- 最多四個帶有 `host.name`、`k8s.node.name` 或 `k8s.pod.name` 欄位的指標或日誌資料流，最多讀取 2,000 個不同位置的資源欄位。

欄位遵循 OpenTelemetry 語意慣例：

| 類型 | 依據 | 鍵 |
|---|---|---|
| 叢集 | `k8s.cluster.name` | 叢集名稱。 |
| 節點 | `k8s.node.name` | `叢集/節點`。 |
| Pod | `k8s.pod.name` 加 `k8s.namespace.name` | `叢集/命名空間/Pod`。 |
| 主機 | `host.name`，僅限 Kubernetes 之外 | 主機名稱。 |
| 容器 | `container.id` 加 `container.name` | 容器 ID。 |

在 Pod 裡 `host.name` 通常是 Pod 名稱，所以寫明了 Pod、節點或叢集的資料不會產生主機。服務執行於它的 Span 寫明的最內層位置：Pod，其次主機，再次節點。Pod 執行於節點上，節點屬於叢集，容器屬於 Pod。

要補齊 Kubernetes 欄位，在 OpenTelemetry Collector 中加入 `k8sattributes` processor，並用 `resource` processor 設定 `k8s.cluster.name`；**資料來源**頁面的 Kubernetes 接入指南包含這兩項。一週沒有出現的實體會被遺忘。

## 清單

清單顯示最近一週看到的全部實體，最近出現的排在前面。綠點表示最近 30 分鐘內出現過，即正在執行；灰點表示只在更早出現過。**服務**是直接執行於它上面的服務數。可以按類型篩選，或按名稱、鍵搜尋；兩者都保存在網址裡。

## 實體頁面

開啟一個實體可以看到：

- **執行於**：它的節點和叢集，或容器所屬的 Pod。
- **執行於它上面**：叢集的節點、節點的 Pod、Pod 的容器。
- **服務**：它上面以及執行於它上面的實體上的服務，每個都連結到 APM 頁面。
- **其服務的變更**：這些服務最近 24 小時的部署和其他變更。參見[變更](/zh-Hant/api/changes)。
- **資源屬性**：它最後一次出現時帶的欄位，每個都可以複製。

**日誌**開啟 Pod 或主機最近一小時的日誌。**指標**按 `k8s.cluster.name`、`k8s.node.name`、`k8s.pod.name`、`host.name` 或 `container.id` 開啟帶有它名字的指標。

服務 [APM](/zh-Hant/apm) 頁面 **執行個體** 表中的 **工作負載 / 主機** 儲存格會開啟該執行個體所在的 Pod 或主機。

## 權限

頁面和 API 需要 `apm.services.read`、`metrics.read`、`logs.read` 之一，系統範圍內也可以是 `sys.telemetry.read`。Mole Agent 用 `list_entities` 和 `get_entity` 讀取同樣的資料。
