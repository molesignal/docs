自動探索每 5 分鐘掃描一次各個組織，將結果儲存為 **探索**。開啟 **警示 → 自動探索**，查看結果需要 `alerts.discovery.read`，建立規則需要 `alerts.rules.manage`。

## 探索項目

| 種類 | 來源 | 判定條件 |
|---|---|---|
| **服務突變** | [APM 洞察](/zh-Hant/apm/insights) | 最近半小時內，服務的錯誤率、P95 延遲或流量，相較於前一時段和上週同一時段都有明顯變化，且請求數足以判斷。 |
| **新版本表現變差** | APM 洞察 | 最近半小時內首次出現的版本，表現比前一個版本差。 |
| **前端新錯誤** | [RUM 錯誤](/zh-Hant/rum/errors) | 應用程式在最近半小時內首次出現的錯誤 issue。 |
| **前端錯誤再次出現** | RUM 錯誤 | 已解決的錯誤 issue 在較新的版本中再次出現。 |
| **錯誤日誌激增** | 日誌 | 最近 15 分鐘內，單一日誌串流記錄了至少 20 筆錯誤日誌，且筆數達到前 1 小時每 15 分鐘平均筆數的 3 倍以上；串流有服務欄位時，按服務分開計算。 |
| **新的錯誤日誌** | 日誌 | 最近 15 分鐘內出現至少 3 次，且在此前一天未曾出現在該串流中的錯誤訊息。訊息中的數字和十六進位字串即使不同，仍視為同一則訊息；每個串流最多列出 10 則。 |
| **資源快用滿** | 指標 | 檔案系統使用率達 90%，或記憶體使用率達 95%。 |
| **CPU 突變** | 指標 | 主機 CPU 使用率至少為 60%，且比 1 小時前高出至少 30 個百分點。 |
| **容器重新啟動** | 指標 | 容器在最近 15 分鐘內曾重新啟動。 |

日誌：每個組織檢查 20 個含有層級欄位（例如 `level`、`severity`、`severity_text`、`severity_number`）的日誌串流，優先檢查最近變更過結構的串流。error、fatal、critical 等層級視為錯誤，`severity_number` 為 17 以上也視為錯誤。指標：只檢查 OpenTelemetry 的主機和 Kubernetes 接收器，以及 Prometheus 的 node_exporter 和 kube-state-metrics 所提供的一組常見資源指標。僅查詢指標目錄中已有的項目，不掃描其他指標。

效能建議（緩慢的相依項目、N+1、緩慢的陳述式、熱門端點）不算問題，不會納入自動探索。已忽略和已解決的 issue 也不算。

同一個問題（種類、服務或應用程式、環境和指標皆相同）只會有一筆進行中的發現。再次偵測到時，更新目前值和最後偵測時間；連續三輪未偵測到就結束，並保留已結束的發現 30 天。如果某個來源無法讀取（例如暫時無法查詢 APM 或 RUM，或某個日誌串流查詢失敗），這一輪不會更新該來源進行中的發現。有多個 `alert` 節點時，依 ID 將組織分配給各節點。

## 發現清單

在 **進行中** 和 **已結束** 之間切換，並可依種類篩選。每列用一句話說明發現內容，例如「checkout 的錯誤率升至 12.0%（先前為 0.40%）」。下方顯示嚴重程度、種類和環境，後方顯示開始時間和最後偵測時間（已結束則顯示結束時間）。

按一下任一列，開啟詳細資料：種類、目前值、前一時段和上週同一時段的值、版本、錯誤位置，以及開始時間和最後偵測時間。APM 的發現也會列出開始前後的部署和版本變更。**在 APM 中開啟**、**在 RUM 中開啟**、**查看這些日誌**、**在指標中開啟** 分別開啟對應的服務、應用程式、日誌串流或查詢。

按一下 **讓 Mole Agent 調查**，關閉詳細資料，並針對這筆發現開啟 [Mole Agent](/zh-Hant/agent) 對話。Mole Agent 會使用 `get_discovery_finding` 讀取這筆發現，查看開始前後的日誌、指標、追蹤和變更，再建議下一步。

## 使用規則傳送通知

發現只會加入清單，不會發送通知吵醒值班人員。這些結果是推算而來的，直接發送通知容易誤報。若要發送通知，請建立自動探索規則：

1. 按一下 **建立自動發現規則**，或在一筆發現的詳細資料中按一下 **為這類發現建立規則**（系統會依該筆發現填入種類、服務和環境）。
2. 在 **哪些發現** 中填寫 **名稱**，選擇 **種類**（全部不勾選即涵蓋所有種類），並填寫 **服務或應用程式**（APM 服務名稱或 RUM 應用程式 ID，以逗號分隔，留空即涵蓋全部）、**環境** 和 **最低嚴重程度**。
3. 在 **通知對象** 中選擇 **升級策略** 和 **緊急程度**：預設為 **低（預設）**，只通知第一級，勿擾時段不發送通知。
4. 按一下 **建立規則**。

規則每分鐘檢查一次進行中的發現，並為每筆符合條件的發現各自建立一個事件。事件沿用發現的嚴重程度，並帶有 `discovery.finding`、`discovery.kind` 和 `discovery.subject` 標籤，供路由規則和靜音設定比對。發現結束時，事件就會恢復。規則會顯示在[規則清單](/zh-Hant/alerting/rules#自動探索規則)中，來源為 **自動探索**。

## 讓 Mole Agent 調查新發現

觸發方式設為 **新的自動發現** 的[自動化](/zh-Hant/automations#觸發方式)，會針對儲存或啟用後出現的每筆符合條件的發現執行一次。條件包括 **種類**（全部不勾選即涵蓋所有種類）、**至少** 達到指定的嚴重程度，以及 **服務、主機或容器**（以逗號分隔，留空即涵蓋全部）。同一筆發現只會調查一次。預設不會自動調查任何發現，避免推算出的問題在未察覺的情況下耗用 Token 額度。

## API 與 Mole Agent

| 操作 | 端點或工具 |
|---|---|
| 列出發現 | [`GET /api/v1/alerts/discovery/findings`](/zh-Hant/api/alerting/discovery) |
| 取得單筆發現 | [`GET /api/v1/alerts/discovery/findings/{id}`](/zh-Hant/api/alerting/discovery) |
| 建立自動發現規則 | [建立規則](/zh-Hant/api/alerting/create-rule)，`query.discovery` |
| Mole Agent | `list_discovery_findings` 和 `get_discovery_finding`（唯讀） |
