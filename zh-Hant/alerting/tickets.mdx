工單連接器會將事件同步到 Jira（Cloud 或 Data Center / Server）、ServiceNow 或飛書專案（海外版為 Meegle）。可在事件上建立工單，也可讓新事件依規則自動建立工單。工單之後會與事件同步：事件確認、解決及新增備註時會在工單上新增留言，事件解決時則會將工單轉為結案狀態。工單狀態每 5 分鐘同步回 MoleSignal 一次，Jira 也可以透過 Webhook 即時推送。

開啟 **警示 → 工單**。檢視工單需要 `alerts.tickets.read`，管理連接器需要 `alerts.tickets.manage`，在事件上建立工單需要 `alerts.incidents.tickets`。

## 連線至 Jira

按一下 **新增工單連接器**，選取 **Jira**：

| 設定 | 說明 |
|---|---|
| **站台位址** | 例如 `https://example.atlassian.net`。 |
| 部署方式 | **Jira Cloud** 使用 **帳號電子郵件** 和 **API Token**（在 Atlassian 帳號設定的安全性頁面建立）；**Jira Data Center / Server** 使用 **個人存取權杖**。 |
| **專案 Key**、**問題類型** | 例如 `OPS` 和 `Incident`。 |
| **對應的工單優先順序** | 先依組織的各級事件優先順序（預設為 P1 到 P5），再依嚴重程度，分別填入 Jira 中的優先順序名稱，例如 P1 填入 `Highest`。若事件未設定優先順序，或該級未填寫，則依嚴重程度對應。若兩者皆未填寫，則不設定工單優先順序。 |
| **標籤** | 加到工單上的標籤。每張工單還會加上 `molesignal`。 |
| **解決事件時的狀態轉換** | 狀態轉換的名稱或 ID。留白時，採用第一個可轉至結案類別狀態的轉換。 |
| **Webhook 密鑰** | 設定後才會接收 Jira 的 Webhook，請參閱[狀態同步](#狀態同步)。 |

用來建立工單的帳號必須能在此專案中建立問題、新增留言及執行狀態轉換。儲存後按一下 **測試連線**，測試成功時會顯示已登入的使用者。

## 連線至 ServiceNow

按一下 **新增工單連接器**，選取 **ServiceNow**。連接器使用 Table API，工單是資料表中的一筆記錄。

| 設定 | 說明 |
|---|---|
| **執行個體網址**、**資料表** | 例如 `https://example.service-now.com` 和 `incident`。資料表必須繼承 `task`。 |
| 驗證方式 | **使用者名稱和密碼**；**OAuth 用戶端憑證**（執行個體必須啟用用戶端憑證授權，屬性為 `glide.oauth.inbound.client.credential.grant_type.enabled`）；**API Key**（自 Washington DC 版本起支援，放在 `x-sn-apikey` 標頭中）。帳號必須能讀寫這個資料表。 |
| **指派群組**、**提單人**、**類別** | 建立工單時填入的欄位。指派群組和提單人填入 `sys_id`，留白則不設定。其他欄位可透過 API 的 `settings.fields` 設定。 |
| **對應的工單優先順序** | ServiceNow 依 impact 和 urgency 計算優先順序。在此填入 `impact/urgency`，例如 `2/1`；若只填一個數字，兩者皆使用該數字。先依事件優先順序對應，再依嚴重程度對應。預設值為：嚴重 `1/1`、錯誤 `2/1`、警告 `2/2`、資訊 `3/3`。 |
| **解決時的狀態值**、**解決代碼** | 解決事件時填入的 `state` 和 `close_code`，預設為 `6` 和 `Solution provided`。預設資料原則要求在解決時提供解決代碼和解決說明。`close_code` 的選項因執行個體而異，請依執行個體調整。解決說明為「事件已在 MoleSignal 解決」，使用工作區的預設語言。 |
| **視為結案的狀態** | `state` 的值，以逗號分隔，預設為 `6, 7, 8`（已解決、已關閉、已取消）。 |

事件的變更會寫入 `work_notes`（內部備註），不會打擾提單人。記錄的 `correlation_id` 為事件 ID，`correlation_display` 為 `MoleSignal`。**測試連線** 會讀取這個資料表一次。

## 連線至飛書專案

按一下 **新增工單連接器**，選取 **飛書專案**。先在飛書專案的開發者後台建立外掛，取得外掛 ID 和外掛密鑰，再將外掛安裝到要建立工單的空間。

| 設定 | 說明 |
|---|---|
| **平台**、**站台位址** | 選取 **飛書**（飛書專案，`https://project.feishu.cn`）或 **Lark**（Meegle，`https://meegle.com`）。站台位址由平台決定，只能複製，無法修改。 |
| **外掛 ID**、**外掛密鑰** | 用於換取外掛 Token。 |
| **使用誰的身分（user_key）** | 以這個身分建立工單和新增留言。 |
| **空間（project_key）**、**工作項目類型（work_item_type_key）** | 指定要在哪個空間建立哪種類型的工作項目。 |
| **優先順序欄位 key**、優先順序對應 | 先依組織的各級事件優先順序，再依嚴重程度，分別填入優先順序選項的值。若事件未設定優先順序，或該級未填寫，則依嚴重程度對應。若兩者皆未填寫，則不設定工單優先順序。 |
| **解決事件時的狀態轉換 ID** | 適用於採用狀態流程的工作項目。 |
| **解決事件時要完成的節點 ID** | 適用於採用節點流程的工作項目。 |
| **視為結案的狀態** | 狀態 key，以逗號分隔。工單進入這些狀態時即視為結案。 |

**測試連線** 會讀取工作項目類型一次。憑證、空間和類型皆正確時，測試即成功。

## 與事件同步

在連接器的 **與事件同步** 中設定工單如何與事件同步：

| 設定 | 效果 |
|---|---|
| **事件獲確認時新增留言**、**事件解決時新增留言** | 在工單上新增一則留言，說明事件已在 MoleSignal 確認或解決。 |
| **將事件備註新增為留言** | 將事件中新增的[備註](/zh-Hant/alerting/incidents#備註)同步為工單留言。 |
| **解決事件時將工單轉為結案狀態** | 依上述狀態轉換設定將工單結案。 |
| **工單結案時解決事件** | 工單結案時，對應的事件也會解決，無論事件仍開啟或已確認。預設關閉。 |
| **宣告重大事件時建立工單** | 事件宣告為[重大事件](/zh-Hant/alerting/major-incidents)時，透過這個連接器建立一張工單。 |

工單標題為 `[严重度] 事件摘要`。內文包含事件的嚴重程度與狀態、服務、標籤、觸發查詢、AI 根因摘要，以及事件頁面的連結。留言和內文使用工作區的預設語言。

## 自動建立工單

開啟 **自動建立工單** 後，如果新事件的嚴重程度達到 **嚴重程度不低於** 設定的門檻，且事件的服務列在 **服務** 中（留白則不限），這個連接器就會自動建立一張工單。每個連接器只會為同一事件建立一張工單。

## 在事件上建立工單

事件詳細資料中的 **工單** 會列出事件的工單編號（按一下即可開啟工單）、狀態、上次同步時間，以及同步或新增留言時發生的錯誤。按一下 **建立工單**。若有多個連接器，請選取 **在 … 建立工單**。系統會將建立工單的操作記錄在事件時間軸和稽核日誌中。

[事後檢討](/zh-Hant/alerting/major-incidents#事後檢討)中的每個改善項目也可以各建立一張工單。這類工單不會隨事件新增留言或轉換狀態，結案時也不會解決事件。

## 狀態同步

尚未結案的工單每 5 分鐘同步一次狀態。狀態有變更時，系統會記錄在事件時間軸上。Jira 依狀態類別判斷是否結案；飛書專案和 ServiceNow 則依連接器中列出的狀態判斷。

Jira 可以改用即時推送。在連接器中設定 **Webhook 密鑰** 後，連接器清單會顯示 Jira Webhook 位址，按一下 **複製位址**。接著在 Jira 的**系統設定 → WebHooks** 中新增 Webhook，在 URL 填入此位址，密鑰填入相同的 Webhook 密鑰，並在事件中勾選問題更新。MoleSignal 會使用密鑰驗證 `X-Hub-Signature`，並拒絕簽章不符的請求。Webhook 位址不需登入，請參閱[公開存取](/zh-Hant/public-access)。
