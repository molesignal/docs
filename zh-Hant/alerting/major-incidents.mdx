影響範圍廣、需要多人協作的事件，宣告為重大事件後會有三個角色、一間作戰室、一場會議、一份任務清單，以及統一的進度通報。事件結束後，依範本起草事後檢討。每項改善措施都有負責人和截止日期，也可以各自建立一張工單。

宣告需要 `alerts.incidents.escalate`；指派角色、管理任務和發布進度需要 `alerts.incidents.update`；修改組織的重大事件設定需要 `alerts.response.manage`；檢視事後檢討需要 `postmortems.read`，撰寫事後檢討需要 `postmortems.manage`。

## 宣告重大事件

在事件詳細資料的 **重大事件** 中，按一下 **宣告重大事件**。接著：

1. 宣告者成為 **指揮官**，系統將組織設定中的 **檢查清單** 項目加入任務。
2. 依設定召開會議：預約飛書視訊會議或騰訊會議、召開 Zoom 會議、建立 Google Meet 會議，或使用固定的會議連結。請參閱[會議](#會議)。
3. 如果已設定用於建立群組的連接器，系統會透過該連接器建立群組（飛書、Slack、釘釘或企業微信），將群組命名為 `[严重度] 事件摘要`，加入事件負責人、各角色和關注者，並傳送開場訊息、事件連結和會議加入連結。
4. 每個啟用 **宣告重大事件時建立工單** 的[工單連接器](/zh-Hant/alerting/tickets)各建立一張工單。

建立群組、召開會議或建立工單失敗，都不影響宣告。卡片隨後會顯示宣告者、三個角色、**進入作戰室** 和 **加入會議** 的連結（釘釘和企業微信的群組沒有加入連結，會顯示 **已建立群組**），以及任務。無法將已解決的事件宣告為重大事件。如果組織啟用了[自動宣告](#重大事件設定)，符合條件的新事件一建立就會成為重大事件。

### 角色

| 角色 | 職責 |
|---|---|
| **指揮官** | 統籌事件處置，決定下一步。 |
| **溝通負責人** | 對內和對外通報進度，例如[發布進度](#發布進度)和更新狀態頁。 |
| **記錄員** | 記錄時間軸和決策，供事後檢討使用。 |

在卡片上為每個角色選擇人員，或選擇 **未指派** 以取消指派。系統會將指派記錄在時間軸上。

### 作戰室

系統會使用組織設定中可建立群組的[訊息連接器](/zh-Hant/notification-channels)建立作戰室：

- **飛書**：應用程式須能建立群組、取得群組的分享連結，以及以應用程式身分傳送訊息。系統會依據成員在此連接器上繫結的 `open_id` 將成員加入群組。
- **Slack**：Slack App 會建立公開頻道，須能建立頻道、邀請成員和傳送訊息。系統會依據已繫結的成員 ID 邀請成員。
- **釘釘**：企業內部應用程式會建立內部群組，須具備釘釘群組基本資訊管理權限（`qyapi_chat_manage`）。系統會依據成員繫結的 userId 將成員加入群組，群組名稱最多 20 個字元。建立群組的 API 不會將應用程式的機器人加入群組。請在釘釘中將機器人加入群組，才能傳送開場訊息和進度。
- **企業微信**：自建應用程式會建立應用程式群組聊天，可見範圍須設為根部門。系統會依據成員繫結的 userid 將成員加入群組，至少需要兩名成員。

釘釘和企業微信的群組擁有者為指揮官。如果指揮官未繫結身分，則由第一位成員擔任。系統不會將未在連接器上[繫結身分](/zh-Hant/notification-channels#繫結使用者通知方式)的人員加入群組。飛書和 Slack 支援透過連結加入群組，釘釘和企業微信的群組則沒有加入連結。Teams 和 Google Chat 的應用程式無法使用連接器現有的憑證建立群組，因此不提供這兩個選項。

### 會議

| 會議 | 召開方式 | 所需設定 |
|---|---|---|
| **預約飛書視訊會議** | 預約一場 6 小時的會議，由指揮官擔任會議擁有者。 | 使用飛書 App 連接器（預設使用建立群組的連接器），並啟用視訊會議預約權限。 |
| **預約騰訊會議** | 以建立者的名義預約一場 6 小時的會議。 | 在騰訊會議的企業管理後台建立企業自建應用程式，填寫 AppId、SdkId（僅在應用程式提供時填寫）、SecretId、SecretKey 和建立者的 userid。 |
| **召開 Zoom 會議** | 召開即時會議，由設定中的使用者擔任主持人。 | 在 Zoom App Marketplace 建立伺服器對伺服器 OAuth 應用程式，授予建立會議的權限（`meeting:write:meeting:admin`）；填寫 Account ID、Client ID、Client Secret 和主持人的電子郵件地址或使用者 ID。 |
| **建立 Google Meet 會議** | 由服務帳號代會議召集人建立會議。 | 準備服務帳號的金鑰（JSON）和會議召集人的電子郵件地址；在 Google Workspace 管理控制台為服務帳號啟用全網域委派，並授予 `https://www.googleapis.com/auth/meetings.space.created` 權限。 |
| **固定的會議連結** | 每次都使用這個連結。 | 以 `https://` 開頭的會議連結。 |

系統會加密儲存 SecretKey、Client Secret 和服務帳號金鑰，儲存後不再顯示。編輯時留空即可保留原值。變更會議方式後，系統不再保留舊金鑰。

### 任務

宣告時會套用檢查清單。之後可在卡片上按一下 **新增一項任務**，也可以勾選任務以標示完成，或刪除任務。已完成的任務會顯示完成者。系統會將新增和完成任務的動作記錄在時間軸上。每個事件最多可有 50 項任務。

### 發布進度

按一下 **發布進度**，填寫 **影響**、**現況** 和 **下一步**（至少一項），再按一下 **傳送**。系統會：

- 將進度記錄在事件的時間軸上；
- 將進度傳送到作戰室；
- 透過內建策略[重大事件進度：通知關注者](/zh-Hant/notification-channels#內建策略)，通知事件負責人、各角色和組織設定中的關注者。

## 重大事件設定

開啟 **警示 → 事後檢討**，按一下 **重大事件設定**：

| 區段 | 設定 |
|---|---|
| **作戰室與會議** | **用於建立群組的連接器**：選擇可建立群組的訊息連接器（飛書 App、Slack App、釘釘、企業微信），或選擇 **不建立群組**。請參閱[作戰室](#作戰室)。**會議**：選擇 **不召開會議**，或選擇[會議](#會議)中的一種方式。 |
| **檢查清單** | 宣告時套用的任務，每行一項，最多 30 項。 |
| **關注者** | 系統會向關注者通報進度，並在建立群組時將關注者加入群組。 |
| **自動宣告** | **啟用自動宣告** 後，如果新事件的嚴重程度和 **優先順序** 達到所選門檻（例如 P2 及以上），且服務在指定清單中（留空則不限），事件一建立就會成為重大事件，卡片上會顯示「依組織規則宣告為重大事件」。如果選擇了優先順序，未設定優先順序的事件不符合條件；選擇 **不限優先順序** 則不受此限制。 |

## 事後檢討

事後檢討是事件的內部總結，每個事件一份，與[狀態頁的事故事後檢討](/zh-Hant/status-pages#事件事後檢討)分開儲存。

在事件詳細資料的 **事後檢討** 中，按一下 **撰寫事後檢討**，MoleSignal 就會依範本起草。標題使用事件摘要，內文分為 **摘要**、**影響**（持續時間、服務、嚴重程度）、**時間軸**（觸發、時間軸上的各個步驟和復原）、**根本原因**（有 AI 分析出的根本原因時填入）、**做得好的地方**、**做得不好的地方** 和 **改善措施**。接著按一下 **開啟事後檢討** 繼續撰寫：

- 修改 **標題**、**狀態**（**草稿**、**審查中**、**已發布**）和 **內文（Markdown）**，再按一下 **儲存**。
- **讓 Mole Agent 起草**：在 Mole Agent 中開啟對話，讓 Mole Agent 根據時間軸、備註、根本原因分析和觸發查詢撰寫草稿，並儲存至這份事後檢討。
- **複製摘要**：複製 **摘要** 段落的文字，貼到狀態頁的事故事後檢討。
- **改善措施**：按一下 **新增一項改善措施**，完成後勾選。如果已啟用工單連接器，可按一下 **建立工單** 為該措施建立工單，工單編號會顯示在旁邊。

**警示 → 事後檢討** 會列出組織的所有事後檢討，並顯示狀態、負責人、未完成和逾期的改善措施數量，以及最後修改時間。按一下標題可開啟事後檢討，按一下下方的事件名稱可前往事件。
