升級策略決定事件要通知哪些人，以及通知的順序。每一級都能指定人員、團隊或值班排程，讓通知跟著輪值走，而不是固定通知特定人員。開啟 **警示 → 值班排程** 和 **警示 → 升級**。讀取兩者分別需要 `schedules.read` 和 `alerts.escalations.read`；建立、修改和刪除排班分別需要 `schedules.create`、`schedules.update` 和 `schedules.delete`，修改升級策略需要 `alerts.escalations.manage`。

## 通知如何送達

1. 規則觸發並開啟事件，事件會使用該規則的升級策略；如果規則使用預設策略，就由[警示路由](/zh-Hant/alerting/routing)選出策略。
2. 策略從第 1 級開始執行：每個目標都會收到一個通知事件。使用者目標是指定的使用者，排班目標是當下的值班人員，團隊目標則是整個團隊。
3. [通知策略](/zh-Hant/notification-channels#建立範本和策略)將每個通知事件轉為傳送作業，依連接器、個人通知順序及備援路由傳送。
4. 若該級的 **確認時限** 內無人確認，就執行下一級，直到有人確認或解決事件，或所有等級都已執行完畢。如果策略設定了[確認後仍未解決](#確認後仍未解決)，確認後逾時仍未解決的事件會退回未確認狀態，重新開始通知。

套用至事件的靜默會在生效期間暫停升級，靜默結束後會繼續升級。請參閱[靜默期間的通知](/zh-Hant/alerting/silences#靜默期間的通知)。有多個 `alert` 節點時，每條規則都歸屬一個節點，該節點也負責升級這條規則的事件。請參閱[依角色部署](/zh-Hant/deployment/role-based#alert-節點之間的分工)。

## 值班排程

**值班排程** 列出各個排班的時區、輪值、人數、目前值班人員、下次切換和狀態。頁面頂端彙整排班數、目前值班人數、本週輪替次數及臨時代班。可依排班、團隊、負責人、時區或狀態篩選，也可勾選 **只顯示我參與的排班**。清單上方的 **訂閱我的值班** 可將個人在各排班的班次加到行事曆應用程式，請參閱[訂閱行事曆](#訂閱行事曆)；**換班申請** 列出個人送出的申請和收到的代班請求，並標示待回覆的件數，請參閱[換班申請](#換班申請)。

| 狀態 | 含義 |
|---|---|
| **進行中** | 有人正在值班。 |
| **即將切換** | 下次交接將在 2 小時內進行。 |
| **尚未開始** | 第一個輪值尚未開始。 |
| **已暫停** | 排班已暫停，不會安排任何人值班。 |
| **有空班** | 目前無人值班。 |

### 建立排班

1. 按一下 **新增排班**。
2. 在 **基本資訊** 中填寫 **排班名稱**、**說明**、**時區**（例如 `Asia/Shanghai`）和 **關聯團隊**。
3. 在 **輪值規則** 中設定各個輪值：

   | 欄位 | 用途 |
   |---|---|
   | 輪值名稱 | 例如 `primary`。 |
   | **輪替方式** | **每日**、**每週**、**工作日**（週一至週五每日輪替）或 **自訂週期**（填寫 **週期（小時）**）。 |
   | **開始日期與時間**、**交接時間** | 輪值何時開始，以及每天幾點交接。 |
   | **在指定時間結束** | 選填：到達 **結束日期與時間** 後，此輪值就不再安排人員值班。 |
   | **輪值成員（依序輪替）** | 參與輪替的人員及順序。 |
   | **限定特定日期／時段** | 只涵蓋一週中的特定時段：每個時段選擇 **星期**，填寫 **開始（HH:MM）** 和 **結束（HH:MM）**，依排班時區計算，精確到分鐘。按一下 **新增時段** 可加入多個時段，例如 9:30–12:00 和 13:30–18:00。結束時間不晚於開始時間表示跨午夜，歸入開始當天；全天請填寫 00:00–24:00。 |
   | **假日** | 選擇 **不考慮國定假日**（預設）、**不計入國定假日** 或 **僅限假日**，並依選取的 **假日行事曆** 計算。請參閱[假日行事曆](#假日行事曆)。將工作日輪值設為不計入國定假日，再於下方新增一個僅限假日的輪值，即可另外安排放假日的值班。 |

4. 視需要開啟 **換班須經核准**：代班人員接受換班後，還須由具備排班管理權限的人員核准，才會生效。
5. 檢查 **未來 7 天預覽**，確認輪值順序、交接時間和各時段的值班人員。
6. 按一下 **建立排班**，或按一下 **儲存草稿**，以暫停狀態儲存。

多個輪值涵蓋同一時間時，以清單中第一個有人值班的輪值為準。例如，可在第一個輪值下方新增夜間或週末輪值。

交接依排班時區的當地時間進行：在紐約時間 09:00 交接的輪值，全年都在 09:00 交接，跨越日光節約時間切換的班次長度為 23 或 25 小時。若交接時間落在切換時跳過的那一小時內，就採用跳過後的第一個時間點；若落在重複的那一小時內，就採用較早的時間點。伺服器會依相同規則計算預覽、時間軸、行事曆訂閱和值班負擔。

### 臨時代班

臨時代班會在固定時段內將值班交給指定人員，適用於請假、換班或故障處理。在排班中按一下 **新增代班**，選擇 **代班人員**，填寫 **原因**、**開始時間** 和 **結束時間**，然後儲存。代班生效期間優先於所有輪值。

同一排班的兩筆代班不得重疊。若代班人員在開始時已參與其他排班，或開始時間已過（儲存後立即生效），表單會顯示提示。按一下 **結束代班**，即可提前結束生效中的代班。

### 換班申請

透過換班申請，可請同一排班中的其他成員代班，不必請管理員新增代班。在排班詳細資料的 **換班申請** 中按一下 **申請換班**，從未來 30 天的個人班次中選擇一個班次（或手動填寫開始與結束時間），再選擇 **代班的人**，視需要填寫簡短備註，然後按一下 **送出申請**。這段時間只能由申請人單獨值班；與尚未定案的申請重疊的時段，不得再次申請。

| 狀態 | 含義 |
|---|---|
| **等待對方回覆** | 代班人員可以 **接受** 或 **拒絕**，申請人可以 **撤回**。 |
| **等待管理員核准** | 排班已開啟 **換班須經核准**，且代班人員已接受；具備排班管理權限的人員可以 **核准** 或 **駁回**。 |
| **已生效** | 排班已新增一筆臨時代班，由接受換班的人員代班。 |
| **對方拒絕**、**管理員駁回**、**已撤回** | 申請已結束，排班不變。 |
| **已過期** | 時段已結束，申請仍未定案。 |

每一步都會通知相關人員：送出申請時通知代班人員；對方拒絕時通知申請人；轉為等待核准時通知排班建立者、最後修改者和申請人；生效或遭駁回時通知申請人和代班人員；撤回時通知代班人員。內建策略[換班：通知相關人員](/zh-Hant/notification-channels#內建策略)會發出這些通知。生效的換班與其他操作都會記入排班的 **變更記錄**。

### 訂閱行事曆

排班的 **更多** 選單中的 **訂閱行事曆** 會產生訂閱網址，可將該排班的所有班次加入 Google 日曆、Outlook、Apple 行事曆等行事曆應用程式；清單上方的 **訂閱我的值班** 則會訂閱個人在各排班中的班次。行事曆應用程式大約每小時重新整理一次，涵蓋過去 30 天到未來 90 天的班次，包括代班和換班。

訂閱網址只顯示一次，取得網址的人都能查看這些班次。每次讀取行事曆時，系統都會重新驗證訂閱者的權限：若帳號停用、訂閱者離開組織或失去排班的檢視權限，該網址就無法再讀取內容。**重設網址** 會產生新網址，讓舊網址立即失效；**停止訂閱** 則會讓網址失效。與透過 **匯出行事曆** 下載的 `.ics` 檔案不同，訂閱會隨排班變更而更新。

### 排班詳細資料與操作

開啟排班即可查看目前的值班人員及其開始時間、下次輪替、輪值規則、臨時代班、[換班申請](#換班申請)、**未來 7 天時間軸**、**成員負擔（近 30 天）**，以及排班的 **變更記錄**。成員負擔會列出每位成員的值班時數、收到的警示通知次數，其中有幾次在夜間（依排班時區從 22:00 到隔天 08:00）、幾次在週末，以及有幾個晚上被吵醒。這些資訊與[洞察](/zh-Hant/alerting/incidents#洞察)中的 **值班負擔** 一致。排班選單提供以下操作：

| 操作 | 效果 |
|---|---|
| **編輯排班** | 修改排班及其輪值。 |
| **新增臨時代班** | 新增一筆代班。 |
| **暫停排班** / **恢復排班** | 暫停的排班不會安排任何人值班，因此以此排班為目標的升級等級無法通知任何人。 |
| **複製排班** | 建立名為 `<名稱> 副本` 的副本。 |
| **訂閱行事曆** | 產生行事曆訂閱網址，請參閱[訂閱行事曆](#訂閱行事曆)。 |
| **匯出行事曆** | 將班次下載為 `.ics` 檔案，以便匯入行事曆。 |
| **刪除排班** | 刪除排班。 |

[首頁](/zh-Hant/home#我的值班)會顯示個人目前或下一個班次。成員可在[帳號設定](/zh-Hant/account#通知設定)中選擇值班通知的送達方式。

### 收不到警示的成員

值班人員收不到警示時，即使開啟事件，也無法喚醒值班人員。MoleSignal 會依高緊急度的個人步驟，將成員分為三類：

| 狀態 | 含義 |
|---|---|
| 收得到 | 已開啟個人警示通知，且至少有一個步驟的通知方式已啟用並通過驗證，其連接器也已啟用。 |
| 只能靠群組 | 沒有個人通知方式，但團隊或組織的預設路由可將通知傳到群組。 |
| 收不到 | 兩種方式都沒有。 |

排班會在收不到警示的成員旁加上標記，升級策略也會在各級標示 **N 人收不到**。若下一班的值班人員收不到警示，排班詳細資料頂端會顯示提示。若個人參與排班卻收不到警示，[帳號設定](/zh-Hant/account#通知設定)和[首頁](/zh-Hant/home#我的值班)的 **我的值班** 面板會顯示提示。班次開始前 30 分鐘，若接班人員收不到警示，內建策略[接班人員收不到警示：通知本人和排班管理員](/zh-Hant/notification-channels#內建策略)會通知接班人員和排班管理員。

事件升級至某一級時，若該級無人能收到警示（包括當下無人值班），就會立即升到下一級，不必等到確認時限屆滿。時間軸會記錄 **第 N 級無人收到警示，直接升到下一級**。若整項策略都無人能收到警示，事件仍會維持開啟，只在時間軸和策略頁面顯示提示。

## 升級策略

**升級** 會列出各項策略的通知對象與通知時間。

1. 按一下 **新增策略** 並填寫 **策略名稱**。
2. 為每一級選擇 **適用的最低嚴重程度**（**任何嚴重程度** 或指定的最低嚴重程度）、**確認時限**（1、5、10、15 或 30 分鐘，或 1 小時）和 **目標**：**使用者**、**排班** 或 **團隊**。按一下 **新增等級** 可新增下一級。
3. 可開啟 **重複執行整個策略，直到事件獲得確認**，並設定 **最多重複次數**。
4. 可設定 **確認後仍未解決**，請參閱[下文](#確認後仍未解決)。
5. 在 **緊急程度** 中選擇這項策略如何決定緊急程度，請參閱[緊急程度](#緊急程度)。
6. 按一下 **建立策略**。

如果某一級的最低嚴重程度高於事件的嚴重程度，系統就會跳過該級。每次傳送使用的連接器和備援路由，請在 **設定 → 通知 → 通知策略** 中設定，而非在升級策略中設定。

### 確認後仍未解決

事件確認後若遲遲未解決，可使用 **確認後仍未解決**，將事件交回值班人員處理：選擇 30 分鐘、1、2 或 4 小時（API 允許 5 分鐘至 24 小時）。從確認起算，若經過這段時間後事件仍未解決，事件會退回 **等待確認**，負責人會再次收到通知，範本中的 `{{escalation.reason}}` 為 `ack_timeout`；若仍無人確認，則照常往下升級。預設為 **不再通知**：事件會維持已確認狀態，直到有人解決。暫緩中的事件不受這段時間限制，會在暫緩結束時退回等待確認。

### 緊急程度

嚴重程度表示訊號有多嚴重，緊急程度則決定是否需要立刻喚醒人員。每個事件開啟時都有一個緊急度等級。兩個內建等級的通知方式如下：

| | 高緊急度 | 低緊急度 |
|---|---|---|
| 升級 | 依策略逐級通知 | 只通知第一級，不往下升級，也不重複執行整項策略 |
| 個人通知 | 依個人的高緊急度步驟 | 依個人的低緊急度步驟；若未設定，只執行高緊急度的第一步 |
| 勿擾時段 | 依個人的 **勿擾期間仍接收高緊急度告警** 設定 | 一律不打擾 |

組織可重新命名各等級、變更通知方式，也可新增等級。請參閱[緊急度與優先順序等級](#緊急度與優先順序等級)。

規則、外部警示、警示管線或手動建立事件時明確指定的緊急程度優先；若未指定，就依事件採用的升級策略中的 **緊急程度** 設定決定：

| 選項 | 效果 |
|---|---|
| **依嚴重程度**（預設） | 每種嚴重程度都對應到組織指定的等級：若未變更設定，嚴重和錯誤對應高緊急度，警告和提示對應低緊急度。 |
| **固定緊急程度** | 每個事件都使用 **緊急程度** 中選取的等級。 |
| **依支援時段** | **時段內** 和 **時段外** 分別使用不同的等級，預設分別為高和低。設定支援時段時，填寫每週的支援時段和一個時區，也可依[假日行事曆](#假日行事曆)排除假日。勾選 **支援時段開始時，將尚未確認且低於時段內設定的事件提升至該緊急程度，並從第一級重新通知** 後，夜間開啟、到早上仍無人確認的事件，會在支援時段開始時升到時段內的等級，並從第一級重新通知。時間軸會記錄 **支援時段開始，緊急程度升為……，從第 1 級重新通知**。 |

勾選 **在這項策略下，原本只通知第一級的緊急程度也會照常逐級升級** 後，各等級都會在這項策略下比照高緊急度逐級升級。若外部警示未提供嚴重程度，則採用高緊急度；若指定的緊急程度在組織中不存在，系統會在開啟事件時捨棄該設定，改由策略決定。策略清單會在升級路徑後標示非依嚴重程度決定的緊急程度。

<Note>
依嚴重程度決定緊急程度時，警告和提示事件預設只通知第一級，且不會在勿擾時段打擾人員。若要讓所有事件維持逐級通知，請將策略的緊急程度設為 **固定緊急程度**，再選擇高緊急度。
</Note>

### 緊急度與優先順序等級

在 **設定 → 警示 → 優先順序與緊急程度** 中設定組織的等級。讀取需要 `alerts.importance.read`，修改需要 `alerts.importance.manage`。

**緊急度等級** 由高到低排列，可用箭頭上移或下移。每個等級都有下列設定：

| 設定 | 用途 |
|---|---|
| 名稱 | 顯示在清單、篩選條件和訊息中的名稱。 |
| **逐級升級** | 依升級策略逐級通知；關閉時，此等級只通知第一級。 |
| **勿擾時段** | **依個人開關設定**（**勿擾期間仍接收高緊急度告警**）或 **一律不打擾**。 |
| **個人步驟** | 選擇要使用哪一組個人步驟：**高緊急度步驟** 或 **低緊急度步驟**。 |
| **依嚴重程度** | 指定策略依嚴重程度決定緊急程度時，哪些嚴重程度對應到此等級。每種嚴重程度只能對應到一個等級。 |

內建的 `high` 和 `low` 可重新命名及變更設定，但無法刪除。透過 **新增緊急度等級** 最多可再新增三個等級，合計五個等級。**新等級的鍵**（例如 `urgent`）須以小寫字母開頭，且只能使用小寫字母、數字和底線。規則、外部警示、警示管線和 API 都以鍵指定緊急程度。刪除等級後，仍使用該等級的事件會依高緊急度通知。

**優先順序等級** 可設定組織使用的等級數量（1 到 9 級），以及各等級的名稱和說明。鍵固定為 `P1`、`P2`……，整合與匯入的檔案都使用這些鍵。若外部警示或警示管線提供的優先順序超出已設定的等級範圍，就採用最低等級。在範本中使用 `{{urgency_name}}` 和 `{{priority_name}}` 取得等級名稱。請參閱[範本變數](/zh-Hant/notification-channels#範本變數)。

### 預設策略

規則透過 `escalationPolicyId` 指定升級策略。未指定策略的規則（包括所有在規則工作台中儲存的規則）會使用別名 `default`：[警示路由](/zh-Hant/alerting/routing)會依路由規則、服務的負責團隊和 team 標籤選出團隊的值班策略。若找不到團隊策略，就使用組織中名為 `default` 的策略，不區分大小寫。若沒有這項策略，這些事件就不會透過升級通知任何人。

請在建立第一條規則前，先建立名為 `default` 的策略，例如讓第 1 級通知主要值班排程，第 2 級通知團隊負責人。事件一旦開始升級，即使之後重新命名 `default` 策略，也會繼續使用原先找到的策略。

## 假日行事曆

假日行事曆記錄放假日和補班日。每週時段可依行事曆排除國定假日，或只在假日生效。開啟 **設定 → 警示 → 假日行事曆**。讀取行事曆需要 `alerts.calendars.read`，修改需要 `alerts.calendars.manage`。MoleSignal 不內建國定假日；假日每年都會變動，請由各組織自行填寫或匯入。

1. 按一下 **新增行事曆**，填寫 **名稱** 和 **說明**。
2. 在 **日期** 中選擇 **年份**，逐筆新增 **日期**、**類型**（**放假** 或 **補班**）和 **當日名稱**。**匯入 ICS** 可讀取國定假日的 `.ics` 檔案：每個全天事件算一天，名稱包含「補班」、「上班」或以「班」結尾的事件視為補班。系統會等到儲存行事曆時才寫入資料，請先確認匯入的日期。
3. 按一下 **建立行事曆**。

在每週時段的 **假日** 欄位中，選擇如何依行事曆計算時段：

| 選項 | 效果 |
|---|---|
| **不考慮國定假日**（預設） | 假日與平日的計算方式相同。 |
| **不計入國定假日** | 這些時段不涵蓋放假日。補班日依週一的時段計算。 |
| **僅限假日** | 這些時段只在放假日生效。 |

日期依引用行事曆處的時區計算，跨午夜的時段歸入開始當天。[值班排程](#建立排班)的輪值、[緊急程度](#緊急程度)的支援時段、[路由規則](/zh-Hant/alerting/routing#新增規則)和[通知策略](/zh-Hant/notification-channels#建立範本和策略)的時間條件、警示管線，以及[靜默](/zh-Hant/alerting/silences#靜默策略)的 **假日** 時間範圍，都可依行事曆計算。無法刪除使用中的行事曆，對話方塊會列出引用該行事曆的位置。變更會在一分鐘內傳到所有節點，行事曆也會隨組織同步到聯邦中的其他叢集。

## 匯入與匯出

升級策略清單和值班排班清單上方的 **匯入與匯出** 功能與告警規則相同，可透過檔案在組織和叢集之間移轉：

- 選擇 **匯出所有升級策略** 或 **匯出所有排班** 以下載套件；選取部分項目時，只匯出選取的項目。套件以電子郵件地址參照使用者，並以名稱參照團隊、排班、升級策略和假日日曆。
- **匯入升級策略…** 或 **匯入排班…** 接受 JSON 或 YAML 套件。系統會先預演，列出將新增、更新、維持不變及發生錯誤的項目；勾選 **只新增，不變更現有的同名規則** 時，會略過現有的同名項目。系統依名稱比對各項目，參照的項目必須存在於組織中。只要有一個項目出錯，就不會寫入任何資料。

套件中的排班包含輪值和設定，但不包含臨時代班和換班；匯入現有排班時，會保留原有的臨時代班和換班。匯入升級策略需要 `alerts.escalations.manage`，匯入排班需要 `schedules.create`。路由規則也支援匯入與匯出，請參閱[告警路由](/zh-Hant/alerting/routing#匯入與匯出)。

**匯入排班…** 也能讀取 Opsgenie 和 PagerDuty API 傳回的排班，請參閱[從 Opsgenie 或 PagerDuty 移轉排班](/zh-Hant/alerting/schedule-migration)。
