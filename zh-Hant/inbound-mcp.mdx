**Inbound MCP** 讓 Claude Code、Cursor、Codex、ChatGPT 等 MCP 用戶端探索並操作 MoleSignal，底層採用與 Mole Agent 相同的受控工具執行環境。用戶端有兩種連線方式：

- **stdio**（建議）：用戶端啟動 MoleSignal 命令列工具（npm 套件 `@molesignal/cli` 的 `molesignal mcp`）。透過瀏覽器登入一次後，命令列工具會將每則訊息轉送至下方端點。
- **Streamable HTTP**：用戶端直接呼叫端點。

端點格式如下：

```text
https://molesignal.example.com/api/v1/mcp
```

服務使用 Streamable HTTP，支援 `2026-07-28`、`2025-11-25`、`2025-06-18` 與 `2025-03-26` 版 MCP 通訊協定，不提供舊版 HTTP+SSE；命令列工具提供 stdio。

具備 `agent.inbound_mcp.manage` 權限的管理員可在 **Mole Agent → 設定 → Inbound MCP** 中調整服務設定。

## 連線前的準備

1. 部署在非回送位址時，將 `http.external_url` 設為 MoleSignal 對外開放的來源（Origin）。請參閱[設定](/zh-Hant/configuration)。
2. 開啟 **Mole Agent → 設定 → Inbound MCP**，確認服務已啟用。
3. 複製頁面顯示的完整端點，包括通訊協定與主機名稱。
4. 選擇 OAuth 2.1、個人 API 權杖或服務帳號 API 權杖。

執行限制與來源允許清單的變更會在下一次 MCP HTTP 請求開始時生效；處理中的請求會繼續使用原有的設定快照。

## 透過 stdio 連線

先用 MoleSignal 命令列工具登入一次。需要 Node.js 20 或更新版本：

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

瀏覽器會開啟 MoleSignal，同意授權即可。命令列工具會將登入資訊儲存在 `~/.config/molesignal/config.json`，只有目前的使用者可讀取。登入憑證會自動續期。接著在用戶端將 MoleSignal 新增為 stdio 伺服器，使用命令 `npx -y @molesignal/cli mcp`：

| 用戶端 | 設定 |
|---|---|
| Claude Code | `claude mcp add --scope user molesignal -- npx -y @molesignal/cli mcp` |
| Cursor | 在 `~/.cursor/mcp.json` 中寫入 `{"mcpServers": {"molesignal": {"command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` |
| Codex | `codex mcp add molesignal -- npx -y @molesignal/cli mcp` |
| VS Code | 在 `.vscode/mcp.json` 中寫入 `{"servers": {"molesignal": {"type": "stdio", "command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` |
| Gemini CLI | `gemini mcp add molesignal npx -y @molesignal/cli mcp` |

執行 `npx -y @molesignal/cli status`，檢查連線並查看工具數量。若無法使用瀏覽器，請略過登入，改在此伺服器的環境變數中設定 `MOLESIGNAL_URL` 與 `MOLESIGNAL_TOKEN`（API 權杖）。用 `npm install -g @molesignal/cli` 安裝後，可直接執行 `molesignal` 命令。完整命令清單請參閱 [MoleSignal 命令列工具](/zh-Hant/cli)。

**Mole Agent → 設定 → Inbound MCP** 中的 **設定提示詞** 會提供這些步驟，供 Agent 工具執行。請在提示詞上方選擇 **stdio** 或 **Streamable HTTP**。

## 使用 API 權杖連線

API 權杖適合非互動式用戶端與自動化作業。

<Tabs>
  <Tab title="個人 API 權杖">
    在 **身分與存取 → API 權杖** 中建立權杖。權杖使用目前使用者的主體身分與指派給該使用者的角色。透過用戶端的密鑰管理機制或環境變數傳送 `Authorization: Bearer <token>`。
  </Tab>
  <Tab title="服務帳號 API 權杖">
    在 **身分與存取 → 服務帳號** 中建立服務帳號。系統會自動產生繫結至該帳號的 API 權杖，且只顯示一次權杖原文。

    服務帳號是非互動式身分，無法登入網頁介面，也無法核准 OAuth 授權。透過用戶端的密鑰管理機制或環境變數傳送 `Authorization: Bearer <token>`。
  </Tab>
</Tabs>

請勿將 API 權杖提交到專案層級的 MCP 設定檔。Codex 與 Claude Code 的範例包含適用於非互動式情境的環境變數設定。

Inbound MCP 只接受個人 API 權杖、服務帳號 API 權杖與 OAuth 存取權杖。Intake 與 RUM 憑證無法存取此端點。MCP 資源、工具、執行歷程與稽核記錄一律不會傳回憑證原文。

## OAuth 探索與有效期限

MoleSignal 在下列位址發布 OAuth 中繼資料：

```text
https://molesignal.example.com/.well-known/oauth-protected-resource/api/v1/mcp
https://molesignal.example.com/.well-known/oauth-authorization-server
```

授權伺服器支援搭配 PKCE `S256` 的授權碼流程、RFC 8707 資源繫結、動態用戶端註冊、重新整理權杖輪替與權杖家族撤銷。存取權杖的有效期限為一小時。重新整理權杖需要 `offline_access` 範圍與 `refresh_token` 授權類型，有效期限為 30 天，且每次使用後都會輪替。

可在 **Mole Agent → 設定 → Inbound MCP** 中查看及撤銷有效的 OAuth 連線。連線清單下方的 **設定提示詞** 包含此部署的端點。選擇 **複製提示詞**，再貼到 Claude Code、Cursor 等 Agent 工具中，該工具就會將 MoleSignal 新增為 MCP 伺服器。

## 瞭解租用戶邊界

請勿在端點、自訂標頭或工具參數中傳送 `userId` 或 `orgId`。MoleSignal 根據驗證憑證判定這兩個身分識別值，在每次請求時重新載入最新的 IAM 快照，並將 MCP 工作階段繫結至初始化該工作階段時使用的憑證。

實際可用的工具集合如下：

```text
Inbound MCP surface ∩ 凭证 IAM 权限 ∩ workspace Tool Policy
```

Agent 設定檔不限制 Inbound MCP。此端點不會代理為 Mole Agent 設定的 Outbound MCP 伺服器及其遠端工具。

任何憑證都無法透過 Inbound MCP 讀取 [`_audit` 資料串流](/zh-Hant/settings/data-security#稽核資料流)的任何資料列或欄位。請在 **日誌** 中開啟該串流。

## 從工具配接器開始

`tools/list` 只列出少量已授權的功能：7 個常用的唯讀工具、核准與執行控制工具，以及 3 個漸進式探索配接器。

| 配接器 | 用途 |
|---|---|
| `tool_search` | 搜尋目前身分有權使用的完整 Inbound MCP 工具目錄。 |
| `call_read_tool` | 執行搜尋到的唯讀或預先檢查工具。 |
| `call_managed_tool` | 使用必填的 `idempotencyKey` 執行搜尋到的受控變更。 |

常見提示詞：

- 「搜尋 MoleSignal 中用於查詢近期事件的工具，摘要影響最大的未解決事件。」
- 「尋找狀態頁面工具並列出處理中的事件，不要執行任何變更。」
- 「先測試這項警示規則，完成必要的確認或核准後才更新。」

請參閱[工具目錄與執行模型](/zh-Hant/tools)，瞭解探索用的結構描述、風險等級、核准行為與支援的產品領域。

## 執行限制

| 限制 | 預設值 | 可設定範圍 |
|---|---:|---:|
| 請求大小 | 1 MB | 1–8 MB |
| 回應大小 | 1 MB | 1–8 MB |
| 每個憑證的同時 HTTP 呼叫數 | 8 | 1–128 |
| 每個憑證每分鐘的 HTTP 呼叫數 | 60 | 1–10,000 |
| 唯讀工具逾時 | 30 秒 | 100 ms–300 秒 |

在 **Mole Agent → 設定 → Inbound MCP** 中編輯這些值。組織工具政策可為個別工具設定更嚴格的逾時或回應大小限制。

## 瀏覽器 Origin 與 Host 檢查

非瀏覽器的 MCP 用戶端可以省略 `Origin` 標頭。瀏覽器請求必須來自同一來源，或與 Inbound MCP 設定中的 HTTP/HTTPS 來源完全相符。

部署在非回送位址時，請求的 `Host` 必須與 `http.external_url` 中的主機相符。這項檢查可防止針對本機 MCP 伺服器的 DNS 重新繫結攻擊。

## 疑難排解連線問題

| 現象 | 檢查項目 |
|---|---|
| `401 missing Authorization Bearer token` | 執行 `codex mcp login molesignal`，或設定支援的 API 權杖環境變數。 |
| 授權頁面要求重新登入 | 網頁介面、`http.external_url` 與 MCP 端點應使用相同的通訊協定與主機名稱，避免混用 `localhost` 和 `127.0.0.1`。 |
| `duplicate field resource` | 移除手動設定的 `--oauth-resource`，然後重新註冊端點。 |
| OAuth 回呼顯示連線遭拒 | 在瀏覽器重新導向至暫時的回送回呼位址之前，請保持 MCP 用戶端執行。如果用戶端已停止接聽，請重新執行 `codex mcp login`。 |
| MCP 端點傳回 `403` | 檢查服務是否啟用、瀏覽器來源、憑證狀態、IAM 權限與工具政策。 |
| 找不到特定工具 | 先用 `tool_search` 搜尋；若無結果，請檢查 Inbound MCP 的開放範圍、IAM 與工具政策。 |
