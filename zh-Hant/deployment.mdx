MoleSignal 以單一執行檔和單一容器映像檔交付。設定決定程序要執行哪些[角色](/zh-Hant/deployment/role-based)：單一程序可以執行所有角色，也可以將角色分配給多個程序。每個部署都需要兩項外部服務：PostgreSQL 與物件儲存。

## 先決條件

| 元件 | 要求 |
|---|---|
| PostgreSQL | 儲存中繼資料、身分、檔案目錄與產品資源。PostgreSQL 是唯一支援的中繼資料庫。Compose 沙箱與 Kubernetes 資訊清單使用 PostgreSQL 17。 |
| 物件儲存 | 儲存 Parquet 檔案、搜尋索引與 Profile 資料區塊。使用 `s3`（AWS S3，或 RustFS、Cloudflare R2、阿里雲 OSS 等相容於 S3 的服務）、`azure` 或 `gcs`。`local` 後端僅供單一節點與開發使用。 |
| 運算資源 | 容器映像檔支援 x86-64 與 arm64 架構的 Linux（`linux/amd64`、`linux/arm64`）。沙箱需要約 2 GB 的記憶體。 |
| 本機磁碟 | 只儲存可重建的快取。系統會先將預寫式日誌（WAL）物件寫入物件儲存，再確認寫入，因此所有節點都不需要持久性磁碟區。請參閱[持久性與接管](/zh-Hant/architecture#持久性與接管)。 |

記憶體與磁碟用量取決於擷取量、作用中的資料流數量，以及[設定](/zh-Hant/configuration)中的快取設定。請依實際用量規劃容量：[擷取用量](/zh-Hant/streams#資料擷取用量與預算)會顯示各來源的擷取量，程序也會透過 `/metrics` 提供 Prometheus 指標。請參閱[正式環境檢查清單](/zh-Hant/deployment/production-checklist)。

## 容器映像檔

映像檔發佈至 `ghcr.io/molesignal/molesignal`。每個版本都有一個版本標籤（例如 `26.1.0.0`）和一個發佈通道標籤（例如 `alpha`）。請在正式環境固定使用版本標籤。

```bash
docker pull ghcr.io/molesignal/molesignal:26.1.0.0
```

所有角色都使用同一個映像檔。執行階段變數 `RELEASE_CHANNEL`（`alpha`、`beta`、`rc` 或 `stable`）用來標示部署的成熟度，不會變更執行檔本身。網頁介面內嵌於執行檔，透過 HTTP 連接埠提供。

## 部署方式

<Tabs>
  <Tab title="Docker Compose">
    程式碼存放庫提供 `deploy/docker/docker-compose.yaml`，內含兩個 profile。兩者都會啟動 PostgreSQL 17 與 RustFS，並執行 `ghcr.io/molesignal/molesignal` 的 MoleSignal 映像檔。

    ```bash
    # 所有角色在一个进程内：提供完整产品
    docker compose -f deploy/docker/docker-compose.yaml --profile standalone up

    # 每个角色一个容器
    docker compose -f deploy/docker/docker-compose.yaml --profile multirole up
    ```

    `multirole` profile 為每個角色部署一個容器。router 在 `5080` 提供網頁介面與 HTTP API，並在 `4317` 提供 OTLP gRPC 接收端。請參閱[依角色部署](/zh-Hant/deployment/role-based)。

    standalone 服務會公開連接埠 `5080` 與 `5082`，但不公開 OTLP gRPC 連接埠 `4317`。若要從主機傳送 OTLP gRPC，請為此服務新增 `4317:4317` 對應。

    Compose 檔案僅供沙箱使用：它使用預設認證資訊、開發用加密金鑰，以及 `multirole` profile 專用的開發用 `MS_SELF_TELEMETRY_CLUSTER_TOKEN`。儲存實際資料前，請務必更換這些值。請參閱[正式環境檢查清單](/zh-Hant/deployment/production-checklist)。沙箱的儲存桶為私有。

  </Tab>
  <Tab title="執行檔與 systemd">
    安裝已發佈的執行檔、設定檔和 GeoIP 資料庫，再將 MoleSignal 當作 systemd 服務執行。

    ```bash
    sudo useradd --system --home-dir /var/lib/molesignal \
      --shell /usr/sbin/nologin molesignal
    sudo install -Dm755 bin/molesignal /usr/local/bin/molesignal
    sudo install -d -o root -g molesignal -m 0750 /etc/molesignal
    sudo install -o root -g molesignal -m 0640 \
      conf/config.toml /etc/molesignal/config.toml
    sudo install -Dm644 deploy/systemd/molesignal.service \
      /etc/systemd/system/molesignal.service
    sudo install -Dm644 mmdb/dbip-city-lite.mmdb \
      /usr/share/molesignal/mmdb/dbip-city-lite.mmdb
    ```

    在 `/etc/molesignal/molesignal.env` 中設定執行階段的發佈通道：

    ```ini
    RELEASE_CHANNEL=alpha
    ```

    依環境調整 `/etc/molesignal/config.toml` 中的 PostgreSQL、物件儲存與金鑰設定，再啟動服務：

    ```bash
    sudo systemctl daemon-reload
    sudo systemctl enable --now molesignal
    sudo systemctl status molesignal
    ```

    此 systemd 單元使用 `/var/lib/molesignal` 作為狀態目錄，並授予 `CAP_NET_BIND_SERVICE`，讓內建 TLS 接聽程式可以繫結至 `80` 與 `443` 連接埠。
  </Tab>
  <Tab title="Helm">
    官方 Chart 可在 Kubernetes 1.27 以上版本部署 MoleSignal，需要 Helm 3.8 以上版本與 MoleSignal 26.2.0.0 以上版本。Chart 存放庫位於 `https://charts.molesignal.com`，同一個 Chart 也發佈至 `oci://ghcr.io/molesignal/charts/molesignal`。

    預設情況下，Chart 會執行一個負責所有角色的程序，外加各一個 PostgreSQL 17 與 RustFS 執行個體。這兩項服務不提供備份或容錯移轉，因此預設設定僅供試用。

    ```bash
    helm repo add molesignal https://charts.molesignal.com
    helm repo update
    helm install molesignal molesignal/molesignal --namespace molesignal --create-namespace
    ```

    透過連接埠轉送開啟網頁介面，再造訪 `http://127.0.0.1:5080`：

    ```bash
    kubectl --namespace molesignal port-forward svc/molesignal 5080:5080
    ```

    在正式環境中，請將各角色拆成獨立的工作負載，停用內建服務，並讓 Chart 使用外部 PostgreSQL 與物件儲存。先建立兩個 Secret：`molesignal-db` 包含鍵 `database-dsn`，`molesignal-s3` 包含 `access-key` 和 `secret-key`。

    ```yaml
    mode: distributed

    postgresql:
      enabled: false
    externalDatabase:
      existingSecret: molesignal-db

    rustfs:
      enabled: false
    objectStore:
      bucket: example-telemetry
      region: eu-west-1
      existingSecret: molesignal-s3
    ```

    [`examples/production.yaml`](https://github.com/molesignal/molesignal-helm/blob/main/examples/production.yaml) 也加入了 TLS、自動調整規模和中斷預算。所有設定項目請參閱 [Chart README](https://github.com/molesignal/molesignal-helm/tree/main/charts/molesignal)。

    | 主題 | 說明 |
    |---|---|
    | 加密金鑰 | Chart 在首次安裝時產生此金鑰，升級或執行 `helm uninstall` 時都會保留。請務必備份：沒有金鑰就無法讀取加密欄位。使用 Argo CD 等透過 `helm template` 產生資訊清單的工具時，請設定 `secrets.cipherKey` 和 `secrets.clusterToken`，或將 `secrets.existingSecret` 指向一個 Secret。 |
    | 映像檔 | 除 PostgreSQL 外，所有映像檔都使用 `latest`，每次啟動 Pod 時都會拉取映像檔。在正式環境中，請固定 `image.tag`，並將 `image.pullPolicy` 設為 `IfNotPresent`。 |
    | Ingress | 設定 `ingress.enabled`。在 Ingress 後方執行時，請在[用戶端 IP 辨識](/zh-Hant/settings/platform#用戶端-ip-識別)中，將控制器 Pod 所在的網段列為受信任的 Proxy。 |
    | 應用程式設定 | 在 `config` 下填寫設定，結構與 `conf/config.toml` 相同。 |

    讀取預設安裝的加密金鑰：

    ```bash
    kubectl --namespace molesignal get secret molesignal-secret -o jsonpath='{.data.cipher-key}' | base64 --decode
    ```
  </Tab>
  <Tab title="Kubernetes 資訊清單">
    [`deploy/k8s/`](https://github.com/molesignal/molesignal/tree/main/deploy/k8s) 中的資訊清單讓所有角色共用同一個映像檔，並引用預留用的映像檔 `molesignal:dev`。請在每個工作負載中將此映像檔替換為 `ghcr.io/molesignal/molesignal:<version>`。

    資訊清單不包含 PostgreSQL 與物件儲存：請以 `postgresql` 為服務名稱提供 PostgreSQL 17（或修改 ConfigMap 中的 `meta_database.dsn`），並提供任一相容於 S3 的物件儲存（修改 ConfigMap 中的 `object_store`）。

    這些資訊清單會依角色部署：`router` 工作負載提供網頁介面與 HTTP API，其餘工作負載執行資料角色與背景角色。若要改用單一程序執行所有角色，請以 `40-intake.yaml`（不含持久性磁碟區的 Deployment）為起點，將 `MS_NODE_ROLES` 設為 `["standalone"]`，為 Service 新增 `5080` 連接埠，並使用 `/api/v1/healthz` 作為探查端點。

    | 工作負載 | 類型 | 複本數 | 角色 |
    |---|---|---|---|
    | `router` | Deployment | 2 | `router`：網頁介面、HTTP API 與 OTLP gRPC |
    | `intake` | Deployment | 2 | `intake`，不需要持久性磁碟區；輪替更新會先啟動新 Pod，再停止舊 Pod |
    | `querier` | Deployment | 2 | `querier` |
    | `compactor` | Deployment | 1 | `compactor`，可增加複本 |
    | `alert` | Deployment | 1 | `alert`，可增加複本 |

    不同角色的節點互相轉送候選追蹤與自身遙測資料時，會使用共用的 `MS_SELF_TELEMETRY_CLUSTER_TOKEN` 進行驗證。追蹤擷取預設開啟，因此每個工作負載都會從 `molesignal-secret` 的 `self_telemetry_cluster_token` 讀取相同的值。建立命名空間、設定與金鑰，再套用各工作負載：

    ```bash
    kubectl apply -f 00-namespace.yaml
    kubectl apply -f 10-configmap.yaml
    kubectl create secret generic molesignal-secret -n molesignal \
      --from-literal=object_store_access_key="<access-key>" \
      --from-literal=object_store_secret_key="<secret-key>" \
      --from-literal=cipher_key="$(openssl rand -base64 32)" \
      --from-literal=self_telemetry_cluster_token="$(openssl rand -base64 32)" \
      --dry-run=client -o yaml | kubectl apply -f -
    kubectl apply -f 30-router.yaml -f 40-intake.yaml -f 50-querier.yaml \
                  -f 60-compactor.yaml -f 70-alert.yaml
    ```

    工作負載透過環境變數 `MS_NODE_ROLES` 選擇角色。透過 router 檢查叢集：

    ```bash
    kubectl -n molesignal port-forward svc/router 5080:5080
    curl http://127.0.0.1:5080/api/v1/healthz
    ```

    網頁介面內嵌於執行檔，只要透過 Ingress 或負載平衡器對外開放 `router` 工作負載的 `5080` 連接埠即可。

    `router` 工作負載在 `5080` 提供完整 API，其就緒探查會傳送 `GET /api/v1/healthz`。其餘工作負載都在 `5080` 提供健康狀態、就緒狀態與指標端點，並使用 `GET /api/v1/readyz` 進行就緒探查。`intake` Pod 一就緒即可接收寫入：啟動時不重播任何資料，其他 intake Pod 會接管遺失的 Pod 的 WAL。`intake` Pod 的終止寬限期為 45 秒，可在停止前將緩衝資料寫入 WAL 並釋放 WAL。
  </Tab>
</Tabs>

## Probe Agent

Probe Agent 從私有網路、區域或邊緣位置執行合成監控，只會向 `standalone` 或 `alert` 節點的 `5084` 與 `5085` 連接埠發起連出連線。Probe Agent 使用專屬的映像檔 `ghcr.io/molesignal/probe-agent`，版本標籤與 MoleSignal 映像檔相同。

| 執行環境 | 安裝方式 | 身分儲存位置 |
|---|---|---|
| Kubernetes | Helm Chart `probe-agent`，來自 `https://charts.molesignal.com` 或 `oci://ghcr.io/molesignal/charts/probe-agent` | 每個複本使用一個持久性磁碟區 |
| Docker | 映像檔 `ghcr.io/molesignal/probe-agent` | 掛載至 `/var/lib/molesignal-probe` 的磁碟區 |
| Linux | 已發佈的 `probe-agent` 執行檔 | `--state-dir` 指定的目錄 |

Chart 的安裝步驟請參閱[在 Kubernetes 上執行 Agent](/zh-Hant/synthetics#在-kubernetes-上執行-agent)，註冊流程與伺服器端設定請參閱[位置與 Probe Agent](/zh-Hant/synthetics#地點與-probe-agent)。

## 連接埠

| 連接埠 | 用途 | 開放範圍 |
|---|---|---|
| `5080` | 網頁介面、HTTP API、`/metrics` 與健康檢查端點。除 `router` 與 `standalone` 外，其他角色只提供健康狀態、就緒狀態與指標。 | `router` 與 `standalone` 透過 TLS 對外開放，其他角色維持私有。 |
| `4317` | OTLP gRPC 接收端。使用明文 gRPC，不含 TLS。 | 僅在終止 TLS 的 Proxy 後方或受信任的網路內開放。 |
| `5082` | 節點間的內部 gRPC：寫入轉送、查詢轉送與掃描分片 | 私有，切勿對外開放。 |
| `5083` | 供資料庫用戶端使用的 Arrow Flight SQL，預設停用。 | 可選，透過 TLS 提供。 |
| `5084`、`5085` | 供在私有節點執行合成監控的 Probe Agent 註冊與控制使用 | 僅在 Probe Agent 於節點外執行時需要。 |
| `80`、`443` | `[http.tls].enabled` 設為 `true` 時啟用的內建 TLS 接聽程式，支援自動佈建憑證 | 對外開放。 |

## 健康檢查與指標

- `GET /api/v1/healthz` 是公開端點。服務正常時回傳 `200` 與 `{"status":"ok"}`；無法連線至物件儲存時回傳 `503`，並附上 `reason`。容器與負載平衡器的健康探查會使用此端點。
- `GET /metrics` 是公開端點，會回傳 Prometheus 指標。請在 Proxy 或網路層限制存取。
- 在 `standalone` 或 `router` 節點上，`GET /api/v1/readyz` 與 `GET /api/v1/version` 需要 Bearer Token。`version` 會回傳版本、commit、建置 ID、發佈通道與版本類型。
- 在依角色部署的叢集中，不提供完整 API 的節點會在同一個連接埠回應 `GET /api/v1/healthz`、`GET /api/v1/readyz` 與 `GET /metrics`，不需驗證。

如需指標與服務內建遙測的詳細資訊，請參閱[自身可觀測性](/zh-Hant/self-observability)。
