跨訊號關聯讓一個問題能在不同訊號之間連貫地追查下去：從一個慢速頁面到它的後端追蹤，從追蹤到它的日誌，從指標尖峰到背後的請求。每次跳轉都會保留時間範圍，並帶上 `trace_id`、服務或主機等識別資訊，無需手動複製。跳轉依賴穩定的欄位，接入時請保留 `service.name`、`deployment.environment`、`trace_id` 和 `host.name`。

## 跳轉入口在哪裡

| 起點 | 操作 | 到達 |
|---|---|---|
| 一筆日誌事件 | 事件帶有 Trace ID 時的 **呼叫鏈** 檢視。 | 追蹤瀑布圖，並選取該事件所在的 Span。參見[日誌](/zh-Hant/logs#閱讀結果)。 |
| 一筆追蹤 | 追蹤頁首的 **相關日誌**、**服務指標** 和 **Profiles**。 | 帶有該 `trace_id` 的日誌、相關服務的指標，以及該時間範圍的 Profile。參見[追蹤](/zh-Hant/traces#檢查單筆-trace)。 |
| 一個 Span | Span 的 **日誌**、**指標** 和 **Profile** 分頁。 | 該 Span 的日誌資料列和指標。 |
| 帶有瀏覽器工作階段的追蹤 | 追蹤頁首的 **使用者工作階段**。 | 發出該請求的使用者體驗工作階段。 |
| 一個使用者體驗工作階段 | **關聯追蹤**。 | 工作階段中各請求對應的後端追蹤。參見 [RUM 探索](/zh-Hant/rum/explorer)。 |
| 指標上的一個資料點 | Exemplar 菱形標記，再點選 **檢視 Trace**。 | 該資料點背後的追蹤。參見[指標](/zh-Hant/metrics#閱讀圖表)。 |
| 一個應用程式效能服務 | 服務頁面上的連結。 | 該服務的追蹤、日誌和使用者體驗工作階段。參見[應用程式效能](/zh-Hant/apm)。 |
| 一個告警事件 | **開啟觸發查詢**、**相關日誌**、**相關指標** 和 **在 RUM 中開啟**。 | 觸發事件的查詢，以及事件前後的內容脈絡。參見[告警事件](/zh-Hant/alerting/incidents#事件詳情)。 |
| 一個 Profile | Profile 關聯的追蹤。 | 收集該 Profile 期間執行的追蹤。參見 [Profiles](/zh-Hant/profiles)。 |
| 一個 APM 執行個體 | **執行個體** 表格的 **工作負載 / 主機** 儲存格。 | 它執行所在的 Pod 或主機，以及該處的其他服務。參見[基礎設施](/zh-Hant/infrastructure)。 |
| 一個 Pod、節點或主機 | **日誌**、**指標** 和其上的服務。 | 它最近一小時的日誌和指標，以及每個服務的 APM 頁面。 |

## 跳轉後什麼也沒找到

跳轉後什麼也沒找到，可能是資料無法關聯，而不是沒有資料：日誌未帶 TraceID，日誌裡的服務名稱和 APM 不一致，或者 Span 沒有回報服務的執行位置。[APM 服務目錄](/zh-Hant/apm)的**關聯度**欄和[收集品質](/zh-Hant/apm/settings#收集品質)會列出每個服務與日誌、指標、Trace 和變更的關聯情況。

## 調查內容脈絡列

調查進行期間，頂端列下方會出現一個內容脈絡列，顯示調查堆疊中的框架數、鎖定的時間範圍、Trace ID 等關鍵訊號，以及在頁面間隨行的篩選條件。

| 控制項 | 效果 |
|---|---|
| **返回調查工作台** | 返回調查堆疊。 |
| **返回追蹤詳細資料** | 返回開啟目前頁面的那筆追蹤。 |
| 移除篩選器 | 移除一個隨行的篩選條件。 |
| **清除** | 結束調查並清空內容脈絡列。 |

## 介面中的調查堆疊

調查堆疊會保存一次下鑽的路徑：每次跳轉都會壓入一個框架，`⌘[` 和 `⌘]` 可在其中後退和前進。調查堆疊最多保存 6 個框架；超出時會捨棄最早的未釘住框架，釘住的框架會保留。`⌘⌥T` 和 `⌘⌥L` 分別以追蹤或日誌搜尋開始一個調查堆疊，[命令面板](/zh-Hant/console#使用命令面板搜尋)可以在新的調查堆疊中開啟結果，或將結果疊加到目前調查堆疊頂端。

`⌘⌥Y` 會複製目前頁面的網址，其中帶有時間範圍和篩選條件。開啟複製的連結時，其中每個資源仍需通過正常的權限檢查。

## 關聯 API

各頁面用已經持有的識別資訊建構跳轉，下列端點提供跳轉背後的檢視：

| 端點 | 用途 |
|---|---|
| `GET /api/v1/web/trace/{trace_id}` | 包含全部 Span 的完整追蹤。 |
| `GET /api/v1/web/topology` | 服務拓撲。 |
| `GET /api/v1/traces/service_graph` | 由追蹤得出的服務圖及 RED 指標。 |
| `GET /api/v1/entities/detail` | 一個 Pod、節點、主機或容器上執行著什麼，以及它執行在哪裡。參見[基礎設施](/zh-Hant/infrastructure)。 |
| `POST /api/v1/web/investigation/blob` | 將調查狀態儲存為 7 天後過期的 Blob。 |
