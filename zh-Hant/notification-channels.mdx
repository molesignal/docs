MoleSignal 分開管理服務供應商憑證、收件者和路由規則。連接器只需設定一次，再將使用者身分或備援目標繫結至連接器，並透過通知策略決定何時使用這些路由。

| 資源 | 用途 |
|---|---|
| **連接器** | 儲存組織層級的服務供應商憑證和傳輸設定。 |
| **使用者通知** | 繫結各平台的身分，並設定個人傳送端點的順序。 |
| **通知策略** | 比對事件、解析收件者、選擇範本並控制升級。 |
| **通知範本** | 可重複使用的訊息正文，依管道分類：通用範本適用於所有管道，也可以為簡訊和電話等管道各自撰寫範本。 |
| **備援路由** | 定義個人傳送失敗後依序使用的團隊和組織目標。 |
| **傳送記錄** | 查看傳送嘗試、耗時、錯誤、重試、確認與升級。 |

| Amazon SNS（`aws_sns`） | 區域、驗證方式、主題 ARN、訊息內容、逾時 | 任意目標，所有訊息都會傳送至此主題 |
| 通用 Webhook（`webhook`） | 預設網址、HTTP 方法、請求標頭、逾時 | 使用者、地址、群組或依目標指定的 Webhook 網址 |

所有連接器的逾時時間必須介於 1 到 60 秒之間。URL 必須是 `http` 或 `https` 的絕對網址。

選擇連接器類型時，畫面會依管道分組顯示：**即時通訊**、**電話**、**簡訊**（含 WhatsApp）、**電子郵件**和**整合**。PagerDuty、Amazon SNS 和 Webhook 都在**整合**中。

連接器會以唯讀方式顯示服務供應商的網址，可複製但無法修改。阿里雲、騰訊雲和 AWS（包括 Amazon SNS）的 API 基礎網址取決於所選區域，PagerDuty 的網址取決於所選服務區域，飛書 App 和 Slack App 的網址取決於所選平台，Teams 機器人的服務網址則取決於所選雲端環境。其餘連接器使用服務供應商的固定網址，例如企業微信智慧機器人的持續連線網址，以及電子郵件使用 Microsoft 365 登入時的登入網址。華為雲是例外：存取網址因應用程式而異，只能從管理主控台複製，無法透過 API 查詢，因此請手動填寫。儲存、測試和直接傳送前，MoleSignal 會依服務供應商的網址清單檢查這些網址，拒絕透過 API 寫入的其他網址，不會將憑證傳送到其他地方。已儲存的連接器無法變更類型。

請手動填寫 Mattermost 機器人和 Matrix 機器人的伺服器位址，方式與 Webhook 網址相同。MoleSignal 只會連線至該網域名稱解析出的位址，拒絕連線至雲端中繼資料位址，也不會跟隨重新導向。

## 建立並測試連接器

檢視連接器需要 `notify.connectors.read`；建立、編輯、測試、啟用、停用或刪除連接器需要 `notify.connectors.manage`。

<Steps>
  <Step title="開啟通知設定">
    前往**設定 → 通知 → 連接器**。
  </Step>
  <Step title="選擇服務供應商">
    點選**新增連接器**，輸入不重複的名稱，並選擇連接器類型。建立連接器後，無法變更類型。
  </Step>
  <Step title="填寫服務設定">
    依照下方說明填寫憑證和傳輸參數。除非要稍後再啟用，否則請保持**允許此連接器傳送訊息**開啟。
  </Step>
  <Step title="儲存連接器">
    點選**儲存連接器**。MoleSignal 會加密儲存完整設定，並在 API 回應中將敏感值替換為 `***`。
  </Step>
  <Step title="傳送測試訊息">
    編輯已儲存的連接器，選擇相容的目標類型，輸入實際目標，再點選**測試連線**。MoleSignal 會根據最近一次測試結果，將連接器狀態更新為**已連線**或**異常**。
  </Step>
</Steps>

<Note>
  請先儲存新連接器，再進行測試。編輯連接器時，請勿變更用來遮蔽金鑰的 `***`，系統會保留原有金鑰。
</Note>

## 設定各服務供應商

### Email SMTP

填寫 SMTP 主機、連接埠和有效的**寄件者地址**，再在**驗證方式**中選擇登入方式：

| 驗證方式 | 填寫內容 |
|---|---|
| **使用者名稱和密碼** | 伺服器要求時填寫**使用者名稱**，再填寫**密碼**。如果郵件服務供應商要求使用授權碼或應用程式專用密碼，請在密碼欄位填入供應商提供的授權碼或密碼。 |
| **Microsoft 365（OAuth 2.0）** | 填寫在 Microsoft Entra ID 註冊的應用程式的**租用戶 ID**、**Client ID** 和 **Client Secret**；**使用者名稱**填寫寄信用的電子郵件地址。請參閱 [Microsoft 365](#microsoft-365)。 |
| **Google Workspace（OAuth 2.0）** | 填寫已啟用全網域委派的服務帳號的**服務帳號金鑰（JSON）**；**使用者名稱**填寫寄信用的電子郵件地址。請參閱 [Google Workspace](#google-workspace)。 |

兩種 OAuth 2.0 方式都使用 Access Token（SASL XOAUTH2）登入，不需要密碼。即使服務供應商停用密碼登入，仍可寄信：Microsoft 自 2026 年底起會預設停用現有 Exchange Online 租用戶的 SMTP AUTH 基本驗證（Basic authentication）。MoleSignal 會重複使用 Token，直到到期前一分鐘。如果傳送失敗，下次會重新登入。

依郵件伺服器選擇 TLS 模式：

| TLS 模式 | 適用情境 |
|---|---|
| `none` | SMTP 連線不使用 TLS。請勿在不受信任的網路上使用。 |
| `starttls` | 先建立連線，再透過 STARTTLS 升級為 TLS；常用連接埠為 `587`。 |
| `tls` | 從建立連線起就使用 TLS；常用連接埠為 `465`。 |

測試時，選擇 `fixed_address` 或 `direct_user`，並輸入 `oncall@example.com` 這類有效的電子郵件地址。

#### Microsoft 365

MoleSignal 以在 Microsoft Entra ID 註冊的應用程式身分登入，並透過一個信箱寄信。僅支援全球版 Microsoft 365：**登入網址**固定為 `https://login.microsoftonline.com`。

<Steps>
  <Step title="註冊應用程式">
    在 Microsoft Entra ID 註冊應用程式。在 **API 權限**中新增 **Office 365 Exchange Online** 的應用程式權限 `SMTP.SendAsApp`，並授與管理員同意；在**憑證和祕密**中新增用戶端密碼。租用戶 ID 和 Client ID 位於應用程式的**概觀**頁面。
  </Step>
  <Step title="在 Exchange Online 註冊應用程式">
    Exchange 管理員使用 `Connect-ExchangeOnline` 連線至 Exchange Online PowerShell，為應用程式註冊服務主體。`<对象 ID>` 是應用程式在 Microsoft Entra ID **企業應用程式**中的物件 ID，不是應用程式註冊的物件 ID：

    ```powershell
    New-ServicePrincipal -AppId <应用 ID> -ObjectId <对象 ID>
    ```
  </Step>
  <Step title="授與信箱權限">
    允許服務主體存取寄信用的信箱：

    ```powershell
    Add-MailboxPermission -Identity <邮箱> -User <服务主体> -AccessRights FullAccess
    ```
  </Step>
  <Step title="為信箱啟用 SMTP AUTH">
    為信箱啟用 SMTP AUTH，例如：

    ```powershell
    Set-CASMailbox -Identity <邮箱> -SmtpClientAuthenticationDisabled $false
    ```
  </Step>
  <Step title="填寫連接器設定">
    主機填寫 `smtp.office365.com`，連接埠填寫 `587`，TLS 模式選擇 `starttls`。驗證方式選擇 **Microsoft 365（OAuth 2.0）**，填寫租用戶 ID、Client ID 和 Client Secret，並在**使用者名稱**和**寄件者地址**中填入相同的電子郵件地址。
  </Step>
</Steps>

#### Google Workspace

MoleSignal 以服務帳號的身分登入，透過全網域委派代表網域內的一個信箱寄信。

<Steps>
  <Step title="建立服務帳號">
    在 Google Cloud 專案中建立服務帳號，並為該帳號建立 JSON 金鑰。在服務帳號的詳細資料頁面記下數字用戶端 ID。
  </Step>
  <Step title="授權 Gmail 範圍">
    由超級管理員在 Google 管理控制台開啟**安全性 → 存取權與資料控管 → API 控制項 → 全網域委派**，新增該用戶端 ID，並將授權範圍設為 `https://mail.google.com/`。授權最多需要 24 小時才會生效。
  </Step>
  <Step title="填寫連接器設定">
    主機填寫 `smtp.gmail.com`，連接埠 `587` 搭配 TLS 模式 `starttls`，或連接埠 `465` 搭配 `tls`。驗證方式選擇 **Google Workspace（OAuth 2.0）**，將金鑰貼到**服務帳號金鑰（JSON）**。**使用者名稱**和**寄件者地址**都填寫服務帳號代為寄信的電子郵件地址，該地址須屬於同一網域的使用者。
  </Step>
</Steps>

金鑰中的 `token_uri` 只能使用 Google 的 Token 交換網址，與 [Google Chat App](#google-chat-app) 相同。

### Slack App

建立可呼叫 `chat.postMessage` 的 Slack App 和 Bot Token，並將機器人加入需要接收通知的頻道。填寫下列欄位：

- **Bot Token** —— 通常以 `xoxb-` 開頭；
- **App-Level Token** —— 選填。使用以 `xapp-` 開頭、具有 `connections:write` 範圍的權杖。填寫後，Mole Agent 可透過 Socket Mode 在 Slack 中回答。請參閱[在 IM 中使用 Mole Agent](/zh-Hant/im)；
- **平台** —— Slack 或 GovSlack（美國政府專用的 Slack）。選擇 GovSlack 時，API 和狀態頁均透過 `slack-gov.com` 授權；
- **Client ID** 與 **Client Secret** —— 請在 Slack App 的 **Basic Information** 查看。這兩個欄位可讓狀態頁訪客將頁面新增到所屬的 Slack 頻道。請參閱[狀態頁](/zh-Hant/status-pages#slack)；
- **逾時** —— 1 到 60 秒。

連接器至少需要 Bot Token，或同時填寫 Client ID 和 Client Secret。也可以三項都填。傳送通知需要 Bot Token。Client Secret 和 Bot Token 都會隨連接器加密儲存，API 不會傳回明文。

`direct_user` 目標填寫 Slack 成員 ID，`fixed_group` 目標填寫頻道 ID。目標不得包含空格；`#alerts` 這類顯示名稱不是頻道 ID。

在 **Mole Agent → 設定 → IM 整合**中啟用這個連接器後，透過此連接器傳送的警示通知會附上確認和解決按鈕。請參閱[警示卡片](/zh-Hant/im#告警卡片)。

### Slack Webhook

在 Slack 建立 Incoming Webhook，並將網址填入 **Webhook 網址**。`fixed_group` 目標使用連接器設定的網址；`webhook` 目標會以目標值取代本次傳送使用的網址。

MoleSignal 會傳送含有 `text` 欄位的 JSON。收到非 2xx 回應時，MoleSignal 會將本次傳送標記為失敗。

### 飛書 App

建立可取得 tenant access token 並傳送訊息的企業自建應用程式，填寫 **App ID** 和 **App Secret**。在**平台**中選擇飛書或 Lark，系統會據此決定 API 基礎網址。

選取的收件者 ID 類型僅適用於 `direct_user`：

| 目標類型 | 目標值 |
|---|---|
| `direct_user` | 依**收件者 ID 類型**填寫 `open_id`、`user_id`、`union_id` 或電子郵件地址 |
| `fixed_address` | 電子郵件地址；MoleSignal 使用 `receive_id_type=email` 傳送 |
| `fixed_group` | 飛書群組聊天 ID；MoleSignal 使用 `receive_id_type=chat_id` 傳送 |

### 電話與簡訊號碼

電話與簡訊連接器會傳送通知給一個號碼：成員綁定的手機號碼（`direct_user`），或備援路由中的固定號碼（`fixed_address`）。號碼以 `+` 和國碼開頭，例如 `+8613800138000`。系統會移除空格和連字號。阿里雲、騰訊雲、華為雲和通用 HTTP 簡訊連接器也支援 11 碼的中國大陸手機號碼。

電話先朗讀通知標題，再朗讀本文，最多 400 字。簡訊的標題和本文各佔一行，最多 320 字。如果通知策略為電話或簡訊管道選取範本，系統只朗讀或傳送範本本文，不附標題。阿里雲、騰訊雲和華為雲僅使用通過審核的範本。請在通知範本中填寫範本編號和變數，詳見[通知範本中的服務供應商範本](#通知範本中的服務供應商範本)。

服務供應商會限制同一號碼接聽電話和接收簡訊的頻率。如果因超出限制、號碼錯誤或範本未通過審核而遭拒，本次傳送就會失敗，通知策略會接著嘗試同一成員的下一個通知方式和備援路由。服務供應商不會回報電話是否接通或是否有人聽完。傳送成功僅表示服務供應商已受理該通電話或該則簡訊。

同一連接器每分鐘只會撥打同一號碼一次。一分鐘內新增的通知會在同一線路上排隊，傳送記錄會顯示**排隊等待合併**。一分鐘後，系統會合併成一通電話，依序朗讀各則通知的標題（若套用電話範本，則朗讀範本本文），並略過排隊期間已確認的通知。阿里雲、騰訊雲和華為雲會朗讀第一則通知使用的範本，並依序將各則通知的值填入各變數。阿里雲原本就限制同一號碼每分鐘只能接到一通電話，合併後便不會因警示過於密集而遭拒。如果通知策略設定了較長的[合併通知](#合併通知)時段，系統會依設定的時段合併。

### 阿里雲語音通知

使用阿里雲語音服務的語音通知，僅能撥打中國大陸號碼。先在語音服務控制台完成企業資格審核，申請**文字轉語音**的語音通知範本，例如 `您好，${content}，请尽快处理。`，再為一個 RAM 使用者建立僅可呼叫語音服務的 AccessKey。填寫下列欄位：

- **AccessKey ID** 與 **AccessKey Secret**；
- **區域** —— 從阿里雲列出的區域中選取，系統會據此決定 API 基礎網址；
- **來電顯示號碼** —— 留空表示使用公用模式。填入在專屬模式購買的號碼後，來電會顯示這個固定號碼，值班人員可將號碼儲存為聯絡人。範本須使用相同的模式；
- **播放次數** —— 1 到 3 次。

在電話管道的通知範本中填寫範本編號（以 `TTS_` 開頭）和變數，再於通知策略中為電話管道選取該範本。請參閱[通知範本中的服務供應商範本](#通知範本中的服務供應商範本)。阿里雲對同一號碼每分鐘最多撥打 1 次、每小時 5 次、每天 20 次。超出限制的通話會遭拒。請勿在變數中放入網址或 IP 位址。

### 阿里雲簡訊

在簡訊服務控制台申請**簡訊簽名**和**通知類**範本，例如 `${content}，请尽快处理。`，再填寫 AccessKey、**區域**和**簡訊簽名**。從阿里雲列出的區域中選取。部分海外區域有專用的存取位址，系統會依區域決定 API 基礎網址。在簡訊管道的通知範本中填寫範本編號（以 `SMS_` 開頭）和變數，再於通知策略中為簡訊管道選取該範本。請參閱[通知範本中的服務供應商範本](#通知範本中的服務供應商範本)。

通知類範本的每個變數預設最多 35 字。企業使用者向阿里雲申請放寬限制後，可在通知範本中調高**每個變數的字數上限**。變數不得包含網址或 IP 位址。號碼可以是中國大陸手機號碼或國際號碼。

### 騰訊雲語音訊息

在語音訊息控制台建立應用程式（取得 `VoiceSdkAppid`），申請語音通知範本，再為子使用者建立 API 金鑰。填寫 **SecretId**、**SecretKey**、**區域**（使用這組金鑰向騰訊雲查詢，系統會依區域決定 API 基礎網址）、**應用程式 ID（SdkAppId）** 和**播放次數**（1 到 3 次）。在電話管道的通知範本中填寫範本 ID 和變數，並依變數的位置填寫 `1`、`2`、`3`。請參閱[通知範本中的服務供應商範本](#通知範本中的服務供應商範本)。

語音服務採預付制。方案額度用完後就無法撥出電話，傳送會失敗，傳送記錄會顯示 `InsufficientBalanceInVoicePackage`。這時通知策略會接著嘗試同一成員的下一個通知方式，因此請勿只設定電話通知。產生的語音內容最多 350 字。服務文件未載明單一變數的上限，超出上限時會遭拒（`ContentLengthLimit`）。系統預設將變數截斷為 20 字，如需放寬限制，請在通知範本中設定。

### 騰訊雲簡訊

在簡訊控制台建立應用程式（取得 `SmsSdkAppId`），申請簽名和範本，再填寫 **SecretId**、**SecretKey**、**區域**、**應用程式 ID（SdkAppId）** 和**簡訊簽名**（填寫簽名文字，而非編號；中國大陸簡訊必填）。在簡訊管道的通知範本中填寫範本 ID 和變數，並依變數的位置填寫 `1`、`2`、`3`。

<Warning>
  2024 年 1 月 25 日後啟用的帳號和長期未使用的帳號，單一變數預設最多 **6 個字元**，超出上限時會遭拒（`TemplateParameterLengthLimit`）。系統預設會將變數截斷為 6 個字元，通常不足以容納警示標題。向騰訊雲申請放寬限制後，請將上限填入通知範本的**每個變數的字數上限**。變數不得包含網址。
</Warning>

API 回報整體成功，不代表已向指定號碼傳送簡訊。請查看該號碼的結果。如果結果不是 `Ok`，本次傳送即告失敗，傳送記錄會列出原因。

### 華為雲語音通知

在語音通話控制台建立應用程式、訂購市話號碼並提交語音範本。填寫下列欄位：

- **AppKey**、**AppSecret** 和 **APP 存取位址** —— 皆可在「應用程式管理」中查看。請原樣複製存取位址，無法透過 API 查詢；
- **來電顯示號碼** —— 填寫訂購的市話號碼，格式為國碼加區碼加號碼。

在電話管道的通知範本中填寫範本 ID 和變數，並依變數的位置填寫 `1`、`2`、`3`。每個變數最多 32 個位元組，一個中文字佔 3 個位元組。系統會截斷超出長度的值，並移除變數中的 `$`、`{`、`}`。

### 華為雲簡訊

在訊息與簡訊控制台建立應用程式，申請簽名和範本。填寫 **AppKey**、**AppSecret**、**APP 存取位址**（皆可在「應用程式管理」中查看）和**通道號碼**（填寫簽名對應的通道號碼）。通用範本還須填寫**簽名名稱**。在簡訊管道的通知範本中填寫範本 ID 和變數，並依變數的位置填寫 `1`、`2`、`3`。每個變數的上限會標在範本中（例如 `TXT_20`）。系統預設會將變數截斷為 20 字，如需其他上限，請在通知範本中設定。

### Twilio 電話

在 Twilio 控制台找到 **Account SID** 和 **Auth Token**，再填寫：

- **來電號碼** —— 帳號中可撥打電話的號碼，例如 `+14155550100`；
- **語言** —— 朗讀通知的語言，例如 `en-US`、`cmn-CN`；
- **語音** —— 選填，例如 `Polly.Joanna`、`Polly.Zhiyu`。留空時使用 Twilio 的預設語音；
- **播放次數** —— 1 到 3 次。

### Twilio 簡訊

填寫 **Account SID**、**Auth Token** 和**傳送方**。傳送方可使用帳號內的號碼（E.164）、Messaging Service（以 `MG` 開頭），或由最多 11 個英文字母或數字組成的英數字傳送方 ID（僅適用於支援此功能的國家）。向美國號碼傳送簡訊前，請先完成 A2P 10DLC 註冊。

### Twilio WhatsApp

透過 Twilio 傳送 WhatsApp 訊息屬於簡訊管道。填寫 **Account SID** 和 **Auth Token**，並在 **WhatsApp 傳送方**填入帳號中已啟用 WhatsApp 的號碼（例如 `+14155550100`），或已設定 WhatsApp 傳送方的 Messaging Service（以 `MG` 開頭）。成員的通知方式填寫 WhatsApp 號碼，格式與簡訊相同。

WhatsApp 僅允許企業使用通過審核的範本主動發起對話。在 Twilio 的 **Content Template Builder** 中建立範本並通過 WhatsApp 審核，再將範本的 Content SID（以 `HX` 開頭）和變數填入簡訊通知範本的 **WhatsApp** 欄位。依變數的位置填寫 `1`、`2`、`3`。請參閱[通知範本中的服務供應商範本](#通知範本中的服務供應商範本)。在通知策略中為簡訊管道選取這個範本。如果範本沒有 WhatsApp 欄位，系統不會傳送訊息，並會在傳送記錄中列出原因。

WhatsApp 不接受含有換行或定位字元的變數，因此系統會將每個值壓成一行、移除 Markdown 標記，並以 `-` 傳送空值。開啟**透過回覆處理警示**後，就能像回覆簡訊一樣，用回覆代碼處理警示。請參閱[回覆簡訊與電話按鍵](#簡訊回覆與電話按鍵)。

### AWS 語音與簡訊

AWS 語音（`aws_voice`）使用 AWS End User Messaging 的 `SendVoiceMessage` 撥號，由 Amazon Polly 朗讀通知。AWS 簡訊（`aws_sms`）使用 `SendTextMessage` 傳送交易型簡訊。填寫下列欄位：

- **區域** —— 從帳號已啟用的區域中選取。填寫憑證後，連接器會向 AWS 查詢並列出區域（使用 EC2 的 `DescribeRegions`）。如果選取的區域未提供 End User Messaging，傳送就會失敗；
- **驗證方式** —— 與資料整合的 AWS 連接器相同：存取金鑰、暫時金鑰、節點身分、擔任角色或 Web Identity。選擇擔任角色時，請在角色的信任政策中要求使用頁面提供的外部 ID；
- **傳送方身分** —— 號碼、號碼 ID、號碼集區 ID，或其對應的 ARN。語音必填，且號碼須能撥打電話。簡訊可留空，由 AWS 依目的地選擇號碼，也可填寫傳送方 ID；
- **Polly 語音** —— 僅適用於語音，選填。留空時使用 `MATTHEW`，中文使用 `ZHIYU`；
- **API 基礎網址** —— 依區域決定，例如 `https://sms-voice.us-east-1.amazonaws.com`。

使用的身分需要 `sms-voice:SendVoiceMessage` 或 `sms-voice:SendTextMessage` 權限。列出區域還需要 `ec2:DescribeRegions` 權限。仍處於沙箱環境的 AWS 帳號只能向已驗證的號碼傳送通知。

### 通用 HTTP 簡訊

透過設定好的 HTTP 請求，將簡訊交給自有的簡訊閘道，或交給尚無專用連接器的服務供應商。填寫下列欄位：

- **閘道網址** —— 接收請求的網址，可包含預留位置，例如 GET 閘道的 `https://sms.example.com/send?to={{phone}}&msg={{content}}`；
- **HTTP 方法** —— POST、PUT 或 GET。GET 不包含請求本文；
- **請求本文格式**與**請求本文** —— JSON 或表單（`x-www-form-urlencoded`），預設為 `{"phone": "{{phone}}", "content": "{{content}}"}`；
- **請求標頭（JSON）** —— 例如 `{"Authorization": "Bearer {{secret}}"}`；
- **金鑰** —— 閘道要求的權杖或密碼。系統會加密儲存金鑰。在網址、請求標頭和請求本文中使用 `{{secret}}` 引用；
- **電話號碼格式** —— `+8613800138000`（E.164）、`8613800138000`（不含 +），或 `13800138000`（不含國碼的中國大陸號碼）；
- **成功欄位**與**成功值** —— 選填。閘道回傳 2xx 即視為傳送成功。如果填寫成功欄位（例如 `code` 或 `result.status`），回應 JSON 中該欄位的值也必須等於成功值。

| 預留位置 | 填入的值 |
|---|---|
| `{{phone}}` | 接收簡訊的號碼，依電話號碼格式填入 |
| `{{content}}` | 簡訊內容：標題一行、本文一行，最多 320 字 |
| `{{title}}` | 通知標題 |
| `{{text}}` | 通知本文 |
| `{{secret}}` | 金鑰 |

系統會依值所在的位置進行逸出處理：JSON 請求本文採用 JSON 字串逸出，表單和網址則採用 URL 編碼。號碼和內容都必須出現在請求中，否則無法儲存連接器。

### 通用 Webhook

填寫預設網址，選擇 `POST`、`PUT` 或 `PATCH`，再選擇**請求本文**：

- **MoleSignal 事件** —— 預設選項。提供供程式讀取的 JSON，包含版本、事件、警示、規則、升級、目標及已轉譯的訊息；
- **通知範本的本文** —— 將通知策略為 Webhook 管道選取的範本本文原樣用作請求本文。JSON 格式的範本會以 JSON 傳送。請參閱[條件](#條件)和[範本格式](#建立範本和策略)。

每個請求都附上 `X-MoleSignal-Event`（通知類型）和 `X-MoleSignal-Delivery`（傳送 ID，供接收方排除重複資料）。填寫**簽章金鑰**（至少 16 個字元）後，請求也會附上 `X-MoleSignal-Timestamp` 和 `X-MoleSignal-Sign`，讓接收方確認請求來自 MoleSignal。請求本文的欄位、簽章演算法和驗證範例，請參閱 [Webhook 通知連接器](/zh-Hant/notification-channels/webhooks#通用-webhook)。

`direct_user`、`fixed_address` 和 `fixed_group` 會向已設定的預設網址發出請求，並將目標作為路由資料加入請求本文。`webhook` 則會以目標值取代預設網址。2xx 回應表示傳送成功。如果回應包含 `X-Request-ID`，MoleSignal 會將該標頭的值記錄為服務供應商的訊息 ID。Webhook 不參與[合併通知](#合併通知)，每則通知各發出一個請求。

<Warning>
  Webhook 網址、Authorization 標頭、Token、密碼和簽章金鑰都屬於憑證。請勿將憑證值寫入測試目標、通知範本或事件屬性。
</Warning>

### Amazon SNS

將每則通知發佈到一個 Amazon SNS 主題，再由該主題的訂閱轉送至 Lambda、SQS、HTTPS 端點或電子郵件信箱等目的地。填寫下列欄位：

- **驗證方式**和**區域** —— 與 [AWS 語音與簡訊](#aws-語音與簡訊)相同。請選取主題 ARN 中指定的區域；
- **主題 ARN** —— 例如 `arn:aws:sns:us-east-1:123456789012:alerts`；
- **訊息內容** —— 預設的 **MoleSignal 事件**會發佈與[通用 Webhook](#通用-webhook) 相同的 JSON。**通知範本的本文**會發佈通知策略為 Webhook 管道選取的範本本文。

系統會將標題壓成一行，並限制在 100 個字元以內（不含 100），作為訊息的主旨（Subject）。每則訊息都包含兩個訊息屬性：`event_type`（例如 `alert.triggered`）和警示的 `severity`。訂閱的篩選政策可依這些屬性篩選訊息。在 FIFO 主題（名稱以 `.fifo` 結尾）中，同一警示的訊息會歸入同一訊息群組並依序送達。系統會使用傳送 ID 排除重複訊息；同一次傳送若發佈兩次，只會保留一則。

使用的身分須具備主題的 `sns:Publish` 權限。主題已加密時，還需要金鑰的 `kms:GenerateDataKey` 和 `kms:Decrypt` 權限。列出區域則需要 `ec2:DescribeRegions` 權限。不限制目標類型：訊息一律傳送到此主題。

### PagerDuty

透過 Events API v2 將事件傳到指定的 PagerDuty 服務。在 PagerDuty 服務的 **Integrations** 頁面新增 **Events API V2** 整合，再將取得的 Integration Key（32 碼的 Routing Key）填入 **Integration Key**。**服務區域**選擇**美國**；如果帳號網址以 `.eu.pagerduty.com` 結尾，則選擇**歐盟**。

| MoleSignal 事件 | PagerDuty 事件 |
|---|---|
| 告警觸發、告警已升級 | `trigger` |
| 告警已確認 | `acknowledge` |
| 告警已恢復 | `resolve` |
| 其他事件 | `trigger`，另建一則 PagerDuty 警示 |

每則 MoleSignal 警示從觸發到恢復都對應同一則 PagerDuty 警示。系統使用去重金鑰 `molesignal-<告警 ID>` 建立對應，因此升級時會觸發同一則警示，不會另建警示。觸發事件包含以下內容：以標題作為摘要（最多 1024 個字元）、以警示所屬的服務作為來源（沒有服務時使用 `MoleSignal`）、嚴重性（`critical`、`error`、`warning` 或 `info`）、發生時間、以通用 Webhook 傳送的事件作為自訂詳細資料，以及在已設定 `http.external_url` 時附上警示連結。

PagerDuty 只會收到通知策略傳給此連接器的事件。若要讓 PagerDuty 的警示與 MoleSignal 同步確認和解決，請一併將**告警已確認**和**告警已恢復**事件傳給此連接器。不限制目標類型：事件一律傳送到這組金鑰對應的整合。

## 繫結使用者通知方式

管理員可以開啟**設定 → 通知 → 使用者通知**，選取成員，再點選**繫結通知方式**。每個通知身分都要選擇一個連接器和一個外部身分，例如電子郵件地址、Slack 使用者 ID、飛書使用者 ID，或電話與簡訊連接器使用的手機號碼。

繫結後依下列步驟設定：

1. 傳送測試通知，確認服務供應商接受該身分；
2. 組織確認身分歸屬後，將該身分標示為已驗證；
3. 在**警示事件**、**值班通知**或**報告**偏好設定中啟用該身分；
4. 有多個身分時，依主要到備用的順序排列；
5. 視需要設定勿擾時段，並決定嚴重警示是否可以略過勿擾限制。

### 無人確認時改用下一種方式

在警示事件的接收順序中，從第二步起可填入要等待的分鐘數：

| 設定 | 效果 |
|---|---|
| 第一步 | 警示觸發或升級至該成員時，立即傳送通知。 |
| 等待 N 分鐘 | 從第一次通知該成員起算，N 分鐘後仍無人確認警示，就用這一步再傳送一次。 |
| 與上一步相同的分鐘數 | 只在上一步傳送失敗時使用。 |

例如飛書（立即）、簡訊（3 分鐘後）、電話（5 分鐘後）：警示一經確認或解決，後續步驟就不再傳送，同一警示在各次升級中發給其他成員的後續通知也一樣。若某一步傳送失敗，仍會立即改用下一步。最長可等待一天，且只適用於警示事件；值班通知和報告的接收順序只在傳送失敗時使用備用方式。

成員可以在**帳號設定 → 通知設定**中管理個人通知身分和偏好設定。讀取其他成員的設定需要 `org.members.read`，修改或確認其他成員的身分需要 `org.members.update`。

<Note>
  刪除通知身分前，請先從所有傳送偏好設定中移除該身分。
</Note>

### 飛書加急與釘釘 DING

如果接收順序中的某一步使用飛書 App 或釘釘 App 連接器，可以讓 App 在訊息送出後再提醒一次。在該步驟旁的下拉式選單中選擇：

| 平台 | 選項 | 要求 |
|---|---|---|
| 飛書（飛書 App 連接器） | **App 內加急**、**簡訊加急**、**電話加急** | App 必須具備對應權限：`im:message.urgent`、`im:message.urgent:sms` 或 `im:message.urgent:phone`。簡訊加急和電話加急會使用企業的加急配額。Lark 國際版只支援 App 內加急。連接器的**收件者 ID 類型**必須是 `open_id`、`user_id` 或 `union_id`，不能使用電子郵件地址。 |
| 釘釘（釘釘 App 連接器） | **App 內 DING**、**簡訊 DING**、**電話 DING** | 必須使用釘釘專業版或專屬版，且 App 必須具備 `Premium.Ding.Write` 權限。簡訊 DING 和電話 DING 必須先購買配額。DING 的內容是通知標題，電話 DING 會唸出標題。 |

在警示事件的接收順序中，同一種方式可以使用兩次，分別設定一種加急方式。例如第一步立即傳送飛書訊息，5 分鐘後仍無人確認，再用同一個飛書通知方式進行**電話加急**。在其他類別的接收順序中，每種方式只能使用一次。

如果加急失敗（例如配額用完或缺少權限），即使訊息已送達，這一步仍視為傳送失敗，並立即改用接收順序中的下一步。企業微信不支援加急。

## 簡訊回覆與電話按鍵

電話、簡訊和 WhatsApp 連接器啟用**透過回覆處理警示**（電話連接器稱為**以按鍵處理警示**）後，收件者無須開啟 MoleSignal 就能處理警示：

- **簡訊** —— 警示觸發或升級時傳送的簡訊末尾會顯示「回覆 31 確認，32 解決。」，回覆其中一個代碼即可。十位數是該號碼輪流使用的序號（0 到 9），個位數 1 代表確認，2 代表解決。只回覆 `1` 或 `2` 時，會處理該號碼最近收到的警示。多則警示合併成一封簡訊時，一個代碼就能處理其中所有警示。代碼一天內有效；
- **電話** —— 唸完警示後，按 1 確認，按 2 解決。電話會隨即播報處理結果。

系統以收到訊息的成員身分處理回覆和按鍵操作。該成員必須具備 `alerts.incidents.acknowledge` 權限，且帳號與組織都必須處於使用中狀態。時間軸會記錄為「簡訊回覆」或「電話按鍵」。只有直接傳給成員的訊息才會附上代碼，傳到備援路由固定號碼的訊息不會附上代碼。

服務供應商需要將回覆和按鍵操作推送到 MoleSignal 的回呼網址，因此請設定對外網址 `http.external_url`，並確保可從公用網路存取 `/api/v1/public/notify/` 底下的路徑，詳見[公用網路存取](/zh-Hant/public-access)。啟用功能並儲存連接器後，可從連接器頁面複製顯示的回呼網址：

| 連接器 | 設定方式 | 回呼驗證方式 |
|---|---|---|
| Twilio 簡訊 | 在號碼的 Messaging 設定中，將 **A message comes in** 設為 Webhook，選擇 HTTP POST，並填入回呼網址。 | 使用連接器的 Auth Token 驗證 Twilio 簽章 `X-Twilio-Signature`。 |
| Twilio WhatsApp | 在 Twilio 的 WhatsApp 傳送端設定中（或在所屬的 Messaging Service 設定中），將接收訊息的 Webhook 設為回呼網址，並選擇 HTTP POST。WhatsApp 只會傳送通過審核的範本，因此請將代碼寫入範本：在範本變數中填入 `{{reply.ack}}`、`{{reply.resolve}}`。如果在範本的快速回覆按鈕 ID 中填入代碼，點選按鈕就等於回覆該代碼。 | Twilio 簽章。 |
| Twilio 電話 | 無須設定：每通電話都會附上按鍵回呼網址。 | Twilio 簽章。 |
| AWS 簡訊 | 為號碼啟用雙向簡訊，將回覆傳到 SNS 主題。在該主題中新增 HTTPS 訂閱，將端點設為回呼網址，系統會自動確認訂閱。可在**回覆用的 SNS 主題 ARN** 中填入該主題，這樣就只會接受該主題推送的回覆。 | 驗證 SNS 訊息的簽章，只從 `sns.<区域>.amazonaws.com` 取得憑證。 |
| 阿里雲簡訊 | 在簡訊服務的上行簡訊設定中選擇 HTTP 推送，並填入回呼網址。阿里雲只會傳送通過審核的範本，因此請將代碼寫入範本：在範本參數中填入變數 `{{reply.ack}}`、`{{reply.resolve}}`，詳見[範本變數](#範本變數)。 | 網址中的回呼 Token。 |
| 阿里雲語音通知 | 改用互動式語音（IvrCall）撥打電話，並填入**來電顯示號碼**（為 IvrCall 購買的實際號碼）。在語音服務的回執設定中選擇 HTTP 推送，並填入回呼網址。唸完範本後會等待 10 秒接收按鍵。 | 網址中的回呼 Token。 |
| 騰訊雲簡訊 | 在簡訊主控台的回呼設定中，將簡訊回覆的回呼欄位設為回呼網址。請將代碼寫入範本：在範本變數中填入 `{{reply.ack}}`、`{{reply.resolve}}`。 | 網址中的回呼 Token。 |
| 騰訊雲語音訊息 | 在語音訊息主控台的事件回呼設定中，將按鍵回呼欄位設為回呼網址。在範本中自行加上「按 1 確認，按 2 解決」。按鍵回呼只會附上受話號碼，系統會依該號碼最近的一通電話處理。 | 網址中的回呼 Token。 |
| 華為雲簡訊 | 建立簡訊應用程式時，將上行簡訊接收位址設為回呼網址。請依上述方式將代碼寫入範本。 | 網址最後一段的回呼 Token。 |
| 華為雲語音通知 | 在應用程式管理中，將通話狀態接收位址設為回呼網址。語音播放完畢後會接收一位數的按鍵輸入。在範本中自行加上「按 1 確認，按 2 解決」。 | 網址最後一段的回呼 Token。 |
| 通用 HTTP 簡訊 | 設定閘道，將收到的簡訊以 JSON `{"phone": "…", "text": "…"}`（或由這類物件組成的陣列）POST 到回呼網址。 | 網址中的回呼 Token。 |

伺服器會以根金鑰為各連接器推導回呼 Token，不會另外儲存。請將回呼網址視為憑證妥善保管。AWS 語音訊息無法接收按鍵輸入，因此 `aws_voice` 沒有這個開關。

## 一次性處理連結

警示通知只發給一位收件者，且連接器未在通知中加入按鈕時，通知末尾會附上一次性連結。警示等待確認時會顯示**確認**和**解決**，確認後只會顯示**解決**。電子郵件會使用這種方式，即時通訊連接器傳送不含按鈕的警示時也一樣，例如 Webex 機器人，或未在 **IM 整合**中啟用的飛書 App。有卡片時，連結會顯示為卡片中的連結按鈕；沒有卡片時，連結會附在訊息末尾。連結文字會使用收件者的介面語言。

- 連結會開啟 MoleSignal 的頁面 `https://<对外地址>/notify/actions/<Token>`，無須登入。頁面會顯示警示的嚴重程度、狀態、標題和開始時間，以及一個按鈕。開啟頁面不會執行任何操作，因此電子郵件安全閘道可以預先開啟連結。只有點選按鈕才會執行操作。
- 每個連結只能使用一次，24 小時內有效。點選按鈕時，系統會以收到通知的成員身分執行操作。該成員當時必須具備這則警示的 `alerts.incidents.acknowledge` 權限，且帳號與組織都必須處於使用中狀態。
- 如果連結已使用或已過期、警示已處理或已恢復，或收件者已無權處理這則警示，頁面會說明原因，不會影響警示。
- 要使用連結，請設定 `http.external_url`。未設定時，通知不會附上連結。如果 MoleSignal 只部署在內部網路，收件者必須能從查看電子郵件的網路存取此頁面及其 API，詳見[公用網路存取](/zh-Hant/public-access)。

傳送到群組或備援路由固定地址的通知不會附上連結。簡訊、電話與整合類連接器也不會附上連結：簡訊和電話可透過[回覆](#簡訊回覆與電話按鍵)處理。

## 建立範本和策略

開啟**設定 → 通知 → 通知範本**，建立可重複使用的訊息本文。選擇通知類別和管道，插入[變數](#範本變數)或從[預設範本](#預設範本)開始，再用預覽事件屬性檢查呈現結果。編輯器右側的變數、預設範本和預覽事件屬性預設為收合，點選標題即可展開。範本清單依管道分類。

| 管道 | 適用範圍 | 本文 |
|---|---|---|
| **一般** | 通知策略未另選範本的所有管道。 | 純文字、Markdown 或 HTML。 |
| **即時通訊**、**電子郵件**、**Webhook** | 僅適用於所選管道。 | 純文字、Markdown 或 HTML；即時通訊範本也可以[以卡片傳送](#即時通訊範本的卡片)，Webhook 範本也可以使用 JSON：變數值會依 JSON 字串規則跳脫，代入後必須是有效的 JSON，用於[一般 Webhook](#通用-webhook) 的**通知範本的本文**。 |
| **簡訊**、**電話** | 僅適用於所選管道。 | 純文字，包含傳送的所有內容，不含通知標題；簡訊最多 320 字，電話最多朗讀 400 字，編輯器會顯示字數。 |

接著開啟**通知策略**並建立路由規則：

1. 選擇事件類型和通知類別；
2. 新增 JSON 比對條件並設定策略優先順序；在 **時間** 中選擇 **僅限這些時段內** 或 **僅限這些時段外**，將策略限制在每週的特定時段，並以通知事件發生的時間判斷是否符合。時段也可以依[假日日曆](/zh-Hant/alerting/on-call#假日行事曆)計算。不符合時，這條策略不會傳送通知，其他策略仍照常比對；
3. 選擇收件人解析器及其設定；
4. 選擇依使用者偏好傳送、強制使用單一連接器，或透過多個連接器傳送；
5. 選擇一般範本，視需要為即時通訊、電話、簡訊等管道另選專用範本，並啟用使用者、團隊或組織備援；
6. 視需要設定確認逾時和升級路由；警示類策略也可以設定[合併通知](#合併通知)；
7. 檢查即時傳送預覽；預覽會解析實際使用者和路由，列出各步驟使用的範本，但不會傳送訊息。

傳送時依連接器所屬的管道選擇範本：優先使用另選的管道範本，其次使用一般範本。兩者皆未設定時，傳送事件的預設訊息。通知策略正在使用的範本無法刪除，也無法變更管道。

策略目前涵蓋警示生命週期和值班排程事件。策略編輯器會列出目前執行中的後端支援的事件類型和收件人解析器。對於符合[靜默](/zh-Hant/alerting/silences)條件的警示事件，策略會暫緩傳送，請參閱[靜默期間的通知](/zh-Hant/alerting/silences#靜默期間的通知)。

### 合併通知

警示密集時，同一位收件人或同一個群組可能在幾十秒內收到多則通知。警示和警示升級類通知策略提供**合併通知**：可選 30 秒、1、2 或 5 分鐘（API 允許 10 秒到 10 分鐘）。在這段時間內，透過同一個連接器傳送給同一位收件人的警示通知會合併：第一則照常立即傳送，其餘在時段結束後一併傳送，排隊期間已確認的通知不再傳送。

- 即時通訊和電子郵件會傳送一份清單：標題為第一則通知的標題加上「(+N)」，本文逐一列出警示。已設定對外網址時，各警示會連到對應的事件；飛書 App 和 Slack App 的卡片上有**全部確認**，請參閱[警示卡片](/zh-Hant/im#告警卡片)；
- 簡訊依序列出各則通知的標題，電話則依序朗讀；回覆一組簡訊代碼即可處理全部通知。電話原本就會合併至少 60 秒內的通知；
- 一般 Webhook、PagerDuty 和 Amazon SNS 不合併。

內建的警示觸發、恢復和升級策略預設合併 1 分鐘內的通知，其餘策略預設為**不合併**。

### 範本變數

本文、阿里雲範本的變數和卡片各處都可以使用變數，例如 `{{rule.name}}`，傳送時會代入這則通知的對應值。編輯器右側的**變數**會列出這個通知類別可用的變數，點選即可插入游標所在位置。名稱以 `_at` 結尾的是微秒時間戳記，以 `_time` 結尾的是 UTC 時間，例如 `2026-07-29 00:00:00 UTC`。事件未提供的變數會原樣保留在本文中。

警示和警示升級的變數：

| 變數 | 值 |
|---|---|
| `{{rule.name}}`、`{{rule.description}}` | 規則的名稱和說明。 |
| `{{severity}}`、`{{incident.status}}` | 嚴重程度和警示狀態。 |
| `{{urgency}}`、`{{priority}}` | 緊急程度等級的鍵值（`high`、`low` 或組織新增的等級）和優先順序（`P1` 到 `P9`，未設定時為空值），請參閱[緊急程度](/zh-Hant/alerting/on-call#緊急程度)。通知策略也可依事件屬性 `urgency`、`priority` 比對。 |
| `{{urgency_name}}`、`{{priority_name}}` | 組織在[緊急程度與優先順序等級](/zh-Hant/alerting/on-call#緊急度與優先順序等級)中為緊急程度和優先順序設定的名稱；未命名時為空值。 |
| `{{value}}`、`{{threshold}}` | 觸發時的值和閾值。若規則有多個等級，則採用警示嚴重程度對應等級的閾值；異常偵測規則沒有閾值，以 `null` 表示。 |
| `{{incident.url}}` | 警示在 MoleSignal 中的網址，必須設定對外網址 `http.external_url`。 |
| `{{incident.started_time}}`、`{{incident.duration}}` | 警示開始的時間和持續時間，例如 `1h 5m`；已恢復的警示計算到恢復時為止。 |
| `{{incident.acknowledged_time}}`、`{{incident.acknowledged_by}}` | 確認時間和確認人員的使用者 ID，僅在確認後提供。 |
| `{{incident.resolved_time}}`、`{{incident.resolved_by}}` | 解決時間和解決人員的使用者 ID，僅在解決後提供；自動恢復的警示沒有解決人員。 |
| `{{incident.assignees}}`、`{{affected_services}}` | 處理人員的使用者 ID 和受影響的服務，以逗號分隔。 |
| `{{service}}`、`{{environment}}` | 服務和環境，取自警示的標籤或註解。 |
| `{{labels}}`、`{{labels.<key>}}` | 所有標籤（`service=api, env=production`）和單一標籤的值；註解使用 `{{annotations.<key>}}`。 |
| `{{escalation.step}}`、`{{escalation.loop}}`、`{{escalation.target}}` | 升級的層級、輪次（皆從 1 開始計算）和該層的通知對象（`user`、`schedule` 或 `team`），僅在升級通知中提供。 |
| `{{escalation.reason}}` | 傳送這則升級通知的原因：`step`（正常升級）、`manual`（立即升級）、`reassigned`（改派）、`responder_added`（增派）、`snooze_ended`（暫緩期滿）、`ack_timeout`（確認後逾時未解決）、`severity_raised`（調高嚴重程度）或 `urgency_raised`（緊急程度升為高），請參閱[處理事件](/zh-Hant/alerting/incidents#處理事件)。 |
| `{{reply.ack}}`、`{{reply.resolve}}` | 回覆以確認或解決警示的代碼，例如 `31`、`32`；僅在已啟用[透過回覆處理警示](#簡訊回覆與電話按鍵)的簡訊連接器所傳送的警示簡訊中代入，其他地方會原樣保留。 |

值班排程提供 `{{schedule.*}}`、`{{oncall.*}}` 和 `{{override.*}}`；交接時間和代班時段除了微秒格式的 `_at`，也提供易讀的 `{{oncall.transition_time}}`、`{{override.start_time}}` 和 `{{override.end_time}}`。各類通知都可以使用 `{{event.time}}`、`{{message.title}}`、`{{message.text}}`，以及任意事件屬性 `{{event.attributes.<key>}}`。

### 條件

本文可以加入條件區塊，只有在條件成立時才保留區塊內的內容：

```text
{{#if severity == "critical"}}立即处理{{else}}请关注{{/if}}：{{rule.name}}
{{#if event.type == "alert.resolved"}}已恢复，持续 {{incident.duration}}{{/if}}
{{#if annotations.runbook_url}}处理手册：{{annotations.runbook_url}}{{/if}}
```

- `{{#if 变量 == "值"}}` 和 `!=` 可比較變數值；只寫變數時，變數有值且不為空即成立；
- `{{else}}` 指定條件不成立時保留的內容，可以省略；
- 條件區塊最多可巢狀嵌套 5 層；未寫完整的區塊（缺少 `{{/if}}`）無法儲存，編輯器會在本文下方指出錯誤位置；
- 預覽會依預覽事件屬性判斷條件。編輯器右側的**條件**提供幾種常用寫法，點選即可插入。

### 預設範本

**預設範本**提供預先寫好的本文，套用後可以繼續編輯。範本依通知類別和管道列出：簡訊和電話各自只列出專用範本；即時通訊和電子郵件也提供專用範本，例如含警示連結的即時通訊 Markdown，以及以表格呈現的警示電子郵件。警示的觸發、確認和恢復通知都有預設範本；套用確認或恢復的預設範本時，預覽會改用已確認或已恢復的範例警示。預設範本的本文會隨介面語言變更，中文介面會套用中文本文。

### 通知範本中的服務供應商範本

阿里雲、騰訊雲和華為雲只會傳送通過審核的範本，WhatsApp 只會傳送通過審核的 Content 範本。可以在簡訊或電話範本中為各家供應商分別設定範本，WhatsApp 則只能在簡訊範本中設定：

- **範本編號** —— 服務供應商提供的編號：阿里雲簡訊以 `SMS_` 開頭，語音以 `TTS_` 開頭；騰訊雲和華為雲使用各自的範本 ID；WhatsApp 使用 **Content SID** 欄位中的 Twilio Content SID，以 `HX` 開頭，後接 32 個十六進位字元；
- **變數** —— 指定每個變數的值，寫法和本文相同，可以使用 `{{rule.name}}` 等變數。阿里雲使用範本中 `${…}` 內的名稱；騰訊雲、華為雲和 WhatsApp 依位置填寫，變數名稱填 `1`、`2`、`3`；
- **每個變數的字數上限** —— 超出上限的部分會截斷。留空時使用預設值：阿里雲 35 字，騰訊雲簡訊 6 字、語音 20 字，華為雲簡訊 20 字、語音 32 字（語音另有 32 位元組的上限），WhatsApp 300 字。

這些服務供應商的連接器會使用各自的專用範本，其他簡訊和電話連接器則會傳送範本本文。如果通知策略為管道選用的範本未設定該供應商的專用範本，該連接器就無法傳送，傳送記錄會列出原因。

測試這些服務供應商的連接器時，從該管道選擇已設定該供應商專用範本的通知範本，並用範例值填入預留位置；測試成員綁定至該連接器的號碼時，使用依名稱排序的第一個符合條件的範本。定期巡檢和自動化等功能會直接傳送內容，不使用通知範本，因此無法選用這些服務供應商的連接器。

### 即時通訊範本的卡片

即時通訊範本可以啟用**以卡片傳送**，讓 App 和群組機器人都傳送卡片；停用時仍傳送文字。卡片本文使用範本的訊息本文，也可以另外設定：

- **卡片標題** —— 留空時使用通知標題；
- **標題顏色** —— 依嚴重程度套用顏色（嚴重為紅色、錯誤為橘色、警告為黃色，其餘為藍色，已恢復為綠色），或使用固定顏色；
- **欄位** —— 名稱和值，例如將 `服务` 的值設為 `{{labels.service}}`，最多 10 個；
- **連結按鈕** —— 按鈕文字和網址，例如將 `处理手册` 的網址設為 `{{annotations.runbook_url}}`，最多 5 個；
- **頁尾** —— 卡片最下方的一行小字。

各處都可以使用變數。無法代入值的欄位和連結不會顯示，網址不是 http(s) 的連結也不會顯示。編輯器的預覽只呈現卡片的大致外觀，各平台會以各自的卡片格式傳送：

| 平台 | 傳送格式 |
|---|---|
| **飛書** | 互動卡片：標題列套用指定顏色，欄位分兩欄排列，頁尾位於分隔線下方；App 的連結按鈕與警示的確認、解決按鈕排在一起。 |
| **Slack** | 含色條的 Block Kit 卡片；App 的連結按鈕與警示按鈕排在一起。 |
| **釘釘** | ActionCard：標題套用顏色，連結以按鈕顯示在卡片下方，最多 5 個；沒有連結時傳送 Markdown。若 App 已填入互動卡片範本 ID，警示通知會依該範本傳送含警示按鈕的互動卡片。 |
| **企業微信** | 排成卡片樣式的 Markdown，標題套用指定顏色（企業微信的文字只有綠、灰、橘三種顏色）。含警示按鈕時，會使用可透過按鈕互動的範本卡片：欄位由次標題和文字組成，最多 6 個，點選卡片即可開啟 MoleSignal。 |
| **Teams** | Adaptive Card：標題列套用指定顏色，欄位以一組名稱和值呈現，連結以按鈕呈現，頁尾位於分隔線下方；機器人的連結按鈕與警示按鈕排在一起。 |
| **Google Chat** | 卡片：每個欄位以一行附有名稱的文字呈現，連結以按鈕呈現，App 的連結按鈕與警示按鈕排在一起；Google Chat 的卡片標題不會套用顏色。 |
| **Telegram** | 單則訊息：標題以粗體呈現，前方有一個與標題顏色相符的圓點，欄位一行一個，頁尾使用斜體。警示按鈕排在第一列，連結按鈕排在下方，每列兩個；如果網址不是公開網路位址而遭 Telegram 拒絕，連結會改為在本文中逐行列出。 |
| **Discord** | 嵌入式卡片（embed）：附有色條，標題連至警示，連結位於本文下方，欄位並排，最後是頁尾。 |
| **Mattermost** | 訊息附件：附有色條，標題連至警示，較短的欄位並排，連結位於本文下方，最後是頁尾；機器人的警示按鈕排在下方。 |
| **Webex** | 機器人會傳送版面與 Teams 卡片相同的 Adaptive Card，最多顯示 5 個連結按鈕，其餘連結放在本文下方；Webhook 會傳送 Markdown。 |
| **Matrix** | 格式化訊息：標題套用顏色，欄位以清單排列，接著是連結，頁尾使用斜體。 |

群組機器人無法接收點選事件，因此卡片上不會顯示警示的確認或解決按鈕。測試連接器時，可以選擇即時通訊範本，用範例值填入變數後傳送卡片。

### 內建策略

建立組織時會自動加入下列通知策略，不必先建立策略，就能將警示和值班事件通知相關人員。所有策略都**依使用者偏好傳送**；傳送失敗時，依序使用使用者備用端點、團隊備援路由和組織備援路由。這些策略不選用範本，直接傳送事件的預設訊息。

| 內建策略 | 事件 | 通知對象 | 預設 |
|---|---|---|---|
| 警示觸發：通知負責人 | 警示觸發 | 警示的負責人，若無負責人則通知處理人員 | 啟用 |
| 警示恢復：通知負責人 | 警示已恢復 | 警示的負責人，若無負責人則通知處理人員 | 啟用 |
| 警示升級：通知此步驟指定的人員 | 警示已升級至個人 | 此步驟指定的人員 | 啟用 |
| 警示升級：通知此步驟指定的團隊 | 警示已升級至團隊 | 該團隊的成員 | 啟用 |
| 值班交接：通知交接雙方 | 值班即將開始 | 交班和接班人員 | 啟用 |
| 值班空檔：通知值班表管理員 | 無人值班 | 值班表管理員 | 啟用 |
| 警示確認：通知負責人 | 警示已確認 | 警示的負責人，若無負責人則通知處理人員 | 停用 |
| 值班代班：通知相關人員 | 已建立臨時代班 | 代班人員和原值班人員 | 停用 |
| 換班：通知相關人員 | 換班申請有變更 | 此步驟需要通知的人員，請參閱[換班申請](/zh-Hant/alerting/on-call#換班申請) | 啟用 |
| 接班人員收不到警示：通知接班人員和排班管理員 | 接班人員收不到警示（班次開始前 30 分鐘） | 接班人員和排班管理員，請參閱[收不到警示的成員](/zh-Hant/alerting/on-call#收不到警示的成員) | 啟用 |
| 資料擷取預算即將用盡：通知預算指定的人員 | 資料擷取預算即將用盡 | 預算指定的人員，請參閱[設定預算](/zh-Hant/streams#設定預算) | 啟用 |
| 資料擷取超出預算：通知預算指定的人員 | 資料擷取超出預算 | 預算指定的人員，請參閱[設定預算](/zh-Hant/streams#設定預算) | 啟用 |
| 重大事件進度：通知關注者 | 重大事件進度 | 事件的負責人、各角色和關注者，請參閱[發布進度](/zh-Hant/alerting/major-incidents#發布進度) | 啟用 |
| 待核准：通知有權核准的人員 | Mole Agent 待核准（`agent.approval.requested`） | 具備 `agent.approve` 權限的成員，最多 20 人，不含發起人，請參閱[核准卡片](/zh-Hant/im#核准卡片) | 啟用 |

**通知策略**清單會將內建策略標示為**內建**。可以修改或停用這些策略，但無法刪除或重新命名。若要將修改過的策略還原為上表的設定，請在編輯器中選擇**還原預設值**。升級至值班表的步驟沒有內建策略，請依值班表另建一條策略，並將收件人設為**目前值班人員**。

## 設定備援路由

開啟**設定 → 通知 → 備援路由**。選擇組織或團隊範圍，再選擇通知類別。新增一或多個已啟用的連接器，選擇 `fixed_address` 或 `fixed_group`，並填寫服務供應商的傳送目標。

已啟用的個人路由階段失敗後，MoleSignal 會依頁面顯示的順序嘗試備援路由。通知策略決定是否啟用使用者、團隊和組織備援。

## 檢視和重試傳送

開啟**設定 → 通知 → 傳送記錄**，依事件 ID、狀態或階段篩選。選擇一筆記錄，即可檢視已遮蔽敏感資訊的傳送目標、連接器、耗時、服務供應商錯誤和完整的傳送路徑。

- `notify.deliveries.read` 可以檢視傳送歷史記錄；
- `notify.deliveries.acknowledge` 可以確認來源事件；
- `notify.deliveries.retry` 可以重試失敗的路由。

重試會建立新的傳送嘗試，不會修改現有的歷史記錄。

傳送失敗的警示通知會自動重試。警示已確認或恢復時，不再自動重試，但仍可手動重試。

階段為 **直接傳送** 的記錄，來自可自行指定連接器和目標的功能，例如[定期記錄巡檢](/zh-Hant/logs/inspections)。直接傳送不經過通知策略，也無法重試。

## 連接器生命週期與狀態

| 狀態 | 含義 |
|---|---|
| **未知** | 連接器尚未完成任何測試，沒有成功或失敗的結果。 |
| **已連線** | 最近一次測試成功。 |
| **異常** | 最近一次測試失敗；在後續測試成功前，正常路由會略過該連接器。 |
| **已停用** | MoleSignal 不會透過該連接器進行測試或投遞。 |

停用連接器不會移除參照。若使用者身分、通知策略、備援路由或排程日誌巡檢仍參照該連接器，就無法刪除它。請先移轉這些參照，再刪除連接器。

## 排查投遞問題

| 現象 | 檢查項目 |
|---|---|
| SMTP 驗證或 TLS 失敗 | 檢查主機、連接埠、憑證、TLS 模式、寄件地址、DNS 和對外網路連線。 |
| Slack 傳回 API 錯誤 | 檢查 Bot Token、`chat.postMessage` 權限、目標 ID 和頻道成員資格。 |
| 飛書拒絕訊息 | 檢查應用程式權限、收件人 ID 類型、群組聊天成員資格、Webhook 密鑰和伺服器時間。 |
| Webhook 傳回錯誤 | 檢查 URL、方法、標頭 JSON、逾時設定，以及對端是否傳回 2xx。 |
| 使用者未收到通知 | 檢查身分和連接器是否已啟用、類別偏好設定是否包含該身分，以及勿擾模式是否生效。 |
| 備援路由未執行 | 檢查策略是否啟用該層備援，以及對應類別是否有已啟用的路由。 |
| 電話未撥出或簡訊未送出 | 檢查號碼是否以 + 和國碼開頭、範本與簽名是否通過審核、通知策略為此管道選用的範本是否包含適用於該服務供應商的版本，以及變數名稱是否一致。另請檢查服務供應商的頻率限制和帳號沙箱。 |
| 回覆簡訊或按鍵未生效 | 檢查連接器是否啟用**透過回覆處理警示**、服務供應商的回呼是否指向連接器頁面顯示的網址、公用網路能否存取該網址、該號碼是否曾收到含代碼的警示簡訊、代碼是否已超過一天，以及收件成員是否具備 `alerts.incidents.acknowledge` 權限。 |
| 飛書或釘釘的第一步訊息已送達，卻判定為傳送失敗 | 加急失敗：檢查應用程式權限、加急或 DING 額度及釘釘版本；飛書還需檢查收件人 ID 類型和平台。 |
| 一次性處理連結未生效 | 檢查連結是否已使用或已超過 24 小時、警示是否仍在等待這項操作、收件人是否仍具備 `alerts.incidents.acknowledge` 權限，以及開啟連結的環境能否存取該頁面和 `/api/v1/public/notify/actions/`。 |
