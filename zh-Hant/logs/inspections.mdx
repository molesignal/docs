日誌巡檢讓 Mole Agent 閱讀一段時間內的日誌並撰寫報告：這段時間是否有問題、問題是什麼，以及哪些日誌可作為依據。巡檢只讀取日誌，不修改任何資料或設定。

| 方式 | 用途 |
|---|---|
| **按需巡檢** | 在 **日誌** 的 **智慧巡檢** 檢視中，立即巡檢一次符合目前查詢的日誌，並在頁面上串流顯示報告。這次巡檢是一則 Mole Agent 對話，可在 **Mole Agent** 中繼續追問，但不會列入排程巡檢的歷史報告。 |
| **排程巡檢** | 儲存資料串流、查詢條件和巡檢要求。MoleSignal 依週期執行巡檢，儲存每次的報告，並在報告判定有異常時發出通知。 |

## 開始之前

- 在 **Mole Agent → 設定 → 模型與推論** 中至少啟用一個 AI 模型，請參閱 [Mole Agent](/zh-Hant/agent#設定模型服務)。未啟用任何模型時，清單仍會顯示已儲存的巡檢，但無法執行。
- 確認權限：

| 操作 | 權限 |
|---|---|
| 按需巡檢 | `agent.use` 和 `logs.read` |
| 查看排程巡檢及其報告 | `inspections.read` 和 `logs.read` |
| 新增、編輯、啟用或停用、刪除 | `inspections.manage`，預設授予 owner、admin 和 editor 角色 |
| 立即執行 | `inspections.run`，預設授予相同的角色 |
| 在表單中選擇通知管道 | `notify.connectors.read`，用於列出通知連接器 |

Mole Agent 在對話中使用 `list_log_inspections`、`list_log_inspection_runs` 和 `get_log_inspection_run` 讀取相同的巡檢與報告，所需權限相同。`run_log_inspection` 會立即執行一次巡檢，需要 `inspections.run`，預設也須在對話中確認。請參閱 [Tool Catalog 與執行模型](/zh-Hant/tools)。

## 按需巡檢

1. 開啟 **日誌**，選擇資料串流和時間範圍，然後執行查詢。查詢留空時，巡檢該資料串流中的所有日誌。
2. 開啟 **智慧巡檢** 檢視。
3. 選擇 **AI 模型**。可在 **巡檢要求** 中說明要留意的重點，例如需要留意的服務，或應視為預期結果的情況。
4. 選擇 **開始巡檢**。

巡檢會將這些日誌的查詢結果傳送給所選模型。選擇 **在 Mole Agent 中繼續**，即可針對報告繼續追問。

## 儲存排程巡檢

開啟 **日誌 → 智慧巡檢**，然後從下列兩種方式擇一：

- 選擇 **儲存為排程巡檢**，開啟已帶入目前資料串流、查詢條件、巡檢要求和模型的表單。目前查詢沒有相符結果時，仍可儲存。
- 選擇 **排程巡檢** 開啟清單，再從清單中選擇 **新增巡檢**，開啟空白表單。

| 欄位 | 說明 |
|---|---|
| **名稱** | 在組織內不得重複，最多 120 個字元。 |
| **資料串流** | 選擇一個日誌資料串流，不可選擇 [`_audit`](/zh-Hant/settings/data-security#稽核資料流)。巡檢只讀取這個資料串流。 |
| **查詢條件** | 選填。只巡檢符合條件的日誌，語法與 **日誌** 頁面相同。 |
| **巡檢要求** | 選填，最多 2,000 個字元。說明要留意的重點，以及哪些情況算正常。 |
| **週期** | 選擇 **依間隔**，或指定 **每天** 或 **每週** 的執行時間。最短間隔由執行個體設定決定，預設為 1 小時。 |
| **涵蓋時段** | 指定每次執行要查看執行時間往前多久的日誌。表單可選 15 分鐘到 7 天，預設與週期相同。 |
| **AI 模型** | 選擇組織內已啟用的一個模型。 |
| **何時通知** | **僅在異常時通知**（預設）、**達「需留意」等級以上時通知** 或 **每次都通知**。 |
| **通知管道** | 選填，最多 10 個。每個管道對應到通知連接器上的一個固定群組或地址。阿里雲簡訊與語音只傳送通過審核的範本，因此無法選用。 |
| **儲存後依週期自動執行** | 關閉時只儲存巡檢，僅在選擇 **立即執行** 時執行。 |

每天或每週的執行時間以新增巡檢時介面使用的時區為準：優先使用個人偏好設定中的時區，未設定時則使用瀏覽器的時區。表單會顯示時區，後續編輯不會變更時區。通知和報告使用新增巡檢時的介面語言。

預設情況下，每個組織最多可儲存 20 筆排程巡檢。

## 執行方式

| 項目 | 行為 |
|---|---|
| 執行身分 | 巡檢以最後一次儲存該巡檢的使用者身分讀取日誌。每次執行前，MoleSignal 都會確認該使用者仍可登入、仍是組織成員，且仍具備 `agent.use` 和 `logs.read` 權限。若驗證未通過，MoleSignal 會將這次執行記為失敗，原因為執行身分已無法使用。由其他具備權限的使用者重新儲存一次，即可改用該使用者的身分執行。無法使用 API Token 儲存排程巡檢。 |
| 工具 | 模型只使用四個唯讀工具：`query_logs`、`get_stream_schema`、`search_field_values` 和 `analyze_log_patterns`（將日誌依模式分組，並與對照時段比較），且只能讀取巡檢所選的資料串流。由於背景執行時無人審核，模型不會使用組織的 Tool Policy 已停用或要求核准的工具。 |
| 時間範圍 | 每次巡檢涵蓋執行時間前的一段時間。系統不會補跑節點停機期間錯過的巡檢。節點恢復後，到期的巡檢會執行一次，之後依週期繼續執行。 |
| 上限 | 單次執行預設上限為 5 分鐘，超過上限即記為逾時。工具結果超過 64 KiB 時，系統不會將結果交給模型，而是要求模型縮小查詢範圍。執行失敗時不會重試，會等到下一個週期再執行。 |
| 並行執行 | 同一筆巡檢同一時間只能執行一次。預設情況下，每個節點最多可同時執行 2 筆巡檢。 |
| **立即執行** | 系統會先將這次執行排入佇列，並在 15 秒內開始執行。執行時仍沿用巡檢的執行身分，並記錄發起執行的使用者。已停用的巡檢也可用這個方式執行。 |

## 報告與結論等級

在清單中選擇一筆巡檢，開啟報告。左側列出歷次執行。選擇其中一次即可查看報告、涵蓋的時間範圍、執行耗時、呼叫過的工具、消耗的 token 和發出的通知。選擇 **查看這段時間的記錄**，即可用相同的資料串流、查詢條件和時間範圍開啟 **日誌**。

排程巡檢的報告會標示結論等級：

| 等級 | 含義 |
|---|---|
| **正常** | 沒有需要處理的問題。 |
| **需留意** | 有值得留意的跡象，但尚未構成故障。 |
| **異常** | 發現需要處理的問題。 |
| **未判定** | 無法從模型的回覆讀取結論等級。系統仍會儲存報告，並在判斷是否通知時視為異常。 |

未完成的執行不會產生報告，執行記錄會顯示狀態和原因：

| 狀態 | 原因 |
|---|---|
| **逾時** | 執行超過時間上限。 |
| **失敗** | 執行身分已無法使用；所選 AI 模型不存在、已停用或未設定金鑰；模型呼叫失敗；組織當天的 Mole Agent token 預算已用完；節點在執行途中結束；沒有節點可執行；或發生內部錯誤。 |

報告預設保留 30 天，系統每小時清理一次過期報告。刪除巡檢時，系統也會一併刪除該巡檢的所有報告。

## 通知

- 報告的結論等級符合 **何時通知** 的設定時，每個管道都會收到一則通知。標題會列出等級和巡檢名稱，內文包含資料串流、時間範圍、等級、報告摘要和報告連結。報告連結需要設定 `http.external_url`。
- 執行失敗時，只有上一次執行未失敗才會發出通知。連續失敗時只通知第一次，不受 **何時通知** 的設定影響。
- 未選擇通知管道時，系統不會發出通知，但仍會儲存報告。
- **設定 → 通知 → 傳送記錄** 會列出每則通知，階段為 **直接傳送**。直接傳送不套用通知政策，也無法從傳送記錄重試。
- 無法刪除排程巡檢使用中的通知連接器。

## 執行個體設定

| 設定項目 | 預設值 | 用途 |
|---|---|---|
| `[log_inspection].min_interval_secs` | `3600` | 同一筆巡檢兩次執行之間的最短間隔。小於 60 時以 60 計算。 |
| `[log_inspection].max_per_org` | `20` | 每個組織可儲存的排程巡檢數量。`0` 表示不允許新增。 |
| `[log_inspection].concurrent_runs` | `2` | 單一節點可同時執行的巡檢數量。 |
| `[log_inspection].run_timeout_secs` | `300` | 單次執行的時間上限，包含所有模型呼叫和查詢。系統會將設定值限制在 30–480 之間。 |
| `[log_inspection].report_retention_days` | `30` | 報告的保留時間。 |

具備 `alert` 角色的節點負責執行排程巡檢，每 15 秒檢查一次是否有到期或已排入佇列的巡檢。部署多個 `alert` 節點時，每次執行只會由一個節點領取。請參閱[依角色部署](/zh-Hant/deployment/role-based)。

以下兩項指標反映執行情況：

| 指標 | 含義 |
|---|---|
| `log_inspection_runs_total{outcome}` | 依結果統計已結束的執行次數：`succeeded`、`failed` 或 `timed_out`。 |
| `log_inspection_run_duration_seconds` | 單次執行的耗時。 |

## API

API 端點位於 `/api/v1/logs/inspections` 下：

| 方法與路徑 | 用途 |
|---|---|
| `GET /logs/inspections` | 列出組織的排程巡檢。 |
| `POST /logs/inspections` | 新增巡檢。 |
| `GET /logs/inspections/limits` | 取得執行個體設定的限制。 |
| `GET`、`PUT`、`DELETE /logs/inspections/{id}` | 讀取、完整更新或刪除單筆巡檢。刪除時會一併刪除報告。 |
| `POST /logs/inspections/{id}/enabled` | 啟用或停用巡檢。 |
| `POST /logs/inspections/{id}/run` | 立即執行一次。 |
| `GET /logs/inspections/{id}/runs` | 列出歷次執行，從最新到最舊排列，不含報告內文。`limit` 預設為 50，上限為 200；使用 `before` 查看更早的執行。 |
| `GET /logs/inspections/{id}/runs/{run_id}` | 取得單次執行及其報告。 |
