Codex 可以啟動 stdio MCP Server，也支援 MoleSignal 的 Streamable HTTP 端點與 OAuth 自動探索。

## 透過 stdio 連線（建議）

用戶端啟動 MoleSignal 命令列工具，由命令列工具將訊息轉送給 MoleSignal。需要 Node.js 20 或更新版本。

<Steps>
  <Step title="登入一次">

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

瀏覽器會開啟 MoleSignal，同意授權即可；命令列工具會儲存登入狀態並自動續期。

  </Step>
  <Step title="新增 MoleSignal">

```bash
codex mcp add molesignal -- npx -y @molesignal/cli mcp
```

也可以寫入 `~/.codex/config.toml`：

```toml
[mcp_servers.molesignal]
command = "npx"
args = ["-y", "@molesignal/cli", "mcp"]
```

  </Step>
</Steps>

沒有瀏覽器時不必登入，改在伺服器的環境變數中設定 `MOLESIGNAL_URL` 與 `MOLESIGNAL_TOKEN`（API 權杖）。請參閱[透過 stdio 連線](/zh-Hant/inbound-mcp#透過-stdio-連線)。

以下各節不使用命令列工具，改用 Streamable HTTP 連線。

## 使用 OAuth 2.1

<Steps>
  <Step title="註冊 MoleSignal">

    ```bash
    codex mcp add molesignal \
      --url https://molesignal.example.com/api/v1/mcp
    ```

  </Step>
  <Step title="授權連線">

    ```bash
    codex mcp login molesignal
    ```

    在瀏覽器中完成 MoleSignal 授權。

  </Step>
  <Step title="驗證伺服器">

    ```bash
    codex mcp get molesignal
    codex mcp list
    ```

    重新啟動目前的 Codex 工作或建立新工作，讓 Codex 重新載入 MCP 工具清單。

  </Step>
</Steps>

<Warning>
  請勿新增 `--oauth-resource`。MoleSignal 已透過 OAuth 探索中繼資料發布受保護資源；再次新增相同值可能觸發 `duplicate field resource`。
</Warning>

## 使用 API 權杖

非互動式 Codex 程序可以使用個人或服務帳號的 API 權杖：

```bash
export MOLESIGNAL_MCP_TOKEN="<api-token>"

codex mcp add molesignal \
  --url https://molesignal.example.com/api/v1/mcp \
  --bearer-token-env-var MOLESIGNAL_MCP_TOKEN
```

Codex 會儲存環境變數名稱，不會儲存權杖值。啟動 Codex 的程序必須能讀取該變數。

## 驗證工具探索

在 Codex 中輸入：

> 使用 MoleSignal MCP Server，搜尋事件相關工具並列出進行中的事件，不要執行任何變更。

首次請求應先使用 `tool_search` 探索工具，再透過 `call_read_tool` 呼叫找到的工具來讀取資料。

請參閱 [Codex MCP 官方文件](https://developers.openai.com/codex/mcp/)。
