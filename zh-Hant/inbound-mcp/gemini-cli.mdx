Gemini CLI 支援 stdio 與 Streamable HTTP Server、OAuth 自動探索，以及 MCP Tools、Resources 與 Prompts。

## 透過 stdio 連線（建議）

用戶端會啟動 MoleSignal 命令列工具，由工具將訊息轉送至 MoleSignal。需要 Node.js 20 或更新版本。

<Steps>
  <Step title="登入一次">

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

瀏覽器會開啟 MoleSignal，同意授權即可。命令列工具會保留登入狀態並自動續期。

  </Step>
  <Step title="新增 MoleSignal">

```bash
gemini mcp add molesignal npx -y @molesignal/cli mcp
```

  </Step>
</Steps>

如果沒有瀏覽器，不必登入，改在伺服器的環境變數中設定 `MOLESIGNAL_URL` 與 `MOLESIGNAL_TOKEN`（API 權杖）。請參閱[透過 stdio 連線](/zh-Hant/inbound-mcp#透過-stdio-連線)。

以下各節不使用 MoleSignal 命令列工具，改透過 Streamable HTTP 連線。

## 使用 OAuth 2.1

<Steps>
  <Step title="新增 MoleSignal">

    ```bash
    gemini mcp add --transport http --scope user \
      molesignal https://molesignal.example.com/api/v1/mcp
    ```

    省略 `--scope user` 時，Gemini CLI 會將設定儲存在目前專案的 `.gemini/settings.json`。

  </Step>
  <Step title="驗證身分">
    啟動互動式 Gemini CLI 工作階段，然後執行：

    ```text
    /mcp auth molesignal
    ```

    在瀏覽器中完成授權。Gemini CLI 會自動探索 OAuth 端點並執行動態用戶端註冊。

  </Step>
  <Step title="驗證伺服器">

    ```bash
    gemini mcp list
    ```

    在互動式工作階段中執行 `/mcp`，檢查已連線的 Tools、Resources 與 Prompts。

  </Step>
</Steps>

## 使用 JSON 設定

`~/.gemini/settings.json` 或 `.gemini/settings.json` 中對應的 Streamable HTTP 設定如下：

```json
{
  "mcpServers": {
    "molesignal": {
      "httpUrl": "https://molesignal.example.com/api/v1/mcp"
    }
  }
}
```

除非本機 Gemini Policy 明確要求略過用戶端確認，否則請勿對受控變更伺服器設定 `trust: true`。MoleSignal 伺服器端的核准政策仍然有效。

請參閱 [Gemini CLI MCP 官方文件](https://geminicli.com/docs/tools/mcp-server/)。
