開啟**追蹤**，在完整 trace、單一 span、RED 向下鑽研和服務圖之間切換。

## 瀏覽 trace 與 span

**追蹤**分頁中，每個請求各佔一列，顯示結束狀態（根 span 的 HTTP 狀態碼，或**正常**、**錯誤**）、開始時間、服務與操作、相對於本頁最長 trace 的耗時、span 數、錯誤數和 trace ID。點選**開始時間**、**耗時**、**Span 數**或**錯誤**欄標題，即可依該欄排序。表格上方的直方圖統計符合查詢的所有 trace，旁邊的圖表則繪製這些 trace 耗時的 p50、p95 和 p99。

**Span** 分頁中，每個符合條件的 span 各佔一列，顯示 span 類型和自身耗時。這裡的 span 欄位篩選條件只套用至 span 本身。

查詢編輯器有 **代碼** 和 **查詢建構器** 兩種模式，可用標題旁的兩個圖示切換（`</>` 代表代碼，積木代表查詢建構器）。**代碼** 模式支援欄位查詢（例如 `status_code = 'ERROR'`，或表示耗時超過 500 毫秒的 `duration_ns > 500000000`），也支援對 trace 資料流執行 SQL；**查詢建構器** 模式將欄位查詢顯示為多列篩選條件，每個分支各佔一列。與[日誌](/zh-Hant/logs#查詢分頁)相同，查詢會在分頁中執行，也能分成兩欄並排顯示。從欄位清單可開啟欄位分析，點選**分享**即可複製查詢連結。網址列也包含已套用的查詢，複製網址即可分享（請參閱[分享查詢](/zh-Hant/logs#分享查詢)）。

比較 span 欄位時，會保留至少有一個符合條件的 span 的 trace；`!=` 只保留所有 span 都不含該值的 trace。`trace_id`、`duration_ns`、`span_count` 和 `error_count` 直接在 trace 層級比較。`in` 可比對多個值中的任一值：`service.name in ('checkout', 'payments')`。

與[日誌](/zh-Hant/logs#撰寫查詢)相同，可以用 `AND` 和 `OR` 串接比較條件。`AND` 優先，也可以用括號分組。比較條件在 `OR` 中的含義不變：`service.name = 'checkout' OR span_count > 50` 會保留含有 `checkout` span 的 trace，以及 span 數超過 50 的 trace。未指定欄位的文字（例如 `timeout`）會在 trace ID、span ID、服務、操作和狀態中搜尋。**Span** 分頁和 RED 向下鑽研會以單一 span 為單位解讀同一筆查詢：span 符合 `a` 或 `b`，就符合 `a OR b`。

欄位清單與結果並排顯示。**常用欄位**排在最前面：`service.name`、`name`、`status_code`、HTTP 狀態碼和 `duration_ns`。展開欄位即可查看已載入的 trace 中有哪些值。**只看這個值**會將該值加入查詢（如果查詢有多個分支，會先用括號括住原查詢，讓這個篩選條件套用至整筆查詢）；在同一欄位選取第二個值時，會與第一個值合併成 `in` 清單，因此可以勾選多個值。**排除這個值**會排除該值。

透過**追蹤**表格上方的**欄位設定**，可以顯示或隱藏欄位、調整欄位順序，也可以將每筆 trace 的根 span 欄位加到表格中；欄位清單中這類欄位旁的眼睛圖示也能將欄位加到表格中。系統會依資料流為每位使用者儲存欄位配置。點選**還原預設值**即可回到表格的預設欄位配置。

## 檢查單筆 trace

點選任一列，即可在清單上方的側邊面板中開啟 trace。拖曳側邊面板的左邊緣即可調整寬度，開啟下一筆 trace 時會沿用相同的寬度。按 **J** 和 **K** 可分別切換至清單中的下一筆和上一筆 trace，也可以從側邊面板開啟該 trace 的詳細資料頁面。

trace 頁首固定顯示：根服務與操作、HTTP 狀態碼、錯誤數、耗時、開始時間、span 數、服務數、深度和 trace ID。**相關日誌** 和 **服務指標** 會開啟該 trace 前後的對應訊號。**效能剖析** 會開啟記錄了該 trace ID 的 profile；如果沒有這類 profile，就開啟該 trace 前後幾分鐘內的 profile。**使用者工作階段** 會開啟該 trace 所服務的 [RUM](/zh-Hant/rum) 工作階段：優先使用 span 在 `session.id` 或 `session_id` 指定的工作階段；如果未指定，就開啟瀏覽器請求在 `traceparent` 中帶有該 trace ID 的工作階段。

使用頁首末端的 **下載追蹤** 將 trace 儲存為檔案：

| 格式 | 內容 |
|---|---|
| **JSON** | 依照[追蹤 API](/zh-Hant/api/web/trace#讀取單筆追蹤)傳回的內容原樣儲存 span。 |
| **OTLP JSON** | OTLP/JSON 匯出請求，結構為 `resourceSpans` → `scopeSpans` → `spans`，可重新傳送至 Collector 或 OTLP HTTP 接收端。時間以十進位字串表示，單位為奈秒。 |

可用四種檢視查看 span：

| 檢視 | 顯示內容 |
|---|---|
| **瀑布圖** | 在時間軸上以樹狀結構呈現 span，每個服務各用一種顏色。拖曳上方的縮圖以選取時段，即可放大該段時間軸。搜尋後可逐一跳至符合條件的 span，也可以用開關只顯示失敗的 span，或聚焦於特定 span 及其下游。 |
| **火焰圖** | 每個 span 都是呼叫端下方的一個區塊。點兩下 span，即可將時間軸放大至該 span。 |
| **Span 清單** | 依服務與操作將 span 分組，顯示數量、錯誤、耗時、自身耗時，以及佔 trace 自身耗時的比例。 |
| **服務地圖** | 顯示該 trace 涉及的服務及其相互呼叫，並列出呼叫次數、耗時和失敗次數。 |

瀑布圖和火焰圖工具列的 **關鍵路徑** 會標出 trace 在端到端執行期間必須等待的 span。關鍵路徑從根 span 的結束時間開始往回追溯：在每個時間點，選取在此時間點之前最晚結束的子 span（子 span 的時間範圍以呼叫它的 span 為限），再從這個子 span 的開始時間繼續往回追溯。當時仍在執行的子 span 與路徑上的子 span 平行執行，因此不在關鍵路徑上。沒有子 span 涵蓋的時段計為呼叫端的自身耗時。在瀑布圖中，橫條上的線會標出該 span 位於關鍵路徑上的時段，其他 span 則會淡化。圖例會顯示關鍵路徑的長度，以及各服務所佔的比例。開啟後，切換至其他 trace 時會維持開啟。

選取 span 後，詳細資料會顯示在檢視旁，可拖曳調整寬度。詳細資料包含 **屬性**、**資源**、**事件**、**連結**、**日誌**、**指標** 和 **效能分析** 分頁。**連結** 也會列出其他 trace 中連結至該 span 的 span。**日誌** 顯示帶有該 trace ID 的日誌，範圍可以是單一 span 或整筆 trace。**指標** 會繪製該 span 所屬服務與操作在前後幾分鐘內的請求數、錯誤數和 p95 耗時。

**效能分析** 顯示 profiler 在該 span 執行期間擷取的樣本。profiler 記錄樣本時必須帶上追蹤內容（例如 [OTLP Profiles](/zh-Hant/profiles)），才能將樣本與 span 建立關聯。有關聯樣本時，分頁會針對特定 profile 類型，依自身消耗量列出消耗最多的函式。點選 **開啟火焰圖** 可繪製這些樣本，點選 **在 Profiles 中開啟** 則可在效能剖析頁面開啟這些樣本。瀑布圖中帶有火焰圖示的列，表示該 span 有關聯樣本。沒有關聯樣本時，點選 **查看此 span 前後的 profile** 即可開啟該 span 前後幾分鐘內的 profile。

每筆 trace 都有專屬的詳細資料頁面，開啟 trace 連結即可進入。如果瀏覽器 RUM 工作階段帶有 session 識別碼，可開啟**工作階段追蹤**查看相關後端請求。

## 比較兩筆 trace

點選**追蹤**表格上方的 **選取兩筆追蹤來比較**，再點選兩列。先選取的 trace 是 **A**，後選取的是 **B**。點選 **比較**，即可在 A 的詳細資料頁面開啟比較。也可以在 trace 頁首點選 **與另一筆追蹤比較**，再輸入另一筆 trace 的 trace ID。只要 trace 透過 OTLP 寫入，且在最近 31 天內開始，就能僅憑 trace ID 找到。

比較頁面會並排列出兩筆 trace、各自的耗時，以及 B 比 A 慢或快多少。下方有三個分頁，各分頁都將變化最大的項目排在最前面：

| 分頁 | 顯示內容 |
|---|---|
| **依服務** | 每個服務在 A 和 B 中的 span 數與自身耗時，以及從 A 到 B 的變化。 |
| **依操作** | 針對每個服務的各項操作，顯示相同的比較資料。 |
| **僅一側有** | 僅出現在其中一筆 trace 的呼叫。系統會依 span 的各個上層 span 的服務與操作進行比對，因此從兩處發出的相同查詢會算作兩次呼叫。對於另一側沒有的呼叫，會將下層呼叫的 span 計入該呼叫。 |

自身耗時是 span 本身的執行時間，不包含等待所呼叫的 span 的時間。頁首有 **交換 A 和 B** 和 **結束比較**。頁面網址會保留兩筆 trace，因此可以分享比較結果。

## 服務圖與服務目錄

**服務圖**會從 trace 的 span 自動衍生節點與邊，顯示請求率、錯誤率與延遲的關係，無須另外維護拓撲。

**服務目錄**依觀測到的服務與操作彙整資料，方便從服務開啟目前的 trace。

## 接收與傳播

透過 OTLP HTTP 或外部 OTLP gRPC Receiver 傳送 trace。MoleSignal 會保留標準 W3C Trace Context 和 OpenTelemetry 語意屬性。支援的應用程式請求會在回應中傳回 `X-Request-Id` 與 `X-Trace-Id`。

資料流上的[即時管線](/zh-Hant/pipelines#追蹤)會在尾端取樣後、寫入前修改或捨棄 span。trace 清單及其中的 span 數、錯誤數，都以實際寫入的 span 為準。

## 權限

組織工作區需要 `traces.read`。平台管理員在受保護的 `_sys` 遙測範圍內使用 `sys.telemetry.read`。
