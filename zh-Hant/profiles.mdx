持續剖析可用來找出服務的 CPU 用量、記憶體配置或鎖定等候情形。從主導覽開啟 **效能剖析**。

## 匯入 Profile

MoleSignal 支援：

- 透過外部 OTLP gRPC Receiver 接收 OTLP Profiles；
- 透過 `/api/v1/profiles/intake` 接收與 Pyroscope 相容的資料；
- 透過 `/api/v1/profiles/upload` 上傳 pprof 檔案；
- 直接在介面上傳單一 profile 檔案。

可查詢 Profile 中繼資料；標準格式的 pprof blob 會先壓縮，再存入物件儲存。

## 分析火焰圖

先設定時間範圍，再使用篩選列縮小分析範圍：

| 篩選 | 選項 |
|---|---|
| **服務** | 單一服務，或 **所有服務**。 |
| **Profile 類型** | 一次選擇一種類型，例如 **CPU**、**已配置的記憶體** 或 **鎖定競爭**。清單只會列出在時間範圍內有 Profile 的類型。 |
| **標籤篩選** | 一組 `key:value` 鍵值配對。 |

篩選列下方會以一行文字摘要分析結果：最熱門的函式及其自身開銷占比、樣本數、服務數和收集時間長度。

火焰圖會合併所選範圍內的 Profile。選取顯示已選數量的 **Profile** 按鈕，即可勾選要合併的 Profile。按一下面板中的任一列，即可單獨開啟該 Profile，其中提供 **下載 pprof** 和相關追蹤的連結。時間範圍內的 Profile 數量超過單次合併上限時，火焰圖會顯示均勻取樣的結果，並顯示提示。

三個檢視都使用同一份合併資料：

| 檢視 | 用途 |
|---|---|
| **火焰圖** | 寬度代表累計開銷，顏色代表自身開銷。按一下堆疊框，即可聚焦並開啟函式詳細資料。頂端的 `/` 堆疊框代表所有樣本。 |
| **呼叫樹** | 以可逐層展開的樹狀結構呈現相同的呼叫堆疊。 |
| **熱門函式** | 依自身開銷和累計開銷排序的函式。 |

工作區也支援依名稱醒目標示堆疊框和全螢幕分析。開啟 **即時** 後，會每 10 秒重新整理近期時段的資料。

## 比較兩個時段

在分析頁面選取 **比較 profile**。比較時會保留服務和 Profile 類型，並並列兩個時段：

| 時段 | 設定方式 |
|---|---|
| **比較時段** | 目前要檢查的時段。使用時間範圍控制項設定相對或絕對時間範圍。 |
| **基準時段** | 用來衡量比較時段的參考時段。**上一個時段**、**一天前的同一時段** 和 **一週前的同一時段** 會隨比較時段調整；**自訂時段** 可設為任意範圍。 |

隨比較時段調整的基準時段只有在兩者不重疊時才能選取。例如，比較時段長達三天時，無法選取 **一天前的同一時段**。

頁面會顯示各時段的 Profile 數量和 **總量變化**。如果兩個時段重疊，或兩者的 Profile 數量不同，頁面會顯示提示，因為部分變化來自收集數量的差異。

差異火焰圖會標示開銷增加或減少的函式。**變化最大的函式** 會依自身開銷的變化排序，只出現在其中一個時段的函式會標示為 **新增** 或 **消失**。在清單中選取函式，即可在火焰圖中標示該函式。這類比較適合分析發佈或設定變更後的效能退化。

## 區分應用程式與節點剖析

應用程式 Profile 屬於組織資料流，並會顯示在產品介面中。MoleSignal 也提供供平台維運使用的節點本機 pprof Listener。該 Listener 預設關閉，通常只應繫結至 loopback。

如需節點 Listener 與定期產生的 `_molesignal` Profile 相關資訊，請參閱[自身可觀測性](/zh-Hant/self-observability)。

## 寫入時修改中繼資料

[效能剖析的即時管線](/zh-Hant/pipelines#效能剖析)可改寫各筆 Profile 中繼資料中的標籤和服務名稱，也可排除不需列出的 Profile。管線不會修改 Profile 本身。

## 權限

- `profiles.read` 用於查找 Profile 資料，以及繪製和比較火焰圖。
- `profiles.write` 或匯入憑證用於傳送 Profile。

<Warning>
  Profile 可能會暴露函式名稱、程式碼配置和資源使用模式。請將 Profile 匯入、下載和節點 pprof Listener 視為敏感維運資料。
</Warning>
