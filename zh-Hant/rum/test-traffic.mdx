工作階段類型為 `user`、`synthetics` 或 `ci_test`。瀏覽器[探測](/zh-Hant/synthetics)開啟執行 0.3.0 以上版本[瀏覽器 SDK](/zh-Hant/rum/browser-sdk) 的頁面時，會產生 `synthetics` 類型的工作階段，不需設定。事件透過 `synthetics.test_id`、`synthetics.result_id`（這次執行結果的 `task_id`）、`synthetics.location_id` 分別標示探測、這次執行和位置。

## 對統計數據的影響

應用程式的統計數據反映真實使用者的活動，因此下列項目不計入測試驅動的工作階段：

- 總覽、效能、挫折、錯誤、分析、熱圖、功能旗標頁面和內建儀表板；
- [RUM 指標警示規則](/zh-Hant/rum/alerts)；
- 探索頁面的資料列和 Mole Agent 的 RUM 工具。

這類工作階段的錯誤不會建立[問題](/zh-Hant/rum/errors)，因此失敗的探測不會算成新問題。頁面排除這類工作階段時，會顯示 **未計入 N 個探測工作階段**，點選即可查看。

取樣也不會捨棄這類工作階段：應用程式的[保留設定](/zh-Hant/rum/sampling)會完整保留這些工作階段。若應用程式有篩選器指定 `session.type`，就表示應用程式已決定是否保留測試執行的工作階段，因此會和其他工作階段一樣，依篩選器和取樣比例處理。無論 SDK 本身的 `sessionSampleRate` 為何，SDK 都會保留這類工作階段。

## 如何找到工作階段

- 從單次執行：在瀏覽器探測結果的執行嘗試中，點選 **開啟這次探測的 RUM 工作階段**。
- 從工作階段：工作階段頁面會標示類型，並提供前往探測結果的連結。
- 在探索頁面：查詢指定 `session.type`、`synthetics.*` 或 `ci_test.*` 時，系統會依查詢傳回結果，因此可用 `session.type = 'synthetics'` 找到這類工作階段；查詢指定某個 `session.id` 時，系統也會依查詢傳回結果。未指定時，只顯示真實使用者的工作階段。`session.type` 的可用值清單涵蓋所有工作階段類型。
- 透過 API：`search`、`aggregate`、`facets`、`histogram` 的篩選條件也遵循相同規則。

## 應用程式自己的測試

在頁面上的任何指令碼執行前，設定同一個全域變數。在 Playwright 中，請使用以下寫法：

```ts
await page.addInitScript((id) => {
  window.__MOLESIGNAL_TEST_CONTEXT__ = { type: 'ci_test', test_execution_id: id };
}, process.env.GITHUB_RUN_ID);
```

SDK 會將記錄到的工作階段 ID 寫入 `window.__MOLESIGNAL_RUM_SESSION__`。探測會讀取這個 ID 來關聯工作階段，並在測試流程結束時離開頁面，讓 SDK 送出尚未傳送的資料。

<Note>
頁面必須執行比 0.2.0 更新的瀏覽器 SDK，工作階段才會標示觸發來源。SDK 的請求和其他請求一樣，都必須符合探測的對外連線政策。若政策不允許存取 MoleSignal，探測就會失敗。
</Note>
