MoleSignal Browser RUM SDK 收集頁面檢視、使用者互動、前端錯誤、Web Vitals、網路資源、長時間工作、[日誌](/zh-Hant/rum/logs)和追蹤關聯的上下文，並以 [RUM 事件](/zh-Hant/rum/events)的形式傳送。

## 先決條件

- MoleSignal 部署網址；
- 一個 [RUM 應用程式](/zh-Hant/rum/applications)，例如 `checkout-web`；
- 該應用程式的 Client Token；
- 透過 npm 安裝時，需要 Node 24 以上版本。

<Warning>
  `clientToken` 會包含在瀏覽器程式碼中，使用者可以看到。請勿使用擁有者、管理員或個人 Token，只使用與應用程式繫結的 Client Token。所有 Token 都以 `mspat-` 開頭，SDK 無法區分。
</Warning>

## 取得應用程式及其 Token

開啟 **使用者體驗 → 應用程式**，按一下 **建立應用程式**，選擇 **瀏覽器** 平台。應用程式頁面會隨即開啟，並顯示其 Client Token。**開啟整合精靈** 可查看端點、Token，以及已填入識別碼的範例。**資料來源** 中的 **Web RUM** 也會開啟同一個精靈。也可以透過 [API](/zh-Hant/api/auth/rum-token) 取得 Token。

## 安裝並初始化

<Steps>
  <Step title="安裝套件">
    ```bash
    npm install @molesignal/browser-rum
    ```
  </Step>
  <Step title="只初始化一次 SDK">
    ```ts
    import { init } from '@molesignal/browser-rum';

    const rum = init({
      applicationId: 'checkout-web',
      clientToken: 'mspat-your-client-token',
      site: 'https://molesignal.example.com',
      service: 'web-frontend',
      env: 'production',
      version: 'v1.4.0',
      sessionSampleRate: 100,
      trackUserInteractions: true,
    });
    ```

    `init` 會傳回用戶端。`initRum` 是同一個函式的舊名稱，`molesignalRum` 則是同一套 API 的單例形式：`molesignalRum.init(...)`、`molesignalRum.setUser(...)`。SDK 會保留在 `init` 前對 `molesignalRum` 的呼叫，並在 `init` 時重新執行這些呼叫。

    請在掛載應用程式路由前初始化 SDK，以擷取第一個頁面檢視。在伺服器端渲染期間可以安全地匯入並初始化此套件：SDK 只會在瀏覽器 API 可用時開始在瀏覽器端收集資料。
  </Step>
  <Step title="驗證第一個工作階段">
    開啟 **使用者體驗 → 探索**，選取涵蓋目前時間的時間範圍，確認工作階段已出現，接著開啟該工作階段，查看檢視、請求和錯誤。
  </Step>
</Steps>

`site` 可以是 MoleSignal 的來源網址，也可以是以 `/api`、`/api/v1` 或 `/api/v1/rum` 結尾的網址。SDK 會將事件傳送至 `POST /api/v1/rum/events`，並將重播片段傳送至 `POST /api/v1/rum/replay`。SDK 會將 `applicationId` 作為 `application.id` 傳送。如果事件的 `application.id` 與 Token 繫結的應用程式不符，MoleSignal 就會拒絕該事件。

## 透過 script 標籤載入

`dist/molesignal-rum.js` 是可獨立使用的套件，內含 rrweb 和 web-vitals，並定義全域變數 `MoleSignalRum`。使用以下程式碼非同步載入。傳給 `onReady` 的回呼會在指令碼載入完成後執行：

```html
<script>
  (function (w, d, s, u, n) {
    w[n] = w[n] || { q: [], onReady: function (callback) { w[n].q.push(callback); } };
    var script = d.createElement(s);
    script.async = 1;
    script.src = u;
    d.head.appendChild(script);
  })(window, document, 'script', 'https://cdn.jsdelivr.net/npm/@molesignal/browser-rum@0.4.0/dist/molesignal-rum.js', 'MoleSignalRum');

  MoleSignalRum.onReady(function () {
    MoleSignalRum.init({
      applicationId: 'checkout-web',
      clientToken: 'mspat-your-client-token',
      site: 'https://molesignal.example.com',
      service: 'web-frontend',
      env: 'production',
      version: 'v1.4.0',
    });
  });
</script>
```

若要同步載入，請使用 `<script src>` 標籤引入該檔案，再呼叫 `MoleSignalRum.init(...)`。

## 檢視與工作階段

檢視代表一次頁面瀏覽或一個路由。SDK 會在檢視開始時立即回報；檢視發生變化時會再次回報，並遞增 `view.revision`（每三秒最多一次）；檢視開啟期間每五分鐘回報一次；檢視結束時再回報一次。切換路由、結束工作階段、隱藏或卸載頁面都會結束檢視。SDK 透過 History API 和 `popstate` 偵測路由切換。設定 `trackViewsManually: true` 並呼叫 `startView`，即可自行命名檢視並決定何時開始。

SDK 不會傳送工作階段事件：MoleSignal 會從檢視推導出工作階段。SDK 將工作階段儲存在 Cookie `_msrum_s_<applicationId>` 中，讓應用程式的所有分頁共用。工作階段閒置達 15 分鐘或持續滿四小時就會結束。下次有使用者活動時，SDK 會開始新的工作階段。SDK 對每個工作階段只取樣一次，請參閱[資料取樣](/zh-Hant/rum/sampling)。設定 `trackSessionAcrossSubdomains: true` 或 `sessionCookieDomain: '.example.com'`，即可在子網域之間共用工作階段。`stopSession()` 會結束所有分頁的工作階段。如果沒有 Cookie，SDK 只會在記憶體中儲存工作階段，每個頁面各保留一份。

## 識別使用者並新增上下文

請盡量在初始化時提供使用者資訊，讓第一個工作階段包含正確的身分。

```ts
const rum = init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  user: { id: currentUser.id, plan: currentUser.plan },
  globalContext: { region: 'eu-west-1' },
});

rum.setUser({ id: 'user-42', name: 'Ada', email: 'ada@example.com' });
rum.setUserProperty('plan', 'enterprise');
rum.setAccount({ id: 'acme' });
rum.setGlobalContextProperty('checkout_step', 'payment');
```

`setUser` 至少需要 `id`、`name` 和 `email` 其中一項，其他索引鍵會保留為屬性。若未設定使用者，SDK 會在 `localStorage` 中建立固定的匿名識別碼。如果隱私權政策不允許持續儲存匿名身分，請設定 `trackAnonymousUser: false`。透過 setter 設定的上下文會加入之後的每個事件。SDK 會合併全域上下文、檢視上下文和呼叫時傳入的上下文，後者優先。

## 追蹤同意

```ts
const rum = init({ /* … */ trackingConsent: 'not-granted' });

rum.setTrackingConsent('granted');
```

在取得同意前，SDK 不會建立 Cookie、匿名識別碼或分頁識別碼，也不會啟用任何收集機制或傳送任何資料。撤回同意後，SDK 會停止收集，並清除識別碼和持久化佇列。

## 新增自訂操作、錯誤、耗時和指標

```ts
rum.addAction('Checkout submitted', { cart_size: 3 });

try {
  await submitOrder();
} catch (error) {
  rum.addError(error, { component: 'CheckoutForm' });
}

// 视图：配合 trackViewsManually 使用，或用来为路由命名。
rum.startView({ name: 'Order confirmation', context: { step: 3 } });
rum.setViewName('Order confirmation (3DS)');

// 自定义耗时和 Feature Flag 属于当前视图。
rum.addTiming('cart_ready');
rum.addFeatureFlagEvaluation('new_checkout', true);

// 时长。
const vital = rum.startDurationVital('checkout_form_ready', { description: 'form is usable' });
rum.stopDurationVital(vital);

await rum.flush();
```

在受控的導覽或關閉前呼叫 `rum.flush()`，並等待佇列中的事件傳送完畢。呼叫 `rum.stop()` 會移除收集機制，並送出用戶端佇列中的事件。[警示規則](/zh-Hant/rum/alerts#應用程式自行測量的指標)可監控自訂 timing 和 vital。[功能旗標](/zh-Hant/rum/feature-flags)有專屬頁面。[日誌](/zh-Hant/rum/logs)會寫入 `rum_logs` 資料流。

請在頁面就緒時呼叫 `rum.setViewLoadingTime()`，以當下的載入耗時取代原本的檢視載入時間。

## 連結至工作階段重播

`getSessionReplayLink()` 會傳回目前工作階段在 MoleSignal 中的網址，可附在工單或錯誤報告中。如果 SDK 尚未啟動、未取樣此工作階段，或尚未取得同意，就會傳回 `undefined`。SDK 會根據 `appUrl` 組合網址，預設值與 `site` 相同。如果開啟 MoleSignal 的網址和 SDK 傳送資料的網址不同，請設定 `appUrl`。

```ts
ticket.replay = molesignalRum.getSessionReplayLink();
```

開啟連結前須登入，並具備 `rum.replay.read` 權限。

## React

`@molesignal/browser-rum/react` 會將路由器的路由轉換成 SDK 檢視，依路由模式命名（`/orders/:id`，而不是 `/orders/42`），並回報元件樹擲出的錯誤。React 是選用的同儕相依套件。

```tsx
import { init } from '@molesignal/browser-rum';
import { reactPlugin, RumErrorBoundary, trackReactRouter } from '@molesignal/browser-rum/react';

init({ /* … */ plugins: [reactPlugin()] });
trackReactRouter(router); // createBrowserRouter 的路由器；TanStack Router 用 trackTanStackRouter

root.render(
  <RumErrorBoundary fallback={<Oops />}>
    <RouterProvider router={router} />
  </RumErrorBoundary>,
);
```

## 遠端設定

設定 `remoteConfiguration: true` 後，SDK 會在啟動前讀取[應用程式的 SDK 設定](/zh-Hant/rum/applications#sdk-遠端設定)。變更取樣率或隱私權等級時，不必重新發布頁面。

## 自動收集的預設值

| 資料 | 選項 | 預設值 |
|---|---|---|
| 頁面檢視 | `trackViewsManually` | 透過 History API 自動追蹤（`false`） |
| Fetch、XHR 和資源耗時 | `trackResources` | `true` |
| 長動畫影格與長時間工作 | `trackLongTasks` | `true` |
| 檢視的 Web Vitals | `trackWebVitals` | `true` |
| 點擊 | `trackUserInteractions` | `false` |
| 檢視中的頁面捲動深度 | `trackScroll` | `true` |
| Rage、Dead 和 Error 點擊 | `trackFrustrations` | 與互動追蹤一致 |
| 執行階段錯誤、未處理的 rejection、失敗的請求 | 內建 | 啟用 |
| `console.error` | `trackConsoleErrors` | `false` |
| 將主控台輸出寫入[日誌](/zh-Hant/rum/logs) | `forwardConsoleLogs` | `[]` |
| 將 SDK 本身的問題寫入日誌 | `trackSdkErrors` | `true` |
| 請求和回應的標頭 | `trackResourceHeaders` | `[]` |
| 從上一頁／下一頁快取還原頁面 | `trackBfcacheViews` | `false` |
| DOM 工作階段重播 | `sessionReplaySampleRate` | `0` |

SDK 會標示由測試觸發的工作階段類型，請參閱[測試流量](/zh-Hant/rum/test-traffic)。在點擊期間開始載入的資源、發生的錯誤和啟動的長時間工作都會帶有該點擊的 `action.id`，並計入該次點擊。SDK 會將失敗的請求記為來源是 `network` 的錯誤，並將請求寫入 `error.resource`。FCP、LCP 和 FID 描述頁面載入情況，並在初始檢視中回報。INP 和 CLS 來自 `web-vitals`，每次頁面載入只測量一次：SDK 會將各項指標記在發生決定性互動或版面位移的檢視上。

## 將瀏覽器請求與追蹤關聯

對於允許追蹤的 URL，fetch 和 XMLHttpRequest 整合會保留現有的 W3C `traceparent` 或注入新的值，接著從請求、回應或名為 `traceparent` 的 `Server-Timing` 項目讀取 trace 上下文。SDK 會將 trace ID 和 span ID 分別寫入 `resource.trace_id` 和 `resource.span_id`，MoleSignal 據此將瀏覽器請求與後端追蹤關聯。預設只會對同源請求注入和讀取 trace 上下文。對於跨來源 API，請公開回應標頭，並明確允許該來源：

```http
Access-Control-Expose-Headers: traceparent, server-timing
```

```ts
allowedTracingUrls: [
  'https://api.example.com',
  /^https:\/\/edge-\w+\.example\.com\//,
]
```

## 設定

| 選項 | 預設值 | 用途 |
|---|---|---|
| `applicationId` | 必填 | 應用程式的識別碼，作為 `application.id` 傳送 |
| `clientToken` | 必填 | 與應用程式繫結的 Client Token（`mspat-<36>`） |
| `site` | 必填 | MoleSignal 來源網址，或 `/api`、`/api/v1`、`/api/v1/rum` 網址 |
| `service` | `applicationId` | 事件的 `service` |
| `env`、`version` | 未設定 | 部署維度。查找 Source Map 時需要 `version` |
| `debugId` | 未設定 | 建置的 debug ID，會以 `debug_id` 寫入錯誤堆疊影格 |
| `user`、`account`、`globalContext` | 未設定 | 初始身分和自訂屬性 |
| `trackingConsent` | `granted` | 決定立即或延後開始收集所有資料及建立識別碼 |
| `sessionSampleRate` | `100` | 收集的工作階段百分比 |
| `sessionReplaySampleRate` | `0` | 已收集的工作階段中錄製重播的百分比 |
| `sessionInactivityTimeout` | `900000` | 工作階段因閒置而結束前的等待時間，單位為毫秒 |
| `maxSessionDuration` | `14400000` | 工作階段的最長持續時間，單位為毫秒 |
| `defaultPrivacyLevel` | `mask` | `mask`、`mask-user-input` 或 `allow`：控制傳送多少頁面內容和輸入內容。請參閱[隱私權](/zh-Hant/rum/privacy) |
| `trackUrlQueryString` | `false` | 在回報的 URL 中保留查詢字串 |
| `excludedUrls` | `[]` | 使用字串、RegExp 或回呼指定要排除的請求 URL |
| `allowedTracingUrls` | 同源 | 可接收及提供 trace 上下文的請求 |
| `traceSampleRate` | `100` | 請求啟動的 trace 中，要求後端保留的百分比（W3C sampled 旗標）。其餘請求仍帶有 trace 上下文，與 trace ID 的關聯不變 |
| `trackResourceHeaders` | `[]` | 依名稱或規則運算式指定要保留的 fetch、XHR 標頭。一律不保留憑證 |
| `forwardConsoleLogs` | `[]` | 同時寫入日誌的主控台方法：`'all'`，或從 `debug`、`log`、`info`、`warn`、`error` 中選取數個 |
| `trackSdkErrors` | `true` | 將 SDK 本身的問題寫入應用程式日誌，每次頁面載入最多寫入數筆 |
| `trackScroll` | `true` | 記錄每個檢視中的頁面捲動深度 |
| `compressIntakeRequests` | `false` | 瀏覽器支援時，使用 gzip 壓縮事件請求 |
| `remoteConfiguration` | `false` | 啟動前讀取[應用程式設定](/zh-Hant/rum/applications#sdk-遠端設定)指定的值 |
| `appUrl` | `site` | 開啟 MoleSignal 的網址，供 `getSessionReplayLink` 使用 |
| `plugins` | `[]` | 擴充 SDK 的外掛程式，例如 `reactPlugin()` |
| `enablePersistentQueue` | `true` | 重新載入後，從 IndexedDB 還原尚未傳送的遙測資料 |
| `flushInterval`、`batchSize` | `5000`、`50` | 傳送請求的時機和每個請求的事件數。每批最多 100 個事件 |
| `maxQueueSize` | `1000` | 離線時保留的事件數 |
| `beforeSend` | 未設定 | 檢查、修改或捨棄事件 |
| `onError` | 未設定 | 接收 SDK 的診斷資訊：上傳失敗、遭拒絕的事件 |
| `transport` | 瀏覽器 fetch | 透過自訂 Proxy 傳送 |

`beforeSend(event, { kind })` 會接收符合[事件格式](/zh-Hant/rum/events)的事件物件。傳回 `false` 就會捨棄該事件。不能捨棄 `view` 事件，否則計數會不一致。

## 傳送

SDK 會將事件加入佇列、分批傳送，並儲存在 IndexedDB 中，直到伺服器接受為止。遇到網路錯誤、`408`、`425`、`429` 或 `5xx` 時，SDK 會以指數退避方式重試請求，並遵循 `Retry-After`。SDK 不會重試 MoleSignal **拒絕**的事件，而會透過 `onError` 回報。遇到其他 `4xx` 時，SDK 會捨棄整批事件。佇列已滿時，SDK 會依序捨棄資源、長時間工作、重播、指標、操作、錯誤，最後才捨棄檢視。離開頁面時，SDK 會先透過一個 `keepalive` 請求傳送最重要的事件。同一個應用程式的多個分頁共用佇列，不會重複傳送彼此的事件。

## 從 0.2 升級

- `defaultPrivacyLevel: 'allow'` 現在會顯示輸入欄位中的內容，但密碼、電子郵件地址、電話號碼、銀行卡和一次性驗證碼欄位除外。`mask-user-input` 現在提供 `allow` 原本的行為。若要繼續遮罩輸入內容，請改用 `mask-user-input`。
- 點擊非控制項區域時，SDK 也會回報點擊事件。

## 從 0.1 升級

0.2 版將 SDK 遷移至 RUM 事件格式，不提供相容模式。

- SDK 只會將事件傳送至 `POST /api/v1/rum/events`，不再提供工作階段、操作和錯誤端點。自訂 `transport` 會收到 `kind: 'events' | 'replay'`。
- SDK 會傳送檢視，不再傳送工作階段。資源、長時間工作和頁面檢視各自是獨立事件。Rage 和 Dead 點擊會記在點擊事件的 `action.frustration.type` 中。
- `beforeSend` 會收到符合事件格式的事件物件，`context.kind` 是事件類型。
- SDK 會將工作階段儲存在分頁共用的 Cookie 中，預設閒置逾時為 15 分鐘。
- 伺服器會從 `User-Agent` 解析瀏覽器、作業系統和裝置。
- 請先建立應用程式。MoleSignal 只會為現有的應用程式核發 Token。
