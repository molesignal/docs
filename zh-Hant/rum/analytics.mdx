**RUM → 分析** 回答使用者在一次工作階段中做了什麼。一次分析一個應用程式，可查看單一環境或所有環境，並採用目前選取的時間範圍；如果開啟頁面時還沒選過，則預設為最近 7 天。這裡有三種檢視：**漏斗**、**路徑** 和 **留存**。瀏覽器應用程式和 App 都能使用這三種檢視；兩者的用詞不同，App 用「畫面」取代「頁面」。第四種檢視[**熱圖**](/zh-Hant/rum/heatmaps)則用來查看瀏覽器應用程式的單一頁面。

每種檢視的查詢條件都記在網址中，因此每個問題都能以連結分享。

## 漏斗

漏斗統計依序完成一連串步驟的工作階段，找出使用者在流程中（例如結帳）從哪一步流失。

### 步驟

一個漏斗有 2 到 8 個步驟。選取 **新增步驟** 可新增一步，選取步驟末端的叉號可移除該步驟。步驟有兩種類型：

| 類型 | 說明 | 可用欄位 |
|---|---|---|
| **頁面**（App 中為 **畫面**） | 開啟的頁面或畫面。 | **頁面分組**（`view.url_path_group`，將 ID 等會變動的部分歸併後的路徑）、**完整路徑**（`view.url_path`）、**檢視名稱**（`view.name`）。瀏覽器應用程式的頁面預設使用頁面分組，App 的畫面預設使用檢視名稱。 |
| **操作** | 使用者執行的動作，例如點擊、輕觸或自訂操作。 | **目標名稱**（`action.target.name`）、**目標選擇器**（`action.target.selector`）、**操作類型**（`action.type`）。 |

每個步驟都會在指定欄位中比對一個值。可從時間範圍內資料中最常見的值選取，也可直接輸入。**是** 要求比對完整的值，其中 `*` 代表任意文字。**包含** 會比對任何含有這段文字的值，不區分大小寫。

### 如何計算工作階段

第一步以該工作階段中第一筆符合條件的資料列計入。後續每一步都在同一個工作階段中，採用晚於上一步資料列且第一筆符合該步驟條件的資料列。兩步之間開啟其他頁面或執行其他操作都不影響計算：即使在購物車和結帳之間開啟了五個其他頁面，該工作階段仍算完成這兩步。

- **時間限制** 只計入在第一步之後指定時間內完成該步驟的工作階段：5 分鐘、30 分鐘、1 小時或 1 天內。**不限時間** 不論工作階段耗時多久都會計入。
- **工作階段依此分組** 依各工作階段計入第一步的資料列中的指定欄位分組，每個值各顯示一個漏斗。可依瀏覽器、系統、裝置類型、版本或國家分組，並保留工作階段數最多的 10 個值。**不分組** 則只顯示一個漏斗。

### 如何解讀結果

每個步驟各占一列，橫條長度代表該步驟的工作階段數占第一步的比例：

| 欄位 | 意義 |
|---|---|
| **工作階段** | 完成這一步的工作階段。 |
| **占第一步的比例** | 占第一步工作階段的比例。 |
| **流失** | 上一步的工作階段中，未到達這一步的比例。流失超過一半時以紅色顯示。 |
| **耗時中位數** | 從上一步到這一步所花時間的中位數。 |

依欄位分組的漏斗會多顯示一張表格：每個值各占一列，列出每一步的工作階段數，旁邊顯示占上一步工作階段的比例。最後一欄 **首尾轉換率** 顯示完成所有步驟的工作階段占第一步工作階段的比例。

如果沒有任何工作階段完成第一步，漏斗會顯示提示，並提供擴大時間範圍的選項。步驟、時間限制和分組欄位在網址中的參數分別是 `steps`、`win` 和 `by`。單一步驟的格式如下：頁面用 `v:`，操作用 `a:`，接著是欄位、`=` 或代表「包含」的 `~`，以及經過 URL 編碼的值；步驟之間以 `|` 連接。

## 路徑

路徑追蹤工作階段曾開啟的頁面：每欄顯示工作階段數最多的頁面，兩個頁面之間的連線越寬，代表從一個頁面前往另一個頁面的工作階段越多。

- **此頁面之後** 追蹤工作階段接下來開啟的頁面，**此頁面之前** 追蹤先前開啟的頁面。未指定頁面時，路徑從每個工作階段的第一個頁面開始；往前追溯時，則以最後一個頁面為終點。
- 可從資料中最常見的頁面選取，也可直接輸入。選取 **清除** 可移除選取的頁面。點選圖中的頁面，即可以該頁面為基準查看路徑。
- **顯示幾頁** 可設定在該頁面之後（或之前）顯示 1 到 6 頁，預設為 3 頁。
- **頁面依此區分** 可選擇頁面分組、完整路徑或檢視名稱（僅適用於瀏覽器應用程式）。

頁面區塊越高，代表開啟該頁面的工作階段越多。每一欄列出工作階段數最多的 8 個頁面，其餘合併為 **其他頁面**。連續開啟同一頁面（例如重新整理）只計一次。路徑以指定頁面為基準，將它放在第一欄；往前追溯時則放在最後一欄。不顯示沒有工作階段到達的欄。工具提示會顯示有多少工作階段未從該頁面繼續前往其他頁面（往前追溯時，則顯示有多少工作階段從該頁面開始）。

頁面、方向、頁數和區分欄位在網址中的參數分別是 `pivot`、`dir`（`before`）、`depth` 和 `page`。

## 留存

留存統計有多少使用者回訪。將時間範圍內首次出現在同一天或同一週的使用者歸為同一個同期群組。每個儲存格顯示該群組中有多少比例的使用者在相隔指定週期數後再次出現。

- 第一個選項是 **天** 或 **週**。週期以 UTC 的日界線為準，每週從星期一開始，因此同期群組以開始日期命名，不受檢視者的時區影響。
- 第二個選項設定要追蹤的週期數：**7 天後**、**14 天後** 或 **30 天後**。按週分組時則以週計算。
- 以工作階段的使用者 ID 辨識使用者。訪客沒有使用者 ID 時，則使用 SDK 儲存在裝置上的匿名 ID。
- 只在選取的時間範圍內判定使用者何時首次出現，因此時間範圍決定了可回溯的歷史。在範圍開始前來過的使用者，會在範圍內第一次出現的當天視為新使用者。
- 時間範圍結束時，尚未結束的週期無法判斷留存情況，儲存格會顯示橫線。
- **平均值** 以所有可計算該週期留存率的同期群組之使用者總數為基礎計算比例，因此較大的同期群組權重較高。

週期和週期數在網址中的參數分別是 `period` 和 `periods`。

## 分群

分群可將每種檢視的範圍縮小到一組工作階段，例如使用特定方案的客戶或來自特定國家的訪客。使用頁面頂端的 **分群** 選取群組，網址也會記錄所選分群（`segment`），因此針對分群的查詢同樣能以連結分享。這個索引標籤中的各種檢視都會沿用同一個分群，提供相同的頁面和可選的值。

在應用程式的[設定](/zh-Hant/rum/applications#分群)中定義分群。分群依據在整個工作階段中不變、且每筆資料列都有的資訊，例如使用者身分和執行位置。無法依工作階段中執行過的操作分群。

## 如何統計數字

每種檢視都透過一條查詢陳述式統計，由處理其他 RUM 查詢的同一個引擎執行，並讀取檢視、工作階段和操作資料。檢視資料的數字每次變動時都會重新寫入，查詢檢視的數字時會使用最新一筆資料。步驟只查詢每次寫入都相同的內容（頁面、應用程式、環境、版本、瀏覽器）時，直接讀取已寫入的檢視資料，不必為每個檢視挑出最新一筆。查詢檢視的數字（錯誤數、核心指標）或使用者身分時，則讀取最新一筆。引擎對讀取者遮罩的資料在這裡也會維持遮罩。統計耗時超過時間上限時，頁面會顯示提示並保持開啟，可縮小時間範圍後再查詢一次。也可透過 API 執行相同的查詢，請參閱 [`/api/v1/rum/analytics`](/zh-Hant/api/rum#漏斗、路徑與留存)。

效能參考：在一個 10 核心的節點上，時間範圍內有 100 萬個工作階段（1800 萬筆事件）時，四步驟的頁面漏斗約需 2 秒，八步驟約需 5 秒，路徑約需 6 秒，留存約需 1.5 秒。耗時會隨範圍內的工作階段數增加，漏斗的耗時也會隨步驟數增加。

應用程式[只保留部分工作階段](/zh-Hant/rum/sampling)時，漏斗和路徑會依每個工作階段的保留比例放大計數，以估算所有工作階段的數量。頁面會標示 **估算值**。留存只統計保留下來的工作階段中出現的使用者：取樣時，同期群組僅包含這些工作階段中的使用者，因此經常造訪的使用者更可能被納入。

此頁面需要 `rum.analytics.read` 權限。請參閱 [RUM](/zh-Hant/rum#權限)。

## Mole Agent

Mole Agent 使用 `get_rum_funnel`、`get_rum_paths` 和 `get_rum_retention` 執行相同的查詢。問題出在某個流程時，內建技能 `/rum-triage` 會使用這些工具，並提供連到此頁面的漏斗或路徑連結。
