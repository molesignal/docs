[警示規則](/zh-Hant/alerting)可以監控一項 **RUM 指標**，不必撰寫查詢。規則指定一個應用程式，可再縮小至特定環境、頁面和版本，並選擇下列其中一項指標。規則會依排程評估，與閾值或前幾天的同一時段比較，不需要資料流或陳述式。

指標的讀取方式與頁面相同，使用與[概覽](/zh-Hant/rum)、[探索](/zh-Hant/rum/explorer)相同的彙總資料：檢視和工作階段只按最新版本計算一次，百分位數只使用有值的檢視。因此，規則監控的數值，就是頁面在相同應用程式、環境、頁面和時間範圍下顯示的數值。

## 指標

| 指標 | `metric` | 含義 | 單位 | 所需資料列數 |
|---|---|---|---|---|
| **工作階段數** | `session_count` | 在時間窗口內開始的工作階段。 | 個 | 無 |
| **檢視數** | `view_count` | 在時間窗口內開始的頁面檢視，App 中則是畫面檢視。 | 個 | 無 |
| **錯誤數** | `error_count` | 在時間窗口內發生的錯誤。 | 個 | 無 |
| **錯誤率（發生錯誤的檢視）** | `error_rate` | 發生錯誤的檢視占全部檢視的比例。 | 百分比 | 100 個檢視 |
| **未當機的工作階段** | `crash_free_sessions` | 未當機的工作階段占全部工作階段的比例。 | 百分比 | 100 個工作階段 |
| **受挫的工作階段** | `frustration_rate` | 出現[受挫訊號](/zh-Hant/rum/frustration)的工作階段占全部工作階段的比例。 | 百分比 | 100 個工作階段 |
| **請求失敗率** | `failed_request_rate` | `fetch` 和 `xhr` 請求中未收到回應或收到 5xx 回應的比例。4xx 在此不算失敗。 | 百分比 | 200 個請求 |
| **LCP（p75）** | `lcp_p75` | 最大內容繪製的第 75 百分位數。 | 毫秒 | 50 個有值的檢視 |
| **INP（p75）** | `inp_p75` | 互動到下一次繪製的第 75 百分位數。 | 毫秒 | 50 個有值的檢視 |
| **CLS（p75）** | `cls_p75` | 累計版面配置位移的第 75 百分位數。 | 分數，0.1 以內為良好 | 50 個有值的檢視 |
| **首位元組（p75）** | `ttfb_p75` | 首位元組時間的第 75 百分位數。 | 毫秒 | 50 個有值的檢視 |
| **新問題** | `new_issues` | 在時間窗口內首次出現的[問題](/zh-Hant/rum/errors)。 | 個 | 無 |
| **再度出現的問題** | `regressed_issues` | 解決後在時間窗口內再度出現的問題。 | 個 | 無 |
| **受影響最大的問題波及的工作階段** | `issue_impact` | 時間窗口內波及最多工作階段的問題所波及的工作階段數，不論是哪個問題或持續多久。 | 個 | 無 |
| **自訂耗時（vital）** | `custom_vital` | 應用程式使用 `startDurationVital` 或 `addDurationVital` 測量的一段耗時，依名稱指定。 | 毫秒或次數 | 30 個資料列；統計**次數**時不需要 |
| **自訂時間點（timing）** | `custom_timing` | 應用程式使用 `addTiming` 標記的時間點，依名稱指定：從檢視開始到這個時間點的耗時。 | 毫秒或次數 | 30 個資料列；統計**次數**時不需要 |
| **Explorer 查詢** | `query` | 針對某一類資料列，從[探索頁面](/zh-Hant/rum/explorer)查詢符合的資料列計算出的數值。請參閱 [Explorer 查詢](#explorer-查詢)。 | 個，或欄位的單位（持續時間為毫秒） | 30 個資料列；計數和加總時不需要 |

工作階段或檢視歸入其**開始**的時間窗口。一分鐘前開始但尚未結束的工作階段也會計入。統計採用工作階段目前的狀態，因此時間窗口內最近幾分鐘的數值，看起來會比這些工作階段結束後略好。時間窗口越長，影響越小。

### 指標沒有值時

計數為零仍算有值，因此規則能偵測流量中斷。其他指標在時間窗口內的資料列數少於上表要求時**沒有值**：不符合任何閾值，不會觸發規則，已開啟的事件也會轉為已解決。這樣一來，流量少的夜間就不會因少數幾個檢視的 p75 觸發規則。規則中的**最少樣本數**可調整所需的資料列數；計數沒有這項設定。

### 應用程式自行測量的指標

自訂指標必須指定測量項目，填入 **Vital 名稱**或 **Timing 名稱**。編輯器會列出應用程式最近一天傳送過的名稱，也接受尚未傳送過的名稱。**值**指定規則如何取用這些數值：`p50`、`p75`（預設）、`p90`、`p95`、`p99`、平均值或測量次數。每個時間窗口只計算真實使用者的資料列，不計入[測試驅動的工作階段](/zh-Hant/rum/test-traffic)。

### Explorer 查詢

探索頁面的 **[新增警示](/zh-Hant/rum/explorer#新增警示)** 會以 **Explorer 查詢**指標開啟編輯器，也可在編輯器中手動填寫。

- **資料列類型**是查詢的目標類型：工作階段、檢視、操作、錯誤、資源、長時間工作或日誌。
- **查詢**的寫法與探索頁面的**代碼**模式相同：使用 `AND` 連接該類型的欄位比較條件，其餘字詞則在該類型的文字欄位中搜尋。編輯器會在欄位下方列出該類型不支援的條件，並忽略這些條件。留空代表該類型的所有資料列。
- **度量**為 `行数`、`不同值的个数`、`求和`、`平均值`、`最小值`、`最大值`，或 `p50` 至 `p99`；**欄位**是度量取值的欄位。持續時間以毫秒為單位。
- **在 Explorer 中開啟**會在探索頁面開啟此查詢，並繪製成時間序列圖。

規則和探索頁面一樣，只讀取真實使用者的資料列：只有查詢提及 `session.type`、`synthetics.*` 或 `ci_test.*` 時，才會計入合成監控與 CI 產生的工作階段。與所有 RUM 指標一樣，當應用程式[只保留部分工作階段](/zh-Hant/rum/sampling)時，計數、加總與平均值會按全部工作階段估算，而探索頁面只計算已儲存的資料列。若時間窗口內沒有符合的資料列，計數和加總為 `0`；其他度量預設需要 30 個資料列，可在規則中調整。請在查詢中指定頁面和版本，因此規則不提供**頁面**和**版本**設定。事件會以查詢最近符合的資料列所屬的工作階段作為樣本。

## 縮小規則範圍

| 篩選條件 | 適用指標 |
|---|---|
| **環境** | 所有指標。 |
| **版本** | 除了**新問題**、**再度出現的問題**（同一問題可能出現在多個版本）和 **Explorer 查詢**（在查詢中指定版本）外的所有指標。 |
| **頁面**（App 為**畫面**） | 適用於檢視、錯誤、請求與 vitals：**檢視數**、**錯誤數**、**錯誤率**、**請求失敗率**、**受影響最大的問題波及的工作階段**、四項 vitals，以及自訂指標。不適用於工作階段類指標（工作階段不只涵蓋單一頁面）、問題類指標和 **Explorer 查詢**（在查詢中指定頁面）。 |

編輯器會列出該應用程式最近一天出現過的環境、頁面和版本。頁面以 URL 路徑表示，會合併路徑中變動的部分，與其他頁面的定義一致。比較名稱時會使用原值，因此其中的 `*` 只代表字元本身。

新問題和再度出現的問題會依問題**出現的環境**計算。每個問題都屬於整個應用程式，系統會記錄問題在各環境中首次出現的時間：上週在預備環境首次出現的問題，若首次出現在正式環境，對正式環境而言就是新問題。未選擇環境時，以問題在應用程式中首次出現的時間判定是否為新問題。

## 建立規則

開啟**警示 → 警示規則**，點選**新增規則**。在**閾值規則**的資料來源中，**RUM 警示**與**指標告警**、**日誌告警**、**追蹤告警**和 **APM 警示**並列。選擇應用程式，視需要縮小範圍，選擇指標，再選擇評估窗口：5 分鐘、15 分鐘或 1 小時。編輯器會為每項指標預設適合的時間窗口（百分位數和比例使用 1 小時），以及常用的警示閾值。建立規則需要 `alerts.rules.manage`。

**測試規則**會繪製近期的指標曲線，每個時間窗口一個資料點，並疊加閾值。時間窗口為 5 或 15 分鐘時，顯示最近 6 小時；為 1 小時時，顯示最近 12 小時。最後一個資料點就是規則目前讀取的值。資料列數不足的時間窗口沒有值，也不會顯示資料點。預覽與規則評估使用同一段程式碼，因此圖表會反映規則實際採用的數值。

切換指標時，編輯器會重新設定閾值和時間窗口，因為指標的單位已變更。若指標無法縮小至頁面或版本範圍，表單會說明原因。

`alert` 角色每隔 `[alert].eval_interval_secs`（預設 30 秒），就會針對最近一個時間窗口評估一次規則。`for_periods` 計算連續跨越警示閾值的評估次數。數分鐘的時間窗口已能平滑指標波動，因此編輯器將 RUM 規則的起始值設為 1。請參閱[建立規則](/zh-Hant/api/alerting/create-rule#規則如何評估)。

## 從頁面查看警示

在概覽、錯誤、效能和受挫頁面中，**警示**位於說明頁面範圍的那一列末尾。旁邊的數字代表這個應用程式正在發生的事件數，並使用最嚴重事件的顏色。沒有事件時不顯示數字。這個按鈕只會在具備 `alerts.rules.read` 權限時顯示。

按鈕會開啟側邊面板，列出這個應用程式的警示。若頁面已選擇環境，則列出該環境的警示；若頁面顯示所有環境，則列出所有環境的警示。側邊面板沒有獨立的應用程式和環境設定，而是沿用頁面的設定。最緊急的項目會排在最上方。

- **正在發生**會列出這個應用程式中狀態為待處理或已確認的事件，最嚴重的排在前面。每筆事件都會顯示嚴重程度、所屬規則、規則的警示閾值及開啟時間。點選**開啟**可在頁面上方開啟該事件。
- **這個應用程式的規則**會列出監控這個應用程式的規則，包括所選環境和所有環境的規則，並將觸發中的規則排在前面。每條規則都會顯示狀態：**觸發中**、**已由處理管線捨棄**、**待定**、**正常**或**已停用**。**新增規則**會開啟規則編輯器，並預先填入應用程式和環境；**編輯**則會開啟指定規則。兩者都需要 `alerts.rules.manage`。
- **範本**會列出適合為這個應用程式建立的規則，可直接建立。

[效能頁面](/zh-Hant/rum/performance#單一值的組成)的資料列側邊面板中有**為此建立警示**。點選後會開啟規則編輯器，以目前分頁的 vital 作為指標，並將範圍縮小至該資料列的頁面或版本。

[探索頁面](/zh-Hant/rum/explorer#新增警示)查詢列中的**新增警示**會使用目前的查詢及其第一項度量開啟規則編輯器，指標為 [Explorer 查詢](#explorer-查詢)。

## 範本

範本是針對特定指標的規則，包含警示閾值和評估窗口。點選**建立**即可立即建立並啟用規則。規則採用 `scheduled`，以範本中的各個閾值對應各級嚴重程度，將 `for_periods` 設為 1，並使用預設升級策略。標籤與透過編輯器建立的規則相同，另加 `rum.template` 標明來源範本。規則以應用程式、環境和範本命名：`Storefront · prod · 页面加载变慢`。之後可在**警示 → 警示規則**中修改。建立規則需要 `alerts.rules.manage`；若缺少這項權限，按鈕會呈灰色並說明原因。

若已針對目前頁面的應用程式和環境使用範本建立規則，介面會顯示**已建立並啟用**及規則連結，取代按鈕，以免重複建立。切換至其他環境後可再次建立。為所有環境建立的規則不算在任何單一環境內。

每張卡片會顯示指標**目前**的值，依範本的時間窗口讀取，並使用與規則評估相同的程式碼。Core Web Vitals 也會標示數值為良好、待改進或差。若依範本建立的規則會立即觸發，卡片會加以說明。資料列數不足時，指標沒有值，卡片會顯示還缺多少資料列。

Core Web Vitals 的閾值採用 web.dev 公布的良好與差的分界。

| 範本 | 指標 | 警示閾值 | 時間窗口 |
|---|---|---|---|
| **網頁載入變慢**，建議 | LCP（p75） | 警告高於 2.5 秒，嚴重高於 4 秒 | 1 小時 |
| **互動變慢**，建議 | INP（p75） | 警告高於 200 毫秒，嚴重高於 500 毫秒 | 1 小時 |
| **網頁錯誤率**，建議 | 錯誤率 | 警告高於 2%，嚴重高於 5% | 15 分鐘 |
| **請求失敗率**，建議 | 請求失敗率 | 警告高於 2%，嚴重高於 5% | 15 分鐘 |
| **出現新問題**，建議 | 新問題 | 警告高於 0 | 15 分鐘 |
| **版面配置抖動** | CLS（p75） | 警告高於 0.1，嚴重高於 0.25 | 1 小時 |
| **受挫的工作階段** | 受挫的工作階段 | 警告高於 3%，嚴重高於 8% | 1 小時 |
| **再度出現的問題** | 再度出現的問題 | 嚴重高於 0 | 15 分鐘 |
| **影響重大的問題** | 受影響最大的問題波及的工作階段 | 警告高於 20，嚴重高於 100 | 1 小時 |
| **流量中斷**，選用 | 工作階段數 | 嚴重低於 1 | 15 分鐘 |

App 提供八個範本，以當機範本取代 Web Vitals 範本。**畫面錯誤率**衡量畫面的錯誤率。

| 範本 | 指標 | 警示閾值 | 時間窗口 |
|---|---|---|---|
| **當機變多**，建議 | 未當機的工作階段 | 警告低於 99.5%，嚴重低於 99% | 1 小時 |
| **畫面錯誤率**，建議 | 錯誤率 | 警告高於 2%，嚴重高於 5% | 15 分鐘 |
| **請求失敗率**，建議 | 請求失敗率 | 警告高於 2%，嚴重高於 5% | 15 分鐘 |

## 異常規則

**異常偵測規則**的資料來源包含 **RUM 指標**。規則會比較最近一個時間窗口與前幾天相同時段的指標，基準線與設定和[其他異常規則](/zh-Hant/alerting)相同。除了**新問題**和**再度出現的問題**以外，所有指標都可選用，因為這兩項指標沒有常態水準。

## 事件

在編輯器中建立的規則會帶有 `rum.application` 標籤，以及對應規則範圍的 `deployment.environment`、`rum.page` 和 `rum.version` 標籤。規則觸發的事件會複製這些標籤。事件開啟時，系統也會儲存最多三個指標表現最差的**工作階段樣本**。每個樣本包含工作階段 ID、時間、該工作階段的數值及相關資訊：vitals 最差的檢視及對應元素、最新錯誤及其訊息、當機或出現受挫訊號的工作階段，以及失敗的請求及其路徑。新問題和再度出現的問題會取這些問題最新錯誤所在的工作階段作為樣本。流量類指標沒有樣本。

可從**正在發生**、**警示 → 事件**或連結開啟事件側邊面板。面板在**工作階段樣本**中列出發生時間、使用者身分（姓名、電子郵件地址、ID，或由 SDK 儲存的未曾登入訪客 ID）、瀏覽器與作業系統，以及選為樣本的原因。若已錄製工作階段，點選**重播**會從該時間點前 5 秒開始播放；若未錄製，點選**工作階段**會開啟工作階段頁面。讀取工作階段的使用者身分和錄製狀態需要 `rum.sessions.read`；若缺少這項權限，每列仍會顯示發生時間及選為樣本的原因。

**在 RUM 中開啟**會前往顯示該指標的頁面，並保留應用程式、環境和頁面範圍。時間範圍從規則讀取的時間窗口開始前，到事件解決後不久；若事件仍在進行，則到目前為止。

| 指標 | 開啟 |
|---|---|
| 某項 vital | [效能](/zh-Hant/rum/performance)，定位至該項 vital；若規則指定頁面，則在該頁面的側邊面板中開啟 |
| 請求失敗率 | [資源](/zh-Hant/rum/performance#資源) |
| 錯誤數、錯誤率、新問題、再度出現的問題、未當機的工作階段 | [錯誤](/zh-Hant/rum/errors) |
| 受挫的工作階段 | [受挫](/zh-Hant/rum/frustration) |
| Explorer 查詢 | [探索頁面](/zh-Hant/rum/explorer)，開啟規則的查詢，將範圍限制在規則的應用程式和環境，並繪製成時間序列圖 |
| 工作階段數、檢視數 | [概覽](/zh-Hant/rum) |

## API 中的規則

RUM 指標規則在 `query` 中使用 `query.rum`，不包含陳述式或資料流。使用此設定[建立規則](/zh-Hant/api/alerting/create-rule)。

```json
{
  "name": "Storefront checkout is slow",
  "kind": "scheduled",
  "query": {
    "language": "sql",
    "statement": "",
    "periodSecs": 3600,
    "rum": {
      "applicationId": "storefront",
      "environment": "prod",
      "page": "/checkout",
      "metric": "lcp_p75"
    }
  },
  "trigger": { "operator": "gt", "threshold": 2500, "forPeriods": 1, "silenceSecs": 300 },
  "thresholds": [
    { "severity": "warning", "operator": "gt", "threshold": 2500, "forPeriods": 1 },
    { "severity": "critical", "operator": "gt", "threshold": 4000, "forPeriods": 1 }
  ],
  "labels": { "rum.application": "storefront", "deployment.environment": "prod", "rum.page": "/checkout" },
  "annotations": {}
}
```

`periodSecs` 是時間窗口，範圍為 60 秒至 6 小時。應用程式必須存在。若指標不支援縮小至頁面或版本範圍，帶有 `page` 或 `version` 的請求就會遭到拒絕。`minSamples` 為選填，計數指標不接受此欄位。閾值採用指標的單位。自訂指標還必須填寫 `custom_name` 和 `statistic`（`p50`、`p75`、`p90`、`p95`、`p99`、`avg`、`count`，預設為 `p75`）；其他指標不接受這兩個欄位。

RUM 頁面會依 `rum.application` 標籤尋找應用程式的事件（若頁面只顯示特定環境，則再依 `deployment.environment` 篩選），並依規則的 `query.rum` 尋找該應用程式的規則。透過 API 建立的規則只會帶有請求中指定的標籤，因此若要在頁面上統計及列出規則的事件，請加上這兩個標籤。從範本建立的規則還會帶有 `rum.template`，卡片會據此判斷是否已使用該範本建立規則。

`POST /api/v1/rum/alerts/preview` 是**測試規則**使用的 API 端點，請參閱 [RUM API](/zh-Hant/api/rum#預覽警示規則)。

## 權限

- `alerts.rules.read` 讓 RUM 頁面顯示 **警示**，側邊面板中有事件、規則和範本。
- `alerts.rules.manage` 可從範本建立規則、點選 **新增規則** 或在規則編輯器中建立規則，也可在規則上點選 **編輯**。
- `rum.events.read` 用於讀取預覽和範本說明中的指標目前值，`rum.sessions.read` 用於查詢事件對應的樣本工作階段。

請參閱 [RUM](/zh-Hant/rum#權限)。
