請在瀏覽器端套用隱私控制，避免敏感值離開使用者裝置。先使用預設遮罩模式，檢查實際記錄結果後，再視需要允許顯示內容。

## 安全的隱私預設值

```ts
init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  defaultPrivacyLevel: 'mask',
  trackUrlQueryString: false,
});
```

使用這些預設值時：

- SDK 會移除 URL 查詢參數和片段；
- SDK 會遞迴遮蔽使用者、帳號和上下文資料中鍵名為 `password`、`secret`、`token`、`authorization`、`cookie`、`api_key` 的值，以及信用卡欄位的值；
- 操作名稱為 `Click <结构化选择器>`，選取器不含 ID、測試 ID 或 class。只有設定 `defaultPrivacyLevel: 'allow'` 時，SDK 才會使用元素文字為操作命名；
- SDK 會遮罩工作階段重播中的 DOM 文字；
- SDK 會遮罩所有 Input 和 `contenteditable` 的值，使用 `mask-user-input` 時也一樣。

<Warning>
  依欄位名稱遮蔽只是最後一道防護，並非資料分類系統。請勿將憑證、付款資料、健康資料或非必要的個人資料加入使用者物件或自訂上下文物件。
</Warning>

## 封鎖或遮罩 DOM 內容

應用程式不必撰寫額外的 Recorder 程式碼，SDK 就能辨識下列隱私屬性：

```html
<section data-molesignal-block>
  <!-- 整个子树会替换为占位符。 -->
</section>

<span data-molesignal-mask>Account holder name</span>

<div data-molesignal-ignore>
  <!-- 忽略这个元素的变化和事件。 -->
</div>
```

也可以視需要替換預設選取器：

```ts
sessionReplay: {
  blockSelector: '.payment-form, [data-private-panel]',
  maskTextSelector: '.customer-name, [data-molesignal-mask]',
  ignoreSelector: '.animation-layer, [data-molesignal-ignore]',
},
```

封鎖機密資訊或大型敏感元件；若文字的版面配置仍有分析價值，請使用遮罩；若元素頻繁變動且無助於疑難排解，請忽略該元素。

## 顯示頁面、隱藏輸入內容

`defaultPrivacyLevel: 'mask-user-input'` 會記錄頁面文字，並遮罩輸入的內容，包括 Input 的值和 `contenteditable` 元素。這項設定適用於所有使用者看到的文字都相同的頁面。SDK 仍會遮罩符合所設定 `maskTextSelector` 的內容。

在 `mask` 層級下，也可以顯示已確認安全的區域：

```html
<nav data-molesignal-allow>Pricing · Docs · Sign in</nav>
```

`data-molesignal-allow` 會顯示這個元素及其中的文字。已封鎖、忽略或由 `maskTextSelector` 標記的內容不受影響，SDK 仍會遮罩 Input 和 `contenteditable` 元素。

## 謹慎允許顯示頁面上的可見文字

標記完所有敏感區域後，才可設定 `defaultPrivacyLevel: 'allow'`。這項設定也會顯示輸入的內容，但密碼、電子郵件地址、電話號碼、`autocomplete` 標示為銀行卡或一次性驗證碼的欄位，以及 `data-molesignal-mask` 內的欄位除外。SDK 仍會遮罩符合所設定 `maskTextSelector` 的內容。

```ts
defaultPrivacyLevel: 'allow',
sessionReplay: {
  blockSelector: '[data-molesignal-block], .payment-details',
  maskTextSelector: '[data-molesignal-mask], .customer-identity',
},
```

## 控制 URL 與網路收集

除非應用程式能確保查詢參數不含識別碼或機密資訊，否則請保留 `trackUrlQueryString: false`。在收集前排除敏感路由或網路端點：

```ts
excludedUrls: [
  '/account/security',
  /^https:\/\/api\.example\.com\/private\//,
  (url) => url.includes('/token-exchange'),
],
```

`allowedTracingUrls` 只控制哪些來源（Origin）可以提供追蹤上下文，不會啟用要求或回應主體的收集。SDK 只記錄耗時和清理後的 URL 中繼資料。

## 在接收事件時移除敏感文字

SDK 是第一道防線，伺服器端是第二道防線。無論事件來自哪個 SDK 或用戶端，應用程式都會在寫入任何內容之前，從每個事件移除所選類別的敏感文字。在 **RUM → 應用程式** 中開啟應用程式，再到 **敏感資料** 啟用或停用各類別。新建的應用程式預設啟用所有類別。

| 類別 | 移除的內容 | 取代為 |
|---|---|---|
| **權杖、金鑰和密碼** | Bearer 和 Basic 權杖、JWT、雲端與程式碼服務的金鑰（AWS 存取金鑰，以及 GitHub、GitLab、Slack、Stripe、OpenAI、Google 和 npm 權杖）、私密金鑰、`password=`、`secret:`、`api_key=`、`authorization:` 等字串後的值，以及 `Authorization`、`Cookie`、`Set-Cookie`、`Proxy-Authorization`、`X-API-Key`、`X-Auth-Token`、`X-CSRF-Token` 等要求標頭的值。 | `[secret]` |
| **電子郵件地址** | 格式如 `jane@example.com` 的地址。 | `[email]` |
| **電話號碼** | 以 `+` 開頭且含 8 到 15 位數字的國際電話號碼、11 位數的中國手機號碼，以及 `(415) 555-2671` 這類北美電話號碼。 | `[phone]` |
| **銀行卡號** | 由 13 到 19 位數字組成，數字群組之間可有空格或連字號，開頭符合卡組織的號段，且通過檢查碼驗證的號碼。 | `[card]` |
| **證件號碼** | 通過檢查碼驗證的中國居民身分證字號，以及美國社會安全號碼。 | `[id]` |
| **敏感的 URL 參數** | 查詢字串和片段中的參數值，適用於名稱為 `code`、`key`、`sig`、`sid`、`otp`、`ticket`、`email`、`phone` 等，或名稱含有 `token`、`secret`、`password`、`auth`、`signature`、`api_key`、`credential`、`jwt`、`session` 的參數。也會移除主機名稱前的使用者名稱和密碼。參數名稱保留。 | `[redacted]` |

應用程式會從下列位置移除敏感文字：事件發生位置和來源的網址（`view.url`、`view.referrer`、`resource.url` 和錯誤網址）、錯誤訊息、堆疊和成因、檢視和點擊目標的名稱、要求中的 GraphQL 操作名稱、承載資料和變數、要求與回應的標頭，以及 `context` 物件。應用程式也會將內嵌在文字中的網址當作網址處理，並保留堆疊中網址後的位置資訊（`:10:5`）。`user` 和 `account` 是應用程式刻意傳送的個人資料，會維持原樣。

應用程式會先移除敏感文字，再將事件拆分成多列，因此衍生內容也以保留的資料為準，包括原本含有電子郵件地址的網址所對應的 `view.url_path` 和 `view.url_path_group`，以及錯誤所屬的[問題](/zh-Hant/rum/errors)。只有電子郵件地址或數字不同的錯誤會歸為同一個問題。

<Warning>
  各類別依格式比對和驗證規則辨識內容，並不會對資料進行分類。看起來像電話號碼的數字，例如以 `13` 開頭的 11 位數訂單編號，會被當作電話號碼移除。自由文字中的姓名和住址則無法辨識。如果某個類別移除了疑難排解所需的內容，請停用該類別，並在 SDK 端防止敏感值進入事件。
</Warning>

變更只適用於之後收到的事件，不影響已儲存的內容。工作階段重播片段不會經過這項處理。SDK 會依照上述隱私層級遮罩其中的文字。

## 上線前檢查

<Steps>
  <Step title="記錄受控的測試工作階段">
    使用非正式環境的測試資料，走完登入、結帳、個人資料、搜尋和錯誤流程。
  </Step>
  <Step title="檢查各類事件資料">
    檢查工作階段中繼資料、操作名稱、URL、錯誤堆疊、自訂上下文和 DOM 重播。
  </Step>
  <Step title="新增選取器和排除規則">
    封鎖敏感子樹，並排除不必收集的路由。
  </Step>
  <Step title="介面變更後重新檢查">
    將隱私選取器納入正式環境設定。頁面結構變更時，務必重新測試。
  </Step>
</Steps>
