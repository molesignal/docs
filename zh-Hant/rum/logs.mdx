瀏覽器 SDK 寫入日誌時會附上當時的工作階段和檢視，因此可從日誌跳到重播，也可在工作階段頁面查看網頁寫入的日誌。只有寫入日誌或啟用主控台轉送時，SDK 才會傳送日誌。日誌功能需要[瀏覽器 SDK](/zh-Hant/rum/browser-sdk) 0.3.0 版以上。

```ts
import { molesignalRum } from '@molesignal/browser-rum';

molesignalRum.logger.info('打开购物车', { items: 3 });

const payments = molesignalRum.createLogger({ name: 'payments', level: 'warn', context: { provider: 'stripe' } });
payments.error('支付被拒', { code: 402 }, error);
```

logger 會略過低於其設定層級的日誌。層級有 `debug`、`info`、`warn`、`error`。若將錯誤當作第三個參數傳入，日誌會保留錯誤的類型和堆疊。

若要一併轉送網頁寫入主控台的內容：

```ts
init({ /* … */ forwardConsoleLogs: ['warn', 'error'] }); // 或者 'all'
```

轉送不會影響主控台原有的輸出。如果主控台可能包含個人資料，請勿啟用轉送，或確認應用程式已設定[擷取時清除敏感文字](/zh-Hant/rum/privacy#在接收事件時移除敏感文字)。這項設定也適用於日誌的文字和堆疊。

## 查看日誌的位置

- [工作階段頁面](/zh-Hant/rum/explorer)的重播下方有 **日誌** 分頁，會依序列出日誌，並醒目標示目前重播位置對應的那一列。點選任一列即可跳到對應的時間點。
- [探索頁面](/zh-Hant/rum/explorer)的資料列類型包含 **日誌**。
- 在 **日誌** 模組中，`rum_logs` 是一般的日誌串流，包含 `level` 和 `message`。層級長條圖等功能與其他日誌相同。

應用程式[不保留](/zh-Hant/rum/sampling)的工作階段也不會保留日誌。日誌不列入檢視計數。

## SDK 本身的問題

當 SDK 本身發生問題時（伺服器拒收事件、`beforeSend` 擲出錯誤），SDK 會寫入一筆日誌，logger 為 `molesignal-rum`，來源為 `sdk`。相同的問題只會記錄一次，每次載入網頁最多只會記錄幾筆。SDK 不會記錄傳送途中發生的問題，因為這類日誌同樣無法送達。使用 `trackSdkErrors: false` 關閉這項功能。無論是否關閉，SDK 都會呼叫 `onError`。

## 欄位

| 欄位 | 說明 |
|---|---|
| `level` | `debug`、`info`、`warn` 或 `error`。 |
| `message` | 內容。 |
| `log.id` | 日誌的 ID。 |
| `log.logger` | logger 的名稱：主控台為 `console`，SDK 本身為 `molesignal-rum`。 |
| `log.origin` | `logger`、`console`、`report` 或 `sdk`。 |
| `log.error_type`、`log.stack` | 這筆日誌記錄的錯誤類型與堆疊。 |
