真實使用者監控（RUM）記錄網頁與行動裝置的使用者體驗，並將前端遙測資料與後端可觀測性資料關聯。

## 資料如何流動

<Steps>
  <Step title="建立應用程式">
    [應用程式](/zh-Hant/rum/applications)是傳送資料的網站或 App。每個應用程式都有專用的 Client Token，只能用來寫入該應用程式的事件。
  </Step>
  <Step title="傳送事件">
    Browser SDK 與 Flutter SDK 會將 JSON [事件](/zh-Hant/rum/events)傳送至同一個端點。未使用 SDK 的用戶端可透過 HTTP 請求傳送相同的事件。
  </Step>
  <Step title="探索資料">
    MoleSignal 會檢查每個事件，補充位置、瀏覽器和裝置資訊，將事件寫入 RUM 資料流，再從檢視衍生出工作階段。在[探索](/zh-Hant/rum/explorer)中搜尋這些資料。
  </Step>
</Steps>

| 端點 | 用途 |
|---|---|
| `POST /api/v1/rum/events` | 依照[事件格式](/zh-Hant/rum/events)傳送檢視、操作、錯誤、請求、長時間工作和指標。 |
| `POST /api/v1/rum/replay` | 傳送瀏覽器 DOM 或 Flutter 畫面的回放片段。 |

兩個端點都使用應用程式的 Client Token。所有 RUM 端點請參閱 [RUM API](/zh-Hant/api/rum)。

## 資料模型

每種事件類型都有各自的一般 Logs 資料流，結構描述固定。工作階段衍生自檢視。

| 資料流 | 資料列 |
|---|---|
| `rum_sessions` | 每個工作階段一列。 |
| `rum_views` | 每次頁面瀏覽或每個介面一列。 |
| `rum_actions` | 每次點擊、輕觸或自訂操作一列。 |
| `rum_errors` | 每個錯誤一列，`error.issue_id` 包含所屬[問題](/zh-Hant/rum/errors)的 ID。 |
| `rum_resources` | 每個請求一列。 |
| `rum_long_tasks` | 每個長時間工作一列。 |
| `rum_vitals` | 每個指標一列。 |

檢視和工作階段有變更時會重新回報。探索頁面上的每一列和每次查詢的結果，都會顯示檢視或工作階段的最新版本。SQL 中的 `rum_views_latest` 和 `rum_sessions_latest` 是只包含最新版本的資料流（請參閱[查詢](/zh-Hant/query#rum-資料列的目前版本)）。

## 總覽

開啟 **使用者體驗** 時，會先看到 **總覽**。總覽一次顯示一個應用程式在所選時間範圍內的情況，可查看單一環境或所有環境。摘要會列出工作階段數、使用者人數，以及無錯誤的工作階段數。未傳送 Web Vitals 的 App 則改為統計無當機的工作階段和使用者人數。下方會顯示瀏覽器應用程式的三項 Core Web Vitals。各指標都有評分量尺（良好、待改善、不佳），標記會指出檢視的第 75 百分位數。點選指標即可開啟該指標的[效能](/zh-Hant/rum/performance)頁面。

再往下會顯示瀏覽量最高的頁面（App 則以畫面為單位），包括瀏覽量、各指標的第 75 百分位數，以及發生錯誤的檢視比例。這裡也會顯示工作階段的來源地圖、工作階段最多的國家、工作階段使用的瀏覽器、作業系統和裝置類型，以及最常造成使用者挫折的元素和各元素上最常見的操作類型。點選表格中的任一列或圖表中的任一長條，即可開啟探索並列出納入統計的資料列。

總覽頁首的 **在儀表板中開啟** 會開啟應用程式所屬平台的[內建 RUM 儀表板](/zh-Hant/dashboards#內建-rum-儀表板)，並自動選取目前頁面的應用程式和環境。

[`/api/v1/rum/aggregate`](/zh-Hant/api/rum#衡量資料列) 會根據每筆符合條件的資料列算出這些數字。如果統計耗時過長，該卡片會說明原因，不影響其他卡片。工作階段的國家資訊來自 IP 地理位置資料庫，因此未隨事件儲存位置的應用程式不會顯示地圖。

## 錯誤

**錯誤** 會依問題列出應用程式的錯誤。相似的錯誤會合併為同一個問題，並列出狀態（待處理、調查中、迴歸、已解決、已忽略）、團隊、負責人，以及出現的時間和版本。已解決的問題若在較新的版本再次出現，系統會自動標記為迴歸。每個問題的側邊面板會顯示發生趨勢、發生位置、還原後的堆疊、範例工作階段和受影響的使用者。詳情請參閱 [RUM 錯誤與問題](/zh-Hant/rum/errors)。

## 效能

**效能** 顯示瀏覽器應用程式的頁面在使用者開啟時的表現。摘要會列出 LCP、INP、CLS 的第 75 百分位數，並以各自的評級顏色標示，旁邊則顯示首次內容繪製和首位元組時間。圖表會依時間呈現所選指標的變化。每項指標各有一個長條，將瀏覽分為良好、待改善和不佳。表格會列出各頁面（或瀏覽器、國家、版本）的指標。點選任一列，側邊面板就會說明指標的組成、決定指標的元素，以及表現最差的幾次瀏覽。另有 **資源** 和 **長時間工作** 兩種檢視，用來查看頁面載入了哪些內容、哪些工作阻礙了載入。瀏覽器檢視會先顯示該次檢視的頁面載入過程。詳情請參閱 [RUM 效能](/zh-Hant/rum/performance)。

## 挫折

**挫折** 說明哪些情況會讓應用程式的使用者感到挫折。摘要會列出出現挫折訊號的工作階段比例（瀏覽器中包括連續點擊、無反應點擊和錯誤點擊；App 中包括連續點按和點按出錯），以及每種訊號涉及的操作次數和工作階段數。表格會依受影響的工作階段數列出元素、頁面、版本或瀏覽器。點選任一列，即可在面板中查看受影響的工作階段如何隨時間變化、訊號、版本、頁面，以及最近的工作階段。每個工作階段都可以從訊號出現前 5 秒開始回放。詳情請參閱 [RUM 挫折訊號](/zh-Hant/rum/frustration)。

## 分析

**分析** 透過三種檢視呈現使用者在一次工作階段中做了什麼。**漏斗** 統計依序完成一系列頁面瀏覽和操作的工作階段，並顯示完成每個步驟的比例和耗時，也可依瀏覽器、作業系統、裝置類型、版本或國家分組。**路徑** 追蹤工作階段在特定頁面之後（或之前）開啟了哪些頁面，並依造訪次數排列。**留存** 統計某天或某週首次出現的使用者人數，以及這些使用者在後續各個週期再次出現的比例。頁面開啟時會顯示最近 7 天的資料。詳情請參閱 [RUM 分析](/zh-Hant/rum/analytics)。**熱圖** 會在錄製的頁面上標示使用者點擊的位置，以及向下捲動的深度。請參閱 [RUM 熱圖](/zh-Hant/rum/heatmaps)。

## 功能開關

**功能開關** 會列出工作階段中評估過的功能開關，並比較不同開關值下的工作階段，包括錯誤、挫折和 vitals。在任何地方都可以用 `feature_flags.<key>` 篩選、分組和計算指標。請參閱 [RUM 功能開關](/zh-Hant/rum/feature-flags)。

## 警示

[警示規則](/zh-Hant/alerting)可以監控應用程式的一項指標：錯誤、無當機的工作階段、出現挫折的工作階段比例、請求失敗、Core Web Vitals 的第 75 百分位數，以及新問題和迴歸問題。規則會以與這些頁面相同的方式讀取指標，因此監控的數字和頁面顯示的數字一致。可依環境、頁面和版本縮小範圍。詳情請參閱 [RUM 警示](/zh-Hant/rum/alerts)。

在總覽、錯誤、效能和挫折頁面中，說明頁面範圍的那一列末尾有 **警示**。這個按鈕會顯示該應用程式進行中的事件數，並可開啟事件、規則，以及可一鍵建立規則的範本。詳情請參閱[從頁面設定警示](/zh-Hant/rum/alerts#從頁面查看警示)。

## 使用 Mole Agent 調查

**使用 Mole Agent 調查** 會開啟 Mole Agent，並針對目前顯示的內容建立新對話。總覽、錯誤、效能和挫折頁面的頁首，以及個別項目的詳細資料中，都有這個按鈕：

| 位置 | 問題中包含的內容 |
|---|---|
| **總覽**頁首 | 應用程式、環境和時間範圍。 |
| **錯誤**頁首 | 同一範圍內的應用程式錯誤。 |
| **效能**頁首 | Web Vitals 檢視中排在首位的 Core Web Vital；**資源**和**長時間工作**檢視中的頁面速度。 |
| 效能表格中的一列 | 頁面、瀏覽器、國家或版本符合該列值的檢視。如果該列的檢視數量足夠，也會納入排在首位的指標的第 75 百分位數。將游標停在該列上即可顯示按鈕；觸控螢幕上會一直顯示。 |
| **挫折**頁首 | 應用程式的使用者感到挫折的原因。 |
| 問題側邊面板（**調查**） | 問題、問題 ID 和相關錯誤。 |
| 挫折分組面板（**調查這個元素**、**調查**） | 元素及其選取器，或分組所用的頁面、版本、瀏覽器、作業系統。 |
| 工作階段頁首（**調查這個工作階段**） | 從開始到結束的整個工作階段。 |
| RUM 指標規則產生的事件（**使用 Mole Agent 調查**） | 警示、應用程式、事件時間，以及觸發警示的工作階段。對話仍屬於該事件，因此可將回答寫回為事件的根本原因分析（RCA）。 |

系統會將應用程式附加至對話，並預先在輸入框填入問題，供檢閱、編輯和傳送。只有點選傳送才會送出。只有具備 `agent.use` 權限才能看到這個按鈕。發起對話需要 `rum.events.read` 權限，在 `_sys` 範圍內則需要 `sys.telemetry.read` 權限。系統也會為該應用程式建立一筆[調查](/zh-Hant/agent#調查)記錄。

在任何問題中輸入 `@` 即可附加應用程式：輸入名稱，再從 **RUM 應用程式** 下選取。若傳送者沒有 RUM 讀取權限，系統會拒絕該訊息。模型會取得問題指定時間範圍內的下列內容（未指定時為最近 24 小時）：

- 工作階段數、使用者人數、無錯誤和無當機的工作階段比例，以及出現挫折的工作階段；
- 瀏覽器應用程式的 Core Web Vitals（第 75 百分位數及評級）和瀏覽量最高的頁面；
- 影響最多工作階段的未解決問題（最多三個），以及這些問題首次出現和迴歸的版本；
- 若具備 `alerts.rules.read` 權限，也會納入該應用程式目前觸發的警示。

Mole Agent 會使用 `get_rum_overview`、`list_rum_issues`、`get_rum_issue`、`get_rum_vitals`、`get_rum_frustration`、`get_rum_view_waterfall`、`aggregate_rum`、`get_rum_funnel`、`get_rum_paths`、`get_rum_retention`、`get_rum_heatmap`、`get_rum_feature_flags`、`get_rum_session_notes`，以及用於工作階段、行為、錯誤和關聯追蹤的工具讀取 RUM 資料。這些工具會讀取與頁面相同的資料，並沿用讀取者適用的欄位遮罩。內建技能 `/rum-triage` 會依序使用這些工具，查看總覽、問題、速度慢或卡頓的檢視、流程中的使用者歷程、工作階段，以及工作階段中請求的追蹤。結論中引用的證據會連結至這些頁面。

## 探索

從主導覽開啟 **使用者體驗**。**探索** 會列出真實使用者的工作階段、檢視、操作、錯誤、資源和長時間工作。使用欄位查詢縮小範圍，在直方圖中按時間查看數量，並在側邊面板開啟個別資料列。尚未有應用程式的工作區會顯示建立應用程式的方式。詳情請參閱 [RUM 探索](/zh-Hant/rum/explorer)。

**應用程式** 會列出應用程式及其 Client Token，也可在此設定要隨每個事件儲存哪些內容。詳情請參閱 [RUM 應用程式](/zh-Hant/rum/applications)。

## 工作階段與回放

從探索頁面開啟工作階段，即可查看回放、使用者資訊、問題、事件時間軸和關聯的後端追蹤。錄有 DOM 回放的工作階段會包含 `session.has_replay` 欄位，因此使用 `session.has_replay = true` 查詢時，只會列出這些工作階段。

工作階段頁首的 **複製此時間點的連結** 會複製可從目前時間點開啟回放的工作階段網址。[播放清單](/zh-Hant/rum/playlists)可收錄值得觀看的工作階段，並依序播放。回放可加入[留言和含章節的 AI 摘要](/zh-Hant/rum/session-replay#留言)，工作階段也會列出頁面[寫入的日誌](/zh-Hant/rum/logs)。

合成監控或 CI 測試產生的工作階段會標示類型，不計入真實使用者的統計。請參閱[測試流量](/zh-Hant/rum/test-traffic)。

請將回放視為敏感的使用者資料。在 SDK 中設定蒐集控制，避免記錄 Secret 或個人資料欄位，並盡可能縮短保留時間。

## 錯誤、Source Maps 與 Symbols

錯誤會隨附結構化的堆疊框架。收到錯誤後，系統會依類型、訊息和應用程式自身程式碼的前幾個框架合併成[問題](/zh-Hant/rum/errors)。透過 **使用者體驗 → RUM 設定 → Source Maps 與 Symbols** 上傳 Browser Source Map 或行動裝置的 Symbols。MoleSignal 會使用已上傳的偵錯成品，還原壓縮、混淆或原生的堆疊框架。讀取偵錯成品的中繼資料需要 `debug_artifacts.read` 權限；上傳和刪除則需要 `debug_artifacts.manage` 權限。

## 關聯後端追蹤

當請求包含 W3C `traceparent` 時，該請求的 `resource.trace_id` 會直接關聯至後端 Span。工作階段會列出其請求所帶的追蹤。如果沒有任何請求帶有追蹤 ID，工作階段詳細資料會在該工作階段的時間範圍內搜尋相關追蹤。

可從速度慢的前端請求直接跳至對應服務的追蹤、日誌和指標，同時保留調查脈絡。

也可以反向查看。如果某個追蹤的 ID 是由某個工作階段的請求送出的，**追蹤**中該筆追蹤的頁首會提供 **使用者工作階段**，可開啟對應的工作階段。

## 代理伺服器後方的用戶端 IP

RUM 事件來自網際網路上的瀏覽器和裝置。依預設，MoleSignal 會記錄直接連線的位址。若 MoleSignal 前方有反向代理伺服器或 CDN，所有事件都會帶有代理伺服器的位址，導致地理位置資訊不準確。開啟 **設定 → 用戶端 IP 識別**，選取單值請求標頭或轉送鏈，並列出受信任代理伺服器的 CIDR。MoleSignal 只會信任來自這些網路連線的請求標頭。這項設定適用於整個部署，不必重新啟動。

## 權限

- `rum.write` 用於傳送 RUM 事件。與應用程式繫結的 Client Token 只授予單一應用程式此權限。
- `rum.events.read` 用於開啟總覽、探索、效能和使用者挫折頁面。
- `rum.issues.read` 用於開啟錯誤頁面，`rum.analytics.read` 用於開啟分析頁面，`rum.applications.read` 用於開啟應用程式清單，`rum.playlists.read` 用於開啟播放清單。
- `rum.sessions.read` 用於開啟工作階段頁面，`rum.replay.read` 用於播放重播並讀取其留言和摘要。
- `rum.replay.comments.write` 用於在重播中留言及編輯自己發表的留言，`rum.replay.comments.manage` 用於編輯任何留言，`rum.replay.summaries.generate` 用於產生 AI 摘要。
- `rum.issues.manage` 用於設定 issue 的狀態、團隊和負責人。擁有者、管理員和編輯者具備此權限。
- `agent.use` 會在這些頁面顯示 **使用 Mole Agent 調查**，並允許透過 `@` 附加應用程式。
- `alerts.rules.read` 會在總覽、錯誤、效能和使用者挫折頁面顯示 **警示**，`alerts.rules.manage` 則允許在這些頁面建立規則。請參閱 [RUM 警示](/zh-Hant/rum/alerts#權限)。
- `rum.applications.manage` 用於建立、編輯和刪除應用程式，以及查看其 Client Token。
- `debug_artifacts.read` 用於列出偵錯成品的中繼資料。
- `debug_artifacts.manage` 用於上傳或刪除 Source Map 與行動應用程式的 Symbols。
