以下概念貫穿收集、查詢、警示、自動化與管理。

## 訊號

MoleSignal 處理四類遙測訊號：

- **日誌**是離散的結構化事件。
- **指標**是依標籤組成時間序列的數值樣本。
- **追蹤**是透過 `trace_id` 與父子關係串連起來的 Span。
- **效能剖析**以呼叫堆疊描述 CPU、配置、堆積或鎖定競爭樣本。

RUM 將記錄儲存在組織的資料串流中，並將瀏覽器工作階段與後端追蹤建立關聯。

[APM](/zh-Hant/apm) 不是第五種遙測資料串流。APM 是在尾端取樣前，從已去除重複項目的 trace span 衍生出的有界投影，因此取樣時捨棄的 trace 仍可納入服務、交易、相依性和錯誤的彙總。

## 資料串流

**資料串流**是收集和查詢共用的具型別契約，包含名稱、`streamType`、可演進的資料結構、保留原則、執行狀態與 `queryable` 開關。

支援的類型包括 `logs`、`metrics`、`traces`、`profiles` 和 `extend`。同一個名稱可以出現在多種類型下，因此 API 會同時使用兩個欄位識別資料串流：

```json
{ "name": "app", "streamType": "logs" }
```

如果備援資料來源只應提供資料給路由管線，不應出現在查詢選擇器中，請關閉 `queryable`。詳見[資料串流](/zh-Hant/streams)。

## 組織與工作區

**組織**是租戶與原則的界線。產品介面將目前選取的組織稱為**工作區**。遙測資料與產品資源各自只屬於一個組織，只有明確的跨組織授權或資源共用才能允許其他組織存取。

永久存在的 `_sys` 組織是受保護的平台範圍，用於系統遙測、平台管理員和全域組織操作。`_sys` 組織不是一般租戶。

## 產品資源

儀表板、已儲存的檢視、警示規則、值班排程、報告、函式、管線和 Agent 工作流程都是組織資源。Handler 在傳回或修改資源前，會載入目標資源、驗證其歸屬，並授權所要求的操作。

## 權限與角色

權限是 `streams.query`、`alerts.rules.manage`、`sys.telemetry.read` 等穩定的存取能力識別碼。角色是具名的權限集合，包含附加到角色的權限原則（可重複使用的權限集合，API Token 也可套用）和為角色個別設定的權限。內建的 Owner、Admin、Editor、Viewer 與 Platform Administrator 角色提供預設權限集合；自訂角色可用來定義範圍更小的職責。

導覽會使用實際生效的存取能力快照，但隱藏頁面不能取代後端授權。詳見[身分與存取](/zh-Hant/identity)。

## 時間與關聯

分析頁面共用時間範圍。透過關聯切換頁面時，系統會保留該範圍，並加入 `trace_id`、服務、主機或工作階段等識別資訊。這樣就能沿著 `RUM → 链路 → 日志 → 指标 → 性能剖析` 調查，同時不將導覽狀態當作授權依據。

## 儲存與查詢

日誌、指標與追蹤以分割的 Parquet 檔案儲存。效能剖析的中繼資料可供查詢，壓縮後的 pprof 檔案則儲存在物件儲存中。PostgreSQL 儲存檔案中繼資料、資料結構、IAM、產品資源與執行狀態。

DataFusion 與 Arrow 執行 SQL、相容於 PromQL 的指標查詢、本機搜尋和同盟掃描。查詢規劃器會在執行前，將授權的組織範圍加入查詢計畫。

## 執行角色

同一個執行檔透過 `[node].roles` 組合以下角色：

| 角色 | 主要職責 |
|---|---|
| `standalone` | 在單一處理程序中執行所有 API 與 Worker。 |
| `router` | 提供完整的 HTTP API 與網頁介面、限制請求速率，並將請求轉送至 intake 與 querier 節點。 |
| `intake` | 驗證資料、執行管線、處理 WAL 與緩衝，並將資料寫入 Parquet。 |
| `querier` | 執行其他節點轉送的查詢。 |
| `compactor` | 執行合併、管理資料保留並維護儲存空間。 |
| `alert` | 評估規則、安排值班、升級警示並傳送通知。 |

元件與資料串流詳見[架構](/zh-Hant/architecture)。
