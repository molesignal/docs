合成監控會從外部主動驗證服務，在客戶回報之前發現故障。開啟**合成監控**，建立檢查、發布排程、檢視執行證據並管理私有 Probe 位置。

## 可以監控什麼

| 檢查類型 | 適用情境 |
|---|---|
| **HTTP / API** | 驗證 URL、方法、標頭、主體、回應狀態、內容與耗時。 |
| **瀏覽器** | 執行瀏覽器操作流程，並驗證頁面或步驟的結果。 |
| **TCP** | 確認可與指定的主機和連接埠建立連線。 |
| **DNS** | 透過系統或指定的解析器解析任意類型的記錄（A、AAAA、CNAME、MX、NS、TXT、SOA、SRV、CAA、PTR），可要求使用 DNSSEC，並驗證解析結果與回傳碼。 |
| **ICMP / Ping** | 傳送數個 ping，檢查封包遺失率與平均往返時間。 |
| **TLS** | 驗證 TLS 交握、憑證身分與到期時間。 |
| **gRPC** | 呼叫 gRPC 端點並驗證回應。 |
| **Heartbeat** | 要求外部工作或服務在截止時間前主動回報。 |

gRPC 檢查的 **位址** 請依 `主机:端口` 格式填寫。是否使用 TLS 只由 **使用 TLS** 決定。如果位址中的通訊協定與開關設定衝突（例如開啟 **使用 TLS** 卻填寫 `http://`），系統會拒絕該位址。

## 建立並發布檢查

<Steps>
  <Step title="建立草稿">
    開啟**合成監控 → 檢查**，選取**建立檢查**並指定類型。設定目標、逾時、斷言、排程與一或多個位置。新檢查會先儲存為草稿。
  </Step>
  <Step title="測試修訂版本">
    選取**測試修訂版本**。MoleSignal 會執行草稿，但不會啟用排程。確認最終目標、嘗試次數、各階段耗時、斷言證據與錯誤。
  </Step>
  <Step title="發布修訂">
    測試成功後，才能選取**發布修訂**。發布會啟用該修訂版本，並計算首次排定的執行時間。
  </Step>
  <Step title="管理 Monitor">
    選取**立即執行**，手動執行一次。編輯已發布的檢查會產生新草稿，舊版本會繼續依排程執行，直到替代版本通過測試並發布。暫停、恢復或封存都不會刪除現有結果。
  </Step>
</Steps>

<Note>
草稿驗證流程可避免未經驗證的目標或斷言直接取代正式環境中正常運作的排程。
</Note>

## 排程與重試

使用固定間隔或明確指定時區的 Cron 運算式。多數主動檢查支援 10 秒到一天的間隔，瀏覽器檢查的間隔至少為 60 秒。逾時範圍為 100 毫秒到 5 分鐘，且必須短於排程間隔。每次執行最多可重試兩次，之後記錄最終結果。

Heartbeat 不會發出對外請求，而是等待工作在截止時間前回報。由執行該工作的工作負載傳送心跳訊號，再透過結果記錄區分延遲回報與實際失敗。

## 斷言與健康狀態

斷言可檢查回應狀態、主體、標頭、DNS 回覆、憑證屬性或瀏覽器步驟等欄位。**警告**斷言失敗時，結果為降級；**嚴重**斷言失敗時，結果為失敗。

每種檢查只能對其回傳的值套用斷言：

| 檢查類型 | 斷言來源 |
|---|---|
| **HTTP / API** | `status`、`body`、`json:<JSONPath>`、`header:<名称>`、`duration_ms`、`size_bytes`、`timing.dns_ms`、`timing.connect_ms`、`timing.tls_ms`、`timing.first_byte_ms` |
| **TCP** | `response`、`duration_ms` |
| **DNS** | `answers`、`answer_count`、`rcode`、`duration_ms` |
| **gRPC** | `status`（健康檢查服務回傳的服務狀態，例如 `SERVING`）、`duration_ms` |

儲存修訂版本時，系統會拒絕檢查未提供的來源。

在 `json:` 後加上 JSONPath（RFC 9535），即可讀取回應主體前 4 MiB 內的 JSON。找到單一字串時，傳回字串本身；找到其他單一值時，傳回其 JSON 文字；找到多個值時，傳回由這些值組成的 JSON 陣列。找不到值或回應主體不是 JSON 時，傳回空值。`body` 也支援**符合 JSON Schema** 斷言，同樣只讀取前 4 MiB。斷言失敗時，會指出第一處不符合的位置。Schema 不得以 `$ref` 參照外部 URL 或檔案。`size_bytes` 是回應主體的位元組數，最多讀取 16 MiB；`timing.*` 是該步驟各階段的耗時，未經過的階段記為 0。使用 JSONPath 擷取變數時，不需要撰寫正規表示式，可直接取得值。

如果無法解析目標、無法連線、連線中途斷開、TLS 交握失敗，或在逾時前未收到回應，這次執行的結果就是失敗，與嚴重斷言失敗相同。只有無法依設定執行檢查時，結果才是未知，例如對外連線原則封鎖目標、缺少金鑰，或使用不支援的設定。

Monitor 會依連續成功與失敗的次數及選取的位置計算健康狀態。設定失敗門檻、恢復門檻與位置策略，避免狀態頻繁變動，也避免將單一網路異常誤判為全域故障。

## HTTP 連線

HTTP 檢查的**連線**區段決定如何連到伺服器。未指定時採用預設設定：

| 設定 | 用途 |
|---|---|
| **HTTP 版本** | 選擇**自動協商**時，會在 TLS 交握中同時提供 HTTP/2 與 HTTP/1.1，由伺服器選擇；未加密的 HTTP 使用 HTTP/1.1。選擇**僅 HTTP/1.1** 時，只提供 HTTP/1.1。選擇**僅 HTTP/2** 時，如果伺服器不接受 HTTP/2，檢查就會失敗；未加密的 HTTP 則依事先約定直接使用 HTTP/2（h2c）。 |
| **DNS 伺服器** | 使用這台伺服器解析網域名稱，格式為 `主机` 或 `主机:端口`。連往這台伺服器的流量也受對外連線原則限制。 |
| **Host 繫結** | 將網域名稱指向指定的 IP，作用與 hosts 檔案相同。請求的 Host 與憑證驗證仍使用原網域名稱，適合檢查特定來源伺服器或 CDN 節點。 |
| **用戶端憑證** | 提供伺服器要求雙向 TLS 時使用的 PEM 格式憑證鏈與私密金鑰。可上傳檔案或直接貼上；若兩者在同一個檔案中，系統會分別填入對應欄位。系統會加密儲存私密金鑰，儲存後不再顯示。修改檢查時，將欄位留空即可沿用原有金鑰。 |

每個步驟的結果都會記錄實際連線的位址（`remote_address`）與伺服器使用的 HTTP 版本（`http_version`）。

## 追蹤關聯與失敗診斷

檢查的**診斷**區段有兩個開關，預設都會開啟。

**關聯追蹤**：HTTP 檢查的每個請求（包括重新導向後的請求）與 gRPC 檢查的呼叫都會附帶 W3C `traceparent`。同一次嘗試中的請求屬於同一筆追蹤，每個請求都是其中一個 span。如果步驟已設定 `traceparent` 請求標頭或中繼資料，就會保留原值，不再另加。步驟與結果都會記錄 `trace_id`。在結果詳細資料中選取**檢視追蹤**，即可開啟受測服務為這次請求記錄的追蹤。如果受測服務未整合追蹤功能，就查不到資料。gRPC 檢查設定的中繼資料也會隨呼叫送出。

**失敗時執行 traceroute**：HTTP、TCP、TLS、gRPC、SSH 或 ICMP 檢查無法連上目標時（連線失敗、逾時、連線中斷、TLS 交握失敗，或 ping 未收到回應或發生封包遺失），Agent 會對最後一次嘗試連線的位址執行一次 ICMP traceroute：最多 30 跳，每跳探測 4 次，最長執行 12 秒。結果詳細資料會以表格逐跳列出位址、封包遺失情形，以及最短、平均與最長往返時間。traceroute 需要原始通訊端（root 或 `CAP_NET_RAW`），或不需特權的 ICMP 通訊端（macOS，以及位於 `net.ipv4.ping_group_range` 範圍內的 Linux 群組）。如果兩者都無法使用，步驟會註明未執行的原因。

舊版 Agent 不會傳送 `traceparent` 或執行 traceroute，但不影響檢查結果。

**RUM 工作階段**：瀏覽器合成監控會在頁面執行任何指令碼前，告知頁面這是一次測試。如果頁面執行[瀏覽器 RUM SDK](/zh-Hant/rum/browser-sdk)，SDK 就會記錄一個 `synthetics` 類型的工作階段。在該次嘗試中選取 **開啟這次探測的 RUM 工作階段**，即可檢視工作階段重播與事件。這類工作階段[不計入真實使用者的統計資料](/zh-Hant/rum/test-traffic)。是否執行 SDK 由頁面決定；未執行 SDK 的頁面不會產生額外資料。

## 時間範圍與可用率

總覽、檢查清單、結果頁面與檢查詳細資料的總覽，都可在導覽卡片右側選擇時間範圍。開啟頁面時預設為最近 24 小時，也可改選其他範圍。

- **可用率** = 結果為可用的執行次數 ÷ 結果已判定的執行次數。通過、不穩定與降級都算可用，失敗不算；未知與略過不列入計算。
- 總覽顯示時間範圍內所有檢查的可用率與趨勢，並依位置在地圖上標示不同顏色。檢查清單另外顯示各項檢查的可用率。檢查詳細資料顯示該範圍內的可用率、回應時間中位數與 p95；**各位置的回應時間** 會依時間間距繪出各位置的耗時中位數。
- **最近一次執行** 的小條形圖仍會顯示最近幾次執行的結果，不受時間範圍影響。

可用率來自 `GET /api/v1/synthetics/availability`，參數為 `from`、`to`（微秒）、`monitor_id`、`location_id`、`step`（秒，未提供時依時間範圍選擇）。API 會回傳整體、依檢查、依位置及依時間間距統計的執行次數、可用次數、失敗次數、未判定次數、可用率，以及 P50、P95 與最長耗時。指定檢查時，還會回傳各位置依時間間距統計的資料。結果清單 `GET /api/v1/synthetics/results` 接受 `fromTime`、`toTime`。

## 結果資料流與保留期限

每次排定的執行（測試執行除外）除了儲存結果詳細資料，還會在組織的 `_synthetic_results` 日誌資料流寫入一筆記錄，並以執行開始的時間為時間戳記。不寫入沒有值的欄位。

| 欄位 | 內容 |
|---|---|
| `check_id`、`check_name`、`check_kind`、`revision_id` | 檢查與執行時使用的修訂版本 |
| `location_id`、`location_name`、`agent_id` | 執行位置與執行檢查的 Agent |
| `result_id`、`outcome`、`available`、`attempts` | 結果、是否可用（未知與略過時不填）、嘗試次數 |
| `duration_ms`、`dns_ms`、`connect_ms`、`tls_ms`、`first_byte_ms` | 最後一次嘗試的總耗時與各階段耗時 |
| `status_code`、`error_category`、`skip_reason`、`trace_id` | HTTP 狀態碼、失敗類別、略過原因、追蹤 |
| `team_id`、`tags` | 檢查所屬的團隊與標籤（以逗號分隔） |

儀表板面板與警示規則使用 SQL 查詢這個資料流。面板的時間範圍會套用至查詢。以下範例查詢各項檢查的可用率與 p95 耗時：

```sql
SELECT check_name,
       avg(CASE WHEN available THEN 1.0 ELSE 0.0 END) AS availability,
       approx_percentile_cont(0.95) WITHIN GROUP (ORDER BY duration_ms) AS p95_ms
FROM _synthetic_results
WHERE available IS NOT NULL
GROUP BY check_name
```

排程警示規則查詢相同的資料，並依 `location_name` [按維度分組](/zh-Hant/alerting/rules#依維度分組)。每個位置的可用率低於門檻時，會各自建立一個事件。

結果詳細資料預設保留 30 天。若要修改，請前往平台設定的 **資料保留**，調整 **合成監測結果**（0 表示永久保留）。請參閱[平台設定](/zh-Hant/settings/platform#資料保留)。系統每天清理一次超過保留期限的執行結果及其附件，以及已結束的工作。`_synthetic_results` 資料流依自身的保留期限保留資料，可在資料流頁面修改。

## 地點與 Probe Agent

MoleSignal 支援兩種地點：

| 地點 | 行為 |
|---|---|
| **內建本機地點** | Standalone 會自動在程序內啟動 Probe runner，適合在本機評估，或從 MoleSignal 所在的網路發起檢查。 |
| **Agent Pool** | 一或多個外部 <code>probe-agent</code> 從私人網路、區域或邊緣地點執行檢查。 |

在**合成監控 → 地點**中建立 Agent Pool 地點並產生一次性註冊 Token，然後註冊 Agent：

```bash
probe-agent register \
  --endpoint https://molesignal.example.com:5084 \
  --token ONE_TIME_TOKEN \
  --ca-certificate-base64 BASE64_CA
```

接著啟動控制串流：

```bash
probe-agent run
```

註冊程序使用伺服器端 TLS。Agent 將私有身分儲存在 <code>--state-dir</code> 下，並透過 5085 連接埠的 mTLS 控制串流接收工作。預設目錄為 <code>/var/lib/molesignal-probe</code>。

在 <code>conf/config.toml</code> 中設定伺服器端端點：

Probe 控制平面會在 **Standalone** 與 **Alert** 節點自動啟動，不提供個別的啟用開關。

```toml
[probe]
bind = "0.0.0.0"
register_port = 5084
control_port = 5085
register_endpoint = "https://molesignal.example.com:5084"
control_endpoint = "https://molesignal.example.com:5085"
server_names = ["molesignal.example.com"]
```

<Warning>
每個網路請求都會先經過對外連線原則檢查。除非所選地點的原則明確允許，否則會拒絕 Loopback、Link-local 與私人網路位址。這項限制可防止伺服器端請求偽造危及 MoleSignal 主機和私人網路。
</Warning>

HTTP 檢查會使用 Probe Agent 環境中的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 與 `NO_PROXY`。透過 Proxy 時，結果中的連線耗時衡量的是到 Proxy 的連線，包含建立通道的請求。由於 Proxy 會發起到目標的連線，因此不會強制將目標限制在對外連線原則核准的位址。請限制 Proxy 可存取的範圍。

Agent 程序能傳送 ping 時才提供 ICMP 檢查：在 Linux 上需要 `CAP_NET_RAW`，或讓 Agent 所屬的群組落在 `net.ipv4.ping_group_range` 範圍內。內建本機地點的程序內執行器也遵循相同規則。

Agent 每次傳送活動訊號時都會回報功能等級。使用舊版 Agent 不支援的設定時，只會將檢查交給支援該設定的新版 Agent 執行：A、AAAA 以外的 DNS 記錄類型、指定解析器、DNSSEC、ICMP、TCP、DNS 與 gRPC 檢查的斷言，以及 HTTP 檢查的 JSONPath、JSON Schema、回應大小與分階段耗時、僅限 HTTP/2、DNS 伺服器、Host 繫結和用戶端憑證。若要在 Agent Pool 中執行這類檢查，請先升級 `probe-agent`。

Agent 一分鐘未傳送活動訊號時，系統會將其標示為離線。地點的健全狀態取決於所屬的 Agent：全部在線上時為線上，部分在線上時為降級，全部不在線上時為離線。截止前沒有 Agent 領取的執行會記為**已略過**，並註明原因：沒有在線上的 Agent、沒有支援該類型檢查的 Agent、Agent 版本太舊，或所有 Agent 都在忙碌。

### 在 Kubernetes 上執行 Agent

Helm Chart `probe-agent` 會將 Agent 部署為 StatefulSet。各副本會個別註冊，並將身分和尚未送達的結果儲存在各自的持久磁碟區，因此替換 Pod 後仍是同一個 Agent。這個 Chart 不會部署伺服器端。請使用 Chart `molesignal` 部署伺服器端，可部署在同一個叢集或其他位置。

<Warning>
外部 Agent 需要比 26.2.0.0 更新的版本。請同時升級伺服器端與 Agent 映像檔。在 26.2.0.0 版中，伺服器端無法註冊 Agent，Agent 也無法進入**已註冊**之後的狀態。
</Warning>

<Steps>
  <Step title="設定 Agent 可連線的伺服器端位址">
    Agent 會連線至 **Standalone** 或 **Alert** 節點的 5084 與 5085 連接埠。`server_names` 必須包含 Agent 使用的主機名稱，預設只有 `localhost`。Agent 與 Chart `molesignal` 位於同一個叢集時，在該 Chart 的 values 中填入 Service 名稱。在 `distributed` 模式下，使用 `alert` 角色的 Service。

    ```yaml
    config:
      probe:
        register_endpoint: https://molesignal.molesignal.svc.cluster.local:5084
        control_endpoint: https://molesignal.molesignal.svc.cluster.local:5085
        server_names: [molesignal.molesignal.svc.cluster.local]
    ```

    Agent 位於其他位置時，使用 `LoadBalancer` 或 `NodePort` 類型的 Service 對外開放這兩個連接埠。請勿在中間終止 TLS：Agent 只信任伺服器端自己的 CA，控制串流也需要使用用戶端憑證驗證 Agent。
  </Step>
  <Step title="建立地點和 Token">
    開啟**合成監控 → 區域**，選取**新增私人區域**，再建立 Token：

    | Token | 建立位置 | 可註冊 | 有效期限 |
    |---|---|---|---|
    | 一次性 Token | **註冊 Agent** | 1 個 Agent | 最長 60 分鐘 |
    | Agent Token | **合成監控 → Agents → 建立 Agent Token** | 可註冊任意數量的 Agent，直到 Token 到期或停用為止 | 30 天至 1 年，或永不到期 |

    有多個副本時，請使用 Agent Token。兩種 Token 都只會顯示一次，並附上註冊指令。下一步會用到指令中的 `--endpoint` 與 `--ca-certificate-base64`。
  </Step>
  <Step title="安裝 Chart">
    將 Token 儲存到 Secret。Chart 沒有預設 Token，也不會將 Token 寫入 ConfigMap。

    ```bash
    kubectl create namespace probes
    ```

    ```bash
    kubectl --namespace probes create secret generic probe-agent-registration --from-literal=token=<token>
    ```

    ```bash
    helm repo add molesignal https://charts.molesignal.com
    ```

    ```bash
    helm install probe-agent molesignal/probe-agent --namespace probes --set registration.endpoint=<endpoint> --set registration.caCertificateBase64=<base64-ca> --set registration.existingSecret=probe-agent-registration
    ```

    檢查位址與 CA。測試時，請使用伺服器端會拒絕的 Token 嘗試註冊。

    ```bash
    helm test probe-agent --namespace probes
    ```

    完成後，Agent 會顯示在**合成監控 → Agents** 中。
  </Step>
</Steps>

| 行為 | 說明 |
|---|---|
| 註冊 | 磁碟區上沒有身分時，init 容器會執行註冊；已有身分時則不執行任何操作。因此，即使一次性 Token 已使用，仍可替換 Pod。 |
| Token | 只有在 Agent 尚無身分時才會讀取 Token。更換 Token 不會重新啟動任何 Pod，Agent 上線後即可刪除 Secret。沒有身分也沒有 Token 的副本會停在 `Init`，並在日誌中註明原因。 |
| 縮減副本與解除安裝 | 系統會保留磁碟區。Agent 重新上線時會保有原有身分。若要停用 Agent，請撤銷該 Agent 並刪除對應的 PersistentVolumeClaim：`state-<release>-probe-agent-<ordinal>`。 |
| 長期離線的 Agent | `[probe].certificate_days` 決定憑證的有效期限，預設為 30 天。Agent 連線時，如果剩餘效期不到一週，就會更新憑證。憑證到期後，Agent 將無法再次連線。請撤銷該 Agent 並刪除對應的磁碟區，讓 Agent 重新註冊。 |
| Ping | Chart 會為 Pod 設定 `net.ipv4.ping_group_range`，因此 ICMP 檢查不需要額外的 capability。 |
| 映像檔 | `ghcr.io/molesignal/probe-agent`。`global.imageRegistry` 會取代映像檔登錄檔的位址。 |

瀏覽器檢查需要決定是否啟用 Chromium 沙箱。Chart 預設使用 `--no-sandbox` 啟動 Chromium，因為沙箱需要非特權使用者命名空間，而 `RuntimeDefault` seccomp 設定會封鎖這項功能。此時由 Pod 限制 Chromium：不以 root 身分執行、不具備 capability 或服務帳號 Token，且根檔案系統為唯讀。如果網頁攻破 Chromium，就會取得這個 Pod 的權限，包括存取 Agent 私密金鑰的權限。若要使用沙箱，請將 `browser.sandbox` 設為 `true`，並將 `securityContext.seccompProfile.type` 設為 `Unconfined`。節點也必須允許非特權使用者命名空間。在 Ubuntu 23.10 及後續版本上，需要設定 `kernel.apparmor_restrict_unprivileged_userns=0`。Pod 安全標準的 `baseline` 與 `restricted` 層級皆不允許 `Unconfined`。

不需要設定 `/dev/shm`。Agent 使用 `--disable-dev-shm-usage` 啟動 Chromium，並將共用記憶體寫入 `/tmp`，由 `browser.tmp` 設定。預設資源配置（請求 512 MiB，上限 2 GiB）適合一次執行一項瀏覽器檢查。`browser.maxConcurrent` 每增加 1，記憶體上限就至少要增加 1 GiB。將 `browser.maxConcurrent` 設為 `0` 時，Agent 不提供瀏覽器檢查。

如需完整設定項目與疑難排解資訊，請參閱 [Chart README](https://github.com/molesignal/molesignal-helm/tree/main/charts/probe-agent)。

## 變數、金鑰與證據

使用變數重複使用非敏感值，並使用加密金鑰儲存憑證。金鑰是僅供寫入的欄位，API 不會傳回明文。結果詳細資料會記錄有限範圍的請求與回應證據、耗時、執行嘗試的中繼資料、地點與生效的修訂版本，但不會洩露已儲存的金鑰。

## 警示事件

檢查失敗時會建立警示事件。值班人員收到通知的方式與規則觸發的警示相同。請在檢查表單的**警示**中設定。

| 檢查狀態 | 警示事件 |
|---|---|
| **失敗** | 建立一個事件，嚴重程度為 `error`。 |
| **降級** | 啟用**降級時發出警示**時，建立一個事件，嚴重程度為 `warning`。 |
| **不穩定** | 啟用**不穩定時發出警示**時，建立一個事件，嚴重程度為 `warning`。 |
| **通過** | 將事件標示為已解決。 |
| **沒有結果** | 啟用**沒有結果時發出警示**（預設啟用）時，另建一個事件，嚴重程度為 `warning`。收到結果後，將該事件標示為已解決。 |

- 每項檢查同時最多有一個狀態事件。檢查在失敗、降級與不穩定之間變更時，系統會依[警示管線](/zh-Hant/pipelines/alert-events#嚴重程度變更)重新判定的結果更新未結案事件的嚴重程度，但手動設定過的事件除外。嚴重程度提高時，會從頭開始升級。已確認的事件會維持原狀，直到有人將其標示為已解決。
- 截止前沒有 Agent 領取的執行會記為已略過，地點狀態維持不變。地點連續略過的次數達到失敗門檻時，視為沒有結果。沒有結果的地點數達到多地點原則的要求時，檢查狀態即為**沒有結果**。檢查頁面會列出這些地點與最近一次略過的原因。無資料事件帶有 `synthetic.state` = `no_data` 與 `alert.condition` = `no_data`，可與狀態事件同時維持未結案。手動將事件標示為已解決後，至少要再收到一次結果，才會再次建立事件。
- 暫停或封存檢查時，系統會將未結案及已確認的事件標示為已解決，因為檢查不會再執行，無法觸發恢復。
- 檢查的**升級策略**負責通知值班人員。選取**依路由分派**時，由[警示路由](/zh-Hant/alerting/routing)選出團隊和升級策略。選取**不關聯升級原則**時，不會呼叫值班人員，但通知原則仍會照常傳送這個事件。
- 事件標題為檢查名稱，並帶有標籤 `alert.source` = `synthetic`、`synthetic.kind` 與 `synthetic.state`。若檢查有設定標籤和團隊，還會帶有 `synthetic.tags` 與 `team_id`，通知原則可依這些標籤分派事件。事件詳細資料會連回檢查。
- 通知標題由嚴重程度加上檢查名稱組成，例如 `ERROR · Checkout API`，內文為 `Synthetic check Checkout API is failing.` 沒有結果時，通知標題為 `NO DATA · Checkout API`，內文會以工作區的預設語言說明哪些地點沒有結果以及原因，例如 `检查 Checkout API 没有结果：法兰克福 连续 3 次没有运行，那里没有在线的 Agent。`
- 系統只看整項檢查的狀態，也就是依連續失敗次數、恢復次數及多地點原則判定的狀態。個別地點的狀態變更不會建立事件。

## 在狀態頁發布故障資訊

狀態頁的自動化規則可選擇**合成監控 Monitor**作為來源。選取 Monitor，設定要比對的狀態轉換與嚴重程度，對應受影響的元件，再選擇手動核准或自動發布。請參閱[狀態頁](/zh-Hant/status-pages#自動化發布)。
