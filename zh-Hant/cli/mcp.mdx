`molesignal mcp` 透過 stdio 提供 MoleSignal 的 MCP 工具。Agent 工具會自行啟動這個命令，透過標準輸入和標準輸出與它通訊；命令列會將每則訊息轉送到 MoleSignal 的 **Inbound MCP** 端點，再傳回每則回覆。工具、權限與核准都由 MoleSignal 決定，命令列不會額外提供任何工具。

## 在 Agent 工具中新增伺服器

先[登入](/zh-Hant/cli/sign-in)，再讓命令列將自己新增到 Agent 工具中：

```bash
molesignal mcp setup claude
```

| Agent 工具 | `molesignal mcp setup` 修改的內容 |
|---|---|
| `claude` | 為 Claude Code 執行 `claude mcp add`。`--scope` 可設為 `user`（預設）、`project` 或 `local`。 |
| `cursor` | `~/.cursor/mcp.json`；使用 `--scope project` 時則為目前目錄下的 `.cursor/mcp.json`。 |
| `codex` | `~/.codex/config.toml`；若已設定 `CODEX_HOME`，則位於該目錄下。 |
| `vscode` | 目前目錄下的 `.vscode/mcp.json`。 |
| `gemini` | `~/.gemini/settings.json`；使用 `--scope project` 時則為目前目錄下的 `.gemini/settings.json`。 |

命令會新增名為 `molesignal` 的伺服器。如果已有同名伺服器，就會取代它，檔案中的其他設定維持不變。伺服器會執行 `npx -y @molesignal/cli mcp`；使用 `--installed` 則改為執行已安裝的 `molesignal`。`--profile` 會將設定檔寫入伺服器設定，讓 Agent 工具一律使用該設定檔的登入資訊，不受目前設定檔切換影響。`--print` 只會輸出設定，不會寫入檔案。

[透過 stdio 連線](/zh-Hant/inbound-mcp#透過-stdio-連線)列出各工具對應的相同設定；**Mole Agent → 設定 → Inbound MCP** 中的設定提示詞會列出適用於目前執行個體的步驟。

如果環境中沒有使用者登入（例如建置機器），請改用環境變數提供憑證：

```json
{
  "mcpServers": {
    "molesignal": {
      "command": "npx",
      "args": ["-y", "@molesignal/cli", "mcp"],
      "env": {
        "MOLESIGNAL_URL": "https://molesignal.example.com",
        "MOLESIGNAL_TOKEN": "<token>"
      }
    }
  }
}
```

## 訊息如何轉送

- Agent 工具送出 `notifications/initialized` 之前，命令列會依序逐則轉送訊息：MoleSignal 要等到回覆 `initialize` 時才會建立工作階段。之後，命令列會在收到訊息時立即轉送，執行較慢的工具呼叫不會耽誤其他呼叫。
- 如果 MoleSignal 不再識別該工作階段（例如重新啟動後），命令列會用 Agent 工具原本送出的 `initialize` 建立新的工作階段，再重送這則訊息。Agent 工具無須重新啟動即可繼續運作。
- 如果請求無法連上 MoleSignal，命令列會傳回錯誤，Agent 工具不會一直等待。
- Agent 工具關閉標準輸入時，命令列會結束 MoleSignal 上的工作階段並離開。
- 供使用者閱讀的資訊（例如連線中斷）會寫入標準錯誤；標準輸出只包含 MCP 訊息。
- 和其他命令一樣，`HTTPS_PROXY` 和 `NO_PROXY` 也會生效。

## 檢查連線

```bash
molesignal status
```

顯示的工具數量與 Agent 工具看到的一致。如果工具數量為零，通常表示組織的 Tool Policy 或使用者權限未允許使用任何工具。
