## 查詢指標

`molesignal metrics query` 執行一次 PromQL 區間查詢，每個時間序列輸出一行：時間範圍內的最新值、最小值、最大值、一張迷你折線圖，以及標籤。

```bash
molesignal metrics query 'sum by (service) (rate(http_server_requests_total[5m]))' --since 6h
```

```text
LAST   MIN    MAX    TREND                           SERIES
12.4   3.1    14.9   ▁▂▂▃▅▆▇█▇▆▆▅▅▆▇▇█▇▆▅▄▄▅▅▆▆▇▇▇▆   {service="checkout"}
```

時間範圍預設為最近一小時，可用 `--since`、`--from` 和 `--to` 調整。`-n` 限制資料點數量，預設為 `1000`。`--json` 輸出每個時間序列及其資料點，`--csv` 逐行輸出資料點。

另外四個子命令可用來找出要查詢的項目：

| 命令 | 列出 |
|---|---|
| `molesignal metrics names [文本]` | 指標名稱，只列出包含指定文字的名稱。 |
| `molesignal metrics labels <指标>` | 指標的標籤。 |
| `molesignal metrics values <指标> <标签>` | 標籤值及各值出現的次數。 |
| `molesignal metrics series <指标>` | 指標的時間序列；使用 `--match 标签=值` 縮小範圍。 |

## 尋找追蹤

```bash
molesignal traces --service checkout --errors --since 6h
```

清單顯示最新的追蹤，以及各筆追蹤的開始時間、耗時、Span 數量和服務。

| 選項 | 說明 |
|---|---|
| `--service <名称>` | 只顯示指定服務的追蹤。 |
| `--errors` | 只顯示含有失敗 Span 的追蹤。 |
| `--min-duration <时长>` | 只顯示耗時達到指定值的追蹤，例如 `500ms`。 |
| `--since`、`--from`、`--to` | 時間範圍，預設為最近一小時。 |
| `-n`、`--limit <数量>` | 追蹤筆數，預設為 `20`，最多 `200`。 |

## 繪製單筆追蹤

`molesignal traces show` 將單筆追蹤繪成瀑布圖：每個 Span 各佔一行，排列在父 Span 下方，並以橫條表示在整筆追蹤中的執行時間與耗時。失敗的 Span 會以 `!` 標示，並在終端機中以紅色顯示。

```bash
molesignal traces show 4bf92f3577b34da6a3ce929d0e0e4736
```

```text
checkout POST /orders          ████████████████████████████████████████  1.24s
├─ checkout SELECT orders       ███                                       98ms
└─ ! payments POST /charge         ███████████████████████████████████    1.1s
```

`--web` 在 MoleSignal 中開啟這筆追蹤，`--json` 輸出其中的 Span。

## 檢視服務摘要

```bash
molesignal services --env production --sort errors
```

清單顯示每個 APM 服務的請求數、錯誤率、p95 延遲、健康狀態和目前版本。`--sort` 依 `requests`、`errors`、`p95` 或 `name` 排序。

`molesignal services show` 彙整單一服務的資訊：先列出請求、錯誤和延遲，再列出介面、相依項目、錯誤和版本：

```bash
molesignal services show checkout --since 2h
```

## 比較兩個版本

`molesignal services compare` 並排比較同一服務的兩個版本，判斷候選版本是退步、改善、持平，還是請求太少而無法判斷。指定 `--fail-on-regression` 時，若候選版本退步，命令會以結束代碼 `1` 結束，讓管線據此阻止發佈：

```bash
molesignal services compare checkout 2.3.9 2.4.0 --since 1h --fail-on-regression
```

## 使用搜尋工作執行耗時的查詢

搜尋工作在背景執行查詢，可涵蓋比即時查詢更多的資料和更長的時間範圍，並保留結果一段時間。提交和取消搜尋工作與其他變更一樣，都受組織的 Tool Policy 控管。請參閱[事件與變更](/zh-Hant/cli/changes#如何執行變更)。

```bash
molesignal search-jobs submit "SELECT * FROM app_logs WHERE level = 'error'" --since 30d --wait
```

預設使用 `FROM` 後的第一個資料流，可用 `--stream` 指定其他資料流。`--promql` 提交 PromQL 陳述式，並在時間範圍的結尾求值；若指定 `--step`（例如 `1m`），則每隔指定的時間間隔求值一次。`--limit` 限制工作保留的列數，最多 `100000`，`--keep` 設定保留時間。`--wait` 等待工作完成。命令會輸出工作的 ID。

| 命令 | 用途 |
|---|---|
| `molesignal search-jobs` | 列出搜尋工作及其狀態、列數和陳述式。 |
| `molesignal search-jobs show <任务>` | 輸出工作的狀態、列數、時間和錯誤。 |
| `molesignal search-jobs results <任务>` | 輸出已完成工作的結果，每行一個 JSON 物件；`--csv` 輸出 CSV，`-o <文件>` 將結果寫入檔案。 |
| `molesignal search-jobs cancel <任务>` | 取消等待中或執行中的工作。 |

## 存取權限

查詢指標需要 `streams.query`，查詢追蹤需要 `traces.read`，APM 需要 `apm.services.read`，搜尋工作需要 `query.jobs.read` 和 `query.jobs.run`。在 `_sys` 範圍內，這些操作都可使用 `sys.telemetry.read`。組織的 Tool Policy 必須啟用對應的工具。
