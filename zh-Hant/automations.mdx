自動化每次啟動時都會將同一項任務交給 Mole Agent：每天早上檢查服務健康狀態、調查每起新的嚴重事件，或在 CI/CD 管線呼叫時檢查一次發布。Mole Agent 會像在對話中一樣處理任務，並可使用自動化所屬範圍內的工具、技能與知識。每次執行都會儲存為一段對話，有權查看該自動化的使用者可以開啟。執行結束後，系統會將結果傳送到選定的通知管道；由事件觸發的自動化也可以撰寫事件的 RCA。

## 開始之前

- 在 **Mole Agent → 設定 → 模型與推論** 中至少啟用一個 AI 模型，請參閱 [Mole Agent](/zh-Hant/agent#設定模型服務)。若未啟用任何模型，執行會失敗並說明原因。
- 確認權限：

| 操作 | 權限 |
|---|---|
| 查看自動化與執行紀錄，開啟某次執行的對話 | `agent.automations.read`，並須符合範圍規則，請參閱[歸屬](#歸屬) |
| 新增、編輯、啟用 | `agent.automations.manage`（預設授予擁有者、管理員與編輯者），並須符合範圍規則 |
| 立即執行 | `agent.automations.run`（預設授予相同角色），並須符合範圍規則 |
| 管理 API 權杖 | `agent.automations.tokens`（預設授予相同角色），並須符合範圍規則 |
| 停用、刪除 | 同上；持有 `agent.manage` 權限的使用者可停用或刪除任何有權查看的自動化 |
| 在表單中選擇通知管道 | `notify.connectors.read`，用於列出通知連接器 |

## 新增自動化

開啟 **Mole Agent → 自動化 → 新增自動化**，從空白自動化或範本開始：

| 範本 | 觸發 | 要做什麼 |
|---|---|---|
| **事件自動分析** | 嚴重性等級為錯誤或嚴重的新事件 | 使用工具調查事件：重新執行觸發查詢、查看錯誤日誌、追蹤、APM 與服務拓撲，找出最可能的根本原因及相關證據，並寫成事件的 RCA。 |
| **每日健康檢查** | 工作日 09:00 | 檢查最近 24 小時的錯誤率、延遲、錯誤模式與尚未結案的事件，說明哪些項目需要留意。 |
| **警示降噪週報** | 每週一 10:00 | 找出上週觸發最頻繁、反覆觸發又解除，或無人處理的警示規則，並逐條提供調整建議。 |
| **值班負載週報** | 每週一 10:30 | 彙整各值班人員與各值班表收到的事件、夜間警示與回應時間，並提出減輕負載的建議。 |
| **變更影響檢查** | API 呼叫 | 比較受該次發布影響的服務在發布前後的表現，判斷變更是否導致表現下降。 |

表單包含以下欄位：

| 欄位 | 說明 |
|---|---|
| **名稱** | 在組織內不得重複。 |
| **要做什麼** | 任務內容，最多 8000 個字元。每次執行時都會交給 Mole Agent，等同於在新對話中提問。 |
| **說明** | 用一句話說明這項自動化的用途。 |
| **歸屬** | 新增時選擇的範圍：個人、所屬的某個團隊，或組織。 |
| **觸發方式** | 排程、新事件、API 呼叫或手動，請參閱[觸發方式](#觸發方式)。 |
| **時間上限** | 5 到 60 分鐘，預設 10 分鐘。超過上限時，系統會停止執行並記為失敗。 |
| **啟用** | 停用的自動化只會在按一下「立即執行」時執行。 |
| **通知管道** | 最多可選五個通知連接器上的固定地址或固定群組。阿里雲簡訊與語音只會傳送通過審核的範本，因此無法選用。 |
| **將結論寫成事件的 RCA** | 適用於由事件觸發的自動化。 |

每個組織最多可建立 50 項自動化。在該列的選單中選擇 **複製**，即可在表單中開啟一份停用的副本，再變更名稱或範圍後儲存。

### 歸屬

範圍決定每次執行可使用哪些資源，以及哪些使用者可查看這項自動化。建立後無法修改範圍；如要變更範圍，請複製自動化。

| 範圍 | 執行時可用 | 哪些使用者可查看 |
|---|---|---|
| 個人 | 組織與個人的技能和 MCP 伺服器、組織的知識，以及個人記憶 | 所屬使用者，以及持有 `agent.manage` 權限的使用者 |
| 團隊 | 組織與該團隊的資源和知識，以及團隊記憶 | 團隊成員，以及持有 `agent.manage` 權限的使用者 |
| 組織 | 僅限組織的資源和知識，執行時不會寫入記憶 | 所有持有 `agent.automations.read` 權限的使用者 |

組織範圍的自動化由事件觸發時，會在該事件所屬的團隊範圍內執行。系統會依事件的升級策略判定歸屬：優先採用策略通知的第一個團隊，否則採用第一個值班表所屬的團隊。若無法判定，仍會在組織範圍內執行。

### 執行身分

自動化以最後儲存該自動化的使用者身分執行。每次執行時，系統都會重新讀取該使用者的權限，並在需要成員憑證的 MCP 伺服器上使用該使用者本身的憑證。儲存時，系統會將儲存者設為執行身分，表單會註明這一點。系統會拒絕以 API 權杖儲存，因為權杖代表其繫結的角色，而不是建立權杖的使用者。

若執行身分無法再在組織中使用 Mole Agent，每次執行都會失敗並註明原因，直到有權限的使用者重新儲存這項自動化。

## 觸發方式

| 觸發方式 | 執行時機 |
|---|---|
| **排程** | 依 Cron 運算式在指定時區的時間執行。運算式有五個欄位：分鐘、小時、日期、月份、星期，最短每 15 分鐘執行一次。星期欄位中的 0 和 7 都代表星期日。日期與星期只能指定其中一個。若上一次執行尚未結束，系統會略過下一次執行。 |
| **新事件** | 自動化儲存或啟用後，每起符合所有已填寫篩選條件的新事件都會觸發執行。條件包括嚴重性等級、警示規則、受影響的服務，以及值相符的標籤。同一事件只分析一次；同一組事件（警示規則與標籤皆相同）在 30 分鐘內只分析一次。 |
| **新的自動發現** | 自動化儲存或啟用後，每筆符合所有已填寫篩選條件的[自動發現](/zh-Hant/alerting/discovery)都會觸發執行。條件包括類型、最低嚴重性，以及服務、主機或容器。同一筆發現只調查一次。 |
| **API 呼叫** | 外部系統附上權杖呼叫時執行，請參閱[從 CI/CD 啟動](#從-ci/cd-啟動)。 |
| **手動** | 僅在手動啟動時執行。 |

在該列選擇 **立即執行**，即可用執行身分啟動任何一項自動化，無論是否啟用。每分鐘最多執行一次。

## 執行紀錄

該列的 **執行紀錄** 依時間由新到舊列出最近 100 次執行，包含結果與原因、觸發方式、回答開頭，以及通知未送達的管道。選擇 **查看執行過程**，即可開啟儲存完整過程的對話。這段對話不會出現在對話清單中，也無法繼續提問；如要重試，請再次執行自動化。

執行期間無法人工回答問題。Mole Agent 提問時，會自行判斷並繼續處理。系統不會執行需要人工確認的工具，也不會使用需要執行身分本身的憑證、但尚未儲存該憑證的 MCP 伺服器。Mole Agent 會在回答中說明這些情況，系統會將這次執行標為需要人工處理。

| 狀態 | 含義 |
|---|---|
| **執行中** | Mole Agent 正在處理。 |
| **成功** | 已回答，並已傳送通知及寫入 RCA。 |
| **部分完成** | 已回答，但未傳送部分通知，或未寫入 RCA。 |
| **需要人工處理** | 已回答，但執行過程中有問題待回答、操作待確認或憑證待補充，且無法人工處理。 |
| **失敗** | 未回答：模型或工具發生錯誤、超過時間上限、未啟用任何模型，或執行身分已無法使用 Mole Agent。 |
| **已略過** | 未開始執行：組織今天的 token 預算已用完、上一次執行尚未結束，或剛分析過同一事件。 |
| **已停止** | 使用者已停止執行，或負責執行的伺服器已停止運作。 |

執行期間的模型呼叫會計入組織的每日 token 預算，並在用量來源分布中顯示為 **自動化**。

## 通知與事件的 RCA

執行成功、需要人工處理或失敗時，系統會向每個管道傳送一則通知，內容包含自動化名稱、執行結果、回答開頭、原因與執行連結。通知採用最後儲存這項自動化的使用者所用的語言，並與其他通知一樣記入傳送紀錄。

對於由事件觸發且已開啟 **將結論寫成事件的 RCA** 的自動化，系統會將 Mole Agent 的回答寫成事件的 RCA，並顯示在事件頁面上。系統會保留使用者從對話寫入的 RCA。組織啟用這類自動化後，內建的 RCA 產生功能便不再處理該組織的事件，以免重複分析同一事件。**事件自動分析** 範本採用這項設定。

## 從 CI/CD 啟動

對於由 API 呼叫觸發的自動化，在該列的選單中開啟 **API 權杖**，再選擇 **產生權杖**。權杖只會顯示一次。產生新權杖時，系統會立即替換舊權杖。選擇 **撤銷權杖** 即可刪除該權杖。

發布時附上權杖呼叫，並在 `text` 中描述這次變更：

```bash
curl -X POST "https://molesignal.example.com/api/v1/public/automations/<automation-id>/trigger" \
  -H "Authorization: Bearer mspat-..." \
  -H "Content-Type: application/json" \
  -d '{"text": "Deployed checkout-api v42 at 14:05"}'
```

`text` 為選填欄位，最多 8000 個字元。Mole Agent 會將其視為這次執行的參考資料，而非指令。成功時傳回 `202`，其中包含 `runId`、`status` 與 `chatUrl`。權杖錯誤或自動化不存在時，傳回 `401`；自動化已停用或不由 API 呼叫觸發時，傳回 `409`；10 秒內再次呼叫時，傳回 `429`。

## 回顧 Mole Agent 的使用情形

`/insight [天数]` 是一項內建技能，可回顧對話所屬範圍內最近 30 天（或指定天數）的 Mole Agent 使用情形：提出的問題、回答與自動化結果、哪些回答被評為沒有幫助及其原因、哪些工具經常發生錯誤，以及使用了哪些技能。最後會提出最多五項值得採取的改善措施，例如應撰寫哪些知識文件，或應修正哪些自動化。這項技能不會修改任何內容。團隊對話會回顧該團隊，個人對話則會回顧該使用者及其所屬團隊。可在對話中使用，也可設為每週自動化任務。
