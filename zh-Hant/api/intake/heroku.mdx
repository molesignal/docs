```http
POST /api/v1/_heroku
```

接受純文字格式的日誌投遞請求主體。此端點不使用 Bearer Token。請建立 `heroku_drain` 類型的連接器，設定至少 16 個字元的 `pushToken`，並設定 `target_stream`。Heroku 無法設定自訂請求標頭，因此請以 `?token=` 的形式將 Token 放在 URL 中。也可使用 `X-Connector-Token` 請求標頭。Token 錯誤時會傳回 `401`。

每一行都會成為 `target_stream`（預設為 `heroku`）中的一筆日誌事件。整行會儲存在 `message` 欄位中，`source` 欄位的值為 `heroku`。成功時會傳回 `204`。

<RequestExample>
```bash Heroku CLI
heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
```
</RequestExample>

如需設定連接器，請參閱[連接器](/zh-Hant/connectors)。

## 驗證投遞與目標資料流

1. 確認連接器已啟用，且推送 Token 與傳送端的設定一致。一般 API Token 無法取代推送 Token。
2. 透過連接器 API 設定原始 `configJson` 時，請使用 `target_stream` 指定目標資料流，不要用 `targetStream` 取代此欄位。`pushToken` 仍採用駝峰式命名。
3. 傳送一筆含有唯一標記的測試事件，並記錄接收時間。接著在 **日誌** 中選取預期的資料流和涵蓋接收時間的時間範圍，查詢該標記。
4. 若請求成功但目標資料流沒有資料，請檢查對應的預設資料流和實際儲存的目標欄位值。HTTP 成功回應無法取代在目標資料流中查詢驗證。

請將 Token 當作憑證保護。透過 URL 查詢參數傳遞 Token 時，請勿將完整 URL 複製到日誌、工單或螢幕擷取畫面中。請求失敗時，先確認問題出在 Token、連接器啟用狀態、請求格式，還是壓縮設定，再決定是否重試。
