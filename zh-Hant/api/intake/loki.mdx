```http
POST /api/v1/loki/api/v1/push
```

接受 Loki JSON push 格式。此呼叫需要 `logs.write` 權限，成功時傳回 `204`，並接受帶有 `Content-Encoding: gzip` 的請求本文。

此端點只解碼 JSON。使用 snappy 壓縮 protobuf 的傳送端（例如 Promtail 和 Grafana Alloy）無法推送至此端點，請改用 OpenTelemetry Collector、Vector 或 Fluent Bit。

<RequestExample>
```bash cURL
LOKI_TIMESTAMP="$(date +%s)000000000"
curl -X POST http://localhost:5080/api/v1/loki/api/v1/push \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -H 'stream-name: app' \
  -d '{"streams":[{"stream":{"service":"api"},"values":[["'"$LOKI_TIMESTAMP"'","started"]]}]}'
```
</RequestExample>

每個 value 會成為一筆日誌事件。標籤會成為欄位，日誌列會成為 `message` 欄位，奈秒時間戳記會轉換為微秒。`stream-name` 請求標頭會指定目標資料流，預設為 `default`。

## 驗證範例

範例會在 macOS 或 Linux shell 中產生目前時間的奈秒時間戳記。收到 `204` 後，在 **日誌** 中選取 `app` 和最近一小時，查詢 `service = 'api'` 對應的 `message`。若使用歷史時間戳記，請確認查詢時段涵蓋事件時間，且資料仍在保留期限內。

請區分這三個欄位：請求中的 `streams` 是 Loki 的批次結構；標籤中的 `service` 是事件欄位；`stream-name` 請求標頭才會決定 MoleSignal 的目標資料流。成功後仍須透過查詢核對資料流和時間，避免重複傳送同一批次。
