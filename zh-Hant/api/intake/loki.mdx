```http
POST /api/v1/loki/api/v1/push
```

接受 Loki JSON push 格式。此呼叫需要 `logs.write`，成功時回傳 `204`，並接受帶有 `Content-Encoding: gzip` 的要求主體。當資料流因值與欄位類型不符而拒收部分日誌行時，其餘日誌行照常寫入，回傳 `400`，並註明拒收的筆數和第一個原因。

此端點只解碼 JSON。使用 snappy 壓縮 protobuf 的傳送端（例如 Promtail 與 Grafana Alloy）無法向其推送，請改用 OpenTelemetry Collector、Vector 或 Fluent Bit。

<RequestExample>
```bash cURL
LOKI_TIMESTAMP="$(date +%s)000000000"
curl -X POST http://localhost:5080/api/v1/loki/api/v1/push \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -H 'stream-name: app' \
  -d '{"streams":[{"stream":{"service":"api"},"values":[["'"$LOKI_TIMESTAMP"'","started"]]}]}'
```
</RequestExample>

每個 value 成為一筆日誌事件。標籤成為欄位，日誌行成為欄位 `message`，奈秒時間戳會轉換為微秒。`stream-name` 要求標頭選擇目標資料流，預設為 `default`。

## 驗證範例

範例在 macOS 或 Linux shell 中產生目前時間的奈秒時間戳。收到 `204` 後，在 **Logs** 中選擇 `app` 和最近一小時，查詢 `service = 'api'` 對應的 `message`。如果使用自己的歷史時間戳，查詢視窗必須涵蓋事件時間，並確認資料仍在保留範圍內。

注意區分三個欄位：要求中的 `streams` 是 Loki 批次結構；標籤中的 `service` 是事件欄位；真正決定 MoleSignal 目標資料流的是 `stream-name` 要求標頭。成功後仍需用查詢核對資料流和時間，避免重複傳送同一批次。
