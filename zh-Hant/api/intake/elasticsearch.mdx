```http
POST /api/v1/_bulk
```

相容 Elasticsearch `_bulk` 的 NDJSON 接入，適用於 Filebeat、Logstash 與 Vector 的 `elasticsearch` sink。此呼叫需要 `logs.write`，並接受帶有 `Content-Encoding: gzip` 的要求本文。

| 動作 | 處理方式 |
|---|---|
| `index`、`create`、`update` | 來源文件作為日誌事件儲存。 |
| `delete` | 略過，不產生回應項目。此端點不會刪除任何遙測資料。 |

動作中的 `_index` 會選擇目標日誌資料流。未提供時使用 `stream-name` 要求標頭，再預設為 `default`。

值與資料流中欄位類型不符的文件會個別遭到拒收：其項目為 `status: 400`，`error` 中會註明 `reason`，`errors` 為 `true`，其餘文件則照常寫入。Filebeat 與 Logstash 不會重試這類項目。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## 選擇此端點

當現有傳送端能夠輸出 Elasticsearch bulk NDJSON 時，請使用此端點。此端點是接入適配器，不是 Elasticsearch 叢集，不提供搜尋、索引範本、文件 ID 或原地更新語意。讀取已儲存事件時，請使用 [SQL 查詢](/zh-Hant/query)。

## 建構有效批次

- 每個 `index` 或 `create` 操作分別佔用一行動作物件和一行文件物件，批次末尾請保留換行。
- `update` 的事件欄位放在 `doc` 內；這些欄位會作為新事件寫入，不會修改已儲存事件。
- 動作中的 `_index` 決定資料流；未指定時使用 `stream-name` 要求標頭，再回退到 `default`。
- 需要保留事件時間時，請提供整數形式、單位為微秒的 Unix `_timestamp`；否則會使用接收當下的時間。
- `delete` 動作會被略過，不會刪除遙測資料，也不會產生已寫入事件的回應項目。

## 驗證接入結果

單一事件批次應傳回 `errors: false`，並包含一個 `status: 201` 的項目。請將項目數與預計寫入的事件數核對；HTTP 成功本身無法證明批次格式符合預期。

開啟 **Logs**，選擇 `_index` 指定的資料流，並選取涵蓋事件時間的範圍。依範例中的特徵欄位查詢。找不到事件時，請先檢查資料流和時間戳記單位，再決定是否重送整批。此端點不會根據 Elasticsearch 文件 ID 對重試進行去重。

## 排解要求遭拒

| 現象 | 檢查項目 |
|---|---|
| 驗證或權限錯誤 | 使用目標組織中具備 `logs.write` 的 API Token。 |
| 動作或文件不是 JSON 物件 | 檢查 NDJSON 的行邊界，不要傳送 JSON 陣列或跨行格式化的物件。 |
| 未知動作 | 使用上表列出的動作名稱。 |
| 解壓縮錯誤 | 僅在要求本文實際壓縮時設定 `Content-Encoding: gzip`。 |
| 成功但事件數少於預期 | 檢查每個寫入動作後是否都有文件行，並區分略過的刪除動作與儲存事件。 |
| `errors: true` 且有狀態為 `400` 的項目 | 某個值與資料流中欄位的類型不符，例如 `int64` 欄位收到文字，項目的 `reason` 會註明欄位。請依資料流儲存的類型傳送該欄位，或用管線轉換。 |
