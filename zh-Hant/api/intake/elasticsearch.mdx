```http
POST /api/v1/_bulk
```

相容於 Elasticsearch `_bulk` 的 NDJSON 資料接收介面，適用於 Filebeat、Logstash 與 Vector 的 `elasticsearch` sink。呼叫此介面需要 `logs.write` 權限，並可傳送帶有 `Content-Encoding: gzip` 的請求本文。

| 動作 | 處理方式 |
|---|---|
| `index`、`create`、`update` | 將來源文件儲存為日誌事件。 |
| `delete` | 略過，不產生回應項目。此端點不會刪除任何遙測資料。 |

動作中的 `_index` 指定目標日誌資料串流。若未指定，則使用 `stream-name` 請求標頭；若也未提供該標頭，則使用預設值 `default`。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## 選擇此介面

現有傳送端可輸出 Elasticsearch bulk NDJSON 時，請使用此介面。此介面是資料接收轉接器，不是 Elasticsearch 叢集，不提供搜尋、索引範本、文件 ID 或就地更新語意。使用 [SQL 查詢](/zh-Hant/query)讀取已儲存的事件。

## 建立有效的批次

- 每個 `index` 或 `create` 操作各使用一行動作物件和一行文件物件，並在批次末尾保留換行。
- 將 `update` 的事件欄位放在 `doc` 內；介面會將這些欄位寫入為新事件，不會修改已儲存的事件。
- 動作中的 `_index` 決定資料串流；若未指定，則使用 `stream-name` 請求標頭；若也未提供該標頭，則使用 `default`。
- 若要保留事件時間，請提供以微秒為單位的整數 Unix `_timestamp`；否則使用接收當下的時間。
- 介面會略過 `delete` 動作，不會刪除遙測資料，也不會產生對應的事件寫入回應項目。

## 驗證資料接收結果

僅含一筆事件的批次應傳回 `errors: false`，並包含一個 `status: 201` 的項目。核對回應項目數是否與預計寫入的事件數相符；僅憑 HTTP 請求成功，無法確認批次格式符合預期。

開啟 **日誌**，選取 `_index` 指定的資料串流，以及涵蓋事件時間的時間範圍。使用範例中可辨識事件的欄位查詢。若找不到事件，請先檢查資料串流和時間戳記的單位，再決定是否重新傳送整個批次。此介面不會依據 Elasticsearch 文件 ID 對重試寫入的事件去除重複。

## 排查請求遭拒的原因

| 現象 | 檢查項目 |
|---|---|
| 驗證或權限錯誤 | 使用在目標組織中具有 `logs.write` 權限的 API 權杖。 |
| 動作或文件不是 JSON 物件 | 檢查 NDJSON 的換行位置，不要傳送 JSON 陣列或格式化成多行的物件。 |
| 未知動作 | 使用上表列出的動作名稱。 |
| 解壓縮錯誤 | 只在請求本文實際經過壓縮時設定 `Content-Encoding: gzip`。 |
| 請求成功，但事件數少於預期 | 檢查每個寫入動作後是否都有一行文件，並區分略過的刪除動作和已儲存的事件。 |
