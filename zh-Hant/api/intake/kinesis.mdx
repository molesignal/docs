```http
POST /api/v1/_kinesis_firehose
```

接受 AWS Data Firehose HTTP 端點的投遞。此端點不使用 Bearer Token。請建立 `aws_kinesis_firehose` 類型的連接器，設定至少 16 個字元的 `pushToken` 及 `target_stream`，並將該 Token 提供給 Firehose 作為存取金鑰。端點從 `X-Amz-Firehose-Access-Key` 讀取 Token，也接受 `X-Connector-Token` 和 `?token=`。Token 錯誤時傳回 `401`。

每筆記錄都包含以 base64 編碼的 `data`。端點會解碼並依行分割，將每個非空白行轉成 `target_stream`（預設為 `kinesis`）中的一筆日誌事件。若該行是 JSON 物件，則將物件內容轉成欄位；若是純文字，則將文字存入 `message` 欄位。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_kinesis_firehose \
  -H 'X-Amz-Firehose-Access-Key: <pushToken>' \
  -H 'content-type: application/json' \
  -d '{"requestId":"req-1","timestamp":1790000000000,"records":[{"data":"eyJsZXZlbCI6ImluZm8ifQo="}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{ "requestId": "req-1", "timestamp": 1790000000123 }
```
</ResponseExample>

為符合 Firehose 的要求，回應會傳回原始的 `requestId`，並附上以毫秒為單位的 `timestamp`。如需設定連接器，請參閱[連接器](/zh-Hant/connectors)。

## 驗證投遞與目標資料流

1. 確認連接器已啟用，且推送 Token 與傳送端的設定一致。一般 API Token 無法取代推送 Token。
2. 透過連接器 API 設定原始 `configJson` 時，請使用 `target_stream` 指定目標資料流，不要以 `targetStream` 取代此欄位。`pushToken` 仍採用駝峰式命名。
3. 傳送一筆含有唯一標記的測試事件，並記下接收時間。接著在 **日誌** 中選取預期的資料流和涵蓋接收時間的範圍，再查詢該標記。
4. 若請求成功，但目標資料流中沒有資料，請檢查對應的預設資料流，以及實際儲存的目標欄位。HTTP 成功回應無法取代在目標資料流中查詢驗證。

請將 Token 視為憑證並妥善保護。透過 URL 查詢參數傳遞 Token 時，請避免將完整 URL 複製到日誌、工單或螢幕擷取畫面中。請求失敗時，請先確認問題出在 Token、連接器啟用狀態、請求格式還是壓縮設定，再決定是否重試。
