```http
POST /api/v1/prometheus/api/v1/write
```

接受 Prometheus 與 VictoriaMetrics 的 `remote_write` 第 1 版請求，即以 snappy 壓縮的 protobuf。此呼叫需要 `metrics.write`，成功時傳回 `204`。

每個請求都會寫入 `stream-name` 請求標頭指定的指標資料流。若未指定這個標頭，則寫入 `default`。每個指標資料流儲存單一來源的所有指標。`__name__` 標籤成為 `metric_name` 欄位，其餘標籤各自成為欄位，樣本則成為 `value` 欄位。與指標欄位同名的標籤（例如 `metric_name`、`metric_kind`）會儲存為 `exported_<名稱>`。系統會略過原生直方圖與指標中繼資料，並將 exemplar 與樣本一併儲存。

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

使用 PromQL 依指標名稱查詢，不必指定指標所在的資料流。帶有 `service` 與 `status` 標籤的 `http_requests_total` 序列會傳回：

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**限制** 依序列與組織套用：每個序列最多 64 個標籤，標籤名稱最長 128 位元組，標籤值最長 2048 位元組。系統也會限制活躍序列與新序列的基數。程序層級的限制請參閱[設定](/zh-Hant/configuration#資料接收緩衝)中的 `[intake.prometheus]`。平台設定 **設定 → 指標基數** 會限制每個組織及組織內每項指標的活躍序列數：使用 `GET /api/v1/settings/series_limits` 讀取，使用 `PUT` 搭配相同的請求主體 `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }` 修改。兩項操作都需要系統範圍的 `sys.settings.limits.manage` 權限。指標的上限不得超過組織的上限，兩者都不得超過 100,000,000。
