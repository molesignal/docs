```http
POST /api/v1/prometheus/api/v1/write
```

接受 Prometheus 與 VictoriaMetrics 的 `remote_write` 第 1 版請求，即 snappy 壓縮的 protobuf。該呼叫需要 `metrics.write`，成功時傳回 `204`。資料流因值與欄位類型不符而拒收部分樣本時，其餘樣本照常寫入，傳回 `400`，並寫明拒收的筆數和第一個原因。Prometheus 不會重試 `400`。

一個請求寫入 `stream-name` 請求標頭指定的指標資料流，沒有這個請求標頭時寫入 `default`。一個指標資料流裝一個來源的全部指標。`__name__` 標籤成為 `metric_name` 欄位，其餘標籤成為欄位，樣本成為 `value` 欄位。與指標欄位同名的標籤（例如 `metric_name`、`metric_kind`）存為 `exported_<名稱>`。原生直方圖與指標中繼資料會被略過，exemplar 與樣本一起儲存。

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

用 PromQL 依指標名稱查詢，不論哪個資料流裝著它。帶有 `service` 與 `status` 標籤的 `http_requests_total` 序列會得到：

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**限制** 依序列與依組織生效：每個序列最多 64 個標籤，標籤名稱最長 128 位元組，標籤值最長 2048 位元組，並對活躍序列與新序列設有基數限制。處理程序層級的限制見[設定](/zh-Hant/configuration#資料接收緩衝)中的 `[intake.prometheus]`。一個組織、以及組織裡一個指標的活躍序列數由平台設定 **設定 → 指標基數** 限制：用 `GET /api/v1/settings/series_limits` 讀取，用 `PUT` 加同樣的請求主體 `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }` 修改，兩者都需要系統範圍的 `sys.settings.limits.manage`。指標的上限不超過組織的上限，兩者都不超過 100,000,000。
