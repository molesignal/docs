將 OpenTelemetry SDK 或 Collector 指向 MoleSignal。兩種傳輸方式都需要具備 `logs.write`、`metrics.write` 或 `traces.write` 權限的 Bearer 憑證。

| 傳輸方式 | 端點 |
|---|---|
| OTLP over HTTP | `POST /api/v1/logs`、`POST /api/v1/metrics`、`POST /api/v1/traces` |
| OTLP over gRPC | `:4317` |

`5082` 是受信任的叢集內部連接埠，不是 OTLP 接收端。

## OTLP over HTTP

將匯出端的 endpoint 設為 `/api` 基礎路徑，匯出端會自動附加 `/v1/logs`、`/v1/metrics` 與 `/v1/traces`。

| 請求標頭 | 說明 |
|---|---|
| `Authorization` | `Bearer <token>`。 |
| `Content-Type` | `application/x-protobuf` 或 `application/json`。JSON 編碼會將 64 位元整數寫成字串，MoleSignal 對字串與數字採用相同的處理方式。 |
| `stream-name` | 選填，指定目標資料流，預設為 `default`。 |

請勿壓縮請求主體。若請求主體經過壓縮，MoleSignal 會回傳 `400`，請在匯出端停用壓縮。請求主體大小上限為 2 MiB。請求成功時會回傳 `200` 與 `{"partialSuccess":null}`。

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK 环境变量
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP over gRPC

`:4317` 上的接收端提供日誌、指標、追蹤與 Profile 四項服務，不使用 TLS。透過 gRPC 中繼資料傳送 `authorization: Bearer <token>` 與選填的 `stream-name`。流量離開受信任的網路時，請在此連接埠前方終止 TLS。

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## 儲存欄位

資源與記錄的屬性會成為頂層欄位，並保留原始鍵名。日誌、Span 與指標的欄位請參閱[儲存欄位](/zh-Hant/query#儲存欄位)。

## 錯誤

| 狀態碼 | 原因 |
|---|---|
| `400` | 請求主體經過壓縮，或不是有效的 OTLP。 |
| `401` | 缺少權杖，或權杖無效。 |
| `403` | 權杖缺少 `logs.write`、`metrics.write` 或 `traces.write` 權限，或資料送往[平台資料流](/zh-Hant/streams#平台資料串流)。 |
| `404` | 匯出端的 endpoint 缺少 `/api`，導致請求送到 `/v1/logs`。 |
| `413` | 請求主體超過 2 MiB。 |

透過 gRPC 傳送請求時，原本會收到 HTTP `403` 的請求會改為收到 `PERMISSION_DENIED`。
