將 OpenTelemetry SDK 或 Collector 指向 MoleSignal。兩種傳輸方式都需要具備 `logs.write`、`metrics.write` 或 `traces.write` 權限的 Bearer 憑證。

| 傳輸方式 | 端點 |
|---|---|
| OTLP over HTTP | `POST /api/v1/logs`、`POST /api/v1/metrics`、`POST /api/v1/traces` |
| OTLP over gRPC | `:4317` |

`5082` 連接埠是受信任的叢集內部連接埠，不是 OTLP 接收端。

## OTLP over HTTP

將匯出端的 endpoint 設為 `/api` 基礎路徑，匯出端會自行附加 `/v1/logs`、`/v1/metrics` 與 `/v1/traces`。

| 請求標頭 | 說明 |
|---|---|
| `Authorization` | `Bearer <token>`。 |
| `Content-Type` | `application/x-protobuf` 或 `application/json`。JSON 編碼會把 64 位元整數寫成字串，MoleSignal 對字串和數字一視同仁。 |
| `stream-name` | 選用，目標資料流，預設為 `default`。 |

請求主體不能壓縮，壓縮的請求主體會傳回 `400`，請在匯出端關閉壓縮。請求主體上限為 2 MiB。成功的請求會傳回 `200` 與 `{"partialSuccess":null}`。當資料流因值與欄位類型不符而拒收部分日誌記錄或資料點時，其餘的照常寫入，`partialSuccess` 中有 `rejectedLogRecords` 或 `rejectedDataPoints`，以及寫明第一個原因的 `errorMessage`。匯出端不會重試這些記錄。gRPC 會傳回相同的回應。

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK 环境变量
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP over gRPC

`:4317` 上的接收端提供日誌、指標、追蹤與 Profile 四個服務，不帶 TLS。透過 gRPC metadata 傳送 `authorization: Bearer <token>` 與選用的 `stream-name`。流量離開可信網路時，請在該連接埠前面終止 TLS。

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## 儲存欄位

資源與記錄的屬性會成為保留原始鍵名的頂層欄位。日誌、Span 與指標的欄位請參閱[儲存欄位](/zh-Hant/query#儲存欄位)。

## 錯誤

| 狀態碼 | 原因 |
|---|---|
| `400` | 請求主體被壓縮，或不是有效的 OTLP。 |
| `401` | Token 缺失或無效。 |
| `403` | Token 缺少 `logs.write`、`metrics.write` 或 `traces.write`，或資料發往[平台資料流](/zh-Hant/streams#平台資料串流)。 |
| `404` | 匯出端 endpoint 缺少 `/api`，請求到達了 `/v1/logs`。 |
| `413` | 請求主體超過 2 MiB。 |

透過 gRPC 傳送時，HTTP 會以 `403` 拒絕的請求會傳回 `PERMISSION_DENIED`。
