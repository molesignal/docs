```http
POST /api/v1/functions
```

建立可在管線中重複使用的轉換。系統會在建立時編譯 VRL 和 JavaScript，並拒絕原始碼無效的函式。兩種執行環境都內建於二進位檔中。這項呼叫需要 `functions.create` 權限。

**請求本文**

| 欄位 | 類型 | 必填 | 說明 |
|---|---|---|---|
| `name` | string | 是 | 函式名稱。 |
| `language` | string | 是 | `vrl`、`js` 或 `llm`。`llm` 函式需要啟用 `[functions].llm_eval_enabled` 並設定模型供應商。 |
| `source` | string | 是 | VRL 或 JavaScript 原始碼，或 `llm` 函式的指令。 |
| `paramsSchema` | object | 否 | 參數。對於 `llm`，使用 `outputField` 選擇輸出欄位，預設為 `_llm_eval`。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/functions \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "lowercase-level",
    "language": "vrl",
    "source": ".level = downcase!(string!(.level))"
  }'
```
</RequestExample>

若有語法錯誤，系統會傳回 `400`，例如 `js syntax error: Uncaught SyntaxError: Unexpected token '}'`。儲存前可使用 `POST /api/v1/functions/run` 測試原始碼。此端點接受 `language`、`source` 和範例 `input`，並傳回 `output`。請參閱[函式](/zh-Hant/functions)。

其他函式路由：`GET /api/v1/functions`，以及 `GET`、`PUT` 和 `DELETE /api/v1/functions/{id}`。內建預設項目為唯讀。

## 儲存前試跑轉換

試跑端點需要 `functions.run` 權限，與 `functions.create` 分開授權。將轉換套用至實際資料前，請使用具代表性的輸入，並測試欄位缺漏或類型不符的情況。

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".level = downcase!(string!(.level))","input":{"level":"ERROR","message":"example"}}'
```

執行這筆輸入後，`output.level` 應為 `error`，不受轉換影響的 `message` 欄位應保留，且 `dropped` 應為 `false`。編譯成功不代表正式環境中的所有事件都符合轉換的假設。例如，上述字串轉換要求 `level` 為字串。

## 將函式接到管線

建立函式只會儲存可重複使用的定義，不會自動轉換傳入的事件。記下傳回的函式 ID，在[管線](/zh-Hant/pipelines)中加入所需的函式步驟，並在套用至實際資料流前測試整條管線。

記錄變更時，一併保留具代表性的輸入和預期輸出。啟用管線後，送出受控的測試事件，再查詢目標資料流，確認實際儲存的欄位。單憑試跑回應無法驗證已部署的資料擷取流程。

## 常見問題

| 現象 | 處理方式 |
|---|---|
| 函式名稱為空 | 提供非空白的 `name`。 |
| 建立時系統拒絕原始碼 | 修正語法或編譯錯誤後再試一次。 |
| 系統拒絕試跑 | 檢查 `functions.run` 權限。建立權限是分開授予的。 |
| 處理輸入時失敗 | 使用試跑重現問題，找出出錯的欄位，並處理欄位缺漏或類型不符的情況。 |
| 儲存函式後，新的日誌沒有變化 | 檢查管線繫結和目標資料流。 |
