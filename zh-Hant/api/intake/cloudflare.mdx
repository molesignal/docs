```http
POST /api/v1/_cloudflare
```

接受 NDJSON，包括 Cloudflare Logpush 通常傳送的 gzip 編碼請求主體。此端點不使用 Bearer Token。建立 `cloudflare_logpush` 類型的連接器，設定至少 16 個字元的 `pushToken` 和 `target_stream`，並在請求標頭 `X-Connector-Token` 中傳送該 Token。也可使用查詢參數 `?token=`。Token 錯誤時傳回 `401`。

每一行都會成為 `target_stream`（預設為 `cloudflare`）中的一筆日誌事件。系統會原樣儲存行內的欄位，並以接收時間作為事件時間。成功時傳回 `204`。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_cloudflare \
  -H 'X-Connector-Token: <pushToken>' \
  -H 'content-encoding: gzip' \
  --data-binary @logs.ndjson.gz
```
</RequestExample>

如需設定連接器，請參閱[連接器](/zh-Hant/connectors)。

## 驗證傳送結果與目標資料流

1. 確認連接器已啟用，且推送 Token 與傳送端的設定一致。一般 API Token 無法取代推送 Token。
2. 透過連接器 API 設定原始 `configJson` 時，使用 `target_stream` 指定目標資料流，不要用 `targetStream` 取代此欄位。`pushToken` 仍採用駝峰式命名。
3. 傳送一筆含有唯一標記的測試事件，並記錄接收時間。接著在 **日誌** 中選取預期的資料流與涵蓋接收時間的時間範圍，再查詢該標記。
4. 如果請求成功，但目標資料流沒有資料，請檢查對應的預設資料流及實際儲存的目標欄位。即使 HTTP 回應顯示成功，仍須在目標資料流中查詢驗證。

將 Token 視為憑證並妥善保護。透過 URL 查詢參數傳遞 Token 時，避免將完整 URL 複製到日誌、工單或螢幕擷取畫面中。請求失敗時，先確認問題出在 Token、連接器啟用狀態、請求格式或壓縮設定，再決定是否重試。
