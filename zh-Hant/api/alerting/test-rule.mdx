```http
POST /api/v1/alerts/rules/{id}/test
```

在 `now - period_secs` 到 `now` 的時間範圍內執行一次已儲存規則的查詢，並回報是否符合條件。這項呼叫不會變更任何狀態：不會影響評估狀態、事件、通知或規則本身。呼叫需要 `alerts.rules.manage` 權限，請求本文為空。

將 `enabled` 設為 `true` 前，請先測試規則。即使陳述式無效或資料流不存在，仍可儲存規則且不會出現錯誤。只有透過測試才能發現問題。

[APM 規則](/zh-Hant/api/alerting/create-rule#apm-規則)不執行查詢，而是讀取指標。結果只有一列，欄位為 `value`、`service` 和 `trace_id`；如果時間範圍內沒有指標讀值，就不會傳回任何列。

[依欄位拆分的規則](/zh-Hant/api/alerting/create-rule#依欄位分組的規則)會在 `groups` 中列出每一組。只要有任一組符合條件，`matched` 就會是 `true`，`value` 為第一個符合條件的組別的值，`severity` 則取各組中最高的嚴重程度。

[RUM 規則](/zh-Hant/api/alerting/create-rule#rum-規則)也會讀取指標。結果只有一列，欄位為 `value` 和 `application`；如果時間範圍內沒有指標讀值，就不會傳回任何列。`scannedRows` 為指標使用的列數。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/test \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "matched": true,
  "value": 2.0,
  "severity": "critical",
  "columns": ["c"],
  "rows": [[2]],
  "scannedRows": 2,
  "tookMs": 170
}
```
</ResponseExample>

**應變**

| 欄位 | 類型 | 說明 |
|---|---|---|
| `matched` | boolean | 目前是否符合條件。結果不考慮 `forPeriods`。 |
| `value` | number 或 null | 第一列第一個欄位的值。結果中沒有數值時為 `null`。 |
| `severity` | string 或 null | 事件將使用的嚴重程度。`matched` 為 `false` 時為 `null`。 |
| `columns` | array | 查詢結果的欄位名稱。 |
| `rows` | array | 結果的前 20 列。 |
| `scannedRows` | integer | 查詢掃描的列數。 |
| `tookMs` | integer | 查詢耗時，單位為毫秒。 |
| `anomaly` | object | 只有 `anomaly` 規則會傳回此欄位，包含 `baseline`、`deviation`、介於 0 到 1 的 `score`，以及 `reason` 文字。 |
| `noData` | boolean | 只有值為 `true` 時才會傳回：這次執行沒有取得值，且規則不會將缺少的值視為 `0`。 |
| `groups` | array | 只有依欄位拆分的規則會傳回此欄位，並依結果順序列出各組。每組包含 `labels`（欄位與其值的對應），以及 `value`、`matched` 和 `severity`。 |
| `groupsTruncated` | boolean | 只有值為 `true` 時才會傳回：結果超過 100 組，未列出其餘組別。 |

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 無法執行查詢。例如 SQL 無效、欄位不存在、`anomaly` 規則沒有可用來建立基準線的歷史資料，或規則屬於不執行查詢的 `composite` 或 `heartbeat` 類型。 |
| `403` | 規則的資料流不存在，或權杖缺少 `alerts.rules.manage` 權限。 |
| `404` | 規則不存在。 |
