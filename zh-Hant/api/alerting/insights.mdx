```http
GET /api/v1/alerts/insights
```

彙整時間區間內建立的事件與人員應變情況：多久有人接手、多久恢復、多少事件曾升級，並與前一個等長的時間區間比較。不計入併入其他事件的事件。此呼叫需要 `alerts.incidents.read` 權限。各人員的值班負擔請參閱[值班負擔](/zh-Hant/api/alerting/oncall-load)。

**查詢參數**

| 參數 | 類型 | 說明 |
|---|---|---|
| `windowSecs` | integer | 回溯時間區間，單位為秒。預設為 `604800`（7 天）。值須介於 3600 至 31536000 之間。 |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/alerts/insights?windowSecs=86400" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**應變**

| 欄位 | 說明 |
|---|---|
| `windowSecs` | 套用範圍限制後的時間區間。 |
| `total` | 時間區間內建立的事件數量。 |
| `active` | 狀態為 `open` 或 `acknowledged` 的事件。 |
| `closed` | 狀態為 `resolved` 或 `closed` 的事件。 |
| `mttrSecs` | 已解決事件從建立到解決的平均秒數。沒有已解決事件時為 `0`。 |
| `noiseRate` | 已解決事件中，在 60 秒內解決的比例，範圍為 0 到 1。沒有已解決事件時為 `0`。 |
| `byHour` | 依事件建立時間統計 UTC 每小時的事件數，共 24 個數值。 |
| `bySeverity` | 各嚴重程度的事件數。未發生事件的嚴重程度不會列出。 |
| `topServices`、`topRules` | 最多 8 筆包含 `key` 與 `count` 的項目，按數量由多至少排列。鍵為服務名稱或規則識別碼。 |
| `response.current`、`response.previous` | 目前時間區間與前一個等長時間區間的人員應變情況，欄位請見下表。 |
| `response.breakdown` | 依團隊（`teams`，鍵為團隊 ID）、服務（`services`）與個人（`people`，鍵為第一位接手人員）分列時間區間內的統計結果。每個維度最多 20 列，按事件數由多至少排列。若一個事件涉及多項服務，每項服務各計一次。每列包含 `incidents`、平均接手秒數 `mttaSecs`、平均恢復秒數 `mttrSecs` 和升級率 `escalationRate`。 |

**`response.current` 與 `response.previous`**

| 欄位 | 說明 |
|---|---|
| `incidents` | 此時間區間內建立的事件數。 |
| `responded` | 曾有人接手的事件數。以第一次確認作為首次接手；若未經確認即由人員解決，則以解決時間為準。規則自行恢復的事件不計入。 |
| `mtta` | 從觸發到首次接手所經過的秒數：平均值 `meanSecs`、中位數 `p50Secs` 與第 90 百分位數 `p90Secs`。沒有任何人員接手時，所有值皆為 `0`。 |
| `mttr` | 已恢復事件從觸發到恢復所經過的秒數，同樣提供平均值、P50 和 P90。 |
| `escalationRate` | 曾升級的事件所占比例，範圍為 0 到 1。曾達到第 2 級或經[立即升級](/zh-Hant/api/alerting/escalate-incident)的事件都計入。 |
| `steps` | 各級的確認情況，`step` 從 0 開始：曾達到該級的事件數 `reached`，以及在該級獲得確認的事件數 `acknowledged`。只計入時間軸上有升級記錄的事件；此時間區間內若無這類事件，則為空。 |
| `ackVia` | 依首次接手的管道統計事件數：`web`、`api`、`im`、`sms`、`phone` 或 `agent`。 |
