```http
POST /api/v1/alerts/incidents/{id}/resolve
```

解決處於 `open` 或 `acknowledged` 狀態的事件。呼叫後，系統會將狀態設為 `resolved`，在 `resolvedBy` 與 `resolvedAt` 中記錄發出呼叫的使用者與時間，並停止升級。系統也會將觸發通知標記為已確認，並傳送 `alert.resolved` 事件。此呼叫需要 `alerts.incidents.acknowledge` 權限，請求主體為空。

解決事件時，系統會一併解決[併入](/zh-Hant/api/alerting/merge-incidents)該事件的其他事件。若規則仍符合觸發條件，系統會在下次評估時開啟新事件。解決事件不會停用規則。

<Note>
  若事件已處於 `resolved` 或 `closed` 狀態，系統會原樣傳回該事件。`resolvedBy` 與 `resolvedAt` 會保留首次解決時的使用者與時間，系統也不會再次傳送事件。
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/resolve \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

回應會傳回更新後的事件。各欄位的說明請參閱[列出事件](/zh-Hant/api/alerting/list-incidents)。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `403` | 權杖缺少 `alerts.incidents.acknowledge` 權限。 |
| `404` | 事件不存在。 |
