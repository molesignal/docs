```http
POST /api/v1/alerts/incidents/{id}/escalate
```

將進行中的事件移至升級策略的某個層級，立即通知該層級的目標，`escalation.reason` 為 `manual`。未指定 `step` 時，採用下一個適用於事件嚴重程度的層級。`acknowledged` 的事件會回到 `open`，暫緩隨即結束，該層級會重新計算確認逾時；若仍無人確認，就從這個層級繼續升級。此呼叫需要 `alerts.incidents.escalate` 權限，請求本文可以留空。

**請求本文**

| 欄位 | 類型 | 必填 | 說明 |
|---|---|---|---|
| `step` | integer | 否 | 層級，從 0 開始計數，且必須適用於事件的嚴重程度。預設採用下一個適用的層級。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/escalate \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"step": 1}'
```
</RequestExample>

回應包含更新後的事件，各欄位的說明請參閱[列出事件](/zh-Hant/api/alerting/list-incidents)。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 事件沒有升級策略；`step` 超出策略的層級範圍或不適用於事件的嚴重程度；或事件已位於最後一個層級，但未指定 `step`。 |
| `403` | 權杖缺少 `alerts.incidents.escalate` 權限，或無權存取此事件。 |
| `404` | 事件不存在。 |
| `409` | 事件已恢復或已併入其他事件，或事件在更新期間持續變動；重試即可。 |
