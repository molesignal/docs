```http
POST /api/v1/alerts/incidents/{id}/reassign
```

將處理中的事件轉交給其他負責對象。請求本文以 `kind` 指定轉交對象：

- `users`：`userIds` 中的使用者（1 到 10 位組織成員）成為負責人，並收到一則升級通知，`escalation.reason` 為 `reassigned`。事件回到 `open`，目前層級重新計算確認逾時；若仍無人確認，則照常升級到下一層級。
- `team`：將事件轉交給 `teamId` 指定的團隊，改用該團隊的值班策略。若團隊未設定值班策略，則使用名為 `default` 的策略，並從第一個適用的層級重新開始。
- `policy`：改用 `escalationPolicyId` 指定的策略，從第一個適用的層級重新開始，團隊維持不變。

三種情況下，事件都會回到 `open`，暫緩隨之結束，並在[時間軸](/zh-Hant/api/alerting/incident-timeline)上記錄這次轉交。此呼叫需要 `alerts.incidents.update` 權限。

**請求本文**

| 欄位 | 類型 | 必填 | 說明 |
|---|---|---|---|
| `kind` | string | 是 | `users`、`team` 或 `policy`。 |
| `userIds` | array | `users` 時必填 | 1 到 10 位組織成員的使用者 ID。 |
| `teamId` | string | `team` 時必填 | 團隊。 |
| `escalationPolicyId` | string | `policy` 時必填 | 升級策略。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/reassign \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"kind": "users", "userIds": ["<user-id>"]}'
```
</RequestExample>

回應會傳回更新後的事件。各欄位的說明請參閱[列出事件](/zh-Hant/api/alerting/list-incidents)。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | `userIds` 為空、包含超過 10 位使用者，或包含組織以外的使用者；或團隊未設定值班策略，且沒有 `default` 策略；或策略中沒有適用於事件嚴重程度的層級。 |
| `403` | 權杖缺少 `alerts.incidents.update` 權限，或沒有此事件的存取權。 |
| `404` | 事件不存在。 |
| `409` | 事件已恢復、已併入其他事件，或在更新期間持續變動；重試即可。 |
