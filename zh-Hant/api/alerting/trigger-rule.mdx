```http
POST /api/v1/alerts/rules/{id}/trigger
```

不評估條件，直接為規則開啟一個事件。此呼叫適合演練通知與升級，或手動觸發事件。已停用的規則也適用。呼叫需要 `alerts.rules.manage` 權限，且要求主體為空。

- 如果規則已有狀態為 `open` 或 `acknowledged` 的事件，呼叫會原樣傳回該事件。可安全地重複呼叫。
- 否則，呼叫會建立狀態為 `open` 的事件，並送出觸發通知事件。
- 嚴重程度優先採用規則的 `severity`，其次是名為 `severity` 的標籤，最後是 `warning`。呼叫會忽略 `thresholds`。
- 註解 `manual_triggered_by` 儲存發起呼叫的使用者識別碼，`triggering_query.sample_values` 為空。

已啟用的規則會在下次評估時解除未符合條件的事件。已停用的規則會讓事件保持開啟，直到使用者解除事件。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/trigger \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `403` | 權杖缺少 `alerts.rules.manage` 權限。 |
| `404` | 規則不存在。 |
