```http
POST /api/v1/alerts/incidents/{id}/ack
```

確認處於 `open` 狀態的事件。呼叫會將狀態設為 `acknowledged`，在 `acknowledgedBy` 和 `acknowledgedAt` 中記錄發起呼叫的使用者與時間，將該使用者加入 `assignees`，並停止升級，因為只有 `open` 事件會依[升級策略](/zh-Hant/api/alerting/create-escalation)繼續升級。呼叫也會將觸發通知標記為已確認，並傳送 `alert.acknowledged` 事件。此呼叫需要 `alerts.incidents.acknowledge` 權限，請求本文為空。

已確認的事件會維持已確認狀態，直到使用者解決事件。如果升級策略設定了 [`ackRetriggerSecs`](/zh-Hant/api/alerting/create-escalation)，且事件在確認後經過指定時間仍未解決，事件就會回到 `open` 並重新傳送通知。即使事件不再符合規則，評估器也不會將其標記為已解決。

<Note>
  確認已處於 `acknowledged` 狀態的事件時，會原樣傳回該事件。`acknowledgedBy` 和 `acknowledgedAt` 會保留首次確認的使用者與時間，且不會再次傳送事件。確認處於 `resolved` 或 `closed` 狀態的事件時，會傳回 `409`，事件維持原狀態。
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/ack \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

回應會傳回更新後的事件。各欄位的說明請參閱[列出事件](/zh-Hant/api/alerting/list-incidents)。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `403` | 權杖缺少 `alerts.incidents.acknowledge` 權限。 |
| `404` | 事件不存在。 |
