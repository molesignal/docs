```http
POST /api/v1/alerts/routing/test
```

依目前的路由規則、團隊的值班策略和服務目錄，計算帶有這些標籤的事件會如何[分派](/zh-Hant/alerting/routing#分派順序)。此操作需要 `alerts.routing.read` 權限。依來源使用預設策略計算，不建立事件，也不傳送通知。

| 欄位 | 類型 | 說明 |
|---|---|---|
| `labels` | object | 事件的標籤。依 `alert.source` 標籤判斷來源：`external` 是警示來源，`synthetic` 是合成監控檢查，其他值則視為警示規則。 |
| `services` | array | 受影響的服務。標籤中沒有 `service.name` 或 `service` 時，取第一個服務。 |
| `severity` | string | `info`、`warning`（預設）、`error` 或 `critical`。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"labels": {"service.name": "checkout", "env": "prod"}, "severity": "critical"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "decision": {
    "escalationPolicyId": "<policy-id>",
    "teamId": "<team-id>",
    "routing": { "reason": "rule", "ruleId": "<rule-id>", "ruleName": "Payments in production" }
  },
  "matchedRuleId": "<rule-id>",
  "service": "default/checkout",
  "serviceTeamId": "<team-id>",
  "labelTeamId": null
}
```
</ResponseExample>

| 欄位 | 說明 |
|---|---|
| `decision.escalation_policy_id` | 事件會採用的升級策略；`default` 表示預設策略。 |
| `decision.team_id` | 事件會分派給哪個團隊；沒有團隊時為 `null`。 |
| `decision.routing` | 分派依據，與事件中的 `routing` 相同。請參閱[事件欄位](/zh-Hant/api/alerting/list-incidents#事件欄位)。 |
| `matchedRuleId` | 符合的路由規則；沒有符合的規則時為 `null`。 |
| `service` | 用來查詢負責團隊的服務，格式為 `命名空间/服务名`。 |
| `serviceTeamId` | 服務目錄中負責此服務的團隊。 |
| `labelTeamId` | 標籤 `teamId` 或 `team` 指向的團隊。 |
