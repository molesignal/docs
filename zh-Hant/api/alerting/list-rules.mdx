```http
GET /api/v1/alerts/rules
GET /api/v1/alerts/rules/{id}
```

第一個呼叫會以陣列傳回組織內的所有告警規則，第二個呼叫則傳回單一規則。兩個呼叫都需要 `alerts.rules.read`。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/rules \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "id": "3KEDBLvTYO6DnWi8H9S9MNLpPT7",
    "orgId": "<organization-id>",
    "name": "High error rate",
    "description": "More than 100 errors in five minutes",
    "enabled": true,
    "kind": "scheduled",
    "query": {
      "language": "sql",
```

規則包含[建立規則](/zh-Hant/api/alerting/create-rule)的欄位，以及下列唯讀欄位：

| 欄位 | 說明 |
|---|---|
| `id`、`orgId` | 規則與組織的識別碼。 |
| `createdAt`、`updatedAt` | 自 Unix 紀元起算的微秒數。 |
| `lastEvalAt` | 最近一次完成評估的時間，單位為微秒。第一次評估前為 `null`。查詢失敗或逾時時維持不變。 |
| `lastState` | 該次評估的結果：不符合條件時為 `{"kind": "healthy"}`，連續符合條件的次數未達 `forPeriods` 時為 `{"kind": "pending", "consecutive": 1}`，持續符合條件達指定時間後為 `{"kind": "firing"}`；若規則已觸發，但[告警管線](/zh-Hant/pipelines/alert-events#處理結果)捨棄了原本要開啟的事件，則為 `{"kind": "dropped"}`。處於 `silenceSecs` 冷卻期間的 `firing` 規則不會開啟新事件。 |

`id` 不存在時傳回 `404`。
