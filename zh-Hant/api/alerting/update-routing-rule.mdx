```http
PUT /api/v1/alerts/routing/rules/{id}
```

完整寫回一條[路由規則](/zh-Hant/alerting/routing#路由規則)，需要 `alerts.routing.manage` 權限。欄位與[建立路由規則](/zh-Hant/api/alerting/create-routing-rule)相同，未提供的選填欄位會恢復為預設值。規則的位置不變，如需變更順序，請使用[調整順序](/zh-Hant/api/alerting/reorder-routing-rules)。已開啟的事件不受影響。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "enabled": false, "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

回應會傳回修改後的規則。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 欄位不正確，或目標團隊或策略不存在。 |
| `403` | 權杖缺少 `alerts.routing.manage` 權限。 |
| `404` | 規則不存在，或屬於其他組織。 |
| `422` | 缺少 `name` 或 `target`，或無法辨識欄位值。回應為純文字。 |
