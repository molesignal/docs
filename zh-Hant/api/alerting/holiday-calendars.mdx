```http
GET    /api/v1/alerts/holiday-calendars
POST   /api/v1/alerts/holiday-calendars
GET    /api/v1/alerts/holiday-calendars/{id}
PUT    /api/v1/alerts/holiday-calendars/{id}
DELETE /api/v1/alerts/holiday-calendars/{id}
GET    /api/v1/alerts/holiday-calendars/{id}/references
POST   /api/v1/alerts/holiday-calendars/parse
```

讀取需要 `alerts.calendars.read`；建立、修改、刪除和讀取檔案需要 `alerts.calendars.manage`。如需瞭解如何依行事曆計算每週時段，請參閱[假日行事曆](/zh-Hant/alerting/on-call#假日行事曆)。

## 建立或修改行事曆

`POST` 建立一份行事曆，`PUT` 取代整份行事曆。回應會傳回這份行事曆，包含 `id`、`orgId`、`createdBy`、`createdAt` 和 `updatedAt`。

| 欄位 | 類型 | 必填 | 說明 |
|---|---|---|---|
| `name` | string | 是 | 最多 80 個字元，同一組織內不得重複。 |
| `description` | string | 否 | 最多 500 個字元。 |
| `days` | array | 否 | 最多 2000 天，每天寫成 `{"date": "2026-10-01", "kind": "holiday", "name": "国庆节"}`。`kind` 為 `holiday`（放假）或 `workday`（補班，依週一的時段計算）；`name` 最多 80 個字元。同一個日期只能出現一次。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/holiday-calendars \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "中国 2026", "days": [{"date": "2026-10-01", "kind": "holiday", "name": "国庆节"}, {"date": "2026-10-10", "kind": "workday", "name": "补班"}]}'
```
</RequestExample>

在每週時段的 `calendar` 中填入行事曆的 ID 即可套用：`{"calendarId": "<id>", "holidays": "exclude"}` 會排除放假日，`"holidays": "only"` 則只在放假日生效。[升級策略](/zh-Hant/api/alerting/create-escalation)的支援時段、[路由規則](/zh-Hant/api/alerting/create-routing-rule)和通知策略的時間條件、值班排程的輪值、警示管線，以及每週重複的靜音時段都可套用行事曆。儲存時，如果行事曆不屬於目前的組織，就會傳回 `400`。

## 讀取 ICS 檔案

`POST /parse` 接受 `{"content": "<.ics 的内容>"}`，大小上限為 2 MiB，並傳回 `{"days": [...]}`，不會儲存任何資料。每個全天事件計為一天，跨日事件逐日計算；名稱包含「補班」、「上班」或以「班」結尾的事件會歸類為 `workday`。

## 查看哪些地方使用行事曆

`GET /{id}/references` 列出使用這份行事曆計算時段的地方，每個項目皆為 `{"kind", "id", "name"}`；`kind` 為 `routing_rule`、`escalationPolicy`、`schedule`、`mute_rule`、`notify_policy` 或 `alert_pipeline`。清單不為空時，`DELETE` 會傳回 `409`。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 欄位超出限制、同一個日期出現兩次，或無法讀取檔案。 |
| `403` | 權杖缺少對應的權限。 |
| `404` | 目前的組織沒有這份行事曆。 |
| `409` | 已有同名行事曆，或行事曆仍在使用中。 |
