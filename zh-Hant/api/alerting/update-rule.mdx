```http
PUT /api/v1/alerts/rules/{id}
```

取代規則的設定。請求主體是[建立規則](/zh-Hant/api/alerting/create-rule)的完整請求主體。此呼叫會保留規則的 `id`、組織、`createdAt`、`lastEvalAt` 與 `lastState`。修改後的 `escalationPolicyId` 必須對應至該組織的其中一項策略，或為 `default`。此呼叫需要 `alerts.rules.manage` 權限。

<Warning>
  此呼叫會取代整條規則，不會合併欄位。省略的欄位會使用預設值，其中 `enabled` 為 `true`，`kind` 為 `scheduled`。省略的 `labels`、`annotations` 與 `thresholds` 會變為空值。只有省略 `escalationPolicyId` 時，才會保留目前的策略。請先讀取規則，再將修改納入完整的請求主體並送出。
</Warning>

事件的指紋由規則的 `id` 與 `labels` 衍生。修改 `labels` 後，已開啟的事件會保留舊指紋，不再自動解決。請透過[解決事件](/zh-Hant/api/alerting/resolve-incident)手動解決。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  --data-binary @- <<'EOF'
{
  "name": "High error rate",
  "description": "More than 200 errors in five minutes",
  "enabled": true,
  "kind": "scheduled",
  "query": {
    "language": "sql",
    "statement": "SELECT count(*) AS c FROM app WHERE level = 'error'",
    "periodSecs": 300,
    "stream": { "name": "app", "streamType": "logs" }
  },
  "trigger": { "operator": "gt", "threshold": 200, "forPeriods": 2, "silenceSecs": 0 },
  "severity": "critical",
  "labels": { "team": "checkout" }
}
EOF
```
</RequestExample>

回應會傳回更新後的規則，格式請參閱[列出規則](/zh-Hant/api/alerting/list-rules)。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 請求主體未通過與[建立規則](/zh-Hant/api/alerting/create-rule)相同的檢查，或修改後的 `escalationPolicyId` 未對應至該組織的任何策略。 |
| `404` | 規則不存在。 |
| `422` | 缺少必填欄位或欄位值的型別錯誤，回應為純文字。 |
