[抑制](/zh-Hant/alerting/inhibition)規則。檢視需要 `alerts.inhibitions.read`，修改需要 `alerts.inhibitions.manage`。

```http
GET    /api/v1/alerts/inhibit-rules
POST   /api/v1/alerts/inhibit-rules
GET    /api/v1/alerts/inhibit-rules/{id}
PUT    /api/v1/alerts/inhibit-rules/{id}
DELETE /api/v1/alerts/inhibit-rules/{id}
```

**請求本文**

| 欄位 | 類型 | 說明 |
|---|---|---|
| `name` | string | 必填，最多 255 個字元。 |
| `enabled` | boolean | 預設為 `true`。 |
| `source.matchers` | array | 來源事件的標籤條件：`{label, op, value}`，`op` 可為 `eq`、`neq`、`re`、`nre`。必須符合所有條件。 |
| `source.min_severity` | string | 嚴重程度必須等於或高於此值。未指定則不限。 |
| `target.matchers` | array | 目標事件的標籤條件。未指定則符合所有事件。 |
| `target.max_severity` | string | 嚴重程度必須等於或低於此值。未指定則不限。 |
| `equal` | array | 來源與目標事件都必須有這些標籤，且值相同，才會抑制。最多 16 個。`source.matchers` 和 `equal` 不可同時為空。 |
| `moreSevereOnly` | boolean | 來源事件的嚴重程度必須高於目標事件。預設為 `true`。 |
| `waitSecs` | integer | 發送目標事件通知前的等待時間，範圍為 0 到 600，預設為 60。小於 15 時以 15 計。 |
| `lingerSecs` | integer | 來源事件恢復後繼續抑制的時間，範圍為 0 到 3600，預設為 120。 |
| `comment` | string | 說明。 |

事件未帶有 `service` 或 `host` 標籤時，標籤條件會分別採用受影響的服務或主機。`alert.rule_id` 代表建立事件的規則或來源。規則運算式有誤時，傳回 `400`。

清單和詳細資料中的每條規則都有一個額外欄位 `inhibiting`，表示目前抑制的事件數量。

<RequestExample>
```bash cURL
curl -X POST "http://localhost:5080/api/v1/alerts/inhibit-rules" \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "name": "同一个服务，严重的压住次要的",

```

## 預覽

```http
POST /api/v1/alerts/inhibit-rules/preview
```

請求本文同上（可省略 `name`，無須先儲存規則），需要 `alerts.inhibitions.read`。僅用這條規則評估目前處理中的事件，忽略其他規則與 `enabled` 的值。

| 欄位 | 說明 |
|---|---|
| `pairs[].source_incident_id`、`sourceSummary`、`sourceSeverity` | 觸發抑制的來源事件。 |
| `pairs[].target_incident_id`、`targetSummary`、`targetSeverity` | 受到抑制的目標事件。 |

## 解除單一事件的抑制

```http
POST /api/v1/alerts/incidents/{id}/inhibition/lift
```

需要有此事件的 `alerts.incidents.update` 權限。系統會立即發送受抑制的通知，不再抑制此事件，並將操作記錄在時間軸與稽核記錄中。若事件未受抑制，則不執行任何操作。若事件已解決或已合併至其他事件，則傳回 `409`。傳回事件本身。

事件的 JSON 使用以下欄位表示抑制狀態：

| 欄位 | 說明 |
|---|---|
| `inhibition` | 目前的抑制資訊：`ruleId`、`ruleName`、`sourceIncidentId`、`sourceSummary`、`since`，以及來源事件恢復後的倒數截止時間 `endingAt`。事件解決後仍保留此欄位，表示當時未發送通知。 |
| `inhibitionWaitUntil` | 先等到此時間點（微秒），確認是否會出現來源事件，再決定是否發送通知。 |
| `inhibitionLiftedBy` | 解除抑制、讓通知照常發送的操作者。 |
