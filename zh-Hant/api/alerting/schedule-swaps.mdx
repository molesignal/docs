換班申請會請排班中的另一位成員代替發起人值班一段時間。受邀者接受後，排班會新增一筆[臨時替班](/zh-Hant/alerting/on-call#臨時代班)，申請隨即生效；若排班啟用了**換班須經核准**（`swapNeedsApproval`），受邀者接受後，還須由具備排班管理權限的人員核准。時段結束時，尚未確定的申請會標記為已過期。每個步驟都會通知相關人員（請參閱內建通知策略[換班：通知相關人員](/zh-Hant/notification-channels#內建策略)），並記錄在稽核日誌中。

| 方法與路徑 | 用途 | 權限 |
|---|---|---|
| `GET /api/v1/schedules/swaps` | 列出目前使用者發起或受邀替班的申請，涵蓋所有排班。 | `schedules.read` |
| `GET /api/v1/schedules/{id}/swaps` | 列出指定排班的申請，最新的排在前面。 | 該排班的 `schedules.read` |
| `POST /api/v1/schedules/{id}/swaps` | 發起申請。 | 該排班的 `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/accept` | 接受申請。僅限受邀者操作。 | 該排班的 `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/decline` | 拒絕申請。僅限受邀者操作。 | 該排班的 `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/cancel` | 撤回申請。僅限發起人操作，可在申請確定前撤回。 | 該排班的 `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/approve` | 核准受邀者已接受的申請，替班隨即生效。 | 該排班的 `schedules.swaps.approve` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/reject` | 駁回受邀者已接受的申請。 | 該排班的 `schedules.swaps.approve` |

## 發起申請

**請求本文**

| 欄位 | 類型 | 必填 | 說明 |
|---|---|---|---|
| `targetId` | string | 是 | 接班人須為該排班的成員，且不得是發起人。 |
| `startAt`、`endAt` | integer | 是 | 要換班的時段，以 Unix 微秒表示。時段須在未來，且結束時間須晚於開始時間。 |
| `note` | string | 否 | 備註，最多 500 字。 |

該時段只能有發起人在排班中值班。同一排班內，不得申請與尚未確定的申請重疊的時段。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/$SCHEDULE_ID/swaps \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"targetId": "<user-id>", "startAt": 1790060400000000, "endAt": 1790146800000000, "note": "Travelling on Friday"}'
```
</RequestExample>

各 API 呼叫都會傳回申請；列表會傳回 `{ "swaps": [ ... ] }`。

<ResponseExample>
```json 200
{
  "id": "3KHq2nB7yZ0d4kVwXc1sPa9LmQe",
  "orgId": "<organization-id>",
  "scheduleId": "<schedule-id>",
  "scheduleName": "Payments primary",
  "requesterId": "<user-id>",
  "targetId": "<another-user-id>",
  "startAt": 1790060400000000,
  "endAt": 1790146800000000,
  "note": "Travelling on Friday",
  "status": "pending",
  "overrideId": null,
  "decidedBy": null,
  "decidedAt": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

| 欄位 | 說明 |
|---|---|
| `status` | `pending`（等待受邀者回覆）、`awaiting_approval`（受邀者已接受，等待核准）、`accepted`（已生效）、`declined`（受邀者已拒絕）、`rejected`（管理員已駁回）、`cancelled`（已撤回）或 `expired`（已過期）。 |
| `overrideId` | 申請生效後新增的替班。 |
| `decidedBy`、`decidedAt` | 最後一次回覆、核准、駁回或撤回的人員與時間。 |

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 時段無效、接班人不是排班成員、該時段不只發起人值班，或時段與尚未確定的申請重疊。 |
| `403` | 缺少權限，或操作者無法執行此步驟。 |
| `404` | 排班或申請不存在。 |
| `409` | 申請已不在此階段（例如已接受或已過期），或有人同時修改了申請；請重新讀取後再試一次。 |
