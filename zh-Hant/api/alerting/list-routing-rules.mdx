```http
GET /api/v1/alerts/routing/rules
```

依比對順序（`position` 由小到大）列出組織的[路由規則](/zh-Hant/alerting/routing#路由規則)，需要 `alerts.routing.read` 權限。清單也包含停用的規則。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "id": "3KF0q7vXbJ2mYc8sTn4LwRk9Ez1",
    "orgId": "<organization-id>",
    "name": "Payments in production",
    "enabled": true,
    "position": 0,
    "conditions": [
      { "key": "env", "operator": "equals", "values": ["prod"] },
      { "key": "service.name", "operator": "in", "values": ["checkout", "cart"] }
    ],
    "minSeverity": "error",
    "origins": [],
    "target": { "kind": "team", "teamId": "<team-id>" },
    "createdBy": "<user-id>",

    "updatedAt": 1790000000000000
  }
]
```
</ResponseExample>

## 規則欄位

| 欄位 | 說明 |
|---|---|
| `id`、`orgId` | 規則與組織的識別碼。 |
| `name` | 規則名稱。 |
| `enabled` | 停用的規則不參與比對。 |
| `position` | 比對順序，數值較小的優先。 |
| `conditions` | 事件標籤須符合所有條件才算命中；若未指定條件，則所有事件都符合。每個條件包含 `key`、`operator` 和 `values`。 |
| `minSeverity` | 事件的嚴重程度須達到此門檻才算命中：`info`、`warning`、`error` 或 `critical`；`null` 表示不限。 |
| `origins` | 僅適用於下列來源的事件：`rule`（警示規則）、`external`（警示來源）、`synthetic`（合成監控檢查）；若未指定來源，則不限。 |
| `target` | 命中後的路由目的地：`{"kind": "team", "teamId": …}` 或 `{"kind": "policy", "policyId": …}`。 |
| `createdBy` | 建立規則的使用者。 |
| `createdAt`、`updatedAt` | 建立時間與最後修改時間，單位為微秒。 |

`operator` 的可用值：

| `operator` | `values` | 命中 |
|---|---|---|
| `equals` | 一個值 | 標籤值等於指定值。 |
| `not_equals` | 一個值 | 標籤值不等於指定值，或事件沒有這個標籤。 |
| `in` | 一或多個值 | 標籤值等於其中任一值。 |
| `matches` | 一個規則運算式 | 整個標籤值符合指定的規則運算式。 |
