每起事件各有一份內部復盤，內文採用 Markdown。內部復盤與[狀態頁的事故復盤](/zh-Hant/status-pages#事件事後檢討)分開儲存；可在頁面上將復盤摘要複製到狀態頁。頁面操作方式請參閱[重大事件與復盤](/zh-Hant/alerting/major-incidents#事後檢討)。

| 方法與路徑 | 用途 | 權限 |
|---|---|---|
| `GET /api/v1/alerts/postmortems` | 列出組織的復盤，最新的排在前面，並附上改進項目數量。 | `postmortems.read` |
| `GET /api/v1/alerts/incidents/{id}/postmortem` | 取得事件的復盤和改進項目。 | 該事件的 `alerts.incidents.read`，以及 `postmortems.read` |
| `POST /api/v1/alerts/incidents/{id}/postmortem` | 為事件建立一份復盤。 | 該事件的 `alerts.incidents.read`，以及 `postmortems.manage` |
| `PUT /api/v1/alerts/postmortems/{id}` | 修改復盤的標題、內文、狀態、負責人和審閱者。 | `postmortems.manage` |
| `POST /api/v1/alerts/postmortems/{id}/actions` | 新增一個改進項目。 | `postmortems.manage` |
| `PUT /api/v1/alerts/postmortems/{id}/actions/{actionId}` | 修改一個改進項目。 | `postmortems.manage` |
| `DELETE /api/v1/alerts/postmortems/{id}/actions/{actionId}` | 刪除一個改進項目。 | `postmortems.manage` |
| `POST /api/v1/alerts/postmortems/{id}/actions/{actionId}/ticket` | 為改進項目建立工單。 | `postmortems.manage` |

## 起草與修改

```http
POST /api/v1/alerts/incidents/{id}/postmortem
```

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `title` | string | 是 | 1 到 200 個字元。 |
| `body` | string | 否 | Markdown 內文，最多 100000 個字元。 |

事件已有復盤時，傳回 `409`。頁面會先依範本起草（摘要、影響、時間軸、根本原因、做得好的地方、做得不好的地方、改進項目），再呼叫這個 API。系統會將建立操作記入稽核記錄。修改時只傳送要變更的欄位：`title`、`body`、`status`、`ownerId`（傳送 `null` 以取消指派）和 `reviewerIds`。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/postmortems/$POSTMORTEM_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"status": "in_review", "reviewerIds": ["<user-id>"]}'
```
</RequestExample>

讀取、起草和修改都會傳回 `{ "postmortem": { ... }, "actions": [ ... ] }`；事件沒有復盤時，`postmortem` 為 `null`。

```json 200
{
```

| 欄位 | 說明 |
|---|---|
| `status` | `draft`（草稿）、`in_review`（審閱中）或 `published`（已發布）。首次改為 `published` 時，記錄 `publishedAt`。 |

清單的每一列包含復盤的各個欄位，另附事件摘要 `incidentSummary`、未完成的改進項目數 `openActions`，以及逾期未完成的改進項目數 `overdueActions`。

## 改進項目

新增改進項目的請求本文為 `{ "title": "…", "ownerId": "<user-id>", "dueAt": 1790600000000000 }`。標題長度為 1 到 300 個字元，每份復盤最多可有 50 個改進項目，`dueAt` 採用 Unix 時間戳記，以微秒為單位。修改時只傳送要變更的欄位：`title`、`ownerId`、`dueAt`（後兩個欄位可傳送 `null` 清除）和 `status`（`open` 或 `done`）。新增和修改都會傳回改進項目，刪除則傳回 `{ "deleted": true }`。

```http
POST /api/v1/alerts/postmortems/{id}/actions/{actionId}/ticket
```

請求本文為 `{ "connectorId": "<connector-id>" }`：透過這個[工單連接器](/zh-Hant/api/alerting/tickets)為改進項目建立工單，並傳回含有 `ticketKey` 和 `ticketUrl` 的改進項目。若已建立工單，則原樣傳回改進項目。這張工單不會隨事件新增留言或變更狀態，關閉工單也不會將事件標為已解決。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 欄位超出限制，或工單連接器已停用。 |
| `403` | 缺少權限，或沒有存取此事件的權限。 |
| `404` | 事件、復盤、改進項目或工單連接器不存在。 |
| `409` | 事件已有復盤。 |
