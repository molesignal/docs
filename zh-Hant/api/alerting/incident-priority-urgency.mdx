```http
PUT /api/v1/alerts/incidents/{id}/priority
PUT /api/v1/alerts/incidents/{id}/urgency
```

兩個呼叫都需要 `alerts.incidents.update`，只能修改進行中且未併入其他事件的事件。時間軸分別記錄 `priority_changed` 和 `urgency_changed`。

- **優先順序**：請求主體為 `{"priority": "P2"}`，`null` 表示不設定。值必須是組織的[優先順序級別](/zh-Hant/alerting/on-call#緊急度與優先順序等級)之一。只修改優先順序，不重新通知。
- **緊急程度**：在請求主體中填入組織某個緊急程度級別的鍵，例如 `{"urgency": "high"}`。系統會將呼叫者記錄在 `urgencySetBy`，之後支援時段不再變更緊急程度。調高緊急程度時，`open` 的事件會從適用的第一級重新通知，`escalation.reason` 為 `urgency_raised`。調低時只修改緊急程度；若調到不逐級升級的級別，之後就不會再升級到下一級。

若要批次修改，請使用[批次處理](/zh-Hant/api/alerting/bulk-incidents)的 `{"action": "set_priority", "priority": "P2"}` 與 `{"action": "set_urgency", "urgency": "low"}`。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/urgency \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"urgency": "high"}'
```
</RequestExample>

回應會傳回更新後的事件。事件的 `urgency` 是某個級別的鍵（在新增此欄位前開啟的事件沒有這個欄位，視為高緊急程度）；`priority` 為 `P1` 到 `P9`，或未設定。`urgencyByPolicy` 為 `true` 表示緊急程度由升級策略決定。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 優先順序超出組織設定的級別範圍，或緊急程度不屬於組織設定的任何級別。 |
| `422` | 優先順序不在 `P1` 到 `P9` 的範圍內，或緊急程度的鍵並非由小寫字母、數字和底線組成。 |
| `403` | 權杖缺少 `alerts.incidents.update` 權限，或無權存取此事件。 |
| `404` | 事件不存在。 |
| `409` | 事件已復原或已併入其他事件。 |
