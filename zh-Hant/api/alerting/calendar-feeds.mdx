訂閱網址供行事曆應用程式（Google 日曆、Outlook、Apple 行事曆等）讀取，內容採用 RFC 5545 的 iCalendar 格式，涵蓋過去 30 天到未來 90 天的班次，包括代班和換班。訂閱分為兩種：單一排班的所有班次，或訂閱者在各個排班中的班次。

| 方法與路徑 | 用途 | 權限 |
|---|---|---|
| `GET /api/v1/schedules/calendar-feeds` | 取得目前使用者的訂閱。 | `schedules.read` |
| `POST /api/v1/schedules/calendar-feeds` | 產生訂閱網址；若同一排班已有訂閱，或個人訂閱已存在，則重設訂閱，舊網址立即失效。 | `schedules.calendar_feeds.manage`，訂閱排班時還需要該排班的 `schedules.calendar_feeds.manage` 權限 |
| `DELETE /api/v1/schedules/calendar-feeds/{id}` | 停止目前使用者的一項訂閱，網址立即失效。 | `schedules.calendar_feeds.manage` |
| `GET /api/v1/public/calendar/{token}.ics` | 供行事曆應用程式讀取的網址，無須登入。 | 網址中的 Token |

## 產生訂閱網址

**請求本文**

| 欄位 | 類型 | 必填 | 說明 |
|---|---|---|---|
| `scheduleId` | string | 否 | 訂閱指定的排班；留空則建立個人訂閱。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/calendar-feeds \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"scheduleId": "<schedule-id>"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "feed": {
    "id": "3KHtq0dYc1fUe8WnP2xLbR7aZsM",
    "scheduleId": "<schedule-id>",
    "scheduleName": "Payments primary",
    "createdAt": 1790000000000000,
    "lastUsedAt": null
  },
  "path": "/api/v1/public/calendar/<token>.ics",
  "url": "https://molesignal.example.com/api/v1/public/calendar/<token>.ics"
}
```
</ResponseExample>

只在產生訂閱網址時傳回一次，資料庫只儲存 Token 的 SHA-256 雜湊值。`url` 以執行個體的外部網址組成。若未設定外部網址，`url` 為 `null`，請將 `path` 接在存取 MoleSignal 的網址後方。清單中的每項訂閱都包含 `id`、`scheduleId`、`scheduleName`、`createdAt`，以及行事曆上次讀取的時間 `lastUsedAt`，但不包含訂閱網址。

## 行事曆應用程式讀取

```http
GET /api/v1/public/calendar/{token}.ics
```

每次讀取時，系統都會重新確認訂閱者的帳號仍有效、仍屬於該組織，且仍擁有 `schedules.read` 權限。若訂閱的是排班，系統也會確認訂閱者仍能檢視該排班。驗證未通過、Token 不正確或訂閱已停止時，一律傳回 `404`。班次標題和說明採用訂閱者的介面語言。

任何取得網址的人都能檢視這些班次。若網址外洩，請重設或停止訂閱。
