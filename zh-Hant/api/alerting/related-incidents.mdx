兩個呼叫都需要事件的 `alerts.incidents.read`。

## 相似事件

```http
GET /api/v1/alerts/incidents/{id}/similar
```

在同一組織於事件觸發前 90 天內開過的事件裡，找出與它最相似的，最多 5 個，分數高的在前，同分則新的在前。併入它的事件和它併入的事件不算。分數是下列各項之和，至少 2 分才列出：

| 依據 | `reasons` 中的值 | 分數 |
|---|---|---|
| 同一告警指紋 | `fingerprint` | 5 |
| 同一條規則（指紋不同時） | `rule` | 3 |
| 涉及的服務有重疊 | `services` | 重疊度 × 2 |
| 標籤相近：相同的鍵值對占兩邊全部鍵值對的比例至少 0.3 | `labels` | 比例 × 2 |
| 標題相近：三字串相似度至少 0.3，做法同 PostgreSQL `pg_trgm`，漢字也算 | `title` | 相似度 × 2 |
| 分派到同一個團隊 | `team` | 1 |

重疊度是兩邊交集除以聯集。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/similar \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "incidents": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
      "summary": "High error rate · checkout",
      "severity": "critical",
      "status": "resolved",
      "createdAt": 1789400000000000,
      "resolvedAt": 1789401800000000,
      "resolvedBy": "<user-id>",
      "score": 7.6,
      "reasons": ["fingerprint", "services", "labels", "team"],
      "notes": 2,
      "rootCause": "Connection pool exhausted after the payments client stopped releasing connections."
    }
  ]
}
```
</ResponseExample>

| 欄位 | 說明 |
|---|---|
| `score`、`reasons` | 分數和分數的依據，見上表。 |
| `resolvedBy` | 解決它的人；規則自行恢復或還沒恢復時為 `null`。 |
| `notes` | 它的[備註](/zh-Hant/api/alerting/add-incident-note)筆數。 |
| `rootCause` | 它的 [AI 根因](/zh-Hant/api/alerting/incident-rca)正文裡第一句說事的話（跳過標題與空行），最長 200 字；沒有分析時省略。 |

## 最近變更

```http
GET /api/v1/alerts/incidents/{id}/changes
```

列出事件觸發前 30 分鐘到觸發後 10 分鐘之間，事件涉及的服務（受影響的服務和 `service` 標籤）及其下游服務[上報的變更](/zh-Hant/apm/deployments#从-ci-上报发布)，最多 20 筆，依時間先後。下游服務從 APM 服務地圖讀出，最多看事件的前 3 個服務；沒有服務地圖時只看事件自己的服務。事件的規則在觸發前 24 小時內改過時，也列一筆 `rule`。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/changes \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "from": 1789998200000000,
  "to": 1790000600000000,
  "changes": [
    {
      "kind": "deployment",
      "at": 1789999100000000,
      "service": "payments",
      "downstream": true,
      "version": "v2026.10.28",
      "status": "succeeded",
      "commit": "9f2c1e4",
      "author": "dana",
      "link": "https://ci.example.com/pipelines/4821"
    },
    {
      "kind": "rule",
      "at": 1789960000000000,
      "downstream": false,
      "ruleId": "3KEDBLvTYO6DnWi8H9S9MNLpPT7",
      "ruleName": "Checkout error rate"
    }
  ]
}
```
</ResponseExample>

| 欄位 | 說明 |
|---|---|
| `from`、`to` | 查看的時間範圍，Unix 微秒。 |
| `kind` | `deployment`、`configuration`、`feature_flag`，或 `rule`（事件的規則被改過）。 |
| `downstream` | 變更屬於下游服務、不是事件自己的服務時為 `true`。 |
| `version`、`status`、`commit`、`description`、`author` | 上報時帶的內容；沒帶的省略。 |
| `link` | 上報的流水線位址，沒有時是合併請求位址。 |
| `ruleId`、`ruleName` | `rule` 變更的規則。 |

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `403` | Token 缺少 `alerts.incidents.read`，或無權存取這個事件。 |
| `404` | 事件不存在。 |

## 業務影響

```http
GET /api/v1/alerts/incidents/{id}/business-impact
```

對 Span 裡帶有的每個[業務鍵](/zh-Hant/business-context)，列出事件觸發前 30 分鐘到觸發後 10 分鐘（不晚於目前）內，送往事件相關服務的請求中失敗最多的取值：每個鍵最多 5 個，先依失敗請求數、再依請求數排序。事件沒有關聯服務時讀取所有服務的請求。請求指服務接收請求的 Span。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/business-impact \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "from": 1789998200000000,
  "to": 1790000600000000,
  "services": ["checkout"],
  "declared": true,
  "keys": [
    {
      "key": "tenant",
      "label": "Tenant",
      "field": "tenant.id",
      "more": true,
      "values": [
        { "value": "acme", "requests": 300, "errors": 120, "important": true },
        { "value": "globex", "requests": 90, "errors": 4, "important": false }
      ]
    }
  ]
}
```
</ResponseExample>

| 欄位 | 說明 |
|---|---|
| `services` | 讀取了請求的事件相關服務；事件沒有關聯服務時為空。 |
| `declared` | 沒有任何業務鍵指定 Span 欄位時為 `false`，此時 `keys` 為空。 |
| `field` | 讀取這個鍵的 Span 欄位。 |
| `important` | 這個取值是組織為該鍵標記的重點取值之一。 |
| `more` | 有請求的取值多於列出的。 |

Trace 流缺少欄位、欄位加密，或沒有請求帶這個鍵的業務鍵不會列出。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `403` | Token 缺少 `alerts.incidents.read` 或無權存取這個事件，或者 `streams.query` 和 `sys.telemetry.read` 都沒有。 |
| `404` | 事件不存在。 |
