```http
GET /api/v1/alerts/incidents/{id}/timeline
```

傳回事件的完整歷程：使用者和 MoleSignal 記錄的每個步驟、針對該事件發送的通知，以及併入該事件的其他事件。此呼叫需要 `alerts.incidents.read` 權限。主控台的事件[時間軸](/zh-Hant/alerting/incidents#事件詳細資料)會根據這些資料繪製。

| 欄位 | 內容 |
|---|---|
| `entries` | 記錄的每個步驟，依時間由早到晚排序：`id`、`orgId`、`incidentId`、`at`（微秒）、`kind`、`actor`（使用者 ID；由 MoleSignal 執行時為 `null`）和 `detail`。 |
| `deliveries` | 此事件的通知，依時間由早到晚排序，最多 500 筆：`id`、`eventId`（`alert.triggered:…`、`alert.escalated:…`、`alert.acknowledged:…` 或 `alert.resolved:…`）、`userId`、`connectorId`、`target`（已遮蔽敏感資訊）、`stage`、`status`、`error`、`createdAt` 和 `deliveredAt`。[管線阻止發送](/zh-Hant/pipelines/alert-events#傳送通知前)的策略，其 `status` 為 `skipped`，不含 `userId` 和 `connectorId`，`error` 會指出原因。 |
| `merged` | [併入](/zh-Hant/api/alerting/merge-incidents)此事件的其他事件：`id`、`summary`、`status`、`severity`、`createdAt` 和 `resolvedAt`。 |

| `kind` | `detail` |
|---|---|
| `acknowledged`、`resolved` | `via`：`web`、`api`、`im`、`sms`、`phone` 或 `agent`。 |
| `escalated` | `step`（從 0 開始）、`loop`、`reason`，以及此層級的 `targets`。 |
| `reassigned` | `to`，格式與[轉派事件](/zh-Hant/api/alerting/reassign-incident)相同；`from`：原本的負責人、團隊和策略。 |
| `responders_added` | `userIds`。 |
| `snoozed` | `until`（微秒）和 `durationSecs`。 |
| `snooze_cancelled` | 空白。 |
| `retriggered` | `reason`：`snooze_ended` 或 `ack_timeout`。 |
| `severity_changed` | `from` 和 `to`。 |
| `merged` | `into`：併入的目標事件。 |
| `merged_in` | `incidents`：併入此事件的其他事件。 |
| `merged_recovered` | 自行復原的併入事件的 `incidentId` 和 `summary`。 |
| `note` | `text` 和 `via`。 |
| `remediation_requested` | 發起[修復動作](/zh-Hant/api/alerting/remediation)：執行記錄 `runId`、動作名稱 `action` 和填入的參數 `inputs`。 |
| `remediation_executed` | 修復動作執行完畢：`runId`、`action`、`status`（`succeeded` 或 `failed`）和 `output`（回應或錯誤的開頭）。 |
| `remediation_verified` | 執行後的驗證：`runId`、`action`、`passed` 和驗證方式 `by`（`incidentResolved` 或 `rule_healthy`）。 |
| `ticket_created` | 建立[工單](/zh-Hant/api/alerting/tickets)：`system`（`jira` 或 `meegle`）、`key`、`url` 和連接器名稱 `connector`。 |
| `ticket_updated` | 同步的工單狀態變更：`key`、`status` 和 `done`。 |
| `declared_major` | 宣告為[重大事件](/zh-Hant/api/alerting/major-incidents)；`auto` 為 `true` 時，由組織的自動規則宣告。 |
| `role_assigned` | 指派角色：`role`（`commander`、`communications` 或 `scribe`）和 `userId`，取消指派時 `userId` 為 `null`。 |
| `war_room_created` | 建立作戰室：`platform`、加入群組的連結 `url` 和會議連結 `meetingUrl`。 |
| `task_added`、`task_done` | 新增或完成一項任務：`title`。 |
| `status_update` | 發布一次進度更新：`impact`、`current` 和 `next`。 |
| `pipeline_processed` | [警示管線](/zh-Hant/pipelines/alert-events#處理結果)在建立事件前修改了事件，或發生錯誤：`pipelineId`、`pipeline`、`changes`（每項包含 `field`，例如 `severity` 或 `labels.team`，以及 `from`（新增時省略）和 `to`（刪除時省略））、`more`（已列出的 40 項之外還有多少項變更）和 `error`。 |

<RequestExample>
```bash cURL
curl -X GET http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/timeline \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `403` | 權杖缺少 `alerts.incidents.read` 權限。 |
| `404` | 事件不存在。 |
