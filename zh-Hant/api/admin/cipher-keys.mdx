加密金鑰用於加密資料流中標記為加密的欄位。每把金鑰都是 32 位元組的 AES-256-GCM 金鑰。MoleSignal 使用 `MS_CIPHER_KEY` 提供的根金鑰封裝金鑰材料，且絕不傳回金鑰材料。請參閱[安全性](/zh-Hant/security#欄位層級加密)。

新寫入的加密值一律使用預設金鑰 `__field_default__` 的最新版本。MoleSignal 會在資料流首次需要時建立這把金鑰。其他具名金鑰及各金鑰的舊版，仍可解密使用對應金鑰版本寫入的值。

| 操作 | 端點 | 權限 |
|---|---|---|
| 列出金鑰 | `GET /api/v1/cipher_keys` | `org.cipher_keys.read` |
| 讀取金鑰 | `GET /api/v1/cipher_keys/{name}` | `org.cipher_keys.read` |
| 建立金鑰 | `POST /api/v1/cipher_keys` | `org.cipher_keys.manage` |
| 輪替金鑰 | `POST /api/v1/cipher_keys/{name}/rotate` | `org.cipher_keys.rotate` |
| 刪除金鑰 | `DELETE /api/v1/cipher_keys/{name}` | `org.cipher_keys.manage` |
| 輪替預設金鑰 | `POST /api/v1/field_encryption/rotate` | `org.cipher_keys.rotate` |

## 金鑰中繼資料

列出、讀取、建立和輪替呼叫會傳回金鑰版本的中繼資料。列出呼叫會傳回每把金鑰的所有版本，同一名稱下的最新版本排在最前面。

```json
{
  "id": "3KEZizkQsvBwoWQihNO6OdxRiSf",
  "name": "payments-key",
  "alg": "aes-256-gcm",
  "version": 1,
  "createdAt": 1790000000000000,
  "rotatedAt": null
}
```

從未輪替的金鑰，其 `rotatedAt` 為 `null`。讀取呼叫會傳回最新版本。

## 建立金鑰

```http
POST /api/v1/cipher_keys
```

| 欄位 | 類型 | 必填 | 說明 |
|---|---|---|---|
| `name` | string | 是 | 金鑰名稱。名稱已存在時會傳回 `409`，訊息會指向輪替呼叫。 |
| `keyMaterialB64` | string | 是 | 32 個隨機位元組，使用含填補字元的標準 base64 編碼。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/cipher_keys \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "{\"name\": \"payments-key\", \"key_material_b64\": \"$(openssl rand -base64 32)\"}"
```
</RequestExample>

回應會傳回上文所示的金鑰中繼資料。

## 輪替金鑰

```http
POST /api/v1/cipher_keys/{name}/rotate
```

要求本文與建立呼叫一樣包含 `keyMaterialB64`。呼叫會使用新的金鑰材料新增一個版本，並保留舊版供解密使用。輪替不存在的金鑰名稱時會傳回 `404`。請先使用建立呼叫建立金鑰。

## 刪除金鑰

```http
DELETE /api/v1/cipher_keys/{name}
```

刪除該名稱下的所有版本，並傳回 `{"deleted": true}`。名稱不存在時會傳回 `404`。呼叫不會檢查已儲存的資料是否仍依賴該金鑰。

<Warning>
  使用已刪除的金鑰加密的值無法再解密。刪除金鑰前，請先檢查依賴該金鑰的加密欄位。
</Warning>

## 輪替預設金鑰

```http
POST /api/v1/field_encryption/rotate
```

在伺服器端產生新的金鑰材料，為 `__field_default__` 新增一個版本，並立即重新整理解密快取。新寫入的值會使用新版本，現有的值仍可讀取。如果組織尚無預設金鑰，呼叫會建立版本 1。要求本文為空，回應包含新金鑰的識別碼與版本：

```json
{
  "keyId": "3KEZj3uxMx5OOFX6NiYv3VFnfmD",
  "version": 2
}
```

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | `keyMaterialB64` 不是有效的 base64，或解碼後的長度不是剛好 32 位元組（`key_material must be 32 bytes, got 5`）。 |
| `403` | 權杖缺少該呼叫所需的權限。 |
| `404` | 讀取、輪替或刪除呼叫找不到該名稱的金鑰。 |
| `409` | 已有同名金鑰。 |
| `422` | 缺少必填欄位。回應為純文字。 |
