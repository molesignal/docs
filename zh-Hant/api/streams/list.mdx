```http
GET /api/v1/streams
```

以 JSON 陣列傳回組織中的每個資料流，依名稱和類型排序。每一項的結構與[取得資料流](/zh-Hant/api/streams/get)中顯示的相同，包含結構描述、明確指定的 `retention`、計算得出的 `effectiveRetention`、設定及微秒精度的時間戳記。此呼叫需要 `streams.read` 或 `sys.telemetry.read`。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/streams \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

回應包含受保護的系統資料流，例如 `_molesignal`；權杖缺少 `audit.read` 時，回應不包含 `_audit`。名稱和類型共同識別資料流，因此同一個名稱可以出現在多種類型中。

## 使用回應

此介面傳回資料流定義，不傳回遙測記錄。讀取單一資料流的結構描述或修改設定前，先從回應查找資料流 ID。使用[查詢 API](/zh-Hant/api/query/execute)查詢事件。

| 欄位 | 意義 |
|---|---|
| `id` | 單一資料流 API 使用的穩定識別碼。 |
| `name` 與 `streamType` | 兩者共同識別資料集，請勿僅依名稱建立清單。 |
| `schema` | 建立查詢時所依據的欄位定義。 |
| `retention` | 資料流明確指定的保留設定；`null` 表示使用預設值。 |
| `effectiveRetention` | 資料流實際採用的保留設定。 |
| `createdAt`、`updatedAt` | Unix 時間戳記，單位為微秒，而非毫秒。 |

## 驗證權限與資料範圍

使用與目標組織關聯的憑證。具備 `streams.read` 或 `sys.telemetry.read` 即可存取清單介面；缺少 `audit.read` 時，不會傳回 `_audit`。清單中沒有 `_audit` 不代表已停用稽核資料收集。

回應是 JSON 陣列，不是包含 `items` 的包裝物件。此路由沒有分頁參數。空陣列表示這次請求在指定組織及可見範圍內未傳回任何資料流，不能據此判斷其他組織沒有資料。

找到目標 `(name, streamType)` 後，將其 `id` 傳給[取得資料流](/zh-Hant/api/streams/get)。另外使用[範例查詢](/zh-Hant/api/query/execute)確認是否有實際事件，以區分資料流是否已定義，以及是否已有可查詢的資料。
