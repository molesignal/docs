```http
GET /api/v1/business-context
PUT /api/v1/business-context
```

業務鍵，例如租戶、方案或實驗分組，以及 Span、日誌和 RUM 事件中承載每個鍵的欄位。參見[業務上下文](/zh-Hant/business-context)。讀取需要 `apm.services.read`、`traces.read`、`logs.read`、`rum.events.read`、`apm.settings.read` 或 `sys.telemetry.read` 其中之一；設定需要 `apm.settings.manage`，並記入操作日誌。

## 設定業務鍵

`PUT` 整體取代所有鍵。留空的欄位表示不指定，`label` 留空時取鍵名，重點值會去除前後空白並去重；傳回儲存後的內容。

| 欄位 | 說明 |
|---|---|
| `key` | 以小寫字母開頭，只能包含小寫字母、數字和 `_`，最多 64 個字元，不能重複。 |
| `label` | 讀者看到的名稱，最多 80 個字元。 |
| `span` | Span 屬性，依 Trace 流中的欄位名稱填寫。 |
| `log` | 日誌欄位。 |
| `rum` | RUM 欄位，可以是 JSON 欄位裡的鍵，例如 `context.tenant`。 |
| `important` | 最重要的值，最多 50 個，每個最多 200 個字元。 |

每個鍵至少要指定 `span`、`log`、`rum` 其中之一。最多 8 個鍵。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/business-context \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"keys":[{"key":"tenant","label":"租户","span":"tenant.id","log":"tenant_id","rum":"context.tenant","important":["acme"]}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "keys": [
    {
      "key": "tenant",
      "label": "租户",
      "span": "tenant.id",
      "log": "tenant_id",
      "rum": "context.tenant",
      "important": ["acme"]
    }
  ]
}
```
</ResponseExample>

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 鍵名不符規則或重複、未指定任何欄位，或鍵、值超過上限。 |
| `403` | Token 缺少此呼叫所需的權限。 |
