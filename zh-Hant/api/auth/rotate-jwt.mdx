兩個路由都需要具備 `sys.signing_keys.rotate` 權限的系統範圍工作階段，使用組織範圍的工作階段或 API 權杖會收到 `403`。透過[選取工作區](/zh-Hant/api/auth/select-organization)，將工作階段切換至 `_sys` 組織。

## 列出簽署金鑰

```http
GET /api/v1/auth/jwt/secrets
```

傳回簽署金鑰的中繼資料，絕不傳回原始金鑰位元組。

<ResponseExample>
```json 200
[
  {
    "id": "3JtcPZ3AZJFyvBvSkJUia0N7wqo",
    "isPrimary": true,
    "createdAt": 1790000000000000,
    "retiredAt": null
  }
]
```
</ResponseExample>

## 輪替

```http
POST /api/v1/auth/jwt/rotate
```

建立新的主金鑰，並停用先前的主金鑰。系統使用新金鑰簽發新權杖。使用舊金鑰簽發的權杖，在該金鑰停用後的 24 小時內仍然有效。

節點無須重新啟動。每個節點從第一個請求起就接受以新金鑰簽發的工作階段，並在約 10 秒內開始使用新金鑰簽發。舊金鑰停用後，節點會繼續用它驗證權杖 24 小時又 5 分鐘。額外的 5 分鐘用來涵蓋上述延遲和節點間的時鐘偏差。

<ResponseExample>
```json 200
{
  "newKid": "<new-key-id>",
  "retiredKid": "<previous-key-id>",
  "activeCount": 2
}
```
</ResponseExample>

`activeCount` 是目前用於驗證權杖的金鑰數量。使用 `MS_AUTH_JWT_SECRET_OVERRIDE` 固定簽署金鑰的部署會依照自身的輪替策略運作，請參閱[安全性與多租戶](/zh-Hant/security#jwt-簽署金鑰)。
