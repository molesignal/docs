```http
POST /api/v1/auth/signin
```

開始 Web 介面工作階段。此路由**不需驗證**。回應會設定工作階段 Cookie，並在 `login` 中傳回登入者的身分。回應本文不含 Token。已啟用多因素驗證的帳號請參閱[第二步](#第二步)。

**請求本文**

| 欄位 | 類型 | 必填 | 說明 |
|---|---|---|---|
| `email` | string | 是 | |
| `password` | string | 是 | |
| `remember` | boolean | 否 | 關閉瀏覽器後仍保留工作階段，預設為 `false`。 |

<RequestExample>
```bash cURL
curl -c ms-cookies.txt -X POST http://localhost:5080/api/v1/auth/signin \
  -H 'content-type: application/json' \
  -d '{"email":"admin@example.com","password":"admin"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "login": {
    "userId": "<user-id>",
    "email": "admin@example.com",
    "displayName": "root",
    "orgId": "<organization-id>",
    "orgName": "default",
    "displayRole": "Owner",
    "roles": [
      {
        "id": "<role-id>",
        "key": "owner",
        "name": "Owner",
        "builtin": true
      }
    ],
    "scope": "organization"
  }
}
```
</ResponseExample>

登入時，系統會從使用者的組織成員資格中，選擇第一個允許這次登入的組織。程式透過 `Authorization` 請求標頭傳送 API Token。此標頭不接受工作階段 Token，請參閱[簽發 API Token](/zh-Hant/api/auth/issue-token)。

## 嘗試次數過多

密碼輸入錯誤次數過多時，系統會傳回 `429`，並在 `Retry-After` 回應標頭中提供須等待的秒數。錯誤碼為 `signin_limited`，無論帳號是否存在，回應內容都相同。此時系統不會核對密碼。密碼錯誤或帳號不存在時，系統會傳回 `401`；密碼正確但帳號已停用或待審核時，則會傳回 `403` 和原因。請參閱[登入速率限制](/zh-Hant/settings/platform#登入速率限制)。

```json
{
  "error": "resource_exhausted",
  "code": "signin_limited",
  "message": "too many failed password attempts; try again in 14 minutes"
}
```

## 第二步

帳號已啟用[多因素驗證](/zh-Hant/identity/mfa)時，只提供密碼不會設定 Cookie。回應會以 `mfa` 取代 `login`，列出帳號可用來完成登入的方式：

```json
{
  "mfa": {
    "challenge": "<challenge>",
    "methods": ["passkey", "totp", "recovery_code"],
    "expiresAt": 1790000000000000
  }
}
```

| 端點 | 用途 |
|---|---|
| `POST /api/v1/auth/signin/verify` | 完成登入。傳入 `challenge`、`method`（`totp` 或 `recovery_code`）和 `code`；若 `method` 為 `passkey`，則傳入 `challenge`、`method`、`ceremony` 和 `credential`。傳回 `{"login": …}` 並設定工作階段 Cookie；使用復原碼時也會傳回 `recoveryCodesLeft`。 |
| `POST /api/v1/auth/signin/verify/passkey` | 傳入 `challenge`，取得該次 Passkey 驗證的 `ceremony` 和 `options`。將 `options` 傳給 `navigator.credentials.get()`，再將 `ceremony` 與結果一併送回。`ceremony` 只能使用一次。 |

## 登入時設定第二驗證因素

組織[要求多因素驗證](/zh-Hant/identity/sso#登入要求)，但帳號尚未設定第二驗證因素時，回應會以 `enroll` 取代 `login`：

```json
{
  "enroll": {
    "challenge": "<challenge>",
    "methods": ["passkey", "totp"],
    "organizationName": "default",
    "expiresAt": 1790000000000000
  }
}
```

| 端點 | 用途 |
|---|---|
| `POST /api/v1/auth/signin/enroll/totp` | 傳入 `challenge`，取得 `setup`、`secret`、`otpauthUrl`、`qrSvg` 和 `expiresAt`。 |
| `POST /api/v1/auth/signin/enroll/totp/confirm` | 傳入 `challenge`、`setup` 和 `code`。傳回 `{"login": …, "recoveryCodes": […]}` 並設定工作階段 Cookie。 |
| `POST /api/v1/auth/signin/enroll/passkey/options` | 傳入 `challenge`，取得供 `navigator.credentials.create()` 使用的 `ceremony` 和 `options`。 |
| `POST /api/v1/auth/signin/enroll/passkey` | 傳入 `challenge`、`ceremony` 和 `credential`，也可選擇傳入 `name`。傳回 `{"login": …, "recoveryCodes": […]}` 並設定工作階段 Cookie。 |

組織[只允許單一登入](/zh-Hant/identity/sso#登入要求)時，使用密碼登入會收到 `403`。帳號屬於多個組織時，會進入第一個允許這次登入的組織。

## Passkey 登入

使用 [Passkey](/zh-Hant/identity/mfa#使用-passkey-免密碼登入) 登入不需要密碼，也不需要第二步。

| 端點 | 用途 |
|---|---|
| `POST /api/v1/auth/signin/passkey/options` | 傳回 `ceremony` 和 `options`。執行個體的 `[http].external_url` 無法作為 Passkey 的[信賴方](/zh-Hant/identity/mfa#執行個體的要求)時，會傳回 `400`。 |
| `POST /api/v1/auth/signin/passkey` | 傳入 `ceremony` 和 `credential`，也可選擇傳入 `remember`。傳回 `{"login": …}` 並設定工作階段 Cookie。 |

## 工作階段 Cookie

| Cookie | Path | 內容 | 有效期限 |
|---|---|---|---|
| `accessToken` | `/api` | Access Token，隨每個 API 請求傳送。 | 15 分鐘，透過 `POST /api/v1/auth/refresh` 延長效期。 |
| `refreshToken` | `/api/v1/auth` | Refresh Token，僅用來延長 Access Token 的效期。 | 到工作階段結束為止，也就是登入後經過 `[auth].session_ttl_secs` 指定的秒數，預設為 24 小時。 |

兩個 Cookie 都設有 `HttpOnly` 和 `SameSite=Strict`。瀏覽器透過 HTTPS 存取 MoleSignal 時，也會設定 `Secure`。未選取 `remember` 時，瀏覽器會在關閉時捨棄這兩個 Cookie。兩個 Token 都是經過簽署的 JWT。伺服器不會儲存 Token，只會驗證簽章、用途和到期時間。停用或刪除使用者後，工作階段會在下一次請求時結束。

## 工作階段端點

| 端點 | 用途 |
|---|---|
| `POST /api/v1/auth/refresh` | 使用 Refresh Token 簽發新的 Access Token，傳回 `204` 和新的 `accessToken` Cookie，不變更工作階段的結束時間。工作階段已到期、使用者已停用或缺少 Cookie 時，傳回 `401` 並清除兩個 Cookie。 |
| `GET /api/v1/auth/session` | 傳回目前工作階段的身分，結構與登入回應中的 `login` 相同。 |
| `POST /api/v1/auth/signout` | 清除兩個 Cookie，並傳回 `204`。 |

使用工作階段 Cookie 修改資料的請求必須來自 MoleSignal 的頁面。若瀏覽器在請求中標示的 `Sec-Fetch-Site` 不是 `same-origin`，請求就會收到 `403`。
