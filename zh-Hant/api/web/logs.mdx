這些呼叫會讀取組織的一個日誌資料流，讀法與**日誌**頁相同。資料流不存在時傳回空結果。所有呼叫都需要 `logs.read`，系統範圍內則需要 `sys.telemetry.read`。

除歸併模式外，每個呼叫都接受帶 JSON 請求主體的 `POST`，或在查詢字串中帶同樣欄位的 `GET`：`filters` 和 `freeText` 寫成 JSON 清單的文字，`where` 寫成 JSON 物件的文字。查詢太長、放不進網址時請用 `POST` 傳送。

## 呼叫符合的記錄

呼叫會比對視窗內同時符合下列各項的記錄：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `filters` | list | 全部需符合的篩選條件。最多 32 個，與 `where` 中的篩選條件合計。 |
| `freeText` | list | 在 `message` 欄位中尋找的詞或片語，每個最長 512 位元組。由字母和數字組成、不超過 40 位元組的小寫詞不區分大小寫比對；其餘文字依原樣比對。最多 8 個，與 `where` 中的文字合計。 |
| `where` | object | 表達多個可選分支的條件樹：一個篩選條件、`{"text": "..."}`、`{"and": [...]}` 或 `{"or": [...]}`。 |
| `expression` | string | **日誌**頁寫法的欄位查詢。它取代 `filters`、`freeText` 和 `where`，兩者只能擇一。 |

篩選條件是帶 `field`、`op`、`value` 和 `quoted` 的物件，欄位名稱使用資料流中的欄位名稱。

| 運算子 | 欄位 | 符合 |
|---|---|---|
| `=`、`!=` | 任意純量欄位 | 該值，或該值以外的值。值為空時判斷欄位是否有值：`=` 符合沒有該欄位值的記錄。 |
| `>`、`>=`、`<`、`<=` | 數字和時間戳記 | 比較結果。 |
| `contains` | 文字 | 欄位中任意位置出現該值。 |
| `match` | 任意欄位 | 以子字串出現該值，不區分大小寫。值為空時不符合任何記錄。 |
| `match_text` | 建有全文索引的文字 | 全文檢索：多詞、片語和萬用字元。欄位沒有全文索引時傳回 `400`。 |

`eq`、`ne` 和 `like` 分別是 `=`、`!=` 和 `contains` 的別名。值寫在引號中時 `quoted` 為 `true`：表示一個詞，而不是數字。這裡不能篩選 JSON 欄位，請改用 SQL 查詢。

`expression` 接收**日誌**頁的文字：比較、`MATCH(field, 'text')` 和 `MATCH_TEXT(field, 'words')`、要尋找的詞、引號中的片語、不區分大小寫的 `AND` 和 `OR`（`AND` 優先），以及括號。伺服器端會把它讀成頁面會傳送的 `filters`、`freeText` 和 `where`，再依上文驗證。文字最長 8 KiB，括號最多巢狀 32 層。無法理解的部分（例如未閉合的括號，或比較的值為空）會傳回 `400`，並指出該部分。

```bash
curl -G "http://localhost:5080/api/v1/web/logs" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'stream=app' \
  --data-urlencode "expression=level = 'error' AND (service.name = 'checkout' OR timeout)"
```

## 列出記錄

```http
POST /api/v1/web/logs
GET  /api/v1/web/logs
```

依時間從新到舊傳回符合的記錄，使用游標分頁。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `stream` | string | 必填，日誌資料流。 |
| `from`、`to` | integer | 以微秒表示的視窗，預設是截至目前的最近 24 小時。`to` 必須大於 `from`。 |
| `filters`、`freeText`、`where`、`expression` | | 呼叫符合的記錄。 |
| `limit` | integer | 每頁筆數，預設 `20`，限定在 1 到 5000 之間。 |
| `cursor` | string | 之前某一頁的 `nextCursor` 或 `previousCursor`。它會保留第一頁的視窗和符合條件。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/web/logs \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"stream":"app","expression":"level = '\''error'\''","limit":2}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    { "_timestamp": 1790000000000000, "level": "error", "message": "db pool exhausted", "trace_id": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "nextCursor": "eyJ2IjoxLC...",
  "previousCursor": null,
  "hasMore": true
}
```
</ResponseExample>

每一項是一條記錄的欄位，`_timestamp` 以微秒為單位。帶著 `cursor` 卻更換了資料流、視窗、`limit` 或符合條件的請求會傳回 `400`。

## 依時間統計記錄數量

```http
POST /api/v1/web/logs/histogram
GET  /api/v1/web/logs/histogram
```

把符合的記錄統計到時間桶中。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `stream` | string | 必填。 |
| `from`、`to` | integer | 必填，以微秒表示的視窗。 |
| `filters`、`freeText`、`where`、`expression` | | 呼叫符合的記錄。 |
| `bucketTime` | integer | 一個時間桶的長度，單位微秒，至少 `1000`。 |
| `originTime` | integer | 第一個時間桶的起點，不晚於 `from`。 |

一個請求從 `originTime` 到 `to` 最多涵蓋 512 個時間桶。

```json
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "buckets": [{ "startTime": 1790000100000000, "total": 120, "errors": 4 }],
  "split": true
}
```

`buckets` 只列出含有記錄的時間桶，依時間從早到晚。`errors` 統計等級為 `ERROR` 的記錄，等級取自 `level` 或 `body_level`。資料流沒有這兩個欄位，或等級對讀取者被遮掩時，`split` 為 `false`，`errors` 為 `0`。統計無法完成時，呼叫仍會傳回 `200`，`buckets` 為空，並帶上 `unavailable`：`time_budget`、`busy` 或 `scan_limit`，意義與[追蹤統計](/zh-Hant/api/web/trace#依時間統計追蹤數量)相同。

## 描述欄位

```http
POST /api/v1/web/logs/field-stats
GET  /api/v1/web/logs/field-stats
```

描述某個欄位在符合記錄中的取值。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `stream` | string | 必填。 |
| `from`、`to` | integer | 以微秒表示的視窗。 |
| `filters`、`freeText`、`where`、`expression` | | 呼叫符合的記錄。 |
| `field` | string | 必填，使用資料流中的欄位名稱。 |

```json
{
  "kind": "text",
  "total": 1840,
  "present": 1840,
  "distinct": 3,
  "distinctExact": true,
  "top": [{ "value": "info", "count": 1500 }, { "value": "warn", "count": 300 }, { "value": "error", "count": 40 }],
  "topSkipped": false
}
```

`kind` 為 `number`、`time`、`text` 或 `bool`。`total` 是符合的記錄數，`present` 是其中有該欄位值的記錄數。`top` 依從多到少列出最常見的取值；幾乎每個值都不相同時 `topSkipped` 為 `true`，不列出取值。`range` 以文字給出最小值和最大值。數字欄位還會給出 `spread` 和 `bars`。`trend` 統計最常見取值隨時間的變化，沒有哪個值明顯更常見時不會出現。

## 歸併為模式

```http
POST /api/v1/web/logs/patterns
```

把整個時間窗內符合的記錄歸併為訊息模式，並與對比時段比較。時間窗內符合記錄超過 5,000 條時，把時間窗分成四等份，各讀取最新的記錄作為樣本，每種模式的 `estimatedCount` 是換算到整個時間窗的數量。需要 `logs.read`。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `stream` | string | 必填。 |
| `from`、`to` | integer | 必填。時間窗，單位為微秒。 |
| `filters`、`freeText`、`where`、`expression` | | 呼叫符合的內容。 |
| `field` | string | 訊息所在欄位；不填時取資料流中 `message`、`body`、`summary`、`log`、`event`、`error`、`msg`、`content`、`text` 裡第一個存在的欄位。 |
| `baseline` | string | `previous`（預設，之前同樣長的一段）、`week_before` 或 `none`。 |
| `limit` | integer | 最多列出的模式數：預設 100，最多 200。 |

```json
{
  "stream": "app_logs",
  "field": "message",
  "levelField": "level",
  "timeRange": { "startTime": 1795510800000000, "endTime": 1795514399999999 },
  "logs": 48210,
  "read": 5000,
  "unread": 0,
  "sampled": true,
  "baseline": { "kind": "previous", "startTime": 1795507199999999, "endTime": 1795510799999999, "logs": 40102, "read": 5000, "sampled": true },
  "newPatterns": 1,
  "surgingPatterns": 0,
  "droppingPatterns": 0,
  "patternCount": 37,
  "patterns": [
    {
      "pattern": "upstream timeout after <number>ms",
      "tokens": [{ "lead": "", "trail": "", "text": "upstream", "wild": null, "unit": "" }],
      "count": 41,
      "share": 0.0082,
      "estimatedCount": 395,
      "firstSeen": 1795513020000000,
      "lastSeen": 1795514390000000,
      "levels": [{ "level": "ERROR", "count": 41 }],
      "baselineCount": 0,
      "change": "new",
      "fragment": "upstream timeout after",
      "example": "upstream timeout after 3000ms"
    }
  ]
}
```

新出現和激增的模式排在最前，時間窗內已不再出現的模式排在最後。`change` 為 `new`（對比時段沒有）、`surging`（至少兩倍且多出至少 5 條）、`dropping`（減少到一半以下且少了至少 5 條）或 `steady`；`ratio` 是時間窗的估算數量與對比時段之比。`tokens` 是模式中的詞，`wild` 表示開放位置上變化的內容類型。靜態加密的欄位會傳回 `400`。沒有寫入過資料的資料流會傳回空報告。

## 錯誤

| 狀態碼 | 原因 |
|---|---|
| `400` | 參數無效：缺少 `stream`、`to` 不大於 `from`、篩選條件使用了未知欄位或其型別不支援的運算子、清單或條件樹超出限制、`expression` 與 `filters`、`freeText` 或 `where` 同時給出或含有無法理解的部分、游標與查詢不符，或統計缺少參數、涵蓋的時間桶超過 512 個。 |
| `403` | Token 缺少 `logs.read`。 |
