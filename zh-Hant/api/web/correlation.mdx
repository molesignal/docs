```http
GET /api/v1/web/correlation/{fromKind}/{toKind}?ctx=<base64url-json>
```

計算使用者從一個訊號跳轉到另一個訊號時，網頁介面套用的篩選條件、時間範圍和預填查詢，例如從追蹤跳轉到相關日誌。此呼叫需要 `traces.read`，系統範圍可使用 `sys.telemetry.read`。

**參數**

| 參數 | 位置 | 必填 | 說明 |
|---|---|---|---|
| `fromKind` | path | 是 | 跳轉的來源訊號：`trace`、`metric`、`log` 或 `host`。 |
| `toKind` | path | 是 | 跳轉的目標訊號：`trace`、`metric`、`log` 或 `host`。 |
| `ctx` | query | 是 | 描述來源訊號的 JSON 物件，使用不含填補字元的 base64url 編碼。 |

`ctx` 物件接受下列選用鍵：

| 鍵 | 類型 | 說明 |
|---|---|---|
| `trace_id` | string | 來源訊號所屬的追蹤。 |
| `service` | string | 單一服務名稱。 |
| `services` | array | 服務名稱清單。 |
| `host` | string | 主機名稱。 |
| `time_range` | object | `{ "from": "<RFC 3339>", "to": "<RFC 3339>" }`。預設為最近一分鐘。 |

## 支援的跳轉

| 來源 → 目標 | 篩選條件 | 預填 |
|---|---|---|
| `trace` → `log` | 來自 `services` 的 `service`，以及 `trace_id` | 無。 |
| `trace` → `metric` | 來自 `services` 的 `service` | `promql`：`rate(http_requests_total{service="<第一个服务>"}[1m])` |
| `trace` → `host` | 來自 `host` 的 `host` | 無。 |
| `metric` → `trace` | 來自 `services` 的 `service`，以及服務圖針對第一個服務回報的 `peer_service` | 無。 |
| `metric` → `log` | 來自 `services` 的 `service` | 無。 |
| `log` → `trace` | `trace_id` 與 `service` | 無。 |
| `log` → `metric` | 來自 `services` 或 `service` 的 `service` | `promql`：`rate(log_records_total{service="<service>"}[1m])` |
| `host` → `trace` | 來自 `host` 的 `host.name` | 無。 |

只涉及單一服務的篩選條件使用運算子 `eq`，涉及多個服務時則使用 `in`。其他所有組合（包括未知類型）都會傳回 `200`，並附上時間範圍，但不含篩選條件。

<RequestExample>
```bash cURL
CTX=$(printf '%s' '{"trace_id":"0af7651916cd43dd8448eb211c80319c","services":["checkout","payments"],"time_range":{"from":"2026-10-04T10:00:00Z","to":"2026-10-04T10:05:00Z"}}' | base64 | tr -d '\n=' | tr '+/' '-_')

curl "http://localhost:5080/api/v1/web/correlation/trace/log?ctx=$CTX" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "timeRange": { "from": "2026-10-04T10:00:00Z", "to": "2026-10-04T10:05:00Z" },
  "filters": [
    { "field": "service", "op": "in", "value": ["checkout", "payments"] },
    { "field": "trace_id", "op": "eq", "value": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "prefill": {}
}
```
</ResponseExample>

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 未提供 `ctx`、`ctx` 不是有效的 base64url，或無法解碼為 JSON。未提供 `ctx` 時以純文字回應；其他情況則傳回 `invalid_argument`，訊息為 `invalid ctx base64: ...` 或 `invalid ctx json: ...`。 |
| `403` | 權杖缺少 `traces.read`。 |
