所有呼叫都會讀取組織的一個追蹤資料流：包含 `trace_id`、`span_id`、`service.name`、`name`、`start_time_unix_nano`、`end_time_unix_nano` 和 `status_code` 全部欄位的資料流。名為 `default` 的資料流優先於其他符合條件的資料流；仍相同時依資料流名稱決定。組織沒有這類資料流時，結果為空。只有透過[尾部取樣](/zh-Hant/configuration#追蹤擷取與尾端取樣)保留的追蹤才能讀取。

所有呼叫都需要 `traces.read`，系統範圍可使用 `sys.telemetry.read`。

## 列出追蹤摘要

```http
GET /api/v1/web/traces
```

每筆追蹤傳回一筆摘要，使用游標分頁。資料流尚無追蹤摘要時，傳回空頁。

**查詢參數**

| 參數 | 類型 | 說明 |
|---|---|---|
| `from`、`to` | integer | 以微秒表示的視窗。預設是最近 24 小時，截至目前。`to` 必須大於 `from`。 |
| `q` | string | 不區分大小寫的文字，必須出現在某個 Span 的 `trace_id`、`span_id`、服務、操作或狀態中。最長 256 個字元。 |
| `filters` | string | 篩選條件的 JSON 陣列，見下文。 |
| `where` | string | JSON 條件樹：以 AND 和 OR 連接的篩選條件和文字，見下文。 |
| `expression` | string | **追蹤**頁寫法的欄位查詢。它會取代 `q`、`filters` 和 `where`，兩者只能擇一，見下文。 |
| `sort` | string | `latest`（預設）、`earliest`、`duration_desc`、`duration_asc`、`span_count_desc` 或 `errors_desc`。 |
| `limit` | integer | 頁面大小。預設 `20`。值限制在 1 到 5000 之間。 |
| `cursor` | string | 先前某一頁傳回的 `nextCursor` 或 `previousCursor`。 |
| `fields` | string | 隨每筆追蹤一起傳回的根 Span 欄位，以逗號分隔，依資料流中的欄位名稱指定。最多 12 個。未知欄位、JSON 欄位或 `molesignal.trace.*` 欄位會傳回 `400`。 |

篩選條件是包含 `field`、`op` 和 `value` 的物件，一個請求最多帶 32 個篩選條件。所有篩選條件必須同時符合。運算子 `in` 以 `values`（值的清單）代替 `value`。

| 欄位 | 類型 | 運算子 |
|---|---|---|
| `trace_id` | 文字 | `=`、`!=`、`contains`、`in` |
| `duration_ns`、`span_count`、`error_count` | 整數 | `=`、`!=`、`>`、`>=`、`<`、`<=`、`in` |
| 追蹤資料流的任何其他純量欄位 | 取決於欄位類型 | 文字：`=`、`!=`、`contains`、`in`。數字與時間戳記：`=`、`!=`、`>`、`>=`、`<`、`<=`、`in`。布林值：`=`、`!=`、`in`。 |

篩選條件依資料流中的欄位名稱指定欄位，例如 `service.name`、`name`，不接受其他名稱。運算子 `eq`、`ne` 和 `like` 分別是 `=`、`!=` 和 `contains` 的別名。JSON 欄位不能用作篩選條件。

`trace_id`、`duration_ns`、`span_count` 和 `error_count` 在追蹤上比較。其他欄位都屬於 Span：追蹤中有一個 Span 符合篩選條件，該追蹤即符合；`!=` 在追蹤的所有 Span 都不含該值時符合。缺少該欄位的 Span 視為不含該值。

`in` 比對 `values` 中的任意一個值：1 到 64 個值，每個最長 512 位元組，且符合欄位類型。重複列出的值只算一次。作用於 Span 欄位時，追蹤中有一個 Span 含有其中某個值，該追蹤即符合。

`where` 表達篩選條件清單無法表達的內容：多個可選分支。它是以下四種形式之一的 JSON 物件：

| 形式 | 比對 |
|---|---|
| 與 `filters` 中相同的篩選條件 | 該篩選條件。 |
| `{"text": "..."}` | 該文字，比對方式與 `q` 相同。 |
| `{"and": [...]}` | 清單中的所有條件。 |
| `{"or": [...]}` | 清單中的任意一個條件。 |

`filters`、`q` 和 `where` 需同時符合。條件樹中的篩選條件含義不變：作用於 Span 欄位時，追蹤中有一個 Span 符合即比對成功；`!=` 在追蹤的所有 Span 都不含該值時比對成功。追蹤比對 `A` 或比對 `B`，即比對 `{"or": [A, B]}`。`filters` 與 `where` 中的篩選條件合計最多 32 個。一棵條件樹最多尋找 8 段文字，分組最多巢狀 8 層，每個分組至少有一個條件。

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'filters=[{"field":"status_code","op":"=","value":"ERROR"}]' \
  --data-urlencode 'where={"or":[{"field":"service.name","op":"=","value":"checkout"},{"field":"span_count","op":">","value":"50"}]}'
```

此請求列出失敗追蹤中，含有 `checkout` 的 Span，或 Span 數超過 50 的追蹤。

`expression` 改為接收**追蹤**頁的文字：使用 `=`、`!=`、`>`、`>=`、`<`、`<=`、`contains` 和 `field in ('a', 'b')` 的比較、要尋找的詞、引號中的片語、不區分大小寫的 `AND` 和 `OR`（`AND` 優先），以及括號。伺服器端會將其解讀為頁面會送出的 `q`、`filters` 和 `where`，再依上文驗證。文字最長 8 KiB，括號最多巢狀 32 層。無法理解的部分（例如未閉合的括號，或比較的值為空）會傳回 `400`，並指出該部分。

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "expression=status_code = 'ERROR' AND (service.name = 'checkout' OR span_count > 50)"
```

此請求列出的追蹤與上一個請求相同。

`cursor` 會將頁面綁定到簽發它的查詢。帶著 `cursor` 重複請求，同時更換 `limit`、`sort`、`q`、`filters` 或 `where`，會傳回 `400`。

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'sort=duration_desc' \
  --data-urlencode 'limit=2' \
  --data-urlencode 'fields=http.route' \
  --data-urlencode 'filters=[{"field":"service.name","op":"in","values":["checkout","payments"]}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "service": "checkout",
      "operation": "GET /checkout",
      "startNs": 1790000000000000000,
      "durationMs": 180.0,
      "spanCount": 3,
      "errorCount": 1,
      "status": "ERROR",
      "httpStatusCode": 502,
      "fields": { "http.route": "/checkout" }
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

每個項目透過根 Span 描述一筆追蹤：根 Span 的 `service` 與 `operation`、以奈秒表示的開始時間、以毫秒表示的時長、Span 數量和錯誤 Span 數量。設定了 `nextCursor` 時，`hasMore` 為 `true`。

| 欄位 | 說明 |
|---|---|
| `status` | 根 Span 的狀態：`OK`、`ERROR` 或 `UNSET`。 |
| `httpStatusCode` | 根 Span 的 `http.response.status_code`，或其 `http.status_code`，值在 100 到 599 之間時傳回。其他情況，以及在摘要開始儲存該欄位之前寫入的追蹤，不傳回此欄位。 |
| `fields` | `fields` 中要求、且根 Span 有值的欄位。沒有時不傳回。讀取失敗時，頁面照常傳回，只是不含這些欄位。 |

## 依時間統計追蹤數量

```http
GET /api/v1/web/traces/histogram
```

依追蹤的開始時間，將清單查詢符合的每一筆追蹤計入時間桶中。此呼叫使用與清單相同的視窗、`q`、`filters` 和 `where`，符合的追蹤也相同。時間桶由呼叫端指定。

**查詢參數**

| 參數 | 類型 | 說明 |
|---|---|---|
| `from`、`to` | integer | 以微秒表示的視窗，兩者都必填。`to` 必須大於 `from`。 |
| `q`、`filters`、`where`、`expression` | string | 與清單相同。 |
| `bucketTime` | integer | 一個時間桶的長度，單位為微秒。不小於 `1000`。 |
| `originTime` | integer | 第一個時間桶的起點，單位為微秒。不晚於 `from`。 |

從 `originTime` 到 `to`，一個請求最多涵蓋 512 個時間桶。

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/histogram" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=900000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode 'filters=[{"field":"service.name","op":"=","value":"checkout"}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 900000000,
  "originTime": 1790000100000000,
  "buckets": [
    { "startTime": 1790000100000000, "total": 42, "errors": 3, "p50Ns": 41000000, "p95Ns": 180000000, "p99Ns": 320000000 },
    { "startTime": 1790001900000000, "total": 17, "errors": 0, "p50Ns": 38000000, "p95Ns": 95000000, "p99Ns": 120000000 }
  ],
  "split": true
}
```
</ResponseExample>

`buckets` 只列出包含追蹤的時間桶，依時間由早到晚排列。`total` 是在該時間桶內開始的追蹤數量。`errors` 是其中至少有一個錯誤 Span 的追蹤數量。`p50Ns`、`p95Ns` 和 `p99Ns` 是這些追蹤耗時的中位數、第 95 和第 99 百分位，以奈秒表示。它們是估算值，沒有統計到耗時時不傳回。

統計會讀取追蹤摘要；篩選條件作用於 Span 欄位時，還會讀取 Span。清單對每筆追蹤只傳回一筆摘要。寫入重試導致同一筆摘要儲存兩份時，統計會計算兩次。

無法統計時，呼叫仍傳回 `200`。此時 `buckets` 為空，`unavailable` 提供原因。

| `unavailable` | 原因 |
|---|---|
| `time_budget` | 統計耗時超過 20 秒。 |
| `busy` | 該角色的查詢已佔滿 [`[search.admission]`](/zh-Hant/configuration#准入控制) 允許的數量，且在 `max_wait_secs` 內沒有等到閒置槽位。 |
| `scan_limit` | 視窗內的列數超過 `[querier].max_scan_rows` 允許單次查詢讀取的數量。 |

## 讀取請求指標

```http
GET /api/v1/web/traces/red
GET /api/v1/web/traces/red/breakdown
```

讀取清單查詢符合的請求速率、錯誤和耗時：總計、逐個時間桶，以及依耗時分佈。拆分端點依某個欄位的每個值讀取相同的指標。一個請求就是一個 Span。預設讀取服務接收請求的 Span：server 或 consumer Span，或追蹤的根 Span；`scope=all` 讀取所有 Span。

作用於 Span 欄位的篩選條件針對 Span 本身，因此 `service.name = 'api'` 讀取的是 `api` 處理的請求。`trace_id` 和 `duration_ns` 取自 Span，`span_count` 和 `error_count` 取自 Span 所屬的追蹤。

**查詢參數**

| 參數 | 類型 | 說明 |
|---|---|---|
| `from`、`to`、`bucketTime`、`originTime` | integer | 與依時間統計追蹤數量相同。 |
| `q`、`filters`、`where`、`expression` | string | 與清單相同。 |
| `scope` | string | `entry`（預設）或 `all`。 |
| `by` | string | 僅用於拆分，且為必填：依哪個欄位分組請求，使用資料流中的欄位名稱。 |

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/red" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=60000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode "expression=service.name = 'checkout'"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "scope": "entry",
  "total": { "requests": 1840, "errors": 12, "p50Ns": 41000000.0, "p95Ns": 180000000.0, "p99Ns": 320000000.0 },
  "buckets": [
    { "startTime": 1790000100000000, "requests": 31, "errors": 0, "p50Ns": 40000000.0, "p95Ns": 150000000.0, "p99Ns": 210000000.0 }
  ],
  "latency": [
    { "fromNs": 0, "toNs": 50000000, "requests": 1203, "errors": 2 },
    { "fromNs": 50000000, "toNs": null, "requests": 637, "errors": 10 }
  ]
}
```
</ResponseExample>

`buckets` 只列出含有請求的時間桶，依時間由早到晚。`latency` 依耗時由短到長列出請求，最後一段沒有上限。無法判斷失敗時 `errors` 為 `null`；耗時以奈秒為單位，沒有請求或耗時被遮蔽時為 `null`。

拆分端點傳回 `field`、`bucketTime`、`originTime`、`scope` 和 `groups`：最常見的 50 個值排在前面，每個值帶有自己的指標，以及由 `requests`、`errors` 和 `p95Ns` 組成的時間桶 `series`。沒有該欄位值的請求，其 `value` 為 `null`。值多於所列時，`more` 為 `true`。

指標無法讀取時，兩個端點仍傳回 `200`，並帶上 `unavailable`：`time_budget`、`busy` 和 `scan_limit` 的含義與追蹤統計相同；對讀取者遮蔽時間時為 `timestamp_masked`；拆分欄位被遮蔽或加密時為 `field_protected`。

`by` 也可以指定 JSON 欄位裡的一個鍵，寫在欄位名稱後面，例如 `attributes.tenant`，請求依這個鍵的值分組。

## 比較慢請求或失敗請求

```http
GET /api/v1/web/traces/red/compare
```

逐欄位比較查詢中選取的請求與其餘請求：失敗的請求、耗時不少於或少於某個值的請求，或同時符合所給條件的請求。對每個欄位，比較各個值在兩組中的佔比，依佔比差距由大到小排出欄位，差距從 `0`（值組成相同）到 `1`（沒有共同值）。ID、時間點、耗時和 JSON 欄位不參與比較，幾乎每一列值都不同的欄位也不參與；選取失敗請求時，`status_code` 也不參與。每組只讀取前 1,000 個 Span 作為樣本。

**查詢參數**

與 RED 指標相同（不含 `by`），另加：

| 參數 | 類型 | 說明 |
|---|---|---|
| `errors` | boolean | 選取失敗的請求。 |
| `minDuration` | integer | 選取耗時不少於這麼多奈秒的請求。 |
| `maxDuration` | integer | 選取耗時少於這麼多奈秒的請求。 |

三者至少要給一個，且 `minDuration` 必須小於 `maxDuration`。

<ResponseExample>
```json 200
{
  "scope": "entry",
  "selected": 212,
  "baseline": 1000,
  "sampled": true,
  "dimensions": [
    {
      "field": "cloud.region",
      "score": 0.71,
      "values": [
        { "value": "eu-west-1", "selected": 0.83, "baseline": 0.12 },
        { "value": "us-east-1", "selected": 0.17, "baseline": 0.88 }
      ]
    }
  ]
}
```
</ResponseExample>

`selected` 和 `baseline` 是兩組各讀取的 Span 數，任一組還有更多時 `sampled` 為 `true`。`dimensions` 最多列出 20 個欄位，差距最大的在前，每個欄位最多列出 5 個佔比差距最大的值；沒有值的請求其 `value` 為 `null`。`unavailable` 的含義與 RED 指標相同。

## 列出 Span

```http
GET /api/v1/web/traces/spans
```

查詢符合的每個 Span 傳回一列，使用游標分頁。呼叫接受追蹤清單的視窗、`q`、`filters` 和 `where`，並依單一 Span 解讀：作用於 Span 欄位的篩選條件針對 Span 本身，`!=` 保留缺少該欄位的 Span。`duration_ns` 是 Span 自身的耗時，`span_count` 與 `error_count` 是 Span 所屬追蹤的數量。Span 比對 `A` 或比對 `B`，即比對 `{"or": [A, B]}`。

**查詢參數**

| 參數 | 類型 | 說明 |
|---|---|---|
| `from`、`to` | integer | 以微秒表示的視窗。預設是最近 24 小時，截至目前。`to` 必須大於 `from`。 |
| `q`、`filters`、`where`、`expression` | string | 與追蹤清單相同。 |
| `sort` | string | `latest`（預設）、`earliest`、`duration_desc` 或 `duration_asc`。 |
| `limit` | integer | 頁面大小。預設 `100`。值限制在 1 到 5000 之間。 |
| `cursor` | string | 先前某一頁傳回的 `nextCursor` 或 `previousCursor`。游標會攜帶其頁面的查詢；更換 `limit` 會傳回 `400`。 |

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "durationNs": 140000000,
      "status": "ERROR",
      "kind": 2,
      "httpStatusCode": 502
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

`status` 為 `OK`、`ERROR` 或 `UNSET`。`kind` 依 OTLP 的編號表示 Span 類型：`1` internal、`2` server、`3` client、`4` producer、`5` consumer。Span 沒有 `parent_span_id`、`kind` 或 `http_status_code` 時不傳回對應欄位。呼叫會作為受追蹤的查詢執行，與其他查詢一樣經過准入控制。

## 讀取單一追蹤

```http
GET /api/v1/web/trace/{traceId}
```

傳回單一追蹤的所有 Span，並依開始時間排序。`trace_id` 由 1 到 128 個字元組成，字元取自 `A-Z`、`a-z`、`0-9`、`-` 和 `_`。

**查詢參數**

| 參數 | 類型 | 說明 |
|---|---|---|
| `from`、`to` | integer | 以微秒表示的視窗，也就是該追蹤的 Span 開始時間範圍。兩者須同時提供，或都不提供。最長 31 天。未提供時，會在最近 24 小時內查詢。 |

回應最多包含 100,000 個 Span，大小不超過 32 MiB。上限截斷 Span 列表時，`truncated` 為 `true`。

<ResponseExample>
```json 200
{
  "traceId": "0af7651916cd43dd8448eb211c80319c",
  "rootSpanId": "b7ad6b7169203331",
  "spans": [
    {
      "spanId": "53995c3f42cd8ad8",
```

## 查詢連結至某個追蹤的 Span

```http
GET /api/v1/web/trace/{traceId}/linked
```

Span 會儲存指向其來源 Span 的連結，追蹤詳情會隨 Span 一起回傳這些連結。本呼叫會查詢反方向的連結：其他追蹤中連結到本追蹤某個 Span 的 Span。呼叫接受與追蹤詳情相同的 `from` 和 `to`，並在該視窗內查詢。

<ResponseExample>
```json 200
{
  "spans": [
    {
      "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
      "spanId": "00f067aa0ba902b7",
      "service": "billing-worker",
      "operation": "process invoice",
      "startNs": 1790000005000000000,
      "durationNs": 30000000,
      "status": "OK",
      "linkedSpanId": "53995c3f42cd8ad8",
      "attributes": { "messaging.operation": "process" }
    }
  ],
  "more": false
}
```
</ResponseExample>

`spans` 最多列出 200 個連結過來的 Span，依時間由新到舊排列；還有更多 Span 連結到該追蹤時，`more` 為 `true`。`linkedSpanId` 是連結指向的本追蹤 Span，`attributes` 是該連結自身的屬性。

查詢會將視窗內每個 Span 的連結當作文字讀取，並受追蹤統計的時間預算限制。無法完成時，呼叫仍會回傳 `200`，`spans` 為空，`unavailable` 會提供原因：`time_budget`、`busy` 或 `scan_limit`，含義與追蹤統計相同。

**錯誤**

| 狀態碼 | 原因 |
|---|---|
| `400` | 參數無效：`to` 不大於 `from`、篩選條件使用了未知的欄位或運算子（`unsupported trace filter field: nope`）、`in` 篩選條件沒有值或超過 64 個值、`where` 不是條件樹或超出其限制、`expression` 與 `q`、`filters` 或 `where` 同時提供或含有無法理解的部分、游標與查詢不符、`fields` 中的欄位未知或是文件，或 `trace_id` 的字元或長度無效。統計時還包括：缺少視窗或時間桶參數、`bucketTime` 小於 `1000`、`originTime` 晚於 `from`，或請求涵蓋的時間桶超過 512 個。追蹤詳情及其反向連結還包括：只提供 `from` 與 `to` 其中一個，或視窗超過 31 天。 |
| `403` | Token 缺少 `traces.read`。 |
| `404` | 視窗內找不到該追蹤，或追蹤已被取樣丟棄。 |
