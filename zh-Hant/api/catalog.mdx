## 授權模型

端點可能要求：

- `streams.query` 或 `alerts.rules.manage` 等組織權限；
- `sys.telemetry.read` 等平台權限；
- 資源層級的擁有權、關係或授權；
- 僅能存取單一資源的公開共用工作階段。

不要依顯示的角色推斷授權。查詢 `/api/v1/iam/capabilities` 以取得實際生效的權限與功能快照。

## 選擇並驗證請求

先開啟對應類別的指南，確認 HTTP 方法、所需權限、組織範圍、請求欄位與回應格式。同一類別可能同時包含管理請求和資料查詢，兩者所需的權限可能不同。

修改設定前，使用文件中的讀取請求確認目標組織和資源。寫入後，重新讀取資源或查詢一筆受控的測試事件，以確認實際結果。HTTP 請求成功不代表遙測資料已進入預期的資料串流，也不代表事件已恢復。

遇到錯誤時，請參閱 [API 入門](/zh-Hant/api-reference)及個別端點的說明。[回報文件不一致之處](/zh-Hant/support)時，請附上目前執行的版本、已遮蔽敏感資訊的請求與請求識別碼，不要附上憑證或敏感事件資料。
