所有訊號都透過 intake API 進入 MoleSignal。網頁介面中的 **資料來源** 頁面會為每個資料來源產生端點、Token 和設定片段，也可以手動設定相同的通訊協定。

## 資料來源頁面

開啟 **資料來源**，連接資料來源：

1. 在目錄中搜尋，或依類別篩選：**建議**、**基礎架構**、**雲端服務**、**資料庫**、**訊息佇列**、**應用程式與語言**、**安全性** 與 **自訂**。使用訊號標籤（**日誌**、**指標**、**追蹤**、**效能剖析**）可進一步縮小範圍。
2. 選取資料來源，例如 Kubernetes、Linux 主機、AWS、OpenTelemetry SDK 或 Web RUM。
3. 依照設定精靈的三個步驟完成連線：
   - **端點與 Token** 會顯示資料的傳送目的地，以及用於驗證身分的 Token。**顯示 Token** 會顯示 Token 及其權限範圍、工作區和有效期限。若是使用者體驗類的資料來源，請先選取 **RUM 應用程式**，才會顯示對應的 Client Token。
   - **設定資料來源** 會顯示命令和設定，其中的端點與 Token 已替換為實際值。
   - **確認是否收到資料** 會先檢查接收端，再確認最近 1 小時內是否收到資料。選取 **驗證連線** 可立即檢查一次，各項數值每 30 秒自動更新。
4. 檢視驗證結果：
   - **已偵測到資料**：最近 1 小時內已收到資料，且該資料來源的所有訊號都正常。選取 **檢視已接收的資料** 可開啟這些資料，選取 **建立管線** 可為這些資料建立管線。
   - **接收端正常，但需確認資料狀態**：接收端有回應，但尚未收到資料，或有部分訊號異常。請檢查部署，或等待下一批資料。
   - **驗證失敗**：無法檢查接收端。**可能原因** 包括收集器未執行、Token 無效或已過期，以及網路或 Proxy 封鎖了端點。

若已設定 `http.external_url`，系統會使用該設定值作為端點；否則，使用瀏覽器目前的網址。若 MoleSignal 位於反向 Proxy 後方，請設定 `http.external_url`，讓產生的片段指向對外網址。請參閱[設定](/zh-Hant/configuration)。

## 資料接收 Token

傳送端使用 Bearer Token 驗證身分：`Authorization: Bearer <token>`。

| Token | 權限 | 建立方式 | 用途 |
|---|---|---|---|
| 預設資料接收 Token | 僅 `logs.write`、`metrics.write`、`traces.write`、`profiles.write` 和 `apm.deploy`，也就是 **資料寫入** 原則 | 資料來源頁面，或 `GET /api/v1/me/api-tokens/default` | 傳送日誌、指標與追蹤的收集器、Agent 與 SDK 匯出端，以及[回報發布](/zh-Hant/apm/deployments#從-ci-回報發佈)的管線。不會過期。 |
| RUM 用戶端 Token | 僅 `rum.write`，繫結至單一應用程式 | Web RUM 與行動裝置 RUM 的資料來源頁面，或 `GET /api/v1/auth/tokens/rum?applicationId=<id>` | 瀏覽器與行動裝置的程式碼。終端使用者可以看到此 Token。 |
| 個人或服務帳號 Token | 以所屬成員或服務帳號的權限為上限，再依權限範圍縮小 | **個人設定 → API 權杖**；服務帳號的 Token 位於 **身分與存取 → API 權杖** | 自動化作業、指令碼與 MCP 用戶端。 |

持續執行的傳送端請使用預設資料接收 Token，或套用 **資料寫入** 原則的服務帳號 Token。在 **個人設定 → API 權杖** 或 **身分與存取 → API 權杖** 中撤銷 Token 可立即使其失效。網頁介面的登入工作階段無法用來傳送資料：瀏覽器將工作階段儲存在 Cookie 中，而 `Authorization` 要求標頭不接受該 Cookie。

在資料來源頁面輸入應用程式 ID 後，系統會建立 RUM Client Token。應用程式 ID 由 1 到 128 個字元組成，可使用 `A-Z`、`a-z`、`0-9`、`.`、`_`、`:` 與 `-`。在 SDK 的 `applicationId` 中使用相同的 ID，請參閱[瀏覽器 RUM SDK](/zh-Hant/rum/browser-sdk)。

## 端點與通訊協定

| 通訊協定 | 端點 | 相容的傳送端 | 目標資料流 |
|---|---|---|---|
| 原生 HTTP JSON | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`、應用程式程式碼、Vector `http` sink、Fluent Bit `http` 輸出 | 路徑中的 `{stream}` |
| OTLP over HTTP | `POST /api/v1/logs`、`/api/v1/metrics`、`/api/v1/traces` | OpenTelemetry SDK 與 Collector | `stream-name` 要求標頭，預設為 `default` |
| OTLP over gRPC | `:4317` | OpenTelemetry SDK 與 Collector | `stream-name` 中繼資料，預設為 `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus、VictoriaMetrics 及任何 remote_write v1 傳送端 | `stream-name` 要求標頭，未指定時為 `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat、Logstash、Vector `elasticsearch` sink | 優先使用各 action 的 `_index`，其次使用 `stream-name` 要求標頭，兩者皆未指定時使用 `default` |
| Loki push（JSON） | `POST /api/v1/loki/api/v1/push` | 能傳送 Loki JSON 格式的傳送端 | `stream-name` 要求標頭，預設為 `default` |
| Kinesis Firehose、Cloudflare Logpush、Heroku | `/api/v1/_kinesis_firehose`、`/api/v1/_cloudflare`、`/api/v1/_heroku` | AWS、Cloudflare、Heroku | 在連接器上設定，請參閱[連接器](/zh-Hant/connectors) |

除了推送型連接器之外，所有端點都需要具備對應訊號寫入權限（`logs.write`、`metrics.write`、`traces.write` 或 `profiles.write`）的 Bearer Token。系統依 Token 判定組織，URL 不會包含組織資訊。

### 傳送端限制

- **要求大小。** 原生 JSON 端點的要求本文大小上限為 16 MiB，以解壓縮後的大小計算；其他接收端點的上限為 2 MiB。端點會拒絕超過上限的要求，並傳回 `413`。請讓每批資料都小於適用的上限。
- **壓縮。** OTLP over HTTP 不接受壓縮的要求本文，並會傳回 `400`。請在傳送端停用壓縮。OpenTelemetry Collector 的 `otlphttp` 匯出端預設使用 gzip 壓縮，請設定 `compression: none`。原生 JSON 端點、Elasticsearch `_bulk`、Loki push 與推送型連接器接受 `Content-Encoding: gzip`。
- **Loki 編碼。** 端點只解析 JSON 格式的要求。Promtail 與 Grafana Alloy 預設傳送以 snappy 壓縮的 protobuf，無法將資料傳送至此端點。
- **速率限制。** `router` 角色會依組織限制要求速率。超過限制時會傳回 `429`，並附上 `Retry-After` 回應標頭。`standalone` 節點不套用此限制。請參閱[依角色部署](/zh-Hant/deployment/role-based#速率限制)。
- **平台資料流。** 只有 MoleSignal 能寫入[平台資料流](/zh-Hant/streams#平台資料串流)，例如儲存服務本身遙測資料的 `_molesignal`，以及儲存稽核記錄的 `_audit`。透過公開端點寫入時，端點會傳回 `403`。

## 資料流與 Schema

系統會在首次寫入時建立資料流，並在出現新欄位時更新 schema。系統以名稱和訊號類型共同識別資料流，因此日誌、指標與追蹤各自都可以有名為 `default` 的資料流。請參閱[資料流](/zh-Hant/streams)。

每個事件都有一個時間戳記，以 Unix 紀元起算的微秒數表示。原生 JSON 與 Elasticsearch `_bulk` 會讀取 `_timestamp` 欄位。若事件未包含 `_timestamp`，則使用伺服器收到事件的時間。

## 原生 HTTP JSON

將記錄陣列傳送至 `/api/v1/intake/{logs,metrics,traces}/{stream}`：

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

回應會列出已接收與已拒絕的記錄筆數，以及每筆遭拒記錄的索引和原因：

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

將 OpenTelemetry SDK 或 Collector 指向 `/api` 基礎路徑。匯出端會自動附加 `/v1/logs`、`/v1/metrics` 與 `/v1/traces`，分別對應 `/api/v1/logs`、`/api/v1/metrics` 與 `/api/v1/traces`。

<Tabs>
  <Tab title="OTLP over HTTP">
    SDK 環境變數：

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector：

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    請傳送 protobuf（`application/x-protobuf`）。這是各 SDK 與 Collector 的預設編碼。日誌、指標與追蹤也接受 JSON（`application/json`）。加上 `stream-name` 要求標頭，即可選擇 `default` 以外的資料流。此標頭適用於透過這個匯出端傳送的所有訊號。
  </Tab>
  <Tab title="OTLP over gRPC">
    OTLP gRPC 接收端會監聽 `4317` 通訊埠，提供日誌、指標、追蹤與效能剖析四項服務。接收端不會終止 TLS。若流量會離開受信任的網路，請在接收端前方終止 TLS。

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector：

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    若此通訊埠前方已有 Proxy 終止 TLS，請移除 `insecure: true`。`5082` 是叢集內部的 gRPC 通訊埠，不是 OTLP 接收端。
  </Tab>
</Tabs>

系統會逐筆儲存 OTLP 指標的資料點。儲存欄位請參閱[指標儲存慣例](/zh-Hant/query#otlp-指標欄位)。

## Prometheus remote_write

在 `prometheus.yml` 中將 MoleSignal 新增為 remote write 目標：

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

每個指標資料流會存放單一來源的所有指標。請使用 `stream-name` 要求標頭（在 `remote_write` 設定的 `headers:` 中），為每個 Prometheus 執行個體指定專屬資料流。若未設定此標頭，樣本會寫入 `default`。每個樣本各占一列，`metric_name` 的值取自該樣本的 `__name__`。其餘標籤會成為欄位。若標籤與指標欄位同名（例如 `metric_name`），系統會將標籤儲存為 `exported_<名稱>`。系統會略過原生直方圖與指標中繼資料，並將 exemplar 與樣本一併儲存。

## Elasticsearch bulk

支援 Elasticsearch bulk 通訊協定的傳送端可直接使用此端點，不必依賴 Loki 或 OTLP：

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

各 action 的 `_index` 決定目標資料流。若沒有 `_index`，則使用 `stream-name` 要求標頭。若也未指定此標頭，則使用 `default`。

## Loki push

此端點接受 Loki 的 JSON 要求格式：

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

端點會將標籤轉為欄位、將每行日誌寫入 `message` 欄位，並將時間戳記從奈秒轉為微秒。端點會傳回 `204`。使用 `stream-name` 要求標頭選擇目標資料流。
