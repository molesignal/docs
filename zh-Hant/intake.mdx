所有訊號都透過 intake API 進入 MoleSignal。網頁介面中的 **資料來源** 頁面會為每個資料來源產生端點、Token 與設定片段，同樣的協定也可以手動設定。

## 資料來源頁面

開啟 **資料來源** 接入資料來源：

1. 在目錄中搜尋，或按分類篩選：**建議**、**基礎設施**、**雲端服務**、**資料庫**、**訊息佇列**、**應用程式與語言**、**安全性** 與 **自訂**。訊號標籤（**日誌**、**指標**、**追蹤**、**Profiles**）可以進一步縮小範圍。
2. 選擇一個資料來源，例如 Kubernetes、Linux 主機、AWS、OpenTelemetry SDK 或 Web RUM。
3. 依精靈的三個步驟完成接入：
   - **端點與 Token** 顯示資料送往哪裡，以及用於驗證的 Token。**顯示 Token** 會顯示 Token 及其權限範圍、工作區與有效期限。使用者體驗類資料來源需要先選擇 **RUM 應用程式**，選擇後才會顯示它的 Client Token。
   - **設定資料來源** 顯示命令與設定，其中的端點與 Token 已替換為實際值。
   - **確認是否收到資料** 先檢查接收端，再查看最近 1 小時內是否收到資料。**驗證連線** 立即檢查一次，各項數字每 30 秒自動重新整理。
4. 檢視驗證結果：
   - **已偵測到資料**：最近 1 小時內收到了資料，且該資料來源的訊號都處於正常狀態。**檢視已接收的資料** 開啟這些資料，**建立管線** 為它們建立管線。
   - **接收端正常，但需確認資料狀態**：接收端有回應，但還沒有收到資料，或並非所有訊號都正常。請檢查部署，或等待下一批資料。
   - **驗證失敗**：無法檢查接收端。**可能原因** 列出採集器未執行、Token 無效或已過期，以及網路或代理封鎖了端點。

設定了 `http.external_url` 時，端點取自該設定；否則取自瀏覽器目前位址。位於反向代理之後時，請設定 `http.external_url`，讓產生的片段指向對外位址。參見[設定](/zh-Hant/configuration)。

## 接入 Token

傳送端使用 Bearer Token 驗證：`Authorization: Bearer <token>`。只支援 Basic 驗證的傳送端（例如雲端服務商託管 Prometheus 的 remote write 出口）把 API Token 放在 `Authorization: Basic` 的密碼裡，使用者名稱任意。其他 Basic 憑證會被忽略，因此在反向代理上另設的 Basic 驗證不受影響。Splunk HEC 傳送端以 `Authorization: Splunk <token>` 攜帶 Token。

| Token | 權限 | 建立方式 | 用途 |
|---|---|---|---|
| 預設接入 Token | 僅 `logs.write`、`metrics.write`、`traces.write`、`profiles.write` 與 `apm.deploy`，即 **資料寫入** 策略 | 資料來源頁面，或 `GET /api/v1/me/api-tokens/default` | 傳送日誌、指標與追蹤的採集器、Agent 與 SDK 匯出端，以及[上報發布](/zh-Hant/apm/deployments#從-ci-回報發佈)的管線。不會過期。 |
| RUM 用戶端 Token | 僅 `rum.write`，綁定一個應用程式 | Web RUM 與行動端 RUM 資料來源的資料來源頁面，或 `GET /api/v1/auth/tokens/rum?applicationId=<id>` | 瀏覽器與行動端程式碼。終端使用者可以看到該 Token。 |
| 個人或服務帳號 Token | 所屬成員或服務帳號能做的，再依權限範圍收窄 | **個人設定 → API 權杖**；服務帳號的 Token 在 **身分與存取 → API 權杖** | 自動化、指令碼與 MCP 用戶端。 |

持續執行的傳送端使用預設接入 Token，或跟隨 **資料寫入** 策略的服務帳號 Token。在 **個人設定 → API 權杖** 或 **身分與存取 → API 權杖** 中撤銷 Token 可立即使其失效。Web 介面的登入工作階段不能用來傳送資料：它儲存在瀏覽器 Cookie 中，`Authorization` 要求標頭不接受它。

在資料來源頁面輸入應用程式 id 後會建立 RUM Client Token。應用程式 id 由 1 到 128 個字元組成，可使用 `A-Z`、`a-z`、`0-9`、`.`、`_`、`:` 與 `-`。SDK 中的 `applicationId` 使用同一個 id，參見[瀏覽器 RUM SDK](/zh-Hant/rum/browser-sdk)。

## 端點與協定

| 協定 | 端點 | 相容的傳送端 | 目標資料流 |
|---|---|---|---|
| 原生 HTTP JSON | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`、應用程式碼、Vector `http` sink、Fluent Bit `http` 輸出 | 路徑中的 `{stream}` |
| OTLP over HTTP | `POST /api/v1/logs`、`/api/v1/metrics`、`/api/v1/traces` | OpenTelemetry SDK 與 Collector | `stream-name` 要求標頭，預設為 `default` |
| OTLP over gRPC | `:4317` | OpenTelemetry SDK 與 Collector | `stream-name` 中繼資料，預設為 `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus、VictoriaMetrics、雲端服務商託管 Prometheus 的匯出，以及任何 remote_write v1 傳送端 | `stream-name` 要求標頭，否則 `?stream=`，否則為 `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat、Logstash、Vector `elasticsearch` sink | 每個 action 的 `_index`，否則 `stream-name` 要求標頭，否則 `default` |
| Splunk HEC | `POST /api/v1/services/collector/event`、`/api/v1/services/collector/raw` | 騰訊雲 CLS、Vector 與 Fluent Bit 的 Splunk 輸出、SIEM 轉送器 | 每個事件的 `index`，否則 `?index=`，否則 `stream-name` 要求標頭，否則 `default` |
| Loki push（JSON） | `POST /api/v1/loki/api/v1/push` | 能傳送 Loki JSON 格式的傳送端 | `stream-name` 要求標頭，預設為 `default` |
| Amazon Data Firehose、Google Cloud Pub/Sub 推送、雲端事件匯流排、Cloudflare Logpush、Heroku | `/api/v1/_kinesis_firehose`、`/api/v1/_gcp_pubsub`、`/api/v1/_cloud_events`、`/api/v1/_cloudflare`、`/api/v1/_heroku` | 經 Firehose 的 CloudWatch Logs 與 CloudWatch Metric Streams、經 Pub/Sub 的 Cloud Logging、EventBridge、Event Grid 與 CloudEvents 傳送方、Cloudflare、Heroku | 在連接器上設定，參見[連接器](/zh-Hant/connectors) |

除推送型連接器外，所有端點都需要具備訊號對應的寫入權限（`logs.write`、`metrics.write`、`traces.write` 或 `profiles.write`）的 Bearer Token。組織由 Token 決定，不會出現在 URL 中。

### 影響傳送端的限制

- **要求大小。** 原生 JSON 接入與推送型連接器的請求主體上限為 16 MiB，Firehose 為 64 MiB，均按解壓後的大小計；其他接入端點為 2 MiB。超過上限的請求主體會被拒絕並傳回 `413`。請讓每批資料小於該大小。
- **壓縮。** OTLP over HTTP 不接受壓縮的請求主體，會傳回 `400`。請在傳送端關閉壓縮；OpenTelemetry Collector 的 `otlphttp` 匯出端預設使用 gzip 壓縮，需要設定 `compression: none`。原生 JSON 接入、Elasticsearch `_bulk`、Loki push 與推送型連接器接受 `Content-Encoding: gzip`。
- **Loki 編碼。** 只解析 JSON 請求格式。Promtail 與 Grafana Alloy 預設傳送 snappy 壓縮的 protobuf，無法向該端點傳送資料。
- **速率限制。** `router` 角色依組織限制請求，超限時傳回 `429` 並附帶 `Retry-After` 回應標頭。`standalone` 節點不套用這個限制。參見[分角色部署](/zh-Hant/deployment/role-based#速率限制)。
- **拒收的事件。** 值與資料流中欄位類型不符的事件會單獨被拒收，請求中的其餘事件照常寫入。`int64` 欄位收到帶小數的數不會被拒收，欄位會變成 `float64`（參見 [Schema 與欄位](/zh-Hant/streams#schema-與欄位)）。各端點都會回報拒收的事件：原生 JSON 寫在 `rejected` 與 `errors` 中，OTLP 寫在 `partialSuccess` 中，Elasticsearch `_bulk` 對應條目的狀態為 `400`，Splunk HEC 傳回錯誤碼 `6`，Prometheus remote write 與 Loki push 傳回 `400`。傳送端不會重試這些事件。推送型連接器仍傳回成功，因為平台會重送整個請求，拒收情況寫在連接器上。
- **平台資料流。** [平台資料流](/zh-Hant/streams#平台資料串流)（例如存放服務自身遙測的 `_molesignal` 與存放稽核記錄的 `_audit`）只由 MoleSignal 寫入，公開接入會傳回 `403`。

## 資料流與 Schema

資料流在首次寫入時建立，schema 會隨新欄位出現而演進。資料流由名稱與訊號類型共同識別，因此 `default` 可以同時存在於日誌、指標與追蹤類型下。參見[資料流](/zh-Hant/streams)。

每個事件都有一個自 Unix 紀元起的微秒時間戳。原生 JSON 與 Elasticsearch `_bulk` 讀取 `_timestamp` 欄位。沒有 `_timestamp` 的事件使用伺服器端接收它的時間。

## 原生 HTTP JSON

向 `/api/v1/intake/{logs,metrics,traces}/{stream}` 傳送記錄陣列：

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

回應會給出已接收與已拒絕的記錄數，並為每條被拒絕的記錄給出索引與原因：

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

把 OpenTelemetry SDK 或 Collector 指向 `/api` 基礎路徑。匯出端會自動附加 `/v1/logs`、`/v1/metrics` 與 `/v1/traces`，對應 `/api/v1/logs`、`/api/v1/metrics` 與 `/api/v1/traces`。

<Tabs>
  <Tab title="OTLP over HTTP">
    SDK 環境變數：

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector：

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    請傳送 protobuf（`application/x-protobuf`），這是各 SDK 與 Collector 的預設編碼。日誌、指標與追蹤也接受 JSON（`application/json`）。新增 `stream-name` 要求標頭可選擇 `default` 之外的資料流，該要求標頭對透過這個匯出端傳送的所有訊號生效。
  </Tab>
  <Tab title="OTLP over gRPC">
    OTLP gRPC 接收端監聽 `4317` 連接埠，提供日誌、指標、追蹤與 Profiles 四個服務。它不終止 TLS，流量離開可信網路時，需要在前面終止 TLS。

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector：

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    連接埠前面有終止 TLS 的代理時，去掉 `insecure: true`。`5082` 是叢集內部 gRPC 連接埠，不是 OTLP 接收端。
  </Tab>
</Tabs>

OTLP 指標按資料點逐條儲存，儲存欄位參見[指標儲存約定](/zh-Hant/query#otlp-指標欄位)。

## Prometheus remote_write

在 `prometheus.yml` 中把 MoleSignal 新增為 remote write 目標：

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

一個指標資料流裝一個來源的全部指標，所以請用 `stream-name` 要求標頭（`remote_write` 設定裡的 `headers:`）給每台 Prometheus 指定自己的資料流；沒有這個要求標頭時樣本寫入 `default`。設不了要求標頭的傳送端可以在位址裡指定資料流，例如 `/api/v1/prometheus/api/v1/write?stream=aliyun`。每個樣本成為一行，`metric_name` 是它的 `__name__`。其餘標籤成為欄位，與指標欄位同名的標籤（例如 `metric_name`）存為 `exported_<名稱>`。原生直方圖與指標中繼資料會被跳過，exemplar 與樣本一起儲存。

## Elasticsearch bulk

支援 Elasticsearch bulk 協定的傳送端無需依賴 Loki 或 OTLP 即可使用：

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

每個 action 的 `_index` 決定目標資料流。沒有 `_index` 時使用 `stream-name` 要求標頭，再預設為 `default`。

## Loki push

該端點接受 Loki 的 JSON 請求格式：

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

標籤成為欄位，日誌行寫入 `message` 欄位，奈秒時間戳會轉換為微秒。回應為 `204`。用 `stream-name` 要求標頭選擇目標資料流。

## Splunk HEC

支援 Splunk HTTP Event Collector 協定的傳送端（例如騰訊雲 CLS 投遞到 Splunk、Vector 與 Fluent Bit 的 Splunk 輸出）可以原樣發給 MoleSignal：HEC 位址填 `https://molesignal.example.com/api/v1`，HEC Token 填有日誌寫入權限的 API Token，以 `Authorization: Splunk <token>` 傳送。

| 端點 | 請求主體 |
|---|---|
| `POST /api/v1/services/collector/event`，也接受 `/services/collector` | 首尾相接的 JSON 物件，每個形如 `{"time", "host", "source", "sourcetype", "index", "event", "fields"}` |
| `POST /api/v1/services/collector/raw` | 文字，每行一筆日誌事件；`host`、`source`、`sourcetype`、`index` 取自查詢參數 |
| `GET /api/v1/services/collector/health` | 不需要 Token，傳回 `{"text":"HEC is healthy","code":17}` |

`event` 是 JSON 物件時作為日誌的欄位，否則放進 `message`。`fields`、`host`、`source`、`sourcetype` 成為欄位，`time`（秒）成為事件時間。`index` 決定資料流，否則取查詢參數 `index`，再否則取 `stream-name` 要求標頭，都沒有時為 `default`。成功傳回 `{"text":"Success","code":0}`，失敗時傳回 `400` 與 HEC 自己的錯誤碼。資料流因值與欄位類型不符拒收事件時，其餘事件照常寫入，傳回錯誤碼 `6`：`invalid-event-number` 是第一個被拒收事件在請求主體中的位置，`text` 寫明原因。不支援索引器確認（indexer acknowledgement）。
