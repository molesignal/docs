資料流是收集、查詢、管線與保留原則共同使用的組織層級資料契約。開啟 **資料流** 可以查看到達的資料，並檢查或設定每條資料流。

## 資料流類型

| 類型 | 典型內容 |
|---|---|
| `logs` | 結構化事件與應用程式日誌。 |
| `metrics` | 單一來源（例如一台 Prometheus）的指標樣本，以 `metric_name` 區分。 |
| `traces` | OpenTelemetry Span。 |
| `profiles` | 與 pprof 物件關聯的效能剖析中繼資料。 |
| `extend` | 作為擴充表管理、在處理過程中使用的查找資料。 |

不同資料流類型可以使用相同名稱。呼叫 API 或撰寫自動化時，請一律傳入 `stream_type`。

### 平台資料流

下列資料流由 MoleSignal 自行寫入：

| 資料流 | 內容 |
|---|---|
| `_molesignal` | MoleSignal 自身的遙測，在 `_sys` 組織中，參見[自身可觀測性](/zh-Hant/self-observability)。 |
| `_synthetic_results` | 撥測檢查的每次執行一行，參見[撥測](/zh-Hant/synthetics#結果資料流與保留期限)。 |
| `_audit` | 工作區的稽核事件，參見[稽核資料流](/zh-Hant/settings/data-security#稽核資料流)。 |
| `_agent_model_traces` | Mole Agent 的模型呼叫，參見[用量與預算](/zh-Hant/agent#用量與預算)。 |
| `_agent_score_traces` | Mole Agent 回答的品質分數，參見[品質](/zh-Hant/quality#串流裡的分數)。 |

它們和其他資料流一樣可以讀取。`_audit` 需要 `audit.read`：沒有這個權限時，列表和執行統計中都看不到它，查看、修改或刪除它都會傳回 `403`。其他途徑都不能寫入它們：不能建立這些名稱的資料流，向它們接入資料會傳回 `403`，任何[管線](/zh-Hant/pipelines#平台資料串流)也不能寫入它們。

## 資料流列表

**資料流** 列出工作區的所有資料流。切換分頁可以顯示 **全部** 資料流或某一種類型，也可以按名稱或說明搜尋，並依執行狀態篩選。頁面頂端統計正常接收和需要關注的資料流數，並彙總時段內寫入的壓縮資料和目前儲存量。

| 欄 | 顯示內容 |
|---|---|
| **狀態** | **正常**、**接收延遲**、**資料流中斷**、**閒置**、**未使用** 或 **統計異常**，見下表。 |
| **接收速率**、**上次接收** | 資料到達的速度，以及最後一次到達的時間。 |
| 壓縮資料 | 時段內寫入的壓縮位元組數。 |
| **目前儲存量**、**保留期限** | 目前儲存的位元組數，以及資料保留多少天。 |
| **資料筆數**、**收集的資料大小**、**實際儲存大小**、**索引大小** | 保留的記錄數、轉換前接收的位元組數、資料檔案的位元組數和索引的位元組數。 |

| 狀態 | 意義 |
|---|---|
| **正常** | 最近 15 分鐘內有資料到達。 |
| **接收延遲** | 最後一次資料在 15 分鐘到 2 小時之前到達。 |
| **資料流中斷** | 超過 2 小時沒有資料。 |
| **閒置** | Mole Agent 追蹤資料流，在兩次回答之間本來就沒有資料。 |
| **未使用** | 從未收到資料。 |

標記為 **無法查詢** 的資料流仍在接收資料，但不會出現在查詢選擇器中。每一列都有 **查詢** 或 **探索**、**查看詳細資料** 和 **複製資料流 ID**。頁首的 **搜尋工作** 開啟[搜尋工作](#搜尋工作)。

## 建立資料流

資料第一次寫入時，MoleSignal 會自動建立資料流，所以大多數資料流會自行出現。如果要在開始時就設定保留期限、加密欄位或查詢權限，可以提前建立。點選 **建立資料流**：

| 欄位 | 規則 |
|---|---|
| **資料流名稱** | `snake_case`，最多 64 個字元。 |
| **說明** | 選填，說明這個資料流承載什麼資料。 |
| **訊號類型** | **日誌**、**指標** 或 **追蹤**。 |
| **保留期限（天）** | 資料保留多久。 |
| **索引欄位** | 以逗號分隔的欄位，為它們建立全文索引。 |
| **加密欄位** | 以逗號分隔的欄位，在儲存前加密，之後無法修改。參見[加密欄位](#加密欄位)。 |
| **可查詢** | 僅為路由管線提供資料的來源資料流應關閉此選項。 |

## 資料流詳細資料

點選資料流即可開啟詳細資料。**查詢資料** 會在對應的探索頁面中開啟它，選單中有 **複製資料流 ID** 和 **刪除資料流**。各分頁如下：

| 分頁 | 內容 |
|---|---|
| **總覽** | 執行狀態、首次接收時間、查詢能力，以及最近 24 小時寫入列數和壓縮資料的趨勢。尚無資料的資料流會提供 **設定資料來源** 和 **傳送測試資料**。 |
| **欄位與索引** | 各欄位的類型、索引類型和加密情況。編輯欄位可以修改它的索引或遮罩，參見 [Schema 與欄位](#schema-與欄位)。 |
| **保留原則** | 資料流的保留期限，以及指標資料流的降取樣。參見[保留與刪除](#保留與刪除)。 |
| **使用位置** | 依賴這個資料流的物件：寫入它的接入端點、管線、已儲存的查詢和警示規則。修改或刪除前請先查看。 |
| **設定** | **說明**、**可查詢**、**查詢時間範圍上限（小時）**、**每日合併小檔案**、**依欄位分片**，日誌資料流還有 **依欄位叢集**。 |

各分頁上的修改會先彙總為草稿。**儲存並套用** 會立即套用，**捨棄變更** 會丟棄草稿。儲存前，頁面會提示無法復原的修改：縮短保留期限會刪除過期資料，降取樣會刪除原始樣本。

**查詢時間範圍上限** 限制對該資料流的一次 SQL 或 PromQL 查詢最多涵蓋多少小時。時間範圍更長的查詢會被拒絕，誤選「最近 90 天」也不會把大型資料流從頭掃到尾。留空或 `0` 表示不限制。

如果某個備援資料來源仍需接收資料，但不應出現在查詢選擇器中，請關閉 **可查詢**。路由管線仍可讀取該資料流。`extend` 資料應透過 **擴充表** 管理，而不是一般遙測查詢路徑。

## Schema 與欄位

欄位包含名稱、資料類型、`nullable` 旗標、索引類型與 `encrypted` 旗標。資料類型有 `bool`、`int64`、`float64`、`utf8`、`timestamp` 與 `json`。傳入的資料中首次出現新欄位時，該欄位會加入 schema；類型不一致的值會被拒絕，並回報 `type mismatch on field`。數值例外：`int64` 欄位收到帶小數的數，或超出 `int64` 範圍的整數時，無論在同一批還是之後的批次，都會變成 `float64`，之前存下的值也以 `float64` 讀取。

索引類型決定 MoleSignal 為欄位建構哪種輔助結構：

| 索引類型 | 效果 |
|---|---|
| `none` | 不建立輔助索引，這是預設值。 |
| `exact` | 對完整取值建立精確比對的反向索引（非文字欄位改用 Parquet Bloom 篩選器），並記下每個檔案的最小值和最大值。`=` 與 `IN` 會在開啟檔案之前跳過不含這些值的檔案，命中列很少時只讀這些列所在的頁。在每個檔案不超過 65,536 個值的欄位上，`LIKE` 與 `ILIKE` 會跳過沒有任何值包含這段文字的檔案。適用於 `trace_id` 之類的識別碼。 |
| `full_text` | 為文字搜尋建立分詞的反向索引：字母數字的連續段是詞，中日韓文字切成相鄰兩字的二元組。`MATCH`、`MATCH_TEXT`、`LIKE` 與 `ILIKE` 的字面量（含標點與中文）據此跳過不可能命中的檔案。僅用於 `utf8` 欄位。 |
| `bloom` | Parquet Bloom 篩選器，文字與 `int64` 欄位的每個檔案另有一個整值篩選器，並記下每個檔案的最小值和最大值：`=` 與 `IN` 會在開啟檔案之前跳過一定不含這些值的檔案。適用於取值很多、只按等值查詢的欄位，例如請求 ID。 |
| `skip` | 記下每個檔案的最小值和最大值，檔案裡不同的值不超過 32 個時還會記下全部的值。比較、`IN`、`BETWEEN` 與前綴 `LIKE` 據此跳過檔案。 |
| `ngram` | 為每個檔案記下值的三元組，為檔案裡每 1024 列的區塊記下值的五位元組片段，不分大小寫：`LIKE`、`ILIKE`、`MATCH` 的字面量有三元組不在檔案裡時跳過這個檔案，有片段不在同一區塊裡時跳過這個區塊，所以查一個 ID 之類少見的字串時只讀可能包含它的那幾個區塊。短於五位元組的字面量每塊都讀。有 `ngram` 欄位的資料流按 1024 列一頁寫入檔案。小頁和片段都佔儲存空間：在這類欄位佔每列三分之二的測試裡，儲存空間大了約 14%。適用於按片段查詢的 URL、路徑和主機名稱，不適合大段自由文字。僅用於 `utf8` 欄位。 |
| `ip` | 記下每個檔案裡位址的範圍，IPv4 會對應到 IPv6：`CIDR_MATCH(field, '10.0.0.0/8')` 與對單一位址的 `=` 據此跳過檔案。僅用於 `utf8` 欄位。 |
| `key_value` | 記下 JSON 物件第一層的鍵與它們的值：`json_text(field, 'key') = 'value'`、`IN` 與 `IS NOT NULL` 會跳過沒有這個鍵或值的檔案，命中列很少時只讀這些列所在的頁。值依 `json_text` 給出的樣子比較：文字原樣，數字與布林值是它們的 JSON。僅用於 `json` 欄位。 |
| `range` | 在索引裡記下每一列的數值，並記下每個檔案的最小值和最大值。只有 `exact` 欄位上的 `=`、`range` 欄位與數字的 `>`、`>=`、`<`、`<=`，以及時間範圍的 `count(*)` 會直接由索引回答，不讀取檔案；其他比較據此跳過範圍之外的檔案。僅用於 `int64`、`float64` 與 `timestamp` 欄位。 |

建立索引的欄位還會記下每個檔案裡有多少列的这个欄位為空。`IS NULL` 會跳過這個欄位總是有值的檔案；欄位上的其他條件，包括 `IS NOT NULL` 與 `!= ''` 這類詢問「有沒有值」的條件，會跳過這個欄位全為空的檔案。

用 `OR` 串連的條件，若每一支在某個檔案裡都被排除，也會跳過這個檔案；每一支由能回答它的索引判斷：`level = 'error' OR status >= 500` 會跳過 `level` 索引裡沒有 `error`、`status` 又不到 500 的檔案。

傳入資料中首次出現的欄位會依名稱取得索引類型：

| 資料流類型 | 欄位 | 索引類型 |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`、`level`、`session_id`、`fingerprint`、`country`、`browser`、`application`、`environment`，以及 OpenTelemetry 欄位 `host.id`、`container.id`、`event.name`、`event.domain`、`severity_text` | `exact` |
| `traces` | `trace_id`、`span_id`、`parent_span_id`、`service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

其餘新欄位為 `none`，但資料流本身設有規則者除外，參見[新欄位的索引](#新欄位的索引)。`level` 建立 `exact` 索引後，日誌直方圖可以直接從索引統計錯誤數，不必讀取資料檔案。RUM 資料流的 `context`、`feature_flags` 與 `usr.extra` 會用 `key_value` 為鍵建立索引。

修改索引類型後，之後寫入的資料會立即依新設定建立索引；之前寫入的資料由背景依新設定補建：每個封存的分區（預設在分區結束 48 小時後封存）會從它的檔案重建，較新的檔案會在封存或合併時重建。補建之前，檔案沿用寫入時的索引，查詢結果不受影響，只是要讀取的檔案多一些。**總覽** 裡的 **索引欄位涵蓋率** 顯示還剩多少檔案。全文索引的格式升級後（例如中日韓文字改為切成二元組），舊檔案的索引也會由背景依新格式重建。

要修改欄位，開啟 **欄位與索引**，點選欄位的編輯按鈕，然後選擇：

- **索引類型**：**未建立索引**、**全文搜尋**、**精確比對**、**Bloom 篩選器**、**跳過索引**、**N-gram 子字串**、**IP 位址** 或 **JSON 鍵值**。全文搜尋、N-gram 子字串與 IP 位址僅用於文字欄位，JSON 鍵值僅用於 JSON 欄位；
- **傳回時套用欄位遮罩** 的 **資料流層級策略**：**繼承全域規則**、**自訂資料流規則** 或 **明確不遮罩此資料流的欄位**。參見[欄位遮罩](/zh-Hant/settings/data-security#欄位遮罩)。指標資料流不參與遮罩。

點選 **套用至草稿**，再點選 **儲存並套用**。欄位的類型不會改變。

### 新欄位的索引

在 **設定** 分頁的 **欄位索引** 裡，可以依名稱為資料流裡第一次出現的欄位選擇索引。點選 **新增規則**，填寫欄位名稱模式，再選擇索引類型：`*` 匹配任意一段文字，`?` 匹配一個字元，例如 `*_id` 匹配 `user_id` 與 `order_id`，`http.*` 匹配 `http` 下的所有欄位。依序由第一條名稱匹配、索引類型適合欄位資料類型的規則生效；在 **欄位與索引** 裡為某個欄位設定過的索引優先，沒有規則匹配的欄位則依上述預設規則。規則只管之後第一次出現的欄位，既有欄位請在 **欄位與索引** 裡修改。一個資料流最多 32 條規則。

### 依欄位分片

日誌與追蹤資料流可以依一或兩個文字欄位分片：在 **設定** 分頁的 **依欄位分片** 裡點選 **新增分片欄位**，選擇欄位，再選擇它的分片方式。之後寫入的資料會依欄位的值分進各個分片，每個分片寫自己的檔案。

- **雜湊**：依值的雜湊分成 2 到 64 片，分得均勻。帶這個欄位等值條件（`=` 或 `IN`）的查詢只讀值所在分片的檔案。
- **首字元**：依值的第一個字元分成 37 片，每個數字和字母（不分大小寫）各佔一片，其餘字元與空值佔一片。帶這個欄位等值條件或以文字開頭的 `LIKE`（如 `'web-%'`）的查詢只讀首字元所在分片的檔案，`ILIKE` 另讀其餘字元那一片。分片是否均勻取決於資料，例如十六進位的追蹤 ID 只會用到其中 16 片。

使用兩個欄位時，檔案會依兩個欄位的分片組合分片，分片數相乘。**依欄位分片** 右側會顯示分片總數，最多 256：首字元（37 片）搭配雜湊時，雜湊最多 4 片。帶其中任一個欄位條件的查詢都能少讀檔案，兩個都帶時少得更多。分片欄位適合幾乎每次查詢都會帶的欄位，例如服務、命名空間或租戶。分片越多，檔案越多、越小。

設定只影響之後寫入的資料：既有檔案保持原樣，查詢會依每個檔案寫入時的分片欄位判斷，Compactor 只會把分片欄位相同的檔案合在一起。分片欄位必須是未加密的文字欄位，兩個分片欄位不能相同。

### 依欄位叢集

日誌資料流可以依一或兩個欄位排列檔案裡的列：在 **設定** 分頁的 **依欄位叢集** 裡點選 **新增叢集欄位**，選擇欄位，再選擇 **時間片**。之後寫入的每個檔案裡，列會依這個寬度的時間片排列，新的在前；片內依這些欄位的值排列，再依時間從新到舊。

列依時間排列時，某個服務這類的值會在檔案的每一頁上都有；叢集之後，每個時間片裡只有幾頁有它，帶叢集欄位等值條件（`=` 或 `IN`）的查詢只讀這幾頁。叢集欄位適合查詢常帶、取值不多的欄位，例如服務或等級。

每個叢集檔案還會記下每分鐘、叢集欄位每組取值各有幾列。只帶文字叢集欄位等值條件的計數、依其中一個欄位分組的計數（`GROUP BY service`），以及柱寬為整分鐘的直方圖，都會直接用這些數回答，不讀取檔案；查詢時間範圍的起止落在檔案中間的整分鐘上時也一樣。一個檔案裡分鐘與取值的組合超過 65,536 種時就不記。這些數還能算出最新（或最早）的一頁落在哪幾分鐘：取這樣一頁時，無論帶不帶叢集欄位的等值條件，都只讀那幾分鐘。

時間片可選 1、5 或 10 分鐘，預設 1 分鐘。時間片越寬，跳過的頁越多；但時間範圍很短的查詢會整片讀入它碰到的時間片。

叢集與[依欄位分片](#依欄位分片)不同：分片會把每個分片寫成各自的檔案，查詢讀的檔案少，資料流的檔案卻更多、更小；叢集不會增加檔案，只排列檔案裡的列。兩者可以同時使用。

設定只影響之後寫入的資料：既有檔案保持寫入時的順序，Compactor 只會把叢集方式相同的檔案合在一起。叢集欄位必須是未加密的文字、`int64` 或 `bool` 欄位，兩個叢集欄位不能相同。

### 加密欄位

建立資料流時把欄位標記為 `encrypted`，該欄位會在寫入 Parquet 之前被加密。儲存的列會保存密文，一般查詢傳回的也是密文。在 SQL 中用 `decrypt(field)` 讀回明文：

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

該旗標之後無法修改，否則既有資料將無法讀取。金鑰來自組織加密金鑰與加密根金鑰 `MS_CIPHER_KEY`，遺失根金鑰會導致加密欄位無法復原，參見[安全性與多租戶](/zh-Hant/security#欄位層級加密)。

## 保留與刪除

保留原則決定 Compactor 何時刪除資料。在 **保留原則** 頁籤設定 **資料保留期限（天）**，留空則使用平台預設值 30 天，該預設值在 `_sys` 組織的[設定 → 資料保留](/zh-Hant/settings/platform#資料保留)中修改。超過保留期限的資料會在下一次清理時刪除，因此縮短保留期限會刪除隨之過期的資料，刪除的檔案無法復原。指標資料串流裡在保留期限內未再出現過的指標，也會從指標清單中移除。

在指標資料串流的**保留原則**頁籤，**對較早的樣本降取樣**會把串流裡每個指標早於設定天數的樣本依 1 分鐘到 1 天的時間桶聚合：同一個 series 在一個桶裡的樣本合成一個點，數值取平均，增量計數取總和，原始樣本隨之刪除。長時間範圍的查詢讀取量少得多，較早的資料只剩時間桶的精度。原始樣本無法復原。

日誌與追蹤資料串流的**每日合併小檔案**設定（預設開啟）會在一天結束一小時後，於這一天的檔案合計不超過 Compactor 的 `[compactor].target_size` 時，將它們合併成一個檔案，跨多天的查詢要開啟的檔案少得多。保留期限隨之按天生效：合併後的檔案在一整天都過期後才刪除。要保留按小時的檔案，在資料串流的**設定**頁籤關閉這個設定。

**刪除資料串流** 會刪除資料串流及其設定，無法復原。它可能導致儀表板、已儲存的檢視、告警、報告和管線失效，刪除前請先查看 **使用位置** 頁籤。

## 搜尋工作

搜尋工作是在背景執行的查詢，結果會保留到工作過期。工作有三個來源：

- 帶 `Prefer: respond-async` 請求標頭的查詢，或預期結果過大、不適合互動式請求的查詢；
- 管線的回填；
- Mole Agent 提交的查詢。

在 **資料串流** 的頁首選擇 **搜尋工作** 開啟清單。清單頂端的檢視依狀態篩選，每個檢視都帶有數量：**全部**、**佇列中**、**執行中**、**已完成**、**失敗** 和 **已取消**。有工作在佇列中或執行中時，清單會自動重新整理。

每一列顯示工作的類型（**查詢** 或 **回填**）、陳述式、狀態、查詢時間範圍、提交時間、耗時、結果列數、嘗試次數和到期時間。每個工作都有一個與狀態對應的操作：

| 狀態 | 操作 |
|---|---|
| 佇列中或執行中 | **取消工作** |
| 已完成 | **下載結果** |
| 失敗或已取消 | **重試** |

**刪除** 可以在任何狀態下移除工作及其結果。

成員可以檢視和管理自己提交的工作。擁有 `org.running_queries.cancel` 的管理員可以檢視和管理組織內的全部工作。工作 API 請參閱[查詢](/zh-Hant/query#時間範圍與非同步工作)。

## 資料擷取用量與預算

在 **資料串流** 頁首選擇 **資料擷取用量**，檢視每個來源最近 24 小時、7 天或 30 天擷取了多少資料。同一份資料依三種方式劃分，合計一致：

| 檢視 | 來源是 |
|---|---|
| **憑證** | API Token、RUM 用戶端 Token、連接器或登入使用者。**平台內部** 是平台自身的遙測。 |
| **資料串流** | 一個資料串流，依名稱和類型區分。 |
| **服務** | 事件在 `service.name` 中標註的服務，沒有時取 `service` 或 `service_name`。沒有標註的事件計入 **未標註的服務**。 |

資料擷取量統計的是被接受資料解壓縮後的請求位元組：被拒絕的事件不計，傳送端重試的請求只計一次。Span 在到達時計入，早於尾端取樣。工作階段回放計入 **資料串流** 檢視的 `rum_replay` 列。一個請求中有多個服務或資料串流時，位元組依事件數分攤，因此這些檢視是近似值。

未知的數值顯示 `–`，不顯示 0。帶 `≥` 的數值是下限，表示計量在這段時間內才開始；清單上方會說明開始時間。資料大約一分鐘內會顯示在頁面上。節點異常停止時，可能少計最後 15 秒。

選擇一列，檢視這個來源的每小時趨勢，以及它在另外兩種檢視上的拆分。

### 設定預算

在一列上選擇 **設定預算**，或者勾選多列，為它們設定相同的預算。

| 欄位 | 說明 |
|---|---|
| **週期** | **每天** 或 **每月**，依 UTC 日曆日或日曆月計算。 |
| **額度** | 1 MiB 到 1 PiB。 |
| **預警比例（%）** | 用到這個比例時提醒一次，用完時再提醒一次。填 `0` 只在用完時提醒。預設 80。 |
| **通知對象** | 組織成員。預設為設定預算的人。 |

預算只用來提醒：來源超出預算時，擷取的回應和儲存都不變，不會遺失資料，也不限流。每個門檻在一個週期內只提醒一次。調高額度後再次超出會再提醒。

通知會透過內建通知原則 **資料擷取預算即將用完** 和 **資料擷取超出預算**，也會顯示在頂端列的通知中心。要調整還要通知哪些對象、如何通知，請見[通知管道](/zh-Hant/notification-channels)。

`_sys` 組織沒有通知原則，所以不能設定預算。**平台內部**、**未標註的服務** 和 **其他服務** 也不能設定預算，其中 **其他服務** 是超出[平台設定](/zh-Hant/settings/platform#資料擷取用量)上限的那些服務。

## 權限

| 權限 | 能力 |
|---|---|
| `intake_usage.read` | 開啟 **資料擷取用量**，頁面上能看到 Token 和成員的名稱。Owner 和 Admin 擁有。 |
| `intake_budgets.manage` | 設定和移除預算。Owner 和 Admin 擁有。 |
| `streams.read` | 列出資料串流並檢視中繼資料。 |
| `streams.query` | 用 SQL 查詢資料串流。 |
| `query.jobs.read`、`query.jobs.run` | 開啟 **搜尋工作**；提交、取消、重試和刪除工作。 |
| `logs.write`、`metrics.write`、`traces.write`、`profiles.write` | 將資料寫入現有資料串流。 |
| `streams.create` | 建立資料串流。 |
| `streams.configure` | 修改資料結構相關設定與保留原則。 |
| `streams.delete` | 刪除資料串流。 |
