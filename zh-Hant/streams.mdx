資料串流是收集、查詢、管線和保留原則共用的組織層級資料契約。開啟 **資料串流**，即可查看收到的資料，並檢查或設定各個資料串流。

## 資料串流類型

| 類型 | 常見內容 |
|---|---|
| `logs` | 結構化事件與應用程式日誌。 |
| `metrics` | 來自單一來源（例如一個 Prometheus 執行個體）的指標樣本，以 `metric_name` 區分。 |
| `traces` | OpenTelemetry Span。 |
| `profiles` | 與 pprof 物件關聯的效能剖析中繼資料。 |
| `extend` | 以擴充表管理、在處理過程中使用的查找資料。 |

不同類型的資料串流可以使用相同名稱。呼叫 API 或撰寫自動化程式時，一律傳入 `stream_type`。

### 平台資料串流

MoleSignal 會寫入下列資料串流：

| 資料串流 | 內容 |
|---|---|
| `_molesignal` | 位於 `_sys` 組織中的 MoleSignal 自身遙測資料，請參閱[自身可觀測性](/zh-Hant/self-observability)。 |
| `_synthetic_results` | 合成監控檢查每執行一次就寫入一列，請參閱[合成監控](/zh-Hant/synthetics#結果資料流與保留期限)。 |
| `_audit` | 工作區的稽核事件，請參閱[稽核資料串流](/zh-Hant/settings/data-security#稽核資料流)。 |
| `_agent_model_traces` | Mole Agent 的模型呼叫，請參閱[用量與預算](/zh-Hant/agent#用量與預算)。 |
| `_agent_score_traces` | Mole Agent 回答的品質分數，請參閱[品質](/zh-Hant/quality#資料流中的分數)。 |

讀取方式與其他資料串流相同。`_audit` 需要 `audit.read` 權限。若沒有此權限，清單和執行統計資料都不會顯示 `_audit`，查看、修改或刪除時也會傳回 `403`。其他途徑都無法寫入這些資料串流：無法以這些名稱建立資料串流，嘗試匯入資料會傳回 `403`，任何[管線](/zh-Hant/pipelines#平台資料串流)也無法寫入。

## 資料串流清單

**資料串流** 列出工作區的所有資料串流。切換分頁可顯示 **全部** 資料串流或特定類型，也可依名稱或說明搜尋，並依執行狀態篩選。頁面頂端會統計正常接收和需要留意的資料串流數量，並彙總所選時段內寫入的壓縮資料量及目前儲存量。

| 欄 | 顯示內容 |
|---|---|
| **狀態** | **正常**、**接收延遲**、**資料流中斷**、**閒置**、**未使用** 或 **統計異常**，請見下表。 |
| **接收速率**、**上次接收** | 資料抵達的速率與上次收到資料的時間。 |
| 壓縮資料 | 所選時段內寫入的壓縮資料位元組數。 |
| **目前儲存量**、**保留期限** | 目前儲存的位元組數，以及資料保留天數。 |
| **資料筆數**、**收集的資料大小**、**實際儲存大小**、**索引大小** | 保留的記錄數、轉換前收到的位元組數、資料檔案的位元組數和索引的位元組數。 |

| 狀態 | 意義 |
|---|---|
| **正常** | 最近 15 分鐘內收到過資料。 |
| **接收延遲** | 上次收到資料是在 15 分鐘至 2 小時前。 |
| **資料流中斷** | 超過 2 小時未收到資料。 |
| **閒置** | Mole Agent 的追蹤資料串流在兩次回答之間本來就沒有資料。 |
| **未使用** | 從未收到資料。 |

標記為 **無法查詢** 的資料串流仍會接收資料，但不會出現在查詢選擇器中。每一列都提供 **查詢** 或 **探索**，以及 **查看詳細資料** 和 **複製資料流 ID**。頁首的 **搜尋工作** 會開啟[搜尋工作](#搜尋工作)。

## 建立資料流

首次寫入資料時，MoleSignal 會自動建立資料串流，因此大多數資料串流會自動出現。若要從一開始就設定保留期限、加密欄位或查詢權限，可預先建立。按一下 **建立資料流**：

| 欄位 | 規則 |
|---|---|
| **資料流名稱** | 使用 `snake_case`，最多 64 個字元。 |
| **說明** | 選填，說明此資料串流包含哪些資料。 |
| **訊號類型** | **日誌**、**指標** 或 **追蹤**。 |
| **保留期限（天）** | 資料的保留天數。 |
| **索引欄位** | 以逗號分隔欄位，系統會為這些欄位建立全文索引。 |
| **加密欄位** | 以逗號分隔欄位。系統會在儲存前加密這些欄位，之後無法修改。請參閱[加密欄位](#加密欄位)。 |
| **可查詢** | 如果來源資料串流只供路由管線使用，請關閉此選項。 |

## 資料串流詳細資料

按一下資料串流即可開啟詳細資料。選取 **查詢資料**，即可在對應的探索頁面開啟此資料串流。選單中有 **複製資料流 ID** 和 **刪除資料串流**。各分頁如下：

| 分頁 | 內容 |
|---|---|
| **總覽** | 執行狀態、首次接收時間、是否可查詢，以及最近 24 小時寫入的列數與壓縮資料量趨勢。尚未收到資料的資料串流會提供 **設定資料來源** 和 **傳送測試資料**。 |
| **欄位與索引** | 各欄位的類型、索引類型和加密狀態。編輯欄位即可修改索引或遮罩，請參閱 [Schema 與欄位](#schema-與欄位)。 |
| **保留原則** | 資料串流的保留期限，以及指標資料串流的降採樣設定。請參閱[保留與刪除](#保留與刪除)。 |
| **使用位置** | 依賴此資料串流的物件，包括寫入資料的擷取端點、管線、已儲存的查詢和警示規則。修改或刪除前請先查看。 |
| **設定** | **說明**、**可查詢**、**查詢時間範圍上限（小時）**、**每日合併小檔案**、**依欄位分片**。日誌資料串流另有 **依欄位叢集**。 |

各分頁的變更會先彙整成草稿。按一下 **儲存並套用** 立即套用，或按一下 **捨棄變更** 捨棄草稿。儲存前，頁面會提示無法復原的變更：縮短保留期限會刪除到期資料，降採樣會刪除原始樣本。

**查詢時間範圍上限** 限制單次 SQL 或 PromQL 查詢此資料串流時最多可涵蓋多少小時。系統會拒絕超出上限的查詢，因此即使誤選「最近 90 天」，也不會掃描整個大型資料串流。留空或填入 `0` 表示不限制。

如果備用資料來源仍須接收資料，但不應出現在查詢選擇器中，請關閉 **可查詢**。路由管線仍可讀取此資料串流。請透過 **擴充表** 管理 `extend` 資料，不要使用一般遙測查詢路徑。

## Schema 與欄位

欄位包含名稱、資料類型、`nullable` 旗標、索引類型與 `encrypted` 旗標。資料類型有 `bool`、`int64`、`float64`、`utf8`、`timestamp` 與 `json`。傳入資料首次出現新欄位時，系統會將該欄位加入 schema。系統會拒絕類型不符的值，並回報 `type mismatch on field`。

索引類型決定 MoleSignal 要為欄位建立哪種輔助結構：

| 索引類型 | 效果 |
|---|---|
| `none` | 不建立輔助索引。這是預設值。 |
| `exact` | 依完整值建立精確比對的倒排索引（非文字欄位改用 Parquet Bloom 篩選器），並記錄各檔案的最小值和最大值。`=` 與 `IN` 會在開啟檔案前跳過不含這些值的檔案。符合條件的列很少時，只讀取這些列所在的頁面。如果欄位在每個檔案中不超過 65,536 個值，`LIKE` 與 `ILIKE` 會跳過沒有任何值包含該段文字的檔案。適用於 `trace_id` 等識別碼。 |
| `full_text` | 為全文搜尋建立斷詞後的倒排索引：連續的英數字元視為一個詞，中文、日文和韓文則切成由相鄰兩字組成的二元組。`MATCH`、`MATCH_TEXT`、`LIKE` 與 `ILIKE` 會依字面值（含標點符號與中文）跳過不可能符合條件的檔案。僅適用於 `utf8` 欄位。 |
| `bloom` | 使用 Parquet Bloom 篩選器。文字與 `int64` 欄位在每個檔案中另有一個比對完整值的篩選器，並記錄各檔案的最小值和最大值。`=` 與 `IN` 會在開啟檔案前跳過確定不含這些值的檔案。適用於可能值很多、只做等值查詢的欄位，例如請求 ID。 |
| `skip` | 記錄各檔案的最小值和最大值。如果檔案中不同的值不超過 32 個，也會記錄所有值。比較條件、`IN`、`BETWEEN` 與有固定前綴的 `LIKE` 可據此跳過檔案。 |
| `ngram` | 為每個檔案記錄值的三元組，並為檔案中每 1024 列的區塊記錄值的五位元組片段，不區分大小寫。如果 `LIKE`、`ILIKE` 或 `MATCH` 的字面值有三元組未出現在檔案中，就跳過該檔案；如果有片段未出現在區塊中，就跳過該區塊。因此，搜尋 ID 等少見字串時，只讀取可能包含該字串的區塊。字面值不足五個位元組時，會讀取所有區塊。含 `ngram` 欄位的資料串流會以每頁 1024 列寫入檔案。較小的頁面和片段都會占用儲存空間。在這類欄位占每列三分之二的測試中，儲存量增加約 14%。適用於依片段查詢的 URL、路徑和主機名稱，不適合大段自由格式文字。僅適用於 `utf8` 欄位。 |
| `ip` | 記錄各檔案的 IP 位址範圍，並將 IPv4 對應至 IPv6。`CIDR_MATCH(field, '10.0.0.0/8')` 與比對單一位址的 `=` 可據此跳過檔案。僅適用於 `utf8` 欄位。 |
| `key_value` | 記錄 JSON 物件第一層的鍵和值。`json_text(field, 'key') = 'value'`、`IN` 與 `IS NOT NULL` 會跳過不含指定鍵或值的檔案。符合條件的列很少時，只讀取這些列所在的頁面。依 `json_text` 傳回的形式比較值：文字維持原樣，數字與布林值採用其 JSON 表示形式。僅適用於 `json` 欄位。 |
| `range` | 在索引中記錄每列的數值，並記錄各檔案的最小值和最大值。如果 `count(*)` 的條件只包含 `exact` 欄位的 `=`、`range` 欄位與數字的 `>`、`>=`、`<`、`<=` 比較及時間範圍，系統會直接從索引取得結果，不讀取檔案。其他比較條件可據此跳過範圍外的檔案。僅適用於 `int64`、`float64` 與 `timestamp` 欄位。 |

已建立索引的欄位還會記錄各檔案中該欄位為空值的列數。`IS NULL` 會跳過該欄位每列都有值的檔案。該欄位的其他條件，包括 `IS NOT NULL` 與 `!= ''` 這類檢查是否有值的條件，會跳過該欄位全為空值的檔案。

如果 `OR` 連接的各個條件在同一檔案中都不可能成立，系統也會跳過該檔案。系統會使用適用的索引逐一判斷。例如，`level = 'error' OR status >= 500` 會跳過 `level` 索引中沒有 `error`，且 `status` 全部小於 500 的檔案。

傳入資料首次出現的欄位會依名稱取得索引類型：

| 資料串流類型 | 欄位 | 索引類型 |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`、`level`、`session_id`、`fingerprint`、`country`、`browser`、`application`、`environment` | `exact` |
| `traces` | `trace_id`、`span_id`、`parent_span_id`、`service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

其餘新欄位預設為 `none`，但資料串流另有設定規則時除外。請參閱[新欄位的索引](#新欄位的索引)。為 `level` 建立 `exact` 索引後，日誌直方圖可直接從索引統計錯誤數，不必讀取資料檔案。RUM 資料串流會使用 `key_value` 為 `context`、`feature_flags` 與 `usr.extra` 中的鍵建立索引。

修改索引類型後，系統會立即依新設定為後續寫入的資料建立索引，並在背景為先前寫入的資料補建索引。系統會使用各已封存分割區的檔案重建索引（預設在分割區結束 48 小時後封存），更新過的檔案則在封存或合併時重建索引。補建完成前，檔案會沿用寫入時的索引。查詢結果不受影響，但可能需要讀取更多檔案。**總覽** 中的 **索引欄位涵蓋率** 會顯示尚待補建的檔案數量。全文索引格式升級後（例如改用二元組處理中文、日文和韓文），系統也會以相同方式在背景依新格式重建舊檔案的索引。

若要修改欄位，請開啟 **欄位與索引**，按一下欄位的編輯按鈕，然後選擇：

- **索引類型**：**未建立索引**、**全文搜尋**、**精確比對**、**Bloom 篩選器**、**跳過索引**、**N-gram 子字串**、**IP 位址** 或 **JSON 鍵值**。全文搜尋、N-gram 子字串與 IP 位址僅適用於文字欄位，JSON 鍵值僅適用於 JSON 欄位；
- **傳回時套用欄位遮罩** 的 **資料流層級策略**：**繼承全域規則**、**自訂資料流規則** 或 **明確不遮罩此資料流的欄位**。請參閱[欄位遮罩](/zh-Hant/settings/data-security#欄位遮罩)。欄位遮罩不適用於指標資料串流。

按一下 **套用至草稿**，再按一下 **儲存並套用**。欄位類型不會變更。

### 新欄位的索引

在 **設定** 分頁的 **欄位索引** 中，可依欄位名稱為資料串流中首次出現的欄位選擇索引。按一下 **新增規則**，填寫欄位名稱模式，再選擇索引類型。`*` 可比對任意文字片段，`?` 可比對單一字元。例如，`*_id` 可比對 `user_id` 與 `order_id`，`http.*` 可比對 `http` 下的所有欄位。系統依序套用第一條名稱相符，且索引類型適用於欄位資料類型的規則。在 **欄位與索引** 中個別設定的索引優先。若沒有相符的規則，則依照上述預設規則。規則只適用於之後首次出現的欄位。若要修改現有欄位，請前往 **欄位與索引**。每個資料串流最多可設定 32 條規則。

### 依欄位分片

日誌與追蹤資料串流可依一或兩個文字欄位分片。在 **設定** 分頁的 **依欄位分片** 中按一下 **新增分片欄位**，選擇欄位，再選擇分片方式。之後寫入的資料會依欄位值分配到各個分片，每個分片各自寫入檔案。

- **雜湊**：依值的雜湊將資料平均分成 2 至 64 個分片。若查詢包含此欄位的等值條件（`=` 或 `IN`），就只會讀取指定值所在分片的檔案。
- **首字元**：依值的第一個字元分成 37 個分片。每個數字和英文字母各占一個分片（不區分大小寫），其他字元與空值共用一個分片。包含此欄位等值條件或有固定文字前綴的 `LIKE`（例如 `'web-%'`）的查詢，只會讀取首字元所在分片的檔案。`ILIKE` 還會讀取其他字元所在的分片。分布是否均勻取決於資料，例如十六進位追蹤 ID 只會用到其中 16 個分片。

使用兩個欄位時，系統會依兩個欄位的分片組合來分割檔案，總分片數為兩者相乘。**依欄位分片** 右側會顯示分片總數，上限為 256 個。首字元分片（37 個）與雜湊分片搭配時，雜湊最多可分成 4 個分片。查詢只要包含其中一個欄位的條件，就能少讀取一些檔案；若同時包含兩個欄位的條件，讀取的檔案會更少。適合用來分片的欄位幾乎每次查詢都會用到，例如服務、命名空間或租用戶。分片越多，檔案就越多、越小。

設定只影響之後寫入的資料。現有檔案維持原樣，查詢會依各檔案寫入時的分片欄位判斷，Compactor 也只會合併分片欄位相同的檔案。分片欄位必須是未加密的文字欄位，且兩個分片欄位不得相同。

### 依欄位叢集

日誌資料串流可依一或兩個欄位排列檔案中的資料列。在 **設定** 分頁的 **依欄位叢集** 中按一下 **新增叢集欄位**，選擇欄位，再選擇 **時間片**。之後寫入檔案的資料列會依指定長度的時間片排列，較新的時間片在前。每個時間片內先依這些欄位的值排序，再依時間由新到舊排列。

只依時間排列時，特定值（例如某個服務）會出現在檔案的每一頁。套用叢集後，每個時間片中只有少數幾頁含有該值。若查詢包含叢集欄位的等值條件（`=` 或 `IN`），就只會讀取這些頁面。適合用來叢集的欄位常用於查詢，且可能值不多，例如服務或層級。

每個套用叢集的檔案還會記錄每分鐘內，叢集欄位的各組值各有多少列。只含文字叢集欄位等值條件的計數、依其中一個欄位分組的計數（`GROUP BY service`），以及長條寬度為整數分鐘的直方圖，都可直接使用這些計數，不必讀取檔案。即使查詢時間範圍的起訖時間落在檔案涵蓋範圍內的整分鐘邊界，也適用。如果單一檔案的分鐘與欄位值組合超過 65,536 種，就不記錄這些計數。這些計數也能算出最新或最早一頁橫跨哪幾分鐘。擷取該頁時，無論是否包含叢集欄位的等值條件，都只讀取這幾分鐘的資料。

時間片可選 1、5 或 10 分鐘，預設為 1 分鐘。時間片越長，能跳過的頁面越多。不過，即使查詢時間範圍很短，也會完整讀取與該範圍重疊的時間片。

叢集與[依欄位分片](#依欄位分片)不同。分片會將各個分片寫入個別檔案，因此查詢讀取的檔案較少，但資料串流的檔案會更多、更小。叢集只調整檔案中的資料列順序，不會增加檔案數量。兩者可同時使用。

設定只影響之後寫入的資料。現有檔案會保留寫入時的順序，Compactor 只會合併叢集方式相同的檔案。叢集欄位必須是未加密的文字、`int64` 或 `bool` 欄位，且兩個叢集欄位不得相同。

### 加密欄位

建立資料串流時，將欄位標記為 `encrypted`。系統會在寫入 Parquet 前加密該欄位。儲存的欄只保留密文，一般查詢也只會傳回密文。在 SQL 中使用 `decrypt(field)` 讀取明文：

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

之後無法變更此旗標，否則將無法讀取現有資料。系統會使用組織加密金鑰與加密根金鑰 `MS_CIPHER_KEY` 衍生金鑰。遺失根金鑰後，將無法還原加密欄位。請參閱[安全性與多租用戶](/zh-Hant/security#欄位層級加密)。

## 保留與刪除

保留原則決定 Compactor 何時刪除資料。在 **保留原則** 分頁設定 **資料保留期限（天）**，留空則使用平台預設值 30 天。若要修改預設值，請前往 `_sys` 組織的[設定 → 資料保留](/zh-Hant/settings/platform#資料保留)。下次清理時會刪除超過保留期限的資料。縮短保留期限會使部分資料到期，這些資料也會一併刪除。刪除的檔案無法復原。若某項指標在保留期限內未再出現在指標資料串流中，也會從指標清單移除。

在指標資料串流的**保留原則**分頁，**對較早的樣本降取樣**會將串流中每項指標超過設定天數的樣本，依 1 分鐘到 1 天的時間區間彙總：同一時間序列在每個區間內的樣本合併為一個資料點，數值取平均，增量計數取總和，接著刪除原始樣本。查詢較長的時間範圍時，讀取的資料量會大幅減少，但較早的資料只保留到時間區間的精細度。原始樣本無法復原。

日誌與追蹤資料串流的**每日合併小檔案**設定（預設啟用）會在一天結束一小時後，將當天的檔案合併成一個檔案，前提是總大小不超過 Compactor 的 `[compactor].target_size`。跨多天的查詢只需開啟少得多的檔案。保留期限也會按天計算：整天的資料都到期後，才會刪除合併後的檔案。若要保留按小時切分的檔案，請在資料串流的**設定**分頁關閉這項設定。

**刪除資料串流** 會刪除資料串流及其設定，且無法復原。這項操作可能導致儀表板、已儲存的檢視、警示、報告及管線失效。刪除前請先查看 **使用位置** 分頁。

## 搜尋工作

搜尋工作是在背景執行的查詢，結果會保留到工作到期。工作有三個來源：

- 帶有 `Prefer: respond-async` 要求標頭的查詢，或預期結果太大而不適合以互動式要求執行的查詢；
- 管線回填；
- Mole Agent 提交的查詢。

在 **資料串流** 頁首選取 **搜尋工作**，開啟清單。清單頂端的檢視依狀態篩選，每個檢視都顯示工作數量：**全部**、**佇列中**、**執行中**、**已完成**、**失敗** 和 **已取消**。有工作在佇列中或執行中時，清單會自動重新整理。

每一列顯示工作的類型（**查詢** 或 **回填**）、陳述式、狀態、查詢時間範圍、提交時間、所需時間、結果列數、嘗試次數及到期時間。每個工作都有與狀態對應的操作：

| 狀態 | 操作 |
|---|---|
| 佇列中或執行中 | **取消工作** |
| 已完成 | **下載結果** |
| 失敗或已取消 | **重試** |

不論工作處於哪種狀態，都可以使用 **刪除** 移除工作及其結果。

成員可以查看及管理自行提交的工作。具備 `org.running_queries.cancel` 權限的管理員可以查看及管理組織內的所有工作。工作 API 請參閱[查詢](/zh-Hant/query#時間範圍與非同步工作)。

## 資料擷取用量與預算

在 **資料串流** 頁首選取 **資料擷取用量**，查看各個來源在最近 24 小時、7 天或 30 天內擷取的資料量。同一份資料以三種方式分類，各檢視的總計相同：

| 檢視 | 來源 |
|---|---|
| **憑證** | API Token、RUM 用戶端 Token、連接器或登入的使用者。**平台內部** 是平台本身的遙測資料。 |
| **資料串流** | 單一資料串流，依名稱和類型區分。 |
| **服務** | 事件在 `service.name` 中標註的服務；若未填寫，則取用 `service` 或 `service_name`。未標註的事件計入 **未標註的服務**。 |

資料擷取用量以要求解壓縮後所接收的資料位元組數計算。不計入遭拒絕的事件，傳送端重試的要求只計一次。Span 到達時即計入，早於尾端取樣。工作階段重播計入 **資料串流** 檢視的 `rum_replay` 列。如果同一個要求包含多個服務或資料串流，會依事件數量分攤位元組，因此各檢視顯示的是估算值。

未知的數值顯示為 `–`，而不是 0。帶有 `≥` 的數值是下限，表示計量在這段期間內才開始；清單上方會顯示開始時間。資料約在一分鐘內顯示在頁面上。如果節點異常停止，可能漏計最後 15 秒的用量。

選取一列，查看該來源每小時的用量趨勢，以及在另外兩個檢視中的用量明細。

### 設定預算

在單一列選取 **設定預算**，或勾選多列以套用相同的預算。

| 欄位 | 說明 |
|---|---|
| **週期** | **每天** 或 **每月**，按 UTC 日曆日或日曆月計算。 |
| **額度** | 1 MiB 到 1 PiB。 |
| **預警比例（%）** | 用量達到這個比例時提醒一次，用完額度時再提醒一次。填入 `0` 則只在用完額度時提醒。預設為 80。 |
| **通知對象** | 組織成員。預設為設定預算的成員。 |

預算只用於提醒。來源超出預算時，資料擷取的回應和儲存方式都不變，不會捨棄資料，也不會限制流量。每個門檻在同一個週期內只提醒一次。調高額度後若再次超出，則會再次提醒。

系統透過內建通知原則 **資料擷取預算即將用完** 和 **資料擷取超出預算** 傳送通知，也會在頂端列的通知中心顯示通知。若要調整其他通知對象或通知方式，請參閱[通知管道](/zh-Hant/notification-channels)。

`_sys` 組織沒有通知原則，因此無法設定預算。**平台內部**、**未標註的服務** 和 **其他服務** 也無法設定預算，其中 **其他服務** 是超出[平台設定](/zh-Hant/settings/platform#資料擷取用量)上限的服務。
