MoleSignal 提供版本化的 HTTP API。產品端點使用 `/api/v1`。健康探針、Prometheus 指標、公開共用連結和少數相容通訊協定也會使用其他路徑。

## 基礎 URL

本機執行個體：

```text
http://localhost:5080/api/v1
```

正式環境請將主機替換為部署的對外位址，也就是 `[http].external_url` 的值。

## 身分驗證

受保護的端點在 `Authorization` 請求標頭中接受 Bearer Token：

```http
Authorization: Bearer <token>
```

| Token | 取得方式 | 有效期限 |
|---|---|---|
| API Token | **個人設定 → API 權杖**，或[簽發 API Token](/zh-Hant/api/auth/issue-token)。格式如 `mspat-<36>`。 | 直到被撤銷，或到所選的到期時間。 |
| 預設接入 Token | `GET /api/v1/me/api-tokens/default`，僅限 `logs.write`、`metrics.write`、`traces.write`、`profiles.write` 和 `apm.deploy`。 | 不會過期。 |
| RUM 用戶端 Token | `GET /api/v1/auth/tokens/rum?applicationId=<id>`，僅限 `rum.write`。 | 不會過期。 |

指令碼和收集器請使用 API Token。接入 Token 的細節請參閱[資料來源](/zh-Hant/intake#接入權杖)。

Web 介面透過 `POST /api/v1/auth/signin` 登入，它會寫入工作階段 Cookie，不傳回 Token。`Authorization` 請求標頭不接受工作階段 Token，請參閱[登入](/zh-Hant/api/auth/login)。

身分驗證會產生包含主體、目前組織或平台範圍，以及實際生效權限的 IAM 情境。請求所屬的組織一律來自這個情境，請求內文無法選擇其他組織。

## 公開與自我驗證路由

少數路由無法使用組織的 Bearer Token，而是改為驗證範圍更窄的憑證或原則：

- 登入、註冊原則與密碼重設；
- `GET /api/v1/healthz` 與頂層的 `/metrics`；
- 公開資源共用的交換與共用工作階段請求；
- 簽章檔案下載與公開頭像；
- 推送型連接器端點，它們會驗證推送 Token。

公開路由並非毫無限制。對應的處理邏輯會檢查註冊原則、共用 Token、下載 Token、簽章或連接器憑證。

## 授權

一個端點可能要求下列一或多個條件：

- 組織權限，例如 `streams.query`；
- 平台權限，例如 `sys.telemetry.read`；
- 對資源的所有權、與資源的關係，或跨組織授權。

`GET /api/v1/iam/capabilities` 會傳回目前主體實際生效的權限。不要根據角色名稱或可見的選單項目推斷存取能力。

## 請求

- 大多數請求內文是 JSON，使用 `Content-Type: application/json`。
- 相容類接入端點使用各自通訊協定的承載資料，例如 Protobuf、NDJSON 或 gzip 壓縮的請求內文。
- 超過 2 MiB 的接入請求內文會被拒絕並傳回 `413`；原生 JSON 接入的上限是 16 MiB。
- 時間是自 Unix 紀元起的微秒整數。時間點依發生的事件命名（`createdAt`、`expiresAt`），只有一個詞無法清楚表達時加上 `Time`（`startTime`）；時長以 `Time` 結尾（`p95Time`），名稱本身就是時長的不加（`duration`）。原生遙測記錄使用 `_timestamp`，同樣以微秒計。
- 路徑中的 id 和資料流名稱需要進行 URL 編碼。

## 回應與錯誤

成功的回應是 JSON，除非端點以串流或檔案的形式傳回。錯誤回應包含狀態碼，以及帶有機器可讀 `error` 碼和 `message` 的 JSON 回應內文：

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

`validation_failed` 錯誤還會附帶 `issues` 陣列，每個無效欄位一項。

| 狀態碼 | `error` | 意義 |
|---|---|---|
| `400` | `invalid_argument`、`validation_failed` | 請求或其中某個參數無效。 |
| `401` | `unauthorized` | Token 缺少、格式錯誤、無效或已過期。 |
| `403` | `forbidden` | 缺少權限、關係或範圍。 |
| `404` | `not_found` | 資源不存在，或在授權範圍內不可見。 |
| `409` | `conflict` | 狀態或唯一性衝突。 |
| `413` | `payload_too_large` | 請求內文超出限制。 |
| `429` | `resource_exhausted` | 已觸發速率限制，如果有 `Retry-After` 回應標頭，請遵循它。 |
| `499` | `cancelled` | 請求已取消。 |
| `503` | `unavailable` | 相依性不可用。 |
| `500` | `internal` | 內部故障。回應內文中的 message 為 `internal error`，詳細資訊只保留在伺服器端日誌中。 |

請求內文無法解析時，請求會在到達端點之前就失敗，此時的回應是純文字而不是 JSON：

| 狀態碼 | 意義 |
|---|---|
| `400` | 請求內文不是有效的 JSON。 |
| `415` | 請求缺少 `Content-Type: application/json`。 |
| `422` | 欄位缺少或型別錯誤，文字中會指出欄位名稱。 |

每個回應都帶有 `X-Request-Id` 與 `X-Trace-Id` 回應標頭。回報伺服器端故障時請同時提供這兩個值。

## 分頁

可能傳回大量資料列的端點接受 `limit` 與 `cursor`，這類回應包含 `items` 與 `nextCursor`。將 `nextCursor` 作為 `cursor` 傳回即可讀取下一頁，為空時停止。其他清單端點會傳回完整清單，詳見各端點頁面。

## 查詢與長時間執行任務

查詢系列介面會傳回一般 JSON、以串流形式傳回 NDJSON，並將耗時較長的查詢作為非同步搜尋任務執行。規模過大的查詢會傳回 `202`，並帶有 `jobId` 與 `monitor` 路徑。串流呼叫端需要處理部分資料到達的情況，並在不再需要結果時取消請求，請參閱[查詢](/zh-Hant/query)。

產生的報告、Profile 資料區塊和匯出檔案等大容量產物，會透過限定範圍的下載 Token 以檔案形式交付，而不是放在 JSON 回應內文中。
