API 토큰을 사용하면 프로그램이 로그인하지 않고 MoleSignal을 호출할 수 있습니다. 토큰에는 자체 역할이 없습니다.
토큰은 멤버나 서비스 계정으로 동작하며, 범위를 설정해 수행할 수 있는 작업을 제한할 수 있습니다. 서비스 계정은
프로그램용 ID입니다. 서비스 계정은 로그인할 수 없고 역할을 가지며, 해당 토큰은 서비스 계정으로 동작합니다.

## 토큰 유형

| 유형 | 동작 주체 | 발급 위치 |
|---|---|---|
| **개인 API 토큰** | 토큰을 발급한 멤버입니다. | **계정 설정 → API 토큰** |
| **서비스 계정 API 토큰** | 서비스 계정입니다. | **ID 및 액세스 → API 토큰** 또는 **서비스 계정** |
| **기본 데이터 수집 토큰** | 토큰 소유자입니다. 데이터 쓰기만 가능합니다. | **데이터 소스**. [데이터 수집 토큰](/ko/intake#수집-토큰)을 참조합니다. |
| **RUM 클라이언트 토큰** | 토큰이 속한 RUM 애플리케이션입니다. RUM 데이터 쓰기만 가능합니다. | **데이터 소스**. [데이터 수집 토큰](/ko/intake#수집-토큰)을 참조합니다. |

모든 토큰은 영문 소문자와 숫자로 구성된 `mspat-<36>` 형식입니다. 처음 10자로
토큰을 찾고, 나머지 문자는 해시만 저장합니다. 토큰을 Bearer 인증 정보로 전송합니다.

```http
Authorization: Bearer mspat-…
```

토큰으로는 `_sys` 조직에 액세스할 수 없습니다.

## 토큰으로 수행할 수 있는 작업

토큰은 요청 시점에 해당 멤버나 서비스 계정이 수행할 수 있는 작업만 수행할 수 있습니다.
토큰 범위는 수행할 수 있는 작업을 더 제한합니다.

| 범위 | 토큰이 사용할 수 있는 권한 |
|---|---|
| **내 권한과 동일**, **서비스 계정 권한과 동일** | 해당 멤버나 서비스 계정의 모든 권한입니다. 멤버나 서비스 계정의 권한이 바뀌면 토큰의 권한도 바뀝니다. |
| **권한 정책** | **데이터 수집**과 같은 [권한 정책](/ko/identity/roles#권한-정책)의 권한입니다. 정책이 바뀌면 토큰의 권한도 바뀝니다. |
| **사용자 지정** | 발급할 때 선택한 권한입니다. 선택한 권한 목록은 바뀌지 않습니다. |

발급자에게 없는 권한은 토큰에 부여할 수 없습니다. 멤버가 권한을 잃으면 해당 멤버의 모든
토큰도 그 권한을 잃습니다. 멤버가 워크스페이스를 떠나거나 비활성화되면 해당 멤버의 토큰은
작동을 멈춥니다. 액세스 권한 부여나 공유를 통해 개별 리소스에 부여된 역할은 토큰 범위 내에서만
적용됩니다. RUM 클라이언트 토큰은 해당 애플리케이션에 속하며, RUM 데이터 쓰기 외에는
아무 작업도 수행할 수 없습니다.

## 개인 토큰 발급

1. **계정 설정 → API 토큰**을 열고 **새 토큰**을 선택합니다.
2. **이름**을 입력합니다(예: `collector-production`).
3. **범위**에서 **내 권한과 동일**, **권한 정책**, **사용자 지정** 권한 중 하나를 선택합니다.
   보유하지 않은 정책이나 권한은 선택할 수 없습니다. 정책을 선택하면 해당 정책에 포함된
   권한 목록이 표시됩니다.
4. **만료까지 남은 일수**를 설정합니다. 기본값은 365일이고 최댓값은 1825일입니다. 만료되지 않는 토큰을 만들려면
   비워 둡니다.
5. **토큰 생성**을 선택한 다음 **토큰 복사**를 선택합니다. 토큰은 이때 한 번만 표시됩니다.

목록에는 토큰의 범위, 유형, 만료 시점, 마지막 사용 시점이 표시됩니다. **취소**를 선택하면
토큰이 즉시 영구적으로 비활성화됩니다. 개인 토큰을 관리하려면 `personal_tokens.manage` 권한이 필요합니다. 모든 기본 제공
역할에 이 권한이 있습니다. 개인 토큰은 로그인한 세션에서 발급합니다. 토큰으로 다른 토큰을 발급할 수 없습니다.

## 조직 토큰

**ID 및 액세스 → API 토큰**에는 워크스페이스의 모든 토큰과 각 토큰이 대신하는 멤버, 서비스
계정 또는 애플리케이션, 그리고 토큰의 범위가 표시됩니다. 목록을 조회하려면 `api_tokens.read` 권한이 필요합니다.
`api_tokens.revoke` 권한이 있으면 모든 토큰을 취소할 수 있습니다. 서비스 계정에 토큰을 발급하려면 **서비스 계정 토큰 발급**을 선택한 후
**서비스 계정**, **범위**, 만료 기간을 지정합니다.

## 서비스 계정

사람의 개입 없이 실행되는 수집기, CI 파이프라인, 통합 또는 AI 에이전트에는
서비스 계정을 사용합니다. 그러면 멤버가 워크스페이스를 떠나도 자동화가 중단되지 않습니다.

1. **서비스 계정**을 열고 **서비스 계정 생성**을 선택합니다.
2. **이름**(예: `deployment-automation`)과 **설명**을 입력하고 **역할**을 선택합니다.
3. **계정 및 토큰 생성**을 선택하고 처음 발급된 API 토큰을 복사합니다. 이 토큰은
   생성 시점의 역할 권한을 가지며 365일 후에 만료됩니다. 토큰은 한 번만 표시됩니다.

관리할 계정을 선택합니다.

| 작업 | 효과 |
|---|---|
| **변경 사항 저장** | 변경한 이름, 설명 또는 역할을 저장합니다. 새 역할에서 빠진 권한은 계정의 모든 토큰에서 즉시 사라집니다. 새로 추가된 권한은 변경 이후 발급하는 토큰에만 적용됩니다. |
| **API 토큰 관리** | 해당 계정의 토큰만 표시하는 **API 토큰** 목록을 엽니다. 여기서 토큰을 추가로 발급하거나 취소할 수 있습니다. |
| **비활성화** / **활성화** | 비활성화된 계정과 해당 계정의 모든 토큰은 계정을 다시 활성화할 때까지 인증할 수 없습니다. |
| **삭제** | 계정을 삭제하고 해당 계정의 모든 토큰을 취소합니다. 이 작업은 되돌릴 수 없습니다. |

감사 기록과 액세스 권한 부여 내역에서는 계정의 **주체 ID**로 계정을 식별합니다. 서비스 계정을
조회하려면 `service_accounts.read` 권한이 필요하고, 변경하려면 `service_accounts.manage` 권한이 필요합니다.

## 토큰 선택

| 호출 주체 | 권장 토큰 |
|---|---|
| 텔레메트리를 전송하는 수집기 또는 에이전트 | **데이터 수집** 정책을 따르는 서비스 계정 토큰 또는 기본 데이터 수집 토큰입니다. |
| RUM 데이터를 전송하는 브라우저 또는 모바일 코드 | 애플리케이션의 RUM 클라이언트 토큰입니다. 최종 사용자에게 노출됩니다. |
| 배포를 보고하는 CI | `apm.deploy` 권한도 포함하는 **데이터 수집** 정책을 따르는 토큰입니다. |
| 데이터를 읽거나 리소스를 변경하는 자동화 | 정책 또는 사용자 지정 권한으로 범위를 제한한 서비스 계정 토큰입니다. |
| MCP 클라이언트 또는 사람이 실행하는 스크립트 | 만료 기간을 설정한 개인 API 토큰입니다. |

로그인 세션은 브라우저의 HttpOnly 쿠키에 저장되며 기본적으로 24시간 후에 종료됩니다
(`[auth].session_ttl_secs`). `Authorization` 헤더로 세션을 전달할 수 없으므로 프로그램은 항상
API 토큰을 사용합니다.

## 토큰 API

| 작업 | 엔드포인트 | 권한 |
|---|---|---|
| 개인 토큰 발급 | `POST /api/v1/me/api-tokens` | `personal_tokens.manage` |
| 개인 토큰 목록 조회 | `GET /api/v1/me/api-tokens` | `personal_tokens.manage` |
| 개인 토큰 취소 | `DELETE /api/v1/me/api-tokens/{id}` | `personal_tokens.manage` |
| 토큰 범위를 제한하는 데 사용할 수 있는 권한 정책 및 조직 권한 목록 조회 | `GET /api/v1/me/api-tokens/scopes` | 로그인한 멤버 |
| 서비스 계정 토큰 발급 | `POST /api/v1/auth/tokens` | `api_tokens.revoke` |
| 모든 토큰 목록 조회 | `GET /api/v1/auth/tokens` | `api_tokens.read` |
| 임의의 토큰 취소 | `DELETE /api/v1/auth/tokens/{id}` | `api_tokens.revoke` |

[API 토큰 발급](/ko/api/auth/issue-token), [API 토큰 목록 조회](/ko/api/auth/list-tokens),
[API 토큰 취소](/ko/api/auth/revoke-token)를 참조합니다.
