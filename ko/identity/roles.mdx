역할은 이름이 지정된 권한 집합입니다. 권한 정책도 이름이 지정된 권한 집합이지만, 여러
역할에 연결하고 API 토큰에도 적용할 수 있도록 별도로 관리합니다. 워크스페이스 전체에 적용되는 역할은
[사용자](/ko/identity/members#사용자)에서 멤버에게 할당합니다. 액세스 권한 부여를 사용하면 사용자나 팀에
조직 전체 또는 선택한 리소스에 대한 역할을 부여하고, 필요에 따라 만료 일시를 지정할 수 있습니다. **ID 및 액세스 →
역할**, **권한 정책** 또는 **액세스 권한 부여**를 엽니다.

## 역할

**역할**에는 워크스페이스의 기본 제공 역할과 사용자 지정 역할이 표시됩니다. 각 역할에 연결된 정책,
부여하는 권한, 사용처(멤버, 서비스 계정, 초대,
바인딩)도 표시됩니다. 기본 제공 역할은 읽기 전용입니다. [기본 제공 역할](/ko/identity#기본-제공-역할)을 참조합니다.

사용자 지정 역할을 만들려면 다음 단계를 따릅니다.

1. **새 역할**을 선택합니다.
2. 영문 소문자, 숫자, 밑줄로 구성된 **키**를 입력합니다. 나중에 변경할 수 없습니다.
3. **이름**과 **설명**을 입력합니다.
4. **권한 정책**에서 역할에 연결할 정책을 선택합니다. 역할에는 연결된 정책의 모든
   권한이 부여되며, 정책이 변경되면 권한에도 변경 사항이 반영됩니다.
5. **직접 부여한 권한**에서 정책 외에 역할에 필요한 권한을 선택합니다. 각
   권한에는 허용하는 작업이 표시됩니다. 선택한 정책에서 부여하는 권한은 이미 선택되어 있으며, 해당
   정책 이름이 함께 표시됩니다. 여기서는 이러한 권한을 선택 해제할 수 없습니다.
6. **역할 만들기**를 선택합니다.

역할은 직접 부여한 권한과 연결된 정책의 권한을 모두 부여합니다. 두 항목 중 하나를 변경하려면 사용자 지정 역할을 선택합니다.
사용자 지정 역할을 사용하는 멤버십, 서비스 계정,
초대 또는 바인딩이 없을 때만 **삭제**로 역할을 삭제할 수 있습니다. 역할을 조회하려면 `iam.roles.read`, 변경하려면
`iam.roles.manage`, 삭제하려면 `iam.roles.delete` 권한이 필요합니다.

## 권한 정책

**권한 정책**에는 워크스페이스의 기본 제공 정책과 사용자 지정 정책이 표시됩니다. 각 정책의
권한과 해당 정책을 사용하는 역할 및 토큰도 표시됩니다. 역할에는 정책을 연결할 수 있으며, API
토큰에는 정책 하나를 적용할 수 있습니다. [토큰이 허용하는 작업](/ko/identity/tokens#토큰으로-수행할-수-있는-작업)을 참조합니다.

| 기본 제공 정책 | 권한 |
|---|---|
| **읽기 전용 관찰자** | 관측성 데이터, 대시보드, 알림, 일정, 저장된 보기, 파이프라인, 함수, 보고서, 상태 페이지, 합성 모니터링, 서비스 수준 및 사후 분석을 조회합니다. |
| **데이터 분석가** | 관측성 데이터를 탐색하고 대시보드와 저장된 보기를 만듭니다. |
| **파이프라인 개발자** | 관측성 데이터를 조회하고 스트림, 파이프라인 및 함수를 관리합니다. |
| **알림 관리자** | 관측성 데이터를 조회하고 알림 규칙, 일정, 상태 페이지, 합성 모니터링 및 사후 분석을 관리합니다. |
| **조직 관리자** | 조직 설정, 멤버, 역할, 액세스 권한 부여, API 토큰, 서비스 계정, 감사 기능뿐 아니라 상태 페이지, 합성 모니터링, 서비스 수준 및 사후 분석도 관리합니다. |
| **데이터 수집** | `logs.write`, `metrics.write`, `traces.write`, `profiles.write`, `apm.deploy` 권한으로 데이터를 쓰고 배포를 보고합니다. 수집 토큰에는 이 정책이 적용됩니다. |

기본 제공 정책은 읽기 전용이며 제품 변경 사항을 따릅니다. 기본 제공 정책을 열고 **사용자 지정
정책으로 복사**를 선택하면 해당 정책을 바탕으로 사용자 지정 정책을 만들 수 있습니다.

사용자 지정 정책을 만들려면 다음 단계를 따릅니다.

1. **새 정책**을 선택합니다.
2. **이름**, 영문 소문자, 숫자, 밑줄로 구성되며 나중에 변경할 수 없는 **키**,
   **설명**을 입력합니다.
3. **권한**에서 **시각적 편집**으로 권한을 선택하거나 **JSON**으로 문서를 작성합니다.
   두 방식 모두 같은 문서를 편집합니다. JSON 편집기는 첫 번째 오류와 그 위치를 표시합니다.
   문서가 유효하면 저장하기 전에 허용되는 권한을 나열합니다.
4. **정책 생성**을 선택합니다.

정책 문서는 AWS IAM 정책 언어를 기반으로 작성합니다.

```json
{
  "Version": "1",
  "Statement": [
    { "Sid": "Dashboards", "Effect": "Allow", "Action": "dashboards.*" },
    { "Effect": "Allow", "Action": ["streams.read", "streams.query"] }
  ]
}
```

- `Version`은 `"1"`이며 정책은 하나 이상의 권한을 허용해야 합니다.
- `Effect`는 항상 `"Allow"`입니다. 정책은 허용만 지원하며 거부는 지원하지 않습니다.
- `Action`은 권한 하나 또는 권한 목록입니다. `*`는 임의의 문자열과 일치하므로
  `dashboards.*`는 모든 대시보드 권한을, `*`는 모든 조직 권한을 나타냅니다. 어떤 권한과도
  일치하지 않는 작업은 허용하지 않습니다.
- `Sid`는 구문의 선택적 이름입니다.
- `Resource`, `Condition`, `Principal`, `NotAction`은 지원하지 않습니다. 정책은 조직
  전체에 적용됩니다. 개별 리소스에 역할을 부여하거나 조건을 적용하려면
  [액세스 권한 부여](#액세스-권한-부여)를 사용합니다.

정책을 저장하면 저장 시점에 문서가 허용하는 권한이 기록됩니다. 패턴은 나중에 권한 카탈로그에
추가되는 권한에도 적용됩니다. 해당 권한은 MoleSignal이 시작될 때 정책에 추가됩니다. **시각적 편집**에서
권한을 선택하면 패턴, `Sid` 또는 여러 구문이 포함된 문서를 개별 권한을 나열하는 단일 구문으로
다시 작성합니다. 다시 작성하기 전에 이를 알립니다.

정책을 변경하면 해당 정책을 연결한 모든 역할과 해당 정책이 적용된 모든 토큰에 변경 사항이 즉시 반영됩니다.
정책을 연결한 역할이 없고 해당 정책이 적용된 유효한 토큰도 없을 때만 **삭제**로 사용자 지정 정책을 삭제할 수 있습니다.
해당 정책이 적용됐던 토큰이 취소되거나 만료된 경우, 기존 권한은 목록으로 유지됩니다. 정책을 조회하려면
`iam.policies.read`, 변경하려면 `iam.policies.manage`, 삭제하려면 `iam.policies.delete` 권한이 필요합니다.

## 액세스 권한 부여

액세스 권한 부여는 조직 내 특정 리소스 범위에서 보안 주체에 역할을 연결하는 역할
바인딩입니다. 광범위한 역할의 권한을 늘리는 대신, 특정 사용자, 팀 또는 리소스에 맞춰 액세스를
부여해야 할 때 사용합니다.

1. **액세스 권한 부여**를 열고 **새 액세스 권한 부여**를 선택합니다.
2. **보안 주체**: **사용자** 또는 **팀**을 고른 뒤 대상을 선택합니다.
3. **조직**: 현재 워크스페이스를 참고용으로 표시합니다.
4. **리소스 범위**: **조직 전체**를 선택하거나, 리소스 유형(**대시보드** 또는 **스트림**)을 선택한 뒤
   리소스 하나 또는 **이 유형의 모든 리소스**를 선택합니다.
5. **역할 및 권한**: 부여할 역할을 선택합니다.
6. **제약 조건**: 필요에 따라 요청과 정확히 일치해야 하는 **환경**(예: `prod`)과
   **만료 일시**를 지정합니다.
7. **액세스 권한 부여**를 선택합니다.

**삭제**를 선택하면 부여된 액세스 권한이 즉시 종료됩니다. 부여 내역을 조회하려면 `iam.grants.read`,
액세스 권한을 부여하거나 삭제하려면 `iam.grants.manage` 권한이 필요합니다.

## 조직 간 리소스 공유

조직 간 공유를 사용하면 현재 조직에서 선택한 리소스에 다른 조직이 액세스할 수 있습니다.
공유 범위는 명시적으로 지정한 조직과 리소스로 제한되며,
공유 권한은 상속되거나 다른 조직으로 전달되지 않습니다.

1. **액세스 권한 부여**에서 **조직 간 공유**를 선택합니다.
2. **대상 조직**을 선택합니다.
3. 리소스 유형(**대시보드** 또는 **스트림**)과 공유할 리소스를 선택합니다.
4. 권한을 선택합니다. 대시보드에는 `dashboards.read`와 `dashboards.edit`를, 스트림에는 `streams.read`와
   `streams.query`를 선택합니다.
5. 필요에 따라 **만료 일시**를 지정한 뒤 **공유 생성**을 선택합니다.

공유는 **수락 대기 중** 상태로 시작합니다. 대상 조직의 관리자가 해당 조직의
**액세스 권한 부여**에서 **수락**을 선택하면 공유가 **활성** 상태가 됩니다. 어느 조직에서든 **취소**를 선택해
공유를 종료할 수 있습니다. 공유를 생성, 수락 또는 취소하려면 `iam.cross_org.manage` 권한이 필요합니다.

## 권한 참조

카탈로그의 모든 권한과 각 권한으로 할 수 있는 작업, 해당 권한이 있는 기본 제공 역할을 설명합니다. 사용자 지정 역할과
정책은 조직 권한을 자유롭게 조합할 수 있습니다. 모듈의 탭에는 해당 역할로 열 수 있는 페이지가 표시되며,
모듈은 그중 첫 번째 페이지를 엽니다. 따라서 페이지 하나에 대한 권한만 있어도 모듈에 접근할 수 있습니다.

### 플랫폼

| 권한 | 허용되는 작업 | 기본 제공 역할 |
|---|---|---|
| `sys.administrators.manage` | 플랫폼 역할과 정책을 만들고 계정에 부여합니다. 보유하지 않은 권한은 부여할 수 없습니다. | `platform_admin` |
| `sys.administrators.read` | 플랫폼 역할, 정책, 권한 부여 내역을 조회하고 계정을 검색합니다. | `platform_admin`, `platform_viewer` |
| `sys.clusters.manage` | 원격 클러스터와 조직 매핑을 추가, 변경, 제거합니다. | `platform_admin` |
| `sys.clusters.read` | 원격 클러스터와 해당 노드, 매핑된 조직의 목록을 조회합니다. | `platform_admin`, `platform_viewer` |
| `sys.dashboards.read` | 시스템 조직의 읽기 전용 대시보드를 열어 봅니다. | `platform_admin`, `platform_viewer` |
| `sys.nodes.drain` | 노드를 서비스 대상에서 제외합니다. | `platform_admin` |
| `sys.nodes.read` | 현재 노드가 드레이닝 중인지 확인합니다. | `platform_admin`, `platform_viewer` |
| `sys.organizations.create` | 새 조직을 만듭니다. 조직을 만든 계정이 첫 번째 소유자가 됩니다. | `platform_admin` |
| `sys.organizations.delete` | 조직과 조직 내 모든 항목을 삭제합니다. | `platform_admin` |
| `sys.organizations.disable` | 조직을 비활성화하거나 활성화합니다. 비활성화된 조직에는 접근할 수 없습니다. | `platform_admin` |
| `sys.organizations.read` | 플랫폼의 조직 목록을 조회합니다. | `platform_admin`, `platform_viewer` |
| `sys.organizations.update` | 조직 이름을 변경합니다. | `platform_admin` |
| `sys.query.admission.manage` | 쿼리 실행 허용 할당량을 변경합니다. | `platform_admin` |
| `sys.query.admission.read` | 쿼리 실행 허용 할당량과 사용량을 조회합니다. | `platform_admin`, `platform_viewer` |
| `sys.settings.alerting.manage` | 플랫폼 전체의 경보 규칙 평가 방식을 변경합니다. | `platform_admin` |
| `sys.settings.alerting.read` | 플랫폼 전체의 경보 규칙 평가 방식을 조회합니다. | `platform_admin`, `platform_viewer` |
| `sys.settings.limits.manage` | 시계열 한도, APM 한도, 수집 사용량 설정을 변경합니다. | `platform_admin` |
| `sys.settings.limits.read` | 시계열 한도, APM 한도, 수집 사용량 설정을 조회합니다. | `platform_admin`, `platform_viewer` |
| `sys.settings.retention.manage` | 스트림, 감사 기록, 신세틱 결과, 스토리지 카탈로그 이력의 보존 기간을 변경합니다. | `platform_admin` |
| `sys.settings.retention.read` | 스트림, 감사 기록, 신세틱 결과, 스토리지 카탈로그 이력의 기본 보존 기간을 조회하고, 기간을 줄이면 삭제되는 항목을 미리 봅니다. | `platform_admin`, `platform_viewer` |
| `sys.settings.signin.manage` | 로그인 요구 사항 및 제한, 셀프서비스 가입, 클라이언트 IP 감지 설정을 변경합니다. | `platform_admin` |

## 역할, 정책 및 액세스 권한 부여 API

| 작업 | 엔드포인트 | 권한 |
|---|---|---|
| 권한 카탈로그 조회 | `GET /api/v1/iam/permissions` | `iam.roles.read` 또는 `iam.policies.read` |
| 역할 목록 조회 | `GET /api/v1/roles` | `iam.roles.read` |
| 사용자 지정 역할 생성 | `POST /api/v1/roles` | `iam.roles.manage` |
| 사용자 지정 역할 업데이트 | `PATCH /api/v1/roles/{id}` | `iam.roles.manage` |
| 사용하지 않는 사용자 지정 역할 삭제 | `DELETE /api/v1/roles/{id}` | `iam.roles.manage` |
| 권한 정책 목록 또는 단일 정책 조회 | `GET /api/v1/iam/policies`, `GET /api/v1/iam/policies/{id}` | `iam.roles.read` |
| 사용자 지정 정책 생성 | `POST /api/v1/iam/policies` | `iam.roles.manage` |
| 사용자 지정 정책 업데이트 | `PATCH /api/v1/iam/policies/{id}` | `iam.roles.manage` |
| 사용하지 않는 사용자 지정 정책 삭제 | `DELETE /api/v1/iam/policies/{id}` | `iam.roles.manage` |
| 액세스 권한 부여 항목 목록 조회 또는 생성 | `GET /api/v1/iam/role-bindings`, `POST /api/v1/iam/role-bindings` | `iam.policies.read`, `iam.policies.manage` |
| 액세스 권한 부여 항목 삭제 | `DELETE /api/v1/iam/role-bindings/{id}` | `iam.policies.manage` |
| 조직 간 공유 목록 조회 또는 생성 | `GET /api/v1/iam/cross-org-grants`, `POST /api/v1/iam/cross-org-grants` | `iam.policies.read`, `iam.policies.manage` |
| 공유 수락 또는 취소 | `POST /api/v1/iam/cross-org-grants/{id}/accept`, `POST /api/v1/iam/cross-org-grants/{id}/revoke` | `iam.policies.manage` |

역할 요청 본문에는 역할에 직접 지정한 `permissions`와 연결한 정책의 `policyIds`가 포함됩니다. 응답에는 역할이 부여하는 모든 권한을 담은
`effectivePermissions`가 추가됩니다. 정책 요청 본문에는 `key`(생성 시에만),
`name`, `description`, `document`가 포함됩니다. 응답에는 `builtin`, 정책에서 계산한 `permissions`,
그리고 정책을 연결한 역할과 정책을 따르는 활성 토큰을 담은 `usage`가 추가됩니다. 유효하지 않은 문서를 보내면 API는
`400`과 함께 다음 예와 같이 오류 위치를 반환합니다.
``Statement[0].Action[1]: no permission is called `alerts.rules.reed` ``. 아직 사용 중인 정책을 삭제하려고 하면 API는
`409`를 반환합니다.
