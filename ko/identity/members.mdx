**ID 및 액세스 → 사용자**, **초대** 또는 **승인**을 엽니다. 멤버 목록을 보려면
`org.members.read` 권한이 필요합니다. 이 페이지에서 변경하려면 모두 `org.members.update` 권한이 필요합니다. 이
권한이 없는 멤버도 서로의 이름과 프로필 사진을 볼 수 있습니다. 인시던트, 일정, 에스컬레이션 정책에서
멤버를 이름으로 표시하고 선택하기 때문입니다. 이메일, 역할, 팀, 로그인 방식, 활동을 보려면
`org.members.read` 권한이 필요합니다.

## 사용자

**사용자**에는 현재 워크스페이스의 멤버가 표시됩니다. 상단에는 전체 사용자 수, 활성 사용자 수,
승인 대기 중인 사용자 수가 표시됩니다. 이름, 이메일 또는 팀으로 검색하고 역할이나 상태로 필터링할 수 있습니다.

| 열 | 표시 내용 |
|---|---|
| **역할** | 현재 워크스페이스에서 멤버가 맡은 역할입니다. |
| **팀** | 멤버가 속한 [팀](/ko/identity/teams#팀)입니다. |
| **로그인 방식** | **비밀번호**, **OIDC** 또는 **SAML**입니다. |
| **마지막 활동** | 마지막 로그인 시각 또는 **로그인 이력 없음**을 표시합니다. |
| **상태** | **활성**, **비활성화됨**, **대기 중**(승인 대기) 또는 **거부됨**입니다. |

행 끝에 있는 메뉴를 열어 다음 작업을 수행합니다.

| 작업 | 효과 |
|---|---|
| **세부 정보 보기** | 멤버의 ID 정보, 멤버십, 액세스 상태를 표시합니다. |
| **역할 변경** | 현재 워크스페이스에서 멤버의 역할을 기본 제공 역할 또는 [사용자 지정 역할](/ko/identity/roles#역할)로 설정합니다. |
| **사용자 비활성화** | 계정이 모든 워크스페이스에 로그인할 수 없게 됩니다. 멤버십과 구성은 유지됩니다. **사용자 활성화**를 선택하면 다시 로그인할 수 있습니다. |
| **멤버 제거** | 멤버가 현재 워크스페이스에 대한 액세스 권한을 즉시 잃습니다. 계정 자체는 유지됩니다. |
| **승인** | 승인 대기 중인 사용자에게 표시됩니다. [승인](#승인)을 참조합니다. |

다음 변경은 허용하지 않습니다.

- 본인의 역할을 변경하거나 본인 계정을 비활성화하거나 현재 워크스페이스에서 본인을
  제거할 수 없습니다.
- 루트 사용자는 처음 시작할 때 `[auth].root_email`을 기준으로 생성하는 계정입니다.
  조직 관리자는 이 계정을 변경할 수 없습니다.
- 마지막으로 남은 플랫폼 관리자는 비활성화하거나 삭제할 수 없습니다.

다른 워크스페이스로 전환하면 해당 조직의 새 세션을 발급합니다. 조직 이름이 바뀌어도 조직의
ID와 슬러그는 바뀌지 않습니다.

## 승인

워크스페이스의 [가입 정책](/ko/settings/organization#가입-및-액세스)에서 직접 가입을 허용하고
관리자 승인을 요구하면 새 계정은 **승인**에서 대기합니다.
상단 표시줄의 **알림** 종 아이콘에도 새 가입 요청이 표시됩니다.

- **승인**을 선택하면 계정이 활성화됩니다.
- **거부**를 선택하면 계정 상태가 거부됨으로 바뀝니다. 거부된 계정은 로그인할 수 없으며 이 페이지에서
  결정을 되돌릴 수 없습니다.

SMTP를 구성하면 MoleSignal은 워크스페이스의 관리자에게 새 가입 요청을 이메일로 알리고
가입 신청자에게는 승인 또는 거부 결과를 이메일로 알립니다. 이메일은 워크스페이스의 기본 언어로 보냅니다.
이메일 전송에 실패해도 가입이나 승인 또는 거부 처리는 진행됩니다.

## 초대

**초대**는 이메일 주소와 초대 대상에게 부여할 역할을 기록합니다. 대기 중인 초대 목록에는
역할, 상태, 발송 시각, 초대한 사용자가 표시됩니다.

1. **사용자 초대**를 선택합니다.
2. **이메일**을 입력합니다. 워크스페이스에 [이메일 도메인](/ko/identity/sso#이메일-도메인)이 설정되어 있으면
   주소는 해당 도메인 중 하나에 속해야 합니다.
3. **역할**을 선택하거나, 직접 가입 시 부여하는 **조직 기본 역할**을 유지합니다.
4. **초대 보내기**를 선택합니다.

**다시 보내기**는 대기 중인 초대를 다시 보낸 것으로 표시하고, **취소**는 초대를 취소합니다. 이미 수락한
초대는 다시 보낼 수 없습니다.

<Note>
  MoleSignal은 초대 이메일을 보내지 않으며, 초대만으로는 계정이나
  멤버십이 생성되지 않습니다. 초대 대상은 [가입](/ko/console#로그인) 또는
  [싱글 사인온](/ko/identity/sso)을 통해 참여하고, 관리자는 **사용자**에서 역할을 설정합니다.
</Note>

## 멤버 API

| 작업 | 엔드포인트 | 권한 |
|---|---|---|
| 사용자 목록 조회 | `GET /api/v1/users` | `org.members.read`. 이 권한이 없는 로그인 상태의 멤버에게는 이름과 프로필 사진만 반환합니다. API 토큰 요청은 거부합니다. |
| 사용자 변경 | `PATCH /api/v1/users/{id}` | `org.members.update` |
| 승인 또는 거부 | `POST /api/v1/users/{id}/approve`, `POST /api/v1/users/{id}/reject` | `org.members.update` |
| 멤버십 추가 또는 변경 | `POST /api/v1/orgs/{id}/members` | `org.members.update` |
| 멤버십 제거 | `DELETE /api/v1/orgs/{id}/members/{user_id}` | `org.members.update` |
| 초대 목록 조회 또는 초대 생성 | `GET /api/v1/invitations`, `POST /api/v1/invitations` | `org.members.read`, `org.members.update` |
