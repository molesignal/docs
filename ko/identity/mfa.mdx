다단계 인증은 비밀번호 외에 추가 확인을 요구하므로 비밀번호만 알아서는
로그인할 수 없습니다. 아래의 두 번째 인증 수단 중 하나라도 등록하면 다단계 인증이 켜지며, 두 수단을
함께 사용할 수 있습니다. 각 계정에서 **계정 설정 → 보안 및 로그인**으로 이동해 설정합니다.
워크스페이스는 [멤버에게 다단계 인증을 요구할 수 있습니다](/ko/identity/sso#로그인-요구-사항). 다단계 인증을 켜지 않은 멤버는
로그인할 때 설정합니다.

| 두 번째 인증 수단 | 인증 방법 |
|---|---|
| 패스키 | 지문, 얼굴 인식 또는 기기 암호로 인증합니다. 입력할 코드가 없으며, 피싱 사이트가 사용자를 속여 패스키를 탈취할 수 없습니다. iCloud 키체인, Google 비밀번호 관리자, 1Password 또는 보안 키에 저장할 수 있습니다. 비밀번호 없이 패스키만으로도 로그인할 수 있습니다. |
| 인증 앱 | Google Authenticator, Microsoft Authenticator, 1Password 등의 앱에 표시되는 6자리 코드를 입력합니다. |

## 먼저 본인 확인

인증 앱을 켜거나 패스키를 추가하려면 먼저 계정 소유자인지
확인합니다. 로그인 상태만으로는 충분하지 않습니다. 세션을 탈취한 사람이 두 번째 인증 수단을
임의로 추가해 계정 소유자의 접근을 막을 수 있기 때문입니다.

| 계정 상태 | 확인 방법 |
|---|---|
| 두 번째 인증 수단이 이미 있음 | 기존 패스키, 인증 앱 또는 복구 코드로 인증합니다. |
| 두 번째 인증 수단이 아직 없음 | 계정 비밀번호를 입력합니다. |
| 비밀번호가 없음(싱글 사인온으로 생성) | 로그인 후 10분 이내에는 입력할 항목이 없습니다. 10분이 지나면 다시 로그인합니다. |

## 패스키 추가

<Steps>
  <Step title="설정 열기">
    **계정 설정 → 보안 및 로그인**의 **패스키** 행에서 **패스키 추가**를 클릭한 후
    위의 방법으로 본인 확인을 완료합니다.
  </Step>
  <Step title="패스키 생성">
    필요한 경우 '내 MacBook'과 같은 이름을 지정합니다. **생성**을 클릭하고
    브라우저 또는 시스템의 안내를 따릅니다.
  </Step>
  <Step title="복구 코드 저장">
    계정에 처음으로 두 번째 인증 수단을 추가하면 다단계 인증이 켜지고 복구 코드
    10개가 이때 한 번만 표시됩니다. **복사** 또는 **다운로드**로 코드를 보관한 후
    **저장했습니다**를 클릭합니다.
  </Step>
</Steps>

인스턴스가 [이메일을 보낼 수 있으면](/ko/configuration#알림-설정-및-이메일) 계정 이메일 주소로
알림을 보냅니다. 첫 패스키를 추가하면 다른 브라우저와 컴퓨터의 모든 로그인 세션이 종료되지만
현재 브라우저의 로그인 상태는 유지됩니다. 이후 패스키를 추가해도 다른 세션에는 영향이 없습니다.

브라우저와 시스템에 따라 패스키를 저장할 수 있는 위치가 달라집니다. 안내 화면에서 저장 위치를 선택합니다.

| 저장 위치 | 참고 |
|---|---|
| iCloud 키체인 | Apple 기기의 Safari에서 사용합니다. 같은 Apple 계정을 사용하는 모든 기기에서 작동합니다. |
| Google 비밀번호 관리자 | Chrome과 Android에서 사용합니다. 같은 Google 계정을 사용하는 모든 기기에서 작동합니다. |
| 비밀번호 관리자 | 1Password, Bitwarden 등을 사용할 수 있습니다. |
| 보안 키 | YubiKey 등 FIDO2 키를 사용할 수 있습니다. |

컴퓨터에서 사용할 수 있는 패스키가 없으면 브라우저에 QR 코드가 표시될 수 있습니다.
QR 코드를 통해 휴대전화의 패스키로 인증합니다.

이름이 없는 패스키는 목록에 저장 위치가 표시됩니다. 브라우저가 저장 위치를 제공하지 않으면
패스키로만 표시됩니다.

### 인스턴스 요구 사항

패스키는 인스턴스의 도메인 이름에 연결되므로 다음 요구 사항을 충족해야 합니다. 충족하지 않으면
**패스키 추가**가 비활성화되고 그 이유가 표시됩니다. 로그인 페이지에도 패스키 옵션이 표시되지 않습니다.

| 요구 사항 | 참고 |
|---|---|
| `[http].external_url`을 설정합니다 | [구성](/ko/configuration)을 참조합니다. |
| 도메인 이름을 사용합니다 | 브라우저는 IP 주소를 허용하지 않습니다. |
| HTTPS를 사용합니다 | `localhost`는 예외입니다. |
| 해당 주소로 콘솔을 엽니다 | 다른 호스트 이름으로 콘솔을 열면 브라우저가 패스키 사용을 허용하지 않습니다. |

`external_url`의 호스트 이름을 변경하면 기존 패스키를 사용할 수 없습니다. 비밀번호
또는 복구 코드로 로그인한 후 패스키를 다시 추가합니다.

## 인증 앱 켜기

<Steps>
  <Step title="설정 열기">
    **계정 설정 → 보안 및 로그인**의 **인증 앱** 행에서 **켜기**를 클릭한 후
    위의 방법으로 본인 확인을 완료합니다.
  </Step>
  <Step title="인증 앱에 추가">
    인증 앱으로 QR 코드를 스캔하거나 코드 아래에 표시된 키를 입력합니다. 앱에
    MoleSignal이라는 이름으로 항목이 표시됩니다. `[http].external_url`을 설정하면 이름에 호스트 이름이 포함되어
    여러 인스턴스를 구분할 수 있습니다.
  </Step>
  <Step title="첫 코드 입력">
    앱에 표시된 6자리 코드를 입력하고 **켜기**를 클릭합니다. 코드가
    일치할 때만 인증 앱이 활성화됩니다.
  </Step>
  <Step title="복구 코드 저장">
    계정에 처음으로 두 번째 인증 수단을 추가하면 복구 코드 10개가 이때 한 번만 표시됩니다.
    **복사** 또는 **다운로드**로 코드를 보관한 후 **저장했습니다**를 클릭합니다.
  </Step>
</Steps>

계정에 두 번째 인증 수단이 없었다면 인증 앱을 켤 때 다른 브라우저와 컴퓨터의
모든 로그인 세션이 종료됩니다. 현재 브라우저의 로그인 상태는 유지되며, 계정 이메일 주소로 알림을 보냅니다.

## 로그인

### 비밀번호 없이 패스키로 로그인

로그인 페이지에서 **패스키로 계속**을 클릭합니다. 또는 **이메일로 로그인**을 클릭한 후 이메일
입력란을 클릭하고 브라우저가 제안하는 패스키를 선택합니다. 패스키는 지문, 얼굴 인식 또는 기기 암호를 요구하므로
그 자체로 다단계 인증을 충족합니다. 별도의 두 번째 단계는 필요하지 않습니다.

### 비밀번호를 너무 많이 틀린 경우

비밀번호를 너무 많이 틀리면 로그인 페이지에 대기 시간이 표시됩니다. 패스키를 사용하거나 비밀번호를 재설정하면
기다리지 않아도 됩니다. 패스키 로그인은 시도 횟수에 포함되지 않고 제한도 받지 않으므로, 다른 사람이 비밀번호를 추측하는 동안에도 계정 소유자는
로그인할 수 있습니다. 비밀번호를 재설정하면 계정 잠금이 즉시 해제됩니다. 구체적인 제한은
[로그인 제한](/ko/settings/platform#로그인-제한)을 참조합니다.

### 비밀번호 입력 후 두 번째 단계

비밀번호를 입력하면 로그인 페이지에 **본인 확인**이 표시됩니다. 계정에 등록된 두 번째 인증 수단을 사용합니다.

| 방법 | 인증 방법 |
|---|---|
| 패스키 | **패스키로 인증**을 클릭하고 브라우저 또는 시스템의 안내에 따라 인증합니다. |
| 인증 앱 | 6자리 코드를 입력합니다. 여섯 자리를 모두 입력하면 코드가 즉시 전송됩니다. 휴대전화와 서버의 시계 차이가 30초 이내일 때 코드가 유효하며, 각 코드는 한 번만 사용할 수 있습니다. |
| 복구 코드 | 사용하지 않은 복구 코드를 입력합니다. 각 코드는 한 번만 사용할 수 있습니다. 코드를 사용하면 로그인 페이지에 남은 코드 수가 표시되고 계정 이메일 주소로 알림을 보냅니다. |

| 상황 | 결과 |
|---|---|
| 한 번의 로그인 과정에서 5회 실패 | 해당 로그인 시도가 종료됩니다. 비밀번호를 다시 입력합니다. |
| 1시간 이내에 잘못된 코드를 10회 입력 | 인증 앱 코드와 복구 코드 사용이 1시간 동안 차단되며, 계정 이메일 주소로 알림을 보냅니다. 패스키에는 영향이 없으므로 비밀번호 없이 계속 로그인할 수 있습니다. |
| 비밀번호 입력 후 5분 이내에 두 번째 단계를 완료하지 않음 | 해당 로그인 시도가 만료됩니다. 비밀번호를 다시 입력합니다. |

## 두 번째 단계가 필요한 로그인 방식

| 로그인 방식 | 두 번째 단계 |
|---|---|
| 계정 비밀번호 | 필요합니다. |
| 비밀번호 없이 패스키 사용 | 필요하지 않습니다. 패스키 자체가 다단계 인증을 충족합니다. |
| LDAP | 필요합니다. LDAP는 디렉터리의 비밀번호만 확인합니다. |
| OIDC, OAuth 2.0 및 SAML 싱글 사인온 | 필요하지 않습니다. ID 공급자가 다단계 인증을 담당합니다. |
| 기존 계정을 연결하는 첫 싱글 사인온 | 필요합니다. 연결을 확인한 후 두 번째 단계를 완료해야 계정이 연결됩니다. [기존 계정 연결](/ko/identity/sso#기존-계정-연결)을 참조합니다. |
| 데이터베이스 클라이언트(Flight SQL)에서 계정으로 로그인 | 계정 비밀번호로는 연결할 수 없습니다. `mspat-`로 시작하는 [API 토큰](/ko/identity/tokens)을 사용합니다. [데이터베이스 클라이언트](/ko/query/database-clients#인증)를 참조합니다. |
| API 토큰 | 영향이 없습니다. |

## 복구 코드 관리

인증 앱과 패스키를 모두 잃어버린 경우 복구 코드 하나로 한 번씩 로그인할 수 있습니다. **보안 및 로그인**의 **복구 코드**
행에서 남은 코드 수를 확인합니다. **새 코드 생성**을 클릭하고 확인하면
새 복구 코드 10개가 생성됩니다. 기존 코드는 더 이상 사용할 수 없습니다.

## 2차 인증 수단 변경

이름 변경을 제외한 모든 작업은 즉시 패스키, 인증 코드 또는
복구 코드로 확인해야 합니다.

| 작업 | 방법 |
|---|---|
| 패스키 이름 변경 | 해당 행에서 **이름 변경**을 클릭합니다. |
| 패스키 삭제 | **삭제**를 클릭합니다. iCloud 키체인이나 비밀번호 관리자에 저장된 사본은 해당 서비스에서 삭제해야 합니다. 이 기능을 지원하는 브라우저는 다음에 해당 패스키로 로그인을 시도할 때 시스템에 사본 삭제를 요청합니다. |
| 인증 앱 교체 | **인증 앱 교체**를 클릭하고 확인한 뒤 새 QR 코드를 스캔하고 인증 앱에 표시된 코드를 입력합니다. 기존 복구 코드는 그대로 유지됩니다. |
| 인증 앱 끄기 | **끄기**를 클릭합니다. |

계정의 마지막 2차 인증 수단을 제거하면 다단계 인증이 꺼집니다. 복구 코드는 더 이상
작동하지 않으며 계정에 등록된 이메일 주소로 알림을 보냅니다. 계정이 속한 워크스페이스에서
[다단계 인증을 요구하는](/ko/identity/sso#로그인-요구-사항) 동안에는 마지막 수단을 제거할 수 없습니다.
**끄기**와 **삭제**가 비활성화되고 다단계 인증을 요구하는 워크스페이스가 표시됩니다.

## 관리자가 재설정

멤버가 모든 2차 인증 수단을 잃어버리고 복구 코드도 모두 사용했다면, 관리자는
**ID 및 액세스 → 사용자**에서 해당 멤버의 작업 메뉴를 열고 **다단계 인증
재설정**을 클릭합니다. 이 작업에는 `org.members.mfa_reset` 권한이 필요합니다. 재설정하면 해당 멤버의 인증 앱, 패스키, 복구
코드가 더 이상 작동하지 않으며, 모든 기기에서 로그아웃되고 계정에 등록된 이메일 주소로 알림을 보냅니다. 멤버는
비밀번호로 로그인한 뒤 다단계 인증을 다시 설정합니다. 워크스페이스에서 다단계 인증을 요구하면 로그인
과정에서 설정합니다.

| 멤버 | 재설정할 수 있는 주체 |
|---|---|
| 이 조직에만 속한 멤버 | 이 조직의 관리자입니다. |
| 다른 조직에도 속한 멤버 | 플랫폼 관리자만 재설정할 수 있습니다. 재설정은 멤버가 속한 모든 조직에 영향을 줍니다. |
| 루트 사용자 | 서버에서 [오프라인 재설정](#오프라인-재설정)으로만 재설정할 수 있습니다. |

**사용자** 목록의 **MFA** 열에서 각 멤버의 다단계 인증 활성화 여부를 확인할 수 있습니다.

## 오프라인 재설정

루트 사용자가 모든 2차 인증 수단을 잃어버렸거나 어떤 관리자도 로그인할 수 없다면 서버에서 다음 명령을 실행합니다.

```bash
molesignal --config /etc/molesignal/config.toml reset-mfa --email root@example.com
```

이 명령은 계정의 다단계 인증을 끄고 모든 로그인 세션을 종료한 뒤
서비스를 시작하지 않고 끝납니다.

## 로그인 세션이 종료되는 경우

다음 작업을 수행하면 다른 브라우저와 컴퓨터에서 해당 계정의 다음
요청이 들어오는 시점에 로그인 세션이 종료됩니다.

- 첫 2차 인증 수단을 추가하여 다단계 인증을 켭니다.
- 인증 앱을 교체하거나 끄거나 패스키를 삭제합니다.
- 관리자가 다단계 인증을 재설정합니다.
- **활성 세션**에서 **다른 모든 기기에서 로그아웃**을 선택합니다.
- 이메일로 받은 링크에서 비밀번호를 재설정합니다. 이 경우 계정의 모든 로그인 세션이 종료됩니다.

워크스페이스에서 [로그인 요구 사항](/ko/identity/sso#로그인-요구-사항)을 활성화하면 해당 요구 사항을
충족하지 않는 세션은 15분 이내에 종료됩니다.
