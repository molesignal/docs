알림 음소거는 일치하는 인시던트의 알림 전송과 에스컬레이션을 일시 중지하지만, 인시던트는 계속
기록합니다. 시맨틱 그룹은 관련 인시던트를 하나로 묶어 한 번에 대응할 수 있게 합니다. 두 기능 모두
규칙을 변경하지 않습니다. 더 심각한 인시던트가 활성 상태일 때 덜 심각한 인시던트의 알림을 억제하려면
[알림 억제](/ko/alerting/inhibition)를 사용합니다.

## 음소거 정책

**알림 → 음소거 정책**을 엽니다. 각 정책에는 상태, 기간, 일치 대상이 표시됩니다.

| 상태 | 의미 |
|---|---|
| **음소거 중** | 일치하는 인시던트의 알림을 음소거합니다. |
| **시작 전** | 아직 음소거 기간이 시작되지 않았습니다. |
| **음소거 시간 외** | 현재 시간이 반복 음소거 기간에 해당하지 않습니다. |
| **종료됨** | 음소거 기간이 끝났습니다. |
| **꺼짐** | 정책이 비활성화되어 있습니다. |

정책을 만들려면 다음 단계를 따릅니다.

1. **새 알림 일시 중지 정책**을 선택하고 **이름**을 입력합니다. **활성화**를 켜 둡니다.
2. **일치 조건**에서 인시던트 라벨에 적용할 조건마다 **일치 조건 추가**를 선택합니다. 예를 들어
   `service` `=` `checkout`을 추가합니다. 모든 조건이 일치해야 합니다. `=~`와 `!~`에는 정규식을 사용합니다. 일치 조건을
   추가하지 않으면 정책이 **모든 인시던트**에 적용됩니다.
3. **기간**에서 **기간 유형**을 선택합니다.
   - **고정 기간**: **시작**과 **종료**를 지정합니다.
   - **매주**: **시간대**와 하나 이상의 시간 범위를 지정합니다. 각 범위에는 **요일**,
     **시작 시간 (HH:MM)**, **종료 시간 (HH:MM)**을 분 단위로 지정합니다. 예를 들어 매주 토요일 02:00부터
     06:00까지로 설정합니다. 종료 시간이 시작 시간과 같거나 더 이르면 자정을 넘어 다음 날에 종료합니다. **공휴일**에서는
     [공휴일 캘린더](/ko/alerting/on-call#휴일-캘린더)에 등록된 휴일을 제외하거나 해당 휴일에만 시간 범위를 적용할 수 있습니다.
   - **공휴일**: **시간대**와 **공휴일 캘린더**를 지정합니다. 캘린더에 등록된 모든 휴일에 하루 종일 적용합니다. 예를 들어
     공휴일에 테스트 환경의 알림을 음소거할 수 있습니다.
   - **매월**: **시간대**와 **매월 날짜**(해당 날짜가 없는 달에는 그달의 마지막
     날을 사용합니다) 또는 **몇 번째**(첫 번째부터 다섯 번째까지 또는 마지막) **요일**을 지정합니다. **시작 시간(HH:MM)**과
     **지속 시간(분)**도 지정합니다. 최대 7일까지 설정할 수 있습니다. 예를 들어 매월 첫 번째 일요일
     02:00부터 240분 동안 적용합니다. 다섯 번째로 지정한 요일이 없는 달은 건너뜁니다.
4. **메모**에서 **사유**를 입력한 다음 **알림 음소거 만들기**를 선택합니다.

목록에는 반복 음소거의 다음 시작 또는 종료 시간이 표시됩니다. 서버는 해당 시간대를 기준으로
일광 절약 시간제까지 반영해 이 시간을 계산합니다.

음소거는 인시던트에 붙은 라벨을 기준으로 적용합니다. 여기에는 규칙의 라벨과
[분할 규칙](/ko/alerting/rules#열-기준으로-규칙-그룹화)의 그룹 값이 포함됩니다. [외부 알림](/ko/alerting/sources)의 인시던트에는
`alert.source=external`, `external.kind`(예: `alertmanager`), 알림 자체의 라벨과
소스의 추가 라벨이 포함됩니다. 예를 들어 `external.kind` `=` `grafana`는 Grafana에서 보내는 모든 알림을 음소거합니다.
계획된 음소거에는 항상 대상 서비스와 종료 시간을 명시합니다. 나중에 직접 삭제하지 말고
지정한 시간에 자동으로 종료되도록 둡니다.

<Warning>
  음소거는 알림 전송을 막을 뿐, 서비스가 복구되었음을 의미하지 않습니다. 음소거 기간이 끝나면 인시던트
  목록을 확인합니다.
</Warning>

### 음소거 중 알림

음소거 중에도 일치하는 인시던트는 평소와 같이 열리고 기록됩니다. 알림은
유형별로 다음과 같이 처리합니다.

| 알림 | 음소거 중 | 음소거 종료 후 |
|---|---|---|
| 알림 발생, 알림 에스컬레이션 | 전송하지 않습니다. 에스컬레이션은 현재 단계에 머무릅니다. | 아직 확인하지 않았고 해결하지도 않은 인시던트는 발생 알림을 전송하고 에스컬레이션을 계속합니다. 음소거 중 현재 단계의 확인 대기 시간이 만료되었다면 다음 단계의 알림을 즉시 전송합니다. 음소거 중 확인하거나 해결한 인시던트에는 알림을 전송하지 않습니다. |
| 개인 알림 순서의 후속 단계, 알림 정책의 확인 시간 초과에 따른 에스컬레이션 | 전송하지 않습니다. | 아직 확인하지 않은 경우 전송합니다. |
| 알림 확인, 알림 해결 | 음소거가 시작되기 전에 발생 알림을 전송했다면 전송합니다. 음소거로 발생 알림을 보내지 않았다면 전송하지 않습니다. | 평소와 같이 전송합니다. |

음소거 기간이 끝나거나 정책을 비활성화 또는 삭제하면 음소거가 종료됩니다.

### 단일 인시던트 음소거

인시던트에서 **알림 음소거**를 선택하면 해당 인시던트의 알림 전송과 에스컬레이션만 **1시간**,
**4시간**, **24시간**, **7일** 중 선택한 기간 동안 일시 중지합니다. 필요에 따라 **사유**를 입력합니다. 규칙은 비활성화하지 않으며,
같은 서비스의 다른 인시던트에는 영향을 주지 않습니다. 등록한 음소거는 **음소거 정책**에서 확인할 수 있으며,
종료 전에 변경하거나 삭제할 수 있습니다.

음소거를 만들거나 변경하거나 삭제하려면 `alerts.mutes.manage` 권한이 필요합니다.

## 시맨틱 그룹

**알림 → 그룹**을 엽니다. 시맨틱 그룹은 Alertmanager의
`group_by`처럼 라벨 값이 같은 인시던트를 하나로 묶습니다. API를 통해 그룹을 확인하거나 해결하면 그룹 내 모든
인시던트에도 동일하게 적용됩니다. [인시던트 그룹](/ko/alerting/incidents#인시던트-그룹)을 참조합니다.

1. **새 그룹**을 선택하고 `critical-by-service`와 같은 **이름**을 입력합니다. **활성화**를 켜 둡니다.
2. **매칭 조건**에서 `severity` = `critical`과 같이 인시던트가 충족해야 하는 조건을 추가합니다.
   모든 조건이 일치해야 합니다. 조건이 없으면 모든 인시던트에 그룹을 적용합니다.
3. **그룹화 기준**에서 `service, region`과 같이 **그룹화 기준 라벨**을 쉼표로 구분해 입력합니다.
   해당 라벨 값이 같은 인시던트를 하나의 그룹으로 묶습니다.
4. **그룹 만들기**를 선택합니다.

비활성화한 그룹은 적용하지 않습니다. 그룹을 삭제해도 인시던트는 유지되며 그룹화만 해제합니다.

**가져오기**는 JSON에서 그룹을 만듭니다. 그룹 배열이나 `groups` 배열이 있는 객체를 사용합니다.

```json
[
  {
    "name": "crit-by-service",
    "enabled": true,
    "matchers": [{ "label": "severity", "op": "eq", "value": "critical" }],
    "groupBy": ["service"]
  }
]
```

그룹을 관리하려면 `alerts.semantic_groups.manage` 권한이 필요합니다.
