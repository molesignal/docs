티켓 커넥터는 인시던트를 Jira(Cloud 또는 Data Center / Server), ServiceNow 또는 Meegle(중국에서는
Feishu Project)에 동기화합니다. 인시던트에서 티켓을 생성하거나 규칙에 따라 새 인시던트에 티켓을 자동으로 생성할 수 있습니다. 생성된 티켓은
인시던트를 추적합니다. 인시던트 확인, 해결, 메모는 댓글로 기록되며, 인시던트를 해결하면
티켓이 완료 상태로 전환됩니다. 티켓 상태는 5분마다 MoleSignal로 다시 동기화되며, Jira는 웹훅을 통해
상태 변경을 즉시 전송할 수도 있습니다.

**알림 → 티켓**을 엽니다. 조회에는 `alerts.tickets.read`, 커넥터 관리에는 `alerts.tickets.manage`,
인시던트에서 티켓을 생성하려면 `alerts.incidents.tickets` 권한이 필요합니다.

## Jira 연결

**새 티켓 커넥터**를 선택한 다음 **Jira**를 선택합니다.

| 설정 | 참고 |
|---|---|
| **사이트 주소** | 예: `https://example.atlassian.net`. |
| 배포 유형 | **Jira Cloud**는 **계정 이메일**과 **API 토큰**(Atlassian 계정 설정의 보안 페이지에서 생성)으로 인증하고, **Jira Data Center / Server**는 **개인 액세스 토큰**으로 인증합니다. |
| **프로젝트 키**, **이슈 유형** | 예: `OPS`, `Incident`. |
| **인시던트 우선순위별 티켓 우선순위** | 조직의 인시던트 우선순위(기본값: P1~P5)별로 Jira 우선순위 이름을 입력한 다음, 심각도별로도 입력합니다. 예를 들어 P1에는 `Highest`를 입력합니다. 인시던트에 우선순위가 없거나 해당 우선순위에 입력한 값이 없으면 심각도를 사용합니다. 모두 비워 두면 티켓에 우선순위를 설정하지 않습니다. |
| **레이블** | 티켓에 추가할 레이블입니다. 모든 티켓에는 `molesignal` 레이블도 추가됩니다. |
| **해결 시 상태 전환** | 상태 전환의 이름 또는 ID입니다. 비워 두면 완료 상태로 이어지는 첫 번째 상태 전환을 사용합니다. |
| **웹훅 시크릿** | 시크릿이 있는 경우에만 Jira 웹훅을 수신합니다. [상태 동기화](#상태-동기화)를 참조합니다. |

계정에는 프로젝트에서 이슈를 생성하고, 댓글을 추가하고, 상태를 전환할 수 있는 권한이 필요합니다. 저장한 후
**연결 테스트**를 선택합니다. 연결에 성공하면 연결에 사용한 계정이 표시됩니다.

## ServiceNow 연결

**새 티켓 커넥터**를 클릭한 다음 **ServiceNow**를 선택합니다. 커넥터는 Table API를 사용하며, 티켓은 테이블의 레코드로 저장됩니다.

| 설정 | 설명 |
|---|---|
| **인스턴스 주소**, **테이블** | 예: `https://example.service-now.com`, `incident`. 테이블은 `task`를 확장해야 합니다. |
| 인증 | **사용자 이름 및 비밀번호**, **OAuth 클라이언트 자격 증명**(인스턴스의 `glide.oauth.inbound.client.credential.grant_type.enabled` 속성으로 해당 권한 부여 유형을 허용해야 함), **API 키**(Washington DC 릴리스부터 지원하며 `x-sn-apikey` 헤더에 지정) 중 하나를 사용합니다. 계정에는 테이블 읽기 및 쓰기 권한이 필요합니다. |
| **할당 그룹**, **신고자**, **카테고리** | 레코드를 생성할 때 기록하는 필드입니다. 그룹과 신고자는 `sys_id`로 지정합니다. 비워 두면 값을 설정하지 않습니다. 다른 필드는 API의 `settings.fields`로 지정합니다. |
| **인시던트별 티켓 우선순위** | ServiceNow는 영향도와 긴급도를 바탕으로 우선순위를 계산합니다. `2/1`처럼 `impact/urgency` 형식으로 입력합니다. 숫자 하나만 입력하면 두 항목에 같은 값을 사용합니다. 인시던트 우선순위에 해당하는 값을 먼저 조회하고, 없으면 심각도에 해당하는 값을 조회합니다. 기본값은 심각 `1/1`, 오류 `2/1`, 경고 `2/2`, 정보 `3/3`입니다. |
| **해결 시 상태 값**, **해결 코드** | 인시던트를 해결할 때 기록하는 `state`와 `close_code` 값입니다. 기본값은 각각 `6`과 `Solution provided`입니다. 기본 데이터 정책은 해결 시 해결 코드와 메모를 요구하며, `close_code`의 선택지는 인스턴스마다 다릅니다. 메모에는 MoleSignal에서 인시던트를 해결했다는 내용을 워크스페이스 기본 언어로 기록합니다. |
| **완료로 간주할 상태** | `state` 값을 쉼표로 구분해 입력합니다. 기본값은 `6, 7, 8`(해결됨, 닫힘, 취소됨)입니다. |

인시던트 변경 사항은 내부 메모인 `work_notes`에 기록하므로 신고자에게 알림을 보내지 않습니다. 레코드의 `correlation_id`는 인시던트 ID이고, `correlation_display`는 `MoleSignal`입니다. **연결 테스트**는 테이블을 한 번 읽습니다.

## Meegle 연결

**새 티켓 커넥터**를 선택한 다음 **Meegle**을 선택합니다. 먼저 Meegle 개발자 콘솔에서 플러그인을 생성해
플러그인 ID와 플러그인 시크릿을 발급받고, 티켓을 생성할 스페이스에 플러그인을 설치합니다.

| 설정 | 참고 |
|---|---|
| **플랫폼**, **사이트 주소** | **Feishu**(Feishu Project, `https://project.feishu.cn`) 또는 **Lark**(Meegle, `https://meegle.com`)를 선택합니다. 사이트 주소는 플랫폼에 따라 정해지며, 복사할 수 있지만 수정할 수는 없습니다. |
| **플러그인 ID**, **플러그인 시크릿** | 두 값을 사용해 플러그인 토큰을 발급받습니다. |
| **작업을 수행할 사용자 (user_key)** | 지정한 사용자 이름으로 티켓을 생성하고 댓글을 작성합니다. |
| **스페이스 (project_key)**, **작업 항목 유형 (work_item_type_key)** | 작업 항목을 생성할 스페이스와 작업 항목 유형을 지정합니다. |
| **우선순위 필드 키**, 우선순위 매핑 | 조직의 인시던트 우선순위별로 우선순위 옵션 값을 지정한 다음, 심각도별로도 지정합니다. 인시던트에 우선순위가 없거나 해당 우선순위에 입력한 값이 없으면 심각도를 사용합니다. 모두 비워 두면 티켓에 우선순위를 설정하지 않습니다. |
| **해결 시 상태 전환 ID** | 상태 흐름을 사용하는 작업 항목에 적용합니다. |
| **해결 시 완료할 노드** | 노드 흐름을 사용하는 작업 항목에 적용합니다. |
| **완료로 간주할 상태** | 상태 키를 쉼표로 구분해 입력합니다. 티켓이 지정한 상태 중 하나에 속하면 완료로 간주합니다. |

**연결 테스트**는 작업 항목 유형을 한 번 조회합니다. 자격 증명, 스페이스, 작업 항목 유형이
모두 올바르면 테스트에 성공합니다.

## 인시던트 추적

커넥터의 **인시던트 추적** 설정에서 티켓에 인시던트 변경 사항을 반영하는 방식을 지정합니다.

| 설정 | 동작 |
|---|---|
| **인시던트 확인 시 댓글 작성**, **인시던트 해결 시 댓글 작성** | MoleSignal에서 인시던트를 확인했거나 해결했다는 댓글을 추가합니다. |
| **인시던트 메모를 댓글로 작성** | 인시던트에 새 [메모](/ko/alerting/incidents#메모)를 작성하면 티켓에 댓글로 추가합니다. |
| **인시던트 해결 시 티켓을 완료 상태로 전환** | 위에서 지정한 상태 전환을 사용해 티켓을 닫습니다. |
| **티켓 완료 시 인시던트를 해결 상태로 전환** | 티켓 작업이 끝나면 인시던트가 열려 있거나 확인된 상태에 관계없이 인시던트를 해결 상태로 전환합니다. 기본적으로 꺼져 있습니다. |
| **주요 인시던트 선언 시 티켓 생성** | 인시던트를 [주요 인시던트](/ko/alerting/major-incidents)로 선언하면 이 커넥터로 티켓을 생성합니다. |

티켓 제목은 `[severity] incident summary` 형식입니다. 본문에는 인시던트의 심각도와 상태,
서비스, 레이블, 인시던트를 트리거한 쿼리, AI가 분석한 근본 원인 요약, 인시던트 페이지 링크가 포함됩니다.
댓글과 본문은 워크스페이스 기본 언어로 작성합니다.

## 티켓 자동 생성

**티켓 자동 생성**을 켜면 새 인시던트가 **최소 심각도** 이상이고 해당 서비스가
**서비스** 목록에 포함될 때 이 커넥터로 티켓을 자동 생성합니다. 서비스 목록을 비워 두면 모든 서비스에 적용합니다. 각 커넥터는
인시던트당 티켓을 최대 하나만 생성합니다.

## 인시던트에서 티켓 생성

인시던트 세부 정보의 **티켓**에는 티켓 키(선택하면 티켓 열기), 상태,
마지막 동기화 시각, 동기화 또는 댓글 작성 중 발생한 오류가 표시됩니다. **티켓 생성**을 선택합니다.
커넥터가 여러 개라면 **…에서 생성**을 선택합니다. 티켓 생성 내역은 인시던트 타임라인과
감사 로그에 기록됩니다.

[사후 분석](/ko/alerting/major-incidents#사후-분석)의 조치 항목에도 각각 티켓을 생성할 수 있습니다. 이 티켓에는
인시던트의 댓글이나 상태 전환을 반영하지 않으며, 티켓을 완료해도 인시던트를 해결 상태로 전환하지 않습니다.

## 상태 동기화

완료되지 않은 티켓은 5분마다 동기화하며, 상태가 바뀌면 인시던트 타임라인에 기록합니다. Jira는 상태 카테고리로 완료 여부를 판단하고, Meegle과 ServiceNow는 커넥터에 지정한 상태로 판단합니다.

Jira는 변경 사항을 즉시 전송할 수도 있습니다. 커넥터에 **웹훅 시크릿**을 설정하면 커넥터 목록에
Jira 웹훅 주소와 **주소 복사**가 표시됩니다. Jira의 **시스템 설정 → 웹훅**에서 해당 URL과
동일한 시크릿을 사용해 이슈 업데이트용 웹훅을 생성합니다. MoleSignal은 시크릿으로 `X-Hub-Signature`를 검증하고
서명이 일치하지 않는 요청을 거부합니다. 웹훅 주소에 접근할 때는 로그인할 필요가 없습니다.
[공개 액세스](/ko/public-access)를 참조합니다.
