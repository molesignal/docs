복구 작업은 미리 정의해 두는 해결 조치입니다. Jenkins, GitHub Actions, Argo, Rundeck 또는
유사한 시스템을 호출하거나, 등록된 Kubernetes 클러스터의 워크로드를 재시작, 스케일링 또는 롤백합니다.
인시던트 담당자는 인시던트에서 한 번의 클릭으로 복구 작업을 시작합니다. 모든 실행에는 승인이 필요하며(
[사전 승인](#사전-승인)을 활성화하면 미리 승인할 수 있습니다), 승인 요건을 충족하는 즉시 실행합니다.
실행 결과와 후속 검증 결과는 인시던트 타임라인에 기록합니다.

**알림 → 문제 해결**을 엽니다. 조회에는 `alerts.remediation.read`, 작업 정의와 클러스터 등록에는
`alerts.remediation.manage`, 인시던트에서 실행을 시작하려면 `alerts.incidents.remediate`, 실행을 승인하려면
`agent.approve` 권한이 필요합니다.

## 복구 작업 정의

**새 복구 작업**을 선택하고 다음 항목을 입력합니다.

| 항목 | 설정 |
|---|---|
| **기본 정보** | **이름**과 **설명**을 입력합니다. |
| **실행 방식** | **HTTP 요청** 또는 **Kubernetes**를 선택합니다. 아래 설명을 참조합니다. |
| **실행 시 입력할 매개변수** | 실행을 시작할 때 입력할 값을 최대 10개까지 정의합니다. **이름**(템플릿에서는 `{{params.name}}`으로 표기), **레이블**, **유형**(**텍스트**, **숫자** 또는 **선택**), **선택지**, **기본값**, **필수**를 설정합니다. |
| **범위 및 승인** | **서비스**(쉼표로 구분하며, 비워 두면 모든 인시던트에 적용), **위험도**(**L2 · 승인자 1명** 또는 **L3 · 승인자 2명**), **확인 대기 시간**(결과를 확인하기 전까지 대기할 시간(분), 0이면 확인하지 않음), **성공 조건**(**인시던트 해결됨** 또는 **규칙이 정상 상태로 돌아옴**), **활성화됨**을 설정합니다. |

목록에는 각 작업의 서비스(제한이 없으면 **모든 인시던트**)와 위험도가 표시됩니다.
**비활성화됨**으로 표시된 작업은 인시던트에서 사용할 수 없습니다.

### HTTP 요청

| 설정 | 참고 사항 |
|---|---|
| **메서드**, **주소** | `GET`, `POST`, `PUT`, `PATCH` 중 하나를 선택하고 `http://` 또는 `https://`로 시작하는 주소를 입력합니다. |
| **헤더** | 예를 들어 `Authorization`을 사용합니다. 값은 암호화하여 저장하며 다시 표시하지 않습니다. 편집할 때 비워 두면 기존 값을 유지합니다. |
| **본문** | JSON 편집기에서 JSON을 작성합니다. 입력값은 JSON 규칙에 따라 이스케이프합니다. 따옴표로 감싼 자리표시자는 문자열이며, 따옴표가 없으면 `{"replicas": {{params.replicas}}}`처럼 숫자를 나타낼 수 있습니다. 모든 자리표시자를 0으로 바꿨을 때 본문이 유효한 JSON이어야 저장할 수 있습니다. |
| **서명 시크릿** | 설정하면 [일반 웹훅 서명](/ko/notification-channels/webhooks#헤더-및-서명)과 마찬가지로 요청에 `X-MoleSignal-Timestamp`와 `X-MoleSignal-Sign`을 포함합니다. 수신 측은 이 헤더로 요청이 MoleSignal에서 왔는지 확인할 수 있습니다. |

주소, 헤더, 본문에서 `{{incident.id}}`, `{{incident.summary}}`, `{{incident.severity}}`,
`{{incident.status}}`, `{{incident.service}}`, `{{incident.url}}`, `{{params.name}}`을 사용할 수 있습니다.
주소에 삽입하는 값은 퍼센트 인코딩합니다.

요청은 주소가 해석되는 IP에만 연결하며, 클라우드 메타데이터 주소에는 연결하지 않습니다. 리디렉션은 따르지
않으며, 30초 후 시간 초과로 처리합니다. 2xx 응답을 받으면 실행이 성공한 것으로 간주하며,
응답의 앞부분을 실행 기록에 저장합니다.

### Kubernetes

| 설정 | 참고 사항 |
|---|---|
| **클러스터** | 등록된 클러스터를 선택합니다. [Kubernetes 클러스터 등록](#kubernetes-클러스터-등록)을 참조합니다. |
| **작업** | **재시작**(`kubectl rollout restart`와 같은 롤링 재시작), **스케일링**, **직전 리비전으로 롤백**(`kubectl rollout undo`와 동일) 중 하나를 선택합니다. |
| **워크로드 유형** | Deployment, StatefulSet 또는 DaemonSet을 선택합니다. Deployment만 롤백할 수 있으며 DaemonSet은 스케일링할 수 없습니다. |
| **네임스페이스**, **워크로드 이름** | `{{incident.service}}`와 같은 템플릿을 사용할 수 있습니다. |
| **복제본 수** | 스케일링 후의 복제본 수입니다. `{{params.replicas}}`를 사용해 실행을 시작할 때 입력할 수 있습니다. |

## Kubernetes 클러스터 등록

**Kubernetes 클러스터**에서 **클러스터 추가**를 선택하고 **이름**, **API 서버 주소**,
**CA 인증서**(PEM 형식, 비워 두면 시스템에서 신뢰하는 루트 인증서 사용), **ServiceAccount 토큰**을 입력합니다.
토큰은 암호화하여 저장하며 다시 표시하지 않습니다. **연결 테스트**는 클러스터 버전을 한 번 조회합니다.

MoleSignal 전용 ServiceAccount를 만들고 필요한 권한만 부여합니다. 대상 워크로드에는 `get`과
`patch` 권한, 스케일링에는 `scale` 하위 리소스 권한, 롤백에는 ReplicaSet 목록 조회 권한이 필요합니다. 예를 들어
`shop` 네임스페이스의 워크로드에만 권한을 부여하려면 다음과 같이 설정합니다.

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: molesignal-remediation
  namespace: shop
rules:
  - apiGroups: ["apps"]
    resources: ["deployments", "statefulsets", "daemonsets", "deployments/scale", "statefulsets/scale"]
    verbs: ["get", "patch"]
  - apiGroups: ["apps"]
    resources: ["replicasets"]
    verbs: ["list"]
```

API 서버 주소가 해석되는 IP에만 연결하며, 클라우드 메타데이터 주소에는 연결하지 않습니다.
작업에서 사용 중인 클러스터는 삭제할 수 없습니다.

## 인시던트에서 복구 작업 실행

인시던트 세부 정보의 **문제 해결**에는 해당 인시던트에 적용되는 작업이 표시됩니다. 서비스 제한이 없는
작업과 인시던트의 서비스에 일치하는 작업이 포함됩니다. 작업 옆의 **실행**을 선택하고 값을 입력한 다음,
**사유**(예: "결제 서비스의 연결이 고갈되어 우선 재시작")를 작성하고
**승인 요청**을 선택합니다. 해결된 인시던트에서는 작업을 시작할 수 없습니다.

승인을 요청하면 실행은 승인 대기 상태가 됩니다. L2는 `agent.approve` 권한이 있는 승인자 1명, L3는 2명이 필요하며,
요청자는 승인할 수 없습니다. 승인자는 같은 카드에서 **승인** 또는 **거부**를 선택하거나
[Mole Agent의 승인 목록](/ko/agent#승인-및-실행)에서 처리할 수 있습니다. 필요한 승인 수를 충족하면 즉시
실행을 시작합니다.

| 상태 | 의미 |
|---|---|
| **승인 대기 중** | 아직 필요한 승인 수를 충족하지 못했습니다. |
| **실행 중** | 주소로 요청을 보내거나 클러스터를 변경하고 있습니다. |
| **실행 완료**, **실패** | 실행이 끝났으며, 상태 옆에 응답의 앞부분이나 오류를 표시합니다. |
| **미실행** | 승인 요청이 거부되었거나 만료되었거나 취소되었습니다. |
| **검증 대기 중** | 실행이 끝났으며, 설정한 시간(분)이 지나면 결과를 확인합니다. |
| **검증 통과**, **검증 실패** | 확인 시점까지 인시던트를 해결했거나 규칙이 정상 상태로 돌아오면 검증을 통과합니다. |

작업 시작, 실행, 검증은 인시던트의 [타임라인](/ko/alerting/incidents#인시던트-상세-정보)에 기록하며,
작업 시작은 감사 로그에도 기록합니다.

Mole Agent는 인시던트에 적용되는 복구 작업의 목록을 표시하고 실행을 제안할 수 있습니다. Mole Agent가 제안한 실행에는
사전 승인이 적용되지 않는 한, 작업의 위험도에 관계없이 승인자 2명의 승인이 필요합니다.

## 사전 승인

사전 승인을 설정하면 적용 대상 인시던트에서 승인 대기 없이 작업을 실행할 수 있습니다. 이 기능은 기본적으로 꺼져 있습니다.
**알림 → 문제 해결** 상단에서 **사전 승인된 작업 즉시 실행**을 켜면 활성화됩니다.
기능을 켜거나 끄거나 작업을 사전 승인하려면 `alerts.remediation.preapprove` 권한이 필요합니다(기본적으로 소유자와 관리자에게 부여).
일반 승인과 마찬가지로 사전 승인에도 `agent.approve` 권한이 필요합니다. 로그인한 사용자만 사전 승인할 수 있으며,
API 토큰으로는 사전 승인할 수 없습니다.

작업 옆의 **사전 승인**을 선택하고 다음 항목을 설정합니다.

| 설정 | 의미 |
|---|---|
| **서비스** | 선택한 서비스의 인시던트에 적용합니다. 작업에 서비스가 지정되어 있으면 해당 서비스가 모두 선택한 목록에 포함되어야 합니다. |
| **최대 실행 횟수**, **실행 횟수 집계 기간** | 지정한 길이의 어느 구간에서든 허용할 최대 실행 횟수입니다. 횟수는 1~20회, 기간은 15분~7일로 설정합니다. |
| **만료일** | 1일, 7일, 30일, 90일 후 또는 **만료 없음**으로 설정합니다. |
| **실행 후 알림** | 알림 커넥터의 그룹이나 주소를 채널로 최대 5개까지 지정합니다. 사전 승인으로 실행할 때마다 성공 여부와 관계없이 해당 채널에 결과를 알립니다. |

저장하면 승인 1건으로 집계합니다. L2 작업은 승인 1건이 필요하므로 사전 승인이 즉시 적용됩니다. L3 작업은
승인 2건이 필요하므로 사전 승인 권한이 있는 다른 사용자가 **사전 승인 확인**을 선택해야 적용됩니다.
사전 승인은 필요한 승인자 수를 줄이지 않습니다. 작업의 실행 방식, 요청 내용,
대상 서비스나 팀, 위험도를 변경하면 기존 승인이 취소되고 사전 승인은
다시 승인 대기 상태가 됩니다.

사용자나 Mole Agent가 사전 승인 대상 인시던트에서 작업을 시작하면 사전 승인한 사용자가 요청을 승인한 것으로 기록하고,
작업을 시작한 사용자의 권한으로 즉시 실행합니다. 작업을 시작한 사용자에게는
여전히 `alerts.incidents.remediate` 권한이 필요합니다. 일반 승인과 마찬가지로 자신의 요청은 승인할 수 없습니다.
요청자가 부여한 사전 승인은 해당 요청에 집계하지 않습니다. 사전 승인한 다른 사용자가 필요한 수에 미치지 못하면
(L2는 1명, L3는 2명) 요청은 일반 승인과 마찬가지로 승인을 기다립니다. 조직에서
사전 승인을 껐거나, 사전 승인이 만료되었거나 두 번째 승인자의 확인을 기다리는 중이거나, 인시던트가
대상 서비스에 속하지 않거나, 집계 기간 내 최대 실행 횟수에 도달한 경우에도 승인을 기다립니다. 인시던트에 실행을 **사전 승인됨**으로 표시하고,
타임라인과 감사 로그에 사전 승인으로 실행한 사실을 기록하며, 알림 채널에 실행 결과를 알립니다.

| 작업 옆에 표시되는 상태 | 의미 |
|---|---|
| **사전 승인 없음** | 작업에 사전 승인이 없습니다. |
| **사전 승인됨 · 집계 기간 내 N/M회 실행** | 사전 승인이 적용 중이며, 집계 기간 내에 N회 실행했습니다. |
| **사전 승인됨 · 두 번째 승인자 확인 대기 중** | L3 작업을 현재 1명만 승인했습니다. |
| **사전 승인됨 · 최대 실행 횟수 도달** | 이전 실행이 집계 기간을 벗어날 때까지 추가로 실행할 수 없습니다. |
| **사전 승인 만료** | 만료일이 지났습니다. 갱신하려면 사전 승인을 다시 설정합니다. |
| **사전 승인됨 · 조직에서 비활성화됨** | 상단의 스위치가 꺼져 있습니다. |

## API

| 작업 | 엔드포인트 |
|---|---|
| 작업 및 클러스터 관리 | [`/api/v1/alerts/remediation/actions`, `/clusters`](/ko/api/alerting/remediation) |
| 인시던트에서 작업 실행 시작 | [`POST /api/v1/alerts/incidents/{id}/remediations`](/ko/api/alerting/remediation#인시던트에서-작업-실행) |
| 사전 승인 설정 조회 및 활성화 또는 비활성화 | `GET`, `PUT /api/v1/alerts/remediation/preapproval` |
| 작업의 사전 승인 설정, 취소 또는 확인 | `PUT`, `DELETE /api/v1/alerts/remediation/actions/{id}/preapproval`, `POST /api/v1/alerts/remediation/actions/{id}/preapproval/confirm` |
