MoleSignal은 일반적으로 사내 네트워크나 VPN을 통해 접속할 수 있는 내부 네트워크에서 실행합니다. 일부 기능은 외부 시스템이나 인터넷 사용자가 직접 접속할 수 있어야 합니다. Datadog 또는 PagerDuty가 보내는 알림, Microsoft Teams의 메시지 콜백, 상태 페이지 방문이 이에 해당합니다. MoleSignal 자체는 내부 요청과 공개 요청을 구분하지 않습니다. 대신 네트워크 진입점에서 구분합니다. 내부 진입점은 기존과 같이 모든 요청을 전달합니다. 공개 진입점은 [아래 표](#공개-접근이-필요한-경로)에서 실제로 사용하는 경로의 요청만 전달하고, 나머지 경로에는 404를 반환합니다.

인터넷에 공개하는 각 경로는 알림 소스 토큰, 푸시 토큰, 공유 링크, 플랫폼이 서명한 토큰 등 자체 인증 수단을 사용합니다. 네트워크 접근 제한은 두 번째 방어선입니다. 인터넷에서 발생하는 스캔과 크리덴셜 스터핑 시도가 로그인 및 관리 엔드포인트에 도달하지 못하도록 차단합니다.

## 공개 접근이 필요한 경로

사용 중인 기능의 경로만 공개합니다. 표의 각 행은 서로 독립적입니다.

MoleSignal은 업로드된 아티팩트를 오브젝트 스토리지에 저장하기 전에 리스 토큰, 아티팩트 크기, 콘텐츠 해시를 확인합니다. 프로브 에이전트에는 오브젝트 스토리지 자격 증명을 제공하지 않으므로 오브젝트 스토리지를 인터넷에 노출하지 않아도 됩니다. 프로브 에이전트는 두 개의 gRPC 포트에도 연결합니다. 등록에는 `5084`를, 제어 스트림에는 `5085`를 사용합니다. MoleSignal이 이 포트에서 직접 TLS를 종료하므로 연결은 4계층(TCP)에서 그대로 전달해야 하며 HTTP 프록시를 경유할 수 없습니다. 외부 위치의 프로브 에이전트가 인터넷을 통해 연결하는 경우 두 포트를 각각 매핑하고 `probe.register_endpoint`와 `probe.control_endpoint`를 공개 주소로 설정합니다. 자세한 내용은 [구성](/ko/configuration)을 참조합니다.

### 웹 파일

상태 페이지, 공유 리소스, 일회용 작업 링크의 확인 페이지는 웹 페이지이므로 공개 진입점에서 해당 페이지의 정적 파일도 전달합니다. 여기에는 `/assets/` 아래의 파일, `/favicon.ico` 및 `/favicon.svg`, `/favicon-dark.ico` 및 `/favicon-dark.svg`가 포함됩니다. 페이지 경로 `/status/`, `/shared`, `/notify/actions/`와 정적 파일만 공개하면 공개 진입점은 로그인 페이지와 그 외 모든 페이지에 대해 404를 반환합니다.

### 상태 페이지의 사용자 지정 도메인

상태 페이지에 자체 도메인을 사용하는 경우에도 해당 도메인이 공개 진입점을 가리키도록 설정합니다. 페이지는 도메인 루트의 `/`, `/history`, `/uptime` 및 `/incidents/`로 시작하는 경로에 있습니다. 페이지 데이터는 `/api/v1/public/status-pages/`로 시작하는 엔드포인트에서 가져옵니다. 해당 도메인에서는 이 경로와 웹 파일만 공개합니다. 공개 진입점에서 인증서를 관리하거나 MoleSignal이 인증서를 발급하도록 설정합니다. 자세한 내용은 [사용자 지정 도메인 및 TLS](/ko/status-pages#사용자-지정-도메인-및-tls)를 참조합니다.

## 진입점을 구성하는 두 가지 방법

### 분할 DNS로 진입점 분리

권장 방식입니다. 내부 DNS는 `molesignal.example.com`을 내부 진입점으로 확인하고, 공개 DNS는 같은 이름을 공개 진입점으로 확인합니다. 내부 진입점은 모든 경로의 요청을 전달하고, 공개 진입점은 표에 나열된 경로의 요청만 전달합니다. `http.external_url`을 이 이름으로 설정합니다. 그러면 페이지에 표시되는 수집 주소, 발신자에게 제공하는 콜백 주소, IM 및 이메일의 링크가 두 네트워크에서 모두 작동하며, 내부 네트워크의 접근 방식은 바뀌지 않습니다.

### 단일 진입점에서 요청 출처 구분

진입점이 하나인 경우 표에 나열된 경로는 모든 출처에 공개하고, 그 외 경로는 사내 네트워크와 VPN의 주소 범위로 제한합니다. 진입점에서 실제 클라이언트 주소를 확인할 수 있어야 합니다. 진입점 앞에 로드 밸런서가 있다면 PROXY 프로토콜 또는 `X-Forwarded-For`로 원래 주소를 전달합니다.

## 보안 강화 체크리스트

- **HTTPS만 허용합니다.** 공개 진입점은 공인 CA가 발급한 인증서를 사용하고 443 포트에서만 수신합니다. Teams는 HTTPS 주소로만 전송합니다.
- **엔드포인트별 요청 본문 크기를 제한합니다.** 외부 알림은 4 MiB, 하트비트 체크인은 64 KiB, Jira 티켓 웹훅은 1 MiB, RUM 이벤트는 5 MiB, 세션 리플레이는 8 MiB, Probe Agent 아티팩트는 10 MiB, 네이티브 JSON 수집은 16 MiB, 기타 수집 엔드포인트는 2 MiB로 제한합니다. 이 한도를 초과하면 MoleSignal은 `413`을 반환합니다. 진입점의 한도를 이보다 낮게 설정하지 않습니다.
- **공개 진입점에 요청 빈도 제한을 적용합니다.** 소스 주소별로 초당 요청 수를 제한합니다. `standalone` 노드는 수집 요청에 빈도 제한을 적용하지 않습니다. [요청 빈도 및 크기 제한](/ko/security#요청-속도-및-크기-제한)을 참조합니다.
- **액세스 로그에 쿼리 문자열을 남기지 않습니다.** Alibaba Cloud CloudMonitor는 주소의 `token` 매개변수로만 토큰을 전달할 수 있으므로 공개 진입점에서는 경로만 기록합니다. 하트비트 체크인, 온콜 캘린더 구독, 일회용 작업 링크, Huawei Cloud 콜백은 경로에 토큰을 포함하므로 해당 경로의 접두사만 기록합니다. [구성 예시](#구성-예시)에서는 `map`으로 토큰을 대체합니다. MoleSignal 자체 트레이스는 라우트만 기록하고 쿼리 문자열은 기록하지 않습니다.
- **MoleSignal에서 실제 클라이언트 주소를 사용합니다.** `_sys` 조직에서 **설정 → 클라이언트 IP 식별**을 열고, 전달된 주소 체인을 선택한 후 공개 진입점의 주소를 신뢰할 수 있는 프록시로 등록합니다. [클라이언트 IP 식별](/ko/settings/platform#클라이언트-ip-식별)을 참조합니다. RUM의 지리적 위치 확인과 [로그인 제한](/ko/settings/platform#로그인-제한)은 이 설정에 의존합니다. 설정하지 않으면 모든 사용자에게 진입점의 주소가 적용됩니다. 이 주소가 비공개이면 로그인 제한 집계에서 제외되고, 공개이면 한 사용자가 제한에 걸렸을 때 다른 사용자도 로그인할 수 없습니다.
- **선택 사항: 소스 주소를 기준으로 접근을 제한합니다.** 송신 서비스에서 송신 IP 주소를 공개하는 경우 해당 주소만 허용합니다. Datadog은 사이트별 `ip-ranges.<site domain>`의 `webhooks` 섹션, PagerDuty는 미국 또는 유럽 서비스 리전별 주소, Alibaba Cloud CloudMonitor는 알람 콜백 문서, Teams는 Azure 서비스 태그 `AzureBotService`를 참조합니다. 이 주소는 변경될 수 있으므로 목록을 최신 상태로 유지합니다. 토큰은 여전히 주요 보호 수단입니다.
- **운영에 적용하기 전에 확인합니다.** 인터넷에서 `/`와 `/api/v1/auth/signin`은 `404`를 반환하고, 토큰 없이 `POST /api/v1/intake/alerts`를 호출하면 `401`을 반환합니다. `401`은 요청이 MoleSignal에 도달했음을 나타냅니다. 내부 네트워크에서 `/`에 접속하면 로그인 페이지가 열립니다.
