`molesignal <command> --help`는 지정한 명령의 도움말을 같은 형식으로 출력합니다.

## 모든 명령의 공통 옵션

MoleSignal과 통신하는 모든 명령에서 다음 옵션을 사용할 수 있습니다.

| 옵션 | 설명 |
|---|---|
| `--profile <name>` | 사용할 로그인 프로필입니다. [여러 로그인 프로필 유지하기](/ko/cli/sign-in#여러-로그인-상태-유지하기)를 참조합니다. |
| `--url <address>` | 프로필에 저장된 주소 대신 사용할 MoleSignal 주소입니다. |
| `--token <token>` | 이 명령에만 사용할 API 토큰입니다. |

시간은 ISO 형식의 시각, `2026-10-26 14:00`과 같은 로컬 날짜와 시각, 에포크 이후 경과한
초, 밀리초, 마이크로초 수 또는 현재를 기준으로 거슬러 올라갈 기간으로 지정합니다. 기간은
숫자와 단위(`ms`, `s`, `m`, `h`, `d`, `w`)로 지정합니다.

## 로그인

| 명령 | 옵션 | 설명 |
|---|---|---|
| `login` | `--url <address>`, `--profile <name>`, `--with-token` | 브라우저에서 로그인하거나 표준 입력으로 받은 API 토큰으로 로그인합니다. 해당 프로필을 현재 프로필로 설정합니다. |
| `logout` | `--profile <name>` | 프로필의 로그인 정보는 삭제하고 주소는 유지합니다. |
| `profiles` | `--json` | 프로필 목록을 표시합니다. `profiles remove <name>`으로 프로필을 삭제합니다. |
| `use <profile>` | 없음 | 지정한 프로필을 현재 프로필로 설정합니다. |
| `status` | 없음 | 주소, 프로필, 서버, MCP 프로토콜 리비전, 로그인 방식, 도구 수를 표시합니다. |
| `whoami` | `--json` | 사용자, 조직, 역할, 권한을 표시합니다. |
| `doctor` | 없음 | Node.js, 구성, 주소, 프록시, 네트워크 및 TLS, 시스템 시계, 로그인 상태, MCP 엔드포인트를 확인합니다. |

## 로그 및 쿼리

| 명령 | 옵션 | 설명 |
|---|---|---|
| `streams` | `--type <type>`, `--names`, `--json` | 지정한 유형의 스트림 목록을 표시합니다. 기본 유형은 `logs`입니다. |
| `logs <stream>` | `-f`, `-n`, `-q`, `--where`, `--since`, `--from`, `--to`, `--fields`, `--around`, `-B`, `-A`, `--interval`, `--json`, `--utc`, `--web` | 스트림의 최신 로그를 출력합니다. `-f`를 사용하면 새 로그를 계속 출력합니다. [로그 조회 및 실시간 확인](/ko/cli/logs)을 참조합니다. |
| `query "<SQL>"` | `--stream`, `--since`, `--from`, `--to`, `-n`, `--csv`, `--json`, `--utc`, `--web` | 로그 스트림에 읽기 전용 SQL 문 하나를 실행합니다. |
| `fields <stream> [field]` | `--type`, `--since`, `--from`, `--to`, `-n`, `--match`, `--json` | 스트림의 필드 목록을 표시하거나 특정 필드에서 가장 자주 나타나는 값을 표시합니다. |

### `logs` 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `-f`, `--follow` | 꺼짐 | **Ctrl+C**를 누를 때까지 새 로그를 계속 출력합니다. |
| `-n`, `--lines <count>` | `100` | 처음에 출력할 최신 로그 수입니다. `1`~`5000`으로 지정합니다. |
| `-q`, `--query <query>` | 없음 | **로그** 페이지와 같은 형식의 필드 쿼리입니다. |
| `--where <condition>` | 없음 | 스트림의 필드에 적용할 SQL 조건입니다. |
| `--since <duration>` | `15m` | 현재를 기준으로 얼마나 이전까지 조회할지 지정합니다. |
| `--from <time>`, `--to <time>` | 없음 | `--since` 대신 조회 시간 범위를 지정합니다. `--to`는 `-f`와 함께 사용할 수 없습니다. |
| `--fields <a,b,c>` | 전체 | 시각과 지정한 필드만 출력합니다. |
| `--around <time>` | 없음 | 지정한 시각 전후의 로그를 출력합니다. |
| `-B`, `--before <count>` | `10` | `--around`와 함께 사용하며, 지정한 시각 이전의 로그를 최대 `250`개까지 출력합니다. |
| `-A`, `--after <count>` | `10` | `--around`와 함께 사용하며, 지정한 시각 이후의 로그를 최대 `250`개까지 출력합니다. |
| `--interval <duration>` | `2s` | 새 로그를 확인하는 간격입니다. |
| `--json` | 꺼짐 | 각 로그를 JSON 한 줄로 출력합니다. |
| `--utc` | 꺼짐 | 시각을 UTC로 출력합니다. |
| `--web` | 꺼짐 | 터미널에 출력하는 대신 **로그** 페이지에서 로그를 엽니다. |

## 메트릭, 트레이스 및 서비스

| 명령 | 옵션 | 설명 |
|---|---|---|
| `metrics query '<PromQL>'` | `--since`, `--from`, `--to`, `-n`, `--csv`, `--json` | PromQL 범위 쿼리를 실행합니다. 시계열마다 스파크라인과 함께 한 줄로 출력합니다. |
| `metrics names [text]`, `metrics labels <metric>`, `metrics values <metric> <label>`, `metrics series <metric>` | `-n`, `--match <label=value>`, `--json` | 메트릭 이름, 레이블, 레이블 값, 시계열 목록을 표시합니다. |
| `traces` | `--service`, `--errors`, `--min-duration`, `--since`, `--from`, `--to`, `-n`, `--json` | 최근 트레이스 목록을 표시합니다. |
| `traces show <trace>` | `--since`, `--from`, `--to`, `--json`, `--web` | 트레이스를 워터폴 차트로 표시합니다. |
| `services` | `--env`, `--namespace`, `--sort`, `--since`, `--from`, `--to`, `-n`, `--json` | APM 서비스 목록과 각 서비스의 상태를 표시합니다. |
| `services show <service>` | `--env`, `--namespace`, `--since`, `--json`, `--web` | 지정한 서비스의 요약을 표시합니다. |
| `services compare <service> <baseline> <candidate>` | `--env`, `--since`, `--fail-on-regression`, `--json` | 두 버전을 비교합니다. |
| `search-jobs` | `-n`, `--json` | 검색 작업 목록을 표시합니다. |
| `search-jobs submit "<statement>"` | `--stream`, `--type`, `--promql`, `--step`, `--since`, `--from`, `--to`, `--limit`, `--keep`, `--wait`, 변경 옵션 | 검색 작업을 제출합니다. |
| `search-jobs show <job>`, `search-jobs results <job>`, `search-jobs cancel <job>` | `-o <file>`, `--csv`, `--json`, 변경 옵션 | 작업 정보를 표시하거나, 결과 행을 출력하거나, 작업을 취소합니다. |

## 온콜 및 변경

| 명령어 | 옵션 | 설명 |
|---|---|---|
| `incidents` | `--status`, `--since`, `-n`, `--json` | 인시던트 목록을 표시합니다. 기본적으로 진행 중인 인시던트만 표시합니다. |
| `incidents show <incident>` | `--rca`, `--json`, `--web` | 인시던트 하나를 출력합니다. |
| `incidents ack <incident>`, `incidents resolve <incident>` | 변경 옵션 | 인시던트를 확인하거나 해결 처리합니다. |
| `incidents create --title <text>` | `--description`, `--severity`, `--priority`, `--urgency`, `--service`, `--label`, `--team`, `--policy`, `--user`, `--major`, `--json`, 변경 옵션 | 어떤 규칙도 감지하지 못한 문제에 대해 인시던트를 수동으로 생성합니다. `--team`, `--policy`, `--user` 중 하나에 ID를 지정해 처리 대상을 정하지 않으면 알림과 같은 방식으로 라우팅합니다. `--priority`와 `--urgency`에는 조직에 설정된 등급을 사용합니다. 새 인시던트의 ID와 링크를 출력합니다. |
| `oncall` | `--schedule`, `--at`, `--json` | 온콜 담당자를 출력합니다. |
| `approvals` | `--all`, `-n`, `--json` | 승인 대기 중이거나 승인된 요청을 나열합니다. |
| `approvals show <approval>`, `approvals execute <approval>` | `--json`, 변경 옵션 | 요청을 출력하거나 승인된 변경을 실행합니다. |
| `annotate "<title>"` | `--description`, `--tags`, `--dashboard`, `--stream`, `--time`, `--end`, 변경 옵션 | 대시보드에 주석을 추가합니다. |
| `synthetics` | `--lifecycle`, `--json` | 합성 모니터링 검사 목록을 표시합니다. |
| `synthetics results <check>` | `--since`, `-n`, `--json` | 검사의 최근 실행 내역을 나열합니다. |
| `synthetics run <check>` | 변경 옵션 | 검사를 즉시 실행합니다. `--wait`를 지정하면 실행이 끝날 때까지 기다립니다. |
| `alerts rules export` | `--ids`, `-o`, `--output` | 알림 규칙을 번들로 내보냅니다. `--ids`를 지정하면 해당 규칙만 내보냅니다. [가져오기 및 내보내기](/ko/alerting/rules#가져오기-및-내보내기)를 참조합니다. |
| `alerts rules apply -f <file>` | `--dry-run`, `--create-only`, `--json` | 번들 또는 Prometheus 알림 규칙 파일을 적용합니다(`-f -`는 표준 입력을 읽습니다). 먼저 적용을 시뮬레이션해 각 규칙의 예상 동작을 출력한 뒤, 실패한 규칙이 없으면 모든 변경을 한 번에 저장합니다. 규칙이 하나라도 실패하면 CI에서 감지할 수 있도록 종료 코드 1을 반환합니다. |
| `alerts policies export`, `alerts schedules export`, `alerts routing export` | `--ids`, `-o`, `--output` | 에스컬레이션 정책, 온콜 일정 또는 라우팅 규칙을 번들로 내보냅니다. 번들에서는 사용자를 이메일 주소로, 나머지 항목을 이름으로 식별합니다. [가져오기 및 내보내기](/ko/alerting/on-call#가져오기-및-내보내기)를 참조합니다. |
| `alerts policies apply -f <file>`, `alerts schedules apply -f <file>`, `alerts routing apply -f <file>` | `--dry-run`, `--create-only`, `--json` | `alerts rules apply`와 같은 방식으로 번들을 적용합니다. 온콜 일정은 해당 일정의 담당자에게 알림을 보내는 정책보다 먼저 적용합니다. 정책은 해당 정책을 참조하는 알림 규칙과 라우팅 규칙보다 먼저 적용합니다. |

변경 옵션은 다음과 같습니다. [변경 실행 방식](/ko/cli/changes#변경-사항-실행-방식)을 참조합니다.

| 옵션 | 의미 |
|---|---|
| `--reason <text>` | 변경 사유를 지정합니다. 승인 내역과 감사 로그에 기록합니다. |
| `--wait` | 승인이 필요한 변경은 승인을 기다린 뒤 실행합니다. |
| `--timeout <duration>` | `--wait`의 대기 시간을 지정합니다. 기본값은 `30m`이며, `synthetics run`의 기본값은 `10m`입니다. |
| `-y`, `--yes` | MoleSignal이 변경 확인을 요청하면 입력을 기다리지 않고 바로 확인합니다. |

## 릴리스 및 데이터

이 명령어에는 API 토큰이 필요합니다. [CI 및 릴리스](/ko/cli/ci)를 참조합니다.

| 명령어 | 옵션 | 설명 |
|---|---|---|
| `deploy` | `--service`, `--version`, `--env`, `--namespace`, `--kind`, `--status`, `--commit`, `--repository`, `--pull-request`, `--author`, `--ci-url`, `--description`, `--time`, `--dry-run`, `-- <command>` | 배포를 기록합니다. |
| `source-maps upload <path>…` | `--application`, `--service`, `--release`, `--platform`, `--arch`, `--debug-id`, `--concurrency`, `--dry-run` | JavaScript 소스 맵을 업로드합니다. |
| `symbols upload <path>…` | `--application`, `--service`, `--release`, `--platform`, `--arch`, `--debug-id`, `--concurrency`, `--dry-run` | Flutter, Android, Apple 심볼을 업로드합니다. |
| `source-maps list`, `symbols list` | `--application`, `--service`, `--release`, `--platform`, `--kind`, `--json` | 업로드한 항목을 나열합니다. |
| `source-maps delete <id>`, `symbols delete <id>` | 없음 | 업로드한 항목을 삭제합니다. |
| `send <stream>` | `--field <name=value>`, `--raw`, `--batch` | 표준 입력에서 읽은 줄을 로그 스트림으로 전송합니다. |
| `run <stream> -- <command>` | `--name`, `--field <name=value>`, `--quiet` | 명령어를 실행하고 출력과 종료 상태를 로그 스트림으로 전송합니다. |

| 명령어 | 옵션 | 설명 |
|---|---|---|

| `call <tool> [name=value…]` | `--input`, `--since`, `--from`, `--to`, 변경 옵션 | 도구를 호출하고 결과를 JSON으로 출력합니다. |

## 환경 변수

| 변수 | 의미 |
|---|---|
| `MOLESIGNAL_URL` | `--url`로 지정한 주소나 저장된 주소 대신 사용할 MoleSignal 주소입니다. |
| `MOLESIGNAL_TOKEN` | 저장된 로그인 정보 대신 사용할 API 토큰입니다. |
| `MOLESIGNAL_PROFILE` | 현재 프로필 대신 사용할 프로필입니다. |
| `MOLESIGNAL_CONFIG` | 프로필을 저장하는 파일입니다. 기본값은 `~/.config/molesignal/config.json`입니다. |
| `HTTPS_PROXY`, `HTTP_PROXY` | 모든 요청에 사용할 프록시입니다. |
| `NO_PROXY` | 프록시를 거치지 않고 접속할 호스트입니다. |
| `NODE_EXTRA_CA_CERTS` | 시스템이 신뢰하는 인증 기관 외에 추가로 신뢰할 인증 기관의 인증서입니다. |
| `NO_COLOR` | 색상 없이 출력합니다. |
| `FORCE_COLOR` | 출력 대상이 터미널이 아니어도 색상을 적용합니다. |

옵션은 환경 변수보다 우선하며, 환경 변수는 저장된 프로필보다 우선합니다.

## 종료 코드

| 코드 | 의미 |
|---|---|
| `0` | 명령어가 성공했거나 실시간 스트림 추적을 중지했습니다. |
| `1` | 명령어가 실패했습니다. 실패 사유는 표준 오류로 출력합니다. `--wait`를 지정한 합성 모니터링 검사 실행이 실패하거나, `--fail-on-regression`을 지정한 상태에서 버전의 회귀가 감지되거나, `send`로 전송한 로그가 거부되거나, `doctor`의 점검 항목이 실패한 경우에도 이 코드를 반환합니다. |
| `2` | 알 수 없는 명령어, 옵션 또는 인수를 지정했습니다. |
| `3` | 변경이 승인 대기 중이어서 아직 실행하지 않았습니다. |

`deploy -- <command>`와 `run`은 실행한 명령어의 종료 코드를 그대로 반환합니다.
