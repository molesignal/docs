이 페이지의 명령은 MoleSignal API를 호출하며 API 토큰이 필요합니다. 파이프라인에서 `MOLESIGNAL_URL`과
`MOLESIGNAL_TOKEN`을 설정하거나 `--url`과 `--token`을 전달합니다. 토큰은
**ID 및 액세스 → API 토큰**에서 생성하고, 각 명령에 명시된 권한이 있는 역할을 지정합니다.

## 배포 보고

```bash
molesignal deploy --service checkout --version 2.4.0 --env production
```

APM은 서비스 타임라인에 배포를 표시하고 배포 버전을 이전 버전과
비교합니다. CI에서는 커밋, 리포지토리, 풀 리퀘스트, 작성자, 실행 링크를
GitHub Actions, GitLab CI/CD, Jenkins, CircleCI, Buildkite,
Bitbucket Pipelines 또는 Azure Pipelines 환경에서 가져옵니다. CI 외부에서는 커밋과 리포지토리를 git에서 가져옵니다.
토큰의 역할에는 `apm.deploy` 권한이 필요합니다.

`--` 뒤에 명령을 지정하면 CLI가 해당 명령을 먼저 실행하고, 종료 상태에 따라 배포 성공 또는 실패를
기록한 뒤 같은 종료 코드로 종료합니다.

```bash
molesignal deploy --service checkout --version 2.4.0 --env production -- ./scripts/deploy.sh
```

| 옵션 | 의미 |
|---|---|
| `--service <name>` | 스팬의 `service.name`에 지정된 서비스 이름입니다. 필수입니다. |
| `--version <version>` | 배포한 버전(`service.version`)입니다. 배포에는 버전이 필요합니다. |
| `--env <environment>` | 환경(`deployment.environment.name`)입니다. |
| `--namespace <namespace>` | 서비스의 `service.namespace`입니다. |
| `--kind <kind>` | `deployment`(기본값), `configuration` 또는 `feature_flag`입니다. |
| `--status <status>` | `succeeded`(기본값), `failed` 또는 `--version`으로 롤백했음을 나타내는 `rolled_back`입니다. |
| `--commit`, `--repository`, `--pull-request`, `--author`, `--ci-url` | CI 또는 git에서 가져온 값을 대신할 값입니다. |
| `--description <text>` | 배포 항목에 마우스 포인터를 올리면 표시하는 설명입니다. |
| `--time <time>` | 현재 시각 대신 기록할 배포 시각입니다. |
| `--dry-run` | 기록할 내용을 출력하지만 실제로 기록하지는 않습니다. |

이 필드는 [CI에서 배포 보고](/ko/apm/deployments#ci에서-배포-보고)의 필드와 같습니다.

## 소스 맵 업로드

```bash
molesignal source-maps upload dist/assets --application checkout-web --service web-frontend --release "$VERSION"
```

폴더 아래의 모든 `.map` 파일을 원래 파일 이름으로 업로드합니다. 파일 이름은 배포한
번들 이름에 `.map`을 붙인 것이어야 합니다. 파일은 전송 중에 gzip으로 압축하며, 한 번에 4개씩 처리합니다. `--concurrency`로
동시 처리 수를 변경합니다. 이름이 같은 맵은 서로 덮어쓰므로 명령이 이를 거부합니다.
`--application`, `--service`, `--release`는 RUM SDK가 보고하는
`applicationId`, `service`, `version`과 각각 일치해야 합니다. Flutter Web에서는 `--platform flutter`와
앱 빌드에 사용한 `--debug-id`를 추가합니다. 토큰의 역할에는 `debug_artifacts.manage` 권한이 필요합니다.

`--dry-run`은 업로드할 파일을 나열합니다. `molesignal source-maps list`는 업로드한 맵을 나열하고,
`molesignal source-maps delete <id>`는 지정한 맵을 삭제합니다.

## 모바일 및 네이티브 심볼 업로드

```bash
molesignal symbols upload build/molesignal-symbols --application checkout-app --service checkout --release 2.4.0 --debug-id "$BUILD_ID"
```

파일 유형에 따라 다음과 같이 업로드합니다.

| 파일 | 업로드 유형 |
|---|---|
| `--split-debug-info`로 생성한 `app.android-arm64.symbols` | Flutter 심볼입니다. 파일 이름에서 플랫폼과 아키텍처를 가져옵니다. `--debug-id`에는 앱 빌드에 사용한 `MOLESIGNAL_DEBUG_ID`를 지정합니다. |
| `mapping.txt` | Android R8 매핑입니다. |
| `libapp.so`와 같은 ELF 라이브러리 | Android 네이티브 심볼입니다. 파일에서 아키텍처와 빌드 ID를 읽습니다. |
| Apple `.dSYM` | 바이너리의 아키텍처별로 한 번씩 업로드하고, 각 아키텍처의 UUID를 파일에서 읽습니다. |

`--debug-id`, `--platform`, `--arch`는 파일에서 가져온 값을 재정의합니다. dSYM에서는 `--arch`로
아키텍처 하나만 선택합니다. `--dry-run`은 모든 파일을 각 파일에서 읽은 ID와 함께 나열합니다. `molesignal symbols list`는
업로드 목록을 표시하고 `molesignal symbols delete <id>`는 지정한 업로드를 삭제합니다. 토큰의 역할에는
`debug_artifacts.manage` 권한이 필요합니다. [RUM 소스 맵 및 심볼](/ko/rum/source-maps)에서 프레임을
매칭하는 방법을 설명합니다.

## 릴리스 확인

`molesignal synthetics run <check> --wait --yes`는 설정된 각 위치에서 합성 검사를 실행하고,
실패한 실행이 있으면 종료 코드 `1`을 반환합니다. `molesignal services compare <service> <baseline> <candidate>
--fail-on-regression`은 후보 버전에서 회귀가 발생하면 종료 코드 `1`을 반환합니다. 자세한 내용은
[인시던트 및 변경 사항](/ko/cli/changes#신세틱-검사-실행)과
[메트릭, 트레이스 및 서비스](/ko/cli/observe#두-버전-비교하기)를 참조합니다.

## 스트림에 줄 전송

`molesignal send`는 표준 입력의 각 줄을 로그 스트림으로 전송합니다. JSON 객체인 줄은 객체의 필드를 로그 필드로 사용하고,
나머지 줄은 `message`에 담습니다. 로그를 받는 대로 배치로 전송하므로 파일에
새로 추가되는 줄도 전송할 수 있습니다.

```bash
tail -f /var/log/app.log | molesignal send app_logs --field service=billing
```

`--field name=value`는 모든 로그에 필드를 추가하고, `--raw`는 모든 줄을 메시지로 전송합니다.
`--batch`는 요청당 최대 로그 수를 설정하며 기본값은 `500`입니다. 서버가 혼잡하면 요청을 재시도합니다.
MoleSignal이 로그를 거부하면 명령은 종료 코드 `1`을 반환합니다. 수집 토큰과 마찬가지로
토큰의 역할에는 `logs.write` 권한이 필요합니다.

## 작업 출력 보관

`molesignal run`은 명령을 실행하고 평소처럼 출력을 표시하면서 각 줄을 로그 스트림으로 전송합니다.
마지막으로 종료 상태와 소요 시간을 담은 로그를 하나 더 전송한 뒤, 실행한 명령과 같은 종료 코드로 종료합니다.

```bash
molesignal run jobs --name nightly-backup -- ./backup.sh --full
```

각 로그에는 `message`, `output`(`stdout` 또는 `stderr`), `command`, `run_id`,
`host` 필드가 있습니다. 마지막 로그에는 `exit_code`, `duration_ms`, `level`도 포함됩니다. `--quiet`는 화면에 출력을
표시하지 않고, `--field`는 필드를 추가합니다.

## GitHub Actions

주소와 토큰을 리포지토리 시크릿으로 저장한 뒤 배포 작업에 단계를 추가합니다.
`if: always()`를 지정하면 실패한 배포도 보고합니다.

```yaml
- name: Upload source maps
  run: npx -y @molesignal/cli source-maps upload dist/assets --application checkout-web --service web-frontend --release "${{ github.sha }}"
  env:
    MOLESIGNAL_URL: ${{ secrets.MOLESIGNAL_URL }}
    MOLESIGNAL_TOKEN: ${{ secrets.MOLESIGNAL_TOKEN }}

- name: Report the deployment
  if: always()
  run: npx -y @molesignal/cli deploy --service checkout --version "${{ github.sha }}" --env production --status "${{ job.status == 'success' && 'succeeded' || 'failed' }}"
  env:
    MOLESIGNAL_URL: ${{ secrets.MOLESIGNAL_URL }}
    MOLESIGNAL_TOKEN: ${{ secrets.MOLESIGNAL_TOKEN }}
```

## GitLab CI/CD

`MOLESIGNAL_URL`과 `MOLESIGNAL_TOKEN`을 마스킹된 CI/CD 변수로 추가한 뒤 배포 명령을
CLI를 통해 실행합니다.

```yaml
deploy:
  stage: deploy
  environment: production
  script:
    - npx -y @molesignal/cli deploy --service checkout --version "$CI_COMMIT_SHORT_SHA" -- ./scripts/deploy.sh
```

환경은 `environment`에서 가져오고, 커밋, 병합 요청, 작업 링크는 GitLab에서 가져옵니다.
