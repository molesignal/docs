**인바운드 MCP**를 사용하면 Claude Code, Cursor, Codex, ChatGPT 등의 MCP 클라이언트가
Mole Agent와 동일하게 정책이 적용되는 도구 런타임에서 MoleSignal의 기능을 검색하고 사용할 수 있습니다. 클라이언트는
다음 두 가지 방식 중 하나로 연결합니다.

- **stdio**(권장): 클라이언트가 npm
  패키지 `@molesignal/cli`의 `molesignal mcp` 명령으로 MoleSignal CLI를 실행합니다. CLI는 브라우저에서 한 번 로그인한 후 모든 메시지를
  아래 엔드포인트로 전달합니다.
- **Streamable HTTP**: 클라이언트가 엔드포인트를 직접 호출합니다.

엔드포인트는 다음과 같습니다.

```text
https://molesignal.example.com/api/v1/mcp
```

서버는 Streamable HTTP를 사용하며 MCP 프로토콜 버전 `2026-07-28`,
`2025-11-25`, `2025-06-18`, `2025-03-26`을 지원합니다. 레거시 HTTP+SSE는 노출하지 않으며, stdio는
CLI에서 제공합니다.

`agent.inbound_mcp.manage` 권한이 있는 관리자는 다음 메뉴에서 서버 설정을 변경할 수 있습니다.
**Mole Agent → 설정 → 인바운드 MCP**.

## 연결하기 전에

1. 루프백 주소가 아닌 배포 환경에서는 `http.external_url`에 MoleSignal의
   공개 오리진을 설정합니다. [구성](/ko/configuration)을 참조합니다.
2. **Mole Agent → 설정 → 인바운드 MCP**를 열고 서버가 활성화되어 있는지 확인합니다.
3. 페이지에 표시된 전체 엔드포인트를 스킴과 호스트를 포함하여 복사합니다.
4. OAuth 2.1, 개인 API 토큰 또는 서비스 계정 API 토큰을 선택합니다.

한도와 Origin 허용 목록을 변경하면
다음 MCP HTTP 요청이 시작될 때 적용됩니다. 처리 중인 요청은 기존 설정
스냅샷을 계속 사용합니다.

## stdio로 연결

MoleSignal CLI로 한 번 로그인합니다. Node.js 20 이상이 필요합니다.

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

브라우저에서 MoleSignal이 열리면 로그인을 승인합니다. CLI는 인증 정보를
`~/.config/molesignal/config.json`에 저장하고 갱신합니다. 이 파일은 해당 사용자만 읽을 수 있습니다. 그런 다음 `npx -y @molesignal/cli mcp` 명령으로 MoleSignal을
클라이언트에 stdio 서버로 추가합니다.

| 클라이언트 | 구성 |
|---|---|
| Claude Code | `claude mcp add --scope user molesignal -- npx -y @molesignal/cli mcp` |
| Cursor | `~/.cursor/mcp.json`에 `{"mcpServers": {"molesignal": {"command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` 추가 |
| Codex | `codex mcp add molesignal -- npx -y @molesignal/cli mcp` |
| VS Code | `.vscode/mcp.json`에 `{"servers": {"molesignal": {"type": "stdio", "command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` 추가 |
| Gemini CLI | `gemini mcp add molesignal npx -y @molesignal/cli mcp` |

`npx -y @molesignal/cli status`는 연결 상태를 확인하고 도구 수를 표시합니다. 브라우저를
사용할 수 없다면 로그인하는 대신 서버의 환경 변수로 `MOLESIGNAL_URL`과 `MOLESIGNAL_TOKEN`(API 토큰)을
설정합니다. `npm install -g @molesignal/cli`로 설치하면
`molesignal` 명령으로 CLI를 실행할 수 있습니다. 전체 명령은 [MoleSignal CLI](/ko/cli)를 참조합니다.

**Mole Agent → 설정 → 인바운드 MCP**의 **설정 프롬프트**는 에이전트
도구가 이 절차를 따르도록 안내합니다. 프롬프트 위에서 **stdio** 또는 **Streamable HTTP**를 선택합니다.

</Note>

## API 토큰으로 연결

API 토큰은 비대화형 클라이언트와 자동화에 유용합니다.

<Tabs>
  <Tab title="개인 API 토큰">
    **ID 및 액세스 → API 토큰**에서 토큰을 생성합니다. 토큰에는 현재 사용자 주체와
    해당 사용자에게 할당된 역할이 적용됩니다. 클라이언트의 시크릿 또는 환경 변수 기능을 사용해
    `Authorization: Bearer <token>` 형식으로 전달합니다.
  </Tab>
  <Tab title="서비스 계정 API 토큰">
    **ID 및 액세스 → 서비스 계정**에서 서비스 계정을 생성합니다. 계정을 생성하면
    해당 계정에 바인딩된 API 토큰 하나를 자동으로 발급하고 평문을 한 번만 표시합니다.

    서비스 계정은 비대화형 ID입니다. 웹 UI에 로그인하거나
    OAuth 권한 부여를 승인할 수 없습니다. 클라이언트의 시크릿 또는 환경 변수
    기능을 사용해 초기 토큰을 `Authorization: Bearer <token>` 형식으로 전달합니다.
  </Tab>
</Tabs>

API 토큰을 프로젝트 수준의 MCP 구성 파일에 커밋하지 않습니다. Codex 및 Claude Code
예제에서는 환경 변수를 사용하는 비대화형 구성을 보여 줍니다.

인바운드 MCP는 개인 API 토큰, 서비스 계정 API 토큰, OAuth 액세스 토큰만 허용합니다. 데이터 수집 및 RUM
자격 증명으로는 이 엔드포인트에 액세스할 수 없습니다. MCP
리소스, 도구, 실행 기록, 감사 기록에서는 자격 증명을 평문으로 반환하지 않습니다.

## OAuth 검색 및 토큰 수명

MoleSignal은 다음 위치에 OAuth 메타데이터를 게시합니다.

```text
https://molesignal.example.com/.well-known/oauth-protected-resource/api/v1/mcp
https://molesignal.example.com/.well-known/oauth-authorization-server
```

인증 서버는 PKCE `S256`을 적용한 인증 코드 방식, RFC 8707 리소스
바인딩, 동적 클라이언트 등록, 갱신 토큰 회전, 토큰 패밀리 폐기를 지원합니다.
액세스 토큰의 유효 기간은 1시간입니다. 갱신 토큰에는 `offline_access` 범위와
`refresh_token` 권한 부여 유형이 필요합니다. 유효 기간은 30일이며 사용할 때마다 교체됩니다.

다음 메뉴에서 활성 OAuth 연결을 확인하고 해제할 수 있습니다. **Mole Agent → 설정 → 인바운드
MCP**. 연결 목록 아래의 **설정 프롬프트**에는 이 배포 환경의 엔드포인트가 포함되어 있습니다.
**프롬프트 복사**를 선택하고 Claude Code나 Cursor 같은 에이전트 도구에 붙여넣으면 해당 도구가
MoleSignal을 MCP 서버로 추가합니다.

## 테넌트 경계 이해하기

엔드포인트, 사용자 지정 헤더 또는 도구 인수에 `userId`나 `orgId`를 넣어 전송하지 않습니다.
MoleSignal은 인증된 자격 증명에서 두 ID를 확인하고, 요청마다 최신 IAM
스냅샷을 다시 불러오며, MCP 세션을 처음 설정한 자격 증명에 바인딩합니다.

실제로 사용할 수 있는 도구 집합은 다음과 같습니다.

```text
Inbound MCP surface ∩ credential IAM permissions ∩ workspace Tool Policy
```

에이전트 프로필은 인바운드 MCP를 제한하지 않습니다. Mole Agent에 구성한 아웃바운드 MCP 서버와
해당 서버의 원격 도구는 이 엔드포인트에서 프록시하지 않습니다.

어떤 자격 증명을 사용해도 인바운드 MCP를 통해서는 [`_audit` 스트림](/ko/settings/data-security#감사-스트림)의
행이나 필드를 읽을 수 없습니다. **로그**에서 해당 스트림을 엽니다.

## 도구 어댑터로 시작하기

`tools/list`는 사용 권한이 있는 일부 도구만 표시합니다. 자주 사용하는 읽기 도구 7개, 승인 및 실행
제어 기능, 단계적으로 도구를 검색하는 어댑터 3개가 포함됩니다.

| 어댑터 | 용도 |
|---|---|
| `tool_search` | 사용 권한이 있는 인바운드 MCP 도구 카탈로그 전체를 검색합니다. |
| `call_read_tool` | 검색한 읽기 전용 도구 또는 사전 점검 도구를 실행합니다. |
| `call_managed_tool` | 필수 `idempotencyKey`를 지정해 검색한 관리형 변경을 실행합니다. |

프롬프트 예시:

- “MoleSignal 도구로 최근 인시던트를 검색한 다음, 아직 해결되지 않은 인시던트 중 영향이 가장 큰 인시던트를 요약합니다.”
- “상태 페이지 도구를 찾아 진행 중인 인시던트를 나열합니다. 변경하지 않습니다.”
- “이 알림 규칙을 테스트한 다음, 필요한 확인 또는 승인을 거친 후에만 업데이트합니다.”

도구 검색 스키마, 위험 수준, 승인
절차, 지원하는 제품 영역은 [도구 카탈로그 및 실행](/ko/tools)을 참조합니다.

## 런타임 제한

| 제한 항목 | 기본값 | 허용 범위 |
|---|---:|---:|
| 요청 크기 | 1 MB | 1–8 MB |
| 응답 크기 | 1 MB | 1–8 MB |
| 자격 증명당 동시 HTTP 호출 수 | 8 | 1–128 |
| 자격 증명당 분당 HTTP 호출 수 | 60 | 1–10,000 |
| 읽기 도구 시간 제한 | 30 seconds | 100 ms–300 seconds |

**Mole Agent → 설정 → 인바운드 MCP**에서 이 값을 변경합니다. 조직 도구 정책을 사용하면
개별 도구의 시간 제한이나 응답 크기 제한을 더 엄격하게 설정할 수 있습니다.

## 브라우저 Origin 및 Host 검사

브라우저가 아닌 MCP 클라이언트의 경우 `Origin` 헤더가 없는 요청도 허용합니다. 브라우저 요청은
동일 출처에서 오거나 인바운드 MCP 설정에 지정된 HTTP 또는 HTTPS Origin과 정확히 일치해야 합니다.

루프백을 사용하지 않는 배포에서는 요청의 `Host`가 `http.external_url`과 일치해야 합니다. 이 검사는
로컬 MCP 서버를 대상으로 하는 DNS 리바인딩 공격을 방지합니다.

## 연결 문제 해결

| 증상 | 확인 사항 |
|---|---|
| `401 missing Authorization Bearer token` | `codex mcp login molesignal`을 실행하거나 지원되는 API 토큰 환경 변수를 설정합니다. |
| 인증 페이지에서 로그인을 다시 요청함 | 웹 UI, `http.external_url`, MCP 엔드포인트에 동일한 스킴과 호스트를 사용합니다. `localhost`와 `127.0.0.1`을 혼용하지 않습니다. |
| `duplicate field resource` | 수동으로 설정한 `--oauth-resource`를 제거하고 엔드포인트를 다시 등록합니다. |
| OAuth 콜백에서 연결이 거부됨 | 브라우저가 MCP 클라이언트의 임시 루프백 콜백으로 리디렉션될 때까지 클라이언트를 계속 실행합니다. 리스너가 중지되었다면 `codex mcp login`을 다시 실행합니다. |
| MCP 엔드포인트가 `403`을 반환함 | 서버 활성화 여부, 브라우저 Origin, 자격 증명 상태, IAM 권한, 도구 정책을 확인합니다. |
| 도구가 표시되지 않음 | `tool_search`로 검색합니다. 일치하는 결과가 없으면 도구 노출 설정, IAM, 도구 정책을 확인합니다. |
