## 일반

### MoleSignal이란?

MoleSignal은 모든 구성 요소를 자체 호스팅할 수 있는 오픈 소스 관측 가능성 및 인시던트 대응 플랫폼입니다. 하나의 시스템에서 텔레메트리, 알림, 온콜, 상태 페이지, AI 조사를 제공합니다. 로그, 메트릭, 트레이스, 프로파일을 오브젝트 스토리지에 Parquet 파일로 저장하고 SQL 및 PromQL 호환 쿼리로 조회합니다. [핵심 개념](/ko/concepts)을 참조합니다.

### 어떤 라이선스를 적용합니까?

MoleSignal은 Apache License 2.0을 적용하는 오픈 소스 소프트웨어입니다. [오픈 소스 에디션](/ko/editions/open-source)을 참조합니다.

### 호스팅 버전이 있습니까?

MoleSignal Cloud는 호스팅 서비스입니다. 자세한 내용은 [molesignal.com/cloud](https://www.molesignal.com/cloud)에서 확인합니다.

### 배포에 어떤 서비스가 필요합니까?

PostgreSQL과 오브젝트 스토리지가 필요합니다. 단일 노드 배포와 개발 환경에서는 `local` 오브젝트 백엔드로 오브젝트 스토리지를 대체합니다. Kafka, Redis, 합의 서비스는 필요하지 않습니다. [MoleSignal 배포](/ko/deployment)를 참조합니다.

### 메타데이터를 어느 데이터베이스에 저장합니까?

PostgreSQL에 저장합니다. `[meta_database].dsn`에 PostgreSQL 연결 문자열을 설정합니다. [구성](/ko/configuration#메타데이터-데이터베이스)을 참조합니다.

### 컨테이너 없이 MoleSignal을 실행할 수 있습니까?

예. MoleSignal은 단일 바이너리로 배포합니다. [배포 가이드](/ko/deployment)에서는 Docker Compose, systemd를 이용한 바이너리 실행, Kubernetes를 다룹니다.

## 데이터

### 데이터를 어디에 저장합니까?

로그, 메트릭, 트레이스는 오브젝트 스토리지에 Parquet 파일로 저장합니다. PostgreSQL에는 메타데이터, ID, 파일 카탈로그, 제품 리소스를 저장합니다. 아직 플러시하지 않은 레코드는 오브젝트 스토리지에 쓰기 전 로그(WAL) 오브젝트로 보관하므로 노드나 디스크가 손실되더라도 수신 확인을 완료한 레코드는 유실되지 않습니다. [백업 및 복원](/ko/backup-restore)을 참조합니다.

### 데이터를 얼마나 오래 보존합니까?

기본값은 30일입니다. `_sys` 조직의 **설정 → 데이터 보존**에서 기본값을 설정하며, 스트림별로 보존 기간을 지정할 수 있습니다. [스트림](/ko/streams)을 참조합니다.

### 어떤 프로토콜로 데이터를 수집합니까?

HTTP 및 gRPC를 사용하는 OTLP, Prometheus `remote_write`, Elasticsearch `_bulk` 프로토콜, JSON 형식의 Loki 푸시, HTTP를 사용하는 네이티브 JSON, Kinesis Firehose, Cloudflare Logpush, Heroku 로그 드레인을 지원합니다. [데이터 소스](/ko/intake)를 참조합니다.

### 레코드가 잘못된 시각에 표시되는 이유는 무엇입니까?

`_timestamp`는 Unix 에포크 이후 경과한 시간을 마이크로초 단위로 나타냅니다. 값을 초, 밀리초 또는 나노초 단위로 입력하면 레코드가 잘못된 시각에 표시됩니다. [문제 해결](/ko/troubleshooting#데이터-누락-또는-이상)을 참조합니다.

### SQL 클라이언트로 어떻게 쿼리합니까?

`[flight_sql]`을 활성화하고 API 토큰을 사용해 DBeaver, JDBC 또는 ADBC 클라이언트를 `5083` 포트에 연결합니다. [데이터베이스 클라이언트로 연결](/ko/query/database-clients)을 참조합니다.

### Grafana에서 MoleSignal 데이터를 조회할 수 있습니까?

예. MoleSignal 데이터 소스 플러그인을 사용하면 대시보드, Explore, 알림 규칙에서 PromQL로 메트릭을, 필드 쿼리로 로그와 트레이스를, SQL로 모든 스트림을 조회할 수 있습니다. [Grafana에서 쿼리](/ko/query/grafana)를 참조합니다.

## 계정 및 보안

### 처음에는 어떻게 로그인합니까?

MoleSignal은 새로 배포할 때 `[auth].root_email`과 `[auth].root_password`를 사용해 루트 계정을 생성합니다. 예제 구성에서는 `admin@example.com`과 `admin`을 사용합니다. 운영 환경에서 사용하기 전에 두 값을 모두 변경합니다. [운영 환경 체크리스트](/ko/deployment/production-checklist)를 참조합니다.

### 비밀번호를 잊어버리면 어떻게 재설정합니까?

로그인 페이지의 비밀번호 재설정 링크를 사용합니다. MoleSignal은 링크를 이메일로 전송하므로 `[notify.smtp]`와 `[http].external_url`을 설정해야 합니다.

### 로그인 시도 실패 횟수가 한도를 초과하면 어떻게 합니까?

표시된 시간이 지날 때까지 기다리거나 패스키, 싱글 사인온, 비밀번호 재설정을 사용합니다. 모든 사용자의 로그인이 동시에 차단되면 [클라이언트 IP 인식](/ko/settings/platform#클라이언트-ip-식별)을 확인합니다. 프록시를 사용하면서 관련 설정을 하지 않으면 MoleSignal이 모든 사용자를 하나의 주소로 처리합니다. 구체적인 한도는 [로그인 제한](/ko/settings/platform#로그인-제한)을 참조합니다.

### 싱글 사인온을 지원합니까?

예. 웹 UI의 **ID 및 액세스 → SSO 공급자**에서 Google, Microsoft, GitHub, Feishu 등 사전 정의된 플랫폼과 OIDC, OAuth 2.0, SAML, LDAP 공급자를 구성합니다. MoleSignal은 이 구성을 PostgreSQL에 저장합니다. [ID 및 액세스](/ko/identity)를 참조합니다.

### `MS_CIPHER_KEY`는 무엇을 보호합니까?

MoleSignal이 PostgreSQL에 저장하는 API 토큰, 알림 커넥터 자격 증명, Mole Agent 공급자 키 등의 시크릿을 보호하는 루트 키입니다. 이 키의 백업을 보관합니다. [운영 환경 체크리스트](/ko/deployment/production-checklist)를 참조합니다.

## 운영

### 배포를 어떻게 확장합니까?

`standalone` 노드 하나로 시작합니다. 데이터 수집, 쿼리, 백그라운드 작업을 각각 확장하려면 역할을 별도 프로세스로 분리합니다. `router` 역할은 웹 UI와 API를 제공하고, 쓰기 요청을 `intake` 노드로, 쿼리를 `querier` 노드로 전달합니다. [역할 기반 배포](/ko/deployment/role-based)와 [알려진 제한 사항](/ko/limitations)을 참조합니다.

### 실행 중인 버전을 어떻게 확인합니까?

`molesignal --version`을 실행하거나 Bearer 토큰을 사용해 `GET /api/v1/version`을 호출합니다.

### 어디에서 지원을 받거나 문제를 신고합니까?

[지원 및 커뮤니티](/ko/support)를 참조합니다. 보안 문제는 해당 페이지에 안내된 채널을 통해 비공개로 신고합니다.
