활성 워크스페이스에서 로그 스트림을 검색하려면 **로그**를 엽니다.

## 스트림과 시간 범위 선택

로그 스트림을 선택한 다음 이벤트가 포함되는 가장 작은 시간 범위를 설정합니다. 좁은 시간 범위는
스캔하는 행 수를 줄이고 필드 탐색을 더 빠르게 합니다.

MoleSignal은 이벤트가 들어오는 동안 스트림 스키마를 추론할 수 있습니다. **필드** 패널은 스트림의
필드를 나열하고 전체 쿼리를 다시 작성하지 않고 필터를 추가합니다.

## 쿼리 탭

모든 쿼리는 자체 탭에서 실행됩니다. 탭은 스트림, 쿼리, 시간 범위를 유지하며, 한 탭의 쿼리는
다른 탭에 영향을 주지 않습니다.

- 다른 쿼리를 열려면 **새 탭**을 선택합니다. 한 번에 최대 10개의 탭을 열 수 있습니다.
- 탭 메뉴를 열어 **이름 변경**, **복제**, **닫기**를 수행합니다.
- 두 탭을 나란히 표시하려면 **화면을 둘로 분할**을 선택합니다. 각 절반에는 자체 탭이 나열되며, 탭은
  메뉴에서 반대쪽으로 이동합니다. **단일 화면으로 돌아가기**를 선택하면 분할이 종료됩니다.

열린 탭은 사용자와 워크스페이스별로 브라우저에 유지됩니다.

## 쿼리 작성

편집기에는 **코드**와 **빌더** 두 가지 모드가 있으며, 제목 옆의 두 아이콘(`</>`는
코드, 블록 아이콘은 빌더)으로 전환합니다. 각 아이콘은 마우스를 올리면 이름이 표시됩니다.

**코드**는 필드 쿼리 또는 SQL을 입력받습니다. `SELECT` 또는 `WITH`로 시작하는 구문은 SQL로 실행됩니다.
그 외의 구문은 필드 쿼리로 실행됩니다:

| 필드 쿼리 | 의미 |
|---|---|
| `service = 'checkout'` | 필드 값이 정확히 이 값입니다. |
| `message contains 'timeout'` | 필드에 텍스트가 포함되어 있습니다. |
| `MATCH(message, 'timeout')` | 대소문자를 구분하지 않는 부분 문자열 검색입니다. |
| `MATCH_TEXT(message, 'timeout disk')` | 전체 텍스트 인덱스가 있는 필드에서 전체 텍스트 검색을 수행합니다. |

조건은 대소문자에 관계없이 `AND`와 `OR`로 결합합니다. `AND`는 `OR`보다 우선하며, 괄호는
조건을 그룹화합니다: `level = 'error' AND (service = 'checkout' OR service = 'payments')`. 필드가 없는 텍스트는
`message` 필드에서 검색되며 다음 대안 중 하나일 수 있습니다:
`timeout OR \"connection reset\"`. 따옴표는 `or`와 같은 단어가 포함된 구문도 하나의 구문으로 유지합니다.
`=`, `!=`, `>`, `>=`, `<`, `<=`로 비교합니다.

**빌더**는 동일한 필드 쿼리를 필터 행으로 표시하며, 각 대안마다 한 행이 표시됩니다: 한
행의 필터는 모두 충족되어야 하며, 첫 번째 이후의 모든 행 앞에는 **또는**이 표시됩니다. **필터**를
선택하여 행에 추가하고, **또는**을 선택하여 행을 추가한 다음 필드, 비교 연산자, 값을 선택합니다. 각
행에는 자체 검색 텍스트가 있습니다. 행 내부의 괄호 부분(예: 위 예시의 `OR`)은
작성된 그대로 유지되며 **코드**에서 변경합니다. SQL인 구문은 필터로 표시할 수 없습니다.

조인, 표현식, CTE 또는 집계에는 SQL을 사용합니다:

```sql
SELECT "_timestamp", level, msg, trace_id
FROM app
WHERE level = 'error'
ORDER BY "_timestamp" DESC
LIMIT 200;
```

```sql
SELECT level, COUNT(*) AS events
FROM app
GROUP BY level
ORDER BY events DESC;
```

쿼리를 실행하려면 **실행**을 선택하거나 편집기에서 `⌘ Enter` 또는 `Ctrl+Enter`를 누릅니다. **쿼리 구문
참조**에는 현재 모드의 예시가 나열됩니다. 텍스트 검색 함수는 [쿼리](/ko/query#텍스트-검색)를
참조하세요.

쿼리 플래너는 사용자 지정 SQL에도 현재 조직 경계를 적용합니다.

## 필드 탐색

**필드** 패널은 **표시된 필드**, **인덱싱된 필드**, **기타
필드**의 세 부분으로 구성됩니다. 점으로 구분된 이름의 첫 부분을 공유하는 필드(예: `http.method`와
`http.route`)는 하나의 그룹으로 열립니다.

- 결과에서 필드의 가장 흔한 값을 보려면 필드를 엽니다. 값을 포함 필터 또는
  제외 필터로 추가합니다. 필터는 전체 쿼리를 좁힙니다. 대안으로 구성된 쿼리는
  해당 필터 앞에서 괄호로 묶입니다.
- 결과의 열로 필드를 표시하거나 숨깁니다.
- 필드에서 **분석**을 선택하여 필드 분석을 엽니다: 고유 값 수, 값이 있는 행과
  값이 없는 행, 숫자 필드의 통계, 값 분포, 가장
  흔한 값의 시간별 추이를 표시합니다.

## 결과 읽기

결과 위의 히스토그램은 시간 범위에서 쿼리와 일치하는 모든 이벤트를 집계하며, 로드된
페이지에만 국한하지 않습니다. 결과는 네 가지 보기로 확인합니다:

| 보기 | 내용 |
|---|---|
| **로그** | 일치하는 이벤트를 각각 한 행으로 표시합니다. |
| **통계** | 집계 차트입니다. 측정값(개수, 고유 개수, 평균, 합계, 최솟값, 최댓값, P50, P95, P99), 그룹화, 차트 유형을 선택하거나 SQL 집계 결과를 그립니다. **대시보드 만들기**는 차트를 새 대시보드의 패널로 저장합니다. |
| **AI 분석** | 쿼리와 일치하는 로그에 대해 Mole Agent가 작성한 보고서입니다. [로그 검사](/ko/logs/inspections)를 참조하세요. |
| **패턴** | 패턴별로 그룹화된 이벤트와 각 패턴의 개수 및 비율입니다. |

**패턴** 보기는 서버에서 전체 시간 범위의 패턴을 집계합니다. 이벤트가 5,000개를 초과하는
범위는 범위 전체에 분산된 샘플로 읽으며, 각 개수는 범위에 맞게 조정되어
`≈`와 함께 표시됩니다. 패턴 아래의 줄에는 해당 범위의 이벤트 수와 읽은 이벤트 수가
표시됩니다. **변경**은 각 패턴을 옆에서 선택한 기준선과 비교합니다: 동일한 길이의
이전 기간(기본값), 일주일 전의 동일한 기간, 또는 없음 중에서 선택합니다. **새로 만들기**는 기준선에
없던 패턴을 표시하고, `×N`은 최소 5개 이상 이벤트가 늘면서 두 배 이상 증가한 패턴, **감소**는
절반으로 줄어든 패턴을 표시합니다. 패턴을 열면 해당 패턴에 속한 로드된 이벤트 또는 로드된 이벤트가 없을 때 해당 패턴의 메시지 하나가
표시됩니다. SQL로 작성된 구문은 반환한 이벤트를 기준으로 그룹화됩니다.

**로그** 보기에서:

- **열**에서 열을 선택하고 순서를 지정합니다. 기본 열은 스트림의 필드에서 가져옵니다:
  시간, 그다음 스트림에 해당 필드가 있으면 수준, 서비스, 메시지 필드 순입니다.
- 페이지 크기는 100, 200, 500, 1,000, 2,000 또는 5,000개 이벤트입니다.
- 이벤트를 클릭하면 결과 옆의 드로어에서 열립니다. 드로어의 왼쪽 가장자리를 끌어 크기를 조정할 수 있으며,
  너비는 유지됩니다. 헤더에는 수준, 시간, 메시지, 그리고 이벤트를 설명하는 속성
  (서비스, 호스트, 환경, 버전, 트레이스)이 표시되며, 각 속성에는 필드와 동일한 작업이 제공됩니다.
  보기는 **필드**, 이벤트에 트레이스 ID가 있을 때 **트레이스**, **컨텍스트**, 그리고
  **원본 JSON**입니다. **트레이스**는 이벤트의 스팬이 선택된 상태로 트레이스의 워터폴을 표시합니다. **컨텍스트**는
  양쪽에 각각 다섯 개의 주변 행을 표시합니다. 필드에서 필터를 추가하거나, 값을 복사하거나, 필드를
  열로 표시할 수 있습니다.
- 식별자가 있으면 트레이스, 서비스, 메트릭 또는 기타 상관된 신호로 피벗합니다.
- 결과를 CSV, 텍스트 또는 JSON으로 다운로드합니다.

## 쿼리 공유

페이지 주소는 화면에 표시된 쿼리입니다. 쿼리가 실행되면 페이지는 스트림, 쿼리문
(`q`는 필드 쿼리, `sql`은 SQL), 결과 보기를 주소에 기록하므로
주소 표시줄을 복사하면 선택기에 표시된 시간 범위(예: 지난
1시간)로 쿼리가 공유됩니다. 페이지를 새로고침해도 쿼리와 편집기는 그대로 유지됩니다.

화면의 쿼리 링크를 복사하려면 **공유**를 선택합니다. 링크는 데이터를 읽을 수 있는 조직의
로그인한 구성원에게 열립니다. 링크의 시간 범위를 선택합니다: **현재 선택한 시간 범위**는
화면의 시점으로 범위를 고정하며, 다른 선택지는 지난 1시간과 같은 상대 범위를
링크를 연 시점부터 계산하여 유지합니다.

## 검색 작업

대화형 요청에 비해 너무 큰 검색은 검색 작업으로 실행됩니다. 작업을 추적하고 결과를 다운로드하려면
**스트림 → 검색 작업**을 엽니다. 참조:
[스트림](/ko/streams#검색-작업).

## 저장된 보기

SQL 쿼리를 이름으로 저장하여 [저장된 보기](/ko/saved-views)로 보관합니다. 보기를 다시 열고, 쿼리를
다른 시간 범위에서 실행하거나, 보기를 보고서에 첨부합니다.

<Tip>
  `service.name`, `deployment.environment`, `trace_id`, `host.name`과 같은 안정적인 차원은
  수집 시 유지합니다. 이 필드는 교차 신호 피벗을 안정적으로 만듭니다.
</Tip>

## 권한

- `streams.read`는 스트림과 스키마를 검색합니다.
- `logs.read`는 로그 목록, 히스토그램, 필드 통계를 읽습니다.
- `streams.query`는 SQL 문을 실행하고 컨텍스트를 엽니다.
- `agent.use`는 AI 검사를 실행하며, 활성화된 AI 모델도 필요합니다.
- `saved_views.create`, `saved_views.edit`, `saved_views.delete`는 저장된 뷰를 관리합니다.
