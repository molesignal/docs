MoleSignal은 역할 이름을 비교하지 않고 권한 키로 작업을 인가합니다. 사용자는
여러 조직에 속할 수 있으며 조직마다 다른 권한을 보유할 수 있습니다. 현재 워크스페이스의
액세스를 관리하려면 메뉴에서 **ID 및 액세스**를 엽니다.

| 그룹 | 섹션 | 가이드 |
|---|---|---|
| 멤버 | **사용자**, **초대**, **승인** | [멤버](/ko/identity/members) |
| 조직 | **조직**, **팀** | [조직 및 팀](/ko/identity/teams) |
| 권한 및 제한 | **역할**, **권한 정책**, **액세스 권한 부여** | [역할, 정책 및 액세스 권한 부여](/ko/identity/roles) |
| 인증 및 액세스 | **API 토큰**, **서비스 계정** | [API 토큰 및 서비스 계정](/ko/identity/tokens) |
| | **SSO 공급자**, **이메일 도메인** | [싱글 사인온](/ko/identity/sso) |

## 인가 방식

인증된 요청에 대해 MoleSignal은 다음 항목을 확인합니다.

1. 주체: 사용자, 서비스 계정 또는 API 토큰
2. 활성 조직 또는 보호된 플랫폼 범위
3. 주체에 할당된 역할과 부여된 액세스 권한
4. 리소스 관계와 수락된 조직 간 액세스 권한 부여
5. 라우트와 대상 리소스에 필요한 권한

MoleSignal은 권한 카탈로그, 기본 제공 역할, 권한 정책을 PostgreSQL에 저장합니다.
`GET /api/v1/iam/capabilities`는 웹 애플리케이션이 탐색 메뉴를 구성하는 데 사용하는
유효 권한을 반환합니다.

<Warning>
  페이지가 표시되거나 역할 레이블이 있다고 해서 작업이 인가되는 것은 아닙니다. 서버는
  보호된 작업마다 필요한 권한과 리소스의 소유권을 확인합니다.
</Warning>

## 권한 범위

조직 권한은 하나의 워크스페이스에 적용됩니다. 예시는 다음과 같습니다.

- `org.preferences.read` 및 `org.preferences.manage`
- `org.members.read` 및 `org.members.update`
- `iam.roles.read`, `iam.roles.manage`, `iam.grants.read` 및 `iam.grants.manage`
- 스트림, 대시보드, 알림, 일정, 저장된 뷰, 파이프라인, 함수,
  보고서, 감사, 로그 검사 및 Mole Agent 관련 권한

플랫폼 권한은 `sys.`로 시작하며 `_sys` 조직에만 적용됩니다. 이 권한은
인스턴스의 조직, 시스템 텔레메트리, 트레이스 디버깅, 플랫폼 관리자 및
플랫폼 설정을 제어합니다.

## 기본 제공 역할

| 역할 | 보유 권한 |
|---|---|
| **소유자** | 카탈로그의 모든 조직 권한을 보유하며 플랫폼 권한은 보유하지 않습니다. |
| **관리자** | 제품 기능 영역뿐 아니라 설정, 멤버, 역할, 액세스 권한 부여, 토큰, 감사, 상태 페이지, 신세틱 모니터링, 서비스 수준, 사후 분석, Mole Agent 관리까지 모든 조직 권한을 보유합니다. |
| **편집기** | 스트림, 대시보드, 알림 및 일정, 저장된 뷰, 파이프라인, 함수, 보고서, APM 및 RUM 설정을 조회하고 변경하며, Mole Agent 자동화와 로그 검사를 실행합니다. |
| **뷰어** | 데이터, 대시보드, 알림 및 일정, 저장된 뷰, 파이프라인, 함수, 보고서를 조회하고 Mole Agent와 채팅합니다. |

[권한 참조](/ko/identity/roles#권한-참조)에는 모든 권한과
각 권한을 보유한 기본 제공 역할이 나와 있습니다. 기본 제공 역할은 편집할 수 없습니다. 업그레이드로 추가한 권한은
시작 시 소유자 역할에 부여됩니다.

담당 범위가 더 좁다면 [사용자 지정 역할](/ko/identity/roles#역할)을 만듭니다.

## 플랫폼 액세스

인스턴스에 구성한 `root` 계정은 최고 관리자입니다. 이 계정에는 역할이 필요하지 않습니다.
모든 조직에서 해당 조직의 권한을, `_sys`에서는 플랫폼 권한을 보유하지만
어느 곳에서도 소유자 역할을 갖지 않습니다. 이 계정의 API 토큰은
토큰이 속한 조직의 권한만 보유하며 플랫폼 권한은 보유하지 않습니다.

다른 계정은 권한을 부여받아야 플랫폼에 액세스할 수 있습니다. `_sys`의 **ID 및 액세스**에는 별도의
**역할**, **권한 정책**, **액세스 권한 부여**가 있으며, 이를 이용하려면 `sys.administrators.read` 및
`sys.administrators.manage` 권한이 필요합니다. 기본 제공 플랫폼 역할은 두 가지입니다.

| 역할 | 보유 권한 |
|---|---|
| `platform_admin` | 모든 플랫폼 권한을 보유합니다. |
| `platform_viewer` | 조회만 허용하는 모든 플랫폼 권한을 보유합니다. |

이메일로 계정을 찾아 권한을 부여합니다. 계정은 조직에 속하지 않아도 됩니다. 부여 범위는
플랫폼 전체 또는 지정한 조직 하나입니다. 조직을 지정하면 `sys.organizations.read`, `.update`,
`.disable`, `.delete`만 해당 조직에 한해 적용됩니다. 플랫폼 전체 범위에서 보유하지 않은 권한은
부여할 수 없으며, 권한 부여를 제거하면 다음 요청부터 액세스할 수 없습니다.

## 워크스페이스 간 액세스

액세스 권한을 부여하면 한 조직의 주체를 다른 조직의 리소스에 연결할 수 있습니다. 서버는
이 관계와 리소스 권한을 함께 확인합니다. 권한을 부여해도 다른 조직이
주체의 활성 워크스페이스로 바뀌지 않습니다. 다음 가이드를 참조합니다.
[조직 간 리소스 공유](/ko/identity/roles#조직-간-리소스-공유).

대시보드와 보고서는 [리소스 공유](/ko/resource-sharing)도 지원합니다. 공개 공유에서는
멤버십 대신 제한된 공유 세션을 제공합니다.

## 플랫폼 관리

`_sys` 조직은 조직 IAM과 분리되어 있습니다. 테넌트 세션과 `mspat-*` 토큰으로는
시스템 텔레메트리나 플랫폼 관리자 목록을 조회할 수 없습니다. 필요한
`sys.*` 권한이 있는 `_sys` 세션을 사용합니다. [관리 개요](/ko/administration)를 참조합니다.
