MoleSignal은 공급자 자격 증명을 수신자 및 라우팅과 분리합니다. 커넥터를 한 번 구성하고,
사용자 ID 또는 대체 대상을 연결한 다음, 알림 엔진이 해당 경로를 사용할
시점을 선택합니다.

| 리소스 | 용도 |
|---|---|
| **커넥터** | 조직 수준의 공급자 자격 증명과 전송 설정을 저장합니다. |
| **사용자 라우팅** | 공급자별 사용자 ID를 연결하고 개인 전송 엔드포인트의 순서를 지정합니다. |
| **정책** | 이벤트를 매칭하고 수신자를 결정하며, 템플릿을 선택하고 에스컬레이션을 제어합니다. |
| **템플릿** | 채널별로 재사용할 수 있는 메시지 본문입니다. 공통 템플릿을 모든 채널에 사용하거나 SMS, 전화 등 채널별로 별도 템플릿을 지정할 수 있습니다. |
| **대체 경로** | 개인 전송이 실패한 후 사용할 팀 및 조직 대상과 그 순서를 지정합니다. |
| **전송 로그** | 전송 시도, 지연 시간, 오류, 재시도, 확인 응답, 에스컬레이션을 확인합니다. |

모든 커넥터의 제한 시간은 1~60초로 설정해야 합니다. URL은 `http` 또는 `https`로 시작하는 절대
URL이어야 합니다.

유형 선택 메뉴에서는 커넥터 유형을 **인스턴트 메시징**, **전화 통화**, **SMS**
(WhatsApp 포함), **이메일**, **통합**으로 구분합니다. **통합**에는 PagerDuty, Amazon SNS,
웹훅이 포함됩니다.

커넥터는 공급자 주소를 복사할 수 있는 읽기 전용 값으로 표시합니다. Alibaba Cloud, Tencent Cloud,
AWS(Amazon SNS 포함)는 선택한 리전의 API 기본 URL을 사용하고, PagerDuty는 선택한
서비스 리전의 주소를 사용합니다. Lark 앱과 Slack 앱은 선택한 플랫폼의 주소를, Teams 봇은
선택한 클라우드의 서비스 URL을 사용합니다. 그 외 커넥터는 WeCom 스마트 봇의 장기
연결 주소나 이메일 커넥터의 Microsoft 로그인 주소처럼 공급자의 고정 주소를 사용합니다. Huawei Cloud는 예외입니다.
주소가 애플리케이션마다 다르고 API에서 조회할 수 없으므로 콘솔에서 복사해 입력합니다. 커넥터를 저장하거나 테스트하거나 알림을 직접 전송하기 전에
MoleSignal은 주소를 공급자의 목록과 대조하고, API를 통해 입력한 주소가 목록에 없으면 거부합니다.
따라서 자격 증명을 다른 주소로 보내지 않습니다. 저장한 커넥터의 유형은 변경할 수 없습니다.

Mattermost 봇이나 Matrix 봇의 서버 주소는 웹훅 URL과 마찬가지로 직접 입력합니다. MoleSignal은
호스트 이름을 확인해 얻은 주소에만 연결하고, 클라우드 메타데이터 주소에는 연결하지 않으며,
리디렉션을 따르지 않습니다.

## 커넥터 생성 및 테스트

커넥터를 조회하려면 `notify.connectors.read` 권한이 필요합니다. 커넥터를 생성, 편집, 테스트, 활성화, 비활성화하거나
삭제하려면 `notify.connectors.manage` 권한이 필요합니다.

<Steps>
  <Step title="알림 관리 열기">
    **설정 → 알림 → 커넥터**로 이동합니다.
  </Step>
  <Step title="공급자 선택">
    **새 커넥터**를 클릭하고 고유한 이름을 입력한 후 커넥터 유형을 선택합니다. 커넥터를 생성한 후에는
    유형을 변경할 수 없습니다.
  </Step>
  <Step title="공급자 설정 입력">
    아래에 설명된 인증 정보와 전송 설정을 입력합니다. 나중에 사용할 커넥터를 준비하는 경우가 아니라면 **이 커넥터에서
    알림 전송 허용** 옵션을 활성화 상태로 유지합니다.
  </Step>
  <Step title="커넥터 저장">
    **커넥터 저장**을 클릭합니다. MoleSignal은 전체 구성을 암호화하여 저장합니다. API 응답은
    민감한 값을 `***`로 대체합니다.
  </Step>
  <Step title="테스트 알림 전송">
    저장한 커넥터를 편집하고 호환되는 대상 유형을 선택한 후 실제 대상을 입력하고
    **연결 테스트**를 클릭합니다. 커넥터 상태는 최근 테스트 결과에 따라
    **연결됨** 또는 **오류**로 바뀝니다.
  </Step>
</Steps>

<Note>
  새 커넥터는 테스트하기 전에 저장합니다. 커넥터를 편집할 때 `***`로 가려진 값을 변경하지 않으면
  저장된 비밀 값이 유지됩니다.
</Note>

## 공급자별 구성

### 이메일 SMTP

SMTP 호스트, 포트, 유효한 **보낸 사람 주소**를 입력하고 MoleSignal의 로그인 방식을
**인증**에서 선택합니다.

| 인증 | 입력 항목 |
|---|---|
| **사용자 이름 및 비밀번호** | 서버에서 요구하는 경우 **사용자 이름**을 입력하고, **비밀번호**를 입력합니다. 메일 공급자가 앱 비밀번호나 인증 코드를 요구하면 해당 값을 비밀번호로 입력합니다. |
| **Microsoft 365 (OAuth 2.0)** | Microsoft Entra ID에 등록한 앱의 **테넌트 ID**, **클라이언트 ID**, **클라이언트 시크릿**을 입력합니다. **사용자 이름**에는 발신 사서함을 입력합니다. [Microsoft 365](#microsoft-365)를 참조합니다. |
| **Google Workspace (OAuth 2.0)** | 도메인 전체 위임 권한이 있는 서비스 계정의 **서비스 계정 키(JSON)**를 입력합니다. **사용자 이름**에는 발신 사서함을 입력합니다. [Google Workspace](#google-workspace)를 참조합니다. |

두 OAuth 2.0 방식은 비밀번호 대신 액세스 토큰(SASL XOAUTH2)으로 로그인하므로 공급자가 비밀번호 로그인을
비활성화해도 계속 작동합니다. Microsoft는 2026년 말에 기존 Exchange Online 테넌트에서 SMTP
AUTH의 기본 인증을 기본적으로 비활성화합니다. MoleSignal은 토큰을 만료 1분 전까지
재사용하며, 전송에 실패하면 다시 로그인합니다.

다음 TLS 모드 중 하나를 선택합니다.

| TLS 모드 | 사용 사례 |
|---|---|
| `none` | SMTP 연결에 TLS를 사용하지 않습니다. 신뢰할 수 없는 네트워크에서는 사용하지 않습니다. |
| `starttls` | 서버가 STARTTLS로 연결을 업그레이드합니다. 일반적으로 포트 `587`을 사용합니다. |
| `tls` | 처음부터 TLS로 연결합니다. 일반적으로 포트 `465`를 사용합니다. |

테스트 대상으로 `fixed_address` 또는 `direct_user`를 사용하고 다음과 같이 유효한 사서함을
입력합니다: `oncall@example.com`.

#### Microsoft 365

MoleSignal은 Microsoft Entra ID에 등록된 앱으로 로그인하고 사서함 하나를 발신에 사용합니다.
글로벌 Microsoft 클라우드만 지원하며, **로그인 URL**은 다음 주소로 고정됩니다.
`https://login.microsoftonline.com`

<Steps>
  <Step title="앱 등록">
    Microsoft Entra ID에서 앱을 등록합니다. **API 권한**에서 **Office 365 Exchange
    Online** 애플리케이션 권한 `SMTP.SendAsApp`을 추가하고 관리자 동의를 부여합니다. **인증서 및
    비밀**에서 클라이언트 시크릿을 만듭니다. 테넌트 ID와 클라이언트 ID는 앱의 **개요**
    페이지에서 확인합니다.
  </Step>
  <Step title="Exchange Online에 앱 등록">
    Exchange 관리자는 Exchange Online PowerShell(`Connect-ExchangeOnline`)에 연결하고
    앱의 서비스 주체를 등록합니다. `<object ID>`는 앱 등록의 개체 ID가 아니라 Microsoft Entra ID의
    **엔터프라이즈 애플리케이션**에 표시되는 앱의 개체 ID입니다.

    ```powershell
    New-ServicePrincipal -AppId <app ID> -ObjectId <object ID>
    ```
  </Step>
  <Step title="사서함 액세스 권한 부여">
    서비스 주체에 발신 사서함에 대한 액세스 권한을 부여합니다.

    ```powershell
    Add-MailboxPermission -Identity <mailbox> -User <service principal> -AccessRights FullAccess
    ```
  </Step>
  <Step title="사서함에서 SMTP AUTH 허용">
    다음 예와 같이 사서함에서 SMTP AUTH를 활성화합니다.

    ```powershell
    Set-CASMailbox -Identity <mailbox> -SmtpClientAuthenticationDisabled $false
    ```
  </Step>
  <Step title="커넥터 설정 입력">
    호스트에 `smtp.office365.com`, 포트에 `587`, TLS 모드에 `starttls`를 입력합니다.
    **Microsoft 365 (OAuth 2.0)**를 선택하고 테넌트 ID, 클라이언트 ID, 클라이언트 시크릿을 입력합니다.
    **사용자 이름**과 **보낸 사람 주소**에는 발신 사서함을 입력합니다.
  </Step>
</Steps>

#### Google Workspace

MoleSignal은 서비스 계정으로 로그인하고 도메인 전체 위임을 통해 도메인 내 사서함 하나를
발신에 사용합니다.

<Steps>
  <Step title="서비스 계정 만들기">
    Google Cloud 프로젝트에서 서비스 계정과 해당 계정의 JSON 키를 만듭니다.
    서비스 계정의 세부정보 페이지에서 숫자로 된 클라이언트 ID를 확인합니다.
  </Step>
  <Step title="Gmail 범위 위임">
    Google 관리 콘솔에서 최고 관리자가 **보안 → 액세스 및 데이터 관리 →
    API 제어 → 도메인 전체 위임**을 열고 클라이언트 ID를 추가한 후 다음 범위를 승인합니다.
    `https://mail.google.com/` 위임을 적용하는 데 최대 24시간이 걸릴 수 있습니다.
  </Step>
  <Step title="커넥터 설정 입력">
    호스트에 `smtp.gmail.com`을 입력하고 포트 `587`과 TLS 모드 `starttls` 또는 포트
    `465`와 TLS 모드 `tls`를 사용합니다. **Google Workspace (OAuth 2.0)**를 선택하고 **서비스 계정
    키(JSON)**에 키를 붙여넣습니다. 서비스 계정이 발신에 사용하는 도메인 사용자의 사서함을 **사용자 이름**과
    **보낸 사람 주소**에 입력합니다.
  </Step>
</Steps>

[Google Chat 앱](#google-chat-앱)과 마찬가지로 키의 `token_uri`는 Google의 토큰 엔드포인트여야 합니다.

### Slack 앱

`chat.postMessage`를 호출할 수 있는 봇 토큰을 사용하는 Slack 앱을 만듭니다. 알림을 보낼 각 채널에
봇을 추가합니다. 다음 항목을 입력합니다.

- **봇 토큰** — 일반적으로 `xoxb-`로 시작하는 봇 토큰입니다.
- **앱 수준 토큰** — 선택 사항입니다. `xapp-`로 시작하고 `connections:write` 범위가 있는 토큰입니다. Mole Agent가 Socket Mode를 통해 Slack에서 응답할 수 있습니다. [IM에서 Mole Agent 사용](/ko/im)을 참조합니다.
- **플랫폼** — Slack 또는 미국 정부용 GovSlack입니다. GovSlack의 API와 상태 페이지
  인증에는 `slack-gov.com`을 사용합니다.
- **클라이언트 ID** 및 **클라이언트 시크릿** — 상태 페이지 방문자가 해당 페이지를 자신의 Slack 채널에 추가할 수 있게 하려면 Slack 앱의
  **기본 정보**에서 두 값을 가져옵니다.
  [상태 페이지](/ko/status-pages#slack)를 참조합니다.
- **타임아웃** — 1~60초 사이의 값입니다.

커넥터에는 봇 토큰, 클라이언트 ID와 시크릿, 또는 세 값 모두가 필요합니다. 알림을 보내려면
봇 토큰이 필요합니다. 커넥터는 클라이언트 시크릿과 봇 토큰을 암호화해 저장하며, 이 값을
반환하지 않습니다.

`direct_user`에는 Slack 멤버 ID를, `fixed_group`에는 채널 ID를 사용합니다. 값에 공백을
포함하지 않습니다. `#alerts`와 같은 표시 이름은 채널 ID가 아닙니다.

**Mole Agent → 설정 → IM**에서 커넥터를 활성화하면 이 커넥터를 통해 전송하는 경보 알림에
확인 및 해결 버튼이 표시됩니다. [경보 카드](/ko/im#알림-카드)를 참조합니다.

### Slack 웹훅

Slack에서 수신 웹훅을 만들고 URL을 복사하여 **웹훅 URL**에 붙여넣습니다. `fixed_group` 대상은
이 URL을 사용합니다. `webhook` 대상은 대상 값을 해당 전송에 사용할 대체 URL로
사용합니다.

MoleSignal은 `text` 필드가 포함된 JSON 객체를 보냅니다. 응답이 2xx가 아니면 전송 시도를
실패로 처리합니다.

### Lark 앱

테넌트 액세스 토큰을 가져오고 메시지를 보낼 수 있는 테넌트 앱을 만듭니다. **앱 ID**와
**앱 시크릿**을 입력합니다. **플랫폼**으로 **Feishu** 또는 **Lark**를 선택하면 API 기본 URL이 결정됩니다.

선택한 수신자 ID 유형은 `direct_user` 대상에 적용됩니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | **수신자 ID 유형**에 따라 `open_id`, `user_id`, `union_id` 또는 이메일 주소 |
| `fixed_address` | 이메일 주소. MoleSignal은 `receive_id_type=email`로 전송합니다. |
| `fixed_group` | Lark 채팅 ID. MoleSignal은 `receive_id_type=chat_id`로 전송합니다. |

앱에서 지속 연결로 이벤트를 수신하면 Mole Agent가 Feishu에서도 응답할 수 있습니다.
[IM에서 Mole Agent 사용](/ko/im#feishu)을 참조합니다.

**Mole Agent → 설정 → IM**에서 커넥터를 활성화하면 이 커넥터를 통해 전송하는 경보 알림에
확인 및 해결 버튼이 표시됩니다. [경보 카드](/ko/im#알림-카드)를 참조합니다.

### Lark 웹훅

커스텀 봇 URL을 복사하여 **웹훅 URL**에 붙여넣습니다. 봇 서명 검증을 활성화한 경우
**서명 시크릿**도 입력합니다. MoleSignal은 요청마다 타임스탬프와 HMAC-SHA256 서명을
생성합니다.

`fixed_group` 대상은 설정된 URL을 사용합니다. `webhook` 대상은 설정된 URL을 다른
절대 URL로 대체할 수 있습니다. 요청 및 서명 형식은 [웹훅 커넥터](/ko/notification-channels/webhooks)를
참조합니다.

### DingTalk 앱

내부 DingTalk 앱의 로봇을 사용합니다. 앱의 **클라이언트 ID**와 **클라이언트 시크릿**을 입력합니다.
로봇에 별도 코드가 없으면 **로봇 코드**를 비워 둡니다. 이 경우 클라이언트 ID를 사용합니다. MoleSignal은
자격 증명을 액세스 토큰으로 교환하고 로봇을 통해 Markdown 메시지를 보냅니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | 앱의 공개 범위에 속하는 사용자의 DingTalk 사용자 ID(`userId`) |
| `fixed_group` | 로봇이 속한 그룹의 `openConversationId` |

로봇이 스트림 모드로 메시지를 수신하면 Mole Agent가 DingTalk에서도 응답할 수 있습니다.
[IM에서 Mole Agent 사용](/ko/im#dingtalk)을 참조합니다. **카드 템플릿 ID**도 지정하면 경보 알림을
확인 및 해결 버튼이 있는 대화형 카드로 보냅니다. 템플릿을 만드는 방법은
[DingTalk 대화형 카드](/ko/im#dingtalk-대화형-카드)를 참조합니다.

### DingTalk 웹훅

커스텀 로봇의 URL을 복사하여 **웹훅 URL**에 붙여넣습니다. 로봇에 요청 서명을 설정한 경우
**서명 시크릿**도 입력합니다. MoleSignal은 요청마다 타임스탬프와 HMAC-SHA256 서명을 추가합니다.
`fixed_group` 대상은 설정된 URL을 사용하고, `webhook` 대상은 해당 URL을 대체합니다.

### WeCom 앱

직접 만든 WeCom 앱을 사용합니다. **기업 ID**, 앱의 **시크릿**, **AgentId**를 입력합니다.
MoleSignal은 이 값으로 액세스 토큰을 받아 Markdown 메시지를 보냅니다. WeCom은 메시지에서
4,096 bytes를 초과하는 부분을 잘라냅니다. MoleSignal이 접속할 때 사용하는 주소를 앱의 신뢰할 수 있는 IP 목록에 추가합니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | 앱의 공개 범위에 속하는 멤버의 사용자 ID |
| `fixed_group` | 앱에서 만든 그룹의 채팅 ID |

**콜백 토큰**과 **EncodingAESKey**를 지정하고 앱의 **메시지 수신**에 커넥터의 콜백 URL을
입력하면 멤버에게 보내는 경보 알림이 확인 및 해결 버튼이 있는
템플릿 카드로 표시됩니다. [WeCom 앱의 버튼](/ko/im#wecom-앱의-버튼)을 참조합니다.

### WeCom 웹훅

그룹 로봇의 URL을 복사하여 **웹훅 URL**에 붙여넣습니다. `fixed_group` 대상은 해당 URL을 사용하고, `webhook` 대상은
해당 URL을 대체합니다.

### WeCom 스마트 봇

API 모드에서 지속 연결로 메시지를 수신하는 WeCom 스마트 봇을 사용합니다. 봇의
**봇 ID**와 봇용으로 생성한 **지속 연결 시크릿**을 입력합니다. **지속 연결 주소**는
`wss://openws.work.weixin.qq.com`으로 고정됩니다. Mole Agent의 **IM**에서 커넥터를 활성화하면 Mole Agent가
WeCom에서 응답하고([IM에서 Mole Agent 사용](/ko/im#wecom) 참조), 봇은 알림도 보냅니다.
메시지와 답장은 모두 지속 연결을 사용합니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | 스마트 봇에서 확인할 수 있는 멤버의 userid |
| `fixed_group` | 그룹의 채팅 ID |

봇은 직접 메시지를 보낸 멤버와 봇을 멘션한 채팅에만
메시지를 보낼 수 있습니다. 확인 및 해결 버튼이 있는 템플릿 카드로 경보 알림을 보내고,
다른 알림은 Markdown으로 보냅니다. 알림을 보내려는 서버에
봇 연결이 없으면 연결을 유지하는 서버가 알림을 보냅니다. 일반적으로 몇 초 내에 전송합니다.
어떤 서버도 연결을 유지하지 않으면 전송에 실패합니다. 이 커넥터는 멤버의 알림 수단을 통해
IM에서 요청을 보낸 멤버도 식별할 수 있습니다.

### Microsoft Teams 봇

Bot Framework 봇을 사용합니다. 봇의 **앱 ID**, **클라이언트 시크릿**, **테넌트 ID**를 입력합니다.
이전 멀티 테넌트 봇의 테넌트는 `botframework.com`입니다. 봇의 **클라우드**로 Global, GCC,
GCC High, DoD 중 하나를 선택합니다. 서비스 URL은 선택한 클라우드에 따라 결정됩니다. GCC High와 DoD에서는
`login.microsoftonline.us`에서 토큰을 발급하고, 정부용 Bot
Framework가 Mole Agent로 보내는 메시지를 검증합니다. 메시지를 받을 사용자와 팀에 봇을 설치합니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | Teams 사용자 ID(`29:…`) 또는 사용자의 Microsoft Entra 개체 ID |
| `fixed_group` | 채널 또는 그룹 채팅의 대화 ID(`19:…`) |

MoleSignal이 제공하는 콜백 주소를 Azure Bot의 메시징 엔드포인트에 입력하면 봇을 통해
Mole Agent가 Teams에서도 응답할 수 있습니다. [IM에서 Mole Agent 사용](/ko/im#microsoft-teams)을 참조합니다.

각 메시지를 Adaptive Card로 보냅니다.

### Google Chat 앱

Chat 앱의 서비스 계정을 사용합니다. 계정의 JSON 키를 복사하여 **서비스 계정 키**에 붙여넣습니다. 커넥터는 키를
암호화해 저장하며 반환하지 않습니다. MoleSignal은 키로 토큰 요청에 서명하고
앱으로 메시지를 보냅니다. 키의 `token_uri`는 다음 Google 토큰 엔드포인트여야 합니다.
`https://oauth2.googleapis.com/token`(이전 키의 경우 `https://accounts.google.com/o/oauth2/token`).
다른 주소를 지정하는 키는 저장하지 않습니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | 앱에 메시지를 보내거나 앱을 설치한 사용자(`users/123…`) |
| `fixed_group` | 앱이 참여 중인 스페이스(`spaces/AAAA…`) |

**Pub/Sub 구독**(`projects/<project>/subscriptions/<name>`)을 설정하면 앱을 통해 Mole
Agent가 Google Chat에서도 응답할 수 있습니다. [IM에서 Mole Agent 사용](/ko/im#google-chat)을 참조합니다.
앱에서 알림만 보내는 경우 비워 둡니다.

### Google Chat 웹훅

스페이스의 수신 웹훅 URL을 복사하여 **웹훅 URL**에 붙여넣습니다. `fixed_group` 대상은 해당 URL을 사용하고,
`webhook` 대상은 해당 URL을 대체합니다.

### Telegram 봇

Telegram에서 **@BotFather**에 메시지를 보내고 `/newbot`으로 봇을 만듭니다. 발급받은 토큰(예:
`123456789:AAE…`)을 **봇 토큰**에 입력합니다. MoleSignal은
`https://api.telegram.org`의 Bot API를 통해 메시지를 보내고 링크 미리보기는 표시하지 않습니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | 사용자의 Telegram 숫자 ID입니다. @username은 사용할 수 없습니다. 사용자가 먼저 Telegram에서 봇을 열고 **시작**을 눌러야 봇이 메시지를 보낼 수 있습니다. @userinfobot과 같은 봇은 메시지를 보낸 사용자의 ID를 조회합니다. |
| `fixed_group` | 그룹이나 채널의 채팅 ID인 음수(슈퍼그룹과 채널은 `-100…`) 또는 공개 채널의 `@username`입니다. 봇은 그룹에 참여 중이거나 채널의 관리자여야 합니다. |

**Mole Agent → 설정 → IM**에서 커넥터를 활성화하면 Mole Agent가 Telegram에서 응답하고,
봇을 통해 보내는 경보 알림에 확인 및 해결 버튼이 표시됩니다.
[Telegram](/ko/im#telegram)과 [경보 카드](/ko/im#알림-카드)를 참조합니다.

### Discord 웹훅

Discord 채널 설정에서 **통합 → 웹훅**을 열고 웹훅을 만듭니다. URL을 복사하여
**웹훅 URL**에 붙여넣습니다(`https://discord.com/api/webhooks/…`; `discordapp.com`과 `ptb.`,
`canary.` 호스트도 지원). **표시 이름**(최대 80자)과 **아바타 URL**은 선택 사항이며,
메시지에 표시되는 웹훅 기본 이름과 아바타를 대체합니다.

알림마다 임베드 하나를 보냅니다. [인스턴트 메시징 템플릿의
카드](#인스턴트-메시징-템플릿의-카드)를 참조합니다. 텍스트의 멘션은 알림을 보내지 않습니다. `fixed_group`
대상은 설정된 URL을 사용하고, `webhook` 대상은 해당 URL을 대체합니다. 웹훅 URL에 `?thread_id=`를 넣으면
채널의 해당 스레드에 게시합니다.

### Mattermost 봇

시스템 콘솔에서 봇 계정을 허용합니다(**통합 → 봇 계정 → 봇 계정
생성 활성화**). **통합 → 봇 계정**에서 봇을 추가하고 액세스 토큰을 복사합니다. 다음 항목을 입력합니다.

- **서버 URL** — Mattermost 서버 주소입니다. 예: `https://chat.example.com`.
- **봇 토큰** — 봇의 액세스 토큰입니다.
- **타임아웃** — 1~60초 사이의 값입니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | `@`를 포함하거나 생략한 사용자 이름 또는 26자 사용자 ID입니다. 사용자와 봇 간의 다이렉트 채널에 게시합니다. |
| `fixed_group` | 채널 ID 또는 채널 URL에 나오는 `team-name/channel-name`입니다. 봇이 팀에 속해야 하며, 비공개 채널에는 봇이 참여 중이어야 합니다. |

이 커넥터에서 멤버의 알림 수단은 Mattermost 사용자 이름 또는 사용자 ID입니다. 게시물은
Slack 형식의 메시지 첨부로 표시됩니다. `http.external_url`을 설정하면 경보 알림에 확인, 해결,
일시 중지 버튼이 표시됩니다. [Mattermost 봇의 버튼](/ko/im#mattermost-봇의-버튼)을 참조합니다.

### Mattermost 웹훅

Mattermost의 **통합 → 수신 웹훅**에서 수신 웹훅을 추가하고 URL을 복사합니다.
복사한 URL(`https://chat.example.com/hooks/…`)을 **웹훅 URL**에 붙여넣습니다. `fixed_group` 대상은 해당 URL을 사용하고, `webhook`
대상은 해당 URL을 대체합니다. 웹훅 게시물에는 버튼 없이 경보 링크만 표시됩니다.

### Webex 봇

`developer.webex.com`의 **내 Webex 앱**에서 봇을 만들고 봇 액세스 토큰을 **봇
토큰**에 입력합니다. MoleSignal은 `https://webexapis.com/v1`을 통해 게시합니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | 사용자의 Webex 계정 이메일 주소 또는 Webex 사용자 ID |
| `fixed_group` | 봇이 참여 중인 스페이스의 룸 ID |

각 메시지에는 Markdown과 Adaptive Card가 포함됩니다. 카드를 지원하는 클라이언트는 Markdown 대신 카드를 표시합니다.
카드에는 누를 수 있는 요소가 없습니다. 멤버에게 보내는 경보 알림에는 버튼 대신 [일회용 작업
링크](#일회용-작업-링크)가 포함됩니다.

### Webex 웹훅

Webex App Hub에서 **수신 웹훅** 통합을 추가하고 스페이스를 선택합니다. 생성된 URL을 복사하여
(`https://webexapis.com/v1/webhooks/incoming/…`; `api.ciscospark.com`의 이전 URL도 지원)
**웹훅 URL**에 붙여넣습니다. 메시지는 Markdown 형식이며 웹훅에 지정한 스페이스로 전송됩니다. `fixed_group`
대상은 해당 URL을 사용하고, `webhook` 대상은 해당 URL을 대체합니다.

### Matrix 봇

봇용 Matrix 계정을 만들고 Element에서 해당 계정으로 로그인합니다.
**설정 → 도움말 및 정보 → 고급**에서 액세스 토큰을 복사합니다. 토큰은 해당 로그인 세션에 속하며, 로그아웃하면
토큰이 무효화됩니다. **홈서버 URL**에 `https://matrix.org`와 같은 HTTPS 주소를 입력하고
**액세스 토큰**을 입력합니다.

| 대상 유형 | 값 |
|---|---|
| `direct_user` | `@name:matrix.org`와 같은 사용자 ID입니다. 봇은 사용자와의 다이렉트 룸에 메시지를 보냅니다. 첫 알림을 보낼 때 룸을 만들고 사용자를 초대합니다. 사용자가 초대를 수락하면 메시지가 표시됩니다. |
| `fixed_group` | 룸 ID(`!…`) 또는 별칭(`#name:server`)입니다. 룸이 공개되어 있거나 봇이 초대를 받은 경우 봇이 룸에 참여합니다. 그 외에는 봇을 초대합니다. |

각 메시지에는 일반 텍스트와 HTML이 포함되며, 메시지의 멘션은 알림을 보내지 않습니다. MoleSignal은
메시지를 암호화하지 않고 보냅니다.

### 음성 및 SMS용 전화번호

음성 및 SMS 커넥터는 멤버가 등록한 전화번호(`direct_user`) 또는 대체 경로에 지정한
고정 번호(`fixed_address`) 한 곳으로 전송합니다. `+`와 국가 코드를 포함하여
`+14155550100`과 같이 입력합니다. 커넥터는 공백과 하이픈을 제거합니다. Alibaba Cloud, Tencent Cloud, Huawei Cloud 및 범용 HTTP SMS
커넥터는 중국 본토의 11자리 휴대전화 번호도 지원합니다.

음성 통화는 알림 제목에 이어 본문을 최대 400자까지 읽습니다. SMS는 첫 줄에 제목을,
다음 줄에 본문을 담아 최대 320자까지 전송합니다. 알림 정책이 전화 또는 SMS 채널에 사용할 템플릿을 선택하면
전화나 SMS는 제목 없이 해당 템플릿의 본문만 전달합니다. Alibaba
Cloud, Tencent Cloud, Huawei Cloud는 승인된 템플릿으로만 전송합니다. 템플릿 코드와 변수는
[알림 템플릿 내 공급자
템플릿](#알림-템플릿의-제공업체-템플릿)의 설명에 따라 알림 템플릿에 작성합니다.

공급자는 한 번호에 전화하거나 문자를 보낼 수 있는 횟수를 제한합니다. 횟수 제한, 잘못된 번호,
미승인 템플릿으로 공급자가 전화나 문자를 거부하면 전송에 실패합니다. 알림 정책은
멤버의 다음 알림 수단과 대체 경로로 전송을 시도합니다. 공급자는 수신자가 전화를 받았는지 또는 내용을 들었는지
알려주지 않습니다. 전송 성공은 공급자가 통화 또는 문자 요청을 수락했다는 뜻입니다.

커넥터 하나가 같은 번호로 거는 전화는 분당 한 번으로 제한됩니다. 1분 이내에 들어오는 알림은
해당 번호의 대기열에 쌓이고 전송 로그에 **병합 대기 중**으로 표시됩니다. 1분이 지나면
한 통화에서 각 알림의 제목을 차례로 읽습니다. 전화 템플릿을 사용한 알림은
본문을 읽으며, 대기 중에 확인한 알림은 제외합니다. Alibaba Cloud, Tencent Cloud, Huawei Cloud는
첫 번째 알림의 템플릿을 읽고, 각 변수에 모든 알림의 해당 값을 순서대로
채웁니다. Alibaba Cloud는 원래 한 번호에
분당 한 번의 통화만 허용하므로, 병합하면 경보가 한꺼번에 들어와도 거부되지 않습니다. 알림 정책이
[알림 병합](#알림-묶기) 간격을 더 길게 설정하면 정책의 간격을 사용합니다.

### Alibaba Cloud 음성

Alibaba Cloud Voice Service를 사용하여 중국 본토 번호에만 음성 알림을 보냅니다. Voice Service 콘솔에서
기업 자격 심사를 완료하고 `Hello, ${content}. Please handle it now.`와 같은 **텍스트 음성 변환**
알림 템플릿을 신청합니다. Voice Service만 호출할 수 있는 RAM 사용자용 AccessKey를
만듭니다. 다음 항목을 입력합니다.

- **AccessKey ID** 및 **AccessKey 시크릿**
- **리전** — Alibaba Cloud가 제공하는 리전 중 하나입니다. 선택한 리전에 따라 API 기본 URL이 결정됩니다.
- **발신번호** — 공유 모드인 경우 비워 둡니다. 전용 모드인 경우 구매한 번호를 입력합니다.
  모든 통화에 이 번호가 표시되므로 온콜 담당자가 연락처에 저장할 수 있습니다. 템플릿도 같은
  모드여야 합니다.
- **낭독 횟수** — 1~3회입니다.

템플릿 코드(`TTS_`로 시작)와 해당 변수를 전화 알림 템플릿에 작성합니다.
알림 정책에서는 전화 채널에 이 템플릿을 선택합니다. [알림 템플릿 내 공급자
템플릿](#알림-템플릿의-제공업체-템플릿)을 참조합니다. Alibaba Cloud는 한 번호로
분당 1회, 시간당 5회, 일일 20회까지 전화를 걸 수 있으며, 한도를 초과하는 통화 요청은 거부합니다.
변수에 링크나 IP 주소를 넣지 않습니다.

### Alibaba Cloud SMS

SMS 콘솔에서 **SMS 서명**과 `${content}. Please handle it
now.`와 같은 **알림** 템플릿을 신청합니다. 그런 다음 AccessKey, **리전**, **서명**을 입력합니다. Alibaba
Cloud가 제공하는 리전 중 하나를 선택합니다. 일부 해외 리전에는 별도 주소가 있으며, API
기본 URL은 선택한 리전에 따라 결정됩니다. 템플릿 코드(`SMS_`로 시작)와 해당 변수를
SMS 알림 템플릿에 작성합니다. 알림 정책에서는 SMS 채널에 이 템플릿을 선택합니다. [알림 템플릿 내
공급자 템플릿](#알림-템플릿의-제공업체-템플릿)을 참조합니다.

알림 템플릿의 변수는 기본적으로 35자까지 허용합니다. Alibaba Cloud가 기업 계정의 한도를
늘린 후 알림 템플릿에서 **변수당 문자 수**를 늘립니다. 변수에
링크나 IP 주소를 넣을 수 없습니다. 중국 본토 휴대전화 번호나 국제 전화번호를 사용할 수 있습니다.

### Tencent Cloud 음성

음성 메시지 콘솔에서 애플리케이션을 만들고(`VoiceSdkAppid` 발급) 음성 알림 템플릿을
신청합니다. 그런 다음 하위 사용자용 API 키를 만듭니다. **SecretId**, **SecretKey**,
**리전**(해당 키로 조회하며, 리전에 따라 API 기본 URL이 결정됨), **앱 ID (SdkAppId)**,
**낭독 횟수**(1~3회)를 입력합니다. 템플릿 ID와 해당 변수를 전화 알림 템플릿에 작성하고
변수 이름은 순서대로 `1`, `2`, `3`을 사용합니다. [알림 템플릿 내 공급자
템플릿](#알림-템플릿의-제공업체-템플릿)을 참조합니다.

음성 서비스는 선불입니다. 패키지를 모두 사용하면 통화에 실패하고 전송 로그에
`InsufficientBalanceInVoicePackage`가 표시됩니다. 알림 정책은 멤버의 다음 수단을 사용하므로
전화를 유일한 수단으로 설정하지 않습니다. 통화에서 읽는 내용은 최대 350자입니다. 공급자 문서에
변수당 한도가 명시되어 있지 않지만 공급자는 너무 긴 값은 거부합니다(`ContentLengthLimit`). 기본적으로
20자를 초과하는 부분은 잘라냅니다. 더 높은 한도는 알림 템플릿에 설정합니다.

### Tencent Cloud SMS

SMS 콘솔에서 애플리케이션을 만들고(`SmsSdkAppId` 발급) 서명과
템플릿을 신청합니다. 그런 다음 **SecretId**, **SecretKey**, **리전**, **앱 ID (SdkAppId)**,
**서명**(ID가 아닌 서명 텍스트, 중국 본토 SMS에 필수)을 입력합니다. 템플릿 ID와
해당 변수를 SMS 알림 템플릿에 작성하고 변수 이름은 순서대로 `1`, `2`, `3`을 사용합니다.

<Warning>
  2024년 1월 25일 이후 개설한 계정과 장기간 사용하지 않은 계정은 기본적으로 변수당 최대 **6자**를
  허용하며, 더 긴 값은 거부합니다(`TemplateParameterLengthLimit`). 기본적으로 값의
  6자를 초과하는 부분을 잘라내므로 경보 제목이 거의 남지 않습니다. Tencent Cloud가 계정의
  한도를 늘리면 알림 템플릿의 **변수당 문자 수**에 새 한도를 입력합니다.
  변수에 링크를 넣을 수 없습니다.
</Warning>

API 호출이 성공해도 해당 번호로 전송했다는 뜻은 아닙니다. 번호별 결과로
성공 여부를 판단합니다. 결과가 `Ok`가 아니면 전송에 실패하고 전송 로그에 이유를 표시합니다.

### Huawei Cloud 음성

음성 통화 콘솔에서 애플리케이션을 만들고 유선 전화번호를 구매한 후 음성 템플릿을 제출합니다.
다음 항목을 입력합니다.

- **AppKey**, **AppSecret** 및 **앱 주소** — 모두 애플리케이션 관리에서 확인합니다. 주소는
  그대로 복사합니다. API로는 조회할 수 없습니다.
- **발신번호** — 구매한 유선 전화번호입니다. 국가 코드, 지역 번호, 전화번호 순으로 입력합니다.

템플릿 ID와 해당 변수를 전화 알림 템플릿에 작성하고 변수 이름은 순서대로
`1`, `2`, `3`을 사용합니다. 변수당 한도는 32 bytes이며, 한자 한 글자는 3 bytes를 차지합니다.
한도를 초과하는 부분을 잘라내고, 변수에 포함된 `$`, `{`, `}`는 제거합니다.

### Huawei Cloud SMS

메시지 및 SMS 콘솔에서 애플리케이션을 만들고 서명과 템플릿을 승인받습니다.
**AppKey**, **AppSecret**, **앱 주소**(모두 애플리케이션 관리에서 확인)와 **채널
번호**(서명에 연결된 번호)를 입력합니다. 범용 템플릿에는 **서명
이름**도 필요합니다. 템플릿 ID와 해당 변수를 SMS 알림 템플릿에 작성하고 변수 이름은 순서대로
`1`, `2`, `3`을 사용합니다. 템플릿에는 변수당 한도가 명시됩니다(예: `TXT_20`). 기본적으로
20자를 초과하는 부분을 잘라냅니다. 다른 한도는 알림 템플릿에 설정합니다.

### Twilio 음성

Twilio 콘솔에서 **계정 SID**와 **인증 토큰**을 확인하고 다음 항목을 입력합니다.

- **발신 번호** — 계정에 등록된 음성 통화 지원 번호입니다. 예: `+14155550100`.
- **언어** — 알림을 읽는 언어입니다. 예: `en-US`, `cmn-CN`.
- **음성** — 선택 사항입니다. 예: `Polly.Joanna`, `Polly.Zhiyu`. 비워 두면 Twilio의 기본 음성을 사용합니다.
- **낭독 횟수** — 1~3회입니다.

### Twilio SMS

**계정 SID**, **인증 토큰**, **발신자**를 입력합니다. 발신자는 계정에 등록된 번호
(E.164), Messaging Service(`MG…`), 또는 수신 국가에서 허용하는 경우 영문자와 숫자로 구성된
최대 11자의 발신자 ID입니다. 미국 번호로 SMS를 보내려면 먼저 A2P 10DLC를 등록합니다.

### Twilio WhatsApp

SMS 채널에서 Twilio를 통해 WhatsApp 메시지를 보냅니다. **계정 SID**와 **인증 토큰**을 입력합니다.
**WhatsApp 발신자**에는 `+14155550100`과 같이 계정에 등록된 WhatsApp 지원 번호 또는 WhatsApp
발신자가 포함된 Messaging Service(`MG…`)를 입력합니다. 멤버의 알림 수단은 SMS와 같은 형식으로 입력한
WhatsApp 번호입니다.

WhatsApp에서 비즈니스가 먼저 대화를 시작하려면 승인된 템플릿을 사용해야 합니다.
Twilio의 **콘텐츠 템플릿 빌더**에서 템플릿을 만들고 WhatsApp용으로 승인받습니다. SMS 알림 템플릿의 **WhatsApp** 섹션에
Content SID(`HX…`)와 변수를 작성하고 변수 이름은 순서대로 `1`,
`2`, `3`을 사용합니다. [알림 템플릿 내 공급자
템플릿](#알림-템플릿의-제공업체-템플릿)을 참조합니다. 알림 정책에서는 SMS 채널에 해당 템플릿을
선택합니다. WhatsApp 섹션이 없으면 전송하지 않고 전송 로그에 이유를 표시합니다.

WhatsApp은 줄바꿈이나 탭이 포함된 변수를 거부하므로 각 값은
Markdown 구문 없이 한 줄로 보내고, 빈 값은 `-`로 보냅니다. **답장 처리**를 활성화하면 답장 코드가 포함된 답장을
SMS와 동일하게 처리합니다. [문자 및 통화에 대한 응답](#문자-메시지와-전화로-경보-처리)을 참조합니다.

### AWS 음성 및 SMS

AWS 음성(`aws_voice`)은 AWS End User Messaging의 `SendVoiceMessage`로 전화를 걸고 Amazon Polly로
알림을 읽습니다. AWS SMS(`aws_sms`)는 `SendTextMessage`로 트랜잭션 SMS를 보냅니다. 다음 항목을
입력합니다.

- **리전** — 계정에서 활성화한 리전입니다. 커넥터에 자격 증명을 입력하면 해당 자격 증명으로 AWS에 리전 목록을
  요청합니다(EC2 `DescribeRegions`). End User Messaging을 지원하지 않는 리전에서는
  전송에 실패합니다.
- **인증** — AWS 데이터 커넥터와 같은 방식인 액세스 키, 임시 키, 노드
  ID, 역할 수임 또는 웹 ID를 사용합니다. 역할을 수임하려면 역할의 신뢰 정책에 페이지에 표시된
  외부 ID를 지정합니다.
- **발신 ID** — 전화번호, 전화번호 ID, 풀 ID 또는 해당 리소스의 ARN입니다. 음성은
  발신 ID가 필수이며, 번호는 음성 통화를 지원해야 합니다. SMS는 비워 두어 AWS가 수신 대상에 맞는 번호를
  선택하게 하거나 발신자 ID를 지정할 수 있습니다.
- **Polly 음성** — 음성 전용 선택 항목입니다. 비워 두면 `MATTHEW`를 사용하며, 표준 중국어에는 `ZHIYU`를 사용합니다.
- **API 기본 URL** — 리전에 따라 결정됩니다. 예: `https://sms-voice.us-east-1.amazonaws.com`.

인증에 사용하는 ID에는 `sms-voice:SendVoiceMessage` 또는 `sms-voice:SendTextMessage` 권한과
리전 목록을 조회할 `ec2:DescribeRegions` 권한이 필요합니다.
아직 샌드박스에 있는 AWS 계정은 검증된 번호에만 전송할 수 있습니다.

### 범용 HTTP SMS

직접 설정한 HTTP 요청으로 자체 SMS 게이트웨이 또는 전용 커넥터가 없는 공급자에
SMS를 전달합니다. 다음 항목을 입력합니다.

- **게이트웨이 URL** — 요청을 보낼 주소입니다. 플레이스홀더를 포함할 수 있습니다. GET 게이트웨이의 예:
  `https://sms.example.com/send?to={{phone}}&msg={{content}}`.
- **HTTP 메서드** — POST, PUT 또는 GET입니다. GET에는 본문이 없습니다.
- **본문 형식** 및 **본문** — JSON 또는 폼(`x-www-form-urlencoded`)입니다. 기본값은
  `{"phone": "{{phone}}", "content": "{{content}}"}`입니다.
- **헤더 (JSON)** — 예: `{"Authorization": "Bearer {{secret}}"}`.
- **시크릿** — 게이트웨이에 필요한 토큰 또는 비밀번호로, 암호화해 저장합니다.
  URL, 헤더, 본문에서 `{{secret}}`으로 참조합니다.
- **전화번호 형식** — `+8613800138000`(E.164), `8613800138000`(+ 제외), `13800138000`(국가 코드를 제외한
  중국 본토 번호) 중 하나입니다.
- **성공 필드** 및 **성공 값** — 선택 사항입니다. 2xx 응답은 전송 성공으로 처리합니다. `code`나
  `result.status`와 같은 성공 필드를 지정하면 JSON 응답의 해당 필드 값도 성공 값과
  일치해야 합니다.

| 플레이스홀더 | 값 |
|---|---|
| `{{phone}}` | 지정한 전화번호 형식의 SMS 수신 번호 |
| `{{content}}` | 첫 줄에 제목, 다음 줄에 본문을 담은 최대 320자의 SMS |
| `{{title}}` | 알림 제목 |
| `{{text}}` | 알림 본문 |
| `{{secret}}` | 시크릿 |

값은 삽입 위치에 맞게 이스케이프합니다. JSON 본문에서는 JSON 문자열로, 폼이나 URL에서는 URL 인코딩된 값으로 처리합니다.
요청에 전화번호와 문자 내용을 모두 포함해야 커넥터를 저장할 수 있습니다.

### 범용 웹훅

기본 URL을 입력하고 `POST`, `PUT`, `PATCH` 중 하나를 선택한 다음 **본문**을 선택합니다.

- **MoleSignal 이벤트** — 기본값입니다. 버전, 이벤트, 경보,
  규칙, 에스컬레이션, 대상, 렌더링된 메시지를 기계가 읽을 수 있는 JSON으로 보냅니다.
- **알림 템플릿 본문** — 알림 정책에서 웹훅 채널에 선택한 템플릿의 본문을
  작성한 그대로 전송합니다. JSON 템플릿은 JSON으로 보냅니다. [조건](#조건)과
  [템플릿 및 정책 만들기](#템플릿-및-정책-만들기)의 형식을 참조합니다.

모든 요청에는 `X-MoleSignal-Event`(알림 유형)와 `X-MoleSignal-Delivery`(수신 측에서 중복을 제거하는 데 사용하는
전송 ID)가 포함됩니다. 16자 이상의 **서명 시크릿**을 설정하면 요청에
`X-MoleSignal-Timestamp`와 `X-MoleSignal-Sign`도 포함됩니다. 수신 측은 이 두 헤더로
요청이 MoleSignal에서 왔는지 확인합니다. 본문 필드, 서명, 서명 검증 예제는
[웹훅 알림 커넥터](/ko/notification-channels/webhooks#범용-웹훅)를 참조합니다.

`direct_user`, `fixed_address`, `fixed_group`의 경우 MoleSignal은 설정된 기본
URL로 요청을 보내고 대상을 라우팅 데이터에 포함합니다. `webhook`의 경우 대상 값이 기본
URL을 대체합니다. 2xx 응답은 성공으로 처리합니다. 응답에 `X-Request-ID`가 포함되면 MoleSignal은
해당 헤더 값을 공급자 메시지 ID로 기록합니다. 웹훅은 [병합](#알림-묶기)하지 않습니다.
알림마다 별도의 요청을 보냅니다.

<Warning>
  웹훅 URL, 인증 헤더, 토큰, 비밀번호, 서명 시크릿은 자격 증명입니다.
  테스트 대상, 템플릿, 이벤트 속성에 자격 증명 값을 넣지 않습니다.
</Warning>

### Amazon SNS

각 알림을 Amazon SNS 주제에 게시합니다. 구독을 통해 Lambda, SQS,
HTTPS 엔드포인트, 이메일 등에 알림을 전달합니다. 다음 항목을 입력합니다.

- **인증** 및 **리전** — [AWS 음성 및 SMS](#aws-음성-및-sms)와 같습니다. 리전은
  주제의 ARN에 표시된 리전을 사용합니다.
- **주제 ARN** — 예: `arn:aws:sns:us-east-1:123456789012:alerts`.
- **메시지** — 기본값인 **MoleSignal 이벤트**는 [범용
  웹훅](#범용-웹훅)과 같은 JSON을 게시합니다. **알림 템플릿 본문**은 알림 정책에서
  웹훅 채널에 선택한 템플릿의 본문을 게시합니다.

제목에는 알림 제목을 100자 미만의 한 줄로 담습니다. 모든 메시지에는
`alert.triggered`와 같은 `event_type` 메시지 속성을 포함하며, 경보에는 `severity`도 포함합니다.
구독 필터 정책은 이 속성으로 메시지를 필터링할 수 있습니다. FIFO 주제(이름이 `.fifo`로 끝나는 주제)에서는 같은 경보의
메시지를 같은 메시지 그룹에 넣고 순서를 유지합니다. 전송 ID를 중복 제거 ID로 사용하므로 SNS는
두 번 게시된 전송의 중복을 제거합니다.

인증에 사용하는 ID에는 주제에 대한 `sns:Publish` 권한, 암호화된 주제의 키에 대한 `kms:GenerateDataKey` 및
`kms:Decrypt` 권한, 리전 목록을 조회할 `ec2:DescribeRegions` 권한이 필요합니다. 모든 대상 유형을 사용할 수 있으며, 메시지는 항상
주제로 전송합니다.

### PagerDuty

Events API v2를 통해 PagerDuty 서비스에 이벤트를 보냅니다. PagerDuty 서비스의 **통합** 탭에서
**Events API V2** 통합을 추가한 후 32자의 라우팅 키인 통합 키를 복사하여
**통합 키**에 붙여넣습니다. **서비스 리전**으로 **미국**을 선택합니다. 계정 주소가
`.eu.pagerduty.com`으로 끝나면 **유럽 연합**을 선택합니다.

| MoleSignal 이벤트 | PagerDuty 이벤트 |
|---|---|
| 경보 발생, 경보 에스컬레이션 | `trigger` |
| 경보 확인 | `acknowledge` |
| 경보 해결 | `resolve` |
| 기타 이벤트 | `trigger`(별도의 PagerDuty 경보로 생성) |

각 MoleSignal 경보는 전체 수명 주기 동안 중복 제거 키
`molesignal-<alert ID>`를 기준으로 PagerDuty 경보 하나에 연결됩니다. 에스컬레이션 시 새 경보를 만들지 않고 같은 경보를 다시 트리거합니다.
트리거에는 요약으로 사용하는 제목(최대 1,024자), 소스로 사용하는 경보의 서비스
(서비스가 없으면 `MoleSignal`), 심각도(`critical`, `error`, `warning`, `info` 중 하나), 시간,
커스텀 세부 정보로 사용하는 범용 웹훅 이벤트가 포함됩니다. `http.external_url`을
설정한 경우 경보 링크도 포함됩니다.

PagerDuty는 알림 정책이 이 커넥터로 보내는 이벤트만 받습니다. MoleSignal 경보와 함께
PagerDuty 경보를 확인하고 해결하려면 **경보 확인** 및 **경보 해결**
이벤트도 전송해야 합니다. 모든 대상 유형을 사용할 수 있으며, 이벤트는 항상 키에 해당하는 통합으로 전송합니다.

## 사용자 알림 수신 방법 연결

관리자는 **설정 → 알림 → 사용자 라우팅**을 열고 구성원을 선택한 후
**알림 수신 방법 연결**을 클릭합니다. 각 수신 ID에는 커넥터 하나와 외부 ID 하나를 지정합니다. 외부 ID에는
이메일 주소, Slack 또는 Lark 사용자 ID, 음성 통화 또는 SMS 커넥터에서 사용하는 전화번호 등이 있습니다.

수신 ID를 연결한 후 다음을 수행합니다.

1. 테스트 알림을 보내 서비스 제공업체가 요청을 수락하는지 확인합니다.
2. 조직에서 소유권을 확인한 후 수신 ID를 인증합니다.
3. **경보 이벤트**, **온콜 이벤트** 또는 **보고서** 설정에서 수신 ID를 활성화합니다.
4. 수신 ID가 여러 개라면 기본 수신 ID부터 대체 수신 ID 순으로 배치합니다.
5. 필요에 따라 알림 제한 시간을 설정하고, 긴급 경보에는 제한을 적용하지 않도록 설정합니다.

### 경보를 확인하지 않으면 다음 단계로 진행

경보 이벤트의 전송 순서에서는 첫 단계를 제외한 각 단계에 대기 시간을 분 단위로 지정할 수 있습니다.

| 설정 | 동작 |
|---|---|
| 첫 단계 | 경보가 발생하거나 해당 구성원에게 에스컬레이션되면 즉시 알림을 보냅니다. |
| N분 대기 | 해당 구성원에게 처음 알림을 보낸 뒤 N분이 지나도 경보를 확인한 사람이 없으면 다시 알림을 보냅니다. |
| 이전 단계와 같은 시간 | 이전 단계에서 알림 전송에 실패한 경우에만 이 단계를 실행합니다. |

예를 들어 Lark로 즉시 알림을 보내고, 3분 후 SMS를 보내고, 5분 후 전화를 걸도록 설정할 수 있습니다.
경보를 확인하거나 해결하면 이후 단계에서는 알림을 보내지 않습니다. 에스컬레이션으로 경보를 받은
구성원의 이후 단계에도 적용됩니다. 알림 전송에 실패하면 즉시 다음 단계로 진행합니다. 각 단계는 최대 하루까지 대기하며,
대기는 경보 이벤트에만 적용됩니다. 온콜 이벤트와 보고서는 전송에 실패한 경우에만 다음 단계로 진행합니다.

구성원은 **계정 설정 → 알림**에서 개인 수신 ID와 알림 설정을 관리할 수 있습니다.
다른 구성원의 설정을 보려면 `org.members.read` 권한이 필요합니다. 다른
구성원의 수신 ID를 변경하거나 인증하려면 `org.members.update` 권한이 필요합니다.

<Note>
  수신 ID를 삭제하기 전에 모든 알림 전송 설정에서 해당 ID를 제거합니다.
</Note>

### Feishu 및 DingTalk의 긴급 호출

단계에서 Lark 앱 또는 DingTalk 앱 커넥터를 사용하면 메시지를 보낸 뒤 앱에
긴급 호출을 요청할 수 있습니다. 단계 옆의 선택 메뉴에서 호출 방식을 선택합니다.

| 플랫폼 | 옵션 | 요구 사항 |
|---|---|---|
| Feishu(Lark 앱 커넥터) | **앱 내 Buzz**, **SMS Buzz**, **전화 Buzz** | 방식에 따라 `im:message.urgent`, `im:message.urgent:sms` 또는 `im:message.urgent:phone` 앱 권한이 필요합니다. SMS Buzz와 전화 Buzz는 테넌트의 긴급 호출 할당량을 사용합니다. 글로벌 서비스인 Lark는 앱 내 Buzz만 지원합니다. 커넥터의 **수신자 ID 유형**은 이메일이 아닌 `open_id`, `user_id` 또는 `union_id`여야 합니다. |
| DingTalk(DingTalk 앱 커넥터) | **앱 내 DING**, **SMS DING**, **전화 DING** | DingTalk Professional 또는 Exclusive 에디션과 `Premium.Ding.Write` 앱 권한이 필요합니다. SMS DING과 전화 DING을 사용하려면 할당량을 구매해야 합니다. DING에는 알림 제목이 포함되며, 전화 DING은 이 제목을 읽어 줍니다. |

경보 이벤트의 전송 순서에는 긴급 호출 방식을 다르게 지정해 같은 수신 방법을 두 번 추가할 수 있습니다. 예를 들어 Feishu로
즉시 메시지를 보내고, 5분이 지나도 아무도 경보를 확인하지 않으면 같은 Feishu 수신 방법으로 **전화 Buzz**를
보낼 수 있습니다. 다른 이벤트의 전송 순서에는 각 수신 방법을 한 번만 추가할 수 있습니다.

할당량이나 권한 부족 등으로 긴급 호출에 실패하면 메시지가 도착했더라도
해당 단계를 실패로 처리하고 즉시 다음 단계로 진행합니다. WeCom은 긴급 호출을 지원하지 않습니다.

## 문자 메시지와 전화로 경보 처리

음성 통화, SMS 또는 WhatsApp 커넥터에서 **답장 처리**(음성 통화의 경우
**키 입력으로 경보 처리**)를 켜면 경보 수신자는 MoleSignal을 열지 않고도 경보를 처리할 수 있습니다.

- **문자 메시지**: 경보가 발생하거나 에스컬레이션될 때 보내는 문자 끝에는 "확인하려면 31, 해결하려면
  32로 답장하세요."라는 안내가 표시됩니다. 두 코드 중 하나로 답장하면 됩니다. 십의 자리 숫자는 전화번호별로
  0부터 9까지 순환하며, 일의 자리는 확인이면 1, 해결이면 2입니다. `1` 또는 `2`만 보내면
  해당 번호로 받은 가장 최근 문자에 적용합니다. 여러 경보를 한 문자에 묶어 보낸 경우 코드 하나가 모든 경보에 적용됩니다. 코드는
  하루 동안 유효합니다.
- **호출 수**: 경보 안내가 끝나면 1을 눌러 확인하거나 2를 눌러 해결합니다. 이어서 통화로
  처리 결과를 안내합니다.

답장이나 키 입력은 경보를 받은 구성원의 권한으로 처리합니다. 해당 구성원에게는 `alerts.incidents.acknowledge` 권한이 있어야 하며,
활성 조직에 속한 활성 계정이 필요합니다. 타임라인에는 SMS 답장 또는 전화 키 입력으로 기록합니다.
구성원에게 보낸 메시지에만 코드가 포함됩니다. 대체 경로의 고정 번호로 보낸 메시지에는 코드가 포함되지 않습니다.

서비스 제공업체는 답장과 키 입력을 MoleSignal의 콜백 URL로 보냅니다. 따라서 외부 URL인
`http.external_url`을 설정하고 인터넷에서 `/api/v1/public/notify/` 하위 경로에 접근할 수 있도록
구성합니다. [공개 액세스](/ko/public-access)를 참조합니다. 옵션을 켜고 커넥터를 저장하면
커넥터에 복사할 수 있는 콜백 URL이 표시됩니다.

| 커넥터 | 설정 방법 | 콜백 검증 방법 |
|---|---|---|
| Twilio SMS | 전화번호의 Messaging 설정에서 **A message comes in**을 Webhook과 HTTP POST로 설정하고 콜백 URL을 입력합니다. | 커넥터의 Auth Token으로 Twilio의 `X-Twilio-Signature`를 검증합니다. |
| Twilio WhatsApp | Twilio에서 WhatsApp 발신자 또는 연결된 Messaging Service의 수신 메시지 웹훅에 콜백 URL을 입력하고 HTTP POST로 설정합니다. WhatsApp은 승인된 템플릿만 전송하므로 템플릿 변수에 `{{reply.ack}}`와 `{{reply.resolve}}`를 지정해 코드를 포함합니다. 템플릿에서 빠른 답장 버튼의 ID에 코드를 지정하면 버튼을 누를 때 해당 코드로 답장하는 것과 동일하게 처리합니다. | Twilio 서명을 검증합니다. |
| Twilio 음성 통화 | 별도로 설정할 필요가 없습니다. 각 통화에 키 입력용 URL이 포함됩니다. | Twilio 서명을 검증합니다. |
| AWS SMS | 전화번호에 양방향 SMS를 활성화하고 답장용 SNS 주제를 지정합니다. 해당 주제에 HTTPS 구독을 추가하고 콜백 URL을 엔드포인트로 지정합니다. 구독은 자동으로 확인됩니다. 해당 주제에서 온 답장만 받으려면 **답장용 SNS 주제 ARN**에 주제의 ARN을 입력합니다. | `sns.<region>.amazonaws.com`에서만 인증서를 가져와 SNS 메시지 서명을 검증합니다. |
| Alibaba Cloud SMS | SMS Service에서 수신 메시지를 HTTP로 콜백 URL에 전송하도록 설정합니다. Alibaba Cloud는 승인된 템플릿만 전송하므로 템플릿 매개변수에 `{{reply.ack}}`와 `{{reply.resolve}}`를 지정해 코드를 포함합니다. [템플릿 변수](#템플릿-변수)를 참조합니다. | URL의 콜백 토큰을 검증합니다. |
| Alibaba Cloud 음성 통화 | 대화형 음성 통화(IvrCall)로 전화를 걸려면 IvrCall용으로 구매한 실제 전화번호를 **발신번호**로 지정합니다. Voice Service에서 수신 확인 정보를 HTTP로 콜백 URL에 전송하도록 설정합니다. 템플릿을 읽은 뒤 10초 동안 키 입력을 기다립니다. | URL의 콜백 토큰을 검증합니다. |
| Tencent Cloud SMS | SMS 콘솔의 콜백 설정에서 답장 콜백에 콜백 URL을 지정합니다. 템플릿 변수에 `{{reply.ack}}`와 `{{reply.resolve}}`를 지정해 코드를 포함합니다. | URL의 콜백 토큰을 검증합니다. |
| Tencent Cloud 음성 통화 | 음성 메시지 콘솔의 이벤트 콜백 설정에서 키 입력 콜백에 콜백 URL을 지정합니다. 템플릿에 "확인하려면 1번, 해결하려면 2번을 누르세요"라고 직접 입력합니다. 키 입력 콜백에는 수신 전화번호만 포함되므로 해당 번호의 가장 최근 통화에 적용합니다. | URL의 콜백 토큰을 검증합니다. |
| Huawei Cloud SMS | SMS 애플리케이션을 만들 때 수신 SMS 주소에 콜백 URL을 지정합니다. 위와 같은 방식으로 템플릿에 코드를 포함합니다. | URL의 마지막 부분에 있는 콜백 토큰을 검증합니다. |
| Huawei Cloud 음성 통화 | 애플리케이션 관리에서 통화 상태 주소에 콜백 URL을 지정합니다. 템플릿을 읽은 뒤 키 입력을 한 번 받습니다. 템플릿에 "확인하려면 1번, 해결하려면 2번을 누르세요"라고 직접 입력합니다. | URL의 마지막 부분에 있는 콜백 토큰을 검증합니다. |
| 범용 HTTP SMS | 게이트웨이가 수신 문자를 JSON 객체 `{"phone": "…", "text": "…"}` 또는 이러한 객체의 배열로 콜백 URL에 POST하도록 설정합니다. | URL의 콜백 토큰을 검증합니다. |

MoleSignal은 서버의 루트 키에서 커넥터별 콜백 토큰을 생성하며 토큰을 저장하지 않습니다. 콜백 URL은
인증 정보로 취급합니다. AWS 음성 메시지는 키 입력을 지원하지 않으므로 `aws_voice`에는 해당 옵션이 없습니다.

## 일회용 작업 링크

버튼을 추가하지 않는 커넥터로 한 명에게 경보 알림을 보내면 알림 끝에
일회용 링크를 표시합니다. 경보가 확인 대기 중이면 **확인**과 **해결**을, 확인된 후에는
**해결**만 표시합니다. 이는 버튼 없이 경보를 보내는 이메일 및 인스턴트 메시징 커넥터에
적용됩니다. 예를 들어 Webex 봇이나 **IM**에서 활성화하지 않은 Lark 앱이 해당합니다.
카드에서는 기존 링크 버튼과 함께 표시하고, 그 외에는 메시지 끝에 표시합니다.
링크 텍스트는 수신자의 인터페이스 언어로 표시합니다.

- 링크를 열면 로그인 없이 MoleSignal 페이지(`https://<external address>/notify/actions/<token>`)에
  접속합니다. 페이지에는 경보의 심각도, 상태, 제목, 시작 시간과 버튼 하나가 표시됩니다.
  페이지를 열기만 해서는 작업을 실행하지 않으므로 메일 스캐너가 링크를 열어도 영향이 없습니다. 버튼을 눌러야
  작업을 실행합니다.
- 링크는 24시간 동안 유효하며 한 번만 사용할 수 있습니다. 버튼을 누르면 알림 수신자의 권한으로 작업을 실행합니다.
  수신자는 버튼을 누르는 시점에 해당 경보에 대한 `alerts.incidents.acknowledge` 권한이 있어야 하며,
  활성 조직에 속한 활성 계정이 있어야 합니다.
- 이미 사용했거나 만료된 링크는 작동하지 않습니다. 경보를 이미 처리했거나 경보가 복구되어 링크가 더 이상 적용되지 않거나
  수신자에게 해당 경보를 처리할 권한이 없으면, 페이지에 이유를 표시하고 아무것도 변경하지 않습니다.
- 링크를 사용하려면 `http.external_url`을 설정해야 합니다. 설정하지 않으면 알림에 링크를 포함하지 않습니다. MoleSignal을
  내부 네트워크에서만 운영하는 경우, 수신자가 메일을 확인하는 위치에서 페이지와 해당 API에 접근할 수 있어야 합니다.
  [공개 액세스](/ko/public-access)를 참조합니다.

그룹이나 대체 경로의 고정 주소로 보내는 알림에는 링크를 포함하지 않습니다.
문자 메시지, 전화, 통합 알림에도 링크를 포함하지 않습니다. 문자 메시지와 전화는 대신 [응답](#문자-메시지와-전화로-경보-처리)을 사용합니다.

## 템플릿 및 정책 만들기

**설정 → 알림 → 템플릿**을 열어 재사용할 메시지 본문을 만듭니다. 알림
카테고리와 채널을 선택한 다음, [변수](#템플릿-변수)를 삽입하거나
[사전 설정 템플릿](#사전-설정-템플릿)을 적용합니다. 미리보기 이벤트 속성으로 렌더링된
메시지를 확인합니다. 편집기 오른쪽의 변수, 사전 설정 템플릿, 미리보기 이벤트 속성은
처음에 접혀 있습니다. 제목을 선택하면 펼쳐집니다. 템플릿 목록은 채널별로 정렬됩니다.

| 채널 | 적용 범위 | 본문 |
|---|---|---|
| **일반** | 알림 정책에서 별도 템플릿을 선택하지 않은 모든 채널에 적용합니다. | 텍스트, Markdown 또는 HTML을 사용합니다. |
| **인스턴트 메시징**, **이메일**, **웹훅** | 해당 채널에만 적용합니다. | 텍스트, Markdown 또는 HTML을 사용합니다. 인스턴트 메시징 템플릿은 [카드로 전송](#인스턴트-메시징-템플릿의-카드)할 수도 있습니다. 웹훅 템플릿은 JSON도 지원합니다. JSON 문자열 규칙에 따라 값을 이스케이프하며, 값을 채운 본문은 유효한 JSON이어야 합니다. 이 본문을 [범용 웹훅](#범용-웹훅)의 **알림 템플릿 본문**으로 전송합니다. |
| **SMS**, **전화** | 해당 채널에만 적용합니다. | 알림 제목 없이 일반 텍스트 본문만 전달합니다. SMS는 최대 320자를 전송하고 전화는 최대 400자를 읽습니다. 편집기에 문자 수가 표시됩니다. |

그런 다음 **정책**을 열고 라우팅 규칙을 만듭니다.

1. 이벤트 유형과 카테고리를 선택합니다.
2. JSON 매칭 조건을 추가하고 정책 우선순위를 설정합니다. **시간**에서 **지정 시간대에만 적용** 또는
   **지정 시간대 외에만 적용**을 선택하면 이벤트 발생 시점을 기준으로 주간 시간대에 따라 정책을 적용합니다.
   [휴일 캘린더](/ko/alerting/on-call#휴일-캘린더)를 사용해 휴일도 반영할 수 있습니다.
   적용 시간대가 아니면 이 정책은 알림을 보내지 않으며, 다른 정책은 계속 적용됩니다.
3. 수신자 결정 방식과 해당 구성을 선택합니다.
4. 사용자 설정을 따르거나, 단일 커넥터를 강제하거나, 여러 커넥터로 전송하도록 설정합니다.
5. 일반 템플릿을 선택합니다. 필요하면 인스턴트 메시징, 전화, SMS
   등의 채널별 템플릿을 선택하고 사용자, 팀 또는 조직의 대체 경로를 활성화합니다.
6. 필요하면 확인 응답 제한 시간과 에스컬레이션 경로를 설정합니다. 경보 정책에서는
   [알림 묶기](#알림-묶기) 시간도 설정할 수 있습니다.
7. 실시간 전송 미리보기를 확인합니다. 알림을 보내지 않고 실제 수신 멤버와 경로를 확인하고
   각 단계에서 사용하는 템플릿 이름을 볼 수 있습니다.

전송 시 커넥터의 채널에 맞는 템플릿을 사용합니다. 해당 채널에 템플릿을 지정하지 않았다면
일반 템플릿을 사용하고, 둘 다 없으면 이벤트 자체 메시지를 사용합니다. 알림 정책에서 사용하는 템플릿은
삭제하거나 다른 채널로 옮길 수 없습니다.

현재 정책은 경보 수명 주기와 온콜 일정 이벤트에 적용됩니다. 정책 편집기는
실행 중인 백엔드가 지원하는 이벤트 유형과 수신자 결정 방식을 표시합니다. 정책은
[알림 일시 중지](/ko/alerting/silences) 조건에 일치하는 인시던트의 경보 이벤트를 전송하지 않습니다.
[알림 일시 중지 중의 알림](/ko/alerting/silences#음소거-중-알림)을 참조합니다.

### 알림 묶기

경보가 몰리면 한 사람이나 그룹에 몇 초 만에 여러 알림이 도착할 수 있습니다.
경보 및 에스컬레이션 카테고리의 알림 정책에는 **알림 묶기**가 있습니다. 30초, 1분, 2분,
5분 중에서 선택합니다(API는 10초~10분을 지원합니다). 설정한 시간 동안 같은 커넥터로 같은 수신자에게 보낼
경보 알림을 묶습니다. 첫 알림은 즉시 보내고 나머지는 시간이 끝나면 한꺼번에 보냅니다.
그 사이에 확인한 경보는 묶음에서 제외합니다.

- 인스턴트 메시징과 이메일은 하나의 목록을 보냅니다. 제목에는 첫 경보의 제목 뒤에 "(+N)"을 붙이고, 본문에는
  경보 목록을 표시합니다. 외부 URL을 설정했으면 각 경보를 해당 인시던트에 연결합니다. Feishu 앱이나
  Slack 앱의 카드에는 **모두 확인**이 표시됩니다. [경보 카드](/ko/im#알림-카드)를 참조합니다.
- SMS와 전화는 각 제목을 차례로 표시하거나 읽습니다. SMS에 한 번 답장하면 묶음 전체에 같은 작업을 적용합니다.
  전화는 설정과 관계없이 최소 60초 동안 묶습니다.
- 범용 웹훅, PagerDuty, Amazon SNS는 알림을 묶지 않습니다.

경보 발생, 복구, 에스컬레이션에 대한 기본 제공 정책은 기본적으로 1분 동안 알림을 묶습니다. 다른
정책의 기본값은 **묶지 않음**입니다.

### 템플릿 변수

본문, 제공업체 템플릿의 값, 카드의 모든 부분에 `{{rule.name}}`과 같은 변수를 넣을 수 있습니다.
전송할 때 알림에 해당하는 값으로 변수를 채웁니다. 편집기 오른쪽의 **변수**에는
템플릿 카테고리에서 사용할 수 있는 변수가 표시됩니다. 변수를 선택하면 커서 위치에 삽입됩니다.
이름이 `_at`으로 끝나면 마이크로초 단위의 타임스탬프이고, `_time`으로 끝나면
`2026-07-29 00:00:00 UTC`와 같은 UTC 시간입니다. 이벤트에 없는 변수는 입력한 그대로 남습니다.

경보 및 에스컬레이션 변수:

| 변수 | 값 |
|---|---|
| `{{rule.name}}`, `{{rule.description}}` | 규칙의 이름과 설명입니다. |
| `{{severity}}`, `{{incident.status}}` | 심각도와 경보 상태입니다. |
| `{{urgency}}`, `{{priority}}` | 긴급도 수준의 키(`high`, `low` 또는 조직에서 추가한 수준)와 우선순위(`P1`~`P9`, 미설정 시 빈 값)입니다. [긴급도](/ko/alerting/on-call#긴급도)를 참조합니다. 알림 정책에서 이벤트 속성 `urgency`와 `priority`를 매칭 조건으로 사용할 수도 있습니다. |
| `{{urgency_name}}`, `{{priority_name}}` | 조직이 [긴급도 및 우선순위 수준](/ko/alerting/on-call#긴급도-및-우선순위-수준)에서 지정한 긴급도 수준과 우선순위의 이름입니다. 이름을 지정하지 않으면 빈 값입니다. |
| `{{value}}`, `{{threshold}}` | 경보를 트리거한 값과 임계값입니다. 심각도 단계가 있는 규칙은 해당 경보의 심각도에 맞는 임계값을 제공합니다. 이상 탐지 규칙은 임계값이 없어 `null`을 표시합니다. |
| `{{incident.url}}` | MoleSignal에서 경보를 열 수 있는 주소입니다. 외부 URL `http.external_url`이 필요합니다. |
| `{{incident.started_time}}`, `{{incident.duration}}` | 경보 시작 시간과 `1h 5m`과 같은 지속 시간입니다. 해결된 경보는 해결 시점까지 계산합니다. |
| `{{incident.acknowledged_time}}`, `{{incident.acknowledged_by}}` | 경보를 확인한 시각과 확인한 사용자의 ID입니다. 확인한 후에 값이 채워집니다. |
| `{{incident.resolved_time}}`, `{{incident.resolved_by}}` | 경보를 해결한 시각과 해결한 사용자의 ID입니다. 해결한 후에 값이 채워집니다. 자동으로 복구된 경보에는 해결한 사용자가 없습니다. |
| `{{incident.assignees}}`, `{{affected_services}}` | 담당자 사용자 ID와 영향을 받은 서비스입니다. 각 목록의 항목은 쉼표로 구분합니다. |
| `{{service}}`, `{{environment}}` | 경보의 레이블 또는 어노테이션에서 가져온 서비스와 환경입니다. |
| `{{labels}}`, `{{labels.<key>}}` | 전체 레이블(`service=api, env=production`)과 개별 레이블의 값입니다. 어노테이션은 `{{annotations.<key>}}`를 사용합니다. |
| `{{escalation.step}}`, `{{escalation.loop}}`, `{{escalation.target}}` | 에스컬레이션 단계와 반복 회차(둘 다 1부터 시작), 해당 단계의 알림 대상(`user`, `schedule` 또는 `team`)입니다. 에스컬레이션에만 적용합니다. |
| `{{escalation.reason}}` | 에스컬레이션 알림을 전송한 이유입니다. `step`(정책이 다음 단계로 진행), `manual`(즉시 에스컬레이션), `reassigned`, `responder_added`, `snooze_ended`, `ack_timeout`(확인 후 제한 시간 내에 해결하지 않음), `severity_raised`, `urgency_raised`가 있습니다. [인시던트에 대응하기](/ko/alerting/incidents#인시던트에-조치하기)를 참조합니다. |
| `{{reply.ack}}`, `{{reply.resolve}}` | 답장으로 경보를 확인하거나 해결하는 코드입니다. 예를 들어 `31`, `32`가 있습니다. [답장으로 처리](#문자-메시지와-전화로-경보-처리)를 켠 SMS 커넥터가 전송하는 경보 문자에서만 값을 채웁니다. 다른 곳에서는 입력한 그대로 남습니다. |

온콜 일정에는 `{{schedule.*}}`, `{{oncall.*}}`, `{{override.*}}`가 있습니다.
마이크로초 단위의 `_at` 값 외에도 인계 시각과 대체 근무 시간대를
`{{oncall.transition_time}}`, `{{override.start_time}}`, `{{override.end_time}}`으로 표시합니다. 모든 카테고리에서
`{{event.time}}`, `{{message.title}}`, `{{message.text}}`를 사용할 수 있으며, 각 이벤트 속성은
`{{event.attributes.<key>}}`로 참조할 수 있습니다.

### 조건

본문에 조건 블록을 넣을 수 있습니다. 조건이 참일 때만 블록의 내용을 포함합니다.

```text
{{#if severity == "critical"}}Act now{{else}}Take a look{{/if}}: {{rule.name}}
{{#if event.type == "alert.resolved"}}Recovered after {{incident.duration}}{{/if}}
{{#if annotations.runbook_url}}Runbook: {{annotations.runbook_url}}{{/if}}
```

- `{{#if variable == "value"}}`와 `!=`로 변수 값을 비교합니다. 변수만 지정하면
  값이 비어 있지 않을 때 참으로 처리합니다.
- `{{else}}` 뒤의 내용은 조건이 거짓일 때 포함합니다. 이 구문은 생략할 수 있습니다.
- 블록은 최대 5단계까지 중첩할 수 있습니다. `{{/if}}`로 닫지 않은 블록이 있으면 저장할 수 없으며, 편집기가
  본문 아래에 오류를 표시합니다.
- 미리보기는 미리보기 이벤트 속성으로 조건을 평가합니다. 편집기 오른쪽의 **조건**에서
  자주 쓰는 조건을 선택해 삽입할 수 있습니다.

### 사전 설정 템플릿

**사전 설정 템플릿**은 미리 작성된 본문입니다. 적용한 후에도 본문을 편집할 수 있습니다.
카테고리와 채널별로 표시합니다. SMS와 전화는 각 채널에 맞는 사전 설정을 제공하며,
인스턴트 메시징과 이메일도 경보 링크가 포함된 인스턴트 메시징용 Markdown이나
표 형식의 경보 이메일 등 채널별 사전 설정을 제공합니다. 경보에는 발생,
확인, 해결 알림용 사전 설정이 있습니다. 확인 또는 해결용 사전 설정을 적용하면
확인되거나 해결된 샘플 경보를 미리 보여줍니다. 사전 설정 본문은 인터페이스 언어를 따르므로
중국어 인터페이스에서는 중국어 본문을 적용합니다.

### 알림 템플릿의 제공업체 템플릿

Alibaba Cloud, Tencent Cloud, Huawei Cloud는 승인한 템플릿만 전송하며, WhatsApp은
승인한 Content 템플릿만 전송합니다. SMS 또는 전화 템플릿에 제공업체별로 하나씩 지정할 수 있습니다.
WhatsApp 템플릿은 SMS 템플릿에만 지정할 수 있습니다.

- **템플릿 코드** — 제공업체에서 발급한 코드입니다. Alibaba Cloud SMS 코드는 `SMS_`로,
  음성 코드는 `TTS_`로 시작합니다. Tencent Cloud와 Huawei Cloud는 템플릿 ID를 사용합니다. WhatsApp은
  **Content SID**에 Twilio Content SID를 입력합니다. `HX` 뒤에 16진수 문자 32개가 이어지는 형식입니다.
- **변수** — 각 변수에 채울 값입니다. 본문과 같은 방식으로 작성하며
  `{{rule.name}}`과 같은 변수를 사용할 수 있습니다. Alibaba Cloud는 템플릿의 `${…}` 안에 있는 이름을 사용합니다.
  Tencent Cloud, Huawei Cloud, WhatsApp은 위치에 따라 값을 채우므로 이름으로 `1`, `2`, `3`을 사용합니다.
- **변수당 문자 수** — 한도를 넘는 값은 잘라냅니다. 비워 두면 기본값을 사용합니다. Alibaba Cloud는 35,
  Tencent Cloud는 SMS 6, 음성 20, Huawei Cloud는 SMS 20, 음성 32(음성은 32바이트에서도 잘라냄),
  WhatsApp은 300입니다.

이들 제공업체의 커넥터는 각 제공업체용 템플릿을 전송하고, 그 외 SMS 및 전화 커넥터는
템플릿 본문을 전송합니다. 알림 정책에서 해당 채널에 선택한 템플릿에 해당 제공업체용 템플릿이 없으면
전송에 실패하며 전송 로그에 이유를 기록합니다.

이러한 커넥터를 테스트할 때는 같은 채널에서 해당 제공업체용 템플릿이 포함된 템플릿을 사용하고
자리표시자를 샘플 값으로 채웁니다. 해당 커넥터에 연결된 멤버의 번호를 테스트할 때는 이름순으로
첫 번째 템플릿을 사용합니다. 예약 점검, 자동화, 기타 직접 전송은 알림 템플릿을 사용하지 않으므로
이러한 커넥터를 사용할 수 없습니다.

### 인스턴트 메시징 템플릿의 카드

인스턴트 메시징 템플릿에서 **카드로 전송**을 켜면 앱과 그룹 봇이 카드를 보냅니다.
끄면 이전과 같이 텍스트를 보냅니다. 카드의 텍스트에는 템플릿의 메시지 본문을 사용합니다. 그 외에
다음 항목을 설정할 수 있습니다.

- **카드 제목** — 비워 두면 알림 제목을 사용합니다.
- **제목 색상** — 심각도에 따른 색상(치명적은 빨간색, 오류는 주황색, 경고는 노란색, 나머지는 파란색,
  해결 후에는 초록색) 또는 고정 색상을 사용합니다.
- **필드** — 이름과 값입니다. 예를 들어 `Service`의 값으로 `{{labels.service}}`를 지정합니다. 최대 10개까지 추가할 수 있습니다.
- **링크 버튼** — 버튼 텍스트와 주소입니다. 예를 들어
  `Runbook`의 주소로 `{{annotations.runbook_url}}`을 지정합니다. 최대 5개까지 추가할 수 있습니다.
- **바닥글** — 카드 하단에 작은 글씨로 표시하는 한 줄입니다.

모든 항목에 변수를 사용할 수 있습니다. 이벤트에서 값을 채울 수 없는 필드나 링크는 제외합니다.
주소가 http(s)가 아닌 링크도 제외합니다. 편집기 미리보기는 대략적인 모양을 보여줍니다.
각 플랫폼은 자체 형식으로 카드를 전송합니다.

| 플랫폼 | 전송 형식 |
|---|---|
| **Lark** | 대화형 카드입니다. 제목 영역에 색상을 적용하고 필드를 두 열로 배치하며 구분선 아래에 바닥글을 표시합니다. 앱에서는 경보의 확인 및 해결 버튼 옆에 링크 버튼을 표시합니다. |
| **Slack** | 색상 막대가 있는 Block Kit 카드입니다. 앱에서는 경보 버튼 옆에 링크 버튼을 표시합니다. |
| **DingTalk** | ActionCard입니다. 제목에 색상을 적용하고 카드 아래에 링크 버튼을 최대 5개까지 표시합니다. 링크가 없으면 Markdown으로 전송합니다. 앱에 카드 템플릿 ID가 있으면 해당 템플릿으로 경보 버튼이 있는 대화형 카드를 전송합니다. |
| **WeCom** | 카드처럼 배치한 Markdown입니다. 제목에 색상을 적용합니다(WeCom은 초록색, 회색, 주황색 텍스트만 지원합니다). 경보 버튼이 있으면 버튼 상호작용형 템플릿 카드로 전송합니다. 필드는 텍스트가 있는 소제목으로 최대 6개까지 표시하며, 카드를 누르면 MoleSignal이 열립니다. |
| **Teams** | Adaptive Card입니다. 제목 영역에 색상을 적용하고, 필드는 이름과 값 쌍으로, 링크는 버튼으로 표시합니다. 바닥글은 구분선 아래에 표시합니다. 봇의 링크 버튼은 경보 버튼과 함께 표시합니다. |
| **Google Chat** | 카드입니다. 필드는 레이블이 붙은 줄로, 링크는 버튼으로 표시합니다. 앱의 링크 버튼은 경보 버튼과 함께 표시합니다. Google Chat 카드 제목에는 색상을 적용하지 않습니다. |
| **Telegram** | 메시지입니다. 제목 색상의 점 뒤에 제목을 굵게 표시하고, 필드는 한 줄에 하나씩, 바닥글은 기울임꼴로 표시합니다. 첫 줄에 경보 버튼을 배치하고 아래에 링크 버튼을 한 줄에 두 개씩 배치합니다. Telegram에서 공개되지 않은 주소를 거부하면 링크를 본문에 줄 단위로 표시합니다. |
| **Discord** | 임베드입니다. 색상 막대를 표시하고 제목을 경보에 연결합니다. 본문 아래에 링크를 표시하고 필드를 나란히 배치한 뒤 바닥글을 표시합니다. |
| **Mattermost** | 메시지 첨부입니다. 색상 막대를 표시하고 제목을 경보에 연결합니다. 필드를 표시하고 짧은 필드는 나란히 배치합니다. 링크는 본문 아래에 표시하고 바닥글을 덧붙입니다. 봇의 경보 버튼은 첨부 아래에 표시합니다. |
| **Webex** | 봇은 Teams 카드와 같은 구조의 Adaptive Card를 전송합니다. 링크 버튼은 최대 5개까지 표시하고, 추가 링크는 본문 아래에 표시합니다. 웹훅은 Markdown을 전송합니다. |
| **Matrix** | 서식이 적용된 메시지입니다. 제목에 색상을 적용하고 필드를 목록으로 표시한 다음 링크와 기울임꼴 바닥글을 표시합니다. |

그룹 봇은 클릭 이벤트를 받지 않으므로 카드에 확인 또는 해결 버튼을 표시하지 않습니다.
커넥터를 테스트할 때 인스턴트 메시징 템플릿을 선택하면 변수에 샘플 값을 채워
카드를 전송할 수 있습니다.

### 기본 제공 정책

모든 조직은 아래 알림 정책을 기본으로 사용합니다. 별도 정책을 만들기 전에도 경보와 온콜 이벤트를
전달할 수 있습니다. 모든 정책은 **사용자 설정 따르기**를 적용합니다. 메시지를 전송할 수 없으면
사용자의 대체 엔드포인트를 먼저 사용한 다음 팀, 조직 순으로 대체 경로를 사용합니다.
별도 템플릿을 선택하지 않고 이벤트 자체 메시지를 전송합니다.

| 기본 제공 정책 | 이벤트 | 알림 대상 | 기본 상태 |
|---|---|---|---|
| 경보 발생: 소유자에게 알림 | 경보 발생 | 경보 소유자, 소유자가 없으면 담당자 | 켜짐 |
| 경보 해결: 소유자에게 알림 | 경보 해결 | 경보 소유자, 소유자가 없으면 담당자 | 켜짐 |
| 에스컬레이션: 단계에 지정된 사용자에게 알림 | 사용자에게 경보 에스컬레이션 | 단계에서 지정한 사용자 | 켜짐 |
| 에스컬레이션: 단계에 지정된 팀에 알림 | 팀에 경보 에스컬레이션 | 해당 팀의 멤버 | 켜짐 |
| 온콜 인계: 양쪽 담당자에게 알림 | 온콜 교대 시작 | 근무를 마치는 담당자와 시작하는 담당자 | 켜짐 |

| 온콜 대체 근무: 관련 담당자에게 알림 | 온콜 대체 근무 생성 | 대체 담당자와 기존 온콜 담당자 | 꺼짐 |

**알림 정책** 목록에서 기본 제공 정책에는 **기본 제공** 표시가 있습니다. 정책을 수정하거나
끌 수 있지만 삭제하거나 이름을 바꿀 수 없습니다. 수정한 정책을 위의 설정으로 되돌리려면 편집기에서
**기본값 복원**을 선택합니다. 일정으로 에스컬레이션하는 단계에는 기본 제공 정책이 없습니다.
일정마다 수신자를 **현재 온콜 담당자**로 지정한 정책을 만듭니다.

## 대체 경로 구성

**설정 → 알림 → 대체 경로**를 엽니다. 조직 또는 팀 범위와
알림 카테고리를 선택합니다. 활성화된 커넥터를 하나 이상 추가하고, `fixed_address` 또는
`fixed_group`을 선택한 뒤 공급자 측 대상을 입력합니다.

MoleSignal은 활성화된 개인 경로 단계가 실패하면 화면에 표시된 순서대로 대체 경로를 시도합니다.
정책에 따라 사용자, 팀, 조직 수준의 대체 경로를 사용할지 결정합니다.

## 전송 내역 확인 및 재시도

**설정 → 알림 → 전송 로그**를 엽니다. 이벤트 ID, 상태 또는 단계로 필터링합니다.
전송 시도를 선택해 마스킹된 대상, 커넥터, 지연 시간, 공급자 오류, 전체 전송
흐름을 확인합니다.

- `notify.deliveries.read` 권한으로 전송 기록을 조회할 수 있습니다.
- `notify.deliveries.acknowledge` 권한으로 원본 이벤트를 확인 처리할 수 있습니다.
- `notify.deliveries.retry` 권한으로 실패한 경로를 재시도할 수 있습니다.

재시도하면 새 전송 시도가 생성됩니다. 기존 전송 기록은 변경되지 않습니다.

전송에 실패한 경보 알림은 자동으로 재시도합니다. 경보를 확인 처리하거나 해결하면 자동 재시도를 중단하지만, 수동으로는 재시도할 수 있습니다.

전송 단계가 **직접**이면 [예약된 로그 검사](/ko/logs/inspections)처럼 커넥터와 대상을
직접 지정하는 기능에서 시작한 전송입니다. 직접 전송에는 정책을 적용하지 않으며
재시도할 수 없습니다.

## 커넥터 수명 주기 및 상태

| 상태 | 의미 |
|---|---|
| **알 수 없음** | 성공 또는 실패로 완료된 커넥터 테스트가 아직 없습니다. |
| **연결됨** | 가장 최근 테스트가 성공했습니다. |
| **오류** | 가장 최근 테스트가 실패했습니다. 이후 테스트가 성공할 때까지 일반 라우팅에서 이 커넥터를 건너뜁니다. |
| **비활성화됨** | MoleSignal은 이 커넥터를 테스트하거나 이 커넥터를 통해 전송하지 않습니다. |

커넥터를 비활성화해도 참조는 그대로 유지됩니다. 사용자 ID,
정책, 대체 경로 또는 예약된 로그 검사가 커넥터를 참조하는 동안에는 삭제할 수 없습니다. 모든
참조를 다른 커넥터로 변경한 뒤 삭제합니다.

## 전송 문제 해결

| 증상 | 확인 사항 |
|---|---|
| SMTP 인증 또는 TLS 실패 | 호스트, 포트, 자격 증명, TLS 모드, 발신자 주소, DNS 및 아웃바운드 네트워크 액세스를 확인합니다. |
| Slack에서 API 오류 반환 | 봇 토큰, `chat.postMessage` 권한, 대상 ID 및 채널 멤버십을 확인합니다. |
| Lark에서 메시지 거부 | 앱 권한, 수신자 ID 유형, 채팅방 멤버십, 웹훅 시크릿 및 서버 시간을 확인합니다. |
| 웹훅에서 오류 반환 | URL, 메서드, 헤더 JSON, 제한 시간 및 엔드포인트가 2xx 응답을 반환하는지 확인합니다. |
| 사용자에게 알림이 전송되지 않음 | 사용자 ID와 커넥터가 활성화되어 있는지, 카테고리 기본 설정에 해당 ID가 포함되어 있는지, 알림 금지 시간으로 전송이 차단되지 않는지 확인합니다. |
| 대체 경로가 실행되지 않음 | 정책에서 해당 수준의 대체 경로를 활성화했는지, 카테고리에 활성화된 경로가 있는지 확인합니다. |
| 전화 또는 문자 메시지가 전송되지 않음 | 번호가 + 기호와 국가 코드로 시작하는지, 템플릿과 서명이 승인되었는지, 알림 정책이 채널에 선택한 템플릿에 해당 공급자용 템플릿이 있는지, 변수 이름이 일치하는지 확인합니다. 공급자의 요청 한도와 계정 샌드박스 설정도 확인합니다. |
| 답장하거나 키를 눌러도 반응이 없음 | 커넥터에서 **답장 처리**가 켜져 있는지, 공급자 콜백이 커넥터에 표시된 URL을 가리키는지, 인터넷에서 해당 URL에 접근할 수 있는지 확인합니다. 해당 번호로 코드가 포함된 경보 문자가 도착했는지, 코드를 발급한 지 24시간이 지나지 않았는지, 수신 멤버에게 `alerts.incidents.acknowledge` 권한이 있는지도 확인합니다. |
| 메시지는 도착했지만 Feishu 또는 DingTalk 단계가 실패함 | 긴급 호출이 실패했습니다. 앱 권한, 긴급 호출 또는 DING 사용 한도, DingTalk 에디션을 확인합니다. Feishu의 경우 수신자 ID 유형과 플랫폼도 확인합니다. |
| 작업 링크를 열어도 반응이 없음 | 링크를 아직 사용하지 않았고 발급한 지 24시간이 지나지 않았는지, 경보가 여전히 해당 작업을 기다리는지, 수신자에게 `alerts.incidents.acknowledge` 권한이 여전히 있는지 확인합니다. 링크를 연 환경에서 페이지와 `/api/v1/public/notify/actions/`에 접근할 수 있는지도 확인합니다. |
