스트림은 수집, 쿼리, 파이프라인, 리텐션에 사용되는 조직 범위의 계약입니다.
**스트림**을 열어 도착하는 데이터를 확인하고 각 스트림을 검사하거나 설정합니다.

## 스트림 유형

| 유형 | 일반적인 내용 |
|---|---|
| `logs` | 구조화된 이벤트와 애플리케이션 로그입니다. |
| `metrics` | 하나의 Prometheus 서버처럼 한 소스의 메트릭 샘플이며 `metric_name`으로 구분합니다. |
| `traces` | OpenTelemetry 스팬입니다. |
| `profiles` | pprof 블롭에 연결된 프로파일 메타데이터입니다. |
| `extend` | 테이블 확장으로 관리되고 처리 중에 사용되는 조회 데이터입니다. |

동일한 스트림 이름이 서로 다른 스트림 유형에 존재할 수 있습니다. API
요청과 자동화에는 항상 `stream_type`을 포함합니다.

### 플랫폼 스트림

MoleSignal은 다음 스트림을 직접 기록합니다:

| 스트림 | 내용 |
|---|---|
| `_molesignal` | `_sys` 조직에 있는 MoleSignal 자체의 텔레메트리입니다. [자체 관측성](/ko/self-observability)을 참고합니다. |
| `_synthetic_results` | 신서틱 검사 실행마다 한 개의 행이 생성됩니다. [신서틱 모니터링](/ko/synthetics#결과-스트림-및-보존)을 참고합니다. |
| `_audit` | 워크스페이스의 감사 이벤트입니다. [감사 스트림](/ko/settings/data-security#감사-스트림)을 참고합니다. |
| `_agent_model_traces` | Mole Agent의 모델 호출입니다. [사용량 및 예산](/ko/agent#사용량-및-예산)을 참고합니다. |
| `_agent_score_traces` | Mole Agent 답변의 품질 점수입니다. [품질](/ko/quality#스트림의-점수)을 참고합니다. |

다른 스트림과 동일하게 읽습니다. `_audit`에는 `audit.read`가 필요합니다. 이 권한이 없으면 스트림이
목록에도 런타임 수치에도 표시되지 않으며, 스트림을 열거나 변경하거나 삭제하면 `403`이 반환됩니다. 그 외에는 이 스트림에 기록할 수 없습니다. 이 이름 중 하나를 사용하는 스트림은 생성할 수 없고, 해당 스트림으로 수집하면
`403`이 반환되며 어떤 [파이프라인](/ko/pipelines#플랫폼-스트림)도 기록하지 않습니다.

## 스트림 목록

**스트림**은 워크스페이스의 모든 스트림을 나열합니다. 탭을 전환하여 **전체** 스트림 또는 한 가지 유형을 표시하고,
이름이나 설명으로 검색하며 런타임 상태로 필터링합니다. 상단에는 정상적으로 수신하는 스트림과
주의가 필요한 스트림의 수를 집계하고, 해당 기간에 기록된 압축 데이터와
현재 저장 용량을 합산합니다.

| 열 | 표시 내용 |
|---|---|
| **상태** | **정상**, **지연**, **중단됨**, **트래픽 없음**, **미사용**, 또는 **통계 확인 불가**입니다. 아래를 참고합니다. |
| **수신 속도**, **마지막 수신** | 데이터가 도착하는 속도와 마지막으로 도착한 시점입니다. |
| 압축 데이터 | 해당 기간에 기록된 압축 바이트입니다. |
| **현재 저장 용량**, **리텐션** | 현재 저장된 바이트와 데이터가 보관되는 일수입니다. |
| **레코드**, **수집 크기**, **저장 크기**, **인덱스 크기** | 보관된 레코드, 변환 전에 수신된 바이트, 데이터 파일의 바이트, 인덱스의 바이트입니다. |

| 상태 | 의미 |
|---|---|
| **정상** | 최근 15분 이내에 데이터가 도착했습니다. |
| **지연** | 마지막 데이터가 15분에서 2시간 전 사이에 도착했습니다. |
| **중단됨** | 2시간 넘게 데이터가 없습니다. |
| **트래픽 없음** | Mole Agent 트레이스의 스트림으로, 답변 사이에는 활동이 없습니다. |
| **미사용** | 스트림이 데이터를 한 번도 수신한 적이 없습니다. |

**쿼리 불가**로 표시된 스트림은 계속 데이터를 수신하지만 쿼리 선택기에서 숨겨집니다. 각 행에는
**쿼리** 또는 **탐색**, **세부 정보 보기**, **스트림 ID 복사**가 있습니다. 상단의 **검색 작업**을 선택하면
[검색 작업](#검색-작업)이 열립니다.

## 스트림 생성

MoleSignal은 스트림에 처음 기록할 때 스트림을 생성하므로 대부분의 스트림은 자동으로 나타납니다. 스트림을
미리 생성하여 처음부터 리텐션, 암호화된 필드 또는 쿼리 액세스를 설정할 수 있습니다. **스트림 생성**을
선택합니다:

| 필드 | 규칙 |
|---|---|
| **스트림 이름** | `snake_case`, 최대 64자입니다. |
| **설명** | 선택 사항입니다. 스트림을 통해 흐르는 데이터입니다. |
| **신호 유형** | **로그**, **메트릭**, 또는 **트레이스**입니다. |
| **보존 기간(일)** | 데이터가 보관되는 기간입니다. |
| **인덱싱된 필드** | 전체 텍스트 인덱스가 생성되는 쉼표로 구분된 필드입니다. |
| **암호화된 필드** | 저장되기 전에 암호화되는 쉼표로 구분된 필드입니다. 나중에 변경할 수 없습니다. [암호화된 필드](#암호화된-필드)를 참고합니다. |
| **쿼리 허용** | 라우팅 파이프라인에만 데이터를 제공하는 소스 스트림의 경우 끕니다. |

## 스트림 세부 정보

스트림을 선택하여 엽니다. **데이터 쿼리**는 해당 스트림을 탐색기에서 열며, 메뉴에는
**스트림 ID 복사**와 **스트림 삭제**가 있습니다. 탭은 다음과 같습니다:

| 탭 | 내용 |
|---|---|
| **개요** | 런타임 상태, 처음 수신된 데이터, 쿼리 액세스, 24시간 동안 기록된 행과 압축 데이터의 추세입니다. 데이터가 없는 스트림에는 **데이터 소스 설정**과 **테스트 데이터 전송**이 제공됩니다. |
| **필드 및 인덱스** | 필드와 해당 유형, 인덱스 유형, 암호화입니다. 필드를 편집하여 인덱스나 마스킹을 변경합니다. [스키마 및 필드](#스키마-및-필드)를 참고합니다. |
| **리텐션** | 스트림의 리텐션과 메트릭 스트림의 다운샘플링입니다. [리텐션 및 삭제](#리텐션-및-삭제)를 참고합니다. |
| **사용량** | 스트림에 의존하는 항목(스트림에 기록하는 수집 엔드포인트, 파이프라인, 저장된 쿼리, 알림 규칙)입니다. 변경하거나 삭제하기 전에 확인합니다. |
| **설정** | **설명**, **쿼리 허용**, **최대 쿼리 범위(시간)**, **작은 파일을 일별로 병합**, **필드별 분할**, 로그의 경우 **필드별 클러스터링**입니다. |

탭의 변경 사항은 초안에 모입니다. **저장 및 적용**은 변경 사항을 한 번에 적용하며,
**변경 사항 삭제**는 변경 사항을 버립니다. 저장하기 전에 페이지에서 되돌릴 수 없는 변경 사항을 경고합니다:
리텐션을 줄이면 만료된 데이터가 삭제되고, 다운샘플링하면 원본 샘플이 삭제됩니다.

**최대 쿼리 범위**는 스트림에 대한 SQL 또는 PromQL 쿼리 하나가 포함할 수 있는 시간 범위를 제한합니다. 더
긴 범위의 쿼리는 거부되므로 실수로 "최근 90일"을 지정해도 대용량 스트림을 처음부터 끝까지 스캔할 수 없습니다. 비어 있거나
`0`이면 제한이 없습니다.

**쿼리 허용**을 끄는 경우는 모든 데이터를 수신하는 소스가 계속 수신해야 하지만 쿼리
선택기에 표시되지 않아야 할 때입니다. 라우팅 파이프라인은 여전히 스트림을 읽을 수 있습니다. `extend` 데이터는 일반 텔레메트리 쿼리 경로가 아니라
**테이블 확장**을 통해 관리합니다.

## 스키마 및 필드

필드에는 이름, 데이터 유형, `nullable` 플래그, 인덱스 유형, `encrypted` 플래그가 있습니다. 데이터 유형은 `bool`, `int64`, `float64`, `utf8`, `timestamp` 및 `json`입니다. 새 필드는 수신 데이터에 처음 나타날 때 스키마에 추가되며, 다른 유형의 값은 `type mismatch on field`와 함께 거부됩니다. 숫자는 예외입니다: 소수가 있는 숫자나 `int64` 범위를 넘는 정수를 받는 `int64` 필드는 같은 배치 또는 이후 배치에서 `float64`가 되며, 이전에 저장된 값은 `float64`로 읽힙니다.

인덱스 유형은 MoleSignal이 필드에 대해 생성하는 보조 구조를 결정합니다:

| 인덱스 유형 | 효과 |
|---|---|
| `none` | 보조 인덱스가 없습니다. 기본값입니다. |
| `exact` | 전체 값에 대한 정확히 일치 역색인(텍스트가 아닌 필드의 경우 Parquet 블룸 필터)과 각 파일의 최솟값 및 최댓값입니다. `=`와 `IN`은 파일을 열기 전에 해당 값이 없는 파일을 건너뛰고, 일치하는 행이 적으면 일치하는 행의 페이지만 읽습니다. 파일당 값이 최대 65,536개인 필드의 `LIKE` 또는 `ILIKE`는 어떤 값에도 텍스트가 없는 파일을 건너뜁니다. `trace_id` 같은 식별자에 사용합니다. |
| `full_text` | 텍스트 검색을 위한 토큰화된 역색인입니다: 연속된 문자와 숫자는 단어이고, CJK 텍스트는 겹치는 두 문자 바이그램으로 나뉩니다. 문장 부호와 CJK 텍스트를 포함한 `MATCH`, `MATCH_TEXT`, `LIKE`, `ILIKE`의 리터럴은 일치할 수 없는 파일을 건너뜁니다. `utf8` 필드에만 적용됩니다. |
| `bloom` | Parquet 블룸 필터와, 텍스트 및 `int64` 필드의 파일별 전체 값 필터, 각 파일의 최솟값 및 최댓값입니다: `=`와 `IN`은 파일을 열기 전에 해당 값이 확실히 없는 파일을 건너뜁니다. 값이 많고 동등 비교로만 조회되는 필드(예: 요청 ID)에 사용합니다. |
| `skip` | 각 파일의 최솟값 및 최댓값과, 서로 다른 값이 최대 32개인 파일의 모든 값입니다. 비교, `IN`, `BETWEEN`, 접두사 `LIKE`는 이를 사용해 파일을 건너뜁니다. |
| `ngram` | 각 파일 값의 트라이그램과, 파일 내 각 1,024행 블록의 5바이트 조각을 대소문자 구분 없이 저장합니다: 파일에 없는 트라이그램이 포함된 `LIKE`, `ILIKE`, `MATCH` 리터럴은 해당 파일을 건너뛰고, 블록에 없는 조각이 포함된 리터럴은 해당 블록을 건너뛰므로, ID 또는 다른 희귀 문자열 검색은 해당 문자열을 포함할 수 있는 몇 개의 블록만 읽습니다. 5바이트보다 짧은 리터럴은 모든 블록을 읽습니다. `ngram` 필드가 있는 스트림은 파일을 1,024행 단위 페이지로 작성합니다. 작은 페이지와 조각은 공간을 차지합니다: 이러한 필드가 각 행의 3분의 2를 차지한 테스트에서 스토리지가 약 14% 증가했습니다. 조각으로 검색되는 URL, 경로, 호스트 이름에 사용하고 긴 자유 텍스트에는 사용하지 마십시오. `utf8` 필드에만 적용됩니다. |
| `ip` | 각 파일 주소의 범위(IPv4는 IPv6로 매핑): `CIDR_MATCH(field, '10.0.0.0/8')` 및 주소에 대한 `=`는 이를 사용해 파일을 건너뜁니다. `utf8` 필드에만 적용됩니다. |
| `key_value` | JSON 객체의 1단계 키와 해당 값입니다: `json_text(field, 'key') = 'value'`, `IN`, `IS NOT NULL`은 키나 값이 없는 파일을 건너뛰고, 일치하는 행이 적으면 일치하는 행의 페이지만 읽습니다. 값은 `json_text`가 반환하는 대로 일치됩니다: 텍스트는 그대로, 숫자와 불리언은 JSON으로 표시됩니다. `json` 필드에만 적용됩니다. |
| `range` | 인덱스에 있는 각 행의 숫자와 각 파일의 최솟값 및 최댓값입니다. 조건이 `exact` 필드의 `=`, `range` 필드의 숫자에 대한 `>`, `>=`, `<`, `<=`, 그리고 시간 범위인 `count(*)`는 파일을 읽지 않고 인덱스에서 응답됩니다; 다른 비교는 범위를 벗어난 파일을 건너뜁니다. `int64`, `float64`, `timestamp` 필드에만 적용됩니다. |

인덱싱된 모든 필드는 각 파일에 대해 해당 필드가 비어 있는 행 수를 기록합니다. `IS NULL`은 필드에 항상 값이 있는 파일을 건너뛰고, 필드에 대한 다른 모든 조건(예: `IS NOT NULL`, `!= ''`처럼 값이 있는지 묻는 조건 포함)은 필드에 값이 전혀 없는 파일을 건너뜁니다.

조건이 `OR`로 결합된 경우, 파일에서 모든 분기가 배제되면 해당 파일도 건너뛰며, 각 분기는 이를 응답하는 인덱스에 의해 배제됩니다: `level = 'error' OR status >= 500`은 `level` 인덱스에 `error`가 없고 `status`가 500에 도달하지 않는 파일을 건너뜁니다.

수신 데이터에 처음 나타나는 필드는 이름에서 인덱스 유형을 가져옵니다:

| 스트림 유형 | 필드 | 인덱스 유형 |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`, `level`, `session_id`, `fingerprint`, `country`, `browser`, `application`, `environment` 및 OpenTelemetry 필드 `host.id`, `container.id`, `event.name`, `event.domain`, `severity_text` | `exact` |
| `traces` | `trace_id`, `span_id`, `parent_span_id`, `service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

다른 모든 새 필드는 `none`을 받습니다. 단, 스트림의 자체 규칙이 달리 지정하는 경우는 예외입니다: [새 필드의 인덱스](#새-필드의-인덱스)를 참조하십시오. `exact` 유형의 `level`을 사용하면 로그 히스토그램이 파일을 읽지 않고 인덱스에서 오류를 집계할 수 있습니다. RUM 스트림은 `context`, `feature_flags`, `usr.extra`의 키를 `key_value`로 인덱싱합니다.

변경된 인덱스 유형은 이후에 작성되는 데이터에 즉시 적용됩니다. 이전에 작성된 데이터는 새 설정에 따라 백그라운드에서 다시 인덱싱됩니다: 각 봉인된 파티션(기본적으로 종료 후 48시간 뒤 봉인됨)은 해당 파일에서 다시 작성되고, 더 새로운 파일은 봉인되거나 병합된 후 다시 작성됩니다. 그때까지 파일은 작성 당시의 인덱스를 유지하며, 이는 쿼리 결과를 바꾸지 않고 쿼리가 읽는 파일 수만 바꿉니다. **개요**의 **인덱싱된 필드 비율**은 남은 파일 수를 보여줍니다. 전체 텍스트 인덱스 형식이 변경되면(예: CJK 텍스트가 바이그램으로 나뉘기 시작한 경우) 이전 파일의 인덱스도 같은 방식으로 백그라운드에서 새 형식으로 다시 작성됩니다.

필드를 변경하려면 **필드 및 인덱스**를 열고, 필드의 편집 작업을 선택한 다음, 다음을 선택합니다:

- **인덱스 유형**: **인덱싱 안 함**, **전체 텍스트 검색**, **정확히 일치**, **블룸 필터**,
  **스킵 인덱스**, **N-gram 부분 문자열**, **IP 주소**, 또는 **JSON 키**. 전체 텍스트 검색, N-gram
  부분 문자열, IP 주소는 텍스트 필드에 적용되고, JSON 키는 JSON 필드에 적용됩니다;
- **결과 필드 마스킹**의 **스트림 수준 정책**: **전역 규칙 상속**, **사용자 지정 스트림 규칙**,
  또는 **이 스트림에서 마스킹 제외**. [필드 마스킹](/ko/settings/data-security#필드-마스킹)을 참조하십시오.
  메트릭 스트림은 마스킹에 참여하지 않습니다.

**초안에 적용**을 선택한 다음 **저장 및 적용**을 선택합니다. 필드의 데이터 유형은 절대 변경되지 않습니다.

### 새 필드의 인덱스

**설정** 탭의 **필드 인덱스**에서 규칙은 스트림에 처음 나타나는 필드에
이름에 따라 인덱스를 부여합니다. **규칙 추가**를 선택하고, 필드 이름 패턴을 입력한 다음 인덱스 유형을 선택합니다:
`*`는 임의의 텍스트 연속을, `?`는 한 문자를 나타내므로 `*_id`는 `user_id` 및
`order_id`와 일치하고, `http.*`는 `http` 아래의 모든 필드와 일치합니다. 순서상 패턴이
이름과 일치하고 인덱스 유형이 필드의 데이터 유형에 맞는 첫 번째 규칙이 적용됩니다.
**필드 및 인덱스**에서 이름으로 필드에 설정한 인덱스가 우선하며, 어떤 규칙과도 일치하지 않는 필드는 위의 기본값을 받습니다.
규칙은 지금부터 나타나는 필드에만 영향을 줍니다: 기존 필드는 **필드 및
인덱스**에서 변경합니다. 스트림에는 최대 32개의 규칙이 있습니다.

### 필드별 분할

로그 또는 트레이스 스트림은 하나 또는 두 개의 텍스트 필드로 분할할 수 있습니다: **설정** 탭의 **필드별 분할**에서
**필드 추가**를 선택하고, 필드를 선택한 다음 분할 방식을 선택합니다. 이후에 작성되는
데이터는 필드 값에 따라 샤드로 분할되며, 각 샤드는 자체 파일에 작성됩니다.

- **해시**는 값을 해시에 따라 2~64개의 샤드로 균등하게 분할합니다. 필드에 동등
  조건(`=` 또는 `IN`)이 있는 쿼리는 해당 값의 샤드 파일만 읽습니다.
- **첫 문자**는 값을 첫 문자에 따라 37개의 샤드로 분할합니다: 각 숫자 및
  각 문자(대소문자 무관), 그리고 기타 모든 값(빈 값 포함)을 위한 샤드 하나입니다. 필드에 동등
  조건이 있는 쿼리 또는 텍스트로 시작하는 `LIKE`(예: `'web-%'`)는 오직
  해당 문자의 샤드 파일만 읽습니다; `ILIKE`는 기타 모든 값의 샤드도 읽습니다. 샤드가 얼마나
  균등한지는 데이터에 따라 다릅니다: 16진수 트레이스 ID는 그중 16개만 사용합니다.

두 필드를 사용하면 파일이 두 필드의 샤드로 분할되므로 샤드 수가 곱해집니다. **필드별
분할**은 총계(최대 256개)를 표시합니다: 첫 문자(37개 샤드)는 최대 4개의
샤드가 있는 해시와 함께 사용됩니다. 어느 한 필드에 조건이 있는 쿼리는 더 적은 파일을 읽고, 두 필드 모두에 조건이 있는 쿼리는
더 적게 읽습니다. 거의 모든 쿼리가 지정하는 분할 필드(예: 서비스, 네임스페이스 또는 테넌트)를 사용하십시오.
샤드가 많을수록 파일이 더 많고 작아집니다.

설정은 변경 이후에 작성되는 데이터에 적용됩니다: 기존 파일은 그대로 유지되며, 쿼리는
각 파일을 작성 당시의 필드를 기준으로 판단하고, 컴팩터는 동일한
필드로 작성된 파일만 병합합니다. 분할 필드는 암호화되지 않은 텍스트 필드여야 하며, 두 필드는 서로 달라야 합니다.

### 필드별 클러스터링

로그 스트림은 하나 또는 두 개의 필드로 파일 내 행을 클러스터링할 수 있습니다: **설정** 탭의 **필드별 클러스터링**에서
**필드 추가**를 선택하고, 필드를 선택한 다음 **시간 구간**을 선택합니다. 이후에 작성되는 각
파일에서 행은 해당 너비의 시간 구간에 최신순으로 배치되고, 구간 내에서는
필드 값에 따라 그다음 최신순으로 배치됩니다.

시간 순서에서는 서비스 같은 값이 파일의 모든 페이지에 나타납니다. 클러스터링하면 각 구간에서
해당 값이 몇 개의 페이지에만 있으므로, 클러스터링 필드에 동등 조건(`=` 또는 `IN`)이 있는 쿼리는
해당 페이지들만 읽습니다. 쿼리가 자주 지정하고 값이 적은 필드(예: 서비스 또는 레벨)를 사용하십시오.

각 클러스터링된 파일은 또한 각 분에 클러스터링 필드 값의 각 조합으로
들어가는 행 수를 유지합니다. 텍스트 클러스터링 필드에 동등 조건이 있는 카운트,
그중 하나로 그룹화한 카운트(`GROUP BY service`), 막대가 정각 분인 히스토그램은
이러한 숫자에서 파일을 읽지 않고 응답됩니다. 쿼리 기간이 파일 내부의 정각 분에서 시작하거나 끝나는 경우에도
마찬가지입니다. 분과 값의 조합이 65,536개를 넘는 파일은 아무것도 유지하지 않습니다.
같은 숫자는 최신 또는 가장 오래된 행의 페이지가 어디에 있는지 알려주므로, 그러한 페이지는
클러스터링 필드에 동등 조건이 있든 없든 해당 페이지가 나오는 분만 읽습니다.

시간 구간은 1분, 5분 또는 10분이며, 기본값은 1분입니다. 더 넓은 구간은 더 많은 페이지를 건너뛰지만,
짧은 시간 범위에 대한 쿼리는 닿는 구간을 전체로 읽습니다.

클러스터링은 [필드별 분할](#필드별-분할)과 다릅니다: 분할은 각 샤드를 자체
파일에 작성하므로 쿼리는 더 적은 파일을 읽지만 스트림에는 더 많고 작은 파일이 생깁니다; 클러스터링은 파일을 유지하고
파일 내부의 행 순서를 정합니다. 두 방식을 결합할 수 있습니다.

설정은 변경 이후에 작성되는 데이터에 적용됩니다: 기존 파일은 작성된 순서를 유지하고,
컴팩터는 유사하게 클러스터링된 파일만 병합합니다. 클러스터링 필드는 암호화되지 않은
텍스트, `int64` 또는 `bool` 필드여야 하며, 두 필드는 서로 달라야 합니다.

### 암호화된 필드

Parquet에 작성되기 전에 암호화하려면 스트림을 만들 때 필드를 `encrypted`로 표시합니다. 저장된 열에는 암호문이 들어 있으며, 일반 쿼리는 암호문을 반환합니다. SQL에서 `decrypt(field)`로 값을 다시 읽습니다:

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

이 플래그는 나중에 변경할 수 없습니다. 기존 데이터를 읽을 수 없게 되기 때문입니다. 키는 조직 암호 키와 암호 루트 키 `MS_CIPHER_KEY`에서 가져옵니다. 루트 키를 잃으면 암호화된 필드를 복구할 수 없습니다. [보안 및 멀티테넌시](/ko/security#필드-수준-암호화)를 참조하십시오.

## 리텐션 및 삭제

리텐션은 컴팩터가 데이터를 제거하는 시점을 제어합니다. **리텐션** 탭에서
**데이터 보존 기간(일)**로 설정하거나, 비워 두면 플랫폼 기본값인 30일이 적용되며, 이 값은
`_sys` 조직의 [설정 → 데이터 보존 기간](/ko/settings/platform#데이터-보존)에서 지정합니다. 리텐션보다
오래된 데이터는 다음 정리 시 삭제되므로, 리텐션을 줄이면 그 시점에 이미 지난 데이터가 삭제되고, 삭제된 파일은 절대 돌아오지 않습니다. 리텐션 기간 내에 조회되지 않은
메트릭 스트림의 메트릭도 메트릭 목록에서
사라집니다.

메트릭 스트림의 **리텐션** 탭에서 **오래된 샘플 다운샘플링**은 스트림 내 모든 메트릭의 샘플 중
지정한 일수보다 오래된 샘플을 1분에서 1일까지의 시간 버킷으로 롤업합니다: 한 버킷에 있는 시계열의 샘플은
하나의 포인트가 되고, 값은 평균 내고 델타 카운트는 합산되며, 원본 샘플은 삭제됩니다.
장기 범위 쿼리는 이후 훨씬 적게 읽고, 오래된 데이터는 버킷 해상도만 유지합니다. 원본
샘플은 복구할 수 없습니다.

로그와 트레이스의 경우, 스트림 설정 **작은 파일을 일별로 병합**(기본적으로 켜짐)은 완료된 하루의 파일들을
해당 날짜가 끝난 한 시간 후에 하나로 병합합니다. 이때 파일들을 합친 크기가
컴팩터의 `[compactor].target_size`보다 크지 않아야 합니다. 그러면 여러 날에 걸친 쿼리가 훨씬 적은 파일을 엽니다. 리텐션은
이후 일 단위로 적용됩니다. 병합된 파일은 해당 날짜 전체가 만료되면 삭제됩니다. 시간별 파일을 유지하려면 스트림의 **설정** 탭에서 이 설정을
끕니다.

**스트림 삭제**는 스트림과 해당 구성을 삭제하며 되돌릴 수 없습니다. 이 작업은
대시보드, 저장된 뷰, 알림, 보고서, 파이프라인을 망가뜨릴 수 있으므로 먼저 **사용량** 탭을 확인하십시오.

## 검색 작업

검색 작업은 백그라운드에서 실행되며 작업이 만료될 때까지 결과를 보관하는 쿼리입니다.
작업은 세 곳에서 발생합니다:

- `Prefer: respond-async`로 전송한 쿼리 또는 결과가 대화형 요청에 담기에는 너무 클 것으로 예상되는
  쿼리입니다.
- 파이프라인의 백필입니다.
- Mole Agent가 제출한 쿼리입니다.

**스트림**의 헤더에서 **검색 작업**을 선택해 목록을 엽니다. 목록 상단의
뷰는 상태별로 필터링되며 각각 개수가 표시됩니다: **전체**, **대기 중**, **실행 중**, **완료**, **실패**,
**취소됨**. 작업이 대기 중이거나 실행 중이면 목록이 자동으로 새로 고쳐집니다.

각 행에는 작업 유형(**쿼리** 또는 **백필**), 쿼리문, 상태,
쿼리 범위, 제출 시각, 소요 시간, 결과 행 수, 시도 횟수, 만료가 표시됩니다. 작업
상태에 따라 하나의 동작만 사용할 수 있습니다:

| 상태 | 동작 |
|---|---|
| 대기 중 또는 실행 중 | **작업 취소** |
| 완료 | **결과 다운로드** |
| 실패 또는 취소됨 | **다시 시도** |

**삭제**는 상태에 관계없이 작업과 해당 결과를 제거합니다.

멤버는 자신이 제출한 작업을 보고 관리합니다. 관리자는
`org.running_queries.cancel` 권한으로 조직의 모든 작업을 보고 관리합니다. 작업 API는
[쿼리](/ko/query#시간-범위-및-비동기-작업)를 참조하십시오.

## 데이터 수집 사용량 및 예산

**스트림**의 헤더에서 **데이터 수집 사용량**을 선택하면 각 소스가 지난
24시간, 7일 또는 30일 동안 수집한 데이터 양을 볼 수 있습니다. 동일한 수치를 세 가지 방식으로 나누어
합계가 일치하도록 표시합니다:

| 보기 | 소스 |
|---|---|
| **인증 정보** | API 토큰, RUM 클라이언트 토큰, 커넥터 또는 로그인한 사용자입니다. **플랫폼 내부**는 플랫폼 자체의 텔레메트리입니다. |
| **스트림** | 이름과 유형으로 식별되는 하나의 스트림입니다. |
| **서비스** | 이벤트가 `service.name`에 지정한 서비스이며, 해당 필드가 없으면 `service` 또는 `service_name`을 사용합니다. **서비스 이름 없음**은 서비스를 지정하지 않은 이벤트를 모읍니다. |

데이터 수집 사용량은 수락된 요청의 압축 해제된 바이트를 집계합니다. 거부된 이벤트는 집계하지 않으며,
발신자가 다시 시도한 요청은 한 번만 집계합니다. 스팬은 도착하는 시점에, 테일 샘플링 전에 집계됩니다.
세션 리플레이는 **스트림** 보기의 `rum_replay` 행에 집계됩니다. 하나의 요청이 여러
서비스나 스트림을 포함하면 해당 바이트는 이벤트 수에 따라 분배되므로, 해당 보기는 정확한
수치가 아니라 근사치입니다.

알 수 없는 수치는 0이 아니라 `–`로 표시됩니다. `≥`로 표시된 수치는 하한값입니다. 이는 측정이
해당 기간 중간에 시작되었기 때문이며, 목록 위의 줄에 언제부터 집계되었는지 표시됩니다. 수치는 약
1분 이내에 페이지에 반영됩니다. 노드가 갑자기 중지되면 마지막 15초의 집계를 잃을 수 있습니다.

행을 선택하면 소스를 시간 단위로 보고, 다른 두 보기 기준으로 소스의 구성 요소를 확인할 수 있습니다.

### 예산 설정

행에서 **예산 설정**을 선택하거나, 여러 행을 선택한 뒤 모두에 하나의 예산을 설정합니다.

| 필드 | 의미 |
|---|---|
| **기간** | UTC 달력 기준 **매일** 또는 **매월**입니다. |
| **제한** | 1 MiB에서 1 PiB까지입니다. |
| **경고 임계값 (%)** | 제한의 이 비율에 도달하면 한 번, 모두 사용하면 한 번 더 알림을 보냅니다. `0`은 모두 사용했을 때만 알립니다. 기본값: 80. |
| **알림 대상** | 조직의 멤버입니다. 기본값: 예산을 설정하는 사람입니다. |

예산은 알림만 보냅니다. 소스가 예산을 초과해도 수집은 동일하게 응답하고 저장하며, 아무것도
버려지거나 느려지지 않습니다. 각 단계는 기간당 한 번씩 알립니다. 제한을 높이면 이후 임계값을
다시 통과할 때 다시 알림을 보냅니다.

알림은 기본 제공 알림 정책인 **데이터 수집 예산 거의 소진** 및 **데이터 수집
예산 초과**를 통해 전송되며, 상단 표시줄의 알림 센터에 표시됩니다. 알림을 받을 다른 대상과 방법을
변경하려면 [알림 채널](/ko/notification-channels)을 참조하십시오.

`_sys` 조직에는 알림 정책이 없으므로 예산도 없습니다. 다음 항목에는 예산을 설정할 수 없습니다:
**플랫폼 내부**, **서비스 이름 없음**, **기타 서비스**. 이들은 [플랫폼 설정](/ko/settings/platform#데이터-수집-사용량)의
제한을 초과한 서비스입니다.

## 권한

| 권한 | 기능 |
|---|---|
| `intake_usage.read` | **데이터 수집 사용량**을 열며, 토큰과 멤버의 이름을 표시합니다. 소유자와 관리자는 이 권한을 가집니다. |
| `intake_budgets.manage` | 예산을 설정하고 제거합니다. 소유자와 관리자는 이 권한을 가집니다. |
| `streams.read` | 스트림을 나열하고 메타데이터를 검사합니다. |
| `streams.query` | SQL로 스트림 데이터를 쿼리합니다. |
| `query.jobs.read`, `query.jobs.run` | **검색 작업**을 열고, 작업을 제출, 취소, 다시 시도, 삭제합니다. |
| `logs.write`, `metrics.write`, `traces.write`, `profiles.write` | 해당 시그널의 기존 스트림으로 데이터를 수집합니다. |
| `streams.create` | 스트림을 생성합니다. |
| `streams.configure` | 스키마 관련 설정과 리텐션을 변경합니다. |
| `streams.delete` | 스트림을 삭제합니다. |
