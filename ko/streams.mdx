스트림은 데이터 수집, 쿼리, 파이프라인, 리텐션에서 사용하는 조직 단위의 데이터 규약입니다.
**스트림**을 열어 수신 데이터를 확인하고 각 스트림을 살펴보거나 설정합니다.

## 스트림 유형

| 유형 | 주요 콘텐츠 |
|---|---|
| `logs` | 구조화된 이벤트와 애플리케이션 로그입니다. |
| `metrics` | Prometheus 서버 하나와 같은 단일 소스의 메트릭 샘플입니다. `metric_name`으로 메트릭을 구분합니다. |
| `traces` | OpenTelemetry 스팬입니다. |
| `profiles` | pprof 블롭에 연결된 프로파일 메타데이터입니다. |
| `extend` | 테이블 확장 기능으로 관리하며 처리 중에 사용하는 조회 데이터입니다. |

스트림 유형이 다르면 같은 스트림 이름을 사용할 수 있습니다. API 요청과 자동화에는
항상 `stream_type`을 포함합니다.

### 플랫폼 스트림

MoleSignal은 다음 스트림에 직접 데이터를 기록합니다.

| 스트림 | 콘텐츠 |
|---|---|
| `_molesignal` | `_sys` 조직에 있는 MoleSignal 자체의 텔레메트리입니다. [자체 관측성](/ko/self-observability)을 참조합니다. |
| `_synthetic_results` | 합성 검사 실행마다 기록하는 행 하나입니다. [합성 모니터링](/ko/synthetics#결과-스트림-및-보존)을 참조합니다. |
| `_audit` | 워크스페이스의 감사 이벤트입니다. [감사 스트림](/ko/settings/data-security#감사-스트림)을 참조합니다. |
| `_agent_model_traces` | Mole Agent의 모델 호출 기록입니다. [사용량 및 예산](/ko/agent#사용량-및-예산)을 참조합니다. |
| `_agent_score_traces` | Mole Agent 응답의 품질 점수입니다. [품질](/ko/quality#스트림에서-점수-조회하기)을 참조합니다. |

다른 스트림과 같은 방식으로 읽습니다. `_audit`에는 `audit.read` 권한이 필요합니다. 이 권한이 없으면 스트림이 목록과
런타임 통계에 표시되지 않으며, 열기, 변경 또는 삭제 요청에 `403`을 반환합니다. MoleSignal만 이 스트림에 데이터를 기록합니다. 위 이름으로 스트림을 생성할 수 없고, 데이터 수집 요청에는
`403`을 반환하며, [파이프라인](/ko/pipelines#플랫폼-스트림)에서도 이 스트림에 데이터를 기록할 수 없습니다.

## 스트림 목록

**스트림**에는 워크스페이스의 모든 스트림이 표시됩니다. 탭을 전환해 **전체** 스트림 또는 특정 유형만 표시하고,
이름이나 설명으로 검색하거나 런타임 상태로 필터링합니다. 상단에는 정상적으로 데이터를 수신하는 스트림과 확인이 필요한 스트림의 수를 표시합니다.
또한 해당 기간에 기록한 압축 데이터의 총량과
현재 저장 용량을 표시합니다.

| 열 | 표시 정보 |
|---|---|
| **상태** | **정상**, **지연**, **중단됨**, **트래픽 없음**, **미사용** 또는 **통계 확인 불가**입니다. 아래 표를 참조합니다. |
| **수신 속도**, **마지막 수신** | 데이터 수신 속도와 마지막으로 데이터를 수신한 시각입니다. |
| 압축 데이터 | 해당 기간에 기록한 압축 데이터의 바이트 수입니다. |
| **현재 저장 용량**, **리텐션** | 현재 저장된 바이트 수와 데이터를 보존하는 일수입니다. |
| **레코드**, **수집 크기**, **저장 크기**, **인덱스 크기** | 보존 중인 레코드 수, 변환 전에 수신한 바이트 수, 데이터 파일의 바이트 수, 인덱스의 바이트 수입니다. |

| 상태 | 의미 |
|---|---|
| **정상** | 최근 15분 이내에 데이터를 수신했습니다. |
| **지연** | 마지막 데이터 수신 시점이 15분 전과 2시간 전 사이입니다. |
| **중단됨** | 2시간 넘게 데이터를 수신하지 않았습니다. |
| **트래픽 없음** | Mole Agent 트레이스 스트림이 응답 사이에 데이터를 수신하지 않는 상태입니다. |
| **미사용** | 스트림에서 데이터를 한 번도 수신하지 않았습니다. |

**쿼리 불가**로 표시된 스트림은 계속 데이터를 수신하지만 쿼리의 스트림 선택 목록에는 표시되지 않습니다. 각 행에는
**쿼리** 또는 **탐색**이 있으며, **세부 정보 보기**와 **스트림 ID 복사**도 있습니다. 상단의 **검색 작업**을 선택하면
[검색 작업](#검색-작업)이 열립니다.

## 스트림 생성

MoleSignal은 데이터를 처음 기록할 때 스트림을 자동으로 생성하므로 대부분의 스트림은 자동으로 표시됩니다.
처음부터 리텐션, 암호화된 필드 또는 쿼리 액세스를 설정하려면 스트림을 미리 생성합니다.
**스트림 생성**을 선택합니다.

| 필드 | 규칙 |
|---|---|
| **스트림 이름** | `snake_case` 형식으로 최대 64자까지 입력합니다. |
| **설명** | 선택 사항입니다. 스트림을 통해 흐르는 데이터를 설명합니다. |
| **신호 유형** | **로그**, **메트릭** 또는 **트레이스**입니다. |
| **보존 기간(일)** | 데이터를 보존하는 기간입니다. |
| **인덱싱된 필드** | 전문 검색 인덱스를 생성할 필드를 쉼표로 구분해 입력합니다. |
| **암호화된 필드** | 저장 전에 암호화할 필드를 쉼표로 구분해 입력합니다. 나중에 변경할 수 없습니다. [암호화된 필드](#암호화된-필드)를 참조합니다. |
| **쿼리 허용** | 라우팅 파이프라인에만 데이터를 공급하는 소스 스트림에서는 이 옵션을 끕니다. |

## 스트림 세부 정보

스트림을 선택해 엽니다. **데이터 쿼리**를 선택하면 탐색 화면에서 스트림이 열립니다. 메뉴에는
**스트림 ID 복사**와 **스트림 삭제**가 있습니다. 탭 구성은 다음과 같습니다.

| 탭 | 콘텐츠 |
|---|---|
| **개요** | 런타임 상태, 최초 데이터 수신 시점, 쿼리 액세스, 최근 24시간 동안 기록한 행 수와 압축 데이터 크기의 추이를 표시합니다. 데이터가 없는 스트림에서는 **데이터 소스 설정**과 **테스트 데이터 전송**을 사용할 수 있습니다. |
| **필드 및 인덱스** | 각 필드의 유형, 인덱스 유형, 암호화 여부를 표시합니다. 인덱스나 마스킹을 변경하려면 필드를 편집합니다. [스키마 및 필드](#스키마-및-필드)를 참조합니다. |
| **리텐션** | 스트림의 리텐션을 표시합니다. 메트릭 스트림의 경우 다운샘플링도 표시합니다. [리텐션 및 삭제](#리텐션-및-삭제)를 참조합니다. |
| **사용량** | 이 스트림에 데이터를 기록하는 수집 엔드포인트, 파이프라인, 저장된 쿼리, 알림 규칙을 표시합니다. 스트림을 변경하거나 삭제하기 전에 확인합니다. |
| **설정** | **설명**, **쿼리 허용**, **최대 쿼리 범위(시간)**, **작은 파일을 일별로 병합**, **필드별 분할**을 설정합니다. 로그 스트림에서는 **필드별 클러스터링**도 설정합니다. |

각 탭에서 변경한 내용은 초안에 모입니다. **저장 및 적용**을 선택하면 변경 사항을 한 번에 적용하고,
**변경 사항 삭제**를 선택하면 변경 사항을 버립니다. 저장하기 전에 페이지에서 되돌릴 수 없는 변경 사항을 경고합니다.
리텐션을 줄이면 보존 기간이 지난 데이터가 삭제되고, 다운샘플링을 적용하면 원본 샘플이 삭제됩니다.

**최대 쿼리 범위**는 스트림에 대한 단일 SQL 또는 PromQL 쿼리가 조회할 수 있는 시간 범위를 제한합니다.
한도를 초과하는 쿼리를 거부하므로 실수로 "최근 90일"을 지정해도 대규모 스트림 전체를 스캔하지 않습니다.
비워 두거나 `0`을 입력하면 제한이 없습니다.

모든 데이터를 받아들이는 소스 스트림이 계속 데이터를 수신하되 쿼리의 스트림 선택 목록에는 표시되지 않아야 한다면
**쿼리 허용**을 끕니다. 라우팅 파이프라인은 계속 이 스트림을 읽을 수 있습니다. 일반 텔레메트리 쿼리 경로 대신
**테이블 확장**에서 `extend` 데이터를 관리합니다.

## 스키마 및 필드

필드에는 이름, 데이터 유형, `nullable` 플래그, 인덱스 유형, `encrypted` 플래그가 있습니다. 데이터 유형은 `bool`, `int64`, `float64`, `utf8`, `timestamp`, `json`입니다. 수신 데이터에 새 필드가 처음 나타나면 스키마에 추가합니다. 이후 해당 필드에 다른 유형의 값이 들어오면 `type mismatch on field` 오류로 거부합니다.

인덱스 유형에 따라 MoleSignal이 필드에 생성하는 보조 구조가 달라집니다.

| 인덱스 유형 | 효과 |
|---|---|
| `none` | 보조 인덱스를 생성하지 않습니다. 기본값입니다. |
| `exact` | 전체 값이 정확히 일치하는지 확인하는 역인덱스(텍스트가 아닌 필드에는 Parquet 블룸 필터)와 파일별 최솟값 및 최댓값을 저장합니다. `=`와 `IN`은 해당 값이 없는 파일을 열지 않고 건너뛰며, 일치하는 행이 적으면 해당 행이 있는 페이지만 읽습니다. 파일당 값이 최대 65,536개인 필드에 `LIKE` 또는 `ILIKE`를 사용하면 해당 텍스트를 포함하는 값이 없는 파일을 건너뜁니다. `trace_id`와 같은 식별자에 사용합니다. |
| `full_text` | 텍스트 검색을 위해 토큰화한 역인덱스입니다. 문자와 숫자가 연속된 구간은 단어로 처리하고, CJK 텍스트는 서로 겹치는 두 글자 바이그램으로 나눕니다. `MATCH`, `MATCH_TEXT`, `LIKE`, `ILIKE`의 리터럴을 기준으로 일치할 수 없는 파일을 건너뜁니다. 문장 부호와 CJK 텍스트가 포함된 리터럴도 지원합니다. `utf8` 필드에만 적용합니다. |
| `bloom` | Parquet 블룸 필터, 텍스트 및 `int64` 필드의 파일별 전체 값 필터, 파일별 최솟값과 최댓값을 저장합니다. `=`와 `IN`은 해당 값이 없다고 확정할 수 있는 파일을 열지 않고 건너뜁니다. 요청 ID처럼 값이 많고 동등 조건으로만 쿼리하는 필드에 사용합니다. |
| `skip` | 파일별 최솟값과 최댓값을 저장하며, 고유 값이 최대 32개인 파일은 모든 값도 저장합니다. 비교 조건, `IN`, `BETWEEN`, 접두사 `LIKE`는 이 정보를 사용해 일치할 수 없는 파일을 건너뜁니다. |
| `ngram` | 대소문자를 구분하지 않고 파일별 값의 트라이그램과 파일 내 1,024행 블록별 5바이트 조각을 저장합니다. `LIKE`, `ILIKE`, `MATCH`의 리터럴에 포함된 트라이그램이 파일에 없으면 해당 파일을 건너뛰고, 리터럴에 포함된 조각이 블록에 없으면 해당 블록을 건너뜁니다. 따라서 ID처럼 드문 문자열을 검색할 때는 해당 문자열이 있을 수 있는 소수의 블록만 읽습니다. 리터럴이 5바이트보다 짧으면 모든 블록을 읽습니다. `ngram` 필드가 있는 스트림은 파일을 1,024행 단위의 페이지로 작성합니다. 작은 페이지와 조각은 저장 공간을 추가로 사용합니다. 테스트에서 해당 필드가 각 행의 3분의 2를 차지할 때 저장 공간 사용량이 약 14% 늘었습니다. 긴 자유 형식 텍스트가 아니라 부분 문자열로 검색하는 URL, 경로, 호스트 이름에 사용합니다. `utf8` 필드에만 적용합니다. |
| `ip` | IPv4 주소를 IPv6 주소로 매핑하고 파일별 주소 범위를 저장합니다. `CIDR_MATCH(field, '10.0.0.0/8')`와 주소에 대한 `=` 조건은 이 범위를 사용해 일치할 수 없는 파일을 건너뜁니다. `utf8` 필드에만 적용합니다. |
| `key_value` | JSON 객체의 최상위 키와 해당 값을 저장합니다. `json_text(field, 'key') = 'value'`, `IN`, `IS NOT NULL`은 해당 키나 값이 없는 파일을 건너뛰며, 일치하는 행이 적으면 해당 행이 있는 페이지만 읽습니다. 값은 `json_text`의 반환값을 기준으로 비교합니다. 텍스트는 그대로, 숫자와 불리언은 JSON 표현으로 비교합니다. `json` 필드에만 적용합니다. |
| `range` | 각 행의 숫자 값과 파일별 최솟값 및 최댓값을 인덱스에 저장합니다. 조건이 `exact` 필드의 `=` 비교, `range` 필드와 숫자 간의 `>`, `>=`, `<`, `<=` 비교, 시간 범위로 구성된 `count(*)`는 파일을 읽지 않고 인덱스에서 결과를 계산합니다. 그 밖의 비교는 범위를 벗어난 파일을 건너뜁니다. `int64`, `float64`, `timestamp` 필드에만 적용합니다. |

인덱싱된 모든 필드는 파일마다 해당 필드에 값이 없는 행의 수도 기록합니다. `IS NULL`은 모든 행에 값이 있는 파일을 건너뜁니다. `IS NOT NULL`, `!= ''`처럼 값이 있는지 확인하는 조건을 비롯한 다른 모든 조건은 어느 행에도 값이 없는 파일을 건너뜁니다.

`OR`로 연결한 조건도 각 분기에 해당하는 인덱스에서 모든 분기가 일치할 수 없다고 판단하면 파일을 건너뜁니다. 예를 들어 `level = 'error' OR status >= 500`은 `level` 인덱스에 `error`가 없고 `status`가 모두 500 미만인 파일을 건너뜁니다.

수신 데이터에 처음 나타나는 필드의 인덱스 유형은 필드 이름에 따라 결정합니다.

| 스트림 유형 | 필드 | 인덱스 유형 |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`, `level`, `session_id`, `fingerprint`, `country`, `browser`, `application`, `environment` | `exact` |
| `traces` | `trace_id`, `span_id`, `parent_span_id`, `service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

스트림에 별도 규칙이 없으면 나머지 새 필드에는 모두 `none`을 적용합니다. [새 필드 인덱스](#새-필드-인덱스)를 참조합니다. `level`에 `exact`를 적용하면 로그 히스토그램에서 파일을 읽지 않고 인덱스로 오류 수를 집계할 수 있습니다. RUM 스트림은 `key_value`로 `context`, `feature_flags`, `usr.extra`의 키를 인덱싱합니다.

인덱스 유형을 변경하면 이후에 작성하는 데이터에 즉시 적용합니다. 이전에 작성한 데이터는 새 설정에 따라 백그라운드에서 다시 인덱싱합니다. 봉인된 각 파티션은 해당 파일로부터 인덱스를 다시 생성합니다. 기본적으로 파티션은 종료 후 48시간이 지나면 봉인합니다. 더 최근에 작성한 파일은 봉인하거나 병합할 때 다시 인덱싱합니다. 그전까지 파일은 작성 당시의 인덱스를 유지합니다. 이 차이는 쿼리 결과가 아니라 쿼리가 읽는 파일 수에만 영향을 줍니다. **개요**의 **인덱싱된 필드 비율**에서 다시 인덱싱할 파일이 얼마나 남았는지 확인할 수 있습니다. CJK 텍스트를 바이그램으로 나누기 시작한 경우처럼 전체 텍스트 인덱스 형식이 바뀌면 같은 방식으로 백그라운드에서 이전 파일의 인덱스를 새 형식으로 다시 생성합니다.

필드를 변경하려면 **필드 및 인덱스**를 열고 해당 필드의 편집 작업을 선택한 다음 다음 항목을 설정합니다.

- **인덱스 유형**: **인덱싱 안 함**, **전체 텍스트 검색**, **정확히 일치**, **블룸 필터**,
  **스킵 인덱스**, **N-gram 부분 문자열**, **IP 주소**, **JSON 키** 중에서 선택합니다. 전체 텍스트 검색, N-gram
  부분 문자열, IP 주소는 텍스트 필드에 적용하고, JSON 키는 JSON 필드에 적용합니다.
- **결과 필드 마스킹**의 **스트림 수준 정책**: **전역 규칙 상속**, **사용자 지정 스트림 규칙**,
  **이 스트림에서 마스킹 제외** 중에서 선택합니다. [필드 마스킹](/ko/settings/data-security#필드-마스킹)을 참조합니다.
  메트릭 스트림에는 마스킹을 적용하지 않습니다.

**초안에 적용**을 선택한 다음 **저장 및 적용**을 선택합니다. 필드의 데이터 유형은 변경할 수 없습니다.

### 새 필드 인덱스

**설정** 탭의 **필드 인덱스**에서는 스트림에 처음 나타나는 필드의 이름을 기준으로
규칙에 따라 인덱스를 지정합니다. **규칙 추가**를 선택하고 필드 이름 패턴을 입력한 다음 인덱스 유형을 선택합니다.
`*`는 임의의 문자열을, `?`는 문자 하나를 나타냅니다. 따라서 `*_id`는 `user_id`와
`order_id`에 일치하고, `http.*`는 `http` 아래의 모든 필드에 일치합니다. 필드 이름이 패턴과
일치하고 인덱스 유형이 필드의 데이터 유형에 맞는 첫 번째 규칙을 적용합니다.
다만 **필드 및 인덱스**에서 필드 이름으로 지정한 인덱스가 우선하며, 일치하는 규칙이 없으면 위의 기본값을 적용합니다.
규칙은 이후에 처음 나타나는 필드에만 적용합니다. 기존 필드는 **필드 및
인덱스**에서 변경합니다. 스트림당 최대 32개의 규칙을 설정할 수 있습니다.

### 필드별 분할

로그 또는 트레이스 스트림은 텍스트 필드 한두 개로 분할할 수 있습니다.
**설정** 탭의 **필드별 분할**에서 **필드 추가**를 선택한 다음 필드와 분할 방식을 선택합니다. 이후에
작성하는 데이터는 필드 값에 따라 샤드로 나누고 각 샤드를 별도의 파일에 작성합니다.

- **해시**는 값의 해시를 기준으로 데이터를 2~64개의 샤드에 고르게 분산합니다. 필드에 동등 조건
  (`=` 또는 `IN`)을 지정한 쿼리는 해당 값이 속한 샤드의 파일만 읽습니다.
- **첫 문자**는 값의 첫 문자를 기준으로 37개의 샤드에 분산합니다. 숫자와 영문자마다 샤드를
  하나씩 할당하고(대소문자 구분 없음), 빈 값을 포함한 나머지 값에 샤드 하나를 할당합니다. 필드에
  동등 조건을 지정하거나 텍스트로 시작하는 `LIKE`(예: `'web-%'`)를 사용한 쿼리는
  해당 문자의 샤드에 속한 파일만 읽습니다. `ILIKE`는 나머지 값의 샤드도 읽습니다. 샤드 간 데이터가 얼마나 고르게
  분포하는지는 데이터에 따라 달라집니다. 예를 들어 16진수 트레이스 ID는 16개의 샤드만 사용합니다.

필드를 두 개 사용하면 두 필드의 샤드 조합에 따라 파일을 분할하므로 샤드 수는 각 필드의 샤드 수를 곱한 값입니다. **필드별
분할**에는 전체 샤드 수가 표시되며, 최대 256개입니다. 첫 문자(37개 샤드)는 최대 4개
샤드의 해시와 조합할 수 있습니다. 한 필드에만 조건을 지정해도 쿼리가 읽는 파일 수가 줄고, 두 필드 모두에 조건을 지정하면
파일 수가 더 줄어듭니다. 서비스, 네임스페이스, 테넌트처럼 거의 모든 쿼리에서 사용하는 필드를 분할 필드로 선택합니다.
샤드가 많을수록 파일 수가 늘고 각 파일의 크기는 작아집니다.

이 설정은 변경 후에 작성하는 데이터에만 적용합니다. 기존 파일은 그대로 유지합니다. 쿼리는
각 파일을 작성할 때 사용한 분할 필드를 기준으로 해당 파일을 읽을지 판단하며, 컴팩터는
분할 필드가 같은 파일만 병합합니다. 분할 필드는 암호화하지 않은 텍스트 필드여야 하며, 두 필드는 서로 달라야 합니다.

### 필드별 클러스터링

로그 스트림은 필드 한두 개를 기준으로 파일 내 행을 클러스터링할 수 있습니다.
**설정** 탭의 **필드별 클러스터링**에서 **필드 추가**를 선택한 다음 필드와 **시간 구간**을 선택합니다. 이후에
작성하는 각 파일에서는 행을 지정된 길이의 시간 구간으로 나누고 최신 구간부터 배치합니다. 각 구간 안에서는
필드 값으로 먼저 정렬한 다음 최신 행부터 배치합니다.

시간순으로만 정렬하면 특정 서비스와 같은 값이 파일의 모든 페이지에 나타납니다. 클러스터링하면 각 시간 구간에서
해당 값이 소수의 페이지에 모이므로, 클러스터링 필드에 동등 조건(`=` 또는 `IN`)을 지정한 쿼리는
해당 페이지만 읽습니다. 서비스나 로그 레벨처럼 쿼리에서 자주 사용하고 고유 값이 적은
필드를 사용합니다.

클러스터링된 각 파일은 분 단위로 클러스터링 필드의 값 조합에 해당하는
행 수도 저장합니다. 텍스트 클러스터링 필드에 동등 조건을 지정한 집계, 해당 필드 중 하나로
그룹화한 집계(`GROUP BY service`), 막대가 온전한 분 단위로 구성된 히스토그램은
파일을 읽지 않고 이 집계 값으로 결과를 계산합니다. 쿼리 시간 범위가 파일 내부의 분 경계에서 시작하거나 끝나는 경우에도
같이 처리합니다. 분과 필드 값의 조합이 65,536개를 초과하는 파일은 집계 값을 저장하지 않습니다.
이 집계 값으로 최신 또는 가장 오래된 행이 담긴 페이지가 어느 분에 해당하는지도 파악할 수 있습니다. 따라서 클러스터링 필드에
동등 조건을 지정했는지와 관계없이 이러한 페이지를 조회할 때는 해당 분의 데이터만 읽습니다.

시간 구간은 1분, 5분 또는 10분이며 기본값은 1분입니다. 구간이 길수록 더 많은 페이지를 건너뛸 수 있지만,
짧은 시간 범위를 쿼리하더라도 범위와 겹치는 구간은 전체를 읽습니다.

클러스터링은 [필드별 분할](#필드별-분할)과 다릅니다. 분할은 샤드마다 별도의
파일을 작성하므로 쿼리가 읽는 파일 수는 줄지만 스트림에 더 작고 많은 파일이 생깁니다. 클러스터링은 파일 구성을 유지하고
파일 안의 행을 정렬합니다. 두 방식을 함께 사용할 수 있습니다.

이 설정은 변경 후에 작성하는 데이터에만 적용합니다. 기존 파일은 작성 당시의 순서를
유지하며, 컴팩터는 클러스터링 방식이 같은 파일만 병합합니다. 클러스터링 필드는
암호화하지 않은 텍스트, `int64`, `bool` 필드여야 하며, 두 필드는 서로 달라야 합니다.

### 암호화된 필드

스트림을 생성할 때 필드에 `encrypted`를 설정하면 Parquet에 쓰기 전에 해당 필드를 암호화합니다. 저장된 열에는 암호문이 들어 있으며, 일반 쿼리는 암호문을 반환합니다. 원래 값을 읽으려면 SQL에서 `decrypt(field)`를 사용합니다.

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

나중에 이 플래그를 변경하면 기존 데이터를 읽을 수 없으므로 변경을 허용하지 않습니다. 암호화 키는 조직 암호화 키와 루트 암호화 키 `MS_CIPHER_KEY`에서 파생합니다. 루트 키를 잃으면 암호화된 필드를 복구할 수 없습니다. [보안 및 멀티테넌시](/ko/security#필드-수준-암호화)를 참조합니다.

## 리텐션 및 삭제

리텐션은 컴팩터가 데이터를 삭제하는 시점을 제어합니다. **리텐션** 탭에서
**데이터 보존 기간(일)**을 설정합니다. 비워 두면 플랫폼 기본값인 30일을 사용합니다. 이 기본값은
`_sys` 조직의 [설정 → 데이터 보존](/ko/settings/platform#데이터-보존)에서 설정합니다. 보존 기간이
지난 데이터는 다음 정리 작업에서 삭제합니다. 보존 기간을 줄이면 새 보존 기간을 초과한 데이터를
삭제하며, 삭제한 파일은 복구할 수 없습니다. 메트릭 스트림에서 보존 기간 내에 관측되지 않은 메트릭도
메트릭 목록에서 제거합니다.

메트릭 스트림의 **리텐션** 탭에서 **오래된 샘플 다운샘플링**을 설정하면 스트림 내 각
메트릭에서 지정한 일수보다 오래된 샘플을 1분에서 1일까지의 시간 버킷으로 집계합니다. 같은 버킷에 속한 한 시계열의 샘플은
하나의 데이터 포인트로 합칩니다. 값은 평균을 내고 델타 카운트는 합산한 뒤 원본 샘플을 삭제합니다.
이후 긴 기간을 조회하는 쿼리는 훨씬 적은 데이터를 읽으며, 오래된 데이터는 버킷 단위의 해상도만 유지합니다.
원본 샘플은 복구할 수 없습니다.

로그 및 트레이스 스트림에서는 **작은 파일을 일별로 병합** 설정(기본값: 켜짐)이 하루가
끝난 지 1시간 후에 해당 일자의 파일을 하나로 합칩니다. 파일 크기의 합이 컴팩터의
`[compactor].target_size` 이하여야 합니다. 이렇게 하면 여러 날을 조회하는 쿼리가 훨씬 적은 파일을 엽니다. 리텐션은
일 단위로 적용하며, 해당 일자 전체가 보존 기간을 벗어나면 병합한 파일을 삭제합니다. 시간별 파일을 유지하려면
스트림의 **설정** 탭에서 이 설정을 끕니다.

**스트림 삭제**는 스트림과 구성을 삭제합니다. 이 작업은 되돌릴 수 없습니다.
대시보드, 저장된 뷰, 알림, 보고서, 파이프라인이 작동하지 않을 수 있으므로 먼저 **사용량** 탭을 확인합니다.

## 검색 작업

검색 작업은 백그라운드에서 실행하는 쿼리입니다. 작업이 만료될 때까지 결과를 보관합니다.
검색 작업은 다음 세 가지 경우에 생성됩니다.

- `Prefer: respond-async`를 지정해 전송한 쿼리 또는 결과가 대화형 요청에서 처리하기에
  너무 클 것으로 예상되는 쿼리
- 파이프라인 백필
- Mole Agent가 제출한 쿼리

**스트림** 헤더에서 **검색 작업**을 선택하여 목록을 엽니다. 목록 상단의
뷰에서는 상태별로 작업을 필터링하고 각 상태의 작업 수를 표시합니다. 상태는 **전체**, **대기 중**, **실행 중**, **완료**, **실패**,
**취소됨**입니다. 대기 중이거나 실행 중인 작업이 있으면 목록을 자동으로 새로 고칩니다.

각 행에는 작업 유형(**쿼리** 또는 **백필**), 쿼리문, 상태,
조회 범위, 제출 시각, 소요 시간, 결과 행 수, 시도 횟수, 만료 시각이 표시됩니다.
작업 상태에 따라 다음 작업을 수행할 수 있습니다.

| 상태 | 작업 |
|---|---|
| 대기 중 또는 실행 중 | **작업 취소** |
| 완료 | **결과 다운로드** |
| 실패 또는 취소됨 | **다시 시도** |

**삭제**는 상태와 관계없이 작업과 결과를 삭제합니다.

구성원은 직접 제출한 작업을 조회하고 관리할 수 있습니다.
`org.running_queries.cancel` 권한이 있는 관리자는 조직의 모든 작업을 조회하고 관리할 수 있습니다.
작업 API는 [쿼리](/ko/query#시간-범위-및-비동기-작업)를 참고합니다.

## 데이터 수집 사용량 및 예산

**스트림** 헤더에서 **데이터 수집 사용량**을 선택하면 소스별로 지난
24시간, 7일 또는 30일 동안 수집한 데이터의 양을 확인할 수 있습니다. 같은 사용량을 세 가지 기준으로 나누어 표시하므로
각 뷰의 합계는 같습니다.

| 뷰 | 소스 기준 |
|---|---|
| **인증 정보** | API 토큰, RUM 클라이언트 토큰, 커넥터 또는 로그인한 사용자입니다. **플랫폼 내부**는 플랫폼 자체의 텔레메트리입니다. |
| **스트림** | 이름과 유형으로 구분한 개별 스트림입니다. |
| **서비스** | 이벤트의 `service.name`에 지정된 서비스입니다. 이 필드가 없으면 `service` 또는 `service_name`을 사용합니다. **서비스 이름 없음**에는 서비스 이름을 지정하지 않은 이벤트가 포함됩니다. |

수집 사용량은 수락한 데이터의 압축 해제 후 요청 바이트를 집계합니다. 거부한 이벤트는 집계하지 않으며,
송신 측에서 재시도한 요청은 한 번만 집계합니다. 스팬은 도착 시점에 테일 샘플링을 적용하기 전에 집계합니다.
세션 리플레이는 **스트림** 뷰의 `rum_replay` 행에 집계합니다. 하나의 요청에 여러
서비스 또는 스트림의 데이터가 포함되면 이벤트 수에 비례해 바이트를 배분합니다. 따라서 해당 뷰의 수치는
정확한 값이 아닌 근삿값입니다.

알 수 없는 값은 0이 아니라 `–`로 표시합니다. `≥`가 붙은 값은
조회 기간 도중에 측정을 시작했으므로 하한값입니다. 목록 위에 측정 시작 시점을 표시합니다. 집계 수치는 약 1분 이내에
페이지에 표시됩니다. 노드가 갑자기 중지되면 마지막 15초 동안의 집계 데이터가 손실될 수 있습니다.

행을 선택하면 해당 소스의 시간별 사용량과 나머지 두 뷰의 기준에 따른 세부 내역을 확인할 수 있습니다.

### 예산 설정

한 행에서 **예산 설정**을 선택하거나, 여러 행을 선택한 후 모두에 동일한 예산을 설정합니다.

| 필드 | 의미 |
|---|---|
| **기간** | UTC 달력 기준으로 **매일** 또는 **매월**을 선택합니다. |
| **제한** | 1 MiB에서 1 PiB까지 설정할 수 있습니다. |
| **경고 임계값 (%)** | 사용량이 제한의 지정 비율에 도달하면 한 번 알리고, 제한에 도달하면 다시 알립니다. `0`으로 설정하면 제한에 도달할 때만 알립니다. 기본값: 80. |
| **알림 대상** | 조직 구성원 중에서 선택합니다. 기본값: 예산을 설정한 구성원. |

예산은 알림에만 사용합니다. 소스가 예산을 초과해도 수집 요청에 대한 응답과 데이터 저장 방식은 바뀌지 않으며,
데이터를 버리거나 수집 속도를 늦추지 않습니다. 기간마다 각 임계값에 대해 한 번만 알립니다. 제한을 높인 뒤
사용량이 새 임계값에 도달하면 다시 알립니다.

기본 알림 정책인 **데이터 수집 예산 소진 임박**과 **데이터 수집
예산 초과**를 통해 알림을 보내며, 상단 바의 알림 센터에 표시합니다.
추가 알림 대상과 알림 전달 방식을 변경하려면 [알림 채널](/ko/notification-channels)을 참고합니다.

`_sys` 조직에는 알림 정책이 없으므로 예산을 설정할 수 없습니다.
**플랫폼 내부**, **서비스 이름 없음**, **기타 서비스**에도 예산을 설정할 수 없습니다. **기타 서비스**에는
[플랫폼 설정](/ko/settings/platform#데이터-수집-사용량)의 표시 한도를 벗어난 서비스가 포함됩니다.

## 권한

| 권한 | 기능 |
|---|---|
| `intake_usage.read` | 토큰과 구성원의 이름이 표시되는 **데이터 수집 사용량**을 엽니다. 소유자와 관리자에게 이 권한이 있습니다. |
| `intake_budgets.manage` | 예산을 설정하고 제거합니다. 소유자와 관리자에게 이 권한이 있습니다. |
| `streams.read` | 스트림 목록과 메타데이터를 확인합니다. |
| `streams.query` | SQL로 스트림 데이터를 쿼리합니다. |
| `query.jobs.read`, `query.jobs.run` | **검색 작업**을 열고 작업을 제출, 취소, 재시도, 삭제합니다. |
| `logs.write`, `metrics.write`, `traces.write`, `profiles.write` | 해당 신호 유형의 기존 스트림으로 데이터를 수집합니다. |
| `streams.create` | 스트림을 생성합니다. |
| `streams.configure` | 스키마 관련 설정과 리텐션을 변경합니다. |
| `streams.delete` | 스트림을 삭제합니다. |
