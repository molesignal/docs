**인프라**는 서비스가 실행되는 위치를 나열하고, 각 위치를 이름으로 지정하는 서비스, 로그,
메트릭과 연결합니다. 문제가 있는 노드는 해당 노드의 파드에서 실행되는 모든 서비스로 이어지며, 느린 서비스
인스턴스는 해당 인스턴스가 실행되는 파드와 노드로 이어집니다.

## 엔티티의 출처
이 페이지에서는 아무것도 구성하지 않습니다. 플랫폼은 5분마다 지난
15분 동안의 두 소스를 읽습니다:

- APM이 스팬에서 확인하는 인스턴스와 각 인스턴스에서 실행된 서비스입니다.
- `host.name`, `k8s.node.name` 또는 `k8s.pod.name` 필드가 있는 최대 4개의 메트릭 또는 로그
  스트림이며, 최대 2,000개의 서로 다른 위치에서 리소스 필드를 읽습니다.

필드는 OpenTelemetry 시맨틱 규칙을 따릅니다:

| 종류 | 이름 지정 기준 | 키 |
|---|---|---|
| 클러스터 | `k8s.cluster.name` | 클러스터 이름입니다. |
| 노드 | `k8s.node.name` | `cluster/node`. |
| 파드 | `k8s.pod.name`, `k8s.namespace.name` 함께 사용 | `cluster/namespace/pod`. |
| 호스트 | `host.name`, Kubernetes 외부에서만 | 호스트 이름입니다. |
| 컨테이너 | `container.id`, `container.name` 함께 사용 | 컨테이너 ID입니다. |

파드 내부에서 `host.name`은 보통 파드의 이름을 지정하므로, 파드, 노드 또는 클러스터의 이름을 지정하는 데이터는
호스트를 만들지 않습니다. 서비스는 해당 스팬이 이름을 지정하는 가장 안쪽 위치에서 실행됩니다. 즉, 파드, 없으면 호스트, 없으면 노드입니다.
파드는 해당 노드에서 실행되고, 노드는 해당 클러스터의 일부이며, 컨테이너는 해당 파드의 일부입니다.

Kubernetes 필드를 채우려면 OpenTelemetry Collector에 `k8sattributes` 프로세서를 추가하고
`resource` 프로세서로 `k8s.cluster.name`을 설정합니다. **데이터 소스** 페이지의 Kubernetes 가이드에
두 방법이 모두 포함되어 있습니다. 일주일 동안 확인되지 않은 엔티티는 제거됩니다.

## 목록
목록에는 지난 일주일 동안 확인된 모든 엔티티가 최근에 확인된 순서대로 표시됩니다. 녹색 점은 지난
30분 이내에 확인되어 현재 실행 중인 엔티티를 나타내고, 회색 점은 이전에만 확인된 엔티티를 나타냅니다.
**서비스**는 해당 엔티티에서 직접 실행되는 서비스 수를 표시합니다. 종류별로 목록을 좁히거나
이름 또는 키로 검색할 수 있으며, 두 조건 모두 주소에 유지됩니다.

## 엔티티 페이지
엔티티를 열면 다음을 확인할 수 있습니다:

- **실행 환경**: 해당 노드와 클러스터, 또는 컨테이너가 속한 파드입니다.
- **여기에서 실행되는 항목**: 클러스터의 노드, 노드의 파드, 파드의 컨테이너입니다.
- **서비스**: 해당 엔티티에서 실행되는 서비스와 해당 엔티티에서 실행되는 항목의 서비스이며, 각 서비스는 해당 APM 페이지로 연결됩니다.
- **서비스 변경 사항**: 지난 24시간 동안
  해당 서비스의 최신 배포 및 기타 변경 사항입니다. [변경 사항](/ko/api/changes)을 참조하세요.
- **리소스 속성**: 마지막으로 확인될 당시의 필드이며, 각 필드는 복사할 수 있습니다.

**로그**는 지난 한 시간 동안 파드 또는 호스트의 로그를 엽니다. **메트릭**은
`k8s.cluster.name`, `k8s.node.name`, `k8s.pod.name`, `host.name` 또는 `container.id`를 기준으로 해당 이름을 포함하는 메트릭을 엽니다.

[APM](/ko/apm) 페이지의 서비스 **인스턴스** 테이블에서 **워크로드 / 호스트** 셀을 선택하면 인스턴스가 실행되는
파드 또는 호스트가 열립니다.

## 권한
페이지와 API에는 `apm.services.read`, `metrics.read`, `logs.read` 또는 시스템
범위의 `sys.telemetry.read` 중 하나가 필요합니다. Mole Agent는 `list_entities`와 `get_entity`로 동일한 데이터를 읽습니다.
