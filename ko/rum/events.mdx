모든 RUM SDK는 동일한 JSON 이벤트를 하나의 엔드포인트로 전송합니다. 아직 SDK를 지원하지 않는 네이티브
앱처럼 SDK가 없는 클라이언트는 HTTP 요청으로 동일한 이벤트를 전송합니다.

이벤트에는 `type`, `date`, 이벤트가 속한 `session`과 `view`, 그리고
유형과 이름이 같고 세부 정보를 담는 객체가 있습니다. 이벤트의 JSON Schema는 소스 코드에
`contracts/rum/events/v1.schema.json`으로 포함되며, 유효한 이벤트 예시와 유효하지 않은 이벤트 예시도 함께 제공됩니다.

## 이벤트 전송

```http
POST /api/v1/rum/events
Authorization: Bearer mspat-<36>
Content-Type: application/json
```

| 항목 | 규칙 |
|---|---|
| 인증 정보 | 애플리케이션의 [클라이언트 토큰](/ko/rum/applications#클라이언트-토큰)입니다. 이 토큰은 해당 애플리케이션에 대해서만 `rum.write` 권한을 갖습니다. `rum.write` 권한이 있는 다른 인증 정보를 사용하려면 모든 이벤트의 `application.id`에 애플리케이션을 지정해야 합니다. |
| 본문 | 이벤트의 JSON 배열입니다. 단일 이벤트 객체나 NDJSON(`Content-Type: application/x-ndjson`, 줄당 이벤트 하나)도 지원합니다. |
| 압축 | `Content-Encoding: gzip`은 선택 사항입니다. 다른 인코딩은 지원하지 않습니다. |
| 크기 | 최대 5000개의 이벤트를 전송할 수 있으며, 압축 해제 후 크기는 최대 5 MiB입니다. 한도를 초과하면 `413`을 반환합니다. |

<RequestExample>
```bash cURL
curl -X POST "http://localhost:5080/api/v1/rum/events" \
  -H "authorization: Bearer $RUM_CLIENT_TOKEN" \
  -H "content-type: application/json" \
  -d '[{
    "type": "error",
    "date": 1790000000000,
    "source": "browser",
    "service": "web-frontend",
    "env": "production",
    "version": "1.4.0",
    "session": { "id": "6f1c2b7e-1d5a-4c6b-9a3e-0a1b2c3d4e5f", "type": "user" },
    "view": { "id": "a91e0d52-7b8c-4f10-8d63-5e2f7c9a1b34", "url": "https://shop.example.com/checkout" },
    "error": {
      "id": "e7b1c9a2-3d4f-4b65-8a90-1c2d3e4f5a61",
      "message": "Payment provider timeout",
      "source": "custom",
      "handling": "handled"
    }
  }]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "accepted": 1,
  "rejected": []
}
```
</ResponseExample>

## 응답

응답은 이벤트별 처리 결과를 보고합니다. 이벤트 하나에 문제가 있어도 요청의 나머지 이벤트는 폐기하지 않습니다.

| 필드 | 의미 |
|---|---|
| `accepted` | 수락한 이벤트 수입니다. 거부하지 않았고 `sampled`에도 집계하지 않은 이벤트를 셉니다. [실시간 파이프라인](/ko/pipelines#rum-스트림)이 의도적으로 제외한 이벤트도 저장하지는 않지만 여기에 집계합니다. |
| `rejected` | 거부한 이벤트마다 항목 하나를 반환합니다. 각 항목에는 요청 내 위치(`index`, `0`부터 시작)와 `reason`이 포함됩니다. |
| `sampled` | 애플리케이션이 [세션의 일부만 보존](/ko/rum/sampling#서버에서-세션의-일부-보관)하기 때문에, 보존하지 않는 세션에 속해 의도적으로 제외한 이벤트 수입니다. 애플리케이션이 모든 오류를 보존하면 해당 세션의 오류는 이 수에 포함하지 않습니다. 제외한 이벤트가 있을 때만 이 필드를 반환합니다. 이러한 이벤트는 거부하지 않으며 `accepted`에도 집계하지 않습니다. |

모든 이벤트가 유효하지 않아도 `accepted`를 `0`으로 설정하고 `200`을 반환합니다. 요청을
아예 읽을 수 없으면 전체 요청이 실패합니다. 본문이 JSON이 아니거나, 지원하지 않는
`Content-Encoding`을 사용하거나, gzip 스트림을 디코딩할 수 없으면 `400`을 반환합니다. 토큰이 없거나,
폐기되었거나, `rum.write` 권한이 없으면 `401` 또는 `403`을 반환합니다. 위 한도를 초과하면 `413`을 반환합니다.

다음 사유 중 하나에 해당하면 이벤트를 거부합니다.

| 사유 | 원인 |
|---|---|
| 필드 이름이 포함된 메시지 | 이벤트가 스키마와 일치하지 않습니다. 필수 필드가 누락되었거나, 값의 타입이 잘못되었거나 허용 목록에 없거나, 숫자가 음수입니다. |
| `date is more than a day in the future` | 디바이스의 시계가 실제 시간보다 크게 앞서 있습니다. |
| `application.id is not the application of the client token` | 이벤트가 토큰에 연결된 애플리케이션과 다른 애플리케이션을 지정합니다. |
| ``application `<id>` does not exist`` | 애플리케이션이 삭제되었거나 처음부터 생성되지 않았습니다. |
| `application.id is required` | 인증 정보가 클라이언트 토큰이 아닌데 이벤트에 애플리케이션을 지정하지 않았습니다. |
| `line is not JSON` | NDJSON 본문의 한 줄을 파싱할 수 없습니다. |
| ``<stream>: realtime transform `<step>` …`` | 스트림의 [실시간 파이프라인](/ko/pipelines#rum-스트림) 단계에서 이벤트를 처리하지 못했거나, 해당 단계가 파이프라인이 유지하는 열을 변경했거나, 뷰 또는 바이탈을 제외했습니다. |

SDK는 거부된 이벤트를 오류 콜백으로 보고하고 다시 전송하지 않습니다.

## 규칙

- `date`는 이벤트 시작 시각을 Unix 에포크 기준 밀리초로 나타냅니다. `view`의 `date`는 뷰의 시작 시각이며
  리비전이 바뀌어도 변경되지 않습니다.
- 모든 소요 시간과 뷰 시작 시점을 기준으로 한 상대 시간(예: `performance.lcp.timestamp`,
  `resource.dns.start`)은 **정수로 표현한 나노초**입니다. 전송하기 전에 반올림합니다.
- 뷰의 내용이 바뀔 때마다 `view.revision`을 높이고 그 시점까지의 집계값과 함께 뷰를 다시 전송합니다.
  MoleSignal은 가장 높은 리비전을 보존합니다. 집계값은 증가분이 아닌 누적값입니다.
- 클라이언트는 세션 이벤트를 전송하지 않습니다. MoleSignal은 뷰를 바탕으로 세션의 시작과 종료 시각,
  소요 시간, 집계값, 랜딩 페이지와 이탈 페이지, 리플레이 기록 여부를 파악합니다.
- `session.start`는 Unix 에포크 기준 밀리초입니다. 필수는 아니지만 제공을 권장합니다. 세션 정보가 아직 없는 노드는
  이 값을 사용해 방금 시작된 세션과 이전에 추적이 끊긴 세션을 구분합니다.
- `application.id`는 선택 사항입니다. 클라이언트 토큰에 연결된 애플리케이션을 사용하며, 다른 값을
  지정하면 이벤트를 거부합니다.
- MoleSignal은 `geo`와 `network`를 직접 기록하므로 클라이언트가 보내는 값은 무시합니다. `retention`도 마찬가지입니다. `retention.rate`는 해당 유형의
  행을 보존한 비율(%)이고, `retention.filter`는 행을 보존한 기준([필터](/ko/rum/sampling#필터)의 ID,
  `default`, 또는 보존하지 않은 세션의 오류인 경우 `errors`)입니다. 이 값을 사용해 총계를 계산합니다.
- 스키마에 정의하지 않은 필드는 수락하고 보존합니다. 스키마에 정의된 필드의 타입이나
  값이 잘못되면 이벤트를 거부합니다.
- `error.frames`에는 소스 맵, 매핑 파일, 네이티브 심볼 파일을 적용하는 구조화된 스택이
  들어 있습니다. `error.stack`에는 표시와 검색에 사용하는 동일한 스택이 텍스트로 들어 있습니다.

## 모든 이벤트의 속성

| 속성 | 타입 | 참고 |
|---|---|---|
| `type` | 문자열 | 필수입니다. `view`, `action`, `error`, `resource`, `long_task`, `vital`, `log` 중 하나입니다. |
| `date` | 정수 | 필수입니다. Unix 에포크 기준 밀리초입니다. |
| `source` | 문자열 | 필수입니다. `browser`, `android`, `ios`, `flutter`, `react-native`, `kotlin-multiplatform`, `unity`, `roku`, `electron`, `other` 중 하나입니다. |
| `session` | 객체 | 필수입니다. `id`는 필수입니다. `type`은 `user`(기본값), `synthetics`, `ci_test` 중 하나입니다. `start`는 Unix 에포크 기준 밀리초입니다. `has_replay`는 불리언입니다. |
| `view` | 객체 | 필수입니다. `id`는 필수입니다. `url`, `name`, `referrer`, `in_foreground`는 선택 사항입니다. |
| `application.id` | 문자열 | 선택 사항입니다. 위의 규칙을 참조합니다. |
| `service`, `env`, `version` | 문자열 | 릴리스 차원입니다. `version`은 소스 맵과 심볼을 조회하는 키입니다. |
| `build_version`, `build_id` | 문자열 | 빌드 번호와 디버그 아티팩트를 업로드할 때 사용한 빌드 식별자입니다. |
| `action.id` | 문자열 | 이 이벤트를 시작한 액션이 있는 경우 해당 액션의 ID입니다. |
| `usr` | 객체 | `id`, `name`, `email`, `anonymous_id`를 포함합니다. 나머지 키는 `usr.extra`에 보존합니다. |
| `account` | 객체 | `id`와 `name`을 포함합니다. |
| `tab.id` | 문자열 | 브라우저 탭의 ID입니다. |
| `connectivity` | 객체 | `status`, `interfaces`, `effective_type`, `cellular`(`technology`, `carrier_name`)를 포함합니다. |
| `display.viewport` | 객체 | `width`와 `height`를 포함합니다. |
| `browser`, `os`, `device` | 객체 | 브라우저 이름과 버전, 운영 체제, 디바이스 유형(`mobile`, `desktop`, `tablet`, `tv`, `gaming_console`, `bot`, `other` 중 하나), 모델, 브랜드, 아키텍처, 로캘, 시간대, 배터리, 메모리를 포함합니다. |
| `sdk` | 객체 | `name`, `version`, `session_sample_rate`, `replay_sample_rate`를 포함합니다. |
| `context` | 객체 | 애플리케이션에서 자유롭게 정의하는 속성입니다. |
| `feature_flags` | 객체 | 자유 형식의 기능 플래그 평가 결과입니다. 각 키를 `feature_flags.<key>`로 조회할 수 있습니다. [기능 플래그](/ko/rum/feature-flags)를 참조합니다. |
| `synthetics` | 객체 | 신세틱 검사에서 실행한 세션의 정보로, `test_id`, `result_id`, `location_id`를 포함합니다. [테스트 트래픽](/ko/rum/test-traffic)을 참조합니다. |
| `ci_test` | 객체 | CI 테스트에서 실행한 세션의 `test_execution_id`를 포함합니다. |

식별자에는 `A-Z`, `a-z`, `0-9`, `.`, `_`, `:`, `-`를 사용할 수 있으며 최대 길이는 128자입니다.
`usr`, `account`, 디바이스의 텍스트 속성은 최대 256자입니다.

## 뷰

`view` 이벤트의 `view` 객체는 위에 나열한 `url`, `name`, `id`와 함께 다음 필드를 포함합니다.

| 필드 | 설명 |
|---|---|
| `revision` | 필수입니다. `1`부터 시작하며 뷰를 다시 전송할 때마다 1씩 증가합니다. |
| `time_spent` | 필수입니다. 뷰가 열린 상태로 유지된 시간을 나노초 단위로 나타냅니다. |
| `url` | 필수입니다. |
| `is_active` | 종료된 뷰의 마지막 리비전에서는 `false`입니다. |
| `loading_type` | `initial_load`, `route_change`, `bf_cache`, `activity_display`, `activity_redisplay`, `fragment_display`, `fragment_redisplay`, `view_controller_display`, `view_controller_redisplay`, `session_renewal` 중 하나입니다. |
| `loading_time`, `first_byte`, `dom_interactive`, `dom_content_loaded`, `dom_complete`, `load_event`, `network_settled_time`, `interaction_to_next_view_time` | 나노초 단위의 탐색 타이밍입니다. |
| `performance.fcp`, `performance.lcp`, `performance.fid`, `performance.inp`, `performance.cls`, `performance.fbc` | Web Vitals 지표입니다. LCP에는 `timestamp`, `target_selector`, `resource_url`, `sub_parts`(`load_delay`, `load_time`, `render_delay`)가 있습니다. INP에는 `duration`, `timestamp`, `target_selector`, `sub_parts`(`input_delay`, `processing_duration`, `presentation_delay`)가 있습니다. CLS에는 `score`가 있습니다. |
| `custom_timings` | 이름을 키로 사용하는 타이밍 객체입니다. |
| `scroll` | 페이지를 얼마나 아래로 스크롤했는지 나타냅니다. `max_depth`(페이지 상단에서 창 하단까지의 거리를 CSS 픽셀 단위로 표시), `max_depth_scroll_top`, `max_scroll_height`, `max_scroll_height_time`(나노초)으로 구성합니다. 스크롤 [히트맵](/ko/rum/heatmaps)에 사용하는 값입니다. |
| `action`, `error`, `resource`, `long_task`, `frustration`, `crash`, `frozen_frame` | 누적 건수를 담은 `{ "count": n }` 형태의 객체입니다. |
| `memory_average`, `memory_max`, `cpu_ticks_count`, `cpu_ticks_per_second`, `refresh_rate_average`, `refresh_rate_min`, `slow_frames_rate`, `freeze_rate` | 모바일 측정값입니다. |
| `flutter_build_time`, `flutter_raster_time` | 나노초 단위의 `{ min, max, average, metric_max }`입니다. |

## 액션

| 필드 | 설명 |
|---|---|
| `id` | 필수입니다. |
| `type` | 필수입니다. `custom`, `click`, `tap`, `scroll`, `swipe`, `application_start`, `back` 중 하나입니다. |
| `loading_time` | 단위는 나노초입니다. |
| `target` | 요소의 `name`, `selector`, `width`, `height`를 포함합니다. `path`는 태그와 순서만으로 페이지 내 요소의 위치를 나타내며, `offset`은 요소 내 클릭 지점의 `x`와 `y`를 나타냅니다. |
| `position` | 포인터의 `x`와 `y` 좌표입니다. |
| `page_position` | 페이지 내 클릭 지점의 `x`와 `y` 좌표입니다. 단위는 CSS 픽셀입니다. |
| `name_source` | 이름을 가져온 방식입니다. `custom_attribute`, `mask_placeholder`, `standard_attribute`, `text_content`, `mask_disallowed`, `blank` 중 하나입니다. |
| `frustration.type` | `rage_click`, `dead_click`, `error_click`, `rage_tap`, `error_tap` 값으로 구성한 목록입니다. |
| `error`, `crash`, `long_task`, `resource` | `{ "count": n }` 형태의 객체입니다. |

## 오류

| 필드 | 설명 |
|---|---|
| `id`, `message`, `source` | 필수입니다. `source`는 `network`, `source`, `console`, `logger`, `agent`, `webview`, `custom`, `report` 중 하나입니다. |
| `type` | `TypeError`와 같은 오류 클래스입니다. |
| `stack` | 텍스트 형식의 스택입니다. |
| `frames` | 최대 1000개의 프레임입니다. 각 프레임은 `file`, `function`, `class`, `module`, `line`, `column`, `debug_id`, `build_id`, `relative_address`, `instruction_addr`, `image_addr`, `artifact_kind`(`javascript_sourcemap`, `flutter_symbols`, `android_native_symbols`, `apple_dsym` 중 하나)를 포함합니다. |
| `fingerprint` | 선택 사항이며 최대 128자입니다. 같은 애플리케이션에서 지문이 같은 오류는 메시지와 스택이 달라도 하나의 [이슈](/ko/rum/errors)로 묶습니다. 이 필드를 생략하면 MoleSignal은 오류 유형, 메시지, 애플리케이션 자체 코드의 첫 몇 개 프레임을 기준으로 오류를 그룹화하고 이슈 ID를 `error.issue_id`에 기록합니다. `issue_id`로 전송한 값은 덮어씁니다. |
| `handling` | `handled` 또는 `unhandled`입니다. |
| `is_crash`, `category`, `source_type` | `category`는 `ANR`, `App Hang`, `Exception`, `Watchdog Termination`, `Memory Warning`, `Network` 중 하나입니다. |
| `resource` | `network` 오류를 일으킨 요청의 `method`, `status_code`, `url`입니다. |
| `causes`, `threads`, `binary_images` | 원인 체인, 스레드 스택, 로드한 바이너리 이미지입니다. |

## 리소스

| 필드 | 설명 |
|---|---|
| `type`, `url` | 필수입니다. `type`은 `document`, `xhr`, `beacon`, `fetch`, `css`, `js`, `image`, `font`, `media`, `other`, `native` 중 하나입니다. |
| `method`, `status_code` | 요청에 대한 응답이 없으면 `status_code`는 `0`입니다. |
| `duration` | 단위는 나노초입니다. |
| `size`, `encoded_body_size`, `decoded_body_size`, `transfer_size` | 단위는 바이트입니다. |
| `redirect`, `dns`, `connect`, `ssl`, `first_byte`, `download`, `worker` | 각 단계는 나노초 단위의 `{ start, duration }`으로 표시합니다. |
| `trace_id`, `span_id` | 요청의 W3C 트레이스 컨텍스트입니다. MoleSignal은 `trace_id`를 기준으로 세션을 백엔드 트레이스에 연결합니다. |
| `graphql` | `operation_type`, `operation_name`, `payload`, `variables`를 포함합니다. |
| `request.headers`, `response.headers` | 헤더를 담은 객체입니다. |

## 긴 작업

| 필드 | 설명 |
|---|---|
| `duration` | 필수입니다. 단위는 나노초입니다. |
| `entry_type` | `long-task` 또는 `long-animation-frame`입니다. |
| `start_time`, `blocking_duration`, `render_start`, `style_and_layout_start`, `first_ui_event_timestamp` | 뷰 시작을 기준으로 한 나노초 값입니다. |
| `is_frozen_frame` | 모바일 앱의 정지 프레임이면 `true`입니다. |
| `scripts` | 긴 애니메이션 프레임의 스크립트 목록입니다. 각 스크립트는 `duration`, `source_url`, `source_function_name`, `invoker`, `invoker_type`을 포함합니다. |

## 바이탈

| 필드 | 설명 |
|---|---|
| `id`, `type` | 필수입니다. `type`은 `duration`, `app_launch`, `operation_step` 중 하나입니다. |
| `name`, `duration` | `duration` 유형에서는 필수입니다. |
| `app_launch_metric`, `startup_type` | `app_launch` 유형에서는 `duration`과 함께 필수입니다. `app_launch_metric`은 `ttid` 또는 `ttfd`이고, `startup_type`은 `cold_start` 또는 `warm_start`입니다. |
| `step_type`, `operation_key`, `failure_reason` | `operation_step` 유형에 사용합니다. `step_type`은 `start`, `update`, `retry`, `end` 중 하나입니다. |

## 로그

`log` 이벤트는 최상위에 `level`과 `message`를 두어 일반 로그 스트림과 같은 방식으로 읽을 수 있으며, `log` 객체도 포함합니다. [브라우저 로그](/ko/rum/logs)를 참고합니다.

| 필드 | 설명 |
|---|---|
| `level` | 필수입니다. `debug`, `info`, `warn`, `error` 중 하나입니다. |
| `message` | 필수입니다. |
| `log.id` | 필수입니다. |
| `log.logger` | 로거 이름입니다. |
| `log.origin` | `logger`, `console`, `report`, `sdk` 중 하나입니다. |
| `log.error_type`, `log.stack` | 로그에 기록한 오류의 유형과 스택입니다. |

## MoleSignal이 추가하는 정보

- **위치:** 클라이언트 IP 주소에 해당하는 국가, 행정 구역, 도시, 대륙, 좌표를
  DB-IP City Lite 데이터베이스에서 조회합니다. IP 주소 자체는 애플리케이션이 보관하도록 설정한 경우에만 보관합니다.
- **브라우저, 시스템, 디바이스:** 브라우저 이벤트에 이 정보가 없으면 `User-Agent` 헤더를 파싱하여 추가합니다.
  크롤러는 `device.type: bot`으로 분류합니다. SDK에서 전송한 값이 우선합니다.
- **URL 구성 요소:** `view.url_host`, `view.url_path`, `view.url_path_group`을 추가합니다. `resource.url`에도 같은 방식으로 적용합니다.
- **긴 작업 스크립트:** `long_task.scripts`에서 가장 오래 실행된 항목을 기준으로 `long_task.top_script.source_url`, `long_task.top_script.function`, `long_task.top_script.invoker_type`을 채웁니다. 브라우저가 스크립트를 보고하지 않으면 이 필드를 비워 두며, 클라이언트가 이 필드에 보낸 값은 무시합니다.
- **세션:** 각 세션의 뷰를 바탕으로 `rum_sessions` 행을 생성합니다.

이벤트를 저장하기 전에 애플리케이션 설정을 적용합니다. 보관하지 않도록 설정한 세션은 제외하고,
제거하도록 설정한 [민감한 텍스트](/ko/rum/privacy#수신-단계에서-민감한-텍스트-제거)는 대체합니다.

IP 주소와 위치 정보는 [애플리케이션 설정](/ko/rum/applications#수집)에 따라 처리합니다.

## 이벤트 저장 위치

각 이벤트 유형에는 전용 일반 로그 스트림이 있으며, 첫 애플리케이션을 생성할 때 이 스트림이 생성됩니다. 스트림은 고정된
스키마를 사용하므로 유형이 맞지 않는 값이 들어와도 열은 변경되지 않습니다.

| 스트림 | 행 |
|---|---|
| `rum_sessions` | 세션당 파생 행 1개입니다. |
| `rum_views` | 뷰당 행 1개입니다. |
| `rum_actions` | 작업당 행 1개입니다. |
| `rum_errors` | 오류당 행 1개입니다. |
| `rum_resources` | 요청당 행 1개입니다. 행이 가장 많은 스트림이므로 스트림 설정에서 보존 기간을 더 짧게 설정합니다. |
| `rum_long_tasks` | 장기 작업당 행 1개입니다. |
| `rum_vitals` | 바이탈 측정값당 행 1개입니다. |
| `rum_logs` | 로그당 행 1개입니다. |

RUM 수집 기능만 이 스트림에 데이터를 씁니다. 실시간 파이프라인은 이벤트가 들어올 때 사용자 지정 부분인 `context`, `usr.extra`, `feature_flags`, `extra`를 변경할 수 있습니다. 예약 파이프라인은 스트림을 읽을 수 있습니다. [RUM 스트림](/ko/pipelines#rum-스트림)을 참조합니다.

열 이름은 `view.performance.lcp.timestamp` 및 `resource.status_code`처럼 이벤트의 필드 이름을 평탄화한 것입니다.
[RUM 탐색기](/ko/rum/explorer)에서 열을 살펴보거나 **로그**에서 SQL로 스트림을 쿼리합니다.
