브라우저 SDK는 로그가 발생한 세션과 뷰를 함께 기록합니다. 따라서 로그에서 해당 리플레이를 열고, 세션에서 페이지가 남긴 로그를 확인할 수 있습니다. 로그를 기록하거나 콘솔 로그 수집을 요청하기 전에는 아무 데이터도 전송하지 않습니다. 로그를 사용하려면 [브라우저 SDK](/ko/rum/browser-sdk) 0.3.0 이상이 필요합니다.

```ts
import { molesignalRum } from '@molesignal/browser-rum';

molesignalRum.logger.info('cart opened', { items: 3 });

const payments = molesignalRum.createLogger({ name: 'payments', level: 'warn', context: { provider: 'stripe' } });
payments.error('payment declined', { code: 402 }, error);
```

로거는 설정한 레벨보다 낮은 로그를 제외하며 `debug`, `info`, `warn`, `error`를 지원합니다. 세 번째 인수로 오류를 전달하면 로그에 오류 유형과 스택을 보존합니다.

페이지가 콘솔에 출력하는 내용도 전달하려면 다음과 같이 설정합니다.

```ts
init({ /* … */ forwardConsoleLogs: ['warn', 'error'] }); // or 'all'
```

콘솔 출력은 변경 없이 전달합니다. 콘솔에 개인 데이터가 포함될 수 있는 환경에서는 이 기능을 끈 상태로 유지하거나, 애플리케이션이 [수집 시 제거하는 항목](/ko/rum/privacy#수신-단계에서-민감한-텍스트-제거)을 확인합니다. 이 처리는 로그 메시지와 스택에도 적용됩니다.

## 로그 확인 위치

- [세션 페이지](/ko/rum/explorer#세션-열기)에서 리플레이 아래의 **로그** 탭은 로그를 시간순으로 표시하고, 리플레이가 도달한 로그를 강조 표시합니다. 행을 선택하면 리플레이가 해당 시점으로 이동합니다.
- [탐색기](/ko/rum/explorer)에서 **로그**는 행 유형 중 하나입니다.
- **로그**에서 `rum_logs`는 `level`과 `message`가 있는 일반 로그 스트림입니다. 레벨 히스토그램을 비롯한 기능은 다른 로그와 동일하게 작동합니다.

애플리케이션이 [보관하지 않는 세션](/ko/rum/sampling)의 로그는 남지 않습니다. 뷰에서는 로그 수를 집계하지 않습니다.

## SDK 오류

SDK 자체에서 문제가 발생하면(예: 서버가 이벤트를 거부하거나 `beforeSend`에서 예외가 발생하는 경우) 로거가 `molesignal-rum`이고 출처가 `sdk`인 로그를 기록합니다. 같은 문제는 한 번만 기록하며, 페이지를 로드할 때마다 몇 건만 기록합니다. 서버로 전송하는 중에 발생한 문제는 로그도 서버에 도달할 수 없으므로 기록하지 않습니다. 이 기능을 끄려면 `trackSdkErrors: false`를 설정합니다. 이 설정과 관계없이 SDK는 `onError`를 호출합니다.

## 필드

| 열 | 설명 |
|---|---|
| `level` | `debug`, `info`, `warn`, `error` 중 하나입니다. |
| `message` | 로그 메시지입니다. |
| `log.id` | 로그 ID입니다. |
| `log.logger` | 로거 이름입니다. 콘솔은 `console`, SDK 자체는 `molesignal-rum`입니다. |
| `log.origin` | `logger`, `console`, `report`, `sdk` 중 하나입니다. |
| `log.error_type`, `log.stack` | 로그에 기록된 오류의 유형과 스택입니다. |
