세션 유형은 `user`, `synthetics`, `ci_test` 중 하나입니다. [브라우저 SDK](/ko/rum/browser-sdk) 0.3.0 이상을 실행하는 페이지를 브라우저 [신세틱 검사](/ko/synthetics)로 열면 `synthetics` 유형의 세션이 생성됩니다. 별도 설정은 필요하지 않습니다. 세션 이벤트는 검사 ID, 실행 결과 ID(해당 결과의 `task_id`), 위치 ID를 각각 `synthetics.test_id`, `synthetics.result_id`, `synthetics.location_id`에 기록합니다.

## 지표에 미치는 영향

애플리케이션 지표는 실제 사용자 활동을 나타내므로 다음 항목에서는 테스트 세션을 제외합니다.

- 개요, 성능, 사용자 불편, 오류, 분석, 히트맵, 기능 플래그 페이지 및 기본 제공 대시보드
- [RUM 지표에 대한 알림 규칙](/ko/rum/alerts)
- 탐색기의 결과 행 및 Mole Agent의 RUM 도구

테스트 세션에서 발생한 오류는 [이슈](/ko/rum/errors)를 생성하지 않습니다. 따라서 검사에 실패해도 새 이슈로 집계하지 않습니다. 테스트 세션을 제외한 페이지에는 **테스트 세션 N개 제외됨**이 표시됩니다. 이 링크를 선택하면 제외된 세션을 확인할 수 있습니다.

테스트 세션에는 샘플링도 적용하지 않습니다. 애플리케이션의 [보존 설정](/ko/rum/sampling)은 세션 전체를 보존합니다. 애플리케이션 필터에 `session.type`을 명시하면 테스트 세션의 처리 방식을 지정한 것으로 간주합니다. 이 경우 다른 세션과 동일하게 애플리케이션의 필터와 비율을 적용합니다. SDK는 자체 `sessionSampleRate` 설정과 관계없이 테스트 세션을 보존합니다.

## 테스트 세션 찾기

- 실행에서: 브라우저 검사 실행 결과의 시도 상세에서 **이 실행의 RUM 세션 열기**를 선택합니다.
- 세션에서: 세션 페이지에는 세션 유형과 검사 결과로 이동하는 링크가 표시됩니다.
- 탐색기에서: `session.type`, `synthetics.*`, `ci_test.*` 중 하나를 명시하거나 특정 `session.id`를 조회하면 쿼리 조건을 그대로 적용합니다. 예를 들어 `session.type = 'synthetics'`로 신세틱 세션을 찾을 수 있습니다. 이런 조건이 없으면 탐색기는 실제 사용자 활동만 표시합니다. `session.type`의 값 목록에는 모든 세션 유형이 표시됩니다.
- API에서: `search`, `aggregate`, `facets`, `histogram`의 필터에도 동일한 동작을 적용합니다.

## 애플리케이션 테스트

페이지의 스크립트가 하나라도 실행되기 전에 동일한 전역 변수를 설정합니다. Playwright 예시는 다음과 같습니다.

```ts
await page.addInitScript((id) => {
  window.__MOLESIGNAL_TEST_CONTEXT__ = { type: 'ci_test', test_execution_id: id };
}, process.env.GITHUB_RUN_ID);
```

SDK는 기록한 세션의 ID를 `window.__MOLESIGNAL_RUM_SESSION__`에 저장합니다. 검사는 이 값을 읽어 세션에 연결합니다. 검사 시나리오가 끝나면 페이지를 벗어나 SDK가 수집한 데이터를 전송하도록 합니다.

<Note>
세션을 생성한 주체를 기록하려면 페이지에서 0.2.0보다 최신 버전의 브라우저 SDK를 실행해야 합니다. 다른 요청과 마찬가지로 SDK 요청에도 검사의 아웃바운드 정책을 적용합니다. 이 정책에서 MoleSignal로의 연결을 허용하지 않으면 검사가 실패합니다.
</Note>
