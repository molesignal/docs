브라우저에서 개인정보 보호 설정을 적용해 민감한 값이 네트워크로 전송되지 않도록 합니다. 먼저
기본 마스킹 모드를 사용하고, 기록 결과를 검토한 뒤에만 추가 콘텐츠를 허용합니다.

## 개인정보 보호를 위한 기본 설정

```ts
init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  defaultPrivacyLevel: 'mask',
  trackUrlQueryString: false,
});
```

이 기본 설정을 적용하면 다음과 같이 동작합니다.

- URL 쿼리 문자열과 프래그먼트를 제거합니다.
- 사용자, 계정 및 컨텍스트 데이터에서 `password`, `secret`, `token`, `authorization`, `cookie`, `api_key` 등의 키와 신용카드
  필드의 값을 중첩된 항목까지 재귀적으로 가립니다.
- 액션 이름은 `Click <structural selector>` 형식이며, 선택자에는 ID, 테스트 ID 또는 클래스가 포함되지 않습니다.
  `defaultPrivacyLevel: 'allow'`일 때만 요소의 텍스트를 액션 이름으로 사용합니다.
- 세션 리플레이에서 DOM 텍스트를 마스킹합니다.
- `mask-user-input`과 마찬가지로 모든 입력 요소와 `contenteditable` 요소의 값을 마스킹합니다.

<Warning>
  필드 이름을 기준으로 값을 가리는 기능은 보조 안전장치이며 데이터 분류 시스템이 아닙니다. 사용자 객체나 커스텀 컨텍스트 객체에 인증 정보,
  결제 데이터, 건강 데이터 또는 불필요한 개인정보를 추가하지 않습니다.
</Warning>

## DOM 콘텐츠 차단 또는 마스킹

SDK는 애플리케이션별 기록 코드 없이도 개인정보 보호 속성을 인식합니다.

```html
<section data-molesignal-block>
  <!-- The entire subtree becomes a placeholder. -->
</section>

<span data-molesignal-mask>Account holder name</span>

<div data-molesignal-ignore>
  <!-- Mutations and events for this element are ignored. -->
</div>
```

필요에 따라 기본 선택자를 교체합니다.

```ts
sessionReplay: {
  blockSelector: '.payment-form, [data-private-panel]',
  maskTextSelector: '.customer-name, [data-molesignal-mask]',
  ignoreSelector: '.animation-layer, [data-molesignal-ignore]',
},
```

비밀 정보나 큰 민감 위젯은 차단하고, 레이아웃을 확인할 필요가 있는 텍스트는 마스킹하며,
조사에 도움이 되지 않고 노이즈만 늘리는 요소는 무시합니다.

## 페이지를 표시하고 입력 내용 숨기기

`defaultPrivacyLevel: 'mask-user-input'`은 페이지 텍스트를 기록하고 직접 입력한 내용, 즉 입력 요소와
`contenteditable` 요소의 값을 마스킹합니다. 모든 사용자에게 같은 텍스트를 표시하는 페이지에 적합합니다. 설정한 `maskTextSelector`에 일치하는 텍스트는 계속 마스킹합니다.

`mask` 모드에서도 안전하다고 확인한 텍스트가 있는 영역은 표시할 수 있습니다.

```html
<nav data-molesignal-allow>Pricing · Docs · Sign in</nav>
```

`data-molesignal-allow`는 해당 요소와 그 안에 있는 텍스트를 표시합니다. 영역 안에서 차단 또는 무시하도록 설정했거나
`maskTextSelector`에 일치하는 콘텐츠에는 기존 설정을 유지합니다. 입력 요소와 `contenteditable` 요소도 계속 마스킹합니다.

## 페이지에 표시되는 텍스트를 신중하게 허용하기

모든 민감 영역을 표시한 뒤에만 `defaultPrivacyLevel: 'allow'`를 설정합니다. 이 모드는 입력 내용도 표시하지만, 비밀번호, 이메일
주소, 전화번호, `autocomplete` 속성에 카드 정보나 일회용 코드를 입력하는 것으로 지정된 필드, 그리고
`data-molesignal-mask` 영역 안의 필드는 계속 마스킹합니다. 설정한 `maskTextSelector`에 일치하는 텍스트도 계속 마스킹합니다.

```ts
defaultPrivacyLevel: 'allow',
sessionReplay: {
  blockSelector: '[data-molesignal-block], .payment-details',
  maskTextSelector: '[data-molesignal-mask], .customer-identity',
},
```

## URL 및 네트워크 데이터 수집 제어

애플리케이션에서 쿼리에 식별자나 비밀 정보가 절대 포함되지 않는다고 보장하지 않는 한
`trackUrlQueryString: false` 설정을 유지합니다. 수집 전에 민감한 경로나 네트워크 엔드포인트를 제외합니다.

```ts
excludedUrls: [
  '/account/security',
  /^https:\/\/api\.example\.com\/private\//,
  (url) => url.includes('/token-exchange'),
],
```

`allowedTracingUrls`는 트레이스 컨텍스트를 제공할 수 있는 오리진을 제어합니다. 이 옵션은 요청
또는 응답 본문 수집을 활성화하지 않습니다. SDK는 타이밍 정보와 민감 정보를 제거한 URL 메타데이터를 기록합니다.

## 수신 단계에서 민감한 텍스트 제거

SDK가 일차로 보호하고 서버가 이차로 보호합니다. 어떤 SDK나 클라이언트에서 이벤트를 전송했든, 애플리케이션은 설정에서 선택한 유형의 민감한 텍스트를
저장 전에 모든 이벤트에서 제거합니다. 
**RUM → 애플리케이션**에서 애플리케이션을 열고 **민감 데이터** 유형별로 제거 기능을 켜거나 끕니다. 새 애플리케이션에서는 모든 유형이 기본으로 켜져 있습니다.

| 유형 | 제거 대상 | 대체 값 |
|---|---|---|
| **토큰, 키 및 비밀번호** | Bearer 및 Basic 토큰, JWT, 클라우드 및 코드 서비스의 키(AWS 액세스 키와 GitHub, GitLab, Slack, Stripe, OpenAI, Google, npm 토큰), 개인 키, `password=`, `secret:`, `api_key=`, `authorization:` 등과 유사한 문자열 뒤에 오는 값, `Authorization`, `Cookie`, `Set-Cookie`, `Proxy-Authorization`, `X-API-Key`, `X-Auth-Token`, `X-CSRF-Token` 헤더의 값입니다. | `[secret]` |
| **이메일 주소** | `jane@example.com`과 같은 주소입니다. | `[email]` |
| **전화번호** | `+`로 시작하는 8~15자리 국제 전화번호, 11자리 중국 휴대전화 번호, `(415) 555-2671`과 같은 북미 전화번호입니다. | `[phone]` |
| **결제 카드 번호** | 숫자 그룹 사이에 공백이나 하이픈이 있고, 카드 네트워크의 접두사와 일치하며 검증 숫자 검사를 통과하는 13~19자리 번호입니다. | `[card]` |
| **개인 식별 번호** | 검증 문자 검사를 통과하는 중국 주민 신분증 번호와 미국 사회보장번호입니다. | `[id]` |
| **민감한 URL 매개변수** | 이름이 `code`, `key`, `sig`, `sid`, `otp`, `ticket`, `email`, `phone` 등과 유사하거나 `token`, `secret`, `password`, `auth`, `signature`, `api_key`, `credential`, `jwt`, `session`을 포함하는 쿼리 및 프래그먼트 매개변수의 값입니다. 호스트 앞의 사용자 이름과 비밀번호도 제거합니다. 매개변수 이름은 유지합니다. | `[redacted]` |

이벤트가 발생한 주소와 유입 주소(`view.url`, `view.referrer`, `resource.url` 및
오류 주소), 오류와 그 원인의 메시지 및 스택, 뷰 이름과 클릭한 항목의 이름, 요청의 GraphQL 작업, 페이로드,
변수, 요청 및 응답 헤더, `context` 객체에서 민감한 텍스트를 제거합니다. 텍스트에 포함된 주소에도
같은 제거 규칙을 적용하되, 스택에서 주소 뒤에 표시하는 위치 정보(`:10:5`)는 유지합니다. `user`와 `account`는 애플리케이션이
전송하기로 선택한 개인 관련 정보이므로 변경하지 않습니다.

이벤트를 행으로 변환하기 전에 민감한 텍스트를 제거하므로, 제거 후 남은 데이터를 기준으로 파생 정보를 생성합니다.
예를 들어 이메일이 포함됐던 주소의 `view.url_path`와 `view.url_path_group`, 오류가 속하는 [이슈](/ko/rum/errors)가 이에 해당합니다.
메시지의 이메일 주소나 번호만 다른 오류는 하나의 이슈로 묶습니다.

<Warning>
  각 유형은 데이터 분류가 아니라 문자열의 형식과 검증 규칙을 기준으로 판단합니다. `13`으로 시작하는 11자리
  주문 번호처럼 전화번호와 형식이 비슷한 값은 전화번호로 판단해 제거하지만, 자유 입력 텍스트에 적은 이름이나 주소는 인식하지 못합니다. 조사에 필요한 정보를
  제거하는 유형은 끄고, SDK 단계에서 민감한 값이 이벤트에 포함되지 않도록 합니다.
</Warning>

변경 사항은 변경 후 수신하는 이벤트에 적용합니다. 이전에 저장한 데이터는 변경하지 않습니다. 세션 리플레이 세그먼트에는
서버의 제거 처리를 적용하지 않습니다. SDK가 위에서 설명한 개인정보 보호 수준에 따라 세그먼트의 텍스트를 마스킹합니다.

## 프로덕션 적용 전 검토

<Steps>
  <Step title="통제된 테스트 세션 기록">
    프로덕션 데이터가 아닌 테스트 데이터로 로그인, 결제, 프로필, 검색 및 오류 흐름을 실행합니다.
  </Step>
  <Step title="이벤트 데이터 노출 지점 모두 점검">
    세션 메타데이터, 액션 이름, URL, 오류 스택, 커스텀 컨텍스트 및 DOM 리플레이를 검토합니다.
  </Step>
  <Step title="선택자 및 제외 항목 추가">
    민감한 DOM 하위 트리를 차단하고 데이터를 수집할 필요가 없는 경로를 제외합니다.
  </Step>
  <Step title="UI 변경 후 다시 점검">
    개인정보 보호 선택자를 프로덕션 설정으로 관리하고, 마크업을 변경한 뒤에는 선택자가 의도대로 동작하는지 테스트합니다.
  </Step>
</Steps>
