**RUM → 오류**에서는 애플리케이션의 오류를 이슈 단위로 표시합니다. 유사한 오류는 하나의 이슈로 묶습니다.
각 이슈에는 상태, 담당 팀, 담당자, 발생 시점과 버전의 기록이 있습니다. 모든 오류는
`rum_errors` 스트림에 남으며, `error.issue_id`에 해당 이슈의 ID를 저장하므로 [탐색기](/ko/rum/explorer)와 쿼리에서 오류와 이슈를 모두 확인할 수 있습니다.

## 오류를 이슈로 그룹화하는 방식

서버는 오류를 수신할 때 해당 오류가 속할 이슈를 결정합니다. 다음 항목을 해시하여 이슈 ID를 생성합니다.

- 애플리케이션과 `error.source`
- 오류의 유형과 범주, 그리고 오류마다 달라지는 부분을 제거한 메시지
- 애플리케이션 자체 코드의 처음 세 스택 프레임. 릴리스의 소스 맵, 매핑 파일 또는 심볼 파일을 업로드한 경우 해당 파일로 복원한 프레임을 사용합니다([소스 맵 및 심볼](/ko/rum/source-maps) 참조).
- 요청 실패의 경우 요청 메서드, 경로, 상태 코드

메시지에서 숫자, UUID, 8자리 이상인 16진수 해시, 이메일 주소, 웹 주소의
쿼리 문자열 또는 프래그먼트를 제거합니다. 따라서 `Loading chunk 482 failed.`와 `Loading chunk 17 failed.`는 하나의 이슈로 묶입니다.
패키지, 프레임워크 또는 런타임의 프레임은 애플리케이션 자체 코드에 속하지 않으므로, 애플리케이션 자체 프레임이
있으면 그룹화에 사용하지 않습니다.

다른 기준으로 오류를 그룹화하려면 `error.fingerprint`(최대 128자)를 전송합니다. 같은 애플리케이션에서 동일한
핑거프린트를 지정한 오류는 메시지와 스택에 관계없이 하나의 이슈로 묶입니다. SDK는 이 값을 설정하지 않으므로 오류를
보고하는 호출에 직접 전달합니다.

<Note>
  ID 생성 규칙은 버전으로 관리합니다. 이후 오류 그룹화 방식이 바뀌면 새 ID를 생성하며,
  기존 이슈는 다시 그룹화하지 않습니다. 이슈 추적을 시작하기 전에 수신한 오류에는 `error.issue_id`가 없으며
  목록에 표시하지 않습니다. 릴리스의 소스 맵을 업로드하기 전에 수신한 오류는 원본 프레임으로 그룹화하고, 업로드 후에
  수신한 오류는 복원된 프레임으로 그룹화합니다. 따라서 같은 문제가 두 이슈로 나뉠 수 있습니다. 기존 이슈는 병합하지 않습니다.
</Note>

## 이슈 목록

목록에는 선택한 애플리케이션과 환경에서 지정한 시간 범위에 오류가 발생한 이슈가 표시됩니다. 각 행에는 다음 정보가 표시됩니다.

| 열 | 표시 정보 |
|---|---|
| **이슈** | 첫 오류의 유형과 메시지, 애플리케이션 자체 코드의 첫 스택 프레임입니다. |
| **상태** | 이슈의 처리 상태입니다. [상태](#상태)를 참조합니다. |
| **담당자** | 이슈를 맡은 담당자입니다. 담당자가 없으면 담당 팀을 표시합니다. |
| **세션** | 지정한 시간 범위에 이슈가 발생한 세션 수입니다. |
| **사용자** | 이슈의 영향을 받은 사용자 수입니다. 사용자 ID가 없는 방문자는 SDK의 익명 ID를 기준으로 집계합니다. |
| **추세** | 시간 범위를 동일한 길이의 12개 구간으로 나누어 각 구간의 발생 빈도를 표시합니다. |
| **버전** | 이슈가 처음 발생한 버전과 가장 최근에 발생한 버전입니다. |
| **마지막 발생** | 전체 기간을 기준으로 이슈가 마지막으로 발생한 시점입니다. |

기본적으로 목록에는 **미해결** 이슈가 표시됩니다. 여기에는 열기, 조사 중, 재발 상태가 포함됩니다. 필터에서 다른 상태나
**모든 이슈**를 선택합니다. 유형, 메시지 또는 발생 위치에 포함된 단어나 이슈 담당자로 목록을 좁힐 수 있습니다.
여러 종류의 클라이언트가 오류를 전송했다면 소스로도 필터링할 수 있습니다. **상태**, **세션**, **사용자** 또는 **마지막 발생**을 클릭해 행을 정렬합니다.
같은 열을 다시 클릭하면 정렬 순서가 반대로 바뀝니다. 페이지 상태가 URL에 저장되므로 현재 보기를 공유할 수 있습니다.

목록은 선택한 정렬 기준(세션 수, 사용자 수 또는 발생 횟수)에 따라 상위 250개 이슈를 가져온 다음
필터를 적용합니다. 따라서 250위 밖의 이슈는 필터로도 찾을 수 없습니다. 목록에는 최대 100개 이슈를 표시합니다.

목록 위의 **발생 위치**는 목록에 있는 이슈의 세션 분포를 버전, 페이지,
브라우저별로 보여 줍니다. 값을 클릭하면 해당 값에 해당하는 오류만 목록에 표시하며, 모든 열에 같은 필터를 적용합니다.
같은 값을 다시 클릭하면 필터를 해제합니다.

## 이슈 상세 정보

행을 클릭하면 이슈가 측면 패널에 열립니다. URL에 이슈 정보가 포함되므로 같은 URL을 열면 측면 패널이 다시 열립니다.

- 상단에서 상태, 담당 팀, 담당자를 설정합니다. **탐색기에서 보기**를 클릭하면 탐색기에서 해당 이슈의 오류를 확인할 수 있습니다.
- 요약 행에는 상태, 지정한 시간 범위의 세션 수와 사용자 수, 이슈의 최초 및 마지막 발생 시점,
  발생 버전이 표시됩니다.
- **시간별 추이**는 최근 14일간의 세션 수를 일별로 표시하고 버전별로 누적합니다. 점선은 이슈를
  해결한 날짜를 나타냅니다.
- **발생 위치**는 이슈가 발생한 세션의 분포를 브라우저, 시스템, 국가별로 보여 줍니다.
- **오류 발생 위치**에는 스택이 있는 가장 최근 오류의 프레임이 표시됩니다. 애플리케이션 자체 프레임은 굵게 표시하고,
  라이브러리 프레임은 흐리게 표시합니다. 디버그 아티팩트로 프레임을 복원한 경우 **복원됨**과 **원본**을 전환할 수 있습니다.
- **최근 세션**에는 이슈가 발생한 최근 세션 3개와 각 세션의 리플레이 및 타임라인 링크가 표시됩니다.
  **영향을 받은 사용자**에는 이슈를 가장 자주 겪은 사용자가 표시됩니다. 저장하지 않은 세션의 오류는 오류만 보관하므로,
  세션 링크 대신 *저장하지 않은 세션*이 표시됩니다. [RUM 데이터 샘플링](/ko/rum/sampling#모든-오류-보존)을 참조합니다.

목록에 표시하는 이슈의 유형, 메시지, 발생 위치는 첫 오류를 수신했을 때의 값으로 유지합니다.
이 값에는 저장 시점의 마스킹 규칙을 적용합니다.

## 상태

| 상태 | 의미 | 설정 주체 |
|---|---|---|
| **열기** | 아직 검토하지 않은 상태입니다. 새 이슈는 이 상태로 시작합니다. | 서버 또는 사용자 |
| **조사 중** | 원인을 조사 중입니다. | 사용자 |
| **재발** | 해결한 이슈가 더 새로운 버전에서 다시 발생했습니다. | 서버만 |
| **해결됨** | 원인을 해결했습니다. | 사용자 |
| **무시됨** | 별도의 조치가 필요하지 않습니다. | 사용자 |

열기, 조사 중, 재발 상태의 이슈는 미해결로 분류합니다.

### 재발

이슈를 해결하면 해결 시점, 해결한 사용자, 당시 애플리케이션의 최신 버전을 기록합니다. 버전 이름과 관계없이
각 버전이 처음 관측된 시점으로 버전 순서를 정합니다. 해결된 이슈의 오류가 기록된 버전보다 나중에 처음 관측된 버전에서
발생한 경우에만 이슈를 **재발** 상태로 다시 엽니다. 업데이트하지 않은 사용자는 이전 버전을 계속 사용하므로,
같은 버전이나 더 오래된 버전에서 오류가 발생해도 이슈를 다시 열지 않습니다.

애플리케이션이 버전 정보를 전송하지 않으면 버전 순서를 확인할 수 없으므로 해결 후 오류가 발생할 때마다 이슈를 다시 엽니다.
단, 해결할 때 버전을 기록한 이슈는 버전 정보가 없는 오류로 다시 열지 않습니다.

재발 상태의 이슈를 다른 상태로 바꾸면 재발 상태가 종료됩니다. 이슈를 다시 해결하면 그 시점의 최신 버전을 기록합니다.

이슈는 특정 환경이 아니라 애플리케이션 전체에 속합니다. 서버는 이슈를 다시 연 오류가 발생한 환경과
각 환경에서 이슈가 처음 발생한 시점을 기록합니다. [알림 규칙](/ko/rum/alerts)은 이 정보를 사용해 환경별로 새 이슈와 재발 이슈를
집계합니다.

서버의 오류 수신부는 이슈 정보를 최대 1분 동안 캐시하므로 사용자가 설정한 상태는 1분 이내에 반영됩니다. 이전 상태가 캐시에 남아 있는 동안 더 새로운 버전에서 오류가 발생해도 이슈를 다시 열지 않습니다. 캐시가 만료된 뒤 다음 오류가 발생하면 이슈를 다시 엽니다.

## 시간당 새 이슈 한도

애플리케이션은 한 시간에 **시간당 새 이슈 한도**까지만 새 이슈를 생성합니다. 기본값은 100개입니다. 한도에 도달하면 해당 시간의 남은 기간에
발생한 오류 중 아직 이슈에 속하지 않는 오류를 **기타 오류**라는 하나의 이슈로 묶어 집계합니다. 이렇게 하면
매번 다른 오류 메시지를 보내는 애플리케이션이 목록을 가득 채우지 않습니다. 한도를 바꾸려면 **RUM → 애플리케이션**의 **이슈**
섹션에서 1~10,000 사이의 값을 설정합니다. 변경 사항은 30초 이내에 적용됩니다.

## 권한

- `rum.issues.read` 권한으로 이슈 목록과 상세 정보를 열 수 있습니다.
- `rum.issues.manage` 권한으로 상태, 팀, 담당자를 설정할 수 있습니다. 소유자, 관리자, 편집자에게 이 권한이 있습니다. 이 권한이 없으면
  현재 설정만 볼 수 있습니다.

엔드포인트는 [RUM API](/ko/api/rum#이슈)에서 확인할 수 있습니다.
