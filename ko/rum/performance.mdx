**RUM → 성능**에서는 브라우저 애플리케이션의 페이지가 실제 사용자에게 어떤 성능을 제공하는지 확인할 수 있습니다. 한 번에 애플리케이션 하나를 대상으로,
선택한 시간 범위와 단일 환경 또는 모든 환경의 데이터를 표시합니다. 코어 웹 바이탈은
[브라우저 SDK](/ko/rum/browser-sdk)에서 측정합니다. 다른 방식으로 데이터를 전송하는 애플리케이션에는 평가할 페이지 로드 데이터가 없으며, 화면에
그 사실을 표시합니다.

이 탭에는 **웹 바이탈**, **리소스**, **장기 작업**의 세 가지 하위 탭이 있습니다. 세 탭은
애플리케이션, 환경, 시간 범위를 공유하며, 링크로 다른 탭을 열어도 애플리케이션과 환경이 유지됩니다.
[리소스](#리소스) 전까지는 웹 바이탈을 설명합니다.

## 웹 바이탈 현황

요약 문장에는 페이지 뷰 수와 LCP, INP, CLS의 75번째 백분위수 값이 표시됩니다. 각 값에는 해당 등급의 색상을
적용합니다. 그 아래에는 다섯 가지 지표가 있습니다. 코어 웹 바이탈 지표 3개와 그보다 앞선 단계의 지표인 최초 콘텐츠 페인트(FCP),
첫 바이트까지의 시간(TTFB)입니다. 지표를 선택하면 차트, 등급, 표가 해당 지표를 기준으로 표시됩니다. 선택한 지표는
URL의 `vital`에 저장되므로 같은 화면을 공유할 수 있습니다.

지표의 등급은 web.dev에서 정한 기준을 따릅니다. 모든 애플리케이션에 같은 기준을 적용합니다.

| 지표 | 양호 | 개선 필요 | 저조 |
|---|---|---|---|
| **LCP**, 최대 콘텐츠 페인트 | 2.5 s 이하 | 2.5 s 초과~4 s 이하 | 4 s 초과 |
| **INP**, 다음 페인트까지의 상호작용 시간 | 200 ms 이하 | 200 ms 초과~500 ms 이하 | 500 ms 초과 |
| **CLS**, 누적 레이아웃 변경 | 0.1 이하 | 0.1 초과~0.25 이하 | 0.25 초과 |
| **FCP**, 최초 콘텐츠 페인트 | 1.8 s 이하 | 1.8 s 초과~3 s 이하 | 3 s 초과 |
| **TTFB**, 첫 바이트까지의 시간 | 0.8 s 이하 | 0.8 s 초과~1.8 s 이하 | 1.8 s 초과 |

## 시간별 추이

선택한 지표의 75번째 백분위수를 시간 구간별로 표시합니다. 두 점선은 양호에서 개선 필요로, 개선 필요에서 저조로
바뀌는 기준을 나타냅니다. 차트에서 원하는 구간을 드래그하여 시간 범위를 좁힙니다.

## 등급별 뷰

각 지표의 막대는 측정값이 있는 뷰를 양호, 개선 필요, 저조로 나누어 표시합니다. 막대 끝에는
양호한 뷰의 비율을 표시합니다. 선택한 지표는 세 등급의 비율, 뷰 수, 기준값을 텍스트로 표시합니다. 비율은
추정치가 아니라 각 기준값 이하인 뷰의 실제 개수를 바탕으로 계산합니다.

## 페이지 및 기타 차원

표에는 한 차원에서 뷰 수가 가장 많은 값이 표시됩니다. 각 값에는 뷰 수, 등급 색상을 적용한 지표별
75번째 백분위수, 선택한 지표가 양호한 뷰의 비율이 표시됩니다.

- **그룹화 기준**에서 페이지(`view.url_path_group`), 브라우저, 운영 체제, 디바이스, 국가 또는 지역, 버전 중 하나를 선택합니다.
- 표는 뷰 수가 가장 많은 값 50개를 가져오며, 열을 기준으로 이 값들을 정렬합니다. 열 제목을 클릭하여 정렬하고,
  다시 클릭하여 정렬 순서를 반대로 바꿉니다. 지표 열을 기준으로 정렬하면 해당 지표가 선택됩니다.
- 뷰 수가 30개 미만인 값은 회색으로 표시하며, 지표 기준으로 정렬할 때 항상 맨 아래에 배치합니다. 적은 수의 뷰만으로는
  페이지 속도를 판단할 수 없습니다.
- 값에 포함된 단어로 표를 필터링합니다. 차원, 정렬 순서, 검색어는 URL에 저장됩니다.

## 값의 세부 구성

행을 클릭하면 해당 값의 뷰를 보여 주는 드로어가 열립니다. URL에 값과 지표를 저장하므로 같은 URL에서 드로어를 다시
열 수 있습니다. **탐색기에서 보기**를 클릭하면 탐색기에서 같은 뷰를 확인할 수 있습니다. 헤더에서 LCP, INP, CLS를 전환합니다.
페이지나 버전의 경우 **이 항목에 대한 알림 설정**을 클릭하면 현재 탭의 지표와 해당 페이지나 버전으로 범위를 제한한 규칙 편집기가 열립니다. 이 기능에는
`alerts.rules.manage` 권한이 필요합니다. [RUM 알림](/ko/rum/alerts#페이지에서-알림-설정)을 참조합니다.

- 첫 줄에는 해당 값의 지표 수준과 측정에 포함된 뷰 수가 표시됩니다. LCP와 INP는 가장 오래 걸린 단계도 표시합니다.
- **소요 시간 구성**(LCP 및 INP)은 각 단계의 소요 시간을 하나의 막대로 표시합니다. LCP의 단계는
  첫 바이트까지의 시간, 이미지 로드 시작 전 지연 시간, 이미지 로드 시간, 페인트 전 지연 시간입니다. INP의 단계는
  핸들러 실행 전 지연 시간, 핸들러 실행 시간, 다음 프레임까지의 대기 시간입니다. 각 단계는 해당 값의
  75번째 백분위수에서 10% 이내인 뷰의 평균이므로, 단계별 소요 시간의 합은 지표 값과 대략 일치합니다. 일부 단계만 표시해도
  전체 소요 시간으로 오해할 수 있으므로, 모든 단계가 보고되지 않은 값에는 막대를 표시하지 않습니다. CLS는 점수이므로 구성 단계가 없습니다.
- **요소**에는 마지막으로 페인트한 요소(LCP), 상호작용한 요소(INP), 또는 이동한 요소(CLS)가 표시됩니다. 해당 요소가 포함된 뷰 수와
  75번째 백분위수도 표시됩니다. LCP에서는 이미지 또는 동영상 파일을 요소 옆에 표시합니다. 행을 클릭하면 해당 요소가 포함된 뷰가
  탐색기에서 열립니다.
- **시간별 추이**에는 같은 차트가 표시되지만, 현재 값만 대상으로 합니다.
- **성능이 가장 낮은 뷰**에는 지표 값이 가장 높은 뷰 5개가 표시됩니다. 각 뷰는 탐색기에서 열리며, 해당 뷰의 전체 세션도 열 수 있습니다.

<kbd>Esc</kbd>를 누르거나 드로어 바깥을 클릭하여 닫습니다.

## 리소스

**리소스**(`/rum/performance/resources`)에서는 페이지가 로드하는 리소스를 확인할 수 있습니다. 요약 문장에는 페이지의 요청 수,
요청 소요 시간의 75번째 백분위수, 실패한 요청 수(오류 상태 또는 응답 없음), 페이지 뷰당 평균 요청 리소스 수와
바이트 수가 표시됩니다.

표는 요청 수가 많은 그룹부터 나열합니다. 그룹마다 요청 수, 소요 시간과 크기의 75번째 백분위수,
실패 비율, 캐시에서 제공된 비율을 표시합니다.

- **그룹화 기준**에서 호스트와 요청 유형(기본값), 호스트와 경로, 유형, 프로토콜, 요청 제공 방식,
  또는 렌더링 차단 여부를 선택합니다.
- **유형**과 **상태**로 요청을 필터링합니다. 상태는 클라이언트 오류(400~499), 서버 오류(500 이상), 응답
  없음으로 구분합니다. 검색어로 요청 URL을 필터링할 수도 있습니다. 필터는 표와
  표 옆 패널에 모두 적용됩니다.
- 표는 요청 수가 가장 많은 그룹 100개를 가져오며, 열을 기준으로 이 그룹들을 정렬합니다. 요청 수가 30개 미만인 그룹은
  회색으로 표시하며, 요청 수 이외의 열로 정렬할 때 항상 맨 아래에 배치합니다.
- 실패 비율은 1% 이상이면 주황색, 5% 이상이면 빨간색으로 표시합니다. 제공 방식을 보고하지 않은 요청은 캐시 제공 비율을
  대시로 표시합니다.

행을 클릭하면 표 옆에 패널이 열립니다. URL에 그룹을 저장하므로 같은 URL에서 패널을 다시 열 수 있습니다.

- 첫 줄에는 소요 시간의 75번째 백분위수, 실패한 요청 수, 가장 오래 걸린 단계가 표시됩니다.
- **기간 내 소요 시간 추이**에는 시간 구간별로 그룹의 소요 시간 75번째 백분위수가 표시됩니다.
- **요청 소요 시간 구성**은 75번째 백분위수에 가까운 요청의 단계별 소요 시간을 하나의 막대로 표시합니다. 단계는 리디렉션, DNS,
  연결, TLS, 첫 바이트까지의 시간, 다운로드입니다. 각 단계의 소요 시간은 75번째 백분위수에서 10% 이내인
  요청의 평균입니다.
- **응답 상태**는 그룹의 상태 코드를 빈도순으로 나열합니다. 각 코드의 비율은 처리 결과를 보고한
  요청을 기준으로 계산합니다.
- **가장 느린 요청**에는 소요 시간이 가장 긴 요청 3개가 표시됩니다. 요청을 클릭하면 해당 요청을 보낸 뷰의 로드 화면이
  열리고 해당 요청이 선택됩니다.
- 트레이스 ID가 있는 요청이 있으면 해당 요청 수를 표시합니다. 이 줄을 클릭하면 그룹의 요청이 탐색기에서 열립니다.

## 장기 작업

**장기 작업** (`/rum/performance/long-tasks`)에서는 페이지의 메인 스레드를 차단하는 작업을 확인할 수 있습니다. 요약 문장에는 전체 장기
작업 수, 장기 작업이 하나 이상 발생한 페이지 뷰 수, 장기 작업 실행 시간과 입력 지연 시간의 75번째
백분위수가 표시됩니다.

표에는 작업 수가 많은 그룹부터 나열하며, 그룹별 장기 작업 수와 해당 작업이 발생한 뷰 수, 실행 시간과 입력 지연 시간의 75번째
백분위수를 표시합니다. 시간은 100 ms 이상이면 주황색으로, 200 ms 이상이면 빨간색으로 표시합니다.

- **그룹화 기준**에서 장기 작업의 출처인 스크립트와 함수(기본값), 페이지, 버전 또는
  트리거 방식을 선택합니다. 검색어가 주소에 포함된 스크립트의 장기 작업만 표시할 수 있습니다.
- 긴 애니메이션 프레임을 보고하는 브라우저는 해당 프레임에서 실행된 스크립트를 보고합니다. MoleSignal은 가장 오래 실행된
  스크립트를 장기 작업의 출처로 지정합니다([MoleSignal이 추가하는 정보](/ko/rum/events#molesignal이-추가하는-정보) 참조). Safari와 Firefox는
  스크립트 정보 없이 장기 작업을 보고합니다. 스크립트를 식별하기 전에 수신한 장기 작업에도 출처 정보가 없습니다. 이러한 작업은
  **출처 미확인** 그룹으로 묶고 다른 그룹과 동일하게 집계합니다.
- 리소스와 마찬가지로 장기 작업이 30개 미만인 그룹은 회색으로 표시하며 순위 맨 아래에 배치합니다.

행을 클릭하면 패널이 열리고 그룹 내 장기 작업의 트리거 방식, 작업이 발생한 페이지, 실행 시간이 가장 긴 작업 3개를 표시합니다.
이 작업 중 하나를 클릭하면 해당 작업이 차단한 뷰의 로드 상세 정보가 열리고, 메인 스레드에서 해당 작업이 선택됩니다.

## 뷰 로드

탐색기에서 브라우저 뷰를 열면 서랍 패널의 **로드 워터폴**이 표시됩니다. 뷰 필드는 다음 섹션에서 설명합니다. 탐색기의 행이나
위에서 설명한 가장 느린 요청 또는 실행 시간이 가장 긴 장기 작업을 클릭해 패널을 엽니다.

- 요약 문장에는 페이지 로드 시간, 첫 바이트 수신 시점, 최대 페인트에 걸린 시간과 대상 요소,
  리소스 수와 장기 작업 수가 표시됩니다.
- 시간 축은 뷰가 시작된 시점부터 페이지 로드가 끝난 이후까지 표시합니다. 첫 바이트 수신, 첫 페인트,
  최대 페인트, 문서 준비 완료, 로드 완료 시점을 선으로 표시합니다. 최대 페인트가 기다린 파일에는 이를 별도로 표시합니다.
- **메인 스레드**에는 동일한 시간 축에 장기 작업이 표시됩니다. 첫 페인트를 차단한 요청에는 이를 별도로 표시합니다.
- 요청을 시작한 순서대로 한 행씩 표시합니다. 막대는 요청 시작부터 종료까지 이어지며 첫 바이트 수신 시점을
  기준으로 수신 전 대기 시간과 수신 후 다운로드 시간으로 나뉩니다. 처음 15개 요청을 표시하고, 나머지는 요청 수와
  대부분의 요청에 걸린 시간을 보여 주는 한 줄로 접습니다. 페이지 로드 후 시작된 요청은 별도의 줄에 집계합니다.
  **유형**과 **표시**(차단, 느림: 500 ms 이상, 실패)로 행을 필터링합니다.
- 요청이나 메인 스레드의 장기 작업을 클릭하면 오른쪽 패널에 대상, 종료 결과, 크기, 전송 방식,
  단계별 소요 시간, 연결된 트레이스가 표시됩니다. 최대 페인트가 기다린 파일의 경우, 패널에
  로드 시작 전 대기 시간, 로드 시간, 렌더링 전 대기 시간도 표시됩니다. 다른 페이지에서 연 요청이 페이지 로드 이후
  시작된 경우 시간 축에 표시하지 않으며 패널에 그 이유를 표시합니다.

모바일 애플리케이션 화면에는 로드할 페이지가 없으므로 서랍 패널에는 화면의 필드만 표시됩니다.

## 수치 집계 방식

[`/api/v1/rum/aggregate`](/ko/api/rum#행-집계)는 조건에 맞는 `rum_views` 행을 기준으로 모든 Web Vitals 수치를 집계합니다.
변경 사항이 다시 보고된 뷰는 최신 버전으로 한 번만 집계합니다. 리소스 수치는
`rum_resources`를 기준으로, 장기 작업 수치는 `rum_long_tasks`를 기준으로 집계합니다. 뷰 비율은 `rum_views`를 기준으로 집계합니다. 집계 시간이
제한을 초과하면 해당 카드에 이를 표시하고 다른 카드는 그대로 유지합니다. 시간 범위를 좁혀 다시 확인합니다. 뷰 로드 상세 정보는
해당 뷰 ID가 있는 요청과 장기 작업을 로드 시간 범위 내에서 조회합니다.

요소, 단계별 소요 시간, 성능이 가장 낮은 뷰는 SDK가 각 Web Vitals 지표와 함께 보고하는 기여도 정보를 바탕으로 표시합니다([이벤트 형식](/ko/rum/events#뷰)의
`view.performance` 필드 참조). 브라우저에서 측정하지 않는 지표는 해당 뷰에 표시하지 않습니다.

이 페이지를 사용하려면 `rum.events.read` 권한이 필요합니다. [RUM](/ko/rum#권한)을 참조합니다.
