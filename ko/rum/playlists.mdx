재생목록은 팀에서 세션을 하나씩 검토할 수 있도록 모아 둔 목록입니다. 버그 보고서와 관련된 세션, 같은 오류로
끝난 방문 세션, 변경 사항의 혜택을 받을 사용자 세션 등을 모을 수 있습니다. **RUM → 재생 목록**에서 목록을 확인합니다. 각 재생목록은 하나의
애플리케이션에 속하며, `rum.playlists.read` 권한이 있으면 볼 수 있습니다. 재생목록을 만들거나 변경하려면 `rum.playlists.manage` 권한이 필요합니다.

## 리플레이의 특정 시점 공유

세션 상단의 **현재 재생 위치 링크 복사**는 현재 시점에서 리플레이가 열리는 세션 주소를
복사합니다. 링크를 열면 해당 시점에 일시 정지된 상태로 리플레이가 표시됩니다. 리플레이를 아직 불러오지 않았거나
기록된 리플레이가 없으면 **링크 복사**로 재생 시점이 없는 세션 주소를 복사합니다.

주소의 `at`에는 에포크 이후 경과한 시간을 마이크로초 단위로 기록합니다. 세션이 진행된 시간 범위는 `from`과
`to`에 기록하므로 이전 세션의 링크로도 해당 세션을 찾을 수 있습니다.

## 재생목록에 세션 추가

세션 상단의 **재생목록에 추가**는 해당 애플리케이션의 재생목록과 각 재생목록의 세션 수를 표시합니다. 체크 표시는
해당 세션이 재생목록에 있음을 나타냅니다. 재생목록을 클릭해 세션을 추가하고, 다시 클릭해 세션을 제거합니다.

- **현재 재생 시점부터 열기**를 선택하면 현재 재생 시점이 세션과 함께 저장됩니다. 그러면
  재생목록에서 세션을 열 때 해당 시점부터 시작합니다. 선택하지 않으면 처음부터 열립니다. 세션을 다시 추가하면 목록 내 위치는 유지하고 재생 시점만 갱신합니다.
- 이름을 입력하고 **만들고 추가**를 클릭하면 해당 애플리케이션에 새 재생목록을 만들고 세션을 추가합니다.

재생목록에는 세션을 최대 500개까지 추가할 수 있습니다. 각 세션은 한 번만 포함되며 추가한 순서대로 표시됩니다.

## 재생목록 목록

목록에는 각 재생목록의 설명, 애플리케이션, 세션 수, 마지막 변경 시각,
생성자가 표시됩니다. 최근에 변경한 재생목록이 맨 위에 표시됩니다. 애플리케이션이 여러 개면 애플리케이션을 선택해 목록을 필터링합니다.

- **새 재생목록**에서 이름(최대 128자)과 설명(최대 1,000자)을 입력하고 애플리케이션을 선택합니다. 같은 애플리케이션의 다른 재생목록과
  이름이 같으면 대소문자가 달라도 사용할 수 없습니다.
- 행을 클릭하면 해당 재생목록이 열립니다.

## 재생목록 상세

재생목록은 세션을 추가한 순서대로 표시합니다. 각 세션에는 첫 페이지, 사용자, 시작 시각,
지속 시간, 세션 중 발생한 이벤트(오류 및 불편 징후), 그리고 세션 시작을 기준으로 한
재생 시작 시점이 표시됩니다. 보존 기간이 지나 세션 데이터가 삭제되면 **데이터에서 찾을 수 없음**으로 표시됩니다. 해당 세션은
행 끝의 X 버튼으로 제거할 때까지 목록에 남습니다.

- **처음부터 재생**을 클릭하면 첫 번째 세션이 열립니다.
- **이름 변경**에서 이름과 설명을 변경합니다. 애플리케이션은 변경하지 않습니다.
- **재생목록 삭제**를 클릭하고 확인하면 재생목록이 삭제됩니다. 재생목록에 있던 세션은 삭제되지 않습니다.

## 재생목록 순서대로 보기

재생목록에서 세션을 열면 상단 표시줄에 재생목록 이름, 전체 세션 수와 현재 세션의 순번,
**이전** 및 **다음** 버튼이 표시됩니다. 각 버튼은 해당 세션을 추가할 때 저장한 시점에서 엽니다. 세션 데이터가 삭제된 경우에도 표시줄이 유지되므로
다른 세션으로 계속 이동할 수 있습니다. 주소에 재생목록이 `playlist`로 포함되므로 페이지를 새로고침해도 표시줄이 유지됩니다.

## API

[RUM API](/ko/api/rum#재생목록)로 재생목록을 조회, 생성, 변경, 삭제하고 세션을 추가하거나 제거할 수 있습니다.
