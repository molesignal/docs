MoleSignal 브라우저 RUM SDK는 페이지 조회, 사용자 인터랙션, 프런트엔드 오류, Web Vitals, 네트워크
리소스, 긴 작업, [로그](/ko/rum/logs), 트레이스 상관관계 컨텍스트를 수집해 [RUM 이벤트](/ko/rum/events)로 전송합니다.

## 사전 요구 사항

- MoleSignal 배포 URL
- `checkout-web`과 같은 [RUM 애플리케이션](/ko/rum/applications)
- 애플리케이션의 클라이언트 토큰
- npm에서 설치하기 위한 Node 24 이상

<Warning>
  브라우저 코드에 포함된 `clientToken`은 사용자에게 노출됩니다. 소유자 토큰, 관리자 토큰,
  개인 토큰은 절대 사용하지 마세요. 애플리케이션에 연결된 클라이언트 토큰을 사용합니다. 모든 토큰이 `mspat-`로 시작하므로
  SDK는 토큰 유형을 구분할 수 없습니다.
</Warning>

## 애플리케이션 및 토큰 가져오기

**RUM → 애플리케이션**을 열고 **애플리케이션 만들기**를 클릭한 다음 **브라우저** 플랫폼을 선택합니다. 애플리케이션이 열리면 클라이언트
토큰을 확인할 수 있습니다. **설정 가이드 열기**를 클릭하면 엔드포인트, 토큰, 식별자가 채워진 코드 스니펫이 표시됩니다.
**데이터 소스**의 **웹 RUM**에서도 같은 가이드를 확인할 수 있습니다. 토큰은
[API](/ko/api/auth/rum-token)에서도 가져올 수 있습니다.

## 설치 및 초기화

<Steps>
  <Step title="패키지 설치">
    ```bash
    npm install @molesignal/browser-rum
    ```
  </Step>
  <Step title="SDK를 한 번만 초기화">
    ```ts
    import { init } from '@molesignal/browser-rum';

    const rum = init({
      applicationId: 'checkout-web',
      clientToken: 'mspat-your-client-token',
      site: 'https://molesignal.example.com',
      service: 'web-frontend',
      env: 'production',
      version: 'v1.4.0',
      sessionSampleRate: 100,
      trackUserInteractions: true,
    });
    ```

    `init`은 클라이언트를 반환합니다. `initRum`은 같은 함수의 이전 이름이며, `molesignalRum`은 같은 API를
    싱글톤으로 제공합니다. 예를 들면 `molesignalRum.init(...)`과 `molesignalRum.setUser(...)`가 있습니다. `init` 전에 `molesignalRum`을 호출하면
    호출이 저장되고 `init`이 이를 다시 실행합니다.

    첫 페이지 조회를 수집하려면 애플리케이션 라우터가 마운트되기 전에 SDK를 초기화합니다.
    서버 측 렌더링 중에도 패키지를 안전하게 가져와 초기화할 수 있습니다. 브라우저 계측은
    브라우저 API를 사용할 수 있을 때만 시작됩니다.
  </Step>
  <Step title="첫 세션 확인">
    **RUM → 탐색기**를 열고 현재 시각을 포함하는 시간 범위를 선택합니다.
    세션이 표시되는지 확인한 다음, 세션을 열어 뷰, 요청, 오류를 확인합니다.
  </Step>
</Steps>

`site` 값으로 MoleSignal 오리진이나 `/api`, `/api/v1`, `/api/v1/rum`으로 끝나는 URL을 사용할 수 있습니다. SDK는 이벤트를
`POST /api/v1/rum/events`로, 리플레이 세그먼트를 `POST /api/v1/rum/replay`로 전송합니다. SDK는 `applicationId`를 `application.id`로 전송하며,
MoleSignal은 `application.id`가 토큰에 연결된 애플리케이션과 일치하지 않는 이벤트를 거부합니다.

## 스크립트 태그에서 로드하기

`dist/molesignal-rum.js`는 rrweb과 web-vitals를 포함하며, 전역 객체
`MoleSignalRum`을 정의하는 독립 실행형 번들입니다. 다음 스니펫으로 비동기 로드합니다. `onReady`에 전달한 콜백은 스크립트 로드가 끝난 뒤 실행됩니다.

```html
<script>
  (function (w, d, s, u, n) {
    w[n] = w[n] || { q: [], onReady: function (callback) { w[n].q.push(callback); } };
    var script = d.createElement(s);
    script.async = 1;
    script.src = u;
    d.head.appendChild(script);
  })(window, document, 'script', 'https://cdn.jsdelivr.net/npm/@molesignal/browser-rum@0.4.0/dist/molesignal-rum.js', 'MoleSignalRum');

  MoleSignalRum.onReady(function () {
    MoleSignalRum.init({
      applicationId: 'checkout-web',
      clientToken: 'mspat-your-client-token',
      site: 'https://molesignal.example.com',
      service: 'web-frontend',
      env: 'production',
      version: 'v1.4.0',
    });
  });
</script>
```

동기 로드하려면 `<script src>` 태그에 파일을 지정한 다음 `MoleSignalRum.init(...)`을 호출합니다.

## 뷰 및 세션

뷰는 페이지 조회 한 건 또는 라우트 하나를 나타냅니다. SDK는 뷰가 시작되면 즉시 보고하고, 뷰에 변경 사항이 생기면
`view.revision` 값을 높여 다시 보고합니다(최대 3초에 한 번). 뷰가 열려 있는 동안에는 5분마다 보고하며,
라우트가 변경되거나 세션이 종료되거나 페이지가 숨겨지거나 언로드되어 뷰가 끝나면 마지막으로 보고합니다. SDK는
History API와 `popstate`로 라우트 변경을 감지합니다. 뷰 이름과 시작 지점을 직접 지정하려면 `trackViewsManually: true`를 설정하고 `startView`를 호출합니다.

SDK는 세션 이벤트를 전송하지 않습니다. MoleSignal은 뷰를 바탕으로 세션을 구성합니다. 세션 정보는
`_msrum_s_<applicationId>` 쿠키에 저장되므로 애플리케이션의 모든 탭이 같은 세션을 공유합니다. 활동이 15분 동안 없거나 세션이 시작된 지
4시간이 지나면 세션이 종료되고, 다음 사용자 활동에서 새 세션이 시작됩니다. 세션마다 샘플링 여부를 한 번만 결정합니다. [데이터 샘플링](/ko/rum/sampling)을 참조합니다.
하위 도메인 간에 세션을 공유하려면 `trackSessionAcrossSubdomains: true` 또는 `sessionCookieDomain: '.example.com'`을 설정합니다.
`stopSession()`은 모든 탭의 세션을 종료합니다. 쿠키를 사용하지 않으면 페이지별로 세션을 메모리에 저장합니다.

## 사용자 식별 및 컨텍스트 추가

가능하면 초기화할 때 사용자 정보를 전달하여 첫 세션에 올바른 식별 정보가 포함되도록 합니다.

```ts
const rum = init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  user: { id: currentUser.id, plan: currentUser.plan },
  globalContext: { region: 'eu-west-1' },
});

rum.setUser({ id: 'user-42', name: 'Ada', email: 'ada@example.com' });
rum.setUserProperty('plan', 'enterprise');
rum.setAccount({ id: 'acme' });
rum.setGlobalContextProperty('checkout_step', 'payment');
```

`setUser`에는 `id`, `name`, `email` 중 하나 이상이 필요합니다. 나머지 키는 속성으로 유지합니다. 사용자를 설정하지 않으면 SDK는
`localStorage`에 계속 사용할 수 있는 익명 식별자를 생성합니다. 개인정보 보호 정책에서 익명 식별자의 영구 저장을 허용하지 않으면
`trackAnonymousUser: false`를 설정합니다. 설정 메서드로 지정한 컨텍스트는 이후 모든 이벤트에 추가됩니다. 전역 컨텍스트, 뷰 컨텍스트,
호출 컨텍스트를 이 순서대로 병합하며, 키가 겹치면 마지막 값이 우선합니다.

## 추적 동의

```ts
const rum = init({ /* … */ trackingConsent: 'not-granted' });

rum.setTrackingConsent('granted');
```

동의가 없으면 SDK는 쿠키, 익명 식별자, 탭 식별자를 생성하지 않고 계측을
설치하지 않으며 데이터를 전송하지 않습니다. 동의를 철회하면 SDK는 계측을 중단하고 자체 식별자와
영구 저장 대기열을 지웁니다.

## 커스텀 액션, 오류, 타이밍 및 바이탈 추가

```ts
rum.addAction('Checkout submitted', { cart_size: 3 });

try {
  await submitOrder();
} catch (error) {
  rum.addError(error, { component: 'CheckoutForm' });
}

// Views: with trackViewsManually, or to name a route.
rum.startView({ name: 'Order confirmation', context: { step: 3 } });
rum.setViewName('Order confirmation (3DS)');

// Custom timings and feature flags belong to the current view.
rum.addTiming('cart_ready');
rum.addFeatureFlagEvaluation('new_checkout', true);

// Durations.
const vital = rum.startDurationVital('checkout_form_ready', { description: 'form is usable' });
rum.stopDurationVital(vital);

// The page is ready when the application says so: this replaces the loading time of the view.
rum.setViewLoadingTime();

// Logs.
rum.logger.warn('cart is stale', { age_ms: 90000 });

await rum.flush();
```

페이지 이동이나 종료 시점을 제어할 수 있다면 그 전에 `rum.flush()`를 호출해 대기열의 이벤트가 전송될 때까지 기다립니다. 계측을 제거하고
클라이언트에 남은 데이터를 전송하려면 `rum.stop()`을 호출합니다. [알림 규칙](/ko/rum/alerts#애플리케이션에서-측정하는-지표)으로 커스텀 타이밍과
바이탈을 모니터링할 수 있습니다. [기능 플래그](/ko/rum/feature-flags)는 별도 페이지를 참조합니다. [로그](/ko/rum/logs)는 `rum_logs` 스트림으로 전송됩니다.

## 세션 리플레이 링크 가져오기

`getSessionReplayLink()`는 지원 티켓이나 오류 보고서에 첨부할 수 있도록 MoleSignal에서 현재 세션을 여는 주소를
반환합니다. SDK가 아직 시작되지 않았거나, 세션이 샘플링 대상이 아니거나, 동의가 없으면 `undefined`를 반환합니다.
주소는 `appUrl`을 기준으로 구성하며, 기본값은 `site`입니다. MoleSignal에 접속하는 주소가 SDK의 전송 주소와 다르면 `appUrl`을 설정합니다.

```ts
ticket.replay = molesignalRum.getSessionReplayLink();
```

링크를 열려면 로그인해야 하며 `rum.replay.read` 권한이 필요합니다.

## React

`@molesignal/browser-rum/react`는 라우터의 라우트를 SDK 뷰로 등록하고 라우트 패턴
(`/orders/42`가 아닌 `/orders/:id`)을 뷰 이름으로 사용하며, 컴포넌트 트리에서 발생한 예외를 보고합니다. React는 선택적 피어 종속성입니다.

```tsx
import { init } from '@molesignal/browser-rum';
import { reactPlugin, RumErrorBoundary, trackReactRouter } from '@molesignal/browser-rum/react';

init({ /* … */ plugins: [reactPlugin()] });
trackReactRouter(router); // a router of createBrowserRouter; trackTanStackRouter for TanStack Router

root.render(
  <RumErrorBoundary fallback={<Oops />}>
    <RouterProvider router={router} />
  </RumErrorBoundary>,
);
```

## 원격 구성

`remoteConfiguration: true`를 설정하면 SDK는 시작하기 전에 [애플리케이션의 SDK 설정](/ko/rum/applications#sdk-원격-구성)을
읽습니다. 따라서 페이지를 새로 배포하지 않아도 샘플링 비율과 개인정보 보호 수준을 변경할 수 있습니다.

## 자동 수집 기본값

| 데이터 | 옵션 | 기본값 |
|---|---|---|
| 페이지 조회 | `trackViewsManually` | History API를 통한 자동 추적 (`false`) |
| Fetch, XHR 및 리소스 타이밍 | `trackResources` | `true` |
| 긴 애니메이션 프레임 및 긴 작업 | `trackLongTasks` | `true` |
| 뷰의 Web Vitals | `trackWebVitals` | `true` |
| 클릭 | `trackUserInteractions` | `false` |
| 뷰의 페이지 스크롤 깊이 | `trackScroll` | `true` |
| 격한 반복 클릭, 무반응 클릭, 오류 클릭 | `trackFrustrations` | 인터랙션 추적과 동일 |
| 런타임 오류, 처리되지 않은 리젝션, 실패한 요청 | 기본 제공 | 활성화 |
| `console.error` | `trackConsoleErrors` | `false` |
| 콘솔 출력을 [로그](/ko/rum/logs)로 수집 | `forwardConsoleLogs` | `[]` |
| SDK 오류를 로그로 수집 | `trackSdkErrors` | `true` |
| 요청 및 응답 헤더 | `trackResourceHeaders` | `[]` |
| 뒤로/앞으로 가기 캐시에서 페이지 복원 | `trackBfcacheViews` | `false` |
| DOM 세션 리플레이 | `sessionReplaySampleRate` | `0` |

테스트에서 생성한 세션에는 테스트임을 표시합니다. [테스트 트래픽](/ko/rum/test-traffic)을 참조합니다. 클릭을 처리하는 동안 시작된 리소스, 오류, 긴 작업에는 해당 클릭의 `action.id`가 포함되며, 해당 클릭에 집계됩니다. 실패한
요청은 소스가 `network`인 오류로 기록되며, `error.resource`에 실패한 요청이 포함됩니다. FCP, LCP, FID는 페이지 로드를 나타내며
SDK는 이를 첫 번째 뷰에서 보고합니다. `web-vitals`는 페이지 로드당 INP와 CLS를 한 번씩 측정합니다. SDK는
각 값을 해당 지표를 결정한 인터랙션 또는 레이아웃 이동이 발생한 뷰에 보고합니다.

## 브라우저 요청을 트레이스에 연결

트레이싱이 허용된 URL의 경우 fetch 및 XMLHttpRequest 통합은 기존 W3C `traceparent`를 유지하거나 새로 주입한 뒤
요청, 응답 또는 이름이 `traceparent`인 `Server-Timing` 항목에서 트레이스 컨텍스트를 읽습니다. 트레이스 ID와 스팬 ID는
각각 `resource.trace_id`와 `resource.span_id`에 기록합니다. MoleSignal은 이 ID를 사용해 브라우저 요청을 백엔드 트레이스에 연결합니다. 기본적으로
동일 오리진 요청에만 트레이스 컨텍스트를 주입하고 읽습니다. 교차 오리진 API의 경우 응답 헤더를 노출하고
오리진을 명시적으로 허용합니다.

```http
Access-Control-Expose-Headers: traceparent, server-timing
```

```ts
allowedTracingUrls: [
  'https://api.example.com',
  /^https:\/\/edge-\w+\.example\.com\//,
]
```

## 구성

| 옵션 | 기본값 | 용도 |
|---|---|---|
| `applicationId` | 필수 | 애플리케이션 식별자입니다. `application.id`로 전송합니다 |
| `clientToken` | 필수 | 애플리케이션에 연결된 클라이언트 토큰(`mspat-<36>`)입니다 |
| `site` | 필수 | MoleSignal 오리진 또는 `/api`, `/api/v1`, `/api/v1/rum`을 기본 경로로 사용하는 URL입니다 |
| `service` | `applicationId` | 이벤트의 `service` 값입니다 |
| `env`, `version` | 미설정 | 배포를 구분하는 속성입니다. 소스 맵을 조회하려면 `version`이 필요합니다 |
| `debugId` | 미설정 | 빌드 디버그 ID입니다. 오류 프레임에서 `debug_id`로 전송합니다 |
| `user`, `account`, `globalContext` | 미설정 | 초기 식별 정보와 사용자 지정 속성입니다 |
| `trackingConsent` | `granted` | 모든 추적 및 식별자 생성을 시작하거나 보류합니다 |
| `sessionSampleRate` | `100` | 수집할 세션의 비율(%)입니다 |
| `sessionReplaySampleRate` | `0` | 수집한 세션 중 리플레이를 기록할 세션의 비율(%)입니다 |
| `sessionInactivityTimeout` | `900000` | 세션을 종료하기까지의 비활성 시간(밀리초)입니다 |
| `maxSessionDuration` | `14400000` | 최대 세션 지속 시간(밀리초)입니다 |
| `defaultPrivacyLevel` | `mask` | `mask`, `mask-user-input`, `allow` 중 하나를 선택해 페이지 콘텐츠와 입력값을 어느 범위까지 전송할지 정합니다. [개인정보 보호](/ko/rum/privacy)를 참조합니다 |
| `trackUrlQueryString` | `false` | 보고하는 URL에 쿼리 문자열을 유지합니다 |
| `excludedUrls` | `[]` | 문자열, RegExp 또는 콜백으로 요청에서 제외할 URL을 지정합니다 |
| `allowedTracingUrls` | 동일 오리진 | 트레이스 컨텍스트를 전달받고 트레이스에 연결할 요청을 지정합니다 |
| `traceSampleRate` | `100` | 요청이 시작한 트레이스 중 백엔드에 보존을 요청할 비율(%)입니다(W3C 샘플링 플래그). 나머지 요청에도 트레이스 컨텍스트를 전달하므로 요청과 트레이스 ID의 연결을 유지합니다 |
| `trackResourceHeaders` | `[]` | 이름 또는 RegExp로 보존할 fetch 또는 XHR 헤더를 지정합니다. 인증 정보는 보존하지 않습니다 |
| `forwardConsoleLogs` | `[]` | 로그에도 기록할 콘솔 메서드를 지정합니다. `'all'` 또는 `debug`, `log`, `info`, `warn`, `error` 중 일부를 선택합니다 |
| `trackSdkErrors` | `true` | SDK 오류를 애플리케이션 로그에 기록합니다. 페이지 로드당 몇 건으로 제한합니다 |
| `trackScroll` | `true` | 각 뷰에서 페이지를 어디까지 스크롤했는지 기록합니다 |
| `compressIntakeRequests` | `false` | 브라우저가 지원하면 이벤트 요청을 Gzip으로 압축합니다 |
| `remoteConfiguration` | `false` | SDK를 시작하기 전에 [애플리케이션 설정](/ko/rum/applications#sdk-원격-구성)을 읽습니다 |
| `appUrl` | `site` | `getSessionReplayLink`에서 사용하는 MoleSignal 접속 URL입니다 |
| `plugins` | `[]` | `reactPlugin()` 등 SDK를 확장하는 플러그인입니다 |
| `enablePersistentQueue` | `true` | 페이지를 새로고침한 후 IndexedDB에서 전송하지 못한 텔레메트리를 복구합니다 |
| `flushInterval`, `batchSize` | `5000`, `50` | 전송 간격과 요청당 이벤트 수를 지정합니다. 배치에는 이벤트를 최대 100개까지 담습니다 |
| `maxQueueSize` | `1000` | 오프라인 상태에서 보관할 최대 이벤트 수입니다 |
| `beforeSend` | 미설정 | 이벤트를 검사, 수정 또는 삭제합니다 |
| `onError` | 미설정 | 업로드 실패나 이벤트 거부 등의 SDK 진단 정보를 받습니다 |
| `transport` | 브라우저 fetch | 자체 프록시를 통해 전송합니다 |

`beforeSend(event, { kind })`는 [이벤트 형식](/ko/rum/events)을 따르는 이벤트 객체를 받습니다. 이벤트를 삭제하려면 `false`를 반환합니다.
`view` 이벤트를 삭제하면 집계가 맞지 않으므로 삭제할 수 없습니다.

## 전송

SDK는 이벤트를 대기열에 추가해 배치로 전송하고, 서버가 수락할 때까지 IndexedDB에 저장합니다. 네트워크 오류가 발생하거나 `408`, `425`, `429`, `5xx` 응답을 받으면 지수
백오프로 요청을 재시도하며, `Retry-After`가 있으면 그 값을 따릅니다. MoleSignal이 **거부한** 이벤트는
재시도하지 않고 `onError`로 보고합니다. 그 외 `4xx` 응답을 받으면 배치를 삭제합니다. 대기열이 가득 차면 리소스부터 삭제하고, 이어서 긴
작업, 리플레이, 바이탈, 액션, 오류, 뷰 순으로 삭제합니다. 페이지를 벗어날 때는 가장 중요한 이벤트부터 하나의
`keepalive` 요청에 담아 전송합니다. 같은 애플리케이션의 탭은 대기열을 공유하며 이벤트를 중복 전송하지 않습니다.

## 0.2에서 업그레이드

- 이제 `defaultPrivacyLevel: 'allow'`는 필드에 입력한 값을 표시합니다. 단, 비밀번호, 이메일 주소, 전화번호, 카드 정보 또는
  일회용 코드 필드는 제외합니다. 이전 `allow`의 동작은 `mask-user-input`에 해당합니다. 입력값을 계속 마스킹하려면 이 값으로 변경합니다.
- 컨트롤이 아닌 요소를 클릭해도 클릭으로 보고합니다.

## 0.1에서 업그레이드

버전 0.2부터 SDK는 RUM 이벤트 형식을 사용하며 호환 모드를 지원하지 않습니다.

- 이벤트는 `POST /api/v1/rum/events`로만 전송합니다. 세션, 액션, 오류 엔드포인트는 더 이상 제공하지 않습니다. 사용자 지정 `transport`
  함수는 `kind: 'events' | 'replay'`를 받습니다.
- SDK는 세션 대신 뷰를 전송합니다. 리소스, 긴 작업, 페이지 뷰를 각각 별도 이벤트로 전송하고, 반복 클릭과 무반응 클릭은
  클릭 이벤트의 `action.frustration.type`에 기록합니다.
- `beforeSend`는 이벤트 형식을 따르는 이벤트 객체를 받으며 `context.kind`는 이벤트 유형입니다.
- 세션은 탭 간에 공유하는 쿠키에 저장하며, 기본 비활성 제한 시간은 15분입니다.
- 서버는 `User-Agent`에서 브라우저, 운영 체제, 디바이스 정보를 가져옵니다.
- 애플리케이션을 먼저 생성합니다. 이미 존재하는 애플리케이션에만 토큰을 발급합니다.
