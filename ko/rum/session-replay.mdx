세션 리플레이는 브라우저 DOM의 전체 스냅샷을 먼저 기록한 뒤, 타임스탬프와 함께 증분 변경 사항을 기록합니다.
MoleSignal은 샌드박스에서 실행되는 비대화형 플레이어에서 이 이벤트를 재구성합니다.

리플레이는 기본적으로 비활성화되어 있습니다.

## 샘플링 기반 리플레이 활성화

```ts
const rum = init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  sessionSampleRate: 100,
  sessionReplaySampleRate: 20,
  sessionReplay: {
    blockSelector: '[data-molesignal-block]',
    maskTextSelector: '[data-molesignal-mask]',
    ignoreSelector: '[data-molesignal-ignore]',
  },
});
```

`sessionReplaySampleRate`는 `sessionSampleRate`로 선택한 세션에만 적용합니다. 실제 샘플링 비율을 계산하는 방법은
[RUM 데이터 샘플링](/ko/rum/sampling)을 참조합니다.

## 수동으로 녹화 시작 또는 중지

```ts
rum.startSessionReplayRecording();

// Stop before a sensitive workflow that should never be recorded.
rum.stopSessionReplayRecording();
```

`sessionSampleRate`로 이미 선택한 세션에서만 녹화를 수동으로 시작할 수 있습니다. 녹화를 시작하면
리플레이를 재구성할 수 있도록 새 전체 DOM 스냅샷을 생성합니다.

## 녹화 이벤트

레코더는 다음 항목을 캡처합니다.

- 전체 DOM 스냅샷 및 증분 DOM 변경 사항
- 포인터 이동 및 클릭
- 스크롤 및 뷰포트 변경
- 입력값을 마스킹한 입력 필드 상호작용
- 스타일시트 상태 및 접근 가능한 인라인 스타일
- rrweb이 지원하는 미디어 상태

기본적으로 5분마다 전체 스냅샷을 기록합니다. `checkoutInterval`로 기록 간격을 30초에서
30분 사이로 설정합니다.

```ts
sessionReplay: {
  checkoutInterval: 5 * 60_000,
},
```

## 개인정보 보호 설정

기본값인 `defaultPrivacyLevel: 'mask'`는 페이지의 모든 텍스트와 입력값을 마스킹합니다. `mask-user-input`은 페이지
텍스트를 표시하고 입력값은 마스킹합니다. `allow`는 입력값도 표시하지만 비밀번호, 이메일 주소, 전화번호, 카드 정보
또는 일회용 코드 필드의 값은 마스킹합니다. 운영 환경에서 리플레이를 활성화하기 전에 차단, 마스킹, 무시 선택자를 정의합니다.

```html
<div data-molesignal-block>Payment details</div>
<span data-molesignal-mask>Customer name</span>
<canvas data-molesignal-ignore></canvas>
```

선택자의 동작과 운영 환경 검토 체크리스트는 [RUM 개인정보 보호](/ko/rum/privacy)를 참조합니다.

## 대용량 캡처 옵션

다음 옵션은 페이로드 크기와 저장 용량을 크게 늘릴 수 있으므로
기본적으로 비활성화되어 있습니다.

```ts
sessionReplay: {
  collectFonts: false,
  inlineImages: false,
  recordCrossOriginIframes: false,
},
```

교차 출처 프레임을 녹화하려면 프레임에 포함된 애플리케이션의 지원도 필요합니다. MoleSignal 플레이어는
캔버스 픽셀을 재생하지 않습니다. 캔버스를 많이 사용하는
콘텐츠에는 DOM으로 표현하거나 자리 표시자를 사용하는 것을 권장합니다.

## 전송 및 보존

리플레이는 별도의 큐를 사용하며, 기본적으로 10초마다 배치당 이벤트 100개를 전송합니다.
`replayFlushInterval`과 `replayBatchSize`로 클라이언트 동작을 조정합니다. MoleSignal은 리플레이 세그먼트를
압축하여 오브젝트 스토리지에 저장하고, 플랫폼의 기본 스트림 보존 기간이 끝나면 만료 처리합니다. 보존 기간은
**설정 → 데이터 보존**에서 설정합니다.

## 댓글

리플레이 옆 **댓글** 탭에서 특정 시점에 의견을 남길 수 있습니다. 댓글은 현재 재생 시점에
등록되며 플레이어 타임라인에 표시됩니다. 댓글 행을 클릭하면 해당 시점으로 이동합니다.

리플레이를 재생할 수 있으면 댓글도 읽을 수 있습니다. `rum.replay.comments.write` 권한으로 댓글을 작성하고 직접 작성한 댓글을 수정하거나 삭제할 수 있으며,
`rum.replay.comments.manage` 권한으로 모든 댓글을 수정하거나 삭제할 수 있습니다. 세션당 최대 500개의 댓글을 남길 수 있으며, 댓글당 최대 2,000자까지 입력할 수 있습니다.
보존 기간이 끝나면 리플레이와 함께 댓글도 삭제합니다.

## AI 요약 및 챕터

세션 페이지에서 **요약 생성**을 선택하면 모델이 세션에서 일어난 일을 몇 문장으로 요약하고, 리플레이를
제목과 시작 시점이 있는 챕터로 나눕니다. 챕터는 플레이어 타임라인에 표시되며, 클릭하면 해당
시점으로 이동합니다.

모델에는 방문한 페이지, 각 페이지에서 수행한 작업, 발생한 문제, 실패했거나 오래 걸린 요청을
시간순으로 한 줄씩 전달합니다. 리플레이 자체는 전달하지 않습니다. 애플리케이션이 [수집 시
민감한 텍스트를 제거](/ko/rum/privacy#수신-단계에서-민감한-텍스트-제거)한 뒤 열람 권한 범위 내의 텍스트만 전달합니다. 긴 세션은 방문한 페이지와 발생한 문제를 우선 전달하고,
나머지 정보는 입력 한도 내에서 전달합니다.

요청할 때만 요약을 생성합니다. 생성에는 `rum.replay.summaries.generate` 권한이 필요하며, 리플레이를 재생할 수 있으면 요약도 읽을 수 있습니다. 키를 설정한 활성
[모델 제공업체](/ko/agent#모델-공급자-설정) 중 첫 번째 제공업체의 기본 모델을 사용합니다. 사용량은 `replay_summary` 출처로 [Mole Agent의 일일
예산](/ko/agent#사용량-및-예산)에 반영합니다. 언어별로 요약을 하나씩 저장하고 리플레이가 삭제될 때까지 보관합니다. 세션에 변경 사항이 없으면 **요약 다시 생성**을 선택해도
모델을 호출하지 않습니다.

## 리플레이 검증

<Steps>
  <Step title="민감한 정보가 없는 테스트 동선 녹화">
    여러 페이지를 탐색하고 컨트롤을 클릭하고 스크롤한 뒤 DOM 업데이트를 한 번 발생시킵니다.
  </Step>
  <Step title="세션 열기">
    **RUM → 탐색기**로 이동하고 **세션**에서 `session.has_replay = true`를 쿼리한 다음 새로 녹화한 세션을 엽니다.
  </Step>
  <Step title="재구성 및 마스킹 확인">
    페이지 구조, 이벤트 타이밍, 재생 위치 조작 기능, 차단된 영역, 마스킹된 값을 확인합니다.
  </Step>
  <Step title="세션 페이지에 표시되는 내용 확인">
    MoleSignal이 유효한 전체 DOM 스냅샷을 받은 후에만 세션 페이지에 리플레이를 표시합니다. 그전에는 작업 타임라인을 표시합니다.
  </Step>
</Steps>
