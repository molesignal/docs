히트맵은 브라우저 애플리케이션의 한 페이지에서 사용자가 무엇을 하는지 보여 줍니다. **분석 → 히트맵**에서는 두 가지 히트맵을 제공합니다.

- **클릭**: 클릭 위치를 보여 줍니다. 클릭이 집중된 곳일수록 색이 강하게 표시되며, 옆에는 클릭된 요소의 목록이 표시됩니다.
- **스크롤**: 사용자가 페이지를 어디까지 내려 봤는지 보여 줍니다. 아래로 갈수록 페이지가 어두워지며, 방문의 75%, 50%, 25%가 도달한 위치를 파선으로 표시합니다.

히트맵을 사용하려면 [브라우저 SDK](/ko/rum/browser-sdk) 0.3.0 이상이 필요합니다. SDK는 클릭 위치와 각 페이지 조회에서 도달한 스크롤 깊이를 보고합니다.

창 유형에 따라 페이지 레이아웃이 달라지므로 각 히트맵은 페이지 하나와 창 유형 하나를 기준으로 표시합니다. 창 너비가 1024픽셀 이상이면 데스크톱, 600픽셀 이상 1024픽셀 미만이면 태블릿, 600픽셀 미만이면 휴대전화로 분류합니다. 모든 선택 사항을 주소에 반영하므로 현재 상태 그대로 히트맵을 공유할 수 있습니다.

## 요구 사항

히트맵은 브라우저 SDK가 수집한 데이터를 사용합니다.

| 히트맵 | 요구 사항 |
|---|---|
| 클릭 | `trackUserInteractions: true` |
| 스크롤 | 없음: `trackScroll`은 기본적으로 켜져 있습니다 |
| 히트맵 배경 페이지 | 해당 페이지를 연 세션 중 일부에서라도 [세션 리플레이](/ko/rum/session-replay)를 활성화해야 합니다 |

컨트롤이 아닌 요소의 클릭도 집계합니다. 사용자가 컨트롤이 있을 것으로 기대하는 위치를 보여 주기 때문입니다.

## 히트맵 배경 페이지

히트맵은 해당 페이지를 연 세션의 [녹화](/ko/rum/session-replay)를 배경으로 사용합니다. 페이지 로드가 완료된 시점의 화면을 페이지 전체 길이에 걸쳐 표시합니다. **녹화**에서 이 창 유형으로 해당 페이지를 녹화한 최근 세션 20개 중 하나를 선택합니다. **이 세션 열기**를 선택하면 현재 표시 중인 세션으로 이동합니다.

세션 리플레이에서 마스킹한 내용은 여기서도 마스킹합니다. 배경 페이지를 보려면 `rum.replay.read` 권한이 필요합니다. 녹화나 권한이 없어도 집계 결과는 동일합니다. 클릭 요소는 목록에서, 스크롤 깊이는 표에서 확인할 수 있습니다.

## 클릭 위치 표시 방식

클릭 데이터에는 클릭된 요소와 요소 내부의 클릭 위치가 포함됩니다. 따라서 창 크기와 관계없이 같은 요소에 클릭을 표시합니다. 녹화에서 요소를 찾을 때는 페이지 내 요소의 경로(`action.target.path`)를 사용합니다. 경로에는 태그와 위치만 포함되며 사용자가 작성한 내용은 포함되지 않습니다. 페이지가 변경되어 녹화에 요소가 없으면 실제로 클릭한 페이지상의 위치에 표시하고, 목록에는 **이 페이지 녹화에 없는 요소**라고 표시합니다.

이 필드가 추가되기 전 버전의 SDK에서 수집한 행은 선택자별로 그룹화합니다. 선택자와 일치하는 요소가 있으면 해당 요소의 중앙에 클릭을 표시합니다.

## 집계 방식

히트맵은 저장된 행을 집계합니다. 애플리케이션이 [세션의 일부만 보관하는 경우](/ko/rum/sampling), 히트맵은 클릭 위치를 보여 주지만 전체 세션의 클릭 수를 나타내지는 않습니다. [테스트에서 생성한 세션](/ko/rum/test-traffic)은 집계에서 제외합니다.

스크롤 깊이는 페이지 상단에서 창 하단까지의 거리로 측정합니다. 각 조회에서는 도달한 깊이 위의 영역도 모두 본 것으로 간주합니다. 따라서 페이지 아래로 내려갈수록 해당 깊이에 도달한 조회 비율은 높아지지 않습니다.

## Mole Agent

`get_rum_heatmap` 도구는 한 페이지에서 클릭 수가 가장 많은 요소, 페이지 전체 길이, 각 깊이에 도달한 조회 비율을 수치로 반환합니다.
