[알림 규칙](/ko/alerting)은 쿼리 대신 **RUM 지표**를 모니터링할 수 있습니다. 규칙에서 애플리케이션과 아래 지표 중 하나를 지정하고,
필요하면 환경, 페이지, 버전으로 범위를 좁힙니다. 규칙은 정해진 일정에 따라 지표 값을
임계값 또는 이전 날짜의 같은 시간대 값과 비교합니다. 스트림이나 구문은 필요하지 않습니다.

지표는 [개요](/ko/rum) 및 [탐색기](/ko/rum/explorer)와
같은 집계 방식을 사용합니다. 페이지 조회나 세션은 최신 리비전을 기준으로 한 번만 집계하고,
백분위수는 값이 있는 페이지 조회만 사용해 계산합니다. 따라서 애플리케이션, 환경, 페이지, 시간 범위가 같으면
규칙이 모니터링하는 값과 해당 페이지에 표시되는 값이 일치합니다.

## RUM 지표

| 지표 | `metric` | 설명 | 단위 | 최소 행 수 |
|---|---|---|---|---|
| **세션** | `session_count` | 집계 기간에 시작한 세션입니다. | 개수 | 없음 |
| **페이지 조회수** | `view_count` | 집계 기간에 시작한 페이지 조회 또는 앱 화면 조회입니다. | 개수 | 없음 |
| **오류** | `error_count` | 집계 기간에 발생한 오류입니다. | 개수 | 없음 |
| **오류율(오류가 발생한 페이지 조회 비율)** | `error_rate` | 전체 페이지 조회 중 오류가 발생한 페이지 조회의 비율입니다. | % | 페이지 조회 100건 |
| **충돌 없는 세션** | `crash_free_sessions` | 전체 세션 중 충돌이 발생하지 않은 세션의 비율입니다. | % | 세션 100개 |
| **사용자 불편 신호가 감지된 세션** | `frustration_rate` | 전체 세션 중 [사용자 불편 신호](/ko/rum/frustration)가 감지된 세션의 비율입니다. | % | 세션 100개 |
| **실패한 요청** | `failed_request_rate` | 전체 `fetch` 및 `xhr` 요청 중 응답을 받지 못했거나 5xx 응답을 받은 요청의 비율입니다. 4xx 응답은 실패로 집계하지 않습니다. | % | 요청 200건 |
| **LCP (p75)** | `lcp_p75` | 최대 콘텐츠 렌더링 시간의 75번째 백분위수입니다. | 밀리초 | 값이 있는 페이지 조회 50건 |
| **INP (p75)** | `inp_p75` | 상호작용부터 다음 렌더링까지 걸린 시간의 75번째 백분위수입니다. | 밀리초 | 값이 있는 페이지 조회 50건 |
| **CLS (p75)** | `cls_p75` | 누적 레이아웃 변경의 75번째 백분위수입니다. | 점수(0.1이면 양호) | 값이 있는 페이지 조회 50건 |
| **첫 바이트까지의 시간 (p75)** | `ttfb_p75` | 첫 바이트까지의 시간의 75번째 백분위수입니다. | 밀리초 | 값이 있는 페이지 조회 50건 |
| **새 이슈** | `new_issues` | 집계 기간에 처음 관측한 [이슈](/ko/rum/errors)입니다. | 개수 | 없음 |
| **재발한 이슈** | `regressed_issues` | 해결 후 집계 기간에 다시 발생한 이슈입니다. | 개수 | 없음 |
| **가장 심각한 이슈의 영향을 받은 세션** | `issue_impact` | 이슈의 종류나 최초 발생 시점과 관계없이, 집계 기간에 가장 많은 세션에 영향을 준 이슈의 영향 세션 수입니다. | 개수 | 없음 |
| **사용자 지정 소요 시간(바이탈)** | `custom_vital` | 애플리케이션이 `startDurationVital` 또는 `addDurationVital`로 측정한 소요 시간을 지정한 이름으로 집계합니다. | 밀리초 또는 개수 | 30행. **개수** 통계에는 최소 행 수가 없습니다. |
| **사용자 지정 타이밍** | `custom_timing` | 애플리케이션이 `addTiming`으로 표시한 시점까지 페이지 조회 시작부터 얼마나 걸렸는지 지정한 이름으로 집계합니다. | 밀리초 또는 개수 | 30행. **개수** 통계에는 최소 행 수가 없습니다. |
| **탐색기 쿼리** | `query` | [탐색기](/ko/rum/explorer) 쿼리와 일치하는 단일 유형의 행을 하나의 값으로 집계합니다. [탐색기 쿼리](#탐색기-쿼리)를 참조합니다. | 개수 또는 필드의 단위(소요 시간은 밀리초) | 30행. 개수나 합계에는 최소 행 수가 없습니다. |

세션이나 페이지 조회는 **시작한** 시점이 속한 집계 기간에 포함합니다. 1분 전에 시작해 아직 끝나지 않은 세션도
지금까지 수집한 데이터로 집계합니다. 따라서 집계 기간의 마지막 몇 분은 해당 세션이 모두 끝난 후보다
지표가 다소 좋게 나타납니다. 집계 기간이 길수록 이 효과는 줄어듭니다.

### 지표에 값이 없는 경우

개수는 0도 유효한 값으로 집계하므로 규칙으로 트래픽 중단을 감지할 수 있습니다. 그 외 지표는 집계 기간의 행 수가
표의 최소 행 수보다 적으면 **값이 없습니다**. 이 경우 임계값 조건을 충족하지 않아 알림을 발생시키지 않고, 열려 있는 인시던트는
해결 처리합니다. 이렇게 하면 트래픽이 적은 밤에 몇 건의 페이지 조회로 계산한 p75 때문에 알림이 발생하지 않습니다. 규칙의
**최소 행 수**에서 해당 규칙에 적용할 값을 변경합니다. 개수에는 최소 행 수를 적용하지 않습니다.

### 애플리케이션에서 측정하는 지표

사용자 지정 지표의 측정 항목을 **바이탈 이름** 또는 **타이밍 이름**으로 지정합니다. 편집기는 지난 24시간 동안
애플리케이션이 전송한 이름을 제안하며, 아직 전송하지 않은 이름도 입력할 수 있습니다. **통계**에서 측정값의 `p50`, `p75`
(기본값), `p90`, `p95`, `p99`, 평균 또는 측정 횟수를 선택합니다. 각 집계 기간에는 실제 사용자 데이터만 포함하며,
[테스트로 실행한 세션](/ko/rum/test-traffic)은 집계하지 않습니다.

### 탐색기 쿼리

[탐색기](/ko/rum/explorer#새-알림)에서 **새 알림**을 선택하면 편집기가 **탐색기 쿼리** 지표로 열립니다.
편집기에서 직접 입력할 수도 있습니다.

- **행 유형**은 쿼리할 데이터 유형입니다. 세션, 페이지 조회, 작업, 오류, 리소스, 긴 작업 또는 로그를 선택합니다.
- **쿼리**는 탐색기의 **코드** 모드와 같은 방식으로 작성합니다. 선택한 유형의 필드 비교 조건을 `AND`로 연결하고,
  텍스트 열에서 찾을 단어를 입력합니다. 해당 유형에서 처리할 수 없는 조건은 입력 필드 아래에 표시하고 쿼리에서 제외합니다. 비워 두면 해당
  유형의 모든 행과 일치합니다.
- **측정값**은 `Rows`, `Distinct values`, `Sum`, `Average`, `Minimum`, `Maximum` 또는 `p50`부터 `p99`까지의 값입니다. **필드**는
  측정에 사용할 필드입니다. 소요 시간은 밀리초 단위로 계산합니다.
- **탐색기에서 열기**를 선택하면 탐색기가 해당 쿼리의 결과를 시계열로 표시합니다.

규칙은 탐색기와 마찬가지로 실제 사용자의 행을 읽습니다. 합성 테스트나 CI에서 실행한 세션은
쿼리가 `session.type`, `synthetics.*` 또는 `ci_test.*`를 지정할 때만 집계합니다. 다른 RUM 지표와 마찬가지로,
애플리케이션이 [세션의 일부만 보관](/ko/rum/sampling)하더라도 규칙은 전체 세션을 기준으로 개수, 합계 또는 평균을 계산하지만, 탐색기는
저장한 행만 집계합니다. 일치하는 행이 없는 집계 기간에는 개수와 합계가 `0`입니다. 다른 측정값에는 규칙에서
별도로 지정하지 않는 한 30행이 필요합니다. 쿼리에서 페이지와 버전을 직접 지정하므로 규칙에는 **페이지**와 **버전** 옵션이 표시되지 않습니다.
인시던트에는 쿼리와 일치한 최신 행에 해당하는 세션이 표시됩니다.

## 규칙 범위 좁히기

| 필터 | 적용할 수 있는 지표 |
|---|---|
| **환경** | 모든 지표에 적용합니다. |
| **버전** | **새 이슈**, **재발한 이슈**, **탐색기 쿼리**를 제외한 모든 지표에 적용합니다. 이슈는 여러 버전에서 발생할 수 있으며, 탐색기 쿼리는 쿼리에서 버전을 지정합니다. |
| **페이지**(앱에서는 **화면**) | 페이지 조회, 오류, 요청, 바이탈 관련 지표에 적용합니다. 해당 지표는 **페이지 조회수**, **오류**, **오류율**, **실패한 요청**, **가장 심각한 이슈의 영향을 받은 세션**, 네 가지 바이탈, 사용자 지정 지표입니다. 세션은 한 페이지에 국한되지 않으므로 세션 단위 지표에는 적용하지 않습니다. 이슈 지표와 쿼리에서 페이지를 직접 지정하는 **탐색기 쿼리**에도 적용하지 않습니다. |

편집기는 지난 24시간 동안 애플리케이션에서 관측한 환경, 페이지, 버전을 제안합니다. 페이지는 URL 경로에서
변하는 부분을 그룹화한 값이며, 다른 RUM 페이지에서도 같은 방식으로 표시합니다. 이름은 입력한 그대로 비교하므로 `*`도 일반 문자로 처리합니다.

새 이슈와 재발한 이슈는 이슈가 **발생한 환경**을 기준으로 집계합니다. 이슈는 애플리케이션 전체에 속하며,
각 환경에서 처음 관측한 시점을 기록합니다. 지난주 스테이징에서 처음 관측한 이슈라도 프로덕션에서 처음 관측하면
프로덕션에서는 새 이슈입니다. 환경을 지정하지 않으면 애플리케이션에서 처음 관측한 시점에 새 이슈로 집계합니다.

## 규칙 생성

**알림 → 알림 규칙**을 열고 **새 규칙**을 선택합니다. **임계값 규칙**에서는 **메트릭 알림**,
**로그 알림**, **트레이스 알림**, **APM 알림**과 함께 **RUM 알림**을 선택할 수 있습니다. 애플리케이션을 선택하고, 필요에 따라 범위를 좁힌 다음, 지표와
집계 구간(5분, 15분, 1시간)을 선택합니다. 편집기는 지표에 맞는 구간(백분위수나 비율은
1시간)과 호출 알림에 일반적으로 사용하는 임계값을 기본값으로 설정합니다. 규칙을 생성하려면 `alerts.rules.manage` 권한이 필요합니다.

**규칙 테스트**는 최근 일정 기간의 지표를 구간마다 한 점씩 표시하고 임계값을 함께 표시합니다. 집계 구간이
5분 또는 15분이면 최근 6시간을, 1시간이면 최근 12시간을 표시합니다. 마지막 점은 현재 규칙이 평가할 값입니다. 구간에
데이터 행이 너무 적으면 값도 점도 표시하지 않습니다. 미리보기는 규칙을 평가하는 코드와 동일한 코드로 계산하므로
실제 규칙 동작을 그대로 보여 줍니다.

다른 지표를 선택하면 단위가 달라지므로 임계값과 집계 구간을 초기화합니다. 페이지나 버전으로 범위를 좁힐 수 없는
지표는 양식에 그 이유를 표시합니다.

`alert` 역할은 `[alert].eval_interval_secs`마다 최근 집계 구간을 기준으로 규칙을 평가합니다. 기본값은 30초입니다. `for_periods`는
임계값을 연속으로 초과한 평가 횟수를 셉니다. 분 단위 집계 구간에서 이미 지표 변동을 완화하므로 편집기는 RUM 규칙의 기본값을
1로 설정합니다. [규칙 생성](/ko/api/alerting/create-rule#규칙-평가-방식)을 참조합니다.

## 페이지에서 알림 설정

개요, 오류, 성능, 사용자 불편 페이지에서 **알림**은 페이지의 대상 범위를 표시하는 행 끝에 있습니다.
버튼 옆에는 애플리케이션에서 진행 중인 인시던트 수를 가장 심각한 인시던트의 색상으로 표시합니다. 진행 중인 인시던트가 없으면
숫자를 표시하지 않습니다. `alerts.rules.read` 권한이 있을 때만 버튼을 표시합니다.

버튼을 누르면 측면 패널이 열리고 현재 페이지의 환경에 해당하는 애플리케이션 알림을 표시합니다. 페이지에서 모든 환경을
보고 있으면 모든 환경의 알림을 표시합니다. 패널은 별도의 애플리케이션이나 환경을 선택하지 않고 현재 페이지의 범위를 따릅니다. 알림은 긴급도가 높은 순서부터
낮은 순서로 표시합니다.

- **진행 중**은 열려 있거나 확인 처리된 애플리케이션 인시던트를 심각도가 높은 순으로 나열합니다. 각 항목에는 심각도,
  관련 규칙, 호출 알림 임계값, 인시던트가 열린 시각을 표시합니다. **열기**를 누르면 현재 페이지 위에 인시던트를 엽니다.
- **이 애플리케이션의 규칙**은 현재 환경의 규칙과 모든 환경에 적용되는 규칙을 나열합니다. 발생 중인 규칙을
  먼저 표시하고 각 상태를 **발생 중**, **파이프라인에서 제외됨**, **대기 중**, **정상**, **꺼짐**으로 표시합니다. **새 규칙**은
  애플리케이션과 환경을 미리 입력한 상태로 규칙 편집기를 열고, **편집**은 기존 규칙을 엽니다. 두 작업 모두 `alerts.rules.manage` 권한이 필요합니다.
- **템플릿**은 애플리케이션에 바로 생성할 수 있는 추천 규칙을 나열합니다.

[성능 페이지](/ko/rum/performance#값의-세부-구성)에서 행의 측면 패널에 있는 **이 항목에 대한 알림 설정**을 누르면
현재 탭의 성능 지표를 선택하고 해당 행의 페이지 또는 버전으로 범위를 좁힌 상태로 규칙 편집기를 엽니다.

[탐색기](/ko/rum/explorer#새-알림)의 쿼리 표시줄에서 **새 알림**을 누르면 현재 쿼리와 첫 번째
측정값을 [탐색기 쿼리](#탐색기-쿼리)로 설정한 상태로 규칙 편집기를 엽니다.

## 템플릿

템플릿은 지표, 호출 알림 임계값, 집계 구간을 미리 설정한 규칙입니다. **생성**을 누르면 즉시 규칙을 생성하고 활성화합니다.
유형은 `scheduled`로 설정하고, 템플릿의 임계값을 심각도별로 적용합니다. `for_periods`는 1로 설정하고 기본 에스컬레이션 정책과
편집기에서 만든 규칙과 동일한 레이블을 적용합니다. 템플릿을 나타내는 `rum.template` 레이블도 추가합니다. 규칙 이름은 애플리케이션, 환경,
템플릿 이름을 조합합니다(예: `Storefront · prod · Slow page loads`). 생성 후에는 **알림 → 알림 규칙**에서 모든 설정을 변경할 수 있습니다.
규칙을 생성하려면 `alerts.rules.manage` 권한이 필요합니다. 권한이 없으면 버튼을 비활성화하고 이유를 표시합니다.

현재 페이지의 애플리케이션과 환경에 이미 적용한 템플릿은 중복 생성을 방지하기 위해 버튼 대신 **생성 및 활성화됨**과 규칙 링크를
표시합니다. 다른 환경에는 같은 템플릿으로 규칙을 다시 생성할 수 있습니다. 모든 환경에 적용되는 규칙과
단일 환경에 적용되는 규칙은 별개입니다.

각 카드는 규칙을 평가하는 코드와 동일한 코드로 템플릿의 집계 구간에 해당하는 **현재** 지표 값을 계산해 보여 줍니다.
코어 웹 바이탈은 값의 등급도 표시합니다. 템플릿으로 생성한 규칙에서 알림이 즉시 발생할 조건이면 카드에 이를 표시합니다. 지표를 계산하기에
데이터 행이 부족하면 값 대신 필요한 행 수를 표시합니다.

코어 웹 바이탈의 임계값은 web.dev의 좋음과 나쁨 등급 기준을 따릅니다.

| 템플릿 | 지표 | 임계값 | 집계 구간 |
|---|---|---|---|
| **느린 페이지 로딩**, 권장 | LCP (p75) | 2.5 s 초과 시 경고, 4 s 초과 시 심각 | 1시간 |
| **느린 상호작용**, 권장 | INP (p75) | 200 ms 초과 시 경고, 500 ms 초과 시 심각 | 1시간 |
| **페이지 오류**, 권장 | 오류율 | 2% 초과 시 경고, 5% 초과 시 심각 | 15분 |
| **실패한 요청**, 권장 | 실패한 요청 | 2% 초과 시 경고, 5% 초과 시 심각 | 15분 |
| **새 이슈**, 권장 | 새 이슈 | 0 초과 시 경고 | 15분 |
| **레이아웃 이동** | CLS (p75) | 0.1 초과 시 경고, 0.25 초과 시 심각 | 1시간 |
| **사용자 불편 세션** | 사용자 불편이 감지된 세션 | 3% 초과 시 경고, 8% 초과 시 심각 | 1시간 |
| **재발한 이슈** | 재발한 이슈 | 0 초과 시 심각 | 15분 |
| **영향이 가장 큰 이슈** | 영향이 가장 큰 이슈의 영향을 받은 세션 | 20 초과 시 경고, 100 초과 시 심각 | 1시간 |
| **트래픽 중단**, 선택 사항 | 세션 | 1 미만 시 심각 | 15분 |

앱에는 템플릿이 8개 있으며, 코어 웹 바이탈 대신 충돌 지표를 사용합니다. **화면 오류**는 화면의 오류율입니다.

|---|---|---|---|
| **충돌 증가**, 권장 | 충돌 없는 세션 비율 | 99.5% 미만 시 경고, 99% 미만 시 심각 | 1시간 |
| **화면 오류**, 권장 | 오류율 | 2% 초과 시 경고, 5% 초과 시 심각 | 15분 |

## 이상 탐지 규칙

**이상 탐지 규칙**에서는 **RUM 지표**를 소스로 선택할 수 있습니다. 최근 집계 구간의 지표를 이전 각 날짜의 동일한 시간대 구간과
비교하며, [다른 이상 탐지 규칙](/ko/alerting)과 동일한 기준선과 설정을 사용합니다. 일반적인 수준을 정하기 어려운
**새 이슈**와 **재발한 이슈**를 제외한 모든 지표를 선택할 수 있습니다.

## 인시던트

편집기에서 만든 규칙에는 필터 범위에 따라 `rum.application`, `deployment.environment`, `rum.page`, `rum.version` 라벨을 붙이며,
규칙에서 발생한 인시던트에도 이 라벨을 복사합니다. 인시던트가 열리면 지표 값이 가장 나빴던 **샘플 세션**을
최대 3개 저장합니다. 각 샘플에는 세션 ID, 발생 시각, 해당 세션의 지표 값과 관련 정보가 포함됩니다. 관련 정보에는
바이탈 값이 가장 나빴던 뷰와 그 원인이 된 요소, 최신 오류와 오류 메시지, 비정상 종료나 불편 신호가 나타난
세션, 실패한 요청과 해당 경로가 포함됩니다. 신규 이슈와 재발 이슈의 경우 각 이슈에서
가장 최근에 발생한 오류의 세션을 샘플로 저장합니다. 트래픽 지표에는 샘플이 없습니다.

**진행 중**, **알림 → 인시던트** 또는 링크에서 인시던트 패널을 열면 **샘플 세션**에
발생 시각, 방문자 식별 정보(이름, 주소, ID 또는 로그인한 적이 없는 방문자의 SDK 저장 ID), 브라우저와
운영체제, 샘플로 선정된 이유가 표시됩니다. 세션을 녹화한 경우 **리플레이**는 해당 시점 5초 전부터 재생하고, **세션**은
녹화하지 않은 세션의 상세 페이지를 엽니다. 방문자 식별 정보와 녹화 여부는 세션에서 가져오며, 이를 조회하려면
`rum.sessions.read` 권한이 필요합니다. 이 권한이 없어도 각 행에 발생 시각과 선정 이유가 표시됩니다.

**RUM에서 열기**를 선택하면 동일한 애플리케이션, 환경, 페이지의 지표를 인시던트 기간에 걸쳐 보여 주는 페이지로 이동합니다.
표시 범위는 규칙의 평가 구간이 시작되기 직전부터 인시던트가 해결된 직후까지입니다. 인시던트가 진행 중이면 현재 시점까지 표시합니다.

| 지표 | 열리는 페이지 |
|---|---|
| 바이탈 | [성능](/ko/rum/performance)에서 해당 바이탈을 엽니다. 규칙에 페이지가 지정되어 있으면 해당 페이지의 패널에서 엽니다. |
| 실패한 요청 | [리소스](/ko/rum/performance#리소스) |
| 오류, 오류율, 신규 및 재발 이슈, 비정상 종료가 없는 세션 | [오류](/ko/rum/errors) |
| 불편 신호가 있는 세션 | [사용자 불편](/ko/rum/frustration) |
| 탐색기 쿼리 | [탐색기](/ko/rum/explorer)에서 규칙의 애플리케이션 및 환경에 해당 쿼리를 적용하고 결과를 시계열로 표시합니다. |
| 세션, 페이지 조회 | [개요](/ko/rum) |

## API에서 규칙 구성

RUM 지표 규칙에는 `query`의 쿼리문과 스트림 대신 `query.rum`을 사용합니다. 이 필드로 [규칙을
생성합니다](/ko/api/alerting/create-rule).

```json
{
  "name": "Storefront checkout is slow",
  "kind": "scheduled",
  "query": {
    "language": "sql",
    "statement": "",
    "periodSecs": 3600,
    "rum": {
      "applicationId": "storefront",
      "environment": "prod",
      "page": "/checkout",
      "metric": "lcp_p75"
    }
  },
  "trigger": { "operator": "gt", "threshold": 2500, "forPeriods": 1, "silenceSecs": 300 },
  "thresholds": [
    { "severity": "warning", "operator": "gt", "threshold": 2500, "forPeriods": 1 },
    { "severity": "critical", "operator": "gt", "threshold": 4000, "forPeriods": 1 }
  ],
  "labels": { "rum.application": "storefront", "deployment.environment": "prod", "rum.page": "/checkout" },
  "annotations": {}
}
```

`periodSecs`는 60초에서 6시간 사이의 평가 구간입니다. 애플리케이션이 존재해야 하며,
`page`와 `version`을 지원하지 않는 지표에는 해당 필드를 지정할 수 없습니다. `minSamples`는 선택 사항이며 개수 지표에는 지정할 수 없습니다. 임계값은 지표와 같은 단위를 사용합니다.
사용자 지정 지표에는 필수 필드인 `custom_name`과 `statistic`도 사용합니다. `statistic`에는 `p50`, `p75`, `p90`, `p95`, `p99`, `avg`, `count` 중 하나를 지정하며,
기본값은 `p75`입니다. 다른 지표에는 두 필드 모두 지정할 수 없습니다.

RUM 페이지는 `rum.application` 라벨로 애플리케이션의 인시던트를 찾고, 특정 환경의 페이지에서는
`deployment.environment` 라벨도 사용합니다. 애플리케이션의 규칙은 `query.rum`으로 찾습니다. API로 만든 규칙에는 지정한 라벨이 붙으므로,
RUM 페이지의 인시던트 집계와 목록에 포함하려면 이 라벨을 지정합니다. 템플릿에서 만든 규칙에는 `rum.template` 라벨을 추가합니다.
템플릿 카드는 이 라벨로 해당 템플릿에서 규칙을 만들었는지 확인합니다.

**규칙 테스트**는 `POST /api/v1/rum/alerts/preview`를 호출합니다. [RUM API](/ko/api/rum#알림-규칙-미리보기)를 참조합니다.

## 권한

- `alerts.rules.read` 권한이 있으면 RUM 페이지에서 **알림**을 볼 수 있고, 알림 패널에서 인시던트, 규칙, 템플릿을 확인할 수 있습니다.
- `alerts.rules.manage` 권한이 있으면 템플릿, **새 규칙** 또는 규칙 편집기에서 규칙을 만들고 기존 규칙에서 **편집**을 열 수 있습니다.
- `rum.events.read` 권한이 있으면 미리보기와 템플릿에 표시되는 현재 지표 값을 확인할 수 있으며, `rum.sessions.read`
  권한이 있으면 인시던트의 샘플 세션에서 방문자 식별 정보를 확인할 수 있습니다.

[RUM](/ko/rum#권한)을 참조합니다.
