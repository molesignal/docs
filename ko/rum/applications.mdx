애플리케이션은 RUM 이벤트를 전송하는 웹사이트 또는 앱입니다. SDK가 데이터를 전송하기 전에 애플리케이션을 만듭니다.
클라이언트 토큰은 하나의 애플리케이션에 연결되며, MoleSignal은 존재하지 않는 애플리케이션의
이벤트를 거부합니다.

**RUM → 애플리케이션**을 열면 워크스페이스의 애플리케이션 목록을 확인할 수 있습니다. 애플리케이션에는 클라이언트 토큰이 포함되므로
애플리케이션을 만들거나 변경하거나 삭제하려면 `rum.applications.manage` 권한이 필요합니다.
목록을 조회하려면 `rum.applications.read` 권한이 필요합니다.

## 애플리케이션 만들기

<Steps>
  <Step title="양식 열기">
    **애플리케이션 만들기**를 클릭합니다. 애플리케이션이 없는 워크스페이스에서는
    탐색기에도 같은 버튼이 표시됩니다.
  </Step>
  <Step title="애플리케이션 이름 지정">
    다른 애플리케이션에서 사용하지 않는 **이름**을 128자 이내로 입력합니다(예: `Checkout web`). 그런 다음 **플랫폼**을 선택합니다.
    브라우저, Android, iOS, Flutter, React Native, 기타 중에서 선택합니다. 플랫폼 설정은 표시할 설정 코드
    스니펫만 결정합니다. 이벤트를 전송한 주체는 이벤트의 `source`에 표시됩니다.
  </Step>
  <Step title="식별자 지정">
    **식별자**는 SDK의 `applicationId`에 설정하는 값입니다. 비워 두면
    이름을 바탕으로 자동 생성합니다(예: `checkout-web`). 직접 입력하려면 `A-Z`, `a-z`, `0-9`,
    `.`, `_`, `:`, `-`를 사용해 64자 이내로 지정합니다. 애플리케이션을 만든 후에는 식별자를 변경할 수 없습니다.
  </Step>
  <Step title="만들기 클릭">
    애플리케이션이 열리고 클라이언트 토큰이 표시됩니다.
  </Step>
</Steps>

애플리케이션을 만들 때 워크스페이스에 RUM 스트림이 없으면 7개의 RUM 스트림도 함께 만듭니다.

## 클라이언트 토큰

애플리케이션을 열어 **클라이언트 토큰**을 확인합니다. 토큰은 `mspat-<36>` 형식이며 만료되지 않습니다.
이 애플리케이션에 대한 `rum.write` 권한만 부여합니다. 토큰은 마스킹되어 표시됩니다. **토큰 표시** 또는 **토큰 복사**를 선택합니다.

<Warning>
  토큰은 브라우저 및 모바일 코드에 포함되므로 사용자가 읽을 수 있습니다. 클라이언트 코드에는 이 토큰만 사용하고,
  소유자, 관리자 또는 개인 토큰은 사용하지 않습니다. 애플리케이션을 삭제하면 토큰도 폐기됩니다.
</Warning>

[API](/ko/api/auth/rum-token)에서도 같은 토큰을 가져올 수 있습니다. 애플리케이션에서 **설정 가이드 열기**를 선택하면
해당 애플리케이션이 선택된 상태로 플랫폼의 **데이터 소스** 가이드가 열립니다. 가이드에서는 엔드포인트, 토큰,
식별자가 입력된 SDK 스니펫을 확인하고 데이터가 들어오는지 확인할 수 있습니다. React Native와 기타 플랫폼에는 가이드가 없습니다.
토큰을 사용해 [이벤트](/ko/rum/events)를 직접 전송합니다.

## 수집

애플리케이션 설정에 따라 각 이벤트와 함께 저장할 항목이 달라집니다. 애플리케이션에서 설정을 변경하고 **저장**을 클릭합니다.

| 설정 | 기본값 | 효과 |
|---|---|---|
| **IP 주소 저장** | 켜짐 | 서버가 확인한 클라이언트 주소를 `network.client.ip`로 저장합니다. 프록시를 사용하는 경우 먼저 [클라이언트 IP 인식](/ko/rum#프록시-뒤의-클라이언트-ip)을 설정합니다. |
| **위치 정보 보관** | 켜짐 | IP 주소를 바탕으로 조회한 국가, 지역, 도시를 저장합니다. IP 주소를 저장하지 않는 경우에도 위치를 조회하고 조회 결과만 저장합니다. |
| **기본 개인정보 보호 수준** | 텍스트 및 입력값 마스킹 | 설정 스니펫에서 세션 리플레이에 권장하는 개인정보 보호 수준입니다. **텍스트 및 입력값 마스킹**, **사용자 입력 마스킹**, **화면에 표시되는 모든 내용 기록** 중 하나입니다. |

설정 변경은 이후에 들어오는 이벤트부터 적용합니다. 이미 저장한 데이터는 변경하지 않습니다.

## SDK 원격 구성

`remoteConfiguration: true`로 시작하는 SDK는 시작 시 이 설정을 읽습니다. 따라서 페이지를 새로 배포하지 않아도 설정을 변경할 수 있습니다.
**페이지 설정 따름**으로 둔 항목에는 페이지에서 `init`에 전달한 값을 사용합니다.

| 설정 | SDK 옵션 |
|---|---|
| **세션 샘플링 비율(%)** | `sessionSampleRate` |
| **세션 리플레이 샘플링 비율(%)** | `sessionReplaySampleRate` |
| **개인정보 보호 수준** | `defaultPrivacyLevel` |
| **클릭 수집** | `trackUserInteractions` |
| **콘솔 출력 전달** | `forwardConsoleLogs` |

SDK는 클라이언트 토큰을 사용해 `GET /api/v1/rum/config`에서 설정을 조회하고 최대 1.5초 동안 기다립니다. 응답이 오지 않으면 페이지에서 전달한 설정으로 시작합니다.

## 세그먼트

**세그먼트**에서는 [분석 페이지](/ko/rum/analytics#세그먼트)의 조회 범위를 좁히는 데 사용할 세션 그룹을 최대 20개까지 정의할 수 있습니다. 세그먼트에는 최대 5개의
조건을 지정할 수 있으며, 세션은 모든 조건을 충족해야 합니다. 조건에 사용할 수 있는 항목은 국가, 대륙, 도시, 브라우저, 운영체제, 기기
유형, 사용자 ID, 이메일, 계정 ID, 서비스, 버전, 플랫폼, 애플리케이션에서 `setUser`로 설정한 사용자 속성
(`usr.extra.plan`)입니다. 각 조건에는 지정한 값 중 하나와 일치하거나 어떤 값과도 일치하지 않도록 설정할 수 있습니다. 변경 사항은 조회 결과에 즉시 반영되며,
이미 저장한 세션에도 적용됩니다. 사용자 속성은 이 기능을 배포한 이후에 시작한 세션에만 포함됩니다.

## 민감 데이터 및 세션 보관

**민감 데이터**에서는 서버가 이벤트를 저장하기 전에 제거할 텍스트 유형을 개별적으로 설정할 수 있습니다. 유형에는 토큰, 키,
비밀번호, 이메일 주소, 전화번호, 결제 카드 번호, 신원 식별 번호, 민감한 URL 매개변수 값이 포함됩니다.
기본적으로 모든 항목이 켜져 있습니다. 각 항목에서 제거하는 데이터는 [RUM 개인정보 보호](/ko/rum/privacy#수신-단계에서-민감한-텍스트-제거)를 참조합니다.

**세션 보관**에서는 애플리케이션이 저장할 세션을 지정합니다. **세션 보관 비율 (%)**에 `0`부터 `100`까지의 정수를 입력하면
수신한 세션 중 해당 비율만큼 보관합니다. 세션은 리플레이를 포함해 통째로 보관하거나 제외합니다.
**필터 추가**를 사용하면 환경, 버전, 국가, 브라우저 등을 기준으로 특정 세션에 별도의 보관 비율을 지정할 수 있습니다. 세션과 일치하는 첫 번째
필터가 보관 비율을 결정합니다. 나머지 세션에는 **나머지 세션 보존 비율(%)**을 적용합니다. **모든
오류 보관**을 켜면 보관하지 않는 세션의 오류도 저장합니다. 합계를 표시하는 페이지에서는 보관한 세션의 집계값을 전체
세션 기준으로 환산하고 **추정치**라고 표시합니다. [RUM 데이터 샘플링](/ko/rum/sampling#서버에서-세션의-일부-보관)을 참조합니다.

## 이슈

**이슈** 섹션에서는 애플리케이션이 한 시간에 생성할 수 있는 새 [이슈](/ko/rum/errors#시간당-새-이슈-한도) 수를 설정합니다.

| 설정 | 기본값 | 효과 |
|---|---|---|
| **시간당 새 이슈 한도** | 100 | 1~10,000 사이로 설정합니다. 한도에 도달하면 해당 시간이 끝날 때까지 기존 이슈에 속하지 않는 오류를 **기타 오류**라는 하나의 이슈로 집계합니다. 변경 사항은 30초 이내에 적용됩니다. |

## 애플리케이션 삭제

**애플리케이션 삭제**를 클릭하고 확인합니다. 클라이언트 토큰은 즉시 무효화되며, MoleSignal은 해당 토큰을 사용하는 SDK의 요청을 거부합니다.
애플리케이션에서 이미 전송한 이벤트는 보존 기간이 끝날 때까지 스트림에 남아 있으며,
탐색기에서 검색할 수 있습니다.
