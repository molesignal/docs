**RUM → 분석**에서는 세션 중에 사용자가 수행한 동작을 분석합니다. 한 번에 애플리케이션 하나를 대상으로, 특정 환경 또는 모든
환경에서 현재 선택한 시간 범위의 데이터를 분석합니다. 시간 범위를 지정하지 않고 페이지를 열면 최근 7일을 기준으로 분석합니다. **퍼널**,
**경로**, **리텐션**의 세 가지 뷰를 제공합니다. 각 뷰는 브라우저 애플리케이션과 앱을 모두 지원합니다. 용어를 구분할 때는 앱에서
페이지 대신 화면이라고 합니다. 네 번째 뷰인 [**히트맵**](/ko/rum/heatmaps)은 브라우저 애플리케이션의 페이지 하나를 분석합니다.

각 뷰의 분석 조건은 모두 URL에 포함되므로, 링크를 공유해 같은 분석을 열 수 있습니다.

## 퍼널

퍼널은 일련의 단계를 순서대로 완료한 세션을 집계합니다. 결제와 같은 흐름에서 사용자가 어느 단계에서
이탈하는지 확인할 수 있습니다.

### 단계

퍼널에는 2~8개의 단계가 있습니다. **단계 추가**를 클릭해 단계를 추가하고, 단계 끝의 X를 클릭해 삭제합니다. 단계는 두 가지 유형으로 나뉩니다.

| 유형 | 설명 | 조회할 수 있는 필드 |
|---|---|---|
| **페이지**(앱에서는 **화면**) | 세션에서 연 페이지 또는 화면입니다. | **페이지 그룹**(`view.url_path_group`, ID처럼 값이 달라지는 부분을 그룹화한 경로), **정확한 경로**(`view.url_path`), **뷰 이름**(`view.name`). 브라우저 페이지의 기본 필드는 페이지 그룹이고, 앱 화면의 기본 필드는 뷰 이름입니다. |
| **동작** | 클릭, 탭, 사용자 지정 동작 등 사용자가 수행한 동작입니다. | **대상 이름**(`action.target.name`), **대상 선택자**(`action.target.selector`), **유형**(`action.type`). |

각 단계는 지정한 필드에서 값을 찾습니다. 시간 범위 내 데이터에서 자주 나타나는 값 중 하나를 선택하거나 직접
입력합니다. **일치**는 전체 값이 일치하는지 확인하며, `*`는 임의의 문자열을 나타냅니다. **포함**은 대소문자를 구분하지 않고 지정한
문자열을 포함하는 값을 찾습니다.

### 세션 집계 방식

첫 단계는 해당 조건을 충족하는 첫 번째 행을 기준으로 세션을 집계합니다. 이후 각 단계는 같은 세션에서 이전 단계의 행보다
나중에 나타나면서 해당 단계의 조건을 충족하는 첫 번째 행을 기준으로 집계합니다. 두 단계 사이에 다른 페이지를 열거나 동작을 수행해도
집계에 영향을 주지 않습니다. 예를 들어 장바구니와 결제 사이에 다른 페이지를 다섯 개 열어도 단계를 완료한 것으로 집계합니다.

- **시간 제한**을 설정하면 첫 단계부터 지정한 시간 안에 도달한 단계에만 세션을 집계합니다. 5분, 30분,
  1시간 또는 1일을 선택할 수 있습니다. **시간 제한 없음**은 소요 시간과 관계없이 세션을 집계합니다.
- **세션 집계 기준**은 첫 단계 집계에 사용한 행에서 선택한 필드의 값별로 퍼널을 표시합니다.
  브라우저, 시스템, 기기 유형, 버전 또는 국가를 기준으로 나눕니다. 세션 수가 가장 많은 값 10개를 표시합니다.
  **모든 세션 통합**은 퍼널 하나를 표시합니다.

### 결과 읽기

단계마다 행을 하나씩 표시하며, 막대 길이는 첫 단계의 세션 수 대비 해당 단계의 세션 수 비율을 나타냅니다.

| 열 | 의미 |
|---|---|
| **세션** | 해당 단계를 완료한 세션입니다. |
| **첫 단계 대비 전환율** | 첫 단계의 세션 중 해당 단계까지 도달한 세션의 비율입니다. |
| **이탈률** | 이전 단계의 세션 중 해당 단계에 도달하지 못한 세션의 비율입니다. 절반을 넘으면 빨간색으로 표시합니다. |
| **소요 시간 중앙값** | 이전 단계에서 해당 단계까지 걸린 시간의 중앙값입니다. |

필드별로 집계한 퍼널에는 값마다 행을 하나씩 표시하는 표가 추가됩니다. 각 행에는 단계별 세션 수와 그 옆에
이전 단계 대비 전환율을 표시합니다. **첫 단계부터 마지막 단계까지**는 첫 단계의 세션 중 모든 단계를 완료한 세션의 비율입니다.

첫 단계를 완료한 세션이 없으면 퍼널에 그 사실을 표시하고 시간 범위를 넓히도록 안내합니다. 단계, 시간 제한, 집계 필드는
URL의 `steps`, `win`, `by`에 각각 들어갑니다. 각 단계는 페이지의 `v:` 또는 동작의 `a:`로 시작한 뒤, 필드, 일치를 뜻하는 `=` 또는
포함을 뜻하는 `~`, URL 인코딩한 값을 차례로 붙여 작성합니다. 단계 사이는 `|`로 구분합니다.

## 경로

경로는 각 세션에서 연 페이지를 추적합니다. 각 열에는 세션 수가 가장 많은 페이지를 표시하고, 두 페이지 사이를 연결하는 띠의
두께로 한 페이지에서 다른 페이지로 이동한 세션 수를 나타냅니다.

- **기준 페이지 이후**는 다음에 연 페이지를, **기준 페이지 이전**은 그 전에 연 페이지를 추적합니다. 기준 페이지를 지정하지 않으면
  정방향 경로는 각 세션의 첫 페이지에서 시작하고, 역방향 경로는 마지막 페이지를 기준으로 거슬러 올라갑니다.
- 데이터에 자주 나타나는 페이지 중 하나를 선택하거나 직접 입력합니다. **지우기**를 클릭하면 선택을 해제합니다. 차트에서
  페이지를 클릭하면 해당 페이지를 기준으로 경로를 표시합니다.
- **페이지 수**는 기준 페이지 이후(또는 이전)에 표시할 페이지 수입니다. 1~6개를 선택할 수 있으며, 기본값은 3개입니다.
- **페이지 구분 기준**은 페이지 그룹, 정확한 경로 또는 뷰 이름(브라우저 애플리케이션)을 사용해 페이지를 구분합니다.

페이지의 높이는 해당 페이지를 연 세션 수에 비례합니다. 각 열에는 세션 수가 가장 많은 페이지 8개의 이름을 표시하고, 나머지는
**기타 페이지**로 묶습니다. 새로고침처럼 같은 페이지를 연달아 열면 한 번만 집계합니다. 기준 페이지는 첫 번째 열에 표시하고,
역방향에서는 마지막 열에 표시합니다. 도달한 세션이 없는 열은 표시하지 않습니다. 툴팁에는 해당 페이지에서 더 이상 이동하지 않은 세션 수(역방향에서는
해당 페이지에서 시작한 세션 수)를 표시합니다.

기준 페이지, 방향, 페이지 수, 페이지 구분 필드는 URL의 `pivot`, `dir`(`before`), `depth`, `page`에
각각 들어갑니다.

## 리텐션

리텐션은 재방문한 사용자를 집계합니다. 시간 범위 내 같은 날 또는 같은 주에 처음 방문한 사용자를 하나의 코호트로 묶습니다. 각 셀에는
해당 기간 수가 지난 뒤 다시 방문한 코호트 구성원의 비율을 표시합니다.

- 먼저 **일** 또는 **주**를 선택합니다. UTC 기준으로 일과 주를 구분하며, 주는 월요일에 시작합니다. 코호트 이름에는
  문서를 보는 위치의 시간대와 관계없이 코호트 시작 날짜를 사용합니다.
- 다음으로 추적할 기간 수를 선택합니다. **7일 후**, **14일 후**, **30일 후** 중에서 선택할 수 있으며, 주간 코호트는
  주 단위로 선택합니다.
- 세션의 사용자 ID로 사용자를 구분합니다. 사용자 ID가 없는 방문자는 SDK가 기기에 보관하는 익명 ID로 구분합니다.
- 선택한 시간 범위 안에서 처음 방문한 시점을 기준으로 삼으므로, 해당 범위의 기록만 조회합니다. 범위 시작 전에 방문한 사용자도
  범위 안에서 처음 방문한 날에 신규 사용자로 집계합니다.
- 시간 범위가 끝나는 시점까지 완료되지 않은 기간은 집계하지 않으며, 해당 셀에는 대시를 표시합니다.
- **평균**은 해당 기간의 집계가 가능한 코호트의 전체 사용자를 기준으로 재방문 비율을 계산합니다. 따라서 규모가 큰 코호트의 비중이 더 큽니다.

기간 단위와 기간 수는 URL의 `period`와 `periods`에 각각 들어갑니다.

## 세그먼트

세그먼트는 특정 요금제의 고객이나 특정 국가의 방문자처럼 지정한 세션 그룹으로 모든 뷰의 범위를 좁힙니다. 페이지 상단의 **세그먼트**에서
하나를 선택합니다. 선택한 값은 URL의 `segment`에 포함되므로 세그먼트를 적용한 분석도 링크로 공유할 수 있습니다. 탭의 모든 뷰와
각 뷰에서 선택할 수 있는 페이지 및 값에도 세그먼트를 적용합니다.

애플리케이션의 [설정](/ko/rum/applications#세그먼트)에서 세그먼트를 정의합니다. 세그먼트는 세션이 지속되는 동안 바뀌지 않고
모든 행에 기록되는 정보로 세션을 구분합니다. 여기에는 사용자와 접속 위치가 포함됩니다. 세션 중에 수행한 동작으로는 세션을 구분하지 않습니다.

## 집계 방식

RUM의 다른 쿼리를 처리하는 엔진이 뷰, 세션, 액션을 대상으로 단일 쿼리를 실행해 각 뷰를 집계합니다.
뷰의 수치가 바뀔 때마다 새 버전을 기록합니다. 뷰에서 사용자 정보를 조회할 때는
최신 버전을 사용합니다. 페이지, 애플리케이션, 환경,
릴리스, 브라우저처럼 뷰의 모든 버전에서 값이 같은 항목만 조회하는 단계에서는 기록된 뷰를 그대로 읽어 최신 버전을 고르는 작업을 생략합니다.
뷰의 수치(오류, 바이탈 지표)나 사용자 정보를 조회하는 단계에서는 최신 버전을 사용합니다. 엔진에서 마스킹한 정보는
계속 마스킹된 상태로 표시합니다. 집계가 제한 시간을 넘으면 페이지를 그대로 유지하면서 시간 초과를 알립니다. 시간 범위를 좁혀
다시 조회합니다. API에서도 [`/api/v1/rum/analytics`](/ko/api/rum#퍼널-경로-및-리텐션)를 통해 같은 내용을 조회할 수 있습니다.

성능 예시: CPU 코어가 10개인 단일 노드에서 조회 범위에 세션 100만 개(이벤트 1,800만 개)가 있을 때, 4페이지 퍼널은
약 2초, 8페이지 퍼널은 약 5초, 경로는 약 6초, 리텐션은 약 1.5초가 걸렸습니다. 처리 비용은
범위 내 세션 수가 많을수록 늘어나며, 퍼널의 경우 단계 수가 많을수록 늘어납니다.

애플리케이션이 [세션의 일부만 보존하는 경우](/ko/rum/sampling), 퍼널과 경로는 각 세션에 보존 비율의 역수를 가중치로 적용해
전체 세션의 집계값을 추정합니다. 페이지에는 **추정치**라고 표시합니다. 리텐션은
보존된 세션에 나타난 사용자만 집계합니다. 샘플링을 적용하면 코호트에는 해당 세션의 사용자만 포함되며,
자주 방문하는 사용자일수록 코호트에 포함될 가능성이 높습니다.

이 페이지를 사용하려면 `rum.analytics.read` 권한이 필요합니다. [RUM](/ko/rum#권한)을 참조합니다.

## Mole Agent

Mole Agent는 `get_rum_funnel`, `get_rum_paths`, `get_rum_retention`을 사용해 동일한 내용을 조회합니다. 기본 제공 스킬인
`/rum-triage`는 사용자 흐름에 문제가 있을 때 이 도구를 사용하고, 이 페이지로 연결되는 링크로 퍼널 또는 경로를 인용합니다.
