MoleSignal Flutter 앱 RUM SDK는 브라우저 RUM SDK와 동일한 [이벤트 형식](/ko/rum/events)으로
모바일 텔레메트리를 전송합니다. Flutter 네이티브 계측은 브라우저 전용 메트릭을 생성하지 않고도 동일한 조사 워크플로를 유지합니다.

## 기능 대응

| 브라우저 기능 | Flutter 앱 SDK의 대응 기능 |
|---|---|
| 탐색 기록 기반 뷰 | `RumNavigationObserver` 또는 `startView`를 사용하며, 각 뷰는 변경될 때마다 다시 보고합니다 |
| 클릭 | `RumApp`으로 탭을 자동 수집하거나 이름을 지정한 `RumUserAction` 위젯을 사용합니다 |
| 분노 클릭 및 오류 클릭 | 탭 작업에 `rage_tap` 및 `error_tap` 불편 신호를 기록합니다 |
| 런타임 및 프로미스 오류 | `FlutterError`, `PlatformDispatcher.onError`(비정상 종료), `addError` 및 실패한 요청 |
| Fetch 및 XHR 리소스 | `MoleSignalHttpClient`, `startResource`와 `stopResource` 또는 `addResource` |
| 장기 작업 | 느린 프레임 및 `is_frozen_frame`으로 표시한 정지 프레임 |
| Web Vitals | 콜드 스타트 바이탈인 `app_launch`, 첫 빌드 완료, 뷰의 프레임 및 메모리 메트릭, 사용자 지정 소요 시간 바이탈 |
| rrweb DOM 리플레이 | 개인정보 보호 처리를 거친 스크린샷을 rrweb 스냅샷과 변경 사항으로 인코딩합니다 |
| W3C 트레이스 상관관계 | 요청, 응답 또는 `Server-Timing`의 `traceparent`를 `resource.trace_id`와 `resource.span_id`에 기록합니다 |

Flutter 애플리케이션의 경우 SDK는 LCP, CLS 등 브라우저 전용 메트릭을 생성하지 않습니다. Flutter는 빌드, 래스터화,
새로 고침 빈도, 느린 프레임, 정지 프레임 및 메모리 데이터를 보고합니다.

## 요구 사항

- Flutter 3.35 이상
- Dart 3.9 이상
- 기본 영구 식별자 저장소를 사용하는 경우 Android 24 이상 또는 iOS 13 이상

이 패키지는 종속 패키지인 `device_info_plus`,
`battery_plus`, `connectivity_plus`를 사용해 디바이스 브랜드, 모델, 운영 체제 버전, 배터리 잔량 및 연결 상태를 읽습니다. Flutter 자체에서
제공하는 정보만 전송하려면 `trackDeviceInfo: false`를 설정합니다.

## 설치 및 초기화

<Warning>
  `clientToken`은 애플리케이션에 포함해 배포하므로 공개 정보로 취급해야 합니다.
  [RUM 애플리케이션](/ko/rum/applications#클라이언트-토큰)에 연결된 클라이언트 토큰을 사용합니다.
</Warning>

<Steps>
  <Step title="애플리케이션 만들기">
    **RUM → 애플리케이션**을 열고 **애플리케이션 만들기**를 클릭한 다음 **Flutter** 플랫폼을 선택합니다. **설정
    가이드 열기**를 클릭하면 엔드포인트, 토큰, 식별자가 입력된 구성을 확인할 수 있습니다.
  </Step>
  <Step title="패키지 추가하기">
    ```yaml
    dependencies:
      molesignal_flutter: ^0.3.0
    ```

    `pubspec.yaml`을 업데이트한 후 `flutter pub get`을 실행합니다.
  </Step>
  <Step title="runApp 실행 전에 초기화하기">
    ```dart
    import 'package:flutter/material.dart';
    import 'package:molesignal_flutter/molesignal_flutter.dart';

    Future<void> main() async {
      WidgetsFlutterBinding.ensureInitialized();

      final rum = await initRum(
        const RumConfiguration(
          applicationId: 'checkout-mobile',
          clientToken: 'mspat-your-client-token',
          site: 'https://molesignal.example.com',
          service: 'checkout-app',
          env: 'production',
          version: String.fromEnvironment('MOLESIGNAL_VERSION'),
          architecture: String.fromEnvironment('MOLESIGNAL_ARCHITECTURE'),
          debugId: String.fromEnvironment('MOLESIGNAL_DEBUG_ID'),
          sessionSampleRate: 100,
          sessionReplaySampleRate: 20,
          trackUserInteractions: true,
        ),
      );

      runApp(
        RumApp(
          client: rum,
          child: MaterialApp(
            navigatorObservers: <NavigatorObserver>[
              RumNavigationObserver(rum),
            ],
            routes: <String, WidgetBuilder>{
              '/': (_) => const HomePage(),
              '/checkout': (_) => const CheckoutPage(),
            },
          ),
        ),
      );
    }
    ```

    `initRum`을 최대한 일찍 호출합니다. SDK는 이 호출부터 첫 프레임까지의 시간을 콜드 스타트 시간으로 측정합니다. `RumApp`은
    리플레이 경계를 설정하고 자동 탭 수집 및 불편 신호 감지를 활성화합니다. `sessionReplaySampleRate`에 따라 현재 세션을
    샘플링하거나 수동으로 녹화를 시작하지 않으면 리플레이는 비활성 상태로 유지됩니다.
  </Step>
  <Step title="첫 번째 세션 확인하기">
    **RUM → 탐색기**를 열고 현재 시각이 포함된 시간 범위를 선택한 다음
    `checkout-mobile`의 세션이 표시되는지 확인합니다. 해당 세션을 열어 뷰와 디바이스 컨텍스트를 확인합니다.
  </Step>
</Steps>

`site`에는 MoleSignal 오리진 또는 `/api`, `/api/v1`, `/api/v1/rum`으로 끝나는 기본 URL을 지정할 수 있습니다. SDK는 나머지 경로를 완성해
`POST /api/v1/rum/events`로 이벤트를 전송합니다. `applicationId`는 토큰이 연결된 애플리케이션의 ID여야 합니다. SDK는 이 값을 `application.id`로 전송하며,
MoleSignal은 다른 애플리케이션을 지정한 이벤트를 거부합니다.

## 세션 및 뷰

SDK는 공유 환경설정에 저장한 UUID로 세션을 식별합니다. 15분 동안 활동이 없거나 세션 시작 후 4시간이 지나면 세션이 종료됩니다.
SDK는 세션이 시작될 때 한 번만 샘플링합니다. SDK는 세션 이벤트를 전송하지 않으며, MoleSignal은 뷰에서 세션을 도출합니다. 모든 이벤트에는
`session.id`, `session.type`, `session.start`가 포함됩니다. 뷰에는 `session.has_replay`도 포함되며, 세션의 일부 구간을
녹화하면 이 값이 참이 됩니다. 하나의 뷰는 두 세션에 걸쳐 유지되지 않습니다. 뷰가 표시된 상태에서 세션이 갱신되면 해당 뷰는 종료되고
같은 화면이 `loading_type: session_renewal`이 설정된 새 뷰에 계속 표시됩니다.

`RumNavigationObserver`는 이름이 지정되어 있고 화면에 표시되는 라우트를 기록합니다. `Router` 또는
`go_router`를 사용하는 애플리케이션에서는 라우터 통합을 통해 옵저버를 전달합니다. 라우트에 고정된 이름이 없거나 `Navigator` 외부에서 탐색을 관리하는 경우 `startView`를 호출합니다.

```dart
rum.startView('/checkout', name: 'Checkout');
rum.addTiming('cart_ready');          // view.custom_timings
rum.stopView('/checkout');
```

`view.url`은 라우트 경로입니다. `trackUrlQueryString`을 설정하지 않으면 쿼리 문자열과 프래그먼트를 제외합니다. `view.name`은 라우트 이름입니다.
새 뷰를 시작하면 이전 뷰가 종료됩니다. 뷰에 변경 사항이 생기면 SDK는 `view.revision`을 높이고 현재까지의 집계값을 포함해 뷰를 다시 보고합니다.
보고 빈도는 `flushInterval`당 최대 한 번입니다. 단, 뷰가 시작되거나 종료될 때 또는 앱이 버퍼를 플러시할 때는 즉시 보고합니다.
앱이 백그라운드로 전환되면 뷰가 종료되고, 포그라운드로 돌아오면 `view_controller_redisplay`로 다시 표시됩니다. 첫 번째
`startView` 호출 전에 발생한 이벤트는 `ApplicationLaunch` 뷰에 속합니다.

## 사용자 식별 및 애플리케이션 활동 기록

```dart
rum.setUser(const RumUser(id: 'user-42', attributes: {'plan': 'enterprise'}));
rum.setAccount(const RumAccount(id: 'acme', name: 'Acme'));
rum.setGlobalContextProperty('region', 'ap-southeast-1');
rum.addFeatureFlagEvaluation('new_checkout', true);

rum.addAction('Checkout submitted', context: {'cart_size': 3});

try {
  await submitOrder();
} catch (error, stackTrace) {
  rum.addError(error, stackTrace: stackTrace, context: {'step': 'payment'});
}

rum.startDurationVital('checkout_form_ready');
// ...
rum.stopDurationVital('checkout_form_ready');
rum.addDurationVital('cart_sync', const Duration(milliseconds: 640));
```

SDK는 기존 `FlutterError.onError` 및 `PlatformDispatcher.onError` 핸들러를 체인으로 연결합니다. 추가 아이솔레이트에서 발생한 오류를
기본 아이솔레이트로 전달하고 `addError`를 호출합니다. 로그아웃 이후의 활동에 기존 사용자 식별 정보를 연결하지 않으려면 `clearUser()`를 호출합니다.

**작업**에는 `tap`, `custom`, `back`과 자동으로 기록하는 `application_start`가 있습니다. 자동 수집 탭에는 일반 이름인 `Tap`을 사용하며, 화면
콘텐츠는 읽지 않습니다. 주요 컨트롤을 `RumUserAction`으로 감싸면 Flutter의
제스처 아레나 제어권을 가져오지 않고도 비즈니스 용도에 맞는 고정 이름을 지정할 수 있습니다.

```dart
RumUserAction(
  client: rum,
  name: 'Pay now',
  child: ElevatedButton(
    onPressed: pay,
    child: const Text('Pay now'),
  ),
)
```

탭 작업은 해당 탭에서 시작한 요청을 처리하는 동안 최대 5초간 열린 상태로 유지됩니다. 이 기간에 발생한 오류, 비정상 종료 및 리소스에는
해당 작업의 `action.id`가 포함되며, 작업은 각각의 건수를 보고합니다. 1초 이내에 50 논리 픽셀 범위에서 세 번 탭하면 마지막 탭을 `rage_tap`으로,
오류를 일으킨 탭을 `error_tap`으로 기록합니다. 탭을 수집하려면 `trackUserInteractions: true`를 설정합니다. `trackFrustrations`는 기본적으로 이 설정을 따릅니다.

**오류**에는 `source`, `type`, `message`, `stack`, 구조화된 `frames`, `handling`이 포함됩니다. 프레임워크 오류는 `unhandled`로 기록하며,
`PlatformDispatcher.onError`에서 발생한 오류는 비정상 종료로도 기록합니다. `addError`는 지정한 `source`로 `handled` 오류를 보고합니다. 기본 소스는 `custom`입니다.
응답을 받기 전에 실패한 요청은 `network` 오류로 기록합니다. HTTP 오류 상태는 리소스로만 기록합니다. SDK는 `error.fingerprint`를 설정하지 않습니다.
그룹화 방식을 지정하려면 `fingerprint:`를 전달합니다.

## HTTP 리소스 및 백엔드 트레이스 모니터링

`package:http`를 `MoleSignalHttpClient`로 감쌉니다.

```dart
import 'package:http/http.dart' as http;

final http.Client httpClient = MoleSignalHttpClient(
  rum,
  inner: http.Client(),
);

await httpClient.get(Uri.parse('https://api.example.com/orders'));
```

애플리케이션에서 아직 `package:http`를 사용하지 않는다면 `http: ^1.6.0`을 애플리케이션의 직접 종속성으로 선언합니다. 래퍼는
민감 정보를 제거한 URL, 메서드, 소요 시간, 상태 코드, 응답 크기 및 사용 가능한 W3C 트레이스 식별자를 기록합니다. 응답 본문을 모두 읽거나,
본문을 읽는 도중 실패 또는 취소가 발생하면 소요 시간 측정을 종료합니다. SDK는 응답의 `traceparent`, `Server-Timing`의 `traceparent` 항목,
요청의 `traceparent` 순서로 트레이스 컨텍스트를 읽습니다. 일부 서비스만 신뢰하는 경우 트레이스 헤더를 읽을 서비스 범위를 제한합니다.

```dart
RumConfiguration(
  // ...
  allowedTracingUrls: <Pattern>[
    'https://api.example.com',
    RegExp(r'^https://edge-\w+\.example\.com/'),
  ],
)
```

SDK는 네트워크 통신을 전역에서 가로채지 않습니다. Dio 등의 클라이언트에서는 인터셉터에서 `startResource`와 `stopResource`를 호출하거나,
완료된 요청에 대해 `addResource`를 호출합니다.

## 렌더링 성능 필드

| 필드 | 의미 |
|---|---|
| `view.performance.fbc.timestamp` | 첫 빌드 완료: 뷰 시작부터 해당 뷰의 첫 프레임 빌드가 끝날 때까지 걸린 시간(나노초) |
| `view.flutter_build_time`, `view.flutter_raster_time` | 프레임별 UI 스레드 빌드 및 래스터 스레드 작업에 걸린 시간의 최솟값, 최댓값, 평균값(나노초) |
| `view.refresh_rate_average`, `view.refresh_rate_min` | 프레임 처리 시간 기준으로 유지할 수 있는 초당 프레임 수. 디스플레이 주사율을 초과하지 않습니다. |
| `view.slow_frames_rate` | 뷰가 지속된 1초당 느린 프레임에 소요된 시간(밀리초). 프레임에 할당된 시간을 초과하고 멈춤 임곗값에는 미치지 않는 프레임을 집계합니다. |
| `view.freeze_rate` | 뷰가 지속된 1시간당 멈춘 프레임에 소요된 시간(초) |
| `view.memory_average`, `view.memory_max` | 상주 메모리 크기(RSS, 바이트). Flutter Web에서는 제공하지 않습니다. |
| `long_task.duration`, `long_task.is_frozen_frame` | 처리 시간이 `longFrameThreshold`(100 ms) 이상인 프레임입니다. `frozenFrameThreshold`(700 ms) 이상이면 멈춘 프레임으로 분류합니다. |
| `app_launch` 유형의 `vital` | 콜드 스타트: `initRum`부터 애플리케이션 UI의 첫 프레임 빌드가 끝날 때까지 걸린 시간(나노초) |

## 릴리스 심볼 업로드

릴리스 파이프라인에서 변경되지 않는 값으로 `version`, `architecture`, `debugId`를 설정합니다. 해당 빌드에서 생성하는 모든 디버그 아티팩트에
같은 값을 사용합니다. 런타임에 감지하거나 계산한 대체 값은 개발에 유용하지만, 프로덕션에서 심볼을 일관되게 매칭하는 데 필요한
식별자로는 적합하지 않습니다.

`--obfuscate`와 `--split-debug-info`를 사용해 Android 및 iOS 릴리스를 빌드하고, `--dart-define`으로 식별 값을 전달합니다.

```bash
flutter build apk \
  --release \
  --obfuscate \
  --split-debug-info=build/molesignal-symbols/android-arm64 \
  --target-platform=android-arm64 \
  --dart-define=MOLESIGNAL_VERSION=1.4.0+42 \
  --dart-define=MOLESIGNAL_ARCHITECTURE=arm64 \
  --dart-define=MOLESIGNAL_DEBUG_ID="$BUILD_ID"
```

`--split-debug-info`를 사용하면 각 오류 프레임에 `artifact_kind: flutter_symbols`, 심볼 파일로 해석할 수 있는 절대 주소와 상대 주소,
빌드에 설정한 `debug_id`가 포함됩니다. 생성된 모든 `.symbols` 파일을 업로드할 때 `kind=flutter_symbols`, 해당 플랫폼(`android` 또는
`ios`), 표준 아키텍처 값, Debug ID를 지정합니다. 네이티브 크래시 프레임을 `RumStackFrame`으로 전달하는 경우,
네이티브 Android ELF 심볼과 Apple dSYM DWARF 파일을 별도로 업로드합니다.

아티팩트를 업로드하려면 `debug_artifacts.manage` 권한이 있는 관리 토큰이 필요합니다. 애플리케이션에 연결된 클라이언트 토큰을 아티팩트 관리에 사용하지 않습니다.

## 세션 리플레이 활성화

Flutter에는 DOM이 없습니다. 처음 캡처한 프레임으로 rrweb `Meta` 및 `FullSnapshot` 이벤트를 생성합니다. 변경된 프레임은 이미지 변경분으로
기록하고 변경되지 않은 프레임은 건너뜁니다. 따라서 기존 MoleSignal 리플레이 플레이어에서 브라우저와 Flutter 세션을
같은 방식으로 재생할 수 있습니다.

```dart
const RumConfiguration(
  // ...
  sessionReplaySampleRate: 20,
  sessionReplay: RumSessionReplayConfiguration(
    captureInterval: Duration(seconds: 2),
    captureOnAction: true,
    pixelRatio: 0.75,
    maximumImageDimension: 1200,
  ),
)

rum.startSessionReplayRecording();
rum.stopSessionReplayRecording();
```

`sessionReplaySampleRate`는 `sessionSampleRate`로 샘플링한 세션에 적용됩니다. 두 비율을 곱하면 전체 세션 중 리플레이 대상 비율을 구할 수 있습니다.
수동 녹화도 샘플링한 세션에만 적용됩니다. 리플레이는 별도의 큐를 사용하며, 기본 플러시 간격은 10초이고 시퀀스 번호는 세션별로 부여합니다.
목표 세그먼트 크기는 약 1 MiB이고 요청당 최대 크기는 8 MiB입니다. 세그먼트는 `POST /api/v1/rum/replay`로 전송합니다.

## 리플레이 콘텐츠 보호

기본 설정인 `RumPrivacyLevel.mask`는 PNG 인코딩 전에 `Text`, `RichText`, 편집 가능한 영역을 마스킹합니다. 입력 필드는 `allow` 모드에서도 마스킹합니다.
SDK는 URL 쿼리와 프래그먼트도 제거하고, 일반적으로 민감한 정보를 담는 컨텍스트 키의 값을 중첩된 항목까지 가립니다. 원본 스택 텍스트는
`RumPrivacyLevel.allow`에서만 전송합니다. 그 외에는 민감한 정보를 제거한 프레임으로 `error.stack`을 다시 구성합니다. 민감한 이미지, 지도, 직접 그린 콘텐츠,
플랫폼 뷰 또는 컴포넌트 전체를 명시적인 개인정보 보호 경계로 감쌉니다.

```dart
RumReplayBlock(
  child: AccountBalanceCard(),
)
```

`RumReplayMask`와 `RumReplayBlock`은 모두 캡처한 영역을 불투명한 블록으로 대체합니다. 마스킹하지 않은 원본 픽셀은 이벤트 큐에 넣지 않습니다.

<Warning>
  위젯 유형만으로는 `CustomPainter`로 그린 텍스트를 감지할 수 없습니다. 직접 그린
  영역을 명시적으로 감쌉니다. 플랫폼 뷰 캡처는 플랫폼의 화면 합성 방식에 따라 달라집니다. 민감한
  플랫폼 뷰는 실제 Android 및 iOS 기기에서 확인합니다.
</Warning>

## 전송

이벤트를 JSON 배열로 묶어 클라이언트 토큰과 함께 `POST {site}/api/v1/rum/events`로 전송합니다. `dart:io`를 사용할 수 있는 환경에서는
1 KiB를 초과하는 배치를 gzip으로 압축합니다. 압축을 끄려면 `compressRequests: false`를 설정합니다. 요청당 이벤트 데이터는 최대 48 KiB로 제한하며,
이는 수신 측에서 허용하는 이벤트 5000개와 5 MiB 한도보다 훨씬 낮습니다.

- MoleSignal이 **거부**한 이벤트는 `onError`와 `RumFlushResult`를 통해 알리고 다시 전송하지 않습니다.
- 네트워크 오류, 시간 초과, `408`, `429`, `5xx`가 발생하면 지수 백오프와 지터를 적용해 재시도합니다. 수신 측이 보낸 `Retry-After`에 지정된
  시점보다 일찍 재시도하지 않습니다. 이벤트는 오프라인 큐에 영구 저장합니다.
- 그 외의 `4xx` 응답을 받으면 배치를 폐기합니다.

큐에는 항목 수, 바이트 크기, 보관 기간 제한(`maxQueueSize`, `maxQueueBytes`, `queueItemTtl`)이 적용됩니다. 뷰의 새 리비전이
아직 대기 중인 이전 리비전을 대체하므로 MoleSignal에서 확인하는 리비전 번호가 연속적이지 않을 수 있습니다.

## 주요 구성

| 옵션 | 기본값 | 용도 |
|---|---|---|
| `applicationId`, `clientToken`, `site` | 필수 | 애플리케이션 식별, 인증, 엔드포인트 |
| `service` | `applicationId` | 이벤트에 저장하는 서비스 |
| `env`, `user`, `globalContext` | 미설정 | 배포 환경, 사용자 식별 정보, 사용자 지정 차원 |
| `version`, `buildVersion` | `unknown`, 미설정 | 디버그 아티팩트 매칭에 사용하는 릴리스 식별자와 빌드 번호 |
| `architecture`, `debugId` | 감지 또는 계산으로 얻은 대체 값 | 심볼 매칭에 사용하는 모바일 빌드 식별자 |
| `sessionSampleRate` | `100` | 세션 샘플링 비율(%) |
| `sessionReplaySampleRate` | `0` | 샘플링한 세션 중 리플레이 비율(%) |
| `sessionReplay` | 개인정보 보호 기본값 | 캡처 간격, 해상도, 동작 캡처, 마스크 색상 |
| `trackUserInteractions` | `false` | 탭 및 `back` 동작 자동 추적 |
| `trackFrustrations` | 상호작용 추적 설정을 따름 | `rage_tap` 및 `error_tap` 감지 |
| `trackResources` | `true` | HTTP 리소스 수집 |
| `trackLongTasks` | `true` | 느린 프레임과 멈춘 프레임을 장기 작업으로 수집 |
| `trackViewPerformance` | `true` | 시작, 첫 빌드, 프레임, 메모리 메트릭 |
| `trackDeviceInfo` | `true` | 플러그인을 통한 브랜드, 모델, 배터리, 연결 상태 수집 |
| `trackFlutterErrors`, `trackPlatformErrors` | `true` | 프레임워크 및 루트 아이솔레이트 오류 |
| `trackAppLifecycle` | `true` | 앱이 백그라운드로 전환되면 뷰를 종료하고 플러시 실행 |
| `trackAnonymousUser` | `true` | 세션 간 유지되는 익명 식별자 |
| `trackUrlQueryString` | `false` | 활성화 시 URL 쿼리 문자열 유지 |
| `defaultPrivacyLevel` | `mask` | 리플레이 텍스트 및 원본 스택 처리 정책 |
| `sessionInactivityTimeout`, `maxSessionDuration` | `15 min`, `4 h` | 세션 제한 |
| `flushInterval`, `batchSize` | `5 s`, `50` | 일반 이벤트 전송 |
| `replayFlushInterval`, `replayBatchSize` | `10 s`, `100` | 리플레이 전송 |
| `beforeSend` | 미설정 | 리플레이를 포함한 모든 유형의 이벤트 수정 또는 폐기 |

`RumSessionReplayConfiguration`의 기본값은 캡처 간격 5초, 동작 후 캡처, 논리 픽셀당 출력 픽셀 `0.5`개,
이미지 한 변의 최대 길이 900픽셀, 마스크 색상 `#6B7280`입니다. `excludedUrls`, `allowedTracingUrls`, 큐 제한, 재시도 지연, 시간 초과,
진단, 사용자 지정 전송, 영구 저장도 구성할 수 있습니다.

## 플러시 및 중지

대기열에 있는 이벤트의 처리가 끝날 때까지 기다려야 하는 제어된 전환 전에는 `flush()`를 호출합니다. 최종 정리 단계에서는 `stop()`을 호출해 활성 뷰를
마지막 보고서와 함께 종료하고, 계측을 제거하고, 두 이벤트 대기열을 모두 플러시합니다. 두 메서드 모두 수락된 이벤트, 재시도한 이벤트,
삭제된 이벤트, 남은 이벤트, 시간 초과된 이벤트를 구분하는 `RumFlushResult`를 반환합니다.

```dart
await rum.flush();
await rum.stop();
```
