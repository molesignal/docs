Mole Agent는 알림 설정의 커넥터를 통해 Feishu, Slack, DingTalk, WeCom, Google Chat, Microsoft Teams, Telegram에서 답변합니다. 그룹에서 멘션하거나 다이렉트 메시지를 보냅니다. Feishu, Slack, Telegram에서는 메시지에 반응을 남겨 처리 중임을 표시합니다. WeCom, Google Chat, Teams에서는 먼저 "확인 중입니다…"라고 응답한 뒤, 처리가 끝나면 해당 메시지를 답변으로 바꿉니다. 답변에는 MoleSignal의 채팅으로 이동하는 링크가 포함됩니다.

이 채팅은 일반 Mole Agent 채팅과 동일합니다. MoleSignal에 표시되며, 그곳에서 대화를 이어갈 수 있습니다. 조직의 일일 예산에 반영되며, 답변은 다른 답변과 동일한 방식으로 평가합니다. [품질](/ko/quality)을 참조합니다.

## 메시지 수신 방식

| 플랫폼 | 커넥터 | 메시지 수신 방식 |
|---|---|---|
| Feishu | Feishu 앱 (`lark_app`) | Feishu의 지속 연결 |
| Slack | Slack 앱 (`slack_app`) | Socket Mode |
| DingTalk | DingTalk 앱 (`dingtalk_app`) | Stream 모드 |
| WeCom | WeCom 스마트 봇 (`wecom_bot`) | 스마트 봇의 지속 연결 |
| Google Chat | Google Chat 앱 (`google_chat_app`) | Cloud Pub/Sub 구독에서 메시지 가져오기 |
| Telegram | Telegram 봇 (`telegram_bot`) | Telegram Bot API 롱 폴링 |
| Microsoft Teams | Microsoft Teams 봇 (`teams_app`) | Bot Framework가 MoleSignal의 공개 콜백 주소로 메시지 전송 |

Teams를 제외하면 커넥터마다 MoleSignal 서버 한 대가 외부로 연결해 메시지를 수신하므로 MoleSignal에 공개 주소가 필요하지 않습니다. Teams에는 공개 HTTPS 콜백 주소가 필요합니다. 먼저 [Teams 보안](#teams-보안)을 확인합니다. 플랫폼별로 필요한 주소, 계정, 권한은 [외부 사전 요구 사항](#외부-사전-요구-사항)에서 확인합니다.

## 시작하기 전에

- 기능을 활성화하려면 `agent.im.manage` 권한이 필요합니다. 질문하려면 `agent.use` 권한이 필요합니다.
- **설정 → 알림 → 커넥터**에 해당 플랫폼의 커넥터가 필요합니다(위 표 참조). Slack 앱에는 봇 토큰과 앱 수준 토큰이 필요하고, Google Chat 앱에는 Pub/Sub 구독이 필요합니다. [알림 채널](/ko/notification-channels)을 참조합니다.
- 사용자가 직접 계정을 연결하고 답변에 채팅 링크를 포함하려면 MoleSignal의 외부 URL인 `http.external_url`을 설정합니다. Teams의 콜백 주소는 이 URL의 하위 경로에 있으므로, Teams를 사용하려면 외부 URL을 HTTPS 주소로 설정합니다. [구성](/ko/configuration)을 참조합니다.

## 플랫폼 설정

### Feishu

<Steps>
  <Step title="지속 연결을 통해 이벤트 수신">
    Feishu 개발자 콘솔에서 앱을 열고 **이벤트 및 콜백**으로 이동한 다음, 지속 연결을 통해 이벤트를 수신하도록 설정합니다.
  </Step>
  <Step title="메시지 구독">
    **메시지 수신** 이벤트(`im.message.receive_v1`)를 추가합니다.
  </Step>
  <Step title="지속 연결을 통해 콜백 수신">
    **이벤트 및 콜백 → 콜백 구성**에서 지속 연결을 통해 콜백을 수신하도록 설정하고 카드 작업 콜백(`card.action.trigger`)을 추가합니다. 알림 카드의 버튼을 사용하려면 이 콜백이 필요합니다. [알림 카드](#알림-카드)를 참조합니다.
  </Step>
  <Step title="권한 부여">
    앱에 다이렉트 메시지와 앱을 멘션한 그룹 메시지를 읽고, 앱 이름으로 메시지를 보내고, 메시지에 반응을 추가할 수 있는 권한을 부여합니다. 스레드에서 매번 봇을 멘션하지 않고 대화를 이어가려면 모든 그룹 메시지를 읽을 수 있는 권한도 부여합니다.
  </Step>
  <Step title="게시">
    앱 버전을 게시하고 봇이 응답할 그룹에 봇을 추가합니다.
  </Step>
</Steps>

Lark를 사용하는 경우 커넥터의 **플랫폼**으로 **Lark**를 선택합니다.

### Slack

<Steps>
  <Step title="앱 수준 토큰 생성">
    **기본 정보 → 앱 수준 토큰**에서 `connections:write` 범위가 있는 토큰을 생성합니다. 이 토큰(`xapp-`로 시작)을 커넥터의 **앱 수준 토큰**에 입력합니다.
  </Step>
  <Step title="소켓 모드 활성화">
    **소켓 모드**에서 이 기능을 활성화합니다.
  </Step>
  <Step title="상호 작용 활성화">
    **상호 작용 및 바로 가기**에서 **상호 작용**을 활성화합니다. 소켓 모드에서는 요청 URL을 입력할 필요가 없습니다. 알림 카드의 버튼을 사용하려면 상호 작용이 필요합니다. [알림 카드](#알림-카드)를 참조합니다.
  </Step>
  <Step title="이벤트 구독">
    **이벤트 구독 → 봇 이벤트 구독**에서 `app_mention`과 `message.im`을 추가합니다. 스레드에서 매번 봇을 멘션하지 않고 대화를 이어가려면 `message.channels`와 `message.groups`도 추가합니다.
  </Step>
  <Step title="봇 권한 범위 추가">
    **OAuth 및 권한**에서 `app_mentions:read`, `chat:write`, `im:history`, `reactions:write`를 추가하고, 스레드 답글을 위해 `channels:history`와 `groups:history`도 추가합니다. **앱 홈**에서 앱에 메시지를 보낼 수 있도록 설정합니다. 앱을 다시 설치하고 봇이 응답할 채널에 봇을 초대합니다.
  </Step>
</Steps>

### DingTalk

<Steps>
  <Step title="Stream을 통해 로봇 메시지 수신">
    DingTalk 개발자 콘솔에서 앱의 로봇을 열고 메시지 수신 모드를 **Stream 모드**로 설정합니다.
  </Step>
  <Step title="게시">
    로봇을 게시하고 로봇이 응답할 그룹에 추가합니다.
  </Step>
</Steps>

커넥터의 **클라이언트 ID**와 **클라이언트 시크릿**에는 앱의 인증 정보를 사용합니다. 로봇에 별도의 코드가 없으면 클라이언트 ID를 로봇 코드로 사용합니다.

### WeCom

WeCom에서 Mole Agent는 스마트 봇으로 응답합니다. API 모드의 지속 연결을 통해 메시지를 받고 같은 연결로 응답을 보냅니다.

<Steps>
  <Step title="스마트 봇 생성">
    WeCom 관리 콘솔이나 클라이언트에서 스마트 봇을 생성하고 **API 모드**를 선택한 다음, **지속 연결**을 통해 메시지를 수신하도록 설정합니다. 봇의 **봇 ID**와 지속 연결용으로 생성한 **시크릿**을 기록합니다.
  </Step>
  <Step title="커넥터 생성">
    **설정 → 알림 → 커넥터**에서 **봇 ID**와 **지속 연결 시크릿**을 사용해 **WeCom 스마트 봇** 커넥터를 생성합니다. 지속 연결 주소는 `wss://openws.work.weixin.qq.com`으로 고정되어 있습니다.
  </Step>
  <Step title="그룹에 봇 추가">
    봇이 응답할 그룹에 봇을 추가하거나 봇에 다이렉트 메시지를 보낼 수 있도록 설정합니다.
  </Step>
</Steps>

- 봇은 한 번에 하나의 지속 연결만 유지합니다. 다른 MoleSignal 인스턴스나 테스트 환경 등이 같은 봇 ID로 연결하면 기존 MoleSignal 연결이 끊기고 상태에 **연결할 수 없음**과 그 사유가 표시됩니다. 환경마다 별도의 봇을 사용합니다.
- 봇은 지속 연결 또는 콜백 URL 중 하나로 메시지를 받습니다. 콜백 URL로 전환하면 지속 연결이 종료됩니다.
- 봇을 생성한 계정이 조직의 최고 관리자이면 메시지에 멤버의 사용자 ID가 평문으로 포함됩니다. 그 외에는 암호화된 사용자 ID가 포함됩니다. 관리자가 암호화된 사용자 ID를 수동으로 연결하기는 어려우므로 Mole Agent가 보내는 일회용 링크로 각 계정을 직접 연결하도록 안내합니다.
- 커넥터를 활성화하면 봇이 알림도 전달합니다. 알림 정책이나 개인 알림 방법에서 이 커넥터를 선택하고 멤버의 userid 또는 채팅의 chatid를 대상으로 지정할 수 있습니다. 봇은 다이렉트 메시지를 보낸 계정이나 봇을 멘션한 채팅에만 알림을 보낼 수 있습니다. 경보 알림은 버튼이 포함된 템플릿 카드로 전송합니다. [알림 카드](#알림-카드)를 참조합니다.

### Google Chat

Google Chat 앱은 Cloud Pub/Sub 주제에 메시지를 게시하고 MoleSignal은 해당 구독에서 메시지를 가져오므로 공개 주소가 필요하지 않습니다.

<Steps>
  <Step title="서비스 계정 준비">
    Google Cloud 프로젝트에서 **Google Chat API**와 **Cloud Pub/Sub API**를 활성화합니다. 같은 프로젝트에서 서비스 계정과 해당 계정의 JSON 키를 생성하고, 키를 커넥터의 **서비스 계정 키**에 입력합니다. Chat 앱은 이 계정으로 메시지를 보내고, MoleSignal은 이 계정으로 구독에서 메시지를 가져옵니다.
  </Step>
  <Step title="주제 및 구독 생성">
    Pub/Sub에서 주제(예: `mole-chat`)를 생성하고 해당 주제의 **풀** 구독(예: `mole-chat-sub`)을 생성합니다. 구독에서 서비스 계정에 **Pub/Sub 구독자** 역할(`roles/pubsub.subscriber`)을 부여합니다.
  </Step>
  <Step title="Chat에 주제 게시 권한 부여">
    주제에서 `chat-api-push@system.gserviceaccount.com`에 **Pub/Sub 게시자** 역할(`roles/pubsub.publisher`)을 부여합니다. Google Workspace 부가기능으로 빌드한 Chat 앱이라면 대신 연결 설정에 표시된 서비스 계정에 이 역할을 부여합니다.
  </Step>
  <Step title="Chat 앱 구성">
    **Google Chat API → 구성**에서 앱 이름과 아바타를 입력하고 **1:1 메시지 수신**과 **스페이스 및 그룹 대화 참여**를 활성화합니다. **연결 설정**에서 **Cloud Pub/Sub**를 선택하고 주제의 전체 이름 `projects/<project>/topics/mole-chat`을 입력한 다음, **공개 범위**에서 앱을 사용할 수 있는 대상을 선택합니다.
  </Step>
  <Step title="구독 입력">
    커넥터의 **Pub/Sub 구독**에 `projects/<project>/subscriptions/mole-chat-sub`를 입력합니다.
  </Step>
</Steps>

- 구독의 확인 응답 기한은 기본값인 10초로 유지합니다. MoleSignal은 각 메시지를 가져오는 즉시 수신을 확인합니다.
- 스페이스와 그룹 대화에서는 앱을 멘션한 메시지만 앱에 전달되므로 스레드에서 대화를 이어가려면 앱을 다시 멘션합니다. 다이렉트 메시지에서는 모든 메시지가 앱에 전달됩니다.

### Telegram

봇은 Telegram Bot API(`getUpdates`)를 롱 폴링하여 메시지를 수신하므로 공개 주소가 필요하지 않습니다.

<Steps>
  <Step title="봇 생성">
    Telegram에서 **@BotFather**에 `/newbot`을 보내고 봇의 이름과 사용자 이름을 지정합니다. 발급된 토큰(예: `123456789:AAE…`)을 복사합니다.
  </Step>
  <Step title="커넥터 생성">
    **설정 → 알림 → 커넥터**에서 **Telegram 봇** 커넥터를 생성하고 **봇 토큰**에 토큰을 입력합니다.
  </Step>
  <Step title="멘션 수신 허용">
    Telegram의 기본 개인정보 보호 모드에서는 그룹의 봇이 자신에게 보낸 명령과 자신의 메시지에 달린 답글만 받고 일반 @멘션은 받지 못합니다. @멘션으로 Mole Agent에 질문하려면 @BotFather에 `/setprivacy`를 보내고 **비활성화**를 선택하거나 봇을 그룹 관리자로 지정합니다.
  </Step>
  <Step title="그룹에 봇 추가">
    봇이 응답할 그룹에 봇을 추가합니다.
  </Step>
</Steps>

- 그룹에서 Mole Agent는 봇을 멘션한 메시지, 명령(`/new@<bot>` 또는 `/new`), 봇의 응답에 달린 답글에 응답합니다. 경보 알림에 대한 답글에도 멘션이 필요하므로 멘션 없이 경보에 관해 나누는 대화는 Mole Agent에 전달되지 않습니다. 개인 채팅에서는 모든 메시지가 전달됩니다.
- 봇과의 개인 채팅을 시작하는 `/start` 명령은 `/help`와 동일하게 처리합니다. 아직 계정을 연결하지 않은 상태에서 이 명령을 보내면 연결 링크를 받습니다.
- Telegram 봇은 봇과의 개인 채팅을 열고 **시작**을 누른 계정에만 개인 메시지를 보낼 수 있습니다. 아직 계정을 연결하지 않았고 개인 메시지를 받을 수 없다면, 해당 계정에만 보이는 그룹 메시지로 링크를 받습니다. 이 방법도 실패하면 Mole Agent가 먼저 개인 메시지를 보내 달라고 요청합니다. [사용자 계정 연결](#사용자-계정-연결)을 참조합니다.
- Telegram은 한 번에 하나의 수신자에게만 봇 메시지를 전달합니다. MoleSignal은 연결할 때 봇에 설정된 웹훅을 제거합니다. 다른 프로그램에서 같은 봇을 폴링하면 Telegram이 둘 중 하나의 요청을 거부하고(HTTP 409), 상태에 **연결할 수 없음**과 그 사유가 표시됩니다. 환경마다 별도의 봇을 사용합니다.

### Microsoft Teams

Bot Framework는 Teams 메시지를 MoleSignal의 공개 콜백 주소로 전송합니다. Microsoft Teams는 인터넷에서 MoleSignal에 접속할 수 있어야 하는 유일한 플랫폼입니다. 커넥터를 활성화하기 전에 [Teams 보안](#teams-보안)의 안내에 따라 외부 주소를 준비합니다.

<Steps>
  <Step title="Azure Bot 준비">
    Azure 포털에서 **단일 테넌트** 유형의 **Azure Bot**을 생성하거나 기존 봇을 사용합니다. 봇의 Microsoft Entra 앱 등록에서 클라이언트 시크릿을 생성합니다. 커넥터에 봇의 **앱 ID**, **클라이언트 시크릿**, **테넌트 ID**를 입력합니다.
  </Step>
  <Step title="Teams 채널 추가">
    Azure Bot의 **채널**에서 **Microsoft Teams**를 추가합니다.
  </Step>
  <Step title="커넥터 활성화 및 콜백 주소 복사">
    **Mole Agent → 설정 → IM**을 열고 커넥터를 활성화한 다음, **콜백** 주소 `https://<external address>/api/v1/public/im/teams/<connector ID>/messages`를 복사합니다.
  </Step>
  <Step title="메시징 엔드포인트 설정">
    Azure Bot의 **구성**에서 **메시징 엔드포인트**를 콜백 주소로 설정합니다.
  </Step>
  <Step title="Teams 앱 게시">
    매니페스트의 `bots`에 봇의 앱 ID와 `personal`, `team`, `groupChat` 범위를 지정한 Teams 앱 패키지를 만듭니다. Teams 관리 센터 또는 개발자 포털에 업로드하고, 앱을 사용할 사용자, 팀, 그룹 채팅에 설치합니다.
  </Step>
</Steps>

- 채널과 그룹 채팅에서는 봇을 멘션한 메시지만 봇에 전달되므로 게시물 아래에서 대화를 이어가려면 봇을 다시 멘션합니다. 개인 채팅에서는 모든 메시지가 봇에 전달됩니다.
- Azure 퍼블릭 클라우드와 미국 정부 클라우드(GCC, GCC High, DoD)의 Bot Framework를 지원합니다. 커넥터에서 **클라우드**를 선택합니다.

## Teams 보안

Teams 콜백 주소는 인터넷에 공개됩니다. MoleSignal은 이 주소로 들어오는 모든 요청을 검사합니다.

- **모든 요청에는 Bot Framework 토큰이 필요합니다.** 이 주소는 MoleSignal 로그인을 받지 않으며 Bot Framework가 서명한 JWT만 허용합니다. 서명 키는 `login.botframework.com`의 OpenID 메타데이터에서 가져와 24시간 동안 캐시합니다. `iss`는 `https://api.botframework.com`이어야 합니다. GCC High와 DoD에서는 대신 `login.botframework.azure.us`와 `https://api.botframework.us`를 사용합니다. `aud`는 봇의 앱 ID여야 합니다. `exp`와 `nbf`는 5분의 시계 오차를 허용합니다. 서명 키는 Teams 채널(`msteams`)을 승인해야 하며 토큰의 `serviceUrl`은 메시지의 `serviceUrl`과 일치해야 합니다. 검증에 실패하면 401 또는 403을 반환하고 요청을 처리하지 않습니다.
- **응답은 Bot Framework로만 보냅니다.** MoleSignal은 Bot Framework 서비스 주소(`smba.trafficmanager.net`, `*.botframework.com`, `*.teams.microsoft.com`, `*.teams.microsoft.us`) 또는 커넥터에 구성한 서비스 URL로만 봇 토큰을 보냅니다. 그 외 주소가 포함된 메시지는 거부합니다.
- **커넥터의 테넌트만 허용합니다.** 커넥터의 테넌트를 테넌트 ID(GUID)로 설정하면 다른 테넌트의 메시지는 처리하지 않습니다. 도메인 이름이나 `botframework.com`을 설정하면 테넌트를 제한하지 않습니다.
- **커넥터가 켜져 있을 때만 주소가 작동합니다.** **IM**에서 커넥터를 켜지 않았거나 껐거나 삭제한 경우 콜백 주소는 404를 반환합니다. 주소에는 커넥터 ID만 포함되며 시크릿은 포함되지 않습니다.
- **요청 본문 크기를 제한합니다.** 256 KiB를 초과하는 요청은 거부합니다.

배포할 때는 다음 사항도 적용합니다.

1. **콜백 경로만 인터넷에 공개합니다.** 역방향 프록시 또는 게이트웨이에서 `POST /api/v1/public/im/teams/`만 전달하고, 로그인 페이지와 나머지 모든 API는 내부 네트워크에 둡니다. 다음은 nginx 예시입니다.

   ```nginx
   server {
     listen 443 ssl;
     server_name molesignal.example.com;
     # ssl_certificate and ssl_certificate_key …
     client_max_body_size 256k;

     location /api/v1/public/im/teams/ {
       limit_except POST { deny all; }
       proxy_pass http://molesignal.internal:8080;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto https;
     }

     location / {
       return 404;
     }
   }
   ```

   이 외부 주소로 MoleSignal에도 접속하는 경우, 게이트웨이에서 나머지 모든 경로를 사내 네트워크 또는 VPN으로 제한하고 콜백 경로만 인터넷에 공개합니다. nginx, Kubernetes Ingress, Gateway API의 전체 구성은 [공개 액세스](/ko/public-access)를 참조합니다.
2. **HTTPS를 사용합니다.** Teams는 HTTP로 POST 요청을 보내지 않으므로 `http.external_url`은 HTTPS 주소여야 합니다. 공인 CA의 인증서를 사용해 프록시에서 TLS를 종료할 수 있습니다.
3. **필요에 따라 요청 출발지를 제한합니다.** 방화벽 또는 게이트웨이에서 Azure 서비스 태그 `AzureBotService`에 속하는 주소만 콜백 경로에 접근하도록 허용할 수 있습니다. 주소는 변경되므로 Azure에서 게시하는 목록에 맞춰 최신 상태로 유지합니다. 기본 방어 수단은 여전히 토큰 검증입니다.
4. **클라이언트 시크릿을 안전하게 관리합니다.** MoleSignal은 시크릿을 암호화하여 커넥터와 함께 저장하며 반환하지 않습니다. 시크릿을 정기적으로 교체하고 교체할 때마다 커넥터를 업데이트합니다. 봇의 앱 등록에는 필요한 권한만 부여합니다.
5. **이상 징후를 모니터링합니다.** MoleSignal의 로그와 트레이스에서 콜백 요청과 토큰 거부 내역을 확인할 수 있습니다. **IM**에는 각 커넥터가 마지막으로 메시지를 받은 시각이 표시됩니다.

## 외부 사전 요구 사항

각 플랫폼에서 MoleSignal 외부에 필요한 항목은 다음과 같습니다.

| 플랫폼 | MoleSignal에서 나가는 연결 | 인바운드 연결 | 플랫폼에서 설정할 항목 |
|---|---|---|---|
| Feishu | `open.feishu.cn`(Lark는 `open.larksuite.com`) 및 플랫폼에서 제공하는 지속 연결 주소 | 없음 | 직접 만든 앱, 지속 연결을 통한 이벤트, 메시지 이벤트, 지속 연결을 통한 콜백, 권한, 게시된 버전 |
| Slack | `slack.com`, Socket Mode WebSocket 주소, 알림 카드용 `hooks.slack.com`. GovSlack은 대신 `slack-gov.com`과 `hooks.slack-gov.com` 사용 | 없음 | 앱 수준 토큰, Socket Mode, 상호작용, 이벤트 구독, 봇 권한 범위 |
| DingTalk | `api.dingtalk.com`, `oapi.dingtalk.com`, Stream WebSocket 주소 | 없음 | 내부 앱의 로봇, Stream 모드. 알림 카드에 버튼을 표시하려면 대화형 카드 템플릿과 카드 권한 필요 |
| WeCom | `openws.work.weixin.qq.com`(WebSocket, 443) | 없음 | 지속 연결을 사용하는 API 모드의 스마트 봇, 해당 봇 ID와 시크릿 |
| Google Chat | `oauth2.googleapis.com`, `pubsub.googleapis.com`, `chat.googleapis.com` | 없음 | Chat 및 Pub/Sub API, 서비스 계정과 해당 JSON 키, 주제와 풀 구독, 구독자 및 게시자 역할, Chat 앱 구성 |
| Telegram | `api.telegram.org`(443) | 없음 | @BotFather로 만든 봇과 해당 토큰 |
| Microsoft Teams | `login.microsoftonline.com`, `login.botframework.com`, 커넥터의 서비스 URL(Global의 경우 `smba.trafficmanager.net`). GCC High와 DoD는 대신 `login.microsoftonline.us`와 `login.botframework.azure.us` 사용 | Bot Framework가 `https://<external address>/api/v1/public/im/teams/…`(443)에 접속 | Azure Bot, 클라이언트 시크릿, Teams 채널, 메시징 엔드포인트, Teams 앱 패키지 |

- 방화벽과 아웃바운드 프록시에서 위 주소로 나가는 연결을 허용해야 합니다. WebSocket 지속 연결(Feishu, Slack, DingTalk, WeCom)은 플랫폼에 직접 연결하며 HTTP 프록시를 사용하지 않습니다.
- Teams의 인바운드 연결에는 공개 DNS, 공인 CA의 인증서, 콜백 경로만 전달하는 역방향 프록시가 필요합니다. [Teams 보안](#teams-보안)을 참조합니다.
- 계정 연결과 응답에 포함된 채팅 링크를 사용하려면 `http.external_url`이 필요합니다.

## 켜기

**Mole Agent → 설정 → IM**을 엽니다. IM에서 응답할 수 있는 모든 커넥터가 표시됩니다.

| 열 | 표시 내용 |
|---|---|
| **커넥터** | 커넥터, 플랫폼, 마지막으로 메시지를 받은 시각을 표시합니다. Teams 커넥터 아래에는 복사할 수 있는 콜백 주소가 표시됩니다. |
| **상태** | **연결됨**과 연결된 계정, **연결 중**, **서버 대기 중**, **연결할 수 없음**과 그 이유, **꺼짐** 또는 Slack 앱 수준 토큰이나 Google Chat Pub/Sub 구독처럼 커넥터에 추가로 필요한 항목을 표시합니다. Teams는 지속 연결을 사용하지 않습니다. **연결됨**은 봇의 자격 증명이 유효하고 Bot Framework가 메시지를 전달한다는 뜻입니다. |
| **새 그룹 스레드** | 그룹의 새 스레드를 보낼 위치를 표시합니다. **질문자의 개인 채팅** 또는 팀을 선택할 수 있습니다. 질문자가 해당 팀의 멤버인 경우에만 팀 설정을 적용합니다. |
| **켜짐** | 커넥터가 IM에서 응답하는지 여부를 표시합니다. Teams 커넥터는 `http.external_url`이 HTTPS 주소일 때만 켤 수 있습니다. |

IM에서 응답하는 커넥터를 알림 설정에서 삭제하려면 먼저 여기서 커넥터를 끕니다.

## 사용자 계정 연결

Mole Agent는 IM 계정에 연결된 MoleSignal 사용자로 응답하며 해당 사용자의 권한을 적용합니다. 같은 커넥터에서 활성화되고 인증된 알림 수단을 기준으로 계정을 식별합니다.

| 플랫폼 | 계정 |
|---|---|
| Feishu | `open_id`, `user_id` 또는 `union_id` |
| Slack | 멤버 ID |
| DingTalk | 사용자 ID |
| WeCom | 스마트 봇에서 확인할 수 있는 사용자 ID |
| Google Chat | 사용자(`users/123…`) 또는 이메일 주소 |
| Telegram | 숫자형 사용자 ID |
| Microsoft Teams | Teams 사용자 ID(`29:…`) 또는 Microsoft Entra 개체 ID |

둘 이상의 사용자에게 연결된 계정에는 응답하지 않습니다.

- **사용자가 직접 연결**: 아직 계정을 연결하지 않은 사용자가 질문하면 Mole Agent가 일회용 링크를 비공개로 보냅니다. 다이렉트 메시지를 사용하며 Slack에서는 질문자에게만 보이는 메시지로 보냅니다. MoleSignal에 로그인한 상태로 링크를 열고 **연결**을 선택하면 해당 계정이 질문자의 알림 수단으로 추가되며 인증도 완료됩니다. 링크는 15분 이내에 한 번만 사용할 수 있습니다. WeCom, Google Chat, Telegram에서는 봇에 직접 메시지를 보낸 사용자에게만 비공개 메시지를 보낼 수 있습니다. Teams에서는 봇이 설치된 사용자에게만 보낼 수 있습니다. 비공개 메시지를 보낼 수 없으면 Mole Agent는 질문이 올라온 곳에서 먼저 다이렉트 메시지를 보내 달라고 안내한 뒤 해당 채팅으로 링크를 보냅니다. Telegram에서는 먼저 그룹에서 질문자에게만 보이는 메시지 전송을 시도합니다.
- **관리자가 연결**: **설정 → 알림 → 사용자 라우팅**에서 계정을 멤버에 연결하고 인증합니다. [알림 채널](/ko/notification-channels#사용자-알림-수신-방법-연결)을 참조합니다.

## 질문하기

그룹에서는 봇을 멘션하고, 다이렉트 메시지에서는 멘션 없이 질문을 작성합니다. 다이렉트 메시지에서는 `/new`를 실행하기 전까지 하나의 채팅이 이어집니다.

| 플랫폼 | 그룹에서 하나의 채팅을 구성하는 단위 |
|---|---|
| Feishu, Slack | 스레드 하나가 채팅 하나입니다. 답변은 해당 스레드에 게시됩니다. |
| Google Chat 스페이스 | 스레드 하나가 채팅 하나입니다. 답변은 해당 스레드에 게시되며, 질문을 이어가려면 봇을 멘션해야 합니다. |
| Microsoft Teams 채널 | 게시물 하나가 채팅 하나입니다. 답변은 해당 게시물 아래에 표시되며, 질문을 이어가려면 봇을 멘션해야 합니다. |
| DingTalk, WeCom, Google Chat 그룹 대화, Teams 그룹 채팅 | 스레드가 없습니다. 같은 그룹에서 한 사람이 한 질문은 모두 하나의 개인 채팅으로 묶입니다. |
| Telegram 그룹 | 포럼 주제마다 질문한 사람별로 별도의 채팅이 이어집니다. 답변은 해당 질문에 대한 답장으로 표시됩니다. |

| 명령어 | 기능 |
|---|---|
| `/help` | 질문하는 방법과 이 명령어 목록을 표시합니다. |
| `/new` | 현재 위치에서 새 채팅을 시작합니다. |
| `/scope` | 이 스레드가 누구의 채팅인지 표시합니다. |
| `/scope <team>` | 지정한 팀의 새 채팅에서 대화를 이어갑니다. 팀원은 대화 내용을 확인하고 질문을 이어갈 수 있습니다. |
| `/scope me` | 새 개인 채팅에서 대화를 이어갑니다. |
| `/feedback 👍` 또는 `/feedback 👎` 뒤에 선택적으로 의견 입력 | 스레드의 마지막 답변을 평가합니다. |

`/rca INC-12` 등의 다른 명령어와 스킬은 MoleSignal에서와 동일하게 작동합니다.

### 스레드의 채팅 소유자

개인 채팅은 시작한 사람만 이어갈 수 있고, 팀 채팅은 해당 팀의 구성원이 이어갈 수 있습니다. 그룹에서 새 스레드를 시작하면 질문한 사람이 커넥터의 팀에 속한 경우에는 해당 팀의 채팅으로, 그렇지 않은 경우에는 질문한 사람의 개인 채팅으로 시작합니다. `/scope`는 스레드를 새 채팅으로 전환합니다. 이전 메시지는 기존 채팅에 남습니다.

## 답변 처리 방식

- 메신저에서는 Mole Agent의 질문에 답하거나 변경 사항을 확인할 수 없습니다. Mole Agent는 합리적인 가정을 세우고 어떤 가정을 적용했는지 밝힙니다. 확인이 필요한 단계는 건너뛰고 그 사실을 답변에 표시합니다. 건너뛴 단계를 계속 진행하려면 링크를 통해 MoleSignal에서 채팅을 엽니다.
- 답변을 생성하는 데 최대 15분이 걸립니다. WeCom에서는 "확인 중…" 메시지를 스트리밍하며, 10분 이내에 스트리밍을 종료해야 합니다. 따라서 생성에 9분 넘게 걸린 답변은 별도 메시지로 전송됩니다.
- 답변은 질문한 사람의 인터페이스 언어로 표시되며, 가능성이 높은 원인, 근거, 다음 단계 등의 섹션을 포함합니다.
- Mole Agent는 질문한 사람의 권한으로 답변을 생성하지만, 그룹의 모든 구성원이 답변을 볼 수 있습니다. 다른 구성원에게 공개하면 안 되는 내용은 다이렉트 메시지로 질문합니다.
- 조직의 일일 예산을 모두 사용하면 Mole Agent가 답변 대신 예산 소진을 알립니다.

## 알림 카드

이 섹션에서는 Mole Agent와의 채팅이 아닌 알림 메시지를 다룹니다. 아래 커넥터는 버튼이 있는 카드로 알림을 전송합니다. MoleSignal을 열지 않고도 카드에서 알림을 확인하거나 해결하거나 일시 중지할 수 있습니다.

| 커넥터 | 카드에 버튼이 표시되는 조건 |
|---|---|
| Feishu 앱, Slack 앱, WeCom 스마트 봇, Google Chat 앱, Microsoft Teams 봇, Telegram 봇 | **IM**에서 커넥터를 활성화합니다. [활성화](#켜기)를 참조합니다 |
| DingTalk 앱 | **IM**에서 커넥터를 활성화하고 **카드 템플릿 ID**를 설정합니다. [DingTalk 대화형 카드](#dingtalk-대화형-카드)를 참조합니다 |
| WeCom 앱 | **IM**에서 활성화할 필요 없이 앱에서 **메시지 수신**을 설정합니다. [WeCom 앱의 버튼](#wecom-앱의-버튼)을 참조합니다. 멤버에게 보내는 알림에만 버튼이 표시됩니다 |
| Mattermost 봇 | **IM**에서 활성화할 필요 없이 `http.external_url`을 설정하고 Mattermost 서버에서 해당 주소에 연결할 수 있도록 합니다. [Mattermost 봇의 버튼](#mattermost-봇의-버튼)을 참조합니다 |

그룹 봇(각 플랫폼의 웹훅 커넥터)은 버튼 클릭 이벤트를 받지 않으므로 버튼 없이 알림을 전송합니다. 인스턴트 메시징 템플릿에서 **카드로 전송**을 활성화하면 버튼 없는 카드를 보내고, 그렇지 않으면 텍스트를 보냅니다. [인스턴트 메시징 템플릿의 카드](/ko/notification-channels#인스턴트-메시징-템플릿의-카드)를 참조합니다. 버튼을 지원하지 않는 커넥터로 한 명에게 알림을 보내는 경우에는 [일회용 작업 링크](/ko/notification-channels#일회용-작업-링크)를 대신 포함합니다.

| 버튼 | 동작 |
|---|---|
| **확인** | MoleSignal에서 알림을 확인할 때와 동일하게 알림을 인수합니다. 에스컬레이션이 중단되고 버튼을 누른 사용자가 담당자로 추가됩니다. |
| **해결** | 알림을 종료합니다. |
| **1시간 일시 중지** | 1시간 동안 알림을 전송하지 않습니다. 확인 대기 중인 알림은 먼저 확인 처리합니다. 1시간이 지나면 다시 확인 대기 상태로 전환하고 담당자에게 알립니다. [인시던트에 조치하기](/ko/alerting/incidents#인시던트에-조치하기)를 참조합니다. |
| **모두 확인** | [알림 병합](/ko/notification-channels#알림-묶기)으로 전송한 메시지에만 표시됩니다. 메시지에서 아직 확인을 기다리는 알림을 최대 20개까지 확인 처리합니다. Telegram 카드에는 이 버튼을 표시하지 않고 **MoleSignal에서 열기**만 표시합니다. |
| **MoleSignal에서 열기** | 인시던트 페이지를 엽니다. 병합된 메시지에서는 인시던트 목록을 엽니다. `http.external_url`을 설정해야 합니다. |

- 카드에 표시되는 버튼은 알림 전송 시점의 상태에 따라 달라집니다. 확인 대기 중인 알림에는 확인, 해결, 1시간 일시 중지가 표시되고, 확인된 알림에는 해결과 1시간 일시 중지가 표시됩니다. 복구 알림에는 버튼이 표시되지 않습니다.
- 버튼을 누르면 IM 계정에 연결된 MoleSignal 사용자로 작업을 실행합니다. 해당 사용자에게 `alerts.incidents.acknowledge` 권한이 필요합니다. 아직 연결되지 않은 계정에는 연결을 요청할 때와 마찬가지로 일회용 링크를 비공개로 보냅니다. [사용자 계정 연결](#사용자-계정-연결)을 참조합니다. Telegram 봇이 개인 메시지를 보낼 수 없으면 버튼을 누른 사용자에게만 보이는 그룹 메시지로 링크를 보냅니다. 또는 버튼을 누를 때 봇과의 개인 채팅을 열고 그곳으로 링크를 보냅니다. 대신 WeCom 앱은 메시지를 보내고, Mattermost 봇은 버튼을 누른 사용자에게만 보이는 메시지를 보냅니다. 두 메시지 모두 먼저 프로필에서 계정을 알림 방법으로 추가하도록 안내합니다. 여러 사용자에 연결된 계정에서 버튼을 눌러도 아무것도 변경되지 않습니다.
- 버튼을 누르면 카드에 알림의 현재 상태가 표시됩니다. 알림을 보낸 알림 정책의 템플릿으로 내용을 다시 작성하고, 누가 알림을 확인하거나 해결했는지 한 줄로 표시하며, 여전히 적용할 수 있는 버튼만 남깁니다. 그룹의 모든 멤버에게 같은 카드가 표시됩니다. 누를 수 있는 버튼이 더 이상 없으면 WeCom 카드에는 아무 동작도 하지 않는 ✓ 버튼을 남깁니다. WeCom 템플릿 카드에는 버튼이 하나 이상 필요하기 때문입니다.
- Feishu와 Telegram은 버튼을 누른 사용자에게 작업 성공 여부를 토스트 메시지로 표시합니다. Telegram에서 문제가 발생하면 닫아야 하는 팝업으로 표시합니다. 다른 플랫폼에서도 작업이 실패하면 버튼을 누른 사용자에게 이유를 알립니다. Slack, Google Chat, Mattermost는 해당 사용자에게만 보이는 메시지를 게시하고, Teams는 해당 사용자에게 한 줄로 표시하며, DingTalk와 WeCom은 해당 사용자에게 다이렉트 메시지를 보냅니다.
- 버튼 레이블에는 수신자의 인터페이스 언어를 사용합니다. 그룹에 보내는 카드에는 조직의 기본 언어를 사용합니다.

### DingTalk 대화형 카드

DingTalk 카드는 대화형 카드 템플릿의 레이아웃을 따릅니다. MoleSignal은 템플릿 변수를 채우고 Stream 연결을 통해 버튼 클릭 이벤트를 받습니다.

<Steps>
  <Step title="템플릿 만들기">
    DingTalk 개발자 콘솔의 **카드 플랫폼**에서 **메시지 카드** 템플릿을 만들고 앱에 연결합니다.
  </Step>
  <Step title="변수 추가">
    텍스트 변수 `title`, `content`, `note`, `footer`, `open_text`, `open_url`을 추가합니다. 각 작업에 `*_text`와 `*_value`도 추가합니다. 작업은 `acknowledge`, `resolve`, `snooze`, `acknowledge_all`이며, [승인 카드](#승인-카드)에는 `approve`와 `reject`를 사용합니다.
  </Step>
  <Step title="구성 요소 배치">
    제목은 `title`에, Markdown 본문은 `content`에 바인딩합니다. 작은 글씨 두 줄은 각각 `note`(알림을 확인하거나 해결한 사용자)와 `footer`(템플릿 바닥글)에 바인딩합니다. 각 작업에 버튼을 추가합니다. 버튼 텍스트를 `*_text`에 바인딩하고, `*_text`가 비어 있지 않을 때만 버튼을 표시합니다. **콜백 요청** 작업의 매개변수 `value`를 `*_value`에 바인딩합니다. 버튼을 하나 더 추가해 텍스트를 `open_text`에 바인딩하고 `open_url`을 열도록 설정합니다. 이 버튼도 `open_text`가 비어 있지 않을 때만 표시합니다.
  </Step>
  <Step title="게시하고 ID 입력">
    템플릿을 저장하고 게시한 다음 **템플릿 ID**를 커넥터의 **카드 템플릿 ID**에 입력합니다. 앱에 대화형 카드 쓰기 권한(`Card.Instance.Write`)이 필요합니다.
  </Step>
</Steps>

- 개인 카드는 앱의 공개 범위에 속한 멤버에게 전송합니다. 그룹에 카드를 보내려면 봇이 해당 그룹에 있어야 합니다.
- 템플릿 ID가 없으면 이전과 같이 버튼 없이 ActionCard 또는 Markdown 형식으로 알림을 전송합니다.

### WeCom 앱의 버튼

WeCom 앱(`wecom_app`)은 Mole Agent 봇이 아니므로 **IM**에서 활성화하지 않습니다. 앱의 **메시지 수신**에서 MoleSignal로 콜백을 보내도록 설정하면 멤버에게 버튼이 있는 템플릿 카드로 알림을 전송합니다. WeCom은 앱 채팅으로 템플릿 카드를 보내지 않으므로 앱 채팅 알림에는 버튼이 없습니다.

<Steps>
  <Step title="API 수신 활성화">
    WeCom 관리 콘솔에서 앱을 열고 **메시지 수신**에서 **API 수신 설정**을 선택한 다음 **토큰**과 **EncodingAESKey**를 생성합니다.
  </Step>
  <Step title="커넥터에 입력">
    생성한 값을 커넥터의 **콜백 토큰**과 **EncodingAESKey**에 각각 입력하고 저장합니다.
  </Step>
  <Step title="콜백 URL 입력">
    커넥터의 **콜백 URL**인 `https://<external address>/api/v1/public/notify/<connector ID>/wecom`을 복사해 **메시지 수신**의 URL에 입력하고 저장합니다. WeCom은 즉시 URL에 요청을 보내 확인합니다.
  </Step>
</Steps>

- 콜백 URL의 도메인은 회사의 ICP 등록에 포함되어야 하며, WeCom이 인터넷에서 이 경로에 연결할 수 있어야 합니다.
- MoleSignal은 서명이 잘못된 요청을 거부합니다. EncodingAESKey로 콘텐츠를 복호화하고 다른 회사에 해당하는 콘텐츠는 무시합니다.
- MoleSignal은 이 커넥터에서 검증한 알림 방법인 멤버의 UserID로 버튼을 누른 사용자를 식별합니다.

### Mattermost 봇의 버튼

Mattermost 봇(`mattermost_bot`)은 Mole Agent 봇이 아니므로 **IM**에서 활성화하지 않습니다. `http.external_url`을 설정하면 알림에 확인, 해결, 1시간 일시 중지 버튼이 표시됩니다. 버튼을 누르면 `https://<external address>/api/v1/public/notify/<connector ID>/mattermost?token=…`으로 MoleSignal에 콜백을 보냅니다. 이 주소에는 커넥터의 콜백 토큰이 포함되며, Mattermost는 이를 클라이언트에 공개하지 않습니다.

- Mattermost 서버가 콜백을 보내므로 외부 주소에 연결할 수 있어야 합니다. 시스템 콘솔의 **환경 → 개발자 → 신뢰하지 않는 내부 연결을 허용할 호스트**(`ServiceSettings.AllowedUntrustedInternalConnections`)에 호스트를 등록하지 않으면 Mattermost는 비공개 주소와 내부 주소에 콜백을 보내지 않습니다. MoleSignal이 내부 네트워크에 있다면 여기에 `http.external_url`의 호스트를 추가합니다.
- MoleSignal은 이 커넥터에서 활성화하고 검증한 알림 방법으로 버튼을 누른 사용자를 식별합니다. `@` 포함 여부와 관계없이 Mattermost 사용자 이름을 사용하거나 사용자 ID를 사용합니다. 사용자를 식별하지 못하면 해당 사용자에게만 보이는 메시지로 먼저 계정을 알림 방법으로 추가하도록 안내합니다.
- 콜백 토큰이 잘못되면 MoleSignal은 401로 요청을 거부합니다. 커넥터가 비활성화되어 있으면 404로 응답합니다.
- 웹훅 게시물(`mattermost_webhook`)에는 버튼을 누른 사용자를 식별할 수 없으므로 버튼이 표시되지 않습니다. 알림 링크만 포함합니다.

## 승인 카드

Mole Agent가 승인이 필요한 작업을 제안하거나 인시던트에서 해결 조치를 시작하면, 기본 알림 정책 **승인 필요: 승인 권한이 있는 사용자에게 알림**을 통해 **Mole Agent 승인 요청** 이벤트를 전송합니다. 요청자를 제외하고 `agent.approve` 권한이 있는 구성원 최대 20명에게 각 구성원의 알림 방법으로 전송합니다. [사전 승인](/ko/alerting/remediation#사전-승인) 대상인 요청은 알림을 보내지 않고 즉시 실행합니다.

버튼이 있는 알림 카드를 지원하는 커넥터에서는 다음 버튼이 포함된 카드로 알림을 보냅니다([알림 카드](#알림-카드) 참조).

| 버튼 | 기능 |
|---|---|
| **승인** | 요청을 승인합니다. 필요한 승인을 모두 받으면 Mole Agent의 승인 화면에서와 마찬가지로 요청을 즉시 실행합니다. |
| **거부** | 요청을 거부합니다. 요청은 실행하지 않습니다. |
| **MoleSignal에서 열기** | Mole Agent의 승인 화면을 엽니다. `http.external_url`이 필요합니다. |

- 버튼을 누르면 IM 계정에 연결된 MoleSignal 사용자로 처리합니다. 커넥터에서 인증된 알림 방법으로만 사용자를 식별하며, 해당 사용자에게는 `agent.approve` 권한이 필요합니다. 요청자는 요청을 승인할 수 없습니다. 아직 연결하지 않은 계정에는 알림 카드와 마찬가지로 일회용 링크를 비공개 메시지로 보냅니다.
- 버튼을 누르면 카드에서 버튼이 사라지고 요청 내용과 함께 승인 또는 거부한 사용자와 실행 여부가 한 줄로 표시됩니다. 버튼을 누른 사용자에게는 처리 성공 여부를 알립니다.
- 다른 곳에서 이미 승인 또는 거부한 요청이나 같은 사용자가 이미 검토한 요청은 버튼을 눌러도 상태가 바뀌지 않습니다. 카드에는 현재 상태가 표시됩니다.
- DingTalk 카드는 템플릿에 `approve_*` 및 `reject_*` 변수가 있을 때만 두 버튼을 표시합니다. [DingTalk 대화형 카드](#dingtalk-대화형-카드)를 참조합니다.

## 제한 사항

- Mole Agent는 텍스트 메시지와 서식 있는 메시지의 텍스트를 읽습니다. WeCom에서는 음성 메시지의 텍스트도 읽습니다. 이미지와 파일은 무시합니다.
- 커넥터를 담당하는 서버가 중지되면 다른 서버가 약 1분 안에 커넥터를 인계받습니다. 이 시간 동안 들어온 질문은 연결이 복구된 후 플랫폼이 다시 전달할 때만 응답합니다. Teams에는 이 제한이 적용되지 않습니다. 콜백을 받은 서버가 해당 콜백을 처리합니다.
- WeCom 응답은 봇 연결을 유지하는 서버에서만 전송할 수 있습니다. 다른 서버에서 응답 생성이 완료되면 연결을 유지하는 서버로 전달하며, 일반적으로 몇 초 안에 도착합니다.
- WeCom에서는 대화별로 분당 30개, 시간당 1,000개의 메시지를 허용합니다.
- Telegram 메시지는 최대 4,096자까지 담을 수 있습니다. 이보다 긴 응답은 여러 메시지로 나누어 전송합니다.
