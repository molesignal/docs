MoleSignal은 아직 1.0 이전 버전입니다. 이 페이지에서는 배포 계획과 운영에 영향을 주는 제한 사항을 설명합니다.

## 배포

- **인계 지연.** 선행 기록 로그(WAL)는 오브젝트 스토어에 저장되므로 수집 노드가 손실되어도 수신 확인을 마친 레코드는 유실되지 않습니다. 다만 아직 플러시하지 않은 레코드는 `[wal].lease_secs`(기본값 15초)가 지난 뒤 다른 수집 노드가 인계할 때까지 쿼리할 수 없습니다. [내구성과 인계](/ko/architecture#내구성-및-인계)를 참조합니다.
- **단일 노드에서 실행하는 작업.** 기본 `alert` 노드는 클러스터 간 이벤트 푸시와 가십, 서비스 그래프 재계산, APM 롤업, 상태 페이지 유지 관리, 신세틱 모니터링 자동화, 느린 쿼리 분석, 인시던트 근본 원인 분석을 실행합니다. `alert` 노드 수를 늘려도 이러한 작업의 처리 용량은 늘어나지 않습니다. 기본 노드가 클러스터 구성에서 빠지면 다른 노드에서 작업을 재개합니다. [역할 기반 배포](/ko/deployment/role-based#알림-노드-간-작업-분담)를 참조합니다.
- **PostgreSQL만 지원.** 메타데이터 데이터베이스로 PostgreSQL만 지원합니다.
- **구성 적용 시 재시작 필요.** 실행 중인 프로세스는 구성 파일의 변경 사항을 적용하지 않습니다. [구성](/ko/configuration)을 참조합니다.
- **상위 버전으로만 마이그레이션.** 이전 빌드는 최신 빌드에서 마이그레이션한 데이터베이스를 열 수 없습니다. 1.0 이전 빌드에서는 기본 스키마가 바뀔 수 있습니다. [업그레이드](/ko/upgrade)를 참조합니다.

## 수집

- **요청 크기.** 요청 본문이 2 MiB(네이티브 JSON 수집의 경우 16 MiB)를 초과하면 `413`을 반환합니다.
- **OTLP over HTTP 압축.** 압축된 요청 본문에는 `400`을 반환합니다. 전송 측에서 압축을 비활성화합니다.
- **히스토그램 버킷.** OTLP 히스토그램은 `count`, `sum`, `min`, `max`를 저장합니다. 버킷 경계값, 버킷별 개수, 요약 분위수는 저장하지 않습니다.
- **중복 스팬.** 동일한 `trace_id`와 `span_id`로 다시 전송한 스팬은 폐기합니다.
- **Loki 푸시.** 엔드포인트는 JSON 요청 형식만 디코딩합니다. Promtail과 Grafana Alloy처럼 snappy로 압축한 protobuf를 사용하는 전송 도구는 이 엔드포인트로 푸시할 수 없습니다.
- **Prometheus remote_write.** 네이티브 히스토그램과 메트릭 메타데이터는 건너뜁니다.
- **TLS 없는 OTLP gRPC.** 수신기는 TLS를 종료하지 않습니다. 신뢰할 수 있는 네트워크를 벗어나는 트래픽을 처리하려면 수신기 앞에 TLS를 종료하는 프록시를 배치합니다.
- **요청 속도 제한.** `router` 역할만 요청을 제한합니다. 인증된 조직별로 요청 수를 집계하며, 각 라우터 복제본은 별도로 집계합니다.
- **플랫폼 스트림.** `_molesignal`, `_synthetic_results`, `_audit`, `_agent_model_traces`, `_agent_score_traces`에는 MoleSignal만 기록할 수 있으며, 공개 수집 요청은 거부합니다. [플랫폼 스트림](/ko/streams#플랫폼-스트림)을 참조합니다.

## 쿼리

- **긴 시간 범위의 쿼리는 비동기로 실행.** 쿼리의 예상 행 수가 `[querier].auto_async_threshold_rows`에 도달하면 `202`와 함께 진행 상황을 추적할 작업을 반환합니다. 기본 설정에서는 약 13.9시간 범위에 해당합니다. 요청 내에서 쿼리를 실행하려면 `Prefer: respond-sync`를 전송합니다. [쿼리](/ko/query#시간-범위-및-비동기-작업)를 참조합니다.
- **PromQL 일부 지원.** 엔진은 PromQL의 일부 기능만 구현합니다. [PromQL 지원 매트릭스](/ko/query/promql-subset)를 참조합니다.
- **쿼리당 행 수.** `[querier].max_scan_rows`(기본값 1억)보다 많은 행을 읽는 쿼리에는 `400`을 반환합니다. 시간 범위를 좁히거나 필터를 추가합니다. PromQL은 각 셀렉터에 제한을 적용합니다.
- **역할 분리형 클러스터에서 최신 데이터 조회.** 쿼리는 카탈로그에 나열된 파일을 읽습니다. 따라서 수집 노드가 아직 버퍼에 보관하는 레코드는 `[intake].flush_interval_secs` 이내에 다음 플러시가 완료되면 조회할 수 있습니다. `standalone` 노드는 자체 버퍼도 읽습니다. 알림 규칙은 기본적으로 **설정 → 알림 평가**의 평가 지연 시간(60초)만큼 평가 구간을 과거로 이동합니다. [평가 지연](/ko/alerting/rules#평가-지연)을 참조합니다.

## 알림

- **실시간 규칙 집계는 메모리에 보관.** `real_time` 규칙은 쓰기 요청을 받는 모든 노드에서 레코드 수를 집계합니다. 규칙을 담당하는 알림 노드는 매초 집계값을 합산하므로 레코드를 기록한 후 최대 1초 안에 인시던트가 열립니다. 노드가 재시작하면 해당 노드의 집계값만 유실됩니다. 집계값을 읽을 수 없는 노드는 해당 초의 합산에서 제외합니다. 노드는 클러스터 Bearer 토큰으로 서로의 집계값을 읽으며, 페더레이션으로 연결된 클러스터 간에는 합산하지 않습니다. 쿼리문은 `SELECT count(*) FROM <stream> [WHERE <condition>]` 형식으로 제한합니다. [실시간 규칙](/ko/alerting/rules#실시간-규칙)을 참조합니다.

## 보안 및 ID

- **내부 gRPC는 인증하지 않음.** 포트 `5082`는 인증 없이 노드 간 트래픽을 전달합니다. 이 포트는 프라이빗 네트워크에서만 사용합니다.
- **패스키는 하나의 도메인 이름에 연결.** `[http].external_url`에 도메인 이름을 사용하는 HTTPS URL을 설정해야 합니다. 다른 호스트 이름으로 콘솔을 열면 패스키가 작동하지 않습니다.
- **비밀번호 재설정에 이메일 필요.** 비밀번호를 재설정할 때 이메일로 링크를 보내므로 `[notify.smtp]`와 `[http].external_url`을 구성해야 합니다.
- **승인 없는 셀프서비스 가입에 이메일 필요.** 가입 시 이메일 주소를 먼저 확인합니다. `[notify.smtp]`와 `[http].external_url`을 구성하지 않으면 모든 신규 계정에 관리자 승인이 필요합니다.
- **로그인 시도는 주소별로 집계.** [클라이언트 IP 인식](/ko/settings/platform#클라이언트-ip-식별)에서 올바른 주소를 식별해야 합니다. 퍼블릭 프록시 또는 CDN을 사용하면서 클라이언트 IP 인식을 구성하지 않으면 모든 사용자가 하나의 주소를 공유하므로 한 사용자의 시도가 다른 사용자의 로그인까지 차단할 수 있습니다. 기본적으로 사설 주소는 집계하지 않습니다. 따라서 내부 배포 환경이나 클라이언트 IP 인식을 구성하지 않은 프록시 뒤에서는 계정별 제한만 적용합니다.
- **계정별 제한은 계정 잠금과 다름.** 제3자가 계정을 잠글 수 없도록 로그인 속도가 제한된 계정에도 하루 약 1,400회의 비밀번호 추측 시도를 허용합니다. 다단계 인증을 사용하는 계정에는 비밀번호를 맞혀도 로그인할 수 없습니다. 다른 사람이 로그인 시도 한도를 계속 소진하면 해당 주소에서 로그인한 적이 없는 계정 소유자는 계속 기다려야 할 수 있습니다. 이 경우 패스키, 싱글 사인온 또는 비밀번호 재설정으로 로그인할 수 있습니다.
- **LDAP 디렉터리의 잠금 정책.** 디렉터리 자체의 잠금 정책이 먼저 적용되면 제3자가 이 정책을 통해 디렉터리 계정을 잠글 수 있습니다. [로그인 제한](/ko/settings/platform#로그인-제한)을 디렉터리의 제한보다 낮게 설정합니다.
- **세션.** 계정 설정 페이지에서는 현재 브라우저의 세션만 관리합니다.

## 보고서

- **PDF 및 PNG 렌더링**에는 헤드리스 Chrome이 필요합니다. 릴리스 컨테이너 이미지에는 Chromium이 포함되어 있습니다. 바이너리로 설치한 경우 Chrome을 설치해야 하며, `[scheduled_reports.renderer].base_url`로 웹 UI에 접속할 수 있어야 합니다.
