**커넥터**는 외부 플랫폼과의 연동을 관리합니다. 커넥터는 두 방향으로 작동합니다.

- **소스**는 다른 서비스에서 로그를 가져와 스트림에 기록합니다. MoleSignal은 일정에 따라 CloudWatch Logs, Kafka 토픽, S3 객체를 가져옵니다. Amazon Data Firehose, Cloudflare Logpush, Heroku는 MoleSignal에 로그를 푸시합니다.
- **대상**은 [예약된 파이프라인](/ko/pipelines#대상-스트림과-커넥터-전송)의 출력을 받습니다. Amazon S3 및 S3 호환 스토리지, Apache Kafka, 모든 HTTP 엔드포인트를 대상으로 사용할 수 있습니다.

| 유형 | 커넥터 | 방향 | 인증 |
|---|---|---|---|
| `aws_cloudwatch_logs` | AWS CloudWatch Logs | 소스, 30초마다 가져오기 | [AWS 자격 증명](#aws-인증) |
| `kafka_source` | Kafka 토픽 | 소스, 30초마다 가져오기 | 없음, SASL 또는 클라이언트 인증서 |
| `s3_source` | S3 객체 | 소스, 30초마다 가져오기 | AWS 자격 증명 |
| `aws_kinesis_firehose` | Amazon Data Firehose | 소스, 푸시 | [푸시 토큰](#푸시-소스) |
| `cloudflare_logpush` | Cloudflare Logpush | 소스, 푸시 | 푸시 토큰 |
| `heroku_drain` | Heroku 로그 드레인 | 소스, 푸시 | 푸시 토큰 |
| `s3` | Amazon S3 | 대상 | AWS 자격 증명 |
| `kafka` | Apache Kafka | 대상 | 없음, SASL 또는 클라이언트 인증서 |
| `http` | HTTP / 웹훅 | 대상 | 없음, Bearer 토큰, 기본 인증, 사용자 지정 헤더 또는 HMAC 서명 |

## 커넥터 만들기

<Steps>
  <Step title="커넥터 페이지 열기">
    **파이프라인 → 커넥터**로 이동합니다. 페이지에 **소스**와 **대상** 목록이 표시됩니다.
  </Step>
  <Step title="유형 선택">
    **새 커넥터**를 클릭하고 연결할 서비스를 선택합니다.
  </Step>
  <Step title="설정 입력">
    조직 내에서 고유한 **이름**을 입력합니다. 커넥터가 데이터를 읽어 올 위치나 전송할 위치를 입력하고 **인증** 방식을 선택합니다.
  </Step>
  <Step title="테스트 및 만들기">
    저장하기 전에 **연결 테스트**를 클릭해 설정을 확인한 다음 **커넥터 만들기**를 클릭합니다. 푸시 소스는 직접 연결할 대상이 없으므로 테스트를 제공하지 않습니다.
  </Step>
</Steps>

API에서 커넥터는 `name`, `kind`, `configJson`으로 구성되며, `configJson`의 키는 유형에 따라 다릅니다. `configJson`의 `auth`는 인증 방식을 지정하며, 각 방식은 서로 다른 키를 사용합니다. 필수 키가 누락되었거나, 쌍으로 필요한 자격 증명 중 하나만 있거나, 선택한 `auth`에서 사용하지 않는 키를 포함하면 저장 시 API가 `400`을 반환합니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "archive",
        "kind": "s3",
        "configJson": {
          "bucket": "acme-logs",
          "region": "eu-west-1",
          "prefix": "pipelines/checkout/",
          "auth": "assume_role",
          "roleArn": "arn:aws:iam::123456789012:role/molesignal-delivery"
        }
      }'
```

## 시크릿

`configJson`에서 다음 키에 시크릿을 저장합니다.

| 유형 | 시크릿 키 |
|---|---|
| `s3`, `aws_cloudwatch_logs` | `accessKey`, `secretKey`, `sessionToken` |
| `aws_kinesis_firehose`, `cloudflare_logpush`, `heroku_drain` | `pushToken` |
| `kafka` | `saslPassword`, `tlsClientKey` |
| `http` | `url`, `bearerToken`, `basicPassword`, `headerValue`, `hmacSecret` |

API는 시크릿 값을 반환하지 않습니다. 응답은 시크릿 값을 `***`로 표시하고 값이 저장된 시크릿의 키를 `secretKeys`에 나열합니다.

```json
{
  "kind": "kafka",
  "configJson": {
    "brokers": "b-1.example.com:9096",
    "topic": "logs",
    "tls": true,
    "auth": "sasl_scram_sha_512",
    "saslUsername": "molesignal",
    "saslPassword": "***"
  },
  "secretKeys": ["saslPassword"]
}
```

- 업데이트 요청에서 시크릿 값으로 `***`를 보내면 저장된 값을 유지합니다. 따라서 자격 증명을 다시 입력하지 않고 커넥터의 이름을 바꾸거나, 커넥터를 비활성화하거나, 연결 위치를 변경할 수 있습니다. UI에서 이미 저장한 시크릿의 입력란을 비워 두면 기존 값을 유지합니다.
- 업데이트 요청에서 시크릿을 생략하면 해당 시크릿을 삭제합니다.
- 업데이트 요청에서 `kind`를 변경하면 저장된 시크릿을 모두 삭제합니다.

MoleSignal은 `MS_CIPHER_KEY`의 루트 키로 시크릿을 다른 설정과 별도로 암호화하며(AES-256-GCM), 시크릿을 평문으로 저장하지 않습니다. MoleSignal은 토큰의 SHA-256 해시로 푸시 소스를 찾습니다. 루트 키를 교체할 때 `molesignal rewrap-kek` 명령은 커넥터 시크릿을 다른 시크릿과 함께 다시 암호화합니다. [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다.

## 소스

### 푸시 소스

세 푸시 소스는 같은 방식으로 설정합니다. **`pushToken`**과 **`target_stream`**을 지정해 커넥터를 생성한 다음, 플랫폼에서 해당 엔드포인트를 지정합니다. 이 엔드포인트는 JWT를 사용하지 않습니다. 요청은 플랫폼이 지원하는 방식으로 전달한 푸시 토큰으로 인증합니다.

| 방식 | 사용 플랫폼 |
|---|---|
| `X-Connector-Token` 헤더 | Cloudflare처럼 헤더를 구성할 수 있는 플랫폼 |
| `X-Amz-Firehose-Access-Key` 헤더 | 이 헤더를 자동으로 보내는 Amazon Data Firehose |
| `?token=` 쿼리 매개변수 | Heroku처럼 헤더를 설정할 수 없는 플랫폼 |

UI는 커넥터를 생성할 때 토큰을 만들고, 플랫폼에 입력할 엔드포인트와 함께 한 번만 표시합니다. 토큰은 다시 조회할 수 없습니다. **새 토큰 생성**을 선택하고 커넥터를 저장하면 기존 토큰이 교체됩니다. API에서는 16자 이상의 `pushToken`을 지정합니다. 같은 유형에서는 토큰 하나로 커넥터 하나에만 접근할 수 있습니다. 이미 사용 중인 토큰을 지정하면 `409`를 반환합니다. 토큰이 없거나 알 수 없는 토큰을 보내거나 비활성화된 커넥터로 요청하면 `401`을 반환합니다. 토큰이 없는 커넥터는 어떤 요청도 수락하지 않습니다.

`Content-Encoding: gzip`으로 전송한 요청 본문은 자동으로 압축을 해제합니다. 이벤트는 다른 데이터와 같은 수집 경로를 거칩니다. 쓰기 시 스키마 적용, [파이프라인](/ko/pipelines), [마스킹](/ko/security)이 모두 적용됩니다.

<Tabs>
  <Tab title="Amazon Data Firehose">
    `kind: "aws_kinesis_firehose"`를 지정해 커넥터를 생성한 다음, Firehose 스트림의 대상으로 **HTTP 엔드포인트**를 선택합니다.

    - **HTTP 엔드포인트 URL**: `https://molesignal.example.com/api/v1/_kinesis_firehose`
    - **액세스 키**: 푸시 토큰을 입력합니다. Firehose는 이 토큰을 `X-Amz-Firehose-Access-Key`로 보냅니다.

    MoleSignal은 각 레코드를 base64로 디코딩하고 줄바꿈을 기준으로 나눈 다음, 각 줄을 JSON으로 파싱합니다. 일반 텍스트는 `message` 필드에 넣습니다. MoleSignal은 Firehose가 기대하는 확인 응답인 `200`을 반환합니다.
  </Tab>
  <Tab title="Cloudflare Logpush">
    `kind: "cloudflare_logpush"`를 지정해 커넥터를 생성한 다음, HTTP 대상을 사용하는 Logpush 작업을 생성합니다. Cloudflare는 `header_` 쿼리 매개변수를 요청 헤더로 변환하므로 토큰을 `X-Connector-Token`에 담아 보냅니다.

    ```text
    https://molesignal.example.com/api/v1/_cloudflare?header_X-Connector-Token=<pushToken>
    ```

    Cloudflare는 gzip으로 압축한 NDJSON을 전송하며, 각 줄은 이벤트 하나가 됩니다. 엔드포인트는 `204 No Content`를 반환합니다.
  </Tab>
  <Tab title="Heroku">
    `kind: "heroku_drain"`을 지정해 커넥터를 생성한 다음, 드레인을 추가합니다. Heroku는 사용자 지정 헤더를 설정할 수 없으므로 토큰을 URL에 담아 보냅니다.

    ```bash
    heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
    ```

    각 로그 줄은 `message`와 `source: "heroku"`를 포함하는 이벤트가 됩니다. 엔드포인트는 `204 No Content`를 반환합니다.
  </Tab>
</Tabs>

<Tip>
  첫 데이터가 도착하면 `target_stream`을 생성합니다. 다른 스트림과 마찬가지로 새 필드가 나타날 때마다 스키마를 갱신합니다. `target_stream`을 생략하면 소스별 기본값인 `kinesis`, `cloudflare`, `heroku` 중 하나를 사용합니다.
</Tip>

### CloudWatch Logs

CloudWatch Logs는 **풀** 소스입니다. MoleSignal은 푸시를 받는 대신 30초마다 `FilterLogEvents`를 호출합니다. 처음 실행할 때는 최근 5분간의 이벤트를 읽습니다. 이후에는 마지막으로 성공한 실행이 끝난 위치에서 이어서 읽습니다. 읽거나 쓰지 못한 이벤트는 다음 실행에서 다시 읽습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "cw-prod",
        "kind": "aws_cloudwatch_logs",
        "configJson": {
          "region": "ap-southeast-1",
          "logGroup": "/aws/lambda/checkout",
          "auth": "node_role",
          "targetStream": "cloudwatch"
        }
      }'
```

| 필드 | 설명 |
|---|---|
| `region` / `logGroup` | 필수 항목입니다. 읽을 CloudWatch 리전과 로그 그룹입니다. |
| `auth` 및 하위 키 | 자격 증명입니다. 로그 그룹에 대한 `logs:FilterLogEvents` 권한이 필요합니다. [AWS 인증](#aws-인증)을 참조합니다. |
| `targetStream` | 대상 스트림입니다. 기본값은 `default`입니다. |

각 커넥터는 한 번에 노드 하나만 폴링합니다. `alert` 노드는 커넥터를 나눠 맡으며, 각 노드는 폴링하기 전에 커넥터를 선점합니다. [알림 노드 간 작업 분담](/ko/deployment/role-based#알림-노드-간-작업-분담)을 참조합니다. 각 이벤트는 `message`, `log_stream`, `log_group`을 포함하는 로그가 됩니다. 비활성화된 커넥터는 폴링하지 않습니다.

### Kafka 토픽

`kafka_source` 커넥터는 30초마다 토픽을 읽으며, 마지막으로 쓰기를 완료한 위치에서 이어서 읽습니다. 컨슈머 그룹에 가입하지 않고 파티션을 직접 할당받으며, 오프셋은 MoleSignal에 저장합니다. 따라서 토픽을 읽을 권한만 필요하며, 클러스터에 컨슈머 그룹이 표시되지 않습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "orders",
        "kind": "kafka_source",
        "configJson": {
          "brokers": "b-1.example.com:9096,b-2.example.com:9096",
          "topic": "orders",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "<password>",
          "targetStream": "orders",
          "startFrom": "latest"
        }
      }'
```

| 필드 | 설명 |
|---|---|
| `brokers`, `topic`, `tls`, `tlsCaCert`, `auth` 및 하위 키 | [Kafka 대상](#apache-kafka)과 동일합니다. |
| `targetStream` | 대상 스트림입니다. 기본값은 `default`입니다. |
| `startFrom` | 처음 읽기 시작할 위치입니다. 기본값인 `latest`는 지금부터 도착하는 메시지를 읽고, `earliest`는 브로커에 보관된 모든 메시지를 읽습니다. 나중에 추가한 파티션은 처음부터 읽습니다. UI: **읽기 시작 위치**. |

- 메시지 값이 JSON 객체이면 해당 객체의 필드를 로그 필드로 사용합니다. 다른 값은 `message`에 넣습니다. 각 로그에는 `kafka_topic`, `kafka_partition`, `kafka_offset`, `source`도 포함합니다. 메시지에 키가 있으면 `kafka_key`도 포함합니다. 로그 시간에는 메시지의 타임스탬프를 사용합니다.
- 한 번에 최대 10,000개 메시지 또는 32 MiB를 읽습니다. 읽을 메시지가 남아 있으면 즉시 다음 읽기를 시작하며, 한 번의 풀 작업은 최대 2분 동안 실행합니다.
- 로그 쓰기를 완료한 후에만 오프셋을 갱신합니다. 읽기나 쓰기에 실패하면 30초 후 같은 위치에서 재시도하므로 메시지를 두 번 쓸 수는 있지만 잃지는 않습니다. 브로커의 보존 기간이 지나 오프셋이 만료되면 브로커에 남아 있는 가장 오래된 메시지부터 이어서 읽습니다.
- 오프셋은 토픽별로 관리하므로 `topic`을 변경하면 `startFrom`부터 다시 읽습니다.

### S3 객체

`s3_source` 커넥터는 30초마다 AWS S3 또는 S3 호환 스토어의 버킷에서 객체 목록을 가져오고, 아직 읽지 않은 객체를 오래된 순서대로 읽습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "elb-logs",
        "kind": "s3_source",
        "configJson": {
          "bucket": "acme-logs",
          "region": "us-east-1",
          "prefix": "AWSLogs/123456789012/",
          "auth": "node_role",
          "targetStream": "elb",
          "startFrom": "latest"
        }
      }'
```

| 필드 | 설명 |
|---|---|
| `bucket`, `region`, `endpoint`, `virtualHostedStyle`, `auth` 및 하위 키 | [S3 대상](#amazon-s3)과 동일합니다. 자격 증명에는 버킷에 대한 `s3:ListBucket` 권한과 객체에 대한 `s3:GetObject` 권한이 필요합니다. |
| `prefix` | 이 접두사 아래의 객체만 읽습니다. 풀 작업마다 해당 접두사 아래의 전체 목록을 가져오므로 소스마다 전용 접두사를 지정합니다. |
| `targetStream` | 대상 스트림입니다. 기본값은 `default`입니다. |
| `startFrom` | 처음 읽기 시작할 위치입니다. 기본값인 `latest`는 이전 5분 동안 추가된 객체와 앞으로 추가되는 객체를 읽고, `earliest`는 접두사 아래의 모든 객체를 읽습니다. UI: **읽기 시작 위치**. |

- 객체를 줄 단위로 읽습니다. 줄이 JSON 객체이면 해당 객체의 필드를 로그 필드로 사용합니다. CloudTrail이 기록하는 형식처럼 `Records`만 있는 줄은 레코드마다 로그 하나를 생성합니다. 그 외의 줄은 `message`에 넣습니다. 이름이 `.gz` 또는 `.zst`로 끝나는 객체는 해당 형식에 맞게 압축을 해제합니다. 각 로그에는 `s3_bucket`, `s3_key`, `source`도 포함합니다. 로그 시간에는 객체의 마지막 수정 시간을 사용합니다.
- 한 번의 풀 작업은 객체 100개 또는 로그 50,000개에 도달할 때까지 읽습니다. 읽을 객체가 남아 있으면 최대 2분 동안 다음 읽기를 즉시 이어갑니다.
- 로그 쓰기를 완료한 후에만 읽기 상태를 갱신합니다. 객체를 가져오지 못하면 해당 위치에서 풀 작업을 중단하고 30초 후 재시도하므로 로그를 두 번 쓸 수는 있지만 잃지는 않습니다.
- 읽을 수 없는 객체는 건너뛰고 커넥터에 표시합니다. 재시도하면 뒤에 있는 모든 객체의 처리가 지연되기 때문입니다. 손상된 객체, 크기가 256 MiB를 초과하는 객체, 압축 해제 후 크기가 512 MiB를 초과하는 객체, 로그가 100만 개를 초과하는 객체, 64 MiB를 초과하는 줄이 있는 객체가 이에 해당합니다.
- 객체는 키와 수정 시간을 기준으로 식별하며, 5분의 허용 범위를 적용합니다. 이 범위 안에서 같은 키로 다시 쓴 객체는 다시 읽지 않습니다. 이미 읽은 가장 최신 객체보다 수정 시간이 5분 넘게 오래된 객체는 아예 읽지 않습니다. S3는 멀티파트 업로드가 시작된 시간을 기준으로 수정 시간을 기록하므로, 이 범위보다 오래 걸린 업로드는 읽지 않습니다.

### 풀 작업 상태 확인

커넥터 페이지에서 소스가 마지막으로 데이터를 수신한 시간을 확인할 수 있습니다. 마지막 읽기에 실패한 소스는 해당 시간 옆에 경고를 표시합니다. 경고의 툴팁과 커넥터 설정에서 실패 원인을 확인할 수 있으며, 가장 최근에 건너뛴 항목도 커넥터 설정에 표시합니다. API에서 `readState`는 각각 `atTime`과 `text`를 포함하는 `lastError` 및 `lastWarning`과 현재 읽기 위치인 `position`을 담습니다. 커넥터를 저장해도 읽기 위치는 유지됩니다.

## 대상

대상은 예약된 파이프라인의 단계를 거치는 모든 이벤트를 수신합니다. **대상 추가 → 커넥터**를 선택해 플로의 **대상**에 커넥터를 추가합니다. 전송에 실패하면 같은 실행 내에서 재시도합니다. 재시도 후에도 커넥터가 받지 못한 이벤트는 데드 레터 스트림으로 보냅니다. [재시도 및 데드 레터](/ko/pipelines#재시도-및-데드-레터)를 참조합니다.

꺼진 대상은 이벤트를 수신하지 않습니다. 실행할 때마다 해당 커넥터를 건너뛰고 실행 결과의 `warning`에 커넥터 이름을 표시합니다. 건너뛴 이벤트는 실패로 집계하지 않으며, 데드 레터로 보내지 않습니다. 커넥터를 다시 켜도 이 이벤트를 전송하지 않습니다. 편집기에서 꺼진 커넥터는 **꺼짐**으로 표시됩니다.

| 유형 | 페이로드 |
|---|---|
| `s3` | 배치마다 JSON Lines 객체 하나를 `s3://<bucket>/<prefix><id>.jsonl`에 `PUT`으로 전송합니다. |
| `kafka` | 토픽에 이벤트당 메시지 하나를 발행합니다. 메시지의 JSON 페이로드는 이벤트입니다. |
| `http` | 배치를 NDJSON 또는 단일 JSON 배열로 전송합니다. 배치가 크면 여러 요청으로 나누고, 그 외에는 한 요청으로 전송합니다. |

### HTTP / 웹훅

| 필드 | 참고 사항 |
|---|---|
| `url` | 필수입니다. `http://` 또는 `https://`로 시작하는 절대 URL을 지정합니다. URL의 경로나 쿼리에 키 등의 인증 정보가 포함되는 경우가 많으므로 비밀로 저장합니다. 응답에는 스킴, 호스트, 포트로 구성된 `urlOrigin`만 표시합니다. URL에 사용자 이름과 비밀번호를 넣으면 거부합니다. 대신 `basic`을 사용합니다. |
| `method` | `post`(기본값) 또는 `put`입니다. |
| `format` | `ndjson`(기본값)은 이벤트를 한 줄에 하나씩 `application/x-ndjson`으로 전송합니다. `json`은 단일 JSON 배열을 `application/json`으로 전송합니다. |

| `auth` | UI | 키 | 요청 |
|---|---|---|---|
| `none` | **없음** | | 인증 정보를 보내지 않습니다. |
| `bearer` | **Bearer 토큰** | `bearerToken` | `Authorization: Bearer <token>` |
| `basic` | **기본 인증** | `basicUsername`, `basicPassword` | HTTP 기본 인증입니다. `https` 연결에서 사용합니다. |
| `header` | **사용자 지정 헤더** | `headerName`, `headerValue` | `X-API-Key` 또는 `DD-API-KEY`와 같이 지정한 헤더에 값을 넣어 전송합니다. |
| `hmac` | **HMAC 서명** | `hmacSecret` | 요청 본문의 서명입니다. 비밀 키는 16자 이상이어야 합니다. |

전송 시 자동으로 설정하는 헤더는 사용자 지정 헤더로 사용할 수 없습니다: `Host`, `Content-Type`, `Content-Length`, `Content-Encoding`, `Transfer-Encoding`, `Connection`, `X-MoleSignal-Timestamp`, `X-MoleSignal-Sign`.

전송에는 다음 규칙을 적용합니다.

- 4 MiB를 초과하는 배치는 여러 요청으로 나눕니다. 이벤트 하나가 4 MiB를 초과하면 별도 요청으로 전송합니다.
- 모든 `2xx` 상태를 전송 성공으로 처리합니다. 그 외의 상태는 전송 실패로 처리합니다. 리디렉션은 따르지 않으며 전송 실패로 처리합니다.
- 요청의 타임아웃은 30초입니다.
- MoleSignal은 요청을 보내기 전에 호스트의 주소를 확인하고, 확인한 주소에만 연결합니다. URL에 직접 지정했든 DNS에서 확인했든 클라우드 메타데이터 서비스가 응답하는 주소는 거부합니다: `169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254`, `100.100.100.200`. 그 외의 사설 주소는 허용합니다.

#### HMAC 서명 검증

`hmac`을 사용하면 모든 요청에 다음 두 헤더가 포함됩니다.

| 헤더 | 내용 |
|---|---|
| `X-MoleSignal-Timestamp` | Unix 시간(초)으로 표시한 요청 시각입니다. |
| `X-MoleSignal-Sign` | `sha256=<hex>` 형식입니다. 공유 비밀 키로 `<timestamp>.<body>`의 HMAC-SHA256을 계산한 값입니다. |

요청을 검증하려면 타임스탬프, `.`, 요청 본문의 원시 바이트를 순서대로 이어 붙인 뒤 같은 비밀 키로 HMAC-SHA256을 계산합니다. 계산한 값과 서명을 상수 시간으로 비교합니다. 가로챈 요청을 나중에 다시 보내는 재전송 공격을 방지하려면 타임스탬프가 현재 시각보다 몇 분 이상 오래된 요청을 거부합니다.

```python
import hashlib
import hmac
import time


def verify(secret: bytes, timestamp: str, signature: str, body: bytes, tolerance: int = 300) -> bool:
    if abs(time.time() - int(timestamp)) > tolerance:
        return False
    signed = timestamp.encode() + b"." + body
    expected = "sha256=" + hmac.new(secret, signed, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## AWS 인증

S3와 CloudWatch Logs는 다음 다섯 가지 방식 중 하나로 AWS에 인증합니다.

| `auth` | UI | 키 | 자격 증명 |
|---|---|---|---|
| `access_key` | **액세스 키** | `accessKey`, `secretKey` | IAM 사용자의 장기 키입니다. |
| `temporary_key` | **임시 키** | `accessKey`, `secretKey`, `sessionToken` | AWS STS에서 발급하는 단기 키입니다. 함께 발급된 세션 토큰이 있어야 유효합니다. 만료되기 전에 교체합니다. |
| `node_role` | **노드 자격 증명** | | MoleSignal이 실행되는 노드의 자격 증명입니다. 키를 저장하지 않습니다. |
| `assume_role` | **역할 수임** | `roleArn`, 선택 사항: `accessKey` 및 `secretKey` | 조직의 외부 ID를 사용해 AWS STS를 통해 수임하는 역할입니다. |
| `web_identity` | **웹 자격 증명** | `roleArn` | 노드의 웹 자격 증명 토큰으로 수임하는 역할입니다. |

`auth`가 없으면 저장된 키에 따라 인증 방식을 결정합니다. 액세스 키가 있으면 `access_key`, `roleArn`이 있으면 `assume_role`, 둘 다 없으면 `node_role`을 사용합니다. `roleArn`의 형식은 `arn:aws:iam::<account>:role/<name>`입니다.

### 노드 자격 증명

`node_role`은 AWS SDK가 노드에서 찾은 자격 증명을 사용합니다. 여기에는 EKS의 서비스 계정용 IAM 역할(IRSA) 또는 EKS Pod Identity, ECS 태스크 역할, EC2 인스턴스 프로파일이 포함됩니다. 커넥터는 `AWS_ACCESS_KEY_ID`와 같이 노드 환경에 설정된 정적 키를 사용하지 않습니다.

<Warning>
  노드 자격 증명과 웹 자격 증명 토큰은 배포 환경에 속합니다. 배포 환경의 모든 조직이 `node_role`과 `web_identity`를 선택할 수 있습니다. 따라서 모든 조직의 커넥터는 노드 자격 증명으로 접근할 수 있는 리소스에 접근하고 노드의 토큰을 신뢰하는 모든 역할을 수임할 수 있습니다. 모든 조직에 허용해도 되는 권한만 부여합니다.
</Warning>

### 역할 수임

`assume_role`은 AWS STS에 역할의 1시간짜리 키를 요청하고 만료 5분 전에 키를 갱신합니다. 역할을 수임할 때는 노드 자격 증명을 기본 자격 증명으로 사용합니다. AWS에서 실행하지 않는 배포 환경에서는 **노드 ID 대신 액세스 키로 역할 수임**을 선택하고 IAM 사용자의 키를 입력합니다.

각 조직은 변경할 수 없는 고유한 외부 ID `molesignal-<organization ID>`를 사용해 역할을 수임합니다. 양식의 **외부 ID** 항목에 이 값이 표시되며, `GET /api/v1/connectors/aws-external-id`도 이 값을 반환합니다. 다른 조직이 ARN을 알아도 역할을 수임할 수 없도록 역할의 신뢰 정책에서 외부 ID를 필수 조건으로 지정합니다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "<ARN of the node role or IAM user>" },
      "Action": "sts:AssumeRole",
      "Condition": { "StringEquals": { "sts:ExternalId": "molesignal-<organization ID>" } }
    }
  ]
}
```

세션 이름은 `molesignal-<connector ID>`이며 AWS CloudTrail에도 이 이름으로 표시됩니다. 요청은 커넥터의 `region`에 해당하는 리전 STS 엔드포인트로 전송됩니다. 리전이 비어 있으면 `us-east-1`을 사용하고, 중국 리전에는 `amazonaws.com.cn` 도메인을 사용합니다.

### 웹 자격 증명

`web_identity`는 노드의 `AWS_WEB_IDENTITY_TOKEN_FILE`이 가리키는 웹 자격 증명 토큰으로 역할을 수임합니다. 예를 들어 EKS가 IRSA용으로 마운트하는 서비스 계정 토큰을 사용합니다. 커넥터에서 다른 파일을 지정할 수 없습니다. 역할의 신뢰 정책은 토큰을 발급하는 OIDC 공급자를 신뢰해야 합니다. 노드에 `AWS_WEB_IDENTITY_TOKEN_FILE`이 없으면 커넥터는 자격 증명을 얻지 못합니다.

커넥터는 `region`에 해당하는 리전 STS 엔드포인트에서 토큰을 교환합니다. 노드 환경에 `AWS_ENDPOINT_URL_STS`가 설정되어 있으면 해당 엔드포인트를 사용합니다. IRSA에서 가져온 노드 자격 증명에도 같은 규칙을 적용합니다.

## 연결 테스트

**연결 테스트**는 저장하기 전에 양식에 입력된 현재 설정을 테스트합니다. 시크릿 필드를 비워 두면 저장된 값을 사용합니다. 각 유형은 데이터 전송 또는 가져오기가 가능한지 확인하는 데 필요한 최소한의 작업만 수행합니다.

| 유형 | 테스트 |
|---|---|
| `s3` | 접두사 아래에 `.molesignal-connection-test` 객체를 쓰고, 정책에서 허용하면 삭제합니다. |
| `kafka` | 브로커에서 토픽 메타데이터를 읽어 연결, TLS, 인증이 정상이고 토픽이 존재하는지 확인합니다. 메시지는 쓰지 않습니다. |
| `http` | 테스트임을 나타내는 `"message": "MoleSignal connection test"`와 `"molesignal_connection_test": true`를 포함한 이벤트 하나를 전송합니다. |
| `aws_cloudwatch_logs` | 로그 그룹의 최근 1분간 이벤트 중 최대 하나를 읽습니다. 스트림에 아무것도 쓰지 않으며 읽기 위치를 변경하지 않습니다. |
| `kafka_source` | `kafka`와 마찬가지로 브로커에서 토픽 메타데이터를 읽습니다. 메시지를 읽지 않으며 읽기 위치를 변경하지 않습니다. |
| `s3_source` | 접두사 아래의 객체 하나를 나열해 자격 증명과 `s3:ListBucket` 권한을 확인합니다. 객체 내용을 읽지 않으며 읽기 위치를 변경하지 않습니다. |

테스트는 25초가 지나면 중단합니다. API에서는 `POST /api/v1/connectors/test`에 테스트할 `kind`와 `configJson`을 전달합니다. 같은 유형의 저장된 커넥터 `id`를 지정하면 `***`는 해당 커넥터에 저장된 시크릿을 나타냅니다. 작동할 수 없는 설정에는 저장할 때와 마찬가지로 `400`을 반환합니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "id": "<connector id>",
        "kind": "kafka",
        "configJson": {
          "brokers": "b-1.example.com:9096",
          "topic": "logs",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "***"
        }
      }'
```

```json
{ "ok": true, "code": "ok", "detail": null, "elapsedMs": 412 }
```

`elapsedMs`는 테스트에 걸린 시간입니다. 테스트에 실패하면 `code`에 원인을 표시하고, `detail`에 상대 시스템의 메시지를 최대 600자까지 담습니다.

| `code` | 의미 |
|---|---|
| `ok` | 연결에 성공했습니다. |
| `invalid` | 설정이 유효하지 않거나, 커넥터가 연결 대상이 없는 푸시 소스입니다. |
| `no_credentials` | AWS 자격 증명을 가져오지 못했습니다. 노드에 자격 증명이 없거나 요청한 유형의 자격 증명이 없습니다. |
| `denied` | 상대 시스템에서 자격 증명을 거부했거나 요청한 작업을 허용하지 않았습니다. |
| `not_found` | 버킷, 토픽, 로그 그룹 또는 주소가 존재하지 않습니다. |
| `tls` | TLS 핸드셰이크에 실패했습니다. 인증서를 신뢰할 수 없거나 상대 시스템이 인증서를 제시하지 않았습니다. |
| `unreachable` | 호스트 이름을 확인할 수 없거나 호스트에 연결할 수 없습니다. |
| `timeout` | 제한 시간 내에 응답을 받지 못했습니다. |
| `failed` | 그 밖의 오류가 발생했습니다. |

## API

| 엔드포인트 | 권한 | 용도 |
|---|---|---|
| `GET /api/v1/connectors` | `pipelines.read` | 조직의 커넥터 목록을 조회합니다. |
| `POST /api/v1/connectors` | `pipelines.edit` | 커넥터를 생성합니다. `enabled`의 기본값은 `true`입니다. |
| `GET /api/v1/connectors/{id}` | `pipelines.read` | 커넥터를 조회합니다. |
| `PUT /api/v1/connectors/{id}` | `pipelines.edit` | `name`, `kind`, `configJson`, `enabled`를 교체합니다. 모든 필드가 필수입니다. |
| `DELETE /api/v1/connectors/{id}` | `pipelines.edit` | 커넥터를 삭제합니다. |
| `POST /api/v1/connectors/test` | `pipelines.edit` | 설정을 저장하기 전에 테스트합니다. |
| `GET /api/v1/connectors/aws-external-id` | `pipelines.read` | 조직의 외부 ID를 `externalId`로 반환합니다. |

커넥터를 조회하면 `id`, `name`, `kind`, 시크릿을 마스킹한 `configJson`, `secretKeys`, `enabled`, `lastRunAt`, `readState`, `createdAt`, `updatedAt`을 반환합니다.

## 권한

`pipelines.read` 권한으로 커넥터 목록과 세부 정보, 외부 ID를 조회할 수 있습니다. `pipelines.edit` 권한으로 커넥터를 생성, 수정, 삭제, 테스트할 수 있습니다. 테스트는 저장된 시크릿을 사용해 요청자를 대신하여 다른 시스템에 연결하므로 `pipelines.edit` 권한이 필요합니다. 푸시 수신기는 푸시 토큰으로 인증하며 일반 로그인 JWT로 대체할 수 없습니다.
