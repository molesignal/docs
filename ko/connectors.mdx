A **커넥터**는 외부 플랫폼과의 관리형 통합입니다. 커넥터는 두 방향으로 동작합니다:

- **소스**는 다른 서비스에서 데이터를 가져와 스트림에 기록합니다. MoleSignal은 CloudWatch Logs, Kafka 토픽, S3 객체를 일정에 따라 가져옵니다. Amazon Data Firehose, Google Cloud Pub/Sub, Cloudflare Logpush, Heroku는 MoleSignal로 푸시하며, Firehose는 CloudWatch 메트릭도 전달합니다.
- **대상**은 [예약된 파이프라인](/ko/pipelines#싱크-및-커넥터-송신)의 출력을 받습니다: Amazon S3 및 S3 호환 스토리지, Apache Kafka, 모든 HTTP 엔드포인트.

| 종류 | 커넥터 | 방향 | 인증 |
|---|---|---|---|
| `aws_cloudwatch_logs` | AWS CloudWatch Logs | 소스, 30초마다 가져옴 | [AWS 자격 증명](#aws-인증) |
| `kafka_source` | Kafka 토픽 | 소스, 30초마다 가져옴 | 없음, SASL 또는 클라이언트 인증서 |
| `s3_source` | S3 객체 | 소스, 30초마다 가져옴 | AWS 자격 증명 |
| `gcp_pubsub_pull` | Google Cloud Pub/Sub 구독 | 소스, 30초마다 가져옴 | 서비스 계정 키 |
| `aws_cloudwatch_metrics`, `azure_monitor_metrics`, `gcp_monitoring_metrics`, `aliyun_cms_metrics`, `tencent_monitor_metrics`, `huawei_ces_metrics` | [클라우드 메트릭](#클라우드-메트릭) | 소스, 주기마다 가져옴 | 클라우드의 자격 증명 |
| `aws_kinesis_firehose` | Amazon Data Firehose | 소스, 푸시됨 | [푸시 토큰](#푸시-소스) |
| `gcp_pubsub_push` | Google Cloud Pub/Sub 푸시 | 소스, 푸시됨 | 푸시 토큰, 선택적으로 구독의 OIDC 토큰 |
| `cloud_events` | 클라우드 이벤트 버스 | 소스, 푸시됨 | 푸시 토큰 |
| `cloudflare_logpush` | Cloudflare Logpush | 소스, 푸시됨 | 푸시 토큰 |
| `heroku_drain` | Heroku 로그 드레인 | 소스, 푸시됨 | 푸시 토큰 |
| `s3` | Amazon S3 | 대상 | AWS 자격 증명 |
| `kafka` | Apache Kafka | 대상 | 없음, SASL 또는 클라이언트 인증서 |
| `http` | HTTP / 웹훅 | 대상 | 없음, 베어러 토큰, Basic 인증, 사용자 지정 헤더 또는 HMAC 서명 |

## 커넥터 만들기

<Steps>
  <Step title="커넥터 열기">
    **파이프라인 → 커넥터**로 이동합니다. 페이지에는 **소스**와 **대상**이 나열됩니다.
  </Step>
  <Step title="종류 선택">
    **새 커넥터**를 클릭하고 연결할 항목을 선택합니다.
  </Step>
  <Step title="설정 입력">
    조직 내에서 고유한 **이름**을 입력하고, 커넥터가 데이터를 읽어 오거나 전달할 위치를 입력한 뒤 **인증**을 선택합니다.
  </Step>
  <Step title="테스트 및 만들기">
    설정을 저장하기 전에 **연결 테스트**를 클릭해 설정을 시험한 뒤 **커넥터 만들기**를 클릭합니다. 푸시 소스는 연결할 대상이 없으므로 테스트를 제공하지 않습니다.
  </Step>
</Steps>

API에서는 커넥터가 `name`, `kind`, 그리고 종류에 따라 키가 달라지는 `configJson`으로 이루어집니다. `configJson`의 `auth`는 인증 방식을 지정하며, 각 방식은 자체 키를 사용합니다. 저장할 때 동작할 수 없는 설정은 `400`을 반환합니다: 필수 키를 빠뜨리거나, 자격 증명 쌍 중 하나만 제공하거나, 선택한 `auth`가 사용하지 않는 키를 포함한 경우입니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "archive",
        "kind": "s3",
        "configJson": {
          "bucket": "acme-logs",
          "region": "eu-west-1",
          "prefix": "pipelines/checkout/",
          "auth": "assume_role",
          "roleArn": "arn:aws:iam::123456789012:role/molesignal-delivery"
        }
      }'
```

## 시크릿

`configJson`의 다음 키는 시크릿을 저장합니다:

| 종류 | 시크릿 키 |
|---|---|
| `s3`, `aws_cloudwatch_logs` | `accessKey`, `secretKey`, `sessionToken` |
| `aws_kinesis_firehose`, `gcp_pubsub_push`, `cloud_events`, `cloudflare_logpush`, `heroku_drain` | `pushToken` |
| `aws_cloudwatch_metrics` | `accessKey`, `secretKey`, `sessionToken` |
| `azure_monitor_metrics` | `clientSecret` |
| `gcp_monitoring_metrics`, `gcp_pubsub_pull` | `serviceAccountKey` |
| `aliyun_cms_metrics`, `tencent_monitor_metrics`, `huawei_ces_metrics` | `accessKey`, `secretKey` |
| `kafka` | `saslPassword`, `tlsClientKey` |
| `http` | `url`, `bearerToken`, `basicPassword`, `headerValue`, `hmacSecret` |

시크릿은 API를 통해 절대 외부로 나가지 않습니다. 응답에는 해당 위치에 `***`가 표시되고, `secretKeys`에 값을 보유한 시크릿의 이름이 나열됩니다:

```json
{
  "kind": "kafka",
  "configJson": {
    "brokers": "b-1.example.com:9096",
    "topic": "logs",
    "tls": true,
    "auth": "sasl_scram_sha_512",
    "saslUsername": "molesignal",
    "saslPassword": "***"
  },
  "secretKeys": ["saslPassword"]
}
```

- `***`를 다시 보내는 업데이트는 저장된 값을 유지하므로, 자격 증명을 다시 입력하지 않고도 커넥터의 이름을 바꾸거나, 비활성화하거나, 다른 곳을 가리키게 할 수 있습니다. UI에서 저장된 시크릿을 비워 두면 해당 값이 유지됩니다.
- 업데이트에서 빠진 시크릿은 제거됩니다.
- `kind`를 변경하는 업데이트는 저장된 시크릿을 하나도 유지하지 않습니다.

MoleSignal은 다른 설정과 별도로 `MS_CIPHER_KEY`(AES-256-GCM)의 루트 키로 시크릿을 암호화하며, 어떤 시크릿도 평문으로 저장하지 않습니다. 푸시 소스는 토큰의 SHA-256으로 찾습니다. `molesignal rewrap-kek`는 루트 키가 교체되면 다른 시크릿과 함께 커넥터 시크릿을 다시 암호화합니다. 자세한 내용은 [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다.

## 소스

### 푸시 소스

다섯 가지 푸시 소스는 하나의 모델을 공유합니다. **`pushToken`**과 **`targetStream`**으로 커넥터를 만든 다음, 플랫폼이 해당 엔드포인트를 가리키도록 설정합니다. 이 엔드포인트는 JWT를 사용하지 않습니다. 요청은 플랫폼이 허용하는 방식으로 제공된 푸시 토큰으로 인증합니다.

| 방식 | 사용 플랫폼 |
|---|---|
| `X-Connector-Token` 헤더 | Cloudflare처럼 헤더를 설정할 수 있는 플랫폼 |
| `X-Amz-Firehose-Access-Key` 헤더 | 자동으로 전송하는 Amazon Data Firehose |
| `X-EventBridge-Signature-Token` 헤더 | Alibaba Cloud EventBridge |
| `?token=` 쿼리 파라미터 | Heroku, Pub/Sub처럼 헤더를 설정할 수 없는 플랫폼 |
| `Authorization: Basic`의 비밀번호 | 자격 증명을 주소에 넣는 플랫폼 |

UI는 커넥터를 만들 때 토큰을 생성하고, 플랫폼에 제공할 엔드포인트와 함께 한 번만 보여줍니다. 토큰은 다시 읽을 수 없습니다. **새 토큰 생성**은 커넥터를 저장할 때 토큰을 교체합니다. API에서는 16자 이상의 `pushToken`을 제공합니다. 하나의 토큰은 한 종류의 커넥터 하나를 엽니다. 이미 사용 중인 토큰은 `409`를 응답합니다. 토큰이 없거나 알 수 없는 토큰으로 요청하거나, 꺼진 커넥터에 요청하면 `401`을 응답합니다. 토큰이 없는 커넥터는 아무것도 받지 않습니다. 노드는 조회한 커넥터를 30초 동안 유지하므로, 커넥터를 끄거나 토큰을 교체하면 그 시간 안에 적용됩니다.

`Content-Encoding: gzip`으로 전송된 본문은 자동으로 압축 해제됩니다. Firehose 본문은 최대 64 MiB, 그 외는 최대 16 MiB이며, 압축 해제 후 기준입니다. 이벤트는 다른 모든 이벤트와 동일한 수집 경로를 거칩니다. 스키마 온 라이트(schema-on-write), [파이프라인](/ko/pipelines), [마스킹](/ko/security)이 모두 적용됩니다.

<Tabs>
  <Tab title="Amazon Data Firehose">
    `kind: "aws_kinesis_firehose"`로 커넥터를 만든 다음, Firehose 스트림의 대상으로 **HTTP 엔드포인트**를 선택합니다.

    - **HTTP 엔드포인트 URL**: `https://molesignal.example.com/api/v1/_kinesis_firehose`
    - **액세스 키**: 푸시 토큰입니다. Firehose는 이를 `X-Amz-Firehose-Access-Key`로 전송합니다.

    Firehose는 공개적으로 신뢰된 인증서를 사용하는 443 포트의 HTTPS로만 전달하므로, 사설 네트워크에 배포한 경우 공개 진입점이 필요합니다. [공개 액세스](/ko/public-access)를 참고하십시오. 스트림의 버퍼는 1~4 MiB로 유지합니다.

    MoleSignal은 각 레코드를 담고 있는 내용에 따라 개별적으로 읽습니다.

    | 레코드 | 변환 결과 |
    |---|---|
    | 구독 필터가 전송하는 대로 gzip 압축된 CloudWatch Logs 구독 메시지 | `logEvents`의 각 항목마다 하나의 로그 이벤트가 되며, 항목 자체의 시간에 `message`, `log_group`, `log_stream`, `account_id`, `region`, `event_id`, `source: "cloudwatch"`를 포함합니다. 구독을 만들 때 전송하는 상태 확인은 건너뜁니다. |
    | JSON, OpenTelemetry 1.0 또는 OpenTelemetry 0.7 출력 형식의 CloudWatch Metric Streams 레코드 | 메트릭 스트림의 메트릭 샘플입니다. 아래를 참고하십시오. |
    | 그 밖의 텍스트 | 줄마다 하나의 로그 이벤트가 됩니다. JSON 객체는 필드를 제공하고, 일반 텍스트는 `message`로 들어갑니다. |

    메트릭 스트림은 메트릭당 분당 하나의 집계를 전송합니다. 각 통계는 `aws_<namespace>_<metric>_<statistic>` 이름의 게이지 샘플이 되며, yet-another-cloudwatch-exporter가 이름을 붙이는 방식과 같습니다. 예: `aws_ec2_cpuutilization_average`, `aws_ec2_cpuutilization_maximum`, `aws_applicationelb_request_count_sum`. 네임스페이스는 `AWS/` 접두사를 제거하고, 메트릭 이름은 소문자가 대문자를 만나는 곳에서 단어로 나뉩니다. 통계는 `average`(샘플 수에 대한 합), `sum`, `sample_count`, `minimum`, `maximum` 및 스트림이 추가하는 백분위수(예: `p99`, `p99_9`)입니다. 레이블은 `account_id`, `region`, 그리고 차원마다 하나의 `dimension_<Name>`(예: `dimension_InstanceId`)입니다. `metric_unit`은 단위를 유지합니다.

    ```promql
    max by (dimension_InstanceId) (aws_ec2_cpuutilization_average)
    ```

    스트림의 파라미터로 설정된 `X-Amz-Firehose-Common-Attributes`는 해당 키를 모든 이벤트와 샘플에 추가합니다. 레코드에 이미 있는 필드가 우선합니다. `X-Amz-Firehose-Source-Arn`은 CloudWatch Logs 이벤트의 `region`을 제공하며, 해당 이벤트에는 region이 없습니다.

    응답은 Firehose 전달 사양을 따릅니다. 요청의 `requestId`, `timestamp`, 실패 시 `errorMessage`가 포함된 `application/json`입니다. 읽을 수 없는 레코드는 제외되고, 요청의 나머지 부분은 여전히 `200`으로 기록됩니다. 일시적으로 실패한 쓰기는 `429` 또는 `5xx`를 응답하며, Firehose가 재시도합니다. 64 MiB를 초과하는 본문은 `413`을 응답하며, Firehose는 재시도하거나 백업하지 않습니다. 기록된 지 30분 이내에 동일한 `X-Amz-Firehose-Request-Id`로 재시도된 전달은 다시 기록하지 않고 `200`으로 응답합니다.
  </Tab>
  <Tab title="Google Cloud Pub/Sub">
    `kind: "gcp_pubsub_push"`로 커넥터를 만듭니다. Log Router 싱크로 로그를 Pub/Sub 주제로 라우팅한 다음, 주제에 푸시 구독을 만듭니다. Pub/Sub은 사용자 지정 헤더를 설정할 수 없으므로 토큰이 URL로 전달됩니다.

    ```bash
    gcloud pubsub subscriptions create molesignal-push --topic=molesignal-logs --push-endpoint="https://molesignal.example.com/api/v1/_gcp_pubsub?token=<pushToken>"
    ```

    구독의 OIDC 토큰도 확인하려면 커넥터의 `oidcServiceAccount`를 서비스 계정 이메일로 설정하고 `--push-auth-service-account=<email>`로 구독을 만듭니다. 그러면 MoleSignal이 Google 키로 토큰을 검증하고 해당 서비스 계정만 허용합니다. 대상(audience)도 확인하려면 `oidcAudience`를 설정하고 동일한 값을 `--push-auth-token-audience`로 전달합니다.

    각 메시지는 하나의 요청입니다. 래핑된 본문과 래핑되지 않은 페이로드를 모두 허용합니다. Cloud Logging `LogEntry`는 하나의 로그 이벤트가 됩니다.

    | `LogEntry` | 이벤트 |
    |---|---|
    | `jsonPayload` | 해당 필드 |
    | `textPayload` | `message` |
    | `protoPayload`(감사 로그) | `proto_payload`, 여기서 `method_name`, `service_name`, `principal_email`을 추출 |
    | `severity` | 소문자로 변환한 `level` |
    | `logName`, `resource.type`, `insertId` | `log_name`, `resource_type`, `insert_id` |
    | `resource.labels`, `labels` | 각자의 이름으로 된 필드 |
    | `trace`, `spanId` | `projects/<id>/traces/` 접두사를 제거한 `trace_id`, `span_id` |
    | `httpRequest` | `http_request` |
    | `timestamp` | 이벤트의 시간. 없으면 `receiveTimestamp` 또는 게시 시간 |

    그 밖의 메시지 데이터는 하나의 이벤트가 되며, JSON 객체의 필드 또는 `message`로 된 텍스트입니다. 엔드포인트는 `204 No Content`를 응답하며, Pub/Sub은 이를 확인 응답으로 간주합니다. 읽을 수 없는 메시지는 확인 응답되고 제외됩니다. 일시적으로 실패한 쓰기는 확인 응답되지 않으므로 Pub/Sub이 다시 전달합니다. 기록된 지 30분 이내에 다시 전달된 메시지는 다시 기록하지 않고 확인 응답됩니다.
  </Tab>
  <Tab title="클라우드 이벤트 버스">
    `kind: "cloud_events"`로 커넥터를 만든 다음, 이벤트 버스가 `https://molesignal.example.com/api/v1/_cloud_events`를 가리키도록 설정합니다.

    | 전송자 | 설정 |
    |---|---|
    | Amazon EventBridge | **API 키** 연결을 사용하는 API 대상. 헤더 이름은 `X-Connector-Token`이고 값은 푸시 토큰입니다. |
    | Azure Event Grid | 엔드포인트가 `?token=<pushToken>`로 끝나는 웹후크 구독. 유효성 검사 핸드셰이크와 CloudEvents 스키마의 `OPTIONS` 핸드셰이크는 자동으로 응답합니다. |
    | Alibaba Cloud EventBridge | 푸시 토큰을 토큰으로 사용하는 HTTPS 대상이며, `X-EventBridge-Signature-Token`으로 전송합니다. |
    | Huawei Cloud EventGrid | `X-Connector-Token` 헤더를 사용하는 웹후크 대상. |
    | 기타 CloudEvents 전송자 | 위의 토큰 방식 중 하나. `https://user:<pushToken>@host/...`처럼 자격 증명을 주소에만 넣을 수 있는 전송자도 허용합니다. |

    본문은 하나의 이벤트 또는 이벤트 배열을 포함하며, 구조화 또는 바이너리 모드의 CloudEvents 1.0, Amazon EventBridge 이벤트 또는 Event Grid 스키마일 수 있습니다. 각 이벤트는 `targetStream`(기본값 `cloud_events`)에 하나의 로그 이벤트가 됩니다.

    | 필드 | 원본 |
    |---|---|
    | `event_id`, `event_source`, `event_type`, `event_subject` | CloudEvents `id`, `source`, `type`, `subject`; EventBridge `id`, `source`, `detail-type`; Event Grid `id`, `topic`, `eventType`, `subject` |
    | `account_id`, `region` | EventBridge `account`, `region`; Alibaba Cloud `aliyunaccountid`, `aliyunregionid`; Event Grid 주제의 구독 |
    | `resources` | EventBridge `resources` |
    | `data` | 하나의 JSON 필드로 된 페이로드. 텍스트 페이로드는 `message`로 들어갑니다. |
    | `event_format` | `cloudevents`, `eventbridge` 또는 `event_grid` |

    확장 속성은 이름을 유지합니다. 이벤트 자체의 시간이 해당 시간이 됩니다. 그 밖의 JSON 객체는 필드를 그대로 가진 하나의 이벤트가 됩니다. 동일한 소스와 ID로 30분 이내에 다시 전달된 이벤트는 두 번 기록되지 않습니다. 엔드포인트는 `200`을 응답하며, JSON이 아닌 본문에는 `400`을 응답합니다.
  </Tab>
  <Tab title="Cloudflare Logpush">
    `kind: "cloudflare_logpush"`로 커넥터를 만든 다음, HTTP 대상으로 Logpush 작업을 만듭니다. Cloudflare는 `header_` 쿼리 파라미터를 요청 헤더로 변환하므로 토큰이 `X-Connector-Token`으로 전달됩니다.

    ```text
    https://molesignal.example.com/api/v1/_cloudflare?header_X-Connector-Token=<pushToken>
    ```

    Cloudflare는 gzip으로 압축된 NDJSON을 전송하며, 각 줄은 하나의 이벤트가 됩니다. 엔드포인트는 `204 No Content`를 응답합니다.
  </Tab>
  <Tab title="Heroku">
    `kind: "heroku_drain"`으로 커넥터를 만든 다음, 드레인을 추가합니다. Heroku는 사용자 지정 헤더를 설정할 수 없으므로 토큰이 URL로 전달됩니다.

    ```bash
    heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
    ```

    각 로그 줄은 `message`와 `source: "heroku"`를 가진 이벤트가 됩니다. 엔드포인트는 `204 No Content`를 응답합니다.
  </Tab>
</Tabs>

<Tip>
  `targetStream`은 첫 전달 시 생성되며, 새 필드가 나타나면 스키마가 진화합니다. 다른 스트림과 마찬가지입니다. `targetStream`을 생략하면 소스별 기본값으로 대체됩니다: `kinesis`, `gcp`, `cloud_events`, `cloudflare`, `heroku`. Firehose 커넥터는 메트릭 샘플을 `metricsStream`에 쓰며, 기본값은 `cloudwatch`입니다.
</Tip>

### CloudWatch Logs

CloudWatch Logs는 **풀** 소스입니다. MoleSignal은 푸시를 받는 대신 30초마다 `FilterLogEvents`를 호출합니다. 첫 실행은 지난 5분을 읽습니다. 이후 각 실행은 마지막으로 성공한 실행이 끝난 지점에서 시작하므로, 읽거나 쓸 수 없었던 이벤트는 다음 실행에서 다시 읽습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "cw-prod",
        "kind": "aws_cloudwatch_logs",
        "configJson": {
          "region": "ap-southeast-1",
          "logGroup": "/aws/lambda/checkout",
          "auth": "node_role",
          "targetStream": "cloudwatch"
        }
      }'
```

| 필드 | 참고 |
|---|---|
| `region` / `logGroup` | 필수입니다. 읽을 CloudWatch 리전과 로그 그룹입니다. |
| `auth` 및 해당 키 | 자격 증명이며, 로그 그룹에 `logs:FilterLogEvents` 권한이 필요합니다. [AWS 인증](#aws-인증)을 참고하십시오. |
| `targetStream` | 대상 스트림. 기본값 `default`. |

한 번에 하나의 노드가 커넥터를 폴링합니다. `alert` 노드가 커넥터를 나누어 맡으며, 노드는 폴링하기 전에 커넥터를 클레임합니다. [alert 노드 간 작업 분담](/ko/deployment/role-based#알림-노드-간-작업-분담)을 참고하십시오. 각 이벤트는 `message`, `log_stream`, `log_group`을 가진 로그가 됩니다. 꺼진 커넥터는 폴링하지 않습니다.

### Kafka 토픽

`kafka_source` 커넥터는 30초마다 토픽을 읽고, 기록된 마지막 읽기가 끝난 지점에서 이어갑니다. 소비자 그룹의 구성원이 아니라 할당 방식으로 파티션을 가져가며, 오프셋을 MoleSignal에 보관합니다. 따라서 토픽을 읽을 권한만 필요하고, 클러스터에 소비자 그룹이 나타나지 않습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "orders",
        "kind": "kafka_source",
        "configJson": {
          "brokers": "b-1.example.com:9096,b-2.example.com:9096",
          "topic": "orders",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "<password>",
          "targetStream": "orders",
          "startFrom": "latest"
        }
      }'
```

| 필드 | 참고 |
|---|---|
| `brokers`, `topic`, `tls`, `tlsCaCert`, `auth` 및 해당 키 | [Kafka 대상](#apache-kafka)과 동일합니다. |
| `targetStream` | 대상 스트림. 기본값 `default`. |
| `messageFormat` | `json`(기본값) 또는 Azure Monitor가 이벤트 허브로 내보내는 데이터용 `azure_records`. 아래를 참고하십시오. UI: **메시지 형식**. |
| `startFrom` | 첫 읽기가 시작할 위치입니다. `latest`(기본값)는 지금부터 도착하는 데이터, `earliest`는 브로커가 보관한 모든 데이터입니다. 나중에 추가된 파티션은 처음부터 읽습니다. UI: **읽기 시작 위치**. |

- 값이 JSON 객체인 메시지는 로그의 필드를 제공합니다. 다른 값은 `message`가 됩니다. 각 로그에는 `kafka_topic`, `kafka_partition`, `kafka_offset`, 메시지에 키가 있으면 `kafka_key`, 그리고 `source`도 있습니다. 시간은 메시지의 타임스탬프입니다.
- 한 번의 읽기는 최대 10,000개 메시지 또는 32 MiB를 가져오며, 더 있으면 다음 읽기가 즉시 이어져 한 번의 풀에서 최대 2분 동안 진행됩니다.
- 오프셋은 로그가 기록된 후에만 이동합니다. 읽기나 쓰기가 실패하면 30초 후 같은 위치에서 다시 시도하므로, 메시지가 두 번 기록될 수는 있지만 유실되지는 않습니다. 브로커가 보관 기간을 넘긴 오프셋은 브로커가 여전히 보관 중인 가장 오래된 메시지에서 이어갑니다.
- 오프셋은 토픽에 속하므로 `topic`을 변경하면 `startFrom`에서 다시 시작합니다.

Azure 진단 설정, Log Analytics 데이터 내보내기, 데이터 수집 규칙은 Azure Event Hubs로 내보내며, Kafka 소스는 허브의 Kafka 엔드포인트를 통해 읽습니다. `brokers`는 `<namespace>.servicebus.windows.net:9093`, `topic`은 이벤트 허브, `tls`는 켜기, `auth: sasl_plain`에 사용자 이름 `$ConnectionString`, 비밀번호는 연결 문자열입니다. Basic 계층에는 Kafka 엔드포인트가 없습니다. `messageFormat: azure_records`를 사용하면 각 `{"records": [...]}` 메시지가 풀립니다. 로그 레코드는 해당 `time`에 로그 이벤트가 되고, 메트릭 레코드는 커넥터의 `metricsStream`(기본값 `default`)에 통계마다 하나의 샘플이 되며, [Azure Monitor 메트릭](#클라우드-메트릭)과 같은 방식으로 이름이 지정됩니다.

### S3 객체

`s3_source` 커넥터는 30초마다 버킷을 나열하고, 아직 읽지 않은 객체를 가장 오래된 것부터 AWS S3 또는 S3 호환 스토리지에서 읽습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "elb-logs",
        "kind": "s3_source",
        "configJson": {
          "bucket": "acme-logs",
          "region": "us-east-1",
          "prefix": "AWSLogs/123456789012/",
          "auth": "node_role",
          "targetStream": "elb",
          "startFrom": "latest"
        }
      }'
```

| 필드 | 참고 |
|---|---|
| `bucket`, `region`, `endpoint`, `virtualHostedStyle`, `auth` 및 해당 키 | [S3 대상](#amazon-s3)과 동일합니다. 자격 증명에는 버킷에 `s3:ListBucket`, 객체에 `s3:GetObject` 권한이 필요합니다. |
| `prefix` | 이 접두사 아래의 객체만 읽습니다. 각 풀이 접두사 전체를 나열하므로, 소스마다 고유한 접두사를 지정하십시오. |
| `targetStream` | 대상 스트림. 기본값 `default`. |
| `startFrom` | 첫 읽기가 시작할 위치입니다. `latest`(기본값)는 지금부터 그리고 그 이전 5분 안에 나타나는 객체, `earliest`는 접두사 아래의 모든 객체입니다. UI: **읽기 시작 위치**. |

- 객체는 줄 단위로 읽습니다. JSON 객체인 줄은 로그의 필드를 제공하고, CloudTrail이 쓰는 것처럼 `Records`만 가진 줄은 레코드마다 로그를 제공하며, 그 밖의 줄은 `message`가 됩니다. `.gz` 및 `.zst` 객체는 이름에 따라 압축이 해제됩니다. 각 로그에는 `s3_bucket`, `s3_key`, `source`도 있습니다. 시간은 객체가 마지막으로 수정된 시각입니다.
- 한 번의 풀은 최대 100개 객체 또는 50,000개 로그까지 읽으며, 더 있으면 다음 풀이 즉시 이어져 최대 2분 동안 진행됩니다.
- 읽기 상태는 로그가 기록된 후에만 이동합니다. 가져올 수 없는 객체는 그 지점에서 풀을 중단하고 30초 후 다시 시도하므로, 로그가 두 번 기록될 수는 있지만 유실되지는 않습니다.
- 읽을 수 없는 객체는 건너뛰고 커넥터에 알리며, 다시 시도하면 그 뒤의 모든 것이 지연되기 때문입니다. 즉 손상되었거나, 256 MiB를 초과하거나, 압축 해제 후 512 MiB를 초과하거나, 로그가 100만 개를 초과하거나, 줄이 64 MiB를 초과하는 객체입니다.
- 객체는 키와 수정 시각으로 인식하며, 5분의 여유를 둡니다. 그 여유 안에 같은 키로 다시 작성된 객체는 다시 읽지 않고, 수정 시각이 읽은 가장 새로운 객체보다 5분 이상 오래된 객체는 전혀 읽지 않습니다. S3는 멀티파트 업로드의 날짜를 시작 시점으로 기록하므로, 그보다 느린 업로드는 읽히지 않습니다.

### Google Cloud Pub/Sub 구독

`gcp_pubsub_pull` 커넥터는 30초마다 Pub/Sub 구독을 읽으며, 요청당 최대 1,000개 메시지를 읽고 더 있으면 즉시 이어서 읽습니다. 메시지는 기록된 후에만 확인 응답합니다. 쓰기에 실패한 메시지는 확인 응답 기한이 지나면 다시 전달되므로, 메시지가 두 번 기록될 수는 있지만 유실되지는 않습니다. 요청당 하나의 메시지를 전송하는 [푸시 구독](#푸시-소스)이 잘 감당하는 것보다 더 많은 로그에 적합합니다.

| 필드 | 참고 |
|---|---|
| `serviceAccountKey` | 구독에 `roles/pubsub.subscriber` 권한이 있는 서비스 계정의 JSON 키 파일입니다. |
| `subscription` | `projects/<project>/subscriptions/<name>` 또는 키의 프로젝트에 있는 구독 이름입니다. 확인 응답 기한을 60초 이상으로 설정하십시오. |
| `targetStream` | 대상 스트림. 기본값 `default`. |

각 메시지는 푸시된 메시지와 같은 방식으로 읽습니다. Cloud Logging `LogEntry`는 푸시 탭의 매핑을 따르고, 다른 JSON 객체는 해당 필드로, 그 밖의 것은 `message`로 읽습니다. **연결 테스트**는 메시지를 가져오지 않고 키가 구독을 소비할 수 있는지 확인합니다.

### 클라우드 메트릭

여섯 가지 소스가 일정에 따라 클라우드 모니터링 서비스의 메트릭을 풀하고 메트릭 스트림에 기록합니다.

| 종류 | 클라우드 | API | 인증 | 권한 | 기본 `metricsStream` |
|---|---|---|---|---|---|
| `aws_cloudwatch_metrics` | Amazon CloudWatch | `ListMetrics`, `GetMetricData` | [AWS 자격 증명](#aws-인증) | `cloudwatch:ListMetrics`, `cloudwatch:GetMetricData` | `cloudwatch` |
| `azure_monitor_metrics` | Azure Monitor | Resource Graph, `metrics:getBatch` | 앱 등록의 `tenantId`, `clientId`, `clientSecret` | 구독의 **Monitoring Reader** | `azure` |
| `gcp_monitoring_metrics` | Google Cloud Monitoring | `timeSeries.list` | `serviceAccountKey`, JSON 키 파일 | 프로젝트의 `roles/monitoring.viewer` | `gcp` |
| `aliyun_cms_metrics` | Alibaba Cloud CloudMonitor | `DescribeMetricList` | `accessKey`, `secretKey` | `AliyunCloudMonitorReadOnlyAccess` | `aliyun` |
| `tencent_monitor_metrics` | Tencent Cloud Monitor | `GetMonitorData` | `accessKey`(SecretId), `secretKey`(SecretKey) | `QcloudMonitorReadOnlyAccess`, CVM 인스턴스를 찾으려면 `QcloudCVMReadOnlyAccess` 추가 | `tencentcloud` |
| `huawei_ces_metrics` | Huawei Cloud Eye | `ListMetrics`, `BatchListMetricData` | `accessKey`(AK), `secretKey`(SK) | `CES ReadOnlyAccess` | `huaweicloud` |

각 풀은 최소 `delay`초 전에 끝난 `period`초의 전체 기간을 읽으며, 마지막으로 기록된 풀이 끝난 지점에서 시작합니다. 클라우드는 기간이 끝난 후 몇 분 뒤에 집계를 완료하며, 각 기간은 한 번만 읽습니다. 나중에 수정된 값은 읽은 그대로 유지됩니다. 새 커넥터는 한 기간 전부터 시작합니다. 한 번의 풀은 최대 12개 기간을 읽고 다음 틱에 이어서 진행합니다. 6시간 넘게 꺼져 있던 커넥터는 더 오래된 데이터를 건너뛰고 그 사실을 알립니다.

각 시계열의 각 통계는 해당 기간의 시작 시점에 `<cloud>_<namespace>_<metric>_<statistic>` 이름의 게이지 샘플이 되며, yet-another-cloudwatch-exporter가 CloudWatch 메트릭에 이름을 붙이는 방식과 같습니다.

| 소스 | 예 | 레이블 |
|---|---|---|
| CloudWatch | `aws_ec2_cpuutilization_average` | `region`, `dimension_<Name>` |
| Azure Monitor | `azure_compute_virtualmachines_percentage_cpu_average` | `subscription_id`, `resource_group`, `resource_name`, `resource_id`, `region`, `dimension_<name>`, `tag_<key>` |
| Cloud Monitoring | `gcp_compute_instance_cpu_utilization_mean` | `project_id`, `resource_type`, 리소스 및 메트릭 레이블 |
| CloudMonitor | `aliyun_ecs_dashboard_cpuutilization_average` | `region`, `user_id`, `dimension_<key>` |
| Tencent Cloud Monitor | `tencentcloud_cvm_cpu_usage_avg` | `region`, `dimension_<Name>` |
| Cloud Eye | `huaweicloud_sys_ecs_cpu_util_average` | `region`, `dimension_<name>` |

### 풀 진행 상황

커넥터 페이지는 소스가 마지막으로 받은 시간을 표시합니다. 마지막 읽기가 실패한 소스는 그 옆에 경고를 표시하며, 툴팁과 커넥터 설정에 이유가 나옵니다. 소스가 마지막으로 건너뛴 내용도 거기에 표시됩니다. 스트림이 필드 유형에 맞지 않는 값 때문에 거부한 이벤트는 다시 전송되지 않습니다. 소스는 계속 진행하며, 푸시 엔드포인트는 여전히 성공을 응답합니다. 플랫폼이 전체 요청을 다시 보낼 것이기 때문입니다. 그러면 커넥터가 마지막으로 건너뛴 내용에 거부된 이벤트 수와 첫 번째 이유가 표시됩니다. API에서는 `readState`에 `lastError`와 `lastWarning`이 각각 `atTime`과 `text`와 함께 있고, 어디까지 진행했는지를 나타내는 `position`이 있습니다. 커넥터를 저장해도 위치는 그대로 유지됩니다.

## 대상

대상은 예약된 파이프라인의 단계를 통과한 모든 이벤트를 수신합니다. 흐름의 **대상**에 **대상 추가 → 커넥터**로 커넥터를 추가합니다. 실패한 전송은 실행 내에서 재시도되며, 커넥터가 계속 받지 않는 이벤트는 데드 레터 스트림으로 이동합니다. [재시도 및 데드 레터](/ko/pipelines#재시도-및-데드-레터)를 참조하십시오.

꺼진 대상은 아무것도 수신하지 않습니다. 각 실행은 커넥터를 건너뛰고 실행의 `warning`에 해당 커넥터의 이름을 기록합니다. 건너뛴 이벤트는 실패로 집계되지 않고, 데드 레터가 되지 않으며, 커넥터를 다시 켜도 전송되지 않습니다. 편집기에서 꺼진 커넥터는 **꺼짐**으로 표시됩니다.

| 종류 | 페이로드 |
|---|---|
| `s3` | 배치마다 JSON Lines 객체 하나를 `s3://<bucket>/<prefix><id>.jsonl`에 `PUT`합니다. |
| `kafka` | 토픽에 이벤트마다 메시지 하나를 보내며, 이벤트는 JSON 페이로드로 사용됩니다. |

사용자 지정 헤더는 전송 시 자체적으로 설정하는 `Host`, `Content-Type`, `Content-Length`, `Content-Encoding`, `Transfer-Encoding`, `Connection`, `X-MoleSignal-Timestamp`, `X-MoleSignal-Sign` 중 하나일 수 없습니다.

전송에는 다음 규칙이 적용됩니다.

- 4 MiB보다 큰 배치는 여러 요청으로 나뉩니다. 그보다 큰 이벤트는 자체 요청으로 전송됩니다.
- `2xx` 상태는 전송된 것으로 간주됩니다. 그 외 상태는 전송 실패로 처리되며, 리디렉션도 마찬가지입니다. 리디렉션은 따르지 않습니다.
- 요청은 30초 후에 타임아웃됩니다.
- MoleSignal은 요청 전에 호스트를 확인하고 확인된 주소에만 연결합니다. 클라우드 메타데이터 서비스가 응답하는 주소는 URL에 있든 DNS에서 오든 거부됩니다: `169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254`, `100.100.100.200`. 다른 프라이빗 주소는 허용됩니다.

#### HMAC 서명 검증

`hmac`을 사용하면 모든 요청에 두 개의 헤더가 포함됩니다.

| 헤더 | 내용 |
|---|---|
| `X-MoleSignal-Timestamp` | Unix 초 단위의 요청 시각입니다. |
| `X-MoleSignal-Sign` | 공유 시크릿을 사용해 `<timestamp>.<body>`에 대한 HMAC-SHA256을 계산한 값인 `sha256=<hex>`입니다. |

요청을 검증하려면 동일한 시크릿으로 타임스탬프, `.`, 원본 본문 바이트를 이어 붙인 값의 HMAC-SHA256을 계산하고 그 결과를 상수 시간으로 서명과 비교합니다. 몇 분보다 오래된 타임스탬프는 거부하여, 캡처된 요청을 나중에 다시 전송할 수 없게 합니다.

```python
import hashlib
import hmac
import time


def verify(secret: bytes, timestamp: str, signature: str, body: bytes, tolerance: int = 300) -> bool:
    if abs(time.time() - int(timestamp)) > tolerance:
        return False
    signed = timestamp.encode() + b"." + body
    expected = "sha256=" + hmac.new(secret, signed, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## AWS 인증

S3와 CloudWatch Logs는 다음 다섯 가지 방법 중 하나로 AWS에 인증합니다.

| `auth` | UI | 키 | 자격 증명 |
|---|---|---|---|
| `access_key` | **액세스 키** | `accessKey`, `secretKey` | IAM 사용자의 장기 키입니다. |
| `temporary_key` | **임시 키** | `accessKey`, `secretKey`, `sessionToken` | AWS STS에서 발급한 단기 키로, 세션 토큰이 있어야만 유효합니다. 만료되기 전에 교체합니다. |
| `node_role` | **노드 자격 증명** | | MoleSignal이 실행되는 노드의 자격 증명입니다. 키를 저장하지 않습니다. |
| `assume_role` | **역할 수임** | `roleArn`, 선택적으로 `accessKey`와 `secretKey` | 조직의 외부 ID로 AWS STS를 통해 수임하는 역할입니다. |
| `web_identity` | **웹 자격 증명** | `roleArn` | 노드의 웹 자격 증명 토큰으로 수임하는 역할입니다. |

`auth`가 없으면 저장된 키로 결정합니다. 액세스 키는 `access_key`, `roleArn`은 `assume_role`, 둘 다 없으면 `node_role`로 읽습니다. `roleArn`의 형식은 `arn:aws:iam::<account>:role/<name>`입니다.

### 노드 자격 증명

`node_role`은 AWS SDK가 노드에서 찾는 자격 증명을 사용합니다. EKS의 서비스 어카운트용 IAM 역할(IRSA) 또는 EKS Pod Identity, ECS 태스크 역할, EC2 인스턴스 프로파일이 여기에 해당합니다. `AWS_ACCESS_KEY_ID`처럼 노드 환경에 있는 정적 키는 커넥터에 사용하지 않습니다.

<Warning>
  노드의 자격 증명과 웹 자격 증명 토큰은 배포에 속합니다. 배포의 모든 조직이 `node_role`과 `web_identity`를 선택할 수 있으므로, 노드의 자격 증명이 접근할 수 있는 모든 대상과 노드의 토큰을 신뢰하는 모든 역할이 모든 조직의 커넥터에 열립니다. 모든 조직이 가져도 되는 권한만 부여합니다.
</Warning>

### 역할 수임

`assume_role`은 AWS STS에 역할의 1시간짜리 키를 요청하고, 만료 5분 전에 키를 갱신합니다. 역할을 수임하는 기본 자격 증명은 노드의 자격 증명입니다. AWS에서 실행되지 않는 배포라면 **노드 ID 대신 액세스 키로 역할 수임**을 선택하고 IAM 사용자의 키를 입력합니다.

모든 조직은 변경할 수 없는 자체 외부 ID인 `molesignal-<organization ID>`로 역할을 수임합니다. 폼은 이를 **외부 ID** 아래에 표시하며, `GET /api/v1/connectors/aws-external-id`가 이를 반환합니다. 역할의 신뢰 정책에 외부 ID를 요구하여, 다른 조직이 ARN을 알아내더라도 역할을 수임할 수 없게 합니다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "<ARN of the node role or IAM user>" },
      "Action": "sts:AssumeRole",
      "Condition": { "StringEquals": { "sts:ExternalId": "molesignal-<organization ID>" } }
    }
  ]
}
```

세션 이름은 `molesignal-<connector ID>`이며, AWS CloudTrail에 이 이름으로 나타납니다. 요청은 커넥터의 `region`에 해당하는 리전 STS 엔드포인트로 전송됩니다. 리전이 비어 있으면 `us-east-1`, 중국 리전이면 `amazonaws.com.cn` 도메인을 사용합니다.

### 웹 자격 증명

`web_identity`는 노드의 `AWS_WEB_IDENTITY_TOKEN_FILE`이 가리키는 경로의 웹 자격 증명 토큰으로 역할을 수임합니다. EKS가 IRSA를 위해 프로젝션하는 서비스 어카운트 토큰이 대표적인 예입니다. 커넥터는 다른 파일을 지정할 수 없습니다. 역할의 신뢰 정책은 토큰을 발급하는 OIDC 공급자를 신뢰해야 합니다. `AWS_WEB_IDENTITY_TOKEN_FILE`이 없는 노드에서는 커넥터에 자격 증명이 없습니다.

토큰은 커넥터의 `region`에 해당하는 리전 STS 엔드포인트에서 교환하며, 노드 환경에 `AWS_ENDPOINT_URL_STS`가 설정되어 있으면 해당 엔드포인트를 사용합니다. IRSA에서 가져온 노드 자격 증명에도 같은 규칙이 적용됩니다.

## 연결 테스트

**연결 테스트**는 설정을 저장하기 전에 폼에 있는 그대로 시도합니다. 시크릿을 비워 두면 저장된 시크릿을 사용합니다. 각 종류는 전송 또는 수집이 동작함을 증명하는 최소한의 작업만 수행합니다.

| 종류 | 테스트 |
|---|---|
| `s3` | 접두사 아래에 `.molesignal-connection-test` 객체를 쓰고, 정책이 허용하면 삭제합니다. |
| `kafka` | 브로커에서 토픽의 메타데이터를 읽어 연결, TLS, 인증, 토픽 존재 여부를 확인합니다. 메시지는 쓰지 않습니다. |
| `http` | 테스트로 표시된 이벤트 하나를 전송합니다: `"message": "MoleSignal connection test"`, `"molesignal_connection_test": true`. |
| `aws_cloudwatch_logs` | 로그 그룹의 지난 1분 내 이벤트를 최대 하나 읽습니다. 스트림에 아무것도 쓰지 않으며 읽기 위치를 그대로 둡니다. |
| `kafka_source` | `kafka`와 마찬가지로 브로커에서 토픽의 메타데이터를 읽습니다. 메시지는 읽지 않으며 읽기 위치를 그대로 둡니다. |
| `s3_source` | 접두사 아래의 객체 하나를 나열하여 자격 증명과 `s3:ListBucket` 권한을 확인합니다. 아무것도 읽지 않으며 읽기 위치를 그대로 둡니다. |

테스트는 25초가 지나면 중단됩니다. API에서는 `POST /api/v1/connectors/test`에 시도할 `kind`와 `configJson`을 전달합니다. 같은 종류의 저장된 커넥터 `id`를 함께 지정하면 `***`가 해당 커넥터가 보관한 시크릿을 나타냅니다. 동작할 수 없는 설정에는 저장할 때와 마찬가지로 `400`을 응답합니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "id": "<connector id>",
        "kind": "kafka",
        "configJson": {
          "brokers": "b-1.example.com:9096",
          "topic": "logs",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "***"
        }
      }'
```

```json
{ "ok": true, "code": "ok", "detail": null, "elapsedMs": 412 }
```

`elapsedMs`는 테스트에 걸린 시간입니다. 실패한 테스트는 `code`에 원인을 담고, `detail`에는 상대방의 메시지를 최대 600자까지 담습니다.

| `code` | 의미 |
|---|---|
| `ok` | 연결되었습니다. |
| `invalid` | 설정이 동작할 수 없거나, 연결할 대상이 없는 푸시 소스 커넥터입니다. |
| `no_credentials` | AWS 자격 증명을 얻지 못했습니다. 노드에 자격 증명이 없거나, 요청한 종류의 자격 증명이 없습니다. |
| `denied` | 상대방이 자격 증명 또는 허용된 작업을 거부했습니다. |
| `not_found` | 버킷, 토픽, 로그 그룹 또는 주소가 존재하지 않습니다. |
| `tls` | TLS 핸드셰이크에 실패했습니다. 인증서를 신뢰하지 않거나 인증서가 제시되지 않았습니다. |
| `unreachable` | 호스트를 확인할 수 없거나 연결할 수 없습니다. |
| `timeout` | 제시간에 응답이 없습니다. |
| `failed` | 그 밖의 모든 실패입니다. |

## API

| 엔드포인트 | 권한 | 용도 |
|---|---|---|
| `GET /api/v1/connectors` | `pipelines.read` | 조직의 커넥터를 나열합니다. |
| `POST /api/v1/connectors` | `pipelines.edit` | 커넥터를 생성합니다. `enabled`의 기본값은 `true`입니다. |
| `GET /api/v1/connectors/{id}` | `pipelines.read` | 커넥터를 조회합니다. |
| `PUT /api/v1/connectors/{id}` | `pipelines.edit` | `name`, `kind`, `configJson`, `enabled`를 모두 필수로 하여 교체합니다. |
| `DELETE /api/v1/connectors/{id}` | `pipelines.edit` | 커넥터를 삭제합니다. |
| `POST /api/v1/connectors/test` | `pipelines.edit` | 설정을 저장하기 전에 테스트합니다. |
| `GET /api/v1/connectors/aws-external-id` | `pipelines.read` | 조직의 외부 ID를 `externalId`로 반환합니다. |

커넥터는 `id`, `name`, `kind`, 시크릿이 마스킹된 `configJson`, `secretKeys`, `enabled`, `lastRunAt`, `readState`, `createdAt`, `updatedAt`으로 조회됩니다.

## 권한

`pipelines.read`는 커넥터를 나열하고 조회하며 외부 ID를 읽습니다. `pipelines.edit`는 커넥터를 생성, 수정, 삭제, 테스트합니다. 테스트는 저장된 시크릿을 사용하고 호출자를 대신해 다른 시스템에 연결하므로 `pipelines.edit`가 필요합니다. 푸시 수신기는 푸시 토큰으로 인증하며, 일반 로그인 JWT로 대체할 수 없습니다.
