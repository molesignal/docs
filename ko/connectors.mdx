**커넥터**는 외부 플랫폼과의 관리형 통합입니다. 커넥터는 두 방향으로 작동합니다:

- **소스**는 다른 서비스에서 데이터를 가져와 스트림에 기록합니다. MoleSignal은 일정에 따라 CloudWatch Logs, Kafka 토픽, S3 객체를 풀링합니다. Amazon Data Firehose, Google Cloud Pub/Sub, Cloudflare Logpush, Heroku는 MoleSignal로 푸시합니다. Firehose는 CloudWatch 메트릭도 전달합니다.
- **대상**은 [예약된 파이프라인](/ko/pipelines#대상-스트림과-커넥터-전송)의 출력을 받습니다: Amazon S3 및 S3 호환 스토리지, Apache Kafka, 모든 HTTP 엔드포인트.

| 종류 | 커넥터 | 방향 | 인증 |
|---|---|---|---|
| `aws_cloudwatch_logs` | AWS CloudWatch Logs | 소스, 30초마다 풀링 | [AWS 자격 증명](#aws-인증) |
| `kafka_source` | Kafka 토픽 | 소스, 30초마다 풀링 | 없음, SASL 또는 클라이언트 인증서 |
| `s3_source` | S3 객체 | 소스, 30초마다 풀링 | AWS 자격 증명 |
| `gcp_pubsub_pull` | Google Cloud Pub/Sub 구독 | 소스, 30초마다 풀링 | 서비스 계정 키 |
| `aws_cloudwatch_metrics`, `azure_monitor_metrics`, `gcp_monitoring_metrics`, `aliyun_cms_metrics`, `tencent_monitor_metrics`, `huawei_ces_metrics` | [클라우드 메트릭](#클라우드-메트릭) | 소스, 주기마다 풀링 | 클라우드의 자격 증명 |
| `aws_kinesis_firehose` | Amazon Data Firehose | 소스, 푸시됨 | [푸시 토큰](#푸시-소스) |
| `gcp_pubsub_push` | Google Cloud Pub/Sub 푸시 | 소스, 푸시됨 | 푸시 토큰, 선택적으로 구독의 OIDC 토큰 |
| `cloud_events` | 클라우드 이벤트 버스 | 소스, 푸시됨 | 푸시 토큰 |
| `cloudflare_logpush` | Cloudflare Logpush | 소스, 푸시됨 | 푸시 토큰 |
| `heroku_drain` | Heroku 로그 드레인 | 소스, 푸시됨 | 푸시 토큰 |
| `s3` | Amazon S3 | 대상 | AWS 자격 증명 |
| `kafka` | Apache Kafka | 대상 | 없음, SASL 또는 클라이언트 인증서 |
| `http` | HTTP / 웹훅 | 대상 | 없음, 베어러 토큰, Basic 인증, 사용자 지정 헤더 또는 HMAC 서명 |

## 커넥터 만들기

<Steps>
  <Step title="커넥터 열기">
    **파이프라인 → 커넥터**로 이동합니다. 페이지에 **소스**와 **대상**이 나열됩니다.
  </Step>
  <Step title="종류 선택">
    **새 커넥터**를 클릭하고 연결할 항목을 선택합니다.
  </Step>
  <Step title="설정 입력">
    조직 내에서 고유한 **이름**을 입력하고, 커넥터가 읽어 오거나 전달할 위치를 입력한 후 **인증**을 선택합니다.
  </Step>
  <Step title="테스트 및 만들기">
    저장하기 전에 설정을 시험하려면 **연결 테스트**를 클릭한 다음 **커넥터 만들기**를 클릭합니다. 푸시 소스는 연결할 대상이 없으므로 테스트를 제공하지 않습니다.
  </Step>
</Steps>

API에서 커넥터는 `name`, `kind`, 그리고 종류에 따라 키가 달라지는 `configJson`으로 구성됩니다. `configJson`의 `auth`는 인증 방식을 지정하며, 각 방식은 자체 키를 사용합니다. 작동할 수 없는 설정은 저장할 때 `400` 응답을 반환합니다. 필수 키가 누락되었거나, 자격 증명 쌍의 일부만 제공되었거나, 선택한 `auth`가 사용하지 않는 키가 포함된 경우입니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "archive",
        "kind": "s3",
        "configJson": {
          "bucket": "acme-logs",
          "region": "eu-west-1",
          "prefix": "pipelines/checkout/",
          "auth": "assume_role",
          "roleArn": "arn:aws:iam::123456789012:role/molesignal-delivery"
        }
      }'
```

## 시크릿

다음 `configJson` 키는 시크릿을 보관합니다:

| 종류 | 시크릿 키 |
|---|---|
| `s3`, `aws_cloudwatch_logs` | `accessKey`, `secretKey`, `sessionToken` |
| `aws_kinesis_firehose`, `gcp_pubsub_push`, `cloud_events`, `cloudflare_logpush`, `heroku_drain` | `pushToken` |
| `aws_cloudwatch_metrics` | `accessKey`, `secretKey`, `sessionToken` |
| `azure_monitor_metrics` | `clientSecret` |
| `gcp_monitoring_metrics`, `gcp_pubsub_pull` | `serviceAccountKey` |
| `aliyun_cms_metrics`, `tencent_monitor_metrics`, `huawei_ces_metrics` | `accessKey`, `secretKey` |
| `kafka` | `saslPassword`, `tlsClientKey` |
| `http` | `url`, `bearerToken`, `basicPassword`, `headerValue`, `hmacSecret` |

시크릿은 API를 통해 절대 외부로 나가지 않습니다. 응답에는 그 자리에 `***`가 표시되고, `secretKeys`에 값을 보유한 시크릿의 이름이 나열됩니다:

```json
{
  "kind": "kafka",
  "configJson": {
    "brokers": "b-1.example.com:9096",
    "topic": "logs",
    "tls": true,
    "auth": "sasl_scram_sha_512",
    "saslUsername": "molesignal",
    "saslPassword": "***"
  },
  "secretKeys": ["saslPassword"]
}
```

- `***`를 다시 보내는 업데이트는 저장된 값을 유지하므로, 자격 증명을 다시 입력하지 않고도 커넥터의 이름을 바꾸거나, 비활성화하거나, 다른 위치를 가리키게 할 수 있습니다. UI에서는 저장된 시크릿을 비워 두면 해당 값이 유지됩니다.
- 업데이트에서 생략된 시크릿은 제거됩니다.
- `kind`를 변경하는 업데이트는 저장된 시크릿을 하나도 유지하지 않습니다.

MoleSignal은 다른 설정과 별도로 `MS_CIPHER_KEY`의 루트 키(AES-256-GCM)로 시크릿을 봉인하며, 시크릿을 평문으로 저장하지 않습니다. 푸시 소스는 해당 토큰의 SHA-256으로 찾습니다. `molesignal rewrap-kek`는 루트 키가 교체될 때 다른 시크릿과 함께 커넥터 시크릿을 다시 봉인합니다. [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조하십시오.

## Sources

### 푸시 소스

다섯 개 푸시 소스는 하나의 모델을 공유합니다. **`pushToken`**과 **`targetStream`**으로 커넥터를 생성한 다음, 플랫폼이 해당 엔드포인트를 가리키게 합니다. 이 엔드포인트는 JWT를 사용하지 않습니다. 요청은 플랫폼이 허용하는 방식으로 제공한 푸시 토큰으로 인증합니다:

| 방식 | 사용처 |
|---|---|
| `X-Connector-Token` 헤더 | Cloudflare처럼 헤더를 구성할 수 있는 플랫폼 |
| `X-Amz-Firehose-Access-Key` 헤더 | 자동으로 전송하는 Amazon Data Firehose |
| `X-EventBridge-Signature-Token` 헤더 | Alibaba Cloud EventBridge |
| `?token=` 쿼리 매개변수 | Heroku 및 Pub/Sub처럼 헤더를 설정할 수 없는 플랫폼 |
| `Authorization: Basic`의 비밀번호 | 자격 증명을 주소에 넣는 플랫폼 |

UI는 커넥터를 생성할 때 토큰을 생성하고, 플랫폼에 제공할 엔드포인트와 함께 한 번만 표시합니다. 토큰은 다시 읽을 수 없습니다. 커넥터를 저장하면 **새 토큰 생성**이 토큰을 교체합니다. API에서는 16자 이상의 `pushToken`을 제공합니다. 하나의 토큰으로 한 종류의 커넥터 하나를 열 수 있습니다. 이미 사용 중인 토큰은 `409`를 반환합니다. 토큰이 없거나 알 수 없는 토큰을 사용한 요청, 또는 꺼져 있는 커넥터에 대한 요청은 `401`을 반환합니다. 토큰이 없는 커넥터는 아무것도 받지 않습니다. 노드는 조회한 커넥터를 30초 동안 유지하므로, 커넥터를 끄거나 토큰을 교체하면 해당 시간 안에 적용됩니다.

`Content-Encoding: gzip`으로 전송된 본문은 자동으로 압축 해제됩니다. Firehose 본문은 최대 64 MiB, 그 밖의 본문은 최대 16 MiB이며, 압축 해제 후에도 같은 기준입니다. 이벤트는 다른 모든 데이터와 동일한 수집 경로를 거칩니다. 쓰기 시 스키마, [파이프라인](/ko/pipelines), [마스킹](/ko/security)이 모두 적용됩니다.

<Tabs>
  <Tab title="Amazon Data Firehose">
    `kind: "aws_kinesis_firehose"`로 커넥터를 생성한 다음 Firehose 스트림의 대상으로 **HTTP 엔드포인트**를 선택합니다:

    - **HTTP 엔드포인트 URL**: `https://molesignal.example.com/api/v1/_kinesis_firehose`
    - **액세스 키**: 푸시 토큰입니다. Firehose는 이를 `X-Amz-Firehose-Access-Key`로 전송합니다.

    Firehose는 공개적으로 신뢰된 인증서를 사용하는 443 포트의 HTTPS로만 전송하므로, 프라이빗 네트워크의 배포에는 공개 진입점이 필요합니다. [공개 액세스](/ko/public-access)를 참조하세요. 스트림의 버퍼는 1~4 MiB로 유지합니다.

    MoleSignal은 각 레코드를 담긴 내용에 따라 개별적으로 읽습니다:

    | 레코드 | 변환 결과 |
    |---|---|
    | CloudWatch Logs 구독 메시지(구독 필터가 전송하는 대로 gzip 압축됨) | `logEvents`의 각 항목마다 해당 항목의 시각에 로그 이벤트 하나가 되며, `message`, `log_group`, `log_stream`, `account_id`, `region`, `event_id`, `source: "cloudwatch"`가 포함됩니다. 구독 생성 시 전송되는 상태 확인은 건너뜁니다. |
    | JSON, OpenTelemetry 1.0 또는 OpenTelemetry 0.7 출력 형식의 CloudWatch Metric Streams 레코드 | 메트릭 스트림의 메트릭 샘플입니다. 아래를 참조하세요. |
    | 기타 텍스트 | 줄마다 로그 이벤트 하나가 됩니다. JSON 객체는 필드를 제공하고, 일반 텍스트는 `message`로 들어갑니다. |

    메트릭 스트림은 분당 메트릭당 집계 하나를 전송합니다. 각 통계는 yet-another-cloudwatch-exporter가 이름을 지정하는 방식대로 `aws_<namespace>_<metric>_<statistic>`라는 이름의 게이지 샘플이 됩니다: `aws_ec2_cpuutilization_average`, `aws_ec2_cpuutilization_maximum`, `aws_applicationelb_request_count_sum`. 네임스페이스는 `AWS/` 접두사를 제거하고, 메트릭 이름은 소문자 뒤에 대문자가 오는 곳에서 단어로 분할합니다. 통계는 `average`(샘플 수에 대한 합계), `sum`, `sample_count`, `minimum`, `maximum`, 그리고 스트림이 추가하는 `p99` 또는 `p99_9` 같은 백분위수입니다. 레이블은 `account_id`, `region`, 그리고 차원당 하나의 `dimension_<Name>`(예: `dimension_InstanceId`)입니다. `metric_unit`은 단위를 유지합니다.

    ```promql
    max by (dimension_InstanceId) (aws_ec2_cpuutilization_average)
    ```

    스트림의 매개변수로 설정된 `X-Amz-Firehose-Common-Attributes`는 해당 키를 모든 이벤트와 샘플에 추가합니다. 레코드에 이미 있는 필드가 우선합니다. `X-Amz-Firehose-Source-Arn`은 리전을 포함하지 않는 CloudWatch Logs 이벤트의 `region`을 제공합니다.

    응답은 Firehose 전송 사양을 따릅니다. `application/json`에 요청의 `requestId`, `timestamp`, 실패 시 `errorMessage`가 포함됩니다. 읽을 수 없는 레코드는 제외되고, 요청의 나머지 부분은 여전히 `200`과 함께 기록됩니다. 일시적으로 실패한 쓰기는 `429` 또는 `5xx`를 반환하며, Firehose가 이를 재시도합니다. 64 MiB를 초과하는 본문은 `413`을 반환하며, Firehose는 이를 재시도하거나 백업하지 않습니다. 기록된 후 30분 이내에 동일한 `X-Amz-Firehose-Request-Id`로 재시도된 전송은 다시 기록하지 않고 `200`으로 응답합니다.
  </Tab>
  <Tab title="Google Cloud Pub/Sub">
    `kind: "gcp_pubsub_push"`로 커넥터를 생성합니다. 로그 라우터 싱크를 사용하여 로그를 Pub/Sub 토픽으로 라우팅한 다음, 해당 토픽에 푸시 구독을 생성합니다. Pub/Sub은 사용자 지정 헤더를 설정할 수 없으므로 토큰은 URL로 전달됩니다:

    ```bash
    gcloud pubsub subscriptions create molesignal-push --topic=molesignal-logs --push-endpoint="https://molesignal.example.com/api/v1/_gcp_pubsub?token=<pushToken>"
    ```

    구독의 OIDC 토큰도 확인하려면 커넥터의 `oidcServiceAccount`를 서비스 계정의 이메일로 설정하고 `--push-auth-service-account=<email>`로 구독을 생성합니다. 그러면 MoleSignal은 Google의 키로 토큰을 검증하고 해당 서비스 계정만 허용합니다. 대상도 확인하려면 `oidcAudience`를 설정하고, 동일한 값을 `--push-auth-token-audience`로 전달합니다.

    각 메시지는 하나의 요청입니다. 래핑된 본문과 래핑되지 않은 페이로드를 모두 허용합니다. Cloud Logging `LogEntry`는 로그 이벤트 하나가 됩니다:

    | `LogEntry` | 이벤트 |
    |---|---|
    | `jsonPayload` | 해당 필드 |
    | `textPayload` | `message` |
    | `protoPayload`(감사 로그) | `proto_payload`이며, 여기서 `method_name`, `service_name`, `principal_email`을 추출합니다 |
    | `severity` | `level`(소문자) |
    | `logName`, `resource.type`, `insertId` | `log_name`, `resource_type`, `insert_id` |
    | `resource.labels`, `labels` | 각자의 이름을 가진 필드 |
    | `trace`, `spanId` | `projects/<id>/traces/` 접두사를 제거한 `trace_id`, `span_id` |
    | `httpRequest` | `http_request` |
    | `timestamp` | 이벤트 시각. 없으면 `receiveTimestamp` 또는 게시 시각 |

    그 밖의 메시지 데이터는 이벤트 하나가 되며, JSON 객체의 필드 또는 `message`로서의 텍스트가 됩니다. 엔드포인트는 `204 No Content`를 응답하며, Pub/Sub은 이를 승인으로 간주합니다. 읽을 수 없는 메시지는 승인되고 제외됩니다. 일시적으로 실패한 쓰기는 승인되지 않으므로 Pub/Sub이 다시 전달합니다. 기록된 후 30분 이내에 다시 전달된 메시지는 다시 기록하지 않고 승인됩니다.
  </Tab>
  <Tab title="클라우드 이벤트 버스">
    `kind: "cloud_events"`로 커넥터를 생성한 다음 이벤트 버스가 `https://molesignal.example.com/api/v1/_cloud_events`를 가리키게 합니다:

    | 발신자 | 설정 |
    |---|---|
    | Amazon EventBridge | **API 키** 연결을 사용하는 API 대상입니다. 헤더 이름은 `X-Connector-Token`이고 값은 푸시 토큰입니다. |
    | Azure Event Grid | 엔드포인트가 `?token=<pushToken>`로 끝나는 웹훅 구독입니다. 유효성 검사 핸드셰이크와 CloudEvents 스키마의 `OPTIONS` 핸드셰이크는 자동으로 응답합니다. |
    | Alibaba Cloud EventBridge | 푸시 토큰을 토큰으로 사용하는 HTTPS 대상이며, `X-EventBridge-Signature-Token`으로 전송됩니다. |
    | Huawei Cloud EventGrid | `X-Connector-Token` 헤더를 사용하는 웹훅 대상입니다. |
    | 기타 CloudEvents 발신자 | 위의 토큰 방식 중 아무거나 사용합니다. `https://user:<pushToken>@host/...`처럼 자격 증명을 주소에만 넣을 수 있는 발신자도 허용됩니다. |

    본문에는 CloudEvents 1.0(구조화 또는 바이너리 모드), Amazon EventBridge 이벤트 또는 Event Grid 스키마 형식의 이벤트 하나 또는 이벤트 배열이 담깁니다. 각 이벤트는 `targetStream`(기본값 `cloud_events`)의 로그 이벤트 하나가 됩니다:

    | 필드 | 원본 |
    |---|---|
    | `event_id`, `event_source`, `event_type`, `event_subject` | CloudEvents `id`, `source`, `type`, `subject`; EventBridge `id`, `source`, `detail-type`; Event Grid `id`, `topic`, `eventType`, `subject` |
    | `account_id`, `region` | EventBridge `account`, `region`; Alibaba Cloud `aliyunaccountid`, `aliyunregionid`; Event Grid 토픽의 구독 |
    | `resources` | EventBridge `resources` |
    | `data` | 하나의 JSON 필드로서의 페이로드. 텍스트 페이로드는 `message`로 들어갑니다 |
    | `event_format` | `cloudevents`, `eventbridge` 또는 `event_grid` |

    확장 속성은 이름을 유지합니다. 이벤트 자체의 시각이 해당 이벤트의 시각입니다. 그 밖의 JSON 객체는 필드를 그대로 가진 이벤트 하나가 됩니다. 동일한 소스와 ID로 30분 이내에 다시 전달된 이벤트는 두 번 기록되지 않습니다. 엔드포인트는 `200`을 응답하고, JSON이 아닌 본문에는 `400`을 응답합니다.
  </Tab>
  <Tab title="Cloudflare Logpush">
    `kind: "cloudflare_logpush"`로 커넥터를 생성한 다음 HTTP 대상으로 Logpush 작업을 생성합니다. Cloudflare는 `header_` 쿼리 매개변수를 요청 헤더로 변환하므로 토큰은 `X-Connector-Token`으로 전달됩니다:

    ```text
    https://molesignal.example.com/api/v1/_cloudflare?header_X-Connector-Token=<pushToken>
    ```

    Cloudflare는 gzip으로 압축된 NDJSON을 전송하며, 각 줄은 이벤트 하나가 됩니다. 엔드포인트는 `204 No Content`를 응답합니다.
  </Tab>
  <Tab title="Heroku">
    `kind: "heroku_drain"`로 커넥터를 생성한 다음 드레인을 추가합니다. Heroku는 사용자 지정 헤더를 설정할 수 없으므로 토큰은 URL로 전달됩니다:

    ```bash
    heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
    ```

    각 로그 줄은 `message`와 `source: "heroku"`를 가진 이벤트가 됩니다. 엔드포인트는 `204 No Content`를 응답합니다.
  </Tab>
</Tabs>

<Tip>
  `targetStream`은 첫 전송 시 생성되며, 스키마는 새 필드가 나타남에 따라 다른 스트림과 마찬가지로 진화합니다. `targetStream`을 생략하면 소스별 기본값인 `kinesis`, `gcp`, `cloud_events`, `cloudflare`, `heroku`로 대체됩니다. Firehose 커넥터는 메트릭 샘플을 `metricsStream`에 기록하며, 기본값은 `cloudwatch`입니다.
</Tip>

### CloudWatch Logs

CloudWatch Logs는 **풀** 소스입니다. MoleSignal은 푸시를 받는 대신 30초마다 `FilterLogEvents`를 호출합니다. 첫 실행은 지난 5분을 읽습니다. 이후 각 실행은 마지막으로 성공한 실행이 끝난 지점에서 시작하므로, 읽거나 쓰지 못한 이벤트는 다음 실행에서 다시 읽습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "cw-prod",
        "kind": "aws_cloudwatch_logs",
        "configJson": {
          "region": "ap-southeast-1",
          "logGroup": "/aws/lambda/checkout",
          "auth": "node_role",
          "targetStream": "cloudwatch"
        }
      }'
```

| 필드 | 참고 |
|---|---|
| `region` / `logGroup` | 필수입니다. 읽을 CloudWatch 리전과 로그 그룹입니다. |
| `auth` 및 해당 키 | 자격 증명으로, 로그 그룹에 대한 `logs:FilterLogEvents` 권한이 필요합니다. [AWS 인증](#aws-인증)을 참조하세요. |
| `targetStream` | 대상 스트림입니다. 기본값 `default`. |

한 번에 한 노드가 커넥터를 폴링합니다. `alert` 노드는 커넥터를 서로 나누어 가지며, 노드는 폴링 전에 커넥터를 확보합니다. [알림 노드 간 작업 분담](/ko/deployment/role-based#알림-노드-간-작업-분담)을 참조하세요. 각 이벤트는 `message`, `log_stream`, `log_group`을 가진 로그가 됩니다. 꺼져 있는 커넥터는 폴링하지 않습니다.

### Kafka 토픽

`kafka_source` 커넥터는 30초마다 토픽을 읽고, 마지막으로 기록된 읽기가 끝난 지점에서 계속합니다. 소비자 그룹의 구성원이 아니라 할당 방식으로 파티션을 가져가며, 오프셋을 MoleSignal에 보관합니다. 따라서 토픽을 읽을 권한만 필요하고 클러스터에 소비자 그룹이 나타나지 않습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "orders",
        "kind": "kafka_source",
        "configJson": {
          "brokers": "b-1.example.com:9096,b-2.example.com:9096",
          "topic": "orders",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "<password>",
          "targetStream": "orders",
          "startFrom": "latest"
        }
      }'
```

| 필드 | 참고 |
|---|---|
| `brokers`, `topic`, `tls`, `tlsCaCert`, `auth` 및 해당 키 | [Kafka 대상](#apache-kafka)과 같습니다. |
| `targetStream` | 대상 스트림입니다. 기본값 `default`. |
| `messageFormat` | 기본값인 `json` 또는 Azure Monitor가 이벤트 허브로 내보내는 데이터용 `azure_records`입니다. 아래를 참조하세요. UI: **메시지 형식**. |
| `startFrom` | 첫 읽기의 시작 위치입니다. 기본값인 `latest`는 지금부터 도착하는 데이터용이고, `earliest`는 브로커가 보관한 모든 데이터용입니다. 나중에 추가된 파티션은 처음부터 읽습니다. UI: **읽기 시작 위치**. |

- 값이 JSON 객체인 메시지는 로그의 필드를 제공합니다. 그 밖의 값은 해당 `message`가 됩니다. 각 로그에는 `kafka_topic`, `kafka_partition`, `kafka_offset`, 메시지에 키가 있을 때 `kafka_key`, 그리고 `source`도 있습니다. 시각은 메시지의 타임스탬프입니다.
- 한 번의 읽기는 최대 10,000개 메시지 또는 32 MiB를 가져오며, 더 남아 있는 동안 다음 읽기가 즉시 이어져 풀 하나에서 최대 2분 동안 진행됩니다.
- 오프셋은 로그가 기록된 후에만 이동합니다. 실패한 읽기나 쓰기는 30초 후 같은 위치에서 다시 시도하므로 메시지가 두 번 기록될 수는 있지만 유실되지는 않습니다. 브로커가 만료시킨 오프셋은 브로커가 여전히 보관 중인 가장 오래된 메시지부터 계속합니다.
- `topic`을 변경하면 오프셋이 토픽에 속하므로 `startFrom`부터 다시 시작합니다.

Azure 진단 설정, Log Analytics 데이터 내보내기, 데이터 수집 규칙은 Azure Event Hubs로 내보내며, Kafka 소스는 허브의 Kafka 엔드포인트를 통해 이를 읽습니다. `brokers`는 `<namespace>.servicebus.windows.net:9093`, `topic`은 이벤트 허브, `tls`는 켜기, `auth: sasl_plain`은 사용자 이름 `$ConnectionString`과 비밀번호로서의 연결 문자열을 사용합니다. Basic 계층에는 Kafka 엔드포인트가 없습니다. `messageFormat: azure_records`이면 각 `{"records": [...]}` 메시지가 풀립니다. 로그 레코드는 해당 `time`에 로그 이벤트가 되고, 메트릭 레코드는 커넥터의 `metricsStream`(기본값 `default`)에서 통계당 샘플 하나가 되며, [Azure Monitor 메트릭](#클라우드-메트릭)과 같은 방식으로 이름이 지정됩니다.

### S3 객체

`s3_source` 커넥터는 30초마다 버킷을 나열하고, 아직 읽지 않은 객체를 오래된 것부터 AWS S3 또는 S3 호환 스토리지에서 읽습니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "elb-logs",
        "kind": "s3_source",
        "configJson": {
          "bucket": "acme-logs",
          "region": "us-east-1",
          "prefix": "AWSLogs/123456789012/",
          "auth": "node_role",
          "targetStream": "elb",
          "startFrom": "latest"
        }
      }'
```

| 필드 | 참고 |
|---|---|
| `bucket`, `region`, `endpoint`, `virtualHostedStyle`, `auth` 및 해당 키 | [S3 대상](#amazon-s3)과 같습니다. 자격 증명에는 버킷에 대한 `s3:ListBucket`과 객체에 대한 `s3:GetObject` 권한이 필요합니다. |
| `prefix` | 이 접두사 아래의 객체만 읽습니다. 각 풀이 접두사 전체를 나열하므로 소스마다 고유한 접두사를 지정합니다. |
| `targetStream` | 대상 스트림입니다. 기본값 `default`. |
| `startFrom` | 첫 읽기의 시작 위치입니다. 기본값인 `latest`는 지금부터 그리고 그 이전 5분 내에 나타나는 객체용이고, `earliest`는 접두사 아래의 모든 객체용입니다. UI: **읽기 시작 위치**. |

- 객체는 줄 단위로 읽습니다. JSON 객체인 줄은 로그의 필드를 제공하고, CloudTrail이 기록하는 것처럼 `Records`만 가진 줄은 레코드마다 로그 하나를 제공하며, 그 밖의 줄은 `message`가 됩니다. `.gz` 및 `.zst` 객체는 파일 이름에 따라 압축 해제됩니다. 각 로그에는 `s3_bucket`, `s3_key`, `source`도 있습니다. 시각은 객체가 마지막으로 수정된 시점입니다.
- 한 번의 풀은 최대 100개 객체 또는 50,000개 로그까지 읽으며, 더 남아 있는 동안 다음 풀이 즉시 이어져 최대 2분 동안 진행됩니다.
- 읽기 상태는 로그가 기록된 후에만 이동합니다. 가져올 수 없는 객체는 해당 지점에서 풀을 중단하고 30초 후 다시 시도하므로 로그가 두 번 기록될 수는 있지만 유실되지는 않습니다.
- 읽을 수 없는 객체는 건너뛰고 커넥터에 알립니다. 다시 시도하면 그 뒤의 모든 항목이 지연되기 때문입니다. 여기에는 손상되었거나, 256 MiB를 초과하거나, 압축 해제 후 512 MiB를 초과하거나, 로그가 100만 개를 초과하거나, 64 MiB를 초과하는 줄이 있는 객체가 해당합니다.
- 객체는 키와 수정 시각으로 식별하며, 허용 범위는 5분입니다. 해당 범위 내에 같은 키로 다시 기록된 객체는 다시 읽지 않고, 수정 시각이 가장 최근에 읽은 객체보다 5분 넘게 오래된 객체는 아예 읽지 않습니다. S3는 멀티파트 업로드 시각을 업로드가 시작된 때로 기록하므로, 그보다 느린 업로드는 읽히지 않습니다.

### Google Cloud Pub/Sub 구독

`gcp_pubsub_pull` 커넥터는 30초마다 Pub/Sub 구독을 읽으며, 요청당 최대 1,000개 메시지를 읽고 더 남아 있는 동안 즉시 계속합니다. 메시지는 기록된 후에만 승인합니다. 기록되지 못한 메시지는 승인 기한이 지나면 다시 전달되므로 메시지가 두 번 기록될 수는 있지만 유실되지는 않습니다. 요청당 하나의 메시지를 보내는 [푸시 구독](#푸시-소스)보다 더 많은 로그를 감당하는 데 적합합니다.

| 필드 | 참고 |
|---|---|
| `serviceAccountKey` | 구독에 대한 `roles/pubsub.subscriber` 권한이 있는 서비스 계정의 JSON 키 파일입니다. |
| `subscription` | `projects/<project>/subscriptions/<name>` 또는 키의 프로젝트에 있는 구독 이름입니다. 승인 기한을 60초 이상으로 설정합니다. |
| `targetStream` | 대상 스트림입니다. 기본값 `default`. |

각 메시지는 푸시된 메시지와 같은 방식으로 읽습니다. Cloud Logging `LogEntry`는 푸시 탭의 매핑을 사용하고, 그 밖의 JSON 객체는 해당 필드로, 그 외의 것은 `message`로 읽습니다. **연결 테스트**는 메시지를 가져오지 않고 키가 구독을 소비할 수 있는지 확인합니다.

### 클라우드 메트릭

여섯 개 소스가 일정에 따라 클라우드 모니터링 서비스의 메트릭을 풀하여 메트릭 스트림에 기록합니다:

| 종류 | 클라우드 | API | 인증 | 권한 | 기본 `metricsStream` |
|---|---|---|---|---|---|
| `aws_cloudwatch_metrics` | Amazon CloudWatch | `ListMetrics`, `GetMetricData` | [AWS 자격 증명](#aws-인증) | `cloudwatch:ListMetrics`, `cloudwatch:GetMetricData` | `cloudwatch` |
| `azure_monitor_metrics` | Azure Monitor | Resource Graph, `metrics:getBatch` | 앱 등록의 `tenantId`, `clientId`, `clientSecret` | 구독에 대한 **Monitoring Reader** | `azure` |
| `gcp_monitoring_metrics` | Google Cloud Monitoring | `timeSeries.list` | `serviceAccountKey`, JSON 키 파일 | 프로젝트에 대한 `roles/monitoring.viewer` | `gcp` |
| `aliyun_cms_metrics` | Alibaba Cloud CloudMonitor | `DescribeMetricList` | `accessKey`, `secretKey` | `AliyunCloudMonitorReadOnlyAccess` | `aliyun` |
| `tencent_monitor_metrics` | Tencent Cloud Monitor | `GetMonitorData` | `accessKey`(SecretId), `secretKey`(SecretKey) | `QcloudMonitorReadOnlyAccess`, 그리고 CVM 인스턴스를 찾기 위한 `QcloudCVMReadOnlyAccess` | `tencentcloud` |
| `huawei_ces_metrics` | Huawei Cloud Eye | `ListMetrics`, `BatchListMetricData` | `accessKey`(AK), `secretKey`(SK) | `CES ReadOnlyAccess` | `huaweicloud` |

각 풀은 최소 `delay`초 전에 종료된 `period`초 단위의 전체 기간을 읽으며, 마지막으로 기록된 풀이 끝난 지점에서 시작합니다. 클라우드는 기간이 끝난 후 몇 분 뒤에 집계를 완료하며, 각 기간은 한 번만 읽습니다. 나중에 수정된 값은 읽은 그대로 유지됩니다. 새 커넥터는 한 기간 전부터 시작합니다. 한 번의 풀은 최대 12개 기간을 읽고 다음 틱에 계속합니다. 6시간 넘게 꺼져 있던 커넥터는 더 오래된 항목을 건너뛰고 이를 알립니다.

각 시계열의 각 통계는 해당 기간의 시작 시점에 `<cloud>_<namespace>_<metric>_<statistic>`라는 이름의 게이지 샘플 하나가 되며, yet-another-cloudwatch-exporter가 CloudWatch 메트릭의 이름을 지정하는 방식과 같습니다:

| 소스 | 예 | 레이블 |
|---|---|---|
| CloudWatch | `aws_ec2_cpuutilization_average` | `region`, `dimension_<Name>` |
| Azure Monitor | `azure_compute_virtualmachines_percentage_cpu_average` | `subscription_id`, `resource_group`, `resource_name`, `resource_id`, `region`, `dimension_<name>`, `tag_<key>` |
| Cloud Monitoring | `gcp_compute_instance_cpu_utilization_mean` | `project_id`, `resource_type`, 리소스 및 메트릭 레이블 |
| CloudMonitor | `aliyun_ecs_dashboard_cpuutilization_average` | `region`, `user_id`, `dimension_<key>` |

### 풀 진행 상황

커넥터 페이지에는 소스가 마지막으로 수신한 시점이 표시됩니다. 마지막 읽기가 실패한 소스는 그 옆에 경고를 표시하며, 이유는 툴팁과 커넥터 설정에 나옵니다. 소스가 마지막으로 건너뛴 항목도 그곳에 표시됩니다. API에서는 `readState`에 `lastError`와 `lastWarning`이 각각 `atTime`과 `text`를 포함해 있고, 어디까지 진행했는지를 나타내는 `position`도 있습니다. 커넥터를 저장해도 위치는 그대로 유지됩니다.

## 대상

대상은 예약된 파이프라인의 단계를 통과하는 모든 이벤트를 받습니다. **대상 추가 → 커넥터**를 사용해 플로우의 **대상**에 커넥터를 추가하십시오. 실패한 전달은 실행 내에서 재시도되며, 커넥터가 계속 수락하지 않는 이벤트는 데드 레터 스트림으로 이동합니다. 자세한 내용은 [재시도 및 데드 레터](/ko/pipelines#재시도-및-데드-레터)를 참조하십시오.

사용자 지정 헤더는 전달에서 자체적으로 설정하는 헤더로 지정할 수 없습니다: `Host`, `Content-Type`, `Content-Length`, `Content-Encoding`, `Transfer-Encoding`, `Connection`, `X-MoleSignal-Timestamp`, 또는 `X-MoleSignal-Sign`.

전달에는 다음 규칙이 적용됩니다:

- 4 MiB보다 큰 배치는 여러 요청으로 분할됩니다. 그보다 큰 이벤트는 별도 요청으로 전송됩니다.
- 모든 `2xx` 상태는 전달된 것으로 간주합니다. 그 외 상태는 전달 실패로 처리하며, 리디렉션도 마찬가지입니다. 리디렉션은 따르지 않습니다.
- 요청은 30초 후에 시간 초과됩니다.
- MoleSignal은 요청 전에 호스트를 확인하고, 확인된 주소로만 연결합니다. 클라우드 메타데이터 서비스가 응답하는 주소는 URL에 있든 DNS에서 오든 거부합니다: `169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254`, `100.100.100.200`. 다른 사설 주소는 허용됩니다.

#### HMAC 서명 확인

`hmac`을 사용하면 모든 요청에 두 개의 헤더가 포함됩니다:

| 헤더 | 내용 |
|---|---|
| `X-MoleSignal-Timestamp` | Unix 초 단위의 요청 시각입니다. |
| `X-MoleSignal-Sign` | `sha256=<hex>`이며, 공유 비밀 값으로 계산한 `<timestamp>.<body>`의 HMAC-SHA256입니다. |

요청을 확인하려면 같은 비밀 값으로 타임스탬프, `.`, 원시 본문 바이트로 구성된 값의 HMAC-SHA256을 계산하고, 그 결과를 서명과 상수 시간으로 비교하십시오. 몇 분이 지난 타임스탬프는 거부하여 캡처된 요청을 나중에 다시 전송할 수 없도록 하십시오.

```python
import hashlib
import hmac
import time


def verify(secret: bytes, timestamp: str, signature: str, body: bytes, tolerance: int = 300) -> bool:
    if abs(time.time() - int(timestamp)) > tolerance:
        return False
    signed = timestamp.encode() + b"." + body
    expected = "sha256=" + hmac.new(secret, signed, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## AWS 인증

S3 및 CloudWatch Logs는 다음 다섯 가지 방법 중 하나로 AWS에 인증합니다:

| `auth` | UI | 키 | 자격 증명 |
|---|---|---|---|
| `access_key` | **액세스 키** | `accessKey`, `secretKey` | IAM 사용자의 장기 키입니다. |
| `temporary_key` | **임시 키** | `accessKey`, `secretKey`, `sessionToken` | AWS STS에서 발급한 단기 키로, 해당 세션 토큰이 있어야만 유효합니다. 만료되기 전에 교체해야 합니다. |
| `node_role` | **노드 자격 증명** | | MoleSignal이 실행되는 노드의 자격 증명입니다. 키는 저장되지 않습니다. |
| `assume_role` | **역할 수임** | `roleArn`, 선택적으로 `accessKey` 및 `secretKey` | 조직의 외부 ID로 AWS STS를 통해 수임하는 역할입니다. |
| `web_identity` | **웹 자격 증명** | `roleArn` | 노드의 웹 자격 증명 토큰으로 수임하는 역할입니다. |

`auth`가 없으면 저장된 키가 결정합니다: 액세스 키는 `access_key`, `roleArn`은 `assume_role`, 둘 다 없으면 `node_role`로 해석됩니다. `roleArn`의 형식은 `arn:aws:iam::<account>:role/<name>`입니다.

### 노드 자격 증명

`node_role`은 AWS SDK가 노드에서 찾는 자격 증명을 사용합니다: 서비스 어카운트용 EKS IAM 역할(IRSA) 또는 EKS Pod Identity, ECS 태스크 역할, EC2 인스턴스 프로파일입니다. `AWS_ACCESS_KEY_ID`와 같이 노드 환경의 정적 키는 커넥터에 사용되지 않습니다.

<Warning>
  노드의 자격 증명과 웹 자격 증명 토큰은 배포에 속합니다. 배포 내 모든 조직이 `node_role` 및 `web_identity`를 선택할 수 있으므로, 노드의 자격 증명이 접근할 수 있는 모든 대상과 노드의 토큰을 신뢰하는 모든 역할은 모든 조직의 커넥터에 열려 있습니다. 모든 조직이 가질 수 있는 액세스 권한만 부여해야 합니다.
</Warning>

### 역할 수임

`assume_role`은 AWS STS에 역할의 1시간 유효 키를 요청하고 만료 5분 전에 키를 갱신합니다. 역할을 수임하는 기본 자격 증명은 노드의 자격 증명입니다. AWS에서 실행되지 않는 배포의 경우 **노드 ID 대신 액세스 키로 역할 수임**을 선택하고 IAM 사용자의 키를 입력합니다.

모든 조직은 변경할 수 없는 자체 외부 ID인 `molesignal-<organization ID>`로 역할을 수임합니다. 양식은 이를 **외부 ID** 항목에 표시하며, `GET /api/v1/connectors/aws-external-id`가 이를 반환합니다. ARN을 알게 되더라도 다른 조직이 역할을 수임할 수 없도록 역할의 신뢰 정책에서 외부 ID를 요구합니다:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "<ARN of the node role or IAM user>" },
      "Action": "sts:AssumeRole",
      "Condition": { "StringEquals": { "sts:ExternalId": "molesignal-<organization ID>" } }
    }
  ]
}
```

세션 이름은 `molesignal-<connector ID>`이며, AWS CloudTrail에 이 이름으로 표시됩니다. 요청은 커넥터의 `region`에 해당하는 리전 STS 엔드포인트로 전송됩니다. 리전이 비어 있으면 `us-east-1`이고, 중국 리전의 경우 `amazonaws.com.cn` 도메인을 사용합니다.

### 웹 자격 증명

`web_identity`는 노드의 `AWS_WEB_IDENTITY_TOKEN_FILE`이 제공하는 경로의 웹 자격 증명 토큰으로 역할을 수임합니다. 예를 들어 EKS가 IRSA용으로 프로젝션하는 서비스 어카운트 토큰입니다. 커넥터는 다른 파일을 지정할 수 없습니다. 역할의 신뢰 정책은 토큰을 발급하는 OIDC 공급자를 신뢰해야 합니다. `AWS_WEB_IDENTITY_TOKEN_FILE`이 없는 노드에서는 커넥터에 자격 증명이 없습니다.

토큰은 커넥터의 `region`에 해당하는 리전 STS 엔드포인트에서 교환되며, 노드 환경에서 `AWS_ENDPOINT_URL_STS`를 설정한 경우에는 해당 엔드포인트에서 교환됩니다. IRSA에서 오는 노드 자격 증명에도 동일하게 적용됩니다.

## 연결 테스트

**연결 테스트**는 저장되기 전에 양식에 있는 그대로 설정을 사용해 테스트합니다. 비워 둔 시크릿에는 저장된 시크릿을 사용합니다. 각 종류는 전송 또는 가져오기가 작동함을 입증하는 최소한의 작업만 수행합니다:

| 종류 | 테스트 |
|---|---|
| `s3` | 접두사 아래에 `.molesignal-connection-test` 객체를 쓰고, 정책이 허용하면 해당 객체를 제거합니다. |
| `kafka` | 브로커에서 토픽의 메타데이터를 읽어 연결, TLS, 인증을 확인하고 토픽이 존재함을 입증합니다. 메시지는 쓰지 않습니다. |
| `http` | 테스트로 표시된 이벤트 하나를 전송합니다: `"message": "MoleSignal connection test"` 및 `"molesignal_connection_test": true`. |
| `aws_cloudwatch_logs` | 로그 그룹의 최근 1분 동안의 이벤트를 최대 하나 읽습니다. 스트림에는 아무것도 쓰지 않고 읽기 위치를 그대로 둡니다. |
| `kafka_source` | `kafka`와 마찬가지로 브로커에서 토픽의 메타데이터를 읽습니다. 메시지는 읽지 않고 읽기 위치를 그대로 둡니다. |
| `s3_source` | 접두사 아래의 객체 하나를 나열하여 자격 증명과 `s3:ListBucket` 권한을 확인합니다. 아무것도 읽지 않고 읽기 위치를 그대로 둡니다. |

테스트는 25초 후 중단됩니다. API에서는 `POST /api/v1/connectors/test`가 시도할 `kind`와 `configJson`을 받습니다. 같은 종류의 저장된 커넥터 `id`를 지정하면 `***`는 해당 커넥터가 보유한 시크릿을 나타냅니다. 작동할 수 없는 설정은 저장할 때와 마찬가지로 `400`으로 응답합니다.

```bash
curl -X POST http://localhost:5080/api/v1/connectors/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "id": "<connector id>",
        "kind": "kafka",
        "configJson": {
          "brokers": "b-1.example.com:9096",
          "topic": "logs",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "***"
        }
      }'
```

```json
{ "ok": true, "code": "ok", "detail": null, "elapsedMs": 412 }
```

`elapsedMs`는 테스트에 걸린 시간입니다. 실패한 테스트는 `code`에 원인을 표시하고, `detail`에는 상대방의 메시지를 최대 600자까지 담습니다:

| `code` | 의미 |
|---|---|
| `ok` | 연결되었습니다. |
| `invalid` | 설정이 작동할 수 없거나 커넥터가 연결할 대상이 없는 푸시 소스입니다. |
| `no_credentials` | AWS 자격 증명을 확보할 수 없습니다: 노드에 자격 증명이 없거나 요청한 종류의 자격 증명이 없습니다. |
| `denied` | 상대방이 자격 증명 또는 허용된 작업을 거부했습니다. |
| `not_found` | 버킷, 토픽, 로그 그룹 또는 주소가 존재하지 않습니다. |
| `tls` | TLS 핸드셰이크에 실패했습니다: 인증서를 신뢰할 수 없거나 인증서가 제시되지 않았습니다. |
| `unreachable` | 호스트를 확인할 수 없거나 연결할 수 없습니다. |
| `timeout` | 시간 내에 응답이 없습니다. |
| `failed` | 그 밖의 실패입니다. |

## API

| 엔드포인트 | 권한 | 목적 |
|---|---|---|
| `GET /api/v1/connectors` | `pipelines.read` | 조직의 커넥터를 나열합니다. |
| `POST /api/v1/connectors` | `pipelines.edit` | 커넥터를 생성합니다. `enabled`의 기본값은 `true`입니다. |
| `GET /api/v1/connectors/{id}` | `pipelines.read` | 커넥터를 읽습니다. |
| `PUT /api/v1/connectors/{id}` | `pipelines.edit` | `name`, `kind`, `configJson`, `enabled`를 교체하며 모두 필수입니다. |
| `DELETE /api/v1/connectors/{id}` | `pipelines.edit` | 커넥터를 삭제합니다. |
| `POST /api/v1/connectors/test` | `pipelines.edit` | 저장하기 전에 설정을 테스트합니다. |
| `GET /api/v1/connectors/aws-external-id` | `pipelines.read` | 조직의 외부 ID를 `externalId`로 반환합니다. |

커넥터는 `id`, `name`, `kind`, 시크릿이 마스킹된 `configJson`, `secretKeys`, `enabled`, `lastRunAt`, `readState`, `createdAt`, `updatedAt`으로 조회됩니다.

## 권한

`pipelines.read`는 커넥터를 나열하고 검사하며 외부 ID를 읽습니다. `pipelines.edit`는 커넥터를 생성, 업데이트, 삭제, 테스트합니다. 테스트는 저장된 시크릿을 사용하고 호출자를 대신하여 다른 시스템에 연결하므로 `pipelines.edit`가 필요합니다. 푸시 수신자는 푸시 토큰으로 인증하며 일반 로그인 JWT를 대체 수단으로 허용하지 않습니다.
