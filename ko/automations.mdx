자동화는 실행될 때마다 Mole Agent에 같은 작업을 요청합니다. 예를 들어 매일 아침 서비스 상태를 점검하거나, 새로 발생한 심각 인시던트를 조사하거나, 파이프라인에서 호출할 때 배포를 검토할 수 있습니다. Mole Agent는 채팅에서와 마찬가지로 자동화의 소속 범위에 있는 도구, 스킬, 지식을 사용합니다. 각 실행은 채팅으로 저장되며, 자동화를 볼 수 있는 사용자는 해당 채팅을 열 수 있습니다. 실행이 끝나면 선택한 알림 채널로 결과를 전송합니다. 인시던스로 시작하는 자동화는 해당 인시던트의 근본 원인 분석(RCA)도 기록할 수 있습니다.

## 시작하기 전에

- **Mole Agent → 설정 → 모델 및 추론**에서 AI 모델을 하나 이상 활성화합니다. [Mole Agent](/ko/agent#모델-공급자-설정)를 참조합니다. 활성화한 모델이 없으면 실행이 실패하고 이유가 표시됩니다.
- 다음 권한을 확인합니다.

| 작업 | 권한 |
|---|---|
| 자동화와 실행 기록 보기, 실행 채팅 열기 | `agent.automations.read` 및 소속 범위에 따른 접근 권한. [소속 범위](#소속-범위)를 참조합니다. |
| 생성, 편집, 켜기 | `agent.automations.manage`(기본적으로 소유자, 관리자, 편집자 역할에 부여) 및 소속 범위에 따른 접근 권한 |
| 지금 실행 | `agent.automations.run`(동일한 역할에 부여) 및 소속 범위에 따른 접근 권한 |
| API 토큰 관리 | `agent.automations.tokens`(동일한 역할에 부여) 및 소속 범위에 따른 접근 권한 |
| 끄기 및 삭제 | 위와 동일한 권한이 필요합니다. `agent.manage` 권한이 있으면 볼 수 있는 모든 자동화를 끄거나 삭제할 수 있습니다. |
| 양식에서 알림 채널 선택 | 알림 커넥터 목록을 조회하는 `notify.connectors.read` |

## 자동화 만들기

**Mole Agent → 자동화 → 새 자동화**를 열고 빈 자동화 또는 템플릿에서 시작합니다.

| 템플릿 | 실행 조건 | 수행 작업 |
|---|---|---|
| **인시던트 분석** | 심각도가 오류 또는 심각인 새 인시던트 | 도구를 사용해 인시던트를 조사합니다. 인시던스를 트리거한 쿼리를 다시 실행하고 오류 로그, 트레이스, APM, 서비스 토폴로지를 검토합니다. 가장 가능성이 높은 근본 원인과 근거를 제시하고 인시던트의 RCA로 기록합니다. |
| **일일 상태 점검** | 평일 09:00 | 최근 24시간의 오류율, 지연 시간, 오류 패턴, 미해결 인시던트를 확인하고 주의가 필요한 항목을 알려줍니다. |
| **주간 알림 노이즈 검토** | 월요일 10:00 | 지난주에 가장 자주 발동했거나, 발동과 해제를 반복했거나, 아무 조치도 이루어지지 않은 알림 규칙을 찾고 각 규칙의 조정 방법을 제안합니다. |
| **주간 온콜 업무량** | 월요일 10:30 | 담당자별 및 일정별 인시던트, 야간 호출, 응답 시간을 집계하고 업무량을 줄이는 방법을 제안합니다. |
| **변경 영향 점검** | API 호출 | 배포의 영향을 받은 서비스의 배포 전후 상태를 비교하고 배포로 인해 회귀가 발생했는지 알려줍니다. |

양식에는 다음 필드가 있습니다.

| 필드 | 설명 |
|---|---|
| **이름** | 조직 내에서 고유해야 합니다. |
| **작업 지시** | 최대 8000자까지 작업을 입력합니다. 실행할 때마다 새 채팅을 시작하듯 Mole Agent에 작업을 요청합니다. |
| **설명** | 자동화의 용도를 한 줄로 설명합니다. |
| **소속 범위** | 자동화를 만들 때 개인, 소속 팀 중 하나 또는 조직을 선택합니다. |
| **실행 조건** | 예약 실행, 새 인시던트, API 호출 또는 수동 실행을 선택합니다. [실행 조건](#실행-조건)을 참조합니다. |
| **시간 제한** | 5~60분으로 설정할 수 있으며 기본값은 10분입니다. 제한을 넘긴 실행은 중지하고 실패로 처리합니다. |
| **켜짐** | 꺼진 자동화는 **지금 실행**을 선택할 때만 시작합니다. |
| **알림 채널** | 알림 커넥터에서 고정 주소 또는 그룹을 최대 5개까지 지정합니다. Alibaba Cloud SMS와 음성 알림은 승인된 템플릿으로만 전송할 수 있으므로 선택할 수 없습니다. |
| **결론을 인시던트의 근본 원인 분석(RCA)으로 기록** | 인시던스로 시작하는 자동화에 사용합니다. |

조직당 자동화를 최대 50개까지 만들 수 있습니다. 행 메뉴에서 **복제**를 선택하면 꺼진 상태의 사본이 양식에 열립니다. 다른 이름이나 소속 범위로 저장할 수 있습니다.

### 소속 범위

소속 범위에 따라 실행에 사용할 수 있는 리소스와 자동화를 볼 수 있는 사용자가 달라집니다. 자동화를 만든 후에는 소속 범위를 변경할 수 없습니다. 다른 범위를 사용하려면 자동화를 복제합니다.

| 소속 범위 | 실행에 사용하는 항목 | 볼 수 있는 사용자 |
|---|---|---|
| 개인 | 조직 및 개인의 스킬과 MCP 서버, 조직의 지식, 개인 메모리 | 자동화의 소유자 및 `agent.manage` 권한이 있는 사용자 |
| 팀 | 조직 및 팀의 리소스와 지식, 팀 메모리 | 팀 구성원 및 `agent.manage` 권한이 있는 사용자 |
| 조직 | 조직의 리소스와 지식만 사용합니다. 실행 메모리는 유지하지 않습니다. | `agent.automations.read` 권한이 있는 모든 사용자 |

인시던스로 시작한 조직 자동화는 인시던트의 에스컬레이션 정책에서 팀을 결정합니다. 정책에서 처음 호출하는 팀을 사용하고, 호출하는 팀이 없으면 첫 번째 온콜 일정에 연결된 팀을 사용합니다. 해당 팀이 없으면 조직 범위에서 실행합니다.

### 실행 계정

자동화는 마지막으로 저장한 사용자의 계정으로 실행합니다. 실행할 때마다 해당 사용자의 권한을 다시 확인하고, 구성원별 자격 증명이 필요한 MCP 서버에는 해당 사용자의 자격 증명을 사용합니다. 자동화를 저장하면 저장한 계정이 실행 계정이 되며, 양식에서 이를 안내합니다. API 토큰은 발급한 사용자가 아닌 역할을 나타내므로 API 토큰으로는 자동화를 저장할 수 없습니다.

실행 계정이 조직에서 더 이상 Mole Agent를 사용할 수 없으면 모든 실행이 실패하고 그 이유가 표시됩니다. 권한이 있는 사용자가 자동화를 다시 저장하면 이 문제를 해결할 수 있습니다.

## 실행 조건

| 트리거 | 실행 시점 |
|---|---|
| **예약 실행** | 지정한 시간대에서 5개 필드(분, 시, 일, 월, 요일)로 구성된 cron 표현식에 따라 15분에 최대 한 번 실행합니다. 요일 필드에서 0과 7은 모두 일요일입니다. 일과 요일 중 하나만 제한하고 둘 다 제한하지 않습니다. 이전 실행이 아직 진행 중이면 다음 실행을 건너뜁니다. |
| **새 인시던트** | 자동화를 저장하거나 켠 후 생성된 인시던트가 지정한 필터를 모두 충족할 때 실행합니다. 심각도, 알림 규칙, 영향받는 서비스, 값이 일치하는 레이블로 필터링합니다. 각 인시던트는 한 번만 분석합니다. 규칙과 레이블이 같은 그룹의 인시던트는 30분 동안 한 번만 분석합니다. |
| **새 탐지 결과** | 자동화를 저장하거나 켠 후 나타난 [탐지](/ko/alerting/discovery) 결과가 지정한 필터를 모두 충족할 때 실행합니다. 유형, 최소 심각도, 서비스, 호스트 또는 컨테이너로 필터링합니다. 각 탐지 결과는 한 번만 조사합니다. |
| **API 호출** | 외부 시스템에서 자동화의 토큰을 전송할 때 실행합니다. [CI/CD에서 시작하기](#ci/cd에서-자동화-시작)를 참조합니다. |
| **수동 실행** | 사용자가 직접 실행할 때만 시작합니다. |

행에서 **지금 실행**을 선택하면 켜짐 여부와 관계없이 지정된 실행 계정으로 자동화를 시작합니다. 1분에 최대 한 번 실행할 수 있습니다.

## 실행 기록

행에서 **실행 기록**을 선택하면 최근 실행 100개를 최신순으로 표시합니다. 각 항목에는 실행 결과와 이유, 트리거, 답변의 첫 부분, 알림을 받지 못한 채널이 표시됩니다. **실행 열기**를 선택하면 전체 실행 내용이 담긴 채팅이 열립니다. 이 채팅은 채팅 목록에 표시되지 않으며 이어서 대화할 수 없습니다. 다시 요청하려면 자동화를 실행합니다.

실행 중에는 사용자가 답변할 수 없습니다. Mole Agent는 질문이 생겨도 자체 판단으로 진행합니다. 사용자 확인이 필요한 도구는 실행하지 않으며, 실행 계정의 자격 증명이 필요하지만 해당 자격 증명이 저장되어 있지 않은 MCP 서버는 사용하지 않습니다. Mole Agent는 답변에 해당 내용을 명시하고 실행 상태를 **사용자 조치 필요**로 표시합니다.

| 상태 | 의미 |
|---|---|
| **실행 중** | Mole Agent가 작업을 수행 중입니다. |
| **성공** | 답변을 생성하고 알림 전송과 RCA 기록을 완료했습니다. |
| **일부 완료** | 답변을 생성했지만 일부 알림을 전송하지 못했거나 RCA를 기록하지 못했습니다. |
| **사용자 조치 필요** | 답변을 생성했지만 필요한 질문 답변, 확인 또는 자격 증명을 받지 못했습니다. |
| **실패** | 답변을 생성하지 못했습니다. 모델이나 도구에 오류가 발생했거나, 시간 제한을 초과했거나, 활성화한 모델이 없거나, 실행 계정이 더 이상 Mole Agent를 사용할 수 없습니다. |
| **건너뜀** | 실행을 시작하지 않았습니다. 조직의 일일 토큰 예산을 모두 사용했거나, 이전 실행이 끝나지 않았거나, 직전에 해당 인시던트를 분석했습니다. |
| **중지됨** | 사용자가 실행을 중지했거나 실행 중인 서버가 중지되었습니다. |

실행 중 모델을 호출할 때 사용한 토큰은 조직의 일일 토큰 예산에 포함되며, 소스별 사용량에서 **자동화**로 표시됩니다.

## 알림 및 인시던트의 근본 원인 분석(RCA)

실행이 성공하거나, 담당자의 개입이 필요하거나, 실패하면 각 채널로 알림을 보냅니다. 알림에는 자동화 이름, 실행 결과, 응답의 첫 부분, 결과의 근거, 실행 링크가 포함됩니다. 자동화를 저장한 사용자의 언어로 알림을 작성하며, 다른 알림과 마찬가지로 전송 기록에 표시합니다.

인시던트로 시작하는 자동화에서 **결론을 인시던트의 근본 원인 분석(RCA)으로 기록**을 켜면 Mole Agent의 응답을 인시던트의 RCA로 기록하고 인시던트 페이지에 표시합니다. 채팅에서 직접 작성한 RCA는 그대로 유지합니다. 조직에서 이러한 자동화를 켜면 기본 RCA 생성 기능이 조직의 인시던트 분석을 자동화에 맡겨 같은 인시던트를 두 번 분석하지 않습니다. **인시던트 분석** 템플릿은 이 방식으로 설정되어 있습니다.

## CI/CD에서 자동화 시작

API 호출로 시작하는 자동화의 행 메뉴에서 **API 토큰**을 열고 **토큰 생성**을 선택합니다. 토큰은 한 번만 표시합니다. 새 토큰을 생성하면 기존 토큰을 즉시 대체하며, **토큰 취소**를 선택하면 토큰을 제거합니다.

배포 시 토큰을 전송하고 `text`에 변경 사항을 설명합니다.

```bash
curl -X POST "https://molesignal.example.com/api/v1/public/automations/<automation-id>/trigger" \
  -H "Authorization: Bearer mspat-..." \
  -H "Content-Type: application/json" \
  -d '{"text": "Deployed checkout-api v42 at 14:05"}'
```

`text`는 선택 사항이며 최대 8000자까지 입력할 수 있습니다. Mole Agent는 이 값을 지시가 아닌 실행 관련 데이터로 읽습니다. API는 `202`와 함께 `runId`, `status`, `chatUrl`을 반환합니다. 토큰이 잘못되었거나 자동화를 찾을 수 없으면 `401`을 반환합니다. 자동화가 꺼져 있거나 API 호출로 시작하도록 설정되지 않았으면 `409`를 반환합니다. 10초 이내에 다시 호출하면 `429`를 반환합니다.

## Mole Agent 사용 내역 검토

`/insight [days]`는 채팅 범위에서 최근 30일 또는 지정한 일수 동안의 Mole Agent 사용 내역을 검토하는 기본 스킬입니다. 질문 내용, 응답 및 자동화 실행 결과, 도움이 되지 않는다고 평가받은 항목과 그 이유, 자주 실패한 도구, 사용한 스킬을 검토합니다. 마지막으로 지식 파일 작성이나 자동화 수정 등 개선 사항을 최대 5개 제안합니다. 실제로 변경하는 항목은 없습니다. 팀 채팅에서는 해당 팀을, 개인 채팅에서는 채팅 사용자와 소속 팀을 검토합니다. 채팅에서 사용하거나 주간 자동화의 작업으로 설정합니다.
