MoleSignal은 TOML 파일 하나와 `MS_` 환경 변수를 읽습니다. 각 릴리스에 포함된 `conf/config.toml` 샘플 파일을 기반으로 설정합니다. 샘플 파일에는 모든 설정이 나열되어 있으며, 이 페이지에서는 각 설정을 설명합니다.

```bash
molesignal --config /etc/molesignal/config.toml
```

## 설정 로드 방식

설정은 다음 순서로 적용합니다. 나중에 읽은 값이 먼저 읽은 값을 덮어씁니다.

1. 내장 기본값.
2. `--config`로 전달한 TOML 파일.
3. `MS_` 환경 변수.

설정을 변경한 후에는 프로세스를 다시 시작합니다. 실행 중인 프로세스는 파일 변경 사항을 로그에 기록하지만 적용하지는 않습니다.

<Note>
  대부분의 섹션은 정의되지 않은 키를 무시하므로 키에 오타가 있어도 설정에 영향을 주거나 경고를 표시하지 않습니다. `[meta_database]`, `[object_store]`(`[object_store.retry]` 포함), `[telemetry]`(`[telemetry.trace]` 및 `[telemetry.self_collect]` 포함), `[apm]`, `[probe]`, `[otlp_grpc]`, `[notify]`, `[scheduled_reports.renderer]` 섹션은 정의되지 않은 키를 허용하지 않으므로 키에 오타가 있으면 프로세스가 시작되지 않습니다.
</Note>

참조 표의 **기본값** 열에는 `conf/config.toml` 샘플 파일의 값이 표시됩니다. 키를 생략했을 때 적용하는 내장 기본값이 샘플 값과 다르면 설명에 명시합니다.

## 환경 변수

모든 설정에 대응하는 환경 변수가 있습니다. `MS_` 접두사 뒤에 설정 경로의 각 단계를 대문자로 쓰고, 단계 사이를 밑줄 하나로 연결합니다.

| 설정 | 환경 변수 |
|---|---|
| `[http].port` | `MS_HTTP_PORT` |
| `[meta_database].dsn` | `MS_META_DATABASE_DSN` |
| `[cluster].advertise_addr` | `MS_CLUSTER_ADVERTISE_ADDR` |
| `[node].roles` | `MS_NODE_ROLES` |

목록은 `MS_NODE_ROLES='["intake","querier"]'`와 같이 TOML 구문으로 작성합니다. 이름에 마침표나 연속된 밑줄 두 개가 있으면 인식하지 않습니다.

다음 변수는 설정과 별도로 읽습니다.

| 변수 | 용도 |
|---|---|
| `MS_CIPHER_KEY` | MoleSignal이 PostgreSQL에서 암호화하는 시크릿의 루트 키입니다. 무작위 바이트 32개를 base64로 인코딩하여 지정합니다. 이 키를 지정하지 않으면 프로세스는 모든 바이트가 0인 개발용 키를 사용하고 경고를 로그에 기록합니다. `rewrap-kek`를 실행하지 않고는 키를 변경하지 마십시오. [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다. |
| `MS_AUTH_JWT_SECRET_OVERRIDE` | 처음 시작할 때 PostgreSQL에서 생성하는 JWT 서명 시크릿 대신 지정한 값을 사용합니다. |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN` | 역할을 분리한 노드가 서로 전달하는 트레이스 후보와 자체 텔레메트리를 인증하는 공유 시크릿입니다. [트레이스 캡처](#트레이스-캡처-및-테일-샘플링)(기본적으로 활성화됨) 또는 `[telemetry.self_collect]`를 활성화한 경우, 역할을 분리한 모든 노드에 동일한 값을 설정합니다. `intake` 역할이 없는 노드는 이 값이 없으면 시작되지 않습니다. |
| `MS_TRACE_FINGERPRINT_KEY` | 저장하지 않는 값을 대신하는 HMAC-SHA-256 지문을 생성하는 키입니다. 지문은 [MoleSignal 자체 스팬](/ko/self-observability#백엔드-분산-트레이싱)의 SQL 문의 구조와 객체 키, [APM 종속성](/ko/apm#종속성)의 데이터베이스 이름을 대신합니다. 16바이트 이상을 사용합니다. 더 짧은 값은 무시합니다. 키가 다르면 지문도 달라지므로 모든 노드에 동일한 값을 설정합니다. 키가 없으면 지문을 기록하지 않으며, 키 없는 해시로 대체하지도 않습니다. 키는 환경 변수에서만 읽으며 API 응답, 로그 또는 스팬에 노출하지 않습니다. |
| `MS_AGENT_OPENAI_API_KEY`, `MS_AGENT_ANTHROPIC_API_KEY`, `MS_AGENT_COMPATIBLE_API_KEY` | Mole Agent 모델 공급자의 개발용 대체 API 키입니다. 각 키에 대응하는 `_BASE_URL` 변수가 있습니다. 프로덕션용 공급자는 제품에서 직접 구성합니다. |
| `RELEASE_CHANNEL` | 배포의 성숙도 단계를 `alpha`, `beta`, `rc`, `stable` 중 하나로 표시합니다. |
| `RUST_LOG` | 설정하면 `[telemetry].log_level`을 덮어씁니다. |
| `AZURE_STORAGE_ACCOUNT`, `AZURE_STORAGE_ACCESS_KEY` | `azure` 객체 스토리지 백엔드에 사용하는 Azure Blob 자격 증명입니다. |
| `GOOGLE_APPLICATION_CREDENTIALS` | `gcs` 객체 스토리지 백엔드에 사용하는 서비스 계정 JSON 파일의 경로입니다. |

## 최소 프로덕션 설정

프로덕션 노드에는 최소한 다음 설정이 필요합니다. 파일의 나머지 설정은 기본값으로 유지해도 됩니다.

```toml
[http]
external_url = "https://molesignal.example.com"

[meta_database]
dsn = "postgres://molesignal:<password>@db.internal:5432/molesignal"

[object_store]
backend = "s3"
bucket = "molesignal"
region = "us-east-1"
endpoint = ""          # empty for AWS S3, the service URL for S3-compatible storage
access_key = ""        # prefer MS_OBJECT_STORE_ACCESS_KEY
secret_key = ""        # prefer MS_OBJECT_STORE_SECRET_KEY

[wal]
dir = "/var/lib/molesignal/wal"

[auth]
root_email = "admin@example.com"
root_password = "<initial password>"
```

환경 변수 `MS_CIPHER_KEY`도 설정합니다. 운영을 시작하기 전에 필요한 전체 단계는 [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다.

## 노드

`[node]`에서 프로세스가 실행할 역할을 선택합니다. [역할 기반 배포](/ko/deployment/role-based)를 참조합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `roles` | `["standalone"]` | 실행할 역할: `standalone`, `router`, `intake`, `querier`, `compactor`, `alert`. `standalone`은 한 프로세스에서 모든 역할을 실행합니다. |
| `id` | 빈 값 | 노드 ID입니다. 최대 64자까지 사용할 수 있습니다. 값을 비워 두면 OS의 호스트 이름을 사용합니다. 한 호스트에서 여러 프로세스를 실행하는 경우 프로세스마다 다른 ID를 설정합니다. |
| `drain_timeout_secs` | `30` | `SIGTERM` 또는 `SIGINT`를 받은 후 아직 처리하지 않은 수집 데이터를 모두 기록할 때까지 대기하는 시간입니다. 이 시간이 지나면 프로세스가 종료되고, 다른 `intake` 노드가 아직 기록하지 않은 데이터를 인계받습니다. |

## 리스너

### HTTP

| 키 | 기본값 | 설명 |
|---|---|---|
| `bind` | `0.0.0.0` | 수신 주소입니다. |
| `port` | `5080` | `[http.tls]`를 비활성화했을 때 사용하는 HTTP 포트입니다. |
| `gzip` | `true` | gzip을 지원하는 클라이언트에 프로세스가 제공하는 웹 UI 파일을 gzip으로 압축합니다. API 응답은 압축하지 않습니다. 리버스 프록시가 압축을 처리하는 경우 `false`로 설정합니다. |
| `external_url` | 비어 있음 | `https://molesignal.example.com`과 같은 공개 오리진입니다. 비워 두면 웹 UI는 브라우저 오리진을 사용합니다. 자동으로 생성되는 온보딩 스니펫은 이 값을 사용하며, 상태 페이지의 사용자 지정 도메인은 이 값을 CNAME 대상으로 사용합니다. IM에서 Mole Agent의 계정 링크와 채팅 링크는 이 값을 사용합니다. Microsoft Teams 콜백 주소도 이 오리진을 사용하므로 Teams 연동 시에는 HTTPS를 사용해야 합니다. [IM에서 Mole Agent 사용](/ko/im#teams-보안)을 참조합니다. [패스키](/ko/identity/mfa#인스턴스-요구-사항)는 이 오리진의 호스트 이름에 연결되므로 HTTPS 도메인 이름을 사용해야 합니다. 값을 변경한 후에는 다시 시작합니다. |

### HTTP TLS 및 ACME

`[http.tls]`는 Let's Encrypt와 같은 ACME 서비스에서 인증서를 자동으로 발급받아 TLS 리스너를 시작합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `false` | TLS 리스너를 활성화하는 설정입니다. `false`로 설정하면 나머지 키를 모두 무시합니다. |
| `plain_port` | `80` | ACME HTTP-01 챌린지와 HTTPS 리디렉션에 사용하는 일반 HTTP 포트입니다. |
| `port` | `443` | HTTPS 포트입니다. |
| `acme_directory` | `production` | `production`, `staging`(Let's Encrypt 스테이징) 또는 사용자 지정 디렉터리 URL을 사용합니다. |
| `account_email` | 비어 있음 | ACME 계정 이메일 주소입니다. Let's Encrypt에서는 필수입니다. |
| `key_storage_dir` | `/var/lib/molesignal/acme` | ACME 계정 키와 도메인별 키를 저장하는 디렉터리입니다. |
| `issue_poll_secs` | `60` | 인증서 발급을 기다리는 도메인을 확인하는 간격입니다. |
| `renewal_retry_secs` | `21600` | 갱신을 재시도하고 만료 여부를 확인하는 간격입니다. |

### 내부 gRPC

`[grpc]`는 노드 간 트래픽을 처리합니다. 이 포트는 신뢰할 수 있는 네트워크에서만 사용합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `bind` | `0.0.0.0` | 수신 주소입니다. |
| `port` | `5082` | 포트입니다. 피어 노드도 `[cluster].advertise_addr`를 통해 이 포트를 사용합니다. |
| `max_message_size` | `32` | gRPC 메시지의 최대 크기(MiB)입니다. |

### OTLP gRPC

`[otlp_grpc]`는 OTLP gRPC 수신기를 구성합니다. 수신기에는 별도의 활성화 설정이 없으며, `standalone` 노드를 포함해 `intake` 역할을 실행하는 모든 노드에서 수신 대기합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `bind` | `0.0.0.0` | 수신 주소입니다. |
| `port` | `4317` | 포트입니다. |
| `max_message_size` | `32` | gRPC 메시지의 최대 크기(MiB)입니다. |

### Arrow Flight SQL

`[flight_sql]`은 DBeaver, JDBC, ADBC와 같은 SQL 클라이언트의 요청을 처리합니다. 모든 호출에는 API 토큰이 필요합니다. [데이터베이스 클라이언트](/ko/query/database-clients)를 참조합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `false` | 리스너를 시작합니다. |
| `bind` | `0.0.0.0` | 수신 주소입니다. |
| `port` | `5083` | 포트입니다. |
| `default_lookback_hours` | `24` | 시간 필터가 없는 SQL 쿼리에서 과거 데이터를 조회할 범위(시간 단위)입니다. |
| `max_message_size` | `32` | 메시지의 최대 크기(MiB)입니다. |

### Probe Agent

`[probe]`는 Probe Agent의 등록 및 제어 엔드포인트를 구성합니다. 이 엔드포인트는 `standalone` 및 `alert` 노드에서 시작합니다. 등록에는 서버를 인증하는 TLS를 사용하며, 제어 스트림에는 수명이 짧은 상호 TLS ID를 사용합니다. [신세틱 모니터링](/ko/synthetics)을 참조합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `bind` | `0.0.0.0` | 수신 주소입니다. |
| `register_port` | `5084` | 등록 포트입니다. `control_port`와 다른 포트를 지정해야 합니다. |
| `control_port` | `5085` | 제어 스트림 포트입니다. |
| `register_endpoint` | `https://localhost:5084` | 에이전트가 등록에 사용하는 공개 `https://` URL입니다. 일회성 등록 명령이 이 URL을 출력합니다. 프록시 또는 로드 밸런서 뒤에서 실행하는 경우 이 값을 설정합니다. |
| `control_endpoint` | `https://localhost:5085` | 제어 스트림의 공개 `https://` URL입니다. |
| `server_names` | `["localhost", "127.0.0.1"]` | 서버 인증서에 포함할 DNS 이름과 IP 주소입니다. 엔드포인트의 공개 호스트 이름을 포함합니다. |
| `certificate_days` | `30` | 발급한 인증서의 유효 기간(일 단위)입니다. 1~365 범위에서 지정합니다. |
| `max_message_size` | `32` | 메시지의 최대 크기(MiB)입니다. |

### pprof

`[profiling]`은 진단을 위해 노드 로컬 pprof 리스너를 시작합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `false` | 리스너를 시작합니다. |
| `bind` | `127.0.0.1` | 수신 주소입니다. `allow_remote`가 `true`가 아니면 루프백 주소를 지정해야 합니다. |
| `port` | `5086` | 포트입니다. 활성화된 다른 리스너와 다른 포트를 지정해야 합니다. 이 노드에서 실행하지 않는 역할의 리스너도 포함합니다. |
| `allow_remote` | `false` | `bind`에 루프백이 아닌 주소를 지정할 수 있도록 허용합니다. 원격 접근을 허용하면 런타임 정보가 유출될 수 있습니다. |

## 스토리지

### 메타데이터 데이터베이스

`[meta_database]`는 메타데이터, ID 정보, 파일 카탈로그, 제품 리소스를 저장하는 PostgreSQL 데이터베이스를 구성합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `dsn` | `postgres://molesignal:molesignal@localhost:5432/molesignal` | PostgreSQL 연결 문자열입니다. 예시 자격 증명을 교체합니다. |
| `min_connections` | `2` | 시작 시 여는 연결 수입니다. `max_connections`를 초과할 수 없습니다. |
| `max_connections` | `16` | 연결 풀의 최대 연결 수입니다. |

MoleSignal은 시작할 때 내장된 스키마 마이그레이션을 데이터베이스에 적용합니다. [업그레이드](/ko/upgrade)를 참조합니다.

### 오브젝트 스토리지

`[object_store]`는 Parquet 파일, 검색 인덱스, 프로파일 Blob을 저장하는 오브젝트 스토리지를 구성합니다. 지원 백엔드는 `local`, `s3`, `azure`, `gcs`입니다. AWS S3와 RustFS, Cloudflare R2, Alibaba Cloud OSS 등의 S3 호환 서비스에는 `s3`를 사용합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `backend` | `local` | `local`, `s3`, `azure`, `gcs` 중 하나입니다. |
| `root` | `./data/objects` | `local` 백엔드의 디렉터리입니다. 다른 백엔드는 이 값을 무시합니다. |
| `bucket` | 비어 있음 | `s3`와 `gcs`의 버킷 이름 또는 `azure`의 컨테이너 이름입니다. 해당 백엔드에서는 필수입니다. |
| `region` | 비어 있음 | S3 리전입니다. S3 호환 서비스에서 지정한 값을 사용합니다. |
| `endpoint` | 비어 있음 | S3 엔드포인트 URL입니다. AWS S3에서는 비워 둡니다. RustFS와 유사한 서비스에는 `http://host:9000` 형식의 URL을 사용합니다. |
| `path_style` | `false` | `false`는 AWS S3와 Huawei Cloud OBS에 필요한 가상 호스팅 방식 주소 지정을 사용합니다. RustFS와 대부분의 자체 호스팅 서비스에 필요한 경로 방식 주소 지정을 사용하려면 `true`로 설정합니다. |
| `access_key` | 비어 있음 | S3 액세스 키 또는 Azure 스토리지 액세스 키입니다. |
| `secret_key` | 비어 있음 | S3 시크릿 키입니다. |
| `credentials_file` | 비어 있음 | `access_key=<value>`와 `secret_key=<value>` 줄이 포함된 파일의 경로입니다. 아래의 우선순위를 참조합니다. |
| `multipart_threshold_size` | `32` | 이 크기(MiB) 이상의 오브젝트는 여러 파트로 나누어 업로드합니다. 매니페스트 오브젝트와 버전 조건이 있는 쓰기는 항상 단일 요청으로 업로드합니다. 최솟값은 1입니다. |
| `multipart_part_size` | `8` | 멀티파트 업로드에서 파트 하나의 크기(MiB)입니다. 범위는 5~1024입니다. 매우 큰 오브젝트는 더 큰 파트를 사용해 업로드당 파트 수를 10,000개 이하로 유지합니다. |
| `range_threshold_size` | `16` | 이 크기(MiB) 이상의 바이트 범위를 읽을 때는 여러 청크 요청으로 나누어 병렬로 실행합니다. 최솟값은 1입니다. |
| `range_chunk_size` | `8` | 청크 요청 하나의 크기(MiB)입니다. 범위는 1~1024입니다. |
| `max_concurrency` | `8` | 프로세스당 동시에 실행할 수 있는 오브젝트 스토리지 작업 수입니다. |
| `op_timeout_secs` | `30` | 동시 실행 슬롯을 기다리는 시간과 백엔드 작업 한 건의 실행 시간에 적용하는 제한입니다. |
| `health_probe_interval_secs` | `30` | 백그라운드에서 쓰기, 읽기, 삭제를 점검하는 간격입니다. 최솟값은 5입니다. |

S3와 Azure 클라이언트는 다음 순서로 확인하여 액세스 키와 시크릿 키를 모두 제공하는 첫 번째 소스에서 자격 증명을 가져옵니다.

1. `MS_OBJECT_STORE_ACCESS_KEY` 및 `MS_OBJECT_STORE_SECRET_KEY` 환경 변수.
2. `credentials_file`이 가리키는 파일.
3. `access_key` 및 `secret_key` 설정 키.

시작 로그의 `object_store_credentials_source` 필드에 선택한 소스를 `env`, `file`, `inline`, `none` 중 하나로 표시합니다. 시크릿 키는 `config.toml`보다 환경 변수나 자격 증명 파일에 저장하는 것을 권장합니다.

멀티파트 업로드의 각 파트와 범위 읽기의 각 청크는 동시 실행 슬롯 하나를 사용하는 개별 오브젝트 스토리지 작업입니다. 각 작업을 독립적으로 재시도하며 `object_store_*` 메트릭에 표시합니다. 전송 한 건이 전체 슬롯의 절반까지만 사용하므로 대용량 오브젝트를 전송해도 다른 작업을 계속 처리할 수 있습니다.

클라우드 백엔드에서 일시적 오류가 발생하면 지수 백오프를 적용해 재시도합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `[object_store.retry].max_attempts` | `4` | 작업당 총 시도 횟수입니다. |
| `[object_store.retry].base_backoff_ms` | `100` | 최초 대기 시간입니다. |
| `[object_store.retry].max_backoff_ms` | `5000` | 최대 대기 시간입니다. |
| `[object_store.retry].jitter_ratio` | `0.2` | 각 대기 시간에 적용하는 무작위 지터 비율입니다. 범위는 `0`~`1`입니다. |

### 선행 기록 로그

`[wal]`은 각 노드가 오브젝트 스토리지에 저장하는 선행 기록 로그(WAL)를 구성합니다. 노드는 WAL 오브젝트를 저장한 후에만 쓰기 성공을 응답하므로 영구 볼륨이 필요하지 않습니다. [아키텍처](/ko/architecture#내구성-및-인계)를 참조합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `lease_secs` | `15` | 쓰기 노드의 임대 기간(초)입니다. 최솟값은 `3`입니다. 노드가 임대 갱신을 중단하면 마지막 갱신 이후 이 기간이 지나고 최대 `takeover_interval_secs`만큼 더 지난 시점에 다른 수집 노드가 작업을 인계받습니다. 시작할 때만 이 값을 읽습니다. |
| `max_group_size` | `8` | WAL 오브젝트의 최대 크기(MiB)입니다. 같은 데이터 세트의 이전 오브젝트를 쓰는 중에 도착한 쓰기 요청을 이 크기까지 다음 오브젝트에 묶습니다. |
| `put_timeout_secs` | `10` | 오브젝트 쓰기 한 건에 허용하는 최대 시간입니다. |
| `put_attempts` | `3` | 오브젝트 쓰기 한 건의 시도 횟수입니다. 모든 시도가 실패하면 오브젝트에 포함된 쓰기 요청을 `503`으로 거부합니다. 거부된 요청은 재시도할 수 있습니다. |
| `takeover_interval_secs` | `5` | 수집 노드가 임대가 만료되어 작업을 인계받을 쓰기 노드를 확인하는 간격입니다. |
| `encrypt` | `false` | 루트 키(`MS_CIPHER_KEY`)로 각 WAL 오브젝트를 암호화합니다. |
| `max_takeover_size` | `512` | 작업 인계 과정에서 세그먼트를 게시하기 전까지 메모리에 유지하는 데이터의 최대 크기(MiB)입니다. `0`은 `1`로 처리합니다. |

### 데이터 수집

`[intake]`는 수집 노드의 인메모리 버퍼를 제어합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `buffer_max_size` | `256` | 스트림 하나의 원시 데이터 버퍼 크기 상한(MiB)입니다. 적응형 임계값은 이 값을 초과하지 않습니다. |
| `max_buffer_memory_size` | `1024` | 프로세스의 활성 버퍼와 분리된 버퍼가 예약하는 총 메모리(MiB)입니다. |
| `flush_interval_secs` | `30` | 플러시 사이의 최대 간격입니다. |
| `flush_parallelism` | `4` | 동시에 실행할 수 있는 플러시 수입니다. |

`[intake.rotation]`은 Parquet 파일 크기를 동적으로 조정합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `adaptive_enabled` | `true` | 생성이 완료된 파일의 원시 데이터 크기 대비 인코딩된 크기 비율을 바탕으로 각 스트림에 다음번에 적용할 원시 데이터 크기 임계값을 조정합니다. |
| `target_file_size` | `128` | 인코딩된 Parquet 파일의 목표 크기(MiB)입니다. |
| `min_buffer_size` | `16` | 적응형 임계값의 하한(MiB)입니다. |
| `ewma_alpha` | `0.2` | 비율에 적용하는 평활화 계수입니다. 0보다 크고 1 이하여야 합니다. |

`[intake.prometheus]`는 Prometheus `remote_write` 입력을 제한합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `max_labels_per_series` | `64` | 시계열당 최대 레이블 수입니다. `__name__`은 제외합니다. |

| `max_label_value_length` | `2048` | 레이블 값의 최대 길이(UTF-8 바이트)입니다. |
| `max_samples_per_batch` | `16384` | 내부 배치 하나에 포함할 수 있는 최대 샘플 수입니다. |

`[intake.prometheus.cardinality]`는 `remote_write` 요청을 받은 프로세스에서 배치를 수집 노드로 전달하기 전에 시계열을 허용할지 결정합니다. 각 프로세스는 자신이 받은 시계열 수를 집계하므로 라우터가 여러 대인 경우 각 라우터가 한도를 독립적으로 적용합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `true` | 한도를 적용합니다. |
| `max_active_series_per_process` | `1000000` | 프로세스당 최대 활성 시계열 수입니다. |
| `max_new_series_per_minute` | `20000` | 프로세스가 분당 허용하는 최대 신규 시계열 수입니다. |
| `idle_ttl_secs` | `900` | 시계열이 이 시간 동안 유휴 상태이면 한도 집계에서 제외합니다. |

조직별 한도와 메트릭별 한도는 `_sys` 조직의 **설정 → 메트릭 카디널리티**에서 구성하는 플랫폼 설정입니다. 각 노드는 30초마다 이 설정을 다시 읽고 집계하는 시계열에 적용합니다.

### 컴팩션 및 리텐션

`[compactor]`는 파일을 병합하고 리텐션을 적용합니다. `standalone` 및 `compactor` 노드에서 실행됩니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `interval_secs` | `300` | 컴팩션 실행 간격입니다. |
| `target_size` | `512` | 한 번에 병합하는 파일의 최대 합계 크기(MiB)입니다. 범위는 `1`~`65536`입니다. 병합된 파일의 크기는 이 값과 비슷하거나 더 작습니다. 병합 작업은 입력을 파트 단위로 읽고 결과도 파트 단위로 업로드하므로 이 값이 커져도 메모리 사용량이 늘어나지 않습니다. 한 번의 병합에서 파일을 최대 128개까지 읽습니다. 나머지 파일은 이후 실행에서 병합 결과와 함께 병합합니다. 한 파일이 같은 병합 대상의 나머지 파일을 모두 합친 것보다 크면 해당 파일을 제외합니다. 새 파일의 합계 크기가 해당 파일의 크기에 도달한 뒤 병합하므로 소량의 새 데이터 때문에 대용량 파일을 다시 쓰지 않습니다. |
| `max_concurrent_groups` | `4` | 한 노드가 한 라운드에서 동시에 처리하는 최대 스트림 수입니다. |

개별 리텐션을 설정하지 않은 스트림의 보존 기간은 `_sys` 조직의 **설정 → 데이터 보존**에서 구성하는 플랫폼 설정입니다. 기본값은 30일입니다. 다운샘플링은 각 메트릭 스트림의 **리텐션** 탭에서 설정합니다. [스트림](/ko/streams)을 참조합니다.

### 카탈로그 유지 관리

`[storage.*]` 섹션은 파일 카탈로그와 오브젝트 스토리지의 백그라운드 유지 관리를 제어합니다.

| `[storage.catalog].seal_after_hours` | `48` | 파티션이 종료된 후 이 시간(시간 단위)이 지나면 파티션을 봉인합니다. 변경할 수 없는 매니페스트와 정확히 일치하는 값을 검색하는 필드의 블룸 필터를 작성합니다. 이 필터를 사용하면 정확한 값을 조회할 때 해당 파티션의 파일을 건너뛸 수 있습니다. 봉인된 파티션에는 더 이상 컴팩션을 적용하지 않으므로 봉인을 늦춰 하루치 시간별 데이터를 병합할 시간을 확보합니다. `0`으로 설정하면 봉인을 비활성화합니다. |
| `[storage.catalog].manifest_cache_size` | `256` | 매니페스트 캐시에 할당하는 메모리(MiB)입니다. |
| `[storage.catalog].interval_secs` | `300` | 봉인 작업의 실행 간격입니다. |
| `[storage.catalog].batch_size` | `64` | 라운드당 처리하는 파티션 수입니다. |
| `[storage.index].enabled` | `true` | 라운드마다 일부 파일의 누락된 검색 인덱스를 생성하고 이전 형식으로 작성한 검색 인덱스를 다시 생성합니다. 카탈로그 유지 관리 작업은 봉인된 파티션의 인덱스를 다시 생성하고 해당 매니페스트의 다음 세대와 함께 게시합니다. |
| `[storage.index].interval_secs` | `30` | 실행 간격입니다. |
| `[storage.index].batch_size` | `64` | 라운드당 처리하는 파일 수입니다. |
| `[storage.index].max_concurrency` | `2` | 동시에 실행할 수 있는 인덱스 생성 작업 수입니다. |
| `[storage.index].retry_after_secs` | `300` | 인덱스 생성에 실패한 후 재시도하기까지의 대기 시간입니다. |
| `[storage.gc].enabled` | `true` | 카탈로그에서 더 이상 참조하지 않는 오브젝트를 삭제합니다. |
| `[storage.gc].interval_secs` | `30` | 실행 간격입니다. |
| `[storage.gc].grace_period_secs` | `3600` | 각 오브젝트가 삭제 대기열에서 대기하는 시간입니다. 최종 삭제 전에 카탈로그 참조와 체크섬을 다시 확인합니다. |
| `[storage.gc].lease_secs` | `900` | 처리 대상으로 확보한 삭제 배치의 임대 기간입니다. |
| `[storage.gc].batch_size` | `128` | 라운드당 처리하는 오브젝트 수입니다. |

| `[querier].auto_async_threshold_rows` | `50000000` | 예상 행 수가 이 값을 초과하는 쿼리를 비동기 검색 작업으로 전환합니다. `0`이면 전환하지 않습니다. |
| `[querier].estimate_throughput_per_sec` | `1000` | 크기를 추정할 때 사용하는 보수적인 초당 행 수입니다. |
| `[search].max_result_rows` | `0` | `LIMIT`이 없고 집계를 수행하지 않는 쿼리의 최대 결과 행 수입니다. `0`이면 제한을 해제합니다. 샘플 파일에는 이 키가 없습니다. |
| `[search_jobs].workers` | `2` | 노드 하나에서 동시에 실행하는 검색 작업 수입니다. |
| `[search_jobs].idle_poll_secs` | `2` | 폴백 폴링의 초기 대기 시간입니다. 유휴 상태에서는 대기 시간을 점차 늘립니다. |
| `[search_jobs].cleanup_interval_secs` | `3600` | 만료된 작업을 삭제하는 간격입니다. |

### 쿼리 승인 제어

`[search.admission]`은 각 작업 그룹이 노드 하나에서 동시에 실행할 수 있는 쿼리 수를 제한합니다. 작업 그룹이 한도에 도달하면 쿼리를 대기열에 넣고, 도착한 순서대로 실행합니다. 쿼리가 `max_wait_secs`보다 오래 대기하면 `429`를 반환합니다. 결과 캐시에서 응답하는 쿼리는 대기하지 않습니다. 이 제한은 쿼리 API 및 Flight SQL을 통해 전송한 쿼리, 탐색기의 차트 및 필드 통계, 공개 공유, 검색 작업에 적용합니다. 알림 평가와 기타 백그라운드 작업은 대기열을 거치지 않습니다. 샘플 파일에는 이 섹션이 없습니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `default_max_concurrent` | CPU 수의 2배 | `groups`에 항목이 없는 작업 그룹의 노드별 동시 실행 한도입니다. `0`이면 제한하지 않습니다. |
| `groups` | 비어 있음 | 작업 그룹 이름을 노드별 한도에 매핑하는 테이블입니다. |
| `role_map` | 비어 있음 | 역할(`owner`, `admin`, `editor`, `viewer`)을 작업 그룹에 매핑하는 테이블입니다. 매핑되지 않은 역할에는 `default`를 사용합니다. |
| `max_wait_secs` | `60` | `429`를 반환하기 전에 쿼리가 빈 슬롯을 기다리는 시간입니다. `0`이면 작업 그룹이 한도에 도달했을 때 즉시 `429`를 반환합니다. |
| `cluster_default_max_concurrent` | `0` | `cluster_groups`에 항목이 없는 작업 그룹에 적용하는 클러스터 전체의 소프트 한도입니다. 한도에 도달한 상태에서 쿼리가 들어오면 즉시 `429`를 반환합니다. `0`이면 제한하지 않습니다. |
| `cluster_groups` | 비어 있음 | 작업 그룹 이름을 클러스터 전체의 소프트 한도에 매핑하는 테이블입니다. |
| `cluster_sync_interval_secs` | `0` | 노드 부하를 게시하는 간격입니다. `0`이면 5를 사용합니다. |
| `cluster_stale_secs` | `0` | 이 시간보다 오래 응답하지 않는 노드는 클러스터 목록에서 제외합니다. `0`이면 30을 사용합니다. |

`/metrics`는 각 작업 그룹의 대기열 상태를 `query_admission_running`, `query_admission_waiting`, `query_admission_wait_seconds`, `query_admission_refusals_total` 메트릭으로 표시합니다.

### 캐시

각 계층은 만료 시간(TTL)이 있는 LRU 캐시입니다. 용량을 `0`으로 설정하면 해당 계층을 비활성화합니다. `/metrics`에서 `cache_<layer>_hit_ratio`로 적중률을 확인할 수 있습니다.

| 섹션 | 기본 용량 | 기본 TTL | 저장 항목 |
|---|---|---|---|
| `[cache.index_handle]` | `10000` | `600` s | 열려 있는 검색 인덱스 핸들입니다. |
| `[cache.query_result]` | `1000` | `60` s | 종료된 시간 구간에 대한 SQL 쿼리 결과입니다. |
| `[cache.tantivy_result]` | `1000000` | `600` s | 읽을 필요가 없는 파일을 걸러내는 데 사용하는 검색어 개수입니다. |
| `[cache.tantivy_footer]` | `100000` | `3600` s | 범위 읽기 횟수를 줄이는 데 사용하는 인덱스 푸터입니다. |

각 섹션에서 `capacity`와 `ttl_secs`를 설정합니다.

`[cache.parquet_metadata]`는 페이지 인덱스를 포함한 Parquet 푸터를 파싱해 메모리에 보관합니다. 쿼리가 캐시된 파일을 열면 푸터를 다시 읽지 않습니다. 유일한 키인 `max_size`의 단위는 MiB이며 기본값은 `256`입니다. `0`이면 캐시를 비활성화합니다.

`[cache.object]`는 원격 객체의 바이트 범위를 로컬 디스크에 캐시합니다. `local` 객체 백엔드는 이 캐시를 사용하지 않습니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `true` | 캐시를 활성화합니다. `max_size`가 `0`이면 이 설정과 관계없이 캐시를 비활성화합니다. |
| `root` | `./data/cache/objects` | 캐시 디렉터리입니다. |
| `max_size` | `10240` | 최대 캐시 크기입니다. 단위는 MiB이며 기본값은 10 GiB입니다. |
| `block_size` | `4` | 블록 크기입니다. 단위는 MiB이며 범위는 1~16입니다. |
| `memory_size` | `256` | 검증한 블록을 메모리에 보관하는 용량입니다. 단위는 MiB입니다. 메모리에 보관한 블록을 다시 읽을 때는 디스크에 접근하지 않습니다. `0`이면 블록을 디스크에만 보관합니다. |
| `min_free_size` | `1024` | 확보할 디스크 여유 공간입니다. 단위는 MiB이며 기본값은 1 GiB입니다. |
| `max_concurrent_fetches` | `16` | 동시에 가져올 수 있는 블록 수입니다. 0보다 큰 값을 지정합니다. |
| `max_concurrent_fetches_per_object` | `4` | 객체 하나에서 동시에 가져올 수 있는 블록 수입니다. 0보다 큰 값을 지정합니다. |

캐시 크기가 `max_size`를 초과하거나 디스크 여유 공간이 `min_free_size` 미만으로 줄어들면 가장 오래 사용하지 않은 블록부터 제거합니다. 가비지 컬렉터가 객체를 삭제할 때, 삭제를 수행하는 노드가 시작된 이후 해당 객체를 읽은 적이 있으면 해당 객체의 블록도 캐시에서 제거합니다. 다른 노드는 일반 블록과 같은 기준으로 해당 블록을 제거합니다.

### 증분 범위 캐시

`[search.stream_agg_cache]`는 `rate(metric[5m])`과 같은 PromQL 범위 쿼리에서 종료된 시간 구간을 캐시합니다. 대시보드를 새로 고칠 때는 가장 최근 구간만 다시 계산합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `max_size` | `256` | 캐시에 할당할 메모리 용량입니다. 단위는 MiB입니다. 각 쿼리가 보관하는 시계열과 시간 구간을 기준으로 사용량을 추정합니다. `0`이면 캐시를 비활성화합니다. |
| `ttl_secs` | `300` | 항목의 보존 시간입니다. `safe_lookback_secs`를 넘겨 도착하는 지연 데이터까지 고려합니다. |
| `safe_lookback_secs` | `300` | 현재 시각에서 이 값을 뺀 시점보다 먼저 종료된 구간만 캐시합니다. |
| `max_series_per_query` | `10000` | 지문당 캐시하는 최대 시계열 수입니다. `0`이면 제한을 해제합니다. |

## 인증

| 키 | 기본값 | 설명 |
|---|---|---|
| `session_ttl_secs` | `86400` | 로그인 유지 시간이며, 리프레시 토큰의 유효 기간인 24시간에 해당합니다. 이 기간에는 15분마다 액세스 토큰을 갱신합니다. `_sys` 조직의 세션은 1시간 이내에 종료됩니다. |
| `root_email` | `admin@example.com` | 루트 계정의 이메일 주소입니다. 내장 값은 비어 있습니다. |
| `root_password` | `admin` | 루트 계정의 비밀번호입니다. 내장 값은 비어 있습니다. 예시 값은 다른 값으로 바꿉니다. |

MoleSignal은 처음 시작할 때 데이터베이스에 사용자가 없고 두 값이 모두 설정되어 있으면 루트 계정을 생성합니다. 나중에 `root_password`를 변경해도 기존 계정의 비밀번호는 바뀌지 않습니다. 기존 계정의 비밀번호는 웹 UI에서 변경합니다. 시작할 때마다 MoleSignal은 `root_email`에 해당하는 계정을 플랫폼 관리자로 지정하므로, `root_email`에는 기존 사용자의 이메일 주소를 지정해야 합니다.

MoleSignal은 처음 시작할 때 JWT 서명 시크릿을 생성하고 PostgreSQL에 저장합니다. 시크릿을 특정 값으로 고정하려면 `MS_AUTH_JWT_SECRET_OVERRIDE`를 사용하고, 시크릿을 교체하려면 `POST /api/v1/auth/jwt/rotate`를 사용합니다.

| `[telemetry].log_format` | `text` | `text` 또는 `json`입니다. |

샘플 파일에서는 마지막 세 키를 주석 처리합니다. 표에 표시된 값은 `log_output`이 `file`일 때 적용합니다.

### 자체 수집 텔레메트리

`[telemetry.self_collect]`는 프로세스의 메트릭, 트레이스, 프로파일을 예약된 `_molesignal` 스트림 그룹에 기록합니다. 프로세스 자체의 시그널만 수집합니다. 테넌트가 전송하는 트레이스는 이 설정의 활성화 여부와 관계없이 저장합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `true` | 전체 수집을 켜거나 끕니다. 내장 기본값은 `false`입니다. 트레이스를 수집하려면 `[telemetry.trace].enabled`도 활성화해야 합니다. |
| `metrics_enabled` | `true` | 프로세스 메트릭을 수집합니다. |
| `metrics_interval_secs` | `15` | 메트릭 수집 간격입니다. |
| `queue_capacity` | `8192` | 시그널별 인메모리 큐의 최대 용량입니다. |
| `batch_max_events` | `256` | 배치당 최대 이벤트 수입니다. |
| `batch_max_delay_ms` | `1000` | 배치를 채울 때까지 기다리는 최대 시간입니다. |
| `flush_timeout_secs` | `5` | 종료 시 큐를 플러시할 수 있는 시간입니다. |
| `profiles_enabled` | `false` | 프로세스 프로파일을 수집합니다. |

| `profile_interval_secs` | `600` | 프로파일 수집 간격입니다. |
| `profile_duration_secs` | `10` | CPU 프로파일 1회 수집 시간입니다. 범위는 1~120입니다. |

`_molesignal` 스트림을 생성할 때 리텐션을 7일로 설정합니다. 값을 변경하려면 `_sys` 조직에서 해당 스트림의 **리텐션** 탭을 사용합니다. 재시작해도 변경한 값을 유지합니다.

### 트레이스 캡처 및 테일 샘플링

`[telemetry.trace]`는 서비스가 자체적으로 기록하는 스팬과 보관할 트레이스를 결정하는 테일 샘플러를 제어합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `true` | 캡처 및 테일 샘플링의 기본 활성화 여부를 설정합니다. `force_disabled`가 `false`이면 런타임 정책을 변경할 수 있습니다. |
| `force_disabled` | `false` | 우선순위가 가장 높은 배포 설정입니다. `/api/v1/system/telemetry`의 런타임 정책으로 이 값을 재정의할 수 없습니다. |
| `filter` | `info` | 스팬 캡처 및 내보내기에 사용하는 `EnvFilter`입니다. `RUST_LOG` 및 `log_level`과 별도로 적용합니다. |
| `deployment_environment` | `production` | 환경 레이블입니다. `development`, `dev`, `test`는 `development_sample_ratio`를 사용합니다. 다른 값은 `normal_sample_ratio`를 사용합니다. |
| `normal_sample_ratio` | `0.10` | 개발 환경 외에서 일반 트레이스에 적용하는 기본 샘플링 비율입니다. 범위는 0.0~1.0입니다. |
| `development_sample_ratio` | `1.0` | 개발 환경의 기본 샘플링 비율입니다. 범위는 0.0~1.0입니다. |
| `decision_window_secs` | `30` | 샘플러가 샘플링 여부를 결정하기 전에 트레이스의 스팬을 모으는 시간입니다. 범위는 5~120입니다. |
| `root_grace_millis` | `1000` | 루트 스팬이 끝난 뒤 늦게 도착하는 하위 스팬을 기다리는 시간입니다. |
| `decision_cache_secs` | `300` | 샘플링 결정의 유효 기간입니다. `decision_window_secs` 이상으로 설정합니다. |
| `tail_max_traces` | `10000` | 샘플러가 샘플링 여부를 결정하기 전까지 보관할 수 있는 최대 트레이스 수입니다. |
| `tail_memory_size` | `256` | 샘플링 여부가 결정되지 않은 트레이스의 메모리 한도입니다. 단위는 MiB입니다. |
| `max_spans_per_trace` | `1000` | 트레이스당 최대 보관 스팬 수입니다. |
| `max_attributes_per_span` | `128` | 스팬당 최대 보관 속성 수입니다. |
| `max_events_per_span` | `128` | 스팬당 최대 보관 이벤트 수입니다. |
| `max_links_per_span` | `128` | 스팬당 최대 보관 링크 수입니다. |
| `max_string_length` | `4096` | 속성, 이벤트 또는 링크 문자열의 최대 길이입니다. 단위는 UTF-8 바이트입니다. |
| `shutdown_timeout_secs` | `10` | 종료 시 파이프라인을 중지할 수 있는 시간입니다. |

`[telemetry.trace.slow_thresholds]`는 다음 밀리초 단위 임계값을 기준으로 스팬을 느린 스팬으로 표시합니다: `http_ms = 1000`, `query_ms = 5000`, `batch_intake_ms = 2000`, `database_ms = 200`, `object_store_ms = 500`, `external_ms = 1000`, `background_ms = 30000`.

`[telemetry.trace.external]`은 외부 OTLP 수신기로 트레이스를 내보냅니다. `endpoint`가 비어 있으면 내보내지 않습니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `endpoint` | 비어 있음 | OTLP 수신기 주소입니다. |
| `protocol` | `grpc` | `grpc` 또는 `http/protobuf`입니다. URL에서 값을 유추하지 않습니다. |
| `timeout_ms` | `5000` | 연결 및 내보내기 제한 시간입니다. |
| `queue_capacity` | `8192` | 내보내기 큐의 용량입니다. |
| `batch_size` | `256` | 배치당 트레이스 수입니다. |
| `gzip` | `false` | 페이로드를 압축합니다. |
| `allow_self_export` | `false` | 이 MoleSignal 클러스터로 내보내기를 허용합니다. 반복 전송을 방지하기 위해 기본적으로 비활성화합니다. |
| `headers` | 없음 | OTLP 헤더입니다. 비밀 값은 직접 적지 말고 `env:NAME` 또는 `secret:NAME`으로 참조합니다. |
| `custom_ca_file` | 없음 | HTTPS 서버 인증서 검증용 CA 파일입니다. |
| `client_certificate_file` | 없음 | mTLS 클라이언트 인증서입니다. `client_key_file`과 함께 설정합니다. |
| `client_key_file` | 없음 | mTLS 클라이언트 키입니다. `client_certificate_file`과 함께 설정합니다. |

### APM

`[apm]`은 애플리케이션 성능 모니터링용 데이터 뷰의 생성을 제어합니다. 트레이스 후보를 담당하거나 `alert` 역할의 롤업을 실행하는 노드에서 시작합니다. [APM](/ko/apm)을 참고합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `queue_capacity` | `65536` | 입력 큐의 용량입니다. 범위는 1024~1048576입니다. |
| `flush_interval_ms` | `5000` | 집계 데이터의 플러시 간격입니다. 범위는 100~60000입니다. |
| `flush_max_snapshots` | `10000` | 플러시당 최대 스냅샷 수입니다. 범위는 1~100000입니다. |
| `shutdown_drain_secs` | `10` | 종료 시 큐를 비울 수 있는 시간입니다. 범위는 1~300입니다. |
| `late_grace_secs` | `300` | 늦게 도착한 트레이스 데이터를 수락하는 유예 시간입니다. 0보다 크고 핫 데이터 리텐션보다 짧아야 합니다. |
| `hot_retention_hours` | `24` | 고해상도 데이터의 리텐션입니다. 범위는 1~168입니다. |
| `rollup_retention_days` | `30` | 롤업의 리텐션입니다. 범위는 1~3650입니다. |
| `max_query_range_days` | `30` | 단일 APM 쿼리의 최대 조회 기간입니다. `rollup_retention_days` 이하여야 합니다. |
| `max_exemplars_per_bucket` | `3` | 집계 버킷당 최대 예시 데이터 포인트 수입니다. 범위는 1~16입니다. |
| `max_error_samples_per_group` | `8` | 그룹당 최대 오류 샘플 수입니다. 범위는 1~64입니다. |
| `[apm.histogram].schema_version` | `2` | 지연 시간 버킷 구조의 버전입니다. `buckets_per_octave`를 변경할 때마다 버전을 높입니다. `2` 이상으로 설정합니다. 이전 집계에 사용한 버전 `1`의 고정 버킷도 계속 읽을 수 있습니다. |
| `[apm.histogram].buckets_per_octave` | `8` | 지연 시간이 두 배가 되는 구간당 버킷 수입니다. 값의 범위는 1~16이며, 버킷은 125 µs부터 약 131 s까지 포괄합니다. `+Inf` 버킷은 자동으로 추가합니다. `8`로 설정하면 인접한 경계값의 차이는 약 9%이고 백분위수 오차는 약 4% 이내입니다. |
| `[apm.version_comparison].min_requests_per_version` | `1000` | 버전 비교에 포함하는 데 필요한 버전별 최소 요청 수입니다. |

APM이 시간당 개별적으로 구분하는 서비스, 엔드포인트, 종속성, 작업, 오류 그룹, 버전, 인스턴스의 수는 플랫폼 설정에서 제한합니다. `sys.settings.limits.manage` 권한이 있으면 **APM → 설정 → 카디널리티 한도**에서 변경할 수 있습니다. 모든 노드는 30초마다 이 설정을 다시 읽습니다. [APM 설정](/ko/apm/settings#카디널리티-한도)을 참고합니다. 구성 파일에 `[apm.cardinality]` 섹션이 남아 있으면 파일을 로드할 수 없습니다.

## 기능 및 통합

| 키 | 기본값 | 설명 |
|---|---|---|
| `[functions].llm_eval_enabled` | `false` | `POST /api/v1/functions/run`에서 LLM 함수를 실행할 수 있게 합니다. 실행당 모델을 한 번 호출합니다. [함수](/ko/functions#언어)를 참조합니다. [알림 파이프라인](/ko/pipelines/alert-events#ai-요약)의 **AI 요약** 단계는 이 설정에 의존하지 않습니다. |
| `[mmdb].db_path` | `/usr/share/molesignal/mmdb/dbip-city-lite.mmdb` | DB-IP City Lite 데이터베이스입니다. 컨테이너 이미지와 릴리스 아카이브는 빌드 당시 최신 월간 버전을 포함합니다. 릴리스 아카이브에서는 `mmdb/`에 있습니다([MoleSignal 배포](/ko/deployment) 참조). RUM은 이벤트를 수집할 때 클라이언트 IP를 기준으로 각 이벤트의 국가를 조회합니다. 파일이 없으면 클라이언트가 보낸 국가 값을 유지합니다. VRL 함수 [`geoip_lookup`](/ko/functions#테이블과-ip-주소-조회)는 같은 파일을 읽으며, 파일이 없으면 `null`을 반환합니다. |

[DB-IP](https://db-ip.com)에서 IP 지리 위치 데이터를 제공하며, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 라이선스를 적용합니다.

릴리스 바이너리에는 JavaScript 함수 런타임과 VRL이 포함되어 있습니다. 둘 다 별도로 설정할 필요가 없습니다. [함수](/ko/functions)를 참조합니다.

Mole Agent의 일일 토큰 예산은 조직별로 적용합니다. 조직 관리자는 **Mole Agent → 설정 → 사용량**에서 조직별 한도를 설정할 수 있습니다. [Mole Agent](/ko/agent#사용량-및-예산)를 참조합니다. 스킬 폴더는 모든 조직에서 사용합니다. [스킬](/ko/agent#스킬)을 참조합니다.

| `[agent].skill_paths` | `[]` | 모든 조직에 스킬을 제공하는 서버 폴더 목록입니다. 각 폴더에서 `SKILL.md`를 포함하는 하위 폴더를 스킬로 사용하며, 제품에서는 읽기 전용입니다. 각 노드는 시작할 때 이 폴더를 읽고 파일이 변경되면 다시 읽습니다. 환경 변수로 설정하는 예: `MS_AGENT_SKILL_PATHS='["/var/lib/molesignal/skills"]'`. |

## 데이터베이스에 저장하는 설정

다음 설정은 PostgreSQL에 저장하며 웹 UI 또는 API에서 변경합니다. 이 설정에 해당하는 TOML 키는 없습니다.

- SSO 공급자(OIDC, OAuth 2.0, SAML 및 LDAP).
- 페더레이션 쿼리용 원격 클러스터.
- 상태 페이지 도메인과 인증서, 그리고 방문자가 Slack에 페이지를 추가할 때 사용하는 Slack 앱.
- 알림 채널, 일정 및 에스컬레이션 정책.
- Mole Agent의 모델 공급자, 프롬프트, 도구 및 승인 정책.
- 조직의 암호화 키, 필드 마스킹 규칙 및 공유 정책.
