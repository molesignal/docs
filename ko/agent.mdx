**Mole Agent**는 제품에 내장된 운영 에이전트이자 해당 에이전트의 작업 공간입니다.

Mole Agent는 서버에 등록된 도구를 통해 로그, 메트릭, 트레이스, RUM, 프로파일, 알림, 온콜 데이터, 보고서를
조회할 수 있습니다. Mole Agent는 로그인한 사용자의 조직과 권한을 사용하며, 모델이 제공하는
조직 식별자는 무시합니다.

## 모델 공급자 설정

채팅에서 응답을 받으려면 먼저 모델 공급자를 설정해야 합니다. `agent.models.manage` 권한이 있는 관리자가 모델 공급자를 추가합니다.

1. **Mole Agent → 설정 → 모델 및 추론**을 열고 **모델 공급자 추가**를 선택합니다.
2. **제공업체 유형**으로 OpenAI, Anthropic 또는 OpenAI 호환 엔드포인트를 선택합니다.
3. **표시 이름**, **기본 모델**, **API 키**를 입력합니다. 키는 쓰기 전용이며 페이지와 API에서는 키를 반환하지 않습니다.
4. OpenAI 호환 엔드포인트의 **기본 URL**을 설정합니다. OpenAI 또는 Anthropic의 공식 엔드포인트를 사용하려면 비워 둡니다.
5. 공급자의 기본값이 적합하지 않으면 **무응답 제한 시간**과 **최대 출력 토큰 수**를 조정합니다. 사용량에서 비용을 확인하려면 **통화**를 선택하고 단가를 입력한 후 저장합니다.

**무응답 제한 시간**은 모델 공급자로부터 아무 데이터도 받지 못한 호출을 실패로 처리하기까지 기다리는 시간입니다. 기본값은 120000 ms이며, 1000~600000 ms 범위의 값을 설정할 수 있습니다. 스트리밍하지 않는 호출은 전체 응답을 기다리므로 가장 오래 걸리는 응답까지 고려해 설정합니다. 연결 실패, 요청 한도 초과(429), 일시적인 서비스 장애(5xx, 529)에는 두 번 재시도합니다. 공급자가 `Retry-After`를 보내면 지정된 시간만큼 기다리며, 응답이 도착하기 전에만 재시도합니다. Anthropic 공급자에서 **최대 출력 토큰 수**를 설정하지 않으면 4096을 사용합니다.

단가는 공급자의 **통화**로 토큰 백만 개당 책정하며, 해당 공급자의 모든 모델에 동일하게 적용합니다. **입력 단가(캐시 미적용)**, 공급자가 캐시에서 제공한 입력에 적용하는 **입력 단가(캐시 적용)**, **출력 단가**를 설정할 수 있습니다. 공급자가 캐시 적중을 별도로 청구하는 경우에만 캐시 적용 단가를 입력합니다. 그렇지 않으면 모든 입력에 캐시 미적용 단가를 적용합니다. 단가를 비워 두면 비용만 계산하지 않으며, 사용량과 예산은 동일하게 작동합니다.

선택할 수 있는 통화는 모델 공급자 목록 아래의 **통화**에서 관리합니다. `agent.usage.manage` 권한이 있는 관리자는 ISO 4217 코드로 통화를 추가합니다. 표준 이름이나 기호가 적합하지 않으면 이름과 기호를 지정합니다. 모델 공급자가 사용하는 통화는 삭제할 수 없습니다. 삭제된 통화로 기록한 비용은 계속 해당 통화로 표시합니다. `agent.usage.read` 권한이 없으면 이 섹션이 표시되지 않으며 **통화**를 변경할 수 없습니다. 새 공급자는 USD를 사용하고, 기존 공급자는 현재 통화를 유지합니다.

모델 호출은 Model Gateway를 거칩니다. 저장된 키를 유지하려면 편집할 때 키 필드를 비워 둡니다. 키를 교체하려면 새 값을 입력합니다. 키를 교체하려면 `agent.models.rotate` 권한이 필요합니다. 이 권한은 있지만 `agent.models.manage` 권한이 없으면 키 필드만 변경할 수 있습니다. 환경 변수 `MS_AGENT_OPENAI_API_KEY`, `MS_AGENT_ANTHROPIC_API_KEY`, `MS_AGENT_COMPATIBLE_API_KEY`는 개발 환경에서 대체 수단으로 사용합니다. [구성](/ko/configuration#환경-변수)을 참조합니다.

## 채팅

**Mole Agent → 채팅**을 열고 사용 가능한 모델을 선택한 다음, 시간 범위를 설정하고
증상을 설명합니다. 서비스, 알림, 환경 또는 스트림을 고정해 조사 컨텍스트로 사용합니다.

활성화된 AI 모델이 없으면 채팅이 메시지 입력란 위에 안내를 표시합니다.
`agent.models.manage` 권한이 있는 관리자는 안내의 링크를 통해 **모델 및 추론**으로 이동합니다.

답변에는 다음 내용이 포함될 수 있습니다.

- 이해하기 쉬운 말로 설명한 결론
- 도구 호출 및 근거 요약
- 원본 로그, 메트릭, 트레이스 또는 인시던트 링크
- 토큰 및 모델 비용 메타데이터(모델 제공업체가 가격을 책정한 경우 비용 표시)
- 재현에 필요한 프롬프트 템플릿 버전과 콘텐츠 해시

답변 하단 왼쪽에는 **복사**, **분기**, **고정** 및 답변 시간이 표시됩니다. 오른쪽 게이지는 답변의 확신도를 표시합니다. 확신도가 높을수록 게이지가 길어지고 끝부분이 더 초록색을 띱니다. 게이지에 마우스를 올리면 확신도 수준이 표시됩니다. 그 뒤에는 **도움이 됨**과 **도움이 되지 않음**이 있습니다. **분기**를 선택하면 해당 답변까지의 메시지를 담은 새 채팅을 만들고 원본 채팅 아래에 표시합니다. **고정**을 선택하면 해당 답변이 선택한 사람의 채팅 상단에 유지됩니다.

답변 아래에서 **도움이 됨**이나 **도움이 되지 않음**을 선택합니다. **도움이 되지 않음**을 선택하면 이유(잘못된 결론 또는 원인, 문제를 찾지 못함, 조언을 적용할 수 없음, 주제에서 벗어남, 기타)를 묻고 선택적으로 의견을 받습니다. 질문을 보낸 사람만 답변을 평가할 수 있습니다. 평가를 취소하려면 선택한 항목을 다시 선택합니다. 평가에는 답변에 사용한 모델과 프롬프트 버전을 기록합니다.

조직의 오늘 토큰 사용량이 예산 경고 임계값에 도달하면 채팅이 메시지 입력란 위에 안내를 표시합니다. 예산을 모두 소진한 경우의 동작은 [사용량 및 예산](#사용량-및-예산)을 참조합니다.

크기가 큰 원본 도구 결과는 객체 스토리지에 저장합니다. 채팅을 삭제하기 전에
가능한 범위에서 대화 기록을 보관합니다.

### 메시지 작성

메시지 입력란에는 전송할 때와 같은 서식이 표시됩니다. `- `는 목록, `1. `는 번호 매기기 목록, `# `는 제목, `> `는 인용문, `[ ] `는 작업 항목, ```` ``` ````는 코드 블록을 시작합니다. `**bold**`와 `` `code` ``에는 입력하면서 서식이 적용됩니다. **Enter**를 누르면 메시지를 전송합니다. 목록이나 코드 블록에서 **Enter**를 누르면 해당 형식으로 계속 입력하고, 빈 목록 항목에서 **Enter**를 누르면 목록을 끝냅니다. **⌘ Enter** 또는 **Ctrl Enter**를 누르면 입력 위치와 관계없이 전송합니다. **Shift Enter**를 누르면 새 줄을 시작합니다. 붙여넣은 Markdown은 서식을 유지합니다. 텍스트를 그대로 유지하려면 일반 텍스트로 붙여넣습니다(**⌘ Shift V** 또는 **Ctrl Shift V**). 메시지는 Markdown으로 전송합니다.

### 실행 모드

메시지 입력란 아래의 모드는 Mole Agent가 채팅에서 실행할 수 있는 작업을 정합니다. 모드 메뉴가 열려 있을 때 숫자 키 1~5로 모드를 선택합니다.

| 모드 | 실행하는 작업 |
|---|---|
| **제안 모드**(권장) | 데이터를 쿼리하고 변경 사항을 제안하지만 적용하지 않습니다. |
| **조사 모드** | 필요에 따라 읽기 전용 쿼리를 실행하며 아무것도 변경하지 않습니다. |
| **승인 후 실행** | 쿼리를 실행합니다. 변경 작업은 도구의 실행 모드에 따라 먼저 확인을 요청하거나 승인을 위해 전달합니다. |
| **자동 모드** | 쿼리를 실행합니다. 메시지를 보낸 사람의 확인만 필요한 변경을 되돌릴 수 있으면 확인 없이 적용합니다. 삭제나 그 밖의 파괴적 변경은 여전히 확인을 요청합니다. |
| **권한 확인 건너뛰기** | 메시지를 보낸 사람의 확인만 필요한 변경을 확인 없이 적용합니다. 파괴적 변경도 포함합니다. |

모든 모드에서 조직의 도구 정책에 따라 승인이 필요한 변경은 지정된 승인자에게 전달하며, 비활성화된 도구는 계속 비활성 상태로 유지합니다. **권한 확인 건너뛰기**는 채팅의 에이전트 프로필에서 **승인 정책** 아래의 **권한 우회 허용**을 설정한 경우에만 표시하며, 활성화하기 전에 확인을 요청합니다. 질문이 대기하는 동안 프로필에서 이 모드를 더 이상 허용하지 않으면, 해당 답변은 변경할 때마다 먼저 확인을 요청하고 그 사실을 안내합니다.

### 채팅 이름

새 채팅의 첫 질문에 답변하는 동안 이름을 정합니다. ChatGPT와 Claude에서 대화 이름을 정하는 것처럼, 질문에 사용한 언어로 채팅 주제를 몇 단어로 요약합니다. 첫 메시지가 인사말이면 주제가 있는 질문을 할 때까지 첫 메시지의 앞부분을 이름으로 유지합니다. 이름은 한 번만 자동으로 정합니다. 이름을 바꾸려면 목록에서 채팅 옆의 연필 아이콘을 선택합니다. **Enter**를 누르면 이름을 저장하고 **Esc**를 누르면 변경을 취소합니다. 이후 Mole Agent는 해당 채팅의 이름을 자동으로 정하지 않습니다. 메모리에는 출처 채팅의 현재 이름을 표시합니다. 이름을 정하는 작업도 다른 호출과 마찬가지로 모델 사용량에 포함합니다.

### 개인 및 팀 채팅

첫 메시지를 보내기 전에 팀을 선택하지 않으면 개인 채팅으로 시작합니다. 메시지 입력란 아래의 **팀**에서 팀을 선택하거나 `/team <team>`을 입력합니다. 목록에는 소속 팀이 표시되며, `agent.manage` 권한이 있으면 모든 팀이 표시됩니다. 첫 메시지를 보내면 채팅의 팀을 변경할 수 없습니다.

| | 개인 채팅 | 팀 채팅 |
|---|---|---|
| 읽고 이어갈 수 있는 대상 | 채팅 소유자 | 팀 구성원과 `agent.manage` 권한이 있는 사람 |
| 사용하는 스킬 및 MCP 서버 | 조직, 채팅 소유자, 채팅에 추가한 팀의 스킬과 MCP 서버 | 조직과 팀의 스킬 및 MCP 서버만 사용하며, 개인 스킬이나 서버는 사용하지 않습니다. |

도구는 항상 메시지를 보낸 사람의 권한과 자격 증명으로 실행합니다. 팀 채팅에서는 다른 사람이 질문하면 질문을 보낸 사람의 이름을 표시합니다. 개인 채팅에서 소속 팀의 스킬이나 MCP 프롬프트를 호출하면 해당 채팅이 끝날 때까지 그 팀의 스킬과 MCP 서버를 사용할 수 있습니다. 채팅 목록에는 팀 채팅의 소속 팀을 표시합니다. 팀 채팅이 하나라도 있으면 **전체**, **개인**, **팀**으로 목록을 필터링할 수 있습니다.

### 슬래시 명령

메시지 입력란의 맨 앞에 `/`를 입력해 명령 메뉴를 엽니다. 계속 입력하면 이름이나 설명으로 명령을 필터링합니다. ↑ ↓로 명령을 선택하고, **Enter**로 실행하고, **탭**으로 실행 없이 자동 완성하고, **Esc**로 메뉴를 닫습니다. 인수가 필요한 명령을 자동 완성하면 메뉴에 선택할 수 있는 인수가 표시됩니다. 채팅 페이지나 어디서든 ⌘J로 열 수 있는 Mole Agent 패널에서 명령을 사용할 수 있습니다.

| 명령 | 동작 |
|---|---|
| `/help` | 모든 명령을 나열합니다. |
| `/new` | 새 채팅을 시작합니다. |
| `/team <team>` | 새 채팅에 사용할 팀을 선택합니다. `personal`을 지정하면 개인 채팅으로 시작합니다. 이미 시작한 채팅에서 실행하면 지정한 팀의 새 채팅을 시작합니다. |
| `/mode auto\|quick\|deep\|query` | 분석 모드를 전환합니다. **자동 모드**, **빠른 답변**, **심층 조사**, **쿼리만 생성** 중에서 선택합니다. |
| `/time 15m\|30m\|1h\|6h\|24h\|7d` | 시간 범위를 설정합니다. |
| `/policy advice\|readonly\|approval\|auto\|bypass` | 실행 모드를 설정합니다. **제안 모드**, **조사 모드**, **승인 후 실행**, **자동 모드**, **권한 확인 건너뛰기** 중에서 선택합니다. `bypass`는 에이전트 프로필이 허용하는 경우에만 사용할 수 있으며, 먼저 확인을 요청합니다. |
| `/model <model provider>` | 제공업체 이름이나 모델 이름으로 모델 제공업체를 선택합니다. `auto`를 지정하면 자동으로 선택합니다. |
| `/profile <agent profile>` | 에이전트 프로필을 선택합니다. `auto`를 지정하면 기본 프로필을 사용합니다. |
| `/prompt <prompt>` | 프롬프트를 선택합니다. `auto`를 지정하면 자동으로 선택합니다. |
| `/query <question>` | 실행하지 않고 쿼리를 작성합니다. |
| `/dashboard <what it should show>` | 대시보드를 만듭니다. |
| `/rca <incident> [more context]` | 인시던트의 근본 원인을 조사합니다. 메뉴에 미해결 인시던트를 나열합니다. `alerts.incidents.read` 권한이 필요합니다. |
| `/export` | 현재 채팅을 Markdown 파일로 다운로드합니다. |

`/query`, `/dashboard`, `/rca`는 메시지로 전송합니다. 채팅에는 명령을 레이블로 표시하고 그 뒤에 인수를 표시합니다. 답변을 다시 생성하면 같은 명령을 다시 실행합니다. `/query` 모드는 해당 메시지에만 적용합니다. `/rca`는 인시던트 시작 30분 전부터 종료 시점까지 조사합니다. 인시던트가 아직 미해결이면 현재 시점까지 조사합니다. 다른 명령은 메시지 입력란의 설정만 변경하며 메시지를 전송하지 않습니다.

명령이 존재하지 않거나, 인수가 누락되거나 잘못되었거나, 필요한 권한이 없으면 명령을 전송하지 않고 메시지 입력란 위에 이유를 표시합니다. `/`로 시작하는 일반 텍스트를 보내려면 맨 앞에 `\/`를 입력합니다. 메시지를 전송할 때 백슬래시를 제거합니다. `/var/log/app.log`처럼 슬래시가 두 개 이상인 경로는 일반 텍스트로 전송합니다.

스킬과 MCP 프롬프트도 명령으로 사용할 수 있습니다. 메뉴의 **스킬**과 **MCP**에서 찾을 수 있습니다.

- `/name [request]`는 현재 채팅에서 사용할 수 있는 스킬을 실행합니다. 두 팀에 이름이 같은 스킬이 있으면 `/name@team`을 입력합니다. 개인 채팅에서는 해당 팀도 채팅에 추가합니다.
- `/<server>:<prompt> [arguments]`는 메시지를 보낸 사람의 자격 증명으로 MCP 서버에서 프롬프트를 가져와 질문으로 전송합니다. 인수는 순서대로 입력하거나 `name=value` 형식으로 이름을 지정해 입력합니다. 순서대로 입력하면 마지막 인수가 나머지 텍스트 전체를 받습니다. 공백이 있는 값은 따옴표로 묶습니다.

스크립트를 실행하는 스킬에는 Mole Runner가 필요합니다. 구성원 자격 증명을 사용하는 서버의 프롬프트를 실행하려면 메시지를 보내기 전에 개인 자격 증명을 설정해야 합니다. 메뉴의 해당 명령에 이러한 요구 사항을 표시합니다.

## 지식 및 메모리

**Mole Agent → 지식**을 엽니다. **지식**에는 채팅에서 읽는 조직 및 각 팀의 Markdown 파일이 있습니다. `MOLE.md`를 시작 파일로 사용하고 `@path`로 다른 파일을 참조합니다. 또는 `/init`을 실행하면 Mole Agent가 현재 설정을 살펴보고 몇 가지 질문을 한 뒤, 확인을 거쳐 각 파일을 작성합니다. `agent.manage` 권한을 가진 구성원은 조직의 지식을 변경할 수 있으며, 팀 구성원은 소속 팀의 지식을 변경할 수 있습니다.

- **새로 만들기**에서는 파일을 만들거나 첫 파일을 담을 폴더를 만들 수 있습니다. `runbooks/api.md`처럼 경로를 입력하면 폴더와 파일을 한 번에 만듭니다.
- **업로드**에서는 파일이나 폴더 전체를 업로드할 수 있습니다.
- 파일은 **미리보기**에서 열립니다. **편집**에서는 메시지 입력란과 마찬가지로 입력하는 동안 렌더링된 내용을 볼 수 있으며, **소스**에서는 Markdown을 직접 편집합니다. HTML 주석처럼 편집기에서 보존하지 않는 Markdown이 포함된 파일은 **소스**에서 편집합니다.
- **AI**를 선택하면 파일을 수정할 수 있는 채팅이 열립니다.

**메모리**에는 채팅이 기억한 기본 설정, 절차, 사실, 교훈이 저장됩니다. 개인 채팅의 메모리는 채팅 소유자에게, 팀 채팅의 메모리는 해당 팀에 저장됩니다. 각 메모리에는 원본 채팅 이름이 링크로 표시됩니다. 지식 파일과 같은 방식으로 메모리의 내용을 수정하거나 메모리를 삭제할 수 있습니다. 새 메모리는 채팅에서만 작성합니다. `agent.memories.settings` 권한을 가진 구성원이 **채팅 후 기억할 내용 추리기**를 켜면, 채팅이 멈춘 지 30분 뒤 모델이 조직의 모델 사용 예산을 사용해 기억할 내용을 고릅니다.

## 조사

복잡한 질문은 진행 상황을 추적할 수 있는 조사로 전환합니다. 조사에는 다음 항목을 기록합니다.

- 상태 및 현재 단계
- 증거 및 증거가 결론에 미친 영향
- 서로 경쟁하는 가설 및 각 가설의 신뢰도
- 관련 채팅, 승인 및 실행
- 최종 요약 및 복구 검증

인시던트에서 시작한 채팅은 해당 인시던트의 조사를 기록합니다. APM 서비스, 엔드포인트, 오류 또는 인사이트에서
**조사**를 선택해 시작한 채팅은 해당 서비스의 조사를 기록합니다. RUM 페이지에서
**Mole Agent로 조사**를 선택해 시작한 채팅은 해당 애플리케이션의 조사를 기록합니다.
**Mole Agent → 조사**에서 조사 목록을 확인합니다. 채팅에 APM 서비스를 연결하면 모델은
채팅의 시간 범위에 해당하는 수치와 인사이트, 해당 서비스를 호출하는 대상과 해당 서비스가 호출하는 대상의 정보를 받습니다.
[Mole Agent로 조사](/ko/apm/insights#mole-agent로-조사)를 참조합니다. 채팅에 RUM 애플리케이션을 연결하면 모델은
해당 애플리케이션의 세션, Core Web Vitals, 주요 문제 및 현재 발생 중인 알림 정보를 받습니다.
[Mole Agent로 조사](/ko/rum#mole-agent로-조사)를 참조합니다.

채팅에 인시던트를 연결하면 모델은 인시던트 자체 외에도 다음 정보를 받습니다. 해당 인시던트를 생성한 알림 규칙의 조사 가이드(가이드에 쿼리가 있으면 모델이 먼저 실행), 영향을 받은 서비스와 해당 데이터의 위치에 관한 서비스 카탈로그 정보, 최근 90일간 가장 유사했던 인시던트의 종료 결과와 근본 원인 설명의 첫 문장, 그리고 인시던트 발생 직전부터 직후까지의 배포, 구성 변경, 기능 플래그 정보입니다. 인시던트에서 시작한 채팅과 인시던트가 트리거한 자동화에는 동일한 정보를 제공합니다.

Mole Agent는 데이터를 읽을 때 요약된 결과부터 확인합니다. `analyze_log_patterns`는 로그를 패턴별로 묶어 기준 기간과 비교하고, `analyze_metric_trend`는 메트릭이 언제부터 얼마나 변했는지와 어떤 시계열 및 레이블이 변화를 주도했는지 보여줍니다. 이후 예시를 확인하기 위해 원본 로그를 읽습니다. 한 단계에서 메트릭, 로그, 트레이스 등을 읽는 작업은 최대 4개까지 동시에 실행합니다. 변경 작업은 한 번에 하나씩 실행합니다.

조직의 자동화가 활성 인시던트의 근본 원인 분석을 작성하지 않으면 백그라운드에서 도구 없이 모델을 한 번 호출해 분석을 작성합니다. 이 분석은 시스템 권한으로 실행하며, 인시던트를 볼 수 있는 모든 구성원이 읽을 수 있습니다. 따라서 스트림 데이터는 읽지 않고 인시던트 자체, 조사 가이드, 서비스 카탈로그, 유사 인시던트 및 발생 전후의 변경 사항을 바탕으로 분석합니다. 도구로 데이터를 확인하는 분석이 필요하면 [자동화](/ko/automations)의 **인시던트 분석** 템플릿을 사용합니다. 이 템플릿은 자동화를 저장한 구성원의 권한으로 실행합니다.

## 자동화

자동화를 사용하면 채팅에 참여하지 않아도 Mole Agent가 작업을 수행합니다. 정해진 일정에 따라, 새 인시던트가 발생할 때마다, CI/CD 작업에서 호출할 때 또는 수동으로 실행할 수 있습니다. 실행할 때마다 채팅으로 기록합니다. 결과를 알림 채널로 보내거나, 인시던트의 경우 해당 인시던트의 근본 원인 분석(RCA)으로 저장할 수 있습니다. [자동화](/ko/automations)를 참조합니다.

## 품질

규칙에 따라 모든 답변의 점수를 매깁니다. 조직에서 설정한 평가기는 답변의 표본을 모델로 평가합니다. 점수가 낮거나 도움이 되지 않는다는 평가를 받은 답변은 **품질** 탭에서 검토를 기다립니다. 채팅 또는 RCA에 사용할 조직 프롬프트를 기본값으로 지정하기 전에 현재 기본 프롬프트와 비교해 검증합니다. [품질](/ko/quality)을 참조합니다.

## IM

Mole Agent는 커넥터를 통해 Feishu, Slack, DingTalk, WeCom, Google Chat, Microsoft Teams, Telegram에서도 답변합니다. 그룹에서 Mole Agent를 멘션하거나 다이렉트 메시지를 보냅니다. 해당 서비스에서 진행한 채팅도 MoleSignal에 표시됩니다. [IM에서 Mole Agent 사용](/ko/im)을 참조합니다.

## 승인 및 실행

쓰기 작업을 수행할 수 있는 도구는 항상 서버의 실행 정책을 따릅니다.

| 위험 수준 | 기본 실행 모드 |
|---|---|
| L0 | 자동 실행합니다. |
| L1 | 사용자 확인이 필요합니다. |
| L2 | 승인 1건이 필요합니다. |
| L3 | 승인 2건이 필요합니다. |
| L4 | 실행을 비활성화합니다. 파괴적 작업을 수행하는 원격 도구에는 최소 이 위험 수준을 적용합니다. |

승인에는 제안된 작업을 저장하며, 정책에 정해진 유효 기간이 지나면 만료됩니다. 실행 전에
서버는 권한, 리소스 상태, 매개변수, 위험 수준 및 멱등성을 다시 검증합니다. 실행
기록에는 실행 결과와 복구 검증 결과를 저장합니다.

## 로그 점검

Mole Agent는 로그 스트림을 읽고 보고서를 작성합니다. **로그**에서 한 번 실행하거나
백그라운드에서 일정에 따라 실행할 수 있습니다. 예약 점검은 모든 보고서를 보관하고, 보고서에서
문제를 발견하면 알림을 보냅니다. [로그 점검](/ko/logs/inspections)을 참조합니다.

## 스킬

스킬은 개방형 Agent Skills 형식으로 한 가지 작업 유형의 지침을 작성한 `SKILL.md`와 지침에서 참조하는 파일을 담은 폴더입니다. Mole Agent는 채팅에서 사용할 수 있는 스킬의 이름과 설명을 확인하고, 요청에 맞는 스킬의 지침을 읽습니다. 지침에서 다른 파일을 참조하면 해당 파일도 읽습니다. 모든 스킬은 슬래시 명령으로도 사용할 수 있습니다.

| 소스 | 관리 위치 | 사용 범위 |
|---|---|---|
| **기본 제공** | MoleSignal에 포함 | 모든 조직, 읽기 전용 |
| **인스턴스 폴더** | 서버의 `[agent].skill_paths`에 나열된 폴더 | 모든 조직, 읽기 전용 |
| **업로드됨** | **Mole Agent → 설정 → 스킬 → 스킬 업로드** | 조직, 팀 또는 개인 |
| **리포지토리** | **Mole Agent → 설정 → 스킬 → 저장소 추가** | 조직, 팀 또는 개인 |

기본 제공 스킬에는 지식 정보를 작성하는 `/init`, Mole Agent의 사용 방식과 개선할 점을 돌아보는 `/insight`([자동화](/ko/automations#mole-agent-사용-내역-검토) 참조), RUM 애플리케이션 개요에서 시작해 이슈, 세션, 트레이스를 살펴보며 실제 사용자 문제를 분류하는 `/rum-triage`, 조사에 필요한 데이터가 얼마나 잘 갖춰져 있는지 점검하고 보고서를 작성하는 `/data-readiness`가 있습니다. `/data-readiness`는 각 스트림에 서비스, 환경, 트레이스 ID를 기록하는지, 로그, 메트릭, 트레이스에서 동일한 서비스 이름을 사용하는지, 메트릭 이름에 단위가 포함되는지 확인하고 항목별로 해결 방법을 제시합니다. `agent.manage` 권한이 있으면 조직의 기본 제공 스킬과 인스턴스 폴더 스킬을 비활성화할 수 있습니다. 이름이 같은 스킬이 있으면 채팅은 개인, 팀, 조직, 인스턴스 폴더, 기본 제공 순으로 스킬을 선택합니다. 시작할 때와 폴더 안의 파일이 변경될 때마다 인스턴스 폴더를 읽습니다. 자세한 내용은 [구성](/ko/configuration)을 참조합니다.

### 스킬 작성

`SKILL.md`는 YAML 프런트매터로 시작합니다.

| 필드 | 필수 | 설명 |
|---|---|---|
| `name` | 예 | 명령 이름입니다. 문자로 시작하고 이후에는 문자, 숫자, `-`, `_`를 사용할 수 있습니다. 최대 64자이며 기본 제공 명령의 이름은 사용할 수 없습니다. |
| `description` | 예 | 스킬이 수행하는 작업과 사용할 시점을 설명합니다. 최대 1024자입니다. Mole Agent는 이 설명을 기준으로 스킬을 선택합니다. |
| `allowed-tools` | 아니요 | 스킬에서 사용하는 도구입니다. 스킬을 명령으로 실행하면 모델에 도구를 직접 제공하되, 조직의 도구 정책과 승인 요건은 그대로 적용합니다. |
| `argument-hint` | 아니요 | 인수 입력 형식입니다. 명령 메뉴에 표시합니다. |
| `version` | 아니요 | 설정에 표시하고 호출할 때마다 기록합니다. `metadata.version`도 사용할 수 있습니다. |
| `tags`, `examples` | 아니요 | 태그와 직접 사용해 볼 질문입니다. 스킬 상세 정보에 표시합니다. |
| `requires` | 아니요 | `runner`는 스크립트를 실행하는 스킬임을 나타냅니다. 이 스킬에는 Mole Runner가 필요합니다. |

지침에서 `$ARGUMENTS`는 명령 뒤에 입력한 전체 텍스트를, `$1`부터 `$9`까지는 해당 텍스트의 각 단어를 나타냅니다. 이 표기를 사용하지 않으면 입력 텍스트를 지침 뒤에 붙입니다.

패키지는 스킬 폴더 하나를 포함한 최대 20 MiB의 `.zip`, `.skill` 또는 `.tar.gz` 파일입니다. 압축을 풀었을 때 파일은 최대 300개, 전체 크기는 최대 20 MiB, 파일당 크기는 최대 8 MiB입니다. 폴더 외부를 가리키는 링크와 경로는 허용하지 않습니다. 같은 소유 범위에 이미 있는 이름으로 스킬을 업로드하면 교체하기 전에 확인을 요청합니다. 스킬 상세 정보에서 **채팅에서 사용해 보기**를 선택하면 명령이 입력된 상태로 Mole Agent가 열립니다.

### 스킬 리포지토리

브랜치 또는 태그에서 리포지토리를 읽고 하나의 아카이브로 다운로드합니다. 리포지토리 전체 또는 지정한 **폴더** 아래에서 `SKILL.md`를 포함하는 각 폴더를 스킬로 가져옵니다. 리포지토리당 아카이브는 최대 64 MiB이며 스킬은 최대 50개까지 포함할 수 있습니다. GitHub, GitLab, Gitea, Forgejo, Bitbucket은 리포지토리 주소에서 읽습니다. 다른 호스트를 사용하는 경우 `{ref}`가 포함된 아카이브 주소를 입력합니다. 비공개 리포지토리에는 액세스 토큰이 필요하며, 토큰은 입력할 수 있지만 조회할 수는 없습니다.

리포지토리를 저장하면 한 번 동기화합니다. **동기화**를 선택하면 다시 동기화하고, **매일 동기화**를 사용하면 최신 상태를 유지합니다. 동기화 시 리포지토리의 스킬을 추가, 업데이트, 제거하고 가져오지 못한 폴더를 이유와 함께 나열합니다. 리포지토리를 삭제하면 해당 스킬도 제거합니다.

## 조직, 팀 및 개인 리소스

스킬, 스킬 리포지토리, MCP 서버는 조직, 팀 또는 개인에 속합니다. 리소스를 추가할 때 **소유 범위**를 지정합니다. 편집 권한이 있으면 관리할 수 있는 다른 범위로 리소스를 옮길 수 있습니다.

| 범위 | 변경 권한 | 사용 위치 |
|---|---|---|
| 조직 | `agent.manage` 권한 보유자 | 모든 채팅 |
| 팀 | 해당 팀의 구성원과 `agent.manage` 권한 보유자 | 팀 채팅과 해당 팀을 추가한 개인 채팅 |
| 개인 | 소유자, 단 `agent.manage` 권한 보유자는 조회, 비활성화 또는 삭제 가능 | 소유자의 개인 채팅 |

스킬, 리포지토리 또는 MCP 서버가 남아 있는 팀은 삭제할 수 없습니다. **ID 및 액세스 → 팀**에 표시되는 리소스를 먼저 옮기거나 삭제합니다.

팀과 개인이 추가한 리포지토리와 MCP 서버는 공용 인터넷과 `agent.network_policy.manage` 권한 보유자가 **Mole Agent → 설정 → 네트워크 정책 → 팀 및 개인 연결용 내부 네트워크**에 등록한 내부 호스트 및 네트워크 범위에만 연결할 수 있습니다. TLS 인증서는 항상 검증합니다. 조직의 리포지토리와 MCP 서버는 각각의 설정을 따릅니다.

### 도구 및 기능

도구는 제품 영역별로 그룹화됩니다. 섹션을 열면 그룹은 접힌 상태로 표시됩니다.
그룹을 펼치거나 검색하여 일치하는 도구가 있는 그룹을 엽니다. **전체**, **읽기 전용**,
**자동**, **승인**, **비활성화됨** 필터에는 각각 해당하는 도구 수가 표시됩니다.

도구의 제목과 설명은 인터페이스 언어로 표시됩니다. 도구 상세 정보에는 모델에 전달하는
정의도 표시됩니다. 이 정의는 인터페이스 언어와 관계없이 영어로 표시됩니다.

### MCP 서버

**도구 및 기능 → MCP 서버**에서 서버를 추가하고 연결을 테스트하며 도구를 가져옵니다. 각 서버에는 소유자가 표시됩니다. 멤버는 여기에서 개인 서버와 팀 서버도 관리합니다.

| 설정 | 설명 |
|---|---|
| 전송 방식 | **Streamable HTTP**, 이전 HTTP 및 SSE 전송 방식을 사용하는 서버용 **SSE (레거시)**, 조직 서버 전용 **stdio** 중에서 선택합니다. **stdio**의 경우 MoleSignal은 자체 서버에서 `[agent].mcp_stdio_commands`에 나열된 명령만 실행합니다. 셸을 사용하지 않고 명령에 `PATH`, `HOME`, `LANG`, `TMPDIR` 및 해당 서버의 **환경 변수**를 전달합니다. 명령은 시스템 임시 폴더에서 실행되며 호출이 끝날 때마다 종료됩니다. 자격 증명은 **환경 변수**에 설정합니다. 인증, 요청 헤더, 멤버 자격 증명은 HTTP로 연결하는 서버에서만 사용합니다. 명령이 액세스하는 대상에는 조직의 네트워크 정책이 적용되지 않습니다. |
| 인증 | 인증 없음, 모든 멤버가 공유하는 토큰이나 키, 또는 **멤버 자격 증명 (멤버별로 사용)** 중에서 선택합니다. 멤버 자격 증명을 사용하면 각 멤버가 서버에서 지정한 헤더의 값을 개별적으로 저장하며, 해당 멤버의 호출에만 그 값을 사용합니다. |
| **헤더** | 모든 요청에 헤더를 전송합니다. 이름에 key, token, secret, password, credential, auth 또는 cookie가 포함된 헤더의 값은 암호화되며 마지막 네 문자만 표시됩니다. 편집할 때 비밀 값을 비워 두면 기존 값을 유지합니다. |

**연결 테스트**는 서버의 도구 목록을 표시합니다. **선택한 도구 동기화**는 선택한 도구를 가져옵니다. 새 도구는 활성화하기 전까지 비활성 상태로 유지되며, 최소 위험 수준은 서버의 주석을 따릅니다. **도구 및 프롬프트**에는 도구마다 스위치가 표시됩니다. **모든 읽기 전용 도구 활성화**를 선택하면 읽기 전용 도구를 한 번에 활성화합니다. 도구 정책과 승인 규칙은 계속 적용됩니다. 서버에서 제공하는 프롬프트는 `/<server>:<prompt>` 형식의 명령으로 등록됩니다.

Mole Agent는 약 한 시간마다 동기화된 각 서버를 다시 확인합니다. 입력 스키마가 변경되었거나, 서버 목록에서 사라졌거나, 서버에서 위험 수준을 높인 도구는 검토 후 다시 동기화할 때까지 사용할 수 없습니다. 멤버 자격 증명을 사용하는 서버는 이 검사에서 제외합니다.

**가져오기**는 Claude Desktop, Claude Code, Cursor 또는 VS Code의 MCP 구성을 읽어 서버를 추가합니다. `${input:token}`처럼 변수를 참조하는 값은 가져오지 않고, 직접 입력할 수 있도록 목록에 표시합니다. `command`가 있는 서버는 stdio 서버입니다. 인스턴스가 허용하는 명령을 사용하는 경우에만 조직으로 가져올 수 있습니다.

멤버 자격 증명을 사용하는 서버에서 **내 자격 증명 추가**를 선택하면 해당 멤버의 값을 저장합니다. 채팅에서 자격 증명 없이 도구를 호출하거나 서버가 저장된 자격 증명을 거부하면, **계속하려면 인증 필요** 카드에서 입력을 받을 때까지 응답을 보류합니다. 카드에는 자격 증명이 필요한 도구와 서버의 안내가 표시됩니다. **저장 후 계속**은 **내 자격 증명 추가**와 마찬가지로 자격 증명을 저장한 다음 도구를 다시 실행합니다. **건너뛰기**를 선택하면 해당 응답의 나머지 과정에서 그 서버를 사용하지 않습니다. 자격 증명은 질문한 멤버의 것이므로 해당 멤버만 카드에 입력할 수 있습니다. 팀 채팅의 다른 멤버에게는 누가 입력해야 하는지 표시됩니다. 카드는 최대 한 시간 동안 입력을 기다립니다. 카드로 입력을 요청할 수 없으면 도구는 자격 증명이 없다고 반환하고, Mole Agent는 멤버에게 자격 증명을 추가하도록 요청합니다.

### 프롬프트 관리

기본 제공 프롬프트는 읽기 전용이며 이름은 인터페이스 언어로 표시됩니다.
기본 제공 프롬프트에서 **재정의 만들기**를 선택해 조직 또는 특정 사용자용 프롬프트로 바꿉니다.
조직 프롬프트를 채팅 또는 근본 원인 분석의 기본값으로 설정하려면 먼저 조직의 검사를 거쳐야 합니다.
자세한 내용은 [품질](/ko/quality#프롬프트를-기본값으로-설정하기-전에-검증하기)을 참조합니다.

### 에이전트 프로필의 실행 한도

프로필을 사용하는 각 채팅 응답에 다음 한도를 적용합니다. 활성 프로필이 없으면 기본값을 적용합니다.

| 설정 | 기본값 | 설명 |
|---|---|---|
| **최대 도구 호출 횟수** | `32` | 응답 한 건에서 도구를 호출할 수 있는 최대 횟수입니다. 범위는 1~256회입니다. |
| **최대 조사 시간(분)** | `30` | 응답 한 건의 제한 시간입니다. 범위는 1~120분입니다. |
| **온도** | `0.2` | 샘플링 온도입니다. 범위는 0~2입니다. 값이 낮을수록 응답이 일관되고 재현성이 높아집니다. |

도구 호출 횟수나 시간이 한도에 도달하면 Mole Agent는 도구 호출을 중단하고 이미 확보한 결과로 응답합니다.

### 사용량 및 예산

**Mole Agent → 설정 → 사용량**에서 조직의 오늘 토큰 사용량, 일일 예산, 최근 30일간의 사용량을 확인합니다. 사용량은 UTC 날짜 기준으로 집계하며, 토큰 수는 입력 토큰과 출력 토큰의 합계입니다. 다음 소스를 집계합니다.

| 소스 | 설명 |
|---|---|
| **채팅** | 대시보드 작성을 포함한 Mole Agent 채팅입니다. |
| **근본 원인 분석** | 진행 중인 인시던트에 대해 자동으로 생성하거나 인시던트에서 요청하여 생성한 분석입니다. |
| **로그 검사** | 즉시 실행하거나 예약한 검사입니다. |
| **LLM 함수** | [알림 파이프라인](/ko/pipelines/alert-events#ai-요약)의 **AI 요약** 단계와 LLM 함수 실행입니다. |
| **자동화** | 인시던트가 시작한 실행을 포함한 자동화 실행입니다. |
| **품질 평가** | 평가기 실행과 프롬프트 검사에서 다시 생성한 응답입니다. |

모델 공급자에 요금 정보가 있으면 공급자별 통화로 비용도 표시합니다. 서로 다른 통화의 비용은 별도로 표시하며 합산하지 않습니다. 요금 정보가 없는 모델 공급자의 호출은 비용에 포함하지 않습니다. 이러한 호출을 제외한 금액에는 **≥**를 표시하며, 실제 비용은 표시된 금액 이상입니다.

일일 예산의 기본값은 인스턴스 설정 `[agent].daily_token_budget`을 따릅니다(`0`은 한도 없음을 의미합니다). 자세한 내용은 [구성](/ko/configuration)을 참조합니다. `agent.usage.manage` 권한이 있는 관리자는 조직의 한도를 **사용자 지정** 또는 **한도 없음**으로 설정하고, 예산을 모두 사용했을 때 채팅 및 요청 시 분석의 동작을 선택할 수 있습니다.

| 옵션 | 동작 |
|---|---|
| **모델 호출 중단**(기본값) | 질문을 전송하지 않고 메시지 입력란에 남겨 둡니다. 채팅에 오늘 예산을 모두 사용했다는 안내와 예산 초기화 시점을 표시합니다. 요청 시 분석에도 같은 안내를 표시합니다. |
| **경고만 표시하고 응답** | 채팅은 응답을 생성하고 메시지 입력란 위에 예산을 초과했다는 경고를 표시합니다. |

예산을 모두 사용하면 자동 근본 원인 분석, 로그 검사, AI 요약 단계, LLM 함수가 모델 호출을 중단합니다. 로그 검사는 예산 소진을 이유로 실패하고, 자동 분석은 예산이 초기화될 때까지 대기하며, AI 요약 단계와 LLM 함수는 실패합니다. 사용량이 경고 임계값(기본값 80%, `[agent].budget_warning_percent`)에 도달하면 채팅의 메시지 입력란 위에 경고를 표시합니다. 약 15초 동안 캐시한 상태를 기준으로 예산을 확인하며, 생성 중인 응답은 중단하지 않습니다. 따라서 사용량이 한도를 약간 초과할 수 있습니다.

모델을 호출할 때마다 내부 스트림 `_agent_model_traces`에 행을 기록합니다. 이 스트림은 **로그**에서 쿼리할 수 있습니다. 공통 필드는 `origin` (`chat`, `rca`, `inspection`, `llm_eval`, `automation`, `evaluation`, `replay_summary`), `provider`, `model`, `prompt_tokens`, `cached_prompt_tokens`(공급자가 캐시에서 처리한 입력 부분), `completion_tokens`, `total_tokens`, `latency_ms`, `cost`, `cost_currency`, `status`, `error`, `tool_calls`, `streaming`, `chat_id`, `user_id`, `profile_id`, `prompt_hash`입니다. 모델 공급자에 요금 정보가 있는 경우에만 `cost`와 `cost_currency`를 기록합니다. `user_id`는 호출 사용량이 집계되는 사용자를 나타냅니다. 채팅에서는 질문한 사용자, 로그 검사에서는 해당 검사를 실행하도록 지정된 사용자입니다. 근본 원인 분석 및 LLM 함수 호출에는 이 필드가 없습니다.

## 데이터 처리

Mole Agent는 대화와 호출한 도구의 실행 결과를 설정된 모델 공급자에게 전송합니다. 모델 공급자를 설정하지 않으면 배포 환경 외부로 어떤 데이터도 전송하지 않습니다. 다음 제어 항목은 에이전트의 액세스 범위를 제한합니다.

- **데이터 액세스**는 기본 프로필이 읽을 수 있는 환경, 서비스, 스트림을 제한합니다. 다른 조직에는 어떤 경우에도 액세스할 수 없습니다.
- **네트워크 정책**은 프로필이 네트워크가 필요한 도구를 사용할 수 있는지 결정합니다. 새 프로필은 네트워크 액세스를 차단합니다. 이 스위치를 켜도 임의의 HTTP 요청을 보내는 도구, 셸 도구, 브라우저 도구, 개방형 MCP 도구는 활성화되지 않습니다.
- **승인 정책**은 쓰기 작업의 위험 수준에 따라 승인을 요구하고, 이 프로필을 사용하는 채팅에서 **권한 확인 건너뛰기**를 선택할 수 있는지 결정합니다.
- **스킬 및 MCP 서버**는 정책 범위를 넓히지 않고 지침과 도구를 추가합니다. 스킬에서 허용하는 도구와 모든 MCP 도구에는 조직의 실행 모드와 승인 요건이 그대로 적용됩니다.

시스템은 암호화 루트 키로 모델 키를 암호화합니다. [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다.

## 권한

- `agent.use`로 채팅과 실행 기록을 열고 답변과 분석을 평가할 수 있습니다.
- `agent.investigations.read`, `agent.knowledge.read`, `agent.memories.read`, `agent.skills.read`, `agent.mcp_servers.read`, `agent.usage.read`로 각각 조사, 지식, 메모리, 스킬, MCP 서버, 사용량을 볼 수 있습니다. 각 항목에 대응하는 `.manage` 권한으로 사용자와 소속 팀의 항목을 변경할 수 있습니다. 리포지토리를 추가하려면 `agent.skill_repositories.manage`가 필요합니다.
- `agent.manage`는 조직 수준의 항목에도 적용됩니다. 모든 팀 채팅과 조직의 지식, 스킬, MCP 서버에 액세스할 수 있습니다.
- `agent.models.manage`, `agent.prompts.manage`, `agent.tools.manage`, `agent.toolsets.manage`, `agent.profiles.manage`, `agent.usage.manage`, `agent.network_policy.manage`, `agent.inbound_mcp.manage`, `agent.im.manage`로 각각 공급자, 프롬프트, 도구, 도구 세트, 프로필, 일일 예산, 네트워크 정책, 인바운드 MCP, 챗봇을 설정할 수 있습니다. **설정**의 각 섹션에는 해당 섹션의 권한만 필요합니다. 읽기 권한이 없으면 필요한 권한을 표시합니다. 해당 `.manage` 권한이 없으면 설정은 읽기 전용이지만, 섹션에 표시되는 내용은 계속 검색하고 복사할 수 있습니다.
- `agent.quality.read`로 **품질** 탭을 열어 점수, 검토, 평가기를 볼 수 있습니다. `agent.quality.manage`로 해당 항목을 변경할 수 있습니다.
- `agent.automations.read`로 자동화 목록을 볼 수 있고, `agent.automations.manage`로 자동화를 만들고 변경할 수 있습니다. `agent.automations.run`으로 자동화를 실행하고, `agent.automations.tokens`로 자동화의 API 토큰을 관리할 수 있습니다. [자동화](/ko/automations#시작하기-전에)를 참조합니다.
- `agent.approve`로 통제 대상 작업을 검토할 수 있습니다.
