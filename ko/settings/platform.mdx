플랫폼 설정은 보호된 `_sys` 조직에 있습니다. 워크스페이스
전환 메뉴에서 이 조직으로 전환합니다. 최고 관리자와 플랫폼 역할을 부여받은 계정만 이 조직에 접근할 수 있습니다. 각 페이지는
이 조직의 **설정** 아래에 표시되며 플랫폼 권한이 필요합니다. 페이지를 보려면 해당 그룹의
`.read` 권한이 필요하고, 설정을 변경하려면 `.manage` 권한이 필요합니다.

| 섹션 | 그룹 | 권한 |
|---|---|---|
| **조직 관리** | 플랫폼 | `sys.organizations.read` |
| **로그인 제한** | 플랫폼 | `sys.settings.signin.manage` |
| **클라이언트 IP 식별** | 데이터 플레인 | `sys.settings.signin.manage` |
| **데이터 보존** | 데이터 플레인 | `sys.settings.retention.manage` |
| **메트릭 카디널리티** | 데이터 플레인 | `sys.settings.limits.manage` |
| **데이터 수집 사용량** | 데이터 플레인 | `sys.settings.limits.manage` |
| **감사 기록 보존** | 데이터 보안 | `sys.settings.retention.manage` |

모든 노드가 데이터베이스에서 이 설정을 읽으므로 설정을 변경해도 다시 시작할 필요가 없습니다.

## 조직 관리

**조직 관리**에서는 인스턴스의 테넌트 조직을 나열하고 각 조직의 이름, 슬러그,
상태, ID를 표시합니다.

| 작업 | 효과 |
|---|---|
| **조직 생성** | **이름**과 **슬러그**를 입력해 테넌트 조직을 생성합니다. 슬러그는 나중에 변경할 수 없습니다. |
| 비활성화 | 조직에 대한 접근을 즉시 차단합니다. 조직을 다시 활성화할 때까지 해당 조직의 세션과 API 자격 증명을 거부합니다. |
| 활성화 | 조직의 멤버와 자격 증명에 대한 접근을 복원합니다. |
| 삭제 | 조직을 즉시 영구 삭제합니다. 저장된 파일을 포함한 조직 데이터는 몇 분 내에 백그라운드에서 삭제합니다. 슬러그는 즉시 다시 사용할 수 있습니다. |

테넌트 조직은 최소 하나 이상 활성 상태로 유지해야 합니다. `_sys` 조직 자체는
변경할 수 없습니다. 조직 멤버를 관리하려면 해당 조직의
[ID 및 액세스](/ko/identity/members)로 이동합니다. 이 페이지는 **IAM 관리**를 선택해 열 수 있습니다.
[조직](/ko/identity/teams#조직) 페이지에서 이 작업을 시작합니다.

## 로그인 제한

**로그인 제한**은 크리덴셜 스터핑과 비밀번호 추측을 방지합니다. 다른 계정의 비밀번호를
틀리게 입력하는 것만으로 해당 계정의 접근을 차단할 수는 없습니다. 계정 비밀번호 확인에 실패한 횟수를 집계합니다. 비밀번호
로그인, LDAP 로그인, 데이터베이스 클라이언트에서의 계정 로그인, 비밀번호 확인이 여기에 포함됩니다. 비밀번호 확인은
[기존 계정을 연결할 때](/ko/identity/sso)와
[두 번째 인증 요소를 추가하기 전에](/ko/identity/mfa) 수행합니다.
[공개 링크](/ko/resource-sharing#접근-비밀번호-제한)의 접근 비밀번호도 집계하며, 링크 하나를 계정 하나로 처리합니다.
패스키와 OIDC, OAuth 2.0, SAML 싱글 사인온은 집계하거나 제한하지 않습니다.

| 설정 | 기본값 | 한도 도달 시 |
|---|---|---|
| **단일 주소 및 단일 계정** | 실패 5회 | 해당 주소에서 이 계정에 접근할 수 없습니다. 다른 주소에는 영향을 주지 않습니다. |
| **단일 주소 및 모든 계정** | 실패 30회 | 해당 주소에서 비밀번호로 로그인할 수 없습니다. 같은 주소를 공유하는 사용자에게도 적용됩니다. |
| **모든 주소 및 단일 계정** | 실패 20회 | 계정을 차단하지 않고 비밀번호 확인 빈도를 제한합니다. 최근 30일 이내에 로그인한 주소에는 이 제한을 적용하지 않습니다. 한 집계 기간 동안 추가 실패가 없으면 횟수를 초기화합니다. |
| **제한 중 비밀번호 확인 간격** | 60초 | 1~600초로 설정할 수 있습니다. |
| **차단 및 집계 기간** | 15분 | 주소를 차단하는 기간이자 이전 실패를 집계하는 기간입니다. 1~1440분으로 설정할 수 있습니다. |

집계를 끄려면 `0`을 입력합니다. 최대 100000회까지 설정할 수 있습니다. 변경 사항은 즉시 적용되며
플랫폼 감사 로그에 `signin_limits.update`로 기록됩니다.

| 상황 | 결과 |
|---|---|
| 요청 거부 | `Retry-After` 헤더와 함께 `429`를 반환합니다. 비밀번호를 확인하거나 차단을 연장하지 않으므로 차단은 설정한 기간을 넘지 않습니다. |
| 존재하지 않는 계정 | 존재하는 계정과 동일하게 집계하고 응답하므로 응답으로 계정의 존재 여부를 알 수 없습니다. |
| 올바른 비밀번호 | 해당 주소에서 해당 계정에 대해 발생한 실패 횟수를 초기화합니다. 주소 전체와 계정 전체의 집계값에서는 이번 시도 1회만 차감하며, 집계값을 초기화하지는 않습니다. |
| 디렉터리에 연결할 수 없는 경우 등 서비스 이용 불가 | 실패로 집계하지 않습니다. |
| 한도 도달 | 플랫폼 감사 로그에 주소 및 도달한 한도와 함께 `signin.lockout`으로 기록합니다. 계정은 존재하는 경우에만 기록합니다. |
| 비밀번호 재설정 성공 | 계정 차단을 즉시 해제하고 해당 주소의 비밀번호 확인 빈도 제한도 해제합니다. |
| 공개 링크의 접근 비밀번호 | 링크 하나를 계정 하나로 집계하고 최근 30일 이내에 해당 링크를 연 주소에는 비밀번호 확인 빈도 제한을 적용하지 않습니다. **단일 주소 및 모든 계정**에서는 접근 비밀번호 오류와 로그인 실패를 합산합니다. 이 한도에 도달하면 해당 주소에서 비밀번호로 로그인할 수 없습니다. |
| 공개 링크 한도 도달 | 링크를 소유한 워크스페이스의 감사 로그에 링크, 주소, 도달한 한도와 함께 `resource_share.lockout`으로 기록합니다. **단일 주소 및 모든 계정** 한도에 도달하면 플랫폼 감사 로그에도 `signin.lockout`으로 기록합니다. |

주소는 [클라이언트 IP 식별](#클라이언트-ip-식별) 설정에 따라 결정하며, IPv6는 /64 단위로 집계합니다.
기본적으로 사설 주소는 주소별 집계에 포함하지 않습니다. 프록시를 설정하지 않으면 프록시 뒤의 모든 연결이
프록시 주소로 표시됩니다. 이 주소를 집계하면 비밀번호를 몇 번 틀리는 것만으로 모든 사용자의 접근을 차단할 수 있습니다.
이 경우 **모든 주소 및 단일 계정**만 적용합니다. 실제로 사설 네트워크에서
접속하는 경우에는 **사설 주소를 클라이언트로 집계**를 켭니다.

페이지의 **내 주소**에는 현재 요청의 출처로 식별한 주소와 해당 주소의
집계 여부가 표시됩니다. 요청에 전달 헤더가 있지만 연결 주소를 사용하면 경고를 표시합니다.
프록시 설정이 누락되었을 가능성이 높습니다.

차단을 조기에 해제해야 하는 경우에만 메타데이터 데이터베이스에서 `DELETE FROM signin_attempts`를 실행합니다.
이 명령은 모든 집계값을 초기화합니다.

## 클라이언트 IP 식별

RUM 데이터 수집은 브라우저 또는 기기별 주소를 기록하고 이를 조회해 국가, 하위 행정 구역,
도시를 확인합니다. [로그인 제한](#로그인-제한)은 주소별 실패 횟수를 집계하며,
[공개 링크](/ko/resource-sharing#감사-및-권한)의 감사 로그는 방문자별 주소를 기록합니다.
**클라이언트 IP 식별**은 주소를 가져올 소스를 결정합니다. 이 설정은 모든 조직에 적용됩니다.

| **주소 소스** | 용도 |
|---|---|
| **직접 연결 주소** | 기본값입니다. TCP 연결 상대의 주소를 사용하고 모든 전달 헤더를 무시합니다. 데이터 수집 엔드포인트를 직접 노출하는 경우에 사용합니다. |
| **단일 값 헤더** | CDN 또는 프록시가 설정하는 `CF-Connecting-IP`와 같은 헤더에서 IP 주소 값 하나만 읽습니다. |
| **전달된 IP 체인** | `X-Forwarded-For`와 같은 IP 체인을 오른쪽에서 왼쪽으로 확인합니다. 신뢰할 수 있는 프록시를 건너뛰고 신뢰 목록에 없는 첫 번째 주소를 사용합니다. **최대 체인 길이**는 요청 하나에서 읽는 주소 수를 제한하며, 1~64개로 설정할 수 있습니다. |

프록시 뒤에서 실행하는 경우 다음 항목도 설정합니다.

| 필드 | 규칙 |
|---|---|
| **클라이언트 IP 헤더** | 읽을 헤더입니다. `Authorization`, `Cookie`, API 키 헤더, 클라이언트 인증서 헤더는 허용하지 않습니다. |
| **신뢰할 수 있는 프록시 CIDR** | 한 줄에 IPv4 또는 IPv6 CIDR 하나를 입력합니다. 최대 64개까지 입력할 수 있습니다. 연결 상대의 주소가 이 네트워크에 속할 때만 헤더를 읽습니다. `/0` 네트워크는 해당 주소 체계의 모든 출처를 신뢰하므로 보호된 인그레스 뒤에서만 사용합니다. |
| **대체 주소로 연결 주소 사용** | 헤더가 없거나, 형식이 잘못되었거나, 너무 길거나, 사용할 수 있는 주소가 없으면 TCP 연결 상대의 주소를 사용합니다. |

주소 소스에 관계없이 **사설 주소를 클라이언트로 집계**를 설정할 수 있습니다. 이 설정을 켜면 신뢰할 수 있는 헤더에서 사설 주소, 루프백 주소,
링크 로컬 주소를 허용하고 [로그인 제한](#로그인-제한) 집계에 포함합니다.
사설 네트워크에서 접속하는 경우 이 설정을 켭니다. 프록시 뒤에서 실행하지만 여기에서 해당 프록시를 설정하지 않은 경우에는 이 설정을 끈 상태로 유지합니다.
그렇지 않으면 모든 사용자를 단일 주소로 집계합니다.

## 데이터 보존

**데이터 보존**은 자체 보존 기간이 없는 스트림의 보존 일수를 설정합니다. 기본값은
30일이며, 1~3650일로 설정할 수 있습니다. 각 스트림의 보존 기간은 [스트림](/ko/streams#리텐션-및-삭제)에서 설정할 수 있습니다.
보존 기간이 지난 데이터는 다음 정리 작업에서 삭제되며 복구할 수 없습니다.

더 짧은 보존 기간을 입력하면 파일 카탈로그를 바탕으로 삭제될 데이터를 추정합니다.
스트림별 행 수, 크기, 가장 오래된 데이터를 크기가 큰 순서로 표시합니다. 저장할 때는 변경 사항을
확인해야 합니다. 삭제 대상이 1 GiB 이상이거나 100만 행 이상이거나 추정할 수 없으면
보존 일수를 다시 입력해야 합니다. 보존 기간을 늘릴 때는 확인을 요청하지 않습니다. 세션 리플레이와 프로파일 아카이브에도
이 설정이 적용되지만 삭제 대상 추정치에는 포함되지 않습니다.

같은 페이지의 **신세틱 테스트 결과**에서는 신세틱 검사 실행 기록의 보존 일수를 설정합니다.
기본값은 30일이며, 0~3650일로 설정할 수 있습니다. 0으로 설정하면 영구 보존합니다. 보존 기간이 지난 실행 기록과 관련 아티팩트, 완료된
작업은 하루에 한 번 삭제합니다. 단, 각 위치에 최신으로 표시되는 실행 기록과 리비전을 게시할 때 사용한 테스트는
보존합니다. 가용성 계산에 사용하는 `_synthetic_results` 스트림은 자체
보존 기간을 따릅니다. [신세틱 모니터링](/ko/synthetics#결과-스트림-및-보존)을 참조합니다.

같은 페이지의 **스토리지 카탈로그 이력**에서는 파일 카탈로그에 완료된 작업의 기록을
보존할 일수를 설정합니다. 기본값은 7일이며, 0~3650일로 설정할 수 있습니다. 0으로 설정하면 영구 보존합니다. 이 기록에는
가비지 컬렉터가 이미 삭제한 파일, 해당 파일이 속했던 이전 세그먼트와 파티션 매니페스트,
그리고 닫힌 쓰기 스트림의 플러시 기록이 포함됩니다. 보존 기간이 지난 기록은 10분마다
정리합니다. 데이터 자체에는 영향을 주지 않으며, 스트림의 누적 수집량도
바뀌지 않습니다.

## 메트릭 카디널리티

**메트릭 카디널리티**는 동시에 활성 상태로 유지할 수 있는 Prometheus 시계열 수를 제한합니다. 이렇게 하면 값의 종류가 많은 레이블로 인해
메모리와 스토리지 리소스가 고갈되는 일을 방지할 수 있습니다.

| 제한 | 기본값 | 의미 |
|---|---|---|
| **조직별** | 200,000 | 조직 하나에서 활성 상태로 유지할 수 있는 시계열 수입니다. |
| **메트릭별** | 100,000 | 조직 내 메트릭 하나에서 활성 상태로 유지할 수 있는 시계열 수입니다. 조직별 한도를 초과할 수 없습니다. |

한도에 도달하면 새 시계열에 대한 쓰기는 거부하지만 기존 시계열에는 계속 쓸 수 있습니다.
한동안 데이터를 받지 않은 시계열은 비활성 상태로 전환됩니다. 각 노드는 30초마다 한도를 다시 읽습니다.
[메트릭](/ko/metrics)의 카디널리티 보기에서 시계열을 생성하는 레이블을 확인합니다.

## 데이터 수집 사용량

**데이터 수집 사용량**은 [소스별 수집량](/ko/streams#데이터-수집-사용량-및-예산) 기록의 보존 기간과
개별 집계할 서비스 수를 설정합니다.

| 필드 | 기본값 | 의미 |
|---|---|---|
| **기록 보존 기간** | 90일 | 보존 기간이 지난 시간별 기록은 하루에 한 번 삭제합니다. 항상 월간 예산을 확인할 수 있도록 최소 35일에서 최대 3650일까지 설정할 수 있습니다. |
| **조직당 서비스 수** | 1,000 | 각 노드에서 조직별로 한 시간 동안 개별 집계할 서비스 수입니다. 1~100,000으로 설정할 수 있습니다. 한도를 초과한 서비스는 **기타 서비스**로 묶어 집계합니다. 이렇게 하면 발신 측에서 서비스 이름을 추가해 기록 수를 늘리는 일을 방지할 수 있습니다. |

## 감사 기록 보존

**감사 기록 보존**은 모든 조직과 플랫폼의 감사 기록을 보존할 일수를
설정합니다. 기본값은 90일이며, 0~3650일로 설정할 수 있습니다. `0`으로 설정하면 영구 보존합니다. 보존 기간이 지난 기록은 하루에 한 번
삭제하며 복구할 수 없습니다. 변경할 때마다 플랫폼 감사 로그에 다음 이벤트를 기록합니다:
`audit_retention.update`.

더 짧은 보존 기간을 입력하면 삭제될 기록 수를 계산합니다. 저장할 때는
변경 사항을 확인해야 합니다. 삭제 대상이 1,000건 이상이거나 기록 수를 계산할 수 없으면
보존 일수를 다시 입력해야 합니다.
