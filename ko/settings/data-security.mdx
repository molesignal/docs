**설정**의 **데이터 보안** 그룹에는 **암호화 키**, **정규식 패턴**,
**필드 마스킹**, **도메인 관리**, **감사**가 있습니다. 처음 네 항목을 조회하려면
`org.field_masking.read` 권한이 필요하고, 변경하려면 `org.field_masking.manage` 권한이 필요합니다. **감사**에는
`audit.read` 권한이 필요합니다. 감사 기록 보존 기간은 [플랫폼 설정](/ko/settings/platform#감사-기록-보존)에서 지정합니다.

## 암호화 키

**암호화 키**에는 워크스페이스의 데이터 키와 각 키의 알고리즘, 버전, 마지막
교체 시각이 표시됩니다. 스트림에서 [암호화된 필드](/ko/streams#암호화된-필드)에 처음으로 값을 쓰면 MoleSignal이
키를 자동으로 생성합니다. 이 키는 `__field_default__`로 표시됩니다. MoleSignal은 모든 키를
루트 암호화 키 `MS_CIPHER_KEY`로 래핑하며, 키 자료는 서버 외부로 내보내지 않습니다.

| 작업 | 방법 |
|---|---|
| **새 키** | **이름**과 base64로 인코딩한 32바이트 키 자료(`keyMaterialB64`)를 입력합니다. |
| **교체** | 새 32바이트 키 자료를 base64 형식으로 붙여넣습니다. 교체하면 새 버전이 추가됩니다. 새 데이터는 새 버전으로 암호화하고, 기존 데이터는 암호화에 사용한 이전 버전으로 계속 복호화합니다. |
| 삭제 | 해당 키로 암호화한 데이터를 더 이상 읽을 수 없습니다. |

<Warning>
  `MS_CIPHER_KEY`를 잃어버리면 암호화된 필드를 모두 복구할 수 없게 됩니다.
  [필드 수준 암호화](/ko/security#필드-수준-암호화)를 참조합니다.
</Warning>

## 정규식 패턴

정규식 패턴은 카드 번호나 토큰과 같은 민감한 텍스트를 찾아 대체합니다.

1. **새 패턴**을 선택합니다.
2. **이름**, **패턴**, **설명**을 입력합니다. 서버는 저장할 때 패턴을
   검사합니다.
3. **대체 문자열**을 입력합니다. `$1` 등으로 캡처 그룹을 참조할 수 있습니다. 대체 문자열을 비워 두면
   일치하는 텍스트가 삭제됩니다.
4. **수집 시 마스킹**으로 적용 시점을 지정한 다음 **생성**을 선택합니다.

| **수집 시 마스킹** | 효과 |
|---|---|
| 켜짐 | 모든 수신 이벤트의 문자열 값을 파이프라인 처리 후 저장 전에 마스킹합니다. 원본 텍스트는 복구할 수 없습니다. |
| 꺼짐 | 저장된 데이터에 원본을 유지합니다. SQL 쿼리에서 `mask(<column>)`을 호출하면 패턴을 적용한 열을 반환합니다. |

`mask()`는 워크스페이스의 모든 패턴을 적용합니다. 목록의 **마스킹** 열은
각 패턴에 **수집 시** 또는 **쿼리 시에만**을 표시합니다.

## 필드 마스킹

필드 마스킹은 쿼리 결과에서 필드 값의 일부를 숨깁니다. 쿼리 계산에는 계속
원본 값을 사용합니다. 메트릭 스트림에는 적용하지 않습니다.

1. **새 규칙**을 선택하고 **규칙 이름**을 입력합니다.
2. **필드 일치 패턴**: 정확한 필드 이름이나 `user.*`처럼 `*` 및 `?` 와일드카드를 포함한 이름을 입력합니다.
   정규식은 사용할 수 없습니다.
3. 필요한 경우 `customer-*`와 같은 **스트림 일치 패턴**과 **스트림 유형**을 지정하여 적용 범위를 좁힙니다.
4. **알고리즘**을 선택하고 **규칙 활성화**를 켠 상태로 저장합니다.

| 알고리즘 | 효과 |
|---|---|
| **전체 마스킹** | 값 전체를 **대체 문자열**로 바꿉니다. |
| **범위 마스킹** | **시작 문자 위치**부터 **끝 문자 위치(해당 문자 제외)**까지의 문자를 마스킹합니다. |
| **내부 마스킹** | **앞부분에 표시할 문자 수**와 **뒷부분에 표시할 문자 수**만큼 문자를 남기고 가운데를 마스킹합니다. |
| **외부 마스킹** | **시작 문자 위치**부터 **끝 문자 위치(해당 문자 제외)**까지의 문자만 남기고 양쪽을 마스킹합니다. |
| **HMAC-SHA-256 해시** | 서버가 관리하는 워크스페이스 키로 다이제스트를 생성하여 값을 대체합니다. 같은 값은 같은 다이제스트를 생성하므로 결과를 계속 그룹화하고 조인할 수 있습니다. |

필드와 일치하는 활성 규칙 중 첫 번째 규칙을 적용합니다. 행을 드래그하여 순서를 변경합니다.
[스트림](/ko/streams#스키마-및-필드)의 필드 설정에서 상속된 규칙을 재정의하거나 해당 필드의
마스킹을 끌 수 있습니다.

## 도메인 관리

**도메인 관리**를 사용하면 워크스페이스에 고유한 호스트 이름으로 접속할 수 있습니다. 인증서는
MoleSignal이 발급받고 갱신합니다.

1. `account_email`을 지정하여 `[http.tls]`를 활성화합니다. [HTTP TLS 및 ACME](/ko/configuration#http-tls-및-acme)를 참조합니다.
2. ACME 서비스가 암호화되지 않은 HTTP 포트의
   `/.well-known/acme-challenge/`에 접근할 수 있도록 호스트 이름의 DNS 레코드가 MoleSignal을 가리키게 설정합니다.
3. **도메인 추가**를 선택하고 **호스트 이름**을 입력한 다음 **도메인 추가**를 선택합니다.

목록에는 각 호스트 이름의 **상태**, 인증서 만료일, **최근 오류**가 표시됩니다.
새 호스트 이름은 인증서를 발급받기 전까지 `pending` 상태로 유지되며, 발급 후에는 `active`로 바뀝니다. 인증서는
만료 전 30일 이내에 자동으로 갱신됩니다. 호스트 이름을 제거하면 해당 이름으로 더 이상 접속할 수 없습니다.

## 감사

**감사**에서는 워크스페이스의 감사 추적 기록을 검색합니다. 보안 관련 동작과
리소스 및 설정 변경을 기록하며, 각 기록에는 실행 주체, 동작, 대상, 상태, 시간이 포함됩니다.

| 필터 | 용도 |
|---|---|
| **시작** / **종료** | 절대 시간 또는 `now-24h`와 같은 상대 시간으로 지정한 시간 범위입니다. |
| **수행 주체 유형** / **실행 주체** | 실행 주체의 유형 또는 특정 사용자입니다. |
| **동작** | `audit_retention.update`와 같은 동작 키입니다. |
| **대상 유형** / **대상 ID** | 변경된 리소스의 유형과 ID입니다. |

검색하려면 **적용**을 선택하고, 필터를 지우려면 **초기화**를 선택합니다. 행을 선택하면 이벤트 전체를 확인하고
**ID 복사**를 사용할 수 있습니다. Mole Agent 채팅 이벤트에는 해당 채팅의 기록이 표시됩니다. 페이지 상단에는
기록의 보관 기간이 표시됩니다. **보관 기간 변경**을 선택하면 `_sys`의 플랫폼 설정이 열립니다.

감사 기록에는 자격 증명, 모델 키, 민감한 웹훅 헤더, 서명에 사용하는 자료가
포함되지 않습니다. [감사](/ko/security#감사)를 참조합니다.

### 감사 스트림

모든 감사 이벤트는 워크스페이스의 `_audit` 로그 스트림에도 행으로 기록되므로
**로그**에서 검색하거나
[예약 파이프라인](/ko/pipelines#플랫폼-스트림)으로 SIEM 등의 외부 대상으로 전송할 수 있습니다. 각 행에서 이 페이지의 기록과 동일한 방식으로 민감한 정보를
제거하며, 행의 타임스탬프에는 이벤트 발생 시간을 사용합니다.

| 필드 | 내용 |
|---|---|
| `audit_id` | **ID 복사**로 복사하는 이벤트 ID입니다. |
| `actor_kind`, `actor_id` | 동작을 수행한 주체입니다. |
| `action` | 동작 키입니다. |
| `target_kind`, `target_id` | 이벤트에 변경된 리소스가 있는 경우 해당 리소스입니다. |
| `ip`, `user_agent` | 이벤트에 기록된 경우 요청의 출처입니다. |
| `payload` | 이벤트에 세부 정보가 있는 경우 해당 정보입니다. |

이 페이지와 [감사 API](/ko/api/admin/audit)는 감사 원본 기록을 읽습니다. 각 노드는
백그라운드에서 행을 일괄 기록하고, 대기열에 이벤트를 최대 4,096개까지 보관합니다. 대기열이
가득 차면 스트림에는 해당 행을 기록하지 않지만 원본 기록은 유지합니다. 다른 스트림의 행과 마찬가지로
이 행에도 해당 스트림의 보관 기간이 적용됩니다.

이 페이지와 마찬가지로 `_audit`를 읽으려면 `audit.read`가 필요합니다.

- 이 권한이 없으면 스트림 목록에 해당 스트림이 표시되지 않으며 스트림을 열거나 변경하거나 삭제할 수 없습니다.
  스트림을 쿼리하면 `403`을 반환합니다. 이 제한은 제품 내 쿼리, NDJSON 스트리밍을 사용하는 쿼리 API,
  Flight SQL, 연합 검색에 적용됩니다. 연합 검색에서는 원격 클러스터가 호출자의 토큰에
  `audit.read` 권한이 있는지 확인합니다.
- `_audit` 쿼리는 항상 요청을 처리하는 동안 실행합니다.
  `Prefer: respond-async`를 지정해도 검색 작업으로 전환하지 않으며, 검색 작업으로 제출하면 `400`을 반환합니다.
- 사용자 개입 없이 백그라운드에서 실행하는 기능은 저장한 사용자와 관계없이 `_audit`를 읽을 수 없습니다.
  `_audit` 스트림을 직접 읽거나 구문의 어느 부분에서든 참조하는 경보 규칙과 해당 스트림을 대상으로 하는 예약 로그 검사에는
  저장 요청 시 소유자에게도 `400`을 반환합니다. 보고서에서도 읽을 수 없습니다.
- Mole Agent 도구와 [인바운드 MCP](/ko/inbound-mcp)는 어떤 자격 증명을 사용해도
  `_audit`의 행이나 필드를 읽을 수 없습니다.

[예약 파이프라인](/ko/pipelines#플랫폼-스트림)은 한 사용자의 권한으로 `_audit`를 읽습니다.
마지막으로 저장한 사용자의 권한을 사용합니다. 일시 중지와 재개는 저장으로 간주하지 않습니다. 파이프라인 페이지 상단과
편집기의 소스에는 해당 사용자가 **\_audit 읽기 계정**으로 표시됩니다. 편집기는
`audit.read` 권한이 있고 저장할 수 있는 다른 사용자에게 다음 안내를 표시합니다. **저장하면 내 권한으로 읽습니다.**

- 변경 사항을 저장하려면 `audit.read`가 필요합니다. 서비스 계정 토큰으로 요청하면
  파이프라인 실행 시 권한을 다시 확인할 수 없으므로 `403`을 반환합니다. 개인 토큰은 발급받은
  사용자의 권한으로 처리합니다.
- 읽기를 실행할 때마다 해당 사용자가 여전히 로그인할 수 있는지, 조직에 속하는지,
  `audit.read` 권한이 있는지 확인합니다. 조건을 충족하지 않으면 읽기가 실패하고 실행 결과에 사용자와 사유가 표시됩니다. 예를 들면
  `` `_audit` is read with the access of admin@example.com, who no longer holds audit.read ``와 같이 표시됩니다.
  파이프라인은 활성 상태를 유지하고 읽기 위치도 그대로 유지하므로 이벤트를 건너뛰지 않습니다.
- 해당 사용자가 `audit.read` 권한을 다시 얻거나 해당 권한이 있는 다른 사용자가 파이프라인을 저장하면 이전 읽기 위치에서 이어서 실행합니다.
  권한이 있는 사용자는 변경 없이 저장해도 됩니다. `audit.read` 없이 또는
  서비스 계정 토큰으로 변경 없이 저장하면 아무것도 바뀌지 않으며 오류도 반환하지 않습니다.
- 일시 중지와 재개에는 `pipelines.pause` 권한만 필요하며, 파이프라인이 읽을 때 사용하는
  사용자의 권한은 바뀌지 않습니다. 다른 파이프라인과 마찬가지로 재개하면 [처음부터 시작합니다](/ko/pipelines#일정-및-읽기-위치). 따라서
  읽기 위치를 유지하려면 파이프라인을 활성 상태로 둡니다.
- 백필은 제출한 사용자의 권한으로 읽습니다. 제출할 때 해당 사용자에게 `audit.read`가 필요하며,
  작업 실행 시에도 이 권한을 다시 확인합니다.

파이프라인이 복사한 행은 대상의 일반 행과 동일하게 취급하며,
대상을 읽을 권한이 있는 사용자는 복사된 행도 읽을 수 있습니다.
