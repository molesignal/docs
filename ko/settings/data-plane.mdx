**노드 / 원격 클러스터**는 인스턴스 전체에 적용되므로 `_sys`
조직의 **설정**에 표시됩니다. 원격 클러스터에는 `sys.clusters.read`와 `sys.clusters.manage` 권한이 필요하며, 서비스
데이터 소스와 페더레이션에는 `sys.settings.topology.read`와 `sys.settings.topology.manage` 권한이 필요합니다.
**AI 및 ML**의 **쿼리 관리**는 워크스페이스에 적용됩니다. 쿼리를 조회하려면
`org.running_queries.read` 권한이, 다른 사용자의 쿼리를 취소하려면 `org.running_queries.cancel` 권한이 필요합니다.

## 노드 및 원격 클러스터

**설정 → 노드 / 원격 클러스터**를 엽니다.

### 서비스 데이터 소스

**저장된 데이터로 재계산(다중 노드)** 설정은 트레이스에서 [서비스 맵](/ko/apm/service-map)을
생성하는 방식을 결정합니다.

| 설정 | 동작 방식 | 장단점 |
|---|---|---|
| 켜기 | 노드 하나가 저장된 트레이스에서 주기적으로 서비스 맵을 다시 생성합니다. | 여러 노드에 걸친 호출도 정확히 집계하지만, 반영까지 약 1~2분이 걸립니다. |
| 끄기 | 각 수집 프로세스가 메모리에서 스팬을 짝짓고 결과를 내보냅니다. | 지연은 짧지만, 같은 호출의 스팬이 서로 다른 수집 노드에 도착하면 호출 수가 실제보다 적게 집계될 수 있습니다. |

수집 노드가 여러 개인 배포 환경에서는 이 설정을 켭니다.

### 클러스터 페더레이션

페더레이션은 클러스터 간 리소스 변경 사항을 동기화합니다. `cluster-eu-west`처럼 페더레이션 내에서 고유하고
재시작 후에도 바뀌지 않는 **클러스터 ID**를 입력한 다음
**변경 사항 저장**을 선택합니다. 클러스터 ID를 비우고 확인하면 페더레이션이 꺼집니다. 페더레이션을 중지해도 로컬 데이터에는
영향이 없습니다.

**고급 매개변수**에서 클러스터 간 데이터 교환을 조정합니다. **아웃박스 푸시 간격 (s)**, **푸시 배치 크기**,
**중복 제거 기간 (s)**, **가십 간격 (s)**을 설정할 수 있습니다.

### 원격 클러스터

원격 클러스터는 [페더레이션 쿼리](/ko/deployment/role-based#페더레이션-쿼리)의 대상입니다.

1. **클러스터 추가**를 선택합니다.
2. 원격 클러스터의 **이름**과 **광고 주소**를 입력합니다. 주소의 예는 다음과 같습니다.
   `https://cluster.example.com`.
3. **토큰 시크릿 참조**에 `env:VAR` 또는 `cipher_keys:<id>`와 같은 참조를 입력합니다. 토큰 자체는
   입력하지 않습니다. 목록에는 `***`로 표시합니다.
4. 원격 클러스터가 현재 클러스터에서 검증할 수 없는 비공개 인증서를 사용하지 않는 한
   **TLS 인증서 검증**을 켜 둡니다.
5. **클러스터 추가**를 선택합니다.

각 행에서 두 가지 추가 작업을 선택할 수 있습니다.

| 작업 | 표시 내용 |
|---|---|
| **노드** | 원격 클러스터의 노드와 각 노드의 역할 및 버전을 표시합니다. 연결할 수 없으면 오류를 표시합니다. |
| **조직 매핑** | 원격 조직과 로컬 조직 간의 매핑을 표시합니다. 매핑되지 않은 조직의 구성은 거부합니다. 매핑마다 별도의 **조직별 토큰 참조**를 지정할 수 있습니다. 지정하지 않으면 클러스터 토큰을 사용합니다. |

클러스터를 제거하면 해당 클러스터로 페더레이션 쿼리를 보내지 않습니다.

## 쿼리 관리

**설정 → 쿼리 관리**에서는 워크스페이스에서 현재 실행 중인 쿼리의 ID,
사용자, 시작 시간, 쿼리 문을 표시합니다. 목록은 3초마다 새로 고칩니다. **취소**를 선택하면
쿼리가 중지됩니다. 백그라운드에서 실행하는 검색 작업은
[스트림 → 검색 작업](/ko/streams#검색-작업)에서 관리합니다.

| 작업 | 엔드포인트 | 권한 |
|---|---|---|
| 실행 중인 쿼리 목록 조회 | `GET /api/v1/query/running` | `sys.clusters.read` |
| 쿼리 취소 | `POST /api/v1/query/{id}/cancel` | `sys.clusters.manage` |
