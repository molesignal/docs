MoleSignal은 단일 바이너리와 단일 컨테이너 이미지로 제공됩니다. 설정에서 프로세스가 수행할 [역할](/ko/deployment/role-based)을 선택합니다. 한 프로세스에서 모든 역할을 수행하거나 여러 프로세스에 역할을 나눌 수 있습니다. 모든 배포에는 PostgreSQL과 오브젝트 스토리지, 두 가지 외부 서비스가 필요합니다.

## 요구 사항

| 구성 요소 | 요구 사항 |
|---|---|
| PostgreSQL | 메타데이터, ID 정보, 파일 카탈로그, 제품 리소스를 저장합니다. 지원하는 메타데이터 데이터베이스는 PostgreSQL뿐입니다. Compose 샌드박스와 Kubernetes 매니페스트는 PostgreSQL 17을 사용합니다. |
| 오브젝트 스토리지 | Parquet 파일, 검색 인덱스, 프로필 Blob을 저장합니다. `s3`(AWS S3 또는 RustFS, Cloudflare R2, Alibaba Cloud OSS와 같은 S3 호환 서비스), `azure`, `gcs` 중 하나를 사용합니다. `local` 백엔드는 단일 노드 환경과 개발용입니다. |
| 컴퓨팅 | x86-64 또는 arm64 기반 Linux에서 컨테이너 이미지(`linux/amd64` 및 `linux/arm64`)를 사용합니다. 샌드박스에는 약 2 GB의 메모리가 필요합니다. |
| 로컬 디스크 | 다시 생성할 수 있는 캐시만 저장합니다. 선행 기록 로그(WAL) 객체를 오브젝트 스토리지에 저장한 뒤 쓰기 완료를 응답하므로 어느 노드에도 영구 볼륨이 필요하지 않습니다. [내구성과 역할 인계](/ko/architecture#내구성-및-인계)를 참조합니다. |

메모리와 디스크 사용량은 수집량, 활성 스트림 수, [설정](/ko/configuration)의 캐시 설정에 따라 달라집니다. 실제 사용량을 기준으로 리소스 용량을 산정합니다. [수집 사용량](/ko/streams#데이터-수집-사용량-및-예산)에서 소스별 수집량을 확인할 수 있으며, 프로세스는 `/metrics`에서 Prometheus 메트릭을 노출합니다. [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다.

## 컨테이너 이미지

이미지는 `ghcr.io/molesignal/molesignal`로 게시됩니다. 각 릴리스에는 버전 태그(예: `26.1.0.0`)와 채널 태그(예: `alpha`)가 함께 게시됩니다. 프로덕션에서는 버전 태그를 고정합니다.

```bash
docker pull ghcr.io/molesignal/molesignal:26.1.0.0
```

모든 역할에 동일한 이미지를 사용합니다. 런타임 변수 `RELEASE_CHANNEL`(`alpha`, `beta`, `rc`, `stable` 중 하나)은 배포의 안정화 단계를 나타내며 바이너리를 변경하지 않습니다. 웹 UI는 바이너리에 내장되어 있으며 HTTP 포트에서 제공됩니다.

## 배포 옵션

<Tabs>
  <Tab title="Docker Compose">
    리포지토리에서 제공하는 `deploy/docker/docker-compose.yaml`에는 두 가지 프로필이 있습니다. 두 프로필 모두 PostgreSQL 17과 RustFS를 시작하고 `ghcr.io/molesignal/molesignal`의 MoleSignal 이미지를 실행합니다.

    ```bash
    # Everything in one process: serves the complete product
    docker compose -f deploy/docker/docker-compose.yaml --profile standalone up

    # One container per role
    docker compose -f deploy/docker/docker-compose.yaml --profile multirole up
    ```

    `multirole` 프로필은 역할마다 컨테이너를 하나씩 배포합니다. 라우터는 웹 UI와 HTTP API를 `5080` 포트에, OTLP gRPC 수신기를 `4317` 포트에 공개합니다. [역할 기반 배포](/ko/deployment/role-based)를 참조합니다.

    독립 실행형 서비스는 `5080`과 `5082` 포트를 공개합니다. OTLP gRPC 포트인 `4317`은 공개하지 않습니다. 호스트에서 OTLP gRPC로 데이터를 전송하려면 서비스에 `4317:4317` 포트 매핑을 추가합니다.

    Compose 파일은 샌드박스용입니다. 기본 자격 증명과 개발용 암호화 키를 사용하며, `multirole` 프로필에는 개발용 `MS_SELF_TELEMETRY_CLUSTER_TOKEN`을 사용합니다. 실제 데이터를 저장하기 전에 이 값들을 교체합니다. [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다. 샌드박스 버킷은 비공개입니다.
  </Tab>
  <Tab title="바이너리 및 systemd">
    릴리스 바이너리, 구성 파일, GeoIP 데이터베이스를 설치한 후 MoleSignal을 systemd 서비스로 실행합니다.

    ```bash
    sudo useradd --system --home-dir /var/lib/molesignal \
      --shell /usr/sbin/nologin molesignal
    sudo install -Dm755 bin/molesignal /usr/local/bin/molesignal
    sudo install -d -o root -g molesignal -m 0750 /etc/molesignal
    sudo install -o root -g molesignal -m 0640 \
      conf/config.toml /etc/molesignal/config.toml
    sudo install -Dm644 deploy/systemd/molesignal.service \
      /etc/systemd/system/molesignal.service
    sudo install -Dm644 mmdb/dbip-city-lite.mmdb \
      /usr/share/molesignal/mmdb/dbip-city-lite.mmdb
    ```

    `/etc/molesignal/molesignal.env`에서 런타임 채널을 설정합니다:

    ```ini
    RELEASE_CHANNEL=alpha
    ```

    `/etc/molesignal/config.toml`에서 PostgreSQL, 오브젝트 스토리지, 시크릿을 구성한 후 서비스를 시작합니다:

    ```bash
    sudo systemctl daemon-reload
    sudo systemctl enable --now molesignal
    sudo systemctl status molesignal
    ```

    유닛은 `/var/lib/molesignal`을 상태 디렉터리로 사용하며, 내장 TLS 리스너가 `80` 및 `443` 포트에 바인딩할 수 있도록 `CAP_NET_BIND_SERVICE` 권한을 부여합니다.
  </Tab>
  <Tab title="Helm">
    공식 차트는 Helm 3.8 이상을 사용해 Kubernetes 1.27 이상에 MoleSignal을 배포합니다. MoleSignal 26.2.0.0 이상이 필요합니다. 차트 리포지토리는 `https://charts.molesignal.com`이며, `oci://ghcr.io/molesignal/charts/molesignal`에서도 같은 차트를 제공합니다.

    기본적으로 차트는 모든 역할을 수행하는 프로세스 하나와 PostgreSQL 17 및 RustFS 인스턴스를 각각 하나씩 실행합니다. 두 서비스 모두 백업이나 장애 조치를 제공하지 않으므로 기본 구성은 평가용으로만 사용합니다.

    ```bash
    helm repo add molesignal https://charts.molesignal.com
    helm repo update
    helm install molesignal molesignal/molesignal --namespace molesignal --create-namespace
    ```

    포트 포워딩으로 웹 UI를 노출한 후 브라우저에서 `http://127.0.0.1:5080`에 접속합니다:

    ```bash
    kubectl --namespace molesignal port-forward svc/molesignal 5080:5080
    ```

    프로덕션에서는 역할별로 별도 워크로드를 실행하고, 번들 서비스를 비활성화한 후 차트가 외부 PostgreSQL과 오브젝트 스토어를 사용하도록 구성합니다. 먼저 Secret 두 개를 생성합니다. `molesignal-db`에는 `database-dsn` 키를, `molesignal-s3`에는 `access-key`와 `secret-key`를 저장합니다.

    ```yaml
    mode: distributed

    postgresql:
      enabled: false
    externalDatabase:
      existingSecret: molesignal-db

    rustfs:
      enabled: false
    objectStore:
      bucket: example-telemetry
      region: eu-west-1
      existingSecret: molesignal-s3
    ```

    [`examples/production.yaml`](https://github.com/molesignal/molesignal-helm/blob/main/examples/production.yaml)은 TLS, 자동 스케일링, 중단 예산을 추가합니다. [차트 README](https://github.com/molesignal/molesignal-helm/tree/main/charts/molesignal)에서 모든 설정값을 확인할 수 있습니다.

    | 항목 | 세부 정보 |
    |---|---|
    | 암호화 키 | 차트는 처음 설치할 때 키를 생성하며, 업그레이드하거나 `helm uninstall`을 실행해도 키를 유지합니다. 키가 없으면 암호화된 필드를 읽을 수 없으므로 키를 백업합니다. Argo CD처럼 `helm template`으로 렌더링하는 도구를 사용하는 경우 `secrets.cipherKey`와 `secrets.clusterToken`을 설정하거나 `secrets.existingSecret`이 Secret을 참조하도록 설정합니다. |
    | 이미지 | PostgreSQL을 제외한 모든 이미지는 `latest` 태그를 사용하며, 파드가 시작할 때마다 이미지를 가져옵니다. 프로덕션에서는 `image.tag`를 특정 버전으로 고정하고 `image.pullPolicy`를 `IfNotPresent`로 설정합니다. |
    | Ingress | `ingress.enabled`를 설정합니다. Ingress 뒤에서 실행할 때는 [클라이언트 IP 인식](/ko/settings/platform#클라이언트-ip-식별)에서 컨트롤러 파드의 네트워크를 신뢰할 수 있는 프록시로 등록합니다. |
    | 애플리케이션 설정 | `conf/config.toml`과 동일한 구조로 `config` 아래에 설정을 추가합니다. |

    기본 설치에서 생성한 암호화 키를 조회합니다:

    ```bash
    kubectl --namespace molesignal get secret molesignal-secret -o jsonpath='{.data.cipher-key}' | base64 --decode
    ```
  </Tab>
  <Tab title="Kubernetes 매니페스트">
    [`deploy/k8s/`](https://github.com/molesignal/molesignal/tree/main/deploy/k8s)의 매니페스트는 모든 역할에 같은 이미지를 사용합니다. 매니페스트는 자리 표시자 이미지인 `molesignal:dev`를 참조합니다. 모든 워크로드에서 이 이미지를 `ghcr.io/molesignal/molesignal:<version>`으로 교체합니다.

    매니페스트에는 PostgreSQL이나 오브젝트 스토리지가 포함되어 있지 않습니다. PostgreSQL 17을 `postgresql` 서비스 이름으로 제공하거나 ConfigMap의 `meta_database.dsn`을 수정합니다. S3 호환 오브젝트 스토어도 제공하고 ConfigMap의 `object_store`를 수정합니다.

    매니페스트는 역할 분리형 토폴로지를 배포합니다. `router` 워크로드는 웹 UI와 HTTP API를 제공하고, 나머지 워크로드는 데이터 처리와 백그라운드 역할을 수행합니다. 대신 단일 프로세스에서 모든 역할을 실행하려면 영구 볼륨이 없는 Deployment인 `40-intake.yaml`을 사용합니다. `MS_NODE_ROLES`를 `["standalone"]`으로 설정하고, Service에 `5080` 포트를 추가한 후 `/api/v1/healthz`를 프로브 대상으로 지정합니다.

    | 워크로드 | 종류 | 복제본 수 | 역할 |
    |---|---|---|---|
    | `router` | Deployment | 2 | `router`: 웹 UI, HTTP API, OTLP gRPC |
    | `intake` | Deployment | 2 | `intake`: 영구 볼륨 없이 실행하며, 롤링 업데이트 시 기존 파드를 중지하기 전에 새 파드를 시작합니다 |
    | `querier` | Deployment | 2 | `querier` |
    | `compactor` | Deployment | 1 | `compactor`: 복제본을 추가할 수 있습니다 |
    | `alert` | Deployment | 1 | `alert`: 복제본을 추가할 수 있습니다 |

    역할 분리형 노드는 공유 `MS_SELF_TELEMETRY_CLUSTER_TOKEN`을 사용해 서로 전달하는 트레이스 후보와 자체 텔레메트리를 인증합니다. 트레이스 캡처는 기본적으로 활성화되어 있으므로 모든 워크로드는 `molesignal-secret`의 `self_telemetry_cluster_token` 키에서 동일한 값을 읽습니다. 네임스페이스, 구성, 시크릿을 생성한 후 워크로드를 적용합니다:

    ```bash
    kubectl apply -f 00-namespace.yaml
    kubectl apply -f 10-configmap.yaml
    kubectl create secret generic molesignal-secret -n molesignal \
      --from-literal=object_store_access_key="<access-key>" \
      --from-literal=object_store_secret_key="<secret-key>" \
      --from-literal=cipher_key="$(openssl rand -base64 32)" \
      --from-literal=self_telemetry_cluster_token="$(openssl rand -base64 32)" \
      --dry-run=client -o yaml | kubectl apply -f -
    kubectl apply -f 30-router.yaml -f 40-intake.yaml -f 50-querier.yaml \
                  -f 60-compactor.yaml -f 70-alert.yaml
    ```

    워크로드는 `MS_NODE_ROLES` 환경 변수로 역할을 선택합니다. 라우터를 통해 클러스터 상태를 확인합니다:

    ```bash
    kubectl -n molesignal port-forward svc/router 5080:5080
    curl http://127.0.0.1:5080/api/v1/healthz
    ```

    웹 UI는 바이너리에 내장되어 있습니다. Ingress 또는 로드 밸런서를 통해 `router` 워크로드의 `5080` 포트를 노출합니다.

    `router` 워크로드는 `5080` 포트에서 전체 API를 제공하며, 준비 상태 프로브는 `GET /api/v1/healthz`를 요청합니다. 나머지 워크로드는 `5080` 포트에서 상태, 준비 상태, 메트릭용 리스너를 실행하며, 준비 상태 프로브로 `GET /api/v1/readyz`를 사용합니다. `intake` 파드는 준비 상태가 되면 즉시 쓰기 요청을 받습니다. 유실된 파드의 WAL은 다른 `intake` 파드가 인계받으므로 시작할 때 WAL을 재생하지 않습니다. 종료 유예 기간은 45초이며, 이 시간 동안 파드는 종료 전에 WAL을 플러시하고 해제합니다.
  </Tab>
</Tabs>

역할, 스케일링, 고가용성에 대한 자세한 내용은 [역할 기반 배포](/ko/deployment/role-based)를 참조합니다.

## 프로브 에이전트

프로브 에이전트는 사설 네트워크, 리전 또는 엣지 로케이션에서 신세틱 검사를 실행합니다. `standalone` 또는 `alert` 노드의 `5084` 및 `5085` 포트로만 아웃바운드 연결을 엽니다. 전용 이미지 `ghcr.io/molesignal/probe-agent`는 MoleSignal 이미지와 동일한 태그로 릴리스됩니다.

| 실행 환경 | 설치 방법 | ID 저장 위치 |
|---|---|---|
| Kubernetes | `https://charts.molesignal.com` 또는 `oci://ghcr.io/molesignal/charts/probe-agent`에서 제공하는 Helm 차트 `probe-agent` | 복제본별 영구 볼륨 |
| Docker | 이미지 `ghcr.io/molesignal/probe-agent` | `/var/lib/molesignal-probe`에 마운트한 볼륨 |
| Linux | 릴리스 바이너리 `probe-agent` | `--state-dir`로 지정한 디렉터리 |

차트는 [Kubernetes에서 에이전트 실행](/ko/synthetics#kubernetes에서-에이전트-실행)을, 등록과 서버 설정은 [로케이션 및 프로브 에이전트](/ko/synthetics#위치-및-probe-에이전트)를 참조합니다.

## 포트

| 포트 | 용도 | 공개 범위 |
|---|---|---|
| `5080` | 웹 UI, HTTP API, `/metrics`, 상태 확인 엔드포인트입니다. `router`와 `standalone`을 제외한 모든 역할에서는 상태 확인, 준비 상태 확인, 메트릭만 제공합니다. | `router`와 `standalone`에서는 TLS로 보호하여 공개합니다. 다른 역할에서는 비공개입니다. |
| `4317` | OTLP gRPC 수신기입니다. TLS 없이 gRPC를 사용합니다. | TLS를 종료하는 프록시 뒤에서만 공개하거나 신뢰할 수 있는 네트워크 내부에서만 사용합니다. |
| `5082` | 노드 간 트래픽을 처리하는 내부 gRPC입니다. 쓰기 및 쿼리를 전달하고 샤드를 스캔합니다. | 비공개입니다. 절대 공개하지 마세요. |
| `5083` | 데이터베이스 클라이언트용 Arrow Flight SQL입니다. 기본적으로 비활성화되어 있습니다. | 필요한 경우에만 TLS로 보호하여 공개합니다. |
| `5084`, `5085` | 신세틱 모니터링의 프라이빗 위치에서 Probe Agent를 등록하고 제어합니다. | Probe Agent가 노드 외부에서 실행될 때만 공개합니다. |
| `80`, `443` | `[http.tls].enabled`가 `true`이면 자동 인증서를 사용하는 내장 TLS 리스너를 실행합니다. | 공개합니다. |

## 상태 확인 및 메트릭

- `GET /api/v1/healthz`는 공개 엔드포인트입니다. `{"status":"ok"}`와 함께 `200`을 반환합니다. 오브젝트 스토어에 연결할 수 없으면 `reason`과 함께 `503`을 반환합니다. 컨테이너 및 로드 밸런서의 상태 확인에 사용하세요.
- `GET /metrics`는 공개 엔드포인트이며 Prometheus 메트릭을 반환합니다. 프록시 또는 네트워크 계층에서 접근을 제한하세요.
- `standalone` 또는 `router` 노드에서 `GET /api/v1/readyz`와 `GET /api/v1/version`을 호출하려면 Bearer 토큰이 필요합니다. `version`은 버전, 커밋, 빌드 ID, 릴리스 채널, 에디션을 반환합니다.
- 역할을 분리한 클러스터에서 전체 API를 제공하지 않는 노드는 동일한 포트에서 `GET /api/v1/healthz`, `GET /api/v1/readyz`, `GET /metrics`에 인증 없이 응답합니다.

서비스 자체의 메트릭과 내장 텔레메트리는 [자체 옵저버빌리티](/ko/self-observability)를 참조하세요.
