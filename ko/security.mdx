MoleSignal은 웹 탐색 계층이 아닌 API와 데이터 플레인에서 테넌트와
권한을 제어합니다.

## 테넌트 격리

조직의 모든 스트림과 제품 리소스에는 소유 조직을 나타내는 `org_id`가 있습니다. 쿼리 계획 단계에서
실행 전에 권한이 있는 조직으로 범위를 제한합니다. 리소스 핸들러도 대상을 불러온 뒤
조회하거나 변경하기 전에 소속 조직을 확인합니다.

다른 워크스페이스에 액세스하려면 IAM에서 명시적으로 권한을 부여하거나 지원되는 리소스 공유 기능을 사용해야 합니다. 조회한
리소스의 소속 조직이 일치하지 않아도 조직을 자동으로 전환하지 않습니다.

`_sys` 조직은 보호된 플랫폼 범위입니다. 테넌트 세션이나 `mspat-*` API 토큰으로는
플랫폼 관리자나 MoleSignal 자체 텔레메트리의 목록을 조회할 수 없습니다.

## 인증 및 권한 부여

MoleSignal은 다음 인증 수단을 지원합니다.

- HttpOnly 쿠키에 저장하는 브라우저 세션. 워크스페이스를 전환하면 새 범위에 맞게 쿠키를 갱신합니다.
- `Authorization` 헤더에 포함하는 `mspat-<36>` 형식의 API 토큰.
- 범위가 제한된 공개 또는 연동 경로 전용으로, 토큰만으로 인증하는 토큰.

비밀번호로 로그인하거나 관리자가 **ID 및 액세스 → SSO 공급자**에서 구성한 OIDC, OAuth 2.0, SAML 또는 LDAP 공급자를 통해 로그인합니다.

API 토큰의 접두사는 조회를 위해 저장하고, 비밀값은 해시로 저장합니다. 전체 토큰은
생성할 때만 표시합니다.

인증 후 서버는 데이터베이스를 기반으로 권한, 역할, 바인딩, 리소스
관계, 대상의 소유권을 확인합니다. [ID 및 액세스](/ko/identity)를 참조합니다.

## 브라우저 세션

로그인하면 쿠키 두 개를 설정합니다. 액세스 토큰은 모든 API 요청에 포함되며 15분 동안 유효합니다.
갱신 토큰은 `[auth].session_ttl_secs`가 지나 세션이 끝날 때까지 액세스 토큰을 갱신합니다. 두 쿠키에는
`HttpOnly`를 설정해 페이지 스크립트에서 읽지 못하게 하고, `SameSite=Strict`를 적용하며, HTTPS에서는 `Secure`를 설정합니다.
세션을 사용해 데이터를 변경하는 요청은 MoleSignal 페이지에서 시작해야 합니다. 브라우저는 요청 출처를
`Sec-Fetch-Site`로 표시합니다. 다른 오리진에서 API를 호출할 때는 인증 정보를 전송하지 않습니다.

서버는 세션 레코드를 저장하지 않습니다. 두 토큰 모두 서명된 JWT입니다. 로그아웃하면 해당 브라우저의
쿠키가 삭제되지만, 브라우저에서 복사한 토큰은 만료될 때까지 유효합니다. 액세스를 즉시 차단하려면
계정을 비활성화합니다. 서버는 모든 요청과 토큰 갱신 시 계정 상태를 확인합니다. 서명 키를
교체하면 24시간의 유예 기간이 지난 뒤 모든 세션이 종료됩니다.

## JWT 서명 키

처음 시작할 때 JWT 서명 키를 생성해 데이터베이스에 저장합니다. 메타데이터 엔드포인트는
원본 키 바이트를 반환하지 않습니다. 키를 교체하면 새 키로 새 토큰에 서명하며, 이전 키로 서명한 토큰은 24시간 동안 유효합니다.
모든 노드는 재시작 없이 새 키를 적용합니다.

서명 키 목록을 조회하거나 키를 교체하려면 플랫폼 권한 `sys.signing_keys.rotate`가 필요합니다.

```text
GET  /api/v1/auth/jwt/secrets
POST /api/v1/auth/jwt/rotate
```

배포 정책에서 고정된 초기 키를 요구하는 경우에만 `MS_AUTH_JWT_SECRET_OVERRIDE`를 사용합니다.

## 감사

보안 관련 작업과 제품 리소스를 변경하는 작업은 수행 주체, 조직, 작업, 대상, 시각,
안전한 메타데이터를 기록합니다. `audit.read` 권한으로 **설정 → 감사**에서 조직 이벤트를 조회합니다. 같은 이벤트는
`_audit` 스트림에도 행으로 저장됩니다. [감사 스트림](/ko/settings/data-security#감사-스트림)을 참조합니다.

감사 기록의 기본 보존 기간은 90일입니다. 하루에 한 번 보존 기간이 지난 기록을
모든 조직과 플랫폼에서 삭제하며, 삭제된 기록은 복구할 수 없습니다. 보존 기간은
`_sys` 조직의 **설정 → 감사 기록 보존**에서 설정합니다. 이 작업에는
`sys.settings.retention.manage` 권한이 필요하며, `0`으로 설정하면 기록을 영구 보존합니다. 보존 기간을 변경할 때마다
플랫폼 감사에 `audit_retention.update`로 기록합니다.

인증 정보, 모델 키, 민감한 웹훅 헤더, 원본 서명 키 자료는
감사 페이로드에 포함하지 않습니다.

## 리소스 공유

공개 대시보드 및 보고서 링크는 소지만으로 액세스할 수 있는 인증 수단이지만, 공개 링크가 조직
토큰으로 바뀌지는 않습니다. MoleSignal은 링크를 수명이 짧은 HttpOnly 공유 세션으로 교환하고, 액세스 범위를
저장된 리소스 하나로 제한합니다.

공개 대시보드 패널은 제한된 프록시를 통해 서버에 저장된 쿼리만 실행할 수 있습니다. 공유에는
만료 기한, 비밀번호, 최대 조회 횟수, 다운로드 차단을 설정할 수 있으며, 공유 링크를 취소하거나
교체할 수도 있습니다. [리소스 공유](/ko/resource-sharing)를 참조합니다.

## 필드 수준 암호화

스트림을 생성할 때 암호화할 필드를 지정합니다. MoleSignal은 값을 Parquet에 저장하기 전에
AES-256-GCM으로 암호화하며, 복호화하지 않고 쿼리하면 암호문을 반환합니다. SQL에서는
`decrypt(field)`로 평문을 복원합니다. [스트림](/ko/streams#암호화된-필드)을 참조합니다.

MoleSignal은 `MS_CIPHER_KEY`에서 가져온 암호화 루트 키로 조직 데이터 키를 래핑하며, 생성 이후에는
키 자료를 반환하지 않습니다. 키 메타데이터를 조회하려면 `org.cipher_keys.read` 권한이 필요합니다. 키를 생성하거나
교체하거나 삭제하려면 `org.cipher_keys.manage` 권한이 필요합니다.

<Warning>
  `MS_CIPHER_KEY`를 분실하면 암호화된 필드를 복구하지 못할 수 있습니다. 키는 시크릿 관리자에 저장하고
  PostgreSQL 및 오브젝트 스토리지와 별도로 백업합니다.
</Warning>

## 시크릿 및 텔레메트리 보안 관리

- 데이터베이스, 오브젝트 스토리지, SMTP, SSO, 모델 공급자, 웹훅 인증 정보는
  시크릿 관리자에 저장합니다.
- 외부로 트레이스를 내보낼 때 사용하는 민감한 헤더에는 `env:` 또는 `secret:` 참조를 사용합니다.
- 내부 gRPC 포트 `5082`는 클러스터 프로토콜에도 사용하므로 신뢰할 수 있는 네트워크에서만 열어 둡니다.
- 외부 HTTP, OTLP gRPC `4317`, Flight SQL `5083` 앞단에서 TLS를 적용합니다.
- 원격 진단에 별도의 보호 조치를 적용하지 않았다면 pprof 리스너를 루프백에만 바인딩합니다.
- 백엔드 트레이싱에는 요청 본문, SQL 값, 인증 정보, 프롬프트, 모델 출력,
  도구 인수를 포함하지 않습니다.

## 요청 속도 및 크기 제한

`router` 역할은 수집 및 쿼리 요청에 조직별 토큰 버킷을 적용하고, 한도를 초과하면
`Retry-After` 헤더와 함께 `429`를 반환합니다. `standalone` 노드는 이 제한을 적용하지 않습니다.
[역할 기반 배포](/ko/deployment/role-based#요청-속도-제한)를 참조합니다. 수집 요청 본문이
2 MiB를 초과하거나 네이티브 JSON 수집에서 16 MiB를 초과하면 `413`을 반환합니다.

비밀번호 로그인 실패 횟수는 계정별로, 또 요청 출발지 주소별로 집계합니다. 한도에 도달하면
`Retry-After` 헤더와 함께 `429`를 반환하고 더 이상 비밀번호를 확인하지 않습니다. 잠금은 요청을 보낸 주소에만 적용합니다.
계정 자체에는 요청 속도만 제한하므로, 잘못된 비밀번호를 반복 입력해 다른 계정을 잠글 수는 없습니다.
존재하지 않는 계정에도 동일한 집계 및 응답 방식을 적용합니다.
[로그인 제한](/ko/settings/platform#로그인-제한)을 참조합니다.

## 프로덕션 보안 강화

실제 데이터를 수집하기 전에 샌드박스 기본값을 교체합니다. 루트 계정, `MS_CIPHER_KEY`, 데이터베이스
및 오브젝트 스토리지 인증 정보가 이에 해당합니다.
[프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다. 내부 네트워크에서는 외부
콜백과 공개 페이지만 인터넷에 노출합니다. [공개 액세스](/ko/public-access)를 참조합니다.
