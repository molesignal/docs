MoleSignal은 버전이 지정된 HTTP API를 제공합니다. 제품 엔드포인트는 `/api/v1`을 사용합니다. 상태 확인 프로브, Prometheus 메트릭, 공개 공유 링크, 일부 호환 프로토콜은 다른 경로를 사용합니다.

## 기본 URL

로컬 인스턴스의 경우:

```text
http://localhost:5080/api/v1
```

프로덕션 환경에서는 호스트를 배포의 공개 주소로 바꾸세요. 이 값은 `[http].external_url`입니다.

## 인증

보호된 엔드포인트는 `Authorization` 헤더에 베어러 토큰을 받습니다:

```http
Authorization: Bearer <token>
```

| 토큰 | 발급 방법 | 유효 기간 |
|---|---|---|
| API 토큰 | **계정 설정 → API 토큰** 또는 [API 토큰 발급](/ko/api/auth/issue-token). 토큰은 `mspat-<36>` 형식입니다. | 해지할 때까지 또는 선택한 만료 시점까지. |
| 기본 수집 토큰 | `GET /api/v1/me/api-tokens/default`. `logs.write`, `metrics.write`, `traces.write`, `profiles.write`, `apm.deploy`로 제한됩니다. | 만료되지 않습니다. |
| RUM 클라이언트 토큰 | `GET /api/v1/auth/tokens/rum?applicationId=<id>`. `rum.write`로 제한됩니다. | 만료되지 않습니다. |

스크립트와 수집기에는 API 토큰을 사용하세요. 수집 토큰은 [데이터 소스](/ko/intake#수집-토큰)를 참고하세요.

웹 UI는 `POST /api/v1/auth/signin`으로 로그인하며, 이 엔드포인트는 토큰을 반환하는 대신 세션 쿠키를 설정합니다. `Authorization` 헤더는 세션 토큰을 받지 않습니다. [로그인](/ko/api/auth/login)을 참고하세요.

인증은 주체, 활성 조직 또는 플랫폼 범위, 유효 권한으로 IAM 컨텍스트를 구성합니다. 요청의 조직은 항상 이 컨텍스트에서 결정됩니다. 요청 본문으로 다른 조직을 선택할 수 없습니다.

## 공개 경로 및 자체 인증 경로

일부 경로는 조직 베어러 토큰을 사용할 수 없습니다. 대신 더 좁은 범위의 자격 증명이나 정책을 검증합니다:

- 로그인, 가입 정책, 비밀번호 재설정;
- `GET /api/v1/healthz` 및 최상위 `/metrics`;
- 공개 리소스 공유 교환 및 공유 세션 요청;
- 서명된 파일 다운로드 및 공개 아바타;
- 푸시 토큰을 검증하는 푸시 커넥터 엔드포인트.

공개 경로라고 해서 제한이 없는 것은 아닙니다. 해당 핸들러는 가입 정책, 공유 토큰, 다운로드 토큰, 서명 또는 커넥터 자격 증명을 확인합니다.

## 인가

엔드포인트는 다음 조건 중 하나 이상을 요구할 수 있습니다:

- `streams.query`와 같은 조직 권한;
- `sys.telemetry.read`와 같은 플랫폼 권한;
- 리소스 소유권, 리소스와의 관계 또는 조직 간 부여.

`GET /api/v1/iam/capabilities`는 현재 주체의 유효 권한을 반환합니다. 역할 이름이나 화면에 보이는 메뉴 항목으로 접근 권한을 추론하지 마세요.

## 요청

- 대부분의 본문은 `Content-Type: application/json`인 JSON입니다.
- 호환 수집 엔드포인트는 Protobuf, NDJSON 또는 gzip으로 압축된 본문 등 해당 프로토콜의 페이로드를 사용합니다.
- 수집 요청 본문이 2 MiB(네이티브 JSON 수집의 경우 16 MiB)를 초과하면 `413`으로 거부됩니다.
- 시각은 Unix 에포크 이후의 마이크로초 정수입니다. 특정 시점은 발생한 일을 따라 이름이 붙고(`createdAt`, `expiresAt`), 한 단어만으로 명확하지 않을 때 `Time`을 덧붙입니다(`startTime`). 기간은 이름이 이미 기간임을 나타내지 않는 한 `Time`으로 끝납니다(`p95Time`, 단 `duration`은 예외). 네이티브 텔레메트리 레코드는 `_timestamp`를 사용하며, 이 역시 마이크로초 단위입니다.
- 경로 ID와 스트림 이름은 URL 인코딩하세요.

## 응답 및 오류

성공 응답은 엔드포인트가 파일을 스트리밍하거나 다운로드하지 않는 한 JSON입니다. 오류 응답은 상태 코드와 함께 기계가 읽을 수 있는 `error` 코드와 `message`를 담은 JSON 본문을 가집니다:

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

`validation_failed` 오류에는 잘못된 필드마다 하나의 항목을 담은 `issues` 배열이 추가됩니다.

| 상태 | `error` | 의미 |
|---|---|---|
| `400` | `invalid_argument`, `validation_failed` | 요청 또는 요청 매개변수가 유효하지 않습니다. |
| `401` | `unauthorized` | 토큰이 없거나 형식이 잘못되었거나 유효하지 않거나 만료되었습니다. |
| `403` | `forbidden` | 권한, 관계 또는 범위가 없습니다. |
| `404` | `not_found` | 리소스가 존재하지 않거나 인가된 범위에서 보이지 않습니다. |
| `409` | `conflict` | 상태 충돌 또는 고유성 충돌입니다. |
| `413` | `payload_too_large` | 본문이 제한을 초과했습니다. |
| `429` | `resource_exhausted` | 속도 제한이 적용됩니다. `Retry-After` 헤더가 있으면 따르세요. |
| `499` | `cancelled` | 요청이 취소되었습니다. |
| `503` | `unavailable` | 의존성을 사용할 수 없습니다. |
| `500` | `internal` | 내부 오류입니다. 본문에는 `internal error` 메시지가 담기고 세부 정보는 서버 로그에 남습니다. |

본문을 파싱할 수 없는 요청은 엔드포인트에 도달하기 전에 실패합니다. 이 응답은 JSON 대신 일반 텍스트입니다:

| 상태 | 의미 |
|---|---|
| `400` | 본문이 유효한 JSON이 아닙니다. |
| `415` | 요청에 `Content-Type: application/json`이 없습니다. |
| `422` | 필드가 없거나 유형이 잘못되었습니다. 텍스트에 해당 필드 이름이 표시됩니다. |

모든 응답에는 `X-Request-Id`와 `X-Trace-Id` 헤더가 포함됩니다. 서버 측 오류를 보고할 때 두 헤더를 모두 포함하세요.

## 페이지네이션

많은 행을 반환할 수 있는 엔드포인트는 `limit`과 `cursor`를 받습니다. 이러한 응답에는 `items`와 `nextCursor`가 포함됩니다. 다음 페이지를 읽으려면 `nextCursor`를 `cursor`로 전달하고, 비어 있으면 중단하세요. 다른 목록 엔드포인트는 전체 목록을 반환합니다. 각 엔드포인트의 페이지를 참고하세요.

## 쿼리 및 장기 실행 작업

쿼리 계열은 일반 JSON을 반환하거나 NDJSON을 스트리밍하며, 긴 쿼리는 비동기 검색 작업으로 실행합니다. 너무 큰 쿼리는 `jobId`와 `monitor` 경로와 함께 `202`를 응답합니다. 스트리밍 호출자는 부분 전달을 처리해야 하며 결과가 더 이상 필요 없으면 요청을 취소해야 합니다. [쿼리](/ko/query)를 참고하세요.

생성된 보고서, 프로파일 블롭, 내보내기 같은 큰 아티팩트는 JSON 본문 대신 범위가 지정된 다운로드 토큰을 통해 파일로 전달됩니다.
