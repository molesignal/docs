비즈니스 키는 텔레메트리를 해당 텔레메트리가 서비스한 대상과 연결합니다. 테넌트, 플랜, 사용자 등급 또는 실험 그룹 등이 여기에 해당합니다. 키를
선언하면 APM 서비스 페이지에서 키별로 요청을 분할하고, 인시던트에서는 문제가 발생한 값 목록을 표시하며,
근본 원인 분석에서는 어떤 테넌트가 실패했는지 알 수 있습니다. MoleSignal은 이를 위해 데이터를 다시 쓰지 않습니다.
애플리케이션이 텔레메트리에 키를 설정하면 서버가 선언에 지정된 필드를 읽습니다.

## 키 선언

**APM → 설정**을 열고 **비즈니스 컨텍스트** 카드를 사용합니다. 각 키에는 다음 항목이 있습니다:

| 필드 | 비고 |
|---|---|
| **키** | 링크와 Mole Agent에서 사용하는 이름입니다. 소문자, 숫자, `_`를 사용하며(예: `tenant`). |
| **레이블** | 사용자에게 표시되는 값입니다(예: `Tenant`). |
| **스팬 속성** | 이를 전달하는 트레이스 스트림의 필드입니다(예: `tenant.id`). |
| **로그 필드** | 이를 전달하는 로그 필드입니다. |
| **RUM 필드** | 포함된 JSON 필드의 키인 RUM 필드입니다(예: `context.tenant`). |
| **중요 값** | 가장 중요한 값(예: 주요 고객)을 쉼표로 구분해 입력합니다. 인시던트 영향이 표시되는 모든 곳에서 이 값에 플래그가 지정됩니다. |

키는 하나 이상의 시그널에 있는 필드를 지정하며, 최대 8개까지 사용할 수 있습니다. 카드를 관리하려면
`apm.settings.manage` 권한이 필요합니다. 동일한 선언은 [API](/ko/api/business-context)를 통해 설정할 수 있습니다.

## 텔레메트리에 키 설정

스팬 및 로그 속성은 수집 시 해당 스트림의 필드가 되므로, 속성으로 설정한 키를 기준으로
즉시 분할할 수 있습니다. 요청의 모든 스팬과 로그 레코드에 키를 설정하는 일반적인 방법은 W3C baggage입니다.
요청이 들어오는 위치에서 키를 한 번 설정하면 baggage 프로세서가 요청이 생성하는 모든 스팬(및
SDK에 해당 기능이 있는 경우 모든 로그 레코드)에 키를 복사하며, 요청이 도달하는 모든 서비스에서 이를 수행합니다.

<Warning>
baggage는 요청 헤더를 통해 타사도 포함하여 모든 다운스트림 서비스로 전달됩니다. 선언한
키만 복사하고, baggage에 비밀 정보나 개인 데이터를 절대 넣지 않습니다.
</Warning>

| 언어 | 스팬에 baggage를 복사하는 방법 |
|---|---|
| Java | OpenTelemetry Java 에이전트 또는 autoconfigure와 함께 `io.opentelemetry.contrib:opentelemetry-baggage-processor`를 사용합니다. `otel.java.experimental.span-attributes.copy-from-baggage.include=tenant.id`를 설정하고, 로그의 경우 `otel.java.experimental.log-attributes.copy-from-baggage.include`도 설정합니다. |
| Go | `go.opentelemetry.io/contrib/processors/baggagecopy`: 트레이서 프로바이더에 `baggagecopy.NewSpanProcessor(filter)`를 설정합니다. |
| Node.js | `@opentelemetry/baggage-span-processor`(`BaggageSpanProcessor`) 및 `@opentelemetry/baggage-log-record-processor`(`BaggageLogRecordProcessor`)를 사용합니다. |
| Python | `opentelemetry-processor-baggage`: 트레이서 프로바이더에 `BaggageSpanProcessor(predicate)`를 설정합니다. |
| .NET | `OpenTelemetry.Extensions`: 모든 내보내기 프로세서보다 먼저 등록되는 baggage 액티비티 프로세서입니다. |
| Ruby | `opentelemetry-processor-baggage` gem입니다. |
| PHP, Rust, Erlang/Elixir | 요청이 들어오는 위치에서 baggage의 키를 읽고 스팬 속성과 로그 속성으로 직접 설정합니다. |

각 프로세서는 복사할 키를 선택하는 조건자를 받습니다. 모든 항목을 복사하는 조건자 대신
선언한 키만 유지하는 조건자를 전달합니다. 예를 들어 Python에서는 다음과 같습니다:

```python
from opentelemetry.processor.baggage import BaggageSpanProcessor

declared = {"tenant.id", "plan"}
tracer_provider.add_span_processor(BaggageSpanProcessor(lambda key: key in declared))
```

요청이 들어오는 위치에서는 다음과 같습니다:

```python
from opentelemetry import baggage, context

token = context.attach(baggage.set_baggage("tenant.id", tenant_id))
```

RUM의 경우 브라우저 SDK의 컨텍스트에 `context.tenant`와 같이 키를 설정하고, 해당 필드를 키의
**RUM 필드**로 지정합니다.

## 키가 사용되는 위치

| 페이지 | 표시 내용 |
|---|---|
| [APM](/ko/apm) 서비스 페이지 | **비즈니스 키별 요청**: 각 값의 요청 수, 오류율, P95, 플래그가 지정된 중요 값, 트레이스 페이지에서 다른 필드로 분할할 수 있는 링크를 표시합니다. |
| [인시던트](/ko/alerting/incidents#인시던트-상세-정보) | **비즈니스 영향**: 각 키에 대해 인시던트의 트리거 시점 전후에 인시던트 서비스로의 요청이 가장 많이 실패한 값을 표시합니다. `streams.query` 또는 `sys.telemetry.read` 권한이 있는 사용자에게 표시됩니다. |
| [근본 원인 분석](/ko/alerting/incidents) | 실패한 값이 있는 각 키에 대한 **비즈니스 영향** 증거 항목입니다. |

[트레이스](/ko/traces) RED 보기는 비즈니스 키를 포함한 모든 스팬 필드로 분할하며,
**비교** 카드는 실패하거나 느린 요청을 구분하는 필드 값을 알려줍니다.
