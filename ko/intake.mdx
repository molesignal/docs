모든 시그널은 수집 API를 통해 MoleSignal에 유입됩니다. 웹 UI의 **데이터 소스** 페이지는 각 소스의 엔드포인트, 토큰, 구성 스니펫을 생성합니다. 동일한 프로토콜은 수동으로 구성할 수도 있습니다.

## 데이터 소스 페이지

소스를 온보딩하려면 **데이터 소스**를 엽니다:

1. 카탈로그를 검색하거나 **권장**, **인프라**, **클라우드**, **데이터베이스**, **메시징**, **앱 및 언어**, **보안**, **사용자 지정** 카테고리로 필터링합니다. 시그널 탭(**로그**, **메트릭**, **트레이스**, **프로필**)은 목록을 더 좁힙니다.
2. Kubernetes, Linux 호스트, AWS, OpenTelemetry SDK 또는 Web RUM과 같은 소스를 선택합니다.
3. 가이드의 세 단계를 따릅니다:
   - **엔드포인트 및 토큰**은 데이터를 보낼 위치와 인증에 사용할 토큰을 보여 줍니다. **토큰 표시**를 클릭하면 범위, 워크스페이스, 만료 정보와 함께 토큰이 표시됩니다. RUM 소스의 경우 **RUM 애플리케이션**을 먼저 선택합니다: 선택하면 해당 클라이언트 토큰이 나타납니다.
   - **소스 설정**은 실제 엔드포인트와 토큰이 미리 입력된 명령과 구성을 보여 줍니다.
   - **데이터 수신 확인**은 수신기를 확인한 다음 최근 1시간 동안 수신된 데이터를 찾습니다. **연결 확인**은 즉시 확인하며, 수치는 30초마다 새로 고쳐집니다.
4. 검증 결과를 확인합니다:
   - **데이터 수신 확인됨**: 최근 1시간 동안 데이터가 수신되었고 소스의 시그널이 정상입니다. **수신 데이터 보기**는 데이터를 열고, **파이프라인 만들기**는 해당 데이터에 대한 파이프라인을 시작합니다.
   - **수신기는 정상이지만 데이터 확인 필요**: 수신기가 응답하지만 데이터가 수신되지 않았거나 일부 시그널이 정상이 아닙니다. 배포를 확인하거나 다음 배치를 기다립니다.
   - **검증 실패**: 수신기를 확인할 수 없습니다. **가능한 원인**에는 실행 중이 아닌 수집기, 유효하지 않거나 만료된 토큰, 엔드포인트를 차단하는 네트워크 또는 프록시가 나열됩니다.

엔드포인트는 `http.external_url`이 설정된 경우 해당 값에서, 그렇지 않으면 브라우저 주소에서 가져옵니다. 역방향 프록시 뒤에서 `http.external_url`을 설정해 생성된 스니펫이 공개 주소를 가리키도록 합니다. [구성](/ko/configuration)을 참조하십시오.

## 수집 토큰

송신자는 베어러 토큰으로 인증합니다: `Authorization: Bearer <token>`. Basic 인증만 수행할 수 있는 송신자(예: 클라우드 공급자의 관리형 Prometheus 원격 쓰기 내보내기)는 `Authorization: Basic`의 비밀번호에 API 토큰을 넣고 사용자 이름은 아무 값이나 사용합니다. 다른 Basic 자격 증명은 무시되므로 자체 자격 증명을 요구하는 역방향 프록시도 계속 작동합니다. Splunk HEC 송신자는 토큰을 `Authorization: Splunk <token>`으로 전달합니다.

| 토큰 | 권한 | 생성 위치 | 용도 |
|---|---|---|---|
| 기본 수집 토큰 | `logs.write`, `metrics.write`, `traces.write`, `profiles.write` 및 `apm.deploy`만: **데이터 수집** 정책 | 데이터 소스 페이지 또는 `GET /api/v1/me/api-tokens/default` | 로그, 메트릭, 트레이스를 전송하는 수집기, 에이전트, SDK 익스포터와 [배포를 보고](/ko/apm/deployments#ci에서-배포-보고)하는 파이프라인입니다. 만료되지 않습니다. |
| RUM 클라이언트 토큰 | `rum.write`만, 애플리케이션 하나에 바인딩됨 | Web RUM 및 모바일 RUM 소스의 데이터 소스 페이지 또는 `GET /api/v1/auth/tokens/rum?applicationId=<id>` | 브라우저 및 모바일 코드. 토큰은 최종 사용자에게 표시됩니다. |
| 개인 또는 서비스 계정 토큰 | 해당 멤버 또는 서비스 계정이 수행할 수 있는 작업을 범위로 제한한 값 | **계정 설정 → API 토큰** 또는 서비스 계정의 경우 **ID 및 액세스 → API 토큰** | 자동화, 스크립트 및 MCP 클라이언트. |

지속적으로 실행되는 송신자에는 기본 수집 토큰 또는 **데이터 수집** 정책을 따르는 서비스 계정 토큰을 사용합니다. 즉시 중지하려면 **계정 설정 → API 토큰** 또는 **ID 및 액세스 → API 토큰**에서 토큰을 해지합니다. 웹 UI의 로그인 세션은 데이터를 전송할 수 없습니다: 세션은 브라우저 쿠키에 저장되며 `Authorization` 헤더는 이를 허용하지 않습니다.

**데이터 소스** 페이지는 애플리케이션 ID를 입력하면 RUM 클라이언트 토큰을 생성합니다. 애플리케이션 ID는 `A-Z`, `a-z`, `0-9`, `.`, `_`, `:`, `-`의 문자 1~128자로 구성됩니다. SDK에서 `applicationId`와 동일한 ID를 사용합니다. [브라우저 RUM SDK](/ko/rum/browser-sdk)를 참조하십시오.

## 엔드포인트 및 프로토콜

| 프로토콜 | 엔드포인트 | 호환 발신자 | 대상 스트림 |
|---|---|---|---|
| Native HTTP JSON | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`, 애플리케이션 코드, Vector `http` 싱크, Fluent Bit `http` 출력 | `{stream}` 경로 세그먼트 |
| OTLP over HTTP | `POST /api/v1/logs`, `/api/v1/metrics`, `/api/v1/traces` | OpenTelemetry SDK 및 Collector | `stream-name` 헤더, 없으면 `default` |
| OTLP over gRPC | `:4317` | OpenTelemetry SDK 및 Collector | `stream-name` 메타데이터, 없으면 `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus, VictoriaMetrics, 클라우드 관리형 Prometheus 내보내기, 모든 remote_write v1 발신자 | `stream-name` 헤더, 없으면 `?stream=`, 없으면 `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat, Logstash, Vector `elasticsearch` 싱크 | 각 액션의 `_index`, 없으면 `stream-name` 헤더, 없으면 `default` |
| Splunk HEC | `POST /api/v1/services/collector/event`, `/api/v1/services/collector/raw` | Tencent Cloud CLS, Vector 및 Fluent Bit Splunk 출력, SIEM 포워더 | 각 이벤트의 `index`, 없으면 `?index=`, 없으면 `stream-name` 헤더, 없으면 `default` |
| Loki push (JSON) | `POST /api/v1/loki/api/v1/push` | Loki JSON 형식을 POST할 수 있는 발신자 | `stream-name` 헤더, 없으면 `default` |
| Amazon Data Firehose, Google Cloud Pub/Sub push, 클라우드 이벤트 버스, Cloudflare Logpush, Heroku | `/api/v1/_kinesis_firehose`, `/api/v1/_gcp_pubsub`, `/api/v1/_cloud_events`, `/api/v1/_cloudflare`, `/api/v1/_heroku` | Firehose를 통한 CloudWatch Logs 및 CloudWatch Metric Streams, Pub/Sub을 통한 Cloud Logging, EventBridge, Event Grid 및 CloudEvents 발신자, Cloudflare, Heroku | 커넥터에서 구성합니다. [커넥터](/ko/connectors)를 참조하십시오. |

푸시 커넥터를 제외한 모든 엔드포인트는 해당 시그널의 쓰기 권한이 있는 베어러 토큰을 요구합니다: `logs.write`, `metrics.write`, `traces.write` 또는 `profiles.write`. 조직은 토큰에서 결정되며 URL에 절대 나타나지 않습니다.

### 발신자에게 영향을 주는 제한

- **요청 크기.** Native JSON 인테이크와 푸시 커넥터는 압축 해제 후 기준으로 최대 16 MiB의 요청 본문을 허용하고, Firehose는 최대 64 MiB를 허용합니다. 다른 인테이크 엔드포인트는 최대 2 MiB를 허용합니다. 더 큰 본문은 `413`으로 거부됩니다. 배치를 해당 크기 미만으로 유지하십시오.
- **압축.** OTLP over HTTP는 압축된 요청 본문을 허용하지 않으며 `400`으로 응답합니다. 발신자에서 압축을 비활성화하십시오. OpenTelemetry Collector의 `otlphttp` 익스포터는 기본적으로 gzip으로 압축하므로 `compression: none`이 필요합니다. Native JSON 인테이크, Elasticsearch `_bulk`, Loki push 및 푸시 커넥터는 `Content-Encoding: gzip`을 허용합니다.
- **Loki 인코딩.** JSON 요청 형식만 디코딩됩니다. Promtail 및 Grafana Alloy는 기본적으로 snappy로 압축된 protobuf를 전송하므로 이 엔드포인트로 전송할 수 없습니다.
- **속도 제한.** `router` 역할은 조직별 요청을 제한하고 `Retry-After` 헤더와 함께 `429`로 응답합니다. `standalone` 노드는 이 제한을 적용하지 않습니다. [역할 기반 배포](/ko/deployment/role-based#요청-속도-제한)를 참조하십시오.
- **거부된 이벤트.** 스트림에서 해당 필드의 타입에 맞지 않는 값을 가진 이벤트는 해당 이벤트만 거부되고 요청의 나머지는 기록됩니다. `int64` 필드에 소수부가 있는 숫자는 거부되지 않습니다. 해당 필드는 `float64`가 됩니다([스키마 및 필드](/ko/streams#스키마-및-필드) 참조). 각 엔드포인트는 거부한 항목을 보고합니다. Native JSON은 `rejected` 및 `errors`로, OTLP는 `partialSuccess`로, Elasticsearch `_bulk`는 상태 `400`인 항목으로, Splunk HEC는 코드 `6`으로, Prometheus remote write 및 Loki push는 `400`으로 보고합니다. 발신자는 이를 재시도하지 않습니다. 푸시 커넥터는 성공으로 응답합니다. 플랫폼이 전체 요청을 다시 보내기 때문이며, 커넥터가 거부된 항목을 알려줍니다.
- **플랫폼 스트림.** 서비스 자체 텔레메트리를 위한 `_molesignal`, 감사 추적을 위한 `_audit`과 같은 [플랫폼 스트림](/ko/streams#플랫폼-스트림)은 MoleSignal만 기록하며 공개 인테이크를 `403`으로 거부합니다.

## 스트림 및 스키마

스트림은 첫 쓰기 시 생성되며, 새 필드가 나타나면서 스키마가 진화합니다. 스트림은 이름과 시그널 타입으로 식별되므로 `default`가 로그, 메트릭, 트레이스에 동시에 존재할 수 있습니다. [스트림](/ko/streams)을 참조하십시오.

모든 이벤트에는 Unix 에포크 이후 마이크로초 단위의 타임스탬프가 있습니다. Native JSON 및 Elasticsearch `_bulk`는 `_timestamp` 필드를 읽습니다. `_timestamp`가 없는 이벤트에는 서버가 수락한 시간이 부여됩니다.

## Native HTTP JSON

`/api/v1/intake/{logs,metrics,traces}/{stream}`에 레코드 배열을 POST합니다:

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

응답은 수락된 레코드 수와 거부된 레코드 수를 거부된 인덱스별 사유와 함께 보고합니다:

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

OpenTelemetry SDK 또는 Collector를 `/api` 기본 경로로 지정합니다. 익스포터는 `/v1/logs`, `/v1/metrics`, `/v1/traces`를 추가하며, 이는 `/api/v1/logs`, `/api/v1/metrics`, `/api/v1/traces`에 매핑됩니다.

<Tabs>
  <Tab title="OTLP over HTTP">
    SDK 환경 변수:

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    protobuf(`application/x-protobuf`)를 전송하십시오. 이는 SDK 및 Collector의 기본 인코딩입니다. 로그, 메트릭, 트레이스는 JSON(`application/json`)도 허용합니다. `default`가 아닌 스트림을 선택하려면 `stream-name` 헤더를 추가하십시오. 이 헤더는 해당 익스포터를 통해 전송되는 모든 시그널에 적용됩니다.
  </Tab>
  <Tab title="OTLP over gRPC">
    OTLP gRPC 수신기는 포트 `4317`에서 수신 대기하며 로그, 메트릭, 트레이스 및 프로파일 서비스를 제공합니다. TLS를 종료하지 않습니다. 신뢰할 수 있는 네트워크를 벗어나는 트래픽의 경우 그 앞에서 TLS를 종료하십시오.

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    TLS 종료 프록시가 포트 앞단에 있으면 `insecure: true`를 제거하십시오. 포트 `5082`는 내부 클러스터 gRPC 포트이며 OTLP 수신기가 아닙니다.
  </Tab>
</Tabs>

OTLP 메트릭은 데이터 포인트당 하나의 이벤트로 저장됩니다. 저장되는 필드는 [메트릭 저장 계약](/ko/query#otlp-메트릭-필드)을 참조하십시오.

## Prometheus remote_write

`prometheus.yml`에 MoleSignal을 remote write 대상으로 추가합니다:

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

메트릭 스트림은 하나의 소스에서 나온 메트릭을 보관하므로 `stream-name` 헤더(`remote_write` 항목의 `headers:`)를 사용하여 각 Prometheus 서버에 자체 스트림을 지정하십시오. 이 헤더가 없으면 샘플은 `default`로 전송됩니다. 헤더를 설정할 수 없는 발신자는 대신 URL에서 스트림을 지정합니다. 예: `/api/v1/prometheus/api/v1/write?stream=aliyun`. 각 샘플은 `metric_name`이 해당 `__name__`인 행이 됩니다. 다른 레이블은 필드가 되며, `metric_name`처럼 메트릭 필드와 같은 이름의 레이블은 `exported_<name>`으로 유지됩니다. 네이티브 히스토그램과 메트릭 메타데이터는 건너뛰며, exemplar는 샘플 옆에 저장됩니다.

## Elasticsearch bulk

Elasticsearch bulk 프로토콜을 사용하는 발신자는 Loki 또는 OTLP 의존성 없이 작동합니다:

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

각 액션의 `_index`가 대상 스트림을 선택합니다. `_index`가 없으면 `stream-name` 헤더가 적용되고, 그다음으로 `default`가 적용됩니다.

## Loki push

이 엔드포인트는 Loki JSON 요청 형식을 허용합니다:

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

레이블은 필드가 되고, 로그 라인은 `message` 필드가 되며, 나노초 타임스탬프는 마이크로초로 변환됩니다. 응답은 `204`입니다. `stream-name` 헤더로 대상 스트림을 선택하십시오.

## Splunk HEC

Splunk HTTP Event Collector 프로토콜을 사용하는 송신자(예: Splunk로 전송하는 Tencent Cloud CLS, Vector와 Fluent Bit의 Splunk 출력)는 변경 없이 MoleSignal로 보낼 수 있습니다. 이들에게 HEC 주소로 `https://molesignal.example.com/api/v1`을, HEC 토큰으로 로그를 쓸 수 있는 API Token을 지정하고 `Authorization: Splunk <token>`으로 전송합니다.

| 엔드포인트 | 본문 |
|---|---|
| `POST /api/v1/services/collector/event`, `/services/collector`도 지원 | JSON 객체를 연속으로 전송하며, 각 객체는 `{"time", "host", "source", "sourcetype", "index", "event", "fields"}`입니다 |
| `POST /api/v1/services/collector/raw` | 텍스트이며 한 줄에 로그 이벤트 하나입니다. `host`, `source`, `sourcetype`, `index`는 쿼리에서 가져옵니다 |
| `GET /api/v1/services/collector/health` | 토큰 없이 `{"text":"HEC is healthy","code":17}`를 응답합니다 |

`event`가 JSON 객체이면 로그의 필드가 되고, 그 밖의 `event`는 `message`가 됩니다. `fields`, `host`, `source`, `sourcetype`는 필드가 되고, 초 단위의 `time`은 시각이 됩니다. `index`는 스트림 이름을 지정하며, 없으면 `index` 쿼리 파라미터, 그다음 `stream-name` 헤더, 마지막으로 `default`를 사용합니다. 응답은 `{"text":"Success","code":0}`이며, 오류 시에는 `400`과 함께 HEC 자체 오류 코드를 반환합니다. 값이 필드 타입에 맞지 않아 스트림이 이벤트를 거부하면 나머지 이벤트는 기록되고, 응답은 코드 `6`이 되며, 본문에서 처음 거부된 이벤트의 위치가 `invalid-event-number`, 사유가 `text`에 담깁니다. 인덱서 확인 응답(indexer acknowledgement)은 제공하지 않습니다.
