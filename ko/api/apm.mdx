The APM API는 트레이스 스팬에서 파생된 조직 범위 집계를 제공합니다. 모든 엔드포인트는
`/api/v1/apm` 접두사를 사용하며 베어러 토큰이 필요합니다.

```http
Authorization: Bearer <token>
```

조직 워크스페이스에는 해당 영역의 읽기 권한이 필요합니다: `apm.services.read`, `apm.errors.read`,
`apm.error_rules.read`, `apm.definitions.read`, `apm.slos.read`, `apm.deployments.read`, `apm.settings.read`. 플랫폼 호출자는
보호된 `_sys` 스코프에서 `sys.telemetry.read`를 사용할 수 있습니다. 쓰기 호출은 각각 필요한 권한을 명시합니다. 배포를 보고하려면
`apm.deploy`가 필요합니다.

## 엔드포인트

| 메서드 및 경로 | 응답 |
|---|---|
| `GET /api/v1/apm/overview` | 모든 서비스의 RED 요약과 추세, 서비스 상태와 그 추세, 순위, 배포, 환경, 계측 공백, 상위 트랜잭션, 의존성, 오류입니다. |
| `GET /api/v1/apm/insights` | 이전 기간과 일주일 전 같은 기간 대비 무엇이 변했는지, 더 나빠진 버전, 시간을 되찾을 수 있는 지점, 각 지점 근처의 변경 사항입니다. |
| `GET /api/v1/apm/services` | 계측, 버전, 상태, RED 지표, 트레이스 필터를 포함한 페이지네이션된 서비스 카탈로그입니다. |
| `GET /api/v1/apm/services/{service}` | 서비스 요약, 추세, 트랜잭션, 의존성, 오류, 버전입니다. |
| `GET /api/v1/apm/services/{service}/instances` | 환경 내 서비스의 인스턴스로, 각 인스턴스의 버전, 리소스 속성, 처리한 내용을 포함합니다. |
| `GET /api/v1/apm/services/{service}/coverage` | `to` 이전 하루 동안 해당 서비스의 로그, 지표, 프로파일, 브라우저 세션이 MoleSignal에 도달하는지 여부입니다. |
| `GET /api/v1/apm/correlation` | 조회 범위의 각 서비스가 로그, 지표, 트레이스, 변경 사항과 얼마나 잘 연결되는지, 그리고 APM이 알지 못하는 로그와 지표의 서비스 이름입니다. |
| `GET /api/v1/apm/transactions` | 페이지네이션된 트랜잭션 RED 지표와 총 시간 순위입니다. |
| `GET /api/v1/apm/transactions/{transaction}` | 트랜잭션 추세, 영향을 받은 오류, 버전, 트레이스 필터입니다. |
| `GET /api/v1/apm/dependencies` | 페이지네이션된 호출자/의존성 RED 지표와 총 시간 순위입니다. |
| `GET /api/v1/apm/map` | 환경과 네임스페이스의 서비스 맵: 서비스, 서비스가 호출하는 대상, 토픽, 서비스 간 호출입니다. |
| `GET /api/v1/apm/map/edge` | 맵의 호출 하나: 해당 호출의 추세, 호출 경로에서 요청된 내용, 호출된 서비스의 오류입니다. |
| `GET /api/v1/apm/blast-radius` | 서비스가 맵을 따라 도달하는 범위: 서비스를 호출하는 대상과 서비스가 호출하는 대상, 홉 단위입니다. |
| `GET /api/v1/apm/errors` | 정제된 백엔드 오류 그룹의 페이지네이션 목록과 나열된 그룹이 발생한 위치입니다. |
| `GET /api/v1/apm/errors/{fingerprint}` | 오류 추세, 영향을 받은 트랜잭션과 버전, 그룹이 발생한 위치, 대표 스택, 제한된 샘플입니다. |
| `GET /api/v1/apm/versions/compare` | 기준 및 후보 RED 지표, 델타, 충분성 상태, 회귀입니다. |
| `GET /api/v1/apm/health` | 테넌트 프로젝션 상태, 런타임 상태, 경계, 공백입니다. |
| `GET /api/v1/apm/service-definitions` | 조직의 모든 서비스 정의입니다. |
| `PUT /api/v1/apm/service-definitions/{service}?namespace=` | 서비스 정의를 생성하거나 교체합니다. `apm.definitions.manage`가 필요합니다. |
| `DELETE /api/v1/apm/service-definitions/{service}?namespace=` | 서비스 정의를 삭제합니다. `apm.definitions.manage`가 필요합니다. |
| `POST /api/v1/apm/service-definitions/{service}/key-transactions?namespace=` | 엔드포인트를 서비스의 주요 트랜잭션으로 별표 표시하거나 별표를 해제합니다. `apm.definitions.manage`가 필요합니다. |
| `PUT /api/v1/apm/errors/{fingerprint}/issue` | 오류 그룹의 상태, 팀, 담당자를 설정합니다. `apm.errors.manage`가 필요합니다. |
| `GET /api/v1/apm/error-rules` | 조직의 오류 그룹화 규칙을 시도되는 순서대로 표시합니다. |
| `POST /api/v1/apm/error-rules` | 그룹화 규칙을 생성하며, 다른 규칙 다음에 시도됩니다. `apm.error_rules.manage`가 필요합니다. |
| `PUT /api/v1/apm/error-rules/{id}` | 그룹화 규칙을 교체합니다. `apm.error_rules.manage`가 필요합니다. |
| `DELETE /api/v1/apm/error-rules/{id}` | 그룹화 규칙을 삭제합니다. `apm.error_rules.manage`가 필요합니다. |
| `PUT /api/v1/apm/error-rules/order` | 규칙이 시도되는 순서를 설정합니다. `apm.error_rules.manage`가 필요합니다. |
| `GET /api/v1/apm/slos` | 모든 서비스 수준 목표와 해당 목표의 상태, 달성한 목표, 남은 오류 예산, 소진율입니다. |
| `GET /api/v1/apm/slos/{id}` | 서비스 수준 목표 하나의 상태와 해당 기간의 일별 현황입니다. |
| `POST /api/v1/apm/slos` | 서비스 수준 목표를 생성합니다. `apm.slos.manage`가 필요합니다. |
| `PUT /api/v1/apm/slos/{id}` | 서비스 수준 목표를 교체합니다. `apm.slos.manage`가 필요합니다. |
| `DELETE /api/v1/apm/slos/{id}` | 서비스 수준 목표를 삭제합니다. `apm.slos.delete`가 필요합니다. |
| `POST /api/v1/apm/deployments` | 배포를 보고합니다. `apm.deploy`가 필요합니다. |
| `GET /api/v1/apm/settings` | 조직의 APM 설정이며, 저장된 설정이 없으면 기본값입니다. |
| `PUT /api/v1/apm/settings` | 조직의 APM 설정을 교체합니다. `apm.settings.manage`가 필요합니다. |

경로 매개변수는 URL 인코딩해야 합니다. 목록 응답에서 반환된 정확한 `transaction` 이름이나 오류 `fingerprint`를 사용합니다.

## 공통 쿼리 매개변수

| 매개변수 | 유형 | 동작 |
|---|---|---|
| `from` | integer | Unix 에포크 기준 마이크로초 단위의 범위 시작입니다. 기본값은 `to`보다 24시간 전입니다. |
| `to` | integer | Unix 에포크 기준 마이크로초 단위의 범위 끝입니다. 기본값은 현재 시각입니다. |
| `namespace` | string | 정확한 서비스 네임스페이스 필터입니다. |
| `service` | string | 정확한 서비스 이름 필터입니다. 서비스 상세 경로가 이 값을 재정의합니다. |
| `environment` | string | 정확한 배포 환경 필터입니다. |
| `version` | string | 정확한 서비스 버전 필터입니다. |
| `resolution` | enum | `auto`, `minute`, `hour` 중 하나입니다. `auto`는 해당 범위에 보존된 해상도를 선택합니다. |
| `sort` | string | 엔드포인트별 정렬 필드입니다. |
| `direction` | enum | `asc` 또는 `desc`입니다. 기본값은 `desc`입니다. |
| `limit` | integer | 페이지 크기로 1에서 200 사이입니다. 기본값은 50입니다. |
| `cursor` | string | 이전 목록 응답에서 받은 불투명 커서입니다. |
| `status` | enum | `/errors` 전용: `all`(기본값), `unresolved`(열림, 조사 중, 다시 나타난 해결됨 그룹), `investigating`, `resolved`, `ignored`입니다. |

필터는 비어 있지 않아야 하며 192바이트를 초과할 수 없습니다. 범위는 설정된 최대값을 초과할 수 없으며,
최대값의 기본값은 30일(`[apm].max_query_range_days`)입니다.

### 정렬 필드

| 엔드포인트 | 지원되는 `sort` 값 | 기본값 |
|---|---|---|
| `/services` | `requestCount`, `errorRate`, `p95`, `name` | `requestCount` |
| `/transactions` | `requestCount`, `errorRate`, `p95`, `total_time` | `requestCount` |
| `/dependencies` | `requestCount`, `errorRate`, `p95`, `total_time` | `total_time` |
| `/errors` | `occurrenceCount`, `errorRate`, `lastSeen` | `occurrenceCount` |

`/overview`는 동일한 필터와 해상도를 받지만 페이지네이션하지 않습니다. 상세, 비교, 상태 엔드포인트는
페이지네이션된 목록을 반환하지 않습니다.

## 개요 조회

<RequestExample>
```bash cURL
NOW=$(date +%s)000000
curl --get 'http://localhost:5080/api/v1/apm/overview' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode "from=$((NOW-86400000000))" \
  --data-urlencode "to=$NOW" \
  --data-urlencode 'environment=production' \
  --data-urlencode 'resolution=auto'
```
</RequestExample>

응답에는 `red`, `trend`, `serviceHealth`, `services`, `topTransactions`,
`topDependencies`, `topErrors`, `recentVersions`와 공통 `meta` 객체, 그리고 다음이 포함됩니다:

| 필드 | 설명 |
|---|---|
| `serviceCount`, `activeServiceCount` | 범위 내에서 확인된 서비스와 그중 요청을 처리한 서비스입니다. |
| `healthTrend` | 각 상태에 있는 서비스 수를 슬롯 단위로 나타냅니다. 범위는 최대 48개의 슬롯으로 나뉘며, 각 슬롯은 버킷보다 짧지 않습니다. 슬롯 내에 요청이 없는 서비스는 해당 슬롯에서 `noTraffic`으로 집계됩니다. |
| `rankings` | `slowest`(p95 기준), `mostErrors`(오류율 기준), `busiest`(요청 수 기준) 각각 5개 서비스입니다. 처음 두 개는 요청이 20개 이상인 서비스를 나열합니다. |
| `deployments` | 범위 내에서 처음 확인된 버전을 최신순으로 최대 20개까지 나열하며, 각 버전에는 [서비스 버전](#서비스의-버전-읽기)에서와 같이 `red`와 `verdict`가 포함됩니다. |
| `environments`, `availableEnvironments` | 보기 기준 환경별 서비스와 요청 수, 그리고 `environment` 필터와 관계없이 서비스가 실행되는 모든 환경입니다. |
| `instrumentation` | 언어 및 SDK별 서비스 수와 `deployment.environment`, `service.version`, `service.instance.id`를 보고하지 않는 서비스 수입니다. |

## 인사이트 조회

`GET /api/v1/apm/insights`는 공통 범위 및 필터 매개변수를 받아 `meta`와 다음을 응답합니다:

| 필드 | 설명 |
|---|---|
| `now`, `previous`, `lastWeek` | 범위 내 보기 기준 서비스, 그 이전 동일 길이 기간, 1주 전 동일 기간의 데이터입니다: `requestCount`, 초당 요청 수인 `throughput`, `errorRate`, `p95Time`, `apdex`가 포함됩니다. 요청이 없는 기간은 표시되지 않습니다. |
| `insights` | 최대 30개의 발견 사항이며, 가장 시급한 항목이 먼저 옵니다. |

각 발견 사항에는 다음이 포함됩니다:

| 필드 | 설명 |
|---|---|
| `kind` | `anomaly`, `regression`, `slow_dependency`, `repeated_call`, `slowQuery`, `hot_endpoint`, `log_errors` 중 하나입니다. |
| `severity` | 제안의 경우 `critical`, `warning`, `info` 중 하나입니다. |
| `service` | `namespace`, `name`, `environment`입니다. |
| `transaction`, `dependency` | 핫 엔드포인트의 엔드포인트, 병목 현상이나 반복 호출, 느린 구문의 종속성입니다. |
| `metric` | 변동되거나 악화된 지표: `errorRate`, `p95`, `throughput`입니다. |
| `value` | 현재 수치: 오류율은 비율, P95는 마이크로초, 요청 수는 초당 요청 수입니다. 병목 현상이나 핫 엔드포인트는 시간 점유율, 반복 호출은 요청당 호출 수, 느린 구문은 마이크로초 단위 P95, `log_errors`는 분당 오류 수준 로그 라인 수를 나타내며 `metric`은 `log_errors`입니다. |
| `previous`, `lastWeek` | 이전 기간과 1주 전 동일 기간의 동일 수치입니다. 회귀의 경우 이전 버전의 수치입니다. |
| `since` | 변동이 시작된 시점 또는 회귀된 버전이 처음 확인된 시점입니다. |
| `version`, `previousVersion` | 회귀의 버전과 그 이전 버전입니다. |
| `calls`, `p95Time` | 제안의 근거가 되는 호출 또는 요청 수와 해당 P95입니다. |
| `changes` | `since` 근처의 변경 사항을 가장 가까운 순으로 나열합니다: `kind`, `source`(`reported` 또는 `observed`), `service`, `version`, `status`, `at`, `downstream`(변동된 서비스가 호출하는 서비스의 경우 `true`), `commit`, `description`입니다. |

임계값은 [인사이트 및 조사](/ko/apm/insights#인사이트가-찾는-항목)에 있습니다.

## 서비스 목록 및 페이지 매기기

```bash
curl --get 'http://localhost:5080/api/v1/apm/services' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'namespace=shop' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'sort=p95' \
  --data-urlencode 'direction=desc' \
  --data-urlencode 'limit=50'
```

`nextCursor` 또는 `previousCursor`를 동일한 엔드포인트, 필터, 범위, 정렬, 방향과 함께 변경 없이 전달하세요.
커서는 서명되었으며 원래 요청 컨텍스트로 범위가 지정됩니다. 커서를 디코딩하거나
편집하지 마세요.

항목의 `traces` 객체는 서비스, 버전, 트랜잭션, 종속성, 오류 필터와 해당 항목의 범위를 다시 명시하여 클라이언트가 일치하는 트레이스를 열 수 있도록 합니다.

## RED 지표 조회

모든 요약에는 범위의 요청, 오류, 기간 수치가 포함된 `red` 객체가 있습니다.

| 필드 | 설명 |
|---|---|
| `requestCount`, `errorCount`, `errorRate` | 요청 수, 실패한 요청 수, 전체 요청에 대한 실패 비율(0에서 1)입니다. |
| `durationSum`, `durationAverage` | 마이크로초 단위의 총 기간과 평균 기간입니다. 요청이 없으면 평균은 `null`입니다. |
| `p50Time`, `p90Time`, `p95Time`, `p99Time` | 마이크로초 단위의 지연 백분위수로, 순위가 속한 히스토그램 버킷 내에서 읽습니다. 기본 레이아웃에서는 값이 정확한 기간의 약 4% 이내입니다. 요청이 없으면 `null`입니다. |
| `apdex` | 임계값 T 이내의 요청과 4T 이내 요청의 절반을 전체 요청으로 나눈 값(0에서 1)입니다. T는 서비스의 `apdexThreshold`이며, 없으면 500ms입니다. 모든 서비스를 합친 개요 수치는 500ms를 사용합니다. 실패한 요청은 만족으로 집계되지 않습니다. 요청이 없으면 `null`입니다. |
| `latencyPartial` | 일부 버킷이 해당 버킷만으로는 구분할 수 없는 지연 레이아웃을 사용할 때 `true`입니다. 이전 레이아웃(`[apm.histogram].schema_version`)의 버킷은 변환되어 계산됩니다. 백분위수는 읽을 수 없는 버킷을 제외하지만, 개수, 합계, 평균에는 여전히 포함합니다. |
| `timeoutCount`, `retryCount` | 시간 초과된 요청(시간 초과 오류 유형, gRPC `DEADLINE_EXCEEDED`, HTTP 408 또는 504)과 다시 전송된 요청(`http.request.resend_count`가 0보다 큼)입니다. 없으면 표시되지 않습니다. |
| `statusCodes` | 상태 코드별 응답으로, `http:<code>`(100~599) 또는 `grpc:<code>`(0~16) 형식입니다. 버킷은 최대 24개 코드를 유지하며, 추가 코드는 `http:other` 또는 `grpc:other`로 집계됩니다. 코드가 집계되지 않은 경우(예: 코드 집계 이전에 작성된 집계)에는 표시되지 않습니다. |
| `exemplars` | 범위의 최대 8개 샘플 스팬으로, 가장 느린 것부터 표시합니다. 스팬은 [테일 샘플링](/ko/configuration#트레이스-캡처-및-테일-샘플링)이 해당 트레이스에 대해 결정하기 전에 프로젝션되므로 `traceAvailable`은 일반적으로 `false`입니다. 트레이스가 유지되었는지 확인하려면 트레이스를 조회하세요. 집계는 유효하게 유지됩니다. |

서비스 및 트랜잭션 요약에는 Apdex를 읽은 T인 `apdexThreshold`가 포함됩니다.
서비스 요약에는 `health`와 `healthReasons`도 포함됩니다. 각 수치가 기준을 초과한 경우 `metric`
(`errorRate` 또는 `p95`), `level`, `value`, `threshold`로 표시됩니다. 또한 `sparkline`(각 버킷의 요청 수, 오류 수, p95)이 포함되며,
`currentVersion`과 `currentVersionSince`(가장 최근에 확인된 버전과 처음 확인된 시점)도 포함됩니다.
서비스 또는 트랜잭션의 상세 정보에는 `latencyDistribution`이 포함됩니다: 히스토그램
요청이 있는 버킷으로, 각각 `lowerTime`, `upperTime`, `count`로 표시되며,
가장 빠른 요청과 가장 느린 요청으로 좁혀집니다.

## 서비스 정의 유지

정의는 서비스 소유자와 중요도를 기록합니다. `namespace`와
서비스 이름을 키로 사용하므로 모든 환경에 적용되며, 서비스가 리포트를 보내기 전에도 존재할 수 있습니다.

```http
PUT /api/v1/apm/service-definitions/checkout?namespace=shop
Content-Type: application/json

{"description": "Takes orders and payments.", "teamId": "<team id>", "ownerId": "<user id>", "tier": "p0", "lifecycle": "production", "repositoryUrl": "https://github.com/acme/checkout", "tags": {"domain": "orders", "pci": ""}, "apdexThreshold": 300000, "aliases": ["order_service", "Order Center"], "dataSources": {"logs": [{"stream": "default", "filter": "service_name = 'order_service'"}], "metrics": [{"selector": "{service=\"checkout\"}"}], "dashboards": ["<dashboard id>"], "links": [{"name": "Runbook", "url": "https://wiki.example.com/checkout"}]}, "archived": false}
```

| 필드 | 참고 |
|---|---|
| `description` | 최대 2,000자입니다. |
| `teamId` | 조직의 팀 또는 `null`입니다. 팀을 삭제하면 이 값이 지워집니다. |
| `ownerId` | 조직의 구성원 또는 `null`입니다. |
| `tier` | `p0`(가장 중요)부터 `p5`까지 또는 `null`입니다. |
| `lifecycle` | `production`, `staging`, `experimental`, `deprecated` 또는 `null`입니다. |
| `repositoryUrl` | `http`, `https`, `ssh`, `git` 또는 `git+ssh` URL, 또는 `user@host:path`이며, 공백 없이 최대 2,048자 또는 `null`입니다. 비밀번호는 `****`로 저장되고, http(s) 주소의 사용자 부분도 마찬가지입니다. 서비스가 저장소를 보고하지 않을 때 표시됩니다. |
| `tags` | 최대 32개의 태그를 `{ "key": "value" }` 형식으로 지정합니다. 키는 1~64자의 소문자, 숫자 및 `_ . - /`이고, 값은 앞뒤 공백 없이 최대 128자이며 키만 있는 경우 비워 둡니다. |
| `apdexThreshold` | 서비스의 Apdex 임계값 T입니다. 0보다 크고 최대 60,000,000(1분)이거나, `null`이면 500ms입니다. |
| `aliases` | 서비스가 로그, 메트릭 및 기타 시스템에서 사용하는 최대 20개의 다른 이름이며, 각 이름은 앞뒤 공백 없이 1~128자입니다. 대소문자는 구분하지 않습니다. 같은 이름을 두 번 사용할 수 없고, 서비스 자체 이름은 사용할 수 없으며, 조직 내 다른 서비스의 이름이나 그 서비스의 다른 별칭도 사용할 수 없습니다. 생략하면 저장된 정의가 기존 이름을 유지합니다. |
| `dataSources` | 서비스 데이터의 위치입니다. `logs`(`stream` 및 선택적 `filter`, 최대 2,000자의 부울 SQL 식), `metrics`(`selector`, `{service="checkout"}`와 같은 PromQL 선택자), `dashboards`(대시보드 ID), `links`(`name` 및 `http` 또는 `https` `url`)를 각각 최대 10개까지 지정합니다. 생략하면 저장된 정의가 기존 소스를 유지합니다. |
| `archived` | `true`이면 카탈로그 기본 보기에서 서비스를 제외합니다. 생략하면 저장된 정의가 상태를 유지합니다. |

정의를 저장해도 정의의 `keyTransactions`는 유지되며, 이 값은 한 번에 하나씩 변경됩니다. 응답은
`namespace`, `name`, `keyTransactions`, `updatedBy`, `updatedAt`을 포함한 저장된 정의입니다.
`DELETE`는 `204`를 반환하고, 서비스에 정의가 없으면 `404`를 반환합니다.

### 핵심 트랜잭션 별표 표시

```http
POST /api/v1/apm/service-definitions/checkout/key-transactions?namespace=shop
Content-Type: application/json

{"transaction": {"name": "POST /orders", "kind": "http"}, "key": true}
```

`key: true`는 엔드포인트를 `keyTransactions`에 추가하고, `false`는 제거합니다. 이미 그 상태인 값을
요청해도 아무것도 바뀌지 않습니다. 정의가 없는 서비스에는 정의가 생성됩니다. 서비스는 최대 50개의 핵심
트랜잭션을 유지하며, 오버플로 행 `__other__`는 핵심 트랜잭션이 될 수 없습니다. 응답은 변경 후의
정의입니다.

## 서비스가 다른 데이터와 얼마나 잘 연결되는지 확인

`GET /api/v1/apm/correlation`은 공통 범위 및 필터 매개변수(`from`, `to`,
`namespace`, `environment`, `service`)를 받고, 조회 범위 내 각 서비스가 로그, 메트릭, 트레이스, 변경 사항과 얼마나 잘 연결되는지 알려줍니다. 서비스는 해당 범위에서, 로그와 메트릭은 `to` 이전
1시간 동안, 변경 사항은 `to` 이전 1주일 동안 조회합니다.
스트림에서는 개수와 이름만 읽고, 라인은 읽지 않습니다. 각 리포트는
5분 동안 보관됩니다.

```json
{
  "from": 1792312896695000,
  "to": 1792316496695000,
  "changesSince": 1791711696695000,
  "services": [
    {
      "service": { "namespace": "shop", "name": "checkout", "environment": "prod" },
      "logs": { "state": "reported", "streams": ["default"], "lines": 1200, "traced": 480, "sampled": 10, "matched": 9 },
      "metrics": "missing",
      "resource": { "environment": true, "version": true, "instance": true, "placement": false },
      "changes": { "count": 3, "lastAt": 1792312896695000 },
      "grades": { "traceIds": "partial", "resource": "partial", "metrics": "missing", "changes": "good" }
    }
  ],
  "unmatched": [{ "name": "checkout-svc", "signal": "logs", "streams": ["default"], "lines": 640 }]
}
```

| 필드 | 의미 |
|---|---|
| `logs` | `service.name`, `service_name` 또는 `service` 필드가 있는 로그 스트림에서 해당 서비스의 라인입니다. 스트림은 최대 8개이며 `default`가 먼저입니다. `traced`는 `trace_id`, `traceId` 또는 `trace.id`가 있는 라인을 계산합니다. 트레이스에서 서비스의 최근 트레이스 ID를 최대 10개(전체 200개) 찾습니다: `sampled` 및 `matched`. |
| `metrics` | 메트릭 스트림에 서비스의 `service.name`이 있는 시계열이 있는지 여부입니다. |
| `resource` | 스팬이 환경, 버전, 인스턴스를 보고하는지, 그리고 인스턴스가 `host.name`, `k8s.pod.name`, `k8s.node.name` 또는 `container.id`(`placement`)를 보고하는지 여부입니다. |
| `changes` | `changesSince` 이후 서비스에 대해 보고된 배포, 구성 변경 및 기능 플래그입니다. |
| `unmatched` | 어떤 APM 서비스에도 해당하지 않는 로그 또는 메트릭의 서비스 이름을 최대 20개까지, 명명 규칙과 별칭을 적용하여 라인 수가 많은 순서로 표시합니다. |

각 등급은 `good`, `partial`, `missing`, `unknown` 중 하나입니다:

| 등급 | `good` | `partial` | `missing` |
|---|---|---|---|
| `traceIds` | 라인의 90% 이상에 트레이스 ID가 있으며, 샘플링된 항목 중 80% 이상이 발견됩니다. | 일부 라인에 트레이스 ID가 있습니다. | 트레이스 ID가 있는 라인이 없거나 서비스가 라인을 작성하지 않았습니다. |
| `resource` | `resource`의 네 항목이 모두 true입니다. | 일부만 true입니다. | 모두 false입니다. |
| `metrics` | 메트릭에 이름이 포함됩니다. | | 없습니다. |
| `changes` | 변경 사항이 하나 이상 있습니다. | | 없습니다. |

`unknown`은 조회가 실패했거나 3초보다 오래 걸렸음을 의미합니다. 스트림을 읽을 수 없을 때 찾지 못한 이름은
`unknown`이며, 절대 `missing`이 아닙니다. Mole Agent는 같은 리포트를
`get_correlation_quality`로 읽습니다.

## 서비스 커버리지 확인

`GET /api/v1/apm/services/{service}/coverage`는 필수인 `namespace`와 `environment`, 그리고
선택적인 `to`(조회 범위의 끝을 마이크로초 단위로 지정하며, 기본값은 현재)를 받습니다. `to` 이전 하루를
조회하며, 각 응답은 5분 동안 보관합니다.

```json
{
  "from": 1792230096695000,
  "to": 1792316496695000,
  "logs": { "state": "reported", "found": ["default"] },
  "metrics": { "state": "missing" },
  "profiles": { "state": "reported", "found": ["cpu", "alloc_space"] },
  "rum": { "state": "unknown" }
}
```

| 신호 | `reported`인 경우 | `found` |
|---|---|---|
| `logs` | `service.name`, `service_name` 또는 `service` 필드가 있는 로그 스트림에 해당 서비스의 라인이 있습니다. 스트림은 최대 8개까지 조회하며 `default`가 먼저입니다. | 스트림입니다. |
| `metrics` | `to` 시점의 `count(last_over_time({"service.name"="<service>"}[1h]))`가 0보다 큽니다. | 시계열 수입니다. |
| `profiles` | 프로필 스트림에 서비스의 프로필이 있습니다. | 프로필 유형입니다. |
| `rum` | 브라우저 작업이 서비스의 가장 최근 샘플 트레이스 5개 중 하나를 포함했습니다. | 세션입니다. |

`missing`은 조회에서 아무것도 찾지 못했음을 의미합니다. `unknown`은 조회가 실패했거나 3초보다 오래
걸렸음을 의미합니다. `rum`은 절대 `missing`이 아닙니다. 트레이스 샘플은 세션이 서비스에 도달함을 보여줄 수 있지만,
어떤 세션도 도달하지 않음을 보여줄 수는 없습니다.

## 서비스의 실행 정보 확인

`GET /api/v1/apm/services` 및 `GET /api/v1/apm/services/{service}`는 각 서비스 요약에
`profile`을 제공하며, 이는 범위 내에서 보고한 인스턴스에서 읽습니다. `version` 매개변수가 설정되면 해당 `version`의 인스턴스만 대상으로 합니다. 각 목록은
값을 공유하는 인스턴스 수를 기준으로 정렬되며, 최대 5개까지 다음 형식으로 표시됩니다:
`{ "value": "1.8.2", "instances": 4 }`.

| 필드 | 참고 |
|---|---|
| `instanceCount`, `hostCount` | 인스턴스 수와 고유한 `host.name` 값입니다. |
| `versions` | 인스턴스가 실행한 버전입니다. 롤아웃 중이면 두 버전이 표시됩니다. |
| `languages`, `runtimes`, `frameworks` | `telemetry.sdk.language`; 버전이 포함된 `process.runtime.name`; 엔트리 스팬의 계측 라이브러리가 지정한 프레임워크입니다. |
| `regions`, `clusters`, `k8sNamespaces`, `workloads` | `cloud.region`, `k8s.cluster.name`, `k8s.namespace.name`, 그리고 `k8s.deployment.name` 또는 `k8s.statefulset.name`입니다. |
| `repositories`, `commits` | `vcs.repository.url.full` 또는 `git.repository_url`(자격 증명은 제외하고 보관); `vcs.ref.head.revision` 또는 `git.commit.sha`. |
| `entryKinds` | `http`, `rpc`, `messaging`, `span`: 서비스가 처리하는 엔트리 유형입니다. |

`GET /api/v1/apm/services/{service}/instances`는 인스턴스를 가장 최근에
관찰된 순서로 하나씩 나열하며, 최대 500개입니다. `namespace`, `environment`, 선택적 `version`, `from`, `to`를
받습니다. 서비스와 환경을 지정하지 않으면 `400`을 반환합니다. 각 항목에는 `instanceId` (
`service.instance.id`, 없으면 `k8s.pod.name`, 없으면 `host.name`), `version`, `firstSeenAt`,
`lastSeenAt`, `attributes`, 인스턴스가 마지막으로 보고한 속성 맵, 그리고 범위 내에서 처리한
항목이 있습니다: 서비스의 임계값에서 Apdex를 사용하는 요약과 마찬가지로 `red`, 그리고 `sparkline`입니다. 인스턴스 한도를
넘는 나머지는 `instanceId`가 `__other__`인 하나의 항목에 집계됩니다. 범위 내에서 처리했지만
해당 인스턴스에 대해 보관된 정보가 없는 경우 빈 `attributes`로 표시됩니다.

## 오류 그룹 상태 설정

```http
PUT /api/v1/apm/errors/<fingerprint>/issue
Content-Type: application/json

{"status": "investigating", "assigneeId": "<user id>", "teamId": "<team id>", "lastSeenAt": 1792316496695000}
```

`status`는 `open`, `investigating`, `resolved`, `ignored` 중 하나입니다. `assigneeId`는
조직의 구성원 또는 `null`이고, `teamId`는 조직의 팀 또는 `null`입니다. `lastSeenAt`은 선택 사항이며, 그룹이 마지막으로 확인된 시각을 마이크로초 단위로 나타냅니다. 상태를
`resolved`로 설정하면 그 시각이 `resolvedAt`에 기록됩니다.

오류 요약은 상태를 `issue`로 전달하며, 아무도 상태를 설정하지 않은 동안에는 `null`입니다. `issue.regressed`는
`resolvedAt` 이후 해결된 그룹이 다시 발생하면 `true`입니다. `unresolved` 필터는
이러한 그룹을 유지합니다. 프로젝션이 알지 못하는 지문의 상태를 설정하면 `404`를 응답합니다.

## 서비스 수준 목표 저장

서비스 수준 목표(SLO)는 한 환경에서 서비스 또는 해당 서비스의 엔드포인트 하나에 대해 롤링 기간 동안
정상 요청 비율을 목표로 합니다. 각 수치의 의미는
[서비스 수준 목표](/ko/apm#서비스-수준-목표)를 참고하세요.

```http
POST /api/v1/apm/slos
Content-Type: application/json

{"name": "Checkout availability", "namespace": "shop", "service": "checkout", "environment": "production", "transaction": null, "kind": "availability", "objective": 0.999, "windowDays": 30}
```

| 필드 | 설명 |
|---|---|
| `name` | 필수이며 최대 255바이트입니다. |
| `description` | 선택 사항이며 최대 2,000바이트입니다. |
| `namespace`, `service`, `environment` | 필수입니다. APM에서 이름을 지정하는 서비스입니다. `service.namespace`가 없는 서비스는 `default` 네임스페이스에 속합니다. |
| `transaction` | 엔드포인트 하나를 `{ "name": "POST /orders", "kind": "http" }`로 지정하거나, 전체 서비스에 대해 `null`로 지정합니다. |
| `kind` | `availability`: 요청이 실패하지 않으면 정상입니다. `latency`: 요청이 실패하지 않았고 `latencyThreshold` 이하의 시간이 걸렸으면 정상입니다. |
| `latencyThreshold` | `latency`에는 필수이며 양수여야 합니다. `availability`에서는 `null`이거나 없어야 합니다. |
| `objective` | 정상 요청의 비율이며 0보다 크고 1보다 작습니다(예: `0.999`). |
| `windowDays` | `7`, `28`, `30` 중 하나입니다. |

`POST`와 `PUT`은 저장된 SLO를 `id`, `createdBy`, `createdAt`, `updatedBy`,
`updatedAt`과 함께 응답합니다. `GET /api/v1/apm/slos`는 조직의 모든 SLO를 상태와 함께 응답합니다. 한 서비스의 SLO로 한정하려면
`namespace`, `service`, `environment`를 함께 전달하세요. 기간은
호출 시점에 끝나므로 일반적인 범위 매개변수는 적용되지 않습니다.

| 상태 필드 | 설명 |
|---|---|
| `slo` | 저장된 그대로의 SLO입니다. |
| `state` | `healthy`, `at_risk`, `breached`, `noData` 중 하나입니다. |
| `sli` | 기간 내 전체 요청 중 정상 요청의 비율이며, 요청이 없으면 `null`입니다. |
| `goodRequests`, `totalRequests` | `sli`의 기반이 되는 개수입니다. 지연 시간 SLO는 지연 시간 히스토그램에서 `goodRequests`를 추정하므로 소수일 수 있습니다. |
| `budgetRemaining` | `1 - (1 - sli) / (1 - objective)`이며, 목표를 위반하면 0 미만이 되고 요청이 없으면 `null`입니다. |
| `burnRates` | `oneHour`, `sixHours`, `oneDay`: 지난 1시간, 6시간, 24시간 동안의 `(1 - sli) / (1 - objective)`이며, 요청이 없으면 `null`입니다. |

`GET /api/v1/apm/slos/{id}`는 `status`와 `history`를 응답하며, `history`에는 요청이 있는 기간의 각 UTC 일마다
항목이 하나씩 있고 가장 오래된 항목이 먼저입니다. 각 항목에는 마이크로초 단위의 `dayStart`, `sli`, `goodRequests`,
`totalRequests`가 있습니다.

`DELETE`는 `204`를 응답합니다. SLO를 감시하는 알림 규칙(예: 번레이트
알림)이 있으면 `409`를 응답하므로, 해당 규칙을 먼저 삭제하세요. SLO에 대한 알림 규칙은 메트릭이
`slo_burn_rate`인 APM 규칙입니다. [규칙 생성](/ko/api/alerting/create-rule#apm-규칙)을 참고하세요.

## 트랜잭션 구분

두 트랜잭션 종류가 같은 이름을 공유할 수 있습니다. 하나를 선택하려면 선택적 `kind` 매개변수를 전달하세요:

```http
GET /api/v1/apm/transactions/POST%20%2Fcheckout?kind=http&service=checkout
```

지원되는 `kind` 값은 `http`, `rpc`, `messaging`, `span`, `other`입니다. 여러
서비스나 종류가 공유하는 이름은 `400`과 함께 `APM transaction identity is ambiguous; provide service,
namespace, environment, and kind`를 응답합니다.

## 버전 비교

서로 다른 `baseline`과 `candidate` 값을 제공하세요. 한 서비스를 비교하려면 `service` 필터를 추가하세요.

```bash
curl --get 'http://localhost:5080/api/v1/apm/versions/compare' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'service=checkout' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'baseline=2.3.1' \
  --data-urlencode 'candidate=2.4.0'
```

응답에는 `baseline`과 `candidate` 양측이 있으며, 각각 `version`, `sampleCount`,
`red`를 포함하고, 여기에 `delta`, `status`, `regressedTransactions`, `regressedErrors`가 더해집니다. 각 회귀
목록에는 최대 20개 항목이 있습니다.

| 필드 | 설명 |
|---|---|
| `sufficientData` | 두 버전 모두 구성된 샘플 임계값을 충족할 때만 `true`이며, 임계값의 기본값은 버전당 1,000개 요청입니다(`[apm.version_comparison].min_requests_per_version`). |
| `status` | `insufficient_data`, `regressed`, `improved`, `neutral` 중 하나입니다. 후보의 오류율이 1포인트 이상 상승해 기준선의 1.5배 이상이 되거나, p95가 1/5(20%) 이상 상승해 50ms 이상 증가하면 `regressed`입니다. 둘 중 하나가 같은 기준만큼 하락하고 둘 다 같은 기준만큼 상승하지 않았으면 `improved`이며, `sufficientData`가 `false`이면 `insufficient_data`입니다. |
| `delta` | `requestCountAbsolute`와 `requestCountRelative`, `errorRateAbsolute`와 `errorRateRelative`, `p95AbsoluteTime`과 `p95Relative`입니다. 기준선이 0이거나 없으면 상대 값은 `null`입니다. |

`candidate` 또는 `baseline`이 없거나 두 버전이 동일하면 `400`을 응답합니다.

## 서비스의 버전 읽기

`GET /api/v1/apm/services/{service}`는 범위 내에서 확인된 버전인 `versions`를 응답합니다. 각 버전은
범위 내에서 제공한 내용인 `red`와, 동일 서비스에서 그 이전에 처음 확인된 버전과 비교한 결과인 `verdict`를 포함하며, 판단 기준은
[비교](#버전-비교)와 같습니다:

| 필드 | 설명 |
|---|---|
| `previous` | 비교 대상 버전입니다. |
| `status` | `regressed`, `improved`, `neutral`, `insufficient_data` 중 하나입니다. |
| `worse` | `status`가 `regressed`일 때 악화된 항목으로, `errorRate`, `latency` 또는 둘 다입니다. |
| `delta` | 비교에서와 같이 이전 버전을 기준선으로 사용합니다. |

처음 확인된 버전에는 `verdict`가 없습니다. 요청의 버전 필터는
수치를 좁히지 않습니다. 모든 버전은 전체 서비스에서 읽습니다.

## 오류 발생 위치 읽기

`GET /api/v1/apm/errors`는 페이지 옆에 `breakdown`을 응답하며, 이는 `status` 필터가
유지하는 모든 그룹(페이지의 그룹만이 아님)을 대상으로 합니다. 그리고 `GET /api/v1/apm/errors/{fingerprint}`는 해당 그룹의 `breakdown`을
응답합니다. 여기에는 `versions`, `environments`, `languages`가 있으며, 각각 `value`와 `count`의 목록으로
발생 횟수를 큰 것부터 나타냅니다. 스팬이 보고하지 않은 값은 비어 있습니다. 처음
일곱 값을 지나면 나머지는 `__other__`로 함께 집계됩니다. 언어는 서비스의
`telemetry.sdk.language`입니다.

## 오류 그룹화 규칙 저장

규칙은 오류가 확인될 때 유형, 프레임, 엔드포인트가 아닌 다른 기준으로 오류를 그룹화합니다. 규칙은
`position` 순서로 시도되며 처음 일치하는 규칙이 적용됩니다.

```http
POST /api/v1/apm/error-rules
Content-Type: application/json

{"name": "Upstream timeouts", "serviceNamespace": "shop", "serviceName": "checkout",
 "errorType": "*Timeout*", "message": "", "frame": "", "endpoint": "", "action": "merge", "enabled": true}
```

| 필드 | 설명 |
|---|---|
| `name` | 최대 128자입니다. 병합된 그룹은 이 이름을 사용합니다. |
| `serviceNamespace`, `serviceName` | 규칙이 적용되는 서비스입니다. `serviceName`이 비어 있으면 모든 서비스를 의미하며, 네임스페이스를 지정할 때는 이름이 필요합니다. |
| `errorType`, `message`, `frame`, `endpoint` | 오류 유형, 예외 메시지, 첫 번째 애플리케이션 프레임, 엔드포인트에 대한 패턴이며 각각 최대 256자입니다. 패턴은 대소문자를 구분하지 않고 전체 텍스트와 일치하며, `*`는 임의의 텍스트를 나타냅니다. 빈 패턴은 무엇이든 일치합니다. 따라서 필드 중 최소 하나는 설정해야 합니다. |
| `action` | `merge`: 서비스에서 일치한 오류가 하나의 그룹이 됩니다. `ignore`: 그룹을 만들지 않으며, 해당 요청은 여전히 실패로 집계됩니다. |
| `enabled` | 꺼진 규칙은 보관되지만 시도되지 않습니다. 기본값은 `true`입니다. |

응답은 규칙과 해당 규칙의 `id`, `position`, `updatedBy`, `updatedAt`입니다. 조직은
최대 100개의 규칙을 보관합니다. `PUT /api/v1/apm/error-rules/order`는 `{"ids": [...]}`를 받아 해당 규칙을
그 순서대로 먼저 배치하고 나머지 규칙을 그 뒤에 배치하며, 새 순서대로 규칙을 응답합니다.

변경 사항은 저장한 노드에는 즉시 적용되고 다른 노드에는 30초 이내에 적용되며, 그때부터 확인되는
오류에 적용됩니다. 이미 만들어진 그룹은 그대로 유지됩니다.

## 서비스 맵 읽기

`GET /api/v1/apm/map`은 공통 조회 범위, `environment`, `namespace` 매개변수를 받고 다음을 응답합니다.
`nodes`, `edges`, `namespaces`(환경 내 서비스의 네임스페이스), `environments`(모든 환경),
`truncated`(가장 트래픽이 많은 400개 노드만 유지할 때 `true`).

| 필드 | 비고 |
|---|---|
| `nodes[].id` | `service:<name>`, `topic:<name>` 또는 서비스가 호출하는 대상의 `<category>:<target>`입니다. |
| `nodes[].kind` | `service`, `external`, `topic`입니다. 외부 노드는 `category`를 포함합니다. |
| `nodes[].red` | `requestCount`, `errorCount`, `errorRate`, `p95Time`: 서비스가 처리한 요청 또는 외부 노드나 토픽에 요청된 내용입니다. 서비스는 `health`, `namespace`, `environments`도 포함합니다. |
| `edges[].kind` | `call`, `publish`(토픽으로), `consume`(토픽에서)입니다. |
| `change` | 에지 또는 노드에서 동일한 길이의 이전 기간과 비교한 변경입니다. 이전에 없었으면 `new`, 더 이상 없으면 `gone`입니다. 이전에 아무것도 없었으면 표시되지 않습니다. |

서비스 간 호출은 서비스 그래프에서 가져오며, 가장 느린 분의 P95를 사용합니다. 나머지는
APM 버킷에서 가져옵니다. `GET /api/v1/apm/map/edge`는 동일한 매개변수 외에 `source` 및 `target` 노드 ID를 받고
`kind`, `red`, `trend`, `operations`(`name`, `kind`, `red`), `everyCaller`
(작업이 모든 호출자로부터 호출된 서비스의 엔드포인트일 때 `true`) 및 `errors`, 즉
호출된 서비스의 오류 그룹을 응답합니다.

## 서비스의 영향 범위 읽기

`GET /api/v1/apm/blast-radius`는 필수인 `service`와 공통 조회 범위 및
`environment` 매개변수를 받습니다. 네임스페이스와 관계없이 환경 전체 맵을 읽고
`meta`, `service`(서비스 자체 노드이며, 범위 내 맵 어디에도 없으면 생략됨),
`upstream`(이를 호출하는 대상, 최대 3홉), `downstream`(이것이 호출하거나 게시하는 대상, 최대 2
홉)을 응답합니다. 각 측은 최대 30개 노드를 포함하며 비정상 노드가 먼저 옵니다. 이전 기간과 비교해 사라진 호출은
제외됩니다.

| 필드 | 비고 |
|---|---|
| `id`, `kind`, `name`, `namespace`, `category` | [서비스 맵](#서비스-맵-읽기)에서 지정하는 노드입니다. |
| `hops` | 노드와 서비스 사이의 홉 수입니다. 직접 호출자 또는 피호출자이면 `1`입니다. |
| `via` | 해당 노드에 도달하는 경로의 노드이며, 서비스에 한 홉 더 가깝습니다. |
| `health` | 서비스 자체의 상태입니다. 호출 대상인 경우 실패한 호출로부터 산출된 상태입니다. |
| `red`, `call` | 해당 노드가 처리했거나 요청받은 내용과, 해당 노드와 `via` 사이의 호출입니다. |

## 배포 보고

`POST /api/v1/apm/deployments`는 배포를 JSON으로 받고, 배포에 `id`,
`createdBy`, `createdAt`을 추가한 배포와 함께 `201`을 응답합니다. 필드, 제한, CI 예시는
[배포](/ko/apm/deployments#ci에서-배포-보고)에 있습니다. 서비스와 환경
이름은 조직의 명명 규칙, 환경 매핑, 별칭이 해석하는 대로 지정됩니다. 저장소
주소는 비밀번호를 마스킹하여 보관됩니다. 구성 변경 또는 기능 플래그는
`kind`를 `configuration` 또는 `feature_flag`로 설정하며 `version`이 필요하지 않습니다.

규모 또는 인프라 변경은 `kind`를 `scaling` 또는 `infrastructure`로 설정합니다. 보고된 변경은
[`GET /api/v1/changes`](/ko/api/changes)에 나열됩니다.

## APM 설정 유지

`GET /api/v1/apm/settings`는 조직의 설정을 응답하고, `PUT`은 설정을 전체 교체하며
유지된 설정을 응답합니다:

```json
{
  "health": {
    "errorRateWarning": 0.02,
    "errorRateCritical": 0.1,
    "p95WarningTime": 500000,
    "p95CriticalTime": 2000000
  },
  "apdexThreshold": 500000,
  "longTaskTime": 1000000,
  "namingRules": [{ "pattern": "^(checkout)-[a-z0-9]{5}$", "replacement": "$1" }],
  "environmentMap": [{ "from": "Production", "to": "production" }],
  "aliases": [{ "aliasNamespace": "shop", "alias": "checkout-v1", "namespace": "shop", "service": "checkout" }],
  "metadataRules": { "teamFromTier": "p1", "ownerFromTier": "p0", "repositoryFromTier": null }
}
```

생략한 필드는 기본값을 사용합니다. 이름의 앞뒤 공백은 제거되며, 별칭 네임스페이스가 비어 있으면 `default`입니다. 제한과
각 설정의 동작은 [APM 설정](/ko/apm/settings)에 있습니다. 저장은
저장한 노드에는 즉시 적용되고 다른 노드에는 30초 이내에 적용됩니다.

플랫폼의 카디널리티 제한은 `GET` 및 `PUT
/api/v1/settings/apm_limits`로 읽고 교체하며, `sys.settings.limits.manage` 권한이 필요합니다. 본문에는
`servicesPerOrgHour`, `transactionsPerServiceHour`, `dependenciesPerServiceHour`,
`operationsPerDependencyHour`, `errorGroupsPerServiceHour`, `versionsPerServiceHour` 및
`instancesPerServiceHour`가 포함되며, 각 값은 1에서 100000 사이입니다.

## 응답 메타데이터 읽기

모든 엔드포인트는 공통 `meta` 객체를 반환합니다:

```json
{
  "range": {
    "from": 1785801600000000,
    "to": 1785888000000000
  },
  "resolution": "minute",
  "projectionStartedAt": 1785798000000000,
  "lastCompleteBucketAt": 1785887940000000,
  "dataQuality": {
    "partial": false,
    "gaps": [],
    "overflowDimensions": []
  },
  "activationBoundary": false
}
```

- `activationBoundary: true`는 `projectionStartedAt` 이전 구간의 커버리지가 불완전한 것으로 간주합니다.
- `dataQuality.partial: true`는 완전한 0이 아니라 불완전한 데이터로 간주합니다.
- `gaps`에서 큐, 저장소, 플러시, 지연 데이터, 카디널리티 또는 종료 실패 여부를 확인합니다.
- `lastCompleteBucketAt`을 사용하여 최근 데이터가 아직 확정 중인지 판단합니다.
- 고카디널리티 세부 분석을 신뢰하기 전에 `overflowDimensions`를 확인합니다.

## 오류

| 상태 코드 | 원인 |
|---|---|
| `400` | 매개변수가 유효하지 않습니다. 지원되지 않는 `sort`(`unsupported APM sort field`), 1에서 200 범위를 벗어난 `limit`, 비어 있거나 너무 큰 필터(`invalid APM service filter`), 최댓값보다 긴 범위(`APM query range exceeds configured maximum`), 시작보다 이른 종료(`APM range end precedes start`), 알 수 없는 `direction` 또는 `resolution`, 위 검사를 통과하지 못한 SLO(`SLO objective must be between 0 and 1, exclusive`), 또는 `namespace`, `service`, `environment`가 모두 포함되지 않은 SLO 목록 필터입니다. |
| `403` | 토큰에 해당 호출의 권한이 없습니다. |
| `404` | 오류 지문, 트랜잭션, 서비스 또는 SLO가 범위에 없습니다. |
| `409` | 삭제 중인 SLO를 알림 규칙이 아직 감시하고 있습니다. |
