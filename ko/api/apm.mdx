APM API는 트레이스 스팬을 집계한 데이터를 조직 범위에서 제공합니다. 모든 엔드포인트는
`/api/v1/apm` 접두사를 사용하며 Bearer 토큰이 필요합니다.

```http
Authorization: Bearer <token>
```

조직 워크스페이스에서 조회하려면 해당 영역의 읽기 권한이 필요합니다. `apm.services.read`, `apm.errors.read`,
`apm.error_rules.read`, `apm.definitions.read`, `apm.slos.read`, `apm.deployments.read`, `apm.settings.read` 중 해당하는 권한을 사용합니다. 플랫폼 호출자는
보호된 `_sys` 범위에서 `sys.telemetry.read`를 사용할 수 있습니다. 쓰기 작업에 필요한 권한은 각 엔드포인트 설명에 명시합니다. 배포를 보고하려면
`apm.deploy` 권한이 필요합니다.

## 엔드포인트

| 메서드 및 경로 | 응답 |
|---|---|
| `GET /api/v1/apm/overview` | 모든 서비스의 RED 요약 및 추세, 서비스 상태 및 추세, 순위, 배포, 환경, 계측 누락, 상위 트랜잭션, 종속성, 오류를 반환합니다. |
| `GET /api/v1/apm/insights` | 직전 기간 및 일주일 전 동일 기간과 비교한 변화, 성능이 저하된 버전, 처리 시간을 줄일 수 있는 지점, 각 항목과 비슷한 시점에 발생한 변경 사항을 반환합니다. |
| `GET /api/v1/apm/services` | 계측 정보, 버전, 상태, RED 메트릭, 트레이스 필터를 포함한 서비스 카탈로그를 페이지 단위로 반환합니다. |
| `GET /api/v1/apm/services/{service}` | 서비스의 요약, 추세, 트랜잭션, 종속성, 오류, 버전을 반환합니다. |
| `GET /api/v1/apm/services/{service}/instances` | 환경 내 서비스 인스턴스와 각 인스턴스의 버전, 리소스 속성, 처리한 요청에 대한 정보를 반환합니다. |
| `GET /api/v1/apm/services/{service}/coverage` | `to` 직전 24시간 동안 서비스의 로그, 메트릭, 프로파일, 브라우저 세션이 MoleSignal에 수집되었는지 반환합니다. |
| `GET /api/v1/apm/transactions` | 트랜잭션의 RED 메트릭과 총 소요 시간 순위를 페이지 단위로 반환합니다. |
| `GET /api/v1/apm/transactions/{transaction}` | 트랜잭션의 추세, 관련 오류, 버전, 트레이스 필터를 반환합니다. |
| `GET /api/v1/apm/dependencies` | 호출자와 종속성 간의 RED 메트릭과 총 소요 시간 순위를 페이지 단위로 반환합니다. |
| `GET /api/v1/apm/map` | 환경과 네임스페이스의 서비스 맵을 반환합니다. 서비스, 호출 대상, 토픽, 이들 간의 호출을 포함합니다. |
| `GET /api/v1/apm/map/edge` | 서비스 맵에서 단일 호출 관계의 추세, 해당 경로의 요청, 호출된 서비스의 오류를 반환합니다. |
| `GET /api/v1/apm/blast-radius` | 서비스 맵에서 해당 서비스를 호출하는 대상과 해당 서비스가 호출하는 대상을 홉 단위로 반환합니다. |
| `GET /api/v1/apm/errors` | 민감 정보를 제거한 백엔드 오류 그룹과 각 그룹의 발생 위치를 페이지 단위로 반환합니다. |
| `GET /api/v1/apm/errors/{fingerprint}` | 오류 추세, 영향을 받은 트랜잭션과 버전, 그룹의 발생 위치, 대표 스택, 개수가 제한된 샘플을 반환합니다. |
| `GET /api/v1/apm/versions/compare` | 기준 버전과 후보 버전의 RED 메트릭, 차이, 비교에 필요한 데이터의 충족 여부, 성능 저하 항목을 반환합니다. |
| `GET /api/v1/apm/health` | 테넌트 프로젝션 상태, 런타임 상태, 경계 및 누락 구간을 반환합니다. |
| `GET /api/v1/apm/service-definitions` | 조직의 모든 서비스 정의를 반환합니다. |
| `PUT /api/v1/apm/service-definitions/{service}?namespace=` | 서비스 정의를 생성하거나 교체합니다. `apm.definitions.manage` 권한이 필요합니다. |
| `DELETE /api/v1/apm/service-definitions/{service}?namespace=` | 서비스 정의를 삭제합니다. `apm.definitions.manage` 권한이 필요합니다. |
| `POST /api/v1/apm/service-definitions/{service}/key-transactions?namespace=` | 엔드포인트를 서비스의 주요 트랜잭션으로 표시하거나 표시를 해제합니다. `apm.definitions.manage` 권한이 필요합니다. |
| `PUT /api/v1/apm/errors/{fingerprint}/issue` | 오류 그룹의 상태, 팀, 담당자를 설정합니다. `apm.errors.manage` 권한이 필요합니다. |
| `GET /api/v1/apm/error-rules` | 조직의 오류 그룹화 규칙을 평가 순서대로 반환합니다. |
| `POST /api/v1/apm/error-rules` | 그룹화 규칙을 생성합니다. 기존 규칙을 모두 평가한 다음 새 규칙을 평가합니다. `apm.error_rules.manage` 권한이 필요합니다. |
| `PUT /api/v1/apm/error-rules/{id}` | 그룹화 규칙을 교체합니다. `apm.error_rules.manage` 권한이 필요합니다. |
| `DELETE /api/v1/apm/error-rules/{id}` | 그룹화 규칙을 삭제합니다. `apm.error_rules.manage` 권한이 필요합니다. |
| `PUT /api/v1/apm/error-rules/order` | 규칙의 평가 순서를 설정합니다. `apm.error_rules.manage` 권한이 필요합니다. |
| `GET /api/v1/apm/slos` | 모든 서비스 수준 목표의 상태, 달성 실적, 남은 오류 예산, 오류 예산 소진율을 반환합니다. |
| `GET /api/v1/apm/slos/{id}` | 단일 서비스 수준 목표의 상태와 평가 기간의 일별 데이터를 반환합니다. |
| `POST /api/v1/apm/slos` | 서비스 수준 목표를 생성합니다. `apm.slos.manage` 권한이 필요합니다. |
| `PUT /api/v1/apm/slos/{id}` | 서비스 수준 목표를 교체합니다. `apm.slos.manage` 권한이 필요합니다. |
| `DELETE /api/v1/apm/slos/{id}` | 서비스 수준 목표를 삭제합니다. `apm.slos.delete` 권한이 필요합니다. |
| `POST /api/v1/apm/deployments` | 배포를 보고합니다. `apm.deploy` 권한이 필요합니다. |
| `GET /api/v1/apm/deployments` | 파이프라인에서 보고한 배포를 최신순으로 반환합니다. |
| `GET /api/v1/apm/settings` | 조직의 APM 설정을 반환합니다. 저장된 설정이 없으면 기본값을 반환합니다. |
| `PUT /api/v1/apm/settings` | 조직의 APM 설정을 교체합니다. `apm.settings.manage` 권한이 필요합니다. |

경로 매개변수는 URL 인코딩해야 합니다. 목록 응답에서 반환한 `transaction` 이름이나 오류 `fingerprint`를
그대로 사용합니다.

## 공통 쿼리 매개변수

| 매개변수 | 유형 | 동작 |
|---|---|---|
| `from` | 정수 | 조회 범위의 시작 시각입니다. Unix 에포크부터 경과한 시간을 마이크로초 단위로 지정합니다. 기본값은 `to`보다 24시간 전입니다. |
| `to` | 정수 | 조회 범위의 종료 시각입니다. Unix 에포크부터 경과한 시간을 마이크로초 단위로 지정합니다. 기본값은 현재 시각입니다. |
| `namespace` | 문자열 | 서비스 네임스페이스가 정확히 일치하는 항목만 조회합니다. |
| `service` | 문자열 | 서비스 이름이 정확히 일치하는 항목만 조회합니다. 서비스 상세 조회에서는 경로 매개변수가 이 값보다 우선합니다. |
| `environment` | 문자열 | 배포 환경이 정확히 일치하는 항목만 조회합니다. |
| `version` | 문자열 | 서비스 버전이 정확히 일치하는 항목만 조회합니다. |
| `resolution` | 열거형 | `auto`, `minute`, `hour` 중 하나를 지정합니다. `auto`는 조회 범위에 대해 보존된 데이터의 해상도를 선택합니다. |
| `sort` | 문자열 | 엔드포인트별 정렬 필드입니다. |
| `direction` | 열거형 | `asc` 또는 `desc`를 지정합니다. 기본값은 `desc`입니다. |
| `limit` | 정수 | 페이지 크기를 1~200으로 지정합니다. 기본값은 50입니다. |
| `cursor` | 문자열 | 이전 목록 응답에서 반환한 불투명 커서입니다. |
| `status` | 열거형 | `/errors`에서만 사용합니다. `all`(기본값), `unresolved`(열린 그룹, 조사 중인 그룹, 해결 후 다시 발생한 그룹), `investigating`, `resolved`, `ignored` 중 하나를 지정합니다. |

필터 값은 비워 둘 수 없으며 192바이트를 초과할 수 없습니다. 조회 범위는 설정한
최댓값을 초과할 수 없습니다. 기본값은 30일입니다(`\[apm\].max_query_range_days`).

### 정렬 필드

| 엔드포인트 | 지원하는 `sort` 값 | 기본값 |
|---|---|---|
| `/services` | `requestCount`, `errorRate`, `p95`, `name` | `requestCount` |
| `/transactions` | `requestCount`, `errorRate`, `p95`, `total_time` | `requestCount` |
| `/dependencies` | `requestCount`, `errorRate`, `p95`, `total_time` | `total_time` |
| `/errors` | `occurrenceCount`, `errorRate`, `lastSeen` | `occurrenceCount` |

`/overview`는 동일한 필터와 해상도를 지원하지만 페이지 나누기는 지원하지 않습니다. 상세 조회, 비교,
상태 엔드포인트는 페이지 단위 목록을 반환하지 않습니다.

## 개요 조회

<RequestExample>
```bash cURL
NOW=$(date +%s)000000
curl --get 'http://localhost:5080/api/v1/apm/overview' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode "from=$((NOW-86400000000))" \
  --data-urlencode "to=$NOW" \
  --data-urlencode 'environment=production' \
  --data-urlencode 'resolution=auto'
```
</RequestExample>

응답에는 `red`, `trend`, `serviceHealth`, `services`, `topTransactions`,
`topDependencies`, `topErrors`, `recentVersions`, 공통 `meta` 객체와 다음 필드가 포함됩니다.

| 필드 | 설명 |
|---|---|
| `serviceCount`, `activeServiceCount` | 조회 범위에서 관측한 서비스 수와 그중 요청을 하나 이상 처리한 서비스 수입니다. |
| `healthTrend` | 시간 슬롯별로 각 상태에 해당하는 서비스 수입니다. 조회 범위를 최대 48개 슬롯으로 나누며, 각 슬롯의 길이는 버킷보다 짧지 않습니다. 슬롯에 요청이 없는 서비스는 해당 슬롯에서 `noTraffic`으로 집계합니다. |
| `rankings` | `slowest`(p95 기준), `mostErrors`(오류율 기준), `busiest`(요청 수 기준)에 각각 서비스 5개를 나열합니다. 앞의 두 순위에는 요청이 20건 이상인 서비스만 포함합니다. |
| `deployments` | 조회 범위에서 처음 관측한 버전을 최신순으로 최대 20개 나열합니다. 각 버전에는 [서비스 버전 조회](#서비스-버전-조회)와 동일하게 `red`와 `verdict`가 포함됩니다. |
| `environments`, `availableEnvironments` | 각각 조회 대상의 환경별 서비스 수와 요청 수, 그리고 `environment` 필터와 관계없이 서비스가 실행되는 모든 환경입니다. |
| `instrumentation` | 언어 및 SDK별 서비스 수와 `deployment.environment`, `service.version`, `service.instance.id`를 보고하지 않는 서비스 수를 각각 제공합니다. |

## 인사이트 조회

`GET /api/v1/apm/insights`는 공통 조회 범위 및 필터 매개변수를 받으며, `meta`와 다음 필드를 반환합니다.

| 필드 | 설명 |
|---|---|
| `now`, `previous`, `lastWeek` | 조회 대상 서비스에 대해 각각 조회 범위, 바로 앞의 동일한 길이의 구간, 일주일 전의 동일한 구간에서 집계한 `requestCount`, 초당 요청 수로 표시한 `throughput`, `errorRate`, `p95Time`, `apdex`입니다. 요청이 없는 구간은 생략합니다. |
| `insights` | 발견 사항을 우선순위가 높은 순서로 최대 30개 나열합니다. |

각 발견 사항에는 다음 필드가 포함됩니다.

| 필드 | 설명 |
|---|---|
| `kind` | `anomaly`, `regression`, `slow_dependency`, `repeated_call`, `slowQuery`, `hot_endpoint` 중 하나입니다. |
| `severity` | `critical` 또는 `warning`이며, 제안에는 `info`를 사용합니다. |
| `service` | `namespace`, `name`, `environment`입니다. |
| `transaction`, `dependency` | 부하가 집중된 엔드포인트의 경우 해당 엔드포인트를, 병목·반복 호출·느린 쿼리의 경우 해당 종속성을 나타냅니다. |
| `metric` | 변동하거나 악화된 지표입니다. `errorRate`, `p95`, `throughput` 중 하나입니다. |
| `value` | 현재 값으로, 오류율은 비율, P95는 마이크로초, 처리량은 초당 요청 수로 표시합니다. 병목이나 부하가 집중된 엔드포인트의 경우 전체 소요 시간에서 차지하는 비율, 반복 호출의 경우 요청당 호출 수, 느린 쿼리의 경우 마이크로초 단위의 P95를 표시합니다. |
| `previous`, `lastWeek` | 바로 앞 구간과 일주일 전의 동일한 구간에서 측정한 같은 지표의 값입니다. 성능 저하의 경우 이전 버전에서 측정한 값을 사용합니다. |
| `since` | 지표가 변동하기 시작한 시점 또는 성능이 저하된 버전을 처음 관측한 시점입니다. |
| `version`, `previousVersion` | 성능이 저하된 버전과 그 이전 버전입니다. |
| `calls`, `p95Time` | 제안의 근거가 된 호출 또는 요청의 수와 해당 P95입니다. |
| `changes` | `since`에 가까운 시점의 변경 사항을 시간 차이가 작은 순서로 나열합니다. 각 항목에는 `kind`, `source`(`reported` 또는 `observed`), `service`, `version`, `status`, `at`, `downstream`(지표가 변동한 서비스에서 호출하는 서비스라면 `true`), `commit`, `description`이 포함됩니다. |

임계값은 [인사이트 및 조사](/ko/apm/insights#인사이트가-감지하는-항목)를 참조합니다.

## 서비스 목록 및 페이지네이션

```bash
curl --get 'http://localhost:5080/api/v1/apm/services' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'namespace=shop' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'sort=p95' \
  --data-urlencode 'direction=desc' \
  --data-urlencode 'limit=50'
```

## RED 메트릭 조회

모든 요약에는 조회 범위의 요청, 오류, 소요 시간 수치를 담은 `red` 객체가 포함됩니다.

| 필드 | 설명 |
|---|---|
| `requestCount`, `errorCount`, `errorRate` | 요청 수, 실패한 요청 수, 전체 요청 중 실패한 요청의 비율(0~1)입니다. |
| `durationSum`, `durationAverage` | 마이크로초 단위의 소요 시간 합계와 평균입니다. 요청이 없으면 평균은 `null`입니다. |
| `p50Time`, `p90Time`, `p95Time`, `p99Time` | 마이크로초 단위의 지연 시간 백분위수입니다. 각 순위가 속한 히스토그램 버킷 내에서 값을 추정합니다. 기본 버킷 구성을 사용하면 실제 소요 시간과의 오차가 약 4% 이내입니다. 요청이 없으면 `null`입니다. |
| `apdex` | T 이내에 완료된 요청 수에 T를 초과하고 4T 이내에 완료된 요청 수의 절반을 더한 뒤, 전체 요청 수로 나눈 값(0~1)입니다. T는 서비스의 `apdexThreshold`이며, 설정하지 않으면 500 ms입니다. 개요에서 모든 서비스를 합산한 수치에는 500 ms를 사용합니다. 실패한 요청은 만족으로 집계하지 않습니다. 요청이 없으면 `null`입니다. |
| `latencyPartial` | 일부 버킷에서 지연 시간 버킷 구성을 판별할 수 없으면 `true`입니다. 이전 구성(`[apm.histogram].schema_version`)의 버킷은 변환하여 집계합니다. 백분위수에서는 읽을 수 없는 버킷을 제외하지만 개수, 합계, 평균에는 포함합니다. |
| `timeoutCount`, `retryCount` | 시간 초과가 발생한 요청 수(시간 초과 오류 유형, gRPC `DEADLINE_EXCEEDED`, HTTP 408 또는 504)와 다시 전송한 요청 수(`http.request.resend_count`가 0보다 큰 경우)입니다. 해당 요청이 없으면 필드를 생략합니다. |
| `statusCodes` | 상태 코드별 응답 수입니다. 코드는 `http:<code>`(100~599) 또는 `grpc:<code>`(0~16)로 표시합니다. 버킷에는 코드를 최대 24개까지 저장하고, 그 외 코드는 `http:other` 또는 `grpc:other`로 집계합니다. 상태 코드 집계를 시작하기 전에 기록한 집계 데이터처럼 집계한 코드가 없으면 이 필드를 생략합니다. |
| `exemplars` | 조회 범위에서 추출한 샘플 스팬을 소요 시간이 긴 순서로 최대 8개 제공합니다. [테일 샘플링](/ko/configuration#트레이스-캡처-및-테일-샘플링)이 트레이스 보존 여부를 결정하기 전에 스팬을 집계에 반영하므로, `traceAvailable`은 보통 `false`입니다. 보존 여부는 해당 트레이스를 조회하여 확인합니다. 집계는 그대로 유효합니다. |

서비스 및 트랜잭션 요약에는 Apdex 계산에 사용한 T 값인 `apdexThreshold`가 포함됩니다.
서비스 요약에는 `health`와 `healthReasons`도 포함됩니다. 임계값을 넘은 각 지표는 `metric`
(`errorRate` 또는 `p95`), `level`, `value`, `threshold`로 표시합니다. `sparkline`에는 각 버킷의 요청 수, 오류 수, p95가 포함되며,
`currentVersion`과 `currentVersionSince`에는 가장 최근에 관측한 버전과 해당 버전을
처음 관측한 시점이 각각 표시됩니다. 서비스 또는 트랜잭션 상세 정보에는 `latencyDistribution`이 포함됩니다. 이 필드에는 요청이 포함된 히스토그램
버킷만 나열하며, 각 버킷은 `lowerTime`, `upperTime`, `count`로 표시하고 전체 범위는
가장 빠른 요청과 가장 느린 요청 사이로 제한합니다.

## 서비스 정의 관리

정의에는 서비스의 소유자와 중요도를 기록합니다. `namespace`와
서비스 이름을 키로 사용하므로 모든 환경에 적용되며, 서비스가 데이터를 보고하기 전에도 정의를 만들 수 있습니다.

```http
PUT /api/v1/apm/service-definitions/checkout?namespace=shop
Content-Type: application/json

{"description": "Takes orders and payments.", "teamId": "<team id>", "ownerId": "<user id>", "tier": "p0", "lifecycle": "production", "repositoryUrl": "https://github.com/acme/checkout", "tags": {"domain": "orders", "pci": ""}, "apdexThreshold": 300000, "aliases": ["order_service", "Order Center"], "dataSources": {"logs": [{"stream": "default", "filter": "service_name = 'order_service'"}], "metrics": [{"selector": "{service=\"checkout\"}"}], "dashboards": ["<dashboard id>"], "links": [{"name": "Runbook", "url": "https://wiki.example.com/checkout"}]}, "archived": false}
```

| 필드 | 참고 |
|---|---|
| `description` | 최대 2,000자입니다. |
| `teamId` | 조직의 팀 또는 `null`입니다. 팀을 삭제하면 이 값을 지웁니다. |
| `ownerId` | 조직의 멤버 또는 `null`입니다. |
| `tier` | 중요도가 가장 높은 `p0`부터 `p5`까지의 값 또는 `null`입니다. |
| `lifecycle` | `production`, `staging`, `experimental`, `deprecated` 또는 `null`입니다. |
| `repositoryUrl` | `http`, `https`, `ssh`, `git` 또는 `git+ssh` URL, `user@host:path`, 또는 `null`입니다. 주소에는 공백을 넣을 수 없으며 최대 2,048자입니다. 비밀번호와 HTTP(S) 주소의 사용자 이름은 `****`로 저장합니다. 서비스가 리포지토리를 보고하지 않을 때 표시합니다. |
| `tags` | `{ "key": "value" }` 형식의 태그를 최대 32개 지정할 수 있습니다. 키는 영문 소문자, 숫자, `_ . - /`를 사용해 1~64자로 작성합니다. 값은 앞뒤 공백 없이 최대 128자이며, 키만 지정하려면 값을 비워 둡니다. |
| `apdexThreshold` | 서비스의 Apdex 임계값 T입니다. 0보다 크고 60,000,000(1분) 이하여야 합니다. `null`이면 500 ms를 사용합니다. |
| `aliases` | 로그, 메트릭 및 기타 시스템에서 서비스에 사용하는 별칭을 최대 20개 지정할 수 있습니다. 각 별칭은 앞뒤 공백 없이 1~128자여야 합니다. 대소문자를 구분하지 않으며, 별칭을 중복 지정하거나 서비스 자체의 이름 또는 같은 조직 내 다른 서비스의 이름이나 별칭을 사용할 수 없습니다. 생략하면 저장된 정의의 별칭을 유지합니다. |
| `dataSources` | 서비스 데이터의 위치입니다. `logs`(`stream`과 선택 사항인 `filter`, 최대 2,000자의 불리언 SQL 표현식), `metrics`(`selector`, `{service="checkout"}`와 같은 PromQL 셀렉터), `dashboards`(대시보드 ID), `links`(`name`과 `http` 또는 `https` 형식의 `url`)를 각각 최대 10개 지정할 수 있습니다. 생략하면 저장된 정의의 데이터 소스를 유지합니다. |
| `archived` | `true`이면 카탈로그의 기본 보기에서 서비스를 숨깁니다. 생략하면 저장된 정의의 상태를 유지합니다. |

정의를 저장할 때 `keyTransactions`는 그대로 유지합니다. 주요 트랜잭션은 한 번에 하나씩 변경합니다. 응답은
`namespace`, `name`, `keyTransactions`, `updatedBy`, `updatedAt`을 포함한 저장된 정의입니다.
`DELETE`는 `204`를 반환하며, 서비스에 정의가 없으면 `404`를 반환합니다.

### 주요 트랜잭션에 별표 표시

```http
POST /api/v1/apm/service-definitions/checkout/key-transactions?namespace=shop
Content-Type: application/json

{"transaction": {"name": "POST /orders", "kind": "http"}, "key": true}
```

`key: true`는 엔드포인트를 `keyTransactions`에 추가하고, `false`는 제거합니다. 현재와 같은 상태를
요청하면 아무것도 변경하지 않습니다. 서비스에 정의가 없으면 새로 만듭니다. 서비스마다 주요
트랜잭션을 최대 50개 지정할 수 있으며, 한도 초과분을 모은 `__other__` 행은 지정할 수 없습니다. 응답은 변경 후
서비스 정의입니다.

## 서비스의 데이터 수집 범위 조회

`GET /api/v1/apm/services/{service}/coverage`에 필수 매개변수인 `namespace`와 `environment`를 지정합니다.
조회 범위의 종료 시각인 `to`는 마이크로초 단위로 지정하며, 생략하면 현재 시각을 사용합니다. `to` 직전 24시간을
확인하고 결과를 5분간 캐시합니다.

```json
{
  "from": 1792230096695000,
  "to": 1792316496695000,
  "logs": { "state": "reported", "found": ["default"] },
  "metrics": { "state": "missing" },
  "profiles": { "state": "reported", "found": ["cpu", "alloc_space"] },
  "rum": { "state": "unknown" }
}
```

| 신호 | `reported` 조건 | `found` |
|---|---|---|
| `logs` | `service.name`, `service_name` 또는 `service` 필드가 있는 로그 스트림에 해당 서비스의 로그가 한 줄 이상 있습니다. `default`부터 최대 8개 스트림을 확인합니다. | 로그 스트림 목록입니다. |
| `metrics` | `to` 시점의 `count(last_over_time({"service.name"="<service>"}[1h]))` 값이 0보다 큽니다. | 시계열 개수입니다. |
| `profiles` | 프로파일 스트림에 해당 서비스의 프로파일이 있습니다. | 프로파일 유형 목록입니다. |
| `rum` | 브라우저 동작에 해당 서비스의 최신 샘플 트레이스 5개 중 하나가 포함되어 있습니다. | 해당 세션입니다. |

`missing`은 조회 결과가 없음을 뜻합니다. `unknown`은 조회에 실패했거나 3초를
초과했음을 뜻합니다. `rum`은 `missing`을 반환하지 않습니다. 샘플 트레이스로 세션이 서비스에 도달했는지는 확인할 수 있지만,
도달한 세션이 전혀 없다고 판단할 수는 없습니다.

## 서비스 실행 정보 조회

`GET /api/v1/apm/services` 및 `GET /api/v1/apm/services/{service}`는 각 서비스 요약에
`profile`을 포함합니다. 조회 범위에서 데이터를 보고한 인스턴스를 바탕으로 작성하며, `version` 매개변수를 지정하면
해당 버전의 인스턴스만 사용합니다. 각 목록은 같은 값을 공유하는 인스턴스가 많은 순서대로 최대 5개 항목을
`{ "value": "1.8.2", "instances": 4 }` 형식으로 반환합니다.

| 필드 | 참고 |
|---|---|
| `instanceCount`, `hostCount` | 인스턴스 수와 고유한 `host.name` 값의 수입니다. |
| `versions` | 인스턴스에서 실행한 버전입니다. 롤아웃 중에는 두 버전을 표시합니다. |
| `languages`, `runtimes`, `frameworks` | 각각 `telemetry.sdk.language`, `process.runtime.name`과 해당 버전, 진입 스팬의 계측 라이브러리가 명시하는 프레임워크입니다. |
| `regions`, `clusters`, `k8sNamespaces`, `workloads` | 각각 `cloud.region`, `k8s.cluster.name`, `k8s.namespace.name`, 그리고 `k8s.deployment.name` 또는 `k8s.statefulset.name`입니다. |
| `repositories`, `commits` | 인증 정보를 제외한 `vcs.repository.url.full` 또는 `git.repository_url`, 그리고 `vcs.ref.head.revision` 또는 `git.commit.sha`입니다. |
| `entryKinds` | 서비스가 처리하는 진입 유형입니다. `http`, `rpc`, `messaging`, `span`을 사용합니다. |

`GET /api/v1/apm/services/{service}/instances`는 가장 최근에 관측한 순서대로
인스턴스를 최대 500개까지 개별적으로 나열합니다. `namespace`, `environment`와 선택 매개변수인 `version`, `from`,
`to`를 받습니다. 서비스와 환경이 모두 필요하며, 하나라도 없으면 `400`을 반환합니다. 각 항목에는 `instanceId`(
`service.instance.id`를 우선 사용하고, 없으면 `k8s.pod.name`, 그다음 `host.name`을 사용), `version`, `firstSeenAt`,
`lastSeenAt`, 인스턴스가 마지막으로 보고한 속성의 맵인 `attributes`, 그리고 조회 범위의 처리 내역이
포함됩니다. 처리 내역은 요약과 같은 형식으로 서비스 임계값을 적용한 Apdex를 포함하는 `red`와 `sparkline`입니다.
한도를 초과한 인스턴스는 `instanceId`가 `__other__`인 한 항목으로 집계합니다.
조회 범위에서 요청을 처리했지만 아직 저장된 정보가 없는 인스턴스는 `attributes`를 비워서 표시합니다.

## 오류 그룹 상태 설정

```http
PUT /api/v1/apm/errors/<fingerprint>/issue
Content-Type: application/json

{"status": "investigating", "assigneeId": "<user id>", "teamId": "<team id>", "lastSeenAt": 1792316496695000}
```

`status`는 `open`, `investigating`, `resolved` 또는 `ignored`입니다. `assigneeId`는 조직의
멤버 또는 `null`이고, `teamId`는 조직의 팀 또는 `null`입니다. 선택 사항인 `lastSeenAt`은 조회자가 그룹을 마지막으로 확인한 시각이며, 단위는 마이크로초입니다.
`resolved`로 설정하면 해당 시각을 `resolvedAt`으로 기록합니다.

오류 요약은 상태를 `issue`로 반환합니다. 아직 상태를 설정하지 않았으면 `null`을 반환합니다. `issue.regressed`는
해결한 그룹의 오류가 `resolvedAt` 이후 다시 발생하면 `true`입니다. `unresolved` 필터는
이러한 그룹을 결과에 포함합니다. 조회 모델에 없는 핑거프린트의 상태를 설정하면 `404`를 반환합니다.

## 서비스 수준 목표 관리

서비스 수준 목표(SLO)는 이동 시간 구간을 기준으로 한 환경에서 서비스 전체 또는
특정 엔드포인트의 양호한 요청 비율을 보장합니다. 각 수치의 의미는
[서비스 수준 목표](/ko/apm#서비스-수준-목표)를 참조합니다.

```http
POST /api/v1/apm/slos
Content-Type: application/json

{"name": "Checkout availability", "namespace": "shop", "service": "checkout", "environment": "production", "transaction": null, "kind": "availability", "objective": 0.999, "windowDays": 30}
```

| 필드 | 설명 |
|---|---|
| `name` | 필수이며 최대 255 bytes입니다. |
| `description` | 선택 사항이며 최대 2,000 bytes입니다. |
| `namespace`, `service`, `environment` | 필수입니다. APM에서 사용하는 서비스 식별 값입니다. `service.namespace`가 없는 서비스는 `default` 네임스페이스에 속합니다. |
| `transaction` | 단일 엔드포인트는 `{ "name": "POST /orders", "kind": "http" }`로, 서비스 전체는 `null`로 지정합니다. |
| `kind` | `availability`: 실패하지 않은 요청을 양호한 요청으로 분류합니다. `latency`: 실패하지 않았고 소요 시간이 `latencyThreshold` 이하인 요청을 양호한 요청으로 분류합니다. |
| `latencyThreshold` | `latency`에서는 필수이며 양수여야 합니다. `availability`에서는 `null`로 설정하거나 생략해야 합니다. |
| `objective` | 양호한 요청의 비율입니다. `0.999`처럼 0보다 크고 1보다 작은 값을 지정합니다. |
| `windowDays` | `7`, `28`, `30` 중 하나입니다. |

`POST`와 `PUT`은 저장한 SLO를 `id`, `createdBy`, `createdAt`, `updatedBy`,
`updatedAt`과 함께 반환합니다. `GET /api/v1/apm/slos`는 조직의 모든 SLO를 상태 객체로 반환합니다.
`namespace`, `service`, `environment`를 함께 전달하면 특정 서비스의 SLO만 조회할 수 있습니다. 이동 시간 구간은
호출 시점에 끝나므로 공통 시간 범위 매개변수를 적용하지 않습니다.

| 상태 필드 | 설명 |
|---|---|
| `slo` | 저장된 SLO입니다. |
| `state` | `healthy`, `at_risk`, `breached`, `noData` 중 하나입니다. |
| `sli` | 이동 시간 구간의 전체 요청 중 양호한 요청의 비율입니다. 요청이 없으면 `null`입니다. |
| `goodRequests`, `totalRequests` | `sli`를 계산하는 데 사용하는 요청 수입니다. 지연 시간 SLO는 지연 시간 히스토그램에서 `goodRequests`를 추정하므로 소수 값이 나올 수 있습니다. |
| `budgetRemaining` | `1 - (1 - sli) / (1 - objective)`입니다. 목표를 위반하면 음수가 되며, 요청이 없으면 `null`입니다. |
| `burnRates` | `oneHour`, `sixHours`, `oneDay`: 각각 최근 1시간, 6시간, 24시간의 `(1 - sli) / (1 - objective)`입니다. 요청이 없으면 `null`입니다. |

`GET /api/v1/apm/slos/{id}`는 `status`와 `history`를 반환합니다. `history`에는 이동 시간 구간 내
요청이 있었던 UTC 날짜별 항목이 하나씩 있으며, 오래된 항목부터 나열합니다. 각 항목에는 마이크로초 단위의 `dayStart`, `sli`, `goodRequests`,
`totalRequests`가 있습니다.

`DELETE`는 `204`를 반환합니다. 소진율 알림처럼 SLO를 모니터링하는 알림 규칙이 있으면
`409`를 반환하므로 해당 규칙을 먼저 삭제합니다. SLO에 대한 알림 규칙은
`slo_burn_rate` 메트릭을 사용하는 APM 규칙입니다. [규칙 만들기](/ko/api/alerting/create-rule#apm-규칙)를 참조합니다.

## 트랜잭션 구분

서로 다른 유형의 트랜잭션이 같은 이름을 사용할 수 있습니다. 하나를 선택하려면 선택 매개변수 `kind`를 전달합니다.

```http
GET /api/v1/apm/transactions/POST%20%2Fcheckout?kind=http&service=checkout
```

지원하는 유형 값은 `http`, `rpc`, `messaging`, `span`, `other`입니다. 여러 서비스나 유형에서 같은
이름을 사용하면 `400`과 함께 `APM transaction identity is ambiguous; provide service,
namespace, environment, and kind`를 반환합니다.

## 버전 비교

`baseline`과 `candidate`에 서로 다른 값을 지정합니다. 특정 서비스만 비교하려면 `service` 필터를 추가합니다.

```bash
curl --get 'http://localhost:5080/api/v1/apm/versions/compare' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'service=checkout' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'baseline=2.3.1' \
  --data-urlencode 'candidate=2.4.0'
```

응답에는 `baseline`과 `candidate`가 포함되며, 각각 `version`, `sampleCount`,
`red`를 담습니다. 응답에는 `delta`, `status`, `regressedTransactions`, `regressedErrors`도 포함됩니다. 각 성능 저하
목록에는 항목이 최대 20개 있습니다.

| 필드 | 설명 |
|---|---|
| `sufficientData` | 두 버전 모두 설정된 최소 샘플 수를 충족할 때만 `true`입니다. 기본값은 버전당 요청 1,000건입니다(`​[apm.version_comparison].min_requests_per_version`). |
| `status` | `insufficient_data`, `regressed`, `improved`, `neutral` 중 하나입니다. 후보 버전의 오류율이 기준 버전보다 1%p 이상 높고 기준 버전의 1.5배 이상이거나, p95가 20% 이상이면서 50 ms 이상 증가하면 `regressed`입니다. 두 지표 중 하나가 같은 기준 이상으로 감소하고 어느 쪽도 그 기준 이상으로 증가하지 않으면 `improved`입니다. `sufficientData`가 `false`이면 `insufficient_data`입니다. |
| `delta` | `requestCountAbsolute`와 `requestCountRelative`, `errorRateAbsolute`와 `errorRateRelative`, `p95AbsoluteTime`과 `p95Relative`를 포함합니다. 기준값이 0이거나 없으면 상대값은 `null`입니다. |

`candidate` 또는 `baseline`이 없거나 두 버전이 같으면 `400`을 반환합니다.

## 서비스 버전 조회

`GET /api/v1/apm/services/{service}`는 지정한 시간 범위에서 관측한 버전을 `versions`로 반환합니다. 각 버전에는
해당 범위의 요청 처리 지표인 `red`와, 같은 서비스에서 최초 관측 시점이 바로 앞선 버전을 기준으로
[버전 비교](#버전-비교)와 같은 방식으로 평가한 결과인 `verdict`가 있습니다.

| 필드 | 설명 |
|---|---|
| `previous` | 비교 기준이 되는 이전 버전입니다. |
| `status` | `regressed`, `improved`, `neutral`, `insufficient_data` 중 하나입니다. |
| `worse` | `status`가 `regressed`일 때 악화된 지표입니다. `errorRate`, `latency` 또는 둘 다 포함합니다. |
| `delta` | 버전 비교와 같은 형식이며, 이전 버전을 기준으로 계산합니다. |

가장 먼저 관측한 버전에는 `verdict`가 없습니다. 요청에 버전 필터를 적용해도
집계 범위는 좁아지지 않습니다. 서비스 전체에서 모든 버전을 조회합니다.

## 오류 발생 내역 조회

`GET /api/v1/apm/errors`는 페이지 결과와 함께 `status` 필터를 통과한 모든 그룹의
`breakdown`을 반환합니다. 현재 페이지의 그룹으로 제한하지 않습니다. `GET /api/v1/apm/errors/{fingerprint}`는 해당
그룹의 `breakdown`을 반환합니다. 여기에는 `versions`, `environments`, `languages`가 있으며, 각각 `value`와 발생 횟수인 `count`로 구성된 항목을
발생 횟수가 많은 순서대로 나열합니다. 스팬이 보고하지 않은 값은 비어 있습니다. 상위
7개 값 이후의 나머지 값은 `__other__`로 합산합니다. 언어는 서비스의
`telemetry.sdk.language` 값입니다.

## 오류 그룹화 규칙 관리

오류가 발생하면 규칙을 사용해 유형, 프레임, 엔드포인트에 따른 기본 방식과 다르게 그룹화할 수 있습니다. 시스템은
`position` 순서대로 규칙을 검사하고 처음 일치하는 규칙을 적용합니다.

```http
POST /api/v1/apm/error-rules
Content-Type: application/json

{"name": "Upstream timeouts", "serviceNamespace": "shop", "serviceName": "checkout",
 "errorType": "*Timeout*", "message": "", "frame": "", "endpoint": "", "action": "merge", "enabled": true}
```

| 필드 | 설명 |
|---|---|
| `name` | 최대 128자입니다. 병합된 그룹의 이름으로 사용합니다. |
| `serviceNamespace`, `serviceName` | 규칙을 적용할 서비스입니다. `serviceName`이 비어 있으면 모든 서비스에 적용합니다. 네임스페이스를 지정하려면 서비스 이름도 지정해야 합니다. |
| `errorType`, `message`, `frame`, `endpoint` | 각각 오류 유형, 예외 메시지, 첫 번째 애플리케이션 프레임, 엔드포인트에 적용하는 패턴이며, 최대 256자입니다. 대소문자를 구분하지 않고 전체 텍스트를 비교하며, `*`는 임의의 텍스트와 일치합니다. 빈 패턴은 모든 값과 일치합니다. 패턴을 하나 이상 지정해야 합니다. |
| `action` | `merge`: 규칙에 일치하는 서비스의 오류를 하나의 그룹으로 병합합니다. `ignore`: 해당 오류를 그룹화하지 않지만, 관련 요청은 계속 실패로 집계합니다. |
| `enabled` | 비활성화한 규칙은 보관하지만 검사하지 않습니다. 기본값은 `true`입니다. |

응답은 `id`, `position`, `updatedBy`, `updatedAt`을 포함한 규칙을 반환합니다. 조직당
최대 100개의 규칙을 저장할 수 있습니다. `PUT /api/v1/apm/error-rules/order`에 `{"ids": [...]}`를 전달하면 지정한 규칙을
전달한 순서대로 맨 앞에 배치하고 나머지 규칙을 뒤에 배치한 후, 새 순서로 규칙을 반환합니다.

변경 사항은 저장한 노드에서 즉시, 다른 노드에서는 30초 이내에 적용됩니다. 각 노드는 적용 시점 이후에
관측한 오류에만 변경 사항을 적용합니다. 기존 그룹은 그대로 유지합니다.

## 서비스 맵 조회

`GET /api/v1/apm/map`은 공통 시간 범위, `environment`, `namespace` 매개변수를 받습니다.
응답에는 `nodes`, `edges`, `namespaces`(해당 환경 내 서비스의 네임스페이스), `environments`(모든 환경),
`truncated`(트래픽이 가장 많은 노드 400개만 포함하면 `true`)가 포함됩니다.

| 필드 | 설명 |
|---|---|
| `nodes[].id` | `service:<name>`, `topic:<name>` 또는 서비스의 호출 대상인 `<category>:<target>`입니다. |
| `nodes[].kind` | `service`, `external`, `topic` 중 하나입니다. 외부 노드에는 `category`도 포함됩니다. |
| `nodes[].red` | `requestCount`, `errorCount`, `errorRate`, `p95Time`입니다. 서비스가 처리한 요청이나 외부 노드 또는 토픽이 받은 요청을 집계합니다. 서비스에는 `health`, `namespace`, `environments`도 포함됩니다. |
| `edges[].kind` | `call`, `publish`(토픽으로 발행), `consume`(토픽에서 소비) 중 하나입니다. |
| `change` | 에지나 노드를 길이가 같은 직전 구간과 비교합니다. 직전 구간에 없었으면 `new`, 현재 구간에 없으면 `gone`입니다. 직전 구간에 데이터가 전혀 없으면 이 필드를 생략합니다. |

서비스 간 호출 데이터는 서비스 그래프에서 가져오며, 가장 느린 1분 구간의 P95를 사용합니다. 나머지 데이터는
APM 버킷에서 가져옵니다. `GET /api/v1/apm/map/edge`는 동일한 매개변수에 더해 `source`와 `target` 노드 ID를 받습니다.
응답에는 `kind`, `red`, `trend`, `operations`(`name`, `kind`, `red`), `everyCaller`
(`operations`가 모든 호출자의 요청을 포함하는 대상 서비스의 엔드포인트 목록이면 `true`), `errors`
(대상 서비스의 오류 그룹)가 포함됩니다.

## 서비스의 영향 범위 조회

`GET /api/v1/apm/blast-radius`는 필수 매개변수인 `service`와 공통 시간 범위 및
`environment` 매개변수를 받습니다. 네임스페이스에 관계없이 해당 환경의 전체 맵을 조회합니다.
응답에는 `meta`, `service`(서비스 자체의 노드로, 지정한 범위 내 맵에 없으면 생략),
`upstream`(서비스를 호출하는 노드, 최대 3홉), `downstream`(서비스가 호출하거나 메시지를 발행하는 대상,
최대 2홉)이 포함됩니다. 각 방향에는 노드가 최대 30개 포함되며, 비정상 노드를 먼저 표시합니다. 직전 구간과 비교해 사라진 호출은
제외합니다.

| 필드 | 설명 |
|---|---|
| `id`, `kind`, `name`, `namespace`, `category` | [서비스 맵](#서비스-맵-조회)에서 사용하는 노드 정보입니다. |
| `hops` | 노드와 서비스 사이의 호출 단계 수입니다. 직접 호출하거나 호출되는 노드는 `1`입니다. |
| `via` | 해당 노드에 도달할 때 거치는 노드로, 서비스에 한 홉 더 가깝습니다. |
| `health` | 서비스 자체의 상태입니다. 호출 대상의 경우 호출 실패를 기준으로 상태를 판단합니다. |
| `red`, `call` | 처리하거나 받은 요청의 지표와 해당 노드와 `via` 사이의 호출 정보입니다. |

## 배포 보고 및 목록 조회

`POST /api/v1/apm/deployments`는 배포 정보를 JSON으로 받고, `id`,
`createdBy`, `createdAt`을 추가한 배포 정보와 함께 `201`을 반환합니다. 필드, 제한 사항, CI 예시는
[배포](/ko/apm/deployments#ci에서-배포-보고)를 참조합니다. 서비스와 환경의 이름에는
조직의 명명 규칙, 환경 매핑, 별칭을 적용합니다.
리포지토리 주소는 비밀번호를 마스킹하여 저장합니다. 구성 변경이나 기능 플래그를 보고할 때는
`kind`를 각각 `configuration` 또는 `feature_flag`로 설정하며, `version`은 필요하지 않습니다.

`GET /api/v1/apm/deployments`는 `service`, `namespace`, `environment`, 그리고 마이크로초 단위의 시간 범위를 지정하는 `from`과 `to`를
받습니다. 최신순으로 배포를 최대 200개 반환합니다. 네임스페이스나 환경을 지정하지 않고 보고한 배포는
해당 항목의 모든 값에 대해 목록에 표시됩니다.

## APM 설정 조회 및 저장

`GET /api/v1/apm/settings`는 조직의 설정을 반환합니다. `PUT`은 설정 전체를 교체하고
저장한 설정을 반환합니다.

```json
{
  "health": {
    "errorRateWarning": 0.02,
    "errorRateCritical": 0.1,
    "p95WarningTime": 500000,
    "p95CriticalTime": 2000000
  },
  "apdexThreshold": 500000,
  "longTaskTime": 1000000,
  "namingRules": [{ "pattern": "^(checkout)-[a-z0-9]{5}$", "replacement": "$1" }],
  "environmentMap": [{ "from": "Production", "to": "production" }],
  "aliases": [{ "aliasNamespace": "shop", "alias": "checkout-v1", "namespace": "shop", "service": "checkout" }],
  "metadataRules": { "teamFromTier": "p1", "ownerFromTier": "p0", "repositoryFromTier": null }
}
```

생략한 필드에는 기본값을 적용합니다. 이름 앞뒤의 공백은 제거하며, 별칭의 네임스페이스가 비어 있으면 `default`를 사용합니다.
제한 사항과 각 설정의 기능은 [APM 설정](/ko/apm/settings)을 참조합니다. 저장한 노드에는 변경 사항을 즉시 적용하고,
나머지 노드에는 30초 이내에 적용합니다.

플랫폼의 카디널리티 제한은 `GET`으로 조회하고 `PUT
/api/v1/settings/apm_limits`로 교체합니다. 두 요청 모두 `sys.settings.limits.manage` 권한이 필요합니다. 요청 본문에는
`servicesPerOrgHour`, `transactionsPerServiceHour`, `dependenciesPerServiceHour`,
`operationsPerDependencyHour`, `errorGroupsPerServiceHour`, `versionsPerServiceHour`,
`instancesPerServiceHour`가 포함되며, 각 값의 범위는 1~100000입니다.

## 응답 메타데이터 조회

모든 엔드포인트는 공통 `meta` 객체를 반환합니다.

```json
{
  "range": {
    "from": 1785801600000000,
    "to": 1785888000000000
  },
  "resolution": "minute",
  "projectionStartedAt": 1785798000000000,
  "lastCompleteBucketAt": 1785887940000000,
  "dataQuality": {
    "partial": false,
    "gaps": [],
    "overflowDimensions": []
  },
  "activationBoundary": false
}
```

- `activationBoundary: true`이면 `projectionStartedAt` 이전 구간의 데이터가 완전하지 않은 것으로 간주합니다.
- `dataQuality.partial: true`이면 데이터가 완전하지 않은 것으로 간주하고, 확정된 0으로 해석하지 않습니다.
- 큐, 리포지토리, 플러시, 지연 데이터, 카디널리티 또는 종료 관련 장애가 있는지 `gaps`에서 확인합니다.
- `lastCompleteBucketAt`을 사용해 최신 데이터가 아직 확정 중인지 확인합니다.
- 카디널리티가 높은 세부 분석 결과를 사용하기 전에 `overflowDimensions`를 확인합니다.

## 오류

| 상태 | 원인 |
|---|---|
| `400` | 매개변수가 유효하지 않습니다. 지원하지 않는 `sort`(`unsupported APM sort field`), 1~200 범위를 벗어난 `limit`, 비어 있거나 크기 제한을 초과한 필터(`invalid APM service filter`), 최대 길이를 초과한 시간 범위(`APM query range exceeds configured maximum`), 시작보다 앞선 종료 시점(`APM range end precedes start`), 알 수 없는 `direction` 또는 `resolution`, 위의 검증 조건을 충족하지 않는 SLO(`SLO objective must be between 0 and 1, exclusive`), 또는 `namespace`, `service`, `environment` 중 하나 이상을 누락한 SLO 목록 필터가 원인입니다. |
| `403` | 토큰에 호출에 필요한 권한이 없습니다. |
| `404` | 지정한 범위에 해당 오류 핑거프린트, 트랜잭션, 서비스 또는 SLO가 없습니다. |
| `409` | 삭제하려는 SLO를 알림 규칙이 아직 모니터링하고 있습니다. |
