두 경로 모두 `sys.signing_keys.rotate` 권한이 있는 시스템 범위 세션이 필요합니다. 조직 범위 세션이나 API 토큰을 사용하면 `403`을 반환합니다. [워크스페이스 선택](/ko/api/auth/select-organization)을 사용해 세션을 `_sys` 조직으로 전환합니다.

## 서명 키 목록 조회

```http
GET /api/v1/auth/jwt/secrets
```

서명 키의 메타데이터를 반환합니다. 키의 원시 바이트는 반환하지 않습니다.

<ResponseExample>
```json 200
[
  {
    "id": "3JtcPZ3AZJFyvBvSkJUia0N7wqo",
    "isPrimary": true,
    "createdAt": 1790000000000000,
    "retiredAt": null
  }
]
```
</ResponseExample>

## 서명 키 교체

```http
POST /api/v1/auth/jwt/rotate
```

새 기본 키를 생성하고 기존 기본 키를 사용 중지합니다. 새 토큰은 새 키로 서명합니다. 사용 중지된 키로 서명한 토큰은 키를 사용 중지한 시점부터 24시간 동안 유효합니다.

노드를 재시작할 필요가 없습니다. 각 노드는 첫 요청부터 새 키로 서명한 세션을 허용하고, 약 10초 이내에 새 키로 서명하기 시작합니다. 노드 간 시계 차이와 이 지연을 고려해, 키를 사용 중지한 후 24시간이 지나고 5분이 더 지나면 해당 키로 토큰을 검증하지 않습니다.

<ResponseExample>
```json 200
{
  "newKid": "<new-key-id>",
  "retiredKid": "<previous-key-id>",
  "activeCount": 2
}
```
</ResponseExample>

`activeCount`는 현재 토큰을 검증할 수 있는 키의 수입니다. `MS_AUTH_JWT_SECRET_OVERRIDE`로 서명 키를 고정한 배포는 자체 교체 정책을 따릅니다. [보안 및 멀티테넌시](/ko/security#jwt-서명-키)를 참조합니다.
