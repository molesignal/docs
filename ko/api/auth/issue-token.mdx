```http
POST /api/v1/me/api-tokens
```

로그인한 사용자로 동작하는 `mspat-<36>` 형식의 개인 토큰을 발급합니다. 평문 토큰은 발급 응답에만 표시되므로 즉시 저장합니다. 토큰이 아닌 로그인 세션에서만 호출할 수 있으며, `personal_tokens.manage` 권한이 필요합니다.

**본문**

| 필드 | 유형 | 필수 여부 | 설명 |
|---|---|---|---|
| `name` | string | 예 | 표시 이름입니다. 1~255자여야 합니다. |
| `policyId` | string | 아니요 | 토큰에 적용할 [권한 정책](/ko/identity/roles#권한-정책)의 ID입니다. 예: `builtin:data_intake`. 정책에 포함된 모든 권한을 보유해야 합니다. |
| `permissions` | string[] | 아니요 | 토큰에 고정할 조직 권한입니다. 지정하는 권한을 모두 보유해야 합니다. |
| `expiresInDays` | integer | 아니요 | 토큰의 유효 기간(일)입니다. 1~1825일로 제한됩니다. 만료되지 않는 토큰을 발급하려면 이 필드를 생략합니다. |

`policyId`와 `permissions` 중 하나만 지정합니다. 둘 다 생략하면 토큰은 사용자가 가진 모든 권한을 사용할 수 있습니다. 토큰은 요청 시점에 사용자가 보유한 권한을 초과할 수 없습니다. 사용자에게서 권한이 제거되면 해당 사용자의 토큰에서도 그 권한이 제거됩니다.

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -X POST http://localhost:5080/api/v1/me/api-tokens \
  -H 'content-type: application/json' \
  -d '{
    "name": "grafana-readonly",
    "permissions": ["streams.read", "streams.query", "dashboards.read"],
    "expiresInDays": 90
  }'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KE5hOsEc3lMC9qr9RWnPn0pqWF",
  "prefix": "k7m2q9xv4b",
  "name": "grafana-readonly",
  "tokenKind": "personal",
  "userId": "<user-id>",
  "policyId": null,
  "permissions": ["dashboards.read", "streams.query", "streams.read"],
  "applicationId": null,
  "serviceAccountId": null,
  "expiresAt": 1798000000000000,
  "lastUsedAt": null,
  "revoked": false,
  "createdAt": 1790000000000000,
  "token": "mspat-k7m2q9xv4b<secret>"
}
```
</ResponseExample>

`ms-cookies.txt`에는 [로그인](/ko/api/auth/login)으로 시작한 세션이 저장됩니다. `GET /api/v1/me/api-tokens/scopes`는 토큰의 권한 범위를 제한하는 데 사용할 수 있는 정책과 조직 권한을 나열합니다. `Authorization` 헤더에 토큰을 담아 전송합니다. 예: `Authorization: Bearer mspat-…`.

## 서비스 계정용 토큰

```http
POST /api/v1/auth/tokens
```

서비스 계정으로 동작하는 토큰을 발급합니다. 본문은 개인 토큰과 동일하며 `serviceAccountId`를 추가합니다. 호출에는 `api_tokens.issue` 권한이 필요합니다. 개인 토큰과 달리 API 토큰으로 발급을 요청할 수 있습니다. `policyId`와 `permissions`를 모두 생략하면 토큰 권한은 발급 시점에 서비스 계정의 역할에 포함된 권한 중 발급 요청자가 보유한 권한으로 고정됩니다. 이후 역할에 추가된 권한은 토큰에 반영되지 않으며, 역할에서 제거된 권한은 토큰으로 즉시 사용할 수 없게 됩니다.

```bash
curl -X POST http://localhost:5080/api/v1/auth/tokens \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "collector-production",
    "serviceAccountId": "<service-account-id>",
    "policyId": "builtin:data_intake",
    "expiresInDays": 365
  }'
```

**오류**

| 상태 | 원인 |
|---|---|
| `400` | `name`이 비어 있거나, `policyId`와 `permissions`를 모두 지정했거나, 빈 목록을 지정했거나, 알 수 없는 권한 또는 정책을 지정했거나, 서비스 계정이 비활성화되었습니다. |
| `403` | 요청한 범위에 호출자가 보유하지 않은 권한이 포함되어 있거나, API 토큰으로 개인 토큰 발급을 요청했거나, 필요한 권한(`personal_tokens.manage` 또는 `api_tokens.issue`)이 없습니다. |
| `404` | 시스템 범위에 API 토큰이 없거나 서비스 계정이 존재하지 않습니다. |
