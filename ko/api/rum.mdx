RUM API는 브라우저 및 모바일 클라이언트에서 이벤트를 수집하고 조회합니다. 모든 엔드포인트는
`/api/v1/rum` 접두사를 사용하며 Bearer 토큰이 필요합니다.

```http
Authorization: Bearer <token>
```

이벤트와 리플레이 세그먼트를 쓰려면 `rum.write` 권한이 필요합니다. 애플리케이션에 연결된 [클라이언트 토큰](/ko/api/auth/rum-token)에는
해당 애플리케이션에 대한 이 권한만 있습니다. 조회하려면 해당 영역의 읽기 권한이 필요합니다. `rum.events.read`, `rum.sessions.read`, `rum.replay.read`, `rum.issues.read`, `rum.analytics.read`, `rum.applications.read`, `rum.playlists.read` 중 하나입니다. 플랫폼 호출자는 `sys.telemetry.read` 권한을
보호된 `_sys` 범위에서 사용할 수 있습니다. 애플리케이션을 생성, 변경, 삭제하려면 `rum.applications.manage` 권한이 필요합니다. 이슈의 상태, 담당 팀,
또는 담당자를 설정하려면 `rum.playlists.manage` 권한이 필요합니다.

조회 결과에는 실제 사용자의 데이터가 포함됩니다. 필터에 `session.type`, `synthetics.*`, `ci_test.*` 중 하나를 지정하지 않으면 `synthetics` 또는 `ci_test` 유형의 세션을 제외합니다. [테스트 트래픽](/ko/rum/test-traffic)을 참조합니다. 필드에는 `feature_flags.<key>`, `context.<key>`, `usr.extra.<key>`, `view.custom_timings.<key>`와 같은 JSON 열의 키도 사용할 수 있습니다.

**유형**은 엔드포인트가 처리하는 행의 종류를 나타냅니다. `sessions`, `views`, `actions`, `errors`, `resources`, `longTasks`,
`vitals`, `logs`를 사용할 수 있습니다. 각 유형은 이름에서 `rum_` 접두사를
제거한 [스트림](/ko/rum/events#이벤트-저장-위치)에 해당합니다.

## 엔드포인트

| 메서드 및 경로 | 용도 |
|---|---|
| `POST /api/v1/rum/events` | 이벤트를 전송합니다. [RUM 이벤트 형식](/ko/rum/events)을 참조합니다. `rum.write` 권한이 필요합니다. |
| `POST /api/v1/rum/replay` | 리플레이 세그먼트를 전송합니다. `rum.write` 권한이 필요합니다. |
| `GET /api/v1/rum/replay/{sessionId}` | 세션의 리플레이 세그먼트를 조회합니다. |
| `GET /api/v1/rum/config` | 애플리케이션이 SDK에 전달하는 설정을 조회합니다. 클라이언트 토큰을 사용합니다. |
| `GET /api/v1/rum/applications` | 조직의 애플리케이션 목록을 조회합니다. |
| `POST /api/v1/rum/applications` | 애플리케이션을 생성합니다. `rum.applications.manage` 권한이 필요합니다. |
| `GET /api/v1/rum/applications/{id}` | 애플리케이션 하나를 조회합니다. |
| `PATCH /api/v1/rum/applications/{id}` | 애플리케이션의 이름, 플랫폼 또는 설정을 변경합니다. `rum.applications.manage` 권한이 필요합니다. |
| `DELETE /api/v1/rum/applications/{id}` | 애플리케이션을 삭제하고 클라이언트 토큰을 폐기합니다. `rum.applications.manage` 권한이 필요합니다. |
| `GET /api/v1/rum/schema/{type}` | 지정한 유형의 열과 각 열의 데이터 유형 및 단위를 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/search` | 지정한 유형의 행을 한 페이지씩 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/facets` | 필드에서 가장 자주 나타나는 값을 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/histogram` | 조건에 일치하는 행의 개수를 시간 구간별로 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/aggregate` | 조건에 일치하는 행의 개수, 합계, 평균, 백분위수를 그룹별 또는 시간 구간별로 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/keys` | JSON 열에 있는 키와 각 키가 포함된 세션을 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/distribution` | 조건에 일치하는 행에서 숫자 값이 어떻게 분포하는지 조회합니다. |
| `POST /api/v1/rum/panel-statement` | 대시보드 패널이 탐색기의 차트를 그리기 위해 실행하는 쿼리문을 반환합니다. |
| `GET /api/v1/rum/playlists` | 조직 또는 특정 애플리케이션의 재생 목록을 조회합니다. |
| `POST /api/v1/rum/playlists` | 처음에 포함할 세션을 지정해 재생 목록을 생성합니다. `rum.playlists.manage` 권한이 필요합니다. |
| `GET /api/v1/rum/playlists/{id}` | 재생 목록 하나와 그 목록에 포함된 세션을 조회합니다. |
| `PATCH /api/v1/rum/playlists/{id}` | 이름 또는 설명을 변경합니다. `rum.playlists.manage` 권한이 필요합니다. |
| `DELETE /api/v1/rum/playlists/{id}` | 재생 목록을 삭제합니다. `rum.playlists.manage` 권한이 필요합니다. |
| `POST /api/v1/rum/playlists/{id}/sessions` | 재생 목록에 세션을 추가합니다. `rum.playlists.manage` 권한이 필요합니다. |
| `DELETE /api/v1/rum/playlists/{id}/sessions/{sessionId}` | 재생 목록에서 세션을 제거합니다. `rum.playlists.manage` 권한이 필요합니다. |
| `GET /api/v1/rum/sessions/{id}/playlists` | 세션이 포함된 재생 목록을 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/analytics/funnel` | 일련의 단계를 순서대로 완료한 세션을 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/analytics/paths` | 세션에서 특정 페이지를 열기 전이나 후에 연 페이지를 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/analytics/retention` | 특정 기간에 처음 관측된 사용자 중 이후 각 기간에 다시 관측된 사용자 수를 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/heatmaps/clicks` | 사용자가 클릭한 페이지 요소와 요소 내 클릭 위치를 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/heatmaps/scroll` | 사용자가 페이지를 얼마나 아래까지 스크롤했는지 조회합니다. |
| `GET` 또는 `POST /api/v1/rum/heatmaps/snapshot` | 히트맵을 덧그릴 페이지의 기록을 조회합니다. `rum.replay.read` 권한이 필요합니다. |
| `POST /api/v1/rum/alerts/preview` | [RUM 지표에 대한 알림 규칙](/ko/rum/alerts)을 최근 구간에 적용했을 때의 결과를 미리 확인합니다. |
| `GET /api/v1/rum/issues` | 애플리케이션의 오류를 묶은 이슈와 지정한 범위 내 각 이슈의 발생 건수를 조회합니다. |
| `GET /api/v1/rum/issues/{id}` | 이슈 하나와 해당 이슈의 최신 세션 및 스택을 조회합니다. |
| `PATCH /api/v1/rum/issues/{id}` | 이슈의 상태, 담당 팀 또는 담당자를 설정합니다. `rum.issues.manage` 권한이 필요합니다. |
| `GET /api/v1/rum/{type}/{id}` | 지정한 유형의 행 하나를 모든 열과 함께 조회합니다. |
| `GET /api/v1/rum/sessions/{id}/timeline` | 세션의 모든 활동을 발생 순서대로 조회합니다. |
| `GET /api/v1/rum/sessions/{id}/related-traces` | 세션의 백엔드 트레이스를 조회합니다. |
| `GET`, `POST /api/v1/rum/sessions/{id}/comments` | 세션 리플레이의 댓글을 조회하거나 새 댓글을 작성합니다. |
| `PATCH`, `DELETE /api/v1/rum/sessions/{id}/comments/{commentId}` | 댓글을 수정하거나 삭제합니다. |
| `GET`, `POST /api/v1/rum/sessions/{id}/summary` | 세션의 AI 요약을 조회하거나 새로 생성합니다. |
| `GET /api/v1/rum/traces/{traceId}/session` | 백엔드 트레이스 ID가 포함된 요청을 보낸 세션을 조회합니다. |

[`GET /api/v1/auth/tokens/rum`](/ko/api/auth/rum-token)은 애플리케이션의 클라이언트 토큰을 반환합니다.

## 리플레이 세그먼트 전송

```http
POST /api/v1/rum/replay
```

```json
{
  "application": "checkout-web",
  "sessionId": "6f1c2b7e-1d5a-4c6b-9a3e-0a1b2c3d4e5f",
  "seq": 1,
  "events": [{ "type": 2, "timestamp": 1790000000000, "data": { "node": {} } }]
}
```

`sessionId`, `seq`, `events`는 필수입니다. SDK에 설정한 `env`, `service`, `version` 값도 함께 전송할 수 있습니다.
애플리케이션의 [보존 필터](/ko/rum/sampling#필터)는 이 값을 사용해 세션을 보존할지 결정하므로,
보존 대상이 아닌 세션의 세그먼트는 저장하지 않습니다. 다른 필드는 허용하지 않습니다. `events`에는 rrweb 이벤트를 넣습니다. 클라이언트 토큰은
연결된 애플리케이션에만 데이터를 씁니다. `application`을 생략할 수 있으며, 다른 값을 지정하면 `403`을 반환합니다. 다른 인증 정보를 사용하면
애플리케이션을 지정해야 합니다. 애플리케이션이 없으면 `404`를 반환합니다. 응답에는 저장된 세그먼트의 다음 정보가 포함됩니다.
`id`, `seq`, `eventCount`, `hasFullSnapshot`입니다.

`GET /api/v1/rum/replay/{sessionId}`는 `sessionId`, `segmentCount`, `events`를 반환합니다. `events`에는 세션의 모든
세그먼트에 포함된 이벤트가 발생 순서대로 들어 있습니다.

## 애플리케이션 관리

애플리케이션에는 `id`, `name`, `platform`, `settings`가 있습니다.

```json
{
  "id": "checkout-web",
  "name": "Checkout web",
  "platform": "browser",
  "settings": {
    "collectIp": true,
    "collectGeo": true,
    "defaultPrivacy": "mask",
    "issuesPerHour": 100,
    "scrub": ["secrets", "emails", "phones", "cards", "national_ids", "url_params"],
    "sessionSampleRate": 100,
    "retentionFilters": [],
    "keepErrors": true,
    "sdk": { "sessionReplaySampleRate": 20, "forwardConsoleLogs": ["warn", "error"] },
    "segments": [{ "id": "enterprise", "name": "Enterprise", "conditions": [{ "field": "usr.extra.plan", "op": "is", "values": ["enterprise"] }] }]
  },
  "createdBy": "<user-id>",
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```

| 필드 | 규칙 |
|---|---|
| `id` | 생성할 때만 지정할 수 있습니다. `A-Z`, `a-z`, `0-9`, `.`, `_`, `:`, `-` 중 1~64자로 구성합니다. 생략하면 이름에서 생성합니다. 변경할 수 없습니다. |
| `name` | 생성 시 필수입니다. 1~128자입니다. |
| `platform` | `browser`(기본값), `android`, `ios`, `flutter`, `react-native`, `other` 중 하나입니다. |
| `settings` | `collectIp`와 `collectGeo`는 불리언이며 기본값은 `true`입니다. `defaultPrivacy`는 `mask`(기본값), `mask-user-input`, `allow` 중 하나입니다. `issuesPerHour`는 애플리케이션이 시간당 생성하는 새 [이슈](/ko/rum/errors#시간당-새-이슈-한도) 수입니다. 범위는 1~10000이며 기본값은 100입니다. `scrub`은 이벤트를 저장하기 전에 제거할 민감한 텍스트의 유형 목록입니다. `secrets`, `emails`, `phones`, `cards`, `national_ids`, `url_params` 중에서 선택합니다. 기본적으로 모든 유형을 제거하며, 빈 목록을 지정하면 아무것도 제거하지 않습니다([RUM 개인정보 보호](/ko/rum/privacy#수신-단계에서-민감한-텍스트-제거) 참조). `sessionSampleRate`는 어떤 보존 필터에도 해당하지 않는 세션 중 보존할 비율입니다. 0~100 사이의 정수이며 기본값은 100입니다([RUM 데이터 샘플링](/ko/rum/sampling#서버에서-세션의-일부-보관) 참조). 100을 초과하면 `400`을 반환합니다. `retentionFilters`는 최대 10개의 [필터](/ko/rum/sampling#필터) 목록입니다. 각 필터는 `{ "name", "rate", "conditions" }`와 `id`를 포함합니다. `id`를 생략하면 서버가 이름에서 생성하며, 필터 이름을 변경해도 기존 `id`를 유지합니다. `PATCH`는 목록 전체를 교체합니다. `rate`는 0~100 사이의 정수입니다. 조건은 `{ "field", "op", "values" }` 형식입니다. `field`는 `env`, `service`, `version`, `source`, `session.type`, `geo.country_iso_code`, `browser.name`, `os.name`, `device.type` 중 하나이고, `op`는 `is` 또는 `is_not`이며, `values`에는 값이 1~20개 들어갑니다. 필터당 조건은 최대 5개입니다. 이름은 대소문자를 구분하지 않고 한 번만 사용할 수 있으며, `default`와 `errors`는 예약된 ID입니다. `keepErrors`는 보존하지 않는 세션의 오류를 보존하며 기본값은 `true`입니다. 목록이 유효하지 않으면 `400`을 반환합니다. `segments`는 최대 20개의 [세그먼트](/ko/rum/analytics#세그먼트) 목록입니다. 각 세그먼트는 `{ "name", "conditions" }`와 `id`를 포함합니다. `id`를 생략하면 이름에서 생성하며, 세그먼트 이름을 변경해도 기존 `id`를 유지합니다. `PATCH`는 목록 전체를 교체합니다. 조건은 `{ "field", "op", "values" }` 형식입니다. `field`는 `service`, `version`, `source`, `usr.id`, `usr.email`, `account.id`, `browser.name`, `os.name`, `device.type`, `geo.country_iso_code`, `geo.continent_code`, `geo.city`, `usr.extra.<key>` 중 하나이고, `op`는 `is` 또는 `is_not`이며, `values`에는 값이 1~20개 들어갑니다. 세그먼트당 조건은 1~5개입니다. `sdk`는 `remoteConfiguration`을 사용해 초기화한 SDK에 `GET /api/v1/rum/config`가 반환하는 설정입니다. `sessionSampleRate`와 `sessionReplaySampleRate`(각각 0~100), `defaultPrivacyLevel`, `trackUserInteractions`, `forwardConsoleLogs`(`debug`, `log`, `info`, `warn`, `error`의 목록) 중 필요한 항목을 지정합니다. 지정하지 않은 SDK 설정은 페이지에서 제공한 값을 사용합니다. 설정 항목을 생략하면 생성 시에는 기본값을 사용하고 `PATCH` 시에는 기존 값을 유지합니다. |

`POST`는 새 애플리케이션을 반환합니다. 식별자나 이름이 이미 있으면 `409`를 반환합니다. `PATCH`에는 `name`, `platform`,
`settings` 중 필요한 항목을 전달합니다. `DELETE`는 `{ "deleted": true }`를 반환합니다. 애플리케이션이 이미 전송한 이벤트는
보존 기간이 끝날 때까지 스트림에 남습니다.

## 행 검색

```http
GET /api/v1/rum/search?type=errors&from=1790000000000000&to=1790003600000000&filters=[{"field":"env","op":"=","value":"production"}]&limit=100
```

`POST`는 JSON 본문에 같은 이름의 파라미터를 받으며, URL에 담기에는 너무 긴 쿼리에 적합합니다. URL에서 `filters`, `freeText`,
`columns`는 JSON으로 인코딩한 목록입니다.

| 파라미터 | 유형 | 동작 |
|---|---|---|
| `type` | 문자열 | 필수입니다. 행의 유형입니다. |
| `from`, `to` | 정수 | Unix 에포크 이후 경과 시간을 마이크로초 단위로 지정한 범위입니다. `to`의 기본값은 현재 시각이며, `from`의 기본값은 `to`보다 24시간 전입니다. `to`는 `from`보다 커야 합니다. |
| `filters` | 목록 | 모든 행이 충족해야 하는 조건입니다. 아래를 참조합니다. |
| `freeText` | 문자열 목록 | 최대 8개 단어를 지정합니다. 각 단어는 대소문자를 구분하지 않고 해당 유형의 텍스트 열 중 하나에서 일치해야 합니다. |
| `columns` | 문자열 목록 | 응답에 포함할 열입니다. 생략하면 해당 유형의 기본 열을 반환합니다. 행을 식별하는 열은 항상 포함합니다. |
| `limit` | 정수 | 페이지당 행 수입니다. 1~5,000이며 기본값은 100입니다. |
| `cursor` | 문자열 | 이전 응답의 `nextCursor` 또는 `previousCursor`입니다. 다른 파라미터는 모두 생략하거나 이전 요청과 동일하게 지정합니다. |

**필터**는 `field`, `op`, `value`로 구성합니다. 필터는 최대 32개이며 각 값은 최대 512자입니다.

| `op` | 의미 |
|---|---|
| `=`, `!=` | 같거나 같지 않은지 확인합니다. `value`가 비어 있으면 각각 필드에 값이 없거나 있는지 확인합니다. |
| `in`, `not_in` | 필드 값이 목록에 포함되거나 포함되지 않는지 확인합니다. `value`는 `["Chrome","Safari"]`처럼 값 1~100개를 담은 JSON 목록입니다. |
| `contains` | 대소문자를 구분하지 않고 필드에 텍스트가 포함되는지 확인합니다. 텍스트 열과 JSON 문서에 적용합니다. |
| `>`, `>=`, `<`, `<=` | 숫자 또는 시간을 비교합니다. |
| `exists`, `missing` | 각각 필드에 값이 있거나 없는지 확인합니다. |

해당 유형에 없는 필드나 필드가 지원하지 않는 연산자를 사용하면 `400`을 반환합니다.

응답은 한 페이지의 행을 최신순으로 반환합니다.

```json
{
  "items": [
    { "timestamp": 1790000001600000, "error.message": "Payment provider timeout", "error.id": "0a9b8c7d-6e5f-4a3b-8c1d-2e3f4a5b6c70" }
  ],
  "hasMore": true,
  "nextCursor": "<cursor>",
  "previousCursor": null
}
```

각 행에는 `timestamp`와 요청한 열이 포함됩니다. JSON 열에는 문서가 들어 있습니다. 뷰와 세션은
각각 최신 버전만 한 번씩 표시합니다.

## 행 집계 및 정보 조회

`facets`는 페이지네이션을 제외한 `search` 파라미터에 `field`(필수)와 `limit`(1~100, 기본값 10)를 추가로 받습니다.
일치하는 행에서 해당 필드에 가장 자주 나타나는 값을 반환합니다.

```json
{ "field": "browser.name", "values": [{ "value": "Chrome", "count": 812 }, { "value": "Safari", "count": 247 }] }
```

집계가 시간 제한을 초과하거나 시스템이 혼잡하면 빈 목록을 반환하고 `unavailable`을 각각 `time_budget` 또는 `busy`로 설정합니다.
JSON 문서가 들어 있는 필드를 지정하면 `400`을 반환합니다. `feature_flags.checkout_v2`와 같은 문서 내 키는 값별로 집계합니다. `session.type`의 패싯은 모든 세션 유형을 집계합니다.

`keys`는 조회 조건, `column`(필수: `feature_flags`, `context`, `usr.extra`, `view.custom_timings` 중 하나), `limit`(1~500, 기본값 100)를 받습니다. `type`의 기본값은 `views`입니다. 가장 많은 세션에 나타난 키부터 반환합니다.

```json
{ "column": "feature_flags", "keys": [{ "key": "checkout_v2", "sessions": 812 }] }
```

`distribution`은 조회 조건, `field`(필수: 숫자 필드 또는 JSON 열 내 숫자 값의 키), `bars`(1~100, 기본값 40)를 받습니다. 저장된 행을 집계합니다. 최솟값부터 99번째 백분위수까지 같은 너비로 구간을 나눕니다. 마지막 구간은 99번째 백분위수를 초과하는 값도 집계하므로 `to`는 최댓값입니다. 모든 값이 같으면 구간 하나로 집계합니다.

```json
{
  "field": "view.loading_time",
  "unit": "ns",
  "rows": 812,
  "min": 90000000,
  "max": 41000000000,
  "p50": 800000000,
  "p75": 1400000000,
  "p95": 3100000000,
  "p99": 6000000000,
  "bars": [{ "from": 90000000, "to": 237750000, "rows": 12 }]
}
```

`histogram`은 동일한 조회 조건과 집계 구간을 정의하는 `bucketTime`(최소 1000), `originTime`을 받습니다. `originTime`은
첫 번째 구간의 시작 시각입니다. 생략하면 `from`을 사용하며, `from`보다 늦을 수 없습니다. 범위 하나에 최대 512개의 구간을 포함할 수 있습니다. 각 버킷의 형식은 `{ startTime, total, errors }`입니다. `errors`는 문제가 발생한 행을
집계합니다. 여기에는 오류가 있는 세션과 뷰, 사용자 불편 신호가 있는 액션, 상태 코드가 `400` 이상이거나
`0`인 요청이 포함됩니다. 이런 행을 집계하지 않는 유형에서는 `split`이 `false`입니다.

`GET /api/v1/rum/schema/{type}`은 다른 엔드포인트가 요청에서 받고 응답에서 반환하는 열 목록을 반환합니다.

```json
{
  "type": "views",
  "stream": "rum_views",
  "idField": "view.id",
  "versioned": true,
  "defaultColumns": ["view.id", "view.url_path", "view.loading_time"],
  "fields": [
    { "name": "view.loading_time", "dataType": "int64", "unit": "ns", "facetable": true, "indexed": false }
  ]
}
```

`dataType`은 `bool`, `int64`, `float64`, `utf8`, `json` 중 하나입니다. `unit`은 `ns`, `ms`, `epoch_ms`, `bytes`, `count`,
`score`, `percent`, `per_second`, `px`, `none` 중 하나입니다. 소요 시간은 SDK가 전송한 나노초 단위로 저장하며, 클라이언트가
표시 형식을 지정합니다. `epoch_ms`는 `session.start`와
`session.last_activity`처럼 Unix 에포크 이후 경과 시간을 밀리초 단위로 표현한 시점을 나타냅니다. 클라이언트는 이를 날짜와 시간으로 표시합니다. `facetable` 필드는 값별로 집계할 수 있고,
`indexed` 필드는 모든 행을 읽지 않고 필터링할 수 있습니다. `idField`는 각 행을 식별하는 열의 이름입니다.

## 행 집계

`aggregate`는 `search`의 선택 조건과 일치하는 모든 행을 집계합니다. 차트, 표, 지도에 표시할 수치를 반환합니다.
예를 들어 페이지별 또는 시간별 세션 수나 웹 바이탈 지표의 75번째 백분위수를 구할 수 있습니다.

```http
GET /api/v1/rum/aggregate?type=views&groupBy=["view.url_path_group"]&measures=[{"fn":"count","name":"views"},{"fn":"p75","field":"view.performance.lcp.timestamp","name":"lcp"}]&limit=5
```

| 매개변수 | 유형 | 동작 |
|---|---|---|
| `type`, `from`, `to`, `filters`, `freeText` | | `search`와 동일합니다. |
| `measures` | 목록 | 필수입니다. 집계 항목을 최대 16개 지정할 수 있습니다. 아래를 참조합니다. |
| `groupBy` | 문자열 목록 | 필드를 최대 2개 지정할 수 있으며, 필드 값의 조합마다 행을 하나 반환합니다. JSON 문서를 담은 필드 자체로는 그룹화할 수 없지만, `feature_flags.checkout_v2`처럼 문서의 키로는 그룹화할 수 있습니다. |
| `bucketTime`, `originTime` | 정수 | `histogram`과 동일합니다. 지정하면 막대마다 각 그룹에 대해 행을 하나 반환합니다. |
| `orderBy` | 문자열 | 집계 항목 이름, 그룹 필드 또는 `time`(그룹이 없는 막대)을 지정합니다. 생략하면 첫 번째 집계 항목을 기준으로 그룹의 순위를 매기고 막대는 시간순으로 정렬합니다. |
| `order` | `asc` 또는 `desc` | 생략하면 집계 항목은 내림차순으로, 그룹 또는 시간은 오름차순으로 정렬합니다. |
| `limit` | 정수 | 그룹 수입니다. 1~250 사이의 값을 지정하며, 기본값은 10입니다. 막대가 있으면 최대 20개 그룹을 반환하고, 각 그룹을 모든 막대에 걸쳐 추적합니다. |
| `estimate` | 불리언 | 기본값은 `true`입니다. 각 행에 보존 비율(`retention.rate`)에 따른 가중치를 적용해 전체 세션의 개수, 합계, 평균을 추정합니다. 백분위수에도 같은 가중치를 적용합니다. `false`이면 탐색기와 마찬가지로 실제로 저장한 행만 집계합니다. |

**집계 항목**에는 `fn`과 `field`가 있으며, `name`, `where`, `fallback`을 추가할 수 있습니다.

| `fn` | 의미 |
|---|---|
| `count` | 행 수를 반환합니다. `field`를 지정하면 해당 필드에 값이 있는 행만 셉니다. `estimate`를 활성화하면 보존 비율에 따라 보정합니다. |
| `stored` | 보존 비율과 관계없이 실제로 저장한 행의 수를 반환합니다. |
| `count_distinct` | `field`의 고유 값 개수를 반환합니다. `fallback`은 `field`에 값이 없을 때 사용할 필드를 지정합니다. 예를 들어 ID가 없는 사용자를 익명 ID로 구분할 수 있습니다. 사용자와 그 밖의 값은 관측한 그대로 세며, `estimate`를 활성화하면 세션(`session.id`) 수는 보존 비율에 따라 보정합니다. |
| `sum`, `avg`, `min`, `max` | 숫자 값의 합계, 평균, 최솟값, 최댓값을 각각 반환합니다. |
| `p50`, `p75`, `p90`, `p95`, `p99` | 숫자 값의 백분위수를 추정합니다. |

`where`는 `search`와 동일한 형식의 필터 목록입니다. 집계 항목은 필터를 충족하는 행만 집계합니다.
`{"fn":"count","where":[{"field":"session.error.count","op":"=","value":"0"}]}`은 오류가 없는 세션의 수를 셉니다. 집계 항목의
이름은 `name`을 사용합니다. `name`을 생략하면 `fn(field)`를 사용하고, 필드도 없으면 `fn`을 사용합니다. 두 집계 항목에 같은 이름을 사용할 수 없습니다. 해당 유형에
없는 필드를 지정하거나 숫자가 아닌 필드에 숫자 집계를 요청하면 `400`을 반환합니다.

```json
{
  "groupBy": ["view.url_path_group"],
  "measures": [
    { "name": "views", "fn": "count", "unit": "count" },
    { "name": "lcp", "fn": "p75", "field": "view.performance.lcp.timestamp", "unit": "ns" }
  ],
  "rows": [
    { "group": ["/checkout"], "values": [8031, 3400000000.0] },
    { "group": [null], "values": [212, null] }
  ]
}
```

각 행의 `group`에는 `groupBy`에 지정한 순서대로 그룹 값이 들어가고, `values`에는 집계 항목을 지정한 순서대로 결과가 들어갑니다. 시간별로 집계하면
막대의 시작 시각인 `startTime`도 포함합니다. 그룹 내 행에 값이 없으면 결과는 `null`이며, 값이 없을 때의 백분위수도
`null`입니다. `unit`은 `count`이거나 `schema`에서 제공하는 필드의 단위입니다. 뷰와 세션은 각각
최신 버전으로 한 번만 집계합니다. 일치하는 행이 없으면 그룹이나 막대가 있는 응답은 행을 반환하지 않습니다. 둘 다 없으면 행을 하나 반환하며, 개수는 `0`이고 나머지 집계 결과는 `null`입니다. 열람 권한이 없는 값은 마스킹된 텍스트로 반환합니다. 집계가 제한 시간을 초과하거나
시스템이 처리 중이면 행을 반환하지 않고 `unavailable`을 각각 `time_budget` 또는 `busy`로 설정합니다.

## 대시보드 패널의 SQL 문

```http
POST /api/v1/rum/panel-statement
```

[대시보드](/ko/dashboards) 패널이 [탐색기](/ko/rum/explorer#대시보드에-추가)와 동일한 결과를 그리는 데 사용하는
SQL 문을 반환합니다. `estimate`가 `false`인 `aggregate`와 동일한 행을 집계해 같은 수치를 얻습니다. 데이터를 읽지는 않습니다.
대시보드는 선택한 시간 범위에 대해 SQL 문을 실행하므로, SQL 문 자체에는 시간 범위를 지정하지 않습니다. `rum.events.read` 권한이 필요합니다.

```json
{
  "type": "views",
  "filters": [{ "field": "env", "op": "=", "value": "production" }],
  "chart": "timeseries",
  "measures": [{ "fn": "p75", "field": "view.loading_time", "name": "p75 Loading" }],
  "groupBy": ["browser.name"],
  "groupNames": ["Browser"],
  "limit": 5,
  "interval": "${interval}"
}
```

| 필드 | 유형 | 동작 |
|---|---|---|
| `type`, `filters`, `freeText` | | `search`와 동일합니다. |
| `chart` | 문자열 | 필수입니다. `timeseries`, `toplist`, `table`, `distribution` 중 하나를 지정합니다. |
| `measures`, `groupBy`, `orderBy`, `order`, `limit` | | `estimate`와 막대 처리 방식을 제외하면 `aggregate`와 동일합니다. `toplist`에는 그룹화 필드가 하나 필요합니다. `timeseries`는 최대 20개 그룹을 추적합니다. 각 집계 항목은 `name`을 열 이름으로 사용합니다. |
| `groupNames` | 문자열 목록 | 그룹 열의 이름을 순서대로 지정합니다. 이름을 지정하지 않은 그룹 열은 필드 이름을 사용합니다. |
| `field` | 문자열 | `distribution`에 필수입니다. 분포를 계산할 숫자 필드를 지정합니다. 값의 열 이름은 `groupNames`의 첫 번째 항목을 사용하고, 개수의 열 이름은 첫 번째 집계 항목의 `name`을 사용합니다. |
| `interval` | 문자열 | `timeseries`에 필수입니다. 시간 구간의 길이를 `${interval}`과 같은 대시보드 변수나 `15 minutes`와 같은 기간으로 지정합니다. |

```json
{
  "stream": "rum_views",
  "statement": "WITH \"__top\" AS (SELECT … LIMIT 5) SELECT date_bin(INTERVAL '${interval}', _timestamp) AS \"time\", … FROM \"rum_views_latest\" JOIN \"__top\" ON … GROUP BY 1, 2 ORDER BY 1, 2",
  "columns": [
    { "name": "time", "role": "time", "unit": "none" },
    { "name": "Browser", "role": "group", "unit": "none" },
    { "name": "p75 Loading", "role": "measure", "unit": "ms" }
  ],
  "limit": 10000
}
```

SQL 문은 `stream`을 읽고, `rum_views_latest` 또는
`rum_sessions_latest`를 통해 뷰나 세션의 최신 버전을 읽습니다. 선택 조건을 적용하며, 필터에 `session.type`, `synthetics.*`, `ci_test.*` 중 하나를 지정하지 않으면
합성 테스트와 CI에서 실행한 세션을 제외합니다. `columns`에는 반환하는 열이 순서대로 들어갑니다. 막대의
시작 시각인 `time`, 그룹, 집계 항목 순입니다. 집계 항목의 `unit`은 화면에 표시하는 단위입니다. 예를 들어 소요 시간은 `ms`로 표시합니다.

- `timeseries`는 막대와 그룹의 조합마다 행을 하나 반환합니다. 전체 시간 범위에서 첫 번째 집계 항목을 기준으로
  순위가 가장 높은 그룹을 선택합니다.
- `toplist` 또는 `table`은 요청한 순서대로 그룹마다 행을 하나씩, 최대 `limit`개까지 반환합니다.
- `distribution`은 최솟값부터 99번째 백분위수까지 막대 40개를 반환합니다. 마지막 막대에는 99번째 백분위수를 초과하는 값도 포함합니다.
  각 막대의 이름은 값의 표시 단위로 나타낸 시작값입니다.

`limit`은 패널이 요청하는 행 수입니다. 해당 유형에 없는 필드를 지정하거나, 요청한 조건으로 차트를 그릴 수 없거나
(`toplist`의 그룹화 필드가 정확히 하나가 아니거나 `timeseries`에 `interval`이 없는 경우), `interval`이 변수도
기간도 아니면 `400`을 반환합니다.

## 퍼널, 경로 및 리텐션

`/api/v1/rum/analytics`의 세 엔드포인트는 [RUM 분석](/ko/rum/analytics) 쿼리의 결과를 반환합니다. 각 엔드포인트는
`search`에서 세션, 뷰, 액션에 적용하는 조건인 마이크로초 단위의 `from`과 `to`, 그리고 모든 행이 충족해야 하는
`filters`를 받습니다. 일반적으로 애플리케이션(`application.id`)과 환경(`env`)을 필터링합니다. `GET`은 목록을 파라미터에 JSON으로 전달하므로
쿼리를 링크로 공유할 수 있습니다. `POST`는 JSON 본문에서 같은 이름을 사용합니다. `rum.analytics.read` 권한이 필요하며,
보호된 `_sys` 범위에서는 `sys.telemetry.read` 권한이 필요합니다. 집계가 너무 오래 걸리거나 시스템이 다른 작업으로 바쁘면 수치를 반환하지 않고 `unavailable`을
`time_budget` 또는 `busy`로 설정합니다. 응답에는 집계에 적용한 `from`과 `to`가 포함됩니다.

### 퍼널

```http
GET /api/v1/rum/analytics/funnel?filters=[{"field":"application.id","op":"=","value":"shop-web"}]&steps=[{"type":"views","filters":[{"field":"view.url_path_group","op":"=","value":"/cart"}]},{"type":"actions","name":"Paid","filters":[{"field":"action.target.name","op":"=","value":"Pay now"}]}]&windowSecs=1800&breakdown=browser.name
```

| 파라미터 | 유형 | 동작 |
|---|---|---|
| `from`, `to` | 정수 | 마이크로초 단위입니다. 생략하면 최근 7일을 사용합니다. |
| `filters` | 목록 | 각 단계가 자체 필터 외에 공통으로 충족해야 하는 조건입니다. |
| `steps` | 목록 | 필수입니다. 2~8개를 지정합니다. 각 단계에는 `views` 또는 `actions`를 지정하는 `type`, `search`와 같은 형식으로 해당 유형의 행에 적용하는 `filters` 목록, 선택 사항인 `name`이 있습니다. `name`을 생략하면 첫 번째 필터의 값을 사용합니다. |
| `windowSecs` | 정수 | 첫 단계부터 이후 단계까지 허용하는 최대 시간(초)입니다. 생략하면 시간 제한을 두지 않습니다. |
| `breakdown` | 문자열 | 첫 단계 행의 텍스트 필드입니다. 필드 값별로 퍼널을 생성합니다. 세션 수가 가장 많은 값 10개를 유지합니다. |

첫 단계에서는 조건을 충족하는 세션의 첫 번째 행을 기준으로 세션을 집계합니다. 이후 각 단계에서는 같은 세션에서 직전 단계의 행보다
시간상 뒤에 있으면서 현재 단계의 조건을 충족하는 첫 번째 행을 기준으로 집계합니다.

```json
{
  "groups": [
    {
      "value": null,
      "steps": [
        { "name": "/cart", "sessions": 4, "conversion": 1.0, "fromPrevious": null, "medianMs": null },
        { "name": "Paid", "sessions": 2, "conversion": 0.5, "fromPrevious": 0.5, "medianMs": 210000.0 }
      ]
    }
  ],
  "from": 1779400000000000,
  "to": 1780000000000000
}
```

그룹은 동일한 `breakdown` 값을 가진 세션의 퍼널입니다. 첫 단계의 세션 수를 기준으로 그룹을 정렬합니다.
전체 세션을 합친 그룹이나 해당 행에 값이 없는 세션의 그룹은 `value`가 `null`입니다. `conversion`은 첫 단계의
세션 수 대비 비율이고, `fromPrevious`는 직전 단계의 세션 수 대비 비율이며, `medianMs`는 직전 단계부터 경과한 시간의
중앙값입니다. 각 값이 의미 없는 단계에서는 `null`을 반환합니다. 필드가 텍스트 필드가 아니거나 해당 유형에 존재하지 않으면
요청이 `400`으로 실패합니다.

### 경로

| 파라미터 | 유형 | 동작 |
|---|---|---|
| `from`, `to`, `filters` | | `funnel`과 같습니다. 뷰 행을 사용합니다. |
| `anchor` | 문자열 | 경로가 시작되는 페이지입니다. 역방향 탐색에서는 경로가 끝나는 페이지입니다. 생략하면 각 세션의 첫 페이지를 사용하며, 역방향에서는 마지막 페이지를 사용합니다. |
| `backward` | 불리언 | 기준 페이지 이전의 페이지를 추적합니다. 기본값은 `false`입니다. |
| `depth` | 정수 | 기준 페이지 이후(또는 이전)의 페이지를 1~6개까지 추적합니다. 기본값은 3입니다. |
| `by` | 문자열 | 페이지를 식별하는 필드입니다. `view.url_path_group`(기본값), `view.url_path` 또는 `view.name`을 사용합니다. |

```json
{
  "columns": 3,
  "sessions": 9,
  "backward": false,
  "nodes": [
    { "column": 0, "page": "/products", "sessions": 2, "ends": 0 },
    { "column": 1, "page": "/cart", "sessions": 2, "ends": 0 },
    { "column": 2, "page": "/checkout", "sessions": 1, "ends": 1 }
  ],
  "links": [
    { "column": 0, "source": "/products", "target": "/cart", "sessions": 2 },
    { "column": 1, "source": "/cart", "target": "/checkout", "sessions": 1 }
  ],
  "from": 1779400000000000,
  "to": 1780000000000000
}
```

`columns`에는 `depth`보다 하나 더 많은 열이 있습니다. 경로의 기준 페이지는 0번 열에 위치하며, 역방향에서는 마지막 열에 위치합니다.
노드는 열에 속한 페이지로, 해당 페이지를 방문한 세션 수 `sessions`와 더 진행하지 않은 세션 수 `ends`를 포함합니다. 역방향에서는
해당 페이지에서 시작한 세션을 `ends`에 집계합니다. 링크는 `column`의 페이지를 다음 열의 페이지에 연결하고(역방향에서도 시간상 다음 페이지에 연결)
그 경로를 이용한 세션을 집계합니다. 페이지는 열린 순서대로 처리하고, 같은 페이지를 연달아 열면 한 번만 집계합니다.
각 열은 세션 수가 가장 많은 페이지 8개를 개별적으로 표시하고 나머지는 `__other__`로 묶습니다. `sessions`는
경로의 기준 페이지를 방문한 세션 수입니다.

### 리텐션

| 파라미터 | 유형 | 동작 |
|---|---|---|
| `from`, `to`, `filters` | | `funnel`과 같습니다. 세션 행을 사용합니다. `from`과 `to`를 생략하면 코호트를 구성할 수 있도록 현재 시점에서 `periods`의 두 배에 해당하는 기간을 거슬러 올라갑니다. 최소 범위는 14일이며, `week`의 경우 8주입니다. |
| `period` | `day` 또는 `week` | UTC 기준 하루 또는 월요일에 시작하는 UTC 기준 한 주입니다. 기본값은 `day`입니다. |
| `periods` | 정수 | 첫 기간 이후 1~30개 기간을 지정합니다. 기본값은 7입니다. |

```json
{
  "period": "day",
  "periods": 3,
  "cohorts": [
    { "startTime": 1779408000000000, "users": 1, "returned": [1, 0, null] },
    { "startTime": 1779494400000000, "users": 6, "returned": [0, null, null] }
  ],
  "from": 1779408000000000,
  "to": 1779753600000000
}
```

코호트는 요청한 시간 범위 내에서 `startTime`에 시작하는 기간에 처음 관측된 사용자 집단입니다. 사용자는
세션의 `usr.id`로 식별하며, 이 값이 없으면 `usr.anonymous_id`를 사용합니다. `returned`에는 이후 각 기간에 다시 관측된
코호트 사용자 수가 포함됩니다. `to` 시점까지 끝나지 않은 기간에는 `null`을 반환합니다.

## 히트맵

`/api/v1/rum/heatmaps`의 엔드포인트는 [RUM 히트맵](/ko/rum/heatmaps) 집계 결과를 반환합니다. 마이크로초 단위의 `from`과 `to`, 그리고 `filters`를 받습니다. 일반적으로 `application.id`, `view.url_path_group`, 창 너비(`display.viewport.width`)를 필터링합니다. `GET`은 목록을 파라미터에 JSON으로 전달합니다. `clicks`와 `scroll`은 `limit`도 받으며 `rum.analytics.read` 권한이 필요합니다. 추정값이 아닌 저장된 행을 집계합니다.

```json
{
  "clicks": 148,
  "elements": [
    {
      "element": "body>main>button:nth-of-type(2)",
      "name": "Pay now",
      "selector": "button.pay",
      "clicks": 92,
      "sessions": 60,
      "frustrated": 4,
      "pageX": 640.5,
      "pageY": 720.0,
      "cells": [[5, 4, 31], [6, 4, 28]]
    }
  ],
  "from": 1779400000000000,
  "to": 1780000000000000
}
```

`clicks`는 클릭 수가 가장 많은 요소를 1~300개 반환하며, 기본값은 100개입니다. `element`는 페이지에서 요소의 위치를 나타냅니다. `pageX`와 `pageY`는 페이지에서 해당 요소를 클릭한 위치의 평균 좌표입니다. `cells`는 요소를 10×10 셀로 나누며, 각 셀은 `[column, row, clicks]` 형식입니다.

```json
{
  "views": 310,
  "pageHeight": 4200,
  "medianDepth": 1800,
  "bands": [{ "depth": 800, "reached": 1.0 }, { "depth": 900, "reached": 0.97 }],
  "from": 1779400000000000,
  "to": 1780000000000000
}
```

`scroll`은 스크롤 깊이 기록이 있는 뷰의 수, 페이지 높이, 해당 뷰의 절반이 도달한 깊이를 반환합니다. 각 구간은 100픽셀이며, `reached`는 해당 깊이에 도달한 뷰의 비율입니다. 이 비율은 깊어질수록 증가하지 않습니다.

`snapshot`은 후보 중 하나의 `viewId`를 받으며 `rum.replay.read` 권한이 필요합니다. `candidates`에는 리플레이가 있는 해당 페이지의 뷰를 최신순으로 최대 20개 반환합니다. 각 후보에는 `sessionId`, `viewId`, `atTime`, 창의 `width`와 `height`가 포함됩니다. `snapshot`에는 표시할 뷰의 동일한 필드와 함께 `atTime` 직전의 마지막 전체 스냅샷부터 해당 시점의 화면을 재구성하는 rrweb `events`가 포함됩니다. 해당 페이지를 연 세션의 기록이 없으면 `snapshot`은 `null`입니다.

## 재생목록

[재생목록](/ko/rum/playlists)은 한 애플리케이션의 세션을 모아 이름을 붙인 목록입니다. 각 항목은 세션을 열 때 볼 시점을 지정합니다.

```json
{
  "id": "2xT9bQ1kLw5nVf8cZ0aR7mHpJd3",
  "application": "checkout-web",
  "name": "Checkout failures",
  "description": "Sessions that ended at the checkout with an error.",
  "createdBy": "<user-id>",
  "createdAt": 1790000000000000,
  "updatedAt": 1790000100000000,
  "sessionCount": 2,
  "sessions": [
    { "sessionId": "3f6c9a52-1b7e-4d08-a5c3-90e2d41f7b68", "atTime": 1790000005000000, "addedBy": "<user-id>", "addedAt": 1790000000000000 },
    { "sessionId": "9d41e7b0-62fa-4c3d-8e15-b7a09c52d3f4", "atTime": null, "addedBy": "<user-id>", "addedAt": 1790000100000000 }
  ]
}
```

`GET /api/v1/rum/playlists`는 `sessions`를 제외한 재생목록을 최근 수정순으로 반환하며, `application`으로
특정 애플리케이션만 조회할 수 있습니다. 조회에는 `rum.playlists.read` 권한이 필요하며, 플랫폼 호출자는 `sys.telemetry.read` 권한을 사용할 수 있습니다. 나머지 요청은 재생목록을 변경하며
`rum.playlists.manage` 권한이 필요합니다. `{ "deleted": true }`를 반환하는 `DELETE`를 제외하면 모두 세션이 포함된 재생목록을 반환합니다.

| 요청 | 본문 | 규칙 |
|---|---|---|
| `POST /rum/playlists` | `application`, `name`, 선택 사항인 `description`과 `sessions` | 애플리케이션이 존재해야 합니다(`404`). 이름은 1~128자여야 하며, 대소문자를 구분하지 않고 같은 애플리케이션의 다른 재생목록 이름과 중복될 수 없습니다(`409`). 설명은 최대 1,000자입니다. |
| `PATCH /rum/playlists/{id}` | `name`과 `description`(각각 선택 사항) | 생략한 항목은 기존 값을 유지합니다. 애플리케이션은 변경할 수 없습니다. |
| `POST /rum/playlists/{id}/sessions` | `sessions` | 기존 세션을 다시 추가하면 목록 내 위치는 유지하고 `atTime`을 전달한 값으로 갱신합니다. 재생목록에는 세션을 최대 500개까지 담을 수 있습니다(`400`). |

요청의 세션 형식은 `{ "sessionId": "...", "atTime": 1790000005000000 }`입니다. ID는 1~128자입니다. `atTime`을
지정하면 에포크 이후 마이크로초 단위로 지정한 시점에서 세션을 엽니다. 생략하면 세션 시작 시점에서 엽니다.
재생목록은 세션 자체가 아니라 ID를 저장합니다. 세션의 존재 여부를 확인하지 않으며, 보존 기간이 지나 세션 행을 삭제해도 해당 세션은
목록에 남습니다. `GET /api/v1/rum/sessions/{id}/playlists`는 해당 세션을 담은 재생목록을 세션 목록 없이 반환합니다.

## 단일 행과 단일 세션 조회

`GET /api/v1/rum/{type}/{id}`는 모든 열을 포함한 단일 행을 반환하며, 행이 없으면 `404`를 반환합니다. `from`과 `to`로 조회 범위를 좁힐 수 있습니다. 두 매개변수를
생략하면 최근 30일을 조회합니다. `{id}`는 해당 유형의 `idField` 값입니다.

`GET /api/v1/rum/sessions/{id}/timeline`은 다음 필드를 반환합니다.

| 필드 | 내용 |
|---|---|
| `session` | 세션 행입니다. 아직 세션 행을 생성하지 않았으면 `null`입니다. |
| `items` | 세션에 속하는 다른 모든 유형의 행을 오래된 순으로 반환합니다. 각 행의 `type`은 `view`, `action`, `error`, `resource`, `long_task`, `vital`, `log` 중 하나입니다. |
| `truncated` | 행 수가 타임라인에 포함할 수 있는 한도를 초과한 유형입니다. |

`GET /api/v1/rum/sessions/{id}/related-traces`는 세션의 백엔드 트레이스 목록을 반환합니다. 먼저 세션의 요청에 ID가 포함된
트레이스(`relation: direct`)를 반환합니다. 해당 트레이스가 없으면 세션이 진행되는 동안 실행된 트레이스
(`relation: time-correlated`)를 반환합니다. 각 트레이스에는 `trace_id`, `service`, `spanCount`, `durationMs`,
`startedAt`이 포함되며, 응답에는 `primaryService`가 포함됩니다. 반대로 `GET /api/v1/rum/traces/{traceId}/session`은
해당 세션을 반환하며, 세션이 없으면 `null`을 반환합니다.

## 댓글

```http
POST /api/v1/rum/sessions/{id}/comments
```

```json
{ "application": "checkout-web", "atTime": 1790000005000000, "body": "The button does nothing here." }
```

`atTime`은 세션 내 시점을 Unix 에포크 이후 마이크로초로 나타낸 값이며, `body`는 1~2,000자입니다. 세션당 댓글을 최대 500개까지 저장할 수 있습니다. `GET`은 세션 내 시점이 이른 순으로 댓글을 담은 `{ "comments": [...] }`를 반환하며, `rum.replay.read` 권한이 필요합니다.

```json
{
  "id": "2xT9bQ1kLw5nVf8cZ0aR7mHpJd3",
  "application": "checkout-web",
  "sessionId": "3f6c9a52-1b7e-4d08-a5c3-90e2d41f7b68",
  "atTime": 1790000005000000,
  "body": "The button does nothing here.",
  "authorId": "<user-id>",
  "authorName": "Ada",
  "createdAt": 1790000010000000,
  "updatedAt": 1790000010000000,
  "editable": true
}
```

`POST`에는 `rum.replay.comments.write` 권한이 필요합니다. `PATCH`는 `body`를 받습니다. `PATCH`와 `DELETE`로 직접 작성한 댓글을 수정하거나 삭제하려면 같은 권한이 필요하며, 다른 작성자의 댓글을 수정하거나 삭제하려면 `rum.replay.comments.manage` 권한이 필요합니다. `editable`은 조회 권한이 있는 사용자가 댓글을 수정할 수 있는지 나타냅니다. `DELETE`는 `{ "deleted": true }`를 반환합니다.

## 요약

`GET /api/v1/rum/sessions/{id}/summary`는 조회에 사용하는 언어로 저장한 요약을 `{ "summary": ... }` 형식으로 반환합니다. 해당 언어의 요약이 없으면 `summary`는 `null`입니다. 이 요청에는 `rum.replay.read` 권한이 필요합니다. `POST`는 모델로 요약을 생성하며 `rum.replay.summaries.generate` 권한이 필요합니다. 저장된 요약은 모델을 호출하지 않고 반환합니다. `{ "regenerate": true }`를 지정하면 세션이 변경된 경우에만 모델을 호출합니다.

```json
{
  "summary": {
    "sessionId": "3f6c9a52-1b7e-4d08-a5c3-90e2d41f7b68",
    "language": "en-us",
    "summary": "The user filled the cart and could not pay: the payment call failed three times.",
    "chapters": [{ "atTime": 1790000005000000, "title": "Fills the cart", "summary": "Adds two items." }],
    "model": "<model>",
    "promptTokens": 1820,
    "completionTokens": 240,
    "generatedAt": 1790000020000000
  }
}
```

이 호출은 출처를 `replay_summary`로 기록하고 Mole Agent의 일일 예산에 반영합니다. 예산을 모두 사용하면 `429`를 반환합니다. 조직에 키를 설정한 활성 모델 제공자가 없거나 세션에 요약할 내용이 없으면 `400`을 반환합니다.

## 이슈

유사한 오류를 [이슈](/ko/rum/errors)로 그룹화합니다. 각 오류 행의 `error.issue_id`에는 해당 이슈의 ID가 들어 있습니다.
지정한 범위의 오류를 기준으로 이슈의 집계값을 계산합니다. 이슈의 상태와 이력은 별도로 저장합니다.
시간은 Unix 에포크 이후 마이크로초 단위입니다.

```http
GET /api/v1/rum/issues?application=checkout-web&status=unresolved&sort=sessions&limit=50
```

| 매개변수 | 유형 | 동작 |
|---|---|---|
| `application` | string | 필수입니다. |
| `env`, `source` | string | 지정한 환경에서 발생한 오류 또는 지정한 소스(`browser`, `flutter` 등)가 전송한 오류만 포함합니다. |
| `filters` | list | `search`와 같은 방식으로 집계할 오류에 조건을 추가합니다. |
| `from`, `to` | integer | `search`와 같은 방식으로 동작합니다. |
| `status` | string | `unresolved`(기본값: 열림, 조사 중, 재발), `all`, 또는 `open`, `investigating`, `regressed`, `resolved`, `ignored` 중 하나입니다. |
| `assignee`, `team` | string | 사용자 ID 또는 팀 ID입니다. 미할당 이슈를 조회하려면 `none`을 사용합니다. |
| `search` | string | 이슈의 유형, 메시지 또는 발생 위치에서 대소문자를 구분하지 않고 단어를 검색합니다. |
| `fresh` | boolean | 지정한 범위에서 처음 발견되었거나 재발한 이슈만 포함합니다. |
| `sort` | string | `sessions`(기본값), `users`, `occurrences`, `lastSeen`, `firstSeen`, `status` 중 하나입니다. |
| `order` | `asc` 또는 `desc` | 생략하면 `status`를 제외한 기준에서 내림차순으로 정렬합니다. |
| `limit` | integer | 1~100입니다. 기본값은 50입니다. |

```json
{
  "issues": [
    {
      "id": "3f9c2a71e0b4c8d1",
      "applicationId": "checkout-web",
      "status": "regressed",
      "assigneeId": "<user-id>",
      "teamId": null,
      "overflow": false,
      "source": "source",
      "errorType": "ChunkLoadError",
      "message": "Loading chunk 482 failed.",
      "location": "src/router/lazy.ts:34 · loadChunk",
      "firstSeenAt": 1789300000000000,
      "lastSeenAt": 1790000000000000,
      "firstVersion": "2.2.0",
      "lastVersion": "2.4.1",
      "resolvedAt": 1789600000000000,
      "resolvedVersion": "2.3.0",
      "resolvedBy": "<user-id>",
      "regressedAt": 1789900000000000,
      "regressedVersion": "2.4.1",
      "regressedEnvironment": "production",
      "updatedBy": null,
      "updatedAt": 1789900000000000,
      "sessions": 612,
      "users": 498,
      "occurrences": 1530,
      "trend": [3, 5, 4, 9, 40, 120]
    }
  ],
  "total": 8
}
```

`regressedEnvironment`는 이슈의 재발을 일으킨 오류의 환경입니다. 해당 오류에 환경이 지정되지 않았으면 `null`입니다. 이슈는
오류가 발생한 환경과 관계없이 애플리케이션 전체에 속합니다. 서버는 각 환경에서 해당 이슈를 처음 발견한 시점도 저장합니다.
[알림 규칙](/ko/rum/alerts#규칙-범위-좁히기)은 이 시점을 기준으로 각 환경의 새 이슈를 집계합니다.

목록은 세션 수가 가장 많은 이슈 250개를 조회합니다. `sort`에 따라 사용자 수 또는 발생 횟수를 기준으로 조회할 수도 있습니다. 조회한 이슈는 `status`, `assignee`,
`team`, `search`, `fresh`로 필터링합니다. `total`은 필터링 후 `limit`을 적용하기 전의 이슈 수입니다. `trend`에는 조회 범위를 최대 12개의 동일한 구간으로 나눈 뒤 각 구간의 발생 횟수를
오래된 순으로 담습니다. `overflow`는 애플리케이션에서 [시간당 생성할 수 있는 새 이슈 한도](/ko/rum/errors#시간당-새-이슈-한도)를 초과한
오류를 집계하는 이슈를 표시합니다. 집계에 시간이 너무 오래 걸리거나 시스템이 사용 중이면
이슈를 반환하지 않고 `unavailable`을 `time_budget` 또는 `busy`로 설정합니다.

`GET /api/v1/rum/issues/{id}`는 목록과 동일한 형식으로 이슈를 반환하되 `trend`는 제외합니다. `sessions`, `users`, `occurrences`는
`from`과 `to` 범위에서 집계하며, 다음 두 필드를 추가로 반환합니다.

| 필드 | 내용 |
|---|---|
| `samples` | 이슈가 발생한 최근 세션 3개를 최신순으로 반환합니다. 각 항목에는 `timestamp`, `sessionId`, `userId`, `anonymousId`, `page`, `browser`, `system`, `version`, `hasReplay`, `retained`가 포함됩니다. 세션을 보존하지 않은 오류의 경우 `retained`는 `false`이며 열 수 있는 세션이 없습니다. |
| `stack` | 프레임이 있는 가장 최근 오류의 스택입니다. 프레임이 있는 오류가 없으면 가장 최근 오류의 스택을 빈 `frames`와 함께 반환합니다. 범위 내에 해당 이슈의 오류가 없으면 `null`을 반환합니다. 스택에는 `message`, `text`, `frames`, `symbolication`, `handling`, `isCrash`, `category`가 포함됩니다. 각 프레임에는 SDK가 전송한 `raw`, 디버그 아티팩트로 복원한 값 또는 `null`을 담은 `restored`, 그리고 `inApp`이 포함됩니다. 심볼 복원을 시도한 경우 `symbolication`은 `completed`, `partial`, `missing` 중 하나입니다. |

이슈가 존재하지 않으면 `404`를 반환합니다.

`PATCH /api/v1/rum/issues/{id}`는 `status`, `assigneeId`, `teamId` 중 하나 이상을 받아 변경 후의 이슈를 반환합니다.

```json
{ "status": "resolved", "assigneeId": "<user-id>", "teamId": null }
```

`status`는 `open`, `investigating`, `resolved`, `ignored` 중 하나입니다. 규칙은 해결된 이슈가 더 최신 버전에서 다시 발생하면 `regressed`로
설정합니다. 요청에서 `regressed`를 지정하면 `400`을 반환합니다. `assigneeId`는 조직의 구성원이어야 하며, `teamId`는 해당 조직의 팀이어야 합니다. `null` 또는
빈 문자열을 지정하면 담당자 또는 팀의 할당을 해제합니다. 생략한 필드는 변경하지 않습니다. 이슈를 해결하면 `resolvedAt`, `resolvedBy`, 그리고 애플리케이션의 최신 버전을
`resolvedVersion`으로 기록합니다. 상태가 바뀌면 이전 해결 또는 재발 기록을 종료합니다. 변경할 필드를 지정하지 않으면 `400`을 반환합니다. 기존 값과 같은 값만 지정하면 변경 없이 `200`을 반환합니다. 각 변경 사항은 감사 로그에 `rum.issue.update`로 기록합니다.

## 알림 규칙 미리보기

```http
POST /api/v1/rum/alerts/preview
```

규칙 평가 코드가 [RUM 지표에 대한 알림 규칙](/ko/rum/alerts)을 최근 기간에 적용했다면 어떤 결과를 얻었을지
시간 창별로 조회합니다. `rum.events.read` 권한이 필요합니다.

```json
{
  "query": { "applicationId": "checkout-web", "environment": "production", "page": "/checkout", "metric": "lcp_p75" },
  "periodSecs": 3600
}
```

| 필드 | 유형 | 동작 |
|---|---|---|
| `query` | 객체 | 필수입니다. 지표를 정의하는 `applicationId`와 `metric`을 지정하고, 필요한 경우 `environment`, `page`, `version`, `minSamples`를 지정합니다. 지표를 `page` 또는 `version`으로 필터링할 수 없으면 해당 필드를 허용하지 않으며, 개수를 집계할 때는 `minSamples`를 허용하지 않습니다. `custom_vital`과 `custom_timing`에는 필수 필드인 `customName`과 `statistic`도 지정할 수 있습니다. `query`에는 `search`가 필요합니다. `search`에는 `type`, 입력한 그대로의 `statement`, 이를 파싱한 `filters`와 `freeText`, 그리고 `measure`(`fn`과 `field`)가 포함됩니다. [규칙 만들기](/ko/api/alerting/create-rule#rum-규칙)를 참조합니다. |
| `periodSecs` | 정수 | 필수입니다. 규칙을 평가하는 시간 창의 길이이며, 범위는 60~21,600입니다. 각 데이터 포인트는 하나의 시간 창에 해당합니다. |
| `from`, `to` | 정수 | Unix 에포크 이후 경과 시간을 마이크로초로 지정한 범위입니다. 조회에는 온전한 시간 창만 포함합니다. `to`의 기본값은 현재 시각입니다. `from`의 기본값은 `to`보다 6시간 전이며, 범위에 시간 창이 12~72개 포함되고 기간이 하루를 넘지 않도록 조정합니다. 범위에는 시간 창을 최대 360개까지 포함할 수 있습니다. |

```json
{
  "metric": "lcp_p75",
  "unit": "milliseconds",
  "minSamples": 50,
  "periodSecs": 3600,
  "from": 1789956800000000,
  "to": 1790000000000000,
  "points": [
    { "at": 1789956800000000, "value": null, "samples": null },
    { "at": 1789960400000000, "value": 2480, "samples": 612 }
  ],
  "current": { "at": 1789996400000000, "value": 2310, "samples": 540 }
}
```

`unit`은 `count`, `percent`, `milliseconds`, `score`, `bytes`, `none` 중 하나입니다. 각 데이터 포인트의 `at`은 시간 창의 시작 시각을, `value`는 지표 값을 나타내며,
`samples`는 지표 산출에 사용한 행 수를 나타냅니다. 행 수가 `minSamples`보다 적은 시간 창에는 `value`와 `samples`가 모두 없습니다. `current`는 마지막 데이터 포인트로,
`to`에서 끝나는 시간 창에 해당합니다. 개수 집계가 제한 시간을 초과하거나 시스템이 사용 중이면 데이터 포인트를 반환하지 않고 `unavailable`을
`time_budget` 또는 `busy`로 설정합니다. 애플리케이션이 없으면 `404`를 반환하고, 규칙이 지표와 호환되지 않으면 `400`을 반환합니다.

## 오류

| 상태 | 원인 |
|---|---|
| `400` | 요청에 맞지 않는 매개변수, 필터, 열 또는 커서가 있습니다. |
| `401`, `403` | 토큰이 누락되었거나 유효하지 않거나, 엔드포인트에 필요한 권한이 없습니다. |
| `404` | 행, 세션 또는 애플리케이션이 존재하지 않습니다. |
| `409` | 해당 식별자 또는 이름을 사용하는 애플리케이션이 이미 존재합니다. |
| `413` | 요청이 [`events`](/ko/rum/events#이벤트-전송)의 제한을 초과합니다. |
