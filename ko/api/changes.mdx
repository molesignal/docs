```http
GET    /api/v1/changes
POST   /api/v1/changes
GET    /api/v1/changes/{id}
PUT    /api/v1/changes/{id}
PATCH  /api/v1/changes/{id}
DELETE /api/v1/changes/{id}
```

변경 사항은 한곳에 모입니다: 배포, 구성 변경, 기능 플래그, 스케일링,
파이프라인이 다음을 통해 보고하는 인프라 변경,
[`POST /api/v1/apm/deployments`](/ko/apm/deployments#ci에서-배포-보고), 그리고 시간 범위에
추가하는 어노테이션입니다. `GET /api/v1/changes`는 APM이 스팬에서 처음 확인한 버전 및
알림 규칙 편집과 함께 이를 나열합니다. 나머지 호출은 어노테이션을 관리합니다.

## 변경 사항 목록 조회

| 매개변수 | 비고 |
|---|---|
| `from`, `to` | 마이크로초 단위의 범위입니다. `to`의 기본값은 현재 시각이고, `from`의 기본값은 `to` 하루 전입니다. |
| `services` | 서비스 이름을 쉼표로 구분합니다. 다른 서비스의 변경 사항은 제외되며, 어노테이션과 규칙 편집처럼 서비스가 없는 변경 사항은 포함됩니다. |
| `namespace`, `environment` | 이 네임스페이스 또는 환경의 보고된 변경 사항 및 버전과, 값을 지정하지 않은 보고된 변경 사항입니다. |
| `kinds` | 쉼표로 구분합니다: `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure`, `annotation`, `version`, `rule`. 생략하면 호출자가 읽을 수 있는 모든 종류가 포함됩니다. |
| `dashboardId`, `stream` | 이 대시보드 또는 로그 스트림의 어노테이션과, 대상을 지정하지 않은 어노테이션입니다. 다른 대시보드나 스트림의 어노테이션은 제외됩니다. |
| `limit` | 최대 500이며 기본값은 500입니다. |

각 종류는 자체 권한을 요구하며, 호출자에게 권한이 없는 종류는 거부하지 않고 제외합니다:

| 종류 | 권한(다음 중 하나) |
|---|---|
| `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure` | `apm.deployments.read`, `sys.telemetry.read` |
| `annotation` | `dashboards.annotations.read` |
| `version` | `apm.services.read`, `sys.telemetry.read` |
| `rule` | `alerts.rules.read` |

응답은 목록이며 최신 항목이 먼저 나옵니다. 파이프라인이 보고한 버전은 보고된 그대로 한 번만 나열됩니다.

```json
[
  {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "kind": "deployment",
    "at": 1792316400000000,
    "service": "checkout",
    "namespace": "shop",
    "environment": "prod",
    "version": "2.0.0",
    "status": "succeeded",
    "commit": "9f2c1e7a4b3d5e6f",
    "author": "ada",
    "ciUrl": "https://ci.example.com/runs/7"
  },
  {
    "id": "3KEDP0aZ1y2b3c4d5e6f7g8h9i0",
    "kind": "annotation",
    "at": 1792312800000000,
    "end": 1792314600000000,
    "title": "Load test",
    "tags": ["test"],
    "dashboardId": "dash-1"
  }
]
```

| 필드 | 비고 |
|---|---|
| `at`, `end` | 발생 시점입니다. `end`는 범위에 걸친 어노테이션을 종료합니다. 마이크로초 단위입니다. |
| `service`, `namespace`, `environment`, `version` | 보고된 변경 사항 또는 버전의 대상입니다. |
| `status` | 보고된 변경 사항의 결과입니다: `succeeded`, `failed`, `rolled_back` 중 하나입니다. |
| `title`, `description`, `tags` | 어노테이션 또는 규칙의 제목과, 변경 사항이 자체적으로 기록한 내용입니다. |
| `commit`, `repositoryUrl`, `pullRequestUrl`, `author`, `ciUrl` | 보고된 변경 사항의 출처입니다. |
| `dashboardId`, `stream` | 어노테이션이 속한 대상입니다. |
| `ruleId` | 편집 대상 규칙입니다. |

## 어노테이션 관리

`POST /api/v1/changes`는 어노테이션을 생성하며 `dashboards.annotations.manage` 권한이 필요합니다:

```json
{
  "title": "Load test",
  "description": "k6, 2,000 users",
  "tags": ["test"],
  "timeStart": 1792312800000000,
  "timeEnd": 1792314600000000,
  "dashboardId": "dash-1",
  "streamName": null
}
```

`GET /api/v1/changes/{id}`는 `dashboards.annotations.read` 권한으로 어노테이션 하나를 읽습니다. `PUT`과 `PATCH`는
`dashboards.annotations.manage` 권한으로 지정한 필드를 변경하며, `DELETE`는 같은 권한으로 해당 어노테이션을 삭제합니다. 이러한 호출은
어노테이션에만 적용됩니다. 조직의 어노테이션이 아닌 ID는 `404`를 반환합니다.
Mole Agent는 `create_annotation`, `update_annotation`, `delete_annotation`으로 어노테이션을 관리하며,
`list_changes`로 변경 사항을 나열합니다.
