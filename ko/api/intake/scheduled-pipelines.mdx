| 작업 | 엔드포인트 | 권한 |
|---|---|---|
| 목록 조회 | `GET /api/v1/scheduled_pipelines` | `pipelines.read` |
| 생성 | `POST /api/v1/scheduled_pipelines` | `pipelines.create`, `_audit`를 읽는 경우 `audit.read`도 필요 |
| 조회 | `GET /api/v1/scheduled_pipelines/{id}` | `pipelines.read` |
| 업데이트 | `PUT /api/v1/scheduled_pipelines/{id}` | 구성을 변경할 때 `pipelines.edit`, `_audit`를 읽는 경우 `audit.read`, `enabled`를 변경할 때 `pipelines.pause` 필요 |
| 삭제 | `DELETE /api/v1/scheduled_pipelines/{id}` | `pipelines.delete` |
| 실행 기록 | `GET /api/v1/scheduled_pipelines/{id}/runs` | `pipelines.read` |
| 오늘의 한도 | `GET /api/v1/scheduled_pipelines/{id}/limits` | `pipelines.read` |
| 백필 | `POST /api/v1/scheduled_pipelines/{id}/backfill` | `pipelines.run`, `_audit`를 읽는 경우 `audit.read`도 필요 |

## 목록 조회

모든 파이프라인을 최근 실행 상태 및 지난 24시간 요약과 함께 반환합니다.

<ResponseExample>
```json 200
[
  {
    "id": "3KBHcb6imgQq7FXBsROGTIRHOyg",
    "name": "normalize-app",
    "sourceStream": "app_raw",
    "targetStream": "app",
    "functionSteps": { "mode": "scheduled", "signalType": "logs", "sources": ["app_raw", "nginx_raw"], "steps": [ ... ] },
    "cron": "every:5m",
    "lookbackSecs": 300,
    "enabled": true,
    "lastRunAt": 1790000000000000,
    "readUntil": { "appRaw": 1789999940000000, "nginxRaw": 1789999940000000 },
    "retry": null,
    "alertRecord": null,
    "auditReaderId": null,
    "auditReader": null,
    "createdAt": 1789900000000000,
    "updatedAt": 1789900000000000,
    "lastRunState": "succeeded",
    "lastRunStartedAt": 1790000000000000,
    "lastRunFinishedAt": 1790000000250000,
    "lastRunScannedRows": 1200,
    "lastRunError": null,
    "runs24h": 288,
    "succeededRuns24h": 288,
    "failedRuns24h": 0
  }
]
```
</ResponseExample>

각 항목에는 [조회](#조회)의 필드와 최근 실행 정보인 `lastRunState`, `lastRunStartedAt`, `lastRunFinishedAt`, `lastRunScannedRows`(읽은 이벤트 수), `lastRunError`, 그리고 지난 24시간의 실행 횟수가 포함됩니다.

## 조회

```http
GET /api/v1/scheduled_pipelines/{id}
```

각 소스의 읽기 위치와 예정된 재시도 정보를 파이프라인과 함께 반환합니다.

<ResponseExample>
```json 200
{
  "id": "3KBHcb6imgQq7FXBsROGTIRHOyg",
  "name": "normalize-app",
  "sourceStream": "app_raw",
  "targetStream": "app",
  "functionSteps": { "mode": "scheduled", "signalType": "logs", "sources": ["app_raw", "nginx_raw"], "steps": [ ... ] },
  "cron": "every:5m",
  "lookbackSecs": 300,
  "enabled": true,
  "lastRunAt": 1790000000000000,
  "readUntil": { "appRaw": 1789999940000000, "nginxRaw": 1789999640000000 },
  "retry": {
    "source": "nginx_raw",
    "attempt": 2,
    "nextAt": 1790000030000000,
    "error": "read: <reason>"
  },
  "alertRecord": null,
  "auditReaderId": null,
  "auditReader": null,
  "createdAt": 1789900000000000,
  "updatedAt": 1789900000000000
}
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `readUntil` | 각 소스의 읽기 위치입니다. 단위는 마이크로초입니다. 해당 위치 이전의 소스 이벤트는 처리한 상태입니다. 아직 읽지 않은 소스는 항목에 포함하지 않습니다. |
| `retry` | 실패한 시간 구간에 대해 가장 먼저 예정된 재시도입니다. 예정된 재시도가 없으면 `null`입니다. `source`는 소스 이름, `attempt`는 재시도 회차, `nextAt`은 재시도 예정 시각, `error`는 마지막 시도의 실패 원인입니다. |
| `alertRecord` | 알림 파이프라인이 이벤트를 수신한 가장 최근 UTC 날짜의 집계입니다. `day`(`YYYY-MM-DD`), `processed`, `dropped`, `failed`를 포함합니다. 해당 날짜의 마지막 삭제 및 실패 기록은 각각 `last_dropped`와 `last_failed`에 담으며, 각 기록에는 `atTime`, `rule`(규칙, 알림 소스 또는 신세틱 검사), `reason`이 포함됩니다. 집계 값이 없으면 0으로 간주합니다. 다른 유형의 파이프라인이나 아직 이벤트를 수신하지 않은 알림 파이프라인에는 `null`을 반환합니다. [일별 집계](/ko/pipelines/alert-events#일일-집계)를 참조합니다. |
| `auditReaderId` | 파이프라인이 `_audit`를 읽을 때 사용하는 권한의 소유자 ID입니다. 파이프라인을 마지막으로 저장한 사용자의 권한을 사용합니다. `_audit`를 읽지 않는 파이프라인에는 `null`을 반환합니다. [감사 스트림](/ko/settings/data-security#감사-스트림)을 참조합니다. |
| `auditReader` | `pipelines.read` 권한이 있으면 해당 사용자의 `id`, `displayName`, `email`을 반환합니다. 사용자가 더 이상 존재하지 않거나 사용자 정보를 조회할 수 없으면 `null`을 반환하고 `auditReaderId`는 그대로 유지합니다. |

[일정 및 읽기 위치](/ko/pipelines#일정-및-읽기-위치)와 [재시도 및 데드 레터](/ko/pipelines#재시도-및-데드-레터)를 참조합니다.

## 업데이트 및 삭제

`PUT`은 [파이프라인 생성](/ko/api/intake/create-pipeline)과 동일한 요청 본문을 받아 구성을 교체합니다. `enabled`만 변경하려면 `pipelines.pause`가 필요합니다. 아무것도 변경하지 않는 요청을 포함한 그 밖의 모든 `PUT` 요청에는 `pipelines.edit`가 필요합니다. `enabled`를 `false`에서 `true`로 변경하면 읽기 위치가 초기화되어 모든 소스에서 `lookbackSecs`만큼 거슬러 올라가 다시 읽습니다. `DELETE`는 `{"deleted": true}`를 반환합니다.

`_audit`를 읽는 파이프라인에서는 `PUT` 요청이 읽기에 사용할 권한의 소유자도 결정합니다. [감사 스트림](/ko/settings/data-security#감사-스트림)을 참조합니다.

| `PUT` 요청 | 추가 요구 사항 | 파이프라인이 `_audit`를 읽을 때 사용하는 권한 |
|---|---|---|
| 구성을 변경함 | `audit.read` 및 서비스 계정에 속하지 않는 토큰 | 이후부터 호출자의 권한을 사용합니다. |
| 아무것도 변경하지 않음 | 없음 | 호출자에게 `audit.read` 권한이 있고 토큰이 서비스 계정에 속하지 않으면 이후부터 호출자의 권한을 사용합니다. 그렇지 않으면 기존 권한을 유지하며 오류를 반환하지 않습니다. |
| `enabled`만 변경함 | 없음 | 기존 권한을 유지합니다. |

## 실행 기록

```http
GET /api/v1/scheduled_pipelines/{id}/runs?limit=50&beforeTime=<cursor>
```

예약 파이프라인의 실행 기록을 최신순으로 반환합니다. 실시간 파이프라인과 알림 파이프라인은 실행 기록을 남기지 않습니다.

<ResponseExample>
```json 200
[
  {
    "id": "3KE7Yq0d3jvXm5cJ8r2bWQzN1aP",
    "pipelineId": "3KBHcb6imgQq7FXBsROGTIRHOyg",
    "state": "succeeded",
    "startedAt": 1790000000000000,
    "finishedAt": 1790000000250000,
    "scannedRows": 1200,
    "writtenRows": 1150,
    "droppedRows": 48,
    "failedRows": 2,
    "attempt": 1,
    "error": null,
    "warning": "stream `app` rejected 2 event(s): <reason>"
  }
]
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `state` | `running`, `succeeded`, `failed`, `cancelled` 중 하나입니다. |
| `startedAt`, `finishedAt` | 실행을 시작한 시각과 종료한 시각입니다. 실행 중에는 `finishedAt`이 `null`입니다. |
| `scannedRows` | 실행 중 소스에서 읽은 이벤트 수입니다. |
| `writtenRows` | 모든 대상이 수신한 이벤트 수입니다. |
| `droppedRows` | 단계에서 `abort`로 삭제했거나 중복 제거로 제외한 이벤트 수입니다. |
| `failedRows` | 단계에서 처리에 실패했거나, 소스로 라우팅했거나, 대상에서 수신하지 않은 이벤트 수입니다. |
| `attempt` | 첫 시도는 `1`입니다. 실패한 시간 구간을 재시도하면 값이 커집니다. |
| `error` | 실행 실패 원인입니다. 실패한 시간 구간과 예정된 재시도를 나타내거나, 파이프라인에 데드 레터 스트림이 없고 대상 스트림이 이벤트를 하나도 수신하지 않았음을 나타냅니다. |
| `warning` | 실행이 실패하지는 않았지만 문제가 발생한 경우의 정보입니다. 예를 들어 처리에 실패했거나 거부되었거나 전달되지 않은 이벤트, 또는 재시도를 마친 후 건너뛴 시간 구간을 나타냅니다. |

`scannedRows`는 `writtenRows`, `droppedRows`, `failedRows`의 합과 같습니다.

## 오늘의 한도

```http
GET /api/v1/scheduled_pipelines/{id}/limits
```

UTC 00:00부터 실시간 파이프라인의 [할당량 및 처리량 제한 단계](/ko/pipelines#집계-및-제한)에서 통과시킨 양과 제한한 양을 모든 노드에서 집계하여 반환합니다. 노드는 5초마다 집계 값을 합산합니다. 오늘 집계한 항목이 없는 단계는 행을 반환하지 않습니다.

<ResponseExample>
```json 200
{
  "dayStart": 1790035200000000,
  "buckets": [
    {
      "step": "daily",
      "bucket": "[\"checkout\"]",
      "admittedEvents": 1000000,
      "admittedBytes": 524288000,
      "overEvents": 1240,
      "overBytes": 650117
    },
    {
      "step": "per-host",
      "bucket": "",
      "admittedEvents": 86400,
      "admittedBytes": 45298483,
      "overEvents": 12,
      "overBytes": 6291
    }
  ]
}
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `step` | 단계 이름입니다. |
| `bucket` | 분할하지 않은 할당량이나 처리량 제한의 경우 비어 있습니다. 분할한 할당량의 경우 분할 기준 필드의 값을 필드 순서대로 JSON 목록에 담습니다. 이벤트에 해당 필드 값이 없으면 `null`을 사용하고, 버킷 한도인 1,000개를 초과한 버킷은 `*`로 표시합니다. |
| `admittedEvents`, `admittedBytes` | 한도 내에서 통과한 이벤트 수와 바이트 수입니다. |
| `overEvents`, `overBytes` | 한도를 초과한 이벤트 수와 바이트 수입니다. 단계 설정에 따라 초과분을 삭제하거나 통과시키거나 다른 스트림으로 보냅니다. |

## 백필

```http
POST /api/v1/scheduled_pipelines/{id}/backfill
```

| 필드 | 유형 | 설명 |
|---|---|---|
| `startTime` | integer | 시간 구간의 시작 시각입니다. 단위는 마이크로초입니다. |
| `endTime` | integer | 시간 구간의 종료 시각입니다. `startTime`보다 커야 하며 시간 구간은 31일을 초과할 수 없습니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines/$PIPELINE_ID/backfill \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"startTime": 1790000000000000, "endTime": 1790086400000000}'
```
</RequestExample>

<ResponseExample>
```json 202
{
  "jobs": [
    {
      "source": "app_raw",
      "jobId": "3KE6epTrWXts1oa2ePEKIHKxG19",
      "monitor": "/api/v1/query/jobs/3KE6epTrWXts1oa2ePEKIHKxG19"
    },
    {
      "source": "nginx_raw",
      "jobId": "3KE6eqAbXq0n2yLr7VvTq9cUo4D",
      "monitor": "/api/v1/query/jobs/3KE6eqAbXq0n2yLr7VvTq9cUo4D"
    }
  ]
}
```
</ResponseExample>

백필은 소스마다 검색 작업을 하나씩 제출합니다. 각 작업은 지정된 시간 구간의 소스 데이터를 읽고 단계를 적용한 다음, 예약 실행과 같은 방식으로 이벤트를 기록하고 전달하며 데드 레터를 보관합니다. 파이프라인의 읽기 위치는 변경하지 않습니다. 각 작업의 `monitor` 경로로 작업 상태를 추적합니다. [쿼리](/ko/query#시간-범위-및-비동기-작업)를 참조합니다.

실시간 파이프라인과 알림 파이프라인은 `400`(`realtime and alert pipelines do not support backfill`)을 반환합니다. `_audit`를 읽는 파이프라인은 토큰에 `audit.read` 권한이 없거나 토큰이 서비스 계정에 속하면 `403`을 반환합니다. 작업을 실행할 때 제출자의 권한을 다시 확인하며, 제출자에게 더 이상 `audit.read` 권한이 없으면 작업이 실패합니다.
