```http
POST /api/v1/scheduled_pipelines
```

파이프라인을 생성합니다. 모든 모드에서 경로 이름은 `scheduled_pipelines`로 유지됩니다. 호출하려면 `pipelines.create` 권한이 필요합니다.

**본문**

| 필드 | 유형 | 필수 | 설명 |
|---|---|---|---|
| `name` | string | 예 | 파이프라인 이름입니다. |
| `sourceStream` | string | 예 | 파이프라인이 가장 먼저 읽는 스트림입니다. 알림 파이프라인에서는 빈 문자열을 지정합니다. |
| `targetStream` | string | 예 | 파이프라인이 가장 먼저 쓰는 스트림입니다. 예약 파이프라인에서 읽는 스트림을 지정하면 `409`를 반환합니다. 알림 파이프라인에서는 빈 문자열을 지정합니다. |
| `functionSteps` | object | 예 | 단계와 모드, 그리고 예약 파이프라인의 설정 또는 알림 파이프라인의 조건입니다. 아래를 참조합니다. |
| `cron` | string | 예 | 예약 파이프라인에서는 `every:30s`, `every:5m` 또는 `every:1h`를 지정합니다. 실시간 또는 알림 파이프라인에서는 빈 문자열을 지정합니다. |
| `lookbackSecs` | integer | 아니요 | 소스의 첫 예약 실행에서 과거 데이터를 읽어 오는 범위(초)입니다. 기본값은 300입니다. 예약 파이프라인에서는 양수를 지정해야 합니다. |
| `enabled` | boolean | 아니요 | 기본값은 `true`입니다. |

`functionSteps` 필드:

| 필드 | 설명 |
|---|---|
| `mode` | `scheduled`(기본값), `realtime` 또는 `alert`입니다. |
| `signalType` | `logs`, `metrics` 또는 `traces`입니다. 실시간 파이프라인에서는 `profiles`도 지정할 수 있습니다. 메트릭, 트레이스 또는 프로파일을 처리하는 실시간 파이프라인은 스트림을 그 자리에서 변경합니다. `targetStream`과 `sourceStream`이 같아야 하며, 라우팅 단계와 `retainSource`는 사용할 수 없습니다. [메트릭 및 트레이스](/ko/pipelines#메트릭과-트레이스)를 참조합니다. 프로파일 파이프라인은 `default`를 소스로 사용합니다. [프로파일](/ko/pipelines#프로필)을 참조합니다. 알림 파이프라인에서는 이 필드를 지정하지 않습니다. |
| `steps` | 실행 순서대로 나열한 단계입니다. VRL 단계에는 `transformName`, `script`, 그리고 `vrl`로 설정한 `kind`가 필요합니다. 라우팅 단계에는 `builtin`으로 설정한 `kind`, `route`로 설정한 `operation`, 그리고 `routing` 객체가 필요합니다. 알림 파이프라인은 단계를 최대 20개까지 지원하며 라우팅 단계는 지원하지 않습니다. AI 요약 단계에는 `transformName`, `ai_summary`로 설정한 `kind`, `prompt`, 그리고 응답을 저장할 어노테이션인 `annotation`(기본값 `ai_summary`)이 필요합니다. API 호출 단계에는 `http_enrich`로 설정한 `kind`와 조직의 HTTP 커넥터를 지정하는 `connectorId`가 필요합니다. 쿼리 단계에는 `query_enrich`로 설정한 `kind`, `language`(`sql`이 기본값, 또는 `promql`), `stream`, `streamType`(`logs`가 기본값, `metrics` 또는 `traces`), `statement`, `windowSecs`(기본값 300, 최대 86400), `maxRows`(기본값 5, 최대 50), `annotation`(기본값 `query_result`)이 필요합니다. [알림 파이프라인의 단계](/ko/pipelines/alert-events#단계)를 참조합니다. 실시간 파이프라인에서는 아래 필드를 사용하여 집계 단계인 `generate_metric`, `quota`, `throttle`도 구성할 수 있습니다. |
| `alert` | 알림 파이프라인 전용입니다. 실행 시점, 조건, 순서를 지정합니다. `stage`(`open`이 기본값, 또는 `notify`), `policies`(`notify` 파이프라인을 적용할 알림 정책으로, 비워 두면 알림 이벤트의 모든 정책에 적용), `sources`(`rule`, `external`, `synthetic`, `noData`, `notify`에서는 `manual`도 가능), `severities`(`info`, `warning`, `error`, `critical`), `labels`(이벤트에 있어야 하는 레이블과 값을 지정하는 객체), `order`(정수, 기본값 0)를 사용합니다. 소스 또는 심각도 목록을 비워 두면 해당 항목의 모든 값에 적용합니다. [알림 파이프라인](/ko/pipelines/alert-events#api로-경보-파이프라인-만들기)을 참조합니다. |
| `sources` | 읽을 스트림입니다. `sourceStream`을 먼저 읽습니다. 예약 파이프라인은 목록의 나머지 스트림도 모두 읽으며, 총 8개까지 지원합니다. 실시간 파이프라인은 `[source_stream]`만 허용합니다. |
| `sinks` | 쓸 스트림입니다. `targetStream`이 목록의 첫 번째 항목이며, 목록의 나머지 스트림에도 모든 이벤트를 씁니다. 총 8개까지 지원합니다. 실시간 파이프라인은 `[target_stream]`만 허용합니다. |
| `sinkConnectors` | 예약 파이프라인 전용입니다. 모든 이벤트를 수신하는 커넥터의 ID입니다. |
| `sinkTables` | 예약 파이프라인 전용입니다. 이벤트마다 행 하나를 저장할 확장 테이블의 이름입니다. 최대 8개까지 지정할 수 있습니다. [확장 테이블에 쓰기](/ko/pipelines#확장-테이블에-쓰기)를 참조합니다. |
| `delaySecs` | 예약 파이프라인 전용입니다. 늦게 도착하는 이벤트를 포함할 수 있도록 실행 시 가장 최근 시간 구간의 읽기를 미루는 시간(초)입니다. 범위는 0~3600이며 기본값은 60입니다. |
| `retry` | 예약 파이프라인 전용입니다. `runRetries`는 읽기 또는 쓰기에 실패한 시간 구간의 재시도 횟수이고, `deliveryRetries`는 커넥터 전송의 재시도 횟수입니다. 각각 범위는 0~10이며 기본값은 3입니다. |
| `deadLetterStream` | 예약 파이프라인 전용입니다. 처리, 쓰기 또는 전송에 실패한 이벤트를 저장하는 로그 스트림입니다. 파이프라인이 읽거나 쓰는 스트림은 지정할 수 없습니다. |
| `dedupeField` | 예약 파이프라인 전용입니다. 한 번의 실행에서 이 필드의 값이 이미 나온 경우 해당 이벤트를 삭제합니다. |
| `retainSource` | 실시간 로그 파이프라인 전용입니다. 소스 스트림에 원본 이벤트를 보존합니다. |

집계 단계에는 `transformName`과 `kind` 외에 다음 필드를 사용합니다. 같은 파이프라인 안에서 단계 이름은 서로 달라야 합니다. [집계 및 제한](/ko/pipelines#집계-및-제한)을 참조합니다.

| 필드 | 설명 |
|---|---|
| `conditions` | 단계를 적용할 이벤트를 지정합니다. 이벤트는 최대 16개의 조건을 모두 충족해야 합니다. 각 조건은 `field`, `test`(`equals`, `not_equals`, `contains`, `starts_with`, `matches`, `exists`, `missing`, `gt`, `gte`, `lt` 또는 `lte`), `value`로 구성합니다. `gt`, `gte`, `lt`, `lte`는 숫자와 비교하고, `matches`는 정규식과 대조합니다. 비워 두면 모든 이벤트에 적용합니다. |
| `metric` | `generate_metric` 전용입니다. `name`, `type`(`count`, `gauge` 또는 `histogram`), `field`(`gauge`와 `histogram`에 필수이며, `count`는 이 필드를 지정하면 해당 값을 합산), `groupBy`(최대 10개 필드), `buckets`(히스토그램의 상한값 1~30개를 오름차순으로 지정), `stream`(메트릭 스트림), `intervalSecs`(`10`, `30`, `60`이 기본값, 또는 `300`)를 지정합니다. 로그, RUM, 트레이스 파이프라인에서만 사용할 수 있습니다. |
| `quota` | `quota` 전용입니다. `unit`(`events` 또는 `bytes`), `limit`(해당 단위의 일일 한도, 1~10^15), `partitionBy`(최대 5개 필드), `overrides`(`{"values": {"<field>": "<value>"}, "limit": <n>}` 형식으로 최대 100개를 지정하며, 각 항목에 `partitionBy`의 모든 필드 값을 지정), `action`(`drop`이 기본값, `pass` 또는 `route`), `target`(`route`에 사용할 로그 스트림)을 지정합니다. 로그 파이프라인과 `rum_views` 및 `rum_vitals`를 제외한 RUM 스트림에서만 사용할 수 있습니다. RUM에서는 `route`를 사용할 수 없습니다. |
| `throttle` | `throttle` 전용입니다. `limit`(시간 구간당 이벤트 수, 1~1,000,000), `windowSecs`(1~86,400), `groupBy`(최대 5개 필드), `action`(`drop`이 기본값, 또는 `route`), `target`을 지정합니다. `quota`와 같은 파이프라인에서 사용할 수 있습니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "normalize-app",
    "sourceStream": "app_raw",
    "targetStream": "app",
    "functionSteps": {
      "mode": "scheduled",
      "signalType": "logs",
      "sources": ["app_raw", "nginx_raw"],
      "sinks": ["app", "app_archive"],
      "delaySecs": 60,
      "retry": { "runRetries": 3, "deliveryRetries": 3 },
      "deadLetterStream": "pipeline_dead_letters",
      "steps": [
        { "transformName": "normalize-level", "kind": "vrl",
          "script": ".level = downcase!(string!(.level))" }
      ]
    },
    "cron": "every:5m",
    "lookbackSecs": 300,
    "enabled": true
  }'
```

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 일정이 `every:Ns/m/h` 형식을 따르지 않거나, 조회 범위가 0 이하이거나, 프로파일에 예약 파이프라인을 사용하거나, 프로파일 파이프라인에서 `default`가 아닌 스트림을 사용했습니다. 메트릭, 트레이스, 프로파일 또는 RUM의 실시간 파이프라인이 다른 스트림에 쓰거나, 라우팅하거나, 소스를 보존하거나, 해당 파이프라인의 단계가 샘플의 [보존 필드](/ko/pipelines#메트릭과-트레이스)를 변경하는 경우에도 이 오류가 발생합니다. 그 밖의 원인으로는 `rum_views` 또는 `rum_vitals`의 이벤트를 삭제할 수 있는 단계, 컴파일되지 않는 VRL 단계, 잘못된 스트림 이름, 읽기 또는 쓰기 스트림이 8개를 초과하거나 확장 테이블이 8개를 초과하는 구성, 고정 스트림 또는 대체 스트림이 소스인 라우팅 단계, 파이프라인이 읽거나 쓰는 데드 레터 스트림, 쓰기 또는 라우팅 대상으로 지정한 [RUM 스트림](/ko/pipelines#rum-스트림), 실시간 파이프라인의 소스로 지정한 `rum_sessions`, 쓰기·라우팅·실시간 변경 대상으로 지정한 [플랫폼 스트림](/ko/pipelines#플랫폼-스트림), 범위를 벗어난 `delaySecs` 또는 재시도 횟수가 있습니다. 알림 파이프라인에서는 알 수 없는 소스 또는 심각도, 라우팅 단계, 프롬프트가 없는 AI 요약 단계, 조직의 HTTP 커넥터가 아닌 커넥터를 사용하는 API 호출 단계, 단일 쿼리가 아니거나 `_audit`를 읽거나 문자열 밖의 자리표시자 또는 이벤트에 없는 자리표시자를 사용하는 쿼리 단계, MoleSignal 외부로 나가는 단계가 있는 `notify` 파이프라인, `policies` 또는 `manual` 소스를 지정한 `open` 파이프라인, 20개를 초과하는 단계가 원인입니다. `generate_metric`, `quota` 또는 `throttle` 단계를 예약 파이프라인이나 알림 파이프라인에서 사용하거나 지원하지 않는 데이터에 적용한 경우, 이 단계 중 두 개에 같은 이름을 지정한 경우, 또는 허용 범위를 벗어난 설정을 사용한 경우에도 이 오류가 발생합니다. 예를 들어 PromQL로 선택할 수 없는 메트릭 이름, 모든 메트릭 샘플에 있는 레이블(`value`, `le`, `metric_name` 등), 소스 스트림과 같은 `target`은 허용되지 않습니다. |
| `403` | 파이프라인이 `_audit`를 읽는데 토큰에 `audit.read` 권한이 없거나 토큰이 서비스 계정에 속합니다. |
| `409` | 예약 파이프라인이 읽는 스트림에 쓰려고 하거나, 동일한 데이터 유형과 소스 스트림에 대해 다른 실시간 파이프라인이 이미 활성화되어 있습니다(`a realtime pipeline is already enabled for this <signal> stream`). |

실시간 모드, 라우팅 단계, 읽기 위치 및 재시도에 대한 자세한 내용은 [파이프라인](/ko/pipelines)을 참조합니다.
