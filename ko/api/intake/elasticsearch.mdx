```http
POST /api/v1/_bulk
```

Filebeat, Logstash 및 Vector `elasticsearch` 싱크를 위한 Elasticsearch `_bulk` 호환 NDJSON 수집입니다. 이 호출에는 `logs.write`가 필요합니다. `Content-Encoding: gzip`이 있는 본문이 허용됩니다.

| 작업 | 처리 |
|---|---|
| `index`, `create`, `update` | 원본 문서는 로그 이벤트로 저장됩니다. |
| `delete` | 응답 항목 없이 건너뜁니다. 이 엔드포인트를 통해서는 텔레메트리가 절대 삭제되지 않습니다. |

작업의 `_index`가 대상 로그 스트림을 선택합니다. `_index`가 없으면 `stream-name` 헤더가 적용되고, 그다음 `default`가 적용됩니다.

스트림의 필드 유형에 맞지 않는 값이 있는 문서는 해당 문서만 거부됩니다. 해당 항목에는 `status: 400`과 `reason`이 포함된 `error`가 있으며, `errors`는 `true`이고 다른 문서는 기록됩니다. Filebeat와 Logstash는 이러한 항목을 재시도하지 않습니다.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## 이 엔드포인트 선택

기존 발신자가 Elasticsearch 벌크 NDJSON을 내보낼 수 있으면 이 엔드포인트를 사용합니다. 이는 수집 어댑터이며 Elasticsearch 클러스터가 아닙니다. 검색, 인덱스 템플릿, 문서 ID 및 제자리 업데이트 시맨틱스는 이 API에서 제공하지 않습니다. 저장된 이벤트를 읽으려면 [SQL 쿼리](/ko/query)를 사용합니다.

## 유효한 배치 구성

- 각 `index` 또는 `create` 작업에 대해 작업 객체와 문서 객체를 별도 줄에 보냅니다. 배치를 줄바꿈으로 끝냅니다.
- `update`의 경우 이벤트 필드를 `doc` 아래에 배치합니다. 해당 필드는 저장된 이벤트를 수정하는 대신 새 이벤트가 됩니다.
- 스트림을 선택하려면 작업에 `_index`를 설정합니다. 그렇지 않으면 `stream-name`을 사용하거나 `default` 스트림을 사용합니다.
- 이벤트 시간을 보존할 때는 `_timestamp`를 마이크로초 단위의 정수 Unix 타임스탬프로 제공합니다. 그렇지 않으면 수신자는 현재 시간을 사용합니다.
- `delete` 작업은 건너뜁니다. 텔레메트리를 삭제하지 않으며 응답에 저장된 이벤트 항목을 추가하지 않습니다.

## 수집 확인

이벤트가 하나인 배치의 경우 `errors: false`와 `status: 201`인 응답 항목 하나를 예상합니다. 항목 수를 수집하려는 이벤트 수와 비교합니다. HTTP 성공만으로는 배치가 의도한 대로 구성되었음을 증명할 수 없습니다.

**로그**를 열고 `_index`에 해당하는 스트림을 선택한 다음 이벤트 타임스탬프가 포함된 시간 범위를 사용합니다. 샘플의 고유한 필드를 쿼리합니다. 이벤트가 없으면 전체 배치를 다시 보내기 전에 스트림 선택과 타임스탬프 단위를 확인합니다. 이 인터페이스는 재시도 중복 제거를 위해 Elasticsearch 문서 ID를 사용하지 않습니다.

## 거부된 요청 문제 해결

| 증상 | 확인 |
|---|---|
| 인증 또는 권한 오류 | `logs.write` 권한이 있는 대상 조직의 API 토큰을 사용합니다. |
| 작업 또는 문서가 JSON 객체가 아님 | NDJSON 줄 경계를 확인합니다. JSON 배열이나 들여쓰기된 여러 줄 객체를 보내지 않습니다. |
| 알 수 없는 작업 | 위에 나열된 지원되는 작업 이름을 사용합니다. |
| 압축 해제 오류 | 본문이 실제로 압축된 경우에만 `Content-Encoding: gzip`을 설정합니다. |
| 예상보다 적은 이벤트로 성공 | 모든 쓰기 작업에 문서 줄이 있는지 확인하고, 건너뛴 삭제와 저장된 이벤트를 구분합니다. |
| `errors: true` 및 상태가 `400`인 항목 | 스트림의 필드 유형에 맞지 않는 값이 있습니다(예: `int64` 필드의 텍스트). 항목의 `reason`에 필드 이름이 표시됩니다. 스트림이 해당 필드에 저장하는 유형으로 값을 보내거나 파이프라인에서 변환합니다. |
