```http
POST /api/v1/_cloudflare
```

Cloudflare Logpush에서 일반적으로 전송하는 gzip으로 압축된 본문을 포함해 NDJSON을 허용합니다. 이 엔드포인트는 Bearer 토큰을 사용하지 않습니다. 16자 이상의 `pushToken`과 `target_stream`을 설정한 `cloudflare_logpush` 유형의 커넥터를 생성하고, `X-Connector-Token` 헤더에 토큰을 담아 전송합니다. 쿼리 매개변수 `?token=`으로도 토큰을 전달할 수 있습니다. 토큰이 올바르지 않으면 `401`을 반환합니다.

각 줄은 `target_stream`(기본값: `cloudflare`)의 로그 이벤트 하나가 됩니다. 엔드포인트는 각 줄의 필드를 그대로 저장하고 수신 시각을 이벤트 시각으로 기록합니다. 성공하면 `204`를 반환합니다.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_cloudflare \
  -H 'X-Connector-Token: <pushToken>' \
  -H 'content-encoding: gzip' \
  --data-binary @logs.ndjson.gz
```
</RequestExample>

커넥터 설정 방법은 [커넥터](/ko/connectors)를 참조합니다.

## 전송 및 스트림 선택 확인

1. 커넥터가 활성화되어 있고 발신 측에서 해당 커넥터의 푸시 토큰을 사용하는지 확인합니다. 일반 API 토큰으로는 푸시 토큰을 대체할 수 없습니다.
2. 커넥터 API로 원시 `configJson`을 설정할 때 대상 스트림에는 `targetStream`이 아닌 `target_stream`을 사용합니다. 토큰 키는 카멜 표기법인 `pushToken`을 그대로 사용합니다.
3. 고유한 마커가 포함된 테스트 이벤트 하나를 전송하고 수신 시각을 기록합니다. **로그**에서 대상 스트림과 수신 시각이 포함된 시간 범위를 선택한 다음 마커를 검색합니다.
4. 요청이 성공했지만 대상 스트림이 비어 있으면 해당 기본 스트림과 저장된 대상 필드를 확인합니다. HTTP 성공 응답만으로는 대상 스트림에 이벤트가 저장되었는지 확인할 수 없으므로 해당 스트림을 직접 조회합니다.

토큰은 인증 정보로 취급해 보호합니다. 토큰을 URL 쿼리 매개변수로 전달할 때는 전체 URL이 로그, 티켓, 스크린샷에 남지 않도록 합니다. 실패한 요청을 다시 시도하기 전에 토큰이나 커넥터 상태의 문제인지, 페이로드 형식이나 압축 오류인지 구분합니다.
