```http
POST /api/v1/_kinesis_firehose
```

AWS Data Firehose가 HTTP 엔드포인트로 전송하는 데이터를 수신합니다. 이 엔드포인트는 베어러 토큰을 사용하지 않습니다. 유형이 `aws_kinesis_firehose`인 커넥터를 생성하고 16자 이상의 `pushToken`과 `target_stream`을 설정한 다음, Firehose에서 이 토큰을 액세스 키로 사용합니다. 엔드포인트는 `X-Amz-Firehose-Access-Key`에서 토큰을 읽으며, `X-Connector-Token`과 `?token=`도 허용합니다. 토큰이 올바르지 않으면 `401`을 반환합니다.

각 레코드에는 base64로 인코딩된 `data`가 있습니다. 엔드포인트는 데이터를 디코딩하고 줄 단위로 나눈 다음, 비어 있지 않은 각 줄을 `target_stream`(기본값: `kinesis`)의 로그 이벤트로 변환합니다. JSON 객체가 있는 줄은 객체의 속성을 필드로 변환하고, 일반 텍스트 줄은 `message` 필드에 저장합니다.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_kinesis_firehose \
  -H 'X-Amz-Firehose-Access-Key: <pushToken>' \
  -H 'content-type: application/json' \
  -d '{"requestId":"req-1","timestamp":1790000000000,"records":[{"data":"eyJsZXZlbCI6ImluZm8ifQo="}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{ "requestId": "req-1", "timestamp": 1790000000123 }
```
</ResponseExample>

Firehose 요구사항에 따라 응답은 요청의 `requestId`를 그대로 반환하고 밀리초 단위의 `timestamp`를 포함합니다. 커넥터 설정 방법은 [커넥터](/ko/connectors)를 참조합니다.

## 전송 및 스트림 선택 확인

1. 커넥터가 활성화되어 있고 발신 측에서 해당 커넥터의 푸시 토큰을 사용하는지 확인합니다. 일반 API 토큰으로 푸시 토큰을 대체할 수 없습니다.
2. 커넥터 API에서 `configJson`을 직접 설정할 때 대상 스트림에는 `targetStream`이 아닌 `target_stream`을 사용합니다. 토큰 키는 기존 카멜 표기법인 `pushToken`을 그대로 사용합니다.
3. 고유한 마커가 포함된 테스트 이벤트를 하나 전송하고 수신 시간을 기록합니다. **로그**에서 대상 스트림과 수신 시간이 포함된 시간 범위를 선택한 다음 마커를 검색합니다.
4. 요청은 성공했지만 대상 스트림이 비어 있으면 해당 기본 스트림과 저장된 대상 필드 값을 확인합니다. HTTP 수신 확인 응답이 있더라도 대상 스트림에서 직접 조회해야 합니다.

토큰은 인증 정보로 취급하여 보호합니다. 토큰을 URL 쿼리 매개변수로 전달할 때는 전체 URL이 로그, 티켓, 스크린샷에 노출되지 않도록 합니다. 실패한 요청을 재시도하기 전에 토큰이나 커넥터 상태의 문제인지, 페이로드 형식이나 압축 오류인지 구분합니다.
