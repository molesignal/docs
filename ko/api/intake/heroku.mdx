```http
POST /api/v1/_heroku
```

텍스트 형식의 로그 드레인 요청 본문을 받습니다. 이 엔드포인트는 베어러 토큰을 사용하지 않습니다. `heroku_drain` 유형의 커넥터를 만들고, 16자 이상의 `pushToken`과 `target_stream`을 설정합니다. Heroku에서는 사용자 지정 헤더를 설정할 수 없으므로 URL에 `?token=`을 붙여 토큰을 전달합니다. `X-Connector-Token` 헤더로도 토큰을 전달할 수 있습니다. 토큰이 잘못되면 `401`을 반환합니다.

각 줄은 `target_stream`(기본값: `heroku`)에 로그 이벤트 하나로 저장됩니다. 줄 전체는 `message` 필드에 저장되며, `source` 필드의 값은 `heroku`입니다. 요청이 성공하면 엔드포인트는 `204`를 반환합니다.

<RequestExample>
```bash Heroku CLI
heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
```
</RequestExample>

커넥터 설정 방법은 [커넥터](/ko/connectors)를 참조합니다.

## 전송 및 스트림 선택 확인

1. 커넥터가 활성화되어 있고 발신 측이 해당 커넥터의 푸시 토큰을 사용하는지 확인합니다. 일반 API 토큰으로는 푸시 토큰을 대체할 수 없습니다.
2. 커넥터 API로 원시 `configJson`을 설정할 때 대상 스트림에는 `targetStream`이 아닌 `target_stream`을 사용합니다. 토큰 키는 그대로 카멜 표기법의 `pushToken`을 사용합니다.
3. 고유한 식별자가 포함된 테스트 이벤트를 하나 보내고 수신 시각을 기록합니다. **로그**에서 대상 스트림과 수신 시각이 포함된 시간 범위를 선택한 다음, 해당 식별자를 검색합니다.
4. 요청이 성공했지만 대상 스트림이 비어 있으면 해당 기본 스트림과 저장된 대상 필드의 값을 확인합니다. HTTP 성공 응답만으로는 대상 스트림에 이벤트가 저장되었는지 확인할 수 없으므로 대상 스트림을 직접 조회합니다.

토큰은 인증 정보로 취급해 보호합니다. 토큰을 URL 쿼리 매개변수로 전달할 때는 전체 URL이 로그, 티켓 또는 스크린샷에 노출되지 않도록 합니다. 실패한 요청을 다시 시도하기 전에 토큰 또는 커넥터 상태 문제인지, 페이로드 형식 또는 압축 오류인지 구분합니다.
