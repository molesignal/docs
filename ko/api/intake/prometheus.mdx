```http
POST /api/v1/prometheus/api/v1/write
```

Prometheus 및 VictoriaMetrics `remote_write` 버전 1 요청을 수락합니다. 이 요청은 snappy로 압축된 protobuf입니다. 호출에는 `metrics.write` 권한이 필요하며 성공 시 `204` 응답을 반환합니다. 값이 해당 필드의 타입에 맞지 않아 스트림이 일부 샘플을 거부하면 나머지 샘플은 기록되고 응답은 `400`이며, 거부된 샘플 수와 첫 번째 이유를 알려줍니다. Prometheus는 `400` 응답을 재시도하지 않습니다.

요청은 `stream-name` 헤더로 지정된 메트릭 스트림에 기록되며, 헤더가 없으면 `default`입니다. 메트릭 스트림은 한 소스의 메트릭을 보관합니다. `__name__` 레이블은 `metric_name` 필드가 되고, 나머지 레이블은 필드가 되며, 샘플은 `value` 필드가 됩니다. `metric_name` 또는 `metric_kind`처럼 메트릭 필드와 같은 이름의 레이블은 `exported_<name>`으로 유지됩니다. 네이티브 히스토그램과 메트릭 메타데이터는 건너뛰고, 예시(exemplar)는 샘플 옆에 저장됩니다.

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

메트릭을 보관하는 스트림과 관계없이 이름으로 PromQL을 사용해 해당 메트릭을 쿼리합니다. `service` 및 `status` 레이블이 있는 `http_requests_total` 시리즈는 다음과 같습니다.

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**제한**은 시리즈별 및 조직별로 적용됩니다: 시리즈당 레이블은 최대 64개, 레이블 이름은 최대 128바이트, 레이블 값은 최대 2048바이트이며, 활성 및 신규 시리즈에 대한 카디널리티 제한이 있습니다. 프로세스 제한은 [구성](/ko/configuration#데이터-수집)의 `[intake.prometheus]`에 있습니다. 조직의 활성 시리즈와 조직 내 특정 메트릭의 활성 시리즈는 플랫폼 설정 **설정 → 메트릭 카디널리티**로 제한되며, `GET /api/v1/settings/series_limits`로 읽고 `PUT`과 동일한 본문 `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }`으로 설정합니다. 두 작업 모두 시스템 범위에서 `sys.settings.limits.manage` 권한이 필요합니다. 메트릭 제한은 조직 제한 이하이고, 두 제한 모두 최대 100,000,000입니다.
