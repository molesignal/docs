```http
POST /api/v1/prometheus/api/v1/write
```

Prometheus 및 VictoriaMetrics의 `remote_write` 버전 1 요청을 수락합니다. 요청은 snappy로 압축한 protobuf 형식입니다. 호출에는 `metrics.write` 권한이 필요하며, 성공하면 `204`를 반환합니다.

요청을 `stream-name` 헤더로 지정한 메트릭 스트림에 기록합니다. 헤더가 없으면 `default` 스트림에 기록합니다. 메트릭 스트림은 단일 소스의 메트릭을 저장합니다. `__name__` 라벨은 `metric_name` 필드가 되고, 나머지 라벨은 각각 필드가 되며, 샘플은 `value` 필드가 됩니다. `metric_name`이나 `metric_kind`처럼 메트릭 필드와 이름이 같은 라벨은 `exported_<name>`으로 저장합니다. 네이티브 히스토그램과 메트릭 메타데이터는 건너뛰고, 예시 데이터(exemplar)는 샘플과 함께 저장합니다.

메트릭이 어느 스트림에 있든 PromQL에서 메트릭 이름으로 쿼리합니다. `service`와 `status` 라벨이 있는 `http_requests_total` 시계열은 다음과 같이 변환됩니다.

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

메트릭이 어느 스트림에 있든 PromQL에서 메트릭 이름으로 쿼리합니다. `service`와 `status` 라벨이 있는 `http_requests_total` 시계열은 다음과 같이 변환됩니다.

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**제한**은 시계열별 및 조직별로 적용합니다. 시계열당 라벨은 최대 64개, 라벨 이름은 최대 128바이트, 라벨 값은 최대 2048바이트로 제한하며, 활성 시계열과 신규 시계열에는 카디널리티 제한을 적용합니다. 프로세스 수준 제한은 [구성](/ko/configuration#데이터-수집)의 `[intake.prometheus]`에서 확인합니다. 조직 전체와 조직 내 개별 메트릭의 활성 시계열 수는 플랫폼의 **설정 → 메트릭 카디널리티**에서 제한합니다. `GET /api/v1/settings/series_limits`로 제한을 조회하고, `PUT`과 동일한 본문 형식인 `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }`으로 제한을 설정합니다. 두 작업 모두 시스템 범위의 `sys.settings.limits.manage` 권한이 필요합니다. 메트릭별 제한은 조직별 제한을 초과할 수 없으며, 두 제한 모두 최대 100,000,000입니다.
