```http
POST /api/v1/functions
```

파이프라인에서 재사용할 수 있는 변환을 생성합니다. 함수를 생성할 때 VRL과 JavaScript를 컴파일하며, 소스가 유효하지 않으면 함수 생성을 거부합니다. 두 런타임은 모두 바이너리에 내장되어 있습니다. 이 호출에는 `functions.create` 권한이 필요합니다.

**본문**

| 필드 | 타입 | 필수 | 참고 |
|---|---|---|---|
| `name` | string | 예 | 함수 이름입니다. |
| `language` | string | 예 | `vrl`, `js` 또는 `llm`입니다. `llm` 함수에는 `[functions].llm_eval_enabled` 설정과 모델 공급자가 필요합니다. |
| `source` | string | 예 | VRL 또는 JavaScript 소스나 `llm` 함수의 지시문입니다. |
| `paramsSchema` | object | 아니요 | 매개변수입니다. `llm`에서는 `outputField`로 출력 필드를 지정하며, 기본값은 `_llm_eval`입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/functions \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "lowercase-level",
    "language": "vrl",
    "source": ".level = downcase!(string!(.level))"
  }'
```
</RequestExample>

구문 오류가 발생하면 `400`을 반환합니다. 오류 메시지의 예는 `js syntax error: Uncaught SyntaxError: Unexpected token '}'`입니다. 저장하기 전에 `POST /api/v1/functions/run`으로 소스를 테스트합니다. 이 엔드포인트는 `language`, `source`, 샘플 `input`을 받아 `output`을 반환합니다. [함수](/ko/functions)를 참조합니다.

다른 함수 경로는 `GET /api/v1/functions`와 `/api/v1/functions/{id}`에 대한 `GET`, `PUT`, `DELETE`입니다. 기본 제공 프리셋은 읽기 전용입니다.

## 저장하기 전에 변환 테스트

드라이런 엔드포인트에는 `functions.create`와 별도로 `functions.run` 권한이 필요합니다. 운영 수집 경로에 변환을 연결하기 전에 누락된 필드와 형식이 잘못된 필드를 포함한 대표 입력으로 테스트합니다.

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".level = downcase!(string!(.level))","input":{"level":"ERROR","message":"example"}}'
```

이 입력에서 `output.level`이 `error`이고, 변환 대상이 아닌 `message` 필드가 그대로 유지되며, `dropped`가 `false`인지 확인합니다. 컴파일이 성공해도 모든 운영 이벤트가 변환의 가정을 충족하는 것은 아닙니다. 예를 들어, 위의 문자열 변환은 실패할 수 있으며 `level`이 문자열이어야 합니다.

## 함수를 파이프라인에 연결

함수를 생성하면 재사용 가능한 정의를 저장할 뿐, 수신 이벤트를 자동으로 변환하지는 않습니다. 반환된 함수 ID를 저장하고 [파이프라인](/ko/pipelines)에서 사용할 함수 단계를 추가한 다음, 운영 스트림에서 활성화하기 전에 전체 파이프라인을 테스트합니다.

대표 입력과 예상 출력을 변경 사항과 함께 기록합니다. 파이프라인을 활성화한 후 테스트 이벤트를 수집하고 대상 스트림을 쿼리하여 저장된 필드를 확인합니다. 드라이런 응답만으로는 배포된 수집 경로를 검증할 수 없습니다.

## 일반적인 오류

| 증상 | 조치 |
|---|---|
| 함수 이름이 비어 있음 | 비어 있지 않은 `name`을 지정합니다. |
| 함수 생성 시 소스가 거부됨 | 구문 오류나 컴파일 오류를 수정한 후 다시 시도합니다. |
| 드라이런이 거부됨 | `functions.run` 권한을 확인합니다. 함수 생성 권한은 별개입니다. |
| 입력 처리 중 런타임 오류가 발생함 | 드라이런에서 오류를 일으킨 필드 구조를 재현하고, 필드가 누락되었거나 타입이 다른 경우를 처리합니다. |
| 저장한 함수가 새 로그에 적용되지 않음 | 함수가 파이프라인에 연결되어 있는지 확인하고 대상 스트림을 확인합니다. |
