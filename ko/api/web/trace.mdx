모든 호출은 조직의 트레이스 스트림 하나를 읽습니다: `trace_id`, `span_id`, `service.name`, `name`, `start_time_unix_nano`, `end_time_unix_nano`, `status_code` 필드를 모두 가진 스트림입니다. 이름이 `default`인 스트림이 조건을 충족하는 다른 스트림보다 우선하며, 스트림 이름이 나머지 동률을 가릅니다. 이러한 스트림이 없는 조직은 빈 결과를 받습니다. [테일 샘플링](/ko/configuration#트레이스-캡처-및-테일-샘플링)을 통과한 트레이스만 읽을 수 있습니다.

모든 호출에는 `traces.read` 또는 시스템 범위의 `sys.telemetry.read` 권한이 필요합니다.

## 트레이스 요약 목록 조회

```http
GET /api/v1/web/traces
```

트레이스마다 요약 하나를 커서 페이지네이션으로 반환합니다. 아직 트레이스 요약이 없는 스트림은 빈 페이지를 반환합니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 설명 |
|---|---|---|
| `from`, `to` | 정수 | 마이크로초 단위의 시간 범위입니다. 기본값은 최근 24시간 전부터 현재까지입니다. `to`는 `from`보다 커야 합니다. |
| `q` | 문자열 | `trace_id`, `span_id`, 스팬의 서비스, 작업 또는 상태에 포함되어야 하는 대소문자 구분 없는 텍스트입니다. 최대 256자입니다. |
| `filters` | 문자열 | 필터의 JSON 배열입니다. 아래를 참조하세요. |
| `where` | 문자열 | 필터와 텍스트를 AND 및 OR로 결합한 JSON 조건 트리입니다. 아래를 참조하세요. |
| `expression` | 문자열 | **트레이스** 페이지에서 작성하는 방식의 필드 쿼리입니다. `q`, `filters`, `where`를 대신하므로 둘 중 하나만 보냅니다. 아래를 참조하세요. |
| `sort` | 문자열 | `latest`(기본값), `earliest`, `duration_desc`, `duration_asc`, `span_count_desc`, `errors_desc` 중 하나입니다. |
| `limit` | 정수 | 페이지 크기입니다. 기본값은 `20`입니다. 값은 1에서 5000 사이로 제한됩니다. |
| `cursor` | 문자열 | 이전 페이지의 `nextCursor` 또는 `previousCursor`입니다. |
| `fields` | 문자열 | 각 트레이스와 함께 반환할 루트 스팬의 필드이며, 쉼표로 구분하고 스트림에서 이름을 지정한 그대로 사용합니다. 최대 12개입니다. 알 수 없는 필드, JSON 필드 또는 `molesignal.trace.*` 필드는 `400` 응답을 반환합니다. |

필터는 `field`, `op`, `value`가 있는 객체이며, 요청에는 필터가 최대 32개 포함됩니다. 모든 필터가 일치해야 합니다. `in` 연산자는 `value` 대신 값 목록인 `values`를 받습니다.

| 필드 | 유형 | 연산자 |
|---|---|---|
| `trace_id` | 텍스트 | `=`, `!=`, `contains`, `in` |
| `duration_ns`, `span_count`, `error_count` | 정수 | `=`, `!=`, `>`, `>=`, `<`, `<=`, `in` |
| 트레이스 스트림의 기타 모든 스칼라 필드 | 필드 유형 기준 | 텍스트: `=`, `!=`, `contains`, `in`. 숫자 및 타임스탬프: `=`, `!=`, `>`, `>=`, `<`, `<=`, `in`. 불리언: `=`, `!=`, `in`. |

필터는 `service.name` 또는 `name`처럼 스트림에서 이름을 지정한 그대로 필드 이름을 사용합니다. 다른 이름은 필드를 의미하지 않습니다. `eq`, `ne`, `like` 연산자는 `=`, `!=`, `contains`의 별칭입니다. JSON 필드는 필터링할 수 없습니다.

`trace_id`, `duration_ns`, `span_count`, `error_count`는 트레이스 단위로 비교됩니다. 나머지 필드는 스팬에 속합니다. 해당 필드에 대한 필터는 스팬 중 하나가 필터를 통과하면 트레이스와 일치하며, `!=`는 스팬 중 어느 것도 해당 값을 갖지 않을 때 트레이스와 일치합니다. 필드가 없는 스팬에는 해당 값이 없습니다.

`in`은 `values` 중 하나와 일치합니다. 값은 1개에서 64개까지이며, 각 값은 최대 512바이트이고 해당 필드의 유형이어야 합니다. 두 번 나열된 값은 한 번만 집계됩니다. 스팬 필드에서 `in`은 스팬 중 하나가 값 중 하나를 가지면 트레이스와 일치합니다.

`where`는 필터 목록으로는 표현할 수 없는 대안을 지정합니다. 다음 네 가지 형식 중 하나의 JSON 객체입니다:

| 형식 | 일치 조건 |
|---|---|
| `filters`에서와 같은 필터 | 해당 필터와 일치합니다. |
| `{"text": "..."}` | `q`가 일치시키는 방식으로 해당 텍스트와 일치합니다. |
| `{"and": [...]}` | 목록의 모든 조건과 일치합니다. |
| `{"or": [...]}` | 목록의 조건 중 하나 이상과 일치합니다. |

`filters`, `q`, `where`는 함께 적용됩니다. 트리 내 필터는 의미를 유지합니다. 스팬 필드에 대한 필터는 스팬 중 하나가 통과하면 트레이스와 일치하고, `!=`는 스팬 중 어느 것도 해당 값을 갖지 않을 때 일치합니다. 트레이스가 `{"or": [A, B]}`와 일치하는 것은 `A`와 일치하거나 `B`와 일치할 때입니다. `filters`와 `where`의 필터는 합산되어 최대 32개 제한에 포함됩니다. 트리는 텍스트를 최대 8회 조회하고, 그룹을 최대 8단계 깊이로 중첩하며, 각 그룹에는 조건이 하나 이상 있어야 합니다.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'filters=[{"field":"status_code","op":"=","value":"ERROR"}]' \
  --data-urlencode 'where={"or":[{"field":"service.name","op":"=","value":"checkout"},{"field":"span_count","op":">","value":"50"}]}'
```

이 요청은 `checkout` 스팬이 있거나 스팬 수가 50개를 초과하는 실패한 트레이스를 나열합니다.

`expression`은 대신 **트레이스** 페이지의 텍스트를 받습니다: `=`, `!=`, `>`, `>=`, `<`, `<=`, `contains`를 사용한 비교, `field in ('a', 'b')`, 검색할 단어, 따옴표로 묶은 구문, 대소문자에 관계없는 `AND` 및 `OR`(`AND`가 더 강하게 결합), 괄호를 사용할 수 있습니다. 서버는 이를 페이지가 전송하는 `q`, `filters`, `where`로 해석하고 위와 같이 검사합니다. 텍스트는 최대 8 KiB이며 괄호 중첩은 최대 32단계입니다. 닫히지 않은 괄호나 비교 대상이 없는 비교처럼 해석할 수 없는 부분이 있으면 `400` 응답을 반환하고 해당 부분을 지목합니다.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "expression=status_code = 'ERROR' AND (service.name = 'checkout' OR span_count > 50)"
```

이 요청은 위의 요청과 동일한 트레이스를 나열합니다.

`cursor`는 페이지를 해당 커서를 발급한 쿼리에 바인딩합니다. 커서와 함께 `limit`, `sort`, `q`, `filters`, `where` 중 하나라도 다른 값으로 요청을 반복하면 `400`을 반환합니다.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'sort=duration_desc' \
  --data-urlencode 'limit=2' \
  --data-urlencode 'fields=http.route' \
  --data-urlencode 'filters=[{"field":"service.name","op":"in","values":["checkout","payments"]}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "service": "checkout",
      "operation": "GET /checkout",
      "startNs": 1790000000000000000,
      "durationMs": 180.0,
      "spanCount": 3,
      "errorCount": 1,
      "status": "ERROR",
      "httpStatusCode": 502,
      "fields": { "http.route": "/checkout" }
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

각 항목은 루트를 기준으로 트레이스를 설명합니다: 루트 스팬의 `service`와 `operation`, 나노초 단위 시작 시간, 밀리초 단위 지속 시간, 스팬 수, 오류 스팬 수입니다. `nextCursor`가 설정되면 `hasMore`는 `true`입니다.

| 필드 | 설명 |
|---|---|
| `status` | 루트 스팬의 상태로, `OK`, `ERROR`, `UNSET` 중 하나입니다. |
| `httpStatusCode` | 루트 스팬이 100에서 599 사이의 코드를 가지고 있으면 해당 스팬의 `http.response.status_code` 또는 `http.status_code`입니다. 그 외의 경우와 요약이 이 값을 보관하기 전에 저장된 트레이스에서는 표시되지 않습니다. |
| `fields` | 루트 스팬에 값이 있는, `fields`에서 요청한 필드입니다. 값이 하나도 없으면 표시되지 않습니다. 해당 필드를 읽지 못하면 해당 필드 없이 페이지를 반환합니다. |

## 시간별 트레이스 수 집계

```http
GET /api/v1/web/traces/histogram
```

목록 쿼리와 일치하는 모든 트레이스를 트레이스 시작 시간 기준의 시간 버킷으로 집계합니다. 이 호출은 목록의 시간 범위, `q`, `filters`, `where`를 받으며 동일한 트레이스와 일치합니다. 버킷은 호출자가 선택합니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 설명 |
|---|---|---|
| `from`, `to` | 정수 | 마이크로초 단위의 시간 범위입니다. 둘 다 필수입니다. `to`는 `from`보다 커야 합니다. |
| `q`, `filters`, `where`, `expression` | 문자열 | 목록과 동일합니다. |
| `bucketTime` | 정수 | 버킷 하나의 길이(마이크로초)입니다. 최소 `1000`입니다. |
| `originTime` | 정수 | 첫 번째 버킷의 시작 시각(마이크로초)입니다. `from`보다 늦을 수 없습니다. |

요청은 `originTime`부터 `to`까지 최대 512개의 버킷을 포함합니다.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/histogram" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=900000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode 'filters=[{"field":"service.name","op":"=","value":"checkout"}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 900000000,
  "originTime": 1790000100000000,
  "buckets": [
    { "startTime": 1790000100000000, "total": 42, "errors": 3, "p50Ns": 41000000, "p95Ns": 180000000, "p99Ns": 320000000 },
    { "startTime": 1790001900000000, "total": 17, "errors": 0, "p50Ns": 38000000, "p95Ns": 95000000, "p99Ns": 120000000 }
  ],
  "split": true
}
```
</ResponseExample>

`buckets`는 트레이스가 있는 버킷만 오래된 순으로 나열합니다. `total`은 해당 버킷에서 시작한 트레이스 수입니다. `errors`는 오류 스팬이 하나 이상 있는 해당 트레이스 수입니다. `p50Ns`, `p95Ns`, `p99Ns`는 해당 트레이스 지속 시간의 중앙값, 95번째 백분위수, 99번째 백분위수(나노초)입니다. 이는 추정치이며 지속 시간이 집계되지 않은 경우에는 표시되지 않습니다.

집계는 트레이스 요약을 읽고, 필터가 스팬 필드에 있으면 스팬도 읽습니다. 목록은 트레이스마다 요약 하나를 반환합니다. 재시도된 쓰기로 인해 요약이 두 번 저장되면 두 번 집계됩니다.

집계를 사용할 수 없어도 호출은 `200`을 반환합니다. 이때 `buckets`는 비어 있고 `unavailable`이 이유를 제공합니다.

| `unavailable` | 원인 |
|---|---|
| `time_budget` | 집계에 20초 넘게 걸렸습니다. |
| `busy` | 역할의 쿼리가 [`[search.admission]`](/ko/configuration#쿼리-승인-제어)을 가득 채웠고 해당 `max_wait_secs` 내에 빈 슬롯이 생기지 않았습니다. |
| `scan_limit` | 시간 범위에 쿼리 하나가 읽을 수 있는 `[querier].max_scan_rows` 제한보다 많은 행이 있습니다. |

## 요청 지표 읽기

```http
GET /api/v1/web/traces/red
GET /api/v1/web/traces/red/breakdown
```

목록 쿼리와 일치하는 요청의 비율, 오류, 기간을 읽습니다: 전체, 버킷별, 소요 시간별로 읽습니다. 분류는 한 필드의 각 값에 대해 동일한 지표를 읽습니다. 요청은 스팬입니다. 기본적으로 요청은 서비스가 요청을 받아들인 스팬, 즉 서버 또는 컨슈머 스팬이거나 트레이스의 루트입니다. `scope=all`은 모든 스팬을 읽습니다.

스팬 필드에 대한 필터는 스팬 자체에 적용되므로 `service.name = 'api'`는 `api`가 처리한 요청을 읽습니다. `trace_id`와 `duration_ns`는 스팬에서 읽고, `span_count`와 `error_count`는 스팬이 속한 트레이스에서 읽습니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 비고 |
|---|---|---|
| `from`, `to`, `bucketTime`, `originTime` | integer | 시간별 트레이스 수와 동일합니다. |
| `q`, `filters`, `where`, `expression` | string | 목록과 동일합니다. |
| `scope` | string | `entry`(기본값) 또는 `all`입니다. |
| `by` | string | 분류에서만 사용하며 필수입니다. 요청을 그룹화할 필드이며, 스트림에서 이름을 지정한 그대로 사용합니다. |

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/red" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=60000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode "expression=service.name = 'checkout'"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "scope": "entry",
  "total": { "requests": 1840, "errors": 12, "p50Ns": 41000000.0, "p95Ns": 180000000.0, "p99Ns": 320000000.0 },
  "buckets": [
    { "startTime": 1790000100000000, "requests": 31, "errors": 0, "p50Ns": 40000000.0, "p95Ns": 150000000.0, "p99Ns": 210000000.0 }
  ],
  "latency": [
    { "fromNs": 0, "toNs": 50000000, "requests": 1203, "errors": 2 },
    { "fromNs": 50000000, "toNs": null, "requests": 637, "errors": 10 }
  ]
}
```
</ResponseExample>

`buckets`는 요청이 있는 버킷을 오래된 순으로 나열합니다. `latency`는 요청을 기간이 짧은 순으로 나열하며, 마지막 범위에는 상한이 없습니다. `errors`는 실패를 판별할 수 없는 경우 `null`이고, 기간은 나노초 단위이며 요청이 없거나 기간이 마스킹된 경우 `null`입니다.

분류는 `field`, `bucketTime`, `originTime`, `scope`, `groups`를 반환합니다. 가장 흔한 값 50개가 먼저 나오며, 각 값에는 지표와 `requests`, `errors`, `p95Ns`가 포함된 버킷의 `series`가 있습니다. 값이 없는 요청의 경우 `value`는 `null`입니다. 나열된 값보다 더 많은 값이 있으면 `more`는 `true`입니다.

지표를 사용할 수 없을 때도 호출은 `200`과 함께 `unavailable`을 반환합니다. `time_budget`, `busy`, `scan_limit`은 시간별 트레이스 수와 동일하고, 조회자에게 시간이 마스킹된 경우 `timestamp_masked`, 분류 필드가 마스킹되거나 암호화된 경우 `field_protected`입니다.

`by`는 JSON 필드 내부의 키를 지정할 수도 있으며, 필드 이름 뒤에 작성합니다(예: `attributes.tenant`). 이 경우 해당 키가 보유한 값을 기준으로 요청을 그룹화합니다.

## 느리거나 실패한 요청 비교

```http
GET /api/v1/web/traces/red/compare
```

쿼리에서 선택한 요청을 나머지 요청과 필드별로 비교합니다. 실패한 요청, 특정 시간 이상 또는 미만이 걸린 요청, 또는 지정된 조건을 모두 충족하는 요청을 대상으로 합니다. 각 필드에 대해 두 집합에서 각 값의 비중을 비교하고, 필드는 비중이 얼마나 다른지에 따라 순위가 매겨집니다. `0`(동일한 구성)부터 `1`(공통 값 없음)까지입니다. ID, 시점, 기간, JSON 필드는 제외되며, 행마다 값이 거의 모두 다른 필드도 제외됩니다. 실패한 요청을 선택한 경우 `status_code`도 제외됩니다. 각 집합은 처음 1,000개 스팬의 샘플로 읽습니다.

**쿼리 매개변수**

RED 지표의 매개변수에서 `by`를 제외하고 다음 매개변수를 사용합니다:

| 매개변수 | 유형 | 비고 |
|---|---|---|
| `errors` | boolean | 실패한 요청을 선택합니다. |
| `minDuration` | integer | 이 나노초 값 이상 걸린 요청을 선택합니다. |
| `maxDuration` | integer | 이 나노초 값 미만 걸린 요청을 선택합니다. |

이 중 하나 이상이 필요하며, `minDuration`은 `maxDuration`보다 작아야 합니다.

<ResponseExample>
```json 200
{
  "scope": "entry",
  "selected": 212,
  "baseline": 1000,
  "sampled": true,
  "dimensions": [
    {
      "field": "cloud.region",
      "score": 0.71,
      "values": [
        { "value": "eu-west-1", "selected": 0.83, "baseline": 0.12 },
        { "value": "us-east-1", "selected": 0.17, "baseline": 0.88 }
      ]
    }
  ]
}
```
</ResponseExample>

`selected`와 `baseline`은 각 집합에서 읽은 스팬 수이고, 둘 중 하나라도 더 많은 스팬이 있었으면 `sampled`는 `true`입니다. `dimensions`는 최대 20개 필드를 차이가 큰 순으로 나열하며, 각 필드는 비중 차이가 가장 큰 최대 5개 값을 포함합니다. 값이 없는 요청의 경우 `value`는 `null`입니다. `unavailable`은 RED 지표와 동일하게 응답합니다.

## 스팬 나열

```http
GET /api/v1/web/traces/spans
```

쿼리와 일치하는 각 스팬당 한 행을 반환하며, 커서 페이지네이션을 사용합니다. 이 호출은 트레이스 목록의 시간 범위, `q`, `filters`, `where`를 받아 각 스팬에 대해 읽습니다. 스팬 필드에 대한 필터는 스팬 자체에 적용되고, `!=`는 해당 필드가 없는 스팬을 유지합니다. `duration_ns`는 스팬 자체의 기간입니다. `span_count`와 `error_count`는 스팬이 속한 트레이스의 값입니다. 스팬이 `A`와 일치하거나 `B`와 일치하면 `{"or": [A, B]}`와 일치합니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 비고 |
|---|---|---|
| `from`, `to` | integer | 마이크로초 단위의 시간 범위입니다. 기본값은 현재까지의 지난 24시간입니다. `to`는 `from`보다 커야 합니다. |
| `q`, `filters`, `where`, `expression` | string | 트레이스 목록과 동일합니다. |
| `sort` | string | `latest`(기본값), `earliest`, `duration_desc`, `duration_asc` 중 하나입니다. |
| `limit` | integer | 페이지 크기입니다. 기본값은 `100`입니다. 값은 1에서 5000 사이로 제한됩니다. |
| `cursor` | string | 이전 페이지의 `nextCursor` 또는 `previousCursor`입니다. 커서는 해당 페이지의 쿼리를 포함하며, 다른 `limit`을 사용하면 `400`을 반환합니다. |

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "durationNs": 140000000,
      "status": "ERROR",
      "kind": 2,
      "httpStatusCode": 502
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

`status`는 `OK`, `ERROR`, `UNSET` 중 하나입니다. `kind`는 OTLP에서처럼 스팬 종류를 숫자로 나타냅니다. `1`은 internal, `2`는 server, `3`은 client, `4`는 producer, `5`는 consumer입니다. `parent_span_id`, `kind`, `http_status_code`는 스팬에 해당 값이 없으면 생략됩니다. 이 호출은 추적된 쿼리로 실행되며 다른 쿼리와 동일하게 허용됩니다.

## 트레이스 하나 읽기

```http
GET /api/v1/web/trace/{traceId}
```

트레이스의 모든 스팬을 시작 시간 순으로 반환합니다. `trace_id`는 `A-Z`, `a-z`, `0-9`, `-`, `_` 중 1~128자로 구성됩니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 비고 |
|---|---|---|
| `from`, `to` | integer | 트레이스의 스팬이 시작된 마이크로초 단위의 시간 범위입니다. 둘 다 제공하거나 둘 다 제공하지 않습니다. 최대 31일입니다. 제공하지 않으면 지난 24시간 내에서 트레이스를 찾습니다. |

응답은 100,000개 스팬과 32 MiB로 제한됩니다. 제한으로 인해 스팬 목록이 잘린 경우 `truncated`는 `true`입니다.

<ResponseExample>
```json 200
{
  "traceId": "0af7651916cd43dd8448eb211c80319c",
  "rootSpanId": "b7ad6b7169203331",
  "spans": [
    {
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "endNs": 1790000000160000000,
      "durationNs": 140000000,
      "kind": 2,
      "status": "ERROR",
      "statusMessage": "upstream timeout",
      "attributes": { "http.method": "POST", "http.status_code": "502" },
      "events": [],
      "links": [],
      "samplingReason": "error",
      "partial": false,
      "late": false,
      "duplicate": false,
      "conflict": false
    }
  ],
  "truncated": false,
  "partial": false,
  "partialReasons": [],
  "samplingReasons": ["error"],
  "lateSpanCount": 0,
  "duplicateSpanCount": 0,
  "conflictSpanCount": 0
}
```
</ResponseExample>

예시는 주요 필드가 있는 스팬 하나를 보여줍니다. 실제 스팬에는 `traceFlags`, `traceState`, `resource`, `scope`, `dropped_*_count` 카운터, `schemaVersion`, `semanticConventionsVersion`도 포함됩니다.

| 필드 | 비고 |
|---|---|
| `rootSpanId` | 부모가 없는 첫 번째 스팬입니다. `span_id`와 `parent_span_id`로 트리를 구성합니다. |
| `spans[].status` | `OK`, `ERROR`, `UNSET` 중 하나입니다. |
| `spans[].attributes` | 스트림의 평면화된 속성 열과 병합된 스팬 속성입니다. |
| `spans[].sampling_reason` | 테일 샘플러가 트레이스를 유지한 이유입니다(예: `error`). |
| `partial`, `partialReasons` | 스팬이 누락되었는지 여부와 그 이유입니다. |
| `lateSpanCount`, `duplicateSpanCount`, `conflictSpanCount` | 늦게 도착했거나, 중복되었거나, 충돌한 스팬입니다. |

## 트레이스에 링크하는 스팬 찾기

```http
GET /api/v1/web/trace/{traceId}/linked
```

스팬은 자신이 이어지는 스팬에 대한 링크를 유지하며, 트레이스 상세는 해당 스팬과 함께 링크를 반환합니다. 이 호출은 반대 방향을 찾습니다. 즉, 링크가 이 트레이스의 스팬을 가리키는 다른 트레이스의 스팬을 찾습니다. 트레이스 상세와 동일한 `from`과 `to`를 받아 해당 구간을 검색합니다.

<ResponseExample>
```json 200
{
  "spans": [
    {
      "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
      "spanId": "00f067aa0ba902b7",
      "service": "billing-worker",
      "operation": "process invoice",
      "startNs": 1790000005000000000,
      "durationNs": 30000000,
      "status": "OK",
      "linkedSpanId": "53995c3f42cd8ad8",
      "attributes": { "messaging.operation": "process" }
    }
  ],
  "more": false
}
```
</ResponseExample>

`spans`는 링크하는 스팬을 최대 200개까지 최신순으로 나열하며, 트레이스에 링크하는 스팬이 더 있으면 `more`가 `true`입니다. `linkedSpanId`는 링크가 가리키는 이 트레이스의 스팬이고, `attributes`에는 링크의 속성이 들어 있습니다.

검색은 트레이스 개수 조회의 시간 예산 내에서 구간에 있는 모든 스팬의 링크를 텍스트로 읽습니다. 검색을 완료할 수 없으면 호출은 트레이스 개수 조회의 경우와 마찬가지로 빈 `spans`와 `unavailable` 사유(`time_budget`, `busy`, `scan_limit`)와 함께 여전히 `200`을 반환합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 매개변수가 유효하지 않습니다. `to`가 `from`보다 크지 않거나, 필터가 알 수 없는 필드나 연산자를 사용하거나(`unsupported trace filter field: nope`), `in` 필터에 값이 없거나 64개를 초과하거나, `where`가 조건 트리가 아니거나 한도를 초과하거나, `expression`이 `q`, `filters` 또는 `where`와 함께 제공되거나 읽을 수 없는 부분이 있거나, 커서가 쿼리와 일치하지 않거나, `fields`의 필드가 알 수 없거나 문서 타입이거나, `trace_id`의 문자나 길이가 유효하지 않은 경우입니다. 개수 조회의 경우 구간 또는 버킷 매개변수가 누락되었거나, `bucketTime`이 `1000` 미만이거나, `originTime`이 `from` 이후이거나, 요청이 512개를 초과하는 버킷을 포함하는 경우입니다. 트레이스 상세 및 링크하는 스팬의 경우 `from`과 `to` 중 하나만 제공되었거나 구간이 31일보다 긴 경우입니다. |
| `403` | 토큰에 `traces.read` 권한이 없습니다. |
| `404` | 구간에서 트레이스를 찾을 수 없거나 샘플링에서 제외되었습니다. |
