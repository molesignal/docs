모든 호출은 조직에서 `trace_id`, `span_id`, `service.name`, `name`, `start_time_unix_nano`, `end_time_unix_nano`, `status_code` 필드를 모두 갖춘 트레이스 스트림 하나를 읽습니다. 조건을 충족하는 스트림 중 이름이 `default`인 스트림을 우선 선택하고, 그 외에 후보가 여러 개면 스트림 이름을 기준으로 선택합니다. 조건을 충족하는 스트림이 없는 조직에는 빈 결과를 반환합니다. [테일 샘플링](/ko/configuration#트레이스-캡처-및-테일-샘플링)에서 유지한 트레이스만 읽을 수 있습니다.

모든 호출에는 `traces.read` 권한이 필요합니다. 시스템 범위에서는 대신 `sys.telemetry.read` 권한이 필요합니다.

## 트레이스 요약 목록 조회

```http
GET /api/v1/web/traces
```

트레이스마다 요약 하나를 반환하며, 커서 기반 페이지네이션을 사용합니다. 스트림에 트레이스 요약이 아직 없으면 빈 페이지를 반환합니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 참고 |
|---|---|---|
| `from`, `to` | 정수 | 조회 시간 범위(µs)입니다. 기본값은 현재 시점까지의 최근 24시간입니다. `to`는 `from`보다 커야 합니다. |
| `q` | 문자열 | 스팬의 `trace_id`, `span_id`, 서비스, 작업 또는 상태 중 하나에 포함되어야 하는 텍스트입니다. 대소문자를 구분하지 않으며 최대 256자입니다. |
| `filters` | 문자열 | 필터의 JSON 배열입니다. 아래 내용을 참조합니다. |
| `where` | 문자열 | 필터와 텍스트를 AND와 OR로 연결한 JSON 조건 트리입니다. 아래 내용을 참조합니다. |
| `expression` | 문자열 | **트레이스** 페이지에서 사용하는 형식의 필드 쿼리입니다. `expression`을 사용하거나 `q`, `filters`, `where`를 사용합니다. 두 방식을 함께 사용하지 않습니다. 아래 내용을 참조합니다. |
| `sort` | 문자열 | `latest`(기본값), `earliest`, `duration_desc`, `duration_asc`, `span_count_desc`, `errors_desc` 중 하나입니다. |
| `limit` | 정수 | 페이지 크기입니다. 기본값은 `20`입니다. 1 미만이면 1로, 5000을 초과하면 5000으로 조정합니다. |
| `cursor` | 문자열 | 앞선 응답 페이지의 `nextCursor` 또는 `previousCursor`입니다. |
| `fields` | 문자열 | 각 트레이스와 함께 반환할 루트 스팬 필드입니다. 스트림에 정의된 필드 이름을 쉼표로 구분해 최대 12개까지 지정합니다. 알 수 없는 필드, JSON 필드 또는 `molesignal.trace.*` 필드를 지정하면 `400`을 반환합니다. |

필터는 `field`, `op`, `value`를 포함하는 객체입니다. 요청 하나에 필터를 최대 32개까지 지정할 수 있습니다. 모든 필터를 충족해야 합니다. `in` 연산자는 `value` 대신 값 목록인 `values`를 사용합니다.

| 필드 | 유형 | 연산자 |
|---|---|---|
| `trace_id` | 텍스트 | `=`, `!=`, `contains`, `in` |
| `duration_ns`, `span_count`, `error_count` | 정수 | `=`, `!=`, `>`, `>=`, `<`, `<=`, `in` |
| 트레이스 스트림의 기타 스칼라 필드 | 필드 유형에 따름 | 텍스트: `=`, `!=`, `contains`, `in`. 숫자 및 타임스탬프: `=`, `!=`, `>`, `>=`, `<`, `<=`, `in`. 불리언: `=`, `!=`, `in`. |

필터에는 `service.name`이나 `name`처럼 스트림에 정의된 필드 이름을 그대로 지정합니다. 다른 이름으로 필드를 지정할 수 없습니다. `eq`, `ne`, `like` 연산자는 각각 `=`, `!=`, `contains`의 별칭입니다. JSON 필드에는 필터를 적용할 수 없습니다.

`trace_id`, `duration_ns`, `span_count`, `error_count`는 트레이스 수준에서 비교합니다. 나머지 필드는 모두 스팬에 속합니다. 스팬 필드에 필터를 적용하면 스팬 중 하나라도 필터를 충족하는 트레이스가 일치합니다. 단, `!=`는 해당 값을 가진 스팬이 하나도 없는 트레이스와 일치합니다. 필드가 없는 스팬에는 해당 값이 없는 것으로 간주합니다.

`in`은 `values`에 지정한 값 중 하나라도 일치하면 충족합니다. 값은 1개에서 64개까지 지정하며, 각 값은 최대 512바이트이고 필드와 유형이 같아야 합니다. 중복 값은 한 번만 계산합니다. 스팬 필드에 `in`을 적용하면 스팬 중 하나라도 목록의 값 중 하나를 가진 트레이스가 일치합니다.

`where`는 필터 목록만으로 표현할 수 없는 OR 조건을 지정할 수 있습니다. 다음 네 가지 형식 중 하나를 사용하는 JSON 객체입니다.

| 형식 | 일치 조건 |
|---|---|
| `filters`와 같은 형식의 필터 | 필터를 충족합니다. |
| `{"text": "..."}` | `q`와 같은 방식으로 텍스트가 일치합니다. |
| `{"and": [...]}` | 목록의 모든 조건을 충족합니다. |
| `{"or": [...]}` | 목록의 조건 중 하나 이상을 충족합니다. |

`filters`, `q`, `where`를 모두 충족해야 합니다. 조건 트리에서도 필터의 동작은 같습니다. 스팬 필드에 적용한 필터는 스팬 중 하나라도 필터를 충족하는 트레이스와 일치하며, `!=`는 해당 값을 가진 스팬이 하나도 없는 트레이스와 일치합니다. `{"or": [A, B]}`는 `A` 또는 `B`를 충족하는 트레이스와 일치합니다. `filters`와 `where`에 포함된 필터를 합쳐 최대 32개까지 지정할 수 있습니다. 한 트리에 텍스트 검색 조건을 최대 8개까지 지정하고 그룹을 최대 8단계까지 중첩할 수 있습니다. 각 그룹에는 조건이 하나 이상 있어야 합니다.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'filters=[{"field":"status_code","op":"=","value":"ERROR"}]' \
  --data-urlencode 'where={"or":[{"field":"service.name","op":"=","value":"checkout"},{"field":"span_count","op":">","value":"50"}]}'
```

이 요청은 실패한 트레이스 중 `checkout` 스팬이 있거나 스팬이 50개를 초과하는 트레이스를 나열합니다.

`expression`에는 대신 **트레이스** 페이지에서 사용하는 쿼리 텍스트를 지정합니다. `=`, `!=`, `>`, `>=`, `<`, `<=`, `contains`, `field in ('a', 'b')`를 사용한 비교, 검색할 단어, 따옴표로 묶은 구문, 대소문자를 구분하지 않는 `AND`와 `OR`, 괄호를 지원합니다. `AND`는 `OR`보다 우선합니다. 서버는 이 텍스트를 페이지에서 전송하는 `q`, `filters`, `where`로 변환하고 위와 같은 방식으로 검증합니다. 텍스트는 최대 8 KiB이며 괄호는 최대 32단계까지 중첩할 수 있습니다. 닫히지 않은 괄호나 비교 대상이 없는 비교식처럼 해석할 수 없는 부분이 있으면 `400`을 반환하고 해당 부분을 표시합니다.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "expression=status_code = 'ERROR' AND (service.name = 'checkout' OR span_count > 50)"
```

이 요청은 위 요청과 동일한 트레이스를 나열합니다.

`cursor`는 해당 페이지를 커서를 발급한 쿼리에 연결합니다. 커서로 다시 요청할 때 `limit`, `sort`, `q`, `filters`, `where` 중 하나라도 변경하면 `400`을 반환합니다.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'sort=duration_desc' \
  --data-urlencode 'limit=2' \
  --data-urlencode 'fields=http.route' \
  --data-urlencode 'filters=[{"field":"service.name","op":"in","values":["checkout","payments"]}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "service": "checkout",
      "operation": "GET /checkout",
      "startNs": 1790000000000000000,
      "durationMs": 180.0,
      "spanCount": 3,
      "errorCount": 1,
      "status": "ERROR",
      "httpStatusCode": 502,
      "fields": { "http.route": "/checkout" }
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

각 항목은 루트 스팬을 기준으로 트레이스를 설명합니다. 루트 스팬의 `service`와 `operation`, 시작 시간(ns), 지속 시간(ms), 스팬 수, 오류 스팬 수를 포함합니다. `nextCursor`가 설정되어 있으면 `hasMore`는 `true`입니다.

| 필드 | 참고 |
|---|---|
| `status` | 루트 스팬의 상태입니다. `OK`, `ERROR`, `UNSET` 중 하나입니다. |
| `httpStatusCode` | 루트 스팬의 `http.response.status_code` 또는 `http.status_code`에 기록된 100~599 범위의 코드입니다. 해당 범위의 코드가 없거나 요약에 이 코드를 기록하기 전에 저장한 트레이스에서는 이 필드를 생략합니다. |
| `fields` | `fields`로 요청한 필드 중 루트 스팬에 값이 있는 필드입니다. 해당하는 필드가 없으면 생략합니다. 필드 값을 읽지 못해도 해당 필드를 제외하고 페이지를 반환합니다. |

## 시간 구간별 트레이스 수 집계

```http
GET /api/v1/web/traces/histogram
```

목록 쿼리와 일치하는 모든 트레이스를 시작 시간에 따라 시간 버킷별로 집계합니다. 목록 조회와 동일한 시간 범위, `q`, `filters`, `where`를 사용해 같은 트레이스와 일치합니다. 요청에서 버킷을 지정합니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 참고 |
|---|---|---|
| `from`, `to` | 정수 | 조회 시간 범위(µs)입니다. 둘 다 필수입니다. `to`는 `from`보다 커야 합니다. |
| `q`, `filters`, `where`, `expression` | 문자열 | 목록 조회와 동일합니다. |
| `bucketTime` | 정수 | 버킷 하나의 길이(µs)입니다. 최소값은 `1000`입니다. |
| `originTime` | 정수 | 첫 번째 버킷의 시작 시간(µs)입니다. `from`보다 늦을 수 없습니다. |

요청 하나는 `originTime`부터 `to`까지 최대 512개 버킷을 포함합니다.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/histogram" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=900000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode 'filters=[{"field":"service.name","op":"=","value":"checkout"}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 900000000,
  "originTime": 1790000100000000,
  "buckets": [
    { "startTime": 1790000100000000, "total": 42, "errors": 3, "p50Ns": 41000000, "p95Ns": 180000000, "p99Ns": 320000000 },
    { "startTime": 1790001900000000, "total": 17, "errors": 0, "p50Ns": 38000000, "p95Ns": 95000000, "p99Ns": 120000000 }
  ],
  "split": true
}
```
</ResponseExample>

`buckets`에는 트레이스가 하나 이상 있는 버킷만 오래된 순서대로 나열합니다. `total`은 해당 버킷에서 시작한 트레이스 수입니다. `errors`는 그중 오류 스팬이 하나 이상 있는 트레이스 수입니다. `p50Ns`, `p95Ns`, `p99Ns`는 해당 트레이스의 지속 시간(ns)에 대한 중앙값, 95번째 백분위수, 99번째 백분위수입니다. 이 값은 추정치이며, 집계한 지속 시간이 없으면 생략합니다.

집계는 트레이스 요약을 읽고, 스팬 필드에 필터를 적용한 경우에는 스팬도 읽습니다. 목록 조회는 트레이스마다 요약 하나를 반환합니다. 쓰기 재시도로 같은 요약을 두 번 저장하면 집계에는 두 번 포함합니다.

집계 결과를 제공할 수 없는 경우에도 `200`을 반환합니다. 이때 `buckets`는 비어 있고 `unavailable`에 이유를 표시합니다.

| `unavailable` | 원인 |
|---|---|
| `time_budget` | 집계에 20초 넘게 걸렸습니다. |
| `busy` | 해당 역할의 쿼리가 [`[search.admission]`](/ko/configuration#쿼리-승인-제어)에서 허용하는 슬롯을 모두 사용 중이며, `max_wait_secs` 내에 빈 슬롯이 생기지 않았습니다. |
| `scan_limit` | 조회 시간 범위의 행 수가 `[querier].max_scan_rows`에서 쿼리 하나에 허용한 읽기 한도를 초과했습니다. |

## 요청 지표 조회

```http
GET /api/v1/web/traces/red
GET /api/v1/web/traces/red/breakdown
```

목록 쿼리와 일치하는 요청의 처리율, 오류, 소요 시간을 조회합니다. 전체 집계, 버킷별 집계, 소요 시간 구간별 집계를 제공합니다. 필드별 집계에서는 한 필드의 각 값에 대해 같은 지표를 조회합니다. 요청은 스팬 하나에 해당합니다. 기본적으로 서비스가 요청을 받은 지점의 스팬, 즉 서버 스팬, 컨슈머 스팬 또는 트레이스의 루트 스팬을 요청으로 간주합니다. `scope=all`은 모든 스팬을 조회합니다.

스팬 필드에 대한 필터는 해당 스팬 자체에 적용됩니다. 따라서 `service.name = 'api'`는 `api`가 처리한 요청을 조회합니다. `trace_id`와 `duration_ns`는 스팬에서, `span_count`와 `error_count`는 해당 스팬이 속한 트레이스에서 읽습니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 설명 |
|---|---|---|
| `from`, `to`, `bucketTime`, `originTime` | 정수 | 시간대별 트레이스 수 조회와 동일합니다. |
| `q`, `filters`, `where`, `expression` | 문자열 | 목록 조회와 동일합니다. |
| `scope` | 문자열 | `entry`(기본값) 또는 `all`입니다. |
| `by` | 문자열 | 필드별 집계에서만 사용하며, 이때는 필수입니다. 요청을 그룹화할 필드의 이름을 스트림에 정의된 그대로 지정합니다. |

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/red" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=60000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode "expression=service.name = 'checkout'"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "scope": "entry",
  "total": { "requests": 1840, "errors": 12, "p50Ns": 41000000.0, "p95Ns": 180000000.0, "p99Ns": 320000000.0 },
  "buckets": [
    { "startTime": 1790000100000000, "requests": 31, "errors": 0, "p50Ns": 40000000.0, "p95Ns": 150000000.0, "p99Ns": 210000000.0 }
  ],
  "latency": [
    { "fromNs": 0, "toNs": 50000000, "requests": 1203, "errors": 2 },
    { "fromNs": 50000000, "toNs": null, "requests": 637, "errors": 10 }
  ]
}
```
</ResponseExample>

`buckets`는 요청이 있는 버킷을 오래된 순서로 나열합니다. `latency`는 요청을 소요 시간 구간별로 나누어 짧은 구간부터 나열합니다. 마지막 구간에는 상한이 없습니다. 실패 여부를 확인할 수 없으면 `errors`는 `null`입니다. 소요 시간의 단위는 나노초이며, 요청이 없거나 소요 시간을 마스킹한 경우에는 `null`입니다.

필드별 집계는 `field`, `bucketTime`, `originTime`, `scope`, `groups`를 반환합니다. `groups`는 빈도가 높은 값부터 최대 50개를 나열합니다. 각 값에는 해당 지표와 버킷 시계열인 `series`가 포함되며, 각 버킷에는 `requests`, `errors`, `p95Ns`가 들어 있습니다. 필드 값이 없는 요청의 `value`는 `null`입니다. 목록에 표시한 것보다 값이 더 많으면 `more`는 `true`입니다.

지표를 조회할 수 없어도 API는 `unavailable` 사유와 함께 `200`을 반환합니다. 사유는 트레이스 수 조회와 동일한 `time_budget`, `busy`, `scan_limit`과, 조회 권한에 따라 시간 값을 마스킹한 경우의 `timestamp_masked`, 집계 필드를 마스킹하거나 암호화한 경우의 `field_protected`입니다.

## 스팬 목록 조회

```http
GET /api/v1/web/traces/spans
```

쿼리와 일치하는 스팬마다 한 행을 반환하며, 커서 기반 페이지 매김을 사용합니다. 트레이스 목록 조회와 같은 시간 범위, `q`, `filters`, `where`를 받아 각 스팬에 적용합니다. 스팬 필드에 대한 필터는 스팬 자체에 적용되며, `!=` 조건은 해당 필드가 없는 스팬도 포함합니다. `duration_ns`는 스팬 자체의 소요 시간입니다. `span_count`와 `error_count`는 스팬이 속한 트레이스의 값입니다. 스팬이 `A` 또는 `B`와 일치하면 `{"or": [A, B]}`와 일치합니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 설명 |
|---|---|---|
| `from`, `to` | 정수 | 시간 범위를 마이크로초 단위로 지정합니다. 기본값은 현재 시점까지의 최근 24시간입니다. `to`는 `from`보다 커야 합니다. |
| `q`, `filters`, `where`, `expression` | 문자열 | 트레이스 목록 조회와 동일합니다. |
| `sort` | 문자열 | `latest`(기본값), `earliest`, `duration_desc`, `duration_asc` 중 하나입니다. |
| `limit` | 정수 | 페이지 크기입니다. 기본값은 `100`입니다. 값을 1~5000 범위로 제한합니다. |
| `cursor` | 문자열 | 앞서 조회한 페이지의 `nextCursor` 또는 `previousCursor`입니다. 커서에는 해당 페이지의 쿼리가 포함됩니다. `limit`을 다르게 지정하면 `400`을 반환합니다. |

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "durationNs": 140000000,
      "status": "ERROR",
      "kind": 2,
      "httpStatusCode": 502
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

`status`는 `OK`, `ERROR`, `UNSET` 중 하나입니다. `kind`는 OTLP와 동일한 숫자로 스팬 유형을 나타냅니다. `1`은 내부, `2`는 서버, `3`은 클라이언트, `4`는 프로듀서, `5`는 컨슈머입니다. 스팬에 해당 값이 없으면 `parent_span_id`, `kind`, `http_status_code`를 각각 생략합니다. 이 API 호출은 추적 대상 쿼리로 실행되며, 다른 쿼리와 동일한 실행 허용 기준을 따릅니다.

## 단일 트레이스 조회

```http
GET /api/v1/web/trace/{traceId}
```

트레이스의 모든 스팬을 시작 시간순으로 반환합니다. `trace_id`는 `A-Z`, `a-z`, `0-9`, `-`, `_`로 구성된 1~128자 문자열입니다.

**쿼리 매개변수**

| 매개변수 | 유형 | 설명 |
|---|---|---|
| `from`, `to` | 정수 | 트레이스의 스팬이 시작된 시간 범위를 마이크로초 단위로 지정합니다. 두 값 모두 지정하거나 모두 생략합니다. 최대 범위는 31일입니다. 두 값을 생략하면 최근 24시간 내에서 트레이스를 찾습니다. |

응답은 최대 100,000개 스팬과 32 MiB로 제한합니다. 한도에 도달해 스팬 목록의 일부를 생략하면 `truncated`는 `true`입니다.

<ResponseExample>
```json 200
{
  "traceId": "0af7651916cd43dd8448eb211c80319c",
  "rootSpanId": "b7ad6b7169203331",
  "spans": [
    {
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "endNs": 1790000000160000000,
      "durationNs": 140000000,
      "kind": 2,
      "status": "ERROR",
      "statusMessage": "upstream timeout",
      "attributes": { "http.method": "POST", "http.status_code": "502" },
      "events": [],
      "links": [],
      "samplingReason": "error",
      "partial": false,
      "late": false,
      "duplicate": false,
      "conflict": false
    }
  ],
  "truncated": false,
  "partial": false,
  "partialReasons": [],
  "samplingReasons": ["error"],
  "lateSpanCount": 0,
  "duplicateSpanCount": 0,
  "conflictSpanCount": 0

```
</ResponseExample>

예제는 스팬 하나의 주요 필드를 보여 줍니다. 실제 스팬에는 `traceFlags`, `traceState`, `resource`, `scope`, `dropped_*_count` 카운터, `schemaVersion`, `semanticConventionsVersion`도 포함됩니다.

| 필드 | 설명 |
|---|---|
| `rootSpanId` | 상위 스팬이 없는 첫 번째 스팬입니다. `span_id`와 `parent_span_id`를 사용해 트리를 구성합니다. |
| `spans[].status` | `OK`, `ERROR`, `UNSET` 중 하나입니다. |
| `spans[].attributes` | 스팬 속성과 스트림에서 평탄화한 속성 열을 병합한 결과입니다. |
| `spans[].sampling_reason` | 테일 샘플러가 트레이스를 유지한 이유입니다. 예를 들어 `error`가 있습니다. |
| `partial`, `partialReasons` | 스팬 누락 여부와 그 이유입니다. |
| `lateSpanCount`, `duplicateSpanCount`, `conflictSpanCount` | 늦게 도착했거나, 중복되었거나, 충돌한 스팬의 개수입니다. |

## 트레이스에 연결되는 스팬 찾기

```http
GET /api/v1/web/trace/{traceId}/linked
```

스팬은 자신이 이어받은 스팬에 대한 링크를 저장하며, 트레이스 상세 조회는 해당 링크를 스팬과 함께 반환합니다. 이 API는 반대 방향으로 검색합니다. 다른 트레이스의 스팬 중 이 트레이스의 스팬을 가리키는 링크가 있는 스팬을 찾습니다. 트레이스 상세 조회와 동일한 `from`과 `to`를 받아 해당 시간 범위를 검색합니다.

<ResponseExample>
```json 200
{
  "spans": [
    {
      "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
      "spanId": "00f067aa0ba902b7",
      "service": "billing-worker",
      "operation": "process invoice",
      "startNs": 1790000005000000000,
      "durationNs": 30000000,
      "status": "OK",
      "linkedSpanId": "53995c3f42cd8ad8",
      "attributes": { "messaging.operation": "process" }
    }
  ],
  "more": false
}
```
</ResponseExample>

`spans`는 링크를 가진 스팬을 최신순으로 최대 200개까지 나열합니다. 트레이스에 연결되는 스팬이 목록에 표시된 것보다 더 많으면 `more`는 `true`입니다. `linkedSpanId`는 링크가 가리키는 이 트레이스 내 스팬의 ID이며, `attributes`에는 링크의 속성이 들어 있습니다.

검색은 트레이스 수 조회와 동일한 시간 한도 내에서 지정한 시간 범위에 속하는 모든 스팬의 링크를 텍스트로 읽습니다. 검색을 완료하지 못해도 API는 빈 `spans`와 `unavailable` 사유를 포함해 `200`을 반환합니다. 사유는 트레이스 수 조회와 동일하게 `time_budget`, `busy`, `scan_limit` 중 하나입니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 매개변수가 유효하지 않습니다. `to`가 `from`보다 크지 않거나, 필터가 알 수 없는 필드 또는 연산자를 사용하거나(`unsupported trace filter field: nope`), `in` 필터의 값이 없거나 64개를 초과하거나, `where`가 조건 트리가 아니거나 허용 한도를 초과하거나, `expression`을 `q`, `filters`, `where` 중 하나와 함께 지정했거나 해석할 수 없는 부분이 있거나, 커서가 쿼리와 일치하지 않거나, `fields`에 알 수 없는 필드 또는 문서 유형의 필드가 있거나, `trace_id`의 문자 또는 길이가 유효하지 않습니다. 개수 조회에서는 시간 범위 또는 버킷 매개변수가 누락되었거나, `bucketTime`이 `1000` 미만이거나, `originTime`이 `from`보다 늦거나, 요청 범위가 512개 버킷을 초과한 경우에도 이 오류를 반환합니다. 트레이스 상세 및 연결 스팬 조회에서는 `from`과 `to` 중 하나만 지정했거나 시간 범위가 31일을 초과한 경우에도 이 오류를 반환합니다. |
| `403` | 토큰에 `traces.read` 권한이 없습니다. |
| `404` | 지정한 시간 범위에서 트레이스를 찾지 못했거나 샘플링에서 트레이스를 제외했습니다. |
