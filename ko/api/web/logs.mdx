이 호출은 **로그** 페이지와 같은 방식으로 조직의 로그 스트림 하나를 읽습니다. 스트림이 없으면 빈 결과를 반환합니다. 모든 호출에는 `logs.read` 권한이 필요하며, 시스템 범위에서는 `sys.telemetry.read` 권한이 필요합니다.

각 호출은 JSON 본문을 포함한 `POST` 또는 동일한 필드를 쿼리 문자열에 넣은 `GET`을 받습니다. `filters`와 `freeText`는 JSON 목록을 나타내는 문자열로, `where`는 JSON 객체를 나타내는 문자열로 보냅니다. URL에 넣기에는 쿼리가 너무 길면 `POST`로 보냅니다.

## 호출의 일치 조건

호출은 지정한 시간 범위 내에서 다음 조건을 모두 충족하는 스트림 레코드와 일치합니다.

| 필드 | 유형 | 참고 |
|---|---|---|
| `filters` | 목록 | 모두 충족해야 하는 필터입니다. `where`의 필터를 포함해 최대 32개까지 지정할 수 있습니다. |
| `freeText` | 목록 | `message` 필드에서 찾을 단어 또는 구문입니다. 각 항목은 최대 512 bytes입니다. 소문자와 숫자로만 이루어진 최대 40 bytes의 단어는 대소문자를 구분하지 않고 일치시킵니다. 그 밖의 텍스트는 입력한 그대로 일치시킵니다. `where`의 텍스트 조건을 포함해 최대 8개까지 지정할 수 있습니다. |
| `where` | 객체 | 조건을 조합하는 트리입니다. 각 노드는 필터, `{"text": "..."}`, `{"and": [...]}`, `{"or": [...]}` 중 하나입니다. |
| `expression` | 문자열 | **로그** 페이지에서 사용하는 형식의 필드 쿼리입니다. `filters`, `freeText`, `where`를 대신하므로 두 방식을 함께 사용하지 않습니다. |

필터는 `field`, `op`, `value`, `quoted`를 포함하는 객체입니다. 스트림에 정의된 필드 이름을 그대로 사용합니다.

| 연산자 | 필드 | 일치 조건 |
|---|---|---|
| `=`, `!=` | 모든 스칼라 필드 | 각각 지정한 값과 같거나 다른 값과 일치합니다. 빈 값을 지정하면 필드에 값이 있는지만 확인합니다. `=`는 값이 없는 레코드와 일치합니다. |
| `>`, `>=`, `<`, `<=` | 숫자 및 타임스탬프 | 비교 조건을 충족하는 값과 일치합니다. |
| `contains` | 텍스트 | 필드 내 어느 위치에든 지정한 값이 있으면 일치합니다. |
| `match` | 모든 필드 | 대소문자를 구분하지 않고 지정한 값이 부분 문자열로 포함되면 일치합니다. 빈 값은 어떤 레코드와도 일치하지 않습니다. |
| `match_text` | 전문 검색 인덱스가 있는 텍스트 | 단어, 구문, 와일드카드로 전문 검색을 수행합니다. 필드에 전문 검색 인덱스가 없으면 `400`을 반환합니다. |

`eq`, `ne`, `like`는 각각 `=`, `!=`, `contains`의 별칭입니다. 따옴표로 묶은 값의 `quoted`는 `true`입니다. 따옴표로 묶은 값은 숫자가 아닌 단어로 처리합니다. 여기서는 JSON 필드를 필터링할 수 없습니다. SQL로 쿼리합니다.

`expression`은 **로그** 페이지의 쿼리 텍스트를 받습니다. 비교식, `MATCH(field, 'text')`와 `MATCH_TEXT(field, 'words')`, 검색할 단어, 따옴표로 묶은 구문, 대소문자를 구분하지 않는 `AND`와 `OR`, 괄호를 사용할 수 있습니다. `AND`가 `OR`보다 우선합니다. 서버는 쿼리를 페이지에서 전송하는 `filters`, `freeText`, `where`로 변환한 뒤 위의 규칙에 따라 검증합니다. 텍스트는 최대 8 KiB이며 괄호는 최대 32단계까지 중첩할 수 있습니다. 닫히지 않은 괄호나 비교 대상이 없는 비교식처럼 해석할 수 없는 부분이 있으면 `400`을 반환하고 해당 부분을 표시합니다.

```bash
curl -G "http://localhost:5080/api/v1/web/logs" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'stream=app' \
  --data-urlencode "expression=level = 'error' AND (service.name = 'checkout' OR timeout)"
```

## 레코드 목록 조회

```http
POST /api/v1/web/logs
GET  /api/v1/web/logs
```

일치하는 레코드를 최신순으로 반환하며, 커서 기반 페이지네이션을 사용합니다.

| 필드 | 유형 | 참고 |
|---|---|---|
| `stream` | 문자열 | 필수입니다. 로그 스트림을 지정합니다. |
| `from`, `to` | 정수 | 마이크로초 단위의 시간 범위입니다. 기본값은 현재 시점까지의 최근 24시간입니다. `to`는 `from`보다 커야 합니다. |
| `filters`, `freeText`, `where`, `expression` | | 호출의 일치 조건을 지정합니다. |
| `limit` | 정수 | 페이지 크기입니다. 기본값은 `20`이며, 1 미만이면 1로, 5000을 초과하면 5000으로 조정합니다. |
| `cursor` | 문자열 | 앞서 조회한 페이지의 `nextCursor` 또는 `previousCursor`입니다. 첫 페이지의 시간 범위와 일치 조건을 유지합니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/web/logs \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"stream":"app","expression":"level = '\''error'\''","limit":2}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    { "_timestamp": 1790000000000000, "level": "error", "message": "db pool exhausted", "trace_id": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "nextCursor": "eyJ2IjoxLC...",
  "previousCursor": null,
  "hasMore": true
}
```
</ResponseExample>

각 항목에는 레코드의 필드가 포함됩니다. `_timestamp`는 마이크로초 단위입니다. `cursor`를 포함한 요청에서 스트림, 시간 범위, `limit`, 일치 조건 중 하나라도 달라지면 `400`을 반환합니다.

## 시간대별 레코드 수 집계

```http
POST /api/v1/web/logs/histogram
GET  /api/v1/web/logs/histogram
```

시간 구간별로 일치하는 레코드 수를 집계합니다.

| 필드 | 유형 | 참고 |
|---|---|---|
| `stream` | 문자열 | 필수입니다. |
| `from`, `to` | 정수 | 필수입니다. 마이크로초 단위의 시간 범위입니다. |
| `filters`, `freeText`, `where`, `expression` | | 호출의 일치 조건을 지정합니다. |
| `bucketTime` | 정수 | 마이크로초 단위의 구간 길이입니다. 최솟값은 `1000`입니다. |
| `originTime` | 정수 | 첫 구간의 시작 시점입니다. `from`보다 늦을 수 없습니다. |

한 요청은 `originTime`부터 `to`까지 최대 512개 구간을 포함합니다.

```json
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "buckets": [{ "startTime": 1790000100000000, "total": 120, "errors": 4 }],
  "split": true
}
```

`buckets`는 레코드가 하나 이상 있는 구간을 오래된 순서로 나열합니다. `errors`는 `level` 또는 `body_level` 필드를 기준으로 레벨이 `ERROR`인 레코드 수를 집계합니다. 스트림에 두 필드가 모두 없거나 조회 시 레벨 값이 마스킹되면 `split`은 `false`이고 `errors`는 `0`입니다. 집계할 수 없으면 [트레이스 수 집계](/ko/api/web/trace#시간-구간별-트레이스-수-집계)와 마찬가지로 빈 `buckets`와 `unavailable` 사유(`time_budget`, `busy`, `scan_limit` 중 하나)를 포함한 `200` 응답을 반환합니다.

## 필드 요약 조회

```http
POST /api/v1/web/logs/field-stats
GET  /api/v1/web/logs/field-stats
```

일치하는 레코드에서 지정한 필드의 값을 요약합니다.

| 필드 | 유형 | 참고 |
|---|---|---|
| `stream` | 문자열 | 필수입니다. |
| `from`, `to` | 정수 | 마이크로초 단위의 시간 범위입니다. |
| `filters`, `freeText`, `where`, `expression` | | 호출의 일치 조건을 지정합니다. |
| `field` | 문자열 | 필수입니다. 스트림에 정의된 필드 이름을 그대로 지정합니다. |

```json
{
  "kind": "text",
  "total": 1840,
  "present": 1840,
  "distinct": 3,
  "distinctExact": true,
  "top": [{ "value": "info", "count": 1500 }, { "value": "warn", "count": 300 }, { "value": "error", "count": 40 }],
  "topSkipped": false
}
```

`kind`는 `number`, `time`, `text`, `bool` 중 하나입니다. `total`은 일치하는 레코드 수이고, `present`는 그중 필드에 값이 있는 레코드 수입니다. `top`은 자주 나타나는 값을 빈도가 높은 순서로 나열합니다. 거의 모든 값이 서로 달라 `top`에 값을 나열하지 않으면 `topSkipped`가 `true`입니다. `range`는 최솟값과 최댓값을 텍스트로 반환합니다. 숫자 필드에는 `spread`와 `bars`도 포함합니다. `trend`는 시간 범위 내에서 자주 나타나는 값의 빈도를 시간에 따라 집계합니다. 다른 값보다 자주 나타나는 값이 없으면 `trend`를 반환하지 않습니다.

## 오류

| 상태 | 원인 |
|---|---|
| `400` | 매개변수가 유효하지 않습니다. `stream`이 누락되었거나, `to`가 `from`보다 크지 않거나, 필터가 알 수 없는 필드를 지정하거나 필드 유형에서 지원하지 않는 연산자를 사용하거나, 목록 또는 트리가 제한을 초과하거나, `expression`을 `filters`, `freeText`, `where` 중 하나와 함께 지정했거나 해석할 수 없는 부분이 있거나, 커서가 쿼리와 일치하지 않거나, 히스토그램 매개변수가 누락되었거나 512개를 초과하는 구간을 포함합니다. |
| `403` | 토큰에 `logs.read` 권한이 없습니다. |
