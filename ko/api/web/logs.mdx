이 호출은 **로그** 페이지가 읽는 방식 그대로 조직의 로그 스트림 하나를 읽습니다. 존재하지 않는 스트림은 빈 결과를 반환합니다. 모든 호출에는 `logs.read` 또는 시스템 범위의 `sys.telemetry.read`가 필요합니다.

패턴 그룹화를 제외한 각 호출은 JSON 본문을 사용하는 `POST`를 사용하거나, 동일한 필드를 쿼리 문자열에 담은 `GET`을 사용합니다. `filters`와 `freeText`는 JSON 목록의 텍스트로, `where`는 JSON 객체의 텍스트로 전달합니다. 주소에 담기에는 너무 긴 쿼리는 `POST`로 보냅니다.

## 호출이 일치시키는 대상

호출은 시간 범위 내 스트림의 레코드 중 다음 조건을 모두 통과하는 레코드와 일치합니다.

| 필드 | 타입 | 비고 |
|---|---|---|
| `filters` | 목록 | 모두 충족하는 필터입니다. 최대 32개이며, `where`의 필터와 함께 계산합니다. |
| `freeText` | 목록 | `message` 필드에서 찾을 단어 또는 구문이며, 각각 최대 512바이트입니다. 문자와 숫자로 된 소문자 단어(최대 40바이트)는 대소문자와 관계없이 일치하고, 그 밖의 텍스트는 작성된 그대로 일치합니다. 최대 8개이며, `where`의 텍스트와 함께 계산합니다. |
| `where` | 객체 | 대안을 위한 조건 트리로, 필터, `{"text": "..."}`, `{"and": [...]}`, 또는 `{"or": [...]}`입니다. |
| `expression` | 문자열 | **로그** 페이지가 작성하는 방식의 필드 쿼리입니다. `filters`, `freeText`, `where`를 대신하므로 둘 중 하나만 보냅니다. |

필터는 `field`, `op`, `value`, `quoted`를 가진 객체입니다. 필드는 스트림이 이름 붙이는 방식으로 지정합니다.

| 연산자 | 필드 | 일치 대상 |
|---|---|---|
| `=`, `!=` | 모든 스칼라 필드 | 해당 값 또는 그 밖의 모든 값입니다. 값이 비어 있으면 필드에 값이 있는지 여부를 나타내며, `=`는 값이 없는 레코드와 일치합니다. |
| `>`, `>=`, `<`, `<=` | 숫자 및 타임스탬프 | 비교입니다. |
| `contains` | 텍스트 | 필드 어디에든 값이 있는지 확인합니다. |
| `match` | 모든 필드 | 대소문자와 관계없이 값을 부분 문자열로 찾습니다. 빈 값은 아무것도 일치하지 않습니다. |
| `match_text` | 전체 텍스트 인덱스가 있는 텍스트 | 단어, 구문, 와일드카드를 사용하는 전체 텍스트 검색입니다. 전체 텍스트 인덱스가 없는 필드는 `400`을 반환합니다. |

`eq`, `ne`, `like`는 `=`, `!=`, `contains`의 별칭입니다. `quoted`는 따옴표로 작성한 값, 즉 단어에 대해 `true`이며 숫자에는 사용하지 않습니다. JSON 필드는 여기서 필터링할 수 없으므로 SQL로 쿼리합니다.

`expression`은 **로그** 페이지의 텍스트를 받습니다: 비교, `MATCH(field, 'text')`와 `MATCH_TEXT(field, 'words')`, 찾을 단어, 따옴표로 묶은 구문, 대소문자를 가리지 않는 `AND`와 `OR`(`AND`가 더 강하게 결합), 괄호를 사용합니다. 서버는 이를 페이지가 보내는 `filters`, `freeText`, `where`로 해석하고 위와 같이 검사합니다. 텍스트는 최대 8 KiB이며 괄호는 최대 32단계까지 중첩할 수 있습니다. 닫히지 않은 괄호나 비교 대상이 없는 비교처럼 해석할 수 없는 부분이 있으면 `400`을 반환하고 해당 부분을 알려줍니다.

```bash
curl -G "http://localhost:5080/api/v1/web/logs" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'stream=app' \
  --data-urlencode "expression=level = 'error' AND (service.name = 'checkout' OR timeout)"
```

## 레코드 목록 조회

```http
POST /api/v1/web/logs
GET  /api/v1/web/logs
```

일치하는 레코드를 최신순으로 반환하며, 커서 페이지네이션을 사용합니다.

| 필드 | 타입 | 비고 |
|---|---|---|
| `stream` | 문자열 | 필수입니다. 로그 스트림입니다. |
| `from`, `to` | 정수 | 마이크로초 단위의 시간 범위입니다. 기본값은 지난 24시간부터 현재까지입니다. `to`는 `from`보다 커야 합니다. |
| `filters`, `freeText`, `where`, `expression` | | 호출이 일치시키는 대상입니다. |
| `limit` | 정수 | 페이지 크기입니다. 기본값은 `20`이며 1부터 5000 사이로 제한됩니다. |
| `cursor` | 문자열 | 이전 페이지의 `nextCursor` 또는 `previousCursor`입니다. 첫 페이지의 시간 범위와 일치 조건을 유지합니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/web/logs \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"stream":"app","expression":"level = '\''error'\''","limit":2}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    { "_timestamp": 1790000000000000, "level": "error", "message": "db pool exhausted", "trace_id": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "nextCursor": "eyJ2IjoxLC...",
  "previousCursor": null,
  "hasMore": true
}
```
</ResponseExample>

각 항목은 레코드의 필드를 담습니다. `_timestamp`는 마이크로초 단위입니다. `cursor`와 함께 스트림, 시간 범위, `limit`, 일치 조건이 다른 요청은 `400`을 반환합니다.

## 시간별 레코드 수 집계

```http
POST /api/v1/web/logs/histogram
GET  /api/v1/web/logs/histogram
```

일치하는 레코드를 시간 버킷별로 집계합니다.

| 필드 | 타입 | 비고 |
|---|---|---|
| `stream` | 문자열 | 필수입니다. |
| `from`, `to` | 정수 | 필수입니다. 마이크로초 단위의 시간 범위입니다. |
| `filters`, `freeText`, `where`, `expression` | | 호출이 일치시키는 대상입니다. |
| `bucketTime` | 정수 | 버킷 하나의 길이(마이크로초)입니다. 최소 `1000`입니다. |
| `originTime` | 정수 | 첫 번째 버킷의 시작입니다. `from`보다 늦을 수 없습니다. |

요청은 `originTime`부터 `to`까지 최대 512개의 버킷을 포함합니다.

```json
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "buckets": [{ "startTime": 1790000100000000, "total": 120, "errors": 4 }],
  "split": true
}
```

`buckets`는 레코드가 있는 버킷을 오래된 순으로 나열합니다. `errors`는 `level` 또는 `body_level`에서 읽은 `ERROR` 레벨 레코드의 수입니다. 스트림에 두 필드가 모두 없거나 읽는 사람에게 레벨이 마스킹된 경우 `split`은 `false`이며, 이때 `errors`는 `0`입니다. 집계를 사용할 수 없으면 [트레이스 수 집계](/ko/api/web/trace#시간별-트레이스-수-집계)와 마찬가지로 빈 `buckets`와 `unavailable`(`time_budget`, `busy`, 또는 `scan_limit`)을 담아 `200`을 반환합니다.

## 필드 설명 조회

```http
POST /api/v1/web/logs/field-stats
GET  /api/v1/web/logs/field-stats
```

일치하는 레코드에서 한 필드가 가지는 값을 설명합니다.

| 필드 | 타입 | 비고 |
|---|---|---|
| `stream` | 문자열 | 필수입니다. |
| `from`, `to` | 정수 | 마이크로초 단위의 시간 범위입니다. |
| `filters`, `freeText`, `where`, `expression` | | 호출이 일치시키는 대상입니다. |
| `field` | 문자열 | 필수입니다. 스트림이 이름 붙이는 방식의 필드입니다. |

```json
{
  "kind": "text",
  "total": 1840,
  "present": 1840,
  "distinct": 3,
  "distinctExact": true,
  "top": [{ "value": "info", "count": 1500 }, { "value": "warn", "count": 300 }, { "value": "error", "count": 40 }],
  "topSkipped": false
}
```

`kind`는 `number`, `time`, `text`, `bool` 중 하나입니다. `total`은 일치하는 레코드 수를, `present`는 값이 있는 레코드 수를 셉니다. `top`은 가장 흔한 값을 흔한 순으로 나열하며, 거의 모든 값이 다르고 나열할 값이 없으면 `topSkipped`가 `true`입니다. `range`는 가장 작은 값과 가장 큰 값을 텍스트로 제공합니다. 숫자 필드는 `spread`와 `bars`를 추가합니다. `trend`는 시간 범위 내 가장 흔한 값의 수를 집계하며, 다른 값보다 흔한 값이 없으면 생략됩니다.

## 패턴으로 그룹화

```http
POST /api/v1/web/logs/patterns
```

일치하는 레코드를 전체 시간 범위에 걸쳐 메시지 패턴으로 그룹화하고, 각 패턴을 기준 구간과 비교합니다. 일치하는 레코드가 5,000개를 초과하는 시간 범위는 동일한 네 구간의 최신 레코드 샘플로 읽으며, 각 패턴의 `estimatedCount`는 해당 수를 시간 범위 전체로 환산합니다. 이 호출에는 `logs.read`가 필요합니다.

| 필드 | 타입 | 비고 |
|---|---|---|
| `stream` | 문자열 | 필수입니다. |
| `from`, `to` | 정수 | 필수입니다. 마이크로초 단위의 시간 범위입니다. |
| `filters`, `freeText`, `where`, `expression` | | 호출이 일치시키는 대상입니다. |
| `field` | 문자열 | 메시지를 담은 필드입니다. 생략하면 스트림에 있는 `message`, `body`, `summary`, `log`, `event`, `error`, `msg`, `content`, `text` 중 첫 번째를 사용합니다. |
| `baseline` | 문자열 | `previous`(기본값이며 바로 앞의 동일한 길이 구간), `week_before`, 또는 `none`입니다. |
| `limit` | 정수 | 나열할 최대 패턴 수로, 기본값은 100이며 최대 200입니다. |

```json
{
  "stream": "app_logs",
  "field": "message",
  "levelField": "level",
  "timeRange": { "startTime": 1795510800000000, "endTime": 1795514399999999 },
  "logs": 48210,
  "read": 5000,
  "unread": 0,
  "sampled": true,
  "baseline": { "kind": "previous", "startTime": 1795507199999999, "endTime": 1795510799999999, "logs": 40102, "read": 5000, "sampled": true },
  "newPatterns": 1,
  "surgingPatterns": 0,
  "droppingPatterns": 0,
  "patternCount": 37,
  "patterns": [
    {
      "pattern": "upstream timeout after <number>ms",
      "tokens": [{ "lead": "", "trail": "", "text": "upstream", "wild": null, "unit": "" }],
      "count": 41,
      "share": 0.0082,
      "estimatedCount": 395,
      "firstSeen": 1795513020000000,
      "lastSeen": 1795514390000000,
      "levels": [{ "level": "ERROR", "count": 41 }],
      "baselineCount": 0,
      "change": "new",
      "fragment": "upstream timeout after",
      "example": "upstream timeout after 3000ms"
    }
  ]
}
```

새로운 패턴과 급증하는 패턴이 먼저 나오고, 시간 범위에 더 이상 없는 패턴이 마지막에 나옵니다. `change`는 `new`(기준 구간에 없음), `surging`(최소 5개 이상이면서 두 배 이상), `dropping`(최소 5개 이상이면서 절반 이하), 또는 `steady`이며, `ratio`는 기준 구간 대비 시간 범위의 추정 수 비율입니다. `tokens`는 패턴의 단어이며, `wild`는 열린 위치에서 달라지는 내용을 나타냅니다. 저장 시 암호화된 필드는 `400`을 반환합니다. 아무것도 기록되지 않은 스트림은 빈 보고서를 반환합니다.

## 오류

| 상태 | 원인 |
|---|---|
| `400` | 매개변수가 유효하지 않습니다: `stream`이 없거나, `to`가 `from`보다 크지 않거나, 필터가 알 수 없는 필드를 지정하거나 해당 타입이 허용하지 않는 연산자를 사용하거나, 목록 또는 트리가 제한을 초과하거나, `expression`이 `filters`, `freeText`, `where`와 함께 오거나 해석할 수 없는 부분이 있거나, 커서가 쿼리와 일치하지 않거나, 히스토그램 매개변수가 없거나 512개를 초과하는 버킷을 포함하는 경우입니다. |
| `403` | 토큰에 `logs.read`가 없습니다. |
