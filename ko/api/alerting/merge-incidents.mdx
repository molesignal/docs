```http
POST /api/v1/alerts/incidents/{id}/merge
```

`sourceIds`에 지정한 인시던트를 `{id}` 인시던트에 병합합니다. 병합된 각 인시던트는 기본 인시던트를
`mergedInto`에 기록합니다. 이후에는 알림을 보내거나 에스컬레이션하지 않으며
[인시던트 목록 조회](/ko/api/alerting/list-incidents) 및 인사이트에 표시되지 않습니다. 활성 상태는 유지되므로 해당 규칙이나
소스는 같은 문제로 새 인시던트를 생성하지 않습니다. 기본 인시던트를 해결하면 병합된 인시던트도 해결됩니다. 병합된
인시던트가 먼저 복구되면 기본 인시던트의
[타임라인](/ko/api/alerting/incident-timeline)에 기록합니다. 병합 대상에 이미 병합된 인시던트도
기본 인시던트로 옮깁니다. 병합은 취소할 수 없습니다.

기본 인시던트와 모든 병합 대상은 활성 상태여야 하며 다른 인시던트에 병합된 상태가 아니어야 합니다. `sourceIds`에 기본 인시던트의
ID나 중복 ID가 있으면 무시합니다. 이 호출에는 기본
인시던트에 대한 `alerts.incidents.escalate` 권한이 필요합니다.

**본문**

| 필드 | 유형 | 필수 | 참고 |
|---|---|---|---|
| `sourceIds` | 배열 | 예 | 병합할 인시던트의 ID 1~50개입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/merge \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"sourceIds": ["<incident-id>", "<another-incident-id>"]}'
```
</RequestExample>

응답은 기본 인시던트입니다. 각 필드에 대한 설명은 [인시던트 목록 조회](/ko/api/alerting/list-incidents)를 참조합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | `sourceIds`에 기본 인시던트 외의 인시던트가 없거나 50개를 초과합니다. |
| `403` | 토큰에 `alerts.incidents.escalate` 권한이 없거나 인시던트가 토큰의 접근 범위를 벗어납니다. |
| `404` | 기본 인시던트 또는 `sourceIds`에 지정한 인시던트 중 하나가 존재하지 않습니다. |
| `409` | 기본 인시던트 또는 `sourceIds`에 지정한 인시던트 중 하나가 이미 복구되었거나 다른 인시던트에 병합되었거나, 업데이트 중에 인시던트가 계속 변경되었습니다. 다시 시도합니다. |
