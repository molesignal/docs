티켓 커넥터는 Jira(Cloud 또는 Data Center / Server), ServiceNow 또는 Feishu Project(중국
외 지역에서는 Meegle)를 연결합니다. 인시던트에 대해 생성한 티켓은 인시던트의 변경 사항을 따라갑니다. 인시던트 확인 및 해결 내역과 메모를
댓글로 기록할 수 있으며, 인시던트를 해결할 때 티켓을 완료 상태로 전환할 수 있습니다. 티켓 상태는
5분마다 동기화하며, Jira는 웹훅을 통해 상태를 즉시 전송할 수도 있습니다. 페이지에서 티켓을 사용하는 방법은
[티켓](/ko/alerting/tickets)을 참조합니다.

| 메서드 및 경로 | 기능 | 권한 |
|---|---|---|
| `GET /api/v1/alerts/tickets/connectors` | 조직의 티켓 커넥터를 `{ "connectors": [ ... ] }` 형식으로 반환합니다. | `alerts.tickets.read` |
| `POST /api/v1/alerts/tickets/connectors` | 커넥터를 생성합니다. | `alerts.tickets.manage` |
| `PUT /api/v1/alerts/tickets/connectors/{id}` | 커넥터를 교체합니다. `system`은 변경할 수 없습니다. | `alerts.tickets.manage` |
| `DELETE /api/v1/alerts/tickets/connectors/{id}` | 커넥터를 삭제합니다. | `alerts.tickets.manage` |
| `POST /api/v1/alerts/tickets/connectors/{id}/test` | 연결을 테스트합니다. Jira는 `{ "ok": true, "detail": "<signed-in user>" }`를 반환하고 Feishu Project는 작업 항목 유형을 한 번 조회합니다. | `alerts.tickets.manage` |
| `GET /api/v1/alerts/tickets/sites` | 각 Feishu Project 플랫폼의 주소를 반환합니다. `{ "meegle": [{ "key": "feishu", "url": "https://project.feishu.cn" }, { "key": "lark", "url": "https://meegle.com" }] }` | `alerts.tickets.read` |
| `GET /api/v1/alerts/incidents/{id}/tickets` | 인시던트의 티켓을 `{ "tickets": [ ... ] }` 형식으로 반환합니다. | 해당 인시던트의 `alerts.incidents.read` |
| `POST /api/v1/alerts/incidents/{id}/tickets` | 커넥터를 사용해 인시던트의 티켓을 생성합니다. | 해당 인시던트의 `alerts.incidents.tickets` |
| `POST /api/v1/public/tickets/jira/{connectorId}` | 로그인 없이 Jira 웹훅을 수신합니다. | `X-Hub-Signature` |

## 커넥터

**요청 본문**

| 필드 | 유형 | 필수 여부 | 참고 |
|---|---|---|---|
| `name` | string | 예 | 이름입니다. |
| `system` | string | 예 | `jira` 또는 `meegle`입니다. |
| `settings` | object | 예 | 사이트, 프로젝트, 유형 및 매핑입니다. 아래 내용을 참조합니다. |
| `secrets` | object | 생성 시 | 자격 증명입니다. 암호화하여 저장하며 응답에 포함하지 않습니다. Jira는 `apiToken`(Cloud API 토큰 또는 Data Center 개인 액세스 토큰)과 선택 사항인 `webhook_secret`을 사용하고, Feishu Project는 `plugin_secret`을 사용합니다. 변경 시 비밀 값을 비워 두면 기존 값을 유지합니다. |
| `comments` | object | 아니요 | `{ "acknowledged": true, "resolved": true, "notes": true }`: 인시던트를 확인하거나 해결할 때 댓글을 남기고 인시던트 메모를 댓글로 기록합니다. 기본값은 모두 `false`입니다. |
| `transitionOnResolve` | boolean | 아니요 | 인시던트를 해결하면 티켓을 완료 상태로 전환합니다. 기본값은 `false`입니다. |
| `resolveIncidentWhenDone` | boolean | 아니요 | 티켓이 완료되면 인시던트가 열려 있거나 확인된 상태인지와 관계없이 인시던트를 해결하며, 해결한 사람은 기록하지 않습니다. 기본값은 `false`입니다. |
| `auto` | object | 아니요 | 자동 티켓 생성 설정입니다. `{ "enabled": true, "minSeverity": "error", "conditions": [ ... ] }`. 새 인시던트의 심각도가 `minSeverity` 이상이고 레이블이 `conditions`를 충족하면 티켓을 생성합니다. `conditions`는 [라우팅 규칙](/ko/api/alerting/create-routing-rule)과 같은 방식으로 작성합니다. |
| `onMajorIncident` | boolean | 아니요 | [주요 인시던트](/ko/api/alerting/major-incidents)를 선언할 때 티켓을 생성합니다. 기본값은 `false`입니다. |
| `enabled` | boolean | 아니요 | 기본값은 `true`입니다. 비활성화한 커넥터는 티켓을 생성하거나 동기화하지 않으며 웹훅을 수신하지 않습니다. |

**`settings`: Jira**

| 필드 | 참고 |
|---|---|
| `siteUrl` | `https://`로 시작하는 사이트 주소입니다. 예: `https://example.atlassian.net`. |
| `deployment` | `cloud`(기본값): 계정 이메일과 API 토큰을 사용합니다. REST API v3로 통신하며 본문은 Atlassian Document Format으로 작성합니다. `data_center`: 개인 액세스 토큰을 사용하며 REST API v2로 통신합니다. |
| `email` | Cloud 계정 이메일입니다. |
| `projectKey`, `issueType` | 프로젝트 키와 이슈 유형입니다. 예: `OPS` 및 `Incident`. |
| `priorities` | 심각도를 Jira 우선순위 이름에 매핑합니다. 예: `{ "critical": "Highest" }`. 매핑하지 않은 심각도에는 우선순위를 설정하지 않습니다. |
| `labels` | 모든 티켓에 붙는 `molesignal` 레이블 외에 추가할 레이블입니다. |
| `fields` | 티켓 생성 시 사용할 다른 필드의 기본값입니다. Jira 필드 ID를 키로 사용합니다. |
| `resolveTransition` | 인시던트를 해결할 때 적용할 전환의 이름 또는 ID입니다. 비워 두면 완료 상태로 이어지는 첫 번째 전환을 적용합니다. |

**`settings`: Feishu Project**

| 필드 | 참고 |
|---|---|
| `site` | 플랫폼입니다. `feishu`(기본값, Feishu Project, `https://project.feishu.cn`) 또는 `lark`(Meegle, `https://meegle.com`)를 사용합니다. 주소는 플랫폼에 따라 정해지며 변경할 수 없습니다. |
| `pluginId` | 플러그인 ID입니다. `plugin_secret`과 함께 사용해 플러그인 토큰을 발급받습니다. |
| `userKey` | 티켓과 댓글을 작성할 때 사용할 사용자 명의입니다. |
| `projectKey`, `workItemTypeKey` | 스페이스와 작업 항목 유형입니다. |
| `priorityField`, `priorities` | 우선순위 필드의 키와 심각도를 우선순위 옵션 값에 매핑하는 설정입니다. 비워 두면 우선순위를 설정하지 않습니다. |
| `fields` | 티켓 생성 시 사용할 다른 필드의 기본값입니다. field_key를 키로 사용합니다. |
| `resolveTransitionId` | 상태 흐름 작업 항목에서 인시던트를 해결할 때 적용할 전환의 ID입니다. |
| `resolveNodeId` | 노드 흐름 작업 항목에서 인시던트를 해결할 때 완료할 노드의 ID입니다. |
| `doneStates` | 완료로 간주할 상태의 키입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/tickets/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "name": "Jira OPS",
    "system": "jira",
    "settings": {
      "siteUrl": "https://example.atlassian.net",
      "deployment": "cloud",
      "email": "oncall-bot@example.com",
      "projectKey": "OPS",
      "issueType": "Incident",
      "priorities": { "critical": "Highest", "error": "High" }
    },
    "secrets": { "apiToken": "<jira-api-token>", "webhookSecret": "<webhook-secret>" },
    "comments": { "acknowledged": true, "resolved": true, "notes": true },
    "transitionOnResolve": true,
    "auto": { "enabled": true, "minSeverity": "critical", "conditions": [] }
  }'
```
</RequestExample>

응답은 저장한 커넥터입니다. `secrets`는 반환하지 않으며, `secretsSet`에는 설정된 자격 증명
목록을 반환합니다. Jira 커넥터에는 `webhook_path`도 포함되며, 값은
`/api/v1/public/tickets/jira/<connector ID>`입니다. 생성, 변경 및 삭제 작업은 감사 로그에 기록합니다.

**ServiceNow의 `settings`**

| 필드 | 설명 |
|---|---|
| `instanceUrl` | https로 시작하는 인스턴스 주소입니다. |
| `auth` | `basic`(기본값, 비밀 값 `password`), `oauth`(클라이언트 자격 증명, 비밀 값 `clientSecret`) 또는 `apiKey`(비밀 값 `apiKey`)입니다. |
| `username`, `clientId` | 각각 기본 인증 사용자와 OAuth 클라이언트 ID입니다. |
| `table` | 티켓을 생성할 테이블입니다. 기본값은 `incident`이며, 테이블은 `task`를 확장해야 합니다. |
| `assignmentGroup`, `callerId`, `category` | 생성 시 입력하는 필드입니다. 처음 두 필드는 `sys_id`를 사용합니다. |
| `priorities` | 심각도 또는 우선순위 → `impact/urgency` 매핑입니다. 숫자 하나를 지정하면 두 값에 모두 적용합니다. |
| `fields` | 생성 시 사용할 다른 필드의 기본값입니다(필드 이름 → 값). |
| `resolveState`, `closeCode` | 인시던트를 해결할 때 기록하는 `state`와 `closeCode`입니다. 기본값은 각각 `6`과 `Solution provided`입니다. `closeCode`를 비워 두면 해당 값을 기록하지 않습니다. |
| `doneStates` | 완료로 간주할 `state` 값입니다. 기본값은 `6`, `7`, `8`입니다. |

커넥터를 테스트하면 `{ "ok": true, "detail": "<table>" }`를 반환합니다.

## 인시던트 티켓 생성

```http
POST /api/v1/alerts/incidents/{id}/tickets
```

| 필드 | 유형 | 필수 여부 | 참고 |
|---|---|---|---|
| `connectorId` | string | 예 | 티켓을 생성할 커넥터입니다. 해당 커넥터에 인시던트 티켓이 이미 있으면 기존 티켓을 반환합니다. |

티켓 제목은 `[severity] incident summary` 형식입니다. 본문에는 인시던트의 심각도와 상태,
서비스, 레이블, 트리거 쿼리, AI 근본 원인 분석 요약 및 인시던트 페이지 주소를
워크스페이스의 기본 언어로 표시합니다. 티켓은 인시던트 타임라인과 감사 로그에 기록합니다.

<ResponseExample>
```json 200
{
  "id": "3KJ4m8T1qHd0Ue6WzB2nLc9RfPa",
  "orgId": "<organization-id>",
  "incidentId": "<incident-id>",
  "connectorId": "<connector-id>",
  "system": "jira",
  "externalId": "10482",
  "externalKey": "OPS-42",
  "url": "https://example.atlassian.net/browse/OPS-42",
  "status": "To Do",
  "done": false,
  "incidentStatus": "open",
  "createdBy": "<user-id>",
  "createdAt": 1790000000000000,
  "syncedAt": 1790000000000000,
  "lastError": "",
  "actionItemId": null
}
```
</ResponseExample>

| 필드 | 참고 |
|---|---|
| `externalId`, `externalKey` | 각각 Jira 이슈 ID와 키입니다. Feishu Project에서는 둘 다 작업 항목 ID입니다. |
| `status`, `done` | 마지막 동기화에서 확인한 상태 이름과 완료 여부입니다. Jira는 `done` 상태 범주를, Feishu Project는 커넥터의 `doneStates`를 기준으로 완료 여부를 판단합니다. |
| `syncedAt`, `lastError` | 마지막 동기화 시각과 마지막 동기화 또는 댓글 작성에서 발생한 오류입니다. 작업에 성공하면 오류를 지웁니다. |
| `actionItemId` | [사후 분석 조치 항목](/ko/api/alerting/postmortems)에 대해 생성한 티켓에 설정합니다. 이러한 티켓에는 인시던트에서 발생한 댓글이나 상태 전환을 반영하지 않습니다. |

## 상태 동기화 및 Jira 웹훅

완료되지 않은 티켓은 5분마다 동기화합니다. 티켓이 완료되고 커넥터에
`resolveIncidentWhenDone`이 설정되어 있으면 인시던트를 해결 처리합니다. 단, 사후 분석의 후속 조치
항목에 대해 생성한 티켓은 제외합니다.

Jira 커넥터에 `webhook_secret`을 설정한 후 Jira의 **시스템 설정 → 웹훅**에서 웹훅을 추가합니다.
URL에는 MoleSignal의 외부 주소 뒤에 `webhook_path`를 붙여 입력하고, 시크릿에는 동일한
`webhook_secret`을 입력합니다. 이벤트는 이슈 업데이트로 설정합니다.

```http
POST /api/v1/public/tickets/jira/{connectorId}
```

MoleSignal은 `webhook_secret`으로 요청 본문의 HMAC-SHA256을 계산하고 그 결과를
`X-Hub-Signature: sha256=<hex>`와 비교합니다. 요청 본문의 최대 크기는 1 MiB입니다.

| 상태 | 이유 |
|---|---|
| `204` | 요청을 수락했습니다. 요청 본문의 이슈가 MoleSignal에서 생성한 티켓이 아닌 경우에도 `204`를 반환합니다. |
| `401` | 서명이 일치하지 않거나, 커넥터에 `webhook_secret`이 없어 웹훅을 수락하지 않습니다. |
| `404` | 커넥터가 없거나, 비활성화되어 있거나, Jira 커넥터가 아닙니다. |
