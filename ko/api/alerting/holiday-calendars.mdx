```http
GET    /api/v1/alerts/holiday-calendars
POST   /api/v1/alerts/holiday-calendars
GET    /api/v1/alerts/holiday-calendars/{id}
PUT    /api/v1/alerts/holiday-calendars/{id}
DELETE /api/v1/alerts/holiday-calendars/{id}
GET    /api/v1/alerts/holiday-calendars/{id}/references
POST   /api/v1/alerts/holiday-calendars/parse
```

조회에는 `alerts.calendars.read` 권한이 필요하며, 생성, 변경, 삭제, 파일 읽기에는 `alerts.calendars.manage` 권한이 필요합니다.
휴일 캘린더가 주간 운영 시간에 어떻게 반영되는지는 [휴일 캘린더](/ko/alerting/on-call#휴일-캘린더)를 참조합니다.

## 캘린더 생성 또는 변경

`POST`는 캘린더를 생성하고, `PUT`은 기존 캘린더를 대체합니다. 응답으로 반환하는 캘린더에는 `id`,
`orgId`, `createdBy`, `createdAt`, `updatedAt`이 포함됩니다.

| 필드 | 유형 | 필수 | 설명 |
|---|---|---|---|
| `name` | 문자열 | 예 | 최대 80자이며 조직 내에서 고유해야 합니다. |
| `description` | 문자열 | 아니요 | 최대 500자입니다. |
| `days` | 배열 | 아니요 | 최대 2,000일을 지정할 수 있으며, 각 항목의 형식은 `{"date": "2026-10-01", "kind": "holiday", "name": "National Day"}`입니다. `kind`는 `holiday`(휴무일) 또는 `workday`(월요일로 처리하는 대체 근무일)입니다. `name`은 최대 80자입니다. 각 날짜는 한 번만 지정할 수 있습니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/holiday-calendars \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "China 2026", "days": [{"date": "2026-10-01", "kind": "holiday", "name": "National Day"}, {"date": "2026-10-10", "kind": "workday", "name": "Make-up workday"}]}'
```
</RequestExample>

캘린더를 사용하려면 주간 운영 시간의 `calendar`에 캘린더 ID를 지정합니다.
`{"calendarId": "<id>", "holidays": "exclude"}`는 휴무일을 제외하고, `"holidays": "only"`는
휴무일에만 운영 시간을 적용합니다. 캘린더를 지정할 수 있는 주간 운영 시간에는
[에스컬레이션 정책](/ko/api/alerting/create-escalation)의 지원 시간,
[라우팅 규칙](/ko/api/alerting/create-routing-rule)과 알림 정책의 시간 조건, 온콜
일정의 로테이션, 경보 파이프라인, 주간 알림 음소거 시간대가 포함됩니다. 이 항목에 조직에 속하지 않는
캘린더를 지정하면 저장이 실패하고 `400`을 반환합니다.

## ICS 파일 읽기

`POST /parse`는 최대 2 MiB의 `{"content": "<the .ics text>"}`를 받아,
아무것도 저장하지 않고 `{"days": [...]}`를 반환합니다. 종일 이벤트는 하루로, 여러 날에 걸친 이벤트는 날짜별로 변환합니다.
이름에 补班 또는 上班이 포함되거나 이름이 班으로 끝나면 해당 날짜를 `workday`로 분류합니다.

## 캘린더 사용 항목 확인

`GET /{id}/references`는 캘린더를 사용하는 항목을 `{"kind", "id", "name"}` 형식으로 나열합니다. `kind`의 값은
`routing_rule`, `escalationPolicy`, `schedule`, `mute_rule`, `notify_policy`, `alert_pipeline` 중 하나입니다.
목록이 비어 있지 않으면 `DELETE`가 실패하고 `409`를 반환합니다.

**오류**

| 상태 | 이유 |
|---|---|
| `400` | 필드 값이 허용 범위를 벗어났거나, 같은 날짜를 두 번 지정했거나, 파일을 읽을 수 없습니다. |
| `403` | 토큰에 필요한 권한이 없습니다. |
| `404` | 조직에 해당 캘린더가 없습니다. |
| `409` | 이름이 같은 다른 캘린더가 있거나 해당 캘린더를 사용 중입니다. |
