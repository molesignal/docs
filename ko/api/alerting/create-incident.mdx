```http
POST /api/v1/alerts/incidents
```

고객 제보처럼 어떤 규칙도 감지하지 못한 문제에 대해 인시던트를 생성합니다. 인시던트에는
`alert.source=manual` 라벨, `createdBy`(호출자) 및 `description` 주석,
`manual` 값의 `ruleId`가 포함됩니다. 이 인시던트는 알림 파이프라인을 거치지 않으며, 다른 인시던트와 중복 제거되지 않고
자동으로 복구되지 않습니다. 이 호출에는 `alerts.incidents.create` 권한이 필요하며, 다음 감사 이벤트를 기록합니다.
`alert.incident.created`.

**요청 본문**

| 필드 | 유형 | 필수 | 설명 |
|---|---|---|---|
| `title` | string | 예 | 최대 200자입니다. |
| `description` | string | 아니요 | Markdown 형식으로 최대 20000자입니다. |
| `severity` | string | 아니요 | `info`, `warning`, `error`(기본값), `critical` 중 하나입니다. |
| `urgency` | string | 아니요 | `high` 또는 `low`와 같은 조직 [긴급도 수준](/ko/alerting/on-call#긴급도-및-우선순위-수준)의 키입니다. 생략하면 인시던트의 에스컬레이션 정책에 따라 결정합니다. 자세한 내용은 [긴급도](/ko/alerting/on-call#긴급도)를 참조합니다. |
| `priority` | string | 아니요 | 조직의 우선순위 중 하나입니다. 기본 범위는 `P1`~`P5`이며, `P9`까지 설정할 수 있습니다. |
| `assign` | object | 아니요 | 담당자 지정 방식입니다. 기본값은 `{"kind": "auto"}`이며 [알림 라우팅](/ko/alerting/routing)에 따라 배정합니다. `{"kind": "team", "teamId": "..."}`은 팀의 온콜 정책을, `{"kind": "policy", "escalationPolicyId": "..."}`는 지정한 에스컬레이션 정책을 적용합니다. `{"kind": "users", "userIds": [...]}`는 에스컬레이션 정책을 적용하지 않고 조직 구성원 1~10명에게 직접 알립니다. |
| `services` | string[] | 아니요 | 영향을 받는 서비스 목록입니다. 최대 20개를 지정할 수 있습니다. |
| `labels` | object | 아니요 | 라벨은 최대 50개입니다. `alert.source`는 항상 `manual`입니다. |
| `declareMajor` | boolean | 아니요 | [중대 인시던트](/ko/alerting/major-incidents)로도 선언합니다. 선언에 실패해도 인시던트를 생성합니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"title": "Customers in the north cannot pay", "severity": "critical", "priority": "P1", "assign": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

응답으로 인시던트를 반환합니다. 필드는 [인시던트 목록 조회](/ko/api/alerting/list-incidents)를 참조합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 제목을 누락했거나 제목이 너무 길거나, 라벨이나 서비스가 최대 개수를 초과하거나, `users`로 지정한 인원이 1~10명 범위를 벗어나거나, 지정한 팀, 정책 또는 구성원이 조직에 속하지 않습니다. |
| `403` | 토큰에 `alerts.incidents.create` 권한이 없습니다. |
