Both 호출 모두 인시던트에 대한 `alerts.incidents.read` 권한이 필요합니다.

## 유사 인시던트

```http
GET /api/v1/alerts/incidents/{id}/similar
```

이 인시던트가 트리거되기 전 90일 동안 같은 조직에서 열린 인시던트 중 이 인시던트와 가장 유사한 인시던트를 찾습니다. 최대 5개이며 점수가 높은 순서로, 점수가 같으면 최신 순서로 정렬합니다. 이 인시던트로 병합된 인시던트와 이 인시던트가 병합된 대상 인시던트는 제외됩니다. 점수는 아래 행들의 합이며, 목록에 포함되려면 점수가 2 이상이어야 합니다:

| 근거 | `reasons` 값 | 점수 |
|---|---|---|
| 동일한 알림 핑거프린트 | `fingerprint` | 5 |
| 동일한 규칙(핑거프린트가 다른 경우) | `rule` | 3 |
| 공유 서비스 | `services` | 겹침 × 2 |
| 유사한 레이블: 공유 키-값 쌍이 양쪽 전체 쌍의 0.3 이상 | `labels` | 공유 비율 × 2 |
| 유사한 제목: PostgreSQL `pg_trgm`이 계산하는 방식과 동일하게 계산한 트라이그램 유사도가 0.3 이상(중국어 포함) | `title` | 유사도 × 2 |
| 동일한 팀으로 라우팅됨 | `team` | 1 |

겹침은 양쪽의 교집합을 합집합으로 나눈 값입니다.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/similar \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "incidents": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
      "summary": "High error rate · checkout",
      "severity": "critical",
      "status": "resolved",
      "createdAt": 1789400000000000,
      "resolvedAt": 1789401800000000,
      "resolvedBy": "<user-id>",
      "score": 7.6,
      "reasons": ["fingerprint", "services", "labels", "team"],
      "notes": 2,
      "rootCause": "Connection pool exhausted after the payments client stopped releasing connections."
    }
  ]
}
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `score`, `reasons` | 점수와 그 근거입니다. 위 표를 참고하세요. |
| `resolvedBy` | 해결한 주체입니다. 규칙이 스스로 복구되었거나 아직 활성 상태이면 `null`입니다. |
| `notes` | 보유한 [노트](/ko/api/alerting/add-incident-note) 수입니다. |
| `rootCause` | [AI 근본 원인](/ko/api/alerting/incident-rca)에서 내용이 있는 첫 문장(제목과 빈 줄은 건너뜀)이며 최대 200자입니다. 분석이 없으면 생략됩니다. |

## 최근 변경 사항

```http
GET /api/v1/alerts/incidents/{id}/changes
```

인시던트가 트리거되기 30분 전부터 10분 후까지 인시던트의 서비스(영향받은 서비스와 `service` 레이블) 및 그 하위 서비스에 대해 [보고된 변경 사항](/ko/apm/deployments#ci에서-배포-보고)을 나열합니다. 최대 20개이며 오래된 순서로 정렬합니다. 하위 서비스는 APM 서비스 맵에서 가져오며, 인시던트의 처음 3개 서비스까지만 대상으로 합니다. 서비스 맵이 없으면 인시던트 자체 서비스만 집계합니다. 트리거 전 24시간 이내에 인시던트의 규칙이 수정된 경우 `rule` 변경도 함께 나열합니다.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/changes \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "from": 1789998200000000,
  "to": 1790000600000000,
  "changes": [
    {
      "kind": "deployment",
      "at": 1789999100000000,
      "service": "payments",
      "downstream": true,
      "version": "v2026.10.28",
      "status": "succeeded",
      "commit": "9f2c1e4",
      "author": "dana",
      "link": "https://ci.example.com/pipelines/4821"
    },
    {
      "kind": "rule",
      "at": 1789960000000000,
      "downstream": false,
      "ruleId": "3KEDBLvTYO6DnWi8H9S9MNLpPT7",
      "ruleName": "Checkout error rate"
    }
  ]
}
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `from`, `to` | 조회한 시간 범위이며 Unix 마이크로초 단위입니다. |
| `kind` | `deployment`, `configuration`, `feature_flag` 또는 `rule`(인시던트의 규칙이 수정됨)입니다. |
| `downstream` | 변경 사항이 인시던트 자체 서비스가 아닌 하위 서비스에 속하면 `true`입니다. |
| `version`, `status`, `commit`, `description`, `author` | 보고서에 포함된 값이며, 없으면 생략됩니다. |
| `link` | 보고된 파이프라인 주소이며, 없으면 풀 리퀘스트 주소입니다. |
| `ruleId`, `ruleName` | `rule` 변경의 규칙입니다. |

**오류**

| 상태 | 사유 |
|---|---|
| `403` | 토큰에 `alerts.incidents.read` 권한이 없거나 이 인시던트에 접근할 수 없습니다. |
| `404` | 인시던트가 존재하지 않습니다. |

## 비즈니스 영향

```http
GET /api/v1/alerts/incidents/{id}/business-impact
```

스팬이 전달하는 각 [비즈니스 키](/ko/business-context)에 대해, 인시던트가 트리거되기 30분 전부터 10분 후까지(현재를 넘지 않음) 인시던트의 서비스로 향한 요청이 가장 많이 실패한 값을 나열합니다. 키당 최대 5개 값이며, 실패한 요청이 많은 순서로, 그다음은 요청이 많은 순서로 정렬합니다. 서비스가 없는 인시던트는 모든 서비스의 요청을 조회합니다. 요청은 서비스가 요청을 받은 스팬입니다.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/business-impact \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "from": 1789998200000000,
  "to": 1790000600000000,
  "services": ["checkout"],
  "declared": true,
  "keys": [
    {
      "key": "tenant",
      "label": "Tenant",
      "field": "tenant.id",
      "more": true,
      "values": [
        { "value": "acme", "requests": 300, "errors": 120, "important": true },
        { "value": "globex", "requests": 90, "errors": 4, "important": false }
      ]
    }
  ]
}
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `services` | 요청을 조회한 인시던트의 서비스입니다. 지정된 서비스가 없으면 비어 있습니다. |
| `declared` | 어떤 비즈니스 키도 스팬 필드를 지정하지 않으면 `false`이며, 이때 `keys`는 비어 있습니다. |
| `field` | 키를 읽어 온 스팬 필드입니다. |
| `important` | 조직이 해당 키에 대해 중요하다고 표시한 값 중 하나입니다. |
| `more` | 나열된 것보다 더 많은 값에 요청이 있었습니다. |

트레이스 스트림에 해당 필드가 없거나 암호화된 상태로 유지되는 키, 또는 어떤 요청에도 값이 없었던 키는 제외됩니다.

**오류**

| 상태 | 사유 |
|---|---|
| `403` | 토큰에 `alerts.incidents.read` 권한이 없거나 이 인시던트에 접근할 수 없거나, `streams.query`와 `sys.telemetry.read` 권한이 모두 없습니다. |
| `404` | 인시던트가 존재하지 않습니다. |
