두 호출 모두 해당 인시던스에 대한 `alerts.incidents.read` 권한이 필요합니다.

## 유사 인시던스

```http
GET /api/v1/alerts/incidents/{id}/similar
```

현재 인시던스가 트리거되기 전 90일 동안 같은 조직에서 개설된 인시던스 중
가장 유사한 인시던스를 최대 5개 찾습니다. 점수가 높은 순으로, 동점이면 최신순으로 정렬합니다. 현재 인시던스에 병합된 인시던스와
현재 인시던스가 병합된 대상 인시던스는 제외합니다. 아래 표의 점수를 합산하며,
총점이 2점 이상인 인시던스만 표시합니다.

| 기준 | `reasons`의 값 | 점수 |
|---|---|---|
| 동일한 알림 지문 | `fingerprint` | 5 |
| 동일한 규칙(지문이 다른 경우) | `rule` | 3 |
| 공통 서비스 | `services` | 중복 비율 × 2 |
| 유사한 레이블: 공통 키-값 쌍이 각 인시던스의 전체 키-값 쌍에서 차지하는 비율이 모두 0.3 이상 | `labels` | 공통 비율 × 2 |
| 유사한 제목: PostgreSQL `pg_trgm`과 같은 방식으로 계산한 트라이그램 유사도가 0.3 이상(중국어 포함) | `title` | 유사도 × 2 |
| 동일한 팀으로 라우팅됨 | `team` | 1 |

중복 비율은 두 집합의 교집합 크기를 합집합 크기로 나눈 값입니다.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/similar \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "incidents": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
      "summary": "High error rate · checkout",
      "severity": "critical",
      "status": "resolved",
      "createdAt": 1789400000000000,
      "resolvedAt": 1789401800000000,
      "resolvedBy": "<user-id>",
      "score": 7.6,
      "reasons": ["fingerprint", "services", "labels", "team"],
      "notes": 2,
      "rootCause": "Connection pool exhausted after the payments client stopped releasing connections."
    }
  ]
}
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `score`, `reasons` | 점수와 산정 근거입니다. 위 표를 참조합니다. |
| `resolvedBy` | 인시던스를 해결한 주체입니다. 규칙이 자동으로 복구되었거나 인시던스가 여전히 활성 상태이면 `null`입니다. |
| `notes` | 인시던스에 추가된 [메모](/ko/api/alerting/add-incident-note) 수입니다. |
| `rootCause` | [AI 근본 원인 분석](/ko/api/alerting/incident-rca)에서 제목과 빈 줄을 건너뛴 뒤 나오는 첫 번째 문장입니다. 최대 200자이며, 분석이 없으면 이 필드를 생략합니다. |

## 최근 변경 사항

```http
GET /api/v1/alerts/incidents/{id}/changes
```

인시던스가 트리거되기 30분 전부터
트리거된 후 10분까지 [보고된 변경 사항](/ko/apm/deployments#ci에서-배포-보고)을 나열합니다. 인시던스의 서비스(영향을 받은
서비스와 `service` 레이블이 가리키는 서비스) 및 그 다운스트림 서비스의 변경 사항을 오래된 순으로 최대 20개 표시합니다.
인시던스의 처음 3개 서비스까지만 APM 서비스 맵에서 다운스트림 서비스를 찾습니다. 서비스 맵이 없으면
인시던스 자체 서비스만 포함합니다. 트리거 전 24시간 이내에 인시던스의 규칙을 편집한 경우
`rule` 변경 사항도 표시합니다.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/changes \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "from": 1789998200000000,
  "to": 1790000600000000,
  "changes": [
    {
      "kind": "deployment",
      "at": 1789999100000000,
      "service": "payments",
      "downstream": true,
      "version": "v2026.10.28",
      "status": "succeeded",
      "commit": "9f2c1e4",
      "author": "dana",
      "link": "https://ci.example.com/pipelines/4821"
    },
    {
      "kind": "rule",
      "at": 1789960000000000,
      "downstream": false,
      "ruleId": "3KEDBLvTYO6DnWi8H9S9MNLpPT7",
      "ruleName": "Checkout error rate"
    }
  ]
}
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `from`, `to` | 조회한 시간 범위입니다. Unix 시간을 마이크로초 단위로 표시합니다. |
| `kind` | `deployment`, `configuration`, `feature_flag`, `rule`(인시던스 규칙 편집) 중 하나입니다. |
| `downstream` | 인시던스 자체 서비스가 아닌 다운스트림 서비스의 변경 사항이면 `true`입니다. |
| `version`, `status`, `commit`, `description`, `author` | 보고서에 포함된 값입니다. 보고서에 없는 필드는 생략합니다. |
| `link` | 보고된 파이프라인 주소입니다. 파이프라인 주소가 없으면 풀 리퀘스트 주소를 사용합니다. |
| `ruleId`, `ruleName` | `rule` 변경에서 편집한 규칙의 ID와 이름입니다. |

**오류**

| 상태 | 이유 |
|---|---|
| `403` | 토큰에 `alerts.incidents.read` 권한이 없거나 이 인시던스에 액세스할 수 없습니다. |
| `404` | 인시던스가 존재하지 않습니다. |
