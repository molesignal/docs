커넥터는 조직에서 사용하는 알림 제공업체 한 곳의 인증 정보와 전송 설정을 저장합니다. 커넥터 목록을 조회하거나 개별 커넥터를 조회하려면 `notify.connectors.read` 권한이 필요합니다. 커넥터를 생성, 업데이트, 테스트 또는 삭제하려면 `notify.connectors.manage` 권한이 필요합니다.

| 작업 | 엔드포인트 |
|---|---|
| 커넥터 유형 목록 조회 | `GET /api/v1/notify/connector-types` |
| 커넥터 목록 조회 | `GET /api/v1/notify/connectors` |
| 커넥터 생성 | `POST /api/v1/notify/connectors` |
| 커넥터 조회 | `GET /api/v1/notify/connectors/{id}` |
| 커넥터 업데이트 | `PUT /api/v1/notify/connectors/{id}` |
| 커넥터 테스트 | `POST /api/v1/notify/connectors/{id}/test` |
| 커넥터 삭제 | `DELETE /api/v1/notify/connectors/{id}` |

## 커넥터 유형

유형 목록은 실행 중인 백엔드에 등록된 모든 유형의 `connectorType`, `capabilities`, `addresses`를 반환합니다. 유형은 `email_smtp`, `lark_app`, `lark_webhook`, `slackApp`, `slack_webhook`, `webhook`입니다.

```json
[
  {
    "connectorType": "slack_app",
    "capabilities": {
      "directUser": true,
      "group": true,
      "richText": true,
      "interactive": true,
      "acknowledgement": false,
      "attachments": false
    },
    "addresses": [
      {
        "field": "apiBaseUrl",
        "picker": "site",
        "choices": [
          { "key": "slack", "url": "https://slack.com/api" },
          { "key": "govslack", "url": "https://slack-gov.com/api" }
        ]
      }
    ]
  }
]
```

`addresses`는 각 유형의 `config`에 저장할 수 있는 제공업체 주소 목록입니다. 웹훅이나 SMTP처럼 주소를 직접 입력하는 유형은 사전 정의된 주소가 없으므로 빈 목록을 반환합니다.

| 필드 | 의미 |
|---|---|
| `field` | `apiBaseUrl`, `serviceUrl`, `wsUrl` 등의 `config` 키입니다. |
| `choices` | 선택할 수 있는 주소 목록입니다. 각 주소에는 `key`와 `url`이 있으며 첫 번째 주소가 기본값입니다. |
| `picker` | 여러 주소 중 하나를 선택하는 기준으로, `site`(플랫폼) 또는 `cloud`입니다. 선택 자체는 저장하지 않습니다. |
| `byRegion` | 주소는 선택한 리전(Alibaba Cloud, AWS)에 따라 `https://{service}.{region}.{one of domains}` 형식을 따릅니다. `choices`에는 리전을 선택하기 전에 사용하는 주소만 들어 있습니다. |

커넥터를 생성, 업데이트, 테스트하거나 알림을 직접 전송할 때는 이 키에 목록에 있는 주소만 지정할 수 있습니다. 리전별 주소의 경우에는 `config`에 지정한 리전에 해당하는 주소만 허용합니다. 키를 생략하면 기본값을 사용합니다. 인증 정보가 다른 곳으로 전송되지 않도록 그 외 주소는 거부합니다.

커넥터의 `config` 객체는 유형에 따라 달라집니다. 모든 유형에서 `timeoutSecs`의 기본값은 10이며 1부터 60까지 지정할 수 있습니다. URL은 절대 `http` 또는 `https` URL이어야 하며, 제공업체 주소는 해당 유형의 `addresses` 목록에 있어야 합니다.

| `connectorType` | `config` 키 |
|---|---|
| `email_smtp` | `host` 및 `from`(필수), `port`(기본값 `587`), `username`, `password`, `tls`(`none`, `starttls`(기본값) 또는 `tls`), `timeoutSecs` |
| `slackApp` | `botToken`, `clientId` 및 `clientSecret`(봇 토큰만, 클라이언트 ID와 시크릿만 또는 세 값 모두), `apiBaseUrl`(기본값 `https://slack.com/api`, GovSlack의 경우 `https://slack-gov.com/api`), `timeoutSecs` |
| `slack_webhook` | `webhookUrl`(필수), `timeoutSecs` |
| `lark_app` | `appId` 및 `appSecret`(필수), `apiBaseUrl`(기본값은 Feishu의 `https://open.feishu.cn/open-apis`, Lark의 경우 `https://open.larksuite.com/open-apis`), `receiveIdType`(`open_id`(기본값), `userId`, `union_id`, `email` 또는 `chatId`), `timeoutSecs` |
| `lark_webhook` | `webhookUrl`(필수), `secret`, `timeoutSecs` |
| `webhook` | `url`(필수), `method`(`post`(기본값), `put` 또는 `patch`), `headers`, `timeoutSecs` |

[알림 채널](/ko/notification-channels)에서 각 제공업체와 해당 전송 대상을 설명합니다.

## 커넥터 생성

```http
POST /api/v1/notify/connectors
```

| 필드 | 유형 | 필수 여부 | 참고 |
|---|---|---|---|
| `name` | string | 예 | 조직 내에서 고유해야 합니다. |
| `connectorType` | string | 예 | 위 유형 중 하나를 지정합니다. 나중에 유형을 변경할 수 없습니다. |
| `config` | object | 예 | 해당 유형의 설정입니다. |
| `enabled` | boolean | 아니요 | 기본값은 `true`입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/notify/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "Operations webhook",
    "connectorType": "webhook",
    "config": {
      "url": "https://hooks.example.com/molesignal",
      "method": "post",
      "headers": { "Authorization": "Bearer <token>" },
      "timeoutSecs": 5
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "id": "3KEDlokKjNmves95sRzL8tXpflY",
  "organizationId": "<organization-id>",
  "name": "Operations webhook",
  "connectorType": "webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 5
  },
  "capabilities": {
    "directUser": true,
    "group": true,
    "richText": true,
    "interactive": false,
    "acknowledgement": false,
    "attachments": false
  },
  "enabled": true,
  "status": "unknown",
  "lastTestedAt": null,
  "lastTestStatus": null,
  "lastTestError": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

MoleSignal은 전체 `config`를 암호화하여 저장합니다. 응답에서는 인증 정보를 담은 모든 키의 값을 `***`로 대체합니다. 해당 키는 `url`, `webhookUrl`, `headers`와 이름이 `password`, `secret` 또는 `token`으로 끝나는 모든 키입니다. `host`, `from`, `timeoutSecs` 등의 다른 키는 값을 그대로 반환합니다.

`status`는 첫 테스트 전까지 `unknown`이며, 이후에는 `connected` 또는 `error`입니다. `lastTestStatus`는 `success` 또는 `failed`입니다. 라우팅은 후속 테스트에 성공할 때까지 `error` 상태인 커넥터를 건너뜁니다.

## 커넥터 목록 및 개별 조회

```http
GET /api/v1/notify/connectors
GET /api/v1/notify/connectors/{id}
```

목록 조회는 위 형식의 커넥터 배열을 반환합니다. 존재하지 않는 `id`로 조회하면 `404`를 반환합니다.

## 커넥터 업데이트

```http
PUT /api/v1/notify/connectors/{id}
```

| 필드 | 유형 | 필수 여부 | 참고 |
|---|---|---|---|
| `name` | string | 예 | 새 이름입니다. |
| `config` | object | 아니요 | 새 설정입니다. 저장된 설정을 유지하려면 생략합니다. |
| `enabled` | boolean | 아니요 | 기본값은 `true`입니다. 값을 생략하면 커넥터를 활성화합니다. |

저장된 시크릿을 유지하려면 마스킹된 키에 `***`를 전송합니다. 시크릿을 교체하려면 새 값을 평문으로 전송합니다.

```json
{
  "name": "Operations webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 8
  },
  "enabled": true
}
```

## 커넥터 테스트

```http
POST /api/v1/notify/connectors/{id}/test
```

커넥터를 통해 메시지 한 건을 전송합니다. 비활성화된 커넥터는 테스트할 수 없습니다.

| 필드 | 유형 | 필수 여부 | 참고 |
|---|---|---|---|
| `targetType` | string | 예 | `directUser`, `fixed_address`, `fixed_group` 또는 `webhook`입니다. 커넥터 유형마다 지원하는 값이 다릅니다. 예를 들어 `email_smtp`는 `directUser`와 `fixed_address`를 지원합니다. |
| `target` | string | 예 | 수신 대상입니다. `targetType`에 따라 주소, 제공업체 식별자, 그룹 또는 URL을 지정합니다. |
| `message` | object | 아니요 | `title`, `text`, `markdown`, `html`을 지정할 수 있습니다. 기본값으로 일반적인 제목과 본문을 사용합니다. |

<ResponseExample>
```json 200
{
  "sent": true,
  "testedAt": 1790000000000000,
  "elapsedMs": 3,
  "providerMessageId": "req-1",
  "error": null
}
```
</ResponseExample>

메시지 전송에 실패해도 `200`을 반환합니다. 이때 `sent`는 `false`이며, `error`에는 `unavailable: webhook request failed`와 같은 실패 사유가 들어 있습니다. 테스트는 커넥터의 `status`, `lastTestedAt`, `lastTestStatus`, `lastTestError`도 업데이트합니다.

## 커넥터 삭제

```http
DELETE /api/v1/notify/connectors/{id}
```

삭제에 성공하면 본문 없이 `204`를 반환합니다. 사용자 엔드포인트, 알림 정책, 대체 경로, 예약된 로그 검사, 상태 페이지 또는 IM의 Mole Agent가 커넥터를 계속 참조하면 `notify connector is referenced by user endpoints, policies, default routes, scheduled log inspections, status pages, or Mole Agent in IM` 메시지와 함께 `409`를 반환합니다. 먼저 참조 대상을 변경합니다.

## 오류

| 상태 | 원인 |
|---|---|
| `400` | `config`가 해당 유형에 맞지 않거나, 지원하지 않는 유형이거나(`unsupported connector type: pagerduty`), 전송 대상이 커넥터와 호환되지 않거나, 커넥터가 비활성화되어 있습니다. |
| `404` | 커넥터가 존재하지 않습니다. |
| `409` | 조직 내 다른 커넥터가 이미 같은 이름을 사용하거나, 삭제하려는 커넥터를 다른 곳에서 계속 참조합니다. |
| `422` | 필드가 누락되었거나 지원하지 않는 `targetType` 등 유효하지 않은 값을 지정했습니다. 응답은 일반 텍스트입니다. |
