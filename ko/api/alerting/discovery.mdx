```http
GET /api/v1/alerts/discovery/findings
GET /api/v1/alerts/discovery/findings/{id}
```

[탐지](/ko/alerting/discovery) 결과를 마지막으로 관측된 시각이 최신인 순서로 나열하거나,
개별 탐지 결과를 조회합니다. `alerts.discovery.read` 권한이 필요합니다.

**쿼리 매개변수**

| 매개변수 | 설명 |
|---|---|
| `status` | `open`(기본값), `ended` 또는 `all`입니다. |
| `kind` | `apm_anomaly`, `apm_regression`, `rum_new_issue` 또는 `rum_regressed_issue`입니다. |
| `limit` | 기본값은 100이며 최댓값은 500입니다. |

**탐지 결과 필드**

| 필드 | 설명 |
|---|---|
| `kind` | 위의 `kind` 매개변수와 같은 값을 사용합니다. |
| `key` | 동일한 문제를 식별하는 키입니다. 유형, 대상, 메트릭으로 구성됩니다. |
| `severity` | `warning`, `error` 또는 `critical`입니다. |
| `subject` | APM 서비스(`namespace/name`) 또는 RUM 애플리케이션 ID입니다. |
| `environment`, `metric` | 환경과 APM에서 변화가 감지된 메트릭입니다. 메트릭은 `errorRate`, `p95`(마이크로초) 또는 `throughput`(초당 요청 수)입니다. |
| `title` | 한 문장으로 된 제목입니다. |
| `value`, `baseline` | 현재 값과 비교 기준값입니다. |
| `startedAt`, `lastSeenAt`, `endedAt` | 시작 시각, 마지막 관측 시각, 종료 시각입니다(마이크로초). `endedAt`이 없으면 열린 상태입니다. |
| `missedRounds` | 연속으로 관측되지 않은 탐지 주기 수입니다. 3회에 도달하면 탐지 결과가 종료됩니다. |
| `detail` | APM 탐지 결과에는 `previous`, `lastWeek`, `version`, `previousVersion`, 발생 시점 전후의 `changes`가 포함됩니다. RUM 탐지 결과에는 `issueId`, `application`, `errorType`, `location`, `version`이 포함됩니다. |

탐지 결과를 인시던트로 전환하려면 `query.discovery`를 지정하여 [규칙을 생성합니다](/ko/api/alerting/create-rule).
`{"kinds": [...], "subjects": [...], "environments": [...], "minSeverity": "warning"}`에서 각 항목을 생략하면
해당 항목으로 필터링하지 않습니다. 저장한 규칙은 조건에 맞는 탐지 결과마다 인시던트를 하나씩 생성합니다.
인시던트의 심각도는 탐지 결과와 같으며, `trigger.urgency`에서 달리 지정하지 않으면 긴급도는 낮음입니다.
