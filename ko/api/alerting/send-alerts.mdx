```http
POST /api/v1/intake/alerts
```

외부 시스템은 [알림 소스](/ko/alerting/sources)의 토큰으로 호출합니다. `Authorization: Bearer <token>` 헤더를 사용하거나, 헤더를 설정할 수 없으면 주소에 `?token=<token>`을 추가합니다. 모든 소스는 이 주소를 공유합니다. 토큰은 알림이 속한 소스를 식별하고, 소스 유형은 본문을 읽을 형식을 결정합니다. [발신자 설정](/ko/alerting/sources#발신-시스템-설정)에서는 발신자별 형식을 설명합니다(이메일 소스는 `Content-Type: message/rfc822`로 원본 메일을 읽습니다). 이 페이지에서는 **API** 유형의 본문을 설명합니다. 본문 크기는 최대 4 MiB입니다.

본문에는 알림 객체 하나 또는 최대 100개의 알림 객체가 담긴 배열을 전달합니다. 알 수 없는 필드가 있으면 요청을 거부합니다.

| 필드 | 유형 | 설명 |
|---|---|---|
| `action` | 문자열 | `trigger`(기본값), `acknowledge` 또는 `resolve`입니다. |
| `dedupKey` | 문자열 | 소스 내에서 사용하는 중복 제거 키입니다. 최대 255자이며, 키 하나당 동시에 활성 인시던트는 최대 하나입니다. `acknowledge`와 `resolve`에 필요합니다. 이 키 없이 `trigger`를 요청하면 `summary`와 `labels`로 키를 계산해 응답에 반환합니다. |
| `summary` | 문자열 | 인시던트 제목입니다. `trigger`에 필요하며 최대 1024자입니다. |
| `severity` | 문자열 | `critical`, `error`, `warning` 또는 `info`입니다. 생략하면 소스의 기본 심각도를 적용합니다. |
| `priority` | 문자열 | 인시던트의 우선순위입니다. `P1`부터 `P9`까지 지정할 수 있으며, `1`부터 `9`까지도 사용할 수 있습니다. 조직에서 설정한 범위를 벗어나면 가장 낮은 우선순위를 적용합니다. 생략하면 우선순위를 지정하지 않습니다. |
| `urgency` | 문자열 | 인시던트의 긴급도입니다. `high` 또는 `low`와 같이 조직에서 설정한 긴급도 수준의 키를 사용합니다. 알 수 없는 키는 무시합니다. 생략하면 소스의 에스컬레이션 정책에 따라 결정하며, `severity`가 없는 알림에는 `high`를 적용합니다. |
| `labels` | 객체 | 레이블은 최대 64개입니다. 키는 `alert.` 또는 `__molesignal`로 시작할 수 없으며 `external.kind`도 사용할 수 없습니다. |
| `annotations` | 객체 | 주석입니다. 링크를 포함해 최대 64개입니다. |
| `links` | 배열 | `{"name": "…", "url": "https://…"}` 항목을 최대 10개까지 지정할 수 있습니다. 각 링크는 `name`을 키로 사용해 주석에 기록합니다. `name`이 없으면 `link`를 사용합니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/intake/alerts \
  -H "authorization: Bearer $SOURCE_TOKEN" \
  -H "content-type: application/json" \
  -d '{"dedupKey": "disk-full/web-1", "summary": "Disk almost full on web-1", "severity": "critical", "labels": {"host.name": "web-1"}, "links": [{"name": "Runbook", "url": "https://wiki.example.com/disk"}]}'
```
</RequestExample>

응답은 각 알림의 처리 결과를 입력 순서대로 반환합니다. PagerDuty 테스트 이벤트처럼 본문을 읽었지만 처리할 알림이 없는 경우, `message`에서 처리하지 않은 이유를 설명합니다.

<ResponseExample>
```json 200
{
  "alerts": [
    {
      "dedupKey": "disk-full/web-1",
      "outcome": "opened",
      "incidentId": "3KEDNEyqouYJeBDTLTMTBui7XHW",
      "reason": null
    }
  ],
  "message": null
}
```
</ResponseExample>

| `outcome` | 의미 |
|---|---|
| `opened` | 새 인시던트를 열었습니다. |
| `updated` | 활성 인시던트의 심각도 또는 해당 알림 그룹에 속한 알림이 변경되었습니다. |
| `unchanged` | 활성 인시던트가 이미 같은 상태이거나 누군가 인시던트를 확인했습니다. |
| `acknowledged` | 인시던트를 확인 처리했습니다. |
| `resolved` | 인시던트를 해결 처리했습니다. 이미 확인한 인시던트도 포함합니다. |
| `ignored` | 변경 사항이 없습니다. 활성 인시던트가 없거나 메시지가 마지막 메시지보다 오래된 경우 등, 무시한 이유는 `reason`에 표시합니다. |

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 본문을 읽을 수 없습니다. `message`에서 이유를 설명합니다. |
| `401` | 토큰이 없거나 올바르지 않거나, 소스가 존재하지 않습니다. |
| `403` | 조직이 비활성화 상태입니다. |
| `409` | 소스가 비활성화 상태입니다. |
| `413` | 본문 크기가 4 MiB를 초과합니다. |
| `503` | 소스의 수신 클러스터에 연결할 수 없거나 요청을 모두 처리하지 못했습니다. 다시 시도합니다. 재시도해도 인시던트를 중복으로 열지 않습니다. |
