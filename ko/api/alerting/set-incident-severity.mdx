```http
PUT /api/v1/alerts/incidents/{id}/severity
```

활성 인시던트의 심각도를 설정하고 `severitySetBy`에 호출자를 기록합니다. 이후에는
규칙을 평가해도 심각도가 바뀌지 않습니다. `open` 상태인 인시던트의 심각도를 높이면
새 심각도에 적용되는 첫 단계부터 에스컬레이션을 다시 시작하고 `escalation.reason`을
`severity_raised`로 설정합니다. 심각도를 낮추거나 확인 처리된 인시던트의 심각도를 변경하면 심각도만 바뀝니다. 이 호출에는
`alerts.incidents.update` 권한이 필요합니다.

**본문**

| 필드 | 유형 | 필수 | 참고 |
|---|---|---|---|
| `severity` | 문자열 | 예 | `info`, `warning`, `error`, `critical` 중 하나입니다. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/severity \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"severity": "critical"}'
```
</RequestExample>

응답으로 업데이트된 인시던트를 반환합니다. 모든 필드에 대한 설명은 [인시던트 목록 조회](/ko/api/alerting/list-incidents)를 참조합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `422` | `severity`가 누락되었거나 허용되는 네 가지 값 중 하나가 아닙니다. |
| `403` | 토큰에 `alerts.incidents.update` 권한이 없거나 토큰으로 해당 인시던트에 접근할 수 없습니다. |
| `404` | 인시던트가 존재하지 않습니다. |
| `409` | 인시던트가 복구되었거나 다른 인시던트에 병합되었거나 업데이트 중에 계속 변경되었습니다. 다시 시도합니다. |
