```http
POST /api/v1/alerts/incidents/{id}/reassign
```

진행 중인 인시던트를 다른 담당자에게 재할당합니다. 본문에서 `kind`로 새 담당자의 유형을 지정합니다.

- `users`: `userIds`에 지정한 조직 구성원 1~10명을 담당자로 지정합니다. 새 담당자는
  `escalation.reason`이 `reassigned`인 에스컬레이션 알림을 받습니다. 인시던트는
  `open` 상태로 돌아가고, 현재 단계의 확인 대기 시간이 처음부터 다시 시작됩니다. 아무도 확인하지 않으면 에스컬레이션이
  다음 단계로 넘어갑니다.
- `team`: `teamId`에 지정한 팀이 인시던트를 담당합니다. 해당 팀의 온콜 정책을 적용하고, 팀에 정책이
  없으면 `default` 정책을 적용합니다. 적용한 정책에서 해당하는 첫 번째 단계부터 다시 시작합니다.
- `policy`: `escalationPolicyId`에 지정한 정책을 인시던트에 적용하고, 해당하는 첫 번째
  단계부터 다시 시작합니다. 담당 팀은 변경하지 않습니다.

모든 경우에 인시던트는 `open` 상태로 돌아가고, 일시 중지는 종료됩니다. 해당 단계는
[타임라인](/ko/api/alerting/incident-timeline)에 기록됩니다. 호출하려면 `alerts.incidents.update` 권한이 필요합니다.

**본문**

| 필드 | 유형 | 필수 여부 | 설명 |
|---|---|---|---|
| `kind` | string | 예 | `users`, `team`, `policy` 중 하나입니다. |
| `userIds` | array | `users`일 때 필수 | 조직 구성원 1~10명의 사용자 ID입니다. |
| `teamId` | string | `team`일 때 필수 | 담당 팀의 ID입니다. |
| `escalationPolicyId` | string | `policy`일 때 필수 | 적용할 정책의 ID입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/reassign \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"kind": "users", "userIds": ["<user-id>"]}'
```
</RequestExample>

응답은 업데이트된 인시던트입니다. [인시던트 목록 조회](/ko/api/alerting/list-incidents)에서 각 필드를 설명합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | `userIds`가 비어 있거나, 사용자가 10명을 초과하거나, 조직 외부 사용자가 포함되어 있습니다. 또는 팀에 정책이 없고 `default` 정책도 없거나, 인시던트 심각도에 적용되는 정책 단계가 없습니다. |
| `403` | 토큰에 `alerts.incidents.update` 권한이 없거나, 토큰으로 해당 인시던트에 액세스할 수 없습니다. |
| `404` | 인시던트가 존재하지 않습니다. |
| `409` | 인시던트가 복구되었거나 다른 인시던트에 병합되었거나, 업데이트 중에 계속 변경되었습니다. 다시 시도합니다. |
