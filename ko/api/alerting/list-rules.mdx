```http
GET /api/v1/alerts/rules
GET /api/v1/alerts/rules/{id}
```

첫 번째 호출은 조직의 모든 알림 규칙을 배열로 반환합니다. 두 번째 호출은 규칙 하나를 반환합니다. 두 호출 모두 `alerts.rules.read` 권한이 필요합니다.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/rules \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "id": "3KEDBLvTYO6DnWi8H9S9MNLpPT7",
    "orgId": "<organization-id>",
    "name": "High error rate",
    "description": "More than 100 errors in five minutes",
    "enabled": true,
    "kind": "scheduled",
    "query": {
      "language": "sql",
```

규칙에는 [규칙 생성](/ko/api/alerting/create-rule)의 필드와 다음 읽기 전용 필드가 포함됩니다.

| 필드 | 설명 |
|---|---|
| `id`, `orgId` | 규칙과 조직의 식별자입니다. |
| `createdAt`, `updatedAt` | Unix 에포크부터 경과한 시간(마이크로초)입니다. |
| `lastEvalAt` | 가장 최근에 완료된 평가 시각(마이크로초)입니다. 첫 평가가 완료되기 전에는 `null`입니다. 쿼리가 실패하거나 시간 초과되면 이 값은 바뀌지 않습니다. |
| `lastState` | 해당 평가의 결과입니다. 조건을 충족하지 않으면 `{"kind": "healthy"}`, 조건을 연속으로 충족한 평가 횟수가 `forPeriods`보다 적으면 `{"kind": "pending", "consecutive": 1}`, `forPeriods`에 도달하면 `{"kind": "firing"}`, 알림이 발동했지만 [알림 파이프라인](/ko/pipelines/alert-events#이벤트-처리-결과)이 생성될 인시던트를 폐기하면 `{"kind": "dropped"}`입니다. `firing` 상태인 규칙은 `silenceSecs`로 지정한 대기 시간 동안 새 인시던트를 생성하지 않습니다. |

존재하지 않는 `id`를 요청하면 `404`를 반환합니다.
