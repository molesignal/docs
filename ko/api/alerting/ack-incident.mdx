```http
POST /api/v1/alerts/incidents/{id}/ack
```

`open` 상태인 인시던트 하나를 확인 처리합니다. 호출은 상태를 `acknowledged`로 변경하고, 호출한 사용자와 확인 시각을 각각 `acknowledgedBy`와 `acknowledgedAt`에 기록하며, 사용자를 `assignees`에 추가합니다. [에스컬레이션 정책](/ko/api/alerting/create-escalation)은 `open` 상태인 인시던트만 다음 단계로 넘기므로 에스컬레이션을 중단합니다. 또한 발송된 알림을 확인됨으로 표시하고 `alert.acknowledged` 이벤트를 전송합니다. `alerts.incidents.acknowledge` 권한이 필요하며 요청 본문은 비워 둡니다.

에스컬레이션 정책에 [`ackRetriggerSecs`](/ko/api/alerting/create-escalation)를 설정하지 않으면, 확인한 인시던트는 사용자가 해결할 때까지 `acknowledged` 상태를 유지합니다. 이 값을 설정하면 확인 후 지정된 시간이 지나도 해결되지 않은 인시던트는 `open` 상태로 돌아가고 시스템은 알림을 다시 보냅니다. 규칙 조건이 더 이상 충족되지 않아도 평가기는 인시던트를 해결 처리하지 않습니다.

<Note>
  이미 `acknowledged` 상태인 인시던트를 확인 처리하면 변경 없이 반환합니다. 최초 확인 사용자와
  시각은 `acknowledgedBy`와 `acknowledgedAt`에 그대로 유지되며, 이벤트는 다시 전송하지 않습니다.
  `resolved` 또는 `closed` 상태인 인시던트를 확인 처리하면 `409`를 반환하며 인시던트의 상태는 바뀌지 않습니다.
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/ack \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

응답은 업데이트된 인시던트입니다. 각 필드에 대한 설명은 [인시던트 목록 조회](/ko/api/alerting/list-incidents)를 참조합니다.
