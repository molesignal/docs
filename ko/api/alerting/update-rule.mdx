```http
PUT /api/v1/alerts/rules/{id}
```

규칙의 구성을 교체합니다. 요청 본문은 [규칙 생성](/ko/api/alerting/create-rule)의 전체 요청 본문과 동일합니다. 이 호출은 규칙의 `id`, 조직, `createdAt`, `lastEvalAt`, `lastState`를 유지합니다. `escalationPolicyId`를 변경할 때는 해당 조직의 정책을 지정하거나 `default`를 사용해야 합니다. 이 호출에는 `alerts.rules.manage` 권한이 필요합니다.

<Warning>
  이 호출은 규칙을 통째로 교체하며 필드를 병합하지 않습니다. 생략한 필드에는 기본값이 적용됩니다.
  예를 들어 `enabled`는 `true`로, `kind`는 `scheduled`로 설정됩니다. 생략한
  `labels`, `annotations`, `thresholds`는 비워집니다. `escalationPolicyId`만 생략해도
  현재 정책을 유지합니다. 먼저 규칙을 조회한 다음 변경 사항을 반영한 전체 본문을 다시 전송합니다.
</Warning>

규칙의 `id`와 `labels`를 바탕으로 인시던트의 지문을 생성합니다. `labels`를 변경하면 이미 열린 인시던트는 기존 지문을 유지하며 더 이상 자동으로 해결되지 않습니다. [인시던트 해결](/ko/api/alerting/resolve-incident)을 사용해 해당 인시던트를 해결합니다.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  --data-binary @- <<'EOF'
{
  "name": "High error rate",
  "description": "More than 200 errors in five minutes",
  "enabled": true,
  "kind": "scheduled",
  "query": {
    "language": "sql",
    "statement": "SELECT count(*) AS c FROM app WHERE level = 'error'",
    "periodSecs": 300,
    "stream": { "name": "app", "streamType": "logs" }
  },
  "trigger": { "operator": "gt", "threshold": 200, "forPeriods": 2, "silenceSecs": 0 },
  "severity": "critical",
  "labels": { "team": "checkout" }
}
EOF
```
</RequestExample>

응답은 업데이트된 규칙이며, 구조는 [규칙 목록 조회](/ko/api/alerting/list-rules)에 표시된 것과 같습니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 요청 본문이 [규칙 생성](/ko/api/alerting/create-rule)과 동일한 유효성 검사를 통과하지 못했거나, 변경한 `escalationPolicyId`가 해당 조직의 정책을 가리키지 않습니다. |
| `404` | 규칙이 존재하지 않습니다. |
| `422` | 필수 필드가 누락되었거나 값의 자료형이 올바르지 않습니다. 응답은 일반 텍스트입니다. |
