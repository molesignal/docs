```http
POST /api/v1/alerts/incidents/{id}/escalate
```

활성 인시던트를 에스컬레이션 정책의 한 단계로 이동하고 해당 단계의 알림 대상에게 즉시 알립니다.
`escalation.reason`은 `manual`로 설정합니다. `step`을 생략하면 인시던트의
심각도에 적용되는 다음 단계로 이동합니다. `acknowledged` 상태의 인시던트는 `open` 상태로 돌아가고, 알림 일시 중지가 해제되며, 해당 단계의
확인 대기 시간이 시작됩니다. 제한 시간 내에 확인하지 않으면 해당 단계부터 에스컬레이션을 계속합니다. 이 호출에는
`alerts.incidents.escalate` 권한이 필요하며, 본문은 비워 둘 수 있습니다.

**본문**

| 필드 | 유형 | 필수 | 참고 |
|---|---|---|---|
| `step` | 정수 | 아니요 | 0부터 시작하는 단계 번호입니다. 인시던트의 심각도에 적용되는 단계여야 합니다. 기본값: 심각도에 적용되는 다음 단계입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/escalate \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"step": 1}'
```
</RequestExample>

응답은 업데이트된 인시던트입니다. 각 필드의 설명은 [인시던트 목록 조회](/ko/api/alerting/list-incidents)를 참조합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 인시던트에 에스컬레이션 정책이 없거나, `step`이 정책의 단계 범위를 벗어나거나 인시던트의 심각도에 적용되지 않거나, 인시던트가 마지막 단계에 있는데 `step`을 지정하지 않았습니다. |
| `403` | 토큰에 `alerts.incidents.escalate` 권한이 없거나 인시던트가 토큰의 접근 범위를 벗어납니다. |
| `404` | 인시던트가 존재하지 않습니다. |
| `409` | 인시던트가 복구되었거나 다른 인시던트에 병합되었거나 업데이트 중에 계속 변경되었습니다. 다시 시도합니다. |
