근무 교환을 요청하면 같은 스케줄의 다른 구성원에게 요청자의 근무를 일정 기간 대신 맡아 달라고 요청합니다. 요청을 받은 구성원이 수락하면
스케줄에 [재정의](/ko/alerting/on-call#임시-당번)를 추가하고 교환을 적용합니다. 스케줄에서
**근무 교환에 승인 필요**(`swapNeedsApproval`)를 켜면 스케줄을 관리할 수 있는 구성원의
승인도 필요합니다. 교환 대상 기간이 끝날 때까지 결정되지 않은 요청은 만료됩니다. 각 단계에서 기본 제공 정책인
[근무 교환: 관련 구성원에게 알림](/ko/notification-channels#기본-제공-정책)을 통해
관련 구성원에게 알림을 보내고,
감사 로그에 기록합니다.

| 메서드 및 경로 | 기능 | 권한 |
|---|---|---|
| `GET /api/v1/schedules/swaps` | 모든 스케줄에서 현재 사용자가 보내거나 받은 근무 교환 요청을 조회합니다. | `schedules.read` |
| `GET /api/v1/schedules/{id}/swaps` | 해당 스케줄의 근무 교환 요청을 최신순으로 조회합니다. | 해당 스케줄의 `schedules.read` |
| `POST /api/v1/schedules/{id}/swaps` | 근무 교환을 요청합니다. | 해당 스케줄의 `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/accept` | 근무 교환 요청을 수락합니다. 요청을 받은 구성원만 수락할 수 있습니다. | 해당 스케줄의 `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/decline` | 근무 교환 요청을 거절합니다. 요청을 받은 구성원만 거절할 수 있습니다. | 해당 스케줄의 `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/cancel` | 근무 교환 요청을 철회합니다. 요청자만 최종 결정 전에 언제든지 철회할 수 있습니다. | 해당 스케줄의 `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/approve` | 수락한 근무 교환을 승인합니다. 재정의를 즉시 적용합니다. | 해당 스케줄의 `schedules.swaps.approve` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/reject` | 수락한 근무 교환을 반려합니다. | 해당 스케줄의 `schedules.swaps.approve` |

## 근무 교환 요청

**요청 본문**

| 필드 | 유형 | 필수 | 비고 |
|---|---|---|---|
| `targetId` | 문자열 | 예 | 근무를 대신 맡을 구성원입니다. 요청자가 아닌 해당 스케줄의 구성원을 지정합니다. |
| `startAt`, `endAt` | 정수 | 예 | 교환할 기간의 시작 및 종료 시각을 Unix 마이크로초로 지정합니다. 시작 시각은 현재보다 늦어야 하며, 종료 시각은 시작 시각보다 늦어야 합니다. |
| `note` | 문자열 | 아니요 | 최대 500자의 메모입니다. |

교환 대상 기간 내내 해당 스케줄에서 요청자만 온콜 근무를 맡아야 합니다. 같은 스케줄에서
아직 결정되지 않은 교환 요청과 겹치는 기간은 요청할 수 없습니다.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/$SCHEDULE_ID/swaps \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"targetId": "<user-id>", "startAt": 1790060400000000, "endAt": 1790146800000000, "note": "Travelling on Friday"}'
```
</RequestExample>

각 호출은 근무 교환 요청을 반환하며, 목록 조회는 `{ "swaps": [ ... ] }`를 반환합니다.

<ResponseExample>
```json 200
{
  "id": "3KHq2nB7yZ0d4kVwXc1sPa9LmQe",
  "orgId": "<organization-id>",
  "scheduleId": "<schedule-id>",
  "scheduleName": "Payments primary",
  "requesterId": "<user-id>",
  "targetId": "<another-user-id>",
  "startAt": 1790060400000000,
  "endAt": 1790146800000000,
  "note": "Travelling on Friday",
  "status": "pending",
  "overrideId": null,
  "decidedBy": null,
  "decidedAt": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

| 필드 | 비고 |
|---|---|
| `status` | `pending`(응답 대기), `awaiting_approval`(수락 후 승인 대기), `accepted`(적용됨), `declined`(거절), `rejected`(관리자가 반려), `cancelled`(철회) 또는 `expired`(만료)입니다. |
| `overrideId` | 근무 교환을 적용할 때 추가한 재정의의 ID입니다. |
| `decidedBy`, `decidedAt` | 마지막으로 응답, 승인, 반려 또는 철회한 구성원과 해당 작업의 시각입니다. |

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 교환 대상 기간이 잘못되었거나, 요청을 받은 구성원이 스케줄에 없거나, 해당 기간에 요청자 외의 구성원이 온콜 근무를 맡거나, 아직 결정되지 않은 교환 요청과 기간이 겹칩니다. |
| `403` | 필요한 권한이 없거나 호출자가 이 단계를 수행할 수 있는 구성원이 아닙니다. |
| `404` | 스케줄 또는 근무 교환 요청이 없습니다. |
| `409` | 근무 교환 요청이 이미 이 단계를 지났거나(예: 수락 또는 만료), 그사이에 다른 구성원이 요청을 변경했습니다. 요청을 다시 조회한 후 재시도합니다. |
