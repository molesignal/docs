```http
GET /api/v1/alerts/importance
PUT /api/v1/alerts/importance
```

`GET`에는 `alerts.importance.read` 권한이 필요하고, `PUT`에는 `alerts.importance.manage` 권한이 필요합니다. 두 요청 모두 조직의 수준을 반환합니다.

```json
{
  "levels": {
    "priorities": [
      {"priority": "P1", "name": "Critical business impact", "description": "Customers cannot pay"},
      {"priority": "P2", "name": "", "description": ""},
      {"priority": "P3", "name": "", "description": ""}
    ],
    "urgencies": [
      {"key": "urgent", "name": "Urgent", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["critical"]},
      {"key": "high", "name": "", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["error"]},
      {"key": "low", "name": "", "escalates": false, "quietHours": "block", "steps": "low", "severities": ["warning", "info"]}
    ]
  },
  "updatedBy": "3KF1...",
  "updatedAt": 1793059200000000
}
```

수준을 저장한 적이 없는 조직에는 기본 수준을 반환합니다. 우선순위는 `P1`부터 `P5`까지이고, 긴급도는
[긴급도](/ko/alerting/on-call#긴급도)에서 설명하는 `high`와 `low`이며, `updatedBy`는 비어 있습니다. `PUT`은
`levels` 객체를 받아 수준을 교체하고 `alert_importance.updated` 감사 이벤트를 기록합니다.

| 필드 | 설명 |
|---|---|
| `priorities` | 수준은 1~9개이며, `P1`, `P2`, … 순으로 번호를 건너뛰지 않습니다. `name`은 최대 32자, `description`은 최대 200자입니다. 이름이 비어 있으면 키를 사용합니다. |
| `urgencies` | 수준은 2~5개이며, 긴급도가 가장 높은 수준을 맨 앞에 둡니다. `key`는 소문자로 시작하며 소문자, 숫자, 밑줄만 포함할 수 있고 최대 32자입니다. `high`와 `low`는 유지해야 합니다. `name`은 최대 32자입니다. 이름이 비어 있으면 기본 이름을 사용합니다. |
| `escalates` | `true`이면 에스컬레이션 정책의 단계에 따라 호출합니다. `false`이면 첫 번째 단계에만 알림을 보냅니다. |
| `quietHours` | `switch`는 개인의 **알림 제한 시간에도 긴급도가 높은 경보 받기** 설정을 따릅니다. `block`은 알림 제한 시간에 누구도 호출하지 않습니다. |
| `steps` | 이 수준에 적용할 개인의 두 단계 그룹 중 하나입니다. `high` 또는 `low`입니다. |
| `severities` | 정책이 심각도에 따라 긴급도를 설정할 때 이 수준에 매핑할 심각도입니다. `critical`, `error`, `warning`, `info`는 각각 정확히 하나의 수준에 매핑합니다. |

규칙, 에스컬레이션 정책, 인시던트, API에서는 설정된 수준만 지정할 수 있습니다. 설정 범위를 벗어나는
우선순위나 설정에 없는 긴급도를 지정하면 `400` 오류를 반환합니다. 외부 경보나 경보 파이프라인에서
설정 범위를 벗어나는 우선순위를 지정하면 가장 낮은 우선순위를 적용하며, 조직에 설정되지 않은
긴급도 값은 무시합니다. 알림에는 이름이 `{{priority_name}}`과 `{{urgency_name}}`으로 표시됩니다.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/importance \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d @levels.json
```
</RequestExample>

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 수준이 위 표의 규칙을 위반합니다. |
| `403` | 토큰에 필요한 권한이 없습니다. |
| `422` | 필드의 타입이 잘못되었거나 키가 유효하지 않습니다. |
