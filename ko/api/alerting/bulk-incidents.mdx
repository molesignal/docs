```http
POST /api/v1/alerts/incidents/bulk
```

`ids`에 지정한 인시던트를 하나씩 처리하며, 각 인시던트에 작업을 하나씩 수행합니다. 처리할 수 없는 인시던트가 있어도
나머지 인시던트는 계속 처리합니다. `action`으로 수행할 작업을 지정하고, 해당 작업에 필요한 필드를 함께 전달합니다.

| `action` | 필드 | 동작 |
|---|---|---|
| `acknowledge` | 없음 | [인시던트 확인](/ko/api/alerting/ack-incident)과 동일하게 동작합니다. |
| `resolve` | 없음 | [인시던트 해결](/ko/api/alerting/resolve-incident)과 동일하게 동작합니다. |
| `snooze` | `durationSecs` | [인시던트 일시 중지](/ko/api/alerting/snooze-incident)와 동일하게 동작합니다. |
| `reassign` | `to`([인시던트 재할당](/ko/api/alerting/reassign-incident)의 요청 본문) | 해당 호출과 동일하게 동작합니다. |
| `set_severity` | `severity` | [인시던트 심각도 설정](/ko/api/alerting/set-incident-severity)과 동일하게 동작합니다. |

이 호출에는 `alerts.incidents.acknowledge` 권한이 필요하며, 각 인시던트를 개별 호출과 동일한 방식으로 검사합니다.
병합은 일괄 작업으로 지원하지 않습니다. [인시던트 병합](/ko/api/alerting/merge-incidents)을 사용합니다.

**본문**

| 필드 | 유형 | 필수 | 참고 |
|---|---|---|---|
| `ids` | 배열 | 예 | 인시던트 ID 1~100개를 지정합니다. 중복 ID는 한 번만 계산합니다. |
| `action` | 문자열 | 예 | `acknowledge`, `resolve`, `snooze`, `reassign` 또는 `set_severity`입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<incident-id>", "<another-incident-id>"], "action": "snooze", "durationSecs": 3600}'
```
</RequestExample>

응답은 인시던트마다 결과를 하나씩 반환합니다. 각 결과에는 `id`가 포함되며, 인시던트가 복구되었거나 `durationSecs`가 허용 범위를 벗어나는 등의 이유로 처리하지 못하면 `error`도 포함됩니다.

<ResponseExample>
```json 200
{
  "results": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW"
    },
    {
      "id": "3KEDQ4mJ8sLp2Xv6Nc1Rt9bYwHe",
      "error": "this incident is no longer active"
    }
  ]
}
```
</ResponseExample>

**오류**

| 상태 | 원인 |
|---|---|
| `400` | `ids`가 비어 있거나 인시던트가 100개를 초과합니다. |
| `403` | 토큰에 `alerts.incidents.acknowledge` 권한이 없습니다. |
| `422` | `action`이 누락되었거나 지원하지 않는 값이거나, 해당 작업에 필요한 필드가 누락되었습니다. |
