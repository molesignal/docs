```http
PUT /api/v1/alerts/incidents/{id}/priority
PUT /api/v1/alerts/incidents/{id}/urgency
```

두 호출 모두 `alerts.incidents.update` 권한이 필요하며, 다른 인시던트에 병합되지 않은 활성 인시던트를 대상으로 합니다.
타임라인에는 `priority_changed`와 `urgency_changed`가 각각 기록됩니다.

- **우선순위**: 요청 본문에 `{"priority": "P2"}`와 같이 조직의
  [우선순위 수준](/ko/alerting/on-call#긴급도-및-우선순위-수준) 중 하나를 지정합니다. 우선순위를 해제하려면 `null`을 지정합니다.
  우선순위만 변경하며 알림을 다시 보내지 않습니다.
- **긴급도**: 요청 본문에 `{"urgency": "high"}`와 같이
  조직의 긴급도 수준 중 하나의 키를 지정합니다. `urgencySetBy`에 호출자를 기록하며, 이후에는 지원 시간에 따라
  긴급도가 바뀌지 않습니다. `open` 상태인 인시던트의 긴급도를 높이면 적용되는 첫 단계부터
  `escalation.reason`을 `urgency_raised`로 설정해 알림을 다시 보냅니다. 긴급도를 낮추면 긴급도만 변경하며,
  에스컬레이션 단계가 올라가지 않는 수준으로 변경하면 추가 에스컬레이션을 중단합니다.

여러 인시던트를 한 번에 변경하려면 [일괄 작업](/ko/api/alerting/bulk-incidents)에
`{"action": "set_priority", "priority": "P2"}`와 `{"action": "set_urgency", "urgency": "low"}`를 사용합니다.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/urgency \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"urgency": "high"}'
```
</RequestExample>

응답은 인시던트입니다. `urgency`는 긴급도 수준의 키입니다. 이 필드가 추가되기 전에 열린
인시던트에는 이 필드가 없으며, 긴급도가 높은 것으로 간주합니다. `priority`는 `P1`부터 `P9`까지의 값이거나 생략됩니다.
에스컬레이션 정책에서 긴급도를 정한 경우 `urgencyByPolicy`는 `true`입니다.

**오류**

| 상태 | 이유 |
|---|---|
| `400` | 우선순위가 조직에서 설정한 범위를 벗어나거나 긴급도가 조직에서 설정한 수준에 해당하지 않습니다. |
| `422` | 우선순위가 `P1`부터 `P9`까지의 값이 아니거나 긴급도 키가 소문자, 숫자, 밑줄로만 구성되어 있지 않습니다. |
| `403` | 토큰에 `alerts.incidents.update` 권한이 없거나 해당 인시던트에 액세스할 수 없습니다. |
| `404` | 해당 인시던트가 없습니다. |
| `409` | 인시던트가 복구되었거나 다른 인시던트에 병합되었습니다. |
