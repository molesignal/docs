```http
POST /api/v1/alerts/routing/test
```

현재 라우팅 규칙, 팀 온콜 정책, 서비스 카탈로그에 따라 이 라벨이 붙은 인시던트를 어떻게 [라우팅할지](/ko/alerting/routing#라우팅-순서) 확인합니다. `alerts.routing.read` 권한이 필요합니다. 소스에는 기본 정책이 적용된다고 가정합니다. 인시던트를 열거나 알림을 보내지 않습니다.

| 필드 | 유형 | 설명 |
|---|---|---|
| `labels` | 객체 | 인시던트의 라벨입니다. `alert.source` 라벨 값으로 출처를 구분합니다. `external`은 알림 소스, `synthetic`은 신세틱 검사, 그 외 값은 알림 규칙을 나타냅니다. |
| `services` | 배열 | 영향을 받는 서비스입니다. 라벨에 `service.name` 또는 `service`가 없으면 첫 번째 서비스를 사용합니다. |
| `severity` | 문자열 | `info`, `warning`(기본값), `error` 또는 `critical`입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"labels": {"service.name": "checkout", "env": "prod"}, "severity": "critical"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "decision": {
    "escalationPolicyId": "<policy-id>",
    "teamId": "<team-id>",
    "routing": { "reason": "rule", "ruleId": "<rule-id>", "ruleName": "Payments in production" }
  },
  "matchedRuleId": "<rule-id>",
  "service": "default/checkout",
  "serviceTeamId": "<team-id>",
  "labelTeamId": null
}
```
</ResponseExample>

| 필드 | 설명 |
|---|---|
| `decision.escalation_policy_id` | 인시던트에 적용할 에스컬레이션 정책입니다. 기본 정책이면 `default`입니다. |
| `decision.team_id` | 인시던트를 전달할 팀입니다. 전달할 팀이 없으면 `null`입니다. |
| `decision.routing` | 라우팅 결정의 근거입니다. 인시던트의 `routing`과 동일합니다. [인시던트 필드](/ko/api/alerting/list-incidents#인시던트-필드)를 참조합니다. |
| `matchedRuleId` | 일치한 라우팅 규칙입니다. 일치하는 규칙이 없으면 `null`입니다. |
| `service` | 소유 팀을 확인하기 위해 조회한 서비스입니다. 형식은 `namespace/name`입니다. |
| `serviceTeamId` | 서비스 카탈로그에서 해당 서비스를 소유한 팀입니다. |
| `labelTeamId` | `teamId` 또는 `team` 라벨이 가리키는 팀입니다. |
