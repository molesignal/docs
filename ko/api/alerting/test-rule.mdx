```http
POST /api/v1/alerts/rules/{id}/test
```

저장된 규칙의 쿼리를 `now - period_secs`부터 `now`까지의 시간 범위에서 한 번 실행하고 조건 충족 여부를 반환합니다. 이 호출은 아무것도 변경하지 않습니다. 평가 상태, 인시던트, 알림, 규칙 자체에는 영향을 주지 않습니다. 호출하려면 `alerts.rules.manage` 권한이 필요하며 요청 본문은 비워 둡니다.

`enabled`를 `true`로 설정하기 전에 규칙을 테스트합니다. 잘못된 쿼리문을 사용하거나 알 수 없는 스트림을 참조하는 규칙도 오류 없이 저장되므로 테스트에서만 문제를 확인할 수 있습니다.

[APM 규칙](/ko/api/alerting/create-rule#apm-규칙)은 쿼리를 실행하는 대신 지표 값을 읽습니다. 결과는 `value`, `service`, `trace_id` 열이 있는 행 하나입니다. 시간 범위에 지표 값이 없으면 행을 반환하지 않습니다.

[열별로 분할된 규칙](/ko/api/alerting/create-rule#열별로-분할한-규칙)은 `groups`에 모든 그룹을 나열합니다. `matched`는 조건을 충족하는 그룹이 하나라도 있으면 `true`이며, `value`는 조건을 충족하는 첫 번째 그룹의 값이고, `severity`는 그룹 중 가장 높은 심각도입니다.

[RUM 규칙](/ko/api/alerting/create-rule#rum-규칙)도 같은 방식으로 지표 값을 읽습니다. 결과는 `value`와 `application` 열이 있는 행 하나이며, 시간 범위에 지표 값이 없으면 행을 반환하지 않습니다. `scannedRows`는 지표 값 산출에 사용한 행 수입니다.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/test \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "matched": true,
  "value": 2.0,
  "severity": "critical",
  "columns": ["c"],
  "rows": [[2]],
  "scannedRows": 2,
  "tookMs": 170
}
```
</ResponseExample>

**응답**

| 필드 | 유형 | 설명 |
|---|---|---|
| `matched` | 불리언 | 현재 조건을 충족하는지 나타냅니다. 결과에 `forPeriods`를 반영하지 않습니다. |
| `value` | 숫자 또는 null | 첫 번째 행의 첫 번째 열 값입니다. 결과에 숫자가 없으면 `null`입니다. |
| `severity` | 문자열 또는 null | 인시던트에 부여할 심각도입니다. `matched`가 `false`이면 `null`입니다. |
| `columns` | 배열 | 쿼리 결과의 열 이름입니다. |
| `rows` | 배열 | 결과 행을 최대 20개까지 포함합니다. |
| `scannedRows` | 정수 | 쿼리가 스캔한 행 수입니다. |
| `tookMs` | 정수 | 쿼리 실행 시간(밀리초)입니다. |
| `anomaly` | 객체 | `anomaly` 규칙에만 포함합니다. `baseline`, `deviation`, 0에서 1 사이의 `score`, 사유를 설명하는 `reason` 텍스트를 포함합니다. |
| `noData` | 불리언 | `true`일 때만 포함합니다. 실행 결과에 값이 없으며 규칙은 누락된 값을 `0`으로 처리하지 않습니다. |
| `groups` | 배열 | 열별로 분할된 규칙에만 포함하며 결과 순서를 따릅니다. 각 그룹에는 열을 해당 값에 매핑하는 `labels`와 그룹의 `value`, `matched`, `severity`가 포함됩니다. |
| `groupsTruncated` | 불리언 | `true`일 때만 포함합니다. 결과에 그룹이 100개를 초과하면 처음 100개만 반환합니다. |

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 잘못된 SQL이나 알 수 없는 필드 등의 이유로 쿼리를 실행할 수 없거나, `anomaly` 규칙에 기준선을 산출할 수 있는 이력이 없거나, 규칙이 쿼리를 실행하지 않는 `composite` 또는 `heartbeat` 유형입니다. |
| `403` | 규칙이 참조하는 스트림이 없거나 토큰에 `alerts.rules.manage` 권한이 없습니다. |
| `404` | 규칙이 존재하지 않습니다. |
