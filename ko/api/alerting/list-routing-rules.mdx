```http
GET /api/v1/alerts/routing/rules
```

조직의 [라우팅 규칙](/ko/alerting/routing#라우팅-규칙)을 평가 순서(`position` 오름차순)로 나열합니다. `alerts.routing.read` 권한이 필요합니다. 비활성화된 규칙도 나열합니다.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "id": "3KF0q7vXbJ2mYc8sTn4LwRk9Ez1",
    "orgId": "<organization-id>",
    "name": "Payments in production",
    "enabled": true,
    "position": 0,
    "conditions": [
      { "key": "env", "operator": "equals", "values": ["prod"] },
      { "key": "service.name", "operator": "in", "values": ["checkout", "cart"] }
    ],
    "minSeverity": "error",
    "origins": [],
    "target": { "kind": "team", "teamId": "<team-id>" },
    "createdBy": "<user-id>",
    "createdAt": 1790000000000000,
    "updatedAt": 1790000000000000
  }
]
```
</ResponseExample>

## 규칙 필드

| 필드 | 설명 |
|---|---|
| `id`, `orgId` | 규칙과 조직의 식별자입니다. |
| `name` | 규칙 이름입니다. |
| `enabled` | 비활성화된 규칙은 평가하지 않습니다. |
| `position` | 평가 순서입니다. 값이 작은 규칙부터 평가합니다. |
| `conditions` | 인시던트 라벨에 적용하는 조건입니다. 모든 조건을 충족해야 하며, 비어 있으면 모든 인시던트가 일치합니다. 각 조건에는 `key`, `operator`, `values`가 있습니다. |
| `minSeverity` | 인시던트의 최소 심각도입니다. `info`, `warning`, `error`, `critical` 중 하나를 지정합니다. `null`이면 모든 심각도를 허용합니다. |
| `origins` | 규칙을 적용할 출처입니다. `rule`(알림 규칙), `external`(알림 소스), `synthetic`(신세틱 검사)을 지정할 수 있습니다. 비어 있으면 모든 출처에 적용합니다. |
| `target` | 일치하는 인시던트를 보낼 대상입니다. `{"kind": "team", "teamId": …}` 또는 `{"kind": "policy", "policyId": …}`를 지정합니다. |
| `createdBy` | 규칙을 생성한 사용자입니다. |
| `createdAt`, `updatedAt` | 규칙을 생성한 시각과 마지막으로 변경한 시각입니다. 단위는 마이크로초입니다. |

`operator` 값:

| `operator` | `values` | 일치 조건 |
|---|---|---|
| `equals` | 값 1개 | 라벨 값이 지정한 값과 같습니다. |
| `not_equals` | 값 1개 | 라벨 값이 지정한 값과 다르거나 인시던트에 해당 라벨이 없습니다. |
| `in` | 값 1개 이상 | 라벨 값이 지정한 값 중 하나와 같습니다. |
| `matches` | 정규 표현식 1개 | 라벨 값 전체가 정규 표현식과 일치합니다. |
