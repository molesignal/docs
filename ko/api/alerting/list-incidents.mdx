```http
GET /api/v1/alerts/incidents
GET /api/v1/alerts/incidents/{id}
```

첫 번째 호출은 인시던트를 최신순으로 나열합니다. 다른 인시던트에 [병합된](/ko/api/alerting/merge-incidents) 인시던트는 제외하며, 해당 인시던트는 병합 대상 인시던트의 [타임라인](/ko/api/alerting/incident-timeline)에 표시됩니다. 두 번째 호출은 병합 여부와 관계없이 인시던트 하나를 반환합니다. 두 호출 모두 `alerts.incidents.read` 권한이 필요합니다.

**목록 조회 쿼리 매개변수**

| 매개변수 | 유형 | 설명 |
|---|---|---|
| `scope` | 문자열 | `active`(기본값)는 상태가 `open` 또는 `acknowledged`인 인시던트를 반환합니다. `all`은 조회 기간 내에 생성된 인시던트와 생성 시점에 관계없이 모든 활성 인시던트를 반환합니다. |
| `windowSecs` | 정수 | `scope=all`의 조회 기간입니다. 기본값은 `604800`(7일)입니다. 값이 범위를 벗어나면 3600 또는 31536000으로 제한합니다. |

목록 항목에는 요약 정보만 포함됩니다. `triggeringQuery`는 `null`이며, `traceIds`, `hostIds`, `affectedServices`에는 각각 값이 최대 하나씩 들어갑니다. 전체 레코드를 확인하려면 개별 인시던트를 조회합니다.

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/alerts/incidents?scope=all&windowSecs=86400" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

## 인시던트 필드

| 필드 | 설명 |
|---|---|
| `id`, `orgId`, `ruleId` | 인시던트, 조직, 규칙의 식별자입니다. |
| `escalationPolicyId` | 인시던트가 열릴 때 소스에서 지정한 정책으로 설정합니다. 소스가 기본 정책을 사용하면 [알림 라우팅](/ko/alerting/routing)에서 선택한 정책으로 설정합니다. 에스컬레이션이 시작되면 별칭 `default`를 이름이 `default`인 정책의 ID로 바꿉니다. |
| `status` | `open`, `acknowledged`, `resolved` 중 하나입니다. 모델에는 `closed`도 있지만, 이 상태로 설정하는 호출은 없습니다. |
| `severity` | `info`, `warning`, `error`, `critical` 중 하나입니다. |
| `summary` | 규칙 이름 뒤에 영향을 받은 서비스를 최대 두 개까지 표시하고, 그보다 많으면 나머지 개수를 `+N`으로 표시합니다. |
| `fingerprint` | 규칙의 `id`와 `labels`를 해시한 값입니다. 규칙마다 핑거프린트 하나에 활성 인시던트가 하나만 존재합니다. |
| `currentStep`, `currentLoop`, `currentStepStartedAt` | 에스컬레이션 진행 상태입니다. 단계 번호는 0부터 시작하며, 시간 단위는 마이크로초입니다. |
| `assignees` | 인시던트 담당자입니다. 현재 에스컬레이션 단계의 직접 대상인 `user` 대상과 각 `schedule` 대상의 온콜 사용자에 더해, 인시던트를 확인한 사용자도 포함합니다. 첫 단계가 실행되기 전에는 비어 있습니다. 팀만 대상으로 지정한 단계에서는 이전 담당자를 유지합니다. |
| `labels`, `annotations` | 인시던트가 열릴 때 저장하는 스냅샷입니다. 규칙의 `labels`와 쿼리 결과의 `service`, `host`를 포함합니다. 이후 규칙을 수정해도 스냅샷은 바뀌지 않습니다. |
| `traceIds`, `hostIds`, `affectedServices` | 쿼리 결과에서 각각 `trace_id`, `host`, `service` 열의 값을 가져와 중복을 제거한 값입니다. 필드마다 최대 10개를 포함합니다. |
| `triggeringQuery` | `language`, `statement`, `sampleValues`를 포함합니다. 각 샘플에는 마이크로초 단위의 `ts`(결과에 시간 열이 없으면 `0`), `value`, `labels`가 들어갑니다. 개별 인시던스 조회 호출만 이 필드를 반환합니다. |
| `createdAt` | 인시던트가 열린 시각입니다. 단위는 마이크로초입니다. |
| `acknowledgedAt`, `acknowledgedBy` | 가장 최근에 인시던트를 확인한 시각과 사용자입니다. |
| `resolvedAt`, `resolvedBy` | 인시던트를 해결한 시각과 사용자입니다. 규칙 조건이 더 이상 충족되지 않아 평가기가 인시던트를 해결한 경우 `resolvedBy`는 `null`입니다. |
| `teamId` | 인시던트가 열릴 때 [알림 라우팅](/ko/alerting/routing)이 배정한 팀의 ID입니다. 배정한 팀이 없으면 `null`입니다. |
| `routing` | 해당 팀으로 라우팅한 이유입니다. 라우팅 기능 도입 전에 열린 인시던트에서는 `null`입니다. `reason`은 `rule`(라우팅 규칙 일치, `ruleId`와 당시의 `ruleName` 포함), `service_owner`(서비스 소유 팀, `service` 포함), `team_label`(팀 레이블), `default`(기본 정책), `source`(소스에서 에스컬레이션 정책을 선택하여 라우팅으로는 팀만 결정) 중 하나입니다. |
| `snoozedUntil`, `snoozedBy` | 인시던트 알림을 [일시 중지한](/ko/api/alerting/snooze-incident) 동안에는 마이크로초 단위의 일시 중지 종료 시각과 일시 중지한 사용자를 나타냅니다. 그 외에는 `null`입니다. |
| `severitySetBy` | [심각도를 설정한](/ko/api/alerting/set-incident-severity) 사용자입니다. 수동으로 설정하면 규칙은 더 이상 심각도를 변경하지 않습니다. 수동으로 설정하지 않은 경우 `null`입니다. |
| `mergedInto` | 이 인시던트가 [병합된](/ko/api/alerting/merge-incidents) 대상 인시던트입니다. 병합되지 않았으면 `null`입니다. |
| `assigneesPinned` | 수동으로 지정한 담당자를 유지하는 동안 `true`입니다. 에스컬레이션은 다음 단계로 넘어갈 때만 담당자를 교체합니다. |
| `dispatchRound`, `dispatchReason` | `dispatchRound`는 에스컬레이션 알림 회차입니다. 수동으로 에스컬레이션하거나, 다른 팀이나 정책으로 재할당하거나, 심각도를 높이면 회차가 증가하므로 같은 단계에서 알림을 다시 보낼 수 있습니다. `dispatchReason`은 현재 단계에서 가장 최근 알림을 보낸 이유이며, `step`, `manual`, `reassigned`, `responder_added`, `snooze_ended`, `ack_timeout`, `severity_raised` 중 하나입니다. |
| `revision` | 인시던트가 변경될 때마다 증가합니다. |

**오류**

| 상태 | 원인 |
|---|---|
| `403` | 토큰에 `alerts.incidents.read` 권한이 없습니다. |
| `404` | 인시던트가 존재하지 않습니다. |
