[억제](/ko/alerting/inhibition) 규칙입니다. 조회에는 `alerts.inhibitions.read`, 변경에는 `alerts.inhibitions.manage` 권한이 필요합니다.

```http
GET    /api/v1/alerts/inhibit-rules
POST   /api/v1/alerts/inhibit-rules
GET    /api/v1/alerts/inhibit-rules/{id}
PUT    /api/v1/alerts/inhibit-rules/{id}
DELETE /api/v1/alerts/inhibit-rules/{id}
```

**요청 본문**

| 필드 | 유형 | 설명 |
|---|---|---|
| `name` | string | 필수이며 최대 255자입니다. |
| `enabled` | boolean | 기본값은 `true`입니다. |
| `source.matchers` | array | 소스의 레이블 조건입니다. 형식은 `{label, op, value}`이며, `op`는 `eq`, `neq`, `re`, `nre` 중 하나입니다. 모든 조건을 충족해야 합니다. |
| `source.min_severity` | string | 소스 심각도는 이 값 이상이어야 합니다. 지정하지 않으면 모든 심각도를 허용합니다. |
| `target.matchers` | array | 대상의 레이블 조건입니다. 지정하지 않으면 모든 인시던트가 대상입니다. |
| `target.max_severity` | string | 대상 심각도는 이 값 이하여야 합니다. 지정하지 않으면 모든 심각도를 허용합니다. |
| `equal` | array | 소스와 대상이 같은 값으로 가져야 하는 레이블로, 최대 16개입니다. `source.matchers`와 `equal`을 모두 비워 둘 수는 없습니다. |
| `moreSevereOnly` | boolean | 소스의 심각도가 대상보다 높아야 합니다. 기본값은 `true`입니다. |
| `waitSecs` | integer | 대상의 알림 대기 시간(초)입니다. 범위는 0~600이고 기본값은 60이며, 15 미만은 15로 처리합니다. |
| `lingerSecs` | integer | 소스가 복구된 후에도 대상의 알림을 계속 억제하는 시간(초)입니다. 범위는 0~3600이고 기본값은 120입니다. |
| `comment` | string | 설명을 남기는 메모입니다. |

레이블 조건에서 인시던트에 해당 레이블이 없으면 `service`와 `host`는 각각 영향을 받은 서비스와 호스트를 사용합니다. `alert.rule_id`는 인시던트를 생성한 규칙 또는 소스입니다. 정규식을 파싱할 수 없으면 `400`을 반환합니다.

목록과 상세 응답의 각 규칙에는 현재 알림을 억제 중인 인시던트 수를 나타내는 `inhibiting`도 포함됩니다.

<RequestExample>
```bash cURL
curl -X POST "http://localhost:5080/api/v1/alerts/inhibit-rules" \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "name": "On one service, the worse holds back the lesser",
    "equal": ["service"],
    "moreSevereOnly": true
  }'
```
</RequestExample>

## 미리 보기

```http
POST /api/v1/alerts/inhibit-rules/preview
```

요청 본문은 동일하며 `alerts.inhibitions.read` 권한이 필요합니다. `name`은 생략할 수 있고 규칙을 저장할 필요도 없습니다. `enabled` 값에 관계없이 현재 활성 상태인 인시던트에 이 규칙만 적용합니다.

| 필드 | 설명 |
|---|---|
| `pairs[].source_incident_id`, `sourceSummary`, `sourceSeverity` | 다른 인시던트의 알림을 억제하는 소스 인시던트입니다. |
| `pairs[].target_incident_id`, `targetSummary`, `targetSeverity` | 알림이 억제되는 대상 인시던트입니다. |

## 인시던트 억제 해제

```http
POST /api/v1/alerts/incidents/{id}/inhibition/lift
```

해당 인시던트에 대한 `alerts.incidents.update` 권한이 필요합니다. 억제 중인 알림을 즉시 전송하고 해당 인시던트의 알림을 다시 억제하지 않습니다. 이 작업을 타임라인과 감사 로그에 기록합니다. 억제 중이 아니면 아무 작업도 하지 않으며, 이미 해결되었거나 병합된 인시던트에는 `409`를 반환합니다. 인시던트를 반환합니다.

인시던트 JSON의 다음 필드에서 억제 상태를 확인할 수 있습니다.

| 필드 | 설명 |
|---|---|
| `inhibition` | 현재 억제 상태입니다. `ruleId`, `ruleName`, `sourceIncidentId`, `sourceSummary`, `since`와 소스 복구 후 억제 종료 시각을 나타내는 `endingAt`을 포함합니다. 인시던트가 해결된 후에도 이 필드가 남아 해결 시점에 알림을 보내지 않았음을 나타냅니다. |
| `inhibitionWaitUntil` | 소스 인시던트가 발생하는지 확인하기 위해 이 시각(마이크로초)까지 알림 전송을 보류합니다. |
| `inhibitionLiftedBy` | 정상적으로 알림을 보내도록 억제를 해제한 주체입니다. |
