```http
GET /api/v1/alerts/incidents/{id}/timeline
```

단일 인시던트에서 일어난 일을 반환합니다. 여기에는 사용자와 MoleSignal이 기록한 조치, 해당 인시던트에 대해 전송한 알림,
그리고 해당 인시던트에 병합한 인시던트가 포함됩니다. 이 API를 호출하려면 `alerts.incidents.read` 권한이 필요합니다. 콘솔은 이 응답을 바탕으로
인시던트의 [타임라인](/ko/alerting/incidents#인시던트-상세-정보)을 구성합니다.

| 필드 | 내용 |
|---|---|
| `entries` | 기록한 조치입니다. 오래된 순으로 정렬합니다. 필드는 `id`, `orgId`, `incidentId`, `at`(마이크로초 단위), `kind`, `actor`(사용자 ID, MoleSignal 자체인 경우 `null`), `detail`입니다. |
| `deliveries` | 인시던트에 대한 알림입니다. 오래된 순으로 최대 500개를 반환합니다. 필드는 `id`, `eventId`(`alert.triggered:…`, `alert.escalated:…`, `alert.acknowledged:…`, `alert.resolved:…` 중 하나), `userId`, `connectorId`, `target`(마스킹 처리), `stage`, `status`, `error`, `createdAt`, `deliveredAt`입니다. [파이프라인에서 알림 전송을 차단한 정책](/ko/pipelines/alert-events#알림-전송-전)은 `status`가 `skipped`이고 `userId`와 `connectorId`가 없으며, `error`에 차단 사유를 담습니다. |
| `merged` | 이 인시던트에 [병합한](/ko/api/alerting/merge-incidents) 인시던트입니다. 필드는 `id`, `summary`, `status`, `severity`, `createdAt`, `resolvedAt`입니다. |

| `kind` | `detail` |
|---|---|
| `acknowledged`, `resolved` | `via`: `web`, `api`, `im`, `sms`, `phone`, `agent` 중 하나입니다. |
| `escalated` | `step`(0부터 시작), `loop`, `reason`, 해당 단계의 `targets`입니다. |
| `reassigned` | [인시던트 재할당](/ko/api/alerting/reassign-incident)과 동일한 `to`, 그리고 이전 담당자, 팀, 정책을 담은 `from`입니다. |
| `responders_added` | `userIds`입니다. |
| `snoozed` | 마이크로초 단위의 `until`과 `durationSecs`입니다. |
| `snooze_cancelled` | 비어 있습니다. |
| `retriggered` | `reason`: `snooze_ended` 또는 `ack_timeout`입니다. |
| `severity_changed` | `from`과 `to`입니다. |
| `merged` | `into`: 병합 대상 인시던트입니다. |
| `merged_in` | `incidents`: 이 인시던트에 병합한 인시던트입니다. |
| `merged_recovered` | 병합 후 복구된 인시던트의 `incidentId`와 `summary`입니다. |
| `note` | `text`와 `via`입니다. |
| `remediation_requested` | [복구 작업](/ko/api/alerting/remediation)을 요청했습니다. 실행 ID인 `runId`, 작업 이름인 `action`, 입력한 값인 `inputs`를 담습니다. |
| `remediation_executed` | 복구 작업이 완료되었습니다. `runId`, `action`, `status`(`succeeded` 또는 `failed`), `output`(응답의 시작 부분 또는 오류)을 담습니다. |
| `remediation_verified` | 실행 후 검증 결과입니다. `runId`, `action`, `passed`, 검증 방식인 `by`(`incidentResolved` 또는 `rule_healthy`)를 담습니다. |
| `ticket_created` | [티켓](/ko/api/alerting/tickets)을 생성했습니다. `system`(`jira` 또는 `meegle`), `key`, `url`, 커넥터 이름인 `connector`를 담습니다. |
| `ticket_updated` | 동기화 중 티켓 상태 변경을 감지했습니다. `key`, `status`, `done`을 담습니다. |
| `declared_major` | [중대 인시던트](/ko/api/alerting/major-incidents)를 선언했습니다. 조직 규칙에 따라 선언한 경우 `auto`는 `true`입니다. |
| `role_assigned` | 역할을 할당했습니다. `role`(`commander`, `communications`, `scribe` 중 하나)과 `userId`를 담습니다. 할당을 해제한 경우 `userId`는 `null`입니다. |
| `war_room_created` | 대응 채널을 생성했습니다. `platform`, 참여 링크인 `url`, 회의 링크인 `meetingUrl`을 담습니다. |
| `task_added`, `task_done` | 작업을 추가하거나 완료했습니다. `title`을 담습니다. |
| `status_update` | 상태 업데이트를 게시했습니다. `impact`, `current`, `next`를 담습니다. |
| `pipeline_processed` | [알림 파이프라인](/ko/pipelines/alert-events#이벤트-처리-결과)이 인시던트가 열리기 전에 이벤트를 변경했거나 처리에 실패했습니다. `pipelineId`, `pipeline`, `changes`(각 항목에는 `severity` 또는 `labels.team`과 같은 `field`, 항목을 추가한 경우 생략하는 `from`, 항목을 제거한 경우 생략하는 `to`가 포함됨), `more`(목록에 표시한 40개 외에 추가로 발생한 변경 수), `error`를 담습니다. |

<RequestExample>
```bash cURL
curl -X GET http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/timeline \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**오류**

| 상태 | 원인 |
|---|---|
| `403` | 토큰에 `alerts.incidents.read` 권한이 없습니다. |
| `404` | 인시던트가 존재하지 않습니다. |
