```http
POST /api/v1/alerts/escalations
```

에스컬레이션 정책을 생성합니다. 정책에는 실행 순서대로 단계를 지정합니다. 각 단계에서는 대상에게 알림을 보내고 확인을 기다립니다. 이 호출에는 `alerts.escalations.manage` 권한이 필요합니다.

## 에스컬레이션 작동 방식

1. `alert` 역할은 `[alert].dispatch_interval_secs` 간격으로 활성 인시던트를 확인합니다. 기본 간격은 10초입니다. 상태가 `open`인 인시던트만 에스컬레이션합니다. 인시던트를 확인하면 에스컬레이션이 중단됩니다.
2. `minSeverity`를 지정한 단계는 해당 심각도 이상의 인시던트에만 적용됩니다. 적용되지 않는 단계는 건너뜁니다.
3. 현재 단계의 모든 대상이 알림 이벤트를 받습니다. [알림 채널](/ko/notification-channels)에서 메시지 전달 방식을 결정합니다. 인시던트의 `assignees`에는 단계에서 직접 지정한 사용자, 즉 `user` 대상과 각 `schedule` 대상의 온콜 사용자가 할당됩니다. 팀만 대상으로 하는 단계에서는 기존 담당자를 유지합니다.
4. 확인 없이 `ackTimeoutSecs`가 지나면 다음으로 적용 가능한 단계를 시작합니다.
5. 적용 가능한 마지막 단계의 확인 대기 시간이 끝나면, `repeat`가 `true`인 정책은 전체 단계 실행 횟수가 `maxLoops`에 도달할 때까지 첫 단계부터 다시 시작합니다.
6. `ackRetriggerSecs`를 설정하면, `acknowledged` 상태의 인시던트가 확인 후 해당 시간이 지나도 해결되지 않을 때 `open` 상태로 돌아갑니다. `escalation.reason`을 `ack_timeout`으로 설정해 담당자에게 알림을 보냅니다. 담당자가 없으면 현재 단계의 대상에게 다시 알립니다. 현재 단계의 확인 대기 시간을 다시 시작하고 에스컬레이션을 평소대로 진행합니다. 일시 중지된 인시던트에는 이 시간 제한을 적용하지 않습니다.

규칙은 `escalationPolicyId`로 정책을 선택합니다. 이 값이 없는 규칙은 `default`를 사용합니다. 이 별칭은 조직 내에서 이름이 `default`인 정책을 가리키며, 이름을 비교할 때는 대소문자를 구분하지 않습니다. 에스컬레이션을 시작하면 인시던트에 해당 정책의 실제 ID를 저장하므로, 나중에 정책 이름을 바꿔도 열린 인시던트가 다른 정책으로 이동하지 않습니다. 조직에 `default`라는 정책이 없으면 해당 규칙의 인시던트는 에스컬레이션되지 않지만, 발생한 이벤트는 알림 정책에 계속 전달됩니다. `default`라는 정책을 만들거나 규칙에 정책 ID를 지정합니다.

**본문**

| 필드 | 유형 | 필수 | 참고 |
|---|---|---|---|
| `name` | 문자열 | 예 | 비워 둘 수 없습니다. |
| `steps` | 배열 | 아니요 | 기본값은 빈 배열입니다. 단계가 없는 정책은 알림을 보내지 않습니다. |
| `repeat` | 불리언 | 아니요 | 기본값은 `false`입니다. 마지막 단계가 끝나면 처음부터 다시 시작할지 지정합니다. |
| `maxLoops` | 정수 | 아니요 | 기본값은 `1`입니다. `repeat`가 `true`일 때 전체 단계를 실행할 총 횟수입니다. 1보다 작은 값은 1로 처리합니다. |
| `ackRetriggerSecs` | 정수 | 아니요 | 확인한 인시던트가 해결되지 않았을 때 다시 알림을 보내기까지 기다리는 시간입니다. 범위는 300~86400초입니다. 기본값인 `null`은 다시 알리지 않음을 뜻합니다. |
| `urgencyRule` | 객체 | 아니요 | 긴급도가 지정되지 않은 인시던트의 긴급도를 설정하는 방식입니다. 기본값인 `{"mode": "by_severity"}`는 심각도별로 조직에서 지정한 긴급도 수준을 적용합니다. 설정을 변경하지 않으면 심각 및 오류는 높음, 경고 및 정보는 낮음으로 설정합니다. `{"mode": "always", "urgency": "high"}` 또는 `{"mode": "support_hours", "hours": {"timezone": "Asia/Shanghai", "ranges": [{"weekdayMask": 62, "start": "09:00", "end": "18:00"}], "calendar": {"calendarId": "<id>", "holidays": "exclude"}}, "inside": "high", "outside": "low", "raiseAtStart": true}`도 사용할 수 있습니다. 지원 시간에는 `inside`를, 그 외에는 `outside`를 적용합니다. 기본값은 각각 `high`와 `low`입니다. `raiseAtStart`를 설정하면 지원 시간이 시작될 때 아직 확인되지 않았고 긴급도가 `inside`보다 낮은 인시던트의 긴급도를 `inside`로 높인 후 첫 단계부터 다시 알립니다. 긴급도 값은 조직의 [수준](/ko/alerting/on-call#긴급도-및-우선순위-수준) 중 하나의 키입니다. `weekdayMask`의 비트 0은 일요일입니다. `calendar`는 선택 사항이며, `holidays`에는 `exclude` 또는 `only`를 지정합니다([휴일 캘린더](/ko/alerting/on-call#휴일-캘린더) 참조). [긴급도](/ko/alerting/on-call#긴급도)를 참조합니다. |
| `escalateLowUrgency` | 불리언 | 아니요 | 기본값은 `false`입니다. 후속 단계로 진행하지 않도록 설정된 긴급도 수준의 인시던트는 첫 단계에서만 알림을 보내며, 이후 단계로 진행하거나 반복하지 않습니다. `true`이면 이러한 인시던트도 이 정책에 따라 평소대로 에스컬레이션합니다. |

각 단계에는 다음 필드가 있습니다.

| 필드 | 유형 | 필수 | 참고 |
|---|---|---|---|
| `targets` | 배열 | 예 | 이 단계의 수신자입니다. 모든 수신자에게 동시에 알림을 보냅니다. |
| `ackTimeoutSecs` | 정수 | 아니요 | 다음 단계로 넘어가기 전에 확인을 기다리는 시간(초)입니다. 생략하면 `[alert].default_ack_timeout_secs` 값(기본값 300)을 적용하고 단계와 함께 저장합니다. |
| `minSeverity` | 문자열 | 아니요 | `info`, `warning`, `error`, `critical` 중 하나입니다. 이 단계는 지정한 심각도 이상의 인시던트에 적용됩니다. 모든 인시던트에 적용하려면 생략합니다. |

대상은 `kind`로 수신자를 지정합니다.

| `kind` | 추가 필드 | 수신자 |
|---|---|---|
| `user` | `userId` | 사용자 한 명. |
| `team` | `teamId` | 팀 구성원. |
| `schedule` | `scheduleId` | 온콜 일정의 현재 당번 사용자. |

이 호출은 참조한 사용자, 팀 또는 일정이 존재하는지 확인하지 않습니다.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/escalations \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
```

**오류**

| 상태 | 원인 |
|---|---|
| `400` | `name`이 비어 있거나 `ackRetriggerSecs`가 300~86400 범위를 벗어납니다. |
| `403` | 토큰에 `alerts.escalations.manage` 권한이 없습니다. |
| `422` | 필드가 누락되었거나 유효하지 않습니다. 예를 들어 대상의 `kind`가 `user`, `team`, `schedule` 중 하나가 아니거나 `minSeverity` 값이 지원되지 않습니다. 응답은 일반 텍스트입니다. |

## 기타 정책 엔드포인트

| 작업 | 엔드포인트 | 권한 |
|---|---|---|
| 목록 조회 | `GET /api/v1/alerts/escalations` | `alerts.escalations.read` |
| 조회 | `GET /api/v1/alerts/escalations/{id}` | `alerts.escalations.read` |
| 교체 | `PUT /api/v1/alerts/escalations/{id}` | `alerts.escalations.manage` |
| 삭제 | `DELETE /api/v1/alerts/escalations/{id}` | `alerts.escalations.delete` |

`PUT`은 생성 호출과 같은 본문을 받아 정책을 교체합니다. `DELETE`는 일반 텍스트 `deleted`를 반환하며, ID가 존재하지 않으면 `404`를 반환합니다. 정책을 삭제할 때 해당 정책을 참조하는 규칙을 확인하지 않습니다. 해당 규칙은 더 이상 인시던트를 에스컬레이션하지 않습니다.
