```http
PUT /api/v1/alerts/routing/rules/{id}
```

[라우팅 규칙](/ko/alerting/routing#라우팅-규칙) 전체를 덮어씁니다. `alerts.routing.manage` 권한이 필요합니다. [라우팅 규칙 만들기](/ko/api/alerting/create-routing-rule)와 동일한 필드를 사용합니다. 선택 필드를 생략하면 해당 필드가 기본값으로 돌아갑니다. 규칙의 순서는 그대로 유지됩니다. 순서를 바꾸려면 [라우팅 규칙 순서 변경](/ko/api/alerting/reorder-routing-rules)을 사용합니다. 이미 열린 인시던트에는 영향을 주지 않습니다.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "enabled": false, "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

응답으로 업데이트된 규칙을 반환합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 필드가 잘못되었거나 대상 팀 또는 정책이 존재하지 않습니다. |
| `403` | 토큰에 `alerts.routing.manage` 권한이 없습니다. |
| `404` | 규칙이 존재하지 않거나 다른 조직에 속해 있습니다. |
| `422` | `name` 또는 `target`이 누락되었거나 값이 인식되지 않습니다. 응답은 일반 텍스트 형식입니다. |
