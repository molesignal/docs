```http
GET /api/v1/alerts/incidents/{id}/rca
POST /api/v1/alerts/incidents/{id}/rca
```

[Mole Agent](/ko/agent)는 인시던트 컨텍스트에서 인시던트에 대한 근본 원인 분석(RCA)을 작성합니다. 각 인시던트에는 분석이 최대 하나만 있습니다.

`alert` 역할은 분석을 자동으로 생성합니다. 이 역할은 3분마다 분석이 없는 활성 인시던트에 대해 분석을 작성하며, 조직에 API 키가 있는 활성화된 모델 제공자가 있으면 한 번 실행할 때 최대 20개까지 작성합니다. `GET` 호출은 저장된 분석을 읽습니다. `POST` 호출은 새 분석을 즉시 생성하고 저장된 분석을 대체합니다.

| 호출 | 권한 | 설명 |
|---|---|---|
| `GET` | `alerts.incidents.read` | 분석이 존재할 때까지 `404` 응답과 함께 `no root-cause analysis for this incident yet` 메시지를 반환합니다. |
| `POST` | `alerts.incidents.rca` | 모델을 기다린 뒤 새 분석을 반환합니다. 선택적 쿼리 매개변수 `locale`은 출력 언어를 선택하며, `en-us` 또는 `zh-cn`입니다. 기본값은 호출하는 사용자의 언어 기본 설정입니다. |

<RequestExample>
```bash cURL
curl -X POST "http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/rca?locale=en-us" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**응답**

| 필드 | 설명 |
|---|---|
| `incidentId`, `orgId` | 인시던트 및 조직 식별자입니다. |
| `summary` | Markdown 텍스트 형식의 분석입니다. 분석에서는 `[E2]`와 같은 레이블로 근거를 인용합니다. |
| `evidence` | 분석에 제공된 레이블이 지정된 근거이며, 최대 30개입니다. 아래를 참조하세요. |
| `provider`, `model` | `openai`, `anthropic` 또는 `openai_compatible`과 같은 모델 제공자 유형 및 모델 이름입니다. |
| `promptBuiltinKey`, `promptHash` | 감사를 위한 프롬프트 템플릿 및 렌더링된 프롬프트의 해시입니다. |
| `promptTokens`, `completionTokens`, `finishReason` | 제공자가 보고하는 토큰 사용량 및 종료 이유입니다. |
| `createdAt`, `updatedAt` | Unix 에포크 이후 마이크로초입니다. `updatedAt`은 분석이 다시 생성될 때 변경됩니다. |

**근거**

각 근거 항목에는 `label` (`E1`, `E2`, …), `kind`, `source`가 있으며, 알려진 경우 `service`, `subject`(그것이 무엇에
관한 것인지, 수치 없이), `detail`, `at`, `figures`, `link`가 있습니다.

| `kind` | `source` | `figures` |
|---|---|---|
| `insight` | `apm` | `value`, `previous`, `lastWeek`, `calls`, `p95Time`; `detail`은 인사이트 유형과 변화한 수치(예: `anomaly.p95`)입니다. |
| `new_error_group` | `apm` | `occurrences`. |
| `sample_trace` | `traces` | 마이크로초 단위의 `duration`; `link.traceId`. |
| `error_logs` | `logs` | `now` 및 `lastWeek`, 기간 내 오류 수준 라인과 일주일 전 동일 기간의 오류 수준 라인입니다. |
| `new_log_pattern` | `logs` | `lines`, 기간 내 패턴의 오류 수준 라인이며, 기간이 샘플링된 경우 추정됩니다. `subject`는 패턴이고 `detail`은 해당 패턴의 메시지 중 하나입니다. |
| `attribute_skew` | `traces` | `failedShare` 및 `otherShare`: 해당 값을 가진 실패한 요청과 기타 요청의 비율입니다. `score`: 해당 필드에서 두 집합이 얼마나 떨어져 있는지(0~1)입니다. `failed`: 조회된 실패 요청입니다. `subject`는 필드이고 `detail`은 값입니다. |
| `business_impact` | `traces` | 요청이 실패한 값의 `errors` 및 `requests`, 해당 값의 개수인 `values`, 그중 중요로 표시된 개수인 `important`입니다. `subject`는 키의 레이블이고 `detail`은 최대 3개 값의 이름을 지정합니다. |
| `change`, `similar_incident`, `investigation` | `incident` | 없음. |

수치는 해당 출처의 권한을 보유한 호출자에게만 반환됩니다: `apm.services.read`
`apm`의 경우, `traces` 및 `logs`의 경우 `streams.query`, 또는 `sys.telemetry.read`입니다. 다른 호출자의 경우 `figures`는
생략되며 `withheld`는 `true`입니다. `POST` 응답과 Mole Agent의
`get_incident_rca`에도 동일하게 적용됩니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | `POST` 호출이 조직에 대해 API 키가 있는 활성화된 모델 제공자를 찾지 못했습니다. |
| `403` | 토큰에 해당 호출의 권한이 없습니다. |
| `404` | 인시던트가 존재하지 않거나 `GET` 호출이 아직 분석을 찾지 못했습니다. |
