```http
POST /api/v1/alerts/routing/rules
```

[라우팅 규칙](/ko/alerting/routing#라우팅-규칙)을 생성합니다. `alerts.routing.manage` 권한이 필요합니다. 새 규칙은 목록 맨 끝에 추가합니다. [라우팅 규칙 순서 변경](/ko/api/alerting/reorder-routing-rules)으로 규칙을 위로 이동할 수 있습니다. 조직당 라우팅 규칙은 최대 200개입니다.

| 필드 | 유형 | 설명 |
|---|---|---|
| `name` | string | 필수입니다. 앞뒤 공백을 제거한 후 1~128자여야 합니다. |
| `enabled` | boolean | 기본값은 `true`입니다. |
| `conditions` | array | 최대 16개이며, 기본값은 빈 배열입니다. `key`는 1~512자입니다. `equals`, `not_equals`, `matches`는 각각 값 1개를 받고, `in`은 값 1~100개를 받습니다. 각 값은 최대 512자이며, `matches` 패턴은 컴파일할 수 있어야 합니다. |
| `minSeverity` | string \| null | `info`, `warning`, `error`, `critical` 중 하나입니다. 기본적으로 모든 심각도와 일치합니다. |
| `origins` | array | `rule`, `external`, `synthetic` 중에서 선택합니다. 기본값은 빈 배열이며, 모든 출처와 일치합니다. |
| `target` | object | 필수입니다. `{"kind": "team", "teamId": …}`은 해당 조직의 팀을, `{"kind": "policy", "policyId": …}`은 해당 조직의 에스컬레이션 정책을 지정해야 합니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "conditions": [{"key": "env", "operator": "equals", "values": ["prod"]}], "minSeverity": "error", "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

응답으로 새 규칙을 반환합니다. [규칙 필드](/ko/api/alerting/list-routing-rules#규칙-필드)를 참조합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | 이름이 비어 있거나, 조건의 값 개수가 올바르지 않거나, 패턴을 컴파일할 수 없거나, 대상 팀 또는 정책이 존재하지 않거나, 이미 규칙이 200개 있습니다. |
| `403` | 토큰에 `alerts.routing.manage` 권한이 없습니다. |
| `422` | `name` 또는 `target`이 누락되었거나, 알 수 없는 `operator`와 같이 인식할 수 없는 값이 있습니다. 응답은 일반 텍스트입니다. |
