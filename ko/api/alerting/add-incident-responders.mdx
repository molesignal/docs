```http
POST /api/v1/alerts/incidents/{id}/responders
```

`userIds`에 지정된 사용자를 활성 인시던트의 담당자로 추가하고, 새로 추가된 각 담당자에게 에스컬레이션
알림을 보냅니다. 알림의 `escalation.reason`은 `responder_added`입니다. 인시던트 상태는 그대로 유지하며,
기존 담당자에게는 알림을 다시 보내지 않습니다. 이 호출에는 `alerts.incidents.update` 권한이 필요합니다.

**본문**

| 필드 | 유형 | 필수 | 참고 |
|---|---|---|---|
| `userIds` | 배열 | 예 | 조직 구성원의 사용자 ID 1~10개입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/responders \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"userIds": ["<another-user-id>"]}'
```
</RequestExample>

응답으로 업데이트된 인시던트를 반환합니다. 각 필드에 대한 설명은 [인시던트 목록 조회](/ko/api/alerting/list-incidents)를 참조합니다.

**오류**

| 상태 | 원인 |
|---|---|
| `400` | `userIds`가 비어 있거나, 사용자가 10명을 초과하거나, 조직에 속하지 않은 사용자를 포함합니다. |
| `403` | 토큰에 `alerts.incidents.update` 권한이 없거나 인시던트가 토큰의 접근 범위에 속하지 않습니다. |
| `404` | 인시던트가 존재하지 않습니다. |
| `409` | 인시던트가 복구되었거나 다른 인시던트에 병합되었거나 업데이트 중에 계속 변경되었습니다. 다시 시도합니다. |
