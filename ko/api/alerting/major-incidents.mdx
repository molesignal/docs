영향 범위가 넓고 여러 사람이 대응하는 인시던트는 주요 인시던트로 선언할 수 있습니다. 세 가지 역할을 지정할 수 있고,
워룸(Feishu 또는 Slack 채팅)과 회의를 개설할 수 있으며, 작업 목록도 제공됩니다. 상태 업데이트는 워룸에 게시되고
관련 담당자에게 알림으로 전달됩니다. 조직은 조건에 맞는 새 인시던트를 생성 즉시 주요 인시던트로 선언하는 규칙도
설정할 수 있습니다. 화면에서 이 기능을 사용하는 방법은 [주요 인시던트 및 사후 분석](/ko/alerting/major-incidents)을 참조합니다.

| 메서드 및 경로 | 기능 | 권한 |
|---|---|---|
| `GET /api/v1/alerts/incidents/{id}/response` | 해당 주요 인시던트의 대응 정보와 작업을 조회합니다. | 해당 인시던스에 대한 `alerts.incidents.read` |
| `POST /api/v1/alerts/incidents/{id}/declare` | 주요 인시던트로 선언합니다. | 해당 인시던트에 대한 `alerts.incidents.escalate` |
| `PUT /api/v1/alerts/incidents/{id}/roles` | 역할을 할당하거나 해제합니다. | 해당 인시던트에 대한 `alerts.incidents.update` |
| `POST /api/v1/alerts/incidents/{id}/tasks` | 작업을 추가합니다. | 해당 인시던트에 대한 `alerts.incidents.update` |
| `PUT /api/v1/alerts/incidents/{id}/tasks/{taskId}` | 작업의 제목, 담당자 또는 완료 여부를 변경합니다. | 해당 인시던트에 대한 `alerts.incidents.update` |
| `DELETE /api/v1/alerts/incidents/{id}/tasks/{taskId}` | 작업을 삭제합니다. | 해당 인시던트에 대한 `alerts.incidents.update` |
| `POST /api/v1/alerts/incidents/{id}/status-updates` | 상태 업데이트를 게시합니다. | 해당 인시던트에 대한 `alerts.incidents.update` |
| `GET /api/v1/alerts/response/settings` | 조직의 주요 인시던트 설정을 조회합니다. | `alerts.response.read` |
| `PUT /api/v1/alerts/response/settings` | 조직의 주요 인시던트 설정을 저장합니다. | `alerts.response.manage` |

주요 인시던트 선언, 역할 할당, 워룸 개설, 작업 추가 및 완료, 상태 업데이트 게시 내역은
인시던트의 [타임라인](/ko/api/alerting/incident-timeline)에 기록됩니다. 주요 인시던트 선언과 설정 저장 내역은
감사 로그에도 기록됩니다.

## 주요 인시던트 선언

```http
POST /api/v1/alerts/incidents/{id}/declare
```

| 필드 | 유형 | 필수 여부 | 참고 |
|---|---|---|---|
| `commanderId` | string | 아니요 | 대응 총괄입니다. 생략하면 주요 인시던트를 선언한 사람이 대응 총괄을 맡습니다. |

이미 주요 인시던트로 선언한 인시던트는 그대로 반환합니다. 해결된 인시던트는 주요 인시던트로 선언할 수 없습니다.
주요 인시던트를 선언하면 조직 설정에 따라 다음을 수행합니다.

1. 설정의 체크리스트 항목을 작업으로 추가합니다.
2. `meeting` 설정에 따라 회의를 개설합니다. `feishu_vc`는 Feishu App을 통해 대응 총괄을 소유자로 지정하고
   6시간짜리 Feishu 회의를 예약합니다. `tencentMeeting`은 6시간짜리 Tencent Meeting을 예약하고, `zoom`은 즉석 회의를 시작합니다.
   `googleMeet`는 회의 공간을 만들고, `fixed_url`은 고정 회의 링크를 사용합니다.
3. 설정에 지정한 커넥터(Feishu App, Slack App, DingTalk 또는 WeCom)가 다음 이름으로 그룹 채팅을 만듭니다.
   `[severity] incident summary`. 해당 커넥터에 연결된 계정을 기준으로 인시던트 담당자, 역할을 할당받은 사용자,
   이해관계자를 추가합니다. DingTalk 및 WeCom 그룹은 대응 총괄이 소유합니다. 그룹 채팅에
   인시던트 및 회의 링크가 포함된 시작 메시지를 게시합니다.
4. `onMajorIncident`가 설정된 티켓 커넥터는 [티켓](/ko/api/alerting/tickets)을 생성합니다.

워룸, 회의, 티켓은 가능한 경우에만 생성합니다. 생성에 실패하면 로그에만 기록하며,
주요 인시던트 선언은 유지합니다.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/declare \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"commanderId": "<user-id>"}'
```
</RequestExample>

주요 인시던트 선언, 조회, 역할 할당은 `{ "response": { ... }, "tasks": [ ... ] }`를 반환합니다. 주요 인시던트로 선언하지 않았다면
`response`는 `null`입니다.

<ResponseExample>
```json 200
{
```

| 필드 | 참고 |
|---|---|
| `declaredBy` | 주요 인시던트를 선언한 사용자입니다. 조직 규칙으로 자동 선언한 경우 `null`입니다. |
| `roles` | `commander`(대응 총괄), `communications`(커뮤니케이션 책임자), `scribe`(기록 담당자)를 사용자 ID에 매핑합니다. 할당하지 않은 역할은 포함하지 않습니다. |
| `warRoom` | 워룸 정보입니다. `platform`(`lark_app`, `slackApp`, `dingtalk_app` 또는 `wecom_app`), 커넥터, 채팅 ID, 참여 링크를 포함합니다. DingTalk 및 WeCom 그룹에는 참여 링크가 없어 `url`이 비어 있습니다. 워룸이 없으면 `null`입니다. |
| `meetingUrl` | 회의 링크입니다. 회의가 없으면 `null`입니다. |

## 역할 및 작업

역할을 할당하려면 `{ "role": "scribe", "userId": "<user-id>" }`를 전송합니다. `userId`를 `null`로 설정하면 역할을 해제합니다.
먼저 인시던트를 주요 인시던트로 선언해야 합니다.

작업을 추가하려면 `{ "title": "…", "assigneeId": "<user-id>" }`를 전송합니다. 제목은 1~200자이며,
인시던트당 작업을 최대 50개 추가할 수 있습니다. 작업을 변경할 때는 `title`, `assigneeId`(담당자를 해제하려면 `null`),
`done` 중 변경할 필드만 전송합니다. 작업을 완료하면 `doneBy`와 `doneAt`을 기록합니다. 작업을 추가하거나 변경하면
해당 작업을 반환하고, 삭제하면 `{ "deleted": true }`를 반환합니다.

## 상태 업데이트 게시

```http
POST /api/v1/alerts/incidents/{id}/status-updates
```

| 필드 | 유형 | 참고 |
|---|---|---|
| `impact` | string | 영향입니다. |
| `current` | string | 현재 상황입니다. |
| `next` | string | 다음 조치입니다. |

필드 중 하나 이상에 내용을 입력해야 하며, 각 필드는 최대 2000자입니다. 먼저 인시던트를
주요 인시던트로 선언해야 합니다. 상태 업데이트는 타임라인에 기록하고 워룸에 게시하며,
`incident.status_update` 이벤트로 알림 엔진에 전달합니다. 인시던트 담당자, 역할을 할당받은 사용자 및
설정에 지정한 이해관계자에게 다음 기본 제공 정책으로 알림을 전송합니다.
[주요 인시던트 업데이트: 이해관계자에게 알림](/ko/notification-channels#기본-제공-정책).
이벤트 속성 `status_update`에는 `impact`, `current`, `next`와 작성자 정보인 `author`가 포함됩니다.
`{ "sent": true }`를 반환합니다.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/status-updates \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"impact": "EU checkout failing for 30% of users", "current": "Rolling back v2026.10.28", "next": "Confirm the error rate drops"}'
```
</RequestExample>

## 조직 설정

```http
PUT /api/v1/alerts/response/settings
```

| 필드 | 유형 | 참고 |
|---|---|---|
| `warRoomConnectorId` | string | 워룸을 만드는 알림 커넥터입니다. 그룹 채팅을 생성할 수 있는 `lark_app`, `slackApp`, `dingtalk_app`, `wecom_app` 중 하나를 지정합니다. `null`이면 워룸을 만들지 않습니다. |
| `meeting` | string | `none`(기본값, 회의 없음), `feishu_vc`, `tencentMeeting`, `zoom`, `googleMeet` 또는 `fixed_url`입니다. |
| `meetingUrl` | string | `fixed_url`에서 사용하는 회의 링크입니다. `https://`로 시작해야 합니다. |
| `meetingConnectorId` | string | `feishu_vc`에서 회의를 예약하는 Feishu App 커넥터입니다. `null`이면 워룸 커넥터를 사용하며, 이 경우 워룸 커넥터는 Feishu App이어야 합니다. |
| `tencentMeeting` | object | `tencentMeeting`을 사용하려면 자체 개발 앱의 `appId`, `sdkId`(있는 경우에만), `secretId`와 회의 생성자의 `userid`를 지정해야 합니다. |
| `zoom` | object | `zoom`을 사용하려면 Server-to-Server OAuth 앱의 `accountId`와 `clientId`, 그리고 `host`(이메일 주소 또는 사용자 ID)를 지정해야 합니다. |
| `googleMeet` | object | `googleMeet`를 사용하려면 서비스 계정이 회의를 대신 생성할 주최자의 `organizer`(이메일 주소)를 지정해야 합니다. |
| `secrets` | object | 쓰기 전용입니다. 새로 입력한 회의 시크릿을 `tencentMeeting.secretKey`, `zoom.clientSecret` 또는 `googleMeet.credentials`(서비스 계정의 JSON 키 텍스트)를 키로 사용해 지정합니다. 값을 비워 두면 기존 값을 유지하며, 선택한 회의 유형의 시크릿만 보관합니다. |
| `checklist` | array | 주요 인시던트를 선언할 때 작업으로 추가할 항목입니다. 최대 30개이며, 각 항목은 최대 200자입니다. |
| `stakeholderIds` | array | 이해관계자입니다. 상태 업데이트 알림을 보내고 워룸에 추가합니다. |
| `auto` | object | 자동 선언 설정입니다. `{ "enabled": true, "minSeverity": "critical", "conditions": [ ... ] }`. 심각도가 `minSeverity` 이상이고 레이블이 `conditions`를 충족하는 새 인시던트는 즉시 주요 인시던트로 선언하며, `declaredBy`는 `null`입니다. `conditions`는 [라우팅 규칙](/ko/api/alerting/create-routing-rule)과 같은 형식으로 작성합니다. |

요청 본문에는 전체 설정 객체를 담으며, 저장한 설정을 반환합니다. 설정을 한 번도 저장하지 않았다면
조회 시 기본값을 반환합니다. 시크릿은 루트 키로 암호화하여 저장합니다. 조회 시 시크릿 관련 정보는
설정된 시크릿의 키 목록인 `secretsSet`만 반환합니다. 또한 워룸을 만들 수 있는 커넥터 유형을
읽기 전용 필드 `war_room_types`로 반환합니다.

**오류**

| 상태 | 이유 |
|---|---|
| `400` | 인시던트가 해결되었거나 아직 주요 인시던트로 선언되지 않았습니다. 또는 필드가 허용 범위를 벗어나거나 커넥터가 이 조직의 Feishu App 또는 Slack App이 아닙니다. |
| `403` | 필요한 권한이 없거나 해당 인시던트에 액세스할 수 없습니다. |
| `404` | 인시던트 또는 작업이 존재하지 않습니다. |
