```http
POST /api/v1/alerts/incidents/{id}/resolve
```

상태가 `open` 또는 `acknowledged`인 인시던트 하나를 해결합니다. 호출은 상태를 `resolved`로 설정하고, 호출한 사용자와 호출 시각을 각각 `resolvedBy`와 `resolvedAt`에 기록한 후 에스컬레이션을 중지합니다. 또한 트리거된 알림을 확인 상태로 표시하고 `alert.resolved` 이벤트를 전송합니다. `alerts.incidents.acknowledge` 권한이 필요하며 요청 본문은 비어 있습니다.

인시던트를 해결하면 해당 인시던트에 [병합된](/ko/api/alerting/merge-incidents) 인시던트도 함께 해결합니다. 규칙의 조건이 계속 충족되면 다음 평가에서 새 인시던트가 열립니다. 인시던트를 해결해도 규칙은 비활성화되지 않습니다.

<Note>
  이미 상태가 `resolved` 또는 `closed`인 인시던트를 해결하면 변경 없이 반환합니다. 처음 해결한 사용자와 시각은
  `resolvedBy`와 `resolvedAt`에 그대로 유지되며 이벤트를 다시 전송하지 않습니다.
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/resolve \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**오류**

| 상태 | 원인 |
|---|---|
| `403` | 토큰에 `alerts.incidents.acknowledge` 권한이 없습니다. |
| `404` | 인시던트가 존재하지 않습니다. |
