암호화 키는 스트림에서 암호화 대상으로 지정한 필드를 암호화합니다. 모든 키는 32바이트 AES-256-GCM 키입니다. MoleSignal은 `MS_CIPHER_KEY`의 루트 키로 키 재료를 래핑하며, 키 재료를 반환하지 않습니다. [보안](/ko/security#필드-수준-암호화)을 참조합니다.

새로 암호화하는 값에는 항상 기본 키 `__field_default__`의 최신 버전을 사용합니다. MoleSignal은 스트림에 기본 키가 처음 필요할 때 이 키를 생성합니다. 이름이 지정된 다른 키와 각 키의 이전 버전도 해당 키로 암호화한 값을 계속 복호화할 수 있습니다.

| 작업 | 엔드포인트 | 권한 |
|---|---|---|
| 키 목록 조회 | `GET /api/v1/cipher_keys` | `org.cipher_keys.read` |
| 키 조회 | `GET /api/v1/cipher_keys/{name}` | `org.cipher_keys.read` |
| 키 생성 | `POST /api/v1/cipher_keys` | `org.cipher_keys.manage` |
| 키 교체 | `POST /api/v1/cipher_keys/{name}/rotate` | `org.cipher_keys.rotate` |
| 키 삭제 | `DELETE /api/v1/cipher_keys/{name}` | `org.cipher_keys.manage` |
| 기본 키 교체 | `POST /api/v1/field_encryption/rotate` | `org.cipher_keys.rotate` |

## 키 메타데이터

목록 조회, 키 조회, 생성 및 교체 호출은 키 버전의 메타데이터를 반환합니다. 목록 조회는 모든 키의 모든 버전을 반환하며, 같은 이름 내에서는 최신 버전을 먼저 반환합니다.

```json
{
  "id": "3KEZizkQsvBwoWQihNO6OdxRiSf",
  "name": "payments-key",
  "alg": "aes-256-gcm",
  "version": 1,
  "createdAt": 1790000000000000,
  "rotatedAt": null
}
```

교체한 적이 없는 키의 `rotatedAt` 값은 `null`입니다. 키 조회 호출은 최신 버전을 반환합니다.

## 키 생성

```http
POST /api/v1/cipher_keys
```

| 필드 | 유형 | 필수 | 참고 |
|---|---|---|---|
| `name` | string | 예 | 키 이름입니다. 이미 존재하는 이름을 지정하면 `409`를 반환하고 메시지에서 키 교체 호출을 안내합니다. |
| `keyMaterialB64` | string | 예 | 패딩을 포함한 표준 base64로 인코딩한 32바이트의 무작위 데이터입니다. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/cipher_keys \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "{\"name\": \"payments-key\", \"key_material_b64\": \"$(openssl rand -base64 32)\"}"
```
</RequestExample>

응답은 위에 표시된 키 메타데이터입니다.

## 키 교체

```http
POST /api/v1/cipher_keys/{name}/rotate
```

요청 본문에는 키 생성 호출과 마찬가지로 `keyMaterialB64`를 넣습니다. 이 호출은 새 키 재료로 버전을 추가하고, 복호화를 위해 이전 버전을 유지합니다. 존재하지 않는 이름을 지정하면 `404`를 반환합니다. 먼저 키 생성 호출로 키를 생성합니다.

## 키 삭제

```http
DELETE /api/v1/cipher_keys/{name}
```

지정한 이름의 키 버전을 모두 삭제하고 `{"deleted": true}`를 반환합니다. 존재하지 않는 이름을 지정하면 `404`를 반환합니다. 이 호출은 저장된 데이터가 여전히 해당 키에 의존하는지 확인하지 않습니다.

<Warning>
  삭제한 키로 암호화한 값은 다시 복호화할 수 없습니다. 키를 삭제하기 전에
  해당 키에 의존하는 암호화된 필드를 확인합니다.
</Warning>

## 기본 키 교체

```http
POST /api/v1/field_encryption/rotate
```

서버에서 새 키 재료를 생성하고 `__field_default__`의 새 버전을 추가한 뒤 복호화 캐시를 즉시 갱신합니다. 새로 기록하는 값에는 새 버전을 사용하며, 기존 값은 계속 읽을 수 있습니다. 조직에 기본 키가 아직 없으면 이 호출이 버전 1로 기본 키를 생성합니다. 요청 본문은 비어 있으며, 응답에는 새 키의 식별자와 버전이 포함됩니다.

```json
{
  "keyId": "3KEZj3uxMx5OOFX6NiYv3VFnfmD",
  "version": 2
}
```

**오류**

| 상태 | 원인 |
|---|---|
| `400` | `keyMaterialB64`가 유효한 base64가 아니거나 디코딩한 결과가 정확히 32바이트가 아닙니다(`key_material must be 32 bytes, got 5`). |
| `403` | 토큰에 이 호출에 필요한 권한이 없습니다. |
| `404` | 조회, 교체 또는 삭제 호출에서 해당 이름의 키를 찾지 못했습니다. |
| `409` | 해당 이름의 키가 이미 존재합니다. |
| `422` | 필수 필드가 누락되었습니다. 응답은 일반 텍스트입니다. |
