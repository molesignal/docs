```http
PUT /api/v1/streams/{id}/settings
```

스트림의 데이터 보존 기간과 설정을 업데이트합니다. 변경할 속성만 전송합니다. 이 호출에는 `streams.configure` 권한이 필요합니다. `_audit` 스트림에는 `audit.read` 권한도 필요하며, 이 권한이 없으면 `403`을 반환합니다. `_molesignal` 시스템 스트림에는 `sys.telemetry.manage` 권한이 필요하며, 데이터 보존 기간, 필드 인덱스, 추출, 마스킹, 다운샘플링만 변경할 수 있습니다.

**본문**

| 필드 | 유형 | 비고 |
|---|---|---|
| `retentionDays` | 정수 또는 `null` | 1~3650일입니다. `null`을 지정하면 명시적으로 설정한 값을 지우고 **설정 → 데이터 보존**의 플랫폼 기본값을 상속합니다. 범위를 벗어난 값을 지정하면 `400`을 반환합니다. |
| `settings` | 객체 | 스트림 설정입니다. 아래를 참조합니다. |
| `fields` | 배열 | 필드 인덱스입니다. [필드 인덱스 구성](/ko/api/streams/edit-schema)을 참조합니다. |

설정:

| 설정 | 비고 |
|---|---|
| `description` | 웹 UI에 표시하는 자유 형식의 텍스트입니다. |
| `queryable` | `false`로 설정하면 스트림은 데이터를 계속 수신하고 보존하지만 쿼리 선택 목록에는 표시되지 않습니다. 이 스트림에 대한 쿼리는 `403`(`stream is not queryable`)을 반환합니다. |
| `maxQueryRangeHours` | 스트림에 대한 단일 SQL 또는 PromQL 쿼리가 조회할 수 있는 최대 시간 범위입니다. 1~87600시간을 지정할 수 있습니다. 이 범위를 초과하는 쿼리는 `400`을 반환합니다. `null`을 지정하면 제한을 해제합니다. |
| `fieldMasking` | 전역 [필드 마스킹](/ko/settings#데이터-보안) 규칙을 스트림 수준에서 재정의합니다. |
| `indexPatterns` | 필드가 처음 나타날 때 인덱스를 생성하는 규칙입니다. `[{ "pattern": "*_id", "indexType": "exact" }]`처럼 최대 32개를 지정할 수 있습니다. `*`는 임의 길이의 문자열을, `?`는 문자 하나를 나타냅니다. 필드 이름으로 직접 지정한 인덱스가 우선합니다. 직접 지정한 인덱스가 없으면 패턴이 필드 이름과 일치하고 `indexType`이 필드의 데이터 유형에 맞는 첫 번째 규칙을 적용합니다. 패턴은 1~128자이며 서로 달라야 합니다. [새 필드 인덱싱](/ko/streams#새-필드-인덱스)을 참조합니다. |
| `dailyMerge` | 로그와 트레이스에만 적용합니다. 기본값인 `true`로 설정하면 하루가 끝난 지 한 시간 후에 해당 날짜의 파일을 하나로 병합합니다. 파일의 전체 크기가 `[compactor].target_size` 이하여야 병합합니다. 병합 후에는 일 단위로 데이터 보존 기간을 적용합니다. `false`로 설정하면 시간 단위 파일을 유지합니다. |
| `partitions` | 로그와 트레이스에만 적용합니다. `[{ "field": "service", "type": "hash", "buckets": 4 }, { "field": "pod", "type": "prefix" }]`처럼 분할 필드를 최대 2개 지정할 수 있습니다. `hash`는 값의 해시를 기준으로 `buckets`개의 샤드(2~64개)로 나누고, `prefix`는 값의 첫 문자를 기준으로 샤드 37개로 나눕니다. 이후 기록하는 데이터를 이 필드로 분할합니다. 두 필드의 샤드 수를 곱한 값이 256 이하여야 하며, 두 필드는 서로 달라야 합니다. 스키마에 이미 있는 필드는 암호화하지 않은 `utf8` 필드여야 합니다. 기본값인 빈 목록은 분할하지 않음을 뜻합니다. [필드별 분할](/ko/streams#필드별-분할)을 참조합니다. |
| `clustering` | 로그에만 적용합니다. `{ "fields": ["service", "level"], "interval": 60000000 }`은 이후 기록하는 각 파일의 행을 `interval` 마이크로초 단위의 시간 구간으로 나누고 최신 구간부터 배치합니다. 각 구간에서는 `fields`의 값으로 먼저 정렬한 다음 최신 행부터 배치합니다. 서로 다른 필드를 최대 2개 지정할 수 있습니다. 스키마에 이미 있는 필드는 암호화하지 않은 `utf8`, `int64` 또는 `bool` 필드여야 합니다. `interval`은 1초~1시간이며 1시간을 나머지 없이 나눌 수 있어야 합니다. 기본값은 1분입니다. 기본값처럼 필드를 지정하지 않으면 행을 시간순으로 유지합니다. [필드별 클러스터링](/ko/streams#필드별-클러스터링)을 참조합니다. |
| `indexChangedAt` | 읽기 전용입니다. 기존 필드의 인덱스 유형이 마지막으로 변경된 시각입니다. 서버가 이 값을 설정하고, 이 시각 전에 인덱싱한 파일을 백그라운드에서 다시 인덱싱합니다. |
| `downsample` | 메트릭에만 적용합니다. `{ "afterDays": 7, "intervalSecs": 300 }`은 `afterDays`일보다 오래된 샘플을 `intervalSecs`초 단위 버킷으로 집계합니다. 같은 버킷에 있는 한 시계열의 샘플을 하나의 데이터 포인트로 합치고, 값은 평균을 내고 델타 카운트는 합산한 뒤 원본 샘플을 삭제합니다. `afterDays`는 0~3650이며, 기본값인 `0`은 다운샘플링을 비활성화합니다. `intervalSecs`는 60 이상이며 하루를 나머지 없이 나눌 수 있어야 합니다. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/streams/$STREAM_ID/settings \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "retentionDays": 30,
    "settings": { "description": "Application logs", "queryable": true }
  }'
```
</RequestExample>

응답은 업데이트된 스트림을 반환합니다. 데이터 보존 기간과 다운샘플링 설정은 컴팩터가 데이터를 삭제하거나 집계할 시점을 결정합니다. 변경 사항은 이후 정리 작업에만 적용하며, 이미 삭제한 파일이나 샘플은 복원하지 않습니다.

자체 데이터 보존 기간이 없는 스트림에 적용할 플랫폼 기본값은 `GET /api/v1/settings/stream_retention`으로 조회합니다. 기본값을 설정하려면 `PUT`과 동일한 형식의 본문 `{ "retentionDays": 30 }`을 사용합니다. 두 요청 모두 시스템 범위의 `sys.settings.retention.manage` 권한이 필요합니다. `retentionDays`는 1~3650 사이의 정수입니다.

동일한 권한과 범위에서 `GET /api/v1/settings/stream_retention/preview?retentionDays=7`을 호출하면 기본 데이터 보존 기간을 줄일 때 삭제할 데이터를 추정합니다. 실제 데이터는 읽지 않고 파일 카탈로그만 읽으므로 응답에 `"estimated": true`를 표시합니다. `rows`, `storedBytes`, `earliestAt`은 이 변경만으로 삭제할 데이터의 전체 행 수, 저장 바이트 수, 가장 이른 시각을 나타냅니다. `streamCount`는 영향을 받는 스트림 수를 나타냅니다. `streams`는 규모가 가장 큰 스트림을 최대 100개까지 나열하고 각 스트림의 동일한 수치와 소속 조직을 표시합니다. `unavailableStreams`는 카탈로그 항목을 읽을 수 없었던 스트림 수를 나타냅니다. 자체 데이터 보존 기간이 있는 스트림과 데이터 세트는 집계에서 제외합니다. `retentionDays`가 현재 기본값 이상이면 응답의 집계 값이 0입니다. 세션 리플레이와 프로파일 아카이브에도 동일한 설정을 적용하지만 집계에는 포함하지 않습니다.
