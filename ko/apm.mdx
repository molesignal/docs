MoleSignal APM은 백엔드 OpenTelemetry 트레이스 스팬을 제한된 RED 집계로 변환하여 느린
서비스, 실패하는 엔드포인트, 비용이 큰 종속성, 반복되는 백엔드 오류, 배포된 버전 간의
회귀를 별도의 메트릭 계측 없이 찾을 수 있게 합니다. 서비스 카탈로그에는 각 서비스의 소유자와
중요도가 기록됩니다.

<Note>
  APM은 또 다른 SDK나 텔레메트리 스트림이 필요하지 않습니다. 계측이 잘 된 트레이스를 보내면
  MoleSignal이 트레이스 중복 제거 후, 테일 샘플링 전에 APM 데이터를 도출합니다. 나중에
  샘플링에서 제외된 트레이스도 APM 메트릭에 기여할 수 있고,
  [실시간 파이프라인](/ko/pipelines#트레이스)에서 버린 스팬도 마찬가지입니다.
</Note>

## 페이지

APM은 개요 페이지에서 열립니다. 각 서비스에는 자체 페이지가 있습니다.

| 페이지 | 용도 |
|---|---|
| **개요** | 모든 서비스를 한데 모아 보여 줍니다: 활성 서비스, 처리량, 오류율, p95와 p50, p90, p99 및 평균, Apdex; 서비스 상태의 분포와 변화; 가장 느린 서비스, 가장 많이 실패하는 서비스, 가장 바쁜 서비스; 이전 기간 및 일주일 전 같은 기간 대비 무엇이 변했는지, 그 무렵의 변경 사항, 시간을 되찾을 수 있는 지점에 대한 인사이트; 서비스를 지정하는 활성 알림; 기간 내 배포된 버전; 환경; 서비스가 계측에서 제외하는 항목. |
| **서비스** | 서비스 카탈로그: APM이 인식하는 모든 서비스와 선언된 모든 서비스를 소유자, 티어, 태그, 진행 중인 알림, 처리량, 오류율, 지연 시간, 버전, 마지막 배포와 함께 보여 줍니다. 즐겨찾기가 먼저 표시되며, 보관된 서비스는 표시하도록 선택할 때까지 제외됩니다. |
| **서비스 맵** | 한 환경의 서비스와 서비스 간 호출, 서비스가 호출하는 대상, 게시하고 소비하는 토픽; 이전 기간 대비 새로 생기거나 사라진 호출. [APM 서비스 맵](/ko/apm/service-map#apm-서비스-맵)을 참고하십시오. |
| **오류** | 모든 서비스의 백엔드 오류 그룹을 상태, 팀, 담당자, 발생 위치, 그룹화 규칙과 함께 보여 줍니다. |
| **SLO** | 서비스 수준 목표와 각 목표가 기간 동안 달성한 값, 남은 오류 예산, 예산 소진 속도, 상태를 보여 줍니다. |
| **설정** | 조직의 상태 기준, 기본 Apdex 임계값, 장기 작업, 카탈로그 요구 사항, 이름 지정 규칙, 환경 매핑, 별칭 및 이에 대한 지난 하루 데이터의 분석 결과; 플랫폼의 카디널리티 한도와 트레이스 샘플링을 보여 줍니다. [APM 설정](/ko/apm/settings)을 참고하십시오. |

서비스 페이지에는 다음 섹션이 있습니다:

| 섹션 | 용도 |
|---|---|
| **개요** | 요청, 오류율, 지연 시간을 나란히 보여 주고, 서비스 인사이트, 서비스의 SLO, 비즈니스 키가 선언된 경우 [비즈니스 키](/ko/business-context)별로 분할한 요청, 지연 시간 분포, 다운스트림에 소요된 시간, 가장 큰 비중을 차지하는 엔드포인트와 오류를 보여 줍니다. |
| **엔드포인트** | HTTP, RPC, 메시징, 워커 진입점을 요청, 오류, 지연 시간 또는 시간 점유율 기준으로 순위화합니다. 엔드포인트를 열면 상태 코드, 시간이 어디에 쓰이는지, 가장 느린 요청을 보여 주는 드로어가 열립니다. 별표는 주요 트랜잭션을 표시하며, 목록에는 해당 트랜잭션만 또는 장기 작업만 표시할 수 있습니다. |
| **트레이스** | 서비스가 참여한 트레이스를 트레이스 페이지의 트레이스 테이블에 표시합니다. |
| **종속성** | 서비스를 호출하는 서비스, 대상별로 그룹화된 외부 호출과 각 대상 아래의 작업, 각 대상의 상태, 시간 초과되었거나 다시 전송된 호출, 가장 느린 SQL 문을 보여 줍니다. |
| **오류** | 서비스의 오류 그룹을 보여 줍니다. |
| **배포** | 파이프라인이 보고한 내용과 스팬이 전달한 버전, 롤백으로 명시된 항목, 각 버전과 이전 버전의 비교, 동시에 실행 중인 두 버전의 나란한 보기, 두 버전의 비교를 보여 줍니다. [배포](/ko/apm/deployments)를 참고하십시오. |
| **런타임** | 서비스를 실행한 인스턴스와 각 인스턴스가 처리한 내용, 프로세스 및 서비스 언어의 런타임 메트릭 차트, 프로필에서 생성한 플레임 그래프를 보여 줍니다. |
| **설정** | 서비스의 카탈로그 항목과 주요 트랜잭션을 인스턴스가 보고한 내용과 함께 보여 줍니다. |

서비스 이름 뒤의 줄은 서비스가 무엇인지 보여 주며, 현재 보기 중인 환경과 버전을
따릅니다:

| 항목 | 출처 |
|---|---|
| 상태 | 해당 기간의 RED 지표이며, 가리키면 이유를 함께 표시합니다. 요청이 없는 기간에는 대신 **이 기간에 데이터가 없습니다**라는 메시지가 표시됩니다. 텔레메트리가 없다고 해서 서비스가 비정상인 것은 아닙니다. |
| 티어 | 카탈로그 항목입니다. |
| 시스템 및 환경 | `service.namespace` 및 `deployment.environment.name`. |
| 유형 | 서비스가 처리하는 진입 스팬: **HTTP**, **RPC**, 메시지용 **컨슈머**, 내부 진입 스팬용 **워커**. |
| 언어 및 프레임워크 | `telemetry.sdk.language`, 그리고 Axum, Spring, Express 등 서비스 진입 스팬의 계측 라이브러리입니다. |
| 버전 | 선택한 버전 또는 기간 동안 인스턴스가 실행한 모든 버전이며, 가장 많이 실행된 버전부터 표시합니다. 롤아웃 중에는 두 버전이 모두 표시됩니다. |
| 팀 | 카탈로그 항목입니다. 팀을 가리키면 소유자와 온콜 담당자가 표시됩니다. |
| 인스턴스 | 현재 보기 중인 버전의 인스턴스 중 기간 내에 보고한 인스턴스입니다. **런타임**을 엽니다. |
| 마지막 배포 | 현재 보기 중인 버전 또는 최신 버전이 처음 확인된 시점입니다. |
| 리전 | 인스턴스의 `cloud.region`입니다. |
| 리포지토리 | 인스턴스의 `vcs.repository.url.full` 또는 `git.repository_url`이며, 없으면 카탈로그 항목의 리포지토리입니다. |
| 다른 이름 | 카탈로그 항목의 다른 이름입니다. 첫 번째 이름과 추가 이름 개수를 표시합니다. |

보관된 서비스는 해당 위치에 **보관됨**도 표시합니다. 제목 행 끝의 **즐겨찾기**를 사용하면
서비스를 즐겨찾기 목록에 유지할 수 있습니다.

탐색 카드의 끝에는 서비스의 로그, 메트릭, 프로필 링크가 있습니다. 각 링크는
현재 보기 기간의 종료 시점 이전 하루 동안 해당 신호에 서비스가 포함되어 있을 때 켜지며, MoleSignal은
5분마다 다시 확인합니다:

| 신호 | 켜지는 조건 |
|---|---|
| 로그 | `service.name`, `service_name` 또는 `service` 필드가 있는 로그 스트림에 서비스의 로그 라인이 포함되어 있습니다. 링크를 열면 해당 스트림에서 로그가 열립니다. |
| 메트릭 | 지난 한 시간의 시리즈에 서비스의 `service.name`이 포함되어 있습니다. |
| 프로필 | 프로필 스트림에 서비스의 프로필이 포함되어 있습니다. |
| RUM | 브라우저 세션이 서비스의 샘플 트레이스 중 하나를 생성한 경우입니다. 이때만 링크가 표시되며, 해당 세션을 엽니다. |

데이터가 없는 신호는 흐리게 표시되며, 해당 신호를 연결하는 **데이터 소스** 페이지를 엽니다. 조회가 실패하거나
3초보다 오래 걸리면 링크는 켜지지도, 흐리게 표시되지도 않습니다.

## 사전 요구 사항

- MoleSignal [트레이스 수집 엔드포인트](/ko/intake)로 전송된 OpenTelemetry 트레이스;
- 조직 워크스페이스의 `apm.services.read` 권한; 또는
- 보호된 `_sys` 텔레메트리를 위한 `sys.telemetry.read` 권한.

## APM용 서비스 계측

<Steps>
  <Step title="안정적인 서비스 리소스 속성 설정">
    모든 서비스에 `service.name`을 설정합니다. 서비스 필터링 또는 배포 비교를 위해 네임스페이스, 환경, 버전 및 인스턴스
    속성을 추가합니다.

    ```bash
    export OTEL_SERVICE_NAME=checkout
    export OTEL_RESOURCE_ATTRIBUTES="service.namespace=shop,deployment.environment.name=production,service.version=2.4.0,service.instance.id=checkout-01"
    ```

    정확한 설정은 선택한 OpenTelemetry SDK 또는 Collector에 따라 달라집니다.
  </Step>
  <Step title="올바른 스팬 종류 사용">
    인바운드 요청에는 `SERVER` 스팬을, 소비된 메시지에는 `CONSUMER` 스팬을 생성합니다. 다운스트림 호출에는
    `CLIENT` 또는 `PRODUCER` 스팬을 생성합니다. MoleSignal은 이러한 스팬 종류를 사용해
    트랜잭션과 종속성을 분리합니다.
  </Step>
  <Step title="상태 및 예외 기록">
    OpenTelemetry 스팬 상태, HTTP 또는 RPC 상태 속성 및 예외 이벤트를 설정합니다. MoleSignal은
    기록된 상태 데이터를 사용해 성공 및 실패 작업을 분류하고 백엔드 오류 그룹을 생성합니다.
  </Step>
  <Step title="트레이스 전송 및 APM 열기">
    OTLP 트레이스를 전송한 다음 **APM → 서비스**를 엽니다. 프로젝터가 첫 버킷을 플러시하는 동안
    전역 시간 범위를 최근 트래픽 구간으로 유지합니다.
  </Step>
</Steps>

### 권장 리소스 속성

| 속성 | 목적 | 대체값 |
|---|---|---|
| `service.name` | 안정적인 서비스 ID입니다. 모든 서비스에 명시적으로 설정합니다. | `unknown_service` |
| `service.namespace` | 시스템 또는 팀 간에 이름이 같은 서비스를 구분합니다. | `default` |
| `deployment.environment.name` | 프로덕션, 스테이징 및 기타 환경을 필터링합니다. | 레거시 `deployment.environment`, 그다음 `unknown` |
| `service.version` | 버전 기록 및 배포 비교를 활성화합니다. | 버전 세분화 없음 |
| `service.instance.id` | 인스턴스를 구분합니다. | `k8s.pod.name`, 그다음 `host.name` |
| `telemetry.sdk.language` | 서비스 카탈로그에 런타임 언어를 표시합니다. | 존재하는 경우 `process.runtime.name` |
| `cloud.region`, `k8s.*`, `host.name`, `container.name`, `container.id` | 각 인스턴스가 실행되는 위치를 나타냅니다. | 표시되지 않음 |
| `process.runtime.name`, `process.runtime.version` | 각 인스턴스의 런타임을 표시합니다. | 표시되지 않음 |
| `vcs.repository.url.full`, `vcs.ref.head.revision` | 리포지토리를 연결하고 커밋 이름을 지정합니다. `git.repository_url` 및 `git.commit.sha`도 작동합니다. | 카탈로그 항목의 리포지토리 |

Kubernetes 속성과 `cloud.region`은 일반적으로 SDK가 아니라 OpenTelemetry Collector의
`k8sattributes` 및 `resourcedetection` 프로세서에서 추가합니다.

카디널리티가 낮은 값을 사용합니다. 요청 ID, 원시 URL, 사용자 ID 또는 기타 범위가 제한되지 않은 값을
서비스, 환경, 버전, 라우트, 오퍼레이션 또는 종속성 속성에 넣지 않습니다.

## MoleSignal이 APM 데이터를 도출하는 방법

### 서비스 및 엔드포인트

`SERVER` 및 `CONSUMER` 스팬은 서비스 및 엔드포인트 RED 메트릭에 기여합니다. API에서는 엔드포인트를 트랜잭션이라고 합니다. 부모가 없는 스팬은
종류가 없을 때 호환성 대체 수단으로 서비스 합계에 기여할 수 있지만, 명시적인 스팬
종류는 더 완전한 페이지를 생성합니다.

MoleSignal은 시맨틱 속성으로 범위가 제한된 엔드포인트 이름을 생성합니다:

- HTTP 메서드에 `http.route`를 더한 값(예: `POST /checkout`);
- RPC 서비스에 메서드를 더한 값;
- 메시징 오퍼레이션에 대상을 더한 값;
- 더 강한 시맨틱 ID가 없을 때 안전하고 카디널리티가 낮은 스팬 이름.

`/orders/83921` 같은 원시 경로보다 `/orders/{id}` 같은 라우트 템플릿을 선호합니다.

### 종속성

`CLIENT` 및 `PRODUCER` 스팬은 종속성 RED 메트릭에 기여합니다. MoleSignal은 대상을
서비스, 데이터베이스, 캐시, 메시징 시스템, 외부 HTTP 엔드포인트, 외부 RPC 엔드포인트 또는 기타
종속성으로 분류합니다. 표준 `peer.service`, `db.*`, `messaging.*`, `rpc.*`, `server.*` 및 HTTP 시맨틱
속성은 종속성 ID를 개선합니다.

`peer.service`가 없는 데이터베이스 또는 캐시 호출은 해당 시스템을 대상으로 합니다. 예: `postgresql` 또는
`redis`. [`MS_TRACE_FINGERPRINT_KEY`](/ko/configuration#환경-변수)가 설정되면 대상에는
`db.namespace`(없으면 `db.name` 또는 `db.collection.name`)의 키 기반 지문도 포함됩니다. 예:
`postgresql:<fingerprint>`. 이렇게 하면 한 시스템의 데이터베이스를 이름을 저장하지 않고도
구분할 수 있습니다.

SQL 데이터베이스 호출의 오퍼레이션은 문을 템플릿으로 사용한 값입니다: `db.query.summary`, 없으면
`db.query.text` 또는 `db.statement`이며, 모든 리터럴은 `?`로 바뀌고, 주석은 제거되며, 값 목록은
하나의 `?`로 축소되고, 최대 512 bytes만 유지됩니다. 큰따옴표 안의 텍스트는 다음 경우에만 유지됩니다.
테이블 또는 열의 이름을 지정하는 데이터베이스(예: PostgreSQL 및 Oracle)입니다. 그 외의 경우에는 값입니다. 문이 없는 호출은
`db.operation.name`을 유지하고, 캐시 호출은 해당 명령을 유지합니다. 서비스는 한 대상의 오퍼레이션을 시간당 최대 32개까지
유지합니다. 그 이상은 같은 대상 아래 **기타**로 함께 집계됩니다.

시간 초과된 요청(시간 초과 오류 유형, gRPC `DEADLINE_EXCEEDED`, HTTP 408 또는 504)과
다시 전송된 요청(`http.request.resend_count`가 0보다 큼)은 RED 메트릭과 함께 집계됩니다.

### 오류

MoleSignal은 예외가 존재하거나 OpenTelemetry 상태가
`ERROR`이거나, HTTP 상태가 500 이상이거나, RPC 상태가 0이 아닐 때 스팬을 오류로 분류합니다. 오류 그룹은
오류 유형, 첫 번째 애플리케이션 스택 프레임 및 트랜잭션 이름을 기반으로 하는 안정적인 지문을 사용합니다.
변경되는 오류 메시지는 지문에 포함되지 않습니다. [그룹화 규칙](#오류를-규칙으로-그룹화)은
오류를 하나의 그룹으로 병합하거나 그룹에서 제외할 수 있습니다.

## RED 메트릭 이해

| 메트릭 | 의미 |
|---|---|
| **요청 수** | 일치하는 서비스, 엔드포인트 또는 종속성 관측 수입니다. |
| **오류율** | 오류 수를 요청 수로 나눈 값입니다. |
| **지연 시간** | 병합된 지연 시간 히스토그램에서 읽은 p50, p90, p95, p99 및 평균 기간입니다. |
| **Apdex** | 임계값 T 내의 요청 수에 4T 내 요청 수의 절반을 더한 값을 전체 요청 수로 나눈 값입니다. T는 조직의 기본값인 500 ms이며, [APM 설정](/ko/apm/settings#상태-및-임계값)에서 변경하지 않는 한 이 값이 사용되고, 서비스 카탈로그 항목이 설정한 T가 있으면 해당 T가 사용됩니다. 사용 중인 T는 지연 시간 분포에 표시됩니다. 개요에서는 조직의 기본값으로 모든 서비스를 함께 조회합니다. 실패한 요청은 만족으로 처리되지 않습니다. 실패는 지연 시간 전반에 균등하게 분산됩니다. |
| **총 시간** | 관측된 기간의 합계이며, 집계 영향이 가장 큰 작업을 강조합니다. |

서비스는 오류율 2% 또는 p95 500 ms부터 **경고** 상태가 되고, 10% 또는 2 s부터 **심각** 상태가 됩니다.
[APM 설정](/ko/apm/settings#상태-및-임계값)에서 다른 기준을 정하지 않는 한 그렇습니다. 서비스 페이지와
카탈로그의 점은 어떤 수치가 어떤 기준을 넘었는지 알려줍니다.

**인사이트** 카드는 이전의 같은 길이 구간과
일주일 전의 같은 길이 구간을 기준으로 어떤 서비스가 움직였는지 보여줍니다. [인사이트가 찾는 내용](/ko/apm/insights#인사이트가-찾는-항목)을 참조합니다.

지연 시간 히스토그램은 지연 시간이 두 배가 될 때마다 125 µs에서 약 131 s까지를 8개 버킷으로 나누며,
백분위수는 해당 버킷 내에서 읽습니다. 백분위수는 정확한 값의 약 4% 이내입니다. 집계는
이전 고정 버킷으로 작성된 경우에도 더 거친 정밀도로 계속 읽을 수 있습니다.

개요와 엔드포인트 드로어의 **비교 대상** 컨트롤은 하루 전 또는
일주일 전의 동일한 범위를 점선으로 그리며, 지연 시간 분포는 해당 범위의 분포를 윤곽으로 표시합니다.
서비스 페이지에서는 서비스의 다른 환경도 나열합니다. 해당 환경의 동일한 범위는
대신 점선으로 그립니다.

엔드포인트의 가장 느린 요청은 트레이스 저장소에서 가져오므로, 목록의 모든 요청은 해당
트레이스를 엽니다. 오류 샘플은 테일 샘플링에서 삭제된 트레이스를 가리킬 수 있으며, 이 경우 트레이스 드로어는
트레이스를 찾을 수 없다고 표시합니다.

## 서비스 카탈로그

카탈로그에는 APM이 확인하는 모든 서비스가 서비스 및 환경당 한 행으로 나열되며, 보고하기 전에
등록된 모든 서비스도 포함됩니다. 카탈로그에서 **서비스 등록**을 하고 서비스 페이지의 **설정** 섹션에서
다음을 기록합니다:

| 필드 | 의미 |
|---|---|
| **담당 팀** | 워크스페이스의 팀입니다. 팀의 첫 번째 활성 온콜 일정이 누가 온콜인지 나타냅니다. |
| **소유자** | 서비스에 대해 책임지는 워크스페이스 구성원입니다. |
| **등급** | 가장 중요한 서비스인 P0부터 P5까지입니다. |
| **수명 주기** | 프로덕션, 스테이징, 실험용 또는 지원 중단입니다. |
| **리포지토리** | 코드가 위치한 곳으로, 서비스가 리포지토리를 보고하지 않을 때 사용됩니다: https 주소 또는 `git@github.com:acme/checkout.git`나 `ssh://git@git.example.com/team/checkout.git` 같은 git 주소입니다. 주소의 비밀번호는 `****`로 유지되며, git이 토큰을 전달하는 https 주소의 사용자 부분도 마찬가지입니다. 서비스 페이지는 git 주소를 동일한 경로의 https 페이지로 엽니다. |
| **태그** | 쉼표로 구분된 `key=value` 쌍 또는 키 단독입니다. 키는 최대 64자의 소문자, 숫자 및 `_ . - /`로 구성되며, 값은 최대 128자입니다. 최대 32개입니다. |
| **Apdex 임계값 T** | 서비스 Apdex의 임계값(밀리초)이며 최대 1분입니다. 비워 두면 조직의 기본값을 사용하며, APM 설정에서 변경하지 않는 한 500ms입니다. |
| **서비스 설명** | 서비스 이름 아래에 표시되는 짧은 설명입니다. |
| **다른 이름** | 로그, 메트릭 및 기타 시스템에서 서비스를 부르는 이름이며 쉼표로 구분됩니다(예: `order_service` 또는 Order Center). 최대 20개이며 각 이름은 최대 128자입니다. 이름은 서비스 자체의 이름이 될 수 없고, 다른 서비스의 이름이나 다른 이름이 될 수도 없습니다. 카탈로그 검색에서도 이 이름으로 서비스를 찾습니다. |
| **데이터 소스** | 서비스의 로그를 보관하는 로그 스트림과, 스트림에서 해당 로그를 선택하는 선택적 SQL 조건; `{service="checkout"}` 같은 메트릭의 PromQL 선택자; 서비스를 표시하는 대시보드; 그리고 런북이나 CMDB 항목 같은 외부 페이지 링크입니다. 각각 최대 10개입니다. 각 행은 데이터를 **로그**, **메트릭**, 대시보드 또는 새 탭에서 엽니다. |

**다른 이름**과 **데이터 소스**는 사람뿐 아니라 Mole Agent에도 유용합니다. Mole Agent가
서비스에 대해 질문을 받으면 두 항목이 포함된 카탈로그 항목을 읽고, 다른 이름 중 하나에 대한
APM 질문은 그 이름이 속한 서비스를 읽습니다. 데이터를 병합하지는 않습니다. 이전 서비스 이름으로 보고된 내용을
서비스 자체의 것으로 읽으려면 대신 [서비스 별칭](/ko/apm/settings#서비스-별칭)을 추가합니다.

같은 양식의 **보관**은 서비스를 카탈로그의 기본 보기에서 제외합니다. 데이터는 계속
수집되고 페이지도 계속 열립니다. 카탈로그의 **보관됨**은 보관된 서비스도 나열합니다.

[카탈로그 요구 사항](/ko/apm/settings#카탈로그-요구-사항)은 특정 등급 이상의 서비스에 팀, 소유자 또는 리포지토리를
요구합니다. 하나라도 부족한 서비스는 카탈로그에서 누락된 항목과 함께
**필요**로 표시됩니다.

정의는 네임스페이스와 이름을 키로 사용하므로 모든 환경에 적용됩니다. 카탈로그와 엔드포인트 표의 **열** 메뉴에서
열을 선택하고 순서를 지정할 수 있으며, 이 배열은 사용자별로 유지됩니다. 수치와 카탈로그 필드 외에도
카탈로그는 범위 내 인스턴스에서 읽은 **유형**,
**언어 / 프레임워크**, **인스턴스**, **리전**, 그리고
**태그**와 **마지막 발생**을 제공합니다.

기본적으로 표시되는 **상관관계**는 서비스가 나머지 데이터와 연결되는 각 방식을 점으로 표시합니다:
로그의 트레이스 ID, 리소스 속성, 메트릭, 보고된 변경 사항입니다. 녹색은 잘 연결됨,
노란색은 부분 연결, 회색은 연결 없음, 가장 흐린 점은 읽을 수 없음을 뜻합니다. 점 위에 마우스를 올리면
그 뒤의 수치를 알 수 있습니다. [수집 품질](/ko/apm/settings#수집-품질)은 수정할 항목을 나열합니다.

카탈로그 행의 별표를 누르면 서비스가 사용자의 즐겨찾기에 추가되며, 즐겨찾기는 카탈로그에서
맨 앞에 표시됩니다. **즐겨찾기**는 즐겨찾기만 나열합니다. 즐겨찾기는 사용자별로 유지됩니다. **그룹**은 행을
팀, 네임스페이스, 등급 또는 태그 값으로 그룹화합니다. 카탈로그는 환경 및 팀별로 필터링하며, 서비스에
둘 이상이 있는 경우 네임스페이스 및 태그별로도 필터링합니다. 필터와 그룹화는
주소의 일부이므로 공유 링크를 열면 동일한 보기가 표시됩니다. 범위 내에서 확인되었지만 범위가 끝날 때까지
하루 동안 보고하지 않은 서비스는 **비활성**으로 표시됩니다.

주요 트랜잭션은 가장 중요한 엔드포인트입니다. 엔드포인트 목록 또는
드로어에서 엔드포인트의 별표로 표시하며, **설정**에는 범위에서 각 항목이 처리한 내용과 함께 서비스의 주요 트랜잭션이 나열됩니다.
서비스는 최대 50개까지 보관합니다.

서비스 문서와 런북은 Mole Agent 지식 베이스의 `services/<service name>/` 아래에 있으며,
조직의 베이스 또는 담당 팀의 베이스에 있습니다. 서비스 페이지의 **문서**는 이를 나열하고 런북을
시작합니다. Mole Agent는 서비스를 조사할 때 같은 파일을 읽습니다.

정의와 주요 트랜잭션을 작성하려면 `apm.definitions.manage`가 필요하고, 오류 상태에는 `apm.errors.manage`가 필요합니다. 소유자, 관리자
및 편집자가 이 권한을 보유합니다.

## 인스턴스

서비스에 대해 보고하는 각 프로세스는 인스턴스이며, `service.instance.id`로 구분되고, 없으면
`k8s.pod.name`, 그도 없으면 `host.name`으로 구분됩니다. MoleSignal은 인스턴스의 스팬을 1분에 한 번 확인하고
버전과 위 표의 속성을 유지하며, 각각 마지막으로 보고된 값입니다. 리포지토리 링크는
사용자, 비밀번호 또는 쿼리가 없는 https 주소로 유지됩니다. 각 인스턴스가 처리한 내용(요청,
오류, 지연 시간)은 서비스 수치와 동일한 스팬에서 자체 버킷으로 집계됩니다.

**런타임**은 현재 보기 중인 범위와 버전의 인스턴스를 최근에 확인된 것부터 나열하며,
처리량, 오류율, p95와 함께 인스턴스의 포드, 없으면 호스트 기준 로그 링크 및 구분 기준 레이블에 따른
메트릭 링크를 표시합니다. 서비스 및 시간당 인스턴스 카디널리티 제한을 초과하면
나머지는 **기타 인스턴스**로 함께 집계되어 인스턴스 합계가 서비스와 일치합니다. 인스턴스를 클릭하면
런타임 차트가 해당 인스턴스로 유지되며, 선택은 주소의 일부입니다. 시간별 집계가 보관되는 기간 동안
확인되지 않은 인스턴스는 제거됩니다.

## 엔드포인트 심층 분석

엔드포인트 드로어는 RED 차트에 두 개의 카드를 추가합니다:

- **상태 코드**는 코드별 응답 수를 집계합니다. HTTP 코드는 `http.response.status_code`에서,
  (이전 계측에서는 `http.status_code`) gRPC 코드는 `rpc.grpc.status_code`에서 가져오며, 각각
  클래스별로 색상이 지정되고 추세가 표시됩니다. 버킷에는 최대 24개 코드가 유지되며, 추가 코드는
  **기타 HTTP** 또는 **기타 gRPC**로 집계됩니다. 상태 코드를 집계하기 전에 작성된 집계에는 상태 코드가 없습니다.
- **소요 시간 내역**은 범위 내 엔드포인트의 최신 요청을 트레이스 저장소에서 읽으며,
  최대 200개와 각 요청 아래의 스팬을 읽습니다. 호출 시간은 호출 대상에 따라 배분됩니다. 데이터베이스
  (`db.system.name`), 캐시(Redis, Memcached, Valkey), HTTP, RPC 또는 메시징이며, 대상을
  명시하지 않는 호출은 **기타**로 분류됩니다. 내부 스팬은 내부 작업으로 집계되며, 요청 아래의 어떤 스팬도
  포함하지 않는 시간은 자체 시간으로 계산됩니다. 각 부분은 비중과 요청당 시간과 함께 표시됩니다.
  병렬로 수행된 호출은 요청 길이를 초과해 합산될 수 있으며, 이 경우 각 부분은 요청 길이에 맞게 조정됩니다.
  테일 샘플링에서 보관한 트레이스만 읽습니다.

엔드포인트 목록의 **장기 작업**은 p99가 1초 이상인 엔드포인트만 표시합니다. 내부 유형의
진입 스팬(예: 메시징 작업이 없는 예약 작업 및 큐 워커)은
**워커**로 나열됩니다.

## 배포

서비스 페이지의 **배포** 섹션은 파이프라인이 보고한 배포를 서비스 스팬이 전달하는
버전과 나란히 표시하고, 롤백을 식별하며, 각 버전을 이전 버전과 비교하고, 동시에 실행 중인 두 버전을
나란히 읽습니다. 파이프라인은 `POST /api/v1/apm/deployments`로 배포를 보고합니다.
[배포](/ko/apm/deployments)를 참조하세요.

## 종속성

서비스의 **종속성** 탭에 있는 각 대상에는 100점에서 시작하는 상태 점수가 있습니다. 실패한 호출의 비율 1%마다
4점(최대 60점)이 차감되고, 시간 초과된 호출의 비율 1%마다 4점(최대 20점)이 차감되며, 비교 기간 동안에는 P95가 20%를 초과해 증가한 비율 1%마다
0.5점(최대 20점)이 차감됩니다. 90점부터 대상이 양호하고, 70점부터 살펴볼 가치가 있습니다. 점수의 제목은 어떤 항목에서 점수가
차감되었는지 보여 줍니다. **비교 대상**을 설정하면 각 대상이 오류율과 P95가 어떻게 변했는지도 보여 줍니다. **느린 SQL**은
P95가 가장 높은 데이터베이스 문을 템플릿으로
나열합니다.

## 백엔드 오류 추적

오류 그룹은 누군가 **조사 중**, **해결됨**, **무시됨**으로 설정할 때까지 열린 상태로 유지됩니다. 각 그룹은
팀에 부여하고 워크스페이스 멤버에게 할당할 수 있습니다. 해결된 그룹이 다시 발생하면
**재발**로 표시됩니다. **APM → 오류**는 기본적으로 미해결 그룹을 표시합니다. 열림, 조사 중,
재발.

목록 위의 **발생 위치**는 나열된 그룹의 발생 건수를 버전,
환경 및 서비스 언어별로 집계하며, 오류 그룹의 드로어에서는 해당 그룹의 발생 건수를 집계합니다. 드로어의 **관련
로그**는 해당 서비스와 범위의 로그를 열고, 샘플 옆의 **로그**는 샘플 트레이스의 로그를
엽니다.

### 오류를 규칙으로 그룹화

오류 목록의 **그룹화 규칙**은 오류를 유형, 프레임, 엔드포인트 외에 어떻게 그룹화할지 설정합니다. 규칙은 서비스 또는 모든 서비스를 지정하고, 오류 유형, 메시지,
오류가 발생한 프레임, 엔드포인트에 대한 패턴을 지정합니다. 각 패턴은 대소문자를 구분하지 않고 전체 텍스트와 일치하며,
모든 텍스트를 나타내는 `*`를 사용할 수 있습니다. 빈 패턴은 모든 항목과 일치하며, 규칙에는 패턴이 하나 이상
필요합니다.

| 작업 | 효과 |
|---|---|
| **하나의 그룹으로 병합** | 서비스에서 규칙과 일치하는 오류는 규칙 이름을 가진 하나의 그룹이 됩니다. |
| **그룹화에서 제외** | 규칙과 일치하는 오류는 그룹을 형성하지 않습니다. 해당 요청은 RED 메트릭에서 여전히 실패로 집계됩니다. |

규칙은 순서대로 적용되며 처음 일치하는 규칙이 유지됩니다. 순서를 변경하려면 규칙을 위 또는 아래로
이동합니다. 규칙은 저장된 후 확인되는 오류에 적용되며, 모든 노드에서 30초 이내에 적용되고,
이미 만들어진 그룹은 그대로 둡니다. 규칙을 편집하는 동안 양식에는 나열된 그룹 중 몇 개가 규칙에
해당하는지 표시됩니다. 오류 그룹의 드로어에 있는 **이 오류로 규칙 만들기**는 그룹의 유형과 서비스로
규칙을 시작합니다.

## 서비스 수준 목표

서비스 수준 목표(SLO)는 7일, 28일 또는 30일의 롤링 기간 동안 양호한 요청의 비율을 약속합니다. 하나의 환경에 있는 서비스 또는 해당 서비스의
엔드포인트 하나를 대상으로 합니다. **APM → SLO**를 열고 **새 SLO**를 클릭하거나, 서비스 개요의
**서비스 수준 목표** 카드에서 **새 SLO**를 클릭합니다.

| 필드 | 의미 |
|---|---|
| **서비스** 및 **환경** | 목표가 대상으로 하는 서비스이며, 하나의 환경에 있습니다. |
| **엔드포인트** | 서비스의 엔드포인트 하나입니다. 전체 서비스를 대상으로 하려면 비워 둡니다. |
| **성공 조건** | **요청 성공**: 요청이 실패하지 않으면 양호합니다. **임계값 이내에 성공**: 요청이 실패하지 않고 **지연 시간 임계값 (ms)** 이내에 완료되면 양호합니다. |
| **목표 (%)** | 약속하는 양호한 요청의 비율이며, 0보다 크고 100보다 작습니다(예: `99.9`). |
| **기간** | 7일, 28일 또는 30일이며, 현재 시점에 종료됩니다. |

SLO는 해당 서비스의 APM 집계를 읽으므로 테일 샘플링 전의 모든 요청을 집계합니다.

| 수치 | 의미 |
|---|---|
| **성공률** | 기간 내 전체 요청 중 양호한 요청의 비율입니다. |
| **남은 오류 예산** | `1 - (1 - met) / (1 - objective)`. 예산은 목표가 허용하는 불량 요청의 비율입니다. 목표가 깨지면 수치는 0 아래로 내려갑니다. |
| **소진율** | 지난 1시간, 6시간, 24시간 동안의 `(1 - met) / (1 - objective)`입니다. `1×`에서는 예산이 정확히 기간만큼 유지됩니다. |
| **일별 목표 달성 현황** | 기간의 각 UTC 일자를 달성, 미달성 또는 요청 없음으로 표시합니다. |

| 상태 | 의미 |
|---|---|
| **목표 위반** | **성공률**이 목표보다 낮습니다. |
| **위험** | 예산이 25% 미만 남았거나, 소진율이 지난 1시간 동안 14.4를 초과했거나, 지난 6시간 동안 6을 초과했습니다. |
| **정상** | 위에 해당하지 않습니다. |
| **데이터 없음** | 기간에 요청이 없습니다. |

지연 시간 목표는 지연 시간 히스토그램을 읽으므로 임계값 이내의 요청 수는 약 4% 오차 범위에서 백분위수만큼
정확합니다. 기간은 시간별 집계를 읽고, 소진율은 분별 집계를 읽습니다. 시간별 집계의 보존 기간보다 긴
기간은 보존된 날짜만
집계합니다.

### 소진율 알림

SLO 드로어의 **소진율 알림 만들기**는 Google SRE 워크북에서 권장하는 두 가지 알림 규칙을 추가합니다. 두 규칙 모두 목표에 대한 APM 알림 규칙이며,
규칙의 에스컬레이션 정책을 통해 알림을 보냅니다.

| 규칙 | 기간 | 발생 조건 | 심각도 |
|---|---|---|---|
| 빠른 소진 | 1시간 및 그 마지막 5분 | 두 기간 모두에서 소진율이 14.4를 초과 | 심각 |
| 느린 소진 | 6시간 및 그 마지막 30분 | 두 기간 모두에서 소진율이 6을 초과 | 경고 |

짧은 기간은 이미 끝난 스파이크로 인해 규칙이 발생하지 않도록 합니다. 규칙이 SLO를 감시하기 시작하면
드로어에 버튼 대신 해당 규칙이 나열됩니다. 규칙을 만들려면 `alerts.rules.manage` 권한이 필요합니다.

SLO를 작성하려면 `apm.slos.manage` 권한이 필요하고, SLO를 삭제하려면 `apm.slos.delete` 권한이 필요합니다. SLO를 삭제하면 먼저 해당 소진율 알림이 삭제되며, 이 작업에도
`alerts.rules.manage` 권한이 필요합니다.

## APM 지표에 알림 설정

APM 알림 규칙은 APM 페이지와 동일한 집계에서 읽은 서비스 또는 해당 엔드포인트의 지표를 감시하므로 쿼리가 필요하지 않습니다.

<Steps>
  <Step title="규칙 편집기 열기">
    서비스 페이지 또는 엔드포인트 드로어의 헤더에서 **새 알림**을 열고 **임계값
    알림**을 선택합니다. 편집기는 서비스, 환경, 엔드포인트가 채워진 **APM 알림** 소스에서 열립니다. 새 규칙을 만들 때
    **알림 → 알림 규칙**에서도 **APM 알림**과 동일한 소스를 제공합니다. 규칙을 만들려면
    `alerts.rules.manage` 권한이 필요합니다.
  </Step>
  <Step title="지표 선택">
    **서비스**, **환경** 또는 **모든 환경**, **엔드포인트** 또는 **서비스 전체**,
    그리고 **지표**를 선택합니다. 편집기에서 지표 아래에 표시하는 단위로 임계값을 설정합니다.
  </Step>
  <Step title="테스트 및 저장">
    **규칙 테스트**를 클릭하여 지난 6시간의 지표를 임계값과 비교해 표시한 뒤,
    규칙을 만듭니다.
  </Step>
</Steps>

| 지표 | 단위 |
|---|---|
| **오류율** | 백분율, 0~100 |
| **P50 지연 시간**, **P90 지연 시간**, **P95 지연 시간**, **P99 지연 시간**, **평균 소요 시간** | 밀리초 |
| **처리량** | 초당 요청 수 |
| **요청 수**, **오류** | 규칙 기간 동안의 개수 |
| **새 오류 그룹** | 규칙 기간에 처음 확인된 서비스 또는 엔드포인트의 오류 그룹 |
| **Apdex** | 0~1 |
| **SLO 소진율** | 목표가 허용하는 속도보다 몇 배 더 빠른지 나타냅니다. SLO에서 설정합니다. |

각 평가는 규칙 기간을 읽습니다. 최대 24시간은 분 집계를, 더 긴 기간은 시간 집계를
사용합니다. 요청이 없는 기간에는 **요청 수**, **오류**, **새 오류 그룹**,
및 **처리량**에 대해 `0`을 반환하므로, 규칙으로 중단된 트래픽을 감지할 수 있습니다. 다른 지표는 이때 값이 없고,
어떤 임계값도 일치하지 않으며, 열린 인시던트는 해결됩니다.

편집기에서 만들거나 SLO에서 만든 규칙은 이름을 지정한 대상에 대해 `service.name`, `service.namespace`,
`deployment.environment`, `apm.endpoint` 레이블을 가지며, 해당 인시던트도 이를 복사합니다. 모든 APM 규칙의
인시던트는 또한 `service` 레이블, `affected_services`의 서비스, 그리고
집계의 샘플 트레이스 ID를 가집니다. 카탈로그의 **알림** 열, 서비스 헤더, 엔드포인트 드로어는 열린 및
확인된 인시던트 중 서비스를 이름으로 지정한 것을 집계하며, 인시던트가 환경을 지정한 경우 해당 환경에서 집계합니다. 엔드포인트 드로어는
자신의 엔드포인트로 레이블이 지정된 인시던트만 집계합니다. 집계 수를 클릭하면 **알림 →
인시던트**가 열립니다.

**이상 감지 알림**은 같은 메뉴에서 지표가 이전 며칠의 같은 시간대에서 벗어날 때,
임계값을 설정할 필요 없이 알림을 보냅니다. 참조
[APM 지표의 이상에 알림 설정](/ko/apm/insights#apm-지표의-이상-징후에-대한-알림).

## 필터, 해상도 및 보존

APM 페이지는 전역 시간 범위를 공유합니다. 카탈로그는 환경 및 팀으로 필터링하고, 서비스
페이지는 환경 및 버전으로 필터링합니다. 목록은 검색과 정렬을 지원합니다. 범위는 URL에 인코딩되어
뷰를 공유하거나 다시 방문할 수 있습니다.

기본 배포 설정 기준:

- 생략된 API 범위는 최근 24시간을 사용합니다.
- `auto` 해상도는 최대 24시간 범위에는 분 버킷을, 더 긴 범위에는 시간 버킷을
  사용합니다.
- 분 집계는 24시간 동안 보존됩니다.
- 시간 집계와 최대 쿼리 범위는 30일을 포함합니다.

관리자는 이러한 배포 제한을 변경할 수 있습니다. 버전 비교는 양쪽이 구성된 요청 임계값에
도달한 후에만 충분한 것으로 표시되며, 기본값은 각각 1,000건의 요청입니다.

## 데이터 품질 공지 확인

모든 APM 응답에는 데이터 품질 메타데이터가 포함됩니다. 표시할 내용이 있으면 짧은 공지가
탐색 카드에 표시되며 세부 정보를 엽니다.

| 공지 | 의미 |
|---|---|
| **이 범위 내에서 데이터 시작** | 선택한 범위 안에서 APM 프로젝션이 시작되어 이전 트래픽은 반영되지 않습니다. |
| **일부 데이터 누락** | 큐, 리포지토리, 플러시, 지연 데이터, 카디널리티 또는 종료 공백이 범위의 일부에 영향을 주었습니다. 누락된 데이터를 0으로 해석하지 마십시오. |
| **데이터 지연** | `lastCompleteBucketAt`이 선택한 범위보다 이전입니다. 최근 집계는 아직 마감되거나 롤업 중일 수 있습니다. |
| **일부 이름이 기타로 집계됨** | 카디널리티 한도에 도달했습니다. 한도를 초과한 이름은 **기타**라는 행에 함께 집계됩니다. 한도는 [APM 설정](/ko/apm/settings#카디널리티-한도)에 있습니다. |

먼저 시간 범위와 필터를 줄입니다. 일부 데이터 누락 또는 데이터 지연 상태가 지속되면 APM
상태 엔드포인트와 [APM 프로젝션 지표](/ko/self-observability#apm-프로젝션)를 확인합니다.

## 런타임 메트릭

**런타임** 섹션은 서비스가 `service.name`과 함께 전송하는 런타임 메트릭을 차트로 표시합니다. 여기에는
모든 언어에 있는 프로세스 수치, 그다음 서비스가 보고하는 각 언어의 런타임이
`telemetry.sdk.language`에 따라 표시되며, 보고하는 언어가 없으면 메트릭이 있는 모든 런타임을 표시합니다. 각 차트는 인스턴스마다 하나의
선을 그리며, 인스턴스는 위와 같이 구분되고, 여기에 저장된 OpenTelemetry 규칙과
각 런타임이 일반적으로 사용하는 Prometheus 클라이언트를 모두 읽습니다. 차트는 서비스가 전송한
메트릭 중 첫 번째 것을 사용합니다:

| 런타임 | 언어 | 차트 | 메트릭, 처음 전송된 항목이 그려짐 |
|---|---|---|---|
| **프로세스** | 모두 | CPU 사용량 | `process_cpu_utilization_ratio`, `process_cpu_time_seconds_total`, `process_cpu_seconds_total` |
|  |  | 메모리 | `process_memory_usage_bytes`, `process_resident_memory_bytes` |
|  |  | 스레드 | `process_thread_count`, `process_threads` |
|  |  | 열린 파일 디스크립터 | `process_open_file_descriptor_count`, `process_open_fds` |
| **JVM** | `java`, `kotlin`, `scala`, `clojure` | CPU 사용량 | `jvm_cpu_recent_utilization_ratio`, `jvm_cpu_time_seconds_total` |
|  |  | 힙 | `jvm_memory_used_bytes` |
|  |  | 비힙 메모리 | `jvm_memory_used_bytes` |
|  |  | 초당 GC 시간 | `jvm_gc_duration_seconds_sum`, `jvm_gc_pause_seconds_sum` |
|  |  | 초당 GC 실행 횟수 | `jvm_gc_duration_seconds_count`, `jvm_gc_pause_seconds_count` |
|  |  | 스레드 | `jvm_thread_count`, `jvm_threads_live_threads` |
|  |  | 로드된 클래스 | `jvm_class_count`, `jvm_classes_loaded_classes` |

|  |  | 초당 GC 실행 횟수 | `go_gc_duration_seconds_count`, `process_runtime_go_gc_count_total` |

평균이며, 히스토그램 합계를 개수로 나눈 값입니다.

섹션 끝의 **프로파일링**은 해당 범위에 대한 서비스의 프로파일을 플레임 그래프로 병합하며,
CPU, 월 클록, 할당, 힙, 잠금 등 프로파일 유형을 한 번에 하나씩 처리합니다. **프로파일에서 열기**는
프로파일 페이지에서 이어집니다.

## 개인정보 보호 및 제한된 데이터

APM은 집계와 소량의 정제된 증거를 저장합니다. APM은 APM 집계에 요청 또는
응답 본문, URL 쿼리 값, 헤더, SQL 매개변수를 보관하지 않습니다. SQL 문은
템플릿으로만 보관되며, 모든 리터럴은 `?`입니다.
식별자 값, 대표 메시지, 스택 프레임은 길이가 제한됩니다. 민감해 보이는
값과 휘발성 값은 영구 저장 전에 제거되거나 마스킹됩니다.

이러한 보호 조치는 적절한 계측 관행을 대체하지 않습니다. 비밀 정보나 개인
데이터를 스팬 이름, 상태 설명, 예외 메시지, 리소스 속성에 배치하지 마십시오.

## 문제 해결

| 증상 | 확인 |
|---|---|
| APM 데이터 없음 | 트레이스가 동일한 워크스페이스에 도착하는지, 시간 범위에 최근 트래픽이 포함되는지, 활성 역할에 `apm.services.read` 권한이 있는지 확인합니다. |
| `unknown_service` | 스팬을 내보내기 전에 안정적인 `service.name` 리소스 속성을 설정합니다. |
| 누락된 엔드포인트 | `SERVER` 또는 `CONSUMER` 스팬 종류와 표준 HTTP, RPC, 메시징 속성을 추가합니다. |
| 누락된 종속성 | 다운스트림 호출 주변에 `CLIENT` 또는 `PRODUCER` 스팬을 추가하고 대상 시맨틱 속성을 포함합니다. |
| 누락된 버전 | 배포의 모든 인스턴스에 `service.version`을 일관되게 설정합니다. |
| 누락된 오류 | 예외 이벤트를 기록하고 OpenTelemetry 규칙에 따라 스팬, HTTP 또는 RPC 상태를 설정합니다. |
| 오류 샘플에서 트레이스를 찾을 수 없음 | 트레이스가 샘플링에서 제외되었거나 만료된 반면, 샘플링 전 APM 집계는 유효하게 유지됩니다. |
| 런타임 차트 없음 | 동일한 `service.name`으로 OpenTelemetry 런타임 메트릭을 전송합니다. |
| 부분적이거나 오래된 결과 | 데이터 품질 안내와 `GET /api/v1/apm/health`를 검토합니다. |
| 중지된 서비스에서 APM 알림이 발생하지 않음 | 오류율, 지연 시간, Apdex는 요청 없이는 값을 가지지 않습니다. 트래픽이 중지되는 경우 **Requests** 또는 **Throughput**을 모니터링합니다. |
| SLO에 **No data**가 표시됨 | 서비스가 SLO의 환경에서 보고되는지, 엔드포인트 이름이 **Endpoints** 목록과 일치하는지 확인합니다. |
