실제 사용자 모니터링(Real User Monitoring, RUM)은 웹과 모바일에서의 사용자 경험을 기록하고 프런트엔드 텔레메트리를
백엔드 옵저버빌리티와 연결합니다.

## 데이터 흐름

<Steps>
  <Step title="애플리케이션 만들기">
    [애플리케이션](/ko/rum/applications)은 데이터를 전송하는 웹사이트 또는 앱입니다. 각 애플리케이션에는
    해당 애플리케이션에 이벤트를 쓰는 권한만 있는 클라이언트 토큰이 제공됩니다.
  </Step>
  <Step title="이벤트 전송하기">
    브라우저 SDK와 Flutter SDK는 JSON [이벤트](/ko/rum/events)를 하나의 엔드포인트로 전송합니다. SDK를 사용하지 않는 클라이언트는
    HTTP 요청으로 동일한 이벤트를 전송합니다.
  </Step>
  <Step title="데이터 탐색하기">
    MoleSignal은 각 이벤트를 검사하고 위치, 브라우저, 디바이스 정보를 추가한 다음 RUM
    스트림에 기록합니다. 뷰를 바탕으로 세션을 생성합니다. [탐색기](/ko/rum/explorer)에서 데이터를 검색합니다.
  </Step>
</Steps>

| 엔드포인트 | 용도 |
|---|---|
| `POST /api/v1/rum/events` | [이벤트 형식](/ko/rum/events)에 맞춘 뷰, 액션, 오류, 요청, 장기 작업, 바이탈 지표를 수집합니다. |
| `POST /api/v1/rum/replay` | 브라우저 DOM 또는 Flutter 화면의 리플레이 세그먼트를 수집합니다. |

두 엔드포인트 모두 애플리케이션의 클라이언트 토큰을 받습니다. 전체 RUM 엔드포인트 목록은
[RUM API](/ko/api/rum)에서 확인합니다.

## 데이터 모델

이벤트 유형마다 고정 스키마를 사용하는 별도의 일반 로그 스트림이 있습니다. 뷰를 바탕으로 세션을 생성합니다.

| 스트림 | 행 |
|---|---|
| `rum_sessions` | 세션당 한 행입니다. |
| `rum_views` | 페이지 뷰 또는 화면당 한 행입니다. |
| `rum_actions` | 클릭, 탭 또는 사용자 지정 액션당 한 행입니다. |
| `rum_errors` | 오류당 한 행이며, 해당 [이슈](/ko/rum/errors)의 ID는 `error.issue_id`에 기록합니다. |
| `rum_resources` | 요청당 한 행입니다. |
| `rum_long_tasks` | 장기 작업당 한 행입니다. |
| `rum_vitals` | 바이탈 지표당 한 행입니다. |

뷰와 세션은 변경될 때마다 다시 보고합니다. 탐색기에 표시되는 각 행과 탐색기에서 실행하는 각 쿼리에는
뷰 또는 세션의 최신 버전이 반영됩니다. SQL에서 `rum_views_latest`와 `rum_sessions_latest`는
최신 버전만 포함하는 스트림입니다([쿼리](/ko/query#rum-행의-최신-버전) 참조).

## 개요

**RUM**을 열면 **개요**가 표시됩니다. 한 번에 애플리케이션 하나를 대상으로, 단일 환경 또는 모든 환경에서 선택한
시간 범위의 데이터를 표시합니다. 요약 문장에는 전체 세션 수, 사용자 수, 오류가 없었던 세션 수가 표시됩니다.
웹 바이탈을 전송하지 않는 앱은 대신 충돌이 없었던 세션 수와 사용자 수를 표시합니다. 요약 아래에는
브라우저 애플리케이션의 코어 웹 바이탈을 지표별 등급 척도(좋음, 개선 필요, 나쁨)로 표시하고,
뷰의 75번째 백분위수에 표시를 붙입니다. 지표를 선택하면 해당 지표의 [성능](/ko/rum/performance) 화면이 열립니다.

그 아래에는 조회수가 가장 높은 페이지(앱의 경우 화면)를 나열하고, 페이지별 조회수, 각 바이탈 지표의 75번째 백분위수와
오류가 발생한 뷰의 비율을 표시합니다. 지도에는 세션이 발생한 위치와 세션 수가 가장 많은 국가를 표시합니다.
세션에서 사용한 브라우저, 운영 체제, 디바이스 유형과 사용자 불편이 가장 많이 발생한 요소도 표시합니다.
요소별로 가장 빈번한 액션을 확인할 수 있습니다. 표의 행이나 막대를 선택하면 집계 대상 행이 탐색기에서 열립니다.

개요 헤더의 **대시보드에서 열기**를 선택하면 애플리케이션 플랫폼에 맞는 [기본 제공 RUM 대시보드](/ko/dashboards#기본-제공-rum-대시보드)가 열립니다.
페이지에서 선택한 애플리케이션과 환경이 대시보드에도 적용됩니다.

[`/api/v1/rum/aggregate`](/ko/api/rum#행-집계)는 조건과 일치하는 모든 행을 집계합니다. 집계에
시간이 너무 오래 걸리는 카드는 지연을 표시하고, 다른 카드는 그대로 유지합니다. IP 지리 위치 데이터베이스로 세션의 국가를 확인하므로
이벤트에 위치 정보를 저장하지 않는 애플리케이션에는 지도가 표시되지 않습니다.

## 오류

**오류**는 애플리케이션의 유사한 오류를 하나의 이슈로 묶어 나열합니다. 이슈에는 상태(열림, 조사 중,
재발, 해결됨, 무시됨), 담당 팀과 담당자, 발생 시점과 버전 기록이 표시됩니다. 해결된 이슈가
최신 버전에서 다시 발생하면 상태가 재발로 바뀝니다. 이슈를 선택하면 추세, 발생 위치, 복원된 스택 트레이스,
최근 세션, 영향을 받은 사용자를 보여 주는 패널이 열립니다. [RUM 오류 및 이슈](/ko/rum/errors)를 참조합니다.

## 성능

**성능**은 사용자가 경험한 브라우저 애플리케이션의 페이지 성능을 보여 줍니다. 요약 문장에는 LCP, INP,
CLS의 75번째 백분위수를 등급별 색상으로 표시하고, 첫 콘텐츠 페인트와 첫 바이트까지 걸린 시간도 함께
표시합니다. 차트는 선택한 지표의 시간에 따른 변화를 보여 줍니다. 지표별 막대는 뷰를 좋음, 개선 필요, 나쁨으로 나누어 표시합니다.
표에는 페이지(또는 브라우저, 국가, 버전)별 지표 값이 표시됩니다. 행을 선택하면 지표의 구성,
지표 값에 영향을 준 요소, 성능이 가장 나빴던 뷰를 보여 주는 패널이 열립니다. **리소스**와 **장기 작업**에서는
페이지가 로드하는 리소스와 페이지를 차단하는 작업을 보여 줍니다. 브라우저 뷰를 열면 해당 페이지가 어떻게 로드되었는지 확인할 수 있습니다. [RUM 성능](/ko/rum/performance)을 참조합니다.

## 사용자 불편

**사용자 불편**은 애플리케이션 사용 중 불편을 유발하는 요인을 보여 줍니다. 요약 문장에는
불편 신호(격분 클릭, 무반응 클릭, 오류 클릭 또는 앱의 격분 탭과 오류 탭)가 나타난 세션 비율과 신호별
액션 수 및 세션 수를 표시합니다. 표는 영향을 받은 세션 수를 기준으로 요소, 페이지, 버전 또는 브라우저를 나열합니다. 행을 선택하면
영향을 받은 세션의 추이, 불편 신호, 버전 및 페이지, 최근 세션을 보여 주는 패널이 열립니다. 각 최근 세션을 선택하면
불편 신호가 나타나기 5초 전부터 리플레이가 재생됩니다. [RUM 사용자 불편](/ko/rum/frustration)을 참조합니다.

## 분석

**분석**은 세 가지 화면에서 세션 내 사용자 행동을 보여 줍니다. **퍼널**은 일련의 페이지 방문과
액션을 순서대로 수행한 세션 수, 단계별 통과 비율과 소요 시간을 집계합니다. 같은 지표를 브라우저, 운영 체제,
디바이스 유형, 버전 또는 국가별로 확인할 수 있습니다. **경로**는 특정 페이지를 열기 전이나 후에 방문한 페이지를 추적하고,
가장 많이 방문한 페이지를 열로 나누어 표시합니다. **리텐션**은 일별 또는 주별로 처음 방문한 사용자 수와 이후 각 기간에
다시 방문한 비율을 집계합니다. 페이지를 열면 최근 7일의 데이터를 표시합니다. [RUM 분석](/ko/rum/analytics)을 참조합니다. **히트맵**은 한
페이지의 기록 위에 사용자가 클릭한 위치와 스크롤한 깊이를 표시합니다. [RUM 히트맵](/ko/rum/heatmaps)을 참조합니다.

## 기능 플래그

**기능 플래그**는 세션에서 평가한 플래그를 나열하고, 플래그 값별로 세션의 오류, 사용자 불편, 바이탈 지표를 비교합니다.
어디서든 `feature_flags.<key>`로 플래그를 필터링하거나 그룹화하고 지표를 집계할 수 있습니다. [RUM 기능 플래그](/ko/rum/feature-flags)를 참조합니다.

## 알림

[알림 규칙](/ko/alerting)은 애플리케이션의 오류, 충돌 없는 세션, 사용자 불편이 발생한 세션 비율,
실패한 요청, 코어 웹 바이탈의 75번째 백분위수, 신규 또는 재발 이슈를 모니터링할 수 있습니다. 규칙은
페이지와 동일한 방식으로 지표를 집계하므로 모니터링하는 값과 페이지에 표시되는 값이 일치합니다. 환경, 페이지, 버전으로 범위를 좁힙니다.
[RUM 알림](/ko/rum/alerts)을 참조합니다.

개요, 오류, 성능, 사용자 불편 페이지의 범위 선택 행 끝에 있는 **알림**은
애플리케이션에서 진행 중인 인시던트 수를 표시합니다. 선택하면 인시던트, 알림 규칙, 클릭 한 번으로 규칙을 만드는 템플릿을 확인할 수 있습니다.
[페이지에서 알림 만들기](/ko/rum/alerts#페이지에서-알림-설정)를 참조합니다.

## Mole Agent로 조사

**Mole Agent로 조사**를 선택하면 현재 보고 있는 내용을 주제로 Mole Agent에서 새 채팅을 엽니다. 이 버튼은
개요, 오류, 성능, 사용자 불편 페이지의 헤더와 개별 항목을 열었을 때 표시됩니다.

| 위치 | 질문에 포함되는 내용 |
|---|---|
| **개요** 헤더 | 애플리케이션, 환경, 시간 범위입니다. |
| **오류** 헤더 | 같은 범위에서 발생한 애플리케이션 오류입니다. |
| **성능** 헤더 | Web Vitals 뷰에서는 현재 표시된 Core Web Vital을, **리소스**와 **장기 작업**에서는 페이지 속도를 다룹니다. |
| 성능 테이블의 행 | 페이지, 브라우저, 국가 또는 버전이 해당 행의 값과 일치하는 뷰입니다. 행에 뷰가 충분하면 현재 표시된 지표의 75번째 백분위수도 포함합니다. 버튼은 행에 포인터를 올리면 표시되며, 터치 화면에서는 항상 표시됩니다. |
| **사용자 불편** 헤더 | 애플리케이션 사용자가 불편을 겪는 원인입니다. |
| 이슈 드로어(**조사**) | 이슈, 이슈 ID, 오류입니다. |
| 사용자 불편 그룹 패널(**이 요소 조사**, **조사**) | 요소와 해당 선택자 또는 그룹의 페이지, 버전, 브라우저, 시스템입니다. |
| 세션 헤더(**이 세션 조사**) | 시작부터 종료까지의 세션입니다. |
| RUM 지표에 설정한 규칙의 인시던트(**Mole Agent로 조사**) | 알림, 애플리케이션, 인시던트 발생 시간, 인시던트를 유발한 세션입니다. 채팅은 인시던트에 연결된 상태로 유지되므로 답변을 근본 원인 분석(RCA)으로 기록할 수 있습니다. |

채팅에 애플리케이션을 첨부하고 메시지 입력란에 질문을 미리 채웁니다. 질문을 확인하거나 수정한 후 전송할 수 있습니다.
전송 버튼을 누르기 전에는 아무것도 보내지 않습니다. `agent.use` 권한이 있으면 버튼이 표시됩니다. 채팅을 시작하려면 `rum.events.read` 또는
`_sys` 범위의 `sys.telemetry.read` 권한이 필요하며, 채팅을 시작하면 애플리케이션의 [조사](/ko/agent#조사)를 기록합니다.

질문에 애플리케이션을 첨부하려면 `@`를 입력한 뒤 이름을 입력하고 **RUM 애플리케이션** 아래에서 선택합니다.
RUM 읽기 권한이 없으면 메시지를 보낼 수 없습니다. 모델에는 질문에 지정한 시간 범위(지정하지 않으면 최근 24시간)에 대해 다음 정보를 제공합니다.

- 세션과 사용자, 오류가 없는 세션의 비율과 충돌이 없는 세션의 비율, 사용자 불편이 감지된 세션
- 브라우저 애플리케이션의 경우 Core Web Vitals의 75번째 백분위수와 각 지표의 등급, 조회수가 가장 높은 페이지
- 가장 많은 세션에 영향을 준 미해결 이슈 최대 3개와 각 이슈가 처음 발생한 버전 및 다시 발생한 버전
- 애플리케이션에서 활성 상태인 알림(`alerts.rules.read` 권한이 있는 경우에만)

Mole Agent는 `get_rum_overview`, `list_rum_issues`, `get_rum_issue`, `get_rum_vitals`, `get_rum_frustration`,
`get_rum_view_waterfall`, `aggregate_rum`, `get_rum_funnel`, `get_rum_paths`, `get_rum_retention`, `get_rum_heatmap`, `get_rum_feature_flags`, `get_rum_session_notes`와 세션,
액션, 오류, 관련 트레이스용 도구를 사용해 RUM 데이터를 읽습니다. 이 도구는 각 페이지와 동일한 데이터를 읽고, 조회 권한에 따른 필드 마스킹을 유지합니다. 기본 제공 스킬인
`/rum-triage`는 개요, 이슈, 느리거나 멈춘 뷰, 흐름 내 사용자 여정, 세션,
세션에서 발생한 요청의 트레이스 순으로 조사합니다. 조사 결과의 근거로 해당 페이지 링크를 표시합니다.

## 탐색기

기본 탐색 메뉴에서 **RUM**을 엽니다. **탐색기**에는 실제 사용자의 세션, 뷰, 액션, 오류, 리소스,
장기 작업이 표시됩니다. 필드 쿼리로 결과를 좁히고, 히스토그램에서 시간대별 건수를 확인하고, 행을 선택해
드로어에서 엽니다. 아직 애플리케이션이 없는 워크스페이스에서는 애플리케이션을 만드는 방법을 안내합니다. [RUM 탐색기](/ko/rum/explorer)를 참조합니다.

**애플리케이션**에서는 애플리케이션 목록과 클라이언트 토큰을 확인하고, 이벤트마다 보관할 데이터를 설정합니다.
[RUM 애플리케이션](/ko/rum/applications)을 참조합니다.

## 세션 및 리플레이

탐색기에서 세션을 열면 리플레이, 사용자 컨텍스트, 이슈, 이벤트 타임라인, 관련 백엔드
트레이스가 표시됩니다. DOM 리플레이를 기록한 세션에는 `session.has_replay` 필드가 있으므로
`session.has_replay = true` 쿼리로 해당 세션만 표시할 수 있습니다.

세션 헤더의 **현재 재생 위치 링크 복사**를 선택하면 리플레이가 현재 재생 위치에서 열리는 주소를 복사합니다.
[재생 목록](/ko/rum/playlists)에 검토할 세션을 모아 순서대로 재생할 수 있습니다. 리플레이에
[댓글을 추가하고 챕터가 있는 AI 요약을 생성할 수 있으며](/ko/rum/session-replay#댓글), 세션에는 페이지가 [로그에 남긴
내용](/ko/rum/logs)이 표시됩니다.

합성 모니터링 검사나 CI 테스트에서 생성한 세션에는 테스트 트래픽 표시가 붙으며, 실제 사용자 지표에서 제외합니다. [테스트 트래픽](/ko/rum/test-traffic)을 참조합니다.

리플레이를 민감한 사용자 데이터로 취급합니다. SDK에서 수집 제어를 설정하고, 비밀 정보나
개인정보가 포함된 필드는 기록하지 않으며, 보존 기간은 필요한 최소한으로 설정합니다.

## 오류, 소스 맵 및 심볼

오류는 구조화된 스택 프레임과 함께 수집됩니다. MoleSignal은 오류 유형, 메시지, 애플리케이션 자체 코드의 첫 번째
프레임을 기준으로 오류를 [이슈](/ko/rum/errors)로 그룹화합니다. 브라우저 소스 맵이나 모바일 심볼은
**RUM → RUM 설정 → 소스 맵 및 심볼**에서 업로드합니다. MoleSignal은 업로드한 디버그 아티팩트를 사용해
축소된 프레임, 난독화된 프레임, 네이티브 프레임을 복원합니다. 아티팩트 메타데이터를 읽으려면 `debug_artifacts.read` 권한이 필요하며,
업로드하거나 삭제하려면 `debug_artifacts.manage` 권한이 필요합니다.

## 관련 백엔드 트레이스

요청에 W3C `traceparent`가 포함되면 요청의 `resource.trace_id`가 백엔드
스팬에 직접 연결됩니다. 세션에는 요청에 포함된 트레이스 목록이 표시됩니다. 어떤 요청에도 트레이스 ID가 없으면 세션 상세 화면에서
해당 세션의 시간 범위 내에 있는 관련 트레이스를 검색합니다.

느린 프런트엔드 요청에서 해당 서비스의 트레이스, 로그, 메트릭으로 바로 이동할 수 있으며,
조사 컨텍스트도 유지됩니다.

반대 방향으로도 이동할 수 있습니다. 세션의 요청에 트레이스 ID가 포함된 경우, **트레이스**의 해당 트레이스 헤더에
**사용자 세션**이 표시됩니다. 이 버튼을 선택하면 해당 세션을 엽니다.

## 프록시 뒤의 클라이언트 IP

RUM 이벤트는 공용 인터넷의 브라우저와 기기에서 전송됩니다. 기본적으로 MoleSignal은 직접 연결한 상대의 IP 주소를 기록합니다. MoleSignal 앞에 리버스 프록시나 CDN이 있으면 모든 이벤트에 프록시의 IP 주소가 기록되어 지리 정보가 부정확해집니다. **설정 → 클라이언트 IP 식별**을 열고 단일 값 헤더 또는 전달 체인을 선택한 다음 신뢰할 프록시의 CIDR을 입력합니다. MoleSignal은 해당 네트워크에서 들어온 연결의 헤더만 신뢰합니다. 이 설정은 재시작 없이 배포 전체에 적용됩니다.

## 권한

- `rum.write` 권한으로 RUM 이벤트를 전송합니다. 애플리케이션에 연결된 클라이언트 토큰은 해당 애플리케이션에 이 권한만 부여합니다.
- `rum.events.read` 권한으로 개요, 탐색기, 성능, 사용자 불편 페이지를 엽니다.
- `rum.issues.read` 권한으로 오류를, `rum.analytics.read` 권한으로 분석을, `rum.applications.read` 권한으로 애플리케이션 목록을, `rum.playlists.read` 권한으로 재생목록을 엽니다.
- `rum.sessions.read` 권한으로 세션 페이지를 엽니다. `rum.replay.read` 권한으로 해당 세션의 리플레이를 재생하고 댓글과 요약을 읽습니다.
- `rum.replay.comments.write` 권한으로 리플레이에 댓글을 작성하고 직접 작성한 댓글을 수정합니다. `rum.replay.comments.manage` 권한으로 모든 댓글을 수정하고, `rum.replay.summaries.generate` 권한으로 AI 요약을 요청합니다.
- `rum.issues.manage` 권한으로 이슈의 상태, 팀, 담당자를 설정합니다. 소유자, 관리자, 편집자에게 이 권한이 있습니다.
- `agent.use` 권한이 있으면 이 페이지에 **Mole Agent로 조사**가 표시되고 `@`로 애플리케이션을 첨부할 수 있습니다.
- `alerts.rules.read` 권한이 있으면 개요, 오류, 성능, 사용자 불편 페이지에 **알림**이 표시됩니다. `alerts.rules.manage` 권한으로
  해당 페이지에서 규칙을 생성합니다. [RUM 알림](/ko/rum/alerts#권한)을 참조합니다.
- `rum.applications.manage` 권한으로 애플리케이션을 생성, 수정, 삭제하고 각 애플리케이션의 클라이언트 토큰을 확인합니다.
- `debug_artifacts.read` 권한으로 디버그 아티팩트의 메타데이터를 나열합니다.
- `debug_artifacts.manage` 권한으로 소스 맵과 모바일 심볼을 업로드하거나 삭제합니다.
