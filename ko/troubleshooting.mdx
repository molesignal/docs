먼저 프로세스 로그를 확인합니다. 프로세스 로그에는 시작 실패 원인이 기록되며, 거부된 요청의 HTTP 오류 응답 본문에는 오류 메시지가 포함됩니다. `[telemetry].log_level` 또는 `RUST_LOG`로 로그 수준을 설정합니다.

## 시작

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| `... password authentication failed for user` | DSN의 사용자 이름 또는 비밀번호가 잘못되었습니다. | `[meta_database].dsn`을 수정합니다. |
| `... pool timed out while waiting for an open connection` | 노드에서 PostgreSQL에 연결할 수 없습니다. | 호스트, 포트, 방화벽, `sslmode` 요구 사항을 확인합니다. |
| `startup_ping put: ... SignatureDoesNotMatch` | 오브젝트 스토리지가 자격 증명을 거부합니다. | `access_key`와 `secret_key`를 확인합니다. `MS_OBJECT_STORE_ACCESS_KEY`와 `MS_OBJECT_STORE_SECRET_KEY`로 설정합니다. |
| `startup_ping put: ... NoSuchBucket` | 버킷이 없습니다. | 버킷을 생성하거나 `[object_store].bucket`을 수정합니다. |
| `Encountered transport error`가 반복된 후 프로세스가 종료됨 | 엔드포인트에 연결할 수 없거나 클라이언트에 자격 증명이 전달되지 않습니다. | `endpoint`, DNS, 네트워크를 확인합니다. `access_key`와 `secret_key`를 통해 자격 증명을 제공해야 합니다. |
| `unknown field: found ...` | 엄격하게 검증하는 섹션에 오타가 있거나 지원하지 않는 키가 있습니다. | 키를 삭제하거나 수정합니다. [구성](/ko/configuration#설정-로드-방식)을 참조합니다. |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN must be set when split-role self intake is enabled` | 역할을 분리한 구성에서 `intake` 역할이 없는 노드가 공유 토큰 없이 시작하며, 트레이스 캡처 또는 자체 수집이 활성화되어 있습니다. | 모든 노드에 동일한 토큰을 설정합니다. 트레이스 캡처는 기본적으로 활성화되므로 `[telemetry.self_collect]`만 비활성화해도 문제가 해결되지 않습니다. |
| `open Probe CA key` | `MS_CIPHER_KEY`가 데이터베이스를 암호화한 키와 다릅니다. | 원래 키를 복원합니다. [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다. |
| `migration ... was previously applied but is missing in the resolved migrations` 또는 `... has been modified` | 바이너리와 데이터베이스의 버전이 호환되지 않습니다. | 데이터베이스와 일치하는 버전을 실행하거나 백업을 복원합니다. [업그레이드](/ko/upgrade)를 참조합니다. |
| `address already in use` | 다른 프로세스가 설정된 포트를 사용 중입니다. | 포트를 변경합니다. |
| `profiling.port and ... are both ...` | pprof 리스너가 다른 리스너와 같은 포트를 사용합니다. | `[profiling].port`에 다른 리스너가 사용하지 않는 포트를 설정합니다. |
| 환경 변수로 지정한 설정이 적용되지 않음 | 변수 이름에 마침표, 연속된 밑줄 두 개 또는 오타가 있습니다. | `MS_META_DATABASE_DSN`처럼 경로의 각 요소를 밑줄 하나로 연결합니다. |

## 로그인

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| `admin@example.com`과 `admin`으로 로그인할 수 없음 | 데이터베이스에 이미 사용자가 있어 루트 계정을 다시 생성하지 않았거나 `root_email`과 `root_password`가 비어 있었습니다. | 기존 계정으로 로그인합니다. 루트 계정을 생성하려면 두 값을 모두 설정하고 빈 데이터베이스를 사용해 시작합니다. |
| 비밀번호 재설정 이메일이 도착하지 않음 | SMTP 또는 `http.external_url`을 설정하지 않았습니다. 요청은 수락하지만 이메일은 보내지 않습니다. | `[notify.smtp].host`와 `[http].external_url`을 설정합니다. |
| 로그인한 후 `Authorization: Bearer`를 보내는 스크립트가 `401`을 받음 | 로그인은 웹 UI용 세션 쿠키를 설정하며 토큰은 반환하지 않습니다. 해당 헤더는 API 토큰만 받습니다. | 스크립트용 API 토큰을 발급합니다. [API 토큰](/ko/identity/tokens)을 참조합니다. |
| 웹 UI에서 매일 다시 로그인하라는 메시지가 표시됨 | 로그인 세션은 `[auth].session_ttl_secs`(24시간)가 지나면 종료됩니다. | `[auth].session_ttl_secs` 값을 높입니다. |

## 데이터 전송

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| `401` | 토큰이 없거나 유효하지 않거나, 헤더에 로그인 세션 토큰을 넣었습니다. | 기본 수집 토큰 또는 서비스 계정 토큰을 사용해 `Authorization: Bearer <token>`을 보냅니다. |
| `403` | 토큰에 `logs.write`와 같은 해당 신호의 쓰기 권한이 없습니다. 예를 들어 수집 경로로 RUM 클라이언트 토큰을 보낸 경우입니다. | 해당 신호의 쓰기 권한이 있는 토큰을 사용합니다. |
| `413` | 요청 본문이 엔드포인트의 한도를 초과합니다. 네이티브 JSON 수집의 한도는 16 MiB이며, 나머지는 2 MiB입니다. | 배치 크기를 줄여 전송합니다. 프록시 한도를 엔드포인트 한도 이상으로 높입니다. |
| OTLP over HTTP 엔드포인트가 `400`을 반환함 | 전송 측에서 요청 본문을 압축했습니다. | OpenTelemetry Collector 익스포터에 `compression: none`을 설정합니다. |
| OTLP over HTTP 엔드포인트가 `404`를 반환함 | 익스포터 엔드포인트에 기본 경로 `/api`가 빠져 있어 요청이 `/v1/logs`로 전송됩니다. | OTLP 엔드포인트로 `http://host:5080/api`를 사용합니다. |
| `Retry-After`가 포함된 `429` | `router` 역할에서 조직에 적용하는 요청 속도 제한에 도달했습니다. | 전송 속도를 낮추거나 `[router.rate_limit]`의 한도를 높입니다. |
| 네이티브 JSON 응답에 `rejected` 레코드가 표시됨 | 필드 값이 스트림 스키마와 일치하지 않습니다(예: `type mismatch on field level: expected Utf8, got Number`). 응답에는 인덱스별로 거부 사유가 표시됩니다. | 스트림이 해당 필드에 이미 사용 중인 타입으로 값을 전송합니다. |
| `event #1 must be a JSON object`가 포함된 `400` | 배열에 JSON 객체가 아닌 요소가 있습니다. 요청 전체를 거부합니다. | JSON 객체의 배열을 전송합니다. |
| Promtail 또는 Grafana Alloy에서 데이터를 푸시할 수 없음 | Loki 엔드포인트는 JSON만 디코딩하지만, 이러한 전송 도구는 Snappy로 압축한 protobuf를 사용합니다. | OpenTelemetry Collector, Vector 또는 Fluent Bit를 통해 전송합니다. |
| 레코드를 수락했지만 조회되지 않음 | 쿼리에서 다른 스트림 이름이나 타입을 사용하거나, 레코드가 포함되지 않는 시간 범위를 지정했습니다. | 스트림 이름과 신호 타입을 확인합니다. 타임스탬프는 다음 섹션을 참조합니다. |

## 데이터 누락 또는 이상

- **타임스탬프.** `_timestamp`는 Unix 에포크부터 경과한 시간을 마이크로초로 나타냅니다. 초, 밀리초 또는 나노초 단위의 값을 보내면 이벤트가 잘못된 연도나 먼 미래의 시점으로 기록되어 최근 시간 범위를 조회해도 나타나지 않습니다. 서버가 데이터를 받은 시각을 사용하려면 `_timestamp`를 생략합니다.
- **시간 범위.** 긴 시간 범위를 조회하는 쿼리는 비동기 작업으로 실행됩니다. 대화형 쿼리에는 시작과 끝을 지정한 `timeRange`를 사용합니다. [쿼리](/ko/query#시간-범위-및-비동기-작업)를 참조합니다.
- **보존 기간.** 스트림의 보존 기간이 지난 데이터는 삭제됩니다. 스트림에 자체 보존 기간이 없으면 **설정 → 데이터 보존**의 플랫폼 기본값을 적용합니다.
- **스트림 타입.** 이름과 타입으로 스트림을 식별합니다. 로그, 메트릭, 트레이스에 각각 `default` 스트림이 동시에 존재할 수 있습니다.

## 쿼리

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| `jobId`와 `monitor` 경로가 포함된 `202` 응답을 받음 | 예상 행 수가 `[querier].auto_async_threshold_rows`에 도달하면 쿼리를 비동기 검색 작업으로 실행합니다. 기본 설정에서는 시간 범위가 약 13.9시간 이상이면 이 기준에 도달합니다. | 작업이 완료될 때까지 `monitor` 경로에 반복해서 요청한 다음, 해당 작업의 `/results`에서 결과를 가져옵니다. 또는 시간 범위를 좁히거나 `Prefer: respond-sync`를 보냅니다. [쿼리](/ko/query#시간-범위-및-비동기-작업)를 참조합니다. |
| Flight SQL 클라이언트가 연결할 수 없음 | `[flight_sql]`은 기본적으로 비활성화되어 있습니다. | `enabled = true`를 설정하고 포트 `5083`을 노출한 다음 API 토큰으로 인증합니다. |

## 운영

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| `GET /api/v1/healthz`가 `503`을 반환합니다 | 오브젝트 스토리지에 연결할 수 없습니다. 응답 본문에 `reason`이 포함됩니다. | 오브젝트 스토리지 연결 문제를 해결합니다. |
| WAL 디렉터리의 크기가 계속 커집니다 | 플러시가 실패합니다. 일반적으로 오브젝트 스토리지에 연결할 수 없을 때 발생합니다. | 오브젝트 스토리지 문제를 해결합니다. 해결하면 수집 서비스가 밀린 데이터를 플러시합니다. |
| 수집 서비스가 `intake buffer memory limit exceeded`와 함께 `429`를 반환합니다 | 프로세스의 버퍼 메모리 사용량이 `[intake].max_buffer_memory_size`를 초과했습니다. 일반적으로 플러시가 계속 실패할 때 발생합니다. | `intake flush failed` 로그에서 원인을 찾아 오브젝트 스토리지 또는 데이터베이스 문제를 해결합니다. 게시할 수 없는 행은 한도 계산에서 제외합니다(다음 두 행 참조). 네이티브 JSON 수집은 이 응답에 `Retry-After`를 포함합니다. 지정된 시간만큼 기다린 후 다시 시도합니다. |
| 로그에 `dataset no longer exists; buffered rows discarded`가 표시됩니다 | 스트림의 행이 버퍼에 남아 있는 동안 해당 스트림이 삭제되었거나 삭제 후 다시 생성되었습니다. 이 행을 게시할 곳이 없으므로 수집 서비스는 행을 폐기하고 해당 메모리를 해제합니다. `intake_flush_errors_total` 카운터는 폐기할 때마다 `stream_gone` 또는 `dataset_gone` 단계로 기록합니다. | 별도의 조치는 필요하지 않습니다. 필요한 경우 데이터를 다시 전송합니다. |
| 쓰기 요청에 `fenced by a newer writer epoch`와 함께 `503`이 반환됩니다 | 다른 프로세스가 동일한 `[node].id`로 동일한 데이터 세트를 게시합니다. 차단된 프로세스는 데이터를 게시할 수 없으므로 메모리에 보관한 행을 폐기하고 해당 데이터 세트에 대한 쓰기 요청을 거부합니다. 해당 프로세스의 WAL은 디스크에 남습니다. `intake_flush_errors_total` 카운터는 차단을 `writer_fenced` 단계로 기록합니다. | 각 프로세스에 고유한 `[node].id`를 지정하고 차단된 프로세스를 다시 시작합니다. [역할 기반 배포](/ko/deployment/role-based)를 참조합니다. |
| 예약된 PDF 또는 PNG 보고서 생성이 실패합니다 | Chrome이 없거나 `[scheduled_reports.renderer].base_url` 주소로 웹 UI에 접속할 수 없습니다. | Chromium이 포함된 릴리스 이미지를 사용하고, 노드에서 접속할 수 있는 웹 UI 주소를 `base_url`로 설정합니다. |
| 온보딩 코드 스니펫에 잘못된 호스트가 표시됩니다 | 프록시 뒤에서 `http.external_url`이 비어 있습니다. | `[http].external_url`을 공개 주소로 설정하고 다시 시작합니다. |
| 쿼리 요청에 `no querier node is available`과 함께 `503`이 반환됩니다 | `querier` 역할을 가진 노드 중 최근에 하트비트를 보낸 노드가 없습니다. | `querier` 노드를 시작하고 라우터에서 해당 노드의 `advertise_addr`에 연결할 수 있는지 확인합니다. [역할 기반 배포](/ko/deployment/role-based#클러스터-멤버십)를 참조합니다. |
| 라우터를 통한 쓰기 요청에 `no intake node is available`과 함께 `503`이 반환됩니다 | `intake` 역할을 가진 노드 중 최근에 하트비트를 보낸 노드가 없습니다. | `intake` 노드를 시작하고 해당 노드의 `advertise_addr`을 확인합니다. [역할 기반 배포](/ko/deployment/role-based#클러스터-멤버십)를 참조합니다. |
| 요청에 `no metadata database connection`과 함께 `503`이 반환됩니다 | 노드가 PostgreSQL 연결을 10초 동안 기다렸지만 연결을 확보하지 못했습니다. PostgreSQL에 과부하가 걸렸거나 연결할 수 없거나, `[meta_database].max_connections`에서 허용하는 연결을 모두 사용 중입니다. | 요청을 다시 시도합니다. 문제가 계속되면 먼저 PostgreSQL 부하와 연결 가능 여부를 확인합니다. PostgreSQL에 부하가 없다면 PostgreSQL의 `max_connections` 한도 내에서 부하에 맞게 `[meta_database].max_connections` 값을 높입니다. |
| 호스트에서 OTLP gRPC 포트에 연결할 수 없습니다 | Compose 파일이 `4317` 포트를 외부에 노출하지 않습니다. | `4317:4317` 매핑을 추가합니다. |
