먼저 프로세스 로그를 확인합니다. 시작 실패의 원인이 출력되며, 거부된 요청의 HTTP 오류 본문에는 메시지가 포함되어 있습니다. 로그 수준은 `[telemetry].log_level` 또는 `RUST_LOG`에서 가져옵니다.

## 시작

| 증상 | 원인 | 해결 |
|---|---|---|
| `... password authentication failed for user` | DSN 사용자 또는 비밀번호가 잘못되었습니다. | `[meta_database].dsn`을 수정합니다. |
| `... pool timed out while waiting for an open connection` | 노드에서 PostgreSQL에 연결할 수 없습니다. | 호스트, 포트, 방화벽 및 `sslmode` 요구 사항을 확인합니다. |
| `startup_ping put: ... SignatureDoesNotMatch` | 오브젝트 스토어가 자격 증명을 거부합니다. | `access_key`와 `secret_key`를 확인합니다. `MS_OBJECT_STORE_ACCESS_KEY`와 `MS_OBJECT_STORE_SECRET_KEY`로 설정합니다. |
| `startup_ping put: ... NoSuchBucket` | 버킷이 존재하지 않습니다. | 버킷을 생성하거나 `[object_store].bucket`을 수정합니다. |
| `Encountered transport error` 줄이 반복된 후 종료 | 엔드포인트에 연결할 수 없거나 클라이언트에 자격 증명이 전달되지 않습니다. | `endpoint`, DNS 및 네트워크를 확인합니다. 자격 증명은 `access_key`와 `secret_key`에서 제공되어야 합니다. |
| `unknown field: found ...` | 엄격한 섹션의 키 이름이 잘못되었거나 지원되지 않습니다. | 키를 제거하거나 수정합니다. [구성](/ko/configuration#설정-로드-방식)을 참조합니다. |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN must be set when split-role self intake is enabled` | `intake` 역할이 없는 역할 분할 노드가 추적 캡처 또는 자체 수집이 켜진 상태에서 공유 토큰 없이 시작합니다. | 모든 노드에 동일한 토큰을 설정합니다. 추적 캡처는 기본적으로 켜져 있으므로 `[telemetry.self_collect]`만 비활성화하는 것으로는 충분하지 않습니다. |
| `open Probe CA key` | `MS_CIPHER_KEY`가 데이터베이스를 암호화한 키와 다릅니다. | 원래 키를 복원합니다. [프로덕션 체크리스트](/ko/deployment/production-checklist)를 참조합니다. |
| `migration ... was previously applied but is missing in the resolved migrations` 또는 `... has been modified` | 바이너리와 데이터베이스가 호환되지 않는 버전입니다. | 일치하는 버전을 실행하거나 백업을 복원합니다. [업그레이드](/ko/upgrade)를 참조합니다. |
| `address already in use` | 다른 프로세스가 구성된 포트를 사용하고 있습니다. | 포트를 변경합니다. |
| `profiling.port and ... are both ...` | pprof 리스너가 다른 리스너와 포트를 공유합니다. | 다른 리스너가 사용하지 않는 포트로 `[profiling].port`를 설정합니다. |
| 환경 변수의 설정이 적용되지 않음 | 변수 이름에 점, 이중 밑줄 또는 오타가 포함되어 있습니다. | `MS_META_DATABASE_DSN`처럼 경로를 단일 밑줄로 연결합니다. |

## 로그인

| 증상 | 원인 | 해결 |
|---|---|---|
| `admin@example.com`에 `admin`을 사용한 로그인이 거부됨 | 데이터베이스에 이미 사용자가 있어 루트 계정이 다시 생성되지 않았거나 `root_email`과 `root_password`가 비어 있었습니다. | 기존 계정으로 로그인합니다. 루트 계정을 생성하려면 두 값을 설정하고 빈 데이터베이스를 대상으로 시작합니다. |
| 비밀번호 재설정 이메일이 도착하지 않음 | SMTP 또는 `http.external_url`이 구성되지 않았습니다. 요청은 아무것도 전송하지 않고 수락됩니다. | `[notify.smtp].host`와 `[http].external_url`을 설정합니다. |
| 로그인하고 `Authorization: Bearer`를 전송하는 스크립트가 `401`을 받음 | 로그인은 웹 UI용 세션 쿠키를 설정하고 토큰을 반환하지 않습니다. 헤더는 API 토큰만 허용합니다. | 스크립트용 API 토큰을 발급합니다. [API 토큰](/ko/identity/tokens)을 참조합니다. |
| 웹 UI가 매일 다시 로그인을 요청함 | 로그인 세션은 `[auth].session_ttl_secs`(24시간) 후에 종료됩니다. | `[auth].session_ttl_secs`를 늘립니다. |

## 데이터 전송

| 증상 | 원인 | 해결 |
|---|---|---|
| `401` | 토큰이 없거나 유효하지 않거나, 헤더에 로그인 세션 토큰이 포함되어 있습니다. | 기본 인테이크 토큰 또는 서비스 계정 토큰과 함께 `Authorization: Bearer <token>`을 전송합니다. |
| `403` | 토큰에 `logs.write`와 같은 시그널의 쓰기 권한이 없습니다. 예를 들어 RUM 클라이언트 토큰을 인테이크 경로로 전송한 경우입니다. | 시그널의 쓰기 권한이 있는 토큰을 사용합니다. |
| `413` | 요청 본문이 엔드포인트의 제한을 초과합니다. 네이티브 JSON 인테이크의 경우 16 MiB, 그 외의 경우 2 MiB입니다. | 더 작은 배치로 전송합니다. 프록시의 제한을 최소한 엔드포인트의 제한까지 높입니다. |
| OTLP over HTTP 엔드포인트의 `400` | 전송자가 본문을 압축했습니다. | OpenTelemetry Collector 익스포터에서 `compression: none`을 설정합니다. |
| OTLP over HTTP 엔드포인트의 `404` | 익스포터 엔드포인트에 `/api` 기본 경로가 없어 요청이 `/v1/logs`로 전송됩니다. | OTLP 엔드포인트로 `http://host:5080/api`를 사용합니다. |
| `Retry-After`가 포함된 `429` | 조직에 대한 `router` 역할 속도 제한이 적용됩니다. | 속도를 줄이거나 `[router.rate_limit]`을 높입니다. |
| 네이티브 JSON이 `rejected` 레코드를 보고함 | 필드 값이 스트림 스키마와 일치하지 않습니다. 예: `type mismatch on field level: expected Utf8, got Number`. 응답은 인덱스별로 이유를 나열합니다. `int64` 필드에서 소수점이 있는 숫자는 여기에 해당하지 않습니다. 해당 필드는 `float64`가 됩니다. | 스트림이 해당 필드에 대해 이미 저장하는 유형으로 전송합니다. |
| `event #1 must be a JSON object`가 포함된 `400` | 배열에 JSON 객체가 아닌 요소가 포함되어 있습니다. 전체 요청이 거부됩니다. | 객체 배열을 전송합니다. |
| Promtail 또는 Grafana Alloy가 푸시할 수 없음 | Loki 엔드포인트는 JSON만 디코딩하며, 이러한 전송자는 snappy로 압축된 protobuf를 사용합니다. | OpenTelemetry Collector, Vector 또는 Fluent Bit를 통해 전송합니다. |
| 레코드가 수락되지만 조회되지 않음 | 쿼리가 다른 스트림 이름이나 유형을 사용하거나, 해당 레코드를 제외하는 시간 범위를 사용합니다. | 스트림 이름과 시그널 유형을 확인합니다. 타임스탬프는 다음 섹션을 참조합니다. |

## 누락되거나 비정상적인 데이터

- **타임스탬프.** `_timestamp`는 Unix 에포크 이후 경과한 마이크로초를 나타냅니다. 초, 밀리초 또는 나노초 단위의 값은 이벤트를 잘못된 연도나 먼 미래에 배치하며, 최근 시간에 대한 쿼리는 이를 반환하지 않습니다. 서버 수신 시간을 사용하려면 `_timestamp`를 생략합니다.
- **시간 범위.** 긴 범위를 다루는 쿼리는 비동기 작업이 됩니다. 대화형 쿼리에는 범위가 제한된 `timeRange`를 사용합니다. [쿼리](/ko/query#시간-범위-및-비동기-작업)를 참조합니다.
- **보존.** 스트림의 보존 기간보다 오래된 데이터, 또는 자체 보존 기간이 없는 스트림의 경우 **설정 → 데이터 보존**의 플랫폼 기본값보다 오래된 데이터는 삭제됩니다.
- **스트림 유형.** 스트림은 이름과 유형으로 식별됩니다. `default`는 로그, 메트릭 및 트레이스에 동시에 존재할 수 있습니다.

## 쿼리

| 증상 | 원인 | 해결 |
|---|---|---|
| `jobId`와 `monitor` 경로가 포함된 `202` 응답 | 예상 크기가 `[querier].auto_async_threshold_rows`에 도달하여 쿼리가 비동기 검색 작업으로 실행됩니다. 기본값에서는 약 13.9시간 이상의 범위입니다. | 작업이 완료될 때까지 `monitor` 경로를 요청한 다음 해당 `/results`를 가져옵니다. 또는 시간 범위를 좁히거나 `Prefer: respond-sync`를 전송합니다. [쿼리](/ko/query#시간-범위-및-비동기-작업)를 참조합니다. |
| Flight SQL 클라이언트가 연결할 수 없음 | `[flight_sql]`은 기본적으로 비활성화되어 있습니다. | `enabled = true`로 설정하고, `5083` 포트를 노출하며, API 토큰으로 인증합니다. |

## 운영

| 증상 | 원인 | 해결 |
|---|---|---|
| `GET /api/v1/healthz`가 `503`을 반환합니다 | 오브젝트 스토리지에 연결할 수 없습니다. 본문에 `reason`이 포함됩니다. | 오브젝트 스토리지 연결을 수정합니다. |
| WAL 디렉터리가 커집니다 | 플러시가 실패하며, 보통 오브젝트 스토리지에 연결할 수 없기 때문입니다. | 오브젝트 스토리지를 수정합니다. 그러면 intake가 이후에 백로그를 플러시합니다. |
| Intake가 `intake buffer memory limit exceeded`와 함께 `429`를 반환합니다 | 프로세스의 버퍼가 `[intake].max_buffer_memory_size`를 초과했습니다. 보통 플러시가 계속 실패하기 때문입니다. | `intake flush failed` 로그 라인에서 원인을 찾고 오브젝트 스토리지나 데이터베이스를 수정합니다. 게시할 수 없는 행은 더 이상 한도에 포함되지 않습니다(다음 두 행 참고). 네이티브 JSON intake는 이 응답과 함께 `Retry-After`를 보냅니다. 해당 지연 후에 재시도합니다. |
| 로그에 `dataset no longer exists; buffered rows discarded`가 표시됩니다 | 스트림의 행이 아직 버퍼에 있는 동안 해당 스트림이 삭제되었거나 삭제 후 다시 생성되었습니다. 그 행들은 갈 곳이 없으므로 intake가 버리고 메모리를 반환합니다. `intake_flush_errors_total` 카운터는 각 폐기를 `stream_gone` 또는 `dataset_gone` 단계로 기록합니다. | 수정할 것은 없습니다. 데이터가 중요하다면 다시 보냅니다. |
| 쓰기가 `fenced by a newer writer epoch`와 함께 `503`을 반환합니다 | 다른 프로세스가 동일한 `[node].id`로 같은 데이터셋을 게시하고 있습니다. 펜싱된 프로세스는 데이터를 게시할 수 없어 메모리에 보관한 행을 버리고 해당 데이터셋에 대한 쓰기를 거부합니다. WAL은 디스크에 남습니다. `intake_flush_errors_total` 카운터는 펜싱을 `writer_fenced` 단계로 기록합니다. | 모든 프로세스에 고유한 `[node].id`를 부여하고 펜싱된 프로세스를 재시작합니다. [역할 기반 배포](/ko/deployment/role-based)를 참고합니다. |
| 예약된 PDF 또는 PNG 보고서가 실패합니다 | Chrome이 없거나 `[scheduled_reports.renderer].base_url`이 웹 UI에 연결할 수 없습니다. | Chromium이 포함된 릴리스 이미지를 사용하고 `base_url`을 노드에서 연결할 수 있는 웹 UI 주소로 설정합니다. |
| 온보딩 스니펫에 잘못된 호스트가 표시됩니다 | 프록시 뒤에서 `http.external_url`이 비어 있습니다. | `[http].external_url`을 공개 주소로 설정하고 재시작합니다. |
| 쿼리가 `no querier node is available`과 함께 `503`을 반환합니다 | `querier` 역할을 가진 노드의 최근 하트비트가 없습니다. | `querier` 노드를 시작하고 해당 `advertise_addr`이 라우터에서 연결 가능한지 확인합니다. [역할 기반 배포](/ko/deployment/role-based#클러스터-멤버십)를 참고합니다. |
| 라우터를 통한 쓰기가 `no intake node is available`과 함께 `503`을 반환합니다 | `intake` 역할을 가진 노드의 최근 하트비트가 없습니다. | `intake` 노드를 시작하고 해당 `advertise_addr`을 확인합니다. [역할 기반 배포](/ko/deployment/role-based#클러스터-멤버십)를 참고합니다. |
| 요청이 `no metadata database connection`과 함께 `503`을 반환합니다 | 노드가 PostgreSQL 연결을 10초 동안 기다렸지만 얻지 못했습니다. PostgreSQL이 과부하 상태이거나 연결할 수 없거나, `[meta_database].max_connections` 연결이 모두 사용 중입니다. | 요청을 재시도합니다. 계속 발생하면 먼저 PostgreSQL의 부하와 연결 가능성을 확인합니다. PostgreSQL이 유휴 상태라면 PostgreSQL의 `max_connections` 범위 내에서 부하에 맞게 `[meta_database].max_connections`를 늘립니다. |
| 호스트에서 OTLP gRPC 포트에 연결할 수 없습니다 | Compose 파일이 `4317` 포트를 게시하지 않습니다. | `4317:4317` 매핑을 추가합니다. |
