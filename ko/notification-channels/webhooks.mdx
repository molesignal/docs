MoleSignal은 현재 세 가지 웹훅 커넥터 유형을 지원합니다. Slack 웹훅, Lark 웹훅,
범용 JSON 웹훅입니다. **설정 → 알림 → 커넥터**에서 웹훅 커넥터를 생성합니다.

ID 연결, 정책 생성, 대체 경로 또는 전송 내역을 알아보려면
[알림 채널 및 전송](/ko/notification-channels)을 먼저 읽습니다.

## 웹훅 유형 비교

| 커넥터 | 요청 형식 | 인증 | 대상 유형 |
|---|---|---|---|
| `slack_webhook` | `{ "text": "..." }` | 웹훅 URL에 포함된 자격 증명 | `fixed_group`, `webhook` |
| `lark_webhook` | Lark `msg_type: text` | URL에 포함된 자격 증명, 선택적 서명 | `fixed_group`, `webhook` |
| `webhook` | MoleSignal 이벤트 JSON 또는 알림 템플릿 본문 | 사용자 지정 JSON 헤더, 선택적 서명 | 모든 대상 유형 |

`fixed_group`의 경우 커넥터는 설정된 URL로 전송합니다. `webhook`의 경우 대상 값은
절대 URL이어야 하며, 해당 전송에서 설정된 URL 대신 사용합니다.

## Slack 웹훅

수신 웹훅 URL을 설정하고 타임아웃을 1~60초로 지정합니다.

```json
{
  "webhookUrl": "https://hooks.slack.com/services/T000/B000/secret",
  "timeoutSecs": 10
}
```

MoleSignal은 메시지 제목과 Markdown 본문을 결합해 다음과 같이 전송합니다.

```json
{
  "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
}
```

HTTP 응답이 2xx이면 전송에 성공한 것으로 처리합니다. 그 외 응답을 받거나 타임아웃이 발생하면 전송 실패로 표시합니다.

## Lark 웹훅

Lark 또는 Feishu의 사용자 지정 봇 URL을 설정합니다. 서명 검증을 활성화한 경우에만
봇 서명 시크릿을 추가합니다.

```json
{
  "webhookUrl": "https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx",
  "secret": "replace-with-signing-secret",
  "timeoutSecs": 10
}
```

서명 시크릿이 없으면 MoleSignal은 다음과 같이 전송합니다.

```json
{
  "msg_type": "text",
  "content": {
    "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
  }
}
```

서명 시크릿을 설정하면 MoleSignal은 초 단위 Unix 타임스탬프를 생성하고,
`timestamp + "\n" + secret` 값을 만듭니다. 이 값을 HMAC-SHA256 키로 사용해 빈 메시지의 다이제스트를 구하고
Base64로 인코딩합니다. 요청에는 두 필드가 모두 포함됩니다.

```json
{
  "timestamp": "1599360473",
  "sign": "base64-signature",
  "msg_type": "text",
  "content": {
    "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
  }
}
```

MoleSignal은 Lark 응답에서 HTTP 상태가 성공을 나타내고 `code` 또는 `status_code`가 0일 때만
전송에 성공한 것으로 처리합니다.

<Note>
  MoleSignal 서버의 시간을 동기화합니다. Lark는 타임스탬프가 오래된 서명 요청을 거부합니다.
</Note>

## 범용 웹훅

기본 URL, 메서드, 본문, 서명 시크릿, 헤더, 타임아웃을 설정합니다.

```json
{
  "url": "https://notify.example.com/molesignal",
  "method": "post",
  "body": "event",
  "signingSecret": "<at-least-16-characters>",
  "headers": {
    "X-Environment": "production"
  },
  "timeoutSecs": 10
}
```

메서드는 `post`, `put`, `patch` 중 하나로 지정합니다. 헤더 이름과 값은 유효한 HTTP 구문을 따라야 하며,
헤더 이름에 `Content-Type`이나 아래의 `X-MoleSignal-*` 이름을 사용할 수 없습니다.

### 본문

`body`를 기본값인 `event`(콘솔의 **MoleSignal 이벤트**)로 설정하면 본문을
시스템이 읽을 수 있는 JSON으로 전송합니다.

```json
{
  "version": 2,
  "event": {
    "id": "alert.triggered:3KEDNEyqouYJeBDTLTMTBui7XHW",
    "type": "alert.triggered",
    "occurredAt": "2026-10-28T08:00:00Z",
    "organizationId": "<organization-id>"
  },
  "alert": {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "status": "open",
    "severity": "critical",
    "title": "High error rate · checkout",
    "url": "https://molesignal.example.com/alerts/incidents/3KEDNEyqouYJeBDTLTMTBui7XHW",
    "startedAt": "2026-10-28T08:00:00Z",
    "acknowledgedAt": null,
    "resolvedAt": null,
    "acknowledgedBy": null,
    "resolvedBy": null,
    "assignees": ["<user-id>"],
    "teamId": "<team-id>",
    "service": "checkout",
    "environment": "production",
    "affectedServices": ["checkout"],
    "labels": { "service": "checkout", "env": "production" },
    "annotations": { "runbook_url": "https://runbooks.example.com/checkout" },
    "value": 120.0,
    "threshold": 50.0
  },
  "rule": { "id": "<rule-id>", "name": "High error rate", "description": "Share of 5xx answers." },
  "target": { "type": "fixed_group", "value": "platform-oncall", "metadata": {} },
  "message": {
    "title": "[CRITICAL] High error rate · checkout",
    "text": "The error rate exceeded 5%.",
    "markdown": "**Checkout** error rate exceeded 5%.",
    "html": null,
    "metadata": { "event_type": "alert.triggered", "alert_id": "3KEDNEyqouYJeBDTLTMTBui7XHW" }
  }
}
```

| 필드 | 내용 |
|---|---|
| `version` | 본문 구조의 버전입니다. 현재 버전은 `2`이며, 본문 자체의 키에는 camelCase를 사용합니다. `data`에는 이벤트 속성을 그대로 담습니다. 필드는 추가만 하며, 기존 수신 측과 호환되지 않는 변경이 있을 때만 버전을 올립니다. |
| `event` | 알림의 `id`, `type`(예: `alert.triggered`, `alert.escalated`, `oncall.shift.starting`), `occurredAt`, `organizationId`입니다. |
| `alert` | 경보 알림에만 포함합니다. 상태, 심각도, 제목, 인시던트 주소(`http.external_url`을 설정한 경우), 시작·확인·해결 시각, 담당자, 팀, 서비스, 환경, 레이블, 주석, 값, 임계값을 담습니다. 시각은 UTC 기준 RFC 3339 형식이며, 담당자와 팀은 ID로 표시합니다. |
| `rule` | 경보 규칙의 `id`, `name`, `description`입니다. |
| `escalation` | 에스컬레이션 알림에만 포함합니다. `step`, `loop`, `reason`(전송 이유, [인시던트에 조치하기](/ko/alerting/incidents#인시던트에-조치하기) 참고), `target`(`kind` 및 `id`)을 담습니다. |
| `data` | 온콜 인계나 당직 공백 등 경보가 아닌 알림의 이벤트 속성을 그대로 담습니다. |
| `target` | 이 전송 대상의 `type`, `value`, `metadata`입니다. |
| `message` | 렌더링된 메시지의 `title`, `text`, `markdown`, `html`, `metadata`입니다. |

`body`를 `template`(**알림 템플릿 본문**)로 설정하면 알림 정책에서 웹훅 채널에 지정한
템플릿을 작성된 형식 그대로 전송합니다. JSON 템플릿은 `application/json`으로 전송하고 값을
JSON 문자열로 이스케이프합니다. 그 외 형식은 `text/plain; charset=utf-8`로 전송합니다. 정책에서
웹훅 채널에 템플릿을 지정하지 않으면 공통 템플릿의 본문이나 이벤트 자체 메시지의 본문을 전송합니다.
템플릿 작성 방법은 [조건](/ko/notification-channels#조건)을 참고합니다.

### 헤더 및 서명

| 헤더 | 내용 |
|---|---|
| `Content-Type` | `application/json`입니다. 템플릿 본문이 JSON이 아니면 `text/plain; charset=utf-8`입니다. |
| `X-MoleSignal-Event` | 알림 유형입니다. `event.type`과 동일합니다. |
| `X-MoleSignal-Delivery` | 이 전송의 ID입니다. 수신 측에서 이 ID로 중복 요청을 무시할 수 있습니다. |
| `X-MoleSignal-Timestamp` | 서명 시크릿을 설정한 경우에만 포함합니다. 전송 시점의 초 단위 Unix 시간입니다. |
| `X-MoleSignal-Sign` | 서명 시크릿을 설정한 경우에만 포함합니다. 서명 시크릿을 키로 사용해 `<timestamp>.<body>`의 HMAC-SHA256을 계산한 `sha256=<hex>` 값입니다. |

수신 측에서는 동일한 시크릿과 원본 본문으로 서명을 다시 계산하고,
`X-MoleSignal-Sign`과 상수 시간으로 비교합니다. 타임스탬프와 현재 시각의 차이가 허용 범위(예: 5
분)를 넘으면 요청을 거부합니다. JSON을 파싱해 다시 직렬화하지 말고 원본 바이트로 서명을 계산합니다.

<CodeGroup>
```python Python
import hashlib, hmac, time

def verify(secret: str, headers, body: bytes, tolerance: int = 300) -> bool:
    timestamp = headers.get("X-MoleSignal-Timestamp", "")
    signature = headers.get("X-MoleSignal-Sign", "")
    if not timestamp.isdigit() or abs(time.time() - int(timestamp)) > tolerance:
        return False
    mac = hmac.new(secret.encode(), timestamp.encode() + b"." + body, hashlib.sha256)
    return hmac.compare_digest("sha256=" + mac.hexdigest(), signature)
```

```javascript Node.js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verify(secret, headers, body, toleranceSecs = 300) {
  const timestamp = headers['x-molesignal-timestamp'] ?? '';
  const signature = Buffer.from(headers['x-molesignal-sign'] ?? '');
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSecs) return false;
  const expected = Buffer.from(
    'sha256=' + createHmac('sha256', secret).update(`${timestamp}.`).update(body).digest('hex'),
  );
  return expected.length === signature.length && timingSafeEqual(expected, signature);
}
```

```go Go
import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"net/http"
	"strconv"
	"time"
)

func verify(secret string, r *http.Request, body []byte, tolerance time.Duration) bool {
	timestamp := r.Header.Get("X-MoleSignal-Timestamp")
	seconds, err := strconv.ParseInt(timestamp, 10, 64)
	if err != nil || time.Since(time.Unix(seconds, 0)).Abs() > tolerance {
		return false
	}

	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(timestamp + "."))
	mac.Write(body)
	expected := "sha256=" + hex.EncodeToString(mac.Sum(nil))

	return hmac.Equal([]byte(expected), []byte(r.Header.Get("X-MoleSignal-Sign")))
}
```
</CodeGroup>

서명 시크릿은 최소 16자여야 합니다. 예를 들어 `openssl rand -hex 32`로 생성할 수 있습니다. 커넥터의
HTTP 대상에도 같은 서명 방식을 사용합니다. [커넥터](/ko/connectors)를 참고합니다.

### 응답 및 아웃바운드 요청

2xx 응답은 모두 성공으로 처리합니다. 응답에 `X-Request-ID`가 있으면 MoleSignal은 해당 헤더
값을 제공업체 메시지 ID로 기록합니다. MoleSignal은 호스트 이름을 조회해 얻은 주소에만 연결하고,
클라우드 메타데이터 주소로의 연결을 거부하며 리디렉션을 따르지 않습니다. 웹훅 알림은
[병합](/ko/notification-channels#알림-묶기)하지 않습니다.

## API로 생성 및 테스트

범용 웹훅 커넥터를 생성합니다.

```bash
curl -X POST "$MOLESIGNAL_URL/api/v1/notify/connectors" \
  -H "Authorization: Bearer $MS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "platform webhook",
    "connectorType": "webhook",
    "enabled": true,
    "config": {
      "url": "https://notify.example.com/molesignal",
      "method": "post",
      "body": "event",
      "signingSecret": "<at-least-16-characters>",
      "headers": {"Authorization": "Bearer <token>"},
      "timeoutSecs": 10
    }
  }'
```

반환된 커넥터 `id`를 저장한 다음 테스트 요청을 전송합니다.

```bash
curl -X POST "$MOLESIGNAL_URL/api/v1/notify/connectors/$CONNECTOR_ID/test" \
  -H "Authorization: Bearer $MS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "targetType": "fixed_group",
    "target": "platform-oncall",
    "message": {
      "title": "MoleSignal connector test",
      "text": "Webhook delivery is working."
    }
  }'
```

커넥터 목록 조회, 상세 조회, 생성, 업데이트 응답에서 민감한 구성 필드의 값은 `***`로 표시합니다.
기존 커넥터를 업데이트할 때 저장된 시크릿을 유지하려면 `***` 값을 변경하지 않고 전송합니다.

## 보안 및 제한 사항

- MoleSignal은 전체 커넥터 구성을 암호화하여 저장합니다.
- API 응답은 `url`, `webhookUrl`, `headers`, `secret`, `signingSecret`, 토큰, 비밀번호를 마스킹합니다.
- 별도의 시크릿을 설정하지 않았더라도 웹훅 URL을 자격 증명으로 취급합니다.
- `https`를 우선 사용합니다. `http`는 신뢰할 수 있는 네트워크에서만 사용합니다.
- MoleSignal의 아웃바운드 액세스를 커넥터에 필요한 대상으로 제한합니다.
- 비활성화된 커넥터는 테스트 요청이나 알림을 전송할 수 없습니다.

<Note>
  DingTalk, WeCom, Teams, Google Chat, Telegram, Discord, Mattermost, Webex, Matrix, PagerDuty,
  Amazon SNS는 각각 전용 커넥터를 제공합니다.
  [제공업체별 구성](/ko/notification-channels#공급자별-구성)을 참고합니다. 대상에서
  다른 JSON 구조를 요구하면 JSON 웹훅 템플릿에 해당 구조를 작성하고 본문으로 **알림 템플릿 본문**을 선택합니다.
  별도의 변환 중계 서비스는 필요하지 않습니다.
</Note>
