APM 개요와 서비스 개요의 **인사이트** 카드는 선택한 시간 범위에서 살펴볼 만한 항목을 보여 줍니다.
직전 시간 범위 및 일주일 전 같은 시간 범위 대비 지표 변화, 성능이 저하된 버전,
처리 시간을 줄일 수 있는 지점을 확인할 수 있습니다. 감지 항목에는 감지 시작 시점 전후의 변경 사항이 표시되며,
**조사**를 선택하면 해당 항목을 Mole Agent로 넘깁니다.

## 기준 시간 범위

감지 항목 위의 두 줄은 현재 보고 있는 서비스의 지표를 길이가 같은 두 기준 시간 범위와 비교합니다.

- **직전 시간 범위 대비**: 선택한 시간 범위가 시작되는 시점에 끝나는 시간 범위입니다.
- **일주일 전 같은 시간 범위 대비**: 선택한 시간 범위를 7일 전으로 옮긴 시간 범위입니다.

각 줄에는 처리량과 오류율이 얼마나 달라졌는지 표시합니다. 오류율 변화는 퍼센트포인트로 표시합니다. 요청이 없는
시간 범위의 비교 결과는 표시하지 않습니다.

분 단위 집계는 24시간 동안 보관합니다. 그보다 일찍 시작하는 시간 범위는 해당 범위를 포함하는 시간 단위
집계를 사용하며, 요청 수는 비교하는 시간 범위의 길이에 맞춰 계산합니다.

## 인사이트가 감지하는 항목

| 인사이트 | 심각도 | 감지 조건 |
|---|---|---|
| **지표 변화** | 선택한 시간 범위에서 서비스 상태가 심각하면 **심각**, 그 외에는 **경고** | 판단에 필요한 요청 수를 충족하는 기준 시간 범위가 하나 이상 있고, 해당하는 모든 기준 시간 범위와 비교해 오류율, P95 또는 처리량이 변화 기준을 충족합니다. |
| **재발** | **경고** | 선택한 시간 범위에서 처음 확인된 버전의 성능이 이전 버전보다 낮다고 [배포](/ko/apm/deployments)에서 판단합니다. |
| **병목** | **제안**. 서비스가 정상이 아니면 **경고** | 종속 대상 하나를 20회 이상 호출했고, 해당 대상이 서비스의 전체 요청 처리 시간 중 40% 이상을 차지합니다. |
| **N+1** | **제안** | 메시지 브로커 호출을 제외한 동일한 호출이 요청당 10회 이상, 전체 200회 이상 발생합니다. 반복 호출을 한 번의 호출로 대체할 수 있습니다. |
| **느린 SQL** | **제안** | 데이터베이스 문을 20회 이상 실행했고 P95가 100 ms 이상입니다. 서비스에서 총 실행 시간이 가장 긴 문 두 개를 표시합니다. |
| **부하 집중 엔드포인트** | **제안** | 엔드포인트 두 개 이상이 요청을 처리했으며, 그중 하나가 요청 50건 이상을 처리하고 서비스의 전체 처리 시간 중 40% 이상을 차지합니다. |

지표 변화 여부는 각 지표별로 판단합니다.

| 지표 | 변화 기준 |
|---|---|
| 오류율 | 2퍼센트포인트 이상 상승하고 기준값의 2배 이상이 됩니다. |
| P95 | 기준값의 1.5배 이상이 되고 100 ms 이상 증가합니다. |
| 처리량 | 기준값의 절반 미만으로 떨어지거나 2배 이상으로 증가합니다. 요청이 더 많은 쪽의 시간 범위에 요청이 100건 이상 있어야 합니다. |

오류율이나 P95를 판단에 사용하려면 해당 시간 범위에 요청이 20건 이상 있어야 합니다. 감지 항목에는
선택한 시간 범위의 지표값을 각 기준 시간 범위의 지표값과 나란히 표시합니다.

감지 항목은 심각, 경고, 제안 순으로 최대 30개를 표시합니다. 제안은 처리 시간이 어디에 쓰이는지
보여 줄 뿐, 서비스가 비정상이라고 판단하지는 않습니다.

### 지표 변화가 시작된 시점

지표 변화는 기준값과 선택한 시간 범위의 지표값 사이의 중간값을 변화 방향으로 처음 넘어선 버킷에서 시작한 것으로 봅니다.
바로 다음 버킷과 그 뒤에 이어지는 버킷 중 절반 이상도 같은 방향으로 중간값을 넘어야
합니다. 버킷 하나만 기준을 벗어나면 지표 변화로 보지 않습니다. 카드는 감지 항목 옆에 변화가 시작된 시점을
표시합니다. 해당 시점에 마우스 포인터를 올리면 정확한 시간을 확인할 수 있습니다.

## 감지 시점 전후의 변경 사항

지표 변화 또는 재발 항목에는 시작 30분 전부터 시작 10분
후까지의 변경 사항을 시작 시점과 가까운 순서로 최대 5개까지 표시합니다.

- 파이프라인이 해당 서비스 또는
  해당 서비스가 호출하는 서비스에 대해 보고한 배포, 구성 변경, 기능 플래그입니다.
- 해당 시간 범위에 서비스의 스팬에서 처음 확인되었지만 파이프라인이 보고하지 않은 버전입니다.
  스팬에서 처음 확인한 버전으로 표시합니다.

환경을 지정해 보고한 변경 사항은 해당 환경에서만 반영합니다. 구성 변경과
기능 플래그는 `kind`를 지정한 배포로 보고합니다. 자세한 내용은
[구성 변경 및 기능 플래그 보고](/ko/apm/deployments#구성-및-기능-플래그-변경-보고)를 참조합니다.

## 인사이트가 표시되는 위치

| 페이지 | 카드에 표시되는 내용 |
|---|---|
| **개요** | 현재 보고 있는 모든 서비스의 감지 항목을 서비스 이름과 함께 표시합니다. 최근 배포 카드에서 성능이 저하된 버전을 표시하므로 **재발**은 제외합니다. |
| 서비스 **개요** | 해당 서비스의 감지 항목을 표시합니다. 같은 페이지에 다운스트림에서 소요된 시간과 처리 시간 비중이 가장 큰 엔드포인트가 표시되므로 **병목**과 **부하 집중 엔드포인트**는 제외합니다. |

특이 사항이 없으면 카드에 감지 항목이 없다고 표시합니다. 페이지의 환경 및 버전 필터를 적용합니다.

## Mole Agent로 조사

**조사**를 선택하면 현재 보고 있는 항목에 관한 새 채팅이 Mole Agent에서 열립니다.

| 위치 | 질문에 포함되는 정보 |
|---|---|
| 서비스 페이지 헤더 | 서비스, 해당 환경, 시간 범위입니다. |
| 엔드포인트 패널 | 엔드포인트, 해당 서비스와 환경, 시간 범위입니다. |
| 오류 패널 | 오류, 해당 지문, 서비스와 환경입니다. |
| **인사이트** 카드의 감지 항목 | 카드에 표시된 감지 내용, 해당 서비스와 환경, 시간 범위입니다. |

채팅에 서비스를 첨부하고 메시지 입력란에 질문을 미리 채웁니다. 질문을 확인하거나 수정한 후
전송할 수 있습니다. `agent.use` 권한이 있어야 버튼이 표시됩니다. 채팅을 시작하려면 `apm.services.read` 권한 또는
`_sys` 범위의 `sys.telemetry.read` 권한이 필요합니다. 채팅을 시작하면 서비스 조사 기록을 남깁니다. 자세한 내용은
[조사](/ko/agent#조사)를 참조합니다.

서비스를 첨부하면 채팅에 설정한 시간 범위의 다음 정보를 모델에 제공합니다. 시간 범위가 없으면 최근 1시간을 사용합니다.

- 환경별 상태와 판단 근거, 요청 수, 오류율, P50, P95, P99, Apdex, 버전입니다.
- 직전 시간 범위와 일주일 전 같은 시간 범위의 지표값입니다.
- **인사이트** 카드의 감지 항목 최대 8개와 감지 시점 전후의 변경 사항입니다.
- 해당 서비스를 호출하는 서비스 최대 6개와 해당 서비스가 호출하는 대상 최대 6개, 각 대상의 상태입니다.

서비스에 APM 데이터가 없으면 대신 서비스 그래프가 최근 24시간 동안 연결한
서비스 간 호출 정보를 제공합니다.

Mole Agent는 `get_apm_insights`로 인사이트를 조회하고,
`get_apm_blast_radius`로 서비스의 영향 범위를 조회할 수도 있습니다. 기본 제공 인시던트 분류 스킬은 두 도구를 모두 사용하며,
지연 시간 악화 스킬은 먼저 해당 서비스의 인사이트를 조회합니다.

## 인시던트의 영향 범위

인시던트에 서비스가 지정되어 있으면 상세 페이지에 **영향 범위** 섹션을 표시합니다. 서비스는
`service.name`, `service_name`, `service`, `svc` 레이블에서 확인합니다. 해당 레이블이 없으면 인시던트의 영향받는 서비스 목록을 사용합니다.
환경은 `deployment.environment` 또는 `environment` 레이블에서 확인합니다. 이 섹션은 인시던트가 시작되기 30분 전부터
해결 시점까지의 APM 서비스 맵을 조회합니다. 인시던트가 아직 열려 있으면
현재 시점까지 조회합니다.

| 목록 | 표시 내용 |
|---|---|
| **이 서비스를 호출하는 서비스: 영향을 받을 수 있는 곳** | 해당 서비스를 직접 호출하는 서비스와 그 상위 호출 서비스를 최대 3단계까지 표시합니다. |
| **이 서비스가 호출하는 서비스: 문제의 원인일 수 있는 곳** | 해당 서비스가 호출하는 서비스, 데이터베이스, 캐시, 외부 엔드포인트와 메시지를 발행하는 토픽, 그리고 호출된 서비스가 다시 호출하는 대상을 최대 2단계까지 표시합니다. |

각 목록은 비정상 대상을 먼저 배치하며 최대 6개를 표시합니다. 각 대상의 호출 거리와 상태,
해당 대상과 바로 앞 경유 노드 사이의 호출 수 및 실패 비율을 표시합니다. 토픽이나 외부
엔드포인트에 도달하면 더 이상 추적하지 않습니다. 프로듀서는 컨슈머를 기다리지 않으므로 토픽을 경유하는 호출은
프로듀서까지 추적하지 않습니다. 직전 시간 범위에는 있었지만 현재 시간 범위에서 사라진 호출은 제외합니다.

**서비스 맵에서 열기**를 선택하면 해당 환경의 [APM 서비스 맵](/ko/apm/service-map#apm-서비스-맵)이
서비스가 선택된 상태로 열립니다. APM 데이터 조회 권한이 있으면 서비스 맵을 불러온 후 이 섹션을
표시합니다. 해당 시간 범위의 서비스 맵에 서비스가 없으면 섹션에 그 사실을 표시합니다.

## APM 지표의 이상 감지 알림 설정

이상 감지 규칙은 쿼리 결과 대신 APM 지표를 모니터링할 수 있습니다. 규칙의 평가 구간에서 지표 값이
이전 각 날짜의 동일 시간대 값에서 벗어나면 알림을 보냅니다.

<Steps>
  <Step title="이상 감지 규칙 편집기 열기">
    서비스 페이지 또는 엔드포인트 드로어에서 **새 알림**을 열고 **이상 감지 알림**을 선택합니다.
    편집기는 데이터 소스를 **APM 지표**로 설정하고 서비스, 환경 및 엔드포인트를 미리 채운 상태로 열립니다.
    **알림**에서 새 이상 감지 규칙을 만들 때도 동일한 데이터 소스를 선택할 수 있습니다.
  </Step>
  <Step title="지표와 기준선 선택">
    지표를 선택한 다음 1~30일의 조회 기간, 알고리즘, 민감도를 선택합니다.
    **주간 계절성**을 사용하면 같은 요일의 데이터만 고려합니다.
  </Step>
  <Step title="저장">
    규칙 이름을 지정하고 규칙을 생성합니다. 규칙을 생성하려면 `alerts.rules.manage` 권한이 필요합니다.
  </Step>
</Steps>

이상 감지 규칙은 **새 오류 그룹**과 **SLO 소진율**을 제외한 모든 APM 지표를 지원합니다. 24시간보다 오래된 구간의 경우
해당 구간을 포함하는 시간별 집계 데이터를 읽고, 요청 수와 오류 수는
해당 구간의 길이를 기준으로 계산합니다. 규칙에는 같은 지표의 임계값 규칙과 동일한 레이블을 적용합니다.
[APM 지표에 알림 설정](/ko/apm#apm-지표에-알림-설정)을 참조합니다. 알고리즘과 각 알고리즘의 매개변수는 다음 문서를 참조합니다.
[알림 설정](/ko/alerting).
