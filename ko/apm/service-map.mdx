**서비스 맵**은 서비스 간 호출을 표시하고 요청률, 오류율,
지연 시간(**RED** 메트릭)으로 호출 상태를 보여 줍니다. MoleSignal은 기존 트레이스에서 맵을 자동으로 생성하므로
일반적인 트레이싱에는 별도의 계측이 필요하지 않습니다.

<Info>
  서비스 맵과 [APM](/ko/apm)은 같은 트레이스 데이터를 사용하지만 처리 방식이 다릅니다. 서비스 맵은
  서로 다른 서비스의 부모 스팬과 자식 스팬을 연결해 토폴로지를 구성합니다. APM은 범위가 제한된 서비스,
  트랜잭션, 종속성, 오류, 버전별 집계를 생성합니다.
</Info>

## 맵 생성 방식

MoleSignal은 트레이스 스팬을 수신할 때마다 각 스팬을 부모 스팬과 연결합니다. **서로 다른
서비스**에 속한 스팬은 *부모 서비스 → 자식 서비스* 방향의 호출 에지를 형성하며, 에지에는
자식 스팬(피호출 스팬)의 소요 시간과 오류 상태를 기록합니다. 같은 서비스 내의 부모·자식 스팬은 내부 호출이므로
에지로 표시하지 않습니다. 에지는 호출자 환경(`deployment.environment.name` 또는
`deployment.environment`)에 속하며, 호출자 환경이 없으면 피호출자 환경에 속합니다.
[실시간 파이프라인](/ko/pipelines#트레이스)에서 제외한 스팬은 연결하지 않습니다.

서비스 쌍별로 에지를 **1분 단위 버킷**에 누적하고
백그라운드에서 스토리지에 기록하므로, 맵에는 최근 트래픽이 약 30초 이내에 반영됩니다.

### 인메모리 모드와 스토리지 모드

기본값인 `intake` 모드에서는 스팬을 수신한 노드의 **메모리 내**에서 스팬을 연결하므로
지연 시간이 짧습니다. 다중 노드 배포에서 한 호출의 스팬이 서로 다른 노드에 도착하면
메모리 내에서 연결할 수 없어 해당 에지가 누락될 수 있습니다. 맵은 확인되지 않은 에지를 생성하지 않습니다.

여러 노드에 걸친 전체 맵을 보려면 **설정 → 일반 → 서비스 맵 데이터 소스**를
**스토리지** 모드로 변경합니다. 단일 노드가 **저장된 트레이스**에서 주기적으로 그래프를 다시 구성하므로
수신 노드와 관계없이 모든 스팬을 확인할 수 있지만 1~2분의 지연이 발생합니다. 설정은
데이터베이스에 저장되며 런타임에 적용되므로 재시작할 필요가 없습니다.

## 필수 트레이스 데이터

맵을 생성하려면 트레이스에 다음 데이터가 필요합니다.

- 모든 스팬에 **`service.name`** 리소스 속성(OTLP 내보내기가 이 속성을 설정합니다)
- 서비스 경계를 넘는 **부모·자식 스팬 관계**. 즉, 한 서비스의 클라이언트 스팬에
  다른 서비스에서 실행되는 자식 서버 스팬이 있어야 합니다.

표준 OpenTelemetry 계측은 두 가지를 모두 생성합니다. 트레이서를 임의의
[트레이스 수신 엔드포인트](/ko/intake)에 연결하면 MoleSignal이 맵을 자동으로 채웁니다.

## 토폴로지

토폴로지 엔드포인트는 지정된 시간 구간의 데이터를 노드(서비스)와 에지(호출)로 집계합니다.

```http
GET /api/v1/web/topology?from=2026-06-14T00:00:00Z&to=2026-06-14T01:00:00Z
Authorization: Bearer <jwt>
```

```json
{
  "nodes": [
    { "id": "checkout", "name": "checkout", "rps": 42.0, "errorRate": 0.01, "p95Ms": 120.0, "spanCount": 151200 }
  ],
  "edges": [
    { "source": "checkout", "target": "payments", "rps": 41.0, "errRate": 0.02, "p95Ms": 95.0 }
  ]
}
```

| 필드 | 의미 |
|---|---|
| `rps` | 구간 내 초당 요청 수입니다. |
| `errorRate` / `errRate` | `ERROR` 상태인 요청의 비율(0~1)입니다. |
| `p95Ms` | 구간 내 1분 단위 P95 지연 시간 중 최댓값(밀리초)입니다. |
| `spanCount` | 구간 내 해당 노드에서 관측한 총 스팬 수입니다. |

## 원시 서비스 그래프

특정 종속성의 시간 경과에 따른 변화를 차트로 표시하는 등 분 단위 에지 스냅샷이 필요하면
서비스 그래프를 직접 쿼리합니다.

```http
GET /api/v1/traces/service_graph?from=1717200000000000&to=1717286400000000&service=checkout
Authorization: Bearer <jwt>
```

`from`과 `to`는 Unix 에포크 이후 경과한 마이크로초입니다. 선택 사항인 `service` 필터는 선택한 서비스가
호출자 또는 피호출자로 나타나는 에지를 반환합니다. 각 행에는 한 서비스 쌍의 1분간 데이터인 `environment`,
`request_count`, `error_count`, `p50_us` / `p95_us` / `p99_us`가 포함됩니다.

## UI에서 보기

- **APM → 서비스 맵**은 환경 내 서비스와 서비스 간 호출을 표시하고, 각 서비스의
  호출 대상과 메시지를 발행하거나 소비하는 토픽을 보여 줍니다. [APM 서비스 맵](#apm-서비스-맵)을 참조합니다.
- 서비스의 APM 페이지에서 **종속성**은 APM 서비스 맵과 마찬가지로 해당 서비스와 호출자 및 호출 대상을 표시하고,
  수신 호출을 나열합니다. 호출을 선택하면 동일한 드로어가 열립니다.
- 트레이스 페이지의 **서비스 그래프** 탭은 쿼리와 일치하는 트레이스의 서비스 맵을 표시합니다.

모든 서비스 맵은 같은 방식으로 표시합니다. 노드는 상태를 나타내는 색상의 링 안에 유형과
이름, 초당 요청 수, 오류율, P95를 표시합니다. 호출은 트래픽에 비례하는 굵기의 화살표로 표시하며, 실패율이
5% 이상이면 빨간색, 1% 이상 5% 미만이면 주황색으로 표시합니다.

서비스나 에지에서
[신호 간 상관관계](/ko/correlation)를 통해 관련 트레이스와 로그로 바로 이동합니다.

## APM 서비스 맵

**APM → 서비스 맵**은 범위 선택 행에서 지정한 환경과
네임스페이스에 대해 서비스 그래프와 APM 집계 데이터를 결합합니다.

| 노드 | 데이터 출처 |
|---|---|
| 서비스 | 서비스 그래프와 APM 요약의 RED 지표 및 상태입니다. |
| 데이터베이스, 캐시, 외부 HTTP 또는 RPC | APM 종속성의 아웃바운드 호출을 대상별로 표시합니다. |
| 데이터를 보고하지 않는 서비스 | 자체 스팬을 전송하지 않는 서비스를 `peer.service`로 지정한 호출입니다. |
| 토픽 | 메시징 대상에 대한 발행 호출과 해당 대상에서 메시지를 소비하는 메시징 엔드포인트입니다. |

호출의 굵기는 트래픽에 비례하고 색상은 실패율을 나타냅니다. 길이가 같은 직전 구간과 비교해
현재 구간에만 발생한 호출은 **새로 만들기**로, 더 이상 발생하지 않는 호출은 **사라짐**으로 표시하고
해당 노드와 함께 점선으로 나타냅니다. 노드를 선택하면 해당 노드로 들어오거나 나가는 호출과
해당 노드에서 시작하는 **가장 느린 경로**를 강조합니다. 이 경로는 각 노드에서 P95가 가장 높은 호출을 따라갑니다.
맵 위의 카드에서 노드의 호출을 확인합니다. 호출을 선택하면 드로어에 시간별 요청 수, 오류 수, 지연 시간과 다음 호출 세부 정보가 표시됩니다.

- 서비스 호출: 모든 호출자가 요청한 대상 서비스의 엔드포인트와 해당 서비스의 오류 그룹입니다.
- 데이터베이스, 캐시 또는 외부 엔드포인트 호출: 호출에서 수행한 작업입니다.
- 토픽을 통한 호출: 발행 종료부터 소비 시작까지의 메시지 대기 시간입니다.
  트레이스 스토어의 최신 소비 스팬(최대 200개)을 사용하며, 각 소비 스팬을 링크가 가리키는 스팬과 연결하고
  해당 링크가 없으면 부모 스팬과 연결합니다.

노드가 60개를 초과하면 처음에는 각 네임스페이스를 하나의 노드로 접어 표시합니다. 해당 노드를 선택하면
네임스페이스가 펼쳐집니다. **네임스페이스 접기**는 모든 네임스페이스를 접거나 펼칩니다. 트래픽이 많은 순으로 노드를 최대 400개 표시합니다.
