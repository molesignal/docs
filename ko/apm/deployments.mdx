서비스 페이지의 **배포** 섹션은 두 가지 정보를 나란히 표시합니다. 파이프라인에서 보고한 배포와
서비스 스팬의 `service.version`에 기록된 버전입니다. 파이프라인에서 보고하지 않은 버전도
스팬에 기록되어 있으면 표시합니다.

## 배포 타임라인

타임라인은 선택한 시간 범위의 서비스 이벤트를 최신순으로 표시합니다.

| 이벤트 | 표시 조건 |
|---|---|
| **배포 완료** | 파이프라인에서 성공한 배포를 보고했습니다. |
| **실패** | 파이프라인에서 실패한 배포를 보고했습니다. 배포에 실패해도 실행 중인 버전은 바뀌지 않습니다. |
| **롤백됨** | 파이프라인에서 롤백을 보고했거나, 다른 버전보다 먼저 실행된 버전을 다시 배포했다고 보고했습니다. 해당 행에는 롤백 직전에 실행 중이던 버전이 표시됩니다. |
| **이전 버전으로 복귀** | 스팬이 파이프라인에서 보고하지 않은 이전 버전으로 돌아갔습니다. 가장 최근에 관측된 버전은 최신 버전보다 먼저 나타났으며, 최신 버전은 가장 최근 관측 시점보다 5분 넘게 앞서 관측이 중단되었습니다. |
| **최초 발생** | 스팬에 파이프라인에서 보고하지 않은 버전이 기록되었습니다. |
| **구성** | 파이프라인이나 도구에서 구성 변경을 보고했습니다. 해당 행에 변경 설명이 표시됩니다. |
| **기능 플래그** | 파이프라인이나 도구에서 기능 플래그 변경을 보고했습니다. 해당 행에 변경 설명이 표시됩니다. |

구성이나 기능 플래그를 변경해도 실행 중인 버전은 바뀌지 않으며, 해당 변경에 대한 별도
지표는 표시하지 않습니다. 인사이트 발생 시점 전후의 변경 사항 목록에 표시합니다. 자세한 내용은
[탐지 시점 전후의 변경 사항](/ko/apm/insights#감지-시점-전후의-변경-사항)을 참조합니다.

보고된 배포에는 커밋, 풀 리퀘스트, CI 실행, 작성자가 표시됩니다. 리포지토리 주소가
http 또는 https이면 GitHub, GitLab, Bitbucket의 커밋 URL 형식에 따라
해당 커밋의 웹 페이지를 엽니다.

각 버전의 최신 행에는 선택한 시간 범위의 요청 수, 오류율, p95와 함께
바로 앞서 처음 관측된 버전과 비교한 판정 결과가 표시됩니다.

| 판정 | 표시 조건 |
|---|---|
| **재발** | 오류율이 1%p 이상 상승하면서 기존의 1.5배 이상이 되었거나, p95가 20% 이상이면서 50 ms 이상 증가했습니다. 판정 뒤에 악화된 지표가 표시됩니다. |
| **개선** | 두 지표 중 하나가 재발 기준에 해당하는 폭만큼 감소했고, 악화된 지표는 없습니다. |
| **변경 없음** | 두 지표 모두 판정 기준에 해당하는 폭만큼 변하지 않았습니다. |
| **요청 수 부족** | 두 버전 중 하나의 요청 처리 수가 버전 비교에 필요한 최소 요청 수보다 적습니다. 기본값은 1,000건입니다. |

판정을 선택하면 **두 버전 비교**에서 해당 버전 두 개를 열고, 응답이 느려진 엔드포인트와
발생 건수가 늘어난 오류를 표시합니다. 재발하거나 개선된 버전은
개요의 최근 배포 목록에도 표시합니다.

## 카나리

카나리 버전과 교체 대상 버전처럼 두 버전이 동시에 실행되면 타임라인 위의
카드에 두 버전을 나란히 표시합니다. 두 버전 모두 서비스의 마지막 스팬을 기준으로
직전 5분 이내에 관측되면 동시에 실행 중인 것으로 판단합니다. 카드는 최신 버전이
처음 관측된 시점부터의 데이터를 기준으로 가장 최근 두 버전을 비교합니다.

- 각 버전이 처리한 요청의 비중
- 각 버전의 요청 수, 오류율, p50, p95, p99
- 이전 버전과 비교한 최신 버전의 판정 결과

## CI에서 배포 보고

파이프라인은 `POST /api/v1/apm/deployments`로 배포를 보고합니다. 요청에는 `apm.deploy` 권한을 사용할 수 있는 API 토큰이
필요합니다. 소유자, 관리자, 편집자에게 이 권한이 있으며, 수집 토큰에 적용되는 **데이터 수집**
정책에도 이 권한이 포함됩니다.

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "version": "2.4.0", "commit": "9f2c1e7a4b3d", "repository": "https://github.com/acme/checkout", "ciUrl": "https://ci.example.com/runs/7"}'
```

| 필드 | 필수 여부 | 설명 |
|---|---|---|
| `service` | 예 | 스팬의 `service.name`에 기록된 서비스 이름입니다. 최대 255자입니다. |
| `version` | 배포 시 필수 | 스팬의 `service.version`에 기록된 배포 버전입니다. 최대 192자입니다. |
| `kind` | 아니요 | `deployment`(기본값), `configuration`, `feature_flag` 중 하나입니다. |
| `namespace` | 아니요 | 서비스의 `service.namespace` 값입니다. 이 값을 지정하지 않은 배포는 모든 네임스페이스에 표시됩니다. |
| `environment` | 아니요 | `deployment.environment.name`에 기록된 환경입니다. 이 값을 지정하지 않은 배포는 모든 환경에 표시됩니다. |
| `status` | 아니요 | `succeeded`(기본값), `failed`, `rolled_back` 중 하나입니다. 배포로 서비스가 `version`으로 돌아간 경우 `rolled_back`을 사용합니다. |
| `commit` | 아니요 | 배포한 커밋입니다. 문자와 숫자를 사용해 최대 64자까지 지정합니다. |
| `repository` | 아니요 | 코드가 있는 리포지토리의 https, http, ssh 또는 git 주소입니다. 최대 512자입니다. 주소에 포함된 비밀번호와 https 주소의 사용자 부분은 `****`로 마스킹하여 저장합니다. |
| `pullRequest` | 아니요 | 풀 리퀘스트의 http 또는 https 링크입니다. |
| `author` | 아니요 | 배포를 실행한 주체입니다. 최대 128자입니다. |
| `ciUrl` | 아니요 | CI 실행의 http 또는 https 링크입니다. |
| `description` | 아니요 | 최대 1,000자입니다. 이벤트에 포인터를 올리면 표시됩니다. |
| `deployedAt` | 아니요 | 배포 시각을 에포크 이후 경과한 마이크로초로 지정합니다. 기본값은 요청 도착 시각입니다. |

서비스와 환경에는 APM에서 사용하는 이름을 지정합니다. 스팬과 마찬가지로 조직의 명명 규칙,
환경 매핑, 별칭을 적용합니다. 자세한 내용은
[APM 설정](/ko/apm/settings)을 참조합니다.

**데이터 소스** 페이지의 **GitHub Actions**, **GitLab CI/CD**,
**Jenkins** 항목에서 워크스페이스 주소가 미리 입력된 아래 절차를 확인할 수 있습니다.

### GitHub Actions

토큰을 리포지토리 시크릿으로 저장한 다음 배포 작업에 단계를 추가합니다. `if: always()`를 지정하면
실패한 배포도 보고합니다.

```yaml
- name: Report the deployment to MoleSignal
  if: always()
  env:
    MOLESIGNAL_TOKEN: ${{ secrets.MOLESIGNAL_TOKEN }}
    DEPLOY_STATUS: ${{ job.status == 'success' && 'succeeded' || 'failed' }}
  run: |
    cat > deployment.json <<EOF
    {
      "service": "checkout",
      "environment": "production",
      "version": "${GITHUB_SHA::12}",
      "status": "$DEPLOY_STATUS",
      "commit": "$GITHUB_SHA",
      "repository": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY",
      "author": "$GITHUB_ACTOR",
      "ciUrl": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID"
    }
    EOF
    curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
      -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
      -H "Content-Type: application/json" \
      --data-binary @deployment.json
```

### GitLab CI/CD

토큰을 `MOLESIGNAL_TOKEN`이라는 마스킹된 CI/CD 변수로 추가한 다음 배포 작업에서
`after_script`로 보고합니다. 이 스크립트는 배포 성공 여부와 관계없이 실행됩니다.

```yaml
deploy:
  stage: deploy
  environment: production
  script:
    - ./deploy.sh
  after_script:
    - |
      if [ "$CI_JOB_STATUS" = "success" ]; then DEPLOY_STATUS=succeeded; else DEPLOY_STATUS=failed; fi
      cat > deployment.json <<EOF
      {
        "service": "checkout",
        "environment": "$CI_ENVIRONMENT_NAME",
        "version": "$CI_COMMIT_SHORT_SHA",
        "status": "$DEPLOY_STATUS",
        "commit": "$CI_COMMIT_SHA",
        "repository": "$CI_PROJECT_URL",
        "author": "$GITLAB_USER_LOGIN",
        "ciUrl": "$CI_PIPELINE_URL"
      }
      EOF
      curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
        -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
        -H "Content-Type: application/json" \
        --data-binary @deployment.json
```

### Jenkins

토큰을 ID가 `molesignal-token`인 **Secret text** 자격 증명으로 추가한 다음
파이프라인의 `post` 블록에서 보고합니다. `post { always }`를 지정하면 실패한 빌드도 보고합니다. `GIT_URL`에 비밀번호가 포함되어 있으면
배포 기록을 저장할 때 마스킹합니다.

```groovy
post {
  always {
    script {
      writeFile file: 'deployment.json', text: groovy.json.JsonOutput.toJson([
        service: 'checkout',
        environment: 'production',
        version: env.GIT_COMMIT.take(12),
        status: currentBuild.currentResult == 'SUCCESS' ? 'succeeded' : 'failed',
        commit: env.GIT_COMMIT,
        repository: env.GIT_URL,
        ci_url: env.BUILD_URL,
      ])
    }
    withCredentials([string(credentialsId: 'molesignal-token', variable: 'MOLESIGNAL_TOKEN')]) {
      sh '''
        curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
          -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
          -H "Content-Type: application/json" \
          --data-binary @deployment.json
      '''
    }
  }
}
```

## 구성 및 기능 플래그 변경 보고

같은 엔드포인트로 구성이나 기능 플래그의 변경을 보고합니다. `kind`를 지정하고
변경 내용을 설명합니다. 버전은 필요하지 않습니다.

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "kind": "feature_flag", "description": "new_checkout on for 10% of users"}'
```

## 문제 해결

| 증상 | 확인 사항 |
|---|---|
| 보고한 배포가 타임라인에 표시되지 않습니다 | 시간 범위에 `deployedAt`이 포함되어야 하며, `service`는 APM에서 사용하는 서비스 이름과 일치해야 합니다. 환경을 지정한 배포는 해당 환경에서만 표시됩니다. |
| 배포와 배포된 버전이 별도의 두 행으로 표시됩니다 | 보고한 `version`이 스팬의 `service.version`과 다릅니다. 동일한 값을 보고합니다. |
| 배포 엔드포인트가 `403`을 반환합니다 | 토큰에 `apm.deploy` 사용 권한이 없습니다. 토큰 범위에 해당 권한이 빠져 있거나 토큰에 연결된 멤버 또는 서비스 계정에 해당 권한이 없습니다. |
| 배포 엔드포인트가 `400`을 반환합니다 | 필드가 위 표의 제한을 충족하지 않습니다. 오류 메시지에서 해당 필드를 확인합니다. |
