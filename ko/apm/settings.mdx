**APM → 설정**에는 조직이 APM에 대해 설정하는 항목이 있습니다. 각 카드는 **저장**을 눌러 개별 저장하며,
**변경 사항 되돌리기**는 그 이후 입력한 내용을 버립니다. 저장하려면 `apm.settings.manage` 권한이 필요하며, 소유자,
관리자, 편집자가 이 권한을 보유합니다. 권한이 없으면 페이지에서 설정을 읽을 수만 있고 변경할 수 없습니다.

저장된 설정은 저장한 노드에서는 즉시 적용되고 다른 노드에서는 30초 이내에 적용됩니다.
이름 지정 규칙과 환경 매핑은 이후 읽는 스팬에 적용됩니다. APM이 이미 보관한
이름은 그대로 유지됩니다. 상태 임계선, 기본 Apdex 임계값, 별칭, 카탈로그 요구 사항은
이미 보관된 데이터를 포함해 모든 읽기에 적용됩니다.

## 수집 품질

첫 번째 카드는 지난 하루를 조회하고 수정이 필요한 항목과 설정으로 개선할 수 있는 항목을 나열합니다:

| 발견 사항 | 의미 |
|---|---|
| 카디널리티 한도 초과 | 엔드포인트 같은 종류의 이름이 시간당 한도를 초과해 나머지가 **기타**로 집계되었습니다. **한도 상향**을 누르면 플랫폼 설정을 관리하는 사용자에게만 한도 카드가 열립니다. |
| APM에서 누락된 스팬 | 프로젝션에 하루 중 빈 구간이 생겼습니다. |
| APM 지연 | 마지막 완전한 분 데이터가 몇 분 이상 지연되었습니다. |
| 속성을 보고하지 않는 서비스 | `deployment.environment.name`, `service.version` 또는 `service.instance.id`가 없는 서비스입니다. **설정**을 누르면 OpenTelemetry 가이드가 열립니다. |
| 대소문자만 다른 환경 | `Production`과 `production` 같은 경우입니다. **모두 같은 이름으로 읽기**를 누르면 환경 카드에 매핑이 추가됩니다. |
| 생성된 접미사가 붙은 이름 | 파드 이름 형태로 명명된 서비스입니다(예: `checkout-7d9f8b6c5-x2x7k`). **이름 지정 규칙 추가**를 누르면 이를 `checkout`으로 읽는 규칙을 추가합니다. |
| 트레이스 ID가 없는 로그 | 지난 1시간 동안 로그 라인에 트레이스 ID가 없어 로그에서 해당 트레이스로 이어지지 않는 서비스입니다. **설정**을 누르면 OpenTelemetry 로그 가이드가 열립니다. |
| 트레이스와 부분적으로만 연결된 로그 | 지난 1시간 동안 한 서비스의 로그 라인 중 90% 미만에 트레이스 ID가 있거나, 해당 트레이스 ID 표본 중 80% 미만이 보관된 트레이스에서 발견됩니다. |
| 실행 위치를 알리지 않는 서비스 | 서비스의 어떤 인스턴스도 `host.name`, `k8s.pod.name`, `k8s.node.name` 또는 `container.id`를 보고하지 않습니다. **설정**을 누르면 OpenTelemetry 트레이스 가이드가 열립니다. |
| APM이 알지 못하는 이름 | 이름 지정 규칙과 별칭을 적용한 후에도 어떤 APM 서비스와도 일치하지 않는 로그 또는 메트릭의 서비스 이름입니다. **이름 지정 규칙**을 누르면 이름 지정 규칙 카드로 이동합니다. |
| 보고된 변경 사항 없음 | 지난주 동안 서비스가 배포, 구성 변경 또는 기능 플래그를 보고하지 않았습니다. **변경 사항 보고**를 누르면 배포 파이프라인 가이드가 열립니다. |

마지막 다섯 가지 발견 사항은 [상관관계 보고서](/ko/api/apm#서비스가-다른-데이터와-얼마나-잘-연결되는지-확인)에서 나오며,
이 보고서는 지난 1시간의 로그와 메트릭, 지난주 동안의 변경 사항을 살펴봅니다.

카드에 추가한 제안은 **저장**할 때까지 그 카드에 남아 있습니다.

## 상태 및 임계값

| 설정 | 기본값 | 범위 |
|---|---|---|
| 오류율, **경고 임계값** 및 **심각 임계값** | 2% 및 10% | 경고 임계선은 0보다 크고 심각 임계선보다 작으며, 심각 임계선은 최대 100%입니다. |
| P95, **경고 임계값** 및 **심각 임계값** | 500 ms 및 2,000 ms | 경고 임계선은 0보다 크고 심각 임계선보다 작으며, 심각 임계선은 최대 10분입니다. |
| **기본 Apdex** T | 500 ms | 0보다 크고 최대 1분입니다. 카탈로그 항목에 자체 T가 설정된 서비스는 해당 값을 유지합니다. 개요에서는 이 T로 모든 서비스를 함께 집계합니다. |
| **장시간 작업**, P99 기준 | 1,000 ms | 1 ms~10분입니다. 엔드포인트 목록은 이 P99부터 엔드포인트를 장시간 작업으로 집계합니다. |

이 임계선은 카탈로그의 각 서비스, 서비스 페이지, 맵, 그리고
개요의 상태 추세에서 서비스 상태를 결정합니다.

## 카탈로그 요구 사항

**팀**, **소유자**, **리포지토리** 각각에 대해 카탈로그에서 요구하는 등급은 다음과 같습니다.
**필수 아님** 또는 등급과 그 이상의 모든 등급입니다. 해당 등급의 서비스에 해당 필드가 없으면
카탈로그에서 누락된 필드와 함께 **필요**로 표시됩니다. 등급이 없는 서비스에는 아무것도 요구하지 않습니다.

## 서비스 이름 지정

이름 지정 규칙은 스팬을 읽을 때 서비스 이름을 다시 작성합니다. 각 규칙은 정규식과
대체 문자열로 구성되며, 대체 문자열에서 표현식의 그룹을 `$1` 또는 `${name}`으로 참조할 수 있습니다. 규칙은
순서대로 시도되며, 이름과 일치하는 첫 번째 표현식이 이름을 다시 작성합니다. 빈 이름으로 다시 작성하면
이름이 유지됩니다. **서비스 이름 테스트**는 이름이 어떻게 읽힐지 보여줍니다.

조직은 최대 20개의 규칙을 유지할 수 있습니다. 트레이스는 스팬이 지닌 이름을 유지하므로 트레이스 검색에서는
규칙 적용 전 이름을 사용합니다.

## 환경 매핑

각 매핑은 스팬을 읽을 때 한 방식으로 명명된 환경을 다른 이름으로 읽으며, 대소문자를 구분하지 않습니다. 예를 들어
`Production`과 `prod`를 모두 `production`으로 읽습니다. 환경은 최대 한 번만 매핑되며,
조직은 최대 50개의 매핑을 유지할 수 있습니다.

## 비즈니스 컨텍스트

조직이 텔레메트리를 읽는 기준이 되는 비즈니스 키(예: 테넌트 또는 플랜)와
스팬, 로그, RUM 이벤트에서 각 키를 전달하는 필드, 그리고 가장 중요한 값을 말합니다. 서비스 페이지는
이를 기준으로 요청을 분할하며, 인시던트는 영향을 받은 값을 나열합니다. [비즈니스 컨텍스트](/ko/business-context)를 참조하세요.

## 서비스 별칭

별칭은 서비스를 이전 이름으로 지정하며, 각 이름에는 네임스페이스가 있고 비워 두면 `default`입니다.
별칭이 보고한 내용은 모든 APM 페이지에서 서비스의 내용으로 읽히며, 서비스가
자체적으로 보고한 내용과 병합됩니다. 이미 보관된 데이터도 포함됩니다. 서비스 맵과 배포 보고서도
별칭을 따릅니다. 별칭을 제거하면 두 이름을 다시 별개로 읽습니다.

서비스는 자기 자신의 별칭이 될 수 없고, 이름은 한 번만 별칭이 될 수 있으며, 별칭은 다른 별칭으로 이어지지 않습니다.
조직은 최대 100개의 별칭을 유지할 수 있습니다. 이전 링크에서 별칭 자체로 연 페이지는
여전히 별칭 자체의 데이터를 읽습니다.

## 카디널리티 한도

`sys.settings.limits.manage` 권한을 보유한 사용자에게 표시됩니다. 한도는 플랫폼 전체에 적용됩니다. APM은 매시간
각 종류별로 최대 이 개수만큼 구분해 보관하고 나머지는 **기타**로 집계합니다.

| 한도 | 기본값 |
|---|---|
| 조직당 서비스 | 200 |
| 서비스당 엔드포인트 | 32 |
| 서비스당 종속성 | 16 |
| 종속성당 작업 | 32 |
| 서비스당 오류 그룹 | 16 |
| 서비스당 버전 | 16 |
| 서비스당 인스턴스 | 256 |

각 한도는 1부터 100,000까지의 정수입니다. 모든 노드는 30초마다 한도를 다시 읽습니다.

## 트레이스 샘플링

`sys.telemetry.read` 권한을 보유한 사용자에게 표시되며, 변경하려면 `sys.telemetry.manage` 권한이 필요합니다. 정책은
트레이스가 종료된 후 플랫폼이 어떤 트레이스를 보관할지 결정합니다:

- **일반 트레이스 보존 비율**은 규칙, 오류, 지연 중 어느 것도 보관 대상으로 삼지 않는 트레이스 중 보관하는 비율입니다.
  기본값은 10%입니다.
- 각 규칙은 스팬이 규칙이 지정한 **서비스**, **라우트**, **작업**을 지니고, 길이가 **최소 소요 시간(ms)** 이상이며,
  **오류만**이 설정된 경우 실패한 트레이스와 일치합니다. 그런 다음 규칙은 해당 트레이스를 보관하거나,
  삭제하거나, 일부 비율만 보관합니다. 규칙은 일반 보존 비율보다 먼저 순서대로 시도됩니다.

저장하면 새 정책 버전이 모든 노드에 게시됩니다. APM은 샘플링 전에 모든 트레이스를 집계하므로
정책은 APM 수치를 바꾸지 않으며, 열 수 있는 트레이스만 바꿉니다.
