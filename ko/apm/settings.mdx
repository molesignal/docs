**APM → 설정**에서 조직의 APM 설정을 관리합니다. 각 카드에서 개별적으로
**저장**을 선택해 저장하고, **변경 사항 되돌리기**를 선택해 마지막 저장 이후의 입력을 취소합니다. 저장하려면 `apm.settings.manage` 권한이 필요하며, 소유자,
관리자, 편집자에게 이 권한이 있습니다. 이 권한이 없으면 설정을 조회할 수만 있습니다.

저장한 설정은 저장을 처리한 노드에 즉시 적용되며, 다른 노드에는 30초 이내에 적용됩니다.
이름 지정 규칙과 환경 매핑은 저장 이후에 읽는 스팬에 적용됩니다. APM이 이미 보존한 데이터의
이름은 그대로 유지됩니다. 상태 임계값, 기본 Apdex 임계값, 별칭, 카탈로그 요구 사항은
이미 보존한 데이터를 포함해 모든 조회에 적용됩니다.

## 수집 품질

첫 번째 카드는 최근 24시간의 데이터를 확인해 수정이 필요한 항목과 설정으로 개선할 수 있는 항목을 표시합니다.

| 감지 항목 | 의미 |
|---|---|
| 카디널리티 한도 초과 | 엔드포인트 등 특정 유형의 이름 수가 시간당 한도를 초과해 나머지 이름을 **기타**로 집계했습니다. 플랫폼 설정 관리자가 **한도 상향**을 선택하면 한도 카드로 이동합니다. |
| APM 스팬 누락 | 집계 과정에서 최근 24시간 데이터의 일부 구간이 누락되었습니다. |
| APM 처리 지연 | 처리를 완료한 마지막 1분 구간이 현재보다 몇 분 이상 뒤처져 있습니다. |
| 속성을 보고하지 않는 서비스 | `deployment.environment.name`, `service.version`, `service.instance.id` 중 누락된 속성이 있는 서비스입니다. **설정**을 선택하면 OpenTelemetry 가이드가 열립니다. |
| 대소문자만 다른 환경 | 예를 들어 `Production`과 `production`입니다. **모두 다음으로 처리**를 선택하면 환경 카드에 매핑을 추가합니다. |
| 자동 생성 접미사가 붙은 이름 | `checkout-7d9f8b6c5-x2x7k`처럼 Pod 이름 형식을 따르는 서비스입니다. **이름 지정 규칙 추가**를 선택하면 해당 이름을 `checkout`으로 처리하는 규칙을 추가합니다. |

카드에 추가한 제안은 **저장**을 선택할 때까지 적용되지 않습니다.

## 상태 및 임계값

| 설정 | 기본값 | 범위 |
|---|---|---|
| 오류율, **경고 임계값** 및 **심각 임계값** | 2% 및 10% | 경고 임계값은 0보다 크고 심각 임계값보다 작아야 합니다. 심각 임계값은 100% 이하여야 합니다. |
| P95, **경고 임계값** 및 **심각 임계값** | 500 ms 및 2,000 ms | 경고 임계값은 0보다 크고 심각 임계값보다 작아야 합니다. 심각 임계값은 10분 이하여야 합니다. |
| **기본 Apdex** T | 500 ms | 0 초과, 1분 이하입니다. 서비스의 카탈로그 항목에 별도의 T를 설정한 경우 해당 값을 유지합니다. 개요에서는 이 기본 T를 사용해 모든 서비스를 함께 평가합니다. |
| **장시간 작업**, P99 임계값 | 1,000 ms | 1 ms 이상 10분 이하입니다. 엔드포인트 목록에서는 P99가 이 임계값 이상인 엔드포인트를 장시간 작업으로 집계합니다. |

이 임계값에 따라 카탈로그, 서비스 페이지, 서비스 맵, 개요의 상태 추세에 표시할
각 서비스의 상태를 결정합니다.

## 카탈로그 요구 사항

**팀**, **소유자**, **리포지토리** 각각에 대해 카탈로그에서 필수로 요구할 최소 등급을 설정합니다.
**필수 아님**을 선택하거나 특정 등급을 선택해 해당 등급 이상에 적용합니다. 필수 대상인 서비스에 해당 필드가 없으면
카탈로그에 **필요**와 함께 누락된 필드를 표시합니다. 등급이 없는 서비스에는 필수 필드가 없습니다.

## 서비스 이름 지정

이름 지정 규칙은 스팬을 읽을 때 서비스 이름을 바꿉니다. 각 규칙은 정규 표현식과
대체 문자열로 구성하며, 대체 문자열에서 `$1` 또는 `${name}`으로 정규 표현식의 그룹을 참조할 수 있습니다. 규칙을
순서대로 확인하고, 이름과 일치하는 첫 번째 규칙으로 이름을 바꿉니다. 결과가 빈 문자열이면
기존 이름을 유지합니다. **서비스 이름 테스트**에서 이름이 어떻게 바뀌는지 확인할 수 있습니다.

조직당 규칙을 최대 20개까지 보존합니다. 트레이스는 스팬에 기록된 이름을 그대로 보존하므로 트레이스를 검색할 때는
규칙을 적용하기 전 이름을 사용합니다.

## 환경 매핑

각 매핑은 스팬을 읽을 때 대소문자를 구분하지 않고 환경 이름을 다른 이름으로 처리합니다.
예를 들어 `Production`과 `prod`를 모두 `production`으로 처리할 수 있습니다. 각 환경은 한 번만 매핑할 수 있으며,
조직당 매핑을 최대 50개까지 보존합니다.

## 서비스 별칭

별칭은 서비스의 이전 이름을 연결합니다. 양쪽에 네임스페이스를 지정하며, 비워 두면 `default`를 사용합니다.
모든 APM 페이지에서 별칭으로 보고된 데이터를 해당 서비스의 데이터로 처리합니다. 이미 보존한 데이터를 포함해 서비스가
직접 보고한 데이터와 병합합니다. 서비스 맵과 배포 보고서에도
별칭을 적용합니다. 별칭을 삭제하면 두 이름의 데이터를 다시 별도로 조회합니다.

서비스 자체를 별칭으로 지정할 수 없으며, 한 이름은 한 번만 별칭으로 지정할 수 있습니다. 별칭이 다른 별칭을 가리킬 수는 없습니다.
조직당 별칭을 최대 100개까지 보존합니다. 이전 링크로 별칭 자체의 페이지를 열면
해당 별칭의 데이터만 표시합니다.

## 카디널리티 한도

`sys.settings.limits.manage` 권한이 있는 경우에만 표시합니다. 한도는 플랫폼 전체에 적용됩니다. APM은 매시간
각 유형의 항목을 한도까지만 개별 집계하고, 나머지는 **기타**로 집계합니다.

| 한도 | 기본값 |
|---|---|
| 조직당 서비스 | 200 |
| 서비스당 엔드포인트 | 32 |
| 서비스당 종속성 | 16 |
| 종속성당 작업 | 32 |
| 서비스당 오류 그룹 | 16 |
| 서비스당 버전 | 16 |
| 서비스당 인스턴스 | 256 |

각 한도는 1부터 100,000까지의 정수입니다. 모든 노드는 30초마다 한도를 다시 읽습니다.

## 트레이스 샘플링

`sys.telemetry.read` 권한이 있는 경우에만 표시합니다. 변경하려면 `sys.telemetry.manage` 권한이 필요합니다. 이 정책은
종료된 트레이스 중 플랫폼이 보존할 트레이스를 결정합니다.

- **일반 트레이스 보존 비율**은 규칙, 오류 또는 지연으로 인해 보존되지 않은 트레이스 중 보존할 비율입니다.
  기본값은 10%입니다.
- 각 규칙은 스팬의 **서비스**, **라우트**, **작업**이 규칙에 지정한 값과 일치하고,
  소요 시간이 **최소 소요 시간(ms)** 이상인 트레이스에 적용합니다. **오류만**을 설정하면 실패한 트레이스만 일치합니다. 규칙에 따라 일치하는 트레이스를 모두 보존하거나,
  삭제하거나, 일정 비율만 보존합니다. 일반 트레이스 보존 비율을 적용하기 전에 규칙을 순서대로 확인합니다.

저장하면 모든 노드에 새 버전의 정책을 배포합니다. APM은 샘플링 전에 모든 트레이스를 집계하므로,
정책은 APM 지표에 영향을 주지 않고 열어 볼 수 있는 트레이스만 결정합니다.
