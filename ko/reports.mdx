**보고서**를 열어 보고서 일정, 생성 내역, 재사용 가능한 템플릿을 관리합니다.

| 탭 | 내용 |
|---|---|
| **일정** | 모든 보고서의 소스, 일정, 다음 실행, 마지막 결과, 수신자, 상태를 표시합니다. 상단에는 실행 중인 보고서 수, 24시간 이내 전송 예정 건수, 최근 30일 성공률, 미해결 실패 건수를 표시합니다. |
| **생성 내역** | 생성된 각 보고서와 전송 내역을 표시합니다. **오류 보기**에서 실패 원인을 확인할 수 있습니다. |
| **템플릿 라이브러리** | 기본 제공 템플릿과 사용자 지정 템플릿을 표시합니다. **템플릿 사용**을 선택해 해당 템플릿으로 보고서를 만듭니다. |

## 보고서 만들기

**새 보고서**를 선택합니다. 보고서 작성 화면은 세 단계로 구성되며, 오른쪽 미리보기에서
작성 중인 보고서의 구조를 확인할 수 있습니다.

<Steps>
  <Step title="콘텐츠 및 범위">
    **보고서 이름**과 **용도**를 입력합니다. **소스 유형**으로 대시보드 또는 저장된 뷰를
    선택하고 **데이터 소스**를 지정합니다. **데이터 범위**로 지난 1시간, 24시간, 7일,
    30일, 어제, 지난주, 지난달 또는 **사용자 지정**을 선택합니다.
  </Step>
  <Step title="생성 일정">
    **생성 주기**를 매시간, 6시간마다, 12시간마다, 24시간마다 또는 7일마다로 설정하고
    **보고서 시간대**를 선택합니다. **고급 cron**에는 cron 표현식을 입력할 수 있지만, 현재는 24시간마다 실행됩니다.
    시간 간격을 사용하는 것이 좋습니다.
  </Step>
  <Step title="전송">
    **전송 대상**으로 이메일 주소, HTTPS 웹훅 URL 또는 S3 경로를 추가합니다. 대상마다
    전송 결과를 별도로 기록합니다. **출력 형식**을 선택합니다. 보고서를 일시 중지 상태로 저장하려면
    **저장 후 활성화**를 끕니다.
  </Step>
</Steps>

**저장 및 활성화**를 선택합니다. **지금 내보내기**를 선택하면 예약된 실행을 기다리지 않고 즉시 보고서를 생성합니다.
보고서에서 **보기**, **편집**, **공유**, **활성화** 또는 **일시 중지**,
**일정 삭제**를 선택할 수 있습니다.

## 콘텐츠 선택

보고서는 대시보드 또는 저장된 뷰를 소스로 사용합니다. 템플릿은 재사용할 소스 유형,
형식, 콘텐츠 기본값을 정의합니다. 일정은 템플릿을 특정 리소스에 연결합니다.

기본 제공 템플릿에는 플랫폼 상태, RUM 사용자 경험, 알림 검토, SLA 준수,
저장된 쿼리 내보내기 등이 포함됩니다.

## 형식 선택

| 형식 | 주요 용도 |
|---|---|
| PDF | 대시보드 또는 저장된 뷰를 헤드리스 방식으로 렌더링합니다. |
| PNG | 협업 도구에서 사용할 이미지를 헤드리스 방식으로 렌더링합니다. |
| CSV | 현재는 정적 보고서 메타데이터를 표 형식으로 제공합니다. |
| JSON | 현재는 자동화에 사용할 정적 보고서 메타데이터를 제공합니다. |
| SVG | 현재는 정적 보고서 요약 카드를 제공합니다. |

PDF와 PNG에는 헤드리스 렌더러가 필요합니다.
`[scheduled_reports.renderer]`에 접속 가능한 웹 기본 URL을 설정합니다. 서버는 임시 콘텐츠를 반환하는 대신 생성된 파일의
시그니처를 검증합니다. 현재 CSV, JSON, SVG는 대시보드나 저장된 뷰를 실행한 결과 행이 아니라 보고서
메타데이터를 포함합니다.

## PDF 또는 PNG 보고서의 구성

PDF 또는 PNG 보고서에는 대시보드 또는 저장된 뷰가 표시되며 주변 웹 UI는 포함되지 않습니다.
탐색 메뉴, 도구 모음, 기타 메뉴는 표시하지 않습니다. 페이지에는 보고서의 범위를 먼저 표시한 뒤
대시보드 또는 저장된 뷰의 결과 행을 표시합니다.

- **페이지 크기.** 페이지 너비는 렌더러의 뷰포트와 같고 높이는 콘텐츠에 맞춥니다. 따라서 PDF는
  한 페이지로 구성되며 패널이나 표의 행이 페이지 경계에서 나뉘지 않습니다. 높이가 16,000
  픽셀을 넘는 콘텐츠는 PNG에서 잘리고 PDF에서는 다음 페이지에 이어서 표시됩니다.
- **모양.** 보고서는 라이트 테마를 사용합니다. 언어와 날짜 및 시간 형식은
  보고서 렌더링에 사용한 사용자 계정의 설정을 따릅니다.
- **시간 범위.** 보고서는 **데이터 범위**를 반영합니다. **지난 24시간**과 **지난 7
  일**은 렌더링 시점에 끝납니다. **어제**, **지난주**,
  **지난달**은 보고서 시간대를 기준으로 온전한 하루, 한 주, 한 달을 각각 포함합니다. 한 주는
  월요일에 시작합니다.
- **시간대.** 헤더, 차트 축, `_timestamp` 열은 시간을
  **보고서 시간대**로 표시합니다. 이 필드에는 모든 IANA 시간대와 각 UTC 오프셋이 표시됩니다. 이름으로 검색해
  원하는 시간대를 찾습니다.
- **실패.** 대시보드나 저장된 뷰를 불러오지 못하거나 저장된 뷰의 쿼리문 실행에 실패하거나
  페이지가 15초 이내에 데이터 로드를 완료하지 못하면 파일을 생성하지 않습니다.
  **지금 내보내기**는 실패 원인을 반환하며, 예약 실행은 수신자별 전송 기록에
  실패 원인을 저장합니다.

### 대시보드

페이지 상단에는 대시보드 제목과 설명을 표시한 뒤 시간 범위,
시간대, 표시되는 각 변수의 값, 생성 시각을 표시합니다. 이어서 대시보드의
레이아웃에 따라 패널을 표시합니다. 데이터 범위가 **사용자 지정**이면 패널에는 지난 1시간의 데이터가 표시됩니다.

### 저장된 뷰

페이지 상단에는 저장된 뷰의 이름을 표시한 뒤 시간 범위, 시간대,
뷰에 지정된 스트림(있는 경우), 행 수, 생성 시각을 표시합니다. 이어서 쿼리 언어 이름 아래에
쿼리문을 표시하고, 쿼리문이 반환한 행을 표로 표시합니다.

- **시간 범위.** 데이터 범위가 **사용자 지정**이면 렌더링 시점에 끝나는 저장된 뷰의 **기본 시간 범위**를
  대상으로 쿼리문을 실행합니다.
- **행.** 표에는 최대 200개 행을 표시합니다. SQL 문이 200개보다 많은 행을 반환하면 행 수를
  **처음 200개만**으로 표시합니다. PromQL 문은 범위 쿼리로 실행하고, 200개 행에 맞도록 각
  시계열의 데이터 포인트를 균등한 간격으로 샘플링합니다.
- **열.** 표에는 결과의 각 열에 대응하는 열을 하나씩 표시하며, 표 너비는
  페이지 너비를 넘지 않습니다. 긴 값은 줄바꿈합니다. `_timestamp`를 제외한 값은 반환된 그대로 표시합니다. 값이 없으면
  `—`로 표시합니다.
- **스트림.** SQL 문은 저장된 뷰의 **스트림**에서 실행합니다. 스트림을 지정하지 않은 뷰는
  **저장된 뷰** 페이지에서 **열기**를 선택할 때와 마찬가지로, 쿼리를 허용하는 첫 번째 로그 스트림을
  사용합니다. 워크스페이스에 해당 스트림이 없으면 보고서 생성에 실패합니다.
- **빈 결과.** 쿼리문이 행을 반환하지 않아도 보고서를 생성합니다. 보고서에는
  해당 시간 범위에 행이 없다고 표시합니다.

## 일정 설정 및 전송

데이터 범위, `every:<n><s|m|h|d>` 간격, 출력 형식 및 한 명 이상의
수신자를 설정합니다. API 필드 이름은 `cron`이지만, 5개 필드로 구성된 cron 표현식은 파싱하지 않습니다.
현재 인식할 수 없는 값은 24시간 간격으로 처리합니다. 수신자 유형은 다음과 같습니다.

- `webhook`: 생성한 바이트를 HTTP(S) URL로 POST 요청을 통해 전송합니다.
- `s3`: MoleSignal에 구성한 오브젝트 스토리지의 `reports/<organization id>/<path>/` 아래에 `<report id>-<time>.<extension>`을 저장합니다.
  `<path>`는 `s3://` 뒤에 오는 대상 경로입니다.
- `email`: 현재 주소를 검증하고 기록하지만 SMTP로 메일을 전송하지 않습니다.

각 수신자의 전송 기록에는 상태, 시도 횟수, 오류 세부 정보가 개별적으로 표시됩니다.
구성을 삭제하지 않고 일정을 일시 중지할 수 있습니다.

<Warning>
  현재 `email` 수신자 유형으로는 보고서를 전송할 수 없습니다. 예약 보고서의 SMTP 전송 기능을 지원할 때까지 웹훅 또는
  구성된 오브젝트 스토리지 접두사를 사용합니다.
</Warning>

### 예약 보고서에 적용하는 액세스 권한

예약된 PDF 또는 PNG를 전송할 때는 로그인한 상태로 보고서를 마지막으로 저장한 사용자의 권한으로
보고서 페이지를 렌더링합니다. 보고서에는 실행 시점에 해당 사용자가 읽을 수 있는 내용이 표시됩니다.

- **사용자 확인 위치.** **보고서**에서 보고서를 엽니다. 대화 상자 하단에 **실행
  사용자** 레이블과 사용자 이름이 표시됩니다. `reports.schedule` 권한이 없는 사용자도 **보기**로
  보고서를 열어 같은 항목을 확인할 수 있습니다.
- **저장.** 일정을 활성화하거나 일시 중지하기만 해도 저장할 때마다 실행 사용자를 지정합니다.
  `reports.schedule` 권한이 있는 사용자가 보고서를 저장하면 해당 사용자가 실행 사용자가 됩니다. 보고서가
  다른 사용자의 권한으로 실행되는 경우, 대화 상자의 **변경 사항 저장** 옆에 저장 후에는 저장한 사용자의 권한으로
  보고서가 실행된다는 안내가 표시됩니다. **일정** 목록의 스위치에도 같은 안내가 표시됩니다.
- **API.** 예약 보고서는 실행 사용자의 ID를 `runAsUserId`로, 해당 사용자의 표시 이름과
  이메일 주소를 `runAsUser`로 반환합니다. 보고서에 실행 사용자가 없거나
  해당 사용자 계정이 더 이상 존재하지 않으면 `runAsUser`는 `null`입니다.
- **실행할 때마다 확인하는 항목.** 실행 사용자가 더 이상 조직에 로그인할 수 없으면 실행에 실패합니다.
  계정이 비활성화되거나 삭제된 경우, 조직 멤버십이 제거된 경우, 조직이 비활성화된 경우가 이에 해당합니다.
  실행 사용자가 대시보드(`dashboards.read`) 또는 저장된 뷰(`saved_views.read`)를 더 이상 읽을 수 없거나,
  저장된 뷰에서 스트림을 더 이상 쿼리할 수 없는 경우에도
  (`streams.query`) 실행에 실패합니다. 각 수신자의 전송 기록에 사용자 이름과 실패 사유가 표시됩니다.
- **API 토큰.** API 토큰에는 발급 사용자의 권한이 아니라 단일 역할의 권한이 적용되므로
  API 토큰으로 저장한 보고서에는 실행 사용자가 없습니다. 이런 보고서의 PDF 및 PNG
  전송은 로그인한 사용자가 보고서를 저장할 때까지 실패합니다. CSV, JSON, SVG
  전송은 페이지를 렌더링하지 않으므로 실행 사용자가 필요하지 않습니다.
- **세션.** 헤드리스 브라우저는 10분 동안 유효한 세션을 사용하며, 페이지를 인쇄한 후
  브라우저에서 세션을 삭제합니다.

**지금 내보내기**와 **공유**는 요청을 보낸 사용자의 권한으로 보고서를 렌더링합니다.

## 내보내기 및 공유

**지금 내보내기**를 사용해 저장된 보고서에서 다운로드 파일을 생성합니다. **공유**를 사용해
인증이 필요한 공유, 워크스페이스 간 공유 또는 제한된 공개 공유를 설정합니다. 공개 보고서에 비밀번호를 요구할 수 있으며,
워크스페이스 정책으로 CSV 다운로드를 차단할 수 있습니다.

## 권한

- `reports.read`: 일정, 템플릿 및 기록을 조회합니다.
- `reports.create`: 보고서를 생성합니다.
- `reports.edit`: 콘텐츠와 전송 설정을 수정합니다.
- `reports.schedule`: 일정을 활성화하거나 일시 중지하거나 실행합니다.
- `reports.delete`: 보고서를 삭제합니다.
