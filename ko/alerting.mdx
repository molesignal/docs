**알림**을 열어 탐지부터 확인, 에스컬레이션, 해결까지 진행합니다.
[규칙](/ko/alerting/rules)은 쿼리나 수치를 모니터링하고 조건이 충족되면 [인시던트](/ko/alerting/incidents)를 생성합니다.
[알림 소스](/ko/alerting/sources)는 다른 시스템에서 알림을 수신하면 인시던트를 생성합니다.
[알림 라우팅](/ko/alerting/routing)은 새 인시던트에 배정할 팀과 적용할 에스컬레이션 정책을 결정합니다.
인시던트의 [에스컬레이션 정책](/ko/alerting/on-call#에스컬레이션-정책)은
지정된 담당자와 [온콜 일정](/ko/alerting/on-call#온콜-일정)에 따라 호출을 보냅니다.
아무도 인시던트를 확인하지 않으면 다음 단계로 넘어갑니다. [알림 채널](/ko/notification-channels)은
각 호출을 전달합니다. [음소거](/ko/alerting/silences)는 유지보수 중 알림을 일시 중지합니다.
[의미 기반 그룹](/ko/alerting/silences#시맨틱-그룹)은 관련 인시던트를 하나로 묶습니다.

## 알림 센터

사이드 메뉴에서는 페이지를 용도에 따라 다섯 그룹으로 나눕니다. 넓은 페이지에 화면 너비를 모두 사용하려면
메뉴의 검색 영역에서 메뉴를 접습니다.

| 그룹 | 페이지 | 용도 | 가이드 |
|---|---|---|---|
| 대응 | **인시던트** | 현재 발생한 인시던트를 확인, 음소거, 해결, 조사합니다. | [인시던트](/ko/alerting/incidents) |
|  | **기록** | 과거 인시던트를 서비스와 상태별로 검색합니다. | [기록](/ko/alerting/incidents#기록) |
|  | **사후 분석** | 인시던트의 내부 사후 분석과 후속 조치 항목, 주요 인시던트 설정을 관리합니다. | [주요 인시던트 및 사후 분석](/ko/alerting/major-incidents) |
|  | **인사이트** | 인시던트 발생 건수, 복구 시간, 알림이 잦은 규칙, 영향을 받은 서비스, 대응 현황, 온콜 업무 부담을 파악합니다. | [인사이트](/ko/alerting/incidents#인사이트) |
| 탐지 | **규칙** | 임계값, 예측, 이상치, 복합, 하트비트, 이상 탐지, 실시간 규칙을 설정합니다. | [알림 규칙](/ko/alerting/rules) |
|  | **탐색** | APM 지표의 급변, 새 버전의 성능 저하, 프런트엔드 오류의 신규 발생 및 재발, 오류 로그 급증, 호스트 이상을 규칙 없이 탐지합니다. | [탐색](/ko/alerting/discovery) |
| 노이즈 감소 | **소스** | Alertmanager, Grafana, Datadog, PagerDuty, Zabbix, 클라우드 모니터링 서비스(Alibaba Cloud, Tencent Cloud, Amazon CloudWatch), 이메일 또는 API에서 알림을 받습니다. | [외부 알림](/ko/alerting/sources) |
| 노이즈 감소 | **그룹** | 의미 기반 그룹으로 관련 인시던트를 하나로 묶습니다. | [의미 기반 그룹](/ko/alerting/silences#시맨틱-그룹) |
|  | **알림 억제** | 더 심각한 인시던트나 업스트림 인시던트가 활성 상태인 동안 덜 심각한 인시던트의 알림을 억제합니다. | [알림 억제](/ko/alerting/inhibition) |
|  | **음소거 정책** | 조건에 맞는 인시던트의 알림을 일시 중지합니다. | [음소거 정책](/ko/alerting/silences#음소거-정책) |
| 알림 전송 | **라우팅** | 새 인시던트에 배정할 팀과 적용할 에스컬레이션 정책을 결정합니다. | [알림 라우팅](/ko/alerting/routing) |
|  | **에스컬레이션** | 호출 대상과 순서, 다음 단계로 넘어갈 시점을 설정합니다. | [에스컬레이션 정책](/ko/alerting/on-call#에스컬레이션-정책) |
|  | **온콜 일정** | 교대 순번, 임시 대체 근무, 근무 교환, 캘린더 구독을 관리합니다. | [온콜 일정](/ko/alerting/on-call#온콜-일정) |
| 후속 조치 | **문제 해결** | 인시던트에서 클릭 한 번으로 HTTP 및 Kubernetes 복구 조치를 요청하고 승인 후 실행합니다. | [문제 해결](/ko/alerting/remediation) |
|  | **티켓** | Jira, ServiceNow 또는 Meegle을 연결해 인시던트 티켓을 생성하고 상태를 동기화합니다. | [티켓](/ko/alerting/tickets) |

고객에게 인시던트와 유지보수 소식을 알리는 상태 페이지는 별도 모듈입니다.
[상태 페이지](/ko/status-pages)를 참조합니다.

## 알림 설정

워크스페이스에서 첫 호출을 받으려면 일반적으로 다음 순서로 설정합니다.

<Steps>
  <Step title="채널 연결">
    이메일, 메신저 앱, 전화 및 SMS 등의 커넥터를
    [설정 → 알림 → 커넥터](/ko/notification-channels)에서 구성합니다. 구성원은
    [계정 설정 → 알림](/ko/account#알림)에서 개인 알림 수단을 연결합니다.
  </Step>
  <Step title="온콜 일정 구성">
    팀의 교대 순번을 반영한 [온콜 일정](/ko/alerting/on-call#일정-생성)을 생성합니다.
  </Step>
  <Step title="기본 에스컬레이션 정책 생성">
    온콜 일정의 담당자를 먼저 호출하고 다음으로 팀 리더를 호출하는 `default` 정책을 생성합니다. 규칙 편집기에 저장한 규칙은
    [라우팅](/ko/alerting/routing)에서 팀 온콜 정책을 찾지 못하면 이 정책을 사용합니다. [기본 정책](/ko/alerting/on-call#기본-정책)을 참조합니다.
  </Step>
  <Step title="규칙 생성 및 테스트">
    [규칙 편집기](/ko/alerting/rules#임계값-규칙-생성)에서 사전 설정을 선택하고
    실제 데이터로 테스트한 후 저장합니다.
  </Step>
  <Step title="모의 훈련">
    [규칙 트리거](/ko/api/alerting/trigger-rule)로 규칙을 수동으로 트리거합니다.
    호출이 전달되고 에스컬레이션이 다음 단계로 진행되며 인시던트를 확인하면 중단되는지 점검합니다.
  </Step>
</Steps>

[운영 환경 알림을 조치 가능하게 만들기](/ko/best-practices/actionable-alerts) 및
[온콜 및 알림 설정](/ko/best-practices/on-call-setup)에서 알림을 보낼 조건과
라우팅 방법을 확인합니다.

## 권한

| 권한 | 허용 작업 |
|---|---|
| `alerts.incidents.read` | 인시던트와 기록, 인사이트를 조회합니다. |
| `alerts.incidents.acknowledge` | 인시던트와 인시던트 그룹을 확인, 해결하거나 일시 보류합니다. |
| `alerts.incidents.update` | 인시던트를 재배정하고 대응 담당자를 추가하며 심각도를 변경하고 메모를 작성합니다. 대응 역할, 작업, 상태 업데이트도 관리합니다. |
| `alerts.incidents.escalate` | 인시던트를 에스컬레이션하거나 병합하고 주요 인시던트를 선언합니다. |
| `alerts.incidents.create`, `alerts.incidents.silence` | 인시던트를 수동으로 생성하거나 음소거합니다. |
| `alerts.incidents.remediate`, `alerts.incidents.tickets`, `alerts.incidents.rca` | 인시던트의 문제 해결을 시작하고 티켓을 생성하며 근본 원인을 기록합니다. |
| `alerts.rules.read`, `alerts.rules.manage` | 규칙을 조회, 생성, 변경합니다. |
| `alerts.routing.read`, `alerts.routing.manage` | 라우팅 규칙과 팀 온콜 정책을 조회하고 변경합니다. |
| `alerts.escalations.read`, `alerts.escalations.manage`, `alerts.escalations.delete` | 에스컬레이션 정책을 조회, 변경, 삭제합니다. |
| `alerts.sources.read`, `alerts.sources.manage` | 알림 소스를 조회하고 변경합니다. |
| `alerts.mutes.read`, `alerts.mutes.manage` | 음소거를 조회, 생성, 변경, 삭제합니다. |
| `alerts.inhibitions.read`, `alerts.inhibitions.manage` | 알림 억제 규칙을 조회, 생성, 변경, 삭제합니다. |
| `alerts.semantic_groups.manage` | 그룹을 관리합니다. |
| `alerts.remediation.read`, `alerts.remediation.manage` | 문제 해결 조치를 조회하고 정의합니다. |
| `alerts.tickets.read`, `alerts.tickets.manage` | 티켓 커넥터를 조회하고 관리합니다. |
| `alerts.response.read`, `alerts.response.manage` | 주요 인시던트 설정을 조회하고 변경합니다. |
| `alerts.discovery.read` | 탐색 결과를 조회합니다. |
| `schedules.read` | 일정과 온콜 담당자를 조회합니다. |
| `schedules.create`, `schedules.update`, `schedules.delete` | 일정과 교대 순번을 생성, 변경, 삭제합니다. |
| `schedules.overrides.manage`, `schedules.swaps.request`, `schedules.swaps.approve` | 근무를 임시로 대체하고 근무 교환을 요청, 승인 또는 거절합니다. |
| `postmortems.read`, `postmortems.manage` | 사후 분석을 조회하고 사후 분석과 후속 조치 항목을 작성합니다. |
