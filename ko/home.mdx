개인 시작 페이지를 변경하지 않으면 로그인 직후 **홈**이 열립니다. 홈에서는
상단 상태 표시줄, 우선 확인할 서비스와 진행 중인
인시던트, 수신 중인 신호, 합성 검사, 계정의 온콜 근무를 통해 현재 시스템 상태를
확인할 수 있습니다. 모든 멤버가 홈을 열 수 있으며, 각 영역에는 계정 권한으로 볼 수 있는 정보만
표시됩니다.

## 페이지 상단

시간 범위는 페이지의 모든 수치에 적용됩니다. **최근 1시간**(기본값),
**최근 24시간**, **최근 7일** 중에서 선택합니다. 선택한 범위를 주소(`?window=24h`)에 저장하므로 링크를
열면 같은 화면이 표시됩니다. 페이지는 1분마다 모든 데이터를 다시 조회합니다. 새로 고침 버튼을 누르면 즉시
조회합니다.

완료하지 않은 설정 단계가 있으면 시간 범위 앞의 버튼에 남은 단계 수가 표시됩니다. 이 버튼을 누르면
[빠른 시작](#빠른-시작)이 열립니다.

## 시스템 상태

상태 표시줄의 첫 부분에는 **모든 시스템 정상** 또는 문제 수가 표시됩니다. 문제에는
진행 중인 인시던트, 실패하거나 성능이 저하되거나 간헐적으로 실패하는 검사, 경고 또는
위험 임계값을 넘은 서비스, 수집이 지연되거나 실패한 신호가 포함됩니다. 심각한 문제가 하나라도 있으면
빨간색으로 표시합니다(위험 또는 오류 인시던트, 실패한 검사, 위험 상태인 서비스, 수집에 실패한 신호).
그 외에 문제가 있으면 노란색으로 표시합니다. 옆에는 시간 범위와 마지막 조회 시간, 각
신호(로그, 메트릭, 트레이스, 프로파일)의 상태가 표시됩니다.

각 타일을 선택하면 요약 정보를 제공하는 페이지가 열립니다.

| 타일 | 표시 내용 |
|---|---|
| **진행 중인 인시던트** | 심각도별 미해결 및 확인된 인시던트와 미확인 인시던트 수를 표시합니다. [알림](/ko/alerting/incidents)을 엽니다. |
| **발동 중인 규칙** | 활성화된 전체 규칙 중 발동 중인 규칙 수와 대기 중인 규칙 수를 표시합니다. 규칙 페이지를 엽니다. |
| **정상 서비스** | 시간 범위 내에 관측된 전체 서비스 중 임계값을 넘지 않은 서비스 수와 위험, 경고, 유휴 상태의 서비스 수를 표시합니다. [APM](/ko/apm)을 엽니다. |
| **통과한 검사** | 실행 중인 전체 검사 중 통과한 검사 수와 실패, 성능 저하, 간헐적 실패 상태의 검사 수를 표시합니다. [합성 모니터링](/ko/synthetics)을 엽니다. |
| **오류율** | 모든 서비스의 실패한 요청 비율, 요청 수, 추세를 표시합니다. |
| **P95 지연 시간** | 모든 서비스의 요청 소요 시간 95번째 백분위수, P50과 P99, 추세를 표시합니다. |

해당 페이지를 열 권한이 있는 계정에만 타일을 표시합니다. 트레이스가 수신되지 않으면
APM 타일에 대시가 표시됩니다.

## 서비스

**서비스**에는 최대 8개의 서비스가 표시됩니다. 위험, 경고, 정상 순으로 나열하며, 같은 상태에서는
요청 수를 기준으로 정렬합니다. 각 행에는 환경, 상태, 시간 범위 내 요청 수와
처리량, 오류율, P95 지연 시간이 표시됩니다. 서비스의 임계값을 넘은 수치는 해당 상태의 색상으로 표시합니다.
서비스를 선택하면 APM에서 해당 서비스가 열립니다. **모두 보기**를 선택하면 서비스 목록이 열립니다.

## 진행 중인 인시던트

**진행 중인 인시던트**에는 미해결 및 확인된 인시던트가 최대 6개 표시됩니다. 심각도가 높은 순으로 나열하며,
심각도가 같으면 더 오래 열려 있는 인시던트를 먼저 표시합니다. 각 행에는 심각도, 처음 영향을 받은 서비스,
인시던트가 열린 후 경과한 시간, 담당자가 표시됩니다. 목록에서 열린 인시던트의 **확인**을 선택하면 확인 처리됩니다.
권한이 없는 계정에는 버튼 대신 인시던트 상태가 표시됩니다.

## 데이터 수집

**데이터 수집**에는 신호별 상태, 마지막 수신 시간, 선택한
시간 범위의 구간별 수집량, 해당 범위의 행 수가 표시됩니다. 패널 하단에는 데이터를 받은 스트림 수와
저장량 및 수신량이 표시됩니다. **스트림**을 선택하면 [스트림](/ko/streams)이 열립니다.

| 상태 | 의미 |
|---|---|
| **정상** | 해당 신호의 스트림 중 하나 이상이 최근 15분 동안 데이터를 받았습니다. |
| **지연** | 해당 신호의 스트림에 데이터가 있지만 최근 15분 동안 수신한 데이터는 없습니다. |
| **실패** | 노드의 수집 프로브가 오류를 보고합니다. |
| **데이터 없음** | 해당 신호의 스트림 중 선택한 시간 범위에 데이터가 있는 스트림이 없습니다. |

## 합성 모니터링

**합성 모니터링**에는 선택한 시간 범위의 검사별 가용성과 추세가 표시됩니다. 실패하거나 성능이 저하되거나 간헐적으로 실패하는
검사는 상태가 가장 나쁜 것부터 최대 4개까지 표시합니다. 모든 검사를 통과하면 통과한 검사 수를 표시합니다.
**모두 보기**를 선택하면 검사 목록이 열립니다.

## 내 온콜

**내 온콜**에는 워크스페이스의 [온콜 일정](/ko/alerting/on-call)에 따라 다음 정보가 표시됩니다.

- 계정이 근무 중이면 **온콜 근무 시간**과 인계 시각을 표시합니다. 근무 중이 아니지만 향후 30일 내에 근무가 있으면 **다음
  근무**와 시작 및 종료 시각을 표시합니다.
- 해당 일정의 현재 온콜 담당자가 다른 멤버라면 해당 담당자를 표시하고,
  임시 재정의로 대체 근무 중이면 원래 담당자도 표시합니다.
- 현재 해당 일정에 온콜 담당자가 없으면 안내를 표시합니다. **지금 배정**을 선택하면 일정이 열리며,
  임시 재정의를 추가할 수 있습니다.
- 계정이 근무 중이지만 알림을 받을 수 없으면 안내를 표시합니다. **알림 설정**을 선택하면
  계정의 [알림 설정](/ko/account#알림)이 열립니다.
- **일정**을 선택하면 해당 근무의 일정이 열립니다.

## 빠른 시작

페이지 상단의 버튼에 남은 설정 단계 수가 표시됩니다. 버튼을 선택하면 목록이 열립니다.

| 단계 | 완료 조건 |
|---|---|
| **데이터 소스 연결** | 워크스페이스에 [플랫폼 스트림](/ko/streams#플랫폼-스트림) 외의 스트림이 있습니다. |
| **샘플 데이터 불러오기** | 샘플 스트림, 샘플 대시보드, 샘플 저장된 뷰 4개가 있습니다. |
| **대시보드 만들기** | 워크스페이스에 대시보드가 있습니다. |
| **알림 만들기** | 워크스페이스에 알림 규칙이 있습니다. |
| **온콜 일정 설정** | 워크스페이스에 [온콜 일정](/ko/alerting/on-call)이 있습니다. |
| **알림 채널 추가** | 워크스페이스에 활성화된 [커넥터](/ko/notification-channels)가 있고 해당 커넥터의 최근 테스트가 실패하지 않았습니다. |
| **AI 모델 연결** | 워크스페이스에 활성화된 [모델 제공자](/ko/agent)가 있고 해당 제공자에 API 키가 설정되어 있습니다. |
| **파이프라인 자동화** | 워크스페이스에 파이프라인이 있습니다. |

각 단계는 로그인한 계정의 권한을 따릅니다. 단계 상태를 읽거나 해당 페이지를 열 수 없으면
단계를 표시하지 않습니다. 상태는 읽을 수 있지만 단계를 완료할 권한이 없으면 완료된 후에만 표시합니다.

**샘플 데이터 불러오기**는 아직 확인할 데이터가 없는 워크스페이스를 위한 단계입니다.
워크스페이스에 자체 스트림이 있거나 계정에 스트림 목록을 읽을 권한이 없으면 표시하지 않습니다. 샘플 데이터를
불러온 후에도 이 단계는 완료 상태로 남고, **데이터 소스 연결**도 함께 완료됩니다.
이미 데이터가 있는 워크스페이스에 샘플 데이터를 불러오려면
[빠른 시작의 요청](/ko/quickstart#샘플-데이터-불러오기)을 전송합니다.

**불러오기**는 서로 연관된 소량의 샘플 데이터를 세 스트림 `sample_app_logs`,
`sample_app_metrics`, `sample_app_traces`에 기록합니다. 트레이스는 `frontend`에서
`checkout`과 `payment`를 거쳐 `db`로 이어지는 호출을 추적합니다. 로그에는 동일한 `trace_id`가 포함되고, 메트릭에는
서비스별 지연 시간이 기록되므로 트레이스에서 관련 로그로 바로 이동할 수 있습니다. 샘플 데이터를 불러올 때 세
스트림을 사용하는 대시보드와
`sample_app_logs`용 고정된 [저장된 뷰](/ko/saved-views) 4개를 만든 뒤 대시보드를 엽니다. 모두 최근 3시간의 데이터를 표시합니다.
데이터는 불러오기 시점보다 앞선 타임스탬프로 한 번만 기록되므로, 불러오고 3시간이 지나면 대시보드와 저장된 뷰에
데이터가 표시되지 않습니다.

다시 불러오면 현재 시점의 데이터를 추가합니다. 기존 대시보드와 저장된 뷰는 수정 사항까지 그대로 유지하고,
없는 항목만 만듭니다. 따라서 불러오기가 중간에 중단되면 다시
실행할 수 있습니다. 불러오려면 `logs.write`, `metrics.write`, `traces.write`, `dashboards.create`,
`saved_views.create` 권한이 필요합니다. 데이터를 기록하기 전에 다섯 가지 권한을 모두 확인합니다.

## 권한

홈을 여는 데는 권한이 필요하지 않습니다. 각 섹션을 불러오려면 해당 영역의 읽기 권한이 필요합니다.

| 권한 | 적용 범위 |
|---|---|
| `alerts.incidents.read` | **진행 중인 인시던트** 섹션, 해당 타일, 종합 상태 판정에서 인시던트가 차지하는 부분 |
| `alerts.incidents.acknowledge` | **진행 중인 인시던트**의 **확인** |
| `alerts.rules.read` | **발동 중인 규칙** |
| `apm.services.read` | **서비스**, **정상 서비스**, **오류율**, **P95 지연 시간** |
| `synthetics.monitors.read` | **합성 모니터링** 및 **통과한 검사** |
| `synthetics.results.read` | **합성 모니터링**의 가용성 및 가용성 추세 |
| `streams.query` | **데이터 수집** 및 상태 표시줄의 신호 상태 |
| `schedules.read` | **내 온콜**. 이 권한이 없으면 패널을 표시하지 않습니다. |
| `notify.policies.read` | **내 온콜**에서 계정이 알림을 받을 수 없음을 알리는 안내 |
| `notify.connectors.read`, `agent.models.read`, `pipelines.read` | 빠른 시작에서 각 권한에 해당하는 단계 |
| `logs.write` | 빠른 시작의 **불러오기** |
