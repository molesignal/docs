이 개념은 수집, 쿼리, 알림, 자동화, 관리 전반에 적용됩니다.

## 시그널

MoleSignal은 네 가지 텔레메트리 시그널을 처리합니다.

- **로그**는 개별 구조화 이벤트입니다.
- **메트릭**은 레이블이 있는 시계열로 그룹화한 숫자 샘플입니다.
- **트레이스**는 `trace_id`와 상위 스팬 관계로 연결한 스팬의 집합입니다.
- **프로필**은 CPU, 메모리 할당, 힙 또는 경합 샘플을 호출 스택으로 표현합니다.

MoleSignal은 RUM 레코드를 조직의 스트림에 저장하고 브라우저 세션을 백엔드 트레이스에 연결합니다.

[APM](/ko/apm)은 다섯 번째 텔레메트리 스트림이 아닙니다. APM은 테일 샘플링 전에
중복을 제거한 트레이스 스팬에서 필요한 데이터만 추출합니다. 따라서 샘플링에서 제외된 트레이스도 서비스,
트랜잭션, 종속성, 오류 집계에 반영할 수 있습니다.

## 스트림

**스트림**은 수집과 쿼리에서 공유하는 타입이 지정된 데이터 계약입니다. 이름, `streamType`,
변경 가능한 스키마, 보존 정책, 런타임 상태, `queryable` 플래그를 포함합니다.

지원하는 타입은 `logs`, `metrics`, `traces`, `profiles`, `extend`입니다. 여러 타입에서 같은 이름을
사용할 수 있으므로 API는 두 필드로 스트림을 식별합니다.

```json
{ "name": "app", "streamType": "logs" }
```

모든 데이터를 받아 라우팅 파이프라인으로 보내되 쿼리 선택기에 표시하지 않을 소스는
`queryable`을 끕니다. [스트림](/ko/streams)을 참조합니다.

## 조직과 워크스페이스

**조직**은 테넌트와 정책의 경계입니다. 제품 UI에서는 선택한 조직을
**워크스페이스**라고 부릅니다. 텔레메트리와 제품 리소스는 각각 하나의 조직에만
속합니다. 조직 간 액세스는 명시적으로 권한을 부여하거나 리소스를 공유한 경우에만 허용됩니다.

영구 조직 `_sys`는 시스템 텔레메트리, 플랫폼 관리자, 조직 전반의 작업을 위한 보호된 플랫폼 범위입니다. `_sys` 조직은
일반 테넌트가 아닙니다.

## 제품 리소스

대시보드, 저장된 뷰, 알림 규칙, 일정, 보고서, 함수, 파이프라인, 에이전트
워크플로는 조직 리소스입니다. 핸들러는 대상 리소스를 불러와 소유권을 확인하고,
요청한 작업에 대한 권한을 확인한 후 리소스를 반환하거나 변경합니다.

## 권한과 역할

권한은 `streams.query`, `alerts.rules.manage`,
`sys.telemetry.read`처럼 변경되지 않는 기능 키입니다. 역할은 이름이 지정된 권한 집합입니다. 역할에는 자체 권한이 있으며, API 토큰에도 적용할 수 있는
재사용 가능한 권한 집합인 권한 정책을 연결할 수 있습니다.
기본 제공 역할인 소유자, 관리자, 편집자,
뷰어, 플랫폼 관리자는 기본 권한을 제공합니다. 더 제한된
책임 범위에는 사용자 지정 역할을 사용할 수 있습니다.

탐색 메뉴는 실제로 유효한 권한의 스냅샷을 사용합니다. 하지만 페이지를 숨기는 것으로 백엔드의
권한 검사를 대체할 수는 없습니다. [ID 및 액세스](/ko/identity)를 참조합니다.

## 시간과 상관관계

탐색 페이지는 동일한 시간 범위를 공유합니다. 상관관계를 따라 페이지를 전환할 때는 이 범위를 유지하고
`trace_id`, 서비스, 호스트, 세션 등의 식별자를 추가합니다. 따라서
`RUM → trace → log → metric → profile` 같은 경로로 이동할 수 있으며, 탐색 상태는 권한 부여에 사용하지 않습니다.

## 스토리지와 쿼리

MoleSignal은 로그, 메트릭, 트레이스를 파티션으로 나눈 Parquet 파일에 저장합니다. 프로필 메타데이터는 쿼리할 수 있으며,
압축된 pprof 블롭은 오브젝트 스토리지에 보관합니다. PostgreSQL은 파일 메타데이터, 스키마,
IAM, 제품 리소스, 운영 상태를 저장합니다.

DataFusion과 Arrow는 SQL 쿼리, PromQL 호환 메트릭 쿼리, 로컬 검색,
페더레이션 스캔을 실행합니다. 쿼리 플래너는 실행 전에 접근이 허용된 조직으로 쿼리 범위를 제한합니다.

## 런타임 역할

단일 바이너리에서 `[node].roles`로 다음 역할을 조합합니다.

| 역할 | 주요 책임 |
|---|---|
| `standalone` | 단일 프로세스에서 모든 API와 워커를 실행합니다. |
| `router` | 전체 HTTP API와 웹 UI를 제공하고, 요청 빈도를 제한하며, 요청을 수집 및 쿼리 노드로 전달합니다. |
| `intake` | 데이터 검증, 파이프라인 실행, WAL 및 버퍼 관리, Parquet 파일 쓰기를 담당합니다. |
| `querier` | 다른 노드가 전달한 요청의 쿼리를 실행합니다. |
| `compactor` | 컴팩션, 보존 정책 적용, 스토리지 유지보수를 담당합니다. |
| `alert` | 규칙 평가, 일정 관리, 에스컬레이션, 알림 전송을 담당합니다. |

구성 요소와 데이터 흐름은 [아키텍처](/ko/architecture)를 참조합니다.
