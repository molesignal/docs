Mole Agent가 작성하는 모든 답변은 평가됩니다. 규칙은 모델 없이 즉시 답변을 평가합니다: 도구가 정상적으로 작동했는지, 근거를 인용하는지, 쿼리가 파싱되는지, 요구된 형식으로 나왔는지, 질문한 사람이 어떻게 평가했는지. 설정한 평가기는 직접 작성한 평가 기준에 따라 모델로 일부 답변을 평가합니다. 낮은 점수를 받은 답변, 누군가 도움이 되지 않음으로 평가한 답변, 무작위로 추출된 답변은 검토를 기다립니다. 검토자가 승인한 답변은 회귀 세트가 됩니다. 조직 프롬프트가 기본값이 되기 전에, 검사가 이러한 질문 중 일부에 새 버전과 현재 버전으로 다시 답변하고, 평가기가 두 답변을 모두 평가합니다.

점수는 0부터 100까지입니다. **품질** 탭에 표시되며, 모든 점수는 `_agent_score_traces` 스트림에도 기록됩니다.

## 시작하기 전에

- **품질** 탭에는 `agent.quality.read` 권한이 필요하며, 소유자 및 관리자 역할에는 기본적으로 이 권한이 있습니다. 해당 역할은 모든 팀 채팅을 이미 읽을 수 있습니다. 개인 채팅은 집계에만 포함되며, 그 내용은 누구도 읽지 않습니다.
- 평가기는 조직의 모델 제공자 중 하나를 사용합니다. [Mole Agent](/ko/agent#모델-공급자-설정)를 참조하세요. 평가기가 없어도 모든 답변은 규칙으로 평가됩니다.

## 평가 대상

| 소스 | 설명 |
|---|---|
| **팀 채팅** | 팀 채팅의 답변입니다. |
| **개인 채팅** | 개인 채팅의 답변입니다. 규칙으로만 평가되며, 집계에만 포함됩니다. |
| **자동화** | 조직 또는 팀 자동화의 각 실행에 대한 답변입니다. [자동화](/ko/automations)를 참조하세요. 개인 자동화의 실행은 개인 채팅입니다. |
| **인시던트 근본 원인 분석** | 근본 원인 분석이 자동 또는 요청 시 생성하는 RCA와 누군가 평가한 모든 RCA입니다. |

답변은 작성될 때 평가되며, 질문한 사람이 평가하거나 평가를 철회할 때 다시 평가됩니다.

## 규칙

규칙은 답변과 해당 실행이 남긴 내용을 살펴보고 각 항목을 0부터 100까지 평가합니다. 답변의 규칙 점수는 적용되는 항목 점수의 평균입니다.

| 규칙 | 점수 | 적용 대상 |
|---|---|---|
| **도구 호출** | 실패하지 않은 도구 호출의 비율입니다. | 도구를 호출한 답변입니다. |
| **근거** | 인용된 근거가 없으면 0, 성공한 도구 호출이 하나도 뒷받침하지 않는 근거를 인용하면 50, 한 개를 인용하면 75, 두 개 이상을 인용하면 100입니다. 인시던트 RCA의 경우: 제공되지 않은 레이블을 인용하면 0, 제공된 근거를 하나도 인용하지 않으면 25, 제공된 근거만 인용하면 100입니다. | 도구를 호출한 요청된 형식의 답변, 근거를 제공받았거나 근거를 인용한 인시던트 RCA입니다. |
| **쿼리** | 도구 호출에서 SQL 및 PromQL이 파싱되는 비율입니다. | 도구가 쿼리를 실행한 답변입니다. |
| **형식** | 답변이 요구된 형식이면 100입니다. | 생성된 쿼리를 제외한 모든 채팅 답변입니다. |
| **완료** | 완료된 답변은 100, 사람이 필요했던 자동화 실행은 50, 실패했거나 중지되었거나 비어 있는 답변은 0입니다. | 모든 답변입니다. |
| **평가** | **도움이 됨**은 100, **도움이 되지 않음**은 0입니다. RCA에서는 **도움이 되지 않음** 하나가 집계됩니다. | 누군가 평가한 답변입니다. |

## 평가기

평가기는 자체 평가 기준에 따라 답변에 1부터 5까지의 점수를 부여하고, 그 이유를 한두 문장으로 설명합니다. 점수는 0, 25, 50, 75, 100으로 표시됩니다. 평가기는 질문, 도구가 찾은 내용, 답변을 읽습니다. RCA의 경우 인시던트의 사실 관계와 RCA를 읽습니다.

- 평가기는 설정한 비율만큼 새 답변을 평가하며, 답변 단위로 추출되므로 다시 추출해도 같은 답변이 선택됩니다.
- **도움이 되지 않음**으로 평가된 답변은 평가기가 이미 평가하지 않은 한 항상 평가됩니다.
- 평가기가 검토 임계값 미만으로 평가한 답변은 한 번 더 평가되며, 두 점수의 평균이 집계됩니다.
- 평가기는 개인 채팅을 평가하지 않습니다.
- 평가기는 마지막으로 저장한 사람의 인터페이스 언어로 이유를 작성합니다.
- 평가기의 모델 호출은 소스별 사용량에서 **품질 평가**로 집계되어 조직의 일일 토큰 예산에 포함됩니다. 예산이 모두 소진되면 평가기는 새 답변을 건너뜁니다.

모든 평가기가 시작하는 지침은 기본 제공 프롬프트인 **답변 평가기**(용도 `evaluation`)입니다. 조직은 **설정 → 프롬프트 관리**에서 이를 재정의할 수 있습니다. 프롬프트에 무엇이 적혀 있든 평가기는 고정된 형식으로 점수를 반환합니다.

답변의 점수는 평가기가 평가한 경우 해당 평가기 점수들의 평균이며, 그렇지 않으면 규칙 점수입니다.

## 품질 탭

**Mole Agent → 품질**을 엽니다. **개요**와 **답변**에서는 최근 7일, 30일, 90일과 하나의 소스 또는 모든 소스를 기준으로 조회합니다.

| 보기 | 표시 내용 |
|---|---|
| **개요** | 점수가 매겨진 답변, 규칙 및 평가자의 평균, 도움이 됨 및 도움이 되지 않음으로 평가된 답변, 검토를 기다리는 답변 수입니다. 아래에는 일별 점수, 각 규칙, 소스, 프롬프트 버전, 스킬, 모델별 답변이 표시됩니다. |
| **답변** | 점수가 매겨진 답변을 최신순으로 표시하며, **낮은 점수만**을 사용하면 검토 기준 점수 미만인 답변만 유지됩니다. 행을 열면 전체 질문과 답변, 각 규칙이 찾은 내용, 각 평가자의 점수와 이유, 답변의 검토가 표시됩니다. **채팅 열기** 또는 **인시던트 열기**를 선택하면 해당 답변이 작성된 위치로 이동합니다. |
| **검토** | 검토를 기다리거나, 수락되었거나, 거부된 답변입니다. |
| **데이터 공백** | 답변의 도구 호출에서 데이터에 누락된 것으로 언급된 내용입니다. [데이터 공백](#데이터-공백)을 참조하세요. |
| **훈련** | 해결된 인시던트를 다시 조사하고 알려진 근본 원인과 비교하여 채점한 결과입니다. [훈련](#훈련)을 참조하세요. |
| **평가자** | 평가자 및 설정입니다. |

### 답변 검토

답변이 검토를 기다리는 경우는 다음과 같습니다:

| 원인 | 조건 |
|---|---|
| **낮은 점수** | 평가자의 점수가 두 번째 채점 후에도 검토 기준 점수 미만이거나, 평가자가 채점하지 않는 답변은 규칙 점수가 기준 미만인 경우입니다. |
| **도움이 되지 않음으로 평가됨** | 질문한 사람이 **도움이 되지 않음**으로 평가했습니다. |
| **무작위 선정** | 점수를 신뢰할 수 있는지 확인하기 위해 **무작위 검토** 비율에 따라 선정되었습니다. |

답변은 검토로 한 번만 넘어옵니다. 답변을 열고 **메모**에 무엇이 잘못되었는지와 좋은 답변이 무엇을 제대로 하는지 작성한 후 선택합니다:

- **수락**: 답변이 잘못되었습니다. 회귀 세트에 추가되며, 프롬프트 검사에서 질문에 다시 답할 때 메모가 평가자에게 전달됩니다.
- **거부**: 답변이 적절합니다.

### 평가자 및 설정

**평가자**에서 **새 평가기**를 선택하면 양식이 열립니다:

| 필드 | 설명 |
|---|---|
| **이름** | 조직 내에서 고유해야 합니다. |
| **채점 기준** | 좋은 답변이 무엇을 수행하는지와 무엇이 감점 사유인지를 최대 4,000자까지 작성합니다. 시작용 채점 기준이 미리 입력되어 있습니다. |
| **답변** | 팀 채팅, 자동화, 인시던트 RCA입니다. |
| **샘플링 비율** | 채점할 새 답변의 비율이며 0에서 100까지입니다. |
| **모델 제공업체** 및 **모델** | 비워 두면 조직에서 사용 가능한 첫 번째 제공업체와 해당 제공업체의 기본 모델을 사용합니다. |
| **온도** | 0에서 1까지이며, 0은 점수를 일정하게 유지합니다. |
| **켜짐** | 꺼져 있는 평가자는 아무것도 채점하지 않습니다. |

한 조직에는 평가자를 최대 10개까지 둘 수 있습니다. 평가자를 삭제해도 해당 평가자가 부여한 점수는 유지됩니다.

평가자 아래의 설정은 다음과 같습니다:

| 설정 | 기본값 | 설명 |
|---|---|---|
| **검토 기준 점수** | 60 | 이 값 미만의 점수를 받은 답변은 검토를 기다립니다. |
| **무작위 검토** | 0 | 검토를 위해 선정되는 나머지 답변의 비율입니다. |
| **기본 프롬프트 지정 전 검사** | 검사하며, 더 나쁠 경우 다시 질문 | 아래를 참조하세요. |

### 데이터 공백

답변이 규칙으로 채점되면, 해당 답변의 도구 호출도 읽어 Mole Agent가 작업해야 했던 데이터에 대해 무엇을 말하는지 확인합니다. 이는 점수를 바꾸지 않습니다. 공백은 답변이 아니라 데이터를 가리킵니다. **데이터 공백**은 최근 7일, 30일, 90일 동안의 공백을 집계합니다.

| 종류 | 발견 조건 | 채우는 방법 |
|---|---|---|
| **데이터 위치** | 동일한 스트림을 3회 이상 쿼리했으며 대부분의 쿼리가 비어 있거나 실패했거나, 구조를 3회 이상 조회한 경우입니다(스트림 스키마, 스트림 목록, 메트릭 이름 및 레이블). | 각 서비스의 데이터가 어디에 있고 어떻게 필터링하는지 기록합니다. 서비스 카탈로그의 데이터 소스 또는 지식의 `MOLE.md`에 기록합니다. |
| **서비스별 이름 통일** | 서비스에 메트릭 또는 APM 데이터가 있었지만 동일한 서비스를 지정한 로그 또는 트레이스 쿼리에서 아무것도 찾지 못했고, 해당 스트림의 다른 쿼리에서도 찾지 못한 경우입니다. | 모든 시그널에서 서비스에 하나의 이름(`service.name`)을 사용하거나, 서비스 카탈로그에 다른 이름을 별칭으로 나열합니다. |
| **데이터 요약** | **로그 패턴 분석** 또는 **메트릭 추세 분석** 없이 각각 행이 많은 원시 로그 또는 원시 시계열을 2회 이상 가져온 경우입니다. | 조직의 Agent 프로필 도구 세트에서 해당 도구가 빠져 있지 않은지 확인합니다. |

이 보기에는 반복해서 발견된 각 공백이 스트림 및 서비스별로 그룹화되어 표시되며, 해당 공백을 발견한 답변 수와 마지막으로 발견된 시점이 함께 표시됩니다. 그 아래의 답변을 열면 점수가 표시됩니다. 개인 채팅은 합계에만 포함되며, 쿼리한 내용은 나열되지 않습니다.

### 훈련

훈련은 해결된 인시던트를 마치 다시 발생한 것처럼 Mole Agent가 조사하고, 인시던트 이후 확립된 근본 원인과 비교하여 채점하는 것입니다. 모델, 프롬프트 또는 도구를 변경한 후 모든 훈련을 다시 실행하면 조사가 개선되었는지 확인할 수 있습니다.

**새 훈련**은 최근 180일 이내에 해결되었고 포스트모템에 근본 원인이 명시된 인시던트를 제공합니다(**근본 원인** 아래의 섹션). 별도로 작성하지 않는 한 포스트모템의 근본 원인이 기준입니다. **다른 인시던트**는 인시던트 ID와 직접 작성한 근본 원인을 사용합니다. 각 인시던트에는 하나의 훈련이 있으며, 한 조직에는 최대 100개까지 보관할 수 있습니다.

훈련 실행은 다음과 같습니다:

- 실행을 시작한 사용자의 권한으로 실행되며, 해당 사용자는 인시던트를 읽을 수 있어야 합니다. 무인 및 읽기 전용으로 최대 10분 동안 실행됩니다.
- 인시던트가 발생할 때 사용된 정보(요약, 심각도, 서비스, 레이블, 인시던트를 발생시킨 쿼리)와 경고 규칙의 조사 가이드를 가져오고, 인시던트 시작 1시간 전부터 30분 후까지의 시간을 살펴봅니다.
- 인시던트 이후에 발견된 내용과 수행된 조치(메모, 타임라인, RCA, 포스트모템, 티켓, 승인, 유사 인시던트)는 읽을 수 없습니다.
- 채팅 목록에 표시되지 않는 채팅입니다. **조사 열기**를 선택하면 실행에서 읽기 전용으로 해당 채팅이 열립니다.

조사가 끝나면 모델이 해당 근본 원인을 기준과 비교하고 1에서 5까지 점수를 매기며, 이를 0에서 100으로 환산해 표시합니다. 이유는 실행을 시작한 사용자의 인터페이스 언어로 작성됩니다. 모델은 활성화된 첫 번째 평가자의 모델을 사용하고, 없으면 조직의 첫 번째 모델 제공업체를 사용합니다. 해당 호출은 **품질 평가**로 일일 토큰 예산에 포함됩니다. 실패했거나 중지되었거나 답변을 작성하지 않은 실행은 점수가 없으며 그 이유를 표시합니다.

**실행**은 훈련 하나를 시작하고, **모두 다시 실행**은 진행 중인 실행이 없는 모든 훈련을 한 번에 최대 50개까지 시작합니다. 훈련을 생성, 실행 및 삭제하려면 `agent.quality.manage` 권한이 필요합니다.

## 프롬프트가 기본값이 되기 전에 검사

채팅(**시스템 지침**) 또는 인시던트 RCA(**근본 원인 분석**)용 조직 프롬프트에서 **기본값으로 설정**을 선택하면 조직 설정에 따라 이후 동작이 결정됩니다:

| 설정 | 프롬프트를 검사하지 않았거나 검사에서 더 나쁜 것으로 확인한 경우 |
|---|---|
| **검사 후 점수가 낮아지면 재확인** | 대화상자에서 **검증 실행**과 **그래도 기본값으로 설정**을 제공합니다. |
| **검사 후 점수가 낮아지면 지정 차단** | 검사에서 더 나쁘지 않다고 확인된 프롬프트만 설정할 수 있습니다. |
| **검사 안 함** | 프롬프트가 즉시 설정됩니다. |

검사는 최대 8개의 답변을 사용합니다. 먼저 회귀 세트를 사용한 다음, 해당 답변을 평가하는 첫 번째 평가자가 가장 최근에 평가한 답변을 사용합니다. 동일한 모델이 각 답변에 현재 기본값과 새 버전으로 두 번씩 다시 답변하며, 도구는 다시 실행하지 않습니다. 모델은 질문과 그때 도구가 찾은 내용을 받습니다. RCA의 경우 두 버전 모두 인시던트의 사실을 바탕으로 답변을 작성합니다. 그런 다음 평가자가 각 답변 쌍을 평가합니다. 새 버전은 평균이 현재 기본값의 평균보다 5 넘게 낮으면 **더 나쁨**, 5 넘게 높으면 **더 좋음**, 그 외에는 **나쁘지 않음**입니다. 비교할 수 있는 답변이 3개 미만이면 검사에서 판단할 수 없으며, 프롬프트 설정을 막지 않습니다.

대화상자에는 진행 상황이 표시된 다음 각 답변의 결과가 표시됩니다. 검사는 하나의 기본값을 기준으로 프롬프트의 한 버전을 검사합니다. 프롬프트를 편집하거나 다른 기본값을 설정하면 검사를 다시 실행해야 합니다. 검사의 모델 호출은 **품질 평가**로 집계됩니다.

다른 용도의 프롬프트는 검사 없이 기본값이 됩니다. 이미 기본값인 프롬프트를 편집해도 검사하지 않습니다. 변경 사항을 검사하려면 새 프롬프트로 저장한 뒤 해당 프롬프트를 기본값으로 설정합니다.

## 스트림의 점수

각 점수는 내부 스트림 `_agent_score_traces`의 행이기도 하며, **로그**에서 조회할 수 있습니다:

| 필드 | 설명 |
|---|---|
| `target_kind`, `target_id` | 메시지 ID가 포함된 `chat_answer` 또는 인시던트 ID가 포함된 `incident_rca`입니다. |
| `source` | `personal_chat`, `team_chat`, `automation` 또는 `incident_rca`입니다. |
| `scorer`, `scorer_kind` | `rules` 또는 `evaluator`가 포함된 평가자 ID입니다. |
| `score`, `samples` | 0에서 1까지의 값이며, 몇 개의 채점 결과에 대한 평균인지 나타냅니다. |
| `tool_success`, `evidence`, `query_validity`, `answer_format`, `completion`, `feedback` | 적용되는 경우 0에서 1까지의 규칙 값입니다. |
| `reason`, `evaluator_model` | 평가자의 사유와 모델입니다. |
| `chat_id`, `team_id`, `automation_id`, `user_id`, `prompt_template_id`, `prompt_version`, `prompt_key`, `provider_id`, `model`, `skill`, `skill_version` | 답변의 출처와 사용한 항목입니다. |

품질 저하 알림을 받으려면 스트림에 [이상 알림 규칙](/ko/alerting)을 생성합니다. 예를 들어 평가자의 평균을 대상으로 설정할 수 있습니다:

```sql
SELECT avg(score) AS value FROM "_agent_score_traces" WHERE scorer_kind = 'evaluator'
```
