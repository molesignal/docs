Mole Agent가 작성하는 모든 답변을 평가합니다. 규칙은 모델을 사용하지 않고 도구 호출의 성공 여부, 근거 인용 여부, 쿼리 파싱 여부, 요청한 형식 준수 여부, 질문자가 남긴 평가를 바탕으로 즉시 점수를 매깁니다. 설정한 평가기는 모델을 사용해 답변 표본에 작성한 평가 기준을 적용합니다. 점수가 낮거나 **도움이 되지 않음** 평가를 받았거나 무작위로 추출한 답변은 검토를 기다립니다. 검토자가 승인한 답변은 회귀 테스트 세트에 추가합니다. 조직 프롬프트를 기본값으로 지정하기 전에 이 세트의 질문 중 일부에 새 버전과 현재 버전으로 각각 다시 답하고, 평가기가 두 버전의 답변을 모두 채점합니다.

점수 범위는 0~100입니다. **품질** 탭에 점수를 표시하고, 모든 점수를 `_agent_score_traces` 스트림에도 기록합니다.

## 시작하기 전에

- **품질** 탭을 보려면 `agent.quality.read` 권한이 필요합니다. 소유자 및 관리자 역할에는 기본적으로 이 권한이 있습니다. 두 역할 모두 모든 팀 채팅을 읽을 수 있습니다. 개인 채팅은 합계에만 반영하며, 이 탭에서는 열람할 수 없습니다.
- 평가기는 조직의 모델 제공업체 중 하나를 사용합니다. [Mole Agent](/ko/agent#모델-공급자-설정)를 참조합니다. 평가기가 없어도 규칙으로 모든 답변을 평가합니다.

## 평가 대상

| 출처 | 설명 |
|---|---|
| **팀 채팅** | 팀 채팅의 답변입니다. |
| **개인 채팅** | 개인 채팅의 답변입니다. 규칙으로만 평가하고 합계에만 반영합니다. |
| **자동화** | 조직 또는 팀 자동화를 실행할 때마다 생성하는 답변입니다. [자동화](/ko/automations)를 참조합니다. 개인 자동화 실행은 개인 채팅으로 처리합니다. |
| **인시던트 근본 원인 분석** | 자동 또는 요청에 따라 생성한 근본 원인 분석(RCA) 결과와 평가를 받은 모든 RCA입니다. |

답변을 작성할 때 평가하고, 질문자가 평가를 남기거나 철회할 때 다시 평가합니다.

## 규칙

규칙은 답변과 실행 기록을 바탕으로 각 항목에 0~100점을 매깁니다. 답변의 규칙 점수는 적용되는 항목의 평균입니다.

| 규칙 | 점수 | 적용 대상 |
|---|---|---|
| **도구 호출** | 실패하지 않은 도구 호출의 비율입니다. | 도구를 호출한 답변입니다. |
| **근거** | 인용한 근거가 없으면 0점, 근거를 인용했지만 성공한 도구 호출이 뒷받침하지 않으면 50점, 성공한 도구 호출이 뒷받침하는 근거가 1개면 75점, 2개 이상이면 100점입니다. | 요청한 형식을 따르고 도구를 호출한 답변입니다. |
| **쿼리** | 도구 호출에 포함된 SQL 및 PromQL 쿼리 중 파싱에 성공한 비율입니다. | 도구로 쿼리를 실행한 답변입니다. |
| **형식** | 요청한 답변 형식을 따르면 100점입니다. | 생성된 쿼리를 제외한 모든 채팅 답변입니다. |
| **완료** | 답변을 완료하면 100점, 자동화 실행에 사람의 개입이 필요하면 50점, 실패하거나 중단되거나 빈 답변이면 0점입니다. | 모든 답변입니다. |
| **평가** | **도움이 됨**은 100점, **도움이 되지 않음**은 0점입니다. RCA는 **도움이 되지 않음** 평가가 하나라도 있으면 반영합니다. | 평가를 받은 답변입니다. |

## 평가기

평가기는 평가 기준에 따라 답변에 1~5점을 매기고 그 이유를 한두 문장으로 설명합니다. 점수는 0, 25, 50, 75 또는 100으로 표시합니다. 평가기는 질문과 도구 호출 결과, 답변을 확인합니다. RCA의 경우 인시던트의 사실관계와 RCA를 확인합니다.

- 평가기는 설정한 비율만큼 새 답변을 추출해 평가합니다. 답변을 기준으로 추출하므로 다시 추출해도 같은 답변을 선택합니다.
- 평가기는 **도움이 되지 않음** 평가를 받은 답변을 항상 평가합니다. 단, 해당 평가기가 이미 평가한 답변은 제외합니다.
- 평가기 점수가 검토 기준값보다 낮으면 한 번 더 평가하고 두 점수의 평균을 사용합니다.
- 평가기는 개인 채팅을 평가하지 않습니다.
- 평가기는 마지막으로 평가기를 저장한 사용자의 인터페이스 언어로 평가 이유를 작성합니다.
- 평가기의 모델 호출은 조직의 일일 토큰 예산에 포함되며, 출처별 사용량에서 **품질 평가**로 표시합니다. 예산을 모두 사용하면 평가기는 새 답변을 평가하지 않습니다.

모든 평가기는 기본 제공 프롬프트인 **답변 평가기**(용도: `evaluation`)를 기본 지침으로 사용합니다. 조직은 **설정 → 프롬프트 관리**에서 이 프롬프트를 재정의할 수 있습니다. 평가기는 프롬프트 내용과 관계없이 고정된 형식으로 점수를 반환합니다.

평가기에서 평가한 답변은 평가기 점수의 평균을 최종 점수로 사용합니다. 평가기에서 평가하지 않은 답변은 규칙 점수를 사용합니다.

## 품질 탭

**Mole Agent → 품질**을 엽니다. **개요**와 **답변**에서 최근 7일, 30일 또는 90일 동안의 데이터를 단일 소스 또는 모든 소스 기준으로 확인합니다.

| 보기 | 표시 내용 |
|---|---|
| **개요** | 채점한 답변 수, 규칙 점수와 평가자 점수의 평균, 도움이 됨과 도움이 되지 않음으로 평가된 답변 수, 검토 대기 중인 답변 수를 표시합니다. 아래에는 일별 점수, 규칙별 점수, 소스, 프롬프트 버전, 스킬, 모델별 답변을 표시합니다. |
| **답변** | 채점한 답변을 최신순으로 표시합니다. **낮은 점수만**을 선택하면 검토 기준 점수 미만인 답변만 표시합니다. 행을 열면 질문과 답변 전문, 각 규칙의 검사 결과, 각 평가자의 점수와 근거, 답변의 검토 내역을 확인할 수 있습니다. **채팅 열기** 또는 **인시던트 열기**를 선택하면 답변이 작성된 곳으로 이동합니다. |
| **검토** | 검토 대기 중이거나 수락 또는 거부된 답변을 표시합니다. |
| **데이터 공백** | 답변을 생성할 때의 도구 호출에서 파악한 누락 데이터를 표시합니다. [데이터 공백](#데이터-공백)을 참조합니다. |
| **훈련** | 해결된 인시던트를 다시 조사하고 알려진 근본 원인을 기준으로 채점한 결과를 표시합니다. [훈련](#훈련)을 참조합니다. |
| **평가자** | 평가자와 설정을 표시합니다. |

### 답변 검토

다음과 같은 경우 답변이 검토를 기다립니다.

| 사유 | 조건 |
|---|---|
| **낮은 점수** | 평가자가 두 번째로 채점한 뒤에도 점수가 검토 기준 점수 미만이거나, 평가자가 채점하지 않은 답변의 규칙 점수가 검토 기준 점수 미만입니다. |
| **도움이 되지 않음으로 평가됨** | 질문을 작성한 사람이 답변을 **도움이 되지 않음**으로 평가했습니다. |
| **무작위 선정** | 점수의 신뢰성을 확인하기 위해 **무작위 검토** 비율에 따라 답변을 선정했습니다. |

각 답변은 한 번만 검토합니다. 답변을 열고 무엇이 잘못되었는지, 좋은 답변이라면 어떤 내용을 정확히 짚어야 하는지 **메모**에 작성한 뒤 다음 중 하나를 선택합니다.

- **수락**: 답변이 잘못되었습니다. 답변을 회귀 테스트 세트에 추가합니다. 프롬프트 검사에서 같은 질문에 다시 답변하면 평가자에게 메모를 전달합니다.
- **거부**: 답변에 문제가 없습니다.

### 평가자 및 설정

**평가자**에서 **새 평가기**를 선택하면 양식이 열립니다.

| 필드 | 설명 |
|---|---|
| **이름** | 조직 내에서 고유해야 합니다. |
| **채점 기준** | 좋은 답변이 충족할 조건과 감점 요인을 최대 4000자로 작성합니다. 양식에 초안이 미리 입력되어 있습니다. |
| **답변** | 팀 채팅, 자동화, 인시던트 RCA입니다. |
| **샘플링 비율** | 새 답변 중 채점할 비율입니다. 0~100 사이의 값을 지정합니다. |
| **모델 제공업체** 및 **모델** | 비워 두면 조직에서 사용 가능한 첫 번째 제공업체와 해당 제공업체의 기본 모델을 사용합니다. |
| **온도** | 0~1 사이의 값을 지정합니다. 0으로 설정하면 점수 편차를 줄일 수 있습니다. |
| **켜짐** | 평가기를 끄면 답변을 채점하지 않습니다. |

조직마다 평가자를 최대 10개까지 둘 수 있습니다. 평가자를 삭제해도 해당 평가자가 부여한 점수는 유지합니다.

평가자 목록 아래에 다음 설정이 있습니다.

| 설정 | 기본값 | 설명 |
|---|---|---|
| **검토 기준 점수** | 60 | 이 점수 미만인 답변은 검토 대기 상태가 됩니다. |
| **무작위 검토** | 0 | 나머지 답변 중 검토 대상으로 무작위 선정할 비율입니다. |
| **기본 프롬프트 지정 전 검사** | 검사하고 결과가 나빠지면 다시 확인 | 아래 내용을 참조합니다. |

### 데이터 공백

규칙으로 답변을 채점할 때 Mole Agent가 어떤 데이터를 사용할 수 있었는지 파악하기 위해 도구 호출도 살펴봅니다. 데이터 공백은 답변이 아닌 데이터의 문제를 나타내므로 점수에는 영향을 주지 않습니다. **데이터 공백**은 최근 7일, 30일 또는 90일 동안 발견한 공백을 요약합니다.

| 유형 | 감지 조건 | 해결 방법 |
|---|---|---|
| **데이터 위치** | 같은 스트림을 3회 이상 쿼리했지만 대부분의 쿼리가 빈 결과를 반환하거나 실패했습니다. 또는 스트림 스키마, 스트림 목록, 메트릭 이름 및 레이블 등 데이터 구조를 3회 이상 조회했습니다. | 서비스 카탈로그의 데이터 소스 또는 지식의 `MOLE.md`에 서비스별 데이터 위치와 필터링 방법을 기록합니다. |
| **서비스별 이름 통일** | 메트릭 또는 APM에 서비스 데이터가 있지만, 같은 서비스 이름을 사용한 로그 또는 트레이스 쿼리에서 데이터를 찾지 못했고 해당 스트림에 대한 다른 쿼리에서도 찾지 못했습니다. | 모든 시그널에서 서비스 이름(`service.name`)을 통일하거나 서비스 카탈로그에 다른 이름을 별칭으로 등록합니다. |
| **데이터 요약** | **로그 패턴 분석** 또는 **메트릭 추세 분석**을 사용하지 않고 원시 로그 또는 원시 시계열을 2회 이상 가져왔으며, 매번 반환된 행이 많았습니다. | 조직의 Agent Profiles 도구 세트에 해당 도구가 포함되어 있는지 확인합니다. |

이 보기에서는 반복해서 발견한 공백을 스트림과 서비스별로 묶어 표시합니다. 각 공백에는 이를 발견한 답변 수와 마지막으로 발견한 시점이 표시됩니다. 공백 아래의 답변을 열면 점수도 확인할 수 있습니다. 개인 채팅은 집계에만 포함하며, 개인 채팅에서 쿼리한 내용은 목록에 표시하지 않습니다.

### 훈련

훈련에서는 Mole Agent가 해결된 인시던트를 진행 중인 것처럼 다시 조사합니다. 인시던트 종료 후 확인한 근본 원인을 기준으로 조사 결과를 채점합니다. 모델, 프롬프트 또는 도구를 변경한 후 모든 훈련을 다시 실행하면 조사 품질이 개선되었는지 확인할 수 있습니다.

**새 훈련**에는 최근 180일 동안 해결되었으며 사후 분석 보고서의 **근본 원인** 섹션에 근본 원인이 명시된 인시던트가 표시됩니다. 별도로 근본 원인을 입력하지 않으면 사후 분석 보고서에 기록된 내용을 기준으로 사용합니다. **다른 인시던트**를 선택하면 인시던트 ID와 근본 원인을 직접 입력할 수 있습니다. 인시던트당 훈련은 하나이며, 조직마다 최대 100개까지 보관할 수 있습니다.

훈련 실행은 다음과 같이 진행됩니다.

- 실행을 시작한 계정의 권한으로 최대 10분 동안 별도 개입 없이 읽기 전용으로 진행합니다. 실행을 시작하려면 인시던트 읽기 권한이 필요합니다.
- 인시던트 발생 당시의 정보(요약, 심각도, 서비스, 레이블, 인시던트를 트리거한 쿼리)와 알림 규칙의 조사 가이드를 가져옵니다. 인시던트 시작 1시간 전부터 시작 후 30분까지의 데이터를 살펴봅니다.
- 인시던트에 대해 나중에 파악한 내용과 후속 조치 내역은 읽을 수 없습니다. 여기에는 메모, 타임라인, RCA, 사후 분석 보고서, 티켓, 승인, 유사 인시던트가 포함됩니다.
- 채팅으로 진행하지만 채팅 목록에는 표시하지 않습니다. 실행 내역에서 **조사 열기**를 선택하면 해당 채팅을 읽기 전용으로 열 수 있습니다.

조사가 끝나면 모델이 조사에서 도출한 근본 원인을 기준과 비교해 1~5점으로 채점합니다. 점수는 0~100점으로 환산하며, 채점 근거는 실행을 시작한 계정의 인터페이스 언어로 표시합니다. 활성화된 첫 번째 평가자의 모델을 사용합니다. 활성화된 평가자가 없으면 조직의 첫 번째 모델 제공업체를 사용합니다. 모델 호출은 **품질 평가** 항목으로 일일 토큰 한도에 반영합니다. 실행이 실패했거나 중지되었거나 답변을 작성하지 않은 경우에는 점수 없이 이유를 표시합니다.

**실행**은 훈련 하나를 시작합니다. **모두 다시 실행**은 실행 중이 아닌 모든 훈련을 한 번에 최대 50개까지 시작합니다. 훈련을 생성, 실행, 삭제하려면 `agent.quality.manage` 권한이 필요합니다.

## 프롬프트를 기본값으로 설정하기 전에 검증하기

채팅용(**시스템 지침**) 또는 인시던트 근본 원인 분석용(**근본 원인 분석**) 조직 프롬프트에서 **기본값으로 설정**을 선택하면 조직 설정에 따라 다음과 같이 처리합니다.

| 설정 | 프롬프트를 검증하지 않았거나 검증 결과 점수가 낮아진 경우 |
|---|---|
| **검사 후 점수가 낮아지면 재확인** | 대화 상자에 **검증 실행**과 **그래도 기본값으로 설정**이 표시됩니다. |
| **검사 후 점수가 낮아지면 지정 차단** | 검증 결과 점수가 낮아지지 않은 프롬프트만 기본값으로 설정할 수 있습니다. |
| **검사 안 함** | 프롬프트를 즉시 기본값으로 설정합니다. |

검증에는 답변을 최대 8개 사용합니다. 먼저 회귀 테스트 세트의 답변을 가져온 뒤, 이 답변을 채점하는 첫 번째 평가기가 가장 최근에 채점한 답변을 가져옵니다. 같은 모델이 현재 기본값과 새 버전으로 각각 답변을 다시 생성합니다. 도구는 다시 실행하지 않고, 모델에 질문과 당시 도구 실행 결과를 제공합니다. 근본 원인 분석에서는 두 버전 모두 인시던트에서 확인된 사실을 바탕으로 분석을 작성합니다. 그런 다음 평가기가 각 답변 쌍을 채점합니다. 새 버전의 평균 점수가 현재 기본값보다 5점 넘게 낮으면 **악화**, 5점 넘게 높으면 **개선**, 그 외에는 **악화 없음**으로 판정합니다. 비교할 수 있는 답변이 3개 미만이면 판정할 수 없으므로 기본값 설정을 차단하지 않습니다.

대화 상자에는 검증 진행 상황과 각 답변의 결과가 차례로 표시됩니다. 검증에서는 프롬프트 버전 하나를 기본값 하나와 비교합니다. 프롬프트를 수정하거나 다른 프롬프트를 기본값으로 설정하면 검증을 다시 실행해야 합니다. 검증 중 발생하는 모델 호출은 **품질 평가**로 집계합니다.

다른 용도의 프롬프트는 검증 없이 기본값으로 설정합니다. 이미 기본값인 프롬프트를 수정할 때도 검증하지 않습니다. 변경 사항을 검증하려면 새 프롬프트로 저장한 뒤 기본값으로 설정합니다.

## 스트림에서 점수 조회하기

각 점수는 내부 스트림 `_agent_score_traces`에도 행 하나로 기록됩니다. 이 스트림은 **로그**에서 쿼리할 수 있습니다.

| 필드 | 설명 |
|---|---|
| `target_kind`, `target_id` | `chat_answer`와 메시지 ID 또는 `incident_rca`와 인시던트 ID입니다. |
| `source` | `personal_chat`, `team_chat`, `automation`, `incident_rca` 중 하나입니다. |
| `scorer`, `scorer_kind` | `rules` 또는 평가기 ID와 `evaluator`입니다. |
| `score`, `samples` | 0에서 1 사이의 평균 점수와 평균을 계산하는 데 사용한 채점 횟수입니다. |
| `tool_success`, `evidence`, `query_validity`, `answer_format`, `completion`, `feedback` | 해당하는 경우 기록하는 규칙별 점수로, 0에서 1 사이입니다. |
| `reason`, `evaluator_model` | 평가 근거와 평가기에 사용한 모델입니다. |
| `chat_id`, `team_id`, `automation_id`, `user_id`, `prompt_template_id`, `prompt_version`, `prompt_key`, `provider_id`, `model`, `skill`, `skill_version` | 답변의 출처와 답변 생성에 사용한 항목입니다. |

품질이 저하될 때 알림을 받으려면 스트림에 [이상 탐지 알림 규칙](/ko/alerting)을 만듭니다. 예를 들어 평가기 점수의 평균을 기준으로 규칙을 만들 수 있습니다.

```sql
SELECT avg(score) AS value FROM "_agent_score_traces" WHERE scorer_kind = 'evaluator'
```
