**확장 테이블**은 MoleSignal에 저장하는 소규모 조회 테이블로, 키를 레코드에 매핑합니다.
[파이프라인](/ko/pipelines) 변환은 이 테이블에서 키를 조회해 이벤트에 참조 데이터를 보강합니다. 예를 들어
`service`를 담당 팀에, 계정 ID를 요금제 등급에, 리전 코드를 리전 이름에 매핑합니다.
이렇게 하면 주요 처리 경로에서 외부 저장소를 호출하지 않아도 됩니다.

## 테이블 목록

**테이블 확장**을 엽니다. 상단에 테이블 수와 전체 레코드 수가 표시됩니다. 각 테이블에는 조회 키와
필드, 레코드 수, 사용 위치, 마지막 업데이트 시점, 상태(**정상** 또는
**비어 있음**)가 표시됩니다. 상태와 사용 여부(**사용 중** 또는 **미사용**)로 필터링하고 이름으로 검색합니다.

## 테이블 만들기

**새 확장 테이블**을 선택합니다. 마법사는 두 단계로 구성됩니다.

<Steps>
  <Step title="스키마 정의">
    **테이블** 이름과 **설명**을 입력합니다. `customer_id`, `service`, `region_code`처럼 레코드를
    식별하는 필드를 **조회 키**로 선택합니다. **값 필드**를 추가하고 **필드** 이름,
    **유형**(**문자열**, **숫자**, **불리언**, **객체**), **필수** 여부,
    설명을 지정합니다. 구조가 정해지지 않은 JSON 레코드를 저장하려면 값 필드를 비워 둡니다. 테이블당
    값 필드를 최대 100개까지 추가할 수 있습니다. 필드 이름에는 문자, 숫자, `.`, `-`, `_`를 사용합니다.
  </Step>
  <Step title="데이터 추가 또는 가져오기">
    나중에 레코드를 추가하려면 **빈 테이블로 시작**을, 지금 추가하려면 **JSON 붙여넣기**를 선택합니다. 각 레코드에 조회 키가 포함된
    JSON 배열이나 각 키를 해당 레코드에 매핑하는 JSON 객체를 사용합니다.
  </Step>
</Steps>

**확장 테이블 만들기**를 선택합니다.

## 레코드

테이블을 엽니다. **데이터 레코드** 탭에 레코드가 표시됩니다. 조회 키나 필드 값으로 검색합니다.

| 작업 | 동작 |
|---|---|
| **레코드 추가** | **양식 모드** 또는 **JSON 모드**에서 조회 키와 필드 값을 입력합니다. 이미 있는 키를 입력하면 경고를 표시한 뒤 기존 레코드를 덮어씁니다. |
| **레코드 편집** | 레코드의 값을 변경합니다. |
| **JSON 보기** | 테이블에 열로 표시되지 않는 필드를 포함해 전체 레코드를 표시합니다. |
| **레코드 삭제** | 레코드를 삭제합니다. 이 작업은 실행 취소할 수 없습니다. |
| **데이터 가져오기** | JSON 파일(배열 또는 키와 레코드의 매핑), 첫 행에 필드 이름이 있는 CSV 파일 또는 붙여넣은 JSON이나 CSV에서 여러 레코드를 한 번에 가져옵니다. 데이터에 조회 키 열이 있어야 합니다. 요약에는 가져올 레코드 수와 기존 키의 레코드를 덮어쓸 레코드 수가 표시됩니다. |

## 스키마, 사용량 및 설정

| 탭 | 내용 |
|---|---|
| **스키마** | 조회 키와 값 필드를 표시합니다. **필드 편집**에서 필드를 추가하고 설명과 **필수** 여부를 변경합니다. 레코드가 있으면 기존 필드의 이름이나 유형을 변경하거나 필드를 삭제할 수 없습니다. 빈 테이블에서는 이러한 변경을 모두 적용할 수 있습니다. 테이블 이름과 조회 키는 변경할 수 없습니다. |
| **사용량** | 테이블을 참조하는 파이프라인과 저장된 쿼리를 표시합니다. 테이블을 변경하거나 삭제하기 전에 확인합니다. |
| **설정** | **테이블 정보**를 표시합니다. **위험 영역**의 **확장 테이블 삭제**를 선택하면 테이블과 모든 레코드를 삭제합니다. 삭제 후 테이블 조회는 `null`을 반환합니다. 파이프라인이 테이블에 쓰려는 이벤트는 쓰기에 실패하며, 파이프라인에 데드 레터 스트림이 있으면 해당 스트림으로 이동합니다. |

## 파이프라인에서 키 조회

파이프라인에서 [**확장 테이블 조회**](/ko/pipelines#확장-테이블-조회)
단계를 사용하면 행의 값을 이벤트 필드에 복사합니다. 또는 VRL 단계에서
[`lookup(table, key)`](/ko/functions#테이블과-ip-주소-조회)를 사용하면 다음과 같이
행을 반환합니다.

```ruby
# enrich each event with the service's owning team
.team = lookup("service_meta", .service).team
```

두 방법 모두 [알림 파이프라인](/ko/pipelines/alert-events)을 포함한 모든 유형의 파이프라인에서 작동합니다. 노드는
단계에서 테이블이 처음 필요할 때 읽고 30초 동안 메모리에 보관합니다. 따라서 조회로 인해 파이프라인 실행에 쿼리
비용이나 스토리지 비용이 추가되지 않습니다. 레코드 추가, 변경 또는 삭제는 모든 파이프라인에
30초 이내에 반영됩니다. 확장 테이블은 워크스페이스에 속하며, 해당 워크스페이스의 모든 파이프라인에서 사용할 수 있습니다.

## 파이프라인에서 테이블 채우기

예약된 파이프라인으로 테이블을 최신 상태로 유지할 수 있습니다. **대상 추가 → 확장 테이블**을 선택하면 각 이벤트를
파이프라인 단계에서 처리한 뒤 조회 키 값에 해당하는 행으로 기록합니다.
[확장 테이블에 쓰기](/ko/pipelines#확장-테이블에-쓰기)를 참조합니다.

## 확장 테이블 API

```bash
# upsert a record keyed by "checkout"
curl -X PUT http://localhost:5080/api/v1/extend_tables/service_meta/rows/checkout \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"team":"payments","tier":"gold"}'
```

| 작업 | 엔드포인트 |
|---|---|
| 테이블 목록 조회 | `GET /api/v1/extend_tables` |
| 테이블의 레코드 목록 조회 | `GET /api/v1/extend_tables/{table}` |
| 레코드 추가 또는 업데이트 | `PUT /api/v1/extend_tables/{table}/rows/{key}` |
| 레코드 삭제 | `DELETE /api/v1/extend_tables/{table}/rows/{key}` |

## 권한

테이블 목록과 사용량을 조회하려면 `functions.read` 권한이 필요합니다. 테이블을 만들려면 `functions.create`,
레코드와 필드를 변경하려면 `functions.edit`, 테이블을 삭제하려면 `functions.delete` 권한이 필요합니다.
