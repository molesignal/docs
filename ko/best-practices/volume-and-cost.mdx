텔레메트리는 그 데이터로 답할 수 있는 질문보다 빠르게 늘어납니다. 디버그 로그를 켜 두거나, 라벨에 사용자 ID를 넣거나,
상태 확인을 매초 기록하면 인시던트 해결에는 도움이 되지 않으면서 저장 용량이 두 배로 늘어날 수 있습니다.
불필요한 데이터는 줄이고 조사에 필요한 데이터는 보존합니다.

## 먼저 측정합니다

설정을 변경하기 전에 데이터 볼륨이 큰 스트림을 찾습니다.

| 위치 | 확인할 수 있는 정보 |
|---|---|
| [홈](/ko/home#데이터-수집) | 선택한 기간에 신호 유형별로 수신하고 저장한 데이터의 양을 보여 줍니다. |
| [스트림](/ko/streams#스트림-목록) | 스트림별로 해당 기간의 압축 데이터 크기, 변환 전 **수집 크기**, **저장 크기**, **인덱스 크기**, **레코드**를 보여 줍니다. 이 값을 비교해 데이터 볼륨이 가장 큰 스트림을 찾습니다. |
| [수집 사용량](/ko/streams#데이터-수집-사용량-및-예산) | 토큰, 커넥터, 스트림, 서비스별 수집량을 보여 줍니다. 예산을 설정하면 소스의 수집량이 예산에 근접하거나 초과할 때 알림을 보냅니다. |
| [메트릭](/ko/metrics#결과-분석하기) | 메트릭의 활성 시계열 수인 **카디널리티**를 보여 줍니다. |
| [Mole Agent 사용량](/ko/agent#사용량-및-예산) | 소스별·일별 모델 토큰 사용량과 일일 예산을 보여 줍니다. |

데이터 볼륨이 가장 큰 스트림의 수치를 기록합니다. 이 수치를 기준으로 각 변경의 효과를 판단합니다.

## 사용하지 않는 데이터는 저장 전에 제거합니다

데이터를 아예 저장하지 않는 것이 가장 저렴합니다. 로그의 경우 실시간
[파이프라인](/ko/pipelines#실시간-파이프라인)이 저장 전 수집 단계에서 실행됩니다.

- **이벤트 필터링**은 프로덕션에서 확인하지 않는 상태 확인, 준비 상태 프로브,
  디버그 로그를 제거합니다.
- **샘플링 비율**은 발생량이 많지만 유용한 이벤트 유형의 일부를 보존합니다. **필드 기준 샘플링**을 사용하면
  동일한 요청 ID처럼 필드 값이 같은 이벤트를 모두 보존하거나 모두 제거합니다.
- **필드 제거**는 전체 요청 본문처럼 어떤 쿼리에서도 사용하지 않는 대용량 필드를 제거합니다.

가능하면 전송 측 설정부터 변경합니다. 프로덕션의 로그 수준을 `info`로 설정하거나
불필요한 데이터를 제거하는 컬렉터 프로세서를 사용하면 네트워크 트래픽도 줄일 수 있습니다. 제거한 이벤트는 복구할 수 없습니다.
반복되는 이벤트만 샘플링하고 오류는 샘플링하지 않습니다.

트레이스 볼륨은 소스나 OpenTelemetry Collector에서 줄이는 것이 가장 좋습니다. 같은 트레이스에 속한
스팬은 함께 처리합니다. APM 지표와 SLO는 도착한 스팬만 집계합니다.
트레이스 스트림의 [실시간 파이프라인](/ko/pipelines#트레이스)에서는 테일 샘플링 이후에도 샘플링할 수 있습니다.
**필드 기준 샘플링**을 `trace_id`로 설정하면 트레이스 단위로 보존하거나 제거합니다. APM 지표는 파이프라인 실행 전에
계산하므로 파이프라인에서 제거한 스팬도 집계합니다. RUM은 애플리케이션별로
[세션 샘플링](/ko/rum/sampling)을 설정합니다.

## 필요한 기간만 데이터를 보존합니다

| 데이터 | 리텐션 | 설정 방법 |
|---|---|---|
| 디버그 로그 및 상세 로그 | 일 단위 | 별도 스트림을 사용하고 **데이터 보존 기간(일)**을 짧게 설정합니다. |
| 애플리케이션 로그 및 액세스 로그 | 주 단위 | [플랫폼 기본값](/ko/settings/platform#데이터-보존)인 30일을 사용하거나 스트림별로 설정합니다. |
| 감사 및 규정 준수 로그 | 월 또는 연 단위 | 보존 기간이 길고 액세스가 제한된 스트림을 사용합니다. |
| 메트릭 | 월 단위 | 메트릭 스트림의 **리텐션** 탭에서 **오래된 샘플 다운샘플링**을 사용합니다. 오래된 샘플을 시간 구간별로 집계해 장기간을 조회하는 쿼리가 읽는 데이터의 양을 크게 줄입니다. |

실제 조사에서 얼마나 과거까지 조회하는지에 맞춰 보존 기간을 설정하고, 문제를 늦게 발견할 경우에 대비해 여유를 둡니다.
보존 기간을 줄이면 다음 정리 작업에서 새 보존 기간을 초과한 데이터를 삭제합니다. 다운샘플링은
원본 샘플을 삭제합니다. 두 작업 모두 되돌릴 수 없습니다. 로그와
트레이스에는 **작은 파일을 일별로 병합**을 켜 둡니다. 이렇게 하면 여러 날을 조회하는 쿼리가 더 적은 파일을 엽니다.

## 메트릭 시계열 수를 제한합니다

고유한 라벨 값 조합마다 시계열 하나가 생성됩니다. 사용자 ID,
요청 ID, 원본 URL처럼 값의 종류를 제한할 수 없는 라벨은 시계열을 계속 늘립니다.
[카디널리티 한도](/ko/settings/platform#메트릭-카디널리티)에 도달하면 조직 전체에서
새 시계열을 추가할 수 없습니다.

- 라벨을 추가한 후 메트릭에서 **카디널리티**를 확인합니다.
- 원본 경로는 경로 템플릿으로, ID는 요금제나 리전과 같은 범주로 대체합니다.
- 요청별 상세 정보는 값의 종류에 따라 비용이 늘지 않는 로그나 스팬에 기록합니다.
- 전송 측을 변경할 수 없다면 메트릭 스트림에 [실시간 파이프라인](/ko/pipelines#메트릭과-트레이스)을 적용해
  샘플을 저장하기 전에 라벨을 제거하거나 변경합니다.

## 쿼리 비용을 줄입니다

| 권장 사항 | 효과 |
|---|---|
| 대용량 스트림에 **최대 쿼리 범위(시간)**를 설정합니다 | 실수로 '최근 90일'을 조회해도 전체 데이터를 스캔하지 않고 쿼리를 거부합니다. |
| 대시보드에서 필터링에 사용하는 필드를 인덱싱합니다 | 필터에 해당하지 않는 파일은 읽지 않습니다. [스트림 및 필드 설계](/ko/best-practices/stream-design#필터링에-사용하는-필드에-인덱스-설정)를 참조합니다. |
| 가장 짧은 시간 범위에서 시작합니다 | 좁은 범위에서 시작해 필요한 경우에만 넓힙니다. |
| 오래 걸리는 스캔은 [검색 작업](/ko/streams#검색-작업)으로 실행합니다 | 페이지를 열어 둘 필요 없이 백그라운드에서 쿼리를 실행하고 결과를 보존합니다. |
| 대시보드는 확인 빈도에 맞춰 새로고침합니다 | **자동** 새로고침은 시간 범위에 맞춰 주기를 조정합니다. 부하가 큰 패널을 벽면 화면에 표시할 때는 짧은 주기를 피합니다. |

## 완료 기준

- 데이터 볼륨이 가장 큰 스트림 5개를 파악하고 변경 전후의 일일 데이터 볼륨을 기록합니다.
- 어느 스트림에도 상태 확인, 준비 상태 프로브, 프로덕션 디버그 로그가 의도치 않게 저장되지 않습니다.
- 스트림별로 필요한 보존 기간을 설정하고 장기 보존 메트릭을 다운샘플링합니다.
- 메트릭 시계열 수가 매주 안정적으로 유지되고 한도보다 훨씬 낮습니다.
- 대용량 스트림에 최대 쿼리 범위를 설정하고 자주 필터링하는 필드를 인덱싱합니다.
