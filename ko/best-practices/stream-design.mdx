데이터, 대시보드, 알림 규칙이 스트림과 필드에 의존하기 시작하면 변경이 어렵습니다. 필드
유형은 한 번 기록되면 고정되고, 암호화 플래그는 나중에 추가할 수 없으며, 필드 이름을 변경하면 저장된 모든
쿼리가 깨집니다. 첫 번째 사용량이 많은 소스를 연결하기 전에 설계에 한 시간을 투자하십시오.

## 다른 점에 따라 스트림 분할

데이터에 다른 계약이 필요할 때만 별도 스트림을 만드십시오. 예를 들어 다른 보존 기간, 다른
접근 규칙, 다른 스키마 또는 별도의 쿼리 범위 제한이 필요할 수 있습니다. 그렇지 않으면 데이터를 함께 두고 필드로
구분하십시오.

| 상황 | 권장 | 트레이드오프 |
|---|---|---|
| 디버그 로그는 3일, 감사 로그는 1년 보관 | 자체 보존 기간을 가진 두 개의 `logs` 스트림 | 두 스트림이 모두 필요한 쿼리는 두 스트림을 사용합니다. |
| 로그 형태가 같은 여러 서비스 | 모든 이벤트에 `service.name`이 있는 하나의 스트림 | 서비스별로 보존 기간과 접근 권한을 다르게 할 수 없습니다. |
| 파이프라인이 스트림으로 분류하는 원시 대량 스트림 | **쿼리 허용**을 끈 소스 스트림과 라우팅 파이프라인 | 원시 이벤트는 보존 기간이 끝날 때까지 보관되므로 보존 기간을 짧게 유지하십시오. |
| 각 Prometheus 서버 | 소스당 하나의 `metrics` 스트림 | 여러 소스를 가로지르는 쿼리는 여러 스트림을 지정합니다. |
| Pod, 버전 또는 고객당 하나의 스트림 | 피하십시오. 대신 필드를 사용하십시오. | 작은 스트림이 많으면 파일 수가 늘어나고 변경할 때마다 대시보드가 깨집니다. |

MoleSignal은 첫 번째 쓰기 시 스트림을 생성하므로 송신자의 오타로 새 스트림이 알림 없이 생성됩니다.
각 소스를 연결한 후 [스트림 목록](/ko/streams#the-stream-list)을 확인하고, 보존 기간과 암호화 필드를
설정하여 중요한 스트림을 미리 만드십시오.

## 전송 전 필드 이름 합의

OpenTelemetry 이름이 있는 경우 해당 이름을 사용하고, 모든 시그널에서 같은 대상에는 같은 이름을
사용하십시오. 시그널 간 이동과 APM은 이 이름에 의존합니다.

| 필드 | 내용 | 이유 |
|---|---|---|
| `service.name` | 로그, 트레이스, 메트릭에서 동일한 서비스 | 모든 시그널을 하나의 서비스로 연결합니다. |
| `deployment.environment.name` | `production`, `staging` 등 | 모든 페이지를 환경별로 필터링합니다. |
| `service.version` | 릴리스된 버전 | APM의 배포 비교 기준입니다. |
| `trace_id`, `span_id` | 요청 내에서 기록되는 모든 로그 라인에 설정합니다. | 로그 라인에서 해당 트레이스로 바로 이동할 수 있게 합니다. |
| `level` | 소문자 `error`, `warn`, `info`와 같은 하나의 표기 | 로그 히스토그램은 인덱스에서 레벨을 집계합니다. |
| `host.name`, `k8s.pod.name` | 이벤트가 발생한 위치 | 문제를 하나의 머신으로 좁힙니다. |

모든 송신자에서 필드 유형을 동일하게 유지하십시오. 한 서비스에서는 숫자로 도착하고 다른
서비스에서는 텍스트로 도착하는 필드는 `type mismatch on field` 오류와 함께 거부됩니다. 이러한 필드는 저장되기 전에
**유형 변환**을 사용하는 파이프라인에서 정규화하십시오. 정수와 소수 부분이 있는 숫자는 하나의
필드를 공유할 수 있으며, 이 경우 `float64`가 됩니다. 기존 필드 이름을 새로운
의미로 재사용하지 마십시오. 대신 새 필드를 추가하십시오.

## 필터링되는 항목에 인덱스 지정

[인덱스 유형](/ko/streams#스키마-및-필드)은 필터 속도를 결정합니다. 새 필드에는 인덱스가 없으며,
몇 가지 잘 알려진 이름은 예외입니다. 대시보드와 알림이 필터링하는 필드를 검토하십시오:

- 전체 값으로 비교하는 식별자에는 **정확히 일치**를 사용하십시오: `trace_id`, `user_id`, `order_id`,
  `service.name`.
- `message`처럼 단어 단위로 검색하는 텍스트에는 **전체 텍스트 검색**을 사용하십시오.
- `<` 및 `>`로 비교하는 숫자와 시간에는 **스킵 인덱스**를 사용하십시오(예: `duration_ms`).
- 표시에만 사용하는 필드에는 인덱스를 지정하지 마십시오.

인덱스 변경은 새 데이터에 적용됩니다. 이전 파일은 컴팩터가 병합할 때 인덱스를 갖게 됩니다. 인덱스는
**스트림 → 필드 및 인덱스**에서 변경한 다음 **저장 및 적용**을 선택하십시오.

## 레이블에서 카디널리티 제외

사용자 ID, 요청 ID 또는 전체 URL처럼 값이 무한정 늘어날 수 있는 메트릭 레이블은 값마다 새
시계열을 만듭니다. 그러면 [카디널리티 제한](/ko/settings/platform#메트릭-카디널리티)이 조직 전체에서
새 시계열을 거부합니다. 이러한 값은 로그나 스팬 속성에 넣으십시오. 여기서는 값당 비용이
들지 않습니다. 또한 메트릭 레이블은 서비스, 경로 템플릿, 메서드 및
상태 클래스처럼 범위가 제한된 집합으로 유지하십시오.

그렇지 않으면 모든 이벤트에 복사될 참조 데이터(예: 서비스의 팀 또는 고객의
요금제)는 [확장 테이블](/ko/extend-tables)에 두십시오. 파이프라인이 처리하는 동안
해당 데이터를 조회합니다.

## 처음부터 민감한 값 보호

| 필요 사항 | 도구 | 적용 시점 |
|---|---|---|
| 카드 번호와 같은 값을 절대 저장하지 않기 | **수집 시 마스킹**을 사용하는 [정규식 패턴](/ko/settings/data-security#정규식-패턴) 또는 필드를 제거하는 파이프라인 단계 | 수집 시점에 영구 적용됩니다. |
| 값을 저장하되 일부 사용자만 읽기 | 스트림을 만들 때 선언하고 `decrypt()`로 읽는 암호화 필드 | 스트림 생성 시점부터 적용됩니다. |
| 대부분의 쿼리 결과에서 값을 숨기기 | [필드 마스킹](/ko/settings/data-security#필드-마스킹) | 쿼리 시점에 결과에 적용됩니다. |

송신자 또는 수집기에서 값을 제거하는 것이 좋습니다. 소스를 떠나지 않는 값은
MoleSignal에서 유출될 수 없습니다.

## 완료 기준

- 모든 스트림에는 소유자, 존재 이유, 의도적으로 설정한 보존 기간이 있습니다.
- 알려진 요청은 로그 라인에서 한 번의 클릭으로 해당 트레이스까지 추적할 수 있습니다.
- 대시보드와 규칙에서 필터링하는 필드에는 적절한 인덱스가 있습니다.
- 값이 무한정 늘어날 수 있는 메트릭 레이블이 없으며, 메트릭의 **카디널리티**에 안정적인 시계열 수가 표시됩니다.
- 민감한 마커가 포함된 테스트 이벤트는 계획대로 수집 시 마스킹, 필드 마스킹 또는 암호화 처리되어 도착합니다.
