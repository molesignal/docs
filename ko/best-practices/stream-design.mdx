데이터, 대시보드, 알림 규칙이 스트림과 필드에 의존하기 시작하면 변경하기 어렵습니다. 필드
유형은 처음 기록할 때 고정되고, 암호화 플래그는 나중에 추가할 수 없습니다. 필드 이름을 바꾸면 해당 필드를 사용하는
저장된 쿼리가 모두 작동하지 않습니다. 트래픽이 많은 첫 소스를 연결하기 전에 한 시간 정도 설계에 투자합니다.

## 요구사항에 따라 스트림 분리

데이터에 다른 보존 기간, 액세스 규칙, 스키마 또는 쿼리 범위 제한이
필요할 때만 별도 스트림을 만듭니다. 그 외에는 데이터를 한 스트림에 유지하고 필드로
구분합니다.

| 상황 | 권장 구성 | 고려할 점 |
|---|---|---|
| 디버그 로그는 3일, 감사 로그는 1년 보존 | 보존 기간을 각각 설정한 `logs` 스트림 두 개를 사용합니다. | 두 로그가 모두 필요한 쿼리는 두 스트림을 사용합니다. |
| 여러 서비스의 로그 구조가 같음 | 스트림 하나를 사용하고 모든 이벤트에 `service.name`을 넣습니다. | 서비스별로 보존 기간과 액세스 규칙을 다르게 설정할 수 없습니다. |
| 파이프라인이 대량의 원시 데이터를 여러 스트림으로 분류 | 소스 스트림에서 **쿼리 허용**을 끄고 라우팅 파이프라인을 사용합니다. | 보존 기간이 끝날 때까지 원시 이벤트가 남으므로 보존 기간을 짧게 설정합니다. |
| Prometheus 서버별로 수집 | 소스마다 `metrics` 스트림을 하나씩 사용합니다. | 여러 소스를 조회하려면 쿼리에 여러 스트림을 지정합니다. |
| Pod, 버전 또는 고객마다 스트림 하나씩 사용 | 이 구성은 피하고 대신 필드를 사용합니다. | 작은 스트림이 많으면 파일 수가 늘고 구성이 바뀔 때마다 대시보드가 작동하지 않습니다. |

MoleSignal은 데이터를 처음 기록할 때 스트림을 생성하므로, 송신 측에서 스트림 이름에 오타를 내면 별도 알림 없이 새 스트림이 생성됩니다.
각 소스를 연결한 후 [스트림 목록](/ko/streams#스트림-목록)을 확인합니다. 중요한 스트림은
보존 기간과 암호화 필드를 지정해 미리 생성합니다.

## 전송 전에 필드 이름 통일

OpenTelemetry에 정의된 이름이 있으면 그대로 사용하고, 동일한 항목에는 모든
시그널에서 같은 이름을 사용합니다. 시그널 간 이동과 APM은 이 이름을 기준으로 동작합니다.

| 필드 | 내용 | 이유 |
|---|---|---|
| `service.name` | 서비스 이름입니다. 로그, 트레이스, 메트릭에 동일한 값을 사용합니다. | 모든 시그널을 같은 서비스에 연결합니다. |
| `deployment.environment.name` | `production`, `staging` 등의 환경 이름입니다. | 모든 페이지에서 환경별로 필터링합니다. |
| `service.version` | 릴리스 버전입니다. | APM에서 배포를 비교하는 기준입니다. |
| `trace_id`, `span_id` | 요청을 처리하는 동안 기록하는 모든 로그 줄에 설정합니다. | 로그 줄에서 해당 트레이스로 바로 이동할 수 있습니다. |
| `level` | 소문자 `error`, `warn`, `info`처럼 표기를 통일합니다. | 로그 히스토그램은 인덱스를 사용해 레벨별 로그 수를 집계합니다. |
| `host.name`, `k8s.pod.name` | 이벤트가 발생한 위치입니다. | 문제가 발생한 머신을 특정할 수 있습니다. |

모든 송신 측에서 필드 유형을 동일하게 유지합니다. 한 서비스는 필드 값을 숫자로 보내고 다른
서비스는 텍스트로 보내면 `type mismatch on field` 오류와 함께 데이터가 거부됩니다. 이런 필드는 저장하기 전에
파이프라인에서 **유형 변환**으로 정규화합니다. 기존 필드 이름을 다른 의미로 재사용하지 않고
새 필드를 추가합니다.

## 필터링에 사용하는 필드에 인덱스 설정

[인덱스 유형](/ko/streams#스키마-및-필드)에 따라 필터링 속도가 달라집니다. 널리 쓰이는 일부 이름을
제외하면 새 필드에는 인덱스가 없습니다. 대시보드와 알림에서 필터링하는 필드를 검토합니다.

- **정확히 일치**: 전체 값을 비교하는 식별자에 사용합니다. 예: `trace_id`, `user_id`, `order_id`,
  `service.name`.
- **전체 텍스트 검색**: `message`처럼 단어 단위로 검색하는 텍스트에 사용합니다.
- **스킵 인덱스**: `duration_ms`처럼 `<`, `>`로 비교하는 숫자나 시간 값에 사용합니다.
- 화면에 표시하기만 하는 필드에는 인덱스를 설정하지 않습니다.

인덱스 변경은 새 데이터에 적용되며, 기존 파일에는 컴팩터가 파일을 병합할 때 적용됩니다. 인덱스를 변경하려면
**스트림 → 필드 및 인덱스**에서 설정을 변경한 다음 **저장 및 적용**을 선택합니다.

## 메트릭 레이블의 카디널리티 제한

사용자 ID, 요청 ID, 전체 URL처럼 가능한 값의 범위가 제한되지 않은 값을 메트릭 레이블에 넣으면 값마다 새
시계열이 생성됩니다. [카디널리티 한도](/ko/settings/platform#메트릭-카디널리티)에 도달하면 조직 전체에서
새 시계열을 추가할 수 없습니다. 이런 값은 값마다 별도 시계열을 만들지 않는
로그나 스팬 속성에 넣습니다. 메트릭 레이블에는 서비스, 라우트 템플릿, 메서드,
상태 코드 분류처럼 가능한 값의 범위가 제한된 항목만 사용합니다.

서비스 담당 팀이나 고객 요금제처럼 모든 이벤트에 반복해서 넣게 되는
참조 데이터는 [확장 테이블](/ko/extend-tables)에 저장합니다. 파이프라인은 이벤트를
처리할 때 이 테이블을 조회합니다.

## 처음부터 민감한 값 보호

| 요구사항 | 도구 | 적용 시점 |
|---|---|---|
| 카드 번호와 같은 값을 저장하지 않음 | [정규식 패턴](/ko/settings/data-security#정규식-패턴)에 **수집 시 마스킹**을 적용하거나 파이프라인 단계에서 필드를 제거합니다. | 수집 시 영구적으로 적용합니다. |
| 값을 저장하되 일부 사용자만 읽을 수 있게 함 | 스트림을 생성할 때 암호화 필드를 지정하고 `decrypt()`로 읽습니다. | 스트림을 생성할 때부터 적용합니다. |
| 대부분의 쿼리 결과에서 값을 숨김 | [필드 마스킹](/ko/settings/data-security#필드-마스킹)을 사용합니다. | 쿼리 실행 시 결과에 적용합니다. |

가능하면 송신 측이나 수집기에서 값을 제거합니다. 소스를 벗어나지 않은 값은 MoleSignal에서
유출될 수 없습니다.

## 완료 기준

- 모든 스트림에 담당자와 사용 목적이 있으며, 목적에 맞는 보존 기간을 설정했습니다.
- 확인하려는 요청의 로그 줄에서 클릭 한 번으로 해당 트레이스를 열 수 있습니다.
- 대시보드와 알림 규칙에서 필터링하는 필드에 적절한 인덱스가 있습니다.
- 가능한 값의 범위가 제한되지 않은 메트릭 레이블이 없고, 메트릭의 **카디널리티**에서 시계열 수가 안정적으로 유지됩니다.
- 민감 데이터 확인용 표식이 포함된 테스트 이벤트에 계획대로 수집 시 마스킹, 필드 마스킹 또는 암호화가 적용됩니다.
