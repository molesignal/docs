인시던트 대응에 MoleSignal을 사용하기 전에 장애가 발생한 배포를 복구할 수 있는지 검증합니다. 백업 작업의 성공은 복구의 전제 조건일 뿐입니다. 복구의 합격 기준은 과거 데이터를 사용할 수 있고 데이터 수집이 재개되는 것입니다.

## 측정 가능한 복구 목표 설정

허용 가능한 최대 데이터 손실 범위인 복구 시점 목표와 허용 가능한 최대 복구 시간인 복구 시간 목표를 합의합니다. 이 목표를 바탕으로 백업 주기와 스토리지 보호 방식을 정합니다. 자격 증명 확보, 객체 복원, 데이터 검증, 송신 측 재연결에 걸리는 시간도 포함합니다.

오픈 소스 버전을 처음 배포할 때는 지원되는 독립 실행형 토폴로지를 우선 사용합니다. 역할을 분리하면 추가 조율이 필요하며, 역할 분리만으로는 고가용성을 확보할 수 없습니다. 역할 분리형 배포를 도입하기 전에 용량 확장이 실제로 필요한지 확인하고 장애 대응 계획을 검증합니다.

## 복구에 필요한 모든 자산 보호

| 자산 | 권장 보호 방법 | 누락 시 문제 |
|---|---|---|
| PostgreSQL 및 객체 스토리지 | 복원한 객체가 카탈로그의 참조와 일치하도록 백업을 보관합니다 | 메타데이터만으로는 쿼리에 응답할 수 없으며, 객체만으로는 카탈로그를 복원할 수 없습니다. |
| `MS_CIPHER_KEY` | 복구 시 접근 권한을 제한한 별도의 보호 사본을 보관합니다 | 일치하는 키 없이는 저장된 암호화 시크릿을 복구할 수 없습니다. |
| 구성 및 이미지 버전 | 각 백업 세트와 함께 구성과 이미지 버전을 모두 기록합니다 | 복원 시 호환되지 않는 설정이나 다른 스키마 버전을 사용할 수 있습니다. |
| 수집 WAL | 객체 스토리지 백업에 `wal/v1/`을 포함합니다. 노드에는 영구 볼륨이 필요하지 않습니다 | `wal/v1/`이 없는 버킷 백업에는 백업 시점에 아직 플러시되지 않은 레코드가 포함되지 않습니다. |

데이터베이스와 객체 스토리지의 백업이 서로 일관되도록 함께 계획합니다. 객체 백업이 완료되기 전에 객체 삭제나 가비지 컬렉션으로 데이터베이스 스냅샷에 필요한 파일이 제거되지 않는지 확인합니다. [백업 및 복원](/ko/backup-restore)의 백업 시점과 버전 관리 관련 고려 사항을 바탕으로 백업 방식을 선택합니다.

## 격리된 환경에서 복구 훈련

별도의 PostgreSQL 데이터베이스와 객체 스토리지 위치에 복원합니다. 프로덕션 송신 측은 계속 프로덕션 환경으로 데이터를 보내도록 유지합니다. 복원한 환경을 시작하기 전에 실제 알림을 보내거나 외부 시스템에 영향을 주는 작업을 실행하지 못하도록 차단합니다.

기록해 둔 이미지 버전과 그에 맞는 시크릿을 사용합니다. 각 단계의 소요 시간과 실패 내역을 기록합니다. 최신 레코드만 확인하지 말고 백업 시점 전후의 과거 데이터도 테스트합니다. 이미 알고 있는 로그 이벤트와 트레이스, 그리고 인시던트 대응 절차에 필요한 기타 신호를 확인합니다.

그런 다음 테스트용 새 데이터를 전송하고 쿼리로 다시 조회합니다. 복원한 환경에서 과거 데이터를 읽고 새 쓰기를 수락할 수 있는지 모두 검증합니다. 복구 목표를 평가하는 데 필요한 증거를 보존한 후에만 훈련 환경을 삭제합니다.

## 내구성과 성능 간의 절충점 평가

모든 쓰기는 해당 WAL 객체가 저장될 때까지 대기하므로 객체 스토리지의 지연 시간이 쓰기 지연 시간에 더해집니다. `[wal].lease_secs`를 줄이면 노드 손실 후 인계 시간이 짧아지지만 리스 갱신 빈도가 높아집니다. 설정을 변경하기 전에 실제 운영을 대표하는 부하와 장애 조건에서 쓰기 지연 시간과 인계 시간을 모두 측정합니다. WAL의 내구성을 확보해도 데이터베이스와 객체 스토리지 백업을 대체할 수는 없습니다.

상태 점검이 성공했다고 복구를 완료한 것으로 간주하지 않습니다. 카탈로그와 객체의 일관성, 이미 알고 있는 데이터, 접근 권한, 테스트 데이터의 쓰기 경로를 확인합니다. 복원한 데이터 세트가 완전하다고 판단하기 전에 보고된 객체 누락 문제를 해결합니다.

## 합격 기준

- 측정한 복원 시간과 복구된 데이터의 시점 범위가 합의한 목표를 충족합니다.
- 시크릿 값을 노출하지 않고 백업한 키와 구성을 사용해 복구합니다.
- 과거 데이터 조회와 테스트용 새 데이터 쓰기가 모두 성공합니다.
- 훈련 중 프로덕션 알림이 발송되거나 외부 시스템에 쓰기가 발생하지 않습니다.
- 지정된 팀이 후속 조치를 담당하고 스토리지, 버전 또는 토폴로지에 중대한 변경이 있을 때마다 훈련을 반복합니다.
