Gemini CLI는 stdio 및 Streamable HTTP 서버, OAuth 검색, MCP 도구, 리소스, 프롬프트를 지원합니다.

## Connect over stdio (recommended)

클라이언트는 MoleSignal CLI를 시작합니다. CLI는 메시지를 MoleSignal에 전달합니다.
Node.js 20 이상이 필요합니다.

<Steps>
  <Step title="한 번 로그인">

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

브라우저에서 MoleSignal이 열리면 로그인을 승인합니다. CLI는 로그인 상태를 유지하고 갱신합니다.

  </Step>
  <Step title="MoleSignal 추가">

```bash
gemini mcp add molesignal npx -y @molesignal/cli mcp
```

  </Step>
</Steps>

브라우저를 사용할 수 없다면 로그인하는 대신 `MOLESIGNAL_URL`과 `MOLESIGNAL_TOKEN`(API 토큰)을
서버 환경 변수로 설정합니다. [stdio로 연결](/ko/inbound-mcp#stdio로-연결)을 참조합니다.

다음 섹션에서는 CLI 없이 Streamable HTTP로 연결하는 방법을 설명합니다.

## Connect with OAuth 2.1

<Steps>
  <Step title="MoleSignal 추가">

    ```bash
    gemini mcp add --transport http --scope user \
      molesignal https://molesignal.example.com/api/v1/mcp
    ```

    항목을 현재 프로젝트의 `.gemini/settings.json`에 저장하려면 `--scope user`를 생략합니다.

  </Step>
  <Step title="인증">
    대화형 Gemini CLI 세션을 시작한 후 다음 명령을 실행합니다.

    ```text
    /mcp auth molesignal
    ```

    브라우저에서 권한 부여 절차를 완료합니다. Gemini CLI는 OAuth 엔드포인트를 찾고
    클라이언트를 동적으로 등록하는 작업을 자동으로 수행합니다.

  </Step>
  <Step title="서버 확인">

    ```bash
    gemini mcp list
    ```

    대화형 세션에서 `/mcp`를 실행해 연결된 도구, 리소스, 프롬프트를 확인합니다.

  </Step>
</Steps>

## Configure with JSON

`~/.gemini/settings.json` 또는
`.gemini/settings.json`에 추가할 동일한 Streamable HTTP 항목은 다음과 같습니다.

```json
{
  "mcpServers": {
    "molesignal": {
      "httpUrl": "https://molesignal.example.com/api/v1/mcp"
    }
  }
}
```

로컬 Gemini 정책에서 클라이언트의 확인 메시지를 건너뛰도록 의도한 경우가 아니라면
관리형 운영 서버에 `trust: true`를 설정하지 않습니다. 서버에는 MoleSignal 승인 정책이
그대로 적용됩니다.

[Gemini CLI MCP 공식 문서](https://geminicli.com/docs/tools/mcp-server/)를 참조합니다.
