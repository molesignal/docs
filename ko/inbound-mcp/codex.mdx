Codex는 stdio MCP 서버를 시작하며 MoleSignal의 Streamable HTTP 엔드포인트와 OAuth 검색을 지원합니다.

## stdio로 연결(권장)

클라이언트는 MoleSignal CLI를 시작하고, CLI는 메시지를 MoleSignal로 전달합니다. CLI를 실행하려면
Node.js 20 이상이 필요합니다.

<Steps>
  <Step title="한 번만 로그인">

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

브라우저에서 MoleSignal이 열리면 로그인을 승인합니다. CLI는 로그인 세션을 유지하고 갱신합니다.

  </Step>
  <Step title="MoleSignal 추가">

```bash
codex mcp add molesignal -- npx -y @molesignal/cli mcp
```

또는 `~/.codex/config.toml`에 다음을 추가합니다.

```toml
[mcp_servers.molesignal]
command = "npx"
args = ["-y", "@molesignal/cli", "mcp"]
```

  </Step>
</Steps>

브라우저를 사용할 수 없으면 로그인하는 대신 `MOLESIGNAL_URL`과 `MOLESIGNAL_TOKEN`(API 토큰)을
서버의 환경 변수로 설정합니다. [stdio로 연결](/ko/inbound-mcp#stdio로-연결)을 참조합니다.

아래 섹션에서는 CLI 없이 Streamable HTTP로 연결합니다.

## OAuth 2.1로 연결

<Steps>
  <Step title="MoleSignal 등록">

    ```bash
    codex mcp add molesignal \
      --url https://molesignal.example.com/api/v1/mcp
    ```

  </Step>
  <Step title="연결 승인">

    ```bash
    codex mcp login molesignal
    ```

    브라우저에서 MoleSignal의 인증 페이지를 열고 연결을 승인합니다.

  </Step>
  <Step title="서버 확인">

    ```bash
    codex mcp get molesignal
    codex mcp list
    ```

    MCP 도구 목록을 새로 고치려면 현재 Codex 작업을 다시 시작하거나 새 작업을 엽니다.

  </Step>
</Steps>

<Warning>
  `--oauth-resource`를 추가하지 않습니다. MoleSignal은 이미 보호된 리소스를
  OAuth 검색을 통해 게시합니다. 같은 값을 다시 추가하면 `duplicate field resource` 오류가 발생할 수 있습니다.
</Warning>

## API 토큰으로 연결

비대화형 Codex 프로세스에는 개인 API 토큰 또는 서비스 계정 API 토큰을 사용합니다.

```bash
export MOLESIGNAL_MCP_TOKEN="<api-token>"

codex mcp add molesignal \
  --url https://molesignal.example.com/api/v1/mcp \
  --bearer-token-env-var MOLESIGNAL_MCP_TOKEN
```

Codex는 토큰 값 대신 환경 변수 이름을 저장합니다. Codex를 시작하는 프로세스에서
이 환경 변수를 사용할 수 있도록 설정합니다.

## 도구 검색 확인

Codex에 다음과 같이 요청합니다.

> MoleSignal MCP 서버를 사용합니다. 인시던트 도구를 검색하고 활성 인시던트 목록을 표시합니다.
> 아무것도 변경하지 않습니다.

첫 요청에서는 `tool_search`를 먼저 사용한 다음, 지연 읽기를 위해 `call_read_tool`을 사용해야 합니다.

[공식 Codex MCP 문서](https://developers.openai.com/codex/mcp/)를 참조합니다.
