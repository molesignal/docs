완전한 트레이스, 개별 스팬, RED 드릴다운, 서비스
그래프 사이를 이동하려면 **트레이스**를 엽니다.

## 트레이스와 스팬 찾아보기

**트레이스** 탭은 요청마다 한 행을 나열합니다: 요청이 어떻게 종료되었는지(루트 스팬의 HTTP 상태 또는
**정상** 및 **오류**), 시작 시각, 서비스와 오퍼레이션, 페이지에서 가장 긴 트레이스 대비
지속 시간, 스팬 수, 오류 수, 트레이스 ID를 표시합니다. **시작 시각**,
**지속 시간**, **스팬**, **오류**를 클릭해 해당 열 기준으로 정렬합니다. 테이블 위의 히스토그램은 쿼리와 일치하는 모든 트레이스를 집계하고, 옆의 차트는
해당 트레이스의 p50, p95, p99 지속 시간을 그립니다.

**스팬** 탭은 일치하는 스팬마다 한 행을 나열하며, 스팬 종류와 자체 지속 시간을 표시합니다. 스팬의
필드에 적용한 필터는 이 탭에서 스팬 자체에 적용됩니다.

쿼리 편집기에는 **코드**와 **빌더** 모드가 있으며, 제목 옆의 두 아이콘으로 전환합니다(`</>`
는 코드, 블록 아이콘은 빌더). **코드**는 필드 쿼리를 받습니다. 예:
`status_code = 'ERROR'` 또는 `duration_ns > 500000000`(500ms보다 긴 경우), 또는 트레이스
스트림에 대한 SQL입니다. **빌더**는 필드 쿼리를 필터 행으로 보여 주며, 대안마다 한 행을 표시합니다. 쿼리는 나란히 배치할 수 있는 탭에서 실행되며,
필드 목록은 필드 분석을 열며, **공유**는 쿼리 링크를 복사합니다. 예를 들어
[로그](/ko/logs#쿼리-탭)에서와 같습니다. 주소 표시줄에는 적용된 쿼리도 유지되므로, 이를 복사하면
쿼리를 공유할 수 있습니다([쿼리 공유](/ko/logs#쿼리-공유)).

스팬 필드에 대한 비교는 해당 필드와 일치하는 스팬이 있는 트레이스를 유지하고, `!=`는
값을 가진 스팬이 하나도 없는 트레이스를 유지합니다. `trace_id`, `duration_ns`, `span_count`, `error_count`는
트레이스 자체에서 비교합니다. `in`은 여러 값 중 하나를 요청합니다:
`service.name in ('checkout', 'payments')`.

`AND`와 `OR`는 비교를 결합하며, `AND`가 먼저이고, 괄호로 묶습니다. 예를 들어
[로그](/ko/logs#쿼리-작성)에서와 같습니다. 비교는 `OR` 안에서도 의미를 유지합니다:
`service.name = 'checkout' OR span_count > 50`은 `checkout` 스팬이 있는 트레이스와
스팬이 50개를 초과하는 트레이스를 유지합니다. 필드가 없는 텍스트(예: `timeout`)는 트레이스
ID, 스팬 ID, 서비스, 오퍼레이션, 상태에서 검색합니다. **스팬** 탭과 RED 드릴다운은 각 스팬에 대해 동일한
쿼리를 해석합니다. 스팬은 `a` 또는 `b`와 일치할 때 `a OR b`와 일치합니다.

필드 목록은 결과 옆에 있습니다. **공통 필드**가 먼저 나옵니다: `service.name`, `name`,
`status_code`, HTTP 상태, `duration_ns`. 필드는 로드된 트레이스가 보유한 값을 기준으로 열립니다.
**이 값만 포함**은 값을 쿼리에 추가하며, 대안으로 구성된 쿼리는 먼저 괄호로 묶어
값이 쿼리 전체를 좁히도록 합니다. 같은 필드의 두 번째 값은
첫 번째 값과 `in` 목록으로 결합되므로 여러 값을 선택할 수 있습니다. **이 값 제외**는
값을 제외합니다.

**트레이스** 테이블 위의 **열**은 열을 표시하고 숨기고 재정렬하며,
각 트레이스의 루트 스팬 필드를 열로 추가합니다. 필드 목록에서 해당 필드의 눈 아이콘도 같은 역할을 합니다. 이러한
배치는 사용자마다 스트림별로 유지되며, **기본값으로 재설정**은
테이블이 처음 열릴 때의 열을 복원합니다.

## RED 드릴다운

**RED** 탭은 쿼리와 일치하는 요청의 요청률, 오류, 지속 시간을 보여 줍니다: 서비스가
요청을 수신한 지점을 기준으로 하거나, 요청 시 모든 스팬을 기준으로 합니다. **분류 기준**은 요청을 모든 스팬 필드로 그룹화하며,
테넌트와 같은 [비즈니스 키](/ko/business-context)도 포함됩니다. 값을 선택하면 쿼리가 해당 값으로 좁혀지고
한 단계 더 깊은 필드로 이동하며, 지연 시간 차트 위를 드래그하면 지속 시간 범위로 좁혀집니다.

**비교**는 실패한 요청 또는 p95나 p99보다 느린 요청을 쿼리의 다른 요청과
필드별로 대조합니다. 두 집합이 값을 가장 적게 공유하는 필드가 먼저 나오며, 각 필드에는
비중이 가장 크게 다른 값과 해당 필드에서 두 집합이 얼마나 떨어져 있는지가 표시됩니다. 범위는 0%(동일한 구성)에서 100%(공통
값 없음)까지입니다. 느린 요청이 몰리는 리전, 버전, 테넌트가 상단에 두드러집니다.
ID, 시점, JSON 필드는 제외되며, 실패한 요청을 비교할 때는 상태도 제외됩니다. 각
집합은 카드에 표시된 대로 최대 1,000개 스팬의 샘플에서 읽습니다. 필드를 열면 해당 필드의 분석이 열리고,
값을 선택하면 쿼리가 해당 값으로 좁혀집니다. Mole Agent는 `compare_attribute_distributions`로 같은 방식으로 비교합니다.

## 트레이스 살펴보기

행을 클릭하면 목록 위의 드로어에서 트레이스가 열립니다. 드로어의 왼쪽 가장자리를 드래그하여
너비를 변경할 수 있으며, 이 너비는 다음 트레이스에도 유지됩니다. **J**와 **K**는 목록의 다음 및 이전 트레이스로 이동하며,
드로어는 해당 트레이스의 자체 페이지도 엽니다.

트레이스의 헤드는 고정되어 있습니다. 루트 서비스와 작업, HTTP 상태, 오류
개수, 기간, 시작 시간, 스팬 수와 서비스 수, 깊이, 트레이스 ID가 표시됩니다.
**관련 로그**와 **서비스 메트릭**은 트레이스 주변의 해당 시그널을 엽니다. **프로필**은
트레이스 ID를 보관한 프로필을 열거나, 그러한 프로필이 없으면 트레이스 전후 몇 분의 프로필을
엽니다. **사용자 세션**은 트레이스가 처리한 [RUM](/ko/rum) 세션을 엽니다. 즉, 스팬이
`session.id` 또는 `session_id`에 지정한 세션, 또는 브라우저 요청이
`traceparent`에 트레이스 ID를 전달한 세션입니다.

헤드 끝의 **트레이스 다운로드**는 트레이스를 파일로 저장합니다:

| 형식 | 내용 |
|---|---|
| **JSON** | [트레이스 API](/ko/api/web/trace#트레이스-하나-읽기)가 반환하는 스팬입니다. |
| **OTLP JSON** | 수집기 또는 OTLP HTTP 수집 엔드포인트가 다시 받아들이는 OTLP/JSON 내보내기 요청으로, `resourceSpans` → `scopeSpans` → `spans` 구조입니다. 시간은 나노초를 십진수 문자열로 표시합니다. |

네 가지 뷰에서 스팬을 보여 줍니다:

| 뷰 | 표시 내용 |
|---|---|
| **워터폴** | 시간 축의 스팬 트리이며 서비스마다 색상이 다릅니다. 위의 미니맵에서 드래그한 구간으로 축을 확대합니다. 검색은 일치하는 스팬을 차례로 이동하고, 토글로 실패한 스팬만 표시하며, 스팬과 해당 스팬이 호출한 항목에 포커스를 맞출 수 있습니다. |
| **플레임 그래프** | 각 스팬은 해당 스팬을 호출한 스팬 아래의 블록으로 표시됩니다. 더블 클릭하면 축이 해당 스팬으로 확대됩니다. |
| **스팬 목록** | 서비스 및 작업별로 그룹화된 스팬이며, 개수, 오류, 기간, 자체 시간, 트레이스 자체 시간에서 차지하는 비중을 표시합니다. |
| **서비스 맵** | 이 트레이스의 서비스와 서비스 간 호출을 표시하며, 호출 수, 기간, 실패를 보여 줍니다. |

워터폴 및 플레임 그래프 도구 모음의 **임계 경로**는 트레이스의
엔드투엔드 시간이 대기한 스팬을 그립니다. 경로는 루트 스팬의 끝에서 시작하여 시간을 거슬러
올라갑니다. 각 시점에서 그때까지 마지막으로 종료된 자식 스팬을 따르며, 해당 자식 스팬을 호출한
스팬까지로 제한하고, 그 자식 스팬이 시작된 시점부터 이어집니다. 그 시점에 아직 실행 중인 자식 스팬은
경로가 따른 자식 스팬과 나란히 실행되었으므로 경로에 포함되지 않습니다. 어떤 자식 스팬도 포함하지 않는 시간은 호출한
스팬에 남습니다. 워터폴에서는 각 막대를 따라 선이
경로에 있는 해당 스팬의 구간을 표시하고, 다른 스팬은 흐려집니다. 범례는 경로 길이와
각 서비스가 차지하는 비중을 보여 줍니다. 이 스위치는 트레이스마다 켜진 상태로 유지됩니다.

선택한 스팬의 상세 정보는 뷰 옆에 표시되며, 너비를 드래그할 수 있습니다. 상세 정보에는
**속성**, **리소스**, **이벤트**, **링크**, **로그**, **메트릭**, **프로필** 탭이 있습니다.
**링크**는 해당 스팬으로 연결되는 다른 트레이스의 스팬도 나열합니다. **로그**는 트레이스 ID를
포함하는 로그 라인을 스팬 또는 전체 트레이스에 대해 표시합니다. **메트릭**은 스팬 전후 몇 분 동안 해당 스팬의 서비스 및 작업에 대한 요청, 오류, p95
기간을 표시합니다.

**프로필**은 스팬이 실행되는 동안 프로파일러가 샘플링한 내용을 표시합니다. 샘플은 다음 경우에 스팬에 연결됩니다.
프로파일러가 [OTLP 프로필](/ko/profiles)처럼 트레이스 컨텍스트와 함께 기록할 때입니다. 연결된
샘플이 있으면 탭은 자체 값 기준으로 한 프로필 유형에서 가장 많은 시간을 차지한 함수를 나열하며,
**플레임 그래프 열기**는 해당 샘플을 그리고, **프로파일에서 열기**는 프로필 페이지에서 해당 샘플을 엽니다.
워터폴 행의 플레임 표시는 해당 스팬에 연결된 샘플이 있음을 보여 줍니다. 연결된 샘플이 없으면,
**스팬 전후의 프로파일**은 스팬 전후 몇 분의 프로필을 엽니다.

각 트레이스에는 자체 페이지도 있으며, 트레이스 링크로 열립니다. 브라우저 RUM 세션에
세션 식별자가 있으면 **세션 트레이스**를 열어 관련 백엔드 요청을 검토합니다.

## 두 트레이스 비교

**트레이스** 테이블 위의 **비교할 트레이스 2개 선택**을 클릭한 다음 두 행을 클릭합니다. 먼저 선택한
트레이스가 **A**이고 두 번째가 **B**입니다. **비교**를 클릭하면 A 페이지에서 비교가 열립니다.
트레이스 헤드에서 **다른 트레이스와 비교**는 다른 트레이스의 ID를 입력받습니다. 트레이스
ID만으로 연 트레이스는 OTLP를 통해 수집되었고 지난 31일 이내에 시작된 경우에 찾을 수 있습니다.

비교에서는 두 트레이스, 각 트레이스의 기간, B가 A보다 얼마나 더 오래 또는 더 짧게 걸렸는지를 보여 줍니다.
이어서 세 개의 탭이 표시되며, 각 탭은 가장 큰 변경부터 보여 줍니다:

| 탭 | 표시 내용 |
|---|---|
| **서비스별** | A와 B에서 각 서비스의 스팬 및 자체 시간과 A에서 B로의 변경을 표시합니다. |
| **작업별** | 각 서비스의 각 작업에 대해 동일한 정보를 표시합니다. |
| **한쪽 트레이스에만 있는 호출** | 한 트레이스는 호출했지만 다른 트레이스는 호출하지 않은 호출입니다. 스팬은 위에 있는 스팬의 서비스 및 작업으로 매칭되므로, 두 위치에서 실행한 동일한 쿼리는 두 개의 호출로 계산됩니다. 누락된 호출은 그 아래에서 호출한 스팬을 포함하여 계산합니다. |

자체 시간은 스팬이 자체 작업에 소비한 시간이며, 호출한 스팬을
기다리는 데 소비한 시간이 아닙니다. **A와 B 바꾸기** 및 **비교 종료**는 페이지 헤드에 있으며,
페이지 주소에 두 트레이스가 모두 유지되므로 비교 결과를 공유할 수 있습니다.

## 서비스 그래프 및 카탈로그

**서비스 그래프** 탭은 트레이스 스팬에서 노드와 엣지를 도출합니다. 그래프는 요청률, 오류율,
지연 관계를 별도로 유지 관리되는 토폴로지 없이 표시합니다.

**서비스 카탈로그**는 관측된 서비스와 작업을 그룹화하여 서비스에서
현재 트레이스로 이동할 수 있게 합니다.

## 수집 및 전파

OTLP HTTP 또는 OTLP gRPC로 트레이스를 전송합니다. MoleSignal은 표준 W3C Trace Context 및
OpenTelemetry 시맨틱 속성을 보존합니다. 응답 헤더는 지원되는 애플리케이션 요청에 대해 `X-Request-Id` 및 `X-Trace-Id`를
노출합니다.

스트림의 [실시간 파이프라인](/ko/pipelines#트레이스)은 테일
샘플링 후, 스팬이 기록되기 전에 스팬을 변경하거나 삭제합니다. 트레이스 목록은 스팬 및 오류 수와 함께 기록된
그대로의 스팬을 표시합니다.

## 권한

조직 워크스페이스에는 `traces.read`가 필요합니다. 플랫폼 관리자는
보호된 `_sys` 텔레메트리 범위에 `sys.telemetry.read`를 사용합니다.
