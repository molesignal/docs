**트레이스**를 열어 전체 트레이스, 개별 스팬, RED 상세 분석,
서비스 그래프 사이를 전환합니다.

## 트레이스와 스팬 찾아보기

**트레이스** 탭에는 요청당 한 행이 표시됩니다. 종료 상태(루트 스팬의 HTTP 상태 또는
**정상** 및 **오류**), 시작 시각, 서비스와 작업, 페이지에서 가장 긴 트레이스 대비 지속 시간,
스팬 수, 오류 수, 트레이스 ID를 확인할 수 있습니다. **시작 시각**,
**지속 시간**, **스팬**, **오류** 중 하나를 클릭하면 해당 열을 기준으로 정렬합니다. 표 위의 히스토그램은 쿼리와 일치하는 모든 트레이스의 수를 집계하고, 옆의 차트는
해당 트레이스의 p50, p95, p99 지속 시간을 표시합니다.

**스팬** 탭에는 쿼리와 일치하는 스팬당 한 행이 표시되며, 각 스팬의 종류와 지속 시간이 나옵니다.
이 탭에서 스팬 필드에 설정한 필터는 스팬 자체에 적용됩니다.

쿼리 편집기에는 **코드**와 **빌더** 모드가 있습니다. 제목 옆의 두 아이콘(`</>`는
코드, 블록은 빌더)으로 모드를 전환합니다. **코드**에서는
`status_code = 'ERROR'` 또는 `duration_ns > 500000000`(500 ms 초과)과 같은 필드 쿼리나 트레이스
스트림을 대상으로 하는 SQL을 입력합니다. **빌더**는 필드 쿼리의 각 대안 조건을 필터 한 행으로 표시합니다. 쿼리는 나란히
배치할 수 있는 탭에서 실행합니다. 필드 목록에서 필드 분석을 열고 **공유**로 쿼리 링크를 복사할 수 있습니다. 동작은
[로그](/ko/logs#쿼리-탭)와 같습니다. 주소 표시줄에도 적용한 쿼리가 포함되므로 주소를 복사해
쿼리를 공유할 수 있습니다([쿼리 공유](/ko/logs#쿼리-공유)).

스팬 필드의 비교 조건은 일치하는 스팬이 하나라도 있는 트레이스를 남깁니다. `!=`는
해당 값을 가진 스팬이 하나도 없는 트레이스를 남깁니다. `trace_id`, `duration_ns`, `span_count`, `error_count`는
트레이스 자체에서 비교합니다. `in`은 여러 값 중 하나와 일치하는지 확인합니다.
`service.name in ('checkout', 'payments')`.

`AND`와 `OR`로 비교 조건을 연결합니다. `AND`를 먼저 평가하며, 괄호로 조건을 묶을 수 있습니다. 동작은
[로그](/ko/logs#쿼리-작성)와 같습니다. `OR` 안에서도 각 비교 조건의 의미는 그대로 유지됩니다.
`service.name = 'checkout' OR span_count > 50`은 `checkout` 스팬이 있는 트레이스와
스팬이 50개를 초과하는 트레이스를 모두 남깁니다. `timeout`처럼 필드를 지정하지 않은 텍스트는 트레이스
ID, 스팬 ID, 서비스, 작업, 상태에서 검색합니다. **스팬** 탭과 RED 상세 분석은 같은
쿼리를 각 스팬에 적용합니다. `a` 또는 `b`와 일치하는 스팬은 `a OR b`와 일치합니다.

필드 목록은 결과 옆에 표시됩니다. **공통 필드**인 `service.name`, `name`,
`status_code`, HTTP 상태, `duration_ns`가 먼저 나옵니다. 필드를 열면 불러온 트레이스에
포함된 값을 확인할 수 있습니다. **이 값만 포함**은 선택한 값을 쿼리에 추가합니다. 대안 조건이 있는 쿼리는 먼저 괄호로 묶어
선택한 값으로 쿼리 전체의 범위를 좁힙니다. 같은 필드에서 값을 하나 더 선택하면
기존 값과 함께 `in` 목록에 들어가므로 여러 값을 선택할 수 있습니다. **이 값 제외**는 해당
값을 제외합니다.

**트레이스** 표 위의 **열**에서 열을 표시하거나 숨기고 순서를 바꿀 수 있습니다. 각 트레이스의
루트 스팬 필드를 열로 추가할 수도 있습니다. 필드 목록에서 해당 필드의 눈 아이콘을 클릭해도 같은 방식으로 열을 추가합니다.
열 배치는 사용자별, 스트림별로 저장됩니다. **기본값으로 재설정**을 클릭하면 표의
기본 열 구성을 복원합니다.

## 트레이스 살펴보기

행을 클릭하면 목록 위의 드로어에서 트레이스가 열립니다. 드로어의 왼쪽 가장자리를 끌어
너비를 조절합니다. 다음 트레이스를 열 때도 이 너비가 유지됩니다. **J**와 **K**로 목록의 다음 트레이스와 이전 트레이스로
이동합니다. 드로어에서 트레이스의 전용 페이지도 열 수 있습니다.

트레이스 헤더는 고정되어 있습니다. 루트 서비스와 작업, HTTP 상태, 오류
수, 지속 시간, 시작 시각, 스팬 및 서비스 수, 깊이, 트레이스 ID를 표시합니다.
**관련 로그**와 **서비스 메트릭**을 클릭하면 트레이스 전후의 해당 신호가 열립니다. **프로필**을 클릭하면
트레이스 ID를 기록한 프로필이 열립니다. 해당 프로필이 없으면 트레이스 전후 몇 분 동안의 프로필이
열립니다. **사용자 세션**을 클릭하면 트레이스가 처리한 [RUM](/ko/rum) 세션이 열립니다. 스팬이
`session.id` 또는 `session_id`에 지정한 세션을 엽니다. 두 필드에 세션이 없으면 브라우저 요청의
`traceparent`에 트레이스 ID를 담은 세션을 엽니다.

헤더 끝의 **트레이스 다운로드**를 클릭하면 트레이스를 파일로 저장합니다.

| 형식 | 내용 |
|---|---|
| **JSON** | [트레이스 API](/ko/api/web/trace#단일-트레이스-조회)가 반환하는 형식 그대로의 스팬입니다. |
| **OTLP JSON** | 수집기 또는 OTLP HTTP 수신 엔드포인트에서 다시 수집할 수 있는 `resourceSpans` → `scopeSpans` → `spans` 구조의 OTLP/JSON 내보내기 요청입니다. 시간 값은 나노초 단위의 10진수 문자열입니다. |

다음 네 가지 보기에서 스팬을 확인할 수 있습니다.

| 보기 | 표시 내용 |
|---|---|
| **워터폴** | 시간 축에 스팬 트리를 표시하며, 서비스마다 다른 색을 사용합니다. 위쪽 미니맵에서 구간을 드래그하면 해당 구간을 확대합니다. 검색으로 일치하는 스팬을 차례로 탐색하고, 토글로 실패한 스팬만 표시할 수 있습니다. 특정 스팬과 해당 스팬이 호출한 스팬에 초점을 맞출 수도 있습니다. |
| **플레임 그래프** | 각 스팬을 호출한 스팬 아래에 블록으로 표시합니다. 스팬을 두 번 클릭하면 해당 스팬의 시간 구간을 확대합니다. |
| **스팬 목록** | 스팬을 서비스와 작업별로 묶어 개수, 오류, 지속 시간, 자체 실행 시간, 트레이스 자체 실행 시간에서 차지하는 비율을 표시합니다. |
| **서비스 맵** | 트레이스에 포함된 서비스와 서비스 간 호출을 표시합니다. 호출 수, 지속 시간, 실패 건수도 함께 표시합니다. |

워터폴과 플레임 그래프의 도구 모음에서 **임계 경로**를 켜면
트레이스의 전체 처리 시간을 결정한 스팬을 표시합니다. 경로는 루트 스팬의 끝에서 시작해 시간을
거슬러 올라갑니다. 각 시점에 이미 끝난 자식 스팬 중 가장 늦게 끝난 스팬을 따라가고, 호출한
스팬의 시간 범위에 맞춰 구간을 자른 뒤 해당 자식 스팬이 시작한 시점부터 계속 거슬러 올라갑니다. 그 시점에 아직 실행 중인 자식 스팬은
경로가 따라간 스팬과 병렬로 실행되었으므로 경로에 포함하지 않습니다. 자식 스팬이 차지하지 않는 시간은 호출한
스팬에 남습니다. 워터폴에서는 각 막대를 따라 그은 선이
해당 스팬에서 경로에 포함된 구간을 표시하며, 다른 스팬은 흐리게 표시합니다. 범례에는 경로의 길이와
각 서비스가 차지하는 비율이 표시됩니다. 다른 트레이스로 이동해도 켜짐 상태를 유지합니다.

선택한 스팬의 세부 정보는 보기 옆에 표시됩니다. 가장자리를 끌어 너비를 조절할 수 있습니다.
**속성**, **리소스**, **이벤트**, **링크**, **로그**, **메트릭**, **프로필** 탭이 있습니다.
**링크**에는 선택한 스팬에 링크를 건 다른 트레이스의 스팬도 표시됩니다. **로그**에는
선택한 스팬 또는 전체 트레이스에 대해 트레이스 ID가 포함된 로그 줄을 표시합니다. **메트릭**에는
스팬 전후 몇 분 동안 해당 서비스 및 작업의 요청 수, 오류 수, p95 지속 시간을 차트로 표시합니다.

**프로필**에는 스팬이 실행되는 동안 프로파일러가 수집한 샘플이 표시됩니다.
[OTLP 프로필](/ko/profiles)처럼 프로파일러가 샘플을 트레이스 컨텍스트와 함께 기록하면 샘플을 스팬에 연결합니다.
연결된 샘플이 있으면 탭에 해당 프로필 유형에서 자체 값이 가장 큰 함수가 표시됩니다.
**플레임 그래프 열기**를 클릭하면 해당 샘플을 그래프로 표시하고, **프로파일에서 열기**를 클릭하면 프로필 페이지에서 해당 샘플을 엽니다.
워터폴 행의 불꽃 아이콘은 스팬에 연결된 샘플이 있음을 나타냅니다. 연결된 샘플이 없으면
**스팬 전후의 프로파일**을 클릭해 스팬 전후 몇 분 동안의 프로필을 엽니다.

각 트레이스에는 전용 페이지가 있으며, 트레이스 링크를 클릭하면 해당 페이지가 열립니다. 브라우저 RUM 세션에
세션 식별자가 있으면 **세션 트레이스**를 열어 관련 백엔드 요청을 확인합니다.

## 트레이스 2개 비교

**트레이스** 테이블 위의 **비교할 트레이스 2개 선택**을 클릭한 다음 두 행을 클릭합니다. 첫 번째로 선택한 트레이스는
**A**, 두 번째는 **B**입니다. **비교**를 클릭하면 A의 페이지에서 비교 결과를 확인할 수 있습니다.
트레이스 페이지 상단의 **다른 트레이스와 비교**에는 비교할 트레이스의 ID를 입력합니다. ID만으로 트레이스를 열려면
해당 트레이스가 OTLP를 통해 수집되었고 최근 31일 이내에 시작되었어야 합니다.

비교 화면에는 두 트레이스의 소요 시간과 B가 A보다 얼마나 오래 또는 짧게 걸렸는지 표시됩니다.
그 아래에는 세 개의 탭이 있으며, 각 탭은 변화가 가장 큰 항목부터 표시합니다.

| 탭 | 표시 내용 |
|---|---|
| **서비스별** | A와 B의 각 서비스에 속한 스팬과 서비스별 자체 실행 시간, A에서 B로의 변화량을 표시합니다. |
| **작업별** | 각 서비스의 개별 작업에 대해 동일한 정보를 표시합니다. |
| **한쪽 트레이스에만 있는 호출** | 한쪽 트레이스에서만 발생한 호출을 표시합니다. 상위 스팬의 서비스와 작업을 기준으로 스팬을 서로 대응시키므로, 같은 쿼리라도 서로 다른 두 위치에서 실행하면 별개의 호출로 집계합니다. 한쪽에만 있는 호출은 그 호출이 실행한 하위 스팬의 수를 집계합니다. |

자체 실행 시간은 스팬이 직접 작업을 수행한 시간으로, 호출한 스팬이 완료되기를 기다린 시간은
제외합니다. 페이지 상단에 **A와 B 바꾸기**와 **비교 종료**가 있으며, 페이지
주소에 두 트레이스 정보가 모두 포함되므로 비교 결과를 공유할 수 있습니다.

## 서비스 그래프 및 카탈로그

**서비스 그래프** 탭은 트레이스 스팬을 바탕으로 노드와 연결선을 구성합니다. 토폴로지를 별도로 관리할 필요 없이 그래프에서 서비스 간 요청률, 오류율,
지연 시간 관계를 확인할 수 있습니다.

**서비스 카탈로그**는 관측된 서비스와 작업을 그룹화하여 서비스에서
최근 트레이스로 이동할 수 있도록 합니다.

## 수집 및 전파

OTLP HTTP 또는 OTLP gRPC로 트레이스를 전송합니다. MoleSignal은 표준 W3C Trace Context와
OpenTelemetry 시맨틱 속성을 보존합니다. 지원되는 애플리케이션 요청의 응답 헤더에는 `X-Request-Id`와 `X-Trace-Id`가
포함됩니다.

스트림에 설정한 [실시간 파이프라인](/ko/pipelines#트레이스)은 테일
샘플링이 끝난 뒤 저장하기 전에 스팬을 변경하거나 삭제합니다. 트레이스 목록에는 저장된 스팬이 그대로 표시되며,
스팬 수와 오류 수도 함께 표시됩니다.
