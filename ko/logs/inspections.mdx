로그 점검에서는 Mole Agent가 특정 기간의 로그를 읽고 보고서를 작성합니다. 보고서에는 문제가 있는지,
어떤 문제인지, 어떤 로그에서 확인할 수 있는지가 나옵니다. 점검은 로그를 읽기만 합니다. 데이터나
구성을 변경하지 않습니다.

| 유형 | 사용 방법 |
|---|---|
| **온디맨드** | **로그**의 **AI 분석** 화면에서 현재 쿼리와 일치하는 로그를 한 번 점검합니다. 보고서는 생성되는 대로 페이지에 표시됩니다. 점검은 Mole Agent 채팅으로 진행되므로 **Mole Agent**에서 계속할 수 있습니다. 보고서는 예약 점검 보고서와 함께 보관하지 않습니다. |
| **예정됨** | 스트림, 쿼리, 중점 분석 항목을 저장합니다. MoleSignal은 일정에 따라 점검하고 모든 보고서를 보관하며, 보고서에서 문제를 확인하면 알림을 보냅니다. |

## 시작하기 전에

- **Mole Agent → 설정 → 모델 및 추론**에서 AI 모델을 하나 이상 활성화합니다.
  [Mole Agent](/ko/agent#모델-공급자-설정)를 참조합니다. 활성화된 모델이 없으면 저장된 점검이
  목록에는 남지만 실행할 수 없습니다.
- 권한을 확인합니다.

| 작업 | 권한 |
|---|---|
| 온디맨드 점검 실행 | `agent.use` 및 `logs.read` |
| 예약 점검 및 보고서 읽기 | `inspections.read` 및 `logs.read` |
| 생성, 편집, 켜기 또는 끄기, 삭제 | `inspections.manage`(기본적으로 소유자, 관리자, 편집자 역할에 부여) |
| 지금 실행 | `inspections.run`(위와 동일한 역할에 부여) |
| 양식에서 알림 채널 선택 | `notify.connectors.read`(알림 커넥터 목록 조회) |

Mole Agent는 채팅에서 `list_log_inspections`,
`list_log_inspection_runs`, `get_log_inspection_run`을 사용해 동일한 권한으로 점검과 보고서를 읽습니다.
`run_log_inspection`은 점검을 즉시 실행합니다. `inspections.run` 권한이 필요하며 기본적으로
채팅에서 실행을 확인해야 합니다. [도구 카탈로그 및 실행](/ko/tools)을 참조합니다.

## 온디맨드 점검 실행

1. **로그**를 열고 스트림과 시간 범위를 선택한 뒤 쿼리를 실행합니다. 스트림의 모든 로그를 점검하려면
   쿼리를 비워 둡니다.
2. **AI 분석** 화면을 엽니다.
3. **AI 모델**을 선택합니다. 필요한 경우 관찰할 서비스나
   정상으로 간주할 결과를 **중점 분석 항목**에 입력합니다.
4. **분석 시작**을 선택합니다.

점검은 로그 쿼리 결과를 선택한 모델에 전송합니다. 보고서에 관해 추가로 질문하려면 **Mole
Agent에서 계속**을 선택합니다.

## 예약 점검 저장

**로그 → AI 분석**을 연 다음 다음 두 항목 중 하나를 선택합니다.

- **예약 점검으로 저장**을 선택하면 현재 스트림, 쿼리, 요구사항 및
  모델이 입력된 양식이 열립니다. 현재 쿼리와 일치하는 로그가 없어도 점검을 저장할 수 있습니다.
- **예약 점검**을 선택하면 목록이 열립니다. 목록에서 **새 점검**을 선택하면 빈 양식이 열립니다.

| 필드 | 의미 |
|---|---|
| **이름** | 조직 내에서 고유한 이름입니다. 최대 120자입니다. |
| **스트림** | [`_audit`](/ko/settings/data-security#감사-스트림)를 제외한 로그 스트림 하나를 선택합니다. 점검은 이 스트림만 읽습니다. |
| **쿼리** | 선택 사항입니다. 쿼리와 일치하는 로그만 점검합니다. 구문은 **로그**와 동일합니다. |
| **중점 분석 항목** | 선택 사항이며 최대 2,000자입니다. 중요하게 볼 항목과 정상으로 간주할 조건을 입력합니다. |
| **일정** | **일정 간격**, **매일**, **매주** 중에서 선택합니다. 매일 또는 매주 실행할 경우 실행 시각을 지정합니다. 최소 간격은 인스턴스 설정에서 정하며 기본값은 1시간입니다. |
| **검사 대상 기간** | 실행할 때마다 시작 시점부터 얼마나 이전까지 점검할지 지정합니다. 양식에서 15분부터 7일까지 설정할 수 있습니다. 기본값은 일정에 따라 정해집니다. |
| **AI 모델** | 조직에서 활성화한 모델 하나를 선택합니다. |
| **알림 조건** | **이상 시 알림**(기본값), **주의 이상 시 알림**, **매번 알림** 중에서 선택합니다. |
| **알림 채널** | 선택 사항이며 최대 10개까지 지정할 수 있습니다. 각 채널은 알림 커넥터에 지정된 그룹 또는 주소입니다. Alibaba Cloud SMS 및 음성 서비스는 승인된 템플릿만 전송하므로 선택할 수 없습니다. |
| **저장 후 일정에 따라 실행** | 끄면 점검을 저장하되 **지금 실행**을 선택할 때만 실행합니다. |

매일 또는 매주 실행할 시각에는 점검을 만들 때의 인터페이스 시간대를 적용합니다. 개인 환경설정의
시간대를 사용하며, 설정이 없으면 브라우저 시간대를 사용합니다. 양식에 시간대가 표시되며,
나중에 점검을 편집해도 시간대는 바뀌지 않습니다. 알림과 보고서에는
점검을 만들 때의 인터페이스 언어를 사용합니다.

조직당 기본적으로 예약 점검을 최대 20개까지 저장할 수 있습니다.

## 실행 방식

| 항목 | 동작 |
|---|---|
| 실행 계정 | 점검을 마지막으로 저장한 사용자의 계정으로 로그를 읽습니다. 실행할 때마다 MoleSignal은 해당 사용자가 여전히 로그인할 수 있는지, 조직에 속해 있는지, `agent.use` 및 `logs.read` 권한이 있는지 확인합니다. 조건을 충족하지 않으면 해당 계정을 더 이상 사용할 수 없다는 사유와 함께 실행이 실패합니다. 필요한 권한이 있는 다른 사용자가 점검을 다시 저장하면 해당 사용자의 계정으로 실행합니다. API 토큰으로는 예약 점검을 저장할 수 없습니다. |
| 도구 | 모델은 읽기 전용 도구 4개(`query_logs`, `get_stream_schema`, `search_field_values`, `analyze_log_patterns`)를 점검 대상 스트림에서만 사용합니다. `analyze_log_patterns`는 로그를 패턴별로 묶고 기준 기간의 패턴과 비교합니다. 백그라운드 실행 중에는 승인할 수 없으므로 조직의 도구 정책에서 비활성화하거나 승인을 요구하는 도구는 사용하지 않습니다. |
| 시간 범위 | 점검은 실행 시작 직전의 기간을 대상으로 합니다. 노드가 중지되어 놓친 실행은 소급하지 않습니다. 노드가 복구되면 실행 시점이 지난 점검을 한 번 실행하고 이후 일정을 이어갑니다. |
| 제한 | 기본 실행 시간은 최대 5분입니다. 이 시간을 넘으면 시간 초과로 처리합니다. 도구 결과가 64 KiB를 초과하면 모델에 전달하지 않고 대신 쿼리 범위를 좁히도록 요청합니다. 실행에 실패하면 다음 예약 실행 전까지 재시도하지 않습니다. |
| 동시 실행 | 같은 점검은 한 번에 하나의 실행만 진행합니다. 노드 하나에서 기본적으로 점검을 최대 2개까지 동시에 실행합니다. |
| **지금 실행** | 실행을 대기열에 추가하고 15초 이내에 점검에 지정된 계정으로 시작합니다. 실행 기록에는 실행을 시작한 사용자를 표시합니다. 꺼진 점검도 이 방식으로 실행할 수 있습니다. |

## 보고서 및 판정

목록에서 점검을 선택하면 보고서가 열립니다. 이전 실행은 왼쪽에 표시됩니다. 실행을 선택하면
보고서, 검사 대상 기간, 소요 시간, 호출한 도구, 사용한 토큰, 전송한
알림이 표시됩니다. **이 기간의 로그 열기**를 선택하면 같은 스트림, 쿼리,
기간이 적용된 **로그**가 열립니다.

예약 점검 보고서에는 판정이 포함됩니다.

| 판정 | 의미 |
|---|---|
| **정상** | 조치가 필요한 항목이 없습니다. |
| **확인 필요** | 확인할 항목이 있지만 장애는 없습니다. |
| **이상** | 문제가 있어 조치가 필요합니다. |
| **판정 없음** | 모델 응답에 식별할 수 있는 판정이 없습니다. 보고서는 보관하고, 알림을 보낼지 판단할 때는 이상으로 처리합니다. |

완료하지 못한 실행에는 보고서가 없습니다. 실행 기록에 상태와 사유가 표시됩니다.

| 상태 | 사유 |
|---|---|
| **시간 초과** | 실행이 제한 시간을 초과했습니다. |
| **실패** | 실행 계정을 더 이상 사용할 수 없거나, 선택한 AI 모델이 없거나 비활성화되었거나 키가 없습니다. 모델 호출 실패, 조직의 당일 Mole Agent 토큰 예산 소진, 실행 중 노드 중지, 실행을 가져간 노드 없음, 내부 오류도 실패 사유에 해당합니다. |

보고서는 기본적으로 30일간 보관합니다. 보관 기간이 지난 보고서는 매시간 삭제합니다. 점검을 삭제하면
해당 점검의 모든 보고서도 삭제합니다.

## 알림

- 보고서의 판정 결과가 **알림 조건**을 충족하면 각 채널로 알림을 하나씩 보냅니다.
  제목에는 판정 결과와 검사 이름을 표시하고, 본문에는 스트림,
  기간, 판정 결과, 보고서 요약, 보고서 링크를 포함합니다. 링크를 사용하려면
  `http.external_url`을 설정해야 합니다.
- 실행에 실패하면 직전 실행이 실패하지 않았을 때만 알림을 보냅니다. 연속으로 실패하면
  **알림 조건**과 관계없이 첫 실패에만 알림을 보냅니다.
- 채널이 없으면 알림을 보내지 않지만 보고서는 계속 보관합니다.
- **설정 → 알림 → 전송 로그**에서 모든 알림의 전송 단계를
  **직접**으로 표시합니다. 직접 전송에는 알림 정책을 적용하지 않으며, 전송 로그에서
  다시 시도할 수 없습니다.
- 예약된 검사에서 사용하는 알림 커넥터는 삭제할 수 없습니다.

## 인스턴스 설정

| 설정 | 기본값 | 용도 |
|---|---|---|
| `[log_inspection].min_interval_secs` | `3600` | 동일한 검사를 연속으로 실행할 때의 최소 간격입니다. 60 미만의 값은 60으로 처리합니다. |
| `[log_inspection].max_per_org` | `20` | 조직당 보관할 수 있는 예약 검사 수입니다. `0`으로 설정하면 예약 검사를 허용하지 않습니다. |
| `[log_inspection].concurrent_runs` | `2` | 노드 하나에서 동시에 실행하는 검사 수입니다. |
| `[log_inspection].run_timeout_secs` | `300` | 모든 모델 호출과 쿼리를 포함한 단일 실행의 제한 시간입니다. 값을 30–480 범위로 제한합니다. |
| `[log_inspection].report_retention_days` | `30` | 보고서 보존 기간입니다. |

`alert` 역할을 가진 노드는 예약 검사를 실행하며, 실행 시간이 되었거나
대기열에 있는 작업이 있는지 15초마다 확인합니다. `alert` 노드가 여러 개 있어도 각 작업은 노드 하나만 가져갑니다.
[역할 기반 배포](/ko/deployment/role-based)를 참조합니다.

두 가지 메트릭으로 검사 실행을 추적합니다.

| 메트릭 | 의미 |
|---|---|
| `log_inspection_runs_total{outcome}` | 결과별로 집계한 종료된 실행 수입니다. 결과는 `succeeded`, `failed` 또는 `timed_out`입니다. |
| `log_inspection_run_duration_seconds` | 한 번의 실행에 걸린 시간입니다. |

## API

엔드포인트는 `/api/v1/logs/inspections` 아래에 있습니다.

| 메서드 및 경로 | 용도 |
|---|---|
| `GET /logs/inspections` | 조직의 예약 검사 목록을 조회합니다. |
| `POST /logs/inspections` | 검사를 생성합니다. |
| `GET /logs/inspections/limits` | 인스턴스에서 설정한 제한을 조회합니다. |
| `GET`, `PUT`, `DELETE /logs/inspections/{id}` | 검사와 해당 보고서를 조회, 교체 또는 삭제합니다. |
| `POST /logs/inspections/{id}/enabled` | 검사를 활성화하거나 비활성화합니다. |
| `POST /logs/inspections/{id}/run` | 검사를 즉시 한 번 실행합니다. |
| `GET /logs/inspections/{id}/runs` | 보고서 본문을 제외한 실행 기록을 최신순으로 조회합니다. `limit`의 기본값은 50이고 최댓값은 200입니다. `before`로 더 오래된 실행 기록을 조회합니다. |
| `GET /logs/inspections/{id}/runs/{run_id}` | 실행 한 건을 해당 보고서와 함께 조회합니다. |
