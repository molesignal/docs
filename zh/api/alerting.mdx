三类规则、多级升级、PagerDuty 风格的 incident。指南见 [告警](/zh/alerting)。

## 规则

```http
GET  /api/v1/alerts/rules        # 列出
POST /api/v1/alerts/rules        # 创建
PUT  /api/v1/alerts/rules/{id}   # 更新
DELETE /api/v1/alerts/rules/{id} # 删除
```

规则的 `kind` 为 `scheduled`、`realtime` 或 `anomaly`。

<Note>
  修改规则阈值会重置其连续触发计数器。
</Note>

<RequestExample>
```json POST body
{
  "name": "High error rate",
  "kind": "scheduled",
  "stream": "app",
  "statement": "SELECT count(*) AS c FROM app WHERE level = 'error'",
  "condition": { "op": ">", "value": 100 },
  "interval_secs": 60,
  "escalation_id": "esc_2abc..."
}
```
</RequestExample>

## 升级策略

```http
POST /api/v1/alerts/escalations
```

多步策略：每步有 targets、`ack_timeout` 与重复行为。支持轮值排班（时区感知）与覆盖（override）。

## 通知渠道

```http
POST /api/v1/alerts/channels
```

渠道通过 Slack、webhook、email 发送，支持模板变量。

## Incident

```http
GET  /api/v1/alerts/incidents              # 列出
POST /api/v1/alerts/incidents/{id}/ack     # 确认
POST /api/v1/alerts/incidents/{id}/resolve # 解决
```

incident 携带 `step`、`acknowledged_at`、`resolved_at`，对应 PagerDuty 的 incident 生命周期。
