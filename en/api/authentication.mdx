title: "Authentication"
description: "Log in for a JWT, and manage long-lived API tokens and the JWT signing secret."
---

All endpoints except `/api/v1/healthz`, `/api/v1/auth/login`, and `/metrics` require a bearer token.
See [Introduction](/en/api-reference#authentication) for the header format.

## Log in

```http
POST /api/v1/auth/login
```

Exchange email + password for a JWT. This route is unauthenticated.

**Body**

| Field | Type | Required |
|---|---|---|
| `email` | string | ✅ |
| `password` | string | ✅ |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/auth/login \
  -H 'content-type: application/json' \
  -d '{"email":"admin@example.com","password":"admin"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "token": "eyJhbGciOi...",
  "user_id": "u_2abc...",
  "org_id": "o_2def...",
  "role": "owner"
}
```
</ResponseExample>

## Issue an API token

```http
POST /api/v1/auth/tokens
```

Create a long-lived token shaped `ms_<prefix>_<secret>`. The plaintext secret is returned **once** —
store it now. Each token carries a role, an expiry, and a last-used timestamp.

<ResponseExample>
```json 200
{
  "id": "t_2ghi...",
  "token": "ms_a1b2c3_d4e5f6g7h8i9...",
  "role": "data_plane_admin",
  "expires_at": 1735689600000000
}
```
</ResponseExample>

## List API tokens

```http
GET /api/v1/auth/tokens
```

Returns token metadata (never the secret).

## Revoke an API token

```http
DELETE /api/v1/auth/tokens/{id}
```

## Rotate the JWT signing secret

```http
POST /api/v1/auth/jwt/rotate
```

Owner-only. Retires the current secret and inserts a new one, with a **24-hour grace** window so
in-flight tokens keep validating. List signing-secret metadata (never the bytes) with
`GET /api/v1/auth/jwt/secrets`.

<Note>
  SSO (OIDC) login — `GET /api/v1/auth/sso/login` and `/api/v1/auth/sso/callback` — is gated behind a
  paid license and returns `403` when not licensed.
</Note>
