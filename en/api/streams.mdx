---
title: "Streams"
description: "List, create, and manage streams, their schema, and retention."
---

A stream is the finest-grained unit of data partitioning. See [Core concepts → Streams](/en/concepts#streams).

## List streams

```http
GET /api/v1/streams
```

<ResponseExample>
```json 200
[
  { "id": "s_app", "name": "app", "stream_type": "logs", "retention_days": 30 },
  { "id": "s_cpu", "name": "host_cpu", "stream_type": "metrics", "retention_days": 90 }
]
```
</ResponseExample>

## Create a stream

```http
POST /api/v1/streams
```

Streams are also created implicitly on first ingest; use this to pre-declare one.

<Note>
  `stream_type: enrichment` cannot be used as a pipeline target.
</Note>

## Get a stream

```http
GET /api/v1/streams/{id}
```

## Delete a stream

```http
DELETE /api/v1/streams/{id}
```

## Edit schema

```http
PUT /api/v1/streams/{id}/schema
```

Adjust field types or add fields. Schema also evolves automatically as new fields arrive.

## Edit retention

```http
PUT /api/v1/streams/{id}/retention
```

Set how long data in the stream is kept before the compactor reclaims it.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/streams/s_app/retention \
  -H "authorization: Bearer $MS_JWT" \
  -H 'content-type: application/json' \
  -d '{"retention_days": 30}'
```
</RequestExample>
