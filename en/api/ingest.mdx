MoleSignal accepts data over 10 protocols. Every ingest endpoint is authenticated. Timestamps are
microseconds since the Unix epoch (`_timestamp`). See [Ingesting data](/en/ingestion) for the
conceptual guide.

## Native JSON ingest

```http
POST /api/v1/ingest/{type}/{stream}
```

`{type}` is `logs`, `metrics`, or `traces`. Post a single record object or an array of them. The
stream is created on first write and its schema evolves as fields appear.

**Path parameters**

| Param | Type | Notes |
|---|---|---|
| `type` | string | `logs` / `metrics` / `traces` |
| `stream` | string | Stream name, e.g. `app` |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/ingest/logs/app \
  -H "authorization: Bearer $MS_JWT" \
  -H 'content-type: application/json' \
  -d '[{"_timestamp":1700000000000000,"level":"error","msg":"db pool exhausted","trace_id":"abc123"}]'
```
</RequestExample>

<ResponseExample>
```json 200
{ "accepted": 1, "rejected": 0, "errors": [] }
```
</ResponseExample>

A `413` means the storage quota is exceeded; a `429` means you hit the ingest rate limit.

## Drop-in protocol endpoints

These accept their native wire formats, so existing agents work unchanged.

| Endpoint | Drop-in for | Success |
|---|---|---|
| `POST /api/v1/prometheus/api/v1/write` | Prometheus / VictoriaMetrics remote_write (snappy + protobuf) | `204` |
| `POST /api/v1/_bulk` | Elasticsearch `_bulk` (NDJSON) | `200` items[] |
| `POST /api/v1/loki/api/v1/push` | Loki push (snappy-protobuf or JSON) | `204` |
| `POST /api/v1/_kinesis_firehose` | AWS Kinesis Firehose | `200` ack |
| `POST /api/v1/_cloudflare` | Cloudflare Logpush (NDJSON) | `204` |
| `POST /api/v1/_heroku` | Heroku log drain (text) | `204` |

<Note>
  `/api/v1/_cloudflare` and `/api/v1/_heroku` authenticate with an `X-Connector-Token` header instead
  of a bearer token.
</Note>

## Pipeline functions

Reusable transforms applied on the ingest hot path.

```http
POST /api/v1/functions          # Create a function (VRL is compiled on create)
POST /api/v1/pipelines          # Create a pipeline (unique on stream + enabled)
GET  /api/v1/scheduled_pipelines
POST /api/v1/scheduled_pipelines # cron: `every:Ns/m/h` (DataPlaneAdmin)
```

See [Ingesting data → Pipeline functions](/en/ingestion#pipeline-functions) for VRL/JS details.
