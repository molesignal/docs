These endpoints power the web shell's cross-signal workflows. See
[Cross-signal correlation](/en/correlation) for the guide.

## Cross-signal correlation

```http
GET /api/v1/web/correlation/{from_kind}/{to_kind}
```

Server-side prefill of filters and time range for `metric ↔ trace ↔ log ↔ host` jumps.

**Parameters**

| Param | In | Required | Notes |
|---|---|---|---|
| `from_kind` | path | ✅ | `trace` / `metric` / `log` / `host` |
| `to_kind` | path | ✅ | `trace` / `metric` / `log` / `host` |
| `ctx` | query | ✅ | base64-url JSON blob of the source signal context |

## Command palette search

```http
GET /api/v1/web/search
```

Cross-entity ⌘K search over streams, dashboards, saved views, alerts, incidents, and services.

| Param | In | Required | Notes |
|---|---|---|---|
| `q` | query | ✅ | Search text |
| `types` | query | — | Comma-separated subset of `stream,dashboard,saved_view,alert,incident,service` |
| `limit` | query | — | Default 20, max 50 |

Returns up to `limit` hits ranked by `pg_trgm` similarity.

## Service topology

```http
GET /api/v1/web/topology          # params: from, to (RFC3339)
GET /api/v1/traces/service_graph  # params: from, to (us), service — edges[] + count
```

Aggregates `service_graph_edges` into nodes and edges within the time window.

## Trace tree

```http
GET /api/v1/web/trace/{trace_id}
```

Full span tree for a `trace_id` (≤ 100k spans, 32 MiB hard cap → `truncated=true`).

## Investigation stack

```http
POST /api/v1/web/investigation/blob        # store; returns blob_id, 7-day retention
GET  /api/v1/web/investigation/blob/{id}   # fetch by blob_id
```
