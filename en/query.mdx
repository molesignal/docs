title: "Querying"
description: "Full SQL and a PromQL subset over one engine, across all three signals."
---

MoleSignal exposes a single query endpoint backed by **DataFusion**. You can run full SQL — including
joins, CTEs, and window functions — or a **PromQL subset** for metrics, all against the same store.

## The query endpoint

```http
POST /api/v1/query
Authorization: Bearer <jwt>
Content-Type: application/json
```

### Request body

| Field | Type | Required | Notes |
|---|---|---|---|
| `org_id` | string | ✅ | Your tenant id (from login). |
| `language` | string | ✅ | `sql` or `promql`. |
| `statement` | string | ✅ | The query text. |
| `time_range` | object | ✅ | `{ "start": <us>, "end": <us> }` — microseconds since epoch. |
| `stream` | object | — | `{ "name": "app", "stream_type": "logs" }`. `stream_type` ∈ `logs`/`metrics`/`traces`/`enrichment`. |
| `limit` | integer | — | Row cap. |

### Response

The response carries `rows`, `columns`, `scanned_rows`, `took_ms`, and `cache_hit`.

<Note>
  Send `Accept: application/x-ndjson` to stream results row-by-row. Streaming bypasses the
  `query_result` cache.
</Note>

## SQL

```bash
curl -X POST http://localhost:5080/api/v1/query \
  -H "authorization: Bearer $MS_JWT" \
  -H 'content-type: application/json' \
  -d "{\"org_id\":\"$MS_ORG\",\"language\":\"sql\",
       \"statement\":\"SELECT level, count(*) FROM app WHERE _timestamp > 0 GROUP BY level\",
       \"time_range\":{\"start\":0,\"end\":2000000000000000},
       \"stream\":{\"name\":\"app\",\"stream_type\":\"logs\"}}"
```

Because logs, metrics, and traces live in the same store, you can **join across signals** in one
query — for example, join error logs to their spans on `trace_id`:

```sql
SELECT l.msg, t.duration_ms
FROM app AS l
JOIN spans AS t ON l.trace_id = t.trace_id
WHERE l.level = 'error'
```

## PromQL

Set `language: "promql"` to run PromQL over metric streams. Both instant and range queries are
supported (range steps through `[start, end]` and returns a matrix). The supported surface is now
broad:

- **Range vectors:** `rate`, `irate`, `increase`, `delta`, `idelta`, `deriv`, `predict_linear`,
  `resets`, `changes`, `holt_winters`, and the full `*_over_time` family (`avg`/`min`/`max`/`sum`/
  `count`/`quantile`/`stddev`/`stdvar`/`last`/`present`/`mad`).
- **Aggregations** (with `by` / `without`): `sum`, `avg`, `min`, `max`, `count`, `stddev`, `stdvar`,
  `quantile`, `group`, `count_values`, `topk`, `bottomk`, `limitk`, `limit_ratio`.
- **Histograms:** `histogram_quantile` (classic `le` buckets).
- **Labels & sorting:** `label_replace`, `label_join`, `sort`, `sort_desc`, `sort_by_label`,
  `sort_by_label_desc`.
- **Time:** `time`, `timestamp`, `minute`, `hour`, `day_of_week`, `day_of_month`, `day_of_year`,
  `days_in_month`, `month`, `year`.
- **Type / absence:** `vector`, `scalar`, `absent`, `absent_over_time`.
- **Math / trig:** `abs`, `ceil`, `floor`, `round`, `exp`, `ln`, `log2`, `log10`, `sqrt`, `sgn`,
  `clamp`/`clamp_min`/`clamp_max`, `sin`/`cos`/`tan`/…, `pi`, `deg`, `rad`.
- **Operators:** arithmetic and comparison binops, the set operators `and` / `or` / `unless`,
  vector matching `on` / `ignoring` with `group_left` / `group_right`, and unary negation.
- **Modifiers & structure:** selector `@` and `offset`, and subqueries `inner[range:step]`.
- **Label matching:** `=`, `!=`, `=~`, `!~` (regex via RE2). `__name__` is the metric stream name.

```json
{
  "org_id": "<org>",
  "language": "promql",
  "statement": "histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket[5m])))",
  "time_range": { "start": 0, "end": 2000000000000000 }
}
```

<Note>
  Not implemented (returns `400`): the native-histogram functions
  (`histogram_count`/`histogram_sum`/`histogram_avg`/`histogram_fraction`/`histogram_stddev`/
  `histogram_stdvar`) — N/A for the classic `le`-bucket model — and the binary `default` fill-in.
  Range-mode subqueries fall back to instant evaluation. See the in-repo `docs/promql_subset.md`
  for the authoritative matrix.
</Note>

## Search around an event

To pull the N events immediately before and after a given one (log context view), use
`POST /api/v1/query/search_around` with `event_timestamp_us`, `stream`, `stream_type`, and optional
`before` / `after` counts (default 50 each).

## Caching

Queries flow through a 3-level cache — `file_meta`, `parquet_meta`, and `query_result` — plus a
parquet disk cache enabled by default (`./data/cache/parquet`, 10 GB LRU). The `cache_hit` field in
the response tells you whether the result came from cache.
