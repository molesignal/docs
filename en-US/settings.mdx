Settings navigation is access-aware and shows only sections allowed by the current organization or
system scope.

## Current organization

| Section | Purpose | Main permission |
|---|---|---|
| **General** | Organization name, stable identifiers, registration and sharing policy, and preference defaults. | `org.settings.read` / `org.settings.manage` |

## Notify

| Section | Purpose | Main permission |
|---|---|---|
| **Connectors** | Configure encrypted SMTP, Slack, Lark, and webhook provider credentials. | `alerts.read` / `alerts.manage` |
| **User routing** | Bind provider identities and order personal delivery methods. | `org.members.read` / `org.members.manage` for other users |
| **Policies** | Match events, resolve recipients, select delivery modes, and configure escalation. | `alerts.read` / `alerts.manage` |
| **Templates** | Build and preview reusable notification messages. | `alerts.read` / `alerts.manage` |
| **Fallback routes** | Define ordered team and organization routes by notification category. | `alerts.read` / `alerts.manage` |
| **Delivery log** | Inspect delivery chains, acknowledge events, and retry failed routes. | `alerts.read`, `alerts.acknowledge`, or `alerts.manage` by action |

See [Notification channels and delivery](/en-US/notification-channels) for provider setup and the
end-to-end routing workflow.

## Data plane

- **Client IP recognition** sets how RUM intake identifies client addresses. The default is the
  direct connection address. Behind a proxy or CDN, select a header or a forwarded chain and list
  the trusted proxy CIDRs, because headers are trusted only from those networks.
- **Nodes / remote clusters** manages the local data plane, cluster federation, remote query
  targets, and organization mappings.

## Data security

- **Cipher keys** manages field-encryption keys and rotation. The section is limited to owners.
- **Regex patterns** maintains reusable matching patterns, also used for sensitive-data masking.
- **Field masking** defines global masking rules in first-match order. Streams can override or
  disable inherited masking. Queries compute on raw values and mask only the final result, and
  metrics streams are excluded.
- **Domain management** manages custom domains with managed TLS certificates.
- **Audit** queries the organization audit trail by time, actor, action, and target. Audit access
  requires `audit.read`.

## AI & ML

- **Query management** lists running queries and recent inspector activity, and lets authorized
  users cancel work.

Mole Agent-specific models, prompts, tools, MCP servers, network policy, and approval rules
live under **Mole Agent → Settings**.

## Platform

- **Organization management** lists tenant organizations and manages membership from the `_sys`
  workspace. It requires `sys.organizations.manage`.

## Account settings are separate

Personal profile, theme, language, timezone, startup route, sign-in settings, active session, and
personal notification identities live under **Account settings**, not workspace Settings. Open
**Account settings → Notify** to manage endpoints, delivery order, and quiet hours.
