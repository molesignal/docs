Open **Metrics** to query the time series stored in metrics streams with PromQL. A query runs in a
tab; tabs can stand side by side, and **Share** copies a link to the query, as on
[Logs](/en-US/logs#query-tabs). The address bar holds the statement that last ran, so a copy of it
shares the query.

## Find a metric

Open the **Metrics browser** beside the editor, or **Search metrics**, and type part of a name. Each
metric shows its type (**counter**, **histogram**, or **gauge**) and how many labels and fields it has.
Select a metric to put it into the query and run it. An empty workspace offers **Connect a metrics
source**; see [Datasource](/en-US/intake).

A metric that has not been seen within the retention of its stream leaves the list.

## Write the query

The editor has two modes:

- **Code**: write PromQL directly. **Common PromQL functions** lists the usual functions; the
  [PromQL support matrix](/en-US/query/promql-subset) lists all that are implemented.
- **Builder**: choose the **Metric**, **Add label filter** for each label to match, a **Function**
  (**Raw metric**, **Rate**, **Instant rate**, or **Increase**), an **Aggregation** (**Sum**,
  **Average**, **Maximum**, or **Minimum**), and the **Range**. The PromQL it builds is shown below.
  An expression that the builder cannot represent, such as a function with extra parameters, stays as
  it is until a builder field is changed.

```promql
sum by (service_name) (
  rate(http_server_request_duration_seconds_count[5m])
)
```

Press **Run**. **Options** set how the query runs:

| Option | Choices |
|---|---|
| **Legend** | **Auto**, **Verbose** (every label), or **Custom** with a template such as `{{service}}`. |
| **Format** | **Time series** or **Table**. |
| **Step** | **auto**, which divides the range into 1,000 steps, or a duration such as `30s` or `5m`. |
| **Type** | **Range** for a chart over the time range, or **Instant** for the value at its end. |
| **Exemplars** | **On** draws the exemplars that link points to traces. |

**Add to dashboard** opens a new dashboard with the query as its first panel. **Clear query** empties
the editor. When a valid query finds nothing, **Expand time range 4×** and **Clear filters and retry**
help before the expression is changed.

## Read the chart

- Drag across the plot to zoom into a time range, drag the X-axis to pan, and double-click to zoom
  out. **Reset time range** returns to the range before the chart was touched.
- Choose the **Draw style** (**line**, **bar**, or **points**) and **Stack** (**Off**, **Normal**, or
  **Percent**; stacking needs two series or more).
- Use the legend to isolate or compare series.
- With exemplars on, select a diamond to see its trace, and **Open trace** to inspect the request
  behind the point.

The zoomed range goes along when moving on to traces or logs.

## Analyze the result

**Graph**, **Table**, and **Query inspector** show the result as a chart, as raw rows, and as the query
that ran. The panels around the result explain the data:

| Panel | Shows |
|---|---|
| **Series** | Each series with its labels and its last, current, average, and maximum value. |
| **Query statistics** | Series, data points, rows scanned, query time, range, and step. |
| **Data quality** | Negative points, missing data, and timestamp anomalies. A counter with negative rates was reset, arrived out of order, or has the wrong type: **View anomalies**, **View raw data**, or **Inspect metric type**. |
| **Top labels** | The label values that weigh most in the result. |
| **Statistical summary** | The distribution of the values of all series. |
| **Cardinality** | The active series of the metric, with the rows scanned. Use it to find labels that create too many series. |
| **Result schema** | The time, value, and label columns of the result. |

The [metric cardinality limits](/en-US/settings/platform#metric-cardinality) of the instance refuse new
series beyond a limit, so check **Cardinality** before adding a label with many values.

## Correlate a metric spike

Select the window of the spike, keep the service and environment labels, then open the related traces
or logs. MoleSignal carries the selected range into the next signal. See
[Cross-signal correlation](/en-US/correlation).

## Permissions

Listing metrics requires `metrics.read`. Running PromQL requires `streams.query`. **Add to dashboard**
requires `dashboards.create`.
