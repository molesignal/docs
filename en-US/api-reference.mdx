MoleSignal exposes a versioned HTTP API. Product endpoints use `/api/v1`. The health probe, Prometheus metrics, public share links, and a few compatibility protocols also use other paths.

## Base URL

For a local instance:

```text
http://localhost:5080/api/v1
```

In production, replace the host with the public address of the deployment, which is the `[http].external_url` value.

## Authentication

Protected endpoints accept a bearer token in the `Authorization` header:

```http
Authorization: Bearer <token>
```

| Token | How to get it | Lifetime |
|---|---|---|
| Login token (JWT) | `POST /api/v1/auth/signin` with an email and a password. See [Log in](/en-US/api/auth/login). | 24 hours by default. |
| API token | **Identity & Access → API tokens**, or [Issue an API token](/en-US/api/auth/issue-token). Tokens look like `ms_<prefix>_<secret>`. | Until revoked, or until the chosen expiry. |
| Default intake token | `GET /api/v1/auth/tokens/default`. Limited to `streams.write`. | Does not expire. |
| RUM client token | `GET /api/v1/auth/tokens/rum?application_id=<id>`. Limited to `rum.write`. | Does not expire. |

Use an API token for scripts and collectors. A login token expires and breaks the sender that uses it. See [Datasource](/en-US/intake#intake-tokens) for the intake tokens.

Authentication builds an IAM context with the subject, the active organization or platform scope, and the effective permissions. The organization of a request always comes from that context. Request bodies cannot select another organization.

## Public and self-authenticating routes

A few routes cannot use an organization bearer token. They validate a narrower credential or a policy instead:

- sign-in, signup policy, and password reset;
- `GET /api/v1/healthz` and the top-level `/metrics`;
- public resource-share exchange and share-session requests;
- signed file downloads and public avatars;
- push connector endpoints, which validate a push token.

A public route is not unrestricted. Its handler checks the signup policy, a share token, a download token, a signature, or the connector credential.

## Authorization

An endpoint can require one or more of these conditions:

- an organization permission such as `streams.query`;
- a platform permission such as `sys.telemetry.read`;
- ownership of a resource, a relationship to it, or a cross-organization grant.

`GET /api/v1/iam/capabilities` returns the effective permissions of the current subject. Do not infer access from a role name or from a visible menu item.

## Requests

- Most bodies are JSON with `Content-Type: application/json`.
- Compatibility intake endpoints use the payload of their protocol, such as Protobuf, NDJSON, or a gzip-compressed body.
- Intake request bodies larger than 2 MiB are rejected with `413`.
- Fields that end in `_micros` hold Unix time in microseconds. Native telemetry records use `_timestamp`, also in microseconds.
- URL-encode path ids and stream names.

## Responses and errors

A successful response is JSON unless the endpoint streams or downloads a file. An error response has a status code and a JSON body with a machine-readable `error` code and a `message`:

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

A `validation_failed` error adds an `issues` array with one entry per invalid field.

| Status | `error` | Meaning |
|---|---|---|
| `400` | `invalid_argument`, `validation_failed` | The request or one of its parameters is invalid. |
| `401` | `unauthorized` | The token is missing, malformed, invalid, or expired. |
| `403` | `forbidden` | The permission, relationship, or scope is missing. |
| `404` | `not_found` | The resource does not exist or is not visible in the authorized scope. |
| `409` | `conflict` | A state or uniqueness conflict. |
| `413` | `payload_too_large` | The body exceeds the limit. |
| `429` | `resource_exhausted` | A rate limit applies. Honor the `Retry-After` header when present. |
| `499` | `cancelled` | The request was cancelled. |
| `503` | `unavailable` | A dependency is unavailable. |
| `500` | `internal` | An internal failure. The body carries the message `internal error`, and the details stay in the server log. |

A request whose body cannot be parsed fails before it reaches the endpoint. That response is plain text instead of JSON:

| Status | Meaning |
|---|---|
| `400` | The body is not valid JSON. |
| `415` | The request lacks `Content-Type: application/json`. |
| `422` | A field is missing or has the wrong type. The text names the field. |

Every response carries the headers `X-Request-Id` and `X-Trace-Id`. Include both when reporting a server-side failure.

## Pagination

Endpoints that can return many rows accept `limit` and `cursor`. Such a response carries `items` and `next_cursor`. Pass `next_cursor` as `cursor` to read the next page, and stop when it is empty. Other list endpoints return the complete list. See the page of each endpoint.

## Query and long-running work

The query family returns regular JSON, streams NDJSON, and runs long queries as asynchronous search jobs. A query that is too large answers `202` with a `job_id` and a `monitor` path. Streaming callers must handle partial delivery and cancel the request when the result is no longer needed. See [Query](/en-US/query).

Large artifacts such as generated reports, profile blobs, and exports are delivered as files through a scoped download token instead of inside a JSON body.
