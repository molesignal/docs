MoleSignal is pre-1.0. This page lists limits that affect planning and operation.

## Deployment

- **No WAL replication.** Intake nodes do not replicate the write-ahead log. Losing an intake volume loses the records that were not flushed to object storage yet.
- **Jobs that run on one node.** The primary `alert` node runs cross-cluster event push and gossip, service graph recompute, APM rollup, status page maintenance, synthetic monitoring automation, slow query analysis, and incident root cause analysis. These jobs do not scale with the number of `alert` nodes. They resume on another node after the primary leaves the membership. See [Role-based deployment](/en-US/deployment/role-based#work-division-between-alert-nodes).
- **PostgreSQL only.** PostgreSQL is the only metadata database.
- **Restart to apply configuration.** A running process does not apply changes to the configuration file. See [Configuration](/en-US/configuration).
- **Forward-only migrations.** A database that a newer build migrated cannot be opened by an older build, and builds before 1.0 can change the baseline schema. See [Upgrade](/en-US/upgrade).

## Intake

- **Request size.** A request body larger than 2 MiB is rejected with `413`.
- **OTLP over HTTP compression.** Compressed request bodies are rejected with `400`. Disable compression in the sender.
- **Histogram buckets.** OTLP histograms store `count`, `sum`, `min`, and `max`. Bucket boundaries, bucket counts, and summary quantiles are not stored.
- **Duplicate spans.** A span that is sent again with the same `trace_id` and `span_id` is dropped.
- **Loki push.** The endpoint decodes the JSON request shape only. Senders that use snappy-compressed protobuf, such as Promtail and Grafana Alloy, cannot push to it.
- **Prometheus remote_write.** Native histograms and metric metadata are skipped.
- **OTLP gRPC without TLS.** The receiver does not terminate TLS. Put a TLS-terminating proxy in front of it for traffic that leaves a trusted network.
- **Rate limiting.** Only the `router` role limits requests. The limit counts the requests of the authenticated organization, and every router replica counts separately.
- **Platform streams.** `_molesignal`, `_synthetic_results`, `_audit`, `_agent_model_traces`, and `_agent_score_traces` are written by MoleSignal only and reject public intake. See [Platform streams](/en-US/streams#platform-streams).

## Query

- **Long ranges run asynchronously.** A query whose estimated size reaches `[querier].auto_async_threshold_rows` returns `202` with a job to follow. With the defaults, that is a range of about 13.9 hours. Send `Prefer: respond-sync` to run it in the request. See [Query](/en-US/query#time-ranges-and-asynchronous-jobs).
- **PromQL subset.** The engine implements a subset of PromQL. See [PromQL support matrix](/en-US/query/promql-subset).
- **Rows per query.** A query that would read more than `[querier].max_scan_rows` rows (100 million by default) is rejected with `400`. Narrow the time range or add filters. PromQL applies the limit to each selector.
- **Freshness in a role-split cluster.** A query reads the files that the catalog lists, so a record that an intake node still buffers becomes visible after the next flush, within `[intake].flush_interval_secs`. A `standalone` node also reads its own buffer. Alert rules move their window back by the evaluation delay of **Settings → Alert evaluation** (60 seconds) by default; see [Evaluation delay](/en-US/alerting/rules#evaluation-delay).

## Alerting

- **Real-time rule counts live in memory.** A `real_time` rule counts on every node that takes writes, and the alert node in charge of the rule adds the counts up every second, so an incident opens at most a second after the records were written. A node that restarts loses only its own share, and a node that cannot be read is left out of that second. Nodes read each other's counts with the cluster bearer, and federated clusters are not added up. The statement is limited to `SELECT count(*) FROM <stream> [WHERE <condition>]`. See [Real-time rules](/en-US/alerting/rules#real-time-rules).

## Security and identity

- **Internal gRPC is unauthenticated.** Port `5082` carries node-to-node traffic without authentication. Keep it on a private network.
- **A passkey is bound to one domain name.** It needs `[http].external_url` to be an HTTPS domain name, and doesn't work when the console is opened at another host name.
- **Password reset needs email.** Resetting a password sends a link by email, so `[notify.smtp]` and `[http].external_url` must be configured.
- **Self-service sign-up without approval needs email.** Signing up proves the address first. Without `[notify.smtp]` and `[http].external_url`, every new account waits for an administrator to approve it.
- **Sign-in limits count per address.** The address must come out right from [Client IP recognition](/en-US/settings/platform#client-ip-recognition). Behind a public proxy or CDN that is not set up, all users share one address and lock each other out. Private addresses do not count by default, so on an internal deployment or behind a proxy that is not set up, only the account limit applies.
- **The account limit is not an account lock.** So that nobody can lock an account out, an account that is being slowed down can still be guessed about 1400 times a day. An account with multi-factor authentication stays closed even to a correct guess. While someone keeps taking the slots, an owner who has not signed in from this address may keep waiting; a passkey, single sign-on, or a password reset gets around it.
- **Lockout policies of an LDAP directory.** The directory's own lockout policy may trigger first, so others can still lock a directory account out through it. Set the [sign-in limits](/en-US/settings/platform#sign-in-limits) lower than the directory's.
- **Sessions.** The account settings page manages only the session of the current browser.

## Reports

- **PDF and PNG rendering** needs headless Chrome. The release container image includes Chromium. A binary installation needs a Chrome installation, and `[scheduled_reports.renderer].base_url` must reach the web UI.
