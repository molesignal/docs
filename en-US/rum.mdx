Real User Monitoring (RUM) records the user experience in the browser and connects it with backend
observability.

## Data model

The browser SDK sends authenticated events to write endpoints:

| Endpoint | Stream or storage | Captures |
|---|---|---|
| `POST /api/v1/rum/v1/sessions` | `logs/rum_sessions` | Session identity, device, browser, geo, and duration. |
| `POST /api/v1/rum/v1/actions` | `logs/rum_actions` | Views, user actions, resources, APIs, and Web Vitals. |
| `POST /api/v1/rum/v1/errors` | `logs/rum_errors` | JavaScript errors and stack frames. |
| `POST /api/v1/rum/v1/replay` | Replay event storage | Session replay events. |

The three streams are created on first write. A new deployment therefore shows an empty state
until the SDK sends its first event.

## Overview

Open **RUM → Overview** to review sessions, users, errors, page performance, and browser or geography
breakdowns for the selected time range.

## Sessions and replay

**Sessions** lists recent browser sessions. Open a session to inspect its action timeline, replay
events, errors, device context, and related backend traces.

Treat replay as sensitive user data. Apply collection controls in the SDK, avoid recording secrets
or personal fields, and use the shortest practical retention.

## Errors and source maps

**Errors** groups recurring JavaScript failures by fingerprint and shows occurrence count, affected
users, stack frames, and example sessions.

Upload source maps from **RUM → Source maps** or the upload route. MoleSignal uses them to
symbolicate minified frames back to original file and line locations. Reading source maps requires
`streams.read`; upload and deletion require `streams.configure`.

## Performance

The performance workspace separates:

- overview trends;
- Core Web Vitals;
- browser error performance;
- API and resource timing.

API tables expose count, latency percentiles, and error rate by URL. Use the global time range and
facets to compare releases, browsers, countries, or pages.

## Related backend traces

When an action carries W3C `traceparent`, its `trace_id` links directly to backend spans. When a
direct id is not available, session detail can search the session time window for related traces.

This lets you move from a slow browser action to its service trace, logs, and metrics while
preserving investigation context.

## Permissions

- `streams.write` sends RUM events.
- `streams.query` opens organization RUM views and related queries.
- `streams.read` lists source-map metadata.
- `streams.configure` uploads or deletes source maps.
