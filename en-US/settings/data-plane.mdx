**Nodes / remote clusters** covers the whole instance, so it appears under **Settings** in the `_sys`
organization. Its remote clusters take `sys.clusters.read` and `sys.clusters.manage`, and the service
data source and federation take `sys.settings.topology.read` and `sys.settings.topology.manage`.
**Query management** under **AI & ML** belongs to the workspace: reading takes
`org.running_queries.read`, and canceling someone's query `org.running_queries.cancel`.

## Nodes and remote clusters

Open **Settings → Nodes / remote clusters**.

### Service data source

**Recompute from storage (multi-node)** decides how the [service map](/en-US/apm/service-map) is
built from traces:

| Setting | How | Trade-off |
|---|---|---|
| On | One node rebuilds the service map from the stored traces at intervals. | Correct across nodes, about 1 to 2 minutes behind. |
| Off | Every intake process pairs spans in memory and flushes the result. | Low delay, but calls whose spans arrive at different intake nodes can be undercounted. |

Turn it on for a deployment with several intake nodes.

### Cluster federation

Federation keeps resource changes in step between clusters. Enter a **Cluster ID** that is unique in
the federation and stays the same across restarts, for example `cluster-eu-west`, and select
**Save changes**. An empty cluster ID turns federation off, after a confirmation. Local data is not
affected when federation stops.

**Advanced parameters** tune the exchange: **Outbox push interval (s)**, **Push batch size**,
**Dedup window (s)**, and **Gossip interval (s)**.

### Remote clusters

A remote cluster is a target of [federated queries](/en-US/deployment/role-based#federated-query).

1. Select **Add cluster**.
2. Enter a **Name** and the **Advertise address** of the remote cluster, for example
   `https://cluster.example.com`.
3. Enter the **Token secret ref**: a reference such as `env:VAR` or `cipher_keys:<id>`, never the token
   itself. The list shows it as `***`.
4. Keep **Verify TLS certificate** on unless the remote cluster uses a private certificate that this
   cluster cannot verify.
5. Select **Add cluster**.

Each row has two more actions:

| Action | Shows |
|---|---|
| **Nodes** | The nodes of the remote cluster, with their roles and versions, or an error when it cannot be reached. |
| **Org map** | The mappings of remote organizations to local ones. Configuration from an unmapped organization is refused. A mapping can carry its own **Per-org token ref**, otherwise the cluster token applies. |

Removing a cluster stops federated queries from reaching it.

## Query management

**Settings → Query management** lists the queries of the workspace that run now, with the query ID,
the user, the start time, and the statement. The list refreshes every 3 seconds. **Cancel** stops a
query. Search jobs that run in the background are managed under
[Streams → Search jobs](/en-US/streams#search-jobs) instead.

| Operation | Endpoint | Permission |
|---|---|---|
| List running queries | `GET /api/v1/query/running` | `sys.clusters.read` |
| Cancel a query | `POST /api/v1/query/{id}/cancel` | `sys.clusters.manage` |
