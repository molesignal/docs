MoleSignal shares one dashboard or one report at a time. A share link never becomes a user token: a
public link opens a short, restricted share session, and every other share still checks the
permissions of the visitor.

## Share a dashboard or a report

Select **Share** on a dashboard, in the dashboard list, or on a report. The **Share resource** dialog
asks for the **Access scope**:

| Scope | Visitors | Rule |
|---|---|---|
| **Current workspace members** | Members who sign in. | They still need the permissions of the resource in the workspace. |
| **Specific organization** | Members of the **Target organization** who sign in. | Creates an explicit cross-organization grant. Only members who can manage cross-organization grants create it. |
| **Anyone with the link** | Anyone who holds the link, without an account. | The link is a revocable, restricted credential. Workspace policy can forbid it. |

Then set the restrictions and select **Create share link**:

| Setting | Applies to | Effect |
|---|---|---|
| **Expiration** | Every scope | **1 day**, **7 days**, **30 days**, or no expiration, within the workspace maximum for public links. The link stops working at once when it expires. |
| **Maximum visits** | Public links | Each new share session counts once. Empty means unlimited. |
| **Access password** | Public links | A restricted session starts only after the password is verified. Spaces around it do not count. Public dashboards always require one, and workspace policy can require one for reports. |
| **Allow download** | Public reports | When off, the report can only be previewed online. Workspace policy can forbid public CSV downloads. |
| **Maximum data time range** | Public dashboards | 1, 6, or 24 hours. **Allow time-range changes** lets visitors pick presets within it. |
| **Public variables** | Public dashboards | Unselected variables are removed from the public model and its requests. **Allow changes to allowlisted variables** lets visitors change the selected ones. |

**Copy link** copies the link. The dialog keeps the link, so it can be copied again later.

## What a public visitor sees

A public dashboard runs only the saved queries of its panels through a restricted proxy: the query
expressions and the explorers stay hidden, and the browser cannot send its own SQL or PromQL. A public
report is a fixed snapshot made when the link was created; opening it never runs a live query. The page
carries a **Public access** watermark and the expiry.

A link that expired, was disabled, or reached its visit limit shows **Link unavailable**. A visit lasts
at most 30 minutes. After that, reloading the page also shows **Link unavailable** and asks to open the
share link again. While the link is still valid, opening it again picks up where it left off, after the
password if it has one, and counts as a new visit.

<Warning>
  A public link is a bearer credential: anyone who obtains it can see the shared content. Do not share
  sensitive data, even with an expiry or a password.
</Warning>

### Access password limits

Wrong access passwords count under the same [sign-in limits](/en-US/settings/platform#sign-in-limits)
as account passwords, with each link as one account. The failure counts, the lock time and the check
interval below are the defaults, and an administrator can change them.

| Failures | Result |
|---|---|
| 5 from one address on one link | This address is locked out of this link for 15 minutes. Other addresses and other links are not affected. |
| 30 from one address, on links or at sign-in | This address cannot open password-protected links or sign in with a password for 15 minutes. |
| 20 from all addresses on one link | The link is not locked. It checks one password every 60 seconds, and an address that opened the link during the last 30 days is not slowed down. |

A refused request answers `429` with `Retry-After` and does not check the password, so even the right
password has to wait. The page shows how long. The right password clears what this address got wrong
on this link.

A private address does not count as an address by default, so behind a proxy nobody has set up, only
the 20 failures apply. See [Client IP recognition](/en-US/settings/platform#client-ip-recognition).

A link is never locked, so guessing can go on at the slowed-down rate. Set a long password and a short
expiry.

## Manage existing shares

**Existing shares** in the dialog lists the links of the resource, with their visit counts and expiry.

| Action | Effect |
|---|---|
| **Copy link** | Copies the link again. |
| **Rotate** | Replaces the link with a new one, when the old one may have leaked. The old link stops working. |
| **Disable** | Stops the link at once. |

A share made before links were kept shows no link until it is rotated once.

## Workspace policy

Administrators set what members may share publicly under
[Settings → General → Sharing and public access](/en-US/settings/organization#sharing-and-public-access):
public links at all, public live dashboards, the maximum lifetime of a public link, passwords for public
reports, no public links to resources tagged `production` or `prod`, and public CSV downloads. When the
policy blocks a scope, the dialog says so and offers the settings. Use a workspace or cross-organization
share instead.

## Audit and permissions

Creating, opening, rotating, and disabling shares are recorded in the
[audit trail](/en-US/settings/data-security#audit). A wrong access password is recorded as
`resource_share.password_failure`, and reaching a limit as `resource_share.lockout`. A visitor's
address comes from [Client IP recognition](/en-US/settings/platform#client-ip-recognition), so behind a
proxy nobody has set up, the audit trail shows the proxy's address. Sharing requires
the share permission of the resource, such as `dashboards.share` or `reports.share`, and MoleSignal
checks access to the resource again before it creates the share.
