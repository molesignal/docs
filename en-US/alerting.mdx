Open **Alerts** to move from detection to acknowledgement, escalation, and resolution. A
[rule](/en-US/alerting/rules) watches a query or a figure and opens an [incident](/en-US/alerting/incidents)
when its condition holds, and an [alert source](/en-US/alerting/sources) opens one for an alert another
system sends in. [Alert routing](/en-US/alerting/routing) decides which team and escalation policy a new
incident gets. The [escalation policy](/en-US/alerting/on-call#escalation-policies) of the
incident pages the people and the [on-call schedules](/en-US/alerting/on-call#on-call-schedules) it names,
and moves on when nobody acknowledges. [Notification channels](/en-US/notification-channels) deliver each
page. [Silences](/en-US/alerting/silences) pause notifications during maintenance, and
[semantic groups](/en-US/alerting/silences#semantic-groups) collapse related incidents.

## The alert center

| Section | Purpose | Guide |
|---|---|---|
| **Incidents** | What fires now: acknowledge, silence, resolve, and investigate. | [Incidents](/en-US/alerting/incidents) |
| **Rules** | Threshold, forecast, outlier, composite, and heartbeat rules, and anomaly and real-time rules. | [Alert rules](/en-US/alerting/rules) |
| **Sources** | Alerts sent in by Alertmanager, Grafana, Datadog, PagerDuty, Zabbix, cloud monitors (Alibaba Cloud, Tencent Cloud, Amazon CloudWatch), email or the API. | [External alerts](/en-US/alerting/sources) |
| **Status pages** | Tell customers about incidents and maintenance. | [Status pages](/en-US/status-pages) |
| **History** | Past incidents, searchable by service and state. | [History](/en-US/alerting/incidents#history) |
| **Postmortems** | Internal postmortems of incidents and their action items, and the major incident settings. | [Major incidents and postmortems](/en-US/alerting/major-incidents) |
| **Insights** | Incident volume, recovery time, noisy rules, affected services, how people responded, and the on-call load. | [Insights](/en-US/alerting/incidents#insights) |
| **Groups** | Semantic groups that collapse related incidents. | [Semantic groups](/en-US/alerting/silences#semantic-groups) |
| **Routing** | Which team and escalation policy a new incident gets. | [Alert routing](/en-US/alerting/routing) |
| **Escalations** | Who is paged, in which order, and when to move on. | [Escalation policies](/en-US/alerting/on-call#escalation-policies) |
| **On-call schedules** | Rotations, temporary coverage, shift swaps, and calendar subscriptions. | [On-call schedules](/en-US/alerting/on-call#on-call-schedules) |
| **Remediation** | HTTP and Kubernetes fixes started on an incident in one click and run once approved. | [Remediation](/en-US/alerting/remediation) |
| **Tickets** | Jira, ServiceNow or Meegle connections that file tickets for incidents and sync their status. | [Tickets](/en-US/alerting/tickets) |
| **Silence policies** | Pause notifications for matching incidents. | [Silence policies](/en-US/alerting/silences#silence-policies) |
| **Inhibition** | Holds back the notifications of lesser incidents while a worse or upstream one is active. | [Inhibition](/en-US/alerting/inhibition) |

## Set up alerting

A workspace usually gets ready for its first page in this order:

<Steps>
  <Step title="Connect a channel">
    Configure a connector such as email, an IM app, or phone and SMS under
    [Settings → Notify → Connectors](/en-US/notification-channels), and have members bind their
    personal methods in [Account settings → Notify](/en-US/account#notify).
  </Step>
  <Step title="Build the on-call schedule">
    Create an [on-call schedule](/en-US/alerting/on-call#create-a-schedule) with the rotation of the team.
  </Step>
  <Step title="Create the default escalation policy">
    Create a policy named `default` that pages the schedule first and a lead next. Rules saved in the
    rule workbench take it when [routing](/en-US/alerting/routing) finds no team on-call policy for them. See [The default policy](/en-US/alerting/on-call#the-default-policy).
  </Step>
  <Step title="Create and test rules">
    Start from a preset in the [rule workbench](/en-US/alerting/rules#create-a-threshold-rule), test it on
    real data, and save it.
  </Step>
  <Step title="Rehearse">
    Trigger a rule on purpose with [Trigger a rule](/en-US/api/alerting/trigger-rule), and check that the
    page arrives, the escalation moves on, and acknowledgement stops it.
  </Step>
</Steps>

See [Make production alerts actionable](/en-US/best-practices/actionable-alerts) and
[Set up on-call and notifications](/en-US/best-practices/on-call-setup) for advice on what to alert on
and how to route it.

## Permissions

| Permission | Capability |
|---|---|
| `alerts.incidents.read` | Read incidents, their history, and insights. |
| `alerts.incidents.acknowledge` | Acknowledge, resolve, and snooze incidents and groups of incidents. |
| `alerts.incidents.update` | Reassign an incident, add responders, change its severity, write notes, and run its response: roles, tasks, and updates. |
| `alerts.incidents.escalate` | Escalate and merge incidents, and declare a major incident. |
| `alerts.incidents.create`, `alerts.incidents.silence` | Open an incident by hand; silence one. |
| `alerts.incidents.remediate`, `alerts.incidents.tickets`, `alerts.incidents.rca` | Start remediation on an incident, create its tickets, and write its root cause. |
| `alerts.rules.read`, `alerts.rules.manage` | Read rules; create and change them. |
| `alerts.routing.read`, `alerts.routing.manage` | Read and change routing rules and team on-call policies. |
| `alerts.escalations.read`, `alerts.escalations.manage`, `alerts.escalations.delete` | Read, change, and delete escalation policies. |
| `alerts.sources.read`, `alerts.sources.manage` | Read and change alert sources. |
| `alerts.mutes.read`, `alerts.mutes.manage` | Read silences; create, change, and remove them. |
| `alerts.inhibitions.read`, `alerts.inhibitions.manage` | Read inhibit rules; create, change and delete them. |
| `alerts.semantic_groups.manage` | Manage groups. |
| `alerts.remediation.read`, `alerts.remediation.manage` | Read and define remediation actions. |
| `alerts.tickets.read`, `alerts.tickets.manage` | Read and manage ticket connectors. |
| `alerts.response.read`, `alerts.response.manage` | Read and change major incident settings. |
| `alerts.discovery.read` | Read what discovery found. |
| `schedules.read` | Read schedules and who is on call. |
| `schedules.create`, `schedules.update`, `schedules.delete` | Create, change, and delete schedules and their rotations. |
| `schedules.overrides.manage`, `schedules.swaps.request`, `schedules.swaps.approve` | Cover a shift; ask for a swap; approve or reject one. |
| `postmortems.read`, `postmortems.manage` | Read postmortems; write postmortems and their action items. |
