## Release notes and upgrade preparation

[GitHub Releases](https://github.com/molesignal/molesignal/releases) is the source of published release notes. The list below loads release details in the browser. If JavaScript or the GitHub request is unavailable, use that link to inspect versions, publication dates, change notes, and downloadable assets.

### Before an upgrade

1. Record the running version with `molesignal --version` and locate the target version in the release notes.
2. Read compatibility and migration notes between the two versions. Distinguish prereleases from stable releases.
3. Protect PostgreSQL, object storage, configuration, and encryption keys following [Backup and restore](/en-US/backup-restore).
4. Validate historical queries, controlled new ingestion, permissions, and notification behavior in an isolated environment before a production upgrade.

Use the [production checklist](/en-US/deployment/production-checklist) and [recovery readiness guide](/en-US/best-practices/recovery-readiness) for acceptance steps. Planned Enterprise capabilities are not shipped features; check the capability page and the target release notes for availability.
