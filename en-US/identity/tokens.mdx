An API token lets a program call MoleSignal without signing in. A token has no role of its own: it
acts as a member or a service account, and its scope can narrow what it may do. A service account is
an identity for a program: it cannot sign in, it has a role, and its tokens act as the account.

## Token types

| Type | Acts as | Issued on |
|---|---|---|
| **Personal API token** | The member who issued it. | **Account settings → API tokens** |
| **Service Account API token** | A service account. | **Identity & Access → API tokens** or **Service accounts** |
| **Default intake token** | Its owner, limited to writing data. | **Datasource**. See [Intake tokens](/en-US/intake#intake-tokens). |
| **RUM client token** | Its RUM application, limited to writing RUM data. | **Datasource**. See [Intake tokens](/en-US/intake#intake-tokens). |

A token has the form `ms_<prefix>_<secret>`, and a RUM client token `msrum_…`. The prefix finds the
token, and only a hash of the secret is stored. Send a token as a bearer credential:

```http
Authorization: Bearer ms_…
```

A token cannot enter the `_sys` organization.

## What a token may do

A token never does more than its member or service account may do at the time of a request. Its
scope narrows that further:

| Scope | The token may |
|---|---|
| **Same as me**, **Same as the service account** | Whatever its member or service account may, as that access changes. |
| **Permission policy** | The permissions of a [permission policy](/en-US/identity/roles#permission-policies), such as **Data intake**, as the policy changes. |
| **Custom** | The permissions ticked when it was issued. They never change. |

A token cannot be given a permission that its issuer lacks. When a member loses a permission, every
token of theirs loses it too, and when a member leaves the workspace or is disabled, their tokens
stop working. A role on a single resource, through an access grant or a share, reaches a token only
within its scope. A RUM client token belongs to its application: it writes RUM data and reaches
nothing else.

## Issue a personal token

1. Open **Account settings → API tokens** and select **New token**.
2. Enter a **Name**, for example `collector-production`.
3. Choose the **Scope**: **Same as me**, a **Permission policy**, or **Custom** permissions. A
   policy or a permission that you do not hold cannot be chosen; a chosen policy lists its
   permissions.
4. Set **Expires in days**: 365 by default, at most 1825. Leave it empty for a token that never
   expires.
5. Select **Create token**, then **Copy token**. The token is shown only this once.

The list shows your tokens with their scope, type, expiry, and last use. **Revoke** stops a token at
once and for good. Managing your own tokens requires `personal_tokens.manage`, which every built-in
role holds. Personal tokens are issued from a signed-in session: a token cannot issue another token.

## Tokens of the organization

**Identity & Access → API tokens** lists every token of the workspace, with the member, service
account, or application it acts as, and its scope. Listing them requires `api_tokens.read`. With
`api_tokens.revoke` you can revoke any token, and select **Issue service account token** to give a
service account a token: choose the **Service account**, the **Scope**, and the expiry.

## Service accounts

Use a service account for a collector, a CI pipeline, an integration, or an AI agent that runs
without a person. Then a member leaving the workspace never breaks the automation.

1. Open **Service accounts** and select **Create service account**.
2. Enter a **Name**, for example `deployment-automation`, a **Description**, and a **Role**.
3. Select **Create account and token**, and copy the initial API token. It may do whatever the
   account may, expires in 365 days, and is shown only once.

Select an account to manage it:

| Action | Effect |
|---|---|
| **Save changes** | Keeps a new name, description, or role. Every token of the account follows the new role at once. |
| **Manage API tokens** | Opens **API tokens** filtered to the account, to issue more tokens or revoke one. |
| **Disable** / **Enable** | A disabled account and all its tokens stop authenticating until it is enabled again. |
| **Delete** | Removes the account and revokes all its tokens. It cannot be undone. |

The **Principal ID** of the account identifies it in audit records and access grants. Reading service
accounts requires `service_accounts.read`, and changing them requires `service_accounts.manage`.

## Choose a token

| Caller | Recommended token |
|---|---|
| A collector or an agent that sends telemetry | A service account token that follows the **Data intake** policy, or your default intake token. |
| Browser or mobile code that sends RUM data | The RUM client token of the application. It is visible to end users. |
| CI that reports deployments | A token that follows the **Data intake** policy, which also holds `apm.deploy`. |
| Automation that reads data or changes resources | A service account token, narrowed with a policy or custom permissions. |
| An MCP client or a script run by a person | A personal API token with an expiry. |

A sign-in session lives in HttpOnly cookies of the browser and ends after 24 hours by default
(`[auth].session_ttl_secs`). The `Authorization` header does not accept it, so programs always use
an API token.

## Tokens API

| Operation | Endpoint | Permission |
|---|---|---|
| Issue a personal token | `POST /api/v1/me/api-tokens` | `personal_tokens.manage` |
| List your tokens | `GET /api/v1/me/api-tokens` | `personal_tokens.manage` |
| Revoke your token | `DELETE /api/v1/me/api-tokens/{id}` | `personal_tokens.manage` |
| List what a token can be limited to: the permission policies and the organization permissions | `GET /api/v1/me/api-tokens/scopes` | A signed-in member |
| Issue a service account token | `POST /api/v1/auth/tokens` | `api_tokens.revoke` |
| List every token | `GET /api/v1/auth/tokens` | `api_tokens.read` |
| Revoke any token | `DELETE /api/v1/auth/tokens/{id}` | `api_tokens.revoke` |

See [Issue an API token](/en-US/api/auth/issue-token), [List API tokens](/en-US/api/auth/list-tokens), and
[Revoke an API token](/en-US/api/auth/revoke-token).
