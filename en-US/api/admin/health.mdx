| Endpoint | Authentication |
|---|---|
| `GET /api/v1/healthz` | None |
| `GET /metrics` | None |
| `GET /api/v1/readyz` | Bearer token |
| `GET /api/v1/version` | Bearer token |

## Liveness

```http
GET /api/v1/healthz
```

The composite health probe. It answers `200` when the node is healthy and `503` with a `reason` while the WAL replays or when the object store is unreachable. Use it for container and load balancer probes.

<ResponseExample>
```json 200
{ "status": "ok" }
```
</ResponseExample>

## Readiness

```http
GET /api/v1/readyz
Authorization: Bearer <token>
```

The traffic-readiness probe. It answers `503` only while the WAL replays. Object store degradation does not make read-only traffic unready. The request needs a bearer token, so a probe without credentials receives `401`. Probe `/api/v1/healthz` instead when the probe cannot carry a token.

<ResponseExample>
```json 200
{ "status": "ready" }
```
</ResponseExample>

## Version

```http
GET /api/v1/version
Authorization: Bearer <token>
```

Returns the product version, the commit and branch, the build time, the build id, the release channel, and the edition.

<ResponseExample>
```json 200
{
  "version": "26.1.0.0",
  "commit": "<git-sha>",
  "branch": "main",
  "build_epoch_secs": 1790000000,
  "build_id": "<build-id>",
  "release_channel": "alpha",
  "edition": "oss"
}
```
</ResponseExample>

## Metrics

```http
GET /metrics
```

Prometheus exposition (`text/plain; version=0.0.4`) with process and subsystem metrics, such as `cache_*` hit ratios, `wal_*`, `object_store_*`, and `storage_reconciler_issues_total`. Restrict this route at the proxy or network layer. See [Self-observability](/en-US/self-observability).
