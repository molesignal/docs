All calls read one traces stream of the organization: the stream that has all of the fields `trace_id`, `span_id`, `service.name`, `name`, `start_time_unix_nano`, `end_time_unix_nano`, and `status_code`. A stream named `default` wins over other streams that qualify, and the stream name breaks the remaining ties. An organization without such a stream gets empty results. Only traces that survived [tail sampling](/en-US/configuration#trace-capture-and-tail-sampling) are readable.

All calls require `traces.read`, or `sys.telemetry.read` in the system scope.

## List trace summaries

```http
GET /api/v1/web/traces
```

Returns one summary per trace, with cursor pagination. A stream that has no trace summaries yet answers an empty page.

**Query parameters**

| Param | Type | Notes |
|---|---|---|
| `from`, `to` | integer | The window in microseconds. The defaults are the last 24 hours until now. `to` must be greater than `from`. |
| `q` | string | Case-insensitive text that must appear in the `trace_id`, `span_id`, service, operation, or status of a span. Up to 256 characters. |
| `filters` | string | A JSON array of filters. See below. |
| `where` | string | A JSON condition tree: filters and text joined by AND and OR. See below. |
| `expression` | string | A field query as the **Traces** page writes it. It stands for `q`, `filters`, and `where`: send one or the other. See below. |
| `sort` | string | `latest` (default), `earliest`, `duration_desc`, `duration_asc`, `span_count_desc`, or `errors_desc`. |
| `limit` | integer | Page size. Default `20`. The value is clamped to 1 through 5000. |
| `cursor` | string | The `next_cursor` or `previous_cursor` of an earlier page. |
| `fields` | string | Fields of the root span of each trace to return with it, comma-separated, named as the stream names them. Up to 12. An unknown field, a JSON field, or a `molesignal.trace.*` field answers `400`. |

A filter is an object with `field`, `op`, and `value`, and a request carries at most 32 filters. All filters must match. The operator `in` takes `values`, a list of values, in place of `value`.

| Field | Type | Operators |
|---|---|---|
| `trace_id` | text | `=`, `!=`, `contains`, `in` |
| `duration_ns`, `span_count`, `error_count` | integer | `=`, `!=`, `>`, `>=`, `<`, `<=`, `in` |
| Any other scalar field of the traces stream | by field type | Text: `=`, `!=`, `contains`, `in`. Numbers and timestamps: `=`, `!=`, `>`, `>=`, `<`, `<=`, `in`. Booleans: `=`, `!=`, `in`. |

A filter names its field as the stream names it, such as `service.name` or `name`; no other name stands for a field. The operators `eq`, `ne`, and `like` are aliases of `=`, `!=`, and `contains`. A JSON field is not filterable.

`trace_id`, `duration_ns`, `span_count`, and `error_count` are compared on the trace. Every other field belongs to a span: a filter on it matches a trace when one of its spans passes the filter, and `!=` matches a trace when none of its spans has the value. A span without the field does not have the value.

`in` matches any of its `values`: from 1 to 64 values, each up to 512 bytes and of the field's type. A value listed twice counts once. On a span field, `in` matches a trace when one of its spans has one of the values.

`where` says what the list of filters cannot: alternatives. It is a JSON object in one of four forms:

| Form | Matches |
|---|---|
| A filter, as in `filters` | The filter. |
| `{"text": "..."}` | The text, as `q` matches it. |
| `{"and": [...]}` | Every condition in the list. |
| `{"or": [...]}` | Any condition in the list. |

`filters`, `q`, and `where` hold together. A filter in the tree keeps its meaning: one on a span field matches a trace when one of its spans passes it, and `!=` when none of its spans has the value. A trace matches `{"or": [A, B]}` when it matches `A` or matches `B`. The filters of `filters` and `where` count together toward the limit of 32. A tree looks for text at most 8 times, nests groups at most 8 deep, and has at least one condition in each group.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'filters=[{"field":"status_code","op":"=","value":"ERROR"}]' \
  --data-urlencode 'where={"or":[{"field":"service.name","op":"=","value":"checkout"},{"field":"span_count","op":">","value":"50"}]}'
```

The request lists the failed traces that have a span of `checkout` or more than 50 spans.

`expression` takes the text of the **Traces** page instead: comparisons with `=`, `!=`, `>`, `>=`, `<`, `<=`, `contains`, and `field in ('a', 'b')`, words to find, a phrase in quotes, `AND` and `OR` in any case with `AND` binding tighter, and brackets. The server reads it into the `q`, `filters`, and `where` the page sends, and checks them as above. The text is at most 8 KiB and nests brackets at most 32 deep. A part it cannot read, such as an unclosed bracket or a comparison with nothing, answers `400` and names the part.

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "expression=status_code = 'ERROR' AND (service.name = 'checkout' OR span_count > 50)"
```

The request lists the same traces as the one above.

A `cursor` binds the page to the query that issued it. Repeating a request with a cursor and a different `limit`, `sort`, `q`, `filters`, or `where` answers `400`.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'sort=duration_desc' \
  --data-urlencode 'limit=2' \
  --data-urlencode 'fields=http.route' \
  --data-urlencode 'filters=[{"field":"service.name","op":"in","values":["checkout","payments"]}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    {
      "trace_id": "0af7651916cd43dd8448eb211c80319c",
      "service": "checkout",
      "operation": "GET /checkout",
      "start_ns": 1790000000000000000,
      "duration_ms": 180.0,
      "span_count": 3,
      "error_count": 1,
      "status": "ERROR",
      "http_status_code": 502,
      "fields": { "http.route": "/checkout" }
    }
  ],
  "next_cursor": null,
  "previous_cursor": null,
  "has_more": false
}
```
</ResponseExample>

Each item describes a trace by its root: the `service` and `operation` of the root span, the start time in nanoseconds, the duration in milliseconds, the number of spans, and the number of error spans. `has_more` is `true` when `next_cursor` is set.

| Field | Notes |
|---|---|
| `status` | The status of the root span: `OK`, `ERROR`, or `UNSET`. |
| `http_status_code` | The `http.response.status_code` of the root span, or its `http.status_code`, when it holds a code from 100 to 599. Absent otherwise, and for traces stored before the summary kept it. |
| `fields` | The fields asked for in `fields` that the root span has a value for. Absent when it has none. The page is answered without them when reading them fails. |

## Count traces over time

```http
GET /api/v1/web/traces/histogram
```

Counts every trace that a list query matches, in time buckets, by the start time of the trace. The call takes the window, `q`, `filters`, and `where` of the list, and matches the same traces. The caller chooses the buckets.

**Query parameters**

| Param | Type | Notes |
|---|---|---|
| `from`, `to` | integer | The window in microseconds. Both are required. `to` must be greater than `from`. |
| `q`, `filters`, `where`, `expression` | string | The same as for the list. |
| `bucket_micros` | integer | The length of one bucket in microseconds. At least `1000`. |
| `origin_micros` | integer | The start of the first bucket in microseconds. Not after `from`. |

A request covers at most 512 buckets from `origin_micros` to `to`.

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/histogram" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucket_micros=900000000' \
  --data-urlencode 'origin_micros=1790000100000000' \
  --data-urlencode 'filters=[{"field":"service.name","op":"=","value":"checkout"}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucket_micros": 900000000,
  "origin_micros": 1790000100000000,
  "buckets": [
    { "start_micros": 1790000100000000, "total": 42, "errors": 3, "p50_ns": 41000000, "p95_ns": 180000000, "p99_ns": 320000000 },
    { "start_micros": 1790001900000000, "total": 17, "errors": 0, "p50_ns": 38000000, "p95_ns": 95000000, "p99_ns": 120000000 }
  ],
  "split": true
}
```
</ResponseExample>

`buckets` lists only the buckets that hold a trace, oldest first. `total` is the number of traces that started in the bucket. `errors` is the number of those traces with at least one error span. `p50_ns`, `p95_ns`, and `p99_ns` are the median, 95th, and 99th percentile durations of those traces in nanoseconds. They are estimates and are absent when no duration was counted.

The count reads the trace summaries, and the spans when a filter is on a span field. The list returns one summary for each trace. A summary that a retried write stored twice counts twice.

When the count is not available, the call still answers `200`. `buckets` is then empty, and `unavailable` gives the reason.

| `unavailable` | Cause |
|---|---|
| `time_budget` | The count took longer than 20 seconds. |
| `busy` | The role already runs as many queries as [`[search.admission]`](/en-US/configuration) allows. |
| `scan_limit` | The window holds more rows than `[querier].max_scan_rows` allows one query to read. |

## Read request figures

```http
GET /api/v1/web/traces/red
GET /api/v1/web/traces/red/breakdown
```

Reads the rate, errors, and duration of the requests a list query matches: in total, bucket by bucket, and by how long they took. The breakdown reads the same figures for each value of one field. A request is a span. By default the requests are the spans where a service took a request in: a server or consumer span, or the root of a trace. `scope=all` reads every span.

A filter on a span field holds for the span itself, so `service.name = 'api'` reads the requests `api` served. `trace_id` and `duration_ns` are read of the span, and `span_count` and `error_count` of the trace the span belongs to.

**Query parameters**

| Param | Type | Notes |
|---|---|---|
| `from`, `to`, `bucket_micros`, `origin_micros` | integer | The same as for the trace count over time. |
| `q`, `filters`, `where`, `expression` | string | The same as for the list. |
| `scope` | string | `entry` (default) or `all`. |
| `by` | string | Breakdown only, and required there: the field to group the requests by, as the stream names it. |

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/red" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucket_micros=60000000' \
  --data-urlencode 'origin_micros=1790000100000000' \
  --data-urlencode "expression=service.name = 'checkout'"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucket_micros": 60000000,
  "origin_micros": 1790000100000000,
  "scope": "entry",
  "total": { "requests": 1840, "errors": 12, "p50_ns": 41000000.0, "p95_ns": 180000000.0, "p99_ns": 320000000.0 },
  "buckets": [
    { "start_micros": 1790000100000000, "requests": 31, "errors": 0, "p50_ns": 40000000.0, "p95_ns": 150000000.0, "p99_ns": 210000000.0 }
  ],
  "latency": [
    { "from_ns": 0, "to_ns": 50000000, "requests": 1203, "errors": 2 },
    { "from_ns": 50000000, "to_ns": null, "requests": 637, "errors": 10 }
  ]
}
```
</ResponseExample>

`buckets` lists the buckets that hold a request, oldest first. `latency` lists the requests by duration, shortest first; the last range has no upper bound. `errors` is `null` where failures cannot be told, and the durations are in nanoseconds, `null` without a request and where durations are masked.

The breakdown answers `field`, `bucket_micros`, `origin_micros`, `scope`, and `groups`: the 50 commonest values first, each with its figures and a `series` of buckets with `requests`, `errors`, and `p95_ns`. `value` is `null` for the requests without a value. `more` is `true` when more values exist than are listed.

When the figures are not available, the calls still answer `200` with `unavailable`: `time_budget`, `busy`, and `scan_limit` as for the trace count, `timestamp_masked` when time is masked for the reader, and `field_protected` when the breakdown field is masked or encrypted.

## List spans

```http
GET /api/v1/web/traces/spans
```

Returns one row per span that a query matches, with cursor pagination. The call takes the window, `q`, `filters`, and `where` of the trace list, and reads them for each span: a filter on a span field holds for the span itself, and `!=` keeps a span without the field. `duration_ns` is the span's own duration. `span_count` and `error_count` are those of the trace the span belongs to. A span matches `{"or": [A, B]}` when it matches `A` or matches `B`.

**Query parameters**

| Param | Type | Notes |
|---|---|---|
| `from`, `to` | integer | The window in microseconds. The defaults are the last 24 hours until now. `to` must be greater than `from`. |
| `q`, `filters`, `where`, `expression` | string | The same as for the trace list. |
| `sort` | string | `latest` (default), `earliest`, `duration_desc`, or `duration_asc`. |
| `limit` | integer | Page size. Default `100`. The value is clamped to 1 through 5000. |
| `cursor` | string | The `next_cursor` or `previous_cursor` of an earlier page. The cursor carries the query of its page; a different `limit` answers `400`. |

<ResponseExample>
```json 200
{
  "items": [
    {
      "trace_id": "0af7651916cd43dd8448eb211c80319c",
      "span_id": "53995c3f42cd8ad8",
      "parent_span_id": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "start_ns": 1790000000020000000,
      "duration_ns": 140000000,
      "status": "ERROR",
      "kind": 2,
      "http_status_code": 502
    }
  ],
  "next_cursor": null,
  "previous_cursor": null,
  "has_more": false
}
```
</ResponseExample>

`status` is `OK`, `ERROR`, or `UNSET`. `kind` numbers the span kind as OTLP does: `1` internal, `2` server, `3` client, `4` producer, `5` consumer. `parent_span_id`, `kind`, and `http_status_code` are absent when the span has none. The call runs as a tracked query and is admitted like any other query.

## Read one trace

```http
GET /api/v1/web/trace/{trace_id}
```

Returns every span of a trace, ordered by start time. `trace_id` has 1 to 128 characters from `A-Z`, `a-z`, `0-9`, `-`, and `_`.

**Query parameters**

| Param | Type | Notes |
|---|---|---|
| `from`, `to` | integer | The window in microseconds that the spans of the trace started in. Give both or neither. At most 31 days. Without them the trace is looked for in the last 24 hours. |

The response is limited to 100,000 spans and 32 MiB. `truncated` is `true` when a limit cut the span list.

<ResponseExample>
```json 200
{
  "trace_id": "0af7651916cd43dd8448eb211c80319c",
  "root_span_id": "b7ad6b7169203331",
  "spans": [
    {
      "span_id": "53995c3f42cd8ad8",
      "parent_span_id": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "start_ns": 1790000000020000000,
      "end_ns": 1790000000160000000,
      "duration_ns": 140000000,
      "kind": 2,
      "status": "ERROR",
      "status_message": "upstream timeout",
      "attributes": { "http.method": "POST", "http.status_code": "502" },
      "events": [],
      "links": [],
      "sampling_reason": "error",
      "partial": false,
      "late": false,
      "duplicate": false,
      "conflict": false
    }
  ],
  "truncated": false,
  "partial": false,
  "partial_reasons": [],
  "sampling_reasons": ["error"],
  "late_span_count": 0,
  "duplicate_span_count": 0,
  "conflict_span_count": 0
}
```
</ResponseExample>

The example shows one span with its main fields. A real span also carries `trace_flags`, `trace_state`, `resource`, `scope`, the `dropped_*_count` counters, `schema_version`, and `semantic_conventions_version`.

| Field | Notes |
|---|---|
| `root_span_id` | The first span without a parent. Build the tree from `span_id` and `parent_span_id`. |
| `spans[].status` | `OK`, `ERROR`, or `UNSET`. |
| `spans[].attributes` | The span attributes, merged with the flattened attribute columns of the stream. |
| `spans[].sampling_reason` | Why the tail sampler kept the trace, for example `error`. |
| `partial`, `partial_reasons` | Whether spans are missing, and why. |
| `late_span_count`, `duplicate_span_count`, `conflict_span_count` | The spans that arrived late, repeated, or conflicted. |

## Find the spans that link to a trace

```http
GET /api/v1/web/trace/{trace_id}/linked
```

A span keeps links to the spans it follows from, and the trace detail returns them with the span. This call finds the other direction: spans of other traces whose links name a span of this trace. It takes the same `from` and `to` as the trace detail, and searches that window.

<ResponseExample>
```json 200
{
  "spans": [
    {
      "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
      "span_id": "00f067aa0ba902b7",
      "service": "billing-worker",
      "operation": "process invoice",
      "start_ns": 1790000005000000000,
      "duration_ns": 30000000,
      "status": "OK",
      "linked_span_id": "53995c3f42cd8ad8",
      "attributes": { "messaging.operation": "process" }
    }
  ],
  "more": false
}
```
</ResponseExample>

`spans` lists up to 200 linking spans, newest first, and `more` is `true` when more spans link to the trace. `linked_span_id` is the span of this trace that the link points at, and `attributes` holds the attributes of the link.

The search reads the links of every span in the window as text, within the time budget of the trace count. When it cannot finish, the call still answers `200` with an empty `spans` and an `unavailable` reason: `time_budget`, `busy`, or `scan_limit`, as for the trace count.

**Errors**

| Status | Cause |
|---|---|
| `400` | A parameter is invalid: `to` is not greater than `from`, a filter uses an unknown field or operator (`unsupported trace filter field: nope`), an `in` filter has no values or more than 64, `where` is not a condition tree or goes past its limits, `expression` comes with `q`, `filters`, or `where` or has a part it cannot read, the cursor does not match the query, a field in `fields` is unknown or a document, or the `trace_id` has invalid characters or length. For the count: the window or a bucket parameter is missing, `bucket_micros` is under `1000`, `origin_micros` is after `from`, or the request covers more than 512 buckets. For the trace detail and its linking spans: only one of `from` and `to` is given, or the window is longer than 31 days. |
| `403` | The token lacks `traces.read`. |
| `404` | The trace is not found in the window, or was sampled out. |
