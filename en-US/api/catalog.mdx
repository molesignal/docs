## Authorization model

An endpoint can require:

- an organization permission such as `streams.query` or `alerts.rules.manage`;
- a platform permission such as `sys.telemetry.read`;
- resource-level ownership or a relationship/grant;
- a public share session restricted to one resource.

Do not infer authorization from a display role. Query `/api/v1/iam/capabilities` for the effective
permission and feature snapshot.

## Choose and verify a request

Start with the linked guide for the relevant family. Check its HTTP method, required permission, organization scope, request fields, and response format before using an endpoint. A family can include both management requests and data queries with different permissions.

Use the documented read request to verify the selected organization and resource before changing configuration. After a write, read back the resource or query a controlled test event to confirm the intended result. An HTTP success alone does not establish that telemetry reached the intended stream or that an incident recovered.

For errors, follow the [API introduction](/en-US/api-reference) and the endpoint-specific guidance. Include the running version, a redacted request, and request identifiers when [reporting a documentation mismatch](/en-US/support); omit credentials and sensitive event data.
