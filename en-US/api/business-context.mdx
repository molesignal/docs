```http
GET /api/v1/business-context
PUT /api/v1/business-context
```

The business keys, such as a tenant, a plan, or an experiment group, and the field that carries each in
spans, logs, and RUM events. See [Business context](/en-US/business-context). Reading needs any of
`apm.services.read`, `traces.read`, `logs.read`, `rum.events.read`, `apm.settings.read`, or
`sys.telemetry.read`; setting needs `apm.settings.manage` and is recorded in the activity log.

## Set the keys

`PUT` replaces every key. Blank fields name nothing, a blank `label` is the key, and important values are
trimmed and listed once each; the answer is what was saved.

| Field | Notes |
|---|---|
| `key` | Starts with a lower-case letter and holds only lower-case letters, digits, and `_`, at most 64. Unique. |
| `label` | What readers see it called, at most 80 characters. |
| `span` | The span attribute, as the traces stream names the field. |
| `log` | The log field. |
| `rum` | The RUM field, a key of a JSON field included, such as `context.tenant`. |
| `important` | Values that matter most, at most 50 of up to 200 characters. |

A key names at least one of `span`, `log`, and `rum`. At most 8 keys.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/business-context \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"keys":[{"key":"tenant","label":"Tenant","span":"tenant.id","log":"tenant_id","rum":"context.tenant","important":["acme"]}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "keys": [
    {
      "key": "tenant",
      "label": "Tenant",
      "span": "tenant.id",
      "log": "tenant_id",
      "rum": "context.tenant",
      "important": ["acme"]
    }
  ]
}
```
</ResponseExample>

**Errors**

| Status | Reason |
|---|---|
| `400` | A key is named badly or twice, names no field, or there are more keys or values than allowed. |
| `403` | The token lacks the permission of the call. |
