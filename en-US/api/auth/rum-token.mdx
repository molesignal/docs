---
title: "RUM client token"
description: "Get or create the application-bound token that browser and mobile code embeds."
"zh-Hans_link": "/zh-Hans/api/auth/rum-token"
---

```http
GET /api/v1/auth/tokens/rum?application_id=<id>
```

Returns the RUM client token of a [RUM application](/en-US/rum/applications) and creates it on the first call. The application must exist: create it first. The token has the form `msrum_<prefix>_<secret>` and belongs to the application, not to whoever fetched it: it holds only `rum.write` for that application, reaches nothing else, and never expires. Embed it in browser or mobile code, where end users can read it. The call requires `api_tokens.issue`.

**Query parameters**

| Param | Type | Required | Notes |
|---|---|---|---|
| `application_id` | string | Yes | The identifier of an application of the workspace. |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/auth/tokens/rum?application_id=checkout-web" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KDZpGNwn5vO9dhXyE3am4qhihX",
  "prefix": "dYrZbAh2UcL2HL7g",
  "token": "msrum_dYrZbAh2UcL2HL7g_<secret>",
  "token_kind": "rum_client",
  "policy_id": null,
  "permissions": ["rum.write"],
  "application_id": "checkout-web",
  "created_at_micros": 1790000000000000
}
```
</ResponseExample>

An `application_id` that is not an identifier answers `400`, and one that no application has answers `404`. Use the same identifier as `applicationId` in the SDK. See [RUM applications](/en-US/rum/applications#client-token).
