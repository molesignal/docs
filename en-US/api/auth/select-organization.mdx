title: "Select a workspace"
description: "Switch the active organization and get a token scoped to it."

```http
POST /api/v1/orgs/{id}/select
```

Switches the signed-in user to another organization that the user belongs to, and returns a new login token scoped to it. The response has the same shape as [Log in](/en-US/api/auth/login) and adds `"system": true` for the protected `_sys` scope. Platform administrators can select the `_sys` organization, which platform-wide calls such as [Rotate JWT signing keys](/en-US/api/auth/rotate-jwt) need.

**Path parameters**

| Param | Type | Notes |
|---|---|---|
| `id` | string | Organization id from `GET /api/v1/orgs`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/orgs/<organization-id>/select \
  -H "authorization: Bearer $MS_JWT"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "token": "eyJhbGciOi...",
  "user_id": "<user-id>",
  "org_id": "<organization-id>",
  "org_name": "default",
  "display_role": "Owner",
  "roles": [
    { "id": "<role-id>", "key": "owner", "name": "Owner", "builtin": true }
  ]
}
```
</ResponseExample>

Use the returned token for later requests. The previous token keeps working in the previous organization until it expires.
