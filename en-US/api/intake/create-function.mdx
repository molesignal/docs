```http
POST /api/v1/functions
```

Creates a reusable transform for pipelines. VRL and JavaScript are compiled when the function is created, and a function with invalid source is rejected. Both runtimes are built into the binary. The call requires `functions.create`.

**Body**

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | Yes | Function name. |
| `language` | string | Yes | `vrl`, `js`, or `llm`. An `llm` function needs `[functions].llm_eval_enabled` and a model provider. |
| `source` | string | Yes | The VRL or JavaScript source, or the instruction of an `llm` function. |
| `paramsSchema` | object | No | Parameters. For `llm`, `outputField` selects the output field, default `_llm_eval`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/functions \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "lowercase-level",
    "language": "vrl",
    "source": ".level = downcase!(string!(.level))"
  }'
```
</RequestExample>

A syntax error answers `400`, for example `js syntax error: Uncaught SyntaxError: Unexpected token '}'`. Test source before saving with `POST /api/v1/functions/run`, which takes `language`, `source`, and a sample `input`, and returns `output`. See [Functions](/en-US/functions).

Other function routes: `GET /api/v1/functions`, `GET`, `PUT`, and `DELETE /api/v1/functions/{id}`. The built-in presets are read-only.

## Test the transform before saving

The dry-run endpoint requires `functions.run`, separately from `functions.create`. Use a representative input, including missing and malformed fields, before attaching a transform to live intake.

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".level = downcase!(string!(.level))","input":{"level":"ERROR","message":"example"}}'
```

For this input, check that `output.level` is `error`, the unrelated `message` field is preserved, and `dropped` is `false`. A successful compilation does not prove that every production event satisfies the transform's assumptions. For example, the fallible string conversion above needs a string `level`.

## Connect the function to a pipeline

Creating a function stores a reusable definition; it does not automatically transform incoming events. Save the returned function ID, add the intended function step through [Pipelines](/en-US/pipelines), and test the complete pipeline before enabling it for a live stream.

Keep a representative input and expected output with the change. After enabling the pipeline, ingest a controlled event and query the destination stream to confirm the stored fields. A dry-run response alone does not validate the deployed intake path.

## Common failures

| Symptom | Action |
|---|---|
| Empty function name | Supply a non-empty `name`. |
| Source rejected on creation | Fix syntax or compilation errors before retrying. |
| Dry run denied | Check `functions.run`; creation permission is a separate permission. |
| Input fails at runtime | Reproduce the failing field shape in a dry run and handle absent or differently typed fields. |
| Saved function has no effect on new logs | Check the pipeline attachment and destination stream. |
