```http
POST /api/v1/_bulk
```

Elasticsearch `_bulk`-compatible NDJSON intake for Filebeat, Logstash, and the Vector `elasticsearch` sink. The call requires `logs.write`. A body with `Content-Encoding: gzip` is accepted.

| Action | Handling |
|---|---|
| `index`, `create`, `update` | The source document is stored as a log event. |
| `delete` | Skipped without a response item. Telemetry is never deleted through this endpoint. |

The `_index` of an action selects the target log stream. Without it, the `stream-name` header applies, and then `default`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## Choose this endpoint

Use this endpoint when an existing sender can emit Elasticsearch bulk NDJSON. It is an ingestion adapter, not an Elasticsearch cluster: search, index templates, document IDs, and in-place update semantics are not supplied by this API. Use [SQL queries](/en-US/query) to read stored events.

## Build a valid batch

- Send an action object and a document object on separate lines for each `index` or `create` operation. End the batch with a newline.
- For `update`, place the event fields under `doc`; the fields become a new event rather than modifying a stored event.
- Set `_index` on the action to choose a stream. Otherwise use `stream-name`, or accept the `default` stream.
- Supply `_timestamp` as an integer Unix timestamp in microseconds when preserving event time. Otherwise the receiver uses the current time.
- A `delete` action is skipped. It does not delete telemetry and does not contribute a stored-event item to the response.

## Verify ingestion

For a one-event batch, expect `errors: false` and one response item with `status: 201`. Compare the item count with the number of events intended for ingestion; an HTTP success alone does not prove the batch was constructed as intended.

Open **Logs**, select the stream chosen by `_index`, and use a time range containing the event timestamp. Query a distinctive field from the sample. If the event is absent, check stream selection and the timestamp unit before resending the whole batch. This interface does not use Elasticsearch document IDs to deduplicate retries.

## Troubleshoot a rejected request

| Symptom | Check |
|---|---|
| Authentication or permission error | Use an API Token for the intended organization with `logs.write`. |
| Action or document is not a JSON object | Check NDJSON line boundaries. Do not send a JSON array or a pretty-printed multiline object. |
| Unknown action | Use the supported action names above. |
| Decompression error | Set `Content-Encoding: gzip` only when the body is actually compressed. |
| Success with fewer events than expected | Check that every write action has its document line and distinguish skipped deletes from stored events. |
