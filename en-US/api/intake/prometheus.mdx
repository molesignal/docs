---
title: "Prometheus remote_write"
description: "Use MoleSignal as a Prometheus remote_write target."
---

```http
POST /api/v1/prometheus/api/v1/write
```

Accepts Prometheus and VictoriaMetrics `remote_write` version 1 requests, which are snappy-compressed protobuf. The call requires `streams.write` and answers `204` on success.

Each time series is written to the metrics stream named by its `__name__` label. The remaining labels become fields, and the sample becomes the `value` field. Native histograms and metric metadata are skipped, and exemplars are stored beside the samples.

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```
</RequestExample>

Query the metrics with PromQL by naming the stream as the metric. A series of `http_requests_total` with the labels `service` and `status` becomes:

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scanned_rows": 1,
  "took_ms": 154
}
```

**Limits** apply per series and per organization: at most 64 labels per series, label names up to 128 bytes, label values up to 2048 bytes, and cardinality limits for active and new series. See `[intake.prometheus]` in [Configuration](/en-US/configuration#intake).
