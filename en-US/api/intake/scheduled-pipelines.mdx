| Operation | Endpoint | Permission |
|---|---|---|
| List | `GET /api/v1/scheduled_pipelines` | `pipelines.read` |
| Create | `POST /api/v1/scheduled_pipelines` | `pipelines.create`, and `audit.read` when it reads `_audit` |
| Get | `GET /api/v1/scheduled_pipelines/{id}` | `pipelines.read` |
| Update | `PUT /api/v1/scheduled_pipelines/{id}` | `pipelines.edit` for a change of configuration, with `audit.read` when it reads `_audit`, and `pipelines.pause` when `enabled` changes |
| Delete | `DELETE /api/v1/scheduled_pipelines/{id}` | `pipelines.delete` |
| Run history | `GET /api/v1/scheduled_pipelines/{id}/runs` | `pipelines.read` |
| Limits today | `GET /api/v1/scheduled_pipelines/{id}/limits` | `pipelines.read` |
| Backfill | `POST /api/v1/scheduled_pipelines/{id}/backfill` | `pipelines.run`, and `audit.read` when it reads `_audit` |

## List

The list returns every pipeline with the state of its latest run and a 24-hour summary:

<ResponseExample>
```json 200
[
  {
    "id": "3KBHcb6imgQq7FXBsROGTIRHOyg",
    "name": "normalize-app",
    "sourceStream": "app_raw",
    "targetStream": "app",
    "functionSteps": { "mode": "scheduled", "signalType": "logs", "sources": ["app_raw", "nginx_raw"], "steps": [ ... ] },
    "cron": "every:5m",
    "lookbackSecs": 300,
    "enabled": true,
    "lastRunAt": 1790000000000000,
    "readUntil": { "appRaw": 1789999940000000, "nginxRaw": 1789999940000000 },
    "retry": null,
    "alertRecord": null,
    "auditReaderId": null,
    "auditReader": null,
    "createdAt": 1789900000000000,
    "updatedAt": 1789900000000000,
    "lastRunState": "succeeded",
    "lastRunStartedAt": 1790000000000000,
    "lastRunFinishedAt": 1790000000250000,
    "lastRunScannedRows": 1200,
    "lastRunError": null,
    "runs24h": 288,
    "succeededRuns24h": 288,
    "failedRuns24h": 0
  }
]
```
</ResponseExample>

Each item carries the fields of [Get](#get), the latest run as `lastRunState`, `lastRunStartedAt`, `lastRunFinishedAt`, `lastRunScannedRows` (the events that it read), and `lastRunError`, and the counts of runs over the past 24 hours.

## Get

```http
GET /api/v1/scheduled_pipelines/{id}
```

Returns the pipeline with the read position of each source and the planned retry:

<ResponseExample>
```json 200
{
  "id": "3KBHcb6imgQq7FXBsROGTIRHOyg",
  "name": "normalize-app",
  "sourceStream": "app_raw",
  "targetStream": "app",
  "functionSteps": { "mode": "scheduled", "signalType": "logs", "sources": ["app_raw", "nginx_raw"], "steps": [ ... ] },
  "cron": "every:5m",
  "lookbackSecs": 300,
  "enabled": true,
  "lastRunAt": 1790000000000000,
  "readUntil": { "appRaw": 1789999940000000, "nginxRaw": 1789999640000000 },
  "retry": {
    "source": "nginx_raw",
    "attempt": 2,
    "nextAt": 1790000030000000,
    "error": "read: <reason>"
  },
  "alertRecord": null,
  "auditReaderId": null,
  "auditReader": null,
  "createdAt": 1789900000000000,
  "updatedAt": 1789900000000000
}
```
</ResponseExample>

| Field | Notes |
|---|---|
| `readUntil` | The read position of each source, in microseconds. The events of the source before it have been handled. A source that has not been read yet has no entry. |
| `retry` | The soonest planned retry of a window that failed, or `null`. `source` names the source, `attempt` is the attempt that the retry will be, `nextAt` is when it is due, and `error` is what the last attempt failed on. |
| `alertRecord` | The counts of an alert pipeline for the latest UTC day on which it took an event: `day` (`YYYY-MM-DD`), `processed`, `dropped`, and `failed`, and the latest drop and failure of that day as `last_dropped` and `last_failed`, each with `atTime`, `rule` (the rule, alert source, or synthetic check), and `reason`. A missing count is 0. `null` for other pipelines and for an alert pipeline that has taken no event yet. See [Daily counts](/en-US/pipelines/alert-events#daily-counts). |
| `auditReaderId` | Whose access the pipeline reads `_audit` with: whoever last saved it. `null` for a pipeline that does not read `_audit`. See [Audit stream](/en-US/settings/data-security#audit-stream). |
| `auditReader` | That person's `id`, `displayName`, and `email`, for anyone with `pipelines.read`. `null` when the user no longer exists or cannot be read, which leaves `auditReaderId` alone. |

See [Schedule and read positions](/en-US/pipelines#schedule-and-read-positions) and [Retries and dead letters](/en-US/pipelines#retries-and-dead-letters).

## Update and delete

`PUT` takes the same body as [Create a pipeline](/en-US/api/intake/create-pipeline) and replaces the configuration. Changing only `enabled` needs `pipelines.pause`, and any other `PUT`, one that changes nothing included, needs `pipelines.edit`. Changing `enabled` from `false` to `true` resets the read positions, so every source reads back `lookbackSecs` again. `DELETE` answers `{"deleted": true}`.

On a pipeline that reads `_audit`, a `PUT` also decides whose access the pipeline reads with. See [Audit stream](/en-US/settings/data-security#audit-stream).

| The `PUT` | Also needs | Whose access the pipeline reads `_audit` with |
|---|---|---|
| Changes the configuration | `audit.read`, and a token that is not a service account's | The caller's from then on. |
| Changes nothing | Nothing | The caller's from then on when the caller holds `audit.read` and the token is not a service account's. Otherwise unchanged, with no error. |
| Changes only `enabled` | Nothing | Unchanged. |

## Run history

```http
GET /api/v1/scheduled_pipelines/{id}/runs?limit=50&beforeTime=<cursor>
```

Returns the runs of a scheduled pipeline, newest first. A realtime or an alert pipeline records no runs.

<ResponseExample>
```json 200
[
  {
    "id": "3KE7Yq0d3jvXm5cJ8r2bWQzN1aP",
    "pipelineId": "3KBHcb6imgQq7FXBsROGTIRHOyg",
    "state": "succeeded",
    "startedAt": 1790000000000000,
    "finishedAt": 1790000000250000,
    "scannedRows": 1200,
    "writtenRows": 1150,
    "droppedRows": 48,
    "failedRows": 2,
    "attempt": 1,
    "error": null,
    "warning": "stream `app` rejected 2 event(s): <reason>"
  }
]
```
</ResponseExample>

| Field | Notes |
|---|---|
| `state` | `running`, `succeeded`, `failed`, or `cancelled`. |
| `startedAt`, `finishedAt` | When the run started and ended. `finishedAt` is `null` while the run is running. |
| `scannedRows` | The events that the run read from its sources. |
| `writtenRows` | The events that every destination took. |
| `droppedRows` | The events that a step dropped with `abort`, or that dedupe removed. |
| `failedRows` | The events that a step failed on, that were routed into a source, or that a destination did not take. |
| `attempt` | `1` for a first attempt. Higher when the run retried a window that failed. |
| `error` | Why the run failed: a window that failed, with the planned retry, or a target stream that took none of its events while the pipeline has no dead letter stream. |
| `warning` | What went wrong without failing the run, such as events that failed, rejected or undelivered events, or a window skipped after its retries. |

`scannedRows` equals the sum of `writtenRows`, `droppedRows`, and `failedRows`.

## Limits today

```http
GET /api/v1/scheduled_pipelines/{id}/limits
```

Returns what the [quota and throttle steps](/en-US/pipelines#count-and-limit) of a realtime pipeline let through and held back today, from 00:00 UTC, counted by every node. Nodes add their counts every 5 seconds. A step that counted nothing today has no row.

<ResponseExample>
```json 200
{
  "dayStart": 1790035200000000,
  "buckets": [
    {
      "step": "daily",
      "bucket": "[\"checkout\"]",
      "admittedEvents": 1000000,
      "admittedBytes": 524288000,
      "overEvents": 1240,
      "overBytes": 650117
    },
    {
      "step": "per-host",
      "bucket": "",
      "admittedEvents": 86400,
      "admittedBytes": 45298483,
      "overEvents": 12,
      "overBytes": 6291
    }
  ]
}
```
</ResponseExample>

| Field | Notes |
|---|---|
| `step` | The name of the step. |
| `bucket` | Empty for a quota that is not split and for a throttle. For a split quota, the values of the fields that it is split by, as a JSON list in their order, `null` where an event had none, and `*` for the buckets past the cap of 1,000. |
| `admittedEvents`, `admittedBytes` | What went through within the limit. |
| `overEvents`, `overBytes` | What came past the limit: dropped, let through, or sent to another stream, as the step says. |

## Backfill

```http
POST /api/v1/scheduled_pipelines/{id}/backfill
```

| Field | Type | Notes |
|---|---|---|
| `startTime` | integer | Start of the window, in microseconds. |
| `endTime` | integer | End of the window. It must be greater than `startTime`, and the window must not exceed 31 days. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines/$PIPELINE_ID/backfill \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"startTime": 1790000000000000, "endTime": 1790086400000000}'
```
</RequestExample>

<ResponseExample>
```json 202
{
  "jobs": [
    {
      "source": "app_raw",
      "jobId": "3KE6epTrWXts1oa2ePEKIHKxG19",
      "monitor": "/api/v1/query/jobs/3KE6epTrWXts1oa2ePEKIHKxG19"
    },
    {
      "source": "nginx_raw",
      "jobId": "3KE6eqAbXq0n2yLr7VvTq9cUo4D",
      "monitor": "/api/v1/query/jobs/3KE6eqAbXq0n2yLr7VvTq9cUo4D"
    }
  ]
}
```
</ResponseExample>

The backfill submits one search job per source. Each job reads its source over the window, applies the steps, and writes, delivers, and keeps dead letters the way a scheduled run does. The read positions of the pipeline do not move. Follow each job with its `monitor` path. See [Query](/en-US/query#time-ranges-and-asynchronous-jobs).

A realtime or an alert pipeline answers `400` (`realtime and alert pipelines do not support backfill`). A pipeline that reads `_audit` answers `403` when the token lacks `audit.read` or belongs to a service account. The job checks the submitter again when it runs, and fails when they no longer hold `audit.read`.
