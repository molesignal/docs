```http
POST /api/v1/_kinesis_firehose
```

Accepts an AWS Data Firehose HTTP endpoint delivery. The endpoint does not use a bearer token. Create a connector of kind `aws_kinesis_firehose` with a `pushToken` of at least 16 characters and a `target_stream`, and give the token to Firehose as the access key. The endpoint reads the token from `X-Amz-Firehose-Access-Key`, and also accepts `X-Connector-Token` and `?token=`. A wrong token answers `401`.

Each record has base64 `data`. The endpoint decodes it, splits it into lines, and turns every non-empty line into a log event in the `target_stream` (default `kinesis`). A line with a JSON object becomes fields, and a plain text line becomes the field `message`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_kinesis_firehose \
  -H 'X-Amz-Firehose-Access-Key: <pushToken>' \
  -H 'content-type: application/json' \
  -d '{"requestId":"req-1","timestamp":1790000000000,"records":[{"data":"eyJsZXZlbCI6ImluZm8ifQo="}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{ "requestId": "req-1", "timestamp": 1790000000123 }
```
</ResponseExample>

The response echoes `requestId` and carries a millisecond `timestamp`, as Firehose requires. See [Connectors](/en-US/connectors) for the connector setup.

## Verify delivery and stream selection

1. Confirm that the connector is enabled and that the sender uses its push token. A regular API token does not replace a push token.
2. When setting raw `configJson` through the connector API, use `target_stream` for the destination stream, not `targetStream`. The token key remains camel-case `pushToken`.
3. Send one test event with a unique marker and record the receipt time. In **Logs**, select the intended stream and a window covering receipt, then query the marker.
4. If the request succeeds but the intended stream is empty, inspect the corresponding default stream and the saved target field. An HTTP acknowledgment does not replace a query against the intended destination.

Protect the token as a credential. When passing it as a URL query parameter, keep the complete URL out of logs, tickets, and screenshots. Before retrying a failed request, distinguish token and connector-state problems from payload-format or compression errors.
