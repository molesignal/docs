```http
POST /api/v1/scheduled_pipelines
```

Creates a pipeline. The path keeps the name `scheduled_pipelines` for both modes. The call requires `pipelines.create`.

**Body**

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | Yes | Pipeline name. |
| `source_stream` | string | Yes | The stream that the pipeline reads. |
| `target_stream` | string | Yes | The stream that the pipeline writes. It must differ from the source, or the call answers `409`. |
| `function_steps` | object | Yes | The steps and the mode. See below. |
| `cron` | string | Yes | `every:30s`, `every:5m`, or `every:1h` for a scheduled pipeline. An empty string for a realtime pipeline. |
| `lookback_secs` | integer | No | Seconds that each scheduled run reads back. Default 300. |
| `enabled` | boolean | No | Default `true`. |

`function_steps` fields:

| Field | Notes |
|---|---|
| `mode` | `scheduled` (default) or `realtime`. |
| `signal_type` | `logs`, `metrics`, or `traces`. A realtime pipeline supports `logs` only. |
| `steps` | Ordered steps. A VRL step has `transform_name`, `script`, and `kind` set to `vrl`. A routing step has `kind` set to `builtin`, `operation` set to `route`, and a `routing` object. |
| `sources`, `sinks` | Stream names. Required for a realtime pipeline. |
| `sink_connectors` | Scheduled only. Ids of the connectors that also receive the output. |
| `retain_source` | Realtime only. Keeps the original event in the source stream. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines \
  -H "authorization: Bearer $MS_JWT" \
  -H 'content-type: application/json' \
  -d '{
    "name": "normalize-app",
    "source_stream": "app_raw",
    "target_stream": "app",
    "function_steps": {
      "language": "vrl",
      "signal_type": "logs",
      "steps": [
        { "transform_name": "normalize-level",
          "script": ".level = downcase!(string!(.level))" }
      ]
    },
    "cron": "every:5m",
    "lookback_secs": 300,
    "enabled": true
  }'
```
</RequestExample>

**Errors**

| Status | Cause |
|---|---|
| `400` | A schedule outside `every:Ns/m/h`, a non-positive lookback, or a realtime pipeline for a signal other than logs. |
| `409` | The source and the target stream are the same, or a realtime pipeline is already enabled for the source stream. |

See [Pipelines](/en-US/pipelines) for the realtime mode and the routing step.
