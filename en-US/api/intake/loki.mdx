```http
POST /api/v1/loki/api/v1/push
```

Accepts the Loki JSON push shape. The call requires `logs.write` and answers `204` on success. A body with `Content-Encoding: gzip` is accepted.

The endpoint decodes JSON only. Senders that use snappy-compressed protobuf, such as Promtail and Grafana Alloy, cannot push to it. Use the OpenTelemetry Collector, Vector, or Fluent Bit instead.

<RequestExample>
```bash cURL
LOKI_TIMESTAMP="$(date +%s)000000000"
curl -X POST http://localhost:5080/api/v1/loki/api/v1/push \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -H 'stream-name: app' \
  -d '{"streams":[{"stream":{"service":"api"},"values":[["'"$LOKI_TIMESTAMP"'","started"]]}]}'
```
</RequestExample>

Each value becomes one log event. The labels become fields, the line becomes the field `message`, and the nanosecond timestamp is converted to microseconds. The `stream-name` header selects the target stream, and the default is `default`.

## Verify the example

The example generates a current nanosecond timestamp in a macOS or Linux shell. After receiving `204`, open **Logs**, select `app` and the last hour, and find the `message` for `service = 'api'`. If you substitute a historical timestamp, select a window covering that event time and confirm it is within retention.

Distinguish three fields: `streams` is the Loki batch structure, the `service` label becomes an event field, and the `stream-name` header selects the MoleSignal destination stream. Verify that stream and time window with a query before resending a batch.
