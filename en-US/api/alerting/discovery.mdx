```http
GET /api/v1/alerts/discovery/findings
GET /api/v1/alerts/discovery/findings/{id}
```

Lists what [discovery](/en-US/alerting/discovery) found, the most recently seen first, or reads one
finding. Requires `alerts.discovery.read`.

**Query parameters**

| Parameter | Description |
|---|---|
| `status` | `open` (default), `ended`, or `all`. |
| `kind` | `apm_anomaly`, `apm_regression`, `rum_new_issue`, or `rum_regressed_issue`. |
| `limit` | 100 by default, at most 500. |

**Finding fields**

| Field | Description |
|---|---|
| `kind` | As above. |
| `key` | What tells the same problem: the kind, the subject, and the metric. |
| `severity` | `warning`, `error`, or `critical`. |
| `subject` | An APM service (`namespace/name`) or a RUM application id. |
| `environment`, `metric` | The environment; the metric of an APM move: `errorRate`, `p95` (microseconds), or `throughput` (requests per second). |
| `title` | A sentence. |
| `value`, `baseline` | The figure now and what it is compared with. |
| `startedAt`, `lastSeenAt`, `endedAt` | When it started, was last seen, and ended (microseconds); no `endedAt` means open. |
| `missedRounds` | Rounds in a row it was not seen; it ends at 3. |
| `detail` | An APM finding has `previous`, `lastWeek`, `version`, `previousVersion`, and nearby `changes`; a RUM finding has `issueId`, `application`, `errorType`, `location`, and `version`. |


To turn findings into incidents, [create a rule](/en-US/api/alerting/create-rule) with `query.discovery`:
`{"kinds": [...], "subjects": [...], "environments": [...], "minSeverity": "warning"}`, each left out to
take all. Saving gives the rule its one shape: split by finding, one incident per finding it takes, as
severe as the finding, and low urgency unless `trigger.urgency` says otherwise.
