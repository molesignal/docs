A ticket connector connects Jira (Cloud, or Data Center / Server), ServiceNow or Feishu Project (Meegle outside
China). A ticket created for an incident follows it: acknowledgements, resolutions, and notes can be
written as comments, and resolving the incident can move the ticket to done. The ticket's status is synced
every 5 minutes, and Jira can also push it at once through a webhook. How the pages use it is in
[Tickets](/en-US/alerting/tickets).

| Method and path | What it does | Permission |
|---|---|---|
| `GET /api/v1/alerts/tickets/connectors` | The organization's ticket connectors, as `{ "connectors": [ ... ] }`. | `alerts.tickets.read` |
| `POST /api/v1/alerts/tickets/connectors` | Creates a connector. | `alerts.tickets.manage` |
| `PUT /api/v1/alerts/tickets/connectors/{id}` | Replaces a connector; `system` cannot change. | `alerts.tickets.manage` |
| `DELETE /api/v1/alerts/tickets/connectors/{id}` | Deletes a connector. | `alerts.tickets.manage` |
| `POST /api/v1/alerts/tickets/connectors/{id}/test` | Tests the connection: Jira returns `{ "ok": true, "detail": "<signed-in user>" }`, Feishu Project reads the work item type once. | `alerts.tickets.manage` |
| `GET /api/v1/alerts/tickets/sites` | The address of each Feishu Project platform: `{ "meegle": [{ "key": "feishu", "url": "https://project.feishu.cn" }, { "key": "lark", "url": "https://meegle.com" }] }`. | `alerts.tickets.read` |
| `GET /api/v1/alerts/incidents/{id}/tickets` | The incident's tickets, as `{ "tickets": [ ... ] }`. | `alerts.incidents.read` on the incident |
| `POST /api/v1/alerts/incidents/{id}/tickets` | Creates a ticket for the incident with a connector. | `alerts.incidents.tickets` on the incident |
| `POST /api/v1/public/tickets/jira/{connectorId}` | Jira's webhook, without signing in. | `X-Hub-Signature` |

## Connectors

**Request body**

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | Yes | A name. |
| `system` | string | Yes | `jira` or `meegle`. |
| `settings` | object | Yes | The site, project, type, and mappings; see below. |
| `secrets` | object | When creating | Credentials, stored encrypted and never returned. Jira takes `apiToken` (a Cloud API Token or a Data Center personal access token) and an optional `webhook_secret`; Feishu Project takes `plugin_secret`. Left empty on a change, a secret keeps its value. |
| `comments` | object | No | `{ "acknowledged": true, "resolved": true, "notes": true }`: comment when the incident is acknowledged or resolved, and write the incident's notes as comments. All default to `false`. |
| `transitionOnResolve` | boolean | No | Move the ticket to done when the incident is resolved. Default `false`. |
| `resolveIncidentWhenDone` | boolean | No | Resolve the incident when the ticket is done, whether it is open or acknowledged, with no one recorded. Default `false`. |
| `auto` | object | No | Automatic tickets: `{ "enabled": true, "minSeverity": "error", "conditions": [ ... ] }`. A new incident at or above `minSeverity` whose labels meet `conditions` gets a ticket; `conditions` are written as in [routing rules](/en-US/api/alerting/create-routing-rule). |
| `onMajorIncident` | boolean | No | Create a ticket when a [major incident](/en-US/api/alerting/major-incidents) is declared. Default `false`. |
| `enabled` | boolean | No | Default `true`. A disabled connector creates and syncs no tickets and takes no webhooks. |

**`settings`: Jira**

| Field | Notes |
|---|---|
| `siteUrl` | The site address, starting with `https://`, for example `https://example.atlassian.net`. |
| `deployment` | `cloud` (default): the account email plus an API Token, over REST API v3 with Atlassian Document Format bodies. `data_center`: a personal access token, over REST API v2. |
| `email` | The Cloud account email. |
| `projectKey`, `issueType` | The project key and issue type, for example `OPS` and `Incident`. |
| `priorities` | Severities mapped to Jira priority names, for example `{ "critical": "Highest" }`; unmapped ones set no priority. |
| `labels` | Labels added to tickets, besides the `molesignal` label every ticket gets. |
| `fields` | Default values for other fields when creating, keyed by Jira field ID. |
| `resolveTransition` | The transition taken when the incident is resolved, by name or ID; empty takes the first transition to a done status. |

**`settings`: Feishu Project**

| Field | Notes |
|---|---|
| `site` | The platform: `feishu` (default, Feishu Project, at `https://project.feishu.cn`) or `lark` (Meegle, at `https://meegle.com`). The address follows the platform and cannot be changed. |
| `pluginId` | The plugin ID, exchanged with `plugin_secret` for a plugin token. |
| `userKey` | Whose name tickets and comments are written in. |
| `projectKey`, `workItemTypeKey` | The space and the work item type. |
| `priorityField`, `priorities` | The priority field's key, and severities mapped to priority option values; empty sets no priority. |
| `fields` | Default values for other fields when creating, keyed by field_key. |
| `resolveTransitionId` | For a status-flow work item: the transition ID taken when the incident is resolved. |
| `resolveNodeId` | For a node-flow work item: the node ID completed when the incident is resolved. |
| `doneStates` | The status keys that count as done. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/tickets/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "name": "Jira OPS",
    "system": "jira",
    "settings": {
      "siteUrl": "https://example.atlassian.net",
      "deployment": "cloud",
      "email": "oncall-bot@example.com",
      "projectKey": "OPS",
      "issueType": "Incident",
      "priorities": { "critical": "Highest", "error": "High" }
    },
    "secrets": { "apiToken": "<jira-api-token>", "webhookSecret": "<webhook-secret>" },
    "comments": { "acknowledged": true, "resolved": true, "notes": true },
    "transitionOnResolve": true,
    "auto": { "enabled": true, "minSeverity": "critical", "conditions": [] }
  }'
```
</RequestExample>

The response is the saved connector: `secrets` is not returned, and `secretsSet` lists the credentials
that are set. A Jira connector also has `webhook_path`, which is
`/api/v1/public/tickets/jira/<connector ID>`. Creating, changing, and deleting are recorded in the audit log.

**`settings` for ServiceNow**

| Field | Description |
|---|---|
| `instanceUrl` | The instance address, starting with https. |
| `auth` | `basic` (default, secret `password`), `oauth` (client credentials, secret `clientSecret`) or `apiKey` (secret `apiKey`). |
| `username`, `clientId` | The basic authentication user, the OAuth client ID. |
| `table` | The table to create in, `incident` by default; it must extend `task`. |
| `assignmentGroup`, `callerId`, `category` | Fields written on creation; the first two are `sys_id`s. |
| `priorities` | Severity or priority → `impact/urgency`; one number means both. |
| `fields` | Defaults of other fields on creation (field name → value). |
| `resolveState`, `closeCode` | The `state` and `closeCode` written when the incident resolves, `6` and `Solution provided` by default. An empty `closeCode` writes none. |
| `doneStates` | Values of `state` that count as done, `6`, `7` and `8` by default. |

Testing the connector answers `{ "ok": true, "detail": "<table>" }`.

## Create a ticket for an incident

```http
POST /api/v1/alerts/incidents/{id}/tickets
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `connectorId` | string | Yes | The connector to create it with. When the incident already has a ticket there, that ticket is returned. |

The ticket's title is `[severity] incident summary`; its body gives the incident's severity and status,
services, labels, triggering query, the summary of its AI root cause, and the incident page address, in the
workspace's default language. The ticket is recorded on the incident's timeline and in the audit log.

<ResponseExample>
```json 200
{
  "id": "3KJ4m8T1qHd0Ue6WzB2nLc9RfPa",
  "orgId": "<organization-id>",
  "incidentId": "<incident-id>",
  "connectorId": "<connector-id>",
  "system": "jira",
  "externalId": "10482",
  "externalKey": "OPS-42",
  "url": "https://example.atlassian.net/browse/OPS-42",
  "status": "To Do",
  "done": false,
  "incidentStatus": "open",
  "createdBy": "<user-id>",
  "createdAt": 1790000000000000,
  "syncedAt": 1790000000000000,
  "lastError": "",
  "actionItemId": null
}
```
</ResponseExample>

| Field | Notes |
|---|---|
| `externalId`, `externalKey` | The Jira issue ID and key; both are the work item ID in Feishu Project. |
| `status`, `done` | The status name found at the last sync, and whether it is done. Jira goes by the `done` status category, Feishu Project by the connector's `doneStates`. |
| `syncedAt`, `lastError` | When it was last synced, and the error from the last sync or comment (cleared after a success). |
| `actionItemId` | Set on a ticket made for a [postmortem action item](/en-US/api/alerting/postmortems); such tickets get no comments or transitions from the incident. |

## Status sync and the Jira webhook

Tickets that are not done are synced every 5 minutes. When a ticket becomes done and its connector has
`resolveIncidentWhenDone`, the incident is resolved, except for tickets made for postmortem action
items.

Once a Jira connector has a `webhook_secret`, add a webhook in Jira under **System settings → WebHooks**:
the URL is MoleSignal's external address followed by `webhook_path`, the secret is the same
`webhook_secret`, and the events are issue updates.

```http
POST /api/v1/public/tickets/jira/{connectorId}
```

MoleSignal computes HMAC-SHA256 over the body with `webhook_secret` and compares it with
`X-Hub-Signature: sha256=<hex>`. The body is at most 1 MiB.

| Status | Reason |
|---|---|
| `204` | Taken; also `204` when the body's issue is not a ticket MoleSignal created. |
| `401` | The signature does not match, or the connector has no `webhook_secret` and takes no webhooks. |
| `404` | The connector does not exist, is disabled, or is not Jira. |
