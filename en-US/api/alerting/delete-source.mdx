---
title: "Delete an alert source"
description: "Delete an alert source and resolve the incidents it left open."
"zh-Hans_link": "/zh-Hans/api/alerting/delete-source"
---

```http
DELETE /api/v1/alerts/sources/{id}
```

Deletes an [alert source](/en-US/alerting/sources). It requires `alerts.sources.manage`. Its token stops working at once, and its recently received requests go with it. Its open incidents are resolved in the name of the calling user, since without the source they would never receive a recovery. With federation on, the other clusters resolve the source's open incidents there once the deletion syncs.

<RequestExample>
```bash cURL
curl -X DELETE http://localhost:5080/api/v1/alerts/sources/$SOURCE_ID \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

On success the answer is `200` with the text `deleted`.

**Errors**

| Status | Cause |
|---|---|
| `403` | The token lacks `alerts.sources.manage`. |
| `404` | The source does not exist. |
