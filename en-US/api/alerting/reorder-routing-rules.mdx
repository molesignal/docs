---
title: "Reorder routing rules"
description: "Put the alert routing rules in the order of the given IDs."
"zh-Hans_link": "/zh-Hans/api/alerting/reorder-routing-rules"
---

```http
PUT /api/v1/alerts/routing/rules/order
```

Puts the organization's [routing rules](/en-US/alerting/routing#routing-rules) in the given order. It requires `alerts.routing.manage`. The listed rules come first in the order given; the rest follow in their previous order. IDs that are not rules of the organization are ignored.

| Field | Type | Description |
|---|---|---|
| `ids` | array | Required; rule IDs, the first tried first. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/order \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<rule-id-2>", "<rule-id-1>"]}'
```
</RequestExample>

The response is every rule in the new order, `position` numbered from 0 without gaps; see [Rule fields](/en-US/api/alerting/list-routing-rules#rule-fields).

**Errors**

| Status | Cause |
|---|---|
| `403` | The token lacks `alerts.routing.manage`. |
| `422` | `ids` is missing, or another field is given. The response is plain text. |
