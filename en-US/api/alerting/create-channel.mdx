A connector stores the credentials and transport settings of one notification provider for an organization. Listing and reading connectors requires `notify.connectors.read`. Creating, updating, testing, and deleting a connector requires `notify.connectors.manage`.

| Operation | Endpoint |
|---|---|
| List connector types | `GET /api/v1/notify/connector-types` |
| List connectors | `GET /api/v1/notify/connectors` |
| Create a connector | `POST /api/v1/notify/connectors` |
| Get a connector | `GET /api/v1/notify/connectors/{id}` |
| Update a connector | `PUT /api/v1/notify/connectors/{id}` |
| Test a connector | `POST /api/v1/notify/connectors/{id}/test` |
| Delete a connector | `DELETE /api/v1/notify/connectors/{id}` |

## Connector types

The type list returns `connectorType`, `capabilities`, and `addresses` for every type that the running backend registers. The types are `email_smtp`, `lark_app`, `lark_webhook`, `slackApp`, `slack_webhook`, and `webhook`.

```json
[
  {
    "connectorType": "slack_app",
    "capabilities": {
      "directUser": true,
      "group": true,
      "richText": true,
      "interactive": true,
      "acknowledgement": false,
      "attachments": false
    },
    "addresses": [
      {
        "field": "apiBaseUrl",
        "picker": "site",
        "choices": [
          { "key": "slack", "url": "https://slack.com/api" },
          { "key": "govslack", "url": "https://slack-gov.com/api" }
        ]
      }
    ]
  }
]
```

`addresses` is the list of the provider addresses a type's `config` keeps. A type whose address a person enters, such as a webhook or SMTP, has none and returns an empty list.

| Field | Meaning |
|---|---|
| `field` | The `config` key, such as `apiBaseUrl`, `serviceUrl`, or `wsUrl`. |
| `choices` | The addresses it can take, each with a `key` and a `url`; the first is the default. |
| `picker` | What one of several addresses is picked by: `site` (platform) or `cloud`. The choice itself is not saved. |
| `byRegion` | The address follows the chosen region (Alibaba Cloud, AWS): `https://{service}.{region}.{one of domains}`. `choices` holds only the address used before a region is chosen. |

Creating, updating, and testing a connector, and sending directly, accept only an address from this list in these keys, or for a regional address the one of the region in `config`; a missing key takes the default. Any other address is refused, so credentials never go elsewhere.

The `config` object of a connector depends on its type. Every `timeoutSecs` defaults to 10 and accepts 1 through 60. URLs must be absolute `http` or `https` URLs, and a provider address must be one listed in the type's `addresses`.

| `connectorType` | `config` keys |
|---|---|
| `email_smtp` | `host` and `from` (required), `port` (default `587`), `username`, `password`, `tls` (`none`, `starttls` by default, or `tls`), `timeoutSecs` |
| `slackApp` | `botToken`, `clientId` and `clientSecret` (a bot token, a client ID and secret, or all three), `apiBaseUrl` (default `https://slack.com/api`, or `https://slack-gov.com/api` for GovSlack), `timeoutSecs` |
| `slack_webhook` | `webhookUrl` (required), `timeoutSecs` |
| `lark_app` | `appId` and `appSecret` (required), `apiBaseUrl` (Feishu's `https://open.feishu.cn/open-apis` by default, or `https://open.larksuite.com/open-apis` for Lark), `receiveIdType` (`open_id` by default, `userId`, `union_id`, `email`, or `chatId`), `timeoutSecs` |
| `lark_webhook` | `webhookUrl` (required), `secret`, `timeoutSecs` |
| `webhook` | `url` (required), `method` (`post` by default, `put`, or `patch`), `headers`, `timeoutSecs` |

[Notification channels](/en-US/notification-channels) explains each provider and its targets.

## Create a connector

```http
POST /api/v1/notify/connectors
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | Yes | Unique within the organization. |
| `connectorType` | string | Yes | One of the types above. The type cannot change later. `type` is accepted as an alias. |
| `config` | object | Yes | The settings of the type. |
| `enabled` | boolean | No | Default `true`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/notify/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "Operations webhook",
    "connectorType": "webhook",
    "config": {
      "url": "https://hooks.example.com/molesignal",
      "method": "post",
      "headers": { "Authorization": "Bearer <token>" },
      "timeoutSecs": 5
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "id": "3KEDlokKjNmves95sRzL8tXpflY",
  "organizationId": "<organization-id>",
  "name": "Operations webhook",
  "connectorType": "webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 5
  },
  "capabilities": {
    "directUser": true,
    "group": true,
    "richText": true,
    "interactive": false,
    "acknowledgement": false,
    "attachments": false
  },
  "enabled": true,
  "status": "unknown",
  "lastTestedAt": null,
  "lastTestStatus": null,
  "lastTestError": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

MoleSignal encrypts the whole `config` at rest. Responses replace the value of every key that holds a credential with `***`. These keys are `url`, `webhookUrl`, `headers`, and every key that ends in `password`, `secret`, or `token`. Other keys, such as `host`, `from`, and `timeoutSecs`, stay readable.

`status` is `unknown` until the first test, then `connected` or `error`. `lastTestStatus` is `success` or `failed`. Routing skips a connector with the status `error` until a later test succeeds.

## List and get connectors

```http
GET /api/v1/notify/connectors
GET /api/v1/notify/connectors/{id}
```

The list returns an array of connectors in the shape above. An unknown `id` answers `404`.

## Update a connector

```http
PUT /api/v1/notify/connectors/{id}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | Yes | The new name. |
| `config` | object | No | The new settings. Omit it to keep the stored configuration. |
| `enabled` | boolean | No | Default `true`. An omitted value enables the connector. |

Send `***` for a masked key to keep the stored secret, or send a new plaintext value to replace it:

```json
{
  "name": "Operations webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 8
  },
  "enabled": true
}
```

## Test a connector

```http
POST /api/v1/notify/connectors/{id}/test
```

Sends one message through the connector. A disabled connector cannot run a test.

| Field | Type | Required | Notes |
|---|---|---|---|
| `targetType` | string | Yes | `directUser`, `fixed_address`, `fixed_group`, or `webhook`. Each connector type accepts a subset, for example `email_smtp` accepts `directUser` and `fixed_address`. |
| `target` | string | Yes | The recipient: an address, a provider identifier, a group, or a URL, depending on `targetType`. |
| `message` | object | No | `title`, `text`, `markdown`, and `html`. The defaults are a generic title and text. |

<ResponseExample>
```json 200
{
  "sent": true,
  "testedAt": 1790000000000000,
  "elapsedMs": 3,
  "providerMessageId": "req-1",
  "error": null
}
```
</ResponseExample>

A delivery failure still answers `200`, with `sent` set to `false` and the reason in `error`, for example `unavailable: webhook request failed`. The test also updates `status`, `lastTestedAt`, `lastTestStatus`, and `lastTestError` of the connector.

## Delete a connector

```http
DELETE /api/v1/notify/connectors/{id}
```

A successful delete answers `204` without a body. While a user endpoint, a notification policy, a fallback route, a scheduled log inspection, a status page, or Mole Agent in IM still references the connector, the call answers `409` with `notify connector is referenced by user endpoints, policies, default routes, scheduled log inspections, status pages, or Mole Agent in IM`. Move the references first.

## Errors

| Status | Cause |
|---|---|
| `400` | The `config` is invalid for the type, the type is unsupported (`unsupported connector type: pagerduty`), the target does not fit the connector, or the connector is disabled. |
| `404` | The connector does not exist. |
| `409` | Another connector in the organization already uses the name, or the connector is still referenced on delete. |
| `422` | A field is missing or a value is invalid, for example an unknown `targetType`. The response is plain text. |
