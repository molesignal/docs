```http
GET /api/v1/alerts/incidents/{id}/rca
POST /api/v1/alerts/incidents/{id}/rca
```

[Mole Agent](/en-US/agent) writes a root cause analysis (RCA) for an incident from the incident context. Each incident has at most one analysis.

The `alert` role creates analyses automatically. Every three minutes, the role writes an analysis for active incidents that have none, up to 20 per pass, when the organization has an enabled model provider with an API key. The `GET` call reads the stored analysis. The `POST` call generates a new analysis immediately and replaces the stored one.

| Call | Permission | Notes |
|---|---|---|
| `GET` | `alerts.incidents.read` | Answers `404` with `no root-cause analysis for this incident yet` until an analysis exists. |
| `POST` | `alerts.incidents.rca` | Waits for the model and returns the new analysis. The optional query parameter `locale` selects the output language, `en-us` or `zh-cn`. The default is the language preference of the calling user. |

<RequestExample>
```bash cURL
curl -X POST "http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/rca?locale=en-us" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**Response**

| Field | Notes |
|---|---|
| `incidentId`, `orgId` | The incident and organization identifiers. |
| `summary` | The analysis, as Markdown text. It cites evidence by label, such as `[E2]`. |
| `evidence` | The labelled evidence the analysis was given, at most 30 pieces. See below. |
| `provider`, `model` | The model provider type, such as `openai`, `anthropic`, or `openai_compatible`, and the model name. |
| `promptBuiltinKey`, `promptHash` | The prompt template and a hash of the rendered prompt, for audit. |
| `promptTokens`, `completionTokens`, `finishReason` | Token usage and the finish reason that the provider reports. |
| `createdAt`, `updatedAt` | Microseconds since the Unix epoch. `updatedAt` changes when the analysis is regenerated. |

**Evidence**

Each piece has `label` (`E1`, `E2`, …), `kind`, `source`, and, when known, `service`, `subject` (what it
is about, without figures), `detail`, `at`, `figures`, and `link`.

| `kind` | `source` | `figures` |
|---|---|---|
| `insight` | `apm` | `value`, `previous`, `lastWeek`, `calls`, `p95Time`; `detail` is the insight kind and the figure that moved, such as `anomaly.p95`. |
| `new_error_group` | `apm` | `occurrences`. |
| `sample_trace` | `traces` | `duration` in microseconds; `link.traceId`. |
| `error_logs` | `logs` | `now` and `lastWeek`, error-level lines in the window and in the same window a week before. |
| `new_log_pattern` | `logs` | `lines`, the pattern's error-level lines in the window, estimated when the window was sampled. `subject` is the pattern and `detail` one of its messages. |
| `attribute_skew` | `traces` | `failedShare` and `otherShare`, the share of the failed requests and of the others with the value; `score`, how far apart the two sets are on the field (0 to 1); `failed`, the failed requests read. `subject` is the field and `detail` the value. |
| `business_impact` | `traces` | `errors` and `requests` of the values whose requests failed, `values`, how many there are, and `important`, how many of them are marked important. `subject` is the key's label and `detail` names up to 3 values. |
| `change`, `similar_incident`, `investigation` | `incident` | None. |

Figures are returned only to callers that hold a permission of their source: `apm.services.read` for
`apm`, `streams.query` for `traces` and `logs`, or `sys.telemetry.read`. For other callers `figures` is
left out and `withheld` is `true`. The same applies to the `POST` response and to Mole Agent's
`get_incident_rca`.

**Errors**

| Status | Cause |
|---|---|
| `400` | The `POST` call found no enabled model provider with an API key for the organization. |
| `403` | The token lacks the permission of the call. |
| `404` | The incident does not exist, or the `GET` call found no analysis yet. |
