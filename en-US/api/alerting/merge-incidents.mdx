title: "Merge incidents"
description: "Merge other active incidents into one main incident."

```http
POST /api/v1/alerts/incidents/{id}/merge
```

Merges the incidents in `source_ids` into the incident `{id}`. Each merged incident records the main one
in `merged_into` and, from then on, sends no notifications, does not escalate, and is left out of
[List incidents](/en-US/api/alerting/list-incidents) and the insights; it stays active, so its rule or
source opens no new incident for it. Resolving the main incident resolves the merged ones; a merged
incident that recovers first is noted on the main incident's
[timeline](/en-US/api/alerting/incident-timeline). Incidents merged earlier into a merged incident move
to the main one. A merge cannot be undone.

The main incident and every merged one must be active and not merged themselves. The main incident's own
ID and repeated IDs in `source_ids` are ignored. The call requires `alerts.incidents.escalate` on the main
incident.

**Body**

| Field | Type | Required | Notes |
|---|---|---|---|
| `source_ids` | array | Yes | 1 to 50 IDs of the incidents to merge in. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/merge \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"source_ids": ["<incident-id>", "<another-incident-id>"]}'
```
</RequestExample>

The response is the main incident. [List incidents](/en-US/api/alerting/list-incidents) describes every field.

**Errors**

| Status | Cause |
|---|---|
| `400` | `source_ids` names no other incident, or more than 50. |
| `403` | The token lacks `alerts.incidents.escalate`, or the incident is out of the token's reach. |
| `404` | The main incident or one of `source_ids` does not exist. |
| `409` | The main incident or one of `source_ids` has recovered or was merged into another, or an incident kept changing while it was being updated; retry. |
