```http
POST /api/v1/alerts/rules/{id}/trigger
```

Opens an incident for a rule without evaluating the condition. Use the call to exercise notifications and escalation, or to raise an incident by hand. The call works for disabled rules. It requires `alerts.rules.manage`, and the body is empty.

- When the rule already has an open or acknowledged incident, the call returns that incident unchanged. Repeating the call is safe.
- Otherwise, the call creates an incident with the status `open` and sends the triggered notification event.
- The severity is the rule `severity`, then a `severity` label, then `warning`. The call ignores `thresholds`.
- The annotation `manual_triggered_by` holds the identifier of the calling user, and `triggering_query.sample_values` is empty.

An enabled rule resolves the incident at the next evaluation when its condition does not match. A disabled rule keeps the incident open until a user resolves it.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/trigger \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

The response is an incident. [List incidents](/en-US/api/alerting/list-incidents) describes every field.

**Errors**

| Status | Cause |
|---|---|
| `403` | The token lacks `alerts.rules.manage`. |
| `404` | The rule does not exist. |
