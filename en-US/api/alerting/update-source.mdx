---
title: "Update an alert source"
description: "Change the name, state, escalation policy, default severity, extra labels and receiving cluster of an alert source."
"zh-Hans_link": "/zh-Hans/api/alerting/update-source"
---

```http
PUT /api/v1/alerts/sources/{id}
```

Writes back the settings of an [alert source](/en-US/alerting/sources) as a whole. It requires `alerts.sources.manage`. The fields are those of [Create an alert source](/en-US/api/alerting/create-source); the kind cannot change, so a `kind` given must be the current one. The token stays; [Rotate a token](/en-US/api/alerting/rotate-source-token) changes it. Without `home_cluster`, the receiving cluster stays. Incidents already open keep their escalation policy and labels.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/sources/$SOURCE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Production Prometheus", "enabled": false, "escalation_policy_id": "default", "severity": "error"}'
```
</RequestExample>

The response is the updated source, without a `token`.

**Errors**

| Status | Cause |
|---|---|
| `400` | A field is wrong, or the kind changed. |
| `403` | The token lacks `alerts.sources.manage`. |
| `404` | The source does not exist. |
