---
title: "Snooze an incident"
description: "Hold an incident's notifications for a while, or end a snooze."
"zh-Hans_link": "/zh-Hans/api/alerting/snooze-incident"
---

```http
POST /api/v1/alerts/incidents/{id}/snooze
DELETE /api/v1/alerts/incidents/{id}/snooze
```

`POST` snoozes an active incident for `durationSecs`. An `open` incident is acknowledged first by the
caller. While it is snoozed, the incident sends no notifications and does not escalate; when
`snoozedUntil` passes, it goes back to `open`, and its assignees receive an escalation notification whose
`escalation.reason` is `snooze_ended`. Snoozing a snoozed incident sets a new end.

`DELETE` ends the snooze at once; the incident stays `acknowledged`. Both calls require
`alerts.incidents.acknowledge`, and `DELETE` has no body.

**Body**

| Field | Type | Required | Notes |
|---|---|---|---|
| `durationSecs` | integer | Yes | 60 (1 minute) to 604800 (7 days). |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/snooze \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"durationSecs": 3600}'
```
</RequestExample>

The response is the updated incident. [List incidents](/en-US/api/alerting/list-incidents) describes every field.

**Errors**

| Status | Cause |
|---|---|
| `400` | `durationSecs` is below 60 or above 604800. |
| `403` | The token lacks `alerts.incidents.acknowledge`, or the incident is out of the token's reach. |
| `404` | The incident does not exist. |
| `409` | The incident has recovered or was merged into another, or it kept changing while it was being updated; retry. |
