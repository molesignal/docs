---
title: "List rules"
description: "List the alert rules of the organization, or read one rule."
"zh-Hans_link": "/zh-Hans/api/alerting/list-rules"
---

```http
GET /api/v1/alerts/rules
GET /api/v1/alerts/rules/{id}
```

The first call returns every alert rule of the organization as an array. The second call returns one rule. Both calls require `alerts.rules.read`.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/rules \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {

    "orgId": "<organization-id>",

    "enabled": true,
    "kind": "scheduled",
    "query": {
      "language": "sql",

```
</ResponseExample>

A rule carries the fields of [Create a rule](/en-US/api/alerting/create-rule) and these read-only fields:

| Field | Notes |
|---|---|
| `id`, `orgId` | The rule and organization identifiers. |
| `createdAt`, `updatedAt` | Microseconds since the Unix epoch. |
| `lastEvalAt` | The time of the latest completed evaluation, in microseconds. `null` until the first one. A query that fails or times out leaves it unchanged. |
| `lastState` | The outcome of that evaluation: `{"kind": "healthy"}` when the condition did not match, `{"kind": "pending", "consecutive": 1}` while it matches for fewer than `forPeriods` evaluations, `{"kind": "firing"}` once it matched long enough, and `{"kind": "dropped"}` when it fired but an [alert pipeline](/en-US/pipelines/alert-events#what-becomes-of-an-event) dropped the incident that it would open. A `firing` rule inside its `silenceSecs` cool-down opens no new incident. |

An unknown `id` answers `404`.
