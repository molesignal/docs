---
title: "List rules"
description: "List the alert rules of the organization, or read one rule."
"zh-Hans_link": "/zh-Hans/api/alerting/list-rules"
---

```http
GET /api/v1/alerts/rules
GET /api/v1/alerts/rules/{id}
```

The first call returns every alert rule of the organization as an array. The second call returns one rule. Both calls require `alerts.read`.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/rules \
  -H "authorization: Bearer $MS_JWT"
```
</RequestExample>

<ResponseExample>

A rule carries the fields of [Create a rule](/en-US/api/alerting/create-rule) and these read-only fields:

| Field | Notes |
|---|---|
| `id`, `org_id` | The rule and organization identifiers. |
| `created_at`, `updated_at` | Microseconds since the Unix epoch. |
| `last_eval_at` | The time of the latest completed evaluation, in microseconds. `null` until the first one. A query that fails or times out leaves it unchanged. |
| `last_state` | The outcome of that evaluation: `{"kind": "healthy"}` when the condition did not match, `{"kind": "pending", "consecutive": 1}` while it matches for fewer than `for_periods` evaluations, and `{"kind": "firing"}` once it matched long enough. A `firing` rule inside its `silence_secs` cool-down opens no new incident. |

An unknown `id` answers `404`.
