---
title: "Set an incident's severity"
description: "Change an incident's severity by hand."
"zh-Hans_link": "/zh-Hans/api/alerting/set-incident-severity"
---

```http
PUT /api/v1/alerts/incidents/{id}/severity
```

Sets the severity of an active incident and records the caller in `severity_set_by`; from then on the
rule's evaluation no longer changes the severity. Raising the severity of an `open` incident starts its
escalation again from the first step that applies to the new severity, with `escalation.reason` set to
`severity_raised`; lowering it, or changing an acknowledged incident, only changes the severity. The call
requires `alerts.incidents.update`.

**Body**

| Field | Type | Required | Notes |
|---|---|---|---|
| `severity` | string | Yes | `info`, `warning`, `error`, or `critical`. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/severity \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"severity": "critical"}'
```
</RequestExample>

The response is the updated incident. [List incidents](/en-US/api/alerting/list-incidents) describes every field.

**Errors**

| Status | Cause |
|---|---|
| `422` | `severity` is missing or not one of the four values. |
| `403` | The token lacks `alerts.incidents.update`, or the incident is out of the token's reach. |
| `404` | The incident does not exist. |
| `409` | The incident has recovered or was merged into another, or it kept changing while it was being updated; retry. |
