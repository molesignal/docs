title: "Resolve an incident"
description: "Mark an incident as resolved."

```http
POST /api/v1/alerts/incidents/{id}/resolve
```

Resolves one `open` or `acknowledged` incident. The call sets the status to `resolved`, records the calling user and the time in `resolved_by` and `resolved_at`, and stops escalation. The call also marks the triggered notification as acknowledged and sends an `alert.resolved` event. It requires `alerts.acknowledge`, and the body is empty.

A rule that still matches opens a new incident at its next evaluation. Resolving an incident does not disable the rule.

<Note>
  Resolving an incident that is already `resolved` or `closed` returns it unchanged. The first user
  and time stay in `resolved_by` and `resolved_at`, and no event is sent again.
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/resolve \
  -H "authorization: Bearer $MS_JWT"
```
</RequestExample>

The response is the updated incident. [List incidents](/en-US/api/alerting/list-incidents) describes every field.

**Errors**

| Status | Cause |
|---|---|
| `403` | The token lacks `alerts.acknowledge`. |
| `404` | The incident does not exist. |
