title: "Update a routing rule"

---

```http
PUT /api/v1/alerts/routing/rules/{id}
```

Writes back a [routing rule](/en-US/alerting/routing#routing-rules) as a whole. It requires `alerts.routing.manage`. The fields are those of [Create a routing rule](/en-US/api/alerting/create-routing-rule); an optional field left out returns to its default. The rule keeps its place; [Reorder routing rules](/en-US/api/alerting/reorder-routing-rules) changes it. Incidents already open are not affected.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "enabled": false, "target": {"kind": "team", "team_id": "<team-id>"}}'
```
</RequestExample>

The response is the updated rule.

**Errors**

| Status | Cause |
|---|---|
| `400` | A field is wrong, or the target team or policy does not exist. |
| `403` | The token lacks `alerts.routing.manage`. |
| `404` | The rule does not exist or belongs to another organization. |
| `422` | `name` or `target` is missing, or a value is not recognized. The response is plain text. |
