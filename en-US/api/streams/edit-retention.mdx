```http
PUT /api/v1/streams/{id}/settings
```

Updates the retention and the settings of a stream. Send only the properties to change. The call requires `streams.configure`, and `audit.read` for the `_audit` stream, which answers `403` without it. On the `_molesignal` system streams it requires `sys.telemetry.manage` and changes only the retention, field indexes, extraction, masking, and downsampling.

**Body**

| Field | Type | Notes |
|---|---|---|
| `retentionDays` | integer or `null` | 1 through 3650 days. `null` clears the explicit value, and the stream inherits the platform default from **Settings → Data retention**. A value outside the range answers `400`. |
| `settings` | object | Stream settings, see below. |
| `fields` | array | Field indexes, see [Configure field indexes](/en-US/api/streams/edit-schema). |

Settings:

| Setting | Notes |
|---|---|
| `description` | Free text shown in the web UI. |
| `queryable` | `false` keeps the stream receiving and retaining data, hides it from query selectors, and makes queries fail with `403` (`stream is not queryable`). |
| `maxQueryRangeHours` | The most hours one SQL or PromQL query of the stream may cover, from 1 to 87600. A query over a longer range answers `400`. `null` removes the limit. |
| `fieldMasking` | Stream-level overrides of the global [field masking](/en-US/settings#data-security) rules. |
| `indexPatterns` | Up to 32 rules that index fields when they first appear, such as `[{ "pattern": "*_id", "indexType": "exact" }]`. `*` stands for any run of text and `?` for one character; the first rule in order whose pattern matches the field's name and whose `indexType` suits its data type applies, after an index set for the field by name. Patterns have 1 to 128 characters and differ. See [Index of new fields](/en-US/streams#index-of-new-fields). |
| `dailyMerge` | Logs and traces only. `true`, the default, merges the files of a finished day into one an hour after the day ends, when together they are no larger than `[compactor].target_size`. Retention then applies by the day. `false` keeps the hourly files. |
| `partitions` | Logs and traces only. Up to two split fields, such as `[{ "field": "service", "type": "hash", "buckets": 4 }, { "field": "pod", "type": "prefix" }]`: `hash` splits by the hash of the value into `buckets` shards (2 to 64), `prefix` by its first character into 37. Data written afterwards is split by these fields; their shard counts multiply to at most 256, and the two fields must differ. A field already in the schema must be an unencrypted `utf8` field. An empty list, the default, means no split. See [Split by field](/en-US/streams#split-by-field). |
| `indexChangedAt` | Read only. When an index type of an existing field last changed; the server sets it, and files indexed before it are indexed again in the background. |
| `downsample` | Metrics only. `{ "afterDays": 7, "intervalSecs": 300 }` rolls samples older than `afterDays` days up into buckets of `intervalSecs` seconds: the samples of a series in one bucket become one point, values averaged and delta counts summed, and the original samples are deleted. `afterDays` is 0 through 3650, `0` turns downsampling off (the default); `intervalSecs` is at least 60 and divides a day evenly. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/streams/$STREAM_ID/settings \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "retentionDays": 30,
    "settings": { "description": "Application logs", "queryable": true }
  }'
```
</RequestExample>

The response is the updated stream. Retention and downsampling control when the compactor removes or rolls up data. A change affects later clean-ups and never restores deleted files or samples.

The platform default for streams without a retention of their own is read with `GET /api/v1/settings/stream_retention` and set with `PUT` and the same body, `{ "retentionDays": 30 }`, both with `sys.settings.retention.manage` in the system scope. `retentionDays` is a whole number from 1 to 3650.

`GET /api/v1/settings/stream_retention/preview?retentionDays=7`, with the same permission and scope, estimates what a shorter default would delete. It reads the file catalog and no data, so the response says `"estimated": true`. `rows`, `storedBytes`, and `earliestAt` total what only this change would remove, `streamCount` counts the streams it reaches, `streams` lists the 100 largest with the same figures and their organization, and `unavailableStreams` counts the streams whose catalog entries could not be read. Streams and datasets with a retention of their own are left out. A `retentionDays` equal to or above the current default answers with zeros. Session replays and profile archives follow the same setting and are not counted.
