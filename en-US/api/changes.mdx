```http
GET    /api/v1/changes
POST   /api/v1/changes
GET    /api/v1/changes/{id}
PUT    /api/v1/changes/{id}
PATCH  /api/v1/changes/{id}
DELETE /api/v1/changes/{id}
```

Changes are kept in one place: deployments, configuration changes, feature flags, scaling, and
infrastructure changes that pipelines report through
[`POST /api/v1/apm/deployments`](/en-US/apm/deployments#report-deployments-from-ci), and annotations
people put on a time range. `GET /api/v1/changes` lists them with the versions APM first saw in spans
and the edits of alert rules. The other calls keep annotations.

## List changes

| Parameter | Notes |
|---|---|
| `from`, `to` | The range in microseconds. `to` defaults to now, `from` to a day before `to`. |
| `services` | Service names, comma-separated. Changes of other services are left out; changes of no service, such as annotations and rule edits, stay. |
| `namespace`, `environment` | Reported changes and versions of this namespace or environment, and reported changes that named none. |
| `kinds` | Comma-separated: `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure`, `annotation`, `version`, `rule`. Every kind the caller may read when left out. |
| `dashboardId`, `stream` | Annotations of this dashboard or log stream, and annotations of none. Annotations of another dashboard or stream are left out. |
| `limit` | At most 500, the default. |

Each kind asks its own permission, and a kind the caller lacks is left out rather than refused:

| Kinds | Permission, any of |
|---|---|
| `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure` | `apm.deployments.read`, `sys.telemetry.read` |
| `annotation` | `dashboards.annotations.read` |
| `version` | `apm.services.read`, `sys.telemetry.read` |
| `rule` | `alerts.rules.read` |

The answer is a list, the latest first. A version a pipeline reported is listed once, as reported.

```json
[
  {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "kind": "deployment",
    "at": 1792316400000000,
    "service": "checkout",
    "namespace": "shop",
    "environment": "prod",
    "version": "2.0.0",
    "status": "succeeded",
    "commit": "9f2c1e7a4b3d5e6f",
    "author": "ada",
    "ciUrl": "https://ci.example.com/runs/7"
  },
  {
    "id": "3KEDP0aZ1y2b3c4d5e6f7g8h9i0",
    "kind": "annotation",
    "at": 1792312800000000,
    "end": 1792314600000000,
    "title": "Load test",
    "tags": ["test"],
    "dashboardId": "dash-1"
  }
]
```

| Field | Notes |
|---|---|
| `at`, `end` | When it happened; `end` closes an annotation over a range. Microseconds. |
| `service`, `namespace`, `environment`, `version` | What a reported change or a version was of. |
| `status` | How a reported change went: `succeeded`, `failed`, or `rolled_back`. |
| `title`, `description`, `tags` | An annotation's or a rule's title, and what a change said of itself. |
| `commit`, `repositoryUrl`, `pullRequestUrl`, `author`, `ciUrl` | Where a reported change came from. |
| `dashboardId`, `stream` | Where an annotation belongs. |
| `ruleId` | The rule an edit was of. |

## Keep annotations

`POST /api/v1/changes` creates an annotation and needs `dashboards.annotations.manage`:

```json
{
  "title": "Load test",
  "description": "k6, 2,000 users",
  "tags": ["test"],
  "timeStart": 1792312800000000,
  "timeEnd": 1792314600000000,
  "dashboardId": "dash-1",
  "streamName": null
}
```

`GET /api/v1/changes/{id}` reads one annotation with `dashboards.annotations.read`. `PUT` and `PATCH`
change the fields they name, and `DELETE` removes it, with `dashboards.annotations.manage`. These calls
reach annotations only; an id that is not one of the organization's annotations answers `404`.
Mole Agent keeps annotations with `create_annotation`, `update_annotation`, and `delete_annotation`, and
lists changes with `list_changes`.
