The CLI signs in once and keeps the sign-in for later commands. Two ways are available:

| Way | Use it for |
|---|---|
| Browser sign-in | A person at a computer with a browser. Uses OAuth 2.1 and renews itself. |
| API token | Scripts, build machines, and computers without a browser. |

## Sign in in the browser

```bash
molesignal login --url https://molesignal.example.com
```

1. The CLI registers itself with MoleSignal and opens the MoleSignal authorization page in the
   default browser. Sign in to MoleSignal there if no session exists yet.
2. The authorization page names the client, the account, and the organization, and lists what the
   access allows. A user in several organizations picks one in **Organization**; the access is
   bound to it.
3. Click **Authorize**. The browser returns to the CLI, which reports the number of tools it can
   use.

The CLI asks for the scopes `mcp` and `offline_access`, so the sign-in renews itself until it is
revoked. The authorization page waits five minutes; after that, the command ends and the earlier
sign-in, if any, stays as it was. A refused or interrupted sign-in also leaves the earlier one in
place.

<Note>
  The browser returns to a listener on `http://127.0.0.1` that exists only while the command runs.
  Nothing listens on the machine after the command ends.
</Note>

## Sign in with an API token

Create a token at **Identity & Access → API tokens**, then pass it on standard input:

```bash
printf '%s' "$MOLESIGNAL_TOKEN" | molesignal login --url https://molesignal.example.com --with-token
```

The token acts with the permissions of the user or service account that owns it.

## Use a token without saving it

Set the address and the token in the environment, as on a build machine. Nothing is saved:

```bash
MOLESIGNAL_URL=https://molesignal.example.com MOLESIGNAL_TOKEN=<token> molesignal status
```

`--url` and `--token` do the same for one command. A token saved for one address is never sent
to another.

## Where the sign-in is kept

The sign-in is saved in `~/.config/molesignal/config.json`, readable by its owner only. The
folder follows `XDG_CONFIG_HOME` when it is set, and `%APPDATA%` on Windows.
`MOLESIGNAL_CONFIG` points to another file.

## Check and end a sign-in

`molesignal status` reports the address, the server that answered, the kind of sign-in, and the
number of MCP tools:

```bash
molesignal status
```

`molesignal logout` forgets the saved sign-in on this machine:

```bash
molesignal logout
```

The grant itself stays in MoleSignal until it is revoked at
**Mole Agent → Settings → Inbound MCP**.
