MoleSignal Enterprise is the commercial, self-hosted option for teams evaluating additional capabilities and support. Start with the open source platform, identify the operational requirements that need a commercial agreement, and confirm the available release and scope before a production commitment.

## Choose a deployment model

| Option | Deployment and operation | Evaluation path |
|---|---|---|
| [Open source](/en-US/editions/open-source) | Operate the Apache 2.0 platform on controlled infrastructure. | Run the quickstart and validate the required workflows. |
| Enterprise | Run a self-hosted deployment with the capabilities and support agreed in an order. | Discuss requirements, release availability, and acceptance criteria. |
| [MoleSignal Cloud](/en-US/editions/cloud) | Planned managed offering, currently on the waitlist. | Register interest and confirm availability before planning a migration. |

Logs, metrics, traces, profiles, alerting, on-call, and Mole Agent are documented in the open source edition. The presence of one of these workflows does not by itself require an Enterprise license. Review the [open source scope](/en-US/editions/open-source) before choosing a commercial option.

## Confirm capability availability

The **Enterprise & Cloud** documentation describes individual capabilities and their edition tags. A page marked **planned** describes a proposal, not a feature available in the installed release. For example, the [Iceberg REST catalog](/en-US/editions/iceberg-rest-catalog) is in design; do not plan a production dependency on it until release availability is confirmed.

For each required capability, record the target version, configuration, permission boundary, operational limitations, and an acceptance test. Confirm these with the evaluation contact instead of inferring availability from a sidebar entry.

## Prepare an evaluation

- Describe daily ingestion volume, peak write rate, retention, signal types, and query concurrency.
- Identify deployment location, network boundaries, object storage, PostgreSQL, and operational ownership.
- List identity, audit, recovery, support, and procurement requirements.
- Select representative queries and incident workflows, including expected latency and recovery objectives.
- Agree on a representative dataset and a repeatable acceptance test. Keep credentials and production data out of an initial contact message.

Run the [Quickstart](/en-US/quickstart) first, then review the [production checklist](/en-US/deployment/production-checklist), [security guide](/en-US/security), and [recovery readiness](/en-US/best-practices/recovery-readiness).

## Licensing and next steps

The [Enterprise License](https://www.molesignal.com/enterprise-license) describes the commercial license framework. The signed order determines the licensed scope, term, usage allowance, and applicable support. Open source components retain their own licenses.

Use [pricing and commercial contact](https://www.molesignal.com/pricing) to discuss the required scope. A documentation page does not replace an order or establish a support commitment.
