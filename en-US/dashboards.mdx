A dashboard is a grid of panels that a team watches together. Each panel runs its own query over the
streams of the workspace and draws the result. Variables above the grid switch every panel to another
service, host, or environment at once.

This page covers finding and using dashboards. To create or change one, see
[Build a dashboard](/en-US/dashboards/edit) and [Variables](/en-US/dashboards/variables).

## The dashboard list

Open **Dashboards**. The head counts the dashboards and folders. Narrow the list with:

- the filter box, which matches names;
- the scopes **All**, **Mine**, **Favorites**, and **Tags**;
- a folder, or **All** folders;
- **Grid** or **List** layout.

The head also has **New dashboard**, **Import JSON**, and **Manage folders**. Select the star of a
dashboard to add it to **Favorites**. The menu at the end of each dashboard has these actions:

| Action | Effect |
|---|---|
| **Open**, **Edit**, **Share** | Opens the dashboard, its editor, or its share dialog. |
| **Move to folder** | Moves the dashboard into another folder. |
| **Create copy** | Creates an editable copy named `<title> copy`. |
| **Export JSON** | Downloads the dashboard model, which **Import JSON** accepts. |
| **Set as NOC display** | Shows this dashboard on the [NOC wallboard](#noc-wallboard) of this browser. |
| **Delete** | Deletes the dashboard and its panels. It cannot be undone. |

## Folders

Folders group dashboards up to three levels deep. Select **Manage folders**, then **New folder** for a
folder at the root or **New subfolder** inside the selected one.

Dashboards without a folder live in the **Default** folder. It cannot be renamed, deleted, or hold
subfolders. A folder can be deleted only after its dashboards and subfolders are moved out.

## Read a dashboard

The head of a dashboard shows its folder, panel count, and last change, and these controls:

| Control | Use |
|---|---|
| Time picker | Sets the time range of every panel. Times show in the personal default timezone; **Change** at the foot of the picker shows another one. |
| **Refresh** | Runs every panel again. The menu beside it sets automatic refresh: **Off**, **Auto**, or an interval. **Auto** adapts the interval to the time range and the panel width. |
| Variables | Choose values for the [variables](/en-US/dashboards/variables). The address keeps them as `var-<name>=<value>`, so a copied link opens the same view. |
| **Share** | Opens the [share dialog](/en-US/resource-sharing). |
| **Edit** | Opens the [editor](/en-US/dashboards/edit). A read-only dashboard offers **Create copy** instead. |
| More | **View dashboard details** with the ID, the UID, the owner, and the schema; **NOC display**; **Create copy**; and **Export JSON**. |

Hover over a panel to see its description. The menu of a panel has:

| Action | Effect |
|---|---|
| **View** | Shows the panel alone, at full size. |
| **Edit** | Opens the panel in the editor. |
| **Explore data** | Opens the query of the panel in its explorer, with the variables filled in and the same time range. |
| **Inspect queries** | Shows the query definitions of the panel as JSON. |
| **Share** | Copies a link to the panel. |
| **Export data** | Downloads the data of the panel as CSV. |
| **Export image** | Downloads a picture of the panel. |
| **Copy** | Copies the JSON of the panel, to paste into another dashboard. |
| Data links | Opens the [data links](/en-US/dashboards/edit#data-links) of the panel. |
| **Create alert** | Opens a new [alert rule](/en-US/alerting/rules) from the query of the panel. |
| **Mole Agent analysis** | Asks [Mole Agent](/en-US/agent) to analyze what the panel shows. |

## Import a dashboard

Select **Import JSON**, then paste MoleSignal Dashboard JSON or upload a `.json` file, choose a folder,
and select **Import**. The JSON is what **Export JSON** downloads, or what
`GET /api/v1/dashboards/{id}` returns as `model`. Its `engine` must be `molesignal-dashboard`.

Grafana dashboard JSON is not accepted. Rebuild such a dashboard in the editor: PromQL expressions can
be pasted into metric panels as they are. To keep a dashboard in Grafana instead, read MoleSignal
through the [Grafana datasource](/en-US/query/grafana).

## Ask Mole Agent for a dashboard

Ask [Mole Agent](/en-US/agent) to draft a dashboard, for example "a dashboard for the checkout
service". Mole Agent prepares a draft without creating anything, and links to **AI Dashboard draft**:

1. Review the **Read-only preview**, which the same renderer draws as a real dashboard.
2. Check **Query preflight**, where each panel query ran once: **Passed**, **Empty result**, or
   **Skipped**, and any **Generation warnings** or **Issues to repair**.
3. Select **Submit creation proposal**. When the creation policy needs reviewers, the draft waits for
   their approval; otherwise select **Confirm and create**.

A draft is bound to its model and expires after a while. Ask again to change it.

## Built-in RUM dashboards

A workspace with RUM applications has read-only dashboards tagged `内置` and `rum`, one for each kind
of application:

| Dashboard | For | Shows |
|---|---|---|
| `RUM · 浏览器应用` | Browser applications | Sessions, sessions without an error, and frustrated sessions; LCP, INP, and CLS at the 75th percentile, each with its trend; errors by source; pages, versions, frustrated elements, and slow hosts; countries and browsers. |
| `RUM · 移动应用` | Android, iOS, Flutter, and React Native applications | Sessions, sessions without a crash or an error, and frustrated sessions; sessions without a crash, errors, and crashes over time; screens, versions, crashes by version, frustrated elements, and slow hosts; devices and operating systems. |

Each dashboard is installed when the first application of its kind is created, and by the server when
it starts, for a workspace that already has one. An upgrade that changes a dashboard is applied the same
way. The variables are **应用** (the application), **环境** (one environment, or **全部** for every
one), and **间隔** (the width of the bars of a chart over time). **Open in dashboard** on the
[RUM overview](/en-US/rum#overview) opens the dashboard with the application and the environment of the
page already chosen.

A panel is a short SQL statement. Views and sessions are read through `rum_views_latest` and
`rum_sessions_latest`, which hold the [newest version](/en-US/query#current-versions-of-rum-rows) of each,
and a percentile counts only the views that have the value: the figures are the ones the overview shows.
The dashboards cannot be edited. Choose **Create copy** in the head of the dashboard, or in the
dashboards list, to get a dashboard that can be changed.

## NOC wallboard

Select **NOC Wallboard** in the top bar to fill the screen with a dark view meant for a wall display.
Press `Esc` or select **Return to console** to leave it.

The status bar sums up the workspace: active incidents and their severities, the state of live data,
the number of services, the request rate, and the P95 latency. The panels show:

| Panel | Shows |
|---|---|
| **Incidents** | The incidents that fire now. |
| **Topology** | The service topology of the last hour. |
| **Health** | Each service with its request rate, P95 latency, and error rate. |
| **Traffic** | The busiest services of the last 60 minutes. |

**Configure layout** changes the wallboard: apply a preset (**Platform Ops**, **SRE**, or
**Executive**), show or hide a panel, make it wide or narrow, move it earlier or later, or **Reset**.
The browser keeps the layout.

When a dashboard is set as the NOC display, the wallboard shows that dashboard instead: its title and
each of its panels with its query. The panels are not drawn as charts on the wallboard; open the
dashboard itself for the charts.

## Reports and sharing

Create a scheduled [report](/en-US/reports) from a dashboard for PDF, PNG, CSV, SVG, or JSON delivery.
Use **Share** for signed-in, cross-workspace, or restricted public access. A public dashboard runs only
the saved queries of its panels and follows the [sharing policy](/en-US/settings/organization#sharing-and-public-access)
of the workspace.

## Permissions

| Permission | Allows |
|---|---|
| `dashboards.read` | Open dashboards and folders. |
| `dashboards.create` | Create, import, and copy dashboards. |
| `dashboards.edit` | Change dashboards and folders. |
| `dashboards.delete` | Delete dashboards. |
| `dashboards.share` | Create and rotate shares. |
