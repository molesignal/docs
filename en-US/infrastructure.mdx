**Infrastructure** lists the places your services run on and ties each to the services, logs, and
metrics that name it. A node that is in trouble leads to every service on its pods; a slow service
instance leads to the pod and node it runs on.

## Where the entities come from

Nothing is configured on this page. Every five minutes the platform reads two sources over the last
15 minutes:

- The instances APM sees in spans, each with the service that ran on it.
- Up to four metric or log streams that have a `host.name`, `k8s.node.name`, or `k8s.pod.name`
  field, reading the resource fields of up to 2,000 distinct places.

The fields follow the OpenTelemetry semantic conventions:

| Kind | Named by | Key |
|---|---|---|
| Cluster | `k8s.cluster.name` | The cluster name. |
| Node | `k8s.node.name` | `cluster/node`. |
| Pod | `k8s.pod.name`, with `k8s.namespace.name` | `cluster/namespace/pod`. |
| Host | `host.name`, outside Kubernetes only | The host name. |
| Container | `container.id`, with `container.name` | The container ID. |

Inside a pod `host.name` usually names the pod, so data that names a pod, node, or cluster makes no
host. A service runs on the innermost place its spans name: its pod, else its host, else its node.
A pod runs on its node, a node is part of its cluster, and a container is part of its pod.

To fill in the Kubernetes fields, add the `k8sattributes` processor to your OpenTelemetry Collector
and set `k8s.cluster.name` with the `resource` processor; the Kubernetes guide on the
**Datasource** page includes both. An entity not seen for a week is forgotten.

## The list

The list shows every entity seen over the last week, the latest seen first. A green dot marks one
seen within the last 30 minutes, which is running now; a grey dot marks one only seen before.
**Services** counts the services that run on it directly. Narrow the list by kind, or search by
name or key; both are kept in the address.

## An entity's page

Open an entity to see:

- **Runs on**: its node and cluster, or the pod a container is part of.
- **Runs here**: the nodes of a cluster, the pods of a node, the containers of a pod.
- **Services**: the services on it, and on what runs on it, each linking to its APM page.
- **Changes to its services**: the latest deployments and other changes of those services over the
  last 24 hours. See [Changes](/en-US/api/changes).
- **Resource attributes**: the fields it was last seen with, each one copyable.

**Logs** opens the logs of a pod or host over the last hour. **Metrics** opens the metrics that carry
its name, by `k8s.cluster.name`, `k8s.node.name`, `k8s.pod.name`, `host.name`, or `container.id`.

The **Workload / host** cell of a service's **Instances** table on its [APM](/en-US/apm) page opens the
pod or host the instance runs on.

## Permissions

The pages and the API need any of `apm.services.read`, `metrics.read`, `logs.read`, or, in the system
scope, `sys.telemetry.read`. Mole Agent reads the same data with `list_entities` and `get_entity`.
