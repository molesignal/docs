Source maps let MoleSignal translate minified JavaScript stack frames into the original file,
function, line, and column from the source tree.

## Match the SDK release

Set `service` and `version` to stable values during each build:

```ts
import { initRum } from '@molesignal/browser-rum';

initRum({
  applicationId: 'checkout-web',
  clientToken: 'ms_your_ingestion_token',
  site: 'https://molesignal.example.com',
  service: 'web-frontend',
  version: '2026.08.04.1',
});
```

Upload the map with the same values:

| Upload field | SDK field | Example |
|---|---|---|
| Service | `service` | `web-frontend` |
| Release | `version` | `2026.08.04.1` |
| File | generated `.map` file | `app.8f312.js.map` |

<Warning>
  A map uploaded under a different service or release cannot symbolicate the event. Keep the SDK
  version and upload release in the same build pipeline variable.
</Warning>

## Upload from the UI

<Steps>
  <Step title="Build with source maps enabled">
    Generate external source maps in the production build. Keep source maps out of the public
    deployment when security policy requires private source code.
  </Step>
  <Step title="Open the upload page">
    Go to **RUM → RUM settings → Source Maps**, then click **Upload Source Map**.
  </Step>
  <Step title="Enter service and release">
    Enter the exact `service` and `version` values configured in the SDK and select the generated
    `.map` file. Each uploaded file can be at most 50 MiB.
  </Step>
  <Step title="Verify symbolication">
    Send an error from the release, open **RUM → Errors**, and confirm the stack displays original
    source locations.
  </Step>
</Steps>

## Upload from CI

Use the authenticated source-map endpoint for automatic release-pipeline uploads:

```bash
curl --fail-with-body \
  -H "Authorization: Bearer ${MOLESIGNAL_TOKEN}" \
  -F "service=web-frontend" \
  -F "release=${RELEASE_VERSION}" \
  -F "file=@dist/assets/app.js.map" \
  "${MOLESIGNAL_SITE}/api/v1/sourcemaps"
```

Use a token scoped to the target workspace. Listing map metadata requires `streams.read`; uploading
or deleting maps requires `streams.configure`.

## Release checklist

- Generate maps from the exact deployed artifacts.
- Set the SDK `version` before any error can be recorded.
- Upload every lazy-loaded chunk map, not only the main bundle map.
- Keep service and release names case-sensitive and identical.
- Verify one controlled error after deployment.
