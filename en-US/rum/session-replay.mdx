Session replay records the browser DOM as a full snapshot followed by timestamped incremental changes.
MoleSignal reconstructs those events in a sandboxed, non-interactive player.

Replay is disabled by default.

## Enable sampled replay

```ts
const rum = init({
  applicationId: 'checkout-web',
  clientToken: 'msrum_your_client_token',
  site: 'https://molesignal.example.com',
  sessionSampleRate: 100,
  sessionReplaySampleRate: 20,
  sessionReplay: {
    blockSelector: '[data-molesignal-block]',
    maskTextSelector: '[data-molesignal-mask]',
    ignoreSelector: '[data-molesignal-ignore]',
  },
});
```

`sessionReplaySampleRate` is evaluated only for sessions included by `sessionSampleRate`. See
[RUM data sampling](/en-US/rum/sampling) for the effective-rate calculation.

## Start or stop recording manually

```ts
rum.startSessionReplayRecording();

// Stop before a sensitive workflow that should never be recorded.
rum.stopSessionReplayRecording();
```

Manual start applies only to a session already selected by `sessionSampleRate`. Starting recording
creates a new full DOM snapshot so the replay can be reconstructed.

## Recorded events

The recorder captures:

- full DOM snapshots and incremental DOM mutations;
- pointer movement and clicks;
- scrolling and viewport changes;
- input interaction with values masked;
- stylesheet state and accessible inline styles;
- media state supported by rrweb.

A periodic full snapshot is recorded every five minutes by default. Configure a value from 30 seconds
through 30 minutes with `checkoutInterval`:

```ts
sessionReplay: {
  checkoutInterval: 5 * 60_000,
},
```

## Privacy controls

With the default `defaultPrivacyLevel: 'mask'`, all page text and everything typed is masked. `mask-user-input` shows the text of the
page and masks what people type. `allow` also shows what people type, but for passwords, e-mail addresses, telephone numbers, and card
or one-time-code fields. Define block, mask, and ignore selectors before enabling production replay.

```html
<div data-molesignal-block>Payment details</div>
<span data-molesignal-mask>Customer name</span>
<canvas data-molesignal-ignore></canvas>
```

Read [RUM privacy](/en-US/rum/privacy) for selector semantics and a production review checklist.

## Optional high-volume capture

The following options are disabled by default because these options can substantially increase payload and
storage size:

```ts
sessionReplay: {
  collectFonts: false,
  inlineImages: false,
  recordCrossOriginIframes: false,
},
```

Cross-origin frame recording also requires cooperation from the framed application. Canvas pixels
are not replayed by the MoleSignal player. Prefer DOM representations or placeholders for canvas-heavy
content.

## Transport and retention

Replay uses a separate queue and defaults to a 10-second flush interval with 100 events per batch.
Use `replayFlushInterval` and `replayBatchSize` to tune client behavior. MoleSignal compresses replay
segments in object storage and expires stored segments after the platform's default stream retention,
set in **Settings → Data retention**.

## Comments

The **Comments** tab beside a replay holds what people have to say about moments of it. A comment is written at the moment the
replay is at, marked on the timeline of the player, and takes the replay back to that moment when you click its row.

Whoever may play the replay reads its comments. `rum.replay.comments.write` writes them and changes or deletes one's own, and
`rum.replay.comments.manage` changes or deletes anyone's. A session holds up to 500 comments of up to 2,000 characters. They are
deleted with the replay when its retention ends.

## AI summary and chapters

**Summarize** on the session page asks a model what happened in the session: a few sentences, and the chapters of the
replay, each with a title and where it begins. The chapters are marked on the timeline of the player, and clicking one takes the
replay there.

The model is told the session as lines, oldest first: the pages, what was done on them, what went wrong, and the requests that
failed or took long. It is not shown the replay. The text has been through what the application [takes out at
intake](/en-US/rum/privacy#take-sensitive-text-out-at-intake) and what the reader may see. A long session is told by its pages and
what went wrong, the rest as far as there is room.

A summary is written only when someone asks, which takes `rum.replay.summaries.generate`, and whoever may play the replay reads it. It uses the first
enabled [model provider](/en-US/agent#set-up-a-model-provider) with a key, and its default model, and counts against the [daily
budget of Mole Agent](/en-US/agent#usage-and-budget), with the origin `replay_summary`. There is one summary a language, kept until the replay goes. **Summarize again** does not call the model when nothing in
the session has changed.

## Verify replay

<Steps>
  <Step title="Record a non-sensitive test journey">
    Navigate through multiple pages, click controls, scroll, and trigger one DOM update.
  </Step>
  <Step title="Open the session">
    Go to **RUM → Explorer**, query `session.has_replay = true` on **Sessions**, and open the newly recorded session.
  </Step>
  <Step title="Check reconstruction and masking">
    Verify the page structure, event timing, progress controls, blocked regions, and masked values.
  </Step>
  <Step title="Check what the session page shows">
    A session shows a replay only after MoleSignal receives a valid full DOM snapshot; until then the session page shows the action timeline.
  </Step>
</Steps>
