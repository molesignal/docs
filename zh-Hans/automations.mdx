自动化每次启动时都把同一个任务交给 Mole Agent：每天早上检查服务健康、调查每个新的严重事件，或在流水线调用时检查一次发布。Mole Agent 像在对话里一样处理它，能用自动化所属范围的工具、技能和知识；每次运行都留成一个对话，能看到这条自动化的人可以打开。运行结束后，结果发到你选的通知渠道；由事件触发的自动化还可以写出事件的 RCA。

## 开始之前

- 在 **Mole Agent → 设置 → 模型与推理** 中至少启用一个 AI 模型，参见 [Mole Agent](/zh-Hans/agent#配置模型服务)。没有启用的模型时，运行会失败并说明原因。
- 确认权限：

| 操作 | 权限 |
|---|---|
| 查看自动化与运行记录，打开某次运行的对话 | `agent.automations.read`，以及范围的规则，参见[归属](#归属) |
| 新建、编辑、启用 | `agent.automations.manage`（默认授予所有者、管理员与编辑者），以及范围的规则 |
| 立即运行 | `agent.automations.run`（默认授予同样的角色），以及范围的规则 |
| 管理 API 令牌 | `agent.automations.tokens`（默认授予同样的角色），以及范围的规则 |
| 停用、删除 | 同上；持有 `agent.manage` 的人能停用、删除看得到的任何自动化 |
| 在表单中选择通知渠道 | `notify.connectors.read`，用于列出通知连接器 |

## 新建自动化

打开 **Mole Agent → 自动化 → 新建自动化**，从空白自动化或模板开始：

| 模板 | 触发 | 做什么 |
|---|---|---|
| **事件自动分析** | 严重级别为错误或严重的新事件 | 用工具调查事件：重新执行触发查询，查看错误日志、链路、APM 与服务拓扑，给出最可能的根因及证据，并写成事件的 RCA。 |
| **每日健康巡检** | 工作日 09:00 | 检查最近 24 小时的错误率、延迟、错误模式与未关闭的事件，说明哪些需要关注。 |
| **告警降噪周报** | 每周一 10:00 | 找出上周触发最多、反复开关或没人处理的告警规则，并逐条给出调整建议。 |
| **值班负载周报** | 每周一 10:30 | 汇总每个人与每个值班表收到的事件、夜间告警与响应时间，并建议如何减轻负载。 |
| **变更影响检查** | API 调用 | 对比一次发布改动的服务在发布前后的表现，判断它是否带来了退化。 |

表单包含以下字段：

| 字段 | 说明 |
|---|---|
| **名称** | 在组织内唯一。 |
| **要做什么** | 任务，最长 8000 个字符。每次运行时交给 Mole Agent，就像在一个新对话里提问。 |
| **说明** | 一句话说明这条自动化的用途。 |
| **归属** | 新建时选择的范围：你自己、你所在的某个团队，或组织。 |
| **触发方式** | 定时、新事件、API 调用或手动，参见[触发方式](#触发方式)。 |
| **时间上限** | 5 到 60 分钟，默认 10 分钟。超过上限的运行会被停下，记为失败。 |
| **启用** | 停用的自动化只在有人点击立即运行时运行。 |
| **通知渠道** | 最多五个通知连接器上的固定地址或固定群组。阿里云短信与语音只发审核过的模板，不在可选之列。 |
| **把结论写成事件的 RCA** | 用于由事件触发的自动化。 |

一个组织最多有 50 条自动化。行菜单中的 **克隆** 会在表单里打开一份停用状态的副本，可以改个名字或换个范围保存。

### 归属

范围决定一次运行能用到什么，以及谁能看到这条自动化。范围创建后不能修改，要换范围请克隆。

| 范围 | 运行时可用 | 谁能看到 |
|---|---|---|
| 个人 | 组织与你自己的技能和 MCP 服务器、组织的知识，以及你的记忆 | 你，以及持有 `agent.manage` 的人 |
| 团队 | 组织与这个团队的资源和知识，以及团队的记忆 | 团队成员，以及持有 `agent.manage` 的人 |
| 组织 | 只有组织的资源和知识，运行不会写入记忆 | 所有持有 `agent.automations.read` 的人 |

组织范围的自动化由事件触发时，运行使用事件所属的团队：从事件的升级策略推出，取它通知的第一个团队，否则取第一个值班表的团队。推不出时，运行仍在组织范围内进行。

### 执行身份

自动化以最后一次保存它的人的身份运行：每次运行时重新读取这个人的权限，并在需要成员凭据的 MCP 服务器上使用这个人自己的凭据。保存即让你成为执行身份，表单会写明这一点。用 API Token 保存会被拒绝，因为 Token 代表它绑定的角色，而不是创建它的人。

执行身份不能再在组织里使用 Mole Agent 时，每次运行都会失败并写明原因，直到有权限的人重新保存这条自动化。

## 触发方式

| 触发方式 | 何时运行 |
|---|---|
| **定时** | 按 Cron 表达式在一个时区里的时间运行。表达式为五段：分、时、日、月、星期，最短 15 分钟一次。星期中 0 和 7 都表示周日。日和星期只能限定其中一个。上一次运行还没结束时，下一次会跳过。 |
| **新事件** | 自动化保存或启用之后创建、且满足所有已填写筛选条件的每个事件：严重级别、告警规则、受影响的服务，以及值相等的标签。同一个事件只分析一次；同一组事件（告警规则与标签都相同）在 30 分钟内只分析一次。 |
| **新的自动发现** | 自动化保存或启用之后出现、且满足所有已填写筛选条件的每条[自动发现](/zh-Hans/alerting/discovery)：种类、最低严重度，以及服务、主机或容器。同一条发现只调查一次。 |
| **API 调用** | 外部系统带着令牌调用时运行，参见[从 CI/CD 启动](#从-ci/cd-启动)。 |
| **手动** | 只在有人运行时运行。 |

行中的 **立即运行** 以执行身份启动任何一条自动化，无论是否启用，每分钟最多一次。

## 运行记录

行中的 **运行记录** 按时间倒序列出最近 100 次运行：结果与原因、触发方式、回答的开头、没有送达的渠道，以及 **查看运行过程**，即保存完整过程的对话。这个对话不在对话列表中，也不能继续提问；要再来一次，就再运行这条自动化。

运行期间没有人能回答。Mole Agent 提问时会按自己的判断继续；需要人确认的工具不会执行；需要执行身份自己凭据、而凭据还没保存的 MCP 服务器不会被使用。Mole Agent 会在回答里说明这些情况，这次运行标为需要有人处理。

| 状态 | 含义 |
|---|---|
| **运行中** | Mole Agent 正在处理。 |
| **成功** | 已经回答，通知和 RCA 都已发出或写入。 |
| **部分完成** | 已经回答，但有通知没有发出，或 RCA 没有写成。 |
| **需要有人处理** | 已经回答，但途中需要回答问题、确认操作或补充凭据，没有人能处理。 |
| **失败** | 没有回答：模型或工具出错、超过时间上限、没有启用的模型，或执行身份已不能使用 Mole Agent。 |
| **已跳过** | 没有开始：组织今天的 token 预算已用完、上一次运行还没结束，或同一事件刚分析过。 |
| **已停止** | 被人停下，或执行它的服务器停了。 |

运行中的模型调用计入组织的每日 token 预算，在用量的来源分布中显示为 **自动化**。

## 通知与事件的 RCA

运行成功、需要有人处理或失败时，会向每个渠道发送一条通知：自动化的名称与运行结果、回答的开头、原因，以及运行链接。通知使用最后保存这条自动化的人的语言，和其他通知一样记入投递记录。

由事件触发、并打开了 **把结论写成事件的 RCA** 的自动化，会把 Mole Agent 的回答写成事件的 RCA，显示在事件页上。有人从对话里写入的 RCA 会保留。组织启用了这样的自动化时，内置的 RCA 生成不再处理这个组织的事件，同一个事件不会分析两遍。**事件自动分析** 模板就是这样设置的。

## 从 CI/CD 启动

对于由 API 调用触发的自动化，在行菜单中打开 **API 令牌**，选择 **生成令牌**。令牌只显示一次；生成新令牌会立即替换旧令牌，**收回令牌** 会删除它。

在发布时带上令牌调用，并在 `text` 中描述这次变更：

```bash
curl -X POST "https://molesignal.example.com/api/v1/public/automations/<automation-id>/trigger" \
  -H "Authorization: Bearer msauto_..." \
  -H "Content-Type: application/json" \
  -d '{"text": "Deployed checkout-api v42 at 14:05"}'
```

`text` 可选，最长 8000 个字符。Mole Agent 把它当作这次运行的资料，而不是指令。成功时返回 `202`，包含 `run_id`、`status` 与 `chat_url`。令牌错误或自动化不存在时返回 `401`；自动化已停用或不是由 API 调用触发时返回 `409`；10 秒内再次调用返回 `429`。

## 回顾 Mole Agent 的使用情况

`/insight [天数]` 是一个内置技能，回顾对话所属范围内最近 30 天（或你给出的天数）Mole Agent 的使用情况：问了什么、回答与自动化的结果、哪些回答被评为没帮助及原因、哪些工具常出错，以及用到了哪些技能。最后给出至多五项值得做的改动，例如该写的知识文件或该修的自动化。它不会修改任何内容。团队对话回顾本团队，个人对话回顾你和你所在的团队。可以在对话中使用，也可以作为每周自动化的任务。
