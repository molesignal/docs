平台设置位于受保护的 `_sys` 组织中。用工作区切换器切换到 `_sys`；超级管理员和被授予平台角色的账号可以进入。这些页面出现在 `_sys` 的 **设置** 中，查看页面需要对应分组的 `.read` 权限，修改需要 `.manage` 权限，每个页面都需要平台权限。

| 分区 | 分组 | 权限 |
|---|---|---|
| **组织管理** | 平台 | `sys.organizations.read` |
| **登录限速** | 平台 | `sys.settings.signin.manage` |
| **客户端 IP 识别** | 数据面 | `sys.settings.signin.manage` |
| **数据保留** | 数据面 | `sys.settings.retention.manage` |
| **指标基数** | 数据面 | `sys.settings.limits.manage` |
| **接入用量** | 数据面 | `sys.settings.limits.manage` |
| **审计保留** | 数据安全 | `sys.settings.retention.manage` |

各节点从数据库读取这些设置，修改后无需重启。

## 组织管理

**组织管理** 列出实例中的租户组织，包括名称、标识、状态和 ID。

| 操作 | 效果 |
|---|---|
| **创建组织** | 用 **名称** 和 **标识** 创建租户组织。标识之后不能修改。 |
| 停用 | 立即暂停对该组织的访问：重新启用前，它的会话和 API 凭证都会被拒绝。 |
| 启用 | 恢复该组织成员和凭证的访问。 |
| 删除 | 永久删除该组织。 |

必须至少保留一个启用中的租户组织，`_sys` 组织本身不能修改。组织的成员在它自己的[身份与访问](/zh-Hans/identity/members)中管理：先在[组织](/zh-Hans/identity/teams#组织)中点击 **管理 IAM**。

## 登录限速

**登录限速** 挡住撞库和暴力破解，又不让别人靠输错密码把账号锁在外面。它计算核对账号密码的失败次数，覆盖密码登录、LDAP 登录、数据库客户端的账号登录、[关联已有账号](/zh-Hans/identity/sso)时的密码确认，以及[添加第二因素](/zh-Hans/identity/mfa)前的密码确认。[公开链接](/zh-Hans/resource-sharing#访问密码的限制)的访问密码也计数，一个链接算一个账号。Passkey 和 OIDC、OAuth 2.0、SAML 单点登录不计数，也不受限。

| 设置 | 默认值 | 到限之后 |
|---|---|---|
| **同一地址、同一账号** | 5 次 | 这个地址对这个账号锁定，其他地址不受影响。 |
| **同一地址、任何账号** | 30 次 | 这个地址不能再用密码登录，共用这个地址的人也会受影响。 |
| **同一账号、所有地址** | 20 次 | 这个账号不锁定，开始限速。最近 30 天在某个地址登录成功过的，从这个地址登录不受限速。连续一个计数时长没有新的失败才清零。 |
| **限速期间，隔多久核对一次密码** | 60 秒 | 范围 1 到 600 秒。 |
| **锁定和计数的时长** | 15 分钟 | 地址锁多久，失败次数往回算多久。范围 1 到 1440 分钟。 |

次数填 `0` 关掉这一项，范围 0 到 100000。修改后立即生效，并以 `signin_limits.update` 记录到平台审计中。

| 情况 | 结果 |
|---|---|
| 被拒绝的请求 | 回答 `429` 和 `Retry-After`，不核对密码，也不延长任何锁，所以锁定最长就是设定的时长。 |
| 账号不存在 | 和账号存在时一样计数、一样回答，回答不会说出账号是否存在。 |
| 密码正确 | 清掉这个地址对这个账号的失败次数。地址和账号的计数只退回这一次，不清零。 |
| 服务不可用（例如目录服务连不上） | 不算失败。 |
| 刚好到限 | 以 `signin.lockout` 记录到平台审计中，带地址和到限的是哪一项。账号存在时才记账号。 |
| 重置密码成功 | 立即解开这个账号，这个地址不再受账号限速。 |
| 公开链接的访问密码 | 一个链接算一个账号，最近 30 天在某个地址打开过这个链接的，从这个地址访问不受限速。输错访问密码和登录失败一起计入 **同一地址、任何账号**，到限后这个地址也不能再用密码登录。 |
| 公开链接刚好到限 | 以 `resource_share.lockout` 记录到链接所属工作区的审计中，带链接、地址和到限的是哪一项。**同一地址、任何账号** 到限时，还会以 `signin.lockout` 记录到平台审计中。 |

这几项按[客户端 IP 识别](#客户端-ip-识别)取地址，IPv6 按 /64 计数。私有地址默认不算地址：部署在代理之后又没有配置时，所有人都是代理的地址，按它计数的话，任何人输错几次都能把所有人锁在外面。这时只有 **同一账号、所有地址** 生效。用户确实从内网连接时，打开 **私有地址也算客户端**。

页面上的 **你现在的地址** 显示这次请求被认成什么地址、是否计数。请求带着转发 Header、地址却取的是连接地址时会给出提醒，说明前面可能有没配置的代理。

确实需要提前解开时，在元数据库执行 `DELETE FROM signin_attempts` 清掉所有计数。

## 客户端 IP 识别

用户体验接入会记录每个浏览器或设备的地址，并据此查出国家、行政区和城市；[登录限速](#登录限速)按地址计算失败次数；[公开链接](/zh-Hans/resource-sharing#审计与权限)的审计记下访问者的地址。**客户端 IP 识别** 决定从哪里取得这个地址，它作用于所有组织。

| **地址来源** | 适用场景 |
|---|---|
| **直接连接地址** | 默认值。使用 TCP 对端地址，忽略所有转发 Header。接入端点直接对外暴露时使用。 |
| **单值 Header** | 从 CDN 或代理设置的 Header（例如 `CF-Connecting-IP`）读取一个裸 IP。 |
| **转发 IP 链** | 从右向左遍历 `X-Forwarded-For` 这类 IP 链，跳过可信代理，取第一个不可信地址。**最大链长度** 限制单个请求最多读取的地址数，范围 1 到 64。 |

位于代理之后时，还需要设置：

| 字段 | 规则 |
|---|---|
| **客户端 IP Header** | 要读取的 Header。`Authorization`、`Cookie`、API Key 和客户端证书 Header 会被拒绝。 |
| **可信代理 CIDR** | 每行一个 IPv4 或 IPv6 CIDR，最多 64 个。只有对端位于这些网络中的连接才会读取 Header。`/0` 网络会信任该地址族的所有来源，只应在受保护的入口之后使用。 |
| **回退到连接地址** | Header 缺失、格式错误、超长或没有可用地址时，使用 TCP 对端地址。 |

**私有地址也算客户端** 在任何地址来源下都可以设置。打开后接受可信 Header 中的私网、loopback 和链路本地地址，[登录限速](#登录限速)也按这些地址计数。用户从内网连接时打开；前面有代理又没有在这里配置时保持关闭，否则所有人都算成同一个地址。

## 数据保留

**数据保留** 设置没有单独保留期的数据流保留多少天：默认 30 天，范围 1 到 3650。每个数据流都可以在[数据流](/zh-Hans/streams#保留与删除)中设置自己的保留期。超过保留期的数据会在下一次清理时删除，无法恢复。

输入更短的保留期时，页面根据文件目录估算这次修改会删除什么：每个数据流的行数、大小和最早数据，最大的排在前面。保存时要求确认；达到 1 GiB 或一百万行，或者无法估算时，还要再输入一遍保留天数。保留期变长时不会询问。会话回放和 Profile 归档也按这个设置清理，没有计入。

同一页的 **拨测结果** 设置拨测的运行结果保留多少天：默认 30 天，范围 0 到 3650，0 表示永久保留。更早的运行结果、它们的附件和已结束的任务每天清理一次；某个地点正显示为最新的结果、修订赖以发布的测试结果会保留下来。可用率读取的 `_synthetic_results` 数据流按数据流自己的保留期保留，见[拨测](/zh-Hans/synthetics#结果数据流与保留期)。

## 指标基数

**指标基数** 限制同时保持活跃的 Prometheus series 数，避免取值很多的标签耗尽内存与存储。

| 上限 | 默认值 | 含义 |
|---|---|---|
| **每个组织** | 200,000 | 一个组织的活跃 series 数。 |
| **每个指标** | 100,000 | 组织中一个指标的活跃 series 数，不超过每个组织的上限。 |

达到上限后，新 series 的写入会被拒绝，已有 series 照常写入。一段时间没有数据的 series 不再算作活跃。各节点每 30 秒重新读取一次上限。可以用[指标](/zh-Hans/metrics)的基数视图找出产生大量 series 的标签。

## 接入用量

**接入用量** 设置[每个来源的接入记录](/zh-Hans/streams#接入用量与预算)保留多久，以及分别统计多少个服务。

| 字段 | 默认值 | 含义 |
|---|---|---|
| **记录保留** | 90 天 | 早于这个天数的小时记录每天清理一次。范围 35 到 3650 天：至少 35 天，这样按月的预算总能读全。 |
| **每组织服务数** | 1000 | 每个节点上，一个组织每小时最多分别统计多少个服务。范围 1 到 100000。超出的合并计入 **其他服务**，防止发送方靠服务名把记录撑大。 |

## 审计保留

**审计保留** 设置所有组织和平台的审计记录保留多少天：默认 90 天，范围 0 到 3650，`0` 表示永久保留。更早的记录每天清理一次，删除后无法恢复。每次修改都会以 `audit_retention.update` 记录到平台审计中。

输入更短的保留期时，页面统计这次修改会删除多少条记录。保存时要求确认；达到 1,000 条，或者无法统计时，还要再输入一遍保留天数。
