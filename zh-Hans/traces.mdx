打开**链路**，在单个 span、完整 trace、服务图和服务目录之间切换。

## 浏览 span 与 trace

已知操作、服务、状态或属性时使用 **Spans**；希望每个请求只显示一行，并查看耗时、
span 数和错误数时使用 **Traces**。

查询编辑器支持字段过滤以及面向 trace 流的 SQL。常见字段包括：

- `trace_id`、`span_id`、`parent_span_id`；
- `service.name` 与操作名；
- 耗时和状态；
- 部署、主机、HTTP、RPC、数据库和对象存储属性。

## 检查单条 trace

选择结果进入 trace 详情。树结构会显示父子关系、关键耗时、错误、Event、Link 和受限属性。

你可以：

- 找到最慢或失败的 span；
- 区分当前服务耗时与下游耗时；
- 打开携带相同 `trace_id` 的日志；
- 比较选定窗口中的服务和操作行为；
- 在继续调查时保留请求与会话上下文。

如果浏览器 RUM 会话带有 session 标识，可以打开**会话链路**查看相关后端请求。

## 服务图与服务目录

**服务图**从 trace span 自动派生节点与边，展示请求率、错误率与延迟关系，无需单独维护
拓扑。

**服务目录**按观察到的服务与操作聚合，便于从服务进入当前 trace。

## 接入与传播

通过 OTLP HTTP 或外部 OTLP gRPC Receiver 发送 trace。MoleSignal 保留标准 W3C Trace
Context 和 OpenTelemetry 语义属性。受支持的应用请求会在响应中返回
`X-Request-Id` 与 `X-Trace-Id`。

## 权限

组织工作区需要 `streams.query`。平台管理员在受保护的 `_sys` 遥测作用域中使用
`sys.telemetry.read`。
