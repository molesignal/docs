打开**链路**，在完整 trace、单个 span、RED 下钻和服务图之间切换。

## 浏览 trace 与 span

**链路**标签页每个请求一行：结束状态（根 span 的 HTTP 状态码，或**正常**、**错误**）、开始时间、服务与操作、相对本页最长 trace 的耗时、span 数、错误数和 trace ID。点击**开始时间**、**耗时**、**Span 数**或**错误**列标题按该列排序。表格上方的直方图统计查询匹配的全部 trace，旁边的图表绘制这些 trace 耗时的 p50、p95 和 p99。

**Span** 标签页每个匹配的 span 一行，带有 span 种类和自身耗时。在这里，对 span 字段的过滤条件针对 span 本身。

查询编辑器有 **代码** 和 **构造器** 两种模式。**代码** 模式接受字段查询（例如 `status_code = 'ERROR'`，或表示耗时超过 500 毫秒的 `duration_ns > 500000000`），也接受面向 trace 流的 SQL；**构造器** 模式把字段查询显示为多行筛选条件，每个分支一行。与[日志](/zh-Hans/logs#查询标签页)一样，查询在标签页中运行并可以分成两栏并排，字段列表可以打开字段分析，**分享** 可以复制查询的链接。地址栏同样带有已应用的查询，复制地址即可分享（参见[分享查询](/zh-Hans/logs#分享查询)）。

对 span 字段的比较会保留含有匹配 span 的 trace；`!=` 保留所有 span 都不含该值的 trace。`trace_id`、`duration_ns`、`span_count` 和 `error_count` 直接在 trace 上比较。`in` 匹配多个值中的任意一个：`service.name in ('checkout', 'payments')`。

与[日志](/zh-Hans/logs#编写查询)一样，比较可以用 `AND` 和 `OR` 连接，`AND` 优先，括号可以分组。比较在 `OR` 中含义不变：`service.name = 'checkout' OR span_count > 50` 保留含有 `checkout` span 的 trace，以及 span 数超过 50 的 trace。不带字段的文本（例如 `timeout`）在 trace ID、span ID、服务、操作和状态中查找。**Span** 标签页和 RED 下钻按单个 span 解读同一条查询：span 匹配 `a` 或 `b` 即匹配 `a OR b`。

字段列表与结果并排。**常用字段**排在最前：`service.name`、`name`、`status_code`、HTTP 状态码和 `duration_ns`。展开字段可以看到已加载 trace 中的取值。**只看这个值**把该值加入查询（含有多个分支的查询会先加上括号，使该值作用于整条查询）；同一字段再选第二个值时，会与第一个值合并为 `in` 列表，因此可以勾选多个值。**排除这个值**排除该值。

**链路**表格上方的**列设置**可以显示、隐藏和调整列的顺序，也可以把每条 trace 根 span 的字段添加为列；字段列表里这类字段的眼睛图标作用相同。列的安排按数据流为每个用户保存，**恢复默认**可以回到表格的默认列。

## 检查单条 trace

点击一行，trace 在列表上方的抽屉中打开。拖动抽屉左边缘可以调整宽度，宽度会保留给下一条 trace。按 **J** 和 **K** 切换到列表中的下一条和上一条 trace，抽屉也可以打开该 trace 的详情页。

trace 的头部固定显示：根服务与操作、HTTP 状态码、错误数、耗时、开始时间、span 数、服务数、深度和 trace ID。**相关日志** 和 **服务指标** 打开该 trace 前后的对应信号。**Profiles** 打开记录了该 trace ID 的 profile；没有这样的 profile 时，打开该 trace 前后几分钟内的 profile。**用户会话** 打开该 trace 所服务的 [RUM](/zh-Hans/rum) 会话：span 在 `session.id` 或 `session_id` 中写明的会话；没有写明时，是浏览器请求在 `traceparent` 中携带该 trace ID 的会话。

头部末尾的 **下载链路** 把 trace 保存为文件：

| 格式 | 内容 |
|---|---|
| **JSON** | span 按[链路接口](/zh-Hans/api/web/trace#读取单条链路)返回的原样保存。 |
| **OTLP JSON** | OTLP/JSON 导出请求，结构为 `resourceSpans` → `scopeSpans` → `spans`，可以重新交给 Collector 或 OTLP HTTP 接入。时间是以十进制字符串表示的纳秒。 |

四种视图展示 span：

| 视图 | 展示内容 |
|---|---|
| **瀑布图** | 时间轴上的 span 树，每个服务一种颜色。上方的缩略图可以拖选一段时间放大时间轴。搜索可以逐个跳到匹配的 span，开关可以只看失败的 span，也可以聚焦某个 span 及其下游。 |
| **火焰图** | 每个 span 是调用方下方的一块。双击可以把时间轴放大到该 span。 |
| **Span 列表** | 按服务和操作分组的 span，带有数量、错误、耗时、自身耗时和占 trace 自身耗时的比例。 |
| **服务地图** | 该 trace 涉及的服务及其相互调用，带有调用次数、耗时和失败数。 |

瀑布图和火焰图工具栏中的 **关键路径** 画出 trace 端到端耗时所等待的 span。关键路径从根 span 的结束时刻开始向前回溯：每个时刻沿着在此之前最晚结束的子 span 走（子 span 按调用它的 span 截断），再从这个子 span 的开始时刻继续回溯。在那个时刻仍在运行的子 span 与路径上的子 span 并行，不在关键路径上。没有子 span 覆盖的时间算作调用方自身的时间。在瀑布图中，每个条形上的一条线标出该 span 位于关键路径上的时段，其他 span 变淡。图例给出关键路径的长度和每个服务所占的比例。开关打开后，切换到其他 trace 时保持打开。

选中 span 的详情显示在视图旁边，宽度可以拖动调整。详情有 **属性**、**资源**、**事件**、**链接**、**日志**、**指标** 和 **性能分析** 标签页。**链接** 还会列出其他 trace 中链接到该 span 的 span。**日志** 显示携带该 trace ID 的日志，范围可以是该 span 或整条 trace。**指标** 绘制该 span 所属服务与操作在前后几分钟内的请求数、错误数和 p95 耗时。

**性能分析** 展示该 span 运行期间 profiler 采到的样本。profiler 记录样本时带上链路上下文（例如 [OTLP Profiles](/zh-Hans/profiles)），样本才会关联到 span。有关联样本时，标签页按自身消耗列出某一种 profile 类型中消耗最多的函数，**打开火焰图** 绘制这些样本，**在 Profiles 中打开** 在 Profiles 页面打开它们。瀑布图中带火焰标记的行表示该 span 有关联样本。没有关联样本时，**查看此 span 前后的 profile** 打开该 span 前后几分钟内的 profile。

每条 trace 也有自己的详情页，打开 trace 链接时进入。如果浏览器 RUM 会话带有 session 标识，可以打开**会话链路** 查看相关后端请求。

## 对比两条 trace

点击**链路**表格上方的 **挑选两条链路进行对比**，再点击两行。先挑选的 trace 是 **A**，后挑选的是 **B**。点击 **对比**，在 A 的详情页打开对比。在 trace 头部，**与另一条链路对比** 接受另一条 trace 的 trace ID。

对比页并列显示两条 trace、各自的耗时，以及 B 比 A 慢或快多少。下面有三个标签页，都把变化最大的排在最前：

| 标签页 | 展示内容 |
|---|---|
| **按服务** | 每个服务在 A 和 B 中的 span 数与自身耗时，以及从 A 到 B 的变化。 |
| **按操作** | 每个服务的每个操作的同样内容。 |
| **仅一侧有** | 一条 trace 有而另一条没有的调用。span 按其上方各 span 的服务与操作匹配，因此从两个地方发出的同一个查询算作两个调用。缺少的调用把它下方调用的 span 计入自身。 |

自身耗时是 span 自己干活的时间，不含等待它调用的 span 的时间。页面头部有 **交换 A 和 B** 和 **结束对比**，页面地址保留两条 trace，因此可以分享对比结果。

## 服务图与服务目录

**服务图**从 trace span 自动派生节点与边，展示请求率、错误率与延迟关系，无需单独维护拓扑。

**服务目录**按观察到的服务与操作聚合，便于从服务进入当前 trace。

## 接入与传播

通过 OTLP HTTP 或外部 OTLP gRPC Receiver 发送 trace。MoleSignal 保留标准 W3C Trace Context 和 OpenTelemetry 语义属性。受支持的应用请求会在响应中返回 `X-Request-Id` 与 `X-Trace-Id`。

流上的[实时流水线](/zh-Hans/pipelines#链路)在尾部采样之后、写入之前改动或丢弃 span。trace 列表及其中的 span 数、出错数按写下的 span 显示。

## 权限

组织工作区需要 `traces.read`。平台管理员在受保护的 `_sys` 遥测作用域中使用 `sys.telemetry.read`。
