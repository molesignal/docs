规则说明什么不该发生。MoleSignal 按间隔评估规则，条件成立时开启[事件](/zh-Hans/alerting/incidents)。打开 **告警 → 规则**。读取规则需要 `alerts.rules.read`，创建或修改规则需要 `alerts.rules.manage`。

## 规则类型

| 类型 | 评估对象 | 创建位置 |
|---|---|---|
| **阈值规则** | SQL 或 PromQL 查询、[APM 指标](/zh-Hans/apm#按-apm-指标告警)或 [RUM 指标](/zh-Hans/rum/alerts)，按间隔与固定阈值比较。 | 规则工作台。 |
| **预测规则** | 查询、APM 指标或 RUM 指标的走势，预计在提前量之内越过阈值就触发。参见[预测规则](#预测规则)。 | 规则工作台的 **判定方式**。 |
| **离群规则** | 按维度拆分的查询，各组相互比较，明显偏离其余组的组触发。参见[离群规则](#离群规则)。 | 规则工作台的 **判定方式**。 |
| **组合规则** | 别的规则有没有进行中的事件，用与、或、非组合。参见[组合规则](#组合规则)。 | 规则工作台的 **判定方式**。 |
| **心跳规则** | 定时任务、备份脚本这类作业有没有按时打卡。参见[心跳规则](#心跳规则)。 | 规则工作台的 **判定方式**。 |
| **异常检测** | 查询、APM 指标或 RUM 指标，与根据其历史学到的基线比较。 | 异常规则编辑器。 |
| **实时规则** | 在接入路径上对到达的记录计数。 | 仅 API。参见[实时规则](#实时规则)。 |

## 规则列表

**规则** 列出每条规则的数据源、触发条件、状态和最近评估时间。可以按规则、服务或数据源搜索，并在 **全部**、**已启用** 和 **已停用** 之间切换。

| 状态 | 含义 |
|---|---|
| **尚未评估** | 规则还没有运行过。 |
| **正常** | 最近一次评估没有满足条件。 |
| **等待持续** | 条件已成立，但持续时间还不够。 |
| **触发中** | 规则有打开的事件。 |
| **被流水线丢弃** | 规则已触发，但要开的事件被[告警流水线](/zh-Hans/pipelines/alert-events#处理结果)丢弃了。 |
| **已停用** | 规则保存为草稿，不会运行。 |

点击规则，或点击行中的 **编辑**，即可打开规则。

## 创建阈值规则

点击 **新建规则 → 阈值规则** 打开规则工作台。

<Steps>
  <Step title="选择规则类型">
    选择 **指标告警**、**日志告警**、**链路告警**、**APM 告警** 或 **RUM 告警**。**快速开始** 中的预设会填入典型查询，例如 **错误率过高**、**P95 延迟过高**、**错误日志激增** 或 **无数据告警**。APM 告警和 RUM 告警选择服务或应用以及一项指标，而不是写查询；参见[按 APM 指标告警](/zh-Hans/apm#按-apm-指标告警)与 [RUM 告警](/zh-Hans/rum/alerts)。
  </Step>
  <Step title="填写基本信息">
    **规则名称** 用作事件标题，例如 `api_high_error_rate`。**服务** 把规则关联到某个服务，用于归属和跨信号上下文。**说明** 描述规则保护的内容。
  </Step>
  <Step title="选择判定方式">
    在 **查询与触发条件** 顶部选择 **判定方式**：**阈值**（默认）、[**预测**](#预测规则)、[**离群**](#离群规则)、[**组合**](#组合规则)或[**心跳**](#心跳规则)。组合和心跳不写查询，下面的查询、测试和阈值换成各自的设置。
  </Step>
  <Step title="编写查询">
    设置 **目标数据流**、**评估间隔**（每 1、5 或 10 分钟）、**查询语言**（指标用 **PromQL**，其他用 **SQL**）和 **查询**。查询要返回一个数值：评估器读取第一行的第一列。可以按需填写[**按维度拆分**](#按维度拆分)。规则不能读取 [`_audit` 数据流](/zh-Hans/settings/data-security#审计数据流)，保存时返回 `400`。
  </Step>
  <Step title="设置触发条件">
    每一行是一个严重度：**当结果** 以运算符与 **阈值** 比较，**并持续** 若干分钟。**添加级别** 可以再加一行。命中的最高严重度生效，高严重度不能比低严重度更容易命中。分钟数会换算为评估次数。在下方设置 [**恢复条件** 和 **没有数据时**](#恢复条件与没有数据)。
  </Step>
  <Step title="添加处理指南">
    在 **Notify 与处理** 中填写 **处理指南 / Runbook URL**，事件处理人员可以从事件列表直接打开。通知谁由[升级策略](/zh-Hans/alerting/on-call#升级策略)和[通知策略](/zh-Hans/notification-channels#创建模板和策略)决定，而不是由规则决定。
  </Step>
  <Step title="测试规则">
    点击 **测试规则**。查询会在最近 6 小时的真实数据上运行，**查询预览** 绘制结果，并显示阈值线、当前值、预计触发次数、扫描行数和耗时。按维度拆分的规则会显示分成了多少组。
  </Step>
  <Step title="保存">
    **创建前检查** 必须全部通过：已填写名称、当前查询测试成功、阈值有效、Runbook URL 有效。然后点击 **保存并启用**，或点击 **保存草稿** 只保存不运行。
  </Step>
</Steps>

在规则工作台中创建的规则不指定升级策略，事件由[告警路由](/zh-Hans/alerting/routing)分派，路由定不下时使用名为 `default` 的升级策略。组织中没有这条策略时，这样的事件不会升级给任何人，请先创建它。参见[默认策略](/zh-Hans/alerting/on-call#默认策略)。

## 按维度拆分

基于 SQL 或 PromQL 查询的定时规则可以按结果里的列拆分，例如按主机或服务。在规则工作台填写**按维度拆分**，或在[创建规则](/zh-Hans/api/alerting/create-rule#按列拆分的规则)时设置 `query.group_by`。之后每组取值都像一条独立的规则。

| 部分 | 行为 |
|---|---|
| 组 | 这些列取值相同的行。列名与结果的列名匹配时不区分大小写。 |
| 值 | 组内第一行给出值：除这些列和时间列以外的第一个数值列。 |
| 触发条件 | 每组各自与触发条件或各档阈值比较，各自累计 `for_periods`。 |
| 事件 | 每组开自己的事件，标签和标题里带上这一组的取值，例如 `Errors per host · web-1`。这一组满足恢复条件时，事件被解决。不在结果里的组算作没有值，按规则的没有数据处理方式处理。 |
| 上限 | 最多 8 列，每轮最多 100 组。超过 100 组时其余的组这一轮不评估，结果里没有的组这一轮也保留它的事件。 |

每组返回一行，最严重的排在前面：

```sql
SELECT host, count(*) AS errors
FROM app_logs
WHERE level = 'error'
GROUP BY host
ORDER BY errors DESC
```

PromQL 里序列的标签就是它的列，因此 `sum by (instance) (rate(http_requests_total{status=~"5.."}[5m]))` 按 `instance` 拆分。结果有行却没有这个名字的列时，这一轮评估失败，什么都不改变。在规则工作台测试查询时会检查这些列。APM、RUM、实时与异常规则不能拆分；[离群规则](#离群规则)必须拆分。

## 恢复条件与没有数据

每条规则都要说清开着的事件什么时候恢复，以及一次评估没有值时算作什么。在规则工作台的**恢复条件**和**没有数据时**里设置，或在[创建规则](/zh-Hans/api/alerting/create-rule#恢复条件与没有数据)时设置 `trigger.recovery` 和 `trigger.no_data`。

- **恢复阈值：**开着的事件要等值越过这条线才恢复，例如高于 90 触发的规则低于 80 才恢复。数值在阈值附近来回时，不会再反复触发、反复恢复。
- **恢复持续时间：**值要在健康的一侧保持这么久，事件才恢复。
- **没有数据时：**查询没有返回值，或按维度拆分的规则里某一组不在结果里。

| 处理方式 | 结果 |
|---|---|
| 当作恢复 | 这次评估算作不命中，开着的事件恢复。默认选项。 |
| 保持原状态 | 什么都不变，规则显示**无数据**。异常规则的默认选项。 |
| 开无数据事件 | 保持原状态，没有数据持续够了时间就开一个标着**无数据**的事件，通知标题为 `NO DATA · <标题>`。数据回来时它自动解决。主机或服务确实下线时请手动解决它：数据回来之前不会再开。 |
| 按 0 计算 | 把缺的值当作 0 比较，适合计数。 |

实时规则不能设置这两项：计数一回落就恢复。

## 异常规则

异常规则在数值偏离其历史所预测的范围时触发，因此不需要固定阈值。点击 **新建规则 → 异常检测规则**。

| 分组 | 字段 | 规则 |
|---|---|---|
| 标识 | **规则名称**、**级别**、**服务** | 服务可选，用于提供跨信号上下文。 |
| 检测查询 | **数据源** | **查询**、某个服务或端点的 **APM 指标**，或某个应用的 **RUM 指标**。参见[对 APM 指标设置异常检测告警](/zh-Hans/apm/insights#对-apm-指标设置异常检测告警)与 [RUM 异常规则](/zh-Hans/rum/alerts#异常规则)。 |
| | **数据流**、**数据流类型**、**查询语言**、**查询** | 返回单个数值的查询，例如平均值、P95 或计数。 |
| | **评估窗口** | 1、5 或 15 分钟，或 1 小时。 |
| 检测器 | **算法** | **MAD**（鲁棒中位数）或 **EWMA**（跟踪近期漂移）。 |
| | **回看天数** | 同一时段 1 到 30 天的历史，默认 7 天。 |
| | **灵敏度（k·σ）** | 与基线的距离超过 k 倍离散度时触发。越大越不敏感，默认 3。 |
| | **平滑系数（α）** | 仅 EWMA，取值 `(0, 1]`。越大越看重近期样本。 |
| | **触发所需连续周期** | 开启事件前需要连续异常的评估次数。 |
| | **周季节性** | 只与相同星期几的历史比较，避免工作日与周末之间的误报。需要至少 7 天回看，28 天以上效果最好。 |

## 预测规则

预测规则按指标过去的走势往后推，预计在提前量之内越过阈值就触发，适合磁盘、配额、连接数这类慢慢逼近上限的指标。在 **判定方式** 里选 **预测**，像阈值规则一样写查询，再设置：

| 设置 | 说明 |
|---|---|
| **预计** | 运算符和阈值，例如预计 `> 90`。 |
| **提前量** | 预计在多久之内越线就触发：1、6、12 小时，或 1、2、3、7 天，默认 1 天。 |
| **回看** | 用过去几天的走势来推：1、3、7、14 或 30 天，默认 7 天。 |
| **外推方式** | **线性趋势**；**按天的规律** 或 **按周的规律**：在一天或一周前同一时刻的值上加上趋势，适合有日、周起伏的指标。按周要回看至少 7 天。 |

规则每轮把当前值记进一条序列；刚建好或改了查询时，先查一批过去的时刻补上历史点。点不够时（不到 6 个，或按天、按周还不满一个周期）这一轮不下结论。事件注明预计越线的时刻和那时的值。预测规则只有一个严重度和持续分钟，没有恢复阈值，可以设[没有数据时](#恢复条件与没有数据)。

## 离群规则

离群规则不和固定阈值比，而是让按维度拆分出的各组相互比较：例如按主机拆分错误数时，一台主机的错误明显多于其余主机就触发，整体一起升高则不触发。在 **判定方式** 里选 **离群**，写好查询并填写[**按维度拆分**](#按维度拆分)，再设置：

| 设置 | 说明 |
|---|---|
| **容差** | 偏离多少个尺度算离群，0.5 到 10，默认 3。越小越敏感。 |
| **看哪一侧** | **偏高或偏低**、**只看偏高** 或 **只看偏低**。 |

偏离程度按各组的中位数和中位数绝对偏差（MAD）计算，各组几乎一样时也不会把小波动当成离群。离群的组各开一个事件，事件注明偏离程度；有值的组少于 3 个时这一轮不判断。离群规则不能用 APM 和 RUM 指标，只有一个严重度和持续分钟。

## 组合规则

组合规则把几条规则合起来看：被组合的规则有进行中的事件就算成立，再用表达式组合。例如 `A && B` 在错误率和延迟同时告警时才通知，`A && !B` 在下游正常时才算上游的问题。在 **判定方式** 里选 **组合**：

| 设置 | 说明 |
|---|---|
| **规则** | 选最多 10 条规则，依次记作 A、B、C…… |
| **表达式** | 用字母和 `&&`（并且）、`\|\|`（或者）、`!`（不是）、括号组合，例如 `A && (B \|\| C)`。 |
| **把这些规则的事件并到组合规则的事件下** | 组合规则开了事件以后，被组合的规则进行中的事件[并入](/zh-Hans/alerting/incidents#合并事件)它，不再单独通知；之后新开的也会并进来。 |

组合规则不跑查询，不能测试，也没有[没有数据时](#恢复条件与没有数据)。被组合的规则不能是组合规则，组合规则也不能被别的组合规则组合；被组合的规则删掉后算不成立。事件注明当时哪些字母成立。

## 心跳规则

心跳规则反过来等作业来报到：定时任务、备份脚本、批处理每次跑完请求一次打卡地址，过了周期加宽限还没打卡，或打卡报了失败，规则就触发。在 **判定方式** 里选 **心跳**：

| 设置 | 说明 |
|---|---|
| **打卡周期** | 作业多久跑一次，1 分钟到 7 天，默认 60 分钟。 |
| **宽限** | 过了周期再等多久才算没打卡，最多 1 天，默认 5 分钟。 |

保存后弹出打卡地址和 `curl` 示例，地址只显示这一次。让作业成功时请求它（`GET` 或 `POST`）；失败时加上 `?status=fail`，规则马上触发。`POST` 的请求体开头会作为这次打卡带的话记进事件，适合附上最后几行日志。

```bash
if ./backup.sh; then
  curl -fsS "$HEARTBEAT_URL"
else
  curl -fsS "$HEARTBEAT_URL?status=fail"
fi
```

编辑心跳规则时可以看到最后一次打卡和最晚的下一次打卡时间。**重置打卡地址** 换一个新地址，旧地址马上失效。打卡地址不用登录，靠地址里的 Token，见[公开访问](/zh-Hans/public-access)和[心跳打卡](/zh-Hans/api/alerting/heartbeats)。心跳规则不跑查询，不能测试，也没有[没有数据时](#恢复条件与没有数据)。

## 实时规则

实时规则在接入路径上运行，而不是按定时器运行。intake 节点接收的每条记录都会与所在数据流的实时规则匹配，匹配结果进入长度为 `period_secs` 秒的滑动窗口。负责这条规则的 alert 节点每秒向各个接收写入的节点拉一次窗口内的匹配数并求和，和达到触发条件时开事件，不再满足条件时事件被解决，比记录写入晚最多 1 秒。

| 部分 | 行为 |
|---|---|
| 语句 | SQL 的 `SELECT count(*) FROM <stream> [WHERE <condition>]`。表名是规则的 `stream`。条件用字段与字面量比较（`=`、`!=`、`<`、`<=`、`>`、`>=`），并支持 `IN`、`BETWEEN`、`LIKE`、`ILIKE` 与 `IS [NOT] NULL`，用 `AND`、`OR`、`NOT` 与括号连接。缺失或为 null 的字段在比较中永远不匹配。 |
| 窗口 | `period_secs` 取 1 到 3600。 |
| 触发条件 | `operator` 为 `gt` 或 `gte`，`for_periods` 为 `0` 或 `1`。`thresholds` 中的各档按计数决定严重程度。 |
| 事件 | 事件遵循通常的生命周期：每条规则只有一个活动事件、`silence_secs` 冷却、升级与通知。 |

[创建规则](/zh-Hans/api/alerting/create-rule)会以 `400` 拒绝超出上述限制的实时规则。计数保存在每个接收写入的节点的内存中，每个节点每 5 秒把窗口存一份快照到元数据库。节点重启时读回自己的快照，最多丢最后 5 秒的计数。节点停了或没应答时，负责汇总的 alert 节点用它最近的快照顶上，直到这些计数出了窗口。负责汇总的节点换了不丢，接手的节点按进行中的事件接上已触发的状态。集群里各节点之间拉计数要配集群 bearer（`MS_SELF_TELEMETRY_CLUSTER_TOKEN`，与分角色部署共用），没配时别的节点只能靠快照。

### 联邦里的实时规则

在[跨集群联邦](/zh-Hans/settings/data-plane#跨集群联邦)里，每个集群各自统计写入自己的记录，默认各集群按自己的计数判断。要把各集群加起来，就指定汇总集群：接口里的 `query.home_cluster`，或在规则工作台打开这条规则时的 **汇总集群**（可选本集群和启用的远端集群）。只有汇总集群开、解决这条规则的事件：它负责这条规则的 alert 节点每秒用组织的 per-org token 向映射了这个组织的各集群要计数，加上自己的再判断，别的集群只计数。800 毫秒内没应答的集群按它上一次答的计数算，最多 30 秒，之后按 0 算，偶尔一秒没答上不会让事件解决；指标 `realtime_federated_counts_failed_total{cluster}` 记下次数。规则随联邦同步、id 不变，每个集群都按它计数。

## 评估延迟

分角色集群里，查询只读 intake 已经刷写的数据，intake 缓冲里的记录最多要等 `[intake].flush_interval_secs`（默认 30 秒）才看得到，所以最近一个窗口的数会偏低。规则工作台 **高级** 里的 **评估延迟** 把每一轮的窗口整体往回挪：设 5 分钟、周期 5 分钟时，07:00 评估的是 06:50 到 06:55 的数据。

| 取值 | 效果 |
|---|---|
| **自动**（默认） | 一个进程跑全部角色的单机不挪；分角色集群按 **设置 → 告警评估** 的 **评估延迟**，默认 60 秒。 |
| **不延迟** | 看到现在为止。 |
| 30 秒到 1 小时 | 按这条规则自己的延迟。接口可以设 0 到 3600 秒（`query.delay_secs`）。 |

无数据判定、恢复条件、异常检测的基线、预测规则的序列、按维度拆分和离群都按同一个延迟往回挪。挪过窗口时，开出来的事件在注解 `evaluated_window` 里记下这一轮看的区间。实时规则不评估查询，没有评估延迟。

## 优先级与紧急度

规则工作台 **Notify 与处理** 里的 **优先级** 和 **紧急度** 定这条规则开出来的事件：

- **优先级**：组织的[优先级档位](/zh-Hans/alerting/on-call#紧急度与优先级档位)之一，默认 P1 到 P5，P1 最重，不设时事件没有优先级（[告警流水线](/zh-Hans/pipelines)还可以设）。优先级不从严重度推导。
- **紧急度**：**按升级策略**（默认）时按事件走的[升级策略的紧急度](/zh-Hans/alerting/on-call#紧急度)定；选了高或低就始终是这一档。

## 自动发现规则

[自动发现](/zh-Hans/alerting/discovery)找到的问题只进列表。要通知，在 **告警 → 自动发现** 点击 **建自动发现规则**，或在一条发现上点击 **为这类发现建规则**：选发现的种类、服务或应用、环境和最低严重度，以及升级策略和紧急度。命中的每条发现各开一个事件，严重度就是发现的严重度，没设紧急度时按低紧急度；发现结束，事件就恢复。规则列表里这类规则的来源是 **自动发现**，打开时回到自动发现页编辑。

## 导入与导出

规则列表的 **导入导出** 把规则存成文件，或从文件导入：

- **导出全部规则**，或筛选后 **导出这 N 条规则**：下载一个 JSON 规则包（`"format": "molesignal.alert-rules/v1"`）。规则带着全部定义，但不带 id、组织、评估状态和时间；升级策略和组合规则的子规则按名称引用，所以同一个包能搬到别的工作区或集群。心跳规则的打卡地址不在包里，导入后在规则上重置。
- **导入规则…**：贴上或选择规则包，或 Prometheus 的告警规则文件（也认 Prometheus Operator 的 `PrometheusRule`），先点击 **预演**，看每条规则会 **新建**、**更新**（列出改动的字段）、**不变** 还是 **出错**，再点击 **导入 N 条**。规则按名称对上：没有同名的就新建，正好一条就更新，同名的有几条时报错，文件里同一个名称出现两次也报错（导出时有同名规则的，先改名再导入）。勾选 **只新建，已有的同名项不动** 时已有的规则 **跳过**。有一条出错时整包都不写；没出错时一次写进去，都写进或都不写。

Prometheus 规则这样换成 MoleSignal 的规则：

| Prometheus | MoleSignal |
|---|---|
| `alert` | 规则名称。同名的告警出现在几个规则组里时，后面的名称带上组名。 |
| `expr` | PromQL 规则，语句是 `count(<expr>)`、条件是 `>= 1`：表达式返回了序列就告警。注解或标签里用到 `{{ $labels.x }}` 时语句是 `count by (x) (<expr>)`，并按 `x` [拆分](#按维度拆分)，每组各开一个事件。数据流取表达式里第一个指标名。 |
| 规则组的 `interval` | 周期，没有时 60 秒。 |
| `for` | 连续命中的周期数，向上取整。 |
| 标签 `severity` | 严重度：`critical`、`page` 为严重，`error`、`high` 为错误，`warning`、`warn` 为警告，`info`、`low`、`none` 为提示；其余标签原样带上。 |
| `annotations` | 原样带上；说明取 `description` 或 `summary`。 |
| `record` | 记录规则不导入，在预演结果下方列出。 |
| `keep_firing_for` | 不支持，列在预演结果下方。 |

导入的规则用默认升级策略，需要时在导入前改好规则包里的 `escalation_policy`。Alertmanager 自己的配置文件（`alertmanager.yml` 的路由和接收方）不是规则，不能这样导入，请改用[告警路由](/zh-Hans/alerting/routing)和[通知策略](/zh-Hans/notification-channels)。

在 CI 里可以用 [CLI](/zh-Hans/cli) 的 `molesignal alerts rules export` 和 `molesignal alerts rules apply -f rules.json [--dry-run]`：预演结果打印成表格，有出错的规则时以 1 退出。

## 修改、暂停或删除规则

打开规则即可修改，修改后再次 **测试规则** 并保存。**保存草稿** 让规则保持停用，**保存并启用** 重新启用它。删除规则请调用[删除规则](/zh-Hans/api/alerting/delete-rule)。如果只想暂时屏蔽某条规则的通知而不修改它，请使用[静默](/zh-Hans/alerting/silences)。

[告警规则 API](/zh-Hans/api/alerting/create-rule) 可以在脚本中创建、测试和触发规则。
