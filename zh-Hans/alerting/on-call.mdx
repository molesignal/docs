升级策略决定一个事件通知谁、按什么顺序通知。它的每一级可以指定人员、团队或值班排班，这样通知会跟随轮值，而不是固定到某个人。打开 **告警 → 值班排班** 和 **告警 → 升级**。读取它们需要 `schedules.read` 和 `alerts.escalations.read`；创建、修改和删除排班分别需要 `schedules.create`、`schedules.update` 和 `schedules.delete`，修改升级策略需要 `alerts.escalations.manage`。

## 通知如何送达

1. 规则触发并开启事件，事件使用规则的升级策略；规则用默认策略时，由[告警路由](/zh-Hans/alerting/routing)选出。
2. 策略的第 1 级开始执行：每个目标收到一个通知事件。用户目标就是这个人，排班目标是此刻的值班人，团队目标面向整个团队。
3. [通知策略](/zh-Hans/notification-channels#创建模板和策略)把每个通知事件转成投递：连接器、每个人的个人顺序，以及兜底路由。
4. 在该级的 **确认超时** 内无人确认时，执行下一级，直到事件被确认或解决，或所有级别执行完毕。策略设了[确认后仍未解决](#确认后仍未解决)时，确认后迟迟没解决的事件会退回未确认，重新开始通知。

命中事件的静默在生效期间暂停升级，结束后升级接着推进，参见[静默期间的通知](/zh-Hans/alerting/silences#静默期间的通知)。有多个 `alert` 节点时，每条规则归属一个节点，该节点也负责升级这条规则的事件。参见[分角色部署](/zh-Hans/deployment/role-based#alert-节点之间的分工)。

## 值班排班

**值班排班** 列出各个排班的时区、轮值、人数、当前值班人、下次切换和状态。页面顶部汇总排班数、当前值班人数、本周轮换次数和临时替班。可以按排班、团队、负责人、时区或状态筛选，或只看 **仅看我参与的排班**。列表上方的 **订阅我的值班** 把自己在各排班里的班次加到日历应用里，见[订阅日历](#订阅日历)；**换班申请** 列出自己发起的和请自己替班的申请，标着有几条等自己答复，见[换班申请](#换班申请)。

| 状态 | 含义 |
|---|---|
| **进行中** | 有人在值班。 |
| **即将切换** | 下次交接在 2 小时以内。 |
| **未开始** | 第一个轮值还没开始。 |
| **已暂停** | 排班已暂停，不会让任何人值班。 |
| **存在空班** | 当前无人值班。 |

### 创建排班

1. 点击 **新建排班**。
2. 在 **基本信息** 中填写 **排班名称**、**说明**、**时区**（例如 `Asia/Shanghai`）和 **关联团队**。
3. 在 **轮值规则** 中设置每个轮值：

   | 字段 | 用途 |
   |---|---|
   | 轮值名称 | 例如 `primary`。 |
   | **轮换方式** | **每日**、**每周**、**工作日**（每日轮换，周一到周五）或 **自定义周期**（填写 **周期（小时）**）。 |
   | **开始日期与时间**、**交接时间** | 轮值何时开始，以及每天几点交接。 |
   | **轮值成员（按顺序轮换）** | 参与轮换的人员及其顺序。 |
   | **限定具体日期 / 时段** | 只覆盖一周里的某些时段：每段选 **星期**，写 **开始（HH:MM）** 和 **结束（HH:MM）**，按排班时区计算，精确到分钟。**添加时段** 可以加多段，例如 9:30–12:00 和 13:30–18:00。结束不晚于开始表示跨午夜，算在开始那天；整天写 00:00–24:00。 |
   | **节假日** | **不考虑节假日**（默认）、**节假日不算** 或 **只在节假日**，按选的 **节假日日历** 算，见[节假日日历](#节假日日历)。工作日轮值选节假日不算，下面再加一个只在节假日的轮值，就能单独安排放假的日子。 |

4. 需要的话打开 **换班需要批准**：对方接受换班后，还要有排班管理权限的人批准才生效。
5. 检查 **未来 7 天预览**，确认轮值顺序、交接时间和覆盖人员。
6. 点击 **创建排班**，或点击 **保存草稿** 以暂停状态保存。

多个轮值覆盖同一时刻时，列表中第一个有人值班的轮值生效。例如可以在第一个轮值下方再加一个夜间或周末轮值。

交接按排班时区的本地时间推进：纽约 09:00 交接的轮值全年都在 09:00 交接，跨夏令时的那一班长 23 或 25 小时。交接时刻落在夏令时跳过的那一小时里时，取跳过之后的第一刻；落在重复的那一小时里时，取前一个。预览、时间线、日历订阅和值班负担都由服务端按同样的规则算出。

### 临时替班

临时替班在固定时段内把值班交给某一个人，用于请假、换班或故障处理。在排班上点击 **添加替班**，选择 **替班人**，填写 **原因**、**开始时间** 和 **结束时间** 后保存。替班生效期间优先于所有轮值。

同一排班的两个替班不能重叠。替班人在开始时已参与其他排班，或开始时间已经过去（保存后立即生效）时，表单会给出提示。**结束替班** 可以提前结束正在生效的替班。

### 换班申请

换班申请请排班里的另一个人替自己值一段班，不用找管理员加替班。在排班详情的 **换班申请** 里点击 **申请换班**，选一个自己接下来 30 天里的班次（或自己填开始和结束时间），选 **接班的人**，可以写一句备注，然后 **发出申请**。这段时间排班上只能有自己一个人在值班；和还没定下来的申请重叠的时间段不能再申请。

| 状态 | 含义 |
|---|---|
| **等对方答复** | 接班的人可以 **接受** 或 **拒绝**，发起人可以 **撤回**。 |
| **等管理员批准** | 排班开了 **换班需要批准**，对方已经接受；有排班管理权限的人可以 **批准** 或 **驳回**。 |
| **已生效** | 排班加上了一条临时替班，替班人是接班的人。 |
| **对方拒绝**、**管理员驳回**、**已撤回** | 申请结束，排班不变。 |
| **已过期** | 时间段结束时还没定下来。 |

每一步都会通知该知道的人：发起时通知接班的人；对方拒绝时通知发起人；转为等批准时通知排班的创建人、最后修改的人和发起人；生效或被驳回时通知发起人和接班的人；撤回时通知接班的人。通知由内置策略[换班：通知相关的人](/zh-Hans/notification-channels#内置策略)发出。生效的换班和其他操作一起记进排班的 **变更记录**。

### 订阅日历

排班的 **更多** 菜单里的 **订阅日历** 生成一个订阅地址，把这个排班的全部班次加到 Google 日历、Outlook、Apple 日历等日历应用里；列表上方的 **订阅我的值班** 订阅自己在各个排班里的班次。日历应用大约每小时刷新一次，包含过去 30 天到未来 90 天，替班和换班都算在内。

地址只显示一次，拿到地址的人都能看到这些班次。日历每次读取时都会重新核对订阅人：账号停用、离开组织或失去排班的查看权限后，地址就读不出内容。**重置地址** 换一个新地址，旧地址马上失效；**停止订阅** 让地址失效。和 **导出日历** 下载的 `.ics` 文件不同，订阅会跟着排班的变化更新。

### 排班详情与操作

打开排班即可看到当前值班人及其开始时间、下次轮换、轮值规则、临时替班、[换班申请](#换班申请)、**未来 7 天时间线**、**成员负担（近 30 天）**，以及排班的 **变更记录**。成员负担列出每个成员值了多久的班、收到几次告警通知，其中几次在夜里（按排班时区 22:00 到次日 08:00）、几次在周末，被吵醒了几个晚上，与[洞察](/zh-Hans/alerting/incidents#洞察)里的 **值班负担** 一致。排班菜单提供：

| 操作 | 效果 |
|---|---|
| **编辑排班** | 修改排班及其轮值。 |
| **添加临时替班** | 添加一个替班。 |
| **暂停排班** / **恢复排班** | 暂停的排班不会让任何人值班，指向它的升级级别也就通知不到人。 |
| **复制排班** | 创建一个名为 `<名称> 副本` 的副本。 |
| **订阅日历** | 生成日历订阅地址，见[订阅日历](#订阅日历)。 |
| **导出日历** | 把班次下载为 `.ics` 文件，导入日历。 |
| **删除排班** | 删除排班。 |

[首页](/zh-Hans/home)显示当前班次，成员可以在[账号设置](/zh-Hans/account#通知设置)中选择值班通知的送达方式。

### 收不到告警的成员

一个人在值班却收不到告警时，事件开出来也叫不醒任何人。MoleSignal 按高紧急度那组个人步骤，把每个成员分成三种：

| 状态 | 含义 |
|---|---|
| 收得到 | 个人的告警通知开着，至少有一步的通知方式启用、已验证，它的连接器也启用。 |
| 只能靠群 | 没有个人通知方式，但团队或组织的默认路由能发到群里。 |
| 收不到 | 两样都没有。 |

收不到的成员在排班成员旁边、升级策略的每一级（**N 人收不到**）标出来；下一班的人收不到时，排班详情顶部会提示。自己在排班里却收不到时，[账号设置](/zh-Hans/account#通知设置)和[首页](/zh-Hans/home)的值班卡片会提示。班次开始前 30 分钟，接班人收不到时，内置策略[接班人收不到告警：通知本人和排班管理员](/zh-Hans/notification-channels#内置策略)通知接班人本人和排班管理员。

事件升级到一级时，这一级里谁都收不到（包括这一刻没人值班）就立即升到下一级，不等确认超时；时间线记一笔 **第 N 级谁都收不到告警，直接升到下一级**。整条策略都没人收得到时，事件照常开着，只在时间线和策略页提示。

## 升级策略

**升级** 列出各策略通知谁、何时通知。

1. 点击 **新建策略** 并填写 **策略名称**。
2. 为每一级选择 **生效起始严重度**（**任意严重度** 或某个最低严重度）、**确认超时**（1、5、10、15 或 30 分钟，或 1 小时）和 **目标**：**用户**、**排班** 或 **团队**。**添加级别** 可以增加下一级。
3. 可以开启 **循环整个策略直到被确认**，并设置 **最大循环次数**。
4. 可以设置 **确认后仍未解决**，见[下文](#确认后仍未解决)。
5. 在 **紧急度** 中选这条策略怎样定紧急度，见[紧急度](#紧急度)。
6. 点击 **创建策略**。

最低严重度高于事件严重度的级别会被跳过。每次投递使用的连接器和兜底路由在 **设置 → 通知 → 通知策略** 中设置，而不是在升级策略中设置。

### 确认后仍未解决

有人确认了事件、之后却一直没有解决时，**确认后仍未解决** 让它回到值班人手里：选 30 分钟、1、2 或 4 小时（接口允许 5 分钟到 24 小时）。从确认起过了这么久事件还没解决，它退回 **等待确认**，负责人重新收到通知，模板里的 `{{escalation.reason}}` 是 `ack_timeout`；还是没人确认时，照常往下升级。默认 **不重新通知**：已确认的事件保持已确认，直到有人解决它。暂缓中的事件不看这个时间，暂缓结束时退回。

### 紧急度

严重度说信号有多糟，紧急度管现在叫不叫醒人。每个事件开出来时有一档紧急度。内置的两档是这样通知的：

| | 高紧急度 | 低紧急度 |
|---|---|---|
| 升级 | 按策略逐级通知 | 只通知第一级，不往下升，也不整轮重复 |
| 个人通知 | 按个人的高紧急度步骤 | 按个人的低紧急度步骤；没设时只用高紧急度的第一步 |
| 免打扰时段 | 看个人的 **免打扰时仍接收高紧急度告警** | 一律不打扰 |

组织可以给各档改名、改通知方式，也可以再加几档，见[紧急度与优先级档位](#紧急度与优先级档位)。

规则、外部告警、告警流水线或手动建事件明确指定的紧急度优先；没指定时，按事件走的升级策略的 **紧急度** 定：

| 选项 | 效果 |
|---|---|
| **按严重度**（默认） | 每个严重度落到组织给它定的那一档：没改过时严重、错误为高，警告、提示为低。 |
| **始终某一档** | 每个事件都用 **紧急度** 里选的那一档。 |
| **按支持时段** | **时段内** 用一档，**时段外** 用另一档，默认是高和低。支持时段按每周的几段时间和一个时区填写，可以按[节假日日历](#节假日日历)把节假日去掉。勾选 **支持时段开始时，把还没人确认、比时段内那一档不急的事件升上去，从第一级重新通知** 后，夜里开的、到早上还没人确认的事件会在支持时段开始时升到时段内那一档，从第一级重新通知，时间线记一笔 **支持时段开始，紧急度升为……，从第 1 级重新通知**。 |

勾选 **只通知第一级的那几档，在这条策略下也照常逐级升级** 时，各档在这条策略下都像高紧急度一样往下升级。外部告警没报严重度时按高紧急度；组织没有的紧急度在事件开出来时去掉，交给策略定。策略列表在链路后面标出不是按严重度定的紧急度。

<Note>
按严重度定紧急度意味着警告和提示事件默认只通知第一级，并且在免打扰时段不打扰。要保持所有事件逐级通知，把策略的紧急度设为 **始终某一档**，选高紧急度。
</Note>

### 紧急度与优先级档位

在 **设置 → 告警 → 优先级与紧急度** 里设组织的档位。读取需要 `alerts.importance.read`，修改需要 `alerts.importance.manage`。

**紧急度档位** 按从急到缓排列，用箭头上移或下移。每档有：

| 设置 | 用途 |
|---|---|
| 名称 | 列表、筛选和消息里显示的名字。 |
| **逐级升级** | 按升级策略逐级通知；关掉时这一档只通知第一级。 |
| **免打扰时** | **看个人开关**（**免打扰时仍接收高紧急度告警**）或 **一律不打扰**。 |
| **个人步骤** | 用个人两组步骤里的哪一组：**高紧急度步骤** 或 **低紧急度步骤**。 |
| **按严重度** | 策略按严重度定紧急度时，哪些严重度落到这一档。每个严重度恰好落在一档里。 |

内置的 `high`、`low` 两档能改名、能改设置，不能删。**加一档紧急度** 最多再加三档，一共五档；**新一档的键** 例如 `urgent`，以小写字母开头，只用小写字母、数字和下划线。规则、外部告警、告警流水线和接口都按键指定紧急度。档位删掉以后，还在用它的事件按高紧急度通知。

**优先级档位** 设组织用几档优先级（1 到 9 档），以及每档的名称和说明。键固定是 `P1`、`P2`……，集成和导入的文件都用它；外部告警或告警流水线给的优先级超出档数时落到最低一档。模板里用 `{{urgency_name}}` 和 `{{priority_name}}` 取档位的名称，见[模板变量](/zh-Hans/notification-channels#模板变量)。

### 默认策略

规则通过 `escalation_policy_id` 指定升级策略。没有指定的规则（在规则工作台中保存的规则都是如此）使用别名 `default`：[告警路由](/zh-Hans/alerting/routing)按路由规则、服务的负责团队和 team 标签选出团队的值班策略，都没有时用组织中名为 `default` 的策略，不区分大小写。没有这条策略时，这些事件不会升级给任何人。

请在创建第一条规则之前创建名为 `default` 的策略，例如第 1 级通知主值班排班，第 2 级通知团队负责人。事件一旦开始升级，就会一直使用它找到的那条策略，即使之后 `default` 策略被改名。

## 节假日日历

节假日日历记下放假和补班的日子，每周时段可以按它去掉法定节假日，或只在节假日生效。打开 **设置 → 告警 → 节假日日历**。读取日历需要 `alerts.calendars.read`，修改需要 `alerts.calendars.manage`。MoleSignal 不内置法定节假日：每年都变，由各组织自己填或导入。

1. 点击 **新建日历**，填写 **名称** 和 **说明**。
2. 在 **日子** 里选 **年份**，逐个添加 **日期**、**类型**（**放假** 或 **补班**）和 **这一天的名称**。**导入 ICS** 读入法定节假日的 `.ics` 文件：每个全天事件算一天，名称含「补班」「上班」或以「班」结尾的算补班。保存日历之前什么都不写，先核对读进来的日子。
3. 点击 **创建日历**。

每周时段在 **节假日** 里选怎么按日历算：

| 选项 | 效果 |
|---|---|
| **不考虑节假日**（默认） | 节假日和平常一样算。 |
| **节假日不算** | 放假的日子不算在这些时段里。补班日按周一的时段算。 |
| **只在节假日** | 这些时段只在放假的日子才算。 |

日期按引用日历的地方的时区算，跨午夜的时段算在开始那天。[值班排班](#创建排班)的轮值、[紧急度](#紧急度)的支持时段、[路由规则](/zh-Hans/alerting/routing#新建规则)和[通知策略](/zh-Hans/notification-channels#创建模板和策略)的时间条件、告警流水线，以及[静默](/zh-Hans/alerting/silences#静默策略)的 **节假日** 窗口都能按日历算。在用的日历不能删，对话框会列出用到它的地方。改动一分钟内到达所有节点，日历随组织同步到联邦里的其他集群。

## 导入导出

升级策略列表和值班排班列表上方的 **导入导出** 像告警规则一样，用文件在组织和集群之间搬运：

- **导出全部升级策略** 或 **导出全部排班** 下载一个包；选中几条时只导出这几条。包里按名字引用：用户按邮箱，团队、排班、升级策略和节假日日历按名称。
- **导入升级策略…** 或 **导入排班…** 接受 JSON 或 YAML 的包，先预演，列出会新建、更新、不变和出错的项；勾选 **只新建，已有的同名项不动** 时跳过已有的。每项按名称对上，引用的东西必须在组织里，有一项出错时什么都不写。

包里的排班带轮值和设置，不带临时替班和换班；导入已有的排班时保留它们。导入升级策略需要 `alerts.escalations.manage`，导入排班需要 `schedules.create`。路由规则也一样，见[告警路由](/zh-Hans/alerting/routing#导入导出)。
