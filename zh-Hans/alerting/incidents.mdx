[规则](/zh-Hans/alerting/rules)触发或[拨测失败](/zh-Hans/synthetics#告警事件)时会开启事件。事件记录规则、取值、标签以及结束前的每一步。打开 **告警 → 告警事件**，或按 `⌘⌥A`。读取事件需要 `alerts.read`；确认和解决需要 `alerts.acknowledge`，静默需要 `alerts.silence`。

## 事件状态

| 状态 | 列表中的标签 | 含义 |
|---|---|---|
| `open` | **等待确认** | 正在触发，还没有人确认，升级继续进行。 |
| `acknowledged` | **处理中** | 已有人接手，升级停止。 |
| `resolved` | **已恢复** | 已结束：规则已恢复，或有人解决了它。 |
| `closed` | **已关闭** | 已结束。 |

规则满足[恢复条件](/zh-Hans/alerting/rules#恢复条件与没有数据)时，打开的事件会自动解决。已确认的事件会一直保持已确认，直到有人解决它。每条规则（或按维度拆分的规则的每一组）同一时间最多只有一个活动事件。

## 事件列表

**告警事件** 页面顶部统计受影响的服务数、等待确认的事件数，以及最近 24 小时恢复的事件数。摘要说明当前有多少事件在触发、最早的一个已持续多久，以及正在评估多少条规则。**最近恢复** 列出最近结束的事件。

在 **触发中** 与 **等待确认**（尚无人接手的事件）之间切换。每一行显示级别、事件及其服务、状态、持续时间和负责人，并提供三个操作：

| 操作 | 效果 |
|---|---|
| **确认** | 接手事件。事件变为 **处理中**，升级停止。 |
| **静默** | 只暂停这个事件的后续通知与升级。参见[静默单个事件](/zh-Hans/alerting/silences#静默单个事件)。 |
| **Runbook** | 打开规则的处理指南（如果有）。 |

## 事件详情

点击事件即可打开详情。页头显示状态、触发时间、规则和已持续时间，并提供 **确认**、**静默** 和 **解决**。

| 分区 | 内容 |
|---|---|
| **时间线** | 何时触发、谁确认、谁解决，以及其间经过的时间。 |
| **调查** | **打开触发查询** 在探索页中重放当时的精确查询。**相关日志** 和 **相关指标** 在同一时间范围打开受影响的上下文。RUM 指标的事件还有 **在 RUM 中打开**。 |
| **AI 根因** | Mole Agent 的分析。参见 [AI 根因](#ai-根因)。 |
| **跨信号引用** | 证据中出现的服务、Trace ID 和主机，均可点击跳转。 |
| **触发查询** | 查询及其返回的值。**展开样本值** 显示样本行。 |
| **元数据** | 事件的标签与注解。 |
| **负责人** | 升级通知到的人员。 |
| **影响范围** | 关联到某个服务的事件，显示该服务沿服务地图影响到的范围。参见[事件的影响范围](/zh-Hans/apm/insights#事件的影响范围)。 |
| **样本会话** | RUM 指标的事件，列出体现问题的会话，每个都有回放。参见 [RUM 告警](/zh-Hans/rum/alerts#事件)。 |

## AI 根因

为 Mole Agent 配置模型服务后，它会在后台分析新事件，并把有证据支持的结果保存到事件中。**生成** 立即请求一次分析，**重新生成** 替换已有结果。可以用 **有帮助** 或 **没帮助** 评价结果，评价会进入[质量](/zh-Hans/quality)。

生成需要 Mole Agent 权限。组织当天的 Mole Agent token 预算用完后，自动分析会暂停，手动生成按预算设置处理。参见[用量与预算](/zh-Hans/agent#用量与预算)。

## 事件分组

[语义分组](/zh-Hans/alerting/silences#语义分组)把相关事件（例如某个服务的所有严重事件）收成一组。用 `POST /api/v1/alerts/incident_groups/{id}/ack` 或 `/resolve` 确认或解决分组时，组内每个事件都会同样处理。

## 历史

**告警 → 历史** 列出过去的事件，包括当前状态、触发和恢复时间以及持续时间。可以按事件名称、服务或事件 ID 搜索，并按级别和状态筛选。

## 洞察

**告警 → 洞察** 展示工作区在最近 24 小时、7 天或 30 天内的响应情况：

| 部分 | 显示内容 |
|---|---|
| 摘要 | 仍需处理的事件数、已恢复事件的 **平均恢复时间**，以及 **快速恢复事件**：60 秒内恢复的占比，是规则噪声较大的信号。 |
| **事件时间趋势** | 24 小时内按小时、更长范围按天统计的事件数，使用浏览器时区，并标出峰值。 |
| **主要影响服务** | 事件中出现最多的服务。规则需要带 `service` 标签。 |
| **主要触发规则** | 开启事件最多的规则，调优应从这里开始。 |

| 操作 | 端点 |
|---|---|
| 列出事件 | [`GET /api/v1/alerts/incidents`](/zh-Hans/api/alerting/list-incidents) |
| 确认 | [`POST /api/v1/alerts/incidents/{id}/ack`](/zh-Hans/api/alerting/ack-incident) |
| 解决 | [`POST /api/v1/alerts/incidents/{id}/resolve`](/zh-Hans/api/alerting/resolve-incident) |
| 根因分析 | [`GET /api/v1/alerts/incidents/{id}/rca`](/zh-Hans/api/alerting/incident-rca) |
| 洞察 | [`GET /api/v1/alerts/insights`](/zh-Hans/api/alerting/insights) |
