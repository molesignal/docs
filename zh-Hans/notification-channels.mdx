MoleSignal 将服务商凭证、接收人和路由规则分开管理。连接器只需配置一次，再把用户身份或兜底目标绑定到连接器，并通过通知策略决定何时使用这些路由。

| 资源 | 用途 |
|---|---|
| **连接器** | 保存组织级服务商凭证和传输配置。 |
| **用户通知** | 绑定各平台身份，并排列个人投递端点。 |
| **通知策略** | 匹配事件、解析接收人、选择模板并控制升级。 |
| **通知模板** | 复用的消息正文，按渠道分类：通用模板哪个渠道都能用，短信、电话等渠道也可以各写一份。 |
| **兜底路由** | 在个人投递失败后，定义有序的团队和组织目标。 |
| **投递记录** | 查看投递尝试、耗时、错误、重试、确认与升级。 |

## 支持的连接器

| 连接器 | 配置 | 支持的目标 |
|---|---|---|
| Email SMTP（`email_smtp`） | SMTP 主机、端口、凭证、发件地址、TLS 模式、超时 | 用户邮箱或固定邮箱 |
| Slack App（`slack_app`） | Bot Token、App-Level Token、平台（Slack 或 GovSlack）、Client ID 与 Client Secret、超时 | Slack 用户 ID 或频道 ID |
| Slack Webhook（`slack_webhook`） | Incoming Webhook 地址、超时 | 已配置 Webhook 或按目标覆盖的 Webhook 地址 |
| 飞书 App（`lark_app`） | App ID、App Secret、平台（飞书或 Lark）、接收人 ID 类型、超时 | 用户身份、邮箱或群聊 ID |
| 飞书 Webhook（`lark_webhook`） | 自定义机器人 Webhook 地址、可选签名密钥、超时 | 已配置 Webhook 或按目标覆盖的 Webhook 地址 |
| 钉钉 App（`dingtalk_app`） | Client ID 与 Client Secret、可选机器人 RobotCode、可选互动卡片模板 ID、超时 | 钉钉 userId 或 `openConversationId` |
| 钉钉 Webhook（`dingtalk_webhook`） | 自定义机器人 Webhook 地址、可选签名密钥、超时 | 已配置 Webhook 或按目标覆盖的 Webhook 地址 |
| 企业微信 App（`wecom_app`） | 企业 ID、应用 Secret、AgentId、可选接收消息 Token 与 EncodingAESKey、超时 | 成员 UserID 或应用群聊 chatid |
| 企业微信 Webhook（`wecom_webhook`） | 群机器人 Webhook 地址、超时 | 已配置 Webhook 或按目标覆盖的 Webhook 地址 |
| 企业微信智能机器人（`wecom_bot`） | Bot ID、长连接 Secret | 成员 userid 或群 chatid |
| Microsoft Teams 机器人（`teams_app`） | 应用 ID、客户端密码、租户 ID、云环境（全球、GCC、GCC High 或 DoD）、超时 | 用户 ID 或会话 ID |
| Microsoft Teams Webhook（`teams_webhook`） | 频道 Webhook 地址、超时 | 已配置 Webhook 或按目标覆盖的 Webhook 地址 |
| Google Chat App（`google_chat_app`） | 服务账号密钥（JSON）、可选 Pub/Sub 订阅、超时 | 用户（`users/…`）或空间（`spaces/…`） |
| Google Chat Webhook（`google_chat_webhook`） | 空间 Webhook 地址、超时 | 已配置 Webhook 或按目标覆盖的 Webhook 地址 |
| 阿里云语音通知（`aliyun_voice`） | AccessKey、区域、可选外显号码、播放遍数、超时；模板编号与变量写在电话模板里 | 内地号码 |
| 阿里云短信（`aliyun_sms`） | AccessKey、区域、短信签名、超时；模板编号与变量写在短信模板里 | 内地号码或国际号码 |
| 腾讯云语音消息（`tencent_voice`） | SecretId 与 SecretKey、区域、应用 ID、播放遍数、超时；模板 ID 与变量写在电话模板里 | 内地号码或国际号码 |
| 腾讯云短信（`tencent_sms`） | SecretId 与 SecretKey、区域、应用 ID、可选短信签名、超时；模板 ID 与变量写在短信模板里 | 内地号码或国际号码 |
| 华为云语音通知（`huawei_voice`） | AppKey 与 AppSecret、APP 接入地址、外显号码、超时；模板 ID 与变量写在电话模板里 | 内地号码或国际号码 |
| 华为云短信（`huawei_sms`） | AppKey 与 AppSecret、APP 接入地址、通道号、可选签名名称、超时；模板 ID 与变量写在短信模板里 | 内地号码或国际号码 |
| Twilio 电话（`twilio_voice`） | Account SID、Auth Token、主叫号码、语言、可选声音、播放遍数、超时 | E.164 号码 |
| Twilio 短信（`twilio_sms`） | Account SID、Auth Token、发送方、超时 | E.164 号码 |
| AWS 语音（`aws_voice`） | 区域、认证方式、发送方身份、可选 Polly 声音、播放遍数、超时 | E.164 号码 |
| AWS 短信（`aws_sms`） | 区域、认证方式、可选发送方身份、超时 | E.164 号码 |
| 通用 HTTP 短信（`http_sms`） | 网关地址、HTTP 方法、请求体格式与请求体、请求头、密钥、号码写法、成功字段与成功值、超时 | 内地号码或国际号码 |
| 通用 Webhook（`webhook`） | 默认地址、HTTP 方法、请求头、超时 | 用户、地址、群组或按目标指定的 Webhook 地址 |

所有连接器的超时必须在 1 到 60 秒之间。URL 必须是绝对 `http` 或 `https` 地址。

服务商的地址在连接器里只读显示，可以复制，不能修改：阿里云、腾讯云和 AWS 的 API 基础地址随所选的区域确定，飞书 App 和 Slack App 的随所选的平台确定，Teams 机器人的服务地址随所选的云环境确定，其余连接器是服务商的固定地址，例如企业微信智能机器人的长连接地址。华为云是例外：接入地址随应用定，只能从控制台抄，没有接口能查，所以由人填。保存、测试和直接发送前，这些地址都按服务商的地址列表检查，通过 API 写的其他地址会被拒绝，凭证不会发到别处。已保存的连接器不能改类型。

## 创建并测试连接器

查看连接器需要 `notify.connectors.read`；创建、编辑、测试、启停或删除连接器需要 `notify.connectors.manage`。

<Steps>
  <Step title="打开通知设置">
    前往**设置 → 通知 → 连接器**。
  </Step>
  <Step title="选择服务商">
    点击**新建连接器**，填写唯一名称并选择连接器类型。连接器创建后不能更改类型。
  </Step>
  <Step title="填写服务配置">
    按下文填写凭证和传输参数。除非准备稍后再启用，否则保持**允许此连接器投递**开启。
  </Step>
  <Step title="保存连接器">
    点击**保存连接器**。MoleSignal 会加密保存完整配置，API 响应会把敏感值替换为 `***`。
  </Step>
  <Step title="发送测试">
    编辑已保存的连接器，选择兼容的目标类型，输入真实目标，再点击**测试连接**。最近一次测试会把连接器状态更新为**已连接**或**异常**。
  </Step>
</Steps>

<Note>
  新连接器必须先保存才能测试。编辑连接器时，不要改动已掩码的 `***`，系统会保留原有密钥。
</Note>

## 配置各服务商

### Email SMTP

填写 SMTP 主机、端口、按需填写用户名、密码，以及有效的**发件地址**。按邮件服务器选择 TLS 模式：

| TLS 模式 | 适用场景 |
|---|---|
| `none` | SMTP 连接不使用 TLS。不要在不可信网络上使用。 |
| `starttls` | 先连接再升级到 STARTTLS，常用端口为 `587`。 |
| `tls` | 从连接开始就使用 TLS，常用端口为 `465`。 |

测试时选择 `fixed_address` 或 `direct_user`，并输入 `oncall@example.com` 这类有效邮箱。

### Slack App

创建能调用 `chat.postMessage` 的 Slack App 和 Bot Token，并把机器人加入需要接收通知的频道。填写：

- **Bot Token** —— 通常以 `xoxb-` 开头；
- **App-Level Token** —— 可选；以 `xapp-` 开头、带 `connections:write` 范围的令牌，填了之后 Mole Agent 可以通过 Socket Mode 在 Slack 里回答，见[在 IM 里使用 Mole Agent](/zh-Hans/im)；
- **平台** —— Slack 或 GovSlack（美国政府的 Slack）；选 GovSlack 时，API 和状态页的授权都在 `slack-gov.com`；
- **Client ID** 与 **Client Secret** —— 见 Slack App 的 **Basic Information**，供状态页访客把页面添加到自己的 Slack 频道，见[状态页](/zh-Hans/status-pages#slack)；
- **超时** —— 1 到 60 秒。

连接器至少需要 Bot Token，或 Client ID 与 Client Secret，也可以三项都填。发送通知需要 Bot Token。Client Secret 与 Bot Token 一样随连接器加密保存，接口不会返回明文。

`direct_user` 目标填写 Slack 成员 ID，`fixed_group` 目标填写频道 ID。目标不能包含空格；`#alerts` 这类显示名称不是频道 ID。

在 **Mole Agent → 设置 → IM 接入**里开启这个连接器后，经它发出的告警通知带确认、解决按钮，见[告警卡片](/zh-Hans/im#告警卡片)。

### Slack Webhook

在 Slack 创建 Incoming Webhook，并把地址填入 **Webhook 地址**。`fixed_group` 目标使用连接器中配置的地址；`webhook` 目标会把目标值作为本次投递的替代地址。

MoleSignal 发送包含 `text` 字段的 JSON。任何非 2xx 响应都会将本次投递标记为失败。

### 飞书 App

创建能够获取 tenant access token 并发送消息的企业自建应用，填写 **App ID** 和 **App Secret**。**平台**选飞书或 Lark，API 基础地址随之确定。

所选接收人 ID 类型只用于 `direct_user`：

| 目标类型 | 目标值 |
|---|---|
| `direct_user` | 按**接收人 ID 类型**填写 `open_id`、`user_id`、`union_id` 或邮箱 |
| `fixed_address` | 邮箱；MoleSignal 使用 `receive_id_type=email` 发送 |
| `fixed_group` | 飞书群聊 ID；MoleSignal 使用 `receive_id_type=chat_id` 发送 |

应用用长连接接收事件后，Mole Agent 也能在飞书里回答，见[在 IM 里使用 Mole Agent](/zh-Hans/im#飞书)。

在 **Mole Agent → 设置 → IM 接入**里开启这个连接器后，经它发出的告警通知带确认、解决按钮，见[告警卡片](/zh-Hans/im#告警卡片)。

### 飞书 Webhook

把自定义机器人地址填入 **Webhook 地址**。如果机器人启用了签名校验，再填写**签名密钥**。MoleSignal 会为每次请求生成时间戳和 HMAC-SHA256 签名。

`fixed_group` 目标使用已配置地址，`webhook` 目标可以用另一个绝对 URL 覆盖。请求体与签名格式见 [Webhook 连接器](/zh-Hans/notification-channels/webhooks)。

### 钉钉 App

使用钉钉企业内部应用的机器人。填写应用的 **Client ID** 和 **Client Secret**。机器人没有单独的 RobotCode 时，**机器人 RobotCode** 留空，此时就是 Client ID。MoleSignal 用凭证换取访问令牌，再通过机器人发送 Markdown 消息。

| 目标类型 | 目标值 |
|---|---|
| `direct_user` | 应用可见范围内成员的钉钉 userId |
| `fixed_group` | 机器人所在群的 `openConversationId` |

机器人的消息用 Stream 模式接收后，Mole Agent 也能在钉钉里回答，见[在 IM 里使用 Mole Agent](/zh-Hans/im#钉钉)。再填上**互动卡片模板 ID**，告警通知就是一张带确认、解决按钮的互动卡片，模板怎么建见[钉钉的互动卡片](/zh-Hans/im#钉钉的互动卡片)。

### 钉钉 Webhook

把自定义机器人的地址填入 **Webhook 地址**。机器人开启了加签时，再填写**签名密钥**：MoleSignal 会为每次请求加上时间戳和 HMAC-SHA256 签名。`fixed_group` 目标使用已配置地址，`webhook` 目标会替换它。

### 企业微信 App

使用企业微信自建应用。填写**企业 ID**、应用的 **Secret** 和 **AgentId**。MoleSignal 用它们换取访问令牌，再发送 Markdown 消息，企业微信会在 4096 字节处截断。请把 MoleSignal 的出口地址加到应用的企业可信 IP。

| 目标类型 | 目标值 |
|---|---|
| `direct_user` | 应用可见范围内成员的 UserID |
| `fixed_group` | 应用创建的群聊 chatid |

填了**接收消息 Token** 和 **EncodingAESKey**，并把连接器的回调地址填到应用的**接收消息**以后，发给成员的告警通知是一张带确认、解决按钮的模板卡片，见[企业微信 App 的按钮](/zh-Hans/im#企业微信-app-的按钮)。

### 企业微信 Webhook

把群机器人的地址填入 **Webhook 地址**。`fixed_group` 目标使用它，`webhook` 目标会替换它。

### 企业微信智能机器人

企业微信的智能机器人（API 模式，用长连接接收消息）。填写机器人的 **Bot ID** 和长连接专用的 **长连接 Secret**；**长连接地址**固定为 `wss://openws.work.weixin.qq.com`。在 Mole Agent 的 IM 接入里开启以后，Mole Agent 能在企业微信里回答，见[在 IM 里使用 Mole Agent](/zh-Hans/im#企业微信)；机器人也发通知，消息与回复都走这条长连接。

| 目标类型 | 目标值 |
|---|---|
| `direct_user` | 机器人看到的成员 userid |
| `fixed_group` | 群的 chatid |

机器人只能发到有人给它发过消息的会话：私聊过它的人，有人 @ 过它的群。告警通知是一张带确认、解决按钮的模板卡片，其余通知是 Markdown。连着机器人的不是发通知的这台服务器时，通知交给连着的那台发，通常几秒内送到；哪台都没连着时这次投递失败。成员在这个连接器上的通知方式也用来认出 IM 里提问的人。

### Microsoft Teams 机器人

使用 Bot Framework 机器人。填写**应用 ID**、**客户端密码**和**租户 ID**；较早的多租户机器人，租户填 `botframework.com`。**云环境**选机器人所在的云：全球、GCC（美国政府社区云）、GCC High（美国政府）或 DoD（美国国防部），服务地址随之确定。GCC High 和 DoD 的令牌向 `login.microsoftonline.us` 申请，发给 Mole Agent 的消息按政府云的 Bot Framework 验证。机器人要先安装给要接收消息的人和团队。

| 目标类型 | 目标值 |
|---|---|
| `direct_user` | Teams 用户 ID（`29:…`）或此人的 Microsoft Entra 对象 ID |
| `fixed_group` | 频道或群聊的会话 ID（`19:…`） |

把 MoleSignal 给出的回调地址填到 Azure Bot 的 Messaging endpoint 后，Mole Agent 也能在 Teams 里回答，见[在 IM 里使用 Mole Agent](/zh-Hans/im#microsoft-teams)。

### Microsoft Teams Webhook

用 Workflows 流程（**收到 Webhook 请求时发布到频道**）创建频道 Webhook，或使用旧版 Incoming Webhook，把地址填入 **Webhook 地址**。MoleSignal 以 Adaptive Card 发送每条消息。

### Google Chat App

使用 Chat 应用的服务账号。把服务账号的 JSON 密钥粘贴到**服务账号密钥**；它随连接器加密保存，接口不会返回。MoleSignal 用这个密钥签名换取令牌，以应用的身份发送消息。密钥里的 `token_uri` 只能是 Google 的换令牌地址 `https://oauth2.googleapis.com/token`（早年的密钥是 `https://accounts.google.com/o/oauth2/token`），写了别的地址的密钥保存不了。

| 目标类型 | 目标值 |
|---|---|
| `direct_user` | 给应用发过消息或装了应用的用户（`users/123…`） |
| `fixed_group` | 应用所在的空间（`spaces/AAAA…`） |

填了 **Pub/Sub 订阅**（`projects/<项目>/subscriptions/<订阅>`）后，Mole Agent 也能在 Google Chat 里回答，见[在 IM 里使用 Mole Agent](/zh-Hans/im#google-chat)。只发通知时不用填。

### Google Chat Webhook

把空间的 Incoming Webhook 地址填入 **Webhook 地址**。`fixed_group` 目标使用它，`webhook` 目标会替换它。

### 电话与短信的号码

电话与短信连接器发给一个号码：成员绑定的手机号（`direct_user`），或兜底路由里的固定号码（`fixed_address`）。号码以 `+` 和国家码开头，例如 `+8613800138000`，空格和短横线会被去掉；阿里云、腾讯云、华为云和通用 HTTP 短信连接器也认 11 位内地手机号。

电话先念通知的标题，再念正文，最多 400 字；短信是标题一行、正文一行，最多 320 字。通知策略给电话或短信渠道选了模板时，念的、发的就是模板正文，不带标题。阿里云、腾讯云和华为云只发审核过的模板，模板编号与变量写在通知模板里，见[通知模板里的服务商模板](#通知模板里的服务商模板)。

服务商会限制同一号码被拨打、接收短信的频率。因为超限、号码有误或模板没通过而被拒时，这次投递失败，通知策略接着尝试此人的下一个通知方式和兜底路由。电话是否接通、有没有人听完不会回传：投递成功只表示服务商已经受理这通电话或这条短信。

同一个连接器给同一个号码一分钟只拨一次。一分钟内再来的通知排在这条线路上，投递记录显示**排队合并**；一分钟到了合并成一通电话，依次念各条通知的标题（套用电话模板的念模板正文），排队期间已被确认的不再拨；阿里云、腾讯云和华为云念第一条通知的模板，每个变量依次填各条通知的值。阿里云对同一号码本来就是每分钟一通，合并之后不会因为告警密集而被拒。通知策略设了更长的[合并通知](#合并通知)窗口时，按策略的窗口合并。

### 阿里云语音通知

使用阿里云语音服务的语音通知，只能拨内地号码。先在语音服务控制台完成企业资质，申请**文本转语音**的语音通知模板，例如 `您好，${content}，请尽快处理。`，再为一个 RAM 用户创建只能调用语音服务的 AccessKey。填写：

- **AccessKey ID** 与 **AccessKey Secret**；
- **区域** —— 从阿里云列出的地域里选，API 基础地址随之确定；
- **外显号码** —— 空着是公共模式；填专属模式里购买的号码时，来电显示这个固定号码，值班人可以把它存成联系人。模板的模式要与之一致；
- **播放遍数** —— 1 到 3 遍。

模板编号（以 `TTS_` 开头）与变量写在电话渠道的通知模板里，通知策略给电话渠道选它，见[通知模板里的服务商模板](#通知模板里的服务商模板)。阿里云对同一号码每分钟最多拨 1 次、每小时 5 次、每天 20 次，超出的呼叫会被拒绝。变量里不要放网址或 IP。

### 阿里云短信

在短信服务控制台申请**短信签名**和**通知类**模板，例如 `${content}，请尽快处理。`，再填写 AccessKey、**区域**和**短信签名**。区域从阿里云列出的地域里选，海外有的地域有自己的接入地址，API 基础地址随区域确定。模板编号（以 `SMS_` 开头）与变量写在短信渠道的通知模板里，通知策略给短信渠道选它，见[通知模板里的服务商模板](#通知模板里的服务商模板)。

通知类模板的每个变量默认最多 35 个字；企业用户向阿里云申请放宽后，可以在通知模板里调大**每个变量最多字数**。变量里不能放网址或 IP。号码可以是内地手机号，也可以是国际号码。

### 腾讯云语音消息

在语音消息控制台建应用（得到 `VoiceSdkAppid`），申请语音通知模板，再为一个子用户创建 API 密钥。填写 **SecretId**、**SecretKey**、**区域**（用这对密钥向腾讯云查，API 基础地址随之确定）、**应用 ID（SdkAppId）** 和 **播放遍数**（1 到 3 遍）。模板 ID 与变量写在电话渠道的通知模板里，变量按位置写成 `1`、`2`、`3`，见[通知模板里的服务商模板](#通知模板里的服务商模板)。

语音是预付费的：套餐用完后拨不出去，投递失败，投递记录写明 `InsufficientBalanceInVoicePackage`。这时通知策略接着尝试此人的下一个通知方式，所以别只留电话一种。生成的语音内容最多 350 字；单个变量的上限文档没写，超了会被拒（`ContentLengthLimit`），默认按 20 个字截断，放宽写在通知模板里。

### 腾讯云短信

在短信控制台建应用（得到 `SmsSdkAppId`），申请签名和模板，再填写 **SecretId**、**SecretKey**、**区域**、**应用 ID（SdkAppId）** 和 **短信签名**（签名的文字，不是编号；内地短信必填）。模板 ID 与变量写在短信渠道的通知模板里，变量按位置写成 `1`、`2`、`3`。

<Warning>
  2024 年 1 月 25 日以后开通的账号和长期闲置的账号，单个变量默认最多 **6 个字符**，超了被拒（`TemplateParameterLengthLimit`）。默认按 6 个字符截断，告警标题基本放不下。向腾讯云申请放宽后，把上限写在通知模板的**每个变量最多字数**里。变量里不能放网址。
</Warning>

接口整体成功不等于这个号码发出去了：要看这个号码的结果，不是 `Ok` 时这次投递失败，投递记录写明原因。

### 华为云语音通知

在语音通话控制台建应用、订购固话号码、提交语音模板。填写：

- **AppKey**、**AppSecret** 和 **APP 接入地址** —— 都在「应用管理」里。接入地址要照抄，没有接口能查；
- **外显号码** —— 订购的固话，写成国家码加区号加号码。

模板 ID 与变量写在电话渠道的通知模板里，变量按位置写成 `1`、`2`、`3`。每个变量最多 32 个字节，一个汉字占 3 个，超长的截断；变量里不能有 `$`、`{`、`}`，会被去掉。

### 华为云短信

在消息&短信控制台建应用、办理签名和模板。填写 **AppKey**、**AppSecret**、**APP 接入地址**（都在「应用管理」里）和 **通道号**（签名对应的那个）；通用模板还要写 **签名名称**。模板 ID 与变量写在短信渠道的通知模板里，变量按位置写成 `1`、`2`、`3`。每个变量的上限写在模板上（如 `TXT_20`），默认按 20 个字截断，别的上限写在通知模板里。

### Twilio 电话

在 Twilio 控制台找到 **Account SID** 与 **Auth Token**，再填写：

- **主叫号码** —— 账号里能打电话的号码，例如 `+14155550100`；
- **语言** —— 念通知用的语言，例如 `en-US`、`cmn-CN`；
- **声音** —— 可选，例如 `Polly.Joanna`、`Polly.Zhiyu`，空着用 Twilio 的默认声音；
- **播放遍数** —— 1 到 3 遍。

### Twilio 短信

填写 **Account SID**、**Auth Token** 和**发送方**。发送方可以是账号里的号码（E.164）、Messaging Service（`MG` 开头），或不超过 11 个字母和数字的字母发送方 ID（只在支持它的国家可用）。发往美国号码前，要先完成 A2P 10DLC 注册。

### AWS 语音与短信

AWS 语音（`aws_voice`）用 AWS End User Messaging 的 `SendVoiceMessage` 拨号，由 Amazon Polly 念通知；AWS 短信（`aws_sms`）用 `SendTextMessage` 发事务类短信。填写：

- **区域** —— 从账号开通的区域里选。列表用连接器的凭证向 AWS 查（EC2 的 `DescribeRegions`），凭证填好后才列出，其中没有 End User Messaging 的区域发送时会失败；
- **认证方式** —— 与数据接入的 AWS 连接器相同：访问密钥、临时密钥、节点身份、扮演角色或 Web Identity。扮演角色时，在角色的信任策略里要求页面给出的外部 ID；
- **发送方身份** —— 号码、号码 ID、号码池 ID 或它们的 ARN。语音必填，而且号码要能打电话；短信可以不填，由 AWS 按目的地选号码，也可以填发送方 ID；
- **Polly 声音** —— 仅语音，可选，空着是 `MATTHEW`，中文用 `ZHIYU`；
- **API 基础地址** —— 随区域确定，例如 `https://sms-voice.us-east-1.amazonaws.com`。

所用身份需要 `sms-voice:SendVoiceMessage` 或 `sms-voice:SendTextMessage` 权限，列出区域还需要 `ec2:DescribeRegions`。还在沙盒里的 AWS 账号只能发给验证过的号码。

### 通用 HTTP 短信

把短信按配置好的 HTTP 请求交给自己的短信网关，或交给还没有专门连接器的服务商。填写：

- **网关地址** —— 请求发往的地址，可以带占位符，例如 GET 网关的 `https://sms.example.com/send?to={{phone}}&msg={{content}}`；
- **HTTP 方法** —— POST、PUT 或 GET，GET 不带请求体；
- **请求体格式**与**请求体** —— JSON 或表单（`x-www-form-urlencoded`），默认是 `{"phone": "{{phone}}", "content": "{{content}}"}`；
- **请求头（JSON）** —— 例如 `{"Authorization": "Bearer {{secret}}"}`；
- **密钥** —— 网关要的令牌或密码，加密保存，在地址、请求头和请求体里写 `{{secret}}` 引用；
- **号码写法** —— `+8613800138000`（E.164）、`8613800138000`（不带 +），或 `13800138000`（内地号码不带国家码）；
- **成功字段**与**成功值** —— 可选。网关返回 2xx 就算发出；填了成功字段（例如 `code` 或 `result.status`），还要回应 JSON 里这个字段的值等于成功值。

| 占位符 | 填进去的值 |
|---|---|
| `{{phone}}` | 收短信的号码，按号码写法 |
| `{{content}}` | 短信内容：标题一行、正文一行，最多 320 字 |
| `{{title}}` | 通知标题 |
| `{{text}}` | 通知正文 |
| `{{secret}}` | 密钥 |

值按所在位置转义：JSON 请求体里按 JSON 字符串转义，表单和地址里按 URL 编码。号码和内容至少要写在请求的某一处，否则连接器保存不了。

### 通用 Webhook

填写默认地址，选择 `POST`、`PUT` 或 `PATCH`，再选**请求体**：

- **MoleSignal 事件** —— 默认。写给机器读的 JSON：版本、事件、告警、规则和升级，加上目标和渲染好的消息；
- **通知模板正文** —— 通知策略给 Webhook 渠道选的模板正文原样作为请求体，JSON 格式的模板按 JSON 发，见[条件](#条件)和[模板的格式](#创建模板和策略)。

每个请求都带 `X-MoleSignal-Event`（通知类型）和 `X-MoleSignal-Delivery`（投递 ID，接收方用来去重）。填了**签名密钥**（至少 16 个字符）时还带 `X-MoleSignal-Timestamp` 和 `X-MoleSignal-Sign`，接收方据此确认请求来自 MoleSignal。请求体的字段、签名的算法和校验示例见 [Webhook 通知连接器](/zh-Hans/notification-channels/webhooks#通用-webhook)。

`direct_user`、`fixed_address` 和 `fixed_group` 会请求已配置的默认地址，并把目标作为路由数据放入请求体。`webhook` 会用目标值替换默认地址。2xx 响应表示成功；响应包含 `X-Request-ID` 时，MoleSignal 会把 Header 值记录为服务商消息 ID。Webhook 不参与[合并通知](#合并通知)，每条通知各发一个请求。

<Warning>
  Webhook 地址、Authorization Header、Token、密码和签名密钥都属于凭证。不要把凭证值写入测试目标、通知模板或事件属性。
</Warning>

## 绑定用户通知方式

管理员可以打开**设置 → 通知 → 用户通知**，选择成员，再点击**绑定通知方式**。每个通知身份会选择一个连接器和一个外部身份，例如邮箱、Slack 用户 ID、飞书用户 ID，或电话与短信连接器用的手机号。

绑定后按以下步骤配置：

1. 发送测试，确认服务商接受该身份；
2. 组织确认归属后，将身份标记为已验证；
3. 在**告警事件**、**值班通知**或**报告**偏好中启用该身份；
4. 有多个身份时，按主用到备用的顺序排列；
5. 按需配置免打扰时段，并决定严重告警能否绕过免打扰。

### 没人确认就换下一种方式

告警事件的接收顺序里，第二步起可以填等待的分钟数：

| 设置 | 效果 |
|---|---|
| 第一步 | 告警触发或升级到此人时立即发送。 |
| 等待 N 分钟 | 从第一次通知此人算起，N 分钟后仍没人确认告警，就用这一步再发一次。 |
| 与上一步相同的分钟数 | 只在上一步发送失败时使用。 |

例如飞书（立即）、短信（3 分钟后）、电话（5 分钟后）：告警被确认或解决后，后面的步骤都不再发，这个告警各次升级发给其他人的也一样。发送失败的一步照旧立即换下一步。等待时间最长一天，只对告警事件生效；值班通知和报告的接收顺序只做失败兜底。

成员可以在**账号设置 → 通知设置**中管理个人身份和偏好。读取其他成员设置需要 `org.members.read`，修改或确认其他成员身份需要 `org.members.update`。

<Note>
  删除通知身份前，先从所有投递偏好中移除该身份。
</Note>

## 回复短信与电话按键

电话和短信连接器打开**回复处理告警**（电话连接器叫**按键处理告警**）后，收到告警的人不用打开 MoleSignal 就能处理：

- **短信** —— 告警触发和升级的短信末尾写着「回复 31 确认，32 解决。」，回复其中一个代码即可。十位数是这个号码轮换使用的序号（0 到 9），个位 1 是确认、2 是解决；只回 `1` 或 `2` 时处理这个号码最近收到的那条。合并成一条的短信，一个代码处理里面全部告警。代码一天内有效；
- **电话** —— 念完告警后按 1 确认、按 2 解决，电话里随即说明处理结果。

回复和按键以收到这条消息的成员的身份处理，要有 `alerts.incidents.acknowledge`，账号和组织都要在用；时间线上记作「回复短信」或「电话按键」。只有发给成员本人的消息带代码，发到兜底路由里固定号码的不带。

服务商要把回复、按键推到 MoleSignal 的回调地址，所以要配置对外地址 `http.external_url`，并且公网能访问 `/api/v1/public/notify/` 下的路径，见[公网访问](/zh-Hans/public-access)。打开开关并保存连接器后，连接器页显示回调地址，可以复制：

| 连接器 | 要做什么 | 回调怎样验证 |
|---|---|---|
| Twilio 短信 | 在号码的 Messaging 设置里，把 **A message comes in** 设为 Webhook、HTTP POST，填回调地址。 | Twilio 的签名 `X-Twilio-Signature`，用连接器的 Auth Token 校验。 |
| Twilio 电话 | 不用配：每通电话自带按键地址。 | Twilio 的签名。 |
| AWS 短信 | 号码开通双向短信，把回复发到一个 SNS 主题；在主题下加一个 HTTPS 订阅，端点填回调地址，订阅自动确认。可以在**回复的 SNS 主题 ARN** 里填这个主题，只认它推来的回复。 | SNS 消息的签名，证书只从 `sns.<区域>.amazonaws.com` 取。 |
| 阿里云短信 | 在短信服务的上行短信设置里选 HTTP 推送，填回调地址。阿里云只发审核过的模板，代码要写进模板：模板参数填变量 `{{reply.ack}}`、`{{reply.resolve}}`，见[模板变量](#模板变量)。 | 地址里的回调 Token。 |
| 阿里云语音通知 | 改用交互式语音（IvrCall）拨打，要填**外显号码**（为 IvrCall 购买的真实号码）；在语音服务的回执设置里选 HTTP 推送，填回调地址。念完模板后等 10 秒按键。 | 地址里的回调 Token。 |
| 腾讯云短信 | 在短信控制台的回调设置里，把回复短信回调的地址填成回调地址。代码要写进模板：模板变量填 `{{reply.ack}}`、`{{reply.resolve}}`。 | 地址里的回调 Token。 |
| 腾讯云语音消息 | 在语音消息控制台的事件回调设置里，把按键回调的地址填成回调地址。模板里自己写上「按 1 确认，按 2 解决」。按键只带被叫号码，按这个号码最近的一通电话处理。 | 地址里的回调 Token。 |
| 华为云短信 | 创建短信应用时把上行短信接收地址填成回调地址。代码要写进模板，同上。 | 地址最后一段的回调 Token。 |
| 华为云语音通知 | 在应用管理里把呼叫状态接收地址填成回调地址。放音后收一位按键，模板里自己写上「按 1 确认，按 2 解决」。 | 地址最后一段的回调 Token。 |
| 通用 HTTP 短信 | 让网关把收到的短信以 JSON `{"phone": "…", "text": "…"}`（或这样的数组）POST 到回调地址。 | 地址里的回调 Token。 |

回调 Token 由服务端的根密钥按连接器算出，不另外保存；地址要当作凭证保管。AWS 的语音消息收不到按键，`aws_voice` 没有这个开关。

## 创建模板和策略

打开**设置 → 通知 → 通知模板**，创建可复用的消息正文。选择通知类别和渠道，插入[变量](#模板变量)或从[预置模板](#预置模板)开始，再用预览事件属性检查渲染结果。编辑器右侧的变量、预置模板和预览事件属性默认收起，点标题展开。模板列表按渠道分类。

| 渠道 | 用在哪 | 正文 |
|---|---|---|
| **通用** | 通知策略没有另选模板的每个渠道。 | 纯文本、Markdown 或 HTML。 |
| **即时通讯**、**邮件**、**Webhook** | 只给这个渠道。 | 纯文本、Markdown 或 HTML；即时通讯模板还可以[发成卡片](#即时通讯模板的卡片)，Webhook 模板还可以是 JSON：变量的值按 JSON 字符串转义，填好后要是合法的 JSON，用在[通用 Webhook](#通用-webhook) 的**通知模板正文**里。 |
| **短信**、**电话** | 只给这个渠道。 | 纯文本，就是发出去的全部内容，不带通知标题；短信最多 320 字，电话最多念 400 字，编辑器里显示字数。 |

然后打开**通知策略**并创建路由规则：

1. 选择事件类型和通知类别；
2. 添加 JSON 匹配条件并设置策略优先级；在 **时间** 里选 **只在这些时段** 或 **只在这些时段以外**，把策略限定在每周的几段时间里，按通知事件发生的时刻判断，时段还能按[节假日日历](/zh-Hans/alerting/on-call#节假日日历)算。不满足时这条策略不发，其他策略照常匹配；
3. 选择接收人解析器和解析器配置；
4. 选择尊重用户偏好、强制一个连接器或通过多个连接器发送；
5. 选择通用模板，按需给即时通讯、电话、短信等渠道另选这个渠道的模板，并启用用户、团队或组织兜底；
6. 按需设置确认超时和升级路由；告警类策略还可以设置[合并通知](#合并通知)；
7. 检查实时投递预览；预览会解析真实用户和路由，写明每一步用哪个模板，但不会发送消息。

投递时按连接器所属的渠道挑模板：有另选的用另选的，没有的用通用模板，都没有时发事件默认的消息。被通知策略用着的模板不能删除，也不能改渠道。

策略当前覆盖告警生命周期和值班排班事件。策略编辑器会列出运行中后端支持的事件类型和接收人解析器。命中[静默](/zh-Hans/alerting/silences)的告警事件，策略先不投递，参见[静默期间的通知](/zh-Hans/alerting/silences#静默期间的通知)。

### 合并通知

告警密集时，同一个人、同一个群可能在几十秒里收到一串通知。告警和告警升级类的通知策略有**合并通知**：选 30 秒、1、2 或 5 分钟（接口允许 10 秒到 10 分钟），窗口里发给同一个接收人、经同一个连接器的告警通知合成一条：第一条照常立刻发，其余等窗口结束一起发，排队期间被确认的不再发。

- 即时通讯和邮件发一条清单：标题是第一条的标题加「(+N)」，正文逐条列出告警，有对外地址时链到各自的事件；飞书 App、Slack App 的卡片上有**全部确认**，见[告警卡片](/zh-Hans/im#告警卡片)；
- 短信和电话依次写、念各条的标题，短信回复一个代码处理全部；电话本来就至少合并 60 秒；
- Webhook 不合并。

内置的告警触发、恢复和升级策略默认合并 1 分钟，其余策略默认**不合并**。

### 模板变量

正文、阿里云模板的变量和卡片的各处都可以写变量，例如 `{{rule.name}}`，发送时换成这条通知的值。编辑器右侧的**变量**列出这个通知类别能用的变量，点一个插入到光标处。名字以 `_at` 结尾的是微秒时间戳，以 `_time` 结尾的是 UTC 时间，例如 `2026-07-29 00:00:00 UTC`。事件里没有的变量照原样留在正文里。

告警、告警升级的变量：

| 变量 | 值 |
|---|---|
| `{{rule.name}}`、`{{rule.description}}` | 规则的名称和说明。 |
| `{{severity}}`、`{{incident.status}}` | 严重度和告警的状态。 |
| `{{urgency}}`、`{{priority}}` | 紧急度档位的键（`high`、`low`，或组织加的档）和优先级（`P1` 到 `P9`，没设时为空），见[紧急度](/zh-Hans/alerting/on-call#紧急度)。通知策略也能按事件属性 `urgency`、`priority` 匹配。 |
| `{{urgency_name}}`、`{{priority_name}}` | 组织在[紧急度与优先级档位](/zh-Hans/alerting/on-call#紧急度与优先级档位)里给紧急度和优先级起的名称；没起名时为空。 |
| `{{value}}`、`{{threshold}}` | 触发时的值和阈值。分档的规则是与告警严重度相同那一档的阈值；异常检测规则没有阈值，写成 `null`。 |
| `{{incident.url}}` | 告警在 MoleSignal 里的地址，要配置对外地址 `http.external_url`。 |
| `{{incident.started_time}}`、`{{incident.duration}}` | 告警开始的时间和持续了多久，例如 `1h 5m`；恢复了的告警算到恢复为止。 |
| `{{incident.acknowledged_time}}`、`{{incident.acknowledged_by}}` | 确认的时间和确认人的用户 ID，确认过才有。 |
| `{{incident.resolved_time}}`、`{{incident.resolved_by}}` | 解决的时间和解决人的用户 ID，解决了才有；自己恢复的告警没有解决人。 |
| `{{incident.assignees}}`、`{{affected_services}}` | 处理人的用户 ID 和受影响的服务，用逗号分隔。 |
| `{{service}}`、`{{environment}}` | 服务和环境，取自告警的标签或注解。 |
| `{{labels}}`、`{{labels.<key>}}` | 全部标签（`service=api, env=production`）和其中一个标签的值；注解是 `{{annotations.<key>}}`。 |
| `{{escalation.step}}`、`{{escalation.loop}}`、`{{escalation.target}}` | 升级到第几层、第几轮（都从 1 数起）和这一层通知谁（`user`、`schedule` 或 `team`），只在升级通知里有。 |
| `{{escalation.reason}}` | 为什么发这条升级通知：`step`（照常升级）、`manual`（立即升级）、`reassigned`（转派）、`responder_added`（增派）、`snooze_ended`（暂缓到点）、`ack_timeout`（确认后超时未解决）、`severity_raised`（调高了严重度）或 `urgency_raised`（紧急度升为高），见[处理事件](/zh-Hans/alerting/incidents#处理事件)。 |
| `{{reply.ack}}`、`{{reply.resolve}}` | 回复确认、解决的代码，例如 `31`、`32`；只在打开了[回复处理告警](#回复短信与电话按键)的短信连接器发出的告警短信里填上，别处原样留下。 |

值班排班有 `{{schedule.*}}`、`{{oncall.*}}` 与 `{{override.*}}`；交接时间和替班时段除了微秒的 `_at`，也有可读的 `{{oncall.transition_time}}`、`{{override.start_time}}` 与 `{{override.end_time}}`。每类通知都能用 `{{event.time}}`、`{{message.title}}`、`{{message.text}}`，以及事件的任意属性 `{{event.attributes.<key>}}`。

### 条件

正文里可以写条件块，条件成立时才留下中间的内容：

```text
{{#if severity == "critical"}}立即处理{{else}}请关注{{/if}}：{{rule.name}}
{{#if event.type == "alert.resolved"}}已恢复，持续 {{incident.duration}}{{/if}}
{{#if annotations.runbook_url}}处理手册：{{annotations.runbook_url}}{{/if}}
```

- `{{#if 变量 == "值"}}` 和 `!=` 比较变量的值；只写变量时，变量有值、不是空的就成立；
- `{{else}}` 是条件不成立时留下的内容，可以不写；
- 条件块可以嵌套，最多 5 层；没写完的块（少了 `{{/if}}`）保存不了，编辑器在正文下方指出哪里不对；
- 预览按预览事件属性判断条件。编辑器右侧的**条件**里有几个常用写法，点一下插入。

### 预置模板

**预置模板**是写好的正文，套用后可以接着改。它按通知类别和渠道列出：短信、电话模板只列给短信、电话写的；即时通讯、邮件模板还有专给这个渠道写的，例如带告警链接的即时通讯 Markdown、排成表格的告警邮件。告警有触发、确认、恢复几种通知的预置模板；套用确认或恢复的预置模板时，预览改用确认、恢复了的示例告警。预置模板的正文跟着界面语言，中文界面套用的是中文正文。

### 通知模板里的服务商模板

阿里云、腾讯云和华为云只发审核过的模板。短信或电话模板里可以给每家各写一份：

- **模板编号** —— 服务商给的编号：阿里云短信以 `SMS_` 开头、语音以 `TTS_` 开头，腾讯云和华为云是它们的模板 ID；
- **变量** —— 每个变量填什么，写法与正文一样，可以用变量，例如 `{{rule.name}}`。阿里云的变量名是模板里 `${…}` 中的名字；腾讯云和华为云按位置填，变量名写 `1`、`2`、`3`；
- **每个变量最多字数** —— 超出的截断。空着时按默认：阿里云 35 字，腾讯云短信 6 字、语音 20 字，华为云短信 20 字、语音 32 字（语音还按 32 字节截）。

这三家的连接器发写给自己的那一份，其他短信、电话连接器发模板正文。通知策略给这个渠道选的模板没有写给这家的那一份时，这家连接器的投递失败，投递记录写明原因。

测试这三家的连接器时，选一个这个渠道里写了给这家的模板的模板，占位符填示例值；测试成员绑定在这家连接器上的号码时，用按名称排第一个这样的模板。定时巡检、自动化这类直接发送的内容不是通知模板，不能选这三家的连接器。

### 即时通讯模板的卡片

即时通讯模板可以打开**发成卡片**，App 与群机器人都发卡片；关掉时照旧发文本。卡片的正文就是模板的消息正文，另外可以写：

- **卡片标题** —— 空着用通知的标题；
- **标题颜色** —— 按严重度（严重红、错误橙、警告黄，其余蓝，恢复了是绿），或固定一种颜色；
- **字段** —— 名称与值，例如 `服务` 填 `{{labels.service}}`，最多 10 个；
- **链接按钮** —— 按钮文字与地址，例如 `处理手册` 填 `{{annotations.runbook_url}}`，最多 5 个；
- **页脚** —— 卡片最下面的一行小字。

各处都可以用变量。填不出值的字段与链接不显示，地址不是 http(s) 的链接也不显示。编辑器里的预览是卡片的大致样子，各平台按自己的卡片发出：

| 平台 | 发成什么 |
|---|---|
| **飞书** | 交互卡片：标题栏按颜色上色，字段两列排，页脚在分隔线下；App 的链接按钮与告警的确认、解决按钮排在一起。 |
| **Slack** | 带颜色条的 Block Kit 卡片；App 的链接按钮与告警按钮排在一起。 |
| **钉钉** | ActionCard：标题上色，链接是卡片下面的按钮，最多 5 个；没有链接时发 Markdown。App 填了互动卡片模板 ID 时，告警通知按这个模板发互动卡片，带告警按钮。 |
| **企业微信** | 排成卡片样子的 Markdown，标题按颜色上色（企业微信只有绿、灰、橙三种字色）。带告警按钮时是按钮交互型的模板卡片：字段是二级标题加文本，最多 6 个，点卡片打开 MoleSignal。 |
| **Teams** | Adaptive Card：标题栏按颜色上色，字段是一组事实，链接是按钮，页脚在分隔线下；机器人的链接按钮与告警按钮排在一起。 |
| **Google Chat** | 卡片：字段是带名称的一行行文字，链接是按钮，App 的链接按钮与告警按钮排在一起；Google Chat 的卡片标题没有颜色。 |

群机器人收不到点击，卡片上没有告警的确认、解决按钮。测试连接器时可以选一个即时通讯模板，发出它的卡片，变量填示例值。

### 内置策略

每个组织建立时自带下面这些通知策略，不用先建策略，告警和值班事件就能通知到人。它们都**尊重用户偏好**，发不出去时依次使用用户备用端点、团队兜底路由和组织兜底路由；不选模板，发事件默认的消息。

| 内置策略 | 事件 | 通知谁 | 默认 |
|---|---|---|---|
| 告警触发：通知负责人 | 告警触发 | 告警的负责人，没有负责人时是处理人 | 开启 |
| 告警恢复：通知负责人 | 告警已恢复 | 告警的负责人，没有负责人时是处理人 | 开启 |
| 告警升级：通知这一步的人 | 告警已升级，升级到人 | 这一步指定的人 | 开启 |
| 告警升级：通知这一步的团队 | 告警已升级，升级到团队 | 这个团队的成员 | 开启 |
| 值班交接：通知交接的两个人 | 值班即将开始 | 交班和接班的人 | 开启 |
| 值班空档：通知值班表管理人 | 值班无人覆盖 | 值班表的管理人 | 开启 |
| 告警确认：通知负责人 | 告警已确认 | 告警的负责人，没有负责人时是处理人 | 关闭 |
| 值班替班：通知相关的人 | 已创建临时替班 | 替班的人和原来值班的人 | 关闭 |
| 换班：通知相关的人 | 换班申请有变化 | 这一步该知道的人，见[换班申请](/zh-Hans/alerting/on-call#换班申请) | 开启 |
| 接班人收不到告警：通知本人和排班管理员 | 接班人收不到告警（班次开始前 30 分钟） | 接班的人和排班管理员，见[收不到告警的成员](/zh-Hans/alerting/on-call#收不到告警的成员) | 开启 |
| 接入预算快用完：通知预算指定的人 | 接入预算快用完 | 预算指定的人，见[设预算](/zh-Hans/streams#设预算) | 开启 |
| 接入超出预算：通知预算指定的人 | 接入超出预算 | 预算指定的人，见[设预算](/zh-Hans/streams#设预算) | 开启 |
| 重大事件进展：通知关注人 | 重大事件进展 | 事件的负责人、各角色和关注人，见[发进展](/zh-Hans/alerting/major-incidents#发进展) | 开启 |

内置策略在**通知策略**列表里标着**内置**，可以修改、停用，不能删除，名称也不能改；改过的在编辑器里选**恢复默认**，回到上表的设置。升级到值班表的步骤没有内置策略，要按值班表另建一条接收人为**当前值班人**的策略。

## 配置兜底路由

打开**设置 → 通知 → 兜底路由**。选择组织或团队范围，再选择通知类别。添加一个或多个已启用的连接器，选择 `fixed_address` 或 `fixed_group`，并填写服务商目标。

已启用的个人路由阶段失败后，MoleSignal 会按页面显示顺序尝试兜底路由。通知策略决定是否启用用户、团队和组织兜底。

## 查看和重试投递

打开**设置 → 通知 → 投递记录**，按事件 ID、状态或阶段筛选。选择一条记录，可以查看脱敏目标、连接器、耗时、服务商错误和完整投递链路。

- `notify.deliveries.read` 可以查看投递历史；
- `notify.deliveries.acknowledge` 可以确认来源事件；
- `notify.deliveries.retry` 可以重试失败路由。

重试会创建新的投递尝试，不会修改已有历史。

阶段为 **直接发送** 的投递来自自行指定连接器和目标的功能，例如[定时日志巡检](/zh-Hans/logs/inspections)。直接发送不经过通知策略，也不能重试。

## 连接器生命周期与状态

| 状态 | 含义 |
|---|---|
| **未知** | 连接器还没有完成过成功或失败的测试。 |
| **已连接** | 最近一次测试成功。 |
| **异常** | 最近一次测试失败；后续测试成功前，正常路由会跳过该连接器。 |
| **已停用** | MoleSignal 不会通过该连接器测试或投递。 |

停用连接器不会删除引用。用户身份、通知策略、兜底路由或定时日志巡检仍引用连接器时，不能删除连接器。先迁移这些引用，再删除连接器。

## 排查投递问题

| 现象 | 检查项 |
|---|---|
| SMTP 身份验证或 TLS 失败 | 检查主机、端口、凭证、TLS 模式、发件地址、DNS 和出向网络。 |
| Slack 返回 API 错误 | 检查 Bot Token、`chat.postMessage` 权限、目标 ID 和频道成员关系。 |
| 飞书拒绝消息 | 检查应用权限、接收人 ID 类型、群聊成员关系、Webhook 密钥和服务器时间。 |
| Webhook 返回错误 | 检查 URL、方法、Header JSON、超时，以及对端是否返回 2xx。 |
| 用户没有收到通知 | 检查身份和连接器是否启用、类别偏好是否包含该身份，以及免打扰是否生效。 |
| 兜底路由没有执行 | 检查策略是否启用该层兜底，以及对应类别是否存在已启用路由。 |
| 电话或短信没有发出 | 检查号码是否以 + 和国家码开头、模板与签名是否已审核、通知策略给这个渠道选的模板是否写了阿里云模板、变量名是否一致，以及服务商的频率限制和账号沙盒。 |
| 回复短信或按键没有生效 | 检查连接器是否打开了**回复处理告警**、服务商的回调是否指向连接器页显示的地址、公网能否访问这个地址、这个号码是否收到过带代码的告警短信、代码是否已过一天，以及收信的成员是否有 `alerts.incidents.acknowledge`。 |
