MoleSignal 提供带版本的 HTTP API。产品端点使用 `/api/v1`。健康探针、Prometheus 指标、公开共享链接和少数兼容协议也会使用其他路径。

## 基础 URL

本地实例：

```text
http://localhost:5080/api/v1
```

生产环境请把主机替换为部署的对外地址，也就是 `[http].external_url` 的值。

## 身份验证

受保护的端点在 `Authorization` 请求头中接受 Bearer Token：

```http
Authorization: Bearer <token>
```

| Token | 获取方式 | 有效期 |
|---|---|---|
| 登录 Token（JWT） | 用邮箱和密码调用 `POST /api/v1/auth/signin`，参见[登录](/zh-Hans/api/auth/login)。 | 默认 24 小时。 |
| API Token | **身份与访问 → API tokens**，或[签发 API Token](/zh-Hans/api/auth/issue-token)。格式形如 `ms_<prefix>_<secret>`。 | 直到被撤销，或到所选的过期时间。 |
| 默认接入 Token | `GET /api/v1/auth/tokens/default`，仅限 `streams.write`。 | 不会过期。 |
| RUM Client Token | `GET /api/v1/auth/tokens/rum?application_id=<id>`，仅限 `rum.write`。 | 不会过期。 |

脚本和采集器请使用 API Token。登录 Token 会过期，并让使用它的发送端中断。接入 Token 的细节参见[数据源](/zh-Hans/intake#接入-token)。

身份验证会生成包含主体、当前组织或平台范围，以及实际生效权限的 IAM 上下文。请求所属的组织始终来自这个上下文，请求体无法选择其他组织。

## 公开与自验证路由

少数路由无法使用组织的 Bearer Token，它们会改为验证范围更窄的凭据或策略：

- 登录、注册策略与密码重置；
- `GET /api/v1/healthz` 与顶层的 `/metrics`；
- 公开资源共享的交换与共享会话请求；
- 签名文件下载与公开头像；
- 推送型连接器端点，它们验证推送 Token。

公开路由并非不受限制。对应的处理逻辑会检查注册策略、共享 Token、下载 Token、签名或连接器凭据。

## 授权

一个端点可能要求以下一个或多个条件：

- 组织权限，例如 `streams.query`；
- 平台权限，例如 `sys.telemetry.read`；
- 对资源的所有权、与资源的关系，或跨组织授权。

`GET /api/v1/iam/capabilities` 返回当前主体实际生效的权限。不要根据角色名称或可见的菜单项推断访问能力。

## 请求

- 大多数请求体是 JSON，使用 `Content-Type: application/json`。
- 兼容类接入端点使用各自协议的载荷，例如 Protobuf、NDJSON 或 gzip 压缩的请求体。
- 超过 2 MiB 的接入请求体会被拒绝并返回 `413`。
- 以 `_micros` 结尾的字段保存以微秒表示的 Unix 时间。原生遥测记录使用 `_timestamp`，同样以微秒计。
- 路径中的 id 和数据流名称需要做 URL 编码。

## 响应与错误

成功的响应是 JSON，除非端点以流或文件的形式返回。错误响应包含状态码，以及带有机器可读的 `error` 码和 `message` 的 JSON 响应体：

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

`validation_failed` 错误还会附带 `issues` 数组，每个无效字段一项。

| 状态码 | `error` | 含义 |
|---|---|---|
| `400` | `invalid_argument`、`validation_failed` | 请求或其中某个参数无效。 |
| `401` | `unauthorized` | Token 缺失、格式错误、无效或已过期。 |
| `403` | `forbidden` | 缺少权限、关系或范围。 |
| `404` | `not_found` | 资源不存在，或在授权范围内不可见。 |
| `409` | `conflict` | 状态或唯一性冲突。 |
| `413` | `payload_too_large` | 请求体超出限制。 |
| `429` | `resource_exhausted` | 触发了速率限制，如果有 `Retry-After` 响应头，请遵循它。 |
| `499` | `cancelled` | 请求已被取消。 |
| `503` | `unavailable` | 依赖不可用。 |
| `500` | `internal` | 内部故障。响应体中的 message 为 `internal error`，详细信息只保留在服务端日志中。 |

请求体无法解析时，请求在到达端点之前就会失败，此时的响应是纯文本而不是 JSON：

| 状态码 | 含义 |
|---|---|
| `400` | 请求体不是有效的 JSON。 |
| `415` | 请求缺少 `Content-Type: application/json`。 |
| `422` | 字段缺失或类型错误，文本中会指出字段名。 |

每个响应都带有 `X-Request-Id` 与 `X-Trace-Id` 响应头。报告服务端故障时请同时提供这两个值。

## 分页

可能返回大量行的端点接受 `limit` 与 `cursor`，这类响应包含 `items` 与 `next_cursor`。把 `next_cursor` 作为 `cursor` 传回即可读取下一页，为空时停止。其他列表端点会返回完整列表，具体见各端点页面。

## 查询与长耗时任务

查询族接口返回普通 JSON、以流的形式返回 NDJSON，并把耗时较长的查询作为异步搜索任务运行。规模过大的查询会返回 `202`，并带有 `job_id` 与 `monitor` 路径。流式调用方需要处理部分数据到达的情况，并在不再需要结果时取消请求，参见[查询](/zh-Hans/query)。

生成的报告、Profile 数据块和导出文件等大体积产物，通过限定范围的下载 Token 以文件形式交付，而不是放在 JSON 响应体中。
