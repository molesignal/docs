MoleSignal 读取一个 TOML 文件和 `MS_` 环境变量。请以每个发布版附带的示例文件 `conf/config.toml` 为起点。示例文件列出了全部配置项，本页对每一项都有说明。

```bash
molesignal --config /etc/molesignal/config.toml
```

## 配置如何加载

配置项按以下顺序生效，后面的来源覆盖前面的。

1. 内置默认值。
2. 通过 `--config` 传入的 TOML 文件。
3. `MS_` 环境变量。

修改配置后需要重启进程。运行中的进程只会在日志中记录文件的变化，不会应用它们。

<Note>
  大多数配置段会忽略它没有定义的键，所以拼写错误既不生效也没有警告。`[meta_database]`、`[object_store]`（包括 `[object_store.retry]`）、`[telemetry]`（包括 `[telemetry.trace]` 与 `[telemetry.self_collect]`）、`[apm]`、`[probe]`、`[otlp_grpc]`、`[notify]` 与 `[scheduled_reports.renderer]` 则相反：出现未知键时，进程会在启动时退出。
</Note>

参考表中的 **默认值** 列取自示例文件 `conf/config.toml`。缺少某个键时使用的内置值与之不同的，会在说明中注明。

## 环境变量

每个配置项都有对应的环境变量：先写 `MS_` 前缀，再把配置路径的每一层转为大写，并用单个下划线连接。

| 配置项 | 环境变量 |
|---|---|
| `[http].port` | `MS_HTTP_PORT` |
| `[meta_database].dsn` | `MS_META_DATABASE_DSN` |
| `[cluster].advertise_addr` | `MS_CLUSTER_ADVERTISE_ADDR` |
| `[node].roles` | `MS_NODE_ROLES` |

列表使用 TOML 语法，例如 `MS_NODE_ROLES='["intake","querier"]'`。包含点号或双下划线的名称不会被识别。

以下变量独立于配置项读取：

| 变量 | 用途 |
|---|---|
| `MS_CIPHER_KEY` | MoleSignal 加密保存在 PostgreSQL 中的密文所用的根密钥。取 32 个随机字节并以 base64 编码。缺少它时，进程回退到全零的开发密钥并记录警告。更换密钥前必须执行 `rewrap-kek`，参见[生产检查清单](/zh-Hans/production-checklist)。 |
| `MS_AUTH_JWT_SECRET_OVERRIDE` | 固定 JWT 签名密钥，取代首次启动时在 PostgreSQL 中生成的密钥。 |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN` | 为分角色节点之间转发的链路候选与自遥测做认证的共享密钥。启用[链路捕获](#链路捕获与尾部采样)（默认启用）或 `[telemetry.self_collect]` 时，每个分角色节点都要设置相同的值，没有 `intake` 角色的节点缺少它会拒绝启动。 |
| `MS_AGENT_OPENAI_API_KEY`、`MS_AGENT_ANTHROPIC_API_KEY`、`MS_AGENT_COMPATIBLE_API_KEY` | Mole Agent 模型服务商的开发用回退 API Key，各自有对应的 `_BASE_URL` 变量。生产环境请在产品中配置服务商。 |
| `RELEASE_CHANNEL` | 标记部署成熟度：`alpha`、`beta`、`rc` 或 `stable`。 |
| `RUST_LOG` | 设置后覆盖 `[telemetry].log_level`。 |
| `AZURE_STORAGE_ACCOUNT`、`AZURE_STORAGE_ACCESS_KEY` | `azure` 对象存储后端的 Azure Blob 凭据。 |
| `GOOGLE_APPLICATION_CREDENTIALS` | `gcs` 对象存储后端使用的服务账号 JSON 文件路径。 |

## 最小生产配置

生产节点至少需要以下配置，文件的其余部分可以保持默认值。

```toml
[http]
external_url = "https://molesignal.example.com"

[meta_database]
dsn = "postgres://molesignal:<password>@db.internal:5432/molesignal"

[object_store]
backend = "s3"
bucket = "molesignal"
region = "us-east-1"
endpoint = ""          # AWS S3 留空，兼容 S3 的服务填写服务地址
access_key = ""        # 建议改用 MS_OBJECT_STORE_ACCESS_KEY
secret_key = ""        # 建议改用 MS_OBJECT_STORE_SECRET_KEY

[wal]
dir = "/var/lib/molesignal/wal"

[auth]
root_email = "admin@example.com"
root_password = "<初始密码>"
```

同时在环境中设置 `MS_CIPHER_KEY`。上线前的完整步骤参见[生产检查清单](/zh-Hans/production-checklist)。

## 节点

`[node]` 选择进程运行的角色，参见[分角色部署](/zh-Hans/distributed-deployment)。

| 键 | 默认值 | 说明 |
|---|---|---|
| `roles` | `["standalone"]` | 要运行的角色：`standalone`、`router`、`intake`、`querier`、`compactor`、`alert`。`standalone` 在一个进程内运行全部角色。 |
| `id` | 空 | 节点 id，最长 64 个字符。留空时使用操作系统的主机名。同一台主机运行多个进程时，必须为每个进程设置不同的 id。 |
| `drain_timeout_secs` | `30` | 收到 `SIGTERM` 或 `SIGINT` 后，等待 intake 待处理数据刷写完成的时间。超时后进程退出。 |

## 监听端口

### HTTP

| 键 | 默认值 | 说明 |
|---|---|---|
| `bind` | `0.0.0.0` | 监听地址。 |
| `port` | `5080` | `[http.tls]` 未启用时的 HTTP 端口。 |
| `gzip` | `true` | 压缩 HTTP 响应。反向代理已经压缩时设为 `false`。 |
| `external_url` | 空 | 对外访问的源地址，例如 `https://molesignal.example.com`。留空时网页界面使用浏览器当前的源地址。生成的接入片段使用该值，状态页自定义域名也把它作为 CNAME 目标。修改后需要重启。 |

### HTTP TLS 与 ACME

`[http.tls]` 启动 TLS 监听器，并通过 Let's Encrypt 等 ACME 服务自动签发证书。

| 键 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 总开关。为 `false` 时，其余键全部被忽略。 |
| `plain_port` | `80` | 用于 ACME HTTP-01 验证和跳转到 HTTPS 的明文 HTTP 端口。 |
| `port` | `443` | HTTPS 端口。 |
| `acme_directory` | `production` | `production`、`staging`（Let's Encrypt 测试环境）或自定义目录 URL。 |
| `account_email` | 空 | ACME 账号邮箱。Let's Encrypt 要求提供。 |
| `key_storage_dir` | `/var/lib/molesignal/acme` | 保存 ACME 账号密钥和各域名密钥的目录。 |
| `issue_poll_secs` | `60` | 扫描等待签发证书的域名的间隔。 |
| `renewal_retry_secs` | `21600` | 续期重试与到期扫描的间隔。 |

### 内部 gRPC

`[grpc]` 承载节点之间的流量，请把该端口放在可信网络内。

| 键 | 默认值 | 说明 |
|---|---|---|
| `bind` | `0.0.0.0` | 监听地址。 |
| `port` | `5082` | 端口。对端通过 `[cluster].advertise_addr` 使用它。 |
| `max_message_size_mb` | `32` | gRPC 单条消息的最大大小，单位 MiB。 |

### OTLP gRPC

`[otlp_grpc]` 配置 OTLP gRPC 接收端。接收端没有启用开关，在每个运行 `intake` 角色的节点（包括 `standalone`）上监听。

| 键 | 默认值 | 说明 |
|---|---|---|
| `bind` | `0.0.0.0` | 监听地址。 |
| `port` | `4317` | 端口。 |
| `max_message_size_mb` | `32` | gRPC 单条消息的最大大小，单位 MiB。 |

### Arrow Flight SQL

`[flight_sql]` 为 DBeaver、JDBC、ADBC 等 SQL 客户端提供服务。每次调用都需要 API Token，参见[用数据库客户端连接](/zh-Hans/query/database-clients)。

| 键 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 启动监听器。 |
| `bind` | `0.0.0.0` | 监听地址。 |
| `port` | `5083` | 端口。 |
| `default_lookback_hours` | `24` | SQL 没有时间过滤条件时默认回看的小时数。 |
| `max_message_size_mb` | `32` | 单条消息的最大大小，单位 MiB。 |

### Probe Agent

`[probe]` 配置 Probe Agent 的注册与控制端点，这些端点在 `standalone` 与 `alert` 节点上启动。注册使用服务端认证的 TLS，控制流使用短期有效的双向 TLS 身份。参见[拨测](/zh-Hans/synthetics)。

| 键 | 默认值 | 说明 |
|---|---|---|
| `bind` | `0.0.0.0` | 监听地址。 |
| `register_port` | `5084` | 注册端口，必须与 `control_port` 不同。 |
| `control_port` | `5085` | 控制流端口。 |
| `register_endpoint` | `https://localhost:5084` | Agent 注册时使用的对外 `https://` 地址，一次性注册命令会打印它。位于代理或负载均衡器之后时需要设置。 |
| `control_endpoint` | `https://localhost:5085` | 控制流的对外 `https://` 地址。 |
| `server_names` | `["localhost", "127.0.0.1"]` | 服务端证书中包含的 DNS 名称与 IP 地址，应包含端点的对外主机名。 |
| `certificate_days` | `30` | 签发证书的有效期，范围 1 到 365。 |
| `max_message_size_mb` | `32` | 单条消息的最大大小，单位 MiB。 |

### pprof

`[profiling]` 启动用于诊断的节点本地 pprof 监听器。

| 键 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 启动监听器。 |
| `bind` | `127.0.0.1` | 监听地址。除非 `allow_remote` 为 `true`，否则必须是回环地址。 |
| `port` | `5084` | 端口。同一台主机上 Probe Agent 注册端口使用相同值时，需要修改其中一个。 |
| `allow_remote` | `false` | 允许非回环的 `bind`。对外暴露可能泄露运行时信息。 |

## 存储

### 元数据库

`[meta_database]` 配置保存元数据、身份、文件目录与产品资源的 PostgreSQL 数据库。

| 键 | 默认值 | 说明 |
|---|---|---|
| `dsn` | `postgres://molesignal:molesignal@localhost:5432/molesignal` | PostgreSQL 连接串。请替换示例中的凭据。 |
| `min_connections` | `2` | 启动时建立的连接数，不超过 `max_connections`。 |
| `max_connections` | `16` | 连接池上限。 |

MoleSignal 启动时会把内嵌的 schema 迁移应用到该数据库，参见[升级](/zh-Hans/upgrade)。

### 对象存储

`[object_store]` 配置存放 Parquet 文件、检索索引与 Profile 数据块的存储。后端有 `local`、`s3`、`azure`、`gcs`。AWS S3 以及 RustFS、Cloudflare R2、阿里云 OSS 等兼容 S3 的服务使用 `s3`。

| 键 | 默认值 | 说明 |
|---|---|---|
| `backend` | `local` | `local`、`s3`、`azure` 或 `gcs`。 |
| `root` | `./data/objects` | `local` 后端的目录，其他后端忽略。 |
| `bucket` | 空 | `s3` 与 `gcs` 的 bucket 名称，`azure` 的容器名称。这些后端必填。 |
| `region` | 空 | S3 region。兼容 S3 的服务按其要求填写。 |
| `endpoint` | 空 | S3 端点 URL。AWS S3 留空。RustFS 等服务使用 `http://host:9000` 形式的地址。 |
| `path_style` | `false` | `false` 使用虚拟主机寻址，AWS S3 与华为云 OBS 需要。`true` 使用路径寻址，RustFS 与大多数自建服务需要。 |
| `access_key` | 空 | S3 的 access key，或 Azure 的存储访问密钥。 |
| `secret_key` | 空 | S3 的 secret key。 |
| `credentials_file` | 空 | 凭据文件的路径，文件包含 `access_key=<值>` 与 `secret_key=<值>` 两行。优先级见下文。 |
| `multipart_threshold_mb` | `32` | 大小达到该值（MiB）的对象分片上传。manifest 对象与带版本条件的写入始终用单个请求上传。最小值为 1。 |
| `multipart_part_size_mb` | `8` | 分片上传中单个分片的大小（MiB），取值 5 到 1024。很大的对象使用更大的分片，使一次上传不超过 10000 个分片。 |
| `range_threshold_mb` | `16` | 字节范围读取的大小达到该值（MiB）时，拆成并行执行的块请求。最小值为 1。 |
| `range_chunk_mb` | `8` | 单个块请求的大小（MiB），取值 1 到 1024。 |
| `max_concurrency` | `8` | 每个进程允许同时进行的对象存储操作数。 |
| `op_timeout_secs` | `30` | 等待并发许可以及单次后端操作的超时时间。 |
| `health_probe_interval_secs` | `30` | 后台写入、读取、删除探测的间隔，最小为 5。 |

S3 与 Azure 客户端从下列来源中第一个同时提供 access key 与 secret key 的来源读取凭据：

1. 变量 `MS_OBJECT_STORE_ACCESS_KEY` 与 `MS_OBJECT_STORE_SECRET_KEY`。
2. `credentials_file` 指向的文件。
3. 配置键 `access_key` 与 `secret_key`。

启动日志会把胜出的来源报告为 `object_store_credentials_source`：`env`、`file`、`inline` 或 `none`。secret 建议用环境变量或凭据文件提供，不要写进 `config.toml`。

分片上传的每个分片与分段读取的每个块，都是占用一个并发槽位的对象存储操作：各自独立重试，并计入 `object_store_*` 指标。一次传输最多占用一半的并发槽位，因此大对象不会饿死其他操作。

云后端的暂态错误会按指数退避重试：

| 键 | 默认值 | 说明 |
|---|---|---|
| `[object_store.retry].max_attempts` | `4` | 单次操作的总尝试次数。 |
| `[object_store.retry].base_backoff_ms` | `100` | 首次等待时间。 |
| `[object_store.retry].max_backoff_ms` | `5000` | 等待时间上限。 |
| `[object_store.retry].jitter_ratio` | `0.2` | 施加在每次等待上的随机抖动比例，范围 0 到 1。 |

### 预写日志

`[wal]` 配置运行 `intake` 角色的节点的预写日志。请把目录放在持久化的本地卷上，参见[备份与恢复](/zh-Hans/backup-restore)。

| 键 | 默认值 | 说明 |
|---|---|---|
| `dir` | `./data/wal` | WAL 目录。 |
| `segment_size_mb` | `256` | 分段大小，单位 MB。写满后切换到新分段。 |
| `flush_strategy` | `batch` | 何时执行 `fsync`。`none` 从不同步，只依赖页缓存。`every_write` 每条记录都同步，持久性最强、延迟最高。`batch` 在积累 `batch_max_pending` 条记录或经过 `batch_max_delay_ms` 后同步。 |
| `sync_level` | `data` | 每次同步的深度。`none` 跳过同步。`data` 同步文件数据。`all` 同时同步元数据与父目录。 |
| `batch_max_pending` | `64` | `batch` 模式下触发同步的记录数。 |
| `batch_max_delay_ms` | `50` | `batch` 模式下两次同步之间的最长间隔。 |
| `encrypt` | `false` | 写入磁盘前，用根密钥（`MS_CIPHER_KEY`）加密每条记录的内容。示例文件中没有该键。 |
| `max_replay_mb` | `512` | 启动重放的内存上限。超出后重放会先刷写一次。 |

### 接入缓冲

`[intake]` 控制 intake 节点的内存缓冲。

| 键 | 默认值 | 说明 |
|---|---|---|
| `buffer_max_mb` | `256` | 单个数据流原始缓冲的硬上限，自适应阈值不会超过它。 |
| `max_buffer_memory_mb` | `1024` | 进程内活跃缓冲与已分离缓冲占用的内存总上限。 |
| `flush_interval_secs` | `30` | 两次刷写之间的最长间隔。 |
| `flush_parallelism` | `4` | 并发刷写数。 |

`[intake.rotation]` 自适应地调整 Parquet 文件大小：

| 键 | 默认值 | 说明 |
|---|---|---|
| `adaptive_enabled` | `true` | 根据已完成文件的编码后与原始大小之比，调整每个数据流下一次的原始阈值。 |
| `target_file_size_mb` | `128` | 编码后 Parquet 文件的目标大小。 |
| `min_buffer_mb` | `16` | 自适应阈值的下限。 |
| `ewma_alpha` | `0.2` | 该比率的平滑系数，大于 0 且不超过 1。 |

`[intake.prometheus]` 限制 Prometheus `remote_write` 的输入：

| 键 | 默认值 | 说明 |
|---|---|---|
| `max_labels_per_series` | `64` | 每个 series 的标签数，不含 `__name__`。 |
| `max_label_name_bytes` | `128` | 标签名的最大 UTF-8 字节数。 |
| `max_label_value_bytes` | `2048` | 标签值的最大 UTF-8 字节数。 |
| `max_samples_per_batch` | `16384` | 一个内部批次承载的 sample 数。 |

`[intake.prometheus.cardinality]` 在一致性哈希路由到的 intake 节点上做 series 准入：

| 键 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 应用这些限制。 |
| `max_active_series_per_process` | `1000000` | 每个进程的活跃 series 数，不得小于组织级上限。 |
| `max_active_series_per_org` | `200000` | 每个组织的活跃 series 数，不得小于指标级上限。 |
| `max_active_series_per_metric` | `100000` | 一个组织内单个指标的活跃 series 数。 |
| `max_new_series_per_minute` | `20000` | 进程每分钟接纳的新 series 数。 |
| `idle_ttl_secs` | `900` | 空闲超过该时长的 series 会释放其占用的容量。 |

### 合并与保留

`[compactor]` 负责合并文件并执行保留策略，在 `standalone` 与 `compactor` 节点上运行。

| 键 | 默认值 | 说明 |
|---|---|---|
| `interval_secs` | `300` | 两轮合并之间的间隔。 |
| `target_mb` | `512` | 合并后 Parquet 的目标大小，单位 MiB。 |
| `max_concurrent_groups` | `4` | 每个节点在一轮内同时处理的数据流数。 |
| `retention_days` | `30` | 未单独设置保留期的数据流使用的保留天数。数据流自己的保留期优先。 |
| `downsample_after_days` | `0` | 把早于该天数的指标降采样为时间桶。`0` 表示关闭。 |
| `downsample_interval_secs` | `3600` | 降采样时间桶的宽度。 |

| `[storage.catalog].interval_secs` | `300` | 封存任务的间隔。 |
| `[storage.catalog].batch_size` | `64` | 每轮处理的分区数。 |
| `[storage.index].enabled` | `true` | 构建并重建检索索引。 |
| `[storage.index].interval_secs` | `30` | 任务间隔。 |
| `[storage.index].batch_size` | `64` | 每轮处理的文件数。 |
| `[storage.index].max_concurrency` | `2` | 并发构建索引的数量。 |
| `[storage.index].retry_after_secs` | `300` | 构建失败后重试前的等待时间。 |
| `[storage.gc].enabled` | `true` | 删除目录不再引用的对象。 |
| `[storage.gc].interval_secs` | `30` | 任务间隔。 |
