打开 **告警**，完成从发现问题到确认、升级和解决的全过程。[规则](/zh-Hans/alerting/rules)监视一个查询或指标，条件成立时开启[事件](/zh-Hans/alerting/incidents)；别的系统发来的告警经[告警来源](/zh-Hans/alerting/sources)同样开成事件。[告警路由](/zh-Hans/alerting/routing)决定新事件交给哪个团队、走哪条升级策略。事件的[升级策略](/zh-Hans/alerting/on-call#升级策略)通知其中指定的人员和[值班排班](/zh-Hans/alerting/on-call#值班排班)，无人确认时继续向后通知。[通知渠道](/zh-Hans/notification-channels)负责每一次投递。[静默](/zh-Hans/alerting/silences)在维护期间暂停通知，[抑制](/zh-Hans/alerting/inhibition)在有更严重的事件时压住次要事件的通知，[语义分组](/zh-Hans/alerting/silences#语义分组)把相关事件收成一组。

## 告警中心

| 分区 | 用途 | 指南 |
|---|---|---|
| **告警事件** | 当前在触发的事件：确认、静默、解决与调查。 | [告警事件](/zh-Hans/alerting/incidents) |
| **规则** | 阈值、预测、离群、组合、心跳规则，以及异常规则和实时规则。 | [告警规则](/zh-Hans/alerting/rules) |
| **告警来源** | Alertmanager、Grafana、Datadog、PagerDuty、Zabbix、云监控（阿里云、腾讯云、Amazon CloudWatch）、邮件或接口发来的告警。 | [外部告警](/zh-Hans/alerting/sources) |
| **状态页** | 向客户通报事件与维护。 | [状态页](/zh-Hans/status-pages) |
| **历史** | 过去的事件，可按服务和状态搜索。 | [历史](/zh-Hans/alerting/incidents#历史) |
| **复盘** | 事件的内部复盘和改进项，以及重大事件设置。 | [重大事件与复盘](/zh-Hans/alerting/major-incidents) |
| **洞察** | 事件量、恢复时间、噪声规则、受影响服务、人的响应和值班负担。 | [洞察](/zh-Hans/alerting/incidents#洞察) |
| **分组** | 把相关事件收成一组的语义分组。 | [语义分组](/zh-Hans/alerting/silences#语义分组) |
| **路由** | 新事件交给哪个团队、走哪条升级策略。 | [告警路由](/zh-Hans/alerting/routing) |
| **升级** | 通知谁、按什么顺序、何时转给下一级。 | [升级策略](/zh-Hans/alerting/on-call#升级策略) |
| **值班排班** | 轮值、临时替班、换班申请和日历订阅。 | [值班排班](/zh-Hans/alerting/on-call#值班排班) |
| **修复动作** | 在事件上一键发起、审批后执行的 HTTP 和 Kubernetes 处置。 | [修复动作](/zh-Hans/alerting/remediation) |
| **工单** | 连接 Jira、ServiceNow 或飞书项目，为事件建单并同步状态。 | [工单](/zh-Hans/alerting/tickets) |
| **静默策略** | 暂停匹配事件的通知。 | [静默策略](/zh-Hans/alerting/silences#静默策略) |
| **抑制** | 有更严重或更上游的事件时，压住次要事件的通知。 | [抑制](/zh-Hans/alerting/inhibition) |

## 配置告警

一个工作区通常按以下顺序准备好第一次告警通知：

<Steps>
  <Step title="接入通知渠道">
    在[设置 → 通知 → 连接器](/zh-Hans/notification-channels)中配置邮件、IM App 或电话与短信等连接器，并让成员在[账号设置 → 通知设置](/zh-Hans/account#通知设置)中绑定个人通知方式。
  </Step>
  <Step title="搭建值班排班">
    按团队的轮值方式创建[值班排班](/zh-Hans/alerting/on-call#创建排班)。
  </Step>
  <Step title="创建默认升级策略">
    创建名为 `default` 的策略，先通知值班排班，再通知负责人。规则工作台中保存的规则经[路由](/zh-Hans/alerting/routing)定不下团队的值班策略时使用它。参见[默认策略](/zh-Hans/alerting/on-call#默认策略)。
  </Step>
  <Step title="创建并测试规则">
    在[规则工作台](/zh-Hans/alerting/rules#创建阈值规则)中从预设开始，用真实数据测试后保存。
  </Step>
  <Step title="演练">
    用[触发规则](/zh-Hans/api/alerting/trigger-rule)接口有意触发一条规则，确认通知送达、升级会向后推进、确认后升级停止。
  </Step>
</Steps>

关于告警什么、如何路由，参见[让生产告警能够指导响应](/zh-Hans/best-practices/actionable-alerts)和[搭建值班与通知](/zh-Hans/best-practices/on-call-setup)。

## 权限

| 权限 | 能力 |
|---|---|
| `alerts.incidents.read` | 读取事件、事件历史和洞察。 |
| `alerts.incidents.acknowledge` | 确认、解决和暂缓事件及事件分组。 |
| `alerts.incidents.update` | 转派事件、增派成员、改严重度、写备注，以及处置事件：角色、任务和进展。 |
| `alerts.incidents.escalate` | 升级和合并事件，宣布重大事件。 |
| `alerts.incidents.create`、`alerts.incidents.silence` | 手动开启事件；静默事件。 |
| `alerts.incidents.remediate`、`alerts.incidents.tickets`、`alerts.incidents.rca` | 在事件上发起修复动作、建工单、写根因。 |
| `alerts.rules.read`、`alerts.rules.manage` | 读取规则；创建和修改规则。 |
| `alerts.routing.read`、`alerts.routing.manage` | 读取和修改路由规则、团队的值班策略。 |
| `alerts.escalations.read`、`alerts.escalations.manage`、`alerts.escalations.delete` | 读取、修改和删除升级策略。 |
| `alerts.sources.read`、`alerts.sources.manage` | 读取和修改告警来源。 |
| `alerts.mutes.read`、`alerts.mutes.manage` | 读取静默；创建、修改和移除静默。 |
| `alerts.inhibitions.read`、`alerts.inhibitions.manage` | 读取抑制规则；创建、修改和删除抑制规则。 |
| `alerts.semantic_groups.manage` | 管理分组。 |
| `alerts.remediation.read`、`alerts.remediation.manage` | 读取和定义修复动作。 |
| `alerts.tickets.read`、`alerts.tickets.manage` | 读取和管理工单连接器。 |
| `alerts.response.read`、`alerts.response.manage` | 读取和修改重大事件设置。 |
| `alerts.discovery.read` | 读取自动发现找到的问题。 |
| `schedules.read` | 读取排班和当前值班人。 |
| `schedules.create`、`schedules.update`、`schedules.delete` | 创建、修改和删除排班及其轮值。 |
| `schedules.overrides.manage`、`schedules.swaps.request`、`schedules.swaps.approve` | 替班；申请换班；批准或驳回换班申请。 |
| `postmortems.read`、`postmortems.manage` | 查看复盘；写复盘和改进项。 |
