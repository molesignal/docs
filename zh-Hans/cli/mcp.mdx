`molesignal mcp` 通过 stdio 提供 MoleSignal 的 MCP 工具。Agent 工具自己启动这个命令，通过标准输入和标准输出与它通信；命令行把每条消息转给 MoleSignal 的 **Inbound MCP** 端点，再把每个回复带回来。工具、权限与审批都由 MoleSignal 决定，命令行不额外提供任何工具。

## 在 Agent 工具中添加服务器

先[登录](/zh-Hans/cli/sign-in)，再让命令行把自己添加到 Agent 工具中：

```bash
molesignal mcp setup claude
```

| Agent 工具 | `molesignal mcp setup` 修改的内容 |
|---|---|
| `claude` | 为 Claude Code 运行 `claude mcp add`。`--scope` 为 `user`（默认）、`project` 或 `local`。 |
| `cursor` | `~/.cursor/mcp.json`；带 `--scope project` 时为当前目录下的 `.cursor/mcp.json`。 |
| `codex` | `~/.codex/config.toml`；设置了 `CODEX_HOME` 时在其下。 |
| `vscode` | 当前目录下的 `.vscode/mcp.json`。 |
| `gemini` | `~/.gemini/settings.json`；带 `--scope project` 时为当前目录下的 `.gemini/settings.json`。 |

命令添加名为 `molesignal` 的服务器，已有同名服务器时替换它，文件中的其他设置保持不变。服务器运行 `npx -y @molesignal/cli mcp`；`--installed` 改为运行已安装的 `molesignal`。`--profile` 把 profile 写进服务器配置，Agent 工具因此始终使用这个登录，不随当前 profile 变化。`--print` 只输出配置，不写入文件。

[通过 stdio 接入](/zh-Hans/inbound-mcp#通过-stdio-接入)列出了每个工具的相同配置；**Mole Agent → 设置 → Inbound MCP** 中的配置提示词会写出适用于当前实例的步骤。

在没有人登录的地方（例如构建机），改为在环境变量中给出凭据：

```json
{
  "mcpServers": {
    "molesignal": {
      "command": "npx",
      "args": ["-y", "@molesignal/cli", "mcp"],
      "env": {
        "MOLESIGNAL_URL": "https://molesignal.example.com",
        "MOLESIGNAL_TOKEN": "<token>"
      }
    }
  }
}
```

## 消息如何转发

- Agent 工具发出 `notifications/initialized` 之前，消息按顺序逐条转发：MoleSignal 在回复 `initialize` 时才建立会话。之后消息随到随转，一个慢的工具调用不会耽误其他调用。
- MoleSignal 不再认得会话时（例如重启之后），命令行用 Agent 工具自己的 `initialize` 建立新会话，再重发这条消息。Agent 工具无需重启即可继续。
- 连不上 MoleSignal 的请求会收到错误回复，Agent 工具不会一直等待。
- Agent 工具关闭标准输入时，命令行结束 MoleSignal 上的会话并退出。
- 写给人看的信息（例如连接断开）输出到标准错误；标准输出只有 MCP 消息。
- 与其他命令一样，`HTTPS_PROXY` 和 `NO_PROXY` 生效。

## 检查连接

```bash
molesignal status
```

显示的工具数与 Agent 工具看到的一致。工具数为零通常说明组织的 Tool Policy 或用户权限没有留下可用的工具。
