**基础设施**列出服务运行的位置，并把每个位置和写明它的服务、日志、指标关联起来。出问题的节点可以找到它的 Pod 上的每个服务；变慢的服务实例可以找到它所在的 Pod 和节点。

## 实体从哪里来

这个页面不需要配置。平台每五分钟读取最近 15 分钟的两类数据：

- APM 在 Span 里看到的实例，以及运行在实例上的服务。
- 最多四个带有 `host.name`、`k8s.node.name` 或 `k8s.pod.name` 字段的指标或日志数据流，最多读取 2,000 个不同位置的资源字段。

字段遵循 OpenTelemetry 语义约定：

| 类型 | 依据 | 键 |
|---|---|---|
| 集群 | `k8s.cluster.name` | 集群名。 |
| 节点 | `k8s.node.name` | `集群/节点`。 |
| Pod | `k8s.pod.name` 加 `k8s.namespace.name` | `集群/命名空间/Pod`。 |
| 主机 | `host.name`，仅限 Kubernetes 之外 | 主机名。 |
| 容器 | `container.id` 加 `container.name` | 容器 ID。 |

在 Pod 里 `host.name` 通常是 Pod 名，所以写明了 Pod、节点或集群的数据不会生成主机。服务运行在它的 Span 写明的最内层位置：Pod，其次主机，再次节点。Pod 运行在节点上，节点属于集群，容器属于 Pod。

要补齐 Kubernetes 字段，在 OpenTelemetry Collector 中加入 `k8sattributes` processor，并用 `resource` processor 设置 `k8s.cluster.name`；**数据源**页面的 Kubernetes 接入指南包含这两项。一周没有出现的实体会被遗忘。

## 列表

列表显示最近一周看到的全部实体，最近出现的排在前面。绿点表示最近 30 分钟内出现过，即正在运行；灰点表示只在更早出现过。**服务**是直接运行在它上面的服务数。可以按类型筛选，或按名称、键搜索；两者都保存在地址里。

## 实体页面

打开一个实体可以看到：

- **运行在**：它的节点和集群，或容器所属的 Pod。
- **运行在它上面**：集群的节点、节点的 Pod、Pod 的容器。
- **服务**：它上面以及运行在它上面的实体上的服务，每个都链接到 APM 页面。
- **其服务的变更**：这些服务最近 24 小时的部署和其他变更。参见[变更](/zh-Hans/api/changes)。
- **资源属性**：它最后一次出现时带的字段，每个都可以复制。

**日志**打开 Pod 或主机最近一小时的日志。**指标**按 `k8s.cluster.name`、`k8s.node.name`、`k8s.pod.name`、`host.name` 或 `container.id` 打开带有它名字的指标。

服务 [APM](/zh-Hans/apm) 页面 **实例** 表中的 **工作负载 / 主机** 单元格会打开该实例所在的 Pod 或主机。

## 权限

页面和 API 需要 `apm.services.read`、`metrics.read`、`logs.read` 之一，系统范围内也可以是 `sys.telemetry.read`。Mole Agent 用 `list_entities` 和 `get_entity` 读取同样的数据。
