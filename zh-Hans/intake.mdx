所有信号都通过 intake API 进入 MoleSignal。网页界面中的 **数据源** 页面会为每个数据源生成端点、Token 和配置片段，同样的协议也可以手工配置。

## 数据源页面

打开 **数据源** 接入数据源：

1. 在目录中搜索，或按分类筛选：**推荐**、**基础设施**、**云服务**、**数据库**、**消息队列**、**应用与语言**、**安全** 与 **自定义**。信号标签（**日志**、**指标**、**链路**、**Profiles**）可以进一步缩小范围。
2. 选择一个数据源，例如 Kubernetes、Linux 主机、AWS、OpenTelemetry SDK 或 Web RUM。
3. 按向导的三个步骤完成接入：
   - **端点与 Token** 显示数据发往哪里，以及用于鉴权的 Token。**显示 Token** 会显示 Token 及其权限范围、工作区和有效期。用户体验类数据源需要先选择 **RUM 应用**，选择后才会显示它的 Client Token。
   - **配置数据源** 显示命令和配置，其中的端点与 Token 已替换为真实值。
   - **验证数据到达** 先检查接收端，再查看最近 1 小时内是否收到数据。**验证接入** 立即检查一次，各项数字每 30 秒自动刷新。
4. 查看验证结果：
   - **已检测到数据**：最近 1 小时内收到了数据，且该数据源的信号都处于正常状态。**查看已接收数据** 打开这些数据，**创建流水线** 为它们创建流水线。
   - **接收端正常，但数据状态需要确认**：接收端有响应，但还没有收到数据，或并非所有信号都正常。请检查部署，或等待下一批数据。
   - **验证失败**：无法检查接收端。**可能原因** 列出采集器未运行、Token 无效或已过期，以及网络或代理阻断了端点。

设置了 `http.external_url` 时，端点取自该配置；否则取自浏览器当前地址。位于反向代理之后时，请设置 `http.external_url`，让生成的片段指向对外地址。参见[配置](/zh-Hans/configuration)。

## 接入 Token

发送端使用 Bearer Token 认证：`Authorization: Bearer <token>`。只支持 Basic 认证的发送端（例如云服务商托管 Prometheus 的 remote write 出口）把 API Token 放在 `Authorization: Basic` 的密码里，用户名任意。其他 Basic 凭据会被忽略，因此在反向代理上另设的 Basic 认证不受影响。Splunk HEC 发送端以 `Authorization: Splunk <token>` 携带 Token。

| Token | 权限 | 创建方式 | 用途 |
|---|---|---|---|
| 默认接入 Token | 仅 `logs.write`、`metrics.write`、`traces.write`、`profiles.write` 和 `apm.deploy`，即 **数据写入** 策略 | 数据源页面，或 `GET /api/v1/me/api-tokens/default` | 发送日志、指标与链路的采集器、Agent 与 SDK 导出端，以及[上报发布](/zh-Hans/apm/deployments#从-ci-上报发布)的流水线。不会过期。 |
| RUM 客户端 Token | 仅 `rum.write`，绑定一个应用 | Web RUM 与移动端 RUM 数据源的数据源页面，或 `GET /api/v1/auth/tokens/rum?applicationId=<id>` | 浏览器与移动端代码。终端用户可以看到该 Token。 |
| 个人或服务账号 Token | 所属成员或服务账号能做的，再按权限范围收窄 | **个人设置 → API tokens**；服务账号的 Token 在 **身份与访问 → API tokens** | 自动化、脚本与 MCP 客户端。 |

持续运行的发送端使用默认接入 Token，或跟随 **数据写入** 策略的服务账号 Token。在 **个人设置 → API tokens** 或 **身份与访问 → API tokens** 中撤销 Token 可立即使其失效。Web 界面的登录会话不能用来发送数据：它保存在浏览器 Cookie 中，`Authorization` 请求头不接受它。

在数据源页面输入应用 id 后会创建 RUM Client Token。应用 id 由 1 到 128 个字符组成，可使用 `A-Z`、`a-z`、`0-9`、`.`、`_`、`:` 与 `-`。SDK 中的 `applicationId` 使用同一个 id，参见[浏览器 RUM SDK](/zh-Hans/rum/browser-sdk)。

## 端点与协议

| 协议 | 端点 | 兼容的发送端 | 目标数据流 |
|---|---|---|---|
| 原生 HTTP JSON | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`、应用代码、Vector `http` sink、Fluent Bit `http` 输出 | 路径中的 `{stream}` |
| OTLP over HTTP | `POST /api/v1/logs`、`/api/v1/metrics`、`/api/v1/traces` | OpenTelemetry SDK 与 Collector | `stream-name` 请求头，缺省为 `default` |
| OTLP over gRPC | `:4317` | OpenTelemetry SDK 与 Collector | `stream-name` 元数据，缺省为 `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus、VictoriaMetrics、云服务商托管 Prometheus 的导出，以及任何 remote_write v1 发送端 | `stream-name` 请求头，否则 `?stream=`，否则为 `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat、Logstash、Vector `elasticsearch` sink | 每个 action 的 `_index`，否则 `stream-name` 请求头，否则 `default` |
| Splunk HEC | `POST /api/v1/services/collector/event`、`/api/v1/services/collector/raw` | 腾讯云 CLS、Vector 与 Fluent Bit 的 Splunk 输出、SIEM 转发器 | 每个事件的 `index`，否则 `?index=`，否则 `stream-name` 请求头，否则 `default` |
| Loki push（JSON） | `POST /api/v1/loki/api/v1/push` | 能发送 Loki JSON 格式的发送端 | `stream-name` 请求头，缺省为 `default` |
| Amazon Data Firehose、Google Cloud Pub/Sub 推送、云事件总线、Cloudflare Logpush、Heroku | `/api/v1/_kinesis_firehose`、`/api/v1/_gcp_pubsub`、`/api/v1/_cloud_events`、`/api/v1/_cloudflare`、`/api/v1/_heroku` | 经 Firehose 的 CloudWatch Logs 与 CloudWatch Metric Streams、经 Pub/Sub 的 Cloud Logging、EventBridge、Event Grid 与 CloudEvents 发送方、Cloudflare、Heroku | 在连接器上配置，参见[连接器](/zh-Hans/connectors) |

除推送型连接器外，所有端点都需要具备信号对应的写入权限（`logs.write`、`metrics.write`、`traces.write` 或 `profiles.write`）的 Bearer Token。组织由 Token 决定，不会出现在 URL 中。

### 影响发送端的限制

- **请求大小。** 原生 JSON 接入和推送型连接器的请求体上限为 16 MiB，Firehose 为 64 MiB，均按解压后的大小计；其他接入端点为 2 MiB。超过上限的请求体会被拒绝并返回 `413`。请让每批数据小于该大小。
- **压缩。** OTLP over HTTP 不接受压缩的请求体，会返回 `400`。请在发送端关闭压缩；OpenTelemetry Collector 的 `otlphttp` 导出端默认使用 gzip 压缩，需要设置 `compression: none`。原生 JSON 接入、Elasticsearch `_bulk`、Loki push 与推送型连接器接受 `Content-Encoding: gzip`。
- **Loki 编码。** 只解析 JSON 请求格式。Promtail 与 Grafana Alloy 默认发送 snappy 压缩的 protobuf，无法向该端点发送数据。
- **速率限制。** `router` 角色按组织限制请求，超限时返回 `429` 并附带 `Retry-After` 响应头。`standalone` 节点不应用这个限制。参见[分角色部署](/zh-Hans/deployment/role-based#速率限制)。
- **拒收的事件。** 值与数据流中字段类型不符的事件单独被拒收，请求中的其余事件照常写入。`int64` 字段收到带小数的数不会被拒收，字段会变为 `float64`（参见 [Schema 与字段](/zh-Hans/streams#schema-与字段)）。各端点都会报告拒收的事件：原生 JSON 写在 `rejected` 与 `errors` 中，OTLP 写在 `partialSuccess` 中，Elasticsearch `_bulk` 对应条目的状态为 `400`，Splunk HEC 返回错误码 `6`，Prometheus remote write 与 Loki push 返回 `400`。发送端不会重试这些事件。推送型连接器仍返回成功，因为平台会重发整个请求，拒收情况写在连接器上。
- **平台数据流。** [平台数据流](/zh-Hans/streams#平台数据流)（例如存放服务自身遥测的 `_molesignal` 和存放审计记录的 `_audit`）只由 MoleSignal 写入，公开接入会返回 `403`。

## 数据流与 Schema

数据流在首次写入时创建，schema 会随新字段出现而演进。数据流由名称和信号类型共同标识，因此 `default` 可以同时存在于日志、指标和链路类型下。参见[数据流](/zh-Hans/streams)。

每个事件都有一个自 Unix 纪元起的微秒时间戳。原生 JSON 与 Elasticsearch `_bulk` 读取 `_timestamp` 字段。没有 `_timestamp` 的事件使用服务端接收它的时间。

## 原生 HTTP JSON

向 `/api/v1/intake/{logs,metrics,traces}/{stream}` 发送记录数组：

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

响应会给出已接收与已拒绝的记录数，并为每条被拒绝的记录给出下标与原因：

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

把 OpenTelemetry SDK 或 Collector 指向 `/api` 基础路径。导出端会自动追加 `/v1/logs`、`/v1/metrics` 与 `/v1/traces`，对应 `/api/v1/logs`、`/api/v1/metrics` 与 `/api/v1/traces`。

<Tabs>
  <Tab title="OTLP over HTTP">
    SDK 环境变量：

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector：

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    请发送 protobuf（`application/x-protobuf`），这是各 SDK 与 Collector 的默认编码。日志、指标与链路也接受 JSON（`application/json`）。添加 `stream-name` 请求头可选择 `default` 之外的数据流，该请求头对通过这个导出端发送的所有信号生效。
  </Tab>
  <Tab title="OTLP over gRPC">
    OTLP gRPC 接收端监听 `4317` 端口，提供日志、指标、链路与 Profiles 四个服务。它不终止 TLS，流量离开可信网络时，需要在前面终止 TLS。

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector：

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    端口前面有终止 TLS 的代理时，去掉 `insecure: true`。`5082` 是集群内部 gRPC 端口，不是 OTLP 接收端。
  </Tab>
</Tabs>

OTLP 指标按数据点逐条存储，存储字段参见[指标存储约定](/zh-Hans/query#otlp-指标字段)。

## Prometheus remote_write

在 `prometheus.yml` 中把 MoleSignal 添加为 remote write 目标：

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

一个指标数据流装一个来源的全部指标，所以请用 `stream-name` 请求头（`remote_write` 配置里的 `headers:`）给每台 Prometheus 指定自己的数据流；没有这个请求头时样本写入 `default`。设不了请求头的发送端可以在地址里指定数据流，例如 `/api/v1/prometheus/api/v1/write?stream=aliyun`。每个样本成为一行，`metric_name` 是它的 `__name__`。其余标签成为字段，与指标字段同名的标签（例如 `metric_name`）存为 `exported_<名称>`。原生直方图与指标元数据会被跳过，exemplar 与样本一起保存。

## Elasticsearch bulk

支持 Elasticsearch bulk 协议的发送端无需依赖 Loki 或 OTLP 即可使用：

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

每个 action 的 `_index` 决定目标数据流。没有 `_index` 时使用 `stream-name` 请求头，再缺省为 `default`。

## Loki push

该端点接受 Loki 的 JSON 请求格式：

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

标签成为字段，日志行写入 `message` 字段，纳秒时间戳会转换为微秒。响应为 `204`。用 `stream-name` 请求头选择目标数据流。

## Splunk HEC

支持 Splunk HTTP Event Collector 协议的发送端（例如腾讯云 CLS 投递到 Splunk、Vector 与 Fluent Bit 的 Splunk 输出）可以原样发给 MoleSignal：HEC 地址填 `https://molesignal.example.com/api/v1`，HEC Token 填有日志写入权限的 API Token，以 `Authorization: Splunk <token>` 发送。

| 端点 | 请求体 |
|---|---|
| `POST /api/v1/services/collector/event`，也接受 `/services/collector` | 首尾相接的 JSON 对象，每个形如 `{"time", "host", "source", "sourcetype", "index", "event", "fields"}` |
| `POST /api/v1/services/collector/raw` | 文本，每行一条日志事件；`host`、`source`、`sourcetype`、`index` 取自查询参数 |
| `GET /api/v1/services/collector/health` | 不需要 Token，返回 `{"text":"HEC is healthy","code":17}` |

`event` 是 JSON 对象时作为日志的字段，否则放进 `message`。`fields`、`host`、`source`、`sourcetype` 成为字段，`time`（秒）成为事件时间。`index` 决定数据流，否则取查询参数 `index`，再否则取 `stream-name` 请求头，都没有时为 `default`。成功返回 `{"text":"Success","code":0}`，失败时返回 `400` 和 HEC 自己的错误码。数据流因值与字段类型不符拒收事件时，其余事件照常写入，返回错误码 `6`：`invalid-event-number` 是第一个被拒收事件在请求体中的位置，`text` 写明原因。不支持索引器确认（indexer acknowledgement）。
