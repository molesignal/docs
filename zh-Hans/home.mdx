未修改个人起始页时，登录后打开的第一个页面就是 **首页**。它显示系统此刻的状态：顶部是一条状态带，下面是需要先看的服务和进行中的事件，再往下是各类数据的接收、拨测和账号的值班。首页对每个成员开放，每个部分只显示账号权限允许查看的内容。

## 页面顶部

时间范围决定页面上所有数字的统计窗口：**近 1 小时**（默认）、**近 24 小时** 或 **近 7 天**。选择会写进地址（`?window=24h`），分享链接时打开的是同一视图。页面每分钟重新读取一次，刷新按钮立即读取。

还有设置步骤没完成时，时间范围前的按钮显示还差几步，点击打开[快速开始](#快速开始)。

## 系统状态

状态带开头是结论：**运行正常**，或有几项异常。异常包括进行中的事件、失败、降级或不稳定的拨测、超过警告线或严重线的服务，以及延迟或异常的数据。其中有严重项（严重或错误级事件、失败的拨测、严重的服务、异常的数据）时结论显示为红色，否则为黄色。结论旁边是统计窗口、最近一次读取的时间，以及日志、指标、链路和 Profiles 各自的接收状态。

每个指标块都能打开它汇总的页面：

| 指标块 | 内容 |
|---|---|
| **进行中事件** | 待确认和处理中的事件，按严重程度分开，并标出待确认的数量。打开[告警事件](/zh-Hans/alerting/incidents)。 |
| **触发中规则** | 正在触发的已启用规则，后面是已启用规则的总数，并标出等待持续的数量。打开规则列表。 |
| **健康服务** | 未超过阈值的服务，后面是窗口内出现过的服务总数，并列出严重、警告和无流量的数量。打开 [APM](/zh-Hans/apm)。 |
| **通过的拨测** | 正在运行且通过的检查，后面是正在运行的检查总数，并列出失败、降级和不稳定的数量。打开[拨测](/zh-Hans/synthetics)。 |
| **请求错误率** | 所有服务的失败请求占比、请求数和走势。 |
| **P95 延迟** | 所有服务请求耗时的第 95 百分位，以及 P50、P99 和走势。 |

账号能打开对应页面时才显示该指标块。没有收到 Trace 时，APM 相关的指标块显示短横线。

## 服务

**服务** 最多列出八个服务：严重的在前，然后是警告，健康的按请求量排序。每行显示环境、健康状态、窗口内的请求走势和吞吐、错误率和 P95。超过该服务阈值的数字会着色。点击服务名在 APM 中打开它；**全部** 打开服务列表。

## 进行中事件

**进行中事件** 最多列出六个待确认和处理中的事件，严重的在前，同一严重程度下持续最久的在前。每行显示严重程度、第一个受影响的服务、已持续的时间和负责人。**确认** 在列表中直接确认待确认的事件；没有确认权限的账号看到的是事件状态。

## 数据接收

**数据接收** 按类型显示每类数据的状态、最近一次收到的时间、窗口内按时间分桶的接收量走势，以及窗口内的行数。面板底部显示有数据的数据流数量，以及存储量和接收量。**数据流** 打开[数据流](/zh-Hans/streams)。

| 状态 | 含义 |
|---|---|
| **正常** | 至少一个该类数据流在最近 15 分钟内收到过数据。 |
| **延迟** | 该类数据流有数据，但最近 15 分钟内没有收到。 |
| **异常** | 节点的接收探测报告故障。 |
| **无数据** | 窗口内没有该类数据流收到数据。 |

## 拨测

**拨测** 显示窗口内所有检查的可用率和走势，并最多列出四个失败、降级或不稳定的检查，最差的在前。全部通过时显示检查数量。**全部** 打开检查列表。

## 我的值班

**我的值班** 跟随工作区的[值班排班](/zh-Hans/alerting/on-call)：

- 账号正在值班时显示 **值班中** 和交班时间；否则在 30 天内有班时显示 **下一班** 及其起止时间。
- 这个排班当前在班的人不是本账号时，显示这个人；临时替班期间还会注明替谁值班。
- 排班此刻无人值班时给出提示。**立即安排** 打开排班并添加临时替班。
- 账号有班、却收不到告警时给出提示。**设置通知方式** 打开账号的[通知设置](/zh-Hans/account#通知设置)。
- **排班** 打开这个班所在的排班。

## 快速开始

页面顶部的按钮显示还差几步完成设置。点击打开步骤列表：

| 步骤 | 完成条件 |
|---|---|
| **接入数据源** | 工作区中有[平台数据流](/zh-Hans/streams#平台数据流)以外的数据流。 |
| **加载示例数据** | 示例数据流、示例仪表盘和四个示例保存的视图都已存在。 |
| **创建仪表盘** | 工作区中有仪表盘。 |
| **创建告警** | 工作区中有告警规则。 |
| **配置值班排班** | 工作区中有[值班排班](/zh-Hans/alerting/on-call)。 |
| **配置通知渠道** | 工作区中有已启用、最近一次测试没有失败的[连接器](/zh-Hans/notification-channels)。 |
| **接入 AI 模型** | 工作区中有已启用且设置了 API Key 的[模型服务](/zh-Hans/agent)。 |
| **自动化流水线** | 工作区中有流水线。 |

每一步都按当前用户的权限显示：读取不到完成状态或打不开对应页面的步骤不显示；能读取但无权完成的步骤只在完成后显示。

**加载示例数据** 面向还没有数据可看的工作区。工作区有了自己的数据流后不再提供这一步，不能读取数据流列表的用户也看不到它。示例加载完成后，这一步保留并显示为已完成，**接入数据源** 也随之完成。要把示例数据加载到已有数据的工作区，请发送[快速开始中的请求](/zh-Hans/quickstart#加载示例数据)。

**加载** 会向三个数据流写入一小批相互关联的示例数据：`sample_app_logs`、`sample_app_metrics` 和 `sample_app_traces`。链路模拟从 `frontend` 经 `checkout`、`payment` 到 `db` 的调用，日志带有相同的 `trace_id`，指标给出各服务的耗时，因此从链路跳转到对应日志可以直接演示。加载还会创建一个基于这三个数据流的仪表盘，以及四个查询 `sample_app_logs` 的已置顶[保存的视图](/zh-Hans/saved-views)，它们都显示最近三小时，加载完成后打开该仪表盘。示例数据只写入一次，时间都在加载之前，因此加载三小时后，仪表盘和保存的视图中将没有数据。

再次加载会追加当前时间的数据；仪表盘和保存的视图保持原样，包括已做的修改，只补建缺少的部分，因此中途失败的加载可以重新执行。加载需要 `logs.write`、`metrics.write`、`traces.write`、`dashboards.create` 和 `saved_views.create`，五项权限都在写入任何数据之前检查。

## 权限

打开首页不需要权限。每个部分按所属模块的读取权限加载。

| 权限 | 部分 |
|---|---|
| `alerts.incidents.read` | **进行中事件**、对应的指标块，以及结论中的事件部分。 |
| `alerts.incidents.acknowledge` | **进行中事件** 中的 **确认**。 |
| `alerts.rules.read` | **触发中规则**。 |
| `apm.services.read` | **服务**、**健康服务**、**请求错误率** 和 **P95 延迟**。 |
| `synthetics.monitors.read` | **拨测** 和 **通过的拨测**。 |
| `synthetics.results.read` | **拨测** 中的可用率和走势。 |
| `streams.query` | **数据接收** 和状态带中的数据接收状态。 |
| `schedules.read` | **我的值班**。没有这项权限时不显示该面板。 |
| `notify.policies.read` | **我的值班** 中“收不到告警”的提示。 |
| `notify.connectors.read`、`agent.models.read`、`pipelines.read` | 快速开始中对应的步骤。 |
| `logs.write` | 快速开始中的 **加载**。 |
