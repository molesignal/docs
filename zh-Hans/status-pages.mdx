状态页把运维状态转换为受控的客户沟通。打开**状态页**创建页面，再通过七个独立工作区管理。

## 工作区

| 一级 Tab | 用途 |
|---|---|
| **概览** | 查看摘要、组件、进行中的 Incident 与即将开始的维护。 |
| **组件** | 创建、排序、隐藏、恢复和更新面向客户的服务组件。 |
| **事件** | 起草、发布、更新、监控和解决非计划事件。 |
| **维护** | 安排、发布、开始、完成或取消计划内工作。 |
| **历史** | 搜索和过滤已经结束的 Incident 与 Maintenance，不在概览中无限展开。 |
| **订阅者** | 管理邮件与 Webhook 订阅、确认状态和投递结果。 |
| **设置** | 配置通用行为、品牌、本地化、域名、访问与自动化。 |

## 创建状态页

选择**创建状态页**，然后配置：

- 面向客户的名称与全局唯一 Slug；
- 一种或多种界面语言、默认语言与 IANA 时区；
- **公开**或**私有**可见性；
- 投递保留期、私有会话有效期与 Incident 历史窗口；
- Logo、品牌颜色与可选自定义域名。

English 与简体中文只负责本地化公共界面。组件名称、Incident 消息与维护更新会保持团队写入时的原文。

默认公共地址为 <code>/status/SLUG</code>。

## 组件

每个组件包含名称、描述、顺序、可见性与一个面向客户的状态：

- **正常**
- **性能下降**
- **部分中断**
- **严重中断**
- **维护中**

需要继续管理但不希望公开时，可隐藏组件；组件退出服务目录时再归档。已有事件历史不会因此删除。

## Incident 生命周期

先把 Incident 保存为草稿，选择受影响组件与影响程度，并编写首条客户更新。发布后事件会公开，并向匹配的订阅者投递更新。

<Steps>
  <Step title="调查中">
    确认症状，并告知客户团队正在调查。
  </Step>
  <Step title="已定位或处理中">
    说明已知原因或正在执行的恢复操作。
  </Step>
  <Step title="监控中">
    说明服务已经恢复，团队正在验证稳定性。
  </Step>
  <Step title="已解决">
    发布结束更新。MoleSignal 会恢复组件状态，并在**历史**中增加一行完整事件。
  </Step>
</Steps>

每次已发布更新都是不可变的客户沟通。继续处理 Incident 时应新增更新，不要改写已经投递的内容。

## Maintenance 生命周期

创建计划工作时设置开始与结束时间、受影响组件、影响程度和客户消息。先发布为**已计划**，工作开始时切换到**进行中**，最后以**已完成**或**已取消**结束。结束的 Maintenance 会以一行完整事件进入**历史**。

## 历史

历史只收录已经结束的业务事件：已解决的 Incident，以及已完成或已取消的 Maintenance。一行代表一个完整事件，包含类型、标题、结束状态、受影响组件与日期。可以按搜索词、类型、状态、组件和日期过滤并分页。点击标题会打开时间线和更新，不会在表格内无限展开。

历史窗口控制公共归档向前读取 1–365 天，不会把 Overview 重新变成无限事件流。

## 订阅者与投递

公共访客可以选择 **Subscribe**，登记邮件地址或 Webhook。邮件订阅需要先确认再激活。管理视图会区分待确认、有效与已退订记录。

每次发布 Incident 或 Maintenance 更新时，系统都会为匹配订阅者创建有界投递任务。**订阅者**页面显示尝试次数、成功状态、最后错误与重试状态。投递保留期可配置为 30、60、90、180 或 365 天。

## 私有访问

私有状态页支持邮件地址与邮件域名 Allowlist。获准访客先申请一次性 Magic Link，再获得 1、7 或 30 天的状态页会话。管理员可以立即吊销活动会话。私有访问会覆盖公共页、归档、事件详情与订阅流程。

## 自定义域名与 TLS

添加域名前，先把 <code>http.external_url</code> 配置为 MoleSignal 的真实公共 URL。域名面板随后会显示需要创建的 DNS 所有权验证与路由记录。

域名状态依次为**等待 DNS**、**验证中**、**已验证**、**正在配置 TLS**与**有效**。**失败**或**降级**状态会显示可执行原因与重试入口。

如需由 MoleSignal 直接使用自动管理的证书托管自定义 Hostname，请启用 <code>http.tls</code> 并设置账户邮箱：

```toml
[http]
external_url = "https://molesignal.example.com"

[http.tls]
enabled = true
account_email = "ops@example.com"
```

如果 TLS 在外部负载均衡器终止，仍需保持公共 URL 与 DNS 目标准确，并在边缘管理证书。

## 发布自动化

打开**设置 → 自动化**，把运维事件转换为客户更新。

1. 选择**告警事件**或**拨测 Monitor**作为来源。
2. 选择具体资源、最低严重度或 Monitor 状态转换，并填写必须匹配的标签。
3. 添加延迟，避免瞬时故障直接形成客户沟通。
4. 映射事件影响与受影响的状态页组件。
5. 选择**人工批准**或**自动发布**，并定义消息模板。
6. 启用前先在规则模拟器中测试。

第一条完整匹配的有序规则会接管事件。Correlation Key 会把来源后续状态转换连接到同一个 Incident。人工模式生成可供授权用户批准、拒绝或编辑的候选项；自动模式会直接发布生成的事件。**暂停全部自动化**只停止新的规则匹配，不会修改已经公开的事件。

<Note>
告警事件适合由响应人员负责的检测，拨测 Monitor 适合直接验证客户路径。两种来源都能更新同一组件模型，但每条规则保留独立的批准与延迟策略。
</Note>

## 权限

| 权限 | 能力 |
|---|---|
| <code>status_pages.read</code> | 读取状态页、组件、事件、历史、订阅者、域名与自动化状态。 |
| <code>status_pages.manage</code> | 创建和修改状态页、组件、访问、订阅者、域名与自动化规则。 |
| <code>status_pages.publish</code> | 发布客户更新，并批准、拒绝或应用自动化候选项。 |
| <code>alerts.read</code> | 选择告警来源，并在自动化模拟器中使用告警事件。 |
