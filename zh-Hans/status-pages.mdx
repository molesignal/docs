状态页把运维状态转换为受控的客户沟通。打开**状态页**创建页面，再通过七个独立工作区管理。

## 工作区

| 一级 Tab | 用途 |
|---|---|
| **概览** | 查看摘要、组件、进行中的事件与即将开始的维护。 |
| **组件** | 创建、分组、排序、隐藏、恢复和更新面向客户的服务组件。 |
| **事件** | 起草、发布、更新、监控和解决非计划事件。 |
| **维护** | 安排、发布、开始、完成或取消计划内工作。 |
| **历史** | 搜索和过滤已经结束的事件与维护，不在概览中无限展开。 |
| **订阅者** | 管理邮件、Webhook 与 Slack 订阅，导入订阅者，查看确认状态和投递结果。 |
| **设置** | 配置通用行为、品牌、本地化、域名、访问与自动化。 |

## 创建状态页

选择**创建状态页**，然后配置：

- 面向客户的名称与全局唯一 Slug；
- 一种或多种界面语言、默认语言与 IANA 时区；
- **公开**或**私有**可见性；
- 投递保留期、私有会话有效期与事件历史窗口；
- Logo、品牌颜色与可选自定义域名。

English 与简体中文只负责本地化公共界面。组件名称、事件消息与维护更新会保持团队写入时的原文。页面发出的邮件也使用默认语言。

默认公共地址为 <code>/status/SLUG</code>。

## 组件

每个组件包含名称、描述、顺序、可见性与一个面向客户的状态：

- **正常**
- **性能下降**
- **部分中断**
- **严重中断**
- **维护中**

需要继续管理但不希望公开时，可隐藏组件；已隐藏的组件不会出现在公共页面和订阅通知中。组件退出服务目录时再归档。已有事件历史不会因此删除。

公共页面逐个列出组件的状态和最近 90 天的状态条。每条状态条下方是一行刻度：**90 天前**、该组件的可用性和**今天**。组件的描述放在名称旁 ⓘ 的提示里。

### 组件分组

像目录收纳文件一样把相关组件放进分组。选择**添加组件**，类型选**分组**，填写名称和描述；再在组件的设置里，从**所属分组**选择它所在的分组。

- 分组没有自己的状态，显示组内组件中最差的状态；它的状态条中，每一天取组内当天最差的组件。
- 公共页面上，一个分组是一行，标明组件数量，读者展开后看到各个组件。组内有组件不正常时，分组默认展开。
- 分组只收纳组件，不能嵌套分组。事件、维护、订阅和自动化规则选择的都是组件，不会单独选择分组。
- **上移**和**下移**在同一分组的组件之间排序；分组本身在最外层的条目之间排序。
- 把组内组件移出或归档之后，分组才能归档。

### 业务服务

组件可以代表一项[业务服务](/zh-Hans/business-services)。在组件设置的**业务服务**里选择服务，并选择健康度如何影响组件：

| 方式 | 行为 |
|---|---|
| **跟随健康度** | 组件状态随业务服务的健康度变化。**通知订阅者**决定这些变化是否通知订阅者。手动设置的状态会保留到健康度下一次变化。 |
| **交给自动化规则** | 健康度的变化作为本页自动化规则的来源，由规则按延迟、审批和文案发布事件。 |

分组不能代表业务服务，请关联组内的组件。

## 事件生命周期

先把事件保存为草稿，选择受影响组件与影响程度，并编写首条客户更新。发布后事件会公开，并向匹配的订阅者投递更新。

<Steps>
  <Step title="调查中">
    确认症状，并告知客户团队正在调查。
  </Step>
  <Step title="已定位或处理中">
    说明已知原因或正在执行的恢复操作。
  </Step>
  <Step title="监控中">
    说明服务已经恢复，团队正在验证稳定性。
  </Step>
  <Step title="已解决">
    发布结束更新。MoleSignal 会恢复组件状态，并在**历史**中增加一行完整事件。
  </Step>
</Steps>

每次已发布更新都是不可变的客户沟通。继续处理事件时应新增更新，不要改写已经投递的内容。

### 下次更新与通知

每次发布更新都可以承诺下一次更新的时间：在**下次更新**里选择 15 或 30 分钟内，1、2、4 或 24 小时内，或**不承诺**。公共页面会在事件详情和进行中事件的通知上显示这个承诺，邮件和 Webhook 也会带上。结束事件的更新、只是已计划的维护不承诺下次更新。通过 API 发布时，用微秒表示的 `next_update_at`，须在 1 分钟到 7 天之后。

**通知订阅者**决定这次更新是否发给订阅者。更正措辞时可以关闭：页面照常更新，但不发送任何通知。工作区时间线会把这样的更新标为**未通知订阅者**。手动修改组件状态时也有同样的开关。通过 API 发布时，传 `"notify": false`。

## 维护生命周期

创建计划工作时设置公开标题、开始时间、受影响组件和客户更新。维护只有计划开始时间，没有计划结束时间，预计时长请写在客户更新中。先发布为**已计划**，最后以**已完成**或**已取消**结束。结束的维护会以一行完整事件进入**历史**。

已计划的维护会在计划开始时间自行动作。每个维护带有两个选项，默认都开启：

| 选项 | API 字段 | 默认值 | 行为 |
|---|---|---|---|
| 到点自动开始 | `auto_start` | `true` | 到达计划开始时间时，维护转为**进行中**，并以页面的默认语言发布一条更新。订阅者像收到其他更新一样收到通知。 |
| 提前提醒 | `reminder_minutes` | `60` | 在计划开始时间之前这么多分钟，订阅者收到一次提醒。提醒不会进入时间线。`0` 表示不提醒，最长可提前 10080 分钟。 |

关闭到点自动开始时，需在工作开始时手动把维护切换到**进行中**。

维护在提醒时间之后才发布或改期的，不再发送提醒，因为订阅者刚刚收到过通知。改期后，提醒随新的计划开始时间一起移动。修改维护时没有指明这两个选项的，保持原值不变。MoleSignal 大约每 30 秒检查一次计划开始时间。

## 事故复盘

已发布的事件可以附一篇事故复盘，用 Markdown 编写：发生了什么、原因是什么、会改进什么。从**事件**或**历史**打开事件，在**事故复盘**中编写；**预览**显示读者看到的样子。

| 操作 | 权限 | 效果 |
|---|---|---|
| **保存草稿** | <code>status_pages.manage</code> | 内容不公开。事件仍在进行时也可以先写草稿。 |
| **发布复盘** | <code>status_pages.publish</code> | 事件解决后才能发布。复盘显示在事件页的进展更新下方，公共历史中该事件一行会标注**有复盘**。打开**通知订阅者**时，订阅者会收到复盘。 |
| **发布修订** | <code>status_pages.publish</code> | 替换已发布的内容，并记录修订时间。修订时**通知订阅者**默认关闭。 |
| **撤回为草稿** | <code>status_pages.publish</code> | 把复盘从公共页面撤下。 |
| **删除草稿** | <code>status_pages.manage</code> | 删除尚未发布的复盘。 |

复盘最多 20,000 个字符。邮件和 Webhook 带的是原样的 Markdown 文本。

## 历史

历史只收录已经结束的业务事件：已解决的事件，以及已完成或已取消的维护。一行代表一个完整事件，包含类型、标题、结束状态、受影响组件与日期。可以按搜索词、类型、状态、组件和日期过滤并分页。点击标题会打开时间线和更新，不会在表格内无限展开。

历史窗口控制公共归档向前读取 1–365 天，不会把 Overview 重新变成无限事件流。

## 订阅者与投递

公共访客可以选择**订阅**，登记邮件地址、Webhook 或 Slack 频道。每种方式都需要先确认再激活。管理视图会区分待确认、有效与已退订记录，并显示每个订阅者的接收范围。

页面有多个组件时，访客可以选择**整个页面**或**指定组件**。只订阅部分组件的订阅者，只收到涉及其中某个组件的更新；组件分组显示为组内组件上方的标题。每封邮件末尾都有管理订阅和退订两个链接。管理链接会打开页面上的**管理订阅**，可以修改组件或退订。为已经有效的地址再次订阅时，会收到一封**管理订阅**邮件，而不是新的确认邮件。

### Slack

| 方式 | 做法 |
|---|---|
| Incoming Webhook | 接收方式选 **Slack**，粘贴该 Slack 频道的 Incoming Webhook 地址（`https://hooks.slack.com/...`），选择**发送确认**。确认消息会发到该频道。 |
| **Add to Slack** | 页面在**设置 → Slack** 中选用了 Slack 应用时显示。访客在 Slack 中选择频道后回到页面，该频道立即生效，并收到一条欢迎消息。私有页面不提供。 |

Slack 消息以主题作为标题，正文是更新内容，并附打开页面和管理订阅的按钮。

提供 **Add to Slack** 的步骤：

1. 在 Slack 中创建一个应用，权限为 `incoming-webhook`。在 **OAuth & Permissions → Redirect URLs** 中添加页面**设置 → Slack** 显示的重定向地址，即 `<http.external_url>/api/v1/public/slack/callback`。`http.external_url` 必须是 `https` 地址。
2. 在**设置 → 通知 → 连接器**中新建一个 **Slack 应用**连接器，填入该应用的 Client ID 和 Client Secret。Client Secret 随连接器加密保存。见[通知渠道](/zh-Hans/notification-channels#slack-应用)。
3. 在页面的**设置 → Slack** 中选择该连接器并保存。

同一组织的多个页面可以共用一个连接器。被页面选用的连接器不能删除；连接器停用期间，页面不提供 **Add to Slack**。选择**关闭**即停止提供。无论哪种情况，已添加的频道都会继续收到更新。

### 导入订阅者

在**订阅者 → 导入订阅者**中，把其他状态页的邮件订阅者迁移过来。选择 CSV 文件或直接粘贴内容：

- 首行可以是表头，包含 `email` 和 `components` 两列，顺序不限。没有表头时，第一列是邮箱，第二列是组件。
- 组件按名称填写，多个用 `;` 分隔。分组的名称代表组内的组件。留空表示订阅整个页面。
- 一次最多导入 10,000 个地址、2 MB。

| 导入方式 | 效果 |
|---|---|
| **直接生效** | 适合已在原状态页确认过的地址。导入后立即生效，不发送任何邮件。 |
| **发送确认** | 给每个地址发一封确认邮件，确认后才开始接收。需要已配置邮件投递。 |

**检查文件**只报告导入结果而不做任何修改：读取的行数、将导入的地址、已是订阅者的地址、曾经退订而被跳过的地址，以及按行号列出的问题行：没有邮箱、不是有效邮箱、文件中已出现过的地址，或页面上没有的组件。

邮件订阅者以纯文本邮件接收每一条更新，邮件使用页面的默认语言。邮件中的状态名称与页面上的标签一致，例如**性能下降**。

| 邮件 | 主题 | 正文 |
|---|---|---|
| 确认订阅 | `确认订阅 <页面名称> 的状态更新` | 确认链接与退订链接。 |
| 组件状态变更 | `<页面名称>：<组件> · <状态>` | 组件、新状态与页面地址。 |
| 事件更新 | `<页面名称>：<标题> · <状态>` | 标题、状态、客户更新与页面地址。 |
| 维护更新 | `<页面名称>：<标题> · <状态>` | 事件更新的全部内容，另加**计划时间**与计划开始时间。 |
| 维护提醒 | `<页面名称>：<标题> · 提醒` | 标题、**计划时间**与计划开始时间，以及页面地址。 |
| 管理订阅 | `管理 <页面名称> 的状态更新订阅` | 管理订阅的链接。 |
| 事故复盘 | `<页面名称>：事故复盘 · <标题>` | Markdown 格式的复盘与事件地址。 |

承诺了下次更新的更新会多一行**下次更新不晚于**和对应时间，时间使用页面时区。除确认邮件外，每封邮件末尾都有管理订阅和退订链接。

**计划时间**使用页面时区并标明时差，例如 `2026-05-25 18:00 UTC+08:00 (Asia/Shanghai)`。

Webhook 订阅者以 JSON 请求接收每一条更新。请求格式、Payload 字段与重试节奏见[状态页 Webhook 订阅](/zh-Hans/status-page-webhooks)。

每次发布事件或维护更新时，系统都会为匹配订阅者创建有界投递任务。**订阅者**页面显示尝试次数、成功状态、最后错误与重试状态。投递保留期可配置为 30、60、90、180 或 365 天。

## 私有访问

私有状态页支持邮件地址与邮件域名 Allowlist。获准访客先申请一次性 Magic Link，再获得 1、7 或 30 天的状态页会话。带链接的邮件使用页面的默认语言，链接 15 分钟内有效。管理员可以立即吊销活动会话。私有访问会覆盖公共页、归档、事件详情与订阅流程。

## 自定义域名与 TLS

添加域名前，先把 <code>http.external_url</code> 配置为 MoleSignal 的真实公共 URL。域名面板随后会显示需要创建的 DNS 所有权验证与路由记录。

域名状态依次为**等待 DNS**、**验证中**、**已验证**、**正在配置 TLS**与**有效**。**失败**或**降级**状态会显示可执行原因与重试入口。

如需由 MoleSignal 直接使用自动管理的证书托管自定义 Hostname，请启用 <code>http.tls</code> 并设置账户邮箱：

```toml
[http]
external_url = "https://molesignal.example.com"

[http.tls]
enabled = true
account_email = "ops@example.com"
```

如果 TLS 在外部负载均衡器终止，仍需保持公共 URL 与 DNS 目标准确，并在边缘管理证书。

## 发布自动化

打开**设置 → 自动化**，把运维事件转换为客户更新。

1. 选择**告警事件**、**拨测检查**或**业务服务**作为来源。
2. 选择具体资源、最低严重度或 Monitor 状态转换，并填写必须匹配的标签。
3. 添加延迟，避免瞬时故障直接形成客户沟通。
4. 映射事件影响与受影响的状态页组件。**业务服务**规则不选组件时，发布到以“交给自动化规则”方式代表该业务服务的组件。
5. 选择**人工批准**或**自动发布**，并定义消息模板。
6. 启用前先在规则模拟器中测试。

第一条完整匹配的有序规则会接管事件。Correlation Key 会把来源后续状态转换连接到同一个事件。人工模式生成可供授权用户批准、拒绝或编辑的候选项；自动模式会直接发布生成的事件。**暂停全部自动化**只停止新的规则匹配，不会修改已经公开的事件。

<Note>
告警事件适合由响应人员负责的检测，拨测 Monitor 适合直接验证客户路径。两种来源都能更新同一组件模型，但每条规则保留独立的批准与延迟策略。
</Note>

## 权限

| 权限 | 能力 |
|---|---|
| <code>status_pages.read</code> | 读取状态页、组件、事件、历史、订阅者、域名与自动化状态。 |
| <code>status_pages.manage</code> | 创建和修改状态页、组件、访问、订阅者、域名与自动化规则。 |
| <code>status_pages.publish</code> | 发布客户更新，并批准、拒绝或应用自动化候选项。 |
| <code>alerts.read</code> | 选择告警来源，并在自动化模拟器中使用告警事件。 |
