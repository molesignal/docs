角色是一组具名的权限。权限策略也是一组具名的权限，它和角色分开存放，可以被多个角色附加，也可以让 API Token 跟随。成员在[用户](/zh-Hans/identity/members#用户)中获得作用于整个工作区的角色。访问授权把角色授予用户或团队，作用于整个组织或选定的资源，还可以设置到期时间。打开 **身份与访问 → 角色**、**权限策略** 或 **访问授权**。

## 角色

**角色** 列出工作区的内置角色和自定义角色，包括每个角色附加的策略、授予的权限和引用情况：成员、服务账号、邀请和绑定。内置角色只读，参见[内置角色](/zh-Hans/identity#内置角色)。

创建自定义角色：

1. 点击 **新建角色**。
2. 填写 **Key**，只能使用小写字母、数字和下划线，创建后不能修改。
3. 填写 **名称** 和 **描述**。
4. 在 **权限策略** 中勾选角色附加的策略。角色拥有这些策略里的全部权限，策略改了，角色跟着变。
5. 在 **单独配置的权限** 中，勾选策略之外角色还需要的权限。每项权限都说明了它允许的操作；已勾选策略授予的权限会自动勾上并标出来源策略，在这里不能取消。
6. 点击 **创建角色**。

角色授予的是它单独配置的权限加上所附加策略的权限。点击自定义角色可以修改这两部分。只有没有任何成员关系、服务账号、邀请或绑定引用时，**删除** 才能删掉自定义角色。读取角色需要 `iam.roles.read`，修改角色需要 `iam.roles.manage`，删除角色需要 `iam.roles.delete`。

## 权限策略

**权限策略** 列出工作区的内置策略和自定义策略，包括每条策略的权限，以及使用它的角色和 Token。角色可以附加策略，API Token 可以跟随一条策略，参见 [Token 能做什么](/zh-Hans/identity/tokens#token-能做什么)。

| 内置策略 | 权限 |
|---|---|
| **只读观察者** | 读取可观测数据、仪表盘、告警、排班、保存的视图、流水线、函数、报告、状态页、拨测、服务等级和复盘。 |
| **数据分析师** | 探索可观测数据，并创建仪表盘和保存的视图。 |
| **流水线开发者** | 读取可观测数据，并管理数据流、流水线和函数。 |
| **告警管理员** | 读取可观测数据，并管理告警规则、排班、状态页、拨测和复盘。 |
| **组织管理员** | 管理组织设置、成员、角色、访问授权、API Token、服务账号和审计，以及状态页、拨测、服务等级和复盘。 |
| **数据写入** | 写入数据并上报部署：`logs.write`、`metrics.write`、`traces.write`、`profiles.write` 和 `apm.deploy`。数据写入 Token 跟随这条策略。 |

内置策略只读，随产品更新。打开一条内置策略，点击 **复制为自定义策略**，可以从它开始写自己的策略。

创建自定义策略：

1. 点击 **新建策略**。
2. 填写 **名称**、**Key**（只能使用小写字母、数字和下划线，创建后不能修改）和 **说明**。
3. 在 **权限** 中，可以在 **可视化** 里勾选权限，也可以在 **JSON** 里直接编写文档，两者编辑的是同一份文档。JSON 会指出文档里的第一个错误及其位置，文档有效时在保存前列出它允许的权限。
4. 点击 **创建策略**。

策略文档的写法参照 AWS IAM 策略：

```json
{
  "Version": "1",
  "Statement": [
    { "Sid": "Dashboards", "Effect": "Allow", "Action": "dashboards.*" },
    { "Effect": "Allow", "Action": ["streams.read", "streams.query"] }
  ]
}
```

- `Version` 为 `"1"`，策略至少要允许一项权限。
- `Effect` 只能是 `"Allow"`：策略只允许，没有拒绝。
- `Action` 是一项权限，或一组权限。`*` 匹配任意一串字符，所以 `dashboards.*` 是全部仪表盘权限，`*` 是全部组织权限。匹配不到任何权限的 Action 会被拒绝。
- `Sid` 是语句的名字，可选。
- `Resource`、`Condition`、`Principal` 和 `NotAction` 会被拒绝：策略作用于整个组织。要把角色限定到单个资源或附加条件，请用[访问授权](#访问授权)。

保存时，策略记下文档在那一刻允许的权限。用了通配符的策略也包含之后加入权限目录的权限：MoleSignal 启动时会把它们补进策略。在 **可视化** 中勾选会把含通配符、`Sid` 或多条语句的文档改写成一条逐项列出权限的语句，改写前会先提示。

修改策略会立即改变所有附加它的角色和所有跟随它的 Token。只有没有角色附加、也没有仍然有效的 Token 跟随时，**删除** 才能删掉自定义策略；曾经跟随它、已撤销或已过期的 Token 会以权限列表的形式保留它当时的权限。读取策略需要 `iam.policies.read`，修改策略需要 `iam.policies.manage`，删除策略需要 `iam.policies.delete`。

## 访问授权

访问授权是一条角色绑定：在一个组织中、对一定范围的资源，把角色授予一个身份主体。访问权应跟随某个人、团队或资源，而不是扩大一个宽泛的角色时，使用访问授权。

1. 打开 **访问授权**，点击 **新建访问授权**。
2. **身份主体**：选择 **用户** 或 **团队**，再选定具体对象。
3. **组织**：显示当前工作区，仅供参考。
4. **资源范围**：**整个组织**，或一种资源类型（**仪表盘** 或 **数据流**）下的某个资源或 **该类型的全部资源**。
5. **角色与权限**：授权给出的角色。
6. **限制条件**：可选的 **环境**，请求的环境必须与它完全一致，例如 `prod`；以及 **到期时间**。
7. 点击 **创建授权**。

**删除** 立即终止授权。读取授权需要 `iam.grants.read`，创建或删除授权需要 `iam.grants.manage`。

## 跨组织共享资源

跨组织共享让另一个组织访问本组织的选定资源。共享是显式且不可传递的：只对选定的组织和资源生效，不会被继承或转授。

1. 在 **访问授权** 中点击 **跨组织共享**。
2. 选择 **目标组织**。
3. 选择资源类型和资源：**仪表盘** 或 **数据流**。
4. 选择权限：仪表盘可选 `dashboards.read` 和 `dashboards.edit`，数据流可选 `streams.read` 和 `streams.query`。
5. 可以设置 **到期时间**，然后点击 **创建共享**。

共享创建后处于 **等待接受** 状态。目标组织的管理员在自己的 **访问授权** 中点击 **接受** 后，共享变为 **已生效**。双方都可以 **撤销** 共享。创建、接受和撤销共享需要 `iam.cross_org.manage`。

## 角色、策略与授权 API

| 操作 | 端点 | 权限 |
|---|---|---|
| 列出权限目录 | `GET /api/v1/iam/permissions` | `iam.roles.read` 或 `iam.policies.read` |
| 列出角色 | `GET /api/v1/roles` | `iam.roles.read` |
| 创建自定义角色 | `POST /api/v1/roles` | `iam.roles.manage` |
| 更新自定义角色 | `PATCH /api/v1/roles/{id}` | `iam.roles.manage` |
| 删除未被使用的自定义角色 | `DELETE /api/v1/roles/{id}` | `iam.roles.manage` |
| 列出权限策略或读取一条 | `GET /api/v1/iam/policies`、`GET /api/v1/iam/policies/{id}` | `iam.roles.read` |
| 创建自定义策略 | `POST /api/v1/iam/policies` | `iam.roles.manage` |
| 更新自定义策略 | `PATCH /api/v1/iam/policies/{id}` | `iam.roles.manage` |
| 删除未被使用的自定义策略 | `DELETE /api/v1/iam/policies/{id}` | `iam.roles.manage` |
| 列出或创建访问授权 | `GET /api/v1/iam/role-bindings`、`POST /api/v1/iam/role-bindings` | `iam.policies.read`、`iam.policies.manage` |
| 删除访问授权 | `DELETE /api/v1/iam/role-bindings/{id}` | `iam.policies.manage` |
| 列出或创建跨组织共享 | `GET /api/v1/iam/cross-org-grants`、`POST /api/v1/iam/cross-org-grants` | `iam.policies.read`、`iam.policies.manage` |
| 接受或撤销共享 | `POST /api/v1/iam/cross-org-grants/{id}/accept`、`POST /api/v1/iam/cross-org-grants/{id}/revoke` | `iam.policies.manage` |

角色的请求体包含它单独配置的 `permissions` 和附加的 `policy_ids`，响应另外给出 `effective_permissions`，即角色授予的全部权限。策略的请求体包含 `key`（仅创建时）、`name`、`description` 和 `document`，响应另外给出 `builtin`、解析出的 `permissions`，以及 `usage`：附加它的角色数和跟随它的有效 Token 数。文档无效时返回 `400` 并指出问题所在，例如 ``Statement[0].Action[1]: no permission is called `alerts.rules.reed` ``；删除仍在使用的策略返回 `409`。
