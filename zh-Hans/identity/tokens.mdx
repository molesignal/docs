API Token 让程序无需登录即可调用 MoleSignal。Token 本身不挂角色：它以某个成员或服务账号的身份执行，权限范围可以进一步限定它能做什么。服务账号是程序的身份：它不能登录，有自己的角色，它的 Token 以该账号的身份执行。

## Token 类型

| 类型 | 以谁的身份执行 | 签发位置 |
|---|---|---|
| **个人 Token** | 签发它的成员。 | **个人设置 → API tokens** |
| **服务账号 Token** | 某个服务账号。 | **身份与访问 → API tokens** 或 **服务账号** |
| **默认接入 Token** | 它的所有者，只能写入数据。 | **数据源**，参见[接入 Token](/zh-Hans/intake#接入-token)。 |
| **RUM 客户端 Token** | 它所属的用户体验应用，只能写入 RUM 数据。 | **数据源**，参见[接入 Token](/zh-Hans/intake#接入-token)。 |

Token 的格式为 `ms_<prefix>_<secret>`，RUM 客户端 Token 为 `msrum_…`。前缀用于查找 Token，Secret 只保存哈希值。把 Token 作为 Bearer 凭证发送：

```http
Authorization: Bearer ms_…
```

Token 不能进入 `_sys` 组织。

## Token 能做什么

Token 能做的永远不超过它所属的成员或服务账号在请求那一刻能做的。权限范围在此基础上再收窄：

| 权限范围 | Token 能做的 |
|---|---|
| **与我相同**、**与服务账号相同** | 所属成员或服务账号能做的都能做，随其权限变化。 |
| **权限策略** | 某条[权限策略](/zh-Hans/identity/roles#权限策略)的权限，例如 **数据写入**，随策略变化。 |
| **自定义** | 签发时勾选的权限，之后不再变化。 |

Token 不能被授予签发者自己没有的权限。成员失去某项权限后，他的所有 Token 也随之失去；成员离开工作区或被禁用后，他的 Token 立即失效。通过访问授权或共享获得的单个资源上的角色，也只在 Token 的权限范围内对它生效。RUM 客户端 Token 属于应用：它只能写入 RUM 数据，其他什么都做不了。

## 签发个人 Token

1. 打开 **个人设置 → API tokens**，点击 **新建 Token**。
2. 填写 **名称**，例如 `collector-production`。
3. 选择 **权限范围**：**与我相同**、某条 **权限策略**，或 **自定义** 权限。你没有的策略或权限不能选；选中的策略会列出它的权限。
4. 设置 **有效天数**：默认 365，最大 1825。留空表示永不过期。
5. 点击 **创建 Token**，再点击 **复制 Token**。Token 只显示这一次。

列表显示你的 Token 及其权限范围、类型、过期时间和最近使用时间。**撤销** 会立即并永久停用 Token。管理自己的 Token 需要 `personal_tokens.manage`，所有内置角色都有这项权限。个人 Token 只能在登录会话中签发：Token 不能签发另一个 Token。

## 组织的 Token

**身份与访问 → API tokens** 列出工作区的所有 Token，以及每个 Token 代表的成员、服务账号或应用和它的权限范围。查看需要 `api_tokens.read`。拥有 `api_tokens.revoke` 时可以撤销任意 Token，也可以点击 **为服务账号签发 Token**：选择 **服务账号**、**权限范围** 和有效期。

## 服务账号

采集器、CI 流水线、集成或 AI Agent 这类无人值守的程序应使用服务账号，这样成员离开工作区也不会中断自动化。

1. 打开 **服务账号**，点击 **创建服务账号**。
2. 填写 **名称**（例如 `deployment-automation`）、**描述** 和 **角色**。
3. 点击 **创建账号和 Token**，并复制初始 API Token。它能做该账号能做的一切，365 天后过期，且只显示一次。

点击某个账号即可管理它：

| 操作 | 效果 |
|---|---|
| **保存更改** | 保存新的名称、描述或角色。该账号的所有 Token 立即跟随新角色。 |
| **管理 API tokens** | 打开按该账号筛选的 **API tokens**，可以再签发 Token 或撤销某个 Token。 |
| **禁用** / **启用** | 禁用后，账号及其所有 Token 都无法通过认证，直到重新启用。 |
| **删除** | 删除账号并撤销它的所有 Token，无法撤回。 |

账号的 **身份主体 ID** 在审计记录和访问授权中标识它。读取服务账号需要 `service_accounts.read`，修改需要 `service_accounts.manage`。

## 选择合适的 Token

| 调用方 | 推荐的 Token |
|---|---|
| 发送遥测数据的采集器或 Agent | 跟随 **数据写入** 策略的服务账号 Token，或你的默认接入 Token。 |
| 发送用户体验数据的浏览器或移动端代码 | 该应用的 RUM 客户端 Token。它对最终用户可见。 |
| 上报部署的 CI | 跟随 **数据写入** 策略的 Token，该策略同时包含 `apm.deploy`。 |
| 读取数据或修改资源的自动化 | 用策略或自定义权限收窄过的服务账号 Token。 |
| 由人运行的 MCP 客户端或脚本 | 设置了有效期的个人 Token。 |

登录会话保存在浏览器的 HttpOnly Cookie 中，默认 24 小时后结束（`[auth].session_ttl_secs`）。`Authorization` 请求头不接受它，程序始终使用 API Token。

## Token API

| 操作 | 端点 | 权限 |
|---|---|---|
| 签发个人 Token | `POST /api/v1/me/api-tokens` | `personal_tokens.manage` |
| 列出自己的 Token | `GET /api/v1/me/api-tokens` | `personal_tokens.manage` |
| 撤销自己的 Token | `DELETE /api/v1/me/api-tokens/{id}` | `personal_tokens.manage` |
| 列出 Token 可以限定到的范围：权限策略和组织权限 | `GET /api/v1/me/api-tokens/scopes` | 已登录的成员 |
| 为服务账号签发 Token | `POST /api/v1/auth/tokens` | `api_tokens.revoke` |
| 列出全部 Token | `GET /api/v1/auth/tokens` | `api_tokens.read` |
| 撤销任意 Token | `DELETE /api/v1/auth/tokens/{id}` | `api_tokens.revoke` |

参见[签发 API Token](/zh-Hans/api/auth/issue-token)、[列出 API Token](/zh-Hans/api/auth/list-tokens)与[撤销 API Token](/zh-Hans/api/auth/revoke-token)。
