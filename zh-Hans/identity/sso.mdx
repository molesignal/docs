单点登录让用户使用企业目录或常用平台的账号登录，而不必使用 MoleSignal 密码。打开 **身份与访问 → SSO 服务商** 和 **邮箱域名**。读取服务商与域名需要 `org.sso.read`，修改需要 `org.sso.manage`。

## 添加服务商之前

把 `[http].external_url` 设置为 MoleSignal 的公开地址。OIDC 与 OAuth 2.0 的 **Redirect URI**、SAML 的 **Assertion Consumer URL（ACS）** 以及 **SP Entity ID** 的默认值都由它派生，身份提供方需要回调这些地址。服务商配置保存在数据库中，无需重启即可生效。

## 添加服务商

1. 打开 **SSO 服务商**，点击 **新建服务**。
2. 选择平台：**常用平台**、**企业目录**，或 **通用协议** 中的 **OIDC**、**OAuth 2.0**、**SAML**、**LDAP**。选错时点击 **更换平台**。
3. 平台支持多种协议时，在 **协议** 中选择。
4. 填写平台需要的信息，并按说明在身份提供方注册表单显示的 **Redirect URI** 或 **Assertion Consumer URL（ACS）**。
5. 检查[身份字段映射](#身份字段映射)、[角色绑定](#角色绑定)与[登录范围](#登录范围)。
6. 点击 **创建服务**。

## 预置平台

选择预置平台后，端点、Scopes 和字段映射会自动填好。OIDC 与 OAuth 2.0 平台只需填写下表的信息和 **Client ID**、**Client Secret**，推出的端点在 **端点与 Scopes** 中查看。

| 平台 | 协议 | 需要填写 | 用户组 |
|---|---|---|---|
| Google | OIDC、SAML | OIDC 无需其他信息 | OIDC 不提供；SAML 为群组成员资格 |
| Microsoft Entra ID | OIDC、SAML | **目录（租户）ID**、**云环境**（全球或世纪互联） | 组的对象 ID |
| GitHub | OAuth 2.0 | **部署方式**；GitHub Enterprise Server 还需 **服务器域名** | 组织（`my-org`）与团队（`my-org/sre`） |
| GitLab | OIDC | **实例地址**，默认 `https://gitlab.com` | `groups` |
| Okta | OIDC、SAML | **Okta 域名**、**授权服务器** | `groups` 声明 |
| Auth0 | OIDC | **租户域名** | 自定义声明 |
| Keycloak | OIDC | **服务地址**、**Realm** | Group Membership mapper 写出的 `groups` |
| authentik | OIDC | **服务地址**、**应用 slug** | `groups` |
| 飞书 | OAuth 2.0 | **版本**（飞书或 Lark） | 不提供 |
| AD FS | SAML | IdP 元数据 | Token-Groups |
| JumpCloud | SAML | IdP 元数据 | `memberOf` |
| Active Directory、OpenLDAP、FreeIPA | LDAP | 服务地址、Base DN 与查询账号 | `memberOf` |

GitHub 按固定字段读取：主体是账号的数字 ID，邮箱取已验证的主邮箱，读取组织和团队需要 `read:org`。组织开启了 OAuth 应用访问限制时，需要组织所有者批准该应用，才能读到组织和团队。飞书需要在开放平台为应用开通获取用户邮箱信息的权限。

## 通用协议

| 协议 | 配置 |
|---|---|
| OIDC | **Issuer URL**、**Authorization URL**、**Token URL**、**UserInfo URL**、**JWKS URL**、**Client ID**、**Client Secret**，以及以空格分隔的 **Scopes**。填好 **Issuer URL** 后点击 **自动发现**，从 `.well-known/openid-configuration` 填好其余端点。 |
| OAuth 2.0 | 用于不签发 ID Token 的身份提供方：**Authorization URL**、**Token URL**、**UserInfo URL**、**Client ID**、**Client Secret** 与 **Scopes**。登录后用访问令牌读取 **UserInfo URL**，再按字段映射取出账号。 |
| SAML | **SP Entity ID**、**IdP Entity ID**、**IdP SSO URL** 和 **IdP 签名证书（PEM）**。在 **IdP 元数据** 中填写元数据 URL，或点击 **粘贴 XML** 粘贴元数据，再点击 **导入**，即可填好后三项。单点登录地址只支持 HTTP-Redirect 方式。 |
| LDAP | **LDAP 服务地址**：`ldaps://`，或开启 **StartTLS** 的 `ldap://`。**用户 Base DN**，例如 `ou=people,dc=example,dc=com`。包含 `{username}` 的 **用户查询过滤器**，查询前会对输入值转义。**查询账号 Bind DN** 及其 **查询账号密码**：只有目录允许匿名查询时才可以同时留空。 |

编辑服务商时，**Client Secret** 或 **查询账号密码** 留空会保留已保存的值。

## 身份字段映射

**身份字段映射** 告诉 MoleSignal 从哪里读取一个人的四个字段：

| MoleSignal 字段 | OIDC 与 OAuth 2.0 | SAML | LDAP |
|---|---|---|---|
| **稳定主体标识** | Claim 或 JSON 字段，支持 `realm_access.roles` 这类点分路径。 | Attribute Name，或用 `NameID` 读取断言主体。 | 属性，或用 `dn` 读取条目的 DN。 |
| **邮箱** | Claim 或 JSON 字段。 | Attribute Name。 | 属性。 |
| **显示名称** | Claim 或 JSON 字段。 | Attribute Name。 | 属性。 |
| **用户组** | Claim 或 JSON 字段。 | Attribute Name。 | 属性。 |

OIDC 与 OAuth 2.0 的值可以用 `|` 列出多个来源，依次取第一个有值的，例如 `email | preferred_username`。没有有效邮箱的登录会被拒绝。

## 角色绑定

**认证平台用户组 → 本平台角色** 列出从 **用户组** 的值到 MoleSignal 角色的映射。点击 **添加映射**，填写 **认证平台用户组值**（例如 `platform-admins`）并选择角色。一个人会获得所有命中映射对应的角色，角色在每次登录时同步。

没有映射命中时使用 **默认角色**；未指定默认角色时，使用自助加入的角色。不提供用户组的平台只使用默认角色。

## 登录范围

填写 **允许登录的组** 后，只有属于其中任一组的账号能通过该服务商登录。

Google、GitHub.com、GitLab.com 以及 Microsoft 不限租户的入口，任何人都能注册账号。这类服务商启用前，工作区必须配置[邮箱域名](#邮箱域名)，或在服务商中填写 **允许登录的组**；登录时只接受身份提供方确认过的邮箱。启用后邮箱域名被清空时，这类服务商会拒绝登录。

## 测试登录

依赖一个服务商之前先测一下：在服务商列表或服务商的设置里点击 **测试**。测试用保存的配置走一遍真实的登录，不留下任何变化：不建立会话，不新建或关联账号，不改角色，你自己的登录也不受影响。停用的服务商也能测，启用之前就可以测。测试需要 `org.sso.manage`，不能用 API Token 发起，每个服务商每分钟最多 10 次。

| 服务商 | 怎么测 |
|---|---|
| OIDC、OAuth 2.0、SAML | 新标签页跳到身份提供方，回来时打开结果页。回调地址或 ACS 地址就是登录用的那个。 |
| LDAP | 输入目录账号和密码。这是一次真实的 bind，输错密码会计入目录的锁定策略和这个实例的登录限速。密码不会保存。 |

结果页显示：

- **是否走通。** 没走通时说明原因、处理建议，以及服务端或身份提供方的原话。真实登录会拒绝的情况也算没通过，比如允许登录的组、邮箱域名、账号已停用。
- **身份源返回了什么：** 邮箱、名称、主体和用户组。
- **真实登录会发生什么：** 落到哪个账号（直接登录、账号主人确认关联，或新建账号），以及登录之后的角色，包括会被替换的角色。

如果身份提供方显示了它自己的错误页面，浏览器不会回来，10 分钟后结果显示没有等到结果。常见原因是回调地址没有在身份提供方注册。

结果只对测试时的配置有效。改了端点、密钥、映射或允许登录的组，结果就作废，列表显示 **配置已改**；改名、启用、停用不算。每个服务商保留最近 20 次测试。令牌、断言、密钥和密码不会显示、保存或写进日志。每次测试都以 `org.sso_provider.test` 记入审计，不含身份信息。

## 登录要求

**身份与访问 → SSO 服务商** 顶部的 **登录要求** 决定进入这个工作区要满足什么，需要 `org.sso.manage`。开启后最迟 15 分钟对所有会话生效：不满足的会话在下一次续期时结束，要重新登录。开启和关闭都记入审计。

| 要求 | 效果 |
|---|---|
| **要求多因素认证** | 进入工作区的会话要过[多因素认证](/zh-Hans/identity/mfa)。经本工作区 OIDC、OAuth 2.0 或 SAML 服务商进入的会话算过了，由身份提供方负责；LDAP 和别的工作区的单点登录不算。 |
| **只允许单点登录** | 只能经本工作区的 OIDC、OAuth 2.0 或 SAML 服务商进入，账号密码、Passkey 和 LDAP 都不能进入。Root 用户例外，身份提供方出问题时还能进来。至少有一个启用的这类服务商才能开启；开启期间，最后一个不能停用或删除。还没有启用的服务商用当前配置通过[测试登录](#测试登录)时开启，会提示风险并要求输入工作区名称，审计里记下 `sso_tested: false`。 |

不满足要求时：

| 情况 | 结果 |
|---|---|
| 登录，账号属于多个工作区 | 进入第一个放行的工作区。 |
| 登录，只差多因素认证 | 现场开启 Passkey 或身份验证器 App，开好才拿到会话，并显示恢复码。 |
| 登录，只属于只允许单点登录的工作区 | 拒绝，登录页说明原因。 |
| 切换到要求多因素认证的工作区 | 账号有第二因素时当场验证一次；没有时先到 **安全与登录** 开启。 |
| 切换到只允许单点登录的工作区 | 提示经它的服务商登录。 |
| 自助注册 | 工作区只允许单点登录时不能注册；要求多因素认证时，账号建好后在登录时现场开启。 |
| 数据库客户端的账号登录 | 工作区有任一要求就拒绝，已连接的客户端在下一个请求时失效。改用 [API Token](/zh-Hans/identity/tokens)。 |
| API Token | 不受影响。 |

账号所在的工作区要求多因素认证时，本人不能删掉最后一种第二因素；[管理员重置](/zh-Hans/identity/mfa#管理员重置)不受限制，成员下次登录时现场开启。

平台组织的要求在 `_sys` 组织的 **设置 → 登录要求** 中设置，需要 `sys.settings.signin.manage`，只有 **要求多因素认证** 这一项。

## 登录时发生什么

登录页为每个已启用的服务商显示一行，带平台图标。使用 LDAP 服务商时，点击这一行后依次输入目录用户名和密码。

1. 浏览器跳到身份提供方，认证后回到 MoleSignal。
2. 服务商确认身份：OIDC 的 ID Token 用 JWKS 中的公钥（RSA、EC 或 EdDSA）或 Client Secret（HMAC）验签；OAuth 2.0 读取用户信息接口。MoleSignal 读取映射的字段。
3. 不在 **允许登录的组** 中的账号被拒绝。
4. 之前登录过的身份已关联到某个账号，直接登录这个账号。MoleSignal 按服务商和身份的 subject 查找，不看邮箱。
5. 第一次登录的身份，如果邮箱已有 MoleSignal 账号，要等账号主人确认，见[关联已有账号](#关联已有账号)。
6. 尚无 MoleSignal 账号的人，在邮箱通过工作区的[邮箱域名](#邮箱域名)检查后会自动获得账号。
7. 还不是成员的人，以映射得到的角色或默认角色加入服务商所在的工作区。
8. 对已有成员，命中映射的角色会替换之前的角色。已停用的账号无法登录。
9. 浏览器回到登录页完成登录，并打开登录前要访问的页面。登录失败时，登录页显示原因。

## 关联已有账号

服务商只为自己工作区的人担保，它给出的邮箱不足以进入一个已有账号：那个账号可能属于用同一邮箱的另一个人。某个身份第一次以已有账号的邮箱登录时，登录页会请账号主人在同一个浏览器里确认。

| 方式 | 何时提供 | 做法 |
|---|---|---|
| **账号密码** | 账号设置过密码。 | 输入账号密码。 |
| **邮件验证码** | 实例能[发送邮件](/zh-Hans/configuration#告警与邮件)。 | 点击 **发送验证码**，输入邮件里的 6 位数字。每分钟最多发一次。 |

验证码只在发起登录的页面有效，自己没有发起登录却收到的验证码邮件可以忽略。输错 5 次或超过 30 分钟后，要重新通过服务商登录。确认后身份即关联，之后通过它登录不再需要确认。账号开启了[多因素认证](/zh-Hans/identity/mfa)时，确认之后还要完成第二步（Passkey、身份验证器或恢复码），关联才完成。账号没有密码、实例也不能发送邮件时无法在这里确认：请用原来的方式登录，或请管理员配置邮件发送。

由工作区自己的服务商创建的账号，在邮箱得到证明之前只能留在这个工作区：管理员和其他服务商都不能把它加入别的工作区。通过邮件链接重置密码，或用邮件验证码确认关联，都能证明邮箱。经 Google、GitHub.com、GitLab.com 或 Microsoft 不限租户入口创建的账号不受此限，因为这些服务商只接受验证过的邮箱。

每个人可以在[账号设置 → 安全与登录](/zh-Hans/account#安全与会话)查看和解除自己已关联的身份。

## 邮箱域名

**邮箱域名** 限制哪些邮箱地址可以通过[邀请](/zh-Hans/identity/members#邀请)或单点登录加入工作区。点击 **添加域名** 并填写域名，例如 `example.com`。列表为空时任何地址都可以加入，但面向公网账号的服务商无法启用。**删除** 从列表中移除一个域名。
