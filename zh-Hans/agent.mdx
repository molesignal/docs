**Mole Agent** 是内置运维智能体及其产品工作区。

Mole Agent 可以通过服务器注册工具查询日志、指标、链路、RUM、性能剖析、告警、值班数据和报告。Mole Agent 使用当前登录用户的组织与权限；模型提供的组织标识会被忽略。

## 配置模型服务

Mole Agent 需要先配置模型服务，对话才能给出回答。具备 `agent.manage` 权限的管理员按以下步骤添加：

1. 打开 **Mole Agent → 设置 → 模型与推理**，选择 **添加模型服务**。
2. 选择 **服务类型**：OpenAI、Anthropic，或兼容 OpenAI 的端点。
3. 填写 **显示名称**、**默认模型** 与 **API Key**。API Key 只写不读，页面和 API 都不会返回它。
4. 兼容 OpenAI 的端点需要设置 **Base URL**。留空则使用 OpenAI 或 Anthropic 的官方端点。
5. 服务商的默认值不合适时，调整 **无响应超时** 与 **最大输出 Token**。需要在用量里看到成本时，选择 **币种** 并填写单价，然后保存。

**无响应超时** 是多久没有收到模型服务的任何数据就判定这次调用失败，默认 120000 毫秒，可设 1000 到 600000 毫秒。非流式调用要等整段回答生成完，按最长的回答来设。连接失败、限流（429）和服务暂时不可用（5xx、529）会自动重试两次，服务端给出 `Retry-After` 时按它等待；重试只发生在收到回答之前。Anthropic 服务没有设置 **最大输出 Token** 时按 4096 计。

单价按每百万 token 计，用该模型服务选的 **币种**，对它的所有模型都一样：**输入单价，未命中缓存**、**输入单价，命中缓存**（服务商从缓存里提供的那部分输入）与 **输出单价**。只有缓存命中单独计价的服务商才填命中缓存的单价，否则全部输入按未命中的单价计。不填单价只是不计算成本，不影响使用和预算。

可选的币种在模型服务下方的 **币种** 中维护。管理员按 ISO 4217 代码添加，标准名称和符号不合适时可以另填。被模型服务用着的币种不能删除；删除后，用它记下的成本仍按它显示。

模型调用经过 Model Gateway。编辑时让已有的密钥字段留空，会保留已保存的密钥，输入新值则会轮换密钥。环境变量 `MS_AGENT_OPENAI_API_KEY`、`MS_AGENT_ANTHROPIC_API_KEY` 与 `MS_AGENT_COMPATIBLE_API_KEY` 是开发用的回退方式，参见[配置](/zh-Hans/configuration#环境变量)。

## 对话

打开 **Mole Agent → 对话**，选择可用模型，设置时间范围并描述现象。服务、告警、环境或数据流均可固定为调查上下文。

没有启用任何 AI 模型时，对话会在输入框上方给出提示。具备 `agent.manage` 权限的管理员可以通过其中的链接前往 **模型与推理**。

响应可以包含：

- 自然语言结论；
- 工具调用与证据摘要；
- 原始日志、指标、链路或事件链接；
- Token 与模型成本元数据（模型服务填了单价时才有成本）；
- 用于复现的提示词模板版本与内容哈希。

回答底部左侧是 **复制**、**分叉**、**置顶** 与回答时间；右侧先是一个表示把握程度的仪表，置信度从低到高，弧线越长、颜色越偏绿，鼠标指向时显示等级；其后是 **有帮助** 与 **没帮助**。**分叉** 用到这条回答为止的消息开始一个新对话，列表里挂在原对话下面。**置顶** 把这条回答固定在对话顶部，只对你自己生效。

回答下方可以选择 **有帮助** 或 **没帮助**。选择 **没帮助** 时可以勾选原因（结论或根因错了、没定位到问题、建议用不上、答非所问、其他）并补充说明。只有提问的人能评价自己的回答；再次点击已选的评价即可撤回。评价会记下回答当时使用的模型与提示词版本。

组织今天的 token 用量到达预算的提醒阈值时，对话会在输入框上方提示。预算用完后的处理见[用量与预算](#用量与预算)。

大型原始工具结果会溢写到对象存储。删除对话前，系统会尽力归档对话记录。

### 编写消息

输入框里的内容按发出后的样子显示：`- ` 开始一个列表，`1. ` 开始编号列表，`# ` 是标题，`> ` 是引用，`[ ] ` 是待办，```` ``` ```` 是代码块，`**粗体**` 与 `` `代码` `` 边输入边成形。**Enter** 发送。在列表或代码块里，**Enter** 接着写下一项或下一行，在空的列表项上按 **Enter** 退出列表；**⌘ Enter** 或 **Ctrl Enter** 在任何位置都发送。**Shift Enter** 另起一行。粘贴的 Markdown 保留格式；按纯文本粘贴（**⌘ Shift V** 或 **Ctrl Shift V**）则保持原样。消息以 Markdown 发出。

### 执行模式

输入框下方的模式决定 Mole Agent 在这个对话里能执行什么。菜单打开时，按数字 1 到 5 选择模式。

| 模式 | 执行什么 |
|---|---|
| **建议模式**（推荐） | 查询数据并给出改动建议，不执行改动。 |
| **调查模式** | 按需自动运行只读查询，不做任何改动。 |
| **执行模式（需审批）** | 查询自动运行；改动按工具的执行方式，先问你确认或提交审批。 |
| **自动模式** | 查询自动运行；只需你确认的改动，可以撤回的直接执行，删除等破坏性改动仍先问你。 |
| **Bypass permissions** | 只需你确认的改动都不再逐条问你，破坏性改动也一样。 |

在任何模式下，组织工具策略要求审批的改动仍提交给审批人，被禁用的工具仍不可用。只有对话所用的 Agent Profile 在 **审批策略** 中打开了 **允许 Bypass permissions**，才能选择 **Bypass permissions**，开启前会弹窗确认。问题排队期间 Profile 不再允许时，这一轮回答改为逐条确认，并在回答中说明。

### 对话名称

新对话在回答第一个问题时起名：用问题的语言，几个词说明这个对话是关于什么的，做法与 ChatGPT、Claude 给对话起名一致。只是打招呼时还没有可起名的内容，对话会先用第一个问题的文字，等出现有主题的问题再起名。名字只起一次。在列表中点对话旁的铅笔图标可以改名：**Enter** 保存，**Esc** 放弃；改过名的对话不再自动起名。记忆中的出处按对话当前的名字显示。起名和其他模型调用一样计入用量。

### 个人会话与团队会话

对话默认是个人会话；在发出第一条消息之前选定团队，就成为这个团队的会话。可以在输入框下方的 **团队** 中选择，也可以输入 `/team <团队>`。列表里是本人所在的团队，持有 `agent.manage` 的管理员可以选择任意团队。第一条消息发出后，对话的归属不再改变。

| | 个人会话 | 团队会话 |
|---|---|---|
| 谁能阅读和续聊 | 发起人本人 | 团队成员与持有 `agent.manage` 的管理员 |
| 使用哪些技能与 MCP 服务器 | 组织的、本人的，以及对话中挂进来的团队的 | 组织的与本团队的；任何人的个人资源都不使用 |

工具始终以发出这条消息的人的身份执行，使用这个人的权限和自己的凭据。团队会话里，其他人提出的问题会显示提问人的名字。个人会话中调用本人所在某个团队的技能或 MCP prompt 时，这个团队的技能与 MCP 服务器会挂进对话，此后一直可用。对话列表会标出团队会话所属的团队；有团队会话后，可以用 **全部**、**个人**、**团队** 筛选列表。

### 斜杠命令

在输入框开头输入 `/` 会弹出命令菜单，继续输入可按名称或说明筛选。用 ↑ ↓ 选择，**Enter** 运行，**Tab** 只补全不运行，**Esc** 关闭菜单。带参数的命令补全后，菜单列出可选的参数。对话页面与随处可用 ⌘J 打开的 Mole Agent 面板都支持命令。

| 命令 | 作用 |
|---|---|
| `/help` | 列出所有命令 |
| `/new` | 开始新对话 |
| `/team <团队>` | 选择新对话所属的团队；`personal` 表示个人会话。在已开始的对话中输入时，会为这个团队开始一个新对话 |
| `/mode auto\|quick\|deep\|query` | 切换分析模式：**自动模式**、**快速问答**、**深度调查**、**仅生成查询** |
| `/time 15m\|30m\|1h\|6h\|24h\|7d` | 设置时间范围 |
| `/policy advice\|readonly\|approval\|auto\|bypass` | 设置执行模式：**建议模式**、**调查模式**、**执行模式（需审批）**、**自动模式**、**Bypass permissions**。`bypass` 会先弹窗确认，并且只在 Agent Profile 允许时可用 |
| `/model <模型服务>` | 按名称或模型名选择模型服务；`auto` 为自动选择 |
| `/profile <Agent 配置>` | 选择 Agent 配置；`auto` 为默认配置 |
| `/prompt <Prompt>` | 选择 Prompt；`auto` 为自动选择 |
| `/query <问题>` | 只生成查询，不执行 |
| `/dashboard <要展示的内容>` | 创建仪表盘 |
| `/rca <事件> [补充说明]` | 调查一个事件的根因；菜单列出进行中的事件。需要 `alerts.read` 权限 |
| `/export` | 把当前对话下载为 Markdown 文件 |

`/query`、`/dashboard` 与 `/rca` 作为一条消息发出，对话里显示为命令标签加参数，重新生成时按同一命令再做一次；`/query` 的模式只对这一条消息生效。`/rca` 的时间范围是事件开始前 30 分钟到事件结束，事件未结束时到当前。其余命令只改变输入框里的设置，不发送消息。

命令不存在、缺少参数、参数不对或没有权限时，命令不会发出，输入框上方会说明原因。要发送以 `/` 开头的普通文字，在开头写 `\/`，发送时会去掉反斜杠。像 `/var/log/app.log` 这样带第二个斜杠的路径按普通文字发送。

技能与 MCP prompt 也是命令，在菜单的 **技能** 与 **MCP** 分组下：

- `/名称 [要求]` 运行一个对话可用的技能。两个团队的技能同名时，写成 `/名称@团队`；在个人会话中，这样写还会把该团队挂进对话。
- `/<服务器>:<prompt> [参数]` 用发送人自己的凭据从 MCP 服务器取一个 prompt，作为这一轮的问题发出。参数按顺序填写，最后一个参数取剩下的全部文字；也可以写成 `名称=值` 按名称填写，值里有空格时加引号。

要运行脚本的技能需要 Mole Runner；要求成员凭据的服务器，其 prompt 要在发送人填写自己的凭据后才能使用。菜单会在命令上注明。

## 知识与记忆

打开 **Mole Agent → 知识**。**知识** 保存对话会读取的 Markdown 文件，分组织的与各团队的。以 `MOLE.md` 作为入口，用 `@路径` 指向其他文件；也可以运行 `/init`，让 Mole Agent 先看看已有的配置，再问你几个问题，确认后一份份写好。组织的知识由持有 `agent.manage` 的人修改，团队的知识由团队成员修改。

- **新建** 创建文件，或为第一个文件创建文件夹；写成 `runbooks/api.md` 这样的路径时，会同时创建文件夹和文件。
- **上传** 可以选择文件或整个文件夹。
- 文件以 **预览** 打开。**编辑** 时按文件读起来的样子边写边显示，和输入框一样；**源码** 直接编辑 Markdown。文件里有编辑器保留不了的写法（如 HTML 注释）时，改用 **源码** 编辑。
- **AI** 打开一个对话，让 Mole Agent 修改这个文件。

**记忆** 保存对话记下的偏好、做法、事实与教训。个人对话记给发起人本人，团队对话记给团队。每条记忆都以对话的名字链接到它出自的对话。记忆的内容可以像知识文件一样编辑，也可以删除；记忆本身由对话写下。持有 `agent.manage` 的人打开 **对话结束后提炼记忆** 后，对话停下半小时后，模型会从中挑出值得记住的内容，这会用掉组织的模型预算。

## 调查

将复杂问题转为可跟踪的调查。调查会记录：

- 状态与当前步骤；
- 证据对结论的影响；
- 竞争假设与置信度；
- 关联的对话、审批与执行；
- 最终摘要与恢复验证。

## 自动化

自动化用于保存可重复执行的 Mole Agent 工作流。配置项包括触发器、允许使用的工具、执行步骤、审批行为与失败处理。使用**试运行**在不产生真实写操作的情况下验证工作流。

## 审批与执行

具备写能力的工具始终受服务器执行策略约束。

| 风险 | 默认执行模式 |
|---|---|
| L0 | 自动执行。 |
| L1 | 用户确认。 |
| L2 | 单人审批。 |
| L3 | 双人审批。 |
| L4 | 默认禁用；破坏性远程工具至少使用该风险等级。 |

审批会保存拟执行操作，并在策略规定的时间后过期。执行前，服务器会重新验证权限、资源状态、参数、风险与幂等性。执行记录会保留结果与恢复验证。

## 日志巡检

Mole Agent 还可以阅读一条日志数据流并写出报告：可以在 **日志** 中立即巡检一次，也可以在后台按周期巡检。定时巡检会保存每次的报告，并在报告判定有异常时通知。参见[日志巡检](/zh-Hans/log-inspections)。

## 技能

技能是一个包含 `SKILL.md` 的目录：某一类任务的做法说明（开放的 Agent Skills 格式），以及说明里用到的文件。Mole Agent 能看到对话可用的技能的名称与说明，请求与某个技能相符时读取它的说明，说明指向其他文件时再读取这些文件。每个技能同时也是一个斜杠命令。

| 来源 | 在哪里管理 | 谁可以使用 |
|---|---|---|
| **内置** | 随 MoleSignal 提供 | 所有组织，只读 |
| **实例目录** | 服务器上 `[agent].skill_paths` 列出的目录 | 所有组织，只读 |
| **上传** | **Mole Agent → 设置 → 技能 → 上传技能** | 组织、某个团队或某个人 |
| **仓库** | **Mole Agent → 设置 → 技能 → 添加仓库** | 组织、某个团队或某个人 |

持有 `agent.manage` 的管理员可以为本组织停用内置技能和实例目录中的技能。技能同名时，对话按以下顺序取第一个：本人的、团队的、组织的、实例目录中的、内置的。实例目录在启动时读取，目录中的文件有变化时会重新读取，参见[配置](/zh-Hans/configuration)。

### 编写技能

`SKILL.md` 以 YAML frontmatter 开头：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 命令名：以字母开头，只含字母、数字、`-` 与 `_`，最多 64 个字符。不能与内置命令同名。 |
| `description` | 是 | 技能做什么、什么时候用，最多 1024 个字符。Mole Agent 依据它选用技能。 |
| `allowed-tools` | 否 | 技能要用的工具。作为命令运行时直接提供给模型，但仍受组织的工具策略与审批约束。 |
| `argument-hint` | 否 | 参数的写法，显示在命令菜单中。 |
| `version` | 否 | 显示在设置中，并随每次调用记录。也可以写成 `metadata.version`。 |
| `tags`、`examples` | 否 | 标签，以及在技能详情中显示的示例问题。 |
| `requires` | 否 | 写 `runner` 表示技能要运行脚本，需要 Mole Runner。 |

说明正文中，`$ARGUMENTS` 代表命令后面的全部文字，`$1` 到 `$9` 代表其中的各个词。正文中没有这些占位符时，命令后面的文字附在说明之后。

技能包是一个最大 20 MiB 的 `.zip`、`.skill` 或 `.tar.gz`，其中只有一个技能目录：解压后最多 300 个文件、共 20 MiB，单个文件最大 8 MiB。链接和指向目录之外的路径会被拒绝。上传的技能与本归属内已有的技能同名时，会先确认是否替换。技能详情中的 **在对话中试试** 会打开 Mole Agent 并填好命令。

### 技能仓库

技能仓库按分支或标签以一个压缩包的形式下载。整个仓库中（或所填 **目录** 之下）每个含 `SKILL.md` 的目录是一个技能；每个仓库最多 50 个技能，压缩包最大 64 MiB。GitHub、GitLab、Gitea 与 Forgejo、Bitbucket 可以从地址识别；其他托管服务填写包含 `{ref}` 的压缩包地址。私有仓库需要访问令牌，令牌只写不读。

保存仓库时会同步一次。**同步** 会再同步一次，**每天自动同步** 让仓库保持最新。每次同步会新增、更新和移除仓库的技能，并列出没能导入的目录及原因。删除仓库会一并移除它的技能。

## 组织、团队与个人资源

技能、技能仓库与 MCP 服务器属于组织、某个团队或某个人。添加时在 **归属** 中选择，之后可由编辑者移到其有权管理的其他归属。

| 归属 | 谁可以修改 | 在哪里使用 |
|---|---|---|
| 组织 | 持有 `agent.manage` 的管理员 | 所有对话 |
| 团队 | 团队成员与持有 `agent.manage` 的管理员 | 本团队的会话，以及挂进了本团队的个人会话 |
| 个人 | 本人；持有 `agent.manage` 的管理员能看到并停用或删除 | 本人的个人会话 |

名下还有技能、技能仓库或 MCP 服务器的团队不能删除：**身份与访问 → 团队** 会列出这些资源，先把它们移交或删除。

团队与个人添加的技能仓库和 MCP 服务器只能访问公网，以及持有 `agent.manage` 的管理员在 **Mole Agent → 设置 → 网络策略 → 团队与个人连接的内网** 中列出的内网主机与网段，并且始终校验 TLS 证书。组织的技能仓库与 MCP 服务器按各自的设置连接。

## Agent 设置

打开 **Mole Agent → 设置**。各分区排成一行，位于 Mole Agent 页签之下：

| 分区 | 用途 |
|---|---|
| **Agent Profile** | Agent 配置，以及其允许使用的工具、单轮回答的工具调用次数、调查时长与温度、数据范围与网络策略。 |
| **模型与推理** | 模型服务商、只写 API Key、无响应超时与单价。 |
| **用量** | 今日用量与每日 token 预算，以及最近 30 天按来源的用量。 |
| **Prompt 管理** | 内置提示词，以及组织级与个人级的覆盖版本。 |
| **技能** | 内置、实例目录、上传与仓库来源的技能，以及技能仓库。 |
| **工具与能力** | 工具注册表：每个工具的执行方式、限制与特定环境的最低风险等级，以及组织、团队与个人的 MCP 服务器及其工具与 prompt。 |
| **Inbound MCP** | 供外部 AI 客户端使用的 MCP 端点。 |
| **数据访问范围** | 默认 Agent 配置可以读取的环境、服务与数据流。 |
| **网络策略** | Agent 配置能否使用需要联网的工具，以及团队与个人的连接可以访问的内网地址。 |
| **审批规则** | 各风险等级的审批规则。 |

凭据会加密保存，API 永远不会返回凭据原文。

### 工具与能力

工具按产品领域分组列出。打开该分区时各组处于收起状态。可以展开某一组，也可以通过搜索展开包含匹配项的组。**全部**、**只读**、**自动执行**、**需审批** 和 **已停用** 这几个筛选各自显示所含工具的数量。

工具的标题和描述按界面语言显示。工具详情还会显示模型读到的定义，该定义在任何界面语言下都是英文。

### MCP 服务器

打开 **工具与能力 → MCP Servers** 添加服务器、测试连接并导入工具。每台服务器都标明归属。成员也在这里管理个人与团队的服务器。

| 设置 | 说明 |
|---|---|
| 连接方式 | **Streamable HTTP**；**SSE（旧版）**，用于旧版 HTTP + SSE 传输的服务器；**stdio**，只有组织的服务器能用：MoleSignal 在自己的服务器上启动命令，并且只启动实例在 `[agent].mcp_stdio_commands` 中列出的命令。命令不经过 shell，只拿到 `PATH`、`HOME`、`LANG`、`TMPDIR` 与这台服务器自己配置的 **环境变量**，在系统临时目录中运行，每次调用结束后退出。它的凭据放在 **环境变量** 里：认证方式、请求头和成员凭据只用于通过 HTTP 连接的服务器。组织的网络策略管不到命令访问的地址。 |
| 认证方式 | 无认证、所有人共用的令牌或密钥，或 **成员凭据（每人填自己的）**：每个成员为服务器指定的请求头保存自己的值，只有本人的调用会用到。 |
| **请求头** | 每个请求都会带上。名称含 key、token、secret、password、credential、auth 或 cookie 的值会加密保存，只显示末四位；编辑时留空的敏感值保持不变。 |

**测试连接** 会列出服务器的工具。**同步所选工具** 导入选中的工具：新工具在有人启用之前保持停用，最低风险等级按服务器的标注推断。**工具与 prompt** 中每个工具都有开关，**启用全部只读工具** 一次启用所有只读工具；工具策略与审批照常生效。服务器提供的 prompt 会成为命令，写作 `/<服务器>:<prompt>`。

Mole Agent 大约每小时重新检查一次已同步的服务器。输入 schema 有变化、服务器不再列出，或被服务器标为风险更高的工具会变为不可用，等有人检查后重新同步。要求成员凭据的服务器不参加这项检查。

**导入配置** 读取 Claude Desktop、Claude Code、Cursor 或 VS Code 的 MCP 配置，添加其中的服务器。引用变量（例如 `${input:token}`）的值不会导入，会列出来待填写。带 `command` 的是 stdio 服务器：只能导入到组织，并且命令要在实例允许的范围内。

在要求成员凭据的服务器上，**填写我的凭据** 保存成员自己的值。没有填写就调用工具时，工具会返回缺少凭据，Mole Agent 会请成员先填写。

### Prompt 管理

内置提示词是只读的，名称按界面语言显示。在内置提示词上选择 **创建覆盖版本**，可以为组织或某个用户替换该提示词。

### Agent Profile 的运行限制

以下三项对使用该 Profile 的每一轮对话回答生效；没有生效的 Profile 时使用默认值：

| 设置 | 默认值 | 说明 |
|---|---|---|
| **最大工具调用次数** | `32` | 一轮回答最多执行的工具调用次数，1 到 256。 |
| **最长调查时间（分钟）** | `30` | 一轮回答的总时限，1 到 120 分钟。 |
| **温度** | `0.2` | 采样温度，0 到 2。越低，回答越稳定、可复现。 |

工具调用次数或时间用完后，Mole Agent 不再调用工具，用已经拿到的结果给出回答。

### 用量与预算

打开 **Mole Agent → 设置 → 用量** 查看组织今天的 token 用量、每日预算和最近 30 天的用量。用量按 UTC 自然日统计，token 数是输入与输出之和，以下来源都计入：

| 来源 | 说明 |
|---|---|
| **对话** | Mole Agent 对话，包括仪表盘创作。 |
| **根因分析** | 后台为活跃事件自动生成的根因分析，以及在事件上手动生成的根因分析。 |
| **日志巡检** | 立即巡检与定时巡检。 |
| **LLM 函数** | 写入管道里 LLM 类型的函数。 |

模型服务填了单价时，页面同时显示成本，用各模型服务的币种显示；不同币种的成本分开显示，不相加。用到未填单价的模型服务的调用不计成本，这时金额前标 **≥**，表示实际成本至少是这么多。

每日预算默认取实例配置 `[agent].daily_token_budget`（`0` 表示不限），参见[配置](/zh-Hans/configuration)。具备 `agent.manage` 权限的管理员可以为本组织改为 **自定义** 上限或 **不限**，并设置预算用完时对话与手动根因分析的处理方式：

| 处理方式 | 行为 |
|---|---|
| **不再调用模型**（默认） | 问题不发出，留在输入框里；对话上方说明今天的预算已用完以及重置时间。手动生成根因分析返回同样的提示。 |
| **照常回答，只提示** | 照常回答，并在输入框上方提示已超出预算。 |

预算用完后，自动根因分析、日志巡检和 LLM 函数不再调用模型：巡检记为失败，原因是预算已用完；自动根因分析留到预算重置之后；LLM 函数的这一步按失败处理。用量到达提醒阈值（默认 80%，`[agent].budget_warning_percent`）时，对话会在输入框上方提醒。预算的判断有十几秒的缓存，正在进行的一轮回答不会被中途打断，因此实际用量可能略超上限。

每次模型调用还会写入内部数据流 `_agent_model_traces`，可以在 **日志** 中查询。常用字段包括 `origin`（`chat`、`rca`、`inspection`、`llm_eval`）、`provider`、`model`、`prompt_tokens`、`cached_prompt_tokens`（服务商从缓存里提供的那部分输入）、`completion_tokens`、`total_tokens`、`latency_ms`、`cost`、`cost_currency`、`status`、`error`、`tool_calls`、`streaming`、`chat_id`、`user_id`、`profile_id` 与 `prompt_hash`。`cost` 与 `cost_currency` 只在模型服务填了单价时写入；`user_id` 是调用记在谁名下：对话的提问人或巡检的执行身份，根因分析与 LLM 函数的调用没有这个字段。

## 数据处理

Mole Agent 会把对话发送给已配置的模型服务商，其中包括它所调用工具的返回结果。没有配置模型服务时，不会有任何数据离开部署。以下控制项限制 Agent 能够触及的范围：

- **数据访问范围** 限制默认 Profile 可以读取的环境、服务与数据流，始终禁止跨组织访问。
- **网络策略** 决定 Profile 是否可以使用需要网络的工具。新建的 Profile 默认禁用网络。该开关不会启用任意 HTTP、shell、浏览器与开放 MCP 工具。
- **审批规则** 按风险等级要求对写操作进行审批，并决定用这个 Profile 的对话能否选择 **Bypass permissions**。
- **技能与 MCP 服务器** 只会增加做法说明和工具，不会放宽策略：技能允许使用的工具和所有 MCP 工具都沿用组织的执行方式与审批。

模型密钥使用加密根密钥加密，参见[生产检查清单](/zh-Hans/production-checklist)。

## 权限

- `agent.use` 用于打开对话、调查、自动化和执行历史，查看用量，以及评价回答与根因分析；还可以添加个人的技能、技能仓库与 MCP 服务器，并管理本人所在团队的这些资源。
- `agent.manage` 用于配置服务商、提示词、工具、Agent、工作流、每日预算，以及组织的技能与 MCP 服务器。
- `agent.approve` 用于审核受控操作。
