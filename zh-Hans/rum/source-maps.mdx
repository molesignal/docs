Source Map 可以让 MoleSignal 把压缩后的 JavaScript 堆栈还原为源码中的文件、函数、行和列。

## 匹配 SDK 版本

每次构建时，为 `service` 和 `version` 设置稳定值：

```ts
import { initRum } from '@molesignal/browser-rum';

initRum({
  applicationId: 'checkout-web',
  clientToken: 'ms_your_ingestion_token',
  site: 'https://molesignal.example.com',
  service: 'web-frontend',
  version: '2026.08.04.1',
});
```

上传 Source Map 时使用相同的值：

| 上传字段 | SDK 字段 | 示例 |
|---|---|---|
| 服务 | `service` | `web-frontend` |
| 版本 | `version` | `2026.08.04.1` |
| 文件 | 生成的 `.map` 文件 | `app.8f312.js.map` |

<Warning>
  如果 Source Map 的服务或版本不同，事件将无法完成符号化。请让 SDK 版本和上传版本使用同一个构建流水线变量。
</Warning>

## 在页面中上传

<Steps>
  <Step title="在构建中启用 Source Map">
    在生产构建中生成外部 Source Map。如果安全策略要求源码保持私有，请不要把 Source Map 部署到公网。
  </Step>
  <Step title="打开上传页面">
    进入 **RUM → RUM 设置 → Source Maps**，然后点击 **上传 Source Map**。
  </Step>
  <Step title="填写服务和版本">
    输入与 SDK 配置完全一致的 `service` 和 `version`，并选择生成的 `.map` 文件。每个上传文件最大为 50 MiB。
  </Step>
  <Step title="验证符号化">
    从该版本发送一个错误，打开 **RUM → 错误**，确认堆栈已显示原始源码位置。
  </Step>
</Steps>

## 从 CI 上传

如果需要在发布流水线中自动上传 Source Map，请调用需要认证的 Source Map 接口：

```bash
curl --fail-with-body \
  -H "Authorization: Bearer ${MOLESIGNAL_TOKEN}" \
  -F "service=web-frontend" \
  -F "release=${RELEASE_VERSION}" \
  -F "file=@dist/assets/app.js.map" \
  "${MOLESIGNAL_SITE}/api/v1/sourcemaps"
```

请使用限定到目标工作区的 Token。列出 Source Map 元数据需要 `streams.read`；上传或删除需要
`streams.configure`。

## 发布检查清单

- 使用实际部署的产物生成 Source Map。
- 在任何错误可能被记录之前设置 SDK `version`。
- 上传所有按需加载 Chunk 的 Source Map，而不只是主 Bundle。
- 服务和版本名称区分大小写，必须完全一致。
- 部署后发送一个受控错误完成验证。
