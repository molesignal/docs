```http
GET /api/v1/alerts/incidents/{id}/rca
POST /api/v1/alerts/incidents/{id}/rca
```

[Mole Agent](/zh-Hans/agent) 根据事件上下文为事件撰写根因分析（RCA）。每个事件最多有一份分析。

`alert` 角色会自动创建分析。组织配置了已启用且带有 API Key 的模型服务商时，该角色每三分钟为尚无分析的活动事件撰写分析，每轮最多 20 个。`GET` 调用读取已保存的分析。`POST` 调用立即生成新的分析，并替换已保存的分析。

| 调用 | 权限 | 说明 |
|---|---|---|
| `GET` | `alerts.incidents.read` | 分析生成之前返回 `404`，消息为 `no root-cause analysis for this incident yet`。 |
| `POST` | `alerts.incidents.rca` | 等待模型并返回新的分析。可选的查询参数 `locale` 选择输出语言，`en-us` 或 `zh-cn`，默认使用调用用户的语言偏好。 |

<RequestExample>
```bash cURL
curl -X POST "http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/rca?locale=zh-cn" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**响应**

| 字段 | 说明 |
|---|---|
| `incidentId`、`orgId` | 事件与组织的标识符。 |
| `summary` | Markdown 文本形式的分析内容，用编号引用证据，例如 `[E2]`。 |
| `evidence` | 分析所依据的带编号证据，至多 30 条，见下文。 |
| `provider`、`model` | 模型服务商类型，如 `openai`、`anthropic` 或 `openai_compatible`，以及模型名称。 |
| `promptBuiltinKey`、`promptHash` | 提示词模板，以及渲染后提示词的哈希，用于审计。 |
| `promptTokens`、`completionTokens`、`finishReason` | Token 用量，以及服务商报告的结束原因。 |
| `createdAt`、`updatedAt` | 自 Unix 纪元起的微秒数。重新生成分析时，`updatedAt` 会变化。 |

**证据**

每条证据有 `label`（`E1`、`E2`……）、`kind`、`source`，已知时还有 `service`、`subject`（证据是关于什么的，不含数字）、`detail`、`at`、`figures` 和 `link`。

| `kind` | `source` | `figures` |
|---|---|---|
| `insight` | `apm` | `value`、`previous`、`lastWeek`、`calls`、`p95Time`；`detail` 是洞察类型和变化的指标，例如 `anomaly.p95`。 |
| `new_error_group` | `apm` | `occurrences`。 |
| `sample_trace` | `traces` | `duration`，单位微秒；`link.traceId`。 |
| `error_logs` | `logs` | `now` 和 `lastWeek`，即这段时间及上周同一时段的错误级别日志行数。 |
| `new_log_pattern` | `logs` | `lines`，即该模式在这段时间内的错误级别日志行数，采样时为估算值。`subject` 是模式，`detail` 是它的一条消息。 |
| `attribute_skew` | `traces` | `failedShare` 和 `otherShare`，即失败请求和其他请求中带这个取值的占比；`score`，两组在这个字段上的差距（0 到 1）；`failed`，读取的失败请求数。`subject` 是字段，`detail` 是取值。 |
| `business_impact` | `traces` | 有失败请求的取值的 `errors` 和 `requests`，`values` 是这些取值的个数，`important` 是其中重点取值的个数。`subject` 是键的显示名，`detail` 列出最多 3 个取值。 |
| `change`、`similar_incident`、`investigation` | `incident` | 无。 |

只有持有对应来源权限的调用方才能拿到数字：`apm` 需要 `apm.services.read`，`traces` 和 `logs` 需要 `streams.query`，或者持有 `sys.telemetry.read`。其他调用方拿不到 `figures`，并且 `withheld` 为 `true`。`POST` 的响应和 Mole Agent 的 `get_incident_rca` 同样如此。

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | `POST` 调用没有找到该组织已启用且带有 API Key 的模型服务商。 |
| `403` | Token 缺少该调用所需的权限。 |
| `404` | 事件不存在，或 `GET` 调用尚未找到分析。 |
