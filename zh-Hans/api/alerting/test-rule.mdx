---
title: "测试规则"
description: "运行一次已保存的规则，查看条件是否命中。"
"en_link": "/en-US/api/alerting/test-rule"
---

```http
POST /api/v1/alerts/rules/{id}/test
```

在 `now - period_secs` 到 `now` 的窗口内运行一次已保存规则的查询，并报告条件是否命中。该调用不会改变任何状态：不触碰评估状态、事件、通知或规则本身。调用需要 `alerts.manage`，请求体为空。

把 `enabled` 设为 `true` 之前，先测试规则。语句无效或数据流不存在的规则也能被保存而不报错，只有测试会暴露问题。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/test \
  -H "authorization: Bearer $MS_JWT"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "matched": true,
  "value": 2.0,
  "severity": "critical",
  "columns": ["c"],
  "rows": [[2]],
  "scanned_rows": 2,
  "took_ms": 170
}
```
</ResponseExample>

**响应**

| 字段 | 类型 | 说明 |
|---|---|---|
| `matched` | boolean | 条件当前是否命中。结果不考虑 `for_periods`。 |
| `value` | number 或 null | 第一行第一列的值。结果中没有数字时为 `null`。 |
| `severity` | string 或 null | 事件将使用的严重程度。`matched` 为 `false` 时为 `null`。 |
| `columns` | array | 查询结果的列名。 |
| `rows` | array | 结果的前 20 行。 |
| `scanned_rows` | integer | 查询扫描的行数。 |
| `took_ms` | integer | 查询耗时，单位为毫秒。 |
| `anomaly` | object | 仅 `anomaly` 规则返回，包含 `baseline`、`deviation`、0 到 1 的 `score` 和 `reason` 文本。 |

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | 查询无法运行，例如 SQL 无效或字段不存在，或者 `anomaly` 规则没有可用于建立基线的历史数据。 |
| `403` | 规则的数据流不存在，或 Token 缺少 `alerts.manage`。 |
| `404` | 规则不存在。 |
