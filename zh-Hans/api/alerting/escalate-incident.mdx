title: "立即升级事件"
description: "立即通知事件升级策略里的某一级。"
"en_link": "/en-US/api/alerting/escalate-incident"
---

```http
POST /api/v1/alerts/incidents/{id}/escalate
```

把进行中的事件移到升级策略的某一级，立即通知这一级的目标，`escalation.reason` 是 `manual`。不写 `step` 时，取下一个适用于事件严重度的级别。`acknowledged` 的事件退回 `open`，暂缓随之结束，这一级重新开始计算确认超时；仍没人确认时从这里接着升级。该调用需要 `alerts.incidents.escalate`，请求体可以为空。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `step` | integer | 否 | 级别，从 0 数起，要适用于事件的严重度。默认取下一个适用的级别。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/escalate \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"step": 1}'
```
</RequestExample>

响应是更新后的事件，各字段说明见[列出事件](/zh-Hans/api/alerting/list-incidents)。

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | 事件没有升级策略；`step` 超出策略的级数或不适用于事件的严重度；或事件已在最后一级而没有写 `step`。 |
| `403` | Token 缺少 `alerts.incidents.escalate`，或无权访问这个事件。 |
| `404` | 事件不存在。 |
| `409` | 事件已恢复或已并入别的事件，或者更新时事件一直在变；重试即可。 |
