修复动作是预先定义好的一步处置，例如调一次 Jenkins 的回滚任务，或把一个 Deployment 滚动重启。在事件上发起后走[审批](/zh-Hans/agent#审批与执行)：L2 要一人批准，L3 要两人批准，发起人不能批准自己发起的；组织打开[预批准](#预批准)时，人数相同的批准可以提前给好。批准后立即执行，结果和验证都记进事件的[时间线](/zh-Hans/api/alerting/incident-timeline)。页面上的用法见[修复动作](/zh-Hans/alerting/remediation)。

| 方法与路径 | 作用 | 权限 |
|---|---|---|
| `GET /api/v1/alerts/remediation/actions` | 组织的修复动作。 | `alerts.remediation.read` |
| `POST /api/v1/alerts/remediation/actions` | 新建修复动作。 | `alerts.remediation.manage` |
| `PUT /api/v1/alerts/remediation/actions/{id}` | 替换修复动作。 | `alerts.remediation.manage` |
| `DELETE /api/v1/alerts/remediation/actions/{id}` | 删除修复动作。 | `alerts.remediation.manage` |
| `GET /api/v1/alerts/remediation/clusters` | 登记的 Kubernetes 集群。 | `alerts.remediation.read` |
| `POST /api/v1/alerts/remediation/clusters` | 登记集群。 | `alerts.remediation.manage` |
| `PUT /api/v1/alerts/remediation/clusters/{id}` | 修改集群。 | `alerts.remediation.manage` |
| `DELETE /api/v1/alerts/remediation/clusters/{id}` | 删除集群。 | `alerts.remediation.manage` |
| `POST /api/v1/alerts/remediation/clusters/{id}/test` | 测试连接，返回 `{ "ok": true, "version": "v1.30.2" }`。 | `alerts.remediation.manage` |
| `GET /api/v1/alerts/incidents/{id}/remediations` | 适用于事件的动作，和事件上的执行记录。 | 对事件的 `alerts.incidents.read` |
| `POST /api/v1/alerts/incidents/{id}/remediations` | 在事件上发起执行，提交审批。 | 对事件的 `alerts.incidents.remediate` |
| `GET /api/v1/alerts/remediation/preapproval` | 组织的预批准开关，以及每个设了预批准的动作在时间窗内执行了几次、处于什么状态。 | `alerts.remediation.read` |
| `PUT /api/v1/alerts/remediation/preapproval` | 打开或关闭组织的预批准，请求体 `{ "enabled": true }`。 | `alerts.remediation.preapprove` |
| `PUT /api/v1/alerts/remediation/actions/{id}/preapproval` | 设置或替换一个动作的预批准。 | `alerts.remediation.preapprove` 与 `agent.approve` |
| `DELETE /api/v1/alerts/remediation/actions/{id}/preapproval` | 去掉一个动作的预批准。 | `alerts.remediation.preapprove` |
| `POST /api/v1/alerts/remediation/actions/{id}/preapproval/confirm` | 第二个人确认 L3 动作的预批准。 | `alerts.remediation.preapprove` 与 `agent.approve` |

新建、修改、删除和发起执行都记进审计日志；预批准的开关、设置、确认与去掉也一样。

## 修复动作

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 1 到 120 个字符。 |
| `description` | string | 否 | 说明。 |
| `target` | object | 是 | 怎样执行：`kind` 为 `http` 或 `kubernetes`，其余字段见下文。 |
| `parameters` | array | 否 | 发起时要填的参数，最多 10 个，见下文。 |
| `services` | array | 否 | 适用的服务。和 `teamIds` 都空着时所有事件都能用；设了时事件的服务或团队要对得上。 |
| `teamIds` | array | 否 | 适用的团队。 |
| `risk` | string | 否 | `l2`（默认，一人批准）或 `l3`（两人批准）。 |
| `verifyAfterSecs` | integer | 否 | 执行成功后多少秒验证，0 到 86400；默认 `0`，不验证。 |
| `verifyBy` | string | 否 | 怎样算有效：`incidentResolved`（默认，事件已解决或关闭）或 `rule_healthy`（事件的规则回到健康）。 |
| `enabled` | boolean | 否 | 默认 `true`。停用的动作不能发起。 |

**`target`：HTTP 请求**

| 字段 | 类型 | 说明 |
|---|---|---|
| `kind` | string | `http`。 |
| `method` | string | `GET`、`POST`（默认）、`PUT` 或 `PATCH`。 |
| `url` | string | 地址模板，`http://` 或 `https://` 开头。 |
| `headers` | object | 请求头；值是模板，加密保存。 |
| `body` | string | 请求体模板，JSON，最长 16384 个字符；占位符可以不带引号当数字用。把每个占位符换成 `0` 后要是合法的 JSON，否则返回 `400`。有请求体时 `Content-Type` 为 `application/json`；空着不带请求体。 |
| `signingSecret` | string | 签名密钥，加密保存。设了就带 `X-MoleSignal-Timestamp` 与 `X-MoleSignal-Sign`，算法同[通用 Webhook 的签名](/zh-Hans/notification-channels/webhooks#请求头与签名)。 |

请求只连地址解析出的 IP，拒绝云厂商元数据地址，不跟随跳转，30 秒超时；返回 2xx 算成功。

**`target`：Kubernetes**

| 字段 | 类型 | 说明 |
|---|---|---|
| `kind` | string | `kubernetes`。 |
| `clusterId` | string | 登记的集群。 |
| `operation` | string | `restart`（滚动重启，同 `kubectl rollout restart`）、`scale`（改副本数）或 `rollback`（回到上一个版本，同 `kubectl rollout undo`）。 |
| `workloadKind` | string | `Deployment`、`StatefulSet` 或 `DaemonSet`。只有 Deployment 能回滚，DaemonSet 不能扩缩容。 |
| `namespace`、`workloadName` | string | 命名空间和工作负载名，可以是模板。 |
| `replicas` | string | 扩缩容的副本数，可以是模板，例如 `{{params.replicas}}`。 |

**`parameters[]`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | string | 模板里写 `{{params.<key>}}`。 |
| `label` | string | 发起时显示的名字。 |
| `kind` | string | `text`（默认）、`number` 或 `select`。 |
| `options` | array | `select` 的选项。 |
| `required` | boolean | 默认 `false`。 |
| `default` | string | 没填时用的值。 |

**模板变量**：`{{incident.id}}`、`{{incident.summary}}`、`{{incident.severity}}`、`{{incident.status}}`、`{{incident.service}}`（`service` 标签，没有时取第一个受影响的服务）、`{{incident.url}}`（事件页地址），以及 `{{params.<key>}}`。填进地址时按百分号编码，填进 JSON 请求体时按 JSON 字符串转义；没有的变量换成空串。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/remediation/actions \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "name": "Roll back checkout",
    "target": {
      "kind": "http",
      "method": "POST",
      "url": "https://jenkins.example.com/job/rollback/buildWithParameters?service={{incident.service}}",
      "headers": { "Authorization": "Bearer <jenkins-token>" },
      "body": "{\"reason\": \"{{params.reason}}\", \"incident\": \"{{incident.url}}\"}"
    },
    "parameters": [{ "key": "reason", "label": "Why", "required": true }],
    "services": ["checkout"],
    "risk": "l3",
    "verifyAfterSecs": 600,
    "verifyBy": "incident_resolved"
  }'
```
</RequestExample>

响应是保存的动作。请求头的值和签名密钥不再返回：`headers` 里的值为空，`secretsSet` 列出已经设了的秘密，例如 `["header:Authorization", "signing_secret"]`。修改时请求头的值留空、不传 `signingSecret` 的保持原样；`signingSecret` 传空串时去掉签名。

## Kubernetes 集群

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 名称。 |
| `apiServer` | string | 是 | API Server 地址，`https://` 开头。 |
| `caCert` | string | 否 | PEM 格式的 CA 证书；空着用系统信任的根证书。 |
| `token` | string | 新建时必填 | ServiceAccount Token，加密保存，不再返回；修改时留空保持原样。 |

Token 需要对目标工作负载有 `get` 和 `patch` 权限，回滚还要能列出 ReplicaSet。连接只连 API Server 地址解析出的 IP，拒绝云厂商元数据地址，30 秒超时。删除还有动作在用的集群会被拒绝。

## 预批准

组织打开预批准之后（默认关闭），可以给修复动作设预批准：对列出的服务，在一个时间窗内最多执行几次，不必每次等人审批。L2 动作设置即生效；L3 动作要另一个人调用 `confirm` 确认后才生效，预批准只把审批提前，不减少审批的人数。设置和确认要以本人登录，API Token 不行。

**请求体**（`PUT /api/v1/alerts/remediation/actions/{id}/preapproval`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `services` | array | 是 | 适用的服务，最多 20 个，都要在动作本身的适用范围内。 |
| `maxRuns` | integer | 是 | 时间窗内最多执行几次，1 到 20。 |
| `windowSecs` | integer | 是 | 时间窗长度，300 到 604800 秒。 |
| `expiresAt` | integer | 否 | 到期时间，自纪元起的微秒；不填不过期。 |
| `channels` | array | 否 | 执行后发通知的地方，最多 5 个：`connectorId`、`targetType` 与 `target`，和通知策略的目标一样。 |

响应是 `{ "preapproval": { ... } }`，比请求体多出 `approvers`（`[{ "userId", "at" }]`）、`setBy` 与 `setAt`。设置的人算第一位批准人；替换预批准时批准人只留下设置的人。修复动作本身的执行方式、参数、适用的服务或团队、风险改了之后，批准人清空，要重新确认。

`GET /api/v1/alerts/remediation/preapproval` 返回 `{ "enabled": true, "actions": { "<action-id>": { "used": 1, "state": "active" } } }`。`state` 是 `off`（组织没打开）、`expired`、`awaiting_approver`（L3 还差一个人确认）、`used_up`（时间窗内的次数用完了）或 `active`。

预批准生效时，在适用服务的事件上发起这个动作，审批直接记为已批准，批准人是设置和确认预批准的人，随后立即执行；发起人仍然要有 `alerts.incidents.remediate`。发起人自己给的预批准不替本人算数：除去发起人以后批准的人不够时，照常等审批，审批记录里也不会出现发起人。次数用完、到期或组织关闭了预批准时照常走审批。执行后不论成败，都发通知到 `channels`。

## 在事件上执行

```http
GET /api/v1/alerts/incidents/{id}/remediations
```

返回 `{ "actions": [ ... ], "runs": [ ... ] }`：适用于这个事件、已启用的动作（秘密已去掉），和事件上的执行记录。审批被驳回、过期或撤销的执行在读取时记成 `declined`。

```http
POST /api/v1/alerts/incidents/{id}/remediations
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `actionId` | string | 是 | 要执行的动作，要适用于这个事件。 |
| `inputs` | object | 否 | 参数的值，键是参数的 `key`。必填的要有，数字要是数字，选项要在选项里，不能有多余的；没填的用默认值。每个值最长 500 个字符。 |
| `reason` | string | 否 | 写在审批上的原因，最长 2000 个字符；不填时自动生成。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/remediations \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"actionId": "<action-id>", "inputs": {"reason": "pool exhausted after v2026.10.28"}}'
```
</RequestExample>

响应是 `{ "run": { ... }, "approval": { ... } }`：执行记录，和提交的审批（风险按动作的 `risk`，影响写明会调的地址，或在哪个集群上对哪个工作负载做什么）。审批人用 `POST /api/v1/agent/approvals/{approvalId}/review` 批准或驳回，请求体为 `{ "approve": true, "comment": "…" }`，需要 `agent.approve`；批准够人数后立即执行。动作的[预批准](#预批准)适用时，返回前已经执行完，响应另有 `"preapproved": true` 和 `execution`，执行记录的 `preapproved` 为 `true`。

| `status` | 含义 |
|---|---|
| `awaiting_approval` | 等审批。 |
| `running` | 执行中。 |
| `succeeded`、`failed` | 执行成功、失败；`output` 是响应或错误的开头。 |
| `declined` | 审批被驳回、过期或撤销，没有执行。 |
| `verifying` | 执行成功，等到 `verifyAt` 验证。 |
| `verified`、`verification_failed` | 验证通过、没通过；`verification` 写明结果。 |

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | 字段不对、集群不在本组织、动作不适用于这个事件或已停用、参数不对，或事件已解决。 |
| `403` | 缺少权限，或无权访问这个事件。 |
| `404` | 动作、集群或事件不存在。 |
