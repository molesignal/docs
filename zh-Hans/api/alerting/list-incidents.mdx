```http
GET /api/v1/alerts/incidents
GET /api/v1/alerts/incidents/{id}
```

第一个调用按时间倒序列出事件，不含[并入](/zh-Hans/api/alerting/merge-incidents)别的事件的事件，它们列在主事件的[时间线](/zh-Hans/api/alerting/incident-timeline)里。第二个调用返回单个事件，并入的也可以读。两个调用都需要 `alerts.incidents.read`。

**列表的查询参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `scope` | string | `active`（默认）返回状态为 `open` 或 `acknowledged` 的事件。`all` 返回窗口内创建的事件，以及所有活动事件，不论开启多久。 |
| `window_secs` | integer | `scope=all` 的回看窗口。默认 `604800`（7 天）。取值限制在 3600 到 31536000 之间。 |

列表项是精简形式：`triggering_query` 为 `null`，`trace_ids`、`host_ids` 与 `affected_services` 最多各保留一个值。完整记录请读取单个事件。

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/alerts/incidents?scope=all&window_secs=86400" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

## 事件字段

| 字段 | 说明 |
|---|---|
| `id`、`org_id`、`rule_id` | 事件、组织与规则的标识符。 |
| `escalation_policy_id` | 事件开启时定下：来源指定的策略，或来源用默认策略时[告警路由](/zh-Hans/alerting/routing)选出的策略。别名 `default` 在开始升级时换成名为 `default` 的策略的 ID。 |
| `status` | `open`、`acknowledged` 或 `resolved`。数据模型还有 `closed`，目前没有任何调用会设置它。 |
| `severity` | `info`、`warning`、`error` 或 `critical`。 |
| `summary` | 规则名称，后接最多两个受影响的服务，更多时以 `+N` 表示。 |
| `fingerprint` | 规则 `id` 与 `labels` 的哈希。一条规则的每个指纹只有一个活动事件。 |
| `current_step`、`current_loop`、`current_step_started_at` | 升级进度。步骤编号从 0 开始，时间单位为微秒。 |
| `assignees` | 事件分配给的用户：当前升级步骤直接点名的目标（该步骤的 `user` 目标，以及每个 `schedule` 目标当前的值班人），加上确认事件的用户。第一个步骤运行之前为空。只指向团队的步骤会保留之前的负责人。 |
| `labels`、`annotations` | 事件开启时的快照：规则的 `labels`，加上查询结果中的 `service` 与 `host`。之后修改规则不会改变它们。 |
| `trace_ids`、`host_ids`、`affected_services` | 查询结果中 `trace_id`、`host` 与 `service` 列的值，已去重，各最多 10 个。 |
| `triggering_query` | 包含 `language`、`statement` 与 `sample_values`。每个样本含以微秒表示的 `ts`（结果没有时间列时为 `0`）、`value` 与 `labels`。只有读取单个事件的调用会返回它。 |
| `created_at` | 事件开启的时间，单位为微秒。 |
| `acknowledged_at`、`acknowledged_by` | 最近一次确认的时间与用户。 |
| `resolved_at`、`resolved_by` | 解决的时间与用户。评估器因规则不再命中而解决事件时，`resolved_by` 为 `null`。 |
| `team_id` | 事件开启时[告警路由](/zh-Hans/alerting/routing)分派到的团队，没有时为 `null`。 |
| `routing` | 分派的依据，路由出现以前开启的事件为 `null`。`reason` 为 `rule`（命中路由规则，带 `rule_id` 和当时的 `rule_name`）、`service_owner`（服务的负责团队，带 `service`）、`team_label`（team 标签）、`default`（默认策略）或 `source`（来源指定了升级策略，只分派团队）。 |
| `snoozed_until`、`snoozed_by` | 事件[暂缓](/zh-Hans/api/alerting/snooze-incident)期间：暂缓到何时（微秒）和谁暂缓的；没有暂缓时为 `null`。 |
| `severity_set_by` | 手动[设置严重度](/zh-Hans/api/alerting/set-incident-severity)的用户，此后规则不再改它；没有时为 `null`。 |
| `merged_into` | 这个事件[并入](/zh-Hans/api/alerting/merge-incidents)的事件，没有时为 `null`。 |
| `assignees_pinned` | 负责人是有人点名指定的时为 `true`；升级到下一级时才换掉。 |
| `dispatch_round`、`dispatch_reason` | 升级通知的轮次：有人立即升级、转派给团队或策略、调高严重度时加一，同一级可以再通知一次；以及当前这一级最近一次通知的原因：`step`、`manual`、`reassigned`、`responder_added`、`snooze_ended`、`ack_timeout` 或 `severity_raised`。 |
| `revision` | 事件每改动一次加一。 |

**错误**

| 状态码 | 原因 |
|---|---|
| `403` | Token 缺少 `alerts.incidents.read`。 |
| `404` | 事件不存在。 |
