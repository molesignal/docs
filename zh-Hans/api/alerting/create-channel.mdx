通知连接器为组织保存一个通知服务商的凭证与传输设置。列出和读取连接器需要 `notify.connectors.read`。创建、更新、测试和删除连接器需要 `notify.connectors.manage`。

| 操作 | 端点 |
|---|---|
| 列出连接器类型 | `GET /api/v1/notify/connector-types` |
| 列出连接器 | `GET /api/v1/notify/connectors` |
| 创建连接器 | `POST /api/v1/notify/connectors` |
| 读取连接器 | `GET /api/v1/notify/connectors/{id}` |
| 更新连接器 | `PUT /api/v1/notify/connectors/{id}` |
| 测试连接器 | `POST /api/v1/notify/connectors/{id}/test` |
| 删除连接器 | `DELETE /api/v1/notify/connectors/{id}` |

## 连接器类型

类型列表返回运行中后端注册的每种类型的 `connectorType`、`capabilities` 与 `addresses`。类型包括 `email_smtp`、`lark_app`、`lark_webhook`、`slackApp`、`slack_webhook` 和 `webhook`。

```json
[
  {
    "connectorType": "slack_app",
    "capabilities": {
      "directUser": true,
      "group": true,
      "richText": true,
      "interactive": true,
      "acknowledgement": false,
      "attachments": false
    },
    "addresses": [
      {
        "field": "apiBaseUrl",
        "picker": "site",
        "choices": [
          { "key": "slack", "url": "https://slack.com/api" },
          { "key": "govslack", "url": "https://slack-gov.com/api" }
        ]
      }
    ]
  }
]
```

`addresses` 是这种连接器配置里服务商地址的目录；地址由人填的类型（例如 Webhook 与 SMTP）没有目录，是空列表。

| 字段 | 说明 |
|---|---|
| `field` | 配置里的键，例如 `apiBaseUrl`、`serviceUrl`、`wsUrl`。 |
| `choices` | 能取的地址，各有 `key` 与 `url`，第一个是默认的。 |
| `picker` | 有几个地址时按什么选：`site`（平台）或 `cloud`（云环境）。它本身不保存。 |
| `byRegion` | 地址随所选的区域定（阿里云、AWS），是 `https://{service}.{区域}.{domains 之一}`；`choices` 只是还没选区域时的地址。 |

创建、更新、测试连接器和直接发送时，这些键只收目录里的地址，随区域定的只收配置里那个区域的地址；没填用默认的。别的地址会被拒绝，凭证不会发到别处。

连接器的 `config` 对象取决于其类型。所有 `timeoutSecs` 默认为 10，取值范围为 1 到 60。URL 必须是绝对的 `http` 或 `https` 地址，服务商的地址只能取连接器类型 `addresses` 里的。

| `connectorType` | `config` 键 |
|---|---|
| `email_smtp` | `host` 与 `from`（必填）、`port`（默认 `587`）、`username`、`password`、`tls`（`none`、默认的 `starttls` 或 `tls`）、`timeoutSecs` |
| `slackApp` | `botToken`、`clientId` 与 `clientSecret`（至少填 Bot Token，或 Client ID 与 Client Secret，也可以三项都填）、`apiBaseUrl`（默认 `https://slack.com/api`，GovSlack 是 `https://slack-gov.com/api`）、`timeoutSecs` |
| `slack_webhook` | `webhookUrl`（必填）、`timeoutSecs` |
| `lark_app` | `appId` 与 `appSecret`（必填）、`apiBaseUrl`（默认飞书的 `https://open.feishu.cn/open-apis`，Lark 是 `https://open.larksuite.com/open-apis`）、`receiveIdType`（默认 `open_id`，另有 `userId`、`union_id`、`email`、`chatId`）、`timeoutSecs` |
| `lark_webhook` | `webhookUrl`（必填）、`secret`、`timeoutSecs` |
| `webhook` | `url`（必填）、`method`（默认 `post`，另有 `put`、`patch`）、`headers`、`timeoutSecs` |

各服务商及其目标的说明参见[通知渠道](/zh-Hans/notification-channels)。

## 创建连接器

```http
POST /api/v1/notify/connectors
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 在组织内唯一。 |
| `connectorType` | string | 是 | 上文的类型之一。创建后无法修改类型。`type` 可作为别名。 |
| `config` | object | 是 | 该类型的设置。 |
| `enabled` | boolean | 否 | 默认 `true`。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/notify/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "Operations webhook",
    "connectorType": "webhook",
    "config": {
      "url": "https://hooks.example.com/molesignal",
      "method": "post",
      "headers": { "Authorization": "Bearer <token>" },
      "timeoutSecs": 5
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "id": "3KEDlokKjNmves95sRzL8tXpflY",
  "organizationId": "<organization-id>",
  "name": "Operations webhook",
  "connectorType": "webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 5
  },
  "capabilities": {
    "directUser": true,
    "group": true,
    "richText": true,
    "interactive": false,
    "acknowledgement": false,
    "attachments": false
  },
  "enabled": true,
  "status": "unknown",
  "lastTestedAt": null,
  "lastTestStatus": null,
  "lastTestError": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

MoleSignal 对整个 `config` 做静态加密。响应会把每个保存凭证的键的值替换为 `***`，这些键包括 `url`、`webhookUrl`、`headers`，以及所有以 `password`、`secret` 或 `token` 结尾的键。`host`、`from`、`timeoutSecs` 等其他键保持可读。

`status` 在首次测试之前为 `unknown`，之后为 `connected` 或 `error`。`lastTestStatus` 为 `success` 或 `failed`。状态为 `error` 的连接器会被路由跳过，直到之后的测试成功。

## 列出与读取连接器

```http
GET /api/v1/notify/connectors
GET /api/v1/notify/connectors/{id}
```

列表返回上述格式的连接器数组。`id` 不存在时返回 `404`。

## 更新连接器

```http
PUT /api/v1/notify/connectors/{id}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 新名称。 |
| `config` | object | 否 | 新设置。省略则保留已保存的配置。 |
| `enabled` | boolean | 否 | 默认 `true`。省略该值会启用连接器。 |

对已掩码的键发送 `***` 可保留已保存的密钥，发送新的明文值则替换它：

```json
{
  "name": "Operations webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 8
  },
  "enabled": true
}
```

## 测试连接器

```http
POST /api/v1/notify/connectors/{id}/test
```

通过连接器发送一条消息。已停用的连接器无法运行测试。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `targetType` | string | 是 | `directUser`、`fixed_address`、`fixed_group` 或 `webhook`。每种连接器类型只接受其中一部分，例如 `email_smtp` 接受 `directUser` 与 `fixed_address`。 |
| `target` | string | 是 | 接收目标：地址、服务商标识符、群组或 URL，取决于 `targetType`。 |
| `message` | object | 否 | `title`、`text`、`markdown` 与 `html`。默认使用通用的标题和正文。 |

<ResponseExample>
```json 200
{
  "sent": true,
  "testedAt": 1790000000000000,
  "elapsedMs": 3,
  "providerMessageId": "req-1",
  "error": null
}
```
</ResponseExample>

投递失败时仍返回 `200`，`sent` 为 `false`，原因在 `error` 中，例如 `unavailable: webhook request failed`。测试还会更新连接器的 `status`、`lastTestedAt`、`lastTestStatus` 与 `lastTestError`。

## 删除连接器

```http
DELETE /api/v1/notify/connectors/{id}
```

删除成功时返回 `204`，没有响应体。用户端点、通知策略、兜底路由、定时日志巡检、状态页或 IM 里的 Mole Agent 仍引用该连接器时，调用返回 `409`，消息为 `notify connector is referenced by user endpoints, policies, default routes, scheduled log inspections, status pages, or Mole Agent in IM`。请先迁移这些引用。

## 错误

| 状态码 | 原因 |
|---|---|
| `400` | `config` 对该类型无效、类型不受支持（`unsupported connector type: pagerduty`）、目标与连接器不匹配，或连接器已停用。 |
| `404` | 连接器不存在。 |
| `409` | 组织内已有同名连接器，或删除时连接器仍被引用。 |
| `422` | 字段缺失或取值无效，例如未知的 `targetType`。响应为纯文本。 |
