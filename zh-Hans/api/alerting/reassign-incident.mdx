---
title: "转派事件"
description: "把事件转给成员、团队或升级策略。"
"enLink": "/en-US/api/alerting/reassign-incident"
---

```http
POST /api/v1/alerts/incidents/{id}/reassign
```

把进行中的事件交给别人。请求体用 `kind` 指明交给谁：

- `users`：`userIds` 里的人（组织成员，1 到 10 个）成为负责人，并收到一条升级通知，`escalation.reason` 是 `reassigned`。事件回到 `open`，当前这一级重新开始计算确认超时；仍没人确认时照常升级到下一级。
- `team`：交给 `teamId` 这个团队，改用团队的值班策略，团队没设时用名为 `default` 的策略，从第一个适用的级别重新开始。
- `policy`：改用 `escalationPolicyId` 这条策略，从第一个适用的级别重新开始，团队不变。

三种情况下事件都回到 `open`，暂缓随之结束，这一步记在[时间线](/zh-Hans/api/alerting/incident-timeline)上。该调用需要 `alerts.incidents.update`。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `kind` | string | 是 | `users`、`team` 或 `policy`。 |
| `userIds` | array | `users` 时必填 | 1 到 10 个组织成员的用户 ID。 |
| `teamId` | string | `team` 时必填 | 团队。 |
| `escalationPolicyId` | string | `policy` 时必填 | 升级策略。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/reassign \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"kind": "users", "userIds": ["<user-id>"]}'
```
</RequestExample>

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | `userIds` 为空、超过 10 个或含有组织外的用户；或团队没有值班策略、也没有 `default` 策略；或策略里没有适用于事件严重度的级别。 |
| `403` | Token 缺少 `alerts.incidents.update`，或无权访问这个事件。 |
| `404` | 事件不存在。 |
| `409` | 事件已恢复或已并入别的事件，或者更新时事件一直在变；重试即可。 |
