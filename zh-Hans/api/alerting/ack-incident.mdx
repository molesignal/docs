title: "确认事件"
description: "确认事件并停止其升级。"
"en_link": "/en-US/api/alerting/ack-incident"
---

```http
POST /api/v1/alerts/incidents/{id}/ack
```

确认一个处于 `open` 状态的事件。调用会把状态设为 `acknowledged`，在 `acknowledged_by` 与 `acknowledged_at` 中记录调用用户与时间，把该用户加入 `assignees`，并停止升级，因为只有 `open` 事件会按[升级策略](/zh-Hans/api/alerting/create-escalation)推进。调用还会把触发通知标记为已确认，并发送 `alert.acknowledged` 事件。该调用需要 `alerts.acknowledge`，请求体为空。

已确认的事件保持已确认，直到用户将其解决。即使规则不再命中，评估器也不会解决它。

<Note>
  确认一个已经是 `acknowledged` 的事件会原样返回它。`acknowledged_by` 与 `acknowledged_at` 保留第一次的用户与时间，也不会再次发送事件。确认一个 `resolved` 或 `closed` 的事件会返回 `409`，事件保持原状态。
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/ack \
  -H "authorization: Bearer $MS_JWT"
```
</RequestExample>

响应是更新后的事件，各字段说明见[列出事件](/zh-Hans/api/alerting/list-incidents)。

**错误**

| 状态码 | 原因 |
|---|---|
| `403` | Token 缺少 `alerts.acknowledge`。 |
| `404` | 事件不存在。 |
