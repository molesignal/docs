```http
GET /api/v1/alerts/insights
```

汇总窗口内创建的事件，以及人的响应：多久有人接手、多久恢复、升级了多少，和前一段同样长的时间相比。并入别处的事件不算。该调用需要 `alerts.incidents.read`。每个人的值班负担见[值班负担](/zh-Hans/api/alerting/oncall-load)。

**查询参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `window_secs` | integer | 回看窗口，单位为秒。默认 `604800`（7 天）。取值限制在 3600 到 31536000 之间。 |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/alerts/insights?window_secs=86400" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**响应**

| 字段 | 说明 |
|---|---|
| `window_secs` | 限制范围之后的窗口。 |
| `total` | 窗口内创建的事件数量。 |
| `active` | 状态为 `open` 或 `acknowledged` 的事件。 |
| `closed` | 状态为 `resolved` 或 `closed` 的事件。 |
| `mttr_secs` | 已解决事件从创建到解决的平均秒数。没有已解决事件时为 `0`。 |
| `noise_rate` | 在 60 秒内被解决的已解决事件所占的比例，范围为 0 到 1。没有已解决事件时为 `0`。 |
| `by_hour` | 按创建时刻的 UTC 小时统计的 24 个事件数量。 |
| `by_severity` | 各严重程度的数量。没有事件的严重程度不会出现。 |
| `top_services`、`top_rules` | 最多 8 个 `key` 与 `count` 条目，数量高者在前。键是服务名称或规则标识符。 |
| `response.current`、`response.previous` | 窗口内和它之前同样长的一段时间里人的响应，字段见下表。 |
| `response.breakdown` | 窗口内按团队（`teams`，键是团队 ID）、服务（`services`）和个人（`people`，键是第一个接手的人）拆开，每个维度最多 20 行，事件多的在前。一个事件涉及几个服务时，每个服务各算一次。每行有 `incidents`、平均接手秒数 `mtta_secs`、平均恢复秒数 `mttr_secs` 和升级率 `escalation_rate`。 |

**`response.current` 与 `response.previous`**

| 字段 | 说明 |
|---|---|
| `incidents` | 这段时间创建的事件数。 |
| `responded` | 有人接手过的事件数。第一次接手是第一次确认；没人确认就被人解决的，算在解决的那一刻。规则自行恢复的不算。 |
| `mtta` | 从触发到第一次接手的秒数：均值 `mean_secs`、中位数 `p50_secs` 和 `p90_secs`。没有人接手过时都是 `0`。 |
| `mttr` | 已恢复事件从触发到恢复的秒数，同样给出均值、P50 和 P90。 |
| `escalation_rate` | 升级过的事件所占比例，范围 0 到 1。到过第 2 级或被[立即升级](/zh-Hans/api/alerting/escalate-incident)的算升级过。 |
| `steps` | 各级的确认情况，`step` 从 0 起：到过这一级的事件数 `reached`，和在这一级被确认的 `acknowledged`。只算时间线上有升级记录的事件；这段时间没有时为空。 |
| `ack_via` | 第一次接手在哪里做的：`web`、`api`、`im`、`sms`、`phone` 或 `agent`，各多少个。 |
