---
title: "设置事件优先级与紧急度"
description: "手动修改事件的优先级或紧急度。"
"en_link": "/en-US/api/alerting/incident-priority-urgency"
---

```http
PUT /api/v1/alerts/incidents/{id}/priority
PUT /api/v1/alerts/incidents/{id}/urgency
```

两个调用都需要 `alerts.incidents.update`，只能改进行中、没有并入别处的事件，时间线分别记 `priority_changed` 和 `urgency_changed`。

- **优先级**：请求体 `{"priority": "P2"}`，`null` 表示不设，取值是组织的[优先级档位](/zh-Hans/alerting/on-call#紧急度与优先级档位)之一。只改优先级，不重新通知。
- **紧急度**：请求体写组织某一档紧急度的键，例如 `{"urgency": "high"}`，并把调用者记在 `urgency_set_by`，此后支持时段不再改它。调到更急的一档时，`open` 的事件从适用的第一级重新通知，`escalation.reason` 是 `urgency_raised`；调到不那么急的一档只改紧急度，不逐级升级的那几档之后不再往下升。

批量修改用[批量处理](/zh-Hans/api/alerting/bulk-incidents)的 `{"action": "set_priority", "priority": "P2"}` 与 `{"action": "set_urgency", "urgency": "low"}`。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/urgency \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"urgency": "high"}'
```
</RequestExample>

响应是更新后的事件。事件上的 `urgency` 是某一档的键（这个字段出现以前开的事件没有它，按高算），`priority` 是 `P1` 到 `P9` 或没有；`urgency_by_policy` 为 `true` 表示紧急度是按升级策略定的。

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | 优先级超出组织的档数，或紧急度不是组织的某一档。 |
| `422` | 优先级不是 `P1` 到 `P9`，或紧急度不是由小写字母、数字和下划线组成的键。 |
| `403` | Token 缺少 `alerts.incidents.update`，或无权访问这个事件。 |
| `404` | 事件不存在。 |
| `409` | 事件已恢复或已并入别的事件。 |
