---
title: "签发 API Token"
description: "为用户或服务账号创建 API Token。"
---

```http
POST /api/v1/auth/tokens
```

创建形如 `ms_<prefix>_<secret>` 的长期 Token。响应是明文 Token 唯一出现的一次，请立即保存。该调用需要在组织范围内具备 `api_tokens.manage` 权限。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 显示名称，不能为空。 |
| `role_id` | string | 否 | Token 的组织角色。默认为内置的 **Intake token** 角色，只有 `streams.write` 权限。该角色不能包含调用者没有的权限，`rum_client` 角色会被拒绝。设置了 `service_account_id` 时请省略该字段。 |
| `service_account_id` | string | 否 | 为服务账号签发 Token，Token 继承该账号的角色。已禁用的账号会被拒绝。 |
| `expires_in_days` | integer | 否 | 有效天数，限制在 1 到 1825 之间。省略则 Token 永不过期。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/auth/tokens \
  -H "authorization: Bearer $MS_JWT" \
  -H 'content-type: application/json' \
  -d '{
    "name": "grafana-readonly",
    "role_id": "<viewer-role-id>",
    "expires_in_days": 90
  }'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KE5hOsEc3lMC9qr9RWnPn0pqWF",
  "prefix": "l2XcQd8UoQzK3pLm",
  "token": "ms_l2XcQd8UoQzK3pLm_<secret>",
  "role_id": "<viewer-role-id>",
  "role_key": "viewer",
  "role_name": "Viewer",
  "token_kind": "personal",
  "application_id": null,
  "service_account_id": null,
  "expires_at_micros": 1798000000000000,
  "created_at_micros": 1790000000000000
}
```
</ResponseExample>

用 `GET /api/v1/roles` 列出角色 id。内置的组织角色有 `owner`、`admin`、`editor`、`viewer` 与 `intake`。

像使用登录 Token 一样发送它：`Authorization: Bearer ms_…`。使用默认角色的 Token 可以发送数据，但不能查询数据。

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | `name` 为空、使用了 `rum_client` 角色，或同时设置了 `role_id` 与 `service_account_id`。 |
| `403` | 角色包含调用者没有的权限，或调用者缺少 `api_tokens.manage`。 |
| `404` | 系统范围没有 API Token，或角色、服务账号不存在。 |
