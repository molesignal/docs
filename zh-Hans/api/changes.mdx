```http
GET    /api/v1/changes
POST   /api/v1/changes
GET    /api/v1/changes/{id}
PUT    /api/v1/changes/{id}
PATCH  /api/v1/changes/{id}
DELETE /api/v1/changes/{id}
```

所有变更保存在同一处：流水线通过 [`POST /api/v1/apm/deployments`](/zh-Hans/apm/deployments#从-ci-上报发布) 上报的发布、配置变更、功能开关、扩缩容和基础设施变更，以及有人加在某段时间上的注解。`GET /api/v1/changes` 会连同 APM 从 Span 中首次看到的版本和告警规则的修改一起列出。其余接口用于维护注解。

## 列出变更

| 参数 | 说明 |
|---|---|
| `from`、`to` | 时间范围，单位微秒。`to` 默认为当前时间，`from` 默认为 `to` 之前一天。 |
| `services` | 服务名，用逗号分隔。其他服务的变更不列出；不属于任何服务的变更（如注解和规则修改）照常列出。 |
| `namespace`、`environment` | 这个 Namespace 或环境的上报变更和版本，以及没有指明 Namespace 或环境的上报变更。 |
| `kinds` | 用逗号分隔：`deployment`、`configuration`、`feature_flag`、`scaling`、`infrastructure`、`annotation`、`version`、`rule`。不填时列出调用方能读取的所有类型。 |
| `dashboardId`、`stream` | 这个仪表盘或日志流的注解，以及不属于任何仪表盘或日志流的注解。属于其他仪表盘或日志流的注解不列出。 |
| `limit` | 最多 500，也是默认值。 |

每种类型各自要求权限，调用方没有的类型直接不列出，不会拒绝整个请求：

| 类型 | 权限（任一即可） |
|---|---|
| `deployment`、`configuration`、`feature_flag`、`scaling`、`infrastructure` | `apm.deployments.read`、`sys.telemetry.read` |
| `annotation` | `dashboards.annotations.read` |
| `version` | `apm.services.read`、`sys.telemetry.read` |
| `rule` | `alerts.rules.read` |

返回一个列表，按时间从新到旧。流水线上报过的版本只列一次，按上报的记录列出。

```json
[
  {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "kind": "deployment",
    "at": 1792316400000000,
    "service": "checkout",
    "namespace": "shop",
    "environment": "prod",
    "version": "2.0.0",
    "status": "succeeded",
    "commit": "9f2c1e7a4b3d5e6f",
    "author": "ada",
    "ciUrl": "https://ci.example.com/runs/7"
  },
  {
    "id": "3KEDP0aZ1y2b3c4d5e6f7g8h9i0",
    "kind": "annotation",
    "at": 1792312800000000,
    "end": 1792314600000000,
    "title": "Load test",
    "tags": ["test"],
    "dashboardId": "dash-1"
  }
]
```

| 字段 | 说明 |
|---|---|
| `at`、`end` | 发生时间；`end` 是时间段注解的结束时间。单位微秒。 |
| `service`、`namespace`、`environment`、`version` | 上报变更或版本所属的服务。 |
| `status` | 上报变更的结果：`succeeded`、`failed` 或 `rolled_back`。 |
| `title`、`description`、`tags` | 注解或规则的标题，以及变更自带的说明。 |
| `commit`、`repositoryUrl`、`pullRequestUrl`、`author`、`ciUrl` | 上报变更的来源。 |
| `dashboardId`、`stream` | 注解所属的仪表盘或日志流。 |
| `ruleId` | 被修改的规则。 |

## 维护注解

`POST /api/v1/changes` 创建一条注解，需要 `dashboards.annotations.manage`：

```json
{
  "title": "Load test",
  "description": "k6, 2,000 users",
  "tags": ["test"],
  "timeStart": 1792312800000000,
  "timeEnd": 1792314600000000,
  "dashboardId": "dash-1",
  "streamName": null
}
```

`GET /api/v1/changes/{id}` 读取一条注解，需要 `dashboards.annotations.read`。`PUT` 和 `PATCH` 修改请求中给出的字段，`DELETE` 删除注解，都需要 `dashboards.annotations.manage`。这些接口只作用于注解；不是本组织注解的 id 返回 `404`。Mole Agent 用 `create_annotation`、`update_annotation` 和 `delete_annotation` 维护注解，用 `list_changes` 列出变更。
