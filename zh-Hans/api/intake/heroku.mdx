```http
POST /api/v1/_heroku
```

接受文本形式的日志投递请求体。该端点不使用 Bearer Token。请创建 `heroku_drain` 类型的连接器，设置至少 16 个字符的 `pushToken` 与 `target_stream`。Heroku 无法设置自定义请求头，因此 Token 以 `?token=` 的形式放在 URL 中，请求头 `X-Connector-Token` 同样可用。Token 错误时返回 `401`。

每一行成为 `target_stream`（默认 `heroku`）中的一条日志事件。整行保存在字段 `message` 中，字段 `source` 为 `heroku`。成功时返回 `204`。

<RequestExample>
```bash Heroku CLI
heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
```
</RequestExample>

连接器的配置参见[连接器](/zh-Hans/connectors)。

## 验证投递与目标数据流

1. 确认连接器已启用，推送 Token 与发送方配置一致。普通 API Token 不能替代推送 Token。
2. 通过连接器 API 设置原始 `configJson` 时，使用 `target_stream` 指定目标数据流；不要用 `targetStream` 代替此字段。`pushToken` 仍使用驼峰命名。
3. 发送一条带唯一标记的测试事件，记录接收时间。随后在 **Logs** 中选择预期数据流与覆盖接收时间的窗口，查询该标记。
4. 若请求成功但目标流没有数据，检查对应的默认流及实际保存的目标字段。HTTP 确认不能代替目标数据流中的查询验证。

Token 应视作凭据保护。使用 URL 查询参数传递时，避免将完整 URL 复制到日志、工单或截图中。请求失败时先区分 Token、连接器启用状态、请求格式与压缩设置，再决定是否重试。
