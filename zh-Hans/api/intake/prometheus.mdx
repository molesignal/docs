```http
POST /api/v1/prometheus/api/v1/write
```

接受 Prometheus 与 VictoriaMetrics 的 `remote_write` 第 1 版请求，即 snappy 压缩的 protobuf。该调用需要 `metrics.write`，成功时返回 `204`。

一个请求写入 `stream-name` 请求头指定的指标数据流，没有这个请求头时写入 `default`。一个指标数据流装一个来源的全部指标。`__name__` 标签成为 `metric_name` 字段，其余标签成为字段，样本成为 `value` 字段。与指标字段同名的标签（例如 `metric_name`、`metric_kind`）存为 `exported_<名称>`。原生直方图与指标元数据会被跳过，exemplar 与样本一起保存。

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

用 PromQL 按指标名查询，不论哪个数据流装着它。带有 `service` 与 `status` 标签的 `http_requests_total` 序列会得到：

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scanned_rows": 1,
  "took_ms": 154
}
```

**限制** 按序列与按组织生效：每个序列最多 64 个标签，标签名最长 128 字节，标签值最长 2048 字节，并对活跃序列与新序列设有基数限制。进程级的限制见[配置](/zh-Hans/configuration#接入缓冲)中的 `[intake.prometheus]`。一个组织、以及组织里一个指标的活跃序列数由平台设置 **设置 → 指标基数** 限制：用 `GET /api/v1/settings/series_limits` 读取，用 `PUT` 加同样的请求体 `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }` 修改，两者都需要系统范围的 `sys.settings.limits.manage`。指标的上限不超过组织的上限，两者都不超过 100,000,000。
