```http
POST /api/v1/loki/api/v1/push
```

接受 Loki JSON push 格式。该调用需要 `logs.write`，成功时返回 `204`，并接受带有 `Content-Encoding: gzip` 的请求体。

该端点只解码 JSON。使用 snappy 压缩 protobuf 的发送端（例如 Promtail 与 Grafana Alloy）无法向它推送，请改用 OpenTelemetry Collector、Vector 或 Fluent Bit。

<RequestExample>
```bash cURL
LOKI_TIMESTAMP="$(date +%s)000000000"
curl -X POST http://localhost:5080/api/v1/loki/api/v1/push \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -H 'stream-name: app' \
  -d '{"streams":[{"stream":{"service":"api"},"values":[["'"$LOKI_TIMESTAMP"'","started"]]}]}'
```
</RequestExample>

每个 value 成为一条日志事件。标签成为字段，日志行成为字段 `message`，纳秒时间戳会转换为微秒。`stream-name` 请求头选择目标数据流，默认为 `default`。

## 验证示例

示例在 macOS 或 Linux shell 中生成当前时间的纳秒时间戳。收到 `204` 后，在 **Logs** 中选择 `app` 和最近一小时，查询 `service = 'api'` 对应的 `message`。如果使用自己的历史时间戳，查询窗口必须覆盖事件时间，并确认数据仍在保留范围内。

注意区分三个字段：请求中的 `streams` 是 Loki 批次结构；标签中的 `service` 是事件字段；真正决定 MoleSignal 目标数据流的是 `stream-name` 请求头。成功后仍需用查询核对数据流和时间，避免重复发送同一批次。
