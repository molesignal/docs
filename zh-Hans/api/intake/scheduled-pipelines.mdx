| 操作 | 端点 | 权限 |
|---|---|---|
| 列出 | `GET /api/v1/scheduled_pipelines` | `pipelines.read` |
| 创建 | `POST /api/v1/scheduled_pipelines` | `pipelines.create`，读取 `_audit` 时还需要 `audit.read` |
| 查看 | `GET /api/v1/scheduled_pipelines/{id}` | `pipelines.read` |
| 更新 | `PUT /api/v1/scheduled_pipelines/{id}` | 修改配置需要 `pipelines.edit`，读取 `_audit` 时还需要 `audit.read`；修改 `enabled` 需要 `pipelines.pause` |
| 删除 | `DELETE /api/v1/scheduled_pipelines/{id}` | `pipelines.delete` |
| 运行历史 | `GET /api/v1/scheduled_pipelines/{id}/runs` | `pipelines.read` |
| 今日配额与限流 | `GET /api/v1/scheduled_pipelines/{id}/limits` | `pipelines.read` |
| 回填 | `POST /api/v1/scheduled_pipelines/{id}/backfill` | `pipelines.run`，读取 `_audit` 时还需要 `audit.read` |

## 列出

列表返回每条流水线，以及最近一次运行的状态和 24 小时汇总：

<ResponseExample>
```json 200
[
  {
    "id": "3KBHcb6imgQq7FXBsROGTIRHOyg",
    "name": "normalize-app",
    "sourceStream": "app_raw",
    "targetStream": "app",
    "functionSteps": { "mode": "scheduled", "signalType": "logs", "sources": ["app_raw", "nginx_raw"], "steps": [ ... ] },
    "cron": "every:5m",
    "lookbackSecs": 300,
    "enabled": true,
    "lastRunAt": 1790000000000000,
    "readUntil": { "appRaw": 1789999940000000, "nginxRaw": 1789999940000000 },
    "retry": null,
    "alertRecord": null,
    "auditReaderId": null,
    "auditReader": null,
    "createdAt": 1789900000000000,
    "updatedAt": 1789900000000000,
    "lastRunState": "succeeded",
    "lastRunStartedAt": 1790000000000000,
    "lastRunFinishedAt": 1790000000250000,
    "lastRunScannedRows": 1200,
    "lastRunError": null,
    "runs24h": 288,
    "succeededRuns24h": 288,
    "failedRuns24h": 0
  }
]
```
</ResponseExample>

每一项包含[查看](#查看)返回的字段、最近一次运行的 `lastRunState`、`lastRunStartedAt`、`lastRunFinishedAt`、`lastRunScannedRows`（它读入的事件数）与 `lastRunError`，以及过去 24 小时的运行次数。

## 查看

```http
GET /api/v1/scheduled_pipelines/{id}
```

返回流水线，以及每个来源的读取位点和已计划的重试：

<ResponseExample>
```json 200
{
  "id": "3KBHcb6imgQq7FXBsROGTIRHOyg",
  "name": "normalize-app",
  "sourceStream": "app_raw",
  "targetStream": "app",
  "functionSteps": { "mode": "scheduled", "signalType": "logs", "sources": ["app_raw", "nginx_raw"], "steps": [ ... ] },
  "cron": "every:5m",
  "lookbackSecs": 300,
  "enabled": true,
  "lastRunAt": 1790000000000000,
  "readUntil": { "appRaw": 1789999940000000, "nginxRaw": 1789999640000000 },
  "retry": {
    "source": "nginx_raw",
    "attempt": 2,
    "nextAt": 1790000030000000,
    "error": "read: <reason>"
  },
  "alertRecord": null,
  "auditReaderId": null,
  "auditReader": null,
  "createdAt": 1789900000000000,
  "updatedAt": 1789900000000000
}
```
</ResponseExample>

| 字段 | 说明 |
|---|---|
| `readUntil` | 每个来源的读取位点，单位微秒。该来源在这个时间之前的事件都已处理。还没有读取过的来源不出现在这里。 |
| `retry` | 最早一次已计划的失败窗口重试，没有时为 `null`。`source` 是来源，`attempt` 是这次重试将是第几次尝试，`nextAt` 是重试的时间，`error` 是上一次尝试失败的原因。 |
| `alertRecord` | 告警流水线最近一个处理过事件的 UTC 日的计数：`day`（`YYYY-MM-DD`）、`processed`、`dropped`、`failed`，以及当天最近一次丢弃和出错 `last_dropped`、`last_failed`，各带 `atTime`、`rule`（告警规则、告警来源或拨测检查）和 `reason`。缺少的计数为 0。其他流水线和还没有处理过事件的告警流水线为 `null`，参见[当天的计数](/zh-Hans/pipelines/alert-events#当天的计数)。 |
| `auditReaderId` | 流水线读取 `_audit` 时用谁的权限，即最后保存它的人；不读取 `_audit` 的流水线为 `null`，参见[审计数据流](/zh-Hans/settings/data-security#审计数据流)。 |
| `auditReader` | 这个人的 `id`、`displayName` 和 `email`，有 `pipelines.read` 就能看到。用户已不存在或读取失败时为 `null`，这时只有 `auditReaderId`。 |

参见[定时与读取位点](/zh-Hans/pipelines#定时与读取位点)和[重试与死信](/zh-Hans/pipelines#重试与死信)。

## 更新与删除

`PUT` 的请求体与[创建流水线](/zh-Hans/api/intake/create-pipeline)相同，并替换整个配置。只修改 `enabled` 需要 `pipelines.pause`，其他 `PUT`（包括什么都没改的）需要 `pipelines.edit`。把 `enabled` 从 `false` 改为 `true` 会重置读取位点，每个来源重新往回读 `lookbackSecs`。`DELETE` 返回 `{"deleted": true}`。

对读取 `_audit` 的流水线，`PUT` 还决定流水线用谁的权限读取，参见[审计数据流](/zh-Hans/settings/data-security#审计数据流)。

| `PUT` | 还需要 | 流水线用谁的权限读取 `_audit` |
|---|---|---|
| 改了配置 | `audit.read`，且 Token 不能属于服务账号 | 此后用调用者的权限。 |
| 什么都没改 | 无 | 调用者持有 `audit.read` 且 Token 不属于服务账号时，此后用调用者的权限；否则不变，也不报错。 |
| 只改 `enabled` | 无 | 不变。 |

## 运行历史

```http
GET /api/v1/scheduled_pipelines/{id}/runs?limit=50&beforeTime=<cursor>
```

按时间倒序返回定时流水线的运行记录。实时流水线和告警流水线不产生运行记录。

<ResponseExample>
```json 200
[
  {
    "id": "3KE7Yq0d3jvXm5cJ8r2bWQzN1aP",
    "pipelineId": "3KBHcb6imgQq7FXBsROGTIRHOyg",
    "state": "succeeded",
    "startedAt": 1790000000000000,
    "finishedAt": 1790000000250000,
    "scannedRows": 1200,
    "writtenRows": 1150,
    "droppedRows": 48,
    "failedRows": 2,
    "attempt": 1,
    "error": null,
    "warning": "stream `app` rejected 2 event(s): <reason>"
  }
]
```
</ResponseExample>

| 字段 | 说明 |
|---|---|
| `state` | `running`、`succeeded`、`failed` 或 `cancelled`。 |
| `startedAt`、`finishedAt` | 运行的开始与结束时间。运行进行中时 `finishedAt` 为 `null`。 |
| `scannedRows` | 这次运行从各来源读入的事件数。 |
| `writtenRows` | 每个目标都收下的事件数。 |
| `droppedRows` | 被步骤用 `abort` 丢弃或被去重去掉的事件数。 |
| `failedRows` | 步骤处理失败、被路由到来源，或某个目标没有收下的事件数。 |
| `attempt` | 第一次尝试为 `1`。运行重试了失败的窗口时更大。 |
| `error` | 运行失败的原因：失败的窗口及已计划的重试，或在没有死信数据流时某个目标数据流一条事件都没有收下。 |
| `warning` | 没有让运行失败的问题，例如处理失败的事件、被拒收或投递不成功的事件，或重试用完后被跳过的窗口。 |

`scannedRows` 等于 `writtenRows`、`droppedRows` 与 `failedRows` 之和。

## 今日配额与限流

```http
GET /api/v1/scheduled_pipelines/{id}/limits
```

返回实时流水线的[配额和限流步骤](/zh-Hans/pipelines#计数与限流)今天（UTC 0 点起）放行了多少、超出了多少，是所有节点的合计。各节点每 5 秒加一次。今天什么都没数的步骤没有行。

<ResponseExample>
```json 200
{
  "dayStart": 1790035200000000,
  "buckets": [
    {
      "step": "daily",
      "bucket": "[\"checkout\"]",
      "admittedEvents": 1000000,
      "admittedBytes": 524288000,
      "overEvents": 1240,
      "overBytes": 650117
    },
    {
      "step": "per-host",
      "bucket": "",
      "admittedEvents": 86400,
      "admittedBytes": 45298483,
      "overEvents": 12,
      "overBytes": 6291
    }
  ]
}
```
</ResponseExample>

| 字段 | 说明 |
|---|---|
| `step` | 步骤名。 |
| `bucket` | 不分桶的配额和限流为空。分桶的配额是各分桶字段的值组成的 JSON 列表，按字段顺序，事件没有的写 `null`；超出 1000 个桶上限的其余桶是 `*`。 |
| `admittedEvents`、`admittedBytes` | 在上限以内放行的量。 |
| `overEvents`、`overBytes` | 超出上限的量：按步骤的设置被丢弃、继续放行或转到别的数据流。 |

## 回填

```http
POST /api/v1/scheduled_pipelines/{id}/backfill
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `startTime` | integer | 窗口的开始时间，单位微秒。 |
| `endTime` | integer | 窗口的结束时间，必须大于 `startTime`，且窗口不能超过 31 天。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines/$PIPELINE_ID/backfill \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"startTime": 1790000000000000, "endTime": 1790086400000000}'
```
</RequestExample>

<ResponseExample>
```json 202
{
  "jobs": [
    {
      "source": "app_raw",
      "jobId": "3KE6epTrWXts1oa2ePEKIHKxG19",
      "monitor": "/api/v1/query/jobs/3KE6epTrWXts1oa2ePEKIHKxG19"
    },
    {
      "source": "nginx_raw",
      "jobId": "3KE6eqAbXq0n2yLr7VvTq9cUo4D",
      "monitor": "/api/v1/query/jobs/3KE6eqAbXq0n2yLr7VvTq9cUo4D"
    }
  ]
}
```
</ResponseExample>

回填为每个来源各提交一个搜索任务。每个任务在窗口内读取它的来源、应用各步骤，并像定时运行一样写入、投递和保存死信。流水线的读取位点不变。用每个任务的 `monitor` 路径跟踪它，参见[查询](/zh-Hans/query#时间范围与异步任务)。

实时流水线和告警流水线会返回 `400`（`realtime and alert pipelines do not support backfill`）。读取 `_audit` 的流水线在 Token 缺少 `audit.read` 或属于服务账号时返回 `403`。任务真正执行时会再核对一次提交人，提交人已不再持有 `audit.read` 时任务失败。
