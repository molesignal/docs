```http
POST /api/v1/_bulk
```

兼容 Elasticsearch `_bulk` 的 NDJSON 接入，适用于 Filebeat、Logstash 与 Vector 的 `elasticsearch` sink。该调用需要 `logs.write`，接受带有 `Content-Encoding: gzip` 的请求体。

| 动作 | 处理方式 |
|---|---|
| `index`、`create`、`update` | 源文档作为日志事件保存。 |
| `delete` | 跳过，不生成响应条目。该端点不会删除任何遥测数据。 |

动作中的 `_index` 选择目标日志数据流。没有它时使用 `stream-name` 请求头，再缺省为 `default`。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## 选择此接口

已有发送端能够输出 Elasticsearch bulk NDJSON 时，使用此接口。该接口是接入适配器，不是 Elasticsearch 集群，不提供搜索、索引模板、文档 ID 或原地更新语义。读取已存储事件时使用 [SQL 查询](/zh-Hans/query)。

## 构造有效批次

- 每个 `index` 或 `create` 操作分别占用一行动作对象和一行文档对象，批次末尾保留换行。
- `update` 的事件字段放在 `doc` 内；这些字段会作为新事件写入，不会修改已存储事件。
- 动作中的 `_index` 决定数据流；未指定时使用 `stream-name` 请求头，再回退到 `default`。
- 保留事件时间时，提供整数形式、单位为微秒的 Unix `_timestamp`；否则使用接收时的当前时间。
- `delete` 动作会被跳过，不会删除遥测，也不产生已写入事件的响应条目。

## 验证接入结果

单事件批次应返回 `errors: false`，并包含一个 `status: 201` 的条目。将条目数与计划写入的事件数核对；HTTP 成功本身不能证明批次格式符合预期。

打开 **Logs**，选择 `_index` 指定的数据流，并选取覆盖事件时间的范围。按样例中的特征字段查询。未找到事件时，先检查数据流和时间戳单位，再决定是否重发整批。此接口不会根据 Elasticsearch 文档 ID 对重试进行去重。

## 排查请求拒绝

| 现象 | 检查项 |
|---|---|
| 认证或权限错误 | 使用目标组织中具备 `logs.write` 的 API Token。 |
| 动作或文档不是 JSON 对象 | 检查 NDJSON 的行边界，不要发送 JSON 数组或跨行格式化对象。 |
| 未知动作 | 使用上表列出的动作名称。 |
| 解压错误 | 仅在请求体实际压缩时设置 `Content-Encoding: gzip`。 |
| 成功但事件数少于预期 | 检查每个写入动作后是否都有文档行，并区分跳过的删除动作与存储事件。 |
