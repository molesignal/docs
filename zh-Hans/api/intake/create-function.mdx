```http
POST /api/v1/functions
```

创建可在流水线中复用的转换。VRL 与 JavaScript 会在创建时编译，源码无效的函数会被拒绝。两种运行时都内置在二进制中。该调用需要 `functions.create`。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 函数名称。 |
| `language` | string | 是 | `vrl`、`js` 或 `llm`。`llm` 函数需要 `[functions].llm_eval_enabled` 与模型服务商。 |
| `source` | string | 是 | VRL 或 JavaScript 源码，或 `llm` 函数的指令。 |
| `paramsSchema` | object | 否 | 参数。对 `llm`，`outputField` 选择输出字段，默认 `_llm_eval`。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/functions \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "lowercase-level",
    "language": "vrl",
    "source": ".level = downcase!(string!(.level))"
  }'
```
</RequestExample>

语法错误会返回 `400`，例如 `js syntax error: Uncaught SyntaxError: Unexpected token '}'`。保存之前可以用 `POST /api/v1/functions/run` 测试源码，它接受 `language`、`source` 与样例 `input`，并返回 `output`，参见[函数](/zh-Hans/functions)。

其他函数路由：`GET /api/v1/functions`，以及 `GET`、`PUT` 与 `DELETE /api/v1/functions/{id}`。内置预设是只读的。

## 保存前试运行转换

试运行接口需要 `functions.run`，与 `functions.create` 分开授权。把转换接入真实数据前，使用代表性输入，并覆盖字段缺失和类型异常的情况。

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".level = downcase!(string!(.level))","input":{"level":"ERROR","message":"example"}}'
```

该输入应产生 `output.level` 为 `error`、保留无关字段 `message`、且 `dropped` 为 `false` 的结果。编译成功不代表所有生产事件都满足转换假设，例如上面的字符串转换要求 `level` 是字符串。

## 将函数连接到流水线

创建函数只保存可复用定义，不会自动转换接入事件。记录返回的函数 ID，通过[流水线](/zh-Hans/pipelines)添加所需函数步骤，并在应用到真实数据流前测试完整流水线。

随变更保留代表性输入与预期输出。启用流水线后，发送受控事件，再查询目标数据流，确认实际存储的字段。试运行响应本身不能验证已部署的接入链路。

## 常见失败

| 现象 | 处理方式 |
|---|---|
| 函数名称为空 | 提供非空 `name`。 |
| 创建时拒绝源码 | 修正语法或编译错误后重试。 |
| 试运行被拒绝 | 检查 `functions.run`，创建权限单独授权。 |
| 输入运行失败 | 用试运行复现失败字段，处理字段缺失或类型不同的情况。 |
| 保存函数后新日志未变化 | 检查流水线绑定和目标数据流。 |
