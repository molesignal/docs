---
title: "创建流水线"
description: "创建实时、定时或告警流水线。"
"en_link": "/en-US/api/intake/create-pipeline"
---

```http
POST /api/v1/scheduled_pipelines
```

创建流水线。各种模式的路径都沿用 `scheduled_pipelines` 这个名称。该调用需要 `pipelines.create`。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 流水线名称。 |
| `sourceStream` | string | 是 | 流水线读取的第一个数据流。告警流水线使用空字符串。 |
| `targetStream` | string | 是 | 流水线写入的第一个数据流。定时流水线中，它是流水线读取的数据流时，调用返回 `409`。告警流水线使用空字符串。 |
| `functionSteps` | object | 是 | 步骤、模式、定时流水线的设置或告警流水线的条件，见下文。 |
| `cron` | string | 是 | 定时流水线使用 `every:30s`、`every:5m` 或 `every:1h`；实时流水线和告警流水线使用空字符串。 |
| `lookbackSecs` | integer | 否 | 每个来源第一次定时运行往回读的秒数，默认 300。定时流水线需要正数。 |
| `enabled` | boolean | 否 | 默认 `true`。 |

`functionSteps` 的字段：

| 字段 | 说明 |
|---|---|
| `mode` | `scheduled`（默认）、`realtime` 或 `alert`。 |
| `signalType` | `logs`、`metrics` 或 `traces`，实时流水线还可以是 `profiles`。指标、链路和性能剖析的实时流水线原地处理所在的流：`targetStream` 与 `sourceStream` 相同，没有路由步骤，也不能设 `retainSource`，参见[指标与链路](/zh-Hans/pipelines#指标与链路)。性能剖析流水线的来源是 `default`，参见[性能剖析](/zh-Hans/pipelines#性能剖析)。告警流水线没有这个字段。 |
| `steps` | 有序步骤。VRL 步骤包含 `transformName`、`script`，并把 `kind` 设为 `vrl`。路由步骤把 `kind` 设为 `builtin`、`operation` 设为 `route`，并带有 `routing` 对象。告警流水线最多 20 个步骤，不能有路由步骤。AI 摘要步骤包含 `transformName`、`prompt` 和 `annotation`（写入回答的注解，默认 `ai_summary`），并把 `kind` 设为 `ai_summary`。调用接口步骤把 `kind` 设为 `http_enrich`，并带 `connectorId`（组织的 HTTP 连接器）。查询步骤把 `kind` 设为 `query_enrich`，并带 `language`（`sql`，默认，或 `promql`）、`stream`、`streamType`（`logs`，默认，`metrics` 或 `traces`）、`statement`、`windowSecs`（默认 300，最多 86400）、`maxRows`（默认 5，最多 50）和 `annotation`（默认 `query_result`）。参见[告警流水线的步骤](/zh-Hans/pipelines/alert-events#步骤)。实时流水线还可以用计数的步骤 `generate_metric`、`quota` 和 `throttle`，字段见下文。 |
| `alert` | 仅告警流水线使用，表示运行时机、条件与执行顺序：`stage`（`open`，默认，或 `notify`）、`policies`（`notify` 流水线针对的通知策略，空表示告警事件的所有策略）、`sources`（`rule`、`external`、`synthetic`、`noData`，`notify` 还可以是 `manual`）、`severities`（`info`、`warning`、`error`、`critical`）、`labels`（事件必须带有、且值相同的标签对象）和 `order`（整数，默认 0）。列表为空时处理全部来源或全部严重度，参见[告警流水线](/zh-Hans/pipelines/alert-events#通过-api-创建)。 |
| `sources` | 读取的数据流。`sourceStream` 最先读取，定时流水线还会读取列表中的其他数据流，合计最多 8 个。实时流水线只接受 `[source_stream]`。 |
| `sinks` | 写入的数据流。`targetStream` 排在第一位，列表中的其他数据流都收到全部事件，合计最多 8 个。实时流水线只接受 `[target_stream]`。 |
| `sinkConnectors` | 仅定时流水线使用，接收全部事件的连接器 id。 |
| `sinkTables` | 仅定时流水线使用，最多 8 张扩展表的名称，每条事件在每张表里写成一行，参见[写入扩展表](/zh-Hans/pipelines#写入扩展表)。 |
| `delaySecs` | 仅定时流水线使用，最新一段时间留给迟到事件的秒数，过后才由运行读取。0 到 3600，默认 60。 |
| `retry` | 仅定时流水线使用。`runRetries` 是读取或写入失败的窗口还会再尝试的次数，`deliveryRetries` 是连接器投递还会再尝试的次数，各为 0 到 10，默认 3。 |
| `deadLetterStream` | 仅定时流水线使用，保存无法处理、写入或投递的事件的日志数据流，不能是流水线读取或写入的数据流。 |
| `dedupeField` | 仅定时流水线使用。同一次运行中，该字段的值已经出现过的事件会被丢弃。 |
| `retainSource` | 仅日志的实时流水线使用，把原始事件保留在来源数据流中。 |

计数步骤在 `transformName` 和 `kind` 之外的字段。同一条流水线里它们的名字不能重复。参见[计数与限流](/zh-Hans/pipelines#计数与限流)。

| 字段 | 说明 |
|---|---|
| `conditions` | 步骤处理哪些事件：最多 16 条全部满足的条件，每条包含 `field`、`test`（`equals`、`not_equals`、`contains`、`starts_with`、`matches`、`exists`、`missing`、`gt`、`gte`、`lt` 或 `lte`）和 `value`。`gt`、`gte`、`lt`、`lte` 和数字比较，`matches` 用正则表达式。为空时处理所有事件。 |
| `metric` | 仅 `generate_metric`。`name`、`type`（`count`、`gauge` 或 `histogram`）、`field`（取值和直方图必填；计数填了就累加它）、`groupBy`（最多 10 个字段）、`buckets`（直方图的 1 到 30 个递增上界）、`stream`（指标数据流）和 `intervalSecs`（`10`、`30`、`60`（默认）或 `300`）。只用于日志、RUM 和链路的流水线。 |
| `quota` | 仅 `quota`。`unit`（`events` 或 `bytes`）、`limit`（按这个单位的每日上限，1 到 10^15）、`partitionBy`（最多 5 个字段）、`overrides`（最多 100 个 `{"values": {"<字段>": "<值>"}, "limit": <n>}`，`partitionBy` 的每个字段都要有值）、`action`（`drop`（默认）、`pass` 或 `route`）和 `target`（`route` 写入的日志数据流）。只用于日志流水线，以及 `rum_views`、`rum_vitals` 以外的 RUM 数据流，且不能 `route`。 |
| `throttle` | 仅 `throttle`。`limit`（每个时间窗放行的条数，1 到 1000000）、`windowSecs`（1 到 86400）、`groupBy`（最多 5 个字段）、`action`（`drop`（默认）或 `route`）和 `target`。适用的流水线和配额相同。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "normalize-app",
    "sourceStream": "app_raw",
    "targetStream": "app",
    "functionSteps": {
      "mode": "scheduled",
      "signalType": "logs",
      "sources": ["app_raw", "nginx_raw"],
      "sinks": ["app", "app_archive"],
      "delaySecs": 60,
      "retry": { "runRetries": 3, "deliveryRetries": 3 },
      "deadLetterStream": "pipeline_dead_letters",
      "steps": [
        { "transformName": "normalize-level", "kind": "vrl",
          "script": ".level = downcase!(string!(.level))" }
      ]
    },
    "cron": "every:5m",
    "lookbackSecs": 300,
    "enabled": true
  }'
```
</RequestExample>

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | 计划不符合 `every:Ns/m/h`、回看窗口不是正数、定时流水线处理性能剖析、性能剖析流水线的来源不是 `default`、指标、链路、性能剖析或 RUM 的实时流水线写入别的数据流、分流或保留原件、这类流水线的步骤在样例上改动了[保持不变的字段](/zh-Hans/pipelines#指标与链路)、`rum_views` 或 `rum_vitals` 上的步骤能丢弃事件、VRL 步骤无法编译、流名不合法、读取或写入的数据流超过 8 个或扩展表超过 8 张、路由步骤的固定数据流或兜底数据流是来源、死信数据流是流水线读取或写入的数据流、要写入或路由到 [RUM 数据流](/zh-Hans/pipelines#rum-数据流)、以 `rum_sessions` 作实时流水线的来源、要写入、路由到或实时改动[平台数据流](/zh-Hans/pipelines#平台数据流)、`delaySecs` 或重试次数超出范围，或告警流水线的来源或严重度无法识别、带有路由步骤、AI 摘要步骤没有提示词、调用接口步骤的连接器不是组织的 HTTP 连接器、查询步骤不是一条查询、读取 `_audit`、占位符不在字符串里或事件没有这个值、`notify` 流水线带有走出 MoleSignal 的步骤、`open` 流水线带有 `policies` 或来源 `manual`、步骤超过 20 个。还有定时或告警流水线带有 `generate_metric`、`quota` 或 `throttle` 步骤、这类步骤用在它不处理的数据上、两个这类步骤同名，或设置超出范围，例如 PromQL 选不了的指标名、每个指标样本都有的标签（`value`、`le`、`metric_name` 等），或 `target` 是来源数据流。 |
| `403` | 流水线读取 `_audit`，而 Token 缺少 `audit.read` 或属于服务账号。 |
| `409` | 定时流水线会写入它读取的数据流，或同一种数据的同一个来源流上已经启用了一条实时流水线（`a realtime pipeline is already enabled for this <signal> stream`）。 |

实时模式、路由步骤、读取位点与重试参见[流水线](/zh-Hans/pipelines)。
