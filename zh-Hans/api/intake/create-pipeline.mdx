---
title: "创建流水线"
description: "创建实时或定时流水线。"
---

```http
POST /api/v1/scheduled_pipelines
```

创建流水线。两种模式的路径都沿用 `scheduled_pipelines` 这个名称。该调用需要 `pipelines.create`。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 流水线名称。 |
| `source_stream` | string | 是 | 流水线读取的数据流。 |
| `target_stream` | string | 是 | 流水线写入的数据流，必须与来源不同，否则调用返回 `409`。 |
| `function_steps` | object | 是 | 步骤与模式，见下文。 |
| `cron` | string | 是 | 定时流水线使用 `every:30s`、`every:5m` 或 `every:1h`；实时流水线使用空字符串。 |
| `lookback_secs` | integer | 否 | 每次定时运行回看的秒数，默认 300。 |
| `enabled` | boolean | 否 | 默认 `true`。 |

`function_steps` 的字段：

| 字段 | 说明 |
|---|---|
| `mode` | `scheduled`（默认）或 `realtime`。 |
| `signal_type` | `logs`、`metrics` 或 `traces`。实时流水线只支持 `logs`。 |
| `steps` | 有序步骤。VRL 步骤包含 `transform_name`、`script`，并把 `kind` 设为 `vrl`。路由步骤把 `kind` 设为 `builtin`、`operation` 设为 `route`，并带有 `routing` 对象。 |
| `sources`、`sinks` | 数据流名称，实时流水线必填。 |
| `sink_connectors` | 仅定时流水线使用，同样接收输出的连接器 id。 |
| `retain_source` | 仅实时流水线使用，把原始事件保留在来源数据流中。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines \
  -H "authorization: Bearer $MS_JWT" \
  -H 'content-type: application/json' \
  -d '{
    "name": "normalize-app",
    "source_stream": "app_raw",
    "target_stream": "app",
    "function_steps": {
      "language": "vrl",
      "signal_type": "logs",
      "steps": [
        { "transform_name": "normalize-level",
          "script": ".level = downcase!(string!(.level))" }
      ]
    },
    "cron": "every:5m",
    "lookback_secs": 300,
    "enabled": true
  }'
```
</RequestExample>

**错误**

| 状态码 | 原因 |
|---|---|
| `400` | 计划不符合 `every:Ns/m/h`、回看窗口不是正数，或为日志之外的信号创建了实时流水线。 |
| `409` | 来源与目标数据流相同，或该来源数据流已经启用了一条实时流水线。 |

实时模式与路由步骤参见[流水线](/zh-Hans/pipelines)。
