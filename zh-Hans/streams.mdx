数据流是采集、查询、流水线和保留策略共同使用的组织级数据契约。打开 **数据流** 可以查看到达的数据，并检查或配置每条数据流。

## 数据流类型

| 类型 | 典型内容 |
|---|---|
| `logs` | 结构化事件与应用日志。 |
| `metrics` | 一个来源（例如一台 Prometheus）的指标样本，用 `metric_name` 区分。 |
| `traces` | OpenTelemetry Span。 |
| `profiles` | 与 pprof 对象关联的性能剖析元数据。 |
| `extend` | 作为扩展表管理、在处理过程中使用的查找数据。 |

不同数据流类型可以使用相同名称。调用 API 或编写自动化时，请始终传入 `stream_type`。

### 平台数据流

以下数据流由 MoleSignal 自己写入：

| 数据流 | 内容 |
|---|---|
| `_molesignal` | MoleSignal 自身的遥测，在 `_sys` 组织中，参见[自身可观测性](/zh-Hans/self-observability)。 |
| `_synthetic_results` | 拨测检查的每次运行一行，参见[拨测](/zh-Hans/synthetics#结果数据流与保留期)。 |
| `_audit` | 工作区的审计事件，参见[审计数据流](/zh-Hans/settings/data-security#审计数据流)。 |
| `_agent_model_traces` | Mole Agent 的模型调用，参见[用量与预算](/zh-Hans/agent#用量与预算)。 |
| `_agent_score_traces` | Mole Agent 回答的质量分数，参见[质量](/zh-Hans/quality#流里的分数)。 |

它们和其他数据流一样可以读取。`_audit` 需要 `audit.read`：没有这个权限时，列表和运行统计里都看不到它，查看、修改或删除它都返回 `403`。其他途径都不能写入它们：不能新建这些名字的数据流，向它们接入数据返回 `403`，任何[流水线](/zh-Hans/pipelines#平台数据流)也不能写入它们。

## 数据流列表

**数据流** 列出工作区的所有数据流。切换标签页可以显示 **全部** 数据流或某一种类型，也可以按名称或描述搜索，并按运行状态筛选。页面顶部统计正常接收和需要关注的数据流数，并汇总时段内写入的压缩数据和当前存储。

| 列 | 显示内容 |
|---|---|
| **状态** | **正常**、**接收延迟**、**断流**、**空闲**、**未使用** 或 **统计异常**，见下表。 |
| **接收速率**、**最后接收** | 数据到达的速度，以及最后一次到达的时间。 |
| 压缩数据 | 时段内写入的压缩字节数。 |
| **当前存储**、**保留期** | 当前存储的字节数，以及数据保留多少天。 |
| **数据量**、**采集数据大小**、**实际存储大小**、**索引大小** | 保留的记录数、转换前接收的字节数、数据文件的字节数和索引的字节数。 |

| 状态 | 含义 |
|---|---|
| **正常** | 最近 15 分钟内有数据到达。 |
| **接收延迟** | 最后一次数据在 15 分钟到 2 小时之前到达。 |
| **断流** | 超过 2 小时没有数据。 |
| **空闲** | Mole Agent 链路数据流，在两次回答之间本来就没有数据。 |
| **未使用** | 从未收到过数据。 |

标记为 **不可查询** 的数据流仍在接收数据，但不会出现在查询选择器中。每一行都有 **查询** 或 **探索**、**查看详情** 和 **复制数据流 ID**。页头的 **搜索任务** 打开[搜索任务](#搜索任务)。

## 创建数据流

数据第一次写入时 MoleSignal 会自动创建数据流，所以大多数数据流会自己出现。如果要从一开始就设置保留期、加密字段或查询权限，可以提前创建。点击 **创建数据流**：

| 字段 | 规则 |
|---|---|
| **数据流名称** | `snake_case`，最多 64 个字符。 |
| **描述** | 可选，说明这条数据流承载什么数据。 |
| **信号类型** | **日志**、**指标** 或 **链路**。 |
| **保留期（天）** | 数据保留多久。 |
| **索引字段** | 用逗号分隔的字段，为它们建立全文索引。 |
| **加密字段** | 用逗号分隔的字段，在存储前加密，之后无法修改。参见[加密字段](#加密字段)。 |
| **可查询** | 只为路由流水线提供数据的源数据流应关闭它。 |

## 数据流详情

点击数据流即可打开详情。**查询数据** 在对应的探索页中打开它，菜单中有 **复制数据流 ID** 和 **删除数据流**。各标签页：

| 标签页 | 内容 |
|---|---|
| **概览** | 运行状态、首次接收时间、查询能力，以及最近 24 小时写入行数和压缩数据的趋势。还没有数据的数据流提供 **配置数据源** 和 **发送测试数据**。 |
| **字段与索引** | 各字段的类型、索引类型和加密情况。编辑字段可以修改它的索引或遮掩，参见 [Schema 与字段](#schema-与字段)。 |
| **保留策略** | 数据流的保留期，以及指标数据流的降采样。参见[保留与删除](#保留与删除)。 |
| **使用位置** | 依赖这条数据流的对象：写入它的接入端点、流水线、保存的查询和告警规则。修改或删除前请先查看。 |
| **设置** | **描述**、**可查询**、**最大查询窗口（小时）**、**按天合并小文件** 和 **按字段分片**。 |

各标签页上的修改会先汇总为草稿。**保存并应用** 立即应用，**放弃更改** 丢弃草稿。保存前，页面会提示无法撤回的修改：缩短保留期会删除过期数据，降采样会删除原始样本。

**最大查询窗口** 限制对该数据流的一次 SQL 或 PromQL 查询最多覆盖多少小时。时间范围更长的查询会被拒绝，误选“最近 90 天”也不会把一个大数据流从头扫到尾。留空或 `0` 表示不限制。

如果一个兜底数据源仍需接收数据、但不应出现在查询选择器中，请关闭 **可查询**。路由流水线仍可读取该数据流。`extend` 数据应通过 **扩展表** 管理，而不是通用遥测查询路径。

## Schema 与字段

字段包含名称、数据类型、`nullable` 标志、索引类型与 `encrypted` 标志。数据类型有 `bool`、`int64`、`float64`、`utf8`、`timestamp` 与 `json`。传入的数据中首次出现新字段时，该字段会加入 schema；类型不一致的值会被拒绝，并报 `type mismatch on field`。

索引类型决定 MoleSignal 为字段构建哪种辅助结构：

| 索引类型 | 效果 |
|---|---|
| `none` | 不建立辅助索引，这是默认值。 |
| `exact` | 对完整取值建立精确匹配的倒排索引与 Parquet Bloom filter，并记下每个文件的最小值和最大值。`=` 与 `IN` 在打开文件之前跳过不含这些值的文件，命中的行很少时只读这些行所在的页。适用于 `trace_id` 之类的标识符。 |
| `full_text` | 为文本搜索建立分词的倒排索引：字母数字的连续段是词，中日韩文字切成相邻两字的二元组。`MATCH`、`MATCH_TEXT`、`LIKE` 与 `ILIKE` 的字面量（含标点与中文）据此跳过不可能命中的文件。只用于 `utf8` 字段。 |
| `bloom` | Parquet Bloom filter，文本字段的每个文件另有一个整值过滤器，并记下每个文件的最小值和最大值：`=` 与 `IN` 在打开文件之前跳过一定不含这些值的文件。适用于取值很多、只按等值查的字段，例如请求 ID。 |
| `skip` | 记下每个文件的最小值和最大值，文件里不同的值不超过 32 个时还记下全部的值。比较、`IN`、`BETWEEN` 与前缀 `LIKE` 据此跳过文件。 |
| `ngram` | 为每个文件记下值的三元组，不分大小写：`LIKE`、`ILIKE`、`MATCH` 的字面量有三元组不在文件里时跳过这个文件。适用于按片段查的 URL、路径和主机名，不适合大段自由文本。只用于 `utf8` 字段。 |
| `ip` | 记下每个文件里地址的范围，IPv4 映射进 IPv6：`CIDR_MATCH(field, '10.0.0.0/8')` 与对一个地址的 `=` 据此跳过文件。只用于 `utf8` 字段。 |

传入数据中首次出现的字段按名称获得索引类型：

| 数据流类型 | 字段 | 索引类型 |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`、`level`、`session_id`、`fingerprint`、`country`、`browser`、`application`、`environment` | `exact` |
| `traces` | `trace_id`、`span_id`、`parent_span_id`、`service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

其余新字段为 `none`。`level` 建了 `exact` 索引后，日志直方图可以直接从索引统计错误数，不必读取数据文件。修改索引类型只影响之后写入的文件和之后被 Compactor 合并的文件；分区封存后（默认在分区结束 48 小时后）不再合并，其中的文件保留原来的索引。全文索引的格式升级后（例如中日韩文字改为切成二元组），旧文件的索引由后台按新格式重建，重建前旧索引照常使用，查询结果不受影响。

要修改字段，打开 **字段与索引**，点击字段的编辑按钮，然后选择：

- **索引类型**：**未索引**、**全文搜索**、**精确匹配**、**Bloom 过滤器**、**跳过索引**、**N-gram 子串** 或 **IP 地址**。全文搜索、N-gram 子串与 IP 地址只用于文本字段；
- **返回时字段遮掩** 的 **流级策略**：**继承全局规则**、**流级自定义** 或 **流级明确不遮掩**。参见[字段遮掩](/zh-Hans/settings/data-security#字段遮掩)。指标数据流不参与遮掩。

点击 **应用到草稿**，再点击 **保存并应用**。字段的类型不会改变。

### 按字段分片

日志与链路数据流可以按一两个文本字段分片：在 **设置** 标签页的 **按字段分片** 里点击 **添加分片字段**，选择字段，再选择它的分片方式。之后写入的数据按字段的值分进各个分片，每个分片写自己的文件。

- **哈希**：按值的哈希分成 2 到 64 片，分得均匀。带这个字段等值条件（`=` 或 `IN`）的查询只读值所在分片的文件。
- **首字符**：按值的第一个字符分成 37 片，每个数字和字母（不分大小写）各占一片，其余字符与空值占一片。带这个字段等值条件或以文字开头的 `LIKE`（如 `'web-%'`）的查询只读首字符所在分片的文件，`ILIKE` 另读其余字符那一片。分片匀不匀取决于数据，例如十六进制的链路 ID 只用到其中 16 片。

两个字段时，文件按两个字段的分片组合分片，分片数相乘。**按字段分片** 右侧显示分片总数，最多 256：首字符（37 片）配哈希时，哈希最多 4 片。带其中任一个字段条件的查询都能少读文件，两个都带时少得更多。分片字段适合几乎每次查询都带的字段，例如服务、命名空间或租户。分片越多，文件越多、越小。

设置只影响之后写入的数据：已有文件保持原样，查询按每个文件写入时的分片字段判断，Compactor 只把分片字段相同的文件合在一起。分片字段必须是没加密的文本字段，两个分片字段不能相同。

### 加密字段

创建数据流时把字段标记为 `encrypted`，该字段会在写入 Parquet 之前被加密。存储的列保存密文，普通查询返回的也是密文。在 SQL 中用 `decrypt(field)` 读回明文：

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

该标志之后无法修改，否则已有数据将无法读取。密钥来自组织加密密钥与加密根密钥 `MS_CIPHER_KEY`，丢失根密钥会导致加密字段无法恢复，参见[安全与多租户](/zh-Hans/security#字段级加密)。

## 保留与删除

保留策略决定 Compactor 何时删除数据。在 **保留策略** 标签页设置 **数据保留期（天）**，留空则使用平台默认值 30 天，该默认值在 `_sys` 组织的[设置 → 数据保留](/zh-Hans/settings/platform#数据保留)中修改。超过保留期的数据会在下一次清理时删除，因此缩短保留期会删除随之过期的数据，删除的文件无法恢复。指标数据流里在保留期内再没出现过的指标，也会从指标列表中移除。

在指标数据流的**保留策略**标签页，**降采样较早的样本**会把流里每个指标早于设定天数的样本按 1 分钟到 1 天的时间桶聚合：同一 series 在一个桶里的样本合成一个点，数值取平均，增量计数取总和，原始样本随之删除。长时间范围的查询读得少得多，更早的数据只剩时间桶的精度。原始样本无法恢复。

日志与链路数据流的**按天合并小文件**设置（默认开启）会在一天结束一小时后，把这一天的文件在加起来不超过 Compactor 的 `[compactor].target_size` 时合成一个文件，跨多天的查询要打开的文件少得多。保留期随之按天生效：合并后的文件在一整天都过期后才删除。要保留按小时的文件，在数据流的**设置**标签页关闭这个设置。

**删除数据流** 会删除数据流及其配置，无法撤回。它可能导致仪表盘、保存的视图、告警、报告和流水线失效，删除前请先查看 **使用位置** 标签页。

## 搜索任务

搜索任务是在后台运行的查询，结果保留到任务过期。任务有三个来源：

- 带 `Prefer: respond-async` 请求头的查询，或预计结果过大、不适合交互式请求的查询；
- 流水线的回填；
- Mole Agent 提交的查询。

在 **数据流** 的页头选择 **搜索任务** 打开列表。列表头部的视图按状态筛选，每个视图带有数量：**全部**、**排队**、**运行中**、**完成**、**失败** 和 **已取消**。有任务在排队或运行时，列表会自动刷新。

每一行显示任务的类型（**查询** 或 **回填**）、语句、状态、查询时间范围、提交时间、耗时、结果行数、尝试次数和过期时间。每个任务有一个与状态对应的操作：

| 状态 | 操作 |
|---|---|
| 排队或运行中 | **取消任务** |
| 完成 | **下载结果** |
| 失败或已取消 | **重试** |

**删除** 可以在任何状态下移除任务及其结果。

成员可以查看和管理自己提交的任务。拥有 `org.running_queries.cancel` 的管理员可以查看和管理组织内的全部任务。任务 API 参见[查询](/zh-Hans/query#时间范围与异步任务)。

## 接入用量与预算

在 **数据流** 页头选择 **接入用量**，查看每个来源最近 24 小时、7 天或 30 天接入了多少数据。同一份数据按三种方式划分，合计一致：

| 视图 | 来源是 |
|---|---|
| **凭证** | API Token、RUM 客户端 Token、连接器或登录用户。**平台内部** 是平台自身的遥测。 |
| **数据流** | 一个数据流，按名称和类型区分。 |
| **服务** | 事件在 `service.name` 中标注的服务，没有时取 `service` 或 `service_name`。没有标注的事件计入 **未标注服务**。 |

接入量统计被接受数据解压后的请求字节：被拒绝的事件不计，发送方重试的请求只计一次。Span 在到达时计入，早于尾采样。会话回放计入 **数据流** 视图的 `rum_replay` 行。一个请求里有多个服务或数据流时，字节按事件数分摊，所以这些视图是近似值。

未知的数值显示 `–`，不显示 0。带 `≥` 的数值是下限，表示计量在这段时间内才开始；列表上方会说明开始时间。数据大约一分钟内显示在页面上。节点异常停止时，可能少计最后 15 秒。

选择一行，查看这个来源按小时的趋势，以及它在另外两个视图上的拆分。

### 设预算

在一行上选择 **设预算**，或者勾选多行，给它们设同样的预算。

| 字段 | 含义 |
|---|---|
| **周期** | **每天** 或 **每月**，按 UTC 自然日或自然月计算。 |
| **额度** | 1 MiB 到 1 PiB。 |
| **预警比例（%）** | 用到这个比例时提醒一次，用完时再提醒一次。填 `0` 只在用完时提醒。默认 80。 |
| **通知谁** | 组织成员。默认是设预算的人。 |

预算只用来提醒：来源超出预算时，接入的应答和存储都不变，不丢数据，也不限流。每一档在一个周期内只提醒一次。调高额度后再次超出会再提醒。

通知走内置通知策略 **接入预算快用完** 和 **接入超出预算**，也显示在顶栏的通知中心。要调整还通知谁、怎样通知，见[通知渠道](/zh-Hans/notification-channels)。

`_sys` 组织没有通知策略，所以不能设预算。**平台内部**、**未标注服务** 和 **其他服务** 也不能设预算，其中 **其他服务** 是超出[平台设置](/zh-Hans/settings/platform#接入用量)上限的那些服务。
