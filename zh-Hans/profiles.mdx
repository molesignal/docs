持续剖析用于定位服务的 CPU 消耗、内存分配或锁等待。通过主导航打开 **Profiles**。

## 接入 Profile

MoleSignal 支持：

- 外部 OTLP gRPC Receiver 上的 OTLP Profiles；
- `/api/v1/profiles/intake` 的 Pyroscope 兼容接入；
- `/api/v1/profiles/upload` 的 pprof 文件上传；
- 在界面直接上传单个 profile 文件。

Profile 元数据可查询，canonical pprof blob 会压缩后存入对象存储。

## 分析火焰图

先设置时间范围，再用筛选行缩小分析范围：

| 筛选 | 选项 |
|---|---|
| **服务** | 一个服务，或 **全部服务**。 |
| **Profile 类型** | 一次一种类型，例如 **CPU**、**已分配内存** 或 **锁竞争**。列表只给出时间范围内有 Profile 的类型。 |
| **标签筛选** | 一个 `key:value` 键值对。 |

筛选行下方的一行文字说明本次分析的结论：最热的函数及其自身占比、样本数、服务数和采集时长。

火焰图由所选范围内的 Profile 合并而成。选择显示已选数量的 **Profile** 按钮，可以勾选参与合并的 Profile。点击该面板中的一行，可以单独打开一个 Profile，其中提供 **下载 pprof** 和关联链路的链接。时间范围内的 Profile 数超过单次合并的上限时，火焰图展示均匀采样后的结果，并给出提示。

三个视图读取同一份合并数据：

| 视图 | 用途 |
|---|---|
| **火焰图** | 宽度表示累计开销，颜色表示自身开销。点击帧可以聚焦并打开函数详情。顶部的 `/` 帧代表全部样本。 |
| **调用树** | 以逐层展开的树呈现同样的调用栈。 |
| **Top 函数** | 按自身开销和累计开销排序的函数。 |

工作区还支持按名称高亮帧、全屏分析，以及在打开 **实时** 时每 10 秒刷新近期窗口。

## 对比两个时段

在分析页选择 **对比 profile**。对比保留服务和 Profile 类型，并把两个时段放在一起比较：

| 时段 | 设置方式 |
|---|---|
| **对比时段** | 当前要检查的时段。用时间范围控件设置相对或绝对范围。 |
| **基线时段** | 用来衡量对比时段的参照。**上一个时段**、**一天前的同一时段** 和 **一周前的同一时段** 会跟随对比时段；**自定义时段** 可以设为任意范围。 |

跟随对比时段的基线只在两者不重叠时可选。例如对比时段为三天时，**一天前的同一时段** 不可选。

页面会给出每个时段的 Profile 数量和 **总量变化**。两个时段有重叠，或两个时段的 Profile 数量不同时，页面会给出提示，因为此时的变化有一部分来自采集数量的差异。

差分火焰图标出开销增加和开销减少的函数。**变化最大的函数** 按自身开销的变化排序，只出现在一个时段的函数标为 **新增** 或 **消失**。在列表中选择函数，可以在火焰图中标出该函数。这种对比适合分析发布或配置变更后的回归。

## 区分应用与节点剖析

应用 Profile 属于组织数据流并显示在产品界面。MoleSignal 还提供面向平台运维的节点本地
pprof Listener。该 Listener 默认关闭，通常应仅绑定 loopback。

节点 Listener 与定时 `_molesignal` Profile 见
[自身可观测](/zh-Hans/self-observability)。

## 权限

- `streams.read` 用于发现 Profile 数据。
- `streams.query` 用于渲染和比较火焰图。
- `streams.write` 或接入凭证用于发送 Profile。

<Warning>
  Profile 可能暴露函数名、代码布局和资源使用模式。请把 Profile 接入、下载和节点 pprof
  Listener 视为敏感运维数据。
</Warning>
