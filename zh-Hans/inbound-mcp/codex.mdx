Codex 可以启动 stdio MCP Server，也支持 MoleSignal 的 Streamable HTTP 端点与 OAuth 自动发现。

## 通过 stdio 接入（推荐）

客户端启动 MoleSignal 命令行，由它把消息转给 MoleSignal。需要 Node.js 20 或更高版本。

<Steps>
  <Step title="登录一次">

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

浏览器会打开 MoleSignal，同意授权即可；命令行会保存登录并自动续期。

  </Step>
  <Step title="添加 MoleSignal">

```bash
codex mcp add molesignal -- npx -y @molesignal/cli mcp
```

也可以写在 `~/.codex/config.toml` 中：

```toml
[mcp_servers.molesignal]
command = "npx"
args = ["-y", "@molesignal/cli", "mcp"]
```

  </Step>
</Steps>

没有浏览器时，不用登录，改为在服务器的环境变量中设置 `MOLESIGNAL_URL` 与 `MOLESIGNAL_TOKEN`（API Token）。参见[通过 stdio 接入](/zh-Hans/inbound-mcp#通过-stdio-接入)。

下面各节不用命令行，通过 Streamable HTTP 接入。

## 使用 OAuth 2.1

<Steps>
  <Step title="注册 MoleSignal">

    ```bash
    codex mcp add molesignal \
      --url https://molesignal.example.com/api/v1/mcp
    ```

  </Step>
  <Step title="授权连接">

    ```bash
    codex mcp login molesignal
    ```

    在浏览器中完成 MoleSignal 授权。

  </Step>
  <Step title="验证 Server">

    ```bash
    codex mcp get molesignal
    codex mcp list
    ```

    重启当前 Codex 任务或创建新任务，让 MCP Tool 列表重新加载。

  </Step>
</Steps>

<Warning>
  不要添加 `--oauth-resource`。MoleSignal 已通过 OAuth 发现元数据发布受保护资源；再次添加相同值可能触发 `duplicate field resource`。
</Warning>

## 使用 API Token

非交互 Codex 进程可以使用个人或 Service Account API Token：

```bash
export MOLESIGNAL_MCP_TOKEN="<api-token>"

codex mcp add molesignal \
  --url https://molesignal.example.com/api/v1/mcp \
  --bearer-token-env-var MOLESIGNAL_MCP_TOKEN
```

Codex 保存环境变量名，不保存 Token 值。启动 Codex 的进程必须可以读取该变量。

## 验证 Tool 发现

向 Codex 输入：

> 使用 MoleSignal MCP Server，搜索事件相关 Tool 并列出活动事件，不要执行任何变更。

首次请求应先使用 `tool_search`，再通过 `call_read_tool` 执行延迟发现的读取。

参见 [Codex MCP 官方文档](https://developers.openai.com/codex/mcp/)。
