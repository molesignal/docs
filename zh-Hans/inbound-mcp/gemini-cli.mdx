Gemini CLI 支持 stdio 与 Streamable HTTP Server、OAuth 自动发现，以及 MCP Tools、Resources 与 Prompts。

## 通过 stdio 接入（推荐）

客户端启动 MoleSignal 命令行，由它把消息转给 MoleSignal。需要 Node.js 20 或更高版本。

<Steps>
  <Step title="登录一次">

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

浏览器会打开 MoleSignal，同意授权即可；命令行会保存登录并自动续期。

  </Step>
  <Step title="添加 MoleSignal">

```bash
gemini mcp add molesignal npx -y @molesignal/cli mcp
```

  </Step>
</Steps>

没有浏览器时，不用登录，改为在服务器的环境变量中设置 `MOLESIGNAL_URL` 与 `MOLESIGNAL_TOKEN`（API Token）。参见[通过 stdio 接入](/zh-Hans/inbound-mcp#通过-stdio-接入)。

下面各节不用命令行，通过 Streamable HTTP 接入。

## 使用 OAuth 2.1

<Steps>
  <Step title="添加 MoleSignal">

    ```bash
    gemini mcp add --transport http --scope user \
      molesignal https://molesignal.example.com/api/v1/mcp
    ```

    省略 `--scope user` 会把配置保存在当前项目的 `.gemini/settings.json`。

  </Step>
  <Step title="认证">
    启动交互式 Gemini CLI 会话，然后运行：

    ```text
    /mcp auth molesignal
    ```

    在浏览器中完成授权。Gemini CLI 会自动发现 OAuth 端点并执行动态客户端注册。

  </Step>
  <Step title="验证 Server">

    ```bash
    gemini mcp list
    ```

    在交互式会话中运行 `/mcp`，检查已连接的 Tools、Resources 与 Prompts。

  </Step>
</Steps>

## 使用 JSON 配置

`~/.gemini/settings.json` 或 `.gemini/settings.json` 中等效的 Streamable HTTP 配置为：

```json
{
  "mcpServers": {
    "molesignal": {
      "httpUrl": "https://molesignal.example.com/api/v1/mcp"
    }
  }
}
```

除非本地 Gemini Policy 明确需要绕过客户端确认，否则不要为受控变更 Server 设置 `trust: true`。MoleSignal 服务端审批策略仍然生效。

参见 [Gemini CLI MCP 官方文档](https://geminicli.com/docs/tools/mcp-server/)。
