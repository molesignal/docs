真实用户监控（RUM）记录 Web 与移动端用户体验，并将前端遥测与后端可观测性关联。

## 数据模型

Browser SDK 与 Flutter App SDK 将通过身份验证的事件发送到同一组写入端点：

| 端点 | 数据流或存储 | 采集内容 |
|---|---|---|
| `POST /api/v1/rum/sessions` | `logs/rum_sessions` | 会话身份、设备、平台、地理与时长。 |
| `POST /api/v1/rum/actions` | `logs/rum_actions` | 页面、用户动作、资源、API 与前端性能。 |
| `POST /api/v1/rum/errors` | `logs/rum_errors` | JavaScript 或 Dart 错误与堆栈帧。 |
| `POST /api/v1/rum/replay` | 回放事件存储 | 浏览器 DOM 或 Flutter 屏幕回放事件。 |

三个数据流会在首次写入时创建。因此新部署在 SDK 发送第一条事件前会显示空状态。

## 概览

打开 **RUM → 概览**，在所选时间范围内查看会话、用户、错误、页面性能，以及浏览器或地理分布。

## 会话与回放

**会话**列出近期 RUM 会话。打开会话可以检查动作时间线、回放事件、错误、设备上下文与关联后端链路。

请将回放视为敏感用户数据。在 SDK 中应用采集控制，避免记录 Secret 或个人字段，并使用尽可能短的保留时间。

## 错误、Source Maps 与 Symbols

**错误**按指纹归并反复出现的 JavaScript 失败，并显示发生次数、受影响用户、堆栈帧和示例会话。

通过 **RUM → RUM 设置 → Source Maps 与 Symbols** 上传 Browser Source Map 或移动端 Symbols。
MoleSignal 使用已上传的调试产物还原压缩、混淆或原生堆栈帧。读取调试产物元数据需要
`streams.read`；上传和删除需要 `streams.configure`。

## 性能

性能工作区分为：

- 概览趋势；
- Core Web Vitals；
- 前端错误性能；
- API 与资源耗时。

API 表按 URL 展示数量、延迟百分位与错误率。使用全局时间范围和分面比较不同发布、平台、国家或页面。
浏览器应用上报 Core Web Vitals；Flutter 应用上报首次渲染、build、raster、vsync 与慢帧数据。

## 关联后端链路

当动作携带 W3C `traceparent` 时，动作 `trace_id` 会直接关联后端 Span。如果没有直接 ID，会话详情可以在会话时间窗口中搜索相关链路。

慢前端动作可以直接跳转到对应的服务链路、日志与指标，同时保留调查上下文。

## 权限

- `rum.write` 用于发送 RUM 事件。应用绑定的 `msrum_` Token 只为一个应用授予此权限。
- `streams.query` 用于打开组织 RUM 视图与关联查询。
- `streams.read` 用于列出调试产物元数据。
- `streams.configure` 用于上传或删除 Source Map 与移动端 Symbols。
