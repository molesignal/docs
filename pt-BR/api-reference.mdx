MoleSignal expõe uma API HTTP versionada. Os endpoints do produto usam `/api/v1`. A sonda de integridade, as métricas do Prometheus, os links de compartilhamento público e alguns protocolos de compatibilidade também usam outros caminhos.

## URL base

Para uma instância local:

```text
http://localhost:5080/api/v1
```

Em produção, substitua o host pelo endereço público da implantação, que é o valor de `[http].external_url`.

## Autenticação

Os endpoints protegidos aceitam um token bearer no cabeçalho `Authorization`:

```http
Authorization: Bearer <token>
```

| Token | Como obter | Validade |
|---|---|---|
| Token de API | **Configurações da conta → Tokens de API**, ou [Emitir um token de API](/pt-BR/api/auth/issue-token). Os tokens têm o formato `mspat-<36>`. | Até ser revogado, ou até a expiração escolhida. |
| Token de ingestão padrão | `GET /api/v1/me/api-tokens/default`. Limitado a `logs.write`, `metrics.write`, `traces.write`, `profiles.write` e `apm.deploy`. | Não expira. |
| Token de cliente RUM | `GET /api/v1/auth/tokens/rum?applicationId=<id>`. Limitado a `rum.write`. | Não expira. |

Use um token de API para scripts e coletores. Consulte [Fonte de dados](/pt-BR/intake#tokens-de-ingestão) para os tokens de ingestão.

A interface web entra com `POST /api/v1/auth/signin`, que define cookies de sessão em vez de retornar um token. O cabeçalho `Authorization` não aceita um token de sessão. Consulte [Entrar](/pt-BR/api/auth/login).

A autenticação monta um contexto IAM com o sujeito, a organização ativa ou o escopo de plataforma, e as permissões efetivas. A organização de uma requisição sempre vem desse contexto. Os corpos das requisições não podem selecionar outra organização.

## Rotas públicas e com autenticação própria

Algumas rotas não podem usar um token bearer de organização. Em vez disso, elas validam uma credencial mais restrita ou uma política:

- login, política de cadastro e redefinição de senha;
- `GET /api/v1/healthz` e o `/metrics` de nível raiz;
- troca de compartilhamento público de recursos e solicitações de sessão de compartilhamento;
- downloads de arquivos assinados e avatares públicos;
- endpoints de conectores de push, que validam um token de push.

Uma rota pública não é irrestrita. O handler dela verifica a política de cadastro, um token de compartilhamento, um token de download, uma assinatura ou a credencial do conector.

## Autorização

Um endpoint pode exigir uma ou mais destas condições:

- uma permissão de organização, como `streams.query`;
- uma permissão de plataforma, como `sys.telemetry.read`;
- a propriedade de um recurso, um relacionamento com ele ou uma concessão entre organizações.

`GET /api/v1/iam/capabilities` retorna as permissões efetivas do sujeito atual. Não infira acesso a partir de um nome de função nem de um item de menu visível.

## Requisições

- A maioria dos corpos é JSON com `Content-Type: application/json`.
- Os endpoints de ingestão de compatibilidade usam o payload do próprio protocolo, como Protobuf, NDJSON ou um corpo comprimido com gzip.
- Corpos de requisição de ingestão maiores que 2 MiB, ou 16 MiB para ingestão JSON nativa, são rejeitados com `413`.
- Os horários são inteiros em microssegundos desde a época Unix. Um instante recebe o nome do que aconteceu (`createdAt`, `expiresAt`), com `Time` adicionado onde uma única palavra seria ambígua (`startTime`); uma duração termina em `Time` (`p95Time`) a menos que o nome já diga isso (`duration`). Os registros de telemetria nativos usam `_timestamp`, também em microssegundos.
- Codifique em URL os ids de caminho e os nomes de stream.

## Respostas e erros

Uma resposta bem-sucedida é JSON, a menos que o endpoint transmita em stream ou baixe um arquivo. Uma resposta de erro tem um código de status e um corpo JSON com um código `error` legível por máquina e uma `message`:

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

Um erro `validation_failed` adiciona um array `issues` com uma entrada por campo inválido.

| Status | `error` | Significado |
|---|---|---|
| `400` | `invalid_argument`, `validation_failed` | A requisição ou um dos seus parâmetros é inválido. |
| `401` | `unauthorized` | O token está ausente, malformado, inválido ou expirado. |
| `403` | `forbidden` | A permissão, o relacionamento ou o escopo está ausente. |
| `404` | `not_found` | O recurso não existe ou não está visível no escopo autorizado. |
| `409` | `conflict` | Um conflito de estado ou de unicidade. |
| `413` | `payload_too_large` | O corpo excede o limite. |
| `429` | `resource_exhausted` | Aplica-se um limite de taxa. Respeite o cabeçalho `Retry-After` quando presente. |
| `499` | `cancelled` | A requisição foi cancelada. |
| `503` | `unavailable` | Uma dependência está indisponível. |
| `500` | `internal` | Uma falha interna. O corpo traz a mensagem `internal error`, e os detalhes ficam no log do servidor. |

Uma requisição cujo corpo não pode ser analisado falha antes de chegar ao endpoint. Essa resposta é texto simples em vez de JSON:

| Status | Significado |
|---|---|
| `400` | O corpo não é um JSON válido. |
| `415` | A requisição não tem `Content-Type: application/json`. |
| `422` | Um campo está ausente ou tem o tipo errado. O texto indica o nome do campo. |

Toda resposta traz os cabeçalhos `X-Request-Id` e `X-Trace-Id`. Inclua ambos ao relatar uma falha no lado do servidor.

## Paginação

Os endpoints que podem retornar muitas linhas aceitam `limit` e `cursor`. Essa resposta traz `items` e `nextCursor`. Passe `nextCursor` como `cursor` para ler a próxima página e pare quando ele estiver vazio. Os outros endpoints de listagem retornam a lista completa. Consulte a página de cada endpoint.

## Consultas e trabalhos de longa duração

A família de consultas retorna JSON comum, transmite NDJSON em stream e executa consultas longas como jobs de busca assíncronos. Uma consulta muito grande responde `202` com um `jobId` e um caminho `monitor`. Os chamadores em streaming devem tratar a entrega parcial e cancelar a requisição quando o resultado não for mais necessário. Consulte [Consulta](/pt-BR/query).

Artefatos grandes, como relatórios gerados, blobs de perfil e exportações, são entregues como arquivos por meio de um token de download com escopo restrito, em vez de dentro de um corpo JSON.
