## Como funciona a execução de uma alteração

Um comando que faz uma alteração, como confirmar o recebimento de um incidente, faz a solicitação ao MoleSignal por meio de uma
ferramenta gerenciada, assim como o Mole Agent e as ferramentas do agente. A política de ferramentas da organização define como cada
ferramenta é executada em **Mole Agent → Configurações → Ferramentas e recursos**:

| Modo de execução | O que o comando faz |
|---|---|
| Automática | A alteração ocorre imediatamente. |
| Confirmação | O MoleSignal exige confirmação, e o comando solicita a confirmação no terminal. `-y` (`--yes`) responde sim antecipadamente, por exemplo, em CI. Sem um terminal ou `--yes`, nada muda. |
| Aprovação única, aprovação dupla | O MoleSignal abre uma solicitação de aprovação para revisão em **Mole Agent → Aprovações**. O comando exibe a solicitação de aprovação e retorna o código `3`. Com `--wait`, o comando aguarda a decisão até o limite de `--timeout` (30 minutos por padrão) e executa a alteração se houver aprovação. |
| Desativada | O comando falha e informa o motivo. |

Sem uma política própria, a ferramenta segue o modo padrão do seu nível de risco: confirmação para
`create_annotation` e `submit_search_job`, e aprovação única para `acknowledge_incident`,
`resolve_incident` e `run_synthetic_monitor`. Use `--reason` para informar o motivo na solicitação de aprovação e no
log de auditoria.

A confirmação exige a revisão 2026-07-28 do protocolo MCP, que a CLI usa quando o MoleSignal oferece suporte a ela.
`molesignal status` informa a revisão em uso.

## Liste incidentes

```bash
molesignal incidents
```

A lista mostra os incidentes ativos, do mais recente ao mais antigo, com status, gravidade, tempo desde a abertura, serviços
e resumo. Use `--status resolved` ou `--status all` para listar outros incidentes, `--since 7d` para listar apenas os abertos
nos últimos sete dias e `-n` para definir a quantidade.

`molesignal incidents show` exibe os detalhes de um incidente: regra, horários, serviços, rótulos, notas como
o runbook e amostras de traces. `--rca` inclui a análise de causa raiz, e `--web` abre o
incidente no MoleSignal:

```bash
molesignal incidents show <incident> --rca
```

## Confirme o recebimento e resolva incidentes

```bash
molesignal incidents ack <incident>
```

```bash
molesignal incidents resolve <incident> --reason "Rolled back to 2.3.9"
```

Os dois comandos seguem a política de ferramentas e exigem `alerts.incidents.acknowledge`.

## Veja quem está de plantão

```bash
molesignal oncall
```

A lista mostra quem está de plantão em cada escala ativa. Use `--schedule` para filtrar por uma única escala
e `--at` para consultar outro horário, como em `--at "2026-10-27 09:00"`.

## Execute alterações aprovadas

`molesignal approvals` lista as solicitações do Mole Agent, das ferramentas do agente e dos comandos que aguardam revisão ou
já receberam aprovação, mas ainda não foram executadas. `--all` também lista as solicitações que já receberam uma
decisão.

```bash
molesignal approvals
```

`molesignal approvals show <approval>` exibe os detalhes de uma solicitação: ação, alvo, motivo, impacto e
pareceres. `molesignal approvals execute <approval>` executa uma alteração aprovada. O MoleSignal pode
solicitar confirmação antes da execução:

```bash
molesignal approvals execute <approval>
```

## Adicione anotações a dashboards

`molesignal annotate` adiciona uma anotação em um momento específico ou em um intervalo de tempo, em todos os dashboards
ou em apenas um:

```bash
molesignal annotate "Release 2.4.0" --tags release,checkout --yes
```

| Opção | Significado |
|---|---|
| `--description <text>` | Descrição da anotação. |
| `--tags <a,b>` | Tags para localizar a anotação. |
| `--dashboard <id>` | Restringe a anotação a este dashboard. |
| `--stream <stream>` | Fluxo ao qual a anotação se refere. |
| `--time <time>`, `--end <time>` | Horários de início e término. Por padrão, a anotação marca apenas o momento atual. |

Adicionar uma anotação exige `dashboards.edit`.

## Execute verificações sintéticas

`molesignal synthetics` lista as verificações com tipo, estado e ciclo de vida.
`molesignal synthetics results <check>` lista as execuções mais recentes de uma verificação em cada local, com
resultado, duração e motivo da falha, se houver. Identifique a verificação pelo ID ou pelo nome.

`molesignal synthetics run` executa uma verificação imediatamente em cada local configurado. Com `--wait`, o comando
aguarda as execuções e retorna o código `1` se alguma falhar ou não terminar no prazo de `--timeout`
(10 minutos por padrão). Assim, um pipeline pode interromper uma publicação:

```bash
molesignal synthetics run "Checkout API" --wait --yes
```

Uma execução passa se o resultado indicar funcionamento normal ou instabilidade. Executar uma verificação exige `synthetics.monitors.manage`. Para
executar verificações em CI sem revisão, configure `run_synthetic_monitor` como **Automática** na política de
ferramentas.
