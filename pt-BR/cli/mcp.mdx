`molesignal mcp` disponibiliza as ferramentas MCP do MoleSignal via stdio. A ferramenta de agente inicia o comando
e se comunica com ele pela entrada e pela saída padrão. A CLI encaminha cada mensagem ao
endpoint **MCP de entrada** do MoleSignal e retorna cada resposta. O MoleSignal define as ferramentas, as permissões e
as aprovações. A CLI não acrescenta nenhuma delas.

## Adicione o servidor a uma ferramenta de agente

[Faça login](/pt-BR/cli/sign-in) primeiro e depois deixe a CLI se adicionar à ferramenta de agente:

```bash
molesignal mcp setup claude
```

| Ferramenta de agente | O que `molesignal mcp setup` altera |
|---|---|
| `claude` | Executa `claude mcp add` para o Claude Code. `--scope` aceita `user` (padrão), `project` ou `local`. |
| `cursor` | `~/.cursor/mcp.json` ou `.cursor/mcp.json` na pasta atual com `--scope project`. |
| `codex` | `~/.codex/config.toml`, no diretório indicado por `CODEX_HOME` se essa variável estiver definida. |
| `vscode` | `.vscode/mcp.json` na pasta atual. |
| `gemini` | `~/.gemini/settings.json` ou `.gemini/settings.json` na pasta atual com `--scope project`. |

O comando adiciona um servidor chamado `molesignal` ou substitui um servidor com esse nome e mantém todas as outras
configurações do arquivo. O servidor executa `npx -y @molesignal/cli mcp`. Com `--installed`, executa
o `molesignal` instalado. `--profile` grava o perfil na configuração do servidor para que a ferramenta de agente
use o login desse perfil, independentemente do perfil ativo. `--print` exibe a configuração em vez de
gravá-la.

[Conecte via stdio](/pt-BR/inbound-mcp#conecte-se-via-stdio) lista a mesma configuração para cada
ferramenta. O prompt de configuração em **Mole Agent → Configurações → MCP de entrada** gera as etapas para a
instância.

Em ambientes sem login, como uma máquina de build, forneça as credenciais do servidor por meio de
variáveis de ambiente:

```json
{
  "mcpServers": {
    "molesignal": {
      "command": "npx",
      "args": ["-y", "@molesignal/cli", "mcp"],
      "env": {
        "MOLESIGNAL_URL": "https://molesignal.example.com",
        "MOLESIGNAL_TOKEN": "<token>"
      }
    }
  }
}
```

## Como a CLI encaminha as mensagens

- Até a ferramenta de agente enviar `notifications/initialized`, a CLI encaminha as mensagens uma por vez, em
  ordem. O MoleSignal abre a sessão ao responder a `initialize`. Depois disso, a CLI encaminha as mensagens
  assim que chegam, para que uma chamada lenta não atrase as outras.
- Quando o MoleSignal deixa de reconhecer a sessão, como após uma reinicialização, a CLI abre outra com
  a mensagem `initialize` da própria ferramenta de agente e reenvia a mensagem. A ferramenta de agente continua funcionando sem
  reiniciar.
- Se uma solicitação não chegar ao MoleSignal, a CLI retorna um erro para que a ferramenta de agente não fique
  esperando.
- Quando a ferramenta de agente fecha a entrada padrão, a CLI encerra a sessão no MoleSignal e termina a execução.
- A CLI envia as mensagens para leitura, como avisos de perda de conexão, à saída de erro padrão.
  A saída padrão contém apenas mensagens MCP.
- `HTTPS_PROXY` e `NO_PROXY` se aplicam, como em todos os comandos.

## Verifique a conexão

```bash
molesignal status
```

A contagem corresponde ao número de ferramentas que a ferramenta de agente vê. Uma contagem de zero geralmente indica que a
política de ferramentas da organização ou as permissões do usuário não disponibilizam nenhuma ferramenta.
