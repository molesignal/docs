`molesignal <command> --help` exibe as mesmas informações para um único comando.

## Opções de todos os comandos

Todos os comandos que se comunicam com o MoleSignal aceitam estas opções:

| Opção | Significado |
|---|---|
| `--profile <name>` | O perfil de login salvo a usar. Consulte [Mantenha vários perfis de login](/pt-BR/cli/sign-in#mantenha-várias-sessões). |
| `--url <address>` | O endereço do MoleSignal, em vez do endereço do perfil. |
| `--token <token>` | Um token de API exclusivo para este comando. |

Para indicar um horário, use o formato ISO, uma data e hora no fuso local, como `2026-10-26 14:00`, uma contagem de
segundos, milissegundos ou microssegundos desde a época Unix ou uma duração contada para trás a partir de agora. Uma duração
consiste em um número e uma unidade: `ms`, `s`, `m`, `h`, `d` ou `w`.

## Login

| Comando | Opções | Descrição |
|---|---|---|
| `login` | `--url <address>`, `--profile <name>`, `--with-token` | Autentica pelo navegador ou com um token de API lido da entrada padrão. Define o perfil como atual. |
| `logout` | `--profile <name>` | Remove a autenticação do perfil, mas mantém o endereço. |
| `profiles` | `--json` | Lista os perfis. Use `profiles remove <name>` para remover um perfil. |
| `use <profile>` | nenhuma | Define um perfil como atual. |
| `status` | nenhuma | Exibe o endereço, o perfil, o servidor, a revisão do protocolo MCP, o método de autenticação e o número de ferramentas. |
| `whoami` | `--json` | Exibe o usuário, a organização, a função e as permissões. |
| `doctor` | nenhuma | Verifica o Node.js, a configuração, o endereço, o proxy, a rede e o TLS, o relógio, a autenticação e o endpoint MCP. |

## Logs e consultas

| Comando | Opções | Descrição |
|---|---|---|
| `streams` | `--type <type>`, `--names`, `--json` | Lista os fluxos de um tipo. O tipo padrão é `logs`. |
| `logs <stream>` | `-f`, `-n`, `-q`, `--where`, `--since`, `--from`, `--to`, `--fields`, `--around`, `-B`, `-A`, `--interval`, `--json`, `--utc`, `--web` | Exibe os logs mais recentes de um fluxo. Use `-f` para acompanhar novos logs. Consulte [Leia e acompanhe logs](/pt-BR/cli/logs). |
| `query "<SQL>"` | `--stream`, `--since`, `--from`, `--to`, `-n`, `--csv`, `--json`, `--utc`, `--web` | Executa uma única instrução SQL somente leitura em um fluxo de logs. |
| `fields <stream> [field]` | `--type`, `--since`, `--from`, `--to`, `-n`, `--match`, `--json` | Lista os campos de um fluxo ou os valores mais frequentes de um campo. |

### Opções de `logs`

| Opção | Padrão | Significado |
|---|---|---|
| `-f`, `--follow` | desativado | Continua exibindo novos logs até pressionar **Ctrl+C**. |
| `-n`, `--lines <count>` | `100` | Quantidade de logs recentes a exibir inicialmente, de `1` a `5000`. |
| `-q`, `--query <query>` | nenhum | Consulta por campos no formato aceito pela página **Logs**. |
| `--where <condition>` | nenhum | Condição SQL aplicada aos campos do fluxo. |
| `--since <duration>` | `15m` | Quanto tempo no passado a busca abrange. |
| `--from <time>`, `--to <time>` | nenhum | Intervalo de tempo em vez de `--since`. Não use `--to` com `-f`. |
| `--fields <a,b,c>` | todos | Exibe o horário e apenas os campos indicados. |
| `--around <time>` | nenhum | Exibe os logs imediatamente anteriores e posteriores a um horário. |
| `-B`, `--before <count>` | `10` | Com `--around`: quantidade de logs anteriores ao horário, até `250`. |
| `-A`, `--after <count>` | `10` | Com `--around`: quantidade de logs posteriores ao horário, até `250`. |
| `--interval <duration>` | `2s` | Intervalo entre leituras ao acompanhar logs. |
| `--json` | desativado | Exibe cada log em uma linha de JSON. |
| `--utc` | desativado | Exibe os horários em UTC. |
| `--web` | desativado | Abre os logs na página **Logs** em vez de exibi-los no terminal. |

## Métricas, traces e serviços

| Comando | Opções | Descrição |
|---|---|---|
| `metrics query '<PromQL>'` | `--since`, `--from`, `--to`, `-n`, `--csv`, `--json` | Executa uma consulta PromQL em um intervalo de tempo e exibe uma linha por série com um minigráfico. |
| `metrics names [text]`, `metrics labels <metric>`, `metrics values <metric> <label>`, `metrics series <metric>` | `-n`, `--match <label=value>`, `--json` | Lista nomes de métricas, rótulos, valores de rótulos e séries. |
| `traces` | `--service`, `--errors`, `--min-duration`, `--since`, `--from`, `--to`, `-n`, `--json` | Lista os traces recentes. |
| `traces show <trace>` | `--since`, `--from`, `--to`, `--json`, `--web` | Exibe um trace em um gráfico em cascata. |
| `services` | `--env`, `--namespace`, `--sort`, `--since`, `--from`, `--to`, `-n`, `--json` | Lista os serviços de APM e o estado de saúde de cada um. |
| `services show <service>` | `--env`, `--namespace`, `--since`, `--json`, `--web` | Exibe um resumo de um serviço. |
| `services compare <service> <baseline> <candidate>` | `--env`, `--since`, `--fail-on-regression`, `--json` | Compara duas versões. |
| `search-jobs` | `-n`, `--json` | Lista as tarefas de busca. |
| `search-jobs submit "<statement>"` | `--stream`, `--type`, `--promql`, `--step`, `--since`, `--from`, `--to`, `--limit`, `--keep`, `--wait`, opções de alteração | Envia uma tarefa de busca. |
| `search-jobs show <job>`, `search-jobs results <job>`, `search-jobs cancel <job>` | `-o <file>`, `--csv`, `--json`, opções de alteração | Exibe uma tarefa, grava as linhas do resultado ou cancela a tarefa. |

## Plantão e alterações

| Comando | Opções | Descrição |
|---|---|---|
| `incidents` | `--status`, `--since`, `-n`, `--json` | Lista incidentes. Por padrão, lista apenas os ativos. |
| `incidents show <incident>` | `--rca`, `--json`, `--web` | Exibe um incidente. |
| `incidents ack <incident>`, `incidents resolve <incident>` | opções de alteração | Confirma o recebimento de um incidente ou o resolve. |
| `incidents create --title <text>` | `--description`, `--severity`, `--priority`, `--urgency`, `--service`, `--label`, `--team`, `--policy`, `--user`, `--major`, `--json`, opções de alteração | Abre manualmente um incidente para um problema que nenhuma regra detectou. Encaminha o incidente como um alerta, a menos que `--team`, `--policy` ou `--user` especifique, por ID, quem deve atendê-lo. As opções `--priority` e `--urgency` aceitam os níveis da organização. Exibe o ID e o link do novo incidente. |
| `oncall` | `--schedule`, `--at`, `--json` | Exibe quem está de plantão. |
| `approvals` | `--all`, `-n`, `--json` | Lista solicitações de aprovação pendentes ou aprovadas. |
| `approvals show <approval>`, `approvals execute <approval>` | `--json`, opções de alteração | Exibe uma solicitação ou executa uma alteração aprovada. |
| `annotate "<title>"` | `--description`, `--tags`, `--dashboard`, `--stream`, `--time`, `--end`, opções de alteração | Adiciona anotações a painéis. |
| `synthetics` | `--lifecycle`, `--json` | Lista verificações sintéticas. |
| `synthetics results <check>` | `--since`, `-n`, `--json` | Lista as execuções mais recentes de uma verificação. |
| `synthetics run <check>` | opções de alteração | Inicia uma verificação imediatamente. Com `--wait`, aguarda o fim das execuções. |
| `alerts rules export` | `--ids`, `-o`, `--output` | Exporta regras de alerta em um pacote. Use `--ids` para exportar apenas as regras indicadas. Consulte [Importação e exportação](/pt-BR/alerting/rules#importar-e-exportar). |
| `alerts rules apply -f <file>` | `--dry-run`, `--create-only`, `--json` | Aplica um pacote ou um arquivo de regras de alerta do Prometheus (`-f -` lê da entrada padrão). Primeiro, testa as regras e exibe o que cada uma faria. Se nenhuma falhar, grava todas de uma vez. Se alguma regra falhar, retorna o código de saída 1 para uso em CI. |
| `alerts policies export`, `alerts schedules export`, `alerts routing export` | `--ids`, `-o`, `--output` | Exporta políticas de escalonamento, escalas de plantão ou regras de roteamento em um pacote que identifica usuários pelo e-mail e os demais itens pelo nome. Consulte [Importação e exportação](/pt-BR/alerting/on-call#importação-e-exportação). |
| `alerts policies apply -f <file>`, `alerts schedules apply -f <file>`, `alerts routing apply -f <file>` | `--dry-run`, `--create-only`, `--json` | Aplica um pacote exportado da mesma forma que `alerts rules apply`. Aplique as escalas de plantão antes das políticas que as acionam. Aplique as políticas antes das regras de alerta e de roteamento que fazem referência a elas. |

Veja a seguir as opções de alteração. Consulte [Como uma alteração é executada](/pt-BR/cli/changes#como-funciona-a-execução-de-uma-alteração).

| Opção | Significado |
|---|---|
| `--reason <text>` | Motivo da alteração. Fica registrado com a aprovação e no log de auditoria. |
| `--wait` | Se a alteração exigir aprovação, aguarda a aprovação e depois executa a alteração. |
| `--timeout <duration>` | Tempo limite de espera de `--wait`: `30m` por padrão e `10m` para `synthetics run`. |
| `-y`, `--yes` | Confirma a alteração imediatamente quando o MoleSignal solicita confirmação. |

## Variáveis de ambiente

| Variável | Significado |
|---|---|
| `MOLESIGNAL_URL` | Endereço do MoleSignal, em vez do endereço informado em `--url` ou do endereço salvo. |
| `MOLESIGNAL_TOKEN` | Token de API, em vez das credenciais salvas. |
| `MOLESIGNAL_PROFILE` | Perfil a usar em vez do perfil atual. |
| `MOLESIGNAL_CONFIG` | Arquivo que armazena os perfis. O padrão é `~/.config/molesignal/config.json`. |
| `HTTPS_PROXY`, `HTTP_PROXY` | Proxy para todas as solicitações. |
| `NO_PROXY` | Hosts acessados sem passar pelo proxy. |
| `NODE_EXTRA_CA_CERTS` | Autoridade certificadora confiável além das autoridades do sistema. |
| `NO_COLOR` | Exibe a saída sem cores. |
| `FORCE_COLOR` | Exibe a saída com cores mesmo quando ela não vai para um terminal. |

As opções têm precedência sobre as variáveis de ambiente, que têm precedência sobre o perfil salvo.

## Códigos de saída

| Código | Significado |
|---|---|
| `0` | O comando foi concluído com sucesso ou o acompanhamento foi interrompido. |
| `1` | O comando falhou. Consulte o motivo na saída de erro padrão. Também indica que uma execução sintética falhou com `--wait`, uma versão apresentou regressão com `--fail-on-regression`, `send` rejeitou logs ou uma verificação de `doctor` falhou. |
| `2` | Comando, opção ou argumento desconhecido. |
| `3` | A alteração aguarda aprovação e ainda não foi executada. |

`deploy -- <command>` e `run` retornam o código de saída do comando que executam.
