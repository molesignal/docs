A CLI autentica uma vez e mantém a sessão para os próximos comandos. Há duas formas de entrar:

| Forma | Quando usar |
|---|---|
| Login pelo navegador | Uso interativo em um computador com navegador. Usa OAuth 2.1 e renova a sessão automaticamente. |
| Token de API | Scripts, máquinas de build e computadores sem navegador. |

O login pelo navegador dá acesso apenas ao endpoint MCP do MoleSignal. Para registrar implantações, carregar
mapas de código-fonte e símbolos e enviar logs, use um token de API. Essas operações chamam a API do MoleSignal.

## Entre pelo navegador

```bash
molesignal login --url https://molesignal.example.com
```

1. A CLI se registra no MoleSignal e abre a página de autorização do MoleSignal no
   navegador padrão. Entre no MoleSignal nessa página se ainda não houver uma sessão ativa.
2. A página de autorização identifica o cliente, a conta e a organização, e lista o que
   o acesso permite. Em caso de vínculo com várias organizações, selecione uma em **Organização**. O acesso fica
   vinculado à organização selecionada.
3. Clique em **Autorizar**. O navegador retorna à CLI, que informa quantas ferramentas estão
   disponíveis.

A CLI solicita os escopos `mcp` e `offline_access`, e a sessão se renova automaticamente até
a revogação do acesso. A página de autorização aguarda cinco minutos. Depois disso, o comando termina e a sessão
anterior, se houver, permanece inalterada. Recusar ou interromper o login também mantém a sessão
anterior.

<Note>
  O navegador retorna a um endereço local, `http://127.0.0.1`, que só aceita conexões enquanto o comando está em execução.
  A máquina deixa de aceitar conexões nesse endereço quando o comando termina. Ao acessar uma máquina remota por SSH,
  o navegador não consegue se conectar a esse endereço local da máquina remota. Nesse caso, entre com um token de API.
</Note>

## Entre com um token de API

Crie um token em **Identidade e acesso → Tokens de API** e passe o token pela entrada padrão:

```bash
printf '%s' "$MOLESIGNAL_TOKEN" | molesignal login --url https://molesignal.example.com --with-token
```

O token tem as permissões do usuário ou da conta de serviço a que pertence.

## Use um token sem salvá-lo

Defina o endereço e o token no ambiente, como em uma máquina de build. A CLI não salva esses dados:

```bash
MOLESIGNAL_URL=https://molesignal.example.com MOLESIGNAL_TOKEN=<token> molesignal status
```

`--url` e `--token` têm o mesmo efeito para um único comando. A CLI nunca envia um token salvo para um endereço
a outro endereço.

## Mantenha várias sessões

A CLI guarda cada sessão em um perfil que contém o endereço e as credenciais de acesso. Com vários perfis, a CLI
mantém sessões em várias instâncias do MoleSignal ou em várias organizações de uma mesma instância.
`--profile` indica em qual perfil salvar a sessão:

```bash
molesignal login --url https://staging.molesignal.example.com --profile staging
```

O perfil usado no login mais recente se torna o perfil atual. Os comandos usam o perfil atual.
Use `--profile` ou `MOLESIGNAL_PROFILE` para selecionar outro perfil para um único comando. No primeiro login sem
`--profile`, a CLI salva a sessão no perfil `default`.

| Comando | Efeito |
|---|---|
| `molesignal profiles` | Lista os perfis, os tipos de login e os endereços. `*` marca o perfil atual. |
| `molesignal use <profile>` | Define o perfil indicado como o atual. |
| `molesignal logout --profile <profile>` | Remove a sessão salva do perfil e mantém o endereço. |
| `molesignal profiles remove <profile>` | Remove o perfil. |

## Onde a CLI salva a sessão

A CLI salva os perfis em `~/.config/molesignal/config.json`. Apenas o proprietário pode ler o arquivo. A
CLI usa o diretório definido por `XDG_CONFIG_HOME`, se essa variável estiver configurada, e por `%APPDATA%` no Windows.
`MOLESIGNAL_CONFIG` aponta para outro arquivo.

## Use a CLI com um proxy

`HTTPS_PROXY` (ou `HTTP_PROXY`) encaminha todas as solicitações da CLI por um proxy, e `NO_PROXY`
lista os hosts que a CLI acessa sem passar pelo proxy:

```bash
HTTPS_PROXY=http://proxy.example.com:3128 NO_PROXY=localhost molesignal status
```

Se uma autoridade certificadora privada emitiu o certificado do MoleSignal, inclua o certificado dessa autoridade
em `NODE_EXTRA_CA_CERTS`.

## Verifique a sessão e a configuração

`molesignal status` informa o endereço, o perfil, o servidor que respondeu, a revisão do protocolo
MCP, o tipo de login e o número de ferramentas do MCP:

```bash
molesignal status
```

`molesignal whoami` informa o usuário, a organização, a função e as permissões que o MoleSignal
concede:

```bash
molesignal whoami
```

`molesignal doctor` verifica os itens de que a CLI depende e indica como corrigir eventuais falhas:
Node.js, permissões do arquivo de configuração, endereço, proxy, rede e TLS,
relógio, sessão e endpoint MCP. O comando retorna o código `1` se alguma verificação falhar:

```bash
molesignal doctor
```

## Encerre uma sessão

`molesignal logout` remove a sessão salva do perfil atual nesta máquina:

```bash
molesignal logout
```

A autorização continua válida no MoleSignal até a revogação em
**Mole Agent → Configurações → MCP de entrada**.
