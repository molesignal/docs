As funções encapsulam transformações reutilizáveis de eventos. Abra **Funções** para criar, testar e manter
definições de funções sem depender de um pipeline.

## Encontrar uma função

A lista contém as funções da organização e as predefinições integradas. Use as três visualizações no topo
da lista para filtrar os resultados. Cada uma exibe sua contagem:

| Visualização | Conteúdo |
|---|---|
| **Todos** | Todas as funções da organização e as predefinições. |
| **Suas funções** | As funções criadas pela organização. |
| **Predefinições** | As funções somente leitura que acompanham o MoleSignal. |

A busca considera o nome da função e a descrição da predefinição. Clique em uma função da
organização para abri-la na área de edição.

## Linguagens

| Linguagem | Disponibilidade | Mais indicada para |
|---|---|---|
| VRL | Integrada | Análise sintática, normalização, filtragem, ocultação de dados e enriquecimento. |
| JavaScript | Integrada | Lógica mais fácil de expressar em JavaScript. |
| LLM | Configurável via API; requer `llm_eval_enabled` e um provedor de modelos | Classificação ou enriquecimento de baixo volume com a saída do modelo. |

VRL e JavaScript são executados no binário do MoleSignal. Nenhum dos dois exige configuração ou instalação adicional.

O MoleSignal valida e compila a função ao salvá-la. Se o código-fonte for inválido, a função não se torna
ativa.

A área de edição de **Funções** oferece suporte a VRL e JavaScript. As funções LLM usam um fluxo avançado pela
API: o código-fonte da função é a instrução de sistema, o evento é a entrada do modelo e
`params_schema.output_field` seleciona o campo de saída (por padrão, `_llm_eval`). Cada execução chama o
modelo, por isso a configuração `[functions].llm_eval_enabled` fica como `false` por padrão. Consulte
[Configuração](/pt-BR/configuration#recursos-e-integrações). Para usar um modelo para resumir eventos de
alerta, use a etapa **Resumo por IA** de um [pipeline de alertas](/pt-BR/pipelines/alert-events#resumo-por-ia),
que não depende dessa configuração.

## Predefinições integradas

Todas as organizações têm acesso a estas funções VRL somente leitura:

| Função | O que faz |
|---|---|
| `add-intake-time` | Adiciona um carimbo de data e hora da ingestão para ajudar a diagnosticar a latência de ponta a ponta. |
| `normalize-logs` | Analisa a mensagem JSON, adiciona campos de ambiente e cluster e converte `level` para minúsculas. |
| `parse-key-value` | Extrai os campos de uma mensagem no formato logfmt ou `key=value` e os incorpora ao evento. |
| `redact-email` | Substitui os endereços de e-mail em `message` por um texto substituto. |
| `route-by-service` | Normaliza o nome do serviço e deriva um fluxo de destino por serviço (`logs_<service>`) como sugestão de roteamento. |

A linha de cada predefinição exibe a etiqueta **Integrada** e a descrição no idioma da interface do
usuário conectado. Clique na linha para ler o código-fonte.

Não é possível editar uma predefinição. Para criar uma versão editável, selecione **Usar como base** na linha ou no painel da
predefinição. A área de edição abre uma nova função com a linguagem e o código-fonte da predefinição e o nome
`<preset>-copy`. Ao salvar, crie uma função da organização sem alterar a predefinição.

## Escrever e testar uma função

A área de edição tem três partes:

- o nome e a linguagem da função;
- **Origem**, o editor, com o status de validação do código-fonte ao lado do título;
- **Executar teste**, com a **Entrada de exemplo** em JSON e a **Saída de exemplo**.

Selecione **Executar exemplo** para executar o código-fonte no editor com o evento de exemplo. Não é
necessário salvar o código antes. O evento transformado aparece em **Saída de exemplo**. Se a execução falhar,
o motivo da falha aparece no lugar do evento.

**Salvar função** e **Cancelar** ficam na linha do título da página. A opção **Excluir função** aparece para
funções já salvas. Se o nome ou o código-fonte estiver vazio, **Salvar função** fica
indisponível e a dica da interface indica o que falta.
No editor, pressione `⌘ Enter` ou `Ctrl+Enter` para executar o exemplo e `⌘S` ou `Ctrl+S` para salvar.

O executor chama `POST /api/v1/functions/run` com a linguagem, o código-fonte e um evento de exemplo e
retorna o evento transformado:

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".service = downcase!(string!(.service))","input":{"service":"Checkout"}}'
```

```json
{ "output": { "service": "checkout" } }
```

Exemplo em VRL:

```vrl
.service = downcase!(string!(.service))
.severity = upcase(string(.level) ?? "INFO")
if exists(.customer_id) {
  .customer = lookup("customers", .customer_id)
}
```

## Consultar tabelas e endereços IP

Duas funções VRL leem dados que o MoleSignal armazena. Elas funcionam na execução de exemplos e em todas as etapas VRL
de um pipeline, inclusive nos pipelines de alertas.

| Função | Retorno |
|---|---|
| `lookup("<table>", key)` | A linha da [tabela de extensão](/pt-BR/extend-tables) `<table>` cuja chave é `key`, como objeto, ou `null`. |
| `geoip_lookup(ip)` | A localização de um endereço IPv4 ou IPv6, como objeto, ou `null`. |

```vrl
# the team that owns the host, from the extend table host_owner
.team = lookup("host_owner", .host).team

# where the client is
place = geoip_lookup(.client_ip)
if is_object(place) {
  .country = place.country
  .city = place.city
}
```

- Nenhuma das funções gera erro. Ambas retornam `null` quando a tabela ou a linha não existe, quando a chave não é texto, número ou
  booleano ou quando o endereço é inválido ou não consta no banco de dados.
  Acessar um caminho como `.team` em `null` também retorna `null`.
- Escreva o nome da tabela de `lookup` como uma string literal. A compilação falha se o nome vier de um campo ou de uma
  variável. A consulta usa a representação em texto de chaves numéricas ou booleanas: `42` encontra a linha com a
  chave `42`.
- `lookup` lê as tabelas de extensão do espaço de trabalho. Consulte
  [Tabelas de extensão](/pt-BR/extend-tables#consultar-uma-chave-em-um-pipeline) para saber quanto tempo leva para as alterações
  nas linhas aparecerem nas consultas.
- `geoip_lookup` lê o banco de dados [DB-IP](https://db-ip.com) City Lite indicado em
  [`[mmdb].db_path`](/pt-BR/configuration#recursos-e-integrações) e retorna `null` se o banco não estiver
  disponível. O banco de dados não inclui endereços privados. O objeto inclui apenas os campos abaixo para os quais o
  banco de dados tem valores:

| Campo | Conteúdo |
|---|---|
| `country` | O código ISO 3166 do país, como `DE`. |
| `country_name` | O nome do país em inglês. |
| `continent_code` | O código do continente, como `EU`. |
| `continent` | O nome do continente em inglês. |
| `region` | O nome em inglês da divisão administrativa de primeiro nível, como um estado ou uma província. |
| `city` | O nome da cidade em inglês. |
| `latitude`, `longitude` | As coordenadas em graus. |

## Funções JavaScript

O código-fonte é executado uma vez por evento. O objeto global `molesignal` contém o evento e funções auxiliares:

| Membro | Finalidade |
|---|---|
| `molesignal.fields` | O evento como objeto. Leia, altere ou atribua um novo objeto. |
| `molesignal.set(name, value)` | Define o valor de um campo. |
| `molesignal.del(name)` | Remove um campo. |
| `molesignal.now()` | O tempo atual em microssegundos desde a época Unix. |
| `molesignal.parse_json(text)` e `molesignal.encode_json(value)` | Convertem texto JSON em valores e vice-versa. |
| `molesignal.sha256(text)` | O hash SHA-256 dos bytes UTF-8 do texto, representado por 64 caracteres hexadecimais minúsculos. |

```js
molesignal.set("severity", String(molesignal.fields.level || "info").toUpperCase());
molesignal.set("seen_at", molesignal.now());
molesignal.del("level");
```

Uma função JavaScript é executada em um mecanismo isolado com estes limites:

- Uma execução que ultrapassa 50 ms é interrompida com `js timeout 50ms`.
- Cada função tem um limite de 32 MiB de memória heap.
- Acesso à rede, temporizadores e `TextEncoder` não estão disponíveis.

## Usar uma função

As etapas do pipeline executam VRL. Em uma etapa de **VRL personalizado**, **Começar com uma função salva** copia para a etapa o código-fonte
de uma função VRL ou de uma predefinição. O código continua editável. A etapa mantém sua própria cópia:
alterar ou excluir a função posteriormente não afeta o pipeline.

## Permissões

- `functions.read` permite listar e abrir funções.
- `functions.create` e `functions.edit` permitem gerenciar definições.
- `functions.run` permite executar exemplos.
- `functions.delete` permite excluir uma definição.
