## Geral

### O que é o MoleSignal?

O MoleSignal é uma plataforma de código aberto para observabilidade e resposta a incidentes que pode ser hospedada integralmente em infraestrutura própria. Reúne telemetria, alertas, plantões, páginas de status e investigação com IA em um único sistema. Armazena logs, métricas, traces e perfis como arquivos Parquet no armazenamento de objetos e permite consultá-los com SQL e consultas compatíveis com PromQL. Consulte [Conceitos fundamentais](/pt-BR/concepts).

### Qual licença se aplica?

O MoleSignal é de código aberto e usa a licença Apache 2.0. Consulte [Edição de código aberto](/pt-BR/editions/open-source).

### Existe uma versão hospedada?

O MoleSignal Cloud é a versão hospedada. Consulte os detalhes em [molesignal.com/cloud](https://www.molesignal.com/cloud).

### De quais serviços uma implantação precisa?

PostgreSQL e armazenamento de objetos. O backend de objetos `local` substitui o armazenamento de objetos em implantações de nó único e em ambientes de desenvolvimento. A implantação não usa Kafka, Redis nem serviços de consenso. Consulte [Implantar o MoleSignal](/pt-BR/deployment).

### Qual banco de dados armazena os metadados?

PostgreSQL. Defina `[meta_database].dsn` com a string de conexão do PostgreSQL. Consulte [Configuração](/pt-BR/configuration#banco-de-dados-de-metadados).

### O MoleSignal pode ser executado sem contêineres?

Sim. O MoleSignal é distribuído como um único binário. O [guia de implantação](/pt-BR/deployment) explica como usar o Docker Compose, o binário com systemd ou o Kubernetes.

## Dados

### Onde ficam os dados?

Logs, métricas e traces ficam em arquivos Parquet no armazenamento de objetos. O PostgreSQL armazena metadados, identidades, o catálogo de arquivos e os recursos do produto. Os registros ainda não gravados nos arquivos ficam em objetos de log de gravação antecipada (WAL) no armazenamento de objetos. Assim, a perda de um nó ou do disco não causa a perda de registros cuja gravação já foi confirmada. Consulte [Backup e restauração](/pt-BR/backup-restore).

### Por quanto tempo os dados ficam armazenados?

30 dias por padrão. A opção **Configurações → Retenção de dados** na organização `_sys` define o padrão, e cada fluxo pode ter seu próprio período de retenção. Consulte [Fluxos](/pt-BR/streams).

### Quais protocolos aceitam dados?

OTLP via HTTP e gRPC, Prometheus `remote_write`, o protocolo `_bulk` do Elasticsearch, envio para o Loki em JSON, JSON nativo via HTTP e os mecanismos de encaminhamento de logs do Kinesis Firehose, do Cloudflare Logpush e do Heroku. Consulte [Fonte de dados](/pt-BR/intake).

### Por que os registros aparecem no horário errado?

`_timestamp` conta os microssegundos desde a época Unix. Valores em segundos, milissegundos ou nanossegundos fazem os registros aparecer em horários incorretos. Consulte [Solução de problemas](/pt-BR/troubleshooting#dados-ausentes-ou-inesperados).

### Como consultar dados com um cliente SQL?

Ative `[flight_sql]` e conecte o DBeaver ou clientes JDBC ou ADBC à porta `5083` com um token de API. Consulte [Conectar com um cliente de banco de dados](/pt-BR/query/database-clients).

### O Grafana pode ler dados do MoleSignal?

Sim. Em painéis, na tela Explorar e em regras de alerta, o plug-in de fonte de dados do MoleSignal consulta métricas com PromQL, logs e traces com consultas por campo e qualquer fluxo com SQL. Consulte [Consultar dados pelo Grafana](/pt-BR/query/grafana).

## Contas e segurança

### Como fazer login pela primeira vez?

Uma nova implantação cria a conta raiz com `[auth].root_email` e `[auth].root_password`. A configuração de exemplo usa `admin@example.com` e `admin`. Altere os dois valores antes de usar a implantação. Consulte [Checklist de produção](/pt-BR/deployment/production-checklist).

### Como redefinir uma senha esquecida?

Use o link de redefinição de senha na tela de login. O MoleSignal envia o link por e-mail. Para isso, configure `[notify.smtp]` e `[http].external_url`.

### O que fazer após muitas tentativas de login malsucedidas?

Aguarde o tempo indicado, use uma chave de acesso ou o login único, ou redefina a senha. Se o sistema bloquear todos os usuários ao mesmo tempo, verifique o [Reconhecimento do IP do cliente](/pt-BR/settings/platform#identificação-do-ip-do-cliente): atrás de um proxy não configurado, o sistema atribui o mesmo endereço IP a todos os usuários. Consulte os valores em [Limites de login](/pt-BR/settings/platform#limites-de-login).

### Há suporte para login único?

Sim. Configure plataformas predefinidas, como Google, Microsoft, GitHub e Feishu, e provedores OIDC, OAuth 2.0, SAML e LDAP na interface web, em **Identidade e acesso → Provedores de SSO**. O MoleSignal armazena essas configurações no PostgreSQL. Consulte [Identidade e acesso](/pt-BR/identity).

### O que `MS_CIPHER_KEY` protege?

É a chave raiz dos segredos que o MoleSignal armazena no PostgreSQL, como tokens de API, credenciais de conectores de notificação e chaves de provedores do Mole Agent. Mantenha uma cópia de backup da chave. Consulte [Checklist de produção](/pt-BR/deployment/production-checklist).

## Operações

### Como escalar uma implantação?

Comece com um único nó `standalone`. Para escalar de forma independente a ingestão, as consultas e as tarefas em segundo plano, distribua as funções entre processos: a função `router` serve a interface web e a API, encaminha as gravações aos nós `intake` e envia as consultas aos nós `querier`. Consulte [Implantação por função](/pt-BR/deployment/role-based) e [Limitações conhecidas](/pt-BR/limitations).

### Como identificar a versão em execução?

Execute `molesignal --version` ou chame `GET /api/v1/version` com um token Bearer.

### Onde obter ajuda ou relatar um problema?

Consulte [Suporte e comunidade](/pt-BR/support). Relate problemas de segurança em particular pelos canais indicados nessa página.
