Um fluxo é o contrato no escopo da organização que rege a ingestão, as consultas, os pipelines e a retenção.
Abra **Fluxos** para ver os dados recebidos e inspecionar ou configurar cada fluxo.

## Tipos de fluxo

| Tipo | Conteúdo típico |
|---|---|
| `logs` | Eventos estruturados e logs de aplicativos. |
| `metrics` | Amostras de métricas de uma única fonte, como um servidor Prometheus, diferenciadas por `metric_name`. |
| `traces` | Spans do OpenTelemetry. |
| `profiles` | Metadados de perfis vinculados a blobs pprof. |
| `extend` | Dados de referência que as tabelas de extensão gerenciam e que os pipelines usam durante o processamento. |

O mesmo nome de fluxo pode aparecer em tipos de fluxo diferentes. Sempre inclua `stream_type` nas
solicitações à API e nas automações.

### Fluxos da plataforma

O MoleSignal grava dados nestes fluxos:

| Fluxo | Conteúdo |
|---|---|
| `_molesignal` | A telemetria do próprio MoleSignal, na organização `_sys`. Consulte [Auto-observabilidade](/pt-BR/self-observability). |
| `_synthetic_results` | Uma linha para cada execução de uma verificação sintética. Consulte [Monitoramento sintético](/pt-BR/synthetics#fluxo-de-resultados-e-retenção). |
| `_audit` | Os eventos de auditoria do espaço de trabalho. Consulte [Fluxo de auditoria](/pt-BR/settings/data-security#fluxo-de-auditoria). |
| `_agent_model_traces` | As chamadas do Mole Agent aos modelos. Consulte [Uso e orçamento](/pt-BR/agent#uso-e-orçamento). |
| `_agent_score_traces` | As pontuações de qualidade das respostas do Mole Agent. Consulte [Qualidade](/pt-BR/quality#pontuações-em-um-fluxo). |

Leia esses fluxos da mesma forma que os demais. O fluxo `_audit` exige `audit.read`: sem essa permissão, ele não aparece
na lista nem nos indicadores operacionais, e as tentativas de abrir, alterar ou excluir o fluxo retornam `403`. Só o MoleSignal grava nesses fluxos: não é possível criar um fluxo com um desses nomes, as tentativas de ingestão
nesses fluxos retornam `403` e nenhum [pipeline](/pt-BR/pipelines#streams-da-plataforma) grava dados neles.

## Lista de fluxos

**Fluxos** lista todos os fluxos do espaço de trabalho. Alterne entre as abas para mostrar **Todos** os fluxos ou apenas um tipo,
busque por nome ou descrição e filtre pelo estado operacional. O cabeçalho mostra quantos fluxos recebem dados
normalmente e quantos precisam de atenção, além dos totais de dados compactados gravados no período e do
armazenamento atual.

| Coluna | O que mostra |
|---|---|
| **Status** | **Saudável**, **Com atraso**, **Interrompido**, **Sem tráfego**, **Sem uso** ou **Estatísticas indisponíveis**. Consulte a tabela abaixo. |
| **Taxa de recebimento**, **Último recebimento** | A velocidade de recebimento e quando os últimos dados chegaram. |
| Dados compactados | Os bytes compactados que o fluxo gravou no período. |
| **Armazenamento atual**, **Retenção** | Quantos bytes o fluxo armazena no momento e por quantos dias mantém os dados. |
| **Registros**, **Tamanho dos dados coletados**, **Tamanho dos dados armazenados**, **Tamanho dos índices** | Os registros que o fluxo mantém, os bytes recebidos antes das transformações, os bytes dos arquivos de dados e os bytes dos índices. |

| Estado | Significado |
|---|---|
| **Saudável** | O fluxo recebeu dados nos últimos 15 minutos. |
| **Com atraso** | O último recebimento ocorreu entre 15 minutos e 2 horas atrás. |
| **Interrompido** | O fluxo não recebe dados há mais de 2 horas. |
| **Sem tráfego** | O fluxo de rastreamentos do Mole Agent fica sem tráfego entre as respostas. |
| **Sem uso** | O fluxo nunca recebeu dados. |

Um fluxo com o status **Não pode ser consultado** continua recebendo dados, mas não aparece nos seletores de consulta. Cada linha oferece
**Consulta** ou **Explorar**, **Ver detalhes** e **Copiar ID do fluxo**. No cabeçalho, **Tarefas de busca** abre
a lista de [tarefas de busca](#tarefas-de-busca).

## Criar um fluxo

O MoleSignal cria o fluxo na primeira gravação de dados, por isso a maioria dos fluxos aparece automaticamente. Crie um fluxo
com antecedência para definir desde o início a retenção, os campos criptografados ou o acesso para consultas. Selecione
**Criar fluxo**:

| Campo | Regra |
|---|---|
| **Nome do fluxo** | `snake_case`, com até 64 caracteres. |
| **Descrição** | Opcional. Descreva os dados que passam pelo fluxo. |
| **Tipo de sinal** | **Logs**, **Métricas** ou **Rastreamentos**. |
| **Retenção (dias)** | Por quanto tempo o fluxo mantém os dados. |
| **Campos indexados** | Campos separados por vírgulas que recebem um índice de texto completo. |
| **Campos criptografados** | Campos separados por vírgulas que o MoleSignal criptografa antes de armazenar. Não é possível alterar essa configuração depois. Consulte [Campos criptografados](#campos-criptografados). |
| **Consultável** | Desative esta opção para um fluxo de origem que só alimenta um pipeline de roteamento. |

## Detalhes do fluxo

Selecione um fluxo para abri-lo. **Consultar dados** abre o fluxo no explorador correspondente, e o menu oferece
**Copiar ID do fluxo** e **Excluir fluxo**. Abas:

| Aba | Conteúdo |
|---|---|
| **Visão geral** | O estado operacional, o primeiro recebimento de dados, o acesso para consultas e a evolução do número de linhas gravadas e do volume de dados compactados ao longo de 24 horas. Um fluxo sem dados oferece **Configurar fonte de dados** e **Enviar dados de teste**. |
| **Campos e índices** | Os campos com seus tipos, tipos de índice e configurações de criptografia. Edite um campo para alterar seu índice ou mascaramento. Consulte [Esquema e campos](#esquema-e-campos). |
| **Retenção** | A retenção do fluxo e, para fluxos de métricas, a redução da resolução das amostras. Consulte [Retenção e exclusão](#retenção-e-exclusão). |
| **Uso** | O endpoint de ingestão que grava no fluxo e os pipelines, as consultas salvas e as regras de alerta que dependem dele. Verifique essa aba antes de alterar ou excluir o fluxo. |
| **Configurações** | **Descrição**, **Consultável**, **Intervalo máximo de consulta (horas)**, **Mesclar arquivos pequenos por dia**, **Particionar por campo** e, para logs, **Agrupar por campo**. |

As alterações nas abas ficam em um rascunho. **Salvar e aplicar** aplica todas de uma vez, e
**Descartar alterações** descarta o rascunho. Antes de salvar, a página alerta sobre alterações irreversíveis:
reduzir a retenção exclui os dados expirados, e reduzir a resolução das amostras exclui as amostras originais.

**Intervalo máximo de consulta** limita o número de horas que uma consulta SQL ou PromQL pode abranger no fluxo. O MoleSignal rejeita consultas com
intervalos maiores. Assim, selecionar “últimos 90 dias” por engano não varre todo um fluxo de grande volume. Deixe o campo em branco
ou insira `0` para não impor limite.

Desative **Consultável** quando um fluxo de origem que recebe todos os dados precisar continuar recebendo sem aparecer nos
seletores de consulta. Um pipeline de roteamento ainda pode ler o fluxo. Gerencie os dados de `extend` em
**Tabelas de extensão**, em vez de usar a interface padrão de consulta de telemetria.

## Esquema e campos

Um campo tem um nome, um tipo de dados, um sinalizador `nullable`, um tipo de índice e um sinalizador `encrypted`. Os tipos de dados são `bool`, `int64`, `float64`, `utf8`, `timestamp` e `json`. O MoleSignal adiciona um campo ao esquema na primeira vez que ele aparece nos dados recebidos e rejeita valores de outro tipo com `type mismatch on field`.

O tipo de índice determina qual estrutura auxiliar o MoleSignal cria para o campo:

| Tipo de índice | Efeito |
|---|---|
| `none` | Sem índice auxiliar. Este é o padrão. |
| `exact` | Um índice invertido de correspondência exata de valores inteiros (um filtro de Bloom do Parquet para campos que não são de texto), além do mínimo e do máximo de cada arquivo. `=` e `IN` ignoram os arquivos sem esses valores antes de abri-los e leem apenas as páginas das linhas correspondentes quando há poucas. Em um campo com até 65.536 valores por arquivo, `LIKE` ou `ILIKE` ignora os arquivos em que nenhum valor contém o texto. Use esse índice para identificadores como `trace_id`. |
| `full_text` | Um índice invertido tokenizado para pesquisa de texto: sequências de letras e dígitos formam palavras, e o índice divide o texto CJK em bigramas sobrepostos de dois caracteres. Os literais de `MATCH`, `MATCH_TEXT`, `LIKE` e `ILIKE`, inclusive pontuação e texto CJK, permitem ignorar arquivos sem correspondência possível. Apenas para campos `utf8`. |
| `bloom` | Um filtro de Bloom do Parquet, mais um filtro de valores inteiros por arquivo para campos de texto e `int64`, além do mínimo e do máximo de cada arquivo: `=` e `IN` ignoram os arquivos que certamente não contêm os valores antes de abri-los. Use esse índice para campos com muitos valores consultados apenas por igualdade, como IDs de requisição. |
| `skip` | O mínimo e o máximo de cada arquivo e todos os valores dos arquivos com até 32 valores distintos. Comparações, `IN`, `BETWEEN` e `LIKE` com prefixo usam esses dados para ignorar arquivos. |
| `ngram` | Os trigramas dos valores de cada arquivo e os fragmentos de cinco bytes de cada bloco de 1.024 linhas, sem distinção entre maiúsculas e minúsculas: um literal de `LIKE`, `ILIKE` ou `MATCH` ignora um arquivo se ele não contém um dos trigramas e ignora um bloco se ele não contém um dos fragmentos. Assim, a pesquisa por um ID ou outra string rara lê apenas os poucos blocos que podem contê-la. Um literal com menos de cinco bytes faz a consulta ler todos os blocos. Um fluxo com um campo `ngram` grava os arquivos em páginas de 1.024 linhas. As páginas pequenas e os fragmentos ocupam espaço: em um teste no qual esse campo ocupava dois terços de cada linha, o uso de armazenamento aumentou cerca de 14%. Use esse índice para URLs, caminhos e nomes de host pesquisados por fragmento, não para texto livre longo. Apenas para campos `utf8`. |
| `ip` | O intervalo de endereços de cada arquivo, com endereços IPv4 mapeados para IPv6: `CIDR_MATCH(field, '10.0.0.0/8')` e `=` com um endereço usam esse intervalo para ignorar arquivos. Apenas para campos `utf8`. |
| `key_value` | As chaves de primeiro nível de um objeto JSON e seus valores: `json_text(field, 'key') = 'value'`, `IN` e `IS NOT NULL` ignoram arquivos sem a chave ou o valor e leem apenas as páginas das linhas correspondentes quando há poucas. A comparação usa o valor retornado por `json_text`: texto como está, números e booleanos em sua representação JSON. Apenas para campos `json`. |
| `range` | Os números de cada linha no índice, além do mínimo e do máximo de cada arquivo. Uma consulta `count(*)` com condições de `=` em campos `exact`, de `>`, `>=`, `<` ou `<=` com um número em campos `range` e com um intervalo de tempo obtém a resposta do índice sem ler os arquivos. Outras comparações ignoram os arquivos fora do intervalo. Apenas para campos `int64`, `float64` e `timestamp`. |

Para cada campo indexado, o MoleSignal também registra quantas linhas de cada arquivo não têm valor nesse campo. `IS NULL` ignora os arquivos em que o campo sempre tem um valor. Qualquer outra condição no campo, inclusive condições que verificam se há um valor, como `IS NOT NULL` e `!= ''`, ignora os arquivos em que o campo nunca tem valor.

Condições ligadas por `OR` também ignoram um arquivo quando o índice aplicável a cada condição descarta todas elas: `level = 'error' OR status >= 500` ignora um arquivo cujo índice de `level` não contém `error` e cujo `status` nunca chega a 500.

Quando um campo aparece pela primeira vez nos dados recebidos, o nome determina o tipo de índice:

| Tipo de fluxo | Campos | Tipo de índice |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`, `level`, `session_id`, `fingerprint`, `country`, `browser`, `application`, `environment` | `exact` |
| `traces` | `trace_id`, `span_id`, `parent_span_id`, `service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

Todo outro campo novo recebe `none`, a menos que as regras do próprio fluxo determinem outro tipo: consulte [Índice de novos campos](#índice-de-novos-campos). Um índice `exact` em `level` permite que o histograma de logs conte erros pelo índice sem ler os arquivos. Os fluxos de RUM indexam as chaves de `context`, `feature_flags` e `usr.extra` com `key_value`.

A alteração no tipo de índice vale de imediato para os dados gravados depois dela. O MoleSignal reindexa os dados anteriores em segundo plano com as novas configurações: reconstrói cada partição selada (por padrão, 48 horas após o fim do período da partição) a partir dos arquivos e reindexa os arquivos mais recentes quando são selados ou mesclados. Até lá, cada arquivo mantém o índice que recebeu na gravação. Isso não altera os resultados, apenas quantos arquivos a consulta lê. **Cobertura de campos indexados**, em **Visão geral**, mostra quantos arquivos ainda faltam. Quando o formato do índice de texto completo muda, como na adoção de bigramas para texto CJK, o MoleSignal reconstrói os índices dos arquivos mais antigos no novo formato em segundo plano da mesma forma.

Para alterar um campo, abra **Campos e índices**, selecione a ação de edição do campo e escolha:

- o **Tipo de índice**: **Não indexado**, **Pesquisa de texto completo**, **Correspondência exata**, **Filtro de Bloom**,
  **Índice de salto**, **Substring de n-gramas**, **Endereço IP** ou **Chaves JSON**. As opções Pesquisa de texto completo, Substring
  de n-gramas e Endereço IP se aplicam a campos de texto, e Chaves JSON a campos JSON;
- a **Política por fluxo** de **Mascaramento de campos nos resultados**: **Herdar regra global**, **Regra personalizada do fluxo**
  ou **Sem mascaramento explícito no fluxo**. Consulte [Mascaramento de campos](/pt-BR/settings/data-security#mascaramento-de-campos).
  O mascaramento não se aplica a fluxos de métricas.

Selecione **Aplicar ao rascunho** e depois **Salvar e aplicar**. O tipo de dados de um campo nunca muda.

### Índice de novos campos

Em **Índices de campos**, na aba **Configurações**, as regras atribuem um índice pelo nome aos campos
que aparecem pela primeira vez no fluxo. Selecione **Adicionar regra**, insira um padrão de nome de campo e escolha um tipo de índice:
`*` representa qualquer sequência de texto e `?` representa um caractere. Assim, `*_id` corresponde a `user_id` e
`order_id`, e `http.*` corresponde a todos os campos em `http`. Vale a primeira regra cujo padrão
corresponda ao nome e cujo tipo de índice seja compatível com o tipo de dados do campo. Um índice configurado para um campo
pelo nome em **Campos e índices** tem prioridade. Sem regra correspondente, o campo recebe o padrão descrito acima.
As regras afetam apenas os campos que aparecerem a partir de então: altere os campos existentes em **Campos e
índices**. Cada fluxo aceita até 32 regras.

### Particionar por campo

Para particionar um fluxo de logs ou rastreamentos por um ou dois campos de texto, em **Particionar por campo**, na
aba **Configurações**, selecione **Adicionar um campo**, escolha o campo e defina como particionar. O MoleSignal divide os dados
gravados depois disso em shards conforme os valores dos campos e grava cada shard em seus próprios arquivos.

- **Hash** distribui os valores uniformemente entre 2 e 64 shards pelo hash. Uma consulta com uma condição de igualdade
  no campo (`=` ou `IN`) lê apenas os arquivos dos shards que correspondem aos valores.
- **Primeiro caractere** distribui os valores em 37 shards pelo primeiro caractere: um para cada dígito e
  cada letra (sem distinção entre maiúsculas e minúsculas) e um para o restante, inclusive valores vazios. Uma consulta com uma
  condição de igualdade no campo ou um `LIKE` que começa com texto (como `'web-%'`) lê apenas
  os arquivos do shard desse caractere. Um `ILIKE` também lê o shard dos demais valores. O equilíbrio entre
  os shards depende dos dados: IDs de rastreamento hexadecimais usam apenas 16 deles.

Com dois campos, o MoleSignal divide os arquivos pelos shards dos dois campos, multiplicando as quantidades de shards. **Particionar por
campo** mostra o total, limitado a 256 shards: o primeiro caractere (37 shards) pode ser combinado com um hash de até 4
shards. Uma consulta com uma condição em qualquer um dos campos lê menos arquivos. Com condições nos dois, lê
ainda menos. Particione por campos usados em quase todas as consultas, como serviço, namespace ou tenant.
Mais shards geram mais arquivos e reduzem o tamanho de cada um.

A configuração vale para os dados gravados após a alteração. Os arquivos existentes permanecem como estão, a consulta avalia
cada arquivo conforme os campos de particionamento usados na gravação e o compactador só mescla arquivos gravados com os
mesmos campos. Use apenas campos de texto sem criptografia e, se usar dois, escolha campos diferentes.

### Agrupar por campo

Para agrupar as linhas nos arquivos de um fluxo de logs por um ou dois campos, em **Agrupar por campo**,
na aba **Configurações**, selecione **Adicionar um campo**, escolha o campo e defina a **Janela de tempo**. Em cada
arquivo gravado depois disso, o MoleSignal organiza as linhas em janelas com essa duração, da mais recente para a mais antiga. Dentro de cada janela,
ordena as linhas pelos valores dos campos e, em seguida, da mais recente para a mais antiga.

Em ordem cronológica, um valor como o nome de um serviço aparece em todas as páginas de um arquivo. Com o agrupamento, cada janela
concentra esse valor em poucas páginas. Assim, uma consulta com uma condição de igualdade em um campo de agrupamento (`=` ou `IN`)
lê apenas essas páginas. Use campos frequentes nas consultas e com poucos valores, como
serviço ou nível.

Cada arquivo agrupado também registra quantas linhas há em cada minuto para cada combinação de valores dos
campos de agrupamento. Uma contagem com condições de igualdade em campos de agrupamento de texto, uma contagem
agrupada por um desses campos (`GROUP BY service`) e um histograma com barras de minutos inteiros usam essas contagens
sem ler o arquivo, mesmo quando a janela da consulta começa ou termina em um minuto
inteiro dentro do arquivo. Se os minutos e valores de um arquivo gerarem mais de 65.536 combinações, o arquivo não guarda nenhuma contagem.
Essas mesmas contagens indicam onde fica uma página com as linhas mais recentes ou mais antigas. Assim, a consulta lê apenas
os minutos que compõem essa página, com ou sem condições de igualdade nos campos de agrupamento.

A janela de tempo pode ser de um, cinco ou dez minutos. O padrão é um minuto. Janelas maiores permitem ignorar mais páginas,
mas uma consulta em um intervalo curto lê por inteiro as janelas que se sobrepõem ao intervalo.

O agrupamento difere de [Particionar por campo](#particionar-por-campo): o particionamento grava cada shard em seus próprios
arquivos. Assim, a consulta lê menos arquivos, mas o fluxo tem mais arquivos, de tamanho menor. O agrupamento mantém os arquivos
e ordena as linhas dentro deles. Combine os dois recursos se necessário.

A configuração vale para os dados gravados após a alteração. Os arquivos existentes mantêm a ordem original de
gravação, e o compactador só mescla arquivos com o mesmo agrupamento. Use apenas campos de
texto, `int64` ou `bool` sem criptografia e, se usar dois, escolha campos diferentes.

### Campos criptografados

Ao criar o fluxo, marque um campo como `encrypted` para que o MoleSignal o criptografe antes de gravá-lo no Parquet. A coluna armazena o texto cifrado, e uma consulta comum retorna esse texto. Para ler o valor original, use `decrypt(field)` em SQL:

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

Não é possível alterar o sinalizador depois, pois os dados existentes ficariam ilegíveis. O MoleSignal deriva a chave da chave de criptografia da organização e da chave raiz de criptografia `MS_CIPHER_KEY`. A perda da chave raiz torna os campos criptografados irrecuperáveis. Consulte [Segurança e multilocação](/pt-BR/security#criptografia-no-nível-de-campo).

## Retenção e exclusão

A retenção define quando o compactador remove os dados. Na guia **Retenção**, preencha o campo
**Retenção de dados (dias)** ou deixe-o em branco para usar o padrão da plataforma, de 30 dias, definido em
[Configurações → Retenção de dados](/pt-BR/settings/platform#retenção-de-dados) na organização `_sys`. A próxima limpeza exclui os dados
que ultrapassarem o prazo de retenção. Ao reduzir o prazo, a limpeza exclui os dados que passarem a ficar
fora dele, e não é possível recuperar os arquivos excluídos. Se uma métrica de um fluxo de métricas não receber
amostras durante o período de retenção, ela também sai da lista de métricas.

Na guia **Retenção** de um fluxo de métricas, **Reduzir a resolução de amostras antigas** agrupa as amostras de cada
métrica do fluxo com mais de um determinado número de dias em intervalos de 1 minuto a 1 dia. As amostras de uma série em cada intervalo
viram um único ponto: o compactador calcula a média dos valores, soma as contagens delta e exclui as amostras originais.
Assim, as consultas em períodos longos leem muito menos dados, e os dados mais antigos mantêm apenas a resolução do intervalo.
Não é possível recuperar as amostras originais.

Para logs e traces, a opção **Mesclar arquivos pequenos por dia** (ativada por padrão) reúne os arquivos
de um dia em um só, uma hora após o fim do dia, se o tamanho total não ultrapassar o valor de
`[compactor].target_size` do compactador. Assim, uma consulta que abrange vários dias abre muito menos arquivos.
A retenção passa a valer por dia: o compactador exclui um arquivo mesclado quando expira a retenção do dia inteiro. Desative a opção
na guia **Configurações** do fluxo para manter os arquivos por hora.

**Excluir fluxo** remove o fluxo e a configuração dele. Não é possível desfazer a exclusão. Ela pode afetar
dashboards, visualizações salvas, alertas, relatórios e pipelines. Confira primeiro a guia **Uso**.

## Tarefas de busca

Uma tarefa de busca é uma consulta que roda em segundo plano e mantém o resultado até expirar.
Há três origens para essas tarefas:

- uma consulta enviada com `Prefer: respond-async` ou cujo resultado previsto é grande demais para
  uma solicitação interativa;
- o preenchimento retroativo de um pipeline;
- uma consulta enviada pelo Mole Agent.

Selecione **Tarefas de busca** no cabeçalho de **Fluxos** para abrir a lista. As visualizações no topo da
lista filtram por status e mostram a contagem de cada um: **Todos**, **Na fila**, **Em execução**, **Concluir**, **Falhou**
e **Cancelado**. Enquanto houver uma tarefa na fila ou em execução, a lista se atualiza automaticamente.

Cada linha mostra o tipo da tarefa (**Consulta** ou **Preenchimento retroativo**), a instrução, o status, o
intervalo consultado, o horário de envio, a duração, as linhas do resultado, a tentativa e a expiração. Cada
status da tarefa tem uma ação correspondente:

| Status | Ação |
|---|---|
| Na fila ou em execução | **Cancelar tarefa** |
| Concluir | **Baixar resultados** |
| Falhou ou cancelado | **Tentar novamente** |

**Excluir** remove a tarefa e o resultado, independentemente do status.

Cada membro pode ver e gerenciar as tarefas que enviou. Administradores com a permissão
`org.running_queries.cancel` podem ver e gerenciar todas as tarefas da organização. Consulte
[Consulta](/pt-BR/query#intervalos-de-tempo-e-tarefas-assíncronas) para saber mais sobre a API de tarefas.

## Uso de ingestão e orçamentos

Selecione **Uso de ingestão** no cabeçalho de **Fluxos** para ver quanto a plataforma ingeriu de cada origem nas
últimas 24 horas, nos últimos 7 dias ou nos últimos 30 dias. As três visualizações agrupam os mesmos valores de formas diferentes,
com totais iguais:

| Visualização | O que conta como origem |
|---|---|
| **Credencial** | Um token de API, um token de cliente RUM, um conector ou um usuário autenticado. **Interno da plataforma** corresponde à telemetria da própria plataforma. |
| **Fluxo** | Um fluxo, identificado pelo nome e pelo tipo. |
| **Serviço** | O serviço que o evento identifica em `service.name`, ou, na ausência desse campo, em `service` ou `service_name`. **Serviço sem nome** agrupa os eventos que não identificam nenhum serviço. |

A ingestão contabiliza os bytes descompactados dos dados aceitos. Eventos recusados não entram na contagem,
e uma solicitação reenviada conta uma única vez. Os spans entram na contagem ao chegar, antes da amostragem de cauda.
Os replays de sessão entram na linha `rum_replay` da visualização **Fluxo**. Quando uma solicitação inclui vários
serviços ou fluxos, a plataforma divide os bytes proporcionalmente ao número de eventos. Por isso, essas visualizações
mostram valores aproximados, não exatos.

Quando o valor é desconhecido, a página mostra `–`, não zero. O símbolo `≥` indica um valor mínimo, pois
a medição começou dentro do período selecionado. A linha acima da lista indica quando. Os valores aparecem na página
em cerca de um minuto. Se um nó parar de forma abrupta, pode perder as contagens dos últimos 15 segundos.

Selecione uma linha para ver o uso da origem hora a hora e como ele se distribui nas outras duas visualizações.

### Defina um orçamento

Selecione **Definir orçamento** em uma linha ou marque várias linhas e defina um único orçamento para todas.

| Campo | Significado |
|---|---|
| **Período** | **Diário** ou **Mensal**, conforme o calendário em UTC. |
| **Limitar** | De 1 MiB a 1 PiB. |
| **Avisar ao atingir (%)** | A plataforma envia uma notificação ao atingir essa porcentagem do limite e outra ao atingir o limite total. Com `0`, só notifica quando o limite se esgota. Padrão: 80. |
| **Quem recebe a notificação** | Membros da organização. Por padrão, o membro que define o orçamento. |

O orçamento serve apenas para notificar. Quando uma origem excede o limite, a ingestão continua respondendo e armazenando dados normalmente:
não descarta dados nem reduz a velocidade. A plataforma notifica uma vez por patamar em cada período. Se o limite aumentar,
a plataforma volta a notificar quando o uso atingir um patamar recalculado.

A plataforma envia notificações pelas políticas integradas **Orçamento de ingestão quase esgotado** e **Orçamento de
ingestão excedido** e as exibe na central de notificações da barra superior. Consulte
[Canais de notificação](/pt-BR/notification-channels) para alterar quem mais recebe essas notificações e por quais canais.

A organização `_sys` não tem orçamentos porque não tem políticas de notificação. Não é possível definir um orçamento para
**Interno da plataforma**, **Serviço sem nome** ou **Outros serviços**, categoria que reúne os serviços que ficam além do
limite definido em [Configurações da plataforma](/pt-BR/settings/platform#uso-de-ingestão).

## Permissões

| Permissão | O que permite |
|---|---|
| `intake_usage.read` | Abrir **Uso de ingestão**, que exibe os nomes dos tokens e dos membros. Proprietários e administradores têm essa permissão. |
| `intake_budgets.manage` | Definir e remover orçamentos. Proprietários e administradores têm essa permissão. |

| `streams.query` | Consultar dados dos fluxos com SQL. |

| `streams.create` | Criar um fluxo. |
| `streams.configure` | Alterar configurações relacionadas ao esquema e à retenção. |
| `streams.delete` | Excluir um fluxo. |
