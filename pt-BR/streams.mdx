Um fluxo é o contrato no escopo da organização usado pela ingestão, consulta, pipelines e retenção.
Abra **Fluxos** para ver o que chega e para inspecionar ou configurar cada fluxo.

## Tipos de fluxo

| Tipo | Conteúdo típico |
|---|---|
| `logs` | Eventos estruturados e logs de aplicação. |
| `metrics` | As amostras de métricas de uma origem, como um servidor Prometheus, diferenciadas por `metric_name`. |
| `traces` | Spans do OpenTelemetry. |
| `profiles` | Metadados de perfil vinculados a blobs pprof. |
| `extend` | Dados de referência gerenciados como tabelas de extensão e usados durante o processamento. |

O mesmo nome de fluxo pode existir para tipos de fluxo diferentes. Sempre inclua `stream_type` nas solicitações de API
e na automação.

### Fluxos da plataforma

O próprio MoleSignal grava estes fluxos:

| Fluxo | Conteúdo |
|---|---|
| `_molesignal` | A telemetria do próprio MoleSignal, na organização `_sys`. Ver [Auto-observabilidade](/pt-BR/self-observability). |
| `_synthetic_results` | Uma linha para cada execução de uma verificação sintética. Ver [Monitoramento sintético](/pt-BR/synthetics#fluxo-de-resultados-e-retenção). |
| `_audit` | Os eventos de auditoria do espaço de trabalho. Ver [Fluxo de auditoria](/pt-BR/settings/data-security#fluxo-de-auditoria). |
| `_agent_model_traces` | As chamadas de modelo do Mole Agent. Ver [Uso e orçamento](/pt-BR/agent#uso-e-orçamento). |
| `_agent_score_traces` | As pontuações de qualidade das respostas do Mole Agent. Ver [Qualidade](/pt-BR/quality#pontuações-em-um-stream). |

Eles são lidos como os demais fluxos. `_audit` exige `audit.read`: sem ele, o fluxo não aparece
na lista nem nas estatísticas de execução, e abrir, alterar ou excluir o fluxo responde `403`. Nada mais os grava: não é possível criar um fluxo com um destes nomes, a ingestão
em um deles responde `403`, e nenhum [pipeline](/pt-BR/pipelines#streams-de-plataforma) grava um.

## A lista de fluxos

**Fluxos** lista todos os fluxos do espaço de trabalho. Alterne entre as abas para mostrar **Todos** os fluxos ou um tipo,
pesquise por nome ou descrição e filtre por estado de execução. O cabeçalho conta os fluxos que recebem
normalmente e os que precisam de atenção, e soma os dados compactados gravados no período e o
armazenamento atual.

| Coluna | Mostra |
|---|---|
| **Status** | **Saudável**, **Com atraso**, **Interrompido**, **Sem tráfego**, **Sem uso** ou **Estatísticas indisponíveis**. Ver abaixo. |
| **Taxa de recebimento**, **Último recebimento** | Com que rapidez os dados chegam e quando chegaram pela última vez. |
| Dados compactados | Os bytes compactados gravados no período. |
| **Armazenamento atual**, **Retenção** | Os bytes armazenados agora e por quantos dias os dados são mantidos. |
| **Registros**, **Tamanho dos dados coletados**, **Tamanho dos dados armazenados**, **Tamanho dos índices** | Os registros mantidos, os bytes recebidos antes das transformações, os bytes dos arquivos de dados e os bytes dos índices. |

| Estado | Significado |
|---|---|
| **Saudável** | Os dados chegaram nos últimos 15 minutos. |
| **Com atraso** | Os últimos dados chegaram entre 15 minutos e 2 horas atrás. |
| **Interrompido** | Sem dados por mais de 2 horas. |
| **Sem tráfego** | O fluxo de rastreamentos do Mole Agent, que fica sem tráfego entre as respostas. |
| **Sem uso** | O fluxo nunca recebeu dados. |

Um fluxo marcado como **Não pode ser consultado** continua recebendo dados, mas fica oculto nos seletores de consulta. Cada linha tem
**Consulta** ou **Explorar**, **Ver detalhes** e **Copiar ID do fluxo**. O botão **Tarefas de busca** no cabeçalho abre
as [tarefas de busca](#tarefas-de-busca).

## Criar um fluxo

O MoleSignal cria um fluxo na primeira gravação nele, então a maioria dos fluxos surge automaticamente. Crie um
com antecedência para definir sua retenção, seus campos criptografados ou seu acesso de consulta desde o início. Selecione
**Criar fluxo**:

| Campo | Regra |
|---|---|
| **Nome do fluxo** | `snake_case`, até 64 caracteres. |
| **Descrição** | Opcional. O que trafega pelo fluxo. |
| **Tipo de sinal** | **Logs**, **Métricas** ou **Rastreamentos**. |
| **Retenção (dias)** | Por quanto tempo os dados são mantidos. |
| **Campos indexados** | Campos separados por vírgula que recebem um índice de texto completo. |
| **Campos criptografados** | Campos separados por vírgula que são criptografados antes de serem armazenados. Isso não pode ser alterado depois. Ver [Campos criptografados](#campos-criptografados). |
| **Consultável** | Desative a opção para um fluxo de origem que apenas alimenta um pipeline de roteamento. |

## Detalhes do fluxo

Selecione um fluxo para abri-lo. **Consultar dados** abre o fluxo em seu explorador, e o menu tem
**Copiar ID do fluxo** e **Excluir fluxo**. As abas:

| Aba | Conteúdo |
|---|---|
| **Visão geral** | O estado de execução, os primeiros dados recebidos, o acesso de consulta e a tendência de linhas gravadas e dados compactados ao longo de 24 horas. Um fluxo sem dados oferece **Configurar fonte de dados** e **Enviar dados de teste**. |
| **Campos e índices** | Os campos com seu tipo, tipo de índice e criptografia. Edite um campo para alterar seu índice ou seu mascaramento. Ver [Esquema e campos](#esquema-e-campos). |
| **Retenção** | A retenção do fluxo e o downsampling de um fluxo de métricas. Ver [Retenção e exclusão](#retenção-e-exclusão). |
| **Uso** | O que depende do fluxo: o endpoint de ingestão que o grava, pipelines, consultas salvas e regras de alerta. Verifique antes de uma alteração ou exclusão. |
| **Configurações** | A **Descrição**, o **Consultável**, o **Intervalo máximo de consulta (horas)**, **Mesclar arquivos pequenos por dia**, **Particionar por campo** e, para logs, **Agrupar por campo**. |

As alterações nas abas são reunidas em um rascunho. **Salvar e aplicar** as aplica de uma vez, e
**Descartar alterações** as descarta. Antes de salvar, a página avisa sobre alterações que não podem ser desfeitas:
uma retenção menor exclui dados expirados, e o downsampling exclui as amostras originais.

**Intervalo máximo de consulta** limita quantas horas uma consulta SQL ou PromQL do fluxo pode abranger. Uma consulta sobre
um intervalo maior é rejeitada, então um "últimos 90 dias" por engano não pode varrer um fluxo grande de ponta a ponta. Vazio
ou `0` significa sem limite.

Desative **Consultável** quando uma origem que recebe tudo deve continuar recebendo, mas não deve aparecer nos
seletores de consulta. Um pipeline de roteamento ainda pode ler o fluxo. Gerencie os dados `extend` por meio de
**Tabelas de extensão**, e não pelo caminho genérico de consulta de telemetria.

## Esquema e campos

Um campo tem um nome, um tipo de dados, um sinalizador `nullable`, um tipo de índice e um sinalizador `encrypted`. Os tipos de dados são `bool`, `int64`, `float64`, `utf8`, `timestamp` e `json`. Um novo campo é adicionado ao esquema quando aparece pela primeira vez nos dados recebidos, e um valor de outro tipo é rejeitado com `type mismatch on field`. Números são a exceção: um campo `int64` que recebe um número com parte fracionária, ou um inteiro acima do intervalo de `int64`, passa a `float64`, no mesmo lote ou em um lote posterior, e os valores armazenados antes são lidos como `float64`.

O tipo de índice decide qual estrutura auxiliar o MoleSignal cria para um campo:

| Tipo de índice | Efeito |
|---|---|
| `none` | Nenhum índice auxiliar. Este é o padrão. |
| `exact` | Um índice invertido de correspondência exata de valores completos (um filtro de Bloom do Parquet para campos que não são de texto), além do mínimo e do máximo de cada arquivo. `=` e `IN` ignoram os arquivos sem os valores antes de abri-los e leem apenas as páginas das linhas correspondentes quando há poucas. Um `LIKE` ou `ILIKE` em um campo com até 65.536 valores por arquivo ignora os arquivos em que nenhum valor contém o texto. Use-o para identificadores como `trace_id`. |
| `full_text` | Um índice invertido com tokenização para pesquisa de texto: sequências de letras e dígitos são palavras, e o texto CJK é dividido em bigramas sobrepostos de dois caracteres. Literais de `MATCH`, `MATCH_TEXT`, `LIKE` e `ILIKE`, incluindo pontuação e texto CJK, ignoram os arquivos que não podem corresponder. Apenas campos `utf8`. |
| `bloom` | Um filtro de Bloom do Parquet, além de um filtro de valores completos por arquivo para campos de texto e `int64` e do mínimo e do máximo de cada arquivo: `=` e `IN` ignoram os arquivos que certamente não têm os valores antes de abri-los. Use-o para campos com muitos valores consultados apenas por igualdade, como IDs de requisição. |
| `skip` | O mínimo e o máximo de cada arquivo, e todos os valores de um arquivo que tenha no máximo 32 valores distintos. Comparações, `IN`, `BETWEEN` e `LIKE` com prefixo ignoram arquivos com eles. |
| `ngram` | Os trigramas dos valores de cada arquivo, e os fragmentos de cinco bytes de cada bloco de 1.024 linhas nele, independentemente de maiúsculas e minúsculas: um literal de `LIKE`, `ILIKE` ou `MATCH` com um trigrama que um arquivo não tem ignora esse arquivo, e um com um fragmento que um bloco não tem ignora esse bloco, então uma pesquisa por um ID ou outra string rara lê apenas os poucos blocos que podem contê-lo. Um literal com menos de cinco bytes lê todos os blocos. Um fluxo com um campo `ngram` grava seus arquivos em páginas de 1.024 linhas. As páginas pequenas e os fragmentos ocupam espaço: o armazenamento cresceu cerca de 14% em um teste em que esse campo ocupava dois terços de cada linha. Use-o para URLs, caminhos e nomes de host pesquisados por fragmento, não para texto livre longo. Apenas campos `utf8`. |
| `ip` | O intervalo dos endereços de cada arquivo, com IPv4 mapeado em IPv6: `CIDR_MATCH(field, '10.0.0.0/8')` e `=` em um endereço ignoram arquivos com ele. Apenas campos `utf8`. |
| `key_value` | As chaves de primeiro nível de um objeto JSON e seus valores: `json_text(field, 'key') = 'value'`, `IN` e `IS NOT NULL` ignoram os arquivos sem a chave ou o valor e leem apenas as páginas das linhas correspondentes quando há poucas. Um valor é comparado conforme `json_text` o retorna: texto como está, números e booleanos como seu JSON. Apenas campos `json`. |
| `range` | Os números de cada linha, no índice, e o mínimo e o máximo de cada arquivo. Um `count(*)` cujas condições sejam `=` em campos `exact`, `>`, `>=`, `<` ou `<=` com um número em campos `range`, além do intervalo de tempo, é respondido a partir do índice sem ler os arquivos; outras comparações ignoram os arquivos fora do intervalo. Apenas campos `int64`, `float64` e `timestamp`. |

Todo campo indexado também registra, para cada arquivo, quantas de suas linhas deixam o campo vazio. `IS NULL` ignora os arquivos em que o campo sempre tem um valor, e qualquer outra condição no campo, incluindo as que perguntam se ele tem um valor, como `IS NOT NULL` e `!= ''`, ignora os arquivos em que ele nunca tem um.

Condições unidas com `OR` também ignoram um arquivo quando todos os ramos são descartados nele, cada ramo pelo índice que o responde: `level = 'error' OR status >= 500` ignora um arquivo cujo índice `level` não tem `error` e cujo `status` nunca chega a 500.

Um campo que aparece pela primeira vez nos dados recebidos obtém seu tipo de índice a partir do nome:

| Tipo de fluxo | Campos | Tipo de índice |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`, `level`, `session_id`, `fingerprint`, `country`, `browser`, `application`, `environment` e os campos OpenTelemetry `host.id`, `container.id`, `event.name`, `event.domain`, `severity_text` | `exact` |
| `traces` | `trace_id`, `span_id`, `parent_span_id`, `service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

Todo outro campo novo recebe `none`, a menos que as regras do próprio fluxo digam o contrário: consulte [Índice de novos campos](#índice-de-novos-campos). Um `level` exato permite que o histograma de logs conte erros a partir do índice em vez de ler os arquivos. Fluxos de RUM indexam as chaves de `context`, `feature_flags` e `usr.extra` com `key_value`.

Um tipo de índice alterado se aplica imediatamente aos dados gravados depois. Os dados gravados antes são indexados novamente em segundo plano com as novas configurações: cada partição selada (selada 48 horas após o término, por padrão) é reconstruída a partir de seus arquivos, e os arquivos mais novos são reconstruídos quando são selados ou mesclados. Até lá, um arquivo mantém o índice com que foi gravado, que nunca altera os resultados da consulta, apenas quantos arquivos uma consulta lê. **Cobertura de campos indexados** na **Visão geral** mostra quantos arquivos restam. Quando o formato do índice de texto completo muda, como quando o texto CJK passou a ser dividido em bigramas, os índices de arquivos mais antigos são reconstruídos no novo formato em segundo plano da mesma forma.

Para alterar um campo, abra **Campos e índices**, selecione a ação de edição do campo e escolha:

- o **Tipo de índice**: **Não indexado**, **Pesquisa de texto completo**, **Correspondência exata**, **Filtro de Bloom**,
  **Índice de salto**, **Substring de n-gramas**, **Endereço IP** ou **Chaves JSON**. Pesquisa de texto completo, substring de n-gramas
  e endereço IP se aplicam a campos de texto, e chaves JSON, a campos JSON;
- a **Política por fluxo** de **Mascaramento de campos nos resultados**: **Herdar regra global**, **Regra personalizada do fluxo**,
  ou **Sem mascaramento explícito no fluxo**. Consulte [Mascaramento de campos](/pt-BR/settings/data-security#mascaramento-de-campos).
  Fluxos de métricas não participam do mascaramento.

Selecione **Aplicar ao rascunho** e depois **Salvar e aplicar**. O tipo de um campo nunca muda.

### Índice de novos campos

Em **Índices de campos**, na aba **Configurações**, regras atribuem aos campos que aparecem pela primeira vez no fluxo
um índice pelo nome. Selecione **Adicionar regra**, insira um padrão de nome de campo e escolha um tipo de índice:
`*` representa qualquer sequência de texto e `?`, um caractere, então `*_id` corresponde a `user_id` e
`order_id`, e `http.*` corresponde a todo campo sob `http`. A primeira regra, em ordem, cujo padrão
corresponde ao nome e cujo tipo de índice é adequado ao tipo de dados do campo se aplica; um índice definido para um campo
pelo nome em **Campos e índices** vem primeiro, e um campo a que nenhuma regra corresponde recebe o padrão acima.
As regras afetam apenas campos que aparecem a partir de agora: altere campos existentes em **Campos e
índices**. Um fluxo contém no máximo 32 regras.

### Particionar por campo

Um fluxo de logs ou traces pode ser particionado por um ou dois campos de texto: em **Particionar por campo** na
aba **Configurações**, selecione **Adicionar um campo**, escolha o campo e escolha como ele particiona. Os dados gravados
depois são divididos em shards pelos valores dos campos, e cada shard é gravado em seus próprios arquivos.

- **Hash** divide os valores em 2 a 64 shards pelo hash deles, de forma uniforme. Uma consulta com uma condição de igualdade
  no campo (`=` ou `IN`) lê apenas os arquivos dos shards dos valores.
- **Primeiro caractere** divide os valores em 37 shards pelo primeiro caractere: um para cada dígito e
  cada letra (maiúscula ou minúscula), e um para todo o resto, incluindo valores vazios. Uma consulta com uma
  condição de igualdade no campo, ou um `LIKE` que começa com texto (como `'web-%'`), lê apenas
  os arquivos do shard desse caractere; um `ILIKE` também lê o shard de todo o resto. Quão uniformes
  os shards são depende dos dados: IDs de trace hexadecimais usam apenas 16 deles.

Com dois campos, os arquivos são divididos pelos shards de ambos, então as contagens de shards se multiplicam. **Particionar por
campo** mostra o total, no máximo 256: primeiro caractere (37 shards) combina com um hash de no máximo 4
shards. Uma consulta com uma condição em qualquer um dos campos lê menos arquivos, e uma com condições em ambos
menos ainda. Use campos de particionamento que quase toda consulta nomeia, como serviço, namespace ou tenant.
Mais shards significam mais arquivos, menores.

A configuração se aplica aos dados gravados após a alteração: os arquivos existentes permanecem como estão, uma consulta avalia
cada arquivo pelos campos com que foi gravado, e o compactador mescla apenas arquivos gravados com os
mesmos campos. Um campo de particionamento deve ser um campo de texto não criptografado, e os dois campos devem ser diferentes.

### Agrupar por campo

Um fluxo de logs pode agrupar as linhas dentro de seus arquivos por um ou dois campos: em **Agrupar por campo**
na aba **Configurações**, selecione **Adicionar um campo**, escolha o campo e escolha a **Janela de tempo**. Em cada
arquivo gravado depois, as linhas ficam em janelas de tempo dessa largura, mais recentes primeiro, e dentro de uma janela pelos
valores dos campos e, em seguida, mais recentes primeiro.

Em ordem temporal, um valor como um serviço aparece em todas as páginas de um arquivo. Agrupado, cada janela
o mantém em poucas páginas, então uma consulta com uma condição de igualdade em um campo de agrupamento (`=` ou `IN`)
lê apenas essas páginas. Use campos que as consultas costumam nomear e que assumem poucos valores, como
serviço ou nível.

Cada arquivo agrupado também mantém quantas de suas linhas caem em cada minuto com cada combinação dos
valores dos campos de agrupamento. Uma contagem com condições de igualdade em campos de agrupamento de texto, uma contagem
agrupada por um deles (`GROUP BY service`) e um histograma cujas barras são minutos inteiros são respondidos
a partir desses números sem ler o arquivo, inclusive quando a janela da consulta começa ou termina em um minuto
inteiro dentro dele. Um arquivo cujos minutos e valores formam mais de 65.536 combinações não mantém nenhuma.
Os mesmos números indicam onde fica uma página das linhas mais recentes ou mais antigas, então essa página, com ou
sem condições de igualdade nos campos de agrupamento, lê apenas os minutos de onde ela vem.

A janela de tempo é de um, cinco ou dez minutos; um minuto é o padrão. Janelas mais amplas ignoram mais páginas,
mas uma consulta em uma janela de tempo curta lê inteiras as janelas que toca.

O agrupamento difere de [Particionar por campo](#particionar-por-campo): um particionamento grava cada shard em seus próprios
arquivos, então uma consulta lê menos arquivos, mas o fluxo tem mais arquivos, menores; o agrupamento mantém os arquivos
e ordena as linhas dentro deles. Os dois podem ser combinados.

A configuração se aplica aos dados gravados após a alteração: os arquivos existentes mantêm a ordem em que foram
gravados, e o compactador mescla apenas arquivos agrupados de forma semelhante. Um campo de agrupamento deve ser um
campo de texto não criptografado, `int64` ou `bool`, e os dois campos devem ser diferentes.

### Campos criptografados

Marque um campo como `encrypted` ao criar o fluxo para criptografá-lo antes de ser gravado no Parquet. A coluna armazenada contém texto cifrado, e uma consulta simples retorna o texto cifrado. Leia o valor de volta com `decrypt(field)` em SQL:

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

O sinalizador não pode ser alterado depois, porque os dados existentes se tornariam ilegíveis. A chave vem da chave de criptografia da organização e da chave raiz de criptografia `MS_CIPHER_KEY`. Perder a chave raiz torna os campos criptografados irrecuperáveis. Consulte [Segurança e multilocação](/pt-BR/security#criptografia-no-nível-de-campo).

## Retenção e exclusão

A retenção controla quando o compactador remove dados. Defina o valor na aba **Retenção** em
**Retenção de dados (dias)** ou deixe o campo vazio para usar o padrão da plataforma, 30 dias, definido em
[Configurações → Retenção de dados](/pt-BR/settings/platform#retenção-de-dados) da organização `_sys`. Os dados
mais antigos que a retenção são excluídos na próxima limpeza, então encurtar a retenção exclui os dados
que ficam para além dela, e arquivos excluídos nunca voltam. Uma métrica de um fluxo de métricas que não foi
vista dentro da retenção também sai da lista de métricas.

Na aba **Retenção** de um fluxo de métricas, **Reduzir a resolução de amostras antigas** agrega as amostras de cada
métrica do fluxo mais antigas que um número de dias em intervalos de tempo de 1 minuto a 1 dia: as amostras de uma série em um intervalo
se tornam um ponto, com valores calculados pela média e contagens delta somadas, e as amostras originais são excluídas.
Consultas em intervalos longos passam a ler muito menos, e os dados mais antigos mantêm apenas a resolução do intervalo. As
amostras originais não podem ser recuperadas.

Para logs e traces, a configuração de fluxo **Mesclar arquivos pequenos por dia** (ativada por padrão) mescla os arquivos
de um dia concluído em um único arquivo uma hora após o fim do dia, quando juntos não passam do
`[compactor].target_size` do compactador. Uma consulta em muitos dias passa a abrir muito menos arquivos. A retenção
então se aplica por dia: um arquivo mesclado é excluído quando o dia inteiro expira. Desative a configuração
na aba **Configurações** do fluxo para manter arquivos por hora.

**Excluir fluxo** exclui o fluxo e sua configuração, e não pode ser desfeita. Isso pode quebrar
dashboards, visualizações salvas, alertas, relatórios e pipelines: verifique a aba **Uso** antes.

## Tarefas de busca

Uma tarefa de busca é uma consulta que roda em segundo plano e mantém o resultado até a tarefa expirar.
As tarefas vêm de três origens:

- uma consulta enviada com `Prefer: respond-async`, ou uma consulta cujo resultado deve ser grande demais para
  uma requisição interativa;
- o preenchimento retroativo de um pipeline;
- uma consulta enviada pelo Mole Agent.

Selecione **Tarefas de busca** no cabeçalho de **Fluxos** para abrir a lista. As visões no topo da
lista filtram por estado, cada uma com sua contagem: **Todos**, **Na fila**, **Em execução**, **Concluir**, **Falhou**,
e **Cancelado**. Enquanto uma tarefa está na fila ou em execução, a lista é atualizada sozinha.

Cada linha mostra o tipo da tarefa (**Consulta** ou **Preenchimento retroativo**), o comando, o estado, o
intervalo consultado, o horário de envio, a duração, as linhas do resultado, a tentativa e a expiração. Uma
ação corresponde ao estado da tarefa:

| Estado | Ação |
|---|---|
| Na fila ou em execução | **Cancelar tarefa** |
| Concluir | **Baixar resultados** |
| Falhou ou cancelado | **Tentar novamente** |

**Excluir** remove uma tarefa com seu resultado em qualquer estado.

Um membro vê e gerencia as tarefas que enviou. Um administrador com
`org.running_queries.cancel` vê e gerencia todas as tarefas da organização. Consulte
[Consulta](/pt-BR/query#intervalos-de-tempo-e-tarefas-assíncronas) para a API de tarefas.

## Uso de ingestão e orçamentos

Selecione **Uso de ingestão** no cabeçalho de **Fluxos** para ver quanto dado cada origem ingeriu nas
últimas 24 horas, 7 dias ou 30 dias. Os mesmos números são divididos de três formas, para que seus
totais coincidam:

| Visão | Uma origem é |
|---|---|
| **Credencial** | Um Token de API, um token de cliente RUM, um conector ou um usuário autenticado. **Interno da plataforma** é a telemetria da própria plataforma. |
| **Fluxo** | Um fluxo, por seu nome e tipo. |
| **Serviço** | O serviço que um evento nomeia em `service.name`, ou então `service` ou `service_name`. **Serviço sem nome** reúne os eventos que não nomeiam nenhum. |

A ingestão conta os bytes descomprimidos da requisição do que foi aceito: um evento recusado não é contado,
e uma requisição que o remetente repete conta uma vez. Spans contam quando chegam, antes da amostragem em cauda.
Reproduções de sessão contam na linha `rum_replay` da visão **Fluxo**. Quando uma requisição contém vários
serviços ou fluxos, seus bytes são distribuídos pelo número de eventos, então essas visões são
números aproximados, não exatos.

Um número desconhecido mostra `–`, não zero. Um número marcado com `≥` é um limite inferior, porque
a medição começou dentro da janela; a linha acima da lista informa desde quando. Os números chegam à página
em cerca de um minuto. Um nó que para de repente pode perder os últimos 15 segundos de contagens.

Selecione uma linha para ver a origem hora a hora e do que ela é composta nas outras duas visões.

### Definir um orçamento

Selecione **Definir orçamento** em uma linha, ou marque linhas e defina um único orçamento para todas elas.

| Campo | Significado |
|---|---|
| **Período** | **Diário** ou **Mensal**, pelo calendário em UTC. |
| **Limitar** | De 1 MiB a 1 PiB. |
| **Avisar ao atingir (%)** | As pessoas são avisadas uma vez nessa proporção do limite e mais uma vez quando ele se esgota. `0` avisa apenas quando ele se esgota. Padrão: 80. |
| **Quem recebe a notificação** | Membros da organização. Padrão: a pessoa que define o orçamento. |

Um orçamento apenas avisa as pessoas: a ingestão responde e armazena do mesmo jeito quando uma origem o ultrapassa, e nada
é descartado ou desacelerado. Cada nível é avisado uma vez por período. Aumentar o limite faz com que um período posterior
volte a notificar.

As notificações passam pelas políticas de notificação integradas **Orçamento de ingestão quase esgotado** e **Orçamento de
ingestão excedido**, e aparecem na central de notificações da barra superior. Consulte
[Canais de notificação](/pt-BR/notification-channels) para alterar quem mais as recebe e como.

A organização `_sys` não tem orçamentos, porque não tem políticas de notificação. Não é possível definir orçamento em
**Interno da plataforma**, **Serviço sem nome** ou **Outros serviços**, que são os serviços além do
limite em [Configurações da plataforma](/pt-BR/settings/platform#uso-de-ingestão).

## Permissões

| Permissão | Capacidade |
|---|---|
| `intake_usage.read` | Abrir **Uso de ingestão**, que mostra os nomes de tokens e membros. Proprietários e administradores têm. |
| `intake_budgets.manage` | Definir e remover orçamentos. Proprietários e administradores têm. |
| `streams.read` | Listar fluxos e inspecionar metadados. |
| `streams.query` | Consultar dados de fluxos com SQL. |
| `query.jobs.read`, `query.jobs.run` | Abrir **Tarefas de busca**; enviar, cancelar, repetir e excluir tarefas. |
| `logs.write`, `metrics.write`, `traces.write`, `profiles.write` | Ingestão em um fluxo existente desse sinal. |
| `streams.create` | Criar um fluxo. |
| `streams.configure` | Alterar configurações voltadas ao esquema e a retenção. |
| `streams.delete` | Excluir um fluxo. |
