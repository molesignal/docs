Verifique o log do processo primeiro. Ele imprime a causa de uma falha de inicialização, e o corpo do erro HTTP de uma requisição rejeitada traz uma mensagem. O nível de log vem de `[telemetry].log_level` ou `RUST_LOG`.

## Inicialização

| Sintoma | Causa | Correção |
|---|---|---|
| `... password authentication failed for user` | O usuário ou a senha do DSN estão incorretos. | Corrija `[meta_database].dsn`. |
| `... pool timed out while waiting for an open connection` | O PostgreSQL está inacessível a partir do nó. | Verifique o host, a porta, o firewall e os requisitos de `sslmode`. |
| `startup_ping put: ... SignatureDoesNotMatch` | O armazenamento de objetos rejeita as credenciais. | Verifique `access_key` e `secret_key`. Defina os valores com `MS_OBJECT_STORE_ACCESS_KEY` e `MS_OBJECT_STORE_SECRET_KEY`. |
| `startup_ping put: ... NoSuchBucket` | O bucket não existe. | Crie o bucket ou corrija `[object_store].bucket`. |
| Linhas repetidas de `Encountered transport error`, seguidas de encerramento | O endpoint está inacessível, ou nenhuma credencial chega ao cliente. | Verifique `endpoint`, DNS e a rede. As credenciais devem vir de `access_key` e `secret_key`. |
| `unknown field: found ...` | Uma chave em uma seção estrita está escrita incorretamente ou não tem suporte. | Remova ou corrija a chave. Consulte [Configuração](/pt-BR/configuration#como-o-molesignal-carrega-a-configuração). |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN must be set when split-role self intake is enabled` | Um nó com separação de papéis sem o papel `intake` inicia sem o token compartilhado enquanto a captura de traces ou a autocoleta está ativada. | Defina o mesmo token em todos os nós. Desativar apenas `[telemetry.self_collect]` não basta, porque a captura de traces está ativada por padrão. |
| `open Probe CA key` | `MS_CIPHER_KEY` é diferente da chave que criptografou o banco de dados. | Restaure a chave original. Consulte [Lista de verificação de produção](/pt-BR/deployment/production-checklist). |
| `migration ... was previously applied but is missing in the resolved migrations` ou `... has been modified` | O binário e o banco de dados vêm de versões incompatíveis. | Execute a versão correspondente ou restaure um backup. Consulte [Atualização](/pt-BR/upgrade). |
| `address already in use` | Outro processo usa uma porta configurada. | Altere a porta. |
| `profiling.port and ... are both ...` | O listener pprof compartilha uma porta com outro listener. | Defina `[profiling].port` como uma porta que nenhum outro listener usa. |
| Uma configuração vinda de uma variável de ambiente não tem efeito | O nome da variável contém um ponto, um sublinhado duplo ou um erro de digitação. | Una o caminho com sublinhados simples, como em `MS_META_DATABASE_DSN`. |

## Login

| Sintoma | Causa | Correção |
|---|---|---|
| `admin@example.com` com `admin` é rejeitado | O banco de dados já tinha usuários, então a conta root não foi criada novamente, ou `root_email` e `root_password` estavam vazios. | Faça login com uma conta existente. Defina os dois valores e inicie com um banco de dados vazio para criar a conta root. |
| O e-mail de redefinição de senha nunca chega | SMTP ou `http.external_url` não está configurado. A requisição é aceita sem que nada seja enviado. | Defina `[notify.smtp].host` e `[http].external_url`. |
| Um script que faz login e envia `Authorization: Bearer` recebe `401` | O login define cookies de sessão para a interface web e não retorna token. O cabeçalho aceita apenas Tokens de API. | Emita um Token de API para o script. Consulte [Tokens de API](/pt-BR/identity/tokens). |
| A interface web pede login novamente todos os dias | Uma sessão de login termina após `[auth].session_ttl_secs` (24 horas). | Aumente `[auth].session_ttl_secs`. |

## Envio de dados

| Sintoma | Causa | Correção |
|---|---|---|
| `401` | O token está ausente ou é inválido, ou o cabeçalho contém um token de sessão de login. | Envie `Authorization: Bearer <token>` com um token de ingestão padrão ou um token de conta de serviço. |
| `403` | O token não tem a permissão de escrita do sinal, como `logs.write`, por exemplo, um token de cliente RUM enviado a um caminho de ingestão. | Use um token com a permissão de escrita do sinal. |
| `413` | O corpo da requisição excede o limite do endpoint: 16 MiB para ingestão JSON nativa, 2 MiB para as demais. | Envie lotes menores. Aumente o limite do proxy para pelo menos o limite do endpoint. |
| `400` de um endpoint OTLP sobre HTTP | O remetente compactou o corpo. | Defina `compression: none` no exportador do OpenTelemetry Collector. |
| `404` de um endpoint OTLP sobre HTTP | O endpoint do exportador omite o caminho base `/api`, então as requisições vão para `/v1/logs`. | Use `http://host:5080/api` como o endpoint OTLP. |
| `429` com `Retry-After` | Aplica-se o limite de taxa do papel `router` para a organização. | Diminua o ritmo ou aumente `[router.rate_limit]`. |
| A ingestão JSON nativa informa registros `rejected` | Um valor de campo não corresponde ao esquema do stream, por exemplo `type mismatch on field level: expected Utf8, got Number`. A resposta lista o motivo por índice. Números com parte fracionária em um campo `int64` não estão entre eles: o campo passa a ser `float64`. | Envie o tipo que o stream já armazena para o campo. |
| `400` com `event #1 must be a JSON object` | O array contém um elemento que não é um objeto JSON. A requisição inteira é rejeitada. | Envie um array de objetos. |
| O Promtail ou o Grafana Alloy não consegue enviar | O endpoint do Loki decodifica apenas JSON, e esses remetentes usam protobuf compactado com snappy. | Envie pelo OpenTelemetry Collector, Vector ou Fluent Bit. |
| Os registros são aceitos, mas não são encontrados | A consulta usa outro nome ou tipo de stream, ou um intervalo de tempo que os exclui. | Verifique o nome do stream e o tipo de sinal. Consulte a próxima seção para timestamps. |

## Dados ausentes ou anormais

- **Timestamps.** `_timestamp` conta microssegundos desde a época Unix. Um valor em segundos, milissegundos ou nanossegundos coloca os eventos no ano errado ou em um futuro distante, e consultas sobre o período recente não os retornam. Omita `_timestamp` para usar o horário de recebimento do servidor.
- **Intervalo de tempo.** Uma consulta que abrange um intervalo longo se torna um job assíncrono. Use um `timeRange` limitado para consultas interativas. Consulte [Consulta](/pt-BR/query#intervalos-de-tempo-e-tarefas-assíncronas).
- **Retenção.** Dados mais antigos que a retenção do stream, ou que o padrão da plataforma em **Configurações → Retenção de dados** para um stream sem retenção própria, são excluídos.
- **Tipo de stream.** Um stream é identificado por nome e tipo. `default` pode existir para logs, métricas e traces ao mesmo tempo.

## Consultas

| Sintoma | Causa | Correção |
|---|---|---|
| A resposta é `202` com um `jobId` e um caminho `monitor` | O tamanho estimado atinge `[querier].auto_async_threshold_rows`, então a consulta é executada como um job de busca assíncrono. Com os padrões, isso corresponde a um intervalo de cerca de 13,9 horas ou mais. | Solicite o caminho `monitor` até o job terminar e depois busque seus `/results`. Ou reduza o intervalo de tempo, ou envie `Prefer: respond-sync`. Consulte [Consulta](/pt-BR/query#intervalos-de-tempo-e-tarefas-assíncronas). |
| O cliente Flight SQL não consegue se conectar | `[flight_sql]` está desativado por padrão. | Defina `enabled = true`, exponha a porta `5083` e use um Token de API para autenticar. |

## Operações

| Sintoma | Causa | Correção |
|---|---|---|
| `GET /api/v1/healthz` retorna `503` | O armazenamento de objetos está inacessível. O corpo traz um `reason`. | Corrija a conexão com o armazenamento de objetos. |
| O diretório WAL cresce | Os flushes falham, geralmente porque o armazenamento de objetos está inacessível. | Corrija o armazenamento de objetos. O intake faz o flush do backlog em seguida. |
| O intake responde `429` com `intake buffer memory limit exceeded` | Os buffers do processo ocupam mais que `[intake].max_buffer_memory_size`, geralmente porque os flushes continuam falhando. | Encontre a causa nas linhas de log `intake flush failed` e corrija o armazenamento de objetos ou o banco de dados. As linhas que nunca poderão ser publicadas deixam de contar para o limite (veja as duas linhas seguintes). O intake JSON nativo envia `Retry-After` com esta resposta; tente novamente após esse intervalo. |
| O log mostra `dataset no longer exists; buffered rows discarded` | Um stream foi excluído, ou excluído e criado de novo, enquanto linhas dele ainda estavam no buffer. Essas linhas não têm para onde ir, então o intake as descarta e devolve a memória delas. O contador `intake_flush_errors_total` registra cada descarte sob a etapa `stream_gone` ou `dataset_gone`. | Nada a corrigir. Envie os dados novamente se forem importantes. |
| As gravações respondem `503` com `fenced by a newer writer epoch` | Outro processo publica o mesmo dataset com o mesmo `[node].id`. O processo bloqueado não consegue publicar seus dados, descarta as linhas que mantém em memória e recusa gravações nesse dataset. O WAL dele permanece no disco. O contador `intake_flush_errors_total` registra o bloqueio sob a etapa `writer_fenced`. | Dê a cada processo um `[node].id` exclusivo e reinicie o processo bloqueado. Veja [Implantação baseada em papéis](/pt-BR/deployment/role-based). |
| Relatórios agendados em PDF ou PNG falham | O Chrome está ausente, ou `[scheduled_reports.renderer].base_url` não alcança a interface web. | Use a imagem de release, que inclui o Chromium, e defina `base_url` com o endereço da interface web que o nó consegue alcançar. |
| Os snippets de onboarding mostram o host errado | `http.external_url` está vazio atrás de um proxy. | Defina `[http].external_url` com o endereço público e reinicie. |
| As consultas respondem `503` com `no querier node is available` | Nenhum nó com o papel `querier` tem heartbeat recente. | Inicie um nó `querier` e verifique se o `advertise_addr` dele é alcançável a partir do router. Veja [Implantação baseada em papéis](/pt-BR/deployment/role-based#participação-no-cluster). |
| As gravações pelo router respondem `503` com `no intake node is available` | Nenhum nó com o papel `intake` tem heartbeat recente. | Inicie um nó `intake` e verifique o `advertise_addr` dele. Veja [Implantação baseada em papéis](/pt-BR/deployment/role-based#participação-no-cluster). |
| As requisições respondem `503` com `no metadata database connection` | O nó esperou 10 segundos por uma conexão com o PostgreSQL e não obteve nenhuma: o PostgreSQL está sobrecarregado ou inacessível, ou todas as `[meta_database].max_connections` conexões estão em uso. | Repita a requisição. Se o problema continuar, verifique primeiro a carga e a acessibilidade do PostgreSQL. Se o PostgreSQL estiver ocioso, aumente `[meta_database].max_connections` conforme a carga, dentro do `max_connections` do PostgreSQL. |
| A porta gRPC do OTLP está inacessível a partir do host | O arquivo Compose não publica a porta `4317`. | Adicione um mapeamento `4317:4317`. |
