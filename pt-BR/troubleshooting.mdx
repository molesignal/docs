Verifique primeiro o log do processo. O log registra a causa de falhas na inicialização, e o corpo da resposta HTTP de erro inclui uma mensagem quando uma solicitação é rejeitada. `[telemetry].log_level` ou `RUST_LOG` define o nível de log.

## Inicialização

| Sintoma | Causa | Correção |
|---|---|---|
| `... password authentication failed for user` | O usuário ou a senha do DSN está incorreto. | Corrija `[meta_database].dsn`. |
| `... pool timed out while waiting for an open connection` | O nó não consegue acessar o PostgreSQL. | Verifique o host, a porta, o firewall e os requisitos de `sslmode`. |
| `startup_ping put: ... SignatureDoesNotMatch` | O armazenamento de objetos rejeita as credenciais. | Verifique `access_key` e `secret_key`. Defina esses valores com `MS_OBJECT_STORE_ACCESS_KEY` e `MS_OBJECT_STORE_SECRET_KEY`. |
| `startup_ping put: ... NoSuchBucket` | O bucket não existe. | Crie o bucket ou corrija `[object_store].bucket`. |
| O processo registra várias linhas com `Encountered transport error` e encerra | O cliente não consegue acessar o endpoint ou não recebe as credenciais. | Verifique `endpoint`, o DNS e a rede. Forneça as credenciais por meio de `access_key` e `secret_key`. |
| `unknown field: found ...` | Uma seção com validação estrita contém uma chave com erro de digitação ou sem suporte. | Remova ou corrija a chave. Consulte [Configuração](/pt-BR/configuration#como-o-molesignal-carrega-a-configuração). |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN must be set when split-role self intake is enabled` | Em uma implantação com funções separadas, um nó sem a função `intake` inicia sem o token compartilhado enquanto a captura de traces ou a coleta de telemetria interna está ativa. | Defina o mesmo token em todos os nós. Não basta desativar `[telemetry.self_collect]`, pois a captura de traces fica ativa por padrão. |
| `open Probe CA key` | `MS_CIPHER_KEY` difere da chave usada para criptografar o banco de dados. | Restaure a chave original. Consulte a [Lista de verificação para produção](/pt-BR/deployment/production-checklist). |
| `migration ... was previously applied but is missing in the resolved migrations` ou `... has been modified` | O binário e o banco de dados vêm de versões incompatíveis. | Execute a versão compatível ou restaure um backup. Consulte [Atualização](/pt-BR/upgrade). |
| `address already in use` | Outro processo usa uma das portas configuradas. | Altere a porta. |
| `profiling.port and ... are both ...` | O listener do pprof usa a mesma porta que outro listener. | Defina `[profiling].port` como uma porta que nenhum outro listener use. |
| Uma configuração feita por variável de ambiente não tem efeito | O nome da variável contém um ponto, um sublinhado duplo ou um erro de digitação. | Separe as partes do caminho com um único sublinhado, como em `MS_META_DATABASE_DSN`. |

## Login

| Sintoma | Causa | Correção |
|---|---|---|
| O login com `admin@example.com` e `admin` falha | O banco de dados já tinha usuários e o sistema não recriou a conta raiz, ou os valores de `root_email` e `root_password` estavam vazios. | Faça login com uma conta existente. Para criar a conta raiz, defina os dois valores e inicie o sistema com um banco de dados vazio. |
| O e-mail de redefinição de senha não chega | Falta configurar o SMTP ou `http.external_url`. O sistema aceita a solicitação sem enviar o e-mail. | Defina `[notify.smtp].host` e `[http].external_url`. |
| Um script faz login, envia `Authorization: Bearer` e recebe `401` | O login define cookies de sessão para a interface web e não retorna um token. O cabeçalho aceita apenas tokens de API. | Gere um token de API para o script. Consulte [Tokens de API](/pt-BR/identity/tokens). |
| A interface web solicita um novo login todos os dias | A sessão expira após o tempo definido em `[auth].session_ttl_secs` (24 horas). | Aumente `[auth].session_ttl_secs`. |

## Envio de dados

| Sintoma | Causa | Correção |
|---|---|---|
| `401` | O token está ausente ou é inválido, ou o cabeçalho contém um token de sessão de login. | Envie `Authorization: Bearer <token>` com um token padrão de ingestão ou um token de conta de serviço. |
| `403` | O token não tem a permissão de gravação exigida pelo sinal, como `logs.write`. Isso acontece, por exemplo, ao enviar um token de cliente RUM para um caminho de ingestão. | Use um token com a permissão de gravação do sinal. |
| `413` | O corpo da solicitação excede o limite do endpoint: 16 MiB para ingestão de JSON nativo e 2 MiB para os demais. | Envie lotes menores. Aumente o limite do proxy para que seja, no mínimo, igual ao do endpoint. |
| `400` de um endpoint OTLP via HTTP | O remetente compactou o corpo da solicitação. | Defina `compression: none` no exportador do OpenTelemetry Collector. |
| `404` de um endpoint OTLP via HTTP | O endpoint do exportador não inclui o caminho base `/api`, então as solicitações vão para `/v1/logs`. | Use `http://host:5080/api` como endpoint OTLP. |
| `429` com `Retry-After` | A organização atingiu o limite de taxa da função `router`. | Reduza a taxa de envio ou aumente `[router.rate_limit]`. |
| A ingestão de JSON nativo indica registros `rejected` | O valor de um campo não corresponde ao esquema do stream, como em `type mismatch on field level: expected Utf8, got Number`. A resposta lista o motivo por índice. | Envie o valor no tipo que o stream já armazena para o campo. |
| `400` com `event #1 must be a JSON object` | O array contém um elemento que não é um objeto JSON. O sistema rejeita toda a solicitação. | Envie um array de objetos. |
| Promtail ou Grafana Alloy não consegue enviar dados | O endpoint Loki decodifica apenas JSON, e essas ferramentas usam protobuf com compressão Snappy. | Envie os dados pelo OpenTelemetry Collector, Vector ou Fluent Bit. |
| A ingestão aceita os registros, mas a consulta não os encontra | A consulta usa outro nome ou tipo de stream, ou um intervalo de tempo que não inclui os registros. | Verifique o nome do stream e o tipo de sinal. Consulte a próxima seção para saber mais sobre carimbos de data e hora. |

## Dados ausentes ou inesperados

- **Carimbos de data e hora.** `_timestamp` conta os microssegundos desde a época Unix. Um valor em segundos, milissegundos ou nanossegundos coloca os eventos no ano errado ou em um futuro distante, e consultas de períodos recentes não retornam esses eventos. Omita `_timestamp` para usar o horário em que o servidor recebe os dados.
- **Intervalo de tempo.** Uma consulta que abrange um intervalo longo vira uma tarefa assíncrona. Use um `timeRange` delimitado para consultas interativas. Consulte [Consultas](/pt-BR/query#intervalos-de-tempo-e-tarefas-assíncronas).
- **Retenção.** O sistema exclui dados que excedem o período de retenção do stream. Se o stream não tiver um período próprio, vale o padrão da plataforma em **Configurações → Retenção de dados**.
- **Tipo de stream.** O nome e o tipo identificam um stream. `default` pode existir ao mesmo tempo para logs, métricas e traces.

## Consultas

| Sintoma | Causa | Correção |
|---|---|---|
| A resposta é `202` com um `jobId` e um caminho `monitor` | O número estimado de linhas atinge `[querier].auto_async_threshold_rows`, então a consulta roda como uma tarefa de busca assíncrona. Com as configurações padrão, isso corresponde a um intervalo de cerca de 13,9 horas ou mais. | Faça solicitações ao caminho `monitor` até a tarefa terminar e, em seguida, busque os resultados em `/results`. Como alternativa, reduza o intervalo de tempo ou envie `Prefer: respond-sync`. Consulte [Consultas](/pt-BR/query#intervalos-de-tempo-e-tarefas-assíncronas). |
| O cliente Flight SQL não consegue se conectar | `[flight_sql]` fica desativado por padrão. | Defina `enabled = true`, exponha a porta `5083` e autentique com um token de API. |

## Operações

| Sintoma | Causa | Solução |
|---|---|---|
| `GET /api/v1/healthz` retorna `503` | O armazenamento de objetos está inacessível. O corpo da resposta contém um `reason`. | Corrija a conexão com o armazenamento de objetos. |
| O diretório do WAL cresce | As operações de descarga do buffer falham, geralmente porque o armazenamento de objetos está inacessível. | Corrija o armazenamento de objetos. A ingestão descarrega os dados acumulados em seguida. |
| A ingestão retorna `429` com `intake buffer memory limit exceeded` | Os buffers do processo ocupam mais memória do que o limite definido em `[intake].max_buffer_memory_size`, geralmente porque as operações de descarga continuam falhando. | Identifique a causa nas linhas de log `intake flush failed` e corrija o armazenamento de objetos ou o banco de dados. As linhas que não podem ser publicadas deixam de contar para o limite (consulte as duas linhas seguintes). A ingestão de JSON nativo inclui `Retry-After` nessa resposta. Aguarde o intervalo indicado e tente novamente. |
| O log exibe `dataset no longer exists; buffered rows discarded` | Um fluxo foi excluído, ou excluído e recriado, enquanto ainda havia linhas dele no buffer. Como essas linhas não têm destino, a ingestão as descarta e libera a memória que ocupavam. O contador `intake_flush_errors_total` registra cada descarte na etapa `stream_gone` ou `dataset_gone`. | Nenhuma correção é necessária. Reenvie os dados se necessário. |
| As gravações retornam `503` com `fenced by a newer writer epoch` | Outro processo publica no mesmo conjunto de dados com o mesmo `[node].id`. O processo bloqueado não consegue publicar os dados, descarta as linhas que mantém na memória e recusa gravações nesse conjunto de dados. O WAL desse processo permanece no disco. O contador `intake_flush_errors_total` registra o bloqueio na etapa `writer_fenced`. | Atribua um `[node].id` exclusivo a cada processo e reinicie o processo bloqueado. Consulte [Implantação baseada em funções](/pt-BR/deployment/role-based). |
| Relatórios agendados em PDF ou PNG falham | O Chrome não está instalado ou o endereço em `[scheduled_reports.renderer].base_url` não permite acessar a interface web. | Use a imagem da versão publicada, que inclui o Chromium, e defina `base_url` com um endereço da interface web que o nó consiga acessar. |
| Os trechos de código da configuração inicial mostram o host incorreto | `http.external_url` está vazio em uma instalação atrás de um proxy. | Defina `[http].external_url` com o endereço público e reinicie. |
| As consultas retornam `503` com `no querier node is available` | Nenhum nó com a função `querier` enviou um sinal de atividade recente. | Inicie um nó `querier` e verifique se o roteador consegue acessar o `advertise_addr` desse nó. Consulte [Implantação baseada em funções](/pt-BR/deployment/role-based#participação-no-cluster). |
| As gravações via roteador retornam `503` com `no intake node is available` | Nenhum nó com a função `intake` enviou um sinal de atividade recente. | Inicie um nó `intake` e verifique o `advertise_addr` desse nó. Consulte [Implantação baseada em funções](/pt-BR/deployment/role-based#participação-no-cluster). |
| As solicitações retornam `503` com `no metadata database connection` | O nó aguardou 10 segundos por uma conexão com o PostgreSQL e não conseguiu obtê-la: o PostgreSQL está sobrecarregado ou inacessível, ou todas as conexões permitidas por `[meta_database].max_connections` estão em uso. | Repita a solicitação. Se o problema persistir, verifique primeiro a carga e a conectividade do PostgreSQL. Se o PostgreSQL estiver ocioso, aumente `[meta_database].max_connections` de acordo com a carga, respeitando o limite de `max_connections` do PostgreSQL. |
| O host não consegue acessar a porta OTLP gRPC | O arquivo Compose não publica a porta `4317`. | Adicione o mapeamento `4317:4317`. |
