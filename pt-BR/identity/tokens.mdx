Um token de API permite que um programa faça chamadas ao MoleSignal sem iniciar sessão. O token não tem função própria:
ele atua como um membro ou uma conta de serviço, e o escopo pode restringir suas ações. Uma conta de serviço é
uma identidade para um programa: ela tem uma função, não pode iniciar sessão e seus tokens atuam em nome da conta.

## Tipos de token

| Tipo | Atua como | Onde emitir |
|---|---|---|
| **Token de API pessoal** | O membro que emitiu o token. | **Configurações da conta → Tokens de API** |
| **Token de API de conta de serviço** | Uma conta de serviço. | **Identidade e acesso → Tokens de API** ou **Contas de serviço** |
| **Token padrão de ingestão** | O titular do token, com acesso limitado à gravação de dados. | **Fonte de dados**. Consulte [Tokens de ingestão](/pt-BR/intake#tokens-de-ingestão). |
| **Token de cliente RUM** | O aplicativo RUM associado, com acesso limitado à gravação de dados de RUM. | **Fonte de dados**. Consulte [Tokens de ingestão](/pt-BR/intake#tokens-de-ingestão). |

Todo token segue o formato `mspat-<36>`, com letras minúsculas e dígitos. Os primeiros 10 caracteres identificam
o token, e o sistema armazena apenas um hash dos demais. Envie o token como credencial Bearer:

```http
Authorization: Bearer mspat-…
```

Nenhum token pode acessar a organização `_sys`.

## O que um token pode fazer

Um token nunca tem mais permissões do que o membro ou a conta de serviço tem no momento da solicitação. O
escopo restringe ainda mais essas permissões:

| Escopo | O que o token pode fazer |
|---|---|
| **Mesmo escopo que o meu**, **Mesmo escopo que o da conta de serviço** | Executar as ações permitidas ao membro ou à conta de serviço, acompanhando as mudanças de acesso. |
| **Política de permissões** | Usar as permissões de uma [política de permissões](/pt-BR/identity/roles#políticas-de-permissão), como **Ingestão de dados**, acompanhando as mudanças na política. |
| **Personalizado** | Usar as permissões selecionadas na emissão. Essas permissões nunca mudam. |

Um token não pode receber uma permissão que a entidade emissora não tem. Quando um membro perde uma permissão, todos
os tokens desse membro também a perdem. Quando o membro sai do espaço de trabalho ou fica inativo, os tokens
deixam de funcionar. Uma função em um único recurso, atribuída por concessão de acesso ou compartilhamento, só se aplica ao token
dentro do escopo. Um token de cliente RUM pertence ao aplicativo associado: grava dados de RUM e não acessa
nenhum outro recurso.

## Emitir um token pessoal

1. Abra **Configurações da conta → Tokens de API** e selecione **Novo token**.
2. Insira um **Nome**, por exemplo, `collector-production`.
3. Escolha o **Escopo**: **Mesmo escopo que o meu**, uma **Política de permissões** ou **Personalizado** para selecionar permissões específicas.
   Só é possível escolher políticas ou permissões disponíveis na conta. Ao selecionar uma política, confira a lista de
   permissões que ela inclui.
4. Defina o **Prazo de expiração (dias)**: 365 por padrão e 1825 no máximo. Deixe o campo em branco para que o token nunca
   expire.
5. Selecione **Criar token** e depois **Copiar token**. O MoleSignal exibe o token apenas uma vez.

A lista mostra os tokens da conta com escopo, tipo, prazo de expiração e último uso. A opção **Revogar** invalida o token de forma
imediata e definitiva. Para gerenciar os próprios tokens, é necessário ter `personal_tokens.manage`, uma permissão que todas as funções
integradas incluem. Emita tokens pessoais em uma sessão autenticada: um token não pode emitir outro.

## Tokens da organização

**Identidade e acesso → Tokens de API** lista todos os tokens do espaço de trabalho, com o membro, a conta de
serviço ou o aplicativo em nome do qual cada token atua, além do escopo. Para listar os tokens, é necessário ter `api_tokens.read`. Com
`api_tokens.revoke`, é possível revogar qualquer token e selecionar **Emitir token de conta de serviço** para emitir um
token para uma conta de serviço: escolha a **Conta de serviço**, o **Escopo** e o prazo de expiração.

## Contas de serviço

Use uma conta de serviço para um coletor, um pipeline de CI, uma integração ou um agente de IA que funcione
sem intervenção humana. Assim, a saída de um membro do espaço de trabalho não interrompe a automação.

1. Abra **Contas de serviço** e selecione **Criar conta de serviço**.
2. Insira um **Nome**, por exemplo, `deployment-automation`, e uma **Descrição**. Selecione uma **Função**.
3. Selecione **Criar conta e token** e copie o token de API inicial. Ele recebe as permissões
   da função no momento da criação e expira em 365 dias. O MoleSignal exibe o token apenas uma vez.

Selecione uma conta para gerenciá-la:

| Ação | Efeito |
|---|---|
| **Salvar alterações** | Salva o novo nome, a nova descrição ou a nova função. Se a nova função remover uma permissão, todos os tokens da conta a perdem imediatamente. Se adicionar uma permissão, apenas os tokens emitidos a partir desse momento a recebem. |
| **Gerenciar tokens de API** | Abre **Tokens de API** com um filtro para a conta, permitindo emitir mais tokens ou revogar um token. |
| **Desativar** / **Ativar** | A conta desativada e todos os seus tokens deixam de autenticar até que a conta volte a ficar ativa. |
| **Excluir** | Remove a conta e revoga todos os seus tokens. Não é possível desfazer essa ação. |

O **ID da entidade** identifica a conta nos registros de auditoria e nas concessões de acesso. Consultar contas de
serviço exige `service_accounts.read`, e alterá-las exige `service_accounts.manage`.

## Escolher um token

| Origem da chamada | Token recomendado |
|---|---|
| Coletor ou agente que envia telemetria | Um token de conta de serviço que segue a política **Ingestão de dados** ou o token padrão de ingestão. |
| Código no navegador ou no dispositivo móvel que envia dados de RUM | O token de cliente RUM do aplicativo. O token fica visível para os usuários finais. |
| CI que registra implantações | Um token que segue a política **Ingestão de dados**, que também inclui `apm.deploy`. |
| Automação que lê dados ou altera recursos | Um token de conta de serviço com escopo restrito por uma política ou por permissões personalizadas. |
| Cliente MCP ou script de execução manual | Um token de API pessoal com prazo de expiração. |

Uma sessão autenticada usa cookies HttpOnly do navegador e termina após 24 horas por padrão
(`[auth].session_ttl_secs`). O cabeçalho `Authorization` não aceita a sessão como credencial, por isso os programas sempre usam
um token de API.

## API de tokens

| Operação | Endpoint | Permissão |
|---|---|---|
| Emitir um token pessoal | `POST /api/v1/me/api-tokens` | `personal_tokens.manage` |
| Listar os próprios tokens | `GET /api/v1/me/api-tokens` | `personal_tokens.manage` |
| Revogar um dos próprios tokens | `DELETE /api/v1/me/api-tokens/{id}` | `personal_tokens.manage` |
| Listar as opções para restringir um token: políticas de permissões e permissões da organização | `GET /api/v1/me/api-tokens/scopes` | Membro com sessão autenticada |
| Emitir token de conta de serviço | `POST /api/v1/auth/tokens` | `api_tokens.revoke` |
| Listar todos os tokens | `GET /api/v1/auth/tokens` | `api_tokens.read` |
| Revogar qualquer token | `DELETE /api/v1/auth/tokens/{id}` | `api_tokens.revoke` |

Consulte [Emitir um token de API](/pt-BR/api/auth/issue-token), [Listar tokens de API](/pt-BR/api/auth/list-tokens) e
[Revogar um token de API](/pt-BR/api/auth/revoke-token).
