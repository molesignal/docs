Uma sessão é do tipo `user`, `synthetics` ou `ci_test`. Uma [verificação sintética](/pt-BR/synthetics) de navegador que abre uma página com o [SDK para navegador](/pt-BR/rum/browser-sdk) 0.3.0 ou posterior cria uma sessão do tipo `synthetics`, sem necessidade de configuração. Os eventos da sessão identificam a verificação, a execução e o local em `synthetics.test_id`, `synthetics.result_id` (o `task_id` do resultado da execução) e `synthetics.location_id`, respectivamente.

## O que isso significa para os números

Os números de um aplicativo refletem a atividade de usuários reais. Por isso, as sessões geradas por testes não entram:

- nas páginas de visão geral, desempenho, frustração, erros, análise, mapas de calor e flags de recursos, nem nos painéis integrados;
- nas [regras de alerta sobre métricas de RUM](/pt-BR/rum/alerts);
- nas linhas do explorador nem nas ferramentas de RUM do Mole Agent.

Os erros dessas sessões não abrem [problemas](/pt-BR/rum/errors), então uma falha na verificação não conta como um novo problema. Quando uma página deixa sessões de teste de fora, ela exibe **N sessões de teste excluídas**, com um link para essas sessões.

Essas sessões também não passam por amostragem: a [retenção](/pt-BR/rum/sampling) do aplicativo as preserva por inteiro. Quando um filtro do aplicativo especifica `session.type`, o aplicativo passa a tratar as execuções de teste como qualquer outra sessão, aplicando os mesmos filtros e proporções de amostragem. O SDK mantém essas sessões independentemente do valor de `sessionSampleRate`.

## Encontre as sessões

- A partir de uma execução: clique em **Abrir a sessão de RUM desta execução** na tentativa exibida no resultado de uma verificação de navegador.
- A partir da sessão: a página da sessão identifica o tipo e inclui um link para os resultados da verificação.
- No explorador: especifique `session.type`, `synthetics.*` ou `ci_test.*` na consulta, ou busque um `session.id` específico. Por exemplo, `session.type = 'synthetics'` encontra sessões sintéticas. Sem esses critérios, o explorador mostra apenas a atividade de usuários reais. A lista de valores de `session.type` inclui todos os tipos de sessão.
- Na API, o mesmo vale para os filtros de `search`, `aggregate`, `facets` e `histogram`.

## Testes de um aplicativo

Defina a mesma variável global antes que qualquer script da página seja executado. No Playwright:

```ts
await page.addInitScript((id) => {
  window.__MOLESIGNAL_TEST_CONTEXT__ = { type: 'ci_test', test_execution_id: id };
}, process.env.GITHUB_RUN_ID);
```

O SDK atribui a `window.__MOLESIGNAL_RUM_SESSION__` o ID da sessão que registrou. A verificação lê esse ID para criar um link para a sessão e sai da página no fim do percurso para que o SDK envie os dados acumulados.

<Note>
A página precisa usar uma versão do SDK para navegador posterior à 0.2.0 para que a sessão identifique o que a gerou. As solicitações do SDK seguem a mesma política de tráfego de saída da verificação que as demais solicitações. Se a política bloquear o acesso ao MoleSignal, a verificação falha.
</Note>
