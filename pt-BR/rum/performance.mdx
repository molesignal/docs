**RUM → Desempenho** mostra o desempenho das páginas de uma aplicação no navegador para quem as acessa. A análise abrange uma aplicação
por vez, em um ambiente ou em todos, no intervalo de tempo exibido. O
[SDK do navegador](/pt-BR/rum/browser-sdk) mede as Core Web Vitals. Se a aplicação enviar dados de outra fonte, a página informa
que não há carregamentos de página para avaliar.

A aba tem três visualizações, cada uma em sua própria aba: **Web Vitals**, **Recursos** e **Tarefas longas**. Todas usam a mesma
aplicação, o mesmo ambiente e o mesmo intervalo de tempo. Os links entre elas mantêm a aplicação e o ambiente.
As seções anteriores a [Recursos](#recursos) tratam das Web Vitals.

## Classificação das métricas

Uma frase informa o número de visualizações de página e o 75º percentil de LCP, INP e CLS, cada um na cor
da sua classificação. Abaixo, aparecem cinco métricas: as três Core Web Vitals e duas métricas anteriores a elas, a primeira renderização de conteúdo (FCP) e
o tempo até o primeiro byte (TTFB). Selecione uma métrica para atualizar o gráfico, as classificações e a tabela. O
endereço guarda a seleção (`vital`), o que permite compartilhar a visualização.

A classificação de cada métrica segue os limites do web.dev. Os limites são os mesmos para todas as aplicações.

| Métrica | Bom | Precisa melhorar | Ruim |
|---|---|---|---|
| **LCP**, renderização do maior elemento de conteúdo | até 2,5 s | de 2,5 s a 4 s | acima de 4 s |
| **INP**, tempo da interação até a próxima renderização | até 200 ms | de 200 ms a 500 ms | acima de 500 ms |
| **CLS**, mudança cumulativa de layout | até 0,1 | de 0,1 a 0,25 | acima de 0,25 |
| **FCP**, primeira renderização de conteúdo | até 1,8 s | de 1,8 s a 3 s | acima de 3 s |
| **TTFB**, tempo até o primeiro byte | até 0,8 s | de 0,8 s a 1,8 s | acima de 1,8 s |

## Ao longo do tempo

O gráfico mostra o 75º percentil da métrica selecionada em cada segmento do intervalo de tempo. Duas linhas tracejadas marcam os limites entre
bom, precisa melhorar e ruim. Arraste sobre o gráfico para restringir o intervalo de tempo.

## Visualizações por classificação

Para cada métrica, uma barra distribui as visualizações com dados entre bom, precisa melhorar e ruim. O percentual de visualizações com classificação boa aparece no
fim da barra. Para a métrica selecionada, o detalhamento indica os três percentuais, a contagem de visualizações e o limite de cada faixa. Os percentuais
se baseiam na contagem de visualizações com valores iguais ou inferiores aos limites, não em estimativas.

## Páginas e outras dimensões

A tabela lista os valores de uma dimensão com mais visualizações. Para cada valor, mostra o número de visualizações, o 75º percentil de cada métrica na cor
da classificação e o percentual de visualizações em que a métrica selecionada teve classificação boa.

- Em **Por**, selecione a dimensão: página (`view.url_path_group`), navegador, sistema operacional, dispositivo, país ou região, ou versão.
- A tabela considera os 50 valores com mais visualizações. A ordenação por coluna se aplica apenas a esses valores. Clique no cabeçalho de uma coluna para ordenar por ela e
  clique novamente para inverter a ordem. Ao ordenar por uma métrica, ela passa a ser a métrica selecionada.
- Um valor com menos de 30 visualizações aparece em cinza e fica no fim da lista ao ordenar por uma métrica: poucas visualizações não bastam para avaliar a
  velocidade de uma página.
- Filtre a tabela por palavras contidas no valor. O endereço guarda a dimensão, a ordenação e os termos da busca.

## Detalhes de um valor

Clique em uma linha para abrir um painel lateral com as visualizações daquele valor. O endereço guarda o valor e a métrica, o que permite reabrir
o painel pelo link. **Ver no Explorador** abre o Explorador com as mesmas visualizações. Alterne entre LCP, INP e CLS no cabeçalho.
Para uma página ou versão, **Criar alerta para esta métrica** abre o editor de regras para a métrica da aba ativa, com um filtro para essa página ou versão. A ação exige a permissão
`alerts.rules.manage`. Consulte [Alertas de RUM](/pt-BR/rum/alerts#criar-alertas-a-partir-de-uma-página).

- A primeira linha mostra o resultado da métrica para esse valor e o número de visualizações consideradas. Para LCP e INP, também identifica a etapa mais longa.
- **Composição** (LCP e INP) mostra em uma única barra as etapas da métrica e a duração de cada uma. Para LCP, as etapas são o tempo
  até o primeiro byte, o atraso até o início do carregamento da imagem, o tempo de carregamento e o atraso até a renderização. Para INP, as etapas
  são o atraso até a execução dos manipuladores de eventos, o tempo de execução e a espera pelo próximo quadro. Cada etapa mostra a média das
  visualizações com valores a até 10% de distância do 75º percentil daquele valor. Por isso, a soma das etapas se aproxima do resultado da métrica. Uma barra incompleta
  daria a impressão de mostrar o total. Por isso, o painel não exibe a barra quando as visualizações não informam todas as etapas. CLS é uma pontuação sem etapas.
- **Elemento** mostra o elemento que o navegador renderizou por último (LCP), com que houve interação (INP) ou que mudou de posição (CLS), além do número de visualizações em que apareceu e
  do seu 75º percentil. Para LCP, se o elemento for uma imagem ou um vídeo, o arquivo aparece ao lado. Clique em uma linha para abrir o Explorador com as visualizações que incluíram
  esse elemento.
- **Ao longo do tempo** mostra o mesmo gráfico, mas apenas para esse valor.
- **Visualizações com pior desempenho** lista as cinco visualizações com os maiores valores da métrica. Abra cada visualização no Explorador ou acesse a sessão completa.

Pressione <kbd>Esc</kbd> ou clique fora do painel lateral para fechá-lo.

## Recursos

**Recursos** (`/rum/performance/resources`) mostra o que as páginas carregam. Uma frase informa quantas requisições as páginas fizeram,
o 75º percentil da duração, quantas falharam (com status de erro ou sem resposta) e quantos recursos e bytes cada visualização de página
solicitou em média.

A tabela lista grupos de requisições, começando pelos de maior volume. Para cada grupo, mostra o número de requisições, o 75º percentil da duração
e do tamanho, o percentual de falhas e o percentual de requisições atendidas pelo cache.

- Em **Por**, escolha como agrupar as requisições: por host e tipo de requisição (padrão), por host e caminho, por tipo, por protocolo, pela forma de
  entrega ou pelo bloqueio da renderização.
- **Tipo** e **Status** filtram as requisições por tipo e status (erros de cliente de 400 a 499, erros de servidor a partir de 500 e ausência de
  resposta). A busca filtra as requisições cujo endereço contém os termos informados. Os filtros se aplicam à tabela
  e ao painel ao lado.
- A tabela considera os 100 grupos com mais requisições. A ordenação por coluna se aplica apenas a esses grupos. Um grupo com menos de 30 requisições
  aparece em cinza e fica no fim da lista em qualquer ordenação que não seja por número de requisições.
- O percentual de falhas aparece em laranja a partir de 1% e em vermelho a partir de 5%. Um traço substitui o percentual de requisições atendidas pelo cache quando as requisições não informam como
  ocorreu a entrega.

Clique em uma linha para abrir um painel ao lado da tabela. O endereço guarda o grupo, o que permite reabrir o painel pelo link.

- A primeira linha informa o 75º percentil da duração, quantas requisições falharam e qual etapa demorou mais.
- **Tempo ao longo do intervalo** mostra o 75º percentil da duração das requisições do grupo em cada segmento do intervalo de tempo.
- **Etapas das requisições** mostra em uma única barra o tempo gasto em cada etapa para as requisições próximas do 75º percentil: redirecionamento, DNS,
  conexão, TLS, tempo até o primeiro byte e download. Cada etapa mostra a média das requisições com duração a até 10% de distância do 75º
  percentil.
- **Status das respostas** lista os códigos de status do grupo, do mais frequente ao menos frequente, com o percentual de cada código entre as requisições que
  informaram o resultado.
- **Requisições mais lentas** lista as três requisições que mais demoraram. Clique em uma delas para abrir o carregamento da visualização que a originou, com a requisição
  selecionada.
- Quando há requisições com ID de trace, uma linha informa quantas têm esse ID. Clique nela para abrir o Explorador com as requisições do grupo.

## Tarefas longas

**Tarefas longas** (`/rum/performance/long-tasks`) mostra o que bloqueia a thread principal das páginas. Uma frase resume quantas
tarefas longas foram executadas, quantas visualizações de página tiveram pelo menos uma e, no percentil 75, quanto tempo essas tarefas duraram
e por quanto tempo bloquearam a entrada do usuário.

A tabela lista os grupos por ordem decrescente de quantidade. Para cada grupo, mostra o total de tarefas longas, o número de visualizações afetadas e o percentil 75
da duração das tarefas e do tempo de bloqueio da entrada do usuário. Os tempos aparecem em laranja a partir de 100 ms e em vermelho a partir de 200 ms.

- Em **Por**, escolha como agrupar as tarefas longas: por script e função a que a tarefa foi atribuída (padrão), por página, por versão ou pela forma como
  a tarefa foi acionada. A busca filtra as tarefas longas pelos termos presentes no endereço dos scripts.
- Navegadores que registram quadros de animação longos identificam os scripts executados em cada quadro. O MoleSignal atribui a tarefa longa ao
  script que rodou por mais tempo (veja [o que o MoleSignal adiciona](/pt-BR/rum/events#o-que-o-molesignal-adiciona)). O Safari e o Firefox registram
  tarefas longas sem identificar o script. As tarefas recebidas antes da implementação dessa atribuição também não têm script. Todas ficam no grupo
  **Sem atribuição** e entram na contagem como as demais.
- Assim como em Recursos, um grupo com menos de 30 tarefas longas aparece em cinza e fica no fim da classificação.

Clique em uma linha para abrir um painel com os acionadores das tarefas longas do grupo, as páginas em que ocorreram e as três tarefas mais longas.
Clique em uma dessas tarefas para abrir o carregamento da visualização que ela bloqueou, com a tarefa selecionada na thread principal.

## Carregamento de uma visualização

Ao abrir uma visualização do navegador, o painel lateral do explorador exibe **Cascata de carregamento**. A próxima seção explica os campos da visualização. Para abrir o painel,
clique em uma linha do explorador ou em uma das solicitações mais lentas ou tarefas mais longas mencionadas acima.

- Uma frase resume quanto tempo a página levou para carregar, quando chegou o primeiro byte, quanto tempo levou a maior renderização, qual elemento foi renderizado
  e quantos recursos e tarefas longas a visualização teve.
- O eixo do tempo começa no início da visualização e termina após o carregamento da página. As linhas marcam a chegada do primeiro byte, a primeira e a
  maior renderização, o momento em que o documento ficou pronto e o fim do carregamento. Uma indicação identifica o arquivo do qual a maior renderização dependeu.
- **Thread principal** mostra as tarefas longas no mesmo eixo. Uma indicação identifica as solicitações que bloqueiam a primeira renderização.
- Cada solicitação ocupa uma linha, em ordem de início. A barra vai do início ao fim da solicitação e se divide no momento em que chega o primeiro byte:
  antes, o tempo de espera; depois, o download. A cascata exibe as primeiras quinze solicitações e agrupa as demais em uma linha recolhida que informa
  quantas são e quanto tempo a maioria levou. Uma linha separada conta as solicitações iniciadas após o carregamento da página.
  Use **Tipo** e **Mostrar** (bloqueantes, lentas a partir de 500 ms, com falha) para filtrar as linhas.
- Clique em uma solicitação ou em uma tarefa longa na thread principal para abrir os detalhes à direita: o que era, como terminou, qual era o tamanho, como ocorreu
  a entrega, quanto tempo cada etapa levou e de qual trace fez parte. Para o arquivo do qual a maior renderização dependeu, o painel também mostra quanto
  tempo a renderização levou para começar, carregar e aparecer na tela. Ao abrir, de outra página, uma solicitação iniciada após o
  carregamento da página, o painel informa que ela não aparece no eixo.

Uma tela de aplicativo móvel não tem página para carregar, por isso o painel lateral exibe apenas os campos da tela.

## Como as métricas são calculadas

A API [`/api/v1/rum/aggregate`](/pt-BR/api/rum#medir-linhas) calcula todas as métricas de Web Vitals a partir das linhas correspondentes de `rum_views`.
Assim, uma visualização reenviada após uma alteração conta uma única vez, na revisão mais recente. As métricas de Recursos usam
`rum_resources`. As de Tarefas longas usam `rum_long_tasks` e, para a proporção de visualizações, `rum_views`. Se o cálculo de um cartão ultrapassar
o limite de tempo, o cartão exibe um aviso, e os demais continuam visíveis. Reduza o intervalo de tempo e consulte o cartão novamente. Para mostrar o carregamento de uma visualização, o painel consulta
as solicitações e as tarefas longas com o ID da visualização no intervalo em que ela carregou.

Os elementos, as etapas e as visualizações com pior desempenho vêm dos dados de atribuição que o SDK envia com cada métrica de Web Vitals (veja os campos de
`view.performance` no [formato do evento](/pt-BR/rum/events#visualização)). Se o navegador não medir uma dessas métricas, a visualização não inclui essa métrica.

A página exige a permissão `rum.events.read`. Veja [RUM](/pt-BR/rum#permissões).
