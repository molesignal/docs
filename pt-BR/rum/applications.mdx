Uma aplicação é o site ou app que envia eventos de RUM. Crie a aplicação antes que qualquer SDK envie dados:
o token de cliente está vinculado a uma única aplicação, e o MoleSignal rejeita eventos de aplicações que
não existem.

Abra **RUM → Aplicações** para listar as aplicações do espaço de trabalho. Criar, alterar e excluir
uma aplicação exige `rum.applications.manage`, pois cada aplicação tem um token de cliente.
Consultar a lista exige `rum.applications.read`.

## Criar uma aplicação

<Steps>
  <Step title="Abra o formulário">
    Clique em **Criar aplicação**. Se o espaço de trabalho não tiver aplicações, o mesmo botão aparece no
    explorador.
  </Step>
  <Step title="Dê um nome à aplicação">
    Digite um **Nome** exclusivo de até 128 caracteres, como `Checkout web`, e escolha a **Plataforma**:
    Navegador, Android, iOS, Flutter, React Native ou Outra. A plataforma só define o trecho de configuração
    que a aplicação exibe. O campo `source` de cada evento indica o que o enviou.
  </Step>
  <Step title="Defina o identificador">
    O **Identificador** é o valor usado como `applicationId` na configuração dos SDKs. Deixe o campo em branco para
    gerar o identificador a partir do nome (`checkout-web`) ou digite até 64 caracteres entre `A-Z`, `a-z`, `0-9`,
    `.`, `_`, `:` e `-`. Não é possível alterar o identificador após a criação da aplicação.
  </Step>
  <Step title="Clique em Criar">
    A aplicação abre com o token de cliente.
  </Step>
</Steps>

Ao criar uma aplicação, o MoleSignal também cria os sete fluxos de RUM do espaço de trabalho, caso ainda não existam.

## Token de cliente

Abra uma aplicação para ver o **Token de cliente**. O token tem o formato `mspat-<36>`, nunca expira
e concede apenas a permissão `rum.write` para essa aplicação. O token aparece mascarado. Selecione **Mostrar token** ou **Copiar token**.

<Warning>
  O token fica no código do navegador e do app móvel, onde os usuários podem lê-lo. Use apenas esse token no código do cliente. Nunca use
  um token de proprietário, de administrador ou pessoal. Excluir a aplicação revoga o token.
</Warning>

O mesmo token está disponível na [API](/pt-BR/api/auth/rum-token). Na aplicação, **Abrir o guia de configuração** abre
o guia de **Fonte de dados** da plataforma com a aplicação selecionada. O guia mostra o endpoint, o token,
o trecho de código do SDK com o identificador preenchido e uma verificação de recebimento de dados. React Native e Outra não têm guia: envie os
[eventos](/pt-BR/rum/events) diretamente com o token.

## Coleta

As configurações da aplicação definem o que o MoleSignal armazena com cada evento. Altere as configurações na aplicação e clique em **Salvar**.

| Configuração | Padrão | Efeito |
|---|---|---|
| **Armazenar o endereço IP** | Ativado | Armazena em `network.client.ip` o endereço IP do cliente que o servidor identificou. Se houver um proxy, configure primeiro a [identificação do IP do cliente](/pt-BR/rum#ip-do-cliente-atrás-de-um-proxy). |
| **Manter a localização** | Ativado | Armazena o país, a região e a cidade identificados a partir do endereço. O servidor faz a consulta mesmo quando não armazena o endereço e guarda apenas o resultado. |
| **Privacidade padrão** | Mascarar textos e campos de entrada | Nível de privacidade que o trecho de configuração sugere para o replay de sessões: **Mascarar textos e campos de entrada**, **Mascarar o que os usuários digitam** ou **Gravar tudo o que aparece na tela**. |

As alterações se aplicam apenas aos eventos que chegam depois. Os dados já armazenados não mudam.

## Configuração remota do SDK

Ao iniciar com `remoteConfiguration: true`, o SDK lê essas configurações, que podem mudar sem publicar uma nova versão da página. Para as opções definidas como
**Conforme definido na página**, o SDK usa os valores que a página passou para `init`.

| Configuração | Opção do SDK |
|---|---|
| **Taxa de amostragem de sessões (%)** | `sessionSampleRate` |
| **Taxa de amostragem de replays (%)** | `sessionReplaySampleRate` |
| **Nível de privacidade** | `defaultPrivacyLevel` |
| **Coletar cliques** | `trackUserInteractions` |
| **Encaminhar mensagens do console** | `forwardConsoleLogs` |

O SDK consulta essas configurações em `GET /api/v1/rum/config` com o token de cliente e aguarda até 1,5 segundo. Se não receber uma resposta, inicia com os valores da página.

## Segmentos

Em **Segmentos**, defina até 20 grupos de sessões para filtrar as [páginas de análise](/pt-BR/rum/analytics#segmentos). Cada segmento tem até cinco
condições, e a sessão precisa atender a todas elas. Cada condição verifica o país, o continente ou a cidade, o navegador, o sistema ou o tipo
de dispositivo, o ID ou e-mail do usuário, o ID da conta, o serviço, a versão ou a plataforma, ou uma propriedade do usuário que a aplicação definiu
com `setUser` (`usr.extra.plan`). A condição verifica se o campo corresponde a um ou mais valores ou a nenhum deles. As alterações se aplicam imediatamente às consultas e às
sessões já armazenadas. As propriedades do usuário só estão disponíveis nas sessões que começaram após a implantação desse recurso.

## Dados sensíveis e sessões mantidas

Em **Dados sensíveis**, use o controle de cada tipo de texto que o servidor remove antes de armazenar o evento: tokens, chaves e
senhas; endereços de e-mail; números de telefone; números de cartões de pagamento; números de identificação; e valores de parâmetros sensíveis de URL.
Todos os controles vêm ativados por padrão. Consulte [Privacidade de RUM](/pt-BR/rum/privacy#remova-texto-sensível-na-ingestão) para saber o que cada controle remove.

**Sessões mantidas** define quais sessões a aplicação armazena. Em **Porcentagem de sessões mantidas (%)**, informe a porcentagem das sessões recebidas que a
aplicação deve manter: um número inteiro de `0` a `100`. A aplicação mantém ou descarta cada sessão inteira, incluindo o replay.
Use **Adicionar um filtro** para definir uma porcentagem específica para as sessões que correspondem aos critérios (ambiente, versão, país, navegador e outros). O primeiro
filtro que corresponde à sessão define a porcentagem. Para as demais, vale a **Retenção das demais sessões (%)**. A opção **Manter todos
os erros** armazena os erros mesmo quando a aplicação descarta a sessão. As páginas de totais extrapolam os dados da amostra para o conjunto de
sessões e exibem o rótulo **Estimado**. Consulte [Amostragem de dados de RUM](/pt-BR/rum/sampling#retenha-uma-porcentagem-das-sessões-no-servidor).

## Problemas

Na seção **Problemas**, defina quantos [problemas](/pt-BR/rum/errors#novos-problemas-por-hora) novos a aplicação abre por hora.

| Configuração | Padrão | Efeito |
|---|---|---|
| **Novos problemas por hora** | 100 | De 1 a 10.000. Ao atingir o limite, a aplicação agrupa os erros que ainda não pertencem a nenhum problema em um único problema chamado **Outros erros** até o fim da hora. As alterações entram em vigor em até 30 segundos. |

## Excluir uma aplicação

Clique em **Excluir aplicação** e confirme. O token de cliente deixa de funcionar imediatamente, e o MoleSignal rejeita solicitações de SDKs que usam esse token.
Os eventos que a aplicação já enviou permanecem nos fluxos até o fim do período de retenção e continuam disponíveis para consulta
no explorador.
