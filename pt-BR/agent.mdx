**Mole Agent** é o agente de operações integrado e o espaço de trabalho correspondente no produto.

O Mole Agent pode consultar logs, métricas, traces, RUM, perfis, alertas, dados de plantão e relatórios por meio de
ferramentas registradas no servidor. O Mole Agent usa a organização e as permissões do usuário autenticado e ignora
os identificadores de organização fornecidos pelo modelo.

## Configure um provedor de modelos

O Mole Agent precisa de um provedor de modelos para responder no chat. Para adicionar um provedor, use uma conta de administrador com a permissão `agent.models.manage`:

1. Abra **Mole Agent → Configurações → Modelos e raciocínio** e selecione **Adicionar provedor de modelos**.
2. Escolha o **Tipo de provedor**: OpenAI, Anthropic ou um endpoint compatível com OpenAI.
3. Preencha o **Nome de exibição**, o **Modelo padrão** e a **Chave de API**. O campo da chave é somente para gravação. Nem a página nem a API retornam a chave.
4. Defina a **URL base** para um endpoint compatível com OpenAI. Deixe o campo em branco para usar o endpoint oficial da OpenAI ou da Anthropic.
5. Ajuste o **Tempo limite sem resposta** e o **Máximo de tokens de saída** se os valores padrão do provedor não forem adequados. Escolha a **Moeda**, preencha os preços para ver os custos nos dados de uso e salve.

O **Tempo limite sem resposta** define quanto tempo uma chamada pode ficar sem receber dados do provedor de modelos antes de falhar. O padrão é 120000 ms, e o intervalo aceito vai de 1000 a 600000 ms. Uma chamada sem streaming aguarda a resposta completa. Defina um tempo suficiente para a resposta mais demorada. Em caso de falha de conexão, limite de taxa (429) ou indisponibilidade temporária (5xx, 529), o Mole Agent repete a chamada até duas vezes, apenas se ainda não tiver recebido uma resposta. Se o provedor enviar `Retry-After`, o Mole Agent aguarda o tempo indicado. Um provedor Anthropic sem **Máximo de tokens de saída** definido usa 4096.

Os preços são por milhão de tokens, na **Moeda** do provedor, e valem para todos os modelos desse provedor: **Preço de entrada sem cache**, **Preço de entrada com cache** para os dados de entrada que o provedor fornece do cache e **Preço de saída**. Preencha o preço com cache apenas se o provedor cobrar separadamente pelos acertos de cache. Caso contrário, o Mole Agent aplica o preço sem cache a toda a entrada. Deixar os preços em branco desativa apenas o cálculo de custos. O acompanhamento do uso e os orçamentos funcionam da mesma forma.

As opções de moeda ficam em **Moedas**, abaixo dos provedores de modelos. Para adicionar uma moeda, use uma conta de administrador com a permissão `agent.usage.manage` e informe o código ISO 4217. Informe também um nome e um símbolo se os valores padrão não forem adequados. Não é possível excluir uma moeda em uso por um provedor de modelos. Mesmo após a exclusão de uma moeda, os custos registrados nela continuam a aparecer nessa moeda. Sem a permissão `agent.usage.read`, a seção não aparece e não é possível alterar a **Moeda**: um novo provedor usa USD e um provedor existente mantém a moeda configurada.

As chamadas aos modelos passam pelo Model Gateway. Ao editar um provedor, deixe o campo da chave em branco para manter a chave salva ou insira um valor para substituí-la. A substituição exige a permissão `agent.models.rotate`. Com essa permissão, mas sem `agent.models.manage`, só é possível alterar a chave. As variáveis de ambiente `MS_AGENT_OPENAI_API_KEY`, `MS_AGENT_ANTHROPIC_API_KEY` e `MS_AGENT_COMPATIBLE_API_KEY` são uma alternativa para ambientes de desenvolvimento. Consulte [Configuração](/pt-BR/configuration#variáveis-de-ambiente).

## Conversa

Abra **Mole Agent → Conversa**, escolha um modelo disponível, defina o intervalo de tempo e descreva o
sintoma. Fixe um serviço, alerta, ambiente ou fluxo como contexto da investigação.

Quando nenhum modelo de IA está habilitado, a conversa exibe um aviso acima da caixa de mensagem. Com a permissão
`agent.models.manage`, acesse **Modelos e raciocínio** pelo link no aviso.

A resposta pode incluir:

- uma conclusão em linguagem simples;
- chamadas de ferramentas e resumos das evidências;
- links para os logs, métricas, traces ou incidentes de origem;
- metadados sobre tokens e custo do modelo (o custo aparece quando o provedor do modelo informa os preços);
- a versão do modelo de prompt e o hash do conteúdo para garantir a reprodutibilidade.

O rodapé da resposta mostra **Copiar**, **Ramificar**, **Fixar** e o horário da resposta à esquerda. À direita, um indicador mostra o nível de confiança da resposta: quanto maior o nível, mais longa fica a barra e mais verde fica a ponta. Passe o cursor sobre o indicador para ver o nome do nível. Depois do indicador, aparecem **Útil** e **Não foi útil**. **Ramificar** inicia uma nova conversa com as mensagens até essa resposta. A nova conversa aparece abaixo da conversa de origem. **Fixar** mantém a resposta no topo da conversa apenas para quem a fixou.

Abaixo da resposta, selecione **Útil** ou **Não foi útil**. Ao selecionar **Não foi útil**, indique o motivo (conclusão ou causa incorreta, problema não identificado, recomendação impraticável, fora do assunto ou outro) e adicione um comentário opcional. Só quem fez a pergunta pode avaliar a resposta. Selecione a mesma opção novamente para remover a avaliação. A avaliação registra o modelo e a versão do prompt usados na resposta.

Quando o uso diário de tokens da organização atinge o limite de aviso do orçamento, a conversa exibe um aviso acima da caixa de mensagem. Consulte [Uso e orçamento](#uso-e-orçamento) para saber o que acontece quando o orçamento se esgota.

O Mole Agent transfere resultados brutos volumosos das ferramentas para o armazenamento de objetos. Antes de excluir a conversa, o Mole Agent tenta
arquivar a transcrição.

### Escreva uma mensagem

A caixa de mensagem mostra a formatação que será enviada: `- ` inicia uma lista, `1. ` uma lista numerada, `# ` um título, `> ` uma citação, `[ ] ` uma tarefa e ```` ``` ```` um bloco de código. Já `**bold**` e `` `code` `` aplicam a formatação durante a digitação. Pressione **Enter** para enviar. Em uma lista ou um bloco de código, pressione **Enter** para continuar. Em um item vazio, pressione **Enter** para sair da lista. Pressione **⌘ Enter** ou **Ctrl Enter** para enviar de qualquer posição. Pressione **Shift Enter** para iniciar uma nova linha. Ao colar Markdown, a formatação é preservada. Para manter o texto como está, cole como texto simples (**⌘ Shift V** ou **Ctrl Shift V**). A caixa envia a mensagem em Markdown.

### Modos de execução

O modo abaixo da caixa de mensagem define o que o Mole Agent pode executar na conversa. Com o menu aberto, pressione um número de 1 a 5 para selecionar um modo.

| Modo | O que executa |
|---|---|
| **Modo de recomendações** (recomendado) | Consulta dados e sugere alterações sem aplicá-las. |
| **Modo de investigação** | Executa consultas somente leitura conforme necessário e não altera nada. |
| **Executar com aprovação** | Executa consultas. Para aplicar uma alteração, pede confirmação ou encaminha a alteração para aprovação, conforme o modo de execução da ferramenta. |
| **Modo automático** | Executa consultas e aplica sem pedir confirmação as alterações reversíveis que exigem apenas confirmação de quem as solicitou. Ainda pede confirmação para exclusões e outras alterações destrutivas. |
| **Ignorar permissões** | Aplica sem pedir confirmação as alterações que exigem apenas confirmação de quem as solicitou, inclusive as destrutivas. |

Em qualquer modo, as alterações que exigem aprovação pela política de ferramentas da organização continuam seguindo para os responsáveis pela aprovação, e as ferramentas desabilitadas continuam desabilitadas. O Mole Agent só oferece **Ignorar permissões** se o perfil de agente da conversa habilitar **Permitir ignorar permissões** em **Política de aprovação**. O modo pede confirmação antes de ser ativado. Se o perfil deixar de permitir o modo enquanto uma pergunta aguarda na fila, o Mole Agent informa isso na resposta e pede confirmação antes de cada alteração.

### Nomes das conversas

Ao responder à primeira pergunta de uma nova conversa, o Mole Agent gera um nome curto sobre o assunto, no idioma da pergunta, como fazem o ChatGPT e o Claude. Uma saudação não define um assunto, então a conversa mantém as primeiras palavras como nome até receber uma pergunta com um assunto. O Mole Agent gera o nome só uma vez. Selecione o lápis ao lado de uma conversa na lista para renomeá-la. Pressione **Enter** para salvar ou **Esc** para cancelar. O Mole Agent deixa de gerar nomes para essa conversa. As memórias mostram o nome atual da conversa de origem. Gerar um nome conta no uso do modelo como qualquer outra chamada.

### Conversas pessoais e de equipe

A conversa é pessoal, a menos que uma equipe seja selecionada antes da primeira mensagem. Selecione uma equipe em **Equipe**, abaixo da caixa de mensagem, ou digite `/team <team>`. A lista mostra as equipes das quais a pessoa faz parte. Com a permissão `agent.manage`, a lista mostra todas as equipes. Após o envio da primeira mensagem, a equipe da conversa não muda.

| | Conversa pessoal | Conversa de equipe |
|---|---|---|
| Quem pode ler e continuar | A pessoa proprietária da conversa | Membros da equipe e pessoas com a permissão `agent.manage` |
| Habilidades e servidores MCP que a conversa usa | Os da organização, os da pessoa proprietária e os de uma equipe adicionada à conversa | Os da organização e os da equipe, sem recursos pessoais |

As ferramentas sempre usam as permissões e as credenciais de quem enviou a mensagem. Em uma conversa de equipe, as perguntas de outras pessoas aparecem com o nome de quem as enviou. Em uma conversa pessoal, chamar uma habilidade ou um prompt MCP de uma das equipes de quem enviou a mensagem adiciona as habilidades e os servidores MCP dessa equipe até o fim da conversa. A lista identifica cada conversa de equipe com a equipe correspondente. Quando há conversas de equipe, **Todos**, **Pessoal** e **Equipe** filtram a lista.

### Comandos de barra

Digite `/` no início da caixa de mensagem para abrir o menu de comandos. Continue digitando para filtrar por nome ou descrição. Use ↑ ↓ para selecionar, **Enter** para executar, **Aba** para completar sem executar e **Esc** para fechar o menu. Ao completar um comando que aceita um argumento, o menu lista os argumentos disponíveis. Os comandos funcionam na página da conversa e no painel do Mole Agent, que o atalho ⌘J abre em qualquer tela.

| Comando | O que faz |
|---|---|
| `/help` | Lista todos os comandos |
| `/new` | Inicia uma nova conversa |
| `/team <team>` | Seleciona a equipe de uma nova conversa. Use `personal` para criar uma conversa pessoal. Em uma conversa já iniciada, abre uma nova conversa para a equipe selecionada |
| `/mode auto\|quick\|deep\|query` | Altera o modo de análise: **Modo automático**, **Resposta rápida**, **Investigação aprofundada**, **Apenas gerar a consulta** |
| `/time 15m\|30m\|1h\|6h\|24h\|7d` | Define o intervalo de tempo |
| `/policy advice\|readonly\|approval\|auto\|bypass` | Define o modo de execução: **Modo de recomendações**, **Modo de investigação**, **Executar com aprovação**, **Modo automático**, **Ignorar permissões**. `bypass` pede confirmação antes de ativar o modo e só funciona se o perfil de agente permitir |
| `/model <model provider>` | Seleciona um provedor de modelos pelo nome do provedor ou do modelo. Use `auto` para selecionar automaticamente |
| `/profile <agent profile>` | Seleciona um perfil de agente. Use `auto` para usar o perfil padrão |
| `/prompt <prompt>` | Seleciona um prompt. Use `auto` para selecionar automaticamente |
| `/query <question>` | Escreve uma consulta sem executá-la |
| `/dashboard <what it should show>` | Cria um dashboard |
| `/rca <incident> [more context]` | Investiga a causa raiz de um incidente. O menu lista os incidentes abertos. Requer `alerts.incidents.read` |
| `/export` | Baixa a conversa como um arquivo Markdown |

`/query`, `/dashboard` e `/rca` enviam uma mensagem. A conversa exibe o comando como um rótulo seguido do argumento. Gerar a resposta novamente executa o mesmo comando. O modo de `/query` se aplica apenas àquela mensagem. `/rca` analisa o período de 30 minutos antes do início do incidente até o encerramento ou, se o incidente ainda estiver aberto, até o momento atual. Os outros comandos apenas alteram as configurações da caixa de mensagem e não enviam nada.

Se o comando não existir, se o argumento estiver ausente ou incorreto ou se faltar uma permissão, a caixa de mensagem não envia o comando e exibe o motivo logo acima. Para enviar texto simples que comece com `/`, digite `\/` no início. A caixa remove a barra invertida ao enviar a mensagem. Um caminho com uma segunda barra, como `/var/log/app.log`, é enviado como texto simples.

As habilidades e os prompts MCP também são comandos e aparecem em **Habilidades** e **MCP** no menu:

- `/name [request]` executa uma habilidade disponível na conversa. Quando duas equipes têm habilidades com o mesmo nome, digite `/name@team`. Em uma conversa pessoal, isso também adiciona a equipe à conversa.
- `/<server>:<prompt> [arguments]` obtém um prompt de um servidor MCP com a credencial de quem enviou a mensagem e envia o prompt como pergunta. Preencha os argumentos na ordem, deixando o restante do texto para o último argumento, ou informe os nomes no formato `name=value`. Coloque valores com espaços entre aspas.

Uma habilidade que executa scripts exige um Mole Runner. Um prompt de um servidor que usa credenciais de membros exige que quem envia a mensagem tenha a própria credencial configurada. O menu indica esses requisitos no comando.

## Conhecimento e memória

Abra **Mole Agent → Conhecimento**. **Conhecimento** reúne os arquivos Markdown da organização e de cada equipe que os chats consultam. Use `MOLE.md` como ponto de entrada e referencie outros arquivos com `@path`, ou execute `/init` para que o Mole Agent verifique a configuração atual, faça algumas perguntas e grave cada arquivo após a confirmação. A permissão `agent.manage` permite alterar o conhecimento da organização. Os membros de cada equipe podem alterar o conhecimento da própria equipe.

- **Novo** cria um arquivo ou uma pasta com o primeiro arquivo. Um caminho como `runbooks/api.md` cria a pasta e o arquivo de uma só vez.
- **Enviar** aceita arquivos ou uma pasta inteira.
- O arquivo abre em **Prévia**. **Editar** mostra o conteúdo renderizado durante a edição, assim como na caixa de mensagem, e **Origem** permite editar o Markdown. Se o arquivo contiver Markdown que o editor não preserva, como um comentário HTML, edite-o em **Origem**.
- **IA** abre um chat para alterar o arquivo.

**Memória** guarda o que os chats registraram: preferências, procedimentos, fatos e aprendizados. Um chat pessoal registra memórias para o proprietário, e um chat de equipe, para a equipe. O nome do chat em cada memória leva ao chat de origem. Edite o texto de uma memória da mesma forma que o de um arquivo de conhecimento ou exclua a memória. Apenas os chats criam memórias. Com **Extrair memórias após os chats**, opção que exige a permissão `agent.memories.settings` para ser ativada, o modelo escolhe o que vale a pena lembrar meia hora após o fim do chat e usa o orçamento da organização para o modelo.

## Investigações

Transforme uma pergunta complexa em uma investigação com acompanhamento. Uma investigação registra:

- status e etapa atual;
- evidências e seu impacto na conclusão;
- hipóteses concorrentes e níveis de confiança;
- chat, aprovações e execuções relacionados;
- resumo final e verificação da recuperação.

Um chat iniciado a partir de um incidente registra uma investigação do incidente. Um chat iniciado com
**Investigar** em um serviço, endpoint, erro ou insight do APM registra uma investigação do serviço. Um chat
iniciado com **Investigar com o Mole Agent** em uma página do RUM registra uma investigação da aplicação.
**Mole Agent → Investigações** lista as investigações. Ao anexar um serviço do APM a um chat, o modelo recebe os
dados do serviço no intervalo de tempo do chat, os insights e as informações sobre quem chama o serviço e o que ele chama. Consulte
[Investigar com o Mole Agent](/pt-BR/apm/insights#investigar-com-o-mole-agent). Ao anexar uma aplicação do RUM a um chat,
o modelo recebe as sessões, as métricas Core Web Vitals, os principais problemas e os alertas ativos. Consulte
[Investigar com o Mole Agent](/pt-BR/rum#investigar-com-o-mole-agent).

Ao anexar um incidente a um chat, o modelo recebe o próprio incidente e os seguintes dados: o guia de investigação da regra de alerta que abriu o incidente (se o guia contiver consultas, o modelo as executa primeiro); o que o catálogo informa sobre os serviços afetados e onde encontrar os dados; os incidentes mais parecidos dos últimos 90 dias (como cada um terminou e a primeira frase sobre sua causa raiz); e as implantações, alterações de configuração e flags de funcionalidade de pouco antes a pouco depois do início do incidente. Os chats e as automações iniciados a partir de um incidente recebem os mesmos dados.

Ao consultar dados, o Mole Agent começa pelos resultados resumidos: `analyze_log_patterns` agrupa os logs por padrão e os compara com um período de referência. `analyze_metric_trend` indica quando uma métrica começou a mudar, quanto mudou e quais séries e rótulos contribuíram para a mudança. Depois, o Mole Agent consulta os logs brutos em busca de exemplos. As consultas de uma mesma etapa (por exemplo, de métricas, logs e traces) são executadas em paralelo, até quatro por vez. As operações que alteram dados ou recursos continuam sendo executadas uma por vez.

Se nenhuma automação da organização gerar a análise de causa raiz de um incidente ativo, o sistema gera a análise em segundo plano com uma única chamada ao modelo, sem ferramentas. A chamada é executada com a identidade do sistema, e qualquer usuário com acesso ao incidente pode ler a análise. Por isso, o modelo não consulta dados de fluxos e usa apenas o incidente, o guia de investigação, o catálogo de serviços, os incidentes semelhantes e as alterações próximas ao início do incidente. Para verificar os dados com ferramentas, use o modelo **Análise de incidente** de [Automações](/pt-BR/automations), que executa a análise com a identidade de quem salvou a automação.

## Automações

Uma automação faz o Mole Agent executar uma tarefa sem a participação de usuários no chat: por agendamento, a cada novo incidente, quando um job de CI/CD aciona a automação ou por acionamento manual. O Mole Agent salva cada execução como um chat. O resultado pode seguir para os canais de notificação e, no caso de um incidente, servir como análise de causa raiz (RCA). Consulte [Automações](/pt-BR/automations).

## Qualidade

As regras atribuem uma pontuação a cada resposta. Os avaliadores que a organização configura usam um modelo para pontuar uma amostra das respostas. Respostas com pontuação baixa ou marcadas como pouco úteis ficam pendentes de revisão na aba **Qualidade**. Antes de adotar um prompt da organização como padrão para chats ou análises de causa raiz, o sistema o compara com o padrão atual. Consulte [Qualidade](/pt-BR/quality).

## Mensagens instantâneas

O Mole Agent também responde no Feishu, Slack, DingTalk, WeCom, Google Chat, Microsoft Teams e Telegram por meio de um conector. Mencione o Mole Agent em um grupo ou envie uma mensagem direta. Os chats dessas plataformas também aparecem no MoleSignal. Consulte [Mole Agent em mensagens instantâneas](/pt-BR/im).

## Aprovações e execuções

As ferramentas com permissão de escrita sempre obedecem à política de execução do servidor.

| Risco | Modo de execução padrão |
|---|---|
| L0 | Automático. |
| L1 | Confirmação do usuário. |
| L2 | Aprovação única. |
| L3 | Aprovação dupla. |
| L4 | Desativado. Ferramentas remotas destrutivas têm, no mínimo, esse nível de risco. |

Uma aprovação registra a operação proposta e expira ao fim do prazo definido pela política. Antes da execução,
o servidor valida novamente a permissão, o estado do recurso, os parâmetros, o risco e a idempotência. O registro de execução
guarda os resultados e a verificação da recuperação.

## Inspeções de logs

O Mole Agent também consulta um fluxo de logs e gera um relatório. Execute uma inspeção avulsa em **Logs** ou
agende inspeções em segundo plano. Uma inspeção agendada salva todos os relatórios e envia uma notificação quando algum deles
aponta um problema. Consulte [Inspeções de logs](/pt-BR/logs/inspections).

## Habilidades

Uma habilidade é uma pasta que contém um `SKILL.md` com instruções para um tipo de tarefa, no formato aberto Agent Skills, e os arquivos citados nessas instruções. O Mole Agent vê os nomes e as descrições das habilidades disponíveis no chat, lê as instruções de uma habilidade quando a solicitação corresponde à descrição e lê os demais arquivos quando as instruções fazem referência a eles. Cada habilidade também é um comando de barra.

| Origem | Onde gerenciar | Quem usa |
|---|---|---|
| **Integrada** | Incluída no MoleSignal | Todas as organizações, somente leitura |
| **Pasta da instância** | Pastas listadas em `[agent].skill_paths` no servidor | Todas as organizações, somente leitura |
| **Enviada** | **Mole Agent → Configurações → Habilidades → Enviar habilidade** | A organização, uma equipe ou um usuário |
| **Repositório** | **Mole Agent → Configurações → Habilidades → Adicionar repositório** | A organização, uma equipe ou um usuário |

Entre as habilidades integradas estão `/init`, que registra o conhecimento, e `/insight`, que analisa como o Mole Agent foi usado e o que pode melhorar; consulte [Automações](/pt-BR/automations#revise-o-uso-do-mole-agent). A habilidade `/rum-triage` faz a triagem de um problema que afeta usuários reais, da visão geral de um aplicativo de RUM até seus problemas, sessões e traces. A habilidade `/data-readiness` verifica se os dados estão prontos para uma investigação e gera um relatório. Ela verifica se cada fluxo registra o serviço, o ambiente e o ID do trace, se cada serviço tem o mesmo nome nos logs, nas métricas e nos traces e se os nomes das métricas incluem as unidades. O relatório indica uma correção para cada problema. Quem tem a permissão `agent.manage` pode desativar habilidades integradas e da pasta da instância para a organização. Quando várias habilidades têm o mesmo nome, o chat prioriza a pessoal, seguida pela da equipe, pela da organização, pela da pasta da instância e pela integrada. O Mole Agent lê as pastas da instância na inicialização e sempre que os arquivos mudam; consulte [Configuração](/pt-BR/configuration).

### Escreva uma habilidade

O arquivo `SKILL.md` começa com um bloco de metadados YAML:

| Campo | Obrigatório | Descrição |
|---|---|---|
| `name` | Sim | Nome do comando: comece com uma letra e use apenas letras, dígitos, `-` e `_` no restante, até o limite de 64 caracteres. Não use nomes de comandos integrados. |
| `description` | Sim | O que a habilidade faz e quando usar, em até 1024 caracteres. O Mole Agent usa a descrição para selecionar as habilidades. |
| `allowed-tools` | Não | Ferramentas que a habilidade usa. Quando a habilidade é executada como comando, o modelo recebe as ferramentas diretamente, ainda sujeito à política de ferramentas e às aprovações da organização. |
| `argument-hint` | Não | Formato do argumento, exibido no menu de comandos. |
| `version` | Não | Versão exibida nas configurações e registrada a cada chamada. Também é possível usar `metadata.version`. |
| `tags`, `examples` | Não | Tags e perguntas para testar, exibidas nos detalhes da habilidade. |
| `requires` | Não | Use `runner` para indicar que a habilidade executa scripts e precisa de um Mole Runner. |

Nas instruções, `$ARGUMENTS` representa o texto depois do comando, e `$1` a `$9` representam as palavras desse texto. Sem esses marcadores, o texto vem depois das instruções.

Um pacote é um arquivo `.zip`, `.skill` ou `.tar.gz` de até 20 MiB que contém uma única pasta de habilidade. O conteúdo descompactado pode ter até 300 arquivos, 20 MiB no total e 8 MiB por arquivo. O MoleSignal rejeita links e caminhos que apontam para fora da pasta. Ao enviar uma habilidade com um nome que já existe no escopo, confirme a substituição. Nos detalhes da habilidade, clique em **Testar em um chat** para abrir o Mole Agent com o comando já digitado.

### Repositórios de habilidades

O MoleSignal lê o repositório a partir de uma branch ou tag e baixa o conteúdo em um único arquivo compactado. Cada pasta que contém um `SKILL.md` é uma habilidade, seja em qualquer parte do repositório ou dentro da **Pasta** indicada. O limite é de 50 habilidades por repositório e 64 MiB por arquivo compactado. Para GitHub, GitLab, Gitea, Forgejo e Bitbucket, informe o endereço do repositório. Para outro host, informe o endereço do arquivo compactado com `{ref}`. Para um repositório privado, informe um token de acesso. O token é somente para gravação.

Ao salvar um repositório, o MoleSignal o sincroniza uma vez. Clique em **Sincronizar** para repetir a operação ou ative **Sincronizar todos os dias** para manter o repositório atualizado. A sincronização adiciona, atualiza e remove as habilidades do repositório e lista as pastas que não conseguiu importar, com o motivo. Excluir um repositório também remove as habilidades dele.

## Recursos da organização, da equipe e pessoais

Habilidades, repositórios de habilidades e servidores MCP pertencem à organização, a uma equipe ou a um usuário. Ao adicionar um recurso, defina o escopo em **Pertence a**. Quem tem permissão para editar o recurso pode movê-lo para outro escopo que gerencia.

| Escopo | Quem altera | Onde é usado |
|---|---|---|
| Organização | Quem tem a permissão `agent.manage` | Todos os chats |
| Equipe | Membros da equipe e quem tem a permissão `agent.manage` | Chats da equipe e chats pessoais que incluem a equipe |
| Pessoal | O proprietário. Quem tem a permissão `agent.manage` pode ver, desativar ou excluir o recurso | Chats pessoais do proprietário |

Não é possível excluir uma equipe que ainda tem habilidades, repositórios ou servidores MCP. Consulte a lista desses recursos em **Identidade e acesso → Equipes** e mova ou exclua os recursos primeiro.

Os repositórios e servidores MCP adicionados por equipes e usuários só acessam a internet pública e os hosts e intervalos de endereços internos que alguém com a permissão `agent.network_policy.manage` lista em **Mole Agent → Configurações → Política de rede → Rede interna para conexões de equipe e pessoais**. Eles sempre verificam os certificados TLS. Os repositórios e servidores da organização seguem as próprias configurações.

## Configurações do agente

Abra **Mole Agent → Configurações**. As seções aparecem em uma linha abaixo das abas do Mole Agent:

| Seção | Finalidade |
|---|---|
| **Perfis do agente** | Perfis com as ferramentas permitidas, os limites de chamadas de ferramentas e de tempo de investigação, a temperatura por resposta, o escopo dos dados e a política de rede. |
| **Modelos e raciocínio** | Provedores de modelos, chaves de API somente para gravação, tempo limite de espera por resposta e preços. |
| **Uso** | Uso de hoje em relação ao orçamento diário de tokens e uso por origem nos últimos 30 dias. |
| **Gerenciamento de prompts** | Prompts integrados, com substituições da organização e pessoais. |
| **Habilidades** | Habilidades integradas, da pasta da instância, enviadas por upload ou provenientes de repositórios, além dos repositórios de habilidades. |
| **Ferramentas e recursos** | Catálogo de ferramentas: modo de execução, limites e níveis mínimos de risco de cada ferramenta por ambiente, além dos servidores MCP da organização, das equipes e dos membros, com suas ferramentas e prompts. |
| **MCP de entrada** | Endpoint MCP para clientes de IA externos. |
| **Acesso a dados** | Ambientes, serviços e fluxos que o perfil padrão pode ler. |
| **Política de rede** | Define se o perfil pode usar ferramentas que precisam de acesso à rede e quais endereços internos as conexões de equipe e pessoais podem acessar. |
| **Política de aprovação** | Regras de aprovação para cada nível de risco. |

As credenciais permanecem criptografadas, e a API nunca as retorna.

### Ferramentas e recursos

A seção agrupa as ferramentas por área do produto. Os grupos começam recolhidos. Expanda
um grupo ou faça uma busca para expandir os grupos com resultados. Os filtros **Todos**, **Somente leitura**,
**Automática**, **Aprovação** e **Desativado** mostram quantas ferramentas correspondem a cada filtro.

Cada ferramenta exibe o título e a descrição no idioma da interface. Os detalhes da ferramenta também exibem a
definição que o modelo recebe, sempre em inglês, independentemente do idioma da interface.

### Servidores MCP

Abra **Ferramentas e recursos → Servidores MCP** para adicionar um servidor, testá-lo e importar suas ferramentas. Cada servidor indica a quem pertence. Os membros também gerenciam servidores pessoais e de equipe nessa tela.

| Configuração | Descrição |
|---|---|
| Transporte | **Streamable HTTP**, **SSE (legado)** para servidores que usam o transporte antigo com HTTP e SSE ou **stdio** apenas para servidores da organização: o MoleSignal inicia o comando no próprio servidor e executa apenas os comandos que a instância lista em `[agent].mcp_stdio_commands`. O comando roda sem shell, recebe `PATH`, `HOME`, `LANG`, `TMPDIR` e as **Variáveis de ambiente** do servidor, roda na pasta temporária do sistema e termina após cada chamada. Insira as credenciais em **Variáveis de ambiente**: a autenticação, os cabeçalhos de solicitação e as credenciais individuais de membro se aplicam aos servidores acessados via HTTP. A política de rede da organização não restringe os destinos que o comando pode acessar. |
| Autenticação | Nenhuma, um token ou uma chave de uso compartilhado, ou **Credencial individual de membro**: cada membro salva um valor pessoal para o cabeçalho especificado pelo servidor, e apenas as chamadas desse membro usam o valor. |
| **Cabeçalhos** | O MoleSignal envia os cabeçalhos em todas as solicitações. Se o nome de um cabeçalho contiver key, token, secret, password, credential, auth ou cookie, o MoleSignal criptografa o valor e exibe apenas os quatro últimos caracteres. Ao editar, deixe um segredo em branco para manter o valor atual. |

**Testar conexão** lista as ferramentas do servidor. **Sincronizar ferramentas selecionadas** importa as ferramentas escolhidas: novas ferramentas permanecem desativadas até que alguém as ative, e o nível mínimo de risco segue as anotações do servidor. **Ferramentas e prompts** exibe um controle de ativação para cada ferramenta, e **Ativar todas as ferramentas somente leitura** ativa todas as ferramentas desse tipo de uma vez. As políticas e aprovações de ferramentas continuam valendo. Os prompts do servidor se tornam comandos no formato `/<server>:<prompt>`.

A cada hora, aproximadamente, o Mole Agent verifica novamente cada servidor sincronizado. Uma ferramenta fica indisponível se o esquema de entrada mudar, se o servidor deixar de listá-la ou se passar a classificá-la com um risco maior. A ferramenta só volta a ficar disponível após revisão e nova sincronização. O Mole Agent não verifica servidores que usam credenciais individuais de membro.

**Importar** lê a configuração MCP do Claude Desktop, Claude Code, Cursor ou VS Code e adiciona os servidores dessa configuração. A importação não inclui valores que fazem referência a variáveis, como `${input:token}`, e lista esses valores para preenchimento. Um servidor com `command` é um servidor stdio: a importação só adiciona esse servidor à organização e apenas se a instância permitir o comando.

Em um servidor que usa credenciais individuais de membro, **Adicionar minha credencial** salva o valor do membro. Se uma conversa chamar uma ferramenta desse servidor sem a credencial ou se o servidor rejeitar o valor salvo, a resposta fica em espera no cartão **Autorizar para continuar**, que identifica a ferramenta e exibe as instruções do servidor. **Salvar e continuar** salva a credencial, assim como **Adicionar minha credencial**, e executa a ferramenta novamente. **Pular** exclui o servidor do restante da resposta. Como a credencial é individual, apenas quem fez a solicitação pode preencher o cartão. Em uma conversa de equipe, os demais participantes veem quem precisa agir. O cartão aguarda por até uma hora. Se não for possível solicitar a credencial, a ferramenta informa que ela está ausente, e o Mole Agent pede ao membro que a adicione.

### Gerenciamento de prompts

Um prompt integrado é somente leitura e aparece com o nome no idioma da interface. Selecione
**Criar substituição** em um prompt integrado para substituí-lo para a organização ou para um usuário.
Antes de definir um prompt da organização como padrão para conversas ou análises de causa raiz, faça a
verificação da organização. Consulte [Qualidade](/pt-BR/quality#verifique-um-prompt-antes-de-defini-lo-como-padrão).

### Limites de execução de um perfil do agente

Os limites valem para cada resposta de conversa que usa o perfil. Sem um perfil ativo, valem os valores padrão:

| Configuração | Padrão | Descrição |
|---|---|---|
| **Máximo de chamadas de ferramentas** | `32` | Número de chamadas de ferramentas por resposta, de 1 a 256. |
| **Duração máxima da investigação (minutos)** | `30` | Tempo limite por resposta, de 1 a 120 minutos. |
| **Temperatura** | `0.2` | Temperatura de amostragem, de 0 a 2. Valores mais baixos geram respostas mais consistentes e reproduzíveis. |

Quando atinge o limite de chamadas ou de tempo, o Mole Agent para de chamar ferramentas e responde com os resultados já obtidos.

### Uso e orçamento

Abra **Mole Agent → Configurações → Uso** para consultar o consumo de tokens da organização hoje, o orçamento diário e o uso nos últimos 30 dias. O cálculo considera cada dia em UTC e soma os tokens de entrada e de saída. As seguintes origens entram no cálculo:

| Origem | Descrição |
|---|---|
| **Conversa** | Conversas do Mole Agent, incluindo a criação de dashboards. |
| **Análise de causa raiz** | Análises automáticas de incidentes ativos e análises sob demanda em um incidente. |
| **Inspeções de logs** | Inspeções imediatas e agendadas. |
| **Funções de LLM** | Etapas de **Resumo por IA** dos [pipelines de alertas](/pt-BR/pipelines/alert-events#resumo-por-ia) e execuções de funções de LLM. |
| **Automações** | Execuções de automações, incluindo as acionadas por incidentes. |
| **Pontuação de qualidade** | Avaliadores e respostas que a verificação de um prompt gera novamente. |

Quando os provedores de modelos têm preços, a página também exibe o custo na moeda de cada provedor. A página exibe custos em moedas diferentes separadamente, sem somá-los. Chamadas a um provedor de modelos sem preços não acrescentam custo ao cálculo. Se o cálculo deixar essas chamadas de fora, a página marca o valor com **≥**: o custo real é pelo menos esse valor.

Por padrão, o orçamento diário usa a configuração `[agent].daily_token_budget` da instância (`0` significa sem limite). Consulte [Configuração](/pt-BR/configuration). Um administrador com a permissão `agent.usage.manage` pode definir um limite **Personalizado** ou selecionar **Sem limite** para a organização e escolher como as conversas e as análises sob demanda se comportam quando o orçamento se esgota:

| Opção | Comportamento |
|---|---|
| **Parar de chamar o modelo** (padrão) | O Mole Agent não envia a pergunta, que permanece no campo de mensagem. A conversa informa que o orçamento de hoje se esgotou e quando será renovado. Uma análise sob demanda recebe a mesma mensagem. |
| **Continuar respondendo e apenas exibir um aviso** | A conversa responde e exibe um aviso acima do campo de mensagem de que o uso ultrapassou o orçamento. |

Quando o orçamento se esgota, as análises automáticas de causa raiz, as inspeções de logs, as etapas de resumo por IA e as funções de LLM param de chamar o modelo: as inspeções falham por falta de orçamento, as análises automáticas aguardam a renovação do orçamento e as etapas de resumo por IA e as funções de LLM falham. Quando o uso atinge o limiar de aviso (80% por padrão, `[agent].budget_warning_percent`), a conversa exibe um aviso acima do campo de mensagem. O Mole Agent verifica o orçamento com base em um status que mantém em cache por cerca de quinze segundos e não interrompe respostas em andamento. Por isso, o uso pode ultrapassar um pouco o limite.

Cada chamada ao modelo também grava uma linha no fluxo interno `_agent_model_traces`. Consulte esse fluxo em **Logs**. Os campos comuns são `origin` (`chat`, `rca`, `inspection`, `llm_eval`, `automation`, `evaluation`, `replay_summary`), `provider`, `model`, `prompt_tokens`, `cached_prompt_tokens` (a parte da entrada que o provedor forneceu a partir do cache), `completion_tokens`, `total_tokens`, `latency_ms`, `cost`, `cost_currency`, `status`, `error`, `tool_calls`, `streaming`, `chat_id`, `user_id`, `profile_id` e `prompt_hash`. O Mole Agent só grava `cost` e `cost_currency` quando o provedor do modelo tem preços. O campo `user_id` identifica o usuário ao qual o Mole Agent atribui a chamada: quem fez a solicitação na conversa ou o usuário em cujo nome a inspeção é executada. As chamadas de análise de causa raiz e de funções de LLM não incluem esse campo.

## Tratamento de dados

O Mole Agent envia a conversa ao provedor de modelos configurado, incluindo os resultados das ferramentas que aciona. Sem um provedor configurado, nenhum dado sai da implantação. Estes controles limitam o que o agente pode acessar:

- **Acesso a dados** limita os ambientes, serviços e fluxos que o perfil padrão pode ler. O acesso entre organizações é sempre proibido.
- **Política de rede** define se o perfil pode usar ferramentas que dependem da rede. Novos perfis bloqueiam o acesso à rede. Essa opção não habilita requisições HTTP arbitrárias nem ferramentas de shell, de navegador ou de MCP abertas.
- **Política de aprovação** exige aprovação para operações de gravação conforme o nível de risco e define se as conversas que usam o perfil podem selecionar **Ignorar permissões**.
- **Skills e servidores MCP** adicionam instruções e ferramentas sem ampliar o escopo da política: as ferramentas permitidas de cada skill e todas as ferramentas MCP seguem os modos de execução e as regras de aprovação da organização.

A chave raiz de criptografia protege as chaves dos modelos. Consulte a [Lista de verificação para produção](/pt-BR/deployment/production-checklist).

## Permissões

- `agent.use` permite acessar o chat e o histórico de execuções e avaliar respostas e análises.
- `agent.investigations.read`, `agent.knowledge.read`, `agent.memories.read`, `agent.skills.read`, `agent.mcp_servers.read` e `agent.usage.read` dão acesso a investigações, conhecimento, memória, skills, servidores MCP e dados de uso. As permissões `.manage` correspondentes permitem alterar os recursos do usuário e das equipes às quais pertence. Para adicionar repositórios, use `agent.skill_repositories.manage`.
- `agent.manage` também dá acesso aos recursos da organização: todos os chats das equipes, além do conhecimento, das skills e dos servidores MCP da organização.
- `agent.models.manage`, `agent.prompts.manage`, `agent.tools.manage`, `agent.toolsets.manage`, `agent.profiles.manage`, `agent.usage.manage`, `agent.network_policy.manage`, `agent.inbound_mcp.manage` e `agent.im.manage` permitem configurar provedores, prompts, ferramentas, conjuntos de ferramentas, perfis, o orçamento diário, a política de rede, o MCP de entrada e os bots de chat. Cada seção de **Configurações** exige apenas as próprias permissões. Sem a permissão de leitura, a seção indica qual permissão é necessária. Sem a permissão `.manage` correspondente, as configurações ficam no modo somente leitura, mas ainda é possível pesquisar e copiar o conteúdo exibido.
- `agent.quality.read` dá acesso à aba **Qualidade**, que reúne pontuações, revisões e avaliadores. `agent.quality.manage` permite alterá-los.
- `agent.automations.read` permite listar automações, `agent.automations.manage` permite criá-las e alterá-las, `agent.automations.run` permite executá-las e `agent.automations.tokens` permite gerenciar os tokens de API dessas automações. Consulte [Automações](/pt-BR/automations#antes-de-começar).
- `agent.approve` permite revisar operações controladas.
