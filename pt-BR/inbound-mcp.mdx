O **MCP de entrada** permite que Claude Code, Cursor, Codex, ChatGPT e outros clientes MCP descubram e
operem o MoleSignal no mesmo ambiente controlado de execução de ferramentas que o Mole Agent usa. O cliente se conecta
de uma das duas formas:

- **stdio** (recomendado): o cliente inicia a CLI do MoleSignal com `molesignal mcp`, do pacote npm
  `@molesignal/cli`. A CLI faz login uma vez pelo navegador e encaminha todas as mensagens ao
  endpoint abaixo.
- **Streamable HTTP**: o cliente chama o endpoint diretamente.

O endpoint é:

```text
https://molesignal.example.com/api/v1/mcp
```

O servidor usa Streamable HTTP e oferece suporte às versões `2026-07-28`,
`2025-11-25`, `2025-06-18` e `2025-03-26` do protocolo MCP. O servidor não expõe o HTTP+SSE legado. A CLI
fornece o transporte stdio.

Administradores com a permissão `agent.inbound_mcp.manage` podem alterar a configuração do servidor em
**Mole Agent → Configurações → MCP de entrada**.

## Antes de conectar

1. Configure `http.external_url` com a origem pública do MoleSignal para qualquer implantação fora da
   interface de loopback. Consulte [Configuração](/pt-BR/configuration).
2. Abra **Mole Agent → Configurações → MCP de entrada** e confirme que o servidor está habilitado.
3. Copie o endpoint completo exibido na página, incluindo o esquema e o host.
4. Escolha OAuth 2.1, um token de API pessoal ou um token de API de conta de serviço.

As alterações nos limites e nas listas de origens permitidas (Origin)
entram em vigor no início da próxima solicitação HTTP do MCP. Uma solicitação em andamento mantém
as configurações do momento em que começou.

## Conecte-se via stdio

Faça login uma vez com a CLI do MoleSignal. Use o Node.js 20 ou uma versão posterior:

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

O navegador abre o MoleSignal para aprovar o login. A CLI salva e renova a credencial em
`~/.config/molesignal/config.json`, arquivo que só o usuário atual pode ler. Em seguida, adicione o MoleSignal ao
cliente como servidor stdio com o comando `npx -y @molesignal/cli mcp`:

| Cliente | Configuração |
|---|---|
| Claude Code | `claude mcp add --scope user molesignal -- npx -y @molesignal/cli mcp` |
| Cursor | `{"mcpServers": {"molesignal": {"command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` em `~/.cursor/mcp.json` |
| Codex | `codex mcp add molesignal -- npx -y @molesignal/cli mcp` |
| VS Code | `{"servers": {"molesignal": {"type": "stdio", "command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` em `.vscode/mcp.json` |
| Gemini CLI | `gemini mcp add molesignal npx -y @molesignal/cli mcp` |

`npx -y @molesignal/cli status` verifica a conexão e conta as ferramentas. Se não houver navegador
disponível, defina `MOLESIGNAL_URL` e `MOLESIGNAL_TOKEN` (um token de API) no ambiente do
servidor em vez de fazer login. Após instalar a CLI com `npm install -g @molesignal/cli`, use o comando
`molesignal`. A documentação da [CLI do MoleSignal](/pt-BR/cli) descreve todos os comandos.

O **Prompt de configuração** em **Mole Agent → Configurações → MCP de entrada** gera essas instruções para
uma ferramenta de agente. Acima do prompt, escolha **stdio** ou **Streamable HTTP**.

<Note>
  Use o mesmo host canônico em todos os lugares. O navegador trata `localhost` e `127.0.0.1` como origens
  distintas para cookies. Misturar os dois pode exigir outro login no MoleSignal ou causar uma incompatibilidade de recurso no OAuth.
</Note>

## Conecte-se com um token de API

Use tokens de API para clientes não interativos e automações.

<Tabs>
  <Tab title="Token de API pessoal">
    Crie um token em **Identidade e acesso → Tokens de API**. O token usa a identidade do usuário atual e
    a função atribuída a esse usuário. Passe o token pelo mecanismo de segredos ou de variáveis de ambiente do cliente como
    `Authorization: Bearer <token>`.
  </Tab>
  <Tab title="Token de API de conta de serviço">
    Crie uma conta de serviço em **Identidade e acesso → Contas de serviço**. Ao criar a conta, o MoleSignal provisiona
    automaticamente um token de API vinculado a ela e exibe o token em texto simples uma única vez.

    Uma conta de serviço é uma identidade não interativa. A conta não pode fazer login na interface Web nem aprovar
    uma concessão OAuth. Passe o token inicial pelo mecanismo de segredos ou de variáveis de ambiente
    do cliente como `Authorization: Bearer <token>`.
  </Tab>
</Tabs>

Nunca inclua um token de API em um commit do arquivo de configuração MCP do projeto. Os exemplos do Codex e do Claude Code
mostram como usar variáveis de ambiente na configuração para uso não interativo.

O MCP de entrada aceita apenas tokens pessoais, tokens de conta de serviço e tokens de acesso OAuth. Credenciais de ingestão e de RUM
não dão acesso a esse endpoint. O MCP nunca retorna credenciais em texto simples por meio de
recursos, ferramentas, histórico de execução ou registros de auditoria.

## Descoberta e validade do OAuth

O MoleSignal publica os metadados do OAuth em:

```text
https://molesignal.example.com/.well-known/oauth-protected-resource/api/v1/mcp
https://molesignal.example.com/.well-known/oauth-authorization-server
```

O servidor de autorização oferece suporte ao fluxo de código de autorização com PKCE `S256`, à vinculação de
recursos conforme a RFC 8707, ao registro dinâmico de clientes, à rotação de tokens de atualização e à revogação de famílias de tokens.
Os tokens de acesso são válidos por uma hora. Os tokens de atualização exigem o escopo `offline_access` e o
tipo de concessão `refresh_token`, são válidos por 30 dias e são substituídos a cada uso.

Revise e revogue conexões OAuth ativas em **Mole Agent → Configurações → MCP de
entrada**. Abaixo da lista de conexões, o **Prompt de configuração** inclui o endpoint desta implantação. Selecione
**Copiar prompt** e cole o prompt em uma ferramenta de agente, como Claude Code ou Cursor, para adicionar o
MoleSignal como servidor MCP.

## Entenda o isolamento entre organizações

Nunca envie `userId` ou `orgId` no endpoint, em um cabeçalho personalizado ou nos argumentos das ferramentas.
O MoleSignal identifica o usuário e a organização pela credencial autenticada, recarrega o estado atual do IAM
a cada solicitação e vincula a sessão MCP à credencial que iniciou a sessão.

O conjunto efetivo de ferramentas é:

```text
Inbound MCP surface ∩ credential IAM permissions ∩ workspace Tool Policy
```

Os perfis de agente não restringem o MCP de entrada. Esse endpoint não atua como proxy para os servidores MCP de saída configurados para o Mole Agent
nem para as ferramentas remotas desses servidores.

Nenhuma credencial permite ler as linhas ou os campos do [fluxo `_audit`](/pt-BR/settings/data-security#fluxo-de-auditoria) pelo MCP de
entrada. Abra o fluxo em **Logs**.

## Comece pelos adaptadores de ferramentas

`tools/list` anuncia um conjunto autorizado restrito: sete ferramentas de leitura comuns, controles de aprovação e execução
e três adaptadores de descoberta progressiva.

| Adaptador | Finalidade |
|---|---|
| `tool_search` | Pesquise no catálogo completo de ferramentas autorizadas do MCP de entrada. |
| `call_read_tool` | Execute uma ferramenta descoberta de somente leitura ou de verificação prévia. |
| `call_managed_tool` | Execute uma alteração gerenciada descoberta com uma `idempotencyKey` obrigatória. |

Exemplos de prompts:

- “Pesquise incidentes recentes com as ferramentas do MoleSignal e resuma o incidente em aberto de maior impacto.”
- “Encontre as ferramentas de páginas de status e liste os incidentes ativos. Não faça alterações.”
- “Teste esta regra de alerta e só atualize a regra após a confirmação ou aprovação obrigatória.”

Consulte [Catálogo e execução de ferramentas](/pt-BR/tools) para ver os esquemas de descoberta, os níveis de risco, o funcionamento das aprovações
e as áreas do produto compatíveis.

## Limites de execução

| Limite | Padrão | Intervalo permitido |
|---|---:|---:|
| Tamanho da solicitação | 1 MB | 1–8 MB |
| Tamanho da resposta | 1 MB | 1–8 MB |
| Chamadas HTTP simultâneas por credencial | 8 | 1–128 |
| Chamadas HTTP por minuto por credencial | 60 | 1–10.000 |
| Tempo limite das ferramentas de leitura | 30 segundos | 100 ms–300 segundos |

Edite esses valores em **Mole Agent → Configurações → MCP de entrada**. A política de ferramentas da organização pode
definir um tempo limite menor ou um limite menor para o tamanho da resposta de uma ferramenta específica.

## Verificações de Origin e Host do navegador

O servidor aceita solicitações sem o cabeçalho `Origin` de clientes MCP que não usam navegador. As solicitações do navegador
devem vir da mesma origem ou corresponder exatamente a uma origem HTTP ou HTTPS configurada no MCP de entrada.

Em implantações que não usam loopback, o `Host` da solicitação deve corresponder a `http.external_url`. Essa verificação
impede ataques de DNS rebinding contra servidores MCP locais.

## Solucione problemas de conexão

| Sintoma | O que verificar |
|---|---|
| `401 missing Authorization Bearer token` | Execute `codex mcp login molesignal` ou configure uma variável de ambiente compatível para o token de API. |
| A página de autorização solicita um novo login | Use o mesmo esquema e host na interface web, em `http.external_url` e no endpoint MCP. Evite misturar `localhost` e `127.0.0.1`. |
| `duplicate field resource` | Remova o `--oauth-resource` configurado manualmente e registre o endpoint novamente. |
| O callback do OAuth informa que a conexão foi recusada | Mantenha o cliente MCP em execução até que o navegador redirecione para o callback temporário no endereço de loopback. Execute `codex mcp login` novamente se o processo que recebe o callback tiver parado. |
| O endpoint MCP retorna `403` | Verifique se o servidor está habilitado e confira a origem do navegador, o status da credencial, a permissão de IAM e a política de ferramentas. |
| Uma ferramenta não aparece | Pesquise com `tool_search`. Se a busca não retornar resultados, verifique se a ferramenta está exposta na interface, além das permissões de IAM e da política de ferramentas. |
