Uma **tabela de extensão** é uma pequena tabela de consulta do MoleSignal que associa chaves a registros. Uma
transformação de [pipeline](/pt-BR/pipelines) consulta uma chave na tabela para enriquecer eventos com dados de referência: associe um
`service` à equipe responsável, um ID de conta a um nível de plano ou um código de região ao nome da região,
sem consultar um armazenamento externo no caminho crítico.

## Lista de tabelas

Abra **Tabelas de extensão**. O cabeçalho mostra o total de tabelas e registros. Cada tabela mostra a chave de consulta e
os campos, o número de registros, onde está em uso, a última atualização e o estado: **Saudável** ou
**Vazia**. Filtre por estado e por uso (**Em uso** ou **Sem uso**) e pesquise por nome.

## Criar uma tabela

Selecione **Nova tabela de extensão**. O assistente tem duas etapas.

<Steps>
  <Step title="Definir o esquema">
    Preencha **Tabela** com o nome e informe uma **Descrição**. Escolha a **Chave de consulta**, o campo que identifica um
    registro, como `customer_id`, `service` ou `region_code`. Ao adicionar **Campos de valor**, informe um nome em **Campo**,
    escolha o **Tipo** (**Texto**, **Número**, **Booleano** ou **Objeto**), indique se o campo é **Obrigatório**
    e informe uma descrição. Deixe os campos de valor em branco para armazenar registros JSON com estrutura flexível. Cada tabela aceita
    até 100 campos de valor. Use letras, dígitos, `.`, `-` e `_` nos nomes dos campos.
  </Step>
  <Step title="Adicionar ou importar dados">
    Selecione **Começar com uma tabela vazia** para adicionar registros depois ou **Colar JSON** para carregá-los agora: use um array JSON de
    registros, cada um com a chave de consulta, ou um objeto que associe cada chave ao registro correspondente.
  </Step>
</Steps>

Selecione **Criar tabela de extensão**.

## Registros

Abra uma tabela. A guia **Registros de dados** lista os registros. Pesquise pela chave de consulta ou pelo valor de um campo.

| Ação | Efeito |
|---|---|
| **Adicionar registro** | Informe a chave de consulta e os valores dos campos no **Modo formulário** ou no **Modo JSON**. Se a chave já existir, o MoleSignal exibe um aviso antes de sobrescrever o registro. |
| **Editar registro** | Altera os valores de um registro. |
| **Exibir JSON** | Mostra o registro completo, incluindo os campos que não aparecem como colunas da tabela. |
| **Excluir registro** | Exclui o registro. Não é possível desfazer a ação. |
| **Importar dados** | Grava vários registros de uma vez a partir de um arquivo JSON (um array ou um mapa de chaves para registros), um arquivo CSV com os nomes dos campos na primeira linha ou dados colados em JSON ou CSV. Os dados devem conter a coluna da chave de consulta. O resumo informa quantos registros a importação vai gravar e quantos vão sobrescrever registros com chaves existentes. |

## Esquema, uso e configurações

| Guia | Conteúdo |
|---|---|
| **Esquema** | Mostra a chave de consulta e os campos de valor. Use **Editar campos** para adicionar campos, alterar descrições e ajustar a opção **Obrigatório**. Enquanto a tabela tiver registros, não é possível renomear campos existentes, mudar o tipo deles nem removê-los. Uma tabela vazia permite todas essas alterações. O nome da tabela e a chave de consulta nunca mudam. |
| **Uso** | Lista os pipelines e as consultas salvas que fazem referência à tabela. Confira a lista antes de alterar ou excluir a tabela. |
| **Configurações** | Mostra **Informações da tabela** e, na **Zona de perigo**, a opção **Excluir tabela de extensão**, que exclui a tabela e todos os registros. Depois da exclusão, as consultas à tabela retornam `null`, e as gravações de eventos nessa tabela falham. Se o pipeline tiver um fluxo de mensagens não entregues, os eventos seguem para esse fluxo. |

## Consultar uma chave em um pipeline

Um pipeline lê a tabela com a etapa [**Consultar uma tabela de extensão**](/pt-BR/pipelines#consultar-uma-tabela-de-extensão),
que copia os valores da linha para os campos do evento, ou com a função
[`lookup(table, key)`](/pt-BR/functions#consultar-tabelas-e-endereços-ip) em uma etapa VRL, que retorna a
linha:

```ruby
# enrich each event with the service's owning team
.team = lookup("service_meta", .service).team
```

As duas opções funcionam em todos os tipos de pipeline, inclusive em [pipelines de alerta](/pt-BR/pipelines/alert-events). Um nó
lê a tabela na primeira vez que uma etapa precisa dela e a mantém na memória por 30 segundos. Assim, as consultas não geram custos de consulta
nem de armazenamento durante a execução do pipeline. Adições, alterações e exclusões de registros chegam a todos os pipelines
em até 30 segundos. As tabelas de extensão pertencem ao espaço de trabalho, e qualquer pipeline desse espaço pode usá-las.

## Preencher uma tabela a partir de um pipeline

Um pipeline agendado pode manter uma tabela atualizada: **Adicionar destino → Tabela de extensão** grava cada evento
que passa pelas etapas do pipeline como uma linha identificada pelo valor da chave de consulta. Consulte
[Gravar em uma tabela de extensão](/pt-BR/pipelines#gravar-em-uma-tabela-de-extensão).

## API de tabelas de extensão

```bash
# upsert a record keyed by "checkout"
curl -X PUT http://localhost:5080/api/v1/extend_tables/service_meta/rows/checkout \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"team":"payments","tier":"gold"}'
```

| Ação | Endpoint |
|---|---|
| Listar tabelas | `GET /api/v1/extend_tables` |
| Listar os registros de uma tabela | `GET /api/v1/extend_tables/{table}` |
| Inserir ou atualizar um registro | `PUT /api/v1/extend_tables/{table}/rows/{key}` |
| Excluir um registro | `DELETE /api/v1/extend_tables/{table}/rows/{key}` |

## Permissões

A permissão `functions.read` permite listar as tabelas e onde estão em uso. Para criar uma tabela, é preciso ter `functions.create`. Para alterar
registros e campos, é preciso ter `functions.edit`. Para excluir uma tabela, é preciso ter `functions.delete`.
