Todos os sinais entram no MoleSignal pela API de ingestão. A página **Fonte de dados** na interface web gera o endpoint, o token e o trecho de configuração para cada origem. Também é possível configurar os mesmos protocolos manualmente.

## Página Fonte de dados

Abra **Fonte de dados** para adicionar uma origem:

1. Pesquise no catálogo ou filtre por categoria: **Recomendado**, **Infraestrutura**, **Nuvem**, **Bancos de dados**, **Mensageria**, **Apps e linguagens**, **Segurança** e **Personalizado**. As abas de sinais (**Logs**, **Métricas**, **Rastreamentos**, **Perfis**) restringem ainda mais a lista.
2. Selecione uma origem, como Kubernetes, um host Linux, AWS, um SDK do OpenTelemetry ou Web RUM.
3. Siga as três etapas do guia:
   - **Endpoint e token** mostra para onde enviar os dados e qual token usar na autenticação. **Mostrar token** exibe o token, o escopo, o espaço de trabalho e a validade. Para uma origem RUM, selecione primeiro o **Aplicativo RUM**: o token de cliente aparece após a seleção.
   - **Configurar a origem** mostra os comandos e a configuração com o endpoint e o token reais já preenchidos.
   - **Verificar se os dados estão chegando** verifica o receptor e depois procura dados recebidos na última hora. **Verificar conexão** executa a verificação imediatamente, e os números são atualizados a cada 30 segundos.
4. Confira o resultado da verificação:
   - **Dados detectados**: os dados chegaram na última hora, e os sinais da origem estão em condições normais. **Ver dados recebidos** abre os dados, e **Criar pipeline** inicia a criação de um pipeline para esses dados.
   - **O receptor está funcionando, mas os dados precisam de atenção**: o receptor responde, mas não chegaram dados ou há sinais com problemas. Verifique a implantação ou aguarde o próximo lote.
   - **Falha na verificação**: não foi possível verificar o receptor. **Possíveis causas** lista um coletor que não está em execução, um token inválido ou expirado e uma rede ou um proxy que bloqueia o endpoint.

O endpoint usa o valor de `http.external_url` quando definido. Caso contrário, usa o endereço no navegador. Defina `http.external_url` ao usar um proxy reverso para que os trechos gerados apontem para o endereço público. Consulte [Configuração](/pt-BR/configuration).

## Tokens de ingestão

Os remetentes se autenticam com um token do tipo Bearer: `Authorization: Bearer <token>`.

| Token | Permissão | Criação | Uso |
|---|---|---|---|
| Token de ingestão padrão | Apenas `logs.write`, `metrics.write`, `traces.write`, `profiles.write` e `apm.deploy`: política **Ingestão de dados** | Página Fonte de dados ou `GET /api/v1/me/api-tokens/default` | Coletores, agentes e exportadores de SDK que enviam logs, métricas e rastreamentos, além de pipelines que [reportam implantações](/pt-BR/apm/deployments#registre-implantações-pela-ci). Não expira. |
| Token de cliente RUM | Apenas `rum.write`, vinculada a um único aplicativo | Página Fonte de dados para origens Web RUM e RUM para dispositivos móveis, ou `GET /api/v1/auth/tokens/rum?applicationId=<id>` | Código executado no navegador ou em dispositivos móveis. O token fica visível para os usuários finais. |
| Token pessoal ou de conta de serviço | Permissões do membro ou da conta de serviço, limitadas pelo escopo do token | **Configurações da conta → Tokens de API** ou **Identidade e acesso → Tokens de API** para contas de serviço | Automações, scripts e clientes MCP. |

Para remetentes que operam continuamente, use o token de ingestão padrão ou um token de conta de serviço que siga a política **Ingestão de dados**. Revogue um token em **Configurações da conta → Tokens de API** ou **Identidade e acesso → Tokens de API** para invalidá-lo imediatamente. A sessão de login da interface web não permite enviar dados: fica armazenada nos cookies do navegador, e o cabeçalho `Authorization` não a aceita.

A página **Fonte de dados** cria um token de cliente RUM ao receber um ID de aplicativo. Um ID de aplicativo contém de 1 a 128 caracteres dentre `A-Z`, `a-z`, `0-9`, `.`, `_`, `:` e `-`. Use o mesmo ID em `applicationId` no SDK. Consulte [SDK do RUM para navegadores](/pt-BR/rum/browser-sdk).

## Endpoints e protocolos

| Protocolo | Endpoint | Remetentes compatíveis | Stream de destino |
|---|---|---|---|
| HTTP com JSON nativo | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`, código do aplicativo, saída `http` do Vector, saída `http` do Fluent Bit | Segmento `{stream}` do caminho |
| OTLP sobre HTTP | `POST /api/v1/logs`, `/api/v1/metrics`, `/api/v1/traces` | SDKs e Collector do OpenTelemetry | Cabeçalho `stream-name` ou, na ausência dele, `default` |
| OTLP sobre gRPC | `:4317` | SDKs e Collector do OpenTelemetry | Metadado `stream-name` ou, na ausência dele, `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus, VictoriaMetrics ou qualquer remetente compatível com remote_write v1 | Cabeçalho `stream-name` ou, na ausência dele, `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat, Logstash, saída `elasticsearch` do Vector | `_index` de cada ação; na ausência desse campo, cabeçalho `stream-name`; na ausência de ambos, `default` |
| Push do Loki (JSON) | `POST /api/v1/loki/api/v1/push` | Remetentes que podem enviar requisições POST com a estrutura JSON do Loki | Cabeçalho `stream-name` ou, na ausência dele, `default` |
| Kinesis Firehose, Cloudflare Logpush, Heroku | `/api/v1/_kinesis_firehose`, `/api/v1/_cloudflare`, `/api/v1/_heroku` | AWS, Cloudflare, Heroku | Definido na configuração do conector. Consulte [Conectores](/pt-BR/connectors). |

Com exceção dos conectores push, todos os endpoints exigem um token do tipo Bearer com a permissão de escrita do sinal: `logs.write`, `metrics.write`, `traces.write` ou `profiles.write`. O token identifica a organização, que nunca aparece na URL.

### Limites que afetam os remetentes

- **Tamanho da requisição.** A ingestão nativa de JSON aceita corpos de requisição de até 16 MiB, medidos após a descompactação. Os demais endpoints de ingestão aceitam até 2 MiB. Os endpoints rejeitam corpos maiores com `413`. Mantenha os lotes abaixo do limite aplicável.
- **Compactação.** OTLP sobre HTTP não aceita corpos de requisição compactados e retorna `400`. Desative a compactação no remetente. O exportador `otlphttp` do OpenTelemetry Collector usa gzip por padrão e exige `compression: none` para desativar a compactação. A ingestão nativa de JSON, o Elasticsearch `_bulk`, o push do Loki e os conectores push aceitam `Content-Encoding: gzip`.
- **Codificação do Loki.** O endpoint decodifica apenas requisições com a estrutura JSON do Loki. Promtail e Grafana Alloy enviam protobuf compactado com Snappy por padrão e não conseguem enviar dados a esse endpoint.
- **Limite de taxa.** A função `router` limita as requisições por organização e retorna `429` com o cabeçalho `Retry-After`. Um nó `standalone` não aplica esse limite. Consulte [Implantação por função](/pt-BR/deployment/role-based#limitação-de-taxa).
- **Streams da plataforma.** Apenas o MoleSignal grava nos [streams da plataforma](/pt-BR/streams#fluxos-da-plataforma), como `_molesignal` para a telemetria do próprio serviço e `_audit` para a trilha de auditoria. Esses streams rejeitam a ingestão pública com `403`.

## Streams e esquema

O MoleSignal cria um stream na primeira gravação e atualiza o esquema à medida que surgem novos campos. O nome e o tipo de sinal identificam o stream. Assim, `default` pode existir para logs, métricas e rastreamentos ao mesmo tempo. Consulte [Streams](/pt-BR/streams).

Cada evento tem um carimbo de data e hora em microssegundos desde a época Unix. A ingestão nativa de JSON e o Elasticsearch `_bulk` leem o campo `_timestamp`. Se o evento não tiver `_timestamp`, o servidor atribui o horário em que o aceitou.

## HTTP com JSON nativo

Envie um array de registros com POST para `/api/v1/intake/{logs,metrics,traces}/{stream}`:

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

A resposta informa quantos registros o endpoint aceitou e rejeitou, com o motivo da rejeição para cada índice correspondente:

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

Aponte um SDK ou Collector do OpenTelemetry para o caminho base `/api`. O exportador acrescenta `/v1/logs`, `/v1/metrics` e `/v1/traces`, que correspondem a `/api/v1/logs`, `/api/v1/metrics` e `/api/v1/traces`.

<Tabs>
  <Tab title="OTLP via HTTP">
    Variáveis de ambiente do SDK:

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    Envie os dados em protobuf (`application/x-protobuf`), a codificação padrão dos SDKs e do Collector. Os endpoints de logs, métricas e rastreamentos também aceitam JSON (`application/json`). Adicione o cabeçalho `stream-name` para selecionar um fluxo diferente de `default`. O cabeçalho se aplica a todos os sinais que o exportador envia.
  </Tab>
  <Tab title="OTLP via gRPC">
    O receptor OTLP via gRPC escuta na porta `4317` e atende aos serviços de logs, métricas, rastreamentos e perfis. O receptor não faz a terminação TLS. Para o tráfego que sai de uma rede confiável, faça a terminação TLS antes que o tráfego chegue ao receptor.

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    Remova `insecure: true` se houver um proxy que faça a terminação TLS antes da porta. A porta `5082` é a porta gRPC interna do cluster e não recebe tráfego OTLP.
  </Tab>
</Tabs>

O MoleSignal armazena as métricas OTLP como um evento por ponto de dados. Consulte o [contrato de armazenamento de métricas](/pt-BR/query#campos-de-métricas-otlp) para saber quais campos o MoleSignal armazena.

## Prometheus remote_write

Adicione o MoleSignal como destino de gravação remota em `prometheus.yml`:

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

Cada fluxo de métricas contém dados de uma única origem. Use o cabeçalho `stream-name` (`headers:` na entrada `remote_write`) para atribuir um fluxo próprio a cada servidor Prometheus. Sem esse cabeçalho, as amostras vão para `default`. Cada amostra gera uma linha com o valor de `__name__` no campo `metric_name`. Os demais rótulos viram campos. Se um rótulo tiver o mesmo nome de um campo de métrica, como `metric_name`, o MoleSignal o mantém como `exported_<name>`. O MoleSignal ignora histogramas nativos e metadados de métricas e armazena os exemplares junto com as amostras.

## Elasticsearch bulk

Clientes que usam o protocolo bulk do Elasticsearch funcionam sem depender de Loki ou OTLP:

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

O campo `_index` de cada ação seleciona o fluxo de destino. Na ausência desse campo, o MoleSignal usa o cabeçalho `stream-name`. Se o cabeçalho também estiver ausente, usa `default`.

## Loki push

O endpoint aceita o formato de requisição JSON do Loki:

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

Os rótulos viram campos, e a linha de log vira o campo `message`. O endpoint converte o carimbo de data e hora de nanossegundos para microssegundos e retorna `204`. Selecione o fluxo de destino com o cabeçalho `stream-name`.
