| Endpoint | Autenticação |
|---|---|
| `GET /api/v1/healthz` | Nenhuma |
| `GET /metrics` | Nenhuma |
| `GET /api/v1/readyz` | Token de portador |
| `GET /api/v1/version` | Token de portador |

## Verificação de atividade

```http
GET /api/v1/healthz
```

A verificação composta de integridade retorna `200` quando o nó está íntegro e `503` com um `reason` quando o armazenamento de objetos está inacessível. Use-a nas verificações de contêineres e balanceadores de carga.

<ResponseExample>
```json 200
{ "status": "ok" }
```
</ResponseExample>

## Verificação de prontidão

```http
GET /api/v1/readyz
Authorization: Bearer <token>
```

A verificação de prontidão para receber tráfego retorna `200` assim que o nó inicia, pois a inicialização não precisa reprocessar dados. A degradação do armazenamento de objetos não impede o nó de atender ao tráfego somente leitura. A solicitação exige um token de portador, portanto uma verificação sem credenciais recebe `401`. Use `/api/v1/healthz` quando a verificação não puder enviar um token.

<ResponseExample>
```json 200
{ "status": "ready" }
```
</ResponseExample>

## Versão

```http
GET /api/v1/version
Authorization: Bearer <token>
```

Retorna a versão do produto, o commit e a branch, a data e a hora do build, o ID do build, o canal de lançamento e a edição.

<ResponseExample>
```json 200
{
  "version": "26.1.0.0",
  "commit": "<git-sha>",
  "branch": "main",
  "buildEpochSecs": 1790000000,
  "buildId": "<build-id>",
  "releaseChannel": "alpha",
  "edition": "oss"
}
```
</ResponseExample>

## Métricas

```http
GET /metrics
```

Expõe métricas do processo e dos subsistemas no formato Prometheus (`text/plain; version=0.0.4`), como taxas de acerto de `cache_*`, `wal_*`, `object_store_*` e `storage_reconciler_issues_total`. Restrinja o acesso a esta rota no proxy ou na camada de rede. Consulte [Auto-observabilidade](/pt-BR/self-observability).
