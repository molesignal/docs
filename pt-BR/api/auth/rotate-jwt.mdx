As duas rotas exigem uma sessão com escopo de sistema e a permissão `sys.signing_keys.rotate`. Uma sessão com escopo de organização ou um token de API recebe `403`. Alterne a sessão para a organização `_sys` com [Selecionar um espaço de trabalho](/pt-BR/api/auth/select-organization).

## Listar chaves de assinatura

```http
GET /api/v1/auth/jwt/secrets
```

Retorna os metadados das chaves de assinatura. A rota nunca retorna os bytes brutos das chaves.

<ResponseExample>
```json 200
[
  {
    "id": "3JtcPZ3AZJFyvBvSkJUia0N7wqo",
    "isPrimary": true,
    "createdAt": 1790000000000000,
    "retiredAt": null
  }
]
```
</ResponseExample>

## Rotacionar chaves

```http
POST /api/v1/auth/jwt/rotate
```

Cria uma nova chave primária e desativa a anterior. A nova chave assina os novos tokens. Os tokens assinados com uma chave desativada continuam válidos por 24 horas após a desativação.

Nenhum nó precisa ser reiniciado. Cada nó aceita sessões assinadas com a nova chave desde a primeira requisição e começa a usá-la para assinar em cerca de 10 segundos. O sistema deixa de usar uma chave desativada para verificar tokens 5 minutos após o fim do período de 24 horas, o que compensa esse atraso e as diferenças entre os relógios dos nós.

<ResponseExample>
```json 200
{
  "newKid": "<new-key-id>",
  "retiredKid": "<previous-key-id>",
  "activeCount": 2
}
```
</ResponseExample>

`activeCount` indica o número de chaves usadas no momento para verificar tokens. Uma implantação que fixa a chave de assinatura com `MS_AUTH_JWT_SECRET_OVERRIDE` segue a própria política de rotação. Consulte [Segurança e multilocação](/pt-BR/security#chaves-de-assinatura-de-jwt).
