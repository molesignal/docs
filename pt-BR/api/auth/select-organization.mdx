```http
POST /api/v1/orgs/{id}/select
```

Altera a organização da sessão autenticada no navegador para outra organização da qual o usuário faz parte. A resposta regrava os cookies da sessão para a organização selecionada, sem alterar o horário de expiração. Consulte [Entrar](/pt-BR/api/auth/login) para saber mais sobre os cookies. Só é possível trocar de organização em uma sessão: uma solicitação com token de API recebe `403`. Administradores da plataforma podem selecionar a organização protegida `_sys`, necessária para chamadas que afetam toda a plataforma, como [Rotacionar chaves de assinatura JWT](/pt-BR/api/auth/rotate-jwt). A sessão em `_sys` termina em até uma hora após a troca.

**Parâmetros de caminho**

| Parâmetro | Tipo | Observações |
|---|---|---|
| `id` | string | ID da organização retornado por `GET /api/v1/orgs`. |

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -c ms-cookies.txt \
  -X POST http://localhost:5080/api/v1/orgs/<organization-id>/select
```
</RequestExample>

<ResponseExample>
```json 200
{
  "userId": "<user-id>",
  "orgId": "<organization-id>",
  "orgName": "default",
  "displayRole": "Owner",
  "roles": [
    { "id": "<role-id>", "key": "owner", "name": "Owner", "builtin": true }
  ],
  "system": false
}
```
</ResponseExample>

As abas do navegador compartilham os mesmos cookies. Por isso, todas as abas abertas passam a usar a organização selecionada.

## Requisitos de autenticação

Se a autenticação atual não atender a todos os [requisitos de autenticação](/pt-BR/identity/sso#requisitos-de-login) da organização, a resposta ainda retorna `200`, sem definir novos cookies, e indica o que falta:

| Resposta | Significado |
|---|---|
| `{"mfa": {"organization_name", "methods"}}` | Valide um segundo fator na hora: reenvie a solicitação com `{"proof": {…}}` no corpo. Use `method` (`totp` ou `recovery_code`) com `code`, ou `method` com o valor `passkey` e os campos `ceremony` e `credential` de `POST /api/v1/me/mfa/passkey-proof`. |
| `{"mfaSetup": {"organization_name"}}` | A conta não tem um segundo fator. Antes de continuar, configure um em `/api/v1/me/mfa` ou `/api/v1/me/passkeys`. |
| `{"sso": {"organization_name", "providers"}}` | O acesso só é permitido pelo login único (SSO) da organização. `providers` lista `id`, `name`, `kind` e `platform`. |
