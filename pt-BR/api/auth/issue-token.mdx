```http
POST /api/v1/me/api-tokens
```

Emite um token pessoal no formato `mspat-<36>` que atua em nome do usuário autenticado. O token em texto simples só aparece na resposta. Guarde-o imediatamente. Faça a chamada a partir de uma sessão autenticada, nunca com outro token. A chamada exige `personal_tokens.manage`.

**Corpo**

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `name` | string | Sim | Nome de exibição, de 1 a 255 caracteres. |
| `policyId` | string | Não | ID da [política de permissões](/pt-BR/identity/roles#políticas-de-permissão) que o token segue, como `builtin:data_intake`. É necessário ter todas as permissões da política. |
| `permissions` | string[] | Não | Permissões da organização fixadas para o token. É necessário ter cada uma delas. |
| `expiresInDays` | integer | Não | Validade em dias, de 1 a 1825. Omita o campo para emitir um token que nunca expira. |

Informe `policyId` ou `permissions`, mas não ambos. Sem nenhum dos dois, o token tem as mesmas permissões do usuário. O token nunca excede as permissões do usuário no momento da solicitação. Se o usuário perder uma permissão, os tokens também a perdem.

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -X POST http://localhost:5080/api/v1/me/api-tokens \
  -H 'content-type: application/json' \
  -d '{
    "name": "grafana-readonly",
    "permissions": ["streams.read", "streams.query", "dashboards.read"],
    "expiresInDays": 90
  }'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KE5hOsEc3lMC9qr9RWnPn0pqWF",
  "prefix": "k7m2q9xv4b",
  "name": "grafana-readonly",
  "tokenKind": "personal",
  "userId": "<user-id>",
  "policyId": null,
  "permissions": ["dashboards.read", "streams.query", "streams.read"],
  "applicationId": null,
  "serviceAccountId": null,
  "expiresAt": 1798000000000000,
  "lastUsedAt": null,
  "revoked": false,
  "createdAt": 1790000000000000,
  "token": "mspat-k7m2q9xv4b<secret>"
}
```
</ResponseExample>

O arquivo `ms-cookies.txt` armazena a sessão iniciada em [Entrar](/pt-BR/api/auth/login). `GET /api/v1/me/api-tokens/scopes` lista as políticas e as permissões da organização às quais é possível restringir um token. Envie o token no cabeçalho `Authorization`: `Authorization: Bearer mspat-…`.

## Para uma conta de serviço

```http
POST /api/v1/auth/tokens
```

Emite um token que atua em nome de uma conta de serviço. O corpo é o mesmo, com o acréscimo de `serviceAccountId`, e a chamada exige `api_tokens.issue`. Ao contrário de um token pessoal, é possível emitir esse token com um token de API. Sem `policyId` nem `permissions`, o token fica restrito às permissões da função da conta que o emissor possui no momento da emissão. Se a função ganhar uma permissão depois, o token não a recebe. Se a função perder uma permissão, o token perde o acesso imediatamente.

```bash
curl -X POST http://localhost:5080/api/v1/auth/tokens \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "collector-production",
    "serviceAccountId": "<service-account-id>",
    "policyId": "builtin:data_intake",
    "expiresInDays": 365
  }'
```

**Erros**

| Status | Causa |
|---|---|
| `400` | `name` vazio, `policyId` e `permissions` informados juntos, lista vazia, permissão ou política desconhecida, ou conta de serviço desativada. |
| `403` | O escopo inclui uma permissão que o solicitante não possui, a solicitação de token pessoal usa um token de API ou falta a permissão exigida (`personal_tokens.manage` ou `api_tokens.issue`). |
| `404` | O escopo do sistema não tem tokens de API ou a conta de serviço não existe. |
