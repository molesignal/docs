A API de APM disponibiliza dados agregados dos spans de traces no escopo da organização. Todos os endpoints usam o
prefixo `/api/v1/apm` e exigem um token bearer.

```http
Authorization: Bearer <token>
```

Um espaço de trabalho da organização exige a permissão de leitura da área: `apm.services.read`, `apm.errors.read`,
`apm.error_rules.read`, `apm.definitions.read`, `apm.slos.read`, `apm.deployments.read` ou `apm.settings.read`. As chamadas da plataforma podem usar
`sys.telemetry.read` no escopo protegido `_sys`. Cada operação de gravação indica a permissão necessária. Para registrar um deploy, é necessário ter
`apm.deploy`.

## Endpoints

| Método e caminho | Resposta |
|---|---|
| `GET /api/v1/apm/overview` | Resumo e tendências das métricas RED de todos os serviços, integridade dos serviços e sua evolução, rankings, deploys, ambientes, lacunas de instrumentação, principais transações, dependências e erros. |
| `GET /api/v1/apm/insights` | Mudanças em relação ao período anterior e ao mesmo período da semana anterior, versões com pior desempenho, oportunidades de reduzir o tempo de execução e mudanças ocorridas em momentos próximos a cada uma delas. |
| `GET /api/v1/apm/services` | Catálogo paginado de serviços com instrumentação, versões, integridade, métricas RED e filtros de traces. |
| `GET /api/v1/apm/services/{service}` | Resumo, tendência, transações, dependências, erros e versões do serviço. |
| `GET /api/v1/apm/services/{service}/instances` | Instâncias de um serviço em um ambiente, com a versão, os atributos de recurso e o tráfego que cada uma atendeu. |
| `GET /api/v1/apm/services/{service}/coverage` | Indica se o MoleSignal recebeu logs, métricas, perfis e sessões de navegador do serviço nas 24 horas anteriores a `to`. |
| `GET /api/v1/apm/transactions` | Métricas RED paginadas das transações e ranking por tempo total. |
| `GET /api/v1/apm/transactions/{transaction}` | Tendência da transação, erros associados, versões e filtros de traces. |
| `GET /api/v1/apm/dependencies` | Métricas RED paginadas dos pares de serviços chamadores e dependências, com ranking por tempo total. |
| `GET /api/v1/apm/map` | Mapa de serviços de um ambiente e namespace: serviços, destinos das chamadas, tópicos e chamadas entre eles. |
| `GET /api/v1/apm/map/edge` | Uma conexão no mapa: tendência das chamadas, solicitações feitas por essa conexão e erros do serviço chamado. |
| `GET /api/v1/apm/blast-radius` | Alcance de um serviço no mapa: quais serviços o chamam e quais ele chama, um salto por vez. |
| `GET /api/v1/apm/errors` | Grupos paginados de erros sanitizados do back-end, com os locais das ocorrências. |
| `GET /api/v1/apm/errors/{fingerprint}` | Tendência do erro, transações e versões afetadas, locais das ocorrências do grupo, stack trace representativo e número limitado de amostras. |
| `GET /api/v1/apm/versions/compare` | Métricas RED da versão de referência e da candidata, diferenças, indicação de suficiência dos dados e regressões. |
| `GET /api/v1/apm/health` | Status da projeção do tenant, integridade do runtime, limites e lacunas. |
| `GET /api/v1/apm/service-definitions` | Todas as definições de serviço da organização. |
| `PUT /api/v1/apm/service-definitions/{service}?namespace=` | Crie ou substitua a definição de um serviço. Requer `apm.definitions.manage`. |
| `DELETE /api/v1/apm/service-definitions/{service}?namespace=` | Exclua a definição de um serviço. Requer `apm.definitions.manage`. |
| `POST /api/v1/apm/service-definitions/{service}/key-transactions?namespace=` | Marque um endpoint com uma estrela para defini-lo como transação principal do serviço ou remova a estrela. Requer `apm.definitions.manage`. |
| `PUT /api/v1/apm/errors/{fingerprint}/issue` | Defina o estado, a equipe e o responsável por um grupo de erros. Requer `apm.errors.manage`. |
| `GET /api/v1/apm/error-rules` | Regras de agrupamento de erros da organização, na ordem de avaliação. |
| `POST /api/v1/apm/error-rules` | Crie uma regra de agrupamento. O sistema avalia a nova regra após as demais. Requer `apm.error_rules.manage`. |
| `PUT /api/v1/apm/error-rules/{id}` | Substitua uma regra de agrupamento. Requer `apm.error_rules.manage`. |
| `DELETE /api/v1/apm/error-rules/{id}` | Exclua uma regra de agrupamento. Requer `apm.error_rules.manage`. |
| `PUT /api/v1/apm/error-rules/order` | Defina a ordem de avaliação das regras. Requer `apm.error_rules.manage`. |
| `GET /api/v1/apm/slos` | Todos os objetivos de nível de serviço, com estado, resultado atingido, orçamento de erro restante e taxas de consumo. |
| `GET /api/v1/apm/slos/{id}` | Status de um objetivo de nível de serviço e dados de cada dia da janela. |
| `POST /api/v1/apm/slos` | Crie um objetivo de nível de serviço. Requer `apm.slos.manage`. |
| `PUT /api/v1/apm/slos/{id}` | Substitua um objetivo de nível de serviço. Requer `apm.slos.manage`. |
| `DELETE /api/v1/apm/slos/{id}` | Exclua um objetivo de nível de serviço. Requer `apm.slos.delete`. |
| `POST /api/v1/apm/deployments` | Registre um deploy. Requer `apm.deploy`. |
| `GET /api/v1/apm/deployments` | Deploys registrados pelos pipelines, dos mais recentes aos mais antigos. |
| `GET /api/v1/apm/settings` | Configurações de APM da organização ou valores padrão quando não há configurações salvas. |
| `PUT /api/v1/apm/settings` | Substitua as configurações de APM da organização. Requer `apm.settings.manage`. |

Codifique os parâmetros de caminho para uso na URL. Use o nome exato de `transaction` ou o `fingerprint` do erro
que a resposta de listagem retornar.

## Parâmetros de consulta comuns

| Parâmetro | Tipo | Comportamento |
|---|---|---|
| `from` | inteiro | Início do intervalo em microssegundos desde a época Unix. Por padrão, 24 horas antes de `to`. |
| `to` | inteiro | Fim do intervalo em microssegundos desde a época Unix. Por padrão, o horário atual. |
| `namespace` | string | Filtra pelo namespace exato do serviço. |
| `service` | string | Filtra pelo nome exato do serviço. O caminho de detalhes do serviço tem precedência sobre esse valor. |
| `environment` | string | Filtra pelo ambiente exato do deploy. |
| `version` | string | Filtra pela versão exata do serviço. |
| `resolution` | enum | `auto`, `minute` ou `hour`. `auto` seleciona a resolução dos dados retidos para o intervalo. |
| `sort` | string | Campo de ordenação específico do endpoint. |
| `direction` | enum | `asc` ou `desc`. O padrão é `desc`. |
| `limit` | inteiro | Tamanho da página, de 1 a 200. O padrão é 50. |
| `cursor` | string | Cursor opaco de uma resposta de listagem anterior. |
| `status` | enum | Somente em `/errors`: `all` (padrão), `unresolved` (grupos em aberto, em investigação ou que voltaram a ocorrer após a resolução), `investigating`, `resolved` ou `ignored`. |

Use valores de filtro não vazios e com no máximo 192 bytes. O intervalo não pode exceder o limite
configurado, que por padrão é de 30 dias (`[apm].max_query_range_days`).

### Campos de ordenação

| Endpoint | Valores de `sort` aceitos | Padrão |
|---|---|---|
| `/services` | `requestCount`, `errorRate`, `p95`, `name` | `requestCount` |
| `/transactions` | `requestCount`, `errorRate`, `p95`, `total_time` | `requestCount` |
| `/dependencies` | `requestCount`, `errorRate`, `p95`, `total_time` | `total_time` |
| `/errors` | `occurrenceCount`, `errorRate`, `lastSeen` | `occurrenceCount` |

`/overview` aceita os mesmos filtros e a mesma resolução, mas não usa paginação. Os endpoints de detalhes, comparação e
integridade não retornam listas paginadas.

## Consulte a visão geral

<RequestExample>
```bash cURL
NOW=$(date +%s)000000
curl --get 'http://localhost:5080/api/v1/apm/overview' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode "from=$((NOW-86400000000))" \
  --data-urlencode "to=$NOW" \
  --data-urlencode 'environment=production' \
  --data-urlencode 'resolution=auto'
```
</RequestExample>

A resposta inclui `red`, `trend`, `serviceHealth`, `services`, `topTransactions`,
`topDependencies`, `topErrors` e `recentVersions`, além do objeto comum `meta` e dos campos a seguir:

| Campo | Observações |
|---|---|
| `serviceCount`, `activeServiceCount` | Número de serviços observados no intervalo e número dos que atenderam a pelo menos uma requisição. |
| `healthTrend` | Número de serviços em cada estado por faixa. O intervalo tem no máximo 48 faixas, nenhuma mais curta que um bucket. Um serviço sem requisições em uma faixa conta como `noTraffic` nessa faixa. |
| `rankings` | `slowest` (por p95), `mostErrors` (por taxa de erros) e `busiest` (por volume de requisições), com cinco serviços em cada lista. As duas primeiras incluem apenas serviços com pelo menos 20 requisições. |
| `deployments` | Até 20 versões observadas pela primeira vez no intervalo, da mais recente para a mais antiga. Cada versão inclui `red` e `verdict`, como em [Versões de um serviço](#consulte-as-versões-de-um-serviço). |
| `environments`, `availableEnvironments` | Serviços e requisições por ambiente na visualização e todos os ambientes em que os serviços são executados, independentemente do filtro `environment`. |
| `instrumentation` | Número de serviços por linguagem e SDK e número de serviços que não informam `deployment.environment`, `service.version` ou `service.instance.id`. |

## Consulte os insights

`GET /api/v1/apm/insights` aceita os parâmetros comuns de intervalo e filtro e retorna `meta` e os campos a seguir:

| Campo | Observações |
|---|---|
| `now`, `previous`, `lastWeek` | Métricas dos serviços na visualização para o intervalo, para o período imediatamente anterior de mesma duração e para o intervalo equivalente uma semana antes: `requestCount`, `throughput` em requisições por segundo, `errorRate`, `p95Time` e `apdex`. A resposta omite períodos sem requisições. |
| `insights` | Até 30 constatações, das mais urgentes para as menos urgentes. |

Cada constatação inclui:

| Campo | Observações |
|---|---|
| `kind` | `anomaly`, `regression`, `slow_dependency`, `repeated_call`, `slowQuery` ou `hot_endpoint`. |
| `severity` | `critical`, `warning` ou `info` no caso de uma sugestão. |
| `service` | `namespace`, `name` e `environment`. |
| `transaction`, `dependency` | O endpoint em destaque ou a dependência associada a um gargalo, a uma chamada repetida ou a uma instrução lenta. |
| `metric` | A métrica que mudou ou piorou: `errorRate`, `p95` ou `throughput`. |
| `value` | O valor atual: taxa de erros em forma de proporção, P95 em microssegundos ou requisições por segundo. Para um gargalo ou endpoint em destaque, indica a proporção do tempo total. Para uma chamada repetida, indica o número de chamadas por requisição. Para uma instrução lenta, indica o P95 em microssegundos. |
| `previous`, `lastWeek` | O mesmo valor para o período imediatamente anterior e para o período equivalente uma semana antes. Para uma regressão, indica o valor da versão anterior. |
| `since` | Quando a mudança começou ou quando a versão com regressão apareceu pela primeira vez. |
| `version`, `previousVersion` | A versão com regressão e a versão anterior. |
| `calls`, `p95Time` | O número de chamadas ou requisições em que a sugestão se baseia e o P95 delas. |
| `changes` | Alterações próximas a `since`, da mais próxima para a mais distante: `kind`, `source` (`reported` ou `observed`), `service`, `version`, `status`, `at`, `downstream` (`true` para um serviço que o serviço afetado chama), `commit` e `description`. |

Consulte os limites em [Insights e investigações](/pt-BR/apm/insights#o-que-os-insights-detectam).

## Consulte as métricas RED

Cada resumo inclui um objeto `red` com as métricas de requisições, erros e duração do intervalo.

| Campo | Observações |
|---|---|
| `requestCount`, `errorCount`, `errorRate` | Total de requisições, total de requisições com falha e proporção de requisições com falha em relação ao total, de 0 a 1. |
| `durationSum`, `durationAverage` | Duração total e média em microssegundos. Sem requisições, a média é `null`. |
| `p50Time`, `p90Time`, `p95Time`, `p99Time` | Percentis de latência em microssegundos, estimados dentro do bucket do histograma que contém a posição de cada percentil. Com a estrutura padrão, o valor fica a cerca de 4% ou menos da duração exata. Sem requisições, o valor é `null`. |
| `apdex` | Número de requisições dentro do limite T mais metade das que ficam entre T e 4T, dividido pelo total de requisições. O resultado varia de 0 a 1. T corresponde a `apdexThreshold` do serviço ou, se não definido, a 500 ms. A visão geral usa 500 ms para as métricas agregadas de todos os serviços. Requisições com falha nunca contam como satisfatórias. Sem requisições, o valor é `null`. |
| `latencyPartial` | `true` quando não é possível identificar o esquema de latência de alguns buckets. O cálculo converte e inclui os buckets de um esquema anterior (`[apm.histogram].schema_version`). Os percentis excluem os buckets ilegíveis, mas as contagens, a soma e a média ainda os incluem. |
| `timeoutCount`, `retryCount` | Requisições que excederam o tempo limite (erro do tipo timeout, gRPC `DEADLINE_EXCEEDED`, HTTP 408 ou 504) e requisições reenviadas (`http.request.resend_count` acima de 0). A resposta omite cada campo quando a contagem correspondente é zero. |
| `statusCodes` | Respostas por código de status, no formato `http:<code>` (100 a 599) ou `grpc:<code>` (0 a 16). Cada bucket armazena até 24 códigos e agrupa os demais em `http:other` ou `grpc:other`. A resposta omite o campo quando nenhum código entra na contagem, como em agregados gerados antes da contagem de códigos. |
| `exemplars` | Até 8 spans de exemplo do intervalo, do mais lento para o mais rápido. O sistema seleciona o span antes que a [amostragem na cauda](/pt-BR/configuration#captura-de-traces-e-amostragem-ao-final) decida se mantém o trace correspondente. Por isso, `traceAvailable` geralmente é `false`. Consulte o trace para verificar se o sistema o manteve. O agregado continua válido. |

Os resumos de serviços e transações incluem `apdexThreshold`, o limite T usado para calcular o Apdex.
O resumo de um serviço também inclui `health` e `healthReasons`. Para cada métrica que ultrapassa o limite, informa `metric`
(`errorRate` ou `p95`), `level`, `value` e `threshold`. O campo `sparkline` inclui o total de requisições, o total de erros e o p95 de cada bucket.
Os campos `currentVersion` e `currentVersionSince` indicam a versão observada mais recentemente e quando ela
apareceu pela primeira vez. Os detalhes de um serviço ou de uma transação incluem `latencyDistribution`: os buckets do histograma
que contêm requisições, cada um com `lowerTime`, `upperTime` e `count`. Os limites da distribuição correspondem às durações da
requisição mais rápida e da mais lenta.

## Mantenha as definições dos serviços

Uma definição registra quem é responsável por um serviço e qual é sua importância. A chave combina `namespace` e o
nome do serviço. Assim, a definição vale em todos os ambientes e pode existir antes que o serviço envie dados.

```http
PUT /api/v1/apm/service-definitions/checkout?namespace=shop
Content-Type: application/json

{"description": "Takes orders and payments.", "teamId": "<team id>", "ownerId": "<user id>", "tier": "p0", "lifecycle": "production", "repositoryUrl": "https://github.com/acme/checkout", "tags": {"domain": "orders", "pci": ""}, "apdexThreshold": 300000, "aliases": ["order_service", "Order Center"], "dataSources": {"logs": [{"stream": "default", "filter": "service_name = 'order_service'"}], "metrics": [{"selector": "{service=\"checkout\"}"}], "dashboards": ["<dashboard id>"], "links": [{"name": "Runbook", "url": "https://wiki.example.com/checkout"}]}, "archived": false}
```

| Campo | Observações |
|---|---|
| `description` | Até 2.000 caracteres. |
| `teamId` | Uma equipe da organização ou `null`. Excluir a equipe limpa o campo. |
| `ownerId` | Um membro da organização ou `null`. |
| `tier` | De `p0`, o nível mais importante, a `p5`, ou `null`. |
| `lifecycle` | `production`, `staging`, `experimental`, `deprecated` ou `null`. |
| `repositoryUrl` | Uma URL `http`, `https`, `ssh`, `git` ou `git+ssh`, ou `user@host:path`, sem espaços e com até 2.048 caracteres, ou `null`. O sistema salva senhas e a parte do usuário de endereços HTTP(S) como `****`. O catálogo exibe esse valor quando o serviço não informa um repositório. |
| `tags` | Até 32 tags no formato `{ "key": "value" }`. A chave tem de 1 a 64 caracteres: letras minúsculas, dígitos e `_ . - /`. O valor tem até 128 caracteres, sem espaços nas extremidades. Use um valor vazio para uma chave sem valor. |
| `apdexThreshold` | O limiar T de Apdex do serviço, maior que 0 e de até 60.000.000 (um minuto), ou `null` para usar 500 ms. |
| `aliases` | Até 20 nomes alternativos do serviço em logs, métricas e outros sistemas, cada um com 1 a 128 caracteres, sem espaços nas extremidades. A comparação não distingue maiúsculas de minúsculas. Não repita nomes nem use o nome do próprio serviço ou o nome principal ou alternativo de outro serviço da organização. Se omitir o campo, a definição mantém os nomes salvos. |
| `dataSources` | Fontes de dados do serviço: `logs` (`stream` e `filter` opcional, uma expressão booleana SQL de até 2.000 caracteres), `metrics` (`selector`, um seletor PromQL como `{service="checkout"}`), `dashboards` (IDs de dashboards) e `links` (`name` e uma `url` `http` ou `https`), até 10 de cada tipo. Se omitir o campo, a definição mantém as fontes salvas. |
| `archived` | `true` oculta o serviço da visualização padrão do catálogo. Se omitir o campo, a definição mantém o estado salvo. |

Ao salvar, o sistema preserva `keyTransactions` da definição. Altere essas transações uma por vez. A resposta contém a
definição salva com `namespace`, `name`, `keyTransactions`, `updatedBy` e `updatedAt`.
`DELETE` retorna `204` ou `404` se o serviço não tiver uma definição.

### Marque transações como principais

```http
POST /api/v1/apm/service-definitions/checkout/key-transactions?namespace=shop
Content-Type: application/json

{"transaction": {"name": "POST /orders", "kind": "http"}, "key": true}
```

`key: true` adiciona o endpoint a `keyTransactions`, e `false` o remove. Repetir a solicitação para o estado atual
não altera nada. Se o serviço não tiver uma definição, o sistema cria uma. Cada serviço aceita até 50 transações
principais. A linha `__other__`, que agrupa os itens excedentes, não pode ser uma delas. A resposta contém a definição após
a alteração.

## Consulte a cobertura de um serviço

`GET /api/v1/apm/services/{service}/coverage` exige `namespace` e `environment` e
aceita `to`, o fim do intervalo em visualização, em microssegundos (o momento atual por padrão). A consulta analisa o dia
anterior a `to` e mantém cada resposta em cache por cinco minutos.

```json
{
  "from": 1792230096695000,
  "to": 1792316496695000,
  "logs": { "state": "reported", "found": ["default"] },
  "metrics": { "state": "missing" },
  "profiles": { "state": "reported", "found": ["cpu", "alloc_space"] },
  "rum": { "state": "unknown" }
}
```

| Sinal | `reported` quando | `found` |
|---|---|---|
| `logs` | Um fluxo de logs com o campo `service.name`, `service_name` ou `service` contém uma linha de log do serviço. A consulta verifica até oito fluxos, começando por `default`. | Os fluxos. |
| `metrics` | `count(last_over_time({"service.name"="<service>"}[1h]))` em `to` é maior que zero. | O número de séries. |
| `profiles` | O fluxo de perfis contém um perfil do serviço. | Os tipos de perfil. |
| `rum` | Uma ação no navegador inclui um dos cinco traces de amostra mais recentes do serviço. | A sessão. |

`missing` indica que a consulta não encontrou dados. `unknown` indica que a consulta falhou ou levou mais de três
segundos. `rum` nunca retorna `missing`: uma amostra de traces pode mostrar que sessões chegam a um serviço, mas não que
nenhuma chega.

## Consulte como um serviço é executado

`GET /api/v1/apm/services` e `GET /api/v1/apm/services/{service}` incluem em cada resumo de serviço um
`profile` com dados das instâncias que enviaram dados no intervalo. Se a solicitação incluir `version`, o perfil considera
apenas as instâncias dessa versão. Cada lista traz até cinco valores, em ordem decrescente pelo número de instâncias que compartilham cada valor, no formato
`{ "value": "1.8.2", "instances": 4 }`.

| Campo | Observações |
|---|---|
| `instanceCount`, `hostCount` | Contagens de instâncias e de valores distintos de `host.name`. |
| `versions` | Versões executadas pelas instâncias. Durante um rollout, a lista mostra duas versões. |
| `languages`, `runtimes`, `frameworks` | `telemetry.sdk.language`; `process.runtime.name` com a versão correspondente; o framework indicado pela biblioteca de instrumentação dos spans de entrada. |
| `regions`, `clusters`, `k8sNamespaces`, `workloads` | `cloud.region`, `k8s.cluster.name`, `k8s.namespace.name` e `k8s.deployment.name` ou `k8s.statefulset.name`. |
| `repositories`, `commits` | `vcs.repository.url.full` ou `git.repository_url`, sem credenciais; `vcs.ref.head.revision` ou `git.commit.sha`. |
| `entryKinds` | `http`, `rpc`, `messaging`, `span`: os tipos de entrada que o serviço atende. |

`GET /api/v1/apm/services/{service}/instances` lista até 500 instâncias individualmente, começando pelas
mais recentes. Aceita `namespace`, `environment` e os parâmetros opcionais `version`, `from` e
`to`. Se faltar o serviço ou o ambiente, retorna `400`. Cada item inclui `instanceId` (o valor de
`service.instance.id` ou, na falta dele, `k8s.pod.name` ou, por fim, `host.name`), `version`, `firstSeenAt`,
`lastSeenAt`, `attributes` (um mapa dos últimos atributos enviados pela instância) e os dados do tráfego atendido
no intervalo: `red`, como nos resumos, com Apdex no limiar do serviço, e `sparkline`. Ao atingir o
limite de instâncias, a API contabiliza as demais em um único item com `instanceId` igual a `__other__`. Se uma instância
atendeu tráfego no intervalo antes de o sistema armazenar dados sobre ela, a API a lista com `attributes` vazio.

## Defina o estado de um grupo de erros

```http
PUT /api/v1/apm/errors/<fingerprint>/issue
Content-Type: application/json

{"status": "investigating", "assigneeId": "<user id>", "teamId": "<team id>", "lastSeenAt": 1792316496695000}
```

`status` aceita `open`, `investigating`, `resolved` ou `ignored`. `assigneeId` indica um membro da
organização ou `null`, e `teamId` indica uma equipe da organização ou `null`. O campo opcional `lastSeenAt` indica quando o leitor viu o grupo pela última vez, em microssegundos. Ao definir
`resolved`, a API registra o horário em `resolvedAt`.

Os resumos de erros incluem o estado em `issue`, com valor `null` até que alguém o defina. `issue.regressed`
vale `true` quando um grupo resolvido volta a ocorrer após `resolvedAt`. O filtro `unresolved` inclui
esses grupos. Ao definir o estado de uma impressão digital que a projeção não reconhece, a API retorna `404`.

## Gerencie objetivos de nível de serviço

Um objetivo de nível de serviço (SLO) define a proporção esperada de requisições consideradas boas para um serviço em um ambiente ou
para um de seus endpoints, ao longo de uma janela móvel. Consulte
[Objetivos de nível de serviço](/pt-BR/apm#objetivos-de-nível-de-serviço) para entender o significado de cada valor.

```http
POST /api/v1/apm/slos
Content-Type: application/json

{"name": "Checkout availability", "namespace": "shop", "service": "checkout", "environment": "production", "transaction": null, "kind": "availability", "objective": 0.999, "windowDays": 30}
```

| Campo | Observações |
|---|---|
| `name` | Obrigatório, com até 255 bytes. |
| `description` | Opcional, com até 2.000 bytes. |
| `namespace`, `service`, `environment` | Obrigatórios. Identifique o serviço conforme o APM. Um serviço sem `service.namespace` fica no namespace `default`. |
| `transaction` | Um endpoint, `{ "name": "POST /orders", "kind": "http" }`, ou `null` para o serviço inteiro. |
| `kind` | `availability`: uma requisição é considerada boa se não falhar. `latency`: uma requisição é considerada boa se não falhar e levar no máximo `latencyThreshold`. |
| `latencyThreshold` | Obrigatório e positivo para `latency`. Para `availability`, use `null` ou omita o campo. |
| `objective` | A proporção de requisições consideradas boas, maior que 0 e menor que 1, como `0.999`. |
| `windowDays` | `7`, `28` ou `30`. |

`POST` e `PUT` retornam o SLO salvo com `id`, `createdBy`, `createdAt`, `updatedBy` e
`updatedAt`. `GET /api/v1/apm/slos` retorna o status de cada SLO da organização. Passe
`namespace`, `service` e `environment` juntos para filtrar os SLOs de um serviço. A janela termina
no momento da chamada, portanto os parâmetros comuns de intervalo não se aplicam.

| Campo de status | Observações |
|---|---|
| `slo` | O SLO conforme salvo. |
| `state` | `healthy`, `at_risk`, `breached` ou `noData`. |
| `sli` | A proporção de requisições consideradas boas em relação ao total de requisições na janela, ou `null` se não houver requisições. |
| `goodRequests`, `totalRequests` | As contagens usadas no cálculo de `sli`. Um SLO de latência estima `goodRequests` com base nos histogramas de latência, por isso o valor pode ser fracionário. |
| `budgetRemaining` | `1 - (1 - sli) / (1 - objective)`. O valor fica negativo quando o objetivo não é cumprido e é `null` se não houver requisições. |
| `burnRates` | `oneHour`, `sixHours` e `oneDay`: `(1 - sli) / (1 - objective)` na última hora, nas últimas seis horas e nas últimas 24 horas, respectivamente, ou `null` se não houver requisições. |

`GET /api/v1/apm/slos/{id}` retorna `status` e `history`, com uma entrada para cada dia em UTC da janela
em que houve requisições, da mais antiga para a mais recente. Cada entrada contém `dayStart` em microssegundos, `sli`, `goodRequests`
e `totalRequests`.

`DELETE` retorna `204`. Retorna `409` se houver regras de alerta que monitoram o SLO, como alertas de taxa de consumo
do orçamento de erros. Exclua essas regras primeiro. As regras de alerta de um SLO são regras de APM que usam a métrica
`slo_burn_rate`. Consulte [Crie uma regra](/pt-BR/api/alerting/create-rule#regras-de-apm).

## Diferencie transações com o mesmo nome

Dois tipos de transação podem ter o mesmo nome. Passe o parâmetro opcional `kind` para selecionar um tipo:

```http
GET /api/v1/apm/transactions/POST%20%2Fcheckout?kind=http&service=checkout
```

Os valores aceitos para `kind` são `http`, `rpc`, `messaging`, `span` e `other`. Se vários
serviços ou tipos compartilharem o mesmo nome, a API retorna `400` com `APM transaction identity is ambiguous; provide service,
namespace, environment, and kind`.

## Compare versões

Informe valores diferentes para `baseline` e `candidate`. Adicione um filtro `service` para comparar as versões de um único serviço.

```bash
curl --get 'http://localhost:5080/api/v1/apm/versions/compare' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'service=checkout' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'baseline=2.3.1' \
  --data-urlencode 'candidate=2.4.0'
```

A resposta inclui `baseline` e `candidate`, cada um com `version`, `sampleCount` e
`red`, além de `delta`, `status`, `regressedTransactions` e `regressedErrors`. Cada lista de regressões
contém até 20 entradas.

| Campo | Observações |
|---|---|
| `sufficientData` | `true` somente quando ambas as versões atingem o tamanho mínimo de amostra configurado. O padrão é de 1.000 requisições por versão (`[apm.version_comparison].min_requests_per_version`). |
| `status` | `insufficient_data`, `regressed`, `improved` ou `neutral`. `regressed` quando a taxa de erros da versão candidata sobe pelo menos um ponto percentual e atinge pelo menos 1,5 vez a taxa da versão de referência, ou quando o p95 sobe pelo menos 20% e 50 ms; `improved` quando uma das métricas cai pelo menos o equivalente aos limites correspondentes e nenhuma sobe a ponto de atingir esses limites; `insufficient_data` quando `sufficientData` é `false`. |
| `delta` | `requestCountAbsolute` e `requestCountRelative`, `errorRateAbsolute` e `errorRateRelative`, e `p95AbsoluteTime` e `p95Relative`. Um valor relativo é `null` quando o valor de referência é zero ou está ausente. |

A API retorna `400` quando falta `candidate` ou `baseline`, ou quando as duas versões são idênticas.

## Consulte as versões de um serviço

`GET /api/v1/apm/services/{service}` retorna `versions`, as versões detectadas no intervalo. Cada versão inclui
`red`, com as métricas das requisições atendidas no intervalo, e `verdict`, com o desempenho em relação à versão do mesmo serviço
cuja primeira detecção ocorreu imediatamente antes. A avaliação segue os critérios de [uma comparação](#compare-versões):

| Campo | Observações |
|---|---|
| `previous` | A versão usada na comparação. |
| `status` | `regressed`, `improved`, `neutral` ou `insufficient_data`. |
| `worse` | O que piorou quando `status` é `regressed`: `errorRate`, `latency` ou ambos. |
| `delta` | Segue o mesmo formato da comparação e usa a versão anterior como referência. |

A primeira versão detectada não tem `verdict`. Um filtro de versão na requisição não restringe
as métricas: a consulta considera todas as versões do serviço.

## Consulte onde ocorreram os erros

`GET /api/v1/apm/errors` retorna um `breakdown` junto com a página, considerando todos os grupos que correspondem ao filtro `status`
(não apenas os da página), e `GET /api/v1/apm/errors/{fingerprint}` retorna o `breakdown` do
grupo. O detalhamento inclui `versions`, `environments` e `languages`, cada um com uma lista de entradas com `value` e `count`,
em ordem decrescente de ocorrências. `value` fica vazio quando os spans não informam o valor. Depois dos primeiros
sete valores, o detalhamento soma as ocorrências dos demais em `__other__`. A linguagem vem do campo
`telemetry.sdk.language` do serviço.

## Gerencie regras de agrupamento de erros

Uma regra permite agrupar erros detectados de forma diferente do agrupamento por tipo, frame e endpoint. O APM
avalia as regras na ordem definida por `position` e aplica a primeira que corresponder.

```http
POST /api/v1/apm/error-rules
Content-Type: application/json

{"name": "Upstream timeouts", "serviceNamespace": "shop", "serviceName": "checkout",
 "errorType": "*Timeout*", "message": "", "frame": "", "endpoint": "", "action": "merge", "enabled": true}
```

| Campo | Observações |
|---|---|
| `name` | Até 128 caracteres. O grupo consolidado recebe esse nome. |
| `serviceNamespace`, `serviceName` | Identificam o serviço ao qual a regra se aplica. Um `serviceName` vazio abrange todos os serviços. Informe o nome do serviço ao definir um namespace. |
| `errorType`, `message`, `frame`, `endpoint` | Padrões para o tipo de erro, a mensagem da exceção, o primeiro frame da aplicação e o endpoint, cada um com até 256 caracteres. O padrão deve corresponder ao texto inteiro, sem distinguir maiúsculas de minúsculas. Use `*` para representar qualquer texto. Um padrão vazio corresponde a qualquer valor. Defina pelo menos um padrão. |
| `action` | `merge`: reúne os erros correspondentes de um serviço em um único grupo. `ignore`: não agrupa esses erros, mas as requisições correspondentes continuam contando como falhas. |
| `enabled` | O APM mantém regras desativadas, mas não as avalia. O padrão é `true`. |

A resposta retorna a regra com `id`, `position`, `updatedBy` e `updatedAt`. Cada organização
pode ter até 100 regras. `PUT /api/v1/apm/error-rules/order` recebe `{"ids": [...]}`, coloca as regras indicadas
no início na ordem informada, posiciona as demais em seguida e retorna as regras na nova ordem.

A alteração entra em vigor imediatamente no nó que a salva e em até 30 segundos nos demais. A alteração só afeta
os erros detectados a partir desse momento. Os grupos existentes permanecem inalterados.

## Consulte o mapa de serviços

`GET /api/v1/apm/map` aceita os parâmetros comuns de intervalo, `environment` e `namespace` e retorna
`nodes`, `edges`, `namespaces` (dos serviços no ambiente), `environments` (todos os ambientes) e
`truncated` (`true` quando o mapa mantém apenas os 400 nós com mais tráfego).

| Campo | Observações |
|---|---|
| `nodes[].id` | `service:<name>`, `topic:<name>` ou `<category>:<target>`, conforme o destino chamado pelos serviços. |
| `nodes[].kind` | `service`, `external` ou `topic`. Um nó externo inclui sua `category`. |
| `nodes[].red` | `requestCount`, `errorCount`, `errorRate` e `p95Time`: métricas das solicitações atendidas por um serviço ou enviadas a um nó externo ou tópico. Um serviço também inclui `health`, `namespace` e `environments`. |
| `edges[].kind` | `call`, `publish` (para um tópico) ou `consume` (de um tópico). |
| `change` | Em uma aresta ou em um nó, compara com o intervalo anterior de mesma duração: `new` se não existia antes, `gone` se deixou de existir. O campo fica ausente quando não há dados no intervalo anterior. |

As chamadas entre serviços vêm do grafo de serviços, com o P95 do minuto mais lento de cada chamada. Os demais dados vêm
dos buckets do APM. `GET /api/v1/apm/map/edge` aceita os IDs de nó `source` e `target` além dos mesmos
parâmetros e retorna `kind`, `red`, `trend`, `operations` (`name`, `kind`, `red`), `everyCaller`
(`true` quando as operações representam os endpoints do serviço chamado considerando todos os chamadores) e `errors`, os
grupos de erros do serviço chamado.

## Consulte o raio de impacto de um serviço

`GET /api/v1/apm/blast-radius` exige `service` e aceita os parâmetros comuns de intervalo e
`environment`. O endpoint consulta todo o mapa do ambiente, independentemente do namespace, e
retorna `meta`, `service` (o nó do próprio serviço, ausente se o serviço não aparece no mapa durante o intervalo),
`upstream` (quem chama o serviço, até três saltos) e `downstream` (os destinos que o serviço chama ou para os quais publica, até dois
saltos). Cada lado tem até 30 nós, com os que apresentam problemas primeiro. A resposta omite as chamadas que deixaram de ocorrer em relação ao intervalo
anterior.

| Campo | Observações |
|---|---|
| `id`, `kind`, `name`, `namespace`, `category` | Identificação do nó conforme o [mapa de serviços](#consulte-o-mapa-de-serviços). |
| `hops` | Número de chamadas entre o nó e o serviço: `1` para um nó que chama o serviço ou recebe chamadas dele diretamente. |
| `via` | Nó pelo qual passa o caminho até esse nó, um salto mais perto do serviço. |
| `health` | Estado de integridade do próprio serviço. Para um destino chamado, esse estado reflete as falhas nas chamadas ao destino. |
| `red`, `call` | Métricas das solicitações que o nó atendeu ou recebeu e das chamadas entre o nó e `via`. |

## Registre e liste implantações

`POST /api/v1/apm/deployments` aceita a implantação em JSON e retorna `201` com a implantação e os campos `id`,
`createdBy` e `createdAt`. Consulte os campos, seus limites e exemplos de CI em
[Implantações](/pt-BR/apm/deployments#registre-implantações-pela-ci). O endpoint identifica o serviço e o ambiente
conforme as regras de nomenclatura, o mapeamento de ambientes e os aliases da organização.
O endpoint armazena o endereço do repositório com a senha mascarada. Para uma mudança de configuração ou uma flag de recurso, defina
`kind` como `configuration` ou `feature_flag`. Nesses casos, não é necessário informar `version`.

`GET /api/v1/apm/deployments` aceita `service`, `namespace`, `environment`, `from` e `to`, com o
intervalo em microssegundos, e retorna até 200 implantações, da mais recente à mais antiga. Uma implantação registrada
sem namespace ou ambiente aparece nos resultados de todos os namespaces ou ambientes, respectivamente.

## Gerencie as configurações de APM

`GET /api/v1/apm/settings` retorna as configurações da organização. `PUT` substitui todas as configurações e
retorna o que salvou:

```json
{
  "health": {
    "errorRateWarning": 0.02,
    "errorRateCritical": 0.1,
    "p95WarningTime": 500000,
    "p95CriticalTime": 2000000
  },
  "apdexThreshold": 500000,
  "longTaskTime": 1000000,
  "namingRules": [{ "pattern": "^(checkout)-[a-z0-9]{5}$", "replacement": "$1" }],
  "environmentMap": [{ "from": "Production", "to": "production" }],
  "aliases": [{ "aliasNamespace": "shop", "alias": "checkout-v1", "namespace": "shop", "service": "checkout" }],
  "metadataRules": { "teamFromTier": "p1", "ownerFromTier": "p0", "repositoryFromTier": null }
}
```

Campos omitidos assumem o valor padrão. O endpoint remove espaços no início e no fim dos nomes e usa `default` quando o namespace de um alias está em branco.
Consulte os limites e a função de cada configuração em [Configurações de APM](/pt-BR/apm/settings). As alterações entram em vigor imediatamente
no nó que as salva e em até 30 segundos nos demais nós.

Consulte e substitua os limites de cardinalidade da plataforma com `GET` e `PUT
/api/v1/settings/apm_limits`. Ambos exigem `sys.settings.limits.manage`. O corpo inclui
`servicesPerOrgHour`, `transactionsPerServiceHour`, `dependenciesPerServiceHour`,
`operationsPerDependencyHour`, `errorGroupsPerServiceHour`, `versionsPerServiceHour` e
`instancesPerServiceHour`, cada um com um valor de 1 a 100000.

## Consulte os metadados da resposta

Todos os endpoints retornam um objeto `meta` comum:

```json
{
  "range": {
    "from": 1785801600000000,
    "to": 1785888000000000
  },
  "resolution": "minute",
  "projectionStartedAt": 1785798000000000,
  "lastCompleteBucketAt": 1785887940000000,
  "dataQuality": {
    "partial": false,
    "gaps": [],
    "overflowDimensions": []
  },
  "activationBoundary": false
}
```

- Interprete `activationBoundary: true` como cobertura incompleta antes de `projectionStartedAt`.
- Interprete `dataQuality.partial: true` como dados incompletos, não como ausência confirmada de ocorrências.
- Consulte `gaps` para identificar falhas na fila, no repositório, na gravação (flush) ou no desligamento, além de problemas com dados atrasados ou cardinalidade.
- Use `lastCompleteBucketAt` para verificar se o processamento dos dados recentes ainda está em andamento.
- Consulte `overflowDimensions` antes de usar um detalhamento com alta cardinalidade.

## Erros

| Status | Causa |
|---|---|
| `400` | Um parâmetro é inválido: um `sort` não compatível (`unsupported APM sort field`), um `limit` fora do intervalo de 1 a 200, um filtro vazio ou grande demais (`invalid APM service filter`), um intervalo maior que o máximo (`APM query range exceeds configured maximum`), um fim anterior ao início (`APM range end precedes start`), um `direction` ou `resolution` desconhecido, um SLO que não passa nas verificações acima (`SLO objective must be between 0 and 1, exclusive`) ou um filtro de listagem de SLOs que não inclui todos os campos `namespace`, `service` e `environment`. |
| `403` | O token não tem a permissão exigida pela chamada. |
| `404` | A assinatura do erro, a transação, o serviço ou o SLO não existe no intervalo. |
| `409` | Ainda há regras de alerta que monitoram o SLO solicitado para exclusão. |
