```http
GET  /api/v1/query/stream
POST /api/v1/query/stream
```

Sempre responde com NDJSON em blocos (`application/x-ndjson`). Cada linha contém um objeto JSON cujas chaves são os nomes das colunas. A última linha é `{"__meta__":{"scannedRows":...,"tookMs":...}}`. O endpoint nunca transforma uma consulta em uma tarefa assíncrona. A chamada exige `streams.query` ou `sys.telemetry.read` no escopo do sistema.

A versão `POST` aceita o mesmo corpo que [Executar uma consulta](/pt-BR/api/query/execute). A versão `GET` aceita parâmetros de consulta:

| Parâmetro | Obrigatório | Observações |
|---|---|---|
| `sql` | Sim | A instrução SQL. Se o valor estiver ausente, o endpoint retorna `400`. |
| `stream` | Sim | Nome do fluxo principal. |
| `streamType` | Não | `logs`, `metrics`, `traces`, `profiles` ou `extend`. O padrão é `logs`. |
| `from`, `to` | Sim | Intervalo de tempo em microssegundos. |
| `limit` | Não | Número máximo de linhas. |

<RequestExample>
```bash cURL
NOW=$(date +%s)000000

curl -G http://localhost:5080/api/v1/query/stream \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "sql=SELECT level, msg FROM app ORDER BY _timestamp DESC" \
  --data-urlencode "stream=app" \
  --data-urlencode "streamType=logs" \
  --data-urlencode "from=$((NOW-3600000000))" \
  --data-urlencode "to=$((NOW+60000000))" \
  --data-urlencode "limit=3"
```
</RequestExample>

<ResponseExample>
```text 200
{"level":"info","msg":"fine"}
{"level":"error","msg":"db pool exhausted"}
{"__meta__":{"scannedRows":5,"tookMs":173}}
```
</ResponseExample>

Desative o buffer de resposta no proxy (`proxy_buffering off`) para receber as linhas assim que o endpoint as gerar. Permita leituras de longa duração. Interrompa a leitura para cancelar o fluxo.
