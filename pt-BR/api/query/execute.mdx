```http
POST /api/v1/query
GET  /api/v1/query
```

Executa uma consulta e retorna as linhas ou inicia um job de busca assíncrono para uma consulta de grande porte. A chamada exige `streams.query` ou `sys.telemetry.read` para telemetria do sistema.

**Corpo**

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `orgId` | string | Sim | Inclua o campo. A API ignora o valor e usa a organização autenticada. |
| `language` | string | Sim | `sql` ou `promql`. |
| `statement` | string | Sim | O texto da consulta. |
| `timeRange` | objeto | Sim | `{ "start": <microseconds>, "end": <microseconds> }`. |
| `stream` | objeto | Para SQL | `{ "name": "app", "streamType": "logs" }` identifica a tabela principal. Ambos os campos são obrigatórios, e o tipo deve ser `logs`, `metrics`, `traces`, `profiles` ou `extend`. |
| `limit` | inteiro | Não | Limite de linhas. Em uma consulta de intervalo PromQL, a API coleta amostras de cada série em intervalos uniformes para respeitar esse limite. |
| `step` | inteiro | Não | Apenas para PromQL. Define o passo da consulta de intervalo em microssegundos. Com `step`, a consulta PromQL retorna um valor por série a cada passo, de `start` a `end`. Sem `step`, retorna o valor em `end`. Cada série pode ter no máximo 11.000 passos. Se um passo menor ultrapassar esse limite, a API retorna `400`. |

**String de consulta de uma requisição GET**

`GET /api/v1/query` aceita a mesma consulta na string de consulta, o que permite
copiar e reabrir o endereço da consulta. Retorna a mesma resposta que `POST`, respeita os mesmos cabeçalhos e exige a
mesma permissão. Envie instruções longas demais para um endereço via `POST`: um proxy na frente do
servidor pode recusar uma linha de requisição com mais de 8 KB.

| Parâmetro | Obrigatório | Observações |
|---|---|---|
| `language` | Sim | `sql` ou `promql`. |
| `statement` | Sim | O texto da consulta com codificação de URL. |
| `start`, `end` | Sim | O intervalo de tempo em microssegundos. |
| `stream`, `streamType` | Para SQL | Informe a tabela principal e o tipo dela juntos. |
| `limit` | Não | Limite de linhas. |
| `step` | Não | Passo da consulta de intervalo PromQL em microssegundos. |

**Cabeçalhos e string de consulta**

| Nome | Efeito |
|---|---|
| `Prefer: respond-async` | Cria um job de busca e retorna `202`. Uma consulta a `_audit` ainda é executada na própria requisição. |
| `Prefer: respond-sync` | Executa a consulta na própria requisição, mesmo para intervalos longos. |
| `Accept: application/x-ndjson` | Transmite um objeto JSON por linha, seguido de um registro `{"__meta__": ...}`. |
| `?clusters=local,remote` | Inclui clusters remotos em uma busca federada. |

<RequestExample>
```bash cURL
NOW=$(date +%s)000000

curl -X POST http://localhost:5080/api/v1/query \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "{\"orgId\":\"$MS_ORG\",\"language\":\"sql\",
       \"statement\":\"SELECT level, count(*) AS n FROM app GROUP BY level\",
       \"timeRange\":{\"start\":$((NOW-3600000000)),\"end\":$((NOW+60000000))},
       \"stream\":{\"name\":\"app\",\"streamType\":\"logs\"}}"
```

```bash cURL (GET)
NOW=$(date +%s)000000

curl -G http://localhost:5080/api/v1/query \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'language=promql' \
  --data-urlencode 'statement=sum(rate(http_requests_total[5m]))' \
  --data-urlencode "start=$((NOW-3600000000))" \
  --data-urlencode "end=$NOW" \
  --data-urlencode 'step=60000000'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "columns": ["level", "n"],
  "rows": [["error", 12], ["info", 40]],
  "scannedRows": 10432,
  "tookMs": 18
}
```
</ResponseExample>

Uma resposta PromQL contém uma linha por valor. Uma consulta de intervalo retorna as colunas `_timestamp` (em microssegundos), `value` e uma coluna por rótulo, com uma linha para cada combinação de série e passo. Uma consulta sem `step` retorna `value` e as colunas de rótulos, com uma linha por série.

```json
{
  "columns": ["_timestamp", "value", "service.name"],
  "rows": [[1761638400000000, 0.42, "checkout"], [1761638460000000, 0.40, "checkout"]],
  "scannedRows": 2,
  "tookMs": 6
}
```

Uma consulta cujo número estimado de linhas atinge `[querier].auto_async_threshold_rows` retorna `202`:

```json
{
  "jobId": "3KE1WD4SrFXhyftdMJY0FN7fTFj",
  "monitor": "/api/v1/query/jobs/3KE1WD4SrFXhyftdMJY0FN7fTFj",
  "state": "pending"
}
```

Consulte [Consulta](/pt-BR/query#intervalos-de-tempo-e-tarefas-assíncronas) para conferir os limites e os endpoints dos jobs.

**Erros**

| Status | Causa |
|---|---|
| `400` | A API não consegue elaborar um plano para a instrução, falta a indicação de `stream` para SQL (`query.stream hint is required`), o `step` de PromQL não é positivo ou gera mais de 11.000 passos por série, ou a consulta leria mais linhas do que `[querier].max_scan_rows` permite. Uma requisição `GET` também retorna `400` se faltar um parâmetro obrigatório ou se `stream` vier sem `streamType`. |
| `503` | Em um cluster com funções separadas, nenhum nó `querier` está ativo (`no querier node is available`). |
| `403` | O stream não existe na organização (`stream not found: <name>`), o token não tem a permissão `streams.query` ou a consulta lê `_audit` e o token não tem a permissão `audit.read`. |
| `422` | Falta um campo no corpo ou um campo tem o tipo incorreto, como `orgId` ou `streamType`. A resposta vem em texto simples. |
| `429` | As consultas do grupo de trabalho ocupam toda a capacidade do nó e a consulta aguardou [`[search.admission].max_wait_secs`](/pt-BR/configuration#controle-de-admissão) sem conseguir uma vaga, ou o grupo atingiu seu limite no cluster. |
