```http
GET    /api/v1/changes
POST   /api/v1/changes
GET    /api/v1/changes/{id}
PUT    /api/v1/changes/{id}
PATCH  /api/v1/changes/{id}
DELETE /api/v1/changes/{id}
```

As alterações ficam em um só lugar: implantações, mudanças de configuração, feature flags, escalonamento e
mudanças de infraestrutura que os pipelines relatam por meio de
[`POST /api/v1/apm/deployments`](/pt-BR/apm/deployments#report-deployments-from-ci) e anotações
inseridas em um intervalo de tempo. `GET /api/v1/changes` as lista com as versões que o APM viu primeiro em spans
e as edições de regras de alerta. As demais chamadas tratam de anotações.

## Listar alterações

| Parâmetro | Observações |
|---|---|
| `from`, `to` | O intervalo em microssegundos. `to` assume o horário atual por padrão e `from`, um dia antes de `to`. |
| `services` | Nomes de serviços, separados por vírgula. Alterações de outros serviços são omitidas; alterações sem serviço, como anotações e edições de regras, permanecem. |
| `namespace`, `environment` | Alterações e versões relatadas deste namespace ou ambiente, e alterações relatadas que não nomearam nenhum. |
| `kinds` | Separados por vírgula: `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure`, `annotation`, `version`, `rule`. Todos os tipos que o chamador pode ler quando omitido. |
| `dashboardId`, `stream` | Anotações deste dashboard ou stream de logs, e anotações sem nenhum. Anotações de outro dashboard ou stream são omitidas. |
| `limit` | No máximo 500, o padrão. |

Cada tipo exige sua própria permissão, e um tipo que o chamador não tem é omitido em vez de recusado:

| Tipos | Permissão, qualquer uma de |
|---|---|
| `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure` | `apm.deployments.read`, `sys.telemetry.read` |
| `annotation` | `dashboards.annotations.read` |
| `version` | `apm.services.read`, `sys.telemetry.read` |
| `rule` | `alerts.rules.read` |

A resposta é uma lista, da mais recente para a mais antiga. Uma versão relatada por um pipeline é listada uma vez, conforme relatada.

```json
[
  {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "kind": "deployment",
    "at": 1792316400000000,
    "service": "checkout",
    "namespace": "shop",
    "environment": "prod",
    "version": "2.0.0",
    "status": "succeeded",
    "commit": "9f2c1e7a4b3d5e6f",
    "author": "ada",
    "ciUrl": "https://ci.example.com/runs/7"
  },
  {
    "id": "3KEDP0aZ1y2b3c4d5e6f7g8h9i0",
    "kind": "annotation",
    "at": 1792312800000000,
    "end": 1792314600000000,
    "title": "Load test",
    "tags": ["test"],
    "dashboardId": "dash-1"
  }
]
```

| Campo | Observações |
|---|---|
| `at`, `end` | Quando aconteceu; `end` fecha uma anotação em um intervalo. Microssegundos. |
| `service`, `namespace`, `environment`, `version` | A que se referia uma alteração relatada ou uma versão. |
| `status` | Como terminou uma alteração relatada: `succeeded`, `failed` ou `rolled_back`. |
| `title`, `description`, `tags` | O título de uma anotação ou de uma regra e o que uma alteração informou sobre si mesma. |
| `commit`, `repositoryUrl`, `pullRequestUrl`, `author`, `ciUrl` | De onde veio uma alteração relatada. |
| `dashboardId`, `stream` | A qual dashboard ou stream uma anotação pertence. |
| `ruleId` | A regra editada. |

## Gerenciar anotações

`POST /api/v1/changes` cria uma anotação e exige `dashboards.annotations.manage`:

```json
{
  "title": "Load test",
  "description": "k6, 2,000 users",
  "tags": ["test"],
  "timeStart": 1792312800000000,
  "timeEnd": 1792314600000000,
  "dashboardId": "dash-1",
  "streamName": null
}
```

`GET /api/v1/changes/{id}` lê uma anotação com `dashboards.annotations.read`. `PUT` e `PATCH`
alteram os campos informados, e `DELETE` a remove, com `dashboards.annotations.manage`. Essas chamadas
atingem apenas anotações; um id que não é de uma anotação da organização responde `404`.
O Mole Agent mantém anotações com `create_annotation`, `update_annotation` e `delete_annotation`, e
lista alterações com `list_changes`.
