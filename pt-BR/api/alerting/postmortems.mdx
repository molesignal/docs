Um incidente tem no máximo um post-mortem interno, escrito em Markdown. Esse post-mortem fica separado dos
[post-mortems da página de status](/pt-BR/status-pages#post-mortems); as páginas podem copiar o resumo. Veja como
as páginas usam esse resumo em [Incidentes graves e post-mortems](/pt-BR/alerting/major-incidents#análises-pós-incidente).

| Método e caminho | O que faz | Permissão |
|---|---|---|
| `GET /api/v1/alerts/postmortems` | Lista os post-mortems da organização, do mais recente ao mais antigo, com a contagem de itens de ação de cada um. | `postmortems.read` |
| `GET /api/v1/alerts/incidents/{id}/postmortem` | Retorna o post-mortem do incidente e os itens de ação. | `alerts.incidents.read` no incidente e `postmortems.read` |
| `POST /api/v1/alerts/incidents/{id}/postmortem` | Inicia um post-mortem para o incidente. | `alerts.incidents.read` no incidente e `postmortems.manage` |
| `PUT /api/v1/alerts/postmortems/{id}` | Altera o título, o corpo, o status, o responsável e os revisores de um post-mortem. | `postmortems.manage` |
| `POST /api/v1/alerts/postmortems/{id}/actions` | Adiciona um item de ação. | `postmortems.manage` |
| `PUT /api/v1/alerts/postmortems/{id}/actions/{actionId}` | Altera um item de ação. | `postmortems.manage` |
| `DELETE /api/v1/alerts/postmortems/{id}/actions/{actionId}` | Exclui um item de ação. | `postmortems.manage` |
| `POST /api/v1/alerts/postmortems/{id}/actions/{actionId}/ticket` | Cria um ticket para um item de ação. | `postmortems.manage` |

## Iniciar e alterar um post-mortem

```http
POST /api/v1/alerts/incidents/{id}/postmortem
```

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `title` | string | Sim | De 1 a 200 caracteres. |
| `body` | string | Não | Corpo em Markdown, com até 100000 caracteres. |

A API retorna `409` se o incidente já tem um post-mortem. As páginas primeiro geram um rascunho do corpo a partir de um modelo
(resumo, impacto, linha do tempo, causa raiz, o que funcionou, o que não funcionou, itens de ação) e depois chamam esse endpoint;
a API registra a criação no log de auditoria. Para fazer uma alteração, envie apenas os campos a alterar: `title`, `body`,
`status`, `ownerId` (`null` limpa o campo) e `reviewerIds`.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/postmortems/$POSTMORTEM_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"status": "in_review", "reviewerIds": ["<user-id>"]}'
```
</RequestExample>

As operações de leitura, criação e alteração retornam `{ "postmortem": { ... }, "actions": [ ... ] }`; `postmortem` tem o valor
`null` quando o incidente não tem post-mortem.

Cada linha da lista inclui os campos do post-mortem, além do resumo do incidente em `incidentSummary`, da contagem de itens de ação
ainda em aberto em `openActions` e da contagem dos que estão em aberto e com prazo vencido em `overdueActions`.

## Itens de ação

Para adicionar um item, envie `{ "title": "…", "ownerId": "<user-id>", "dueAt": 1790600000000000 }`, com um título de 1
a 300 caracteres e `dueAt` em microssegundos Unix. Cada post-mortem aceita até 50 itens. Para fazer uma alteração, envie apenas os
campos a alterar: `title`, `ownerId` e `dueAt` (`null` limpa o campo correspondente) e `status` (`open` ou `done`).
As operações de adição e alteração retornam o item de ação, e a exclusão retorna `{ "deleted": true }`.

```http
POST /api/v1/alerts/postmortems/{id}/actions/{actionId}/ticket
```

O corpo é `{ "connectorId": "<connector-id>" }`: a API cria um ticket para o item de ação com esse
[conector de tickets](/pt-BR/api/alerting/tickets) e retorna o item de ação com `ticketKey` e
`ticketUrl`; se o item já tem um ticket, a API retorna o item sem alterações. O ticket não recebe comentários nem
transições de status do incidente, e concluir o ticket não resolve o incidente.

**Erros**

| Status | Motivo |
|---|---|
| `400` | Um campo excede os limites ou o conector de tickets está desativado. |
| `403` | Falta uma permissão ou o incidente está fora do escopo de acesso. |
| `404` | O incidente, o post-mortem, o item de ação ou o conector de tickets não existe. |
| `409` | O incidente já tem um post-mortem. |
