Um conector armazena as credenciais e as configurações de transporte de um provedor de notificações para uma organização. Para listar e consultar conectores, é necessário ter a permissão `notify.connectors.read`. Para criar, atualizar, testar e excluir um conector, é necessário ter a permissão `notify.connectors.manage`.

| Operação | Endpoint |
|---|---|
| Listar tipos de conector | `GET /api/v1/notify/connector-types` |
| Listar conectores | `GET /api/v1/notify/connectors` |
| Criar um conector | `POST /api/v1/notify/connectors` |
| Consultar um conector | `GET /api/v1/notify/connectors/{id}` |
| Atualizar um conector | `PUT /api/v1/notify/connectors/{id}` |
| Testar um conector | `POST /api/v1/notify/connectors/{id}/test` |
| Excluir um conector | `DELETE /api/v1/notify/connectors/{id}` |

## Tipos de conector

A lista de tipos retorna `connectorType`, `capabilities` e `addresses` para cada tipo que o backend em execução registra. Os tipos são `email_smtp`, `lark_app`, `lark_webhook`, `slackApp`, `slack_webhook` e `webhook`.

```json
[
  {
    "connectorType": "slack_app",
    "capabilities": {
      "directUser": true,
      "group": true,
      "richText": true,
      "interactive": true,
      "acknowledgement": false,
      "attachments": false
    },
    "addresses": [
      {
        "field": "apiBaseUrl",
        "picker": "site",
        "choices": [
          { "key": "slack", "url": "https://slack.com/api" },
          { "key": "govslack", "url": "https://slack-gov.com/api" }
        ]
      }
    ]
  }
]
```

`addresses` lista os endereços do provedor que o `config` de um tipo armazena. Quando o tipo exige que o usuário informe o endereço, como no caso de um webhook ou de SMTP, o tipo não define endereços de provedor e retorna uma lista vazia.

| Campo | Significado |
|---|---|
| `field` | A chave de `config`, como `apiBaseUrl`, `serviceUrl` ou `wsUrl`. |
| `choices` | Os endereços que a chave aceita, cada um com `key` e `url`. O primeiro é o padrão. |
| `picker` | O critério para escolher entre vários endereços: `site` (plataforma) ou `cloud`. O sistema não salva a escolha. |
| `byRegion` | O endereço segue a região selecionada (Alibaba Cloud, AWS): `https://{service}.{region}.{one of domains}`. `choices` contém apenas o endereço usado antes da seleção de uma região. |

Ao criar, atualizar ou testar um conector ou ao enviar uma mensagem diretamente, a API aceita nessas chaves apenas um endereço da lista. Para um endereço regional, aceita apenas o endereço da região indicada em `config`. Se a chave estiver ausente, a API usa o valor padrão. A API rejeita qualquer outro endereço para impedir o envio de credenciais a outro destino.

O objeto `config` de um conector depende do tipo. Em todos os tipos, `timeoutSecs` tem o valor padrão 10 e aceita valores de 1 a 60. Use URLs absolutas com `http` ou `https`. O endereço do provedor deve constar em `addresses` do tipo.

| `connectorType` | Chaves de `config` |
|---|---|
| `email_smtp` | `host` e `from` (obrigatórios), `port` (padrão: `587`), `username`, `password`, `tls` (`none`, `starttls` por padrão ou `tls`), `timeoutSecs` |
| `slackApp` | `botToken`, `clientId` e `clientSecret` (um token de bot, um ID e um segredo de cliente, ou os três), `apiBaseUrl` (padrão: `https://slack.com/api`, ou `https://slack-gov.com/api` para GovSlack), `timeoutSecs` |
| `slack_webhook` | `webhookUrl` (obrigatório), `timeoutSecs` |
| `lark_app` | `appId` e `appSecret` (obrigatórios), `apiBaseUrl` (`https://open.feishu.cn/open-apis` do Feishu por padrão, ou `https://open.larksuite.com/open-apis` para Lark), `receiveIdType` (`open_id` por padrão, `userId`, `union_id`, `email` ou `chatId`), `timeoutSecs` |
| `lark_webhook` | `webhookUrl` (obrigatório), `secret`, `timeoutSecs` |
| `webhook` | `url` (obrigatório), `method` (`post` por padrão, `put` ou `patch`), `headers`, `timeoutSecs` |

A página [Canais de notificação](/pt-BR/notification-channels) explica cada provedor e seus destinos.

## Criar um conector

```http
POST /api/v1/notify/connectors
```

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `name` | string | Sim | Único na organização. |
| `connectorType` | string | Sim | Um dos tipos acima. Não é possível alterar o tipo depois. |
| `config` | object | Sim | As configurações do tipo. |
| `enabled` | boolean | Não | Padrão: `true`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/notify/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "Operations webhook",
    "connectorType": "webhook",
    "config": {
      "url": "https://hooks.example.com/molesignal",
      "method": "post",
      "headers": { "Authorization": "Bearer <token>" },
      "timeoutSecs": 5
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "id": "3KEDlokKjNmves95sRzL8tXpflY",
  "organizationId": "<organization-id>",
  "name": "Operations webhook",
  "connectorType": "webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 5
  },
  "capabilities": {
    "directUser": true,
    "group": true,
    "richText": true,
    "interactive": false,
    "acknowledgement": false,
    "attachments": false
  },
  "enabled": true,
  "status": "unknown",
  "lastTestedAt": null,
  "lastTestStatus": null,
  "lastTestError": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

O MoleSignal criptografa todo o objeto `config` em repouso. Nas respostas, a API substitui por `***` o valor de cada chave que armazena uma credencial. Essas chaves são `url`, `webhookUrl`, `headers` e todas as chaves que terminam em `password`, `secret` ou `token`. As demais chaves, como `host`, `from` e `timeoutSecs`, continuam legíveis.

O campo `status` tem o valor `unknown` até o primeiro teste e, depois, passa a `connected` ou `error`. O campo `lastTestStatus` tem o valor `success` ou `failed`. O roteamento ignora um conector com status `error` até que um teste posterior seja bem-sucedido.

## Listar e consultar conectores

```http
GET /api/v1/notify/connectors
GET /api/v1/notify/connectors/{id}
```

A lista retorna um array de conectores com a estrutura acima. Se o `id` não existir, a API retorna `404`.

## Atualizar um conector

```http
PUT /api/v1/notify/connectors/{id}
```

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `name` | string | Sim | O novo nome. |
| `config` | object | Não | As novas configurações. Omita o campo para manter a configuração armazenada. |
| `enabled` | boolean | Não | Padrão: `true`. Se o valor estiver ausente, a API ativa o conector. |

Envie `***` para uma chave mascarada para manter o segredo armazenado ou envie um novo valor em texto simples para substituí-lo:

```json
{
  "name": "Operations webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 8
  },
  "enabled": true
}
```

## Testar um conector

```http
POST /api/v1/notify/connectors/{id}/test
```

O teste envia uma mensagem pelo conector. Não é possível testar um conector desativado.

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `targetType` | string | Sim | `directUser`, `fixed_address`, `fixed_group` ou `webhook`. Cada tipo de conector aceita apenas algumas dessas opções. Por exemplo, `email_smtp` aceita `directUser` e `fixed_address`. |
| `target` | string | Sim | O destinatário: um endereço, um identificador do provedor, um grupo ou uma URL, dependendo de `targetType`. |
| `message` | object | Não | `title`, `text`, `markdown` e `html`. Por padrão, o teste usa um título e um texto genéricos. |

<ResponseExample>
```json 200
{
  "sent": true,
  "testedAt": 1790000000000000,
  "elapsedMs": 3,
  "providerMessageId": "req-1",
  "error": null
}
```
</ResponseExample>

Mesmo se a entrega falhar, a API retorna `200`, com `sent` igual a `false` e o motivo em `error`, por exemplo, `unavailable: webhook request failed`. O teste também atualiza `status`, `lastTestedAt`, `lastTestStatus` e `lastTestError` do conector.

## Excluir um conector

```http
DELETE /api/v1/notify/connectors/{id}
```

Quando a exclusão é bem-sucedida, a API retorna `204` sem corpo. Se um endpoint de usuário, uma política de notificação, uma rota alternativa, uma inspeção agendada de logs, uma página de status ou o Mole Agent em mensagens instantâneas ainda fizer referência ao conector, a API retorna `409` com `notify connector is referenced by user endpoints, policies, default routes, scheduled log inspections, status pages, or Mole Agent in IM`. Mova as referências antes de excluir o conector.

## Erros

| Status | Causa |
|---|---|
| `400` | O objeto `config` é inválido para o tipo, a API não oferece suporte ao tipo (`unsupported connector type: pagerduty`), o destino é incompatível com o conector ou o conector está desativado. |
| `404` | O conector não existe. |
| `409` | Outro conector na organização já usa o nome ou ainda há referências ao conector que a chamada tenta excluir. |
| `422` | Falta um campo ou um valor é inválido, como um `targetType` desconhecido. A API retorna a resposta em texto simples. |
