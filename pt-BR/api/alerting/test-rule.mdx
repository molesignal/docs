```http
POST /api/v1/alerts/rules/{id}/test
```

Executa uma vez a consulta de uma regra salva na janela de `now - period_secs` a `now` e informa se a condição é atendida. A chamada não altera nada. Não modifica o estado da avaliação, os incidentes, as notificações nem a própria regra. A chamada exige `alerts.rules.manage` e tem corpo vazio.

Teste a regra antes de definir `enabled` como `true`. O sistema salva regras com instruções inválidas ou fluxos desconhecidos sem retornar erro. Só o teste revela o problema.

Uma [regra de APM](/pt-BR/api/alerting/create-rule#regras-de-apm) lê o valor do indicador em vez de executar uma consulta. O resultado contém uma linha com as colunas `value`, `service` e `trace_id`, ou nenhuma linha se o indicador não tiver valor na janela.

Uma [regra dividida por colunas](/pt-BR/api/alerting/create-rule#regras-divididas-por-colunas) lista todos os grupos em `groups`. `matched` é `true` se algum grupo atender à condição, `value` contém o valor do primeiro grupo que atende à condição e `severity` contém a maior gravidade entre os grupos.

Uma [regra de RUM](/pt-BR/api/alerting/create-rule#regras-de-rum) lê o valor do indicador da mesma forma. O resultado contém uma linha com as colunas `value` e `application`, ou nenhuma linha se o indicador não tiver valor na janela. `scannedRows` indica quantas linhas compõem o indicador.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/test \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "matched": true,
  "value": 2.0,
  "severity": "critical",
  "columns": ["c"],
  "rows": [[2]],
  "scannedRows": 2,
  "tookMs": 170
}
```
</ResponseExample>

**Resposta**

| Campo | Tipo | Observações |
|---|---|---|
| `matched` | booleano | Indica se a condição é atendida agora. O resultado ignora `forPeriods`. |
| `value` | número ou nulo | A primeira coluna da primeira linha. `null` quando o resultado não contém um número. |
| `severity` | string ou nulo | A gravidade que o incidente receberia. `null` quando `matched` é `false`. |
| `columns` | array | Os nomes das colunas do resultado da consulta. |
| `rows` | array | Até 20 linhas do resultado. |
| `scannedRows` | inteiro | Número de linhas que a consulta verificou. |
| `tookMs` | inteiro | Duração da consulta em milissegundos. |
| `anomaly` | objeto | Apenas para regras do tipo `anomaly`. Contém `baseline`, `deviation`, `score` de 0 a 1 e um texto em `reason`. |
| `noData` | booleano | Apenas quando `true`: a execução não retornou um valor e a regra não trata a ausência de valor como `0`. |
| `groups` | array | Apenas para regras divididas por colunas, na ordem do resultado. Cada grupo contém `labels`, que associa as colunas aos respectivos valores, além de `value`, `matched` e `severity`. |
| `groupsTruncated` | booleano | Apenas quando `true`: o resultado tem mais de 100 grupos e omite os demais. |

**Erros**

| Status | Causa |
|---|---|
| `400` | A consulta não pode ser executada, por exemplo, por conter SQL inválido ou um campo desconhecido; a regra do tipo `anomaly` não tem histórico que possa servir de linha de base; ou a regra é do tipo `composite` ou `heartbeat` e não executa consultas. |
| `403` | O fluxo da regra não existe ou o token não tem a permissão `alerts.rules.manage`. |
| `404` | A regra não existe. |
