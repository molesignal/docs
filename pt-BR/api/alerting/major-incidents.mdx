Um incidente de amplo impacto que envolve várias pessoas na resposta pode ser declarado grave: ele recebe três funções, pode contar com
uma sala de crise (um chat no Feishu ou no Slack) e uma reunião, tem uma lista de tarefas e envia atualizações à sala de crise e
notifica as pessoas envolvidas. A organização também pode configurar uma regra que declara graves os novos incidentes que atendem aos critérios
desde o início. Consulte [Incidentes graves e análises pós-incidente](/pt-BR/alerting/major-incidents) para ver como as páginas usam esse recurso.

| Método e caminho | O que faz | Permissão |
|---|---|---|
| `GET /api/v1/alerts/incidents/{id}/response` | Retorna a resposta ao incidente grave e as tarefas. | `alerts.incidents.read` no incidente |
| `POST /api/v1/alerts/incidents/{id}/declare` | Declara o incidente como grave. | `alerts.incidents.escalate` no incidente |
| `PUT /api/v1/alerts/incidents/{id}/roles` | Atribui ou remove uma função. | `alerts.incidents.update` no incidente |
| `POST /api/v1/alerts/incidents/{id}/tasks` | Adiciona uma tarefa. | `alerts.incidents.update` no incidente |
| `PUT /api/v1/alerts/incidents/{id}/tasks/{taskId}` | Altera o título, o responsável ou o estado de conclusão de uma tarefa. | `alerts.incidents.update` no incidente |
| `DELETE /api/v1/alerts/incidents/{id}/tasks/{taskId}` | Exclui uma tarefa. | `alerts.incidents.update` no incidente |
| `POST /api/v1/alerts/incidents/{id}/status-updates` | Publica uma atualização. | `alerts.incidents.update` no incidente |
| `GET /api/v1/alerts/response/settings` | Retorna as configurações de incidentes graves da organização. | `alerts.response.read` |
| `PUT /api/v1/alerts/response/settings` | Salva as configurações de incidentes graves da organização. | `alerts.response.manage` |

O MoleSignal registra a declaração, a atribuição de funções, a abertura da sala de crise, a criação e a conclusão de tarefas e a publicação de atualizações
na [linha do tempo](/pt-BR/api/alerting/incident-timeline) do incidente. Também registra a declaração e o salvamento das
configurações no log de auditoria.

## Declarar um incidente grave

```http
POST /api/v1/alerts/incidents/{id}/declare
```

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `commanderId` | string | Não | Responsável pelo comando do incidente. Se o campo for omitido, assume a função quem declara o incidente. |

A API retorna sem alterações um incidente já declarado grave e não permite declarar um incidente resolvido. A declaração
segue as configurações da organização:

1. Os itens da lista de verificação das configurações viram tarefas.
2. O campo `meeting` define como criar a reunião: `feishu_vc` usa um Feishu App para agendar uma reunião de 6 horas no Feishu sob a responsabilidade de
   quem comanda o incidente; `tencentMeeting` agenda uma reunião de 6 horas no Tencent Meeting; `zoom` inicia uma reunião instantânea;
   `googleMeet` cria um espaço de reunião; `fixed_url` usa o link fixo da reunião.
3. O conector definido nas configurações (Feishu App, Slack App, DingTalk ou WeCom) cria um chat em grupo chamado
   `[severity] incident summary` e adiciona os responsáveis pelo incidente, os usuários com funções atribuídas e as partes interessadas (pelas
   identidades vinculadas ao conector). Nos grupos do DingTalk e do WeCom, quem comanda o incidente é o proprietário do grupo. O conector publica uma
   mensagem de abertura com os links do incidente e da reunião.
4. Os conectores de chamados com `onMajorIncident` criam um [chamado](/pt-BR/api/alerting/tickets).

O MoleSignal tenta criar a sala de crise, a reunião e os chamados. Se alguma criação falhar, apenas registra a falha no log, sem invalidar a
declaração.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/declare \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"commanderId": "<user-id>"}'
```
</RequestExample>

As operações de declaração, leitura e atribuição de funções retornam `{ "response": { ... }, "tasks": [ ... ] }`. O campo `response` é
`null` quando o incidente ainda não foi declarado grave.

| Campo | Observações |
|---|---|
| `declaredBy` | Quem declarou o incidente grave. Quando a regra da organização faz a declaração, o valor é `null`. |
| `roles` | Mapeia `commander`, `communications` (responsável pela comunicação) e `scribe` para IDs de usuário. Omite funções sem atribuição. |
| `warRoom` | Dados da sala de crise: `platform` (`lark_app`, `slackApp`, `dingtalk_app` ou `wecom_app`), o conector, o ID do chat e o link de acesso. Os grupos do DingTalk e do WeCom não têm link de acesso, por isso `url` fica vazio. Sem sala de crise, o valor é `null`. |
| `meetingUrl` | Link da reunião. Sem reunião, o valor é `null`. |

## Funções e tarefas

Para atribuir uma função, envie `{ "role": "scribe", "userId": "<user-id>" }`. Para remover a atribuição, use `null` em `userId`.
Declare o incidente como grave antes de atribuir funções.

Para adicionar uma tarefa, envie `{ "title": "…", "assigneeId": "<user-id>" }`. Use um título de 1 a 200 caracteres
e adicione no máximo 50 tarefas por incidente. Para alterar uma tarefa, envie apenas os campos que deseja alterar: `title`, `assigneeId` (use `null`
para remover o responsável) e `done`. Ao concluir uma tarefa, o MoleSignal registra `doneBy` e `doneAt`. A criação e a alteração retornam a
tarefa, e a exclusão retorna `{ "deleted": true }`.

## Publicar uma atualização

```http
POST /api/v1/alerts/incidents/{id}/status-updates
```

| Campo | Tipo | Observações |
|---|---|---|
| `impact` | string | Impacto do incidente. |
| `current` | string | Situação atual. |
| `next` | string | Próximas etapas. |

Preencha pelo menos um campo e use no máximo 2000 caracteres por campo. Antes de publicar, declare o incidente
como grave. O MoleSignal registra a atualização na linha do tempo, publica na sala de crise e envia ao mecanismo de
notificações o evento `incident.status_update`, destinado aos responsáveis pelo incidente, aos usuários com funções atribuídas e às
partes interessadas das configurações. O mecanismo envia as notificações conforme a política integrada
[Atualização de incidente grave: notificar as partes interessadas](/pt-BR/notification-channels#políticas-integradas). O
atributo `status_update` do evento contém `impact`, `current`, `next` e `author`. A operação retorna
`{ "sent": true }`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/status-updates \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"impact": "EU checkout failing for 30% of users", "current": "Rolling back v2026.10.28", "next": "Confirm the error rate drops"}'
```
</RequestExample>

## Configurações da organização

```http
PUT /api/v1/alerts/response/settings
```

| Campo | Tipo | Observações |
|---|---|---|
| `warRoomConnectorId` | string | Conector de notificações que cria salas de crise. Use um conector que possa criar chats em grupo: `lark_app`, `slackApp`, `dingtalk_app` ou `wecom_app`. Com `null`, o MoleSignal não cria salas. |
| `meeting` | string | `none` (padrão, sem reunião), `feishu_vc`, `tencentMeeting`, `zoom`, `googleMeet` ou `fixed_url`. |
| `meetingUrl` | string | Link da reunião para `fixed_url`. Deve começar com `https://`. |
| `meetingConnectorId` | string | Para `feishu_vc`, use o conector do Feishu App que agenda reuniões. Com `null`, o MoleSignal usa o conector da sala de crise, que deve ser um Feishu App. |
| `tencentMeeting` | object | Obrigatório para `tencentMeeting`: `appId`, `sdkId` (se houver) e `secretId` do aplicativo próprio, além do `userid` de quem cria a reunião. |
| `zoom` | object | Obrigatório para `zoom`: `accountId` e `clientId` do aplicativo Server-to-Server OAuth e `host` (e-mail ou ID de usuário). |
| `googleMeet` | object | Obrigatório para `googleMeet`: `organizer` (e-mail) em nome de quem a conta de serviço cria as reuniões. |
| `secrets` | object | Somente gravação: novos segredos da integração de reuniões, sob as chaves `tencentMeeting.secretKey`, `zoom.clientSecret` ou `googleMeet.credentials` (o texto da chave JSON da conta de serviço). Deixe o campo vazio para manter o valor atual. O MoleSignal mantém apenas o segredo da opção de reunião selecionada. |
| `checklist` | array | Itens que viram tarefas ao declarar um incidente grave. Adicione até 30 itens de até 200 caracteres cada. |
| `stakeholderIds` | array | Partes interessadas que recebem notificações de atualização e entram nas salas de crise. |
| `auto` | object | Declaração automática: `{ "enabled": true, "minSeverity": "critical", "conditions": [ ... ] }`. O MoleSignal declara imediatamente como grave qualquer novo incidente com gravidade igual ou superior a `minSeverity` e rótulos que atendam a `conditions`, com `declaredBy` igual a `null`. Escreva `conditions` como nas [regras de roteamento](/pt-BR/api/alerting/create-routing-rule). |

Envie o objeto completo de configurações no corpo da solicitação. A API retorna as configurações salvas. Antes de salvar pela primeira vez, a leitura
retorna os valores padrão. O MoleSignal armazena os segredos com criptografia usando a chave raiz. A leitura retorna apenas `secretsSet`,
com as chaves dos segredos configurados, e `war_room_types`, um campo somente leitura com os tipos de conector que podem
criar salas de crise.

**Erros**

| Status | Motivo |
|---|---|
| `400` | O incidente já foi resolvido ou ainda não foi declarado grave, um campo excede os limites ou o conector não é um Feishu App nem um Slack App desta organização. |
| `403` | Falta uma permissão ou o incidente está fora do escopo de acesso. |
| `404` | O incidente ou a tarefa não existe. |
