```http
POST /api/v1/alerts/incidents
```

Abre um incidente para um problema que nenhuma regra detectou, como um problema relatado por um cliente. O incidente recebe o
rótulo `alert.source=manual`, as anotações `createdBy` (quem fez a chamada) e `description`, e o
`ruleId` `manual`. O incidente ignora os pipelines de alertas, nunca passa por desduplicação com outro incidente e nunca
se resolve sozinho. Esta chamada exige `alerts.incidents.create` e registra o evento de auditoria
`alert.incident.created`.

**Corpo da solicitação**

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `title` | string | Sim | Até 200 caracteres. |
| `description` | string | Não | Markdown, até 20000 caracteres. |
| `severity` | string | Não | `info`, `warning`, `error` (padrão) ou `critical`. |
| `urgency` | string | Não | A chave de um dos [níveis de urgência](/pt-BR/alerting/on-call#níveis-de-urgência-e-prioridade) da organização, como `high` ou `low`. Se não informar esse campo, a política de escalonamento do incidente define a urgência. Consulte [Urgência](/pt-BR/alerting/on-call#urgência). |
| `priority` | string | Não | Uma das prioridades da organização, de `P1` a `P5` por padrão (até `P9`). |
| `assign` | object | Não | Define quem assume o incidente. O padrão é `{"kind": "auto"}`, que segue o [roteamento de alertas](/pt-BR/alerting/routing). `{"kind": "team", "teamId": "..."}` usa a política de plantão da equipe; `{"kind": "policy", "escalationPolicyId": "..."}` usa a política indicada; `{"kind": "users", "userIds": [...]}` notifica diretamente de 1 a 10 membros da organização, sem usar uma política de escalonamento. |
| `services` | string[] | Não | Os serviços afetados, até 20. |
| `labels` | object | Não | Até 50 rótulos. O valor de `alert.source` é sempre `manual`. |
| `declareMajor` | boolean | Não | Também declara um [incidente grave](/pt-BR/alerting/major-incidents). A chamada abre o incidente mesmo se a declaração falhar. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"title": "Customers in the north cannot pay", "severity": "critical", "priority": "P1", "assign": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

A resposta contém o incidente. Consulte [Listar incidentes](/pt-BR/api/alerting/list-incidents) para ver os campos.

**Erros**

| Status | Motivo |
|---|---|
| `400` | Falta o título ou ele excede o limite, há rótulos ou serviços em excesso, `users` indica menos de 1 ou mais de 10 pessoas, ou a equipe, a política ou as pessoas não pertencem à organização. |
| `403` | O token não tem a permissão `alerts.incidents.create`. |
