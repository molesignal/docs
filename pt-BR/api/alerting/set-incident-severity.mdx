```http
PUT /api/v1/alerts/incidents/{id}/severity
```

Define a severidade de um incidente ativo e registra quem fez a chamada em `severitySetBy`. A partir daí, a
avaliação da regra não altera mais a severidade. Aumentar a severidade de um incidente `open` reinicia o
escalonamento na primeira etapa aplicável à nova severidade e define `escalation.reason` como
`severity_raised`. Reduzir a severidade ou alterá-la em um incidente já reconhecido não afeta o escalonamento. A chamada
exige `alerts.incidents.update`.

**Corpo**

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `severity` | string | Sim | `info`, `warning`, `error` ou `critical`. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/severity \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"severity": "critical"}'
```
</RequestExample>

A resposta contém o incidente atualizado. A página [Listar incidentes](/pt-BR/api/alerting/list-incidents) descreve todos os campos.

**Erros**

| Status | Causa |
|---|---|
| `422` | O campo `severity` está ausente ou não contém um dos quatro valores aceitos. |
| `403` | O token não tem a permissão `alerts.incidents.update` ou não tem acesso ao incidente. |
| `404` | O incidente não existe. |
| `409` | O incidente se recuperou, foi mesclado a outro ou continuou mudando durante a atualização. Tente novamente. |
