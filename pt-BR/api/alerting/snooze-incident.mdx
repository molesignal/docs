```http
POST /api/v1/alerts/incidents/{id}/snooze
DELETE /api/v1/alerts/incidents/{id}/snooze
```

`POST` adia um incidente ativo por `durationSecs`. Para adiar um incidente `open`, a chamada
primeiro o reconhece. Durante o adiamento, o incidente não envia notificações nem é escalado. Quando
o prazo em `snoozedUntil` termina, o incidente volta para `open` e os responsáveis recebem uma notificação de escalonamento com
`escalation.reason` igual a `snooze_ended`. Adiar um incidente já adiado redefine o prazo.

`DELETE` encerra o adiamento imediatamente. O incidente permanece em `acknowledged`. Ambas as chamadas exigem
`alerts.incidents.acknowledge`, e `DELETE` não tem corpo.

**Corpo**

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `durationSecs` | inteiro | Sim | De 60 (1 minuto) a 604800 (7 dias). |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/snooze \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"durationSecs": 3600}'
```
</RequestExample>

A resposta retorna o incidente atualizado. [Listar incidentes](/pt-BR/api/alerting/list-incidents) descreve todos os campos.

**Erros**

| Status | Causa |
|---|---|
| `400` | `durationSecs` é menor que 60 ou maior que 604800. |
| `403` | O token não tem a permissão `alerts.incidents.acknowledge` ou não tem acesso ao incidente. |
| `404` | O incidente não existe. |
| `409` | O incidente se recuperou, foi mesclado a outro ou continuou mudando durante a atualização. Tente novamente. |
