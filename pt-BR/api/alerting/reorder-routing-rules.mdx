```http
PUT /api/v1/alerts/routing/rules/order
```

Coloca as [regras de roteamento](/pt-BR/alerting/routing#regras-de-roteamento) da organização na ordem indicada. Requer `alerts.routing.manage`. As regras listadas vêm primeiro, na ordem indicada. As demais mantêm a ordem anterior. A operação ignora IDs que não correspondem a regras da organização.

| Campo | Tipo | Descrição |
|---|---|---|
| `ids` | array | Obrigatório. IDs das regras na ordem em que serão testadas. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/order \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<rule-id-2>", "<rule-id-1>"]}'
```
</RequestExample>

A resposta inclui todas as regras na nova ordem, com `position` numerado a partir de 0, sem lacunas. Consulte [Campos da regra](/pt-BR/api/alerting/list-routing-rules#campos-da-regra).

**Erros**

| Status | Causa |
|---|---|
| `403` | O token não tem a permissão `alerts.routing.manage`. |
| `422` | A solicitação não inclui `ids` ou inclui outro campo. A resposta é em texto simples. |
