```http
PUT /api/v1/alerts/routing/rules/{id}
```

Regrava uma [regra de roteamento](/pt-BR/alerting/routing#regras-de-roteamento) por inteiro. A operação exige `alerts.routing.manage`. Use os mesmos campos de [Criar uma regra de roteamento](/pt-BR/api/alerting/create-routing-rule). Ao omitir um campo opcional, ele volta ao valor padrão. A regra mantém sua posição. Para alterá-la, use [Reordenar regras de roteamento](/pt-BR/api/alerting/reorder-routing-rules). A operação não afeta os incidentes já abertos.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "enabled": false, "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

A resposta contém a regra atualizada.

**Erros**

| Status | Causa |
|---|---|
| `400` | Um campo está incorreto ou a equipe ou política de destino não existe. |
| `403` | O token não tem a permissão `alerts.routing.manage`. |
| `404` | A regra não existe ou pertence a outra organização. |
| `422` | Falta `name` ou `target`, ou a API não reconhece um valor. A resposta é em texto simples. |
