As regras de [inibição](/pt-BR/alerting/inhibition). A leitura exige `alerts.inhibitions.read`, e a alteração exige `alerts.inhibitions.manage`.

```http
GET    /api/v1/alerts/inhibit-rules
POST   /api/v1/alerts/inhibit-rules
GET    /api/v1/alerts/inhibit-rules/{id}
PUT    /api/v1/alerts/inhibit-rules/{id}
DELETE /api/v1/alerts/inhibit-rules/{id}
```

**Corpo da solicitação**

| Campo | Tipo | Descrição |
|---|---|---|
| `name` | string | Obrigatório, com até 255 caracteres. |
| `enabled` | boolean | `true` por padrão. |
| `source.matchers` | array | Condições de rótulo da origem: `{label, op, value}`, em que `op` é `eq`, `neq`, `re` ou `nre`. Todos os critérios devem ser atendidos. |
| `source.min_severity` | string | Severidade mínima. Sem esse valor, aceita qualquer severidade. |
| `target.matchers` | array | Condições de rótulo do alvo. Sem condições, inclui todos os incidentes. |
| `target.max_severity` | string | Severidade máxima. Sem esse valor, aceita qualquer severidade. |
| `equal` | array | Até 16 rótulos que a origem e o alvo devem ter com o mesmo valor. `source.matchers` e `equal` não podem estar ambos vazios. |
| `moreSevereOnly` | boolean | A origem deve ter severidade superior à do alvo. `true` por padrão. |
| `waitSecs` | integer | Tempo de espera para enviar as notificações do alvo. De 0 a 600, com padrão de 60. Valores abaixo de 15 contam como 15. |
| `lingerSecs` | integer | Tempo durante o qual a origem continua inibindo os alvos após se recuperar. De 0 a 3600, com padrão de 120. |
| `comment` | string | Um comentário. |

Nas condições de rótulo, `service` e `host` usam o serviço e o host afetados quando o incidente não tem o rótulo correspondente. `alert.rule_id` identifica a regra ou a origem que abriu o incidente. Uma expressão regular inválida gera um erro `400`.

Cada regra, tanto na lista quanto na visualização de detalhes, também inclui `inhibiting`: o número de incidentes que ela inibe no momento.

## Prévia

```http
POST /api/v1/alerts/inhibit-rules/preview
```

Use o mesmo corpo da solicitação (`name` é opcional e não é necessário salvar a regra). A prévia exige `alerts.inhibitions.read` e aplica apenas essa regra aos incidentes ativos no momento, independentemente do valor de `enabled`.

| Campo | Descrição |
|---|---|
| `pairs[].source_incident_id`, `sourceSummary`, `sourceSeverity` | Incidente que inibe outro. |
| `pairs[].target_incident_id`, `targetSummary`, `targetSeverity` | Incidente sob inibição. |

## Liberar um incidente

```http
POST /api/v1/alerts/incidents/{id}/inhibition/lift
```

Exige `alerts.incidents.update` no incidente. Envia imediatamente as notificações retidas e impede que o incidente volte a sofrer inibição. A operação fica registrada na linha do tempo e no log de auditoria. Não faz nada se o incidente não estiver sob inibição e retorna `409` se o incidente já tiver sido resolvido ou mesclado. Retorna o incidente.

No JSON do incidente, os seguintes campos indicam o estado da inibição:

| Campo | Descrição |
|---|---|
| `inhibition` | Inibição ativa: `ruleId`, `ruleName`, `sourceIncidentId`, `sourceSummary`, `since` e `endingAt`, que indica quando a inibição termina após a recuperação da origem. O campo permanece após a resolução do incidente para indicar que não houve envio de notificações naquele momento. |
| `inhibitionWaitUntil` | Prazo de espera para o envio das notificações (em microssegundos), caso surja uma origem. |
| `inhibitionLiftedBy` | Quem liberou o envio normal de notificações. |
