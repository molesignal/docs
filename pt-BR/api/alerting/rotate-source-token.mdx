```http
POST /api/v1/alerts/sources/{id}/token
```

Gera um novo token para uma [fonte de alertas](/pt-BR/alerting/sources). A operação exige `alerts.sources.manage`, e o corpo da solicitação fica vazio. O token antigo deixa de funcionar imediatamente. Com a federação ativada, ele deixa de funcionar nos outros clusters assim que a alteração é sincronizada. Os remetentes que ainda usam o token antigo precisam usar o novo.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/sources/$SOURCE_ID/token \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

A resposta retorna a fonte com o novo `token`, que aparece apenas desta vez.

**Erros**

| Status | Causa |
|---|---|
| `403` | O token não tem a permissão `alerts.sources.manage`. |
| `404` | A fonte não existe. |
