Both calls require `alerts.incidents.read` on the incident.

## Incidentes semelhantes

```http
GET /api/v1/alerts/incidents/{id}/similar
```

Localiza os incidentes abertos na mesma organização nos 90 dias anteriores ao acionamento deste que
mais se parecem com ele: no máximo 5, maior pontuação primeiro, mais recente primeiro em caso de empate. Incidentes mesclados nele e o
incidente no qual ele foi mesclado ficam de fora. A pontuação é a soma das linhas abaixo, e um incidente precisa
de pelo menos 2 para ser listado:

| Fundamento | Valor em `reasons` | Pontuação |
|---|---|---|
| O mesmo fingerprint do alerta | `fingerprint` | 5 |
| A mesma regra (quando o fingerprint difere) | `rule` | 3 |
| Serviços em comum | `services` | sobreposição × 2 |
| Labels semelhantes: os pares chave-valor em comum são pelo menos 0,3 de todos os pares em ambos | `labels` | proporção × 2 |
| Um título semelhante: similaridade de trigramas de pelo menos 0,3, calculada como o PostgreSQL `pg_trgm` faz, inclusive em chinês | `title` | similaridade × 2 |
| Roteado para a mesma equipe | `team` | 1 |

A sobreposição é a interseção dos dois lados dividida pela união deles.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/similar \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "incidents": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
      "summary": "High error rate · checkout",
      "severity": "critical",
      "status": "resolved",
      "createdAt": 1789400000000000,
      "resolvedAt": 1789401800000000,
      "resolvedBy": "<user-id>",
      "score": 7.6,
      "reasons": ["fingerprint", "services", "labels", "team"],
      "notes": 2,
      "rootCause": "Connection pool exhausted after the payments client stopped releasing connections."
    }
  ]
}
```
</ResponseExample>

| Campo | Descrição |
|---|---|
| `score`, `reasons` | A pontuação e de onde ela veio; consulte a tabela acima. |
| `resolvedBy` | Quem o resolveu; `null` quando a regra dele se recuperou sozinha ou ele ainda está ativo. |
| `notes` | Quantas [notas](/pt-BR/api/alerting/add-incident-note) ele tem. |
| `rootCause` | A primeira frase que diz algo na [causa raiz por IA](/pt-BR/api/alerting/incident-rca) dele (títulos e linhas em branco ignorados), no máximo 200 caracteres; omitida quando ele não tem análise. |

## Mudanças recentes

```http
GET /api/v1/alerts/incidents/{id}/changes
```

Lista as [mudanças relatadas](/pt-BR/apm/deployments#report-deployments-from-ci) de 30
minutos antes do acionamento do incidente até 10 minutos depois, para os serviços do incidente (seus serviços
afetados e o label `service` dele) e os serviços a jusante deles: no máximo 20, mais antigas primeiro.
Os serviços a jusante vêm do mapa de serviços do APM, para no máximo os 3 primeiros serviços do incidente; sem
um mapa de serviços, só contam os serviços do próprio incidente. Quando a regra do incidente foi editada nas 24 horas
anteriores ao acionamento, uma mudança `rule` também é listada.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/changes \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "from": 1789998200000000,
  "to": 1790000600000000,
  "changes": [
    {
      "kind": "deployment",
      "at": 1789999100000000,
      "service": "payments",
      "downstream": true,
      "version": "v2026.10.28",
      "status": "succeeded",
      "commit": "9f2c1e4",
      "author": "dana",
      "link": "https://ci.example.com/pipelines/4821"
    },
    {
      "kind": "rule",
      "at": 1789960000000000,
      "downstream": false,
      "ruleId": "3KEDBLvTYO6DnWi8H9S9MNLpPT7",
      "ruleName": "Checkout error rate"
    }
  ]
}
```
</ResponseExample>

| Campo | Descrição |
|---|---|
| `from`, `to` | O intervalo de tempo consultado, em microssegundos Unix. |
| `kind` | `deployment`, `configuration`, `feature_flag` ou `rule` (a regra do incidente foi editada). |
| `downstream` | `true` quando a mudança pertence a um serviço a jusante, não a um dos serviços do próprio incidente. |
| `version`, `status`, `commit`, `description`, `author` | O que o relatório carregava; omitido quando não carregava. |
| `link` | O endereço do pipeline relatado ou, na falta dele, o endereço do pull request. |
| `ruleId`, `ruleName` | A regra de uma mudança `rule`. |

**Erros**

| Status | Motivo |
|---|---|
| `403` | O token não tem `alerts.incidents.read` ou não consegue acessar este incidente. |
| `404` | O incidente não existe. |

## Impacto no negócio

```http
GET /api/v1/alerts/incidents/{id}/business-impact
```

Para cada [chave de negócio](/pt-BR/business-context) que os spans carregam, lista os valores cujas requisições aos
serviços do incidente mais falharam, de 30 minutos antes do acionamento do incidente até 10 minutos depois
(não mais tarde que agora): no máximo 5 valores por chave, os com mais requisições com falha primeiro, depois os com mais requisições. Um
incidente sem serviços lê as requisições de todos os serviços. As requisições são os spans em que um serviço recebeu
uma requisição.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/business-impact \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "from": 1789998200000000,
  "to": 1790000600000000,
  "services": ["checkout"],
  "declared": true,
  "keys": [
    {
      "key": "tenant",
      "label": "Tenant",
      "field": "tenant.id",
      "more": true,
      "values": [
        { "value": "acme", "requests": 300, "errors": 120, "important": true },
        { "value": "globex", "requests": 90, "errors": 4, "important": false }
      ]
    }
  ]
}
```
</ResponseExample>

| Campo | Descrição |
|---|---|
| `services` | Os serviços do incidente, cujas requisições foram lidas. Vazio quando ele não nomeia nenhum. |
| `declared` | `false` quando nenhuma chave de negócio nomeia um campo de span: nesse caso `keys` fica vazio. |
| `field` | O campo do span de onde a chave foi lida. |
| `important` | O valor está entre os que a organização marcou como importantes para a chave. |
| `more` | Mais valores tiveram requisições do que os listados. |

Fica de fora uma chave cujo campo o stream de traces não tem ou mantém criptografado, ou da qual nenhuma requisição teve valor.

**Erros**

| Status | Motivo |
|---|---|
| `403` | O token não tem `alerts.incidents.read` ou não consegue acessar este incidente, ou não tem `streams.query` e `sys.telemetry.read` ao mesmo tempo. |
| `404` | O incidente não existe. |
