```http
POST /api/v1/alerts/rules/{id}/trigger
```

Abre um incidente para uma regra sem avaliar a condição. Use a chamada para testar notificações e escalonamento ou para abrir um incidente manualmente. A chamada funciona com regras desativadas. Ela exige a permissão `alerts.rules.manage` e usa um corpo vazio.

- Quando a regra já tem um incidente aberto ou reconhecido, a chamada retorna esse incidente sem alterações. É seguro repetir a chamada.
- Caso contrário, a chamada cria um incidente com o status `open` e envia o evento de notificação de disparo.
- A chamada usa o primeiro valor disponível nesta ordem: o campo `severity` da regra, o rótulo `severity` e o valor `warning`. A chamada ignora `thresholds`.
- A anotação `manual_triggered_by` contém o identificador do usuário que fez a chamada, e `triggering_query.sample_values` fica vazio.

Uma regra ativada resolve o incidente na próxima avaliação se a condição não for atendida. Uma regra desativada mantém o incidente aberto até que um usuário o resolva.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/trigger \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**Erros**

| Status | Causa |
|---|---|
| `403` | O token não tem a permissão `alerts.rules.manage`. |
| `404` | A regra não existe. |
