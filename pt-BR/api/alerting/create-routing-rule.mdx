```http
POST /api/v1/alerts/routing/rules
```

Cria uma [regra de roteamento](/pt-BR/alerting/routing#regras-de-roteamento). Exige `alerts.routing.manage`. A nova regra fica no fim da lista. Use [Reordenar regras de roteamento](/pt-BR/api/alerting/reorder-routing-rules) para movê-la para cima. Cada organização pode ter até 200 regras de roteamento.

| Campo | Tipo | Descrição |
|---|---|---|
| `name` | string | Obrigatório. De 1 a 128 caracteres após remover os espaços nas extremidades. |
| `enabled` | boolean | O valor padrão é `true`. |
| `conditions` | array | Até 16 condições. Por padrão, a lista fica vazia. Uma `key` tem de 1 a 512 caracteres. `equals`, `not_equals` e `matches` aceitam um valor cada, e `in` aceita de 1 a 100. Cada valor pode ter até 512 caracteres. O padrão de `matches` deve compilar. |
| `minSeverity` | string \| null | `info`, `warning`, `error` ou `critical`. Por padrão, aceita qualquer severidade. |
| `origins` | array | Aceita uma seleção entre `rule`, `external` e `synthetic`. Por padrão, a lista fica vazia, o que inclui todas as origens. |
| `target` | object | Obrigatório. `{"kind": "team", "teamId": …}` deve indicar uma equipe da organização, e `{"kind": "policy", "policyId": …}` deve indicar uma política de escalonamento da organização. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "conditions": [{"key": "env", "operator": "equals", "values": ["prod"]}], "minSeverity": "error", "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

A resposta retorna a nova regra. Consulte [Campos da regra](/pt-BR/api/alerting/list-routing-rules#campos-da-regra).

**Erros**

| Status | Causa |
|---|---|
| `400` | A solicitação contém um nome vazio, uma condição com quantidade incorreta de valores, um padrão que não compila ou uma equipe ou política de destino inexistente, ou a organização já tem 200 regras. |
| `403` | O token não tem a permissão `alerts.routing.manage`. |
| `422` | Falta `name` ou `target`, ou a solicitação contém um valor desconhecido, como um `operator` não reconhecido. A resposta vem em texto simples. |
