```http
GET /api/v1/alerts/importance
PUT /api/v1/alerts/importance
```

`GET` exige `alerts.importance.read`, e `PUT` exige `alerts.importance.manage`. Ambos retornam os níveis da organização:

```json
{
  "levels": {
    "priorities": [
      {"priority": "P1", "name": "Critical business impact", "description": "Customers cannot pay"},
      {"priority": "P2", "name": "", "description": ""},
      {"priority": "P3", "name": "", "description": ""}
    ],
    "urgencies": [
      {"key": "urgent", "name": "Urgent", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["critical"]},
      {"key": "high", "name": "", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["error"]},
      {"key": "low", "name": "", "escalates": false, "quietHours": "block", "steps": "low", "severities": ["warning", "info"]}
    ]
  },
  "updatedBy": "3KF1...",
  "updatedAt": 1793059200000000
}
```

Uma organização que nunca salvou níveis recebe os níveis padrão: de `P1` a `P5`, além de `high` e `low`, conforme
descrito em [Urgência](/pt-BR/alerting/on-call#urgência), com `updatedBy` vazio. `PUT` recebe o
objeto `levels`, substitui os níveis e registra o evento de auditoria `alert_importance.updated`.

| Campo | Descrição |
|---|---|
| `priorities` | De 1 a 9 níveis consecutivos: `P1`, `P2`, … `name` aceita até 32 caracteres, e `description`, até 200. Se o nome estiver vazio, use a chave. |
| `urgencies` | De 2 a 5 níveis, começando pelo mais urgente. `key` começa com uma letra minúscula e aceita apenas letras minúsculas, dígitos e sublinhados, até 32 caracteres. Mantenha `high` e `low`. `name` aceita até 32 caracteres. Se o nome estiver vazio, use o nome padrão. |
| `escalates` | `true` aciona notificações de plantão conforme as etapas da política de escalonamento; `false` notifica apenas na primeira etapa. |
| `quietHours` | `switch` respeita a preferência **Receber alertas de alta urgência mesmo durante o horário de silêncio**; `block` nunca aciona notificações de plantão durante o horário de silêncio. |
| `steps` | Define qual dos dois grupos de etapas da pessoa de plantão o nível usa: `high` ou `low`. |
| `severities` | Severidades associadas ao nível quando uma política define a urgência por severidade. Associe cada uma das severidades `critical`, `error`, `warning` e `info` a um único nível. |

Os níveis definem quais prioridades e urgências as regras, as políticas de escalonamento, os incidentes e a API podem usar. Uma prioridade fora dos
níveis configurados ou uma urgência não configurada gera o erro `400` nesses casos. Para alertas externos ou pipelines de alertas,
o MoleSignal substitui uma prioridade fora dos níveis configurados pela mais baixa e descarta urgências que a organização não
configurou. As notificações incluem os nomes em `{{priority_name}}` e `{{urgency_name}}`.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/importance \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d @levels.json
```
</RequestExample>

**Erros**

| Status | Motivo |
|---|---|
| `400` | Os níveis não atendem a uma regra da tabela acima. |
| `403` | O token não tem a permissão necessária. |
| `422` | Um campo tem o tipo incorreto ou uma chave é inválida. |
