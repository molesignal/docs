Um conector de tickets integra o Jira (Cloud ou Data Center / Server), o ServiceNow ou o Feishu Project (Meegle fora da
China). O ticket criado para um incidente acompanha seu andamento: o conector pode registrar confirmações, resoluções e notas
como comentários. Ao resolver o incidente, o conector pode marcar o ticket como concluído. O conector sincroniza o status do ticket
a cada 5 minutos, e o Jira também pode enviar a atualização imediatamente por um webhook. Para saber como as páginas usam esse recurso, consulte
[Tickets](/pt-BR/alerting/tickets).

| Método e caminho | O que faz | Permissão |
|---|---|---|
| `GET /api/v1/alerts/tickets/connectors` | Retorna os conectores de tickets da organização no formato `{ "connectors": [ ... ] }`. | `alerts.tickets.read` |
| `POST /api/v1/alerts/tickets/connectors` | Cria um conector. | `alerts.tickets.manage` |
| `PUT /api/v1/alerts/tickets/connectors/{id}` | Substitui um conector sem alterar `system`. | `alerts.tickets.manage` |
| `DELETE /api/v1/alerts/tickets/connectors/{id}` | Exclui um conector. | `alerts.tickets.manage` |
| `POST /api/v1/alerts/tickets/connectors/{id}/test` | Testa a conexão: o Jira retorna `{ "ok": true, "detail": "<signed-in user>" }`, e o Feishu Project consulta uma vez o tipo de item de trabalho. | `alerts.tickets.manage` |
| `GET /api/v1/alerts/tickets/sites` | Retorna o endereço de cada plataforma do Feishu Project: `{ "meegle": [{ "key": "feishu", "url": "https://project.feishu.cn" }, { "key": "lark", "url": "https://meegle.com" }] }`. | `alerts.tickets.read` |
| `GET /api/v1/alerts/incidents/{id}/tickets` | Retorna os tickets do incidente no formato `{ "tickets": [ ... ] }`. | `alerts.incidents.read` no incidente |
| `POST /api/v1/alerts/incidents/{id}/tickets` | Cria um ticket para o incidente usando um conector. | `alerts.incidents.tickets` no incidente |
| `POST /api/v1/public/tickets/jira/{connectorId}` | Recebe o webhook do Jira sem exigir login. | `X-Hub-Signature` |

## Conectores

**Corpo da solicitação**

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `name` | string | Sim | Nome do conector. |
| `system` | string | Sim | `jira` ou `meegle`. |
| `settings` | object | Sim | Site, projeto, tipo e mapeamentos. Consulte as seções abaixo. |
| `secrets` | object | Na criação | O conector armazena as credenciais de forma criptografada e nunca as retorna. O Jira aceita `apiToken` (um token de API do Cloud ou um token de acesso pessoal do Data Center) e, opcionalmente, `webhook_secret`. O Feishu Project aceita `plugin_secret`. Para manter o valor de um segredo ao editar, deixe o campo vazio. |
| `comments` | object | Não | `{ "acknowledged": true, "resolved": true, "notes": true }`: adiciona comentários na confirmação e na resolução do incidente e registra as notas do incidente como comentários. O padrão é `false` para todas as opções. |
| `transitionOnResolve` | boolean | Não | Marca o ticket como concluído na resolução do incidente. Padrão: `false`. |
| `resolveIncidentWhenDone` | boolean | Não | Resolve o incidente quando o ticket é concluído, esteja o incidente aberto ou confirmado, sem registrar quem fez a resolução. Padrão: `false`. |
| `auto` | object | Não | Tickets automáticos: `{ "enabled": true, "minSeverity": "error", "conditions": [ ... ] }`. Cria um ticket para cada novo incidente com severidade igual ou superior a `minSeverity` e rótulos que atendam a `conditions`. Escreva `conditions` como nas [regras de roteamento](/pt-BR/api/alerting/create-routing-rule). |
| `onMajorIncident` | boolean | Não | Cria um ticket na declaração de um [incidente grave](/pt-BR/api/alerting/major-incidents). Padrão: `false`. |
| `enabled` | boolean | Não | Padrão: `true`. Um conector desativado não cria nem sincroniza tickets e não recebe webhooks. |

**`settings`: Jira**

| Campo | Observações |
|---|---|
| `siteUrl` | Endereço do site, começando com `https://`, por exemplo, `https://example.atlassian.net`. |
| `deployment` | `cloud` (padrão): usa o e-mail da conta e um token de API pela API REST v3, com corpos no Atlassian Document Format. `data_center`: usa um token de acesso pessoal pela API REST v2. |
| `email` | E-mail da conta do Cloud. |
| `projectKey`, `issueType` | Chave do projeto e tipo de issue, por exemplo, `OPS` e `Incident`. |
| `priorities` | Mapeia severidades para nomes de prioridades no Jira, por exemplo, `{ "critical": "Highest" }`. Severidades sem mapeamento não definem prioridade. |
| `labels` | Rótulos que o conector adiciona aos tickets além de `molesignal`, que todos os tickets recebem. |
| `fields` | Valores padrão para outros campos na criação. Use o ID do campo no Jira como chave. |
| `resolveTransition` | Nome ou ID da transição que o conector aplica na resolução do incidente. Se o campo estiver vazio, o conector usa a primeira transição para um status de conclusão. |

**`settings`: Feishu Project**

| Campo | Observações |
|---|---|
| `site` | Plataforma: `feishu` (padrão, Feishu Project, em `https://project.feishu.cn`) ou `lark` (Meegle, em `https://meegle.com`). O endereço depende da plataforma e não permite alterações. |
| `pluginId` | ID do plugin. Use com `plugin_secret` para obter um token de plugin. |
| `userKey` | Identifica o usuário em cujo nome o conector cria tickets e comentários. |
| `projectKey`, `workItemTypeKey` | Espaço e tipo de item de trabalho. |
| `priorityField`, `priorities` | Chave do campo de prioridade e mapeamento das severidades para os valores das opções de prioridade. Se estiverem vazios, o conector não define prioridade. |
| `fields` | Valores padrão para outros campos na criação. Use field_key como chave. |
| `resolveTransitionId` | Para um item de trabalho com fluxo de status: ID da transição que o conector aplica na resolução do incidente. |
| `resolveNodeId` | Para um item de trabalho com fluxo de nós: ID do nó que o conector conclui na resolução do incidente. |
| `doneStates` | Chaves dos status que indicam conclusão. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/tickets/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "name": "Jira OPS",
    "system": "jira",
    "settings": {
      "siteUrl": "https://example.atlassian.net",
      "deployment": "cloud",
      "email": "oncall-bot@example.com",
      "projectKey": "OPS",
      "issueType": "Incident",
      "priorities": { "critical": "Highest", "error": "High" }
    },
    "secrets": { "apiToken": "<jira-api-token>", "webhookSecret": "<webhook-secret>" },
    "comments": { "acknowledged": true, "resolved": true, "notes": true },
    "transitionOnResolve": true,
    "auto": { "enabled": true, "minSeverity": "critical", "conditions": [] }
  }'
```
</RequestExample>

A resposta traz o conector salvo: omite `secrets`, e `secretsSet` lista as credenciais
configuradas. Um conector do Jira também inclui `webhook_path`, com o valor
`/api/v1/public/tickets/jira/<connector ID>`. O log de auditoria registra a criação, a alteração e a exclusão de conectores.

**`settings` para ServiceNow**

| Campo | Descrição |
|---|---|
| `instanceUrl` | Endereço da instância, começando com https. |
| `auth` | `basic` (padrão, segredo `password`), `oauth` (credenciais do cliente, segredo `clientSecret`) ou `apiKey` (segredo `apiKey`). |
| `username`, `clientId` | Usuário da autenticação básica e ID do cliente OAuth, respectivamente. |
| `table` | Tabela em que o conector cria o registro. O padrão é `incident`. A tabela deve estender `task`. |
| `assignmentGroup`, `callerId`, `category` | Campos que o conector preenche na criação. Os dois primeiros usam valores `sys_id`. |
| `priorities` | Severidade ou prioridade → `impact/urgency`. Um único número vale para ambos. |
| `fields` | Valores padrão para outros campos na criação (nome do campo → valor). |
| `resolveState`, `closeCode` | Valores de `state` e `closeCode` que o conector grava na resolução do incidente. Os padrões são `6` e `Solution provided`, respectivamente. Se `closeCode` estiver vazio, o conector não grava esse campo. |
| `doneStates` | Valores de `state` que indicam conclusão. Os padrões são `6`, `7` e `8`. |

O teste do conector retorna `{ "ok": true, "detail": "<table>" }`.

## Crie um ticket para um incidente

```http
POST /api/v1/alerts/incidents/{id}/tickets
```

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `connectorId` | string | Sim | Conector a usar na criação. Se o incidente já tiver um ticket nesse conector, a API retorna o ticket existente. |

O título do ticket segue o formato `[severity] incident summary`. O corpo inclui a severidade e o status do incidente,
os serviços, os rótulos, a consulta que o disparou, o resumo da causa raiz gerado pela IA e o endereço da página do incidente, no
idioma padrão do workspace. A linha do tempo do incidente e o log de auditoria registram o ticket.

<ResponseExample>
```json 200
{
  "id": "3KJ4m8T1qHd0Ue6WzB2nLc9RfPa",
  "orgId": "<organization-id>",
  "incidentId": "<incident-id>",
  "connectorId": "<connector-id>",
  "system": "jira",
  "externalId": "10482",
  "externalKey": "OPS-42",
  "url": "https://example.atlassian.net/browse/OPS-42",
  "status": "To Do",
  "done": false,
  "incidentStatus": "open",
  "createdBy": "<user-id>",
  "createdAt": 1790000000000000,
  "syncedAt": 1790000000000000,
  "lastError": "",
  "actionItemId": null
}
```
</ResponseExample>

| Campo | Observações |
|---|---|
| `externalId`, `externalKey` | ID e chave da issue do Jira. No Feishu Project, ambos contêm o ID do item de trabalho. |
| `status`, `done` | Nome do status na última sincronização e indicação de que o ticket está ou não concluído. O Jira usa a categoria de status `done`, e o Feishu Project usa `doneStates` do conector. |
| `syncedAt`, `lastError` | Data e hora da última sincronização e erro da última sincronização ou tentativa de adicionar um comentário. Uma operação bem-sucedida limpa o erro. |
| `actionItemId` | Identifica o [item de ação do post-mortem](/pt-BR/api/alerting/postmortems) para o qual o conector criou o ticket. Esses tickets não recebem comentários nem transições do incidente. |

## Sincronização de status e webhook do Jira

O MoleSignal sincroniza os chamados não concluídos a cada 5 minutos. Quando um chamado é concluído e o conector tem
`resolveIncidentWhenDone`, o MoleSignal resolve o incidente, exceto no caso de chamados criados para itens de ação de
post-mortem.

Quando o conector do Jira tiver um `webhook_secret`, adicione um webhook no Jira em **Configurações do sistema → WebHooks**:
use como URL o endereço externo do MoleSignal seguido de `webhook_path`, use o mesmo
`webhook_secret` como segredo e selecione as atualizações de itens como eventos.

```http
POST /api/v1/public/tickets/jira/{connectorId}
```

O MoleSignal calcula o HMAC-SHA256 do corpo com `webhook_secret` e compara o resultado com
`X-Hub-Signature: sha256=<hex>`. O corpo tem no máximo 1 MiB.

| Status | Motivo |
|---|---|
| `204` | Webhook aceito. O MoleSignal também retorna `204` se o item no corpo não for um chamado criado pelo MoleSignal. |
| `401` | A assinatura não confere ou o conector não tem `webhook_secret` e não aceita webhooks. |
| `404` | O conector não existe, está desativado ou não é do Jira. |
