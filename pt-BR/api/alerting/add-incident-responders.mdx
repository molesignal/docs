```http
POST /api/v1/alerts/incidents/{id}/responders
```

Adiciona os usuários em `userIds` à lista de responsáveis por um incidente ativo e envia a cada novo responsável uma notificação
de escalonamento com `escalation.reason` definido como `responder_added`. O status do incidente não muda,
e a chamada não notifica quem já está na lista de responsáveis. A chamada exige `alerts.incidents.update`.

**Corpo**

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `userIds` | array | Sim | De 1 a 10 IDs de usuários que fazem parte da organização. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/responders \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"userIds": ["<another-user-id>"]}'
```
</RequestExample>

A resposta contém o incidente atualizado. [Listar incidentes](/pt-BR/api/alerting/list-incidents) descreve todos os campos.

**Erros**

| Status | Causa |
|---|---|
| `400` | `userIds` está vazio, contém mais de 10 usuários ou inclui um usuário de fora da organização. |
| `403` | O token não tem a permissão `alerts.incidents.update` ou o incidente está fora do escopo do token. |
| `404` | O incidente não existe. |
| `409` | O incidente se recuperou, foi mesclado a outro ou continuou mudando durante a atualização. Tente novamente. |
