```http
POST /api/v1/alerts/routing/test
```

Determina como um incidente com esses rótulos seria [roteado](/pt-BR/alerting/routing#ordem-de-roteamento) com base nas regras de roteamento, nas políticas de plantão das equipes e no catálogo de serviços atuais. Exige `alerts.routing.read`. A simulação considera que a origem usa a política padrão. Não abre incidentes nem envia notificações.

| Campo | Tipo | Descrição |
|---|---|---|
| `labels` | objeto | Rótulos do incidente. O rótulo `alert.source` indica a origem: `external` para uma fonte de alertas, `synthetic` para uma verificação sintética e qualquer outro valor para uma regra de alerta. |
| `services` | array | Serviços afetados. Se os rótulos não incluírem `service.name` nem `service`, o roteamento usa o primeiro serviço da lista. |
| `severity` | string | `info`, `warning` (padrão), `error` ou `critical`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"labels": {"service.name": "checkout", "env": "prod"}, "severity": "critical"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "decision": {
    "escalationPolicyId": "<policy-id>",
    "teamId": "<team-id>",
    "routing": { "reason": "rule", "ruleId": "<rule-id>", "ruleName": "Payments in production" }
  },
  "matchedRuleId": "<rule-id>",
  "service": "default/checkout",
  "serviceTeamId": "<team-id>",
  "labelTeamId": null
}
```
</ResponseExample>

| Campo | Descrição |
|---|---|
| `decision.escalation_policy_id` | Política de escalonamento que se aplicaria ao incidente. O valor `default` indica a política padrão. |
| `decision.team_id` | Equipe que receberia o incidente, ou `null`. |
| `decision.routing` | Motivo da decisão de roteamento, com o mesmo significado de `routing` em um incidente. Consulte [Campos do incidente](/pt-BR/api/alerting/list-incidents#campos-do-incidente). |
| `matchedRuleId` | Regra de roteamento que correspondeu ao incidente, ou `null`. |
| `service` | Serviço consultado para identificar a equipe responsável, no formato `namespace/name`. |
| `serviceTeamId` | Equipe responsável pelo serviço no catálogo de serviços. |
| `labelTeamId` | Equipe indicada pelo rótulo `teamId` ou `team`. |
