```http
GET    /api/v1/alerts/sources/{id}/mailbox
PUT    /api/v1/alerts/sources/{id}/mailbox
DELETE /api/v1/alerts/sources/{id}/mailbox
POST   /api/v1/alerts/sources/{id}/mailbox/test
```

A caixa de correio IMAP que uma [fonte de e-mail](/pt-BR/alerting/sources#e-mail) lê. A leitura exige `alerts.sources.read`; as alterações e os testes exigem `alerts.sources.manage`. Apenas fontes do tipo `email` têm uma caixa de correio. A configuração fica no cluster que recebe os dados da fonte e não é sincronizada por federação. Antes de fazer um `PUT`, registre a lista de remetentes na fonte (`email.allowed_senders`).

**Corpo de `PUT` e `test`**

| Campo | Tipo | Descrição |
|---|---|---|
| `host` | string | Obrigatório: nome do host, sem esquema nem porta. |
| `port` | integer | 993 por padrão. |
| `security` | string | `tls` (padrão), `starttls` ou `none`. |
| `username` | string | Obrigatório. |
| `secret` | string | A senha ou o segredo do cliente. A resposta nunca inclui esse valor; deixe o campo vazio para manter o valor salvo. |
| `auth` | object | `{"kind": "password"}` (padrão) ou `{"kind": "oauth2", "tokenUrl": "https://…", "clientId": "…", "scope": "…"}` para usar, via `XOAUTH2`, um token obtido com as credenciais do cliente. |
| `folder` | string | `INBOX` por padrão. |
| `pollSecs` | integer | Intervalo entre leituras, de 15 a 3600, com padrão de 60. |

Cada conexão usa apenas o endereço para o qual o host resolve naquele momento e nunca usa um endereço de metadados da nuvem. Se o host, a conta ou a pasta mudar, a próxima conexão redefine a posição de leitura.

**Resposta de `GET` e `PUT`** (`GET` retorna `null` quando não há configuração)

| Campo | Descrição |
|---|---|
| `settings` | As configurações acima, sem `secret`. |
| `secretSet` | Indica se há um segredo configurado. |
| `reading` | Indica se a fonte já se conectou e está lendo as mensagens que chegam desde então. |
| `lastPolledAt`, `lastSuccessAt` | Horários da última tentativa de leitura e da última leitura bem-sucedida (em microssegundos). |
| `lastError` | Motivo da falha na última leitura. Uma leitura bem-sucedida limpa esse campo. |

`test` se conecta uma vez com as configurações do corpo da solicitação (se `secret` estiver vazio, usa o valor salvo) e retorna `{"ok": true, "messages": 3}` ou `503` com a mensagem do servidor de e-mail.

<RequestExample>
```bash cURL
curl -X PUT "http://localhost:5080/api/v1/alerts/sources/$SOURCE_ID/mailbox" \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"host": "imap.example.com", "username": "alerts@example.com", "secret": "<password>"}'
```
</RequestExample>
