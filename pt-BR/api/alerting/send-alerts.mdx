```http
POST /api/v1/intake/alerts
```

Um sistema externo faz a chamada com o token de uma [fonte de alertas](/pt-BR/alerting/sources): no cabeçalho `Authorization: Bearer <token>` ou, se o sistema não puder definir cabeçalhos, no endereço com `?token=<token>`. Todas as fontes usam o mesmo endereço. O token identifica a fonte do alerta, e o tipo da fonte determina o formato usado para interpretar o corpo. [Configure o remetente](/pt-BR/alerting/sources#configure-o-remetente) explica o formato de cada remetente (uma fonte de e-mail lê a mensagem bruta com `Content-Type: message/rfc822`). Esta página descreve o corpo das solicitações para fontes do tipo **API**. O corpo tem no máximo 4 MiB.

O corpo contém um objeto de alerta ou um array com até 100 objetos. A API rejeita campos desconhecidos.

| Campo | Tipo | Descrição |
|---|---|---|
| `action` | string | `trigger` (padrão), `acknowledge` ou `resolve`. |
| `dedupKey` | string | A chave de desduplicação na fonte, com até 255 caracteres. Cada chave pode ter no máximo um incidente ativo por vez. Obrigatória para `acknowledge` e `resolve`. Para `trigger`, se a chave estiver ausente, a API calcula uma a partir de `summary` e `labels` e a retorna na resposta. |
| `summary` | string | O título do incidente, obrigatório para `trigger`, com até 1024 caracteres. |
| `severity` | string | `critical`, `error`, `warning` ou `info`. Se o campo estiver ausente, vale a severidade padrão da fonte. |
| `priority` | string | A prioridade do incidente, de `P1` a `P9` (também aceita de `1` a `9`). Se o nível informado estiver além dos níveis da organização, vale o nível mais baixo. Se o campo estiver ausente, o incidente fica sem prioridade. |
| `urgency` | string | A urgência do incidente, identificada pela chave de um dos níveis da organização, como `high` ou `low`. A API ignora chaves desconhecidas. Se o campo estiver ausente, vale a política de escalonamento da fonte. Um alerta sem `severity` tem urgência `high`. |
| `labels` | object | Até 64 rótulos. A chave não pode começar com `alert.` ou `__molesignal` nem ser `external.kind`. |
| `annotations` | object | Anotações. O limite é de 64, incluindo os links. |
| `links` | array | Até 10 objetos `{"name": "…", "url": "https://…"}`. A API grava cada link nas anotações usando `name` como chave. Se o link não tiver `name`, a API usa `link`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/intake/alerts \
  -H "authorization: Bearer $SOURCE_TOKEN" \
  -H "content-type: application/json" \
  -d '{"dedupKey": "disk-full/web-1", "summary": "Disk almost full on web-1", "severity": "critical", "labels": {"host.name": "web-1"}, "links": [{"name": "Runbook", "url": "https://wiki.example.com/disk"}]}'
```
</RequestExample>

A resposta retorna o resultado de cada alerta, na mesma ordem. `message` explica por que a API não tomou nenhuma ação quando conseguiu ler o corpo, mas não encontrou alertas para processar, como em um evento de teste do PagerDuty.

<ResponseExample>
```json 200
{
  "alerts": [
    {
      "dedupKey": "disk-full/web-1",
      "outcome": "opened",
      "incidentId": "3KEDNEyqouYJeBDTLTMTBui7XHW",
      "reason": null
    }
  ],
  "message": null
}
```
</ResponseExample>

| `outcome` | Significado |
|---|---|
| `opened` | A API abriu um novo incidente. |
| `updated` | A severidade do incidente ativo ou os alertas do grupo de notificação mudaram. |
| `unchanged` | O incidente ativo já estava nesse estado ou já tinha um reconhecimento registrado por uma pessoa. |
| `acknowledged` | A API registrou o reconhecimento do incidente. |
| `resolved` | A API resolveu o incidente, mesmo se já houvesse um reconhecimento. |
| `ignored` | Nada mudou. `reason` explica o motivo, como a ausência de um incidente ativo ou uma mensagem mais antiga que a última. |

**Erros**

| Status | Causa |
|---|---|
| `400` | A API não consegue ler o corpo. `message` explica o motivo. |
| `401` | O token está ausente ou incorreto, ou a fonte não existe. |
| `403` | A organização está desativada. |
| `409` | A fonte está desativada. |
| `413` | O corpo excede 4 MiB. |
| `503` | O cluster que recebe os alertas da fonte está inacessível ou a API não conseguiu processar toda a solicitação. Tente novamente. Uma nova tentativa não abre o mesmo incidente duas vezes. |
