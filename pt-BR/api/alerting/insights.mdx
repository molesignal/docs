```http
GET /api/v1/alerts/insights
```

Agrega os incidentes criados em uma janela e os dados de resposta: quanto tempo levou para alguém
assumir cada incidente, quanto tempo levou até a recuperação e quantos foram escalonados. Compara esses dados com os do período anterior, de mesma duração.
Exclui incidentes mesclados a outros. A chamada exige `alerts.incidents.read`. Consulte a carga de plantão de cada pessoa em
[Carga de plantão](/pt-BR/api/alerting/oncall-load).

**Parâmetros de consulta**

| Parâmetro | Tipo | Observações |
|---|---|---|
| `windowSecs` | inteiro | A janela retrospectiva, em segundos. O valor padrão é `604800` (7 dias). O valor fica limitado ao intervalo de 3600 a 31536000. |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/alerts/insights?windowSecs=86400" \
  -H "authorization: Bearer $MS_TOKEN"
```

**Resposta**

| Campo | Observações |
|---|---|
| `windowSecs` | A janela após a aplicação dos limites. |
| `total` | O número de incidentes criados na janela. |
| `active` | Incidentes com status `open` ou `acknowledged`. |
| `closed` | Incidentes com status `resolved` ou `closed`. |
| `mttrSecs` | O tempo médio, em segundos, da criação à resolução dos incidentes resolvidos. `0` quando não há incidentes resolvidos. |
| `noiseRate` | A proporção, de 0 a 1, dos incidentes resolvidos em até 60 segundos entre todos os incidentes resolvidos. `0` quando não há incidentes resolvidos. |
| `byHour` | 24 contagens de incidentes por hora de criação em UTC. |
| `bySeverity` | A contagem por severidade. Não inclui severidades sem incidentes. |
| `topServices`, `topRules` | Até 8 entradas com `key` e `count`, em ordem decrescente de contagem. A chave é o nome de um serviço ou o identificador de uma regra. |
| `response.current`, `response.previous` | Os dados de resposta na janela e no período anterior de mesma duração. Os campos aparecem abaixo. |
| `response.breakdown` | Os dados da janela por equipe (`teams`, com o ID da equipe como chave), serviço (`services`) e pessoa (`people`, com a primeira pessoa a assumir o incidente como chave). Cada grupo tem até 20 linhas, em ordem decrescente de incidentes. Um incidente com vários serviços conta uma vez para cada serviço. Cada linha inclui `incidents`, o tempo médio em segundos até alguém assumir o incidente (`mttaSecs`), o tempo médio em segundos até a recuperação (`mttrSecs`) e a taxa de escalonamento (`escalationRate`). |

**`response.current` e `response.previous`**

| Campo | Observações |
|---|---|
| `incidents` | Os incidentes criados no período. |
| `responded` | Os incidentes que alguém assumiu. O primeiro reconhecimento conta como o momento em que alguém assumiu o incidente. Se alguém resolver um incidente sem reconhecê-lo, conta o momento da resolução. Não inclui incidentes cuja regra se recuperou automaticamente. |
| `mtta` | Tempo em segundos do disparo até alguém assumir o incidente pela primeira vez: a média `meanSecs`, a mediana `p50Secs` e o percentil 90 `p90Secs`. Todos os valores são `0` quando ninguém assume um incidente. |
| `mttr` | Tempo em segundos do disparo até a recuperação, considerando apenas os incidentes que se recuperaram. Usa as mesmas estatísticas: média, P50 e P90. |
| `escalationRate` | A proporção, de 0 a 1, de incidentes escalonados: os que chegaram à segunda etapa ou foram [escalonados imediatamente](/pt-BR/api/alerting/escalate-incident). |
| `steps` | Os resultados de cada etapa, com `step` a partir de 0: os incidentes que chegaram à etapa (`reached`) e os que receberam reconhecimento nela (`acknowledged`). Inclui apenas incidentes com escalonamentos na linha do tempo. Fica vazio quando não há nenhum no período. |
| `ackVia` | O canal do primeiro reconhecimento dos incidentes: `web`, `api`, `im`, `sms`, `phone` ou `agent`, com uma contagem por canal. |
