Um aplicativo de calendário (Google Calendar, Outlook, Apple Calendar e outros) lê o endereço de assinatura. O endereço
retorna dados no formato iCalendar (RFC 5545) com os turnos dos últimos 30 dias e dos próximos 90 dias, incluindo alterações pontuais e trocas.
Um feed reúne todos os turnos de uma escala ou apenas os turnos do assinante em todas as escalas.

| Método e caminho | O que faz | Permissão |
|---|---|---|
| `GET /api/v1/schedules/calendar-feeds` | Lista os feeds do usuário atual. | `schedules.read` |
| `POST /api/v1/schedules/calendar-feeds` | Cria um endereço de assinatura. Se a mesma escala (ou o feed pessoal) já tiver um endereço, gera um novo e invalida o anterior imediatamente. | `schedules.calendar_feeds.manage` e, para um feed de escala, `schedules.calendar_feeds.manage` na escala |
| `DELETE /api/v1/schedules/calendar-feeds/{id}` | Desativa um dos feeds do usuário atual e invalida o endereço imediatamente. | `schedules.calendar_feeds.manage` |
| `GET /api/v1/public/calendar/{token}.ics` | Fornece o feed ao aplicativo de calendário sem exigir login. | O token no endereço |

## Crie um endereço de assinatura

**Corpo da solicitação**

| Campo | Tipo | Obrigatório | Observações |
|---|---|---|---|
| `scheduleId` | string | Não | Cria uma assinatura para esta escala. Omita o campo para criar um feed pessoal. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/calendar-feeds \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"scheduleId": "<schedule-id>"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "feed": {
    "id": "3KHtq0dYc1fUe8WnP2xLbR7aZsM",
    "scheduleId": "<schedule-id>",
    "scheduleName": "Payments primary",
    "createdAt": 1790000000000000,
    "lastUsedAt": null
  },
  "path": "/api/v1/public/calendar/<token>.ics",
  "url": "https://molesignal.example.com/api/v1/public/calendar/<token>.ics"
}
```
</ResponseExample>

A API retorna o endereço apenas uma vez, nesta resposta, e armazena apenas o hash SHA-256 do token. A API monta `url` com o
endereço externo da instância e retorna `null` quando não há um endereço externo configurado. Nesse caso, acrescente `path` ao endereço
de acesso ao MoleSignal. Cada feed da lista inclui `id`, `scheduleId`, `scheduleName`, `createdAt` e
`lastUsedAt`, que indica a última leitura por um aplicativo de calendário. A lista não inclui o endereço.

## Como o aplicativo de calendário lê o feed

```http
GET /api/v1/public/calendar/{token}.ics
```

A cada leitura, a API verifica se a conta do assinante continua ativa, ainda faz parte da organização e ainda
tem a permissão `schedules.read`. Para um feed de escala, também verifica se o assinante ainda pode visualizar a escala. Se uma verificação falhar, o token for inválido
ou o feed estiver desativado, a API retorna `404`. Os títulos e as descrições dos turnos usam o idioma da interface
do assinante.

Qualquer pessoa com o endereço pode ver esses turnos. Se o endereço vazar, gere um novo ou desative o feed.
