Aponte um SDK ou Collector do OpenTelemetry para o MoleSignal. Os dois transportes exigem uma credencial bearer com a permissão de escrita do sinal: `logs.write`, `metrics.write` ou `traces.write`.

| Transporte | Endpoint |
|---|---|
| OTLP sobre HTTP | `POST /api/v1/logs`, `POST /api/v1/metrics`, `POST /api/v1/traces` |
| OTLP sobre gRPC | `:4317` |

A porta `5082` é a porta interna confiável do cluster e não é um receptor OTLP.

## OTLP sobre HTTP

Defina o endpoint do exportador como o caminho base `/api`. Os exportadores acrescentam `/v1/logs`, `/v1/metrics` e `/v1/traces` por conta própria.

| Cabeçalho | Observações |
|---|---|
| `Authorization` | `Bearer <token>`. |
| `Content-Type` | `application/x-protobuf` ou `application/json`. A codificação JSON grava inteiros de 64 bits como strings, e o MoleSignal lê strings e números da mesma forma. |
| `stream-name` | Opcional. O stream de destino. O padrão é `default`. |

O corpo não pode ser comprimido: um corpo comprimido responde `400`. Desative a compressão no exportador. O limite do corpo é de 2 MiB. Uma requisição bem-sucedida responde `200` com `{"partialSuccess":null}`. Quando o stream recusa alguns registros de log ou data points porque um valor não se encaixa no tipo do campo, os demais são gravados e `partialSuccess` traz `rejectedLogRecords` ou `rejectedDataPoints` com um `errorMessage` que informa o primeiro motivo. Os exportadores não tentam reenviá-los. A mesma resposta vem pelo gRPC.

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP sobre gRPC

O receptor em `:4317` atende os serviços de logs, métricas, traces e profiles sem TLS. Envie `authorization: Bearer <token>` e o `stream-name` opcional como metadados gRPC. Termine o TLS na frente da porta para o tráfego que sai de uma rede confiável.

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## Campos armazenados

Os atributos de resource e de registro se tornam campos de nível superior com suas chaves originais. Consulte [Campos armazenados](/pt-BR/query#campos-armazenados) para as colunas de logs, spans e métricas.

## Erros

| Status | Causa |
|---|---|
| `400` | Um corpo comprimido, ou um corpo que não é OTLP válido. |
| `401` | Token ausente ou inválido. |
| `403` | O token não tem a permissão de escrita do sinal, ou os dados são enviados para um [stream de plataforma](/pt-BR/streams#fluxos-da-plataforma). |
| `404` | O endpoint do exportador omite `/api`, então a requisição chega a `/v1/logs`. |
| `413` | O corpo excede 2 MiB. |

No gRPC, uma requisição que o HTTP recusa com `403` responde `PERMISSION_DENIED`.
