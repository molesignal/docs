```http
POST /api/v1/_heroku
```

Aceita o corpo em texto de um dreno de logs. O endpoint não usa um token Bearer. Crie um conector do tipo `heroku_drain` com um `pushToken` de pelo menos 16 caracteres e um `target_stream`. O Heroku não permite definir cabeçalhos personalizados, então passe o token na URL como `?token=`. O cabeçalho `X-Connector-Token` também funciona. Se o token estiver incorreto, o endpoint retorna `401`.

Cada linha se torna um evento de log no `target_stream` (por padrão, `heroku`). O endpoint armazena a linha inteira no campo `message` e define o campo `source` como `heroku`. Em caso de sucesso, o endpoint retorna `204`.

<RequestExample>
```bash Heroku CLI
heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
```
</RequestExample>

Consulte [Conectores](/pt-BR/connectors) para configurar o conector.

## Verifique a entrega e a seleção do fluxo

1. Confirme que o conector está habilitado e que o remetente usa o token de push do conector. Um token de API comum não substitui um token de push.
2. Ao definir `configJson` diretamente pela API de conectores, use `target_stream` para indicar o fluxo de destino, não `targetStream`. A chave do token continua sendo `pushToken`, em camelCase.
3. Envie um evento de teste com um marcador exclusivo e anote o horário de recebimento. Em **Logs**, selecione o fluxo de destino e um intervalo que inclua o horário de recebimento. Em seguida, busque o marcador.
4. Se a solicitação for bem-sucedida, mas o fluxo de destino estiver vazio, verifique o fluxo padrão correspondente e o valor salvo no campo de destino. Uma confirmação HTTP não substitui uma consulta ao destino esperado.

Proteja o token como uma credencial. Ao passá-lo como parâmetro de consulta da URL, não inclua a URL completa em logs, chamados nem capturas de tela. Antes de repetir uma solicitação que falhou, verifique se o problema está no token ou no estado do conector, ou se há um erro de formato ou de compactação do corpo da solicitação.
