```http
POST /api/v1/_bulk
```

Ingestão NDJSON compatível com `_bulk` do Elasticsearch para Filebeat, Logstash e o sink `elasticsearch` do Vector. A chamada requer `logs.write`. Um corpo com `Content-Encoding: gzip` é aceito.

| Ação | Tratamento |
|---|---|
| `index`, `create`, `update` | O documento de origem é armazenado como um evento de log. |
| `delete` | Ignorado sem um item de resposta. A telemetria nunca é excluída por este endpoint. |

O `_index` de uma ação seleciona o fluxo de log de destino. Sem ele, o cabeçalho `stream-name` se aplica e, em seguida, `default`.

Um documento com um valor que não se ajusta ao tipo do seu campo no fluxo é recusado isoladamente. Seu item tem `status: 400` e um `error` com o `reason`, `errors` é `true`, e os outros documentos são gravados. O Filebeat e o Logstash não tentam novamente um item como esse.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## Escolha este endpoint

Use este endpoint quando um remetente existente consegue emitir NDJSON em massa do Elasticsearch. Ele é um adaptador de ingestão, não um cluster do Elasticsearch: pesquisa, modelos de índice, IDs de documento e semântica de atualização no local não são fornecidos por esta API. Use [consultas SQL](/pt-BR/query) para ler eventos armazenados.

## Monte um lote válido

- Envie um objeto de ação e um objeto de documento em linhas separadas para cada operação `index` ou `create`. Termine o lote com uma nova linha.
- Para `update`, coloque os campos do evento em `doc`; os campos se tornam um novo evento em vez de modificar um evento armazenado.
- Defina `_index` na ação para escolher um fluxo. Caso contrário, use `stream-name` ou aceite o fluxo `default`.
- Forneça `_timestamp` como um timestamp Unix inteiro em microssegundos ao preservar o horário do evento. Caso contrário, o receptor usa o horário atual.
- Uma ação `delete` é ignorada. Ela não exclui telemetria e não contribui com um item de evento armazenado para a resposta.

## Verifique a ingestão

Para um lote de um único evento, espere `errors: false` e um item de resposta com `status: 201`. Compare a contagem de itens com o número de eventos destinados à ingestão; um sucesso HTTP isolado não prova que o lote foi montado como pretendido.

Abra **Logs**, selecione o fluxo escolhido por `_index` e use um intervalo de tempo que contenha o timestamp do evento. Consulte um campo distintivo do exemplo. Se o evento estiver ausente, verifique a seleção do fluxo e a unidade do timestamp antes de reenviar o lote inteiro. Esta interface não usa IDs de documento do Elasticsearch para deduplicar novas tentativas.

## Solucione problemas de uma requisição rejeitada

| Sintoma | Verificação |
|---|---|
| Erro de autenticação ou permissão | Use um API Token da organização pretendida com `logs.write`. |
| A ação ou o documento não é um objeto JSON | Verifique os limites de linha do NDJSON. Não envie um array JSON nem um objeto multilinha formatado. |
| Ação desconhecida | Use os nomes de ação suportados acima. |
| Erro de descompressão | Defina `Content-Encoding: gzip` apenas quando o corpo estiver realmente comprimido. |
| Sucesso com menos eventos do que o esperado | Verifique se cada ação de gravação tem sua linha de documento e diferencie exclusões ignoradas de eventos armazenados. |
| `errors: true` com itens de status `400` | Um valor não se ajusta ao tipo do seu campo no fluxo, como texto em um campo `int64`; o `reason` do item nomeia o campo. Envie o tipo que o fluxo armazena para ele ou converta-o em um pipeline. |
