```http
POST /api/v1/_bulk
```

Ingestão de NDJSON compatível com `_bulk` do Elasticsearch para Filebeat, Logstash e o sink `elasticsearch` do Vector. A chamada exige `logs.write`. O endpoint aceita um corpo com `Content-Encoding: gzip`.

| Ação | Tratamento |
|---|---|
| `index`, `create`, `update` | O endpoint armazena o documento de origem como um evento de log. |
| `delete` | O endpoint ignora a ação e não inclui um item correspondente na resposta. Este endpoint nunca exclui dados de telemetria. |

O campo `_index` da ação seleciona o fluxo de logs de destino. Se o campo não estiver presente, o endpoint usa o cabeçalho `stream-name` ou, na ausência dele, `default`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## Quando usar este endpoint

Use este endpoint quando um emissor existente puder enviar NDJSON em lote no formato do Elasticsearch. Ele funciona como um adaptador de ingestão, não como um cluster do Elasticsearch: a API não oferece busca, modelos de índice, IDs de documentos nem atualização de documentos existentes. Use [consultas SQL](/pt-BR/query) para ler os eventos armazenados.

## Monte um lote válido

- Envie um objeto de ação e um objeto de documento em linhas separadas para cada operação `index` ou `create`. Termine o lote com uma quebra de linha.
- Para `update`, coloque os campos do evento em `doc`. Esses campos formam um novo evento, em vez de modificar um evento armazenado.
- Defina `_index` na ação para escolher um fluxo. Como alternativa, use `stream-name` ou aceite o fluxo `default`.
- Para preservar o horário do evento, informe `_timestamp` como um timestamp Unix inteiro em microssegundos. Caso contrário, o receptor usa o horário atual.
- O endpoint ignora a ação `delete`. Ela não exclui dados de telemetria nem gera um item de evento armazenado na resposta.

## Verifique a ingestão

Para um lote com um único evento, verifique se a resposta contém `errors: false` e um item com `status: 201`. Compare a quantidade de itens com a quantidade de eventos que deveriam ser ingeridos. Uma resposta HTTP de sucesso, por si só, não comprova que o lote foi montado como esperado.

Abra **Logs**, selecione o fluxo indicado por `_index` e use um intervalo de tempo que inclua o timestamp do evento. Consulte um campo que diferencie o evento de exemplo dos demais. Se o evento não aparecer, confira o fluxo selecionado e a unidade do timestamp antes de reenviar o lote inteiro. Esta interface não usa IDs de documentos do Elasticsearch para eliminar duplicatas em novas tentativas.

## Diagnostique problemas na requisição

| Sintoma | O que verificar |
|---|---|
| Erro de autenticação ou permissão | Use um token de API da organização de destino com a permissão `logs.write`. |
| A ação ou o documento não é um objeto JSON | Confira as quebras de linha do NDJSON. Não envie um array JSON nem um objeto formatado em várias linhas. |
| Ação desconhecida | Use os nomes de ação compatíveis listados acima. |
| Erro de descompactação | Defina `Content-Encoding: gzip` somente se o corpo estiver compactado. |
| Sucesso com menos eventos do que o esperado | Verifique se cada ação de gravação tem a linha do documento correspondente e diferencie as ações de exclusão ignoradas dos eventos armazenados. |
