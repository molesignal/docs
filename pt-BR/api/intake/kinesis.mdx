```http
POST /api/v1/_kinesis_firehose
```

Aceita entregas do AWS Data Firehose por um endpoint HTTP. O endpoint não usa token bearer. Crie um conector do tipo `aws_kinesis_firehose` com um `pushToken` de pelo menos 16 caracteres e um `target_stream`. Informe o token ao Firehose como chave de acesso. O endpoint lê o token de `X-Amz-Firehose-Access-Key` e também aceita `X-Connector-Token` e `?token=`. Se o token estiver incorreto, o endpoint retorna `401`.

Cada registro contém `data` em base64. O endpoint decodifica esse conteúdo, divide-o em linhas e transforma cada linha não vazia em um evento de log no `target_stream` (padrão: `kinesis`). Uma linha com um objeto JSON é convertida em campos, e uma linha de texto simples é convertida no campo `message`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_kinesis_firehose \
  -H 'X-Amz-Firehose-Access-Key: <pushToken>' \
  -H 'content-type: application/json' \
  -d '{"requestId":"req-1","timestamp":1790000000000,"records":[{"data":"eyJsZXZlbCI6ImluZm8ifQo="}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{ "requestId": "req-1", "timestamp": 1790000000123 }
```
</ResponseExample>

A resposta repete o `requestId` e inclui um `timestamp` em milissegundos, conforme exigido pelo Firehose. Consulte [Conectores](/pt-BR/connectors) para configurar o conector.

## Verifique a entrega e a seleção do fluxo

1. Confirme que o conector está ativado e que o remetente usa o token de push do conector. Um token de API comum não substitui um token de push.
2. Ao definir o `configJson` bruto pela API de conectores, use `target_stream` para o fluxo de destino, não `targetStream`. A chave do token continua em camelCase: `pushToken`.
3. Envie um evento de teste com um marcador exclusivo e anote o horário de recebimento. Em **Logs**, selecione o fluxo desejado e um intervalo que inclua esse horário. Em seguida, pesquise pelo marcador.
4. Se a solicitação for bem-sucedida, mas o fluxo desejado estiver vazio, verifique o fluxo padrão correspondente e o valor salvo no campo de destino. Uma confirmação HTTP não substitui uma consulta ao destino pretendido.

Proteja o token como uma credencial. Ao passá-lo como parâmetro de consulta da URL, não inclua a URL completa em logs, chamados ou capturas de tela. Antes de repetir uma solicitação que falhou, diferencie problemas com o token ou com o estado do conector de erros de formato ou compactação da carga útil.
