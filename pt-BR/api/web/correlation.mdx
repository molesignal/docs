```http
GET /api/v1/web/correlation/{fromKind}/{toKind}?ctx=<base64url-json>
```

Calcula os filtros, o intervalo de tempo e o preenchimento automático da consulta que a interface web aplica quando o usuário navega de um sinal para outro, por exemplo, de um trace para os logs associados. A chamada exige `traces.read` ou, no escopo do sistema, `sys.telemetry.read`.

**Parâmetros**

| Parâmetro | Em | Obrigatório | Observações |
|---|---|---|---|
| `fromKind` | caminho | Sim | O sinal de origem da navegação: `trace`, `metric`, `log` ou `host`. |
| `toKind` | caminho | Sim | O sinal de destino da navegação: `trace`, `metric`, `log` ou `host`. |
| `ctx` | consulta | Sim | Um objeto JSON que descreve o sinal de origem, codificado em base64url sem preenchimento. |

O objeto `ctx` aceita estas chaves opcionais:

| Chave | Tipo | Observações |
|---|---|---|
| `trace_id` | string | O trace do sinal de origem. |
| `service` | string | O nome de um serviço. |
| `services` | array | Os nomes dos serviços. |
| `host` | string | O nome de um host. |
| `time_range` | object | `{ "from": "<RFC 3339>", "to": "<RFC 3339>" }`. O padrão é o último minuto. |

## Navegações compatíveis

| Origem → destino | Filtros | Preenchimento automático |
|---|---|---|
| `trace` → `log` | `service` obtido de `services` e `trace_id` | Nenhum. |
| `trace` → `metric` | `service` obtido de `services` | `promql`: `rate(http_requests_total{service="<first service>"}[1m])` |
| `trace` → `host` | `host` obtido de `host` | Nenhum. |
| `metric` → `trace` | `service` obtido de `services` e um `peer_service` que o grafo de serviços indica para o primeiro serviço | Nenhum. |
| `metric` → `log` | `service` obtido de `services` | Nenhum. |
| `log` → `trace` | `trace_id` e `service` | Nenhum. |
| `log` → `metric` | `service` obtido de `services` ou `service` | `promql`: `rate(log_records_total{service="<service>"}[1m])` |
| `host` → `trace` | `host.name` obtido de `host` | Nenhum. |

Um filtro para um único serviço usa o operador `eq`. Um filtro para vários serviços usa `in`. Para qualquer outra combinação, inclusive quando o tipo é desconhecido, a chamada retorna `200` com o intervalo de tempo e sem filtros.

<RequestExample>
```bash cURL
CTX=$(printf '%s' '{"trace_id":"0af7651916cd43dd8448eb211c80319c","services":["checkout","payments"],"time_range":{"from":"2026-10-04T10:00:00Z","to":"2026-10-04T10:05:00Z"}}' | base64 | tr -d '\n=' | tr '+/' '-_')

curl "http://localhost:5080/api/v1/web/correlation/trace/log?ctx=$CTX" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "timeRange": { "from": "2026-10-04T10:00:00Z", "to": "2026-10-04T10:05:00Z" },
  "filters": [
    { "field": "service", "op": "in", "value": ["checkout", "payments"] },
    { "field": "trace_id", "op": "eq", "value": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "prefill": {}
}
```
</ResponseExample>

**Erros**

| Status | Causa |
|---|---|
| `400` | O parâmetro `ctx` está ausente, não está em base64url válido ou não gera um JSON ao ser decodificado. Se `ctx` estiver ausente, a chamada retorna texto simples. Nos demais casos, retorna `invalid_argument` com a mensagem `invalid ctx base64: ...` ou `invalid ctx json: ...`. |
| `403` | O token não tem a permissão `traces.read`. |
