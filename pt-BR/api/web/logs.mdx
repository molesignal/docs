Estas chamadas leem um stream de logs da organização, do mesmo modo que a página **Logs** o lê. Um stream que não existe responde com um resultado vazio. Todas as chamadas exigem `logs.read`, ou `sys.telemetry.read` no escopo do sistema.

Todas as chamadas, exceto o agrupamento em padrões, usam `POST` com um corpo JSON, ou `GET` com os mesmos campos na query string: `filters` e `freeText` como o texto de uma lista JSON, e `where` como o texto de um objeto JSON. Envie como `POST` uma consulta longa demais para um endereço.

## Critérios de correspondência de uma chamada

Uma chamada corresponde aos registros do stream na janela que atendem a todos estes critérios:

| Campo | Tipo | Observações |
|---|---|---|
| `filters` | lista | Filtros que precisam valer todos. No máximo 32, contados com os filtros de `where`. |
| `freeText` | lista | Palavras ou frases a encontrar no campo `message`, cada uma com até 512 bytes. Uma palavra em minúsculas de letras e dígitos, com até 40 bytes, corresponde independentemente de maiúsculas ou minúsculas; os demais textos correspondem como escritos. No máximo 8, contadas com o texto de `where`. |
| `where` | objeto | Uma árvore de condições para alternativas: um filtro, `{"text": "..."}`, `{"and": [...]}` ou `{"or": [...]}`. |
| `expression` | string | Uma consulta de campo como a página **Logs** a escreve. Ela substitui `filters`, `freeText` e `where`: envie uma ou a outra. |

Um filtro é um objeto com `field`, `op`, `value` e `quoted`. Ele nomeia o campo como o stream o nomeia.

| Operador | Campos | Corresponde a |
|---|---|---|
| `=`, `!=` | Qualquer campo escalar | O valor, ou todos os outros valores. Com um valor vazio, se o campo tem algum valor: `=` corresponde aos registros sem valor. |
| `>`, `>=`, `<`, `<=` | Números e timestamps | A comparação. |
| `contains` | Texto | O valor em qualquer lugar do campo. |
| `match` | Qualquer campo | O valor como substring, independentemente de maiúsculas ou minúsculas. Um valor vazio não corresponde a nada. |
| `match_text` | Texto com índice de texto completo | Uma busca de texto completo: palavras, frases e curingas. Um campo sem índice de texto completo responde `400`. |

`eq`, `ne` e `like` são aliases de `=`, `!=` e `contains`. `quoted` é `true` para um valor escrito entre aspas: uma palavra, nunca um número. Um campo JSON não é filtrável aqui; consulte-o com SQL.

`expression` recebe o texto da página **Logs**: comparações, `MATCH(field, 'text')` e `MATCH_TEXT(field, 'words')`, palavras a encontrar, uma frase entre aspas, `AND` e `OR` em qualquer combinação de maiúsculas e minúsculas, com `AND` tendo precedência, e parênteses. O servidor o lê para os `filters`, `freeText` e `where` que a página envia, e os verifica como acima. O texto tem no máximo 8 KiB e aninha parênteses no máximo 32 níveis de profundidade. Uma parte que ele não consegue ler, como um parêntese não fechado ou uma comparação sem nada, responde `400` e nomeia a parte.

```bash
curl -G "http://localhost:5080/api/v1/web/logs" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'stream=app' \
  --data-urlencode "expression=level = 'error' AND (service.name = 'checkout' OR timeout)"
```

## Listar registros

```http
POST /api/v1/web/logs
GET  /api/v1/web/logs
```

Retorna os registros correspondentes, do mais recente para o mais antigo, com paginação por cursor.

| Campo | Tipo | Observações |
|---|---|---|
| `stream` | string | Obrigatório. O stream de logs. |
| `from`, `to` | inteiro | A janela em microssegundos. Os padrões são as últimas 24 horas até agora. `to` deve ser maior que `from`. |
| `filters`, `freeText`, `where`, `expression` | | Critérios de correspondência da chamada. |
| `limit` | inteiro | Tamanho da página. Padrão `20`, limitado ao intervalo de 1 a 5000. |
| `cursor` | string | O `nextCursor` ou `previousCursor` de uma página anterior. Ele mantém a janela e os critérios de correspondência da primeira página. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/web/logs \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"stream":"app","expression":"level = '\''error'\''","limit":2}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    { "_timestamp": 1790000000000000, "level": "error", "message": "db pool exhausted", "trace_id": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "nextCursor": "eyJ2IjoxLC...",
  "previousCursor": null,
  "hasMore": true
}
```
</ResponseExample>

Cada item contém os campos de um registro. `_timestamp` está em microssegundos. Uma requisição com um `cursor` e um stream, janela, `limit` ou correspondência diferentes responde `400`.

## Contar registros ao longo do tempo

```http
POST /api/v1/web/logs/histogram
GET  /api/v1/web/logs/histogram
```

Conta os registros correspondentes em buckets de tempo.

| Campo | Tipo | Observações |
|---|---|---|
| `stream` | string | Obrigatório. |
| `from`, `to` | inteiro | Obrigatório. A janela em microssegundos. |
| `filters`, `freeText`, `where`, `expression` | | Critérios de correspondência da chamada. |
| `bucketTime` | inteiro | O comprimento de um bucket em microssegundos. No mínimo `1000`. |
| `originTime` | inteiro | O início do primeiro bucket. Não depois de `from`. |

Uma requisição abrange no máximo 512 buckets de `originTime` a `to`.

```json
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "buckets": [{ "startTime": 1790000100000000, "total": 120, "errors": 4 }],
  "split": true
}
```

`buckets` lista os buckets que contêm um registro, do mais antigo para o mais novo. `errors` conta os registros no nível `ERROR`, lidos de `level` ou `body_level`. `split` é `false` quando o stream não tem nenhum dos dois campos ou o nível está mascarado para o leitor; `errors` é então `0`. Quando a contagem não está disponível, a chamada responde `200` com `buckets` vazio e `unavailable`: `time_budget`, `busy` ou `scan_limit`, como na [contagem de traces](/pt-BR/api/web/trace#contar-rastreamentos-ao-longo-do-tempo).

## Descrever um campo

```http
POST /api/v1/web/logs/field-stats
GET  /api/v1/web/logs/field-stats
```

Descreve os valores que um campo assume nos registros correspondentes.

| Campo | Tipo | Observações |
|---|---|---|
| `stream` | string | Obrigatório. |
| `from`, `to` | inteiro | A janela em microssegundos. |
| `filters`, `freeText`, `where`, `expression` | | Critérios de correspondência da chamada. |
| `field` | string | Obrigatório. O campo, como o stream o nomeia. |

```json
{
  "kind": "text",
  "total": 1840,
  "present": 1840,
  "distinct": 3,
  "distinctExact": true,
  "top": [{ "value": "info", "count": 1500 }, { "value": "warn", "count": 300 }, { "value": "error", "count": 40 }],
  "topSkipped": false
}
```

`kind` é `number`, `time`, `text` ou `bool`. `total` conta os registros correspondentes e `present` os que têm um valor. `top` lista os valores mais comuns, do mais comum para o menos comum; `topSkipped` é `true` quando quase todo valor é diferente e nenhum é listado. `range` fornece o menor e o maior valor como texto. Um campo numérico adiciona `spread` e `bars`. `trend` conta os valores mais comuns ao longo da janela e fica ausente quando nenhum valor é mais comum que os demais.

## Agrupar em padrões

```http
POST /api/v1/web/logs/patterns
```

Agrupa os registros correspondentes em padrões de mensagem ao longo de toda a janela e compara cada um com um trecho de linha de base. Uma janela com mais de 5.000 registros correspondentes é lida como uma amostra dos registros mais recentes de quatro partes iguais, e o `estimatedCount` de cada padrão dimensiona sua contagem para a janela. A chamada exige `logs.read`.

| Campo | Tipo | Observações |
|---|---|---|
| `stream` | string | Obrigatório. |
| `from`, `to` | inteiro | Obrigatório. A janela em microssegundos. |
| `filters`, `freeText`, `where`, `expression` | | Critérios de correspondência da chamada. |
| `field` | string | O campo que contém a mensagem; quando omitido, o primeiro entre `message`, `body`, `summary`, `log`, `event`, `error`, `msg`, `content` e `text` que o stream tiver. |
| `baseline` | string | `previous` (o padrão, o trecho de mesmo comprimento imediatamente anterior), `week_before` ou `none`. |
| `limit` | inteiro | O máximo de padrões listados: 100 por padrão, no máximo 200. |

```json
{
  "stream": "app_logs",
  "field": "message",
  "levelField": "level",
  "timeRange": { "startTime": 1795510800000000, "endTime": 1795514399999999 },
  "logs": 48210,
  "read": 5000,
  "unread": 0,
  "sampled": true,
  "baseline": { "kind": "previous", "startTime": 1795507199999999, "endTime": 1795510799999999, "logs": 40102, "read": 5000, "sampled": true },
  "newPatterns": 1,
  "surgingPatterns": 0,
  "droppingPatterns": 0,
  "patternCount": 37,
  "patterns": [
    {
      "pattern": "upstream timeout after <number>ms",
      "tokens": [{ "lead": "", "trail": "", "text": "upstream", "wild": null, "unit": "" }],
      "count": 41,
      "share": 0.0082,
      "estimatedCount": 395,
      "firstSeen": 1795513020000000,
      "lastSeen": 1795514390000000,
      "levels": [{ "level": "ERROR", "count": 41 }],
      "baselineCount": 0,
      "change": "new",
      "fragment": "upstream timeout after",
      "example": "upstream timeout after 3000ms"
    }
  ]
}
```

Padrões novos e em crescimento vêm primeiro, e os padrões que a janela não tem mais, por último. `change` é `new` (a linha de base não tinha nenhum), `surging` (pelo menos o dobro e pelo menos cinco a mais), `dropping` (metade ou menos e pelo menos cinco a menos) ou `steady`; `ratio` é a contagem estimada da janela sobre a da linha de base. `tokens` são as palavras do padrão, e `wild` nomeia o que muda em uma posição aberta. Um campo criptografado em repouso responde `400`. Um stream no qual nada foi escrito responde com um relatório vazio.

## Erros

| Status | Causa |
|---|---|
| `400` | Um parâmetro é inválido: `stream` está ausente, `to` não é maior que `from`, um filtro nomeia um campo desconhecido ou usa um operador que seu tipo não aceita, as listas ou a árvore passam de seus limites, `expression` vem junto com `filters`, `freeText` ou `where`, ou tem uma parte que não consegue ler, o cursor não corresponde à consulta, ou um parâmetro do histograma está ausente ou abrange mais de 512 buckets. |
| `403` | O token não tem `logs.read`. |
