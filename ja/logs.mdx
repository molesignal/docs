**ログ**を開き、現在のワークスペース内のログストリームを検索します。

## ストリームと時間範囲を選択する

ログストリームを選択し、対象イベントを含む最小の時間範囲を設定します。範囲を絞ると、スキャンする行数が減り、フィールドをすばやく調べられます。

MoleSignal は、受信したイベントからストリームのスキーマを推定できます。**フィールド**パネルにはストリームのフィールドが一覧表示され、クエリ全体を書き直さずにフィルターを追加できます。

## クエリタブ

クエリはそれぞれ個別のタブで実行します。各タブはストリーム、クエリ、時間範囲を保持します。あるタブでクエリを実行しても、他のタブには影響しません。

- **新しいタブ**を選択して、別のクエリを開きます。同時に開けるタブは最大10個です。
- タブのメニューを開き、**名前を変更**、**複製**、**閉じる**のいずれかを選択します。
- **画面を2分割**を選択すると、2つのタブを横に並べて表示できます。左右にそれぞれタブの一覧があり、タブのメニューから反対側に移動できます。**分割表示を解除**を選択すると、1画面に戻ります。

開いているタブは、ユーザーとワークスペースの組み合わせごとにブラウザーに保存されます。

## クエリを記述する

エディターには **コード**と **ビルダー**の2つのモードがあります。タイトル横の2つのアイコンで切り替えます（`</>` はコード、ブロックのアイコンはビルダー）。アイコンにカーソルを合わせると、モード名が表示されます。

**コード**では、フィールドクエリまたは SQL を入力できます。`SELECT` または `WITH` で始まる文は SQL として実行します。それ以外はフィールドクエリとして実行します。

| フィールドクエリ | 意味 |
|---|---|
| `service = 'checkout'` | フィールドの値がこの値と完全に一致します。 |
| `message contains 'timeout'` | フィールドの値に指定したテキストが含まれます。 |
| `MATCH(message, 'timeout')` | 大文字と小文字を区別せずに部分一致で検索します。 |
| `MATCH_TEXT(message, 'timeout disk')` | 全文検索インデックスのあるフィールドを全文検索します。 |

条件は `AND` と `OR` で結合します。大文字と小文字は区別しません。`AND` は `OR` より優先され、かっこで条件をグループ化できます。例：`level = 'error' AND (service = 'checkout' OR service = 'payments')`。フィールドを指定しないテキストは `message` フィールドで検索します。このテキストも `OR` でつなぐ候補にできます。例：`timeout OR "connection reset"`。引用符で囲むと、`or` などの語を含むフレーズもひとまとまりとして扱います。比較には `=`、`!=`、`>`、`>=`、`<`、`<=` を使います。

**ビルダー**では、同じフィールドクエリをフィルターの行として表示します。候補ごとに1行を使い、行内のフィルターはすべて満たす必要があります。2行目以降の各行の先頭には **または**が付きます。**フィルター**を選択して行にフィルターを追加するか、**または**を選択して行を追加し、フィールド、比較演算子、値を指定します。各行には個別の検索テキストを指定できます。上の例の `OR` のように行内のかっこで囲まれた部分は、記述どおりに保持され、**コード**で編集できます。SQL 文をフィルターとして表示することはできません。

結合、式、CTE、集計には SQL を使います。

```sql
SELECT "_timestamp", level, msg, trace_id
FROM app
WHERE level = 'error'
ORDER BY "_timestamp" DESC
LIMIT 200;
```

```sql
SELECT level, COUNT(*) AS events
FROM app
GROUP BY level
ORDER BY events DESC;
```

**実行**を選択するか、エディターで `⌘ Enter` または `Ctrl+Enter` を押してクエリを実行します。**クエリ構文リファレンス**には、現在のモードで使える例が表示されます。テキスト検索関数については、[クエリ](/ja/query#テキスト検索)を参照してください。

クエリプランナーは、カスタム SQL でも検索対象を現在の組織内に制限します。

## フィールドを調べる

**フィールド**パネルは、**表示中のフィールド**、**インデックス付きフィールド**、**その他のフィールド**の3つに分かれています。`http.method` と `http.route` のように、ドット区切りの名前の先頭部分が同じフィールドは、1つのグループとして展開できます。

- フィールドを展開すると、結果に多く出現する値を確認できます。値は、条件に一致する行を含めるフィルターや除外するフィルターとして追加できます。フィルターはクエリ全体を絞り込みます。`OR` でつないだ条件がある場合は、クエリをかっこで囲んでからフィルターを追加します。
- 結果の列にフィールドを表示するかどうかを切り替えます。
- フィールドの **分析**を選択すると、フィールド分析が開きます。異なる値の数、値がある行とない行、数値フィールドの統計、値の分布、時間の経過に伴う頻出値の変化を確認できます。

## 結果を確認する

結果の上にあるヒストグラムは、読み込んだページだけでなく、指定した時間範囲でクエリに一致するすべてのイベントを集計します。結果は4つのビューで確認できます。

| ビュー | 内容 |
|---|---|
| **ログ** | 一致したイベントを1件ずつ行に表示します。 |
| **統計** | 集計結果をグラフに表示します。集計方法（件数、重複を除いた件数、平均、合計、最小値、最大値、P50、P95、P99）、グループ化、グラフの種類を選択するか、SQL の集計結果をグラフに表示します。**ダッシュボードを作成**を選択すると、新しいダッシュボードのパネルとしてグラフを保存します。 |
| **AI 分析** | クエリに一致したログについて Mole Agent が作成するレポートです。[ログの AI 分析](/ja/logs/inspections)を参照してください。 |
| **パターン** | イベントをパターン別にグループ化し、各パターンの件数と割合を表示します。 |

**ログ**ビューでは、次の操作ができます。

- **列**で、表示する列とその順序を指定します。デフォルトでは、ストリームのフィールドに基づいて時刻を最初に表示し、該当するフィールドがあればレベル、サービス、メッセージの順に表示します。
- 1ページあたりのイベント件数は、100、200、500、1,000、2,000、5,000から選べます。
- イベントをクリックすると、結果の横に詳細パネルが開きます。パネルの左端をドラッグして幅を調整できます。調整した幅は保持されます。ヘッダーには、レベル、時刻、メッセージと、イベントの属性（サービス、ホスト、環境、バージョン、トレース）が表示されます。各属性にはフィールドと同じ操作を実行できます。ビューは **フィールド**、イベントにトレース ID がある場合の **トレース**、**コンテキスト**、 **生のJSON**です。**トレース**には、イベントのスパンを選択した状態でトレースのウォーターフォールを表示します。**コンテキスト**にはイベントの前後5行ずつを表示します。フィールドからフィルターを追加したり、値をコピーしたり、フィールドを列として表示したりできます。
- 識別子がある場合は、関連するトレース、サービス、メトリクス、その他のシグナルに移動できます。
- 結果を CSV、テキスト、JSON のいずれかでダウンロードできます。

## クエリを共有する

ページの URL には、画面に表示中のクエリが反映されます。クエリを実行すると、ストリーム、クエリ文（フィールドクエリは `q`、SQL は `sql`）、結果のビューが URL に反映されます。そのため、アドレスバーの URL をコピーすると、時間範囲ピッカーに表示された直近1時間などの範囲でクエリを共有できます。ページを再読み込みしても、クエリとエディターの状態は保持されます。

**共有**を選択すると、表示中のクエリへのリンクをコピーできます。データの読み取り権限がある組織のメンバーは、サインインしてリンクを開けます。リンクの時間範囲を選択します。**現在選択中の時間範囲**は、画面に表示されている開始時刻と終了時刻に範囲を固定します。もう一方の選択肢では、直近1時間など、リンクを開いた時点を基準とする相対的な時間範囲を保持します。

## 検索ジョブ

対話型リクエストで処理するには規模が大きすぎる検索は、検索ジョブとして実行します。 **ストリーム → 検索ジョブ**を開くと、ジョブの進捗を確認し、結果をダウンロードできます。詳しくは[ストリーム](/ja/streams#検索ジョブ)を参照してください。

## 保存済みビュー

SQL クエリに名前を付けて[保存済みビュー](/ja/saved-views)として保存できます。ビューを開き直したり、別の時間範囲でクエリを実行したり、ビューをレポートに添付したりできます。

<Tip>
  取り込み時には、`service.name`、`deployment.environment`、`trace_id`、 `host.name` などの安定したディメンションを保持してください。これらのフィールドがあれば、関連するシグナルに確実に移動できます。
</Tip>

## 権限

- `streams.read` でストリームとスキーマを確認できます。
- `logs.read` でログの一覧、ヒストグラム、フィールド統計を参照できます。
- `streams.query` で SQL 文を実行し、コンテキストを開けます。
- `agent.use` で AI 分析を実行できます。実行には、有効な AI モデルも必要です。
- `saved_views.create`、`saved_views.edit`、`saved_views.delete` で、保存済みビューをそれぞれ作成、編集、削除できます。
