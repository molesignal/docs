**ログ**を開いて、アクティブなワークスペースでログストリームを検索します。

## ストリームと時間範囲を選択

ログストリームを選択し、イベントを含む最小の時間ウィンドウを設定します。狭いウィンドウはスキャンする行を減らし、フィールドの探索を速くします。

MoleSignal はイベントの到着に合わせてストリームスキーマを推論できます。**フィールド**パネルにはストリームのフィールドが一覧表示され、完全なクエリを書き換えずにフィルターを追加できます。

## クエリタブ

各クエリはそれぞれのタブで実行されます。タブはストリーム、クエリ、時間範囲を保持し、あるタブのクエリは別のタブに影響しません。

- **新しいタブ**を選択して、別のクエリを開きます。一度に最大 10 個のタブを開けます。
- タブのメニューを開き、**名前を変更**、**複製**、または**閉じる**を選択します。
- **画面を2分割**を選択して、2 つのタブを並べて表示します。各半分にはそれぞれのタブが一覧表示され、タブはそのメニューから反対側へ移動できます。**分割表示を解除**で分割を終了します。

開いているタブは、ユーザーとワークスペースごとにブラウザに保持されます。

## クエリを記述

エディターには **コード**と**ビルダー**の 2 つのモードがあり、タイトル横の 2 つのアイコンで切り替えます（コードは `</>`、ビルダーはブロックのアイコン）。それぞれのアイコンはホバー時に名前を表示します。

**コード**ではフィールドクエリまたは SQL を入力します。`SELECT` または `WITH` で始まるステートメントは SQL として実行されます。それ以外はフィールドクエリとして実行されます：

| フィールドクエリ | 意味 |
|---|---|
| `service = 'checkout'` | フィールドが正確にこの値を持ちます。 |
| `message contains 'timeout'` | フィールドにテキストが含まれます。 |
| `MATCH(message, 'timeout')` | 大文字と小文字を区別しない部分文字列検索です。 |
| `MATCH_TEXT(message, 'timeout disk')` | 全文インデックスを持つフィールドに対する全文検索です。 |

条件は `AND` と `OR` で結合し、大文字と小文字は区別しません。`AND` は `OR` より強く結合し、括弧は条件をグループ化します：`level = 'error' AND (service = 'checkout' OR service = 'payments')`。テキストフィールドのないテキストは `message` フィールドで検索され、次の代替のいずれかになります： `timeout OR "connection reset"`。引用符はフレーズをまとまりとして保持し、`or` のような単語を含む場合も同様です。比較には `=`, `!=`, `>`, `>=`, `<`, `<=` を使用します。

**ビルダー**では同じフィールドクエリをフィルターの行として表示し、各代替は 1 行になります。行のフィルターはすべて成立し、**または**は最初の行を除く各行の前に置かれます。**フィルター**を選択して行にフィルターを追加するか、**または**で行を追加し、フィールド、比較、値を選択します。各行には独自の検索テキストがあります。行内の括弧で囲まれた部分（上記の例の `OR` など）は記述されたまま保持され、**コード**で変更します。SQL であるステートメントはフィルターとして表示できません。

結合、式、CTE、または集計には SQL を使用します：

```sql
SELECT "_timestamp", level, msg, trace_id
FROM app
WHERE level = 'error'
ORDER BY "_timestamp" DESC
LIMIT 200;
```

```sql
SELECT level, COUNT(*) AS events
FROM app
GROUP BY level
ORDER BY events DESC;
```

**実行**でクエリを実行するか、エディターで `⌘ Enter` または `Ctrl+Enter` を押します。**クエリ構文リファレンス**には現在のモードの例が一覧表示されます。テキスト検索機能については [クエリ](/ja/query#テキスト検索) を参照してください。

クエリプランナーは、カスタム SQL であっても現在の組織境界を適用します。

## フィールドを探索

**フィールド**パネルには、**表示中のフィールド**、**インデックス付きフィールド**、**その他のフィールド**の 3 つの部分があります。`http.method` や `http.route` のように、ドット区切りの名前の最初の部分を共有するフィールドは、1 つのグループとして開きます。

- フィールドを開くと、結果内の最も一般的な値が表示されます。値を包含フィルターまたは除外フィルターとして追加します。フィルターはクエリ全体を絞り込みます：代替のクエリはその前に括弧で囲まれます。
- フィールドを結果の列として表示または非表示にします。
- フィールドの**分析**を選択してフィールド分析を開きます：個別の値の数、値がある行とない行、数値フィールドの統計、値の分布、および時間経過に伴う最も一般的な値が表示されます。

## 結果を確認

結果のヒストグラムは、読み込まれたページだけでなく、時間範囲内でクエリに一致するすべてのイベントをカウントします。結果は 4 つのビューで確認できます：

| ビュー | 内容 |
|---|---|
| **ログ** | 一致するイベントを 1 行ずつ表示します。 |
| **統計** | 集計のチャートです。メジャー（カウント、個別カウント、平均、合計、最小、最大、P50、P95、P99）、グループ化、チャートの種類を選択するか、SQL 集計の結果を描画します。**ダッシュボードを作成**で、チャートを新しいダッシュボードのパネルとして保存します。 |
| **AI 分析** | Mole Agent がクエリに一致するログについて作成するレポートです。[ログ検査](/ja/logs/inspections) を参照してください。 |
| **パターン** | イベントをパターンごとにグループ化し、各パターンのカウントと割合を表示します。 |

**パターン**ビューは、サーバー上で時間範囲全体のパターンをカウントします。5,000 を超えるイベントを含む範囲は、範囲全体に分散したサンプルとして読み取られ、各カウントは範囲に合わせてスケーリングされ、 `≈` を付けて表示されます。パターンの下の行には、範囲内のイベント数と、読み取られたイベント数が表示されます。**変更**は、各パターンを横で選択したベースラインと比較します：直前の同じ長さの期間（デフォルト）、1 週間前の同じ長さの期間、またはなしです。**新規**は、ベースラインになかったパターン、`×N` は少なくとも 5 イベント増えて少なくとも 2 倍になったパターン、**減少**は半分になったパターンを示します。パターンを開くと、そのパターンに該当する読み込み済みイベント、または読み込み済みイベントがない場合はそのメッセージの 1 つが表示されます。SQL で記述されたステートメントは、返されたイベントからグループ化されます。

**ログ**ビューでは：

- **列**では列を選択して順序を設定します。デフォルトの列はストリームのフィールドから取得されます：時間、次にストリームに存在する場合はレベル、サービス、メッセージのフィールドです。
- ページサイズは 100、200、500、1,000、2,000、または 5,000 イベントです。
- イベントをクリックすると、結果の横のドロワーで開きます。ドロワーの左端をドラッグしてサイズを変更でき、幅は保持されます。ヘッダーにはレベル、時間、メッセージ、およびイベントを識別する属性（サービス、ホスト、環境、バージョン、トレース）が表示され、それぞれフィールドと同じアクションを実行できます。ビューは **フィールド**、イベントにトレース ID がある場合は **トレース**、**コンテキスト**、 **生のJSON**です。**トレース**は、イベントのスパンが選択された状態でトレースのウォーターフォールを表示します。**コンテキスト** は、両側に 5 行ずつ周囲の行を表示します。フィールドから、フィルターの追加、値のコピー、またはフィールドの列としての表示を行えます。
- 識別子が存在する場合は、トレース、サービス、メトリクス、またはその他の相関シグナルにピボットします。
- 結果を CSV、テキスト、または JSON としてダウンロードします。

## クエリを共有

ページのアドレスは、画面に表示されているクエリです。クエリを実行すると、ページはそのストリーム、ステートメント（フィールドクエリの場合は `q`、SQL の場合は `sql`）、および結果のビューをアドレスに書き込むため、アドレスバーをコピーするとクエリを共有できます。共有されるのは、ピッカーに表示される時間範囲（直近 1 時間など）です。ページを再読み込みしても、クエリとエディターはそのまま保持されます。

**共有**を選択して、画面に表示されているクエリへのリンクをコピーします。リンクは、データを読み取る権限を持つ組織のサインイン済みメンバーに対して開きます。リンクの時間範囲を選択します：**現在選択中の時間範囲** は範囲を画面に表示されている時点に固定し、もう一方の選択肢は相対的な範囲（直近 1 時間など）を保持し、リンクが開かれた時点からカウントされます。

## 検索ジョブ

インタラクティブなリクエストには大きすぎる検索は、検索ジョブとして実行されます。 **ストリーム → 検索ジョブ**を開いてジョブを追跡し、結果をダウンロードします。 [ストリーム](/ja/streams#検索ジョブ) を参照してください。

## 保存済みビュー

SQL クエリに名前を付けて [保存済みビュー](/ja/saved-views) として保存します。ビューを再度開き、別の時間ウィンドウでクエリを実行するか、ビューをレポートに添付します。

<Tip>
  取り込み時に `service.name`、`deployment.environment`、`trace_id`、 `host.name` などの安定したディメンションを保持します。これらのフィールドにより、シグナル間のピボットが信頼できるものになります。
</Tip>

## 権限

- `streams.read` はストリームとスキーマを検出します。
- `logs.read` はログを読み取ります: 一覧、ヒストグラム、フィールド統計です。
- `streams.query` は SQL ステートメントを実行し、コンテキストを開きます。
- `agent.use` は AI インスペクションを実行します。これには有効な AI モデルも必要です。
- `saved_views.create`、`saved_views.edit`、`saved_views.delete` は保存済みビューを制御します。
