**APM → 設定**では、組織の APM 設定を管理します。各カードの設定は、カードごとに **保存**で保存します。**変更を元に戻す**を選ぶと、前回の保存以降の入力を破棄します。保存には `apm.settings.manage` が必要です。この権限はオーナー、管理者、編集者が持ちます。権限がない場合は、設定の閲覧のみ可能です。

保存した設定は、保存したノードにはすぐに、ほかのノードには 30 秒以内に反映されます。命名ルールと環境マッピングは、保存後に読み込むスパンに適用します。APM がすでに保持しているデータの名前は変わりません。ヘルス判定のしきい値、デフォルトの Apdex しきい値、エイリアス、カタログの必須項目は、保持済みのデータも含め、読み込みのたびに適用します。

## 収集品質

最初のカードでは、過去 1 日分のデータを確認し、修正が必要な問題と、設定で改善できる点を一覧表示します。

| 検出項目 | 意味 |
|---|---|
| カーディナリティの上限超過 | エンドポイントなど、ある種類の名前の数が 1 時間あたりの上限を超え、超過分を **その他** として集計しました。プラットフォーム設定を管理する権限がある場合、**上限を引き上げる**から上限のカードを開けます。 |
| APM のスパン欠損 | 集計処理の結果に、過去 1 日のうちデータが欠けている時間帯があります。 |
| APM の処理遅延 | 集計が完了した最新の 1 分間が、数分以上前です。 |
| 属性を報告していないサービス | `deployment.environment.name`、`service.version`、`service.instance.id` のいずれかがないサービスです。**計装を設定**を選ぶと OpenTelemetry ガイドが開きます。 |
| 大文字と小文字だけが異なる環境 | `Production` と `production` などです。**すべて同じ名前として扱う**を選ぶと、環境のカードにマッピングを追加します。 |
| 自動生成された接尾辞を持つ名前 | `checkout-7d9f8b6c5-x2x7k` など、Pod のような名前が付いたサービスです。**命名ルールを追加**を選ぶと、その名前を `checkout` として扱うルールを追加します。 |

カードに追加した提案は、**保存**するまで適用しません。

## ヘルスとしきい値

| 設定 | デフォルト | 範囲 |
|---|---|---|
| エラー率の **警告しきい値** と **重大しきい値** | 2% と 10% | 警告しきい値は 0 より大きく、重大しきい値より小さい値です。重大しきい値は 100% 以下です。 |
| P95 の **警告しきい値** と **重大しきい値** | 500 ms と 2,000 ms | 警告しきい値は 0 より大きく、重大しきい値より小さい値です。重大しきい値は 10 分以下です。 |
| **デフォルトの Apdex** の T | 500 ms | 0 より大きく、1 分以下です。カタログでサービス固有の T を設定している場合は、その値を使います。概要では、このデフォルトの T を使って全サービスをまとめて評価します。 |
| **ロングタスク** の P99 しきい値 | 1,000 ms | 1 ms から 10 分までです。エンドポイント一覧では、P99 がこの値以上のエンドポイントをロングタスクとしてカウントします。 |

これらのしきい値で各サービスのヘルスを判定し、カタログ、サービスページ、マップ、概要のヘルス推移に反映します。

## カタログの必須項目

**チーム**、**オーナー**、**リポジトリ**ごとに、カタログで必須にするティアを設定します。 **必須ではない**を選ぶか、選んだティアとそれより上位のすべてのティアで必須にします。対象のティアのサービスで必須項目が未入力の場合は、カタログに **要対応** と不足項目を表示します。ティアが設定されていないサービスには必須項目はありません。

## サービスの命名

命名ルールは、スパンの読み込み時にサービス名を書き換えます。各ルールは正規表現と置換文字列で構成し、置換文字列では `$1` や `${name}` で正規表現のグループを参照できます。ルールを上から順に評価し、名前に最初に一致したルールで書き換えます。書き換え後の名前が空になる場合は、元の名前を保持します。**サービス名を試す**では、適用後の名前を確認できます。

組織ごとに最大 20 件のルールを保持できます。トレースではスパンに含まれる名前を保持するため、トレースを検索する際はルール適用前の名前を使います。

## 環境マッピング

各マッピングは、スパンの読み込み時に大文字と小文字を区別せず、環境名を別の名前として扱います。たとえば、 `Production` と `prod` をどちらも `production` として扱えます。同じ環境に設定できるマッピングは 1 件までで、組織ごとに最大 50 件のマッピングを保持できます。

## サービスエイリアス

エイリアスは、サービスの以前の名前を現在の名前に関連付けます。両方に名前空間を指定でき、空欄の場合は `default` を使います。すべての APM ページで、エイリアス名で報告したデータをサービス自体が報告したデータと統合します。保持済みのデータも対象です。サービスマップとデプロイレポートにもエイリアスを適用します。エイリアスを削除すると、2 つの名前のデータを再び個別に表示します。

サービス自体の名前をそのサービスのエイリアスにはできません。同じ名前をエイリアスにできるのは 1 回だけで、エイリアスから別のエイリアスを参照することはできません。組織ごとに最大 100 件のエイリアスを保持できます。以前のリンクからエイリアス名のページを直接開いた場合は、引き続きエイリアス名で報告したデータだけを表示します。

## カーディナリティの上限

`sys.settings.limits.manage` を持つ場合に表示します。上限はプラットフォーム全体に適用します。APM は 1 時間ごとに、種類ごとの上限まで個別に保持し、超過分は **その他** として集計します。

| 上限 | デフォルト |
|---|---|
| 組織あたりのサービス数 | 200 |
| サービスあたりのエンドポイント数 | 32 |
| サービスあたりの依存関係数 | 16 |
| 依存関係あたりのオペレーション数 | 32 |
| サービスあたりのエラーグループ数 | 16 |
| サービスあたりのバージョン数 | 16 |
| サービスあたりのインスタンス数 | 256 |

各上限には 1 から 100,000 までの整数を指定できます。各ノードは 30 秒ごとに上限を読み直します。

## トレースサンプリング

`sys.telemetry.read` を持つ場合に表示します。変更には `sys.telemetry.manage` が必要です。このポリシーで、完了したトレースのうち、どれをプラットフォームに保持するかを決めます。

- **通常のトレースの保持率**は、ルール、エラー、処理の遅さのいずれによっても保持されないトレースのうち、保持する割合です。デフォルトは 10% です。
- 各ルールは、指定した **サービス**、**ルート**、**オペレーション**を持つスパンを含み、そのスパンの所要時間が **最小所要時間（ms）** 以上で、**エラーのみ** を有効にした場合はそのスパンが失敗したトレースに一致します。一致したトレースは、ルールに従って保持するか、破棄するか、指定の割合で保持します。ルールを上から順に評価してから、通常の保持率を適用します。

保存すると、新しいバージョンのポリシーを全ノードに配信します。APM はサンプリング前にすべてのトレースを集計するため、ポリシーが変えるのは開けるトレースだけで、APM の集計値には影響しません。
