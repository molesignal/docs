**APM → 設定** は、組織が APM に設定する内容を保持します。各カードはそれぞれ **保存** で保存され、**変更を元に戻す** はそれ以降に入力された内容を破棄します。保存には `apm.settings.manage` が必要です。オーナー、管理者、およびエディターがそれを保持します。これがないと、ページは設定を読み取るだけで何も変更しません。

保存された設定は、保存したノードではすぐに適用され、他のノードでは 30 秒以内に適用されます。命名ルールと環境マッピングは、それ以降に読み取られるスパンに適用されます。APM がすでに保持しているものはその名前を保持します。ヘルスライン、デフォルトの Apdex しきい値、エイリアス、カタログ要件は、すでに保持されているデータを含め、すべての読み取りに適用されます。

## 収集品質

最初のカードは過去 1 日を読み取り、修正が必要なものと、設定によって改善されるものを一覧表示します。

| 検出項目 | 意味 |
|---|---|
| カーディナリティ上限を超過 | エンドポイントなど、ある種類の名前が 1 時間あたりの上限を超え、残りは **その他** としてカウントされました。**上限を引き上げる** は、プラットフォーム設定を管理するユーザー向けの上限カードに移動します。 |
| APM がスパンを取りこぼした | プロジェクションにより、その日のデータに欠落が生じました。 |
| APM が遅延している | 最後に完了した 1 分が数分以上前です。 |
| 属性を報告しないサービス | `deployment.environment.name`、`service.version`、または `service.instance.id` がないサービス。**計装を設定** は OpenTelemetry ガイドを開きます。 |
| 大文字と小文字だけが異なる環境 | `Production` と `production` など。**すべてを次のように読み取る** は環境カードにマッピングを追加します。 |
| 生成されたサフィックスを持つ名前 | ポッドのような名前のサービス（例: `checkout-7d9f8b6c5-x2x7k`）。**命名ルールを追加** は、それを `checkout` として読み取るルールを追加します。 |
| トレース ID のないログ | 過去 1 時間のログ行にトレース ID が含まれないサービス。そのため、どのログからもそのトレースにたどり着けません。**計装を設定** は OpenTelemetry ログガイドを開きます。 |
| トレースと部分的にしか結び付いていないログ | 過去 1 時間のサービスの行の 90% 未満にトレース ID が含まれている、または、それらのトレース ID のサンプルの 80% 未満しか保持されているトレースの中に見つかりません。 |
| 実行場所を報告しないサービス | サービスのどのインスタンスも `host.name`、`k8s.pod.name`、`k8s.node.name`、または `container.id` を報告しません。**計装を設定** は OpenTelemetry トレースガイドを開きます。 |
| APM が認識しない名前 | ログまたはメトリクス内のサービス名で、命名ルールとエイリアスを適用してもどの APM サービスにも一致しないもの。**命名ルール** は命名ルールカードに移動します。 |
| 変更が報告されていない | 過去 1 週間に、デプロイ、設定変更、またはフィーチャーフラグが報告されていないサービス。**変更を報告** はデリバリーパイプラインガイドを開きます。 |

最後の 5 つの検出項目は、[相関レポート](/ja/api/apm#サービスが他のデータとどれだけ関連しているかを確認する) に由来します。これは過去 1 時間のログとメトリクス、および過去 1 週間の変更を調べます。

カードに追加された提案は、**保存** するまでそこに残ります。

## ヘルスとしきい値

| 設定 | デフォルト | 範囲 |
|---|---|---|
| エラー率、**警告しきい値** と **重大しきい値** | 2% と 10% | 警告ラインは 0 より大きく、重大ラインより小さいです。重大ラインは最大 100% です。 |
| P95、**警告しきい値** と **重大しきい値** | 500 ms と 2,000 ms | 警告ラインは 0 より大きく、重大ラインより小さいです。重大ラインは最大 10 分です。 |
| **デフォルトの Apdex** T | 500 ms | 0 より大きく、最大 1 分です。カタログエントリで独自の T を設定しているサービスは、その T を保持します。概要は、この T で全サービスをまとめて読み取ります。 |
| **ロングタスク**、P99 のしきい値 | 1,000 ms | 1 ms から 10 分です。エンドポイント一覧は、この P99 以上になるとエンドポイントをロングタスクとしてカウントします。 |

これらのラインは、カタログ内、サービスページ、マップ、および概要のヘルス傾向における各サービスのヘルスを決定します。

## カタログ要件

**チーム**、**オーナー**、**リポジトリ** のそれぞれについて、カタログがそれを要求する階層: **必須ではない**、または階層とその上のすべての階層です。そのような階層のサービスでそのフィールドがない場合、カタログ内で不足しているフィールドとともに **必要** と表示されます。階層のないサービスには何も要求されません。

## サービスの命名

命名ルールは、スパンの読み取り時にサービス名を書き換えます。各ルールは正規表現と置換で構成され、置換では式のグループを `$1` や `${name}` として参照できます。ルールは順に試行され、名前に一致する最初の式がそれを書き換えます。空の名前への書き換えは名前を保持します。 **サービス名を試す** は、名前がどのように読み取られるかを表示します。

組織は最大 20 個のルールを保持できます。トレースはスパンが持つ名前を保持するため、トレース検索ではルール適用前の名前が使用されます。

## 環境マッピング

各マッピングは、スパンの読み取り時に、大文字と小文字を区別せずに、ある名前の環境を別の名前として読み取ります。たとえば、 `Production` と `prod` はどちらも `production` として読み取られます。環境は最大 1 回だけマッピングされ、組織は最大 50 個のマッピングを保持できます。

## ビジネスコンテキスト

組織がテレメトリを読み取る際のビジネスキー（テナントやプランなど）と、スパン、ログ、RUM イベントでそれぞれを保持するフィールド、および最も重要な値です。サービスページはそれらでリクエストを分割し、インシデントはそれらが該当する値を一覧表示します。[ビジネスコンテキスト](/ja/business-context) を参照してください。

## サービスのエイリアス

エイリアスは、サービスを古い名前で指定します。各側には名前空間があり、空白の場合は `default` になります。エイリアスが報告した内容は、すべての APM ページでそのサービスのものとして読み取られ、サービス自身が報告した内容とマージされます。すでに保持されているデータも含まれます。サービスマップとデプロイレポートもエイリアスに従います。エイリアスを削除すると、再び 2 つは別々に読み取られます。

サービスはそれ自身のエイリアスにはなれず、名前は 1 回だけエイリアスになり、エイリアスが別のエイリアスにつながることはありません。組織は最大 100 個のエイリアスを保持できます。古いリンクからエイリアス自体で開かれたページは、引き続きエイリアス自身のデータを読み取ります。

## カーディナリティ上限

`sys.settings.limits.manage` を持つユーザーに表示されます。上限はプラットフォーム全体に適用されます。1 時間ごとに、APM は各種類につき最大でこの数だけを分けて保持し、残りは **その他** としてカウントします。

| 上限 | デフォルト |
|---|---|
| 組織あたりのサービス数 | 200 |
| サービスあたりのエンドポイント数 | 32 |
| サービスあたりの依存関係数 | 16 |
| 依存関係あたりのオペレーション数 | 32 |
| サービスあたりのエラーグループ数 | 16 |
| サービスあたりのバージョン数 | 16 |
| サービスあたりのインスタンス数 | 256 |

各上限は 1 から 100,000 までの整数です。各ノードは 30 秒ごとに上限を再読み取りします。

## トレースサンプリング

`sys.telemetry.read` を持つユーザーに表示されます。変更には `sys.telemetry.manage` が必要です。ポリシーは、トレースが終了した後にプラットフォームがどのトレースを保持するかを決定します:

- **通常のトレースの保持率** は、ルール、エラー、または遅延のいずれも保持しないトレースのうち保持される割合です。デフォルトでは 10% です。
- 各ルールは、スパンがそのルールで指定された **サービス**、**ルート**、**オペレーション** を持ち、長さが **最小所要時間（ms）** 以上で、**エラーのみ** が設定されている場合は失敗したトレースに一致します。その後、ルールはそれらを保持、破棄、または一部を保持します。ルールは通常の割合より前に順に試行されます。

保存すると、ポリシーの新しいバージョンがすべてのノードに公開されます。APM はサンプリング前にすべてのトレースをカウントするため、ポリシーが APM の数値を変更することはなく、開けるトレースが変わるだけです。
