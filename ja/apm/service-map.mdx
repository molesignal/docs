**サービスマップ**は、サービス間の呼び出しと、リクエストレート、エラー率、レイテンシ（**RED** メトリクス）で見た呼び出しの健全性を表示します。MoleSignal は既存のトレースからマップを自動で作成するため、通常のトレース計測に追加のインストルメンテーションは不要です。

<Info>
  サービスマップと [APM](/ja/apm) は同じトレースを入力に使いますが、データのまとめ方が異なります。サービスマップはサービスをまたぐ親スパンと子スパンを対応付けて、トポロジーを構築します。APM は上限を設けてサービス、トランザクション、依存関係、エラー、バージョンごとの集計データを作成します。
</Info>

## マップの作成方法

トレーススパンを受信すると、MoleSignal は各スパンをその親スパンと対応付けます。**異なるサービス**のスパンは呼び出しエッジ（*親サービス → 子サービス*）を形成し、そのエッジには子（呼び出し先）スパンの所要時間とエラーステータスを使用します。同じサービス内の親子スパンは内部処理であり、エッジとして表示しません。エッジは呼び出し元の環境（`deployment.environment.name` または `deployment.environment`）に属します。呼び出し元に環境の指定がない場合は、呼び出し先の環境に属します。 [リアルタイムパイプライン](/ja/pipelines#トレース)が破棄したスパンは対応付けの対象外です。

エッジをサービスのペアごとに **1 分単位のバケット**に集約し、バックグラウンドでストレージに書き込みます。そのため、直近のトラフィックはおよそ 30 秒以内にマップに反映されます。

### メモリ内処理とストレージモードの比較

デフォルト（`intake` モード）では、スパンを受け付けたノードの**メモリ内**で対応付けるため、低レイテンシです。複数ノード構成では、1 回の呼び出しのスパンが別々のノードに届くと、メモリ内で対応付けられません。そのため、マップで一部のエッジが過少に集計される場合があります。実際にないエッジは表示しません。

全ノードを含む完全なマップを取得するには、**設定 → 一般 → サービスマップのデータソース**を **ストレージ**モードに切り替えます。1 台のノードが**保存済みトレース**からグラフを定期的に再構築し、受信ノードに関係なくすべてのスパンを処理しますが、反映には 1～2 分かかります。この設定はデータベースに保存され、稼働中に反映されます。再起動は不要です。

## 必要なトレースデータ

マップの作成には、トレースに次の情報が必要です。

- すべてのスパンに **`service.name`** リソース属性（OTLP エクスポーターがこの属性を設定します）
- サービスをまたぐ**スパンの親子関係**。つまり、あるサービスのクライアントスパンに対して、別のサービスで実行されるサーバースパンが子になっていること

標準の OpenTelemetry インストルメンテーションでは、どちらの情報も生成されます。任意の [トレース受信エンドポイント](/ja/intake)をトレーサーに設定すると、MoleSignal がマップを自動で作成します。

## トポロジー

トポロジーエンドポイントは、指定した時間範囲のデータをノード（サービス）とエッジ（呼び出し）に集約します。

```http
GET /api/v1/web/topology?from=2026-06-14T00:00:00Z&to=2026-06-14T01:00:00Z
Authorization: Bearer <jwt>
```

```json
{
  "nodes": [
    { "id": "checkout", "name": "checkout", "rps": 42.0, "errorRate": 0.01, "p95Ms": 120.0, "spanCount": 151200 }
  ],
  "edges": [
    { "source": "checkout", "target": "payments", "rps": 41.0, "errRate": 0.02, "p95Ms": 95.0 }
  ]
}
```

| フィールド | 意味 |
|---|---|
| `rps` | 時間範囲内の 1 秒あたりのリクエスト数です。 |
| `errorRate` / `errRate` | ステータスが `ERROR` のリクエストの割合（0～1）です。 |
| `p95Ms` | 時間範囲内で 1 分ごとに算出した 95 パーセンタイルレイテンシの最大値（ミリ秒）です。 |
| `spanCount` | 時間範囲内でそのノードに対して観測したスパンの総数です。 |

## サービスグラフの生データ

エッジの 1 分ごとのスナップショットを取得するには、サービスグラフに直接クエリを実行します。特定の依存関係の推移をグラフ化するときに便利です。

```http
GET /api/v1/traces/service_graph?from=1717200000000000&to=1717286400000000&service=checkout
Authorization: Bearer <jwt>
```

`from` と `to` は Unix エポックからの経過時間をマイクロ秒で指定します。省略可能な `service` フィルターは、指定したサービスが呼び出し元または呼び出し先であるエッジを返します。各行には、1 サービスペアの 1 分間の `environment`、 `request_count`、`error_count`、および `p50_us` / `p95_us` / `p99_us` が含まれます。

## UI での表示

- **APM → サービスマップ**は、環境内のサービスとサービス間の呼び出しを表示します。各サービスの呼び出し先と、メッセージの発行先および取得元のトピックも表示します。[APM のサービスマップ](#apm-のサービスマップ)を参照してください。
- サービスの APM ページの**依存関係**は、APM のサービスマップと同様に、そのサービスと呼び出し元、呼び出し先を表示し、そのサービスへの呼び出しを一覧表示します。呼び出しを選択すると、同じドロワー内で詳細が開きます。
- トレースページの**サービスグラフ**タブは、クエリに一致するトレースのマップを表示します。

どのサービスマップでも表示方法は同じです。ノードは健全性を色で示すリングで囲み、その中にノードの種類、名前、1 秒あたりのリクエスト数、エラー率、P95 を表示します。呼び出しはトラフィック量に応じた太さの矢印で示し、失敗率が 5% 以上なら赤、1% 以上 5% 未満ならオレンジで表示します。

任意のサービスやエッジから、 [シグナル間の相関分析](/ja/correlation)を通じて、対応するトレースやログに直接移動できます。

## APM のサービスマップ

**APM → サービスマップ**は、スコープ欄で選択した環境とネームスペースについて、サービスグラフと APM の集計データを組み合わせて表示します。

| ノード | データソース |
|---|---|
| サービス | サービスグラフに、APM サマリーの RED メトリクスと健全性を組み合わせます。 |
| データベース、キャッシュ、外部 HTTP または RPC | APM の依存関係に含まれる外向きの呼び出しを、呼び出し先ごとに表示します。 |
| データを報告しないサービス | サービス自体がスパンを送信しない場合は、`peer.service` でそのサービスを指定する呼び出しを使用します。 |
| トピック | メッセージングの宛先に発行する呼び出しと、そこからメッセージを取得するメッセージングエンドポイントを使用します。 |

呼び出しはトラフィック量に応じた太さと、失敗率に応じた色で表示します。同じ長さの直前の期間と比較して、今回だけ発生した呼び出しには**新規**、今回は発生しなかった呼び出しには**消失**と表示し、消失した呼び出しは対応するノードとともに破線で示します。ノードを選択すると、呼び出し元と呼び出し先、およびそのノードからの**最も遅い経路**が強調表示されます。この経路は、各ノードで P95 が最も高い呼び出しをたどります。マップ上のカードにはノードの呼び出しが一覧表示されます。呼び出しを選択するとドロワーが開き、リクエスト数、エラー数、レイテンシの推移と、次の詳細が表示されます。

- サービスへの呼び出し：すべての呼び出し元がアクセスしたサービスのエンドポイントと、そのエラーグループ
- データベース、キャッシュ、外部エンドポイントへの呼び出し：呼び出しで実行された操作
- トピック経由の呼び出し：メッセージの発行完了からコンシューム開始までの待ち時間。トレースストア内の最新のコンシュームスパン（最大 200 件）を、それぞれのリンクが参照するスパン、参照先がなければ親スパンと対応付けて算出します。

ノードが 60 個を超えるマップでは、初期表示で各ネームスペースを 1 つのノードに折りたたみます。そのノードを選択するとネームスペースが展開します。**ネームスペースを折りたたむ**で、すべてを一括で折りたたんだり展開したりできます。トラフィック量の多い順に最大 400 個のノードを表示します。
