サービスページの **デプロイ** セクションでは、2つのデータソースを並べて表示します。パイプラインが報告したデプロイと、サービスのスパンが `service.version` に記録したバージョンです。パイプラインから報告されていないバージョンも、スパンの情報だけで表示します。

## デプロイのタイムライン

タイムラインには、指定した期間内にサービスで発生したイベントを新しい順に表示します。

| イベント | 表示条件 |
|---|---|
| **デプロイ済み** | パイプラインがデプロイの成功を報告しました。 |
| **失敗** | パイプラインがデプロイの失敗を報告しました。デプロイに失敗しても、稼働中のバージョンは変わりません。 |
| **ロールバック済み** | パイプラインがロールバックを報告したか、別のバージョンより前に稼働していたバージョンへのデプロイを報告しました。行にはロールバック前のバージョンを表示します。 |
| **以前のバージョンに復帰** | スパンで、パイプラインから報告されていない古いバージョンへの復帰を検出しました。最後に観測したバージョンの初回検出は、新しいバージョンの初回検出よりも前で、その新しいバージョンの観測は5分以上前ではなく、5分を超えて前に途絶えています。 |
| **初回検出** | スパンに、パイプラインから報告されていないバージョンが記録されました。 |
| **設定** | パイプラインまたはツールが設定変更を報告しました。行には変更の説明を表示します。 |
| **機能フラグ** | パイプラインまたはツールが機能フラグの変更を報告しました。行には変更の説明を表示します。 |

設定や機能フラグを変更しても、稼働中のバージョンは変わりません。変更自体に指標はありません。インサイトの前後に発生した変更の一覧に表示します。詳しくは、 [検出事項の前後に発生した変更](/ja/apm/insights#検出結果の発生前後の変更)を参照してください。

報告されたデプロイには、コミット、プルリクエスト、CI の実行、実行者を表示します。リポジトリのアドレスが http または https の場合、コミットを選択すると Web ページが開きます。コミットの URL は GitHub、GitLab、Bitbucket それぞれの形式に従います。

各バージョンの最新行には、指定した期間内のリクエスト数、エラー率、p95 を表示します。あわせて、初回検出順で1つ前のバージョンと比較した判定を表示します。

| 判定 | 条件 |
|---|---|
| **再発** | エラー率が1パーセントポイント以上上昇し、かつ1.5倍以上になったか、p95 が20%以上かつ50 ms 以上増加しました。判定の後に悪化した指標を表示します。 |
| **改善** | いずれかの指標が悪化時と同等のしきい値に達するまで低下し、どちらの指標も悪化しませんでした。 |
| **変化なし** | どちらの指標の変化も、しきい値に達しませんでした。 |
| **リクエスト数不足** | いずれかのバージョンのリクエスト数が、バージョンの比較に必要な件数（デフォルトは1,000件）に達しませんでした。 |

判定を選択すると、**2つのバージョンを比較**で対象のバージョンが開きます。この画面には、応答が遅くなったエンドポイントと増加したエラーを一覧表示します。再発または改善と判定したバージョンには、概要の最近のデプロイにもマークを付けます。

## カナリアデプロイ

カナリアと置き換え対象のバージョンのように、2つのバージョンが同時に稼働している場合は、タイムラインの上に両者を並べたカードを表示します。サービスの最新スパンを基準に、直近5分以内に両方のバージョンを観測した場合、同時に稼働しているとみなします。カードには、最新の2つのバージョンについて、新しいバージョンの初回検出時点からのデータを比較して表示します。

- 各バージョンが処理したリクエストの割合
- 各バージョンのリクエスト数、エラー率、p50、p95、p99
- 古いバージョンと比較した新しいバージョンの判定

## CI からデプロイを報告する

パイプラインから `POST /api/v1/apm/deployments` を使ってデプロイを報告します。リクエストには、 `apm.deploy` 権限を持つ API トークンが必要です。オーナー、管理者、編集者にはこの権限があります。取り込みトークンに適用する **データ取り込み** ポリシーにもこの権限が含まれます。

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "version": "2.4.0", "commit": "9f2c1e7a4b3d", "repository": "https://github.com/acme/checkout", "ciUrl": "https://ci.example.com/runs/7"}'
```

| フィールド | 必須 | 説明 |
|---|---|---|
| `service` | はい | スパンの `service.name` に記録したサービス名です。最大255文字です。 |
| `version` | デプロイの場合 | デプロイしたバージョンです。スパンの `service.version` と同じ値を指定します。最大192文字です。 |
| `kind` | いいえ | `deployment`（デフォルト）、`configuration`、`feature_flag` のいずれかを指定します。 |
| `namespace` | いいえ | サービスの `service.namespace` です。省略すると、すべての名前空間にデプロイを表示します。 |
| `environment` | いいえ | `deployment.environment.name` で指定する環境です。省略すると、すべての環境にデプロイを表示します。 |
| `status` | いいえ | `succeeded`（デフォルト）、`failed`、`rolled_back` のいずれかを指定します。デプロイでサービスを `version` に戻した場合は `rolled_back` を指定します。 |
| `commit` | いいえ | デプロイしたコミットです。最大64文字の英数字を指定できます。 |
| `repository` | いいえ | コードの保存先です。最大512文字の https、http、ssh、git アドレスを指定できます。アドレス内のパスワードは `****` に置き換えて保存します。https アドレスのユーザー名部分も同様です。 |
| `pullRequest` | いいえ | プルリクエストへの http または https リンクです。 |
| `author` | いいえ | デプロイの実行者です。最大128文字です。 |
| `ciUrl` | いいえ | CI の実行への http または https リンクです。 |
| `description` | いいえ | 最大1,000文字です。イベントにポインターを合わせると表示します。 |
| `deployedAt` | いいえ | デプロイの実行時刻です。エポックからの経過時間をマイクロ秒単位で指定します。デフォルトはリクエストの受信時刻です。 |

サービス名と環境名は、APM での表記に合わせます。スパンと同様に、組織の命名ルール、環境のマッピング、エイリアスを適用します。詳しくは、 [APM 設定](/ja/apm/settings)を参照してください。

**データソース** ページの **GitHub Actions**、**GitLab CI/CD**、 **Jenkins** には、ワークスペースのアドレスを入力済みの状態で、以下の手順を表示します。

### GitHub Actions

トークンをリポジトリのシークレットとして保存し、デプロイジョブにステップを追加します。`if: always()` を指定すると、デプロイに失敗した場合も報告します。

```yaml
- name: Report the deployment to MoleSignal
  if: always()
  env:
    MOLESIGNAL_TOKEN: ${{ secrets.MOLESIGNAL_TOKEN }}
    DEPLOY_STATUS: ${{ job.status == 'success' && 'succeeded' || 'failed' }}
  run: |
    cat > deployment.json <<EOF
    {
      "service": "checkout",
      "environment": "production",
      "version": "${GITHUB_SHA::12}",
      "status": "$DEPLOY_STATUS",
      "commit": "$GITHUB_SHA",
      "repository": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY",
      "author": "$GITHUB_ACTOR",
      "ciUrl": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID"
    }
    EOF
    curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
      -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
      -H "Content-Type: application/json" \
      --data-binary @deployment.json
```

### GitLab CI/CD

トークンを `MOLESIGNAL_TOKEN` という名前のマスク済み CI/CD 変数として追加し、デプロイジョブの `after_script` から報告します。`after_script` はデプロイの成否にかかわらず実行します。

```yaml
deploy:
  stage: deploy
  environment: production
  script:
    - ./deploy.sh
  after_script:
    - |
      if [ "$CI_JOB_STATUS" = "success" ]; then DEPLOY_STATUS=succeeded; else DEPLOY_STATUS=failed; fi
      cat > deployment.json <<EOF
      {
        "service": "checkout",
        "environment": "$CI_ENVIRONMENT_NAME",
        "version": "$CI_COMMIT_SHORT_SHA",
        "status": "$DEPLOY_STATUS",
        "commit": "$CI_COMMIT_SHA",
        "repository": "$CI_PROJECT_URL",
        "author": "$GITLAB_USER_LOGIN",
        "ciUrl": "$CI_PIPELINE_URL"
      }
      EOF
      curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
        -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
        -H "Content-Type: application/json" \
        --data-binary @deployment.json
```

### Jenkins

トークンを ID が `molesignal-token` の **Secret text** 認証情報として追加し、パイプラインの `post` ブロックで報告します。`post { always }` を使うと、ビルドに失敗した場合も報告します。`GIT_URL` 内のパスワードは、デプロイ情報の保存時にマスクします。

```groovy
post {
  always {
    script {
      writeFile file: 'deployment.json', text: groovy.json.JsonOutput.toJson([
        service: 'checkout',
        environment: 'production',
        version: env.GIT_COMMIT.take(12),
        status: currentBuild.currentResult == 'SUCCESS' ? 'succeeded' : 'failed',
        commit: env.GIT_COMMIT,
        repository: env.GIT_URL,
        ci_url: env.BUILD_URL,
      ])
    }
    withCredentials([string(credentialsId: 'molesignal-token', variable: 'MOLESIGNAL_TOKEN')]) {
      sh '''
        curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
          -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
          -H "Content-Type: application/json" \
          --data-binary @deployment.json
      '''
    }
  }
}
```

## 設定変更と機能フラグの変更を報告する

設定や機能フラグの変更も、同じエンドポイントで報告します。`kind` を設定し、変更内容の説明を指定してください。バージョンの指定は不要です。

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "kind": "feature_flag", "description": "new_checkout on for 10% of users"}'
```

## トラブルシューティング

| 症状 | 確認事項 |
|---|---|
| 報告したデプロイがタイムラインに表示されない | 指定した期間に `deployedAt` が含まれ、`service` が APM 上のサービス名と一致していることを確認してください。環境を指定したデプロイは、その環境にのみ表示します。 |
| デプロイとデプロイ先のバージョンが別々の行に表示される | 報告した `version` がスパンの `service.version` と異なります。同じ値を報告してください。 |
| デプロイのエンドポイントが `403` を返す | トークンに `apm.deploy` 権限がありません。トークンのスコープに含まれていないか、紐づくメンバーまたはサービスアカウントに権限がありません。 |
| デプロイのエンドポイントが `400` を返す | フィールドの値が上の表の制限に違反しています。エラーメッセージで該当するフィールドを確認してください。 |
