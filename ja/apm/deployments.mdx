サービスページの**デプロイ**セクションでは、2つのソースを並べて表示します。パイプラインが報告するデプロイと、サービスのスパンが `service.version` で持つバージョンです。どのパイプラインも報告していないバージョンも、スパンだけから表示されます。

## デプロイのタイムライン

タイムラインには、対象の期間にサービスで起きたことが新しい順に一覧表示されます。

| イベント | 発生条件 |
|---|---|
| **デプロイ済み** | パイプラインが成功したデプロイを報告しました。 |
| **失敗** | パイプラインが失敗したデプロイを報告しました。失敗したデプロイは実行中のバージョンを変更しません。 |
| **ロールバック済み** | パイプラインがロールバックを報告したか、別のバージョンより前に実行されていたバージョンのデプロイを報告しました。この行には、どのバージョンから戻ったかが表示されます。 |
| **以前のバージョンに復帰** | スパンが、どのパイプラインも報告していない古いバージョンに戻りました。最後に確認されたバージョンが、5分以上前に停止したより新しいバージョンより前に初回検出された場合です。 |
| **初回検出** | スパンが、どのパイプラインも報告していないバージョンを持っていました。 |
| **設定** | パイプラインまたはツールが設定変更を報告しました。その説明が行に表示されます。 |
| **機能フラグ** | パイプラインまたはツールが機能フラグの変更を報告しました。その説明が行に表示されます。 |

設定変更や機能フラグは実行中のバージョンを変更せず、独自の数値も持っていません。インサイトの近くの変更として一覧表示されます。詳細は [検出結果の近くの変更](/ja/apm/insights#検出結果の前後の変更) を参照してください。

報告されたデプロイには、コミット、プルリクエスト、CI 実行、作成者が表示されます。リポジトリが http または https のアドレスの場合、コミットは GitHub、GitLab、Bitbucket におけるコミットのアドレスと同じ形式で、その Web ページから開きます。

各バージョンの期間内のリクエスト数、エラー率、p95 は最新の行に表示され、その前に初回検出されたバージョンに対する判定も示されます。

| 判定 | 発生条件 |
|---|---|
| **再発** | エラー率が1ポイント以上、かつ1.5倍以上に上昇したか、p95 が5分の1以上、かつ50 ms 以上上昇しました。悪化した部分は判定の後に続きます。 |
| **改善** | 2つのうち一方が同じだけ低下し、どちらも悪化しませんでした。 |
| **変化なし** | どちらもそこまで変化しませんでした。 |
| **リクエスト数不足** | どちらかのバージョンのリクエスト数が、バージョン比較に必要な数（デフォルトでは1,000）を下回りました。 |

判定を選択すると、その2つのバージョンが**2つのバージョンを比較**で開き、遅くなったエンドポイントと増加したエラーが一覧表示されます。再発または改善したバージョンは、概要の最近のデプロイでもマークされます。

## カナリア

カナリアが置き換え対象のバージョンの隣で実行される場合のように、2つのバージョンが同時に実行されていると、タイムラインの上にカードが表示され、2つが並べて示されます。2つのバージョンが同時に実行されているとみなされるのは、どちらもサービスの最後のスパンから5分以内に確認された場合です。カードは、より新しいバージョンが初回検出された時点から、最新の2つを比較します。

- 各バージョンが処理したリクエストの割合。
- 各バージョンのリクエスト数、エラー率、p50、p95、p99。
- より新しいバージョンの、古いバージョンに対する判定。

## CI からデプロイを報告する

パイプラインは `POST /api/v1/apm/deployments` でデプロイを報告します。リクエストには、`apm.deploy` を使用できる API トークンが必要です。オーナー、管理者、エディターがこれを持ち、取り込みトークンが従う**データ取り込み** ポリシーにも含まれています。

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "version": "2.4.0", "commit": "9f2c1e7a4b3d", "repository": "https://github.com/acme/checkout", "ciUrl": "https://ci.example.com/runs/7"}'
```

| フィールド | 必須 | 説明 |
|---|---|---|
| `service` | はい | サービス名。スパンが `service.name` で示す名前です。最大255文字。 |
| `version` | デプロイの場合は必須 | デプロイされたバージョン。スパンが `service.version` で報告する値です。最大192文字。 |
| `kind` | いいえ | `deployment`（デフォルト）、`configuration`、`feature_flag`、`scaling`、`infrastructure` のいずれか。 |
| `namespace` | いいえ | サービスの `service.namespace`。指定しないデプロイはすべての名前空間に表示されます。 |
| `environment` | いいえ | 環境。`deployment.environment.name` として指定します。指定しないデプロイはすべての環境に表示されます。 |
| `status` | いいえ | `succeeded`（デフォルト）、`failed`、またはデプロイによってサービスが `version` に戻った場合は `rolled_back`。 |
| `commit` | いいえ | デプロイされたコミット。最大64文字の英字と数字。 |
| `repository` | いいえ | コードの場所。https、http、ssh、git のアドレスで、最大512文字。アドレス内のパスワードは `****` として保持され、https アドレスのユーザー部分も同様です。 |
| `pullRequest` | いいえ | プルリクエストへの http または https リンク。 |
| `author` | いいえ | デプロイした人。最大128文字。 |
| `ciUrl` | いいえ | CI 実行への http または https リンク。 |
| `description` | いいえ | 最大1,000文字。ポインターをイベントの上に置くと表示されます。 |
| `deployedAt` | いいえ | デプロイが行われた時刻。エポックからのマイクロ秒単位。デフォルトはリクエストが到着した時刻です。 |

サービスと環境は、APM が名前を付ける方法で指定します。組織の命名規則、環境マッピング、エイリアスがスパンに適用されるのと同様に、これらにも適用されます。詳細は [APM 設定](/ja/apm/settings) を参照してください。

**データソース**ページには、以下の手順が **GitHub Actions**、**GitLab CI/CD**、**Jenkins** の各項目に、ワークスペースのアドレスを入力した状態で記載されています。

### GitHub Actions

トークンをリポジトリシークレットとして保存し、デプロイを行うジョブにステップを追加します。`if: always()` を指定すると、失敗したデプロイも報告されます。

```yaml
- name: Report the deployment to MoleSignal
  if: always()
  env:
    MOLESIGNAL_TOKEN: ${{ secrets.MOLESIGNAL_TOKEN }}
    DEPLOY_STATUS: ${{ job.status == 'success' && 'succeeded' || 'failed' }}
  run: |
    cat > deployment.json <<EOF
    {
      "service": "checkout",
      "environment": "production",
      "version": "${GITHUB_SHA::12}",
      "status": "$DEPLOY_STATUS",
      "commit": "$GITHUB_SHA",
      "repository": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY",
      "author": "$GITHUB_ACTOR",
      "ciUrl": "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID"
    }
    EOF
    curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
      -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
      -H "Content-Type: application/json" \
      --data-binary @deployment.json
```

### GitLab CI/CD

トークンを `MOLESIGNAL_TOKEN` という名前のマスクされた CI/CD 変数として追加し、デプロイジョブの `after_script` から報告します。`after_script` はデプロイが成功したかどうかに関係なく実行されます。

```yaml
deploy:
  stage: deploy
  environment: production
  script:
    - ./deploy.sh
  after_script:
    - |
      if [ "$CI_JOB_STATUS" = "success" ]; then DEPLOY_STATUS=succeeded; else DEPLOY_STATUS=failed; fi
      cat > deployment.json <<EOF
      {
        "service": "checkout",
        "environment": "$CI_ENVIRONMENT_NAME",
        "version": "$CI_COMMIT_SHORT_SHA",
        "status": "$DEPLOY_STATUS",
        "commit": "$CI_COMMIT_SHA",
        "repository": "$CI_PROJECT_URL",
        "author": "$GITLAB_USER_LOGIN",
        "ciUrl": "$CI_PIPELINE_URL"
      }
      EOF
      curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
        -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
        -H "Content-Type: application/json" \
        --data-binary @deployment.json
```

### Jenkins

トークンを ID `molesignal-token` の **Secret text** 認証情報として追加し、パイプラインの `post` ブロックで報告します。`post { always }` を指定すると、失敗したビルドも報告されます。`GIT_URL` 内のパスワードはデプロイを保存するときにマスクされます。

```groovy
post {
  always {
    script {
      writeFile file: 'deployment.json', text: groovy.json.JsonOutput.toJson([
        service: 'checkout',
        environment: 'production',
        version: env.GIT_COMMIT.take(12),
        status: currentBuild.currentResult == 'SUCCESS' ? 'succeeded' : 'failed',
        commit: env.GIT_COMMIT,
        repository: env.GIT_URL,
        ci_url: env.BUILD_URL,
      ])
    }
    withCredentials([string(credentialsId: 'molesignal-token', variable: 'MOLESIGNAL_TOKEN')]) {
      sh '''
        curl -fsS -X POST "https://<host>/api/v1/apm/deployments" \
          -H "Authorization: Bearer $MOLESIGNAL_TOKEN" \
          -H "Content-Type: application/json" \
          --data-binary @deployment.json
      '''
    }
  }
}
```

## 設定変更と機能フラグを報告する

設定変更、機能フラグ、スケールの変更、インフラストラクチャの変更は、同じエンドポイントを使ってサービスの配下で報告します。`kind` を設定し、何が変わったかの説明を付けます。バージョンは不要です。

報告されたすべての変更は、[`GET /api/v1/changes`](/ja/api/changes) にも一覧表示され、ログとトレースのヒストグラム、メトリクスチャートの下、およびアラートの**変更**ページでマークされます。

```bash
curl -X POST "https://<host>/api/v1/apm/deployments" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"service": "checkout", "environment": "production", "kind": "feature_flag", "description": "new_checkout on for 10% of users"}'
```

## Webhook から変更を報告する

Argo CD の通知、Spinnaker、ボディテンプレートを使う Unleash の webhook アドオンなど、webhook でボディとヘッダーを設定できるツールは、上記のように `POST /api/v1/apm/deployments` を呼び出します。独自のボディを送信するツール、またはヘッダーを設定できないツールは、代わりに `POST /api/v1/intake/changes` を呼び出します。API トークンは `Authorization: Bearer` に、ヘッダーを設定できない場合は `?token=` に指定し、`apm.deploy` を保持している必要があります。アドレス内のトークンはプロキシのログに残る可能性があります。そのようなツールには、`apm.deploy` のみにスコープした専用のトークンを発行してください。

| パラメーター | 備考 |
|---|---|
| `format` | `generic` (デフォルト)、`launchdarkly`、`unleash`、`nacos`、または `apollo`。 |
| `service`、`namespace`、`environment` | ボディで指定されていない内容。サービスを指定しない変更は拒否されます。 |
| `kind` | `deployment`、`configuration`、`feature_flag`、`scaling`、または `infrastructure`。ボディの内容を上書きします。 |
| `serviceField`、`environmentField`、`versionField`、`descriptionField`、`authorField` | `generic` 用: `/app/name` のような JSON ポインター、またはトップレベルのフィールド名。指定しない場合は、`POST /api/v1/apm/deployments` が受け取る同名のフィールドが読み取られます。 |

| フォーマット | 読み取り内容 |
|---|---|
| `launchdarkly` | フィーチャーフラグ。環境は監査対象リソースの `env/` 部分、説明はエントリのタイトル、作成者はメンバーのメールアドレスです。 |
| `unleash` | フィーチャーフラグ: イベントタイプとトグルの名前、その環境、および変更者。 |
| `nacos` | データ ID とグループの設定変更。Nacos の名前空間が namespace になります。 |
| `apollo` | 設定変更: アプリ ID がサービス、クラスターが環境、名前空間とリリースタイトルが変更内容です。 |

**データソース → DevOps** には、LaunchDarkly、Unleash、Nacos、Apollo それぞれのガイドがあり、ワークスペースのアドレスが入力されています。

ボディには 1 件の変更、または最大 100 件の変更のリストを含めることができます。応答は `201` で、保持された変更が返ります。プリセットは各ツールのドキュメントに記載されたペイロードに基づいて作成されており、実際のアカウントでは検証されていません。ツールのペイロードが異なる場合は、ポインターを指定して `generic` を使用してください。

```bash
curl -X POST "https://<host>/api/v1/intake/changes?format=launchdarkly&service=checkout&token=<token>" \
  -H "Content-Type: application/json" \
  -d @launchdarkly-event.json
```

## トラブルシューティング

| 症状 | 確認事項 |
|---|---|
| 報告されたデプロイがタイムラインに表示されない | 時間範囲に `deployedAt` が含まれていること、および `service` が APM と同じサービス名を指定していることを確認します。環境付きで報告されたデプロイは、その環境でのみ表示されます。 |
| デプロイとそのデプロイされたバージョンが 2 行で表示される | 報告された `version` が、スパンが持つ `service.version` と異なっています。同じ値を報告してください。 |
| デプロイメントエンドポイントから `403` が返る | トークンが `apm.deploy` を使用できない可能性があります。スコープに含まれていないか、そのメンバーまたはサービスアカウントに権限がありません。 |
| デプロイメントエンドポイントから `400` が返る | いずれかのフィールドが上記の表の制限に違反しています。エラーにどのフィールドかが示されます。 |
