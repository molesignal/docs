**インバウンド MCP** を使うと、Claude Code、Cursor、Codex、ChatGPT などの MCP クライアントは、Mole Agent と同じアクセス制御下のツールランタイムを通じて MoleSignal の機能を検出し、操作できます。クライアントは次のいずれかの方法で接続します。

- **stdio**（推奨）：クライアントは、npm パッケージ `@molesignal/cli` に含まれる `molesignal mcp` コマンドで MoleSignal CLI を起動します。CLI はブラウザーで一度サインインし、すべてのメッセージを次のエンドポイントに転送します。
- **Streamable HTTP**：クライアントがエンドポイントを直接呼び出します。

エンドポイントは次のとおりです。

```text
https://molesignal.example.com/api/v1/mcp
```

サーバーは Streamable HTTP を使用し、MCP プロトコルのバージョン `2026-07-28`、 `2025-11-25`、`2025-06-18`、`2025-03-26` に対応します。従来の HTTP+SSE は公開していません。stdio は CLI が提供します。

`agent.inbound_mcp.manage` 権限を持つ管理者は、次の場所でサーバー設定を変更できます。 **Mole Agent → 設定 → インバウンド MCP**

## 接続前の準備

1. ループバック以外のデプロイメントでは、`http.external_url` に MoleSignal の公開オリジンを設定します。 [設定](/ja/configuration)を参照してください。
2. **Mole Agent → 設定 → インバウンド MCP** を開き、サーバーが有効になっていることを確認します。
3. ページに表示されたエンドポイント全体を、スキームとホストを含めてコピーします。
4. OAuth 2.1、個人用 API トークン、サービスアカウントの API トークンのいずれかを選択します。

制限値と Origin 許可リストの変更は、次の MCP HTTP リクエストが開始された時点で反映されます。処理中のリクエストでは、開始時点の設定スナップショットが引き続き適用されます。

## stdio で接続する

MoleSignal CLI で一度サインインします。Node.js 20 以降が必要です。

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

ブラウザーで MoleSignal が開くので、サインインを承認します。CLI はサインイン情報を現在のユーザーだけが読み取れる `~/.config/molesignal/config.json` に保存し、更新します。次に、 `npx -y @molesignal/cli mcp` コマンドを使い、MoleSignal を stdio サーバーとしてクライアントに追加します。

| クライアント | 設定 |
|---|---|
| Claude Code | `claude mcp add --scope user molesignal -- npx -y @molesignal/cli mcp` |
| Cursor | `{"mcpServers": {"molesignal": {"command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` を `~/.cursor/mcp.json` に設定します |
| Codex | `codex mcp add molesignal -- npx -y @molesignal/cli mcp` |
| VS Code | `{"servers": {"molesignal": {"type": "stdio", "command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` を `.vscode/mcp.json` に設定します |
| Gemini CLI | `gemini mcp add molesignal npx -y @molesignal/cli mcp` |

`npx -y @molesignal/cli status` を実行すると、接続状態とツール数を確認できます。ブラウザーを利用できない場合は、サインインの代わりに、サーバーの環境変数に `MOLESIGNAL_URL` と `MOLESIGNAL_TOKEN`（API トークン）を設定します。 `npm install -g @molesignal/cli` でインストールすると、 `molesignal` コマンドで CLI を実行できます。すべてのコマンドについては、[MoleSignal CLI](/ja/cli) を参照してください。

**Mole Agent → 設定 → インバウンド MCP** の **セットアップ用プロンプト** は、エージェントツールが実行するセットアップ手順を生成します。プロンプトの上で **stdio** または **Streamable HTTP** を選択します。

</Note>

## API トークンで接続する

API トークンは、非対話型クライアントや自動化に適しています。

<Tabs>
  <Tab title="個人用 API トークン">
    **ID とアクセス → API トークン** からトークンを作成します。トークンには現在のユーザープリンシパルと、そのプリンシパルに割り当てられたロールが適用されます。クライアントのシークレットまたは環境変数の仕組みを使い、 `Authorization: Bearer <token>` として渡します。
  </Tab>
  <Tab title="サービスアカウントの API トークン">
    **ID とアクセス → サービスアカウント** からサービスアカウントを作成します。作成時に、そのアカウントにひも付く API トークンを 1 つ自動で発行し、平文の値を一度だけ表示します。

    サービスアカウントは非対話型の ID です。Web UI へのサインインや OAuth グラントの承認はできません。クライアントのシークレットまたは環境変数の仕組みを使い、初回発行のトークンを `Authorization: Bearer <token>` として渡します。
  </Tab>
</Tabs>

プロジェクトレベルの MCP 設定ファイルに API トークンを含めてコミットしないでください。Codex と Claude Code の例では、非対話型での利用に向けて環境変数を使う設定を紹介しています。

インバウンド MCP が受け付けるのは、個人用 API トークン、サービスアカウントの API トークン、OAuth アクセストークンのみです。データ取り込みや RUM の認証情報では、このエンドポイントにアクセスできません。MCP のリソース、ツール、実行履歴、監査レコードのいずれも、平文の認証情報を返しません。

## OAuth のディスカバリーと有効期間

MoleSignal は次の場所で OAuth メタデータを公開します。

```text
https://molesignal.example.com/.well-known/oauth-protected-resource/api/v1/mcp
https://molesignal.example.com/.well-known/oauth-authorization-server
```

認可サーバーは、PKCE `S256` を使う認可コードフロー、RFC 8707 に基づくリソースのバインド、動的クライアント登録、リフレッシュトークンのローテーション、トークンファミリーの失効に対応しています。アクセストークンの有効期間は 1 時間です。リフレッシュトークンには `offline_access` スコープと `refresh_token` グラントが必要です。有効期間は 30 日で、使用するたびに新しいトークンに置き換わります。

アクティブな OAuth 接続は、**Mole Agent → 設定 → インバウンド MCP** で確認および失効できます。接続一覧の下にある **セットアップ用プロンプト** には、このデプロイメントのエンドポイントが含まれます。 **プロンプトをコピー** を選択し、Claude Code や Cursor などのエージェントツールに貼り付けると、そのツールが MoleSignal を MCP サーバーとして追加します。

## テナント境界について

エンドポイント、カスタムヘッダー、ツール引数に `userId` や `orgId` を含めて送信しないでください。 MoleSignal は認証済みの認証情報から両方の ID を特定し、リクエストごとに最新の IAM スナップショットを読み込み直し、MCP セッションをその開始時に使った認証情報にひも付けます。

利用可能なツールセットは次のとおりです。

```text
Inbound MCP surface ∩ credential IAM permissions ∩ workspace Tool Policy
```

エージェントプロファイルはインバウンド MCP を制限しません。このエンドポイントは、Mole Agent に設定したアウトバウンド MCP サーバーやそのリモートツールへのアクセスを中継しません。

どの認証情報を使っても、インバウンド MCP 経由で [`_audit` ストリーム](/ja/settings/data-security#監査ストリーム) の行やフィールドを読み取ることはできません。**ログ** で開いてください。

## まずツールアダプターを使う

`tools/list` は、利用が許可された少数のツールを公開します。これには、よく使う 7 つの読み取りツール、承認と実行の制御機能、段階的にツールを検出するための 3 つのアダプターが含まれます。

| アダプター | 用途 |
|---|---|
| `tool_search` | 利用が許可されたインバウンド MCP ツールのカタログ全体を検索します。 |
| `call_read_tool` | 検出した読み取り専用ツールまたは事前チェックツールを実行します。 |
| `call_managed_tool` | 検出した管理対象の変更操作を実行します。`idempotencyKey` の指定が必須です。 |

プロンプトの例:

- 「MoleSignal のツールで最近のインシデントを検索し、未解決のインシデントのうち最も影響が大きいものを要約してください。」
- 「ステータスページのツールを探し、進行中のインシデントを一覧表示してください。変更は加えないでください。」
- 「このアラートルールをテストし、必要な確認または承認を得てから更新してください。」

ツール検出用のスキーマ、リスクレベル、承認の動作、対応する製品領域については、 [ツールカタログと実行](/ja/tools)を参照してください。

## 実行時の制限

| 制限 | デフォルト | 設定可能な範囲 |
|---|---:|---:|
| リクエストサイズ | 1 MB | 1–8 MB |
| レスポンスサイズ | 1 MB | 1–8 MB |
| 認証情報ごとの同時 HTTP 呼び出し数 | 8 | 1–128 |
| 認証情報ごとの 1 分あたりの HTTP 呼び出し数 | 60 | 1–10,000 |
| 読み取りツールのタイムアウト | 30 秒 | 100 ms–300 秒 |

これらの値は **Mole Agent → 設定 → インバウンド MCP** で変更します。組織のツールポリシーでは、ツールごとにタイムアウトやレスポンスサイズにさらに厳しい制限を設定できます。

## ブラウザーの Origin と Host のチェック

ブラウザー以外の MCP クライアントからは、`Origin` ヘッダーのないリクエストを受け付けます。ブラウザーからのリクエストは、同一オリジンであるか、インバウンド MCP の設定で指定した HTTP または HTTPS のオリジンと完全に一致する必要があります。

ループバックを使用しないデプロイでは、リクエストの `Host` が `http.external_url` と一致する必要があります。このチェックにより、ローカル MCP サーバーに対する DNS リバインディング攻撃を防ぎます。

## 接続のトラブルシューティング

| 症状 | 確認事項 |
|---|---|
| `401 missing Authorization Bearer token` | `codex mcp login molesignal` を実行するか、サポートされている API トークン用の環境変数を設定してください。 |
| 認可ページで再度サインインを求められる | Web UI、`http.external_url`、MCP エンドポイントに同じスキームとホストを使用してください。`localhost` と `127.0.0.1` を混在させないでください。 |
| `duplicate field resource` | 手動で設定した `--oauth-resource` を削除し、エンドポイントを再登録してください。 |
| OAuth コールバックで接続拒否エラーが発生する | ブラウザーが一時的なループバックコールバックにリダイレクトされるまで、MCP クライアントを起動したままにしてください。リスナーが停止している場合は、`codex mcp login` を再実行してください。 |
| MCP エンドポイントが `403` を返す | サーバーが有効かどうか、ブラウザーのオリジン、認証情報の状態、IAM 権限、ツールポリシーを確認してください。 |
| ツールが見つからない | `tool_search` で検索してください。一致するツールがない場合は、ツールの公開設定、IAM、ツールポリシーを確認してください。 |
