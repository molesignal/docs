プラットフォーム設定は、保護された `_sys` 組織にあります。ワークスペース切り替えメニューでこの組織に切り替えてください。アクセスできるのは、スーパー管理者とプラットフォームロールを付与されたアカウントです。各ページはこの組織の **設定** にあり、プラットフォーム権限が必要です。ページを表示するには該当グループの `.read` 権限が、変更するには `.manage` 権限が必要です。

| セクション | グループ | 権限 |
|---|---|---|
| **組織管理** | プラットフォーム | `sys.organizations.read` |
| **サインイン制限** | プラットフォーム | `sys.settings.signin.manage` |
| **クライアントIPの識別** | データプレーン | `sys.settings.signin.manage` |
| **データ保持** | データプレーン | `sys.settings.retention.manage` |
| **メトリクスのカーディナリティ** | データプレーン | `sys.settings.limits.manage` |
| **データ取り込み量** | データプレーン | `sys.settings.limits.manage` |
| **監査ログの保持** | データセキュリティ | `sys.settings.retention.manage` |

すべてのノードがデータベースからこれらの設定を読み取るため、変更後に再起動する必要はありません。

## 組織管理

**組織管理** には、インスタンス内のテナント組織の名前、スラッグ、ステータス、ID が一覧表示されます。

| 操作 | 動作 |
|---|---|
| **組織を作成** | **名前** と **スラッグ** を指定してテナント組織を作成します。スラッグは後から変更できません。 |
| 無効化 | 組織へのアクセスを直ちに停止します。再度有効にするまで、その組織のセッションと API 認証情報によるアクセスを拒否します。 |
| 有効化 | 組織のメンバーと認証情報によるアクセスを再開します。 |
| 削除 | 組織を完全に削除します。組織は直ちに削除され、保存済みファイルを含むデータも数分以内にバックグラウンドで削除されます。スラッグはすぐに再利用できます。 |

少なくとも1つのテナント組織を有効にしておく必要があります。`_sys` 組織自体は変更できません。組織のメンバーを管理するには、対象組織の [ID とアクセス](/ja/identity/members) を使用します。このページを開くには、**IAM を管理** を [組織](/ja/identity/teams#組織) で選択してください。

## サインイン制限

**サインイン制限** は、クレデンシャルスタッフィングやパスワードの推測を防ぐと同時に、誤ったパスワードを入力するだけで他のアカウントをロックできないようにします。アカウントのパスワード照合に失敗した回数をカウントします。対象は、パスワードによるサインイン、LDAP サインイン、データベースクライアントからのアカウントへのログイン、 [既存アカウントのリンク](/ja/identity/sso) 時のパスワード確認、および [第2要素の追加](/ja/identity/mfa) 前のパスワード確認です。 [公開リンク](/ja/resource-sharing#アクセスパスワードの制限) のアクセスパスワードも対象で、リンクごとに1つのアカウントとして扱います。パスキーと、OIDC、OAuth 2.0、SAML によるシングルサインオンは、カウントも制限もしません。

| 設定 | デフォルト | 上限に達した場合 |
|---|---|---|
| **1つのアドレスから同じアカウントへの試行** | 5回の失敗 | このアドレスからこのアカウントへのアクセスをロックします。他のアドレスには影響しません。 |
| **1つのアドレスから全アカウントへの試行** | 30回の失敗 | このアドレスからパスワードでサインインできなくなります。同じアドレスを共有する利用者にも影響します。 |
| **すべてのアドレスから同じアカウントへの試行** | 20回の失敗 | アカウントはロックせず、パスワードの照合頻度を制限します。過去30日間にサインインしたアドレスは制限しません。カウント期間を通して新たな失敗がなければ、カウントをリセットします。 |
| **制限中のパスワード照合間隔** | 60秒 | 1～600秒です。 |
| **ロックとカウントの期間** | 15分 | アドレスをロックする期間と、失敗をさかのぼってカウントする期間です。1～1440分です。 |

カウントを無効にするには `0` を入力してください。上限は100000です。変更は直ちに適用され、プラットフォームの監査ログに `signin_limits.update` として記録されます。

| ケース | 結果 |
|---|---|
| リクエストの拒否 | `Retry-After` を付けて `429` を返します。パスワードの照合もロックの延長も行わないため、ロックは設定した時間を超えません。 |
| 存在しないアカウント | 存在するアカウントと同じようにカウントして応答するため、応答からアカウントの有無は判別できません。 |
| 正しいパスワード | このアドレスからこのアカウントへの失敗回数をリセットします。アドレス全体とアカウント全体のカウントはリセットせず、この試行の1回分だけ差し引きます。 |
| ディレクトリに接続できないなど、サービスが利用できない場合 | 失敗としてカウントしません。 |
| 上限への到達 | アドレスと到達した上限を、プラットフォームの監査ログに `signin.lockout` として記録します。アカウントは、存在する場合のみ記録します。 |
| パスワードのリセット成功 | アカウントのロックを直ちに解除し、このアドレスからの照合頻度の制限も解除します。 |
| 公開リンクのアクセスパスワード | リンクごとに1つのアカウントとして扱い、過去30日間にそのリンクを開いたアドレスは照合頻度を制限しません。アクセスパスワードの照合失敗とサインインの失敗は **1つのアドレスから全アカウントへの試行** に合算するため、この上限に達すると、このアドレスからパスワードでサインインすることもできなくなります。 |
| 公開リンクでの上限への到達 | リンクを所有するワークスペースの監査ログに、リンク、アドレス、到達した上限を `resource_share.lockout` として記録します。**1つのアドレスから全アカウントへの試行** の上限に達した場合は、プラットフォームの監査ログにも `signin.lockout` として記録します。 |

アドレスは [クライアントIPの識別](#クライアントipの識別) で取得します。IPv6 は /64 単位でカウントします。デフォルトでは、プライベートアドレスをクライアントアドレスとしてカウントしません。未設定のプロキシを経由すると、すべての利用者が同じプロキシのアドレスを共有します。そのアドレスをカウントすると、数回パスワードを間違えるだけで全員のアクセスをロックできてしまいます。この場合は **すべてのアドレスから同じアカウントへの試行** のみが適用されます。実際にプライベートネットワークから接続する場合は、**プライベートアドレスをクライアントとしてカウント** をオンにしてください。

ページの **あなたのアドレス** には、このリクエストの送信元として識別したアドレスと、カウント対象かどうかが表示されます。リクエストに転送ヘッダーがあるにもかかわらず、接続元アドレスを使用した場合は警告を表示します。プロキシが設定されていない可能性があります。

ロックを早期に解除する必要がある場合に限り、メタデータデータベースで `DELETE FROM signin_attempts` を実行してください。すべてのカウントをリセットします。

## クライアントIPの識別

RUM データの取り込みでは、ブラウザーやデバイスごとにアドレスを記録し、そのアドレスから国、行政区画、都市を特定します。[サインイン制限](#サインイン制限) ではアドレスごとに失敗をカウントし、 [公開リンク](/ja/resource-sharing#監査と権限) の監査ログではアクセス元のアドレスを記録します。 **クライアントIPの識別** では、アドレスの取得元を指定します。この設定はすべての組織に適用されます。

| **アドレスの取得元** | 用途 |
|---|---|
| **直接接続元のアドレス** | デフォルトです。TCP 接続元のアドレスを使用し、すべての転送ヘッダーを無視します。取り込みエンドポイントを直接公開する場合に使用します。 |
| **単一値ヘッダー** | `CF-Connecting-IP` など、CDN やプロキシが設定するヘッダーから、IP アドレスだけを1つ読み取ります。 |
| **転送 IP アドレスチェーン** | `X-Forwarded-For` などの IP アドレスチェーンを右から左にたどり、信頼するプロキシをスキップして、信頼対象外の最初のアドレスを使用します。**チェーンの最大長** では、1つのリクエストから読み取るアドレスの上限を1～64の範囲で指定します。 |

プロキシを経由する場合は、次の項目も設定してください。

| フィールド | ルール |
|---|---|
| **クライアント IP ヘッダー** | 読み取るヘッダーを指定します。`Authorization`、`Cookie`、API キー、クライアント証明書のヘッダーは指定できません。 |
| **信頼するプロキシの CIDR** | IPv4 または IPv6 の CIDR を1行に1つ、最大64個まで指定します。接続元がこれらのネットワークに含まれる場合のみ、ヘッダーを読み取ります。`/0` を指定すると、そのアドレスファミリーのすべての接続元を信頼します。保護されたイングレスの背後でのみ使用してください。 |
| **接続元アドレスへのフォールバック** | ヘッダーがない、形式が不正、長すぎる、または使用可能なアドレスを含まない場合に、TCP 接続元のアドレスを使用します。 |

**プライベートアドレスをクライアントとしてカウント** は、どのアドレス取得元でも設定できます。この設定をオンにすると、信頼するヘッダーからプライベートアドレス、ループバックアドレス、リンクローカルアドレスを受け入れ、[サインイン制限](#サインイン制限) の対象にします。プライベートネットワークから接続する場合はオンにしてください。ここで設定していないプロキシを経由する場合は、オフのままにしてください。オンにすると、すべての利用者が同じアドレスとしてカウントされます。

## データ保持

**データ保持**では、個別の保持期間を設定していないストリームの保持日数を指定します。デフォルトは30日で、 1〜3650日の範囲で設定できます。各ストリームの保持期間は、[ストリーム](/ja/streams#リテンションと削除)で個別に設定できます。保持期間を過ぎたデータは次回のクリーンアップで削除され、復元できません。

現在より短い保持期間を入力すると、ページはファイルカタログを使って削除対象のデータを見積もり、ストリームごとに行数、サイズ、最も古いデータをサイズの大きい順に表示します。保存時には確認を求めます。削除対象が1 GiB以上または100万行以上の場合や、見積もりができない場合は、保持日数の再入力も求めます。保持期間を延長する場合は確認を求めません。セッションリプレイとプロファイルアーカイブにもこの設定が適用されますが、見積もりには含まれません。

同じページの**シンセティックテスト結果**では、シンセティックチェックの実行結果を保持する日数を指定します。デフォルトは30日で、0〜3650日の範囲で設定できます。0を指定すると無期限に保持します。保持期間を過ぎた実行結果とそのアーティファクト、および完了済みのタスクは1日1回削除されます。ただし、ロケーションに最新として表示される実行結果や、リビジョンの公開先となったテストは保持します。可用性の算出に使う `_synthetic_results` ストリームには、そのストリーム固有の保持期間を適用します。[シンセティックモニタリング](/ja/synthetics#結果ストリームと保持期間)を参照してください。

同じページの**ストレージカタログの履歴**では、ファイルカタログが完了済みの処理の記録を保持する日数を指定します。デフォルトは7日で、0〜3650日の範囲で設定できます。0を指定すると無期限に保持します。対象は、ガベージコレクターが削除済みのファイル、それらのファイルが属していた古いセグメントとパーティションマニフェスト、およびクローズ済みの書き込みストリームのフラッシュ記録です。10分ごとにクリーンアップを実行し、保持期間を過ぎた記録を削除します。データ自体には手を加えず、ストリームの累計データ取り込み量も変わりません。

## メトリクスのカーディナリティ

**メトリクスのカーディナリティ**では、同時にアクティブにできるPrometheusの時系列数を制限します。これにより、多数の値を持つラベルがメモリやストレージを使い切るのを防ぎます。

| 上限 | デフォルト | 意味 |
|---|---|---|
| **組織ごと** | 200,000 | 1つの組織でアクティブにできる時系列数です。 |
| **メトリクスごと** | 100,000 | 組織内の1つのメトリクスでアクティブにできる時系列数です。組織ごとの上限は超えられません。 |

上限に達すると、新しい時系列への書き込みを拒否します。既存の時系列への書き込みは続行できます。一定時間データを受信しない時系列は非アクティブになります。ノードは30秒ごとに上限を読み直します。時系列を生成しているラベルは、[メトリクス](/ja/metrics)のカーディナリティビューで確認できます。

## データ取り込み量

**データ取り込み量**では、[ソースごとのデータ取り込み量](/ja/streams#データ取り込み量と予算)の記録を保持する期間と、個別に集計するサービス数を指定します。

| フィールド | デフォルト | 意味 |
|---|---|---|
| **記録の保持期間** | 90日 | 保持期間を過ぎた1時間単位の記録は、1日1回削除されます。35〜3650日の範囲で設定できます。月次予算をいつでも確認できるよう、最短でも35日間保持します。 |
| **組織あたりのサービス数** | 1,000 | 各ノードで、1つの組織について1時間あたりに個別集計するサービス数です。1〜100,000の範囲で設定できます。上限を超えたサービスは**その他のサービス**としてまとめて集計し、送信元がサービス名を増やして記録数を増やすのを防ぎます。 |

## 監査ログの保持

**監査ログの保持**では、すべての組織とプラットフォームの監査ログの保持日数を指定します。デフォルトは90日で、0〜3650日の範囲で設定できます。`0`を指定すると無期限に保持します。保持期間を過ぎた記録は1日 1回削除され、復元できません。変更のたびに、プラットフォームの監査ログに次のイベントを記録します。 `audit_retention.update`。

現在より短い保持期間を入力すると、ページは変更によって削除される記録の件数を数えます。保存時には確認を求めます。削除対象が1,000件以上の場合や、件数を取得できない場合は、保持日数の再入力も求めます。
