```http
PUT /api/v1/streams/{id}/settings
```

ストリームのデータ保持期間と設定を更新します。変更するプロパティだけを送信してください。この呼び出しには `streams.configure` が必要です。`_audit` ストリームには `audit.read` も必要で、この権限がなければ `403` を返します。`_molesignal` システムストリームでは `sys.telemetry.manage` が必要で、データ保持期間、フィールドインデックス、抽出、マスキング、ダウンサンプリングのみ変更できます。

**ボディ**

| フィールド | 型 | 説明 |
|---|---|---|
| `retentionDays` | 整数または `null` | 1～3650 日です。`null` を指定すると明示的に設定した値が解除され、ストリームは **設定 → データ保持** のプラットフォームデフォルト値を継承します。範囲外の値を指定すると `400` を返します。 |
| `settings` | オブジェクト | ストリームの設定です。以下を参照してください。 |
| `fields` | 配列 | フィールドインデックスです。[フィールドインデックスを設定する](/ja/api/streams/edit-schema)を参照してください。 |

設定:

| 設定 | 説明 |
|---|---|
| `description` | Web UI に表示する自由記述のテキストです。 |
| `queryable` | `false` に設定しても、ストリームはデータの受信と保持を続けます。クエリのストリーム選択欄には表示されず、このストリームへのクエリは `403`（`stream is not queryable`）を返します。 |
| `maxQueryRangeHours` | ストリームに対する 1 回の SQL または PromQL クエリで指定できる時間範囲の上限です。1～87600 時間を指定できます。上限を超えるクエリは `400` を返します。`null` を指定すると上限がなくなります。 |
| `fieldMasking` | グローバルな[フィールドマスキング](/ja/settings#データセキュリティ)ルールをストリーム単位で上書きします。 |
| `indexPatterns` | `[{ "pattern": "*_id", "indexType": "exact" }]` のように、フィールドが初めて現れたときにインデックスを作成するルールを最大 32 件指定できます。`*` は任意の文字列、`?` は任意の 1 文字に一致します。フィールド名を明示して設定したインデックスが優先されます。その設定がなければ、パターンがフィールド名に一致し、`indexType` がデータ型に適合する最初のルールを適用します。パターンは 1～128 文字で、重複は指定できません。[新しいフィールドのインデックス](/ja/streams#新規フィールドのインデックス)を参照してください。 |
| `dailyMerge` | ログとトレースにのみ適用します。デフォルトの `true` では、1 日分のファイルの合計サイズが `[compactor].target_size` 以下の場合、その日が終わってから 1 時間後に 1 つのファイルにマージします。マージ後は、データ保持期間を日単位で適用します。`false` にすると、1 時間ごとのファイルを維持します。 |
| `partitions` | ログとトレースにのみ適用します。`[{ "field": "service", "type": "hash", "buckets": 4 }, { "field": "pod", "type": "prefix" }]` のように、分割に使うフィールドを最大 2 つ指定できます。`hash` は値のハッシュに基づいて `buckets` 個（2～64 個）のシャードに分割し、`prefix` は値の先頭文字に基づいて 37 個のシャードに分割します。設定後に書き込むデータを、これらのフィールドで分割します。シャード数の積は最大 256 で、2 つのフィールドには異なるフィールドを指定してください。スキーマにすでに存在するフィールドを指定する場合は、暗号化されていない `utf8` フィールドである必要があります。デフォルトの空リストでは分割しません。[フィールドで分割する](/ja/streams#フィールドで分割)を参照してください。 |
| `clustering` | ログにのみ適用します。`{ "fields": ["service", "level"], "interval": 60000000 }` のように設定すると、その後に書き込む各ファイル内の行を `interval` マイクロ秒ごとの時間区間に分け、区間を新しい順に並べます。各区間内では `fields` の値で並べ、値が同じ行は新しい順に並べます。フィールドは最大 2 つまで指定でき、重複は指定できません。スキーマにすでに存在するフィールドを指定する場合は、暗号化されていない `utf8`、`int64`、`bool` のいずれかのフィールドである必要があります。`interval` には 1 秒～1 時間の範囲で、1 時間を余りなく分割できる値を指定します。デフォルトは 1 分です。デフォルトではフィールドを指定せず、行を時刻順に維持します。[フィールドでクラスタリングする](/ja/streams#フィールドでクラスタリング)を参照してください。 |
| `indexChangedAt` | 読み取り専用です。既存フィールドのインデックスタイプが最後に変更された時刻を示します。サーバーが値を設定し、その時刻より前にインデックスを作成したファイルのインデックスをバックグラウンドで再作成します。 |
| `downsample` | メトリクスにのみ適用します。`{ "afterDays": 7, "intervalSecs": 300 }` のように設定すると、`afterDays` 日より古いサンプルを `intervalSecs` 秒ごとのバケットに集約します。バケット内の同じ系列のサンプルを 1 つのデータポイントにまとめ、値は平均し、デルタカウントは合計します。その後、元のサンプルを削除します。`afterDays` は 0～3650 で、デフォルトの `0` ではダウンサンプリングを無効にします。`intervalSecs` には 60 以上で、1 日を余りなく分割できる値を指定します。 |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/streams/$STREAM_ID/settings \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "retentionDays": 30,
    "settings": { "description": "Application logs", "queryable": true }
  }'
```
</RequestExample>

レスポンスは更新後のストリームです。データ保持期間とダウンサンプリングの設定は、コンパクターがデータを削除または集約するタイミングを決めます。変更は以降のクリーンアップに適用され、削除済みのファイルやサンプルは復元されません。

個別のデータ保持期間を設定していないストリームに適用するプラットフォームデフォルト値は、`GET /api/v1/settings/stream_retention` で取得し、同じボディ `{ "retentionDays": 30 }` を指定して `PUT` で設定します。どちらの操作にも、システムスコープの `sys.settings.retention.manage` が必要です。`retentionDays` には 1～3650 の整数を指定します。

`GET /api/v1/settings/stream_retention/preview?retentionDays=7` は、同じ権限とスコープで、デフォルトの保持期間を短縮した場合に削除されるデータを推定します。データ本体は読み取らず、ファイルカタログだけを参照するため、レスポンスは `"estimated": true` になります。`rows`、`storedBytes`、`earliestAt` は、この変更によって新たに削除されるデータの合計行数、合計保存バイト数、最も古い時刻を示します。`streamCount` は影響を受けるストリーム数、`streams` は規模の大きい上位 100 件のストリームとそれぞれの同じ指標および所属組織、`unavailableStreams` はカタログエントリを読み取れなかったストリーム数を示します。個別のデータ保持期間を設定したストリームとデータセットは対象外です。`retentionDays` が現在のデフォルト値以上の場合は、集計値としてゼロを返します。セッションリプレイとプロファイルアーカイブにも同じ設定が適用されますが、集計には含めません。
