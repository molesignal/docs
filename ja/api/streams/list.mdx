```http
GET /api/v1/streams
```

組織内のすべてのストリームを名前とタイプで並べ替え、JSON 配列として返します。各要素は [ストリームの取得](/ja/api/streams/get) に示す形式で、スキーマ、明示的に設定した `retention`、算出した `effectiveRetention`、設定、マイクロ秒単位のタイムスタンプを含みます。この呼び出しには `streams.read` または `sys.telemetry.read` が必要です。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/streams \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

レスポンスには、`_molesignal` などの保護されたシステムストリームが含まれます。トークンに `audit.read` がない場合は、`_audit` を除外します。ストリームは名前とタイプの組み合わせで識別するため、同じ名前が複数のタイプに存在することがあります。

## レスポンスの使用

このエンドポイントは、テレメトリレコードではなくストリーム定義を返します。ストリームのスキーマを読み取ったり設定を変更したりする前に、このエンドポイントでストリーム ID を確認してください。イベントをクエリするには、[クエリ API](/ja/api/query/execute) を使用してください。

| フィールド | 説明 |
|---|---|
| `id` | 単一のストリームを取得する API で使用する、変わらない識別子です。 |
| `name` と `streamType` | この 2 つの組み合わせでデータセットを識別します。ストリームの一覧を管理するときは、名前だけをキーにしないでください。 |
| `schema` | クエリの作成に使用するフィールド定義です。 |
| `retention` | ストリームに明示的に設定した保持期間です。`null` の場合はデフォルト値を適用します。 |
| `effectiveRetention` | ストリームに実際に適用される保持期間です。 |
| `createdAt`、`updatedAt` | ミリ秒ではなく、マイクロ秒単位の Unix タイムスタンプです。 |

## アクセス権限とデータの範囲の確認

対象の組織に関連付けられた認証情報を使用してください。一覧を取得するには `streams.read` または `sys.telemetry.read` が必要です。`audit.read` がない場合は `_audit` を除外します。`_audit` が含まれなくても、監査データの収集が無効になっているとは限りません。

レスポンスは JSON 配列であり、配列を `items` フィールドに格納したオブジェクトではありません。このエンドポイントにはページネーション用のパラメーターがありません。空の配列は、このリクエストの対象組織とアクセス権限の範囲内でストリームが返されなかったことを示します。別の組織にデータがないことを示すものではありません。

目的の `(name, streamType)` が見つかったら、その `id` を [ストリームの取得](/ja/api/streams/get) に渡してください。ストリーム定義の有無とは別に、実際にイベントを取得できるかどうかを [サンプルクエリ](/ja/api/query/execute) で確認してください。
