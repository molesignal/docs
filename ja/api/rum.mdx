RUM API は、ブラウザーやモバイルクライアントからイベントを受け取り、読み出せるようにします。すべてのエンドポイントは `/api/v1/rum` プレフィックスを使用し、Bearer トークンを必要とします。

```http
Authorization: Bearer <token>
```

イベントやリプレイセグメントの書き込みには `rum.write` が必要です。アプリケーションに紐づく[クライアントトークン](/ja/api/auth/rum-token)には、そのアプリケーションに対するこの権限だけが付与されます。読み取りには、対象に応じて `rum.events.read`、`rum.sessions.read`、`rum.replay.read`、`rum.issues.read`、`rum.analytics.read`、`rum.applications.read`、`rum.playlists.read` のいずれかが必要です。プラットフォームからの呼び出しでは、`sys.telemetry.read` を保護された `_sys` スコープで使用できます。アプリケーションの作成、変更、削除には `rum.applications.manage` が必要です。イシューのステータス、担当チーム、担当者の設定には `rum.playlists.manage` が必要です。

各行には実際のユーザーのデータが入ります。`synthetics` または `ci_test` タイプのセッションは、フィルターで `session.type`、`synthetics.*`、`ci_test.*` のいずれかを指定しない限り除外します。詳しくは[テストトラフィック](/ja/rum/test-traffic)を参照してください。フィールドには、`feature_flags.<key>`、`context.<key>`、`usr.extra.<key>`、`view.custom_timings.<key>` のように、JSON 列のキーも指定できます。

**タイプ**は、エンドポイントが処理する行の種類を表します。指定できる値は `sessions`、`views`、`actions`、`errors`、`resources`、`longTasks`、 `vitals`、`logs` です。各タイプの名前は、対応する[ストリーム](/ja/rum/events#イベントの保存先)の名前から `rum_` プレフィックスを除いたものです。

## リプレイセグメントを送信する

```http
POST /api/v1/rum/replay
```

```json
{
  "application": "checkout-web",
  "sessionId": "6f1c2b7e-1d5a-4c6b-9a3e-0a1b2c3d4e5f",
  "seq": 1,
  "events": [{ "type": 2, "timestamp": 1790000000000, "data": { "node": {} } }]
}
```

`sessionId`、`seq`、`events` は必須です。`env`、`service`、`version` も、SDK で設定した値を送信できます。アプリケーションの[保持フィルター](/ja/rum/sampling#フィルター)はこれらの値を使ってセッションを保持するかどうかを判定し、保持対象外のセッションのセグメントは保存しません。これら以外のフィールドは受け付けません。`events` には rrweb イベントを指定します。クライアントトークンで書き込めるのは、そのトークンに紐づくアプリケーションだけです。`application` は省略できますが、別の値を指定すると `403` が返ります。ほかの認証情報を使用する場合は、アプリケーションを指定します。存在しないアプリケーションを指定すると `404` が返ります。レスポンスには、保存したセグメントの情報が含まれます。含まれるフィールドは `id`、`seq`、`eventCount`、`hasFullSnapshot` です。

`GET /api/v1/rum/replay/{sessionId}` は `sessionId`、`segmentCount`、`events` を返します。`events` には、セッション内のすべてのセグメントのイベントが順番に含まれます。

## アプリケーションを管理する

アプリケーションには `id`、`name`、`platform`、`settings` があります。

```json
{
  "id": "checkout-web",
  "name": "Checkout web",
  "platform": "browser",
  "settings": {
    "collectIp": true,
    "collectGeo": true,
    "defaultPrivacy": "mask",
    "issuesPerHour": 100,
    "scrub": ["secrets", "emails", "phones", "cards", "national_ids", "url_params"],
    "sessionSampleRate": 100,
    "retentionFilters": [],
    "keepErrors": true,
    "sdk": { "sessionReplaySampleRate": 20, "forwardConsoleLogs": ["warn", "error"] },
    "segments": [{ "id": "enterprise", "name": "Enterprise", "conditions": [{ "field": "usr.extra.plan", "op": "is", "values": ["enterprise"] }] }]
  },
  "createdBy": "<user-id>",
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```

| フィールド | ルール |
|---|---|
| `id` | 作成時のみ指定できます。`A-Z`、`a-z`、`0-9`、`.`、`_`、`:`、`-` のいずれかを使って、1～64文字で指定します。省略すると、名前から生成します。作成後は変更できません。 |
| `name` | 作成時に必須です。1～128文字で指定します。 |
| `platform` | `browser`（デフォルト）、`android`、`ios`、`flutter`、`react-native`、`other` のいずれかです。 |
| `settings` | `collectIp` と `collectGeo` はブール値で、デフォルトは `true` です。`defaultPrivacy` は `mask`（デフォルト）、`mask-user-input`、`allow` のいずれかです。`issuesPerHour` は、アプリケーションが1時間に作成する新規[イシュー](/ja/rum/errors#1-時間あたりの新規イシュー数の上限)の上限です。1～10000の範囲で、デフォルトは100です。`scrub` は、イベントの保存前に除去する機密テキストの種類のリストです。`secrets`、`emails`、`phones`、`cards`、`national_ids`、`url_params` から指定します。デフォルトではすべての種類を除去し、空のリストを指定すると何も除去しません（[RUM のプライバシー](/ja/rum/privacy#受信時に機密テキストを除去する)を参照）。`sessionSampleRate` は、どの保持フィルターにも一致しないセッションのうち、保持する割合です。0～100の整数で、デフォルトは100です（[RUM データのサンプリング](/ja/rum/sampling#セッションの一部をサーバー側で保持する)を参照）。100を超える値を指定すると `400` を返します。`retentionFilters` は最大10件の[フィルター](/ja/rum/sampling#フィルター)のリストです。各フィルターは `{ "name", "rate", "conditions" }` と `id` を持ちます。`id` を省略するとサーバーが名前から生成し、フィルターの名前を変更しても `id` は変わりません。`PATCH` はリスト全体を置き換えます。`rate` は0～100の整数です。条件は `{ "field", "op", "values" }` で指定します。`field` は `env`、`service`、`version`、`source`、`session.type`、`geo.country_iso_code`、`browser.name`、`os.name`、`device.type` のいずれか、`op` は `is` または `is_not` です。`values` には1～20個の値を指定します。フィルターごとに最大5件の条件を指定できます。名前は大文字と小文字を区別せず、一意にしてください。`default` と `errors` は予約済みの ID です。`keepErrors` は、保持しないセッションのエラーを保持する設定で、デフォルトは `true` です。無効なリストを指定すると `400` を返します。`segments` は最大20件の[セグメント](/ja/rum/analytics#セグメント)のリストです。各セグメントは `{ "name", "conditions" }` と `id` を持ちます。`id` を省略すると名前から生成し、セグメントの名前を変更しても `id` は変わりません。`PATCH` はリスト全体を置き換えます。条件は `{ "field", "op", "values" }` で指定します。`field` は `service`、`version`、`source`、`usr.id`、`usr.email`、`account.id`、`browser.name`、`os.name`、`device.type`、`geo.country_iso_code`、`geo.continent_code`、`geo.city`、`usr.extra.<key>` のいずれか、`op` は `is` または `is_not` です。`values` には1～20個の値を指定します。セグメントごとに1～5件の条件を指定します。`sdk` は、`remoteConfiguration` を指定して初期化した SDK に `GET /api/v1/rum/config` が返す設定です。`sessionSampleRate` と `sessionReplaySampleRate`（いずれも0～100）、`defaultPrivacyLevel`、`trackUserInteractions`、`forwardConsoleLogs`（`debug`、`log`、`info`、`warn`、`error` のリスト）を任意で指定できます。この設定に含まれない項目には、SDK がページで指定された値を使います。`settings` の各項目を省略すると、作成時はデフォルト値を使い、`PATCH` 時は既存の値を維持します。 |

`POST` は新しいアプリケーションを返します。識別子または名前が既存のものと重複すると `409` を返します。`PATCH` では `name`、`platform`、 `settings` を任意で指定できます。`DELETE` は `{ "deleted": true }` を返します。アプリケーションがすでに送信したイベントは、ストリーム内に保持期間が終了するまで残ります。

## 行を検索する

```http
GET /api/v1/rum/search?type=errors&from=1790000000000000&to=1790003600000000&filters=[{"field":"env","op":"=","value":"production"}]&limit=100
```

`POST` は同じ名前のパラメーターを JSON ボディで受け取ります。URL に収まらない長いクエリに適しています。URL で指定する場合、`filters`、`freeText`、 `columns` は JSON でエンコードしたリストにします。

| パラメーター | 型 | 動作 |
|---|---|---|
| `type` | 文字列 | 必須です。行のタイプを指定します。 |
| `from`, `to` | 整数 | Unix エポックからの経過時間をマイクロ秒で指定します。デフォルトは、`to` が現在時刻、`from` が `to` の24時間前です。`to` は `from` より後にしてください。 |
| `filters` | リスト | 各行がすべて満たす必要がある条件です。詳細は下記を参照してください。 |
| `freeText` | 文字列のリスト | 最大8語を指定できます。各単語が、対象タイプのいずれかのテキスト列に含まれている必要があります。大文字と小文字は区別しません。 |
| `columns` | 文字列のリスト | レスポンスに含める列です。省略すると、対象タイプのデフォルト列を返します。行を識別する列は常に含みます。 |
| `limit` | 整数 | 1ページあたりの行数です。1～5,000の範囲で指定します。デフォルトは100です。 |
| `cursor` | 文字列 | 以前のレスポンスの `nextCursor` または `previousCursor` を指定します。他のパラメーターはすべて省略するか、前回とまったく同じ値を指定してください。 |

**フィルター**には `field`、`op`、`value` があります。フィルターは最大32件で、`value` は最大512文字です。

| `op` | 意味 |
|---|---|
| `=`, `!=` | 値が等しいか、等しくないかを判定します。`value` が空の場合、`=` はフィールドに値がないか、`!=` は値があるかを判定します。 |
| `in`, `not_in` | フィールドの値がリスト内のいずれかの値に一致するか、どの値にも一致しないかを判定します。`value` は `["Chrome","Safari"]` のように、1～100個の値を含む JSON リストです。 |
| `contains` | フィールドに指定のテキストが含まれるかを判定します。大文字と小文字は区別しません。テキスト列と JSON ドキュメントに使用できます。 |
| `>`, `>=`, `<`, `<=` | 数値または時刻を比較します。 |
| `exists`, `missing` | フィールドに値があるか、ないかを判定します。 |

対象タイプに存在しないフィールドや、そのフィールドがサポートしない演算子を指定すると、リクエストは `400` で失敗します。

レスポンスには、1ページ分の行が新しい順に含まれます。

```json
{
  "items": [
    { "timestamp": 1790000001600000, "error.message": "Payment provider timeout", "error.id": "0a9b8c7d-6e5f-4a3b-8c1d-2e3f4a5b6c70" }
  ],
  "hasMore": true,
  "nextCursor": "<cursor>",
  "previousCursor": null
}
```

各行には `timestamp` と指定した列が含まれます。JSON 列にはドキュメントが含まれます。ビューとセッションはそれぞれ最新バージョンのみを1回返します。

## 行の件数と内訳を取得する

`facets` は、ページネーション用のパラメーターを除く `search` のパラメーターに加え、`field`（必須）と `limit`（1～100、デフォルトは10）を受け取ります。一致する行で出現頻度が高いフィールドの値を返します。

```json
{ "field": "browser.name", "values": [{ "value": "Chrome", "count": 812 }, { "value": "Safari", "count": 247 }] }
```

集計が制限時間を超えた場合やシステムがビジー状態の場合は、空のリストを返し、`unavailable` をそれぞれ `time_budget` または `busy` に設定します。 JSON ドキュメントを格納するフィールド全体を指定すると `400` を返します。`feature_flags.checkout_v2` のようにドキュメント内のキーを指定すると、値ごとに集計します。`session.type` のファセットでは、すべての種類のセッションを集計します。

`keys` は、検索条件に加え、`column`（必須。`feature_flags`、`context`、`usr.extra`、`view.custom_timings` のいずれか）と `limit`（1～500、デフォルトは100）を受け取ります。`type` のデフォルトは `views` です。キーを、そのキーを含むセッションの数が多い順に返します。

```json
{ "column": "feature_flags", "keys": [{ "key": "checkout_v2", "sessions": 812 }] }
```

`distribution` は、検索条件に加え、`field`（必須。数値フィールド、または JSON 列内の数値を格納するキー）と `bars`（1～100、デフォルトは40）を受け取ります。保存済みの行を集計します。最小値から99パーセンタイルまでを等幅のバーに分け、99パーセンタイルを超える値は最後のバーにまとめます。このため、最後のバーの `to` は最大値になります。すべての値が同じ場合は、バーが1本になります。

```json
{
  "field": "view.loading_time",
  "unit": "ns",
  "rows": 812,
  "min": 90000000,
  "max": 41000000000,
  "p50": 800000000,
  "p75": 1400000000,
  "p95": 3100000000,
  "p99": 6000000000,
  "bars": [{ "from": 90000000, "to": 237750000, "rows": 12 }]
}
```

`histogram` は、同じ検索条件に加え、集計区間を指定する `bucketTime`（1000以上）と、最初のバーの開始時刻を指定する `originTime` を受け取ります。`originTime` を省略すると `from` を使い、`from` より後の時刻は指定できません。1つの範囲に含められるバーは最大512本です。各バケットは `{ startTime, total, errors }` です。`errors` は問題が発生した行を集計します。対象は、エラーのあるセッションとビュー、フラストレーションのあるアクション、ステータスが `400` 以上または `0` のリクエストです。このような行がないタイプでは、`split` は `false` です。

`GET /api/v1/rum/schema/{type}` は、他のエンドポイントで指定または取得できる列を一覧で返します。

```json
{
  "type": "views",
  "stream": "rum_views",
  "idField": "view.id",
  "versioned": true,
  "defaultColumns": ["view.id", "view.url_path", "view.loading_time"],
  "fields": [
    { "name": "view.loading_time", "dataType": "int64", "unit": "ns", "facetable": true, "indexed": false }
  ]
}
```

`dataType` は `bool`、`int64`、`float64`、`utf8`、`json` のいずれかです。`unit` は `ns`、`ms`、`epoch_ms`、`bytes`、`count`、 `score`、`percent`、`per_second`、`px`、`none` のいずれかです。時間の長さは、SDK が送信したナノ秒単位の値のまま保存し、クライアントが表示形式を整えます。`epoch_ms` は、`session.start` や `session.last_activity` などの時点を Unix エポックからの経過時間としてミリ秒単位で表し、クライアントは日時として表示します。`facetable` フィールドは値ごとに集計でき、 `indexed` フィールドはすべての行を読み取らずにフィルタリングできます。`idField` は、行を一意に識別する列の名前です。

## 行の集計

`aggregate` は `search` の抽出条件に一致するすべての行を集計します。チャート、テーブル、マップの元になる数値を返します。たとえば、セッション数やバイタル指標の75パーセンタイルを、ページ別や時間別に取得できます。

```http
GET /api/v1/rum/aggregate?type=views&groupBy=["view.url_path_group"]&measures=[{"fn":"count","name":"views"},{"fn":"p75","field":"view.performance.lcp.timestamp","name":"lcp"}]&limit=5
```

| パラメーター | 型 | 動作 |
|---|---|---|
| `type`, `from`, `to`, `filters`, `freeText` | | `search` と同じです。 |
| `measures` | リスト | 必須です。集計指標は最大16個です。詳細は後述します。 |
| `groupBy` | 文字列のリスト | 最大2つのフィールドを指定できます。値の組み合わせごとに1行を返します。JSONドキュメントを格納するフィールド自体ではグループ化できませんが、そのキー（例: `feature_flags.checkout_v2`）ではグループ化できます。 |
| `bucketTime`, `originTime` | 整数 | `histogram` と同じです。指定すると、グループとバーの組み合わせごとに1行を返します。 |
| `orderBy` | 文字列 | 集計指標名、グループ化フィールド名、または `time`（グループなしのバー）を指定します。省略すると、グループは最初の集計指標で順位付けし、バーは時系列順に並べます。 |
| `order` | `asc` または `desc` | 省略すると、集計指標では降順、グループまたは時刻では昇順に並べます。 |
| `limit` | 整数 | グループ数を1〜250の範囲で指定します。デフォルトは10です。バーがある場合は最大20グループとし、各グループをすべてのバーにわたって追跡します。 |
| `estimate` | ブール値 | デフォルトは `true` です。各行を保持率（`retention.rate`）の逆数で重み付けし、全セッションの件数、合計、平均、パーセンタイルを推定します。`false` の場合は、エクスプローラーと同様に保存済みの行だけを集計します。 |

各**集計指標**は `fn` と `field` を持ち、必要に応じて `name`、`where`、`fallback` を指定できます。

| `fn` | 意味 |
|---|---|
| `count` | 行数を返します。`field` を指定すると、そのフィールドに値がある行だけを数えます。`estimate` が有効な場合は、各行の保持率に応じて件数を補正します。 |
| `stored` | 保持率に関係なく、保存済みの行数を返します。 |
| `count_distinct` | `field` の一意な値の数を返します。`fallback` では、`field` に値がない場合に使うフィールドを指定します。これにより、IDのないユーザーを匿名IDで区別できます。ユーザーなどは観測された値をそのまま数えますが、セッション（`session.id`）の件数は `estimate` が有効な場合に補正します。 |
| `sum`, `avg`, `min`, `max` | 数値の合計、平均、最小値、最大値をそれぞれ返します。 |
| `p50`, `p75`, `p90`, `p95`, `p99` | 数値のパーセンタイルを推定します。 |

`where` は `search` と同じ形式のフィルターのリストです。集計指標は、すべてのフィルターに一致する行だけを対象にします。 `{"fn":"count","where":[{"field":"session.error.count","op":"=","value":"0"}]}` は、エラーのないセッションを数えます。集計指標の名前には `name` を使います。省略すると `fn(field)`、フィールドもない場合は `fn` を使います。複数の集計指標に同じ名前は使えません。指定した型に存在しないフィールドを参照した場合や、数値型ではないフィールドに対して数値の集計を指定した場合は、リクエストが失敗し、`400` を返します。

```json
{
  "groupBy": ["view.url_path_group"],
  "measures": [
    { "name": "views", "fn": "count", "unit": "count" },
    { "name": "lcp", "fn": "p75", "field": "view.performance.lcp.timestamp", "unit": "ns" }
  ],
  "rows": [
    { "group": ["/checkout"], "values": [8031, 3400000000.0] },
    { "group": [null], "values": [212, null] }
  ]
}
```

各行には、`groupBy` の指定順にグループの値を格納する `group` と、集計指標の指定順に結果を格納する `values` が含まれます。時系列の場合は、バーの開始時刻を示す `startTime` も含まれます。グループ内のどの行にも値がない場合や、パーセンタイルの計算対象となる値がない場合は `null` を返します。`unit` は `count`、または `schema` が返すフィールドの単位です。ビューとセッションはそれぞれ、最新バージョンで1回だけ数えます。一致する行がない場合、グループまたはバーがあれば行を返さず、どちらもなければ1行を返します。この行では件数が `0`、その他の集計指標が `null` になります。閲覧権限のない値はマスク後のテキストで返します。集計が制限時間を超えた場合やシステムがビジー状態の場合は行を返さず、`unavailable` にそれぞれ `time_budget` または `busy` を設定します。

## ダッシュボードパネルのSQLステートメント

```http
POST /api/v1/rum/panel-statement
```

[エクスプローラー](/ja/rum/explorer#ダッシュボードに追加)と同じ結果を描画するために[ダッシュボード](/ja/dashboards)パネルが実行するSQLステートメントを返します。対象の行と集計結果は、`aggregate` で `estimate` を `false` にした場合と同じです。このリクエストではデータを読み取りません。 SQLステートメントには時間範囲を指定しません。ダッシュボードで選択した時間範囲で実行するためです。`rum.events.read` 権限が必要です。

```json
{
  "type": "views",
  "filters": [{ "field": "env", "op": "=", "value": "production" }],
  "chart": "timeseries",
  "measures": [{ "fn": "p75", "field": "view.loading_time", "name": "p75 Loading" }],
  "groupBy": ["browser.name"],
  "groupNames": ["Browser"],
  "limit": 5,
  "interval": "${interval}"
}
```

| フィールド | 型 | 動作 |
|---|---|---|
| `type`, `filters`, `freeText` | | `search` と同じです。 |
| `chart` | 文字列 | 必須です。`timeseries`、`toplist`、`table`、`distribution` のいずれかを指定します。 |
| `measures`, `groupBy`, `orderBy`, `order`, `limit` | | `estimate` とバーの扱いを除き、`aggregate` と同じです。`toplist` ではグループ化フィールドを1つ指定します。`timeseries` では最大20グループを追跡します。各集計指標は、その `name` を列名とする列になります。 |
| `groupNames` | 文字列のリスト | グループ化フィールドの列名を、指定順に設定します。列名を指定しない場合はフィールド名を使います。 |
| `field` | 文字列 | `distribution` では必須です。分布を表示する数値フィールドを指定します。その列には `groupNames` の最初の名前を、件数の列には最初の集計指標の `name` を使います。 |
| `interval` | 文字列 | `timeseries` では必須です。時間の区切り幅を、`${interval}` などのダッシュボード変数、または `15 minutes` などの時間の長さで指定します。 |

```json
{
  "stream": "rum_views",
  "statement": "WITH \"__top\" AS (SELECT … LIMIT 5) SELECT date_bin(INTERVAL '${interval}', _timestamp) AS \"time\", … FROM \"rum_views_latest\" JOIN \"__top\" ON … GROUP BY 1, 2 ORDER BY 1, 2",
  "columns": [
    { "name": "time", "role": "time", "unit": "none" },
    { "name": "Browser", "role": "group", "unit": "none" },
    { "name": "p75 Loading", "role": "measure", "unit": "ms" }
  ],
  "limit": 10000
}
```

SQLステートメントは `stream` を読み取り、ビューまたはセッションの最新バージョンを `rum_views_latest` または `rum_sessions_latest` から読み取ります。抽出条件を適用し、フィルターで `session.type`、`synthetics.*`、`ci_test.*` のいずれかを指定しない限り、シンセティックテストやCIで実行したセッションを除外します。`columns` は結果に含まれる列を順に示します。列は、バーの開始時刻を表す `time`、グループ、集計指標の順です。集計指標の `unit` は表示単位です。たとえば、所要時間は `ms` で表示します。

- `timeseries` は、バーとグループの組み合わせごとに1行を返します。グループは、時間範囲全体で最初の集計指標の値が上位のものを選びます。
- `toplist` または `table` は、指定した順序でグループごとに1行を返します。行数の上限は `limit` です。
- `distribution` は、最小値から99パーセンタイルまでを40本のバーで返します。99パーセンタイルを超える値も最後のバーに含めます。各バーの名前には、その値の表示単位で表した下限値を使います。

`limit` はパネルが要求する行数です。指定した型に存在しないフィールドを参照した場合、指定内容ではチャートを描画できない場合（`toplist` のグループ化フィールドが1つではない、`timeseries` に `interval` がない）、または `interval` が変数でも時間の長さでもない場合は、`400` を返します。

## ファネル、パス、リテンション

`/api/v1/rum/analytics` 配下の 3 つのエンドポイントは、[RUM 分析](/ja/rum/analytics)のクエリに応答します。各エンドポイントは `search` のうち、セッション、ビュー、アクションに適用する条件を受け取ります。`from` と `to` はマイクロ秒で指定します。`filters` はすべての行が満たす条件で、通常はアプリケーション（`application.id`）と環境（`env`）を指定します。`GET` では、リストを JSON 形式でクエリパラメーターに渡すため、クエリをリンクとして共有できます。`POST` では、同じ名前のフィールドを JSON ボディで渡します。`rum.analytics.read` が必要です。保護された `_sys` スコープでは `sys.telemetry.read` が必要です。集計が制限時間を超えた場合やシステムがビジー状態の場合、集計値は返さず、`unavailable` をそれぞれ `time_budget` または `busy` に設定します。レスポンスには、集計対象の `from` と `to` が含まれます。

### ファネル

```http
GET /api/v1/rum/analytics/funnel?filters=[{"field":"application.id","op":"=","value":"shop-web"}]&steps=[{"type":"views","filters":[{"field":"view.url_path_group","op":"=","value":"/cart"}]},{"type":"actions","name":"Paid","filters":[{"field":"action.target.name","op":"=","value":"Pay now"}]}]&windowSecs=1800&breakdown=browser.name
```

| パラメーター | 型 | 動作 |
|---|---|---|
| `from`, `to` | 整数 | マイクロ秒で指定します。省略すると直近 7 日間が対象になります。 |
| `filters` | リスト | 各ステップの個別フィルターに加え、すべてのステップが満たす必要がある条件です。 |
| `steps` | リスト | 必須です。2〜8 個のステップを指定します。各ステップには `type`（`views` または `actions`）、その型の行に適用する `search` と同じ形式の `filters` のリスト、任意の `name` を指定します。`name` を省略すると、最初のフィルターの値を使用します。 |
| `windowSecs` | 整数 | 最初のステップから後続のステップまでの最大経過時間を秒単位で指定します。省略すると時間の制限はありません。 |
| `breakdown` | 文字列 | 最初のステップの行にあるテキストフィールドを指定します。値ごとにファネルを作成し、セッション数の多い上位 10 件の値を使用します。 |

最初のステップでは、セッション内で条件を満たす最初の行でそのセッションをカウントします。後続の各ステップでは、同じセッション内で、直前のステップの行より後に条件を満たす最初の行でカウントします。

```json
{
  "groups": [
    {
      "value": null,
      "steps": [
        { "name": "/cart", "sessions": 4, "conversion": 1.0, "fromPrevious": null, "medianMs": null },
        { "name": "Paid", "sessions": 2, "conversion": 0.5, "fromPrevious": 0.5, "medianMs": 210000.0 }
      ]
    }
  ],
  "from": 1779400000000000,
  "to": 1780000000000000
}
```

各グループは、`breakdown` の値が同じセッションのファネルです。最初のステップのセッション数が多い順に並びます。全セッションをまとめたグループと、該当する行に値がないセッションのグループでは、`value` は `null` です。`conversion` は最初のステップのセッション数に対する割合、`fromPrevious` は直前のステップのセッション数に対する割合、`medianMs` は直前のステップからの経過時間の中央値です。該当しない項目は `null` になります。指定した行の型にフィールドが存在しないか、フィールドがテキスト型でない場合は、リクエストに `400` を返します。

### パス

| パラメーター | 型 | 動作 |
|---|---|---|
| `from`, `to`, `filters` | | `funnel` と同じです。ビューの行が対象です。 |
| `anchor` | 文字列 | パスの起点となるページです。逆方向にたどる場合は終点になります。省略すると、各セッションの最初のページを使用します。逆方向の場合は最後のページを使用します。 |
| `backward` | ブール値 | 起点より前のページをたどります。デフォルトは `false` です。 |
| `depth` | 整数 | 起点より後（逆方向の場合は前）のページ数を 1〜6 の範囲で指定します。デフォルトは 3 です。 |
| `by` | 文字列 | ページを識別するフィールドです。`view.url_path_group`（デフォルト）、`view.url_path`、`view.name` のいずれかを指定します。 |

```json
{
  "columns": 3,
  "sessions": 9,
  "backward": false,
  "nodes": [
    { "column": 0, "page": "/products", "sessions": 2, "ends": 0 },
    { "column": 1, "page": "/cart", "sessions": 2, "ends": 0 },
    { "column": 2, "page": "/checkout", "sessions": 1, "ends": 1 }
  ],
  "links": [
    { "column": 0, "source": "/products", "target": "/cart", "sessions": 2 },
    { "column": 1, "source": "/cart", "target": "/checkout", "sessions": 1 }
  ],
  "from": 1779400000000000,
  "to": 1780000000000000
}
```

ページは `columns` に格納されます。列数は `depth` より 1 つ多く、パスの基準ページは列 0（逆方向では最後の列）に入ります。ノードは各列のページを表します。`sessions` はそのページを通過したセッション数、`ends` はそこで終了したセッション数です（逆方向では、そこで始まったセッション数です）。リンクは `column` のページから次の列のページへつながり、その経路を通ったセッション数を示します。逆方向でも、リンクは時系列で後の列に向かいます。ページは開いた順に扱い、同じページを連続して開いた場合は 1 回として数えます。各列ではセッション数の上位 8 ページを個別に表示し、残りを `__other__` にまとめます。レスポンスの `sessions` は、パスの基準ページを含むセッション数です。

### リテンション

| パラメーター | 型 | 動作 |
|---|---|---|
| `from`, `to`, `filters` | | `funnel` と同じです。セッションの行が対象です。`from` と `to` を省略すると、コホートを作成できるように、現在から `periods` の 2 倍の期間をさかのぼります。ただし、最短でも 14 日間（`week` の場合は 8 週間）を対象とします。 |
| `period` | `day` または `week` | UTC の 1 日、または UTC の月曜日に始まる 1 週間です。デフォルトは `day` です。 |
| `periods` | 整数 | 最初の期間に続く期間数を 1〜30 の範囲で指定します。デフォルトは 7 です。 |

```json
{
  "period": "day",
  "periods": 3,
  "cohorts": [
    { "startTime": 1779408000000000, "users": 1, "returned": [1, 0, null] },
    { "startTime": 1779494400000000, "users": 6, "returned": [0, null, null] }
  ],
  "from": 1779408000000000,
  "to": 1779753600000000
}
```

コホートは、指定した時間範囲内で、`startTime` から始まる期間に初めて観測されたユーザーのグループです。ユーザーの識別には、セッションの `usr.id` を使用します。ない場合は `usr.anonymous_id` を使用します。`returned` には、後続の各期間に再び観測されたコホートのユーザー数が入ります。`to` の時点で終了していない期間の値は `null` です。

## ヒートマップ

`/api/v1/rum/heatmaps` 配下のエンドポイントは、[RUM ヒートマップ](/ja/rum/heatmaps)の集計結果を返します。`from` と `to` はマイクロ秒で指定し、`filters` には通常、`application.id`、`view.url_path_group`、ウィンドウの幅（`display.viewport.width`）を指定します。`GET` では、リストを JSON 形式でクエリパラメーターに渡します。`clicks` と `scroll` は `limit` も受け取り、`rum.analytics.read` が必要です。推定値ではなく、保存済みの行を集計します。

```json
{
  "clicks": 148,
  "elements": [
    {
      "element": "body>main>button:nth-of-type(2)",
      "name": "Pay now",
      "selector": "button.pay",
      "clicks": 92,
      "sessions": 60,
      "frustrated": 4,
      "pageX": 640.5,
      "pageY": 720.0,
      "cells": [[5, 4, 31], [6, 4, 28]]
    }
  ],
  "from": 1779400000000000,
  "to": 1780000000000000
}
```

`clicks` はクリック数の多い要素を返します。返す件数は 1〜300 件で、デフォルトは 100 件です。`element` はページ内での要素の位置を示します。`pageX` と `pageY` は、その要素がクリックされた位置のページ内での平均座標です。`cells` は要素を 10 × 10 のセルに分割した結果で、各セルは `[column, row, clicks]` で表します。

```json
{
  "views": 310,
  "pageHeight": 4200,
  "medianDepth": 1800,
  "bands": [{ "depth": 800, "reached": 1.0 }, { "depth": 900, "reached": 0.97 }],
  "from": 1779400000000000,
  "to": 1780000000000000
}
```

`scroll` は、スクロール深度が記録されたビューの数、ページの高さ、そのビューの半数が到達した深度を返します。深度は 100 ピクセルごとに区切ります。`reached` はその深度に到達したビューの割合で、深度が増しても値が増えることはありません。

`snapshot` には候補の 1 つの `viewId` を指定します。`rum.replay.read` が必要です。レスポンスの `candidates` には、そのページのリプレイがあるビューが新しい順に最大 20 件含まれます。各候補には `sessionId`、`viewId`、`atTime`、ウィンドウの `width` と `height` が含まれます。レスポンスの `snapshot` には、描画対象のビューについて同じ項目に加え、`atTime` より前の直近の完全スナップショットから `atTime` 時点のビューを再構築するための rrweb の `events` が含まれます。そのページを開いたセッションが 1 件も記録されていない場合、`snapshot` は `null` です。

## プレイリスト

[プレイリスト](/ja/rum/playlists)は、1 つのアプリケーションのセッションをまとめた名前付きリストです。各セッションには、確認したい再生位置を指定できます。

```json
{
  "id": "2xT9bQ1kLw5nVf8cZ0aR7mHpJd3",
  "application": "checkout-web",
  "name": "Checkout failures",
  "description": "Sessions that ended at the checkout with an error.",
  "createdBy": "<user-id>",
  "createdAt": 1790000000000000,
  "updatedAt": 1790000100000000,
  "sessionCount": 2,
  "sessions": [
    { "sessionId": "3f6c9a52-1b7e-4d08-a5c3-90e2d41f7b68", "atTime": 1790000005000000, "addedBy": "<user-id>", "addedAt": 1790000000000000 },
    { "sessionId": "9d41e7b0-62fa-4c3d-8e15-b7a09c52d3f4", "atTime": null, "addedBy": "<user-id>", "addedAt": 1790000100000000 }
  ]
}
```

`GET /api/v1/rum/playlists` は、`sessions` を含まないプレイリスト一覧を最終更新日時の新しい順に返します。`application` を指定すると、 1 つのアプリケーションに絞り込めます。読み取りには `rum.playlists.read` が必要です。プラットフォームからの呼び出しでは `sys.telemetry.read` を使用できます。その他のリクエストはプレイリストを変更するため、 `rum.playlists.manage` が必要です。いずれもセッションを含むプレイリストを返しますが、`DELETE` は `{ "deleted": true }` を返します。

| リクエスト | ボディ | ルール |
|---|---|---|
| `POST /rum/playlists` | `application` と `name`、任意で `description` と `sessions` | アプリケーションが存在する必要があります（存在しない場合は `404`）。名前は 1〜128 文字で、同じアプリケーション内では大文字と小文字を区別せずに一意である必要があります（重複する場合は `409`）。説明は 1,000 文字以内です。 |
| `PATCH /rum/playlists/{id}` | `name` と `description`（どちらも任意） | 省略した項目は現在の値を保持します。アプリケーションは変更できません。 |
| `POST /rum/playlists/{id}/sessions` | `sessions` | 追加済みのセッションを再度指定すると、リスト内の位置を変えずに `atTime` を更新します。プレイリストには最大 500 件のセッションを登録できます（超過すると `400`）。 |

リクエスト内のセッションは `{ "sessionId": "...", "atTime": 1790000005000000 }` の形式で指定します。ID は 1〜128 文字です。`atTime` を指定する場合は、セッションを開く時刻をエポックからの経過マイクロ秒で指定します。省略すると、セッションの先頭から開きます。プレイリストに保存するのはセッションそのものではなく ID です。セッションの存在は確認しません。保持期間の経過により行が削除されたセッションも、リストに残ります。`GET /api/v1/rum/sessions/{id}/playlists` は、指定したセッションを含むプレイリストを、各プレイリストのセッション一覧を除いて返します。

## 1 行または 1 セッションの取得

`GET /api/v1/rum/{type}/{id}` は、全列を含む 1 行を返します。該当する行がなければ `404` を返します。`from` と `to` で検索範囲を絞り込めます。省略すると、過去 30 日間を検索します。`{id}` は、そのタイプの `idField` の値です。

`GET /api/v1/rum/sessions/{id}/timeline` は次のフィールドを返します。

| フィールド | 内容 |
|---|---|
| `session` | セッションの行です。セッションの行がまだ生成されていない場合は `null` です。 |
| `items` | セッションに属する他のすべてのタイプの行を、古い順に並べたものです。各行の `type` は `view`、`action`、`error`、`resource`、`long_task`、`vital`、`log` のいずれかです。 |
| `truncated` | 行数がタイムラインの上限を超えたタイプです。 |

`GET /api/v1/rum/sessions/{id}/related-traces` は、セッションに関連するバックエンドトレースを一覧表示します。セッション内のリクエストにトレース ID が含まれている場合は、該当するトレースを返します（`relation: direct`）。該当するトレースがない場合は、セッションと同じ時間帯に実行されたトレースを返します（`relation: time-correlated`）。各トレースには `trace_id`、`service`、`spanCount`、`durationMs`、 `startedAt` が含まれ、レスポンスには `primaryService` も含まれます。逆に、`GET /api/v1/rum/traces/{traceId}/session` はトレースに関連するセッションを返します。該当するセッションがなければ `null` を返します。

## コメント

```http
POST /api/v1/rum/sessions/{id}/comments
```

```json
{ "application": "checkout-web", "atTime": 1790000005000000, "body": "The button does nothing here." }
```

`atTime` は、セッション内の時点をエポックからの経過マイクロ秒で表します。`body` は 1～2,000 文字です。1 セッションに最大 500 件のコメントを保存できます。`GET` は `{ "comments": [...] }` を時刻の古い順に返します。`rum.replay.read` 権限が必要です。

```json
{
  "id": "2xT9bQ1kLw5nVf8cZ0aR7mHpJd3",
  "application": "checkout-web",
  "sessionId": "3f6c9a52-1b7e-4d08-a5c3-90e2d41f7b68",
  "atTime": 1790000005000000,
  "body": "The button does nothing here.",
  "authorId": "<user-id>",
  "authorName": "Ada",
  "createdAt": 1790000010000000,
  "updatedAt": 1790000010000000,
  "editable": true
}
```

`POST` には `rum.replay.comments.write` 権限が必要です。`PATCH` は `body` を受け取ります。`PATCH` と `DELETE` のどちらも、コメントの作成者には同じ `rum.replay.comments.write` 権限が必要で、作成者以外には `rum.replay.comments.manage` 権限が必要です。`editable` は、リクエスト元がコメントを編集できるかどうかを示します。`DELETE` は `{ "deleted": true }` を返します。

## サマリー

`GET /api/v1/rum/sessions/{id}/summary` は `{ "summary": ... }` を返します。閲覧時の言語で保存されたサマリーがあればその内容を、なければ `null` を返します。`rum.replay.read` 権限が必要です。`POST` はモデルでサマリーを生成して保存します。`rum.replay.summaries.generate` 権限が必要です。保存済みのサマリーがある場合は、モデルを呼び出さずに返します。`{ "regenerate": true }` を指定すると、セッションに変更がない場合を除き、モデルを呼び出します。

```json
{
  "summary": {
    "sessionId": "3f6c9a52-1b7e-4d08-a5c3-90e2d41f7b68",
    "language": "en-us",
    "summary": "The user filled the cart and could not pay: the payment call failed three times.",
    "chapters": [{ "atTime": 1790000005000000, "title": "Fills the cart", "summary": "Adds two items." }],
    "model": "<model>",
    "promptTokens": 1820,
    "completionTokens": 240,
    "generatedAt": 1790000020000000
  }
}
```

モデルの呼び出しは、呼び出し元を `replay_summary` として Mole Agent の日次予算に計上します。予算を使い切ると `429` を返します。組織でキーを設定済みのモデルプロバイダーが有効になっていない場合や、セッションに要約する内容がない場合は `400` を返します。

## イシュー

類似するエラーを[イシュー](/ja/rum/errors)にまとめます。各エラー行の `error.issue_id` には、所属するイシューの ID が入ります。イシューの集計値は、指定範囲内のエラーに基づいて算出します。イシューのステータスと履歴は別々に管理します。時刻は Unix エポックからの経過マイクロ秒で表します。

```http
GET /api/v1/rum/issues?application=checkout-web&status=unresolved&sort=sessions&limit=50
```

| パラメーター | 型 | 動作 |
|---|---|---|
| `application` | string | 必須です。 |
| `env`, `source` | string | 指定した環境のエラー、または指定したソース（`browser`、`flutter` など）から送信されたエラーに絞り込みます。 |
| `filters` | list | `search` と同様に、集計対象のエラーに追加条件を指定します。 |
| `from`, `to` | integer | `search` と同じです。 |
| `status` | string | `unresolved`（デフォルト。`open`、`investigating`、`regressed` が対象）、`all`、または `open`、`investigating`、`regressed`、`resolved`、`ignored` のいずれかを指定します。 |
| `assignee`, `team` | string | ユーザー ID またはチーム ID を指定します。未割り当てのイシューには `none` を指定します。 |
| `search` | string | 指定した語句をイシューのタイプ、メッセージ、または発生箇所から検索します。大文字と小文字は区別しません。 |
| `fresh` | boolean | 指定範囲内で初めて発生したか、再発したイシューだけに絞り込みます。 |
| `sort` | string | `sessions`（デフォルト）、`users`、`occurrences`、`lastSeen`、`firstSeen`、`status` のいずれかを指定します。 |
| `order` | `asc` または `desc` | 省略時は、`status` を除き降順です。 |
| `limit` | integer | 1～100 を指定します。デフォルトは 50 です。 |

```json
{
  "issues": [
    {
      "id": "3f9c2a71e0b4c8d1",
      "applicationId": "checkout-web",
      "status": "regressed",
      "assigneeId": "<user-id>",
      "teamId": null,
      "overflow": false,
      "source": "source",
      "errorType": "ChunkLoadError",
      "message": "Loading chunk 482 failed.",
      "location": "src/router/lazy.ts:34 · loadChunk",
      "firstSeenAt": 1789300000000000,
      "lastSeenAt": 1790000000000000,
      "firstVersion": "2.2.0",
      "lastVersion": "2.4.1",
      "resolvedAt": 1789600000000000,
      "resolvedVersion": "2.3.0",
      "resolvedBy": "<user-id>",
      "regressedAt": 1789900000000000,
      "regressedVersion": "2.4.1",
      "regressedEnvironment": "production",
      "updatedBy": null,
      "updatedAt": 1789900000000000,
      "sessions": 612,
      "users": 498,
      "occurrences": 1530,
      "trend": [3, 5, 4, 9, 40, 120]
    }
  ],
  "total": 8
}
```

`regressedEnvironment` は、イシューの再発を引き起こしたエラーの環境です。そのエラーに環境の指定がなければ `null` です。イシューは、エラーが発生した環境に関係なく、アプリケーション全体に属します。サーバーは、環境ごとにイシューの初回発生時刻も記録します。 [アラートルール](/ja/rum/alerts#ルールの絞り込み)は、この時刻を使って環境ごとの新規イシューを集計します。

一覧では、セッション数（`sort` の指定によってはユーザー数または発生回数）の多い上位 250 件のイシューを取得し、`status`、`assignee`、 `team`、`search`、`fresh` で絞り込みます。`total` は、フィルター適用後、`limit` 適用前のイシュー数です。`trend` には、指定範囲を最大 12 個の等間隔の区間に分けた発生回数が、古い順に入ります。`overflow` は、アプリケーションが [1 時間に作成できるイシュー数の上限](/ja/rum/errors#1-時間あたりの新規イシュー数の上限)を超えた分のエラーを集計するイシューを示します。集計が制限時間を超えた場合やシステムがビジーの場合は、イシューを返さず、`unavailable` に `time_budget` または `busy` を設定します。

`GET /api/v1/rum/issues/{id}` は、一覧と同じ形式でイシューを返します。ただし、`trend` は含めず、`sessions`、`users`、`occurrences` は `from` と `to` の範囲で集計します。さらに、次の 2 つのフィールドを返します。

| フィールド | 内容 |
|---|---|
| `samples` | イシューが発生した直近 3 件のセッションを新しい順に返します。各要素には `timestamp`、`sessionId`、`userId`、`anonymousId`、`page`、`browser`、`system`、`version`、`hasReplay`、`retained` が含まれます。保存していないセッションのエラーでは `retained` が `false` になり、セッションを開けません。 |
| `stack` | フレームを含む最新のエラーのスタックです。どのエラーにもフレームがない場合は、最新のエラーを空の `frames` とともに返します。指定範囲内にイシューのエラーがなければ `null` です。`message`、`text`、`frames`、`symbolication`、`handling`、`isCrash`、`category` が含まれます。各フレームには、SDK が送信した `raw`、デバッグアーティファクトで復元した内容または `null` を示す `restored`、および `inApp` が含まれます。シンボリケーションを試行した場合、`symbolication` は `completed`、`partial`、`missing` のいずれかです。 |

イシューが存在しない場合は `404` を返します。

`PATCH /api/v1/rum/issues/{id}` は、`status`、`assigneeId`、`teamId` のうち指定したフィールドを更新し、更新後のイシューを返します。

```json
{ "status": "resolved", "assigneeId": "<user-id>", "teamId": null }
```

`status` には `open`、`investigating`、`resolved`、`ignored` を指定できます。解決済みのイシューが新しいバージョンで再発すると、ルールが `regressed` を設定します。`regressed` をリクエストで指定すると `400` を返します。`assigneeId` には組織のメンバーを、`teamId` には組織のチームを指定してください。`null` または空文字列を指定すると、担当者またはチームの割り当てを解除します。省略したフィールドは変更しません。イシューを解決すると `resolvedAt` と `resolvedBy` を記録し、アプリケーションの最新バージョンを `resolvedVersion` として記録します。ステータスを変更すると、以前の解決または再発の記録を終了します。変更対象のフィールドを指定しなければ `400` を返します。現在と同じ値を指定すると `200` を返し、何も変更しません。変更のたびに、監査ログに `rum.issue.update` を記録します。

## アラートルールをプレビューする

```http
POST /api/v1/rum/alerts/preview
```

[RUM 指標のアラートルール](/ja/rum/alerts)が直近の期間に参照したはずの値を、ウィンドウごとに取得します。取得には、ルールの評価と同じコードを使用します。`rum.events.read` 権限が必要です。

```json
{
  "query": { "applicationId": "checkout-web", "environment": "production", "page": "/checkout", "metric": "lcp_p75" },
  "periodSecs": 3600
}
```

| フィールド | 型 | 動作 |
|---|---|---|
| `query` | オブジェクト | 必須です。指標を指定します。`applicationId` と `metric` を指定し、必要に応じて `environment`、`page`、`version`、`minSamples` を指定します。指標を `page` や `version` で絞り込めない場合は、該当するフィールドを指定できません。カウントには `minSamples` を指定できません。`custom_vital` と `custom_timing` には、必須の `customName` と `statistic` も指定できます。`query` には `search` が必須です。`search` には `type`、入力どおりの `statement`、その解析結果である `filters` と `freeText`、および `measure`（`fn` と `field`）を指定します。[ルールを作成する](/ja/api/alerting/create-rule#rum-ルール)を参照してください。 |
| `periodSecs` | 整数 | 必須です。ルールを評価するウィンドウの長さを 60〜21,600 の範囲で指定します。各データポイントは 1 つのウィンドウに対応します。 |
| `from`, `to` | 整数 | Unix エポックからの経過時間をマイクロ秒で指定します。範囲はウィンドウ単位で読み取ります。`to` のデフォルトは現在時刻です。`from` のデフォルトは `to` の 6 時間前で、範囲が 12〜72 ウィンドウかつ 1 日以内に収まるように調整します。指定できる範囲は最大 360 ウィンドウです。 |

```json
{
  "metric": "lcp_p75",
  "unit": "milliseconds",
  "minSamples": 50,
  "periodSecs": 3600,
  "from": 1789956800000000,
  "to": 1790000000000000,
  "points": [
    { "at": 1789956800000000, "value": null, "samples": null },
    { "at": 1789960400000000, "value": 2480, "samples": 612 }
  ],
  "current": { "at": 1789996400000000, "value": 2310, "samples": 540 }
}
```

`unit` は `count`、`percent`、`milliseconds`、`score`、`bytes`、`none` のいずれかです。各データポイントの `at` にはウィンドウの開始時刻、`value` には指標の値が入ります。 `samples` には指標の算出に使った行数が入ります。行数が `minSamples` 未満のウィンドウには、`value` も `samples` も入りません。`current` は最後のデータポイントです。このデータポイントは `to` で終わるウィンドウに対応します。カウント処理が制限時間を超えた場合やシステムがビジーの場合は、データポイントを返さず、`unavailable` に `time_budget` または `busy` を設定します。アプリケーションが存在しない場合は `404`、ルールが指標に適合しない場合は `400` を返します。

## エラー

| ステータス | 原因 |
|---|---|
| `400` | パラメーター、フィルター、列、カーソルのいずれかがリクエストに適合していません。 |
| `401`, `403` | トークンが指定されていないか無効です。または、エンドポイントが要求する権限がトークンにありません。 |
| `404` | 行、セッション、またはアプリケーションが存在しません。 |
| `409` | 同じ識別子または名前を持つアプリケーションがすでに存在します。 |
| `413` | リクエストが [`events`](/ja/rum/events#イベントの送信) の上限を超えています。 |
