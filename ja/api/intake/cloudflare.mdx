```http
POST /api/v1/_cloudflare
```

NDJSON を受け付けます。Cloudflare Logpush が通常送信する gzip で圧縮されたリクエストボディにも対応します。このエンドポイントはベアラートークンを使用しません。種別が `cloudflare_logpush` のコネクターを作成し、16 文字以上の `pushToken` と `target_stream` を設定して、`X-Connector-Token` ヘッダーでトークンを送信します。クエリパラメーター `?token=` も使用できます。トークンが正しくない場合は `401` を返します。

各行を 1 件のログイベントとして `target_stream`（デフォルトは `cloudflare`）に取り込みます。各行のフィールドはそのまま保存し、受信時刻をイベント時刻として使用します。成功時は `204` を返します。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_cloudflare \
  -H 'X-Connector-Token: <pushToken>' \
  -H 'content-encoding: gzip' \
  --data-binary @logs.ndjson.gz
```
</RequestExample>

コネクターの設定については、[コネクター](/ja/connectors)を参照してください。

## 配信とストリームの選択を確認する

1. コネクターが有効になっており、送信側がそのコネクターのプッシュトークンを使用していることを確認します。通常の API トークンをプッシュトークンの代わりに使用することはできません。
2. コネクター API で `configJson` を直接設定する場合は、宛先ストリームに `targetStream` ではなく `target_stream` を使用します。トークンのキーは引き続きキャメルケースの `pushToken` を使用します。
3. 一意のマーカーを含むテストイベントを 1 件送信し、受信時刻を記録します。**ログ**で目的のストリームと受信時刻を含む時間範囲を選択し、マーカーを検索します。
4. リクエストが成功しても目的のストリームが空の場合は、対応するデフォルトストリームと、保存済みの宛先フィールドを確認します。HTTP の成功レスポンスだけで判断せず、目的のストリームをクエリして確認してください。

トークンは認証情報として保護してください。URL のクエリパラメーターで渡す場合は、トークンを含む完全な URL をログ、チケット、スクリーンショットに残さないでください。失敗したリクエストを再試行する前に、トークンやコネクターの状態に問題があるのか、ペイロードの形式や圧縮にエラーがあるのかを切り分けてください。
