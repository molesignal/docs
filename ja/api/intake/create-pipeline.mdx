```http
POST /api/v1/scheduled_pipelines
```

パイプラインを作成します。どのモードでも、パスには `scheduled_pipelines` という名前を使用します。この呼び出しには `pipelines.create` が必要です。

**ボディ**

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `name` | string | はい | パイプライン名です。 |
| `sourceStream` | string | はい | パイプラインが最初に読み取るストリームです。アラートパイプラインでは空文字列を指定します。 |
| `targetStream` | string | はい | パイプラインが最初に書き込むストリームです。スケジュール済みパイプラインで読み取り元のストリームを指定すると、`409` が返ります。アラートパイプラインでは空文字列を指定します。 |
| `functionSteps` | object | はい | ステップとモード、およびスケジュール済みパイプラインの設定またはアラートパイプラインの条件です。以下を参照してください。 |
| `cron` | string | はい | スケジュール済みパイプラインでは `every:30s`、`every:5m`、または `every:1h` を指定します。リアルタイムパイプラインまたはアラートパイプラインでは空文字列を指定します。 |
| `lookbackSecs` | integer | いいえ | スケジュールに従って読み取り元を初めて読み取る際に、何秒前までさかのぼるかを指定します。デフォルトは 300 です。スケジュール済みパイプラインでは正の値が必要です。 |
| `enabled` | boolean | いいえ | デフォルトは `true` です。 |

`functionSteps` のフィールド：

| フィールド | 備考 |
|---|---|
| `mode` | `scheduled`（デフォルト）、`realtime`、または `alert` を指定します。 |
| `signalType` | `logs`、`metrics`、`traces` のいずれかを指定します。リアルタイムパイプラインでは `profiles` も指定できます。メトリクス、トレース、プロファイルのリアルタイムパイプラインは、同じストリーム内でデータを変更します。`targetStream` は `sourceStream` と同じ値にし、ルーティングステップと `retainSource` は指定しません。[メトリクスとトレース](/ja/pipelines#メトリクスとトレース)を参照してください。プロファイルパイプラインの読み取り元は `default` です。[プロファイル](/ja/pipelines#プロファイル)を参照してください。アラートパイプラインでは指定しません。 |
| `steps` | 実行順に並べたステップです。VRL ステップには `transformName`、`script`、および `vrl` を指定した `kind` が必要です。ルーティングステップには、`builtin` を指定した `kind`、`route` を指定した `operation`、および `routing` オブジェクトが必要です。アラートパイプラインには最大 20 個のステップを指定できますが、ルーティングステップは指定できません。AI 要約ステップには、`transformName`、`ai_summary` を指定した `kind`、`prompt`、および回答を格納するアノテーションの `annotation`（デフォルトは `ai_summary`）を指定します。API 呼び出しステップには、`http_enrich` を指定した `kind` と、組織の HTTP コネクターを示す `connectorId` を指定します。クエリステップには、`query_enrich` を指定した `kind`、`language`（`sql` がデフォルト、または `promql`）、`stream`、`streamType`（`logs` がデフォルト、または `metrics`、`traces`）、`statement`、`windowSecs`（デフォルトは 300、最大 86400）、`maxRows`（デフォルトは 5、最大 50）、`annotation`（デフォルトは `query_result`）を指定します。[アラートパイプラインのステップ](/ja/pipelines/alert-events#ステップ)を参照してください。リアルタイムパイプラインでは、以下のフィールドを使用して、カウントを行う `generate_metric`、`quota`、`throttle` ステップも指定できます。 |
| `alert` | アラートパイプライン専用です。実行タイミング、条件、順序を指定します。`stage`（`open` がデフォルト、または `notify`）、`policies`（`notify` パイプラインが対象とする通知ポリシー。空の場合は、アラートイベントのすべてのポリシーが対象）、`sources`（`rule`、`external`、`synthetic`、`noData`。`notify` では `manual` も指定可能）、`severities`（`info`、`warning`、`error`、`critical`）、`labels`（イベントに必要なラベルとその値を指定するオブジェクト）、`order`（整数。デフォルトは 0）があります。`sources` または `severities` に空のリストを指定すると、該当するすべてのソースまたは重大度が対象になります。[アラートパイプライン](/ja/pipelines/alert-events#apiで作成する)を参照してください。 |
| `sources` | 読み取るストリームです。最初に `sourceStream` を読み取ります。スケジュール済みパイプラインでは、リスト内の残りのストリームもすべて読み取ります。指定できるのは合計で最大 8 個です。リアルタイムパイプラインでは `[source_stream]` のみ指定できます。 |
| `sinks` | 書き込み先のストリームです。先頭は `targetStream` です。リスト内の残りの各ストリームにもすべてのイベントを書き込みます。指定できるのは合計で最大 8 個です。リアルタイムパイプラインでは `[target_stream]` のみ指定できます。 |
| `sinkConnectors` | スケジュール済みパイプライン専用です。すべてのイベントを受信するコネクターの ID です。 |
| `sinkTables` | スケジュール済みパイプライン専用です。イベントごとに 1 行を書き込む拡張テーブルの名前です。最大 8 個まで指定できます。[拡張テーブルに書き込む](/ja/pipelines#拡張テーブルへの書き込み)を参照してください。 |
| `delaySecs` | スケジュール済みパイプライン専用です。遅れて到着するイベントを取り込めるよう、直近の時間範囲を読み取るまで待機する秒数です。範囲は 0～3600 で、デフォルトは 60 です。 |
| `retry` | スケジュール済みパイプライン専用です。`runRetries` は読み取りまたは書き込みに失敗した時間ウィンドウの再試行回数、`deliveryRetries` はコネクターへの配信の再試行回数です。いずれも範囲は 0～10 で、デフォルトは 3 です。 |
| `deadLetterStream` | スケジュール済みパイプライン専用です。処理、書き込み、または配信に失敗したイベントを格納するログストリームです。パイプラインの読み取り元や書き込み先のストリームは指定できません。 |
| `dedupeField` | スケジュール済みパイプライン専用です。同じ実行中にこのフィールドの値がすでに出現している場合、そのイベントを破棄します。 |
| `retainSource` | リアルタイムのログパイプライン専用です。元のイベントを読み取り元のストリームに保持します。 |

カウントを行うステップでは、`transformName` と `kind` に加えて、以下のフィールドを使用します。パイプライン内で同じステップ名を使用することはできません。[カウントと制限](/ja/pipelines#カウントと制限)を参照してください。

| フィールド | 備考 |
|---|---|
| `conditions` | ステップを適用するイベントの条件です。最大 16 個の条件を指定でき、イベントはそのすべてを満たす必要があります。各条件には `field`、`test`（`equals`、`not_equals`、`contains`、`starts_with`、`matches`、`exists`、`missing`、`gt`、`gte`、`lt`、`lte` のいずれか）、`value` を指定します。`gt`、`gte`、`lt`、`lte` は数値と比較し、`matches` は正規表現との一致を確認します。空の場合は、すべてのイベントが対象です。 |
| `metric` | `generate_metric` 専用です。`name`、`type`（`count`、`gauge`、または `histogram`）、`field`（ゲージとヒストグラムでは必須。カウントで指定すると値を合計）、`groupBy`（最大 10 フィールド）、`buckets`（ヒストグラムの上限値を昇順に 1～30 個指定）、`stream`（メトリクスストリーム）、`intervalSecs`（`10`、`30`、`60`、`300` のいずれか。デフォルトは `60`）を指定します。ログ、RUM、トレースのパイプラインでのみ使用できます。 |
| `quota` | `quota` 専用です。`unit`（`events` または `bytes`）、`limit`（指定した単位での 1 日あたりの上限。1～10^15）、`partitionBy`（最大 5 フィールド）、`overrides`（`{"values": {"<field>": "<value>"}, "limit": <n>}` を最大 100 個指定。`partitionBy` のすべてのフィールドに値が必要）、`action`（`drop` がデフォルト、または `pass`、`route`）、`target`（`route` の書き込み先となるログストリーム）を指定します。ログパイプラインと、`rum_views` および `rum_vitals` 以外の RUM ストリームでのみ使用できます。RUM では `route` を指定できません。 |
| `throttle` | `throttle` 専用です。`limit`（ウィンドウあたりのイベント数。1～1,000,000）、`windowSecs`（1～86,400）、`groupBy`（最大 5 フィールド）、`action`（`drop` がデフォルト、または `route`）、`target` を指定します。使用できるパイプラインは `quota` と同じです。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/scheduled_pipelines \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "normalize-app",
    "sourceStream": "app_raw",
    "targetStream": "app",
    "functionSteps": {
      "mode": "scheduled",
      "signalType": "logs",
      "sources": ["app_raw", "nginx_raw"],
      "sinks": ["app", "app_archive"],
      "delaySecs": 60,
      "retry": { "runRetries": 3, "deliveryRetries": 3 },
      "deadLetterStream": "pipeline_dead_letters",
      "steps": [
        { "transformName": "normalize-level", "kind": "vrl",
          "script": ".level = downcase!(string!(.level))" }
      ]
    },
    "cron": "every:5m",
    "lookbackSecs": 300,
    "enabled": true
  }'
```
</RequestExample>

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | 次のいずれかに該当します。スケジュールが `every:Ns/m/h` 形式ではない、ルックバックが 0 以下、プロファイルにスケジュール済みパイプラインを設定している、プロファイルパイプラインのストリームが `default` ではない、メトリクス、トレース、プロファイル、RUM のリアルタイムパイプラインが別のストリームに書き込むか、ルーティングするか、元のイベントを読み取り元に保持する、そのようなパイプラインのステップがサンプルの[保持対象フィールド](/ja/pipelines#メトリクスとトレース)を変更する、`rum_views` または `rum_vitals` のイベントを破棄できるステップがある、VRL ステップをコンパイルできない、ストリーム名が無効、読み取り元または書き込み先のストリームが 8 個を超えるか、拡張テーブルが 8 個を超える、ルーティングステップの固定ストリームまたはフォールバックストリームが読み取り元と同じ、デッドレターストリームがパイプラインの読み取り元または書き込み先と同じ、[RUM ストリーム](/ja/pipelines#rum-ストリーム)を書き込み先またはルーティング先に指定している、リアルタイムパイプラインの読み取り元に `rum_sessions` を指定している、[プラットフォームストリーム](/ja/pipelines#プラットフォームストリーム)を書き込み先、ルーティング先、またはリアルタイムでの変更対象に指定している、`delaySecs` または再試行回数が範囲外です。アラートパイプラインでは、ソースまたは重大度が不明、ルーティングステップがある、AI 要約ステップにプロンプトがない、API 呼び出しステップのコネクターが組織の HTTP コネクターではない、クエリステップが単一のクエリではないか、`_audit` を読み取るか、文字列の外にプレースホルダーがあるか、イベントに存在しない値をプレースホルダーで参照している、`notify` パイプラインに MoleSignal の外部にアクセスするステップがある、`open` パイプラインに `policies` またはソース `manual` を指定している、ステップが 20 個を超える場合にもこのエラーが発生します。また、`generate_metric`、`quota`、`throttle` のいずれかのステップをスケジュール済みパイプラインやアラートパイプラインで使用するか、非対応のデータに適用する場合、これらのステップの名前が重複する場合、設定値が許容範囲外の場合にも発生します。無効な設定の例として、PromQL で選択できないメトリクス名、すべてのメトリクスサンプルに存在するラベル（`value`、`le`、`metric_name` など）、読み取り元のストリームと同じ `target` があります。 |
| `403` | パイプラインが `_audit` を読み取りますが、トークンに `audit.read` 権限がないか、トークンがサービスアカウントに属しています。 |
| `409` | スケジュール済みパイプラインが読み取り元のストリームに書き込もうとしています。または、同じ種類のデータと同じ読み取り元のストリームに対して、別のリアルタイムパイプラインがすでに有効です（`a realtime pipeline is already enabled for this <signal> stream`）。 |

リアルタイムモード、ルーティングステップ、読み取り位置、再試行については、[パイプライン](/ja/pipelines)を参照してください。
