OpenTelemetry SDK または Collector を MoleSignal に向けます。どちらのトランスポートでも、シグナルの書き込み権限を持つベアラー資格情報が必要です: `logs.write`、`metrics.write`、または `traces.write`。

| トランスポート | エンドポイント |
|---|---|
| OTLP（HTTP） | `POST /api/v1/logs`、`POST /api/v1/metrics`、`POST /api/v1/traces` |
| OTLP（gRPC） | `:4317` |

ポート `5082` は信頼された内部クラスタポートであり、OTLP レシーバーではありません。

## OTLP（HTTP）

エクスポーターのエンドポイントには `/api` ベースパスを設定します。`/v1/logs`、`/v1/metrics`、`/v1/traces` はエクスポーター自身が付加します。

| ヘッダー | 備考 |
|---|---|
| `Authorization` | `Bearer <token>`。 |
| `Content-Type` | `application/x-protobuf` または `application/json`。JSON エンコーディングは 64 ビット整数を文字列として書き出しますが、MoleSignal は文字列と数値のどちらも読み取ります。 |
| `stream-name` | 任意。対象のストリーム。デフォルトは `default` です。 |

ボディは圧縮してはいけません。圧縮されたボディには `400` を返します。エクスポーターで圧縮を無効にしてください。ボディの上限は 2 MiB です。リクエストが成功すると `200` と `{"partialSuccess":null}` を返します。値がフィールドの型に合わないためにストリームが一部のログレコードやデータポイントを拒否した場合、それ以外は書き込まれ、`partialSuccess` に `rejectedLogRecords` または `rejectedDataPoints` が入り、最初の理由を示す `errorMessage` が付きます。エクスポーターはこれらを再試行しません。gRPC でも同じ応答を返します。

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP（gRPC）

`:4317` のレシーバーは、TLS なしで logs、metrics、traces、profiles の各サービスを提供します。`authorization: Bearer <token>` と任意の `stream-name` を gRPC メタデータとして送信します。信頼されたネットワークを出るトラフィックでは、ポートの手前で TLS を終端してください。

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## 保存されるフィールド

リソース属性とレコード属性は、元のキーのままトップレベルのフィールドになります。logs、spans、metrics のカラムについては「[保存されるフィールド](/ja/query#保存されるフィールド)」を参照してください。

## エラー

| ステータス | 原因 |
|---|---|
| `400` | 圧縮されたボディ、または有効な OTLP でないボディ。 |
| `401` | トークンが欠落しているか無効。 |
| `403` | トークンにシグナルの書き込み権限がない、またはデータが[プラットフォームストリーム](/ja/streams#プラットフォームストリーム)に送信されている。 |
| `404` | エクスポーターのエンドポイントに `/api` がないため、リクエストが `/v1/logs` に到達している。 |
| `413` | ボディが 2 MiB を超えている。 |

gRPC では、HTTP が `403` で拒否するリクエストに対して `PERMISSION_DENIED` を返します。
