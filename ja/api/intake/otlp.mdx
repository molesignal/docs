OpenTelemetry SDK または Collector の送信先に MoleSignal を指定します。どちらのトランスポートでも、対象のシグナルに対応する書き込み権限（`logs.write`、`metrics.write`、`traces.write` のいずれか）を持つ Bearer トークンが必要です。

| トランスポート | エンドポイント |
|---|---|
| HTTP 経由の OTLP | `POST /api/v1/logs`, `POST /api/v1/metrics`, `POST /api/v1/traces` |
| gRPC 経由の OTLP | `:4317` |

ポート `5082` は信頼されたクラスター内部用のポートで、OTLP の受信には使用しません。

## HTTP 経由の OTLP

エクスポーターのエンドポイントには、ベースパス `/api` を指定します。エクスポーターは `/v1/logs`、`/v1/metrics`、`/v1/traces` を自動で追加します。

| ヘッダー | 補足 |
|---|---|
| `Authorization` | `Bearer <token>` を指定します。 |
| `Content-Type` | `application/x-protobuf` または `application/json` を指定します。JSON では 64 ビット整数を文字列としてエンコードします。MoleSignal は文字列と数値の両方を読み取れます。 |
| `stream-name` | オプションです。送信先のストリームを指定します。デフォルトは `default` です。 |

リクエストボディは圧縮しないでください。圧縮したボディを送信すると、MoleSignal は `400` を返します。エクスポーターで圧縮を無効にしてください。ボディの上限は 2 MiB です。リクエストが成功すると、MoleSignal は `200` と `{"partialSuccess":null}` を返します。

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## gRPC 経由の OTLP

`:4317` のレシーバーは、ログ、メトリクス、トレース、プロファイルの各サービスを TLS なしで提供します。gRPC メタデータとして `authorization: Bearer <token>` を送信します。必要に応じて `stream-name` も指定します。信頼されたネットワークの外に出るトラフィックについては、このポートの手前で TLS を終端してください。

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## 保存されるフィールド

リソースとレコードの属性は、元のキーを保持したままトップレベルのフィールドになります。ログ、スパン、メトリクスの列については、[保存されるフィールド](/ja/query#保存されるフィールド)を参照してください。

## エラー

| ステータス | 原因 |
|---|---|
| `400` | ボディが圧縮されているか、有効な OTLP 形式ではありません。 |
| `401` | トークンが指定されていないか、無効です。 |
| `403` | トークンに対象のシグナルへの書き込み権限がないか、データの送信先が[プラットフォームストリーム](/ja/streams#プラットフォームストリーム)です。 |
| `404` | エクスポーターのエンドポイントに `/api` が含まれていないため、リクエストが `/v1/logs` に送信されます。 |
| `413` | ボディが 2 MiB を超えています。 |

HTTP で `403` になるリクエストに対して、gRPC では `PERMISSION_DENIED` を返します。
