```http
POST /api/v1/functions
```

パイプラインで再利用できる変換関数を作成します。関数の作成時に VRL と JavaScript のソースをコンパイルし、ソースが無効な場合は作成を拒否します。どちらのランタイムもバイナリに組み込まれています。この呼び出しには `functions.create` 権限が必要です。

**ボディ**

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `name` | string | はい | 関数名です。 |
| `language` | string | はい | `vrl`、`js`、または `llm` を指定します。`llm` 関数を使用するには、`[functions].llm_eval_enabled` を有効にし、モデルプロバイダーを設定する必要があります。 |
| `source` | string | はい | VRL または JavaScript のソース、もしくは `llm` 関数への指示です。 |
| `paramsSchema` | object | いいえ | パラメーターです。`llm` の場合は、`outputField` で出力フィールドを指定します。デフォルトは `_llm_eval` です。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/functions \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "lowercase-level",
    "language": "vrl",
    "source": ".level = downcase!(string!(.level))"
  }'
```
</RequestExample>

構文エラーがある場合は、`js syntax error: Uncaught SyntaxError: Unexpected token '}'` などのエラーメッセージとともに `400` を返します。保存する前に `POST /api/v1/functions/run` でソースをテストしてください。このエンドポイントは `language`、`source`、サンプルの `input` を受け取り、`output` を返します。[関数](/ja/functions)を参照してください。

関数のその他のルートは、`GET /api/v1/functions` と、`/api/v1/functions/{id}` に対する `GET`、`PUT`、`DELETE` です。組み込みプリセットは読み取り専用です。

## 保存前に変換をテストする

ドライランのエンドポイントには `functions.run` 権限が必要です。`functions.create` は別の権限です。本番の取り込み処理に変換を追加する前に、フィールドが欠落している場合や形式が不正な場合も含め、代表的な入力でテストしてください。

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".level = downcase!(string!(.level))","input":{"level":"ERROR","message":"example"}}'
```

この入力では、`output.level` が `error` になり、変換対象外の `message` フィールドが保持され、`dropped` が `false` になることを確認してください。コンパイルに成功しても、すべての本番イベントが変換の前提条件を満たすとは限りません。たとえば、上記の文字列変換は失敗する可能性があり、`level` が文字列である必要があります。

## 関数をパイプラインに追加する

関数を作成すると再利用可能な定義が保存されますが、受信イベントが自動的に変換されるわけではありません。返された関数 ID を保存し、[パイプライン](/ja/pipelines)で使用する関数をステップとして追加してください。本番ストリームで有効にする前に、パイプライン全体をテストしてください。

代表的な入力と期待する出力を、変更内容と一緒に保存してください。パイプラインを有効にしたら、内容が既知のテストイベントを取り込み、出力先ストリームをクエリして、保存されたフィールドを確認してください。ドライランのレスポンスだけでは、デプロイ済みの取り込み経路が正しく動作するかどうかは確認できません。

## よくある問題

| 症状 | 対処 |
|---|---|
| 関数名が空です | `name` に空でない値を指定してください。 |
| 作成時にソースが拒否されます | 構文エラーやコンパイルエラーを修正してから、再試行してください。 |
| ドライランが拒否されます | `functions.run` 権限を確認してください。関数の作成権限とは別です。 |
| 入力の処理時にエラーが発生します | エラーが発生したフィールドの構造をドライランで再現し、フィールドが存在しない場合や型が異なる場合を処理してください。 |
| 保存した関数が新しいログに適用されません | パイプラインに関数が追加されていることと、出力先ストリームを確認してください。 |
