```http
POST /api/v1/_kinesis_firehose
```

AWS Data Firehose の HTTP エンドポイント配信を受け付けます。このエンドポイントは Bearer トークンを使用しません。種類が `aws_kinesis_firehose` のコネクターを作成し、16 文字以上の `pushToken` と `target_stream` を設定します。Firehose には、このトークンをアクセスキーとして設定します。エンドポイントは `X-Amz-Firehose-Access-Key` からトークンを読み取ります。`X-Connector-Token` と `?token=` でもトークンを指定できます。トークンが正しくない場合は `401` を返します。

各レコードには base64 でエンコードされた `data` が含まれます。エンドポイントはデータをデコードして行に分割し、空でない各行を `target_stream`（デフォルトは `kinesis`）のログイベントに変換します。JSON オブジェクトを含む行はフィールドに展開し、プレーンテキストの行は `message` フィールドに格納します。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_kinesis_firehose \
  -H 'X-Amz-Firehose-Access-Key: <pushToken>' \
  -H 'content-type: application/json' \
  -d '{"requestId":"req-1","timestamp":1790000000000,"records":[{"data":"eyJsZXZlbCI6ImluZm8ifQo="}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{ "requestId": "req-1", "timestamp": 1790000000123 }
```
</ResponseExample>

Firehose の要件に従い、レスポンスにはリクエストと同じ `requestId` とミリ秒単位の `timestamp` が含まれます。コネクターの設定方法は、[コネクター](/ja/connectors)を参照してください。

## 配信とストリームの選択を確認する

1. コネクターが有効で、送信元がそのコネクターのプッシュトークンを使用していることを確認します。通常の API トークンはプッシュトークンの代わりにはなりません。
2. コネクター API で `configJson` を直接設定する場合は、宛先ストリームのキーに `targetStream` ではなく `target_stream` を使用します。トークンのキーはキャメルケースの `pushToken` のままです。
3. 一意のマーカーを含むテストイベントを 1 件送信し、受信時刻を記録します。**ログ**で目的のストリームと受信時刻を含む時間範囲を選択し、マーカーを検索します。
4. リクエストが成功しても目的のストリームが空の場合は、対応するデフォルトストリームと、保存済みの宛先フィールドの値を確認します。HTTP の成功応答だけでは、目的のストリームへの配信は確認できません。目的のストリームを検索して確認してください。

トークンは認証情報として保護してください。URL のクエリパラメーターで渡す場合は、完全な URL をログ、チケット、スクリーンショットに残さないでください。失敗したリクエストを再試行する前に、トークンやコネクターの状態に問題があるのか、ペイロードの形式や圧縮に問題があるのかを切り分けてください。
