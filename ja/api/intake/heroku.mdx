```http
POST /api/v1/_heroku
```

テキスト形式のログドレインのリクエストボディを受け付けます。このエンドポイントではベアラートークンを使用しません。種類が `heroku_drain` のコネクターを作成し、16 文字以上の `pushToken` と `target_stream` を設定してください。Heroku ではカスタムヘッダーを設定できないため、URL の `?token=` でトークンを渡します。`X-Connector-Token` ヘッダーでも渡せます。トークンが正しくない場合は `401` を返します。

各行を `target_stream`（デフォルトは `heroku`）のログイベント 1 件として取り込みます。行全体を `message` フィールドに保存し、`source` フィールドを `heroku` に設定します。処理が成功すると、エンドポイントは `204` を返します。

<RequestExample>
```bash Heroku CLI
heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
```
</RequestExample>

コネクターの設定方法は、[コネクター](/ja/connectors)を参照してください。

## 配信とストリームの選択を確認する

1. コネクターが有効で、送信元がそのコネクターのプッシュトークンを使用していることを確認してください。通常の API トークンでプッシュトークンを代用することはできません。
2. コネクター API で未加工の `configJson` を設定する場合、送信先ストリームには `targetStream` ではなく `target_stream` を使用してください。トークンのキーはキャメルケースの `pushToken` のままです。
3. 一意のマーカーを含むテストイベントを 1 件送信し、受信時刻を記録してください。**ログ**で目的のストリームと受信時刻を含む時間範囲を選択し、マーカーを検索してください。
4. リクエストが成功しても目的のストリームが空の場合は、該当するデフォルトストリームと、保存済みの送信先フィールドを確認してください。HTTP の成功応答だけでは配信先を確認できません。目的のストリームを検索してください。

トークンは認証情報として保護してください。URL のクエリパラメーターで渡す場合は、完全な URL がログ、チケット、スクリーンショットに含まれないようにしてください。失敗したリクエストを再試行する前に、トークンやコネクターの状態に問題があるのか、ペイロードの形式や圧縮に問題があるのかを切り分けてください。
