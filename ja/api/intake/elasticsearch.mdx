```http
POST /api/v1/_bulk
```

Filebeat、Logstash、および Vector の `elasticsearch` sink 向けの、Elasticsearch `_bulk` 互換 NDJSON 取り込みです。この呼び出しには `logs.write` が必要です。`Content-Encoding: gzip` を指定したボディを受け付けます。

| アクション | 処理 |
|---|---|
| `index`、`create`、`update` | ソースドキュメントはログイベントとして保存されます。 |
| `delete` | レスポンス項目を返さずにスキップされます。このエンドポイントを通じてテレメトリが削除されることはありません。 |

アクションの `_index` は対象のログストリームを選択します。指定がない場合は `stream-name` ヘッダーが適用され、その次に `default` が適用されます。

ストリーム内のフィールドの型に合わない値を持つドキュメントは、そのドキュメントだけが拒否されます。その項目は `status: 400` となり、`reason` を含む `error` が付き、`errors` は `true` になり、他のドキュメントは書き込まれます。Filebeat と Logstash はそのような項目を再試行しません。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```
</RequestExample>

<ResponseExample>
```json 200
{ "took": 0, "errors": false, "items": [ { "index": { "status": 201 } } ] }
```
</ResponseExample>

## このエンドポイントを使う場面

既存の送信元が Elasticsearch の bulk NDJSON を出力できる場合は、このエンドポイントを使用します。これは取り込みアダプターであり、Elasticsearch クラスターではありません。検索、インデックステンプレート、ドキュメント ID、インプレース更新のセマンティクスは、この API では提供されません。保存されたイベントを読み取るには、[SQL クエリ](/ja/query)を使用します。

## 有効なバッチを構築する

- `index` または `create` の各操作について、アクションオブジェクトとドキュメントオブジェクトを別々の行に送信します。バッチは改行で終了します。
- `update` の場合は、イベントのフィールドを `doc` の下に配置します。これらのフィールドは保存済みのイベントを変更するのではなく、新しいイベントになります。
- ストリームを選択するには、アクションに `_index` を設定します。それ以外の場合は `stream-name` を使用するか、`default` ストリームを受け入れます。
- イベントの時刻を保持する場合は、`_timestamp` をマイクロ秒単位の整数の Unix タイムスタンプとして指定します。それ以外の場合、レシーバーは現在時刻を使用します。
- `delete` アクションはスキップされます。テレメトリは削除されず、レスポンスに保存済みイベントの項目も追加されません。

## 取り込みを検証する

1 イベントのバッチでは、`errors: false` と、`status: 201` を持つ 1 つのレスポンス項目が返されることを確認します。項目数を、取り込みを意図したイベント数と比較します。HTTP の成功だけでは、バッチが意図どおりに構築されたことは証明されません。

**ログ**を開き、`_index` で選択したストリームを選び、イベントのタイムスタンプを含む時間範囲を指定します。サンプルから特徴的なフィールドをクエリします。イベントが見つからない場合は、バッチ全体を再送する前に、ストリームの選択とタイムスタンプの単位を確認します。このインターフェースは、再試行の重複排除に Elasticsearch のドキュメント ID を使用しません。

## 拒否されたリクエストをトラブルシューティングする

| 症状 | 確認内容 |
|---|---|
| 認証エラーまたは権限エラー | 対象の組織の、`logs.write` を持つ API トークンを使用します。 |
| アクションまたはドキュメントが JSON オブジェクトではない | NDJSON の行の区切りを確認します。JSON 配列や、整形された複数行のオブジェクトを送信しないでください。 |
| 不明なアクション | 上記のサポートされているアクション名を使用します。 |
| 圧縮解除エラー | ボディが実際に圧縮されている場合にのみ `Content-Encoding: gzip` を設定します。 |
| 成功したがイベントが想定より少ない | すべての書き込みアクションに対応するドキュメント行があることを確認し、スキップされた `delete` と保存されたイベントを区別します。 |
| ステータス `400` の項目を伴う `errors: true` | ストリーム内のフィールドの型に値が合っていません。たとえば `int64` フィールドにテキストが入っている場合です。項目の `reason` にフィールド名が示されます。ストリームがそのフィールドに保存する型で送信するか、パイプラインで変換します。 |
