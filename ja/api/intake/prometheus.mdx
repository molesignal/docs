```http
POST /api/v1/prometheus/api/v1/write
```

Prometheus と VictoriaMetrics の `remote_write` バージョン 1 リクエスト（snappy で圧縮された protobuf）を受け付けます。この呼び出しには `metrics.write` が必要で、成功時は `204` を返します。値がフィールドの型に適合しないためにストリームが一部のサンプルを拒否した場合、他のサンプルは書き込まれ、応答は `400` となり、拒否されたサンプル数と最初の理由が示されます。Prometheus は `400` を再試行しません。

リクエストは `stream-name` ヘッダーで指定されたメトリクスストリームに書き込まれます。ヘッダーがない場合、ストリーム名は `default` です。メトリクスストリームは 1 つのソースのメトリクスを保持します。`__name__` ラベルは `metric_name` フィールドになり、残りのラベルはフィールドになり、サンプルは `value` フィールドになります。`metric_name` や `metric_kind` など、メトリクスフィールドと同じ名前のラベルは、`exported_<name>` として保持されます。ネイティブヒストグラムとメトリクスメタデータはスキップされ、エグザンプラーはサンプルとともに保存されます。

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

どのストリームに保持されていても、メトリクスを名前で PromQL を使ってクエリします。ラベル `service` と `status` を持つ `http_requests_total` のシリーズは次のようになります:

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**制限**はシリーズごとおよび組織ごとに適用されます。シリーズあたり最大 64 個のラベル、ラベル名は 128 バイトまで、ラベル値は 2048 バイトまで、アクティブシリーズと新規シリーズにはカーディナリティ制限があります。プロセス制限は [設定](/ja/configuration#インテーク) の `[intake.prometheus]` です。組織とそのメトリクス 1 つあたりのアクティブシリーズは、プラットフォーム設定 **設定 → メトリクスのカーディナリティ** により制限されます。この設定は `GET /api/v1/settings/series_limits` で読み取り、同じボディ `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }` を指定した `PUT` で設定し、どちらもシステムスコープの `sys.settings.limits.manage` が必要です。メトリクスの制限は組織の制限以下で、どちらも最大 100,000,000 です。
