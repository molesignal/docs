```http
POST /api/v1/prometheus/api/v1/write
```

Prometheus と VictoriaMetrics の `remote_write` バージョン 1 リクエストを受け付けます。リクエストは Snappy で圧縮した protobuf 形式です。呼び出しには `metrics.write` が必要で、成功すると `204` を返します。

`stream-name` ヘッダーで指定したメトリクスストリームにリクエストを書き込みます。ヘッダーがない場合は `default` に書き込みます。1 つのメトリクスストリームには、1 つのソースのメトリクスを格納します。`__name__` ラベルは `metric_name` フィールドに、残りのラベルはそれぞれのフィールドに、サンプルは `value` フィールドになります。`metric_name` や `metric_kind` など、メトリクスのフィールドと同名のラベルは `exported_<name>` として保持します。ネイティブヒストグラムとメトリクスのメタデータはスキップし、エグザンプラーはサンプルとともに保存します。

<RequestExample>
```yaml prometheus.yml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
    headers:
      stream-name: prod
```
</RequestExample>

メトリクスがどのストリームにあっても、メトリクス名を指定して PromQL でクエリできます。`service` と `status` のラベルが付いた `http_requests_total` の時系列は、次のようになります。

```json
{
  "columns": ["value", "service", "status"],
  "rows": [[25.0, "checkout", "200"]],
  "scannedRows": 1,
  "tookMs": 154
}
```

**制限**は時系列単位および組織単位で適用します。1 時系列あたりのラベル数は最大 64 個、ラベル名は最大 128 バイト、ラベル値は最大 2048 バイトです。アクティブな時系列と新規の時系列にはカーディナリティの上限があります。プロセス単位の制限は、[設定](/ja/configuration#インテーク)の `[intake.prometheus]` で指定します。組織全体と組織内のメトリクスごとのアクティブな時系列数は、プラットフォームの **設定 → メトリクスのカーディナリティ** で制限します。設定の取得には `GET /api/v1/settings/series_limits` を使い、更新には同じパスに `PUT` で同じ形式のボディ `{ "max_active_series_per_org": 200000, "max_active_series_per_metric": 100000 }` を送信します。どちらの操作にも、システムスコープの `sys.settings.limits.manage` が必要です。メトリクスごとの上限は組織全体の上限以下で、どちらも最大 100,000,000 です。
