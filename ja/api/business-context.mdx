```http
GET /api/v1/business-context
PUT /api/v1/business-context
```

テナント、プラン、実験グループなどのビジネスキーと、それぞれをスパン、ログ、RUM イベントで保持するフィールドです。[ビジネスコンテキスト](/ja/business-context)を参照してください。読み取りには次の権限のいずれかが必要です: `apm.services.read`、`traces.read`、`logs.read`、`rum.events.read`、`apm.settings.read`、または `sys.telemetry.read` です。設定には `apm.settings.manage` が必要で、アクティビティログに記録されます。

## キーを設定する

`PUT` はすべてのキーを置き換えます。空のフィールドは何も指定せず、空の `label` はキーになり、重要な値はトリミングされ、それぞれ 1 回だけ一覧表示されます。応答は保存された内容です。

| フィールド | 注意事項 |
|---|---|
| `key` | 小文字の英字で始まり、小文字の英字、数字、`_` のみを使用できます。最大 64 文字です。一意である必要があります。 |
| `label` | 閲覧者に表示される名前です。最大 80 文字です。 |
| `span` | スパン属性です。トレースストリームでそのフィールドを指定する名前です。 |
| `log` | ログフィールドです。 |
| `rum` | RUM フィールドです。含まれる JSON フィールドのキーで、たとえば `context.tenant` です。 |
| `important` | 最も重要な値です。最大 50 個で、それぞれ最大 200 文字です。 |

キーは `span`、`log`、`rum` の少なくとも 1 つを指定します。最大 8 個のキーを設定できます。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/business-context \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"keys":[{"key":"tenant","label":"Tenant","span":"tenant.id","log":"tenant_id","rum":"context.tenant","important":["acme"]}]}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "keys": [
    {
      "key": "tenant",
      "label": "Tenant",
      "span": "tenant.id",
      "log": "tenant_id",
      "rum": "context.tenant",
      "important": ["acme"]
    }
  ]
}
```
</ResponseExample>

**エラー**

| ステータス | 理由 |
|---|---|
| `400` | キーの名前が不適切か重複している、フィールドを指定していない、または許可されている数を超えるキーや値がある場合です。 |
| `403` | トークンにこの呼び出しの権限がありません。 |
