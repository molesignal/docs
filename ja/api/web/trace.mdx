すべての呼び出しは、組織の1つのトレースストリームを読み取ります。そのストリームは、`trace_id`、`span_id`、`service.name`、`name`、`start_time_unix_nano`、`end_time_unix_nano`、`status_code` のすべてのフィールドを持ちます。`default` という名前のストリームは、条件を満たす他のストリームより優先され、残りの同順位はストリーム名で解決されます。そのようなストリームがない組織では、空の結果が返ります。[テールサンプリング](/ja/configuration#トレースのキャプチャとテールサンプリング) を通過したトレースのみ読み取り可能です。

すべての呼び出しには `traces.read`、またはシステムスコープの `sys.telemetry.read` が必要です。

## トレースサマリーを一覧表示する

```http
GET /api/v1/web/traces
```

トレースごとに1つのサマリーを、カーソルページネーションで返します。まだトレースサマリーがないストリームは、空のページを返します。

**クエリパラメータ**

| パラメータ | 型 | 備考 |
|---|---|---|
| `from`, `to` | 整数 | マイクロ秒単位のウィンドウ。デフォルトは現在までの直近24時間です。`to` は `from` より大きい必要があります。 |
| `q` | 文字列 | スパンの `trace_id`、`span_id`、サービス、オペレーション、ステータスのいずれかに含まれる必要がある、大文字と小文字を区別しないテキスト。最大256文字。 |
| `filters` | 文字列 | フィルタの JSON 配列。以下を参照してください。 |
| `where` | 文字列 | JSON 条件ツリー。フィルタとテキストを AND と OR で結合します。以下を参照してください。 |
| `expression` | 文字列 | **トレース**ページが書き出すフィールドクエリ。`q`、`filters`、`where` を表すため、いずれか一方を送信します。以下を参照してください。 |
| `sort` | 文字列 | `latest`（デフォルト）、`earliest`、`duration_desc`、`duration_asc`、`span_count_desc`、`errors_desc`。 |
| `limit` | 整数 | ページサイズ。デフォルトは `20`。値は1から5000にクランプされます。 |
| `cursor` | 文字列 | 以前のページの `nextCursor` または `previousCursor`。 |
| `fields` | 文字列 | 各トレースとともに返す、そのルートスパンのフィールド。カンマ区切りで、ストリームでの名前を指定します。最大12個。不明なフィールド、JSON フィールド、`molesignal.trace.*` フィールドは `400` を返します。 |

フィルタは `field`、`op`、`value` を持つオブジェクトで、1つのリクエストに最大32個のフィルタを含められます。すべてのフィルタに一致する必要があります。演算子 `in` は `value` の代わりに、値のリストである `values` を取ります。

| フィールド | 型 | 演算子 |
|---|---|---|
| `trace_id` | テキスト | `=`, `!=`, `contains`, `in` |
| `duration_ns`, `span_count`, `error_count` | 整数 | `=`, `!=`, `>`, `>=`, `<`, `<=`, `in` |
| トレースストリームのその他のスカラーフィールド | フィールドの型による | テキスト: `=`, `!=`, `contains`, `in`。数値とタイムスタンプ: `=`, `!=`, `>`, `>=`, `<`, `<=`, `in`。ブール値: `=`, `!=`, `in`。 |

フィルタは、`service.name` や `name` など、ストリームでの名前でフィールドを指定します。他の名前がフィールドを表すことはありません。演算子 `eq`、`ne`、`like` は `=`、`!=`、`contains` の別名です。JSON フィールドはフィルタできません。

`trace_id`、`duration_ns`、`span_count`、`error_count` はトレース上で比較されます。その他のフィールドはスパンに属します。そのフィールドに対するフィルタは、いずれかのスパンがそのフィルタを満たすとトレースに一致し、`!=` はどのスパンもその値を持たない場合にトレースに一致します。フィールドを持たないスパンは、その値を持ちません。

`in` は `values` のいずれかに一致します。値は1から64個で、それぞれ最大512バイトで、フィールドの型に従います。2回指定された値は1回として数えます。スパンフィールドでは、`in` はいずれかのスパンが値のいずれかを持つ場合にトレースに一致します。

`where` は、フィルタのリストでは表現できないもの、つまり選択肢を指定します。4つの形式のいずれかの JSON オブジェクトです。

| 形式 | 一致条件 |
|---|---|
| `filters` と同様のフィルタ | そのフィルタ。 |
| `{"text": "..."}` | `q` と同様に一致するテキスト。 |
| `{"and": [...]}` | リスト内のすべての条件。 |
| `{"or": [...]}` | リスト内のいずれかの条件。 |

`filters`、`q`、`where` は同時に適用されます。ツリー内のフィルタはその意味を保ちます。スパンフィールドに対するフィルタは、いずれかのスパンがそれを満たすとトレースに一致し、`!=` はどのスパンもその値を持たない場合に一致します。トレースは `{"or": [A, B]}` に、`A` または `B` に一致する場合に一致します。`filters` と `where` のフィルタは合算して32個の上限に数えられます。ツリーはテキストを最大8回検索し、グループを最大8階層までネストし、各グループに少なくとも1つの条件を持ちます。

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'filters=[{"field":"status_code","op":"=","value":"ERROR"}]' \
  --data-urlencode 'where={"or":[{"field":"service.name","op":"=","value":"checkout"},{"field":"span_count","op":">","value":"50"}]}'
```

このリクエストは、`checkout` というスパンを持つ、またはスパン数が50を超える失敗したトレースを一覧表示します。

`expression` は代わりに、**トレース**ページのテキストを受け取ります。`=`、`!=`、`>`、`>=`、`<`、`<=`、`contains`、`field in ('a', 'b')` による比較、検索する単語、引用符で囲んだフレーズ、大文字と小文字を問わない `AND` と `OR`（`AND` の方が強く結合）、および括弧です。サーバーはこれを、ページが送信する `q`、`filters`、`where` に変換し、上記と同様に検証します。テキストは最大8 KiBで、括弧のネストは最大32階層です。閉じられていない括弧や比較対象のない比較など、読み取れない部分があると、`400` を返し、その部分を示します。

```bash
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "expression=status_code = 'ERROR' AND (service.name = 'checkout' OR span_count > 50)"
```

このリクエストは、上記と同じトレースを一覧表示します。

`cursor` は、ページをそれを発行したクエリに結び付けます。カーソルと異なる `limit`、`sort`、`q`、`filters`、`where` を指定してリクエストを繰り返すと、`400` を返します。

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'sort=duration_desc' \
  --data-urlencode 'limit=2' \
  --data-urlencode 'fields=http.route' \
  --data-urlencode 'filters=[{"field":"service.name","op":"in","values":["checkout","payments"]}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "service": "checkout",
      "operation": "GET /checkout",
      "startNs": 1790000000000000000,
      "durationMs": 180.0,
      "spanCount": 3,
      "errorCount": 1,
      "status": "ERROR",
      "httpStatusCode": 502,
      "fields": { "http.route": "/checkout" }
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

各項目は、トレースをそのルートに基づいて説明します。ルートスパンの `service` と `operation`、ナノ秒単位の開始時刻、ミリ秒単位の所要時間、スパン数、エラースパン数です。`nextCursor` が設定されている場合、`hasMore` は `true` です。

| フィールド | 備考 |
|---|---|
| `status` | ルートスパンのステータス: `OK`、`ERROR`、`UNSET`。 |
| `httpStatusCode` | ルートスパンが100〜599のコードを保持している場合の、その `http.response.status_code` または `http.status_code`。それ以外の場合、およびサマリーがこの値を保持する前に保存されたトレースでは存在しません。 |
| `fields` | `fields` で要求されたフィールドのうち、ルートスパンが値を持つもの。値がない場合は存在しません。読み取りに失敗した場合、ページはこれらのフィールドなしで返されます。 |

## トレースを時系列でカウントする

```http
GET /api/v1/web/traces/histogram
```

リストクエリに一致するすべてのトレースを、トレースの開始時刻に基づいて時間バケットごとにカウントします。この呼び出しは、リストのウィンドウ、`q`、`filters`、`where` を受け取り、同じトレースに一致します。バケットは呼び出し元が選択します。

**クエリパラメータ**

| パラメータ | 型 | 備考 |
|---|---|---|
| `from`, `to` | 整数 | マイクロ秒単位のウィンドウ。両方とも必須です。`to` は `from` より大きい必要があります。 |
| `q`, `filters`, `where`, `expression` | 文字列 | リストの場合と同じです。 |
| `bucketTime` | 整数 | 1つのバケットの長さ（マイクロ秒）。最小 `1000`。 |
| `originTime` | 整数 | 最初のバケットの開始時刻（マイクロ秒）。`from` より後にすることはできません。 |

1つのリクエストは、`originTime` から `to` までで最大512個のバケットを対象とします。

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/histogram" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=900000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode 'filters=[{"field":"service.name","op":"=","value":"checkout"}]'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 900000000,
  "originTime": 1790000100000000,
  "buckets": [
    { "startTime": 1790000100000000, "total": 42, "errors": 3, "p50Ns": 41000000, "p95Ns": 180000000, "p99Ns": 320000000 },
    { "startTime": 1790001900000000, "total": 17, "errors": 0, "p50Ns": 38000000, "p95Ns": 95000000, "p99Ns": 120000000 }
  ],
  "split": true
}
```
</ResponseExample>

`buckets` は、トレースを含むバケットのみを古い順にリストします。`total` は、そのバケットで開始したトレースの数です。`errors` は、少なくとも1つのエラースパンを持つそれらのトレースの数です。`p50Ns`、`p95Ns`、`p99Ns` は、それらのトレースの所要時間の中央値、95パーセンタイル、99パーセンタイル（ナノ秒）です。これらは推定値であり、所要時間が1つもカウントされなかった場合は存在しません。

カウントはトレースサマリーを読み取り、フィルタがスパンフィールドに対するものである場合はスパンも読み取ります。リストはトレースごとに1つのサマリーを返します。再試行された書き込みによって2回保存されたサマリーは、2回カウントされます。

カウントを利用できない場合でも、呼び出しは `200` を返します。その場合 `buckets` は空になり、`unavailable` が理由を示します。

| `unavailable` | 原因 |
|---|---|
| `time_budget` | カウントに20秒を超える時間がかかりました。 |
| `busy` | ロールのクエリが [`[search.admission]`](/ja/configuration#クエリの受付制御) を埋め尽くし、その `max_wait_secs` 内に空きスロットができませんでした。 |
| `scan_limit` | ウィンドウ内の行数が、1つのクエリで読み取れる `[querier].max_scan_rows` の上限を超えています。 |

## リクエストの数値を読み取る

```http
GET /api/v1/web/traces/red
GET /api/v1/web/traces/red/breakdown
```

リストクエリに一致するリクエストのレート、エラー、所要時間を読み取ります。合計、バケットごと、そして所要時間ごとの内訳です。内訳は、1つのフィールドの各値について同じ数値を読み取ります。リクエストはスパンです。デフォルトでは、リクエストはサービスがリクエストを受け付けたスパン、つまりサーバースパンかコンシューマースパン、またはトレースのルートです。`scope=all` を指定すると、すべてのスパンを読み取ります。

スパンフィールドに対するフィルターはスパン自体に適用されるため、`service.name = 'api'` は `api` が処理したリクエストを読み取ります。`trace_id` と `duration_ns` はスパンから読み取り、`span_count` と `error_count` はスパンが属するトレースから読み取ります。

**クエリパラメーター**

| パラメーター | 型 | 備考 |
|---|---|---|
| `from`、`to`、`bucketTime`、`originTime` | 整数 | トレース数の時系列と同じです。 |
| `q`、`filters`、`where`、`expression` | 文字列 | 一覧と同じです。 |
| `scope` | 文字列 | `entry`（デフォルト）または `all`。 |
| `by` | 文字列 | 内訳でのみ使用し、必須です。リクエストをグループ化するフィールドを、ストリームでの名前で指定します。 |

<RequestExample>
```bash cURL
curl -G "http://localhost:5080/api/v1/web/traces/red" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'from=1790000100000000' \
  --data-urlencode 'to=1790003700000000' \
  --data-urlencode 'bucketTime=60000000' \
  --data-urlencode 'originTime=1790000100000000' \
  --data-urlencode "expression=service.name = 'checkout'"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "scope": "entry",
  "total": { "requests": 1840, "errors": 12, "p50Ns": 41000000.0, "p95Ns": 180000000.0, "p99Ns": 320000000.0 },
  "buckets": [
    { "startTime": 1790000100000000, "requests": 31, "errors": 0, "p50Ns": 40000000.0, "p95Ns": 150000000.0, "p99Ns": 210000000.0 }
  ],
  "latency": [
    { "fromNs": 0, "toNs": 50000000, "requests": 1203, "errors": 2 },
    { "fromNs": 50000000, "toNs": null, "requests": 637, "errors": 10 }
  ]
}
```
</ResponseExample>

`buckets` は、リクエストを含むバケットを古い順に列挙します。`latency` は、リクエストを所要時間の短い順に列挙します。最後の範囲には上限がありません。`errors` は、失敗を判別できない場合は `null` です。所要時間の単位はナノ秒で、リクエストがない場合と所要時間がマスクされている場合は `null` になります。

内訳は `field`、`bucketTime`、`originTime`、`scope`、`groups` を返します。`groups` には最も多い50個の値が先頭に並び、それぞれに数値と、`requests`、`errors`、`p95Ns` を持つバケットの `series` が含まれます。値のないリクエストでは `value` は `null` です。列挙されているより多くの値が存在する場合、`more` は `true` になります。

数値を取得できない場合でも、呼び出しは `200` と `unavailable` を返します。トレース数と同様に `time_budget`、`busy`、`scan_limit`、読み取り者に対して時刻がマスクされている場合は `timestamp_masked`、内訳フィールドがマスクまたは暗号化されている場合は `field_protected` です。

`by` では、JSON フィールド内のキーをフィールド名の後に続けて指定することもできます（例: `attributes.tenant`）。この場合、リクエストはそのキーが保持する値でグループ化されます。

## 遅いリクエストまたは失敗したリクエストを比較する

```http
GET /api/v1/web/traces/red/compare
```

クエリで選択したリクエストを、同じクエリの他のリクエストとフィールドごとに比較します。選択するのは、失敗したリクエスト、所要時間が指定値以上または未満のリクエスト、あるいは指定されたすべての条件を満たすリクエストです。各フィールドについて、2つの集合における各値の割合を比較し、フィールドは割合の差が大きい順にランク付けされます。`0`（同じ構成）から `1`（共通する値がない）までの範囲です。ID、時刻、所要時間、JSON フィールドは除外され、行ごとに値がほぼすべて異なるフィールドも除外されます。失敗したリクエストを選択した場合は、`status_code` も除外されます。各集合は最初の1,000スパンのサンプルとして読み取られます。

**クエリパラメーター**

RED 数値のパラメーターから `by` を除いたものに、以下を加えます。

| パラメーター | 型 | 備考 |
|---|---|---|
| `errors` | ブール値 | 失敗したリクエストを選択します。 |
| `minDuration` | 整数 | 所要時間がこのナノ秒数以上のリクエストを選択します。 |
| `maxDuration` | 整数 | 所要時間がこのナノ秒数未満のリクエストを選択します。 |

これらのうち少なくとも1つが必須で、`minDuration` は `maxDuration` より小さい必要があります。

<ResponseExample>
```json 200
{
  "scope": "entry",
  "selected": 212,
  "baseline": 1000,
  "sampled": true,
  "dimensions": [
    {
      "field": "cloud.region",
      "score": 0.71,
      "values": [
        { "value": "eu-west-1", "selected": 0.83, "baseline": 0.12 },
        { "value": "us-east-1", "selected": 0.17, "baseline": 0.88 }
      ]
    }
  ]
}
```
</ResponseExample>

`selected` と `baseline` は各集合で読み取ったスパン数で、`sampled` はどちらかの集合がそれより多かった場合に `true` になります。`dimensions` は最大20個のフィールドを差の大きい順に列挙し、それぞれに割合の差が最も大きい最大5個の値が含まれます。値のないリクエストでは `value` は `null` です。`unavailable` は RED 数値の場合と同じように返されます。

## スパンを一覧表示する

```http
GET /api/v1/web/traces/spans
```

クエリに一致するスパンごとに1行を返します。ページネーションはカーソル方式です。この呼び出しはトレース一覧のウィンドウ、`q`、`filters`、`where` を受け取り、各スパンについて評価します。スパンフィールドに対するフィルターはスパン自体に適用され、`!=` はそのフィールドを持たないスパンも保持します。`duration_ns` はスパン自体の所要時間です。`span_count` と `error_count` は、スパンが属するトレースのものです。スパンは、`A` に一致するか `B` に一致する場合に `{"or": [A, B]}` に一致します。

**クエリパラメーター**

| パラメーター | 型 | 備考 |
|---|---|---|
| `from`、`to` | 整数 | マイクロ秒単位のウィンドウ。デフォルトは現在までの過去24時間です。`to` は `from` より大きい必要があります。 |
| `q`、`filters`、`where`、`expression` | 文字列 | トレース一覧と同じです。 |
| `sort` | 文字列 | `latest`（デフォルト）、`earliest`、`duration_desc`、`duration_asc` のいずれか。 |
| `limit` | 整数 | ページサイズ。デフォルトは `100`。値は1〜5000にクランプされます。 |
| `cursor` | 文字列 | 前のページの `nextCursor` または `previousCursor`。カーソルはそのページのクエリを保持します。異なる `limit` を指定すると `400` を返します。 |

<ResponseExample>
```json 200
{
  "items": [
    {
      "traceId": "0af7651916cd43dd8448eb211c80319c",
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "durationNs": 140000000,
      "status": "ERROR",
      "kind": 2,
      "httpStatusCode": 502
    }
  ],
  "nextCursor": null,
  "previousCursor": null,
  "hasMore": false
}
```
</ResponseExample>

`status` は `OK`、`ERROR`、`UNSET` のいずれかです。`kind` は OTLP と同様にスパン種別を数値で表します。`1` は internal、`2` は server、`3` は client、`4` は producer、`5` は consumer です。スパンが値を持たない場合、`parent_span_id`、`kind`、`http_status_code` は省略されます。この呼び出しはトラッキング対象のクエリとして実行され、他のクエリと同様に受け付けられます。

## 1つのトレースを読み取る

```http
GET /api/v1/web/trace/{traceId}
```

トレースのすべてのスパンを開始時刻順に返します。`trace_id` は `A-Z`、`a-z`、`0-9`、`-`、`_` の1〜128文字です。

**クエリパラメーター**

| パラメーター | 型 | 備考 |
|---|---|---|
| `from`、`to` | 整数 | トレースのスパンが開始されたマイクロ秒単位のウィンドウ。両方指定するか、どちらも指定しません。最大31日間です。指定しない場合、トレースは過去24時間から検索されます。 |

レスポンスは100,000スパン、32 MiB に制限されます。制限によってスパン一覧が切り詰められた場合、`truncated` は `true` になります。

<ResponseExample>
```json 200
{
  "traceId": "0af7651916cd43dd8448eb211c80319c",
  "rootSpanId": "b7ad6b7169203331",
  "spans": [
    {
      "spanId": "53995c3f42cd8ad8",
      "parentSpanId": "b7ad6b7169203331",
      "service": "payments",
      "operation": "POST /pay",
      "startNs": 1790000000020000000,
      "endNs": 1790000000160000000,
      "durationNs": 140000000,
      "kind": 2,
      "status": "ERROR",
      "statusMessage": "upstream timeout",
      "attributes": { "http.method": "POST", "http.status_code": "502" },
      "events": [],
      "links": [],
      "samplingReason": "error",
      "partial": false,
      "late": false,
      "duplicate": false,
      "conflict": false
    }
  ],
  "truncated": false,

  "samplingReasons": ["error"],
  "lateSpanCount": 0,
  "duplicateSpanCount": 0,
  "conflictSpanCount": 0

```
</ResponseExample>

この例は、主要なフィールドを持つ1つのスパンを示しています。実際のスパンには、`traceFlags`、`traceState`、`resource`、`scope`、`dropped_*_count` カウンター、`schemaVersion`、`semanticConventionsVersion` も含まれます。

| フィールド | 備考 |
|---|---|
| `rootSpanId` | 親を持たない最初のスパン。ツリーは `span_id` と `parent_span_id` から構築します。 |
| `spans[].status` | `OK`、`ERROR`、`UNSET` のいずれか。 |
| `spans[].attributes` | スパン属性。ストリームのフラット化された属性カラムとマージされます。 |
| `spans[].sampling_reason` | テールサンプラーがトレースを保持した理由（例: `error`）。 |
| `partial`、`partialReasons` | スパンが欠落しているかどうかと、その理由。 |
| `lateSpanCount`、`duplicateSpanCount`、`conflictSpanCount` | 遅れて到着したスパン、重複したスパン、競合したスパン。 |

## トレースにリンクするスパンを検索する

```http
GET /api/v1/web/trace/{traceId}/linked
```

スパンは、先行するスパンへのリンクを保持し、トレース詳細はそれらをスパンとともに返します。この呼び出しは逆方向、つまりリンクがこのトレースのスパンを参照している他のトレースのスパンを検索します。トレース詳細と同じ `from` と `to` を受け取り、その期間を検索します。

<ResponseExample>
```json 200
{
  "spans": [
    {
      "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
      "spanId": "00f067aa0ba902b7",
      "service": "billing-worker",
      "operation": "process invoice",
      "startNs": 1790000005000000000,
      "durationNs": 30000000,
      "status": "OK",
      "linkedSpanId": "53995c3f42cd8ad8",
      "attributes": { "messaging.operation": "process" }
    }
  ],
  "more": false
}
```
</ResponseExample>

`spans` は最大 200 件のリンクしているスパンを新しい順に一覧表示し、さらに多くのスパンがトレースにリンクしている場合は `more` が `true` になります。`linkedSpanId` はリンクが指すこのトレースのスパンで、`attributes` はリンクの属性です。

この検索は、トレース数のタイムバジェット内で、期間内のすべてのスパンのリンクをテキストとして読み取ります。完了できない場合でも、呼び出しは空の `spans` と `unavailable` 理由を付けて `200` を返します。理由はトレース数と同様に `time_budget`、`busy`、`scan_limit` のいずれかです。

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | パラメータが無効です: `to` が `from` より大きくない、フィルタが不明なフィールドまたは演算子を使用している (`unsupported trace filter field: nope`)、`in` フィルタに値がないか 64 を超える値がある、`where` が条件ツリーでないか制限を超えている、`expression` が `q`、`filters`、`where` と一緒に指定されているか解釈できない部分がある、カーソルがクエリと一致しない、`fields` 内のフィールドが不明かドキュメントである、または `trace_id` の文字または長さが無効です。カウントの場合: 期間またはバケットパラメータが欠けている、`bucketTime` が `1000` 未満である、`originTime` が `from` より後である、またはリクエストが 512 バケットを超えています。トレース詳細とそのリンクしているスパンの場合: `from` と `to` の一方のみが指定されている、または期間が 31 日を超えています。 |
| `403` | トークンに `traces.read` がありません。 |
| `404` | トレースが期間内に見つからない、またはサンプリングで除外されています。 |
