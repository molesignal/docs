```http
POST /api/v1/alerts/incidents/{id}/resolve
```

`open` または `acknowledged` のインシデントを1件解決します。この呼び出しは、ステータスを `resolved` に変更し、呼び出し元のユーザーと解決時刻をそれぞれ `resolvedBy` と `resolvedAt` に記録して、エスカレーションを停止します。また、トリガーされた通知を確認済みにし、`alert.resolved` イベントを送信します。`alerts.incidents.acknowledge` 権限が必要です。リクエストボディは空です。

インシデントを解決すると、そのインシデントに[マージされた](/ja/api/alerting/merge-incidents)インシデントも解決します。ルールの条件が引き続き満たされている場合、次回の評価時に新しいインシデントが発生します。インシデントを解決しても、ルールは無効になりません。

<Note>
  すでに `resolved` または `closed` のインシデントを解決しようとすると、変更せずに返します。最初の解決時のユーザーと時刻は、それぞれ `resolvedBy` と `resolvedAt` に保持し、イベントは再送信しません。
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/resolve \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

レスポンスは、更新後のインシデントです。各フィールドの詳細は、[インシデント一覧の取得](/ja/api/alerting/list-incidents)を参照してください。

**エラー**

| ステータス | 原因 |
|---|---|
| `403` | トークンに `alerts.incidents.acknowledge` 権限がありません。 |
| `404` | インシデントが存在しません。 |
