[抑制](/ja/alerting/inhibition)ルールです。参照には `alerts.inhibitions.read`、変更には `alerts.inhibitions.manage` が必要です。

```http
GET    /api/v1/alerts/inhibit-rules
POST   /api/v1/alerts/inhibit-rules
GET    /api/v1/alerts/inhibit-rules/{id}
PUT    /api/v1/alerts/inhibit-rules/{id}
DELETE /api/v1/alerts/inhibit-rules/{id}
```

**リクエストボディ**

| フィールド | 型 | 説明 |
|---|---|---|
| `name` | string | 必須です。最大255文字です。 |
| `enabled` | boolean | デフォルトは `true` です。 |
| `source.matchers` | array | 抑制元のラベル条件です。形式は `{label, op, value}` で、`op` は `eq`、`neq`、`re`、`nre` のいずれかです。すべての条件に一致する必要があります。 |
| `source.min_severity` | string | 抑制元の重大度の下限です。未指定の場合は、すべての重大度が対象になります。 |
| `target.matchers` | array | 抑制対象のラベル条件です。条件がない場合は、すべてのインシデントが対象になります。 |
| `target.max_severity` | string | 抑制対象の重大度の上限です。未指定の場合は、すべての重大度が対象になります。 |
| `equal` | array | 抑制元と抑制対象の両方が同じ値で持つ必要があるラベルです。最大16個まで指定できます。`source.matchers` と `equal` の両方を空にはできません。 |
| `moreSevereOnly` | boolean | 抑制元の重大度が抑制対象より高い場合にのみ抑制します。デフォルトは `true` です。 |
| `waitSecs` | integer | 抑制対象の通知を保留する秒数です。範囲は0〜600で、デフォルトは60です。15未満の値は15として扱います。 |
| `lingerSecs` | integer | 抑制元が復旧してからも抑制を継続する秒数です。範囲は0〜3600で、デフォルトは120です。 |
| `comment` | string | コメントです。 |

ラベル条件では、インシデントに該当するラベルがない場合、`service` と `host` に影響を受けたサービスとホストを使用します。`alert.rule_id` は、インシデントを作成したルールまたはソースを示します。正規表現を解析できない場合は `400` を返します。

一覧と詳細の各ルールには `inhibiting` も含まれます。このフィールドは、ルールが現在抑制しているインシデントの数を示します。

<RequestExample>
```bash cURL
curl -X POST "http://localhost:5080/api/v1/alerts/inhibit-rules" \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "name": "On one service, the worse holds back the lesser",
    "equal": ["service"],
    "moreSevereOnly": true
  }'
```
</RequestExample>

## プレビュー

```http
POST /api/v1/alerts/inhibit-rules/preview
```

同じリクエストボディを使用し、`alerts.inhibitions.read` が必要です。`name` は省略でき、ルールを保存する必要はありません。`enabled` の値に関係なく、現在アクティブなインシデントに対して、このルールだけを実行します。

| フィールド | 説明 |
|---|---|
| `pairs[].source_incident_id`, `sourceSummary`, `sourceSeverity` | 抑制元のインシデントです。 |
| `pairs[].target_incident_id`, `targetSummary`, `targetSeverity` | 抑制対象のインシデントです。 |

## インシデントの抑制を解除する

```http
POST /api/v1/alerts/incidents/{id}/inhibition/lift
```

対象のインシデントに対する `alerts.incidents.update` が必要です。保留中の通知をすぐに送信し、以降はこのインシデントを抑制しません。解除はタイムラインと監査ログに記録します。インシデントが抑制されていない場合は何もせず、解決済みまたはマージ済みの場合は `409` を返します。インシデントを返します。

インシデントのJSONでは、次のフィールドが抑制状態を示します。

| フィールド | 説明 |
|---|---|
| `inhibition` | 現在の抑制情報です。`ruleId`、`ruleName`、`sourceIncidentId`、`sourceSummary`、`since`、`endingAt` が含まれます。抑制元が復旧すると、`endingAt` が示す終了時刻までのカウントダウンが始まります。インシデントの解決後もこの情報は残り、解決時に通知しなかったことを示します。 |
| `inhibitionWaitUntil` | 抑制元が発生するかを確認するため、通知を保留する期限です（マイクロ秒）。 |
| `inhibitionLiftedBy` | 通常どおり通知するように抑制を解除したユーザーを示します。 |
