```http
POST /api/v1/alerts/rules/{id}/test
```

保存済みルールのクエリを `now - period_secs` から `now` までの期間に対して1回実行し、条件に一致するかどうかを返します。この呼び出しは、評価状態、インシデント、通知、ルール自体を一切変更しません。呼び出しには `alerts.rules.manage` 権限が必要です。リクエストボディは空です。

`enabled` を `true` に設定する前に、ルールをテストしてください。無効なステートメントや不明なストリームを指定したルールもエラーなしで保存されます。この問題はテストでのみ確認できます。

[APM ルール](/ja/api/alerting/create-rule#apm-ルール)は、クエリを実行せずに指標値を取得します。結果は `value`、`service`、`trace_id` の各列を持つ1行です。対象期間内に指標値がなければ、行は返りません。

[列で分割したルール](/ja/api/alerting/create-rule#列で分割するルール)は、すべてのグループを `groups` に列挙します。いずれかのグループが条件に一致すると `matched` は `true` になり、`value` は最初に一致したグループの値、`severity` は全グループの中で最も高い重大度になります。

[RUM ルール](/ja/api/alerting/create-rule#rum-ルール)も同じ方法で指標値を取得します。結果は `value` と `application` の列を持つ1行です。対象期間内に指標値がなければ、行は返りません。`scannedRows` は指標値の算出元となった行数です。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/test \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "matched": true,
  "value": 2.0,
  "severity": "critical",
  "columns": ["c"],
  "rows": [[2]],
  "scannedRows": 2,
  "tookMs": 170
}
```
</ResponseExample>

**レスポンス**

| フィールド | 型 | 説明 |
|---|---|---|
| `matched` | 真偽値 | 現時点で条件に一致するかどうかを示します。結果には `forPeriods` を適用しません。 |
| `value` | 数値または null | 最初の行の最初の列の値です。結果に数値がなければ `null` になります。 |
| `severity` | 文字列または null | インシデントが発生した場合に割り当てる重大度です。`matched` が `false` の場合は `null` になります。 |
| `columns` | 配列 | クエリ結果の列名です。 |
| `rows` | 配列 | 結果の行です。最大20行を返します。 |
| `scannedRows` | 整数 | クエリがスキャンした行数です。 |
| `tookMs` | 整数 | クエリの実行時間（ミリ秒）です。 |
| `anomaly` | オブジェクト | `anomaly` ルールでのみ返します。`baseline`、`deviation`、0〜1 の `score`、理由を示す文字列 `reason` を含みます。 |
| `noData` | 真偽値 | `true` の場合のみ返します。実行結果に値がなく、ルールが欠損値を `0` として扱わないことを示します。 |
| `groups` | 配列 | 列で分割したルールでのみ、結果の順序で返します。各グループには、列名を対応する値にマッピングする `labels` と、そのグループの `value`、`matched`、`severity` が含まれます。 |
| `groupsTruncated` | 真偽値 | `true` の場合のみ返します。結果が100グループを超え、101番目以降を省略したことを示します。 |

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | 無効な SQL や不明なフィールドなどが原因でクエリを実行できません。または、`anomaly` ルールにベースラインの算出に使える履歴がないか、クエリを実行しない `composite` または `heartbeat` ルールです。 |
| `403` | ルールが参照するストリームが存在しないか、トークンに `alerts.rules.manage` 権限がありません。 |
| `404` | ルールが存在しません。 |
