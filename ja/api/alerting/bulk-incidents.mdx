```http
POST /api/v1/alerts/incidents/bulk
```

`ids` に含まれる各インシデントに対して、指定された操作を1件ずつ実行します。処理できないインシデントがあっても、残りの処理は続行します。`action` で実行する操作を指定し、その操作に必要なフィールドも併せて指定します。

| `action` | フィールド | 動作 |
|---|---|---|
| `acknowledge` | なし | [インシデントを確認する](/ja/api/alerting/ack-incident)と同じ動作です。 |
| `resolve` | なし | [インシデントを解決する](/ja/api/alerting/resolve-incident)と同じ動作です。 |
| `snooze` | `durationSecs` | [インシデントをスヌーズする](/ja/api/alerting/snooze-incident)と同じ動作です。 |
| `reassign` | `to`（[インシデントを再割り当てする](/ja/api/alerting/reassign-incident)のリクエストボディ） | リンク先の API と同じ動作です。 |
| `set_severity` | `severity` | [インシデントの重大度を設定する](/ja/api/alerting/set-incident-severity)と同じ動作です。 |

この呼び出しには `alerts.incidents.acknowledge` 権限が必要です。各インシデントは、個別の API 呼び出しと同じ方法でチェックします。マージは一括操作の対象外です。[インシデントをマージする](/ja/api/alerting/merge-incidents)を使用してください。

**ボディ**

| フィールド | 型 | 必須 | 補足 |
|---|---|---|---|
| `ids` | 配列 | はい | インシデント ID を1〜100件指定します。同じ ID は1件として数えます。 |
| `action` | 文字列 | はい | `acknowledge`、`resolve`、`snooze`、`reassign`、`set_severity` のいずれかを指定します。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<incident-id>", "<another-incident-id>"], "action": "snooze", "durationSecs": 3600}'
```
</RequestExample>

レスポンスには、インシデントごとに1件の結果が含まれます。各結果には `id` が含まれます。インシデントが復旧済み、`durationSecs` が範囲外などの理由で処理できなかった場合は、`error` も含まれます。

<ResponseExample>
```json 200
{
  "results": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW"
    },
    {
      "id": "3KEDQ4mJ8sLp2Xv6Nc1Rt9bYwHe",
      "error": "this incident is no longer active"
    }
  ]
}
```
</ResponseExample>

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | `ids` が空か、インシデントが100件を超えています。 |
| `403` | トークンに `alerts.incidents.acknowledge` 権限がありません。 |
| `422` | `action` が指定されていないか、サポートされていない値です。または、操作に必要なフィールドが指定されていません。 |
