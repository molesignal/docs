```http
GET /api/v1/alerts/incidents/{id}/rca
POST /api/v1/alerts/incidents/{id}/rca
```

[Mole Agent](/ja/agent)は、インシデントのコンテキストからインシデントの根本原因分析（RCA）を作成します。各インシデントには最大1つの分析があります。

`alert` ロールは分析を自動的に作成します。3分ごとに、このロールは分析がまだないアクティブなインシデントに対して分析を作成します（1パスあたり最大20件）。これは、組織にAPIキー付きの有効なモデルプロバイダーがある場合に実行されます。`GET` 呼び出しは保存された分析を読み取ります。`POST` 呼び出しは新しい分析を即座に生成し、保存されている分析を置き換えます。

| 呼び出し | 権限 | 備考 |
|---|---|---|
| `GET` | `alerts.incidents.read` | 分析が存在するまで、`no root-cause analysis for this incident yet` を付けて `404` を返します。 |
| `POST` | `alerts.incidents.rca` | モデルを待機し、新しい分析を返します。オプションのクエリパラメータ `locale` で出力言語（`en-us` または `zh-cn`）を選択します。デフォルトは呼び出し元ユーザーの言語設定です。 |

<RequestExample>
```bash cURL
curl -X POST "http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/rca?locale=en-us" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**レスポンス**

| フィールド | 備考 |
|---|---|
| `incidentId`、`orgId` | インシデントと組織の識別子。 |
| `summary` | Markdown テキストとしての分析。`[E2]` などのラベルで証拠を引用します。 |
| `evidence` | 分析に与えられたラベル付き証拠。最大30件。以下を参照してください。 |
| `provider`、`model` | モデルプロバイダーの種類（`openai`、`anthropic`、`openai_compatible` など）とモデル名。 |
| `promptBuiltinKey`、`promptHash` | 監査用のプロンプトテンプレートと、レンダリングされたプロンプトのハッシュ。 |
| `promptTokens`、`completionTokens`、`finishReason` | プロバイダーが報告するトークン使用量と終了理由。 |
| `createdAt`、`updatedAt` | Unix エポックからのマイクロ秒。`updatedAt` は分析が再生成されると変更されます。 |

**証拠**

各項目には `label`（`E1`、`E2`、…）、`kind`、`source` があり、判明している場合は `service`、`subject`（何についてかを示し、数値は含みません）、`detail`、`at`、`figures`、`link` もあります。

| `kind` | `source` | `figures` |
|---|---|---|
| `insight` | `apm` | `value`、`previous`、`lastWeek`、`calls`、`p95Time`。`detail` はインサイトの種類と変動した数値（`anomaly.p95` など）です。 |
| `new_error_group` | `apm` | `occurrences`。 |
| `sample_trace` | `traces` | マイクロ秒単位の `duration`。`link.traceId`。 |
| `error_logs` | `logs` | `now` と `lastWeek`。ウィンドウ内と1週間前の同じウィンドウ内のエラーレベルの行数。 |
| `new_log_pattern` | `logs` | `lines`。ウィンドウ内のパターンのエラーレベルの行数で、ウィンドウがサンプリングされた場合は推定値です。`subject` はパターン、`detail` はそのメッセージの1つです。 |
| `attribute_skew` | `traces` | `failedShare` と `otherShare`（その値を持つ失敗リクエストとその他のリクエストの割合）、`score`（そのフィールド上で2つの集合がどれだけ離れているか。0〜1）、`failed`（読み取った失敗リクエスト）。`subject` はフィールド、`detail` は値です。 |
| `business_impact` | `traces` | リクエストが失敗した値の `errors` と `requests`、`values`（その数）、`important`（そのうち重要なものとしてマークされている数）。`subject` はキーのラベル、`detail` は最大3つの値の名前です。 |
| `change`、`similar_incident`、`investigation` | `incident` | なし。 |

数値は、そのソースの権限を持つ呼び出し元にのみ返されます。`apm` には `apm.services.read`、 `traces` と `logs` には `streams.query`、または `sys.telemetry.read` です。その他の呼び出し元では `figures` は省略され、`withheld` は `true` になります。同じことが `POST` レスポンスと Mole Agent の `get_incident_rca` にも当てはまります。

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | `POST` 呼び出しで、組織にAPIキー付きの有効なモデルプロバイダーが見つかりませんでした。 |
| `403` | トークンに呼び出しの権限がありません。 |
| `404` | インシデントが存在しないか、`GET` 呼び出しでまだ分析が見つかりませんでした。 |
