```http
POST /api/v1/alerts/incidents/{id}/escalate
```

進行中のインシデントをエスカレーションポリシーの指定ステップに進め、そのステップの通知先にただちに通知します。 `escalation.reason` は `manual` に設定します。`step` を指定しない場合は、インシデントの重大度に該当する次のステップに進みます。`acknowledged` のインシデントは `open` に戻り、スヌーズが終了し、そのステップの確認応答のタイムアウトまでのカウントが始まります。確認応答がなければ、そのステップからエスカレーションを続けます。この呼び出しには `alerts.incidents.escalate` が必要です。ボディは空でもかまいません。

**ボディ**

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `step` | 整数 | いいえ | 0 から数えたステップ番号です。インシデントの重大度に該当するステップを指定してください。デフォルトは、該当する次のステップです。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/escalate \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"step": 1}'
```
</RequestExample>

レスポンスには、更新後のインシデントが含まれます。各フィールドの詳細は、[インシデントの一覧取得](/ja/api/alerting/list-incidents)を参照してください。

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | インシデントにエスカレーションポリシーがありません。`step` がポリシーのステップ範囲を超えているか、インシデントの重大度に該当しません。または、インシデントが最終ステップにあり、`step` が指定されていません。 |
| `403` | トークンに `alerts.incidents.escalate` がないか、インシデントがトークンのアクセス範囲外です。 |
| `404` | インシデントが存在しません。 |
| `409` | インシデントが復旧したか、別のインシデントに統合されたか、更新処理中に変更され続けました。再試行してください。 |
