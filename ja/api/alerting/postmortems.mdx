インシデントごとに、Markdown で記述する内部ポストモーテムを最大1件作成できます。内部ポストモーテムは [ステータスページのポストモーテム](/ja/status-pages#ポストモーテム)とは別に管理します。ステータスページには、その概要をコピーできます。ステータスページでの使い方については、[重大インシデントとポストモーテム](/ja/alerting/major-incidents#ポストモーテム)を参照してください。

| メソッドとパス | 処理内容 | 権限 |
|---|---|---|
| `GET /api/v1/alerts/postmortems` | 組織のポストモーテムを新しい順に返します。各ポストモーテムにはアクションアイテムの件数が含まれます。 | `postmortems.read` |
| `GET /api/v1/alerts/incidents/{id}/postmortem` | インシデントのポストモーテムとアクションアイテムを返します。 | 対象インシデントに対する `alerts.incidents.read` と `postmortems.read` |
| `POST /api/v1/alerts/incidents/{id}/postmortem` | インシデントのポストモーテムを作成します。 | 対象インシデントに対する `alerts.incidents.read` と `postmortems.manage` |
| `PUT /api/v1/alerts/postmortems/{id}` | ポストモーテムのタイトル、本文、ステータス、オーナー、レビュー担当者を更新します。 | `postmortems.manage` |
| `POST /api/v1/alerts/postmortems/{id}/actions` | アクションアイテムを追加します。 | `postmortems.manage` |
| `PUT /api/v1/alerts/postmortems/{id}/actions/{actionId}` | アクションアイテムを更新します。 | `postmortems.manage` |
| `DELETE /api/v1/alerts/postmortems/{id}/actions/{actionId}` | アクションアイテムを削除します。 | `postmortems.manage` |
| `POST /api/v1/alerts/postmortems/{id}/actions/{actionId}/ticket` | アクションアイテムのチケットを作成します。 | `postmortems.manage` |

## ポストモーテムの作成と更新

```http
POST /api/v1/alerts/incidents/{id}/postmortem
```

| フィールド | 型 | 必須 | 補足 |
|---|---|---|---|
| `title` | string | はい | 1～200文字です。 |
| `body` | string | いいえ | Markdown 形式の本文です。最大100000文字です。 |

インシデントにポストモーテムがすでにある場合は `409` を返します。画面ではまず、テンプレート（概要、影響、タイムライン、根本原因、うまくいった点、改善が必要な点、アクションアイテム）から本文の下書きを作成し、その後でこの API を呼び出します。作成操作は監査ログに記録されます。更新時は、変更するフィールドだけを送信します。対象は `title`、`body`、 `status`、`ownerId`（`null` で解除）、`reviewerIds` です。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/postmortems/$POSTMORTEM_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"status": "in_review", "reviewerIds": ["<user-id>"]}'
```
</RequestExample>

取得、作成、更新はいずれも `{ "postmortem": { ... }, "actions": [ ... ] }` を返します。インシデントにポストモーテムがない場合、 `postmortem` は `null` です。

<ResponseExample>
```json 200
{
```

| フィールド | 補足 |
|---|---|
| `status` | `draft`、`in_review`、`published` のいずれかです。初めて `published` に変更すると、`publishedAt` が記録されます。 |

一覧の各行には、ポストモーテムのフィールドに加え、インシデントの概要 `incidentSummary`、未完了のアクションアイテムの件数 `openActions`、および期限を過ぎても未完了の件数 `overdueActions` が含まれます。

## アクションアイテム

追加するには、`{ "title": "…", "ownerId": "<user-id>", "dueAt": 1790600000000000 }` を送信します。タイトルは1～ 300文字で、ポストモーテムごとに最大50件まで追加できます。`dueAt` は Unix 時刻をマイクロ秒で指定します。更新時は、変更するフィールドだけを送信します。対象は `title`、`ownerId` と `dueAt`（いずれも `null` で解除）、`status`（`open` または `done`）です。追加と更新はアクションアイテムを返し、削除は `{ "deleted": true }` を返します。

```http
POST /api/v1/alerts/postmortems/{id}/actions/{actionId}/ticket
```

リクエスト本文は `{ "connectorId": "<connector-id>" }` です。指定した [チケットコネクター](/ja/api/alerting/tickets)を使ってアクションアイテムのチケットを作成し、`ticketKey` と `ticketUrl` を含むアクションアイテムを返します。すでにチケットがある場合は、アクションアイテムをそのまま返します。インシデントのコメントやステータス変更はチケットに反映されません。チケットが完了しても、インシデントは解決済みになりません。

**エラー**

| ステータス | 理由 |
|---|---|
| `400` | フィールドの値が制限範囲外か、チケットコネクターが無効です。 |
| `403` | 必要な権限がないか、対象インシデントにアクセスできません。 |
| `404` | インシデント、ポストモーテム、アクションアイテム、またはチケットコネクターが存在しません。 |
| `409` | インシデントにポストモーテムがすでにあります。 |
