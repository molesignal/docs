```http
GET /api/v1/alerts/rules
GET /api/v1/alerts/rules/{id}
```

1 つ目の呼び出しは、組織のすべてのアラートルールを配列で返します。2 つ目の呼び出しは、ルールを 1 件返します。どちらの呼び出しにも `alerts.rules.read` が必要です。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/rules \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "id": "3KEDBLvTYO6DnWi8H9S9MNLpPT7",
    "orgId": "<organization-id>",
    "name": "High error rate",
    "description": "More than 100 errors in five minutes",
    "enabled": true,
    "kind": "scheduled",
    "query": {
      "language": "sql",
      "statement": "SELECT count(*) AS c FROM app WHERE level = 'error'",
      "periodSecs": 300,
      "stream": { "name": "app", "streamType": "logs" }
```

ルールには、[ルールを作成する](/ja/api/alerting/create-rule)のフィールドに加えて、次の読み取り専用フィールドがあります。

| フィールド | 説明 |
|---|---|
| `id`, `orgId` | それぞれルールと組織の識別子です。 |
| `createdAt`, `updatedAt` | Unix エポックからの経過時間です。単位はマイクロ秒です。 |
| `lastEvalAt` | 最後に完了した評価の時刻です。単位はマイクロ秒です。最初の評価が完了するまでは `null` です。クエリが失敗またはタイムアウトしても、この値は変わりません。 |
| `lastState` | 最後に完了した評価の結果です。条件を満たさなかった場合は `{"kind": "healthy"}`、条件を連続して満たした評価回数が `forPeriods` 未満の場合は `{"kind": "pending", "consecutive": 1}`、`forPeriods` に達した場合は `{"kind": "firing"}` です。ルールが発火しても、[アラートパイプライン](/ja/pipelines/alert-events#イベントの処理結果)が作成予定のインシデントを破棄した場合は `{"kind": "dropped"}` です。`firing` 状態のルールは、`silenceSecs` で指定したクールダウン期間中は新しいインシデントを作成しません。 |

指定した `id` が存在しない場合は `404` を返します。
