カレンダーアプリ（Google Calendar、Outlook、Apple Calendar など）は、購読用アドレスからフィードを取得します。フィードは、過去30日から今後90日までのシフトを、上書きや交代も含めて RFC 5545 準拠の iCalendar 形式で配信します。フィードの対象は、1つのスケジュールの全シフト、または複数のスケジュールにまたがる購読者自身のシフトです。

| メソッドとパス | 機能 | 必要な権限 |
|---|---|---|
| `GET /api/v1/schedules/calendar-feeds` | 現在のユーザーのフィード一覧を取得します。 | `schedules.read` |
| `POST /api/v1/schedules/calendar-feeds` | 購読用アドレスを作成します。同じスケジュールまたは個人用フィードに既存のアドレスがある場合は、アドレスを再発行し、古いアドレスを即時に無効化します。 | `schedules.calendar_feeds.manage`。スケジュールのフィードの場合は、対象スケジュールに対する `schedules.calendar_feeds.manage` も必要です。 |
| `DELETE /api/v1/schedules/calendar-feeds/{id}` | 現在のユーザーの指定したフィードを停止し、そのアドレスを即時に無効化します。 | `schedules.calendar_feeds.manage` |
| `GET /api/v1/public/calendar/{token}.ics` | カレンダーアプリがサインインせずにフィードを取得するためのアドレスです。 | アドレスに含まれるトークン |

## 購読用アドレスを作成する

**リクエストボディ**

| フィールド | 型 | 必須 | 補足 |
|---|---|---|---|
| `scheduleId` | 文字列 | いいえ | 購読するスケジュールを指定します。個人用フィードを作成する場合は省略してください。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/calendar-feeds \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"scheduleId": "<schedule-id>"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "feed": {
    "id": "3KHtq0dYc1fUe8WnP2xLbR7aZsM",
    "scheduleId": "<schedule-id>",
    "scheduleName": "Payments primary",
    "createdAt": 1790000000000000,
    "lastUsedAt": null
  },
  "path": "/api/v1/public/calendar/<token>.ics",
  "url": "https://molesignal.example.com/api/v1/public/calendar/<token>.ics"
}
```
</ResponseExample>

購読用アドレスは、このレスポンスで一度だけ返します。保存するのは、トークンの SHA-256 ハッシュのみです。 `url` はインスタンスの外部アドレスをもとに生成します。外部アドレスを設定していない場合、`url` は `null` になります。その場合は、MoleSignal にアクセスするアドレスの末尾に `path` を追加してください。一覧の各フィードには `id`、`scheduleId`、`scheduleName`、`createdAt` と、カレンダーアプリが最後に取得した日時を示す `lastUsedAt` が含まれます。購読用アドレスは含まれません。

## カレンダーアプリがフィードを取得する仕組み

```http
GET /api/v1/public/calendar/{token}.ics
```

フィードを取得するたびに、購読者のアカウントが有効で、組織に所属し、 `schedules.read` 権限を引き続き持っていることを確認します。スケジュールのフィードの場合は、そのスケジュールを引き続き閲覧できることも確認します。確認に失敗した場合、トークンが正しくない場合、またはフィードが停止している場合は、いずれも `404` を返します。シフトのタイトルと説明には、購読者のインターフェース言語を使用します。

購読用アドレスを知っていれば誰でもシフトを閲覧できます。アドレスが漏えいした場合は、アドレスを再発行するか、フィードを停止してください。
