```http
GET    /api/v1/alerts/holiday-calendars
POST   /api/v1/alerts/holiday-calendars
GET    /api/v1/alerts/holiday-calendars/{id}
PUT    /api/v1/alerts/holiday-calendars/{id}
DELETE /api/v1/alerts/holiday-calendars/{id}
GET    /api/v1/alerts/holiday-calendars/{id}/references
POST   /api/v1/alerts/holiday-calendars/parse
```

カレンダーの読み取りには `alerts.calendars.read` が必要です。作成、変更、削除、およびファイルの読み取りには `alerts.calendars.manage` が必要です。カレンダーに基づいて週次の時間帯を適用する方法については、[休日カレンダー](/ja/alerting/on-call#休日カレンダー)を参照してください。

## カレンダーを作成または変更する

`POST` はカレンダーを作成し、`PUT` は既存のカレンダーを置き換えます。レスポンスには、カレンダーとその `id`、 `orgId`、`createdBy`、`createdAt`、`updatedAt` が含まれます。

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| `name` | string | はい | 最大80文字です。組織内で一意である必要があります。 |
| `description` | string | いいえ | 最大500文字です。 |
| `days` | array | いいえ | 最大2,000日を指定できます。各要素は `{"date": "2026-10-01", "kind": "holiday", "name": "National Day"}` の形式です。`kind` は `holiday`（休日）または `workday`（振替出勤日。月曜日として扱います）です。`name` は最大80文字です。同じ日付を複数回指定することはできません。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/holiday-calendars \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "China 2026", "days": [{"date": "2026-10-01", "kind": "holiday", "name": "National Day"}, {"date": "2026-10-10", "kind": "workday", "name": "Make-up workday"}]}'
```
</RequestExample>

カレンダーを使用するには、週次の時間帯の `calendar` にカレンダーのIDを指定します。 `{"calendarId": "<id>", "holidays": "exclude"}` を指定すると休日を除外し、`"holidays": "only"` を指定すると休日にのみ時間帯を適用します。週次の時間帯にカレンダーを指定できるのは、 [エスカレーションポリシー](/ja/api/alerting/create-escalation)のサポート時間、[ルーティングルール](/ja/api/alerting/create-routing-rule) と通知ポリシーの時間条件、オンコールスケジュールのローテーション、アラートパイプライン、および週次のサイレンス期間です。いずれの場合も、組織内に存在しないカレンダーを指定して保存すると、 `400` エラーが返ります。

## ICSファイルを読み取る

`POST /parse` は最大2 MiBの `{"content": "<the .ics text>"}` を受け取り、何も保存せずに `{"days": [...]}` を返します。終日イベントごとに1日分の項目を生成し、複数日にまたがるイベントは日ごとに分割します。名前に「补班」または「上班」が含まれる場合や、名前が「班」で終わる場合は、`workday` として扱います。

## カレンダーの参照元を確認する

`GET /{id}/references` は、カレンダーを使用する項目を `{"kind", "id", "name"}` の形式で一覧表示します。`kind` の値は、 `routing_rule`、`escalationPolicy`、`schedule`、`mute_rule`、`notify_policy`、`alert_pipeline` のいずれかです。一覧が空でない場合、`DELETE` は `409` エラーを返します。

**エラー**

| ステータス | 理由 |
|---|---|
| `400` | フィールドの値が制限を超えている、同じ日付を2回指定している、またはファイルを読み取れません。 |
| `403` | トークンに必要な権限がありません。 |
| `404` | 指定したカレンダーが組織内に存在しません。 |
| `409` | 同じ名前のカレンダーがすでに存在するか、カレンダーが使用中です。 |
