```http
GET /api/v1/alerts/insights
```

指定期間内に作成されたインシデントと、対応開始までの時間、復旧までの時間、エスカレーションされた件数を集計し、直前の同じ長さの期間と比較します。別のインシデントに統合されたものは集計から除外します。呼び出しには `alerts.incidents.read` 権限が必要です。担当者ごとのオンコール負荷は、[オンコール負荷](/ja/api/alerting/oncall-load)で確認できます。

**クエリパラメーター**

| パラメーター | 型 | 説明 |
|---|---|---|
| `windowSecs` | 整数 | 遡って集計する期間を秒単位で指定します。デフォルトは `604800`（7日間）です。値は3600～31536000の範囲に収まるように調整します。 |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/alerts/insights?windowSecs=86400" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**レスポンス**

| フィールド | 説明 |
|---|---|
| `windowSecs` | 範囲調整後の集計期間です。 |
| `total` | 集計期間内に作成されたインシデントの件数です。 |
| `active` | ステータスが `open` または `acknowledged` のインシデントの件数です。 |
| `closed` | ステータスが `resolved` または `closed` のインシデントの件数です。 |
| `mttrSecs` | 解決済みインシデントの作成から解決までの平均時間（秒）です。解決済みのインシデントがない場合は `0` です。 |
| `noiseRate` | 解決済みインシデントのうち、60秒以内に解決したものの割合（0～1）です。解決済みのインシデントがない場合は `0` です。 |
| `byHour` | インシデントの作成時刻をUTCの時（0～23時）で分類した24個の件数です。 |
| `bySeverity` | 重大度ごとの件数です。インシデントがない重大度は含めません。 |
| `topServices`, `topRules` | `key` と `count` の組を、件数の多い順に最大8件返します。キーはサービス名またはルールの識別子です。 |
| `response.current`, `response.previous` | 集計期間と、その直前の同じ長さの期間における対応状況です。各フィールドは以下のとおりです。 |
| `response.breakdown` | 集計期間の内訳を、チーム（`teams`、キーはチームID）、サービス（`services`）、担当者（`people`、キーは最初に対応を開始した担当者）ごとに、インシデント件数の多い順にそれぞれ最大20行返します。複数のサービスに関連するインシデントは、サービスごとに1件として数えます。各行には、件数 `incidents`、対応開始までの平均時間（秒）`mttaSecs`、復旧までの平均時間（秒）`mttrSecs`、エスカレーション率 `escalationRate` が含まれます。 |

**`response.current` と `response.previous`**

| フィールド | 説明 |
|---|---|
| `incidents` | 対象期間に作成されたインシデントの件数です。 |
| `responded` | 対応を開始したインシデントの件数です。最初の確認を対応開始とします。担当者が確認せずに解決した場合は、解決時点を対応開始とします。ルールが自動的に復旧したインシデントは数えません。 |
| `mtta` | トリガーから最初の対応開始までの時間（秒）です。平均値 `meanSecs`、中央値 `p50Secs`、90パーセンタイル `p90Secs` を返します。対応を開始したインシデントがない場合は、すべて `0` です。 |
| `mttr` | 復旧したインシデントのトリガーから復旧までの時間（秒）です。同じく平均値、P50、P90を返します。 |
| `escalationRate` | エスカレーションされたインシデントの割合（0～1）です。2番目のステップに到達したか、[即時エスカレーション](/ja/api/alerting/escalate-incident)を実行したインシデントを数えます。 |
| `steps` | 各ステップの集計結果です。`step` は0から始まり、そのステップに到達したインシデントの件数を `reached`、そのステップで確認した件数を `acknowledged` で返します。タイムラインにエスカレーションの記録があるインシデントだけを集計します。対象期間に該当するインシデントがなければ空です。 |
| `ackVia` | 最初に対応を開始した経路ごとの件数です。経路は `web`、`api`、`im`、`sms`、`phone`、`agent` のいずれかです。 |
