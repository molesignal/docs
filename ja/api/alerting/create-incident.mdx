```http
POST /api/v1/alerts/incidents
```

顧客からの報告など、どのルールでも検知できなかった問題に対してインシデントを作成します。インシデントには、ラベル `alert.source=manual`、アノテーション `createdBy`（呼び出し元）と `description`、および `ruleId` として `manual` が設定されます。アラートパイプラインを経由せず、他のインシデントとの重複排除も行わず、自動では復旧しません。この呼び出しには `alerts.incidents.create` 権限が必要で、監査イベント `alert.incident.created` を記録します。

**リクエストボディ**

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| `title` | string | はい | 最大200文字です。 |
| `description` | string | いいえ | Markdown 形式で最大2000文字です。 |
| `severity` | string | いいえ | `info`、`warning`、`error`（デフォルト）、`critical` のいずれかです。 |
| `urgency` | string | いいえ | `high` や `low` など、組織の[緊急度レベル](/ja/alerting/on-call#緊急度と優先度のレベル)のキーです。省略すると、インシデントのエスカレーションポリシーに従って決まります。詳しくは[緊急度](/ja/alerting/on-call#緊急度)を参照してください。 |
| `priority` | string | いいえ | 組織の優先度のいずれかです。デフォルトでは `P1` から `P5` までで、最大で `P9` まで設定できます。 |
| `assign` | object | いいえ | 割り当て先を指定します。デフォルトは `{"kind": "auto"}` で、[アラートルーティング](/ja/alerting/routing)に従います。`{"kind": "team", "teamId": "..."}` はチームのオンコールポリシーを、`{"kind": "policy", "escalationPolicyId": "..."}` は指定したポリシーを使用します。`{"kind": "users", "userIds": [...]}` はエスカレーションポリシーを使用せず、組織のメンバー1〜10人に直接通知します。 |
| `services` | string[] | いいえ | 影響を受けるサービスを最大20件指定できます。 |
| `labels` | object | いいえ | ラベルを最大50個指定できます。`alert.source` は常に `manual` です。 |
| `declareMajor` | boolean | いいえ | [重大インシデント](/ja/alerting/major-incidents)としても宣言します。宣言に失敗しても、インシデントは作成します。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"title": "Customers in the north cannot pay", "severity": "critical", "priority": "P1", "assign": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

レスポンスにはインシデントが含まれます。フィールドについては[インシデントの一覧取得](/ja/api/alerting/list-incidents)を参照してください。

**エラー**

| ステータス | 理由 |
|---|---|
| `400` | タイトルが未指定か文字数の上限を超えている、ラベルまたはサービスの数が上限を超えている、`users` で指定した人数が1〜10人の範囲外である、または指定したチーム、ポリシー、ユーザーが組織に属していません。 |
| `403` | トークンに `alerts.incidents.create` 権限がありません。 |
