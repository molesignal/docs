```http
PUT /api/v1/alerts/incidents/{id}/priority
PUT /api/v1/alerts/incidents/{id}/urgency
```

どちらの呼び出しにも `alerts.incidents.update` が必要です。対象は、別のインシデントにマージされていないアクティブなインシデントです。タイムラインには `priority_changed` と `urgency_changed` が記録されます。

- **優先度**: リクエストボディには `{"priority": "P2"}` のように、組織の [優先度レベル](/ja/alerting/on-call#緊急度と優先度のレベル)のいずれかを指定します。優先度を設定しない場合は `null` を指定します。優先度だけを変更し、再通知は行いません。
- **緊急度**: リクエストボディには、組織の緊急度レベルのキーを指定します。たとえば、 `{"urgency": "high"}` を指定します。呼び出し元は `urgencySetBy` に記録され、以降はサポート時間によって緊急度が変わることはありません。`open` のインシデントの緊急度を上げると、 `escalation.reason` を `urgency_raised` として、該当する最初のステップから再通知します。緊急度を下げると、緊急度だけが変わります。エスカレーションステップを進まないレベルに変更すると、それ以降のエスカレーションは停止します。

複数のインシデントを一度に変更するには、[一括操作](/ja/api/alerting/bulk-incidents)で `{"action": "set_priority", "priority": "P2"}` や `{"action": "set_urgency", "urgency": "low"}` を指定してください。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/urgency \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"urgency": "high"}'
```
</RequestExample>

レスポンスにはインシデントが返ります。`urgency` は緊急度レベルのキーです（このフィールドの追加前に作成されたインシデントには含まれず、緊急度は高として扱います）。`priority` は `P1` から `P9` のいずれかです。未設定の場合は含まれません。エスカレーションポリシーで緊急度を設定した場合、`urgencyByPolicy` は `true` になります。

**エラー**

| ステータス | 理由 |
|---|---|
| `400` | 優先度が組織で設定したレベルの範囲外か、緊急度が組織で設定したレベルのいずれにも該当しません。 |
| `422` | 優先度が `P1` から `P9` のいずれでもないか、緊急度が小文字の英字、数字、アンダースコアのみで構成されたキーではありません。 |
| `403` | トークンに `alerts.incidents.update` 権限がないか、対象のインシデントにアクセスできません。 |
| `404` | 対象のインシデントが存在しません。 |
| `409` | インシデントは復旧済みか、別のインシデントにマージ済みです。 |
