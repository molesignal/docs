```http
GET /api/v1/alerts/incidents/{id}/timeline
```

1 件のインシデントについて、ユーザーと MoleSignal が記録した対応履歴、送信した通知、そのインシデントに統合したインシデントを返します。この呼び出しには `alerts.incidents.read` が必要です。コンソールはこのレスポンスを使って、インシデントの[タイムライン](/ja/alerting/incidents#インシデントの詳細)を作成します。

| フィールド | 内容 |
|---|---|
| `entries` | 記録した対応履歴を古い順に返します。フィールドは `id`、`orgId`、`incidentId`、`at`（マイクロ秒単位）、`kind`、`actor`（ユーザー ID。MoleSignal 自体の場合は `null`）、`detail` です。 |
| `deliveries` | インシデントの通知を古い順に最大 500 件返します。フィールドは `id`、`eventId`（`alert.triggered:…`、`alert.escalated:…`、`alert.acknowledged:…`、`alert.resolved:…` のいずれか）、`userId`、`connectorId`、`target`（マスク済み）、`stage`、`status`、`error`、`createdAt`、`deliveredAt` です。[パイプラインが送信を抑止した](/ja/pipelines/alert-events#通知の送信前)通知ポリシーでは、`status` は `skipped` になり、`userId` と `connectorId` は含まれず、`error` に理由が入ります。 |
| `merged` | このインシデントに[統合した](/ja/api/alerting/merge-incidents)インシデントを返します。フィールドは `id`、`summary`、`status`、`severity`、`createdAt`、`resolvedAt` です。 |

| `kind` | `detail` |
|---|---|
| `acknowledged`, `resolved` | `via` は `web`、`api`、`im`、`sms`、`phone`、`agent` のいずれかです。 |
| `escalated` | `step`（0 から開始）、`loop`、`reason`、そのステップの `targets` です。 |
| `reassigned` | [インシデントを再割り当てする](/ja/api/alerting/reassign-incident)ときと同じ `to` と、変更前の担当者、チーム、ポリシーを示す `from` です。 |
| `responders_added` | `userIds` です。 |
| `snoozed` | `until`（マイクロ秒単位）と `durationSecs` です。 |
| `snooze_cancelled` | 空です。 |
| `retriggered` | `reason` は `snooze_ended` または `ack_timeout` です。 |
| `severity_changed` | `from` と `to` です。 |
| `merged` | `into` は統合先のインシデントです。 |
| `merged_in` | `incidents` はこのインシデントに統合したインシデントです。 |
| `merged_recovered` | 復旧した統合済みインシデントの `incidentId` と `summary` です。 |
| `note` | `text` と `via` です。 |
| `remediation_requested` | [修復アクション](/ja/api/alerting/remediation)の実行リクエストを記録します。`runId` は実行 ID、`action` はアクション名、`inputs` は入力値です。 |
| `remediation_executed` | 修復アクションの完了を記録します。フィールドは `runId`、`action`、`status`（`succeeded` または `failed`）、`output`（レスポンスの先頭部分またはエラー）です。 |
| `remediation_verified` | 実行後の検証を記録します。フィールドは `runId`、`action`、`passed`、検証方法を示す `by`（`incidentResolved` または `rule_healthy`）です。 |
| `ticket_created` | [チケット](/ja/api/alerting/tickets)の作成を記録します。フィールドは `system`（`jira` または `meegle`）、`key`、`url`、コネクター名を示す `connector` です。 |
| `ticket_updated` | 同期時に検出したチケットのステータス変更を記録します。フィールドは `key`、`status`、`done` です。 |
| `declared_major` | [重大インシデント](/ja/api/alerting/major-incidents)の宣言を記録します。組織のルールが宣言した場合、`auto` は `true` です。 |
| `role_assigned` | ロールの割り当てを記録します。フィールドは `role`（`commander`、`communications`、`scribe` のいずれか）と `userId` です。割り当てを解除した場合、`userId` は `null` です。 |
| `war_room_created` | ウォールームの作成を記録します。フィールドは `platform`、参加リンクを示す `url`、ミーティングリンクを示す `meetingUrl` です。 |
| `task_added`, `task_done` | タスクの追加または完了を記録します。フィールドは `title` です。 |
| `status_update` | ステータス更新の投稿を記録します。フィールドは `impact`、`current`、`next` です。 |
| `pipeline_processed` | インシデントがオープンする前に[アラートパイプライン](/ja/pipelines/alert-events#イベントの処理結果)がイベントを変更したか、処理に失敗したことを記録します。フィールドは `pipelineId`、`pipeline`、`changes`（各変更には `field`（`severity` や `labels.team` など）、`from`（追加の場合は省略）、`to`（削除の場合は省略）が入ります）、`more`（一覧に含まれる 40 件を超えた変更の件数）、`error` です。 |

<RequestExample>
```bash cURL
curl -X GET http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/timeline \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**エラー**

| ステータス | 原因 |
|---|---|
| `403` | トークンに `alerts.incidents.read` 権限がありません。 |
| `404` | インシデントが存在しません。 |
