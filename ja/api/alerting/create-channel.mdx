コネクターは、組織で使用する1つの通知プロバイダーの認証情報とトランスポート設定を保存します。コネクターの一覧表示と取得には `notify.connectors.read` 権限が必要です。コネクターの作成、更新、テスト、削除には `notify.connectors.manage` 権限が必要です。

| 操作 | エンドポイント |
|---|---|
| コネクタータイプの一覧を取得 | `GET /api/v1/notify/connector-types` |
| コネクターの一覧を取得 | `GET /api/v1/notify/connectors` |
| コネクターを作成 | `POST /api/v1/notify/connectors` |
| コネクターを取得 | `GET /api/v1/notify/connectors/{id}` |
| コネクターを更新 | `PUT /api/v1/notify/connectors/{id}` |
| コネクターをテスト | `POST /api/v1/notify/connectors/{id}/test` |
| コネクターを削除 | `DELETE /api/v1/notify/connectors/{id}` |

## コネクタータイプ

コネクタータイプの一覧には、稼働中のバックエンドに登録されているすべてのタイプの `connectorType`、`capabilities`、`addresses` が含まれます。タイプは `email_smtp`、`lark_app`、`lark_webhook`、`slackApp`、`slack_webhook`、`webhook` です。

```json
[
  {
    "connectorType": "slack_app",
    "capabilities": {
      "directUser": true,
      "group": true,
      "richText": true,
      "interactive": true,
      "acknowledgement": false,
      "attachments": false
    },
    "addresses": [
      {
        "field": "apiBaseUrl",
        "picker": "site",
        "choices": [
          { "key": "slack", "url": "https://slack.com/api" },
          { "key": "govslack", "url": "https://slack-gov.com/api" }
        ]
      }
    ]
  }
]
```

`addresses` は、タイプの `config` に設定するプロバイダーアドレスの一覧です。Webhook や SMTP のようにアドレスを手動で入力するタイプには候補がないため、空のリストを返します。

| フィールド | 意味 |
|---|---|
| `field` | `apiBaseUrl`、`serviceUrl`、`wsUrl` などの `config` キーです。 |
| `choices` | 設定できるアドレスの候補です。各候補には `key` と `url` があり、先頭の候補がデフォルトです。 |
| `picker` | 複数のアドレスから選ぶときの基準です。`site`（プラットフォーム）または `cloud` です。選択内容自体は保存しません。 |
| `byRegion` | 選択したリージョンに応じてアドレスが変わります（Alibaba Cloud、AWS）。形式は `https://{service}.{region}.{one of domains}` です。`choices` には、リージョンを選択する前に使用するアドレスのみが含まれます。 |

コネクターの作成、更新、テスト、および通知の直接送信では、対象のキーにこの一覧のアドレスのみを指定できます。リージョン別のアドレスの場合は、`config` で指定したリージョンのアドレスのみを指定できます。キーを省略すると、デフォルト値を使用します。ほかのアドレスは拒否するため、認証情報が許可されていない宛先に送信されることはありません。

コネクターの `config` オブジェクトはタイプによって異なります。すべてのタイプで `timeoutSecs` のデフォルトは 10 で、1 から 60 までの値を指定できます。URL は `http` または `https` の絶対 URL にしてください。プロバイダーアドレスは、そのタイプの `addresses` に含まれるものを指定してください。

| `connectorType` | `config` キー |
|---|---|
| `email_smtp` | `host` と `from`（必須）、`port`（デフォルトは `587`）、`username`、`password`、`tls`（`none`、`starttls`（デフォルト）、`tls` のいずれか）、`timeoutSecs` |
| `slackApp` | `botToken`、`clientId` と `clientSecret`（ボットトークンのみ、クライアント ID とシークレットの組み合わせ、または 3 つすべて）、`apiBaseUrl`（デフォルトは `https://slack.com/api`、GovSlack の場合は `https://slack-gov.com/api`）、`timeoutSecs` |
| `slack_webhook` | `webhookUrl`（必須）、`timeoutSecs` |
| `lark_app` | `appId` と `appSecret`（必須）、`apiBaseUrl`（デフォルトは Feishu の `https://open.feishu.cn/open-apis`、Lark の場合は `https://open.larksuite.com/open-apis`）、`receiveIdType`（`open_id`（デフォルト）、`userId`、`union_id`、`email`、`chatId` のいずれか）、`timeoutSecs` |
| `lark_webhook` | `webhookUrl`（必須）、`secret`、`timeoutSecs` |
| `webhook` | `url`（必須）、`method`（`post`（デフォルト）、`put`、`patch` のいずれか）、`headers`、`timeoutSecs` |

各プロバイダーとその送信先については、[通知チャネル](/ja/notification-channels)を参照してください。

## コネクターを作成する

```http
POST /api/v1/notify/connectors
```

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `name` | 文字列 | はい | 組織内で一意の名前です。 |
| `connectorType` | 文字列 | はい | 上記のタイプのいずれかです。作成後はタイプを変更できません。 |
| `config` | オブジェクト | はい | タイプに応じた設定です。 |
| `enabled` | 真偽値 | いいえ | デフォルトは `true` です。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/notify/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "Operations webhook",
    "connectorType": "webhook",
    "config": {
      "url": "https://hooks.example.com/molesignal",
      "method": "post",
      "headers": { "Authorization": "Bearer <token>" },
      "timeoutSecs": 5
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "id": "3KEDlokKjNmves95sRzL8tXpflY",
  "organizationId": "<organization-id>",
  "name": "Operations webhook",
  "connectorType": "webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 5
  },
  "capabilities": {
    "directUser": true,
    "group": true,
    "richText": true,
    "interactive": false,
    "acknowledgement": false,
    "attachments": false
  },
  "enabled": true,
  "status": "unknown",
  "lastTestedAt": null,
  "lastTestStatus": null,
  "lastTestError": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

MoleSignal は `config` 全体を暗号化して保存します。レスポンスでは、認証情報を含むすべてのキーの値を `***` に置き換えます。対象は `url`、`webhookUrl`、`headers` と、末尾が `password`、`secret`、`token` のいずれかであるすべてのキーです。`host`、`from`、`timeoutSecs` など、ほかのキーの値はそのまま返します。

初回のテストまでは `status` が `unknown` で、テスト後は `connected` または `error` になります。`lastTestStatus` は `success` または `failed` です。`status` が `error` のコネクターは、以降のテストが成功するまでルーティングの対象から外します。

## コネクターの一覧と詳細を取得する

```http
GET /api/v1/notify/connectors
GET /api/v1/notify/connectors/{id}
```

一覧取得では、上記の形式でコネクターの配列を返します。指定した `id` が存在しない場合は `404` を返します。

## コネクターを更新する

```http
PUT /api/v1/notify/connectors/{id}
```

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `name` | 文字列 | はい | 新しい名前です。 |
| `config` | オブジェクト | いいえ | 新しい設定です。保存済みの設定を維持するには省略してください。 |
| `enabled` | 真偽値 | いいえ | デフォルトは `true` です。省略するとコネクターが有効になります。 |

マスクされたキーのシークレットを維持するには `***` を指定し、置き換えるには新しい値をプレーンテキストで指定してください。

```json
{
  "name": "Operations webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 8
  },
  "enabled": true
}
```

## コネクターをテストする

```http
POST /api/v1/notify/connectors/{id}/test
```

コネクターを通じてメッセージを 1 件送信します。無効なコネクターはテストできません。

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `targetType` | 文字列 | はい | `directUser`、`fixed_address`、`fixed_group`、`webhook` のいずれかです。指定できる値はコネクタータイプによって異なります。たとえば、`email_smtp` では `directUser` と `fixed_address` を指定できます。 |
| `target` | 文字列 | はい | メッセージの送信先です。`targetType` に応じて、アドレス、プロバイダー側の識別子、グループ、URL のいずれかを指定します。 |
| `message` | オブジェクト | いいえ | `title`、`text`、`markdown`、`html` を指定できます。デフォルトでは汎用のタイトルと本文を使用します。 |

<ResponseExample>
```json 200
{
  "sent": true,
  "testedAt": 1790000000000000,
  "elapsedMs": 3,
  "providerMessageId": "req-1",
  "error": null
}
```
</ResponseExample>

配信に失敗した場合も `200` を返します。この場合、`sent` は `false` になり、`error` に `unavailable: webhook request failed` などの理由が入ります。テストを実行すると、コネクターの `status`、`lastTestedAt`、`lastTestStatus`、`lastTestError` も更新します。

## コネクターを削除する

```http
DELETE /api/v1/notify/connectors/{id}
```

削除に成功すると、レスポンス本文なしで `204` を返します。ユーザーエンドポイント、通知ポリシー、フォールバックルート、スケジュール済みのログ検査、ステータスページ、または IM 内の Mole Agent がコネクターを参照している場合は、`409` と `notify connector is referenced by user endpoints, policies, default routes, scheduled log inspections, status pages, or Mole Agent in IM` を返します。削除する前に、参照先を変更してください。

## エラー

| ステータス | 原因 |
|---|---|
| `400` | `config` がタイプに対して無効、タイプが未対応（`unsupported connector type: pagerduty`）、送信先がコネクターに適合しない、またはコネクターが無効です。 |
| `404` | コネクターが存在しません。 |
| `409` | 組織内の別のコネクターが同じ名前を使用しているか、削除対象のコネクターがまだ参照されています。 |
| `422` | フィールドが不足しているか、未対応の `targetType` など、無効な値が指定されています。レスポンスはプレーンテキストです。 |
