```http
POST /api/v1/alerts/incidents/{id}/responders
```

`userIds` で指定したユーザーを進行中のインシデントの担当者に追加し、新しく追加した担当者それぞれにエスカレーション通知を送信します。通知の `escalation.reason` は `responder_added` です。インシデントのステータスは変わらず、すでに担当者になっているユーザーには再通知しません。この呼び出しには `alerts.incidents.update` 権限が必要です。

**ボディ**

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `userIds` | 配列 | はい | 組織メンバーのユーザー ID を 1〜10 件指定します。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/responders \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"userIds": ["<another-user-id>"]}'
```
</RequestExample>

レスポンスには更新後のインシデントが含まれます。各フィールドについては、[インシデント一覧の取得](/ja/api/alerting/list-incidents)を参照してください。

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | `userIds` が空であるか、ユーザーが 10 人を超えているか、組織外のユーザーが含まれています。 |
| `403` | トークンに `alerts.incidents.update` 権限がないか、トークンでインシデントにアクセスできません。 |
| `404` | インシデントが存在しません。 |
| `409` | インシデントが復旧済みか、別のインシデントに統合済みか、更新中に繰り返し変更されました。再試行してください。 |
