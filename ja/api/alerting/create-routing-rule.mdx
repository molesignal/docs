```http
POST /api/v1/alerts/routing/rules
```

[ルーティングルール](/ja/alerting/routing#ルーティングルール)を作成します。`alerts.routing.manage` 権限が必要です。新しいルールは末尾に追加されます。[ルーティングルールの並べ替え](/ja/api/alerting/reorder-routing-rules)で上位に移動できます。ルーティングルールは組織ごとに最大200件まで作成できます。

| フィールド | 型 | 説明 |
|---|---|---|
| `name` | string | 必須です。前後の空白を除いて1〜128文字です。 |
| `enabled` | boolean | デフォルトは `true` です。 |
| `conditions` | array | 最大16件です。デフォルトは空の配列です。`key` は1〜512文字です。`equals`、`not_equals`、`matches` には値を1つずつ、`in` には1〜100個の値を指定します。各値は最大512文字です。`matches` のパターンはコンパイル可能である必要があります。 |
| `minSeverity` | string \| null | `info`、`warning`、`error`、`critical` のいずれかです。デフォルトではすべての重要度が対象です。 |
| `origins` | array | `rule`、`external`、`synthetic` から選択します。デフォルトは空の配列で、すべての発生元が対象です。 |
| `target` | object | 必須です。`{"kind": "team", "teamId": …}` には組織内のチームを、`{"kind": "policy", "policyId": …}` には組織内のエスカレーションポリシーを指定します。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "conditions": [{"key": "env", "operator": "equals", "values": ["prod"]}], "minSeverity": "error", "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

レスポンスは作成したルールです。[ルールのフィールド](/ja/api/alerting/list-routing-rules#ルールのフィールド)を参照してください。

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | 名前が空、条件に指定した値の個数が不正、パターンをコンパイルできない、指定したチームやポリシーが存在しない、またはすでにルールが200件あります。 |
| `403` | トークンに `alerts.routing.manage` 権限がありません。 |
| `422` | `name` または `target` が指定されていないか、未定義の `operator` など、認識できない値が指定されています。レスポンスはプレーンテキストです。 |
