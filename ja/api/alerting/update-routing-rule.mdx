```http
PUT /api/v1/alerts/routing/rules/{id}
```

[ルーティングルール](/ja/alerting/routing#ルーティングルール)全体を上書きします。`alerts.routing.manage` 権限が必要です。フィールドは[ルーティングルールの作成](/ja/api/alerting/create-routing-rule)と同じです。省略したオプションフィールドはデフォルト値に戻ります。ルールの順序は変わりません。順序を変更するには、[ルーティングルールの並べ替え](/ja/api/alerting/reorder-routing-rules)を使用します。すでにオープンしているインシデントには影響しません。

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "enabled": false, "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

更新後のルールを返します。

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | フィールドに誤りがあるか、ターゲットのチームまたはポリシーが存在しません。 |
| `403` | トークンに `alerts.routing.manage` 権限がありません。 |
| `404` | ルールが存在しないか、別の組織に属しています。 |
| `422` | `name` または `target` が指定されていないか、認識できない値が指定されています。レスポンスはプレーンテキストです。 |
