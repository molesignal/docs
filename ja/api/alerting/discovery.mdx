```http
GET /api/v1/alerts/discovery/findings
GET /api/v1/alerts/discovery/findings/{id}
```

[ディスカバリー](/ja/alerting/discovery)の検出結果を最終検出日時が新しい順に一覧表示するか、単一の検出結果を取得します。`alerts.discovery.read` が必要です。

**クエリパラメーター**

| パラメーター | 説明 |
|---|---|
| `status` | `open`（デフォルト）、`ended`、または `all`。 |
| `kind` | `apm_anomaly`、`apm_regression`、`rum_new_issue`、または `rum_regressed_issue`。 |
| `limit` | デフォルトは100、最大は500です。 |

**検出結果のフィールド**

| フィールド | 説明 |
|---|---|
| `kind` | 上記の `kind` と同じです。 |
| `key` | 同じ問題かどうかを判定するキーです。種類、対象、メトリクスで構成します。 |
| `severity` | `warning`、`error`、または `critical`。 |
| `subject` | APMサービス（`namespace/name`）またはRUMアプリケーションID。 |
| `environment`, `metric` | それぞれ環境と、APMで変動を検出したメトリクスです。メトリクスは `errorRate`、`p95`（マイクロ秒）、`throughput`（1秒あたりのリクエスト数）のいずれかです。 |
| `title` | 検出内容を表す1文です。 |
| `value`, `baseline` | 現在値と比較基準値です。 |
| `startedAt`, `lastSeenAt`, `endedAt` | それぞれ開始時刻、最終検出時刻、終了時刻（マイクロ秒）です。`endedAt` がなければ、検出結果はオープンです。 |
| `missedRounds` | 連続で検出しなかった回数です。3回に達すると、検出結果は終了します。 |
| `detail` | APMの検出結果には `previous`、`lastWeek`、`version`、`previousVersion`、および検出時刻前後の変更を示す `changes` が含まれます。RUMの検出結果には `issueId`、`application`、`errorType`、`location`、`version` が含まれます。 |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/alerts/discovery/findings?status=open" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

検出結果からインシデントを作成するには、`query.discovery` を指定して[ルールを作成します](/ja/api/alerting/create-rule)。 `{"kinds": [...], "subjects": [...], "environments": [...], "minSeverity": "warning"}` の各項目は、省略するとその項目で絞り込みません。保存すると、ルールは条件に一致する検出結果ごとに1件のインシデントを作成します。インシデントの重大度は検出結果と同じです。`trigger.urgency` で別の値を指定しない限り、緊急度は低になります。
