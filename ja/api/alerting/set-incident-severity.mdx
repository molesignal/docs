```http
PUT /api/v1/alerts/incidents/{id}/severity
```

アクティブなインシデントの重大度を設定し、呼び出し元を `severitySetBy` に記録します。それ以降は、ルールの評価によって重大度が変わることはありません。`open` 状態のインシデントの重大度を上げると、新しい重大度に該当する最初のステップからエスカレーションを再開し、`escalation.reason` に `severity_raised` を設定します。重大度を下げる場合や確認済みのインシデントを変更する場合は、重大度だけが変わります。この呼び出しには `alerts.incidents.update` が必要です。

**ボディ**

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `severity` | 文字列 | はい | `info`、`warning`、`error`、`critical` のいずれかです。 |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/severity \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"severity": "critical"}'
```
</RequestExample>

レスポンスは更新後のインシデントです。各フィールドについては、[インシデントの一覧取得](/ja/api/alerting/list-incidents)を参照してください。

**エラー**

| ステータス | 原因 |
|---|---|
| `422` | `severity` が指定されていないか、4 つの値のいずれにも該当しません。 |
| `403` | トークンに `alerts.incidents.update` 権限がないか、インシデントがトークンのアクセス範囲外です。 |
| `404` | インシデントが存在しません。 |
| `409` | インシデントが復旧したか、別のインシデントに統合されたか、更新処理中に変更が続きました。再試行してください。 |
