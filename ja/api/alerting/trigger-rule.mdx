```http
POST /api/v1/alerts/rules/{id}/trigger
```

ルールの条件を評価せずにインシデントを発生させます。通知やエスカレーションの動作を確認する場合や、インシデントを手動で発生させる場合に、このAPIを呼び出してください。無効なルールでも使用できます。`alerts.rules.manage` 権限が必要です。リクエストボディは空にします。

- ルールに未解決（オープンまたは確認済み）のインシデントがすでにある場合は、そのインシデントを変更せずに返します。同じAPIを繰り返し呼び出しても安全です。
- それ以外の場合は、ステータスが `open` のインシデントを作成し、インシデント発生の通知イベントを送信します。
- 重大度は、ルールの `severity`、`severity` ラベル、`warning` の順に採用します。`thresholds` は無視します。
- `manual_triggered_by` アノテーションには呼び出し元ユーザーの識別子が入り、`triggering_query.sample_values` は空になります。

ルールが有効な場合、次回の評価で条件を満たさなければ、インシデントを解決します。ルールが無効な場合は、手動で解決するまでインシデントはオープンのままです。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/trigger \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**エラー**

| ステータス | 原因 |
|---|---|
| `403` | トークンに `alerts.rules.manage` 権限がありません。 |
| `404` | ルールが存在しません。 |
