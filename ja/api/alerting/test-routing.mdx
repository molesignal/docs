```http
POST /api/v1/alerts/routing/test
```

現在のルーティングルール、チームのオンコールポリシー、サービスカタログに基づいて、指定したラベルを持つインシデントがどのように[ルーティングされるか](/ja/alerting/routing#ルーティングの順序)を判定します。`alerts.routing.read` 権限が必要です。ソースにはデフォルトポリシーを適用するものとして判定します。インシデントは作成せず、通知も送信しません。

| フィールド | 型 | 説明 |
|---|---|---|
| `labels` | object | インシデントのラベルです。ラベル `alert.source` は発生元を示します。`external` はアラートソース、`synthetic` は外形監視チェック、それ以外の値はアラートルールを示します。 |
| `services` | array | 影響を受けるサービスです。ラベルに `service.name` も `service` もない場合は、先頭のサービスを使用します。 |
| `severity` | string | `info`、`warning`（デフォルト）、`error`、`critical` のいずれかです。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"labels": {"service.name": "checkout", "env": "prod"}, "severity": "critical"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "decision": {
    "escalationPolicyId": "<policy-id>",
    "teamId": "<team-id>",
    "routing": { "reason": "rule", "ruleId": "<rule-id>", "ruleName": "Payments in production" }
  },
  "matchedRuleId": "<rule-id>",
  "service": "default/checkout",
  "serviceTeamId": "<team-id>",
  "labelTeamId": null
}
```
</ResponseExample>

| フィールド | 説明 |
|---|---|
| `decision.escalation_policy_id` | インシデントに適用されるエスカレーションポリシーです。デフォルトポリシーの場合は `default` です。 |
| `decision.team_id` | インシデントのルーティング先チームです。該当するチームがない場合は `null` です。 |
| `decision.routing` | ルーティングの判定理由です。インシデントの `routing` と同じです。[インシデントのフィールド](/ja/api/alerting/list-incidents#インシデントのフィールド)を参照してください。 |
| `matchedRuleId` | 一致したルーティングルールです。一致するルールがない場合は `null` です。 |
| `service` | 所有チームの検索対象となったサービスです。`namespace/name` 形式で示します。 |
| `serviceTeamId` | サービスカタログでそのサービスを所有するチームです。 |
| `labelTeamId` | ラベル `teamId` または `team` が示すチームです。 |
