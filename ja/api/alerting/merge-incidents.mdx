```http
POST /api/v1/alerts/incidents/{id}/merge
```

`sourceIds` のインシデントをインシデント `{id}` にマージします。マージされた各インシデントは、メインインシデントを `mergedInto` に記録します。以降、通知もエスカレーションも行わず、 [インシデントの一覧取得](/ja/api/alerting/list-incidents)やインサイトにも表示されません。アクティブなままなので、そのルールやソースは同じ事象について新しいインシデントを作成しません。メインインシデントを解決すると、マージされたインシデントも解決します。マージされたインシデントが先に復旧すると、メインインシデントの [タイムライン](/ja/api/alerting/incident-timeline)に記録します。マージ対象のインシデントに以前マージされたインシデントも、メインインシデントに移します。マージは取り消せません。

メインインシデントとマージ対象のインシデントはすべて、アクティブで、別のインシデントにマージされていない必要があります。メインインシデント自体の ID と `sourceIds` 内の重複 ID は無視します。この呼び出しには、メインインシデントに対する `alerts.incidents.escalate` 権限が必要です。

**ボディ**

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `sourceIds` | 配列 | はい | マージ対象のインシデントの ID を 1～50 件指定します。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/merge \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"sourceIds": ["<incident-id>", "<another-incident-id>"]}'
```
</RequestExample>

レスポンスはメインインシデントです。各フィールドの詳細は[インシデントの一覧取得](/ja/api/alerting/list-incidents)を参照してください。

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | `sourceIds` にメインインシデント以外のインシデントが指定されていないか、指定数が 50 件を超えています。 |
| `403` | トークンに `alerts.incidents.escalate` 権限がないか、そのトークンではインシデントにアクセスできません。 |
| `404` | メインインシデントか、`sourceIds` で指定したインシデントのいずれかが存在しません。 |
| `409` | メインインシデントか `sourceIds` で指定したインシデントのいずれかが復旧済みか、別のインシデントにマージ済みです。または、更新処理中にインシデントが繰り返し変更されました。再試行してください。 |
