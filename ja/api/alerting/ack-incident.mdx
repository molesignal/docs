```http
POST /api/v1/alerts/incidents/{id}/ack
```

`open` 状態のインシデントを1件確認済みにします。この呼び出しは、ステータスを `acknowledged` に変更し、呼び出し元のユーザーと確認時刻をそれぞれ `acknowledgedBy` と `acknowledgedAt` に記録し、そのユーザーを `assignees` に追加します。[エスカレーションポリシー](/ja/api/alerting/create-escalation)に沿って次の段階に進むのは `open` 状態のインシデントだけなので、エスカレーションは停止します。また、トリガーされた通知を確認済みにし、`alert.acknowledged` イベントを送信します。この呼び出しには `alerts.incidents.acknowledge` 権限が必要です。リクエストボディは空です。

確認済みのインシデントは、ユーザーが解決するまで確認済みのままです。ただし、エスカレーションポリシーに [`ackRetriggerSecs`](/ja/api/alerting/create-escalation) が設定されている場合は、確認後に指定の時間が経過しても未解決であれば、ステータスが `open` に戻り、再通知されます。ルールの条件を満たさなくなっても、ルール評価処理はインシデントを解決済みにしません。

<Note>
  すでに `acknowledged` 状態のインシデントを確認すると、変更せずに返します。最初に確認したユーザーと確認時刻は `acknowledgedBy` と `acknowledgedAt` に保持され、イベントは再送信されません。 `resolved` または `closed` 状態のインシデントを確認すると、`409` を返し、ステータスは変更しません。
</Note>

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/ack \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

レスポンスは更新後のインシデントです。各フィールドについては、[インシデントの一覧を取得する](/ja/api/alerting/list-incidents)を参照してください。

**エラー**

| ステータス | 原因 |
|---|---|
| `403` | トークンに `alerts.incidents.acknowledge` 権限がありません。 |
| `404` | インシデントが存在しません。 |
