```http
POST /api/v1/alerts/incidents/{id}/reassign
```

進行中のインシデントを別の担当先に割り当てます。ボディの `kind` で新しい担当先の種類を指定します。

- `users`: `userIds` で指定した組織メンバー（1〜10 人）が担当者になり、 `escalation.reason` が `reassigned` のエスカレーション通知を受け取ります。インシデントは `open` に戻り、現在のステップの確認応答タイムアウトの計測をやり直します。確認応答がなければ、次のステップにエスカレーションします。
- `team`: `teamId` で指定したチームがインシデントを引き継ぎます。そのチームのオンコールポリシーに切り替え、ポリシーがなければ `default` ポリシーに切り替えます。該当する最初のステップから再開します。
- `policy`: `escalationPolicyId` で指定したポリシーに切り替え、該当する最初のステップから再開します。担当チームは変わりません。

いずれの場合も、インシデントは `open` に戻り、スヌーズは終了します。ステップは [タイムライン](/ja/api/alerting/incident-timeline)に記録します。この呼び出しには `alerts.incidents.update` 権限が必要です。

**ボディ**

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `kind` | string | はい | `users`、`team`、または `policy`。 |
| `userIds` | array | `users` の場合 | 組織メンバーのユーザー ID を 1〜10 件指定します。 |
| `teamId` | string | `team` の場合 | 担当チームを指定します。 |
| `escalationPolicyId` | string | `policy` の場合 | エスカレーションポリシーを指定します。 |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/$INCIDENT_ID/reassign \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"kind": "users", "userIds": ["<user-id>"]}'
```
</RequestExample>

レスポンスには、更新後のインシデントが含まれます。各フィールドの詳細は、[インシデントの一覧を取得](/ja/api/alerting/list-incidents)を参照してください。

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | `userIds` が空か、ユーザーが 10 人を超えているか、組織外のユーザーを指定しています。または、チームにポリシーがなく `default` ポリシーも存在しないか、インシデントの重大度に該当するステップがポリシーにありません。 |
| `403` | トークンに `alerts.incidents.update` 権限がないか、そのトークンではインシデントにアクセスできません。 |
| `404` | インシデントが存在しません。 |
| `409` | インシデントが復旧したか、別のインシデントに統合されたか、更新処理中に変更が続きました。再試行してください。 |
