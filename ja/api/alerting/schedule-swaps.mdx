担当交代リクエストでは、スケジュール内の別のメンバーに、リクエストしたメンバーの担当を指定期間だけ代わってもらうよう依頼します。依頼を受けたメンバーが承諾すると、スケジュールに[オーバーライド](/ja/alerting/on-call#臨時の担当)が追加され、担当交代が有効になります。ただし、スケジュールで**担当交代に承認が必要**（`swapNeedsApproval`）を有効にしている場合は、スケジュールの管理権限を持つメンバーによる承認も必要です。交代対象の期間が終わるまでに確定しなかったリクエストは失効します。各ステップでは、組み込みポリシー [担当交代：関係者に通知](/ja/notification-channels#組み込みポリシー)で関係者に通知し、監査ログに記録します。

| メソッドとパス | 動作 | 権限 |
|---|---|---|
| `GET /api/v1/schedules/swaps` | 現在のユーザーが送信または受信した担当交代リクエストを、スケジュールを横断して取得します。 | `schedules.read` |
| `GET /api/v1/schedules/{id}/swaps` | 指定したスケジュールの担当交代リクエストを新しい順に取得します。 | 対象スケジュールの `schedules.read` |
| `POST /api/v1/schedules/{id}/swaps` | 担当交代をリクエストします。 | 対象スケジュールの `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/accept` | リクエストを承諾します。依頼を受けたメンバーのみ実行できます。 | 対象スケジュールの `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/decline` | リクエストを辞退します。依頼を受けたメンバーのみ実行できます。 | 対象スケジュールの `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/cancel` | リクエストを取り消します。リクエストしたメンバーのみ、確定前であればいつでも実行できます。 | 対象スケジュールの `schedules.swaps.request` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/approve` | 承諾済みのリクエストを承認します。オーバーライドはすぐに有効になります。 | 対象スケジュールの `schedules.swaps.approve` |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/reject` | 承諾済みのリクエストを却下します。 | 対象スケジュールの `schedules.swaps.approve` |

## 担当交代をリクエストする

**リクエストボディ**

| フィールド | 型 | 必須 | 補足 |
|---|---|---|---|
| `targetId` | string | はい | シフトを引き受けるメンバーです。対象スケジュールのメンバーから、リクエストしたメンバー以外を指定します。 |
| `startAt`, `endAt` | integer | はい | 交代対象の期間を Unix 時刻（マイクロ秒）で指定します。開始時刻は未来、終了時刻は開始時刻より後に設定します。 |
| `note` | string | いいえ | 最大500文字のメモです。 |

リクエストするメンバーは、指定期間を通じてスケジュール上の唯一のオンコール担当者である必要があります。また、同じスケジュール内の未確定の担当交代リクエストと重なる期間は指定できません。

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/$SCHEDULE_ID/swaps \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"targetId": "<user-id>", "startAt": 1790060400000000, "endAt": 1790146800000000, "note": "Travelling on Friday"}'
```
</RequestExample>

各呼び出しは担当交代リクエストを返します。一覧取得では `{ "swaps": [ ... ] }` を返します。

<ResponseExample>
```json 200
{
  "id": "3KHq2nB7yZ0d4kVwXc1sPa9LmQe",
  "orgId": "<organization-id>",
  "scheduleId": "<schedule-id>",
  "scheduleName": "Payments primary",
  "requesterId": "<user-id>",
  "targetId": "<another-user-id>",
  "startAt": 1790060400000000,
  "endAt": 1790146800000000,
  "note": "Travelling on Friday",
  "status": "pending",
  "overrideId": null,
  "decidedBy": null,
  "decidedAt": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

| フィールド | 補足 |
|---|---|
| `status` | `pending`（回答待ち）、`awaiting_approval`（承諾済みで承認待ち）、`accepted`（有効）、`declined`（辞退）、`rejected`（管理者による却下）、`cancelled`（取り消し）、`expired`（失効）のいずれかです。 |
| `overrideId` | 担当交代が有効になったときに追加したオーバーライドの ID です。 |
| `decidedBy`, `decidedAt` | 最後に回答、承認、却下、または取り消しを行ったメンバーと、その操作の日時です。 |

**エラー**

| ステータス | 理由 |
|---|---|
| `400` | 期間が無効、依頼先のメンバーがスケジュールに含まれていない、指定期間にリクエストしたメンバー以外のオンコール担当者がいる、または未確定の担当交代リクエストと期間が重複しています。 |
| `403` | 必要な権限がないか、呼び出し元のユーザーがこの操作を実行できるメンバーではありません。 |
| `404` | スケジュールまたは担当交代リクエストが存在しません。 |
| `409` | 担当交代リクエストがすでに次の状態に進んでいる（承諾済みや失効など）か、その間に別のメンバーが変更しました。リクエストを再取得してから、もう一度操作してください。 |
