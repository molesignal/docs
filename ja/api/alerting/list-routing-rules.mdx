```http
GET /api/v1/alerts/routing/rules
```

組織の[ルーティングルール](/ja/alerting/routing#ルーティングルール)を評価順（`position` の昇順）に一覧表示します。`alerts.routing.read` 権限が必要です。無効なルールも一覧に含まれます。

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/routing/rules \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "id": "3KF0q7vXbJ2mYc8sTn4LwRk9Ez1",
    "orgId": "<organization-id>",
    "name": "Payments in production",
    "enabled": true,
    "position": 0,
    "conditions": [
      { "key": "env", "operator": "equals", "values": ["prod"] },
      { "key": "service.name", "operator": "in", "values": ["checkout", "cart"] }
    ],
    "minSeverity": "error",
    "origins": [],
    "target": { "kind": "team", "teamId": "<team-id>" },
    "createdBy": "<user-id>",
    "createdAt": 1790000000000000,
    "updatedAt": 1790000000000000
  }
]
```
</ResponseExample>

## ルールのフィールド

| フィールド | 説明 |
|---|---|
| `id`, `orgId` | ルールと組織の識別子です。 |
| `name` | ルールの名前です。 |
| `enabled` | 無効なルールは評価しません。 |
| `position` | ルールの評価順です。値が小さいルールから評価します。 |
| `conditions` | インシデントのラベルに対する条件です。すべての条件を満たす必要があります。空の場合はすべてのインシデントに一致します。各条件には `key`、`operator`、`values` があります。 |
| `minSeverity` | インシデントに必要な最小重大度です。`info`、`warning`、`error`、`critical` のいずれかです。`null` の場合は重大度を問いません。 |
| `origins` | ルールの適用対象となる発生元です。`rule`（アラートルール）、`external`（アラートソース）、`synthetic`（外形監視チェック）を指定できます。空の場合はすべての発生元が対象です。 |
| `target` | 一致したインシデントのルーティング先です。`{"kind": "team", "teamId": …}` または `{"kind": "policy", "policyId": …}` を指定します。 |
| `createdBy` | ルールを作成したユーザーです。 |
| `createdAt`, `updatedAt` | ルールの作成時刻と最終更新時刻です。単位はマイクロ秒です。 |

`operator` の値：

| `operator` | `values` | 一致条件 |
|---|---|---|
| `equals` | 値1つ | ラベルの値が指定した値と等しい場合に一致します。 |
| `not_equals` | 値1つ | ラベルの値が指定した値と異なる場合、またはインシデントにそのラベルがない場合に一致します。 |
| `in` | 1つ以上の値 | ラベルの値が指定した値のいずれかと等しい場合に一致します。 |
| `matches` | 正規表現1つ | ラベルの値全体が正規表現に一致する場合に一致します。 |
