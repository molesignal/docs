```http
POST /api/v1/orgs/{id}/select
```

サインイン済みのブラウザーセッションを、アカウントが所属する別の組織に切り替えます。レスポンスはセッション Cookie を切り替え先の組織用に書き換えますが、セッションの有効期限は変わりません。Cookie については、[ログイン](/ja/api/auth/login)を参照してください。組織を切り替えられるのはセッションのみです。API トークンを使うと `403` が返ります。プラットフォーム管理者は、保護された `_sys` 組織を選択できます。[JWT 署名キーのローテーション](/ja/api/auth/rotate-jwt)など、プラットフォーム全体を対象とする API 呼び出しには、この組織が必要です。`_sys` のセッションは、切り替え後 1 時間以内に終了します。

**パスパラメーター**

| パラメーター | 型 | 説明 |
|---|---|---|
| `id` | string | `GET /api/v1/orgs` で取得した組織 ID です。 |

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -c ms-cookies.txt \
  -X POST http://localhost:5080/api/v1/orgs/<organization-id>/select
```
</RequestExample>

<ResponseExample>
```json 200
{
  "userId": "<user-id>",
  "orgId": "<organization-id>",
  "orgName": "default",
  "displayRole": "Owner",
  "roles": [
    { "id": "<role-id>", "key": "owner", "name": "Owner", "builtin": true }
  ],
  "system": false
}
```
</ResponseExample>

同じブラウザーのタブは Cookie を共有するため、開いているすべてのタブが選択した組織に切り替わります。

## サインイン要件

現在のサインインが組織の[サインイン要件](/ja/identity/sso#サインイン要件)を満たしていない場合も、`200` が返ります。新しい Cookie は発行せず、不足している要件をレスポンスに示します。

| レスポンス | 意味 |
|---|---|
| `{"mfa": {"organization_name", "methods"}}` | この時点で第 2 要素を確認するため、ボディに `{"proof": {…}}` を含めてリクエストを再送してください。`proof` には、`method` に `totp` または `recovery_code` を指定して `code` を含めるか、`method` に `passkey` を指定して `POST /api/v1/me/mfa/passkey-proof` で取得した `ceremony` と `credential` を含めます。 |
| `{"mfaSetup": {"organization_name"}}` | アカウントに第 2 要素が設定されていません。先に `/api/v1/me/mfa` または `/api/v1/me/passkeys` で設定してください。 |
| `{"sso": {"organization_name", "providers"}}` | 組織のシングルサインオンでのみサインインできます。`providers` には、各プロバイダーの `id`、`name`、`kind`、`platform` が含まれます。 |
