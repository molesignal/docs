```http
POST /api/v1/me/api-tokens
```

サインイン中のユーザーとして動作する `mspat-<36>` 形式のパーソナルトークンを発行します。トークンが平文で表示されるのはこのレスポンスだけなので、すぐに保存してください。この呼び出しにはサインイン済みのセッションと `personal_tokens.manage` 権限が必要です。別のトークンでは呼び出せません。

**ボディ**

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| `name` | string | はい | 表示名です。1〜255文字で指定します。 |
| `policyId` | string | いいえ | トークンに適用する[権限ポリシー](/ja/identity/roles#権限ポリシー)のIDです。例: `builtin:data_intake`。ポリシーに含まれるすべての権限を持っている必要があります。 |
| `permissions` | string[] | いいえ | トークンに固定で割り当てる組織の権限です。指定するすべての権限を持っている必要があります。 |
| `expiresInDays` | integer | いいえ | 有効期間を日数で指定します。指定できる範囲は1〜1825です。有効期限のないトークンを発行するには、このフィールドを省略してください。 |

`policyId` と `permissions` はどちらか一方だけを指定してください。どちらも指定しない場合、トークンは発行者と同じ操作を実行できます。トークンはリクエスト時点で発行者が持つ権限を超えて操作できません。発行者が権限を失うと、発行済みのトークンもその権限を失います。

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -X POST http://localhost:5080/api/v1/me/api-tokens \
  -H 'content-type: application/json' \
  -d '{
    "name": "grafana-readonly",
    "permissions": ["streams.read", "streams.query", "dashboards.read"],
    "expiresInDays": 90
  }'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KE5hOsEc3lMC9qr9RWnPn0pqWF",
  "prefix": "k7m2q9xv4b",
  "name": "grafana-readonly",
  "tokenKind": "personal",
  "userId": "<user-id>",
  "policyId": null,
  "permissions": ["dashboards.read", "streams.query", "streams.read"],
  "applicationId": null,
  "serviceAccountId": null,
  "expiresAt": 1798000000000000,
  "lastUsedAt": null,
  "revoked": false,
  "createdAt": 1790000000000000,
  "token": "mspat-k7m2q9xv4b<secret>"
}
```
</ResponseExample>

`ms-cookies.txt` には、[ログイン](/ja/api/auth/login)で開始したセッションが保存されています。`GET /api/v1/me/api-tokens/scopes` は、トークンの権限を制限するために指定できるポリシーと組織の権限を一覧表示します。トークンは `Authorization` ヘッダーで送信してください: `Authorization: Bearer mspat-…`。

## サービスアカウント用のトークン

```http
POST /api/v1/auth/tokens
```

サービスアカウントとして動作するトークンを発行します。ボディはパーソナルトークンの場合と同じですが、`serviceAccountId` を追加します。この呼び出しには `api_tokens.issue` 権限が必要です。パーソナルトークンとは異なり、このトークンはAPIトークンを使って発行できます。`policyId` と `permissions` のどちらも指定しない場合、トークンの権限は、発行時点でサービスアカウントのロールに含まれ、かつ発行者が持っている権限に固定されます。後からロールに追加された権限はトークンに反映されず、ロールから削除された権限はトークンでも直ちに使えなくなります。

```bash
curl -X POST http://localhost:5080/api/v1/auth/tokens \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "collector-production",
    "serviceAccountId": "<service-account-id>",
    "policyId": "builtin:data_intake",
    "expiresInDays": 365
  }'
```

**エラー**

| ステータス | 原因 |
|---|---|
| `400` | `name` が空、`policyId` と `permissions` の両方を指定、リストが空、指定した権限またはポリシーが不明、またはサービスアカウントが無効です。 |
| `403` | スコープに発行者が持っていない権限が含まれている、APIトークンでパーソナルトークンの発行をリクエストした、または必要な権限（`personal_tokens.manage` または `api_tokens.issue`）がありません。 |
| `404` | システムスコープにAPIトークンがないか、サービスアカウントが存在しません。 |
