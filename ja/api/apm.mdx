The APM API exposes organization-scoped aggregates derived from trace spans. All endpoints use the
`/api/v1/apm` prefix and require a bearer token.

```http
Authorization: Bearer <token>
```

組織ワークスペースでは、対象領域の読み取り権限が必要です: `apm.services.read`、`apm.errors.read`、 `apm.error_rules.read`、`apm.definitions.read`、`apm.slos.read`、`apm.deployments.read`、または `apm.settings.read`。プラットフォームの呼び出し元は、保護された `_sys` スコープで `sys.telemetry.read` を使用できます。書き込みを行う各呼び出しは、必要な権限を示します。デプロイの報告には `apm.deploy` が必要です。

## エンドポイント

| メソッドとパス | レスポンス |
|---|---|
| `GET /api/v1/apm/overview` | 全サービスのREDサマリーとトレンド、サービスのヘルスとそのトレンド、ランキング、デプロイ、環境、インストルメンテーションのギャップ、トップトランザクション、依存関係、エラー。 |
| `GET /api/v1/apm/insights` | 直前の期間および1週間前の同じ期間と比べて何が変化したか、悪化したバージョン、時間を取り戻せる箇所、およびそれぞれの近くにある変更。 |
| `GET /api/v1/apm/services` | インストルメンテーション、バージョン、ヘルス、REDメトリクス、トレースフィルターを含む、ページネーションされたサービスカタログ。 |
| `GET /api/v1/apm/services/{service}` | サービスのサマリー、トレンド、トランザクション、依存関係、エラー、バージョン。 |
| `GET /api/v1/apm/services/{service}/instances` | 環境内のサービスのインスタンス。それぞれのバージョン、リソース属性、および各インスタンスが処理した内容。 |
| `GET /api/v1/apm/services/{service}/coverage` | `to` の前日の期間にわたり、サービスのログ、メトリクス、プロファイル、ブラウザセッションが MoleSignal に到達しているかどうか。 |
| `GET /api/v1/apm/correlation` | 表示中の各サービスがログ、メトリクス、トレース、変更とどれだけ結び付いているか、および APM が認識していないログとメトリクス内のサービス名。 |
| `GET /api/v1/apm/transactions` | ページネーションされたトランザクションのREDメトリクスと合計時間ランキング。 |
| `GET /api/v1/apm/transactions/{transaction}` | トランザクションのトレンド、影響を受けるエラー、バージョン、トレースフィルター。 |
| `GET /api/v1/apm/dependencies` | ページネーションされた呼び出し元/依存関係のREDメトリクスと合計時間ランキング。 |
| `GET /api/v1/apm/map` | 環境と名前空間のサービスマップ: サービス、それらが呼び出すもの、トピック、およびそれらの間の呼び出し。 |
| `GET /api/v1/apm/map/edge` | マップの1つの呼び出し: そのトレンド、それに沿って要求された内容、および呼び出されたサービスのエラー。 |
| `GET /api/v1/apm/blast-radius` | サービスがマップに沿って到達する範囲: それを呼び出すものと呼び出されるもの、1ホップずつ。 |
| `GET /api/v1/apm/errors` | ページネーションされたサニタイズ済みのバックエンドエラーグループ。一覧のグループが発生した場所を含みます。 |
| `GET /api/v1/apm/errors/{fingerprint}` | エラーのトレンド、影響を受けるトランザクションとバージョン、グループの発生場所、代表的なスタック、および上限付きのサンプル。 |
| `GET /api/v1/apm/versions/compare` | ベースラインと候補のREDメトリクス、差分、十分性ステータス、およびリグレッション。 |
| `GET /api/v1/apm/health` | テナントプロジェクションのステータス、ランタイムのヘルス、境界、およびギャップ。 |
| `GET /api/v1/apm/service-definitions` | 組織のすべてのサービス定義。 |
| `PUT /api/v1/apm/service-definitions/{service}?namespace=` | サービスの定義を作成または置き換えます。`apm.definitions.manage` が必要です。 |
| `DELETE /api/v1/apm/service-definitions/{service}?namespace=` | サービスの定義を削除します。`apm.definitions.manage` が必要です。 |
| `POST /api/v1/apm/service-definitions/{service}/key-transactions?namespace=` | エンドポイントをサービスのキートランザクションとしてスター付けする、またはスターを外します。`apm.definitions.manage` が必要です。 |
| `PUT /api/v1/apm/errors/{fingerprint}/issue` | エラーグループの状態、チーム、担当者を設定します。`apm.errors.manage` が必要です。 |
| `GET /api/v1/apm/error-rules` | 組織のエラーグループ化ルールを、試行される順序で示します。 |
| `POST /api/v1/apm/error-rules` | グループ化ルールを作成します。他のルールの後に試行されます。`apm.error_rules.manage` が必要です。 |
| `PUT /api/v1/apm/error-rules/{id}` | グループ化ルールを置き換えます。`apm.error_rules.manage` が必要です。 |
| `DELETE /api/v1/apm/error-rules/{id}` | グループ化ルールを削除します。`apm.error_rules.manage` が必要です。 |
| `PUT /api/v1/apm/error-rules/order` | ルールを試行する順序を設定します。`apm.error_rules.manage` が必要です。 |
| `GET /api/v1/apm/slos` | すべてのサービスレベル目標と、その状態、達成した内容、残りのエラーバジェット、バーンレート。 |
| `GET /api/v1/apm/slos/{id}` | 1つのサービスレベル目標のステータスと、そのウィンドウの各日。 |
| `POST /api/v1/apm/slos` | サービスレベル目標を作成します。`apm.slos.manage` が必要です。 |
| `PUT /api/v1/apm/slos/{id}` | サービスレベル目標を置き換えます。`apm.slos.manage` が必要です。 |
| `DELETE /api/v1/apm/slos/{id}` | サービスレベル目標を削除します。`apm.slos.delete` が必要です。 |
| `POST /api/v1/apm/deployments` | デプロイを報告します。`apm.deploy` が必要です。 |
| `GET /api/v1/apm/settings` | 組織のAPM設定。保存されていない場合は既定値。 |
| `PUT /api/v1/apm/settings` | 組織のAPM設定を置き換えます。`apm.settings.manage` が必要です。 |

パスパラメーターはURLエンコードする必要があります。リストレスポンスで返された正確な `transaction` 名またはエラーの `fingerprint` を使用してください。

## 共通クエリパラメーター

| パラメーター | 型 | 動作 |
|---|---|---|
| `from` | integer | Unixエポックからのマイクロ秒単位の範囲開始。既定では `to` の24時間前。 |
| `to` | integer | Unixエポックからのマイクロ秒単位の範囲終了。既定では現在時刻。 |
| `namespace` | string | サービス名前空間の完全一致フィルター。 |
| `service` | string | サービス名の完全一致フィルター。サービス詳細のパスはこの値より優先されます。 |
| `environment` | string | デプロイ環境の完全一致フィルター。 |
| `version` | string | サービスバージョンの完全一致フィルター。 |
| `resolution` | enum | `auto`、`minute`、または `hour`。`auto` は範囲に対して保持されている解像度を選択します。 |
| `sort` | string | エンドポイント固有の並べ替えフィールド。 |
| `direction` | enum | `asc` または `desc`。既定は `desc`。 |
| `limit` | integer | 1〜200のページサイズ。既定は50。 |
| `cursor` | string | 以前のリストレスポンスで得た不透明なカーソル。 |
| `status` | enum | `/errors` のみ: `all`（既定）、`unresolved`（オープン、調査中、および再び検出された解決済みのグループ）、`investigating`、`resolved`、または `ignored`。 |

フィルターは空でなく、192バイト以下である必要があります。範囲は設定された最大値を超えることはできません。この最大値の既定は30日です（`[apm].max_query_range_days`）。

### 並べ替えフィールド

| エンドポイント | サポートされる `sort` 値 | 既定 |
|---|---|---|
| `/services` | `requestCount`、`errorRate`、`p95`、`name` | `requestCount` |
| `/transactions` | `requestCount`、`errorRate`、`p95`、`total_time` | `requestCount` |
| `/dependencies` | `requestCount`、`errorRate`、`p95`、`total_time` | `total_time` |
| `/errors` | `occurrenceCount`、`errorRate`、`lastSeen` | `occurrenceCount` |

`/overview` は同じフィルターと解像度を受け付けますが、ページネーションは行いません。詳細、比較、およびヘルスの各エンドポイントはページネーションされたリストを返しません。

## 概要をクエリする

<RequestExample>
```bash cURL
NOW=$(date +%s)000000
curl --get 'http://localhost:5080/api/v1/apm/overview' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode "from=$((NOW-86400000000))" \
  --data-urlencode "to=$NOW" \
  --data-urlencode 'environment=production' \
  --data-urlencode 'resolution=auto'
```
</RequestExample>

レスポンスには `red`、`trend`、`serviceHealth`、`services`、`topTransactions`、 `topDependencies`、`topErrors`、`recentVersions` が含まれ、さらに共通の `meta` オブジェクトと次のものが含まれます。

| フィールド | 備考 |
|---|---|
| `serviceCount`、`activeServiceCount` | 期間内に確認されたサービスと、そのうちリクエストを処理したサービス。 |
| `healthTrend` | 各状態にあったサービスの数 (スロット単位)。期間を最大 48 スロットに分割し、各スロットはバケットより短くならない。スロット内にリクエストがないサービスは、そのスロットでは `noTraffic` として扱う。 |
| `rankings` | `slowest` (p95 順)、`mostErrors` (エラー率順)、`busiest` (リクエスト数順) で、それぞれ 5 サービス。最初の 2 つは 20 件以上のリクエストがあるサービスのみを一覧する。 |
| `deployments` | 期間内に初めて確認されたバージョン (新しい順、最大 20 件)。各バージョンには [サービスのバージョン](#サービスのバージョンを読み取る) と同様の `red` と `verdict` が付く。 |
| `environments`、`availableEnvironments` | 表示対象の環境ごとのサービスとリクエスト、および `environment` フィルターに関係なくサービスが稼働するすべての環境。 |
| `instrumentation` | 言語と SDK ごとのサービス、および `deployment.environment`、`service.version`、`service.instance.id` を報告していないサービスの数。 |

## インサイトを取得する

`GET /api/v1/apm/insights` は共通の期間とフィルターのパラメータを受け取り、`meta` と次のものを返します。

| フィールド | 備考 |
|---|---|
| `now`、`previous`、`lastWeek` | 期間内、その直前の同じ長さの区間、および 1 週間前の同じ区間における表示対象のサービス: `requestCount`、1 秒あたりのリクエスト数である `throughput`、`errorRate`、`p95Time`、`apdex`。リクエストがない区間は省略される。 |
| `insights` | 最大 30 件の検出結果 (緊急度の高い順)。 |

各検出結果には次のものが含まれます。

| フィールド | 備考 |
|---|---|
| `kind` | `anomaly`、`regression`、`slow_dependency`、`repeated_call`、`slowQuery`、`hot_endpoint`、または `log_errors`。 |
| `severity` | `critical`、`warning`、または提案の場合は `info`。 |
| `service` | `namespace`、`name`、`environment`。 |
| `transaction`、`dependency` | ホットエンドポイントのエンドポイント; ボトルネック、繰り返し呼び出し、または低速なステートメントの依存関係。 |
| `metric` | 変動または悪化した指標: `errorRate`、`p95`、または `throughput`。 |
| `value` | 現在の値: エラー率は比率、P95 はマイクロ秒、または 1 秒あたりのリクエスト数。ボトルネックまたはホットエンドポイントは所要時間に占める割合、繰り返し呼び出しは 1 リクエストあたりの呼び出し回数、低速なステートメントは P95 (マイクロ秒)、`log_errors` は 1 分あたりのエラーレベルのログ行数を返し、`metric` は `log_errors` となる。 |
| `previous`、`lastWeek` | 直前の区間および 1 週間前の同じ区間における同じ値。リグレッションの場合は直前のバージョンの値。 |
| `since` | 変動が始まった時刻、またはリグレッションしたバージョンが最初に確認された時刻。 |
| `version`、`previousVersion` | リグレッションのバージョンとその直前のバージョン。 |
| `calls`、`p95Time` | 提案の根拠となった呼び出しまたはリクエスト数と、その P95。 |
| `changes` | `since` 付近の変更 (近い順): `kind`、`source` (`reported` または `observed`)、`service`、`version`、`status`、`at`、`downstream` (変動したサービスが呼び出しているサービスの場合は `true`)、`commit`、`description`。 |

しきい値については [インサイトと調査](/ja/apm/insights#インサイトで検出される内容) を参照してください。

## サービスを一覧表示してページネーションする

```bash
curl --get 'http://localhost:5080/api/v1/apm/services' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'namespace=shop' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'sort=p95' \
  --data-urlencode 'direction=desc' \
  --data-urlencode 'limit=50'
```

## RED メトリクスを取得する

すべてのサマリーには、期間のリクエスト、エラー、所要時間の数値を含む `red` オブジェクトが付きます。

| フィールド | 備考 |
|---|---|
| `requestCount`、`errorCount`、`errorRate` | リクエスト数、失敗したリクエスト数、および全リクエストに対する失敗の比率 (0 から 1)。 |
| `durationSum`、`durationAverage` | 合計所要時間と平均所要時間 (マイクロ秒)。リクエストがない場合、平均は `null`。 |
| `p50Time`、`p90Time`、`p95Time`、`p99Time` | レイテンシのパーセンタイル (マイクロ秒)。該当する順位が含まれるヒストグラムバケット内で読み取る。デフォルトのレイアウトでは、値は正確な所要時間の約 4% 以内に収まる。リクエストがない場合は `null`。 |
| `apdex` | しきい値 T 以内のリクエスト数と 4T 以内のリクエスト数の半分を全リクエスト数で割った値 (0 から 1)。T はサービスの `apdexThreshold`、なければ 500 ms。概要の全サービス合算の値では 500 ms を使用する。失敗したリクエストは満足とはみなされない。リクエストがない場合は `null`。 |
| `latencyPartial` | 一部のバケットが、そこからは判別できないレイテンシレイアウトを使用している場合に `true`。以前のレイアウト (`[apm.histogram].schema_version`) のバケットは変換されて集計される。パーセンタイルは読み取れないバケットを除外するが、件数、合計、平均には引き続き含まれる。 |
| `timeoutCount`、`retryCount` | タイムアウトしたリクエスト (タイムアウトのエラータイプ、gRPC `DEADLINE_EXCEEDED`、HTTP 408 または 504) と、再送されたリクエスト (`http.request.resend_count` が 0 より大きい)。該当がない場合は省略される。 |
| `statusCodes` | ステータスコード別のレスポンス。`http:<code>` (100 から 599) または `grpc:<code>` (0 から 16) の形式。バケットは最大 24 個のコードを保持し、それ以降のコードは `http:other` または `grpc:other` として集計される。コードの集計が始まる前に書き込まれた集計値など、コードが集計されていない場合は省略される。 |
| `exemplars` | 期間内の最大 8 件のサンプルスパン (遅い順)。スパンは、[テールサンプリング](/ja/configuration#トレースのキャプチャとテールサンプリング) がそのトレースについて判定する前に投影されるため、通常 `traceAvailable` は `false` になる。保持されたかどうかを知るにはトレースを参照する。集計値は引き続き有効。 |

サービスとトランザクションのサマリーには、Apdex の算出に使用したしきい値 T である `apdexThreshold` が含まれます。サービスのサマリーには、`health` と `healthReasons` も含まれます。しきい値を超えた各数値を `metric` (`errorRate` または `p95`)、`level`、`value`、`threshold` として示します。また、`sparkline` (各バケットのリクエスト数、エラー数、p95) および `currentVersion` と `currentVersionSince` (最後に確認されたバージョンと、それが最初に確認された時刻) も提供します。サービスまたはトランザクションの詳細には `latencyDistribution` が含まれます。これはヒストグラムのリクエストを含むバケットを `lowerTime`、`upperTime`、`count` として表し、最速と最遅のリクエストの範囲に絞り込んだものです。

## サービス定義を保持する

定義には、サービスの所有者と重要度が記録されます。定義は `namespace` とサービス名をキーとするため、すべての環境で有効であり、サービスがレポートを開始する前から存在できます。

```http
PUT /api/v1/apm/service-definitions/checkout?namespace=shop
Content-Type: application/json

{"description": "Takes orders and payments.", "teamId": "<team id>", "ownerId": "<user id>", "tier": "p0", "lifecycle": "production", "repositoryUrl": "https://github.com/acme/checkout", "tags": {"domain": "orders", "pci": ""}, "apdexThreshold": 300000, "aliases": ["order_service", "Order Center"], "dataSources": {"logs": [{"stream": "default", "filter": "service_name = 'order_service'"}], "metrics": [{"selector": "{service=\"checkout\"}"}], "dashboards": ["<dashboard id>"], "links": [{"name": "Runbook", "url": "https://wiki.example.com/checkout"}]}, "archived": false}
```

| フィールド | 備考 |
|---|---|
| `description` | 最大 2,000 文字。 |
| `teamId` | 組織のチーム、または `null`。チームを削除するとクリアされます。 |
| `ownerId` | 組織のメンバー、または `null`。 |
| `tier` | `p0`（最も重要）から `p5`、または `null`。 |
| `lifecycle` | `production`、`staging`、`experimental`、`deprecated`、または `null`。 |
| `repositoryUrl` | `http`、`https`、`ssh`、`git`、`git+ssh` の URL、または `user@host:path`。空白を含まず、最大 2,048 文字、または `null`。パスワードは `****` として保存され、http(s) アドレスのユーザー部分も同様です。サービスがリポジトリをレポートしない場合に表示されます。 |
| `tags` | `{ "key": "value" }` 形式の最大 32 個のタグ。キーは 1～64 文字の小文字英字、数字、および `_ . - /` です。値は前後に空白を付けずに最大 128 文字で、キーのみの場合は空です。 |
| `apdexThreshold` | サービスの Apdex しきい値 T。0 より大きく最大 60,000,000（1 分）、または `null`（500 ms）。 |
| `aliases` | ログ、メトリクス、その他のシステムでサービスが使用する最大 20 個の別名。各 1～128 文字で、前後に空白は付けません。大文字と小文字は区別されません。同じ名前を重複して指定できず、サービス自身の名前は使用できません。また、組織内の別のサービスの名前やその別名も使用できません。省略した場合、保存済みの定義はその名前を保持します。 |
| `dataSources` | サービスのデータの所在です。`logs`（`stream` と、最大 2,000 文字のブール SQL 式である省略可能な `filter`）、`metrics`（`{service="checkout"}` などの PromQL セレクターである `selector`）、`dashboards`（ダッシュボード ID）、`links`（`name` と `http` または `https` の `url`）があり、それぞれ最大 10 個です。省略した場合、保存済みの定義はそのソースを保持します。 |
| `archived` | `true` の場合、サービスはカタログの既定の表示から除外されます。省略した場合、保存済みの定義はその状態を保持します。 |

保存しても定義の `keyTransactions` は保持されます。これは 1 件ずつ変更されます。レスポンスは `namespace`、`name`、`keyTransactions`、`updatedBy`、`updatedAt` を含む保存済みの定義です。 `DELETE` は `204` を返し、サービスに定義がない場合は `404` を返します。

### キートランザクションにスターを付ける

```http
POST /api/v1/apm/service-definitions/checkout/key-transactions?namespace=shop
Content-Type: application/json

{"transaction": {"name": "POST /orders", "kind": "http"}, "key": true}
```

`key: true` はエンドポイントを `keyTransactions` に追加し、`false` は削除します。すでにその状態の場合は何も変更されません。定義のないサービスには定義が作成されます。サービスは最大 50 件のキートランザクションを保持でき、オーバーフロー行 `__other__` をキートランザクションにはできません。レスポンスは変更後の定義です。

## サービスが他のデータとどれだけ関連しているかを確認する

`GET /api/v1/apm/correlation` は共通の範囲およびフィルターパラメーター（`from`、`to`、 `namespace`、`environment`、`service`）を受け取り、表示範囲内の各サービスについて、そのサービスがログ、メトリクス、トレース、変更とどれだけ結び付いているかを示します。サービスは範囲全体、ログとメトリクスは `to` より前の 1 時間、変更は `to` より前の 1 週間を対象に読み取ります。ストリームから読み取るのは件数と名前のみで、行は読み取りません。各レポートは 5 分間保持されます。

```json
{
  "from": 1792312896695000,
  "to": 1792316496695000,
  "changesSince": 1791711696695000,
  "services": [
    {
      "service": { "namespace": "shop", "name": "checkout", "environment": "prod" },
      "logs": { "state": "reported", "streams": ["default"], "lines": 1200, "traced": 480, "sampled": 10, "matched": 9 },
      "metrics": "missing",
      "resource": { "environment": true, "version": true, "instance": true, "placement": false },
      "changes": { "count": 3, "lastAt": 1792312896695000 },
      "grades": { "traceIds": "partial", "resource": "partial", "metrics": "missing", "changes": "good" }
    }
  ],
  "unmatched": [{ "name": "checkout-svc", "signal": "logs", "streams": ["default"], "lines": 640 }]
}
```

| フィールド | 意味 |
|---|---|
| `logs` | `service.name`、`service_name`、または `service` フィールドを持つログストリーム内の、そのサービスの行。最大 8 ストリームで、`default` が最初です。`traced` は `trace_id`、`traceId`、または `trace.id` を持つ行を数えます。サービスの直近のトレース ID を最大 10 個（合計 200 個）トレースの中から探します: `sampled` と `matched`。 |
| `metrics` | メトリクスストリームに、サービスの `service.name` を持つシリーズがあるかどうか。 |
| `resource` | スパンが環境、何らかのバージョン、インスタンスをレポートするかどうか、およびインスタンスが `host.name`、`k8s.pod.name`、`k8s.node.name`、または `container.id` をレポートするかどうか（`placement`）。 |
| `changes` | `changesSince` 以降にサービスについてレポートされたデプロイ、構成変更、および機能フラグ。 |
| `unmatched` | ログまたはメトリクス内の、どの APM サービスにも該当しない最大 20 個のサービス名。命名ルールとエイリアスを適用した上で、行数の多い順です。 |

各評価は `good`、`partial`、`missing`、または `unknown` です:

| 評価 | `good` | `partial` | `missing` |
|---|---|---|---|
| `traceIds` | 行の少なくとも 90% にトレース ID があり、サンプリングされたものの少なくとも 80% が見つかります。 | 一部の行にトレース ID があります。 | どの行にもトレース ID がないか、サービスが行を書き込んでいません。 |
| `resource` | `resource` の 4 つすべてが true です。 | 一部が true です。 | どれも true ではありません。 |
| `metrics` | メトリクスに名前が含まれます。 | | どれにも含まれません。 |
| `changes` | 少なくとも 1 件の変更があります。 | | ありません。 |

`unknown` は、検索が失敗したか 3 秒を超えたことを意味します。ストリームを読み取れなかったために名前が見つからない場合は `unknown` であり、`missing` にはなりません。Mole Agent は同じレポートを `get_correlation_quality` で読み取ります。

## サービスのカバレッジを確認する

`GET /api/v1/apm/services/{service}/coverage` は `namespace` と `environment`（どちらも必須）を受け取り、省略可能な `to`（表示範囲の終了をマイクロ秒で指定。既定は現在）も受け取ります。これは `to` より前の 1 日を対象とし、各回答を 5 分間保持します。

```json
{
  "from": 1792230096695000,
  "to": 1792316496695000,
  "logs": { "state": "reported", "found": ["default"] },
  "metrics": { "state": "missing" },
  "profiles": { "state": "reported", "found": ["cpu", "alloc_space"] },
  "rum": { "state": "unknown" }
}
```

| シグナル | `reported` になる条件 | `found` |
|---|---|---|
| `logs` | `service.name`、`service_name`、または `service` フィールドを持つログストリームに、そのサービスの行が含まれています。最大 8 ストリームを `default` から順に確認します。 | ストリーム。 |
| `metrics` | `to` 時点の `count(last_over_time({"service.name"="<service>"}[1h]))` が 0 より大きい。 | シリーズの数。 |
| `profiles` | プロファイルストリームに、そのサービスのプロファイルが含まれています。 | プロファイルの種類。 |
| `rum` | ブラウザーアクションが、そのサービスの直近 5 つのサンプルトレースのいずれかを含んでいました。 | セッション。 |

`missing` は、検索で何も見つからなかったことを意味します。`unknown` は、検索が失敗したか 3 秒を超えたことを意味します。`rum` が `missing` になることはありません。トレースのサンプルは、セッションがサービスに到達することを示せても、到達しないことは示せません。

## サービスが何として実行されているかを確認する

`GET /api/v1/apm/services` と `GET /api/v1/apm/services/{service}` は、各サービスのサマリーに `profile` を付与します。これは範囲内でレポートしたインスタンスから読み取られ、`version` が指定されている場合はそのバージョンのインスタンスのみが対象になります。各リストは、値を共有するインスタンスの数でランク付けされ、最大 5 件で、次の形式です: `{ "value": "1.8.2", "instances": 4 }`.

| フィールド | 備考 |
|---|---|
| `instanceCount`、`hostCount` | インスタンス数と、重複しない `host.name` の値。 |
| `versions` | インスタンスが実行したバージョン。ロールアウトでは 2 つ表示されます。 |
| `languages`、`runtimes`、`frameworks` | `telemetry.sdk.language`、バージョン付きの `process.runtime.name`、エントリースパンの計装ライブラリが示すフレームワーク。 |
| `regions`、`clusters`、`k8sNamespaces`、`workloads` | `cloud.region`、`k8s.cluster.name`、`k8s.namespace.name`、および `k8s.deployment.name` または `k8s.statefulset.name`。 |
| `repositories`、`commits` | `vcs.repository.url.full` または `git.repository_url`（認証情報を除いて保持）、`vcs.ref.head.revision` または `git.commit.sha`。 |
| `entryKinds` | `http`、`rpc`、`messaging`、`span`: サービスが提供するエントリーの種類。 |

`GET /api/v1/apm/services/{service}/instances` はインスタンスを 1 件ずつ一覧表示し、最も最近確認されたものを先頭にして最大 500 件を返します。`namespace`、`environment`、および省略可能な `version`、`from`、 `to` を受け取ります。サービスと環境がない場合は `400` を返します。各項目には `instanceId`（ `service.instance.id`、なければ `k8s.pod.name`、それもなければ `host.name`）、`version`、`firstSeenAt`、 `lastSeenAt`、`attributes`（インスタンスが最後にレポートした属性のマップ）、および範囲内で提供した内容があります: `red`（サービスしきい値での Apdex を含むサマリーと同様）と `sparkline`。インスタンス上限を超えた分は、`instanceId` が `__other__` である 1 項目にまとめて数えられます。範囲内で提供したが、そのインスタンスについて何も保持されていないものは、空の `attributes` を付けて一覧表示されます。

## エラーグループの状態を設定する

```http
PUT /api/v1/apm/errors/<fingerprint>/issue
Content-Type: application/json

{"status": "investigating", "assigneeId": "<user id>", "teamId": "<team id>", "lastSeenAt": 1792316496695000}
```

`status` は `open`、`investigating`、`resolved`、`ignored` のいずれかです。`assigneeId` は組織のメンバーまたは `null`、`teamId` は組織のチームまたは `null` です。`lastSeenAt` は省略可能で、リーダーが最後にグループを確認した時刻をマイクロ秒で表します。`resolved` を設定すると、その時刻が `resolvedAt` として記録されます。

エラーサマリーは状態を `issue` として持ち、誰も設定していない間は `null` です。`issue.regressed` は、解決済みのグループが `resolvedAt` より後に再発した場合に `true` になります。`unresolved` フィルターはそのようなグループを保持します。プロジェクションが知らないフィンガープリントの状態を設定すると `404` を返します。

## サービスレベル目標を管理する

サービスレベル目標(SLO)は、ある環境のサービス、またはそのエンドポイントの1つについて、ローリングウィンドウ内で良好なリクエストの割合を約束するものです。各指標の意味については [サービスレベル目標](/ja/apm#サービスレベル目標) を参照してください。

```http
POST /api/v1/apm/slos
Content-Type: application/json

{"name": "Checkout availability", "namespace": "shop", "service": "checkout", "environment": "production", "transaction": null, "kind": "availability", "objective": 0.999, "windowDays": 30}
```

| フィールド | 備考 |
|---|---|
| `name` | 必須。最大255バイト。 |
| `description` | 省略可能。最大2,000バイト。 |
| `namespace`, `service`, `environment` | 必須。APM が付けるサービス名。`service.namespace` を持たないサービスは名前空間 `default` に属します。 |
| `transaction` | 1つのエンドポイントは `{ "name": "POST /orders", "kind": "http" }`、サービス全体の場合は `null`。 |
| `kind` | `availability`: リクエストが失敗しなかった場合に良好とみなします。`latency`: リクエストが失敗せず、かつ `latencyThreshold` 以下であった場合に良好とみなします。 |
| `latencyThreshold` | `latency` では必須で正の値。`availability` では `null` または省略でなければなりません。 |
| `objective` | 良好なリクエストの割合。0より大きく1未満(例: `0.999`)。 |
| `windowDays` | `7`、`28`、`30` のいずれか。 |

`POST` と `PUT` は、保存された SLO を `id`、`createdBy`、`createdAt`、`updatedBy`、`updatedAt` とともに返します。`GET /api/v1/apm/slos` は組織のすべての SLO をステータスとして返します。`namespace`、`service`、`environment` をまとめて渡すと、1つのサービスの SLO に絞り込めます。ウィンドウは呼び出し時刻で終わるため、共通の範囲パラメーターは適用されません。

| ステータスフィールド | 備考 |
|---|---|
| `slo` | 保存されたままの SLO。 |
| `state` | `healthy`、`at_risk`、`breached`、`noData` のいずれか。 |
| `sli` | ウィンドウ内の全リクエストに対する良好なリクエストの割合。リクエストがない場合は `null`。 |
| `goodRequests`, `totalRequests` | `sli` の元になる件数。レイテンシ SLO はレイテンシのヒストグラムから `goodRequests` を推定するため、小数になることがあります。 |
| `budgetRemaining` | `1 - (1 - sli) / (1 - objective)`。目標が破られるとゼロ未満になり、リクエストがない場合は `null`。 |
| `burnRates` | `oneHour`、`sixHours`、`oneDay`: 直近1時間、6時間、24時間の `(1 - sli) / (1 - objective)`。リクエストがない場合は `null`。 |

`GET /api/v1/apm/slos/{id}` は `status` と `history` を返します。`history` は、ウィンドウ内でリクエストがある UTC の各日について1件ずつで、古い順に並びます。各エントリは `dayStart`(マイクロ秒)、`sli`、`goodRequests`、`totalRequests` を持ちます。

`DELETE` は `204` を返します。バーンレートアラートなど、アラートルールがその SLO を監視している間は `409` を返します。先にそれらのルールを削除してください。SLO に対するアラートルールは、メトリクス `slo_burn_rate` を持つ APM ルールです。[ルールの作成](/ja/api/alerting/create-rule#apm-ルール) を参照してください。

## トランザクションを特定する

2つのトランザクション種別が同じ名前を共有することがあります。省略可能な `kind` パラメーターを渡して1つを選択します:

```http
GET /api/v1/apm/transactions/POST%20%2Fcheckout?kind=http&service=checkout
```

サポートされる kind の値は `http`、`rpc`、`messaging`、`span`、`other` です。複数のサービスや種別が共有する名前の場合、`400` と `APM transaction identity is ambiguous; provide service, namespace, environment, and kind` を返します。

## バージョンを比較する

異なる `baseline` と `candidate` の値を指定します。1つのサービスを比較するには `service` フィルターを追加します。

```bash
curl --get 'http://localhost:5080/api/v1/apm/versions/compare' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'service=checkout' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'baseline=2.3.1' \
  --data-urlencode 'candidate=2.4.0'
```

レスポンスは `baseline` と `candidate` の両側を持ち、それぞれに `version`、`sampleCount`、`red` が含まれます。さらに `delta`、`status`、`regressedTransactions`、`regressedErrors` も含まれます。各リグレッションリストは最大20件です。

| フィールド | 備考 |
|---|---|
| `sufficientData` | 両方のバージョンが設定されたサンプルしきい値を満たす場合にのみ `true`。既定ではバージョンあたり1,000リクエスト(`[apm.version_comparison].min_requests_per_version`)。 |
| `status` | `insufficient_data`、`regressed`、`improved`、`neutral` のいずれか。候補のエラー率が1ポイント以上かつベースラインの1.5倍以上に上昇した場合、または p95 が5分の1以上かつ50 ms以上に上昇した場合は `regressed`。いずれかが同じだけ低下し、どちらもそのように上昇しなかった場合は `improved`。`sufficientData` が `false` の場合は `insufficient_data`。 |
| `delta` | `requestCountAbsolute` と `requestCountRelative`、`errorRateAbsolute` と `errorRateRelative`、`p95AbsoluteTime` と `p95Relative`。ベースラインがゼロまたは欠けている場合、相対値は `null` になります。 |

`candidate` または `baseline` がない場合、または2つのバージョンが同一の場合は `400` を返します。

## サービスのバージョンを読み取る

`GET /api/v1/apm/services/{service}` は `versions` を返します。これは指定した範囲で見られたバージョンです。各バージョンは `red`(その範囲で提供した内容)と `verdict`(その前に最初に見られた同じサービスのバージョンに対する結果)を持ち、[比較](#バージョンを比較する)と同様に判定されます:

| フィールド | 備考 |
|---|---|
| `previous` | 比較対象のバージョン。 |
| `status` | `regressed`、`improved`、`neutral`、`insufficient_data` のいずれか。 |
| `worse` | `status` が `regressed` のときに悪化したもの: `errorRate`、`latency`、またはその両方。 |
| `delta` | 比較と同様。以前のバージョンをベースラインとします。 |

最初に見られたバージョンには `verdict` がありません。リクエストのバージョンフィルターは数値を絞り込みません。すべてのバージョンはサービス全体から読み取られます。

## エラーが発生した場所を読み取る

`GET /api/v1/apm/errors` は、ページの内容と並べて `breakdown` を返します。これは `status` フィルターが保持するすべてのグループ(ページのグループだけではありません)を対象とします。`GET /api/v1/apm/errors/{fingerprint}` はそのグループの `breakdown` を返します。`breakdown` は `versions`、`environments`、`languages` を持ち、それぞれが `value` と `count` のリストで、発生回数の多い順に並びます。スパンが報告しなかった場合、値は空になります。最初の7つの値より後はまとめて `__other__` として数えます。言語はサービスの `telemetry.sdk.language` です。

## エラーグループ化ルールを管理する

ルールは、エラーが発生したときに、その型、フレーム、エンドポイントとは別の方法でエラーをグループ化します。ルールは `position` の順に試され、最初に一致したものが適用されます。

```http
POST /api/v1/apm/error-rules
Content-Type: application/json

{"name": "Upstream timeouts", "serviceNamespace": "shop", "serviceName": "checkout",
 "errorType": "*Timeout*", "message": "", "frame": "", "endpoint": "", "action": "merge", "enabled": true}
```

| フィールド | 備考 |
|---|---|
| `name` | 最大128文字。マージされたグループの名前になります。 |
| `serviceNamespace`, `serviceName` | ルールの対象となるサービス。`serviceName` が空の場合はすべてのサービスを意味します。名前空間には名前が必要です。 |
| `errorType`, `message`, `frame`, `endpoint` | エラー型、例外メッセージ、最初のアプリケーションフレーム、エンドポイントのパターン。それぞれ最大256文字。パターンはテキスト全体に一致し、大文字と小文字を区別せず、`*` は任意のテキストを表します。空のパターンは何にでも一致します。少なくとも1つを設定する必要があります。 |
| `action` | `merge`: 一致したサービスのエラーは1つのグループになります。`ignore`: グループを作らず、それらのリクエストは失敗として数えられます。 |
| `enabled` | オフのルールは保持されますが試されません。既定値は `true`。 |

レスポンスは、ルールに `id`、`position`、`updatedBy`、`updatedAt` を加えたものです。組織は最大100個のルールを保持できます。`PUT /api/v1/apm/error-rules/order` は `{"ids": [...]}` を受け取り、それらのルールをその順序で先頭に置き、残りをその後に置いて、新しい順序でルールを返します。

変更は、保存したノードでは即座に、他のノードでは30秒以内に、それ以降に見られるエラーに適用されます。すでに作成されたグループはそのまま残ります。

## サービスマップを読み取る

`GET /api/v1/apm/map` は共通の範囲、`environment`、`namespace` パラメータを受け取り、`nodes`、`edges`、`namespaces`（環境内のサービスのもの）、`environments`（すべて）、`truncated`（最も負荷の高い 400 ノードのみを保持する場合に `true`）を返します。

| フィールド | 備考 |
|---|---|
| `nodes[].id` | `service:<name>`、`topic:<name>`、またはサービスが呼び出すものについては `<category>:<target>`。 |
| `nodes[].kind` | `service`、`external`、または `topic`。外部ノードは自身の `category` を持ちます。 |
| `nodes[].red` | `requestCount`、`errorCount`、`errorRate`、`p95Time`: サービスが処理した内容、または外部ノードやトピックに対して要求された内容。サービスは `health`、`namespace`、`environments` も持ちます。 |
| `edges[].kind` | `call`、`publish`（トピックへ）、または `consume`（トピックから）。 |
| `change` | エッジまたはノードについて、直前の同じ長さの期間と比較した値: 存在しなかった場合は `new`、存在しなくなった場合は `gone`。以前に何も存在しなかった場合は省略されます。 |

サービス間の呼び出しはサービスグラフから取得し、最も遅い 1 分間の P95 を伴います。それ以外は APM バケットから取得します。`GET /api/v1/apm/map/edge` は同じパラメータに加えて `source` と `target` のノード ID を受け取り、`kind`、`red`、`trend`、`operations`（`name`、`kind`、`red`）、`everyCaller`（オペレーションがすべての呼び出し元からの被呼び出しサービスのエンドポイントである場合に `true`）、および被呼び出しサービスのエラーグループである `errors` を返します。

## サービスのブラストラディウスを読み取る

`GET /api/v1/apm/blast-radius` は必須の `service`、および共通の範囲と `environment` パラメータを受け取ります。名前空間に関係なく環境全体のマップを読み取り、`meta`、`service`（サービス自身のノード。範囲内のどこにもマップに存在しない場合は省略）、`upstream`（自身を呼び出すもの、最大 3 ホップ）、`downstream`（自身が呼び出す、または publish する先、最大 2 ホップ）を返します。各側は最大 30 ノードを保持し、異常なものが先頭になります。直前の期間と比較して消失した呼び出しは除外されます。

| フィールド | 備考 |
|---|---|
| `id`、`kind`、`name`、`namespace`、`category` | [サービスマップ](#サービスマップを読み取る)が命名する形のノード。 |
| `hops` | ノードとサービス間の呼び出し: 直接の呼び出し元または呼び出し先の場合は `1`。 |
| `via` | 到達するために経由するノード。サービスに 1 ホップ近いもの。 |
| `health` | サービス自身のヘルス。呼び出されるものについては、失敗した呼び出しが示すヘルス。 |
| `red`、`call` | 処理した内容または要求された内容、およびそれと `via` の間の呼び出し。 |

## デプロイを報告する

`POST /api/v1/apm/deployments` はデプロイを JSON として受け取り、それに `id`、`createdBy`、`createdAt` を加えて `201` で返します。フィールド、その制限、CI の例は[デプロイ](/ja/apm/deployments#ci-からデプロイを報告する)にあります。サービスと環境は、組織の命名規則、環境マッピング、エイリアスが読み取る形で指定します。リポジトリのアドレスはパスワードをマスクして保存されます。設定変更またはフィーチャーフラグは `kind` を `configuration` または `feature_flag` に設定し、`version` は不要です。

スケールまたはインフラストラクチャの変更は `kind` を `scaling` または `infrastructure` に設定します。報告された変更は [`GET /api/v1/changes`](/ja/api/changes) で一覧表示されます。

## APM 設定を保持する

`GET /api/v1/apm/settings` は組織の設定を返します。`PUT` は設定全体を置き換え、保持された内容を返します:

```json
{
  "health": {
    "errorRateWarning": 0.02,
    "errorRateCritical": 0.1,
    "p95WarningTime": 500000,
    "p95CriticalTime": 2000000
  },
  "apdexThreshold": 500000,
  "longTaskTime": 1000000,
  "namingRules": [{ "pattern": "^(checkout)-[a-z0-9]{5}$", "replacement": "$1" }],
  "environmentMap": [{ "from": "Production", "to": "production" }],
  "aliases": [{ "aliasNamespace": "shop", "alias": "checkout-v1", "namespace": "shop", "service": "checkout" }],
  "metadataRules": { "teamFromTier": "p1", "ownerFromTier": "p0", "repositoryFromTier": null }
}
```

省略されたフィールドはデフォルト値になります。名前はトリムされ、空のエイリアス名前空間は `default` になります。制限と各設定の動作は [APM 設定](/ja/apm/settings)にあります。保存は、保存したノードでは即座に、その他のノードでは 30 秒以内に適用されます。

プラットフォームのカーディナリティ制限は `GET` と `PUT /api/v1/settings/apm_limits` で読み取りおよび置き換えを行い、`sys.settings.limits.manage` が必要です。ボディには `servicesPerOrgHour`、`transactionsPerServiceHour`、`dependenciesPerServiceHour`、`operationsPerDependencyHour`、`errorGroupsPerServiceHour`、`versionsPerServiceHour`、`instancesPerServiceHour` を含め、それぞれ 1 から 100000 の範囲です。

## レスポンスのメタデータを読み取る

すべてのエンドポイントは共通の `meta` オブジェクトを返します:

```json
{
  "range": {
    "from": 1785801600000000,
    "to": 1785888000000000
  },
  "resolution": "minute",
  "projectionStartedAt": 1785798000000000,
  "lastCompleteBucketAt": 1785887940000000,
  "dataQuality": {
    "partial": false,
    "gaps": [],
    "overflowDimensions": []
  },
  "activationBoundary": false
}
```

- `activationBoundary: true` は `projectionStartedAt` より前のカバレッジが不完全であると解釈します。
- `dataQuality.partial: true` は完全なゼロではなく、不完全なデータと解釈します。
- キュー、リポジトリ、フラッシュ、遅延データ、カーディナリティ、またはシャットダウンの失敗については `gaps` を確認します。
- 最近のデータがまだ確定中かどうかを判断するには `lastCompleteBucketAt` を使用します。
- 高カーディナリティの内訳に依存する前に `overflowDimensions` を確認します。

## エラー

| ステータス | 原因 |
|---|---|
| `400` | パラメータが無効です: サポートされていない `sort`（`unsupported APM sort field`）、1 から 200 の範囲外の `limit`、空またはサイズ超過のフィルタ（`invalid APM service filter`）、最大値を超える範囲（`APM query range exceeds configured maximum`）、開始より前の終了（`APM range end precedes start`）、不明な `direction` または `resolution`、上記のチェックに失敗する SLO（`SLO objective must be between 0 and 1, exclusive`）、または `namespace`、`service`、`environment` のすべてを含まない SLO リストフィルタ。 |
| `403` | トークンに呼び出しに必要な権限がありません。 |
| `404` | エラーフィンガープリント、トランザクション、サービス、または SLO が範囲内に存在しません。 |
| `409` | 削除対象の SLO をアラートルールがまだ監視しています。 |
