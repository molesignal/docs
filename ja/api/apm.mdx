APM API は、トレーススパンから算出した組織単位の集計データを提供します。すべてのエンドポイントは `/api/v1/apm` プレフィックスを使用し、ベアラートークンを必要とします。

```http
Authorization: Bearer <token>
```

組織のワークスペースでは、対象領域に応じた読み取り権限が必要です：`apm.services.read`、`apm.errors.read`、 `apm.error_rules.read`、`apm.definitions.read`、`apm.slos.read`、`apm.deployments.read`、`apm.settings.read` のいずれかです。プラットフォームからの呼び出しでは、保護された `_sys` スコープで `sys.telemetry.read` を使用できます。書き込みを行う各操作には、必要な権限を明記しています。デプロイの報告には `apm.deploy` が必要です。

## エンドポイント

| メソッドとパス | レスポンス |
|---|---|
| `GET /api/v1/apm/overview` | 全サービスの RED メトリクスの概要と推移、サービスの健全性とその推移、ランキング、デプロイ、環境、計装の不足箇所、上位のトランザクション、依存関係、エラーを返します。 |
| `GET /api/v1/apm/insights` | 直前の同じ長さの期間および 1 週間前の同じ期間と比べて変化した項目、パフォーマンスが低下したバージョン、処理時間を短縮できる箇所、それぞれの前後に発生した変更を返します。 |
| `GET /api/v1/apm/services` | 計装、バージョン、健全性、RED メトリクス、トレースフィルターを含むサービスカタログをページ分割して返します。 |
| `GET /api/v1/apm/services/{service}` | サービスの概要、推移、トランザクション、依存関係、エラー、バージョンを返します。 |
| `GET /api/v1/apm/services/{service}/instances` | 対象環境内のサービスインスタンスと、各インスタンスのバージョン、リソース属性、処理したリクエストを返します。 |
| `GET /api/v1/apm/services/{service}/coverage` | `to` までの 24 時間に、サービスのログ、メトリクス、プロファイル、ブラウザーセッションが MoleSignal に届いたかどうかを返します。 |
| `GET /api/v1/apm/transactions` | トランザクションの RED メトリクスと合計処理時間のランキングをページ分割して返します。 |
| `GET /api/v1/apm/transactions/{transaction}` | トランザクションの推移、関連するエラー、バージョン、トレースフィルターを返します。 |
| `GET /api/v1/apm/dependencies` | 呼び出し元と依存先の組み合わせごとの RED メトリクスと合計処理時間のランキングをページ分割して返します。 |
| `GET /api/v1/apm/map` | 対象の環境と名前空間のサービスマップを返します。サービス、呼び出し先、トピック、およびそれらの間の呼び出しが含まれます。 |
| `GET /api/v1/apm/map/edge` | サービスマップ上の 1 つの呼び出し関係について、推移、リクエストの内容、呼び出し先サービスのエラーを返します。 |
| `GET /api/v1/apm/blast-radius` | サービスマップ上で対象サービスにつながる呼び出し元と呼び出し先を、ホップごとに返します。 |
| `GET /api/v1/apm/errors` | サニタイズ済みのバックエンドエラーグループとその発生箇所をページ分割して返します。 |
| `GET /api/v1/apm/errors/{fingerprint}` | エラーの推移、影響を受けたトランザクションとバージョン、グループの発生箇所、代表的なスタックトレース、上限付きのサンプルを返します。 |
| `GET /api/v1/apm/versions/compare` | ベースラインと比較対象の RED メトリクス、差分、データが十分かどうか、パフォーマンスの低下を返します。 |
| `GET /api/v1/apm/health` | テナントのプロジェクションの状態、ランタイムの健全性、境界、欠落箇所を返します。 |
| `GET /api/v1/apm/service-definitions` | 組織内のすべてのサービス定義を返します。 |
| `PUT /api/v1/apm/service-definitions/{service}?namespace=` | サービス定義を作成または置換します。`apm.definitions.manage` が必要です。 |
| `DELETE /api/v1/apm/service-definitions/{service}?namespace=` | サービス定義を削除します。`apm.definitions.manage` が必要です。 |
| `POST /api/v1/apm/service-definitions/{service}/key-transactions?namespace=` | エンドポイントにスターを付けてサービスのキートランザクションに指定するか、スターを外して指定を解除します。`apm.definitions.manage` が必要です。 |
| `PUT /api/v1/apm/errors/{fingerprint}/issue` | エラーグループのステータス、チーム、担当者を設定します。`apm.errors.manage` が必要です。 |
| `GET /api/v1/apm/error-rules` | 組織のエラーグループ化ルールを評価順に返します。 |
| `POST /api/v1/apm/error-rules` | グループ化ルールを作成します。新しいルールは既存のルールの後に評価されます。`apm.error_rules.manage` が必要です。 |
| `PUT /api/v1/apm/error-rules/{id}` | グループ化ルールを置換します。`apm.error_rules.manage` が必要です。 |
| `DELETE /api/v1/apm/error-rules/{id}` | グループ化ルールを削除します。`apm.error_rules.manage` が必要です。 |
| `PUT /api/v1/apm/error-rules/order` | ルールの評価順序を設定します。`apm.error_rules.manage` が必要です。 |
| `GET /api/v1/apm/slos` | すべてのサービスレベル目標について、ステータス、達成実績、残りのエラーバジェット、バーンレートを返します。 |
| `GET /api/v1/apm/slos/{id}` | 指定したサービスレベル目標のステータスと、評価期間内の日ごとのデータを返します。 |
| `POST /api/v1/apm/slos` | サービスレベル目標を作成します。`apm.slos.manage` が必要です。 |
| `PUT /api/v1/apm/slos/{id}` | サービスレベル目標を置換します。`apm.slos.manage` が必要です。 |
| `DELETE /api/v1/apm/slos/{id}` | サービスレベル目標を削除します。`apm.slos.delete` が必要です。 |
| `POST /api/v1/apm/deployments` | デプロイを報告します。`apm.deploy` が必要です。 |
| `GET /api/v1/apm/deployments` | パイプラインが報告したデプロイを新しい順に返します。 |
| `GET /api/v1/apm/settings` | 組織の APM 設定を返します。保存済みの設定がない場合は、デフォルト値を返します。 |
| `PUT /api/v1/apm/settings` | 組織の APM 設定を置換します。`apm.settings.manage` が必要です。 |

パスパラメーターは URL エンコードしてください。一覧レスポンスが返す `transaction` 名またはエラーの `fingerprint` の値をそのまま使用してください。

## 共通クエリパラメーター

| パラメーター | 型 | 動作 |
|---|---|---|
| `from` | 整数 | 範囲の開始時刻を Unix エポックからのマイクロ秒数で指定します。デフォルトは `to` の 24 時間前です。 |
| `to` | 整数 | 範囲の終了時刻を Unix エポックからのマイクロ秒数で指定します。デフォルトは現在時刻です。 |
| `namespace` | 文字列 | サービスの名前空間を完全一致で絞り込みます。 |
| `service` | 文字列 | サービス名を完全一致で絞り込みます。サービス詳細のパスで指定した値が優先されます。 |
| `environment` | 文字列 | デプロイ環境を完全一致で絞り込みます。 |
| `version` | 文字列 | サービスのバージョンを完全一致で絞り込みます。 |
| `resolution` | 列挙型 | `auto`、`minute`、または `hour` を指定します。`auto` は指定範囲のデータが保持されている解像度を選択します。 |
| `sort` | 文字列 | エンドポイントごとに定められたソートフィールドを指定します。 |
| `direction` | 列挙型 | `asc` または `desc` を指定します。デフォルトは `desc` です。 |
| `limit` | 整数 | ページサイズを 1～200 で指定します。デフォルトは 50 です。 |
| `cursor` | 文字列 | 以前の一覧レスポンスが返した不透明なカーソルを指定します。 |
| `status` | 列挙型 | `/errors` のみ：`all`（デフォルト）、`unresolved`（未対応、調査中、および解決後に再発したグループ）、`investigating`、`resolved`、`ignored` のいずれかを指定します。 |

フィルターには空でない 192 バイト以下の値を指定してください。範囲は設定された上限を超えないようにしてください。上限のデフォルトは 30 日です（`[apm].max_query_range_days`）。

### ソートフィールド

| エンドポイント | 指定可能な `sort` の値 | デフォルト |
|---|---|---|
| `/services` | `requestCount`, `errorRate`, `p95`, `name` | `requestCount` |
| `/transactions` | `requestCount`, `errorRate`, `p95`, `total_time` | `requestCount` |
| `/dependencies` | `requestCount`, `errorRate`, `p95`, `total_time` | `total_time` |
| `/errors` | `occurrenceCount`, `errorRate`, `lastSeen` | `occurrenceCount` |

`/overview` は同じフィルターと解像度を指定できますが、ページ分割は行いません。詳細、比較、健全性のエンドポイントは、ページ分割した一覧を返しません。

## 概要を取得する

<RequestExample>
```bash cURL
NOW=$(date +%s)000000
curl --get 'http://localhost:5080/api/v1/apm/overview' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode "from=$((NOW-86400000000))" \
  --data-urlencode "to=$NOW" \
  --data-urlencode 'environment=production' \
  --data-urlencode 'resolution=auto'
```
</RequestExample>

レスポンスには、`red`、`trend`、`serviceHealth`、`services`、`topTransactions`、 `topDependencies`、`topErrors`、`recentVersions`、共通の `meta` オブジェクト、および以下のフィールドが含まれます。

| フィールド | 説明 |
|---|---|
| `serviceCount`, `activeServiceCount` | 指定期間内に観測したサービス数と、そのうちリクエストを 1 件以上処理したサービス数です。 |
| `healthTrend` | 各スロットにおける状態別のサービス数です。指定期間を最大 48 個のスロットに分割します。スロットの長さはバケットの長さ以上です。スロット内にリクエストがないサービスは、そのスロットでは `noTraffic` としてカウントします。 |
| `rankings` | `slowest`（p95 順）、`mostErrors`（エラー率順）、`busiest`（リクエスト数順）に、それぞれ上位 5 サービスを返します。最初の 2 つはリクエストが 20 件以上のサービスのみを対象とします。 |
| `deployments` | 指定期間内に初めて観測したバージョンを新しい順に最大 20 件返します。各バージョンには、[サービスのバージョン](#サービスのバージョンを取得する)と同様に `red` と `verdict` が含まれます。 |
| `environments`, `availableEnvironments` | 表示対象の環境ごとのサービス数とリクエスト数、および `environment` フィルターに関係なく、対象サービスが稼働するすべての環境です。 |
| `instrumentation` | 言語別および SDK 別のサービス数と、`deployment.environment`、`service.version`、`service.instance.id` のそれぞれを報告していないサービス数です。 |

## インサイトを取得する

`GET /api/v1/apm/insights` は共通の期間パラメーターとフィルターパラメーターを受け取り、`meta` と以下のフィールドを返します。

| フィールド | 説明 |
|---|---|
| `now`, `previous`, `lastWeek` | 表示対象のサービスについて、指定期間、その直前の同じ長さの期間、および指定期間の 1 週間前の同じ期間の指標を返します。指標は `requestCount`、1 秒あたりのリクエスト数を示す `throughput`、`errorRate`、`p95Time`、`apdex` です。リクエストがない期間のフィールドは返しません。 |
| `insights` | 検出結果を緊急度の高い順に最大 30 件返します。 |

各検出結果には以下のフィールドが含まれます。

| フィールド | 説明 |
|---|---|
| `kind` | `anomaly`、`regression`、`slow_dependency`、`repeated_call`、`slowQuery`、`hot_endpoint` のいずれかです。 |
| `severity` | `critical`、`warning`、`info` のいずれかです。改善提案には `info` を使用します。 |
| `service` | `namespace`、`name`、`environment` です。 |
| `transaction`, `dependency` | ホットエンドポイントの場合は該当するエンドポイント、ボトルネック、繰り返し呼び出し、低速なステートメントの場合は該当する依存先です。 |
| `metric` | 変化または悪化したメトリクスです。`errorRate`、`p95`、`throughput` のいずれかです。 |
| `value` | 現在の値です。エラー率は比率、P95 はマイクロ秒、スループットは 1 秒あたりのリクエスト数で示します。ボトルネックまたはホットエンドポイントでは全体の時間に占める割合、繰り返し呼び出しではリクエストあたりの呼び出し回数、低速なステートメントではマイクロ秒単位の P95 を示します。 |
| `previous`, `lastWeek` | 直前の期間と 1 週間前の同じ期間における同じ指標の値です。リグレッションの場合は、直前のバージョンの値です。 |
| `since` | 変化が始まった時刻、またはリグレッションが発生したバージョンを初めて観測した時刻です。 |
| `version`, `previousVersion` | リグレッションが発生したバージョンとその直前のバージョンです。 |
| `calls`, `p95Time` | 改善提案の根拠となった呼び出し数またはリクエスト数と、その P95 です。 |
| `changes` | `since` の前後に発生した変更を、時刻が近い順に返します。各変更には `kind`、`source`（`reported` または `observed`）、`service`、`version`、`status`、`at`、`downstream`（メトリクスが変化したサービスが呼び出すサービスの場合は `true`）、`commit`、`description` が含まれます。 |

しきい値については、[インサイトと調査](/ja/apm/insights#インサイトの検出項目)を参照してください。

## サービスを一覧表示してページを切り替える

```bash
curl --get 'http://localhost:5080/api/v1/apm/services' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'namespace=shop' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'sort=p95' \
  --data-urlencode 'direction=desc' \
  --data-urlencode 'limit=50'
```

## RED メトリクスを取得する

各サマリーの `red` オブジェクトには、指定期間内のリクエスト数、エラー、処理時間に関する指標が含まれます。

| フィールド | 説明 |
|---|---|
| `requestCount`, `errorCount`, `errorRate` | リクエスト数、失敗したリクエスト数、および全リクエストに占める失敗したリクエストの割合（0〜1）です。 |
| `durationSum`, `durationAverage` | 処理時間の合計と平均です。単位はマイクロ秒です。リクエストがない場合、平均は `null` です。 |
| `p50Time`, `p90Time`, `p95Time`, `p99Time` | レイテンシーのパーセンタイル値です。対応する順位を含むヒストグラムバケット内で算出します。単位はマイクロ秒です。デフォルトのバケット構成では、実際の処理時間に対する誤差は約 4% 以内です。リクエストがない場合は `null` です。 |
| `apdex` | しきい値 T 以内のリクエスト数と、T を超えて 4T 以内のリクエスト数の半分を合計し、全リクエスト数で割った値（0〜1）です。T にはサービスの `apdexThreshold` を使用し、未設定の場合は 500 ms を使用します。概要で全サービスを集計する場合は 500 ms を使用します。失敗したリクエストは満足として扱いません。リクエストがない場合は `null` です。 |
| `latencyPartial` | バケットの情報からレイテンシーのバケット構成を判別できないものがある場合は `true` です。旧構成のバケット（`[apm.histogram].schema_version`）は変換して集計します。読み取れないバケットはパーセンタイルの算出から除外しますが、件数、合計、平均には含めます。 |
| `timeoutCount`, `retryCount` | タイムアウトしたリクエスト数（タイムアウトのエラータイプ、gRPC の `DEADLINE_EXCEEDED`、HTTP の 408 または 504）と、再送したリクエスト数（`http.request.resend_count` が 0 より大きいもの）です。該当するリクエストがない場合、そのフィールドは返しません。 |
| `statusCodes` | ステータスコード別のレスポンス数です。キーは `http:<code>`（100〜599）または `grpc:<code>`（0〜16）です。各バケットは最大 24 種類のコードを保持し、それ以外のコードは `http:other` または `grpc:other` に集計します。ステータスコードの集計を開始する前に作成した集計データなど、コードを 1 件も集計していない場合、このフィールドは返しません。 |
| `exemplars` | 指定期間内のサンプルスパンを、処理時間が長い順に最大 8 件返します。[テールサンプリング](/ja/configuration#トレースのキャプチャとテールサンプリング)がトレースの保持を判断する前にスパンを抽出するため、通常 `traceAvailable` は `false` です。トレースを検索して、保持されたかどうかを確認してください。集計値は引き続き有効です。 |

サービスとトランザクションのサマリーには、Apdex の計算に使用したしきい値 T を示す `apdexThreshold` が含まれます。サービスのサマリーには `health` と `healthReasons` も含まれます。`healthReasons` はしきい値を超えた各指標を `metric` （`errorRate` または `p95`）、`level`、`value`、`threshold` で示します。また、各バケットのリクエスト数、エラー数、p95 を示す `sparkline` と、直近に観測したバージョンを示す `currentVersion`、そのバージョンを初めて観測した時刻を示す `currentVersionSince` が含まれます。サービスまたはトランザクションの詳細には、レイテンシーのヒストグラムを示す `latencyDistribution` が含まれます。リクエストがあるバケットのみを返し、各バケットを `lowerTime`、`upperTime`、`count` で示します。範囲は最速と最遅のリクエストの処理時間に合わせて絞り込みます。

## サービス定義を保存する

サービス定義には、サービスの所有者と重要度を記録します。`namespace` とサービス名をキーとするため、すべての環境に適用されます。サービスがデータを送信する前でも作成できます。

```http
PUT /api/v1/apm/service-definitions/checkout?namespace=shop
Content-Type: application/json

{"description": "Takes orders and payments.", "teamId": "<team id>", "ownerId": "<user id>", "tier": "p0", "lifecycle": "production", "repositoryUrl": "https://github.com/acme/checkout", "tags": {"domain": "orders", "pci": ""}, "apdexThreshold": 300000, "aliases": ["order_service", "Order Center"], "dataSources": {"logs": [{"stream": "default", "filter": "service_name = 'order_service'"}], "metrics": [{"selector": "{service=\"checkout\"}"}], "dashboards": ["<dashboard id>"], "links": [{"name": "Runbook", "url": "https://wiki.example.com/checkout"}]}, "archived": false}
```

| フィールド | 説明 |
|---|---|
| `description` | 最大2,000文字です。 |
| `teamId` | 組織内のチーム、または `null` です。チームを削除すると、この値がクリアされます。 |
| `ownerId` | 組織内のメンバー、または `null` です。 |
| `tier` | 最も重要な `p0` から `p5` までのいずれか、または `null` です。 |
| `lifecycle` | `production`、`staging`、`experimental`、`deprecated`、または `null` です。 |
| `repositoryUrl` | `http`、`https`、`ssh`、`git`、`git+ssh` のいずれかの URL、`user@host:path`、または `null` です。空白は使用できず、最大2,048文字です。パスワードと HTTP(S) URL のユーザー名部分は `****` として保存します。サービスからリポジトリ情報が送信されない場合に表示します。 |
| `tags` | `{ "key": "value" }` 形式のタグを最大32個指定できます。キーは1〜64文字で、小文字の英字、数字、および `_ . - /` を使用できます。値は最大128文字で、前後に空白を含めることはできません。キーのみのタグには空の値を指定します。 |
| `apdexThreshold` | サービスの Apdex しきい値 T です。0より大きく60,000,000（1分）以下の値を指定できます。`null` の場合は500 msを使用します。 |
| `aliases` | ログ、メトリクス、その他のシステムで使われるサービスの別名を最大20個指定できます。各別名は1〜128文字で、前後に空白を含めることはできません。大文字と小文字は区別しません。同じ名前を複数回指定することも、サービス自体の名前や組織内の別のサービスの名前または別名を指定することもできません。省略すると、保存済みの定義にある別名を保持します。 |
| `dataSources` | サービスのデータソースです。`logs`（`stream` とオプションの `filter`。`filter` は最大2,000文字の真偽値を返す SQL 式）、`metrics`（`selector`。`{service="checkout"}` などの PromQL セレクター）、`dashboards`（ダッシュボード ID）、`links`（`name` と `http` または `https` の `url`）をそれぞれ最大10件指定できます。省略すると、保存済みの定義にあるデータソースを保持します。 |
| `archived` | `true` にすると、カタログのデフォルトビューにサービスを表示しません。省略すると、保存済みの定義にある状態を保持します。 |

定義を保存しても `keyTransactions` は変更されません。キートランザクションは1件ずつ変更します。レスポンスには、保存した定義とその `namespace`、`name`、`keyTransactions`、`updatedBy`、`updatedAt` が含まれます。 `DELETE` は `204` を返します。サービスに定義がない場合は `404` を返します。

### キートランザクションにスターを付ける

```http
POST /api/v1/apm/service-definitions/checkout/key-transactions?namespace=shop
Content-Type: application/json

{"transaction": {"name": "POST /orders", "kind": "http"}, "key": true}
```

`key: true` はエンドポイントを `keyTransactions` に追加し、`false` は削除します。現在と同じ状態を指定しても変更はありません。サービスに定義がない場合は作成します。キートランザクションは最大50件まで登録でき、上限超過分をまとめる行 `__other__` は登録できません。レスポンスには変更後の定義が含まれます。

## サービスのシグナルのカバレッジを取得する

`GET /api/v1/apm/services/{service}/coverage` には、必須の `namespace` と `environment` に加え、表示範囲の終了時刻をマイクロ秒単位で指定する `to`（オプション、デフォルトは現在時刻）を指定できます。`to` の直前1日間を調べ、各結果を5分間キャッシュします。

```json
{
  "from": 1792230096695000,
  "to": 1792316496695000,
  "logs": { "state": "reported", "found": ["default"] },
  "metrics": { "state": "missing" },
  "profiles": { "state": "reported", "found": ["cpu", "alloc_space"] },
  "rum": { "state": "unknown" }
}
```

| シグナル | `reported` になる条件 | `found` の内容 |
|---|---|---|
| `logs` | `service.name`、`service_name`、`service` のいずれかのフィールドを持つログストリームに、対象サービスのログ行が含まれています。`default` を最初に、最大8件のストリームを調べます。 | 該当するストリームです。 |
| `metrics` | `to` 時点の `count(last_over_time({"service.name"="<service>"}[1h]))` が0より大きい場合です。 | 時系列の数です。 |
| `profiles` | プロファイルストリームに対象サービスのプロファイルが含まれています。 | プロファイルタイプです。 |
| `rum` | ブラウザーアクションに、対象サービスの最新5件のサンプルトレースのいずれかが含まれています。 | 該当するセッションです。 |

`missing` は何も見つからなかったことを示します。`unknown` は、確認に失敗したか、3秒を超えたことを示します。`rum` が `missing` になることはありません。サンプルトレースから、セッションがサービスに到達したことは確認できますが、到達したセッションがないことまでは確認できません。

## サービスの実行情報を取得する

`GET /api/v1/apm/services` と `GET /api/v1/apm/services/{service}` は、各サービスのサマリーに `profile` を含めます。この情報は、指定範囲内にデータを送信したインスタンスから取得します。`version` を指定すると、そのバージョンのインスタンスのみを対象にします。各リストには、同じ値を持つインスタンスの数が多い順に最大5件を、次の形式で返します。 `{ "value": "1.8.2", "instances": 4 }`

| フィールド | 説明 |
|---|---|
| `instanceCount`, `hostCount` | インスタンス数と、一意の `host.name` の値の数です。 |
| `versions` | インスタンスが実行していたバージョンです。ロールアウト中は2つのバージョンを表示します。 |
| `languages`, `runtimes`, `frameworks` | `telemetry.sdk.language`、`process.runtime.name` とそのバージョン、エントリースパンの計装ライブラリが示すフレームワークです。 |
| `regions`, `clusters`, `k8sNamespaces`, `workloads` | `cloud.region`、`k8s.cluster.name`、`k8s.namespace.name`、および `k8s.deployment.name` または `k8s.statefulset.name` です。 |
| `repositories`, `commits` | 認証情報を除いて保存した `vcs.repository.url.full` または `git.repository_url` と、`vcs.ref.head.revision` または `git.commit.sha` です。 |
| `entryKinds` | サービスが処理するエントリーの種類です。`http`、`rpc`、`messaging`、`span` があります。 |

`GET /api/v1/apm/services/{service}/instances` は、インスタンスを最後に観測した時刻が新しい順に最大500件まで個別に返します。`namespace`、`environment` と、オプションの `version`、`from`、 `to` を指定できます。サービスまたは環境を指定しない場合は `400` を返します。各項目には `instanceId`（ `service.instance.id`、なければ `k8s.pod.name`、それもなければ `host.name`）、`version`、`firstSeenAt`、 `lastSeenAt`、インスタンスが最後に送信した属性のマップである `attributes`、および指定範囲内の処理を示す `red` と `sparkline` が含まれます。`red` の形式はサマリーと同じで、Apdex にはサービスのしきい値を使用します。上限を超えたインスタンスは、`instanceId` が `__other__` の1項目にまとめて集計します。指定範囲内で処理を行った時点で情報がまだ保存されていなかったインスタンスは、`attributes` を空にして一覧に含めます。

## エラーグループの状態を設定する

```http
PUT /api/v1/apm/errors/<fingerprint>/issue
Content-Type: application/json

{"status": "investigating", "assigneeId": "<user id>", "teamId": "<team id>", "lastSeenAt": 1792316496695000}
```

`status` は `open`、`investigating`、`resolved`、`ignored` のいずれかです。`assigneeId` は組織内のメンバーまたは `null`、`teamId` は組織内のチームまたは `null` です。オプションの `lastSeenAt` には、読み取り側が最後にグループを確認した時刻をマイクロ秒単位で指定します。 `resolved` に設定すると、その時刻を `resolvedAt` に記録します。

エラーサマリーは状態を `issue` として返します。状態が未設定の場合は `null` を返します。解決済みのグループが `resolvedAt` より後に再発すると `issue.regressed` は `true` になり、`unresolved` フィルターの結果に含まれます。プロジェクションに存在しないフィンガープリントの状態を設定しようとすると、`404` を返します。

## サービスレベル目標を管理する

サービスレベル目標（SLO）は、指定した環境のサービス全体、またはそのエンドポイントの 1 つを対象として、ローリングウィンドウ内で良好なリクエストが占める割合を保証します。各数値の意味については、[サービスレベル目標](/ja/apm#サービスレベル目標)を参照してください。

```http
POST /api/v1/apm/slos
Content-Type: application/json

{"name": "Checkout availability", "namespace": "shop", "service": "checkout", "environment": "production", "transaction": null, "kind": "availability", "objective": 0.999, "windowDays": 30}
```

| フィールド | 説明 |
|---|---|
| `name` | 必須です。最大 255 bytes です。 |
| `description` | オプションです。最大 2,000 bytes です。 |
| `namespace`, `service`, `environment` | 必須です。APM で使用するサービスの識別情報を指定します。`service.namespace` がないサービスは、名前空間 `default` に属します。 |
| `transaction` | 単一のエンドポイントを指定する場合は `{ "name": "POST /orders", "kind": "http" }` の形式を使用します。サービス全体を対象にする場合は `null` を指定します。 |
| `kind` | `availability`：失敗しなかったリクエストを良好と判定します。`latency`：失敗せず、所要時間が `latencyThreshold` 以下だったリクエストを良好と判定します。 |
| `latencyThreshold` | `latency` の場合は必須で、正の値を指定します。`availability` の場合は `null` を指定するか、省略します。 |
| `objective` | 良好なリクエストの割合です。`0.999` など、0 より大きく 1 未満の値を指定します。 |
| `windowDays` | `7`、`28`、または `30` を指定します。 |

`POST` と `PUT` は、保存した SLO を `id`、`createdBy`、`createdAt`、`updatedBy`、 `updatedAt` とともに返します。`GET /api/v1/apm/slos` は、組織内のすべての SLO をステータスとして返します。単一のサービスの SLO に絞り込むには、`namespace`、`service`、`environment` をまとめて指定します。ウィンドウは API 呼び出し時点で終了するため、共通の時間範囲パラメーターは適用されません。

| ステータスフィールド | 説明 |
|---|---|
| `slo` | 保存された SLO です。 |
| `state` | `healthy`、`at_risk`、`breached`、または `noData` です。 |
| `sli` | ウィンドウ内の全リクエストに占める良好なリクエストの割合です。リクエストがない場合は `null` です。 |
| `goodRequests`, `totalRequests` | `sli` の算出に使用するリクエスト数です。レイテンシー SLO では、レイテンシーのヒストグラムから `goodRequests` を推定するため、小数になる場合があります。 |
| `budgetRemaining` | `1 - (1 - sli) / (1 - objective)` です。目標を下回ると負の値になり、リクエストがない場合は `null` です。 |
| `burnRates` | `oneHour`、`sixHours`、`oneDay` は、それぞれ直近 1 時間、6 時間、24 時間の `(1 - sli) / (1 - objective)` です。リクエストがない場合は `null` です。 |

`GET /api/v1/apm/slos/{id}` は `status` と `history` を返します。`history` には、ウィンドウ内でリクエストがあった UTC の日ごとに 1 件のエントリが含まれます。エントリは古い順に並び、それぞれマイクロ秒単位の `dayStart`、`sli`、`goodRequests`、 `totalRequests` を含みます。

`DELETE` は `204` を返します。バーンレートアラートなど、その SLO を監視するアラートルールがある場合は `409` を返します。先にそれらのルールを削除してください。SLO のアラートルールは、メトリクスに `slo_burn_rate` を使用する APM ルールです。[ルールを作成する](/ja/api/alerting/create-rule#apm-ルール)を参照してください。

## トランザクションを一意に指定する

種類の異なるトランザクションが同じ名前を持つことがあります。対象の種類を選ぶには、オプションの `kind` パラメーターを指定します。

```http
GET /api/v1/apm/transactions/POST%20%2Fcheckout?kind=http&service=checkout
```

指定できる値は `http`、`rpc`、`messaging`、`span`、`other` です。複数のサービスや種類で同じ名前を使用している場合は、 `400` と次のメッセージを返します。`APM transaction identity is ambiguous; provide service, namespace, environment, and kind`。

## バージョンを比較する

`baseline` と `candidate` に異なる値を指定します。単一のサービスを比較するには、`service` フィルターを追加します。

```bash
curl --get 'http://localhost:5080/api/v1/apm/versions/compare' \
  --header "Authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'service=checkout' \
  --data-urlencode 'environment=production' \
  --data-urlencode 'baseline=2.3.1' \
  --data-urlencode 'candidate=2.4.0'
```

レスポンスの `baseline` と `candidate` には、それぞれ `version`、`sampleCount`、 `red` が含まれます。レスポンスには `delta`、`status`、`regressedTransactions`、`regressedErrors` も含まれます。各悪化項目のリストには最大 20 件のエントリが含まれます。

| フィールド | 説明 |
|---|---|
| `sufficientData` | 両方のバージョンが設定済みのサンプル数のしきい値を満たした場合にのみ `true` になります。デフォルトはバージョンごとに 1,000 リクエストです（`[apm.version_comparison].min_requests_per_version`）。 |
| `status` | `insufficient_data`、`regressed`、`improved`、または `neutral` です。比較対象のエラー率がベースラインより 1 ポイント以上上昇し、かつ 1.5 倍以上になった場合、または p95 が 20% 以上かつ 50 ms 以上増加した場合は `regressed` になります。いずれかが対応するしきい値以上に低下し、どちらもしきい値以上に増加していない場合は `improved` になります。`sufficientData` が `false` の場合は `insufficient_data` になります。 |
| `delta` | `requestCountAbsolute` と `requestCountRelative`、`errorRateAbsolute` と `errorRateRelative`、`p95AbsoluteTime` と `p95Relative` です。ベースラインがゼロまたは欠落している場合、相対値は `null` になります。 |

`candidate` または `baseline` が指定されていない場合や、同じバージョンを 2 つ指定した場合は、`400` を返します。

## サービスのバージョンを取得する

`GET /api/v1/apm/services/{service}` は、指定した時間範囲で観測したバージョンを `versions` として返します。各バージョンには、その範囲内の実績を示す `red` と、同じサービスで初回観測時点が直前のバージョンと比較した結果を示す `verdict` が含まれます。判定には[バージョン比較](#バージョンを比較する)と同じ基準を使用します。

| フィールド | 説明 |
|---|---|
| `previous` | 比較元のバージョンです。 |
| `status` | `regressed`、`improved`、`neutral`、または `insufficient_data` です。 |
| `worse` | `status` が `regressed` の場合に悪化した指標です。`errorRate`、`latency`、またはその両方です。 |
| `delta` | バージョン比較と同じ差分です。古い方のバージョンをベースラインとして使用します。 |

最初に観測したバージョンには `verdict` がありません。リクエストにバージョンフィルターを指定しても、集計対象は絞り込まれません。サービス全体からすべてのバージョンを取得します。

## エラーの発生箇所を確認する

`GET /api/v1/apm/errors` は、ページのデータとともに、`status` フィルターに一致するすべてのグループ（そのページに含まれるグループだけではありません）の `breakdown` を返します。`GET /api/v1/apm/errors/{fingerprint}` は、指定したグループの `breakdown` を返します。`breakdown` には `versions`、`environments`、`languages` が含まれ、それぞれ値を示す `value` と発生回数を示す `count` のリストを件数の多い順に並べます。スパンが値を報告していない場合、その値は空になります。上位 7 件以外の値は `__other__` にまとめて集計します。言語には、サービスの `telemetry.sdk.language` を使用します。

## エラーのグループ化ルールを管理する

ルールを使用すると、エラーの発生時に、種類、フレーム、エンドポイントによる標準の方法とは異なる方法でグループ化できます。 `position` の順にルールを評価し、最初に一致したルールを適用します。

```http
POST /api/v1/apm/error-rules
Content-Type: application/json

{"name": "Upstream timeouts", "serviceNamespace": "shop", "serviceName": "checkout",
 "errorType": "*Timeout*", "message": "", "frame": "", "endpoint": "", "action": "merge", "enabled": true}
```

| フィールド | 説明 |
|---|---|
| `name` | 最大 128 文字です。統合後のグループにはこの名前を使用します。 |
| `serviceNamespace`, `serviceName` | ルールを適用するサービスを指定します。`serviceName` が空の場合はすべてのサービスが対象です。名前空間を指定する場合は、サービス名も指定します。 |
| `errorType`, `message`, `frame`, `endpoint` | エラーの種類、例外メッセージ、最初のアプリケーションフレーム、エンドポイントに対応するパターンです。それぞれ最大 256 文字です。大文字と小文字を区別せず、テキスト全体に対して照合します。`*` は任意の文字列に一致します。空のパターンはすべての値に一致します。少なくとも 1 つのパターンを指定してください。 |
| `action` | `merge`：サービス内で一致したエラーを 1 つのグループにまとめます。`ignore`：一致したエラーをグループ化しませんが、そのリクエストは引き続き失敗としてカウントします。 |
| `enabled` | 無効にしたルールは保存しますが、評価しません。デフォルトは `true` です。 |

レスポンスは、ルールを `id`、`position`、`updatedBy`、`updatedAt` とともに返します。組織ごとに最大 100 件のルールを保存できます。`PUT /api/v1/apm/error-rules/order` は `{"ids": [...]}` を受け取り、指定したルールを指定順に先頭に並べ、残りのルールをその後に配置して、新しい順序でルールを返します。

変更は保存したノードでは即座に、他のノードでは 30 秒以内に反映し、反映後に観測したエラーに適用します。すでに作成したグループは変更しません。

## サービスマップを取得

`GET /api/v1/apm/map` は、共通の期間パラメーターと `environment`、`namespace` を受け取り、 `nodes`、`edges`、`namespaces`（環境内のサービスの名前空間）、`environments`（すべての環境）、 `truncated`（トラフィック量が多い上位400ノードだけを残した場合は `true`）を返します。

| フィールド | 説明 |
|---|---|
| `nodes[].id` | `service:<name>`、`topic:<name>`、またはサービスの呼び出し先を示す `<category>:<target>` です。 |
| `nodes[].kind` | `service`、`external`、または `topic` です。外部ノードには `category` も含まれます。 |
| `nodes[].red` | `requestCount`、`errorCount`、`errorRate`、`p95Time` です。サービスが処理したリクエスト、または外部ノードやトピックが受けたリクエストの指標です。サービスには `health`、`namespace`、`environments` も含まれます。 |
| `edges[].kind` | `call`、`publish`（トピックへの発行）、または `consume`（トピックからの読み取り）です。 |
| `change` | エッジまたはノードを、同じ長さの直前の期間と比較します。以前は存在しなかった場合は `new`、現在は存在しない場合は `gone` です。直前の期間にデータがない場合、このフィールドは含まれません。 |

サービス間の呼び出しデータはサービスグラフから取得し、最も遅かった1分間のP95を使用します。それ以外のデータは APMバケットから取得します。`GET /api/v1/apm/map/edge` は、同じパラメーターに加えてノードIDの `source` と `target` を受け取り、 `kind`、`red`、`trend`、`operations`（`name`、`kind`、`red`）、`everyCaller` （すべての呼び出し元からの呼び出しを対象に、呼び出し先サービスのエンドポイントを `operations` に含める場合は `true`）、および呼び出し先サービスのエラーグループを示す `errors` を返します。

## サービスの影響範囲を取得

`GET /api/v1/apm/blast-radius` は、必須の `service` と、共通の期間パラメーターおよび `environment` を受け取ります。名前空間に関係なく、環境全体のサービスマップを参照し、 `meta`、`service`（対象サービス自体のノード。指定期間のマップに存在しない場合は省略）、 `upstream`（対象サービスの呼び出し元、最大3ホップ）、`downstream`（対象サービスの呼び出し先または発行先、最大2ホップ）を返します。上流と下流にはそれぞれ最大30ノードを含め、異常のあるノードを先に並べます。直前の期間には存在したものの、現在は存在しない呼び出しは除外します。

| フィールド | 説明 |
|---|---|
| `id`, `kind`, `name`, `namespace`, `category` | [サービスマップ](#サービスマップを取得)と同じノード情報です。 |
| `hops` | ノードと対象サービスの間の呼び出しのホップ数です。直接の呼び出し元または呼び出し先は `1` です。 |
| `via` | そのノードに到達する際に経由するノードです。対象サービスに1ホップ近い位置にあります。 |
| `health` | サービス自体の正常性です。呼び出し先の場合は、そのノードへの呼び出しの失敗状況に基づく正常性です。 |
| `red`, `call` | ノードが処理または受信したリクエストの指標と、そのノードと `via` の間の呼び出し情報です。 |

## デプロイを報告・一覧取得

`POST /api/v1/apm/deployments` はデプロイ情報をJSONで受け取り、`201` と、`id`、 `createdBy`、`createdAt` を追加したデプロイ情報を返します。フィールド、制限、CIの例については、 [デプロイ](/ja/apm/deployments#ci-からデプロイを報告する)を参照してください。サービス名と環境名には、組織の命名ルール、環境マッピング、エイリアスを適用します。リポジトリのアドレスは、パスワードをマスクして保存します。設定変更や機能フラグの場合は、 `kind` を `configuration` または `feature_flag` に設定します。`version` は不要です。

`GET /api/v1/apm/deployments` は `service`、`namespace`、`environment`、および期間をマイクロ秒単位で指定する `from` と `to` を受け取り、最新のデプロイから順に最大200件を返します。報告時に名前空間や環境を指定しなかったデプロイは、指定しなかった項目のすべての値に対して一覧に表示します。

## APM設定を取得・保存

`GET /api/v1/apm/settings` は組織の設定を返します。`PUT` は設定全体を置き換え、保存した設定を返します。

```json
{
  "health": {
    "errorRateWarning": 0.02,
    "errorRateCritical": 0.1,
    "p95WarningTime": 500000,
    "p95CriticalTime": 2000000
  },
  "apdexThreshold": 500000,
  "longTaskTime": 1000000,
  "namingRules": [{ "pattern": "^(checkout)-[a-z0-9]{5}$", "replacement": "$1" }],
  "environmentMap": [{ "from": "Production", "to": "production" }],
  "aliases": [{ "aliasNamespace": "shop", "alias": "checkout-v1", "namespace": "shop", "service": "checkout" }],
  "metadataRules": { "teamFromTier": "p1", "ownerFromTier": "p0", "repositoryFromTier": null }
}
```

省略したフィールドにはデフォルト値を使用します。名前の前後にある空白を削除し、エイリアスの名前空間が空欄の場合は `default` を使用します。制限と各設定の詳細については、[APM設定](/ja/apm/settings)を参照してください。保存したノードには設定を即座に適用し、他のノードには30秒以内に適用します。

プラットフォームのカーディナリティ上限は、`GET` と `PUT /api/v1/settings/apm_limits` で取得および置き換えができます。どちらにも `sys.settings.limits.manage` が必要です。リクエストボディには `servicesPerOrgHour`、`transactionsPerServiceHour`、`dependenciesPerServiceHour`、 `operationsPerDependencyHour`、`errorGroupsPerServiceHour`、`versionsPerServiceHour`、 `instancesPerServiceHour` を指定します。各フィールドの範囲は1〜100000です。

## レスポンスのメタデータを確認

すべてのエンドポイントは共通の `meta` オブジェクトを返します。

```json
{
  "range": {
    "from": 1785801600000000,
    "to": 1785888000000000
  },
  "resolution": "minute",
  "projectionStartedAt": 1785798000000000,
  "lastCompleteBucketAt": 1785887940000000,
  "dataQuality": {
    "partial": false,
    "gaps": [],
    "overflowDimensions": []
  },
  "activationBoundary": false
}
```

- `activationBoundary: true` の場合、`projectionStartedAt` より前の期間はデータ収集範囲が不完全として扱ってください。
- `dataQuality.partial: true` の場合、データが完全に揃った結果のゼロではなく、不完全なデータとして扱ってください。
- キュー、リポジトリ、フラッシュ、データの遅延到着、カーディナリティ、シャットダウンに起因する欠損がないか、`gaps` を確認してください。
- 最新のデータがまだ確定していないかどうかは、`lastCompleteBucketAt` で判断してください。
- カーディナリティの高い項目別の内訳を利用する前に、`overflowDimensions` を確認してください。

## エラー

| ステータス | 原因 |
|---|---|
| `400` | パラメーターが無効です。サポート対象外の `sort`（`unsupported APM sort field`）、1〜200の範囲外の `limit`、空またはサイズ上限を超えたフィルター（`invalid APM service filter`）、上限を超えた期間（`APM query range exceeds configured maximum`）、開始より前の終了（`APM range end precedes start`）、不明な `direction` または `resolution`、上記の検証条件を満たさないSLO（`SLO objective must be between 0 and 1, exclusive`）、または `namespace`、`service`、`environment` のいずれかが欠けているSLO一覧フィルターが原因です。 |
| `403` | トークンに、この呼び出しに必要な権限がありません。 |
| `404` | 指定期間内に、該当するエラーのフィンガープリント、トランザクション、サービス、またはSLOが存在しません。 |
| `409` | 削除対象のSLOを監視しているアラートルールが残っています。 |
