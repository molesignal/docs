MoleSignal はバージョン管理された HTTP API を公開しています。プロダクトのエンドポイントは `/api/v1` を使用します。ヘルスプローブ、Prometheus メトリクス、公開共有リンク、および一部の互換プロトコルは、別のパスも使用します。

## ベース URL

ローカルインスタンスの場合:

```text
http://localhost:5080/api/v1
```

本番環境では、ホストをデプロイメントの公開アドレス（`[http].external_url` の値）に置き換えます。

## 認証

保護されたエンドポイントは、`Authorization` ヘッダーでベアラートークンを受け付けます:

```http
Authorization: Bearer <token>
```

| トークン | 取得方法 | 有効期間 |
|---|---|---|
| API トークン | **アカウント設定 → API トークン**、または [API トークンを発行する](/ja/api/auth/issue-token)。トークンは `mspat-<36>` の形式です。 | 失効するまで、または選択した有効期限が切れるまで。 |
| デフォルトの取り込みトークン | `GET /api/v1/me/api-tokens/default`。`logs.write`、`metrics.write`、`traces.write`、`profiles.write`、および `apm.deploy` に限定されます。 | 有効期限はありません。 |
| RUM クライアントトークン | `GET /api/v1/auth/tokens/rum?applicationId=<id>`。`rum.write` に限定されます。 | 有効期限はありません。 |

スクリプトやコレクターには API トークンを使用します。取り込みトークンについては [データソース](/ja/intake#取り込みトークン) を参照してください。

Web UI は `POST /api/v1/auth/signin` でサインインし、トークンを返す代わりにセッション Cookie を設定します。`Authorization` ヘッダーはセッショントークンを受け付けません。詳細は [ログイン](/ja/api/auth/login) を参照してください。

認証により、サブジェクト、アクティブな組織またはプラットフォームのスコープ、および有効な権限を含む IAM コンテキストが構築されます。リクエストの組織は常にこのコンテキストから決まります。リクエストボディで別の組織を選択することはできません。

## パブリックルートと自己認証ルート

一部のルートでは組織のベアラートークンを使用できません。代わりに、より限定的な資格情報またはポリシーを検証します:

- サインイン、サインアップポリシー、パスワードリセット。
- `GET /api/v1/healthz` と最上位の `/metrics`。
- 公開リソース共有の交換と共有セッションのリクエスト。
- 署名付きファイルダウンロードと公開アバター。
- プッシュトークンを検証するプッシュコネクターのエンドポイント。

パブリックルートが無制限というわけではありません。そのハンドラーは、サインアップポリシー、共有トークン、ダウンロードトークン、署名、またはコネクターの資格情報を検証します。

## 認可

エンドポイントは、次のいずれか 1 つ以上の条件を要求する場合があります:

- `streams.query` などの組織の権限。
- `sys.telemetry.read` などのプラットフォームの権限。
- リソースの所有権、リソースとの関係、または組織をまたぐ付与。

`GET /api/v1/iam/capabilities` は、現在のサブジェクトの有効な権限を返します。ロール名や表示されているメニュー項目からアクセス権を推測しないでください。

## リクエスト

- ほとんどのボディは `Content-Type: application/json` の JSON です。
- 互換性の取り込みエンドポイントは、Protobuf、NDJSON、gzip 圧縮されたボディなど、そのプロトコルのペイロードを使用します。
- 取り込みリクエストのボディが 2 MiB を超える場合（ネイティブ JSON 取り込みでは 16 MiB）は、`413` で拒否されます。
- 時刻は Unix エポックからのマイクロ秒単位の整数です。ある瞬間は発生した事象にちなんで命名され（`createdAt`、`expiresAt`）、1 語だけでは不明確な場合は `Time` を付けます（`startTime`）。期間の長さは、名前自体が示していない限り（`duration`）、`Time` で終わります（`p95Time`）。ネイティブのテレメトリレコードは `_timestamp` を使用し、これもマイクロ秒単位です。
- パスの ID とストリーム名は URL エンコードします。

## レスポンスとエラー

成功レスポンスは、エンドポイントがストリーミングまたはファイルのダウンロードを行う場合を除き、JSON です。エラーレスポンスはステータスコードと、機械可読な `error` コードおよび `message` を含む JSON ボディで構成されます:

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

`validation_failed` エラーには、無効なフィールドごとに 1 つのエントリを持つ `issues` 配列が追加されます。

| ステータス | `error` | 意味 |
|---|---|---|
| `400` | `invalid_argument`、`validation_failed` | リクエストまたはそのパラメーターのいずれかが無効です。 |
| `401` | `unauthorized` | トークンが欠落している、形式が不正、無効、または期限切れです。 |
| `403` | `forbidden` | 権限、関係、またはスコープが不足しています。 |
| `404` | `not_found` | リソースが存在しないか、認可されたスコープ内で表示されません。 |
| `409` | `conflict` | 状態または一意性の競合です。 |
| `413` | `payload_too_large` | ボディが上限を超えています。 |
| `429` | `resource_exhausted` | レート制限が適用されています。`Retry-After` ヘッダーがある場合はそれに従ってください。 |
| `499` | `cancelled` | リクエストがキャンセルされました。 |
| `503` | `unavailable` | 依存先が利用できません。 |
| `500` | `internal` | 内部障害です。ボディには `internal error` というメッセージが含まれ、詳細はサーバーログに残ります。 |

ボディを解析できないリクエストは、エンドポイントに到達する前に失敗します。そのレスポンスは JSON ではなくプレーンテキストになります:

| ステータス | 意味 |
|---|---|
| `400` | ボディが有効な JSON ではありません。 |
| `415` | リクエストに `Content-Type: application/json` がありません。 |
| `422` | フィールドが欠落しているか、型が正しくありません。テキストにそのフィールド名が示されます。 |

すべてのレスポンスには `X-Request-Id` と `X-Trace-Id` ヘッダーが付きます。サーバー側の障害を報告する際は、両方を含めてください。

## ページネーション

多数の行を返す可能性があるエンドポイントは、`limit` と `cursor` を受け付けます。そのようなレスポンスには `items` と `nextCursor` が含まれます。次のページを読み取るには `nextCursor` を `cursor` として渡し、空になったら停止します。その他のリストエンドポイントは完全なリストを返します。各エンドポイントのページを参照してください。

## クエリと長時間実行される処理

クエリファミリーは、通常の JSON を返す、NDJSON をストリーミングする、および長時間のクエリを非同期の検索ジョブとして実行する、という動作を行います。大きすぎるクエリには `202` と `jobId`、および `monitor` パスで応答します。ストリーミングを行う呼び出し元は、部分的な配信を処理し、結果が不要になった時点でリクエストをキャンセルする必要があります。詳細は [クエリ](/ja/query) を参照してください。

生成されたレポート、プロファイルの BLOB、エクスポートなどの大きな成果物は、JSON ボディ内ではなく、スコープ付きのダウンロードトークンを介してファイルとして配信されます。
