**ホーム**は、個人のスタートページを変更していない場合に、サインイン後に最初に開くページです。システムの現在の状態を確認できます。上部のステータスバーに続き、優先して確認すべきサービスと進行中のインシデント、取り込み中のシグナル、外形監視チェック、アカウントのオンコールシフトが表示されます。すべてのメンバーがこのページを開けますが、各セクションに表示される情報はアカウントの権限によって異なります。

## ページ上部

時間範囲を選ぶと、ページ上のすべての数値の集計期間が切り替わります。**過去1時間**（デフォルト）、 **過去24時間**、**過去7日間**から選択できます。選択した範囲は URL（`?window=24h`）に保持されるため、リンクを開くと同じビューが表示されます。ページは1分ごとにすべてのデータを再取得します。更新ボタンを押すとすぐに再取得します。

未完了のセットアップ手順がある場合は、時間範囲の手前に残りの手順数を示すボタンが表示されます。このボタンから [クイックスタート](#クイックスタート)を開きます。

## システムステータス

ステータスバーの先頭には、**すべてのシステムは正常です**、または問題の件数が表示されます。問題には、進行中のインシデント、失敗・劣化・不安定のいずれかの状態にあるチェック、警告または重大のしきい値を超えたサービス、取り込みが遅延または失敗しているシグナルが含まれます。重大な問題が1件でもある場合は赤色で表示します。重大な問題とは、重大またはエラーのインシデント、失敗したチェック、重大状態のサービス、取り込みに失敗したシグナルです。それ以外の場合は黄色で表示します。隣には、集計期間と最終取得時刻に加え、ログ、メトリクス、トレース、プロファイルの各シグナルの状態が表示されます。

各タイルを選択すると、対応する詳細ページが開きます。

| タイル | 表示内容 |
|---|---|
| **進行中のインシデント** | オープン中および確認済みのインシデントの重大度別件数と、未確認の件数です。[アラート](/ja/alerting/incidents)を開きます。 |
| **発報中のルール** | 有効なルールの総数に対する発報中のルール数と、保留中のルール数です。ルールの一覧を開きます。 |
| **正常なサービス** | 集計期間内に観測された全サービスに対する、しきい値を超えていないサービスの数と、重大、警告、アイドルの各状態のサービス数です。[APM](/ja/apm)を開きます。 |
| **合格したチェック** | 実行中の全チェックに対する合格数と、失敗、劣化、不安定の各状態のチェック数です。[外形監視](/ja/synthetics)を開きます。 |
| **エラー率** | 全サービスのリクエストに占める失敗の割合、リクエスト数、トレンドです。 |
| **P95 レイテンシ** | 全サービスのリクエスト処理時間の95パーセンタイル、P50、P99、トレンドです。 |

タイルは、対応するページを開く権限があるアカウントにのみ表示されます。トレースを受信していない間は、 APM のタイルにダッシュが表示されます。

## サービス

**サービス**には最大8件のサービスが表示されます。重大、警告、正常の順に並び、正常なサービスはリクエスト数順に表示されます。各行には、環境、稼働状態、集計期間内のリクエスト数とスループット、エラー率、P95 が表示されます。サービスのしきい値を超えた数値は、該当するしきい値の色で表示されます。サービスを選択すると APM で詳細が開き、**すべて表示**を選択するとサービス一覧が開きます。

## 進行中のインシデント

**進行中のインシデント**には、オープン中および確認済みのインシデントが最大6件表示されます。重大度の高い順に並び、重大度が同じ場合は、オープンからの経過時間が長い順に表示されます。各行には、重大度、影響を受けた最初のサービス、オープンからの経過時間、担当者が表示されます。**確認済みにする**を選択すると、オープン中のインシデントを一覧から確認済みにできます。権限がないアカウントには、代わりにインシデントの状態が表示されます。

## データ取り込み

**データ取り込み**には、シグナルごとに状態、最終受信時刻、集計期間内の時間バケットごとの取り込み量、集計期間内の行数が表示されます。パネル下部には、データを受信したストリームの数、保存したデータ量、受信したデータ量が表示されます。**ストリーム**を選択すると[ストリーム](/ja/streams)が開きます。

| 状態 | 意味 |
|---|---|
| **標準** | シグナルのストリームのうち、少なくとも1つが過去15分間にデータを受信しました。 |
| **遅延** | シグナルのストリームにデータはありますが、過去15分間はデータを受信していません。 |
| **失敗** | ノードの取り込みプローブが異常を報告しています。 |
| **データなし** | 集計期間内にデータがあるストリームは、このシグナルにはありません。 |

## 外形監視

**外形監視**には、集計期間内の各チェックの可用性とトレンドが表示されます。失敗、劣化、不安定のいずれかの状態にあるチェックは、状態が悪い順に最大4件表示されます。すべて合格している場合は、合格したチェックの件数が表示されます。 **すべて表示**を選択するとチェックの一覧が開きます。

## 自分のオンコール

**自分のオンコール**には、ワークスペースの[オンコールスケジュール](/ja/alerting/on-call)に基づいて、次の情報が表示されます。

- アカウントがシフトを担当中の場合は、**オンコール**と引き継ぎ時刻が表示されます。担当中でなく、今後30日以内にシフトがある場合は、**次回のシフト**とその開始・終了時刻が表示されます。
- 現在の担当者が別のメンバーの場合は、そのメンバーが表示されます。一時的な上書きで担当している場合は、代わりに担当している相手も表示されます。
- スケジュールに現在の担当者がいない場合は、その旨が表示されます。**今すぐ割り当て**を選択すると、一時的な上書きを追加するためのスケジュールが開きます。
- アカウントがシフトを担当中でもアラートを受信できない場合は、その旨が表示されます。**通知を設定**を選択すると、アカウントの[通知設定](/ja/account#通知)が開きます。
- **スケジュール**を選択すると、シフトのスケジュールが開きます。

## クイックスタート

ページ上部のボタンには、セットアップの残りの手順数が表示されます。ボタンを選択すると、手順の一覧が開きます。

| 手順 | 完了条件 |
|---|---|
| **データソースを接続** | ワークスペースに[プラットフォームストリーム](/ja/streams#プラットフォームストリーム)以外のストリームがあります。 |
| **サンプルデータを読み込む** | サンプルのストリーム、ダッシュボード、4つの保存済みビューが作成されています。 |
| **ダッシュボードを作成** | ワークスペースにダッシュボードがあります。 |
| **アラートを作成** | ワークスペースにアラートルールがあります。 |
| **オンコールスケジュールを設定** | ワークスペースに[オンコールスケジュール](/ja/alerting/on-call)があります。 |
| **通知チャネルを追加** | ワークスペースに、直近のテストで失敗していない有効な[コネクター](/ja/notification-channels)があります。 |
| **AI モデルを接続** | ワークスペースに、API キーを設定した有効な[モデルプロバイダー](/ja/agent)があります。 |
| **パイプラインを自動化** | ワークスペースにパイプラインがあります。 |

各手順の表示は、サインイン中のアカウントの権限によって異なります。状態を参照する権限またはページを開く権限がない手順は表示されません。参照できても実行できない手順は、完了後にのみ表示されます。

**サンプルデータを読み込む**は、まだ確認できるデータがないワークスペース向けです。ワークスペースに独自のストリームがある場合や、ストリーム一覧を参照する権限がない場合は表示されません。サンプルデータを読み込むと、この手順は完了済みとして残り、**データソースを接続**も同時に完了します。既存のデータがあるワークスペースにサンプルデータを読み込むには、 [クイックスタートに記載のリクエスト](/ja/quickstart#サンプルデータを読み込む)を送信してください。

**読み込む**を選択すると、関連する少量のサンプルデータを3つのストリーム（`sample_app_logs`、 `sample_app_metrics`、`sample_app_traces`）に書き込みます。トレースは `frontend` から `checkout` と `payment` を経由して `db` に至る呼び出しを記録します。ログには同じ `trace_id` が含まれ、メトリクスには各サービスのレイテンシが記録されるため、トレースから関連するログにすぐ移動できます。読み込み時には、 3つのストリームを対象とするダッシュボードと、 `sample_app_logs` を対象とするピン留め済みの[保存済みビュー](/ja/saved-views)を4つ作成し、ダッシュボードを開きます。いずれも過去3時間のデータを表示します。データは 1回だけ書き込まれ、読み込み時点より前のタイムスタンプが付くため、読み込みから3時間経過すると、ダッシュボードと保存済みビューにはデータが表示されなくなります。

再度読み込むと、現在時刻のデータが追加されます。既存のダッシュボードと保存済みビューは、編集内容も含めてそのまま保持し、不足しているものだけを作成します。読み込みが途中で止まった場合も、再実行できます。読み込みには `logs.write`、`metrics.write`、`traces.write`、`dashboards.create`、 `saved_views.create` が必要です。書き込みを開始する前に、5つすべての権限を確認します。

## 権限

ホームを開くのに権限は必要ありません。各エリアの読み取り権限があれば、対応する部分を読み込めます。

| 権限 | 対象 |
|---|---|
| `alerts.incidents.read` | **進行中のインシデント**、そのタイル、総合判定における該当部分。 |
| `alerts.incidents.acknowledge` | **進行中のインシデント**の**確認済みにする**。 |
| `alerts.rules.read` | **発報中のルール**。 |
| `apm.services.read` | **サービス**、**正常なサービス**、**エラー率**、**P95 レイテンシ**。 |
| `synthetics.monitors.read` | **外形監視**と**合格したチェック**。 |
| `synthetics.results.read` | **外形監視**の可用性とその推移。 |
| `streams.query` | **データ取り込み**とステータスバーのシグナルの状態。 |
| `schedules.read` | **自分のオンコール**。この権限がない場合、パネルは表示されません。 |
| `notify.policies.read` | **自分のオンコール**で、アカウントがアラートを受信できないことを示す注記。 |
| `notify.connectors.read`, `agent.models.read`, `pipelines.read` | クイックスタートの対応する手順。 |
| `logs.write` | クイックスタートの**読み込む**。 |
