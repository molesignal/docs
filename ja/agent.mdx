**Mole Agent** は、製品に組み込まれた運用エージェントと、そのワークスペースです。

Mole Agent は、ログ、メトリクス、トレース、RUM、プロファイル、アラート、オンコールデータ、レポートを照会できます。その際、サーバーに登録されたツールと、サインイン中のユーザーの組織および権限を使います。モデルが指定した組織識別子は無視します。

## モデルプロバイダーを設定する

Mole Agent がチャットで応答するには、モデルプロバイダーが必要です。`agent.models.manage` 権限を持つ管理者が追加します。

1. **Mole Agent → 設定 → モデルと推論**を開き、**モデルプロバイダーを追加**を選択します。
2. **プロバイダーの種類**として、OpenAI、Anthropic、OpenAI 互換エンドポイントのいずれかを選択します。
3. **表示名**、**デフォルトモデル**、**API キー**を入力します。キーは書き込み専用で、設定画面にも API のレスポンスにも表示しません。
4. OpenAI 互換エンドポイントを使用する場合は、**ベースURL**を設定します。OpenAI または Anthropic の公式エンドポイントを使用する場合は、空欄のままにします。
5. プロバイダーのデフォルト値が適さない場合は、**無応答タイムアウト**と**最大出力トークン数**を調整します。使用状況にコストを表示するには、**通貨**を選択して単価を入力し、保存します。

**無応答タイムアウト**は、モデルプロバイダーからデータを受信しないまま、呼び出しを失敗と判定するまでの時間です。デフォルトは 120000 ms で、1000 ～ 600000 ms の範囲で設定できます。ストリーミングを使用しない呼び出しでは応答全体を待つため、最も時間のかかる応答も受け取れる値を設定してください。接続に失敗した場合や、レート制限 (429) または一時的な障害 (5xx、529) が発生した場合は、応答を受け取る前に限り、2 回再試行します。プロバイダーが `Retry-After` を返した場合は、指定された時間だけ待ってから再試行します。Anthropic プロバイダーで**最大出力トークン数**を設定しない場合は、4096 を使用します。

単価は、プロバイダーの**通貨**で 100 万トークンあたりの金額を指定し、そのプロバイダーの全モデルに共通で適用します。設定項目は、**入力単価（キャッシュなし）**、プロバイダーがキャッシュから提供する入力に適用する**入力単価（キャッシュあり）**、**出力単価**です。キャッシュヒットに別の単価を適用するプロバイダーの場合のみ、キャッシュありの単価を入力します。それ以外の場合は、すべての入力にキャッシュなしの単価を適用します。単価を空欄にするとコストの計算だけを省略し、使用状況と予算の機能はそのまま動作します。

選択できる通貨は、モデルプロバイダーの下にある**通貨**セクションで管理します。`agent.usage.manage` 権限を持つ管理者が ISO 4217 コードで通貨を追加します。標準の名前や記号が適さない場合は、名前と記号を指定します。モデルプロバイダーが使用中の通貨は削除できません。削除した通貨で記録済みのコストは、引き続きその通貨で表示します。`agent.usage.read` 権限がない場合、セクションは表示されず、**通貨**も変更できません。新規プロバイダーには USD を使用し、既存のプロバイダーでは現在の通貨を維持します。

モデルの呼び出しは Model Gateway を経由します。編集時に保存済みのキーを維持するには、キー欄を空欄のままにします。キーをローテーションするには、新しい値を入力します。この操作には `agent.models.rotate` 権限が必要です。この権限があり、`agent.models.manage` 権限がない場合は、キー欄のみ変更できます。環境変数 `MS_AGENT_OPENAI_API_KEY`、`MS_AGENT_ANTHROPIC_API_KEY`、`MS_AGENT_COMPATIBLE_API_KEY` は、開発時のフォールバックとして使用します。[設定](/ja/configuration#環境変数)を参照してください。

## チャット

**Mole Agent → チャット**を開き、利用可能なモデルを選択して時間範囲を設定し、症状を入力します。調査のコンテキストとして、サービス、アラート、環境、ストリームのいずれかをピン留めします。

有効な AI モデルがない場合、メッセージ入力欄の上にその旨が表示されます。 `agent.models.manage` 権限を持つ管理者は、そこにあるリンクから**モデルと推論**を開きます。

回答には、次の内容が含まれることがあります。

- わかりやすい言葉でまとめた結論
- ツールの呼び出しと根拠の要約
- 根拠となったログ、メトリクス、トレース、インシデントへのリンク
- トークンとモデルコストのメタデータ（モデルプロバイダーが料金を設定している場合はコストも表示）
- 再現性を確保するためのプロンプトテンプレートのバージョンとコンテンツハッシュ

回答の下部には、左側に**コピー**、**フォーク**、**ピン留め**、回答時刻が表示されます。右側のゲージは回答の確信度を示します。確信度が高いほどゲージが長く伸び、先端の色が緑に近づきます。ゲージにカーソルを合わせるとレベルが表示されます。その右に**役に立った**と**役に立たなかった**が並びます。**フォーク**を選ぶと、その回答までのメッセージを引き継いだ新しいチャットが作成され、元のチャットの下に表示されます。**ピン留め**を選ぶと、自分の画面で回答がチャットの上部に固定されます。

回答の下で**役に立った**または**役に立たなかった**を選択します。**役に立たなかった**を選ぶと、理由（結論や原因が誤っている、問題を特定できなかった、提案を実行できない、話題がずれている、その他）を選択し、任意でコメントを入力できます。評価できるのは質問を送信した本人だけです。同じ評価をもう一度選ぶと取り消せます。評価には、回答に使用したモデルとプロンプトのバージョンが記録されます。

組織の当日のトークン使用量が予算の警告しきい値に達すると、メッセージ入力欄の上に通知が表示されます。予算を使い切った場合の動作については、[使用量と予算](#使用状況と予算)を参照してください。

サイズの大きいツールの生データはオブジェクトストレージに保存されます。チャットを削除する際は、まずベストエフォートで会話履歴のアーカイブを試みます。

### メッセージを入力する

メッセージ入力欄には送信時の書式が反映されます。`- ` はリスト、`1. ` は番号付きリスト、`# ` は見出し、`> ` は引用、`[ ] ` はタスク、```` ``` ```` はコードブロックを開始します。`**bold**` と `` `code` `` は入力と同時に書式が適用されます。**Enter** で送信します。リストやコードブロック内で **Enter** を押すと入力を続けられ、空のリスト項目で押すとリストを終了します。**⌘ Enter** または **Ctrl Enter** なら、入力位置に関係なく送信できます。**Shift Enter** で改行します。Markdown を貼り付けると書式が保持されます。書式を適用せずに貼り付けるには、プレーンテキストとして貼り付けます（**⌘ Shift V** または **Ctrl Shift V**）。メッセージは Markdown として送信されます。

### 実行モード

メッセージ入力欄の下にあるモードで、チャット内で Mole Agent が実行できる操作を設定します。メニューを開いている間は、数字キーの 1〜5 でモードを選択できます。

| モード | 実行する操作 |
|---|---|
| **提案モード**（推奨） | データをクエリし、変更を提案しますが、適用はしません。 |
| **調査モード** | 必要に応じて読み取り専用クエリを実行します。変更は行いません。 |
| **承認後に実行** | クエリを実行します。変更は、ツールの実行モードに従って、事前に確認を求めるか、承認に回します。 |
| **自動モード** | クエリを実行します。送信者本人の確認だけで済み、元に戻せる変更は、確認せずに実行します。削除などの破壊的な変更では確認を求めます。 |
| **権限チェックをスキップ** | 送信者本人の確認だけで済む変更は、破壊的な変更も含め、確認せずに実行します。 |

どのモードでも、組織のツールポリシーで承認が必要な変更は承認者に回され、無効なツールは使用できません。**権限チェックをスキップ**は、チャットのエージェントプロファイルの**承認ポリシー**で**権限確認のスキップを許可**が有効な場合にのみ表示され、オンにする前に確認を求めます。質問が処理待ちの間にプロファイルで許可が取り消された場合は、変更のたびに確認を求め、その旨を回答に表示します。

### チャット名

新しいチャットでは、最初の質問に回答するときに名前を付けます。ChatGPT や Claude と同様に、質問と同じ言語でチャットの内容を短くまとめます。あいさつだけでは話題がわからないため、具体的な質問が届くまでは最初のメッセージの冒頭が名前になります。自動で名前を付けるのは一度だけです。名前を変更するには、一覧でチャットの横にある鉛筆アイコンを選択します。**Enter** で名前を保存し、**Esc** で変更をキャンセルします。手動で名前を変更すると、Mole Agent はそのチャットに自動で名前を付けません。メモリには、元のチャットが現在の名前で表示されます。名前の生成も、ほかの呼び出しと同様にモデルの使用量に計上されます。

### 個人チャットとチームチャット

最初のメッセージを送る前にチームを選択しない限り、個人チャットになります。メッセージ入力欄の下にある**チーム**で選択するか、`/team <team>` と入力します。一覧には所属するチームが表示され、`agent.manage` 権限がある場合はすべてのチームが表示されます。最初のメッセージを送信すると、チャットのチームは変更できません。

| | 個人チャット | チームチャット |
|---|---|---|
| 閲覧と続きのやりとりができる範囲 | チャットの所有者 | チームメンバーと `agent.manage` 権限を持つアカウント |
| 使用するスキルと MCP サーバー | 組織、チャットの所有者本人、チャットに追加したチームのもの | 組織とチームのもの。個人のものは使用しません |

ツールは常に、メッセージの送信者本人の権限と認証情報で実行します。チームチャットでは、ほかのメンバーの質問に送信者名が表示されます。個人チャットで所属チームのスキルや MCP プロンプトを呼び出すと、以降、そのチャットでチームのスキルと MCP サーバーを利用できます。チャット一覧では、チームチャットにチーム名が表示されます。チームチャットが作成されると、**すべて**、**個人**、**チーム**で一覧を絞り込めます。

### スラッシュコマンド

メッセージ入力欄の先頭に `/` を入力すると、コマンドメニューが開きます。続けて入力すると、名前や説明で絞り込めます。↑ ↓ で選択し、**Enter** で実行します。**タブ**では実行せずに補完し、**Esc** でメニューを閉じます。引数を取るコマンドを補完すると、メニューに選択できる引数が表示されます。コマンドは、チャットページのほか、どの画面からでも ⌘J で開ける Mole Agent パネルで使用できます。

| コマンド | 動作 |
|---|---|
| `/help` | すべてのコマンドを表示します |
| `/new` | 新しいチャットを開始します |
| `/team <team>` | 新しいチャットのチームを選択します。`personal` を指定すると個人チャットになります。開始済みのチャットで実行すると、指定したチームの新しいチャットを開始します |
| `/mode auto\|quick\|deep\|query` | 分析モードを切り替えます：**自動モード**、**クイック回答**、**詳細調査**、**クエリ生成のみ** |
| `/time 15m\|30m\|1h\|6h\|24h\|7d` | 時間範囲を設定します |
| `/policy advice\|readonly\|approval\|auto\|bypass` | 実行モードを設定します：**提案モード**、**調査モード**、**承認後に実行**、**自動モード**、**権限チェックをスキップ**。`bypass` は事前に確認を求め、エージェントプロファイルで許可されている場合にのみ使用できます |
| `/model <model provider>` | プロバイダー名またはモデル名でモデルプロバイダーを選択します。`auto` を指定すると自動で選択します |
| `/profile <agent profile>` | エージェントプロファイルを選択します。`auto` を指定するとデフォルトのプロファイルを使用します |
| `/prompt <prompt>` | プロンプトを選択します。`auto` を指定すると自動で選択します |
| `/query <question>` | クエリを生成しますが、実行はしません |
| `/dashboard <what it should show>` | ダッシュボードを作成します |
| `/rca <incident> [more context]` | インシデントの根本原因を調査します。メニューには未解決のインシデントが表示されます。`alerts.incidents.read` 権限が必要です |
| `/export` | このチャットを Markdown ファイルとしてダウンロードします |

`/query`、`/dashboard`、`/rca` はメッセージとして送信されます。チャットにはコマンドがラベルとして表示され、その後に引数が続きます。回答を再生成すると、同じコマンドをもう一度実行します。`/query` のモードは、そのメッセージにのみ適用されます。`/rca` の調査範囲は、インシデントの開始 30 分前から終了時点までです。未解決の場合は現在までを調査します。ほかのコマンドはメッセージ入力欄の設定だけを変更し、何も送信しません。

コマンドが存在しない、引数が不足しているか無効である、または必要な権限がない場合、コマンドは送信されず、メッセージ入力欄の上に理由が表示されます。`/` で始まるプレーンテキストを送信するには、先頭に `\/` と入力します。送信時にバックスラッシュが取り除かれます。`/var/log/app.log` のように 2 つ目のスラッシュがあるパスは、そのままプレーンテキストとして送信されます。

スキルと MCP プロンプトもコマンドとして使用でき、メニューの**スキル**と**MCP**に表示されます。

- `/name [request]` は、チャットで使用できるスキルを実行します。2 つのチームに同じ名前のスキルがある場合は、`/name@team` と入力します。個人チャットでは、指定したチームもチャットに追加されます。
- `/<server>:<prompt> [arguments]` は、送信者本人の認証情報で MCP サーバーからプロンプトを取得し、質問として送信します。引数は記述順に割り当てられ、最後の引数には残りのテキストがすべて入ります。`name=value` の形式で引数名を指定することもできます。スペースを含む値は引用符で囲みます。

スクリプトを実行するスキルには Mole Runner が必要です。メンバーごとの認証情報を使うサーバーのプロンプトを実行するには、送信者本人の認証情報を事前に設定してください。これらの要件はメニュー内の各コマンドに表示されます。

## ナレッジとメモリ

**Mole Agent → ナレッジ**を開きます。**ナレッジ**には、チャットが読み込む組織および各チームの Markdown ファイルが格納されます。`MOLE.md` を起点にして `@path` で他のファイルを参照します。または、`/init` を実行します。Mole Agent が現在の設定を確認していくつか質問し、確認を得てから各ファイルを作成します。組織のナレッジは `agent.manage` 権限を持つメンバーが変更し、チームのナレッジはそのチームのメンバーが変更します。

- **新規**では、ファイルを作成するか、最初のファイルとともにフォルダーを作成します。`runbooks/api.md` のようなパスを指定すると、フォルダーとファイルを同時に作成できます。
- **アップロード**では、ファイルまたはフォルダー全体をアップロードできます。
- ファイルは**プレビュー**で開きます。**編集**では、メッセージ入力欄と同じように、表示結果を確認しながら編集できます。**ソース**では Markdown を直接編集します。HTML コメントなど、エディターで保持できない Markdown を含むファイルは、**ソース**で編集します。
- **AI**では、ファイルの変更を依頼するチャットを開きます。

**メモリ**には、チャットが記憶した設定の好み、手順、事実、教訓が格納されます。個人チャットの記憶はその所有者向けに、チームチャットの記憶はそのチーム向けに保存します。各記憶には、記憶の元になったチャットへのリンクがチャット名で表示されます。記憶のテキストはナレッジファイルと同じ方法で編集でき、削除もできます。記憶そのものはチャットが作成します。`agent.memories.settings` 権限を持つメンバーが**チャット後に記憶を抽出**を有効にすると、チャットの終了から30分後に、モデルが組織のモデル予算を使って記憶に残す内容を選びます。

## 調査

複雑な疑問は、進捗を追跡できる調査として管理します。調査では、次の情報を記録します。

- ステータスと現在のステップ
- 証拠と、それが結論に与えた影響
- 競合する仮説とその確信度
- 関連するチャット、承認、実行
- 最終サマリーと復旧の確認

インシデントから開始したチャットでは、そのインシデントの調査を記録します。 APM のサービス、エンドポイント、エラー、インサイトで**調査**を選んでチャットを開始すると、サービスの調査を記録します。また、 RUM ページで**Mole Agent で調査**を選んでチャットを開始すると、アプリケーションの調査を記録します。 **Mole Agent → 調査**には、これらの調査が一覧表示されます。APM サービスをチャットに添付すると、チャットで指定した時間範囲の数値データと、サービスのインサイト、呼び出し元と呼び出し先の情報がモデルに渡ります。詳しくは [Mole Agent で調査](/ja/apm/insights#mole-agentで調査する)を参照してください。RUM アプリケーションをチャットに添付すると、セッション、Core Web Vitals、主な問題、発生中のアラートがモデルに渡ります。詳しくは [Mole Agent で調査](/ja/rum#mole-agent-で調査)を参照してください。

インシデントをチャットに添付すると、インシデント自体に加えて、次の情報がモデルに渡ります。インシデントを起票したアラートルールの調査ガイド（クエリが含まれる場合、モデルはそれを最初に実行します）、影響を受けたサービスとデータの所在に関するサービスカタログの情報、過去90日間で最も類似するインシデント（各インシデントの終結状況と根本原因の記述の最初の1文）、およびインシデント発生の直前から直後までのデプロイ、設定変更、機能フラグです。インシデントから開始したチャットや、インシデントをトリガーに開始したオートメーションにも、同じ情報が渡ります。

Mole Agent は、データを読み取る際に、まず集約結果を確認します。`analyze_log_patterns` はログをパターン別にグループ化し、ベースライン期間と比較します。`analyze_metric_trend` は、メトリクスがいつ、どの程度変化し、どの時系列とラベルがその変化に寄与したかを示します。その後、具体例を確認するために生ログを読み取ります。同じステップ内の読み取り（メトリクス、ログ、トレースなど）は最大4件まで並列で実行します。変更を伴う操作は引き続き1件ずつ実行します。

組織のオートメーションが根本原因分析を作成しない場合、対応中のインシデントについて、バックグラウンドでツールを使わずに1回のモデル呼び出しで根本原因分析を作成します。この分析はシステムとして実行され、インシデントの閲覧権限があれば誰でも結果を閲覧できます。そのため、ストリームデータは読み取らず、インシデント自体、調査ガイド、サービスカタログ、類似インシデント、発生前後の変更に基づいて分析します。ツールでデータを確認する分析には、[オートメーション](/ja/automations)の**インシデント分析**テンプレートを使用します。このテンプレートは、オートメーションを保存したメンバーの権限で実行されます。

## オートメーション

オートメーションでは、チャットへの参加なしで Mole Agent がタスクを実行します。スケジュール、新規インシデントの発生、CI/CD ジョブからの呼び出し、または手動操作で実行できます。各実行はチャットとして保存され、結果を通知チャンネルに送信できます。インシデントの場合は、結果をそのインシデントの根本原因分析（RCA）として保存することもできます。詳しくは[オートメーション](/ja/automations)を参照してください。

## 品質

すべての回答をルールに基づいて採点します。組織が設定した評価機能は、回答の一部を抽出し、モデルを使って採点します。スコアが低い回答や、役に立たなかったと評価された回答は、**品質**タブでレビューできます。組織がチャットや RCA 向けに設定したプロンプトは、デフォルトに設定する前に、現在のデフォルトと比較して検証します。詳しくは[品質](/ja/quality)を参照してください。

## IM

Mole Agent はコネクターを通じて、Feishu、Slack、DingTalk、WeCom、Google Chat、Microsoft Teams、Telegram でも応答します。グループで Mole Agent をメンションするか、ダイレクトメッセージを送信してください。そこでのチャットも MoleSignal に表示されます。詳しくは[IM での Mole Agent の利用](/ja/im)を参照してください。

## 承認と実行

書き込み可能なツールは、常にサーバーの実行ポリシーに従います。

| リスク | デフォルトの実行モード |
|---|---|
| L0 | 自動実行。 |
| L1 | ユーザーによる確認。 |
| L2 | 1件の承認。 |
| L3 | 2件の承認。 |
| L4 | 無効。破壊的な操作を行うリモートツールのリスクレベルは L4 以上です。 |

承認には実行予定の操作が記録され、ポリシーで定めた有効期間が過ぎると失効します。実行前に、サーバーは権限、リソースの状態、パラメーター、リスク、冪等性を再検証します。実行記録には、実行結果と復旧の確認結果が残ります。

## ログ検査

Mole Agent はログストリームを読み取り、レポートを作成します。**ログ**から単発で実行するか、スケジュールを設定してバックグラウンドで実行します。スケジュールで実行する検査では、すべてのレポートを保存し、レポートで問題が報告された場合に通知します。詳しくは[ログ検査](/ja/logs/inspections)を参照してください。

## スキル

スキルは、特定の種類のタスクの手順をオープンな Agent Skills 形式で記述した `SKILL.md` と、その手順が参照するファイルをまとめたフォルダーです。Mole Agent は、チャットで利用できるスキルの名前と説明を確認し、リクエストに合ったスキルの手順を読み込みます。手順にほかのファイルへの参照があれば、そのファイルも読み込みます。すべてのスキルはスラッシュコマンドとしても使えます。

| ソース | 管理場所 | 利用範囲 |
|---|---|---|
| **組み込み** | MoleSignal に付属 | すべての組織（読み取り専用） |
| **インスタンスフォルダー** | サーバー上で `[agent].skill_paths` に指定したフォルダー | すべての組織（読み取り専用） |
| **アップロード済み** | **Mole Agent → 設定 → スキル → スキルをアップロード** | 組織、チーム、または個人 |
| **リポジトリ** | **Mole Agent → 設定 → スキル → リポジトリを追加** | 組織、チーム、または個人 |

組み込みスキルには、ナレッジを記述する `/init`、Mole Agent の使われ方を振り返って改善点を見つける `/insight`（[自動化](/ja/automations#mole-agentの利用状況を振り返る)を参照）、RUM アプリケーションの概要から問題、セッション、トレースへと掘り下げて実際のユーザーが遭遇した問題をトリアージする `/rum-triage`、調査に必要なデータがそろっているかを確認してレポートを作成する `/data-readiness` があります。`/data-readiness` は、各ストリームにサービス、環境、トレース ID が記録されているか、ログ、メトリクス、トレースでサービス名が統一されているか、メトリクス名に単位が含まれているかを確認し、各項目の修正方法も示します。`agent.manage` 権限があれば、組み込みスキルとインスタンスフォルダーのスキルを組織全体で無効にできます。同名のスキルがある場合、チャットでは個人、チーム、組織、インスタンスフォルダー、組み込みの順に優先します。Mole Agent は起動時と、インスタンスフォルダー内のファイルが変更されるたびに、インスタンスフォルダーを読み込みます。[設定](/ja/configuration)を参照してください。

### スキルを作成する

`SKILL.md` の先頭に YAML フロントマターを記述します。

| フィールド | 必須 | 説明 |
|---|---|---|
| `name` | はい | コマンド名です。先頭は英字にし、以降は英字、数字、`-`、`_` を使います。最大 64 文字です。組み込みコマンドの名前は使えません。 |
| `description` | はい | スキルの機能と使用する場面を最大 1024 文字で記述します。Mole Agent はこの説明をもとにスキルを選びます。 |
| `allowed-tools` | いいえ | スキルが使用するツールです。スキルをコマンドとして実行すると、ツールはモデルに直接渡されます。組織のツールポリシーと承認要件は引き続き適用されます。 |
| `argument-hint` | いいえ | 引数の書き方です。コマンドメニューに表示します。 |
| `version` | いいえ | 設定に表示し、呼び出しごとに記録します。`metadata.version` も使えます。 |
| `tags`, `examples` | いいえ | スキルの詳細画面に表示するタグと、試せる質問の例です。 |
| `requires` | いいえ | `runner` は、スクリプトを実行するスキルを示します。このスキルには Mole Runner が必要です。 |

手順では、`$ARGUMENTS` がコマンドの後に続くテキスト全体を、`$1` から `$9` がそのテキスト内の各単語を表します。これらを使わない場合は、手順の後にテキストを追加します。

パッケージは、スキルフォルダーを 1 つ含む最大 20 MiB の `.zip`、`.skill`、または `.tar.gz` です。展開後は最大 300 ファイル、合計 20 MiB、1 ファイルあたり 8 MiB までです。フォルダーの外を参照するリンクやパスは受け付けません。同じスコープに同名のスキルがある場合、アップロード時に置き換えるかどうかを確認します。スキルの詳細画面で **チャットで試す** を選択すると、コマンドを入力した状態で Mole Agent が開きます。

### スキルリポジトリ

指定したブランチまたはタグから、リポジトリを 1 つのアーカイブとしてダウンロードします。リポジトリ全体、または **フォルダー** を指定した場合はその配下で、`SKILL.md` を含む各フォルダーを 1 つのスキルとして扱います。1 つのリポジトリにつき、アーカイブは最大 64 MiB、スキルは最大 50 個です。GitHub、GitLab、Gitea、Forgejo、Bitbucket ではリポジトリのアドレスを指定します。それ以外のホストでは、`{ref}` を含むアーカイブのアドレスを指定してください。プライベートリポジトリには、書き込み専用のアクセストークンが必要です。

リポジトリを保存すると、1 回同期します。**同期** で再度同期でき、**毎日同期** を有効にすると最新の状態を維持できます。同期ではリポジトリ内のスキルの追加、更新、削除を反映し、インポートできなかったフォルダーとその理由を一覧表示します。リポジトリを削除すると、そのリポジトリのスキルも削除します。

## 組織、チーム、個人のリソース

スキル、スキルリポジトリ、MCP サーバーは、組織、チーム、または個人に属します。追加時に **所属先** を指定します。編集権限があれば、管理できる別のスコープにリソースを移動できます。

| スコープ | 変更できるユーザー | 利用できる場所 |
|---|---|---|
| 組織 | `agent.manage` 権限を持つユーザー | すべてのチャット |
| チーム | チームメンバーと `agent.manage` 権限を持つユーザー | チームのチャットと、そのチームを追加した個人チャット |
| 個人 | 所有者（`agent.manage` 権限を持つユーザーは閲覧、無効化、削除が可能） | 所有者の個人チャット |

スキル、リポジトリ、MCP サーバーが残っているチームは削除できません。**ID とアクセス → チーム** に対象のリソースが表示されるので、先に移動または削除してください。

チームや個人が追加したリポジトリと MCP サーバーの接続先は、公開インターネットと、`agent.network_policy.manage` 権限を持つユーザーが **Mole Agent → 設定 → ネットワークポリシー → チーム接続と個人接続の内部ネットワーク** に指定した内部ホストとネットワーク範囲に限られます。これらの接続では、常に TLS 証明書を検証します。組織のリポジトリと MCP サーバーには、それぞれの設定を適用します。

## エージェントの設定

**Mole Agent → 設定**を開きます。Mole Agent のタブの下に、次のセクションが横一列に並びます。

| セクション | 用途 |
|---|---|
| **エージェントプロファイル** | プロファイルごとに、使用できるツール、回答ごとのツール呼び出し回数・調査時間・温度、データの範囲、ネットワークポリシーを設定します。 |
| **モデルと推論** | モデルプロバイダー、書き込み専用の API キー、応答がない場合のタイムアウト、料金を設定します。 |
| **使用状況** | 1 日のトークン予算に対する本日の使用量と、過去 30 日間のソース別使用量を確認します。 |
| **プロンプト管理** | 組み込みプロンプトと、組織または個人のオーバーライドを管理します。 |
| **スキル** | 組み込みスキル、インスタンスのフォルダーにあるスキル、アップロードしたスキル、リポジトリ内のスキル、およびスキルリポジトリを管理します。 |
| **ツールと機能** | ツールレジストリで、各ツールの実行モード、制限、環境ごとの最低リスクレベルを管理します。組織、チーム、個人の MCP サーバーと、そのツールやプロンプトも管理します。 |
| **インバウンド MCP** | 外部 AI クライアント向けの MCP エンドポイントを管理します。 |
| **データアクセス** | デフォルトのプロファイルが読み取れる環境、サービス、ストリームを設定します。 |
| **ネットワークポリシー** | プロファイルがネットワークを必要とするツールを使えるかどうかと、チーム接続と個人接続でアクセスできる内部アドレスを設定します。 |
| **承認ポリシー** | リスクレベルごとの承認ルールを設定します。 |

認証情報は暗号化したまま保存し、API のレスポンスには含めません。

### ツールと機能

ツールは製品の機能領域ごとにグループ化します。セクションを開くと、グループは折りたたまれています。グループを展開するか、検索して一致するツールを含むグループを開きます。**すべて**、**読み取り専用**、 **自動**、**承認**、**無効**の各フィルターには、該当するツールの件数が表示されます。

ツールのタイトルと説明は、インターフェースの言語で表示します。ツールの詳細には、モデルに渡す定義も表示します。この定義は、インターフェースの言語にかかわらず英語です。

### MCP サーバー

**ツールと機能 → MCP サーバー**を開き、サーバーを追加して接続をテストし、ツールをインポートします。各サーバーには、どの組織、チーム、個人に属するかを表示します。メンバーはここで個人用サーバーとチーム用サーバーも管理できます。

| 設定 | 説明 |
|---|---|
| トランスポート | **Streamable HTTP**、旧式の HTTP と SSE を使うサーバー向けの **SSE（レガシー）**、または組織のサーバー専用の **stdio** を選択します。stdio では、MoleSignal が自身のサーバー上でコマンドを起動します。実行できるのは、インスタンスの `[agent].mcp_stdio_commands` に登録したコマンドだけです。シェルを介さずに `PATH`、`HOME`、`LANG`、`TMPDIR` と、そのサーバーに設定した**環境変数**を渡し、システムの一時フォルダーで実行します。コマンドは呼び出しごとに終了します。stdio の認証情報は**環境変数**に設定します。認証、リクエストヘッダー、メンバー別の認証情報は、HTTP 経由で接続するサーバー向けです。組織のネットワークポリシーは、コマンドの接続先には適用しません。 |
| 認証 | 認証なし、全員で共有するトークンまたはキー、**メンバー別の認証情報**から選択します。メンバー別の認証情報を選ぶと、各メンバーがサーバー指定のヘッダーに使う値を個別に保存します。その値は、保存したメンバーによる呼び出しにのみ使います。 |
| **ヘッダー** | リクエストごとに送信します。名前に key、token、secret、password、credential、auth、cookie のいずれかを含むヘッダーの値は暗号化し、末尾の 4 文字だけを表示します。編集中にシークレット欄を空欄にしても、保存済みの値は変わりません。 |

**接続をテスト**を選択すると、サーバーのツールが一覧に表示されます。**選択したツールを同期**で、選んだツールをインポートします。新しいツールは手動で有効にするまで無効のままです。最低リスクレベルはサーバーのアノテーションに従います。**ツールとプロンプト**にはツールごとにスイッチがあり、**すべての読み取り専用ツールを有効化**で読み取り専用ツールを一括で有効にできます。ツールポリシーと承認ルールは引き続き適用します。サーバーが提供するプロンプトは、`/<server>:<prompt>` 形式のコマンドになります。

Mole Agent は、同期済みの各サーバーを約 1 時間ごとに再確認します。入力スキーマが変わったツール、サーバーの一覧から削除されたツール、サーバーが以前より高いリスクレベルを指定したツールは、確認して再同期するまで使えません。メンバー別の認証情報を使うサーバーは、この確認の対象外です。

**インポート**では、Claude Desktop、Claude Code、Cursor、VS Code の MCP 設定を読み込み、サーバーを追加します。`${input:token}` のように変数を参照する値はインポートせず、入力が必要な項目として一覧に表示します。`command` を持つサーバーは stdio サーバーです。インスタンスが許可するコマンドを使う場合に限り、組織のサーバーとしてインポートします。

メンバー別の認証情報を使うサーバーでは、**自分の認証情報を追加**でメンバー自身の値を保存します。認証情報が未登録のままチャットでそのサーバーのツールを呼び出した場合や、サーバーが保存済みの認証情報を拒否した場合は、**続行には認証が必要**カードを表示し、回答を一時停止します。カードには、認証情報が必要なツールと、サーバーが案内する手順を表示します。**保存して続行**は、**自分の認証情報を追加**と同じ方法で認証情報を保存し、ツールを再実行します。**スキップ**を選択すると、その回答の残りの処理ではサーバーを使いません。入力するのは質問したメンバー自身の認証情報のため、カードに入力できるのはそのメンバーだけです。チームチャットでは、他のメンバーにも誰の入力を待っているかが表示されます。カードは最大 1 時間、入力を待ちます。入力を求める相手がいない場合、ツールは認証情報がないことを返し、Mole Agent は該当するメンバーに追加を求めます。

### プロンプト管理

組み込みプロンプトは読み取り専用です。名前はインターフェースの言語で表示します。組み込みプロンプトで**オーバーライドを作成**を選択すると、組織全体または特定のユーザー向けに置き換えられます。チャットや根本原因分析に使う組織のプロンプトをデフォルトに設定するには、先に組織のチェックを通過する必要があります。詳しくは、[品質](/ja/quality#プロンプトをデフォルトに設定する前にチェックする)を参照してください。

### エージェントプロファイルの実行制限

制限は、プロファイルを使うチャットの回答ごとに適用します。有効なプロファイルがない場合は、デフォルト値を適用します。

| 設定 | デフォルト | 説明 |
|---|---|---|
| **ツール呼び出し回数の上限** | `32` | 1 回の回答でツールを呼び出せる回数の上限です。1〜256 回で設定します。 |
| **最大調査時間（分）** | `30` | 1 回の回答にかけられる時間の上限です。1〜120 分で設定します。 |
| **温度** | `0.2` | サンプリング温度です。0〜2 で設定します。値を下げるほど、回答のばらつきが減り、再現性が高まります。 |

ツール呼び出し回数または調査時間が上限に達すると、Mole Agent はツールの呼び出しを終了し、それまでに得た結果で回答します。

### 使用状況と予算

**Mole Agent → 設定 → 使用状況**を開くと、組織の本日のトークン使用量、1 日の予算、過去 30 日間の使用量を確認できます。使用量は UTC の日付単位で集計し、入力トークンと出力トークンを合計します。集計対象は次のとおりです。

| ソース | 説明 |
|---|---|
| **チャット** | Mole Agent のチャットです。ダッシュボードの作成も含みます。 |
| **根本原因分析** | アクティブなインシデントに対して自動で生成する分析と、インシデントごとにオンデマンドで生成する分析です。 |
| **ログ検査** | 即時実行とスケジュール実行のログ検査です。 |
| **LLM 関数** | [アラートパイプライン](/ja/pipelines/alert-events#aiによる要約)の**AIによる要約**ステップと、LLM 関数の実行です。 |
| **オートメーション** | オートメーションの実行です。インシデントをきっかけとする実行も含みます。 |
| **品質スコアリング** | 評価の実行と、プロンプトのチェック時に生成し直す回答です。 |

モデルプロバイダーに料金設定がある場合は、プロバイダーごとの通貨でコストも表示します。通貨が異なるコストは個別に表示し、合計しません。料金設定のないモデルプロバイダーへの呼び出しはコストに加算しません。その呼び出しを含まない金額には **≥** を付けます。実際のコストは表示額以上です。

1 日の予算には、デフォルトでインスタンス設定 `[agent].daily_token_budget` の値を使います（`0` は上限なしを意味します）。詳しくは、[設定](/ja/configuration)を参照してください。`agent.usage.manage` 権限を持つ管理者は、組織の上限を**カスタム**または**上限なし**に設定し、予算を使い切ったときのチャットとオンデマンド分析の動作を選択できます。

| 選択肢 | 動作 |
|---|---|
| **モデルの呼び出しを停止**（デフォルト） | 質問は送信せず、メッセージ入力欄に残します。チャットには、本日の予算を使い切ったことと、予算がリセットされる時刻を表示します。オンデマンド分析にも同じメッセージを表示します。 |
| **警告のみ表示して回答を続行** | チャットは回答し、メッセージ入力欄の上に予算を超過したことを表示します。 |

予算を使い切ると、自動の根本原因分析、ログ検査、AIによる要約ステップ、LLM 関数はモデルの呼び出しを停止します。ログ検査は予算超過を理由に失敗し、自動分析は予算がリセットされるまで待機します。AIによる要約ステップと LLM 関数も失敗します。使用量が警告しきい値（デフォルトは 80%、`[agent].budget_warning_percent`）に達すると、チャットのメッセージ入力欄の上に警告を表示します。予算の確認には約 15 秒間キャッシュした状態を使い、進行中の回答は中断しないため、使用量が上限をわずかに超えることがあります。

モデルを呼び出すたびに、内部ストリーム `_agent_model_traces` に 1 行を書き込みます。このストリームは**ログ**でクエリできます。主なフィールドは、`origin`（`chat`、`rca`、`inspection`、`llm_eval`、`automation`、`evaluation`、`replay_summary`）、`provider`、`model`、`prompt_tokens`、`cached_prompt_tokens`（プロバイダーがキャッシュから処理した入力トークン）、`completion_tokens`、`total_tokens`、`latency_ms`、`cost`、`cost_currency`、`status`、`error`、`tool_calls`、`streaming`、`chat_id`、`user_id`、`profile_id`、`prompt_hash` です。`cost` と `cost_currency` は、モデルプロバイダーに料金設定がある場合にのみ書き込みます。`user_id` は、呼び出しを誰の使用量として集計するかを示します。チャットでは質問したユーザー、ログ検査では実行ユーザーを記録します。根本原因分析と LLM 関数の呼び出しには、このフィールドがありません。

## データの取り扱い

Mole Agent は、呼び出したツールの実行結果を含む会話を、設定済みのモデルプロバイダーに送信します。プロバイダーを設定していない場合、デプロイメントの外部には何も送信しません。以下の設定で、エージェントがアクセスできる範囲を制限します。

- **データアクセス**は、デフォルトプロファイルが読み取れる環境、サービス、ストリームを制限します。組織をまたぐアクセスは一切許可しません。
- **ネットワークポリシー**は、ネットワーク接続が必要なツールをプロファイルで使用できるかどうかを制御します。新規プロファイルではネットワークアクセスをブロックします。この設定をオンにしても、任意の HTTP リクエスト、シェル操作、ブラウザー操作、制限のない MCP ツールは有効になりません。
- **承認ポリシー**は、書き込み操作のリスクレベルに応じて承認を要求し、そのプロファイルを使うチャットで **権限チェックをスキップ** を選択できるかどうかを制御します。
- **スキルと MCP サーバー**は、ポリシーで許可する範囲を広げずに指示やツールを追加します。スキルで許可したツールとすべての MCP ツールには、組織の実行モードと承認ルールが引き続き適用されます。

モデルのキーは、暗号化ルートキーで暗号化します。[本番環境のチェックリスト](/ja/deployment/production-checklist)を参照してください。

## 権限

- `agent.use` でチャットと実行履歴を開き、回答と分析を評価できます。
- `agent.investigations.read`、`agent.knowledge.read`、`agent.memories.read`、`agent.skills.read`、`agent.mcp_servers.read`、`agent.usage.read` で、それぞれ調査、ナレッジ、メモリ、スキル、MCP サーバー、使用状況を閲覧できます。対応する `.manage` 権限があれば、個人または所属チームが所有する項目を変更できます。リポジトリの追加には `agent.skill_repositories.manage` が必要です。
- `agent.manage` では、組織が所有する項目にもアクセスできます。対象は、すべてのチームチャットと、組織のナレッジ、スキル、MCP サーバーです。
- `agent.models.manage`、`agent.prompts.manage`、`agent.tools.manage`、`agent.toolsets.manage`、`agent.profiles.manage`、`agent.usage.manage`、`agent.network_policy.manage`、`agent.inbound_mcp.manage`、`agent.im.manage` で、それぞれプロバイダー、プロンプト、ツール、ツールセット、プロファイル、1 日あたりの予算、ネットワークポリシー、インバウンド MCP、チャットボットを設定できます。**設定**の各セクションでは、そのセクションに必要な権限のみを要求します。読み取り権限がない場合は、必要な権限を表示します。`.manage` 権限がない場合、設定は読み取り専用になりますが、表示される内容は引き続き検索およびコピーできます。
- `agent.quality.read` で **品質** タブを開き、スコア、レビュー、評価器を確認できます。`agent.quality.manage` でこれらを変更できます。
- `agent.automations.read` でオートメーションの一覧を表示し、`agent.automations.manage` で作成や変更、`agent.automations.run` で実行、`agent.automations.tokens` でオートメーションの API トークンを管理できます。[オートメーション](/ja/automations#開始前の準備)を参照してください。
- `agent.approve` で承認対象の操作をレビューできます。
