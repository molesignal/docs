MoleSignal は 1.0 より前のバージョンです。このページでは、計画と運用に影響する制限を説明します。

## デプロイ

- **引き継ぎの遅延。** 先行書き込みログはオブジェクトストアにあるため、取り込みノードが失われても、受領確認済みのレコードは失われません。ただし、そのノードがまだフラッシュしていないレコードは、`[wal].lease_secs`（デフォルトは 15 秒）の経過後に別の取り込みノードが引き継ぐまでクエリできません。[耐久性と引き継ぎ](/ja/architecture#データの耐久性と引き継ぎ)を参照してください。
- **単一ノードで実行するジョブ。** プライマリの `alert` ノードは、クラスター間のイベントプッシュとゴシップ、サービスグラフの再計算、APM ロールアップ、ステータスページのメンテナンス、合成モニタリングの自動化、スロークエリの分析、インシデントの根本原因分析を実行します。`alert` ノードを増やしても、これらのジョブの処理能力は向上しません。プライマリがクラスターから離脱すると、別のノードでジョブが再開します。[ロールベースのデプロイ](/ja/deployment/role-based#アラートノード間の処理分担)を参照してください。
- **PostgreSQL のみ。** メタデータベースには PostgreSQL のみを使用できます。
- **設定の反映には再起動が必要。** 実行中のプロセスは設定ファイルの変更を反映しません。[設定](/ja/configuration)を参照してください。
- **マイグレーションは前方のみ。** 新しいビルドでマイグレーションしたデータベースは、古いビルドでは開けません。1.0 より前のビルドでは、ベースラインスキーマが変わることがあります。[アップグレード](/ja/upgrade)を参照してください。

## 取り込み

- **リクエストサイズ。** リクエストボディが 2 MiB（ネイティブ JSON の取り込みでは 16 MiB）を超えると、`413` を返して拒否します。
- **OTLP over HTTP の圧縮。** 圧縮されたリクエストボディは `400` を返して拒否します。送信側で圧縮を無効にしてください。
- **ヒストグラムのバケット。** OTLP ヒストグラムでは `count`、`sum`、`min`、`max` を保存します。バケット境界、バケットごとの件数、サマリーの分位数は保存しません。
- **重複するスパン。** 同じ `trace_id` と `span_id` で再送されたスパンは破棄します。
- **Loki プッシュ。** エンドポイントは JSON 形式のリクエストのみをデコードします。Promtail や Grafana Alloy など、Snappy で圧縮した protobuf を使用する送信元からはプッシュできません。
- **Prometheus remote_write。** ネイティブヒストグラムとメトリクスのメタデータはスキップします。
- **TLS なしの OTLP gRPC。** レシーバーは TLS を終端しません。信頼できるネットワークの外に出るトラフィックには、レシーバーの前段に TLS を終端するプロキシを配置してください。
- **レート制限。** リクエストを制限するのは `router` ロールだけです。認証済みの組織ごとにリクエスト数を集計し、ルーターの各レプリカが個別にカウントします。
- **プラットフォームストリーム。** `_molesignal`、`_synthetic_results`、`_audit`、`_agent_model_traces`、`_agent_score_traces` に書き込めるのは MoleSignal だけです。これらのストリームは公開取り込みを拒否します。[プラットフォームストリーム](/ja/streams#プラットフォームストリーム)を参照してください。

## クエリ

- **長い時間範囲のクエリは非同期で実行。** 推定行数が `[querier].auto_async_threshold_rows` に達すると、クエリは `202` と進捗を追跡できるジョブを返します。デフォルト設定では、約 13.9 時間の範囲がこのしきい値に相当します。同じリクエスト内で実行するには、`Prefer: respond-sync` を送信してください。[クエリ](/ja/query#時間範囲と非同期ジョブ)を参照してください。
- **PromQL のサブセット。** エンジンは PromQL の一部を実装しています。[PromQL サポートマトリックス](/ja/query/promql-subset)を参照してください。
- **クエリあたりの行数。** 読み取り対象が `[querier].max_scan_rows`（デフォルトは 1 億行）を超えるクエリは `400` を返して拒否します。時間範囲を狭めるか、フィルターを追加してください。PromQL では、セレクターごとに制限を適用します。
- **ロールを分離したクラスターでのデータの鮮度。** クエリはカタログに登録されたファイルを読み取ります。そのため、取り込みノードのバッファーに残っているレコードは、`[intake].flush_interval_secs` 以内に行われる次のフラッシュ後にクエリできるようになります。`standalone` ノードは自身のバッファーも読み取ります。デフォルトでは、アラートルールは **設定 → アラート評価** の評価遅延（60 秒）分だけ評価ウィンドウを過去にずらします。[評価遅延](/ja/alerting/rules#評価遅延)を参照してください。

## アラート

- **リアルタイムルールのカウントはメモリに保持。** `real_time` ルールは、書き込みを受け付けるすべてのノードで件数をカウントします。ルールを担当するアラートノードが毎秒その件数を合算するため、レコードの書き込みから最長 1 秒でインシデントが開きます。ノードが再起動すると、そのノードのカウントだけが失われます。カウントを読み取れないノードは、その秒の集計から除外します。ノード間でカウントを読み取る際は、クラスターの Bearer トークンを使用します。フェデレーション先のクラスターのカウントは合算しません。使用できるステートメントは `SELECT count(*) FROM <stream> [WHERE <condition>]` のみです。[リアルタイムルール](/ja/alerting/rules#リアルタイムルール)を参照してください。

## セキュリティと ID 管理

- **内部 gRPC は認証なし。** ポート `5082` はノード間通信を認証なしで受け付けます。このポートはプライベートネットワーク内でのみ使用してください。
- **パスキーは 1 つのドメイン名に紐付きます。** `[http].external_url` には、ドメイン名を使用した HTTPS URL を設定する必要があります。別のホスト名でコンソールを開くと、パスキーは機能しません。
- **パスワードのリセットにはメールが必要。** パスワードのリセットではリンクをメールで送信するため、`[notify.smtp]` と `[http].external_url` を設定する必要があります。
- **承認不要のセルフサービス登録にはメールが必要。** 登録時に、まずメールアドレスを確認します。`[notify.smtp]` と `[http].external_url` を設定していない場合、新規アカウントはすべて管理者の承認待ちになります。
- **サインイン制限は IP アドレス単位でカウント。** [クライアント IP の認識](/ja/settings/platform#クライアントipの識別)で正しい IP アドレスを取得する必要があります。パブリックプロキシや CDN を使う構成でクライアント IP の認識を設定していないと、すべてのユーザーが同じ IP アドレスを共有し、互いにサインインできなくなります。デフォルトではプライベート IP アドレスをカウントしないため、内部デプロイや、クライアント IP の認識を設定していないプロキシの背後では、アカウント単位の制限のみが適用されます。
- **アカウント単位の制限はアカウントロックではありません。** 第三者がアカウントをロックできないように、試行頻度を制限しているアカウントでも、1 日あたり約 1,400 回のパスワード試行を許容します。多要素認証を有効にしているアカウントには、パスワードが合っていても、それだけではサインインできません。第三者が試行枠を使い続けると、その IP アドレスからサインインしたことがないアカウント所有者は、待たされ続けることがあります。パスキー、シングルサインオン、またはパスワードのリセットを利用できます。
- **LDAP ディレクトリのロックアウトポリシー。** ディレクトリ独自のロックアウトポリシーが先に発動し、第三者によってディレクトリアカウントがロックされる場合があります。[サインイン制限](/ja/settings/platform#サインイン制限)は、ディレクトリのしきい値より低く設定してください。
- **セッション。** アカウント設定ページで管理できるのは、現在のブラウザーのセッションのみです。

## レポート

- **PDF と PNG のレンダリング**にはヘッドレス Chrome が必要です。リリース用コンテナイメージには Chromium が含まれています。バイナリでインストールする場合は Chrome をインストールし、`[scheduled_reports.renderer].base_url` で Web UI にアクセスできるように設定してください。
