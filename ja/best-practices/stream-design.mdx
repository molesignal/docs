データ、ダッシュボード、アラートルールが依存するようになると、ストリームやフィールドの変更は難しくなります。一度書き込むとフィールドの型が固定され、暗号化フラグは後から追加できません。フィールド名を変更すると、そのフィールドを使う保存済みクエリはすべて動作しなくなります。最初の高負荷なソースを接続する前に、1時間ほど設計に時間をかけてください。

## 要件の違いに応じてストリームを分ける

保持期間、アクセスルール、スキーマ、クエリ範囲の上限のいずれかを変える必要がある場合にのみ、ストリームを分けます。それ以外の場合は、データを同じストリームにまとめ、フィールドで区別します。

| 状況 | 推奨構成 | トレードオフ |
|---|---|---|
| デバッグログは3日間、監査ログは1年間保持する | 2つの `logs` ストリームを作成し、それぞれに保持期間を設定します。 | 両方のログが必要なクエリでは、2つのストリームを指定します。 |
| 多くのサービスが同じ構造のログを出力する | 1つのストリームを使い、すべてのイベントに `service.name` を設定します。 | サービスごとに保持期間やアクセスルールを変えることはできません。 |
| 大量の未処理データをパイプラインで複数のストリームに振り分ける | **クエリを許可**をオフにしたソースストリームと、振り分け用のパイプラインを使います。 | 未処理のイベントは保持期間が終わるまで残るため、保持期間を短く設定します。 |
| Prometheus サーバーごとにデータを取り込む | ソースごとに1つの `metrics` ストリームを使います。 | 複数のソースを横断するクエリでは、複数のストリームを指定します。 |
| ポッド、バージョン、顧客ごとにストリームを作る | ストリームを分けず、フィールドで区別します。 | 小さなストリームが増えるとファイル数が増え、構成が変わるたびにダッシュボードが動作しなくなります。 |

MoleSignal は最初の書き込み時にストリームを作成します。送信元でストリーム名を誤入力すると、通知なしで新しいストリームが作成されます。各ソースを接続した後に[ストリーム一覧](/ja/streams#ストリーム一覧)を確認してください。重要なストリームは、保持期間と暗号化するフィールドを指定して事前に作成してください。

## 送信前にフィールド名を統一する

OpenTelemetry で定義済みの名前があればその名前を使い、同じ項目にはすべてのシグナルで同じ名前を使ってください。シグナル間の移動や APM は、この命名に依存します。

| フィールド | 内容 | 用途 |
|---|---|---|
| `service.name` | サービス名。ログ、トレース、メトリクスで統一します。 | すべてのシグナルを同じサービスに関連付けます。 |
| `deployment.environment.name` | `production`、`staging` など。 | すべてのページで環境による絞り込みに使います。 |
| `service.version` | リリースされたバージョン。 | APM でデプロイを比較するために使います。 |
| `trace_id`, `span_id` | リクエストの処理中に出力するすべてのログ行に設定します。 | ログ行から対応するトレースに移動できるようにします。 |
| `level` | 小文字の `error`、`warn`、`info` など、表記を統一します。 | ログのヒストグラムは、インデックスを使ってレベルごとの件数を集計します。 |
| `host.name`, `k8s.pod.name` | イベントが発生した場所。 | 問題が発生したマシンを特定します。 |

フィールドの型は、すべての送信元で統一してください。あるサービスが数値で送信し、別のサービスが文字列で送信すると、MoleSignal は `type mismatch on field` エラーで拒否します。該当するフィールドは、保存前にパイプラインの **型を変換** で型を統一してください。既存のフィールド名を別の意味で使わず、新しいフィールドを追加してください。

## 絞り込みに使うフィールドにインデックスを設定する

[インデックスの種類](/ja/streams#スキーマとフィールド)によって、絞り込みの速度が変わります。新しいフィールドには、一部の一般的な名前を除き、インデックスが付きません。ダッシュボードやアラートで絞り込みに使うフィールドを確認してください。

- `trace_id`、`user_id`、`order_id`、 `service.name` など、値全体を比較する識別子には **完全一致** を使います。
- `message` など、単語単位で検索するテキストには **全文検索** を使います。
- `duration_ms` など、`<` や `>` で比較する数値や時刻には **スキップインデックス** を使います。
- 表示にしか使わないフィールドには、インデックスを設定しません。

インデックスの変更は新しいデータに適用されます。既存のファイルには、コンパクターがファイルをマージする際に適用されます。 **ストリーム → フィールドとインデックス** で変更し、**保存して適用** を選択してください。

## メトリクスラベルのカーディナリティを抑える

ユーザー ID、リクエスト ID、完全な URL など、値の種類に上限がない項目をメトリクスラベルに使うと、値ごとに新しい時系列が作成されます。[カーディナリティの上限](/ja/settings/platform#メトリクスのカーディナリティ)に達すると、組織全体で新しい時系列を作成できなくなります。このような値は、値の種類が増えても時系列が増えないログやスパン属性に格納してください。メトリクスラベルは、サービス、ルートテンプレート、メソッド、ステータスコードのクラスなど、値の種類が限られる項目に絞ってください。

サービスの担当チームや顧客の契約プランなど、イベントごとにコピーすることになる参照データは、 [拡張テーブル](/ja/extend-tables)に格納してください。パイプラインは処理中に拡張テーブルから値を取得します。

## 最初から機密性の高い値を保護する

| 要件 | 手段 | 適用タイミング |
|---|---|---|
| カード番号などの値を一切保存しない | [正規表現パターン](/ja/settings/data-security#正規表現パターン)で **取り込み時にマスキング** を使用するか、パイプラインのステップでフィールドを削除します。 | 取り込み時に適用し、元の値は残しません。 |
| 値を保存し、閲覧できるユーザーを限定する | ストリーム作成時に暗号化フィールドを定義し、`decrypt()` で読み取ります。 | ストリームの作成時点から適用します。 |
| ほとんどのクエリ結果で値を非表示にする | [フィールドマスキング](/ja/settings/data-security#フィールドマスキング)を使います。 | クエリの実行時に結果に適用します。 |

可能であれば、送信元またはコレクターで値を削除してください。ソースから送信しない値は、MoleSignal から漏えいすることもありません。

## 受け入れ基準

- すべてのストリームに担当者と明確な用途があり、用途に合った保持期間を設定しています。
- 確認対象のリクエストのログ行から、対応するトレースにワンクリックで移動できます。
- ダッシュボードやルールの絞り込みに使うフィールドに、適切なインデックスを設定しています。
- 値の種類に上限がないメトリクスラベルがなく、メトリクスの **カーディナリティ** で時系列数が安定しています。
- 機密データを模した目印を含むテストイベントに、取り込み時のマスキング、フィールドマスキング、または暗号化が想定どおり適用されます。
