## 変更の実行方法

インシデントの確認など、変更を行うコマンドは、Mole Agent やエージェントツールと同様に、管理対象ツールを介して MoleSignal に変更をリクエストします。組織のツールポリシーで、各ツールの実行方法を **Mole Agent → 設定 → ツールと機能** から設定します。

| 実行モード | コマンドの動作 |
|---|---|
| 自動 | 変更をすぐに実行します。 |
| 確認 | MoleSignal が確認を要求し、コマンドがターミナルで確認を求めます。CI などでは `-y` (`--yes`) であらかじめ同意できます。ターミナルがなく、`--yes` も指定していない場合は、変更を実行しません。 |
| 1 人の承認、2 人の承認 | MoleSignal は **Mole Agent → 承認** にレビュー担当者向けの承認リクエストを作成します。コマンドは承認リクエストを出力し、終了コード `3` で終了します。`--wait` を指定すると、`--timeout` で指定した時間（デフォルトは 30 分）を上限に承認結果を待ち、承認された場合に変更を実行します。 |
| 無効 | コマンドは失敗し、その理由を出力します。 |

ツール固有のポリシーがない場合、リスクに応じたデフォルトのモードで実行します。 `create_annotation` と `submit_search_job` は確認、`acknowledge_incident`、 `resolve_incident`、`run_synthetic_monitor` は 1 人の承認です。`--reason` で指定した理由は、レビュー担当者に提示し、監査ログに記録します。

確認には MCP プロトコルのリビジョン 2026-07-28 が必要です。MoleSignal が対応していれば、CLI はこのリビジョンを使用します。 `molesignal status` で使用中のリビジョンを確認できます。

## インシデントを一覧表示する

```bash
molesignal incidents
```

アクティブなインシデントを新しい順に表示します。各インシデントのステータス、重大度、経過時間、サービス、概要を確認できます。`--status resolved` や `--status all` で対象を変更できます。`--since 7d` で直近 7 日間に作成されたインシデントに絞り込み、 `-n` で表示件数を指定します。

`molesignal incidents show` は、指定したインシデントのルール、時刻、サービス、ラベル、ランブックなどのメモ、サンプリングされたトレースを表示します。`--rca` で根本原因分析を追加し、`--web` でインシデントを MoleSignal で開きます。

```bash
molesignal incidents show <incident> --rca
```

## インシデントを確認・解決する

```bash
molesignal incidents ack <incident>
```

```bash
molesignal incidents resolve <incident> --reason "Rolled back to 2.3.9"
```

どちらの操作にもツールポリシーが適用され、`alerts.incidents.acknowledge` 権限が必要です。

## オンコール担当者を確認する

```bash
molesignal oncall
```

有効なオンコールスケジュールごとに担当者を表示します。`--schedule` でスケジュールを 1 つに絞り込みます。 `--at "2026-10-27 09:00"` のように `--at` を指定すると、別の時刻の担当者を確認できます。

## 承認済みの変更を実行する

`molesignal approvals` は、Mole Agent、エージェントツール、コマンドからの承認リクエストのうち、レビュー待ちのものと承認済みで未実行のものを一覧表示します。`--all` を指定すると、承認または却下の判断が済んだリクエストも表示します。

```bash
molesignal approvals
```

`molesignal approvals show <approval>` は、指定したリクエストのアクション、対象、理由、影響、レビュー結果を表示します。`molesignal approvals execute <approval>` は承認済みの変更を実行します。MoleSignal が実行前に確認を求める場合があります。

```bash
molesignal approvals execute <approval>
```

## ダッシュボードにアノテーションを追加する

`molesignal annotate` は、特定の時点または期間にアノテーションを追加します。対象は、すべてのダッシュボードまたは指定した 1 つのダッシュボードです。

```bash
molesignal annotate "Release 2.4.0" --tags release,checkout --yes
```

| オプション | 説明 |
|---|---|
| `--description <text>` | アノテーションの詳細です。 |
| `--tags <a,b>` | アノテーションの検索に使うタグです。 |
| `--dashboard <id>` | 指定したダッシュボードだけに追加します。 |
| `--stream <stream>` | アノテーションの対象ストリームです。 |
| `--time <time>`, `--end <time>` | 開始時刻と終了時刻です。デフォルトでは現在の時点に追加します。 |

アノテーションの追加には `dashboards.edit` 権限が必要です。

## シンセティックチェックを実行する

`molesignal synthetics` は、チェックの種類、状態、ライフサイクルを一覧表示します。 `molesignal synthetics results <check>` は、指定したチェックのロケーションごとの直近の実行について、結果、実行時間、失敗した場合の理由を一覧表示します。チェックは ID または名前で指定します。

`molesignal synthetics run` は、指定したチェックを各ロケーションですぐに実行します。`--wait` を指定すると、実行の完了を待ち、いずれかの実行が失敗するか、`--timeout` で指定した時間内（デフォルトは 10 分）に完了しなければ、終了コード `1` で終了します。パイプラインはこの終了コードでリリースを停止できます。

```bash
molesignal synthetics run "Checkout API" --wait --yes
```

結果が正常または不安定の場合、その実行は合格です。チェックの実行には `synthetics.monitors.manage` 権限が必要です。レビューなしで CI からチェックを実行するには、ツールポリシーで `run_synthetic_monitor` を **自動** に設定します。
