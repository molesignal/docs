`molesignal <command> --help` は、指定したコマンドについて同じ情報を表示します。

## すべてのコマンドに共通するオプション

MoleSignal と通信するすべてのコマンドで、次のオプションを指定できます。

| オプション | 説明 |
|---|---|
| `--profile <name>` | 使用する保存済みのサインイン情報です。[複数のサインイン情報を保存する](/ja/cli/sign-in#複数のサインイン状態を保持する)を参照してください。 |
| `--url <address>` | プロファイルに設定されたアドレスの代わりに使用する MoleSignal のアドレスです。 |
| `--token <token>` | このコマンドでのみ使用する API トークンです。 |

時刻には、ISO 形式の時刻、ローカル時刻での日時（例：`2026-10-26 14:00`）、エポックからの経過時間（秒、ミリ秒、マイクロ秒）、または現在からさかのぼる期間を指定できます。期間は、数値と単位（`ms`、`s`、`m`、`h`、`d`、`w`）を組み合わせて指定します。

## サインイン

| コマンド | オプション | 説明 |
|---|---|---|
| `login` | `--url <address>`, `--profile <name>`, `--with-token` | ブラウザーで、または標準入力から受け取った API トークンを使ってサインインします。そのプロファイルが現在のプロファイルになります。 |
| `logout` | `--profile <name>` | プロファイルのサインイン情報を削除します。アドレスは保持します。 |
| `profiles` | `--json` | プロファイルを一覧表示します。`profiles remove <name>` で指定したプロファイルを削除します。 |
| `use <profile>` | なし | 指定したプロファイルを現在のプロファイルに設定します。 |
| `status` | なし | アドレス、プロファイル、サーバー、MCP プロトコルのリビジョン、サインイン方式、ツール数を表示します。 |
| `whoami` | `--json` | ユーザー、組織、ロール、権限を表示します。 |
| `doctor` | なし | Node.js、構成、アドレス、プロキシ、ネットワークと TLS、システム時刻、サインイン状態、MCP エンドポイントを確認します。 |

## ログとクエリ

| コマンド | オプション | 説明 |
|---|---|---|
| `streams` | `--type <type>`, `--names`, `--json` | 指定した種類のストリームを一覧表示します。デフォルトは `logs` です。 |
| `logs <stream>` | `-f`, `-n`, `-q`, `--where`, `--since`, `--from`, `--to`, `--fields`, `--around`, `-B`, `-A`, `--interval`, `--json`, `--utc`, `--web` | ストリームの最新のログを出力します。`-f` を指定すると、新しいログを継続して出力します。[ログの表示と追跡](/ja/cli/logs)を参照してください。 |
| `query "<SQL>"` | `--stream`, `--since`, `--from`, `--to`, `-n`, `--csv`, `--json`, `--utc`, `--web` | ログストリームに対して読み取り専用の SQL ステートメントを 1 つ実行します。 |
| `fields <stream> [field]` | `--type`, `--since`, `--from`, `--to`, `-n`, `--match`, `--json` | ストリームのフィールド、または指定したフィールドで出現頻度の高い値を一覧表示します。 |

### `logs` のオプション

| オプション | デフォルト | 説明 |
|---|---|---|
| `-f`, `--follow` | オフ | **Ctrl+C** を押すまで、新しいログを出力し続けます。 |
| `-n`, `--lines <count>` | `100` | 最初に出力する最新のログの件数です。`1`～`5000` を指定できます。 |
| `-q`, `--query <query>` | なし | **ログ**ページと同じ形式のフィールドクエリです。 |
| `--where <condition>` | なし | ストリームのフィールドに適用する SQL 条件です。 |
| `--since <duration>` | `15m` | 現在からさかのぼる期間です。 |
| `--from <time>`, `--to <time>` | なし | `--since` の代わりに時間範囲を指定します。`--to` は `-f` と併用できません。 |
| `--fields <a,b,c>` | すべて | 時刻と指定したフィールドのみを出力します。 |
| `--around <time>` | なし | 指定した時刻の直前と直後のログを出力します。 |
| `-B`, `--before <count>` | `10` | `--around` と併用し、指定時刻より前のログの件数を指定します。最大 `250` 件です。 |
| `-A`, `--after <count>` | `10` | `--around` と併用し、指定時刻より後のログの件数を指定します。最大 `250` 件です。 |
| `--interval <duration>` | `2s` | ログの追跡時に新しいログを読み取る間隔です。 |
| `--json` | オフ | 各ログを JSON 形式で 1 行ずつ出力します。 |
| `--utc` | オフ | 時刻を UTC で出力します。 |
| `--web` | オフ | ログを出力する代わりに、**ログ**ページで開きます。 |

## メトリクス、トレース、サービス

| コマンド | オプション | 説明 |
|---|---|---|
| `metrics query '<PromQL>'` | `--since`, `--from`, `--to`, `-n`, `--csv`, `--json` | PromQL の範囲クエリを実行し、時系列ごとにスパークライン付きで 1 行ずつ出力します。 |
| `metrics names [text]`, `metrics labels <metric>`, `metrics values <metric> <label>`, `metrics series <metric>` | `-n`, `--match <label=value>`, `--json` | メトリクス名、ラベル、ラベル値、時系列を一覧表示します。 |
| `traces` | `--service`, `--errors`, `--min-duration`, `--since`, `--from`, `--to`, `-n`, `--json` | 最近のトレースを一覧表示します。 |
| `traces show <trace>` | `--since`, `--from`, `--to`, `--json`, `--web` | トレースをウォーターフォール形式で表示します。 |
| `services` | `--env`, `--namespace`, `--sort`, `--since`, `--from`, `--to`, `-n`, `--json` | APM サービスを稼働状態とともに一覧表示します。 |
| `services show <service>` | `--env`, `--namespace`, `--since`, `--json`, `--web` | 指定したサービスの概要を表示します。 |
| `services compare <service> <baseline> <candidate>` | `--env`, `--since`, `--fail-on-regression`, `--json` | 2 つのバージョンを比較します。 |
| `search-jobs` | `-n`, `--json` | 検索ジョブを一覧表示します。 |
| `search-jobs submit "<statement>"` | `--stream`, `--type`, `--promql`, `--step`, `--since`, `--from`, `--to`, `--limit`, `--keep`, `--wait`, 変更オプション | 検索ジョブを送信します。 |
| `search-jobs show <job>`, `search-jobs results <job>`, `search-jobs cancel <job>` | `-o <file>`, `--csv`, `--json`, 変更オプション | ジョブの詳細を表示する、結果の行を書き出す、またはジョブをキャンセルします。 |

## オンコールと変更

| コマンド | オプション | 説明 |
|---|---|---|
| `incidents` | `--status`, `--since`, `-n`, `--json` | インシデントを一覧表示します。デフォルトではアクティブなインシデントのみを表示します。 |
| `incidents show <incident>` | `--rca`, `--json`, `--web` | 指定したインシデントを表示します。 |
| `incidents ack <incident>`, `incidents resolve <incident>` | 変更オプション | インシデントを確認済みまたは解決済みにします。 |
| `incidents create --title <text>` | `--description`, `--severity`, `--priority`, `--urgency`, `--service`, `--label`, `--team`, `--policy`, `--user`, `--major`, `--json`, 変更オプション | ルールで検知できなかった問題について、インシデントを手動で作成します。`--team`、`--policy`、`--user` のいずれかで割り当て先の ID を指定しない限り、アラートと同じ方法でルーティングします。`--priority` と `--urgency` には、組織で設定したレベルを指定します。作成したインシデントの ID とリンクを表示します。 |
| `oncall` | `--schedule`, `--at`, `--json` | オンコール担当者を表示します。 |
| `approvals` | `--all`, `-n`, `--json` | 承認待ちまたは承認済みのリクエストを一覧表示します。 |
| `approvals show <approval>`, `approvals execute <approval>` | `--json`, 変更オプション | 承認リクエストを表示するか、承認済みの変更を実行します。 |
| `annotate "<title>"` | `--description`, `--tags`, `--dashboard`, `--stream`, `--time`, `--end`, 変更オプション | ダッシュボードにアノテーションを追加します。 |
| `synthetics` | `--lifecycle`, `--json` | シンセティックチェックを一覧表示します。 |
| `synthetics results <check>` | `--since`, `-n`, `--json` | 指定したチェックの直近の実行結果を一覧表示します。 |
| `synthetics run <check>` | 変更オプション | チェックをすぐに実行します。`--wait` を指定すると、実行が完了するまで待機します。 |
| `alerts rules export` | `--ids`, `-o`, `--output` | アラートルールをバンドルとしてエクスポートします。`--ids` を指定すると、指定したルールのみをエクスポートします。[インポートとエクスポート](/ja/alerting/rules#インポートとエクスポート)を参照してください。 |
| `alerts rules apply -f <file>` | `--dry-run`, `--create-only`, `--json` | バンドルまたは Prometheus のアラートルールファイルを適用します（`-f -` は標準入力から読み込みます）。まず試行して各ルールを適用した場合の処理内容を表示し、失敗がなければすべてを一括で書き込みます。ルールの処理に失敗した場合は、CI で検知できるように終了コード 1 を返します。 |
| `alerts policies export`, `alerts schedules export`, `alerts routing export` | `--ids`, `-o`, `--output` | エスカレーションポリシー、オンコールスケジュール、またはルーティングルールをバンドルとしてエクスポートします。バンドルでは、ユーザーをメールアドレスで、それ以外を名前で識別します。[インポートとエクスポート](/ja/alerting/on-call#インポートとエクスポート)を参照してください。 |
| `alerts policies apply -f <file>`, `alerts schedules apply -f <file>`, `alerts routing apply -f <file>` | `--dry-run`, `--create-only`, `--json` | `alerts rules apply` と同じ方法でバンドルを適用します。まずスケジュールを適用し、次にそのスケジュールに従って担当者を呼び出すポリシーを適用します。最後に、そのポリシーを参照するアラートルールとルーティングルールを適用してください。 |

変更オプションは次のとおりです。[変更の実行方法](/ja/cli/changes#変更の実行方法)を参照してください。

| オプション | 意味 |
|---|---|
| `--reason <text>` | 変更の理由を指定します。理由は承認リクエストとともに保存し、監査ログにも記録します。 |
| `--wait` | 変更に承認が必要な場合は、承認されるまで待機してから変更を実行します。 |
| `--timeout <duration>` | `--wait` の待機時間を指定します。デフォルトは `30m` で、`synthetics run` の場合は `10m` です。 |
| `-y`, `--yes` | MoleSignal が変更の確認を求める場合に、入力を待たずに確認します。 |

## リリースとデータ

以下のコマンドには API トークンが必要です。[CI とリリース](/ja/cli/ci)を参照してください。

| コマンド | オプション | 説明 |
|---|---|---|
| `deploy` | `--service`, `--version`, `--env`, `--namespace`, `--kind`, `--status`, `--commit`, `--repository`, `--pull-request`, `--author`, `--ci-url`, `--description`, `--time`, `--dry-run`, `-- <command>` | デプロイを記録します。 |
| `source-maps upload <path>…` | `--application`, `--service`, `--release`, `--platform`, `--arch`, `--debug-id`, `--concurrency`, `--dry-run` | JavaScript のソースマップをアップロードします。 |
| `symbols upload <path>…` | `--application`, `--service`, `--release`, `--platform`, `--arch`, `--debug-id`, `--concurrency`, `--dry-run` | Flutter、Android、Apple のシンボルをアップロードします。 |
| `source-maps list`, `symbols list` | `--application`, `--service`, `--release`, `--platform`, `--kind`, `--json` | アップロード済みの項目を一覧表示します。 |
| `source-maps delete <id>`, `symbols delete <id>` | なし | 指定したアップロードを削除します。 |
| `send <stream>` | `--field <name=value>`, `--raw`, `--batch` | 標準入力の各行をログストリームに送信します。 |
| `run <stream> -- <command>` | `--name`, `--field <name=value>`, `--quiet` | コマンドを実行し、その出力と終了ステータスをログストリームに送信します。 |

## ツールとセットアップ

| コマンド | オプション | 説明 |
|---|---|---|
| `tools [words…]` | `--domain`, `--json` | 呼び出し権限のあるツールを一覧表示します。`tools show <tool>` は、指定したツールとその引数を表示します。 |
| `call <tool> [name=value…]` | `--input`, `--since`, `--from`, `--to`, 変更オプション | ツールを呼び出し、結果を JSON 形式で出力します。 |
| `mcp` | なし | MoleSignal の MCP ツールを標準入出力（stdio）経由で提供します。 |
| `mcp setup <tool>` | `--scope`, `--installed`, `--print` | `claude`、`cursor`、`codex`、`vscode`、`gemini` のいずれかにサーバーを追加します。 |
| `open [page] [id]` | `--print` | MoleSignal のページをブラウザーで開きます。 |
| `completion <shell>` | なし | `bash`、`zsh`、`fish` のいずれかの補完スクリプトを出力します。 |
| `--help`, `--version` | なし | ヘルプまたはバージョンを表示します。 |

## 環境変数

| 変数 | 意味 |
|---|---|
| `MOLESIGNAL_URL` | `--url` オプションや保存済みのアドレスの代わりに使用する MoleSignal のアドレスを指定します。 |
| `MOLESIGNAL_TOKEN` | 保存済みのサインイン情報の代わりに使用する API トークンを指定します。 |
| `MOLESIGNAL_PROFILE` | 現在のプロファイルの代わりに使用するプロファイルを指定します。 |
| `MOLESIGNAL_CONFIG` | プロファイルを保存するファイルを指定します。デフォルトは `~/.config/molesignal/config.json` です。 |
| `HTTPS_PROXY`, `HTTP_PROXY` | リクエストに使用するプロキシを指定します。 |
| `NO_PROXY` | プロキシを経由せずに接続するホストを指定します。 |
| `NODE_EXTRA_CA_CERTS` | システムの認証局に加えて信頼する認証局を指定します。 |
| `NO_COLOR` | 色を付けずに出力します。 |
| `FORCE_COLOR` | 出力先がターミナルでない場合も、色を付けて出力します。 |

オプション、環境変数、保存済みのプロファイルの順に優先します。

## 終了コード

| コード | 意味 |
|---|---|
| `0` | コマンドが成功したか、追跡を停止しました。 |
| `1` | コマンドが失敗しました。理由は標準エラー出力に表示します。`--wait` の指定時にシンセティックチェックの実行が失敗した場合、`--fail-on-regression` の指定時にバージョンのリグレッションを検出した場合、`send` がログを拒否した場合、`doctor` のチェックが失敗した場合も、このコードを返します。 |
| `2` | 不明なコマンド、オプション、または引数を指定しました。 |
| `3` | 変更は承認待ちで、まだ実行していません。 |

`deploy -- <command>` と `run` は、実行したコマンドの終了コードをそのまま返します。
