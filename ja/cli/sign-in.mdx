CLI は一度サインインすると、その状態を保存して以降のコマンドで再利用します。サインイン方法は 2 つあります。

| 方法 | 用途 |
|---|---|
| ブラウザーでのサインイン | ブラウザーを使える端末での手動操作に適しています。OAuth 2.1 を使用し、サインイン状態を自動で更新します。 |
| API トークン | スクリプト、ビルドマシン、ブラウザーのない端末に適しています。 |

ブラウザーでのサインインでアクセスできるのは、MoleSignal の MCP エンドポイントだけです。デプロイの報告、ソースマップやシンボルのアップロード、ログの送信には MoleSignal の API を呼び出すため、API トークンが必要です。

## ブラウザーでサインインする

```bash
molesignal login --url https://molesignal.example.com
```

1. CLI が MoleSignal に自身を登録し、MoleSignal の認可ページを既定のブラウザーで開きます。セッションがない場合は、そのページで MoleSignal にサインインしてください。
2. 認可ページには、クライアント、アカウント、組織の名前と、許可される操作の一覧が表示されます。複数の組織に所属している場合は、**組織**で 1 つ選択してください。アクセス権は選択した組織に紐付きます。
3. **認可**をクリックします。ブラウザーから CLI に処理が戻り、CLI が利用できるツールの数を表示します。

CLI は `mcp` と `offline_access` のスコープを要求します。認可を取り消すまで、サインイン状態は自動で更新されます。認可ページは 5 分間待機します。時間が経過するとコマンドが終了し、既存のサインイン状態があればそのまま維持します。サインインを拒否または中断した場合も、既存のサインイン状態を維持します。

<Note>
  ブラウザーは、コマンドの実行中だけ動作する `http://127.0.0.1` のリスナーに処理を戻します。コマンドが終了すると、端末上にリスナーは残りません。SSH で接続したリモート端末では、ブラウザーからそのリスナーに接続できません。API トークンでサインインしてください。
</Note>

## API トークンでサインインする

**ID とアクセス → API トークン**でトークンを作成し、標準入力で渡します。

```bash
printf '%s' "$MOLESIGNAL_TOKEN" | molesignal login --url https://molesignal.example.com --with-token
```

トークンには、所有者であるユーザーまたはサービスアカウントの権限が適用されます。

## トークンを保存せずに使う

ビルドマシンなどでは、アドレスとトークンを環境変数に設定します。どちらも保存しません。

```bash
MOLESIGNAL_URL=https://molesignal.example.com MOLESIGNAL_TOKEN=<token> molesignal status
```

`--url` と `--token` を使うと、1 回のコマンド実行に限って同じ設定を適用できます。特定のアドレスに対して保存したトークンを別のアドレスに送信することはありません。

## 複数のサインイン状態を保持する

サインインするたびに、アドレスとそのアクセス情報をプロファイルに保存します。複数のプロファイルを使うと、CLI で複数の MoleSignal インスタンスや、1 つのインスタンス内の複数の組織へのサインイン状態を保持できます。 `--profile` で、サインイン情報を保存するプロファイルを指定します。

```bash
molesignal login --url https://staging.molesignal.example.com --profile staging
```

最後にサインインしたプロファイルが現在のプロファイルになります。コマンドは現在のプロファイルを使用します。 `--profile` または `MOLESIGNAL_PROFILE` で、1 回のコマンド実行に限って別のプロファイルを選択できます。初回のサインインで `--profile` を指定しない場合は、プロファイル `default` に保存します。

| コマンド | 動作 |
|---|---|
| `molesignal profiles` | プロファイルと、それぞれのサインイン方法およびアドレスを一覧表示します。現在のプロファイルには `*` が付きます。 |
| `molesignal use <profile>` | 指定したプロファイルを現在のプロファイルにします。 |
| `molesignal logout --profile <profile>` | プロファイルのサインイン情報を削除し、アドレスは残します。 |
| `molesignal profiles remove <profile>` | プロファイルを削除します。 |

## サインイン情報の保存先

プロファイルは `~/.config/molesignal/config.json` に保存されます。このファイルを読み取れるのは所有者だけです。 `XDG_CONFIG_HOME` が設定されている場合はその設定に従い、Windows では `%APPDATA%` を使用します。 `MOLESIGNAL_CONFIG` で別のファイルを指定できます。

## プロキシ経由で使う

`HTTPS_PROXY`（または `HTTP_PROXY`）を設定すると、CLI のすべてのリクエストがプロキシを経由します。`NO_PROXY` にはプロキシを経由せずに接続するホストを指定します。

```bash
HTTPS_PROXY=http://proxy.example.com:3128 NO_PROXY=localhost molesignal status
```

MoleSignal がプライベート認証局の発行した証明書を使用する場合は、その認証局の証明書を `NODE_EXTRA_CA_CERTS` で指定します。

## サインイン状態と設定を確認する

`molesignal status` は、アドレス、プロファイル、応答したサーバー、MCP プロトコルのリビジョン、サインイン方法、MCP ツールの数を表示します。

```bash
molesignal status
```

`molesignal whoami` は、ユーザー、組織、ロール、および MoleSignal が付与する権限を表示します。

```bash
molesignal whoami
```

`molesignal doctor` は、CLI の動作に必要な以下の項目を確認し、問題があれば対処方法を表示します。確認項目は、Node.js、設定ファイルの権限、アドレス、プロキシ、ネットワークと TLS、システム時刻、サインイン状態、MCP エンドポイントです。確認に失敗すると、終了コード `1` を返します。

```bash
molesignal doctor
```

## サインアウトする

`molesignal logout` は、この端末に保存されている現在のプロファイルのサインイン情報を削除します。

```bash
molesignal logout
```

付与されたアクセス権は、次の場所で取り消すまで MoleSignal に残ります。 **Mole Agent → 設定 → インバウンド MCP**。
