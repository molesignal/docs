**トレース**を開くと、トレース全体、個々のスパン、RED ドリルダウン、およびサービスグラフの間を移動できます。

## トレースとスパンを参照

**トレース**タブには、リクエストごとに 1 行が表示されます。終了状態 (ルートスパンの HTTP ステータス、または **OK** と **エラー**)、開始時刻、サービスとオペレーション、ページ内で最長のトレースに対する所要時間、スパン数、エラー数、トレース ID です。**開始時刻**、 **所要時間**、**スパン**、**エラー**をクリックすると、その列で並べ替えられます。テーブルの上には、クエリに一致するすべてのトレースをカウントするヒストグラムがあり、その横のグラフにはそれらのトレースの p50、p95、p99 の所要時間が描画されます。

**スパン**タブには、一致するスパンごとに 1 行が、種類とそのスパン自身の所要時間とともに表示されます。スパンのフィールドに対するフィルターは、そこではスパン自体に適用されます。

クエリエディターには **コード** と **ビルダー** のモードがあり、タイトル横の 2 つのアイコンで切り替えます (`</>` はコード、ブロックはビルダー)。**コード**では、次のようなフィールドクエリを入力できます。 `status_code = 'ERROR'` や `duration_ns > 500000000` (500 ms 超)、またはトレースストリームに対する SQL です。**ビルダー**では、フィールドクエリがフィルターの行として表示され、代替案ごとに 1 行になります。クエリは並べて表示できるタブで実行され、フィールドリストではフィールド分析が開き、**共有**ではクエリへのリンクをコピーできます。 [ログ](/ja/logs#クエリタブ)と同様です。アドレスバーにも適用済みのクエリが保持されるため、そのコピーでクエリを共有できます ([クエリを共有する](/ja/logs#クエリを共有))。

スパンのフィールドに対する比較では、そのフィールドに一致するスパンを持つトレースが保持され、`!=` ではどのスパンにもその値を持たないトレースが保持されます。`trace_id`、`duration_ns`、`span_count`、`error_count` はトレース自体に対して比較されます。`in` は複数の値のいずれかを指定します: `service.name in ('checkout', 'payments')`。

`AND` と `OR` は比較を結合し、`AND` が先に評価され、括弧でグループ化します。 [ログ](/ja/logs#クエリを記述)と同様です。比較は `OR` の中でも意味を保ちます: `service.name = 'checkout' OR span_count > 50` は `checkout` のスパンを持つトレースと、 50 を超えるスパンを持つトレースを保持します。`timeout` のようにフィールドを指定しないテキストは、トレース ID、スパン ID、サービス、オペレーション、ステータスから検索されます。**スパン**タブと RED ドリルダウンは、各スパンに対して同じクエリを読み取ります。スパンは `a OR b` に一致するとき、`a` または `b` に一致します。

フィールドリストは結果の横にあります。**共通フィールド**が最初に表示されます: `service.name`、`name`、 `status_code`、HTTP ステータス、`duration_ns` です。フィールドを開くと、読み込まれたトレースが保持する値が表示されます。**この値で絞り込み**は値をクエリに追加します。代替案のクエリは先に括弧で囲まれるため、値はその全体を絞り込み、同じフィールドの 2 番目の値は最初の値と `in` リストで結合されるため、複数の値を選択できます。**この値を除外**をクリックすると、値が除外されます。

**トレース**テーブルの **列** では、列の表示、非表示、並べ替えを行い、各トレースのルートスパンのフィールドを列として追加できます。フィールドリストでそのようなフィールドの目アイコンを操作しても同じです。この配置はユーザーごと、ストリームごとに保持され、**デフォルトに戻す**でテーブルを開いたときの列に戻ります。

## RED ドリルダウン

**RED** タブでは、クエリに一致するリクエストのレート、エラー、所要時間を確認できます。サービスがリクエストを受け付けた場所、または指定した場合はすべてのスパンが対象です。**集計単位**では、任意のスパンフィールドでリクエストをグループ化でき、テナントなどの [ビジネスキー](/ja/business-context) も含まれます。値を選ぶとクエリがその値に絞り込まれ、さらに 1 つ下のフィールドへ進みます。レイテンシーチャート上でドラッグすると、所要時間の範囲に絞り込まれます。

**比較**では、失敗したリクエスト、または p95 や p99 より遅いリクエストを、クエリ内の他のリクエストとフィールドごとに比較します。2 つのセットで値の共有が最も少ないフィールドが先頭に表示され、それぞれについて割合が最も異なる値と、そのフィールドで 2 つのセットがどの程度離れているかが、0% (同じ構成) から 100% (共通する値なし) で示されます。遅いリクエストが集中するリージョン、バージョン、テナントなどが上位に目立ちます。 ID、時刻、JSON フィールドは除外され、失敗したリクエストを比較する場合はステータスも除外されます。各セットは最大 1,000 スパンのサンプルから読み取られ、そのことはカードに表示されます。フィールドを開くとその内訳が表示され、値を選ぶとクエリがその値に絞り込まれます。Mole Agent も `compare_attribute_distributions` で同じように比較します。

## トレースを調査する

行をクリックすると、リストの上にドロワーでトレースが開きます。ドロワーの左端をドラッグすると幅を変更できます。幅は次のトレースを開くときも維持されます。**J** と **K** でリストの次と前のトレースに移動でき、ドロワーではそのトレース自身のページも開きます。

トレースのヘッダーは固定されたままです。ルートのサービスとオペレーション、HTTP ステータス、エラー数、所要時間、開始時刻、スパン数とサービス数、深さ、トレース ID が表示されます。 **関連ログ** と **サービスメトリクス** を開くと、トレース周辺のこれらのシグナルが表示されます。**プロファイル** を開くと、トレースの ID を保持していたプロファイルが開きます。保持しているものがない場合は、トレース前後の数分間のプロファイルが開きます。**ユーザーセッション** を開くと、そのトレースが処理した [RUM](/ja/rum) セッションが開きます。スパンが `session.id` または `session_id` で示すセッション、それがなければブラウザのリクエストが `traceparent` でトレースの ID を運んだセッションです。

ヘッダーの末尾にある **トレースをダウンロード** を使うと、トレースをファイルとして保存できます。

| 形式 | 内容 |
|---|---|
| **JSON** | [トレース API](/ja/api/web/trace#1つのトレースを読み取る) が返すスパン。 |
| **OTLP JSON** | OTLP/JSON のエクスポートリクエストです。形式は `resourceSpans` → `scopeSpans` → `spans` で、コレクターまたは OTLP HTTP の受信エンドポイントがそのまま取り込みます。時刻は 10 進文字列のナノ秒です。 |

スパンは次の 4 つのビューで表示されます。

| ビュー | 表示内容 |
|---|---|
| **ウォーターフォール** | 時間軸上のスパンツリーで、サービスごとに 1 色で表示されます。上部のミニマップでは、ドラッグした範囲に時間軸をズームできます。検索では一致するスパンを順にたどり、トグルで失敗したスパンのみを表示できます。また、スパンは呼び出した先とあわせてフォーカスできます。 |
| **フレームグラフ** | 各スパンを、それを呼び出したスパンの下のブロックとして表示します。ダブルクリックすると、そのスパンに時間軸をズームします。 |
| **スパン一覧** | サービスとオペレーションでグループ化したスパンです。件数、エラー、所要時間、セルフタイム、トレース自身の時間に占める割合を表示します。 |
| **サービスマップ** | このトレースのサービスと、その間の呼び出しです。呼び出し回数、所要時間、失敗を表示します。 |

ウォーターフォールとフレームグラフのツールバーにある **クリティカルパス** は、トレースのエンドツーエンドの時間が待機していたスパンを描画します。パスはルートスパンの終了時点から時間をさかのぼります。各時点で、その時点までに最後に終了した子スパンをたどり、呼び出したスパンまで切り詰めて、その子スパンが開始した時点から続けます。その時点でまだ実行中の子スパンは、パスがたどったスパンと並行して実行されたものであり、パスには含まれません。どの子スパンにも覆われない時間は、呼び出したスパンに残ります。ウォーターフォールでは、各バーに沿った線がパス上のそのスパンの区間を示し、他のスパンは淡色表示になります。凡例にはパスの長さと、各サービスが占めるその割合が表示されます。このスイッチの状態はトレースを切り替えても維持されます。

選択したスパンの詳細はビューの横に表示され、幅はドラッグで変更できます。タブは **属性**、**リソース**、**イベント**、**リンク**、**ログ**、**メトリクス**、**プロフィール** です。 **リンク** には、そのスパンにリンクしている他のトレースのスパンも一覧表示されます。**ログ** には、トレース ID を持つログ行が、スパン単位またはトレース全体で表示されます。**メトリクス** には、そのスパンのサービスとオペレーションのリクエスト数、エラー数、p95 所要時間が、前後の数分間について描画されます。

**プロフィール** には、スパンの実行中にプロファイラーがサンプリングした内容が表示されます。サンプルは、[OTLP プロファイル](/ja/profiles) と同様に、プロファイラーがトレースコンテキスト付きで記録した場合にスパンにリンクされます。リンクされたサンプルがある場合、タブにはセルフ値で見て 1 つのプロファイルタイプの大半を占めた関数が一覧表示され、**フレームグラフを開く** でそれらのサンプルが描画され、**プロファイル画面で開く** でプロファイルページに表示されます。ウォーターフォールの行にある炎のマークは、そのスパンにリンクされたサンプルがあることを示します。リンクされたサンプルがない場合は、**このスパンの前後のプロファイル** でスパン前後の数分間のプロファイルが開きます。

各トレースには専用のページもあり、トレースへのリンクを開くとそのページが表示されます。ブラウザの RUM セッションにセッション識別子が含まれている場合は、**セッションのトレース** を開いて関連するバックエンドリクエストを確認します。

## 2 つのトレースを比較する

**トレース** テーブルの上にある **比較するトレースを 2 件選択** をクリックし、続けて 2 つの行をクリックします。最初に選んだトレースが **A**、2 番目が **B** です。**比較** をクリックすると、A のページで比較が開きます。トレースのヘッダーでは、**別のトレースと比較** で相手のトレース ID を指定します。ID だけで開くトレースは、OTLP 経由で受信し、過去 31 日以内に開始したものが対象です。

比較画面には、両方のトレース、それぞれの所要時間、B が A よりどれだけ長く（または短く）かかったかが表示されます。続いて 3 つのタブがあり、いずれも変化の大きい順に並びます。

| タブ | 表示内容 |
|---|---|
| **サービス別** | A と B それぞれのサービスのスパンとセルフタイム、および A から B への変化。 |
| **オペレーション別** | 各サービスのオペレーションごとに同じ内容。 |
| **片方のトレースのみ** | 一方のトレースだけが行った呼び出し。スパンは、その上位にあるスパンのサービスとオペレーションで照合されるため、同じクエリを 2 か所から実行すると 2 回の呼び出しとして数えられます。欠けている呼び出しは、その下で呼び出したスパンも含めて数えます。 |

セルフタイムは、スパンが自身の処理に費やした時間であり、呼び出したスパンの完了を待つ間に費やした時間は含みません。ページの先頭には **A と B を入れ替え** と **比較を終了** があり、ページのアドレスには両方のトレースが含まれるため、比較結果を共有できます。

## サービスグラフとカタログ

**サービスグラフ** タブは、トレースのスパンからノードとエッジを導出します。グラフには、リクエストレート、エラーレート、レイテンシの関係が、別途メンテナンスするトポロジーなしで表示されます。

**サービスカタログ** は、観測されたサービスとオペレーションをグループ化し、サービスから現在のトレースへ移動できるようにします。

## 受信と伝播

トレースは OTLP HTTP または OTLP gRPC で送信します。MoleSignal は標準の W3C Trace Context と OpenTelemetry のセマンティック属性を保持します。サポート対象のアプリケーションリクエストでは、レスポンスヘッダーで `X-Request-Id` と `X-Trace-Id` が公開されます。

ストリーム上の [リアルタイムパイプライン](/ja/pipelines#トレース) は、テールサンプリングの後、スパンが書き込まれる前にスパンを変更または破棄します。トレース一覧は、スパン数とエラー数とともに、書き込まれたとおりのスパンを表示します。

## 権限

組織のワークスペースでは `traces.read` が必要です。プラットフォーム管理者は、保護された `_sys` テレメトリスコープに対して `sys.telemetry.read` を使用します。
