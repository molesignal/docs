**トレース**を開くと、トレース全体、個別のスパン、RED ドリルダウン、サービスグラフを切り替えられます。

## トレースとスパンを参照する

**トレース**タブには、リクエストごとに 1 行が表示されます。各行には、終了ステータス（ルートスパンの HTTP ステータス、または **OK** や **エラー**）、開始時刻、サービスとオペレーション、ページ内で最長のトレースに対する相対的な所要時間、スパン数、エラー数、トレース ID が表示されます。**開始時刻**、 **所要時間**、**スパン**、**エラー**をクリックすると、その列で並べ替えられます。テーブルの上には、クエリに一致するすべてのトレースを集計したヒストグラムがあり、その隣のグラフには、該当するトレースの所要時間の p50、p95、p99 が表示されます。

**スパン**タブには、一致するスパンごとに 1 行が表示され、スパンの種類と所要時間を確認できます。このタブでは、スパンのフィールドに対するフィルターを各スパンに適用します。

クエリエディターには **コード** と **ビルダー** の 2 つのモードがあり、タイトルの横にある 2 つのアイコン（`</>` はコード、ブロックはビルダー）で切り替えます。**コード**では、 `status_code = 'ERROR'` や `duration_ns > 500000000`（500 ms より長い）などのフィールドクエリ、またはトレースストリームに対する SQL を入力できます。**ビルダー**はフィールドクエリをフィルターの行として表示し、OR で結ぶ条件ごとに 1 行を使用します。クエリはタブで実行し、タブを横に並べられます。フィールドリストからフィールド分析を開けます。**共有**をクリックすると、クエリへのリンクがコピーされます。これらの操作は [ログ](/ja/logs#クエリタブ)と同じです。適用済みのクエリはアドレスバーの URL にも含まれるため、URL をコピーしてクエリを共有できます（[クエリを共有する](/ja/logs#クエリを共有する)）。

スパンのフィールドに比較条件を指定すると、一致するスパンを含むトレースが残ります。`!=` を指定すると、どのスパンにも指定した値がないトレースが残ります。`trace_id`、`duration_ns`、`span_count`、`error_count` はトレース自体の値で比較します。`in` は次のように、複数の値のいずれかに一致するものを抽出します。 `service.name in ('checkout', 'payments')`。

[ログ](/ja/logs#クエリを記述する)と同様に、`AND` と `OR` で比較条件を結合し、括弧でグループ化します。`AND` を先に評価します。 `OR` で結合しても、各比較条件の意味は変わりません。 `service.name = 'checkout' OR span_count > 50` は、`checkout` のスパンを含むトレースと、スパンが 50 個を超えるトレースを抽出します。`timeout` のようにフィールドを指定しないテキストは、トレース ID、スパン ID、サービス、オペレーション、ステータスから検索します。**スパン**タブと RED ドリルダウンでは、同じクエリをスパンごとに評価します。`a` または `b` に一致するスパンは、`a OR b` に一致します。

フィールドリストは結果の横に表示されます。先頭の **共通フィールド** には `service.name`、`name`、 `status_code`、HTTP ステータス、`duration_ns` が並びます。フィールドを開くと、読み込んだトレースに含まれる値が表示されます。**この値で絞り込み**を選択すると、その値がクエリに追加されます。OR で結んだ条件がある場合は、クエリ全体を括弧で囲んでから値を追加します。同じフィールドで 2 つ目の値を選ぶと、最初の値と同じ `in` リストに追加されるため、複数の値を選択できます。**この値を除外**を選択すると、その値を除外できます。

**トレース**テーブルの上にある **列** では、列の表示、非表示、並べ替えのほか、各トレースのルートスパンのフィールドを列に追加できます。フィールドリストでは、対象フィールドの目のアイコンからも列に追加できます。列の設定はユーザーごと、ストリームごとに保存されます。**デフォルトに戻す**を選択すると、テーブルの列が初期状態に戻ります。

## トレースの詳細を確認する

行をクリックすると、一覧に重ねてドロワーが開き、トレースが表示されます。ドロワーの左端をドラッグして幅を変更できます。変更した幅は次のトレースにも適用されます。**J** と **K** で一覧の次または前のトレースに移動できます。ドロワーからトレースの個別ページも開けます。

トレースのヘッダーは固定表示されます。ルートサービスとオペレーション、HTTP ステータス、エラー数、所要時間、開始時刻、スパン数とサービス数、深さ、トレース ID を確認できます。 **関連ログ**と**サービスメトリクス**を選択すると、トレース前後のログやメトリクスが開きます。**プロファイル**を選択すると、トレース ID を記録したプロファイルが開きます。該当するプロファイルがなければ、トレース前後の数分間のプロファイルが開きます。**ユーザーセッション**を選択すると、トレースに関連する [RUM](/ja/rum) セッションが開きます。スパンの `session.id` または `session_id` で指定されたセッションが対象です。指定がなければ、ブラウザーリクエストの `traceparent` にトレース ID を含むセッションが対象です。

ヘッダーの末尾にある **トレースをダウンロード** を選択すると、トレースをファイルとして保存できます。

| 形式 | 内容 |
|---|---|
| **JSON** | [トレース API](/ja/api/web/trace#1-件のトレースを取得する) が返す形式のスパンです。 |
| **OTLP JSON** | コレクターや OTLP HTTP の取り込みエンドポイントで再取り込みできる OTLP/JSON エクスポートリクエストです。構造は `resourceSpans` → `scopeSpans` → `spans` です。時間の値は nanoseconds 単位の 10 進文字列です。 |

スパンは 4 つのビューで確認できます。

| ビュー | 表示内容 |
|---|---|
| **ウォーターフォール** | スパンツリーを時間軸上に表示し、サービスごとに色分けします。上部のミニマップで範囲をドラッグすると、その範囲に時間軸を拡大できます。検索に一致するスパンを順に確認したり、トグルで失敗したスパンだけを表示したり、特定のスパンとその呼び出し先に表示を絞ったりできます。 |
| **フレームグラフ** | 各スパンを、呼び出し元のスパンの下にブロックとして表示します。スパンをダブルクリックすると、そのスパンの範囲に時間軸を拡大できます。 |
| **スパン一覧** | スパンをサービスとオペレーションごとにグループ化し、スパン数、エラー数、所要時間、自己時間、トレース全体の時間に占める割合を表示します。 |
| **サービスマップ** | トレースに含まれるサービスとサービス間の呼び出しを表示します。呼び出し回数、所要時間、失敗数を確認できます。 |

ウォーターフォールとフレームグラフのツールバーにある **クリティカルパス** をオンにすると、トレース全体の完了時間を決めたスパンが表示されます。パスはルートスパンの終了時点から時間をさかのぼります。各時点までに終了した子スパンのうち、最も遅く終了したものを選び、呼び出し元スパンの区間内に収めてたどります。その子スパンの開始時点からさらにさかのぼります。その時点でまだ実行中だった別の子スパンは、パスがたどった子スパンと並行して実行されていたため、パスには含まれません。どの子スパンにも該当しない時間は、呼び出し元のスパンに含めます。ウォーターフォールでは、各バーに沿った線でそのスパンのうちパスに含まれる区間を示し、ほかのスパンは薄く表示します。凡例にはパスの所要時間と、サービスごとの割合が表示されます。別のトレースを開いても、スイッチはオンのままです。

選択したスパンの詳細はビューの横に表示され、境界をドラッグして幅を変更できます。詳細には **属性**、**リソース**、**イベント**、**リンク**、**ログ**、**メトリクス**、**プロフィール**の各タブがあります。 **リンク**には、そのスパンにリンクする別のトレースのスパンも表示されます。**ログ**には、トレース ID を含むログ行が、スパン単位またはトレース全体で表示されます。**メトリクス**には、スパンの前後数分間における対象サービスとオペレーションのリクエスト数、エラー数、p95 の所要時間がグラフで表示されます。

**プロフィール**には、スパンの実行中にプロファイラーが収集したサンプルが表示されます。 [OTLP プロファイル](/ja/profiles)のように、プロファイラーがトレースコンテキストとともにサンプルを記録すると、そのサンプルがスパンに関連付けられます。関連付けられたサンプルがある場合、タブには、1 つのプロファイルタイプについて自己値が大きい順に関数が表示されます。 **フレームグラフを開く**を選択するとサンプルがグラフに表示され、**プロファイル画面で開く**を選択するとプロファイル画面でサンプルが開きます。ウォーターフォールの行に炎のアイコンがある場合、そのスパンには関連付けられたサンプルがあります。関連付けられたサンプルがない場合は、 **このスパンの前後のプロファイル**を選択すると、スパンの前後数分間のプロファイルが開きます。

各トレースには個別ページがあり、トレースへのリンクから開けます。ブラウザーの RUM セッションにセッション識別子が含まれる場合は、**セッションのトレース**を開いて関連するバックエンドリクエストを確認します。

## 2 件のトレースを比較する

**トレース**テーブルの上にある**比較するトレースを 2 件選択**をクリックし、2 行をクリックします。最初に選択したトレースが **A**、次に選択したトレースが **B** です。**比較**をクリックすると、A のページに比較結果が表示されます。トレースページの上部にある**別のトレースと比較**では、比較相手のトレース ID を入力します。ID だけでトレースを開けるのは、 OTLP 経由で取り込まれ、過去 31 日以内に開始したトレースです。

比較結果には、両方のトレースとそれぞれの所要時間、B が A よりどれだけ長かったか、または短かったかが表示されます。その下に 3 つのタブがあり、各タブでは変化が大きい項目から順に表示します。

| タブ | 表示内容 |
|---|---|
| **サービス別** | A と B の各サービスのスパンと自己実行時間、および A から B への変化を表示します。 |
| **オペレーション別** | 同じ情報を、サービス内のオペレーションごとに表示します。 |
| **片方のトレースのみ** | 片方のトレースにしかない呼び出しを表示します。スパンは祖先スパンのサービスとオペレーションに基づいて照合するため、同じクエリでも異なる 2 か所から実行した場合は、2 件の呼び出しとして扱います。片方にしかない呼び出しでは、その配下で呼び出されたスパンを数えます。 |

自己実行時間とは、スパンが自身の処理に費やした時間です。呼び出し先のスパンの完了を待つ時間は含みません。ページ上部には **A と B を入れ替え**と**比較を終了**があります。ページの URL には両方のトレースの情報が含まれるため、比較結果を共有できます。

## サービスグラフとサービスカタログ

**サービスグラフ**タブは、トレースのスパンからノードとエッジを生成します。トポロジーを別途管理しなくても、サービス間のリクエストレート、エラー率、レイテンシーをグラフで確認できます。

**サービスカタログ**は、観測したサービスとオペレーションをまとめて表示します。サービスから最近のトレースに移動できます。

## 取り込みと伝播

OTLP HTTP または OTLP gRPC でトレースを送信します。MoleSignal は、標準の W3C Trace Context と OpenTelemetry のセマンティック属性を保持します。対応するアプリケーションリクエストでは、レスポンスヘッダーに `X-Request-Id` と `X-Trace-Id` が含まれます。

ストリーム上の[リアルタイムパイプライン](/ja/pipelines#トレース)は、テールサンプリング後、書き込み前にスパンを変更または破棄します。トレース一覧には、書き込まれたスパンがスパン数とエラー数とともに表示されます。

## アクセス権限

組織のワークスペースには `traces.read` が必要です。プラットフォーム管理者は、保護された `_sys` テレメトリスコープにアクセスするために `sys.telemetry.read` を使用します。
