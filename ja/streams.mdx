ストリームは、取り込み、クエリ、パイプライン、リテンションで使用される組織単位の契約です。 **ストリーム**を開くと、到着するデータを確認し、各ストリームを検査または設定できます。

## ストリームの種類

| タイプ | 主な内容 |
|---|---|
| `logs` | 構造化イベントとアプリケーションログです。 |
| `metrics` | 1 つのソース（1 つの Prometheus サーバーなど）のメトリクスサンプルで、`metric_name` によって区別されます。 |
| `traces` | OpenTelemetry スパンです。 |
| `profiles` | pprof BLOB にリンクされたプロファイルメタデータです。 |
| `extend` | 拡張テーブルとして管理され、処理中に使用されるルックアップデータです。 |

同じストリーム名が異なるストリームタイプに存在する場合があります。API リクエストと自動化では常に `stream_type` を含めてください。

### プラットフォームストリーム

MoleSignal はこれらのストリーム自体を書き込みます:

| ストリーム | 内容 |
|---|---|
| `_molesignal` | `_sys` 組織内の MoleSignal 自体のテレメトリです。詳細は[セルフオブザーバビリティ](/ja/self-observability)を参照してください。 |
| `_synthetic_results` | 合成チェックの各実行につき 1 行です。詳細は[合成モニタリング](/ja/synthetics#結果ストリームと保持期間)を参照してください。 |
| `_audit` | ワークスペースの監査イベントです。詳細は[監査ストリーム](/ja/settings/data-security#監査ストリーム)を参照してください。 |
| `_agent_model_traces` | Mole Agent のモデル呼び出しです。詳細は[使用状況と予算](/ja/agent#使用状況と予算)を参照してください。 |
| `_agent_score_traces` | Mole Agent の回答の品質スコアです。詳細は[品質](/ja/quality#ストリーム内のスコア)を参照してください。 |

これらは他のストリームと同様に読み取られます。`_audit` には `audit.read` が必要です。これがない場合、ストリームは一覧にも実行時の数値にも含まれず、開く、変更する、削除する操作は `403` を返します。他のものはこれらを書き込みません。これらの名前のストリームは作成できず、取り込みを行うと `403` を返し、どの [パイプライン](/ja/pipelines#プラットフォームストリーム)も書き込みません。

## ストリーム一覧

**ストリーム**にはワークスペースのすべてのストリームが一覧表示されます。タブを切り替えて、**すべて**のストリームまたは 1 つのタイプを表示し、名前または説明で検索し、実行時の状態でフィルタリングします。ヘッダーには、正常に受信しているストリームと注意が必要なストリームの数が表示され、期間中に書き込まれた圧縮データと現在のストレージ使用量が合計されます。

| 列 | 表示内容 |
|---|---|
| **ステータス** | **正常**、**遅延**、**中断**、**トラフィックなし**、**未使用**、または**統計を取得できません**。以下を参照してください。 |
| **受信レート**、**最終受信日時** | データの到着速度と、最後に到着した日時です。 |
| 圧縮データ | 期間中に書き込まれた圧縮バイト数です。 |
| **現在のストレージ使用量**、**リテンション** | 現在保存されているバイト数と、データが保持される日数です。 |
| **レコード**、**収集サイズ**、**保存サイズ**、**インデックスサイズ** | 保持されているレコード、変換前に受信したバイト数、データファイルのバイト数、インデックスのバイト数です。 |

| 状態 | 意味 |
|---|---|
| **正常** | 過去 15 分以内にデータが到着しています。 |
| **遅延** | 最後のデータは 15 分前から 2 時間前の間に到着しています。 |
| **中断** | 2 時間以上データがありません。 |
| **トラフィックなし** | Mole Agent トレースのストリームで、回答と回答の間はデータがありません。 |
| **未使用** | ストリームがデータを一度も受信していません。 |

**クエリ不可**とマークされたストリームはデータを受信し続けますが、クエリセレクターには表示されません。各行には **クエリ**または**探索**、**詳細を表示**、**ストリーム ID をコピー**があります。ヘッダーの**検索ジョブ**から [検索ジョブ](#検索ジョブ)を開けます。

## ストリームを作成

MoleSignal は最初の書き込み時にストリームを作成するため、ほとんどのストリームは自動的に表示されます。事前に作成してリテンション、暗号化対象フィールド、クエリへのアクセスを最初から設定できます。次を選択します: **ストリームを作成**:

| フィールド | ルール |
|---|---|
| **ストリーム名** | `snake_case`、最大 64 文字です。 |
| **説明** | 任意です。ストリームを流れるデータの内容です。 |
| **シグナルタイプ** | **ログ**、**メトリクス**、または**トレース**です。 |
| **保持期間（日）** | データが保持される期間です。 |
| **インデックス付きフィールド** | 全文インデックスが付与されるフィールドをカンマ区切りで指定します。 |
| **暗号化対象フィールド** | 保存前に暗号化されるフィールドをカンマ区切りで指定します。後から変更することはできません。詳細は[暗号化対象フィールド](#暗号化されたフィールド)を参照してください。 |
| **クエリを許可** | ルーティングパイプラインにのみデータを渡すソースストリームではオフにします。 |

## ストリームの詳細

ストリームを選択して開きます。**データをクエリ**を選択すると、そのストリームのエクスプローラーで開き、メニューには **ストリーム ID をコピー**と**ストリームを削除**があります。タブは次のとおりです:

| タブ | 内容 |
|---|---|
| **概要** | 実行時の状態、最初に受信したデータ、クエリへのアクセス、24 時間にわたる書き込み行数と圧縮データの推移です。データがないストリームでは**データソースの設定**と**テストデータを送信**を利用できます。 |
| **フィールドとインデックス** | フィールドとその型、インデックスタイプ、暗号化です。インデックスやマスキングを変更するには、フィールドを編集します。詳細は[スキーマとフィールド](#スキーマとフィールド)を参照してください。 |
| **リテンション** | ストリームのリテンションと、メトリクスストリームのダウンサンプリングです。詳細は[リテンションと削除](#リテンションと削除)を参照してください。 |
| **使用状況** | ストリームに依存するもの（書き込みを行う取り込みエンドポイント、パイプライン、保存済みクエリ、アラートルール）です。変更または削除の前に確認してください。 |
| **設定** | **説明**、**クエリを許可**、**クエリの最大対象期間（時間）**、**小さいファイルを日単位で統合**、**フィールドで分割**、およびログの場合は**フィールドでクラスタリング**です。 |

タブでの変更はドラフトにまとめられます。**保存して適用**を選択すると一度に適用され、 **変更を破棄**を選択すると破棄されます。保存前に、元に戻せない変更について警告が表示されます: 保持期間を短くすると期限切れのデータが削除され、ダウンサンプリングでは元のサンプルが削除されます。

**クエリの最大対象期間**は、ストリームに対する 1 つの SQL または PromQL クエリが対象にできる時間数を制限します。それより長い期間を対象とするクエリは拒否されるため、誤って「過去 90 日間」を指定しても大規模なストリームを端から端までスキャンすることはできません。空または `0` は制限なしを意味します。

キャッチオールのソースが受信を続けてもクエリセレクターに表示しない場合は、**クエリを許可**をオフにします。ルーティングパイプラインは引き続きストリームを読み取ることができます。`extend` データは汎用のテレメトリクエリパスではなく、**テーブルを拡張**で管理します。

## スキーマとフィールド

フィールドには名前、データ型、`nullable` フラグ、インデックスタイプ、および `encrypted` フラグがあります。データ型は `bool`、`int64`、`float64`、`utf8`、`timestamp`、および `json` です。新しいフィールドは、受信データに初めて現れたときにスキーマに追加され、別の型の値は `type mismatch on field` で拒否されます。数値は例外です: `int64` フィールドが小数部を含む数値、または `int64` の範囲を超える整数を受け取ると、同じバッチでも後のバッチでも `float64` になり、それ以前に保存された値は `float64` として読み取られます。

インデックスタイプは、MoleSignal がフィールドに対して構築する補助構造を決定します:

| インデックスタイプ | 効果 |
|---|---|
| `none` | 補助インデックスなし。これがデフォルトです。 |
| `exact` | 値全体に対する完全一致の転置インデックス (テキスト以外のフィールドでは Parquet ブルームフィルター) と、各ファイルの最小値および最大値。`=` と `IN` は値を含まないファイルを開く前にスキップし、一致する行が少ない場合はそのページだけを読み取ります。ファイルあたり最大 65,536 個の値を持つフィールドに対する `LIKE` または `ILIKE` は、テキストを含む値がないファイルをスキップします。`trace_id` などの識別子に使用します。 |
| `full_text` | テキスト検索用のトークン化された転置インデックス: 英字と数字の連続を単語とし、CJK テキストは重複する 2 文字のバイグラムに分割します。`MATCH`、`MATCH_TEXT`、`LIKE`、`ILIKE` のリテラル (句読点と CJK テキストを含む) は、一致できないファイルをスキップします。`utf8` フィールドのみ。 |
| `bloom` | Parquet ブルームフィルターに加えて、テキストおよび `int64` フィールド用のファイルごとの値全体フィルターと、各ファイルの最小値および最大値: `=` と `IN` は値を確実に含まないファイルを開く前にスキップします。リクエスト ID など、等値比較のみでクエリされる値の多いフィールドに使用します。 |
| `skip` | 各ファイルの最小値および最大値と、最大 32 個の異なる値しか持たないファイルのすべての値。比較、`IN`、`BETWEEN`、および前方一致 `LIKE` はこれらを使用してファイルをスキップします。 |
| `ngram` | 各ファイルの値のトライグラムと、そのファイル内の 1,024 行ごとのブロックの 5 バイト断片 (大文字と小文字を区別しない): ファイルに存在しないトライグラムを含む `LIKE`、`ILIKE`、または `MATCH` のリテラルはそのファイルをスキップし、ブロックに存在しない断片を含むリテラルはそのブロックをスキップするため、ID やその他の希少な文字列の検索では、それを含む可能性がある少数のブロックだけを読み取ります。5 バイトより短いリテラルはすべてのブロックを読み取ります。`ngram` フィールドを持つストリームは、ファイルを 1,024 行のページで書き込みます。小さなページと断片は容量を消費します: そのようなフィールドが各行の 3 分の 2 を占めるテストでは、ストレージが約 14% 増加しました。断片による検索を行う URL、パス、ホスト名に使用し、長い自由テキストには使用しないでください。`utf8` フィールドのみ。 |
| `ip` | 各ファイルのアドレスの範囲 (IPv4 は IPv6 にマッピング): `CIDR_MATCH(field, '10.0.0.0/8')` と、アドレスに対する `=` はこれを使用してファイルをスキップします。`utf8` フィールドのみ。 |
| `key_value` | JSON オブジェクトの第 1 階層のキーとその値: `json_text(field, 'key') = 'value'`、`IN`、および `IS NOT NULL` はキーまたは値を含まないファイルをスキップし、一致する行が少ない場合はそのページだけを読み取ります。値は `json_text` が返すとおりに照合されます: テキストはそのまま、数値とブール値は JSON として。`json` フィールドのみ。 |
| `range` | 各行の数値をインデックスに保持し、各ファイルの最小値および最大値も保持します。条件が `exact` フィールドに対する `=`、`range` フィールドに対する数値との `>`、`>=`、`<`、または `<=` であり、時間範囲が指定された `count(*)` は、ファイルを読み取らずにインデックスから応答されます。その他の比較は範囲外のファイルをスキップします。`int64`、`float64`、`timestamp` フィールドのみ。 |

インデックス付きの各フィールドは、ファイルごとに、その行のうち何行でフィールドが空になるかも記録します。`IS NULL` はフィールドが常に値を持つファイルをスキップし、フィールドに対するその他の条件 (値を持つかどうかを問う `IS NOT NULL` や `!= ''` など) は、フィールドが値をまったく持たないファイルをスキップします。

`OR` で結合された条件も、すべての分岐がファイル内で除外されるときにそのファイルをスキップします。各分岐は、それを処理するインデックスによって除外されます: `level = 'error' OR status >= 500` は、`level` インデックスに `error` がなく、`status` が 500 に到達しないファイルをスキップします。

受信データに初めて現れるフィールドは、その名前からインデックスタイプを取得します:

| ストリームタイプ | フィールド | インデックスタイプ |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`, `level`, `session_id`, `fingerprint`, `country`, `browser`, `application`, `environment` | `exact` |
| `traces` | `trace_id`, `span_id`, `parent_span_id`, `service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

その他の新しいフィールドはすべて `none` になります (ストリーム独自のルールが別途指定している場合を除く): [新しいフィールドのインデックス](#新しいフィールドのインデックス) を参照してください。`exact` の `level` により、ログのヒストグラムはファイルを読み取らずにインデックスからエラーをカウントできます。RUM ストリームは `context`、`feature_flags`、`usr.extra` のキーを `key_value` でインデックス化します。

変更されたインデックスタイプは、その後に書き込まれるデータにすぐに適用されます。以前に書き込まれたデータは、新しい設定でバックグラウンドで再インデックス化されます: 各シール済みパーティション (デフォルトでは終了から 48 時間後にシールされます) はそのファイルから再構築され、新しいファイルはシールまたはマージされた後に再構築されます。それまでは、ファイルは書き込み時のインデックスを保持します。これはクエリ結果を変えることはなく、クエリが読み取るファイル数にのみ影響します。**概要** の **インデックス付きフィールドの割合** は、残っているファイル数を示します。全文検索インデックスの形式が変わるとき (CJK テキストがバイグラムに分割されるようになったときなど)、古いファイルのインデックスは同じ方法でバックグラウンドで新しい形式に再構築されます。

フィールドを変更するには、**フィールドとインデックス** を開き、そのフィールドの編集アクションを選択して、次を選択します:

- **インデックスタイプ**: **インデックスなし**、**全文検索**、**完全一致**、**ブルームフィルター**、 **スキップインデックス**、**N-gram 部分文字列**、**IP アドレス**、または **JSON キー**。全文検索、N-gram 部分文字列、IP アドレスはテキストフィールドに、JSON キーは JSON フィールドに適用されます。
- **結果フィールドのマスキング** の **ストリーム単位のポリシー**: **グローバルルールを継承**、**カスタムストリームルール**、または **このストリームではマスキングしない**。[フィールドのマスキング](/ja/settings/data-security#フィールドマスキング) を参照してください。メトリクスストリームはマスキングの対象外です。

**下書きに適用** を選択してから、**保存して適用** を選択します。フィールドのデータ型が変わることはありません。

### 新しいフィールドのインデックス

**設定** タブの **フィールドのインデックス** で、ルールにより、ストリームに初めて現れるフィールドにその名前でインデックスが付与されます。**ルールを追加** を選択し、フィールド名のパターンを入力して、インデックスタイプを選択します: `*` は任意のテキストの連続、`?` は 1 文字を表すため、`*_id` は `user_id` と `order_id` に一致し、`http.*` は `http` 配下のすべてのフィールドに一致します。パターンが名前に一致し、インデックスタイプがフィールドのデータ型に適する最初のルールが適用されます。フィールドに対して名前を指定して **フィールドとインデックス** で設定されたインデックスが優先され、どのルールにも一致しないフィールドには上記のデフォルトが適用されます。ルールは今後現れるフィールドにのみ影響します: 既存のフィールドを変更するには **フィールドとインデックス** を使用します。ストリームが保持できるルールは最大 32 個です。

### フィールドで分割

ログまたはトレースのストリームは、1 つまたは 2 つのテキストフィールドで分割できます: **設定** タブの **フィールドで分割** で、**フィールドを追加** を選択し、フィールドを選択して、分割方法を選択します。その後に書き込まれるデータはフィールドの値によってシャードに分割され、各シャードは独自のファイルに書き込まれます。

- **ハッシュ** は値をそのハッシュによって 2〜64 個のシャードに均等に分割します。フィールドに対する等値条件 (`=` または `IN`) を含むクエリは、その値のシャードのファイルだけを読み取ります。
- **先頭文字** は値をその先頭文字によって 37 個のシャードに分割します: 各数字と各文字 (大文字と小文字を問わない) に 1 つずつ、およびそれ以外のすべて (空の値を含む) に 1 つです。フィールドに対する等値条件、またはテキストで始まる `LIKE` (`'web-%'` など) を含むクエリは、その文字のシャードのファイルだけを読み取ります。`ILIKE` はそれ以外のすべてのシャードも読み取ります。シャードがどれだけ均等になるかはデータによって異なります: 16 進数のトレース ID はそのうち 16 個しか使用しません。

2 つのフィールドを指定すると、ファイルは両方のシャードで分割されるため、シャード数は掛け算になります。**フィールドで分割** には合計が表示されます (最大 256): 先頭文字 (37 シャード) は最大 4 シャードのハッシュと組み合わせられます。いずれかのフィールドに条件があるクエリは読み取るファイルが少なくなり、両方に条件があるクエリはさらに少なくなります。ほぼすべてのクエリで指定される分割フィールド (サービス、名前空間、テナントなど) を使用してください。シャードが多いほど、ファイルはより多く、より小さくなります。

この設定は変更後に書き込まれるデータに適用されます: 既存のファイルはそのまま残り、クエリは各ファイルを、それが書き込まれたときのフィールドに基づいて判断し、コンパクターは同じフィールドで書き込まれたファイルのみをマージします。分割フィールドは暗号化されていないテキストフィールドである必要があり、2 つのフィールドは異なる必要があります。

### フィールドでクラスタリング

ログストリームは、そのファイル内の行を 1 つまたは 2 つのフィールドでクラスタリングできます: **設定** タブの **フィールドでクラスタリング** で、**フィールドを追加** を選択し、フィールドを選択して、**時間スライス** を選択します。その後に書き込まれる各ファイルでは、行はその幅の時間スライスに新しい順で配置され、スライス内ではフィールドの値によって、次に新しい順で配置されます。

時間順では、1 つのサービスのような値がファイルのすべてのページに現れます。クラスタリングすると、各スライスはその値を少数のページに保持するため、クラスタリングフィールドに対する等値条件 (`=` または `IN`) を含むクエリはそれらのページだけを読み取ります。クエリで頻繁に指定され、値が少ないフィールド (サービスやレベルなど) を使用してください。

クラスタリングされた各ファイルは、その行のうち何行が各分において、クラスタリングフィールドの値の各組み合わせで出現するかも保持します。テキストのクラスタリングフィールドに対する等値条件を含むカウント、それらの 1 つでグループ化されたカウント (`GROUP BY service`)、および棒が分単位のヒストグラムは、ファイルを読み取らずにこれらの数値から応答されます。クエリウィンドウがファイル内の分単位の境界で開始または終了する場合も同様です。分と値の組み合わせが 65,536 を超えるファイルは、何も保持しません。同じ数値は、最新または最古の行のページがどこにあるかを示すため、そのようなページは、クラスタリングフィールドに対する等値条件の有無にかかわらず、それが由来する分だけを読み取ります。

時間スライスは 1 分、5 分、または 10 分で、デフォルトは 1 分です。スライスが広いほどスキップできるページは増えますが、短い時間ウィンドウに対するクエリは、触れるスライスを全体として読み取ります。

クラスタリングは [フィールドで分割](#フィールドで分割) とは異なります: 分割では各シャードが独自のファイルに書き込まれるため、クエリが読み取るファイルは少なくなりますが、ストリームのファイルはより多く、より小さくなります。クラスタリングはファイルを保持し、その内部の行を並べ替えます。2 つは組み合わせることができます。

この設定は変更後に書き込まれるデータに適用されます: 既存のファイルは書き込まれたときの順序を保持し、コンパクターは同じようにクラスタリングされたファイルのみをマージします。クラスタリングフィールドは、暗号化されていないテキスト、`int64`、または `bool` フィールドである必要があり、2 つのフィールドは異なる必要があります。

### 暗号化されたフィールド

ストリームの作成時にフィールドを `encrypted` としてマークすると、Parquet に書き込まれる前に暗号化されます。保存された列には暗号文が保持され、通常のクエリは暗号文を返します。SQL で `decrypt(field)` を使用して値を読み戻します:

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

このフラグは後から変更できません。変更すると既存のデータが読み取れなくなるためです。キーは組織の暗号キーと暗号ルートキー `MS_CIPHER_KEY` から取得されます。ルートキーを失うと、暗号化されたフィールドは復元できなくなります。[セキュリティとマルチテナンシー](/ja/security#フィールドレベルの暗号化) を参照してください。

## リテンションと削除

リテンションは、コンパクターがデータを削除するタイミングを制御します。**リテンション**タブで **データ保持期間（日）**として設定するか、空のままにしてプラットフォームのデフォルトである 30 日を使用します。デフォルトは `_sys` 組織の [設定 → データ保持期間](/ja/settings/platform#データ保持) で設定されています。リテンションより古いデータは次のクリーンアップで削除されるため、リテンションを短くすると、その時点でリテンションを超えるデータが削除され、削除されたファイルが戻ることはありません。メトリクスストリームのメトリクスがリテンション内に確認されない場合も、そのメトリクスはメトリクス一覧から削除されます。

メトリクスストリームの **リテンション**タブでは、**古いサンプルをダウンサンプリング**は、ストリーム内のすべてのメトリクスの、指定した日数より古いサンプルを 1 分から 1 日までの時間バケットに集約します。1 つのバケット内のシリーズのサンプルは 1 つのポイントになり、値は平均化され、デルタカウントは合計され、元のサンプルは削除されます。長期間にわたるクエリは読み取るデータ量が大幅に減り、古いデータはバケットの解像度のみを保持します。元のサンプルは復元できません。

ログとトレースでは、ストリーム設定の **小さいファイルを日単位で統合**（デフォルトで有効）が、ファイルを終了した日の 1 時間後に 1 つに統合します。ただし、合計サイズがコンパクターの `[compactor].target_size` 以下の場合に限ります。多数の日にわたるクエリは開くファイル数が大幅に減ります。リテンションは日単位で適用されます。統合されたファイルは、その日全体が期限切れになると削除されます。1 時間単位のファイルを保持するには、ストリームの **設定**タブでこの設定をオフにします。

**ストリームを削除**は、ストリームとその設定を削除し、元に戻せません。次のものが機能しなくなる可能性があります。ダッシュボード、保存済みビュー、アラート、レポート、パイプライン。まず **使用状況**タブを確認してください。

## 検索ジョブ

検索ジョブはバックグラウンドで実行されるクエリで、ジョブの有効期限が切れるまで結果を保持します。ジョブは次の 3 つの経路で作成されます:

- `Prefer: respond-async` を付けて送信されたクエリ、または結果が大きすぎて対話型リクエストに適さないと予想されるクエリ。
- パイプラインのバックフィル。
- Mole Agent が送信するクエリ。

**ストリーム**のヘッダーで **検索ジョブ**を選択すると、一覧が開きます。一覧の先頭にあるビューは状態でフィルターされ、それぞれに件数が表示されます: **すべて**、**キューに追加済み**、**実行中**、**完了**、**失敗**、 **キャンセル済み**。ジョブがキューに追加済みまたは実行中の場合、一覧は自動的に更新されます。

各行には、ジョブの種類（**クエリ**または**バックフィル**）、ステートメント、状態、クエリ対象期間、送信時刻、所要時間、結果行数、試行回数、有効期限が表示されます。ジョブの状態に応じて、実行できる操作は 1 つです:

| 状態 | 操作 |
|---|---|
| キューに追加済みまたは実行中 | **ジョブをキャンセル** |
| 完了 | **結果をダウンロード** |
| 失敗またはキャンセル済み | **再試行** |

**削除**は、どの状態でもジョブとその結果を削除します。

メンバーは、自身が送信したジョブを表示および管理できます。管理者は `org.running_queries.cancel` を持つ場合、組織のすべてのジョブを表示および管理できます。ジョブ API については [クエリ](/ja/query#時間範囲と非同期ジョブ) を参照してください。

## データ取り込み量と予算

**ストリーム**のヘッダーで **データ取り込み量**を選択すると、各ソースが過去 24 時間、7 日間、または 30 日間にどれだけのデータを取り込んだかを確認できます。同じ数値が 3 つの方法で分類され、合計が一致します:

| ビュー | ソースの単位 |
|---|---|
| **認証情報** | API トークン、RUM クライアントトークン、コネクタ、またはサインイン済みユーザーです。**プラットフォーム内部**はプラットフォーム自身のテレメトリーです。 |
| **ストリーム** | 名前と種類で識別される 1 つのストリームです。 |
| **サービス** | イベントが `service.name` で示すサービス、それがなければ `service` または `service_name` で示すサービスです。**サービス名なし**は、どのサービス名も示さないイベントをまとめます。 |

取り込み量は、受け入れられたデータの展開後のリクエストバイト数をカウントします。拒否されたイベントはカウントされず、送信者が再試行するリクエストは 1 回のみカウントされます。スパンは到着時に、テールサンプリングの前にカウントされます。セッションリプレイは、**ストリーム**ビューの `rum_replay` 行でカウントされます。1 つのリクエストに複数のサービスまたはストリームが含まれる場合、そのバイト数はイベント数に応じて配分されるため、これらのビューは概算の数値であり、正確な値ではありません。

不明な数値はゼロではなく `–` と表示されます。`≥` が付いた数値は下限値です。これは計測がウィンドウの途中で開始されたためです。一覧の上の行に、いつから計測しているかが表示されます。数値はページに約 1 分以内に反映されます。突然停止したノードでは、最後の 15 秒間のカウントが失われる可能性があります。

行を選択すると、そのソースを 1 時間ごとに確認でき、他の 2 つのビューに沿ってその内訳を確認できます。

### 予算を設定

行の **予算を設定**を選択するか、行にチェックを入れてすべてに同じ予算を設定します。

| フィールド | 意味 |
|---|---|
| **期間** | UTC のカレンダーに基づく **日次**または**月次**です。 |
| **上限** | 1 MiB から 1 PiB までです。 |
| **警告しきい値 (%)** | 上限に対してこの割合に達したときに 1 回、上限を使い切ったときにもう 1 回通知されます。`0` は使い切ったときのみ通知します。デフォルト: 80。 |
| **通知先** | 組織のメンバーです。デフォルト: 予算を設定するユーザー。 |

予算は通知のみを行います。ソースが予算を超えても、データ取り込みは同じように応答および保存し、何も破棄されたり速度が低下したりしません。各しきい値レベルは期間ごとに 1 回通知されます。上限を引き上げると、次の評価時に再度通知されます。

通知は、組み込みの通知ポリシー **データ取り込み予算の上限間近** と **データ取り込み予算の上限超過** を通じて行われ、トップバーの通知センターに表示されます。他に誰がどのように通知を受け取るかを変更するには [通知チャネル](/ja/notification-channels) を参照してください。

`_sys` 組織には通知ポリシーがないため、予算はありません。次のものには予算を設定できません: **プラットフォーム内部**、**サービス名なし**、または **その他のサービス**。これらは [プラットフォーム設定](/ja/settings/platform#データ取り込み量) で上限を超えたサービスです。
