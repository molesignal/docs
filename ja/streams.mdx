ストリームは、取り込み、クエリ、パイプライン、リテンションで共通して使う組織単位の取り決めです。 **ストリーム**を開くと、受信データを確認し、各ストリームの詳細を表示したり設定を変更したりできます。

## ストリームタイプ

| タイプ | 主な内容 |
|---|---|
| `logs` | 構造化イベントとアプリケーションログです。 |
| `metrics` | 1 台の Prometheus サーバーなど、単一のソースから取得したメトリクスのサンプルです。`metric_name` でメトリクスを区別します。 |
| `traces` | OpenTelemetry のスパンです。 |
| `profiles` | pprof ブロブに関連付けられたプロファイルのメタデータです。 |
| `extend` | 拡張テーブルで管理し、処理時に参照するデータです。 |

異なるストリームタイプで同じストリーム名を使用できます。API リクエストや自動化では、必ず `stream_type` を指定してください。

### プラットフォームストリーム

MoleSignal は次のストリームにデータを書き込みます。

| ストリーム | 内容 |
|---|---|
| `_molesignal` | `_sys` 組織に保存する MoleSignal 自体のテレメトリです。[自己オブザーバビリティ](/ja/self-observability)を参照してください。 |
| `_synthetic_results` | シンセティックチェックの実行ごとに 1 行を記録します。[シンセティック監視](/ja/synthetics#結果ストリームと保持期間)を参照してください。 |
| `_audit` | ワークスペースの監査イベントです。[監査ストリーム](/ja/settings/data-security#監査ストリーム)を参照してください。 |
| `_agent_model_traces` | Mole Agent によるモデルの呼び出しです。[使用状況と予算](/ja/agent#使用状況と予算)を参照してください。 |
| `_agent_score_traces` | Mole Agent の回答の品質スコアです。[品質](/ja/quality#ストリーム内のスコア)を参照してください。 |

これらのストリームは、他のストリームと同じ方法で読み取れます。`_audit` には `audit.read` が必要です。この権限がない場合、一覧にも稼働状況の集計にも表示されず、開く、変更する、削除する操作には `403` が返ります。これらのストリームに書き込めるのはプラットフォームだけです。これらの名前でストリームを作成することはできず、データを送信すると `403` が返ります。[パイプライン](/ja/pipelines#プラットフォームストリーム)からも書き込めません。

## ストリーム一覧

**ストリーム**には、ワークスペース内のすべてのストリームが表示されます。タブを切り替えて**すべて**のストリームまたは特定のタイプを表示できます。名前や説明で検索したり、稼働状態で絞り込んだりできます。ヘッダーには、正常にデータを受信しているストリームと対応が必要なストリームの件数に加え、対象期間中に書き込んだ圧縮データの合計と現在のストレージ使用量の合計が表示されます。

| 列 | 表示内容 |
|---|---|
| **ステータス** | **正常**、**遅延**、**中断**、**トラフィックなし**、**未使用**、**統計を取得できません**のいずれかです。下の表を参照してください。 |
| **受信レート**、**最終受信日時** | データを受信する速さと、最後に受信した日時です。 |
| 圧縮データ | 対象期間中に書き込んだ圧縮データのバイト数です。 |
| **現在のストレージ使用量**、**リテンション** | 現在保存しているデータのバイト数と、データを保持する日数です。 |
| **レコード**、**収集サイズ**、**保存サイズ**、**インデックスサイズ** | 保持しているレコード数、変換前に受信したデータのバイト数、データファイルのバイト数、インデックスのバイト数です。 |

| 状態 | 意味 |
|---|---|
| **正常** | 過去 15 分以内にデータを受信しました。 |
| **遅延** | 最後にデータを受信したのは 15 分前から 2 時間前までの間です。 |
| **中断** | 2 時間を超えてデータを受信していません。 |
| **トラフィックなし** | Mole Agent のトレース用ストリームで、回答と回答の間はデータを受信しません。 |
| **未使用** | まだデータを受信したことがありません。 |

**クエリ不可**のストリームはデータの受信を続けますが、クエリのストリーム選択欄には表示されません。各行には、 **クエリ**または**探索**に加え、**詳細を表示**と**ストリーム ID をコピー**があります。ヘッダーの**検索ジョブ**を選択すると、 [検索ジョブ](#検索ジョブ)が開きます。

## ストリームを作成する

MoleSignal は最初の書き込み時にストリームを作成するため、ほとんどのストリームは自動的に表示されます。最初からリテンション、暗号化対象フィールド、クエリの可否を設定するには、事前にストリームを作成します。 **ストリームを作成**を選択します。

| フィールド | ルール |
|---|---|
| **ストリーム名** | `snake_case` 形式で、最大 64 文字です。 |
| **説明** | 任意です。ストリームを流れるデータの内容を記入します。 |
| **シグナルタイプ** | **ログ**、**メトリクス**、**トレース**のいずれかです。 |
| **保持期間（日）** | データを保持する日数です。 |
| **インデックス付きフィールド** | 全文検索インデックスを作成するフィールドをカンマ区切りで指定します。 |
| **暗号化対象フィールド** | 保存前に暗号化するフィールドをカンマ区切りで指定します。この設定は後から変更できません。[暗号化対象フィールド](#暗号化フィールド)を参照してください。 |
| **クエリを許可** | ルーティングパイプラインへの入力専用のソースストリームでは、オフにします。 |

## ストリームの詳細

ストリームを選択して開きます。**データをクエリ**を選択すると、そのストリームの探索画面が開きます。メニューには **ストリーム ID をコピー**と**ストリームを削除**があります。次のタブを利用できます。

| タブ | 内容 |
|---|---|
| **概要** | 稼働状態、最初にデータを受信した日時、クエリの可否、過去 24 時間の書き込み行数と圧縮データ量の推移を表示します。データがないストリームには、**データソースの設定**と**テストデータを送信**が表示されます。 |
| **フィールドとインデックス** | 各フィールドの型、インデックスタイプ、暗号化の有無を表示します。インデックスやマスキングを変更するには、フィールドを編集します。[スキーマとフィールド](#スキーマとフィールド)を参照してください。 |
| **リテンション** | ストリームのリテンションと、メトリクスストリームのダウンサンプリング設定を表示します。[リテンションと削除](#リテンションと削除)を参照してください。 |
| **使用状況** | ストリームに依存する取り込みエンドポイント、パイプライン、保存済みクエリ、アラートルールを表示します。変更や削除の前に確認してください。 |
| **設定** | **説明**、**クエリを許可**、**クエリの最大対象期間（時間）**、**小さいファイルを日単位で統合**、**フィールドで分割**を設定します。ログの場合は、**フィールドでクラスタリング**も設定できます。 |

各タブでの変更は下書きにまとめられます。**保存して適用**ですべての変更を一度に適用し、 **変更を破棄**で変更を取り消します。保存前に、元に戻せない変更について警告が表示されます。リテンションを短縮すると保持期間を過ぎたデータを削除し、ダウンサンプリングを行うと元のサンプルを削除します。

**クエリの最大対象期間**では、ストリームに対する 1 回の SQL または PromQL クエリが対象にできる期間を時間単位で制限します。制限を超えるクエリは拒否されるため、誤って「過去 90 日間」を指定しても、大規模なストリーム全体をスキャンすることはありません。空欄または `0` の場合は、制限がありません。

すべてのデータを受け付けるソースで、受信は続けながらクエリのストリーム選択欄に表示しない場合は、 **クエリを許可**をオフにします。ルーティングパイプラインは引き続きストリームを読み取れます。`extend` データは、通常のテレメトリ用のクエリ機能ではなく、 **テーブルを拡張**から管理します。

## スキーマとフィールド

フィールドには、名前、データ型、`nullable` フラグ、インデックスタイプ、`encrypted` フラグがあります。データ型は `bool`、`int64`、`float64`、`utf8`、`timestamp`、`json` です。受信データに初めて現れたフィールドはスキーマに追加します。別の型の値は `type mismatch on field` エラーで拒否します。

インデックスタイプによって、MoleSignal がフィールドに構築する補助データ構造が決まります。

| インデックスタイプ | 動作 |
|---|---|
| `none` | 補助インデックスを作成しません。これがデフォルトです。 |
| `exact` | 値全体の完全一致転置インデックス（テキスト以外のフィールドでは Parquet ブルームフィルター）と、ファイルごとの最小値と最大値を保持します。`=` と `IN` は、該当する値がないファイルを開かずにスキップします。一致する行が少ない場合は、その行があるページだけを読み取ります。ファイルあたりの値が最大 65,536 個のフィールドでは、`LIKE` や `ILIKE` は指定されたテキストを含む値がないファイルをスキップします。`trace_id` などの識別子に使用してください。 |
| `full_text` | テキスト検索用に、トークン化した転置インデックスを作成します。英数字の連続を単語として扱い、CJK テキストは文字が重なるように 2 文字ずつのバイグラムに分割します。`MATCH`、`MATCH_TEXT`、`LIKE`、`ILIKE` のリテラル（句読点や CJK テキストを含む）に一致しないファイルをスキップします。`utf8` フィールドにのみ適用します。 |
| `bloom` | Parquet ブルームフィルターに加え、テキストフィールドと `int64` フィールドの値全体を対象とするファイル単位のフィルター、およびファイルごとの最小値と最大値を保持します。`=` と `IN` は、該当する値が確実に存在しないファイルを開かずにスキップします。リクエスト ID など、値の種類が多く、等価条件でのみ検索するフィールドに使用してください。 |
| `skip` | ファイルごとの最小値と最大値を保持します。ファイル内の異なる値が 32 個以下の場合は、すべての値も保持します。比較演算、`IN`、`BETWEEN`、前方一致の `LIKE` は、この情報を使って対象外のファイルをスキップします。 |
| `ngram` | 大文字と小文字を区別せず、ファイルごとに値のトライグラムを、さらにファイル内の 1,024 行ごとのブロックに対して 5 バイトの断片を保持します。`LIKE`、`ILIKE`、`MATCH` のリテラルに含まれるトライグラムがファイルになければ、そのファイルをスキップします。同様に、リテラルに含まれる断片がブロックになければ、そのブロックをスキップします。このため、ID などの出現頻度が低い文字列を検索する場合は、一致する可能性がある少数のブロックだけを読み取ります。5 バイト未満のリテラルでは、すべてのブロックを読み取ります。`ngram` フィールドがあるストリームでは、ファイルを 1,024 行単位のページで書き込みます。小さなページと断片の保持には追加の容量が必要です。対象フィールドが各行の 3 分の 2 を占めるテストでは、ストレージ使用量が約 14% 増加しました。長い自由記述テキストではなく、部分文字列で検索する URL、パス、ホスト名に使用してください。`utf8` フィールドにのみ適用します。 |
| `ip` | ファイルごとに IP アドレスの範囲を保持します。IPv4 アドレスは IPv6 にマッピングします。`CIDR_MATCH(field, '10.0.0.0/8')` や IP アドレスに対する `=` は、この範囲を使って対象外のファイルをスキップします。`utf8` フィールドにのみ適用します。 |
| `key_value` | JSON オブジェクトの最上位のキーとその値を保持します。`json_text(field, 'key') = 'value'`、`IN`、`IS NOT NULL` は、該当するキーや値がないファイルをスキップします。一致する行が少ない場合は、その行があるページだけを読み取ります。比較には `json_text` が返す形式を使います。テキストはそのまま、数値とブール値は JSON 表現で比較します。`json` フィールドにのみ適用します。 |
| `range` | 各行の数値をインデックスに保持し、ファイルごとの最小値と最大値も保持します。条件が `exact` フィールドに対する `=`、`range` フィールドと数値を比較する `>`、`>=`、`<`、`<=`、および時間範囲で構成される `count(*)` は、ファイルを読み取らずにインデックスから結果を返します。その他の比較では、範囲外のファイルをスキップします。`int64`、`float64`、`timestamp` フィールドにのみ適用します。 |

インデックス付きフィールドごとに、そのフィールドに値がない行の数もファイル単位で記録します。`IS NULL` は、すべての行に値があるファイルをスキップします。`IS NOT NULL` や `!= ''` など、値の有無を調べる条件を含むその他の条件は、どの行にも値がないファイルをスキップします。

`OR` で結んだ条件でも、各条件に対応するインデックスを使い、どの条件にも一致しないと判断できるファイルをスキップします。たとえば `level = 'error' OR status >= 500` は、`level` のインデックスに `error` がなく、`status` が 500 以上の行もないファイルをスキップします。

受信データに初めて現れたフィールドには、名前に応じてインデックスタイプを割り当てます。

| ストリームタイプ | フィールド | インデックスタイプ |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`、`level`、`session_id`、`fingerprint`、`country`、`browser`、`application`、`environment` | `exact` |
| `traces` | `trace_id`、`span_id`、`parent_span_id`、`service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

その他の新規フィールドには、ストリーム固有のルールで別途指定しない限り、`none` を割り当てます。[新規フィールドのインデックス](#新規フィールドのインデックス)を参照してください。`level` に `exact` を設定すると、ログのヒストグラムはファイルを読み取らずにインデックスからエラー数を集計できます。RUM ストリームでは、`context`、`feature_flags`、`usr.extra` のキーを `key_value` でインデックス化します。

インデックスタイプを変更すると、それ以降に書き込むデータに新しい設定がすぐに適用されます。変更前に書き込んだデータは、バックグラウンドで新しい設定に従って再インデックス化します。確定済みのパーティション（デフォルトでは対象期間の終了から 48 時間後に確定）は、構成ファイルから再構築します。それより新しいファイルは、確定またはマージされた時点で再インデックス化します。それまでは、各ファイルが書き込み時のインデックスを保持します。これによってクエリ結果が変わることはなく、読み取るファイル数だけが変わります。**概要**の**インデックス付きフィールドの割合**で、処理が残っているファイル数を確認できます。CJK テキストをバイグラムに分割するようになったときのように、全文検索インデックスの形式が変わった場合も、同じように古いファイルのインデックスをバックグラウンドで新しい形式に再構築します。

フィールドを変更するには、**フィールドとインデックス**を開き、対象フィールドの編集操作を選択して、次の項目を設定します。

- **インデックスタイプ**：**インデックスなし**、**全文検索**、**完全一致**、**ブルームフィルター**、 **スキップインデックス**、**N-gram 部分文字列**、**IP アドレス**、**JSON キー**。全文検索、N-gram 部分文字列、IP アドレスはテキストフィールドに、JSON キーは JSON フィールドに適用します。
- **結果フィールドのマスキング**の**ストリーム単位のポリシー**：**グローバルルールを継承**、**カスタムストリームルール**、 **このストリームではマスキングしない**のいずれかを選択します。[フィールドのマスキング](/ja/settings/data-security#フィールドマスキング)を参照してください。メトリクスストリームはマスキングの対象外です。

**下書きに適用**を選択し、続いて**保存して適用**を選択します。フィールドのデータ型は変更できません。

### 新規フィールドのインデックス

**設定**タブの**フィールドのインデックス**では、ストリームに初めて現れるフィールドに対して、名前に応じたインデックスをルールで割り当てます。**ルールを追加**を選択し、フィールド名のパターンを入力して、インデックスタイプを選択します。 `*` は任意の文字列、`?` は任意の 1 文字を表します。たとえば `*_id` は `user_id` や `order_id` に一致し、`http.*` は `http` 配下のすべてのフィールドに一致します。ルールを先頭から評価し、パターンが名前に一致し、インデックスタイプがフィールドのデータ型に適合する最初のルールを適用します。ただし、フィールド名を指定して **フィールドとインデックス**で設定したインデックスを優先します。一致するルールがないフィールドには、前述のデフォルトを適用します。ルールは、設定後に初めて現れるフィールドにのみ適用します。既存のフィールドは、次の画面で変更してください。 **フィールドとインデックス**。ストリームごとに最大 32 個のルールを設定できます。

### フィールドで分割

ログまたはトレースのストリームは、1 つまたは 2 つのテキストフィールドで分割できます。 **設定**タブの**フィールドで分割**で、**フィールドを追加**を選択し、フィールドと分割方法を選択します。それ以降に書き込むデータは、フィールドの値に基づいてシャードに分割し、シャードごとに個別のファイルに書き込みます。

- **ハッシュ**は、値のハッシュに基づいて 2～64 個のシャードに均等に分割します。フィールドに等価条件（`=` または `IN`）を指定したクエリは、該当する値のシャードのファイルだけを読み取ります。
- **先頭文字**は、値の先頭文字に基づいて 37 個のシャードに分割します。数字と英字に 1 つずつ（大文字と小文字は区別しません）、空の値を含むその他すべてに 1 つを割り当てます。フィールドに等価条件を指定したクエリや、テキストで始まる `LIKE`（`'web-%'` など）を指定したクエリは、その文字に対応するシャードのファイルだけを読み取ります。`ILIKE` は、その他の値のシャードも読み取ります。シャード間の分布はデータによって異なります。たとえば、16 進数のトレース ID は 16 個のシャードだけを使用します。

2 つのフィールドを使うと、両方のシャードの組み合わせでファイルを分割するため、合計は各シャード数の積になります。 **フィールドで分割**には合計数が表示され、上限は 256 です。先頭文字（37 シャード）と組み合わせる場合、ハッシュは最大 4 シャードです。どちらか一方のフィールドに条件を指定すると、クエリが読み取るファイル数が減ります。両方に条件を指定すると、さらに減ります。サービス、名前空間、テナントなど、ほぼすべてのクエリで指定するフィールドを分割に使用してください。シャードを増やすと、ファイルは小さくなり、数は増えます。

設定は変更後に書き込むデータに適用します。既存のファイルは変更しません。クエリは、書き込み時の分割フィールドに基づいて各ファイルを評価し、コンパクターは分割フィールドが同じファイルだけをマージします。分割に使えるのは暗号化していないテキストフィールドのみです。2 つ指定する場合は、異なるフィールドを選択してください。

### フィールドでクラスタリング

ログストリームでは、1 つまたは 2 つのフィールドを使ってファイル内の行をクラスタリングできます。 **設定**タブの**フィールドでクラスタリング**で、**フィールドを追加**を選択し、フィールドと**時間スライス**を選択します。それ以降に書き込む各ファイルでは、指定した幅の時間スライスを新しい順に並べます。スライス内では、フィールドの値で並べ、同じ値の行は新しい順に並べます。

時刻順だけで並べると、特定のサービスなどの値はファイル内の各ページに分散します。クラスタリングすると、各スライス内でその値が少数のページにまとまります。クラスタリングフィールドに等価条件（`=` または `IN`）を指定したクエリは、それらのページだけを読み取ります。サービスやレベルなど、クエリで頻繁に指定し、値の種類が少ないフィールドを使用してください。

クラスタリングした各ファイルには、1 分ごとに、クラスタリングフィールドの値の組み合わせごとの行数も記録します。テキスト型のクラスタリングフィールドに等価条件を指定した件数集計、そのうち 1 つのフィールドでグループ化した件数集計（`GROUP BY service`）、各バーの幅が整数分のヒストグラムは、この行数を使ってファイルを読み取らずに結果を返します。クエリ範囲の開始時刻や終了時刻がファイル内の分境界にある場合も同様です。時刻（分単位）と値の組み合わせが 65,536 通りを超えるファイルでは、行数を記録しません。同じ行数を使うと、最新または最古の行を含むページがどの分にあるかも特定できます。クラスタリングフィールドに等価条件があるかどうかにかかわらず、そのページの取得には該当する分だけを読み取ります。

時間スライスは 1 分、5 分、10 分から選択します。デフォルトは 1 分です。時間スライスの幅を広げると、スキップできるページが増えます。ただし、短い時間範囲のクエリでも、範囲と重なる時間スライスは全体を読み取ります。

クラスタリングは[フィールドで分割](#フィールドで分割)とは異なります。分割では、シャードごとに個別のファイルに書き込むため、クエリが読み取るファイル数は減りますが、ストリーム全体では小さなファイルが増えます。クラスタリングではファイルを分割せず、ファイル内の行を並べ替えます。両方を組み合わせることもできます。

設定は変更後に書き込むデータに適用します。既存のファイルでは書き込み時の行順を維持し、コンパクターはクラスタリング設定が同じファイルだけをマージします。クラスタリングに使えるのは、暗号化していないテキスト、`int64`、`bool` のいずれかのフィールドです。2 つ指定する場合は、異なるフィールドを選択してください。

### 暗号化フィールド

ストリームを作成するときにフィールドに `encrypted` を設定すると、Parquet に書き込む前に暗号化します。保存する列には暗号文が入り、通常のクエリは暗号文を返します。元の値を読み取るには、SQL で `decrypt(field)` を使用します。

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

フラグを変更すると既存データを読み取れなくなるため、作成後は変更できません。暗号鍵は、組織の暗号鍵とルート暗号鍵 `MS_CIPHER_KEY` から導出します。ルート鍵を失うと、暗号化フィールドを復元できません。[セキュリティとマルチテナンシー](/ja/security#フィールドレベルの暗号化)を参照してください。

## リテンションと削除

リテンションは、コンパクターがデータを削除するタイミングを制御します。**リテンション**タブの **データ保持期間（日）**で設定します。空欄にすると、プラットフォームのデフォルト値である30日が適用されます。この値は `_sys`組織の[設定 → データ保持期間](/ja/settings/platform#データ保持)で設定します。保持期間を過ぎたデータは、次回のクリーンアップで削除します。保持期間を短くすると、新しい保持期間を過ぎたデータを削除します。削除したファイルは復元できません。メトリクスストリームで保持期間内に一度も受信していないメトリクスも、メトリクス一覧から削除します。

メトリクスストリームの**リテンション**タブにある**古いサンプルをダウンサンプリング**では、指定した日数より古いすべてのメトリクスのサンプルを、1分から1日までの時間バケットに集約します。同じ系列の同じバケット内にあるサンプルは 1つのデータポイントにまとめます。値は平均し、デルタカウントは合計して、元のサンプルを削除します。これにより、長期間のクエリで読み取るデータ量が大幅に減り、古いデータはバケット単位の粒度でのみ保持されます。元のサンプルは復元できません。

ログとトレースでは、ストリーム設定の**小さいファイルを日単位で統合**がデフォルトで有効です。この設定では、 1日の終了から1時間後に、その日のファイルの合計サイズがコンパクターの `[compactor].target_size`以下であれば、1つのファイルに統合します。複数日にわたるクエリで開くファイルの数が大幅に減ります。リテンションは日単位で適用し、その日全体が保持期間を過ぎると統合ファイルを削除します。時間単位のファイルを保持するには、ストリームの**設定**タブでこの設定をオフにしてください。

**ストリームを削除**を実行すると、ストリームとその設定を削除します。この操作は取り消せません。ダッシュボード、保存済みビュー、アラート、レポート、パイプラインが動作しなくなることがあるため、先に**使用状況**タブを確認してください。

## 検索ジョブ

検索ジョブはバックグラウンドで実行するクエリです。ジョブの有効期限まで結果を保持します。検索ジョブは次の3つの方法で作成されます。

- `Prefer: respond-async`を指定して送信したクエリ、または対話型リクエストで扱うには結果が大きすぎると見込まれるクエリ
- パイプラインのバックフィル
- Mole Agentが送信するクエリ

**ストリーム**のヘッダーで**検索ジョブ**を選択して、一覧を開きます。一覧の上部にあるビューでは、 **すべて**、**キューに追加済み**、**実行中**、**完了**、**失敗**、 **キャンセル済み**の状態で絞り込めます。各ビューには件数が表示されます。キューに追加済みまたは実行中のジョブがある間は、一覧が自動で更新されます。

各行には、ジョブの種類（**クエリ**または**バックフィル**）、ステートメント、状態、クエリの対象期間、送信時刻、所要時間、結果行数、試行回数、有効期限が表示されます。ジョブの状態に応じて、次の操作を実行できます。

| 状態 | 操作 |
|---|---|
| キューに追加済みまたは実行中 | **ジョブをキャンセル** |
| 完了 | **結果をダウンロード** |
| 失敗またはキャンセル済み | **再試行** |

**削除**は、状態にかかわらず、ジョブとその結果を削除します。

メンバーが表示および管理できるのは、自分が送信したジョブです。 `org.running_queries.cancel`権限を持つ管理者は、組織内のすべてのジョブを表示および管理できます。ジョブAPIについては、[クエリ](/ja/query#時間範囲と非同期ジョブ)を参照してください。

## データ取り込み量と予算

**ストリーム**のヘッダーで**データ取り込み量**を選択すると、ソースごとの過去24時間、7日間、30日間のデータ取り込み量を確認できます。同じデータを3つの切り口で集計するため、どのビューでも合計は一致します。

| ビュー | ソースの単位 |
|---|---|
| **認証情報** | APIトークン、RUMクライアントトークン、コネクター、またはサインイン済みユーザーです。**プラットフォーム内部**は、プラットフォーム自体のテレメトリーです。 |
| **ストリーム** | 名前と種類で識別する個々のストリームです。 |
| **サービス** | イベントの`service.name`で指定したサービスです。`service.name`がない場合は、`service`または`service_name`を使用します。**サービス名なし**には、サービス名を指定していないイベントがまとまります。 |

データ取り込み量は、受け付けたデータについて、解凍後のリクエストサイズをバイト単位で集計します。拒否したイベントは含めず、送信元がリクエストを再試行しても1回だけ計上します。スパンは、テールサンプリングの前に、受信した時点で計上します。セッションリプレイは、**ストリーム**ビューの`rum_replay`行に計上します。1つのリクエストに複数のサービスまたはストリームのイベントが含まれる場合は、イベント数に応じてバイト数を按分します。そのため、これらのビューに表示される値は概算です。

不明な値は、ゼロではなく`–`で表示します。`≥`が付いた値は、対象期間の途中から計測を開始したため、下限値を示します。計測の開始時刻は一覧の上に表示します。値は約1分以内にページに反映します。ノードが突然停止すると、直前の15秒間の集計データが失われることがあります。

行を選択すると、そのソースの時間ごとの取り込み量と、他の2つのビューでの内訳を確認できます。

### 予算を設定

行の**予算を設定**を選択します。複数の行にチェックを入れると、選択したすべての行に同じ予算を設定できます。

| フィールド | 意味 |
|---|---|
| **期間** | UTCの暦に基づく**日次**または**月次**です。 |
| **件数の上限** | 1 MiBから1 PiBまでです。 |
| **警告しきい値 (%)** | 上限に対する使用率がこの割合に達したときと、上限に達したときに、それぞれ1回通知します。`0`を指定すると、上限に達したときだけ通知します。デフォルトは80です。 |
| **通知先** | 組織のメンバーです。デフォルトは予算を設定したメンバーです。 |

予算は通知にのみ使用します。ソースが予算を超えても、リクエストへの応答やデータの保存は変わらず、データの破棄や取り込み速度の制限も行いません。各しきい値の通知は、期間ごとに1回です。上限を引き上げると、新しいしきい値に達したときに再度通知します。

通知には、組み込みの通知ポリシー**データ取り込み予算の上限間近**と**データ取り込み予算の上限超過**を使用します。通知は上部バーの通知センターに表示します。通知先の追加や通知方法の変更については、[通知チャネル](/ja/notification-channels)を参照してください。

`_sys`組織には通知ポリシーがないため、予算を設定できません。また、 **プラットフォーム内部**、**サービス名なし**、**その他のサービス**にも予算を設定できません。**その他のサービス**には、 [プラットフォーム設定](/ja/settings/platform#データ取り込み量)で指定した表示上限に収まらないサービスが含まれます。
