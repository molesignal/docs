ストリームは、取り込み、クエリ、パイプライン、リテンションで使用される組織スコープのコントラクトです。 **ストリーム**を開くと、到着するデータを確認し、各ストリームを検査または設定できます。

## ストリームの種類

| タイプ | 典型的な内容 |
|---|---|
| `logs` | 構造化イベントとアプリケーションログ。 |
| `metrics` | 1 つの Prometheus サーバーなど、単一ソースのメトリクスサンプル。`metric_name` で区別されます。 |
| `traces` | OpenTelemetry スパン。 |
| `profiles` | pprof BLOB に関連付けられたプロファイルメタデータ。 |
| `extend` | 拡張テーブルとして管理され、処理中に使用されるルックアップデータ。 |

同じストリーム名が異なるストリームタイプに存在する場合があります。API リクエストと自動化では常に `stream_type` を含めてください。

### プラットフォームストリーム

MoleSignal はこれらのストリーム自体を書き込みます:

| ストリーム | 内容 |
|---|---|
| `_molesignal` | `_sys` 組織内の MoleSignal 自体のテレメトリ。[セルフオブザーバビリティ](/ja/self-observability)を参照してください。 |
| `_synthetic_results` | シンセティックチェックの各実行につき 1 行。[シンセティックモニタリング](/ja/synthetics#結果ストリームと保持期間)を参照してください。 |
| `_audit` | ワークスペースの監査イベント。[監査ストリーム](/ja/settings/data-security#監査ストリーム)を参照してください。 |
| `_agent_model_traces` | Mole Agent のモデル呼び出し。[使用量と予算](/ja/agent#使用状況と予算)を参照してください。 |
| `_agent_score_traces` | Mole Agent の回答の品質スコア。[品質](/ja/quality#ストリーム内のスコア)を参照してください。 |

これらは他のストリームと同様に読み取られます。`_audit` には `audit.read` が必要です。これがない場合、ストリームは一覧にも実行時の数値にも表示されず、開く、変更する、削除する操作は `403` を返します。これらを書き込む他のものはありません。これらの名前のストリームは作成できず、取り込みは `403` を返し、どの[パイプライン](/ja/pipelines#プラットフォームストリーム)も書き込みません。

## ストリーム一覧

**ストリーム**にはワークスペースのすべてのストリームが一覧表示されます。タブを切り替えて **すべて** のストリームまたは 1 つのタイプを表示し、名前または説明で検索し、実行状態でフィルタできます。ヘッダーでは、正常に受信しているストリームと注意が必要なストリームをカウントし、期間中に書き込まれた圧縮データと現在のストレージ使用量を合計します。

| 列 | 表示内容 |
|---|---|
| **ステータス** | **正常**、**遅延**、**中断**、**トラフィックなし**、**未使用**、または **統計を取得できません**。以下を参照してください。 |
| **受信レート**、**最終受信日時** | データの到着速度と、最後に到着した日時。 |
| 圧縮データ | 期間中に書き込まれた圧縮バイト数。 |
| **現在のストレージ使用量**、**リテンション** | 現在保存されているバイト数と、データを保持する日数。 |
| **レコード**、**収集サイズ**、**保存サイズ**、**インデックスサイズ** | 保持されているレコード、変換前に受信したバイト数、データファイルのバイト数、インデックスのバイト数。 |

| 状態 | 意味 |
|---|---|
| **正常** | 過去 15 分以内にデータが到着しました。 |
| **遅延** | 最後のデータ到着が 15 分前から 2 時間前の間です。 |
| **中断** | 2 時間以上データがありません。 |
| **トラフィックなし** | Mole Agent トレースのストリームで、回答の合間はトラフィックがありません。 |
| **未使用** | ストリームがデータを一度も受信していません。 |

**クエリ不可** とマークされたストリームはデータを受信し続けますが、クエリセレクターには表示されません。各行には **クエリ** または **探索**、**詳細を表示**、**ストリーム ID をコピー** があります。ヘッダーの **検索ジョブ** を開くと [検索ジョブ](#検索ジョブ) のページが開きます。

## ストリームを作成

MoleSignal は最初の書き込み時にストリームを作成するため、ほとんどのストリームは自動的に表示されます。事前に作成して、リテンション、暗号化対象フィールド、クエリへのアクセスを最初から設定できます。次を選択します。 **ストリームを作成**:

| フィールド | ルール |
|---|---|
| **ストリーム名** | `snake_case`、最大 64 文字。 |
| **説明** | 任意。ストリームを流れるデータの内容。 |
| **シグナルタイプ** | **ログ**、**メトリクス**、または **トレース**。 |
| **保持期間（日）** | データを保持する期間。 |
| **インデックス付きフィールド** | 全文インデックスが付与される、カンマ区切りのフィールド。 |
| **暗号化対象フィールド** | 保存前に暗号化される、カンマ区切りのフィールド。後から変更することはできません。[暗号化対象フィールド](#暗号化されたフィールド)を参照してください。 |
| **クエリを許可** | ルーティングパイプラインにのみデータを供給するソースストリームではオフにします。 |

## ストリームの詳細

ストリームを選択して開きます。**データをクエリ** を選択するとエクスプローラーで開き、メニューには **ストリーム ID をコピー** と **ストリームを削除** があります。タブは次のとおりです:

| タブ | 内容 |
|---|---|
| **概要** | 実行状態、最初にデータを受信した日時、クエリへのアクセス、24 時間の書き込み行数と圧縮データの推移。データのないストリームでは **データソースの設定** と **テストデータを送信** を利用できます。 |
| **フィールドとインデックス** | フィールドとそのタイプ、インデックスタイプ、暗号化。フィールドを編集して、インデックスまたはマスキングを変更します。[スキーマとフィールド](#スキーマとフィールド)を参照してください。 |
| **リテンション** | ストリームのリテンションと、メトリクスストリームのダウンサンプリング。[リテンションと削除](#リテンションと削除)を参照してください。 |
| **使用状況** | ストリームに依存するもの: 書き込みを行う取り込みエンドポイント、パイプライン、保存済みクエリ、アラートルール。変更または削除の前に確認してください。 |
| **設定** | **説明**、**クエリを許可**、**クエリの最大対象期間（時間）**、**小さいファイルを日単位で統合**、**フィールドで分割**、ログの場合は **フィールドでクラスタリング**。 |

タブでの変更は下書きにまとめられます。**保存して適用** を選択すると一度に適用され、 **変更を破棄** を選択すると破棄されます。保存前に、元に戻せない変更について警告が表示されます: 保持期間を短くすると期限切れデータが削除され、ダウンサンプリングでは元のサンプルが削除されます。

**クエリの最大対象期間** は、ストリームに対する 1 つの SQL または PromQL クエリが対象にできる時間数を制限します。より長い期間を指定したクエリは拒否されるため、誤って「過去 90 日間」を指定しても大規模なストリームを端から端までスキャンすることはできません。空または `0` は制限なしを意味します。

キャッチオールソースが受信を続ける必要がある一方で、クエリに表示してはいけない場合は、**クエリを許可** をオフに設定します。クエリセレクターには表示されません。ルーティングパイプラインは引き続きストリームを読み取れます。`extend` データは、汎用のテレメトリクエリ経路ではなく **テーブルを拡張** で管理します。

## スキーマとフィールド

フィールドには名前、データ型、`nullable` フラグ、インデックスタイプ、`encrypted` フラグがあります。データ型は `bool`、`int64`、`float64`、`utf8`、`timestamp`、`json` です。新しいフィールドは、受信データに最初に現れたときにスキーマへ追加され、別の型の値は `type mismatch on field` で拒否されます。数値は例外です。小数を含む数値、または `int64` の範囲を超える整数を受け取った `int64` フィールドは、同じバッチ内でも後続のバッチでも `float64` になり、それ以前に保存された値も `float64` として読み取られます。

インデックスタイプは、MoleSignal がフィールドに対して構築する補助構造を決定します:

| インデックスタイプ | 効果 |
|---|---|
| `none` | 補助インデックスなし。これがデフォルトです。 |
| `exact` | 値全体の完全一致転置インデックス（テキスト以外のフィールドでは Parquet ブルームフィルター）に加えて、各ファイルの最小値と最大値。`=` と `IN` は、値を含まないファイルを開く前にスキップし、一致する行が少ない場合はそのページだけを読み取ります。ファイルあたり最大 65,536 個の値を持つフィールドに対する `LIKE` または `ILIKE` は、テキストを含む値がないファイルをスキップします。`trace_id` などの識別子に使用します。 |
| `full_text` | テキスト検索用のトークン化された転置インデックス。英字と数字の連続が単語になり、CJK テキストは重複する 2 文字のバイグラムに分割されます。句読点や CJK テキストを含む `MATCH`、`MATCH_TEXT`、`LIKE`、`ILIKE` のリテラルは、一致しないファイルをスキップします。`utf8` フィールドのみ。 |
| `bloom` | Parquet ブルームフィルターに加えて、テキストおよび `int64` フィールドではファイルごとの値全体フィルター、さらに各ファイルの最小値と最大値。`=` と `IN` は、値を確実に含まないファイルを開く前にスキップします。リクエスト ID など、等価比較のみでクエリされる値の多いフィールドに使用します。 |
| `skip` | 各ファイルの最小値と最大値、および最大 32 個の異なる値しか持たないファイルの全値。比較、`IN`、`BETWEEN`、プレフィックス `LIKE` はこれらを使ってファイルをスキップします。 |
| `ngram` | 各ファイルの値のトリグラムと、そのファイル内の 1,024 行ごとのブロックの 5 バイト断片（大文字小文字を問わず）。ファイルに存在しないトリグラムを含む `LIKE`、`ILIKE`、`MATCH` のリテラルはそのファイルをスキップし、ブロックに存在しない断片を含むリテラルはそのブロックをスキップします。そのため、ID やその他のまれな文字列の検索では、それを含む可能性がある少数のブロックだけを読み取ります。5 バイト未満のリテラルはすべてのブロックを読み取ります。`ngram` フィールドを持つストリームは、ファイルを 1,024 行のページで書き込みます。小さなページと断片は容量を消費します。あるテストでは、そのようなフィールドが各行の 3 分の 2 を占めた場合、ストレージが約 14% 増加しました。断片で検索する URL、パス、ホスト名に使用し、長い自由テキストには使用しないでください。`utf8` フィールドのみ。 |
| `ip` | 各ファイルのアドレスの範囲（IPv4 は IPv6 にマッピング）: `CIDR_MATCH(field, '10.0.0.0/8')` とアドレスに対する `=` は、それを使ってファイルをスキップします。`utf8` フィールドのみ。 |
| `key_value` | JSON オブジェクトの第 1 階層のキーとその値: `json_text(field, 'key') = 'value'`、`IN`、`IS NOT NULL` は、キーまたは値がないファイルをスキップし、一致する行が少ない場合はそのページだけを読み取ります。値は `json_text` が返す形式で照合されます。テキストはそのまま、数値と真偽値は JSON として扱われます。`json` フィールドのみ。 |
| `range` | インデックス内の各行の数値と、各ファイルの最小値と最大値。条件が `exact` フィールドに対する `=`、`range` フィールドに対する数値との `>`、`>=`、`<`、`<=`、および時間範囲である `count(*)` は、ファイルを読み取らずにインデックスから応答されます。その他の比較は範囲外のファイルをスキップします。`int64`、`float64`、`timestamp` フィールドのみ。 |

インデックス付きの各フィールドは、ファイルごとに、その行のうち何行がフィールドを空のままにしているかも記録します。`IS NULL` は、フィールドが常に値を持つファイルをスキップします。また、フィールドに対するその他の条件（`IS NOT NULL` や `!= ''` など、値の有無を問い合わせる条件を含む）は、フィールドが決して値を持たないファイルをスキップします。

`OR` で結合された条件も、すべての分岐がそのファイルで除外されるときにファイルをスキップします。各分岐は、それを処理するインデックスによって除外されます。`level = 'error' OR status >= 500` は、`level` インデックスに `error` がなく、`status` が 500 に達しないファイルをスキップします。

受信データに最初に現れるフィールドは、その名前からインデックスタイプを取得します:

| ストリームタイプ | フィールド | インデックスタイプ |
|---|---|---|
| `logs` | `message` | `full_text` |
| `logs` | `_event_id`, `level`, `session_id`, `fingerprint`, `country`, `browser`, `application`, `environment`、および OpenTelemetry フィールド `host.id`, `container.id`, `event.name`, `event.domain`, `severity_text` | `exact` |
| `traces` | `trace_id`, `span_id`, `parent_span_id`, `service.name` | `exact` |
| `metrics` | `metric_name` | `exact` |

その他の新しいフィールドはすべて `none` になります（ストリーム固有のルールで別段の定めがある場合を除きます）。[新しいフィールドのインデックス](#新しいフィールドのインデックス) を参照してください。`level` が exact の場合、ログヒストグラムはファイルを読み取らずにインデックスからエラーをカウントできます。RUM ストリームは `context`、`feature_flags`、`usr.extra` のキーを `key_value` でインデックス化します。

変更されたインデックスタイプは、その後に書き込まれるデータにすぐに適用されます。以前に書き込まれたデータは、新しい設定でバックグラウンドで再インデックス化されます。各シール済みパーティション（デフォルトでは終了から 48 時間後にシール）はそのファイルから再構築され、より新しいファイルはシールまたはマージされた後に再構築されます。それまでの間、ファイルは書き込み時のインデックスを保持します。これはクエリ結果を変えることはなく、クエリが読み取るファイル数にのみ影響します。**概要** の **インデックス付きフィールドの割合** は、残っているファイル数を示します。全文検索インデックスの形式が変わった場合（CJK テキストがバイグラムに分割されるようになったときなど）、古いファイルのインデックスは同じ方法でバックグラウンドで新しい形式に再構築されます。

フィールドを変更するには、**フィールドとインデックス** を開き、そのフィールドの編集アクションを選択して、次を選びます:

- **インデックスタイプ**: **インデックスなし**、**全文検索**、**完全一致**、**ブルームフィルター**、 **スキップインデックス**、**N-gram 部分文字列**、**IP アドレス**、または **JSON キー**。全文検索、N-gram 部分文字列、IP アドレスはテキストフィールドに適用され、JSON キーは JSON フィールドに適用されます;
- **結果フィールドのマスキング** の **ストリーム単位のポリシー**: **グローバルルールを継承**、**カスタムストリームルール**、または **このストリームではマスキングしない**。[フィールドのマスキング](/ja/settings/data-security#フィールドマスキング) を参照してください。メトリクスストリームはマスキングの対象外です。

**下書きに適用** を選択してから、**保存して適用** を選択します。フィールドのデータ型は変更できません。

### 新しいフィールドのインデックス

**設定** タブの **フィールドのインデックス** で、ルールによって、ストリームに最初に現れるフィールドにその名前でインデックスを付与します。**ルールを追加** を選択し、フィールド名のパターンを入力して、インデックスタイプを選びます: `*` は任意のテキストの連続、`?` は 1 文字を表すため、`*_id` は `user_id` と `order_id` に一致し、`http.*` は `http` 配下のすべてのフィールドに一致します。順序で最初にパターンが名前に一致し、インデックスタイプがフィールドのデータ型に適合するルールが適用されます。**フィールドとインデックス** で名前によってフィールドに設定されたインデックスが優先され、どのルールにも一致しないフィールドには上記のデフォルトが適用されます。ルールは今後現れるフィールドにのみ影響します。既存のフィールドを変更するには、**フィールドとインデックス** で行います。ストリームは最大 32 個のルールを保持します。

### フィールドで分割

ログまたはトレースのストリームは、1 つまたは 2 つのテキストフィールドで分割できます。**設定** タブの **フィールドで分割** で、 **フィールドを追加** を選択し、フィールドを選んで、分割方法を選択します。その後に書き込まれるデータはフィールドの値によってシャードに分割され、各シャードは独自のファイルに書き込まれます。

- **ハッシュ** は値をハッシュによって 2～64 個のシャードに均等に分割します。フィールドに対する等価条件（`=` または `IN`）を含むクエリは、その値のシャードのファイルだけを読み取ります。
- **先頭文字** は値を先頭文字によって 37 個のシャードに分割します。各数字と各英字（大文字小文字を問わず）に 1 つずつ、それ以外のすべて（空の値を含む）に 1 つです。フィールドに対する等価条件、またはテキストで始まる `LIKE`（`'web-%'` など）を含むクエリは、その文字のシャードのファイルだけを読み取ります。`ILIKE` はそれ以外のすべてのシャードも読み取ります。シャードがどれだけ均等になるかはデータによって異なります。16 進数のトレース ID では 16 個のシャードしか使用されません。

2 つのフィールドを使用すると、ファイルは両方のシャードによって分割されるため、シャード数は掛け算になります。**フィールドで分割** には合計が表示され、最大 256 です。先頭文字（37 シャード）は最大 4 シャードのハッシュと組み合わせます。どちらかのフィールドに対する条件を含むクエリは読み取るファイルが少なくなり、両方のフィールドに対する条件を含むクエリはさらに少なくなります。ほぼすべてのクエリで指定されるフィールド（サービス、名前空間、テナントなど）を分割フィールドとして使用します。シャードが多いほど、ファイルはより多く、より小さくなります。

この設定は変更後に書き込まれるデータに適用されます。既存のファイルはそのまま残り、クエリは各ファイルを書き込み時のフィールドによって判定し、コンパクターは同じフィールドで書き込まれたファイルのみをマージします。分割フィールドは暗号化されていないテキストフィールドである必要があり、2 つのフィールドは異なる必要があります。

### フィールドでクラスタリング

ログストリームは、ファイル内の行を 1 つまたは 2 つのフィールドでクラスタリングできます。**設定** タブの **フィールドでクラスタリング** で、**フィールドを追加** を選択し、フィールドを選んで、**時間スライス** を選択します。その後に書き込まれる各ファイルでは、行はその幅の時間スライスに配置され、新しい順に、スライス内ではフィールドの値で並び、その後さらに新しい順に並びます。

時間順では、あるサービスのような値がファイルのすべてのページに現れます。クラスタリングすると、各スライスではその値が少数のページに収まるため、クラスタリングフィールドに対する等価条件（`=` または `IN`）を含むクエリはそれらのページだけを読み取ります。クエリで頻繁に指定され、値の種類が少ないフィールド（サービスやレベルなど）を使用します。

クラスタリングされた各ファイルは、クラスタリングフィールドの値の各組み合わせについて、各行が各分にいくつあるかも保持します。テキストのクラスタリングフィールドに対する等価条件を含むカウント、それらの 1 つでグループ化されたカウント（`GROUP BY service`）、および棒が分単位のヒストグラムは、ファイルを読み取らずにこれらの数値から応答されます。クエリウィンドウがファイル内の分単位の境界で開始または終了する場合も同様です。分と値の組み合わせが 65,536 を超えるファイルは、何も保持しません。同じ数値は、最新または最古の行のページがどこにあるかを示すため、そのようなページは、クラスタリングフィールドに対する等価条件の有無にかかわらず、そのページの元になる分だけを読み取ります。

時間スライスは 1 分、5 分、または 10 分で、デフォルトは 1 分です。スライスを広くするとより多くのページをスキップできますが、短い時間ウィンドウに対するクエリは、触れるスライスを丸ごと読み取ります。

クラスタリングは [フィールドで分割](#フィールドで分割) とは異なります。分割では各シャードが独自のファイルに書き込まれるため、クエリが読み取るファイルは少なくなりますが、ストリームにはより多くの小さなファイルができます。クラスタリングはファイルを保持し、その内部の行を並べ替えます。両者は組み合わせることができます。

この設定は変更後に書き込まれるデータに適用されます。既存のファイルは書き込み時の順序を保持し、コンパクターは同じようにクラスタリングされたファイルのみをマージします。クラスタリングフィールドは暗号化されていないテキスト、`int64`、または `bool` フィールドである必要があり、2 つのフィールドは異なる必要があります。

### 暗号化されたフィールド

ストリームの作成時にフィールドを `encrypted` としてマークすると、Parquet に書き込まれる前に暗号化されます。保存される列には暗号文が保持され、通常のクエリは暗号文を返します。SQL で `decrypt(field)` を使用して値を読み戻します:

```sql
SELECT user, decrypt(secret) AS secret FROM app
```

このフラグは後から変更できません。既存のデータが読み取れなくなるためです。キーは組織の暗号鍵と暗号ルートキー `MS_CIPHER_KEY` から取得されます。ルートキーを失うと、暗号化されたフィールドは復元できなくなります。[セキュリティとマルチテナンシー](/ja/security#フィールドレベルの暗号化) を参照してください。

## リテンションと削除

リテンションは、コンパクターがデータを削除するタイミングを制御します。**リテンション**タブで **データ保持期間（日）**として設定するか、空のままにするとプラットフォームのデフォルトである 30 日が適用されます。これは `_sys` 組織の[設定 → データ保持期間](/ja/settings/platform#データ保持)で設定します。リテンションより古いデータは次のクリーンアップで削除されるため、リテンションを短くするとその時点で期限を過ぎたデータが削除され、削除されたファイルが戻ることはありません。リテンション内に受信されなかったメトリクスストリームのメトリックも、メトリック一覧から外れます。

メトリクスストリームの**リテンション**タブでは、**古いサンプルをダウンサンプリング**により、ストリーム内のすべてのメトリックのうち指定した日数より古いサンプルを 1 分から 1 日までの時間バケットに丸めます。1 つのバケット内のある系列のサンプルは 1 つのポイントになり、値は平均、差分カウントは合計され、元のサンプルは削除されます。長期間にわたるクエリは読み取る量が大幅に減り、古いデータはバケットの解像度だけを保持します。元のサンプルを復元することはできません。

ログとトレースでは、ストリーム設定の**小さいファイルを日単位で統合**（デフォルトでオン）により、終了した 1 日分のファイルを、まとめたサイズがコンパクターの `[compactor].target_size` 以下であれば、その日の終了から 1 時間後に 1 つに統合します。多くの日にまたがるクエリは、開くファイル数が大幅に減ります。その後、リテンションは日単位で適用されます。統合されたファイルは、その日の全体が期限切れになった時点で削除されます。時間単位のファイルを保持するには、ストリームの**設定**タブでこの設定をオフにします。

**ストリームを削除**は、ストリームとその設定を削除し、元に戻すことはできません。ダッシュボード、保存済みビュー、アラート、レポート、パイプラインが壊れる可能性があります。まず**使用状況**タブを確認してください。

## 検索ジョブ

検索ジョブは、バックグラウンドで実行され、ジョブの有効期限が切れるまで結果を保持するクエリです。ジョブは次の 3 つの場所から作成されます。

- `Prefer: respond-async` を付けて送信されたクエリ、または結果が対話的なリクエストには大きすぎると見込まれるクエリ。
- パイプラインのバックフィル。
- Mole Agent が送信するクエリ。

**ストリーム**のヘッダーで**検索ジョブ**を選択すると、一覧が開きます。一覧の先頭にあるビューでは状態で絞り込め、それぞれに件数が表示されます: **すべて**、**キューに追加済み**、**実行中**、**完了**、**失敗**、 **キャンセル済み**。ジョブがキューに追加済みまたは実行中である間、一覧は自動的に更新されます。

各行には、ジョブの種類（**クエリ**または**バックフィル**）、ステートメント、状態、クエリ対象の範囲、送信時刻、所要時間、結果の行数、試行回数、有効期限が表示されます。ジョブの状態に応じて、実行できるアクションは 1 つです:

| 状態 | アクション |
|---|---|
| キューに追加済みまたは実行中 | **ジョブをキャンセル** |
| 完了 | **結果をダウンロード** |
| 失敗またはキャンセル済み | **再試行** |

**削除**は、どの状態でもジョブをその結果ごと削除します。

メンバーは、自分が送信したジョブを表示および管理できます。`org.running_queries.cancel` を持つ管理者は、組織内のすべてのジョブを表示および管理できます。ジョブ API については [クエリ](/ja/query#時間範囲と非同期ジョブ)を参照してください。

## データ取り込み量と予算

**ストリーム**のヘッダーで**データ取り込み量**を選択すると、各ソースが過去 24 時間、7 日間、または 30 日間にどれだけのデータを取り込んだかを確認できます。同じ数値が 3 つの方法で分類されるため、それぞれの合計は一致します:

| ビュー | ソースとは |
|---|---|
| **認証情報** | API トークン、RUM クライアントトークン、コネクター、またはサインイン済みユーザー。**プラットフォーム内部**はプラットフォーム自身のテレメトリーです。 |
| **ストリーム** | 名前と種類で識別される 1 つのストリーム。 |
| **サービス** | イベントが `service.name` で示すサービス。ない場合は `service` または `service_name`。**サービス名なし**は、サービス名を指定していないイベントをまとめたものです。 |

データ取り込み量は、受け付けた内容の展開後のリクエストバイト数を数えます。拒否されたイベントは数えられず、送信者が再試行したリクエストは 1 回として数えられます。スパンは、テールサンプリングの前に、到着時に数えられます。セッションリプレイは**ストリーム**ビューの `rum_replay` 行で数えられます。1 つのリクエストに複数のサービスやストリームが含まれる場合、そのバイト数はイベント数で按分されるため、これらのビューは正確な値ではなく概算値になります。

不明な数値はゼロではなく `–` と表示されます。`≥` が付いた数値は下限値です。これは計測がウィンドウの途中で始まったためで、一覧の上にある行に開始時点が表示されます。数値は約 1 分以内にページに反映されます。突然停止したノードでは、最後の 15 秒間のカウントが失われることがあります。

行を選択すると、そのソースを 1 時間ごとに確認でき、他の 2 つのビューに沿った内訳も確認できます。

### 予算を設定

行の**予算を設定**を選択するか、複数の行にチェックを入れてすべてに 1 つの予算を設定します。

| フィールド | 意味 |
|---|---|
| **期間** | **日次**または**月次**（UTC の暦に基づく）。 |
| **件数の上限** | 1 MiB から 1 PiB まで。 |
| **警告しきい値 (%)** | 上限に対するこの割合に達したときに 1 回、使い切ったときにもう 1 回通知されます。`0` の場合は使い切ったときのみ通知されます。デフォルト: 80。 |
| **通知先** | 組織のメンバー。デフォルト: 予算を設定した人。 |

予算は通知のみを行います。ソースが予算を超えても、データ取り込みは同じように応答および保存し、何も破棄されたり遅くなったりしません。各レベルは期間ごとに 1 回通知されます。上限を引き上げると、以降の判定で再び通知されます。

通知は、組み込みの通知ポリシーである**予算の上限に近づいています**と**予算を超過しました**を通じて送信され、上部バーの通知センターに表示されます。他の誰にどのように通知するかを変更するには、 [通知チャネル](/ja/notification-channels)を参照してください。

`_sys` 組織には通知ポリシーがないため、予算もありません。**プラットフォーム内部**、**サービス名なし**、**その他のサービス**には予算を設定できません。これらは[プラットフォーム設定](/ja/settings/platform#データ取り込み量)で上限を超えたサービスです。

## 権限

| 権限 | できること |
|---|---|
| `intake_usage.read` | **データ取り込み量**を開けます。トークンとメンバーの名前が表示されます。オーナーと管理者が持ちます。 |
| `intake_budgets.manage` | 予算を設定および削除できます。オーナーと管理者が持ちます。 |
| `streams.read` | ストリームを一覧表示し、メタデータを確認できます。 |
| `streams.query` | SQL でストリームデータをクエリできます。 |

| `streams.create` | ストリームを作成できます。 |
| `streams.configure` | スキーマに関わる設定とリテンションを変更できます。 |
| `streams.delete` | ストリームを削除できます。 |
