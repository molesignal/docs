MoleSignal は、1 つの TOML ファイルと `MS_` 環境変数を読み込みます。まず、各リリースに同梱されているサンプル `conf/config.toml` を使用してください。サンプルにはすべての設定項目が記載されており、このページでは各項目について説明します。

```bash
molesignal --config /etc/molesignal/config.toml
```

## 設定の読み込み順序

次の順序で設定を適用します。後から読み込む設定が、それ以前の設定を上書きします。

1. 組み込みのデフォルト値。
2. `--config` で指定した TOML ファイル。
3. `MS_` 環境変数。

設定を変更したら、プロセスを再起動してください。実行中のプロセスはファイルの変更をログに記録しますが、設定には反映しません。

<Note>
  ほとんどのセクションでは、定義されていないキーを無視します。そのため、キーの入力ミスは設定に影響せず、警告も出ません。`[meta_database]`、`[object_store]`（`[object_store.retry]` を含む）、`[telemetry]`（`[telemetry.trace]` と `[telemetry.self_collect]` を含む）、`[apm]`、`[probe]`、`[otlp_grpc]`、`[notify]`、`[scheduled_reports.renderer]` は未定義のキーを受け付けないため、キーの入力ミスがあるとプロセスは起動しません。
</Note>

リファレンス表の **デフォルト** 列には、サンプル `conf/config.toml` の値を示します。キーを省略したときに使用する組み込みの値が異なる場合は、説明欄にその旨を記載します。

## 環境変数

すべての設定項目に対応する環境変数があります。`MS_` を先頭に付け、設定パスの各階層を大文字にして、アンダースコア 1 つでつないでください。

| 設定 | 環境変数 |
|---|---|
| `[http].port` | `MS_HTTP_PORT` |
| `[meta_database].dsn` | `MS_META_DATABASE_DSN` |
| `[cluster].advertise_addr` | `MS_CLUSTER_ADVERTISE_ADDR` |
| `[node].roles` | `MS_NODE_ROLES` |

リストは `MS_NODE_ROLES='["intake","querier"]'` のように TOML 構文で記述してください。ピリオドまたは連続する 2 つのアンダースコアを含む名前は認識しません。

次の環境変数は、設定とは別に読み込みます。

| 環境変数 | 用途 |
|---|---|
| `MS_CIPHER_KEY` | MoleSignal が PostgreSQL 内で暗号化するシークレットのルートキーです。ランダムな 32 bytes を base64 でエンコードして指定してください。未設定の場合、プロセスはすべてのバイトがゼロの開発用キーを使用し、警告をログに記録します。キーを変更するときは、必ず `rewrap-kek` を実行してください。[本番環境チェックリスト](/ja/deployment/production-checklist)を参照してください。 |
| `MS_AUTH_JWT_SECRET_OVERRIDE` | 初回起動時に PostgreSQL 内で生成する JWT 署名用シークレットの代わりに、指定した値を使用します。 |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN` | ロールを分割したノード間で転送するトレース候補と自己テレメトリを認証するための共有シークレットです。[トレースキャプチャ](#トレースのキャプチャとテールサンプリング)（デフォルトで有効）または `[telemetry.self_collect]` が有効な場合は、ロールを分割したすべてのノードに同じ値を設定してください。`intake` ロールを持たないノードは、この値を設定しないと起動しません。 |
| `MS_TRACE_FINGERPRINT_KEY` | 保存しない値の代わりに使う HMAC-SHA-256 フィンガープリントのキーです。対象は、[MoleSignal 自身のスパン](/ja/self-observability#バックエンドの分散トレーシング)に含まれる SQL ステートメントの構造とオブジェクトキー、および [APM の依存関係](/ja/apm#依存関係)に含まれるデータベース名です。16 bytes 以上の値を指定してください。それより短い値は無視します。キーが異なるとフィンガープリントも異なるため、すべてのノードに同じ値を設定してください。キーがない場合は、フィンガープリントを記録せず、キーなしのハッシュで代用することもありません。キーは環境変数からのみ読み込み、API レスポンス、ログ、スパンには出力しません。 |
| `MS_AGENT_OPENAI_API_KEY`, `MS_AGENT_ANTHROPIC_API_KEY`, `MS_AGENT_COMPATIBLE_API_KEY` | Mole Agent のモデルプロバイダー向けの開発用フォールバック API キーです。それぞれに対応する `_BASE_URL` 変数があります。本番環境のプロバイダーは、MoleSignal 上で設定してください。 |
| `RELEASE_CHANNEL` | デプロイメントの成熟度を `alpha`、`beta`、`rc`、`stable` のいずれかで示します。 |
| `RUST_LOG` | 設定すると `[telemetry].log_level` を上書きします。 |
| `AZURE_STORAGE_ACCOUNT`, `AZURE_STORAGE_ACCESS_KEY` | `azure` オブジェクトストレージバックエンドで使用する Azure Blob の認証情報です。 |
| `GOOGLE_APPLICATION_CREDENTIALS` | `gcs` オブジェクトストレージバックエンドで使用するサービスアカウントの JSON ファイルへのパスです。 |

## 本番環境に必要な最小限の設定

本番環境のノードには、少なくとも次の設定が必要です。ファイル内のその他の設定は、デフォルト値のままで構いません。

```toml
[http]
external_url = "https://molesignal.example.com"

[meta_database]
dsn = "postgres://molesignal:<password>@db.internal:5432/molesignal"

[object_store]
backend = "s3"
bucket = "molesignal"
region = "us-east-1"
endpoint = ""          # empty for AWS S3, the service URL for S3-compatible storage
access_key = ""        # prefer MS_OBJECT_STORE_ACCESS_KEY
secret_key = ""        # prefer MS_OBJECT_STORE_SECRET_KEY

[wal]
dir = "/var/lib/molesignal/wal"

[auth]
root_email = "admin@example.com"
root_password = "<initial password>"
```

環境変数 `MS_CIPHER_KEY` も設定してください。本番稼働前に必要な手順の一覧は、[本番環境チェックリスト](/ja/deployment/production-checklist)を参照してください。

## ノード

`[node]` で、プロセスが実行するロールを指定します。[ロールベースのデプロイメント](/ja/deployment/role-based)を参照してください。

| キー | デフォルト | 説明 |
|---|---|---|
| `roles` | `["standalone"]` | 実行するロールは `standalone`、`router`、`intake`、`querier`、`compactor`、`alert` です。`standalone` はすべてのロールを 1 つのプロセスで実行します。 |
| `id` | 空 | 最大 64 文字のノード ID です。空の場合は、OS のホスト名を使用します。1 台のホストで複数のプロセスを実行する場合は、プロセスごとに異なる ID を設定してください。 |
| `drain_timeout_secs` | `30` | `SIGTERM` または `SIGINT` の受信後、取り込み処理で保留中のデータがフラッシュされるまで待機する時間です。指定時間が経過するとプロセスは終了し、フラッシュされなかったデータの処理は別の取り込みノードが引き継ぎます。 |

## リスナー

### HTTP

| キー | デフォルト | 説明 |
|---|---|---|
| `bind` | `0.0.0.0` | 待ち受けアドレスです。 |
| `port` | `5080` | `[http.tls]` が無効な場合の HTTP ポートです。 |
| `gzip` | `true` | gzip に対応するクライアント向けに、プロセスが配信する Web UI ファイルを gzip で圧縮します。API レスポンスは圧縮しません。リバースプロキシで圧縮する場合は `false` に設定してください。 |
| `external_url` | 空 | 公開オリジンです。例: `https://molesignal.example.com`。空の場合、Web UI はブラウザーのオリジンを使用します。オンボーディング用スニペットの生成にはこの値を使用し、ステータスページのカスタムドメインではこの値を CNAME の参照先に使用します。Mole Agent は IM 内のアカウントリンクとチャットリンクにこの値を使用します。Microsoft Teams のコールバックアドレスもこの URL の配下にあるため、Microsoft Teams を使用する場合は HTTPS が必要です。[IM での Mole Agent](/ja/im#teams-のセキュリティ)を参照してください。[パスキー](/ja/identity/mfa#インスタンスの要件)はこの URL のホスト名に紐づくため、ドメイン名を使った HTTPS URL を設定してください。変更後は再起動してください。 |

### HTTP TLS と ACME

`[http.tls]` は、Let's Encrypt などの ACME サービスから証明書を自動取得する TLS リスナーを起動します。

| キー | デフォルト | 説明 |
|---|---|---|
| `enabled` | `false` | TLS リスナーの有効・無効を切り替えます。`false` の場合は、ほかのすべてのキーを無視します。 |
| `plain_port` | `80` | ACME の HTTP-01 チャレンジと HTTPS へのリダイレクトに使用する、暗号化なしの HTTP ポートです。 |
| `port` | `443` | HTTPS ポートです。 |
| `acme_directory` | `production` | `production`、`staging`（Let's Encrypt のステージング環境）、またはカスタムディレクトリの URL を指定します。 |
| `account_email` | 空 | ACME アカウントのメールアドレスです。Let's Encrypt を使用する場合は必須です。 |
| `key_storage_dir` | `/var/lib/molesignal/acme` | ACME アカウントキーとドメインごとのキーを保存するディレクトリです。 |
| `issue_poll_secs` | `60` | 証明書の発行を待っているドメインを確認する間隔です。 |
| `renewal_retry_secs` | `21600` | 証明書の更新を再試行し、有効期限を確認する間隔です。 |

### 内部 gRPC

`[grpc]` はノード間の通信に使用します。このポートは信頼できるネットワーク内でのみ使用してください。

| キー | デフォルト | 説明 |
|---|---|---|
| `bind` | `0.0.0.0` | 待ち受けアドレスです。 |
| `port` | `5082` | ポートです。ピアも `[cluster].advertise_addr` を通じてこのポートを使用します。 |
| `max_message_size` | `32` | gRPC メッセージの最大サイズです。単位は MiB です。 |

### OTLP gRPC

`[otlp_grpc]` は OTLP gRPC レシーバーを設定します。レシーバーに有効・無効を切り替える設定はなく、`standalone` を含め、`intake` ロールを実行するすべてのノードで待ち受けます。

| キー | デフォルト | 説明 |
|---|---|---|
| `bind` | `0.0.0.0` | 待ち受けアドレスです。 |
| `port` | `4317` | ポートです。 |
| `max_message_size` | `32` | gRPC メッセージの最大サイズです。単位は MiB です。 |

### Arrow Flight SQL

`[flight_sql]` は DBeaver、JDBC、ADBC などの SQL クライアントからの接続を受け付けます。すべての呼び出しに API トークンが必要です。[データベースクライアント](/ja/query/database-clients)を参照してください。

| キー | デフォルト | 説明 |
|---|---|---|
| `enabled` | `false` | リスナーを起動します。 |
| `bind` | `0.0.0.0` | 待ち受けアドレスです。 |
| `port` | `5083` | ポートです。 |
| `default_lookback_hours` | `24` | 時間フィルターのない SQL クエリで、過去何時間分のデータを対象にするかを指定します。 |
| `max_message_size` | `32` | メッセージの最大サイズです。単位は MiB です。 |

### Probe Agent

`[probe]` は Probe Agent の登録用エンドポイントと制御用エンドポイントを設定します。これらのエンドポイントは `standalone` ノードと `alert` ノードで起動します。登録にはサーバー認証付きの TLS を使用し、制御ストリームには有効期間の短い認証情報を使った相互 TLS を使用します。[外形監視](/ja/synthetics)を参照してください。

| キー | デフォルト | 説明 |
|---|---|---|
| `bind` | `0.0.0.0` | 待ち受けアドレスです。 |
| `register_port` | `5084` | 登録用ポートです。`control_port` とは異なるポートを指定してください。 |
| `control_port` | `5085` | 制御ストリーム用のポートです。 |
| `register_endpoint` | `https://localhost:5084` | エージェントが登録に使用する公開 `https://` URL です。初回登録用のコマンドがこの URL を出力します。プロキシやロードバランサーの背後で運用する場合は、この値を設定してください。 |
| `control_endpoint` | `https://localhost:5085` | 制御ストリームの公開 `https://` URL です。 |
| `server_names` | `["localhost", "127.0.0.1"]` | サーバー証明書に含める DNS 名と IP アドレスです。各エンドポイントの公開ホスト名を含めてください。 |
| `certificate_days` | `30` | 発行する証明書の有効期間です。1〜365 日の範囲で指定します。 |
| `max_message_size` | `32` | メッセージの最大サイズです。単位は MiB です。 |

### pprof

`[profiling]` は、診断用の pprof リスナーをノード上で起動します。

| キー | デフォルト | 説明 |
|---|---|---|
| `enabled` | `false` | リスナーを起動します。 |
| `bind` | `127.0.0.1` | 待ち受けアドレスです。`allow_remote` が `true` でない限り、ループバックアドレスを指定してください。 |
| `port` | `5086` | ポートです。ノードが実行していないロールのリスナーも含め、ほかの有効なリスナーとは異なるポートを指定してください。 |
| `allow_remote` | `false` | `bind` にループバック以外のアドレスを指定できるようにします。リモートからアクセスできるようにすると、実行時情報が漏えいするおそれがあります。 |

## ストレージ

### メタデータデータベース

`[meta_database]` では、メタデータ、ID、ファイルカタログ、プロダクトリソースを格納する PostgreSQL データベースを設定します。

| キー | デフォルト | 説明 |
|---|---|---|
| `dsn` | `postgres://molesignal:molesignal@localhost:5432/molesignal` | PostgreSQL の接続文字列です。サンプルの認証情報は置き換えてください。 |
| `min_connections` | `2` | 起動時に開く接続数です。`max_connections` を超えることはありません。 |
| `max_connections` | `16` | 接続プールの上限です。 |

MoleSignal は起動時に、組み込みのスキーママイグレーションをデータベースに適用します。[アップグレード](/ja/upgrade)を参照してください。

### オブジェクトストレージ

`[object_store]` では、Parquet ファイル、検索インデックス、プロファイルの BLOB を格納するストレージを設定します。バックエンドは `local`、`s3`、`azure`、`gcs` です。AWS S3 や、RustFS、Cloudflare R2、Alibaba Cloud OSS などの S3 互換サービスには `s3` を使用してください。

| キー | デフォルト | 説明 |
|---|---|---|
| `backend` | `local` | `local`、`s3`、`azure`、`gcs` のいずれかです。 |
| `root` | `./data/objects` | `local` バックエンドのディレクトリです。他のバックエンドでは使用しません。 |
| `bucket` | 空 | `s3` と `gcs` ではバケット名、`azure` ではコンテナー名です。これらのバックエンドでは必須です。 |
| `region` | 空 | S3 リージョンです。S3 互換サービスでは、各サービスが指定する値を使用してください。 |
| `endpoint` | 空 | S3 エンドポイントの URL です。AWS S3 の場合は空のままにしてください。RustFS などのサービスでは `http://host:9000` 形式の URL を使用してください。 |
| `path_style` | `false` | `false` の場合は、AWS S3 と Huawei Cloud OBS が必要とする仮想ホスト形式を使用します。RustFS やほとんどのセルフホスト型サービスが必要とするパス形式を使うには、`true` に設定してください。 |
| `access_key` | 空 | S3 のアクセスキー、または Azure Storage のアクセスキーです。 |
| `secret_key` | 空 | S3 のシークレットキーです。 |
| `credentials_file` | 空 | `access_key=<value>` と `secret_key=<value>` の各行を含むファイルのパスです。以下の優先順位を参照してください。 |
| `multipart_threshold_size` | `32` | このサイズ以上のオブジェクトを分割してアップロードします。単位は MiB です。マニフェストオブジェクトとバージョン条件付きの書き込みは、常に 1 回のリクエストでアップロードします。最小値は 1 です。 |
| `multipart_part_size` | `8` | マルチパートアップロードの 1 パートのサイズです。単位は MiB で、範囲は 5～1024 です。非常に大きなオブジェクトには、1 回のアップロードが 10,000 パート以内に収まるように、より大きなパートを使用します。 |
| `range_threshold_size` | `16` | 読み取るバイト範囲がこのサイズ以上の場合、複数のチャンクリクエストに分割して並列に実行します。単位は MiB で、最小値は 1 です。 |
| `range_chunk_size` | `8` | 1 回のチャンクリクエストのサイズです。単位は MiB で、範囲は 1～1024 です。 |
| `max_concurrency` | `8` | プロセスごとに同時実行できるオブジェクトストレージ操作の数です。 |
| `op_timeout_secs` | `30` | 同時実行枠の空き待ちと、1 回のバックエンド操作に適用するタイムアウトです。 |
| `health_probe_interval_secs` | `30` | バックグラウンドで書き込み、読み取り、削除を確認するヘルスチェックの実行間隔です。最小値は 5 です。 |

S3 と Azure のクライアントは、以下の順に確認し、アクセスキーとシークレットキーの両方がそろっている最初の取得元から認証情報を取得します。

1. 環境変数 `MS_OBJECT_STORE_ACCESS_KEY` と `MS_OBJECT_STORE_SECRET_KEY`。
2. `credentials_file` で指定したファイル。
3. キー `access_key` と `secret_key`。

起動ログの `object_store_credentials_source` には、使用した取得元が `env`、`file`、`inline`、`none` のいずれかで記録されます。シークレットは、`config.toml` ではなく、環境変数または認証情報ファイルで指定することを推奨します。

マルチパートアップロードの各パートと範囲読み取りの各チャンクは、それぞれ 1 回のオブジェクトストレージ操作です。各操作は同時実行枠を 1 つ使用し、個別にリトライし、`object_store_*` メトリクスに反映します。1 件の転送が使用する枠は全体の半分までなので、大きなオブジェクトの転送が他の操作を妨げることはありません。

クラウドバックエンドで一時的なエラーが発生した場合は、指数バックオフでリトライします。

| キー | デフォルト | 説明 |
|---|---|---|
| `[object_store.retry].max_attempts` | `4` | 1 回の操作あたりの合計試行回数です。 |
| `[object_store.retry].base_backoff_ms` | `100` | 初回の待機時間です。 |
| `[object_store.retry].max_backoff_ms` | `5000` | 最大待機時間です。 |
| `[object_store.retry].jitter_ratio` | `0.2` | 各待機時間にランダムなばらつき（ジッター）を加えるための比率です。範囲は `0`～`1` です。 |

### 先行書き込みログ

`[wal]` では、各ノードがオブジェクトストレージに保存する先行書き込みログ（WAL）を設定します。ノードは WAL オブジェクトを保存してから書き込みの成功を返すため、永続ボリュームは不要です。[アーキテクチャ](/ja/architecture#データの耐久性と引き継ぎ)を参照してください。

| キー | デフォルト | 説明 |
|---|---|---|
| `lease_secs` | `15` | 書き込み側のリース期間（秒）です。最小値は `3` です。ノードがリースの更新を停止すると、最終更新からこの期間が経過した後、最大 `takeover_interval_secs` 以内に別のインテークノードが処理を引き継ぎます。起動時にのみ読み込みます。 |

### コンパクションとリテンション

`[compactor]` では、ファイルのマージとリテンションの適用を設定します。これらの処理は `standalone` ノードと `compactor` ノードで実行します。

| キー | デフォルト | 説明 |
|---|---|---|
| `interval_secs` | `300` | コンパクションの実行間隔です。 |
| `target_size` | `512` | 1 回のマージでまとめるファイルの合計サイズの上限です。単位は MiB で、範囲は `1`～`65536` です。マージ後のファイルは、おおむねこのサイズ以下になります。入力をパート単位で読み取り、出力もパート単位でアップロードするため、この値を増やしてもマージのメモリ使用量は増えません。1 回のマージで読み取るファイルは最大 128 個です。残りは後続のラウンドでマージ結果とまとめます。あるファイルが同じマージ対象の他のファイルの合計より大きい場合は、その回の対象から除外し、新しいファイルの合計がそのサイズに達してからマージします。これにより、少量の新規データのために大きなファイルを書き直さずに済みます。 |
| `max_concurrent_groups` | `4` | 1 回のラウンドで 1 ノードが同時に処理するストリーム数です。 |

個別のリテンションを設定していないストリームの保持期間は、`_sys` 組織の **設定 → データ保持** で指定するプラットフォーム設定です。デフォルトは 30 日です。ダウンサンプリングは、メトリクスストリームごとに **リテンション** タブで設定します。[ストリーム](/ja/streams)を参照してください。

### クエリの受付制御

`[search.admission]` は、各ワークグループが 1 ノードで同時に実行できるクエリ数を制限します。ワークグループの実行枠に空きがない場合、クエリをキューに入れ、到着順に実行します。待機時間が `max_wait_secs` を超えたクエリには `429` を返します。結果キャッシュから応答できるクエリは待機しません。上限は、クエリ API や Flight SQL 経由のクエリ、エクスプローラーのチャートやフィールド統計、公開共有、検索ジョブに適用します。アラート評価などのバックグラウンド処理はキューに入りません。サンプルファイルにはこのセクションを記載していません。

| キー | デフォルト | 説明 |
|---|---|---|
| `default_max_concurrent` | CPU 数の 2 倍 | `groups` にエントリがないワークグループのノードごとの上限です。`0` の場合は上限を設けません。 |
| `groups` | 空 | ワークグループ名とノードごとの上限を対応付けるテーブルです。 |
| `role_map` | 空 | ロール（`owner`、`admin`、`editor`、`viewer`）をワークグループに対応付けるテーブルです。対応付けのないロールには `default` を使用します。 |
| `max_wait_secs` | `60` | クエリの実行枠が空くまで待機する時間です。この時間内に空かなければ `429` を返します。`0` の場合は、ワークグループの実行枠に空きがなければすぐに `429` を返します。 |
| `cluster_default_max_concurrent` | `0` | `cluster_groups` にエントリがないワークグループに適用する、クラスター全体のソフト上限です。実行枠に空きがなければ、クエリにすぐに `429` を返します。`0` の場合は上限を設けません。 |
| `cluster_groups` | 空 | ワークグループ名とクラスター全体のソフト上限を対応付けるテーブルです。 |
| `cluster_sync_interval_secs` | `0` | ノードの負荷情報を公開する間隔です。`0` の場合は 5 を使用します。 |
| `cluster_stale_secs` | `0` | この時間を超えて負荷情報の通知がないノードは、クラスターのビューから除外します。`0` の場合は 30 を使用します。 |

`/metrics` では、各ワークグループのキューの状態を `query_admission_running`、`query_admission_waiting`、`query_admission_wait_seconds`、`query_admission_refusals_total` で確認できます。

### キャッシュ

各レイヤーは、有効期間（TTL）を持つ LRU キャッシュです。容量が `0` の場合は、そのレイヤーを無効にします。ヒット率は `/metrics` の `cache_<layer>_hit_ratio` で確認できます。

| セクション | デフォルト容量 | デフォルト TTL | キャッシュ内容 |
|---|---|---|---|
| `[cache.index_handle]` | `10000` | `600` s | 開いている検索インデックスのハンドルです。 |
| `[cache.query_result]` | `1000` | `60` s | 終了済みの時間ウィンドウを対象とした SQL クエリの結果です。 |
| `[cache.tantivy_result]` | `1000000` | `600` s | 読み取り対象のファイルを絞り込むための用語ごとの件数です。 |
| `[cache.tantivy_footer]` | `100000` | `3600` s | 範囲読み取りを省くためのインデックスフッターです。 |

各セクションでは `capacity` と `ttl_secs` を指定します。

`[cache.parquet_metadata]` は、ページインデックスを含む解析済みの Parquet フッターをメモリに保持します。キャッシュ済みのファイルを開くクエリは、フッターの読み取りを省略します。設定キーは `max_size` のみです。単位は MiB で、デフォルトは `256` です。`0` の場合はキャッシュを無効にします。

`[cache.object]` は、リモートオブジェクトのバイト範囲をローカルディスクにキャッシュします。`local` オブジェクトバックエンドはこのキャッシュを使用しません。

| キー | デフォルト | 説明 |
|---|---|---|
| `enabled` | `true` | キャッシュを有効にします。`max_size` が `0` の場合もキャッシュを無効にします。 |
| `root` | `./data/cache/objects` | キャッシュディレクトリです。 |
| `max_size` | `10240` | キャッシュの最大サイズです。単位は MiB で、デフォルトは 10 GiB です。 |
| `block_size` | `4` | ブロックサイズです。単位は MiB で、1〜16 の範囲で指定します。 |
| `memory_size` | `256` | 検証済みブロックをメモリに保持する容量です。単位は MiB です。保持したブロックを再度読み取る際は、ディスクにアクセスしません。`0` の場合はブロックをディスクにのみ保持します。 |
| `min_free_size` | `1024` | 確保するディスクの空き容量です。単位は MiB で、デフォルトは 1 GiB です。 |
| `max_concurrent_fetches` | `16` | ブロックを同時に取得できる数です。0 より大きい値を指定してください。 |
| `max_concurrent_fetches_per_object` | `4` | 1 つのオブジェクトに対してブロックを同時に取得できる数です。0 より大きい値を指定してください。 |

キャッシュサイズが `max_size` を超えるか、ディスクの空き容量が `min_free_size` を下回ると、最後に使った時点が古いブロックからキャッシュから削除します。ガベージコレクターがオブジェクトを削除すると、削除を実行したノードは、起動後にそのオブジェクトを読み取っていた場合に限り、対応するブロックもキャッシュから削除します。他のノードは、通常のキャッシュ削除ルールに従ってそれらのブロックを削除します。

### インクリメンタル範囲キャッシュ

`[search.stream_agg_cache]` は、`rate(metric[5m])` などの PromQL 範囲クエリで終了済みの時間ウィンドウをキャッシュします。ダッシュボードの更新時には、最新のウィンドウだけを再計算します。

| キー | デフォルト | 説明 |
|---|---|---|
| `max_size` | `256` | キャッシュに割り当てるメモリ容量です。単位は MiB です。使用量は、各クエリが保持する時系列とウィンドウに基づいて推定します。`0` の場合はキャッシュを無効にします。 |
| `ttl_secs` | `300` | キャッシュエントリの有効期間です。`safe_lookback_secs` を超えて遅れて到着するデータにも対応します。 |
| `safe_lookback_secs` | `300` | 現在時刻からこの値を引いた時刻より前に終了したウィンドウだけをキャッシュします。 |
| `max_series_per_query` | `10000` | フィンガープリントごとにキャッシュする時系列数の上限です。`0` の場合は上限を設けません。 |

| `from` | `molesignal@example.com` | 送信元アドレスです。SMTP が有効な場合は必須です。組み込み値は空です。 |
| `tls` | `starttls` | `none`、`starttls`、`tls` のいずれかです。 |
| `timeout_secs` | `10` | 接続と送信のタイムアウトです。組み込み値の `0` は 1 秒を意味します。 |

## 認証

| キー | デフォルト | 説明 |
|---|---|---|
| `session_ttl_secs` | `86400` | サインイン状態が続く時間で、リフレッシュトークンの有効期間にあたります。デフォルトは 24 時間です。この期間中、アクセストークンは 15 分ごとに更新されます。`_sys` 組織のセッションは 1 時間以内に終了します。 |
| `root_email` | `admin@example.com` | ルートアカウントのメールアドレスです。組み込み値は空です。 |
| `root_password` | `admin` | ルートアカウントのパスワードです。組み込み値は空です。サンプル値は置き換えてください。 |

初回起動時に、データベースにユーザーが存在せず、両方の値が設定されている場合、MoleSignal はルートアカウントを作成します。後から `root_password` を変更しても、既存のアカウントのパスワードは変わりません。パスワードは Web UI で変更してください。起動するたびに、`root_email` に指定したメールアドレスを持つアカウントがプラットフォーム管理者になります。そのため、`root_email` には既存ユーザーのメールアドレスを指定してください。

初回起動時に JWT 署名シークレットを生成し、PostgreSQL に保存します。シークレットを固定するには `MS_AUTH_JWT_SECRET_OVERRIDE` を使用し、ローテーションするには `POST /api/v1/auth/jwt/rotate` を使用してください。

## 自己オブザーバビリティ

プロセスのログと自動収集するテレメトリーには `[telemetry]` を使用します。[自己オブザーバビリティ](/ja/self-observability)を参照してください。

| キー | デフォルト | 説明 |
|---|---|---|
| `[telemetry].log_level` | `info,tantivy=warn` | `EnvFilter` 構文のログフィルターです。組み込み値は `info` です。`RUST_LOG` で上書きできます。 |
| `[telemetry].log_format` | `text` | `text` または `json` です。 |
| `[telemetry].log_output` | `console` | `console` または `file` です。 |
| `[telemetry].log_directory` | `logs` | `log_output` が `file` の場合のログファイルのディレクトリです。 |
| `[telemetry].log_rotation` | `daily` | `minutely`、`hourly`、`daily`、`never` のいずれかです。 |
| `[telemetry].log_max_files` | `7` | ローテーション後に保持するファイル数です。 |

サンプルファイルでは、最後の 3 つのキーをコメントアウトしています。表に示す値は、`log_output` が `file` の場合に適用されます。

### プロセス自身のテレメトリーの収集

`[telemetry.self_collect]` は、プロセスのメトリクス、トレース、プロファイルを予約済みの `_molesignal` ストリーム群に書き込みます。収集対象はプロセス自身のシグナルのみです。この設定の有効・無効にかかわらず、テナントが送信するトレースは保存します。

| キー | デフォルト | 説明 |
|---|---|---|
| `enabled` | `true` | 自己収集全体の有効・無効を切り替えます。組み込み値は `false` です。トレースを収集するには、`[telemetry.trace].enabled` も有効にする必要があります。 |
| `metrics_enabled` | `true` | プロセスのメトリクスを収集します。 |
| `metrics_interval_secs` | `15` | メトリクスの収集間隔です。 |
| `queue_capacity` | `8192` | シグナルごとのインメモリキューの上限です。 |
| `batch_max_events` | `256` | 1 バッチあたりの最大イベント数です。 |
| `batch_max_delay_ms` | `1000` | バッチがいっぱいになるまでの最大待機時間です。 |
| `flush_timeout_secs` | `5` | シャットダウン時にキューをフラッシュするための制限時間です。 |
| `profiles_enabled` | `false` | プロセスのプロファイルを収集します。 |
| `profile_kinds` | `["cpu"]` | `cpu`、`heap`、またはその両方です。 |
| `profile_interval_secs` | `600` | プロファイルの収集間隔です。 |
| `profile_duration_secs` | `10` | 1 回の CPU プロファイルの収集時間です。1～120 の範囲で指定します。 |

MoleSignal は、リテンションを 7 日に設定して `_molesignal` ストリームを作成します。変更するには、`_sys` 組織で対象ストリームの **リテンション** タブを開いてください。設定値は再起動後も維持されます。

### トレースのキャプチャとテールサンプリング

`[telemetry.trace]` は、サービスが自身について記録するスパンと、保持するトレースを選ぶテールサンプラーを制御します。

| キー | デフォルト | 説明 |
|---|---|---|
| `enabled` | `true` | キャプチャとテールサンプリングのデフォルトの有効・無効を切り替えます。`force_disabled` が `false` の間は、実行時ポリシーで変更できます。 |
| `force_disabled` | `false` | デプロイ時に最優先される切り替え設定です。`/api/v1/system/telemetry` の実行時ポリシーでは上書きできません。 |
| `filter` | `info` | スパンのキャプチャとエクスポートに使用する `EnvFilter` です。`RUST_LOG` と `log_level` には依存しません。 |
| `deployment_environment` | `production` | 環境ラベルです。`development`、`dev`、`test` では `development_sample_ratio` を使用します。それ以外の値では `normal_sample_ratio` を使用します。 |
| `normal_sample_ratio` | `0.10` | 開発環境以外での通常のトレースの基本サンプリング率です。0.0～1.0 の範囲で指定します。 |
| `development_sample_ratio` | `1.0` | 開発環境での基本サンプリング率です。0.0～1.0 の範囲で指定します。 |
| `decision_window_secs` | `30` | サンプラーが採否を決定する前に、トレースのスパンを集約する時間です。5～120 の範囲で指定します。 |
| `root_grace_millis` | `1000` | ルートスパンの終了後、遅れて到着する子スパンを待つ時間です。 |
| `decision_cache_secs` | `300` | サンプリングの判定結果を保持する時間です。`decision_window_secs` 以上を指定します。 |
| `tail_max_traces` | `10000` | サンプラーが判定前に保持できるトレースの上限数です。 |
| `tail_memory_size` | `256` | 判定前のトレースに使用するメモリの上限です。単位は MiB です。 |
| `max_spans_per_trace` | `1000` | トレースごとに保持するスパンの上限数です。 |
| `max_attributes_per_span` | `128` | スパンごとに保持する属性の上限数です。 |
| `max_events_per_span` | `128` | スパンごとに保持するイベントの上限数です。 |
| `max_links_per_span` | `128` | スパンごとに保持するリンクの上限数です。 |
| `max_string_length` | `4096` | 属性、イベント、リンクの文字列の最大長です。UTF-8 のバイト数で指定します。 |
| `shutdown_timeout_secs` | `10` | シャットダウン時にパイプラインを停止するための制限時間です。 |

`[telemetry.trace.slow_thresholds]` では、スパンを低速と判定するしきい値をミリ秒単位で指定します。`http_ms = 1000`、`query_ms = 5000`、`batch_intake_ms = 2000`、`database_ms = 200`、`object_store_ms = 500`、`external_ms = 1000`、`background_ms = 30000` です。

`[telemetry.trace.external]` は、トレースを外部の OTLP レシーバーにエクスポートします。`endpoint` が空の場合はエクスポートしません。

| キー | デフォルト | 説明 |
|---|---|---|

| `timeout_ms` | `5000` | 接続とエクスポートのタイムアウトです。 |
| `queue_capacity` | `8192` | エクスポートキューの容量です。 |

| `gzip` | `false` | ペイロードを圧縮します。 |
| `allow_self_export` | `false` | この MoleSignal クラスターへのエクスポートを許可します。ループを防ぐため、デフォルトでは無効です。 |
| `headers` | なし | OTLP ヘッダーです。シークレットは `env:NAME` または `secret:NAME` で参照し、値を直接記述しないでください。 |
| `custom_ca_file` | なし | HTTPS サーバー証明書の検証に使用する CA ファイルです。 |

### APM

`[apm]` は、アプリケーションパフォーマンスモニタリング用のデータ生成を制御します。この処理は、トレース候補を所有するノードか、`alert` ロールのロールアップ処理を実行するノードで開始します。[APM](/ja/apm) を参照してください。

| キー | デフォルト | 説明 |
|---|---|---|
| `queue_capacity` | `65536` | 入力キューの容量です。1024～1048576 の範囲で指定します。 |
| `flush_interval_ms` | `5000` | 集計データをフラッシュする間隔です。100～60000 の範囲で指定します。 |
| `flush_max_snapshots` | `10000` | 1 回のフラッシュあたりの最大スナップショット数です。1～100000 の範囲で指定します。 |
| `shutdown_drain_secs` | `10` | シャットダウン時にキューを空にするための制限時間です。1～300 の範囲で指定します。 |
| `late_grace_secs` | `300` | 遅れて到着したトレースデータを受け付ける猶予時間です。0 より大きく、高解像度データのリテンションより短い値を指定します。 |
| `hot_retention_hours` | `24` | 高解像度データのリテンションです。1～168 の範囲で指定します。 |
| `rollup_retention_days` | `30` | ロールアップのリテンションです。1～3650 の範囲で指定します。 |
| `max_query_range_days` | `30` | 1 回の APM クエリで指定できる最大期間です。`rollup_retention_days` 以下を指定します。 |
| `max_exemplars_per_bucket` | `3` | 集計バケットごとのエグゼンプラーの上限数です。1～16 の範囲で指定します。 |
| `max_error_samples_per_group` | `8` | グループごとのエラーサンプルの上限数です。1～64 の範囲で指定します。 |
| `[apm.histogram].schema_version` | `2` | レイテンシーバケット構成のバージョンです。`buckets_per_octave` を変更するたびに、この値を増やしてください。`2` 以上を指定します。バージョン `1` は以前の集計で使用した固定バケット構成で、その集計データは引き続き読み取れます。 |
| `[apm.histogram].buckets_per_octave` | `8` | レイテンシーが 2 倍になる区間ごとのバケット数です。1～16 の範囲で指定します。対象範囲は 125 µs～約 131 s で、`+Inf` は自動で追加します。`8` の場合、隣接する境界値の差は約 9% で、パーセンタイルの誤差は約 4% 以内です。 |
| `[apm.version_comparison].min_requests_per_version` | `1000` | バージョンを比較対象に含めるために必要な最小リクエスト数です。 |

APM が 1 時間あたりに個別に保持するサービス、エンドポイント、依存関係、オペレーション、エラーグループ、バージョン、インスタンスの件数上限は、プラットフォーム設定で管理します。`sys.settings.limits.manage` 権限がある場合は、**APM → 設定 → カーディナリティの上限** で変更できます。各ノードは 30 秒ごとに設定を再読み込みします。[APM の設定](/ja/apm/settings#カーディナリティの上限)を参照してください。`[apm.cardinality]` セクションが残っている構成ファイルは読み込めません。

## データベースに保存する設定

以下の設定は PostgreSQL に保存します。Web UI または API から変更できます。対応する TOML キーはありません。

- SSO プロバイダー（OIDC、OAuth 2.0、SAML、LDAP）。
- フェデレーションクエリ用のリモートクラスター。
- ステータスページのドメインと証明書、および訪問者がページを Slack に追加する際に使用する Slack アプリ。
- 通知チャネル、スケジュール、エスカレーションポリシー。
- Mole Agent のモデルプロバイダー、プロンプト、ツール、承認ポリシー。
- 組織の暗号鍵、フィールドのマスキングルール、共有ポリシー。
