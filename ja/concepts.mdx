これらの概念は、取り込み、クエリ、アラート、自動化、管理のすべてに共通します。

## シグナル

MoleSignal は 4 種類のテレメトリシグナルを扱います。

- **ログ**は、個々の構造化イベントです。
- **メトリクス**は、ラベル付きの時系列にまとめた数値サンプルです。
- **トレース**は、`trace_id` と親子関係でつながったスパンです。
- **プロファイル**は、CPU、メモリ割り当て、ヒープ、競合のサンプルをコールスタックで表します。

RUM レコードは組織のストリームに保存され、ブラウザーセッションとバックエンドのトレースを関連付けます。

[APM](/ja/apm) は 5 番目のテレメトリストリームではありません。APM は、テールサンプリング前に重複を除いたトレーススパンから生成する、範囲を限定した射影です。このため、サンプリングで除外されたトレースも、サービス、トランザクション、依存関係、エラーの集計に反映できます。

## ストリーム

**ストリーム**は、取り込みとクエリが共有する型付きの契約です。名前、`streamType`、更新可能なスキーマ、保持期間、実行時の状態、`queryable` フラグを持ちます。

サポートする型は `logs`、`metrics`、`traces`、`profiles`、`extend` です。同じ名前を複数の型で使用できるため、 API は名前と型の両方でストリームを識別します。

```json
{ "name": "app", "streamType": "logs" }
```

すべてのデータを受け付けるソースをルーティングパイプラインに接続し、クエリの選択肢には表示しない場合は、 `queryable` を無効にしてください。[ストリーム](/ja/streams)を参照してください。

## 組織とワークスペース

**組織**は、テナントとポリシーの境界です。製品 UI では、選択した組織を **ワークスペース**と呼びます。テレメトリと製品リソースはそれぞれ 1 つの組織にのみ属します。組織をまたぐアクセスには、明示的な権限付与またはリソースの共有が必要です。

永続的な `_sys` 組織は、システムテレメトリ、プラットフォーム管理者、組織全体に関わる操作のための保護されたプラットフォームスコープです。`_sys` 組織は通常のテナントではありません。

## 製品リソース

ダッシュボード、保存済みビュー、アラートルール、スケジュール、レポート、関数、パイプライン、 Mole Agent のワークフローは、組織のリソースです。ハンドラーは対象リソースを読み込み、所有権を確認し、要求された操作を認可してから、リソースを返すか変更します。

## 権限とロール

権限は、`streams.query`、`alerts.rules.manage`、 `sys.telemetry.read` などの固定の機能キーです。ロールは名前付きの権限セットです。ロールには、再利用可能な権限セットである権限ポリシーを関連付けます。 API トークンにも同じポリシーを適用できます。ロールは独自の権限も持ちます。組み込みのオーナー、管理者、編集者、閲覧者、プラットフォーム管理者の各ロールを既定で用意しています。カスタムロールでは、より限定された職務に合わせて権限を設定できます。

ナビゲーションには有効な権限のスナップショットを使いますが、ページを非表示にしても、バックエンドでの認可は必要です。[ID とアクセス](/ja/identity)を参照してください。

## 時間範囲と相関

探索ページは時間範囲を共有します。相関データに移動するときは、その範囲を維持し、 `trace_id`、サービス、ホスト、セッションなどの識別子を追加します。これにより、 `RUM → trace → log → metric → profile` のように移動できます。ナビゲーションの状態は認可には使いません。

## ストレージとクエリ

ログ、メトリクス、トレースは、パーティション分割した Parquet ファイルに保存します。プロファイルのメタデータにはクエリを実行できますが、圧縮した pprof BLOB はオブジェクトストレージに保存します。PostgreSQL には、ファイルのメタデータ、スキーマ、 IAM、製品リソース、運用状態を保存します。

DataFusion と Arrow は、SQL、PromQL 互換のメトリクスクエリ、ローカル検索、フェデレーションスキャンを実行します。クエリプランナーは、実行前にアクセスを許可された組織に対象を絞ります。

## 実行時ロール

単一のバイナリで、`[node].roles` を使って以下のロールを組み合わせます。

| ロール | 主な役割 |
|---|---|
| `standalone` | すべての API とワーカーを 1 つのプロセスで実行します。 |
| `router` | すべての HTTP API と Web UI を提供し、レート制限を適用して、リクエストを取り込みノードやクエリノードに転送します。 |
| `intake` | 検証、パイプラインの実行、WAL、バッファー管理、Parquet へのフラッシュを担当します。 |
| `querier` | 他のノードから転送されたリクエストのクエリを実行します。 |
| `compactor` | コンパクション、保持期間の管理、ストレージのメンテナンスを担当します。 |
| `alert` | ルールの評価、スケジュール管理、エスカレーション、通知の配信を担当します。 |

コンポーネントとデータフローについては、[アーキテクチャ](/ja/architecture)を参照してください。
