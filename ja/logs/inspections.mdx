ログ分析では、Mole Agent が指定期間のログを読み取り、問題の有無、問題の内容、根拠となるログをレポートにまとめます。ログ分析は読み取り専用です。データや設定は変更しません。

| 種類 | 用途 |
|---|---|
| **オンデマンド** | **ログ**の **AI 分析**ビューで、現在のクエリに一致するログを一度だけ分析します。レポートはページに順次表示されます。分析は Mole Agent のチャットとして実行されるため、**Mole Agent** で続けられます。レポートは定期チェックのレポートとは別扱いで、定期チェックの履歴には保存されません。 |
| **スケジュール実行** | ストリーム、クエリ、分析時の注目点を保存します。MoleSignal はスケジュールに従って分析し、すべてのレポートを保存します。レポートが問題を示すと通知します。 |

## 開始する前に

- **Mole Agent → 設定 → モデルと推論**で、少なくとも 1 つの AI モデルを有効にします。 [Mole Agent](/ja/agent#モデルプロバイダーを設定する)を参照してください。有効なモデルがない場合、保存済みのチェックは一覧に残りますが、実行できません。
- 権限を確認します。

| 操作 | 権限 |
|---|---|
| オンデマンドで分析する | `agent.use` と `logs.read` |
| 定期チェックとそのレポートを閲覧する | `inspections.read` と `logs.read` |
| 作成、編集、有効化、無効化、削除を行う | `inspections.manage`。デフォルトでオーナー、管理者、編集者のロールに付与されます。 |
| 今すぐ実行する | `inspections.run`。同じロールに付与されます。 |
| フォームで通知チャネルを選択する | `notify.connectors.read`。通知コネクターを一覧表示できます。 |

Mole Agent はチャット内で `list_log_inspections`、 `list_log_inspection_runs`、`get_log_inspection_run` を使い、同じ権限でチェックとレポートを読み取ります。 `run_log_inspection` はチェックを即時実行します。`inspections.run` が必要で、デフォルトではチャット内での確認も必要です。[ツールカタログと実行](/ja/tools)を参照してください。

## オンデマンドで分析する

1. **ログ**を開き、ストリームと時間範囲を選択して、クエリを実行します。ストリーム内のすべてのログを分析するには、クエリを空欄のままにします。
2. **AI 分析**ビューを開きます。
3. **AI モデル**を選択します。必要に応じて、監視対象のサービスや正常とみなす結果などを **分析時の注目点**に記述します。
4. **分析を開始**を選択します。

分析では、ログのクエリ結果を選択したモデルに送信します。レポートについて追加で質問するには、**Mole Agent で続ける**を選択します。

## 定期チェックを保存する

**ログ → AI 分析**を開き、次のいずれかを選択します。

- **定期チェックとして保存**を選択すると、現在のストリーム、クエリ、分析時の注目点、モデルが入力されたフォームが開きます。現時点でクエリに一致するログがなくても、チェックを保存できます。
- **定期チェック**を選択すると一覧が開きます。**新規チェック**を選択すると、空のフォームが開きます。

| フィールド | 説明 |
|---|---|
| **名前** | 組織内で一意の名前です。最大 120 文字です。 |
| **ストリーム** | [`_audit`](/ja/settings/data-security#監査ストリーム) 以外のログストリームを 1 つ選択します。チェックはこのストリームだけを読み取ります。 |
| **クエリ** | 任意です。クエリに一致するログだけを分析します。構文は**ログ**と同じです。 |
| **分析時の注目点** | 任意です。最大 2,000 文字で、何に注目するか、何を正常とみなすかを指定します。 |
| **スケジュール** | **一定間隔**、または指定時刻に**毎日**もしくは**毎週**実行します。最短間隔はインスタンス設定で決まり、デフォルトは 1 時間です。 |
| **対象期間** | 各実行の開始時点からどこまでさかのぼって分析するかを指定します。フォームでは 15 分から 7 日まで指定できます。デフォルト値はスケジュールに応じて決まります。 |
| **AI モデル** | 組織で有効になっているモデルを 1 つ選択します。 |
| **通知タイミング** | **異常時に通知**（デフォルト）、**要注意以上で通知**、**毎回通知**のいずれかを選択します。 |
| **通知チャネル** | 任意です。最大 10 件まで選択できます。各チャネルは通知コネクターで指定された固定のグループまたはアドレスです。Alibaba Cloud の SMS と音声は承認済みテンプレートでしか送信できないため、選択肢に含まれません。 |
| **保存後にスケジュールに従って実行** | オフにすると、チェックは保存されますが、**今すぐ実行**を選択した場合にのみ実行されます。 |

毎日または毎週の実行時刻には、作成時のインターフェイスのタイムゾーンを使います。個人設定にタイムゾーンがあればその設定を使い、なければブラウザーのタイムゾーンを使います。フォームにタイムゾーンを表示し、後から編集しても変わりません。通知とレポートには、作成時のインターフェイス言語を使います。

組織に保存できる定期チェックは、デフォルトで最大 20 件です。

## チェックの実行の仕組み

| 項目 | 動作 |
|---|---|
| 実行ユーザー | チェックは、最後に保存したユーザーとしてログを読み取ります。実行前に毎回、MoleSignal は、そのユーザーが引き続きサインインできること、組織のメンバーであること、`agent.use` と `logs.read` を持っていることを確認します。いずれかの条件を満たさない場合は、そのユーザーとして実行できなくなったことを理由として記録し、実行は失敗します。再開するには、必要な権限を持つ別のユーザーがチェックを保存し直します。以降はそのユーザーとして実行します。API トークンでは定期チェックを保存できません。 |
| ツール | モデルは、読み取り専用の 4 つのツール `query_logs`、`get_stream_schema`、`search_field_values`、`analyze_log_patterns`（ログをパターン別にまとめ、基準期間と比較するツール）を、チェック対象のストリームに対してのみ使用します。バックグラウンドでは承認を行えないため、組織のツールポリシーで無効になっているツールや、承認が必要なツールは使用しません。 |
| 時間範囲 | チェックは実行開始直前の対象期間を分析します。ノードの停止中に実行できなかった分はさかのぼって実行しません。ノードが復旧すると、実行予定時刻を過ぎたチェックを一度だけ実行し、その後はスケジュールに従って実行します。 |
| 制限 | 1 回の実行の上限はデフォルトで 5 分です。上限を超えるとタイムアウトになります。ツールの結果が 64 KiB を超える場合は、結果をモデルに渡さず、代わりにクエリを絞り込むようモデルに指示します。実行が失敗しても、次のスケジュール実行までは再試行しません。 |
| 同時実行 | 同じチェックの実行は同時に 1 件までです。1 つのノードが同時に実行できるチェックは、デフォルトで最大 2 件です。 |
| **今すぐ実行** | チェックをキューに追加し、15 秒以内にそのチェックの実行ユーザーとして実行を開始します。記録には、実行を開始したユーザーの名前が残ります。無効にしたチェックもこの方法で実行できます。 |

## レポートと判定

一覧からチェックを選択すると、レポートが開きます。過去の実行は左側に表示されます。実行を選択すると、レポート、対象期間、実行時間、呼び出したツール、使用したトークン数、送信した通知を確認できます。**この期間のログを開く**を選択すると、同じストリーム、クエリ、対象期間で**ログ**が開きます。

定期チェックのレポートには判定が付きます。

| 判定 | 説明 |
|---|---|
| **標準** | 対応が必要な項目はありません。 |
| **要確認** | 確認すべき項目はありますが、障害は発生していません。 |
| **異常** | 問題があり、対応が必要です。 |
| **判定なし** | モデルの回答に読み取れる判定がありませんでした。レポートは保存され、通知では異常として扱います。 |

完了しなかった実行にはレポートがありません。記録には状態と理由が表示されます。

| 状態 | 理由 |
|---|---|
| **タイムアウト** | 実行が制限時間を超えました。 |
| **失敗** | 次のいずれかが発生しました。実行ユーザーとして実行できなくなった、選択した AI モデルが存在しないか無効かキーが未設定だった、モデルの呼び出しに失敗した、組織の当日分の Mole Agent のトークン予算を使い切った、実行中にノードが停止した、どのノードも実行を引き受けなかった、または内部エラーが発生した。 |

レポートの保存期間はデフォルトで 30 日です。保存期間を過ぎたレポートは 1 時間ごとに削除します。チェックを削除すると、そのチェックのすべてのレポートも削除します。

## 通知

- レポートの判定が**通知タイミング**の条件を満たすと、各チャネルに通知を1件送信します。タイトルには判定と検査名が含まれます。本文にはストリーム、対象期間、判定、レポートの概要、レポートへのリンクが含まれます。リンクを使用するには、 `http.external_url` を設定してください。
- 実行が失敗し、直前の実行が失敗していなければ、通知を1件送信します。失敗が続く場合は、 **通知タイミング**の設定にかかわらず、最初の失敗時にのみ通知します。
- チャネルが設定されていない場合、通知は送信せず、レポートは保持します。
- すべての通知は**設定 → 通知 → 配信ログ**に表示され、ステージは **直接**になります。直接配信には通知ポリシーが適用されず、配信ログから再試行できません。
- スケジュール済みの検査が使用している通知コネクターは削除できません。

## インスタンス設定

| 設定 | デフォルト | 用途 |
|---|---|---|
| `[log_inspection].min_interval_secs` | `3600` | 同じ検査を実行する最短間隔です。60未満の値は60として扱います。 |
| `[log_inspection].max_per_org` | `20` | 1つの組織で保持できるスケジュール済み検査の上限です。`0` を指定すると1件も保持できません。 |
| `[log_inspection].concurrent_runs` | `2` | 1つのノードで同時に実行できる検査の数です。 |
| `[log_inspection].run_timeout_secs` | `300` | 1回の実行の制限時間です。すべてのモデル呼び出しとクエリを含みます。値は30～480の範囲に収めます。 |
| `[log_inspection].report_retention_days` | `30` | レポートの保持期間です。 |

`alert` ロールのノードがスケジュール済みの検査を実行します。実行予定時刻に達した検査やキューに入っている検査がないか、15秒ごとに確認します。`alert` ノードが複数あっても、各実行を処理するノードは1つだけです。 [ロールベースのデプロイ](/ja/deployment/role-based)を参照してください。

実行状況は次の2つのメトリクスで確認できます。

| メトリクス | 意味 |
|---|---|
| `log_inspection_runs_total{outcome}` | 完了した実行の結果別件数です。結果は `succeeded`、`failed`、`timed_out` のいずれかです。 |
| `log_inspection_run_duration_seconds` | 1回の実行の所要時間です。 |

## API

エンドポイントは `/api/v1/logs/inspections` 配下にあります。

| メソッドとパス | 用途 |
|---|---|
| `GET /logs/inspections` | 組織のスケジュール済み検査を一覧表示します。 |
| `POST /logs/inspections` | 検査を作成します。 |
| `GET /logs/inspections/limits` | インスタンスに設定された上限値を取得します。 |
| `GET`, `PUT`, `DELETE /logs/inspections/{id}` | 検査を取得、置換、または削除します。削除時はレポートも削除します。 |
| `POST /logs/inspections/{id}/enabled` | 検査を有効または無効にします。 |
| `POST /logs/inspections/{id}/run` | 検査を今すぐ1回実行します。 |
| `GET /logs/inspections/{id}/runs` | 過去の実行を新しい順に取得します。レポート本文は含みません。`limit` のデフォルトは50、上限は200です。`before` で古い実行のページを取得します。 |
| `GET /logs/inspections/{id}/runs/{run_id}` | 1回の実行をレポートとともに取得します。 |
