**レポート**を開いて、レポートのスケジュール、生成履歴、再利用可能なテンプレートを管理します。

| タブ | 内容 |
|---|---|
| **スケジュール** | すべてのレポートについて、ソース、スケジュール、次回の実行、前回の結果、受信者、状態を表示します。上部には、稼働中のレポート数、今後24時間以内の配信予定件数、過去30日間の成功率、未解決の失敗件数を表示します。 |
| **生成履歴** | 生成したレポートとその配信結果を表示します。**エラーを表示**で失敗の理由を確認できます。 |
| **テンプレートライブラリ** | 組み込みテンプレートとカスタムテンプレートを表示します。**テンプレートを使用**で、選択したテンプレートからレポートを作成できます。 |

## レポートを作成する

**新規レポート**を選択します。作成画面では3つのステップで設定を進めます。右側のプレビューには、設定に応じてレポートの構成が表示されます。

<Steps>
  <Step title="内容と対象範囲">
    **レポート名**と**用途**を入力します。**ソースタイプ**としてダッシュボードまたは保存済みビューを選び、**データソース**を選択します。**データ期間**には、過去1時間、過去24時間、過去7日間、過去30日間、前日、先週、先月、または**カスタム**を指定します。
  </Step>
  <Step title="生成スケジュール">
    **生成頻度**を1時間、6時間、12時間、24時間、7日間のいずれかの間隔から選び、 **レポートのタイムゾーン**を選択します。**cron の詳細設定**では cron 式を入力できますが、現時点では24時間ごとに実行します。実行間隔を指定してください。
  </Step>
  <Step title="配信">
    **配信先**にメールアドレス、HTTPS Webhook URL、または S3 パスを追加します。配信結果は配信先ごとに記録します。**出力形式**を選択します。レポートを一時停止した状態で保存するには、 **保存後に有効化**をオフにします。
  </Step>
</Steps>

**保存して有効化**を選択します。**今すぐエクスポート**を選択すると、スケジュールを待たずにレポートを生成します。レポートで利用できる操作は、**表示**、**編集**、**共有**、**有効化**または**一時停止**、および**スケジュールを削除**です。

## 内容を選択する

レポートは、ダッシュボードまたは保存済みビューをソースとして使用します。テンプレートには、再利用できるソースタイプ、形式、内容のデフォルト設定を定義します。スケジュールはテンプレートを特定のリソースに関連付けます。

組み込みテンプレートには、プラットフォームの稼働状況、RUM によるユーザー体験、アラートのレビュー、SLA の遵守状況、保存済みクエリのエクスポートなどがあります。

## 形式を選択する

| 形式 | 主な用途 |
|---|---|
| PDF | ダッシュボードまたは保存済みビューのヘッドレスレンダリング。 |
| PNG | コラボレーションツール向けのヘッドレス画像レンダリング。 |
| CSV | 現時点では、静的なレポートのメタデータを表形式で出力します。 |
| JSON | 現時点では、自動化向けに静的なレポートのメタデータを出力します。 |
| SVG | 現時点では、静的なレポートのサマリーカードを出力します。 |

PDF と PNG にはヘッドレスレンダラーが必要です。 `[scheduled_reports.renderer]` にアクセス可能な Web ベース URL を設定します。サーバーは、生成したファイルのシグネチャを検証し、プレースホルダーの内容は返しません。CSV、JSON、SVG には現在、ダッシュボードや保存済みビューのクエリが返す行ではなく、レポートのメタデータが含まれます。

## PDF または PNG レポートの内容

PDF または PNG レポートには、ダッシュボードまたは保存済みビューが含まれます。周囲の Web UI は含まれません。ナビゲーション、ツールバー、メニューは表示しません。ページの先頭にレポートの対象を示し、その後にダッシュボードまたは保存済みビューの行を表示します。

- **ページサイズ。** ページの幅はレンダラーのビューポートに、高さはコンテンツに合わせます。そのため、PDF は基本的に1ページで、パネルやテーブルの行がページをまたいで分割されることはありません。高さが16,000 ピクセルを超える部分は、PNG では切り捨て、PDF では次のページに表示します。
- **外観。** レポートにはライトテーマを使用します。言語と日時の形式には、レンダリング時に使用するユーザーの設定を適用します。
- **時間範囲。** レポートは**データ期間**を対象とします。**過去24時間**と**過去7 日間**はレンダリング時点までを対象とします。**前日**、**先週**、 **先月**は、レポートのタイムゾーンでそれぞれ暦上の1日、1週間、1か月全体を対象とします。週は月曜日から始まります。
- **タイムゾーン。** ヘッダー、グラフの軸、`_timestamp` 列の時刻は **レポートのタイムゾーン**で表示します。このフィールドには、すべての IANA タイムゾーンを UTC オフセット付きで表示します。名前で検索して選択してください。
- **失敗時の動作。** ダッシュボードや保存済みビューを読み込めない場合、保存済みビューのクエリの実行に失敗した場合、またはページが15秒以内にデータを読み込み終えない場合は、ファイルを生成しません。 **今すぐエクスポート**では失敗の理由を返します。スケジュール実行では、受信者ごとの配信記録に理由を保存します。

### ダッシュボード

ページの先頭にダッシュボードのタイトルと説明を表示します。続いて、時間範囲、タイムゾーン、表示されている各変数の値、生成時刻を表示します。その後、ダッシュボードと同じレイアウトでパネルを表示します。データ期間が**カスタム**の場合、パネルには直近1時間のデータを表示します。

### 保存済みビュー

ページの先頭に保存済みビューの名前を表示します。続いて、時間範囲、タイムゾーン、ビューで指定している場合はストリーム、行数、生成時刻を表示します。その後、クエリ言語名の下にクエリ文を表示し、実行結果の行をテーブルに表示します。

- **時間範囲。** データ期間が**カスタム**の場合、保存済みビューの**デフォルトの時間範囲**を使い、レンダリング時点を終了時刻としてクエリを実行します。
- **行。** テーブルには最大200行を表示します。SQL 文の結果が200行を超える場合、行数の欄に **先頭200行のみ**と表示します。PromQL 文は範囲クエリとして実行し、200行に収まるように各系列のデータポイントを等間隔でサンプリングします。
- **列。** 結果の各列に対応する列をテーブルに表示します。テーブルはページ幅を超えず、長い値は折り返します。`_timestamp` 以外の値は、クエリが返したとおりに表示します。欠損値は `—` と表示します。
- **ストリーム。** SQL 文は、保存済みビューの**ストリーム**を使用して実行します。ストリームを指定していないビューでは、 **保存済みビュー**ページの**開く**と同じく、クエリを実行できる最初のログストリームを使用します。ワークスペースに該当するストリームがない場合、レポートの生成に失敗します。
- **結果が空の場合。** クエリが行を返さない場合もレポートを生成します。レポートには、指定した時間範囲に該当する行がないことを表示します。

## スケジュール設定と配信

データ範囲、`every:<n><s|m|h|d>` 形式の間隔、出力形式、 1 件以上の配信先を設定します。API フィールド名は `cron` ですが、5 フィールドの cron 式は解析しません。認識できない値を指定すると、現在は 24 時間間隔にフォールバックします。配信先の種類は次のとおりです。

- `webhook`：生成したバイト列を HTTP(S) URL に POST します。
- `s3`：MoleSignal で設定したオブジェクトストアの `reports/<organization id>/<path>/` 配下に `<report id>-<time>.<extension>` を書き込みます。`<path>` は `s3://` に続く配信先のパスです。
- `email`：現在はメールアドレスの検証と記録のみを行い、SMTP でメールを送信しません。

配信先ごとに、ステータス、試行回数、エラーの詳細を含む配信記録を保持します。設定を削除せずにスケジュールを一時停止できます。

<Warning>
  現在、`email` を配信先に指定してもメールは届きません。スケジュール済みレポートの SMTP 配信に対応するまでは、 Webhook または設定済みのオブジェクトストアのプレフィックスを使用してください。
</Warning>

### スケジュール済みレポートの実行権限

スケジュールに従って PDF または PNG を配信する際は、ログインした状態で最後にレポートを保存したユーザーの権限でレポートページをレンダリングします。レポートには、実行時にそのユーザーが読み取れる内容が表示されます。

- **実行ユーザーの確認場所。** **レポート**でレポートを開きます。ダイアログのフッターに**実行ユーザー**とユーザー名が表示されます。`reports.schedule` 権限がない場合も、**表示** からレポートを開くと同じ情報を確認できます。
- **保存。** 保存するたびに実行ユーザーが設定されます。スケジュールの有効化や一時停止だけを保存した場合も同様です。 `reports.schedule` 権限を持つユーザーがレポートを保存すると、そのユーザーが実行ユーザーになります。別のユーザーの権限でレポートを実行する設定の場合、 **変更を保存**の横に、保存後は保存したユーザーの権限でレポートを実行する旨が表示されます。 **スケジュール**一覧のスイッチにも同じ案内が表示されます。
- **API。** スケジュール済みレポートは、実行ユーザーの ID を `runAsUserId` として返し、表示名とメールアドレスを `runAsUser` として返します。実行ユーザーが設定されていないか、ユーザーアカウントが存在しない場合、`runAsUser` は `null` になります。
- **実行ごとのチェック。** 実行ユーザーが組織にログインできなくなると、実行は失敗します。これには、アカウントが無効化または削除された場合、組織のメンバーから外された場合、組織が無効化された場合が含まれます。ダッシュボードの読み取り権限（`dashboards.read`）や保存済みビューの読み取り権限（`saved_views.read`）を失った場合や、保存済みビューでストリームをクエリする権限（`streams.query`）を失った場合も、実行は失敗します。配信先ごとの配信記録に実行ユーザー名と失敗理由が記録されます。
- **API トークン。** API トークンには、発行したユーザーの権限ではなく、単一のロールの権限が適用されるため、 API トークンで保存したレポートには実行ユーザーが設定されません。ログインしたユーザーがレポートを保存するまでは、PDF と PNG の配信は失敗します。CSV、JSON、SVG の配信ではページをレンダリングしないため、実行ユーザーは不要です。
- **セッション。** ヘッドレスブラウザーが使用するセッションは 10 分間有効です。ページの印刷後にブラウザーからセッションを削除します。

**今すぐエクスポート**と**共有**では、リクエストしたユーザーの権限でレポートをレンダリングします。

## エクスポートと共有

**今すぐエクスポート**を使用して、保存済みレポートからダウンロード用ファイルを生成します。**共有**を使用して、認証が必要な共有、ワークスペース間の共有、またはアクセスを制限した公開共有を設定します。公開レポートにはパスワードを設定できます。また、ワークスペースポリシーで CSV のダウンロードを禁止できます。

## 権限

- `reports.read`：スケジュール、テンプレート、履歴を表示します。
- `reports.create`：レポートを作成します。
- `reports.edit`：レポートの内容と配信設定を更新します。
- `reports.schedule`：スケジュールを有効化、一時停止、または実行します。
- `reports.delete`：レポートを削除します。
