**RUM → パフォーマンス**では、ブラウザーアプリケーションのページが実際の利用時にどのようなパフォーマンスを示すかを確認できます。対象アプリケーションは一度に1つで、表示中の時間範囲について、1つの環境またはすべての環境を対象にできます。Core Web Vitals は [ブラウザー SDK](/ja/rum/browser-sdk) で計測します。それ以外の方法でデータを送信するアプリケーションには評価対象のページ読み込みがなく、その旨が画面に表示されます。

このタブには、**Web Vitals**、**リソース**、**ロングタスク**の3つのビューがあります。各ビューはアプリケーション、環境、時間範囲を共有します。ビュー間をリンクで移動しても、アプリケーションと環境の選択は保持されます。 [リソース](#リソース)までの各セクションでは、Web Vitals について説明します。

## Web Vitals の評価

概要には、ページビュー数と、LCP、INP、CLS の75パーセンタイル値が表示されます。各値は評価に応じた色で表示されます。その下には、3つの Web Vitals と、それらに先行する First Contentful Paint（FCP）および Time to First Byte（TTFB）の計5つの指標があります。指標を1つ選択すると、グラフ、評価、テーブルがその指標に切り替わります。選択した指標は URL の `vital` に記録されるため、表示内容を共有できます。

指標の評価には web.dev のしきい値を使います。しきい値はすべてのアプリケーションで共通です。

| 指標 | 良好 | 改善が必要 | 不良 |
|---|---|---|---|
| **LCP**（Largest Contentful Paint） | 2.5 s 以下 | 2.5 s～4 s | 4 s 超 |
| **INP**（Interaction to Next Paint） | 200 ms 以下 | 200 ms～500 ms | 500 ms 超 |
| **CLS**（Cumulative Layout Shift） | 0.1 以下 | 0.1～0.25 | 0.25 超 |
| **FCP**（First Contentful Paint） | 1.8 s 以下 | 1.8 s～3 s | 3 s 超 |
| **TTFB**（Time to First Byte） | 0.8 s 以下 | 0.8 s～1.8 s | 1.8 s 超 |

## 推移

選択中の指標の75パーセンタイル値を、表示中の時間範囲内の各区間について表示します。2本の破線は、「良好」と「改善が必要」の境界、および「改善が必要」と「不良」の境界を示します。グラフ上をドラッグして時間範囲を絞り込みます。

## 評価別のビュー

指標ごとに、計測値のあるビューを「良好」「改善が必要」「不良」に分けてバーで表示し、バーの末尾に「良好」の割合を示します。選択中の指標については、3段階それぞれの割合、ビュー数、評価のしきい値もテキストで表示します。割合は、しきい値以下の値を持つビューを実際に数えて算出し、推定は行いません。

## ページとその他のディメンション

テーブルには、選択したディメンションでビュー数の多い値が並びます。値ごとにビュー数、各指標の75パーセンタイル値を評価に応じた色で表示し、選択中の指標が「良好」だったビューの割合も表示します。

- **グループ化の基準**で、ページ（`view.url_path_group`）、ブラウザー、オペレーティングシステム、デバイス、国または地域、バージョンからディメンションを選択します。
- テーブルはビュー数が最も多い50件の値を取得します。列で並べ替える場合も、対象はその50件です。列見出しをクリックして並べ替え、もう一度クリックして順序を反転します。指標の列で並べ替えると、その指標が選択されます。
- ビュー数が30未満の値はグレーで表示します。少数のビューではページの速度を判断できないため、指標で並べ替えても末尾に表示します。
- 値に含まれる語句でテーブルを絞り込みます。ディメンション、並べ替え順、検索語句は URL に記録されます。

## ディメンション値の詳細

行をクリックすると、その値に該当するビューの詳細がドロワーに表示されます。URL にディメンション値と指標を記録するため、同じ URL からドロワーを再度開けます。**エクスプローラーで表示**をクリックすると、同じビューがエクスプローラーに表示されます。ヘッダーで LCP、INP、CLS を切り替えます。ページまたはバージョンの詳細で**この指標のアラートを作成**をクリックすると、開いているタブの指標を対象に、そのページまたはバージョンに絞り込んだルールエディターが開きます。この操作には `alerts.rules.manage` 権限が必要です。[RUM アラート](/ja/rum/alerts#ページからアラートを作成する)を参照してください。

- 最初の行に、この値における指標の評価と対象ビュー数を表示します。LCP と INP では、最も時間がかかった内訳項目も表示します。
- **所要時間の内訳**（LCP と INP）では、内訳項目ごとの所要時間を1本のバーで表示します。LCP の内訳は、最初のバイトを受信するまでの時間、画像の読み込みが始まるまでの遅延、画像の読み込み時間、画像が描画されるまでの遅延です。INP の内訳は、ハンドラーの実行開始までの遅延、ハンドラーの実行時間、次のフレームまでの待ち時間です。各項目は、そのディメンション値の 75パーセンタイル値の±10%以内にあるビューの平均です。そのため、各項目の合計は指標の値におおむね一致します。一部の項目だけをバーに表示するとその合計が指標の値に見えるため、ビューからすべての項目が報告されていない場合はバーを表示しません。CLS はスコアなので内訳はありません。
- **要素**には、最後に描画された要素（LCP）、操作の対象になった要素（INP）、または位置がずれた要素（CLS）を、その要素が計測対象になったビュー数と 75パーセンタイル値とともに表示します。LCP では、画像や動画のファイルも併記します。行をクリックすると、その要素が計測対象となったビューがエクスプローラーに表示されます。
- **推移**には、その値だけを対象に同じグラフを表示します。
- **パフォーマンスが最も悪いビュー**には、選択中の指標の値が最も高い5件のビューを表示します。各ビューをエクスプローラーで開くことができ、セッション全体も開けます。

<kbd>Esc</kbd> キーを押すか、ドロワーの外側をクリックして閉じます。

## リソース

**リソース**（`/rum/performance/resources`）では、ページが読み込むリソースを確認できます。概要には、ページが送信したリクエスト数、リクエストの所要時間の75パーセンタイル値、失敗数（エラーステータスまたは応答なし）、1ページビューあたりの平均リソース数と平均バイト数を表示します。

テーブルには、リクエストのグループをリクエスト数の多い順に表示します。各グループには、リクエスト数、所要時間とサイズの 75パーセンタイル値、失敗率、キャッシュから配信された割合を表示します。

- **グループ化の基準**で、ホストとリクエストの種類（デフォルト）、ホストとパス、種類、プロトコル、配信方法、レンダリングをブロックするかどうかのいずれかを選択します。
- **種類**と**ステータス**でリクエストを絞り込みます。ステータスは、クライアントエラー（400～499）、サーバーエラー（500 以上）、応答なしから選択できます。検索では、URL に検索語句が含まれるリクエストに絞り込みます。これらの絞り込みはテーブルとその横のパネルの両方に適用されます。
- テーブルはリクエスト数が最も多い100グループを取得します。列で並べ替える場合も、対象はその100グループです。リクエスト数が30未満のグループはグレーで表示し、リクエスト数以外で並べ替える場合は末尾に表示します。
- 失敗率は1%以上でオレンジ、5%以上で赤になります。配信方法が報告されていないリクエストでは、キャッシュから配信された割合をダッシュで表示します。

行をクリックすると、テーブルの横にパネルが開きます。URL にグループを記録するため、同じ URL からパネルを再度開けます。

- 最初の行に、所要時間の75パーセンタイル値、失敗したリクエスト数、最も時間がかかった内訳項目を表示します。
- **所要時間の推移**には、表示中の時間範囲内の各区間について、そのグループの所要時間の75パーセンタイル値を表示します。
- **リクエストの所要時間の内訳**では、75パーセンタイル値に近いリクエストの各工程の所要時間を1本のバーで表示します。内訳はリダイレクト、DNS、接続、TLS、最初のバイトを受信するまでの時間、ダウンロードです。各項目は、所要時間が75パーセンタイル値の ±10%以内にあるリクエストの平均です。
- **レスポンスステータス**には、グループ内のステータスコードを件数の多い順に表示します。各コードの割合は、結果が報告されたリクエストを母数として算出します。
- **最も遅いリクエスト**には、所要時間が最も長い3件のリクエストを表示します。各項目を開くと、リクエストを送信したビューの読み込み詳細が、該当のリクエストが選択された状態で表示されます。
- トレース ID を持つリクエストがある場合は、その件数を表示します。その行をクリックすると、グループ内のリクエストがエクスプローラーに表示されます。

## ロングタスク

**ロングタスク**（`/rum/performance/long-tasks`）では、各ページのメインスレッドをブロックする処理を確認できます。概要には、実行されたロングタスクの数、ロングタスクが1件以上発生したページビューの数、ロングタスクの実行時間と入力をブロックした時間の75パーセンタイルを表示します。

テーブルには、ロングタスクのグループを件数の多い順に表示します。グループごとに、ロングタスクの件数、発生したビューの数、実行時間と入力をブロックした時間の75パーセンタイルを表示します。時間は100 ms以上でオレンジ、200 ms以上で赤になります。

- **グループ化の基準**では、ロングタスクの発生元のスクリプトと関数（デフォルト）、ページ、バージョン、またはロングタスクのトリガーを選択します。検索では、アドレスに検索語を含むスクリプトのロングタスクに絞り込みます。
- 長いアニメーションフレームを報告するブラウザーは、そのフレーム内で実行したスクリプトも報告します。MoleSignalは、実行時間が最も長いスクリプトをロングタスクの発生元とみなします（[MoleSignalが追加する情報](/ja/rum/events#molesignal-が追加する情報)を参照）。SafariとFirefoxは、スクリプト情報なしでロングタスクを報告します。スクリプトを特定できるようになる前に受信したロングタスクにも、この情報はありません。これらは **発生元不明**のグループにまとめ、ほかのグループと同様に集計します。
- リソースと同様に、ロングタスクが30件未満のグループはグレーで表示し、ランキングの末尾に配置します。

行をクリックすると、グループ内のロングタスクのトリガー、発生したページ、実行時間が最も長い3件をパネルに表示します。上位3件のいずれかをクリックすると、そのタスクがブロックしたビューの読み込み詳細が開き、メインスレッド上で該当のタスクが選択されます。

## ビューの読み込み

ブラウザーのビューを開くと、エクスプローラーのドロワーに**読み込みウォーターフォール**が表示されます。ビューのフィールドは次のセクションで説明します。ドロワーは、エクスプローラーの行や、前述の最も遅いリクエスト、実行時間が最も長いロングタスクから開けます。

- 概要には、ページの読み込み時間、最初のバイトの受信時点、最大コンテンツの描画にかかった時間とその対象、ビュー内のリソースとロングタスクの件数を表示します。
- 時間軸はビューの開始時点からページの読み込み完了後までを示します。最初のバイトの受信、初回描画と最大コンテンツの描画、ドキュメントの準備完了、読み込み完了の各時点を線で示します。最大コンテンツの描画が待機したファイルには、その旨を表示します。
- **メインスレッド**には、同じ時間軸上にロングタスクを表示します。初回描画をブロックしたリクエストには、その旨を表示します。
- リクエストは開始順に1行ずつ表示します。バーはリクエストの開始から終了までを示し、最初のバイトを受信した時点で、受信前の待機時間と受信後のダウンロード時間に分かれます。最初の15件を表示し、残りは件数と大半のリクエストにかかった時間を示す行にまとめます。ページの読み込み完了後に開始したリクエストは、別の行に件数を表示します。 **種類**と**表示**（ブロッキング、低速（500 ms以上）、失敗）で行を絞り込めます。
- リクエストまたはメインスレッド上のロングタスクをクリックすると、右側のパネルに対象、終了時の状態、サイズ、配信方法、処理時間の内訳、関連付けられたトレースを表示します。最大コンテンツの描画が待機したファイルの場合は、読み込み開始までの待機時間、読み込み時間、描画までの待機時間も表示します。別のページから開いたリクエストがページの読み込み完了後に開始した場合は、時間軸に表示せず、詳細パネルにその旨を表示します。

モバイルアプリの画面には読み込むページがないため、ドロワーには画面のフィールドだけを表示します。

## 集計方法

Web Vitalsの各指標は、[`/api/v1/rum/aggregate`](/ja/api/rum#行の集計)で条件に一致する`rum_views`の行を集計して算出します。変更に伴って同じビューを再報告しても、最新のリビジョンだけを1回集計します。リソースの指標は `rum_resources`から、ロングタスクの指標は`rum_long_tasks`から算出します。ビューの割合には`rum_views`も使用します。集計が制限時間を超えたカードにはその旨を表示し、ほかのカードはそのまま表示します。時間範囲を絞って再確認してください。ビューの読み込み詳細には、ビューのIDと読み込み時間の範囲に一致するリクエストとロングタスクを取得します。

対象要素、内訳、指標値が最も悪いビューは、SDKが各指標とともに報告するアトリビューション情報に基づきます（[イベント形式](/ja/rum/events#ビュー)の`view.performance`のフィールドを参照）。ブラウザーが指標を計測しない場合、そのビューには該当の指標がありません。

このページを表示するには`rum.events.read`が必要です。[RUM](/ja/rum#権限)を参照してください。
