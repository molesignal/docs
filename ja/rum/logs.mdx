ブラウザー SDK は、ログを記録時のセッションとビューに関連付けます。ログからセッションリプレイを開き、セッションからページが出力したログを確認できます。ログを記録するか、コンソールの収集を有効にするまでは、何も送信しません。ログを利用するには、[ブラウザー SDK](/ja/rum/browser-sdk) 0.3.0 以降が必要です。

```ts
import { molesignalRum } from '@molesignal/browser-rum';

molesignalRum.logger.info('cart opened', { items: 3 });

const payments = molesignalRum.createLogger({ name: 'payments', level: 'warn', context: { provider: 'stripe' } });
payments.error('payment declined', { code: 402 }, error);
```

ロガーは、設定したレベルより低いログを記録しません。レベルには `debug`、`info`、`warn`、`error` を指定できます。第 3 引数にエラーを渡すと、ログにエラーの種類とスタックトレースを保持します。

ページのコンソール出力も転送するには、次のように設定します。

```ts
init({ /* … */ forwardConsoleLogs: ['warn', 'error'] }); // or 'all'
```

コンソールの出力はそのまま転送します。コンソールに個人データが含まれる可能性がある場合は、この機能を無効のままにするか、アプリケーションが[取り込み時に除去する内容](/ja/rum/privacy#受信時に機密テキストを除去する)を確認してください。この処理は、ログの本文とスタックトレースにも適用されます。

## ログの確認場所

- [セッションページ](/ja/rum/explorer#セッションを開く)では、リプレイの下にある **ログ** タブにログが時系列で並びます。再生位置に対応するログが強調表示され、行を選択すると、そのログの時点に移動します。
- [エクスプローラー](/ja/rum/explorer)では、**ログ** は行の種類の 1 つです。
- **ログ** では、`rum_logs` は `level` と `message` を持つ通常のログストリームです。レベル別ヒストグラムなどの機能は、他のログと同様に動作します。

アプリケーションが[保持しない](/ja/rum/sampling)セッションのログは残りません。ビューではログの件数を集計しません。

## SDK のエラー

SDK 自体で問題が発生すると（サーバーがイベントを拒否した場合や、`beforeSend` が例外をスローした場合など）、ロガー `molesignal-rum`、発生元 `sdk` のログを記録します。同じ問題は 1 回だけ記録し、ページの読み込み 1 回あたり数件に制限します。サーバーへの送信中に発生した問題は、ログもサーバーに届かないため、記録の対象外です。この機能を無効にするには、`trackSdkErrors: false` を設定してください。この設定にかかわらず、`onError` は呼び出されます。

## フィールド

| 列 | 説明 |
|---|---|
| `level` | `debug`、`info`、`warn`、`error` のいずれかです。 |
| `message` | ログのメッセージです。 |
| `log.id` | ログの ID です。 |
| `log.logger` | ロガー名です。コンソールの場合は `console`、SDK 自体の場合は `molesignal-rum` です。 |
| `log.origin` | `logger`、`console`、`report`、`sdk` のいずれかです。 |
| `log.error_type`, `log.stack` | ログが対象とするエラーの種類とスタックトレースです。 |
