MoleSignal Browser RUM SDK は、ページビュー、ユーザーインタラクション、フロントエンドエラー、Web Vitals、ネットワークリソース、ロングタスク、[ログ](/ja/rum/logs)、トレース相関コンテキストを収集し、[RUM イベント](/ja/rum/events)として送信します。

## 前提条件

- MoleSignal のデプロイ先 URL
- `checkout-web` などの [RUM アプリケーション](/ja/rum/applications)
- アプリケーションのクライアントトークン
- npm からインストールする場合は Node 24 以降

<Warning>
  `clientToken` はブラウザーで実行するコードに含まれ、ユーザーから見えます。オーナー、管理者、または個人のトークンは使用しないでください。アプリケーションに紐付けられたクライアントトークンを使用してください。すべてのトークンは `mspat-` で始まるため、 SDK はトークンの種類を判別できません。
</Warning>

## アプリケーションとトークンを取得する

**RUM → アプリケーション**を開き、**アプリケーションを作成**をクリックして、プラットフォームに**ブラウザー**を選択します。アプリケーション画面が開き、クライアントトークンが表示されます。**セットアップガイドを開く**を選択すると、エンドポイント、トークン、識別子が入力済みのコードスニペットが表示されます。 **データソース**の **Web RUM** にも同じガイドがあります。トークンは [API](/ja/api/auth/rum-token) からも取得できます。

## インストールと初期化

<Steps>
  <Step title="パッケージをインストールする">
    ```bash
    npm install @molesignal/browser-rum
    ```
  </Step>
  <Step title="SDK を一度だけ初期化する">
    ```ts
    import { init } from '@molesignal/browser-rum';

    const rum = init({
      applicationId: 'checkout-web',
      clientToken: 'mspat-your-client-token',
      site: 'https://molesignal.example.com',
      service: 'web-frontend',
      env: 'production',
      version: 'v1.4.0',
      sessionSampleRate: 100,
      trackUserInteractions: true,
    });
    ```

    `init` はクライアントを返します。`initRum` は同じ関数の旧名です。`molesignalRum` は同じ API をシングルトンとして提供します（`molesignalRum.init(...)` と `molesignalRum.setUser(...)`）。`init` の前に `molesignalRum` に対して行った呼び出しは保持され、 `init` が再実行します。

    最初のページビューを取得するため、アプリケーションのルーターがマウントされる前に SDK を初期化してください。サーバーサイドレンダリング中にパッケージをインポートして初期化しても問題ありません。ブラウザーの計測は、ブラウザー API が利用できる環境でのみ開始します。
  </Step>
  <Step title="最初のセッションを確認する">
    **RUM → エクスプローラー**を開き、現在時刻を含む時間範囲を選択します。セッションが表示されることを確認し、そのセッションを開いてビュー、リクエスト、エラーを確認します。
  </Step>
</Steps>

`site` には MoleSignal のオリジン、または `/api`、`/api/v1`、`/api/v1/rum` で終わる URL を指定できます。SDK はイベントを `POST /api/v1/rum/events` に、リプレイセグメントを `POST /api/v1/rum/replay` に送信します。SDK は `applicationId` を `application.id` として送信します。 MoleSignal は、`application.id` がトークンに紐付けられたアプリケーションと一致しないイベントを拒否します。

## script タグから読み込む

`dist/molesignal-rum.js` は、rrweb と web-vitals を含む自己完結型のバンドルです。このバンドルは、グローバル変数 `MoleSignalRum` を定義します。次のスニペットで非同期に読み込みます。`onReady` に渡したコールバックは、スクリプトの読み込みが完了してから実行されます。

```html
<script>
  (function (w, d, s, u, n) {
    w[n] = w[n] || { q: [], onReady: function (callback) { w[n].q.push(callback); } };
    var script = d.createElement(s);
    script.async = 1;
    script.src = u;
    d.head.appendChild(script);
  })(window, document, 'script', 'https://cdn.jsdelivr.net/npm/@molesignal/browser-rum@0.4.0/dist/molesignal-rum.js', 'MoleSignalRum');

  MoleSignalRum.onReady(function () {
    MoleSignalRum.init({
      applicationId: 'checkout-web',
      clientToken: 'mspat-your-client-token',
      site: 'https://molesignal.example.com',
      service: 'web-frontend',
      env: 'production',
      version: 'v1.4.0',
    });
  });
</script>
```

同期的に読み込むには、`<script src>` タグでファイルを指定し、その後に `MoleSignalRum.init(...)` を呼び出してください。

## ビューとセッション

ビューは、1 回のページビューまたは 1 つのルートに対応します。SDK はビューの開始直後に報告し、ビュー内で変更があると `view.revision` を増やして再度報告します（最短で 3 秒間隔）。ビューが開いている間は 5 分ごとに報告し、ビューの終了時にも最後に 1 回報告します。ビューは、ルートの変更時、セッションの終了時、ページが非表示になるかアンロードされたときに終了します。SDK は、 History API と `popstate` でルートの変更を検出します。ビューの名前と開始タイミングを指定するには、`trackViewsManually: true` を設定し、`startView` を呼び出してください。

SDK はセッションイベントを送信しません。MoleSignal はビューからセッションを特定します。SDK はセッションを Cookie `_msrum_s_<applicationId>` に保存するため、アプリケーションのすべてのタブで同じセッションを共有します。操作がない状態が 15 分続くか、開始から 4 時間が経過するとセッションは終了し、次のユーザー操作で新しいセッションが始まります。セッションごとに 1 回サンプリングを判定します。[データサンプリング](/ja/rum/sampling)を参照してください。サブドメイン間でセッションを共有するには、`trackSessionAcrossSubdomains: true` または `sessionCookieDomain: '.example.com'` を設定してください。 `stopSession()` はすべてのタブでセッションを終了します。Cookie を使用しない場合は、ページごとにセッションをメモリに保持します。

## ユーザーを識別してコンテキストを追加する

最初のセッションに正しいユーザー情報を含めるため、可能であれば初期化時にユーザー情報を指定してください。

```ts
const rum = init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  user: { id: currentUser.id, plan: currentUser.plan },
  globalContext: { region: 'eu-west-1' },
});

rum.setUser({ id: 'user-42', name: 'Ada', email: 'ada@example.com' });
rum.setUserProperty('plan', 'enterprise');
rum.setAccount({ id: 'acme' });
rum.setGlobalContextProperty('checkout_step', 'payment');
```

`setUser` には `id`、`name`、`email` のうち少なくとも 1 つが必要です。その他のキーはプロパティとして保持します。ユーザー情報を設定しない場合、SDK は `localStorage` に永続的な匿名識別子を作成します。プライバシーポリシーで匿名識別子の永続化が認められていない場合は、`trackAnonymousUser: false` を設定してください。セッターで設定したコンテキストは、それ以降のすべてのイベントに追加されます。グローバルコンテキスト、ビューコンテキスト、呼び出し時のコンテキストをこの順にマージし、キーが重複する場合は後の値を優先します。

## トラッキングへの同意

```ts
const rum = init({ /* … */ trackingConsent: 'not-granted' });

rum.setTrackingConsent('granted');
```

同意がない間、SDK は Cookie、匿名識別子、タブ識別子を作成せず、計測を設定せず、データも送信しません。同意を撤回すると、SDK は計測を停止し、SDK の識別子と永続キューを消去します。

## カスタムアクション、エラー、タイミング、Vitals を追加する

```ts
rum.addAction('Checkout submitted', { cart_size: 3 });

try {
  await submitOrder();
} catch (error) {
  rum.addError(error, { component: 'CheckoutForm' });
}

// Views: with trackViewsManually, or to name a route.
rum.startView({ name: 'Order confirmation', context: { step: 3 } });
rum.setViewName('Order confirmation (3DS)');

// Custom timings and feature flags belong to the current view.
rum.addTiming('cart_ready');
rum.addFeatureFlagEvaluation('new_checkout', true);

// Durations.
const vital = rum.startDurationVital('checkout_form_ready', { description: 'form is usable' });
rum.stopDurationVital(vital);

// The page is ready when the application says so: this replaces the loading time of the view.
rum.setViewLoadingTime();

// Logs.
rum.logger.warn('cart is stale', { age_ms: 90000 });

await rum.flush();
```

アプリケーション側で制御する画面遷移や終了の前に `rum.flush()` を呼び出し、キュー内のイベントの送信が完了するまで待機してください。`rum.stop()` を呼び出すと、計測を解除し、クライアントのキューを送信します。[アラートルール](/ja/rum/alerts#アプリケーションが計測する指標)では、カスタムタイミングと Vitals を監視できます。[機能フラグ](/ja/rum/feature-flags)については、専用ページを参照してください。[ログ](/ja/rum/logs)は `rum_logs` ストリームに送信されます。

## セッションリプレイへのリンクを取得する

`getSessionReplayLink()` は、サポートチケットやエラー報告に添付できる、MoleSignal 上の現在のセッションの URL を返します。SDK の起動前、セッションがサンプリング対象外の場合、または同意がない場合は `undefined` を返します。 URL は `appUrl` から生成されます。デフォルト値は `site` です。MoleSignal にアクセスする URL が SDK の送信先と異なる場合は、`appUrl` を設定してください。

```ts
ticket.replay = molesignalRum.getSessionReplayLink();
```

リンクを開くには、サインインと `rum.replay.read` 権限が必要です。

## React

`@molesignal/browser-rum/react` は、ルーターの各ルートを SDK のビューとして扱い、ルートパターンをビュー名に使用します（`/orders/42` ではなく `/orders/:id`）。コンポーネントツリーでスローされたエラーも報告します。React はオプションのピア依存関係です。

```tsx
import { init } from '@molesignal/browser-rum';
import { reactPlugin, RumErrorBoundary, trackReactRouter } from '@molesignal/browser-rum/react';

init({ /* … */ plugins: [reactPlugin()] });
trackReactRouter(router); // a router of createBrowserRouter; trackTanStackRouter for TanStack Router

root.render(
  <RumErrorBoundary fallback={<Oops />}>
    <RouterProvider router={router} />
  </RumErrorBoundary>,
);
```

## リモート設定

`remoteConfiguration: true` を設定すると、SDK は起動前に[アプリケーションの SDK 設定](/ja/rum/applications#sdk-のリモート設定)を読み込みます。これにより、ページを再リリースせずにサンプリングレートとプライバシーレベルを変更できます。

## 自動収集のデフォルト設定

| データ | オプション | デフォルト |
|---|---|---|
| ページビュー | `trackViewsManually` | History API による自動トラッキング（`false`） |
| Fetch、XHR、リソースタイミング | `trackResources` | `true` |
| 長時間アニメーションフレームとロングタスク | `trackLongTasks` | `true` |
| ビューの Web Vitals | `trackWebVitals` | `true` |
| クリック | `trackUserInteractions` | `false` |
| ビュー内でページをスクロールした深さ | `trackScroll` | `true` |
| レイジクリック、デッドクリック、エラークリック | `trackFrustrations` | インタラクショントラッキングと同じ |
| ランタイムエラー、未処理の Promise の拒否、失敗したリクエスト | 組み込み | 有効 |
| `console.error` | `trackConsoleErrors` | `false` |
| コンソール出力の[ログ](/ja/rum/logs) | `forwardConsoleLogs` | `[]` |
| SDK 内部エラーのログ | `trackSdkErrors` | `true` |
| リクエストとレスポンスのヘッダー | `trackResourceHeaders` | `[]` |
| 戻る・進むキャッシュからのページ復元 | `trackBfcacheViews` | `false` |
| DOM セッションリプレイ | `sessionReplaySampleRate` | `0` |

テストで生成されたセッションにはその旨が記録されます。[テストトラフィック](/ja/rum/test-traffic)を参照してください。クリックの処理中に発生したリソース、エラー、ロングタスクには、そのクリックの `action.id` が付き、そのアクションに集計されます。失敗したリクエストは、ソースが `network` のエラーとして記録され、該当するリクエストは `error.resource` に格納されます。FCP、LCP、FID はページの読み込みに関する指標で、 SDK は最初のビューに紐付けて報告します。`web-vitals` はページの読み込みごとに INP と CLS をそれぞれ 1 回測定します。SDK は、各指標の値を決めたインタラクションまたはレイアウトシフトが発生したビューに、その指標を紐付けて報告します。

## ブラウザーリクエストをトレースに関連付ける

トレースを許可した URL では、fetch と XMLHttpRequest のインテグレーションが既存の W3C `traceparent` を保持するか、新しい値を挿入します。その後、リクエスト、レスポンス、または `traceparent` という名前の `Server-Timing` エントリからトレースコンテキストを読み取ります。トレース ID とスパン ID は `resource.trace_id` と `resource.span_id` に書き込まれます。これにより、MoleSignal はブラウザーリクエストをバックエンドのトレースに関連付けます。デフォルトでは、同一オリジンのリクエストに限り、トレースコンテキストを挿入して読み取ります。クロスオリジン API の場合は、レスポンスヘッダーを公開し、オリジンを明示的に許可してください。

```http
Access-Control-Expose-Headers: traceparent, server-timing
```

```ts
allowedTracingUrls: [
  'https://api.example.com',
  /^https:\/\/edge-\w+\.example\.com\//,
]
```

## 設定

| オプション | デフォルト | 用途 |
|---|---|---|
| `applicationId` | 必須 | アプリケーションの識別子です。`application.id` として送信します |
| `clientToken` | 必須 | アプリケーションに紐づくクライアントトークン（`mspat-<36>`）です |
| `site` | 必須 | MoleSignal のオリジン、または `/api`、`/api/v1`、`/api/v1/rum` を含むベース URL です |
| `service` | `applicationId` | イベントの `service` です |
| `env`, `version` | 未設定 | デプロイのディメンションです。ソースマップの検索には `version` が必要です |
| `debugId` | 未設定 | ビルドのデバッグ ID です。エラーフレームの `debug_id` として送信します |
| `user`, `account`, `globalContext` | 未設定 | 初期の識別情報とカスタム属性です |
| `trackingConsent` | `granted` | すべてのトラッキングと識別子の作成を開始するか、保留するかを指定します |
| `sessionSampleRate` | `100` | 収集するセッションの割合です |
| `sessionReplaySampleRate` | `0` | 収集したセッションのうち、リプレイを記録する割合です |
| `sessionInactivityTimeout` | `900000` | セッションを終了するまでの無操作時間です。単位はミリ秒です |
| `maxSessionDuration` | `14400000` | セッションの最長継続時間です。単位はミリ秒です |
| `defaultPrivacyLevel` | `mask` | `mask`、`mask-user-input`、`allow` のいずれかを指定し、ページの表示内容や入力内容をどこまで送信するかを制御します。[プライバシー](/ja/rum/privacy)を参照してください |
| `trackUrlQueryString` | `false` | 報告する URL にクエリ文字列を残します |
| `excludedUrls` | `[]` | 収集対象から除外するリクエストの URL を、文字列、RegExp、またはコールバックで指定します |
| `allowedTracingUrls` | 同一オリジン | トレースコンテキストの挿入と読み取りの対象となるリクエストを指定します |
| `traceSampleRate` | `100` | リクエストが開始したトレースのうち、バックエンドに保持を要求する割合です（W3C の sampled フラグ）。それ以外のリクエストにもトレースコンテキストが残るため、リクエストとトレース ID の関連付けを維持できます |
| `trackResourceHeaders` | `[]` | 保持する fetch または XHR のヘッダーを名前または RegExp で指定します。認証情報は保持しません |
| `forwardConsoleLogs` | `[]` | ログにも出力するコンソールメソッドを指定します。`'all'`、または `debug`、`log`、`info`、`warn`、`error` から選択します |
| `trackSdkErrors` | `true` | SDK のエラーをアプリケーションログに記録します。記録はページの読み込みごとに数件までです |
| `trackScroll` | `true` | 各ビューでページのどこまでスクロールしたかを記録します |
| `compressIntakeRequests` | `false` | ブラウザーが対応している場合に、イベントの送信リクエストを Gzip で圧縮します |
| `remoteConfiguration` | `false` | SDK の起動前に[アプリケーションの設定](/ja/rum/applications#sdk-のリモート設定)を読み取ります |
| `appUrl` | `site` | ブラウザーで MoleSignal を開く URL です。`getSessionReplayLink` が使用します |
| `plugins` | `[]` | `reactPlugin()` など、SDK を拡張するプラグインを指定します |
| `enablePersistentQueue` | `true` | ページの再読み込み後に、IndexedDB から未送信のテレメトリを復元します |
| `flushInterval`, `batchSize` | `5000`, `50` | 送信間隔と、1 リクエストに含めるイベント数を指定します。1 バッチの上限は 100 件です |
| `maxQueueSize` | `1000` | オフライン時に保持するイベント数です |
| `beforeSend` | 未設定 | イベントを確認、変更、または破棄します |
| `onError` | 未設定 | アップロードの失敗やイベントの拒否など、SDK の診断情報を受け取ります |
| `transport` | ブラウザーの fetch | 独自のプロキシを経由して送信します |

`beforeSend(event, { kind })` は、[イベント形式](/ja/rum/events)に従うイベントオブジェクトを受け取ります。イベントを破棄するには `false` を返してください。 `view` イベントを破棄すると集計値が合わなくなるため、破棄できません。

## イベントの送信

SDK はイベントをキューに入れてバッチで送信し、サーバーが受け付けるまで IndexedDB に保持します。ネットワークエラー、`408`、`425`、`429`、または `5xx` が発生した場合は、指数バックオフでリクエストを再試行し、`Retry-After` が指定されている場合はそれに従います。MoleSignal が**拒否した**イベントは再試行せず、`onError` で報告します。それ以外の `4xx` ではバッチを破棄します。キューがいっぱいになると、まずリソースを破棄し、続いてロングタスク、リプレイ、バイタル、アクション、エラーの順に破棄します。ビューは最後に破棄します。ページを離れるときは、優先度の高いイベントから順に、1 回の `keepalive` リクエストで送信します。同じアプリケーションのタブはキューを共有し、同じイベントを重複して送信しません。

## 0.2 からのアップグレード

- `defaultPrivacyLevel: 'allow'` では、フィールドへの入力内容が表示されるようになりました。ただし、パスワード、メールアドレス、電話番号、カード情報、ワンタイムコードのフィールドは除きます。以前の `allow` と同じように入力内容をマスクし続けるには、`mask-user-input` に変更してください。
- コントロール以外の要素をクリックした場合も、クリックとして報告します。

## 0.1 からのアップグレード

0.2 では、SDK が RUM イベント形式に移行します。互換モードはありません。

- イベントは `POST /api/v1/rum/events` にのみ送信します。セッション、アクション、エラー用のエンドポイントは廃止しました。カスタムの `transport` 関数は `kind: 'events' | 'replay'` を受け取ります。
- SDK はセッションではなくビューを送信します。リソース、ロングタスク、ページビューはそれぞれ独立したイベントです。レイジクリックとデッドクリックは、クリックイベントの `action.frustration.type` で表します。
- `beforeSend` はイベント形式に従うイベントオブジェクトを受け取ります。`context.kind` はイベントの種類です。
- セッションはタブ間で共有する Cookie に保持します。無操作タイムアウトのデフォルトは 15 分です。
- サーバーは `User-Agent` からブラウザー、OS、デバイスを判定します。
- 先にアプリケーションを作成してください。トークンは既存のアプリケーションにのみ発行します。
