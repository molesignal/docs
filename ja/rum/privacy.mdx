機密値がネットワークに送信されないよう、ブラウザーでプライバシー制御を適用します。まずはデフォルトのマスクモードを使用し、記録結果を確認してから追加のコンテンツを許可してください。

## プライバシーを保護するデフォルト設定

```ts
init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  defaultPrivacyLevel: 'mask',
  trackUrlQueryString: false,
});
```

デフォルトでは、次のように処理します。

- URLのクエリ文字列とフラグメントを削除します。
- `password`、`secret`、`token`、`authorization`、`cookie`、`api_key` などのキーや、決済カード情報のフィールドを、ユーザー、アカウント、コンテキストのデータから再帰的に除去します。
- アクション名には `Click <structural selector>` を使用し、セレクターにはID、テストID、クラスを含めません。要素のテキストをアクション名に使用するのは、`defaultPrivacyLevel: 'allow'` の場合のみです。
- セッションリプレイではDOMのテキストをマスクします。
- `mask-user-input` と同様に、すべての入力フィールドと `contenteditable` 要素の値をマスクします。

<Warning>
  フィールド名に基づく除去は補助的な保護機能であり、データ分類の仕組みではありません。認証情報、決済データ、健康情報、不要な個人情報をユーザーオブジェクトやカスタムコンテキストオブジェクトに追加しないでください。
</Warning>

## DOMコンテンツをブロックまたはマスクする

SDKは、アプリケーション固有の記録コードを追加しなくても、プライバシー属性を認識します。

```html
<section data-molesignal-block>
  <!-- The entire subtree becomes a placeholder. -->
</section>

<span data-molesignal-mask>Account holder name</span>

<div data-molesignal-ignore>
  <!-- Mutations and events for this element are ignored. -->
</div>
```

必要に応じて、デフォルトのセレクターを置き換えてください。

```ts
sessionReplay: {
  blockSelector: '.payment-form, [data-private-panel]',
  maskTextSelector: '.customer-name, [data-molesignal-mask]',
  ignoreSelector: '.animation-layer, [data-molesignal-ignore]',
},
```

機密情報や大きな機密ウィジェットはブロックし、レイアウトが調査に役立つテキストはマスクします。調査に役立たずノイズになる要素は無視します。

## ページを表示し、入力内容を隠す

`defaultPrivacyLevel: 'mask-user-input'` は、ページのテキストを記録し、入力内容をマスクします。対象は入力フィールドと `contenteditable` 要素の値です。すべての利用者に同じテキストを表示するページに適しています。`maskTextSelector` に一致するテキストは引き続きマスクします。

`mask` モードでは、安全であることを確認済みのテキストに限り、領域を指定して表示できます。

```html
<nav data-molesignal-allow>Pricing · Docs · Sign in</nav>
```

`data-molesignal-allow` は、要素とその内部のテキストを表示します。内部でブロックまたは無視の対象になっている要素や、 `maskTextSelector` に一致するテキストには、引き続きそれぞれの設定を適用します。入力フィールドと `contenteditable` 要素も引き続きマスクします。

## ページのテキストの表示は慎重に許可する

すべての機密領域にマークを付けてから、`defaultPrivacyLevel: 'allow'` を設定してください。この設定では入力内容も表示しますが、パスワード、メールアドレス、電話番号、`autocomplete` がカード情報やワンタイムコードを示すフィールド、および `data-molesignal-mask` 内のフィールドは除きます。`maskTextSelector` に一致するテキストは引き続きマスクします。

```ts
defaultPrivacyLevel: 'allow',
sessionReplay: {
  blockSelector: '[data-molesignal-block], .payment-details',
  maskTextSelector: '[data-molesignal-mask], .customer-identity',
},
```

## URLとネットワークデータの収集を制御する

アプリケーションがクエリ文字列に識別子や機密情報が含まれないことを保証できない限り、 `trackUrlQueryString: false` のままにします。機密性の高いルートやネットワークエンドポイントは、収集前に除外してください。

```ts
excludedUrls: [
  '/account/security',
  /^https:\/\/api\.example\.com\/private\//,
  (url) => url.includes('/token-exchange'),
],
```

`allowedTracingUrls` は、トレースコンテキストを提供できるオリジンを制御します。このオプションでリクエストやレスポンスのボディのキャプチャが有効になることはありません。SDKはタイミング情報とサニタイズ済みのURLメタデータを記録します。

## 受信時に機密テキストを除去する

SDKが最初の防御を、サーバーが二段目の防御を担います。送信元のSDKやクライアントにかかわらず、アプリケーションは設定で指定した種類の機密テキストをすべてのイベントから保存前に除去します。 **RUM → アプリケーション**で対象のアプリケーションを開き、**機密データ**の種類ごとにオンまたはオフにします。新規アプリケーションでは、すべての種類がオンです。

| 種類 | 除去する内容 | 置換後の値 |
|---|---|---|
| **トークン、キー、パスワード** | BearerおよびBasicトークン、JWT、クラウドサービスや開発サービスのキー（AWSアクセスキー、GitHub、GitLab、Slack、Stripe、OpenAI、Google、npmのトークン）、秘密鍵、`password=`、`secret:`、`api_key=`、`authorization:` などに続く値、および `Authorization`、`Cookie`、`Set-Cookie`、`Proxy-Authorization`、`X-API-Key`、`X-Auth-Token`、`X-CSRF-Token` ヘッダーの値です。 | `[secret]` |
| **メールアドレス** | `jane@example.com` などのメールアドレスです。 | `[email]` |
| **電話番号** | `+` で始まる8〜15桁の国際電話番号、中国の11桁の携帯電話番号、`(415) 555-2671` などの北米の電話番号です。 | `[phone]` |
| **決済カード番号** | 桁のグループをスペースまたはダッシュで区切った13〜19桁の番号で、先頭の数字が決済カードネットワークの規則に一致し、チェックディジットの検証を通過するものです。 | `[card]` |
| **個人識別番号** | チェック文字の検証を通過する中国の住民身分証番号、および米国の社会保障番号です。 | `[id]` |
| **機密情報を含むURLパラメーター** | 名前が `code`、`key`、`sig`、`sid`、`otp`、`ticket`、`email`、`phone` などであるか、名前に `token`、`secret`、`password`、`auth`、`signature`、`api_key`、`credential`、`jwt`、`session` を含むクエリパラメーターやフラグメントパラメーターの値です。ホストの前にあるユーザー名とパスワードも除去します。パラメーター名は保持します。 | `[redacted]` |

除去の対象は、イベントの発生先や参照元のアドレス（`view.url`、`view.referrer`、`resource.url`、エラーの発生先アドレス）、エラーとその原因のメッセージおよびスタック、ビュー名とクリック対象の名前、リクエストのGraphQLオペレーション、ペイロード、変数、リクエストとレスポンスのヘッダー、および `context` オブジェクトです。テキスト内のアドレスも、アドレスとしてサニタイズします。スタック内でアドレスに続く位置情報（`:10:5`）は保持します。`user` と `account` は、アプリケーションが送信することを選んだ個人に関する情報です。これらは変更しません。

イベントを行に変換する前に機密テキストを除去するため、派生データの生成には除去後の内容を使います。たとえば、メールアドレスを含んでいたアドレスの `view.url_path` と `view.url_path_group` や、エラーが属する[イシュー](/ja/rum/errors)が該当します。メッセージ内のメールアドレスや番号だけが異なるエラーは、1つのイシューにまとめます。

<Warning>
  各種類の判定にはパターンと検証ルールを使います。データの分類は行いません。たとえば、`13` で始まる11桁の注文番号は、電話番号に似ているため電話番号として除去します。一方、自由記述欄に入力した氏名や住所は検出しません。調査に必要な情報まで除去する場合は該当する種類をオフにし、SDK側で機密値がイベントに含まれないようにしてください。
</Warning>

設定の変更は、変更後に受信するイベントに適用します。保存済みのデータは変更しません。セッションリプレイのセグメントには受信時の除去処理を適用しません。SDKが、上記のプライバシーレベルに従ってセグメント内のテキストをマスクします。

## 本番環境に適用する前に確認する

<Steps>
  <Step title="管理されたテストセッションを記録する">
    本番データに含まれないテストデータを使い、サインイン、購入手続き、プロフィール、検索、エラーの各フローをテストします。
  </Step>
  <Step title="イベントの各記録項目を確認する">
    セッションのメタデータ、アクション名、URL、エラースタック、カスタムコンテキスト、DOMリプレイを確認します。
  </Step>
  <Step title="セレクターと除外ルールを追加する">
    機密情報を含むサブツリーをブロックし、収集が不要なルートを除外します。
  </Step>
  <Step title="UIの変更後に再テストする">
    プライバシー用のセレクターを本番設定として扱い、マークアップの変更後にセレクターの動作をテストします。
  </Step>
</Steps>
