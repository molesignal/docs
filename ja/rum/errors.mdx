**RUM → エラー**では、アプリケーションのエラーをイシューとして一覧表示します。イシューは、類似するエラーをひとまとめにしたものです。イシューには、状態、チーム、担当者、検出日時と検出されたバージョンの記録があります。すべてのエラーは、`error.issue_id` にイシュー ID を格納した状態で `rum_errors` ストリームに残るため、[エクスプローラー](/ja/rum/explorer)やクエリでエラーとイシュー ID の両方を参照できます。

## エラーをイシューにまとめる仕組み

サーバーはエラーを受信すると、そのエラーが属するイシューを特定します。イシュー ID は、以下の情報から算出するハッシュです。

- アプリケーションと `error.source`
- エラーのタイプとカテゴリ、およびエラーごとに変わる部分を取り除いたメッセージ
- アプリケーション独自のコードの先頭 3 フレーム。リリースのソースマップ、マッピングファイル、またはシンボルファイルをアップロード済みの場合は、それらを使って復元したフレームを使用します（[ソースマップとシンボル](/ja/rum/source-maps)を参照）
- リクエストが失敗した場合は、メソッド、パス、ステータスコード

メッセージからは、数値、UUID、16 進数で 8 桁以上のハッシュ、メールアドレス、Web アドレスのクエリ文字列やフラグメントを取り除きます。そのため、`Loading chunk 482 failed.` と `Loading chunk 17 failed.` は同じイシューになります。パッケージ、フレームワーク、ランタイムのフレームはアプリケーション独自のコードではありません。アプリケーション独自のフレームがある場合は、これらのフレームをグループ化に使用しません。

別の方法でエラーをグループ化するには、`error.fingerprint`（最大 128 文字）を送信してください。同じアプリケーションで同じフィンガープリントを指定したエラーは、メッセージやスタックにかかわらず、同じイシューにまとまります。SDK はこのフィールドを設定しないため、エラーを報告する呼び出しで指定してください。

<Note>
  ID の生成ルールはバージョン管理されます。グループ化の方法を変更すると新しい ID が生成されますが、既存のイシューは再グループ化しません。イシューの記録を開始する前に受信したエラーには `error.issue_id` がなく、一覧には表示されません。リリースのソースマップをアップロードする前に受信したエラーはオリジナルのフレームで、アップロード後に受信したエラーは復元したフレームでグループ化します。そのため、同じ問題が 2 つのイシューになることがあります。既存のイシューは統合しません。
</Note>

## イシューの一覧

一覧には、選択したアプリケーションと環境で、指定した期間内にエラーが発生したイシューが表示されます。各行には次の情報が表示されます。

| 列 | 表示内容 |
|---|---|
| **イシュー** | 最初のエラーのタイプとメッセージ、およびアプリケーション独自のコードの先頭フレームです。 |
| **状態** | イシューの対応状況です。[状態](#状態)を参照してください。 |
| **担当者** | イシューの担当者です。担当者がいない場合はチームを表示します。 |
| **セッション** | 指定した期間内にイシューが発生したセッション数です。 |
| **ユーザー** | イシューの影響を受けたユーザー数です。ユーザー ID がない訪問者は、SDK の匿名 ID でカウントします。 |
| **推移** | 指定した期間を 12 等分した各区間の発生回数です。 |
| **バージョン** | イシューを最初に検出したバージョンと、検出した中で最新のバージョンです。 |
| **最終検出** | 全期間を通じて最後にイシューを検出した日時です。 |

デフォルトでは、**未解決**のイシュー（「開く」、「調査中」、「再発」）が表示されます。フィルターで別の状態や **すべての問題**を選択できます。タイプ、メッセージ、発生箇所に含まれる語句や、担当者で絞り込めます。複数の種類のクライアントからエラーを受信した場合は、ソースでも絞り込めます。**状態**、**セッション**、**ユーザー**、**最終検出**をクリックすると並べ替えられ、同じ列をもう一度クリックすると順序が逆になります。ページの表示状態は URL に反映されるため、そのまま共有できます。

一覧では、選択した並べ替え順に応じて、セッション数、ユーザー数、または発生回数が多い上位 250 件のイシューを取得してから、フィルターを適用します。上位 250 件に入らないイシューは、フィルターの対象外です。表示するイシューは最大 100 件です。

一覧の上にある**発生環境**では、一覧のイシューが発生したセッションの分布を、バージョン、ページ、ブラウザー別に表示します。値をクリックすると、その条件で発生したエラーに一覧を絞り込みます。すべての列に絞り込みが反映されます。同じ値をもう一度クリックすると、絞り込みを解除します。

## イシューの詳細

行をクリックすると、イシューの詳細がドロワーに開きます。URL にイシューの情報が含まれるため、その URL にアクセスすると同じドロワーが開きます。

- ヘッダーで状態、チーム、担当者を設定できます。**エクスプローラーで表示**をクリックすると、そのイシューのエラーがエクスプローラーに表示されます。
- 概要欄には、状態、指定した期間内に影響を受けたセッション数とユーザー数、初回検出日時と最終検出日時、およびバージョンが表示されます。
- **推移**では、直近 14 日間のセッション数を日別に表示し、バージョンごとに積み上げます。破線はイシューを解決した日を示します。
- **発生環境**では、このイシューが発生したセッションの分布をブラウザー、システム、国別に表示します。
- **発生箇所**には、スタックを持つ最新のエラーのフレームが表示されます。アプリケーション独自のフレームは太字で、ライブラリのフレームは薄く表示します。デバッグアーティファクトでフレームを復元した場合は、**復元済み**と**オリジナル**を切り替えられます。
- **最新のセッション**には、イシューが発生した直近 3 件のセッションと、各セッションのリプレイとタイムラインへのリンクが表示されます。 **影響を受けたユーザー**には、発生回数が最も多いユーザーが表示されます。セッションを保持していない場合もエラーは保持し、セッションへのリンクの代わりに *セッション未保持* と表示します。[RUM データのサンプリング](/ja/rum/sampling#すべてのエラーを保持)を参照してください。

イシューの一覧に表示するタイプ、メッセージ、発生箇所は、最初のエラーを受信したときの値を、書き込み時のマスキングルールを適用した状態で保持します。

## 状態

| 状態 | 意味 | 設定元 |
|---|---|---|
| **開く** | まだ誰も確認していません。新規イシューの初期状態です。 | サーバーまたはユーザー |
| **調査中** | 調査を進めています。 | ユーザー |
| **再発** | 解決後、新しいバージョンで再び発生しました。 | サーバーのみ |
| **解決済み** | 原因を修正しました。 | ユーザー |
| **無視** | 対応は不要です。 | ユーザー |

「開く」、「調査中」、「再発」のイシューは未解決です。

### 再発

イシューを解決すると、解決日時、解決したユーザー、その時点でのアプリケーションの最新バージョンを記録します。バージョンの順序は、バージョン名にかかわらず、各バージョンの初回検出日時で決まります。解決済みのイシューは、解決時に記録したバージョンより初回検出日時が後のバージョンでエラーが発生した場合にのみ、**再発**になります。アップデートしていないユーザーには古いバージョンで引き続きエラーが発生しますが、同じか古いバージョンでエラーが発生しても、イシューは再発になりません。

バージョンを送信しないアプリケーションでは、バージョンの順序を判定できないため、解決後にエラーが発生するとイシューは再発になります。ただし、解決時にバージョンを記録したイシューは、バージョン情報のないエラーでは再発になりません。

再発したイシューの状態を変更すると、再発状態が終了します。再度解決すると、その時点での最新バージョンを記録します。

イシューは、すべての環境を含むアプリケーション全体に属します。サーバーは、再発のきっかけとなったエラーの環境と、各環境でイシューを初めて検出した日時を記録します。[アラートルール](/ja/rum/alerts)は、この情報を使って環境ごとに新規イシューと再発したイシューをカウントします。

エラーを受信するサーバー側の処理はイシューの情報を最大 1 分間キャッシュするため、ユーザーが設定した状態は 1 分以内に反映されます。古い状態をキャッシュしている間に新しいバージョンのエラーを受信しても、イシューは再発になりません。1 分経過した後、次のエラーを受信すると再発になります。

## 1 時間あたりの新規イシュー数の上限

アプリケーションが 1 時間に作成する新規イシューの数は、**1 時間あたりの新規イシュー数の上限**で制限します。デフォルトは 100 件です。上限に達した後は、その時間内に受信したエラーのうち、まだイシューに属していないものを **その他のエラー**という 1 件のイシューにまとめてカウントします。これにより、毎回異なるメッセージを送信するアプリケーションのエラーで一覧が埋まるのを防ぎます。上限を変更するには、**RUM → アプリケーション**で対象のアプリケーションを開き、**イシュー** セクションで 1～10,000 の範囲で設定してください。変更は 30 秒以内に反映されます。

## 権限

- `rum.issues.read` があると、イシュー一覧と各イシューの詳細を表示できます。
- `rum.issues.manage` があると、ステータス、担当チーム、担当者を設定できます。オーナー、管理者、編集者にはこの権限があります。この権限がない場合、設定項目は現在の値を表示するだけで、変更はできません。

エンドポイントについては、[RUM API](/ja/api/rum#イシュー)を参照してください。
