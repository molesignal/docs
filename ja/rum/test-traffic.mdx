セッションのタイプは `user`、`synthetics`、`ci_test` のいずれかです。ブラウザーの[合成チェック](/ja/synthetics)で、[ブラウザー SDK](/ja/rum/browser-sdk) 0.3.0 以降を実行するページを開くと、`synthetics` タイプのセッションが作成されます。設定は不要です。セッションのイベントでは、チェック、実行、ロケーションをそれぞれ `synthetics.test_id`、`synthetics.result_id`（実行結果の `task_id`）、`synthetics.location_id` に記録します。

## 集計への影響

アプリケーションの指標は実際のユーザーの操作を反映するため、テストによるセッションを次の対象から除外します。

- 概要、パフォーマンス、フラストレーション、エラー、分析、ヒートマップ、機能フラグの各ページと、組み込みダッシュボード
- [RUM 指標のアラートルール](/ja/rum/alerts)
- エクスプローラーの一覧と、Mole Agent の RUM ツール

テストセッションのエラーからは[イシュー](/ja/rum/errors)を作成しないため、チェックが失敗しても新規イシューとしてカウントしません。除外したセッションがあるページには **N 件のテストセッションを除外** と表示され、そのリンクから該当するセッションを確認できます。

テストセッションはサンプリングの対象にもなりません。アプリケーションの[保持設定](/ja/rum/sampling)では、セッション全体を保持します。アプリケーションのフィルターに `session.type` を指定すると、テストセッションにも他のセッションと同じようにフィルターと保持割合を適用します。SDK は `sessionSampleRate` の値にかかわらず、テストセッションを保持します。

## テストセッションを見つける

- 実行から確認する場合: ブラウザーチェックの結果で該当する試行を開き、**この実行の RUM セッションを開く** を選択します。
- セッションから確認する場合: セッションページにはセッションのタイプが表示され、リンクからチェック結果を確認できます。
- エクスプローラーで確認する場合: `session.type`、`synthetics.*`、`ci_test.*` のいずれかを指定するクエリや、単一の `session.id` を指定するクエリは、指定どおりに評価します。たとえば、`session.type = 'synthetics'` で合成チェックのセッションを検索できます。これらの指定がない場合、エクスプローラーには実際のユーザーの操作が表示されます。`session.type` の値の一覧には、すべてのセッションタイプが含まれます。
- API で確認する場合: `search`、`aggregate`、`facets`、`histogram` のフィルターにも同じルールを適用します。

## アプリケーションのテスト

ページ内のどのスクリプトよりも先に、同じグローバル変数を設定します。Playwright では次のように設定します。

```ts
await page.addInitScript((id) => {
  window.__MOLESIGNAL_TEST_CONTEXT__ = { type: 'ci_test', test_execution_id: id };
}, process.env.GITHUB_RUN_ID);
```

SDK は、記録したセッションの ID を `window.__MOLESIGNAL_RUM_SESSION__` に設定します。チェックはこの値を読み取ってセッションにリンクし、一連の操作が終わったらページを離れます。これにより、SDK が保持しているデータを送信します。

<Note>
セッションの実行元を記録するには、ページで 0.2.0 より新しいブラウザー SDK を実行する必要があります。SDK のリクエストにも、他のリクエストと同じようにチェックのエグレスポリシーが適用されます。ポリシーで MoleSignal への通信を許可していない場合、チェックは失敗します。
</Note>
