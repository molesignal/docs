セッションリプレイでは、ブラウザーの DOM の完全なスナップショットを記録し、その後の差分をタイムスタンプ付きで記録します。 MoleSignal は、サンドボックス内の操作不可のプレーヤーで、記録したイベントからセッションを再現します。

リプレイはデフォルトで無効です。

## サンプリングによるリプレイを有効にする

```ts
const rum = init({
  applicationId: 'checkout-web',
  clientToken: 'mspat-your-client-token',
  site: 'https://molesignal.example.com',
  sessionSampleRate: 100,
  sessionReplaySampleRate: 20,
  sessionReplay: {
    blockSelector: '[data-molesignal-block]',
    maskTextSelector: '[data-molesignal-mask]',
    ignoreSelector: '[data-molesignal-ignore]',
  },
});
```

`sessionReplaySampleRate` は、`sessionSampleRate` でサンプリングされたセッションにのみ適用されます。実効サンプリング率の計算方法は、[RUM データのサンプリング](/ja/rum/sampling)を参照してください。

## 記録を手動で開始または停止する

```ts
rum.startSessionReplayRecording();

// Stop before a sensitive workflow that should never be recorded.
rum.stopSessionReplayRecording();
```

記録を手動で開始できるのは、`sessionSampleRate` でサンプリング済みのセッションだけです。記録を開始すると、リプレイでセッションを再現できるように、新しい完全な DOM スナップショットを作成します。

## 記録するイベント

レコーダーは次の情報を記録します。

- 完全な DOM スナップショットと DOM の差分
- ポインターの移動とクリック
- スクロールとビューポートの変更
- 入力操作（入力値はマスク）
- スタイルシートの状態とアクセス可能なインラインスタイル
- rrweb がサポートするメディアの状態

デフォルトでは、5分ごとに完全なスナップショットを記録します。`checkoutInterval` には、 30秒から30分までの値を設定してください。

```ts
sessionReplay: {
  checkoutInterval: 5 * 60_000,
},
```

## プライバシー設定

デフォルトの `defaultPrivacyLevel: 'mask'` では、ページ内のすべてのテキストと入力内容をマスクします。`mask-user-input` ではページ内のテキストを表示し、入力内容をマスクします。`allow` では入力内容も表示しますが、パスワード、メールアドレス、電話番号、カード情報、ワンタイムコードのフィールドはマスクします。本番環境でリプレイを有効にする前に、ブロック、マスク、無視の各セレクターを定義してください。

```html
<div data-molesignal-block>Payment details</div>
<span data-molesignal-mask>Customer name</span>
<canvas data-molesignal-ignore></canvas>
```

セレクターの動作と本番導入前のチェックリストについては、[RUM のプライバシー](/ja/rum/privacy)を参照してください。

## データ量が多いオプションの記録

次のオプションを有効にすると、ペイロードのサイズとストレージ使用量が大幅に増える可能性があるため、デフォルトでは無効です。

```ts
sessionReplay: {
  collectFonts: false,
  inlineImages: false,
  recordCrossOriginIframes: false,
},
```

クロスオリジンのフレームを記録するには、フレーム内のアプリケーション側での対応も必要です。MoleSignal のプレーヤーは Canvas のピクセルを再現しません。Canvas を多用するコンテンツには、DOM での表現やプレースホルダーを使用してください。

## 送信と保持

リプレイは専用のキューを使用します。デフォルトでは10秒間隔でフラッシュし、1バッチあたり100件のイベントを送信します。 `replayFlushInterval` と `replayBatchSize` でクライアントの動作を調整してください。MoleSignal はリプレイのセグメントを圧縮してオブジェクトストレージに保存し、プラットフォームのデフォルトのストリーム保持期間が過ぎると、保存したセグメントを削除します。この保持期間は **設定 → データ保持** で設定します。

## コメント

リプレイの横にある **コメント** タブでは、リプレイの特定の時点にコメントを追加できます。コメントは追加時の再生位置に紐づき、プレーヤーのタイムラインに表示されます。コメントの行をクリックすると、その時点に移動します。

リプレイを再生できる場合は、コメントも閲覧できます。`rum.replay.comments.write` でコメントを投稿し、自分のコメントを編集または削除できます。 `rum.replay.comments.manage` では、すべてのコメントを編集または削除できます。1セッションにつき最大500件、各コメントは最大2,000文字です。保持期間が終了すると、リプレイと一緒にコメントを削除します。

## AI による要約とチャプター

セッションページの **要約する** をクリックすると、モデルがセッションの内容を数文で要約し、タイトルと開始位置を付けたリプレイのチャプターを生成します。チャプターはプレーヤーのタイムラインに表示され、クリックするとその開始位置に移動します。

モデルには、閲覧したページ、ページ上での操作、発生した問題、失敗したリクエストや時間がかかったリクエストを、古い順に1行ずつ渡します。リプレイそのものは渡しません。テキストは、アプリケーションが[取り込み時に機密テキストを除去する処理](/ja/rum/privacy#受信時に機密テキストを除去する)を経たうえで、閲覧権限の範囲に絞り込みます。長いセッションでは、閲覧したページと発生した問題を優先し、残りの情報は入力上限に収まる範囲で渡します。

要約はリクエストしたときだけ生成します。生成には `rum.replay.summaries.generate` が必要です。リプレイを再生できる場合は、要約も閲覧できます。API キーが設定された有効な[モデルプロバイダー](/ja/agent#モデルプロバイダーを設定する)のうち、最初のプロバイダーのデフォルトモデルを使用します。利用分は `replay_summary` を発生元として、[Mole Agent の1日あたりの予算](/ja/agent#使用状況と予算)に計上します。要約は言語ごとに1件保持し、リプレイと一緒に削除します。セッションに変更がない場合、**再要約する** をクリックしてもモデルは呼び出しません。

## リプレイを確認する

<Steps>
  <Step title="機密情報を含まないテスト操作を記録する">
    複数のページを移動し、コントロールのクリックとスクロールを行い、DOM を1回更新してください。
  </Step>
  <Step title="セッションを開く">
    **RUM → エクスプローラー** に移動し、**セッション** で `session.has_replay = true` を検索して、新しく記録したセッションを開いてください。
  </Step>
  <Step title="再現とマスキングを確認する">
    ページ構造、イベントのタイミング、再生位置の操作、ブロックされた領域、マスクされた値を確認してください。
  </Step>
  <Step title="セッションページの表示を確認する">
    MoleSignal が有効な完全な DOM スナップショットを受信すると、セッションページにリプレイが表示されます。それまでは、アクションのタイムラインが表示されます。
  </Step>
</Steps>
