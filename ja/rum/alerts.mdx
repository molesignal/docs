[アラートルール](/ja/alerting)では、クエリの代わりに **RUM 指標**を監視できます。ルールではアプリケーションを指定し、必要に応じて環境、ページ、バージョンで絞り込んで、以下の指標から 1 つを選びます。スケジュールに従って、しきい値または過去数日の同じ時刻の値と比較します。ストリームやステートメントは不要です。

指標の算出には、各ページと同じ集計を使います。 [概要](/ja/rum)や[エクスプローラー](/ja/rum/explorer)と同様に、ビューやセッションは最新のリビジョンで 1 回だけカウントし、パーセンタイルは値があるビューのみを対象に計算します。そのため、アプリケーション、環境、ページ、時間範囲が同じなら、ルールが監視する値と各ページに表示される値は一致します。

## 指標一覧

| 指標 | `metric` | 説明 | 単位 | 必要な行数 |
|---|---|---|---|---|
| **セッション** | `session_count` | 評価期間内に開始したセッションです。 | 件数 | なし |
| **ページビュー数** | `view_count` | 評価期間内に開始したページビューまたはアプリの画面ビューです。 | 件数 | なし |
| **エラー** | `error_count` | 評価期間内に発生したエラーです。 | 件数 | なし |
| **エラー率（エラーが発生したビューの割合）** | `error_rate` | 全ビューのうち、エラーが発生したビューの割合です。 | % | 100 ビュー |
| **クラッシュのないセッション** | `crash_free_sessions` | 全セッションのうち、クラッシュが発生しなかったセッションの割合です。 | % | 100 セッション |
| **フラストレーションが検出されたセッション** | `frustration_rate` | 全セッションのうち、[フラストレーションの兆候](/ja/rum/frustration)が見られたセッションの割合です。 | % | 100 セッション |
| **失敗したリクエスト** | `failed_request_rate` | すべての `fetch` および `xhr` リクエストのうち、応答がなかったか、5xx が返ったリクエストの割合です。4xx は失敗に含めません。 | % | 200 リクエスト |
| **LCP (p75)** | `lcp_p75` | Largest Contentful Paint の 75 パーセンタイルです。 | ミリ秒 | 値がある 50 ビュー |
| **INP (p75)** | `inp_p75` | Interaction to Next Paint の 75 パーセンタイルです。 | ミリ秒 | 値がある 50 ビュー |
| **CLS (p75)** | `cls_p75` | Cumulative Layout Shift の 75 パーセンタイルです。 | スコア（0.1 は良好） | 値がある 50 ビュー |
| **最初のバイトを受信するまでの時間 (p75)** | `ttfb_p75` | 最初のバイトを受信するまでの時間の 75 パーセンタイルです。 | ミリ秒 | 値がある 50 ビュー |
| **新規イシュー** | `new_issues` | 評価期間内に初めて検出された[イシュー](/ja/rum/errors)です。 | 件数 | なし |
| **再発したイシュー** | `regressed_issues` | 解決後、評価期間内に再発したイシューです。 | 件数 | なし |
| **影響が最も大きいイシューの影響を受けたセッション** | `issue_impact` | 評価期間内に最も多くのセッションに影響したイシューについて、影響を受けたセッション数を集計します。イシューの種類や初回検出時期は問いません。 | 件数 | なし |
| **カスタム所要時間（バイタル）** | `custom_vital` | アプリケーションが `startDurationVital` または `addDurationVital` で計測する所要時間を名前で指定します。 | ミリ秒または件数 | 30 行。統計量が **件数**の場合は不要 |
| **カスタムタイミング** | `custom_timing` | アプリケーションが `addTiming` で記録するタイミングを名前で指定します。値はビューの開始からの経過時間です。 | ミリ秒または件数 | 30 行。統計量が **件数**の場合は不要 |
| **エクスプローラーのクエリ** | `query` | [エクスプローラー](/ja/rum/explorer)のクエリに一致する、1 種類の行を集計した値です。[エクスプローラーのクエリ](#エクスプローラーのクエリ)を参照してください。 | 件数またはフィールドの単位（所要時間はミリ秒） | 30 行。件数または合計の場合は不要 |

セッションやビューは、**開始した**評価期間に含まれます。1 分前に始まり、まだ終了していないセッションも、その時点までのデータでカウントします。そのため、評価期間の末尾数分の値は、セッションが終了した後の値よりもやや良好に見えます。評価期間を長くすると、この影響を抑えられます。

### 指標に値がない場合

件数はゼロでも有効な値なので、トラフィックが途絶えたことをルールで検知できます。それ以外の指標は、評価期間内の行数が表に示す必要数を下回ると**値なし**になります。この場合、しきい値条件は成立せず、アラートは発報しません。未解決のインシデントは解決します。これにより、トラフィックの少ない夜間に、わずかなビューから計算した p75 でアラートが発報するのを防ぎます。ルールの **必要な行数**でそのルールの最低行数を変更できます。件数に最低行数はありません。

### アプリケーションが計測する指標

カスタム指標では、計測対象を **バイタル名**または **タイミング名**で指定します。エディターにはアプリケーションが過去 24 時間に送信した名前が候補として表示されます。まだ送信していない名前も入力できます。**統計量**では、集計に使う値として `p50`、`p75` （デフォルト）、`p90`、`p95`、`p99`、平均、計測回数のいずれかを選びます。各評価期間では実ユーザーの行のみを対象とし、 [テストで生成したセッション](/ja/rum/test-traffic)はカウントしません。

### エクスプローラーのクエリ

[エクスプローラー](/ja/rum/explorer#新規アラート)で **新規アラート**を選ぶと、指標に **エクスプローラーのクエリ**を設定した状態でエディターが開きます。エディターで手動入力することもできます。

- **行の種類**では、クエリの対象をセッション、ビュー、アクション、エラー、リソース、ロングタスク、ログから選びます。
- **クエリ**は、エクスプローラーの **コード**モードと同じ形式で記述します。対象の行のフィールドに対する比較条件を `AND` でつなぎ、テキスト列から検索する語句を指定します。選択した行の種類で評価できない部分は入力欄の下に表示し、評価から除外します。空欄の場合は、選択した種類のすべての行が対象になります。
- **集計方法**は `Rows`、`Distinct values`、`Sum`、`Average`、`Minimum`、`Maximum`、または `p50` から `p99` です。**フィールド**では集計対象のフィールドを指定します。所要時間はミリ秒で扱います。
- **エクスプローラーで開く**を選ぶと、クエリの結果がエクスプローラーに時系列で表示されます。

ルールはエクスプローラーと同様に、実ユーザーの行を対象とします。合成テストや CI が実行したセッションは、クエリに `session.type`、`synthetics.*`、または `ci_test.*` を指定した場合にのみカウントします。他の RUM 指標と同様に、アプリケーションが[セッションの一部のみを保持する](/ja/rum/sampling)場合でも、ルールの件数、合計、平均は全セッションを対象とします。一方、エクスプローラーは保存された行を集計します。一致する行がない評価期間では、件数と合計は `0` になります。他の集計方法では、ルールで別の行数を指定しない限り、30 行が必要です。ページとバージョンはクエリで指定するため、ルールの **ページ**と **バージョン**は表示されません。インシデントには、クエリに一致した最新の行に対応するセッションが表示されます。

## ルールの絞り込み

| 絞り込み条件 | 対象の指標 |
|---|---|
| **環境** | すべての指標が対象です。 |
| **バージョン** | **新規イシュー**、**再発したイシュー**、**エクスプローラーのクエリ**を除くすべての指標が対象です。イシューは複数のバージョンで発生し、エクスプローラーのクエリではバージョンをクエリ内で指定します。 |
| **ページ**（アプリの場合は **画面**） | ページビュー、エラー、リクエスト、バイタルに関する指標が対象です。具体的には、**ページビュー数**、**エラー**、**エラー率**、**失敗したリクエスト**、**影響が最も大きいイシューの影響を受けたセッション**、4 つのバイタル、カスタム指標です。セッションは 1 つのページに限定されないため、セッション単位の指標は対象外です。イシューの指標も対象外です。**エクスプローラーのクエリ**では、ページをクエリ内で指定します。 |

エディターには、過去 24 時間にアプリケーションで確認された環境、ページ、バージョンが候補として表示されます。ページは、各ページに表示されるとおり、可変部分をグループ化した URL パスです。名前は文字列のまま比較するため、`*` も通常の文字として扱います。

新規イシューと再発したイシューは、イシューが**検出された環境**ごとにカウントします。イシューはアプリケーション全体に属し、環境ごとに初回検出時刻を保持します。たとえば、先週ステージング環境で初めて検出されたイシューでも、本番環境で初めて検出された時点では、本番環境の新規イシューとして扱います。環境を指定しない場合は、アプリケーション全体で初めて検出された時点で新規イシューとして扱います。

## ルールを作成する

**アラート → アラートルール**を開き、**新規ルール**を選択します。**しきい値ルール**では、**メトリクスアラート**、 **ログアラート**、**トレースアラート**、**APMアラート**に加えて、**RUMアラート**を選択できます。アプリケーションを選択し、必要に応じて対象を絞り込み、指標と集計ウィンドウ（5分、15分、1時間）を選択します。エディターは指標に適したウィンドウ（パーセンタイルや割合の場合は 1時間）と、通知によく使われるしきい値を初期値に設定します。ルールの作成には `alerts.rules.manage` が必要です。

**ルールをテスト**を選択すると、直近の指標値をウィンドウごとに1点ずつプロットし、しきい値とあわせて表示します。表示範囲は、 5分または15分のウィンドウでは過去6時間、1時間のウィンドウでは過去12時間です。最後の点は、ルールが現在評価する値です。行数が足りないウィンドウには値がなく、点も表示されません。プレビューはルールの評価と同じコードで計算するため、表示内容はルールの実際の動作と一致します。

別の指標を選択すると、単位が変わるため、しきい値とウィンドウは初期値に戻ります。指標をページやバージョンで絞り込めない場合は、フォームに理由が表示されます。

`alert` ロールは、`[alert].eval_interval_secs` ごとに直近のウィンドウを使ってルールを評価します。デフォルトの間隔は30秒です。`for_periods` はしきい値を超えた評価の連続回数を指定します。分単位のウィンドウですでに指標が平滑化されるため、エディターはRUMルールの初期値を 1に設定します。[ルールを作成する](/ja/api/alerting/create-rule#ルールの評価方法)を参照してください。

## ページからアラートを作成する

概要、エラー、パフォーマンス、ユーザーの不満の各ページでは、表示対象を示す行の末尾に**アラート**があります。ボタンの横には、アプリケーションで発生中のインシデント数が最も重大なインシデントの色で表示されます。インシデントがない場合は数値を表示しません。このボタンの表示には `alerts.rules.read` が必要です。

ボタンを押すとドロワーが開き、ページで選択中の環境におけるアプリケーションのアラートが表示されます。ページがすべての環境を対象としている場合は、すべての環境のアラートが表示されます。ドロワーには独自のアプリケーションや環境の設定はなく、ページの選択に従います。アラートは緊急度の高い順に表示されます。

- **発生中**には、アプリケーションの未解決のインシデント（確認済みを含む）が重大度の高い順に表示されます。各インシデントには、重大度、該当するルール、通知のしきい値、発生時刻が表示されます。**開く**を選択すると、ページに重ねてインシデントを表示します。
- **このアプリケーションのルール**には、現在の環境またはすべての環境でアプリケーションを監視するルールが、発報中のものを先頭に表示されます。各ルールの状態は、**発報中**、**パイプラインで破棄**、**保留中**、**正常**、**オフ**のいずれかです。**新規ルール**を選択すると、アプリケーションと環境を入力済みのルールエディターが開きます。**編集**を選択すると既存のルールが開きます。どちらにも `alerts.rules.manage` が必要です。
- **テンプレート**には、アプリケーションに推奨されるルールが、すぐに作成できる状態で表示されます。

[パフォーマンスページ](/ja/rum/performance#ディメンション値の詳細)の各行のドロワーには、**この指標のアラートを作成**があります。選択すると、開いているタブの指標を使い、その行のページまたはバージョンに対象を絞り込んだ状態でルールエディターが開きます。

[エクスプローラー](/ja/rum/explorer#新規アラート)のクエリバーで**新規アラート**を選択すると、クエリとその最初の測定項目を [エクスプローラークエリ](#エクスプローラーのクエリ)として設定した状態でルールエディターが開きます。

## テンプレート

テンプレートは、指標、通知のしきい値、集計ウィンドウを定義したルールです。**作成**を選択すると、すぐにルールを作成します。ルールは有効な `scheduled` ルールとして作成され、重大度ごとにテンプレートのしきい値を使用します。`for_periods` は1で、デフォルトのエスカレーションポリシーと、エディターで作成したルールと同じラベルに加え、テンプレートを示す `rum.template` ラベルが付きます。ルール名はアプリケーション名、環境名、テンプレート名をつないだものです（例：`Storefront · prod · Slow page loads`）。作成後は、**アラート → アラートルール**で設定を変更できます。ルールの作成には `alerts.rules.manage` が必要です。権限がない場合はボタンが無効になり、理由が表示されます。

ページのアプリケーションと環境に対してテンプレートからルールを作成済みの場合は、重複作成を防ぐため、ボタンの代わりに **作成済み（有効）**とルールへのリンクが表示されます。別の環境には同じテンプレートからルールを作成できます。すべての環境を対象とするルールと単一の環境を対象とするルールは別々に扱います。

各カードには、テンプレートのウィンドウにおける指標の**現在**の値が表示されます。値の計算には、ルールの評価と同じコードを使います。 Core Web Vitalsの指標には、値の評価ランクも表示されます。テンプレートから作成したルールがすぐに発報する場合は、カードにその旨が表示されます。指標の計算に必要な行数が足りない場合は、値の代わりに必要な行数が表示されます。

Core Web Vitalsのしきい値には、web.devの「良好」と「不良」の評価基準を使います。

## 異常検知ルール

**異常検知ルール**では、ソースとして**RUM 指標**を選択できます。直近のウィンドウの指標値を過去の各日の同じ時間帯の値と比較します。ベースラインと設定は、[他の異常検知ルール](/ja/alerting)と同じです。通常時の水準がない **新規イシュー**と**再発したイシュー**を除き、すべての指標を選択できます。

## インシデント

エディターで作成したルールには、絞り込み条件に応じて `rum.application`、`deployment.environment`、`rum.page`、`rum.version` のラベルが付きます。ルールから発生したインシデントは、これらのラベルを引き継ぎます。インシデントが発生すると、指標が最も悪化したときの **サンプルセッション** を最大 3 件保存します。各サンプルには、セッション ID、発生時刻、そのセッションでの指標値、指標に応じた詳細が含まれます。詳細には、バイタル指標の値が最も悪かったビューとその原因となった要素、最新のエラーとそのメッセージ、クラッシュやフラストレーションの兆候があったセッション、失敗したリクエストとそのパスが含まれます。新規および再発した問題では、各問題の最新のエラーが発生したセッションがサンプルになります。トラフィック指標にはサンプルがありません。

**発生中**、**アラート → インシデント**、またはリンクからインシデントのドロワーを開くと、**サンプルセッション** に発生時刻、ユーザーの識別情報（名前、アドレス、ID、または一度もサインインしていない訪問者について SDK が保持する ID）、ブラウザーと OS、サンプルに選ばれた理由が表示されます。記録済みのセッションでは、**リプレイ** が発生時刻の 5 秒前から再生を開始します。**セッション** は記録されていないセッションの詳細ページを開きます。ユーザーの識別情報と記録の有無はセッションから取得するため、 `rum.sessions.read` が必要です。この権限がなくても、発生時刻とサンプルに選ばれた理由は表示されます。

**RUMで開く** を選ぶと、同じアプリケーション、環境、ページの指標をインシデント前後の期間で確認できます。表示期間は、ルールの評価ウィンドウより前から、解決の少し後までです。インシデントが発生中の場合は、現在まで表示します。

| 指標 | 開くページ |
|---|---|
| バイタル指標 | [パフォーマンス](/ja/rum/performance)で該当する指標を表示します。ルールでページを指定している場合は、そのページのドロワー内に表示します |
| 失敗したリクエスト | [リソース](/ja/rum/performance#リソース) |
| エラー、エラー率、新規および再発した問題、クラッシュのないセッション | [エラー](/ja/rum/errors) |
| フラストレーションがあったセッション | [フラストレーション](/ja/rum/frustration) |
| エクスプローラークエリ | [エクスプローラー](/ja/rum/explorer)で、ルールのアプリケーションと環境を対象にクエリ結果を時系列で表示します |
| セッション、ページビュー | [概要](/ja/rum) |

## API でのルール設定

RUM 指標のルールでは、`query` のステートメントとストリームの代わりに `query.rum` を指定します。この設定を使って[ルールを作成](/ja/api/alerting/create-rule)します。

```json
{
  "name": "Storefront checkout is slow",
  "kind": "scheduled",
  "query": {
    "language": "sql",
    "statement": "",
    "periodSecs": 3600,
    "rum": {
      "applicationId": "storefront",
      "environment": "prod",
      "page": "/checkout",
      "metric": "lcp_p75"
    }
  },
  "trigger": { "operator": "gt", "threshold": 2500, "forPeriods": 1, "silenceSecs": 300 },
  "thresholds": [
    { "severity": "warning", "operator": "gt", "threshold": 2500, "forPeriods": 1 },
    { "severity": "critical", "operator": "gt", "threshold": 4000, "forPeriods": 1 }
  ],
  "labels": { "rum.application": "storefront", "deployment.environment": "prod", "rum.page": "/checkout" },
  "annotations": {}
}
```

`periodSecs` は評価ウィンドウで、60 秒から 6 時間まで指定できます。既存のアプリケーションを指定してください。`page` と `version` は、それぞれに対応していない指標では指定できません。`minSamples` は任意ですが、件数を数える指標では指定できません。しきい値には指標と同じ単位を使います。カスタム指標では `custom_name` が必須です。`statistic` には `p50`、`p75`、`p90`、`p95`、`p99`、`avg`、`count` のいずれかを指定できます。デフォルトは `p75` です。他の指標ではどちらも指定できません。

RUM ページは `rum.application` ラベル（特定の環境のページでは `deployment.environment` ラベルも）を使って、アプリケーションのインシデントを特定します。ルールの特定には `query.rum` を使います。API で作成するルールには指定したラベルが付くため、インシデントを RUM ページで集計・一覧表示するには、これらのラベルを指定してください。テンプレートから作成したルールには `rum.template` が付きます。テンプレートカードはこのラベルで、そのテンプレートからルールが作成済みかどうかを判定します。

**ルールをテスト** は `POST /api/v1/rum/alerts/preview` を呼び出します。[RUM API](/ja/api/rum#アラートルールをプレビューする)を参照してください。

## 権限

- `alerts.rules.read` があると、RUM ページに **アラート** が表示され、そのドロワーでインシデント、ルール、テンプレートを確認できます。
- `alerts.rules.manage` があると、テンプレート、**新規ルール**、ルールエディターからルールを作成でき、既存のルールの **編集** を開けます。
- `rum.events.read` があると、プレビューとテンプレートに表示される現在の指標値を確認できます。`rum.sessions.read` があると、インシデントのサンプルセッションのユーザー識別情報を確認できます。

[RUM](/ja/rum#権限)を参照してください。
