オートメーションは、起動するたびに同じタスクをMole Agentに依頼します。たとえば、毎朝サービスの健全性をチェックしたり、新しい重大インシデントを調査したり、パイプラインから呼び出されたときにデプロイを確認したりします。Mole Agentはチャットと同じように、オートメーションのスコープで利用できるツール、スキル、ナレッジを使ってタスクを実行します。実行内容はチャットとして保存され、オートメーションの閲覧権限があれば開けます。実行が完了すると、選択した通知チャンネルに結果を送信します。インシデントをトリガーとするオートメーションでは、そのインシデントのRCAも記録できます。

## 開始前の準備

- **Mole Agent → 設定 → モデルと推論**で、少なくとも1つのAIモデルを有効にしてください。[Mole Agent](/ja/agent#モデルプロバイダーを設定する)を参照してください。有効なモデルがない場合、実行は失敗し、その理由が表示されます。
- 権限を確認してください。

| タスク | 権限 |
|---|---|
| オートメーションとその実行履歴を表示し、実行のチャットを開く | `agent.automations.read`とスコープに応じたアクセス権が必要です。[オートメーションの所属](#オートメーションの所属)を参照してください。 |
| 作成、編集、オンへの切り替え | `agent.automations.manage`とスコープに応じたアクセス権が必要です。この権限はデフォルトでオーナー、管理者、編集者ロールに付与されます。 |
| 今すぐ実行 | `agent.automations.run`とスコープに応じたアクセス権が必要です。この権限は同じロールに付与されます。 |
| APIトークンを管理する | `agent.automations.tokens`とスコープに応じたアクセス権が必要です。この権限は同じロールに付与されます。 |
| オフへの切り替えと削除 | 作成・編集と同じ権限が必要です。`agent.manage`があれば、閲覧可能なオートメーションをオフにしたり削除したりできます。 |
| フォームで通知チャンネルを選択する | 通知コネクターを一覧表示する `notify.connectors.read` が必要です。 |

## オートメーションを作成する

**Mole Agent → オートメーション → 新しいオートメーション**を開き、空のオートメーションまたはテンプレートから作成します。

| テンプレート | 開始 | 実行内容 |
|---|---|---|
| **インシデント分析** | 重大度がエラーまたはクリティカルの新しいインシデント | ツールを使ってインシデントを調査します。トリガーとなったクエリを再実行し、エラーログ、トレース、APM、サービスのトポロジーを確認します。根本原因の候補を根拠とともに示し、インシデントのRCAとして記録します。 |
| **毎日の健康チェック** | 平日の09:00 | 過去24時間のエラー率、レイテンシー、エラーパターン、未解決のインシデントを確認し、対応が必要な項目を示します。 |
| **毎週のアラートノイズの見直し** | 月曜日の10:00 | 先週最も頻繁に発報したアラートルール、発報と解消を繰り返したルール、一度も対応されなかったルールを特定し、それぞれの調整方法を提案します。 |
| **毎週のオンコール負荷の確認** | 月曜日の10:30 | 担当者別およびスケジュール別のインシデント件数、夜間の呼び出し、対応時間を集計し、負荷を下げる方法を提案します。 |
| **変更の影響チェック** | APIコール | デプロイの対象となったサービスをデプロイの前後で比較し、デグレードが発生したかどうかを示します。 |

フォームには次のフィールドがあります。

| フィールド | 説明 |
|---|---|
| **名前** | 組織内で一意の名前を指定します。 |
| **何をするか** | タスクを最大8000文字で指定します。新しいチャットと同じように、実行のたびにMole Agentにタスクを依頼します。 |
| **説明** | オートメーションの用途を1行で記述します。 |
| **誰の** | オートメーションの作成時に、個人、所属するチームのいずれか、または組織をスコープとして選択します。 |
| **開始** | スケジュール、新しいインシデント、APIコール、または手動で開始します。[開始トリガー](#開始トリガー)を参照してください。 |
| **制限時間** | 5〜60分で、デフォルトは10分です。制限時間を超えた実行は停止し、失敗としてカウントします。 |
| **オン** | オフのオートメーションは、**今すぐ実行**を選択した場合にのみ開始します。 |
| **通知チャンネル** | 通知コネクターから、固定のアドレスまたはグループを最大5件指定します。Alibaba CloudのSMSと音声通知は承認済みのテンプレートのみを送信するため、選択できません。 |
| **結論をインシデントのRCAとして記録する** | インシデントをトリガーとするオートメーションで使用します。 |

1つの組織で最大50件のオートメーションを作成できます。行メニューの**複製**を選択すると、コピーがオフの状態でフォームに開きます。別の名前やスコープで保存できます。

### オートメーションの所属

スコープによって、実行時に利用できるものと、オートメーションを閲覧できる範囲が決まります。作成後にスコープを変更することはできません。別のスコープを使うには、オートメーションを複製してください。

| スコープ | 実行時に利用するもの | 閲覧できる範囲 |
|---|---|---|
| 個人 | 組織と個人のスキルおよびMCPサーバー、組織のナレッジ、個人のメモリ | 本人と `agent.manage` 権限を持つメンバー |
| チーム | 組織とチームのリソースおよびナレッジ、チームのメモリ | チームメンバーと `agent.manage` 権限を持つメンバー |
| 組織 | 組織のリソースとナレッジのみを利用します。実行時にメモリは保持しません。 | `agent.automations.read` 権限を持つすべてのメンバー |

組織スコープのオートメーションがインシデントをトリガーに開始する場合は、インシデントのエスカレーションポリシーから特定したチームのスコープで実行します。最初に呼び出すチームを使い、該当するチームがなければ最初のオンコールスケジュールのチームを使います。どちらにもチームがなければ、組織スコープのまま実行します。

### 実行ユーザー

オートメーションは、最後に保存したユーザーとして実行します。実行のたびにそのユーザーの権限を再取得し、メンバーごとに認証情報が必要なMCPサーバーでは、そのユーザーの認証情報を使います。保存すると、保存したユーザーが実行ユーザーになり、フォームにその旨が表示されます。APIトークンは発行者本人ではなくロールを表すため、APIトークンでは保存できません。

実行ユーザーが組織内でMole Agentを利用できなくなると、利用権限のあるメンバーがオートメーションを再保存するまで、毎回の実行がその理由で失敗します。

## 開始トリガー

| トリガー | 実行タイミング |
|---|---|
| **スケジュールで** | タイムゾーンを指定し、5フィールドのcron式（分、時、日、月、曜日）で設定した時刻に実行します。実行頻度は最大で15分に1回です。曜日の0と7は日曜日です。日と曜日の両方に条件を設定せず、どちらか一方だけに設定してください。前回の実行が続いている場合は、次の実行をスキップします。 |
| **新しいインシデント** | オートメーションの保存後またはオンへの切り替え後に作成され、設定したすべてのフィルター（重大度、アラートルール、影響を受けたサービス、値が一致するラベル）に一致するインシデントごとに実行します。同じインシデントは1回だけ分析します。同じルールとラベルを持つ同一グループのインシデントは、30分間に1回だけ分析します。 |
| **新しい発見** | オートメーションの保存後またはオンへの切り替え後に[検出](/ja/alerting/discovery)で見つかり、設定したすべてのフィルター（種類、最低重大度、サービス、ホスト、またはコンテナ）に一致する項目ごとに実行します。同じ項目は1回だけ調査します。 |
| **APIコール** | 外部システムがトークンを送信したときに実行します。[CI/CDから開始する](#ci/cdからオートメーションを起動する)を参照してください。 |
| **手動で** | 手動で実行した場合にのみ開始します。 |

行の**今すぐ実行**を選択すると、オンかオフかにかかわらず、設定されている実行ユーザーとしてオートメーションを開始します。実行頻度は最大で1分に1回です。

## 実行

行の**実行**には、直近100件の実行が新しい順に表示されます。各実行の結果と理由、トリガー、回答の冒頭、通知が届かなかったチャンネルを確認できます。**実行を開く**を選択すると、実行の全内容を記録したチャットが開きます。このチャットはチャット一覧に表示されず、会話を続けることもできません。再度依頼するには、オートメーションを実行してください。

実行中は質問に回答できません。Mole Agentは質問しても、回答を待たずに自身の判断で進めます。ユーザーの確認が必要なツールは実行せず、実行ユーザーの認証情報が必要で、その情報が保存されていないMCPサーバーも使用しません。Mole Agentはその旨を回答に記載し、実行のステータスを**誰かが必要です**にします。

| ステータス | 意味 |
|---|---|
| **実行中** | Mole Agentがタスクを処理しています。 |
| **成功** | Mole Agentは回答し、通知の送信とRCAの記録も完了しました。 |
| **一部完了** | Mole Agentは回答しましたが、送信できなかった通知があるか、RCAを記録できませんでした。 |
| **誰かが必要です** | Mole Agentは回答しましたが、必要な質問への回答、確認、または認証情報を得られませんでした。 |
| **失敗** | Mole Agentは回答しませんでした。モデルやツールのエラー、制限時間の超過、有効なモデルがない、実行ユーザーがMole Agentを利用できなくなった、のいずれかが原因です。 |
| **スキップ済み** | 組織の1日あたりのトークン予算を使い切った、前回の実行が完了していない、または同じインシデントを直前に分析したため、実行を開始しませんでした。 |
| **停止されました** | 手動で実行を停止したか、実行を処理していたサーバーが停止しました。 |

実行時のモデル呼び出しは、組織の1日あたりのトークン予算に計上され、ソース別の使用量では**オートメーション**として表示されます。

## 通知とインシデントのRCA

実行が成功した場合、担当者の対応が必要な場合、または実行が失敗した場合に、各チャネルに通知を送信します。通知には、オートメーション名、実行結果、回答の冒頭、判断理由、実行へのリンクが含まれます。通知にはオートメーションを保存したユーザーの言語を使用し、ほかの通知と同様に配信履歴に表示します。

インシデントをトリガーとするオートメーションで**結論をインシデントのRCAとして記録する**を有効にすると、Mole Agentの回答をインシデントのRCAとして記録し、インシデントページに表示します。チャットから作成したRCAは上書きしません。組織でこの設定のオートメーションが有効な間は、組み込みのRCA生成機能はその組織のインシデントの分析をオートメーションに任せます。同じインシデントを二重に分析することはありません。**インシデント分析**テンプレートには、この設定が適用されています。

## CI/CDからオートメーションを起動する

API呼び出しで起動するオートメーションの行メニューで**APIトークン**を開き、**トークンを作成**を選択します。トークンは一度だけ表示します。新しいトークンを作成すると既存のトークンは即座に置き換わります。**トークンを取り消す**を選択すると、トークンを無効にします。

デプロイ時にトークンを送信し、`text`に変更内容を記述します。

```bash
curl -X POST "https://molesignal.example.com/api/v1/public/automations/<automation-id>/trigger" \
  -H "Authorization: Bearer mspat-..." \
  -H "Content-Type: application/json" \
  -d '{"text": "Deployed checkout-api v42 at 14:05"}'
```

`text`はオプションで、最大8,000文字です。Mole Agentは`text`を指示ではなく、実行に関するデータとして扱います。APIは`202`とともに`runId`、`status`、`chatUrl`を返します。トークンが無効な場合やオートメーションが見つからない場合は`401`、オートメーションが無効な場合やAPI呼び出しで起動する設定になっていない場合は`409`、10秒以内に再度呼び出した場合は`429`を返します。

## Mole Agentの利用状況を振り返る

`/insight [days]`は、チャットのスコープ内で過去30日間、または指定した日数分のMole Agentの利用状況を振り返る組み込みスキルです。質問の内容、回答やオートメーションの実行結果、役に立たないと評価された内容とその理由、失敗が多かったツール、使用したスキルを確認します。最後に、ナレッジファイルの作成やオートメーションの修正など、改善案を最大5件提示します。変更は加えません。チームチャットではそのチームを対象とし、個人チャットではチャットの利用者と所属チームを対象とします。チャットで実行するか、週次オートメーションのタスクとして使用します。
