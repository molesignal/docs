すべてのシグナルは、取り込み API を通じて MoleSignal に送信されます。Web UI の **データソース**ページでは、送信元ごとにエンドポイント、トークン、設定スニペットを生成します。同じプロトコルを手動で設定することもできます。

## データソースページ

送信元を追加するには、**データソース**を開きます。

1. カタログを検索するか、カテゴリ（**推奨**、**インフラストラクチャ**、**クラウド**、**データベース**、**メッセージング**、**アプリと言語**、**セキュリティ**、**カスタム**）で絞り込みます。シグナルのタブ（**ログ**、**メトリクス**、**トレース**、**プロファイル**）で、一覧をさらに絞り込めます。
2. Kubernetes、Linux ホスト、AWS、OpenTelemetry SDK、Web RUM などの送信元を選択します。
3. ガイドの 3 つの手順に従います。
   - **エンドポイントとトークン**には、データの送信先と認証に使用するトークンが表示されます。**トークンを表示**を選択すると、トークンとそのスコープ、ワークスペース、有効期限が表示されます。RUM の送信元では、まず **RUM アプリケーション**を選択します。選択すると、そのクライアントトークンが表示されます。
   - **送信元の設定**には、実際のエンドポイントとトークンを設定済みのコマンドや設定内容が表示されます。
   - **データの受信を確認**では、レシーバーの状態を確認した後、過去 1 時間にデータを受信したかどうかを確認します。**接続を確認**を選択するとすぐに確認を実行します。表示される数値は 30 秒ごとに更新されます。
4. 確認結果を確認します。
   - **データ受信を確認済み**：過去 1 時間にデータを受信しており、送信元のシグナルは正常です。**受信データを表示**でデータを開き、**パイプラインを作成**でそのデータ用のパイプラインの作成を開始できます。
   - **レシーバーは正常ですが、データの確認が必要です**：レシーバーは応答していますが、データを受信していないか、一部のシグナルが正常ではありません。デプロイを確認するか、次のバッチの到着を待ってください。
   - **検証失敗**：レシーバーの状態を確認できませんでした。**考えられる原因**には、コレクターが動作していない、トークンが無効か期限切れになっている、ネットワークやプロキシがエンドポイントへのアクセスをブロックしている、などが表示されます。

`http.external_url` を設定している場合はその値をエンドポイントとして使用し、設定していない場合はブラウザーで開いているアドレスを使用します。リバースプロキシの背後で運用する場合は、生成されるスニペットが公開アドレスを参照するように `http.external_url` を設定してください。[設定](/ja/configuration)を参照してください。

## 取り込みトークン

送信元は Bearer トークンで認証します：`Authorization: Bearer <token>`。

| トークン | 権限 | 作成方法 | 用途 |
|---|---|---|---|
| デフォルトの取り込みトークン | `logs.write`、`metrics.write`、`traces.write`、`profiles.write`、`apm.deploy` のみ（**データ取り込み**ポリシー） | データソースページ、または `GET /api/v1/me/api-tokens/default` | ログ、メトリクス、トレースを送信するコレクター、エージェント、SDK エクスポーター、および[デプロイを報告する](/ja/apm/deployments#ci-からデプロイを報告する)パイプラインに使用します。有効期限はありません。 |
| RUM クライアントトークン | `rum.write` のみ。1 つのアプリケーションに紐づきます | Web RUM およびモバイル RUM の送信元用のデータソースページ、または `GET /api/v1/auth/tokens/rum?applicationId=<id>` | ブラウザーやモバイルアプリのコードで使用します。トークンはエンドユーザーから見えます。 |
| 個人用トークンまたはサービスアカウントトークン | メンバーまたはサービスアカウントの権限のうち、トークンのスコープで許可された権限 | **アカウント設定 → API トークン**。サービスアカウントの場合は **ID とアクセス → API トークン** | 自動化、スクリプト、MCP クライアントに使用します。 |

継続的に動作する送信元には、デフォルトの取り込みトークンか、**データ取り込み**ポリシーに従うサービスアカウントトークンを使用してください。トークンをすぐに無効にするには、**アカウント設定 → API トークン**または **ID とアクセス → API トークン**で失効させます。Web UI のサインインセッションではデータを送信できません。セッションはブラウザーの Cookie に保存され、`Authorization` ヘッダーでは使用できません。

**データソース**ページでアプリケーション ID を入力すると、RUM クライアントトークンが作成されます。アプリケーション ID には、`A-Z`、`a-z`、`0-9`、`.`、`_`、`:`、`-` の文字を 1〜128 文字使用できます。SDK の `applicationId` には同じ ID を指定してください。[ブラウザー RUM SDK](/ja/rum/browser-sdk)を参照してください。

## エンドポイントとプロトコル

| プロトコル | エンドポイント | 対応する送信元 | 送信先ストリーム |
|---|---|---|---|
| ネイティブ HTTP JSON | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`、アプリケーションコード、Vector の `http` シンク、Fluent Bit の `http` 出力 | パスセグメント `{stream}` |
| HTTP 経由の OTLP | `POST /api/v1/logs`、`/api/v1/metrics`、`/api/v1/traces` | OpenTelemetry SDK と Collector | `stream-name` ヘッダー。指定がなければ `default` |
| gRPC 経由の OTLP | `:4317` | OpenTelemetry SDK と Collector | `stream-name` メタデータ。指定がなければ `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus、VictoriaMetrics、その他の remote_write v1 対応の送信元 | `stream-name` ヘッダー。指定がなければ `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat、Logstash、Vector の `elasticsearch` シンク | 各アクションの `_index`。指定がなければ `stream-name` ヘッダー、どちらも指定がなければ `default` |
| Loki プッシュ（JSON） | `POST /api/v1/loki/api/v1/push` | Loki の JSON 形式で POST できる送信元 | `stream-name` ヘッダー。指定がなければ `default` |
| Kinesis Firehose、Cloudflare Logpush、Heroku | `/api/v1/_kinesis_firehose`、`/api/v1/_cloudflare`、`/api/v1/_heroku` | AWS、Cloudflare、Heroku | コネクターで設定します。[コネクター](/ja/connectors)を参照してください。 |

プッシュコネクターを除くすべてのエンドポイントには、シグナルに対応する書き込み権限（`logs.write`、`metrics.write`、`traces.write`、`profiles.write` のいずれか）を持つ Bearer トークンが必要です。組織はトークンから判別するため、URL には含めません。

### 送信元に適用される制限

- **リクエストサイズ。** ネイティブ JSON 取り込みで受け付けるリクエストボディは、解凍後のサイズで最大 16 MiB です。その他の取り込みエンドポイントでは最大 2 MiB です。上限を超えるボディには `413` を返します。バッチのサイズは該当する上限未満にしてください。
- **圧縮。** HTTP 経由の OTLP は圧縮されたリクエストボディを受け付けず、`400` を返します。送信元で圧縮を無効にしてください。OpenTelemetry Collector の `otlphttp` エクスポーターはデフォルトで gzip 圧縮を使用するため、`compression: none` を設定してください。ネイティブ JSON 取り込み、Elasticsearch `_bulk`、Loki プッシュ、プッシュコネクターは `Content-Encoding: gzip` を受け付けます。
- **Loki のエンコード。** デコードできるのは JSON 形式のリクエストのみです。Promtail と Grafana Alloy はデフォルトで snappy 圧縮した protobuf を送信するため、このエンドポイントには送信できません。
- **レート制限。** `router` ロールは組織ごとにリクエスト数を制限し、上限を超えると `Retry-After` ヘッダー付きで `429` を返します。`standalone` ノードでは、この制限を適用しません。[ロールベースのデプロイ](/ja/deployment/role-based#レート制限)を参照してください。
- **プラットフォームストリーム。** サービス自体のテレメトリー用の `_molesignal` や監査証跡用の `_audit` などの[プラットフォームストリーム](/ja/streams#プラットフォームストリーム)には、MoleSignal だけが書き込めます。公開の取り込み API からの書き込みには `403` を返します。

## ストリームとスキーマ

初回の書き込み時にストリームを作成し、新しいフィールドが現れるたびにスキーマを更新します。ストリームは名前とシグナルの種類の組み合わせで識別するため、ログ、メトリクス、トレースのそれぞれに `default` が存在できます。[ストリーム](/ja/streams)を参照してください。

各イベントは、Unix エポックからの経過時間をマイクロ秒単位で表すタイムスタンプを持ちます。ネイティブ JSON と Elasticsearch `_bulk` は `_timestamp` フィールドを読み取ります。`_timestamp` がないイベントには、サーバーが受け付けた時刻を設定します。

## ネイティブ HTTP JSON

レコードの配列を `/api/v1/intake/{logs,metrics,traces}/{stream}` に POST します。

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

レスポンスには、受け付けたレコード数と拒否したレコード数、および拒否した各レコードのインデックスに対応する理由が含まれます。

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

OpenTelemetry SDK または OpenTelemetry Collector の送信先に、ベースパス `/api` を指定します。エクスポーターは `/v1/logs`、`/v1/metrics`、`/v1/traces` を末尾に追加し、それぞれ `/api/v1/logs`、`/api/v1/metrics`、`/api/v1/traces` に送信します。

<Tabs>
  <Tab title="HTTP 経由の OTLP">
    SDK の環境変数:

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    SDK と OpenTelemetry Collector のデフォルトのエンコーディングである protobuf（`application/x-protobuf`）で送信します。ログ、メトリクス、トレースは JSON（`application/json`）でも受け付けます。`default` 以外のストリームを選択するには、`stream-name` ヘッダーを追加してください。このヘッダーは、そのエクスポーターが送信するすべてのシグナルに適用されます。
  </Tab>
  <Tab title="gRPC 経由の OTLP">
    OTLP gRPC レシーバーはポート `4317` でリッスンし、ログ、メトリクス、トレース、プロファイルの各サービスを提供します。レシーバー自体は TLS を終端しません。信頼できるネットワークの外に出るトラフィックについては、レシーバーの手前で TLS を終端してください。

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    このポートの手前に TLS を終端するプロキシを配置する場合は、`insecure: true` を削除してください。ポート `5082` はクラスター内部の gRPC ポートであり、OTLP レシーバーのポートではありません。
  </Tab>
</Tabs>

MoleSignal は、OTLP メトリクスのデータポイントごとに 1 件のイベントを保存します。保存するフィールドについては、[メトリクスの保存仕様](/ja/query#otlp-メトリクスのフィールド)を参照してください。

## Prometheus remote_write

`prometheus.yml` にリモート書き込み先として MoleSignal を追加します:

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

メトリクスストリームには 1 つのソースのメトリクスを格納します。`stream-name` ヘッダー（`remote_write` エントリの `headers:`）で、Prometheus サーバーごとに別のストリームを指定してください。このヘッダーを指定しない場合、サンプルは `default` に送られます。各サンプルは 1 行になり、その `__name__` が `metric_name` の値になります。他のラベルはフィールドになりますが、`metric_name` などのメトリクスフィールドと同名のラベルは `exported_<name>` として保持します。ネイティブヒストグラムとメトリクスメタデータは保存せず、エグゼンプラーはサンプルと一緒に保存します。

## Elasticsearch bulk

Elasticsearch bulk プロトコルに対応する送信元は、Loki や OTLP に依存せずにデータを送信できます:

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

各アクションの `_index` で送信先ストリームを指定します。`_index` がない場合は `stream-name` ヘッダーを使用し、そのヘッダーもない場合は `default` を使用します。

## Loki push

エンドポイントは Loki の JSON リクエスト形式を受け付けます:

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

エンドポイントはラベルをフィールドに、ログ行を `message` フィールドに変換し、ナノ秒単位のタイムスタンプをマイクロ秒単位に変換します。レスポンスは `204` です。送信先ストリームは `stream-name` ヘッダーで指定してください。
