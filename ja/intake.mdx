すべてのシグナルは取り込み API を介して MoleSignal に取り込まれます。Web UI の**データソース**ページでは、送信元ごとにエンドポイント、トークン、設定スニペットが生成されます。同じプロトコルは手動でも設定できます。

## データソースページ

送信元をオンボーディングするには、**データソース**を開きます:

1. カタログを検索するか、カテゴリで絞り込みます: **推奨**、**インフラストラクチャ**、**クラウド**、**データベース**、**メッセージング**、**アプリと言語**、**セキュリティ**、**カスタム**。シグナルのタブ（**ログ**、**メトリクス**、**トレース**、**プロファイル**）でリストをさらに絞り込めます。
2. Kubernetes、Linux ホスト、AWS、OpenTelemetry SDK、Web RUM などの送信元を選択します。
3. ガイドの 3 つのステップに従います:
   - **エンドポイントとトークン**には、データの送信先と認証に使用するトークンが表示されます。**トークンを表示**すると、トークンとそのスコープ、ワークスペース、有効期限が表示されます。RUM ソースの場合は、先に **RUM アプリケーション**を選択します。選択すると、そのクライアントトークンが表示されます。
   - **送信元の設定**には、実際のエンドポイントとトークンが入力済みのコマンドと設定が表示されます。
   - **データの受信を確認**では、レシーバーを確認してから、過去 1 時間に受信したデータを探します。**接続を確認**は即座に確認し、数値は 30 秒ごとに更新されます。
4. 検証結果を確認します:
   - **データ受信を確認済み**: 過去 1 時間にデータが到着し、送信元のシグナルは正常です。**受信データを表示**でデータを開き、**パイプラインを作成**でそのデータのパイプラインを開始できます。
   - **レシーバーは正常ですが、データの確認が必要です**: レシーバーは応答していますが、データが到着していないか、一部のシグナルが正常ではありません。デプロイを確認するか、次のバッチを待ってください。
   - **検証失敗**: レシーバーを確認できませんでした。**考えられる原因**には、コレクターが実行されていないこと、トークンが無効または期限切れであること、ネットワークまたはプロキシがエンドポイントをブロックしていることが表示されます。

エンドポイントは、`http.external_url` が設定されている場合はその値から、設定されていない場合はブラウザのアドレスから取得されます。リバースプロキシの背後では `http.external_url` を設定し、生成されるスニペットがパブリックアドレスを指すようにします。詳細は[設定](/ja/configuration)を参照してください。

## 取り込みトークン

送信元はベアラートークンで認証します: `Authorization: Bearer <token>`。クラウドプロバイダーのマネージド Prometheus のリモート書き込みエクスポートなど、Basic 認証しか使用できない送信元は、任意のユーザー名とともに API トークンを `Authorization: Basic` のパスワードに設定します。その他の Basic 認証情報は無視されるため、独自の認証情報を要求するリバースプロキシも引き続き機能します。Splunk HEC の送信元は、`Authorization: Splunk <token>` としてトークンを提示します。

| トークン | 権限 | 作成元 | 用途 |
|---|---|---|---|
| デフォルトの取り込みトークン | `logs.write`、`metrics.write`、`traces.write`、`profiles.write`、および `apm.deploy` のみ: **データ取り込み**ポリシー | データソースページ、または `GET /api/v1/me/api-tokens/default` | ログ、メトリクス、トレースを送信するコレクター、エージェント、SDK エクスポーター、および[デプロイを報告する](/ja/apm/deployments#ci-からデプロイを報告する)パイプライン。有効期限はありません。 |
| RUM クライアントトークン | `rum.write` のみ。1 つのアプリケーションにバインドされます | Web RUM およびモバイル RUM ソースのデータソースページ、または `GET /api/v1/auth/tokens/rum?applicationId=<id>` | ブラウザおよびモバイルのコード。トークンはエンドユーザーから参照できます。 |
| 個人またはサービスアカウントのトークン | メンバーまたはサービスアカウントに許可される操作（スコープにより限定） | **アカウント設定 → API トークン**、またはサービスアカウントの場合は **ID とアクセス → API トークン** | 自動化、スクリプト、MCP クライアント。 |

継続的に実行される送信元には、デフォルトの取り込みトークン、または **データ取り込み**ポリシーに従うサービスアカウントのトークンを使用します。トークンを即座に停止するには、**アカウント設定 → API トークン**または **ID とアクセス → API トークン**からトークンを取り消します。Web UI のサインインセッションではデータを送信できません。これはブラウザの Cookie に保持されており、`Authorization` ヘッダーでは受け付けられません。

**データソース**ページでは、アプリケーション ID を入力すると RUM クライアントトークンが作成されます。アプリケーション ID は、`A-Z`、`a-z`、`0-9`、`.`、`_`、`:`、`-` の 1～128 文字で構成されます。SDK では同じ ID を `applicationId` として使用します。詳細は[ブラウザ RUM SDK](/ja/rum/browser-sdk)を参照してください。

## エンドポイントとプロトコル

| プロトコル | エンドポイント | 対応する送信元 | 送信先ストリーム |
|---|---|---|---|
| ネイティブ HTTP JSON | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`、アプリケーションコード、Vector `http` シンク、Fluent Bit `http` 出力 | `{stream}` パスセグメント |
| OTLP over HTTP | `POST /api/v1/logs`, `/api/v1/metrics`, `/api/v1/traces` | OpenTelemetry SDK と Collector | `stream-name` ヘッダー、なければ `default` |
| OTLP over gRPC | `:4317` | OpenTelemetry SDK と Collector | `stream-name` メタデータ、なければ `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus、VictoriaMetrics、クラウドマネージド Prometheus エクスポート、任意の remote_write v1 送信元 | `stream-name` ヘッダー、なければ `?stream=`、それもなければ `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat、Logstash、Vector `elasticsearch` シンク | 各アクションの `_index`、なければ `stream-name` ヘッダー、それもなければ `default` |
| Splunk HEC | `POST /api/v1/services/collector/event`, `/api/v1/services/collector/raw` | Tencent Cloud CLS、Vector と Fluent Bit の Splunk 出力、SIEM フォワーダー | 各イベントの `index`、なければ `?index=`、それもなければ `stream-name` ヘッダー、それもなければ `default` |
| Loki push (JSON) | `POST /api/v1/loki/api/v1/push` | Loki の JSON 形式を POST できる送信元 | `stream-name` ヘッダー、なければ `default` |
| Amazon Data Firehose、Google Cloud Pub/Sub push、クラウドイベントバス、Cloudflare Logpush、Heroku | `/api/v1/_kinesis_firehose`, `/api/v1/_gcp_pubsub`, `/api/v1/_cloud_events`, `/api/v1/_cloudflare`, `/api/v1/_heroku` | Firehose 経由の CloudWatch Logs と CloudWatch Metric Streams、Pub/Sub 経由の Cloud Logging、EventBridge、Event Grid、CloudEvents 送信元、Cloudflare、Heroku | コネクタで設定します。[コネクタ](/ja/connectors)を参照してください。 |

プッシュコネクタを除くすべてのエンドポイントは、シグナルの書き込み権限を持つベアラートークンを必要とします: `logs.write`、`metrics.write`、`traces.write`、または `profiles.write`。組織はトークンから決まり、URL に現れることはありません。

### 送信元に影響する制限

- **リクエストサイズ。** ネイティブ JSON 取り込みとプッシュコネクタは最大 16 MiB、Firehose は最大 64 MiB のリクエストボディを受け付けます（展開後にカウント）。他の取り込みエンドポイントは最大 2 MiB です。それを超えるボディは `413` で拒否されます。バッチはそのサイズ未満に保ってください。
- **圧縮。** OTLP over HTTP は圧縮されたリクエストボディを受け付けず、`400` を返します。送信元で圧縮を無効にしてください。OpenTelemetry Collector の `otlphttp` エクスポーターはデフォルトで gzip 圧縮するため、`compression: none` が必要です。ネイティブ JSON 取り込み、Elasticsearch `_bulk`、Loki push、プッシュコネクタは `Content-Encoding: gzip` を受け付けます。
- **Loki エンコーディング。** デコードされるのは JSON リクエスト形式のみです。Promtail と Grafana Alloy はデフォルトで snappy 圧縮された protobuf を送信するため、このエンドポイントには送信できません。
- **レート制限。** `router` ロールは組織ごとにリクエストを制限し、`Retry-After` ヘッダー付きで `429` を返します。`standalone` ノードはこの制限を適用しません。[ロールベースのデプロイ](/ja/deployment/role-based#レート制限)を参照してください。
- **拒否されたイベント。** ストリーム内のフィールドの型に合わない値を持つイベントは、そのイベントだけが拒否され、リクエストの残りは書き込まれます。`int64` フィールドの小数を含む数値は拒否されません。フィールドは `float64` になります（[スキーマとフィールド](/ja/streams#スキーマとフィールド)を参照）。各エンドポイントは拒否した内容を報告します。ネイティブ JSON は `rejected` と `errors`、OTLP は `partialSuccess`、Elasticsearch `_bulk` はステータス `400` のアイテム、Splunk HEC はコード `6`、Prometheus remote write と Loki push は `400` で報告します。送信元はこれらを再試行しません。プッシュコネクタは成功を返します。プラットフォームがリクエスト全体を再送するためで、拒否された内容はコネクタが示します。
- **プラットフォームストリーム。** [プラットフォームストリーム](/ja/streams#プラットフォームストリーム)（サービス自身のテレメトリー用の `_molesignal`、監査証跡用の `_audit` など）は MoleSignal のみが書き込み、パブリック取り込みを `403` で拒否します。

## ストリームとスキーマ

ストリームは最初の書き込み時に作成され、スキーマは新しいフィールドが現れるにつれて進化します。ストリームは名前とシグナル種別で識別されるため、`default` はログ、メトリクス、トレースで同時に存在できます。[ストリーム](/ja/streams)を参照してください。

すべてのイベントには Unix エポックからのマイクロ秒単位のタイムスタンプがあります。ネイティブ JSON と Elasticsearch `_bulk` は `_timestamp` フィールドを読み取ります。`_timestamp` のないイベントには、サーバーが受け付けた時刻が付与されます。

## ネイティブ HTTP JSON

レコードの配列を `/api/v1/intake/{logs,metrics,traces}/{stream}` に POST します:

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

レスポンスは、受け付けられたレコード数と拒否されたレコード数を、拒否されたインデックスごとの理由とともに報告します:

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

OpenTelemetry SDK または Collector を `/api` ベースパスに向けます。エクスポーターは `/v1/logs`、`/v1/metrics`、`/v1/traces` を追加し、これらは `/api/v1/logs`、`/api/v1/metrics`、`/api/v1/traces` にマッピングされます。

<Tabs>
  <Tab title="OTLP over HTTP">
    SDK の環境変数:

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    protobuf（`application/x-protobuf`）を送信します。これは SDK と Collector のデフォルトのエンコーディングです。ログ、メトリクス、トレースは JSON（`application/json`）も受け付けます。`default` 以外のストリームを選択するには `stream-name` ヘッダーを追加します。このヘッダーは、そのエクスポーターを通じて送信されるすべてのシグナルに適用されます。
  </Tab>
  <Tab title="OTLP over gRPC">
    OTLP gRPC レシーバーはポート `4317` で待ち受け、ログ、メトリクス、トレース、プロファイルの各サービスを提供します。TLS を終端しません。信頼されたネットワークを出るトラフィックでは、その手前で TLS を終端してください。

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    TLS 終端プロキシがポートの手前に配置されている場合は、`insecure: true` を削除します。ポート `5082` はクラスター内部の gRPC ポートであり、OTLP レシーバーではありません。
  </Tab>
</Tabs>

OTLP メトリクスはデータポイントごとに 1 イベントとして保存されます。保存されるフィールドについては[メトリクス保存契約](/ja/query#otlp-メトリクスのフィールド)を参照してください。

## Prometheus remote_write

`prometheus.yml` に MoleSignal をリモート書き込みターゲットとして追加します:

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

メトリクスストリームは 1 つのソースのメトリクスを保持するため、`stream-name` ヘッダー（`remote_write` エントリの `headers:`）を使って各 Prometheus サーバーに専用のストリームを割り当てます。これがない場合、サンプルは `default` に送られます。ヘッダーを設定できない送信元は、代わりに URL でストリームを指定します（例: `/api/v1/prometheus/api/v1/write?stream=aliyun`）。各サンプルは、`metric_name` がその `__name__` である行になります。他のラベルはフィールドになり、`metric_name` のようにメトリクスフィールドと同じ名前のラベルは `exported_<name>` として保持されます。ネイティブヒストグラムとメトリクスメタデータはスキップされ、エグザンプラーはサンプルの横に保存されます。

## Elasticsearch バルク

Elasticsearch バルクプロトコルを話す送信元は、Loki または OTLP に依存せずに動作します:

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

各アクションの `_index` が送信先ストリームを選択します。これがない場合は `stream-name` ヘッダーが適用され、それもなければ `default` になります。

## Loki push

このエンドポイントは Loki の JSON リクエスト形式を受け付けます:

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

ラベルはフィールドになり、ログ行は `message` フィールドになり、ナノ秒のタイムスタンプはマイクロ秒に変換されます。レスポンスは `204` です。送信先ストリームは `stream-name` ヘッダーで選択します。

## Splunk HEC

Splunk HTTP Event Collector プロトコルに対応した送信元（Tencent Cloud CLS から Splunk への転送や、Vector および Fluent Bit の Splunk 出力など）は、そのまま MoleSignal に送信できます。HEC アドレスには `https://molesignal.example.com/api/v1` を、HEC トークンにはログの書き込み権限を持つ API Token を指定し、`Authorization: Splunk <token>` として送信します。

| エンドポイント | ボディ |
|---|---|
| `POST /api/v1/services/collector/event`（`/services/collector` も同様） | JSON オブジェクトを連続して送信。各オブジェクトは `{"time", "host", "source", "sourcetype", "index", "event", "fields"}` |
| `POST /api/v1/services/collector/raw` | テキスト。1 行に 1 ログイベント。`host`、`source`、`sourcetype`、`index` はクエリから取得します |
| `GET /api/v1/services/collector/health` | トークンなしで `{"text":"HEC is healthy","code":17}` を返します |

`event` が JSON オブジェクトの場合はその内容がログのフィールドになり、それ以外の `event` は `message` になります。`fields`、`host`、`source`、`sourcetype` はフィールドになり、秒単位の `time` は時刻になります。`index` はストリーム名を指定し、ない場合は `index` クエリパラメータ、それもない場合は `stream-name` ヘッダー、さらにない場合は `default` が使われます。応答は `{"text":"Success","code":0}`、または HEC 独自のエラーコードと `400` です。値がフィールドの型に合わないためにストリームがイベントを拒否した場合、他のイベントは書き込まれ、応答はコード `6` になり、最初に拒否されたイベントのボディ内の位置が `invalid-event-number` に、理由が `text` に格納されます。インデクサーの確認応答は提供されません。
