すべてのシグナルは取り込み API を通じて MoleSignal に入ります。Web UI の **データソース** ページでは、送信元ごとにエンドポイント、トークン、設定スニペットを生成します。同じプロトコルは手動で設定することもできます。

## データソースページ

送信元のオンボーディングを開始するには、**データソース** を開きます:

1. カタログを検索するか、カテゴリで絞り込みます: **推奨**、**インフラストラクチャ**、**クラウド**、**データベース**、**メッセージング**、**アプリと言語**、**セキュリティ**、**カスタム**。シグナルのタブ（**ログ**、**メトリクス**、**トレース**、**プロファイル**）で一覧をさらに絞り込めます。
2. Kubernetes、Linux ホスト、AWS、OpenTelemetry SDK、Web RUM などの送信元を選択します。
3. ガイドの 3 つのステップに従います:
   - **エンドポイントとトークン** には、データの送信先と認証に使用するトークンが表示されます。**トークンを表示** で、スコープ、ワークスペース、有効期限とともにトークンが表示されます。RUM の送信元の場合は、先に **RUM アプリケーション** を選択します。選択すると、そのクライアントトークンが表示されます。
   - **送信元の設定** には、実際のエンドポイントとトークンが入力済みのコマンドと設定が表示されます。
   - **データの受信を確認** は、レシーバーを確認してから、過去 1 時間に受信したデータを検索します。**接続を確認** はすぐに確認を実行し、数値は 30 秒ごとに更新されます。
4. 検証の結果を確認します:
   - **データ受信を確認済み**: 過去 1 時間にデータが到着しており、送信元のシグナルは正常です。**受信データを表示** でデータを開き、**パイプラインを作成** でそのデータ用のパイプラインを開始します。
   - **レシーバーは正常ですが、データの確認が必要です**: レシーバーは応答していますが、データが到着していないか、すべてのシグナルが正常ではありません。デプロイメントを確認するか、次のバッチを待ちます。
   - **検証失敗**: レシーバーを確認できませんでした。**考えられる原因** には、コレクターが実行されていない、トークンが無効または期限切れである、ネットワークやプロキシがエンドポイントをブロックしている、といった原因が一覧表示されます。

エンドポイントは、`http.external_url` が設定されている場合はその値から、設定されていない場合はブラウザのアドレスから取得されます。リバースプロキシの背後では `http.external_url` を設定して、生成されるスニペットがパブリックアドレスを指すようにします。詳しくは [設定](/ja/configuration) を参照してください。

## 取り込みトークン

送信元はベアラートークンで認証します: `Authorization: Bearer <token>`。クラウドプロバイダーのマネージド Prometheus の remote write エクスポートなど、Basic 認証しか利用できない送信元は、任意のユーザー名とともに API Token を `Authorization: Basic` のパスワードに指定します。他の Basic 認証情報は無視されるため、独自の認証を要求するリバースプロキシもそのまま動作します。Splunk HEC の送信元は、`Authorization: Splunk <token>` としてトークンを提示します。

| トークン | 権限 | 作成方法 | 用途 |
|---|---|---|---|
| デフォルトの取り込みトークン | `logs.write`、`metrics.write`、`traces.write`、`profiles.write`、および `apm.deploy` のみ: **データ取り込み** ポリシー | データソースページ、または `GET /api/v1/me/api-tokens/default` | ログ、メトリクス、トレースを送信するコレクター、エージェント、SDK エクスポーター、および [デプロイメントを報告する](/ja/apm/deployments#ci-からデプロイを報告する) パイプライン。有効期限はありません。 |
| RUM クライアントトークン | `rum.write` のみ、1 つのアプリケーションにバインド | Web RUM およびモバイル RUM の送信元のデータソースページ、または `GET /api/v1/auth/tokens/rum?applicationId=<id>` | ブラウザおよびモバイルのコード。トークンはエンドユーザーに表示されます。 |
| 個人またはサービスアカウントのトークン | そのメンバーまたはサービスアカウントが実行できる内容を、スコープで絞り込んだもの | **アカウント設定 → API トークン**、またはサービスアカウントの場合は **ID とアクセス → API トークン** | 自動化、スクリプト、MCP クライアント。 |

継続的に実行される送信元には、デフォルトの取り込みトークン、または **データ取り込み** ポリシーに従うサービスアカウントのトークンを使用します。トークンを即座に停止するには、**アカウント設定 → API トークン** または **ID とアクセス → API トークン** から取り消します。Web UI のサインインセッションではデータを送信できません。セッションはブラウザの Cookie に保存されており、`Authorization` ヘッダーでは受け付けられません。

**データソース** ページでは、アプリケーション ID を入力すると RUM クライアントトークンが作成されます。アプリケーション ID は `A-Z`、`a-z`、`0-9`、`.`、`_`、`:`、`-` からなる 1〜128 文字です。SDK では同じ ID を `applicationId` として使用します。詳しくは [ブラウザ RUM SDK](/ja/rum/browser-sdk) を参照してください。

## エンドポイントとプロトコル

| プロトコル | エンドポイント | 互換性のある送信元 | ターゲットストリーム |
|---|---|---|---|
| ネイティブ HTTP JSON | `POST /api/v1/intake/{logs,metrics,traces}/{stream}` | `curl`、アプリケーションコード、Vector の `http` シンク、Fluent Bit の `http` 出力 | `{stream}` パスセグメント |
| HTTP 経由の OTLP | `POST /api/v1/logs`、`/api/v1/metrics`、`/api/v1/traces` | OpenTelemetry SDK および Collector | `stream-name` ヘッダー、なければ `default` |
| gRPC 経由の OTLP | `:4317` | OpenTelemetry SDK および Collector | `stream-name` メタデータ、なければ `default` |
| Prometheus remote_write | `POST /api/v1/prometheus/api/v1/write` | Prometheus、VictoriaMetrics、クラウドマネージド Prometheus のエクスポート、任意の remote_write v1 送信元 | `stream-name` ヘッダー、なければ `?stream=`、それもなければ `default` |
| Elasticsearch `_bulk` | `POST /api/v1/_bulk` | Filebeat、Logstash、Vector の `elasticsearch` シンク | 各アクションの `_index`、なければ `stream-name` ヘッダー、それもなければ `default` |
| Splunk HEC | `POST /api/v1/services/collector/event`、`/api/v1/services/collector/raw` | Tencent Cloud CLS、Vector および Fluent Bit の Splunk 出力、SIEM フォワーダー | 各イベントの `index`、なければ `?index=`、それもなければ `stream-name` ヘッダー、それもなければ `default` |
| Loki push（JSON） | `POST /api/v1/loki/api/v1/push` | Loki の JSON 形式を POST できる送信元 | `stream-name` ヘッダー、なければ `default` |
| Amazon Data Firehose、Google Cloud Pub/Sub push、クラウドのイベントバス、Cloudflare Logpush、Heroku | `/api/v1/_kinesis_firehose`、`/api/v1/_gcp_pubsub`、`/api/v1/_cloud_events`、`/api/v1/_cloudflare`、`/api/v1/_heroku` | Firehose 経由の CloudWatch Logs および CloudWatch Metric Streams、Pub/Sub 経由の Cloud Logging、EventBridge、Event Grid、CloudEvents の送信元、Cloudflare、Heroku | コネクターで設定します。詳しくは [コネクター](/ja/connectors) を参照してください。 |

プッシュコネクターを除くすべてのエンドポイントでは、シグナルの書き込み権限を持つベアラートークンが必要です: `logs.write`、`metrics.write`、`traces.write`、または `profiles.write`。組織はトークンから特定され、URL に現れることはありません。

### 送信元に影響する制限

- **リクエストサイズ。** ネイティブ JSON の取り込みとプッシュコネクターは展開後のサイズで最大 16 MiB、Firehose は最大 64 MiB のリクエストボディを受け付けます。その他の取り込みエンドポイントは最大 2 MiB です。それを超えるボディは `413` で拒否されます。バッチはそのサイズ以下に保ちます。
- **圧縮。** HTTP 経由の OTLP は圧縮されたリクエストボディを受け付けず、`400` を返します。送信元で圧縮を無効にしてください。OpenTelemetry Collector の `otlphttp` エクスポーターはデフォルトで gzip 圧縮するため、`compression: none` が必要です。ネイティブ JSON の取り込み、Elasticsearch `_bulk`、Loki push、プッシュコネクターは `Content-Encoding: gzip` を受け付けます。
- **Loki のエンコーディング。** デコードされるのは JSON リクエスト形式のみです。Promtail と Grafana Alloy はデフォルトで snappy 圧縮した protobuf を送信するため、このエンドポイントには送信できません。
- **レート制限。** `router` ロールは組織ごとにリクエストを制限し、`Retry-After` ヘッダーとともに `429` を返します。`standalone` ノードにはこの制限は適用されません。詳しくは [ロールベースのデプロイメント](/ja/deployment/role-based#レート制限) を参照してください。
- **プラットフォームストリーム。** [プラットフォームストリーム](/ja/streams#プラットフォームストリーム)（サービス自身のテレメトリー用の `_molesignal` や監査証跡用の `_audit` など）は MoleSignal のみが書き込み、公開された取り込みは `403` で拒否されます。

## ストリームとスキーマ

ストリームは最初の書き込み時に作成され、スキーマは新しいフィールドが現れるたびに進化します。ストリームは名前とシグナル種別で識別されるため、`default` はログ、メトリクス、トレースに同時に存在できます。詳しくは [ストリーム](/ja/streams) を参照してください。

すべてのイベントは、Unix エポックからのマイクロ秒単位のタイムスタンプを持ちます。ネイティブ JSON と Elasticsearch `_bulk` は `_timestamp` フィールドを読み取ります。`_timestamp` のないイベントには、サーバーが受け付けた時刻が設定されます。

## ネイティブ HTTP JSON

レコードの配列を `/api/v1/intake/{logs,metrics,traces}/{stream}` に POST します:

```bash
curl -X POST http://localhost:5080/api/v1/intake/logs/app \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d "[{\"_timestamp\":$(date +%s)000000,\"level\":\"error\",\"msg\":\"db pool exhausted\",\"trace_id\":\"abc123\"}]"
```

レスポンスには、受け入れられたレコード数と拒否されたレコード数、および拒否されたインデックスごとの理由が示されます:

```json
{"accepted":1,"rejected":0,"errors":[]}
```

## OpenTelemetry

OpenTelemetry SDK または Collector の接続先を `/api` ベースパスに設定します。エクスポーターは `/v1/logs`、`/v1/metrics`、`/v1/traces` を付加し、これらは `/api/v1/logs`、`/api/v1/metrics`、`/api/v1/traces` にマッピングされます。

<Tabs>
  <Tab title="HTTP 経由の OTLP">
    SDK の環境変数:

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlphttp/molesignal:
        endpoint: http://localhost:5080/api
        compression: none
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    protobuf (`application/x-protobuf`) を送信します。これは SDK と Collector のデフォルトのエンコーディングです。ログ、メトリクス、トレースでは JSON (`application/json`) も受け付けます。`default` 以外のストリームを選択するには、`stream-name` ヘッダーを追加します。このヘッダーは、そのエクスポーターを通じて送信されるすべてのシグナルに適用されます。
  </Tab>
  <Tab title="gRPC 経由の OTLP">
    OTLP gRPC レシーバーはポート `4317` で待ち受け、ログ、メトリクス、トレース、プロファイルの各サービスを提供します。TLS を終端しません。信頼されたネットワークの外に出るトラフィックでは、その前段で TLS を終端してください。

    ```bash
    export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
    export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
    export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
    ```

    OpenTelemetry Collector:

    ```yaml
    exporters:
      otlp/molesignal:
        endpoint: localhost:4317
        tls:
          insecure: true
        headers:
          authorization: "Bearer ${env:MS_TOKEN}"
    ```

    TLS 終端プロキシがポートの前段にある場合は、`insecure: true` を削除します。ポート `5082` はクラスター内部の gRPC ポートであり、OTLP レシーバーではありません。
  </Tab>
</Tabs>

OTLP メトリクスはデータポイントごとに 1 つのイベントとして保存されます。保存されるフィールドについては、[メトリクス保存コントラクト](/ja/query#otlp-メトリクスのフィールド)を参照してください。

## Prometheus remote_write

`prometheus.yml` に MoleSignal をリモート書き込みターゲットとして追加します:

```yaml
remote_write:
  - url: http://localhost:5080/api/v1/prometheus/api/v1/write
    authorization:
      credentials: "${MS_TOKEN}"
```

メトリクスストリームは 1 つのソースのメトリクスを保持するため、各 Prometheus サーバーに `stream-name` ヘッダー（`remote_write` エントリの `headers:`）で専用のストリームを割り当てます。これがない場合、サンプルは `default` に送られます。ヘッダーを設定できない送信者は、代わりに URL でストリームを指定します（例: `/api/v1/prometheus/api/v1/write?stream=aliyun`）。各サンプルは 1 行になり、その `metric_name` は `__name__` です。その他のラベルはフィールドになり、`metric_name` のようなメトリクスフィールドと同じ名前のラベルは `exported_<name>` として保持されます。ネイティブヒストグラムとメトリクスメタデータはスキップされ、エグザンプラーはサンプルの横に保存されます。

## Elasticsearch バルク

Elasticsearch バルクプロトコルを話す送信者は、Loki や OTLP への依存なしで動作します:

```bash
curl -X POST http://localhost:5080/api/v1/_bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/x-ndjson' \
  --data-binary $'{"index":{"_index":"app"}}\n{"level":"info","msg":"hello"}\n'
```

各アクションの `_index` がターゲットストリームを選択します。これがない場合は `stream-name` ヘッダーが適用され、それもなければ `default` が適用されます。

## Loki プッシュ

このエンドポイントは Loki の JSON リクエスト形式を受け付けます:

```json
{"streams":[{"stream":{"service":"checkout","level":"error"},"values":[["1700000000000000000","payment failed"]]}]}
```

ラベルはフィールドになり、ログ行は `message` フィールドになり、ナノ秒のタイムスタンプはマイクロ秒に変換されます。レスポンスは `204` です。ターゲットストリームは `stream-name` ヘッダーで選択します。

## Splunk HEC

Splunk HTTP Event Collector プロトコルを話す送信者（Tencent Cloud CLS から Splunk への転送、Vector や Fluent Bit の Splunk 出力など）は、そのまま MoleSignal に送信できます。HEC アドレスとして `https://molesignal.example.com/api/v1` を指定し、ログの書き込みが許可された API Token を HEC トークンとして `Authorization: Splunk <token>` の形式で送信します。

| エンドポイント | ボディ |
|---|---|
| `POST /api/v1/services/collector/event`、および `/services/collector` | JSON オブジェクトを連続して送信します。各オブジェクトは `{"time", "host", "source", "sourcetype", "index", "event", "fields"}` です |
| `POST /api/v1/services/collector/raw` | テキスト。1 行につき 1 つのログイベントです。`host`、`source`、`sourcetype`、`index` はクエリから取得します |
| `GET /api/v1/services/collector/health` | トークンなしで `{"text":"HEC is healthy","code":17}` を返します |

`event` が JSON オブジェクトの場合はログのフィールドになります。それ以外の `event` は `message` になります。`fields`、`host`、`source`、`sourcetype` はフィールドになり、秒単位の `time` は時刻になります。`index` はストリーム名を指定します。指定がない場合は `index` クエリパラメータ、それもない場合は `stream-name` ヘッダー、それもない場合は `default` が使用されます。応答は `{"text":"Success","code":0}` です。エラーの場合は HEC 独自のエラーコードと `400` を返します。インデクサー確認応答は提供されません。
