MoleSignal は、AI が操作できる製品機能を、特定のプロトコルに依存しない **ツールカタログ** として定義します。 Mole Agent と Inbound MCP は、アダプターごとにビジネスロジックを重複して実装せず、同じ `ToolSpec` コントラクトとサーバー側ランタイムを使用します。

現在のカタログには **254 個の登録済みツール** があります。各ツールは、固定の名前、正式な説明、入出力スキーマ、必要な IAM 権限、リスクレベル、アクセスモード、アノテーション、利用可能なサーフェスを定義します。

## ツールの粒度

適切な MoleSignal ツールは、操作の目的が 1 つに絞られ、結果の範囲も限定されています。

- 1 つのツールは、読み取り、事前チェック、変更のいずれか 1 つを不可分な操作として実行するようにします。
- 一覧表示、取得、作成、更新、削除、テスト、トリガー、キャンセル、再試行は、それぞれ別の操作にします。
- ルートを直接公開したり、任意のリクエストを組み立てる機能を提供したりせず、製品の機能を公開します。
- モデルでの処理や監査記録に適した、範囲を限定した構造化出力を返します。
- 認証情報の平文、バイナリ転送、未加工データの取り込み、シェルの実行、ブラウザーの操作は、カタログの対象外にします。

この粒度により、HTTP リソース群全体への広範なアクセスを許可せずに、 IAM とツールポリシーで個々の操作を制御できます。

## サーフェス

ツールを公開するかどうかは、ランタイムのサーフェスごとに明示的に設定します。

| サーフェス | 検出と実行 |
|---|---|
| Mole Agent | よく使うツールに加え、必要に応じて検索する組み込みツールと、使用を許可されたアウトバウンド MCP ツールに `tool_search → tools_call` を使用します。 |
| Inbound MCP | よく使う読み取りツールと承認操作に加え、`tool_search → call_read_tool` または `call_managed_tool` を使用します。 |
| オートメーション | オートメーションのサーフェスでの使用を明示的に有効にしたツールのみ利用できます。[スケジュールされたログ検査](/ja/logs/inspections)では、`query_logs`、`get_stream_schema`、`search_field_values`、`analyze_log_patterns` を利用できます。 |

サーバーは、ツール一覧の生成時と実行の直前に、そのサーフェスでツールが公開されているかを確認します。`tools/list` を経由しなくても、サーフェスごとの制限は適用されます。

## Inbound MCP でのツールの検出

Inbound MCP は `tools/list` の内容を最小限に抑えます。権限に応じて、レスポンスには以下が含まれます。

- 固定表示する 7 つの読み取りツール: `query_logs`、`query_metrics`、`list_streams`、 `get_stream_schema`、`list_traces`、`get_trace`、`get_incident`
- 承認操作: `list_agent_approvals`、`get_agent_approval`、 `execute_agent_approval`
- 実行操作: `list_agent_executions` と `get_agent_execution`
- `tool_search`、`call_read_tool`、`call_managed_tool`

IAM とツールポリシーで、任意の製品ツールをこの一覧から除外できます。

### 使用が許可されたツールをカタログで検索する

製品機能を表す語句や機能領域を指定して `tool_search` を呼び出します。

```json
{
  "query": "status page incident",
  "limit": 10,
  "includeSchema": true
}
```

検索結果には、Inbound MCP で利用でき、ワークスペースのツールポリシーで有効になっており、使用中の認証情報に利用権限があるツールのみが含まれます。要求に応じて、各結果にはスキーマと実行時に適用されるメタデータが含まれます。

### 読み取りまたは事前チェックを実行する

見つかったツールの名前と引数を `call_read_tool` に渡します。

```json
{
  "name": "list_status_page_incidents",
  "arguments": {
    "pageId": "status-page-id",
    "view": "current"
  }
}
```

MCP クライアントが Tasks 拡張機能への対応を通知している場合、`asTask` を `true` に設定すると、読み取りを永続タスクとして実行できます。返されたタスクの状態確認、更新、キャンセルには MCP のタスクメソッドを使用します。

### 管理対象の変更を実行する

一意の冪等性キーを `call_managed_tool` に渡します。

```json
{
  "name": "update_annotation",
  "arguments": {
    "annotationId": "annotation-id",
    "title": "Deployment rollback started"
  },
  "idempotencyKey": "8d7788d2-9b4e-44bd-bf35-61a5690f0064"
}
```

MoleSignal は、承認レコードを作成したり変更を実行したりする前に、認証済みのプリンシパルに対してキーを予約します。同じリクエストを再送すると、保存済みの結果または処理中のステータスが返ります。同じキーを異なる引数で再利用すると、リクエストは拒否されます。

## リスクと実行ポリシー

ツールのリスクレベルに応じて、安全なデフォルトの実行モードが決まります。ワークスペースのツールポリシーでは、より厳格な実行モードを適用できます。

| リスク | デフォルトモード | 意味 |
|---|---|---|
| L0 | 自動 | 範囲を限定した読み取り専用の操作です。 |
| L1 | 確認 | リスクの低い変更には、ポリシーで自動実行を指定しない限り、MCP ホストでの確認が必要です。 |
| L2 | 単一承認 | MoleSignal で 1 件の承認が必要です。 |
| L3 | 二重承認 | MoleSignal で 2 件の承認が必要です。 |
| L4 | 無効 | リスクの高い、または破壊的なリモート操作は、デフォルトでは利用できません。 |

管理対象の変更を自動実行する場合も、監査可能な承認レコードを作成します。確認モードでは、 MCP で複数回の入力を求めるフローを使用できます。単一承認モードと二重承認モードでは、MoleSignal での審査を待ちます。必要な審査が完了したら、最初のリクエストの送信元は、別の `idempotencyKey` を指定して `execute_agent_approval` を呼び出し、操作を完了できます。

実行前に、ランタイムは以下の項目を再検証します。

1. 認証済みのプリンシパルと組織の状態
2. 必要な IAM 権限と権限モード
3. サーフェスでの公開設定と現在のツールポリシー
4. 入力スキーマ、対象リソースの状態、リスク
5. タイムアウト、レスポンスサイズの上限、冪等性
6. 操作後の検証と監査記録

## カタログの対象範囲

このカタログは、AI による調査と管理に安全かつ有用な製品操作を対象とします。

| 領域 | 主な機能 |
|---|---|
| ログ、メトリクス、ストリーム | テレメトリをクエリし、スキーマや設定を確認し、前後のイベントを検索し、メトリクスのラベルや系列を探索します。ログをパターン別にグループ化してベースライン期間と比較し、メトリクスがいつ変化し始めたか、変化の大きさ、変化の要因となった系列やラベルを要約します。データの準備状況（サービス、環境、トレース ID が記録されているか、シグナル間でサービス名が統一されているか、メトリクス名に単位が含まれているか）を確認します。スケジュール済みのログ検査とそのレポートを確認したり、ログ検査をすぐに実行したりできます。 |
| トレース、APM、RUM、プロファイル | トレース、サービスのトポロジー、セッション、エラー、依存関係、フレームグラフ、シグナル間の相関を確認します。APM インサイトと、サービスマップ上でサービスが到達する先を確認します。名前、エイリアス、説明、タグでサービスカタログを検索します。Core Web Vitals をページごとに要約します。RUM アプリケーションの概要をまとめ、問題を一覧表示して詳細を確認し、ユーザーが不満を感じる要因を特定します。個別のビューのウォーターフォールを確認し、任意の RUM ストリームを集計します。 |
| アラートとインシデント | インシデントとオンコールの状況を確認します。過去 90 日間の類似インシデントを探し、指定した時刻やインシデントの前後のデプロイ、設定変更、機能フラグを一覧表示します。アラートルールを作成、更新、削除、テスト、またはトリガーします。インシデントを確認済みにするか、解決します。 |
| ダッシュボード、レポート、アノテーション | ダッシュボード、フォルダー、パネル、アノテーション、レポートテンプレート、スケジュール、配信を管理します。 |
| 検索ジョブと保存済みビュー | 永続化される検索を送信、確認、キャンセル、再試行、または削除し、保存済みビューを管理します。 |
| パイプライン、関数、エンリッチメント、コネクター | スケジュール実行を確認し、関数を管理し、変換をテストし、エンリッチメントやコネクターのメタデータを確認します。 |
| Synthetic Monitoring とステータスページ | モニターと結果を確認し、モニターを実行または一時停止し、ステータスページのライフサイクルと自動化を管理し、インシデントのポストモーテムの下書きを作成します。 |
| 通知 | コネクター、ポリシー、テンプレート、配信を確認します。配信を再試行するか、確認済みにします。 |
| IAM と管理 | ユーザー、チーム、ロール、機能、監査イベント、サービスアカウント、API トークンのメタデータを参照します。認証情報のうち、シークレットを含まない状態を管理します。 |
| Mole Agent の制御 | 調査、承認、実行、自動化を確認し、権限がある場合は承認済みの操作を実行します。 |

利用するインターフェースに応じた機能の概要を取得するには、`get_platform_capabilities` を呼び出してください。固定のリストに頼らず、 `tool_search` を呼び出して、現在利用を許可されているツールの名前とスキーマを取得してください。

## ID とシークレットの境界

- 認証済みの認証情報から、呼び出し元の `userId` と `orgId` を取得します。
- `get_user_profile` と `get_user_preferences` は、リソースの選択に限り、オプションの `target_user_id` を受け付けます。他のメンバーの情報を参照するには、`org.members.read` 権限と、そのメンバーが組織に所属していることの確認が必要です。
- 読み取りツールと一覧表示ツールは、認証情報のメタデータのみを返します。
- `create_api_token` と `create_service_account` は、どちらも平文のシークレットを一度だけ返すため、 Inbound MCP では使用できません。これらの認証情報は Web UI で作成してください。
- 既存のサービスアカウントと API トークンは、権限が付与されたシークレットを扱わないツールを使って、一覧表示、更新、有効化、無効化、失効、削除ができます。
- `query_logs`、`search_around`、`search_field_values`、`get_stream_schema`、およびストリームスキーマのリソースは、認証情報にかかわらず、[`_audit` ストリーム](/ja/settings/data-security#監査ストリーム)へのアクセスを拒否します。

カタログでは、ログイン、登録、パスワードのリセット、認証不要の公開ルート、加工前の OTLP または Prometheus データの取り込み、外部 Webhook、バイナリのアップロードとダウンロード、ノードのドレイン、ランタイムプロファイリング、任意の HTTP リクエスト、シェル実行、ブラウザーでの実行を意図的に対象外としています。

## MCP のリソース、プロンプト、タスク

Inbound MCP では、プラットフォーム機能、ツールカタログ、承認、実行、検索ジョブ、ストリームスキーマのリソースも IAM 権限に応じて公開します。組み込み、組織、現在のユーザーの Mole Agent プロンプトは、`prompts/list` と `prompts/get` で利用できます。

時間のかかる読み取り操作は、MCP タスクとして実行できます。進捗通知、リソースのサブスクリプション、カタログ変更通知は、ネゴシエーションで合意した MCP プロトコルのバージョンが対応している場合に利用できます。
