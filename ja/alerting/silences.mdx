サイレンスは、一致するインシデントの通知とエスカレーションを一時停止しますが、インシデントの記録は続けます。セマンティックグループは、関連するインシデントをまとめ、対応担当者が一度に対処できるようにします。どちらの機能もルールを変更しません。重大度の高いインシデントが発生している間、重大度の低いインシデントの通知を抑制するには、 [抑制](/ja/alerting/inhibition)を使用します。

## サイレンスポリシー

**アラート → サイレンスポリシー**を開きます。各ポリシーには、状態、適用期間、マッチ条件が表示されます。

| 状態 | 意味 |
|---|---|
| **サイレンス適用中** | 条件に一致するインシデントにサイレンスを適用しています。 |
| **開始前** | 適用期間はまだ始まっていません。 |
| **適用時間外** | 現在は繰り返しスケジュールの適用時間外です。 |
| **終了日時** | 適用期間が終了しています。 |
| **オフ** | ポリシーは無効です。 |

ポリシーを作成するには、次の手順に従います。

1. **サイレンスポリシーを作成**を選択し、**名前**を入力します。**有効**はオンのままにします。
2. **マッチ条件**で、インシデントのラベルに対する条件ごとに**マッチャーを追加**を選択します。条件の例は `service` `=` `checkout` です。すべてのマッチャーに一致する必要があります。`=~` と `!~` には正規表現を指定します。マッチャーを指定しない場合、ポリシーは**すべてのインシデント**に一致します。
3. **適用期間**で、**期間の種類**を選択します。
   - **固定期間**：**開始**と**終了**を指定します。
   - **毎週**：**タイムゾーン**と、1つ以上の時間帯を指定します。時間帯ごとに**曜日**、 **開始時刻（HH:MM）**、**終了時刻（HH:MM）**を指定します。時刻は分単位で指定します。たとえば、毎週土曜日の02:00から 06:00までです。終了時刻が開始時刻以前の場合は、翌日まで適用します。**祝日**では、 [祝日カレンダー](/ja/alerting/on-call#休日カレンダー)の休日を適用対象から除外したり、休日にのみ適用したりできます。
   - **祝日**：**タイムゾーン**と**祝日カレンダー**を指定します。カレンダー上のすべての休日に終日適用します。たとえば、祝日にテスト環境からの通知を停止する場合に使用します。
   - **毎月**：**タイムゾーン**と、**日（毎月）**（指定日がない月は月末日）または**第何**（第1〜第5、または最終）と**曜日**の組み合わせを指定します。**開始時刻 (HH:MM)**と **継続時間 (分)**も指定します。継続時間は最大7日間です。たとえば、毎月第1日曜日の 02:00から240分間です。第5に指定した曜日がない月はスキップします。
4. **コメント**で**理由**を入力し、**サイレンスを作成**を選択します。

一覧には、繰り返しサイレンスの次回の開始日時または終了日時が表示されます。サーバーは自身のタイムゾーンを使い、夏時間を考慮して日時を計算します。

サイレンスは、インシデントに付与されたラベルに照合します。対象は、ルールのラベルと、 [分割ルール](/ja/alerting/rules#列でルールをグループ化する)のグループの値です。[外部アラート](/ja/alerting/sources)のインシデントには、 `alert.source=external`、`external.kind`（`alertmanager` など）、アラート自体のラベル、ソースの追加ラベルが付与されます。たとえば、`external.kind` `=` `grafana` は、Grafanaが送信するすべてのアラートにサイレンスを適用します。計画したサイレンスには必ず対象サービスと終了時刻を明記し、後から削除するのではなく、設定した時刻に自動で終了するようにしてください。

<Warning>
  サイレンスは通知を止めるだけで、サービスの復旧を示すものではありません。適用期間が終了したら、インシデント一覧を確認してください。
</Warning>

### サイレンス中の通知

サイレンスの適用中も、条件に一致するインシデントは通常どおりオープンし、記録されます。通知の扱いは種類によって異なります。

| 通知 | サイレンス中 | サイレンス終了後 |
|---|---|---|
| アラート発生、アラートのエスカレーション | 送信しません。エスカレーションは現在のステップで停止します。 | インシデントが未確認かつ未解決の場合は、発生通知を送信し、エスカレーションを再開します。現在のステップの確認待ちがサイレンス中にタイムアウトした場合は、次のステップの通知をすぐに送信します。サイレンス中に確認済みまたは解決済みになったインシデントについては、通知を送信しません。 |
| 個人の通知順序の後続ステップ、通知ポリシーの確認タイムアウトによるエスカレーション | 送信しません。 | インシデントが未確認の間は送信します。 |
| アラート確認、アラート解決 | サイレンス開始前に発生通知を送信していれば送信します。サイレンスによって発生通知を止めた場合は送信しません。 | 通常どおり送信します。 |

サイレンスは、適用期間が終了するか、ポリシーを無効化または削除すると終了します。

### 1件のインシデントにサイレンスを適用する

インシデントの**サイレンス**を選択すると、そのインシデントに限り、通知とエスカレーションを**1時間**、 **4時間**、**24時間**、または**7日間**停止します。必要に応じて**理由**を入力できます。ルールを無効化したり、同じサービスのほかのインシデントにサイレンスを適用したりすることはありません。サイレンスは**サイレンスポリシー**に表示され、そこで変更したり、適用期間の途中で削除したりできます。

サイレンスの作成、変更、削除には `alerts.mutes.manage` が必要です。

## セマンティックグループ

**アラート → グループ**を開きます。セマンティックグループは、Alertmanagerの `group_by` と同様に、ラベル値が同じインシデントをまとめます。APIでグループを確認済みまたは解決済みにすると、グループ内のすべてのインシデントに同じ操作を適用します。[インシデントのグループ](/ja/alerting/incidents#インシデントのグループ)を参照してください。

1. **新規グループ**を選択し、`critical-by-service` などの**名前**を入力します。**有効**はオンのままにします。
2. **マッチャー**で、インシデントが満たすべき条件を追加します。たとえば、`severity` = `critical` です。すべての条件に一致する必要があります。条件を指定しない場合は、すべてのインシデントが対象になります。
3. **グループ化の基準**で、`service, region` のように**グループ化に使うラベル**をカンマ区切りで入力します。指定したラベルの値が同じインシデントを1つのグループにまとめます。
4. **グループを作成**を選択します。

無効なグループは適用しません。グループを削除してもインシデントは残り、グループ化だけが解除されます。

**インポート**では、グループの配列、または `groups` 配列を含むオブジェクトをJSONで指定して、グループを作成します。

```json
[
  {
    "name": "crit-by-service",
    "enabled": true,
    "matchers": [{ "label": "severity", "op": "eq", "value": "critical" }],
    "groupBy": ["service"]
  }
]
```

グループの管理には `alerts.semantic_groups.manage` が必要です。
