データベースが停止すると、それに依存する10個のサービスがすべてエラーを報告します。オンコール担当者に必要なのはデータベースの障害通知であり、残りは不要な呼び出しです。抑制ルールでは、**抑制元のインシデントがアクティブな間、指定されたラベルの値が一致する抑制対象のインシデントの通知を保留します。**

抑制対象のインシデントも通常どおり起票・記録し、各ページに表示します。通知は保留し、エスカレーションは行いません。抑制元が復旧すると、未解決の抑制対象について通常どおり通知します。

**アラート → 抑制**を開きます。閲覧には `alerts.inhibitions.read`、作成・変更・削除には `alerts.inhibitions.manage` が必要です。

## 抑制とサイレンス

| | サイレンス | 抑制 |
|---|---|---|
| 適用されるタイミング | 指定した時間帯 | 条件に一致するインシデントがアクティブな間 |
| 適した用途 | 計画メンテナンス、既知のノイズ | 1つの障害から連鎖的に発生するアラート |
| 保留対象の決め方 | 担当者が事前に時間帯を指定します | システムが現在アクティブなインシデントに基づいて判断します |

どちらも保留するのは通知とエスカレーションだけです。インシデント自体、[ステータスページ](/ja/status-pages)、[チケット](/ja/alerting/tickets)には影響しません。

## ルールを作成する

**新規抑制ルール**をクリックします。

| 設定 | 説明 |
|---|---|
| **名前**、**有効** | 無効なルールはインシデントを抑制しません。 |
| 抑制元の**重大度の下限**、ラベル条件 | どのインシデントが抑制元になれるかを指定します。空欄の場合はすべてのインシデントが該当しますが、**一致が必要なラベル**の指定が必須です。 |
| 抑制対象の**重大度の上限**、ラベル条件 | どのインシデントを抑制するかを指定します。空欄の場合はすべてのインシデントが該当します。 |
| **一致が必要なラベル** | カンマ区切りで指定します。抑制元と抑制対象の両方に同じ値のラベルが必要です。片方にラベルがなければ一致しません。空欄の場合はラベルの一致を確認しないため、抑制元の条件を指定する必要があります。指定しないと、どのインシデントも他のすべてを抑制することになります。 |
| **抑制元の重大度が抑制対象より高い場合のみ** | デフォルトでオンです。抑制元の重大度が抑制対象より高い場合に限って抑制します。たとえば、同じサービス内で重大度が高いインシデントが低いインシデントを抑制するルールに使います。データベースが依存先のサービスを抑制するなど、依存関係に基づくルールではオフにします。 |
| **抑制対象の待機時間（秒）** | デフォルトは60秒で、15～600秒の範囲で指定します。[2つの待機時間](#2つの待機時間)を参照してください。 |
| **復旧後の抑制継続時間（秒）** | デフォルトは120秒で、最大3600秒です。 |

ラベル条件は[サイレンスポリシー](/ja/alerting/silences)と同じ形式で記述します。すべての条件を満たす必要があり、`=~` と `!~` は値全体を対象とする正規表現です。インシデントのラベルに加えて、次の3つも指定できます。

- `service` と `host`：インシデントに該当するラベルがない場合は、影響を受けたサービスまたはホストを使います。
- `alert.rule_id`：インシデントを起票したルールまたはアラートソースのIDです。「ルールAがルールBを抑制する」といった条件に使います。

**実行**をクリックすると、ルールを保存していなくても、現在アクティブなインシデントに対してルールを評価し、どのインシデントがどのインシデントを抑制するかを一覧表示します。

## よく使うルール

**同じサービス内で、重大度が高いインシデントが低いインシデントを抑制します。** 新規ルールの初期設定は次のとおりです。

- 一致が必要なラベル：`service`
- 抑制元の重大度が抑制対象より高い場合のみ：オン

**データベースが停止した場合は、それに依存するサービスの障害を通知しません。** 重大度に関係なく抑制します。

- 抑制元のラベル条件：`service` `=` `database`
- 抑制対象のラベル条件：`tier` `=` `api`
- 一致が必要なラベル：`region`（同じリージョン内のみ）
- 抑制元の重大度が抑制対象より高い場合のみ：オフ

## 抑制の判定方法

エスカレーションの配信処理は実行サイクルごと（デフォルトでは10秒ごと）に抑制を判定し、結果をインシデントに記録します。**インシデントを抑制する場合に、少なくとも1つの上流のインシデントが実際に通知されるように**、次のルールを適用します。

- **サイレンス中のインシデントは抑制元になりません。** それ自体が通知されないため、他のインシデントまで抑制すると誰にも通知が届きません。
- **確認済みのインシデントは引き続き抑制元になります。** 担当者がすでに把握しています。
- **別のインシデントに統合したインシデントは、抑制元にも抑制対象にもなりません。**
- **手動で起票したインシデントは抑制対象になりません**が、抑制元にはなれます。
- **抑制は連鎖します。** AがBを抑制し、BがCを抑制する場合、BとCは通知せず、Aだけを通知します。
- **相互に抑制する場合は、片方だけを通知します。** 2つのルールでAがBを抑制し、BがAを抑制する場合、重大度が高い方（同じなら先に起票した方）を通常どおり通知します。

## 2つの待機時間

**抑制対象は通知を待機します。** 多くの場合、原因より先に症状を検知します。たとえば、先にエラー率がしきい値を超え、その後、次のサイクルでデータベースのルールを評価します。抑制対象になり得るインシデントを起票すると、**抑制対象の待機時間（秒）**で指定した時間だけ通知を待機します。その間に抑制元が発生すれば通知を抑制し、発生しなければ通常どおり通知します。0に設定しても15秒間待機します。次の配信サイクルで抑制を判定するため、最初の通知が判定より先に送信されないようにします。

待機するのは抑制対象になり得るインシデントだけです。抑制元により高い重大度が必要な場合、重大度が最も高いインシデントは待機しません。一致が必要なラベルを持たないインシデントも待機しません。

**復旧後も抑制を継続します。** 原因が解消すると、通常は症状もまもなく収まるため、担当者を呼び出す必要はありません。抑制元が復旧した後も、設定した時間は対象の抑制を継続します。別の抑制元が発生すれば、さらに継続します。抑制が終了した時点で未解決のインシデントについてのみ、保留した通知を送信します。

## 通知の動作

| 通知 | 抑制中 | 抑制終了後 |
|---|---|---|
| 発報、エスカレーション | 送信しません。エスカレーションは現在のレベルで停止します。 | 未確認かつ未解決のインシデントについて発報通知を送信し、エスカレーションを再開します。そのレベルの確認タイムアウトはこの時点から計測します。抑制中に確認または解決したインシデントには送信しません。 |
| 個人の通知順序の後続ステップ、ポリシーの確認タイムアウト | 送信しません。 | 未確認のままであれば送信します。 |
| 確認済み、解決済み | 発報通知を送信済みの場合のみ送信します。 | 通常どおり送信します。 |

## 各ページでの表示

- **インシデント一覧**：抑制したインシデントの概要行に**抑制中**と表示します。抑制中のインシデントが1件以上ある間は、**抑制中**ビューも表示します。
- **インシデントページ**：抑制元のインシデントと適用したルールを、抑制元へのリンクとともに表示します。通知の待機中は、待機終了時刻を表示します。横にある**通常どおり通知**をクリックすると、そのインシデントの抑制を解除します。保留中の通知をすぐに送信し、そのインシデントは再度抑制しません。この操作には `alerts.incidents.update` が必要で、タイムラインと監査ログに記録します。
- **タイムライン**：抑制の開始時と終了時（抑制元の復旧、ルールの変更・削除、手動解除）に項目を追加します。
- **ルール一覧**：発生したインシデントがすべて抑制中のルールには、**発報中（抑制）**と表示します。
- **抑制ページ**：各ルールが現在抑制しているインシデントの件数を表示します。抑制中のインシデントがあるルールを削除するときは、通知を即時送信することを表示します。

即時エスカレーション、担当者の再割り当て、対応者の追加は、担当者を呼び出すための操作なので、インシデントの抑制も解除します。再割り当てと対応者の追加では、選択した担当者だけに通知します。ポリシーの現在のステップに設定されている担当者には、追加で通知しません。

## 複数クラスターでの動作

抑制ルールは[クラスターフェデレーション](/ja/settings/data-plane#クラスターフェデレーション)を通じて同期します。各クラスターは自身のインシデントに基づいて抑制を判定するため、あるクラスターのインシデントが別のクラスターのインシデントを抑制することはありません。

## 抑制API

| 操作 | エンドポイント |
|---|---|
| 抑制ルールを管理する | [`/api/v1/alerts/inhibit-rules`](/ja/api/alerting/inhibit-rules) |
| ルールをプレビューする | [`POST /api/v1/alerts/inhibit-rules/preview`](/ja/api/alerting/inhibit-rules#プレビュー) |
| インシデントの抑制を解除する | [`POST /api/v1/alerts/incidents/{id}/inhibition/lift`](/ja/api/alerting/inhibit-rules#インシデントの抑制を解除する) |
