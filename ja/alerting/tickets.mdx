チケットコネクターは、インシデントを Jira（Cloud または Data Center / Server）、ServiceNow、Meegle（中国では Feishu Project）に同期します。インシデントから手動でチケットを作成するか、ルールに従って新規インシデントのチケットを自動作成します。作成後、チケットはインシデントに追従します。確認、解決、メモはコメントとして投稿され、インシデントを解決するとチケットが完了になります。チケットのステータスは 5 分ごとに MoleSignal に同期されます。Jira は変更を Webhook で即時に通知することもできます。

**アラート → チケット**を開きます。閲覧には `alerts.tickets.read`、コネクターの管理には `alerts.tickets.manage`、インシデントからのチケット作成には `alerts.incidents.tickets` が必要です。

## Jira に接続する

**新規チケットコネクター**を選択し、**Jira** を選びます。

| 設定 | 補足 |
|---|---|
| **サイトアドレス** | 例: `https://example.atlassian.net`。 |
| デプロイメント | **Jira Cloud** では、**アカウントのメールアドレス**と、Atlassian アカウント設定のセキュリティページで作成した **APIトークン**を使ってサインインします。**Jira Data Center / Server** では、**パーソナルアクセストークン**を使います。 |
| **プロジェクトキー**、**課題タイプ** | 例: `OPS` と `Incident`。 |
| **インシデントの優先度に応じたチケットの優先度** | 組織のインシデントの優先度（デフォルトでは P1〜P5）ごとに Jira の優先度名を指定し、次に重大度ごとに指定します。たとえば、P1 には `Highest` を指定できます。インシデントに優先度がない場合や、該当する優先度の設定が空欄の場合は、重大度に対応する設定を使います。すべて空欄の場合は、優先度を設定しません。 |
| **ラベル** | チケットに追加するラベルです。すべてのチケットに `molesignal` も追加します。 |
| **解決時のトランジション** | トランジションの名前または ID です。空欄の場合は、完了ステータスに移行する最初のトランジションを使います。 |
| **Webhook シークレット** | Jira の Webhook を受け付けるにはシークレットが必要です。[ステータス同期](#ステータス同期)を参照してください。 |

アカウントには、プロジェクトで課題を作成し、コメントを追加し、トランジションを実行する権限が必要です。保存後、 **接続をテスト**を選択します。接続に成功すると、接続に使ったアカウントが表示されます。

## ServiceNow に接続する

**新規チケットコネクター**をクリックし、**ServiceNow** を選択します。コネクターは Table API を使い、チケットをテーブル内のレコードとして扱います。

| 設定 | 説明 |
|---|---|
| **インスタンスのアドレス**、**テーブル** | 例: `https://example.service-now.com` と `incident`。テーブルは `task` を拡張している必要があります。 |
| 認証 | **ユーザー名とパスワード**、**OAuth クライアント認証情報**（インスタンスのプロパティ `glide.oauth.inbound.client.credential.grant_type.enabled` でこのグラントを許可する必要があります）、**API キー**（Washington DC リリース以降で、`x-sn-apikey` ヘッダーに指定）のいずれかを使います。アカウントにはテーブルの読み取りと書き込みの権限が必要です。 |
| **割り当てグループ**、**発信者**、**カテゴリ** | チケットの作成時に書き込むフィールドです。割り当てグループと発信者は `sys_id` で指定します。空欄のフィールドは設定しません。他のフィールドは API の `settings.fields` で指定します。 |
| **インシデントに応じたチケットの優先度** | ServiceNow は影響度と緊急度から優先度を算出します。`2/1` のように `impact/urgency` 形式で指定します。数値を 1 つだけ指定すると、両方に同じ値を使います。まずインシデントの優先度に対応する設定を確認し、該当する設定がなければ重大度に対応する設定を使います。デフォルト値は、クリティカルが `1/1`、エラーが `2/1`、警告が `2/2`、情報が `3/3` です。 |
| **解決時の状態値**、**解決コード** | インシデントの解決時に書き込む `state` と `close_code` です。デフォルト値はそれぞれ `6` と `Solution provided` です。デフォルトのデータポリシーでは、解決時に解決コードとメモが必要です。`close_code` の選択肢はインスタンスによって異なります。メモには、MoleSignal でインシデントが解決されたことをワークスペースのデフォルト言語で記録します。 |
| **完了とみなすステータス** | `state` の値をカンマ区切りで指定します。デフォルト値は `6, 7, 8`（解決済み、クローズ済み、キャンセル済み）です。 |

発信者に影響しないよう、インシデントの変更は内部メモである `work_notes` に記録します。レコードの `correlation_id` はインシデント ID、`correlation_display` は `MoleSignal` です。**接続をテスト**はテーブルを 1 回読み取ります。

## Meegle に接続する

**新規チケットコネクター**を選択し、**Meegle** を選びます。まず Meegle の開発者コンソールでプラグインを作成してプラグイン ID とプラグインシークレットを取得し、チケットの作成先スペースにプラグインをインストールします。

| 設定 | 補足 |
|---|---|
| **プラットフォーム**、**サイトアドレス** | **Feishu**（Feishu Project、`https://project.feishu.cn`）または **Lark**（Meegle、`https://meegle.com`）です。サイトアドレスはプラットフォームに応じて決まります。コピーはできますが、編集はできません。 |
| **プラグイン ID**、**プラグインシークレット** | プラグイントークンの取得に使います。 |
| **操作ユーザー (user_key)** | 指定したユーザーの名義でチケットを作成し、コメントを投稿します。 |
| **スペース (project_key)**、**作業項目タイプ (work_item_type_key)** | 作業項目を作成するスペースと、作成する作業項目のタイプを指定します。 |
| **優先度フィールドキー**、優先度のマッピング | 組織のインシデントの優先度ごとに優先度オプションの値を指定し、次に重大度ごとに指定します。インシデントに優先度がない場合や、該当する優先度の設定が空欄の場合は、重大度に対応する設定を使います。すべて空欄の場合は、優先度を設定しません。 |
| **解決時のトランジション ID** | ステータスフローを使う作業項目に指定します。 |
| **解決時に完了するノード** | ノードフローを使う作業項目に指定します。 |
| **完了とみなすステータス** | ステータスキーをカンマ区切りで指定します。いずれかに該当するチケットを完了とみなします。 |

**接続をテスト**は作業項目タイプを 1 回読み取ります。認証情報、スペース、作業項目タイプがすべて正しければ、テストは成功します。

## インシデントの追跡

コネクターの**インシデントの追跡**で、チケットをインシデントに追従させる方法を設定します。

| 設定 | 動作 |
|---|---|
| **インシデントの確認時にコメントを投稿**、**インシデントの解決時にコメントを投稿** | MoleSignal でインシデントを確認または解決したことをコメントとして投稿します。 |
| **インシデントのメモをコメントとして投稿** | インシデントに追加した[メモ](/ja/alerting/incidents#メモ)をチケットのコメントとして投稿します。 |
| **インシデントの解決時にチケットを完了に変更** | 上で設定したトランジションを使ってチケットをクローズします。 |
| **チケットの完了時にインシデントを解決** | チケット側の作業が完了すると、インシデントがオープンでも確認済みでも解決します。デフォルトではオフです。 |
| **重大インシデントの宣言時にチケットを作成** | インシデントを[重大インシデント](/ja/alerting/major-incidents)として宣言すると、このコネクターでチケットを作成します。 |

チケットのタイトルは `[severity] incident summary` 形式です。本文には、インシデントの重大度とステータス、サービス、ラベル、トリガーとなったクエリ、AI による根本原因分析の要約、インシデントページへのリンクが含まれます。コメントと本文には、ワークスペースのデフォルト言語を使います。

## チケットの自動作成

**チケットを自動作成**をオンにすると、**重大度の下限**以上で、対象のサービスが **サービス**に含まれる新規インシデントに対し、このコネクターでチケットを自動作成します（空欄の場合はすべてのサービスが対象です）。各コネクターが作成するチケットは、インシデントごとに最大 1 件です。

## インシデントからチケットを作成する

インシデント詳細の**チケット**には、紐づくチケットのキー（選択するとチケットが開きます）、ステータス、最終同期日時、同期やコメント投稿時のエラーが表示されます。**チケットを作成**を選択します。コネクターが複数ある場合は、**… に作成**を選択します。チケットの作成は、インシデントのタイムラインと監査ログに記録されます。

[ポストモーテム](/ja/alerting/major-incidents#ポストモーテム)のアクションアイテムごとにチケットを作成することもできます。これらのチケットにはインシデントからコメントを投稿せず、トランジションも実行しません。チケットを完了してもインシデントは解決しません。

## ステータス同期

未完了のチケットは 5 分ごとに同期され、ステータスの変更はインシデントのタイムラインに記録されます。Jira ではステータスカテゴリで完了を判定し、Meegle と ServiceNow ではコネクターに設定したステータスで判定します。

Jira では、定期同期を待たずに変更を即時通知できます。コネクターに **Webhook シークレット**を設定すると、コネクター一覧に Jira の Webhook アドレスと**アドレスをコピー**が表示されます。Jira の **システム設定 → WebHooks** で、その URL と同じシークレットを使い、課題の更新を通知する Webhook を作成します。MoleSignal はシークレットを使って `X-Hub-Signature` を検証し、署名が一致しないリクエストを拒否します。Webhook アドレスへのアクセスにサインインは不要です。 [パブリックアクセス](/ja/public-access)を参照してください。
