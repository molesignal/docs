[ルール](/ja/alerting/rules)が発報したとき、[外形監視チェックが失敗したとき](/ja/synthetics#アラートインシデント)、または[アラートソース](/ja/alerting/sources)が外部アラートを受信したときに、インシデントが起票されます。インシデントには、ルール、値、ラベル、起票から終了までのすべての経過が記録されます。**アラート → インシデント**を開くか、`⌘⌥A` を押してください。インシデントの閲覧には `alerts.incidents.read` が必要です。確認済み、解決済み、スヌーズにするには `alerts.incidents.acknowledge` が必要です。[インシデントに対応する](#インシデントを操作する)のその他の操作には `alerts.incidents.update`、エスカレーションと統合には `alerts.incidents.escalate`、サイレンスには `alerts.incidents.silence` が必要です。アラート通知を Feishu アプリまたは Slack アプリで受信した場合は、カードから確認済み、解決済み、スヌーズにすることもできます。 [アラートカード](/ja/im#アラートカード)を参照してください。SMS や電話には、コードの返信やキーの入力で応答できます。 [SMS と電話への応答](/ja/notification-channels#メッセージへの返信と通話での応答)を参照してください。

## インシデントの状態

| 状態 | 一覧の表示ラベル | 意味 |
|---|---|---|
| `open` | **レビュー待ち** | 発報中で、まだ確認されていません。エスカレーションが続きます。 |
| `acknowledged` | **対応中** | 担当者が決まっています。エスカレーションは停止します。 |
| `resolved` | **復旧済み** | ルールが復旧したか、解決済みにする操作によってインシデントが終了しました。 |
| `closed` | **クローズ済み** | インシデントは終了しています。 |

レビュー待ちのインシデントは、ルールが[復旧条件](/ja/alerting/rules#復旧と欠損データ)を満たすと自動的に復旧します。確認済みのインシデントは、解決済みにするまで対応中のままです。エスカレーションポリシーで [確認済みだが未解決](/ja/alerting/on-call#確認済み・未解決)を設定している場合は、設定した時間が経過すると **レビュー待ち**に戻り、オンコール担当者に再通知します。スヌーズ中のインシデントは**対応中**です。外部ソースのインシデントは、確認済みかどうかにかかわらず、ソースが復旧を報告すると復旧します。 [アラートがインシデントになる仕組み](/ja/alerting/sources#アラートがインシデントになる仕組み)を参照してください。各ルールで同時にアクティブになるインシデントは最大1件です。グループに分割したルールでは、グループごとに最大1件です。

## インシデント一覧

**インシデント**画面の上部に、影響を受けたサービス数、レビュー待ちのインシデント数、過去24時間に復旧したインシデント数が表示されます。概要には、現在発報中のインシデント数、最も古いインシデントの発報からの経過時間、評価対象のルール数が表示されます。**最近復旧したインシデント**には、直近で終了したインシデントが表示されます。

**発報中**と、担当者がまだ決まっていない**レビュー待ち**を切り替えられます。チームに所属している場合は、 **所属チーム**に、所属先のチームに[ルーティングされた](/ja/alerting/routing)インシデントが表示されます。右側で優先度を指定して絞り込むか、**なし**を選択して優先度が未設定のインシデントを表示します。インシデントは重大度、優先度、発報からの経過時間の順に並びます。各行には、重大度、インシデントと対象サービス（緊急度が低い場合は**緊急度：低**も表示）、優先度、状態、継続時間、担当者とルーティング先のチームが表示され、次の3つの操作を実行できます。

| 操作 | 動作 |
|---|---|
| **確認済みにする** | 担当を引き受けます。インシデントは**対応中**になり、エスカレーションが停止します。 |
| **サイレンス** | このインシデントに限り、以降の通知とエスカレーションを一時停止します。[個別のインシデントをサイレンスする](/ja/alerting/silences#1件のインシデントにサイレンスを適用する)を参照してください。 |
| **ランブック** | ルールにランブックが設定されている場合は、対応手順を開きます。 |

行のチェックボックスをオンにするか、ヘッダーからすべての行を選択すると、一覧の上に一括操作バーが表示されます。 **確認済みにする**、**解決済みにする**、**スヌーズ**、**担当者の変更**、**調整**（重大度、優先度、緊急度）を実行できます。 2件以上を選択すると、 **統合**も実行でき、残すインシデントの選択を求められます。1回のリクエストで最大100件を処理できます。すでに復旧しているなどの理由で処理できないインシデントは、最初に該当した理由ごとに集計し、残りのインシデントを処理します。

### インシデントを手動で起票する

顧客からの報告や目視で見つけた問題など、ルールで検知できなかった問題もインシデントとして起票でき、他のインシデントと同様にオンコール通知とエスカレーションが行われます。一覧の上にある**新規インシデント**を選択します（`alerts.incidents.create` が必要です）。

1. **発生内容**で、**タイトル**（必須）と**説明**（Markdown 対応）を入力し、 **重大度**（デフォルトはエラー）、**優先度**、**緊急度**（デフォルトではエスカレーションポリシーに準拠）を選択します。必要に応じて、**影響を受けたサービス**をカンマ区切りで入力し、**ラベル**を1行につき1つ、 `key=value` の形式で入力します。
2. **対応担当**で、次のいずれかを選択します。

   | 選択肢 | 動作 |
   |---|---|
   | **自動ルーティング** | ルールによるインシデントと同様に、[アラートルーティング](/ja/alerting/routing)に従って振り分けます。 |
   | **チームを指定** | チームのオンコールポリシーを使用します。設定がなければ、デフォルトのポリシーを使用します。 |
   | **エスカレーションポリシーを指定** | ポリシーのステップ1から通知します。 |
   | **担当者を個別に指定** | エスカレーションポリシーを使わず、最大10名に直接通知します。 |

3. 必要に応じて**重大インシデントとして宣言**をオンにし、**インシデントを作成**を選択します。インシデントのページが開きます。

手動で起票したインシデントには `alert.source=manual` ラベルが付き、`created_by` アノテーションには起票者が、`description` アノテーションには説明が記録されます。アラートパイプラインを経由せず、他のインシデントとの重複排除も行いません。自動では復旧しないため、手動で解決済みにします。インシデントページの**起票者**には起票者名が表示され、インサイトでは該当するインシデントを**手動起票**として集計します。Mole Agent の `create_incident` ツールでも、1回の承認でインシデントを起票できます。

## インシデントの詳細

インシデントを選択して詳細を開きます。ヘッダーには、状態、発生時刻、ルール、発生からの経過時間に加え、**確認済みにする**、**解決済みにする**、**その他の操作**が表示されます。**その他の操作**には、 [インシデントを操作する](#インシデントを操作する)の各操作と**サイレンス**が含まれます。

| セクション | 内容 |
|---|---|
| **タイムライン** | 発生時刻、通知先、操作を行った人と操作内容（確認、担当者の変更、対応者の追加、エスカレーション、スヌーズ、重大度の変更、統合、解決、修復・チケット・重大インシデントの各ステップ）、インシデントが作成される前に[アラートパイプライン](/ja/pipelines/alert-events#イベントの処理結果)が加えた変更、操作経路（API、チャット、SMSへの返信、電話のキー入力、Mole Agent）、各イベント間の経過時間が表示されます。末尾に[メモ](#メモ)を追加できます。その下には、このインシデントに統合されたインシデントが表示されます。 |
| **調査** | **トリガークエリを開く**は、クエリエクスプローラーで元のクエリをそのまま再実行します。**関連ログ**と**関連メトリクス**は、影響を受けた対象のデータを同じ時間範囲で開きます。RUM指標がトリガーとなったインシデントには、**RUMで開く**が表示されます。 |
| **調査ガイド** | ルールの[調査ガイド](/ja/alerting/rules#調査ガイド)に沿って、手順、インシデントの時間範囲で開くクエリ、ダッシュボードを表示します。ルールにガイドがある場合にのみ表示します。 |
| **AIによる根本原因分析** | Mole Agentによる分析です。[AIによる根本原因分析](#aiによる根本原因分析)を参照してください。 |
| **関連シグナルへのリンク** | 根拠データに含まれるサービス、トレースID、ホストをそれぞれリンクとして表示します。 |
| **トリガークエリ** | クエリとその戻り値を表示します。**サンプル値を表示**を選択すると、サンプル行が表示されます。 |
| **メタデータ** | インシデントのラベルとアノテーションを表示します。 |
| **担当者** | エスカレーションの通知先、インシデントの[ルーティング先](/ja/alerting/routing#インシデントでのルーティング結果)チームとその理由を表示します。スヌーズ、別のインシデントへの統合、重大度の手動設定もここに表示します。 |
| **影響範囲** | インシデントでサービスが特定されている場合、サービスマップに基づいて、そのサービスの影響が及ぶ範囲を表示します。[インシデントの影響範囲](/ja/apm/insights#インシデントの影響範囲)を参照してください。 |
| **サンプルセッション** | RUM指標がトリガーとなったインシデントでは、該当する現象が確認できるセッションを表示します。各セッションをリプレイできます。[RUMアラート](/ja/rum/alerts#インシデント)を参照してください。 |
| **類似インシデント** | 過去90日間の類似インシデントと、その対応結果を表示します。[類似インシデントと最近の変更](#類似インシデントと最近の変更)を参照してください。 |
| **最近の変更** | トリガーの前後に対象サービスとその下流サービスで報告されたデプロイ、設定変更、機能フラグを表示します。前日にルールを編集した場合は、そのルールも表示します。 |
| **修復** | インシデントに適用できる修復アクションと、リクエストされた実行や承認を表示します。[修復](/ja/alerting/remediation)を参照してください。 |
| **チケット** | インシデントに関連するJiraまたはFeishu Projectのチケットとそのステータスを表示します。ここからチケットを作成できます。[チケット](/ja/alerting/tickets)を参照してください。 |
| **重大インシデント** | 重大インシデントを宣言し、役割を割り当て、対策ルームやミーティングに参加し、対応作業をタスクに分割し、進捗を投稿できます。[重大インシデントとポストモーテム](/ja/alerting/major-incidents)を参照してください。 |
| **ポストモーテム** | インシデントの内部向けポストモーテムです。**ポストモーテムを作成**でテンプレートから下書きを作成し、**ポストモーテムを開く**で編集を続けます。[ポストモーテム](/ja/alerting/major-incidents#ポストモーテム)を参照してください。 |

## インシデントを操作する

**その他の操作**のすべての操作はタイムラインに記録され、 [API](#インシデントapi)からも実行できます。Mole Agentもこれらの操作を実行できます。メモの追加には依頼者の確認が必要で、それ以外の操作には承認が1件必要です。[承認と実行](/ja/agent#承認と実行)を参照してください。 Mole Agentは、チケットの作成、重大インシデントでの役割の割り当て、タスクの追加、ポストモーテムの下書きの作成（いずれも依頼者の確認が必要）、重大インシデントの宣言と進捗の投稿（承認が1件必要）、修復の実行の提案（[事前承認](/ja/alerting/remediation#事前承認)の対象でない限り、承認が2件必要）も行えます。復旧したインシデントや、別のインシデントに統合されたインシデントには、これらの操作を実行できません。ただし、 [メモ](#メモ)は引き続き追加できます。

| 操作 | 結果 |
|---|---|
| **担当者の変更** | 個人に割り当てる場合：最大10人を担当者に設定し、通知します。インシデントは**レビュー待ち**に戻り、誰も確認済みにしない場合はエスカレーションを続行します。チームに割り当てる場合：チームのオンコールポリシーをステップ1から再開します。チームにポリシーがない場合は、デフォルトのポリシーを使用します。エスカレーションポリシーに割り当てる場合：そのポリシーをステップ1から再開し、チームは変更しません。担当者の変更とともにメモをタイムラインに追加できます。 |
| **対応者の追加** | 選択した対応者を担当者に追加し、通知します。状態は変わりません。 |
| **今すぐエスカレーション** | 選択したステップの通知先にすぐに通知します。デフォルトでは次のステップを選択します。インシデントの重大度に該当するステップのみを表示します。確認済みのインシデントは**レビュー待ち**に戻ります。 |
| **スヌーズ** | 1時間、4時間、8時間、24時間、または**カスタム…**（1分〜7日間）を選択します。レビュー待ちのインシデントは、先に確認済みになります。スヌーズ中は通知を送信しません。スヌーズが終了すると、インシデントは**レビュー待ち**に戻り、担当者に再通知します。**スヌーズの解除**を選択すると、スヌーズがすぐに終了します。 |
| **重大度** | 手動で設定すると、ルール、アラートソース、合成監視チェックでは重大度が変わらなくなります。レビュー待ちのインシデントの重大度を上げると、新しい重大度でステップ1から再通知します。下げる場合は重大度だけを変更します。 |
| **優先度** | 組織の[優先度レベル](/ja/alerting/on-call#緊急度と優先度のレベル)（デフォルトはP1〜P5）のいずれか、または**なし**を選択します。優先度だけを変更し、再通知は行いません。優先度は、一覧の列とフィルター、[ルーティングルール](/ja/alerting/routing)の条件、重大インシデントの自動宣言、チケットの優先度マッピング、インサイトで使用します。 |
| **緊急度** | **緊急度：高**または**緊急度：低**を選択します。[緊急度](/ja/alerting/on-call#緊急度)を参照してください。レビュー待ちのインシデントを**緊急度：高**に変更すると、ステップ1から再通知します。緊急度を下げた場合は、緊急度だけを変更し、それ以降のエスカレーションを停止します。一度手動で設定すると、サポート時間帯によって緊急度が変わることはありません。 |
| **統合** | 他のアクティブなインシデントをこのインシデントに統合します。[インシデントを統合する](#インシデントを統合する)を参照してください。 |
| **サイレンス** | [単一のインシデントをサイレンスする](/ja/alerting/silences#1件のインシデントにサイレンスを適用する)を参照してください。 |

これらの操作で送信する通知はエスカレーション通知です。テンプレートの `{{escalation.reason}}`は通知理由を示します。値は`reassigned`、`responder_added`、`manual`（今すぐエスカレーション）、`snooze_ended`、 `severity_raised`、`urgency_raised`、`ack_timeout`（確認済みのまま長時間未解決）のいずれかです。テンプレートでは `{{urgency}}`と`{{priority}}`も使用できます。詳しくは [テンプレート変数](/ja/notification-channels#テンプレート変数)を参照してください。

### インシデントを統合する

1つの障害で複数のルールが発火するなど、同じ問題で複数のインシデントが作成された場合は、 1つのメインインシデントに統合します。統合されたインシデントは個別に通知やエスカレーションを行わず、インシデント一覧やインサイトにも表示されません。メインインシデントのタイムラインの下に表示されます。メインインシデントを解決済みにすると、統合されたインシデントも解決済みになります。統合されたインシデントが先に復旧した場合は、メインインシデントのタイムラインに記録されます。一度に最大50件のインシデントを統合できます。統合は元に戻せません。

詳細画面では、**その他の操作 → 統合**で統合するインシデントにチェックを入れます。インシデント一覧では、複数のインシデントにチェックを入れて**統合**を選択し、メインインシデントを選択します。

### メモ

引き継ぎ時に調査結果と実施した対応をすぐに確認できるよう、タイムライン下部の入力欄に最大4,000文字のメモを追加します。担当者の変更時に入力したメモも同じ場所に表示されます。 Mole Agentはインシデントとあわせて最新のメモを読み取ります。

## AIによる根本原因分析

モデルプロバイダーを設定すると、Mole Agentは新しいインシデントをバックグラウンドで分析し、根拠に基づく分析結果をインシデントに保存します。**生成**を選択するとすぐに結果を生成し、 **再生成**を選択すると結果を置き換えます。結果は**役に立った**または**役に立たなかった**で評価します。評価は [品質](/ja/quality)に反映されます。

結果を生成するには、Mole Agentの権限が必要です。組織のMole Agentの日次トークン予算を使い切ると、自動分析は一時停止し、オンデマンド生成は予算設定に従います。詳しくは [使用量と予算](/ja/agent#使用状況と予算)を参照してください。

## 類似インシデントと最近の変更

**類似インシデント**には、組織内の過去90日間のインシデントのうち、現在のインシデントに最も似ているものが最大5件表示されます。類似の理由は、**同じアラート**（フィンガープリントが同じ）、**同じルール**、**同じサービス**、 **類似のラベル**、**類似のタイトル**（中国語のタイトルも対象）、**同じチーム**のいずれかです。各インシデントには継続時間、解決した担当者、メモの件数、AIによる根本原因分析の最初の1文が表示されます。これにより、インシデントの担当者は過去の対応を確認できます。

**最近の変更**には、インシデントのトリガーの30分前から 10分後までに[報告された変更](/ja/apm/deployments#ci-からデプロイを報告する)が表示されます。対象は、インシデントに関連するサービスと、サービスマップ上でその下流にあるサービスです。デプロイ（失敗またはロールバックしたものにはマークが付きます）、構成変更、機能フラグが表示されます。下流サービスの変更にはマークが付き、パイプラインへのリンクがある場合は表示されます。インシデントのルールをトリガー前の24時間以内に編集した場合は、そのルールも表示されます。サービスマップがない場合は、インシデントに直接関連するサービスのみが対象です。

## インシデントのグループ

[セマンティックグループ](/ja/alerting/silences#セマンティックグループ)は、関連するインシデント（たとえば、あるサービスのクリティカルなインシデントすべて）を1つのグループにまとめます。 `POST /api/v1/alerts/incident_groups/{id}/ack`または`/resolve`でグループを確認済みまたは解決済みにすると、グループ内のすべてのインシデントにも同じ操作を適用します。

## 履歴

**アラート → 履歴**では、過去のインシデントと、現在の状態、発報時刻、復旧時刻、継続時間を確認できます。インシデント、サービス、インシデントIDで検索し、重大度と状態で絞り込めます。

## インサイト

**アラート → インサイト**では、過去24時間、7日間、または30日間のワークスペースの対応状況を確認できます。

| 項目 | 表示内容 |
|---|---|
| サマリー | 対応が必要なインシデントの件数、復旧したインシデントの**平均復旧時間**、**短時間での復旧**が表示されます。短時間での復旧は60秒以内に復旧した割合で、不要な発報が多いルールを見つける目安になります。 |
| **インシデントのタイムライン** | ブラウザーのタイムゾーンで、24時間の場合は時間ごと、それより長い期間の場合は日ごとのインシデント件数を表示します。ピークも表示します。 |
| **影響が最も多かったサービス** | インシデントに最も多く登場するサービスを表示します。この集計にはルールに`service`ラベルが必要です。 |
| **発報数上位のルール** | 最も多くのインシデントを作成したルールを表示します。上位のルールから調整してください。 |
| **レスポンス** | インシデントの対応開始までの平均時間（P50とP90も表示）、復旧までの時間の中央値、エスカレーション率、担当者が対応を開始した割合を、直前の同じ長さの期間と比較して表示します。エスカレーションのステップごとの確認率、最初に対応を開始した経路（Web、API、チャットカード、SMSへの返信、電話のキー操作、Mole Agent）、チーム、サービス、担当者、優先度ごとの対応開始、復旧、エスカレーションの内訳も表示します（優先度が未設定のインシデントは優先度別の集計から除外します）。最初に確認済みにした時点を対応開始とみなします。確認済みにせず担当者が解決した場合は、解決時点を対応開始とみなします。 |
| **オンコール負荷** | 担当者ごとに、オンコール時間、受信したアラート通知の件数、夜間（担当者のスケジュールのタイムゾーンで22:00から08:00）と週末に受信した件数、夜間に通知があった日数、最初に対応を開始したインシデントの件数と対応開始までの時間を表示します。スケジュールの詳細では、そのメンバーについて同じ情報を確認できます。 |
