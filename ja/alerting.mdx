**アラート**を開くと、検出から確認、エスカレーション、解決まで進められます。 [ルール](/ja/alerting/rules)はクエリや数値を監視し、条件を満たすと[インシデント](/ja/alerting/incidents) を作成します。[アラートソース](/ja/alerting/sources)は、外部システムからアラートを受信するとインシデントを作成します。[アラートルーティング](/ja/alerting/routing)は、新しいインシデントに割り当てるチームとエスカレーションポリシーを決定します。インシデントの[エスカレーションポリシー](/ja/alerting/on-call#エスカレーションポリシー)は、指定した担当者や[オンコールスケジュール](/ja/alerting/on-call#オンコールスケジュール)の当番に通知し、誰も確認しない場合は次の段階に進みます。[通知チャネル](/ja/notification-channels)は各通知を配信します。[サイレンス](/ja/alerting/silences)はメンテナンス中の通知を一時停止し、 [セマンティックグループ](/ja/alerting/silences#セマンティックグループ)は関連するインシデントをまとめます。

## アラートセンター

ページ横のメニューには、用途別に5つのグループに分けてページが並びます。幅の広いページを画面いっぱいに表示するには、メニューの検索欄からメニューを折りたたみます。

| グループ | ページ | 用途 | ガイド |
|---|---|---|---|
| 対応 | **インシデント** | 発生中のインシデントを確認、サイレンス、解決、調査します。 | [インシデント](/ja/alerting/incidents) |
|  | **履歴** | 過去のインシデントをサービスやステータスで検索します。 | [履歴](/ja/alerting/incidents#履歴) |
|  | **ポストモーテム** | インシデントの社内向けポストモーテムやアクションアイテムを管理し、重大インシデントを設定します。 | [重大インシデントとポストモーテム](/ja/alerting/major-incidents) |
|  | **インサイト** | インシデント件数、復旧時間、ノイズの多いルール、影響を受けたサービス、対応状況、オンコールの負荷を確認します。 | [インサイト](/ja/alerting/incidents#インサイト) |
| 検出 | **ルール** | しきい値、予測、外れ値、複合、ハートビート、異常検知、リアルタイムのルールを管理します。 | [アラートルール](/ja/alerting/rules) |
|  | **検出** | ルールなしで検出した問題を確認します。APMサービスの急変、新バージョンのパフォーマンス低下、フロントエンドエラーの新規発生や再発、エラーログの急増、ホストの異常などが対象です。 | [検出](/ja/alerting/discovery) |
|  | **ソース** | Alertmanager、Grafana、Datadog、PagerDuty、Zabbix、クラウド監視サービス（Alibaba Cloud、Tencent Cloud、Amazon CloudWatch）、メール、APIから送信されたアラートを受け取ります。 | [外部アラート](/ja/alerting/sources) |
| ノイズの削減 | **グループ** | セマンティックグループで関連するインシデントをまとめます。 | [セマンティックグループ](/ja/alerting/silences#セマンティックグループ) |
|  | **抑制** | より重大なインシデントや上流のインシデントが発生中は、影響の小さいインシデントの通知を抑制します。 | [抑制](/ja/alerting/inhibition) |
|  | **サイレンスポリシー** | 条件に一致するインシデントの通知を一時停止します。 | [サイレンスポリシー](/ja/alerting/silences#サイレンスポリシー) |
| 通知 | **ルーティング** | 新しいインシデントに割り当てるチームとエスカレーションポリシーを決定します。 | [アラートルーティング](/ja/alerting/routing) |
|  | **エスカレーション** | 通知先、通知順序、次の段階に進むタイミングを設定します。 | [エスカレーションポリシー](/ja/alerting/on-call#エスカレーションポリシー) |
|  | **オンコールスケジュール** | ローテーション、一時的な代理対応、シフト交代、カレンダーの購読を管理します。 | [オンコールスケジュール](/ja/alerting/on-call#オンコールスケジュール) |
| フォローアップ | **修復** | インシデントからHTTPやKubernetesの修復アクションをワンクリックで開始し、承認後に実行します。 | [修復](/ja/alerting/remediation) |
|  | **チケット** | Jira、ServiceNow、Meegleと連携し、インシデントのチケットを作成してステータスを同期します。 | [チケット](/ja/alerting/tickets) |

顧客にインシデントやメンテナンスを知らせるステータスページは、独立したモジュールです。 [ステータスページ](/ja/status-pages)を参照してください。

## アラートを設定する

ワークスペースでは通常、次の順序で初回通知の準備を行います。

<Steps>
  <Step title="通知チャネルを接続する">
    メール、チャットアプリ、電話やSMSなどのコネクターを [設定 → 通知 → コネクター](/ja/notification-channels)で設定します。各メンバーは、 [アカウント設定 → 通知](/ja/account#通知)で個人の通知手段を登録してください。
  </Step>
  <Step title="オンコールスケジュールを作成する">
    チームのローテーションを含む[オンコールスケジュール](/ja/alerting/on-call#スケジュールを作成する)を作成します。
  </Step>
  <Step title="デフォルトのエスカレーションポリシーを作成する">
    まずオンコールスケジュールの当番に、次に責任者に通知する `default` という名前のポリシーを作成します。ルールワークベンチに保存したルールには、[ルーティング](/ja/alerting/routing)でチームのオンコールポリシーが見つからない場合にこのポリシーを適用します。[デフォルトポリシー](/ja/alerting/on-call#デフォルトポリシー)を参照してください。
  </Step>
  <Step title="ルールを作成してテストする">
    [ルールワークベンチ](/ja/alerting/rules#しきい値ルールを作成する)でプリセットを選び、実データでテストしてから保存します。
  </Step>
  <Step title="通知の流れを確認する">
    [ルールをトリガーする](/ja/api/alerting/trigger-rule)を使って意図的にルールを発動させ、通知が届き、エスカレーションが次の段階に進み、確認すると停止することを確かめます。
  </Step>
</Steps>

[本番環境のアラートを対応につなげる](/ja/best-practices/actionable-alerts)と [オンコールと通知を設定する](/ja/best-practices/on-call-setup)では、アラートの対象とルーティングの決め方を説明します。

## 権限

| 権限 | できること |
|---|---|
| `alerts.incidents.read` | インシデント、履歴、インサイトを閲覧します。 |
| `alerts.incidents.acknowledge` | インシデントやインシデントグループを確認、解決、スヌーズします。 |
| `alerts.incidents.update` | インシデントの担当を変更し、対応者を追加し、重大度を変更し、メモを記録します。対応時の役割、タスク、進捗更新も管理します。 |
| `alerts.incidents.escalate` | インシデントをエスカレーションまたは統合し、重大インシデントを宣言します。 |
| `alerts.incidents.create`, `alerts.incidents.silence` | インシデントを手動で作成し、サイレンスを適用します。 |
| `alerts.incidents.remediate`, `alerts.incidents.tickets`, `alerts.incidents.rca` | インシデントの修復を開始し、チケットを作成し、根本原因を記録します。 |
| `alerts.rules.read`, `alerts.rules.manage` | ルールを閲覧、作成、変更します。 |
| `alerts.routing.read`, `alerts.routing.manage` | ルーティングルールとチームのオンコールポリシーを閲覧、変更します。 |
| `alerts.escalations.read`, `alerts.escalations.manage`, `alerts.escalations.delete` | エスカレーションポリシーを閲覧、変更、削除します。 |
| `alerts.sources.read`, `alerts.sources.manage` | アラートソースを閲覧、変更します。 |
| `alerts.mutes.read`, `alerts.mutes.manage` | サイレンスを閲覧、作成、変更、削除します。 |
| `alerts.inhibitions.read`, `alerts.inhibitions.manage` | 抑制ルールを閲覧、作成、変更、削除します。 |
| `alerts.semantic_groups.manage` | グループを管理します。 |
| `alerts.remediation.read`, `alerts.remediation.manage` | 修復アクションを閲覧、定義します。 |
| `alerts.tickets.read`, `alerts.tickets.manage` | チケットコネクターを閲覧、管理します。 |
| `alerts.response.read`, `alerts.response.manage` | 重大インシデントの設定を閲覧、変更します。 |
| `alerts.discovery.read` | 検出結果を閲覧します。 |
| `schedules.read` | スケジュールとオンコール担当者を閲覧します。 |
| `schedules.create`, `schedules.update`, `schedules.delete` | スケジュールとローテーションを作成、変更、削除します。 |
| `schedules.overrides.manage`, `schedules.swaps.request`, `schedules.swaps.approve` | シフトを代理で担当し、交代を申請し、申請を承認または却下します。 |
| `postmortems.read`, `postmortems.manage` | ポストモーテムを閲覧し、ポストモーテムとアクションアイテムを記録します。 |
