MoleSignal は現在、Slack Webhook、Lark Webhook、汎用 JSON Webhook の 3 種類の Webhook コネクターを提供しています。Webhook コネクターは **設定 → 通知 → コネクター** で作成します。

ID の紐付け、ポリシーの作成、フォールバックルート、配信履歴については、まず[通知チャネルと配信](/ja/notification-channels)を参照してください。

## Webhook タイプの比較

| コネクター | リクエスト形式 | 認証 | ターゲットタイプ |
|---|---|---|---|
| `slack_webhook` | `{ "text": "..." }` | Webhook URL に含まれる認証情報 | `fixed_group`、`webhook` |
| `lark_webhook` | Lark `msg_type: text` | URL に含まれる認証情報、オプションの署名 | `fixed_group`、`webhook` |
| `webhook` | MoleSignal イベントの JSON、または通知テンプレートの本文 | カスタム JSON ヘッダー、オプションの署名 | すべてのターゲットタイプ |

`fixed_group` の場合、コネクターは設定済みの URL に送信します。`webhook` の場合、ターゲットの値には絶対 URL を指定します。その配信に限り、設定済みの URL の代わりに指定した URL を使用します。

## Slack Webhook

Incoming Webhook URL と、1～60 seconds のタイムアウトを設定します。

```json
{
  "webhookUrl": "https://hooks.slack.com/services/T000/B000/secret",
  "timeoutSecs": 10
}
```

MoleSignal はメッセージのタイトルと Markdown 本文を結合し、次の形式で送信します。

```json
{
  "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
}
```

HTTP レスポンスが 2xx なら、配信は成功です。それ以外のレスポンスやタイムアウトの場合、配信は失敗になります。

## Lark Webhook

Lark または Feishu のカスタムボット URL を設定します。署名検証を有効にしている場合に限り、ボットの署名シークレットを追加します。

```json
{
  "webhookUrl": "https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx",
  "secret": "replace-with-signing-secret",
  "timeoutSecs": 10
}
```

署名シークレットを設定しない場合、MoleSignal は次の形式で送信します。

```json
{
  "msg_type": "text",
  "content": {
    "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
  }
}
```

署名シークレットを設定すると、MoleSignal は秒単位の Unix タイムスタンプを生成し、 `timestamp + "\n" + secret` を組み立てます。この値を HMAC-SHA256 のキーとして空のメッセージのダイジェストを計算し、 Base64 でエンコードします。リクエストには両方のフィールドが含まれます。

```json
{
  "timestamp": "1599360473",
  "sign": "base64-signature",
  "msg_type": "text",
  "content": {
    "text": "[Critical] Checkout error rate is high\nThe error rate exceeded 5%."
  }
}
```

MoleSignal が配信を成功と判定するには、HTTP ステータスが成功を示し、かつ Lark のレスポンスの `code` または `status_code` が 0 である必要があります。

<Note>
  MoleSignal サーバーの時刻を同期してください。Lark はタイムスタンプが古い署名付きリクエストを拒否します。
</Note>

## 汎用 Webhook

デフォルトの URL、メソッド、本文、署名シークレット、ヘッダー、タイムアウトを設定します。

```json
{
  "url": "https://notify.example.com/molesignal",
  "method": "post",
  "body": "event",
  "signingSecret": "<at-least-16-characters>",
  "headers": {
    "X-Environment": "production"
  },
  "timeoutSecs": 10
}
```

メソッドには `post`、`put`、`patch` を指定できます。ヘッダー名と値は HTTP の構文に従う必要があります。ヘッダー名には `Content-Type` や、後述の `X-MoleSignal-*` を指定できません。

### 本文

`body` をデフォルト値の `event`（コンソールの **MoleSignal イベント**）に設定すると、本文は機械処理用の JSON になります。

```json
{
  "version": 2,
  "event": {
    "id": "alert.triggered:3KEDNEyqouYJeBDTLTMTBui7XHW",
    "type": "alert.triggered",
    "occurredAt": "2026-10-28T08:00:00Z",
    "organizationId": "<organization-id>"
  },
  "alert": {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "status": "open",
    "severity": "critical",
    "title": "High error rate · checkout",
    "url": "https://molesignal.example.com/alerts/incidents/3KEDNEyqouYJeBDTLTMTBui7XHW",
    "startedAt": "2026-10-28T08:00:00Z",
    "acknowledgedAt": null,
    "resolvedAt": null,
    "acknowledgedBy": null,
    "resolvedBy": null,
    "assignees": ["<user-id>"],
    "teamId": "<team-id>",
    "service": "checkout",
    "environment": "production",
    "affectedServices": ["checkout"],
    "labels": { "service": "checkout", "env": "production" },
    "annotations": { "runbook_url": "https://runbooks.example.com/checkout" },
    "value": 120.0,
    "threshold": 50.0
  },
  "rule": { "id": "<rule-id>", "name": "High error rate", "description": "Share of 5xx answers." },
  "target": { "type": "fixed_group", "value": "platform-oncall", "metadata": {} },
  "message": {
    "title": "[CRITICAL] High error rate · checkout",
    "text": "The error rate exceeded 5%.",
    "markdown": "**Checkout** error rate exceeded 5%.",
    "html": null,
    "metadata": { "event_type": "alert.triggered", "alert_id": "3KEDNEyqouYJeBDTLTMTBui7XHW" }
  }
}
```

| フィールド | 内容 |
|---|---|
| `version` | 本文構造のバージョンです。現在は `2` で、本文構造のキーには camelCase を使用します。`data` には引き続きイベントの属性がそのまま入ります。フィールドは追加のみで、既存の読み取り処理と互換性のない変更がある場合にのみバージョンが上がります。 |
| `event` | 通知の `id`、`type`（例: `alert.triggered`、`alert.escalated`、`oncall.shift.starting`）、`occurredAt`、`organizationId` です。 |
| `alert` | アラート通知のみ。ステータス、重大度、タイトル、インシデントの URL（`http.external_url` を設定している場合）、開始・確認・解決の各時刻、担当者、チーム、サービス、環境、ラベル、アノテーション、値、しきい値が含まれます。時刻は UTC の RFC 3339 形式で、担当者とチームは ID で示します。 |
| `rule` | アラートルールの `id`、`name`、`description` です。 |
| `escalation` | エスカレーション通知のみ。`step`、`loop`、`reason`（送信理由。[インシデントに対応する](/ja/alerting/incidents#インシデントを操作する)を参照）、`target`（`kind` と `id`）が含まれます。 |
| `data` | オンコールの引き継ぎや担当者不在など、アラート以外の通知では、イベントの属性がそのまま入ります。 |
| `target` | この配信のターゲットを示す `type`、`value`、`metadata` です。 |
| `message` | レンダリング済みメッセージの `title`、`text`、`markdown`、`html`、`metadata` です。 |

`body` を `template`（**通知テンプレートの本文**）に設定すると、通知ポリシーが Webhook チャネル用に選択したテンプレートを、記述した形式のまま本文として送信します。JSON テンプレートの場合は `application/json` で送信し、値を JSON 文字列としてエスケープします。それ以外の形式は `text/plain; charset=utf-8` で送信します。通知ポリシーで Webhook チャネル用のテンプレートを選択していない場合は、共通テンプレートまたはイベント自体のメッセージの本文を送信します。テンプレートの書き方は[条件](/ja/notification-channels#条件)を参照してください。

### ヘッダーと署名

| ヘッダー | 内容 |
|---|---|
| `Content-Type` | `application/json` です。テンプレートの本文が JSON ではない場合は `text/plain; charset=utf-8` です。 |
| `X-MoleSignal-Event` | 通知タイプです。`event.type` と同じ値です。 |
| `X-MoleSignal-Delivery` | この配信の ID です。受信側はこの ID を使って重複リクエストを破棄できます。 |
| `X-MoleSignal-Timestamp` | 署名シークレットを設定した場合のみ。送信時の Unix 時刻を秒単位で示します。 |
| `X-MoleSignal-Sign` | 署名シークレットを設定した場合のみ。`sha256=<hex>` の形式で、署名シークレットをキーとして `<timestamp>.<body>` の HMAC-SHA256 を計算した値です。 |

受信側では、同じシークレットと未加工の本文を使って署名を再計算し、 `X-MoleSignal-Sign` と定数時間で比較します。タイムスタンプが現在時刻から大きくずれている場合（たとえば 5 分を超える場合）は拒否します。JSON を解析して再シリアライズした結果ではなく、受信したままのバイト列を使って計算してください。

<CodeGroup>
```python Python
import hashlib, hmac, time

def verify(secret: str, headers, body: bytes, tolerance: int = 300) -> bool:
    timestamp = headers.get("X-MoleSignal-Timestamp", "")
    signature = headers.get("X-MoleSignal-Sign", "")
    if not timestamp.isdigit() or abs(time.time() - int(timestamp)) > tolerance:
        return False
    mac = hmac.new(secret.encode(), timestamp.encode() + b"." + body, hashlib.sha256)
    return hmac.compare_digest("sha256=" + mac.hexdigest(), signature)
```

```javascript Node.js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verify(secret, headers, body, toleranceSecs = 300) {
  const timestamp = headers['x-molesignal-timestamp'] ?? '';
  const signature = Buffer.from(headers['x-molesignal-sign'] ?? '');
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSecs) return false;
  const expected = Buffer.from(
    'sha256=' + createHmac('sha256', secret).update(`${timestamp}.`).update(body).digest('hex'),
  );
  return expected.length === signature.length && timingSafeEqual(expected, signature);
}
```

```go Go
import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"net/http"
	"strconv"
	"time"
)

func verify(secret string, r *http.Request, body []byte, tolerance time.Duration) bool {
	timestamp := r.Header.Get("X-MoleSignal-Timestamp")
	seconds, err := strconv.ParseInt(timestamp, 10, 64)
	if err != nil || time.Since(time.Unix(seconds, 0)).Abs() > tolerance {
		return false
	}

	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(timestamp + "."))
	mac.Write(body)
	expected := "sha256=" + hex.EncodeToString(mac.Sum(nil))

	return hmac.Equal([]byte(expected), []byte(r.Header.Get("X-MoleSignal-Sign")))
}
```
</CodeGroup>

署名シークレットには、`openssl rand -hex 32` で生成した値など、16 文字以上の値を使用します。コネクターの HTTP ターゲットでも同じ方法で署名します。[コネクター](/ja/connectors)を参照してください。

### レスポンスとアウトバウンドリクエスト

2xx レスポンスはすべて成功として扱います。レスポンスに `X-Request-ID` が含まれる場合、MoleSignal はそのヘッダーの値をプロバイダーのメッセージ ID として記録します。MoleSignal はホスト名の解決で得られたアドレスにのみ接続し、クラウドメタデータのアドレスへの接続を拒否します。また、リダイレクトを追跡しません。Webhook 通知は [統合](/ja/notification-channels#通知をまとめる)しません。

## API での作成とテスト

汎用 Webhook コネクターを作成します。

```bash
curl -X POST "$MOLESIGNAL_URL/api/v1/notify/connectors" \
  -H "Authorization: Bearer $MS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "platform webhook",
    "connectorType": "webhook",
    "enabled": true,
    "config": {
      "url": "https://notify.example.com/molesignal",
      "method": "post",
      "body": "event",
      "signingSecret": "<at-least-16-characters>",
      "headers": {"Authorization": "Bearer <token>"},
      "timeoutSecs": 10
    }
  }'
```

レスポンスに含まれるコネクターの `id` を保存し、テスト通知を送信します。

```bash
curl -X POST "$MOLESIGNAL_URL/api/v1/notify/connectors/$CONNECTOR_ID/test" \
  -H "Authorization: Bearer $MS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "targetType": "fixed_group",
    "target": "platform-oncall",
    "message": {
      "title": "MoleSignal connector test",
      "text": "Webhook delivery is working."
    }
  }'
```

コネクターの一覧取得、詳細取得、作成、更新では、機密性の高い設定フィールドを `***` として返します。既存のコネクターを更新する際、保存済みのシークレットを維持するには、`***` の値を変更せずに送信してください。

## セキュリティと制限事項

- MoleSignal はコネクターの設定全体を暗号化して保存します。
- API レスポンスでは、`url`、`webhookUrl`、`headers`、`secret`、`signingSecret`、トークン、パスワードをマスクします。
- 追加のシークレットを設定していない場合でも、Webhook URL は認証情報として扱ってください。
- `https` を優先し、`http` は信頼できるネットワークでのみ使用してください。
- MoleSignal からのアウトバウンドアクセスは、コネクターに必要な送信先のみに制限してください。
- 無効なコネクターでは、テスト通知も通常の通知も送信できません。

<Note>
  DingTalk、WeCom、Teams、Google Chat、Telegram、Discord、Mattermost、Webex、Matrix、PagerDuty、 Amazon SNS には専用のコネクターがあります。 [各プロバイダーの設定](/ja/notification-channels#プロバイダーごとの設定)を参照してください。送信先が別の JSON 構造を要求する場合は、JSON Webhook テンプレートにその構造を記述し、本文に **通知テンプレートの本文** を選択してください。形式を変換する中継サービスは不要です。
</Note>
