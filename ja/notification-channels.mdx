MoleSignal では、プロバイダーの認証情報を受信者やルーティングとは別に管理します。コネクターを一度設定し、ユーザー ID やフォールバック先を紐付けたうえで、通知エンジンがそれらのルートを使用する条件を指定します。

| リソース | 用途 |
|---|---|
| **コネクター** | 組織レベルのプロバイダー認証情報と通信設定を保存します。 |
| **ユーザールーティング** | プロバイダー上のユーザー ID を紐付け、個人の通知先に優先順位を設定します。 |
| **ポリシー** | イベントを条件に照合し、受信者を特定し、テンプレートを選択して、エスカレーションを制御します。 |
| **テンプレート** | チャネルごとに再利用できるメッセージ本文です。全チャネルで共通テンプレートを使用でき、SMS、音声通話などには個別のテンプレートも設定できます。 |
| **フォールバックルート** | 個人への配信が失敗した場合に使用するチームや組織の通知先を、優先順に設定します。 |
| **配信ログ** | 配信試行、レイテンシー、エラー、再試行、確認応答、エスカレーションを確認します。 |

| Webhook (`webhook`) | デフォルト URL、HTTP メソッド、ヘッダー、タイムアウト | ユーザー、アドレス、グループ、または通知先ごとの Webhook URL |

すべてのコネクターのタイムアウトは 1 秒以上 60 秒以下に設定してください。URL には `http` または `https` の絶対 URL を指定してください。

コネクタータイプの選択画面では、タイプをチャネル別に表示します。カテゴリは **インスタントメッセージ**、**音声通話**、**SMS** （WhatsApp を含む）、**メールアドレス**、**インテグレーション**です。**インテグレーション**には PagerDuty、Amazon SNS、 Webhook が含まれます。

コネクターには、プロバイダーのアドレスをコピー可能な読み取り専用の値として表示します。Alibaba Cloud、Tencent Cloud、 AWS（Amazon SNS を含む）は選択したリージョンの API ベース URL を、PagerDuty は選択したサービスリージョンの URL を使用します。Lark アプリと Slack アプリは選択したプラットフォームの URL を、Teams ボットは選択したクラウドのサービス URL を使用します。その他のコネクターは固定アドレスを使用します。たとえば、WeCom スマートボットは常時接続用のアドレスを、メールは Microsoft のサインイン用アドレスを使用します。Huawei Cloud は例外です。アドレスはアプリケーションごとに異なり、API では取得できないため、コンソールからコピーしてください。保存、テスト、直接送信の前に、 MoleSignal はこれらのアドレスをプロバイダーのリストと照合します。API 経由で指定したリスト外のアドレスは拒否し、認証情報が別の宛先に送信されないようにします。コネクターのタイプは保存後に変更できません。

Mattermost ボットや Matrix ボットのサーバー URL は、Webhook URL と同様に入力します。MoleSignal は、ホスト名の名前解決で得たアドレスにのみ接続します。クラウドのメタデータアドレスへの接続は拒否し、リダイレクトは追跡しません。

## コネクターを作成してテストする

コネクターの表示には `notify.connectors.read` 権限が必要です。コネクターの作成、編集、テスト、有効化、無効化、削除には `notify.connectors.manage` 権限が必要です。

<Steps>
  <Step title="通知管理を開く">
    **設定 → 通知 → コネクター**に移動します。
  </Step>
  <Step title="プロバイダーを選択する">
    **新規コネクター**をクリックし、一意の名前を入力して、コネクターのタイプを選択します。コネクターのタイプは作成後に変更できません。
  </Step>
  <Step title="プロバイダーの設定を入力する">
    以下で説明する認証情報とトランスポート設定を入力します。**このコネクターからの通知送信を許可**は、コネクターを後で使うために準備する場合を除き、有効のままにします。
  </Step>
  <Step title="コネクターを保存する">
    **コネクターを保存**をクリックします。MoleSignal は設定全体を暗号化して保存します。API レスポンスでは、機密値を `***` に置き換えます。
  </Step>
  <Step title="テスト通知を送信する">
    保存したコネクターを編集し、対応している送信先タイプを選択して、実際の送信先を入力し、 **接続をテスト**をクリックします。コネクターのステータスは、直近のテスト結果に応じて **接続済み**または**エラー**に変わります。
  </Step>
</Steps>

<Note>
  新規コネクターはテストする前に保存してください。コネクターを編集する際は、マスクされた値 `***` を変更しなければ、保存済みのシークレットが保持されます。
</Note>

## プロバイダーごとの設定

### メール（SMTP）

SMTP ホスト、ポート、有効な **送信元アドレス**を入力し、MoleSignal のサインイン方法を **認証**で選択します。

| 認証 | 入力内容 |
|---|---|
| **ユーザー名とパスワード** | サーバーが要求する場合は **ユーザー名**を入力し、**パスワード**も入力します。メールプロバイダーがアプリパスワードや認証コードを要求する場合は、プロバイダーが発行したものをパスワードとして入力します。 |
| **Microsoft 365（OAuth 2.0）** | Microsoft Entra ID に登録したアプリの **テナントID**、**クライアント ID**、**クライアントシークレット**を入力します。**ユーザー名**には送信元メールボックスを指定します。[Microsoft 365](#microsoft-365)を参照してください。 |
| **Google Workspace（OAuth 2.0）** | ドメイン全体の委任を設定したサービスアカウントの **サービスアカウントキー（JSON）**を入力します。**ユーザー名**には送信元メールボックスを指定します。[Google Workspace](#google-workspace)を参照してください。 |

2 つの OAuth 2.0 方式は、パスワードの代わりにアクセストークン（SASL XOAUTH2）でサインインするため、プロバイダーがパスワードでのサインインを無効にしても引き続き使用できます。Microsoft は 2026 年末に、既存の Exchange Online テナントで SMTP AUTH の基本認証を既定で無効にします。MoleSignal は有効期限の 1 分前までトークンを保持し、送信に失敗すると再度サインインします。

次の TLS モードから選択します。

| TLS モード | 用途 |
|---|---|
| `none` | SMTP 接続で TLS を使用しません。信頼できないネットワークでは使用しないでください。 |
| `starttls` | サーバーが STARTTLS で接続をアップグレードします。通常はポート `587` を使用します。 |
| `tls` | 接続の開始時から TLS を使用します。通常はポート `465` を使用します。 |

テストターゲットには `fixed_address` または `direct_user` を使用し、有効なメールボックスを入力します。例： `oncall@example.com`。

#### Microsoft 365

MoleSignal は Microsoft Entra ID に登録したアプリとしてサインインし、1 つのメールボックスから送信します。 Microsoft のグローバルクラウドのみをサポートします。**サインイン URL** は次の値に固定されています。 `https://login.microsoftonline.com`。

<Steps>
  <Step title="アプリを登録する">
    Microsoft Entra ID でアプリを登録します。**API のアクセス許可**で **Office 365 Exchange Online** のアプリケーション権限 `SMTP.SendAsApp` を追加し、管理者の同意を付与します。**証明書とシークレット**でクライアントシークレットを作成します。テナントIDとクライアント ID は、アプリの**概要** ページで確認できます。
  </Step>
  <Step title="Exchange Online にアプリを登録する">
    Exchange 管理者が Exchange Online PowerShell に接続し（`Connect-ExchangeOnline`）、アプリのサービスプリンシパルを登録します。`<object ID>` は、Microsoft Entra ID の **エンタープライズ アプリケーション**にあるアプリのオブジェクト ID です。アプリ登録のオブジェクト ID ではありません。

    ```powershell
    New-ServicePrincipal -AppId <app ID> -ObjectId <object ID>
    ```
  </Step>
  <Step title="メールボックスへのアクセスを許可する">
    サービスプリンシパルに送信元メールボックスへのアクセス権を付与します。

    ```powershell
    Add-MailboxPermission -Identity <mailbox> -User <service principal> -AccessRights FullAccess
    ```
  </Step>
  <Step title="メールボックスで SMTP AUTH を有効にする">
    送信元メールボックスで SMTP AUTH を有効にします。例：

    ```powershell
    Set-CASMailbox -Identity <mailbox> -SmtpClientAuthenticationDisabled $false
    ```
  </Step>
  <Step title="コネクターを設定する">
    ホストに `smtp.office365.com`、ポートに `587`、TLS モードに `starttls` を入力します。 **Microsoft 365（OAuth 2.0）**を選択し、テナントID、クライアント ID、クライアントシークレットを入力します。 **ユーザー名**と**送信元アドレス**の両方に送信元メールボックスを入力します。
  </Step>
</Steps>

#### Google Workspace

MoleSignal はサービスアカウントとしてサインインし、ドメイン全体の委任を使ってドメイン内の 1 つのメールボックスを代行します。

<Steps>
  <Step title="サービスアカウントを作成する">
    Google Cloud プロジェクトでサービスアカウントと、その JSON キーを作成します。サービスアカウントの詳細ページにある数値のクライアント ID を控えます。
  </Step>
  <Step title="Gmail のスコープを委任する">
    特権管理者が Google 管理コンソールで **セキュリティ → アクセスとデータ管理 → API の制御 → ドメイン全体の委任**を開き、クライアント ID を追加して次のスコープを承認します。 `https://mail.google.com/`。委任が反映されるまで最大 24 時間かかることがあります。
  </Step>
  <Step title="コネクターを設定する">
    ホストに `smtp.gmail.com` を指定し、ポート `587` と TLS モード `starttls`、またはポート `465` と `tls` を設定します。**Google Workspace（OAuth 2.0）**を選択し、**サービスアカウントキー（JSON）**にキーを貼り付けます。送信元となるドメイン内ユーザーのメールボックスを**ユーザー名**と **送信元アドレス**の両方に入力します。
  </Step>
</Steps>

[Google Chat アプリ](#google-chat-アプリ)と同様に、キーの `token_uri` には Google のトークンエンドポイントを指定します。

### Slack アプリ

`chat.postMessage` を呼び出せるボットトークンを持つ Slack アプリを作成します。通知を送信する各チャンネルにボットを追加します。次の項目を入力します。

- **ボットトークン** — 通常は `xoxb-` で始まるボットトークンです。
- **アプリレベルトークン** — オプションです。`xapp-` で始まり、`connections:write` スコープを持つトークンです。Mole Agent が Socket Mode 経由で Slack に応答できるようになります。[IM での Mole Agent](/ja/im)を参照してください。
- **プラットフォーム** — Slack または米国政府機関向けの GovSlack です。GovSlack では API とステータスページの認可に `slack-gov.com` を使用します。
- **クライアント ID**と**クライアントシークレット** — Slack アプリの **Basic Information** にあります。ステータスページの訪問者が、そのページを自身の Slack チャンネルに追加する場合に使用します。 [ステータスページ](/ja/status-pages#slack)を参照してください。
- **タイムアウト** — 1～60 秒の値です。

コネクターには、ボットトークン、クライアント ID とクライアントシークレットの組み合わせ、または 3 つすべてが必要です。通知にはボットトークンが必要です。クライアントシークレットは、ボットトークンと同様に暗号化してコネクターに保存し、返却しません。

`direct_user` には Slack のメンバー ID、`fixed_group` にはチャンネル ID を使用します。値に空白文字を含めないでください。`#alerts` のような表示名はチャンネル ID ではありません。

**Mole Agent → 設定 → IM** でコネクターを有効にすると、コネクター経由のアラート通知に確認ボタンと解決ボタンが付きます。[アラートカード](/ja/im#アラートカード)を参照してください。

### Slack Webhook

Slack で着信 Webhook を作成し、URL を **Webhook URL** に貼り付けます。`fixed_group` ターゲットは設定した URL を使用します。`webhook` ターゲットは、その配信に限りターゲットの値を代替 URL として使用します。

MoleSignal は `text` フィールドを含む JSON オブジェクトを送信します。レスポンスが 2xx 以外の場合は、配信の試行を失敗として記録します。

### Lark アプリ

テナントアクセストークンの取得とメッセージの送信が可能なテナントアプリを作成します。**アプリID**と **アプリシークレット**を入力します。**プラットフォーム**で **Feishu** または **Lark** を選択します。APIベースURL は選択に応じて決まります。

選択した受信者IDの種類は `direct_user` ターゲットに適用されます。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | **受信者IDの種類**に応じて `open_id`、`user_id`、`union_id`、またはメールアドレス |
| `fixed_address` | メールアドレス。MoleSignal は `receive_id_type=email` を指定して送信します |
| `fixed_group` | Lark チャット ID。MoleSignal は `receive_id_type=chat_id` を指定して送信します |

常時接続でイベントを受信すると、Mole Agent はアプリ経由で Feishu に応答できます。 [IM での Mole Agent](/ja/im#feishu)を参照してください。

**Mole Agent → 設定 → IM** でコネクターを有効にすると、コネクター経由のアラート通知に確認ボタンと解決ボタンが付きます。[アラートカード](/ja/im#アラートカード)を参照してください。

### Lark Webhook

カスタムボットの URL を **Webhook URL** に貼り付けます。ボットの署名検証を有効にしている場合は、 **署名用シークレット**も入力します。MoleSignal はリクエストごとにタイムスタンプと HMAC-SHA256 署名を生成します。

`fixed_group` ターゲットは設定した URL を使用します。`webhook` ターゲットでは、設定した URL を別の絶対 URL で上書きできます。リクエストと署名の形式については、[Webhook コネクター](/ja/notification-channels/webhooks)を参照してください。

### DingTalk アプリ

DingTalk の内部アプリのロボットを使用します。アプリの**クライアント ID**と**クライアントシークレット**を入力します。ロボットに固有のコードがある場合のみ**ロボットコード**に入力します。空欄の場合はクライアント ID を使用します。MoleSignal は認証情報をアクセストークンと交換し、ロボット経由で Markdown メッセージを送信します。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | アプリの公開範囲内にいるメンバーの DingTalk ユーザー ID（`userId`） |
| `fixed_group` | ロボットが参加しているグループの `openConversationId` |

Stream モードでメッセージを受信すると、Mole Agent はロボット経由で DingTalk に応答できます。 [IM での Mole Agent](/ja/im#dingtalk)を参照してください。**カードテンプレートID**も設定すると、アラート通知は確認ボタンと解決ボタンが付いたインタラクティブカードになります。テンプレートの作成方法は [DingTalk のインタラクティブカード](/ja/im#dingtalk-のインタラクティブカード)を参照してください。

### DingTalk Webhook

カスタムロボットの URL を **Webhook URL** に貼り付けます。ロボットがリクエストに署名する場合は、 **署名用シークレット**も入力します。MoleSignal はすべてのリクエストにタイムスタンプと HMAC-SHA256 署名を追加します。 `fixed_group` ターゲットは設定した URL を使用し、`webhook` ターゲットはその URL を置き換えます。

### WeCom アプリ

自社で作成した WeCom アプリを使用します。**企業ID**、アプリの**シークレット**、**AgentId** を入力します。 MoleSignal はこれらをアクセストークンと交換して Markdown メッセージを送信します。WeCom はメッセージを 4,096 バイトで切り詰めます。MoleSignal の接続元アドレスをアプリの信頼済み IP に追加します。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | アプリの公開範囲内にいるメンバーのユーザー ID |
| `fixed_group` | アプリが作成したグループのチャット ID |

**コールバックトークン**と **EncodingAESKey** を設定し、コネクターのコールバック URL をアプリの**メッセージ受信**に入力すると、メンバーへのアラート通知は確認ボタンと解決ボタンが付いたテンプレートカードになります。[WeCom アプリのボタン](/ja/im#wecom-アプリのボタン)を参照してください。

### WeCom Webhook

グループロボットの URL を **Webhook URL** に貼り付けます。`fixed_group` ターゲットはその URL を使用し、`webhook` ターゲットはその URL を置き換えます。

### WeCom スマートボット

API モードで常時接続を介してメッセージを受信する WeCom スマートボットを使用します。ボットの **ボットID**と、ボット用に作成した**常時接続用シークレット**を入力します。**常時接続先アドレス**は `wss://openws.work.weixin.qq.com` に固定されています。Mole Agent の **IM** で有効にすると、Mole Agent は WeCom に応答し（[IM での Mole Agent](/ja/im#wecom)を参照）、ボットは通知も配信します。メッセージと返信はすべて常時接続を経由します。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | スマートボットから見たメンバーの userid |
| `fixed_group` | グループのチャット ID |

ボットが送信できるのは、ボットに直接メッセージを送ったメンバーとの会話と、ボットがメンションされたチャットだけです。アラート通知には確認ボタンと解決ボタンが付いたテンプレートカードを使用し、その他の通知には Markdown を使用します。通知を送信するサーバーがボットとの接続を保持していない場合は、接続を保持するサーバーが通常は数秒以内に送信します。どのサーバーも接続を保持していない場合は配信に失敗します。このコネクターに登録したメンバーの通知方法は、 IM で問い合わせたメンバーの識別にも使います。

### Microsoft Teams ボット

Bot Framework ボットを使用します。**アプリID**、**クライアントシークレット**、**テナントID**を入力します。旧式のマルチテナントボットでは、テナントに `botframework.com` を指定します。ボットの**クラウド**に Global、GCC、 GCC High、DoD のいずれかを選択します。サービス URL は選択に応じて決まります。GCC High と DoD では `login.microsoftonline.us` からトークンを取得し、政府機関向けの Bot Framework が Mole Agent 宛てのメッセージを検証します。送信先のユーザーやチームにボットをインストールしてください。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | Teams のユーザー ID（`29:…`）またはユーザーの Microsoft Entra オブジェクト ID |
| `fixed_group` | チャンネルまたはグループチャットの会話 ID（`19:…`） |

MoleSignal が提示するコールバックアドレスを Azure Bot のメッセージングエンドポイントに入力すると、 Mole Agent はボット経由で Teams に応答できます。[IM での Mole Agent](/ja/im#microsoft-teams)を参照してください。

### Microsoft Teams Webhook

Workflows のフロー（**Webhook 要求を受信したときにチャネルに投稿する**）でチャンネル Webhook を作成するか、従来の着信 Webhook を使用します。その URL を **Webhook URL** に貼り付けます。MoleSignal は各メッセージを Adaptive Card として送信します。

### Google Chat アプリ

Chat アプリのサービスアカウントを使用します。アカウントの JSON キーを**サービスアカウントキー**に貼り付けます。キーは暗号化してコネクターに保存し、返却しません。MoleSignal はキーでトークンリクエストに署名し、アプリとしてメッセージを送信します。キーの `token_uri` には Google のトークンエンドポイントを指定します。 `https://oauth2.googleapis.com/token`（古いキーでは `https://accounts.google.com/o/oauth2/token`）を使用します。それ以外のアドレスを指定するキーは保存できません。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | アプリにメッセージを送信したか、アプリをインストールしたユーザー（`users/123…`） |
| `fixed_group` | アプリが参加しているスペース（`spaces/AAAA…`） |

**Pub/Subサブスクリプション**（`projects/<project>/subscriptions/<name>`）を設定すると、アプリを通じて Mole Agent が Google Chat に応答できます。[IM での Mole Agent](/ja/im#google-chat)を参照してください。アプリが通知の送信にしか使われない場合は、空欄のままにします。

### Google Chat Webhook

スペースの着信 Webhook URL を **Webhook URL** に貼り付けます。`fixed_group` ターゲットはその URL を使用し、 `webhook` ターゲットはその URL を置き換えます。

### Telegram ボット

Telegram で **@BotFather** にメッセージを送り、`/newbot` でボットを作成します。発行されたトークン（例：`123456789:AAE…`）を**ボットトークン**に入力します。MoleSignal は `https://api.telegram.org` の Bot API を使い、リンクプレビューを無効にして送信します。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | Telegram ユーザーの数値 ID です。@ユーザー名ではありません。ユーザーは先に Telegram でボットを開き、**開始**を押す必要があります。Telegram ボットはそれ以外のユーザーには送信できません。@userinfobot などのボットにメッセージを送ると、送信者の ID を確認できます |
| `fixed_group` | グループやチャンネルのチャット ID である負の数（スーパーグループとチャンネルでは `-100…`）、または公開チャンネルの `@username` です。ボットをグループに参加させるか、チャンネルの管理者に設定してください |

**Mole Agent → 設定 → IM** でコネクターを有効にすると、Mole Agent は Telegram に応答し、ボット経由のアラート通知に確認ボタンと解決ボタンが付きます。 [Telegram](/ja/im#telegram)と[アラートカード](/ja/im#アラートカード)を参照してください。

### Discord Webhook

Discord チャンネルの設定で **インテグレーション → Webhook** を開き、Webhook を作成して URL をコピーします。 **Webhook URL** に貼り付けます（`https://discord.com/api/webhooks/…` のほか、`discordapp.com` や `ptb.` と `canary.` のホストも使用できます）。**表示名**（最大 80 文字）と**アバター URL** はオプションです。指定すると、送信メッセージ上で Webhook の名前とアバターが置き換わります。

通知ごとに 1 つの埋め込みを送信します。[インスタントメッセージング用テンプレートのカード](#インスタントメッセージテンプレートのカード)を参照してください。本文中のメンションでは通知しません。`fixed_group` ターゲットは設定した URL を使用し、`webhook` ターゲットはその URL を置き換えます。Webhook URL に `?thread_id=` が含まれる場合、チャンネル内の指定スレッドに投稿します。

### Mattermost ボット

システムコンソールでボットアカウントを許可します（**インテグレーション → ボットアカウント → ボットアカウントの作成を有効にする**）。**インテグレーション → ボットアカウント**でボットを追加してアクセストークンをコピーします。次の項目を入力します。

- **サーバー URL** — Mattermost サーバーのアドレスです。例：`https://chat.example.com`。
- **ボットトークン** — ボットのアクセストークンです。
- **タイムアウト** — 1～60 秒の値です。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | ユーザー名（`@` は省略可）または 26 文字のユーザー ID です。ユーザーとボットのダイレクトチャンネルに投稿します |
| `fixed_group` | チャンネル ID、またはチャンネルの URL に含まれる `team-name/channel-name` です。ボットをチームに参加させてください。非公開チャンネルの場合は、ボットをそのチャンネルにも参加させてください |

このコネクターでは、メンバーの通知方法に Mattermost のユーザー名またはユーザー ID を使用します。投稿には Slack 形式のメッセージ添付を使用します。`http.external_url` を設定すると、アラート通知に確認、解決、スヌーズのボタンが付きます。[Mattermost ボットのボタン](/ja/im#mattermost-ボットのボタン)を参照してください。

### Mattermost Webhook

Mattermost の **インテグレーション → 内向きのウェブフック**で着信 Webhook を追加し、その URL （`https://chat.example.com/hooks/…`）を **Webhook URL** に貼り付けます。`fixed_group` ターゲットはその URL を使用し、`webhook` ターゲットはその URL を置き換えます。Webhook の投稿にはボタンがなく、アラートへのリンクのみが付きます。

### Webex ボット

`developer.webex.com` の **My Webex Apps** でボットを作成し、ボットのアクセストークンを **ボットトークン**に入力します。MoleSignal は `https://webexapis.com/v1` 経由で投稿します。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | Webex アカウントのメールアドレス、または Webex のユーザー ID |
| `fixed_group` | ボットが参加しているスペースのルーム ID |

各メッセージに Markdown と Adaptive Card を含めます。カードに対応したクライアントは Markdown の代わりにカードを表示します。カード上の項目は押せません。個人宛てのアラート通知にはボタンではなく、[ワンタイムアクションリンク](#1-回限りのアクションリンク)が付きます。

### Webex Webhook

Webex App Hub から **Incoming Webhooks** インテグレーションを追加し、スペースを選択します。発行された URL （`https://webexapis.com/v1/webhooks/incoming/…`。`api.ciscospark.com` の旧 URL も使用可）を **Webhook URL** に貼り付けます。メッセージは Markdown 形式で、Webhook に指定したスペースに送信されます。`fixed_group` ターゲットは設定した URL を使用し、`webhook` ターゲットはその URL を置き換えます。

### Matrix ボット

ボット用の Matrix アカウントを作成して Element でサインインし、 **設定 → ヘルプとバージョン情報 → 詳細**からアクセストークンをコピーします。トークンはそのセッションに紐づくため、サインアウトすると無効になります。**ホームサーバー URL** に `https://matrix.org` などの HTTPS アドレスを入力し、 **アクセストークン**を入力します。

| ターゲットの種類 | 値 |
|---|---|
| `direct_user` | `@name:matrix.org` などのユーザー ID です。ボットはユーザーとのダイレクトルームに投稿します。初回通知時にボットがルームを作成し、ユーザーを招待します。ユーザーは招待を承諾するとメッセージを確認できます |
| `fixed_group` | ルーム ID（`!…`）またはエイリアス（`#name:server`）です。未参加のボットは、誰でも参加できるルームか、招待済みのルームに参加します。それ以外の場合はボットを招待してください |

各メッセージにはプレーンテキストと HTML が含まれます。メッセージ内のメンションでは通知しません。MoleSignal はメッセージを暗号化せずに送信します。

### 音声通話と SMS 用の電話番号

音声通話と SMS のコネクターは、メンバーが登録した電話番号（`direct_user`）またはフォールバックルートに設定した固定の電話番号（`fixed_address`）のいずれか 1 件に送信します。`+` と国番号を付けて入力します。例： `+14155550100`。空白とハイフンは削除されます。Alibaba Cloud、Tencent Cloud、Huawei Cloud、汎用 HTTP SMS のコネクターでは、中国本土の 11 桁の携帯電話番号も使用できます。

通話では通知のタイトル、続いて本文を合計 400 文字まで読み上げます。SMS では 1 行目にタイトル、 2 行目に本文を記載し、合計 320 文字まで送信します。通知ポリシーが電話チャネルまたは SMS チャネル用にテンプレートを指定している場合は、タイトルを付けず、テンプレートの本文だけを読み上げるか送信します。Alibaba Cloud、Tencent Cloud、Huawei Cloud は承認済みのテンプレートのみを送信します。コードと変数は、 [通知テンプレートでのプロバイダーテンプレートの使用](#通知テンプレート内のプロバイダーテンプレート)に従って、通知テンプレートに記述します。

プロバイダーは同じ番号への発信や SMS 送信の頻度を制限します。頻度制限、無効な番号、未承認のテンプレートなどを理由にプロバイダーが拒否すると、配信は失敗します。通知ポリシーはメンバーの次の通知方法とフォールバックルートに進みます。通話に応答したか、内容を聞いたかは報告されません。配信の成功は、プロバイダーが通話や SMS を受け付けたことを示します。

1 つのコネクターが同じ番号に発信する頻度は、1 分に 1 回までです。その 1 分以内に届いた通知は番号ごとに待機し、配信ログに**マージ待ち**と表示されます。1 分経過すると 1 回の通話にまとめて、通知のタイトルを順に読み上げます。電話用テンプレートを使う通知では本文を読み上げます。待機中に確認済みになった通知は除外します。Alibaba Cloud、Tencent Cloud、Huawei Cloud では、最初の通知のテンプレートを読み上げ、各変数にすべての通知の値を順に入れます。 Alibaba Cloud はもともと同じ番号への発信を 1 分に 1 回に制限しているため、アラートが集中してもこの制限で拒否されなくなります。通知ポリシーで [通知のマージ](#通知をまとめる)にさらに長い時間枠を設定している場合は、その時間枠を使用します。

### Alibaba Cloud 音声通話

Alibaba Cloud Voice Service を使い、中国本土の電話番号にのみ音声通知を送信します。 Voice Service コンソールで企業認証を完了し、**テキスト読み上げ**方式の音声通知テンプレートを申請します。例：`Hello, ${content}. Please handle it now.`。続いて、Voice Service の呼び出しだけを許可した RAM ユーザーの AccessKey を作成します。次の項目を入力します。

- **AccessKey ID** と **AccessKeyシークレット**。
- **リージョン** — Alibaba Cloud が提供するリージョンのいずれかです。APIベースURL は選択に応じて決まります。
- **発信者番号** — 共有モードでは空欄にします。専用モードでは購入した番号を指定します。すべての通話にその番号が表示されるため、オンコール担当者は連絡先に登録できます。テンプレートには、発信者番号と同じモードを使用してください。
- **読み上げ回数** — 1～3 回です。

テンプレートコード（`TTS_` で始まるコード）と変数を電話用の通知テンプレートに記述します。通知ポリシーで、このテンプレートを電話チャネル用に選択します。[通知テンプレートでのプロバイダーテンプレートの使用](#通知テンプレート内のプロバイダーテンプレート)を参照してください。Alibaba Cloud は同じ番号への発信を 1 分に 1 回、1 時間に 5 回、1 日に 20 回までに制限し、上限を超える通話を拒否します。変数にリンクや IP アドレスを含めないでください。

### Alibaba Cloud SMS

SMS コンソールで **SMS シグネチャ**と**通知**テンプレートを申請します。例： `${content}. Please handle it now.`。次に、AccessKey、**リージョン**、**シグネチャ**を入力します。 Alibaba Cloud が提供するリージョンから選択してください。一部の海外リージョンには専用のアドレスがあり、 APIベースURL はリージョンに応じて決まります。テンプレートコード（`SMS_` で始まるコード）と変数を SMS 用の通知テンプレートに記述し、通知ポリシーで SMS チャネル用に選択します。[通知テンプレートでのプロバイダーテンプレートの使用](#通知テンプレート内のプロバイダーテンプレート)を参照してください。

通知テンプレートの変数は既定で 35 文字までです。Alibaba Cloud が企業アカウントの上限を引き上げたら、通知テンプレートの**変数あたりの文字数**を増やします。変数にリンクや IP アドレスは含められません。中国本土の携帯電話番号または国際電話番号を使用できます。

### Tencent Cloud 音声通話

音声メッセージコンソールでアプリケーションを作成して `VoiceSdkAppid` を取得し、音声通知テンプレートを申請します。次に、サブユーザー用の API キーを作成します。**SecretId**、**SecretKey**、 **リージョン**（キーを使って取得し、APIベースURL の決定に使用）、**アプリID（SdkAppId）**、 **読み上げ回数**（1～3 回）を入力します。テンプレート ID と変数を電話用の通知テンプレートに記述し、変数名には位置に応じて `1`、`2`、`3` を指定します。[通知テンプレートでのプロバイダーテンプレートの使用](#通知テンプレート内のプロバイダーテンプレート)を参照してください。

音声通話は前払い制です。パッケージの残量がなくなると通話に失敗し、配信ログに `InsufficientBalanceInVoicePackage` が表示されます。通知ポリシーはメンバーの次の通知方法に進むため、電話以外の通知方法も設定してください。生成される通話は最大 350 文字です。Tencent Cloud のドキュメントには変数ごとの上限が記載されていませんが、長すぎる値は拒否されます（`ContentLengthLimit`）。値は既定で 20 文字に切り詰めます。より大きな上限は通知テンプレートで指定します。

### Tencent Cloud SMS

SMS コンソールでアプリケーションを作成して `SmsSdkAppId` を取得し、シグネチャとテンプレートを申請します。次に、**SecretId**、**SecretKey**、**リージョン**、**アプリID（SdkAppId）**、 **シグネチャ**（ID ではなくシグネチャのテキスト。中国本土向け SMS では必須）を入力します。テンプレート ID と変数を SMS 用の通知テンプレートに記述し、変数名には位置に応じて `1`、`2`、`3` を指定します。

<Warning>
  2024 年 1 月 25 日より後に開設したアカウントや、長期間使用していないアカウントでは、既定で変数 1 つにつき **6 文字**まで使用でき、それを超える値は拒否されます（`TemplateParameterLengthLimit`）。既定では値を 6 文字に切り詰めるため、アラートのタイトルはほとんど残りません。Tencent Cloud が上限を引き上げたら、通知テンプレートの**変数あたりの文字数**に新しい上限を入力します。変数にリンクは含められません。
</Warning>

API 呼び出し全体が成功しても、対象の番号に送信できたとは限りません。その番号の結果が `Ok` でなければ配信は失敗し、配信ログに理由が表示されます。

### Huawei Cloud 音声通話

音声通話コンソールでアプリケーションを作成し、固定電話番号を購入して音声テンプレートを申請します。次の項目を入力します。

- **AppKey**、**AppSecret**、**アプリのアドレス** — すべてアプリケーション管理にあります。アドレスはそのままコピーします。API では取得できません。
- **発信者番号** — 購入した固定電話番号です。国番号、市外局番、電話番号の順に入力します。

テンプレート ID と変数を電話用の通知テンプレートに記述し、変数名には位置に応じて `1`、`2`、`3` を指定します。変数は最大 32 バイトです。漢字 1 文字は 3 バイトを使い、上限を超える値は切り詰めます。変数に `$`、`{`、`}` が含まれる場合は削除します。

### Huawei Cloud SMS

メッセージおよび SMS コンソールでアプリケーションを作成し、シグネチャとテンプレートの承認を受けます。 **AppKey**、**AppSecret**、**アプリのアドレス**（すべてアプリケーション管理にあります）と**チャネル番号**（シグネチャに対応する番号）を入力します。汎用テンプレートには**シグネチャ名**も必要です。テンプレート ID と変数を SMS 用の通知テンプレートに記述し、変数名には位置に応じて `1`、`2`、`3` を指定します。変数ごとの上限はプロバイダーのテンプレートに記載されています（例：`TXT_20`）。値は既定で 20 文字に切り詰めます。別の上限を使う場合は通知テンプレートで指定します。

### Twilio 音声通話

Twilio コンソールで**アカウント SID**と**認証トークン**を確認し、次の項目を入力します。

- **発信元電話番号** — アカウントに登録されている音声通話対応の番号です。例：`+14155550100`。
- **言語** — 通知を読み上げる言語です。例：`en-US`、`cmn-CN`。
- **音声** — オプションです。例：`Polly.Joanna`、`Polly.Zhiyu`。空欄の場合は Twilio の既定の音声を使用します。
- **読み上げ回数** — 1～3 回です。

### Twilio SMS

**アカウント SID**、**認証トークン**、**送信元**を入力します。送信元には、アカウントの電話番号（E.164）、Messaging Service（`MG…`）、または送信先の国で許可されている場合は最大 11 桁の英数字の送信元 ID を指定します。米国の番号に SMS を送信するには、事前に A2P 10DLC に登録する必要があります。

### Twilio WhatsApp

SMS チャネルで Twilio 経由の WhatsApp メッセージを送信します。**アカウント SID**と**認証トークン**を入力します。 **WhatsApp送信元**には、アカウントの WhatsApp 対応番号（例：`+14155550100`）か、 WhatsApp 送信元を設定した Messaging Service（`MG…`）を指定します。メンバーの通知方法には、 SMS と同じ形式で WhatsApp の電話番号を入力します。

WhatsApp では、企業が会話を開始する際に、承認済みのテンプレートしか使用できません。 Twilio の **Content Template Builder** でテンプレートを作成し、WhatsApp 用の承認を受けます。Content SID （`HX…`）と変数を SMS 用の通知テンプレートの **WhatsApp** セクションに記述し、変数名には位置に応じて `1`、 `2`、`3` を指定します。[通知テンプレートでのプロバイダーテンプレートの使用](#通知テンプレート内のプロバイダーテンプレート)を参照してください。通知ポリシーで、そのテンプレートを SMS チャネル用に選択します。WhatsApp セクションがない場合は送信せず、配信ログに理由を表示します。

WhatsApp は改行やタブを含む変数を拒否します。そのため各値を 1 行にまとめ、 Markdown の書式記号を除いて送信します。空の値は `-` として送信します。**返信の処理**を有効にすると、返信コードを含む返信を SMS と同様に処理します。[SMS と通話への返信](#メッセージへの返信と通話での応答)を参照してください。

### AWS 音声通話と SMS

AWS 音声通話（`aws_voice`）は AWS End User Messaging の `SendVoiceMessage` で発信し、Amazon Polly が通知を読み上げます。AWS SMS（`aws_sms`）は `SendTextMessage` でトランザクション SMS を送信します。次の項目を入力します。

- **リージョン** — アカウントで有効なリージョンです。コネクターの認証情報を入力すると、 EC2 の `DescribeRegions` で AWS から一覧を取得します。End User Messaging を利用できないリージョンでは送信に失敗します。
- **認証** — AWS データコネクターと同じ方式を使用できます。アクセスキー、一時キー、ノード ID、引き受けるロール、Web ID のいずれかです。ロールを引き受けるには、ページに表示される外部 ID をロールの信頼ポリシーに設定する必要があります。
- **送信元 ID** — 電話番号、電話番号 ID、プール ID、またはこれらの ARN です。音声通話では必須で、音声通話に対応した番号が必要です。SMS では空欄にして AWS に宛先に応じた番号を選ばせるか、送信元 ID を指定できます。
- **Polly の音声** — 音声通話専用のオプションです。空欄の場合は `MATTHEW` を使用します。中国語（標準中国語）には `ZHIYU` を指定します。
- **APIベースURL** — リージョンに応じて決まります。例：`https://sms-voice.us-east-1.amazonaws.com`。

IAM アイデンティティには `sms-voice:SendVoiceMessage` または `sms-voice:SendTextMessage` が必要です。リージョンの一覧を取得するには、 `ec2:DescribeRegions` も必要です。AWS アカウントがまだサンドボックス内にある場合は、検証済みの番号にしか送信できません。

### 汎用 HTTP SMS

設定した HTTP リクエストを使って、SMS を独自の SMS ゲートウェイや専用コネクターのないプロバイダーに渡します。次の項目を入力します。

- **ゲートウェイ URL** — リクエストの送信先です。プレースホルダーを使用できます。GET ゲートウェイの例： `https://sms.example.com/send?to={{phone}}&msg={{content}}`。
- **HTTPメソッド** — POST、PUT、GET のいずれかです。GET にはボディがありません。
- **本文の形式**と**ボディ** — JSON またはフォーム（`x-www-form-urlencoded`）です。既定値は `{"phone": "{{phone}}", "content": "{{content}}"}` です。
- **ヘッダー（JSON）** — 例：`{"Authorization": "Bearer {{secret}}"}`。
- **シークレット** — ゲートウェイが要求するトークンまたはパスワードです。暗号化して保存します。 URL、ヘッダー、ボディでは `{{secret}}` で参照します。
- **電話番号の形式** — `+8613800138000`（E.164）、`8613800138000`（+ なし）、`13800138000`（中国本土の国番号なしの番号）のいずれかです。
- **成功判定フィールド**と**成功判定値** — オプションです。2xx レスポンスを送信成功とみなします。`code` や `result.status` などの成功判定フィールドを設定した場合は、JSON レスポンスのそのフィールドが成功判定値と一致する必要もあります。

| プレースホルダー | 値 |
|---|---|
| `{{phone}}` | 指定の電話番号の形式に従った SMS の送信先番号 |
| `{{content}}` | SMS の内容。1 行目にタイトル、2 行目に本文を記載し、合計 320 文字まで |
| `{{title}}` | 通知のタイトル |
| `{{text}}` | 通知の本文 |
| `{{secret}}` | シークレット |

値は挿入先に応じてエスケープします。JSON ボディでは JSON 文字列としてエスケープし、フォームや URL では URL エンコードします。リクエスト内に電話番号と SMS の内容の両方を含めてください。含めないとコネクターを保存できません。

### 汎用 Webhook

デフォルト URL を入力し、`POST`、`PUT`、`PATCH` のいずれかを選択して、**ボディ**を指定します。

- **MoleSignal イベント**（デフォルト）— 機械処理用の JSON です。バージョン、イベント、アラート、ルール、エスカレーションに加えて、ターゲットとレンダリング済みのメッセージを含みます。
- **通知テンプレートの本文** — 通知ポリシーが Webhook チャネル用に選んだテンプレートの本文を記述どおりに送信します。JSON テンプレートは JSON として送信します。[条件](#条件)と、 [テンプレートとポリシーの作成](#テンプレートとポリシーを作成する)に記載の形式を参照してください。

すべてのリクエストに `X-MoleSignal-Event`（通知の種類）と `X-MoleSignal-Delivery`（受信側が重複を除外するための配信 ID）が付きます。16 文字以上の**署名用シークレット**を設定すると、 `X-MoleSignal-Timestamp` と `X-MoleSignal-Sign` も付き、受信側はリクエストの送信元が MoleSignal であることを確認できます。ボディのフィールド、署名、署名の検証例は [Webhook 通知コネクター](/ja/notification-channels/webhooks#汎用-webhook)を参照してください。

`direct_user`、`fixed_address`、`fixed_group` の場合、MoleSignal は設定したデフォルト URL に送信し、ルーティングデータにターゲットを含めます。`webhook` の場合は、ターゲットの値がデフォルト URL を置き換えます。2xx レスポンスは成功です。レスポンスに `X-Request-ID` が含まれる場合、MoleSignal はそのヘッダー値をプロバイダーのメッセージ ID として記録します。Webhook は[マージ](#通知をまとめる)しません。通知ごとにリクエストを送信します。

<Warning>
  Webhook URL、認証ヘッダー、トークン、パスワード、署名用シークレットは認証情報です。テストターゲット、テンプレート、イベント属性に認証情報の値を入れないでください。
</Warning>

### Amazon SNS

各通知を Amazon SNS トピックに発行します。トピックのサブスクリプションは、通知を Lambda、SQS、 HTTPS エンドポイント、メールなどに転送します。次の項目を入力します。

- **認証**と**リージョン** — [AWS 音声通話と SMS](#aws-音声通話と-sms)と同じです。リージョンには、トピックの ARN に含まれるリージョンを指定します。
- **トピック ARN** — 例：`arn:aws:sns:us-east-1:123456789012:alerts`。
- **メッセージ** — デフォルトの **MoleSignal イベント**を選ぶと、[汎用 Webhook](#汎用-webhook)と同じ JSON を発行します。**通知テンプレートの本文**を選ぶと、通知ポリシーが Webhook チャネル用に選択したテンプレートの本文を発行します。

件名には、通知タイトルを 100 文字未満の 1 行で指定します。すべてのメッセージに `alert.triggered` などの `event_type` メッセージ属性が付き、アラートには `severity` も付きます。サブスクリプションのフィルターポリシーはこれらの属性を照合できます。FIFO トピック（名前が `.fifo` で終わるトピック）では、同じアラートのメッセージを同一のメッセージグループに入れ、順序を維持します。配信 ID を重複排除 ID として使用するため、SNS は同じ配信を 2 回発行しても重複を破棄します。

IAM アイデンティティには、トピックへの `sns:Publish`、トピックを暗号化するキーへの `kms:GenerateDataKey` と `kms:Decrypt`、リージョンの一覧を取得するための `ec2:DescribeRegions` が必要です。どの種類のターゲットでも、メッセージは常にトピックに送信されます。

### PagerDuty

Events API v2 を使って PagerDuty のサービスにイベントを送信します。PagerDuty のサービスの**インテグレーション**タブで **Events API V2** インテグレーションを追加し、32 文字のルーティングキーであるインテグレーションキーを **インテグレーションキー**に貼り付けます。**サービスリージョン**は **米国**を選択します。アカウントのアドレスが `.eu.pagerduty.com` で終わる場合は **EU** を選択します。

| MoleSignal イベント | PagerDuty イベント |
|---|---|
| アラート発生、アラートエスカレーション | `trigger` |
| アラート確認済み | `acknowledge` |
| アラート解決済み | `resolve` |
| その他のイベント | `trigger`（個別の PagerDuty アラートとして作成） |

MoleSignal の各アラートは、発生から解決まで 1 件の PagerDuty アラートに対応します。重複排除キー `molesignal-<alert ID>` で照合するため、エスカレーション時には新規アラートを作成せず、同じアラートを再度トリガーします。 `trigger` には、概要としてタイトル（最大 1,024 文字）、ソースとしてアラートのサービス（サービスがない場合は `MoleSignal`）、重大度（`critical`、`error`、`warning`、`info` のいずれか）、時刻、カスタム詳細として汎用 Webhook が送信するイベントが含まれます。`http.external_url` を設定している場合は、アラートへのリンクも含まれます。

PagerDuty が受信するのは、通知ポリシーがこのコネクターに送信したイベントだけです。MoleSignal での確認や解決を PagerDuty のアラートにも反映するには、**アラート確認済み**と**アラート解決済み**のイベントも送信してください。どの種類のターゲットでも、イベントは常にキーに対応するインテグレーションに送信されます。

## ユーザーの通知方法を登録する

管理者は **設定 → 通知 → ユーザールーティング** を開き、メンバーを選択して **通知方法を登録** をクリックします。通知先ごとに、コネクターと外部の識別情報を1つずつ選択します。外部の識別情報には、メールアドレス、Slack や Lark のユーザーID、音声通話やSMSコネクターで使用する電話番号などがあります。

通知先を登録したら、次の手順を実行します。

1. テスト通知を送信し、プロバイダーが受け付けることを確認します。
2. 組織が通知先の所有者を確認したら、その通知先を検証します。
3. **アラートイベント**、**オンコールイベント**、または **レポート** の通知設定で通知先を有効にします。
4. 通知先が複数ある場合は、優先する通知先からフォールバック先の順に並べます。
5. 必要に応じて通知を抑制する時間帯を設定し、重大なアラートはその時間帯でも通知できるようにします。

### 応答がなければ次のステップに進む

アラートイベントの通知順序では、2番目以降の各ステップに分単位の待ち時間を設定できます。

| 設定 | 動作 |
|---|---|
| 最初のステップ | アラートが発報するか、対象メンバーにエスカレーションされた時点で通知を送信します。 |
| N分待機 | 対象メンバーに最初に通知してからN分経過しても、誰もアラートを確認済みにしていない場合に、再度通知を送信します。 |
| 前のステップと同じ分数 | 前のステップで通知の送信に失敗した場合にのみ送信します。 |

たとえば、Lark ですぐに通知し、3分後にSMS、5分後に電話で通知するように設定できます。アラートが確認済みまたは解決済みになると、以降のステップでは通知を送信しません。エスカレーション先のメンバーへの後続通知も送信しません。送信に失敗した場合も、すぐに次のステップに進みます。待ち時間は最大1日で、アラートイベントにのみ設定できます。オンコールイベントとレポートでは、送信に失敗した場合にのみ次の通知先に切り替えます。

メンバーは **アカウント設定 → 通知** で、自分の通知先と通知設定を管理できます。他のメンバーの設定を閲覧するには `org.members.read` が必要です。他のメンバーの通知先を変更したり、所有者を確認したりするには `org.members.update` が必要です。

<Note>
  通知先を削除する前に、すべての配信設定からその通知先を外してください。
</Note>

### Feishu と DingTalk での緊急通知

Lark アプリまたは DingTalk アプリのコネクターを使用するステップでは、通常のメッセージを送信した後にアプリから緊急通知を送信できます。ステップの横にあるドロップダウンで通知方法を選択します。

| プラットフォーム | 選択肢 | 要件 |
|---|---|---|
| Feishu（Lark アプリコネクター） | **アプリ内でBuzz**、**SMSでBuzz**、**電話でBuzz** | 通知方法に応じて、アプリ権限 `im:message.urgent`、`im:message.urgent:sms`、または `im:message.urgent:phone` が必要です。SMSと電話によるBuzzは、テナントの緊急通知クォータを消費します。国際版の Lark では、アプリ内のBuzzのみ利用できます。コネクターの **受信者IDの種類** には、メールアドレスではなく `open_id`、`user_id`、または `union_id` を指定します。 |
| DingTalk（DingTalk アプリコネクター） | **アプリ内でDING**、**SMSでDING**、**電話でDING** | DingTalk の Professional または Exclusive エディションと、アプリ権限 `Premium.Ding.Write` が必要です。SMSと電話によるDINGには、クォータの購入が必要です。DINGには通知タイトルが含まれ、電話でのDINGではそのタイトルを読み上げます。 |

アラートイベントの通知順序では、緊急通知方法を変えて、同じ通知方法を2回設定できます。たとえば、Feishu のメッセージをすぐに送信し、5分後に誰もアラートを確認済みにしていなければ、同じ Feishu の通知方法で **電話でBuzz** を実行します。他の通知順序では、各通知方法を1回だけ設定できます。

クォータ不足や権限不足などで緊急通知に失敗した場合は、通常のメッセージが届いていてもそのステップを失敗として扱い、すぐに次のステップに進みます。WeCom は緊急通知に対応していません。

## メッセージへの返信と通話での応答

音声通話、SMS、または WhatsApp コネクターで **返信の処理**（音声通話では **キー入力による操作**）を有効にすると、受信者は MoleSignal を開かずにアラートに対応できます。

- **テキストメッセージ**: アラートの発報時やエスカレーション時に送信するメッセージの末尾には、「確認済みにするには31、解決済みにするには32と返信してください」と表示します。該当するコードを返信するだけで操作できます。十の位は電話番号ごとに 0から9まで順に循環し、一の位は確認済みなら1、解決済みなら2です。`1` または `2` だけを返信すると、その電話番号が最後に受信したメッセージが対象になります。メッセージに複数のアラートがまとめられている場合は、1つのコードですべてに適用します。コードの有効期間は 1日です。
- **呼び出し回数**: アラートの読み上げ後に、確認済みにするには1、解決済みにするには2を押します。通話音声で処理結果を案内します。

返信やキー入力は、通知を受けたメンバーの操作として処理します。このメンバーには `alerts.incidents.acknowledge` 権限が必要で、アカウントと所属組織の両方が有効である必要があります。タイムラインにはSMS返信または電話でのキー入力として記録します。コードが含まれるのはメンバー宛てのメッセージだけです。フォールバックルートで指定した固定の電話番号宛てのメッセージには含まれません。

プロバイダーは返信やキー入力を MoleSignal のコールバックURLに送信します。そのため、外部URLの `http.external_url` を設定し、`/api/v1/public/notify/` 配下のパスにインターネットからアクセスできるようにします。[外部公開アクセス](/ja/public-access)を参照してください。機能を有効にしてコネクターを保存すると、コネクターにコールバックURLが表示され、コピーできます。

| コネクター | 設定手順 | コールバックの検証方法 |
|---|---|---|
| Twilio SMS | 電話番号の Messaging 設定で、**A message comes in** に Webhook と HTTP POST を選択し、コールバックURLを指定します。 | コネクターの Auth Token で Twilio の `X-Twilio-Signature` を検証します。 |
| Twilio WhatsApp | Twilio で、WhatsApp 送信者または紐づく Messaging Service の受信メッセージ用 Webhook にコールバックURLを指定し、HTTP POST を選択します。WhatsApp は承認済みのテンプレートのみを送信するため、テンプレート変数に `{{reply.ack}}` と `{{reply.resolve}}` を指定してコードを埋め込みます。クイック返信ボタンのIDにテンプレートでコードを設定すると、そのボタンはコードを返信した場合と同じように動作します。 | Twilio の署名を検証します。 |
| Twilio 音声通話 | 設定は不要です。各通話にキー入力用のURLが含まれます。 | Twilio の署名を検証します。 |
| AWS SMS | 電話番号で双方向SMSを有効にし、返信用の SNS トピックを指定します。そのトピックに、コールバックURLをエンドポイントとする HTTPS サブスクリプションを追加します。サブスクリプションは自動で確認されます。そのトピックからの返信のみを受け付けるには、**返信用 SNS トピック ARN** にトピックの ARN を指定します。 | `sns.<region>.amazonaws.com` からのみ証明書を取得し、SNS メッセージの署名を検証します。 |
| Alibaba Cloud SMS | SMS Service で、受信メッセージを HTTP 経由でコールバックURLにプッシュするように設定します。Alibaba Cloud は承認済みのテンプレートのみを送信するため、テンプレートのパラメーターに変数 `{{reply.ack}}` と `{{reply.resolve}}` を指定してコードを埋め込みます。[テンプレート変数](#テンプレート変数)を参照してください。 | URLに含まれるコールバックトークンを検証します。 |
| Alibaba Cloud 音声通話 | 通話は対話型音声通話（IvrCall）として発信されます。**発信者番号** には、IvrCall 用に購入した実際の電話番号が必要です。Voice Service で、通話結果を HTTP 経由でコールバックURLにプッシュするように設定します。テンプレートの読み上げ後、キー入力を10秒間待ちます。 | URLに含まれるコールバックトークンを検証します。 |
| Tencent Cloud SMS | SMS コンソールのコールバック設定で、返信コールバックにコールバックURLを指定します。テンプレート変数に `{{reply.ack}}` と `{{reply.resolve}}` を指定してコードを埋め込みます。 | URLに含まれるコールバックトークンを検証します。 |
| Tencent Cloud 音声通話 | 音声メッセージコンソールのイベントコールバック設定で、キー入力コールバックにコールバックURLを指定します。テンプレートには「確認済みにするには1、解決済みにするには2を押してください」と記載します。キー入力に含まれるのは着信先の電話番号だけなので、その番号への最新の通話を対象とします。 | URLに含まれるコールバックトークンを検証します。 |
| Huawei Cloud SMS | SMS アプリケーションの作成時に、受信SMSアドレスにコールバックURLを指定します。上記と同様に、テンプレートにコードを埋め込みます。 | URLの末尾にあるコールバックトークンを検証します。 |
| Huawei Cloud 音声通話 | アプリケーション管理で、通話ステータスの通知先アドレスにコールバックURLを指定します。テンプレートの読み上げ後にキー入力を1回受け付けます。テンプレートには「確認済みにするには1、解決済みにするには2を押してください」と記載します。 | URLの末尾にあるコールバックトークンを検証します。 |
| 汎用 HTTP SMS | ゲートウェイが受信したテキストを JSON `{"phone": "…", "text": "…"}` またはその配列として、コールバックURLに POST するように設定します。 | URLに含まれるコールバックトークンを検証します。 |

コールバックトークンは、サーバーのルートキーからコネクターごとに生成し、保存しません。URLは認証情報として扱ってください。AWS の音声メッセージはキー入力に対応していないため、`aws_voice` にはこの機能の切り替えスイッチがありません。

## 1 回限りのアクションリンク

ボタンを付けないコネクターで 1 人に送信するアラート通知の末尾には、確認待ちの間は **確認済みにする** と **解決済みにする**、確認後は **解決済みにする** のみが、1 回限りのリンクとして表示されます。対象はメールや、ボタンなしでアラートを送信するインスタントメッセージングコネクターです。たとえば、Webex ボットや **IM** で有効にしていない Lark アプリが対象です。カード形式では、既存のリンクボタンにこれらのリンクを追加します。それ以外の場合は、メッセージの末尾に表示します。リンクのテキストは受信者のインターフェース言語で表示します。

- リンクを開くと、サインインせずに MoleSignal のページ `https://<external address>/notify/actions/<token>` を表示できます。ページには、アラートの重大度、ステータス、タイトル、開始時刻と、ボタンが 1 つ表示されます。ページを開くだけでは何も実行しないため、メールスキャナーがリンクを開いても影響はありません。操作を実行するのは、ボタンを押したときだけです。
- リンクは 1 回だけ使用でき、有効期間は 24 時間です。ボタンを押すと、通知の受信者として操作を実行します。操作時点で、受信者には対象アラートに対する `alerts.incidents.acknowledge` 権限が必要です。また、アクティブな組織にアクティブなアカウントが必要です。
- リンクが使用済みまたは期限切れの場合、アラートが対応済みまたは復旧済みでリンクが適用できなくなった場合、または受信者がアラートを操作できなくなった場合は、ページにその旨を表示し、何も変更しません。
- リンクを付けるには `http.external_url` の設定が必要です。未設定の場合、通知にリンクを付けません。MoleSignal を内部ネットワーク内で運用する場合は、受信者がメールを読む環境からページとその API にアクセスできるようにしてください。 [パブリックアクセス](/ja/public-access)を参照してください。

グループ宛てやフォールバックルートの固定アドレス宛ての通知には、リンクを付けません。 SMS、電話、インテグレーションにもリンクを付けません。SMS と電話では、代わりに[応答](#メッセージへの返信と通話での応答)を使用します。

## テンプレートとポリシーを作成する

**設定 → 通知 → テンプレート**を開き、再利用できるメッセージ本文を作成します。通知のカテゴリとチャネルを選び、[変数](#テンプレート変数)を挿入するか、 [プリセットテンプレート](#プリセットテンプレート)を適用します。プレビュー用のイベント属性で、メッセージの表示を確認します。エディター右側の変数、プリセットテンプレート、プレビュー用のイベント属性は最初は折りたたまれています。各見出しを選択すると展開できます。テンプレート一覧はチャネル順に並びます。

| チャネル | 適用先 | 本文 |
|---|---|---|
| **一般** | 通知ポリシーで個別のテンプレートを選んでいないすべてのチャネルに適用します。 | テキスト、Markdown、HTML のいずれかです。 |
| **インスタントメッセージ**、**メールアドレス**、**Webhook** | 該当するチャネルにのみ適用します。 | テキスト、Markdown、HTML のいずれかです。インスタントメッセージは[カードとして送信](#インスタントメッセージテンプレートのカード)することもできます。Webhook では JSON も使えます。値は JSON 文字列としてエスケープします。値を埋め込んだ本文は有効な JSON である必要があり、[汎用 Webhook](#汎用-webhook)の**通知テンプレートの本文**として送信します。 |
| **SMS**、**電話** | 該当するチャネルにのみ適用します。 | プレーンテキストの本文だけを送信し、通知タイトルは含めません。SMS は最大 320 文字を送信し、電話は最大 400 文字を読み上げます。エディターに文字数が表示されます。 |

次に、**ポリシー**を開き、ルーティングルールを作成します。

1. イベントタイプとカテゴリを選択します。
2. JSON マッチャーを追加し、ポリシーの優先順位を設定します。**時刻**で**指定した時間帯内のみ**または **指定した時間帯外のみ**を選ぶと、毎週の時間帯に基づいて適用範囲を制限できます。判定にはイベントの発生時刻を使います。[休日カレンダー](/ja/alerting/on-call#休日カレンダー)で休日も考慮できます。適用時間外は、このポリシーから通知を送信しません。他のポリシーは引き続き適用します。
3. 受信者リゾルバーとその設定を選択します。
4. ユーザー設定を優先するか、1 つのコネクターに固定するか、複数のコネクターで送信するかを選択します。
5. 一般テンプレートを選択します。必要に応じてインスタントメッセージ、電話、SMS、その他のチャネル専用のテンプレートを選び、ユーザー、チーム、組織のフォールバックを有効にします。
6. 必要に応じて確認応答のタイムアウトとエスカレーションルートを設定します。アラートポリシーでは、 [通知をまとめる](#通知をまとめる)時間枠も設定できます。
7. リアルタイムの配信プレビューを確認します。実際のメンバーとルートを特定し、各ステップで使うテンプレート名を表示します。通知は送信しません。

配信時はコネクターのチャネルに応じてテンプレートを選びます。チャネル専用のテンプレートを優先し、なければ一般テンプレートを使います。どちらもなければイベント自体のメッセージを使います。通知ポリシーが使用中のテンプレートは、削除したり別のチャネルに移動したりできません。

現在、ポリシーはアラートのライフサイクルイベントとオンコールスケジュールのイベントに対応しています。ポリシーエディターには、稼働中のバックエンドがサポートするイベントタイプと受信者リゾルバーが表示されます。ポリシーは [サイレンス](/ja/alerting/silences)に一致するインシデントのアラートイベントの通知を抑止します。 [サイレンス適用中の通知](/ja/alerting/silences#サイレンス中の通知)を参照してください。

### 通知をまとめる

アラートが集中すると、同じ受信者やグループに数秒のうちに通知が相次ぐことがあります。アラートとエスカレーションの通知ポリシーでは、**通知をまとめる**で 30 秒、1 分、2 分、 5 分のいずれかを選べます（API では 10 秒から 10 分まで指定できます）。時間枠内に同じコネクターから同じ受信者に送るアラート通知をまとめます。最初の通知はすぐに送信し、残りは時間枠の終了時にまとめて送信します。その間に確認済みになったアラートは除外します。

- インスタントメッセージとメールでは、最初のタイトルに「(+N)」を付け、本文にアラートを一覧表示します。外部 URL を設定している場合は、各アラートからインシデントにリンクします。Feishu アプリや Slack アプリのカードには**すべて確認**ボタンが付きます。[アラートカード](/ja/im#アラートカード)を参照してください。
- SMS では各タイトルを順番に記載し、電話では順番に読み上げます。SMS への返信 1 回ですべてのアラートを操作できます。電話は設定にかかわらず 60 秒以上の時間枠でまとめます。
- 汎用 Webhook、PagerDuty、Amazon SNS の通知はまとめません。

アラートの発生、復旧、エスカレーションに対応する組み込みポリシーは、デフォルトで 1 分間の通知をまとめます。他のポリシーのデフォルトは**まとめない**です。

### テンプレート変数

本文、プロバイダーテンプレートの値、カードの各要素では、 `{{rule.name}}` などの変数を使えます。送信時に通知の値を埋め込みます。エディター右側の**変数**には、テンプレートのカテゴリで使える変数が表示されます。変数を選択すると、カーソル位置に挿入します。 `_at` で終わる名前はマイクロ秒単位のタイムスタンプを示し、`_time` で終わる名前は `2026-07-29 00:00:00 UTC` のような UTC の時刻を示します。イベントにない変数は、置換せずにそのまま残します。

アラートとエスカレーションの変数は次のとおりです。

| 変数 | 値 |
|---|---|
| `{{rule.name}}`、`{{rule.description}}` | ルールの名前と説明です。 |
| `{{severity}}`、`{{incident.status}}` | アラートの重大度とステータスです。 |
| `{{urgency}}`、`{{priority}}` | 緊急度レベルのキー（`high`、`low`、または組織が追加したレベル）と優先度（`P1`～`P9`、未設定の場合は空）です。[緊急度](/ja/alerting/on-call#緊急度)を参照してください。通知ポリシーでは、イベント属性 `urgency` と `priority` もマッチングに使えます。 |
| `{{urgency_name}}`、`{{priority_name}}` | 組織が[緊急度と優先度のレベル](/ja/alerting/on-call#緊急度と優先度のレベル)で設定した緊急度レベルと優先度の名前です。名前が未設定の場合は空になります。 |
| `{{value}}`、`{{threshold}}` | アラートをトリガーした値としきい値です。重大度が段階別のルールでは、アラートの重大度に対応するしきい値を使います。異常検知ルールにはしきい値がないため、`null` を出力します。 |
| `{{incident.url}}` | MoleSignal 内のアラートの URL です。外部 URL `http.external_url` の設定が必要です。 |
| `{{incident.started_time}}`、`{{incident.duration}}` | アラートの開始時刻と、`1h 5m` のような経過時間です。解決済みのアラートでは、解決時刻までを計算します。 |
| `{{incident.acknowledged_time}}`、`{{incident.acknowledged_by}}` | 確認済みの場合、確認時刻と、確認した担当者のユーザー ID です。 |
| `{{incident.resolved_time}}`、`{{incident.resolved_by}}` | 解決済みの場合、解決時刻と、解決した担当者のユーザー ID です。自動復旧したアラートに解決担当者はいません。 |
| `{{incident.assignees}}`、`{{affected_services}}` | 担当者のユーザー ID と影響を受けたサービスです。それぞれカンマ区切りで表示します。 |
| `{{service}}`、`{{environment}}` | アラートのラベルまたはアノテーションから取得したサービスと環境です。 |
| `{{labels}}`、`{{labels.<key>}}` | すべてのラベル（`service=api, env=production`）と、指定したラベルの値です。アノテーションには `{{annotations.<key>}}` を使います。 |
| `{{escalation.step}}`、`{{escalation.loop}}`、`{{escalation.target}}` | エスカレーションのステップ番号と周回番号（いずれも 1 から開始）、およびステップの通知先（`user`、`schedule`、`team`）です。エスカレーションでのみ使えます。 |
| `{{escalation.reason}}` | エスカレーション通知を送信した理由です。`step`（ポリシーが次のステップに進行）、`manual`（手動で即時エスカレーション）、`reassigned`、`responder_added`、`snooze_ended`、`ack_timeout`（確認済みのまま解決期限を超過）、`severity_raised`、`urgency_raised` のいずれかです。[インシデントを操作する](/ja/alerting/incidents#インシデントを操作する)を参照してください。 |
| `{{reply.ack}}`、`{{reply.resolve}}` | `31` や `32` など、返信で確認または解決するためのコードです。[返信で操作](#メッセージへの返信と通話での応答)を有効にした SMS コネクターが送信するアラートの SMS でのみ値を埋め込み、それ以外では変数をそのまま残します。 |

オンコールスケジュールでは `{{schedule.*}}`、`{{oncall.*}}`、`{{override.*}}` を使えます。マイクロ秒単位の `_at` の値に加え、引き継ぎ時刻とオーバーライドの時間枠には `{{oncall.transition_time}}`、`{{override.start_time}}`、`{{override.end_time}}` を使えます。すべてのカテゴリで `{{event.time}}`、`{{message.title}}`、`{{message.text}}` を使えます。任意のイベント属性は `{{event.attributes.<key>}}` で参照できます。

### 条件

本文には条件ブロックを記述できます。条件を満たす場合にのみブロックの内容を残します。

```text
{{#if severity == "critical"}}Act now{{else}}Take a look{{/if}}: {{rule.name}}
{{#if event.type == "alert.resolved"}}Recovered after {{incident.duration}}{{/if}}
{{#if annotations.runbook_url}}Runbook: {{annotations.runbook_url}}{{/if}}
```

- `{{#if variable == "value"}}` や `!=` で変数の値を比較します。変数だけを指定した場合は、値が空でなければ条件を満たします。
- `{{else}}` には条件を満たさない場合に残す内容を記述します。省略できます。
- ブロックは最大 5 階層までネストできます。`{{/if}}` で閉じていないブロックがあると保存できません。エディターは本文の下にエラーを表示します。
- プレビューでは、プレビュー用のイベント属性を使って条件を判定します。エディター右側の**条件**にはよく使う条件が表示されます。選択すると挿入できます。

### プリセットテンプレート

**プリセットテンプレート**には、ひな形となる本文が用意されています。適用後も本文を編集できます。一覧にはカテゴリとチャネルごとに表示されます。SMS と電話のテンプレートには、それぞれのチャネル専用のプリセットが表示されます。インスタントメッセージとメールにも専用のプリセットがあります。たとえば、アラートへのリンクを含むインスタントメッセージ用の Markdown や、表形式のアラートメールがあります。アラートには、発生、確認、解決の各通知用のプリセットがあります。確認済みまたは解決済みのプリセットを適用すると、対応する状態のサンプルアラートをプレビューします。プリセットの本文はインターフェースの言語に対応します。たとえば、中国語のインターフェースでは中国語の本文を適用します。

### 通知テンプレート内のプロバイダーテンプレート

Alibaba Cloud、Tencent Cloud、Huawei Cloud は承認済みのテンプレートのみを送信します。WhatsApp も承認済みのコンテンツテンプレートのみを送信します。SMS または電話のテンプレートには、プロバイダーごとに 1 つ登録できます。WhatsApp 用は SMS テンプレートにのみ登録できます。

- **テンプレートコード** — プロバイダーが発行したコードです。Alibaba Cloud では SMS 用が `SMS_`、音声用が `TTS_` で始まるコードを使います。Tencent Cloud と Huawei Cloud ではテンプレート ID を使います。WhatsApp では **コンテンツ SID** に、`HX` に続く 32 桁の 16 進数で構成される Twilio Content SID を入力します。
- **変数** — 各変数に埋め込む値です。本文と同じ形式で記述でき、 `{{rule.name}}` などの変数も使えます。Alibaba Cloud では、テンプレートの `${…}` 内の名前を使います。 Tencent Cloud、Huawei Cloud、WhatsApp では位置順に値を埋め込むため、名前には `1`、`2`、`3` を使います。
- **変数あたりの文字数** — 上限を超える値は切り詰めます。空欄の場合はデフォルト値を使います。Alibaba Cloud は 35 文字、 Tencent Cloud は SMS が 6 文字、音声が 20 文字、Huawei Cloud は SMS が 20 文字、音声が 32 文字（音声は 32 バイトでも切り詰めます）、 WhatsApp は 300 文字です。

これらのプロバイダーのコネクターは専用のテンプレートを使い、その他の SMS と電話のコネクターは通知テンプレートの本文を送信します。通知ポリシーがチャネルに指定したテンプレートに、そのプロバイダー用のテンプレートがない場合は配信に失敗し、配信ログに理由を記録します。

これらのコネクターをテストすると、該当するチャネルから、そのプロバイダー用のテンプレートを含むものを選び、プレースホルダーにサンプル値を入れて送信します。コネクターに紐付いたメンバーの電話番号をテストする場合は、該当するテンプレートのうち名前順で最初のものを使います。スケジュール済みの点検や自動化などから直接送信する場合は、通知テンプレートを使わないため、これらのコネクターは利用できません。

### インスタントメッセージテンプレートのカード

インスタントメッセージテンプレートで**カードとして送信**を有効にすると、アプリとグループボットがカードを送信します。無効にすると、従来どおりテキストを送信します。カードのテキストにはテンプレートのメッセージ本文を使います。そのほかに、次の項目を設定できます。

- **カードのタイトル** — 空欄の場合は通知タイトルを使います。
- **タイトルの色** — 重大度に応じた色（重大は赤、エラーはオレンジ、警告は黄色、その他は青、解決後は緑）または固定色を使います。
- **フィールド** — 名前と値の組み合わせです。たとえば、`Service` の値に `{{labels.service}}` を指定します。最大 10 件です。
- **リンクボタン** — ボタンのラベルとリンク先です。たとえば、 `Runbook` のリンク先に `{{annotations.runbook_url}}` を指定します。最大 5 件です。
- **フッター** — カードの下部に小さい文字で表示する 1 行のテキストです。

すべての項目で変数を使えます。イベントから値を埋め込めないフィールドやリンク、およびリンク先が HTTP または HTTPS でないリンクは省略します。エディターのプレビューはおおまかなレイアウトを示します。実際のカード形式はプラットフォームによって異なります。

| プラットフォーム | 送信形式 |
|---|---|
| **Lark** | インタラクティブカードです。タイトル帯に色を付け、フィールドを 2 列に配置し、区切り線の下にフッターを表示します。アプリでは、アラートの確認ボタンと解決ボタンの横にリンクボタンを配置します。 |
| **Slack** | カラーバー付きの Block Kit カードです。アプリでは、アラート操作ボタンの横にリンクボタンを配置します。 |
| **DingTalk** | ActionCard です。タイトルに色を付け、カードの下に最大 5 個のリンクボタンを配置します。リンクがない場合は Markdown を使います。アプリにカードテンプレート ID を設定している場合、アラート通知にはそのテンプレートのインタラクティブカードを使い、アラート操作ボタンを付けます。 |
| **WeCom** | カード風にレイアウトした Markdown です。タイトルに色を付けます（WeCom のテキスト色は緑、グレー、オレンジのみです）。アラート操作ボタンを付ける場合は、ボタン操作型のテンプレートカードを使います。フィールドは小見出しとテキストの組み合わせで最大 6 件表示します。カードを押すと MoleSignal が開きます。 |
| **Teams** | Adaptive Card です。タイトル帯に色を付け、フィールドを名前と値の組み合わせで表示し、リンクをボタンにして、区切り線の下にフッターを表示します。ボットでは、アラート操作ボタンと一緒にリンクボタンを配置します。 |
| **Google Chat** | カード形式です。フィールドをラベル付きの行にし、リンクをボタンにします。アプリでは、アラート操作ボタンと一緒にリンクボタンを配置します。Google Chat のカードタイトルには色を付けません。 |
| **Telegram** | メッセージ形式です。タイトル色の丸印の後に太字のタイトルを表示し、フィールドを 1 行ずつ並べ、フッターを斜体にします。最初の行にアラート操作ボタンを配置し、その下にリンクボタンを 1 行に 2 個ずつ並べます。非公開の URL を Telegram が拒否した場合は、リンクを本文の行として表示します。 |
| **Discord** | 埋め込み形式です。カラーバー、アラートへのリンク付きタイトル、本文とその下のリンク、横並びのフィールド、フッターを表示します。 |
| **Mattermost** | メッセージの添付形式です。カラーバー、アラートへのリンク付きタイトル、フィールド（短いものは横並び）、本文の下のリンク、フッターを表示します。ボットでは、添付の下にアラート操作ボタンを配置します。 |
| **Webex** | ボットでは、Teams と同じ構成の Adaptive Card を使い、リンクボタンは最大 5 個まで配置します。残りのリンクは本文の下に表示します。Webhook では Markdown を使います。 |
| **Matrix** | 書式付きメッセージです。タイトルに色を付け、フィールドをリストにし、その後にリンクを並べ、フッターを斜体で表示します。 |

グループボットはクリック操作を受け取れないため、カードに確認ボタンや解決ボタンを付けません。コネクターをテストするときは、インスタントメッセージテンプレートを選び、変数にサンプル値を入れたカードを送信できます。

### 組み込みポリシー

すべての組織には、以下の通知ポリシーが最初から用意されています。ポリシーを新規作成する前でも、アラートやオンコールイベントを関係者に通知できます。すべて**ユーザー設定を優先**します。メッセージを送信できない場合は、ユーザーのフォールバックエンドポイントを試し、次にチーム、組織のフォールバックルートを使います。テンプレートは指定せず、イベント自体のメッセージを送信します。

| 組み込みポリシー | イベント | 通知先 | 初期状態 |
|---|---|---|---|
| アラート発生：オーナーに通知 | アラートが発生 | アラートのオーナー。オーナーがいない場合は担当者 | オン |
| アラート解決：オーナーに通知 | アラートが解決 | アラートのオーナー。オーナーがいない場合は担当者 | オン |
| エスカレーション：ステップの対象者に通知 | アラートを個人にエスカレーション | ステップで指定した対象者 | オン |
| エスカレーション：ステップの対象チームに通知 | アラートをチームにエスカレーション | 対象チームのメンバー | オン |
| オンコールの引き継ぎ：両方の担当者に通知 | オンコールシフトの開始 | シフトを終える担当者と、シフトを開始する担当者 | オン |
| オンコールの空白：スケジュール管理者に通知 | オンコール担当者の不在 | スケジュールの管理者 | オン |
| アラート確認：オーナーに通知 | アラートを確認済みに変更 | アラートのオーナー。オーナーがいない場合は担当者 | オフ |
| オンコールのオーバーライド：関係者に通知 | オンコールのオーバーライドを作成 | 代わりに担当するメンバーと、元のオンコール担当者 | オフ |
| シフト交代：関係者に通知 | シフト交代を更新 | その段階で通知が必要な関係者。[シフト交代](/ja/alerting/on-call#シフト交代)を参照してください。 | オン |
| オンコール担当者に連絡できない場合：担当者とスケジュール管理者に通知 | オンコール担当者に連絡不可（シフト開始の 30 分前） | シフトを担当するメンバーとスケジュールの管理者。[アラートを受信できないメンバー](/ja/alerting/on-call#アラートを受信できないメンバー)を参照してください。 | オン |
| 取り込み予算の上限間近：指定の対象者に通知 | 取り込み予算の上限間近 | 予算で指定した対象者。[予算を設定する](/ja/streams#予算を設定)を参照してください。 | オン |
| 取り込み予算の上限超過：指定の対象者に通知 | 取り込み予算の上限超過 | 予算で指定した対象者。[予算を設定する](/ja/streams#予算を設定)を参照してください。 | オン |
| 重大インシデントの更新：ステークホルダーに通知 | 重大インシデントの更新 | インシデントの担当者、ロール、ステークホルダー。[更新を投稿する](/ja/alerting/major-incidents#進捗を投稿する)を参照してください。 | オン |
| 承認が必要：承認権限を持つメンバーに通知 | Mole Agent が承認をリクエスト（`agent.approval.requested`） | `agent.approve` を持つメンバー（最大 20 名、リクエスト元を除く）。[承認カード](/ja/im#承認カード)を参照してください。 | オン |

組み込みポリシーには、**通知ポリシー**一覧で**組み込み**と表示します。設定の変更や無効化はできますが、削除や名前の変更はできません。設定を変更したポリシーは、エディターの **デフォルトに戻す**で上記の設定に戻せます。スケジュール宛てのエスカレーションステップには、組み込みポリシーがありません。スケジュールごとに、受信者を**現在のオンコール担当者**に設定したポリシーを作成してください。

## フォールバックルートを設定する

**設定 → 通知 → フォールバックルート**を開きます。適用範囲として組織またはチームを選択し、通知カテゴリを選択します。有効なコネクターを1つ以上追加し、`fixed_address` または `fixed_group` を選択して、プロバイダー側の送信先を入力します。

有効な個人ルートの各ステージで配信に失敗すると、MoleSignalは表示順にルートを試します。ユーザー、チーム、組織の各フォールバックを使用するかどうかは、ポリシーで決まります。

## 配信を確認して再試行する

**設定 → 通知 → 配信ログ**を開きます。イベントID、ステータス、またはステージで絞り込みます。配信試行を選択すると、マスクされた送信先、コネクター、レイテンシー、プロバイダーのエラー、配信チェーン全体を確認できます。

- `notify.deliveries.read` 権限で配信履歴を確認できます。
- `notify.deliveries.acknowledge` 権限で元のイベントを確認済みにできます。
- `notify.deliveries.retry` 権限で失敗したルートを再試行できます。

再試行すると、新しい配信試行が作成されます。既存の配信履歴は変わりません。

配信に失敗したアラート通知は自動で再試行されます。アラートが確認済みまたは解決済みになると自動再試行は停止しますが、手動での再試行は引き続き可能です。

ステージが**直接**の配信は、[スケジュール済みログ検査](/ja/logs/inspections)など、コネクターと送信先を機能自体が指定する場合に行われます。直接配信にはポリシーが適用されず、再試行もできません。

## コネクターのライフサイクルとステータス

| ステータス | 意味 |
|---|---|
| **不明** | コネクターのテストがまだ完了しておらず、成功か失敗かが確定していません。 |
| **接続済み** | 直近のテストが成功しました。 |
| **エラー** | 直近のテストが失敗しました。その後のテストが成功するまで、通常のルーティングではこのコネクターをスキップします。 |
| **無効** | MoleSignalはこのコネクターをテストせず、このコネクター経由で配信もしません。 |

コネクターを無効にしても、参照は削除されません。ユーザーID、ポリシー、フォールバックルート、またはスケジュール済みログ検査がコネクターを参照している間は削除できません。コネクターを削除する前に、すべての参照を別のコネクターに切り替えてください。

## 配信のトラブルシューティング

| 症状 | 確認事項 |
|---|---|
| SMTP認証またはTLS接続が失敗する | ホスト、ポート、認証情報、TLSモード、送信元アドレス、DNS、外部へのネットワーク接続を確認してください。 |
| SlackがAPIエラーを返す | ボットトークン、`chat.postMessage` 権限、送信先ID、チャンネルへの参加状況を確認してください。 |
| Larkがメッセージを拒否する | アプリの権限、受信者IDの種類、チャットへの参加状況、Webhookシークレット、サーバーの時刻を確認してください。 |
| Webhookがエラーを返す | URL、メソッド、ヘッダーのJSON、タイムアウトを確認し、エンドポイントが2xxを返すことを確認してください。 |
| ユーザーに配信されない | IDとコネクターが有効で、カテゴリの通知設定にそのIDが含まれており、通知を停止する時間帯に該当しないことを確認してください。 |
| フォールバックが実行されない | ポリシーで該当レベルのフォールバックが有効になっており、カテゴリに有効なルートがあることを確認してください。 |
| 電話がかからない、またはSMSが送信されない | 電話番号が + と国番号で始まること、テンプレートと署名が承認済みであること、通知ポリシーがそのチャネルに選択したテンプレートに該当プロバイダー向けの定義があること、変数名が一致することを確認してください。プロバイダーのレート制限とアカウントのサンドボックス設定も確認してください。 |
| 返信やキー入力が反映されない | コネクターで**返信の処理**が有効で、プロバイダーのコールバック先がコネクターに表示されるURLと一致し、そのURLにインターネットからアクセスできることを確認してください。電話番号にコード付きのアラートSMSが届いていること、コードの発行から24時間未満であること、送信先のメンバーに `alerts.incidents.acknowledge` 権限があることも確認してください。 |
| メッセージが届いたのにFeishuまたはDingTalkのステップが失敗する | 緊急呼び出しに失敗しています。アプリの権限、緊急通知またはDINGの利用枠、DingTalkのエディションを確認してください。Feishuでは、受信者IDの種類とプラットフォームも確認してください。 |
| アクションリンクが機能しない | リンクが未使用で発行から24時間未満であること、アラートが引き続きそのアクションを待っていること、受信者に引き続き `alerts.incidents.acknowledge` 権限があることを確認してください。リンクを開いた環境からページと `/api/v1/public/notify/actions/` にアクセスできることも確認してください。 |
