ロールは、名前を付けた権限のセットです。権限ポリシーも権限のセットですが、複数のロールに関連付けたり、API トークンに適用したりできるよう、別に管理します。メンバーにはワークスペース全体に適用されるロールを [ユーザー](/ja/identity/members#ユーザー)で割り当てます。アクセス権の付与では、ユーザーまたはチームにロールを割り当てます。適用範囲は組織全体または選択したリソースで、必要に応じて有効期限を指定できます。**ID とアクセス → ロール**、**権限ポリシー**、または**アクセス権の付与**を開きます。

## ロール

**ロール**には、ワークスペースの組み込みロールとカスタムロールが表示されます。各ロールに関連付けたポリシー、付与する権限、使用先（メンバー、サービスアカウント、招待、バインディング）も確認できます。組み込みロールは読み取り専用です。[組み込みロール](/ja/identity#組み込みロール)を参照してください。

カスタムロールを作成するには、次の手順に従います。

1. **新規ロール**を選択します。
2. **キー**に英小文字、数字、アンダースコアを使って入力します。後から変更することはできません。
3. **名前**と**説明**を入力します。
4. **権限ポリシー**で、ロールに関連付けるポリシーにチェックを入れます。ロールには、これらのポリシーのすべての権限が付与され、ポリシーの変更も反映されます。
5. **ロール固有の権限**で、ポリシーに含まれない必要な権限にチェックを入れます。各権限には、許可する操作が表示されます。選択済みのポリシーが付与する権限にはあらかじめチェックが入り、付与元のポリシーも表示されます。ここではチェックを外せません。
6. **ロールを作成**を選択します。

ロールは、ロール固有の権限と、関連付けたポリシーの権限を付与します。どちらかを変更するには、カスタムロールを選択します。 **削除**でカスタムロールを削除できるのは、そのロールをメンバーシップ、サービスアカウント、招待、バインディングのいずれも使用していない場合に限ります。ロールの閲覧には `iam.roles.read`、変更には `iam.roles.manage`、削除には `iam.roles.delete` が必要です。

## 権限ポリシー

**権限ポリシー**には、ワークスペースの組み込みポリシーとカスタムポリシーが表示されます。ポリシーごとに、付与する権限と、そのポリシーを使用するロールやトークンを確認できます。ロールにはポリシーを関連付けることができ、API トークンにはポリシーを 1 つ適用できます。[トークンで許可される操作](/ja/identity/tokens#トークンで実行できる操作)を参照してください。

| 組み込みポリシー | 権限 |
|---|---|
| **読み取り専用オブザーバー** | オブザーバビリティデータ、ダッシュボード、アラート、スケジュール、保存済みビュー、パイプライン、関数、レポート、ステータスページ、外形監視、サービスレベル、ポストモーテムを閲覧します。 |
| **データアナリスト** | オブザーバビリティデータを探索し、ダッシュボードと保存済みビューを作成します。 |
| **パイプライン開発者** | オブザーバビリティデータを閲覧し、ストリーム、パイプライン、関数を管理します。 |
| **アラート管理者** | オブザーバビリティデータを閲覧し、アラートルール、スケジュール、ステータスページ、外形監視、ポストモーテムを管理します。 |
| **組織管理者** | 組織設定、メンバー、ロール、アクセス権の付与、API トークン、サービスアカウント、監査に加え、ステータスページ、外形監視、サービスレベル、ポストモーテムを管理します。 |
| **データ取り込み** | データを書き込み、デプロイを報告します。権限は `logs.write`、`metrics.write`、`traces.write`、`profiles.write`、`apm.deploy` です。取り込みトークンにはこのポリシーが適用されます。 |

組み込みポリシーは読み取り専用で、製品の更新に合わせて変更されます。組み込みポリシーを開いて、**カスタムポリシーとしてコピー**を選択すると、そのポリシーを基にカスタムポリシーを作成できます。

カスタムポリシーを作成するには、次の手順に従います。

1. **新規ポリシー**を選択します。
2. **名前**、英小文字、数字、アンダースコアで構成する**キー**（後から変更できません）、**説明**を入力します。
3. **権限**で、**ビジュアル**の権限にチェックを入れるか、**JSON**でドキュメントを記述します。どちらも同じドキュメントを編集します。JSON エディターは、最初に見つかったエラーの内容と位置を表示します。ドキュメントが有効な場合は、保存前に許可される操作を一覧表示します。
4. **ポリシーを作成**を選択します。

ポリシードキュメントは、AWS IAM のポリシー言語に準じて記述します。

```json
{
  "Version": "1",
  "Statement": [
    { "Sid": "Dashboards", "Effect": "Allow", "Action": "dashboards.*" },
    { "Effect": "Allow", "Action": ["streams.read", "streams.query"] }
  ]
}
```

- `Version` は `"1"` です。ポリシーには少なくとも 1 つの権限を指定します。
- `Effect` は常に `"Allow"` です。ポリシーで指定できるのは許可のみで、拒否は指定できません。
- `Action` には、権限を 1 つ指定するか、権限のリストを指定します。`*` は任意の文字列に一致するため、 `dashboards.*` はダッシュボードのすべての権限、`*` は組織のすべての権限に一致します。どの権限にも一致しないアクションは指定できません。
- `Sid` はステートメントに付ける任意の名前です。
- `Resource`、`Condition`、`Principal`、`NotAction` は指定できません。ポリシーは組織全体に適用されます。個別のリソースに対して、または条件付きでロールを付与するには、 [アクセス権の付与](#アクセス権の付与)を使用します。

ポリシーは、保存時点でドキュメントが許可する権限を保持します。パターンは、後から権限カタログに追加された権限にも適用されます。一致する権限は MoleSignal の起動時にポリシーに追加されます。**ビジュアル**でチェックを入れると、パターン、`Sid`、または複数のステートメントを含むドキュメントは、各権限を列挙する 1 つのステートメントに書き換わります。書き換えの前に通知が表示されます。

ポリシーを変更すると、関連付け先のすべてのロールと、適用先のすべてのトークンに変更が即時に反映されます。 **削除**でカスタムポリシーを削除できるのは、関連付け先のロールがなく、適用先に有効なトークンがない場合に限ります。ポリシーが適用されていたトークンは、取り消し済みまたは期限切れでも、それまでの権限をリストとして保持します。ポリシーの閲覧には `iam.policies.read`、変更には `iam.policies.manage`、削除には `iam.policies.delete` が必要です。

## アクセス権の付与

アクセス権の付与は、組織内のプリンシパルに、指定した範囲のリソースに対するロールを割り当てるロールバインディングです。広範なロールの権限を拡大するのではなく、特定のユーザー、チーム、またはリソースにアクセスを限定する場合に使用します。

1. **アクセス権の付与**を開き、**アクセス権を付与**を選択します。
2. **プリンシパル**：**ユーザー**または**チーム**を選び、対象を選択します。
3. **組織**：現在のワークスペースが参照用に表示されます。
4. **リソースの範囲**：**組織全体**を選ぶか、リソースの種類（**ダッシュボード**または**ストリーム**）を選び、個別のリソースまたは**この種類のすべてのリソース**を選択します。
5. **ロールと権限**：付与するロールを選択します。
6. **制約**：必要に応じて、リクエストが完全一致する必要がある**環境**（`prod` など）と、 **有効期限**の日時を指定します。
7. **アクセス許可を作成**を選択します。

**削除**を選択すると、付与したアクセス権は即時に無効になります。付与内容の閲覧には `iam.grants.read`、付与内容の作成または削除には `iam.grants.manage` が必要です。

## 組織間でリソースを共有する

組織間の共有では、この組織で選択したリソースへのアクセス権を別の組織に付与します。共有は明示的に指定した組織とリソースにのみ適用され、他の組織への継承や再共有はできません。

1. **アクセス権の付与**で、**組織間で共有**を選択します。
2. **対象組織**を選択します。
3. リソースの種類（**ダッシュボード**または**ストリーム**）と、共有するリソースを選択します。
4. 権限を選択します。ダッシュボードの場合は `dashboards.read` と `dashboards.edit`、ストリームの場合は `streams.read` と `streams.query` です。
5. 必要に応じて**有効期限**を設定し、**共有を作成**を選択します。

共有の初期ステータスは**承諾待ち**です。対象組織の管理者が、その組織の **アクセス権の付与**で**承認**を選択すると、共有が**有効**になります。どちらの組織も**取り消し** を選択できます。共有の作成、承認、取り消しには `iam.cross_org.manage` が必要です。

## 権限リファレンス

権限カタログのすべての権限について、許可される操作と、その権限を持つ組み込みロールを示します。カスタムロールとポリシーには、任意の組織権限を組み合わせられます。モジュールのタブには、ロールで開けるページが表示されます。モジュールを開くとそのうち最初のページが表示されるため、いずれか1ページへのアクセス権限があればモジュールを開けます。

| `sys.administrators.read` | プラットフォームのロール、ポリシー、付与状況を閲覧し、アカウントを検索できます。 | `platform_admin`, `platform_viewer` |

## ロール、ポリシー、アクセス付与の API

| 操作 | エンドポイント | 権限 |
|---|---|---|
| 権限カタログを一覧表示 | `GET /api/v1/iam/permissions` | `iam.roles.read` または `iam.policies.read` |
| ロールを一覧表示 | `GET /api/v1/roles` | `iam.roles.read` |
| カスタムロールを作成 | `POST /api/v1/roles` | `iam.roles.manage` |
| カスタムロールを更新 | `PATCH /api/v1/roles/{id}` | `iam.roles.manage` |
| 未使用のカスタムロールを削除 | `DELETE /api/v1/roles/{id}` | `iam.roles.manage` |
| 権限ポリシーを一覧表示または個別に取得 | `GET /api/v1/iam/policies`, `GET /api/v1/iam/policies/{id}` | `iam.roles.read` |
| カスタムポリシーを作成 | `POST /api/v1/iam/policies` | `iam.roles.manage` |
| カスタムポリシーを更新 | `PATCH /api/v1/iam/policies/{id}` | `iam.roles.manage` |
| 未使用のカスタムポリシーを削除 | `DELETE /api/v1/iam/policies/{id}` | `iam.roles.manage` |
| アクセス付与を一覧表示または作成 | `GET /api/v1/iam/role-bindings`, `POST /api/v1/iam/role-bindings` | `iam.policies.read`, `iam.policies.manage` |
| アクセス付与を削除 | `DELETE /api/v1/iam/role-bindings/{id}` | `iam.policies.manage` |
| 組織間共有を一覧表示または作成 | `GET /api/v1/iam/cross-org-grants`, `POST /api/v1/iam/cross-org-grants` | `iam.policies.read`, `iam.policies.manage` |
| 共有を承認または取り消し | `POST /api/v1/iam/cross-org-grants/{id}/accept`, `POST /api/v1/iam/cross-org-grants/{id}/revoke` | `iam.policies.manage` |

ロールのリクエストボディには、ロール固有の `permissions` と、関連付けるポリシーの `policyIds` を指定します。レスポンスには、ロールが付与するすべての権限を示す `effectivePermissions` が加わります。ポリシーのリクエストボディには、`key`（作成時のみ）、 `name`、`description`、`document` を指定します。レスポンスには、`builtin`、解決済みの `permissions`、およびポリシーを関連付けているロールと、そのポリシーが適用される有効なトークンを示す `usage` が加わります。ドキュメントが無効な場合、API は `400` と、問題の箇所を示す次のようなメッセージを返します。 ``Statement[0].Action[1]: no permission is called `alerts.rules.reed` ``。使用中のポリシーを削除しようとすると、 `409` が返ります。
