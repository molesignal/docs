多要素認証では、パスワードに加えてもう一段階の確認が必要になるため、パスワードを知っているだけではサインインできません。以下の第2認証要素のいずれかを設定すると多要素認証がオンになり、両方を併用できます。アカウントごとに **アカウント設定 → セキュリティとサインイン** で設定します。ワークスペースでは [メンバーに多要素認証を必須にする](/ja/identity/sso#サインイン要件)ことができます。まだオンにしていないメンバーは、サインイン時に設定します。

| 第2認証要素 | 確認方法 |
|---|---|
| パスキー | 指紋、顔、またはデバイスのパスコードで確認します。コードの入力は不要で、フィッシングサイトにパスキーをだまし取られることもありません。iCloudキーチェーン、Google パスワード マネージャー、1Password、またはセキュリティキーに保存できます。パスワードを使わず、パスキーだけでもサインインできます。 |
| 認証アプリ | Google Authenticator、Microsoft Authenticator、1Password などのアプリに表示される6桁のコードを入力します。 |

## 先に本人確認を行う

認証アプリをオンにする場合も、パスキーを追加する場合も、まずアカウントの所有者であることを確認します。サインイン済みであるだけでは不十分です。セッションを取得した第三者が独自の第2認証要素を追加し、所有者がアカウントにアクセスできなくなるおそれがあるためです。

| アカウントの状態 | 確認方法 |
|---|---|
| 第2認証要素を設定済み | 既存のパスキー、認証アプリ、またはリカバリーコードを使います。 |
| 第2認証要素を未設定 | アカウントのパスワードを入力します。 |
| パスワードなし（シングルサインオンで作成） | サインインから10分以内は入力不要です。10分を過ぎた場合は、サインインし直してください。 |

## パスキーを追加する

<Steps>
  <Step title="設定を開く">
    **アカウント設定 → セキュリティとサインイン** の **パスキー** 行で **パスキーを追加** をクリックし、上記の方法で本人確認を行います。
  </Step>
  <Step title="パスキーを作成する">
    必要に応じて「MacBook」などの名前を付け、**作成** をクリックします。ブラウザーまたはシステムの画面に表示される指示に従ってください。
  </Step>
  <Step title="リカバリーコードを保存する">
    アカウントで初めて第2認証要素を設定すると、多要素認証がオンになり、10個のリカバリーコードが表示されます。表示はこの1回限りです。**コピー** または **ダウンロード** で保存し、 **保存しました** をクリックします。
  </Step>
</Steps>

インスタンスで[メールを送信できる](/ja/configuration#アラートとメール)場合は、アカウントのメールアドレスに通知が届きます。最初のパスキーを追加すると、ほかのブラウザーやコンピューターでのサインインセッションがすべて終了しますが、現在のブラウザーではサインイン状態が維持されます。2つ目以降の追加は、ほかのセッションに影響しません。

パスキーの保存先はブラウザーとシステムによって決まります。表示された選択肢から保存先を選びます。

| 保存先 | 補足 |
|---|---|
| iCloudキーチェーン | Apple デバイスの Safari で使えます。同じ Apple Account を使うすべてのデバイスで利用できます。 |
| Google パスワード マネージャー | Chrome と Android で使えます。同じ Google アカウントを使うすべてのデバイスで利用できます。 |
| パスワードマネージャー | 1Password、Bitwarden などです。 |
| セキュリティキー | YubiKey などの FIDO2 キーです。 |

コンピューターでパスキーを利用できない場合は、ブラウザーに QR コードを表示し、スマートフォンのパスキーで本人確認することもできます。

名前を付けていないパスキーは、一覧に保存先が表示されます。ブラウザーから保存先の情報を取得できない場合は、「パスキー」とだけ表示されます。

### インスタンスの要件

パスキーはインスタンスのドメイン名にひも付くため、以下の要件を満たす必要があります。満たさない場合、** パスキーを追加** はグレー表示になり、理由が表示されます。サインインページにもパスキーの選択肢が表示されません。

| 要件 | 補足 |
|---|---|
| `[http].external_url` を設定している | [構成](/ja/configuration)を参照してください。 |
| ドメイン名を指定している | ブラウザーは IP アドレスを受け付けません。 |
| HTTPS を使っている | `localhost` は例外です。 |
| そのアドレスでコンソールを開いている | 別のホスト名で開くと、ブラウザーはパスキーの使用を拒否します。 |

`external_url` のホスト名を変更すると、既存のパスキーは使えなくなります。パスワードまたはリカバリーコードでサインインし、パスキーを追加し直してください。

## 認証アプリをオンにする

<Steps>
  <Step title="設定を開く">
    **アカウント設定 → セキュリティとサインイン** の **認証アプリ** 行で **オンにする** をクリックし、上記の方法で本人確認を行います。
  </Step>
  <Step title="認証アプリに追加する">
    認証アプリで QR コードを読み取るか、その下に表示されるキーを入力します。アプリには MoleSignal と表示されます。`[http].external_url` を設定している場合は、名前にホスト名も表示されるため、複数のインスタンスを区別できます。
  </Step>
  <Step title="最初のコードを入力する">
    アプリに表示される6桁のコードを入力し、**オンにする** をクリックします。コードが一致した場合にのみオンになります。
  </Step>
  <Step title="リカバリーコードを保存する">
    アカウントで初めて第2認証要素を設定すると、10個のリカバリーコードが表示されます。表示はこの1回限りです。 **コピー** または **ダウンロード** で保存し、**保存しました** をクリックします。
  </Step>
</Steps>

アカウントに第2認証要素がなかった場合、認証アプリをオンにすると、ほかのブラウザーやコンピューターでのサインインセッションがすべて終了します。現在のブラウザーではサインイン状態が維持され、アカウントのメールアドレスに通知が届きます。

## サインインする

### パスワードを使わずにパスキーでサインインする

サインインページで **パスキーで続行** をクリックします。または、**メールアドレスでサインイン** をクリックしてメールアドレス欄をクリックし、ブラウザーに表示される候補からパスキーを選びます。パスキーでは指紋、顔、またはデバイスのパスコードで確認するため、パスキーだけで多要素認証が成立し、2段階目の確認は不要です。

### パスワードの入力ミスが上限に達した場合

パスワードの入力ミスが上限に達すると、サインインページに待機時間が表示されます。パスキーを使うか、パスワードをリセットすれば、待たずにサインインできます。パスキーは試行回数の集計や制限の対象外なので、第三者がパスワードを推測している間もアカウントの所有者はサインインできます。パスワードのリセットが完了すると、アカウントのロックはすぐに解除されます。具体的な上限や待機時間は [サインインの制限](/ja/settings/platform#サインイン制限)を参照してください。

### パスワード入力後の2段階目の確認

パスワードを入力すると、サインインページに **本人確認** が表示され、アカウントに設定済みの第2認証要素を使って確認できます。

| 方法 | 手順 |
|---|---|
| パスキー | **パスキーで本人確認** をクリックし、ブラウザーまたはシステムに表示される指示に従って確認します。 |
| 認証アプリ | 6桁のコードを入力します。6桁すべてを入力すると、コードが自動的に送信されます。スマートフォンとサーバーの時刻の差が30秒以内であれば、コードを使用できます。各コードは1回限り有効です。 |
| リカバリーコード | 未使用のリカバリーコードを入力します。各コードは1回限り有効です。使うと、サインインページに残りのコード数が表示され、アカウントのメールアドレスに通知が届きます。 |

| 条件 | 結果 |
|---|---|
| 1回のサインインで5回間違えた場合 | そのサインイン手続きが終了します。パスワードを入力し直してください。 |
| 1時間以内にコードを10回間違えた場合 | 認証アプリのコードとリカバリーコードが1時間使えなくなり、アカウントのメールアドレスに通知が届きます。パスキーには影響せず、引き続きパスワードなしでサインインできます。 |
| パスワード入力から5分以内に2段階目の確認を完了しなかった場合 | そのサインイン手続きが期限切れになります。パスワードを入力し直してください。 |

## 2段階目の確認が必要なサインイン方法

| サインイン方法 | 2段階目の確認 |
|---|---|
| アカウントのパスワード | 必要です。 |
| パスワードを使わないパスキー | 不要です。パスキーだけで多要素認証が成立します。 |
| LDAP | 必要です。LDAP はディレクトリ内のパスワードのみを確認します。 |
| OIDC、OAuth 2.0、SAML によるシングルサインオン | 不要です。多要素認証は ID プロバイダーが行います。 |
| 既存のアカウントをリンクする初回のシングルサインオン | 必要です。リンクを確認した後、2段階目の確認を完了してリンクを確定します。[既存のアカウントをリンクする](/ja/identity/sso#既存のアカウントを連携する)を参照してください。 |
| データベースクライアント（Flight SQL）からのアカウントへのログイン | アカウントのパスワードでは接続できません。`mspat-` で始まる [API トークン](/ja/identity/tokens)を使用してください。[データベースクライアント](/ja/query/database-clients#認証)を参照してください。 |
| API トークン | 影響はありません。 |

## リカバリーコードを管理する

認証アプリとパスキーを利用できなくなった場合は、リカバリーコード1つにつき1回サインインできます。 **セキュリティとサインイン** の **リカバリーコード** 行に残りのコード数が表示されます。**新しいコードを作成** をクリックして確認すると、新しいリカバリーコードが10個発行され、以前のコードは使えなくなります。

## 第2認証要素を変更する

名前の変更を除き、各操作ではその場でパスキー、認証コード、またはリカバリーコードによる確認が必要です。

| 操作 | 手順 |
|---|---|
| パスキーの名前を変更する | 該当する行の**名前を変更**をクリックします。 |
| パスキーを削除する | **削除**をクリックします。iCloud キーチェーンやパスワードマネージャーに保存したコピーは、保存先でも削除してください。対応ブラウザーでは、次回そのパスキーでサインインを試みたときに、システムにコピーの削除を要求します。 |
| 認証アプリを交換する | **認証アプリを交換**をクリックして確認し、新しい QR コードを読み取って、認証アプリに表示されたコードを入力します。リカバリーコードは変わりません。 |
| 認証アプリをオフにする | **オフにする**をクリックします。 |

アカウントの最後の第2認証要素を削除すると、多要素認証がオフになります。リカバリーコードは使えなくなり、アカウントのメールアドレスに通知が届きます。アカウントが所属するワークスペースで [多要素認証が必須](/ja/identity/sso#サインイン要件)の場合、最後の第2認証要素は削除できません。 **オフにする**と**削除**はグレー表示になり、多要素認証を必須にしているワークスペースが表示されます。

## 管理者によるリセット

メンバーがすべての第2認証要素を失い、リカバリーコードも使い切った場合、管理者は **ID とアクセス → ユーザー**で該当メンバーの操作メニューを開き、**多要素認証をリセット**をクリックします。この操作には `org.members.mfa_reset` 権限が必要です。メンバーの認証アプリ、パスキー、リカバリーコードは使えなくなり、すべてのデバイスからサインアウトします。アカウントのメールアドレスに通知が届きます。その後、メンバーはパスワードでサインインし、多要素認証を再設定します。ワークスペースで多要素認証が必須の場合は、サインインの途中で再設定します。

| メンバー | リセットできる管理者 |
|---|---|
| この組織にのみ所属 | この組織の管理者です。 |
| 他の組織にも所属 | プラットフォーム管理者のみです。リセットは、そのメンバーが所属するすべての組織に影響します。 |
| ルートユーザー | サーバー上での[オフラインリセット](#オフラインリセット)でのみリセットできます。 |

**ユーザー**一覧の **MFA** 列には、メンバーごとに多要素認証がオンかどうかが表示されます。

## オフラインリセット

ルートユーザーがすべての第2認証要素を失った場合や、どの管理者もサインインできない場合は、サーバー上で次のコマンドを実行します。

```bash
molesignal --config /etc/molesignal/config.toml reset-mfa --email root@example.com
```

このコマンドは、対象アカウントの多要素認証をオフにし、すべてのセッションを終了してから、サービスを起動せずに終了します。

## セッションが終了する操作

次の操作を行うと、別のブラウザーや別のコンピューターでのアカウントのセッションは、それぞれの環境から次のリクエストが送信された時点で終了します。

- 最初の第2認証要素を追加して、多要素認証をオンにする
- 認証アプリを交換またはオフにする、あるいはパスキーを削除する
- 管理者が多要素認証をリセットする
- **アクティブセッション**で**他のすべてのデバイスをサインアウト**を選択する
- メールで届いたリンクからパスワードをリセットする（アカウントのすべてのセッションが終了します）

ワークスペースで[サインイン要件](/ja/identity/sso#サインイン要件)を有効にすると、その要件を満たさないセッションは 15 分以内に終了します。
