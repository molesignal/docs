**ID とアクセス → ユーザー**、**招待**、または **承認**を開きます。メンバーの一覧表示には `org.members.read` が必要です。これらのページで変更を行うには、すべて `org.members.update` が必要です。この権限がなくても、メンバー同士の名前とプロフィール画像は表示されます。インシデント、スケジュール、エスカレーションポリシーでは、名前でメンバーを表示・選択します。メールアドレス、ロール、チーム、ログイン方法、アクティビティの表示には `org.members.read` が必要です。

## ユーザー

**ユーザー**には、現在のワークスペースのメンバーが表示されます。ページ上部には、全ユーザー、有効なユーザー、承認待ちのユーザーの件数が表示されます。名前、メールアドレス、チームで検索し、ロールやステータスで絞り込めます。

| 列 | 表示内容 |
|---|---|
| **ロール** | このワークスペースでのメンバーのロールです。 |
| **チーム** | メンバーが所属する[チーム](/ja/identity/teams#チーム)です。 |
| **ログイン方法** | **パスワード**、**OIDC**、または **SAML** です。 |
| **最終アクティブ日時** | 最後にログインした日時、または **ログイン履歴なし**です。 |
| **ステータス** | **有効**、**無効**、**承認待ち**（承認を待っている状態）、または **却下済み**です。 |

次の操作を行うには、行の右端にあるメニューを開きます。

| 操作 | 結果 |
|---|---|
| **詳細を表示** | メンバーの ID 情報、所属先、アクセス状況を表示します。 |
| **ロールを変更** | このワークスペースでのメンバーのロールを、組み込みロールまたは[カスタムロール](/ja/identity/roles#ロール)に設定します。 |
| **ユーザーを無効化** | アカウントはどのワークスペースにもログインできなくなります。所属情報と設定は保持されます。**ユーザーを有効化**すると、再びログインできるようになります。 |
| **メンバーを削除** | メンバーはこのワークスペースにすぐにアクセスできなくなります。アカウント自体は削除されません。 |
| **承認** | 承認待ちのユーザーに表示されます。[承認](#承認)を参照してください。 |

次の変更はできません。

- 自分のロールを変更したり、自分のアカウントを無効にしたり、現在のワークスペースから自分を削除したりすることはできません。
- 初回起動時に `[auth].root_email` から作成されるアカウントがルートユーザーです。このアカウントは、組織の管理者でも変更できません。
- 最後のプラットフォーム管理者は無効化も削除もできません。

別のワークスペースに切り替えると、切り替え先の組織用に新しいセッションが発行されます。組織の ID とスラッグは、組織名が変わっても変わりません。

## 承認

ワークスペースの[登録ポリシー](/ja/settings/organization#登録とアクセス)でセルフサービス登録を許可し、管理者の承認を必須にしている場合、新しいアカウントは **承認**に承認待ちとして表示されます。上部バーのベルアイコン（**通知**）にも表示されます。

- **承認**すると、アカウントが有効になります。
- **却下**すると、アカウントは却下済みになり、ログインできなくなります。却下はこのページから取り消せません。

SMTP を設定している場合、MoleSignal は、新規登録があったことをワークスペースの管理者に、承認または却下の結果を登録者に、ワークスペースのデフォルト言語でメール通知します。メールの送信に失敗しても、登録や承認・却下の処理は続行されます。

## 招待

**招待**では、メールアドレスと付与するロールを記録します。保留中の招待の一覧には、ロール、ステータス、送信日時、招待者が表示されます。

1. **ユーザーを招待**を選択します。
2. **メールアドレス**を入力します。ワークスペースに[メールドメイン](/ja/identity/sso#メールドメイン)が設定されている場合、いずれかのドメインに属するメールアドレスを入力してください。
3. **ロール**を選択するか、セルフサービス登録時に付与される **組織のデフォルト**のままにします。
4. **招待を送信**を選択します。

**再送信**すると、保留中の招待が再送信済みとして記録されます。**取り消し**を選択すると招待を取り消せます。承諾済みの招待は再送信できません。

<Note>
  MoleSignal は招待メールを送信しません。また、招待しても、アカウントの作成やワークスペースへの追加は行われません。招待されたユーザーは、[サインアップ](/ja/console#サインイン)または [シングルサインオン](/ja/identity/sso)で参加し、管理者が **ユーザー**でロールを設定します。
</Note>

## メンバー API

| 操作 | エンドポイント | 権限 |
|---|---|---|
| ユーザーの一覧を取得 | `GET /api/v1/users` | `org.members.read`。この権限がない場合、ログイン済みのメンバーには名前とプロフィール画像のみを返し、API トークンによるリクエストは拒否します。 |
| ユーザーを変更 | `PATCH /api/v1/users/{id}` | `org.members.update` |
| 承認または却下 | `POST /api/v1/users/{id}/approve`, `POST /api/v1/users/{id}/reject` | `org.members.update` |
| メンバーの追加または所属情報の変更 | `POST /api/v1/orgs/{id}/members` | `org.members.update` |
| メンバーを削除 | `DELETE /api/v1/orgs/{id}/members/{user_id}` | `org.members.update` |
| 招待の一覧を取得または招待を作成 | `GET /api/v1/invitations`, `POST /api/v1/invitations` | `org.members.read`, `org.members.update` |
