**コネクター**は外部プラットフォームとのマネージド統合です。コネクターは次の 2 方向で動作します:

- **ソース**は別のサービスからデータを取り込み、ストリームに書き込みます。MoleSignal は CloudWatch Logs、Kafka トピック、S3 オブジェクトをスケジュールに従ってプルします。Amazon Data Firehose、Google Cloud Pub/Sub、Cloudflare Logpush、Heroku は MoleSignal にプッシュします。Firehose は CloudWatch メトリクスも転送します。
- **送信先**は[スケジュールされたパイプライン](/ja/pipelines#書き込み先とコネクターへの外部配信)の出力を受け取ります。対象は Amazon S3 と S3 互換ストレージ、Apache Kafka、任意の HTTP エンドポイントです。

| 種類 | コネクター | 方向 | 認証 |
|---|---|---|---|
| `aws_cloudwatch_logs` | AWS CloudWatch Logs | ソース（30 秒ごとにプル） | [AWS 認証情報](#aws-認証) |
| `kafka_source` | Kafka トピック | ソース（30 秒ごとにプル） | なし、SASL、またはクライアント証明書 |
| `s3_source` | S3 オブジェクト | ソース（30 秒ごとにプル） | AWS 認証情報 |
| `gcp_pubsub_pull` | Google Cloud Pub/Sub サブスクリプション | ソース（30 秒ごとにプル） | サービスアカウントキー |
| `aws_cloudwatch_metrics`, `azure_monitor_metrics`, `gcp_monitoring_metrics`, `aliyun_cms_metrics`, `tencent_monitor_metrics`, `huawei_ces_metrics` | [クラウドメトリクス](#クラウドメトリクス) | ソース（各期間ごとにプル） | クラウドの認証情報 |
| `aws_kinesis_firehose` | Amazon Data Firehose | ソース（プッシュ） | [プッシュトークン](#プッシュソース) |
| `gcp_pubsub_push` | Google Cloud Pub/Sub プッシュ | ソース（プッシュ） | プッシュトークン（任意でサブスクリプションの OIDC トークンも併用） |
| `cloud_events` | クラウドイベントバス | ソース（プッシュ） | プッシュトークン |
| `cloudflare_logpush` | Cloudflare Logpush | ソース（プッシュ） | プッシュトークン |
| `heroku_drain` | Heroku ログドレイン | ソース（プッシュ） | プッシュトークン |
| `s3` | Amazon S3 | 送信先 | AWS 認証情報 |
| `kafka` | Apache Kafka | 送信先 | なし、SASL、またはクライアント証明書 |
| `http` | HTTP / Webhook | 送信先 | なし、ベアラートークン、Basic 認証、カスタムヘッダー、または HMAC 署名 |

## コネクターを作成

<Steps>
  <Step title="コネクターを開く">
    **パイプライン → コネクター**に移動します。ページには**ソース**と**送信先**が一覧表示されます。
  </Step>
  <Step title="種類を選択">
    **新規コネクター**をクリックし、接続先を選択します。
  </Step>
  <Step title="設定を入力">
    組織内で一意の**名前**を入力し、コネクターの読み取り元または配信先を入力して、**認証**を選択します。
  </Step>
  <Step title="テストして作成">
    設定を保存する前に試すには、**接続をテスト**をクリックし、その後**コネクターを作成**をクリックします。プッシュソースには接続する対象がないため、テストは提供されません。
  </Step>
</Steps>

API 経由では、コネクターは `name`、`kind`、およびキーが種類によって異なる `configJson` です。`configJson` の `auth` は認証方法を指定し、各方法は固有のキーを使用します。動作できない設定は保存時に `400` を返します。たとえば、必須キーの欠落、認証情報ペアの片方のみ、選択した `auth` が使用しないキーなどです。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "archive",
        "kind": "s3",
        "configJson": {
          "bucket": "acme-logs",
          "region": "eu-west-1",
          "prefix": "pipelines/checkout/",
          "auth": "assume_role",
          "roleArn": "arn:aws:iam::123456789012:role/molesignal-delivery"
        }
      }'
```

## シークレット

`configJson` の次のキーはシークレットを保持します:

| 種類 | シークレットキー |
|---|---|
| `s3`, `aws_cloudwatch_logs` | `accessKey`, `secretKey`, `sessionToken` |
| `aws_kinesis_firehose`, `gcp_pubsub_push`, `cloud_events`, `cloudflare_logpush`, `heroku_drain` | `pushToken` |
| `aws_cloudwatch_metrics` | `accessKey`, `secretKey`, `sessionToken` |
| `azure_monitor_metrics` | `clientSecret` |
| `gcp_monitoring_metrics`, `gcp_pubsub_pull` | `serviceAccountKey` |
| `aliyun_cms_metrics`, `tencent_monitor_metrics`, `huawei_ces_metrics` | `accessKey`, `secretKey` |
| `kafka` | `saslPassword`, `tlsClientKey` |
| `http` | `url`, `bearerToken`, `basicPassword`, `headerValue`, `hmacSecret` |

シークレットが API を通じて外部に出ることはありません。レスポンスは、その場所に `***` を表示し、値を保持しているシークレットの名前を `secretKeys` に示します:

```json
{
  "kind": "kafka",
  "configJson": {
    "brokers": "b-1.example.com:9096",
    "topic": "logs",
    "tls": true,
    "auth": "sasl_scram_sha_512",
    "saslUsername": "molesignal",
    "saslPassword": "***"
  },
  "secretKeys": ["saslPassword"]
}
```

- `***` を送り返す更新では保存済みの値が維持されるため、認証情報を再入力せずにコネクターの名前変更、無効化、接続先の変更を行えます。UI では、保存済みのシークレットを空のままにすると値が維持されます。
- 更新に含めなかったシークレットは削除されます。
- `kind` を変更する更新では、保存済みのシークレットは一切維持されません。

MoleSignal は、他の設定とは別に、`MS_CIPHER_KEY` のルートキー（AES-256-GCM）でシークレットを暗号化し、シークレットを平文で保存しません。プッシュソースは、そのトークンの SHA-256 によって特定されます。ルートキーがローテーションされると、`molesignal rewrap-kek` がコネクターのシークレットを他のシークレットとともに再暗号化します。[本番チェックリスト](/ja/deployment/production-checklist)を参照してください。

## ソース

### プッシュソース

5 つのプッシュソースは 1 つのモデルを共有します。**`pushToken`** と **`targetStream`** を指定してコネクタを作成し、プラットフォームを対応するエンドポイントに向けます。これらのエンドポイントは JWT を使用しません。リクエストは、プラットフォームが許可する任意の方法で指定されたプッシュトークンで認証されます:

| 方法 | 使用元 |
|---|---|
| `X-Connector-Token` ヘッダー | Cloudflare など、ヘッダーを設定できるプラットフォーム |
| `X-Amz-Firehose-Access-Key` ヘッダー | Amazon Data Firehose（自動的に送信） |
| `X-EventBridge-Signature-Token` ヘッダー | Alibaba Cloud EventBridge |
| `?token=` クエリパラメータ | Heroku や Pub/Sub など、ヘッダーを設定できないプラットフォーム |
| `Authorization: Basic` のパスワード | 認証情報をアドレスに含めるプラットフォーム |

UI はコネクタの作成時にトークンを生成し、プラットフォームに渡すエンドポイントとともに一度だけ表示します。トークンは後から読み取ることはできません。**新しいトークンを生成**は、コネクタの保存時にトークンを置き換えます。API 経由では、16 文字以上の `pushToken` を指定します。1 つのトークンで開けるコネクタは 1 種類につき 1 つです。すでに使用中のトークンには `409` を返します。トークンがない、不明なトークンである、またはコネクタが無効であるリクエストには `401` を返します。トークンのないコネクタは何も受け付けません。ノードは参照したコネクタを 30 秒間保持するため、コネクタの無効化やトークンの置き換えはその時間内に反映されます。

`Content-Encoding: gzip` で送信された本文は自動的に展開されます。Firehose の本文は最大 64 MiB、その他は最大 16 MiB で、展開後も同様にカウントされます。イベントは他のすべてと同様の取り込み経路を通ります。スキーマオンライト、[パイプライン](/ja/pipelines)、[マスキング](/ja/security)がいずれも適用されます。

<Tabs>
  <Tab title="Amazon Data Firehose">
    `kind: "aws_kinesis_firehose"` でコネクタを作成し、Firehose ストリームの送信先として **HTTP エンドポイント**を選択します:

    - **HTTP エンドポイント URL**: `https://molesignal.example.com/api/v1/_kinesis_firehose`
    - **アクセスキー**: プッシュトークン。Firehose は `X-Amz-Firehose-Access-Key` として送信します。

    Firehose は、公的に信頼された証明書を使用するポート 443 の HTTPS にのみ配信します。そのため、プライベートネットワーク上のデプロイにはパブリックエントリポイントが必要です。[パブリックアクセス](/ja/public-access)を参照してください。ストリームのバッファーは 1～4 MiB に保ちます。

    MoleSignal は各レコードを、その内容に応じて個別に読み取ります:

    | レコード | 変換後 |
    |---|---|
    | CloudWatch Logs サブスクリプションメッセージ（サブスクリプションフィルターが送信するときに gzip 圧縮されたもの） | `logEvents` のエントリごとに 1 つのログイベント。時刻はエントリ自身のもの。`message`、`log_group`、`log_stream`、`account_id`、`region`、`event_id`、および `source: "cloudwatch"` を含みます。サブスクリプションの作成時に送信されるヘルスチェックはスキップされます。 |
    | JSON、OpenTelemetry 1.0、または OpenTelemetry 0.7 出力形式の CloudWatch メトリクスストリームレコード | メトリクスストリーム内のメトリクスサンプル（下記参照）。 |
    | その他のテキスト | 1 行につき 1 つのログイベント。JSON オブジェクトはフィールドを提供し、プレーンテキストは `message` に入ります。 |

    メトリクスストリームは、メトリクスごとに 1 分あたり 1 つの集計を送信します。各統計は、yet-another-cloudwatch-exporter が付けるのと同じ方法で `aws_<namespace>_<metric>_<statistic>` という名前のゲージサンプルになります。例: `aws_ec2_cpuutilization_average`、`aws_ec2_cpuutilization_maximum`、`aws_applicationelb_request_count_sum`。名前空間は `AWS/` プレフィックスを除き、メトリクス名は小文字の後に大文字が続く箇所で単語に分割されます。統計は `average`（サンプル数で割った合計）、`sum`、`sample_count`、`minimum`、`maximum`、およびストリームが追加する任意のパーセンタイル（`p99` や `p99_9` など）です。ラベルは `account_id`、`region`、およびディメンションごとの `dimension_<Name>`（`dimension_InstanceId` など）です。`metric_unit` は単位を保持します。

    ```promql
    max by (dimension_InstanceId) (aws_ec2_cpuutilization_average)
    ```

    ストリームのパラメータとして設定された `X-Amz-Firehose-Common-Attributes` は、そのキーをすべてのイベントとサンプルに追加します。レコードにすでに存在するフィールドが優先されます。`X-Amz-Firehose-Source-Arn` は、リージョンを持たない CloudWatch Logs イベントに `region` を提供します。

    応答は Firehose の配信仕様に従います。`application/json` で、リクエストの `requestId`、`timestamp`、失敗時の `errorMessage` を含みます。読み取れないレコードは除外され、リクエストの残りは引き続き `200` で書き込まれます。一時的に失敗した書き込みは `429` または `5xx` を返し、Firehose はこれを再試行します。64 MiB を超える本文は `413` を返し、Firehose は再試行もバックアップもしません。書き込み後 30 分以内に同じ `X-Amz-Firehose-Request-Id` で再試行された配信には、再度書き込まずに `200` を返します。
  </Tab>
  <Tab title="Google Cloud Pub/Sub">
    `kind: "gcp_pubsub_push"` でコネクタを作成します。Log Router シンクでログを Pub/Sub トピックにルーティングし、そのトピックにプッシュサブスクリプションを作成します。Pub/Sub はカスタムヘッダーを設定できないため、トークンは URL で送信します:

    ```bash
    gcloud pubsub subscriptions create molesignal-push --topic=molesignal-logs --push-endpoint="https://molesignal.example.com/api/v1/_gcp_pubsub?token=<pushToken>"
    ```

    サブスクリプションの OIDC トークンも確認するには、コネクタの `oidcServiceAccount` にサービスアカウントのメールアドレスを設定し、`--push-auth-service-account=<email>` を指定してサブスクリプションを作成します。MoleSignal は Google のキーに対してトークンを検証し、そのサービスアカウントのみを受け入れます。`oidcAudience` を設定するとオーディエンスも確認でき、同じ値を `--push-auth-token-audience` に渡します。

    各メッセージは 1 つのリクエストです。ラップされた本文とラップされていないペイロードの両方を受け付けます。Cloud Logging の `LogEntry` は 1 つのログイベントになります:

    | `LogEntry` | イベント |
    |---|---|
    | `jsonPayload` | そのフィールド |
    | `textPayload` | `message` |
    | `protoPayload`（監査ログ） | そこから `method_name`、`service_name`、`principal_email` を取り出した `proto_payload` |
    | `severity` | 小文字化された `level` |
    | `logName`、`resource.type`、`insertId` | `log_name`、`resource_type`、`insert_id` |
    | `resource.labels`、`labels` | それぞれの名前のフィールド |
    | `trace`、`spanId` | `projects/<id>/traces/` プレフィックスを除いた `trace_id`、`span_id` |
    | `httpRequest` | `http_request` |
    | `timestamp` | イベントの時刻。欠落している場合は `receiveTimestamp` またはパブリッシュ時刻 |

    その他のメッセージデータは 1 つのイベントになります。JSON オブジェクトのフィールド、または `message` としてのテキストです。エンドポイントは `204 No Content` を返し、Pub/Sub はこれを確認応答として扱います。読み取れないメッセージは確認応答されて除外されます。一時的に失敗した書き込みは確認応答されないため、Pub/Sub が再配信します。書き込み後 30 分以内に再配信されたメッセージは、再度書き込まずに確認応答されます。
  </Tab>
  <Tab title="クラウドイベントバス">
    `kind: "cloud_events"` でコネクタを作成し、イベントバスを `https://molesignal.example.com/api/v1/_cloud_events` に向けます:

    | 送信元 | セットアップ |
    |---|---|
    | Amazon EventBridge | **API キー**接続を使用する API 送信先。ヘッダー名は `X-Connector-Token`、値はプッシュトークンです。 |
    | Azure Event Grid | エンドポイントが `?token=<pushToken>` で終わる Webhook サブスクリプション。検証ハンドシェイクと CloudEvents スキーマの `OPTIONS` ハンドシェイクには自動的に応答します。 |
    | Alibaba Cloud EventBridge | プッシュトークンをトークンとして持つ HTTPS ターゲット。`X-EventBridge-Signature-Token` として送信されます。 |
    | Huawei Cloud EventGrid | `X-Connector-Token` ヘッダーを付ける Webhook ターゲット。 |
    | その他の CloudEvents 送信元 | 上記のいずれかのトークン方法。`https://user:<pushToken>@host/...` のように認証情報をアドレスにしか含められない送信元も受け付けます。 |

    本文には 1 つのイベントまたはその配列を格納します。形式は、構造化モードまたはバイナリモードの CloudEvents 1.0、Amazon EventBridge イベント、または Event Grid スキーマです。各イベントは `targetStream`（デフォルトは `cloud_events`）の 1 つのログイベントになります:

    | フィールド | 取得元 |
    |---|---|
    | `event_id`、`event_source`、`event_type`、`event_subject` | CloudEvents の `id`、`source`、`type`、`subject`、EventBridge の `id`、`source`、`detail-type`、Event Grid の `id`、`topic`、`eventType`、`subject` |
    | `account_id`、`region` | EventBridge の `account`、`region`、Alibaba Cloud の `aliyunaccountid`、`aliyunregionid`、Event Grid トピックのサブスクリプション |
    | `resources` | EventBridge の `resources` |
    | `data` | 1 つの JSON フィールドとしてのペイロード。テキストペイロードは `message` に入ります |
    | `event_format` | `cloudevents`、`eventbridge`、または `event_grid` |

    拡張属性は名前をそのまま保持します。イベント自身の時刻がそのイベントの時刻になります。その他の JSON オブジェクトは、そのフィールドをそのまま持つ 1 つのイベントになります。同じソースと id を持つイベントが 30 分以内に再配信された場合、二重には書き込みません。エンドポイントは `200` を返します。JSON でない本文の場合は `400` を返します。
  </Tab>
  <Tab title="Cloudflare Logpush">
    `kind: "cloudflare_logpush"` でコネクタを作成し、HTTP 送信先を指定した Logpush ジョブを作成します。Cloudflare は `header_` クエリパラメータをリクエストヘッダーに変換するため、トークンは `X-Connector-Token` で送信します:

    ```text
    https://molesignal.example.com/api/v1/_cloudflare?header_X-Connector-Token=<pushToken>
    ```

    Cloudflare は gzip 圧縮された NDJSON を送信し、各行が 1 つのイベントになります。エンドポイントは `204 No Content` を返します。
  </Tab>
  <Tab title="Heroku">
    `kind: "heroku_drain"` でコネクタを作成し、ドレインを追加します。Heroku はカスタムヘッダーを設定できないため、トークンは URL で送信します:

    ```bash
    heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
    ```

    各ログ行は `message` と `source: "heroku"` を持つイベントになります。エンドポイントは `204 No Content` を返します。
  </Tab>
</Tabs>

<Tip>
  `targetStream` は最初の配信時に作成され、スキーマは新しいフィールドが現れるたびに、他のストリームと同様に進化します。`targetStream` を省略すると、ソースごとのデフォルト（`kinesis`、`gcp`、`cloud_events`、`cloudflare`、または `heroku`）にフォールバックします。Firehose コネクタはメトリクスサンプルを `metricsStream` に書き込み、デフォルトは `cloudwatch` です。
</Tip>

### CloudWatch Logs

CloudWatch Logs は **プル**ソースです。MoleSignal はプッシュを受信する代わりに、30 秒ごとに `FilterLogEvents` を呼び出します。初回実行では直近 5 分間を読み取ります。以降の実行は最後に成功した実行が終了した位置から開始するため、読み取りまたは書き込みできなかったイベントは次回の実行で再度読み取られます。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "cw-prod",
        "kind": "aws_cloudwatch_logs",
        "configJson": {
          "region": "ap-southeast-1",
          "logGroup": "/aws/lambda/checkout",
          "auth": "node_role",
          "targetStream": "cloudwatch"
        }
      }'
```

| フィールド | 備考 |
|---|---|
| `region` / `logGroup` | 必須。読み取る CloudWatch リージョンとロググループ。 |
| `auth` とそのキー | 認証情報。ロググループに対する `logs:FilterLogEvents` が必要です。[AWS 認証](#aws-認証)を参照してください。 |
| `targetStream` | 送信先ストリーム。デフォルトは `default`。 |

一度に 1 つのノードが 1 つのコネクタをポーリングします。`alert` ノードはコネクタを分担し、ノードはポーリング前にコネクタを確保します。[アラートノード間の作業分担](/ja/deployment/role-based#アラートノード間の処理分担)を参照してください。各イベントは `message`、`log_stream`、`log_group` を持つログになります。無効なコネクタはポーリングされません。

### Kafka トピック

`kafka_source` コネクタは 30 秒ごとにトピックを読み取り、書き込みが完了した最後の読み取り位置から続行します。コンシューマーグループのメンバーとしてではなく、割り当てによってパーティションを取得し、オフセットを MoleSignal に保持します。そのため、トピックを読み取る権限だけが必要で、クラスター上にコンシューマーグループは表示されません。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "orders",
        "kind": "kafka_source",
        "configJson": {
          "brokers": "b-1.example.com:9096,b-2.example.com:9096",
          "topic": "orders",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "<password>",
          "targetStream": "orders",
          "startFrom": "latest"
        }
      }'
```

| フィールド | 備考 |
|---|---|
| `brokers`、`topic`、`tls`、`tlsCaCert`、`auth` とそのキー | [Kafka 送信先](#apache-kafka)と同様。 |
| `targetStream` | 送信先ストリーム。デフォルトは `default`。 |
| `messageFormat` | デフォルトの `json`、または Azure Monitor がイベントハブにエクスポートするデータ向けの `azure_records`（下記参照）。UI: **メッセージ形式**。 |
| `startFrom` | 最初の読み取りを開始する位置。今後到着するデータにはデフォルトの `latest`、ブローカーが保持するすべてのデータには `earliest`。後から追加されたパーティションは先頭から読み取られます。UI: **読み取り開始位置**。 |

- 値が JSON オブジェクトであるメッセージは、ログのフィールドを提供します。その他の値は `message` になります。各ログには `kafka_topic`、`kafka_partition`、`kafka_offset`、メッセージにキーがある場合は `kafka_key`、および `source` も含まれます。時刻はメッセージのタイムスタンプです。
- 1 回の読み取りでは最大 10,000 メッセージまたは 32 MiB を処理し、さらにデータがある間は次の読み取りを即座に続けます（1 回のプルで最大 2 分間）。
- オフセットはログが書き込まれた後にのみ進みます。失敗した読み取りまたは書き込みは 30 秒後に同じ位置から再試行されるため、メッセージが 2 回書き込まれることはありますが、失われることはありません。ブローカーが期限切れで削除したオフセットは、保持している最も古いメッセージから続行します。
- `topic` を変更すると、オフセットはトピックに属するため、`startFrom` からやり直します。

Azure の診断設定、Log Analytics のデータエクスポート、データ収集ルールは Azure Event Hubs にエクスポートされます。Kafka ソースはハブの Kafka エンドポイントを通じてこれを読み取ります。`brokers` は `<namespace>.servicebus.windows.net:9093`、`topic` はイベントハブ、`tls` はオン、`auth: sasl_plain` でユーザー名は `$ConnectionString`、パスワードは接続文字列です。Basic レベルには Kafka エンドポイントがありません。`messageFormat: azure_records` を指定すると、各 `{"records": [...]}` メッセージが展開されます。ログレコードはその `time` のログイベントになり、メトリクスレコードはコネクタの `metricsStream`（デフォルトは `default`）に統計ごとに 1 つのサンプルとして書き込まれ、[Azure Monitor メトリクス](#クラウドメトリクス)と同様に命名されます。

### S3 オブジェクト

`s3_source` コネクタは 30 秒ごとにバケットを一覧表示し、AWS S3 または S3 互換ストアから、まだ読み取っていないオブジェクトを古い順に読み取ります。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "elb-logs",
        "kind": "s3_source",
        "configJson": {
          "bucket": "acme-logs",
          "region": "us-east-1",
          "prefix": "AWSLogs/123456789012/",
          "auth": "node_role",
          "targetStream": "elb",
          "startFrom": "latest"
        }
      }'
```

| フィールド | 備考 |
|---|---|
| `bucket`、`region`、`endpoint`、`virtualHostedStyle`、`auth` とそのキー | [S3 送信先](#amazon-s3)と同様。認証情報にはバケットに対する `s3:ListBucket` とオブジェクトに対する `s3:GetObject` が必要です。 |
| `prefix` | このプレフィックス配下のオブジェクトのみが読み取られます。各プルでプレフィックス全体を一覧表示するため、ソースごとに専用のプレフィックスを指定してください。 |
| `targetStream` | 送信先ストリーム。デフォルトは `default`。 |
| `startFrom` | 最初の読み取りを開始する位置。今後現れるオブジェクトと直前 5 分間に現れたオブジェクトにはデフォルトの `latest`、プレフィックス配下のすべてには `earliest`。UI: **読み取り開始位置**。 |

- オブジェクトは行単位で読み取られます。JSON オブジェクトである行はログのフィールドを提供し、CloudTrail が書き込むように `Records` のみを含む行はレコードごとに 1 つのログを提供し、その他の行は `message` になります。`.gz` および `.zst` オブジェクトは拡張子に基づいて展開されます。各ログには `s3_bucket`、`s3_key`、`source` も含まれます。時刻はオブジェクトの最終更新時刻です。
- 1 回のプルでは最大 100 オブジェクトまたは 50,000 ログまで読み取り、さらにデータがある間は次のプルを即座に続けます（最大 2 分間）。
- 読み取り状態はログが書き込まれた後にのみ進みます。取得できないオブジェクトがあるとそこでプルが停止し、30 秒後に再試行されるため、ログが 2 回書き込まれることはありますが、失われることはありません。
- 読み取れないオブジェクトはスキップされ、コネクタにその旨が表示されます。再試行するとそれ以降のすべてが遅れるためです。対象は、破損している、256 MiB を超える、展開後 512 MiB を超える、100 万ログを超える、または 64 MiB を超える行を含むオブジェクトです。
- オブジェクトはキーと更新時刻によって、5 分間の余裕を持って識別されます。その範囲内に同じキーで再度書き込まれたオブジェクトは再読み取りされず、更新時刻が読み取り済みの最新オブジェクトより 5 分を超えて古いオブジェクトはまったく読み取られません。S3 はマルチパートアップロードの日時を開始時点とするため、それより遅いアップロードは読み取られません。

### Google Cloud Pub/Sub サブスクリプション

`gcp_pubsub_pull` コネクタは 30 秒ごとに Pub/Sub サブスクリプションを読み取り、1 リクエストあたり最大 1,000 メッセージを処理し、さらにメッセージがある間は即座に続行します。メッセージの確認応答は、書き込みが完了した後にのみ行います。書き込みに失敗したものは、確認応答の期限が切れると再配信されるため、メッセージが 2 回書き込まれることはありますが、失われることはありません。これは、1 リクエストにつき 1 メッセージを送信する[プッシュサブスクリプション](#プッシュソース)より、大量のログをうまく扱えます。

| フィールド | 備考 |
|---|---|
| `serviceAccountKey` | サブスクリプションに対する `roles/pubsub.subscriber` を持つサービスアカウントの JSON キーファイル。 |
| `subscription` | `projects/<project>/subscriptions/<name>`、またはキーのプロジェクト内のサブスクリプション名。確認応答の期限を 60 秒以上に設定してください。 |
| `targetStream` | 送信先ストリーム。デフォルトは `default`。 |

各メッセージはプッシュされたメッセージと同様に読み取られます。Cloud Logging の `LogEntry` はプッシュタブのマッピングで、その他の JSON オブジェクトはそのフィールドとして、それ以外は `message` として扱われます。**接続をテスト**は、メッセージを取得せずに、キーがサブスクリプションを消費できるかどうかを確認します。

### クラウドメトリクス

6 つのソースが、クラウドのモニタリングサービスのメトリクスをスケジュールに従ってプルし、メトリクスストリームに書き込みます:

| 種類 | クラウド | API | 認証 | 権限 | デフォルトの `metricsStream` |
|---|---|---|---|---|---|
| `aws_cloudwatch_metrics` | Amazon CloudWatch | `ListMetrics`、`GetMetricData` | [AWS 認証情報](#aws-認証) | `cloudwatch:ListMetrics`、`cloudwatch:GetMetricData` | `cloudwatch` |
| `azure_monitor_metrics` | Azure Monitor | Resource Graph、`metrics:getBatch` | アプリ登録の `tenantId`、`clientId`、`clientSecret` | サブスクリプションに対する **監視閲覧者** | `azure` |
| `gcp_monitoring_metrics` | Google Cloud Monitoring | `timeSeries.list` | `serviceAccountKey`（JSON キーファイル） | プロジェクトに対する `roles/monitoring.viewer` | `gcp` |
| `aliyun_cms_metrics` | Alibaba Cloud CloudMonitor | `DescribeMetricList` | `accessKey`、`secretKey` | `AliyunCloudMonitorReadOnlyAccess` | `aliyun` |
| `tencent_monitor_metrics` | Tencent Cloud Monitor | `GetMonitorData` | `accessKey`（SecretId）、`secretKey`（SecretKey） | `QcloudMonitorReadOnlyAccess`、および CVM インスタンスを検出するための `QcloudCVMReadOnlyAccess` | `tencentcloud` |
| `huawei_ces_metrics` | Huawei Cloud Eye | `ListMetrics`、`BatchListMetricData` | `accessKey`（AK）、`secretKey`（SK） | `CES ReadOnlyAccess` | `huaweicloud` |

各プルは、少なくとも `delay` 秒前に終了した `period` 秒の期間全体を、最後に書き込みが完了したプルが終了した位置から読み取ります。クラウドは期間終了後数分で集計を完了し、各期間は 1 回だけ読み取られます。後から修正された値は、読み取ったときのまま保持されます。新しいコネクタは 1 期間前から開始します。1 回のプルでは最大 12 期間を読み取り、次のティックで続行します。6 時間を超えて停止していたコネクタは、古い期間をスキップし、その旨を表示します。

各シリーズの各統計は、期間の開始時点で、yet-another-cloudwatch-exporter が CloudWatch メトリクスに付けるのと同じ方法で `<cloud>_<namespace>_<metric>_<statistic>` という名前の 1 つのゲージサンプルになります:

| ソース | 例 | ラベル |
|---|---|---|
| CloudWatch | `aws_ec2_cpuutilization_average` | `region`、`dimension_<Name>` |
| Azure Monitor | `azure_compute_virtualmachines_percentage_cpu_average` | `subscription_id`、`resource_group`、`resource_name`、`resource_id`、`region`、`dimension_<name>`、`tag_<key>` |
| Cloud Monitoring | `gcp_compute_instance_cpu_utilization_mean` | `project_id`、`resource_type`、リソースとメトリクスのラベル |
| CloudMonitor | `aliyun_ecs_dashboard_cpuutilization_average` | `region`、`user_id`、`dimension_<key>` |
| Tencent Cloud Monitor | `tencentcloud_cvm_cpu_usage_avg` | `region`、`dimension_<Name>` |
| Cloud Eye | `huaweicloud_sys_ecs_cpu_util_average` | `region`、`dimension_<name>` |

これらは [Firehose 経由の CloudWatch メトリクスストリーム](#プッシュソース)が書き込む名前と同じであるため、PromQL で両方に対してクエリできます:

```promql
max by (dimension_InstanceId) (aws_ec2_cpuutilization_average)
```

| フィールド | ソース | 備考 |
|---|---|---|
| `metricsStream` | すべて | 送信先メトリクスストリーム。 |
| `period` | すべて | 秒単位、分単位の整数。デフォルトは 300。Azure は 60、300、900、1800、3600、21600、43200、または 86400、Huawei Cloud は 300、1200、3600、14400、または 86400 を受け付けます。 |
| `delay` | すべて | 期間終了後、読み取るまでの秒数。CloudWatch と Azure のデフォルトは 600、その他は 300。 |
| `region` | Google Cloud 以外すべて | 例: `us-east-1`、`eastus`、`cn-hangzhou`、`ap-guangzhou`、`cn-north-4`。 |
| `namespace` | CloudWatch、CloudMonitor、Tencent Cloud、Cloud Eye | 例: `AWS/EC2`、`acs_ecs_dashboard`、`QCE/CVM`、`SYS.ECS`。 |
| `metrics` | すべて | メトリクス名。カンマまたは改行区切り。CloudWatch 以外は必須。CloudWatch は空の場合、直近 3 時間にデータがあった名前空間のすべてのメトリクスを最大 2,000 シリーズまで読み取ります。Google Cloud はメトリクスタイプ（`compute.googleapis.com/instance/cpu/utilization` など）を受け付けます。 |
| `statistics` | CloudWatch、CloudMonitor、Tencent Cloud、Cloud Eye | CloudWatch: `Average`、`Sum`、`Minimum`、`Maximum`、`SampleCount`、および `p99` などのパーセンタイル。デフォルトは `Average`、`Maximum`。CloudMonitor: `Average`、`Maximum`、`Minimum`、`Sum`。デフォルトは `Average`、`Maximum`。Tencent Cloud: `avg`、`max`、`min`。デフォルトは `avg`。Cloud Eye: `average`、`max`、`min`、`sum`、`variance`。デフォルトは `average`。 |
| `subscriptionId`、`resourceType`、`aggregations`、`filter`、`top` | Azure | リソースタイプはメトリクス名前空間でもあります（`Microsoft.Compute/virtualMachines` など）。集計: `average`（デフォルト）、`minimum`、`maximum`、`total`、`count`。`filter` はディメンションで分割します（`LUN eq '*'` など）。`top` は分割後のシリーズ数を上限設定し、デフォルトは 100 です。 |
| `projectId`、`filter` | Google Cloud | プロジェクトはキーのプロジェクトがデフォルトです。`filter` は各メトリクスのフィルターに追加される句です。ゲージは `mean`、デルタは `sum`、カウンターは `rate`、分布は `count` と `mean` として読み取られます。 |
| `dimensions` | CloudMonitor | `Dimensions` として渡す任意の JSON。空の場合はアカウントのすべてのインスタンスを読み取ります。 |
| `instances` | Tencent Cloud | 1 行に 1 インスタンスを `Name=Value` で指定し、複数のディメンションは `&` で結合します。`QCE/CVM` 以外は必須。`QCE/CVM` は空の場合、リージョン内のインスタンスが検出されます。 |
| `projectId` | Cloud Eye | リージョンのプロジェクト。 |

すべてのクエリはクラウドによって課金されます。CloudWatch は各シリーズの各統計をリクエストされた 1 メトリクスとして課金し、Google Cloud は返されたシリーズ数で課金し、その他は無料の月間クォータを超えた API 呼び出しで課金されます。`metrics` と `statistics` は必要なものだけに抑えてください。`period` を長くするとコストが下がります。**接続をテスト**は保存済みの設定で小さなリクエストを 1 回行い、読み取り状態は変更しません。

<Tip>
  リポジトリの `deploy/cloud` ディレクトリには、クラウド側をセットアップするテンプレートがあります。Firehose ストリーム、メトリクスストリーム、CloudWatch Logs サブスクリプションを含む CloudFormation スタック、Log Router シンクと Pub/Sub サブスクリプションを含む Terraform モジュール、Kafka ソースが読み取る Event Hubs 名前空間を含む Bicep ファイルです。
</Tip>

### プルの進行状況

コネクタのページには、ソースが最後に受信した日時が表示されます。最後の読み取りに失敗したソースはその横に警告を表示し、理由はツールチップとコネクタの設定に表示されます。ソースが最後にスキップした内容もそこに表示されます。API 経由では、`readState` に `lastError` と `lastWarning` があり、それぞれ `atTime` と `text` を持ちます。また、どこまで進んだかを示す `position` もあります。コネクタを保存しても位置は変わりません。

## 送信先

送信先は、スケジュールされたパイプラインのステップを通過するすべてのイベントを受信します。**送信先を追加 → コネクター** で、フローの **送信先** にコネクターを追加します。失敗した配信は実行内で再試行され、コネクターがそれでも受け付けないイベントはデッドレターストリームに送られます。[再試行とデッドレター](/ja/pipelines#再試行とデッドレター) を参照してください。

オフになっている送信先は何も受信しません。各実行はそのコネクターをスキップし、実行の `warning` にその名前を記録します。スキップされたイベントは失敗としてカウントされず、デッドレターにもならず、コネクターを再びオンにしても送信されません。エディターでは、オフになっているコネクターは **オフ** と表示されます。

| 種類 | ペイロード |
|---|---|
| `s3` | バッチごとに 1 つの JSON Lines オブジェクトを `s3://<bucket>/<prefix><id>.jsonl` に `PUT` します。 |
| `kafka` | トピック上のイベントごとに 1 つのメッセージを送信し、イベントを JSON ペイロードとして含めます。 |
| `http` | バッチを 1 つのリクエストで、大きい場合は複数のリクエストで、NDJSON または 1 つの JSON 配列として送信します。 |

### Amazon S3

`s3` 種類は、MinIO、Cloudflare R2、Alibaba Cloud OSS などの S3 互換ストレージにも配信します。UI で **S3 互換ストレージ** をオンにすると、エンドポイントを設定できます。

| フィールド | 備考 |
|---|---|
| `bucket` | 必須です。 |
| `region` | バケットのリージョンです。S3 互換ストアでは不要な場合があります。 |
| `prefix` | オブジェクト名は `<prefix><id>.jsonl` になります。先頭の `/` は削除され、末尾の `/` が追加されます。 |
| `endpoint` | S3 互換ストアの S3 API アドレスで、`http://` または `https://` で始まります。 |
| `virtualHostedStyle` | `true` の場合、バケットをパスではなくホスト名として扱います。Alibaba Cloud OSS などのストアではこれが必要です。UI: **バケット名をホスト名に含める**。 |
| `auth` とそのキー | 認証情報です。バケットに対する `s3:PutObject` 権限が必要です。[AWS 認証](#aws-認証) を参照してください。 |

### Apache Kafka

| フィールド | 備考 |
|---|---|
| `brokers` | 必須です。ホストとポートを指定し、複数指定する場合はカンマで区切ります。 |
| `topic` | 必須です。 |
| `tls` | `true` の場合、TLS で接続を暗号化します。ブローカーの TLS ポート（多くの場合 9093、9094、9096）に接続します。UI: **TLS で接続を暗号化**。 |
| `tlsCaCert` | ブローカーの証明書を発行したプライベート CA の PEM 証明書です。`tls` と併用する場合のみ指定します。指定しない場合は、システムの CA が信頼されます。 |

| `auth` | UI | キー | 備考 |
|---|---|---|---|
| `none` | **なし** | | 認証情報を要求しないブローカー用です。 |
| `sasl_plain` | **SASL/PLAIN** | `saslUsername`, `saslPassword` | パスワードをそのまま送信します。TLS を使用しない場合は、プライベートネットワーク内でのみ使用してください。 |
| `sasl_scram_sha_256` | **SCRAM-SHA-256** | `saslUsername`, `saslPassword` | パスワード自体がネットワークを通過することはありません。 |
| `sasl_scram_sha_512` | **SCRAM-SHA-512** | `saslUsername`, `saslPassword` | Amazon MSK が使用するメカニズムです。 |
| `mtls` | **クライアント証明書** | `tlsClientCert`, `tlsClientKey` | 相互 TLS です。`tls` が必要です。どちらも PEM 形式で、秘密鍵は暗号化できません。 |

TLS と SASL は組み合わせられます。TLS 上の SCRAM は `SASL_SSL` として接続します。

### HTTP / Webhook

| フィールド | 備考 |
|---|---|
| `url` | 必須です。絶対 `http://` または `https://` URL です。URL にはパスやクエリ内のキーなど認証情報が含まれることが多いため、シークレットとして保持されます。レスポンスには `urlOrigin`、スキーム、ホスト、ポートのみが表示されます。URL 内のユーザー名とパスワードは拒否されます。`basic` を使用してください。 |
| `method` | `post`（デフォルト）または `put`。 |
| `format` | `ndjson`（デフォルト）は 1 行につき 1 イベントを `application/x-ndjson` として送信します。`json` は 1 つの JSON 配列を `application/json` として送信します。 |

| `auth` | UI | キー | リクエスト |
|---|---|---|---|
| `none` | **なし** | | 認証情報なし。 |
| `bearer` | **Bearer トークン** | `bearerToken` | `Authorization: Bearer <token>` |
| `basic` | **Basic 認証** | `basicUsername`, `basicPassword` | HTTP Basic 認証です。`https` 経由で使用してください。 |
| `header` | **カスタムヘッダー** | `headerName`, `headerValue` | 指定したヘッダーに値を設定します（例: `X-API-Key`、`DD-API-KEY`）。 |
| `hmac` | **HMAC 署名** | `hmacSecret` | ボディの署名です。シークレットは 16 文字以上である必要があります。 |

カスタムヘッダーには、配信側が自動で設定するヘッダーを指定できません: `Host`、`Content-Type`、`Content-Length`、`Content-Encoding`、`Transfer-Encoding`、`Connection`、`X-MoleSignal-Timestamp`、または `X-MoleSignal-Sign`。

配信は次のルールに従います:

- 4 MiB を超えるバッチは複数のリクエストに分割されます。それを超えるイベントは、単独のリクエストで送信されます。
- 任意の `2xx` ステータスは配信成功と見なされます。それ以外のステータスは配信失敗となり、リダイレクトも同様です。リダイレクトは追跡されません。
- リクエストは 30 秒でタイムアウトします。
- MoleSignal はリクエスト前にホストを名前解決し、解決したアドレスにのみ接続します。クラウドメタデータサービスが応答するアドレスは、URL に含まれる場合でも DNS から返される場合でも拒否されます: `169.254.0.0/16`、`fe80::/10`、`fd00:ec2::254`、`100.100.100.200`。その他のプライベートアドレスは許可されます。

#### HMAC 署名を検証する

`hmac` の場合、各リクエストには 2 つのヘッダーが付与されます:

| ヘッダー | 内容 |
|---|---|
| `X-MoleSignal-Timestamp` | リクエスト時刻（Unix 秒）。 |
| `X-MoleSignal-Sign` | `sha256=<hex>`。共有シークレットを使用した `<timestamp>.<body>` の HMAC-SHA256 です。 |

リクエストを検証するには、同じシークレットを使用して、タイムスタンプ、`.`、生のボディバイトの HMAC-SHA256 を計算し、結果を署名と定数時間で比較します。数分より古いタイムスタンプは拒否し、キャプチャされたリクエストが後から再送されないようにします。

```python
import hashlib
import hmac
import time


def verify(secret: bytes, timestamp: str, signature: str, body: bytes, tolerance: int = 300) -> bool:
    if abs(time.time() - int(timestamp)) > tolerance:
        return False
    signed = timestamp.encode() + b"." + body
    expected = "sha256=" + hmac.new(secret, signed, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## AWS 認証

S3 と CloudWatch Logs は、次の 5 つの方法のいずれかで AWS に認証します:

| `auth` | UI | キー | 認証情報 |
|---|---|---|---|
| `access_key` | **アクセスキー** | `accessKey`、`secretKey` | IAM ユーザーの長期キーです。 |
| `temporary_key` | **一時キー** | `accessKey`、`secretKey`、`sessionToken` | AWS STS が発行する短期キーで、セッショントークンと組み合わせた場合のみ有効です。有効期限が切れる前に更新してください。 |
| `node_role` | **ノード ID** | | MoleSignal が実行されているノードの ID です。キーは保存されません。 |
| `assume_role` | **ロールの引き受け** | `roleArn`、任意で `accessKey` と `secretKey` | 組織の外部 ID を使用して AWS STS 経由で引き受けるロールです。 |
| `web_identity` | **ウェブ ID** | `roleArn` | ノードのウェブ ID トークンを使用して引き受けるロールです。 |

`auth` を指定しない場合は、保存されているキーで決まります。アクセスキーは `access_key`、`roleArn` は `assume_role`、どちらもなければ `node_role` として扱われます。`roleArn` の形式は `arn:aws:iam::<account>:role/<name>` です。

### ノード ID

`node_role` は、AWS SDK がノード上で検出する ID を使用します。EKS のサービスアカウント用 IAM ロール (IRSA) または EKS Pod Identity、ECS タスクロール、EC2 インスタンスプロファイルのいずれかです。`AWS_ACCESS_KEY_ID` などノードの環境にある静的キーは、コネクターには使用されません。

<Warning>
  ノードの ID とそのウェブ ID トークンはデプロイメントに属します。デプロイメント内のすべての組織が `node_role` と `web_identity` を選択できるため、ノードの ID が到達できる範囲と、ノードのトークンを信頼するすべてのロールは、すべての組織のコネクターに開かれています。すべての組織が持ってよいアクセス権だけを付与してください。
</Warning>

### ロールの引き受け

`assume_role` は AWS STS にロールの 1 時間有効なキーを要求し、有効期限の 5 分前にキーを更新します。ロールを引き受けるためのベース認証情報は、ノードの ID です。AWS 上で実行されないデプロイメントでは、**ノードの ID ではなくアクセスキーでロールを引き受ける** を選択し、IAM ユーザーのキーを入力します。

各組織は、変更できない独自の外部 ID `molesignal-<organization ID>` でロールを引き受けます。フォームでは **外部 ID** の下に表示され、`GET /api/v1/connectors/aws-external-id` で取得できます。ロールの信頼ポリシーで外部 ID を必須にすると、他の組織が ARN を知ってもそのロールを引き受けることはできません:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "<ARN of the node role or IAM user>" },
      "Action": "sts:AssumeRole",
      "Condition": { "StringEquals": { "sts:ExternalId": "molesignal-<organization ID>" } }
    }
  ]
}
```

セッション名は `molesignal-<connector ID>` で、AWS CloudTrail にはこの名前で表示されます。リクエストはコネクターの `region` のリージョン別 STS エンドポイントに送信されます。`region` が空の場合は `us-east-1`、中国リージョンの場合は `amazonaws.com.cn` ドメインを使用します。

### ウェブ ID

`web_identity` は、ノードの `AWS_WEB_IDENTITY_TOKEN_FILE` が示すパスのウェブ ID トークン (EKS が IRSA 用に投影するサービスアカウントトークンなど) でロールを引き受けます。コネクターが別のファイルを指定することはできません。ロールの信頼ポリシーは、トークンを発行する OIDC プロバイダーを信頼している必要があります。`AWS_WEB_IDENTITY_TOKEN_FILE` がないノードでは、コネクターに認証情報がありません。

トークンは、コネクターの `region` のリージョン別 STS エンドポイント、またはノードの環境が設定している場合は `AWS_ENDPOINT_URL_STS` で交換されます。IRSA からのノード ID についても同じです。

## 接続をテストする

**接続をテスト** は、保存前のフォームの内容のまま設定を試します。シークレットを空のままにすると、保存済みの値が使われます。種類ごとに、送信または取得が機能することを証明する最小限の処理を行います:

| 種類 | テスト |
|---|---|
| `s3` | プレフィックス配下に `.molesignal-connection-test` オブジェクトを書き込み、ポリシーが許可する場合は削除します。 |
| `kafka` | ブローカーからトピックのメタデータを読み取り、接続、TLS、認証、およびトピックの存在を確認します。メッセージは書き込みません。 |
| `http` | テストであることを示す 1 件のイベントを送信します: `"message": "MoleSignal connection test"` と `"molesignal_connection_test": true`。 |
| `aws_cloudwatch_logs` | ロググループの直近 1 分間のイベントを最大 1 件読み取ります。ストリームには何も書き込まず、読み取り位置はそのままにします。 |
| `kafka_source` | `kafka` と同様に、ブローカーからトピックのメタデータを読み取ります。メッセージは読み取らず、読み取り位置はそのままにします。 |
| `s3_source` | プレフィックス配下のオブジェクトを 1 件リストし、認証情報と `s3:ListBucket` を確認します。何も読み取らず、読み取り位置はそのままにします。 |

テストは 25 秒で打ち切られます。API では、`POST /api/v1/connectors/test` に試す `kind` と `configJson` を渡します。同じ種類の保存済みコネクターの `id` を指定すると、`***` はそのコネクターが保持するシークレットを表します。機能しない設定は、保存時と同様に `400` を返します。

```bash
curl -X POST http://localhost:5080/api/v1/connectors/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "id": "<connector id>",
        "kind": "kafka",
        "configJson": {
          "brokers": "b-1.example.com:9096",
          "topic": "logs",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "***"
        }
      }'
```

```json
{ "ok": true, "code": "ok", "detail": null, "elapsedMs": 412 }
```

`elapsedMs` はテストにかかった時間です。失敗したテストは `code` で原因を示し、`detail` には相手側の文言が最大 600 文字まで入ります:

| `code` | 意味 |
|---|---|
| `ok` | 接続しました。 |
| `invalid` | 設定が機能しないか、コネクターがプッシュソースであり、接続先がありません。 |
| `no_credentials` | AWS 認証情報を取得できませんでした。ノードに ID がないか、要求された種類の ID がありません。 |
| `denied` | 相手側が認証情報、またはその認証情報に許可された操作を拒否しました。 |
| `not_found` | バケット、トピック、ロググループ、またはアドレスが存在しません。 |
| `tls` | TLS ハンドシェイクに失敗しました。証明書が信頼されていないか、提示されていません。 |
| `unreachable` | ホストを解決できないか、接続できませんでした。 |
| `timeout` | 時間内に応答がありませんでした。 |
| `failed` | その他の失敗。 |

## API

| エンドポイント | 権限 | 用途 |
|---|---|---|
| `GET /api/v1/connectors` | `pipelines.read` | 組織のコネクターを一覧表示します。 |
| `POST /api/v1/connectors` | `pipelines.edit` | コネクターを作成します。`enabled` の既定値は `true` です。 |
| `GET /api/v1/connectors/{id}` | `pipelines.read` | コネクターを取得します。 |
| `PUT /api/v1/connectors/{id}` | `pipelines.edit` | `name`、`kind`、`configJson`、`enabled` を置き換えます。すべて必須です。 |
| `DELETE /api/v1/connectors/{id}` | `pipelines.edit` | コネクターを削除します。 |
| `POST /api/v1/connectors/test` | `pipelines.edit` | 保存前に設定をテストします。 |
| `GET /api/v1/connectors/aws-external-id` | `pipelines.read` | 組織の外部 ID を `externalId` として返します。 |

コネクターは、`id`、`name`、`kind`、シークレットをマスクした `configJson`、`secretKeys`、`enabled`、`lastRunAt`、`readState`、`createdAt`、`updatedAt` として返されます。

## 権限

`pipelines.read` はコネクターの一覧表示と検査、および外部 ID の取得を行います。`pipelines.edit` はコネクターの作成、更新、削除、テストを行います。テストは保存済みのシークレットを使用し、呼び出し元に代わって別のシステムに接続するため、`pipelines.edit` が必要です。プッシュレシーバーはプッシュトークンで認証し、通常のログイン JWT を代わりに受け付けることはありません。
