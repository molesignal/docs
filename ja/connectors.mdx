**コネクター**は、外部プラットフォームとの管理された統合です。コネクターは次の2つの方向に動作します:

- **ソース**は他のサービスからデータを取り込み、ストリームに書き込みます。MoleSignal は CloudWatch Logs、Kafka トピック、S3 オブジェクトをスケジュールに従ってポーリングします。Amazon Data Firehose、Google Cloud Pub/Sub、Cloudflare Logpush、Heroku は MoleSignal にプッシュします。Firehose は CloudWatch メトリクスも転送します。
- **送信先**は[スケジュールされたパイプライン](/ja/pipelines#シンクとコネクターのイグレス)の出力を受け取ります。Amazon S3 と S3 互換ストレージ、Apache Kafka、任意の HTTP エンドポイントです。

| 種類 | コネクター | 方向 | 認証 |
|---|---|---|---|
| `aws_cloudwatch_logs` | AWS CloudWatch Logs | ソース、30秒ごとにポーリング | [AWS 認証情報](#aws-認証) |
| `kafka_source` | Kafka トピック | ソース、30秒ごとにポーリング | なし、SASL、またはクライアント証明書 |
| `s3_source` | S3 オブジェクト | ソース、30秒ごとにポーリング | AWS 認証情報 |
| `gcp_pubsub_pull` | Google Cloud Pub/Sub サブスクリプション | ソース、30秒ごとにポーリング | サービスアカウントキー |
| `aws_cloudwatch_metrics`, `azure_monitor_metrics`, `gcp_monitoring_metrics`, `aliyun_cms_metrics`, `tencent_monitor_metrics`, `huawei_ces_metrics` | [クラウドメトリクス](#クラウドメトリクス) | ソース、期間ごとにポーリング | 各クラウドの認証情報 |
| `aws_kinesis_firehose` | Amazon Data Firehose | ソース、プッシュ | [プッシュトークン](#プッシュソース) |
| `gcp_pubsub_push` | Google Cloud Pub/Sub プッシュ | ソース、プッシュ | プッシュトークン（任意でサブスクリプションの OIDC トークン） |
| `cloud_events` | クラウドイベントバス | ソース、プッシュ | プッシュトークン |
| `cloudflare_logpush` | Cloudflare Logpush | ソース、プッシュ | プッシュトークン |
| `heroku_drain` | Heroku ログドレイン | ソース、プッシュ | プッシュトークン |
| `s3` | Amazon S3 | 送信先 | AWS 認証情報 |
| `kafka` | Apache Kafka | 送信先 | なし、SASL、またはクライアント証明書 |
| `http` | HTTP / Webhook | 送信先 | なし、ベアラートークン、Basic 認証、カスタムヘッダー、または HMAC 署名 |

## コネクターを作成

<Steps>
  <Step title="コネクターを開く">
    **パイプライン → コネクター**に移動します。ページには**ソース**と**送信先**が一覧表示されます。
  </Step>
  <Step title="種類を選択">
    **新規コネクター**をクリックし、接続先を選択します。
  </Step>
  <Step title="設定を入力">
    組織内で一意の**名前**を入力し、コネクターが読み取る元または配信する先を入力し、**認証**を選択します。
  </Step>
  <Step title="テストして作成">
    保存する前に**接続をテスト**をクリックして設定を試し、**コネクターを作成**をクリックします。プッシュソースには接続先がないため、テストは提供されません。
  </Step>
</Steps>

API では、コネクターは `name`、`kind`、および `configJson` で構成され、`configJson` のキーは種類によって異なります。`configJson` の `auth` は認証方法を指定し、各方法は独自のキーを持ちます。動作できない設定は保存時に `400` を返します。必須キーの欠落、認証情報ペアの片方のみ、または選択した `auth` が使用しないキーです。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "archive",
        "kind": "s3",
        "configJson": {
          "bucket": "acme-logs",
          "region": "eu-west-1",
          "prefix": "pipelines/checkout/",
          "auth": "assume_role",
          "roleArn": "arn:aws:iam::123456789012:role/molesignal-delivery"
        }
      }'
```

## シークレット

`configJson` の次のキーはシークレットを保持します:

| 種類 | シークレットキー |
|---|---|
| `s3`, `aws_cloudwatch_logs` | `accessKey`, `secretKey`, `sessionToken` |
| `aws_kinesis_firehose`, `gcp_pubsub_push`, `cloud_events`, `cloudflare_logpush`, `heroku_drain` | `pushToken` |
| `aws_cloudwatch_metrics` | `accessKey`, `secretKey`, `sessionToken` |
| `azure_monitor_metrics` | `clientSecret` |
| `gcp_monitoring_metrics`, `gcp_pubsub_pull` | `serviceAccountKey` |
| `aliyun_cms_metrics`, `tencent_monitor_metrics`, `huawei_ces_metrics` | `accessKey`, `secretKey` |
| `kafka` | `saslPassword`, `tlsClientKey` |
| `http` | `url`, `bearerToken`, `basicPassword`, `headerValue`, `hmacSecret` |

シークレットが API を通じて外部に出ることはありません。レスポンスではその箇所に `***` が表示され、`secretKeys` に値を持つシークレットの名前が示されます:

```json
{
  "kind": "kafka",
  "configJson": {
    "brokers": "b-1.example.com:9096",
    "topic": "logs",
    "tls": true,
    "auth": "sasl_scram_sha_512",
    "saslUsername": "molesignal",
    "saslPassword": "***"
  },
  "secretKeys": ["saslPassword"]
}
```

- `***` を返送する更新では保存済みの値が維持されるため、認証情報を再入力せずにコネクターの名前変更、無効化、接続先の変更ができます。UI では、保存済みのシークレットを空のままにすると値が維持されます。
- 更新に含まれないシークレットは削除されます。
- `kind` を変更する更新では、保存済みのシークレットは一切維持されません。

MoleSignal は他の設定とは別に、`MS_CIPHER_KEY` のルートキー（AES-256-GCM）でシークレットを封緘し、シークレットを平文で保存しません。プッシュソースはトークンの SHA-256 で検索されます。ルートキーをローテーションすると、`molesignal rewrap-kek` が他のシークレットとともにコネクターのシークレットを再封緘します。詳しくは[本番環境チェックリスト](/ja/deployment/production-checklist)を参照してください。

## ソース

### プッシュソース

5 つのプッシュソースは 1 つのモデルを共有します。**`pushToken`** と **`targetStream`** を指定してコネクタを作成し、プラットフォームを対応するエンドポイントに向けます。これらのエンドポイントは JWT を使用しません。リクエストは、プラットフォームが許可する方法で指定されたプッシュトークンで認証します:

| 方式 | 使用元 |
|---|---|
| `X-Connector-Token` ヘッダー | Cloudflare など、ヘッダーを設定できるプラットフォーム |
| `X-Amz-Firehose-Access-Key` ヘッダー | Amazon Data Firehose（自動で送信） |
| `X-EventBridge-Signature-Token` ヘッダー | Alibaba Cloud EventBridge |
| `?token=` クエリパラメータ | Heroku や Pub/Sub など、ヘッダーを設定できないプラットフォーム |
| `Authorization: Basic` のパスワード | 認証情報をアドレスに含めるプラットフォーム |

UI はコネクタの作成時にトークンを生成し、プラットフォームに渡すエンドポイントとともに一度だけ表示します。トークンを後から読み取ることはできません。**新しいトークンを生成** は、コネクタの保存時にトークンを置き換えます。API では、16 文字以上の `pushToken` を指定します。1 つのトークンで開けるのは、ある種類のコネクタ 1 つだけです。すでに使用中のトークンは `409` を返します。トークンがない、不明なトークンである、またはコネクタがオフになっているリクエストは `401` を返します。トークンのないコネクタは何も受け付けません。ノードは参照したコネクタを 30 秒間保持するため、コネクタをオフにするかトークンを置き換えると、その時間内に反映されます。

`Content-Encoding: gzip` で送信された本文は自動的に展開されます。Firehose の本文は最大 64 MiB、それ以外は最大 16 MiB で、展開後のサイズも同様にカウントされます。イベントは他のすべてと同様の取り込み経路を通り、スキーマオンライト、[パイプライン](/ja/pipelines)、[マスキング](/ja/security) がすべて適用されます。

<Tabs>
  <Tab title="Amazon Data Firehose">
    `kind: "aws_kinesis_firehose"` でコネクタを作成し、Firehose ストリームの送信先として **HTTP エンドポイント** を選択します:

    - **HTTP エンドポイント URL**: `https://molesignal.example.com/api/v1/_kinesis_firehose`
    - **アクセスキー**: プッシュトークン。Firehose は `X-Amz-Firehose-Access-Key` として送信します。

    Firehose は、公的に信頼された証明書を使用するポート 443 の HTTPS にのみ配信するため、プライベートネットワーク上のデプロイにはパブリックエントリポイントが必要です。[パブリックアクセス](/ja/public-access) を参照してください。ストリームのバッファは 1～4 MiB に保ちます。

    MoleSignal は各レコードを、その内容に応じて個別に読み取ります:

    | レコード | 変換先 |
    |---|---|
    | サブスクリプションフィルタが送信するときに gzip 圧縮される CloudWatch Logs サブスクリプションメッセージ | `logEvents` の各エントリにつき 1 つのログイベントを、エントリ自身の時刻で作成します。`message`、`log_group`、`log_stream`、`account_id`、`region`、`event_id`、`source: "cloudwatch"` を含みます。サブスクリプションの作成時に送信されるヘルスチェックはスキップされます。 |
    | JSON、OpenTelemetry 1.0、または OpenTelemetry 0.7 の出力形式の CloudWatch Metric Streams レコード | メトリクスストリーム内のメトリクスサンプル（後述）。 |
    | その他のテキスト | 1 行につき 1 つのログイベント。JSON オブジェクトはフィールドを提供し、プレーンテキストは `message` に入ります。 |

    メトリクスストリームはメトリクスごとに 1 分あたり 1 つの集計を送信します。各統計は `aws_<namespace>_<metric>_<statistic>` という名前のゲージサンプルになります。命名は yet-another-cloudwatch-exporter に従います: `aws_ec2_cpuutilization_average`、`aws_ec2_cpuutilization_maximum`、`aws_applicationelb_request_count_sum`。名前空間は `AWS/` プレフィックスを削除し、メトリクス名は小文字の後に大文字が続く箇所で単語に分割されます。統計は `average`（サンプル数に対する合計）、`sum`、`sample_count`、`minimum`、`maximum`、およびストリームが追加する `p99` や `p99_9` などのパーセンタイルです。ラベルは `account_id`、`region`、およびディメンションごとの `dimension_<Name>`（`dimension_InstanceId` など）です。`metric_unit` は単位を保持します。

    ```promql
    max by (dimension_InstanceId) (aws_ec2_cpuutilization_average)
    ```

    ストリームのパラメータとして設定された `X-Amz-Firehose-Common-Attributes` は、そのキーをすべてのイベントとサンプルに追加します。レコードにすでにあるフィールドが優先されます。`X-Amz-Firehose-Source-Arn` は、`region` を持たない CloudWatch Logs イベントに `region` を付与します。

    応答は Firehose 配信仕様に従います。`application/json` で、リクエストの `requestId`、`timestamp`、失敗時の `errorMessage` を含みます。読み取れないレコードは除外され、リクエストの残りは引き続き `200` で書き込まれます。一時的に失敗した書き込みは `429` または `5xx` を返し、Firehose が再試行します。64 MiB を超える本文は `413` を返し、Firehose は再試行もバックアップも行いません。書き込み後 30 分以内に同じ `X-Amz-Firehose-Request-Id` で再試行された配信は、再度書き込まずに `200` を返します。
  </Tab>
  <Tab title="Google Cloud Pub/Sub">
    `kind: "gcp_pubsub_push"` でコネクタを作成します。Log Router シンクを使用してログを Pub/Sub トピックにルーティングし、そのトピックにプッシュサブスクリプションを作成します。Pub/Sub はカスタムヘッダーを設定できないため、トークンは URL で送信します:

    ```bash
    gcloud pubsub subscriptions create molesignal-push --topic=molesignal-logs --push-endpoint="https://molesignal.example.com/api/v1/_gcp_pubsub?token=<pushToken>"
    ```

    サブスクリプションの OIDC トークンも確認するには、コネクタの `oidcServiceAccount` にサービスアカウントのメールアドレスを設定し、`--push-auth-service-account=<email>` でサブスクリプションを作成します。MoleSignal は Google の鍵に対してトークンを検証し、そのサービスアカウントのみを受け入れます。`oidcAudience` を設定するとオーディエンスも確認でき、`--push-auth-token-audience` に同じ値を渡します。

    各メッセージは 1 つのリクエストです。ラップされた本文とラップされていないペイロードの両方を受け付けます。Cloud Logging の `LogEntry` は 1 つのログイベントになります:

    | `LogEntry` | イベント |
    |---|---|
    | `jsonPayload` | そのフィールド |
    | `textPayload` | `message` |
    | `protoPayload`（監査ログ） | `proto_payload`。`method_name`、`service_name`、`principal_email` はそこから取り出されます |
    | `severity` | `level`（小文字化） |
    | `logName`、`resource.type`、`insertId` | `log_name`、`resource_type`、`insert_id` |
    | `resource.labels`、`labels` | それぞれの名前のフィールド |
    | `trace`、`spanId` | `projects/<id>/traces/` プレフィックスを除いた `trace_id`、`span_id` |
    | `httpRequest` | `http_request` |
    | `timestamp` | イベントの時刻。ない場合は `receiveTimestamp` または公開時刻 |

    その他のメッセージデータは 1 つのイベントになります。JSON オブジェクトのフィールド、またはテキストが `message` になります。エンドポイントは `204 No Content` を返し、Pub/Sub はこれを確認応答として扱います。読み取れないメッセージは確認応答して除外します。一時的に失敗した書き込みは確認応答しないため、Pub/Sub が再配信します。書き込み後 30 分以内に再配信されたメッセージは、再度書き込まずに確認応答します。
  </Tab>
  <Tab title="クラウドイベントバス">
    `kind: "cloud_events"` でコネクタを作成し、イベントバスを `https://molesignal.example.com/api/v1/_cloud_events` に向けます:

    | 送信元 | 設定 |
    |---|---|
    | Amazon EventBridge | **API キー** 接続を使用する API 送信先。ヘッダー名は `X-Connector-Token`、値はプッシュトークンです。 |
    | Azure Event Grid | エンドポイントが `?token=<pushToken>` で終わる Webhook サブスクリプション。検証ハンドシェイクと CloudEvents スキーマの `OPTIONS` ハンドシェイクには自動で応答します。 |
    | Alibaba Cloud EventBridge | プッシュトークンをトークンとする HTTPS ターゲット。`X-EventBridge-Signature-Token` として送信されます。 |
    | Huawei Cloud EventGrid | `X-Connector-Token` ヘッダーを付ける Webhook ターゲット。 |
    | その他の CloudEvents 送信元 | 上記のいずれかのトークン方式。`https://user:<pushToken>@host/...` のように認証情報をアドレスにしか含められない送信元も受け付けます。 |

    本文には 1 つのイベントまたはイベントの配列が含まれます。形式は、structured モードまたは binary モードの CloudEvents 1.0、Amazon EventBridge イベント、または Event Grid スキーマです。各イベントは `targetStream`（デフォルトは `cloud_events`）内の 1 つのログイベントになります:

    | フィールド | 取得元 |
    |---|---|
    | `event_id`、`event_source`、`event_type`、`event_subject` | CloudEvents の `id`、`source`、`type`、`subject`；EventBridge の `id`、`source`、`detail-type`；Event Grid の `id`、`topic`、`eventType`、`subject` |
    | `account_id`、`region` | EventBridge の `account`、`region`；Alibaba Cloud の `aliyunaccountid`、`aliyunregionid`；Event Grid トピックのサブスクリプション |
    | `resources` | EventBridge の `resources` |
    | `data` | 1 つの JSON フィールドとしてのペイロード。テキストペイロードは `message` に入ります |
    | `event_format` | `cloudevents`、`eventbridge`、または `event_grid` |

    拡張属性は名前を保持します。イベント自身の時刻がその時刻になります。その他の JSON オブジェクトは、そのフィールドをそのまま持つ 1 つのイベントになります。同じ送信元と ID で 30 分以内に再配信されたイベントは、二重に書き込まれません。エンドポイントは `200` を返し、JSON でない本文には `400` を返します。
  </Tab>
  <Tab title="Cloudflare Logpush">
    `kind: "cloudflare_logpush"` でコネクタを作成し、HTTP 送信先を使用する Logpush ジョブを作成します。Cloudflare は `header_` クエリパラメータをリクエストヘッダーに変換するため、トークンは `X-Connector-Token` で送信します:

    ```text
    https://molesignal.example.com/api/v1/_cloudflare?header_X-Connector-Token=<pushToken>
    ```

    Cloudflare は gzip 圧縮された NDJSON を送信し、各行が 1 つのイベントになります。エンドポイントは `204 No Content` を返します。
  </Tab>
  <Tab title="Heroku">
    `kind: "heroku_drain"` でコネクタを作成し、ドレインを追加します。Heroku はカスタムヘッダーを設定できないため、トークンは URL で送信します:

    ```bash
    heroku drains:add "https://molesignal.example.com/api/v1/_heroku?token=<pushToken>"
    ```

    各ログ行は `message` と `source: "heroku"` を持つイベントになります。エンドポイントは `204 No Content` を返します。
  </Tab>
</Tabs>

<Tip>
  `targetStream` は最初の配信時に作成され、スキーマは新しいフィールドが現れるたびに進化します。これは他のストリームと同じです。`targetStream` を省略すると、ソースごとのデフォルト（`kinesis`、`gcp`、`cloud_events`、`cloudflare`、または `heroku`）にフォールバックします。Firehose コネクタはメトリクスサンプルを `metricsStream` に書き込み、デフォルトは `cloudwatch` です。
</Tip>

### CloudWatch Logs

CloudWatch Logs は **プル** ソースです。MoleSignal はプッシュを受信する代わりに、30 秒ごとに `FilterLogEvents` を呼び出します。初回実行では直近 5 分間を読み取ります。以降の実行は、最後に成功した実行が終了した位置から開始するため、読み取りまたは書き込みができなかったイベントは次回の実行で再度読み取られます。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "cw-prod",
        "kind": "aws_cloudwatch_logs",
        "configJson": {
          "region": "ap-southeast-1",
          "logGroup": "/aws/lambda/checkout",
          "auth": "node_role",
          "targetStream": "cloudwatch"
        }
      }'
```

| フィールド | 備考 |
|---|---|
| `region` / `logGroup` | 必須。読み取る CloudWatch リージョンとロググループ。 |
| `auth` とそのキー | 認証情報。ロググループに対する `logs:FilterLogEvents` が必要です。[AWS 認証](#aws-認証) を参照してください。 |
| `targetStream` | 送信先ストリーム。デフォルトは `default`。 |

ノードは一度に 1 つのコネクタをポーリングします。`alert` ノードはコネクタを互いに分担し、ノードはポーリング前にコネクタを要求します。[アラートノード間の作業分担](/ja/deployment/role-based#アラートノード間の処理分担) を参照してください。各イベントは `message`、`log_stream`、`log_group` を持つログになります。オフになっているコネクタはポーリングされません。

### Kafka トピック

`kafka_source` コネクタは 30 秒ごとにトピックを読み取り、書き込み済みの最後の読み取りが終了した位置から続行します。コンシューマーグループのメンバーとしてではなく、割り当てによってパーティションを取得し、オフセットを MoleSignal 内に保持します。そのため、トピックを読み取る権限だけが必要で、クラスタ上にコンシューマーグループは表示されません。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "orders",
        "kind": "kafka_source",
        "configJson": {
          "brokers": "b-1.example.com:9096,b-2.example.com:9096",
          "topic": "orders",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "<password>",
          "targetStream": "orders",
          "startFrom": "latest"
        }
      }'
```

| フィールド | 備考 |
|---|---|
| `brokers`、`topic`、`tls`、`tlsCaCert`、`auth` とそのキー | [Kafka の送信先](#apache-kafka) と同様です。 |
| `targetStream` | 送信先ストリーム。デフォルトは `default`。 |
| `messageFormat` | `json`（デフォルト）、または Azure Monitor がイベントハブにエクスポートするデータ用の `azure_records`。後述。UI: **メッセージ形式**。 |
| `startFrom` | 最初の読み取りを開始する位置。`latest`（デフォルト）は今後到着するデータ、`earliest` はブローカーが保持するすべてのデータ。後から追加されたパーティションは先頭から読み取られます。UI: **読み取り開始位置**。 |

- 値が JSON オブジェクトのメッセージは、ログのフィールドを提供します。それ以外の値は `message` になります。各ログには `kafka_topic`、`kafka_partition`、`kafka_offset`、メッセージにキーがある場合は `kafka_key`、および `source` も含まれます。その時刻はメッセージのタイムスタンプです。
- 1 回の読み取りでは最大 10,000 メッセージまたは 32 MiB を処理し、さらにデータがある間は次の読み取りがすぐに続きます（1 回のプルで最大 2 分間）。
- オフセットはログが書き込まれた後にのみ進みます。失敗した読み取りまたは書き込みは、30 秒後に同じ位置から再試行されるため、メッセージが 2 回書き込まれることはありますが、失われることはありません。ブローカーが期限切れにしたオフセットは、まだ保持している最も古いメッセージから続行します。
- オフセットはトピックに属するため、`topic` を変更すると `startFrom` からやり直しになります。

Azure の診断設定、Log Analytics のデータエクスポート、データ収集ルールは Azure Event Hubs にエクスポートされ、Kafka ソースはハブの Kafka エンドポイントを通じて読み取ります。`brokers` は `<namespace>.servicebus.windows.net:9093`、`topic` はイベントハブ、`tls` はオン、`auth: sasl_plain` でユーザー名は `$ConnectionString`、パスワードは接続文字列です。Basic レベルには Kafka エンドポイントがありません。`messageFormat: azure_records` を指定すると、各 `{"records": [...]}` メッセージが展開されます。ログレコードはその `time` のログイベントになり、メトリクスレコードはコネクタの `metricsStream`（デフォルトは `default`）内の統計ごとに 1 つのサンプルになり、[Azure Monitor メトリクス](#クラウドメトリクス) と同じ命名になります。

### S3 オブジェクト

`s3_source` コネクタは 30 秒ごとにバケットを一覧表示し、AWS S3 または S3 互換ストアから、まだ読み取っていないオブジェクトを古い順に読み取ります。

```bash
curl -X POST http://localhost:5080/api/v1/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "name": "elb-logs",
        "kind": "s3_source",
        "configJson": {
          "bucket": "acme-logs",
          "region": "us-east-1",
          "prefix": "AWSLogs/123456789012/",
          "auth": "node_role",
          "targetStream": "elb",
          "startFrom": "latest"
        }
      }'
```

| フィールド | 備考 |
|---|---|
| `bucket`、`region`、`endpoint`、`virtualHostedStyle`、`auth` とそのキー | [S3 の送信先](#amazon-s3) と同様です。認証情報には、バケットに対する `s3:ListBucket` とオブジェクトに対する `s3:GetObject` が必要です。 |
| `prefix` | このプレフィックス配下のオブジェクトのみが読み取られます。各プルはプレフィックス全体を一覧表示するため、ソースごとに専用のプレフィックスを指定してください。 |
| `targetStream` | 送信先ストリーム。デフォルトは `default`。 |
| `startFrom` | 最初の読み取りを開始する位置。`latest`（デフォルト）は今後現れるオブジェクトとその 5 分前まで、`earliest` はプレフィックス配下のすべて。UI: **読み取り開始位置**。 |

- オブジェクトは行単位で読み取られます。JSON オブジェクトの行はログのフィールドを提供し、CloudTrail が書き込むように `Records` のみを含む行はレコードごとに 1 つのログになり、その他の行は `message` になります。`.gz` および `.zst` オブジェクトはファイル名に従って展開されます。各ログには `s3_bucket`、`s3_key`、`source` も含まれます。その時刻はオブジェクトの最終更新時刻です。
- 1 回のプルでは最大 100 オブジェクトまたは 50,000 ログまで読み取り、さらにデータがある間は次のプルがすぐに続きます（最大 2 分間）。
- 読み取り状態はログが書き込まれた後にのみ進みます。取得できないオブジェクトがあるとそこでプルが停止し、30 秒後に再試行されるため、ログが 2 回書き込まれることはありますが、失われることはありません。
- 読み取れないオブジェクトはスキップされ、コネクタ上に表示されます。再試行すると後続のすべてが滞るためです。対象は、破損している、256 MiB を超える、展開後に 512 MiB を超える、100 万ログを超える、または 64 MiB を超える行を含むオブジェクトです。
- オブジェクトはキーと更新時刻で識別され、5 分間の余裕があります。その余裕内に同じキーで再度書き込まれたオブジェクトは再読み取りされず、更新時刻が読み取り済みの最新オブジェクトより 5 分以上古いオブジェクトは読み取られません。S3 はマルチパートアップロードの日時を開始時点とするため、それより遅いアップロードは読み取られません。

### Google Cloud Pub/Sub サブスクリプション

`gcp_pubsub_pull` コネクタは 30 秒ごとに Pub/Sub サブスクリプションを読み取り、1 リクエストあたり最大 1,000 メッセージを処理し、さらにデータがある間はすぐに続行します。メッセージは書き込まれた後にのみ確認応答します。書き込みに失敗したものは確認応答の期限が切れると再配信されるため、メッセージが 2 回書き込まれることはありますが、失われることはありません。これは、1 リクエストにつき 1 メッセージを送信する [プッシュサブスクリプション](#プッシュソース) よりも多くのログを扱うのに適しています。

| フィールド | 備考 |
|---|---|
| `serviceAccountKey` | サブスクリプションに対する `roles/pubsub.subscriber` を持つサービスアカウントの JSON キーファイル。 |
| `subscription` | `projects/<project>/subscriptions/<name>`、またはキーのプロジェクト内のサブスクリプション名。確認応答の期限は 60 秒以上に設定してください。 |
| `targetStream` | 送信先ストリーム。デフォルトは `default`。 |

各メッセージはプッシュされたものと同様に読み取られます。Cloud Logging の `LogEntry` はプッシュタブのマッピングで、その他の JSON オブジェクトはそのフィールドとして、それ以外は `message` として読み取られます。**接続をテスト** は、メッセージを取得せずに、キーがサブスクリプションを消費できるかを確認します。

### クラウドメトリクス

6 つのソースが、クラウドの監視サービスのメトリクスをスケジュールに従ってプルし、メトリクスストリームに書き込みます:

| 種類 | クラウド | API | 認証 | 権限 | デフォルトの `metricsStream` |
|---|---|---|---|---|---|
| `aws_cloudwatch_metrics` | Amazon CloudWatch | `ListMetrics`、`GetMetricData` | [AWS 認証情報](#aws-認証) | `cloudwatch:ListMetrics`、`cloudwatch:GetMetricData` | `cloudwatch` |
| `azure_monitor_metrics` | Azure Monitor | Resource Graph、`metrics:getBatch` | アプリ登録の `tenantId`、`clientId`、`clientSecret` | サブスクリプション上の **Monitoring Reader** | `azure` |
| `gcp_monitoring_metrics` | Google Cloud Monitoring | `timeSeries.list` | `serviceAccountKey`（JSON キーファイル） | プロジェクト上の `roles/monitoring.viewer` | `gcp` |
| `aliyun_cms_metrics` | Alibaba Cloud CloudMonitor | `DescribeMetricList` | `accessKey`、`secretKey` | `AliyunCloudMonitorReadOnlyAccess` | `aliyun` |
| `tencent_monitor_metrics` | Tencent Cloud Monitor | `GetMonitorData` | `accessKey`（SecretId）、`secretKey`（SecretKey） | `QcloudMonitorReadOnlyAccess`、および CVM インスタンスを検出するための `QcloudCVMReadOnlyAccess` | `tencentcloud` |
| `huawei_ces_metrics` | Huawei Cloud Eye | `ListMetrics`、`BatchListMetricData` | `accessKey`（AK）、`secretKey`（SK） | `CES ReadOnlyAccess` | `huaweicloud` |

各プルは、少なくとも `delay` 秒前に終了した `period` 秒の期間全体を、最後に書き込まれたプルが終了した位置から読み取ります。クラウドは期間終了後数分で集計を完了し、各期間は 1 回だけ読み取られます。後から修正された値は読み取られたままになります。新しいコネクタは 1 期間前から開始します。1 回のプルは最大 12 期間を読み取り、次のティックで続行します。6 時間を超えてオフだったコネクタは、それより古いデータをスキップし、その旨を表示します。

各シリーズの各統計は、期間の開始時点で `<cloud>_<namespace>_<metric>_<statistic>` という名前の 1 つのゲージサンプルになります。命名は yet-another-cloudwatch-exporter が CloudWatch メトリクスを命名する方法に従います:

| ソース | 例 | ラベル |
|---|---|---|
| CloudWatch | `aws_ec2_cpuutilization_average` | `region`、`dimension_<Name>` |
| Azure Monitor | `azure_compute_virtualmachines_percentage_cpu_average` | `subscription_id`、`resource_group`、`resource_name`、`resource_id`、`region`、`dimension_<name>`、`tag_<key>` |
| Cloud Monitoring | `gcp_compute_instance_cpu_utilization_mean` | `project_id`、`resource_type`、リソースとメトリクスのラベル |
| CloudMonitor | `aliyun_ecs_dashboard_cpuutilization_average` | `region`、`user_id`、`dimension_<key>` |
| Tencent Cloud Monitor | `tencentcloud_cvm_cpu_usage_avg` | `region`、`dimension_<Name>` |
| Cloud Eye | `huaweicloud_sys_ecs_cpu_util_average` | `region`、`dimension_<name>` |

これらは [Firehose 経由の CloudWatch メトリクスストリーム](#プッシュソース) が書き込む名前と同じであるため、PromQL は両方に対して機能します:

```promql
max by (dimension_InstanceId) (aws_ec2_cpuutilization_average)
```

| フィールド | ソース | 備考 |
|---|---|---|
| `metricsStream` | すべて | 送信先のメトリクスストリーム。 |
| `period` | すべて | 秒単位、分単位の整数。デフォルトは 300。Azure は 60、300、900、1800、3600、21600、43200、または 86400。Huawei Cloud は 300、1200、3600、14400、または 86400。 |
| `delay` | すべて | 期間終了後、読み取るまでの秒数。CloudWatch と Azure のデフォルトは 600、その他は 300。 |
| `region` | Google Cloud 以外のすべて | `us-east-1`、`eastus`、`cn-hangzhou`、`ap-guangzhou`、`cn-north-4` など。 |
| `namespace` | CloudWatch、CloudMonitor、Tencent Cloud、Cloud Eye | `AWS/EC2`、`acs_ecs_dashboard`、`QCE/CVM`、`SYS.ECS` など。 |
| `metrics` | すべて | メトリクス名。カンマ区切りまたは行区切り。CloudWatch 以外は必須。CloudWatch は空の場合、直近 3 時間にデータがあった名前空間のすべてのメトリクスを最大 2,000 シリーズまで読み取ります。Google Cloud は `compute.googleapis.com/instance/cpu/utilization` などのメトリクスタイプを受け取ります。 |
| `statistics` | CloudWatch、CloudMonitor、Tencent Cloud、Cloud Eye | CloudWatch: `Average`、`Sum`、`Minimum`、`Maximum`、`SampleCount`、および `p99` などのパーセンタイル。デフォルトは `Average`、`Maximum`。CloudMonitor: `Average`、`Maximum`、`Minimum`、`Sum`。デフォルトは `Average`、`Maximum`。Tencent Cloud: `avg`、`max`、`min`。デフォルトは `avg`。Cloud Eye: `average`、`max`、`min`、`sum`、`variance`。デフォルトは `average`。 |
| `subscriptionId`、`resourceType`、`aggregations`、`filter`、`top` | Azure | リソースの種類はメトリクスの名前空間でもあります（`Microsoft.Compute/virtualMachines` など）。集計: `average`（デフォルト）、`minimum`、`maximum`、`total`、`count`。`filter` はディメンションで分割します（`LUN eq '*'` など）。`top` は分割後のシリーズ数の上限で、デフォルトは 100。 |
| `projectId`、`filter` | Google Cloud | プロジェクトのデフォルトはキーのプロジェクトです。`filter` は各メトリクスのフィルタに追加される句です。ゲージは `mean`、デルタは `sum`、カウンターは `rate`、ディストリビューションは `count` と `mean` として読み取られます。 |
| `dimensions` | CloudMonitor | `Dimensions` として渡す任意の JSON。空の場合はアカウントのすべてのインスタンスを読み取ります。 |
| `instances` | Tencent Cloud | 1 行につき 1 インスタンスを `Name=Value` で指定し、複数のディメンションは `&` で結合します。`QCE/CVM` 以外は必須。`QCE/CVM` は空の場合、リージョン内のインスタンスが検出されます。 |
| `projectId` | Cloud Eye | リージョンのプロジェクト。 |

すべてのクエリはクラウドによって課金されます。CloudWatch は各シリーズの各統計を 1 メトリクスリクエストとして課金し、Google Cloud は返されたシリーズで課金し、その他は無料の月間クォータを超えた API 呼び出しで課金されます。`metrics` と `statistics` は必要なものだけにし、`period` を長くするとコストが下がります。**接続をテスト** は保存済みの設定で 1 つの小さなリクエストを行い、何も移動しません。

<Tip>
  リポジトリの `deploy/cloud` ディレクトリには、クラウド側を設定するテンプレートがあります。Firehose ストリーム、メトリクスストリーム、CloudWatch Logs サブスクリプションを含む CloudFormation スタック、Log Router シンクと Pub/Sub サブスクリプションを含む Terraform モジュール、Kafka ソースが読み取る Event Hubs 名前空間を含む Bicep ファイルです。
</Tip>

### プルの進行状況

コネクタのページには、ソースが最後に受信した時刻が表示されます。最後の読み取りに失敗したソースには、その横に警告が表示され、理由はツールチップとコネクタの設定に表示されます。また、ソースが最後にスキップした内容もそこに表示されます。値がフィールドの型に合わないためにストリームが拒否したイベントは再送されません。ソースは次に進み、プッシュエンドポイントは引き続き成功を返します。プラットフォームがリクエスト全体を再送するためです。コネクタが最後にスキップした内容には、拒否されたイベント数と最初の理由が表示されます。API では、`readState` に `lastError` と `lastWarning`（それぞれ `atTime` と `text` を含む）および `position`（どこまで進んだか）が保持されます。コネクタを保存しても、その位置は残ります。

## 送信先

送信先は、スケジュールされたパイプラインの各ステップを通過したすべてのイベントを受信します。**送信先を追加 → コネクター** を使用して、フローの **送信先** にコネクターを追加します。配信に失敗した場合は実行内で再試行され、それでもコネクターが受け取らないイベントはデッドレターストリームに送られます。詳細は [再試行とデッドレター](/ja/pipelines#再試行とデッドレター) を参照してください。

オフになっている送信先は何も受信しません。各実行ではコネクターがスキップされ、実行の `warning` にその名前が記録されます。スキップされたイベントは失敗としてカウントされず、デッドレターにもならず、コネクターを再びオンにしても送信されません。エディターでは、オフのコネクターは **オフ** と表示されます。

| 種類 | ペイロード |
|---|---|
| `s3` | バッチごとに 1 つの JSON Lines オブジェクトを `s3://<bucket>/<prefix><id>.jsonl` に `PUT` します。 |
| `kafka` | トピック上のイベントごとに 1 つのメッセージを送信し、イベントをその JSON ペイロードとして含めます。 |
| `http` | バッチを 1 つのリクエストで、大きい場合は複数のリクエストで、NDJSON または 1 つの JSON 配列として送信します。 |

### Amazon S3

`s3` の種類では、MinIO、Cloudflare R2、Alibaba Cloud OSS などの S3 互換ストレージにも配信できます。エンドポイントを設定するには、UI で **S3 互換ストレージ** をオンにします。

| フィールド | 備考 |
|---|---|
| `bucket` | 必須です。 |
| `region` | バケットのリージョンです。S3 互換ストアでは不要な場合があります。 |
| `prefix` | オブジェクト名は `<prefix><id>.jsonl` になります。先頭の `/` は削除され、末尾の `/` が追加されます。 |
| `endpoint` | S3 互換ストアの S3 API アドレスで、`http://` または `https://` で始まります。 |
| `virtualHostedStyle` | `true` の場合はバケットをパスではなくホスト名として指定します。これは Alibaba Cloud OSS などのストアで必要です。UI: **バケット名をホスト名に含める**。 |
| `auth` とそのキー | 認証情報です。バケットに対する `s3:PutObject` 権限が必要です。詳細は [AWS 認証](#aws-認証) を参照してください。 |

### Apache Kafka

| フィールド | 備考 |
|---|---|
| `brokers` | 必須です。ホストとポートを指定し、複数はカンマで区切ります。 |
| `topic` | 必須です。 |
| `tls` | `true` にすると TLS で接続を暗号化します。ブローカーの TLS ポート（多くの場合 9093、9094、9096）に接続します。UI: **TLS で接続を暗号化**。 |
| `tlsCaCert` | ブローカーの証明書を発行したプライベート CA の PEM 証明書です。`tls` を指定した場合のみ使用します。指定しない場合、システムの CA が信頼されます。 |

| `auth` | UI | キー | 備考 |
|---|---|---|---|
| `none` | **なし** | | 認証情報を要求しないブローカー向けです。 |
| `sasl_plain` | **SASL/PLAIN** | `saslUsername`, `saslPassword` | パスワードをそのまま送信します。TLS を使用しない場合は、プライベートネットワークでのみ使用してください。 |
| `sasl_scram_sha_256` | **SCRAM-SHA-256** | `saslUsername`, `saslPassword` | パスワード自体がネットワークを通過することはありません。 |
| `sasl_scram_sha_512` | **SCRAM-SHA-512** | `saslUsername`, `saslPassword` | Amazon MSK が使用するメカニズムです。 |
| `mtls` | **クライアント証明書** | `tlsClientCert`, `tlsClientKey` | 相互 TLS です。`tls` が必要です。どちらも PEM 形式で、秘密鍵は暗号化できません。 |

TLS と SASL は組み合わせて使用できます。TLS 経由の SCRAM は `SASL_SSL` として接続します。

### HTTP / Webhook

| フィールド | 備考 |
|---|---|
| `url` | 必須です。`http://` または `https://` の絶対 URL です。URL にはパスやクエリ内のキーなど認証情報が含まれることが多いため、シークレットとして保持されます。応答には `urlOrigin`（スキーム、ホスト、ポート）のみが表示されます。URL 内のユーザー名とパスワードは拒否されます。`basic` を使用してください。 |
| `method` | `post`（デフォルト）または `put` です。 |
| `format` | `ndjson`（デフォルト）は 1 イベントを 1 行として `application/x-ndjson` で送信します。`json` は 1 つの JSON 配列を `application/json` で送信します。 |

| `auth` | UI | キー | リクエスト |
|---|---|---|---|
| `none` | **なし** | | 認証情報なし。 |
| `bearer` | **Bearer トークン** | `bearerToken` | `Authorization: Bearer <token>` |
| `basic` | **Basic 認証** | `basicUsername`, `basicPassword` | HTTP Basic 認証です。`https` 経由で使用してください。 |
| `header` | **カスタムヘッダー** | `headerName`, `headerValue` | 指定したヘッダーに値を設定します（例: `X-API-Key`、`DD-API-KEY`）。 |
| `hmac` | **HMAC 署名** | `hmacSecret` | 本文の署名です。シークレットは 16 文字以上必要です。 |

カスタムヘッダーには、配信時に自動設定されるヘッダー（`Host`、`Content-Type`、`Content-Length`、`Content-Encoding`、`Transfer-Encoding`、`Connection`、`X-MoleSignal-Timestamp`、`X-MoleSignal-Sign`）を指定できません。

配信は次のルールに従います。

- 4 MiB を超えるバッチは複数のリクエストに分割されます。それを超えるイベントは単独のリクエストで送信されます。
- 任意の `2xx` ステータスは配信済みとして扱われます。それ以外のステータスは配信失敗となり、リダイレクトも同様です。リダイレクトは追跡されません。
- リクエストは 30 秒でタイムアウトします。
- MoleSignal はリクエスト前にホストを解決し、解決したアドレスにのみ接続します。クラウドメタデータサービスが応答するアドレスは、URL に含まれる場合も DNS から返される場合も拒否されます: `169.254.0.0/16`、`fe80::/10`、`fd00:ec2::254`、`100.100.100.200`。その他のプライベートアドレスは許可されます。

#### HMAC 署名を検証する

`hmac` の場合、すべてのリクエストに 2 つのヘッダーが付与されます:

| ヘッダー | 内容 |
|---|---|
| `X-MoleSignal-Timestamp` | リクエスト時刻を Unix 秒で表したものです。 |
| `X-MoleSignal-Sign` | `sha256=<hex>` 形式で、共有シークレットを使用した `<timestamp>.<body>` の HMAC-SHA256 です。 |

リクエストを検証するには、同じシークレットを使用して、タイムスタンプ、`.`、および生の本文バイト列を連結したデータの HMAC-SHA256 を計算し、結果を署名と定数時間で比較します。数分より古いタイムスタンプは拒否し、キャプチャされたリクエストを後から再送できないようにします。

```python
import hashlib
import hmac
import time


def verify(secret: bytes, timestamp: str, signature: str, body: bytes, tolerance: int = 300) -> bool:
    if abs(time.time() - int(timestamp)) > tolerance:
        return False
    signed = timestamp.encode() + b"." + body
    expected = "sha256=" + hmac.new(secret, signed, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## AWS 認証

S3 と CloudWatch Logs は、次の 5 つの方法のいずれかで AWS に認証します:

| `auth` | UI | キー | 認証情報 |
|---|---|---|---|
| `access_key` | **アクセスキー** | `accessKey`、`secretKey` | IAM ユーザーの長期キー。 |
| `temporary_key` | **一時キー** | `accessKey`、`secretKey`、`sessionToken` | AWS STS が発行する短期キーで、セッショントークンと組み合わせた場合にのみ有効です。有効期限が切れる前に更新してください。 |
| `node_role` | **ノード ID** | | MoleSignal が実行されているノードの ID。キーは保存されません。 |
| `assume_role` | **ロールの引き受け** | `roleArn`、任意で `accessKey` と `secretKey` | 組織の外部 ID を使って AWS STS 経由で引き受けるロール。 |
| `web_identity` | **ウェブ ID** | `roleArn` | ノードのウェブ ID トークンで引き受けるロール。 |

`auth` を指定しない場合は、保存されているキーで決まります。アクセスキーは `access_key`、`roleArn` は `assume_role`、どちらもなければ `node_role` として扱われます。`roleArn` の形式は `arn:aws:iam::<account>:role/<name>` です。

### ノード ID

`node_role` は、AWS SDK がノード上で見つける ID を使用します。EKS のサービスアカウント用 IAM ロール (IRSA) または EKS Pod Identity、ECS タスクロール、EC2 インスタンスプロファイルなどです。ノードの環境にある `AWS_ACCESS_KEY_ID` などの静的キーがコネクターに使われることはありません。

<Warning>
  ノードの ID とそのウェブ ID トークンはデプロイに属します。デプロイ内のすべての組織が `node_role` と `web_identity` を選択できるため、ノードの ID が到達できるものすべてと、ノードのトークンを信頼するすべてのロールが、すべての組織のコネクターに開かれています。すべての組織が持ってよい権限だけを付与してください。
</Warning>

### ロールの引き受け

`assume_role` は AWS STS にロールの 1 時間有効なキーを要求し、有効期限の 5 分前にキーを更新します。ロールを引き受けるためのベース認証情報はノードの ID です。AWS 上で実行されないデプロイでは、**ノードの ID ではなくアクセスキーでロールを引き受ける** を選択し、IAM ユーザーのキーを入力します。

すべての組織は、変更できない独自の外部 ID `molesignal-<organization ID>` でロールを引き受けます。フォームでは **外部 ID** の下に表示され、`GET /api/v1/connectors/aws-external-id` で取得できます。ロールの信頼ポリシーで外部 ID を必須にしてください。そうすれば、ARN を知った他の組織がロールを引き受けることはできません:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "<ARN of the node role or IAM user>" },
      "Action": "sts:AssumeRole",
      "Condition": { "StringEquals": { "sts:ExternalId": "molesignal-<organization ID>" } }
    }
  ]
}
```

セッション名は `molesignal-<connector ID>` で、AWS CloudTrail にもこの名前で表示されます。リクエストはコネクターの `region` のリージョン STS エンドポイントに送られます。リージョンが空の場合は `us-east-1`、中国リージョンの場合は `amazonaws.com.cn` ドメインです。

### ウェブ ID

`web_identity` は、ノードの `AWS_WEB_IDENTITY_TOKEN_FILE` が示すパスのウェブ ID トークンでロールを引き受けます。たとえば EKS が IRSA 用に投影するサービスアカウントトークンです。コネクターが別のファイルを指定することはできません。ロールの信頼ポリシーは、トークンを発行する OIDC プロバイダーを信頼している必要があります。`AWS_WEB_IDENTITY_TOKEN_FILE` がないノードでは、コネクターに認証情報はありません。

トークンは、コネクターの `region` のリージョン STS エンドポイント、またはノードの環境で `AWS_ENDPOINT_URL_STS` が設定されている場合はそのエンドポイントで交換されます。IRSA に由来するノード ID も同様です。

## 接続をテスト

**接続をテスト** は、保存前のフォームのままの設定を試します。空のままのシークレットは保存済みのものが使われます。各 kind は、配信または取得が機能することを証明する最小限の処理を行います:

| kind | テスト |
|---|---|
| `s3` | プレフィックスの下にオブジェクト `.molesignal-connection-test` を書き込み、ポリシーが許可していれば削除します。 |
| `kafka` | ブローカーからトピックのメタデータを読み取ります。これにより接続、TLS、認証、およびトピックの存在が確認されます。メッセージは書き込みません。 |
| `http` | テストとしてマークされたイベントを 1 つ送信します: `"message": "MoleSignal connection test"` と `"molesignal_connection_test": true`。 |
| `aws_cloudwatch_logs` | ロググループの直近 1 分間のイベントを最大 1 つ読み取ります。ストリームには何も書き込まず、読み取り位置もそのままにします。 |
| `kafka_source` | `kafka` と同様に、ブローカーからトピックのメタデータを読み取ります。メッセージは読み取らず、読み取り位置もそのままにします。 |
| `s3_source` | プレフィックスの下のオブジェクトを 1 つ一覧表示し、認証情報と `s3:ListBucket` を確認します。何も読み取らず、読み取り位置もそのままにします。 |

テストは 25 秒でタイムアウトします。API では、`POST /api/v1/connectors/test` に試す `kind` と `configJson` を渡します。同じ kind の保存済みコネクターの `id` を指定すると、`***` はそのコネクターが保持するシークレットを表します。動作しない設定は、保存時と同様に `400` を返します。

```bash
curl -X POST http://localhost:5080/api/v1/connectors/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
        "id": "<connector id>",
        "kind": "kafka",
        "configJson": {
          "brokers": "b-1.example.com:9096",
          "topic": "logs",
          "tls": true,
          "auth": "sasl_scram_sha_512",
          "saslUsername": "molesignal",
          "saslPassword": "***"
        }
      }'
```

```json
{ "ok": true, "code": "ok", "detail": null, "elapsedMs": 412 }
```

`elapsedMs` はテストにかかった時間です。失敗したテストは `code` に原因を示し、`detail` には相手側のメッセージが最大 600 文字まで入ります:

| `code` | 意味 |
|---|---|
| `ok` | 接続しました。 |
| `invalid` | 設定が動作しない、またはコネクターがプッシュソースであり、接続先がありません。 |
| `no_credentials` | AWS 認証情報を取得できませんでした。ノードに ID がないか、要求された種類の ID がありません。 |
| `denied` | 相手側が認証情報、または認証情報に許可された操作を拒否しました。 |
| `not_found` | バケット、トピック、ロググループ、またはアドレスが存在しません。 |
| `tls` | TLS ハンドシェイクに失敗しました。証明書が信頼されていないか、提示されていません。 |
| `unreachable` | ホストを解決できなかったか、接続できませんでした。 |
| `timeout` | 時間内に応答がありませんでした。 |
| `failed` | その他の失敗。 |

## API

| エンドポイント | 権限 | 目的 |
|---|---|---|
| `GET /api/v1/connectors` | `pipelines.read` | 組織のコネクターを一覧表示します。 |
| `POST /api/v1/connectors` | `pipelines.edit` | コネクターを作成します。`enabled` の既定値は `true` です。 |
| `GET /api/v1/connectors/{id}` | `pipelines.read` | コネクターを取得します。 |

## 権限

`pipelines.read` はコネクターの一覧表示と参照、外部 ID の読み取りを行います。`pipelines.edit` はコネクターの作成、更新、削除、テストを行います。テストは保存済みのシークレットを使い、呼び出し元に代わって別のシステムに接続するため、`pipelines.edit` が必要です。プッシュレシーバーはプッシュトークンで認証し、通常のログイン JWT で代用することはできません。
