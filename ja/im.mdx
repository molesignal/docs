Mole Agent は、通知設定のコネクターを通じて Feishu、Slack、DingTalk、WeCom、Google Chat、Microsoft Teams、Telegram で回答します。グループでメンションするか、ダイレクトメッセージを送信してください。回答を作成している間、Feishu、Slack、Telegram ではメッセージにリアクションを付けます。WeCom、Google Chat、Teams では、まず「確認中です…」と返信し、回答ができたらその返信を置き換えます。回答には MoleSignal のチャットへのリンクが含まれます。

これらのチャットは、通常の Mole Agent チャットと同じです。MoleSignal に表示され、そこで会話を続けられます。利用分は組織の 1 日あたりの予算に計上され、回答はほかの回答と同様に評価されます。[品質](/ja/quality)を参照してください。

## メッセージの受信方法

| プラットフォーム | コネクター | メッセージの受信方法 |
|---|---|---|
| Feishu | Feishu アプリ (`lark_app`) | Feishu の常時接続 |
| Slack | Slack アプリ (`slack_app`) | ソケットモード |
| DingTalk | DingTalk アプリ (`dingtalk_app`) | ストリームモード |
| WeCom | WeCom スマートボット (`wecom_bot`) | スマートボットの常時接続 |
| Google Chat | Google Chat アプリ (`google_chat_app`) | Cloud Pub/Sub サブスクリプションから取得 |
| Telegram | Telegram ボット (`telegram_bot`) | Telegram Bot API のロングポーリング |
| Microsoft Teams | Microsoft Teams ボット (`teams_app`) | Bot Framework が MoleSignal の公開コールバックアドレスに送信 |

Teams 以外では、1 台の MoleSignal サーバーが各コネクターに外向きに接続してメッセージを受信するため、MoleSignal に公開アドレスは不要です。Teams には公開 HTTPS コールバックアドレスが必要です。先に [Teams のセキュリティ](#teams-のセキュリティ)を確認してください。各プラットフォームに必要なアドレス、アカウント、権限については、[外部サービスの前提条件](#外部の前提条件)を参照してください。

## 始める前に

- 有効化には `agent.im.manage` が必要です。Mole Agent に質問するには `agent.use` が必要です。
- **設定 → 通知 → コネクター** で、対象プラットフォームのコネクターを設定してください（上の表を参照）。Slack アプリにはボットトークンとアプリレベルトークンが、Google Chat アプリには Pub/Sub サブスクリプションが必要です。[通知チャネル](/ja/notification-channels)を参照してください。
- 各自でアカウントを連携できるようにし、返信にチャットへのリンクを含めるには、MoleSignal の外部 URL（`http.external_url`）を設定してください。Teams の場合は、コールバックアドレスがこの URL の配下にあるため、HTTPS の URL を設定してください。[構成](/ja/configuration)を参照してください。

## プラットフォームを設定する

### Feishu

<Steps>
  <Step title="常時接続でイベントを受信する">
    Feishu の開発者コンソールでアプリを開き、**イベントとコールバック**に移動して、常時接続でイベントを受信する設定を選択します。
  </Step>
  <Step title="メッセージをサブスクライブする">
    **メッセージ受信**イベント（`im.message.receive_v1`）を追加します。
  </Step>
  <Step title="常時接続でコールバックを受信する">
    **イベントとコールバック → コールバック設定**で、常時接続でコールバックを受信する設定を選択し、カードアクションのコールバック（`card.action.trigger`）を追加します。アラートカードのボタンを使用するには、このコールバックが必要です。[アラートカード](#アラートカード)を参照してください。
  </Step>
  <Step title="権限を付与する">
    アプリに、直接送信されたメッセージとアプリへのメンションを含むグループメッセージの読み取り、アプリとしてのメッセージ送信、メッセージへのリアクションの追加を許可します。毎回ボットをメンションせずにスレッドで会話を続けるには、すべてのグループメッセージの読み取りも許可します。
  </Step>
  <Step title="公開する">
    アプリのバージョンを公開し、応答させるグループにボットを追加します。
  </Step>
</Steps>

Lark を使用する場合は、コネクターの**プラットフォーム**に **Lark** を選択します。

### Slack

<Steps>
  <Step title="アプリレベルトークンを作成する">
    **基本情報 → アプリレベルトークン**で、`connections:write` スコープを持つトークンを生成します。生成したトークン（`xapp-` で始まる文字列）をコネクターの**アプリレベルトークン**に入力します。
  </Step>
  <Step title="ソケットモードを有効にする">
    **ソケットモード**で、ソケットモードを有効にします。
  </Step>
  <Step title="インタラクティビティを有効にする">
    **インタラクティビティとショートカット**で、**インタラクティビティ**を有効にします。ソケットモードでは、リクエスト URL を入力する必要はありません。アラートカードのボタンを使用するには、この設定が必要です。[アラートカード](#アラートカード)を参照してください。
  </Step>
  <Step title="イベントをサブスクライブする">
    **イベントのサブスクリプション → ボットイベントをサブスクライブ**で、`app_mention` と `message.im` を追加します。毎回ボットをメンションせずにスレッドで会話を続けるには、`message.channels` と `message.groups` も追加します。
  </Step>
  <Step title="ボットのスコープを追加する">
    **OAuth と権限**で、`app_mentions:read`、`chat:write`、`im:history`、`reactions:write` を追加します。スレッドで返信できるように、`channels:history` と `groups:history` も追加します。**アプリホーム**で、アプリへのメッセージ送信を許可します。アプリを再インストールし、応答させるチャンネルにボットを招待します。
  </Step>
</Steps>

### DingTalk

<Steps>
  <Step title="Stream でロボットのメッセージを受信する">
    DingTalk の開発者コンソールでアプリのロボットを開き、メッセージ受信モードを**Stream モード**に設定します。
  </Step>
  <Step title="公開する">
    ロボットを公開し、応答させるグループに追加します。
  </Step>
</Steps>

コネクターの**クライアント ID**と**クライアントシークレット**には、アプリの認証情報を使用します。ロボットに専用のロボットコードがない場合は、クライアント ID がロボットコードになります。

### WeCom

WeCom では、Mole Agent がスマートボットとして応答します。API モードの常時接続でメッセージを受信し、同じ接続で返信します。

<Steps>
  <Step title="スマートボットを作成する">
    WeCom の管理コンソールまたはクライアントでスマートボットを作成し、**API モード**を選択して、**常時接続**でメッセージを受信するように設定します。ボットの**ボットID**と、常時接続用に発行された**シークレット**を控えます。
  </Step>
  <Step title="コネクターを作成する">
    **設定 → 通知 → コネクター**で、**ボットID**と**常時接続用シークレット**を指定して、**WeCom スマートボット**コネクターを作成します。常時接続のアドレスは `wss://openws.work.weixin.qq.com` に固定されています。
  </Step>
  <Step title="グループに追加する">
    応答させるグループにボットを追加するか、ボットに直接メッセージを送信できるようにします。
  </Step>
</Steps>

- 1 つのボットが同時に使用できる常時接続は 1 つです。別の MoleSignal インスタンスやテスト環境などが同じボットIDで接続すると、MoleSignal の接続が切断され、ステータスに**接続できません**とその理由が表示されます。環境ごとに専用のボットを用意してください。
- ボットは、常時接続またはコールバック URL のいずれかでメッセージを受信します。コールバック URL に切り替えると、常時接続が終了します。
- ボットの作成者が組織の特権管理者の場合、メンバーのユーザー ID はメッセージに平文で含まれます。それ以外の場合は暗号化されます。管理者が暗号化されたユーザー ID を手動で紐付けるのは難しいため、Mole Agent が送信するワンタイムリンクで各メンバーがアカウントを連携するようにしてください。
- コネクターを有効にすると、ボットは通知も配信します。通知ポリシーや各メンバーの通知方法でこのコネクターを選択し、メンバーの userid に直接送信するか、チャットの chatid に送信できます。ボットが通知を送信できるのは、ボットに直接メッセージを送信したメンバーと、ボットがメンションされたチャットに限られます。アラート通知はボタン付きのテンプレートカードです。[アラートカード](#アラートカード)を参照してください。

### Google Chat

Google Chat アプリが Cloud Pub/Sub トピックにメッセージをパブリッシュし、MoleSignal がサブスクリプションからプルするため、公開アドレスは不要です。

<Steps>
  <Step title="サービス アカウントを準備する">
    Google Cloud プロジェクトで **Google Chat API** と **Cloud Pub/Sub API** を有効にします。同じプロジェクトでサービス アカウントとその JSON キーを作成し、キーをコネクターの**サービス アカウント キー**に入力します。Chat アプリはこのサービス アカウントとしてメッセージを送信し、MoleSignal はこのアカウントでサブスクリプションからメッセージをプルします。
  </Step>
  <Step title="トピックとサブスクリプションを作成する">
    Pub/Sub でトピック（例: `mole-chat`）と、そのトピックの**プル**サブスクリプション（例: `mole-chat-sub`）を作成します。サブスクリプションでサービス アカウントに **Pub/Sub サブスクライバー**ロール（`roles/pubsub.subscriber`）を付与します。
  </Step>
  <Step title="Chat にトピックへのパブリッシュを許可する">
    トピックで `chat-api-push@system.gserviceaccount.com` に **Pub/Sub パブリッシャー**ロール（`roles/pubsub.publisher`）を付与します。Chat アプリを Google Workspace アドオンとして作成した場合は、代わりに接続設定に表示されるサービス アカウントに付与します。
  </Step>
  <Step title="Chat アプリを設定する">
    **Google Chat API → 設定**で、アプリの名前とアバターを指定します。**1 対 1 のメッセージを受信する**と**スペースとグループの会話に参加する**を有効にします。**接続設定**で **Cloud Pub/Sub** を選択し、トピックの完全名 `projects/<project>/topics/mole-chat` を入力します。**公開範囲**で、アプリを使用できるユーザーを選択します。
  </Step>
  <Step title="サブスクリプションを入力する">
    コネクターの **Pub/Subサブスクリプション**に `projects/<project>/subscriptions/mole-chat-sub` を入力します。
  </Step>
</Steps>

- サブスクリプションの確認応答期限はデフォルトの 10 秒のままにします。MoleSignal はメッセージをプルするたびに確認応答を返します。
- スペースやグループの会話では、アプリへのメンションを含むメッセージだけがアプリに届きます。スレッドで会話を続けるには、アプリを再度メンションしてください。ダイレクト メッセージでは、すべてのメッセージがアプリに届きます。

### Telegram

ボットは Telegram Bot API（`getUpdates`）をロングポーリングしてメッセージを受信するため、公開アドレスは不要です。

<Steps>
  <Step title="ボットを作成する">
    Telegram で **@BotFather** に `/newbot` を送信し、ボットの名前とユーザー名を設定します。発行されたトークン（例: `123456789:AAE…`）をコピーします。
  </Step>
  <Step title="コネクターを作成する">
    **設定 → 通知 → コネクター**で **Telegram ボット**コネクターを作成し、**ボットトークン**にトークンを入力します。
  </Step>
  <Step title="メンションを受信できるようにする">
    Telegram のデフォルトのプライバシーモードでは、グループ内のボットは自分宛てのコマンドと自分のメッセージへの返信を受信しますが、通常の @メンションは受信しません。@メンションで Mole Agent に質問するには、@BotFather に `/setprivacy` を送信して**無効化**を選択するか、ボットをグループの管理者にします。
  </Step>
  <Step title="グループに追加する">
    応答させるグループにボットを追加します。
  </Step>
</Steps>

- グループでは、Mole Agent はボットへのメンションを含むメッセージ、コマンド（`/new@<bot>` または `/new`）、ボットの応答への返信に反応します。アラート通知への返信にもメンションが必要です。メンションなしでアラートについて会話しても、Mole Agent には届きません。プライベートチャットでは、すべてのメッセージが届きます。
- ボットとのプライベートチャットを開始する `/start` は、`/help` として扱われます。アカウントが未連携の場合は、連携用リンクが返されます。
- Telegram ボットがプライベートメッセージを送信できるのは、ボットとのプライベートチャットを開いて**開始**を押したユーザーに限られます。この条件を満たさず、アカウントも未連携の場合は、該当するユーザーだけに表示されるグループメッセージで連携用リンクを送信します。それもできない場合は、Mole Agent が先にプライベートメッセージを送信するよう案内します。[ユーザーアカウントを連携する](#ユーザーアカウントを連携する)を参照してください。
- Telegram はボットのメッセージを同時に 1 つの受信先にのみ配信します。ボットに Webhook が設定されている場合、MoleSignal は接続時に削除します。別のプログラムが同じボットをポーリングすると、Telegram がいずれか一方を拒否し（HTTP 409）、ステータスに**接続できません**とその理由が表示されます。環境ごとに専用のボットを用意してください。

### Microsoft Teams

Bot Framework は、Teams のメッセージを MoleSignal の公開コールバックアドレスに送信します。MoleSignal にインターネットからアクセスできる必要があるのは Microsoft Teams だけです。有効にする前に、[Teams のセキュリティ](#teams-のセキュリティ)の説明に従って外部アドレスを準備してください。

<Steps>
  <Step title="Azure Bot を準備する">
    Azure ポータルで、**シングルテナント**タイプの **Azure Bot** を作成するか、既存のボットを使用します。Microsoft Entra のアプリ登録で、そのボットのクライアントシークレットを作成します。ボットの**アプリID**、**クライアントシークレット**、**テナントID**をコネクターに入力します。
  </Step>
  <Step title="Teams チャネルを追加する">
    Azure Bot の**チャネル**で **Microsoft Teams** を追加します。
  </Step>
  <Step title="有効にしてコールバックアドレスをコピーする">
    **Mole Agent → 設定 → IM** を開き、コネクターを有効にして、**コールバック**をコピーします: `https://<external address>/api/v1/public/im/teams/<connector ID>/messages`。
  </Step>
  <Step title="メッセージング エンドポイントを設定する">
    Azure Bot の**設定**で、**メッセージング エンドポイント**にコールバックアドレスを設定します。
  </Step>
  <Step title="Teams アプリを公開する">
    Teams アプリパッケージを作成します。マニフェストの `bots` にボットのアプリIDを記載し、スコープに `personal`、`team`、`groupChat` を指定します。Teams 管理センターまたは開発者ポータルでパッケージをアップロードし、アプリを使用するユーザー、チーム、グループチャットにインストールします。
  </Step>
</Steps>

- チャネルやグループチャットでは、ボットへのメンションを含むメッセージだけがボットに届きます。同じ投稿で会話を続けるには、ボットを再度メンションしてください。個人チャットでは、すべてのメッセージがボットに届きます。
- Azure パブリッククラウドと米国政府機関向けクラウド（GCC、GCC High、DoD）の Bot Framework に対応しています。コネクターで**クラウド**を選択します。

## Teams のセキュリティ

Teams のコールバックアドレスはインターネットに公開されます。MoleSignal は、このアドレスへのすべてのリクエストを検証します。

- **すべてのリクエストに Bot Framework トークンが必要です。** このアドレスは MoleSignal のサインインを受け付けず、Bot Framework が署名した JWT のみを受け付けます。署名鍵は `login.botframework.com` の OpenID メタデータから取得し、24 時間キャッシュします。`iss` は `https://api.botframework.com` です。GCC High と DoD では、代わりに `login.botframework.azure.us` と `https://api.botframework.us` を使用します。`aud` はボットのアプリ ID です。`exp` と `nbf` の検証では、5 分間の時刻のずれを許容します。署名鍵は Teams チャネル（`msteams`）を承認している必要があります。また、トークンの `serviceUrl` はメッセージの `serviceUrl` と一致する必要があります。検証に失敗したリクエストには 401 または 403 を返し、処理しません。
- **返信先は Bot Framework に限定します。** MoleSignal は、Bot Framework のサービスアドレス（`smba.trafficmanager.net`、`*.botframework.com`、`*.teams.microsoft.com`、`*.teams.microsoft.us`）またはコネクターに設定したサービス URL にのみボットのトークンを送信します。それ以外のアドレスを指定したメッセージは拒否します。
- **コネクターと同じテナントに限定します。** コネクターのテナントにテナント ID（GUID）を指定すると、他のテナントからのメッセージは処理しません。ドメイン名や `botframework.com` を指定しても、テナントは制限されません。
- **オンのコネクターでのみアドレスが機能します。** コネクターを **IM** でオンにしていない場合、オフに切り替えた場合、または削除した場合、コールバックアドレスは 404 を返します。アドレスにはコネクターの ID のみが含まれ、シークレットは含まれません。
- **リクエストボディのサイズを制限します。** 256 KiB を超えるリクエストは拒否します。

デプロイ時には、次の対策も行います。

1. **コールバックパスのみをインターネットに公開します。** リバースプロキシまたはゲートウェイで `POST /api/v1/public/im/teams/` のみを転送し、サインインページとその他すべての API は内部ネットワークからのみアクセスできるようにします。たとえば、nginx では次のように設定します。

   ```nginx
   server {
     listen 443 ssl;
     server_name molesignal.example.com;
     # ssl_certificate and ssl_certificate_key …
     client_max_body_size 256k;

     location /api/v1/public/im/teams/ {
       limit_except POST { deny all; }
       proxy_pass http://molesignal.internal:8080;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto https;
     }

     location / {
       return 404;
     }
   }
   ```

   この外部アドレスで MoleSignal にもアクセスする場合は、ゲートウェイでその他すべてのパスへのアクセスを社内ネットワークまたは VPN に限定し、コールバックパスのみをインターネットに公開します。nginx、Kubernetes Ingress、Gateway API の完全な設定例については、[パブリックアクセス](/ja/public-access)を参照してください。
2. **https を使用します。** Teams は http に POST リクエストを送信しないため、`http.external_url` には https のアドレスを指定します。パブリック CA が発行した証明書を使用して、プロキシで TLS を終端できます。
3. **必要に応じて、接続元を制限します。** ファイアウォールやゲートウェイで、Azure のサービスタグ `AzureBotService` に含まれるアドレスからのアクセスのみをコールバックパスに許可できます。アドレスは変更されるため、Azure が公開するリストに合わせて更新してください。トークンの検証が引き続き主な防御策です。
4. **クライアントシークレットを安全に管理します。** クライアントシークレットは暗号化してコネクターに保存し、応答には含めません。定期的にローテーションし、そのたびにコネクターの設定を更新してください。ボットのアプリ登録には、必要最小限の権限のみを付与します。
5. **異常がないか監視します。** MoleSignal のログとトレースには、コールバックリクエストと拒否したトークンが記録されます。**IM** では、各コネクターが最後にメッセージを受信した時刻を確認できます。

## 外部の前提条件

各プラットフォームで必要となる、MoleSignal の外部での設定や接続要件は次のとおりです。

| プラットフォーム | MoleSignal からのアウトバウンド通信 | インバウンド通信 | プラットフォーム側の設定 |
|---|---|---|---|
| Feishu | `open.feishu.cn`（Lark の場合は `open.larksuite.com`）と、プラットフォームが返す常時接続用アドレス | なし | 自社開発アプリ、常時接続によるイベント受信、メッセージイベント、常時接続によるコールバック、権限、公開済みバージョン |
| Slack | `slack.com`、Socket Mode の WebSocket アドレス、アラートカード用の `hooks.slack.com`。GovSlack の場合は、`slack.com` と `hooks.slack.com` の代わりに `slack-gov.com` と `hooks.slack-gov.com` を使用 | なし | アプリレベルトークン、Socket Mode、インタラクティビティ、イベントサブスクリプション、ボットスコープ |
| DingTalk | `api.dingtalk.com`、`oapi.dingtalk.com`、Stream の WebSocket アドレス | なし | 内部アプリのロボットと Stream モード。アラートカードにボタンを表示するには、インタラクティブカードテンプレートとカード権限も必要 |
| WeCom | `openws.work.weixin.qq.com`（WebSocket、443） | なし | API モードで常時接続するスマートボットと、そのボット ID およびシークレット |
| Google Chat | `oauth2.googleapis.com`、`pubsub.googleapis.com`、`chat.googleapis.com` | なし | Chat API と Pub/Sub API、サービスアカウントとその JSON キー、トピックとプルサブスクリプション、サブスクライバーとパブリッシャーのロール、Chat アプリの設定 |
| Telegram | `api.telegram.org`（443） | なし | @BotFather で作成したボットとそのトークン |
| Microsoft Teams | `login.microsoftonline.com`、`login.botframework.com`、コネクターのサービス URL（Global の場合は `smba.trafficmanager.net`）。GCC High と DoD の場合は、サインイン先と Bot Framework のアドレスにそれぞれ `login.microsoftonline.us` と `login.botframework.azure.us` を使用 | Bot Framework が `https://<external address>/api/v1/public/im/teams/…`（443）にアクセス | Azure Bot、クライアントシークレット、Teams チャネル、メッセージングエンドポイント、Teams アプリパッケージ |

- ファイアウォールとアウトバウンドプロキシでは、上記のアウトバウンドアドレスへの通信を許可してください。WebSocket の常時接続（Feishu、Slack、DingTalk、WeCom）はプラットフォームに直接接続し、HTTP プロキシは使用しません。
- Teams のインバウンド通信には、パブリック DNS、パブリック CA が発行した証明書、コールバックパスのみを転送するリバースプロキシが必要です。[Teams のセキュリティ](#teams-のセキュリティ)を参照してください。
- アカウントの連携と返信内のチャットリンクには、`http.external_url` が必要です。

## 有効にする

**Mole Agent → 設定 → IM** を開きます。IM で応答できるすべてのコネクターが一覧に表示されます。

| 列 | 表示内容 |
|---|---|
| **コネクター** | コネクター、プラットフォーム、最後にメッセージを受信した時刻を表示します。Teams コネクターの下には、そのままコピーできるコールバックアドレスが表示されます。 |
| **ステータス** | **接続済み**（接続に使用しているアカウントも表示）、**接続中**、**サーバー待機中**、**接続できません**（理由も表示）、**オフ**、またはコネクターに不足している設定（Slack のアプリレベルトークンや Google Chat の Pub/Sub サブスクリプションなど）を表示します。Teams は常時接続を使用しません。**接続済み** は、ボットの認証情報が有効で、Bot Framework がメッセージを配信することを示します。 |
| **新規グループスレッド** | グループ内で開始した新規スレッドの振り分け先を表示します。**質問者の個人チャット**、またはチームを指定できます。チームが適用されるのは、質問者がそのチームのメンバーである場合のみです。 |
| **オン** | コネクターが IM で応答するかどうかを示します。Teams コネクターをオンにできるのは、`http.external_url` が https の場合のみです。 |

IM で応答するコネクターを通知設定から削除するには、先にここでオフにしてください。

## ユーザーアカウントを連携する

Mole Agent は、IM アカウントに紐づく MoleSignal ユーザーとして、そのユーザーの権限で応答します。同じコネクター上で有効かつ検証済みの通知方法を使って、アカウントを識別します。

| プラットフォーム | アカウント |
|---|---|
| Feishu | `open_id`、`user_id`、または `union_id` |
| Slack | メンバー ID |
| DingTalk | ユーザー ID |
| WeCom | スマートボットが認識するユーザー ID |
| Google Chat | ユーザー（`users/123…`）またはメールアドレス |
| Telegram | 数値のユーザー ID |
| Microsoft Teams | Teams ユーザー ID（`29:…`）または Microsoft Entra オブジェクト ID |

複数のユーザーに紐づくアカウントには応答しません。

- **ユーザー自身で連携する**: 未連携のユーザーが質問すると、Mole Agent は一度だけ使えるリンクを、ダイレクトメッセージか、Slack では質問者にのみ表示されるメッセージで送信します。MoleSignal にサインインした状態でリンクを開くと、**連携** が表示されます。**連携** を選択すると、アカウントが検証済みの通知方法として質問者に追加されます。リンクは 15 分以内に一度だけ使用できます。WeCom、Google Chat、Telegram でプライベートメッセージを送信できるのは、ボットにダイレクトメッセージを送ったことがあるユーザーのみです。Teams では、ボットがインストールされているユーザーにのみ送信できます。送信できない場合、Mole Agent は元の会話で先にダイレクトメッセージを送るよう案内し、そのダイレクトメッセージにリンクを送信します。Telegram では、まずグループ内で質問者にのみ表示されるメッセージの送信を試みます。
- **管理者が連携する**: **設定 → 通知 → ユーザールーティング** で、アカウントをメンバーに紐づけて検証します。[通知チャネル](/ja/notification-channels#ユーザーの通知方法を登録する)を参照してください。

## 質問する

グループではボットをメンションしてください。ダイレクトメッセージでは、質問をそのまま送信してください。ダイレクトメッセージでは、`/new` を実行するまで同じチャットが続きます。

| プラットフォーム | グループでのチャットの単位 |
|---|---|
| Feishu、Slack | スレッドごとに 1 つのチャットになります。返信は同じスレッドに投稿されます。 |
| Google Chat のスペース | スレッドごとに 1 つのチャットになります。返信は同じスレッドに投稿されます。やり取りを続けるにはメンションが必要です。 |
| Microsoft Teams のチャネル | 投稿ごとに 1 つのチャットになります。返信は元の投稿の下に表示されます。やり取りを続けるにはメンションが必要です。 |
| DingTalk、WeCom、Google Chat のグループ会話、Teams のグループチャット | スレッドはありません。グループ内で同じメンバーが送った質問は、そのメンバー専用の 1 つのチャットにまとまります。 |
| Telegram のグループ | フォーラムトピックごとに、同じメンバーが送った質問がそのメンバー専用の 1 つのチャットにまとまります。回答は質問への返信として投稿されます。 |

| コマンド | 動作 |
|---|---|
| `/help` | 質問の方法と、ここに掲載しているコマンドの一覧を表示します。 |
| `/new` | その場で新しいチャットを開始します。 |
| `/scope` | このスレッドのチャットが誰に属するかを表示します。 |
| `/scope <team>` | 指定したチームの新しいチャットでやり取りを続けます。チームメンバーはそのチャットを閲覧し、やり取りを続けられます。 |
| `/scope me` | 新しい個人チャットでやり取りを続けます。 |
| `/feedback 👍` または `/feedback 👎`（後ろにコメントを追加できます） | スレッド内の直前の回答を評価します。 |

`/rca INC-12` やスキルなど、その他のコマンドも MoleSignal と同じように使えます。

### スレッドのチャットの所属先

個人チャットでやり取りを続けられるのは、チャットを開始したメンバーだけです。チームチャットでは、そのチームのメンバーがやり取りを続けられます。グループの新しいスレッドでは、質問者がコネクターのチームに所属している場合はそのチームのチャットになり、所属していない場合は質問者の個人チャットになります。`/scope` を実行すると、スレッドは新しいチャットに切り替わります。それまでのメッセージは元のチャットに残ります。

## 回答時の動作

- IM からは、Mole Agent の質問に答えたり、変更を承認したりできません。Mole Agent は妥当な前提を置いて回答し、置いた前提を明示します。確認が必要な手順はスキップし、その旨を返信に記載します。スキップした手順を続けるには、リンクから MoleSignal のチャットを開いてください。
- 回答の生成には最長 15 分かかります。WeCom では「調査中…」と表示するメッセージをストリーミングで配信し、10 分以内に配信を終了する必要があります。そのため、回答に 9 分を超える時間がかかる場合は、回答を別のメッセージで送信します。
- 返信には、考えられる原因、根拠、次の手順などのセクションを含む回答を、質問者のインターフェース言語で表示します。
- Mole Agent は質問者の権限で回答を生成しますが、グループのメンバー全員が返信を閲覧できます。他のメンバーに見せたくない内容は、ダイレクトメッセージで質問してください。
- 組織が 1 日の予算を使い切ると、Mole Agent は質問に回答せず、予算を使い切ったことを通知します。

## アラートカード

このセクションでは、Mole Agent とのチャットではなく、アラート通知について説明します。以下のコネクターは、アラート通知をボタン付きのカードとして送信します。MoleSignal を開かずに、カード上でアラートを確認済みや解決済みにしたり、スヌーズしたりできます。

| コネクター | カードにボタンが表示される条件 |
|---|---|
| Feishu アプリ、Slack アプリ、WeCom スマートボット、Google Chat アプリ、Microsoft Teams ボット、Telegram ボット | **IM** でコネクターを有効にします。[有効にする](#有効にする)を参照してください |
| DingTalk アプリ | **IM** でコネクターを有効にし、**カードテンプレートID**を設定します。[DingTalk のインタラクティブカード](#dingtalk-のインタラクティブカード)を参照してください |
| WeCom アプリ | **IM** で有効にする必要はありません。アプリで**メッセージ受信**を設定します。[WeCom アプリのボタン](#wecom-アプリのボタン)を参照してください。メンバー宛ての通知にのみボタンが表示されます |
| Mattermost ボット | **IM** で有効にする必要はありません。`http.external_url` を設定し、Mattermost サーバーからその URL にアクセスできるようにします。[Mattermost ボットのボタン](#mattermost-ボットのボタン)を参照してください |

グループボット（各プラットフォームの Webhook コネクター）はボタン操作を受け取れないため、送信するアラート通知にボタンは付きません。インスタントメッセージングのテンプレートで**カードとして送信**を有効にすると、ボタンのないカードを送信します。それ以外の場合はテキストを送信します。[インスタントメッセージングのテンプレートでカードを使う](/ja/notification-channels#インスタントメッセージテンプレートのカード)を参照してください。ボタンに対応していないコネクターから個人宛てに送信するアラート通知には、代わりに[ワンタイム操作リンク](/ja/notification-channels#1-回限りのアクションリンク)が付きます。

| ボタン | 動作 |
|---|---|
| **確認済みにする** | MoleSignal 上で確認済みにしたときと同じように、アラートを引き受けます。エスカレーションが止まり、ボタンを押したメンバーが担当者になります。 |
| **解決済みにする** | アラートを終了します。 |
| **1時間スヌーズ** | 1時間は通知を送信しません。確認待ちのアラートはまず確認済みになり、1時間後に確認待ちに戻ると、担当者に再度通知します。[インシデントに対応する](/ja/alerting/incidents#インシデントを操作する)を参照してください。 |
| **すべて確認済みにする** | [通知をまとめて送信](/ja/notification-channels#通知をまとめる)したメッセージにのみ表示されます。メッセージ内で確認待ちのアラートを最大20件までまとめて確認済みにします。Telegram のカードにはこのボタンは表示されず、**MoleSignal で開く**のみが表示されます。 |
| **MoleSignal で開く** | インシデントのページを開きます。通知をまとめたメッセージからは、インシデント一覧を開きます。`http.external_url` の設定が必要です。 |

- カードに表示するボタンは、通知を送信した時点のアラートの状態に応じて変わります。確認待ちの場合は「確認済みにする」「解決済みにする」「1時間スヌーズ」、確認済みの場合は「解決済みにする」「1時間スヌーズ」が表示されます。復旧通知にはボタンが表示されません。
- ボタン操作は、IM アカウントに連携した MoleSignal ユーザーとして実行します。そのユーザーには `alerts.incidents.acknowledge` 権限が必要です。未連携のアカウントには、連携をリクエストした場合と同様に、ワンタイムリンクを個別に送信します。[メンバーのアカウントを連携する](#ユーザーアカウントを連携する)を参照してください。Telegram でボットが個別メッセージを送れない場合は、操作したメンバーだけに見えるグループメッセージでリンクを送るか、ボタン操作でボットとの個別チャットを開き、そこにリンクを送ります。WeCom アプリと Mattermost ボットは、代わりに、先にプロフィールでアカウントを通知方法として追加するよう案内します。Mattermost では、操作したメンバーだけにメッセージが表示されます。アカウントが複数のユーザーに連携されている場合は、ボタンを押しても何も変わりません。
- ボタンを押すと、カードはアラートの最新の状態を表示します。送信元の通知ポリシーのテンプレートで内容を再生成し、確認済みまたは解決済みにしたメンバーを示す行を追加して、その状態で使えるボタンだけを残します。グループ内の全員に同じカードが表示されます。操作できるボタンがなくなっても、WeCom のテンプレートカードにはボタンが1つ以上必要なため、押しても何も起きない「✓」ボタンを残します。
- Feishu と Telegram は、操作結果を操作したメンバーにトーストで表示します。Telegram で問題が発生した場合は、閉じる操作が必要な警告を表示します。他のプラットフォームでは、操作が失敗した場合に理由を伝えます。Slack、Google Chat、Mattermost では操作したメンバーだけに見えるメッセージを投稿し、Teams では操作したメンバーに1行のメッセージを表示します。DingTalk と WeCom ではダイレクトメッセージを送信します。
- ボタンのラベルには受信者のインターフェース言語を使います。グループ宛てのカードには、組織のデフォルト言語を使います。

### DingTalk のインタラクティブカード

DingTalk のカードは、インタラクティブカードテンプレートで定義したレイアウトで表示されます。MoleSignal がテンプレートの変数に値を設定し、Stream 接続を通じてボタン操作を受け取ります。

<Steps>
  <Step title="テンプレートを作成する">
    DingTalk 開発者コンソールの**カードプラットフォーム**で、**メッセージカード**のテンプレートを作成し、アプリに関連付けます。
  </Step>
  <Step title="変数を追加する">
    テキスト変数 `title`、`content`、`note`、`footer`、`open_text`、`open_url` を追加します。各アクションにも `*_text` と `*_value` を追加します。対象のアクションは `acknowledge`、`resolve`、`snooze`、`acknowledge_all` と、[承認カード](#承認カード)用の `approve`、`reject` です。
  </Step>
  <Step title="コンポーネントを配置する">
    タイトルを `title` に、Markdown の本文を `content` に、2行の小さなテキストをそれぞれ `note`（アラートを確認済みまたは解決済みにしたメンバー）と `footer`（テンプレートのフッター）にバインドします。アクションごとにボタンを追加し、ラベルを `*_text` にバインドします。`*_text` が空でない場合にのみ表示し、**コールバックリクエスト**アクションのパラメーター `value` を `*_value` にバインドします。さらに、ラベルを `open_text` にバインドし、`open_url` を開くボタンを追加します。このボタンも `open_text` が空でない場合にのみ表示します。
  </Step>
  <Step title="公開してIDを入力する">
    テンプレートを保存して公開し、その**テンプレートID**をコネクターの**カードテンプレートID**に入力します。アプリにはインタラクティブカードへの書き込み権限（`Card.Instance.Write`）が必要です。
  </Step>
</Steps>

- 個人宛てのカードは、アプリの公開範囲内にいるメンバーに送信します。グループ宛てのカードを送信するには、グループにボットを追加してください。
- テンプレートIDを設定しない場合は、従来どおり、ボタンなしの ActionCard または Markdown でアラート通知を送信します。

### WeCom アプリのボタン

WeCom アプリ（`wecom_app`）は Mole Agent のボットではないため、**IM** で有効にする必要はありません。アプリの**メッセージ受信**で MoleSignal へのコールバックを設定すると、メンバー宛てのアラート通知をボタン付きのテンプレートカードとして送信します。WeCom はアプリチャットにテンプレートカードを送信しないため、アプリチャット宛ての通知にはボタンが付きません。

<Steps>
  <Step title="API 受信を有効にする">
    WeCom 管理コンソールでアプリを開き、**メッセージ受信**の**API 受信を設定**を選択して、**トークン**と**EncodingAESKey**を生成します。
  </Step>
  <Step title="コネクターに入力する">
    生成した値をコネクターの**コールバックトークン**と**EncodingAESKey**に入力し、保存します。
  </Step>
  <Step title="コールバックURLを入力する">
    コネクターの**コールバックURL** `https://<external address>/api/v1/public/notify/<connector ID>/wecom` をコピーし、**メッセージ受信**の URL 欄に入力して保存します。WeCom はすぐにその URL にリクエストを送信して検証します。
  </Step>
</Steps>

- コールバックURLのドメインは、企業の ICP 届出に登録されている必要があります。WeCom がインターネット経由でこのパスにアクセスできるようにしてください。
- MoleSignal は署名が正しくないリクエストを拒否します。EncodingAESKey で内容を復号し、別の企業宛ての内容は無視します。
- MoleSignal は、このコネクターで検証済みの通知方法に登録されたメンバーの UserID を使って、ボタンを押したメンバーを識別します。

### Mattermost ボットのボタン

Mattermost ボット（`mattermost_bot`）は Mole Agent のボットではないため、**IM** で有効にする必要はありません。`http.external_url` を設定すると、アラート通知に「確認済みにする」「解決済みにする」「1時間スヌーズ」のボタンが付きます。ボタンを押すと、Mattermost は `https://<external address>/api/v1/public/notify/<connector ID>/mattermost?token=…` にリクエストを送信して MoleSignal を呼び出します。この URL にはコネクターのコールバックトークンが含まれ、Mattermost はクライアントに公開しません。

- リクエストは Mattermost サーバーから送信するため、サーバーが外部アドレスにアクセスできる必要があります。Mattermost は、システムコンソールの**環境 → 開発者 → 信頼されていない内部接続の許可先**（`ServiceSettings.AllowedUntrustedInternalConnections`）にホストを登録していない限り、プライベートアドレスや内部アドレスへのリクエストを拒否します。MoleSignal が内部ネットワーク上にある場合は、`http.external_url` のホストをこの設定に追加してください。
- MoleSignal は、このコネクターで有効かつ検証済みの通知方法に登録された Mattermost のユーザー名（`@` は省略可）またはユーザーIDで、ボタンを押したメンバーを識別します。識別できない場合は、先にアカウントを通知方法として追加するよう、操作したメンバーだけに見えるメッセージで案内します。
- コールバックトークンが正しくない場合、MoleSignal は 401 を返します。コネクターが無効な場合は 404 を返します。
- Webhook の投稿（`mattermost_webhook`）ではボタンを押したメンバーを識別できないため、ボタンは付きません。アラートへのリンクのみが表示されます。

## 承認カード

Mole Agent が承認を必要とする操作を提案した場合、またはインシデントの修復アクションが開始された場合、組み込みの通知ポリシー **承認が必要：承認権限を持つユーザーに通知** を通じて、リクエストを **Mole Agent の承認がリクエストされました** イベントとして送信します。通知先は `agent.approve` を持つメンバーのうち、リクエスト元のユーザーを除く最大 20 人です。各メンバーが設定した通知方法で送信します。[事前承認](/ja/alerting/remediation#事前承認)の対象となるリクエストはすぐに実行し、通知は送信しません。

ボタン付きのアラートカードに対応するコネクタ（[アラートカード](#アラートカード)を参照）では、次のボタンを備えたカードで通知します。

| ボタン | 動作 |
|---|---|
| **承認** | リクエストを承認します。Mole Agent の承認画面で承認する場合と同様に、必要な承認がそろうとすぐにリクエストを実行します。 |
| **却下** | リクエストを却下します。リクエストは実行しません。 |
| **MoleSignal で開く** | Mole Agent の承認画面を開きます。`http.external_url` の設定が必要です。 |

- ボタンを押すと、IM アカウントに紐付けられた MoleSignal ユーザーとして操作します。ユーザーの識別には、そのコネクタで検証済みの通知方法のみを使用します。操作には `agent.approve` が必要です。リクエスト元のユーザーは、そのリクエストを承認できません。未連携のアカウントには、アラートカードと同様に、1 回限り有効なリンクを個別に送信します。
- ボタンを押すと、カードからボタンが消え、リクエストの内容に加えて、承認または却下したユーザーと実行の有無が 1 行で表示されます。ボタンを押したユーザーには、操作が成功したかどうかを通知します。
- 別の場所ですでに承認または却下されたリクエストや、ボタンを押したユーザーが確認済みのリクエストは、ボタンを押しても変更されません。カードには現在の状態が表示されます。
- DingTalk のカードに 2 つのボタンが表示されるのは、テンプレートに `approve_*` と `reject_*` の変数がある場合だけです。[DingTalk のインタラクティブカード](#dingtalk-のインタラクティブカード)を参照してください。

## 制限事項

- Mole Agent はテキストメッセージとリッチテキストメッセージのテキストを読み取ります。WeCom では、音声メッセージのテキストも読み取ります。画像とファイルは読み取りません。
- コネクタを保持するサーバーが停止すると、約 1 分以内に別のサーバーが引き継ぎます。その間に送信された質問には、接続の復旧後にプラットフォームが質問を再配信した場合にのみ回答します。Teams はこの影響を受けず、コールバックを受信したサーバーが処理します。
- WeCom への返信は、ボットの接続を保持するサーバーからのみ送信できます。別のサーバーで生成が完了した回答は、接続を保持するサーバーに転送され、通常は数秒以内に届きます。
- WeCom では、会話ごとに 1 分あたり 30 件、1 時間あたり 1,000 件のメッセージを送信できます。
- Telegram のメッセージは 1 件あたり最大 4,096 文字です。この上限を超える回答は、複数のメッセージに分けて送信します。
- MoleSignal や別のカードでアラートを確認済みまたは解決済みにしても、送信済みのアラートカードは更新されません。送信済みのカードでボタンを押すと、アラートがすでに確認済みまたは解決済みであることが表示され、カードが最新の状態に更新されます。
