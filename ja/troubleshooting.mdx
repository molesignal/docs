まずプロセスログを確認します。起動失敗の原因が出力され、拒否されたリクエストの HTTP エラーボディにはメッセージが含まれます。ログレベルは `[telemetry].log_level` または `RUST_LOG` から取得します。

## 起動

| 症状 | 原因 | 対処 |
|---|---|---|
| `... password authentication failed for user` | DSN のユーザーまたはパスワードが誤っています。 | `[meta_database].dsn` を修正します。 |
| `... pool timed out while waiting for an open connection` | ノードから PostgreSQL に到達できません。 | ホスト、ポート、ファイアウォール、`sslmode` の要件を確認します。 |
| `startup_ping put: ... SignatureDoesNotMatch` | オブジェクトストアが認証情報を拒否しています。 | `access_key` と `secret_key` を確認します。`MS_OBJECT_STORE_ACCESS_KEY` と `MS_OBJECT_STORE_SECRET_KEY` で設定します。 |
| `startup_ping put: ... NoSuchBucket` | バケットが存在しません。 | バケットを作成するか、`[object_store].bucket` を修正します。 |
| `Encountered transport error` が繰り返し出力されてから終了する | エンドポイントに到達できないか、認証情報がクライアントに渡っていません。 | `endpoint`、DNS、ネットワークを確認します。認証情報は `access_key` と `secret_key` から取得する必要があります。 |
| `unknown field: found ...` | 厳格なセクションのキーの綴りが誤っているか、サポートされていません。 | キーを削除するか修正します。詳細は [設定](/ja/configuration#設定の読み込み順序) を参照してください。 |
| `MS_SELF_TELEMETRY_CLUSTER_TOKEN must be set when split-role self intake is enabled` | ロール分割されたノードのうち `intake` ロールを持たないものが、トレースキャプチャまたは自己収集が有効な状態で共有トークンなしに起動しています。 | すべてのノードに同じトークンを設定します。トレースキャプチャはデフォルトで有効なため、`[telemetry.self_collect]` を無効にするだけでは不十分です。 |
| `open Probe CA key` | `MS_CIPHER_KEY` がデータベースの暗号化に使用したキーと異なっています。 | 元のキーを復元します。詳細は [本番チェックリスト](/ja/deployment/production-checklist) を参照してください。 |
| `migration ... was previously applied but is missing in the resolved migrations` または `... has been modified` | バイナリとデータベースのバージョンが互換性のない組み合わせです。 | 一致するバージョンを実行するか、バックアップを復元します。詳細は [アップグレード](/ja/upgrade) を参照してください。 |
| `address already in use` | 別のプロセスが設定済みのポートを使用しています。 | ポートを変更します。 |
| `profiling.port and ... are both ...` | pprof リスナーが別のリスナーとポートを共有しています。 | `[profiling].port` に他のリスナーが使用していないポートを設定します。 |
| 環境変数からの設定が反映されない | 変数名にドット、二重アンダースコア、または誤記が含まれています。 | `MS_META_DATABASE_DSN` のように、パスを単一のアンダースコアで連結します。 |

## サインイン

| 症状 | 原因 | 対処 |
|---|---|---|
| `admin@example.com` と `admin` でのサインインが拒否される | データベースにすでにユーザーが存在したため root アカウントが再作成されなかったか、`root_email` と `root_password` が空でした。 | 既存のアカウントでサインインします。両方の値を設定し、空のデータベースに対して起動すると root アカウントが作成されます。 |
| パスワードリセットのメールが届かない | SMTP または `http.external_url` が設定されていません。リクエストは何も送信されずに受け付けられます。 | `[notify.smtp].host` と `[http].external_url` を設定します。 |
| サインインして `Authorization: Bearer` を送信するスクリプトが `401` を受け取る | サインインは Web UI 用のセッション Cookie を設定し、トークンを返しません。このヘッダーは API トークンのみを受け付けます。 | スクリプト用に API トークンを発行します。詳細は [API トークン](/ja/identity/tokens) を参照してください。 |
| Web UI が毎日サインインを要求する | サインインセッションは `[auth].session_ttl_secs`(24 時間) で終了します。 | `[auth].session_ttl_secs` を引き上げます。 |

## データの送信

| 症状 | 原因 | 対処 |
|---|---|---|
| `401` | トークンがないか無効であるか、ヘッダーにサインインセッショントークンが含まれています。 | デフォルトの取り込みトークンまたはサービスアカウントトークンを使用して `Authorization: Bearer <token>` を送信します。 |
| `403` | トークンに、`logs.write` などそのシグナルの書き込み権限がありません。たとえば、取り込みパスに RUM クライアントトークンが送信された場合です。 | そのシグナルの書き込み権限を持つトークンを使用します。 |
| `413` | リクエストボディがエンドポイントの上限を超えています。ネイティブ JSON 取り込みでは 16 MiB、それ以外では 2 MiB です。 | より小さなバッチで送信します。プロキシの上限をエンドポイントの上限以上に引き上げます。 |
| OTLP over HTTP エンドポイントからの `400` | 送信側がボディを圧縮しています。 | OpenTelemetry Collector のエクスポーターで `compression: none` を設定します。 |
| OTLP over HTTP エンドポイントからの `404` | エクスポーターのエンドポイントが `/api` ベースパスを省略しているため、リクエストが `/v1/logs` に送信されています。 | OTLP エンドポイントとして `http://host:5080/api` を使用します。 |
| `Retry-After` 付きの `429` | 組織に対する `router` ロールのレート制限が適用されています。 | 送信を遅くするか、`[router.rate_limit]` を引き上げます。 |
| ネイティブ JSON が `rejected` レコードを報告する | フィールドの値がストリームのスキーマと一致していません。たとえば `type mismatch on field level: expected Utf8, got Number` です。レスポンスにはインデックスごとの理由が一覧表示されます。`int64` フィールドの小数を含む数値はこれに該当しません。その場合、フィールドは `float64` になります。 | そのフィールドに対してストリームがすでに保持している型を送信します。 |
| `event #1 must be a JSON object` 付きの `400` | 配列に JSON オブジェクトでない要素が含まれています。リクエスト全体が拒否されます。 | オブジェクトの配列を送信します。 |
| Promtail または Grafana Alloy がプッシュできない | Loki エンドポイントは JSON のみをデコードしますが、これらの送信側は snappy 圧縮された protobuf を使用します。 | OpenTelemetry Collector、Vector、Fluent Bit 経由で送信します。 |
| レコードは受け付けられるが見つからない | クエリが別のストリーム名または型を使用しているか、レコードを除外する時間範囲を使用しています。 | ストリーム名とシグナルの種類を確認します。タイムスタンプについては次のセクションを参照してください。 |

## データの欠落または異常

- **タイムスタンプ。** `_timestamp` は Unix エポックからのマイクロ秒を表します。秒、ミリ秒、ナノ秒の値はイベントを誤った年または遠い未来に配置するため、直近の時間範囲のクエリでは返されません。`_timestamp` を省略するとサーバーの受信時刻が使用されます。
- **時間範囲。** 長い範囲を対象とするクエリは非同期ジョブになります。対話的なクエリには範囲を限定した `timeRange` を使用します。詳細は [クエリ](/ja/query#時間範囲と非同期ジョブ) を参照してください。
- **保持期間。** ストリームの保持期間より古いデータ、または独自の保持期間を持たないストリームでは **設定 → データ保持** のプラットフォームデフォルトより古いデータは削除されます。
- **ストリームの種類。** ストリームは名前と種類で識別されます。`default` はログ、メトリクス、トレースに同時に存在できます。

## クエリ

| 症状 | 原因 | 対処 |
|---|---|---|
| レスポンスが `jobId` と `monitor` パスを含む `202` である | 推定サイズが `[querier].auto_async_threshold_rows` に達したため、クエリが非同期検索ジョブとして実行されています。デフォルトでは、約 13.9 時間以上の範囲が該当します。 | ジョブが完了するまで `monitor` パスをリクエストし、その後 `/results` を取得します。または時間範囲を狭めるか、`Prefer: respond-sync` を送信します。詳細は [クエリ](/ja/query#時間範囲と非同期ジョブ) を参照してください。 |
| Flight SQL クライアントが接続できない | `[flight_sql]` はデフォルトで無効です。 | `enabled = true` を設定し、ポート `5083` を公開し、API トークンで認証します。 |

## 運用

| 症状 | 原因 | 対処 |
|---|---|---|
| `GET /api/v1/healthz` が `503` を返す | オブジェクトストアに到達できません。レスポンスボディに `reason` が含まれます。 | オブジェクトストアの接続を修正します。 |
| WAL ディレクトリが増え続ける | フラッシュが失敗しています。通常はオブジェクトストアに到達できないことが原因です。 | オブジェクトストアを修正します。その後、intake がバックログをフラッシュします。 |
| intake が `intake buffer memory limit exceeded` とともに `429` を返す | プロセスのバッファが `[intake].max_buffer_memory_size` を超えています。通常はフラッシュが失敗し続けていることが原因です。 | `intake flush failed` のログ行で原因を特定し、オブジェクトストアまたはデータベースを修正します。公開できない行は上限のカウント対象から外れます（次の 2 行を参照）。ネイティブ JSON の intake はこの応答とともに `Retry-After` を送信します。その時間が経過してから再試行してください。 |
| ログに `dataset no longer exists; buffered rows discarded` が表示される | ストリームの行がまだバッファにある間に、そのストリームが削除されたか、削除後に再作成されました。これらの行は送信先がないため、intake はそれらを破棄してメモリを解放します。カウンター `intake_flush_errors_total` は、各破棄をステップ `stream_gone` または `dataset_gone` として記録します。 | 修正は不要です。必要であればデータを再送信してください。 |
| 書き込みが `fenced by a newer writer epoch` とともに `503` を返す | 別のプロセスが同じ `[node].id` で同じデータセットを公開しています。フェンシングされたプロセスはデータを公開できず、メモリ上に保持している行を破棄し、そのデータセットへの書き込みを拒否します。WAL はディスク上に残ります。カウンター `intake_flush_errors_total` は、フェンシングをステップ `writer_fenced` として記録します。 | すべてのプロセスに一意の `[node].id` を設定し、フェンシングされたプロセスを再起動します。詳細は[ロールベースのデプロイ](/ja/deployment/role-based)を参照してください。 |
| スケジュールされた PDF または PNG レポートが失敗する | Chrome が見つからないか、`[scheduled_reports.renderer].base_url` から Web UI に到達できません。 | Chromium を含むリリースイメージを使用し、`base_url` にノードから到達できる Web UI のアドレスを設定します。 |
| オンボーディングのスニペットに誤ったホストが表示される | プロキシの背後で `http.external_url` が空です。 | `[http].external_url` に公開アドレスを設定して再起動します。 |
| クエリが `no querier node is available` とともに `503` を返す | `querier` ロールを持つノードから最近のハートビートがありません。 | `querier` ノードを起動し、その `advertise_addr` にルーターから到達できることを確認します。詳細は[ロールベースのデプロイ](/ja/deployment/role-based#クラスターのメンバーシップ)を参照してください。 |
| ルーター経由の書き込みが `no intake node is available` とともに `503` を返す | `intake` ロールを持つノードから最近のハートビートがありません。 | `intake` ノードを起動し、その `advertise_addr` を確認します。詳細は[ロールベースのデプロイ](/ja/deployment/role-based#クラスターのメンバーシップ)を参照してください。 |
| リクエストが `no metadata database connection` とともに `503` を返す | ノードは PostgreSQL の接続を 10 秒間待ちましたが取得できませんでした。PostgreSQL が過負荷または到達不能であるか、`[meta_database].max_connections` の接続がすべて使用中です。 | リクエストを再試行します。継続して発生する場合は、まず PostgreSQL の負荷と到達性を確認します。PostgreSQL がアイドル状態であれば、PostgreSQL の `max_connections` の範囲内で、負荷に合わせて `[meta_database].max_connections` を増やします。 |
| ホストから OTLP gRPC ポートに到達できない | Compose ファイルがポート `4317` を公開していません。 | `4317:4317` のマッピングを追加します。 |
