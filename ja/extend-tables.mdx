**拡張テーブル**は、MoleSignal 内に保存する、キーとレコードを対応付ける小規模なルックアップテーブルです。 [パイプライン](/ja/pipelines)の変換処理でキーを検索し、参照データを使ってイベントをエンリッチします。たとえば、 `service` を担当チームに、アカウント ID をプランの階層に、リージョンコードをリージョン名に対応付けます。主要な処理経路で外部ストアを呼び出す必要はありません。

## テーブル一覧

**テーブルを拡張**を開きます。ヘッダーにはテーブル数とレコード数が表示されます。各テーブルには、ルックアップキーとフィールド、レコード数、使用先、最終更新日時、状態（**正常**または **空**）が表示されます。状態や使用状況（**使用中**または**未使用**）で絞り込むことや、名前で検索することができます。

## テーブルを作成する

**新規拡張テーブル**を選択します。ウィザードは 2 ステップで構成されます。

<Steps>
  <Step title="スキーマを定義する">
    **テーブル**名と**説明**を入力します。レコードを識別するフィールドを**ルックアップキー**に指定します。たとえば、`customer_id`、`service`、`region_code` です。**値フィールド**を追加し、**フィールド**名、 **タイプ**（**文字列**、**数値**、**ブール値**、**オブジェクト**）、**必須**かどうか、説明を設定します。柔軟な構造の JSON レコードを保存するには、値フィールドを設定しません。テーブルに追加できる値フィールドは最大 100 個です。フィールド名には英字、数字、`.`、`-`、`_` を使用できます。
  </Step>
  <Step title="データを追加またはインポートする">
    レコードを後で追加するには**空のテーブルを作成**を選択します。今すぐ読み込むには**JSON を貼り付け**を選択します。JSON は、各レコードにルックアップキーを含む配列か、各キーを対応するレコードにマッピングするオブジェクトを指定します。
  </Step>
</Steps>

**拡張テーブルを作成**を選択します。

## レコード

テーブルを開きます。**データレコード**タブにレコードが表示されます。ルックアップキーまたはフィールドの値で検索できます。

| 操作 | 内容 |
|---|---|
| **レコードを追加** | **フォームモード**または**JSON モード**でルックアップキーとフィールドの値を入力します。キーがすでに存在する場合は、警告を表示してから上書きします。 |
| **レコードを編集** | レコードの値を変更します。 |
| **JSON を表示** | テーブルの列に表示されないフィールドも含め、レコード全体を表示します。 |
| **レコードを削除** | レコードを削除します。この操作は元に戻せません。 |
| **データをインポート** | JSON ファイル（配列またはキーとレコードのマップ）、1 行目にフィールド名を含む CSV ファイル、または貼り付けた JSON や CSV から、複数のレコードを一括で書き込みます。データにはルックアップキーの列が必要です。概要には、インポートするレコードの件数と、そのうち既存のキーを上書きする件数が表示されます。 |

## スキーマ、使用状況、設定

| タブ | 内容 |
|---|---|
| **スキーマ** | ルックアップキーと値フィールドを表示します。**フィールドの編集**では、フィールドの追加、説明や**必須**設定の変更ができます。テーブルにレコードがある間は、既存フィールドの名前やタイプを変更したり、フィールドを削除したりすることはできません。テーブルが空の場合は、これらの制限はありません。テーブル名とルックアップキーは変更できません。 |
| **使用状況** | テーブルを参照するパイプラインと保存済みクエリを表示します。テーブルを変更または削除する前に確認してください。 |
| **設定** | **テーブル情報**を表示します。**危険な操作**の**拡張テーブルを削除**では、テーブルとすべてのレコードを削除します。削除後は、テーブルの参照結果が `null` になり、パイプラインからのイベントの書き込みは失敗します。パイプラインにデッドレターストリームがある場合は、書き込みに失敗したイベントをそこに送ります。 |

## パイプラインでキーを検索する

パイプラインでテーブルを読み取るには、[**拡張テーブルを参照**](/ja/pipelines#拡張テーブルを参照) ステップで行の値をイベントのフィールドにコピーするか、 VRL ステップで [`lookup(table, key)`](/ja/functions#テーブルとipアドレスを検索する) を使って行を取得します。

```ruby
# enrich each event with the service's owning team
.team = lookup("service_meta", .service).team
```

どちらの方法も、[アラートパイプライン](/ja/pipelines/alert-events)を含むすべての種類のパイプラインで使用できます。ノードは、ステップが初めてテーブルを必要としたときに読み取り、30 秒間メモリに保持します。そのため、参照によってパイプラインの実行にクエリコストやストレージコストが追加されることはありません。レコードの追加、変更、削除は、すべてのパイプラインに 30 秒以内に反映されます。拡張テーブルはワークスペースに属し、そのワークスペース内のすべてのパイプラインで使用できます。

## パイプラインからテーブルにデータを書き込む

スケジュール実行するパイプラインでテーブルを最新の状態に保てます。**送信先を追加 → 拡張テーブル**では、パイプラインのステップを通過したすべてのイベントを、ルックアップキーの値に対応する行として書き込みます。詳しくは、 [拡張テーブルに書き込む](/ja/pipelines#拡張テーブルへの書き込み)を参照してください。

## 拡張テーブル API

```bash
# upsert a record keyed by "checkout"
curl -X PUT http://localhost:5080/api/v1/extend_tables/service_meta/rows/checkout \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"team":"payments","tier":"gold"}'
```

| 操作 | エンドポイント |
|---|---|
| テーブルを一覧表示する | `GET /api/v1/extend_tables` |
| テーブルのレコードを一覧表示する | `GET /api/v1/extend_tables/{table}` |
| レコードを追加または更新する | `PUT /api/v1/extend_tables/{table}/rows/{key}` |
| レコードを削除する | `DELETE /api/v1/extend_tables/{table}/rows/{key}` |

## 権限

テーブルとその使用状況を一覧表示するには `functions.read` が必要です。テーブルの作成には `functions.create`、レコードとフィールドの変更には `functions.edit`、テーブルの削除には `functions.delete` が必要です。
