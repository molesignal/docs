ダッシュボードは、チームで監視するパネルをグリッドに並べたものです。各パネルはワークスペースのストリームに対して個別にクエリを実行し、結果を描画します。グリッドの上にある変数を使うと、すべてのパネルの表示対象を別のサービス、ホスト、環境に一度に切り替えられます。

このページでは、ダッシュボードの探し方と使い方を説明します。ダッシュボードを作成または変更するには、 [ダッシュボードを作成する](/ja/dashboards/edit)と[変数](/ja/dashboards/variables)を参照してください。

## ダッシュボード一覧

**ダッシュボード**を開きます。ヘッダーにダッシュボードとフォルダーの件数が表示されます。次の項目で一覧の絞り込みや表示の切り替えができます。

- 名前で絞り込むフィルター欄
- 表示範囲の**すべて**、**自分**、**お気に入り**、**タグ**
- 特定のフォルダー、または**すべて**のフォルダー
- **グリッド**または**リスト**のレイアウト

ヘッダーには**新規ダッシュボード**、**JSONをインポート**、**フォルダーを管理**もあります。ダッシュボードの星アイコンを選択すると、**お気に入り**に追加できます。各ダッシュボードの末尾にあるメニューには、次の操作があります。

| 操作 | 動作 |
|---|---|
| **開く**、**編集**、**共有** | それぞれダッシュボード、エディター、共有ダイアログを開きます。 |
| **フォルダーに移動** | ダッシュボードを別のフォルダーに移動します。 |
| **コピーを作成** | `<title> copy` という名前の編集可能なコピーを作成します。 |
| **JSONをエクスポート** | **JSONをインポート**で読み込めるダッシュボードモデルをダウンロードします。 |
| **NOC表示に設定** | このブラウザーの[NOC ウォールボード](#noc-ウォールボード)にこのダッシュボードを表示します。 |
| **削除** | ダッシュボードとそのパネルを削除します。この操作は元に戻せません。 |

## フォルダー

フォルダーは最大3階層まで作成でき、ダッシュボードを分類できます。**フォルダーを管理**を選択し、最上位に作成する場合は**新規フォルダー**、選択したフォルダー内に作成する場合は**新規サブフォルダー**を選択します。

フォルダーを指定していないダッシュボードは、**デフォルト**フォルダーに入ります。このフォルダーは名前の変更も削除もできず、サブフォルダーも作成できません。フォルダーを削除するには、中のダッシュボードとサブフォルダーをすべて移動してください。

## ダッシュボードを確認する

ダッシュボードのヘッダーには、フォルダー、パネル数、最終変更日時、および次のコントロールが表示されます。

| コントロール | 用途 |
|---|---|
| 時間範囲ピッカー | すべてのパネルの時間範囲を設定します。時刻は個人設定のデフォルトのタイムゾーンで表示します。ピッカーの下部にある**変更**で別のタイムゾーンに切り替えられます。 |
| **更新** | すべてのパネルのクエリを再実行します。横のメニューで、自動更新を**オフ**、**自動**、または指定した間隔に設定します。**自動**では、時間範囲とパネルの幅に応じて更新間隔を調整します。 |
| 変数 | [変数](/ja/dashboards/variables)の値を選択します。URL に `var-<name>=<value>` として値を保持するため、コピーしたリンクから同じ表示を開けます。 |
| **共有** | [共有ダイアログ](/ja/resource-sharing)を開きます。 |
| **編集** | [エディター](/ja/dashboards/edit)を開きます。読み取り専用のダッシュボードでは、代わりに**コピーを作成**を表示します。 |
| その他 | **ダッシュボードの詳細を表示**（ID、UID、所有者、スキーマ）、**NOC表示**、**コピーを作成**、**JSONをエクスポート**を選択できます。 |

パネルにカーソルを合わせると説明が表示されます。パネルのメニューには、次の操作があります。

| 操作 | 動作 |
|---|---|
| **表示** | パネルだけをフルサイズで表示します。 |
| **編集** | パネルをエディターで開きます。 |
| **データを探索** | パネルのクエリを対応するエクスプローラーで開きます。変数の値と時間範囲はそのまま引き継ぎます。 |
| **クエリを調べる** | パネルのクエリ定義を JSON で表示します。 |
| **共有** | パネルへのリンクをコピーします。 |
| **データをエクスポート** | パネルのデータを CSV でダウンロードします。 |
| **画像をエクスポート** | パネルの画像をダウンロードします。 |
| **コピー** | 別のダッシュボードに貼り付けられるように、パネルの JSON をコピーします。 |
| データリンク | パネルの[データリンク](/ja/dashboards/edit#データリンク)を開きます。 |
| **アラートを作成** | パネルのクエリをもとに、新しい[アラートルール](/ja/alerting/rules)の作成画面を開きます。 |
| **Mole Agent による分析** | パネルに表示されている内容の分析を [Mole Agent](/ja/agent) に依頼します。 |

## ダッシュボードをインポートする

**JSONをインポート**を選択し、MoleSignal のダッシュボードの JSON を貼り付けるか `.json` ファイルをアップロードします。フォルダーを選び、 **インポート**を選択します。使える JSON は、**JSONをエクスポート**でダウンロードしたもの、または `GET /api/v1/dashboards/{id}` が `model` として返すものです。`engine` は `molesignal-dashboard` である必要があります。

Grafana のダッシュボードの JSON はインポートできません。エディターでダッシュボードを作り直してください。PromQL 式はメトリクスパネルにそのまま貼り付けられます。ダッシュボードを Grafana に残す場合は、 [Grafana データソース](/ja/query/grafana)を通じて MoleSignal のデータを読み取ります。

## Mole Agent にダッシュボードの作成を依頼する

[Mole Agent](/ja/agent) にダッシュボードの下書きを依頼します。たとえば「チェックアウトサービスのダッシュボード」と指定します。Mole Agent はダッシュボードを作成せずに下書きを用意し、**AIダッシュボードの下書き**へのリンクを表示します。

1. **読み取り専用プレビュー**を確認します。実際のダッシュボードと同じレンダラーで描画します。
2. **クエリの事前チェック**で、各パネルのクエリを1回実行した結果（**成功**、**結果なし**、 **スキップ済み**）と、**生成時の警告**や**修正が必要な問題**がないかを確認します。
3. **作成提案を送信**を選択します。作成ポリシーでレビューが必要な場合、下書きは承認待ちになります。レビューが不要な場合は、**確認して作成**を選択します。

下書きは対応するモデルにひも付き、一定時間が経過すると期限切れになります。変更するには、改めて依頼してください。

## 組み込み RUM ダッシュボード

RUM アプリケーションがあるワークスペースには、`内置` と `rum` のタグが付いた読み取り専用のダッシュボードがアプリケーションの種類ごとにあります。

| ダッシュボード | 対象 | 表示内容 |
|---|---|---|
| `RUM · 浏览器应用` | ブラウザーアプリケーション | 全セッション、エラーが発生しなかったセッション、フラストレーションが検出されたセッション、LCP・INP・CLS の75パーセンタイル値とそれぞれの推移、発生元別のエラー、ページ、バージョン、フラストレーションが検出された要素、応答が遅いホスト、国、ブラウザー。 |
| `RUM · 移动应用` | Android、iOS、Flutter、React Native のアプリケーション | 全セッション、クラッシュもエラーも発生しなかったセッション、フラストレーションが検出されたセッション、クラッシュが発生しなかったセッション・エラー・クラッシュの時系列、画面、バージョン、バージョン別のクラッシュ、フラストレーションが検出された要素、応答が遅いホスト、デバイス、OS。 |

サーバーは、種類ごとに最初のアプリケーションを作成したときにダッシュボードを追加します。該当するアプリケーションがすでにあるワークスペースには、サーバーの起動時に追加します。アップグレードでダッシュボードが変わる場合も、同じタイミングで更新します。変数は、**应用**（アプリケーション）、**环境**（特定の環境、またはすべての環境を表す **全部**）、**间隔**（時系列チャートの棒の幅）です。 [RUM の概要](/ja/rum#概要)で**ダッシュボードで開く**を選択すると、そのページのアプリケーションと環境を選択した状態でダッシュボードが開きます。

各パネルは短い SQL 文でデータを取得します。ビューとセッションの読み取りには `rum_views_latest` と `rum_sessions_latest` を使います。それぞれの[最新バージョン](/ja/query#rum-の行の最新バージョン)を保持しており、パーセンタイルは対象の値があるビューだけで計算します。表示される数値は概要ページと同じです。組み込みのダッシュボードは編集できません。編集可能なダッシュボードを作るには、ダッシュボードのヘッダーまたはダッシュボード一覧で**コピーを作成**を選択します。

## NOC ウォールボード

上部バーで **NOC ウォールボード**を選択すると、壁面ディスプレイ向けの暗色のビューが全画面で開きます。終了するには、`Esc` を押すか、**コンソールに戻る**を選択します。

ステータスバーには、ワークスペースの概要として、アクティブなインシデントとその重大度、ライブデータの状態、サービス数、リクエストレート、P95 レイテンシーが表示されます。各パネルには次の内容が表示されます。

| パネル | 表示内容 |
|---|---|
| **インシデント** | 現在発生しているインシデント。 |
| **トポロジー** | 過去1時間のサービスのトポロジー。 |
| **稼働状態** | サービスごとのリクエストレート、P95 レイテンシー、エラー率。 |
| **トラフィック** | 過去60分間でトラフィックが最も多かったサービス。 |

**レイアウト設定**でウォールボードのレイアウトを変更できます。プリセット（**プラットフォーム運用**、**SRE**、 **経営層向け**）の適用、パネルの表示・非表示、幅や表示順の変更、**リセット**ができます。レイアウトはブラウザーに保存されます。

ダッシュボードをNOC表示に設定すると、ウォールボードは通常のパネルの代わりに、ダッシュボードのタイトルと各パネルを対応するクエリとともに表示します。ウォールボードではパネルをチャートとして描画しません。チャートを確認するには、ダッシュボードを直接開いてください。

## レポートと共有

ダッシュボードから定期配信の[レポート](/ja/reports)を作成し、PDF、PNG、CSV、SVG、JSON のいずれかの形式で配信します。 **共有**で、サインイン済みユーザーへの共有、ワークスペース間の共有、アクセス制限付きの公開を設定します。公開ダッシュボードは、パネルに保存されたクエリのみを実行し、[共有ポリシー](/ja/settings/organization#共有とパブリックアクセス)に従います。適用されるのは、ダッシュボードが属するワークスペースのポリシーです。

## 権限

| 権限 | 許可される操作 |
|---|---|
| `dashboards.read` | ダッシュボードとフォルダーを開きます。 |
| `dashboards.create` | ダッシュボードを作成、インポート、コピーします。 |
| `dashboards.edit` | ダッシュボードとフォルダーを編集します。 |
| `dashboards.delete` | ダッシュボードを削除します。 |
| `dashboards.share` | 共有リンクを作成、再発行します。 |
