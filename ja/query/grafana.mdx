MoleSignal データソースは Grafana プラグインです。Grafana は、メトリクスを PromQL で、ログとトレースを **ログ**ページと**トレース**ページのフィールドクエリで、任意のストリームを SQL で読み取ります。シグナル間も移動できます。ログ行やエグザンプラーから対応するトレースを開くことができ、すべての結果から MoleSignal に戻れます。

<Note>
プラグインのバックエンドは Grafana サーバーで動作し、Grafana が子プロセスとして起動します。MoleSignal へのリクエストはすべて、データソースのトークンを使って Grafana サーバーから送信します。ブラウザーが MoleSignal に直接アクセスすることはありません。Grafana Cloud は、Private data source connect を通じてプライベートネットワーク内の MoleSignal に接続します。
</Note>

## 要件

| 項目 | 要件 |
|---|---|
| Grafana | 12.3 以降。13.x も含みます。 |
| MoleSignal | [`POST /api/v1/query`](/ja/api/query/execute) の `step` フィールドと、[ログ](/ja/api/web/logs)および[トレース](/ja/api/web/trace)の読み取り時の `expression` パラメーターに対応するバージョンが必要です。古いバージョンはフィールドクエリに対して絞り込みなしの結果を返すため、**保存してテスト**では接続を拒否します。 |
| ネットワーク | Grafana サーバーから MoleSignal の HTTP ポート（デフォルトは 5080）に接続できる必要があります。 |
| トークン | **閲覧者**ロールを持つサービスアカウントの APIトークンが必要です。データソースは `streams.read`、`streams.query`、`logs.read`、`traces.read`、`metrics.read` を使用します。また、アノテーションと変数には `dashboards.read` と `dashboards.annotations.read`、デプロイのアノテーションには `apm.deployments.read`、インシデントのアノテーションには `alerts.incidents.read` を使用します。 |

## Grafana 用のトークンを作成する

1. **ID とアクセス → サービスアカウント**を開き、**サービスアカウントの作成**を選択します。
2. **名前**に `grafana` と入力し、**閲覧者**ロールを選択します。
3. **アカウントとトークンを作成**を選択し、トークンをコピーします。トークンは 365 日で有効期限が切れ、作成時に一度だけ表示されます。

Grafana のアクセスを読み取り専用にするには、権限を絞ったトークンを発行します。**ID とアクセス → API トークン**を開き、**サービスアカウント用トークンを発行**を選択します。対象のアカウントを選び、**スコープ**に**読み取り専用オブザーバー**ポリシーを指定します。[API トークンとサービスアカウント](/ja/identity/tokens)を参照してください。

各データソースが読み取るデータは、トークンが属する 1 つの組織に限られます。データソースを使用できる Grafana ユーザーは全員、そのトークンで読み取り可能なデータにアクセスできます。Grafana のデータソース権限でアクセスを制限するか、チームごとに専用のデータソースとトークンを用意してください。

## プラグインをインストールする

Grafana CLI でリリースアーカイブをインストールするか、Grafana のプラグインディレクトリに展開します。Linux パッケージと Docker イメージでは、このディレクトリは `/var/lib/grafana/plugins` です。

```bash
grafana cli --pluginUrl https://github.com/molesignal/molesignal-grafana-plugin/releases/download/v0.1.0/molesignal-datasource-0.1.0.zip plugins install molesignal-datasource
```

プラグインはまだ署名されていません。`grafana.ini` または環境変数 `GF_PLUGINS_ALLOW_LOADING_UNSIGNED_PLUGINS=molesignal-datasource` でプラグインの読み込みを許可し、Grafana を再起動します。

```ini
[plugins]
allow_loading_unsigned_plugins = molesignal-datasource
```

## データソースを追加する

1. Grafana で **接続 → データソース**を開き、**新しいデータソースを追加**を選択して、**MoleSignal** を選びます。
2. MoleSignal の **URL**（例: `https://molesignal.example.com`）を入力し、**APIトークン**を貼り付けます。
3. **保存してテスト**を選択します。

**保存してテスト**では、MoleSignal のバージョンを取得し、トークンに `streams.read` と `streams.query` があることを確認します。また、種類ごとにストリーム数を集計し、MoleSignal がフィールドクエリに対応していることを確認します。

| 設定 | デフォルト | 説明 |
|---|---|---|
| **URL** | | `/api/v1` を含まない MoleSignal のアドレスです。 |
| **APIトークン** | | Grafana サーバーで暗号化して保存します。 |
| **TLS 証明書の検証をスキップ** | オフ | 自己署名証明書を使うテストインスタンスでのみ使用します。 |
| **CA 証明書** | | MoleSignal の証明書に署名した認証局の証明書を PEM 形式で指定します。 |
| **ログストリーム** | | 新しいログクエリの対象となるストリームです。Explore のアドホックフィルターでは、このストリームのフィールドを選択できます。 |
| **ログフィールド** | `message`, `level`, `trace_id` | ログ行の本文、レベル、トレース ID を格納するフィールドです。 |
| **スクレイプ間隔** | `15s` | メトリクスを取得する間隔です。`$__rate_interval` はこの間隔の 4 倍以上です。 |
| **フェデレーションクラスター** | このクラスター | すべての SQL クエリと PromQL クエリの対象となるクラスターをカンマ区切りで指定します。 |
| **MoleSignal の Web アドレス** | URL の設定値 | **MoleSignal で開く**リンクの移動先です。 |
| **タイムアウト（秒）** | `60` | MoleSignal への 1 回のリクエストで待機する最大時間です。 |
| **同時クエリ数** | `10` | 1 つのパネル、Explore ペイン、またはアラートルールで同時に実行するクエリの数です。 |

## クエリタイプ

| クエリタイプ | 読み取るデータ | 表示形式 |
|---|---|---|
| **PromQL** | パネルの間隔に合わせた範囲クエリ、またはインスタントクエリで取得したメトリクス | 時系列、テーブル、エグザンプラー |
| **SQL** | 任意のストリーム | テーブル、時系列、またはログ行 |
| **ログ** | フィールドクエリに一致するログストリームの最新レコード | ログ行 |
| **トレース** | ID で指定した 1 件のトレース | トレースビュー |
| **トレース検索** | フィールドクエリに一致するトレース | 各トレースを開けるテーブル |
| **RED** | フィールドクエリに一致するスパンの、秒あたりのリクエスト数、秒あたりのエラー数、エラー率、または所要時間のパーセンタイル | 時系列。**グループ化の基準**でフィールドを指定した場合は、値ごとに 1 系列を表示します。 |
| **サービスグラフ** | サービス間の呼び出し | ノードグラフ |

### PromQL

範囲クエリは 1 ステップにつき 1 データポイントを読み取ります。ステップにはパネルの間隔を使用しますが、**最小ステップ**を下回らず、1 系列あたりのステップ数が 11,000 を超えないように調整します。**凡例**では各系列の表示名を指定します。ラベルの値を表示するには `{{label}}` を使用します。**エグザンプラー**を有効にすると、系列のエグザンプラーが表示され、各エグザンプラーから対応するトレースを開けます。MoleSignal は [PromQL のサブセット](/ja/query/promql-subset)を実装しています。

### フィールドクエリ

**ログ**、**トレース検索**、**RED** は、MoleSignal の**ログ**ページと**トレース**ページと同じフィールドクエリを使用します。同じクエリは、Grafana と MoleSignal のどちらでも同じ意味になります。

```text
level = 'error' AND (service.name = 'checkout' OR timeout)
```

| 要素 | 意味 |
|---|---|
| `AND`、`OR`、括弧 | `AND` は `OR` より優先されます。括弧で条件をグループ化します。 |
| `=`、`!=`、`>`、`>=`、`<`、`<=`、`contains` | フィールドを値と比較します。 |
| `field in ('a', 'b')` | トレースクエリで、指定した複数の値のいずれかに一致します。 |
| `MATCH(field, 'text')`、`MATCH_TEXT(field, 'words')` | ログクエリで、フィールドを全文検索します。 |
| 引用符で囲まない単語、または引用符で囲んだフレーズ | 検索するテキストです。 |

**条件を追加**の行では、**フィールド**、**演算子**、**値**で比較条件を作り、`AND` で追加します。**RED** は、サービスがリクエストを受け付けた箇所の**エントリースパン**、または**すべてのスパン**を読み取ります。

### SQL

SQL は任意のストリームを読み取ります。**ストリーム**では、SQL 文の実行計画を作成する対象のストリームを指定します。空欄の場合は `FROM` の後のテーブルを使用します。**形式**では、表示形式として**テーブル**、**時系列**、**ログ**のいずれかを選択します。次のマクロはパネルの時間範囲を使用します。

| マクロ | 展開結果 |
|---|---|
| `$__timeFilter(_timestamp)` | `_timestamp >= <from> AND _timestamp < <to>` |
| `$__timeGroup(_timestamp, $__interval)` | `date_bin(INTERVAL '<interval>', _timestamp)` |
| `$__timeFrom()`、`$__timeTo()` | 時間範囲の開始時刻と終了時刻を示すタイムスタンプ |

`$__interval`、`$__rate_interval`、`$__range` は PromQL と SQL で使用できます。アラートルールでも使用できます。

## Explore

| 操作 | 結果 |
|---|---|
| ログクエリを実行する | ログ行の上に、レベル別のログ件数を表示します。 |
| ログ行のコンテキストを開く | そのログ行の前後 50 件ずつのレコードを表示します。 |
| ログ行の詳細で、指定した値を含めるか除外する | `field = 'value'` または `field != 'value'` を `AND` でクエリに追加します。 |
| ログ行のトレース ID またはエグザンプラーを選択する | クエリの横にトレースを開きます。 |
| **MoleSignal で開く**を選択する | 同じクエリと時間範囲を MoleSignal で開きます。 |

## 変数とアドホックフィルター

クエリ変数は、次のいずれかを一覧表示します。

| リスト | 値 |
|---|---|
| **ストリーム** | 指定したタイプのストリームです。 |
| **フィールド** | ストリームのフィールドです。 |
| **フィールド値** | ログストリームのフィールドに頻出する値です。 |
| **メトリクス** | メトリクス名です。指定したテキストを含む名前だけに絞り込むこともできます。 |
| **ラベル値** | メトリクスのラベルの値です。 |
| **SQL** | SQL 文の結果の最初の列です。 |

変数で複数の値を選択すると、各クエリ言語の構文に合わせて展開します。PromQL の `=~` では `(a|b)`、SQL の `IN (...)` では `'a', 'b'`、トレースのフィールドクエリの `in (...)` では `'a', 'b'` になります。

アドホックフィルターは、PromQL ではすべてのセレクターにラベルマッチャーを追加し、フィールドクエリでは `AND` 条件を追加して結果を絞り込みます。フィルターのキーと値は、データソースの **ログストリーム** から取得します。

## アノテーション

アノテーションクエリは、1 つの **ソース** の情報をダッシュボードのパネルに表示します。

| ソース | 表示内容 |
|---|---|
| **アノテーション** | MoleSignal のアノテーションです。指定した **タグ** が付いたものだけに絞り込むこともできます。 |
| **デプロイ** | [APM](/ja/apm/deployments) が記録したデプロイです。特定のサービスだけに絞り込むこともできます。 |
| **インシデント** | インシデントの開始から解決までの期間です。特定のサービスだけに絞り込むこともできます。 |

## アラート

Grafana のアラートルールは、プラグインのバックエンドで PromQL と SQL のクエリを実行します。[MoleSignal のアラート機能](/ja/alerting)では、リアルタイムルール、インシデント管理、オンコール、エスカレーションも利用できます。Grafana で発火したアラートも、[外部アラート](/ja/alerting/sources#grafana)として MoleSignal に送信できます。

## ダッシュボード

データソースの **ダッシュボード** タブでは、次の 2 つのダッシュボードをインポートできます。

| ダッシュボード | 表示内容 |
|---|---|
| **MoleSignal · サービス** | 各サービスのリクエスト数、エラー数、処理時間に加え、サービスグラフと最も遅いトレースを表示します。 |
| **MoleSignal · ログ** | ログストリームのログ量と最新のエラーを表示します。 |

## 上限

| 項目 | 上限 |
|---|---|
| ログクエリ | 最新の 1,000 件です。**行数の上限** で最大 5,000 件まで増やせます。 |
| トレース検索 | 100 件です。**行数の上限** で最大 5,000 件まで増やせます。 |
| トレース | 指定した時間範囲のうち、終了時点からさかのぼって 31 日以内に開始したトレースが対象です。 |
| PromQL | シリーズあたり 11,000 ステップ、クエリあたり 100,000 データポイントです。上限を超えると、MoleSignal は各シリーズのデータポイントを等間隔に間引きます。 |
| SQL | 10,000 行です。**行数の上限** で最大 1,000,000 行まで増やせます。 |

Grafana の Logs Drilldown、Traces Drilldown、Metrics Drilldown アプリは、それぞれ Loki、Tempo、Prometheus のみをサポートするため、このデータソースは利用できません。
