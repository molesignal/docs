Une application est le site Web ou l’application qui envoie les événements RUM. Créez-la avant qu’un SDK envoie des données :
le jeton client est associé à une seule application, et MoleSignal rejette tout événement destiné à une application
qui n’existe pas.

Ouvrez **RUM → Applications** pour afficher les applications de l’espace de travail. Pour créer, modifier ou supprimer
une application, la permission `rum.applications.manage` est requise, car chaque application possède un jeton client.
Pour consulter la liste, la permission `rum.applications.read` est requise.

## Créer une application

<Steps>
  <Step title="Ouvrir le formulaire">
    Cliquez sur **Créer une application**. Si l’espace de travail ne contient aucune application, le même bouton apparaît dans
    l’explorateur.
  </Step>
  <Step title="Nommer l’application">
    Saisissez un **Nom** unique de 128 caractères maximum, par exemple `Checkout web`, puis choisissez la **Plateforme** :
    Navigateur, Android, iOS, Flutter, React Native ou Autre. La plateforme détermine uniquement l’extrait de configuration
    affiché dans l’application : le champ `source` de chaque événement indique ce qui l’a envoyé.
  </Step>
  <Step title="Choisir l’identifiant">
    L’**Identifiant** correspond à la valeur du paramètre `applicationId` dans les SDK. Laissez ce champ vide pour
    générer l’identifiant à partir du nom (`checkout-web`), ou saisissez jusqu’à 64 caractères parmi `A-Z`, `a-z`, `0-9`,
    `.`, `_`, `:` et `-`. Une fois l’application créée, l’identifiant ne peut plus être modifié.
  </Step>
  <Step title="Cliquer sur Créer">
    L’application s’ouvre et affiche son jeton client.
  </Step>
</Steps>

La création d’une application crée également les sept flux RUM de l’espace de travail s’ils n’existent pas encore.

## Jeton client

Ouvrez une application pour consulter son **Jeton client**. Au format `mspat-<36>`, ce jeton n’expire jamais
et accorde uniquement la permission `rum.write` pour cette application. Il est masqué par défaut. Sélectionnez **Afficher le jeton** ou **Copier le jeton**.

<Warning>
  Le code du navigateur et des applications mobiles contient le jeton, que les utilisateurs peuvent lire. Utilisez uniquement ce jeton dans le code client, jamais
  un jeton de propriétaire ou d’administrateur, ni un jeton personnel. La suppression de l’application révoque le jeton.
</Warning>

Le même jeton est disponible via l’[API](/fr/api/auth/rum-token). Dans l’application, **Ouvrir le guide de configuration** ouvre
le guide **Source de données** de la plateforme avec l’application présélectionnée. Le guide indique le point de terminaison et le jeton,
fournit un extrait de code SDK prérempli avec l’identifiant et permet de vérifier la réception des données. Aucun guide n’est disponible pour React Native et Autre : envoyez
directement les [événements](/fr/rum/events) avec le jeton.

## Collecte

Les paramètres de l’application déterminent les données conservées avec chaque événement. Modifiez-les dans l’application, puis cliquez sur **Enregistrer**.

| Paramètre | Valeur par défaut | Effet |
|---|---|---|
| **Conserver l’adresse IP** | Activé | Stocke dans `network.client.ip` l’adresse IP du client telle que le serveur l’a déterminée. Si un proxy est utilisé, configurez d’abord la [détection de l’adresse IP du client](/fr/rum#adresse-ip-du-client-derrière-un-proxy). |
| **Conserver la localisation** | Activé | Stocke le pays, la région et la ville déterminés à partir de l’adresse IP. Le serveur détermine la localisation même si l’adresse IP n’est pas conservée et ne stocke que le résultat de cette recherche. |
| **Confidentialité par défaut** | Masquer le texte et les valeurs saisies | Niveau de confidentialité proposé par l’extrait de configuration pour les enregistrements de session : **Masquer le texte et les valeurs saisies**, **Masquer les saisies utilisateur** ou **Enregistrer tout ce qui s’affiche**. |

Les modifications s’appliquent aux événements reçus par la suite. Les données déjà stockées ne changent pas.

## Configuration à distance du SDK

Si `remoteConfiguration: true` est activé, le SDK lit ces paramètres au démarrage. Modifiez-les sans redéployer la page. Pour tout paramètre laissé sur
**Selon la configuration de la page**, le SDK utilise la valeur que la page transmet à `init`.

| Paramètre | Option du SDK |
|---|---|
| **Taux d’échantillonnage des sessions (%)** | `sessionSampleRate` |
| **Taux d’échantillonnage des enregistrements de session (%)** | `sessionReplaySampleRate` |
| **Niveau de confidentialité** | `defaultPrivacyLevel` |
| **Collecter les clics** | `trackUserInteractions` |
| **Transférer les messages de la console** | `forwardConsoleLogs` |

Le SDK récupère ces paramètres via `GET /api/v1/rum/config` avec son jeton client. Sans réponse au bout de 1,5 seconde, il démarre avec les valeurs fournies par la page.

## Segments

La section **Segments** permet de nommer jusqu’à 20 groupes de sessions et de filtrer les [pages d’analyse](/fr/rum/analytics#segments) selon ces groupes. Un segment comporte jusqu’à cinq
conditions. Pour en faire partie, une session doit toutes les remplir. Une condition peut porter sur le pays, le continent, la ville, le navigateur, le système, le type
d’appareil, l’identifiant ou l’adresse e-mail de l’utilisateur, l’identifiant du compte, le service, la version, la plateforme ou une propriété utilisateur définie par l’application
avec `setUser` (`usr.extra.plan`). Elle peut vérifier qu’une ou plusieurs valeurs correspondent, ou qu’aucune ne correspond. Toute modification s’applique immédiatement aux consultations, y compris aux
sessions déjà stockées. Les propriétés utilisateur sont disponibles pour les sessions démarrées après le déploiement de cette fonctionnalité.

## Données sensibles et sessions conservées

La section **Données sensibles** propose un interrupteur pour chaque type de texte que le serveur retire d’un événement avant de le stocker : jetons, clés et
mots de passe ; adresses e-mail ; numéros de téléphone ; numéros de carte de paiement ; numéros d’identification ; et valeurs des paramètres d’URL sensibles.
Tous les interrupteurs sont activés par défaut. Consultez la page [Confidentialité RUM](/fr/rum/privacy#retirer-les-données-sensibles-à-l’ingestion) pour savoir ce que chaque interrupteur retire.

La section **Sessions conservées** détermine les sessions que l’application stocke. **Part des sessions conservées (%)** fixe la proportion de sessions reçues que
l’application conserve. Saisissez un entier de `0` à `100`. La conservation ou l’exclusion porte sur la session entière, enregistrement compris.
**Ajouter un filtre** permet de fixer une proportion spécifique pour les sessions qui répondent à ses critères (environnement, version, pays, navigateur, etc.). Le premier
filtre correspondant l’emporte. Pour les autres sessions, **Part des autres sessions conservées (%)** s’applique. L’option **Conserver toutes
les erreurs** stocke aussi les erreurs des sessions non conservées. Les pages qui affichent des totaux extrapolent les données conservées à l’ensemble des
sessions et affichent la mention **Estimé**. Consultez la page [Échantillonnage des données RUM](/fr/rum/sampling#conserver-une-part-des-sessions-côté-serveur).

## Problèmes

La section **Problèmes** fixe le nombre de nouveaux [problèmes](/fr/rum/errors#nouveaux-problèmes-par-heure) que l’application peut ouvrir par heure.

| Paramètre | Valeur par défaut | Effet |
|---|---|---|
| **Nouveaux problèmes par heure** | 100 | De 1 à 10 000. Une fois la limite atteinte, l’application regroupe les erreurs qui ne sont encore associées à aucun problème sous un seul problème nommé **Autres erreurs**, jusqu’à la fin de l’heure. Toute modification prend effet en 30 secondes maximum. |

## Supprimer une application

Cliquez sur **Supprimer l’application**, puis confirmez. Le jeton client cesse de fonctionner immédiatement et MoleSignal rejette les requêtes des SDK qui l’utilisent.
Les événements déjà envoyés par l’application restent dans les flux jusqu’à la fin de leur durée de conservation. Ils restent consultables
dans l’explorateur.
