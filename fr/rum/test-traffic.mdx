Une session est de type `user`, `synthetics` ou `ci_test`. Un [test synthétique](/fr/synthetics) dans un navigateur qui ouvre une page utilisant le [SDK navigateur](/fr/rum/browser-sdk) 0.3.0 ou ultérieur crée une session de type `synthetics`, sans configuration. Les événements de la session indiquent le test, l’exécution et l’emplacement dans `synthetics.test_id`, `synthetics.result_id` (le `task_id` du résultat de l’exécution) et `synthetics.location_id`, respectivement.

## Effet sur les chiffres

Les chiffres d’une application reflètent l’activité des utilisateurs réels. Une session générée par un test est donc exclue des éléments suivants :

- les pages de vue d’ensemble, de performances, de frustration, d’erreurs, d’analyses, de cartes de chaleur et d’indicateurs de fonctionnalité, ainsi que les tableaux de bord intégrés ;
- les [règles d’alerte fondées sur les chiffres RUM](/fr/rum/alerts) ;
- les lignes de l’explorateur et les outils RUM de Mole Agent.

Les erreurs de cette session ne créent pas de [problèmes](/fr/rum/errors). Un test en échec ne compte donc pas comme un nouveau problème. Toute page qui exclut des sessions affiche **N sessions de test exclues**. Cliquez sur ce libellé pour les consulter.

La [politique de rétention](/fr/rum/sampling) de l’application conserve aussi la session dans son intégralité, sans échantillonnage. Si un filtre de l’application mentionne `session.type`, l’application applique aux sessions de test ses filtres et ses taux de rétention, comme pour toute autre session. Le SDK conserve ces sessions quelle que soit la valeur de son paramètre `sessionSampleRate`.

## Retrouver les sessions de test

- Depuis une exécution : cliquez sur **Ouvrir la session RUM de cette exécution** dans la tentative associée au résultat d’un test dans un navigateur.
- Depuis la session : la page de la session indique son type et donne accès aux résultats du test.
- Dans l’explorateur : une requête qui mentionne `session.type`, `synthetics.*` ou `ci_test.*` s’applique sans exclusion implicite. Par exemple, `session.type = 'synthetics'` renvoie les sessions synthétiques. Il en va de même pour une requête ciblant un seul `session.id`. Sans requête de ce type, l’explorateur affiche l’activité des utilisateurs réels. La liste des valeurs de `session.type` couvre tous les types de sessions.
- Avec l’API, la même règle s’applique aux filtres de `search`, `aggregate`, `facets` et `histogram`.

## Tests d’une application

Définissez la même variable globale avant l’exécution de tout script de la page. Dans Playwright :

```ts
await page.addInitScript((id) => {
  window.__MOLESIGNAL_TEST_CONTEXT__ = { type: 'ci_test', test_execution_id: id };
}, process.env.GITHUB_RUN_ID);
```

Le SDK attribue à `window.__MOLESIGNAL_RUM_SESSION__` l’identifiant de la session enregistrée. Le test lit cette valeur pour créer un lien vers la session, puis quitte la page à la fin du parcours pour que le SDK envoie les données en attente.

<Note>
Pour que la session indique ce qui l’a déclenchée, la page doit utiliser une version du SDK navigateur strictement supérieure à 0.2.0. La politique de trafic sortant du test s’applique aux requêtes du SDK comme à toutes les autres. Si elle n’autorise pas l’accès à MoleSignal, le test échoue.
</Note>
