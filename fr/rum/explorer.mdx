L’explorateur affiche les données des utilisateurs réels, à raison d’un type de ligne à la fois. Retrouvez ces lignes avec une requête sur les champs,
comptez-les dans le temps et ouvrez une ligne sans quitter la liste. Ouvrez **RUM → Explorateur**. La lecture des données RUM
nécessite l’autorisation `rum.events.read`.

Si l’espace de travail ne contient encore aucune [application](/fr/rum/applications), l’explorateur indique comment en créer une.

## Types de lignes

Les onglets sous le titre déterminent ce que représente chaque ligne. Une ligne affiche la version la plus récente de l’entité : une vue signalée
plusieurs fois n’apparaît qu’une fois, avec les derniers totaux.

| Onglet | Ce que représente une ligne | Ce que signale l’histogramme |
|---|---|---|
| **Sessions** | Une session reconstituée à partir de ses vues : utilisateur, page d’entrée, durée, nombres de vues, d’actions et d’erreurs, navigateur et pays. | Sessions avec des erreurs |
| **Vues** | Une vue de page ou d’écran : temps de chargement, Web Vitals et compteurs. | Vues avec des erreurs |
| **Actions** | Un clic, un appui ou une action personnalisée. | Actions associées à un signal de frustration |
| **Erreurs** | Une erreur : message, type, source, gestion et trace de pile. | — |
| **Ressources** | Une requête : méthode, URL, statut, durée, taille et trace. | Requêtes en échec, avec un statut de `400` ou plus, ou de `0` |
| **Tâches longues** | Une image d’animation longue, une tâche longue ou une image figée. | — |
| **Journaux** | Une [entrée du journal du navigateur](/fr/rum/logs) : niveau, message, enregistreur et page. | Entrées de niveau `error` |

Les lignes correspondent à des utilisateurs réels. Une requête qui mentionne `session.type`, `synthetics.*` ou `ci_test.*` inclut aussi les [sessions générées par des tests](/fr/rum/test-traffic).

## Écrire une requête

L’éditeur de requêtes est replié par défaut. Pour l’ouvrir, sélectionnez **Développer** ou l’icône **Code** ou **Éditeur visuel**.

Dans **Code**, saisissez une requête qui combine des comparaisons sur les champs du type sélectionné avec `AND`.

| Requête sur les champs | Signification |
|---|---|
| `usr.id = 'u-42'` | Le champ a exactement cette valeur. |
| `view.url_path contains 'checkout'` | Le champ contient ce texte. |
| `browser.name != 'Safari'` | Le champ a une autre valeur. |
| `resource.duration >= 1000000000` | Comparez les nombres avec `=`, `!=`, `>`, `>=`, `<` et `<=`. |
| `error.issue_id = '3f9c2a71e0b4c8d1'` | Les erreurs d’un même [problème](/fr/rum/errors). |
| `error.fingerprint = ''` | Une valeur vide vérifie que le champ n’a aucune valeur. `!= ''` vérifie qu’il en a une. |
| `feature_flags.checkout_v2 = 'treatment'` | Une clé d’un champ JSON : `feature_flags`, `context`, `usr.extra` ou `view.custom_timings`. Consultez la section sur les [indicateurs de fonctionnalité](/fr/rum/feature-flags). |

MoleSignal stocke les durées en **nanosecondes** : `1000000000` correspond à une seconde. Le tableau affiche chaque durée dans l’unité la mieux adaptée.

L’explorateur recherche les mots saisis hors des comparaisons dans les colonnes de texte du type sélectionné, comme l’utilisateur, la page,
le message d’erreur et l’URL de la requête. Il ignore toute comparaison sur un champ absent de ce type ou sur un champ contenant un
document JSON entier plutôt que sur l’une de ses clés, et affiche la mention **Ignoré**.

L’**Éditeur visuel** affiche la même requête sous forme de filtres. Sélectionnez **Filtrer**, puis choisissez un champ, une comparaison et une valeur.

Cliquez sur **Exécuter la requête** ou appuyez sur `⌘ Enter` ou `Ctrl+Enter` dans l’éditeur. Cliquez sur **Actualiser** pour charger de nouveau les
résultats. La plage temporelle se trouve à côté du bouton d’exécution. L’explorateur affiche par défaut les dernières 24 heures.

## Champs

La liste **Champs**, à côté des résultats, regroupe tous les champs du type sélectionné en trois catégories : **Champs affichés**,
qui correspondent aux colonnes du tableau ; **Champs indexés**, qui permettent de filtrer sans lire chaque ligne ; et **Autres champs**. Saisissez du texte dans
**Rechercher un champ** pour affiner la liste.

- Cliquez sur le nom d’un champ pour afficher ses valeurs les plus fréquentes et leur nombre d’occurrences parmi les lignes qui correspondent à la requête.
- **Filtrer sur cette valeur** et **Exclure cette valeur** ajoutent la comparaison à la requête. Sélectionnez une valeur déjà
  filtrée pour supprimer le filtre.
- Cliquez sur l’icône en forme d’œil d’un champ pour l’ajouter au tableau ou l’en retirer. Cliquez sur **Rétablir les colonnes par défaut** pour réinitialiser le tableau.
- Cliquez sur le bouton plus d’un champ pour commencer une comparaison sur ce champ dans la requête.

## Résultats et histogramme

Le tableau affiche une ligne par résultat, de la plus récente à la plus ancienne, avec l’horodatage dans la première colonne. Un repère sur le bord gauche
signale les lignes présentant un problème. Choisissez le nombre de lignes par page : 100, 200, 500, 1 000, 2 000 ou 5 000. Parcourez les pages avec
**Précédent** et **Suivant**.

L’histogramme au-dessus du tableau compte **toutes** les lignes qui correspondent à la requête sur la plage temporelle, pas seulement celles de la page chargée,
et indique le nombre de lignes que représente chaque barre. Faites glisser le pointeur sur les barres pour réduire la plage temporelle. Sélectionnez **Masquer l’histogramme** pour
le fermer. L’explorateur conserve ce choix.

**Télécharger** exporte les lignes qui correspondent à la requête dans un fichier CSV, dans la limite des 5 000 plus récentes, avec les colonnes du tableau. Le
navigateur génère le fichier à partir des seules données accessibles en lecture : les données masquées le restent dans le fichier.

## Visualiser les lignes sous forme de chiffres

La rangée d’icônes en haut à droite des résultats permet de choisir comment afficher les lignes qui correspondent à la requête. Le nom de chaque visualisation s’affiche
au survol. **Liste** affiche les lignes dans un tableau et
s’ouvre par défaut. Les cinq autres visualisations calculent des valeurs sur **toutes** les lignes qui correspondent à la requête dans la plage temporelle, pas seulement sur
la page chargée. Leurs chiffres sont donc cohérents avec la liste affichée à côté.

| Visualisation | Affichage | Paramètres |
|---|---|---|
| **Série temporelle** | Une valeur au fil du temps. Les percentiles, les moyennes, les minimums et les maximums s’affichent sous forme de courbes. Les nombres de lignes et les sommes s’affichent sous forme de barres empilées par groupe. | Une mesure, jusqu’à deux regroupements et jusqu’à 20 séries |
| **Classement** | Les groupes classés selon une valeur, avec une barre par groupe suivie de sa valeur. | Une mesure, un regroupement |
| **Tableau** | Une ligne par groupe et une colonne par valeur. | Jusqu’à six mesures et deux regroupements |
| **Carte** | Les pays sur un planisphère, avec une teinte qui varie selon leur valeur par rapport à la valeur maximale. | Une mesure ; le champ `geo.country_iso_code` définit les groupes de lignes |
| **Distribution** | La répartition des valeurs d’une mesure : une barre par intervalle de valeurs, avec des repères pour les 50e, 75e, 95e et 99e percentiles. | Une mesure ; les barres couvrent les valeurs du minimum au 99e percentile, et la dernière compte les valeurs au-delà de ce seuil |

La carte offre un zoom allant de la vue mondiale à un grossissement de 8×. Utilisez les boutons dans le coin de la carte, la molette ou un geste de pincement (centrés sur le pointeur),
ou double-cliquez, puis faites glisser la carte agrandie pour la déplacer. Quand la carte a le focus, `+` et `-` règlent le zoom, `0` rétablit la vue mondiale
et les touches fléchées déplacent la carte agrandie. Un repère indique l’emplacement des pays trop petits pour être visibles, comme Singapour ou Malte.
Survolez un pays pour lire sa valeur. Les contours reprennent les frontières de Natural Earth à l’échelle 1:10m,
simplifiées et représentées selon le point de vue de la Chine, sans l’Antarctique. Selon cette représentation, Taïwan, Hong Kong et Macao font partie de la Chine. Taïwan forme une
zone distincte sans tracé de frontière, ce qui permet d’afficher les lignes qui s’y rapportent dans une teinte distincte. La carte de disponibilité de la
[supervision synthétique](/fr/synthetics) utilise les mêmes contours.

Sélectionnez un groupe dans un classement ou un tableau pour limiter la requête à ce groupe. Sélectionnez-le de nouveau pour retirer le filtre. Sélectionnez un en-tête de colonne
pour trier le tableau selon cette colonne : le serveur effectue le tri et renvoie les premières lignes de ce classement, au lieu de retrier
les premières lignes d’un autre classement. Cliquez sur une série temporelle pour épingler son infobulle. Dans celle-ci, **Inclure** limite la requête à la série sous le pointeur et
**Exclure** l’en retire. Faites glisser le pointeur sur le graphique pour réduire la plage temporelle, comme dans l’histogramme.

Si la mesure porte sur **Largest Contentful Paint**, **Interaction to Next Paint** ou **Cumulative Layout Shift**, le
graphique affiche respectivement des secondes, des millisecondes ou un score. Deux lignes en pointillés séparent les niveaux « bon », « à améliorer » et « médiocre »
(2,5 s et 4 s, 200 ms et 500 ms, 0,1 et 0,25). Dans un classement ou un tableau, la couleur des valeurs indique leur niveau.

### Paramètres de calcul

Dans les visualisations chiffrées, ces paramètres s’affichent en haut à droite des résultats, avant la rangée d’icônes.
Chaque modification prend effet immédiatement.

- **Mesure** applique une fonction à un champ. `count` compte les lignes. `count_distinct` compte les valeurs distinctes d’un champ, comme
  `session.id` ou `usr.id`. `sum`, `avg`, `min`, `max`, `p50`, `p75`, `p90`, `p95` et `p99` prennent un champ numérique. Les
  percentiles sont des estimations. MoleSignal stocke les durées en nanosecondes et les affiche dans l’unité la plus adaptée. Sélectionnez une mesure pour
  la modifier, ou sélectionnez **Mesure** pour en ajouter une à un tableau.
- **Regrouper par** répartit les lignes selon les valeurs d’un champ, et **Puis par** affine le regroupement selon un deuxième champ. Les lignes sans valeur dans le champ
  entrent dans le groupe **(aucune)**. Les champs de type mesure, horaire ou document JSON ne peuvent pas servir au regroupement.
- **Compartiment** définit la durée que représente chaque point d’une série temporelle. **Automatique** divise la plage en une trentaine de points et aligne le début de chacun sur un
  multiple de cette durée selon l’horloge de la page. Seules les durées qui divisent la plage en 2 à 300 points sont proposées.
- **Premiers résultats** fixe le nombre de groupes à afficher : 3 à 20 dans une série temporelle, 5 à 100 dans un classement ou un tableau.
- **Champ** définit la valeur dont la distribution s’affiche. Par défaut, il s’agit de la valeur qui caractérise le mieux le type de données : le temps de chargement d’une vue ou la durée d’une requête.

L’explorateur compte les lignes conservées. Lorsque l’application [ne conserve qu’une partie de ses sessions](/fr/rum/sampling),
les pages de totaux extrapolent les chiffres à l’ensemble des sessions, contrairement à l’explorateur : sa liste, son histogramme et ses autres
visualisations comptent uniquement les lignes stockées.

Par défaut, un classement ou un tableau utilise le champ de classement le plus courant pour chaque type : le navigateur pour les sessions, la page pour les vues et
les tâches longues, la cible pour les actions, le type d’erreur pour les erreurs et l’hôte pour les ressources. Par défaut, une série temporelle compte les
lignes sans les regrouper. Si le calcul dépasse le délai imparti, l’explorateur affiche **Non disponible** à la place des valeurs.
Réduisez la plage temporelle ou affinez la requête, puis relancez-la.

L’adresse contient la visualisation et ses paramètres de calcul. Copiez-la depuis la barre d’adresse pour partager le graphique : `viz` vaut
`timeseries`, `toplist`, `table` ou `map` (la liste omet ce paramètre). `m` indique une mesure, comme `count` ou
`p75:view.performance.lcp.timestamp`, et se répète pour chaque mesure. `by` se répète pour chaque champ de regroupement. `bucket` indique une durée, comme `5m` ou
`1h`. `top` fixe le nombre de groupes, et `sort` et `dir` définissent le tri d’un tableau. Un changement de type de données conserve la visualisation et
supprime `m`, `by` et `sort`, qui dépendent des champs du type précédent. Pour récupérer les valeurs, utilisez
[`aggregate`](/fr/api/rum#mesurer-les-lignes).

## Tableaux de bord et alertes

Dans la barre de requête, **Ajouter au tableau de bord** et **Nouvelle alerte** reprennent les données affichées dans l’explorateur. Ces deux actions ne sont disponibles qu’après le chargement des champs du
type de données.

### Ajouter au tableau de bord

**Ajouter au tableau de bord** crée un panneau à partir des données affichées, dans un **Nouveau tableau de bord** ou sous les panneaux d’un **Tableau de bord
existant**. Le panneau lit les mêmes lignes avec SQL : il reprend les filtres, les mots recherchés, les mesures, les groupes, l’ordre et le nombre de groupes,
sur la plage temporelle du tableau de bord. Comme dans l’explorateur, il compte les lignes stockées : chaque vue ou session compte une seule fois, dans sa
version la plus récente (`rum_views_latest`, `rum_sessions_latest`). Il exclut les sessions issues des tests synthétiques et de la CI, sauf si
la requête mentionne `session.type`, `synthetics.*` ou `ci_test.*`.

| Explorateur | Panneau du tableau de bord |
|---|---|
| **Série temporelle** | Une série temporelle par groupe. Les décomptes et les sommes s’affichent sous forme de barres empilées par groupe, les autres mesures sous forme de courbes. Comme dans l’explorateur, seuls les groupes les mieux classés sur l’ensemble de la plage temporelle s’affichent. |
| **Classement** | Des barres horizontales classées selon la première mesure. |
| **Tableau** | Un tableau avec une colonne par mesure. |
| **Distribution** | Des barres : 40 intervalles de la valeur la plus basse au 99e percentile, le dernier comptant les valeurs au-delà de ce percentile. Le découpage est recalculé pour la plage temporelle du tableau de bord. |
| **Liste** | Le nombre de lignes correspondantes au fil du temps, comme dans l’histogramme au-dessus de la liste. |
| **Carte** | Les tableaux de bord n’affichent pas de carte : des barres horizontales représentent les 20 pays les mieux classés. |

Les durées sont exprimées en millisecondes et les autres valeurs conservent leur unité. Les colonnes gardent leur nom, par exemple
`p75 Loading`.

La variable **Intervalle** du tableau de bord (`${interval}`) découpe la série temporelle en tranches de 1 minute, 5 minutes, 15 minutes, 1 heure ou
1 jour. Un nouveau tableau de bord reçoit cette variable, avec la valeur la plus proche de la largeur des barres affichées dans l’explorateur. Si un tableau de bord existant n’a pas cette variable,
l’ajout du panneau l’ajoute aussi. La boîte de dialogue le signale. Un nouveau tableau de bord s’ouvre sur la plage temporelle de l’explorateur, sauf si cette plage est
fixe, et porte le tag `rum`.

La création d’un tableau de bord nécessite `dashboards.create`. L’ajout d’un panneau nécessite `dashboards.edit` sur le tableau de bord. Les tableaux de bord RUM intégrés
sont en lecture seule et ne figurent pas parmi les options. L’instruction SQL du panneau provient de
[`panel-statement`](/fr/api/rum#requête-sql-d’un-panneau-de-tableau-de-bord).

### Nouvelle alerte

**Nouvelle alerte** ouvre l’éditeur de règles d’alerte sur la valeur **[Requête de l’explorateur](/fr/rum/alerts#requête-de-l’explorateur)** : les lignes du
type sélectionné, filtrées par la requête, et la première mesure. Choisissez une **Alerte de seuil** ou une **Alerte d’anomalie** qui compare la valeur à celle du même créneau horaire
les jours précédents. La création de la règle nécessite `alerts.rules.manage`.

Le menu indique d’abord ce que la règle surveille et ce qu’elle ne reprend pas :

- Une règle surveille une seule valeur : la première mesure. Elle ne reprend ni les autres mesures, ni le type de visualisation, ni les groupes, ni leur ordre, ni le nombre
  de groupes : une règle RUM ne se décline pas par groupe.
- Pour une **Liste**, la règle surveille le nombre de lignes correspondantes. Pour une **Distribution**, elle surveille le 75e percentile du champ.
- Une règle porte sur une seule application : celle que la requête désigne avec `application.id = '…'` ou l’unique application de l’espace de travail.
  Dans les autres cas, sélectionnez l’application dans l’éditeur. Si la requête contient `env = '…'`, l’éditeur renseigne aussi l’environnement.
- La règle ne reprend pas la plage temporelle : elle utilise sa propre fenêtre d’évaluation de 5 minutes, 15 minutes ou 1 heure.

## Ouvrir une ligne

Cliquez sur une ligne ou sélectionnez-la avec les touches fléchées, puis appuyez sur `Enter`. Un volet s’ouvre à côté de la liste, avec la même disposition que
le volet d’un log. L’en-tête indique le nom, le type et l’horodatage de la ligne. Sous l’en-tête figurent le contenu complet de la ligne (le message
d’une erreur ou d’un log, la méthode et l’URL d’une requête), les mesures propres à son type (par exemple, la durée d’une session, ses vues,
ses actions, ses erreurs et ses signaux de frustration), ainsi que l’utilisateur concerné et le lieu. Pour une session enregistrée, sélectionnez **Regarder la
rediffusion**. Plus bas, la section **Champs** répertorie les champs qui ne figurent pas plus haut. Recherchez un champ par un mot de son nom ou de sa
valeur. La section **JSON** affiche la ligne entière. Faites glisser le bord gauche du volet pour le redimensionner.

- Appuyez sur `J` ou `K`, ou cliquez sur les flèches de l’en-tête, pour passer à la ligne suivante ou précédente. L’en-tête indique la position de la ligne et
  le nombre total de lignes.
- **Ouvrir la session** ouvre la session à laquelle appartient la ligne. **Copier la ligne au format JSON** copie la ligne.
- Une erreur s’ouvre sur **Empilement**.
- Une vue de navigateur s’ouvre dans un volet élargi sur **Cascade de chargement** : les requêtes de la vue et les tâches longues qui l’ont bloquée figurent sur un même axe
  temporel, à partir du début de la vue. Consultez [le chargement d’une vue](/fr/rum/performance#chargement-d’une-vue).
- La fermeture du volet replace le focus sur la ligne.

## Ouvrir une session

Ouvrez la page de la session depuis l’explorateur. Elle affiche :

- le **Lecteur de session** si la session contient un enregistrement du DOM, ou la **Chronologie des actions** dans le cas contraire. L’échelle de lecture
  comporte un repère pour chaque erreur (rouge), chaque action qui signale une frustration (orange) et chaque page après la première
  (gris) ;
- les **Outils de développement** sous le lecteur : **Erreurs**, **Réseau** et **Performances**, décrits ci-dessous ;
- le **Contexte utilisateur** : l’utilisateur, l’appareil, la localisation, l’adresse IP, l’application, l’environnement, la version et
  la durée ;
- **Notifications d’alerte** : la première et la dernière page de la visite, et **Problèmes détectés** : les erreurs, les plantages, les signaux de frustration et
  les tâches longues ;
- la **Chronologie des événements** : toutes les vues, actions, requêtes, erreurs et tâches longues de la session, dans l’ordre chronologique ;
- les **Traces associées** : les traces du backend dont une requête de la session contient l’identifiant (**Lien direct**) ou, si aucune requête n’en contient,
  les traces exécutées pendant la session (**Corrélation temporelle**). Chaque trace s’ouvre dans **Traces**.

L’en-tête d’une trace dans **Traces** propose **Session utilisateur** lorsqu’une requête de la session contient l’identifiant de la trace.

L’en-tête de la session propose **Copier le lien vers ce moment**, qui copie l’adresse avec la position actuelle de lecture, et
**Ajouter à une liste de lecture**, qui ajoute la session à une [liste de lecture](/fr/rum/playlists).

### Outils de développement

Sous le lecteur figurent trois onglets, chacun avec un compteur : **Erreurs**, **Réseau** et **Performances**. Ils affichent les événements de la
session et suivent la lecture.

- Un trait à gauche souligne la ligne du dernier événement survenu au moment affiché. La liste défile pour
  garder cette ligne visible pendant la lecture ou lors d’un déplacement dans l’enregistrement, sans faire défiler la page.
- Cliquez sur une ligne pour placer la lecture au moment correspondant et la mettre en pause. Les temps indiquent les minutes et secondes écoulées depuis le début de l’enregistrement, comme sur l’échelle de
  la barre de progression. Pour une session sans enregistrement, les temps partent du début de la session :
  chaque ligne indique seulement ce qui s’est passé, sans contrôler la lecture.
- **Erreurs** répertorie les erreurs de la session dans l’ordre chronologique : l’heure, le type, le message et le problème auquel
  l’erreur se rattache. Ce problème s’ouvre dans [Erreurs](/fr/rum/errors). Les outils s’ouvrent sur cet onglet si la session
  comporte une erreur, et sur **Réseau** dans le cas contraire.
- **Réseau** répertorie les requêtes d’une vue : l’heure, la méthode, l’hôte et le chemin, le statut, le type, la durée et
  la taille. Une barre situe chaque requête dans la chronologie des requêtes de la vue. Sélectionnez la vue dans **Afficher**. Par défaut, l’onglet affiche
  la vue en cours de lecture. Cliquez sur **Suivre la lecture de la session** pour rétablir ce comportement. **Toutes les vues** répertorie toutes les requêtes de la session. **Afficher** filtre
  les requêtes lentes (500 ms ou plus) ou celles qui ont échoué. **Cascade** présente le chargement de la vue comme dans l’explorateur
  (voir [le chargement d’une vue](/fr/rum/performance#chargement-d’une-vue)).
- **Performances** contient une ligne par vue de la session, avec les métriques LCP, INP et CLS dans la couleur de leur note, ainsi que le nombre de requêtes et
  de tâches longues. Cliquez sur une ligne pour ouvrir la cascade de la vue dans **Réseau**.
- **Journaux** répertorie les [entrées de journal écrites par la page](/fr/rum/logs) et met en évidence celle atteinte pendant la lecture. Cliquez sur une ligne pour accéder au moment correspondant.
- **Commentaires** regroupe les [commentaires sur des moments de la session enregistrée](/fr/rum/session-replay#commentaires).

L’adresse indique l’onglet, la vue et le mode d’affichage des requêtes
(`tab`, `view`, `display` et `show`), ainsi que la position initiale de lecture (`at`, en microsecondes depuis l’époque Unix). La
lecture reste en pause à cette position. Les liens de [Frustration](/fr/rum/frustration) ouvrent une session au moment indiqué.

## Onglets, partage et adresse

L’explorateur utilise les mêmes onglets de requête que **Journaux** : ouvrez plusieurs requêtes côte à côte, renommez-les et scindez la page.
L’adresse de la page représente la requête affichée. Elle contient le type (`type`), la requête sur les champs (`q`), la plage temporelle (`time`) et,
si les lignes s’affichent sous forme de chiffres, le mode d’affichage (voir [Afficher les lignes sous forme de chiffres](#visualiser-les-lignes-sous-forme-de-chiffres)). Copiez l’adresse pour partager la requête. **Partager** copie un lien avec la plage temporelle de votre choix.

**Vues enregistrées** conserve sous un nom la configuration affichée pour la retrouver plus tard : le type, la requête, le mode d’affichage des lignes et une plage temporelle
relative (« la dernière heure »). À l’ouverture de la vue, choisissez une plage si la plage d’origine était fixe. Chaque compte peut enregistrer jusqu’à 30 vues, accessibles dans tous les
navigateurs où le compte est connecté. Pour partager une vue, envoyez son adresse.

## Sources de données de l’explorateur

Les lignes proviennent des [flux RUM](/fr/rum/events#où-sont-stockés-les-événements). Le moteur exécute la requête avec les
mêmes règles de masquage et les mêmes limites que **Journaux**. Si le calcul d’un total prend trop de temps, l’explorateur l’indique comme indisponible. Les colonnes et leurs
unités correspondent aux champs du [format des événements](/fr/rum/events).
