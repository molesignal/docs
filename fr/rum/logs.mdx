Le SDK navigateur associe chaque journal à la session et à la vue dans lesquelles il a été généré. Le journal donne ainsi accès à la relecture de la session, et la session affiche les journaux de la page. Le SDK n’envoie rien tant qu’aucun journal n’est généré et que la collecte des messages de la console n’est pas activée. Les journaux nécessitent la version 0.3.0 ou ultérieure du [SDK navigateur](/fr/rum/browser-sdk).

```ts
import { molesignalRum } from '@molesignal/browser-rum';

molesignalRum.logger.info('cart opened', { items: 3 });

const payments = molesignalRum.createLogger({ name: 'payments', level: 'warn', context: { provider: 'stripe' } });
payments.error('payment declined', { code: 402 }, error);
```

Un journaliseur ignore les messages dont le niveau est inférieur au seuil configuré et accepte les niveaux `debug`, `info`, `warn` et `error`. Passez une erreur en troisième argument pour conserver son type et sa trace de pile dans le journal.

Pour transmettre aussi les messages que la page écrit dans la console :

```ts
init({ /* … */ forwardConsoleLogs: ['warn', 'error'] }); // or 'all'
```

Les messages de la console sont transmis tels quels. Laissez cette option désactivée si la console peut contenir des données personnelles, ou consultez la liste des données que l’application [supprime à l’ingestion](/fr/rum/privacy#retirer-les-données-sensibles-à-l’ingestion). Ce filtrage s’applique aussi au texte et à la trace de pile des journaux.

## Où trouver les journaux

- Sur la [page de la session](/fr/rum/explorer#ouvrir-une-session), l’onglet **Journaux**, sous la relecture, affiche les journaux dans l’ordre et met en surbrillance celui qui correspond à la position de lecture. Cliquez sur une ligne pour accéder au moment correspondant.
- Dans l’[explorateur](/fr/rum/explorer), **Journaux** est un type de ligne.
- Dans **Journaux**, `rum_logs` est un flux de journaux standard, avec les champs `level` et `message`. L’histogramme des niveaux et les autres fonctionnalités s’utilisent comme pour n’importe quel flux de journaux.

L’application ne conserve aucun journal pour les sessions qu’elle [écarte](/fr/rum/sampling). Les journaux n’entrent pas dans les compteurs de la vue.

## Erreurs du SDK

Si le SDK rencontre un problème (le serveur rejette un événement ou `beforeSend` lève une exception), il le signale dans un journal avec le journaliseur `molesignal-rum` et l’origine `sdk`. Le SDK ne signale chaque problème qu’une fois et limite ces journaux à quelques entrées par chargement de page. Il ne journalise pas les erreurs de transmission au serveur, car les journaux ne lui parviendraient pas non plus. Désactivez cette journalisation avec `trackSdkErrors: false`. Le SDK appelle `onError` dans les deux cas.

## Champs

| Colonne | Description |
|---|---|
| `level` | `debug`, `info`, `warn` ou `error`. |
| `message` | Le texte du journal. |
| `log.id` | L’identifiant du journal. |
| `log.logger` | Le nom du journaliseur : `console` pour la console, `molesignal-rum` pour le SDK lui-même. |
| `log.origin` | `logger`, `console`, `report` ou `sdk`. |
| `log.error_type`, `log.stack` | Le type et la trace de pile de l’erreur signalée dans le journal. |
