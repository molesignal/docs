Une **table d’enrichissement** est une petite table de correspondance stockée dans MoleSignal qui associe des clés à des enregistrements. Une
transformation de [pipeline](/fr/pipelines) y recherche une clé pour enrichir les événements avec des données de référence : associez un
`service` à l’équipe responsable, un identifiant de compte à un niveau d’abonnement ou un code de région à un nom de région,
sans interroger un stockage externe sur le chemin critique.

## Liste des tables

Ouvrez **Étendre les tables**. L’en-tête indique le nombre de tables et d’enregistrements. Pour chaque table, la liste affiche la clé de recherche et
les champs, le nombre d’enregistrements, les utilisations, la dernière mise à jour et l’état : **Opérationnel** ou
**Vide**. Filtrez par état ou par utilisation (**Utilisée** ou **Non utilisée**) et recherchez par nom.

## Créer une table

Sélectionnez **Nouvelle table d’enrichissement**. L’assistant comporte deux étapes.

<Steps>
  <Step title="Définir le schéma">
    Saisissez le nom du **Tableau** et une **Description**. Choisissez comme **Clé de recherche** le champ qui identifie un
    enregistrement, par exemple `customer_id`, `service` ou `region_code`. Ajoutez des **Champs de valeur** en indiquant un nom dans **Champ**,
    un **Type** (**Chaîne de caractères**, **Nombre**, **Booléen** ou **Objet**), si le champ est **Obligatoire**,
    et une description. Ne définissez aucun champ de valeur pour stocker des enregistrements JSON à la structure libre. Une table accepte
    jusqu’à 100 champs de valeur ; les noms de champs peuvent contenir des lettres, des chiffres, `.`, `-` et `_`.
  </Step>
  <Step title="Ajouter ou importer des données">
    Choisissez **Commencer avec une table vide** pour ajouter les enregistrements plus tard, ou **Coller du JSON** pour les charger immédiatement : fournissez un tableau JSON
    dont chaque enregistrement contient la clé de recherche, ou un objet qui associe chaque clé à son enregistrement.
  </Step>
</Steps>

Sélectionnez **Créer une table d’enrichissement**.

## Enregistrements

Ouvrez une table. L’onglet **Enregistrements** répertorie les enregistrements ; recherchez-les par clé de recherche ou par valeur de champ.

| Action | Effet |
|---|---|
| **Ajouter un enregistrement** | Saisissez la clé de recherche et les valeurs des champs en **Mode formulaire** ou en **Mode JSON**. Si la clé existe déjà, MoleSignal affiche un avertissement avant de remplacer l’enregistrement. |
| **Modifier l’enregistrement** | Modifie les valeurs d’un enregistrement. |
| **Afficher le JSON** | Affiche l’enregistrement complet, y compris les champs qui n’apparaissent pas dans les colonnes de la table. |
| **Supprimer l’enregistrement** | Supprime définitivement l’enregistrement. |
| **Importer des données** | Ajoute plusieurs enregistrements à la fois à partir d’un fichier JSON (un tableau ou un objet qui associe chaque clé à un enregistrement), d’un fichier CSV dont la première ligne contient les noms des champs, ou de données JSON ou CSV collées. Les données doivent contenir la colonne de la clé de recherche. Le récapitulatif indique combien d’enregistrements l’importation traitera et combien remplaceront des enregistrements existants. |

## Schéma, utilisation et paramètres

| Onglet | Contenu |
|---|---|
| **Schéma** | Affiche la clé de recherche et les champs de valeur. Sélectionnez **Modifier les champs** pour ajouter des champs ou modifier leur description et l’option **Obligatoire**. Tant que la table contient des enregistrements, il est impossible de renommer ou de supprimer les champs existants, ou d’en changer le type. Une table vide autorise toutes ces modifications. Le nom de la table et la clé de recherche restent immuables. |
| **Utilisation** | Répertorie les pipelines et les requêtes enregistrées qui utilisent la table. Consultez cet onglet avant de modifier ou de supprimer la table. |
| **Paramètres** | Contient les **Informations sur la table** et, dans la **Zone de danger**, l’action **Supprimer la table d’enrichissement**, qui supprime la table et tous ses enregistrements. Les recherches dans cette table renvoient alors `null`. Les écritures d’événements dans cette table échouent, et le pipeline envoie ces événements vers son flux de rejet s’il en possède un. |

## Rechercher une clé dans un pipeline

Un pipeline lit une table avec l’étape [**Consulter une table d’enrichissement**](/fr/pipelines#consulter-une-table-d’enrichissement)
pour copier les valeurs de la ligne dans les champs de l’événement. Il peut aussi appeler
[`lookup(table, key)`](/fr/functions#interroger-les-tables-et-géolocaliser-les-adresses-ip) dans une étape VRL pour obtenir
la ligne :

```ruby
# enrich each event with the service's owning team
.team = lookup("service_meta", .service).team
```

Les deux méthodes fonctionnent dans tous les types de pipelines, y compris les [pipelines d’alertes](/fr/pipelines/alert-events). Un nœud
lit la table dès qu’une étape en a besoin et la conserve en mémoire pendant 30 secondes. Les recherches n’ajoutent donc aucun coût de requête
ou de stockage à l’exécution d’un pipeline. Tout ajout, toute modification ou toute suppression d’enregistrement se répercute dans tous les pipelines
sous 30 secondes. Les tables d’enrichissement appartiennent à l’espace de travail. Tous ses pipelines peuvent les utiliser.

## Alimenter une table depuis un pipeline

Un pipeline planifié peut tenir une table à jour : **Ajouter une destination → Table d’enrichissement** écrit chaque événement
qui traverse le pipeline dans une ligne associée à la valeur de la clé de recherche. Consultez
[Écrire dans une table d’enrichissement](/fr/pipelines#écrire-dans-une-table-d’enrichissement).

## API des tables d’enrichissement

```bash
# upsert a record keyed by "checkout"
curl -X PUT http://localhost:5080/api/v1/extend_tables/service_meta/rows/checkout \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"team":"payments","tier":"gold"}'
```

| Action | Point de terminaison |
|---|---|
| Lister les tables | `GET /api/v1/extend_tables` |
| Lister les enregistrements d’une table | `GET /api/v1/extend_tables/{table}` |
| Insérer ou mettre à jour un enregistrement | `PUT /api/v1/extend_tables/{table}/rows/{key}` |
| Supprimer un enregistrement | `DELETE /api/v1/extend_tables/{table}/rows/{key}` |

## Autorisations

`functions.read` permet de lister les tables et leurs utilisations. La création d’une table nécessite `functions.create`, la modification
des enregistrements et des champs nécessite `functions.edit`, et la suppression d’une table nécessite `functions.delete`.
