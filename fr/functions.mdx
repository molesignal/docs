Les fonctions regroupent des transformations d’événements réutilisables. Ouvrez **Fonctions** pour créer, tester et gérer
les définitions de fonctions indépendamment des pipelines.

## Rechercher une fonction

La liste regroupe les fonctions de l’organisation et les préréglages intégrés. Trois vues en haut
de la liste permettent de la filtrer et affichent chacune le nombre de fonctions :

| Vue | Contenu |
|---|---|
| **Tous** | Toutes les fonctions de l’organisation et les préréglages. |
| **Vos fonctions** | Les fonctions créées par l’organisation. |
| **Préréglages** | Les fonctions en lecture seule fournies avec MoleSignal. |

La recherche porte sur le nom des fonctions et la description des préréglages. Cliquez sur une fonction de
l’organisation pour l’ouvrir dans l’atelier.

## Langages

| Langage | Disponibilité | Cas d’usage recommandés |
|---|---|---|
| VRL | Intégré | Analyse, normalisation, filtrage, masquage et enrichissement. |
| JavaScript | Intégré | Logique plus facile à exprimer en JavaScript. |
| LLM | Configurable via l’API ; nécessite `llm_eval_enabled` et un fournisseur de modèles | Classification ou enrichissement à faible débit à partir de la sortie du modèle. |

VRL et JavaScript s’exécutent dans le binaire de MoleSignal. Aucun des deux ne nécessite de configuration ni d’installation supplémentaire.

MoleSignal valide et compile la fonction lors de l’enregistrement. Un code source non valide ne remplace pas la fonction
active.

L’atelier **Fonctions** prend en charge VRL et JavaScript. Les fonctions LLM s’utilisent via l’API pour des cas avancés :
le code source de la fonction sert d’instruction système, l’événement sert d’entrée au modèle et
`params_schema.output_field` définit le champ de sortie (`_llm_eval` par défaut). Chaque exécution appelle le
modèle. Le paramètre `[functions].llm_eval_enabled` reste donc à `false` par défaut. Consultez la page
[Configuration](/fr/configuration#fonctionnalités-et-intégrations). Pour résumer les événements d’alerte à l’aide d’un
modèle, utilisez l’étape **Résumé par IA** d’un [pipeline d’alertes](/fr/pipelines/alert-events#résumé-par-ia),
qui ne dépend pas de ce paramètre.

## Préréglages intégrés

Les fonctions VRL suivantes sont disponibles en lecture seule dans chaque organisation :

| Fonction | Rôle |
|---|---|
| `add-intake-time` | Ajoute un horodatage d’ingestion pour faciliter le diagnostic de la latence de bout en bout. |
| `normalize-logs` | Analyse le message JSON, ajoute les champs d’environnement et de cluster, puis met `level` en minuscules. |
| `parse-key-value` | Extrait les champs d’un message au format logfmt ou `key=value` et les fusionne avec ceux de l’événement. |
| `redact-email` | Remplace les adresses e-mail dans `message` par une valeur de substitution. |
| `route-by-service` | Normalise le nom du service et en déduit un flux cible propre à ce service (`logs_<service>`) pour guider le routage. |

Chaque ligne de préréglage affiche le badge **Intégré** et sa description dans la langue de l’interface du
compte connecté. Cliquez sur la ligne pour consulter le code source.

Les préréglages sont en lecture seule. Pour en adapter un, sélectionnez **Utiliser comme base** sur la ligne ou dans le panneau du
préréglage. L’atelier ouvre une nouvelle fonction qui reprend le langage et le code source du préréglage, sous le nom
`<preset>-copy`. L’enregistrement crée une fonction dans l’organisation sans modifier le préréglage.

## Écrire et tester une fonction

L’atelier comporte trois parties :

- le nom et le langage de la fonction ;
- **Code source**, l’éditeur, qui affiche l’état de validation du code à côté de son titre ;
- **Exécution de test**, avec l’**Exemple d’entrée** au format JSON et l’**Exemple de sortie**.

Sélectionnez **Exécuter l’exemple** pour tester le code de l’éditeur sur l’événement d’exemple. Il n’est pas nécessaire
d’enregistrer le code au préalable. L’événement transformé s’affiche sous **Exemple de sortie**. Si l’exécution échoue,
le motif de l’échec s’affiche à la place.

**Enregistrer la fonction** et **Annuler** figurent dans la barre de titre de la page, tout comme **Supprimer la fonction** si la
fonction est déjà enregistrée. Si le nom ou le code source est vide, le bouton **Enregistrer la fonction** reste
désactivé et son infobulle indique l’élément manquant.
Dans l’éditeur, utilisez `⌘ Enter` ou `Ctrl+Enter` pour exécuter l’exemple, et `⌘S` ou `Ctrl+S` pour enregistrer.

Le moteur de test appelle `POST /api/v1/functions/run` avec un langage, du code source et un événement d’exemple, puis
renvoie l’événement transformé :

```bash
curl -X POST http://localhost:5080/api/v1/functions/run \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"language":"vrl","source":".service = downcase!(string!(.service))","input":{"service":"Checkout"}}'
```

```json
{ "output": { "service": "checkout" } }
```

Exemple en VRL :

```vrl
.service = downcase!(string!(.service))
.severity = upcase(string(.level) ?? "INFO")
if exists(.customer_id) {
  .customer = lookup("customers", .customer_id)
}
```

## Interroger les tables et géolocaliser les adresses IP

Deux fonctions VRL consultent des données conservées par MoleSignal. Elles fonctionnent lors d’une exécution de test et dans chaque étape VRL
d’un pipeline, y compris dans les pipelines d’alertes.

| Fonction | Valeur renvoyée |
|---|---|
| `lookup("<table>", key)` | La ligne de la [table d’enrichissement](/fr/extend-tables) `<table>` dont la clé est `key`, sous forme d’objet, ou `null`. |
| `geoip_lookup(ip)` | La localisation d’une adresse IPv4 ou IPv6, sous forme d’objet, ou `null`. |

```vrl
# the team that owns the host, from the extend table host_owner
.team = lookup("host_owner", .host).team

# where the client is
place = geoip_lookup(.client_ip)
if is_object(place) {
  .country = place.country
  .city = place.city
}
```

- Aucune des deux fonctions ne renvoie d’erreur. Une table ou une ligne inexistante, une clé qui n’est ni du texte, ni un nombre, ni
  un booléen ou une adresse non valide ou absente de la base de données donnent `null`.
  Un chemin comme `.team` appliqué à `null` donne également `null`.
- Écrivez le nom de la table dans `lookup` sous forme de chaîne littérale. Un nom issu d’un champ ou d’une variable
  empêche la compilation. La recherche convertit les clés numériques ou booléennes en texte : `42` trouve la ligne dont la
  clé est `42`.
- `lookup` consulte les tables d’enrichissement de l’espace de travail. Consultez la page
  [Tables d’enrichissement](/fr/extend-tables#rechercher-une-clé-dans-un-pipeline) pour connaître le délai de prise en compte des modifications
  apportées aux lignes.
- `geoip_lookup` consulte la base de données [DB-IP](https://db-ip.com) City Lite indiquée par
  [`[mmdb].db_path`](/fr/configuration#fonctionnalités-et-intégrations) et renvoie `null` en l’absence de
  cette base. La base ne contient pas les adresses privées. L’objet contient les champs suivants lorsqu’ils sont renseignés dans la
  base de données :

| Champ | Contenu |
|---|---|
| `country` | Le code ISO 3166 du pays, par exemple `DE`. |
| `country_name` | Le nom du pays en anglais. |
| `continent_code` | Le code du continent, par exemple `EU`. |
| `continent` | Le nom du continent en anglais. |
| `region` | Le nom en anglais de la subdivision administrative de premier niveau, par exemple un État ou une province. |
| `city` | Le nom de la ville en anglais. |
| `latitude`, `longitude` | Les coordonnées, en degrés. |

## Fonctions JavaScript

Le code source s’exécute une fois par événement. L’objet global `molesignal` contient l’événement et des fonctions utilitaires :

| Membre | Rôle |
|---|---|
| `molesignal.fields` | L’événement sous forme d’objet. Lisez-le, modifiez-le ou remplacez-le par un nouvel objet. |
| `molesignal.set(name, value)` | Définit la valeur d’un champ. |
| `molesignal.del(name)` | Supprime un champ. |
| `molesignal.now()` | L’heure actuelle en microsecondes depuis le début de l’époque Unix. |
| `molesignal.parse_json(text)` et `molesignal.encode_json(value)` | Convertissent du texte JSON en valeurs et inversement. |
| `molesignal.sha256(text)` | L’empreinte SHA-256 des octets UTF-8 du texte, sous forme de 64 caractères hexadécimaux en minuscules. |

```js
molesignal.set("severity", String(molesignal.fields.level || "info").toUpperCase());
molesignal.set("seen_at", molesignal.now());
molesignal.del("level");
```

Une fonction JavaScript s’exécute dans un moteur isolé soumis aux limites suivantes :

- Toute exécution qui dépasse 50 ms s’arrête avec l’erreur `js timeout 50ms`.
- Chaque fonction dispose d’au maximum 32 MiB de mémoire de tas.
- L’accès réseau, les temporisateurs et `TextEncoder` ne sont pas disponibles.

## Utiliser une fonction

Les étapes de pipeline exécutent du VRL. Dans une étape **VRL personnalisé**, l’option **Partir d’une fonction enregistrée** copie le code source
d’une fonction VRL ou d’un préréglage dans l’étape. Le code y reste modifiable. L’étape conserve sa propre copie :
toute modification ou suppression ultérieure de la fonction laisse le pipeline inchangé.

## Autorisations

- `functions.read` permet de lister et d’ouvrir les fonctions.
- `functions.create` et `functions.edit` permettent de créer et de modifier les définitions de fonctions.
- `functions.run` permet de lancer une exécution de test.
- `functions.delete` permet de supprimer une définition de fonction.
