| Terme | Définition |
|---|---|
| **Alerte** | Rôle qui évalue les règles d’alerte, déclenche les escalades, génère les rapports planifiés et exécute les connecteurs. Consultez [Déploiement par rôle](/fr/deployment/role-based). |
| **Jeton API** | Jeton d’accès au porteur au format `mspat-<36>` qui représente une identité utilisateur ou un compte de service. Consultez [Identité et accès](/fr/identity). |
| **APM** | Surveillance des performances des applications. Les agrégats par service, transaction, dépendance, erreur et version sont bornés et dérivés des spans de traces. Consultez [APM](/fr/apm). |
| **Arrow Flight SQL** | Protocole SQL sur le port `5083` pour les clients de base de données tels que DBeaver, JDBC et ADBC. Désactivé par défaut. Consultez [Connexion avec un client de base de données](/fr/query/database-clients). |
| **Catalogue** | Registre dans PostgreSQL qui répertorie les fichiers Parquet et les index associés à chaque flux. |
| **Clé de chiffrement** | Clé racine définie dans `MS_CIPHER_KEY` qui chiffre les secrets que MoleSignal stocke dans PostgreSQL. Consultez [Liste de contrôle pour la production](/fr/deployment/production-checklist). |
| **Compactage** | Fusion de petits fichiers Parquet en fichiers plus volumineux. Le rôle `compactor` assure le compactage et applique les règles de rétention. |
| **Connecteur** | Intégration gérée avec une plateforme externe. Une source collecte les logs à intervalles planifiés ou les reçoit de la plateforme, et une destination reçoit les données produites par le pipeline. Consultez [Connecteurs](/fr/connectors). |
| **Source de données** | Entrée du catalogue des sources de données qui génère le point de terminaison, le jeton et l’extrait de configuration d’une source. Consultez [Source de données](/fr/intake). |
| **Politique d’escalade** | Liste ordonnée de destinataires des notifications, avec des délais d’accusé de réception. Consultez [Gestion des alertes](/fr/alerting). |
| **Table d’enrichissement** | Table de correspondance entre clés et enregistrements. Les pipelines consultent cette table pour enrichir les événements et peuvent y écrire des lignes. Consultez [Tables d’enrichissement](/fr/extend-tables). |
| **Requête fédérée** | Requête qui interroge aussi les clusters distants sélectionnés avec `?clusters=local,<name>`. Consultez [Déploiement par rôle](/fr/deployment/role-based). |
| **Vidage du tampon** | Écriture des données du tampon en mémoire d’un nœud de réception dans des fichiers Parquet et des index dans le stockage objet. |
| **Fonction** | Transformation réutilisable écrite en VRL ou JavaScript. Consultez [Fonctions](/fr/functions). |
| **Incident** | Occurrence d’une alerte qui passe par les étapes d’accusé de réception et de résolution. Consultez [Gestion des alertes](/fr/alerting). |
| **Réception** | Circuit de réception de la télémétrie. Désigne aussi le rôle qui valide la télémétrie, la met en mémoire tampon et l’écrit dans le stockage. Consultez [Source de données](/fr/intake). |
| **Jeton d’ingestion** | Jeton régi par la politique d’autorisations **Ingestion de données** et destiné aux émetteurs et aux pipelines de déploiement. Autorisations : `logs.write`, `metrics.write`, `traces.write`, `profiles.write` et `apm.deploy`. Consultez [Source de données](/fr/intake#jetons-d’ingestion). |
| **Inspection des logs** | Rapport que Mole Agent rédige sur les logs d’une période donnée, à la demande ou à intervalles planifiés. Consultez [Inspections des logs](/fr/logs/inspections). |
| **Mole Agent** | Agent d’exploitation intégré qui examine les problèmes à l’aide du catalogue d’outils. Consultez [Mole Agent](/fr/agent). |
| **Planning d’astreinte** | Rotation qui tient compte du fuseau horaire, accepte des dérogations et sert de cible aux escalades. Consultez [Gestion des alertes](/fr/alerting). |
| **Organisation** | Périmètre d’isolation d’un locataire et d’application de ses politiques. L’interface web le présente comme un espace de travail. Consultez [Concepts clés](/fr/concepts). |
| **Parquet** | Format de fichier en colonnes dans lequel MoleSignal stocke les logs, les métriques et les traces. |
| **Pipeline** | Suite d’étapes qui achemine, normalise, masque et enrichit les événements en temps réel lors de la réception ou à intervalles planifiés. Un pipeline peut aussi modifier les événements d’alerte avant l’ouverture des incidents associés. Consultez [Pipelines](/fr/pipelines). |
| **Administrateur de la plateforme** | Identité utilisateur définie dans `[auth].root_email` qui gère les paramètres de l’ensemble de la plateforme. |
| **Flux de la plateforme** | Flux dans lequel seul MoleSignal écrit, tel que `_audit` ou `_synthetic_results`. Consultez [Flux](/fr/streams#flux-de-la-plateforme). |
| **Agent de sondage** | Processus qui exécute des vérifications synthétiques depuis un emplacement. Un agent intégré s’exécute sur les nœuds `standalone`. Consultez [Surveillance synthétique](/fr/synthetics). |
| **Rôle** | Rôle de processus sélectionné avec `[node].roles` : `standalone`, `router`, `intake`, `querier`, `compactor` ou `alert`. Désigne aussi un ensemble nommé d’autorisations dans IAM, composé de politiques d’autorisations et d’autorisations propres au rôle. |
| **RUM** | Surveillance des sessions réelles dans les navigateurs et les applications mobiles. Consultez [RUM](/fr/rum). |
| **Jeton client RUM** | Jeton associé à une seule application et doté de l’autorisation `rum.write`. Le code dans le navigateur ou dans l’application mobile envoie ce jeton. |
| **Vue enregistrée** | Requête enregistrée avec sa plage temporelle et ses options. |
| **Tâche de recherche** | Requête asynchrone persistante. Les requêtes qui dépassent le seuil de taille deviennent des tâches de recherche et figurent dans **Flux → Tâches de recherche**. Consultez [Requêtes](/fr/query). |
| **Télémétrie interne** | Métriques, traces et profils que MoleSignal collecte sur son propre fonctionnement et enregistre dans le flux réservé `_molesignal`. Consultez [Observabilité interne](/fr/self-observability). |
| **Compte de service** | Identité non humaine destinée aux collecteurs et aux automatisations. Ce compte ne permet pas d’ouvrir une session. Consultez [Identité et accès](/fr/identity). |
| **Mettre en sourdine** | Règle qui suspend temporairement les notifications des alertes correspondantes. Consultez [Gestion des alertes](/fr/alerting). |
| **Mode autonome** | Rôle par défaut qui exécute tous les rôles dans un seul processus. |
| **Page de statut** | Page publique ou privée qui affiche l’état des composants et les incidents. Consultez [Pages de statut](/fr/status-pages). |
| **Flux** | Contrat typé d’un signal : un nom, un type, un schéma et une durée de rétention. Consultez [Flux](/fr/streams). |
| **Type de flux** | L’un des types suivants : `logs`, `metrics`, `traces`, `profiles` ou `extend`. |
| **Moniteur synthétique** | Vérification planifiée, telle qu’une requête HTTP, qui enregistre la disponibilité et la latence. Consultez [Surveillance synthétique](/fr/synthetics). |
| **VRL** | Vector Remap Language, l’un des langages utilisés pour les fonctions de pipeline. |
| **WAL** | Journal d’écriture anticipée : les objets du stockage objet conservent les enregistrements dont la réception a été confirmée jusqu’à leur écriture définitive. |
| **Espace de travail** | Nom que l’interface web donne à l’organisation sélectionnée. |
