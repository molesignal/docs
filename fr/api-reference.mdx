MoleSignal expose une API HTTP versionnée. Les points de terminaison du produit utilisent `/api/v1`. La sonde de santé, les métriques Prometheus, les liens de partage publics et quelques protocoles de compatibilité utilisent aussi d’autres chemins.

## URL de base

Pour une instance locale :

```text
http://localhost:5080/api/v1
```

En production, remplacez l’hôte par l’adresse publique du déploiement, c’est-à-dire la valeur de `[http].external_url`.

## Authentification

Les points de terminaison protégés acceptent un jeton bearer dans l’en-tête `Authorization` :

```http
Authorization: Bearer <token>
```

| Jeton | Comment l’obtenir | Durée de vie |
|---|---|---|
| Jeton d’API | **Paramètres du compte → Jetons d’API**, ou [Émettre un jeton d’API](/fr/api/auth/issue-token). Les jetons ressemblent à `mspat-<36>`. | Jusqu’à révocation, ou jusqu’à l’expiration choisie. |
| Jeton d’ingestion par défaut | `GET /api/v1/me/api-tokens/default`. Limité à `logs.write`, `metrics.write`, `traces.write`, `profiles.write` et `apm.deploy`. | N’expire pas. |
| Jeton client RUM | `GET /api/v1/auth/tokens/rum?applicationId=<id>`. Limité à `rum.write`. | N’expire pas. |

Utilisez un jeton d’API pour les scripts et les collecteurs. Consultez [Source de données](/fr/intake#jetons-d’ingestion) pour les jetons d’ingestion.

L’interface web se connecte avec `POST /api/v1/auth/signin`, qui définit des cookies de session au lieu de renvoyer un jeton. L’en-tête `Authorization` n’accepte pas de jeton de session. Consultez [Se connecter](/fr/api/auth/login).

L’authentification construit un contexte IAM avec le sujet, la portée de l’organisation active ou de la plateforme, et les permissions effectives. L’organisation d’une requête vient toujours de ce contexte. Les corps de requête ne peuvent pas sélectionner une autre organisation.

## Routes publiques et auto-authentifiantes

Quelques routes ne peuvent pas utiliser de jeton bearer d’organisation. Elles valident à la place un identifiant plus restreint ou une politique :

- la connexion, la politique d’inscription et la réinitialisation de mot de passe ;
- `GET /api/v1/healthz` et le chemin racine `/metrics` ;
- l’échange public de partage de ressource et les requêtes de session de partage ;
- les téléchargements de fichiers signés et les avatars publics ;
- les points de terminaison de connecteur push, qui valident un jeton push.

Une route publique n’est pas sans restriction. Son gestionnaire vérifie la politique d’inscription, un jeton de partage, un jeton de téléchargement, une signature ou l’identifiant du connecteur.

## Autorisation

Un point de terminaison peut exiger une ou plusieurs de ces conditions :

- une permission d’organisation telle que `streams.query` ;
- une permission de plateforme telle que `sys.telemetry.read` ;
- la propriété d’une ressource, une relation avec celle-ci ou une autorisation inter-organisations.

`GET /api/v1/iam/capabilities` renvoie les permissions effectives du sujet courant. Ne déduisez pas l’accès d’un nom de rôle ou d’un élément de menu visible.

## Requêtes

- La plupart des corps sont du JSON avec `Content-Type: application/json`.
- Les points de terminaison d’ingestion de compatibilité utilisent la charge utile de leur protocole, comme Protobuf, NDJSON ou un corps compressé avec gzip.
- Les corps de requête d’ingestion supérieurs à 2 MiB, ou 16 MiB pour l’ingestion JSON native, sont rejetés avec `413`.
- Les horodatages sont des entiers en microsecondes depuis l’époque Unix. Un instant est nommé d’après ce qui s’est produit (`createdAt`, `expiresAt`), avec `Time` ajouté lorsqu’un seul mot serait ambigu (`startTime`) ; une durée se termine par `Time` (`p95Time`) sauf si son nom l’indique déjà (`duration`). Les enregistrements de télémétrie natifs utilisent `_timestamp`, également en microsecondes.
- Encodez en URL les identifiants de chemin et les noms de flux.

## Réponses et erreurs

Une réponse réussie est du JSON, sauf si le point de terminaison diffuse un flux ou télécharge un fichier. Une réponse d’erreur comporte un code de statut et un corps JSON avec un code `error` lisible par machine et un `message` :

```json
{
  "error": "unauthorized",
  "message": "unauthorized: missing Authorization Bearer token"
}
```

Une erreur `validation_failed` ajoute un tableau `issues` avec une entrée par champ invalide.

| Statut | `error` | Signification |
|---|---|---|
| `400` | `invalid_argument`, `validation_failed` | La requête ou l’un de ses paramètres est invalide. |
| `401` | `unauthorized` | Le jeton est absent, mal formé, invalide ou expiré. |
| `403` | `forbidden` | La permission, la relation ou la portée est manquante. |
| `404` | `not_found` | La ressource n’existe pas ou n’est pas visible dans la portée autorisée. |
| `409` | `conflict` | Un conflit d’état ou d’unicité. |
| `413` | `payload_too_large` | Le corps dépasse la limite. |
| `429` | `resource_exhausted` | Une limite de débit s’applique. Respectez l’en-tête `Retry-After` lorsqu’il est présent. |
| `499` | `cancelled` | La requête a été annulée. |
| `503` | `unavailable` | Une dépendance est indisponible. |
| `500` | `internal` | Une défaillance interne. Le corps porte le message `internal error`, et les détails restent dans le journal du serveur. |

Une requête dont le corps ne peut pas être analysé échoue avant d’atteindre le point de terminaison. Cette réponse est en texte brut au lieu de JSON :

| Statut | Signification |
|---|---|
| `400` | Le corps n’est pas du JSON valide. |
| `415` | La requête n’a pas de `Content-Type: application/json`. |
| `422` | Un champ est manquant ou a un type incorrect. Le texte nomme le champ. |

Chaque réponse porte les en-têtes `X-Request-Id` et `X-Trace-Id`. Indiquez les deux lorsque vous signalez une défaillance côté serveur.

## Pagination

Les points de terminaison qui peuvent renvoyer de nombreuses lignes acceptent `limit` et `cursor`. Une telle réponse porte `items` et `nextCursor`. Passez `nextCursor` comme `cursor` pour lire la page suivante, et arrêtez-vous lorsqu’il est vide. Les autres points de terminaison de liste renvoient la liste complète. Consultez la page de chaque point de terminaison.

## Requêtes et travaux de longue durée

La famille des requêtes renvoie du JSON classique, diffuse du NDJSON et exécute les requêtes longues sous forme de tâches de recherche asynchrones. Une requête trop volumineuse répond `202` avec un `jobId` et un chemin `monitor`. Les appelants en streaming doivent gérer une livraison partielle et annuler la requête lorsque le résultat n’est plus nécessaire. Consultez [Requête](/fr/query).

Les artefacts volumineux tels que les rapports générés, les blobs de profils et les exports sont livrés sous forme de fichiers via un jeton de téléchargement limité à une portée, plutôt que dans un corps JSON.
