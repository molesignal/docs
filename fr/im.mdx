Mole Agent répond dans Feishu, Slack, DingTalk, WeCom, Google Chat, Microsoft Teams et Telegram via un connecteur configuré dans les paramètres de notification. Mentionnez-le dans un groupe ou envoyez-lui un message direct. Sur Feishu, Slack et Telegram, il ajoute une réaction au message pendant qu’il prépare sa réponse. Sur WeCom, Google Chat et Teams, il répond d’abord « Je regarde… », puis remplace ce message par la réponse. La réponse contient un lien vers la conversation dans MoleSignal.

Ces conversations fonctionnent comme les autres conversations de Mole Agent. Elles s’affichent dans MoleSignal et peuvent s’y poursuivre. Elles sont décomptées du budget quotidien de l’organisation, et leurs réponses sont évaluées comme toutes les autres. Consultez [Qualité](/fr/quality).

## Comment les messages arrivent

| Plateforme | Connecteur | Mode de réception des messages |
|---|---|---|
| Feishu | Application Feishu (`lark_app`) | Connexion persistante de Feishu |
| Slack | Application Slack (`slack_app`) | Mode Socket |
| DingTalk | Application DingTalk (`dingtalk_app`) | Mode Stream |
| WeCom | Bot intelligent WeCom (`wecom_bot`) | Connexion persistante du bot intelligent |
| Google Chat | Application Google Chat (`google_chat_app`) | Récupération depuis un abonnement Cloud Pub/Sub |
| Telegram | Bot Telegram (`telegram_bot`) | Interrogation longue de l’API Bot de Telegram |
| Microsoft Teams | Bot Microsoft Teams (`teams_app`) | Bot Framework envoie les messages à une adresse de rappel publique de MoleSignal |

Sauf pour Teams, un serveur MoleSignal établit une connexion sortante pour recevoir les messages de chaque connecteur. MoleSignal n’a donc pas besoin d’adresse publique. Teams exige une adresse de rappel HTTPS publique ; consultez d’abord [Sécurité pour Teams](#sécurité-pour-teams). Les adresses, les comptes et les autorisations nécessaires pour chaque plateforme figurent dans [Prérequis externes](#prérequis-externes).

## Avant de commencer

- L’activation nécessite l’autorisation `agent.im.manage`. L’envoi de demandes nécessite l’autorisation `agent.use`.
- Configurez un connecteur pour la plateforme dans **Paramètres → Notifications → Connecteurs** (voir le tableau ci-dessus). Une application Slack nécessite un jeton de bot et un jeton d’application. Une application Google Chat nécessite son abonnement Pub/Sub. Consultez [Canaux de notification](/fr/notification-channels).
- Configurez l’URL externe de MoleSignal, `http.external_url`, pour permettre l’association des comptes en libre-service et l’ajout de liens vers les conversations dans les réponses. Pour Teams, utilisez une URL HTTPS : l’adresse de rappel est construite à partir de cette URL. Consultez [Configuration](/fr/configuration).

## Configurez la plateforme

### Feishu

<Steps>
  <Step title="Recevez les événements via une connexion persistante">
    Dans la console de développement Feishu, ouvrez l’application, accédez à **Événements et rappels**, puis choisissez de recevoir les événements via une connexion persistante.
  </Step>
  <Step title="Abonnez-vous aux messages">
    Ajoutez l’événement **Message reçu** (`im.message.receive_v1`).
  </Step>
  <Step title="Recevez les rappels via une connexion persistante">
    Dans **Événements et rappels → Configuration des rappels**, choisissez de recevoir les rappels via une connexion persistante, puis ajoutez le rappel d’action de carte (`card.action.trigger`). Les boutons des cartes d’alerte nécessitent ce rappel. Consultez [Cartes d’alerte](#cartes-d’alerte).
  </Step>
  <Step title="Accordez les autorisations">
    Autorisez l’application à lire les messages directs et les messages de groupe qui la mentionnent, à envoyer des messages en son nom et à ajouter des réactions aux messages. Pour poursuivre la discussion dans un fil sans mentionner le bot à chaque réponse, autorisez aussi la lecture de tous les messages de groupe.
  </Step>
  <Step title="Publiez l’application">
    Publiez une version de l’application, puis ajoutez le bot aux groupes dans lesquels il doit répondre.
  </Step>
</Steps>

Pour Lark, sélectionnez **Lark** comme **Plateforme** du connecteur.

### Slack

<Steps>
  <Step title="Créez un jeton au niveau de l’application">
    Dans **Informations de base → Jetons au niveau de l’application**, générez un jeton avec l’autorisation `connections:write`. Saisissez ce jeton, qui commence par `xapp-`, dans le champ **Jeton au niveau de l’application** du connecteur.
  </Step>
  <Step title="Activez le mode Socket">
    Dans **Mode Socket**, activez ce mode.
  </Step>
  <Step title="Activez l’interactivité">
    Dans **Interactivité et raccourcis**, activez **Interactivité**. Le mode Socket ne nécessite aucune URL de requête. Les boutons des cartes d’alerte nécessitent l’interactivité. Consultez [Cartes d’alerte](#cartes-d’alerte).
  </Step>
  <Step title="Abonnez-vous aux événements">
    Dans **Abonnements aux événements → S’abonner aux événements du bot**, ajoutez `app_mention` et `message.im`. Pour poursuivre la discussion dans un fil sans mentionner le bot à chaque réponse, ajoutez aussi `message.channels` et `message.groups`.
  </Step>
  <Step title="Ajoutez les autorisations du bot">
    Dans **OAuth et autorisations**, ajoutez `app_mentions:read`, `chat:write`, `im:history` et `reactions:write`, ainsi que `channels:history` et `groups:history` pour les réponses dans les fils. Dans **Accueil de l’application**, autorisez l’envoi de messages à l’application. Réinstallez l’application et invitez le bot dans les canaux où il doit répondre.
  </Step>
</Steps>

### DingTalk

<Steps>
  <Step title="Recevez les messages du robot en mode Stream">
    Dans la console de développement DingTalk, ouvrez le robot de l’application et sélectionnez **Mode Stream** comme mode de réception des messages.
  </Step>
  <Step title="Publiez le robot">
    Publiez le robot et ajoutez-le aux groupes dans lesquels il doit répondre.
  </Step>
</Steps>

Les champs **ID client** et **Secret client** du connecteur correspondent aux identifiants de l’application. Le code du robot correspond à l’ID client, sauf si le robot possède son propre code.

### WeCom

Dans WeCom, Mole Agent répond en tant que bot intelligent : il reçoit les messages via la connexion persistante du mode API et envoie ses réponses via la même connexion.

<Steps>
  <Step title="Créez un bot intelligent">
    Créez un bot intelligent dans WeCom depuis la console d’administration ou l’application cliente, sélectionnez **Mode API**, puis choisissez de recevoir les messages via une **connexion persistante**. Notez l’**ID du bot** et le **Secret** généré pour la connexion persistante.
  </Step>
  <Step title="Créez le connecteur">
    Dans **Paramètres → Notifications → Connecteurs**, créez un connecteur **Bot intelligent WeCom** et renseignez les champs **ID du bot** et **Secret de la connexion persistante**. L’adresse de la connexion persistante est fixe : `wss://openws.work.weixin.qq.com`.
  </Step>
  <Step title="Ajoutez le bot aux groupes">
    Ajoutez le bot aux groupes dans lesquels il doit répondre ou autorisez l’envoi de messages directs au bot.
  </Step>
</Steps>

- Un bot ne peut avoir qu’une seule connexion persistante à la fois. Si une autre instance de MoleSignal ou un environnement de test se connecte avec le même ID du bot, la nouvelle connexion remplace celle de MoleSignal et l’état affiche **Connexion impossible**, avec le motif. Attribuez un bot distinct à chaque environnement.
- Un bot reçoit les messages soit via la connexion persistante, soit à une URL de rappel. Le passage à une URL de rappel ferme la connexion persistante.
- Si le compte qui a créé le bot dispose du rôle de superadministrateur de l’organisation, les messages contiennent les ID utilisateur des membres en clair. Sinon, ces ID sont chiffrés. Comme il est difficile d’associer manuellement des ID utilisateur chiffrés, invitez les membres à associer leur compte à l’aide du lien à usage unique envoyé par Mole Agent.
- Une fois activé, le bot envoie aussi des notifications. Sélectionnez ce connecteur dans les politiques de notification ou les méthodes de notification des membres pour envoyer un message directement à l’identifiant `userid` d’un membre ou à l’identifiant `chatid` d’une conversation. Le bot ne peut envoyer des notifications qu’aux membres qui lui ont envoyé un message direct et aux conversations dans lesquelles il a été mentionné. Les notifications d’alerte utilisent des modèles de cartes avec des boutons. Consultez [Cartes d’alerte](#cartes-d’alerte).

### Google Chat

L’application Google Chat publie les messages dans un sujet Cloud Pub/Sub, et MoleSignal les récupère via son abonnement. Aucune adresse publique n’est nécessaire.

<Steps>
  <Step title="Préparez un compte de service">
    Dans un projet Google Cloud, activez l’**API Google Chat** et l’**API Cloud Pub/Sub**. Dans le même projet, créez un compte de service et une clé JSON pour ce compte. Saisissez la clé dans le champ **Clé du compte de service** du connecteur. L’application Chat envoie les messages au nom de ce compte, que MoleSignal utilise pour les récupérer via l’abonnement.
  </Step>
  <Step title="Créez un sujet et un abonnement">
    Dans Pub/Sub, créez un sujet (par exemple `mole-chat`) et un abonnement de type **pull** à ce sujet (par exemple `mole-chat-sub`). Sur l’abonnement, attribuez au compte de service le rôle **Abonné Pub/Sub** (`roles/pubsub.subscriber`).
  </Step>
  <Step title="Autorisez Chat à publier dans le sujet">
    Sur le sujet, attribuez le rôle **Éditeur Pub/Sub** (`roles/pubsub.publisher`) à `chat-api-push@system.gserviceaccount.com`. Si l’application Chat est un module complémentaire Google Workspace, attribuez plutôt ce rôle au compte de service indiqué dans ses paramètres de connexion.
  </Step>
  <Step title="Configurez l’application Chat">
    Dans **API Google Chat → Configuration**, renseignez le nom et l’avatar de l’application. Activez **Recevoir des messages privés** et **Rejoindre des espaces et des conversations de groupe**. Dans **Paramètres de connexion**, sélectionnez **Cloud Pub/Sub** et saisissez le nom complet du sujet, `projects/<project>/topics/mole-chat`. Dans **Visibilité**, choisissez qui peut utiliser l’application.
  </Step>
  <Step title="Renseignez l’abonnement">
    Saisissez `projects/<project>/subscriptions/mole-chat-sub` dans le champ **Abonnement Pub/Sub** du connecteur.
  </Step>
</Steps>

- Conservez le délai d’accusé de réception par défaut de 10 secondes pour l’abonnement : MoleSignal accuse réception de chaque message dès qu’il le récupère.
- Dans les espaces et les conversations de groupe, l’application ne reçoit que les messages qui la mentionnent. Mentionnez-la de nouveau pour poursuivre la discussion dans un fil. Dans une conversation privée, l’application reçoit tous les messages.

### Telegram

Le bot reçoit ses messages par interrogation longue de l’API Telegram Bot (`getUpdates`). Aucune adresse publique n’est nécessaire.

<Steps>
  <Step title="Créez un bot">
    Dans Telegram, envoyez la commande `/newbot` à **@BotFather**, puis choisissez un nom et un nom d’utilisateur pour le bot. Copiez le jeton fourni, par exemple `123456789:AAE…`.
  </Step>
  <Step title="Créez le connecteur">
    Dans **Paramètres → Notifications → Connecteurs**, créez un connecteur **Bot Telegram** et renseignez le champ **Jeton du bot**.
  </Step>
  <Step title="Autorisez le bot à recevoir les mentions">
    Avec le mode de confidentialité par défaut de Telegram, un bot dans un groupe reçoit les commandes qui lui sont destinées et les réponses à ses messages, mais pas les simples @mentions. Pour solliciter Mole Agent par @mention, envoyez `/setprivacy` à @BotFather et sélectionnez **Désactiver**, ou attribuez au bot le rôle d’administrateur du groupe.
  </Step>
  <Step title="Ajoutez le bot aux groupes">
    Ajoutez le bot aux groupes dans lesquels il doit répondre.
  </Step>
</Steps>

- Dans un groupe, Mole Agent répond aux messages qui mentionnent le bot, aux commandes (`/new@<bot>` ou `/new`) et aux réponses à ses propres messages. Mentionnez aussi le bot dans les réponses aux notifications d’alerte, sinon Mole Agent ne reçoit pas les échanges sur l’alerte. Dans une conversation privée, il reçoit tous les messages.
- Mole Agent traite la commande `/start`, qui lance une conversation privée avec le bot, comme `/help`. Si le compte n’est pas encore associé, Mole Agent envoie le lien d’association.
- Un bot Telegram ne peut envoyer de messages privés qu’aux membres qui ont ouvert une conversation privée avec lui et appuyé sur **Début**. Pour un compte non associé qui n’a pas effectué cette étape, Mole Agent envoie le lien dans un message de groupe visible uniquement par le compte concerné. Si cet envoi échoue aussi, Mole Agent demande d’abord un message privé. Consultez [Associer les comptes des membres](#associer-les-comptes-des-utilisateurs).
- Telegram ne transmet les messages d’un bot qu’à un seul destinataire à la fois. À la connexion, MoleSignal supprime tout webhook configuré sur le bot. Si un autre programme interroge le même bot, Telegram refuse l’un des deux (HTTP 409) et l’état affiche **Connexion impossible**, avec le motif. Attribuez un bot distinct à chaque environnement.

### Microsoft Teams

Bot Framework envoie les messages Teams à une adresse de rappel publique de MoleSignal. Teams est la seule plateforme qui exige que MoleSignal soit accessible depuis Internet. Configurez l’adresse externe comme indiqué dans [Sécurité pour Teams](#sécurité-pour-teams) avant d’activer le connecteur.

<Steps>
  <Step title="Préparez un bot Azure">
    Dans le portail Azure, créez un **Azure Bot** de type **Locataire unique** ou utilisez un bot existant de ce type. Créez un secret client dans l’inscription d’application Microsoft Entra du bot. Dans le connecteur, renseignez l’**ID de l’application**, le **Secret client** et l’**ID du locataire** du bot.
  </Step>
  <Step title="Ajoutez le canal Teams">
    Dans **Canaux** du bot Azure, ajoutez **Microsoft Teams**.
  </Step>
  <Step title="Activez le connecteur et copiez l’adresse de rappel">
    Ouvrez **Mole Agent → Paramètres → Messagerie instantanée**, activez le connecteur, puis copiez l’adresse indiquée dans **Rappel** : `https://<external address>/api/v1/public/im/teams/<connector ID>/messages`.
  </Step>
  <Step title="Configurez le point de terminaison de messagerie">
    Dans **Configuration** du bot Azure, renseignez l’adresse de rappel dans **Point de terminaison de messagerie**.
  </Step>
  <Step title="Publiez une application Teams">
    Créez un package d’application Teams dont le manifeste indique l’ID de l’application du bot sous `bots`, avec les portées `personal`, `team` et `groupChat`. Importez le package dans le centre d’administration Teams ou dans le portail des développeurs, puis installez l’application pour les membres, les équipes et les conversations de groupe concernés.
  </Step>
</Steps>

- Dans les canaux et les conversations de groupe, le bot ne reçoit que les messages qui le mentionnent. Mentionnez-le de nouveau pour poursuivre la discussion sous une publication. Dans une conversation individuelle, il reçoit tous les messages.
- MoleSignal prend en charge Bot Framework dans le cloud public Azure et dans les clouds du gouvernement des États-Unis (GCC, GCC High, DoD). Sélectionnez le **Cloud** dans le connecteur.

## Sécurité pour Teams

L’adresse de rappel Teams est accessible sur Internet. MoleSignal vérifie chaque requête envoyée à cette adresse :

- **Chaque requête contient un jeton Bot Framework.** L’adresse n’accepte pas l’authentification MoleSignal, mais uniquement un JWT signé par Bot Framework : les clés de signature proviennent des métadonnées OpenID de `login.botframework.com` (mises en cache pendant 24 heures) ; `iss` vaut `https://api.botframework.com` ; GCC High et DoD utilisent à la place `login.botframework.azure.us` et `https://api.botframework.us` ; `aud` correspond à l’ID d’application du bot ; `exp` et `nbf` tolèrent un décalage d’horloge de cinq minutes ; la clé de signature doit autoriser le canal Teams (`msteams`) ; enfin, le champ `serviceUrl` du jeton doit correspondre à celui du message. Si une vérification échoue, MoleSignal renvoie un code 401 ou 403 sans traiter la requête.
- **Les réponses vont uniquement à Bot Framework.** MoleSignal envoie le jeton du bot uniquement aux adresses de service de Bot Framework (`smba.trafficmanager.net`, `*.botframework.com`, `*.teams.microsoft.com`, `*.teams.microsoft.us`) ou à l’URL de service configurée dans le connecteur, et refuse tout message dont l’adresse ne correspond à aucune de ces destinations.
- **Seul le tenant du connecteur est autorisé.** Si le connecteur spécifie un ID de tenant (un GUID), MoleSignal ne traite pas les messages des autres tenants. Un nom de domaine ou `botframework.com` n’impose aucune restriction.
- **L’adresse ne fonctionne que si le connecteur est activé.** Si le connecteur n’est pas activé dans **Messagerie instantanée**, ou s’il est désactivé ou supprimé, l’adresse de rappel renvoie un code 404. L’adresse contient uniquement l’ID du connecteur, jamais de secret.
- **La taille du corps est limitée.** MoleSignal refuse les requêtes de plus de 256 KiB.

Lors du déploiement, prenez aussi les mesures suivantes :

1. **Exposez uniquement le chemin de rappel sur Internet.** Configurez un proxy inverse ou une passerelle pour ne relayer que `POST /api/v1/public/im/teams/`. Réservez la page de connexion et toutes les autres API au réseau interne. Par exemple, avec nginx :

   ```nginx
   server {
     listen 443 ssl;
     server_name molesignal.example.com;
     # ssl_certificate and ssl_certificate_key …
     client_max_body_size 256k;

     location /api/v1/public/im/teams/ {
       limit_except POST { deny all; }
       proxy_pass http://molesignal.internal:8080;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto https;
     }

     location / {
       return 404;
     }
   }
   ```

   Si cette adresse externe sert aussi à accéder à MoleSignal, limitez l’accès à tous les autres chemins au réseau de l’entreprise ou au VPN au niveau de la passerelle. Exposez uniquement le chemin de rappel sur Internet. Consultez les configurations complètes pour nginx, Kubernetes Ingress et Gateway API dans [Accès public](/fr/public-access).
2. **Utilisez HTTPS.** `http.external_url` doit être une adresse HTTPS, car Teams n’envoie pas de requêtes POST sur HTTP. Le proxy peut assurer la terminaison TLS avec un certificat délivré par une autorité de certification publique.
3. **Limitez les sources si nécessaire.** Un pare-feu ou une passerelle peut limiter l’accès au chemin de rappel aux adresses associées à l’étiquette de service Azure `AzureBotService`. Ces adresses changent : tenez-les à jour à partir de la liste publiée par Azure. La vérification du jeton reste la protection principale.
4. **Protégez le secret client.** MoleSignal le chiffre avec le connecteur et ne le renvoie jamais. Renouvelez-le régulièrement et mettez le connecteur à jour à chaque renouvellement. Accordez à l’inscription d’application du bot uniquement les autorisations nécessaires.
5. **Surveillez les anomalies.** Les journaux et les traces de MoleSignal indiquent les requêtes de rappel et les jetons refusés. La page **Messagerie instantanée** indique quand chaque connecteur a reçu son dernier message.

## Prérequis externes

Prérequis de chaque plateforme en dehors de MoleSignal :

| Plateforme | Trafic sortant de MoleSignal | Trafic entrant | Configuration sur la plateforme |
|---|---|---|---|
| Feishu | `open.feishu.cn` (`open.larksuite.com` pour Lark) et l’adresse de connexion persistante fournie par la plateforme | Aucun | Une application développée en interne, les événements sur une connexion persistante, l’événement de message, les rappels sur une connexion persistante, les autorisations et une version publiée |
| Slack | `slack.com`, les adresses WebSocket de Socket Mode et `hooks.slack.com` pour les cartes d’alerte ; pour GovSlack, `slack-gov.com` et `hooks.slack-gov.com` à la place | Aucun | Un jeton au niveau de l’application, Socket Mode, l’interactivité, les abonnements aux événements et les portées d’autorisation du bot |
| DingTalk | `api.dingtalk.com`, `oapi.dingtalk.com` et l’adresse WebSocket de Stream | Aucun | Le bot d’une application interne et le mode Stream ; pour les boutons des cartes d’alerte, un modèle de carte interactive et l’autorisation associée |
| WeCom | `openws.work.weixin.qq.com` (WebSocket, 443) | Aucun | Un bot intelligent en mode API sur une connexion persistante, avec son ID de bot et son secret |
| Google Chat | `oauth2.googleapis.com`, `pubsub.googleapis.com`, `chat.googleapis.com` | Aucun | Les API Chat et Pub/Sub, un compte de service et sa clé JSON, un sujet et un abonnement de type pull, les rôles Abonné et Éditeur, et la configuration de l’application Chat |
| Telegram | `api.telegram.org` (443) | Aucun | Un bot créé avec @BotFather et son jeton |
| Microsoft Teams | `login.microsoftonline.com`, `login.botframework.com` et l’URL de service du connecteur (`smba.trafficmanager.net` pour Global) ; pour GCC High et DoD, `login.microsoftonline.us` et `login.botframework.azure.us` à la place | Bot Framework accède à `https://<external address>/api/v1/public/im/teams/…` (443) | Un Azure Bot, un secret client, le canal Teams, le point de terminaison de messagerie et un package d’application Teams |

- Configurez les pare-feu et les proxys sortants pour autoriser le trafic vers les adresses ci-dessus. Les connexions WebSocket persistantes (Feishu, Slack, DingTalk, WeCom) accèdent directement à la plateforme sans passer par un proxy HTTP.
- Pour le trafic entrant, Teams nécessite un DNS public, un certificat délivré par une autorité de certification publique et un proxy inverse qui relaie uniquement le chemin de rappel. Consultez [Sécurité pour Teams](#sécurité-pour-teams).
- Configurez `http.external_url` pour permettre l’association des comptes et l’utilisation des liens de conversation dans les réponses.

## Activer un connecteur

Ouvrez **Mole Agent → Paramètres → Messagerie instantanée**. La page répertorie tous les connecteurs capables de répondre dans la messagerie instantanée :

| Colonne | Informations affichées |
|---|---|
| **Connecteur** | Le connecteur, sa plateforme et la date de réception du dernier message. Pour un connecteur Teams, l’adresse de rappel figure sous le connecteur, prête à être copiée. |
| **Statut** | **Connecté** avec l’identité utilisée pour la connexion, **Connexion en cours**, **En attente d’un serveur**, **Connexion impossible** avec le motif, **Désactivé**, ou l’élément manquant, par exemple un jeton au niveau de l’application Slack ou un abonnement Pub/Sub pour Google Chat. Teams n’utilise pas de connexion persistante : **Connecté** signifie que les identifiants du bot sont valides et que Bot Framework transmet les messages. |
| **Nouveaux fils de discussion de groupe** | La destination des nouveaux fils de discussion lancés dans un groupe : **Conversation privée de la personne à l’origine de la demande** ou une équipe. L’équipe ne s’applique que si la personne à l’origine de la demande en est membre. |
| **Activée** | Indique si le connecteur répond dans la messagerie instantanée. Pour activer un connecteur Teams, `http.external_url` doit être une adresse HTTPS. |

Pour supprimer des paramètres de notification un connecteur qui répond dans la messagerie instantanée, désactivez-le d’abord sur cette page.

## Associer les comptes des utilisateurs

Mole Agent répond avec l’identité et les autorisations du compte utilisateur MoleSignal associé au compte de messagerie instantanée. Mole Agent reconnaît ce compte grâce à une méthode de notification activée et vérifiée sur le même connecteur :

| Plateforme | Compte |
|---|---|
| Feishu | `open_id`, `user_id` ou `union_id` |
| Slack | ID de membre |
| DingTalk | ID utilisateur |
| WeCom | ID utilisateur connu du bot intelligent |
| Google Chat | Utilisateur (`users/123…`) ou adresse e-mail |
| Telegram | ID utilisateur numérique |
| Microsoft Teams | ID utilisateur Teams (`29:…`) ou ID d’objet Microsoft Entra |

Mole Agent ne répond pas si le compte est associé à plusieurs utilisateurs.

- **Association par la personne concernée** : à la réception d’une demande provenant d’un compte non associé, Mole Agent envoie un lien à usage unique en privé, dans un message direct ou, dans Slack, dans un message visible uniquement par la personne à l’origine de la demande. Ouvrez le lien avec une session MoleSignal active, puis cliquez sur **Associer** pour ajouter le compte à vos méthodes de notification avec le statut vérifié. Le lien fonctionne une seule fois et expire au bout de 15 minutes. Dans WeCom, Google Chat et Telegram, le bot ne peut envoyer un message privé qu’après avoir reçu un message direct. Dans Teams, le bot doit être installé pour la personne concernée. Si l’envoi échoue, Mole Agent invite la personne dans la conversation en cours à envoyer d’abord un message direct, puis transmet le lien dans cette conversation privée. Dans Telegram, Mole Agent tente d’abord d’envoyer dans le groupe un message visible uniquement par la personne concernée.
- **Association par un administrateur** : dans **Paramètres → Notifications → Routage par utilisateur**, associez le compte au membre, puis vérifiez le compte. Consultez [Canaux de notification](/fr/notification-channels#associer-les-modes-de-notification-des-membres).

## Poser une question

Dans un groupe, mentionnez le bot ; en message privé, écrivez directement. Les messages privés restent dans la même conversation jusqu’à la commande `/new`.

| Plateforme | À quoi correspond une conversation dans un groupe |
|---|---|
| Feishu, Slack | Un fil de discussion ; la réponse apparaît dans ce fil |
| Espaces Google Chat | Un fil de discussion ; la réponse apparaît dans ce fil. Mentionnez le bot pour poursuivre |
| Canaux Microsoft Teams | Une publication ; la réponse apparaît sous cette publication. Mentionnez le bot pour poursuivre |
| DingTalk, WeCom, conversations de groupe Google Chat, discussions de groupe Teams | Pas de fil de discussion : dans chaque groupe, les questions de chaque personne forment une conversation distincte |
| Groupes Telegram | Dans chaque sujet de forum, les questions de chaque personne forment une conversation distincte ; le bot répond directement à la question |

| Commande | Fonction |
|---|---|
| `/help` | Explique comment poser une question et répertorie ces commandes. |
| `/new` | Démarre une nouvelle conversation ici. |
| `/scope` | Indique à qui appartient la conversation associée à ce fil. |
| `/scope <team>` | Poursuit l’échange dans une nouvelle conversation d’équipe que les membres de cette équipe peuvent suivre et poursuivre. |
| `/scope me` | Poursuit l’échange dans une nouvelle conversation personnelle. |
| `/feedback 👍` ou `/feedback 👎`, suivi d’un commentaire facultatif | Évalue la dernière réponse du fil. |

Les autres commandes, comme `/rca INC-12` ou une commande de compétence, fonctionnent comme dans MoleSignal.

### À qui appartient la conversation d’un fil

Seule la personne à l’origine d’une conversation personnelle peut la poursuivre. Seuls les membres de l’équipe peuvent poursuivre une conversation d’équipe. Dans un groupe, un nouveau fil ouvre une conversation de l’équipe du connecteur si la personne qui pose la question en fait partie, ou une conversation personnelle dans le cas contraire. `/scope` associe le fil à une nouvelle conversation ; les messages précédents restent dans l’ancienne.

## Pendant la préparation de la réponse

- La messagerie instantanée ne permet ni de répondre aux questions de Mole Agent ni de confirmer des modifications. Mole Agent formule des hypothèses raisonnables et les précise. Il ignore les étapes qui nécessitent une confirmation et le signale dans la réponse. Pour reprendre ces étapes, ouvrez la conversation dans MoleSignal à l’aide du lien.
- La préparation d’une réponse dure au maximum 15 minutes. Dans WeCom, le message « Analyse en cours… » s’affiche progressivement et doit se terminer dans les 10 minutes. Si la préparation prend plus de 9 minutes, Mole Agent envoie la réponse dans un message distinct.
- Mole Agent envoie la réponse avec ses différentes sections, comme les causes probables, les éléments de preuve et les prochaines étapes, dans la langue de l’interface de la personne qui a posé la question.
- Dans un groupe, tous les membres peuvent lire la réponse, même si Mole Agent la prépare avec les autorisations de la personne qui a posé la question. Posez en message privé toute question qui doit rester confidentielle.
- Si le budget quotidien de l’organisation est épuisé, Mole Agent le signale au lieu de répondre.

## Cartes d’alerte

Cette section traite des notifications d’alerte, et non des conversations avec Mole Agent : les connecteurs ci-dessous envoient ces notifications sous forme de cartes à boutons. Les boutons permettent d’acquitter, de résoudre ou de mettre en veille une alerte sans ouvrir MoleSignal.

| Connecteur | Quand les cartes comportent des boutons |
|---|---|
| Application Feishu, application Slack, bot intelligent WeCom, application Google Chat, bot Microsoft Teams, bot Telegram | Le connecteur est activé dans **Messagerie instantanée** ; consultez [Activer le connecteur](#activer-un-connecteur) |
| Application DingTalk | Le connecteur est activé dans **Messagerie instantanée** et dispose d’un **ID du modèle de carte** ; consultez [Cartes interactives DingTalk](#cartes-interactives-dingtalk) |
| Application WeCom | Inutile de l’activer dans **Messagerie instantanée** : l’application utilise la configuration **Recevoir des messages** ; consultez [Boutons d’une application WeCom](#boutons-d’une-application-wecom). Seules les notifications envoyées aux membres comportent des boutons |
| Bot Mattermost | Inutile de l’activer dans **Messagerie instantanée** : `http.external_url` est configuré et le serveur Mattermost peut accéder à cette adresse ; consultez [Boutons d’un bot Mattermost](#boutons-d’un-bot-mattermost) |

Les bots de groupe (les connecteurs webhook de chaque plateforme) ne reçoivent pas les clics sur les boutons. Leurs notifications d’alerte ne comportent donc pas de boutons d’action : les bots envoient une carte sans boutons si l’option **Envoyer sous forme de carte** est activée dans le modèle de messagerie instantanée, et du texte dans le cas contraire. Consultez [Cartes dans les modèles de messagerie instantanée](/fr/notification-channels#cartes-dans-les-modèles-de-messagerie-instantanée). Les notifications d’alerte envoyées à une seule personne via un connecteur sans boutons contiennent à la place des [liens d’action à usage unique](/fr/notification-channels#liens-d’action-à-usage-unique).

| Bouton | Effet |
|---|---|
| **Acquitter** | Prend en charge l’alerte, comme lors d’un acquittement dans MoleSignal : l’escalade s’arrête et l’alerte est assignée au compte à l’origine du clic. |
| **Résoudre** | Clôt l’alerte. |
| **Mettre en veille 1 heure** | Suspend l’envoi des notifications pendant une heure. Si l’alerte est en attente d’acquittement, le bouton l’acquitte d’abord. Au bout d’une heure, l’alerte repasse en attente d’acquittement et les responsables reçoivent une nouvelle notification. Consultez [Agir sur un incident](/fr/alerting/incidents#agir-sur-un-incident). |
| **Tout acquitter** | Disponible uniquement dans un message de [notifications regroupées](/fr/notification-channels#regrouper-les-notifications) : acquitte jusqu’à 20 alertes du message encore en attente d’acquittement. Les cartes Telegram n’affichent que le bouton **Ouvrir dans MoleSignal**. |
| **Ouvrir dans MoleSignal** | Ouvre la page de l’incident ou, dans un message regroupé, la liste des incidents. Nécessite `http.external_url`. |

- Les boutons d’une carte correspondent à l’état de l’alerte au moment de l’envoi de la notification : une alerte en attente d’acquittement affiche Acquitter, Résoudre et Mettre en veille 1 heure. Une alerte acquittée affiche Résoudre et Mettre en veille 1 heure. Une notification de retour à la normale n’affiche aucun bouton.
- Un clic exécute l’action au nom du compte MoleSignal associé au compte de messagerie instantanée. Le compte MoleSignal doit disposer de l’autorisation `alerts.incidents.acknowledge`. Un compte non associé reçoit un lien à usage unique en privé, comme lors d’une demande à Mole Agent. Consultez [Associer les comptes des membres](#associer-les-comptes-des-utilisateurs). Sur Telegram, si le bot ne peut pas envoyer de message privé, le lien apparaît dans un message de groupe visible uniquement par le compte à l’origine du clic, ou le clic ouvre la conversation privée avec le bot, qui y envoie le lien. Une application WeCom envoie plutôt un message demandant d’abord d’ajouter le compte comme méthode de notification dans le profil. Un bot Mattermost envoie la même demande dans un message visible uniquement par le compte à l’origine du clic. Si le compte est associé à plusieurs comptes MoleSignal, le clic ne change rien.
- Après un clic, la carte affiche l’état actuel de l’alerte : MoleSignal régénère le contenu à partir du modèle de la politique de notification utilisée pour l’envoi, ajoute une ligne indiquant le compte qui a acquitté ou résolu l’alerte et ne conserve que les boutons encore utiles. Tous les membres du groupe voient la même carte. Lorsqu’il ne reste plus d’action possible, la carte WeCom conserve un bouton ✓ sans effet, car les cartes basées sur un modèle WeCom nécessitent au moins un bouton.
- Feishu et Telegram affichent une notification éphémère au compte à l’origine du clic pour indiquer le résultat de l’action. Sur Telegram, un échec s’affiche dans une boîte de dialogue à fermer. Sur les autres plateformes, en cas d’échec, Slack, Google Chat et Mattermost affichent la raison dans un message visible uniquement par le compte à l’origine du clic, Teams l’affiche sur une ligne visible uniquement par ce compte, et DingTalk et WeCom l’envoient par message direct.
- Les boutons s’affichent dans la langue de l’interface du destinataire ou, pour les cartes envoyées à un groupe, dans la langue par défaut de l’organisation.

### Cartes interactives DingTalk

Le modèle de carte interactive définit la présentation de la carte DingTalk. MoleSignal renseigne les variables du modèle et reçoit les clics via la connexion Stream.

<Steps>
  <Step title="Créer un modèle">
    Dans la **plateforme de cartes** de la console de développement DingTalk, créez un modèle de **carte de message** et associez-le à l’application.
  </Step>
  <Step title="Ajouter les variables">
    Ajoutez les variables de texte `title`, `content`, `note`, `footer`, `open_text` et `open_url`, ainsi que `*_text` et `*_value` pour chaque action : `acknowledge`, `resolve`, `snooze` et `acknowledge_all`, puis `approve` et `reject` pour les [cartes d’approbation](#cartes-d’approbation).
  </Step>
  <Step title="Disposer les composants">
    Liez le titre à `title`, le corps Markdown à `content` et deux lignes de texte en petits caractères à `note` (le compte qui a acquitté ou résolu l’alerte) et à `footer` (le pied de page du modèle). Ajoutez un bouton pour chaque action. Liez le libellé du bouton à `*_text` et affichez-le uniquement si `*_text` n’est pas vide. Configurez une action de type **requête de rappel** et liez son paramètre `value` à `*_value`. Ajoutez un dernier bouton dont le libellé est lié à `open_text` et qui ouvre `open_url`. Affichez-le uniquement si `open_text` n’est pas vide.
  </Step>
  <Step title="Publier le modèle et saisir son ID">
    Enregistrez et publiez le modèle, puis renseignez son **ID de modèle** dans le champ **ID du modèle de carte** du connecteur. L’application doit disposer de l’autorisation d’écriture des cartes interactives (`Card.Instance.Write`).
  </Step>
</Steps>

- Seuls les membres inclus dans le périmètre de visibilité de l’application reçoivent les cartes envoyées directement. Pour envoyer des cartes à un groupe, ajoutez le bot à ce groupe.
- Sans ID de modèle, le connecteur continue d’envoyer les notifications d’alerte au format ActionCard ou Markdown, sans boutons.

### Boutons d’une application WeCom

Une application WeCom (`wecom_app`) n’est pas un bot Mole Agent. Ne l’activez pas dans **Messagerie instantanée** : dès que la fonction **Recevoir des messages** de l’application envoie les requêtes de rappel à MoleSignal, les membres reçoivent les notifications d’alerte sous forme de cartes à boutons basées sur un modèle. Les notifications envoyées aux conversations de l’application ne comportent aucun bouton, car WeCom n’envoie pas de cartes basées sur un modèle à ces conversations.

<Steps>
  <Step title="Activer la réception via l’API">
    Ouvrez l’application dans la console d’administration WeCom, choisissez **Configurer la réception via l’API** dans **Recevoir des messages**, puis générez un **Jeton** et une **EncodingAESKey**.
  </Step>
  <Step title="Renseigner les valeurs dans le connecteur">
    Renseignez ces valeurs dans les champs **Jeton de rappel** et **EncodingAESKey** du connecteur, puis enregistrez.
  </Step>
  <Step title="Saisir l’URL de rappel">
    Copiez l’**URL de rappel** du connecteur, `https://<external address>/api/v1/public/notify/<connector ID>/wecom`, renseignez-la comme URL dans **Recevoir des messages**, puis enregistrez. WeCom envoie immédiatement une requête à cette URL pour la vérifier.
  </Step>
</Steps>

- Le domaine de l’URL de rappel doit figurer dans un enregistrement ICP de l’entreprise, et WeCom doit pouvoir accéder à ce chemin depuis Internet.
- MoleSignal refuse les requêtes dont la signature est incorrecte, déchiffre le contenu avec la clé EncodingAESKey et ignore le contenu destiné à une autre entreprise.
- MoleSignal identifie le compte à l’origine du clic grâce à une méthode de notification vérifiée sur ce connecteur : le UserID du membre.

### Boutons d’un bot Mattermost

Un bot Mattermost (`mattermost_bot`) n’est pas un bot Mole Agent. Ne l’activez pas dans **Messagerie instantanée** : dès que `http.external_url` est configuré, ses notifications d’alerte affichent les boutons Acquitter, Résoudre et Mettre en veille 1 heure. Les boutons déclenchent une requête de rappel à MoleSignal à l’adresse `https://<external address>/api/v1/public/notify/<connector ID>/mattermost?token=…`. Cette adresse contient le jeton de rappel du connecteur, que Mattermost ne communique pas à ses clients.

- Le serveur Mattermost envoie la requête et doit donc pouvoir accéder à l’adresse externe. Mattermost refuse d’appeler les adresses privées et internes, sauf si l’hôte figure dans la console système sous **Environnement → Développeur → Autoriser les connexions internes non approuvées vers** (`ServiceSettings.AllowedUntrustedInternalConnections`). Ajoutez l’hôte de `http.external_url` à cette liste si MoleSignal se trouve sur le réseau interne.
- MoleSignal identifie le compte à l’origine du clic grâce à une méthode de notification activée et vérifiée sur ce connecteur : le nom d’utilisateur Mattermost, avec ou sans `@`, ou l’ID d’utilisateur. Si MoleSignal ne reconnaît pas le compte, un message visible uniquement par ce compte demande de l’ajouter d’abord comme méthode de notification.
- MoleSignal renvoie le code 401 si le jeton de rappel est incorrect et le code 404 si le connecteur est désactivé.
- Les messages envoyés par webhook (`mattermost_webhook`) ne comportent pas de boutons, car MoleSignal ne pourrait pas identifier le compte à l’origine d’un clic. Ils ne conservent que le lien vers l’alerte.

## Cartes d’approbation

Lorsque Mole Agent propose une opération soumise à approbation ou qu’une action de remédiation est lancée sur un incident, la politique de notification intégrée **Approbation requise : notifier les personnes habilitées à approuver** envoie la demande sous la forme de l’événement **Demande d’approbation pour Mole Agent**. Elle notifie au maximum 20 membres disposant de l’autorisation `agent.approve`, à l’exclusion de l’auteur de la demande, selon les modes de notification de chaque membre. Si une [approbation préalable](/fr/alerting/remediation#préapprobation) couvre la demande, l’opération s’exécute immédiatement sans envoyer de notification.

Sur les connecteurs dont les cartes d’alerte comportent des boutons (voir [Cartes d’alerte](#cartes-d’alerte)), la notification s’affiche sous forme de carte avec les boutons suivants :

| Bouton | Fonction |
|---|---|
| **Approuver** | Approuve la demande. Dès que la demande obtient les approbations requises, l’opération s’exécute immédiatement, comme depuis la page des approbations de Mole Agent. |
| **Rejeter** | Rejette la demande. L’opération ne s’exécute pas. |
| **Ouvrir dans MoleSignal** | Ouvre la page des approbations de Mole Agent. Nécessite `http.external_url`. |

- Un clic agit au nom du compte MoleSignal associé au compte de messagerie instantanée. Seul un mode de notification vérifié sur le connecteur permet d’identifier ce compte MoleSignal, qui doit disposer de l’autorisation `agent.approve`. L’auteur de la demande ne peut pas l’approuver. Si le compte de messagerie n’est pas encore associé, le connecteur envoie un lien à usage unique en privé, comme pour les cartes d’alerte.
- Après un clic, la carte affiche la demande sans ses boutons et indique qui a approuvé ou rejeté la demande et si l’opération a été exécutée. Une notification confirme à l’auteur du clic si l’action a réussi.
- Si une décision a déjà été prise ailleurs ou si le même compte a déjà examiné la demande, un clic ne change rien : la carte affiche l’état actuel de la demande.
- Les cartes DingTalk affichent les deux boutons uniquement si le modèle contient les variables `approve_*` et `reject_*` ; voir [Cartes interactives DingTalk](#cartes-interactives-dingtalk).

## Limites

- Mole Agent lit les messages texte et le contenu textuel des messages enrichis. Dans WeCom, Mole Agent lit aussi la transcription des messages vocaux. Mole Agent ignore les images et les fichiers.
- Lorsque le serveur qui héberge un connecteur s’arrête, un autre serveur prend le relais en une minute environ. Une fois la connexion rétablie, Mole Agent répond aux questions posées pendant cette interruption uniquement si la plateforme les transmet de nouveau. Cette limite ne concerne pas Teams : le serveur qui reçoit un rappel le traite.
- Seul le serveur qui maintient la connexion du bot peut envoyer des réponses WeCom. Si un autre serveur termine de générer une réponse, il la transmet au serveur connecté. La réponse arrive généralement en quelques secondes.
- WeCom limite chaque conversation à 30 messages par minute et à 1 000 messages par heure.
- Un message Telegram peut contenir jusqu’à 4 096 caractères. Une réponse plus longue arrive donc en plusieurs messages.
- L’acquittement ou la résolution d’une alerte dans MoleSignal ou sur une autre carte ne modifie pas les cartes d’alerte déjà envoyées. Un clic sur un bouton d’une de ces cartes indique que l’alerte est déjà acquittée ou résolue et met la carte à jour.
