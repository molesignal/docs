L’authentification multifacteur ajoute une vérification au mot de passe. Connaître le mot de passe
ne suffit donc plus pour se connecter. L’ajout de l’un des deux facteurs ci-dessous l’active, et les deux
peuvent coexister. Configurez-la dans **Paramètres du compte → Sécurité et connexion**. Un
espace de travail peut [l’imposer à ses membres](/fr/identity/sso#exigences-de-connexion) : les membres qui ne l’ont pas
activée la configurent lors de leur connexion.

| Second facteur | Mode de vérification |
|---|---|
| Clé d’accès | Confirmez votre identité avec une empreinte digitale, la reconnaissance faciale ou le code de déverrouillage de votre appareil. Aucun code de vérification à saisir, et un site de phishing ne peut pas vous soutirer la clé. Elle peut être stockée dans le Trousseau iCloud, le Gestionnaire de mots de passe de Google, 1Password ou sur une clé de sécurité. Elle permet aussi de se connecter sans mot de passe. |
| Application d’authentification | Saisissez un code à 6 chiffres fourni par une application comme Google Authenticator, Microsoft Authenticator ou 1Password. |

## Confirmez d’abord votre identité

Avant d’activer l’application d’authentification ou d’ajouter une clé d’accès, confirmez que le compte
vous appartient. Une session ouverte ne suffit pas : sinon, quiconque y accède pourrait ajouter son propre
second facteur et bloquer l’accès au compte.

| Compte | Mode de confirmation |
|---|---|
| Dispose déjà d’un second facteur | Utilisez une clé d’accès existante, l’application d’authentification ou un code de récupération. |
| Ne dispose pas encore d’un second facteur | Saisissez le mot de passe du compte. |
| N’a pas de mot de passe (créé via l’authentification unique) | Ne saisissez rien dans les 10 minutes suivant la connexion. Au-delà, reconnectez-vous. |

## Ajouter une clé d’accès

<Steps>
  <Step title="Ouvrez le paramètre">
    Dans **Paramètres du compte → Sécurité et connexion**, à la ligne **Clés d’accès**, cliquez sur **Ajouter une clé d’accès**, puis
    confirmez votre identité comme indiqué ci-dessus.
  </Step>
  <Step title="Créez la clé d’accès">
    Si nécessaire, donnez-lui un nom, par exemple « Mon MacBook », cliquez sur **Créer**, puis suivez les instructions du
    navigateur ou du système.
  </Step>
  <Step title="Enregistrez les codes de récupération">
    Si c’est le premier second facteur du compte, l’authentification multifacteur s’active et dix
    codes de récupération s’affichent, une seule fois. Conservez-les avec **Copier** ou **Télécharger**, puis cliquez sur
    **Je les ai enregistrés**.
  </Step>
</Steps>

Si l’instance peut [envoyer des e-mails](/fr/configuration#alertes-et-e-mails), elle envoie une
notification à l’adresse du compte. La première clé d’accès ferme aussi toutes les sessions du compte dans les autres navigateurs et sur les autres ordinateurs,
mais laisse la session actuelle ouverte. L’ajout d’autres clés ne ferme aucune session.

Le navigateur et le système déterminent les emplacements de stockage possibles et proposent de choisir parmi eux :

| Emplacement de stockage | Remarques |
|---|---|
| Trousseau iCloud | Safari sur les appareils Apple. La clé fonctionne sur tous les appareils qui utilisent le même compte Apple. |
| Gestionnaire de mots de passe de Google | Chrome et Android. La clé fonctionne sur tous les appareils qui utilisent le même compte Google. |
| Gestionnaire de mots de passe | 1Password, Bitwarden et autres. |
| Clé de sécurité | YubiKey et autres clés FIDO2. |

Si aucune clé d’accès n’est disponible sur l’ordinateur, le navigateur peut aussi afficher un code QR pour confirmer l’identité avec une clé d’accès sur
un téléphone.

Dans la liste, une clé d’accès sans nom s’affiche sous son emplacement de stockage. Si le navigateur ne l’indique pas,
seul le libellé Clé d’accès s’affiche.

### Prérequis de l’instance

Une clé d’accès est liée au nom de domaine de l’instance. Si les conditions ci-dessous ne sont pas remplies, l’option **Ajouter une
clé d’accès** est grisée et le motif s’affiche. La page de connexion ne propose pas de clé d’accès.

| Prérequis | Remarques |
|---|---|
| Définir `[http].external_url` | Consultez [Configuration](/fr/configuration). |
| Indiquer un nom de domaine | Les navigateurs n’acceptent pas les adresses IP. |
| Utiliser HTTPS | Sauf sur `localhost`. |
| Ouvrir la console à cette adresse | Avec un autre nom d’hôte, le navigateur refuse d’utiliser les clés d’accès. |

Si le nom d’hôte de `external_url` change, les clés d’accès existantes cessent de fonctionner. Connectez-vous avec le mot de passe
ou un code de récupération, puis ajoutez-les à nouveau.

## Activer l’application d’authentification

<Steps>
  <Step title="Ouvrez le paramètre">
    Dans **Paramètres du compte → Sécurité et connexion**, à la ligne **Application d’authentification**, cliquez sur **Activer**, puis
    confirmez votre identité comme indiqué ci-dessus.
  </Step>
  <Step title="Ajoutez le compte à l’application d’authentification">
    Scannez le code QR avec l’application d’authentification ou saisissez la clé affichée en dessous. L’application affiche
    l’entrée sous le nom MoleSignal. Si `[http].external_url` est défini, le nom inclut le nom d’hôte de l’instance, ce qui
    permet de distinguer plusieurs instances.
  </Step>
  <Step title="Saisissez le premier code">
    Saisissez le code à 6 chiffres affiché par l’application et cliquez sur **Activer**. L’activation n’a lieu que si le code
    correspond.
  </Step>
  <Step title="Enregistrez les codes de récupération">
    Si c’est le premier second facteur du compte, dix codes de récupération s’affichent, une seule fois.
    Conservez-les avec **Copier** ou **Télécharger**, puis cliquez sur **Je les ai enregistrés**.
  </Step>
</Steps>

Si le compte ne disposait pas encore d’un second facteur, l’activation ferme toutes ses sessions dans les autres
navigateurs et sur les autres ordinateurs, laisse la session actuelle ouverte et envoie une notification à l’adresse e-mail du compte.

## Se connecter

### Avec une clé d’accès, sans mot de passe

Sur la page de connexion, cliquez sur **Continuer avec une clé d’accès** ou sur **Se connecter avec votre adresse e-mail**, puis cliquez dans le champ
d’adresse e-mail et choisissez la clé d’accès parmi les suggestions du navigateur. La clé d’accès demande déjà une empreinte digitale, la reconnaissance faciale ou le code de déverrouillage de l’appareil.
Elle assure donc à elle seule l’authentification multifacteur, sans seconde étape.

### Trop de tentatives avec un mot de passe incorrect

Après trop de tentatives avec un mot de passe incorrect, la page de connexion indique le délai d’attente. Pour vous connecter sans attendre, utilisez une clé d’accès ou réinitialisez le mot de passe.
Les connexions par clé d’accès ne sont ni comptabilisées ni limitées : l’accès au compte reste possible même si
des tentatives de deviner le mot de passe sont en cours. Une réinitialisation réussie débloque immédiatement le compte. Consultez
[Limites de connexion](/fr/settings/platform#limites-de-connexion) pour connaître les seuils.

### La seconde étape après le mot de passe

Après la saisie du mot de passe, la page de connexion affiche **Confirmez votre identité** et propose les seconds facteurs configurés pour le compte :

| Méthode | Procédure |
|---|---|
| Clé d’accès | Cliquez sur **Confirmer votre identité avec une clé d’accès** et suivez les instructions du navigateur ou du système. |
| Application d’authentification | Saisissez le code à 6 chiffres. La page l’envoie dès la saisie du dernier chiffre. Le code fonctionne si l’écart entre l’horloge du téléphone et celle du serveur ne dépasse pas 30 secondes. Chaque code ne fonctionne qu’une fois. |
| Code de récupération | Saisissez un code de récupération inutilisé. Chaque code ne fonctionne qu’une fois. Après son utilisation, la page de connexion indique le nombre de codes restants et une notification est envoyée à l’adresse e-mail du compte. |

| Cas | Résultat |
|---|---|
| Cinq tentatives incorrectes lors d’une même connexion | La tentative de connexion prend fin. Saisissez à nouveau le mot de passe. |
| Dix codes incorrects en une heure | La saisie des codes de vérification et de récupération est bloquée pendant une heure, et une notification est envoyée à l’adresse e-mail du compte. Les clés d’accès permettent toujours de se connecter sans mot de passe. |
| Seconde étape non terminée dans les cinq minutes suivant la saisie du mot de passe | La tentative de connexion expire. Saisissez à nouveau le mot de passe. |

## Modes de connexion qui exigent une seconde étape

| Mode de connexion | Seconde étape |
|---|---|
| Mot de passe du compte | Oui. |
| Clé d’accès sans mot de passe | Non : la clé d’accès assure à elle seule l’authentification multifacteur. |
| LDAP | Oui : LDAP vérifie uniquement le mot de passe dans l’annuaire. |
| Authentification unique via OIDC, OAuth 2.0 ou SAML | Non : le fournisseur d’identité gère l’authentification multifacteur. |
| Première authentification unique avec association à un compte existant | Oui : après avoir confirmé l’association, terminez la seconde étape pour la valider. Consultez [Associer un compte existant](/fr/identity/sso#associer-un-compte-existant). |
| Connexion à un compte depuis un client de base de données (Flight SQL) | La connexion avec le mot de passe du compte est refusée. Utilisez un [jeton d’API](/fr/identity/tokens) qui commence par `mspat-`. Consultez [Clients de base de données](/fr/query/database-clients#authentification). |
| Jetons d’API | Aucun changement. |

## Gérer les codes de récupération

Si l’application d’authentification et les clés d’accès ne sont plus disponibles, utilisez un code de récupération par connexion. La ligne **Codes de récupération**
dans **Sécurité et connexion** indique le nombre de codes restants. **Générer de nouveaux codes** demande une confirmation et fournit
dix nouveaux codes de récupération. Les anciens codes cessent de fonctionner.

## Modifier les seconds facteurs

Sauf pour le renommage, chaque action exige une confirmation immédiate avec une clé d’accès, un code ou un
code de récupération.

| Action | Procédure |
|---|---|
| Renommer une clé d’accès | Cliquez sur **Renommer** sur la ligne correspondante. |
| Supprimer une clé d’accès | Cliquez sur **Supprimer**. Supprimez également toute copie conservée dans le trousseau iCloud ou dans un gestionnaire de mots de passe. Les navigateurs compatibles demandent au système de supprimer la copie restante lors de la prochaine tentative de connexion avec cette clé. |
| Remplacer l’application d’authentification | Cliquez sur **Remplacer l’application d’authentification**, confirmez, puis scannez le nouveau code QR et saisissez un code généré par l’application. Les codes de récupération restent inchangés. |
| Désactiver l’application d’authentification | Cliquez sur **Désactiver**. |

La suppression du dernier second facteur du compte désactive l’authentification multifacteur : les codes de récupération cessent
de fonctionner et un e-mail de notification est envoyé à l’adresse du compte. Tant qu’un espace de travail associé au compte
[exige l’authentification multifacteur](/fr/identity/sso#exigences-de-connexion), cette suppression est impossible :
les boutons **Désactiver** et **Supprimer** sont grisés et indiquent l’espace de travail qui l’exige.

## Réinitialisation par un administrateur

Lorsqu’un membre a perdu tous ses seconds facteurs et épuisé ses codes de récupération, un administrateur ouvre le
menu des actions du membre dans **Identité et accès → Utilisateurs** et clique sur **Réinitialiser l’authentification
multifacteur**. Cette action exige l’autorisation `org.members.mfa_reset`. L’application d’authentification, les clés d’accès et les codes de récupération
du membre cessent de fonctionner. Toutes les sessions prennent fin et un e-mail de notification est envoyé à l’adresse du compte. Le membre
se connecte ensuite avec son mot de passe et configure à nouveau l’authentification multifacteur. Si un espace de travail l’exige, cette configuration s’effectue au moment de la
connexion.

| Membre | Qui peut réinitialiser l’authentification multifacteur |
|---|---|
| Membre de cette organisation uniquement | Un administrateur de cette organisation. |
| Membre d’autres organisations également | Seul l’administrateur de la plateforme : la réinitialisation affecte toutes les organisations du membre. |
| Utilisateur racine | Uniquement sur le serveur, avec une [réinitialisation hors ligne](#réinitialisation-hors-ligne). |

Dans la liste **Utilisateurs**, la colonne **MFA** indique si l’authentification multifacteur est activée pour chaque membre.

## Réinitialisation hors ligne

Si l’utilisateur racine a perdu tous ses seconds facteurs ou si aucun administrateur ne peut se connecter, exécutez cette commande sur le serveur :

```bash
molesignal --config /etc/molesignal/config.toml reset-mfa --email root@example.com
```

La commande désactive l’authentification multifacteur du compte, met fin à toutes ses sessions et
se termine sans démarrer le service.

## Fermeture des sessions

Les actions suivantes mettent fin aux sessions du compte dans les autres navigateurs et sur les autres ordinateurs, dès la requête suivante
dans chacune de ces sessions :

- l’ajout du premier second facteur, qui active l’authentification multifacteur ;
- le remplacement ou la désactivation de l’application d’authentification, ou la suppression d’une clé d’accès ;
- la réinitialisation par un administrateur ;
- l’action **Déconnecter tous les autres appareils** dans **Sessions actives** ;
- la réinitialisation du mot de passe à partir du lien reçu par e-mail, qui met fin à toutes les sessions du compte.

Lorsqu’un espace de travail active une [exigence de connexion](/fr/identity/sso#exigences-de-connexion), les sessions
qui ne la respectent pas prennent fin dans les 15 minutes.
