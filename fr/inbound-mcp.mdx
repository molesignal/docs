Le **MCP entrant** permet à Claude Code, Cursor, Codex, ChatGPT et aux autres clients MCP de découvrir et
d’utiliser MoleSignal via le même environnement d’exécution contrôlé des outils que Mole Agent. Le client se connecte
de deux façons :

- **stdio** (recommandé) : le client lance la CLI MoleSignal avec la commande `molesignal mcp` du paquet npm
  `@molesignal/cli`. La CLI s’authentifie une seule fois dans le navigateur et transmet chaque message
  au point de terminaison ci-dessous.
- **Streamable HTTP** : le client appelle directement le point de terminaison.

Le point de terminaison est le suivant :

```text
https://molesignal.example.com/api/v1/mcp
```

Le serveur utilise Streamable HTTP et prend en charge les versions `2026-07-28`,
`2025-11-25`, `2025-06-18` et `2025-03-26` du protocole MCP. L’ancien transport HTTP+SSE n’est pas exposé ; la CLI
fournit le transport stdio.

Un administrateur disposant de l’autorisation `agent.inbound_mcp.manage` peut modifier le paramètre du serveur dans
**Mole Agent → Paramètres → MCP entrant**.

## Avant la connexion

1. Pour tout déploiement accessible en dehors de l’interface de bouclage, renseignez `http.external_url` avec l’origine publique
   de MoleSignal. Consultez [Configuration](/fr/configuration).
2. Ouvrez **Mole Agent → Paramètres → MCP entrant** et vérifiez que le serveur est activé.
3. Copiez le point de terminaison complet affiché sur la page, y compris le schéma et l’hôte.
4. Choisissez OAuth 2.1, un jeton d’API personnel ou un jeton d’API de compte de service.

Les modifications des limites et des listes d’origines autorisées
prennent effet au début de la prochaine requête HTTP MCP. Une requête en cours conserve
les paramètres en vigueur à son démarrage.

## Connexion via stdio

Connectez-vous une seule fois avec la CLI MoleSignal. Elle nécessite Node.js 20 ou une version ultérieure :

```bash
npx -y @molesignal/cli login --url https://molesignal.example.com
```

Le navigateur ouvre MoleSignal pour valider la connexion. La CLI conserve les données d’authentification dans
`~/.config/molesignal/config.json` (accessible en lecture uniquement au compte local concerné) et les renouvelle. Ajoutez ensuite MoleSignal
au client comme serveur stdio avec la commande `npx -y @molesignal/cli mcp` :

| Client | Configuration |
|---|---|
| Claude Code | `claude mcp add --scope user molesignal -- npx -y @molesignal/cli mcp` |
| Cursor | `{"mcpServers": {"molesignal": {"command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` dans `~/.cursor/mcp.json` |
| Codex | `codex mcp add molesignal -- npx -y @molesignal/cli mcp` |
| VS Code | `{"servers": {"molesignal": {"type": "stdio", "command": "npx", "args": ["-y", "@molesignal/cli", "mcp"]}}}` dans `.vscode/mcp.json` |
| Gemini CLI | `gemini mcp add molesignal npx -y @molesignal/cli mcp` |

`npx -y @molesignal/cli status` vérifie la connexion et compte les outils. En l’absence de navigateur,
définissez `MOLESIGNAL_URL` et `MOLESIGNAL_TOKEN` (un jeton d’API) dans l’environnement du serveur
plutôt que de passer par la connexion interactive. Après l’installation avec `npm install -g @molesignal/cli`, lancez la CLI avec
la commande `molesignal`. La page [CLI MoleSignal](/fr/cli) décrit toutes ses commandes.

Dans **Mole Agent → Paramètres → MCP entrant**, le **Prompt de configuration** génère les étapes à faire suivre à
un outil agent. Sélectionnez **stdio** ou **Streamable HTTP** au-dessus du prompt.

## Connexion avec un jeton d’API

Les jetons d’API conviennent aux clients non interactifs et à l’automatisation.

<Tabs>
  <Tab title="Jeton d’API personnel">
    Créez un jeton dans **Identité et accès → Jetons d’API**. Le jeton utilise l’identité de l’utilisateur actuel et
    le rôle qui lui est attribué. Transmettez-le via le mécanisme de gestion des secrets ou des variables d’environnement du client, sous la forme
    `Authorization: Bearer <token>`.
  </Tab>
  <Tab title="Jeton d’API de compte de service">
    Créez un compte de service dans **Identité et accès → Comptes de service**. MoleSignal génère automatiquement
    un jeton d’API associé au compte et l’affiche en clair une seule fois.

    Un compte de service est une identité non interactive. Il ne peut ni se connecter à l’interface Web ni approuver
    une autorisation OAuth. Transmettez le jeton initial via le mécanisme de gestion des secrets ou des variables d’environnement
    du client, sous la forme `Authorization: Bearer <token>`.
  </Tab>
</Tabs>

N’incluez jamais de jeton d’API dans un commit contenant un fichier de configuration MCP au niveau du projet. Les exemples pour Codex et Claude Code
montrent des configurations qui utilisent des variables d’environnement pour un usage non interactif.

Le MCP entrant accepte uniquement les jetons d’API personnels, les jetons d’API de compte de service et les jetons d’accès OAuth. Les identifiants d’ingestion et de RUM
ne donnent pas accès à ce point de terminaison. MoleSignal ne renvoie jamais d’identifiants en clair dans les ressources
ou les outils MCP, ni dans l’historique d’exécution ou les enregistrements d’audit.

## Découverte et durée de validité OAuth

MoleSignal publie les métadonnées OAuth à l’adresse suivante :

```text
https://molesignal.example.com/.well-known/oauth-protected-resource/api/v1/mcp
https://molesignal.example.com/.well-known/oauth-authorization-server
```

Le serveur d’autorisation prend en charge le flux par code d’autorisation avec PKCE `S256`, la liaison aux ressources
selon la RFC 8707, l’enregistrement dynamique des clients, la rotation des jetons d’actualisation et la révocation par famille de jetons.
Les jetons d’accès sont valides une heure. Les jetons d’actualisation nécessitent la portée `offline_access` et
le type d’autorisation `refresh_token`. Ils sont valides 30 jours et sont remplacés à chaque utilisation.

Consultez et révoquez les connexions OAuth actives depuis **Mole Agent → Paramètres → MCP
entrant**. Sous ces connexions, le **Prompt de configuration** contient le point de terminaison de ce déploiement. Sélectionnez
**Copier le prompt**, puis collez-le dans un outil agent comme Claude Code ou Cursor. L’outil ajoute
MoleSignal comme serveur MCP.

## Cloisonnement entre organisations

N’envoyez jamais `userId` ni `orgId` dans l’URL du point de terminaison, dans un en-tête personnalisé ou dans les arguments d’un outil.
MoleSignal déduit les deux identités du jeton authentifié, recharge l’état actuel des autorisations IAM
à chaque requête et lie la session MCP au jeton utilisé pour l’ouvrir.

L’ensemble effectif des outils est le suivant :

```text
Inbound MCP surface ∩ credential IAM permissions ∩ workspace Tool Policy
```

Les profils d’agent ne restreignent pas le MCP entrant. Ce point de terminaison ne relaie ni les serveurs MCP sortants configurés pour Mole Agent
ni leurs outils distants.

Aucun jeton ne permet de lire les lignes ou les champs du [flux `_audit`](/fr/settings/data-security#flux-d’audit) via le MCP
entrant. Ouvrez ce flux dans **Journaux**.

## Commencez par les adaptateurs d’outils

`tools/list` annonce un ensemble restreint d’outils autorisés : sept outils de lecture courants, des contrôles d’approbation et d’exécution,
et trois adaptateurs de découverte progressive.

| Adaptateur | Rôle |
|---|---|
| `tool_search` | Recherchez dans l’ensemble du catalogue autorisé du MCP entrant. |
| `call_read_tool` | Exécutez un outil de lecture seule ou de vérification préalable trouvé dans le catalogue. |
| `call_managed_tool` | Exécutez une modification gérée avec un outil trouvé dans le catalogue, en fournissant obligatoirement une `idempotencyKey`. |

Exemples de requêtes :

- « Recherchez les incidents récents avec les outils de MoleSignal, puis résumez l’incident ouvert qui a le plus fort impact. »
- « Trouvez les outils de pages de statut et listez les incidents actifs. N’apportez aucune modification. »
- « Testez cette règle d’alerte, puis mettez-la à jour uniquement après avoir obtenu la confirmation ou l’approbation requise. »

Consultez [Catalogue et exécution des outils](/fr/tools) pour connaître les schémas de découverte, les niveaux de risque, les modalités
d’approbation et les domaines fonctionnels pris en charge.

## Limites d’exécution

| Limite | Valeur par défaut | Plage autorisée |
|---|---:|---:|
| Taille de la requête | 1 MB | 1–8 MB |
| Taille de la réponse | 1 MB | 1–8 MB |
| Appels HTTP simultanés par identifiant d’accès | 8 | 1–128 |
| Appels HTTP par minute et par identifiant d’accès | 60 | 1–10 000 |
| Délai d’expiration des outils de lecture | 30 secondes | 100 ms–300 secondes |

Modifiez ces valeurs dans **Mole Agent → Paramètres → MCP entrant**. La politique d’utilisation des outils de l’organisation peut
imposer un délai d’expiration plus court ou une taille maximale de réponse plus faible pour un outil donné.

## Vérification de l’origine du navigateur et de l’hôte

Le serveur accepte les requêtes sans en-tête `Origin` des clients MCP qui ne passent pas par un navigateur. Les requêtes du navigateur
doivent provenir de la même origine ou correspondre exactement à une origine HTTP ou HTTPS configurée dans les paramètres du MCP entrant.

Pour les déploiements hors boucle locale, l’en-tête `Host` de la requête doit correspondre à `http.external_url`. Cette vérification
empêche les attaques par réassociation DNS contre les serveurs MCP locaux.

## Résoudre les problèmes de connexion

| Symptôme | Vérification |
|---|---|
| `401 missing Authorization Bearer token` | Exécutez `codex mcp login molesignal` ou configurez une variable d’environnement prise en charge pour le jeton d’API. |
| La page d’autorisation demande une nouvelle connexion | Utilisez le même schéma et le même hôte pour l’interface Web, `http.external_url` et le point de terminaison MCP. Évitez de mélanger `localhost` et `127.0.0.1`. |
| `duplicate field resource` | Supprimez l’option `--oauth-resource` configurée manuellement, puis enregistrez de nouveau le point de terminaison. |
| Le rappel OAuth signale un refus de connexion | Laissez le client MCP en cours d’exécution jusqu’à ce que le navigateur redirige vers l’adresse de rappel temporaire sur la boucle locale. Relancez `codex mcp login` si le service d’écoute s’est arrêté. |
| Le point de terminaison MCP renvoie `403` | Vérifiez que le serveur est activé, puis contrôlez l’origine du navigateur, l’état de l’identifiant d’accès, l’autorisation IAM et la politique d’utilisation des outils. |
| Un outil n’apparaît pas | Recherchez-le avec `tool_search`. Si la recherche ne renvoie aucun résultat, vérifiez que l’outil est exposé via le MCP entrant, puis contrôlez les autorisations IAM et la politique d’utilisation des outils. |
