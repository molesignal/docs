Ouvrez **Journaux** pour effectuer des recherches dans les flux de journaux de l’espace de travail actif.

## Choisir un flux et une plage temporelle

Sélectionnez un flux de journaux, puis définissez la plage temporelle la plus courte qui contient l’événement. Les plages courtes
réduisent le nombre de lignes parcourues et accélèrent l’exploration des champs.

MoleSignal peut déduire le schéma d’un flux à mesure que les événements arrivent. Le panneau **Champs** répertorie les champs du
flux et permet d’ajouter des filtres sans réécrire toute la requête.

## Onglets de requête

Chaque requête s’exécute dans son propre onglet. Un onglet conserve son flux, sa requête et sa plage temporelle. Une requête dans
un onglet n’a aucun effet sur les autres.

- Sélectionnez **Nouvel onglet** pour ouvrir une autre requête. Ouvrez jusqu’à 10 onglets à la fois.
- Ouvrez le menu d’un onglet pour le **Renommer**, le **Dupliquer** ou le **Fermer**.
- Sélectionnez **Scinder en deux** pour afficher deux onglets côte à côte. Chaque moitié affiche ses propres onglets. Pour déplacer un onglet
  vers l’autre moitié, utilisez son menu. Sélectionnez **Revenir à une seule page** pour quitter l’affichage scindé.

Le navigateur conserve les onglets ouverts pour chaque compte et chaque espace de travail.

## Écrire une requête

L’éditeur propose deux modes, **Code** et **Éditeur visuel**. Passez de l’un à l’autre avec les deux icônes à côté du titre (`</>` pour
le mode Code, les blocs pour l’Éditeur visuel). Survolez une icône pour afficher son libellé.

Le mode **Code** accepte les requêtes par champ et les instructions SQL. Une instruction qui commence par `SELECT` ou `WITH` s’exécute en SQL.
Toute autre instruction s’exécute comme une requête par champ :

| Requête par champ | Signification |
|---|---|
| `service = 'checkout'` | Le champ contient exactement cette valeur. |
| `message contains 'timeout'` | Le champ contient ce texte. |
| `MATCH(message, 'timeout')` | Recherche de sous-chaîne sans distinction de casse. |
| `MATCH_TEXT(message, 'timeout disk')` | Recherche en texte intégral dans un champ doté d’un index de texte intégral. |

Combinez les conditions avec `AND` et `OR`, sans distinction de casse. `AND` est prioritaire sur `OR`. Utilisez des parenthèses
pour regrouper les conditions : `level = 'error' AND (service = 'checkout' OR service = 'payments')`. Si aucun champ n’est indiqué,
la recherche porte sur le champ `message`. Le texte peut constituer l’une des alternatives :
`timeout OR "connection reset"`. Les guillemets délimitent une expression exacte, même si elle contient un mot comme `or`.
Utilisez les opérateurs de comparaison `=`, `!=`, `>`, `>=`, `<` et `<=`.

L’**Éditeur visuel** affiche la même requête par champ sous forme de lignes de filtres, à raison d’une ligne par alternative :
tous les filtres d’une ligne doivent correspondre, et **OU** précède chaque ligne après la première. Sélectionnez **Filtrer** pour
ajouter un filtre à une ligne, ou **OU** pour ajouter une ligne, puis choisissez un champ, un opérateur de comparaison et une valeur. Chaque
ligne a son propre texte de recherche. Une expression entre parenthèses dans une ligne, comme le `OR` de l’exemple
ci-dessus, reste telle quelle. Modifiez-la dans le mode **Code**. L’éditeur ne peut pas afficher une instruction SQL sous forme de
filtres.

Utilisez SQL pour les jointures, les expressions, les CTE ou les agrégations :

```sql
SELECT "_timestamp", level, msg, trace_id
FROM app
WHERE level = 'error'
ORDER BY "_timestamp" DESC
LIMIT 200;
```

```sql
SELECT level, COUNT(*) AS events
FROM app
GROUP BY level
ORDER BY events DESC;
```

Sélectionnez **Exécuter** pour lancer la requête, ou appuyez sur `⌘ Enter` ou `Ctrl+Enter` dans l’éditeur. La **Référence de la
syntaxe des requêtes** présente des exemples pour le mode actif. Consultez [Requêtes](/fr/query#recherche-textuelle) pour connaître les fonctions de recherche
textuelle.

Le planificateur de requêtes limite la recherche à l’organisation active, même pour les requêtes SQL personnalisées.

## Explorer les champs

Le panneau **Champs** comporte trois sections : **Champs affichés**, **Champs indexés** et **Autres
champs**. Les champs dont le nom commence par le même préfixe suivi d’un point, comme `http.method` et
`http.route`, s’ouvrent dans un même groupe.

- Développez un champ pour voir ses valeurs les plus fréquentes dans les résultats. Ajoutez une valeur comme filtre d’inclusion ou
  d’exclusion. Le filtre restreint l’ensemble de la requête : si la requête contient des alternatives, l’éditeur les place entre parenthèses
  avant d’ajouter le filtre.
- Affichez ou masquez la colonne d’un champ dans les résultats.
- Sélectionnez **Analyser** sur un champ pour afficher son analyse : le nombre de valeurs distinctes, les nombres de lignes
  avec et sans valeur, les statistiques pour les champs numériques, la distribution des valeurs et les valeurs
  les plus fréquentes au fil du temps.

## Lire les résultats

L’histogramme au-dessus des résultats compte tous les événements qui correspondent à la requête dans la plage temporelle, et pas
seulement ceux de la page chargée. Les résultats se déclinent en quatre vues :

| Vue | Contenu |
|---|---|
| **Journaux** | Les événements correspondants, à raison d’un événement par ligne. |
| **Statistiques** | Un graphique d’agrégation. Choisissez la mesure (nombre total, nombre de valeurs distinctes, moyenne, somme, minimum, maximum, P50, P95 ou P99), le regroupement et le type de graphique, ou tracez le résultat d’une agrégation SQL. **Créer un tableau de bord** enregistre le graphique comme panneau d’un nouveau tableau de bord. |
| **Analyse par l’IA** | Un rapport de Mole Agent sur les journaux qui correspondent à la requête. Consultez [Analyses des journaux](/fr/logs/inspections). |
| **Motifs** | Les événements regroupés par motif, avec le nombre d’événements et la part de chaque motif. |

Dans la vue **Journaux** :

- Utilisez **Colonnes** pour sélectionner et ordonner les colonnes. Les colonnes par défaut proviennent des champs du
  flux : l’horodatage, puis le niveau, le service et le message si le flux contient ces champs.
- Chaque page contient 100, 200, 500, 1 000, 2 000 ou 5 000 événements.
- Cliquez sur un événement pour l’ouvrir dans un panneau latéral à côté des résultats. Faites glisser le bord gauche du panneau pour le redimensionner :
  l’interface conserve sa largeur. L’en-tête affiche le niveau, l’horodatage, le message et les attributs qui
  caractérisent l’événement (service, hôte, environnement, version, trace). Chaque attribut propose les mêmes actions qu’un
  champ. Les vues sont **Champs**, **Trace** si l’événement contient un identifiant de trace, **Contexte** et
  **JSON brut**. **Trace** affiche le diagramme en cascade de la trace et sélectionne le span de l’événement. **Contexte**
  affiche les cinq lignes qui précèdent l’événement et les cinq qui le suivent. Depuis un champ, ajoutez un filtre, copiez la valeur ou affichez le
  champ sous forme de colonne.
- Accédez à une trace, à un service, à une métrique ou à un autre signal corrélé si les identifiants sont disponibles.
- Téléchargez les résultats au format CSV, texte ou JSON.

## Partager une requête

L’adresse de la page reflète la requête à l’écran. Lors de l’exécution, la page inscrit dans l’adresse le flux, la
requête (`q` pour une requête par champ, `sql` pour SQL) et la vue des résultats. Copiez
l’adresse dans la barre d’adresse pour partager la requête avec la plage temporelle affichée dans le sélecteur, par exemple la dernière
heure. Le rechargement de la page conserve la requête et l’état de l’éditeur.

Sélectionnez **Partager** pour copier un lien vers la requête à l’écran. Le lien s’ouvre pour les membres connectés de
l’organisation qui disposent d’un accès en lecture aux données. Choisissez la plage temporelle du lien : **Plage temporelle sélectionnée**
fixe les bornes aux dates et heures affichées. L’autre option conserve une plage relative, comme la
dernière heure, calculée à partir du moment où le lien s’ouvre.

## Tâches de recherche

Une recherche trop volumineuse pour une requête interactive s’exécute sous forme de tâche de recherche. Ouvrez
**Flux → Tâches de recherche** pour suivre la tâche et télécharger les résultats. Consultez
[Flux](/fr/streams#tâches-de-recherche).

## Vues enregistrées

Enregistrez une requête SQL sous un nom dans une [vue enregistrée](/fr/saved-views). Rouvrez la vue, exécutez la requête
sur une autre plage temporelle ou joignez la vue à un rapport.

<Tip>
  Conservez des dimensions stables comme `service.name`, `deployment.environment`, `trace_id` et
  `host.name` lors de l’ingestion. Ces champs permettent de passer d’un signal à un autre de manière fiable.
</Tip>

## Autorisations

- `streams.read` permet de découvrir les flux et leurs schémas.
- `logs.read` permet de consulter les journaux : la liste, l’histogramme et les statistiques des champs.
- `streams.query` permet d’exécuter une instruction SQL et d’ouvrir le contexte.
- `agent.use` permet de lancer une analyse par l’IA, qui nécessite aussi un modèle d’IA actif.
- `saved_views.create`, `saved_views.edit` et `saved_views.delete` régissent respectivement la création, la modification et la suppression des vues enregistrées.
