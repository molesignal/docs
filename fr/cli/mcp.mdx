`molesignal mcp` met les outils MCP de MoleSignal à disposition via stdio. L’outil d’agent lance la commande
et communique avec elle via l’entrée et la sortie standard ; la CLI transmet chaque message au
point de terminaison **MCP entrant** de MoleSignal et renvoie chaque réponse. MoleSignal gère les outils, leurs autorisations et
leurs approbations. La CLI n’en ajoute aucun.

## Ajouter le serveur à un outil d’agent

[Connectez-vous](/fr/cli/sign-in), puis laissez la CLI s’ajouter à l’outil d’agent :

```bash
molesignal mcp setup claude
```

| Outil d’agent | Modifications apportées par `molesignal mcp setup` |
|---|---|
| `claude` | Exécute `claude mcp add` pour Claude Code. `--scope` accepte `user` (par défaut), `project` ou `local`. |
| `cursor` | `~/.cursor/mcp.json` ou `.cursor/mcp.json` dans le dossier actuel avec `--scope project`. |
| `codex` | `~/.codex/config.toml`, dans `CODEX_HOME` si cette variable est définie. |
| `vscode` | `.vscode/mcp.json` dans le dossier actuel. |
| `gemini` | `~/.gemini/settings.json` ou `.gemini/settings.json` dans le dossier actuel avec `--scope project`. |

La commande ajoute un serveur nommé `molesignal` ou remplace le serveur du même nom. Elle conserve tous les autres
paramètres du fichier. Le serveur exécute `npx -y @molesignal/cli mcp` ; `--installed` utilise à la place la
version installée de `molesignal`. `--profile` inscrit le profil dans la configuration du serveur. L’outil d’agent
utilise ainsi les identifiants de ce profil, quel que soit le profil actif. `--print` affiche la configuration au lieu de
l’écrire dans le fichier.

[Se connecter via stdio](/fr/inbound-mcp#connexion-via-stdio) présente la même configuration pour chaque
outil. L’invite de configuration dans **Mole Agent → Paramètres → MCP entrant** génère les étapes propres à
l’instance.

En l’absence de connexion utilisateur, par exemple sur une machine de compilation, fournissez les identifiants du serveur dans les
variables d’environnement :

```json
{
  "mcpServers": {
    "molesignal": {
      "command": "npx",
      "args": ["-y", "@molesignal/cli", "mcp"],
      "env": {
        "MOLESIGNAL_URL": "https://molesignal.example.com",
        "MOLESIGNAL_TOKEN": "<token>"
      }
    }
  }
}
```

## Transmission des messages

- Tant que l’outil d’agent n’a pas envoyé `notifications/initialized`, la CLI transmet les messages un par un, dans
  l’ordre : MoleSignal ouvre la session en répondant à `initialize`. Ensuite, la CLI transmet les messages
  dès leur arrivée. Un appel d’outil lent ne bloque donc pas les autres.
- Si MoleSignal ne reconnaît plus la session, par exemple après un redémarrage, la CLI en ouvre une nouvelle avec
  le message `initialize` de l’outil d’agent, puis renvoie le message. L’outil d’agent poursuit son exécution sans
  redémarrer.
- Si une requête ne peut pas atteindre MoleSignal, la CLI renvoie une erreur pour que l’outil d’agent ne reste pas
  en attente.
- Quand l’outil d’agent ferme l’entrée standard, la CLI met fin à la session côté MoleSignal, puis se termine.
- La CLI écrit les messages d’information, par exemple pour signaler une perte de connexion, sur la sortie d’erreur standard.
  La sortie standard ne transporte que les messages MCP.
- `HTTPS_PROXY` et `NO_PROXY` s’appliquent, comme pour toutes les commandes.

## Vérifier la connexion

```bash
molesignal status
```

Le nombre d’outils correspond à celui qu’affiche l’outil d’agent. Si ce nombre est nul, c’est généralement que la
politique d’utilisation des outils de l’organisation ou les autorisations du compte ne donnent accès à aucun outil.
