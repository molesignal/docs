Les commandes de la CLI couvrent les tâches courantes. Pour tous les autres outils du catalogue MoleSignal, comme les
outils de RUM, de profilage ou de gestion des pages de statut, utilisez `molesignal call`.

## Rechercher un outil

```bash
molesignal tools incident
```

La liste affiche les outils qui correspondent le mieux aux mots saisis, le type d’appel (`read` ou
`change`), les règles d’exécution des modifications selon la politique d’utilisation des outils de l’organisation et le rôle de chaque outil.
Sans mot-clé, la commande répertorie tous les outils accessibles. `--domain` limite la liste à un domaine, par exemple
`observability` ou `alerts_on_call`.

`molesignal tools show` affiche un outil et les arguments acceptés au format JSON Schema :

```bash
molesignal tools show list_rum_sessions
```

## Appeler un outil

```bash
molesignal call list_rum_sessions --since 1h limit=20
```

La commande affiche le résultat de l’outil au format JSON. Saisissez les arguments comme suit :

| Syntaxe | Valeur transmise |
|---|---|
| `name=value` | La valeur, convertie dans le type attendu par le schéma de l’outil : du texte, un nombre, `true` ou `false`, ou une liste construite à partir de `a,b`. |
| `name:=json` | Le JSON tel que saisi, par exemple `match:='{"service":"checkout"}'`. |
| `parent.child=value` | Un champ dans un objet, par exemple `timeRange.startTime=…`. |
| `--input <file>` | Un objet JSON contenant les arguments lus dans un fichier, ou depuis l’entrée standard avec `-`. Les paires indiquées ensuite s’ajoutent à cet objet. |
| `--since`, `--from`, `--to` | La valeur de `timeRange` pour les outils qui acceptent ce champ. |

Tout outil qui effectue une modification suit la politique d’utilisation des outils, comme indiqué dans
[Exécution d’une modification](/fr/cli/changes#comment-une-modification-s’exécute). Les options `--reason`, `--wait`, `--timeout` et
`--yes` s’appliquent. La demande d’approbation reprend sans modification tout argument `reason` ou `impact`.

```bash
molesignal call trigger_alert_rule rule_id=<rule> --reason "Testing the pager"
```

## Ouvrir une page

`molesignal open` ouvre une page de MoleSignal dans le navigateur. Sans nom de page, la commande ouvre la page d’accueil :

```bash
molesignal open logs app_logs
```

Les pages disponibles sont `home`, `logs`, `metrics`, `traces`, `services`, `incidents`, `oncall`,
`synthetics`, `dashboards`, `approvals`, `jobs`, `streams` et `agent`. La plupart acceptent un identifiant, par exemple
celui d’une trace, d’un incident ou d’un tableau de bord. `--print` affiche l’adresse sans ouvrir la page.

Les commandes `logs`, `query`, `traces show`, `incidents show` et `services show` acceptent l’option `--web` pour ouvrir
les résultats dans le navigateur au lieu de les afficher dans le terminal.

## Activer l’autocomplétion des commandes dans le shell

`molesignal completion` affiche un script d’autocomplétion pour les commandes, les sous-commandes, les profils et les noms
de flux. Le script récupère les noms de flux toutes les quelques minutes. Pour bash :

```bash
echo 'source <(molesignal completion bash)' >> ~/.bashrc
```

Pour zsh :

```bash
echo 'source <(molesignal completion zsh)' >> ~/.zshrc
```

Pour fish :

```bash
molesignal completion fish > ~/.config/fish/completions/molesignal.fish
```
