## Interroger les métriques

`molesignal metrics query` exécute une requête PromQL sur une période et affiche une ligne par série : la dernière valeur,
les valeurs minimale et maximale sur la période, un mini-graphique de la série et ses étiquettes.

```bash
molesignal metrics query 'sum by (service) (rate(http_server_requests_total[5m]))' --since 6h
```

```text
LAST   MIN    MAX    TREND                           SERIES
12.4   3.1    14.9   ▁▂▂▃▅▆▇█▇▆▆▅▅▆▇▇█▇▆▅▄▄▅▅▆▆▇▇▇▆   {service="checkout"}
```

Par défaut, la requête porte sur la dernière heure. `--since`, `--from` et `--to` modifient cette période. `-n` limite le nombre
de points à `1000` par défaut. `--json` affiche chaque série avec ses points, et `--csv` affiche
un point par ligne.

Quatre autres sous-commandes permettent de trouver les données à interroger :

| Commande | Éléments listés |
|---|---|
| `molesignal metrics names [text]` | Les noms des métriques qui contiennent le texte indiqué. |
| `molesignal metrics labels <metric>` | Les étiquettes d’une métrique. |
| `molesignal metrics values <metric> <label>` | Les valeurs d’une étiquette et le nombre d’occurrences de chacune. |
| `molesignal metrics series <metric>` | Les séries d’une métrique. `--match label=value` filtre la liste. |

## Rechercher des traces

```bash
molesignal traces --service checkout --errors --since 6h
```

La liste affiche les traces les plus récentes, avec leur heure de début, leur durée, leur nombre de spans et leur service.

| Option | Signification |
|---|---|
| `--service <name>` | Uniquement les traces de ce service. |
| `--errors` | Uniquement les traces qui contiennent un span en échec. |
| `--min-duration <time>` | Uniquement les traces qui ont duré au moins le temps indiqué, par exemple `500ms`. |
| `--since`, `--from`, `--to` | La période de recherche, limitée à la dernière heure par défaut. |
| `-n`, `--limit <count>` | Le nombre de traces, `20` par défaut et `200` au maximum. |

## Afficher une trace

`molesignal traces show` affiche une trace sous forme de graphique en cascade, à raison d’une ligne par span, sous son parent.
Une barre indique quand le span s’est exécuté dans la trace et combien de temps il a duré. La commande signale les spans en échec par
`!` et les affiche en rouge dans un terminal.

```bash
molesignal traces show 4bf92f3577b34da6a3ce929d0e0e4736
```

```text
checkout POST /orders          ████████████████████████████████████████  1.24s
├─ checkout SELECT orders       ███                                       98ms
└─ ! payments POST /charge         ███████████████████████████████████    1.1s
```

`--web` ouvre la trace dans MoleSignal, et `--json` affiche ses spans.

## Afficher un récapitulatif des services

```bash
molesignal services --env production --sort errors
```

La liste affiche, pour chaque service APM, le nombre de requêtes, le taux d’erreur, la latence p95, l’état de santé et la version
actuelle. `--sort` trie la liste par `requests`, `errors`, `p95` ou `name`.

`molesignal services show` récapitule les données d’un service : le débit de requêtes, les erreurs et la latence, puis les
points de terminaison, les dépendances, les erreurs et les versions :

```bash
molesignal services show checkout --since 2h
```

## Comparer deux versions

`molesignal services compare` compare deux versions d’un service et indique si la
version candidate présente une régression, une amélioration ou aucun changement, ou si les requêtes sont trop peu nombreuses pour conclure. Avec
`--fail-on-regression`, la commande renvoie le code `1` en cas de régression. Un pipeline peut ainsi interrompre la
mise en production :

```bash
molesignal services compare checkout 2.3.9 2.4.0 --since 1h --fail-on-regression
```

## Exécuter des requêtes longues sous forme de tâches de recherche

Une tâche de recherche exécute une requête en arrière-plan sur plus de données et sur une période plus longue qu’une requête
immédiate. Elle conserve le résultat pendant un certain temps. Comme pour toute modification, la politique d’utilisation des outils de
l’organisation régit la soumission et l’annulation des tâches. Consultez
[Incidents et modifications](/fr/cli/changes#comment-une-modification-s’exécute).

```bash
molesignal search-jobs submit "SELECT * FROM app_logs WHERE level = 'error'" --since 30d --wait
```

La commande utilise le premier flux après `FROM`. `--stream` sélectionne un autre flux, et `--promql` soumet une
requête PromQL que la tâche évalue à la fin de la période, ou à chaque pas `--step`, par exemple `1m`. `--limit` fixe le nombre maximal
de lignes conservées, sans dépasser `100000`, et `--keep` fixe leur durée de conservation. `--wait` attend
la fin de la tâche. La commande affiche l’identifiant de la tâche.

| Commande | Effet |
|---|---|
| `molesignal search-jobs` | Liste les tâches de recherche avec leur état, leurs lignes et leur requête. |
| `molesignal search-jobs show <job>` | Affiche l’état, les lignes, les horodatages et l’erreur d’une tâche. |
| `molesignal search-jobs results <job>` | Écrit les résultats d’une tâche terminée, à raison d’un objet JSON par ligne. `--csv` utilise le format CSV et `-o <file>` écrit les résultats dans un fichier. |
| `molesignal search-jobs cancel <job>` | Annule une tâche en attente ou en cours d’exécution. |

## Accès

Les métriques nécessitent `streams.query`, les traces `traces.read`, l’APM `apm.services.read` et les tâches de recherche `query.jobs.read` et
`query.jobs.run`. `sys.telemetry.read` autorise la lecture de toutes ces données dans le périmètre `_sys`. La politique d’utilisation des outils de l’organisation doit laisser
les outils activés.
