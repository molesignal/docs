## Comment une modification s’exécute

Une commande qui apporte une modification, comme la prise en compte d’un incident, envoie une demande à MoleSignal via un
outil géré, comme le font Mole Agent et les outils d’agent. La politique d’utilisation des outils de l’organisation définit le mode d’exécution de chaque
outil dans **Mole Agent → Paramètres → Outils et capacités** :

| Mode d’exécution | Comportement de la commande |
|---|---|
| Automatique | La modification s’applique immédiatement. |
| Confirmation | MoleSignal exige une confirmation, que la commande demande dans le terminal. `-y` (`--yes`) répond oui à l’avance, par exemple en CI. Sans terminal ni option `--yes`, rien ne change. |
| Approbation simple, double approbation | MoleSignal crée une demande d’approbation à examiner dans **Mole Agent → Approbations**. La commande affiche la demande et se termine avec le code `3`. Avec `--wait`, elle attend la décision pendant la durée définie par `--timeout` (30 minutes par défaut), puis applique la modification si la demande est approuvée. |
| Désactivé | La commande échoue et en indique la raison. |

Sans politique propre, le mode d’exécution d’un outil dépend de son niveau de risque : par défaut, la confirmation s’applique à
`create_annotation` et `submit_search_job`, et l’approbation simple à `acknowledge_incident`,
`resolve_incident` et `run_synthetic_monitor`. `--reason` indique le motif pour l’examen de la demande et le
journal d’audit.

La confirmation nécessite la révision 2026-07-28 du protocole MCP. La CLI l’utilise si MoleSignal l’utilise également.
`molesignal status` indique la révision utilisée.

## Lister les incidents

```bash
molesignal incidents
```

La liste affiche les incidents actifs, du plus récent au plus ancien, avec leur statut, leur gravité, leur ancienneté, les services concernés
et un résumé. `--status resolved` ou `--status all` affiche aussi des incidents résolus. `--since 7d` limite la liste aux incidents ouverts
dans les 7 derniers jours et `-n` fixe le nombre de résultats.

`molesignal incidents show` affiche les détails d’un incident : sa règle, ses horodatages, ses services, ses libellés, des notes telles que
le guide d’intervention, et un échantillon de traces. `--rca` ajoute l’analyse de la cause racine et `--web` ouvre
l’incident dans MoleSignal :

```bash
molesignal incidents show <incident> --rca
```

## Prendre en compte et résoudre des incidents

```bash
molesignal incidents ack <incident>
```

```bash
molesignal incidents resolve <incident> --reason "Rolled back to 2.3.9"
```

Les deux commandes suivent la politique d’utilisation des outils et nécessitent l’autorisation `alerts.incidents.acknowledge`.

## Consulter les astreintes en cours

```bash
molesignal oncall
```

La liste indique qui est d’astreinte pour chaque planning d’astreinte activé. `--schedule` limite la liste à un seul planning,
et `--at` permet de consulter les astreintes à un autre moment, par exemple avec `--at "2026-10-27 09:00"`.

## Appliquer les modifications approuvées

`molesignal approvals` affiche les demandes d’approbation de Mole Agent, des outils d’agent et des commandes qui sont en attente d’examen ou dont la modification a été approuvée mais
n’a pas encore été appliquée. `--all` affiche également toutes les demandes qui ont fait l’objet d’une
décision.

```bash
molesignal approvals
```

`molesignal approvals show <approval>` affiche une demande : son action, sa cible, son motif, son impact et
les avis émis. `molesignal approvals execute <approval>` applique une modification approuvée. MoleSignal peut
d’abord demander une confirmation :

```bash
molesignal approvals execute <approval>
```

## Annoter les tableaux de bord

`molesignal annotate` ajoute une annotation à un instant précis ou sur une période, sur tous les tableaux de bord
ou sur un seul :

```bash
molesignal annotate "Release 2.4.0" --tags release,checkout --yes
```

| Option | Signification |
|---|---|
| `--description <text>` | Description de l’annotation. |
| `--tags <a,b>` | Tags pour retrouver l’annotation. |
| `--dashboard <id>` | Limite l’annotation à ce tableau de bord. |
| `--stream <stream>` | Flux concerné par l’annotation. |
| `--time <time>`, `--end <time>` | Début et fin de la période. Par défaut, l’annotation s’applique à l’instant présent. |

L’ajout d’une annotation nécessite l’autorisation `dashboards.edit`.

## Exécuter des tests synthétiques

`molesignal synthetics` liste les tests avec leur type, leur état et leur cycle de vie.
`molesignal synthetics results <check>` affiche les dernières exécutions d’un test pour chaque emplacement, avec leur
résultat, leur durée et le motif des éventuels échecs. Indiquez l’identifiant ou le nom du test.

`molesignal synthetics run` lance immédiatement un test depuis chacun de ses emplacements. Avec `--wait`, la commande
attend les résultats et renvoie le code `1` si une exécution échoue ou ne se termine pas dans le délai `--timeout`
(10 minutes par défaut). Un pipeline peut ainsi interrompre un déploiement :

```bash
molesignal synthetics run "Checkout API" --wait --yes
```

Une exécution réussit si son résultat indique un fonctionnement normal ou intermittent. L’exécution d’un test nécessite l’autorisation `synthetics.monitors.manage`. Pour
lancer des tests depuis la CI sans examen préalable, réglez `run_synthetic_monitor` sur **Automatique** dans la politique d’utilisation
des outils.
