L’interface en ligne de commande s’authentifie une seule fois et conserve la connexion pour les commandes suivantes. Deux méthodes sont disponibles :

| Méthode | Cas d’usage |
|---|---|
| Connexion via le navigateur | Utilisation interactive sur un ordinateur équipé d’un navigateur. Utilise OAuth 2.1 et se renouvelle automatiquement. |
| Jeton d’API | Scripts, machines de build et ordinateurs sans navigateur. |

La connexion via le navigateur donne uniquement accès au point de terminaison MCP de MoleSignal. Le signalement des déploiements, l’envoi
de fichiers source map et de symboles, et l’envoi de logs passent par l’API de MoleSignal et nécessitent un jeton d’API.

## Connectez-vous via le navigateur

```bash
molesignal login --url https://molesignal.example.com
```

1. L’interface en ligne de commande s’enregistre auprès de MoleSignal et ouvre la page d’autorisation de MoleSignal dans le
   navigateur par défaut. Connectez-vous à MoleSignal sur cette page si aucune session n’est ouverte.
2. La page d’autorisation indique le client, le compte et l’organisation, et répertorie les actions autorisées par
   cet accès. Si le compte appartient à plusieurs organisations, sélectionnez-en une dans **Organisation**. L’accès
   reste limité à cette organisation.
3. Cliquez sur **Autoriser**. Le navigateur redirige vers l’interface en ligne de commande, qui indique le nombre d’outils
   disponibles.

L’interface en ligne de commande demande les portées `mcp` et `offline_access`. La connexion se renouvelle donc automatiquement jusqu’à
la révocation de l’accès. La page d’autorisation attend cinq minutes. Passé ce délai, la commande se termine sans modifier la
connexion précédente, le cas échéant. Un refus ou une interruption de la connexion laisse également la connexion précédente
intacte.

<Note>
  Le navigateur redirige vers un service local qui écoute sur `http://127.0.0.1` uniquement pendant l’exécution de la commande.
  Une fois la commande terminée, ce service cesse d’écouter sur la machine. Si la commande s’exécute sur une machine distante via SSH,
  le navigateur ne peut pas joindre ce service : connectez-vous sur cette machine avec un jeton d’API.
</Note>

## Connectez-vous avec un jeton d’API

Créez un jeton dans **Identité et accès → Jetons d’API**, puis transmettez-le sur l’entrée standard :

```bash
printf '%s' "$MOLESIGNAL_TOKEN" | molesignal login --url https://molesignal.example.com --with-token
```

Le jeton hérite des autorisations du compte utilisateur ou du compte de service auquel il appartient.

## Utilisez un jeton sans l’enregistrer

Définissez l’adresse et le jeton dans les variables d’environnement, par exemple sur une machine de build. Cette méthode n’enregistre rien :

```bash
MOLESIGNAL_URL=https://molesignal.example.com MOLESIGNAL_TOKEN=<token> molesignal status
```

Les options `--url` et `--token` produisent le même effet pour une seule commande. L’interface en ligne de commande n’envoie jamais à une autre adresse
un jeton enregistré pour une adresse donnée.

## Conservez plusieurs connexions

Chaque profil conserve une connexion : une adresse et les informations d’accès correspondantes. Utilisez plusieurs profils pour rester
connecté à plusieurs instances de MoleSignal ou à plusieurs organisations d’une même instance.
L’option `--profile` indique dans quel profil enregistrer la connexion :

```bash
molesignal login --url https://staging.molesignal.example.com --profile staging
```

Le profil de la dernière connexion devient le profil actif. Les commandes utilisent le profil actif.
Utilisez `--profile` ou `MOLESIGNAL_PROFILE` pour sélectionner un autre profil le temps d’une commande. Sans
`--profile`, la première connexion utilise le profil `default`.

| Commande | Effet |
|---|---|
| `molesignal profiles` | Répertorie les profils, leur méthode de connexion et leur adresse. `*` indique le profil actif. |
| `molesignal use <profile>` | Active le profil indiqué. |
| `molesignal logout --profile <profile>` | Supprime la connexion enregistrée pour le profil, mais conserve son adresse. |
| `molesignal profiles remove <profile>` | Supprime le profil. |

## Emplacement de stockage des connexions

L’interface en ligne de commande enregistre les profils dans `~/.config/molesignal/config.json`. Seul le propriétaire du fichier peut le lire.
Le dossier dépend de `XDG_CONFIG_HOME` si cette variable est définie, et de `%APPDATA%` sous Windows.
Utilisez `MOLESIGNAL_CONFIG` pour indiquer un autre fichier.

## Utilisez un proxy

`HTTPS_PROXY` (ou `HTTP_PROXY`) fait passer toutes les requêtes de l’interface en ligne de commande par un proxy, et `NO_PROXY`
répertorie les hôtes à joindre directement :

```bash
HTTPS_PROXY=http://proxy.example.com:3128 NO_PROXY=localhost molesignal status
```

Si le certificat de MoleSignal provient d’une autorité de certification privée, indiquez le certificat de cette autorité
dans `NODE_EXTRA_CA_CERTS`.

## Vérifiez la connexion et la configuration

`molesignal status` indique l’adresse, le profil, le serveur qui a répondu, la version du protocole
MCP, la méthode de connexion et le nombre d’outils MCP :

```bash
molesignal status
```

`molesignal whoami` indique le compte utilisateur, l’organisation, le rôle et les autorisations que MoleSignal
accorde :

```bash
molesignal whoami
```

`molesignal doctor` vérifie les éléments suivants et indique comment corriger les problèmes détectés :
Node.js, les droits d’accès au fichier de configuration, l’adresse, le proxy, le réseau et TLS,
l’horloge, la connexion et le point de terminaison MCP. La commande renvoie le code `1` si une vérification échoue :

```bash
molesignal doctor
```

## Déconnectez-vous

`molesignal logout` supprime la connexion enregistrée pour le profil actif sur cette machine :

```bash
molesignal logout
```

L’autorisation reste active dans MoleSignal. Pour la révoquer, accédez à
**Mole Agent → Paramètres → MCP entrant**.
