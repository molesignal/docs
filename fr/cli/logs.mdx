## Lister les flux

```bash
molesignal streams
```

La liste affiche chaque flux de journaux accessible en lecture, avec son nombre de champs, sa durée de rétention et
sa description. `--type` liste les flux d’un autre type : `metrics`, `traces`, `profiles` ou
`extend`. `--names` affiche uniquement les noms et `--json` affiche un flux par ligne au format JSON.

## Afficher les journaux les plus récents

```bash
molesignal logs app_logs
```

La commande affiche les 100 entrées de journal les plus récentes des 15 dernières minutes, de la plus ancienne à la plus récente, à raison d’une par ligne :
l’heure, le niveau, le service et le message.

```text
2026-10-18 03:14:15.361 INFO  checkout order 4812 created
2026-10-18 03:14:25.361 ERROR payment gateway timeout after 3 retries
```

La commande lit le niveau dans un champ tel que `level`, `severity` ou `severity_text`, le service dans
`service` ou `service.name`, et le message dans `message`, `msg`, `body` ou `log`. Pour une entrée
sans champ de message, la commande affiche les autres champs sous la forme `name=value`. Les couleurs s’affichent dans un terminal ;
`NO_COLOR` les désactive et `FORCE_COLOR` les conserve lors d’une redirection par pipe.

| Option | Valeur par défaut | Description |
|---|---|---|
| `-n`, `--lines <count>` | `100` | Nombre d’entrées récentes à afficher au départ, au maximum `5000`. |
| `--since <duration>` | `15m` | Durée à remonter dans le temps : `30s`, `10m`, `2h`, `1d`, `1w`. |
| `--from <time>`, `--to <time>` | aucune | Plage horaire à la place de `--since` : une date et une heure au format ISO, `2026-10-26 14:00` en heure locale ou une durée à remonter depuis l’instant présent, comme `2h`. |
| `-q`, `--query <query>` | aucune | Requête sur les champs, au même format que sur la page **Journaux**. |
| `--where <condition>` | aucune | Condition SQL sur les champs du flux. |
| `--fields <a,b,c>` | tous | Affiche l’heure et uniquement les champs indiqués, sous la forme `name=value`. |
| `--json` | désactivé | Affiche chaque entrée sur une ligne au format JSON. |
| `--utc` | désactivé | Affiche les heures en UTC plutôt qu’en heure locale. |
| `--web` | désactivé | Ouvre les mêmes entrées sur la page **Journaux** au lieu de les afficher dans le terminal. |

## Filtrer les journaux

`-q` accepte une requête sur les champs dans le langage de la page **Journaux** : combinez des expressions telles que
`level = 'error'`, `contains`, `MATCH` et `MATCH_TEXT` avec `AND` et `OR`, et regroupez-les
entre parenthèses. Sans champ précisé, la commande recherche le texte dans `message` :

```bash
molesignal logs app_logs --since 1h -q "level = 'error' AND (service = 'payment' OR timeout)"
```

`--where` accepte une condition SQL sur les champs du flux, comme dans la clause `WHERE` d’une requête :

```bash
molesignal logs app_logs --where "status >= 500 AND duration_ms > 2000"
```

Avec les deux options, chaque entrée doit satisfaire les deux conditions. Si une condition fait référence à un champ absent
ou contient du SQL non valide, la commande s’arrête et indique le motif.

## Suivre les nouvelles entrées de journal

```bash
molesignal logs app_logs -f
```

Après les entrées les plus récentes, la commande continue d’afficher les nouvelles entrées jusqu’à **Ctrl+C** :

- La commande relance la lecture toutes les 2 secondes. Modifiez cet intervalle avec `--interval`.
- Chaque lecture commence 10 secondes avant la fin de la précédente pour inclure les entrées qui parviennent à
  MoleSignal avec quelques secondes de retard. Chaque entrée ne s’affiche qu’une fois.
- Si une arrivée massive d’entrées dépasse la capacité d’une lecture, la commande enchaîne les lectures sans attendre.
- En cas de perte de connexion, la CLI tente de se reconnecter avec un délai croissant, jusqu’à 30 secondes. Elle signale la perte
  et le rétablissement de la connexion sur la sortie d’erreur standard.

Le suivi repose sur l’horodatage des entrées. Une entrée dont l’horodatage précède le début
de la lecture en cours ne s’affiche pas. N’utilisez pas `--to` avec `-f`.

## Consulter les journaux autour d’un instant précis

`--around` affiche les entrées juste avant et juste après l’instant indiqué, avec une ligne qui marque cet instant
entre les deux groupes. `-B` et `-A` fixent le nombre d’entrées de chaque côté : 10 par défaut et 250 au maximum. `-q` et `--where`
filtrent les résultats :

```bash
molesignal logs app_logs --around "2026-10-26 14:03:12.345" -B 20 -A 20
```

`--around` accepte un horodatage copié depuis la sortie de `molesignal logs`.

## Exécuter une requête SQL sur un flux

`molesignal query` exécute une seule instruction SQL en lecture seule, avec des expressions, des jointures et des agrégats,
puis affiche le résultat sous forme de tableau :

```bash
molesignal query "SELECT level, COUNT(*) AS logs FROM app_logs GROUP BY level ORDER BY logs DESC"
```

La commande utilise le premier flux qui suit `FROM`. `--stream` permet d’en indiquer un autre. Par défaut, la requête porte sur la dernière heure ;
`--since`, `--from` et `--to` modifient cette plage. `-n` fixe le nombre maximal de lignes, à `1000` par défaut et
à `5000` au plus. `--csv` affiche le résultat au format CSV avec une ligne d’en-tête, `--json` affiche une ligne par résultat au format JSON et
`--web` ouvre la requête sur la page **Journaux**.

## Consulter les champs d’un flux

```bash
molesignal fields app_logs
```

La liste affiche chaque champ avec son type et son index. Si un champ est indiqué, la commande liste ses valeurs les plus
fréquentes sur la dernière heure, avec le nombre d’occurrences de chacune :

```bash
molesignal fields app_logs service --since 1d
```

`--match` conserve les valeurs qui contiennent le texte indiqué et `-n` fixe le nombre de valeurs, à `20` par défaut.
`--type` permet de lire un flux d’un autre type.

## Transmettre la sortie à une autre commande via un pipe

`--json` affiche chaque entrée avec tous ses champs :

```bash
molesignal logs app_logs -n 1000 --since 2h --json | jq -r .message
```

Si la commande qui lit la sortie, par exemple `head`, s’arrête avant la fin, la commande MoleSignal se termine sans afficher de message.

## Accès

La CLI lit les données à l’aide des outils MoleSignal `list_streams`, `query_logs`, `get_stream_schema`,
`search_field_values` et `search_around`, avec les autorisations du compte connecté ou du compte
propriétaire du jeton d’API. Le compte utilisé doit disposer de l’autorisation `streams.query`, et la politique d’utilisation des outils de l’organisation doit
autoriser ces outils.
