`molesignal <command> --help` affiche la même aide pour une commande donnée.

## Options communes à toutes les commandes

Toutes les commandes qui communiquent avec MoleSignal acceptent les options suivantes :

| Option | Description |
|---|---|
| `--profile <name>` | La connexion enregistrée à utiliser. Consultez [Gérer plusieurs connexions](/fr/cli/sign-in#conservez-plusieurs-connexions). |
| `--url <address>` | L’adresse de MoleSignal à utiliser à la place de celle du profil. |
| `--token <token>` | Un jeton d’API valable uniquement pour cette commande. |

Indiquez un horodatage au format ISO, une date et une heure locales comme `2026-10-26 14:00`, un nombre de
secondes, de millisecondes ou de microsecondes depuis l’époque Unix, ou une durée à remonter depuis l’instant présent. Une durée
se compose d’un nombre et d’une unité : `ms`, `s`, `m`, `h`, `d` ou `w`.

## Connexion

| Commande | Options | Description |
|---|---|---|
| `login` | `--url <address>`, `--profile <name>`, `--with-token` | Ouvre une session dans le navigateur ou avec un jeton d’API lu sur l’entrée standard. Le profil devient actif. |
| `logout` | `--profile <name>` | Supprime les données de connexion d’un profil, mais conserve son adresse. |
| `profiles` | `--json` | Répertorie les profils. `profiles remove <name>` supprime un profil. |
| `use <profile>` | aucune | Active un profil. |
| `status` | aucune | Affiche l’adresse, le profil, le serveur, la révision du protocole MCP, le mode de connexion et le nombre d’outils. |
| `whoami` | `--json` | Affiche le compte utilisateur, l’organisation, le rôle et les autorisations. |
| `doctor` | aucune | Vérifie Node.js, la configuration, l’adresse, le proxy, le réseau et TLS, l’horloge, la connexion et le point de terminaison MCP. |

## Journaux et requêtes

| Commande | Options | Description |
|---|---|---|
| `streams` | `--type <type>`, `--names`, `--json` | Répertorie les flux d’un type donné (`logs` par défaut). |
| `logs <stream>` | `-f`, `-n`, `-q`, `--where`, `--since`, `--from`, `--to`, `--fields`, `--around`, `-B`, `-A`, `--interval`, `--json`, `--utc`, `--web` | Affiche les entrées les plus récentes d’un flux ; `-f` affiche les nouvelles entrées à mesure qu’elles arrivent. Consultez [Lire et suivre les journaux](/fr/cli/logs). |
| `query "<SQL>"` | `--stream`, `--since`, `--from`, `--to`, `-n`, `--csv`, `--json`, `--utc`, `--web` | Exécute une instruction SQL en lecture seule sur un flux de journaux. |
| `fields <stream> [field]` | `--type`, `--since`, `--from`, `--to`, `-n`, `--match`, `--json` | Répertorie les champs d’un flux ou les valeurs les plus fréquentes d’un champ. |

### Options de `logs`

| Option | Valeur par défaut | Description |
|---|---|---|
| `-f`, `--follow` | désactivé | Affiche les nouvelles entrées jusqu’à l’appui sur **Ctrl+C**. |
| `-n`, `--lines <count>` | `100` | Nombre d’entrées récentes à afficher au départ, de `1` à `5000`. |
| `-q`, `--query <query>` | aucune | Requête sur les champs, dans le même format que sur la page **Journaux**. |
| `--where <condition>` | aucune | Condition SQL sur les champs du flux. |
| `--since <duration>` | `15m` | Durée à remonter depuis l’instant présent. |
| `--from <time>`, `--to <time>` | aucune | Plage horaire à utiliser à la place de `--since`. `--to` est incompatible avec `-f`. |
| `--fields <a,b,c>` | tous | Affiche l’horodatage et uniquement les champs indiqués. |
| `--around <time>` | aucune | Affiche les entrées juste avant et après un instant donné. |
| `-B`, `--before <count>` | `10` | Avec `--around` : nombre d’entrées à afficher avant cet instant, au maximum `250`. |
| `-A`, `--after <count>` | `10` | Avec `--around` : nombre d’entrées à afficher après cet instant, au maximum `250`. |
| `--interval <duration>` | `2s` | Intervalle entre deux lectures en mode suivi. |
| `--json` | désactivé | Affiche chaque entrée sur une ligne au format JSON. |
| `--utc` | désactivé | Affiche les horodatages en UTC. |
| `--web` | désactivé | Ouvre les journaux sur la page **Journaux** au lieu de les afficher dans le terminal. |

| `metrics names [text]`, `metrics labels <metric>`, `metrics values <metric> <label>`, `metrics series <metric>` | `-n`, `--match <label=value>`, `--json` | Répertorie les noms des métriques, les étiquettes, leurs valeurs et les séries. |

| `traces show <trace>` | `--since`, `--from`, `--to`, `--json`, `--web` | Affiche une trace sous forme de diagramme en cascade. |
| `services` | `--env`, `--namespace`, `--sort`, `--since`, `--from`, `--to`, `-n`, `--json` | Répertorie les services APM et leur état de santé. |
| `services show <service>` | `--env`, `--namespace`, `--since`, `--json`, `--web` | Affiche un récapitulatif du service. |
| `services compare <service> <baseline> <candidate>` | `--env`, `--since`, `--fail-on-regression`, `--json` | Compare deux versions. |
| `search-jobs` | `-n`, `--json` | Répertorie les tâches de recherche. |
| `search-jobs submit "<statement>"` | `--stream`, `--type`, `--promql`, `--step`, `--since`, `--from`, `--to`, `--limit`, `--keep`, `--wait`, options de modification | Soumet une tâche de recherche. |
| `search-jobs show <job>`, `search-jobs results <job>`, `search-jobs cancel <job>` | `-o <file>`, `--csv`, `--json`, options de modification | Affiche une tâche, écrit les lignes de résultat ou annule la tâche. |

## Astreinte et modifications

| Commande | Options | Description |
|---|---|---|
| `incidents` | `--status`, `--since`, `-n`, `--json` | Liste les incidents. Par défaut, seuls les incidents actifs s’affichent. |
| `incidents show <incident>` | `--rca`, `--json`, `--web` | Affiche un incident. |
| `incidents ack <incident>`, `incidents resolve <incident>` | options de modification | Accuse réception d’un incident ou le résout. |
| `incidents create --title <text>` | `--description`, `--severity`, `--priority`, `--urgency`, `--service`, `--label`, `--team`, `--policy`, `--user`, `--major`, `--json`, options de modification | Ouvre manuellement un incident pour un problème qu’aucune règle n’a détecté. Achemine l’incident comme une alerte, sauf si `--team`, `--policy` ou `--user` désigne, par identifiant, qui doit le prendre en charge. `--priority` et `--urgency` utilisent les niveaux de l’organisation. Affiche l’identifiant et le lien du nouvel incident. |
| `oncall` | `--schedule`, `--at`, `--json` | Indique qui est d’astreinte. |
| `approvals` | `--all`, `-n`, `--json` | Liste les demandes d’approbation en attente ou approuvées. |
| `approvals show <approval>`, `approvals execute <approval>` | `--json`, options de modification | Affiche une demande ou exécute une modification approuvée. |
| `annotate "<title>"` | `--description`, `--tags`, `--dashboard`, `--stream`, `--time`, `--end`, options de modification | Ajoute des annotations aux tableaux de bord. |
| `synthetics` | `--lifecycle`, `--json` | Liste les tests synthétiques. |
| `synthetics results <check>` | `--since`, `-n`, `--json` | Liste les dernières exécutions d’un test. |
| `synthetics run <check>` | options de modification | Lance un test immédiatement. Avec `--wait`, attend la fin des exécutions. |
| `alerts rules export` | `--ids`, `-o`, `--output` | Exporte les règles d’alerte dans un lot. `--ids` limite l’export aux règles indiquées. Consultez [Importation et exportation](/fr/alerting/rules#importer-et-exporter-des-règles). |
| `alerts rules apply -f <file>` | `--dry-run`, `--create-only`, `--json` | Applique un lot ou un fichier de règles d’alerte Prometheus (`-f -` lit l’entrée standard). Teste d’abord la configuration et affiche l’effet de chaque règle, puis enregistre toutes les règles en une seule opération si aucune n’échoue. Renvoie le code 1 si une règle échoue, pour l’intégration continue. |
| `alerts policies export`, `alerts schedules export`, `alerts routing export` | `--ids`, `-o`, `--output` | Exporte les politiques d’escalade, les plannings d’astreinte ou les règles de routage dans un lot. Le lot identifie les comptes utilisateur par leur adresse e-mail et les autres éléments par leur nom. Consultez [Importation et exportation](/fr/alerting/on-call#importation-et-exportation). |
| `alerts policies apply -f <file>`, `alerts schedules apply -f <file>`, `alerts routing apply -f <file>` | `--dry-run`, `--create-only`, `--json` | Applique un lot de la même façon que `alerts rules apply`. Appliquez les plannings avant les politiques qui les utilisent pour envoyer des notifications, puis les politiques avant les règles d’alerte et de routage qui les référencent. |

Voici les options de modification. Consultez [Déroulement d’une modification](/fr/cli/changes#comment-une-modification-s’exécute).

| Option | Signification |
|---|---|
| `--reason <text>` | Motif de la modification, conservé avec l’approbation et dans le journal d’audit. |
| `--wait` | Attend l’approbation si nécessaire, puis exécute la modification. |
| `--timeout <duration>` | Durée maximale d’attente de `--wait` : `30m` par défaut et `10m` pour `synthetics run`. |
| `-y`, `--yes` | Confirme immédiatement la modification lorsque MoleSignal demande une confirmation. |

## Variables d’environnement

| Variable | Signification |
|---|---|
| `MOLESIGNAL_URL` | Adresse de MoleSignal, à utiliser à la place de `--url` ou de l’adresse enregistrée. |
| `MOLESIGNAL_TOKEN` | Jeton d’API à utiliser à la place des identifiants enregistrés. |
| `MOLESIGNAL_PROFILE` | Profil à utiliser à la place du profil actif. |
| `MOLESIGNAL_CONFIG` | Fichier qui contient les profils. Par défaut : `~/.config/molesignal/config.json`. |
| `HTTPS_PROXY`, `HTTP_PROXY` | Proxy à utiliser pour toutes les requêtes. |
| `NO_PROXY` | Hôtes à joindre sans passer par le proxy. |
| `NODE_EXTRA_CA_CERTS` | Autorité de certification à approuver en plus de celles du système. |
| `NO_COLOR` | Désactive les couleurs dans la sortie. |
| `FORCE_COLOR` | Active les couleurs même si la sortie n’est pas dirigée vers un terminal. |

Les options priment sur les variables d’environnement, qui priment sur le profil enregistré.

## Codes de sortie

| Code | Signification |
|---|---|
| `0` | La commande a réussi ou le suivi en continu a pris fin. |
| `1` | La commande a échoué. Le motif figure sur la sortie d’erreur standard. Ce code signale aussi les cas suivants : une exécution de test synthétique a échoué avec `--wait`, une version a présenté une régression avec `--fail-on-regression`, `send` a rejeté des logs ou une vérification de `doctor` a échoué. |
| `2` | Commande, option ou argument inconnu. |
| `3` | La modification reste en attente d’approbation et n’a pas eu lieu. |

`deploy -- <command>` et `run` renvoient le code de sortie de la commande exécutée.
