| Point de terminaison | Authentification |
|---|---|
| `GET /api/v1/healthz` | Aucune |
| `GET /metrics` | Aucune |
| `GET /api/v1/readyz` | Jeton Bearer |
| `GET /api/v1/version` | Jeton Bearer |

## Vivacité

```http
GET /api/v1/healthz
```

Cette sonde de santé combine plusieurs vérifications. Elle renvoie `200` si le nœud est opérationnel et `503` avec un champ `reason` si le stockage objet est inaccessible. Utilisez-la pour les vérifications des conteneurs et des équilibreurs de charge.

<ResponseExample>
```json 200
{ "status": "ok" }
```
</ResponseExample>

## Disponibilité

```http
GET /api/v1/readyz
Authorization: Bearer <token>
```

Cette sonde vérifie si le nœud est prêt à recevoir du trafic. Elle renvoie `200` dès que le nœud a démarré, car le démarrage ne nécessite aucune relecture. Même si le stockage objet fonctionne en mode dégradé, le nœud reste prêt à traiter les requêtes en lecture seule. La requête exige un jeton Bearer. Sans ce jeton, la sonde reçoit `401`. Utilisez plutôt `/api/v1/healthz` si la sonde ne peut pas envoyer de jeton.

<ResponseExample>
```json 200
{ "status": "ready" }
```
</ResponseExample>

## Version

```http
GET /api/v1/version
Authorization: Bearer <token>
```

Renvoie la version du produit, le commit, la branche, la date et l’heure de compilation, l’identifiant de compilation, le canal de publication et l’édition.

<ResponseExample>
```json 200
{
  "version": "26.1.0.0",
  "commit": "<git-sha>",
  "branch": "main",
  "buildEpochSecs": 1790000000,
  "buildId": "<build-id>",
  "releaseChannel": "alpha",
  "edition": "oss"
}
```
</ResponseExample>

## Métriques

```http
GET /metrics
```

Expose les métriques du processus et des sous-systèmes au format Prometheus (`text/plain; version=0.0.4`), notamment les taux de réussite du cache `cache_*` et les métriques `wal_*`, `object_store_*` et `storage_reconciler_issues_total`. Restreignez l’accès à cette route au niveau du proxy ou de la couche réseau. Consultez [Auto-observabilité](/fr/self-observability).
