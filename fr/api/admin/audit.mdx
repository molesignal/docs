```http
GET /api/v1/audit
```

Renvoie les événements d’audit de l’organisation, du plus récent au plus ancien, avec une pagination par curseur. L’appel nécessite `audit.read`.

Chaque événement correspond aussi à une ligne du flux `_audit` de l’organisation. Un pipeline peut interroger ce flux et en acheminer les données vers une autre destination. Cette API lit les enregistrements de référence. Consultez [Flux d’audit](/fr/settings/data-security#flux-d’audit).

Le journal d’audit consigne les opérations sensibles du cycle de vie. Il ne consigne pas toutes les modifications. Dans la version actuelle, les noms d’action commencent par les préfixes suivants :

| Préfixe | Opérations |
|---|---|
| `agent.` | Fournisseurs de modèles, invites, outils et appels d’outils, serveurs MCP, approbations, conversations, investigations et exécutions de Mole Agent. |
| `iam.` | Attributions de rôles, relations et octrois d’autorisations entre organisations. |
| `resource_share.` | Création, rotation, révocation et ouverture de liens de partage, ainsi que tentatives avec un mot de passe incorrect. |
| `status_page.` | Pages de statut, composants, règles d’automatisation et logos. |
| `synthetic.` | Emplacements, agents et jetons d’agent de surveillance synthétique. |
| `schedule.` | Plannings d’astreinte et dérogations. |
| `trace_debug_token.` | Utilisation d’un jeton de débogage des traces. |
| `dashboard.` | Tableaux de bord créés à partir d’un brouillon généré par l’IA. |

Le journal ne consigne pas les modifications apportées aux flux, aux règles d’alerte, aux incidents ni aux connecteurs.

**Paramètres de requête**

| Paramètre | Type | Notes |
|---|---|---|
| `from`, `to` | chaîne | Fenêtre temporelle. Chaque valeur est exprimée en microsecondes depuis l’époque Unix ou sous forme relative : `now` ou `now-<N><unit>`, avec l’unité `s`, `m`, `h` ou `d`, par exemple `now-30m`. |
| `actorKind` | chaîne | Type d’entité à l’origine de l’action, par exemple `user`. |
| `actor` | chaîne | Identifiant de l’entité à l’origine de l’action. |
| `action` | chaîne | Nom exact de l’action, par exemple `agent.model_provider.created`. |
| `targetKind`, `targetId` | chaîne | Type et identifiant de la cible. |
| `limit` | entier | Taille de la page. Valeur par défaut : `50`. L’API borne la valeur entre 1 et 200. |
| `cursor` | chaîne | Valeur de `nextCursor` renvoyée sur la page précédente. Cette valeur est opaque. |

<RequestExample>
```bash cURL
curl "http://localhost:5080/api/v1/audit?from=now-7d&action=agent.model_provider.created&limit=20" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

**Réponse**

| Champ | Notes |
|---|---|
| `items[].actor_kind`, `items[].actor_id` | Entité à l’origine de la modification. |
| `items[].action` | Nom de l’action, par exemple `iam.role_binding.create`. |
| `items[].target_kind`, `items[].target_id` | Objet concerné. Les deux champs peuvent valoir `null`. |
| `items[].ip`, `items[].user_agent` | Adresse du client et agent utilisateur, si l’opération consigne ces valeurs. Les deux champs peuvent valoir `null`. |
| `items[].payload` | Détails de l’opération. Ces données excluent les secrets, le contenu des invites et les résultats des outils. |
| `items[].ts` | Horodatage de l’événement en microsecondes. |
| `nextCursor` | Curseur de la page suivante ou `null` sur la dernière page. |
| `retentionDays` | Durée de conservation des enregistrements d’audit, en jours, pour toutes les organisations et pour la plateforme. L’API supprime une fois par jour les enregistrements qui dépassent cette durée. La valeur `0` les conserve indéfiniment. |

**Erreurs**

| Statut | Cause |
|---|---|
| `400` | `from` ou `to` n’est ni un nombre ni une valeur relative valide (`unparseable time: yesterday`, `bad time unit in: now-3x`), ou `cursor` n’est pas valide. |
| `403` | Le jeton ne possède pas l’autorisation `audit.read`. |

## Routes d’audit associées

| Point de terminaison | Autorisation | Fonction |
|---|---|---|
| `GET /api/v1/system/audit` | `sys.telemetry.read`, dans le périmètre système | Exécute la même requête sur les événements d’audit de l’organisation système. Ces événements couvrent notamment l’activation ou la désactivation d’une organisation et la modification de la politique de traçage ou de la durée de conservation des enregistrements d’audit. |
| `GET /api/v1/settings/audit_retention` | `sys.settings.retention.manage`, dans le périmètre système | Renvoie la durée de conservation des enregistrements d’audit : `{ "retentionDays": 90 }`. |
| `PUT /api/v1/settings/audit_retention` | `sys.settings.retention.manage`, dans le périmètre système | Définit la durée de conservation des enregistrements d’audit avec le même corps de requête. `retentionDays` est un entier compris entre `0` (conservation indéfinie) et `3650`. Une valeur supérieure renvoie `400`. |
| `GET /api/v1/settings/audit_retention/preview?retentionDays=30` | `sys.settings.retention.manage`, dans le périmètre système | Indique combien d’enregistrements une durée de conservation plus courte supprimerait : `{ "retentionDays": 30, "previousRetentionDays": 90, "rows": 2400, "earliestAt": 1780000000000000 }`. L’API compte les enregistrements au lieu d’estimer leur nombre. Une durée plus longue ou la valeur `0` renvoie `"rows": 0`. |
| `GET /api/v1/agent/audit/chat/{id}` | `audit.read` | Renvoie la transcription intégrale d’une conversation avec Mole Agent : l’enregistrement `chat` et ses `messages`, avec les empreintes des invites, le nombre de jetons et les éléments de preuve. Renvoie `404` si la conversation est inconnue. |

<Warning>
  La transcription d’une conversation contient les questions du personnel utilisateur et les réponses du modèle. Accordez `audit.read` uniquement aux comptes autorisés à consulter ce contenu.
</Warning>
