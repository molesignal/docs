```http
GET  /api/v1/query/stream
POST /api/v1/query/stream
```

Le point de terminaison renvoie toujours du NDJSON par fragments (`application/x-ndjson`). Chaque ligne contient un objet JSON dont les clés sont les noms des colonnes. La dernière ligne est `{"__meta__":{"scannedRows":...,"tookMs":...}}`. Le point de terminaison ne transforme jamais une requête en tâche asynchrone. L’appel nécessite `streams.query` ou, dans la portée système, `sys.telemetry.read`.

La variante `POST` accepte le même corps que [Exécuter une requête](/fr/api/query/execute). La variante `GET` accepte les paramètres de requête suivants :

| Paramètre | Obligatoire | Remarques |
|---|---|---|
| `sql` | Oui | L’instruction SQL. Si la valeur manque, le point de terminaison renvoie `400`. |
| `stream` | Oui | Nom du flux principal. |
| `streamType` | Non | `logs`, `metrics`, `traces`, `profiles` ou `extend`. Valeur par défaut : `logs`. |
| `from`, `to` | Oui | Plage temporelle en microsecondes. |
| `limit` | Non | Nombre maximal de lignes. |

<RequestExample>
```bash cURL
NOW=$(date +%s)000000

curl -G http://localhost:5080/api/v1/query/stream \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode "sql=SELECT level, msg FROM app ORDER BY _timestamp DESC" \
  --data-urlencode "stream=app" \
  --data-urlencode "streamType=logs" \
  --data-urlencode "from=$((NOW-3600000000))" \
  --data-urlencode "to=$((NOW+60000000))" \
  --data-urlencode "limit=3"
```
</RequestExample>

<ResponseExample>
```text 200
{"level":"info","msg":"fine"}
{"level":"error","msg":"db pool exhausted"}
{"__meta__":{"scannedRows":5,"tookMs":173}}
```
</ResponseExample>

Désactivez la mise en mémoire tampon des réponses sur le proxy (`proxy_buffering off`) pour recevoir les lignes à mesure que le serveur les produit, et autorisez les lectures de longue durée. Arrêtez la lecture pour annuler le flux.
