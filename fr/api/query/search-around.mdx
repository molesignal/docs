```http
POST /api/v1/query/search_around
```

Renvoie les événements qui précèdent et suivent immédiatement un événement, dans une fenêtre de 24 heures de chaque côté. Le nombre d’événements de chaque côté est de 50 par défaut et doit être compris entre 1 et 1000. L’appel nécessite `streams.query`, ou `sys.telemetry.read` pour la télémétrie système.

`before` contient les événements dont l’horodatage est antérieur ou égal à celui du pointeur, du plus récent au plus ancien. Si l’événement de référence est stocké, il figure donc en première ligne. `after` contient les événements dont l’horodatage est postérieur à celui du pointeur, du plus ancien au plus récent. Si le flux n’existe pas, l’appel renvoie des champs `before` et `after` vides au lieu d’une erreur.

**Corps**

| Champ | Type | Obligatoire | Valeur par défaut |
|---|---|---|---|
| `eventTimestampUs` | entier | Oui | |
| `stream` | chaîne | Oui | |
| `streamType` | chaîne | Oui | |
| `eventFingerprint` | chaîne | Non | Le serveur renvoie la valeur telle quelle dans `pointer` sans l’utiliser pour sélectionner les événements. |
| `before` | entier | Non | 50 |
| `after` | entier | Non | 50 |

<ResponseExample>
```json 200
{
  "pointer": { "ts": 1790000000000000, "fingerprint": null },
  "before": {
    "columns": ["_timestamp", "msg"],
    "rows": [[1789999999500000, "..."]],
    "scannedRows": 100,
    "tookMs": 4
  },
  "after": {
    "columns": ["_timestamp", "msg"],
    "rows": [[1790000000500000, "..."]],
    "scannedRows": 100,
    "tookMs": 4
  }
}
```
</ResponseExample>
