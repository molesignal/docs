```http
GET    /api/v1/changes
POST   /api/v1/changes
GET    /api/v1/changes/{id}
PUT    /api/v1/changes/{id}
PATCH  /api/v1/changes/{id}
DELETE /api/v1/changes/{id}
```

Les changements sont consignés au même endroit : les déploiements, les modifications de configuration, les feature flags, la mise à l'échelle et
les changements d'infrastructure que les pipelines signalent via
[`POST /api/v1/apm/deployments`](/fr/apm/deployments#signaler-des-déploiements-depuis-la-ci), ainsi que les annotations
placées sur une plage de temps. `GET /api/v1/changes` les liste avec les versions qu'APM a vues en premier dans les spans
et les modifications de règles d'alerte. Les autres appels portent sur les annotations.

## Lister les changements

| Paramètre | Remarques |
|---|---|
| `from`, `to` | La plage en microsecondes. `to` vaut par défaut l'instant présent, `from` un jour avant `to`. |
| `services` | Noms de services, séparés par des virgules. Les changements des autres services sont exclus ; les changements sans service, comme les annotations et les modifications de règles, restent. |
| `namespace`, `environment` | Les changements signalés et les versions de ce namespace ou de cet environnement, ainsi que les changements signalés qui n'en désignaient aucun. |
| `kinds` | Séparés par des virgules : `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure`, `annotation`, `version`, `rule`. Tous les types que l'appelant est autorisé à lire lorsque le paramètre est omis. |
| `dashboardId`, `stream` | Les annotations de ce tableau de bord ou de ce flux de logs, et les annotations sans tableau de bord ni flux. Les annotations d'un autre tableau de bord ou d'un autre flux sont exclues. |
| `limit` | 500 au maximum, la valeur par défaut. |

Chaque type exige sa propre permission, et un type dont l'appelant ne dispose pas est exclu plutôt que refusé :

| Types | Permission, l'une des suivantes |
|---|---|
| `deployment`, `configuration`, `feature_flag`, `scaling`, `infrastructure` | `apm.deployments.read`, `sys.telemetry.read` |
| `annotation` | `dashboards.annotations.read` |
| `version` | `apm.services.read`, `sys.telemetry.read` |
| `rule` | `alerts.rules.read` |

La réponse est une liste, de l'élément le plus récent au plus ancien. Une version signalée par un pipeline n'y figure qu'une fois, telle que signalée.

```json
[
  {
    "id": "3KEDNEyqouYJeBDTLTMTBui7XHW",
    "kind": "deployment",
    "at": 1792316400000000,
    "service": "checkout",
    "namespace": "shop",
    "environment": "prod",
    "version": "2.0.0",
    "status": "succeeded",
    "commit": "9f2c1e7a4b3d5e6f",
    "author": "ada",
    "ciUrl": "https://ci.example.com/runs/7"
  },
  {
    "id": "3KEDP0aZ1y2b3c4d5e6f7g8h9i0",
    "kind": "annotation",
    "at": 1792312800000000,
    "end": 1792314600000000,
    "title": "Load test",
    "tags": ["test"],
    "dashboardId": "dash-1"
  }
]
```

| Champ | Remarques |
|---|---|
| `at`, `end` | Le moment où le changement a eu lieu ; `end` ferme une annotation sur une plage. Microsecondes. |
| `service`, `namespace`, `environment`, `version` | Ce à quoi correspondaient un changement signalé ou une version. |
| `status` | Le déroulement d'un changement signalé : `succeeded`, `failed` ou `rolled_back`. |
| `title`, `description`, `tags` | Le titre d'une annotation ou d'une règle, et ce qu'un changement indiquait de lui-même. |
| `commit`, `repositoryUrl`, `pullRequestUrl`, `author`, `ciUrl` | L'origine d'un changement signalé. |
| `dashboardId`, `stream` | Le tableau de bord ou le flux de logs auquel une annotation appartient. |
| `ruleId` | La règle à laquelle une modification s'appliquait. |

## Gérer les annotations

`POST /api/v1/changes` crée une annotation et nécessite `dashboards.annotations.manage` :

```json
{
  "title": "Load test",
  "description": "k6, 2,000 users",
  "tags": ["test"],
  "timeStart": 1792312800000000,
  "timeEnd": 1792314600000000,
  "dashboardId": "dash-1",
  "streamName": null
}
```

`GET /api/v1/changes/{id}` lit une annotation avec `dashboards.annotations.read`. `PUT` et `PATCH`
modifient les champs qu'ils nomment, et `DELETE` la supprime, avec `dashboards.annotations.manage`. Ces appels
ne concernent que les annotations ; un id qui n'est pas celui d'une annotation de l'organisation renvoie `404`.
Mole Agent gère les annotations avec `create_annotation`, `update_annotation` et `delete_annotation`, et
liste les changements avec `list_changes`.
