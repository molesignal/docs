Pointez un SDK ou un Collector OpenTelemetry vers MoleSignal. Les deux transports exigent un identifiant bearer disposant de la permission d'écriture du signal : `logs.write`, `metrics.write` ou `traces.write`.

| Transport | Point de terminaison |
|---|---|
| OTLP sur HTTP | `POST /api/v1/logs`, `POST /api/v1/metrics`, `POST /api/v1/traces` |
| OTLP sur gRPC | `:4317` |

Le port `5082` est le port interne de confiance du cluster et n'est pas un récepteur OTLP.

## OTLP sur HTTP

Définissez le point de terminaison de l'exporteur sur le chemin de base `/api`. Les exporteurs ajoutent eux-mêmes `/v1/logs`, `/v1/metrics` et `/v1/traces`.

| En-tête | Remarques |
|---|---|
| `Authorization` | `Bearer <token>`. |
| `Content-Type` | `application/x-protobuf` ou `application/json`. L'encodage JSON écrit les entiers 64 bits sous forme de chaînes, et MoleSignal lit aussi bien les chaînes que les nombres. |
| `stream-name` | Facultatif. Le flux cible. La valeur par défaut est `default`. |

Le corps ne doit pas être compressé : un corps compressé renvoie `400`. Désactivez la compression dans l'exporteur. La limite du corps est de 2 MiB. Une requête réussie renvoie `200` avec `{"partialSuccess":null}`. Lorsque le flux refuse certains enregistrements de logs ou points de données parce qu'une valeur ne correspond pas au type de son champ, les autres sont écrits et `partialSuccess` contient `rejectedLogRecords` ou `rejectedDataPoints` avec un `errorMessage` qui indique la première raison. Les exporteurs ne les réessaient pas. La même réponse est renvoyée via gRPC.

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP sur gRPC

Le récepteur sur `:4317` sert les services logs, metrics, traces et profiles sans TLS. Envoyez `authorization: Bearer <token>` et le paramètre facultatif `stream-name` en tant que métadonnées gRPC. Terminez TLS devant le port pour le trafic qui quitte un réseau de confiance.

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## Champs stockés

Les attributs de ressource et d'enregistrement deviennent des champs de premier niveau avec leurs clés d'origine. Consultez [Champs stockés](/fr/query#champs-stockés) pour les colonnes des logs, des spans et des métriques.

## Erreurs

| Statut | Cause |
|---|---|
| `400` | Un corps compressé, ou un corps qui n'est pas un OTLP valide. |
| `401` | Jeton manquant ou invalide. |
| `403` | Le jeton ne dispose pas de la permission d'écriture du signal, ou les données sont envoyées vers un [flux de plateforme](/fr/streams#flux-de-plateforme). |
| `404` | Le point de terminaison de l'exporteur omet `/api`, la requête atteint donc `/v1/logs`. |
| `413` | Le corps dépasse 2 MiB. |

Via gRPC, une requête que HTTP refuse avec `403` renvoie `PERMISSION_DENIED`.
