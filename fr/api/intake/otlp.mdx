Configurez un SDK ou un Collector OpenTelemetry pour envoyer les données à MoleSignal. Les deux transports exigent un jeton Bearer doté de l’autorisation d’écriture correspondant au signal : `logs.write`, `metrics.write` ou `traces.write`.

| Transport | Point de terminaison |
|---|---|
| OTLP sur HTTP | `POST /api/v1/logs`, `POST /api/v1/metrics`, `POST /api/v1/traces` |
| OTLP sur gRPC | `:4317` |

Le port `5082` est réservé aux communications internes de confiance du cluster. Il ne reçoit pas de trafic OTLP.

## OTLP sur HTTP

Définissez le point de terminaison de l’exportateur avec le chemin de base `/api`. Les exportateurs ajoutent automatiquement `/v1/logs`, `/v1/metrics` et `/v1/traces`.

| En-tête | Remarques |
|---|---|
| `Authorization` | `Bearer <token>`. |
| `Content-Type` | `application/x-protobuf` ou `application/json`. L’encodage JSON représente les entiers 64 bits sous forme de chaînes. MoleSignal accepte aussi bien les chaînes que les nombres. |
| `stream-name` | Facultatif. Indique le flux cible. La valeur par défaut est `default`. |

N’envoyez pas de corps compressé : MoleSignal renvoie `400` si le corps est compressé. Désactivez la compression dans l’exportateur. La taille maximale du corps est de 2 MiB. Si la requête aboutit, MoleSignal renvoie `200` avec `{"partialSuccess":null}`.

<RequestExample>
```yaml OpenTelemetry Collector
exporters:
  otlphttp/molesignal:
    endpoint: http://localhost:5080/api
    compression: none
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

```bash SDK environment variables
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer ${MS_TOKEN}"
```
</RequestExample>

## OTLP sur gRPC

Le récepteur sur `:4317` expose les services de journaux, de métriques, de traces et de profils sans TLS. Envoyez `authorization: Bearer <token>` et, éventuellement, `stream-name` dans les métadonnées gRPC. Pour le trafic qui sort d’un réseau de confiance, configurez la terminaison TLS en amont de ce port.

```yaml
exporters:
  otlp/molesignal:
    endpoint: localhost:4317
    tls:
      insecure: true
    headers:
      authorization: "Bearer ${env:MS_TOKEN}"
```

## Champs stockés

Les attributs des ressources et des enregistrements deviennent des champs de premier niveau et conservent leurs clés d’origine. Consultez la section [Champs stockés](/fr/query#champs-stockés) pour connaître les colonnes des journaux, des spans et des métriques.

## Erreurs

| Code d’état | Cause |
|---|---|
| `400` | Le corps est compressé ou ne contient pas de données OTLP valides. |
| `401` | Le jeton est manquant ou non valide. |
| `403` | Le jeton ne dispose pas de l’autorisation d’écriture correspondant au signal, ou les données sont destinées à un [flux de la plateforme](/fr/streams#flux-de-la-plateforme). |
| `404` | Le point de terminaison de l’exportateur ne contient pas `/api`, de sorte que la requête arrive sur `/v1/logs`. |
| `413` | La taille du corps dépasse 2 MiB. |

Pour une requête que HTTP refuse avec `403`, gRPC renvoie `PERMISSION_DENIED`.
