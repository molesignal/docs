```http
POST /api/v1/_cloudflare
```

Le point de terminaison accepte le NDJSON, y compris les corps de requête compressés avec gzip que Cloudflare Logpush envoie généralement. Il n’utilise pas de jeton Bearer. Créez un connecteur de type `cloudflare_logpush` avec un `pushToken` d’au moins 16 caractères et un `target_stream`, puis envoyez le jeton dans l’en-tête `X-Connector-Token`. Le paramètre de requête `?token=` fonctionne aussi. Si le jeton est incorrect, le point de terminaison renvoie `401`.

Chaque ligne devient un événement de journal dans le flux `target_stream` (par défaut, `cloudflare`). Le point de terminaison conserve les champs de la ligne tels quels et utilise l’heure de réception comme horodatage de l’événement. En cas de succès, il renvoie `204`.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/_cloudflare \
  -H 'X-Connector-Token: <pushToken>' \
  -H 'content-encoding: gzip' \
  --data-binary @logs.ndjson.gz
```
</RequestExample>

Consultez la page [Connecteurs](/fr/connectors) pour configurer le connecteur.

## Vérifier la livraison et la sélection du flux

1. Vérifiez que le connecteur est activé et que l’émetteur utilise le jeton d’envoi du connecteur. Un jeton d’API standard ne remplace pas un jeton d’envoi.
2. Si vous définissez directement `configJson` via l’API des connecteurs, utilisez `target_stream` comme clé du flux de destination, et non `targetStream`. La clé du jeton reste en camelCase : `pushToken`.
3. Envoyez un événement de test avec un marqueur unique et notez l’heure de réception. Dans **Journaux**, sélectionnez le flux attendu et une plage horaire qui inclut l’heure de réception, puis recherchez le marqueur.
4. Si la requête aboutit mais que le flux attendu est vide, vérifiez le flux par défaut correspondant et la valeur enregistrée dans le champ de destination. Une réponse HTTP positive ne dispense pas de vérifier le flux de destination par une requête.

Protégez le jeton comme un secret d’authentification. Si vous le transmettez dans un paramètre de requête de l’URL, ne consignez pas l’URL complète dans les journaux, les tickets ou les captures d’écran. Avant de réessayer une requête qui a échoué, déterminez si le problème vient du jeton ou de l’état du connecteur, plutôt que du format ou de la compression des données.
