```http
POST /api/v1/loki/api/v1/push
```

Le point de terminaison accepte le format JSON d’envoi de Loki. L’appel nécessite l’autorisation `logs.write` et renvoie `204` en cas de succès. La requête peut contenir un corps avec l’en-tête `Content-Encoding: gzip`.

Le point de terminaison décode uniquement le JSON. Les clients qui utilisent protobuf avec la compression snappy, comme Promtail et Grafana Alloy, ne peuvent pas y envoyer de données. Utilisez plutôt OpenTelemetry Collector, Vector ou Fluent Bit.

<RequestExample>
```bash cURL
LOKI_TIMESTAMP="$(date +%s)000000000"
curl -X POST http://localhost:5080/api/v1/loki/api/v1/push \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -H 'stream-name: app' \
  -d '{"streams":[{"stream":{"service":"api"},"values":[["'"$LOKI_TIMESTAMP"'","started"]]}]}'
```
</RequestExample>

Chaque valeur devient un événement de journal. Les étiquettes deviennent des champs, la ligne devient le champ `message` et le point de terminaison convertit l’horodatage de nanosecondes en microsecondes. L’en-tête `stream-name` sélectionne le flux de destination. Par défaut, le flux est `default`.

## Vérifier l’exemple

L’exemple génère un horodatage actuel en nanosecondes dans un shell macOS ou Linux. Après avoir reçu `204`, ouvrez **Journaux**, sélectionnez `app` et la dernière heure, puis recherchez le champ `message` correspondant à `service = 'api'`. En cas d’utilisation d’un horodatage antérieur, sélectionnez une plage qui couvre l’heure de l’événement et vérifiez que celle-ci se situe dans la période de rétention.

Distinguez trois éléments : `streams` est la structure du lot Loki, l’étiquette `service` devient un champ de l’événement et l’en-tête `stream-name` sélectionne le flux de destination dans MoleSignal. Vérifiez le flux et la plage horaire à l’aide d’une requête avant de renvoyer un lot.
