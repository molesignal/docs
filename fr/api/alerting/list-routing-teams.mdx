```http
GET /api/v1/alerts/routing/teams
```

Répertorie les équipes de l’organisation par nom (sans tenir compte de la casse), avec leur [politique d’astreinte](/fr/alerting/routing#politiques-d’astreinte-des-équipes) et les services dont elles sont responsables dans le catalogue de services APM. Nécessite l’autorisation `alerts.routing.read`.

<RequestExample>
```bash cURL
curl http://localhost:5080/api/v1/alerts/routing/teams \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "teamId": "<team-id>",
    "name": "Payments",
    "memberCount": 4,
    "escalationPolicyId": "<policy-id>",
    "services": ["default/checkout", "default/cart"]
  }
]
```
</ResponseExample>

| Champ | Description |
|---|---|
| `teamId`, `name` | Identifiant et nom de l’équipe. |
| `memberCount` | Nombre de membres de l’équipe. |
| `escalationPolicyId` | Identifiant de la politique d’astreinte de l’équipe. Si aucune politique n’est configurée, la valeur est `null` et les incidents acheminés vers l’équipe suivent la politique par défaut. |
| `services` | Services non archivés associés à l’équipe dans le catalogue de services, au format `namespace/name`. |
