Une demande d’échange d’astreinte invite un autre membre du planning à assurer une période d’astreinte à la place du demandeur. Dès que la personne sollicitée accepte,
une [dérogation](/fr/alerting/on-call#couverture-temporaire) s’ajoute au planning et l’échange prend effet. Si l’option
**Les échanges nécessitent une approbation** (`swapNeedsApproval`) est activée, une personne autorisée à gérer le planning doit
aussi approuver l’échange. Un échange encore en attente à la fin de la période expire. À chaque étape, la politique intégrée
[Échange d’astreinte : notifier les personnes concernées](/fr/notification-channels#politiques-intégrées)
notifie les personnes concernées, et le journal d’audit consigne l’étape.

| Méthode et chemin | Description | Autorisation |
|---|---|---|
| `GET /api/v1/schedules/swaps` | Renvoie les échanges demandés ou reçus par l’utilisateur actuel, tous plannings confondus. | `schedules.read` |
| `GET /api/v1/schedules/{id}/swaps` | Renvoie les échanges d’un planning, du plus récent au plus ancien. | `schedules.read` sur le planning |
| `POST /api/v1/schedules/{id}/swaps` | Demande un échange. | `schedules.swaps.request` sur le planning |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/accept` | Accepte l’échange. Seule la personne sollicitée peut l’accepter. | `schedules.swaps.request` sur le planning |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/decline` | Refuse l’échange. Seule la personne sollicitée peut le refuser. | `schedules.swaps.request` sur le planning |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/cancel` | Retire la demande. Seul le demandeur peut la retirer, tant que l’échange reste en attente. | `schedules.swaps.request` sur le planning |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/approve` | Approuve un échange accepté. La dérogation prend effet immédiatement. | `schedules.swaps.approve` sur le planning |
| `POST /api/v1/schedules/{id}/swaps/{swapId}/reject` | Rejette un échange accepté. | `schedules.swaps.approve` sur le planning |

## Demander un échange

**Corps de la requête**

| Champ | Type | Obligatoire | Notes |
|---|---|---|---|
| `targetId` | string | Oui | Personne qui reprend l’astreinte : un membre du planning autre que le demandeur. |
| `startAt`, `endAt` | integer | Oui | Bornes de la période à échanger, en microsecondes Unix. La période doit commencer dans le futur et se terminer après son début. |
| `note` | string | Non | Note de 500 caractères maximum. |

Le demandeur doit être la seule personne d’astreinte dans le planning pendant toute la période.
La période demandée ne doit pas chevaucher un échange en attente dans le même planning.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/$SCHEDULE_ID/swaps \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"targetId": "<user-id>", "startAt": 1790060400000000, "endAt": 1790146800000000, "note": "Travelling on Friday"}'
```
</RequestExample>

Chaque appel renvoie l’échange, sauf les appels de liste, qui renvoient `{ "swaps": [ ... ] }`.

<ResponseExample>
```json 200
{
  "id": "3KHq2nB7yZ0d4kVwXc1sPa9LmQe",
  "orgId": "<organization-id>",
  "scheduleId": "<schedule-id>",
  "scheduleName": "Payments primary",
  "requesterId": "<user-id>",
  "targetId": "<another-user-id>",
  "startAt": 1790060400000000,
  "endAt": 1790146800000000,
  "note": "Travelling on Friday",
  "status": "pending",
  "overrideId": null,
  "decidedBy": null,
  "decidedAt": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

| Champ | Notes |
|---|---|
| `status` | `pending` (en attente de réponse), `awaiting_approval` (accepté, en attente d’approbation), `accepted` (en vigueur), `declined` (refusé), `rejected` (rejeté par un gestionnaire), `cancelled` (retiré) ou `expired` (expiré). |
| `overrideId` | Dérogation ajoutée à la prise d’effet de l’échange. |
| `decidedBy`, `decidedAt` | Personne à l’origine de la dernière action (réponse, approbation, rejet ou retrait) et date de cette action. |

**Erreurs**

| Statut | Motif |
|---|---|
| `400` | La période est invalide, la personne sollicitée ne figure pas dans le planning, une autre personne que le demandeur est d’astreinte pendant la période ou la période chevauche un échange en attente. |
| `403` | Il manque une autorisation ou la personne à l’origine de l’appel ne peut pas effectuer cette action. |
| `404` | Le planning ou l’échange n’existe pas. |
| `409` | L’échange a dépassé cette étape (par exemple, il est déjà accepté ou a expiré) ou a changé entre-temps. Récupérez à nouveau l’échange, puis réessayez. |
