```http
GET /api/v1/alerts/importance
PUT /api/v1/alerts/importance
```

`GET` exige `alerts.importance.read` et `PUT` exige `alerts.importance.manage`. Les deux renvoient les niveaux de l’organisation :

```json
{
  "levels": {
    "priorities": [
      {"priority": "P1", "name": "Critical business impact", "description": "Customers cannot pay"},
      {"priority": "P2", "name": "", "description": ""},
      {"priority": "P3", "name": "", "description": ""}
    ],
    "urgencies": [
      {"key": "urgent", "name": "Urgent", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["critical"]},
      {"key": "high", "name": "", "escalates": true, "quietHours": "switch", "steps": "high", "severities": ["error"]},
      {"key": "low", "name": "", "escalates": false, "quietHours": "block", "steps": "low", "severities": ["warning", "info"]}
    ]
  },
  "updatedBy": "3KF1...",
  "updatedAt": 1793059200000000
}
```

Une organisation qui n’a jamais enregistré de niveaux reçoit les niveaux prédéfinis : `P1` à `P5`, ainsi que `high` et `low`, comme
indiqué dans [Urgence](/fr/alerting/on-call#urgence), avec `updatedBy` vide. `PUT` prend l’objet
`levels`, remplace les niveaux et enregistre l’événement d’audit `alert_importance.updated`.

| Champ | Description |
|---|---|
| `priorities` | De 1 à 9 niveaux, `P1`, `P2`, … sans saut. `name` accepte jusqu’à 32 caractères et `description` jusqu’à 200 ; si le nom est vide, la clé sert de nom. |
| `urgencies` | De 2 à 5 niveaux, du plus urgent au moins urgent. `key` commence par une lettre minuscule et contient uniquement des lettres minuscules, des chiffres et des tirets bas, avec un maximum de 32 caractères ; `high` et `low` doivent rester. `name` accepte jusqu’à 32 caractères ; si le nom est vide, le libellé prédéfini s’applique. |
| `escalates` | `true` envoie des alertes d’astreinte selon les étapes de la politique d’escalade ; `false` envoie une notification uniquement à la première étape. |
| `quietHours` | `switch` respecte le réglage individuel **Recevoir les alertes à forte urgence même pendant les heures silencieuses** ; `block` ne déclenche aucune alerte d’astreinte pendant les heures silencieuses. |
| `steps` | Groupe d’étapes utilisé par le niveau parmi les deux groupes associés à chaque personne : `high` ou `low`. |
| `severities` | Gravités associées au niveau lorsqu’une politique définit l’urgence en fonction de la gravité ; chacune des gravités `critical`, `error`, `warning` et `info` correspond à un seul niveau. |

Les niveaux déterminent les valeurs que les règles, les politiques d’escalade, les incidents et l’API peuvent utiliser : dans ces contextes, une priorité hors de la plage des
niveaux ou une urgence inconnue entraîne une erreur `400`. Si une alerte externe ou un pipeline d’alertes
indique une priorité hors plage, la priorité la plus basse s’applique. Si l’organisation ne reconnaît pas l’urgence,
le système ignore cette valeur. Les notifications utilisent `{{priority_name}}` et `{{urgency_name}}` pour les noms.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/importance \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d @levels.json
```
</RequestExample>

**Erreurs**

| Statut | Motif |
|---|---|
| `400` | Les niveaux ne respectent pas une règle du tableau ci-dessus. |
| `403` | Le jeton ne dispose pas de l’autorisation requise. |
| `422` | Un champ a un type incorrect ou une clé n’est pas valide. |
