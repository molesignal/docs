```http
GET /api/v1/alerts/discovery/findings
GET /api/v1/alerts/discovery/findings/{id}
```

Liste les problèmes détectés par la [détection automatique](/fr/alerting/discovery), du plus récemment observé au plus ancien, ou renvoie un seul
problème. Nécessite `alerts.discovery.read`.

**Paramètres de requête**

| Paramètre | Description |
|---|---|
| `status` | `open` (par défaut), `ended` ou `all`. |
| `kind` | `apm_anomaly`, `apm_regression`, `rum_new_issue` ou `rum_regressed_issue`. |
| `limit` | 100 par défaut, 500 au maximum. |

**Champs du problème détecté**

| Champ | Description |
|---|---|
| `kind` | Mêmes valeurs que pour le paramètre de requête. |
| `key` | Identifie le problème par son type, l’entité concernée et la métrique. |
| `severity` | `warning`, `error` ou `critical`. |
| `subject` | Un service APM (`namespace/name`) ou l’identifiant d’une application RUM. |
| `environment`, `metric` | L’environnement et la métrique qui a varié en APM : `errorRate`, `p95` (microsecondes) ou `throughput` (requêtes par seconde). |
| `title` | Une phrase. |
| `value`, `baseline` | La valeur actuelle et la valeur de référence. |
| `startedAt`, `lastSeenAt`, `endedAt` | Dates de début, de dernière observation et de fin (en microsecondes) ; sans `endedAt`, le problème reste ouvert. |
| `missedRounds` | Nombre de cycles consécutifs sans observation du problème. Le problème prend fin après 3 cycles. |
| `detail` | Un problème APM contient `previous`, `lastWeek`, `version`, `previousVersion` et les changements survenus autour de la détection (`changes`) ; un problème RUM contient `issueId`, `application`, `errorType`, `location` et `version`. |

Pour générer des incidents à partir des problèmes détectés, [créez une règle](/fr/api/alerting/create-rule) avec `query.discovery` :
`{"kinds": [...], "subjects": [...], "environments": [...], "minSeverity": "warning"}`. Omettez un filtre pour
ne pas restreindre les résultats sur ce critère. À l’enregistrement, la règle adopte un fonctionnement fixe : un incident par problème correspondant,
avec la même gravité que le problème et une urgence faible, sauf indication contraire dans `trigger.urgency`.
