Une application de calendrier (Google Calendar, Outlook, Apple Calendar, entre autres) consulte l’adresse d’abonnement. Cette adresse
fournit un flux iCalendar conforme à la RFC 5545 qui couvre les astreintes des 30 derniers jours et des 90 prochains jours, remplacements et échanges compris.
Un flux couvre soit toutes les astreintes d’un planning, soit les astreintes du compte abonné dans tous les plannings.

| Méthode et chemin | Fonction | Autorisation |
|---|---|---|
| `GET /api/v1/schedules/calendar-feeds` | Répertorie les flux du compte actuel. | `schedules.read` |
| `POST /api/v1/schedules/calendar-feeds` | Crée une adresse d’abonnement. Si le même planning ou le flux personnel dispose déjà d’une adresse, l’API la remplace et désactive immédiatement l’ancienne. | `schedules.calendar_feeds.manage` et, pour un flux de planning, `schedules.calendar_feeds.manage` sur le planning |
| `DELETE /api/v1/schedules/calendar-feeds/{id}` | Désactive un flux du compte actuel. Son adresse cesse immédiatement de fonctionner. | `schedules.calendar_feeds.manage` |
| `GET /api/v1/public/calendar/{token}.ics` | Fournit le flux à l’application de calendrier, sans authentification. | Le jeton dans l’adresse |

## Créer une adresse d’abonnement

**Corps de la requête**

| Champ | Type | Obligatoire | Remarques |
|---|---|---|---|
| `scheduleId` | chaîne | Non | Abonne le compte à ce planning. Omettez ce champ pour créer un flux personnel. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/schedules/calendar-feeds \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"scheduleId": "<schedule-id>"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "feed": {
    "id": "3KHtq0dYc1fUe8WnP2xLbR7aZsM",
    "scheduleId": "<schedule-id>",
    "scheduleName": "Payments primary",
    "createdAt": 1790000000000000,
    "lastUsedAt": null
  },
  "path": "/api/v1/public/calendar/<token>.ics",
  "url": "https://molesignal.example.com/api/v1/public/calendar/<token>.ics"
}
```
</ResponseExample>

L’API ne renvoie l’adresse qu’une seule fois, dans cette réponse, et ne stocke que le condensat SHA-256 du jeton. Elle construit `url` à partir de
l’adresse externe de l’instance. Si aucune adresse externe n’est configurée, `url` vaut `null`. Dans ce cas, ajoutez `path` à l’adresse
d’accès à MoleSignal. Chaque flux de la liste contient `id`, `scheduleId`, `scheduleName`, `createdAt` et
`lastUsedAt`, qui indique la dernière consultation par une application de calendrier, mais ne contient pas l’adresse d’abonnement.

## Comment l’application de calendrier consulte le flux

```http
GET /api/v1/public/calendar/{token}.ics
```

À chaque consultation, MoleSignal vérifie que le compte abonné est toujours actif, fait toujours partie de l’organisation et
dispose toujours de `schedules.read`. Pour un flux de planning, MoleSignal vérifie aussi que le compte a toujours accès au planning. Si une vérification échoue, si le jeton est incorrect
ou si le flux est désactivé, MoleSignal renvoie `404`. Les titres et les descriptions des astreintes s’affichent dans la langue de l’interface
du compte abonné.

L’adresse suffit pour consulter ces astreintes. Si elle a été divulguée, remplacez-la ou désactivez le flux.
