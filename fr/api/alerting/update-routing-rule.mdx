```http
PUT /api/v1/alerts/routing/rules/{id}
```

Remplace intégralement une [règle de routage](/fr/alerting/routing#règles-de-routage). Cette opération exige l’autorisation `alerts.routing.manage`. Les champs sont les mêmes que dans [Créer une règle de routage](/fr/api/alerting/create-routing-rule) ; tout champ facultatif omis reprend sa valeur par défaut. La règle conserve sa position. Pour la modifier, utilisez [Réordonner les règles de routage](/fr/api/alerting/reorder-routing-rules). Les incidents déjà ouverts restent inchangés.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Payments in production", "enabled": false, "target": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

La réponse contient la règle mise à jour.

**Erreurs**

| Statut | Cause |
|---|---|
| `400` | Un champ est incorrect, ou l’équipe ou la politique cible n’existe pas. |
| `403` | Le jeton ne dispose pas de l’autorisation `alerts.routing.manage`. |
| `404` | La règle n’existe pas ou appartient à une autre organisation. |
| `422` | Le champ `name` ou `target` manque, ou une valeur ne correspond à aucune valeur reconnue. La réponse est en texte brut. |
