```http
PUT /api/v1/alerts/rules/{id}
```

Remplace la configuration d’une règle. Le corps de la requête est identique au corps complet de [Créer une règle](/fr/api/alerting/create-rule). L’appel conserve l’`id` de la règle, son organisation, ainsi que `createdAt`, `lastEvalAt` et `lastState`. Si `escalationPolicyId` change, sa valeur doit désigner une politique d’escalade de l’organisation ou être `default`. L’appel nécessite l’autorisation `alerts.rules.manage`.

<Warning>
  L’appel remplace la règle sans fusionner les champs. Tout champ omis reprend sa valeur par défaut,
  notamment `enabled`, qui prend la valeur `true`, et `kind`, qui prend la valeur `scheduled`. Si la requête omet
  `labels`, `annotations` ou `thresholds`, ces champs deviennent vides. Seule l’omission de `escalationPolicyId`
  conserve la politique actuelle. Récupérez d’abord la règle, puis renvoyez le corps complet avec la modification.
</Warning>

L’empreinte d’un incident dépend de l’`id` et des `labels` de la règle. Après une modification de `labels`, un incident déjà ouvert conserve son ancienne empreinte et reste ouvert tant qu’une action ne le résout pas. Utilisez [Résoudre un incident](/fr/api/alerting/resolve-incident).

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/rules/$RULE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  --data-binary @- <<'EOF'
{
  "name": "High error rate",
  "description": "More than 200 errors in five minutes",
  "enabled": true,
  "kind": "scheduled",
  "query": {
    "language": "sql",
    "statement": "SELECT count(*) AS c FROM app WHERE level = 'error'",
    "periodSecs": 300,
    "stream": { "name": "app", "streamType": "logs" }
  },
  "trigger": { "operator": "gt", "threshold": 200, "forPeriods": 2, "silenceSecs": 0 },
  "severity": "critical",
  "labels": { "team": "checkout" }
}
EOF
```
</RequestExample>

La réponse contient la règle mise à jour, au format présenté dans [Lister les règles](/fr/api/alerting/list-rules).

**Erreurs**

| Statut | Cause |
|---|---|
| `400` | Le corps de la requête échoue aux mêmes contrôles que dans [Créer une règle](/fr/api/alerting/create-rule), ou la nouvelle valeur de `escalationPolicyId` ne désigne aucune politique d’escalade de l’organisation. |
| `404` | La règle n’existe pas. |
| `422` | Un champ obligatoire manque ou une valeur n’est pas du type attendu. La réponse est en texte brut. |
