Un connecteur stocke les identifiants et les paramètres de transport d’un fournisseur de notifications pour une organisation. Pour lister ou consulter les connecteurs, la clé d’autorisation `notify.connectors.read` est requise. Pour créer, mettre à jour, tester ou supprimer un connecteur, la clé d’autorisation `notify.connectors.manage` est requise.

| Opération | Point de terminaison |
|---|---|
| Lister les types de connecteurs | `GET /api/v1/notify/connector-types` |
| Lister les connecteurs | `GET /api/v1/notify/connectors` |
| Créer un connecteur | `POST /api/v1/notify/connectors` |
| Récupérer un connecteur | `GET /api/v1/notify/connectors/{id}` |
| Mettre à jour un connecteur | `PUT /api/v1/notify/connectors/{id}` |
| Tester un connecteur | `POST /api/v1/notify/connectors/{id}/test` |
| Supprimer un connecteur | `DELETE /api/v1/notify/connectors/{id}` |

## Types de connecteurs

La liste des types renvoie `connectorType`, `capabilities` et `addresses` pour chaque type que le backend en cours d’exécution enregistre. Les types disponibles sont `email_smtp`, `lark_app`, `lark_webhook`, `slackApp`, `slack_webhook` et `webhook`.

```json
[
  {
    "connectorType": "slack_app",
    "capabilities": {
      "directUser": true,
      "group": true,
      "richText": true,
      "interactive": true,
      "acknowledgement": false,
      "attachments": false
    },
    "addresses": [
      {
        "field": "apiBaseUrl",
        "picker": "site",
        "choices": [
          { "key": "slack", "url": "https://slack.com/api" },
          { "key": "govslack", "url": "https://slack-gov.com/api" }
        ]
      }
    ]
  }
]
```

`addresses` répertorie les adresses du fournisseur que le champ `config` du type stocke. Pour un type dont l’adresse se saisit manuellement, comme un webhook ou SMTP, `addresses` renvoie une liste vide.

| Champ | Signification |
|---|---|
| `field` | Clé de `config`, par exemple `apiBaseUrl`, `serviceUrl` ou `wsUrl`. |
| `choices` | Adresses possibles, chacune avec une `key` et une `url` ; la première est l’adresse par défaut. |
| `picker` | Critère de sélection parmi les adresses : `site` (plateforme) ou `cloud`. Le système n’enregistre pas le choix lui-même. |
| `byRegion` | L’adresse dépend de la région sélectionnée (Alibaba Cloud, AWS) : `https://{service}.{region}.{one of domains}`. `choices` contient uniquement l’adresse utilisée avant la sélection d’une région. |

Lors de la création, de la mise à jour ou du test d’un connecteur, ainsi que lors d’un envoi direct, ces clés acceptent uniquement une adresse de cette liste ou, pour une adresse régionale, celle de la région indiquée dans `config` ; si la clé est absente, le système utilise la valeur par défaut. Le système refuse toute autre adresse pour que les identifiants ne soient jamais transmis ailleurs.

L’objet `config` d’un connecteur dépend de son type. Chaque champ `timeoutSecs` vaut 10 par défaut et accepte les valeurs de 1 à 60. Utilisez des URL absolues en `http` ou `https` et choisissez l’adresse du fournisseur parmi celles répertoriées dans le champ `addresses` du type.

| `connectorType` | Clés de `config` |
|---|---|
| `email_smtp` | `host` et `from` (obligatoires), `port` (`587` par défaut), `username`, `password`, `tls` (`none`, `starttls` par défaut ou `tls`), `timeoutSecs` |
| `slackApp` | `botToken`, `clientId` et `clientSecret` (un jeton de bot, un identifiant client et un secret client, ou les trois), `apiBaseUrl` (`https://slack.com/api` par défaut ou `https://slack-gov.com/api` pour GovSlack), `timeoutSecs` |
| `slack_webhook` | `webhookUrl` (obligatoire), `timeoutSecs` |
| `lark_app` | `appId` et `appSecret` (obligatoires), `apiBaseUrl` (`https://open.feishu.cn/open-apis` pour Feishu par défaut ou `https://open.larksuite.com/open-apis` pour Lark), `receiveIdType` (`open_id` par défaut, `userId`, `union_id`, `email` ou `chatId`), `timeoutSecs` |
| `lark_webhook` | `webhookUrl` (obligatoire), `secret`, `timeoutSecs` |
| `webhook` | `url` (obligatoire), `method` (`post` par défaut, `put` ou `patch`), `headers`, `timeoutSecs` |

La page [Canaux de notification](/fr/notification-channels) présente chaque fournisseur et ses cibles.

## Créer un connecteur

```http
POST /api/v1/notify/connectors
```

| Champ | Type | Obligatoire | Remarques |
|---|---|---|---|
| `name` | chaîne | Oui | Unique au sein de l’organisation. |
| `connectorType` | chaîne | Oui | L’un des types ci-dessus. Le type ne peut plus changer après la création. |
| `config` | objet | Oui | Paramètres propres au type. |
| `enabled` | booléen | Non | `true` par défaut. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/notify/connectors \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "Operations webhook",
    "connectorType": "webhook",
    "config": {
      "url": "https://hooks.example.com/molesignal",
      "method": "post",
      "headers": { "Authorization": "Bearer <token>" },
      "timeoutSecs": 5
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "id": "3KEDlokKjNmves95sRzL8tXpflY",
  "organizationId": "<organization-id>",
  "name": "Operations webhook",
  "connectorType": "webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 5
  },
  "capabilities": {
    "directUser": true,
    "group": true,
    "richText": true,
    "interactive": false,
    "acknowledgement": false,
    "attachments": false
  },
  "enabled": true,
  "status": "unknown",
  "lastTestedAt": null,
  "lastTestStatus": null,
  "lastTestError": null,
  "createdAt": 1790000000000000,
  "updatedAt": 1790000000000000
}
```
</ResponseExample>

MoleSignal chiffre l’intégralité de `config` au repos. Les réponses remplacent par `***` la valeur de chaque clé qui contient des identifiants. Il s’agit des clés `url`, `webhookUrl` et `headers`, ainsi que de toutes les clés qui se terminent par `password`, `secret` ou `token`. Les autres clés, comme `host`, `from` et `timeoutSecs`, restent lisibles.

`status` vaut `unknown` jusqu’au premier test, puis `connected` ou `error`. `lastTestStatus` vaut `success` ou `failed`. Le routage ignore tout connecteur dont le statut est `error` jusqu’à ce qu’un test ultérieur réussisse.

## Lister et récupérer les connecteurs

```http
GET /api/v1/notify/connectors
GET /api/v1/notify/connectors/{id}
```

La liste renvoie un tableau de connecteurs au format ci-dessus. Si l’`id` est inconnu, la requête renvoie `404`.

## Mettre à jour un connecteur

```http
PUT /api/v1/notify/connectors/{id}
```

| Champ | Type | Obligatoire | Remarques |
|---|---|---|---|
| `name` | chaîne | Oui | Nouveau nom. |
| `config` | objet | Non | Nouveaux paramètres. Omettez ce champ pour conserver la configuration enregistrée. |
| `enabled` | booléen | Non | `true` par défaut. Si ce champ est absent, le connecteur s’active. |

Envoyez `***` pour une clé masquée afin de conserver le secret enregistré, ou envoyez une nouvelle valeur en clair pour le remplacer :

```json
{
  "name": "Operations webhook",
  "config": {
    "url": "***",
    "method": "post",
    "headers": "***",
    "timeoutSecs": 8
  },
  "enabled": true
}
```

## Tester un connecteur

```http
POST /api/v1/notify/connectors/{id}/test
```

Le test envoie un message via le connecteur. Pour lancer un test, activez le connecteur.

| Champ | Type | Obligatoire | Remarques |
|---|---|---|---|
| `targetType` | chaîne | Oui | `directUser`, `fixed_address`, `fixed_group` ou `webhook`. Chaque type de connecteur accepte un sous-ensemble de ces valeurs. Par exemple, `email_smtp` accepte `directUser` et `fixed_address`. |
| `target` | chaîne | Oui | Destinataire : une adresse, un identifiant du fournisseur, un groupe ou une URL, selon `targetType`. |
| `message` | objet | Non | `title`, `text`, `markdown` et `html`. Par défaut, le titre et le texte sont génériques. |

<ResponseExample>
```json 200
{
  "sent": true,
  "testedAt": 1790000000000000,
  "elapsedMs": 3,
  "providerMessageId": "req-1",
  "error": null
}
```
</ResponseExample>

Même si l’envoi échoue, la requête renvoie `200`, avec `sent` à `false` et le motif dans `error`, par exemple `unavailable: webhook request failed`. Le test met aussi à jour les champs `status`, `lastTestedAt`, `lastTestStatus` et `lastTestError` du connecteur.

## Supprimer un connecteur

```http
DELETE /api/v1/notify/connectors/{id}
```

Si la suppression réussit, la requête renvoie `204` sans corps de réponse. Tant qu’un point de terminaison utilisateur, une politique de notification, une route de secours, une inspection planifiée des logs, une page de statut ou Mole Agent dans la messagerie instantanée référence le connecteur, la requête renvoie `409` avec `notify connector is referenced by user endpoints, policies, default routes, scheduled log inspections, status pages, or Mole Agent in IM`. Réaffectez d’abord ces références.

## Erreurs

| Statut | Cause |
|---|---|
| `400` | La valeur de `config` est invalide pour ce type, le système ne prend pas en charge le type (`unsupported connector type: pagerduty`), la cible est incompatible avec le connecteur ou le connecteur est désactivé. |
| `404` | Le connecteur n’existe pas. |
| `409` | Un autre connecteur de l’organisation utilise déjà ce nom, ou une référence au connecteur subsiste lors de la tentative de suppression. |
| `422` | Un champ est absent ou une valeur est invalide, par exemple si `targetType` est inconnu. La réponse est au format texte brut. |
