```http
PUT /api/v1/alerts/routing/rules/order
```

Place les [règles de routage](/fr/alerting/routing#règles-de-routage) de l’organisation dans l’ordre indiqué. Nécessite l’autorisation `alerts.routing.manage`. Les règles listées passent en tête, dans l’ordre indiqué. Les autres conservent leur ordre relatif. L’opération ignore les identifiants qui ne correspondent à aucune règle de l’organisation.

| Champ | Type | Description |
|---|---|---|
| `ids` | tableau | Obligatoire. Identifiants des règles, dans leur ordre d’évaluation. |

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/routing/rules/order \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<rule-id-2>", "<rule-id-1>"]}'
```
</RequestExample>

La réponse contient toutes les règles dans le nouvel ordre, avec des valeurs de `position` consécutives à partir de 0. Voir [Champs des règles](/fr/api/alerting/list-routing-rules#champs-des-règles).

**Erreurs**

| Statut | Cause |
|---|---|
| `403` | Le jeton ne dispose pas de l’autorisation `alerts.routing.manage`. |
| `422` | La requête ne contient pas `ids` ou contient un autre champ. La réponse est en texte brut. |
