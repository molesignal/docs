```http
POST /api/v1/alerts/incidents/bulk
```

Applique une action à chaque incident de `ids`, un par un : si un incident ne peut pas être traité,
les autres restent traités. `action` indique l’action à effectuer. Indiquez à côté les champs nécessaires :

| `action` | Champs | Effet |
|---|---|---|
| `acknowledge` | Aucun | Voir [Acquitter un incident](/fr/api/alerting/ack-incident). |
| `resolve` | Aucun | Voir [Résoudre un incident](/fr/api/alerting/resolve-incident). |
| `snooze` | `durationSecs` | Voir [Mettre un incident en pause](/fr/api/alerting/snooze-incident). |
| `reassign` | `to`, le corps de [Réattribuer un incident](/fr/api/alerting/reassign-incident) | Même effet que cet appel. |
| `set_severity` | `severity` | Voir [Définir la gravité d’un incident](/fr/api/alerting/set-incident-severity). |

L’appel nécessite `alerts.incidents.acknowledge` et vérifie chaque incident de la même manière que les appels individuels.
La fusion n’est pas une action groupée. Utilisez [Fusionner des incidents](/fr/api/alerting/merge-incidents).

**Corps**

| Champ | Type | Obligatoire | Remarques |
|---|---|---|---|
| `ids` | tableau | Oui | 1 à 100 identifiants d’incident. Chaque identifiant ne compte qu’une fois. |
| `action` | chaîne | Oui | `acknowledge`, `resolve`, `snooze`, `reassign` ou `set_severity`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents/bulk \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"ids": ["<incident-id>", "<another-incident-id>"], "action": "snooze", "durationSecs": 3600}'
```
</RequestExample>

La réponse contient un résultat par incident : `id`, et `error` si le traitement a échoué, par exemple si la situation est déjà revenue à la normale ou si `durationSecs` est hors limites.

<ResponseExample>
```json 200
{
  "results": [
    {
      "id": "3KEDNEyqouYJeBDTLTMTBui7XHW"
    },
    {
      "id": "3KEDQ4mJ8sLp2Xv6Nc1Rt9bYwHe",
      "error": "this incident is no longer active"
    }
  ]
}
```
</ResponseExample>

**Erreurs**

| Statut | Cause |
|---|---|
| `400` | `ids` est vide ou contient plus de 100 incidents. |
| `403` | Le jeton ne dispose pas de l’autorisation `alerts.incidents.acknowledge`. |
| `422` | `action` est absent ou inconnu, ou un champ nécessaire à l’action est absent. |
