```http
POST /api/v1/alerts/rules/{id}/test
```

Exécute une seule fois la requête d’une règle enregistrée sur la fenêtre de `now - period_secs` à `now` et indique si la condition est remplie. L’appel ne modifie ni l’état de l’évaluation, ni les incidents, ni les notifications, ni la règle elle-même. L’appel nécessite l’autorisation `alerts.rules.manage` et son corps est vide.

Testez une règle avant de définir `enabled` sur `true`. L’API enregistre sans erreur une règle qui contient une instruction non valide ou qui référence un flux inconnu. Seul le test révèle le problème.

Une [règle APM](/fr/api/alerting/create-rule#règles-apm) lit la valeur de son indicateur au lieu d’exécuter une requête. Le résultat contient une ligne avec les colonnes `value`, `service` et `trace_id`, ou aucune ligne si l’indicateur n’a pas de valeur sur la fenêtre.

Une [règle avec regroupement par colonnes](/fr/api/alerting/create-rule#règles-segmentées-par-colonnes) répertorie tous les groupes dans `groups`. `matched` vaut `true` si au moins un groupe remplit la condition, `value` contient la valeur du premier groupe qui la remplit et `severity` indique le niveau de gravité le plus élevé parmi les groupes.

Une [règle RUM](/fr/api/alerting/create-rule#règles-rum) lit la valeur de son indicateur de la même manière. Le résultat contient une ligne avec les colonnes `value` et `application`, ou aucune ligne si l’indicateur n’a pas de valeur sur la fenêtre. `scannedRows` indique le nombre de lignes sur lesquelles repose l’indicateur.

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/rules/$RULE_ID/test \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "matched": true,
  "value": 2.0,
  "severity": "critical",
  "columns": ["c"],
  "rows": [[2]],
  "scannedRows": 2,
  "tookMs": 170
}
```
</ResponseExample>

**Réponse**

| Champ | Type | Notes |
|---|---|---|
| `matched` | booléen | Indique si la condition est remplie au moment du test. Le résultat ne tient pas compte de `forPeriods`. |
| `value` | nombre ou null | Valeur de la première colonne de la première ligne. Vaut `null` si le résultat ne contient aucun nombre. |
| `severity` | chaîne ou null | Niveau de gravité que recevrait un incident. Vaut `null` si `matched` vaut `false`. |
| `columns` | tableau | Noms des colonnes du résultat de la requête. |
| `rows` | tableau | Jusqu’à 20 lignes du résultat. |
| `scannedRows` | entier | Nombre de lignes analysées par la requête. |
| `tookMs` | entier | Durée de la requête en millisecondes. |
| `anomaly` | objet | Uniquement pour les règles `anomaly`. Contient `baseline`, `deviation`, un `score` compris entre 0 et 1 et un texte `reason`. |
| `noData` | booléen | Présent uniquement s’il vaut `true` : l’exécution n’a renvoyé aucune valeur et la règle ne traite pas une valeur manquante comme `0`. |
| `groups` | tableau | Uniquement pour les règles avec regroupement par colonnes. Les groupes suivent l’ordre du résultat. Chaque groupe contient `labels`, qui associe les colonnes à leurs valeurs, ainsi que ses champs `value`, `matched` et `severity`. |
| `groupsTruncated` | booléen | Présent uniquement s’il vaut `true` : le résultat compte plus de 100 groupes et seuls les 100 premiers figurent dans la réponse. |

**Erreurs**

| Statut | Cause |
|---|---|
| `400` | La requête ne peut pas s’exécuter, par exemple si le code SQL n’est pas valide ou si un champ est inconnu. Ce code s’applique aussi si une règle `anomaly` ne dispose pas d’un historique exploitable pour établir une référence ou si la règle est de type `composite` ou `heartbeat` et n’exécute donc aucune requête. |
| `403` | Le flux de la règle n’existe pas ou le jeton ne dispose pas de l’autorisation `alerts.rules.manage`. |
| `404` | La règle n’existe pas. |
