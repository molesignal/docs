```http
PUT /api/v1/alerts/sources/{id}
```

Réenregistre tous les paramètres d’une [source d’alerte](/fr/alerting/sources). Cette opération requiert l’autorisation `alerts.sources.manage`. Les champs sont les mêmes que dans [Créer une source d’alerte](/fr/api/alerting/create-source). Le type ne peut pas changer : si le champ `kind` est renseigné, sa valeur doit correspondre au type actuel. Le jeton reste inchangé. Pour le remplacer, utilisez [Renouveler un jeton](/fr/api/alerting/rotate-source-token). Sans `homeCluster`, le cluster de réception reste inchangé. Les incidents déjà ouverts conservent leur politique d’escalade et leurs étiquettes.

<RequestExample>
```bash cURL
curl -X PUT http://localhost:5080/api/v1/alerts/sources/$SOURCE_ID \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "Production Prometheus", "enabled": false, "escalationPolicyId": "default", "severity": "error"}'
```
</RequestExample>

La réponse contient la source mise à jour, sans le champ `token`.

**Erreurs**

| Statut | Cause |
|---|---|
| `400` | Un champ est incorrect ou le type a changé. |
| `403` | Le jeton ne dispose pas de l’autorisation `alerts.sources.manage`. |
| `404` | La source n’existe pas. |
