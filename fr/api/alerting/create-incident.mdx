```http
POST /api/v1/alerts/incidents
```

Ouvre un incident pour un problème qu’aucune règle n’a détecté, par exemple après un signalement client. L’incident porte
l’étiquette `alert.source=manual`, les annotations `createdBy` (l’auteur de l’appel) et `description`, ainsi que
la valeur `manual` pour `ruleId`. Il contourne les pipelines d’alertes, ne fait jamais l’objet d’une déduplication avec un autre incident et ne
se résout jamais automatiquement. Cet appel exige l’autorisation `alerts.incidents.create` et consigne l’événement d’audit
`alert.incident.created`.

**Corps de la requête**

| Champ | Type | Obligatoire | Description |
|---|---|---|---|
| `title` | string | Oui | 200 caractères maximum. |
| `description` | string | Non | Markdown, 20 000 caractères maximum. |
| `severity` | string | Non | `info`, `warning`, `error` (par défaut) ou `critical`. |
| `urgency` | string | Non | Clé d’un des [niveaux d’urgence](/fr/alerting/on-call#niveaux-d’urgence-et-de-priorité) de l’organisation, par exemple `high` ou `low`. Si ce champ est absent, la politique d’escalade de l’incident détermine le niveau. Voir [Urgence](/fr/alerting/on-call#urgence). |
| `priority` | string | Non | Une des priorités de l’organisation, de `P1` à `P5` par défaut (`P9` au maximum). |
| `assign` | object | Non | Affectation de l’incident. Par défaut, `{"kind": "auto"}` suit le [routage des alertes](/fr/alerting/routing). `{"kind": "team", "teamId": "..."}` applique la politique d’astreinte de l’équipe. `{"kind": "policy", "escalationPolicyId": "..."}` applique la politique d’escalade indiquée. `{"kind": "users", "userIds": [...]}` notifie directement 1 à 10 membres de l’organisation, sans politique d’escalade. |
| `services` | string[] | Non | Services affectés, 20 au maximum. |
| `labels` | object | Non | 50 étiquettes au maximum. `alert.source` vaut toujours `manual`. |
| `declareMajor` | boolean | Non | Déclare également un [incident majeur](/fr/alerting/major-incidents). L’appel ouvre l’incident même si cette déclaration échoue. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/incidents \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"title": "Customers in the north cannot pay", "severity": "critical", "priority": "P1", "assign": {"kind": "team", "teamId": "<team-id>"}}'
```
</RequestExample>

La réponse contient l’incident. Pour connaître ses champs, consultez [Lister les incidents](/fr/api/alerting/list-incidents).

**Erreurs**

| Statut | Motif |
|---|---|
| `400` | Le titre manque ou dépasse la longueur maximale, le nombre d’étiquettes ou de services dépasse la limite, `users` ne désigne pas entre 1 et 10 membres, ou l’équipe, la politique ou les membres indiqués ne font pas partie de l’organisation. |
| `403` | Le jeton ne dispose pas de l’autorisation `alerts.incidents.create`. |
