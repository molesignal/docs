```http
POST /api/v1/alerts/routing/test
```

Détermine comment un incident portant ces étiquettes serait [routé](/fr/alerting/routing#ordre-de-routage) selon les règles de routage, les politiques d’astreinte des équipes et le catalogue de services en vigueur. Nécessite l’autorisation `alerts.routing.read`. La simulation suppose que la source utilise la politique par défaut. Elle n’ouvre aucun incident et n’envoie aucune notification.

| Champ | Type | Description |
|---|---|---|
| `labels` | objet | Étiquettes de l’incident. L’étiquette `alert.source` indique l’origine : `external` pour une source d’alertes, `synthetic` pour un contrôle synthétique et toute autre valeur pour une règle d’alerte. |
| `services` | tableau | Services affectés. Le routage utilise le premier si les étiquettes ne contiennent ni `service.name` ni `service`. |
| `severity` | chaîne | `info`, `warning` (par défaut), `error` ou `critical`. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/alerts/routing/test \
  -H "authorization: Bearer $MS_TOKEN" \
  -H "content-type: application/json" \
  -d '{"labels": {"service.name": "checkout", "env": "prod"}, "severity": "critical"}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "decision": {
    "escalationPolicyId": "<policy-id>",
    "teamId": "<team-id>",
    "routing": { "reason": "rule", "ruleId": "<rule-id>", "ruleName": "Payments in production" }
  },
  "matchedRuleId": "<rule-id>",
  "service": "default/checkout",
  "serviceTeamId": "<team-id>",
  "labelTeamId": null
}
```
</ResponseExample>

| Champ | Description |
|---|---|
| `decision.escalation_policy_id` | Politique d’escalade qui s’appliquerait à l’incident ; `default` pour la politique par défaut. |
| `decision.team_id` | Équipe vers laquelle l’incident serait routé, ou `null`. |
| `decision.routing` | Motif de la décision de routage, comme dans le champ `routing` d’un incident. Voir les [champs d’un incident](/fr/api/alerting/list-incidents#champs-de-l’incident). |
| `matchedRuleId` | Règle de routage correspondante, ou `null`. |
| `service` | Service pour lequel le routage recherche l’équipe responsable, au format `namespace/name`. |
| `serviceTeamId` | Équipe responsable de ce service dans le catalogue de services. |
| `labelTeamId` | Équipe désignée par l’étiquette `teamId` ou `team`. |
