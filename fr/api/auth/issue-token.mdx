```http
POST /api/v1/me/api-tokens
```

Émet un jeton personnel au format `mspat-<36>` qui agit au nom du compte connecté. Le jeton en clair n’apparaît que dans la réponse. Enregistrez-le immédiatement. Effectuez l’appel depuis une session authentifiée, jamais avec un autre jeton. L’appel exige la permission `personal_tokens.manage`.

**Corps**

| Champ | Type | Obligatoire | Remarques |
|---|---|---|---|
| `name` | string | Oui | Nom d’affichage de 1 à 255 caractères. |
| `policyId` | string | Non | Identifiant de la [politique de permissions](/fr/identity/roles#politiques-de-permissions) qui s’applique au jeton, par exemple `builtin:data_intake`. Détenez toutes les permissions de cette politique. |
| `permissions` | string[] | Non | Permissions de l’organisation attribuées au jeton. Détenez chacune de ces permissions. |
| `expiresInDays` | integer | Non | Durée de validité en jours, de 1 à 1825. Omettez ce champ pour créer un jeton sans expiration. |

Indiquez `policyId` ou `permissions`, mais pas les deux. Sans ces champs, le jeton dispose des mêmes permissions que le compte connecté. Lors de chaque requête, le jeton ne peut exercer que les permissions dont le compte dispose à cet instant : toute permission retirée au compte l’est aussi à ses jetons.

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -X POST http://localhost:5080/api/v1/me/api-tokens \
  -H 'content-type: application/json' \
  -d '{
    "name": "grafana-readonly",
    "permissions": ["streams.read", "streams.query", "dashboards.read"],
    "expiresInDays": 90
  }'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "id": "3KE5hOsEc3lMC9qr9RWnPn0pqWF",
  "prefix": "k7m2q9xv4b",
  "name": "grafana-readonly",
  "tokenKind": "personal",
  "userId": "<user-id>",
  "policyId": null,
  "permissions": ["dashboards.read", "streams.query", "streams.read"],
  "applicationId": null,
  "serviceAccountId": null,
  "expiresAt": 1798000000000000,
  "lastUsedAt": null,
  "revoked": false,
  "createdAt": 1790000000000000,
  "token": "mspat-k7m2q9xv4b<secret>"
}
```
</ResponseExample>

`ms-cookies.txt` contient la session ouverte lors de la [connexion](/fr/api/auth/login). `GET /api/v1/me/api-tokens/scopes` répertorie les politiques et les permissions de l’organisation auxquelles limiter un jeton. Envoyez le jeton dans l’en-tête `Authorization` : `Authorization: Bearer mspat-…`.

## Pour un compte de service

```http
POST /api/v1/auth/tokens
```

Émet un jeton qui agit au nom d’un compte de service. Ajoutez `serviceAccountId` au même corps de requête. L’appel exige la permission `api_tokens.issue`. Contrairement à un jeton personnel, ce jeton peut être émis à l’aide d’un jeton d’API. Sans `policyId` ni `permissions`, le jeton reçoit uniquement les permissions du rôle du compte de service que détient aussi le compte appelant au moment de l’émission : le jeton ne reçoit aucune permission ajoutée par la suite au rôle et perd immédiatement toute permission retirée au rôle.

```bash
curl -X POST http://localhost:5080/api/v1/auth/tokens \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "collector-production",
    "serviceAccountId": "<service-account-id>",
    "policyId": "builtin:data_intake",
    "expiresInDays": 365
  }'
```

**Erreurs**

| Statut | Cause |
|---|---|
| `400` | `name` vide, présence simultanée de `policyId` et de `permissions`, liste vide, permission ou politique inconnue, ou compte de service désactivé. |
| `403` | Le périmètre demandé inclut une permission que le compte appelant ne détient pas, la demande de jeton personnel utilise un jeton d’API ou la permission requise (`personal_tokens.manage` ou `api_tokens.issue`) manque. |
| `404` | Le périmètre système ne contient aucun jeton d’API ou le compte de service n’existe pas. |
