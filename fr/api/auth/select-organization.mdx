```http
POST /api/v1/orgs/{id}/select
```

Bascule la session ouverte dans le navigateur vers une autre organisation dont le compte est membre. La réponse réécrit les cookies de session pour cette organisation, sans modifier l’heure d’expiration de la session. Consultez [Connexion](/fr/api/auth/login) pour en savoir plus sur les cookies. Seule une session peut changer d’organisation : la requête renvoie `403` avec un jeton d’API. Les administrateurs de la plateforme peuvent sélectionner l’organisation protégée `_sys`, nécessaire aux appels à l’échelle de la plateforme tels que [Renouveler les clés de signature JWT](/fr/api/auth/rotate-jwt). Une session dans `_sys` prend fin dans l’heure qui suit le basculement.

**Paramètres de chemin**

| Paramètre | Type | Notes |
|---|---|---|
| `id` | string | Identifiant de l’organisation renvoyé par `GET /api/v1/orgs`. |

<RequestExample>
```bash cURL
curl -b ms-cookies.txt -c ms-cookies.txt \
  -X POST http://localhost:5080/api/v1/orgs/<organization-id>/select
```
</RequestExample>

<ResponseExample>
```json 200
{
  "userId": "<user-id>",
  "orgId": "<organization-id>",
  "orgName": "default",
  "displayRole": "Owner",
  "roles": [
    { "id": "<role-id>", "key": "owner", "name": "Owner", "builtin": true }
  ],
  "system": false
}
```
</ResponseExample>

Les onglets d’un même navigateur partagent les cookies. Tous les onglets ouverts basculent donc vers l’organisation sélectionnée.

## Exigences de connexion

Si la connexion actuelle ne satisfait pas toutes les [exigences de connexion](/fr/identity/sso#exigences-de-connexion) de l’organisation, la réponse conserve le code `200`, n’envoie aucun nouveau cookie et indique ce qui manque :

| Réponse | Signification |
|---|---|
| `{"mfa": {"organization_name", "methods"}}` | Validez un second facteur immédiatement : renvoyez la requête avec `{"proof": {…}}` dans le corps. La preuve contient `method` (`totp` ou `recovery_code`) et `code`, ou `method` avec la valeur `passkey` et les champs `ceremony` et `credential` issus de `POST /api/v1/me/mfa/passkey-proof`. |
| `{"mfaSetup": {"organization_name"}}` | Le compte n’a pas de second facteur. Configurez-en d’abord un via `/api/v1/me/mfa` ou `/api/v1/me/passkeys`. |
| `{"sso": {"organization_name", "providers"}}` | L’accès passe obligatoirement par l’authentification unique (SSO) de l’organisation. `providers` répertorie les champs `id`, `name`, `kind` et `platform`. |
