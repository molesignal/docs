Ces appels lisent un flux de journaux de l'organisation, comme le fait la page **Journaux**. Un flux qui n'existe pas répond un résultat vide. Tous les appels exigent `logs.read`, ou `sys.telemetry.read` dans la portée système.

Chaque appel, sauf le regroupement en motifs, accepte `POST` avec un corps JSON, ou `GET` avec les mêmes champs dans la chaîne de requête : `filters` et `freeText` comme texte d'une liste JSON, et `where` comme texte d'un objet JSON. Envoyez en `POST` une requête trop longue pour une adresse.

## Ce à quoi correspond un appel

Un appel correspond aux enregistrements du flux, dans la fenêtre, qui satisfont tous ces critères :

| Champ | Type | Remarques |
|---|---|---|
| `filters` | liste | Filtres qui doivent tous être satisfaits. 32 au maximum, en comptant les filtres de `where`. |
| `freeText` | liste | Mots ou phrases à rechercher dans le champ `message`, chacun jusqu'à 512 octets. Un mot en minuscules composé de lettres et de chiffres, jusqu'à 40 octets, correspond quelle que soit sa casse ; les autres textes correspondent tels qu'écrits. 8 au maximum, en comptant le texte de `where`. |
| `where` | objet | Une arborescence de conditions pour les alternatives : un filtre, `{"text": "..."}`, `{"and": [...]}` ou `{"or": [...]}`. |
| `expression` | chaîne | Une requête de champs telle que l'écrit la page **Journaux**. Elle remplace `filters`, `freeText` et `where` : envoyez l'un ou l'autre. |

Un filtre est un objet avec `field`, `op`, `value` et `quoted`. Il nomme son champ comme le flux le nomme.

| Opérateur | Champs | Correspond à |
|---|---|---|
| `=`, `!=` | Tout champ scalaire | La valeur, ou toute autre valeur. Avec une valeur vide, indique si le champ a une valeur : `=` correspond aux enregistrements qui n'en ont pas. |
| `>`, `>=`, `<`, `<=` | Nombres et horodatages | La comparaison. |
| `contains` | Texte | La valeur n'importe où dans le champ. |
| `match` | Tout champ | La valeur comme sous-chaîne, quelle que soit sa casse. Une valeur vide ne correspond à rien. |
| `match_text` | Texte avec un index plein texte | Une recherche plein texte : mots, phrases et jokers. Un champ sans index plein texte répond `400`. |

`eq`, `ne` et `like` sont des alias de `=`, `!=` et `contains`. `quoted` vaut `true` pour une valeur écrite entre guillemets : un mot, jamais un nombre. Un champ JSON n'est pas filtrable ici ; interrogez-le avec SQL.

`expression` reprend le texte de la page **Journaux** : comparaisons, `MATCH(field, 'text')` et `MATCH_TEXT(field, 'words')`, mots à rechercher, une phrase entre guillemets, `AND` et `OR` dans n'importe quelle casse avec `AND` prioritaire, et des parenthèses. Le serveur la lit dans les `filters`, `freeText` et `where` que la page envoie, et les vérifie comme ci-dessus. Le texte fait au plus 8 Kio et imbrique les parenthèses sur 32 niveaux au plus. Une partie qu'il ne peut pas lire, comme une parenthèse non fermée ou une comparaison sans rien, répond `400` et nomme la partie.

```bash
curl -G "http://localhost:5080/api/v1/web/logs" \
  -H "authorization: Bearer $MS_TOKEN" \
  --data-urlencode 'stream=app' \
  --data-urlencode "expression=level = 'error' AND (service.name = 'checkout' OR timeout)"
```

## Lister les enregistrements

```http
POST /api/v1/web/logs
GET  /api/v1/web/logs
```

Renvoie les enregistrements correspondants, du plus récent au plus ancien, avec une pagination par curseur.

| Champ | Type | Remarques |
|---|---|---|
| `stream` | chaîne | Obligatoire. Le flux de journaux. |
| `from`, `to` | entier | La fenêtre en microsecondes. Par défaut, les dernières 24 heures jusqu'à maintenant. `to` doit être supérieur à `from`. |
| `filters`, `freeText`, `where`, `expression` | | Ce à quoi l'appel correspond. |
| `limit` | entier | Taille de page. `20` par défaut, ramené entre 1 et 5000. |
| `cursor` | chaîne | Le `nextCursor` ou le `previousCursor` d'une page précédente. Il conserve la fenêtre et la correspondance de la première page. |

<RequestExample>
```bash cURL
curl -X POST http://localhost:5080/api/v1/web/logs \
  -H "authorization: Bearer $MS_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"stream":"app","expression":"level = '\''error'\''","limit":2}'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "items": [
    { "_timestamp": 1790000000000000, "level": "error", "message": "db pool exhausted", "trace_id": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "nextCursor": "eyJ2IjoxLC...",
  "previousCursor": null,
  "hasMore": true
}
```
</ResponseExample>

Chaque élément contient les champs d'un enregistrement. `_timestamp` est en microsecondes. Une requête avec un `cursor` et un flux, une fenêtre, un `limit` ou une correspondance différents répond `400`.

## Compter les enregistrements dans le temps

```http
POST /api/v1/web/logs/histogram
GET  /api/v1/web/logs/histogram
```

Compte les enregistrements correspondants par intervalles de temps.

| Champ | Type | Remarques |
|---|---|---|
| `stream` | chaîne | Obligatoire. |
| `from`, `to` | entier | Obligatoire. La fenêtre en microsecondes. |
| `filters`, `freeText`, `where`, `expression` | | Ce à quoi l'appel correspond. |
| `bucketTime` | entier | La longueur d'un intervalle en microsecondes. Au moins `1000`. |
| `originTime` | entier | Le début du premier intervalle. Pas après `from`. |

Une requête couvre au plus 512 intervalles de `originTime` à `to`.

```json
{
  "bucketTime": 60000000,
  "originTime": 1790000100000000,
  "buckets": [{ "startTime": 1790000100000000, "total": 120, "errors": 4 }],
  "split": true
}
```

`buckets` liste les intervalles qui contiennent un enregistrement, du plus ancien au plus récent. `errors` compte les enregistrements de niveau `ERROR`, lus dans `level` ou `body_level`. `split` vaut `false` quand le flux n'a aucun des deux champs ou que le niveau est masqué pour le lecteur ; `errors` vaut alors `0`. Quand le compte n'est pas disponible, l'appel répond `200` avec `buckets` vide et `unavailable` : `time_budget`, `busy` ou `scan_limit`, comme pour le [comptage des traces](/fr/api/web/trace#compter-les-traces-dans-le-temps).

## Décrire un champ

```http
POST /api/v1/web/logs/field-stats
GET  /api/v1/web/logs/field-stats
```

Décrit les valeurs que prend un champ dans les enregistrements correspondants.

| Champ | Type | Remarques |
|---|---|---|
| `stream` | chaîne | Obligatoire. |
| `from`, `to` | entier | La fenêtre en microsecondes. |
| `filters`, `freeText`, `where`, `expression` | | Ce à quoi l'appel correspond. |
| `field` | chaîne | Obligatoire. Le champ, tel que le flux le nomme. |

```json
{
  "kind": "text",
  "total": 1840,
  "present": 1840,
  "distinct": 3,
  "distinctExact": true,
  "top": [{ "value": "info", "count": 1500 }, { "value": "warn", "count": 300 }, { "value": "error", "count": 40 }],
  "topSkipped": false
}
```

`kind` vaut `number`, `time`, `text` ou `bool`. `total` compte les enregistrements correspondants et `present` ceux qui ont une valeur. `top` liste les valeurs les plus fréquentes, les plus fréquentes en premier ; `topSkipped` vaut `true` quand presque toutes les valeurs diffèrent et qu'aucune n'est listée. `range` donne la plus petite et la plus grande valeur sous forme de texte. Un champ numérique ajoute `spread` et `bars`. `trend` compte les valeurs les plus fréquentes sur la fenêtre, et est absent quand aucune valeur n'est plus fréquente que les autres.

## Regrouper en motifs

```http
POST /api/v1/web/logs/patterns
```

Regroupe les enregistrements correspondants en motifs de message sur toute la fenêtre et compare chacun à une période de référence. Une fenêtre de plus de 5 000 enregistrements correspondants est lue comme un échantillon des enregistrements les plus récents de quatre parties égales, et `estimatedCount` de chaque motif ramène son compte à la fenêtre. L'appel exige `logs.read`.

| Champ | Type | Remarques |
|---|---|---|
| `stream` | chaîne | Obligatoire. |
| `from`, `to` | entier | Obligatoire. La fenêtre en microsecondes. |
| `filters`, `freeText`, `where`, `expression` | | Ce à quoi l'appel correspond. |
| `field` | chaîne | Le champ qui contient le message ; le premier de `message`, `body`, `summary`, `log`, `event`, `error`, `msg`, `content` et `text` que possède le flux quand il est omis. |
| `baseline` | chaîne | `previous` (par défaut, la période de même longueur juste avant), `week_before` ou `none`. |
| `limit` | entier | Le nombre maximal de motifs listés : 100 par défaut, 200 au plus. |

```json
{
  "stream": "app_logs",
  "field": "message",
  "levelField": "level",
  "timeRange": { "startTime": 1795510800000000, "endTime": 1795514399999999 },
  "logs": 48210,
  "read": 5000,
  "unread": 0,
  "sampled": true,
  "baseline": { "kind": "previous", "startTime": 1795507199999999, "endTime": 1795510799999999, "logs": 40102, "read": 5000, "sampled": true },
  "newPatterns": 1,
  "surgingPatterns": 0,
  "droppingPatterns": 0,
  "patternCount": 37,
  "patterns": [
    {
      "pattern": "upstream timeout after <number>ms",
      "tokens": [{ "lead": "", "trail": "", "text": "upstream", "wild": null, "unit": "" }],
      "count": 41,
      "share": 0.0082,
      "estimatedCount": 395,
      "firstSeen": 1795513020000000,
      "lastSeen": 1795514390000000,
      "levels": [{ "level": "ERROR", "count": 41 }],
      "baselineCount": 0,
      "change": "new",
      "fragment": "upstream timeout after",
      "example": "upstream timeout after 3000ms"
    }
  ]
}
```

Les motifs nouveaux et en forte hausse viennent en premier, et les motifs que la fenêtre ne contient plus en dernier. `change` vaut `new` (la référence n'en avait aucun), `surging` (au moins deux fois plus, avec au moins cinq de plus), `dropping` (la moitié ou moins, avec au moins cinq de moins) ou `steady` ; `ratio` est le compte estimé de la fenêtre divisé par celui de la référence. `tokens` sont les mots du motif, `wild` nommant ce qui change à un emplacement ouvert. Un champ chiffré au repos répond `400`. Un flux dans lequel rien n'a été écrit répond un rapport vide.

## Erreurs

| Statut | Cause |
|---|---|
| `400` | Un paramètre est invalide : `stream` est absent, `to` n'est pas supérieur à `from`, un filtre nomme un champ inconnu ou utilise un opérateur que son type n'accepte pas, les listes ou l'arborescence dépassent leurs limites, `expression` est fourni avec `filters`, `freeText` ou `where` ou contient une partie illisible, le curseur ne correspond pas à la requête, ou un paramètre d'histogramme est absent ou couvre plus de 512 intervalles. |
| `403` | Le jeton ne dispose pas de `logs.read`. |
