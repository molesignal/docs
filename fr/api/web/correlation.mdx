```http
GET /api/v1/web/correlation/{fromKind}/{toKind}?ctx=<base64url-json>
```

Calcule les filtres, la plage temporelle et le contenu prérempli de la requête que l’interface web applique lors du passage d’un signal à un autre, par exemple d’une trace aux journaux associés. L’appel nécessite `traces.read` ou, dans la portée système, `sys.telemetry.read`.

**Paramètres**

| Paramètre | Emplacement | Obligatoire | Remarques |
|---|---|---|---|
| `fromKind` | chemin | Oui | Type de signal source : `trace`, `metric`, `log` ou `host`. |
| `toKind` | chemin | Oui | Type de signal de destination : `trace`, `metric`, `log` ou `host`. |
| `ctx` | requête | Oui | Objet JSON qui décrit le signal source, encodé en base64url sans remplissage. |

L’objet `ctx` accepte les clés facultatives suivantes :

| Clé | Type | Remarques |
|---|---|---|
| `trace_id` | chaîne | Identifiant de la trace associée au signal source. |
| `service` | chaîne | Nom d’un service. |
| `services` | tableau | Noms des services. |
| `host` | chaîne | Nom d’un hôte. |
| `time_range` | objet | `{ "from": "<RFC 3339>", "to": "<RFC 3339>" }`. La plage par défaut couvre la dernière minute. |

## Transitions prises en charge

| Source → destination | Filtres | Requête préremplie |
|---|---|---|
| `trace` → `log` | `service` à partir de `services`, ainsi que `trace_id` | Aucune. |
| `trace` → `metric` | `service` à partir de `services` | `promql` : `rate(http_requests_total{service="<first service>"}[1m])` |
| `trace` → `host` | `host` à partir de `host` | Aucune. |
| `metric` → `trace` | `service` à partir de `services`, ainsi qu’un `peer_service` indiqué dans le graphe des services pour le premier service | Aucune. |
| `metric` → `log` | `service` à partir de `services` | Aucune. |
| `log` → `trace` | `trace_id` et `service` | Aucune. |
| `log` → `metric` | `service` à partir de `services` ou de `service` | `promql` : `rate(log_records_total{service="<service>"}[1m])` |
| `host` → `trace` | `host.name` à partir de `host` | Aucune. |

Un filtre sur un seul service utilise l’opérateur `eq` et un filtre sur plusieurs services utilise `in`. Pour toute autre combinaison, y compris si un type est inconnu, l’API renvoie `200` avec la plage temporelle et sans filtre.

<RequestExample>
```bash cURL
CTX=$(printf '%s' '{"trace_id":"0af7651916cd43dd8448eb211c80319c","services":["checkout","payments"],"time_range":{"from":"2026-10-04T10:00:00Z","to":"2026-10-04T10:05:00Z"}}' | base64 | tr -d '\n=' | tr '+/' '-_')

curl "http://localhost:5080/api/v1/web/correlation/trace/log?ctx=$CTX" \
  -H "authorization: Bearer $MS_TOKEN"
```
</RequestExample>

<ResponseExample>
```json 200
{
  "timeRange": { "from": "2026-10-04T10:00:00Z", "to": "2026-10-04T10:05:00Z" },
  "filters": [
    { "field": "service", "op": "in", "value": ["checkout", "payments"] },
    { "field": "trace_id", "op": "eq", "value": "0af7651916cd43dd8448eb211c80319c" }
  ],
  "prefill": {}
}
```
</ResponseExample>

**Erreurs**

| Statut | Cause |
|---|---|
| `400` | Le paramètre `ctx` est absent, son encodage base64url est invalide ou son décodage ne produit pas de JSON. Si `ctx` est absent, l’API répond en texte brut. Dans les autres cas, elle renvoie `invalid_argument` avec le message `invalid ctx base64: ...` ou `invalid ctx json: ...`. |
| `403` | Le jeton ne dispose pas de l’autorisation `traces.read`. |
